# acceptance — 验收

> **目录定位**:Quantalithos 的**验收标准与验收结果**。A 方案下与 `governance` 域的 Gate 机制、`standards/产品遵循规范清单.md` 联动。

---

## 一、目录构成

```
phase-1/                  Phase 1 验收记录(归档)
├── 验收标准.md
└── 验收结果.md
```

A 方案迭代启动后会新增:

```
iteration-NN/            A 方案每次迭代的验收
├── 验收标准.md          (迭代定制,继承产品清单)
└── 验收结果.md
```

---

## 二、A 方案下的定位

### 2.1 `phase-1/`(归档)

Phase 1 验收记录作为**历史证据**保留,支撑可审计性(红线 1)。**不可删除**。

### 2.2 新验收的承载位置

A 方案下验收作为**治理域的 Gate**(`kind=acceptance-confirm` / `release-confirm`)运行:

- **验收标准**来自 `standards/产品遵循规范清单.md` + 迭代特化项
- **验收结果**进入 `governance.Gate.resolution` + 归档 Artifact
- 每次验收产出 `ComplianceDeclaration` Artifact(对齐 24748-2)

### 2.3 本目录在验收闭环中的作用

- **产出物归档位置**:每次 Gate 决策后,详细的验收标准文档和结果报告以 Artifact 形式存储,并在本目录按迭代归档索引
- **跨迭代对比**:本目录提供历史验收结果的人类可读索引,辅助管理评审(42001 §9.3)

---

## 三、验收标准的三层结构

```
共同强制项(产品遵循规范清单 §零)
    │
    ▼
产品特定强制项(产品遵循规范清单 §一-§十)
    │
    ▼
迭代特定强制项(本目录 iteration-NN/验收标准.md)
```

---

## 四、与其他目录的分工

| 目录 | 作用 |
|---|---|
| **acceptance/** (本目录) | 验收标准 + 验收结果归档 |
| `standards/产品遵循规范清单.md` | 必守条目 |
| `review/` | 代码与设计审查(不是产品验收) |
| `governance` 域(实现) | Gate 的运行时载体 |

---

## 五、修订纪律

- Phase 1 归档**不可修改**
- 新迭代按模板创建 `iteration-NN/`
- 验收标准修改**必须经过 Gate**(本身就是"验收规则的变更")

# 第一阶段验收标准

> 波次 1-3（core/platform/flow/runtime/gate/sandbox/infra）编码完成后的验收标准。
> 验收分为两个层级：单项目验收（每个项目独立验证）和跨项目验收（服务间协作验证）。

---

## 一、验收范围

| 项目 | 语言 | 验收类型 |
|------|------|---------|
| core | Python | 单项目 |
| platform | Rust | 单项目 |
| flow | Python | 单项目 |
| runtime | Python | 单项目 |
| gate | Rust | 单项目 |
| sandbox | Rust | 单项目 |
| infra | Shell/YAML/SQL | 单项目 |
| **跨项目** | — | 协议一致性 + 联调 |

---

## 二、单项目验收

### 2.1 编译/构建

每个项目必须能从干净状态编译成功，无 error、无 warning（Rust clippy warning 除外）。

| 项目 | 验证命令 | 通过标准 |
|------|---------|---------|
| core | `cd quantalithos-core && pip install -e ".[dev]" && python -c "import quantalithos_core; print('OK')"` | 输出 OK，无 ImportError |
| flow | `cd quantalithos-flow && pip install -e ".[dev]" && python -c "import quantalithos_flow; print('OK')"` | 输出 OK，无 ImportError |
| runtime | `cd quantalithos-runtime && pip install -e ".[dev]" && python -c "import quantalithos_runtime; print('OK')"` | 输出 OK，无 ImportError |
| platform | `cd quantalithos-platform && cargo build --workspace` | exit code 0，无 error |
| gate | `cd quantalithos-gate && cargo build` | exit code 0，无 error |
| sandbox | `cd quantalithos-sandbox && cargo build` | exit code 0，无 error |
| infra | `cd quantalithos-infra && bash -n scripts/*.sh` | 所有脚本语法检查通过 |

### 2.2 单元测试

每个项目自带的测试必须全部通过。

| 项目 | 验证命令 | 通过标准 |
|------|---------|---------|
| core | `cd quantalithos-core && pytest -v` | 全部 PASSED，0 FAILED |
| flow | `cd quantalithos-flow && pytest -v` | 全部 PASSED，0 FAILED |
| runtime | `cd quantalithos-runtime && pytest -v` | 全部 PASSED，0 FAILED |
| platform | `cd quantalithos-platform && cargo test --workspace` | test result: ok |
| gate | `cd quantalithos-gate && cargo test` | test result: ok |
| sandbox | `cd quantalithos-sandbox && cargo test` | test result: ok |

### 2.3 静态检查

代码质量工具必须通过，确保无明显缺陷。

**Rust 项目（platform / gate / sandbox）：**

| 检查项 | 验证命令 | 通过标准 |
|--------|---------|---------|
| clippy | `cargo clippy --workspace -- -D warnings` | 0 warnings（deny 模式） |
| 格式化 | `cargo fmt --check` | 无格式差异 |

**Python 项目（core / flow / runtime）：**

| 检查项 | 验证命令 | 通过标准 |
|--------|---------|---------|
| ruff | `ruff check .` | 0 errors |
| 格式化 | `ruff format --check .` | 无格式差异 |

### 2.4 依赖完整性

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| Python 依赖可安装 | `pip install -e .` 在干净 venv 中执行 | 无缺失依赖 |
| Rust 依赖可编译 | `cargo build` 在干净环境中执行 | 无缺失 crate |
| 锁定文件存在 | 检查 Cargo.lock / requirements.txt | 文件存在且已提交 |

### 2.5 目录结构一致性

每个项目的代码目录结构必须与详细设计 §一 一致。

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| 设计中定义的目录都存在 | `find` 对比详细设计目录树 | 无缺失目录 |
| 无设计中未定义的顶层模块 | 人工审查 | 无多余模块（或已补充设计） |

## 三、跨项目验收

### 3.1 协议导入一致性

core 导出的共享模型必须能被 flow 和 runtime 正确导入。

```bash
# 验证脚本
cd ~/WorkProject/quantalithos-core && python -c "
from quantalithos_core import (
    FlowMessage, FlowMessageType, NodeResult, NodeResultType,
    NodeExecutePayload, ChatMessagePayload, AgentCreatePayload,
    SandboxProvider, ExecResult, FileInfo
)
print('core exports: OK')
"

cd ~/WorkProject/quantalithos-flow && python -c "
from quantalithos_core import (
    FlowMessage, FlowMessageType, NodeResult, NodeResultType,
    NodeExecutePayload, ChatMessagePayload, AgentCreatePayload
)
print('flow imports: OK')
"

cd ~/WorkProject/quantalithos-runtime && python -c "
from quantalithos_core import (
    FlowMessage, FlowMessageType, NodeResult, NodeResultType,
    NodeExecutePayload, ChatMessagePayload, AgentCreatePayload,
    SandboxProvider, ExecResult, FileInfo
)
print('runtime imports: OK')
"
```

| 通过标准 | 说明 |
|---------|------|
| 三个 OK 全部输出 | 共享模型导入无报错 |
| 无 `from quantalithos_core.protocol.payloads import` | 不绕过公共 API 导入内部模块 |

### 3.2 FlowMessageType 枚举对齐

```bash
python -c "
from quantalithos_core import FlowMessageType
expected = {'agent_create','agent_destroy','agent_suspend','agent_resume','node_execute','node_cancel','chat_message'}
actual = {e.value for e in FlowMessageType}
assert actual == expected, f'Mismatch: {actual.symmetric_difference(expected)}'
print(f'FlowMessageType: {len(actual)} variants, all aligned')
"
```

### 3.3 NodeResultType 枚举对齐

```bash
python -c "
from quantalithos_core import NodeResultType
expected = {'completed','blocked','failed'}
actual = {e.value for e in NodeResultType}
assert actual == expected, f'Mismatch: {actual.symmetric_difference(expected)}'
print(f'NodeResultType: {len(actual)} variants, all aligned')
"
```

| Docker Compose 启动 | `cd quantalithos-infra && docker compose up -d` | 所有容器 running |
| 健康检查 | `bash scripts/health-check.sh` | 全部 OK |

### 3.5 服务健康检查

所有服务启动后，健康检查端点必须返回 200。

| 服务 | 验证命令 | 通过标准 |
|------|---------|---------|
| platform | `curl -sf http://localhost:8001/health` | HTTP 200 |
| runtime | `curl -sf http://localhost:8003/health` | HTTP 200 |
| sandbox | `curl -sf http://localhost:8004/health` | HTTP 200 |
| gate | `curl -sf http://localhost:8000/health` | HTTP 200 |

### 3.6 gate 路由转发

| 检查项 | 验证命令 | 通过标准 |
|--------|---------|---------|
| JWT 登录 | `curl -X POST localhost:8000/auth/login -d '{"email":"dev@quantalithos.ai","password":"dev-password"}'` | 返回 token |

## 四、验收流程

```
单项目验收（可并行）
  │
  ├── core: 编译 → 测试 → 静态检查
  ├── platform: 编译 → 测试 → clippy
  ├── flow: 编译 → 测试 → ruff
  ├── runtime: 编译 → 测试 → ruff
  ├── gate: 编译 → 测试 → clippy
  ├── sandbox: 编译 → 测试 → clippy
  └── infra: 脚本语法检查
  │
  ▼
跨项目验收（串行）
  │
  ├── 协议导入一致性
  ├── 枚举值对齐
  ├── infra 环境启动
  ├── 服务健康检查
  └── gate 路由转发
  │
  ▼
验收结论
```

---

## 五、通过标准

| 级别 | 条件 | 判定 |
|------|------|------|
| 通过 | 单项目验收全部通过 + 跨项目验收全部通过 | 进入联调 |
| 有条件通过 | 单项目验收全部通过，跨项目验收有 ≤ 2 项失败且已记录修复计划 | 进入联调，并行修复 |
| 不通过 | 任一项目编译失败 或 单元测试失败 | 修复后重新验收 |

## 二、阅读顺序

**首次来,建立整体认识**:

1. `架构设计.md` — 架构方法论(为什么这样分,底层哲学)
2. `仓库拆分方案.md` §一-§二 — 拆分哲学 + 七层总览
3. `开发路线图与优先级.md` — 交付节点
4. `标准对齐全景图.md` §零 — 标准速查表

**做设计决策前必读**:

- `product/六域模型.md`(领域模型是架构的上游)
- `架构设计.md`(方法论)
- `标准对齐全景图.md`(对应层和仓的标准对齐)
- `adr/` 已有决策(避免重复或冲突)

## 三、ADR 书写纪律

**必须走 ADR 的决策**:

- 仓库新增 / 删除 / 合并
- 技术栈选型(语言 / 数据库 / 部署平台)
- 跨仓接口变化(breaking change)
- 聚合根不变量的变化
- 产品矩阵的改动
- 三红线的改动

**编号**:从 0001 递增,不补编号。
**文件名**:`NNNN-kebab-case-topic.md`
**格式**:遵循 `架构设计.md` §7.1 的 9 段式。
**ADR 末尾必须有"标准对齐"一节**。

---

## 四、修订纪律

- 仓库拆分 / 路线图 / 标准对齐图的修改必须走 ADR
- 架构设计方法论(`架构设计.md`)原则上不修改(是外部方法论提炼,更新走原文升级再对照)
- ADR 一旦 Accepted 不可修改内容,变更走"新 ADR Supersedes 旧 ADR"
- 旧 ADR 归入 legacy 时必须保留原号码

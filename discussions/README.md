# discussions — 对话与讨论记录

> **目录定位**:Quantalithos 设计过程中的**对话与推演记录**,按日期归档。是产品决策的**思考底稿**。

---

## 一、目录构成

```
2026-05-07-标准与建模.md    A 方案的完整推演记录(约 2300 行,9 轮)
```

**未来会按日期继续追加**:

```
YYYY-MM-DD-<主题>.md
```

---

## 二、作用

- **决策源头追溯**:任何 ADR / 架构决策背后都能在 discussions 找到完整推演
- **产品叙事的演进证据**:产品原则 / 六域 / 产品矩阵 的每一次调整都有推演根据
- **争议处置的依据**:对冲突方案的讨论过程保留,未来复盘时可查
- **知识沉淀**:未来新加入者可以通过 discussions 理解"为什么这样设计"

---

## 三、内容性质

- **未经编辑的对话记录**(按时间线顺序)
- **非权威文档** —— 结论性内容一旦定稿会迁入 `product/` / `architecture/` / `standards/`
- **保留所有迭代痕迹**(包括被否决的方案)
- **明确标注决策节点**(每轮末尾的"决策/结论")

---

## 四、阅读建议

**对 Quantalithos 首次认识**:
1. `2026-05-07-标准与建模.md` 第 5-6 轮 — 六域建模的关键推演
2. 同文件第 7-8 轮 — 仓库拆分 + 产品矩阵推演

**遇到设计困惑,想知道"为什么这样决定"时**:
- 在 discussions 里按关键词搜索
- 顺着推演路径读下去,看到决策点

---

## 五、修订纪律

- 已归档的 discussions **不可修改内容**(历史证据)
- 允许补注释(如"此方案已被 A 方案顶替,见 product/六域模型.md")
- 新讨论按 `YYYY-MM-DD-<主题>.md` 命名,允许一天多份
- 合并 / 重组 discussions 文件需要走 ADR

---

## 六、与其他目录的分工

| 目录 | 作用 |
|---|---|
| **discussions/** (本目录) | 思考底稿(时间序) |
| `product/` | 叙事权威(定稿) |
| `architecture/` | 架构权威(定稿) |
| `architecture/adr/` | 架构决策的正式记录 |

推演(discussions) → ADR → 权威文档(product / architecture / standards) 是单向升级路径。

# 项目仓库拆分方案

> 基于 AI 驱动研发协作平台设计文档，梳理完整实现所需的仓库拆分方案。

---

## 一、整体架构概览

本项目是一个 **AI 驱动的软件研发协作平台**，核心交互形态为：

```
用户 ←→ AI助手(Assistant) ←→ 群聊(多个Agent协作)
```

### 核心功能
- 私聊入口：用户与 Assistant 一对一对话
- 群聊协作：项目群组内多 Agent + 用户协作
- 六阶段流程：项目启动 → 需求理解 → 方案拆解 → 迭代开发 → 验收确认 → 发布执行
- 产物管理：PRD、设计文档、代码、测试报告等全生命周期管理
- 工作区管理：项目配置、快照、文档、任务的跨机器同步与恢复

## 二、推荐仓库拆分（7 仓库方案）

### 1. quantalithos-runtime — Agent 运行时

**职责：**
- Agent 生命周期管理（实例化、挂起、恢复、销毁）
- Agent 角色定义与 Prompt 管理（shared_rules + role_store，全 YAML）
- LLM 调用封装（多模型支持、流式输出、成本追踪）
- 工具调用系统（工具注册、执行、沙箱隔离、两层权限校验）
- 记忆系统（Phase 1 内存、Phase 2 数据库、Phase 3 向量库）
- Agent 级工作流引擎（加载工作流模板，按 step 驱动单 Agent 执行）
- step 内部的 think → act 循环
- 消息格式校验（reply_type 必填字段、forbidden_patterns 拦截）
- TaskProvider 抽象接口（支持平台 API / 本地文件 / 第三方工单系统）

**技术栈：** Phase 1 纯 Python，Phase 2 按需引入 Rust（PyO3）

**核心模块：**
- `core/`：Agent 基类、状态定义、消息结构、会话管理
- `llm/`：统一客户端接口、多模型适配、流式输出
- `memory/`：分层记忆架构、记忆压缩
- `tools/`：工具基类、执行器、沙箱、内置工具、平台 API 工具
- `roles/`：角色加载（从 YAML）、注册表、实例化工厂
- `shared_rules/`：系统级共享规则（YAML，schema + content 分离）
- `role_store/`：系统级角色定义（YAML）
- `runtime/`：执行器、Agent 级工作流引擎、群聊管理、生命周期

---

### 2. quantalithos-flow — 流程编排引擎

**职责：**
- 阶段状态机（Pipeline Template 驱动，配置化阶段定义，非硬编码枚举）
- 工作流模板解析与执行（Workflow Template，daemon 驱动多 Agent 协作）
- step 调度器（触发、推进、回退、循环）
- 门禁控制（hard / soft / none，done_when、output_schema 校验）
- 交接包管理（阶段间产物传递）
- 流程模型动态编排（TL 提议 → flow 编译 → WorkflowInstance）
- 任务状态机（created → assigned → in_development → ... → completed）
- 消息路由与参与度控制（mention_only / free / round_robin / muted）
- 项目级快照与恢复（snapshots/workflow/）

**技术栈：** Python

**核心模块：**
- `pipeline/`：Pipeline Template 加载、阶段流转、门禁校验
- `workflow/`：Workflow Template 解析、WorkflowInstance 管理、step 调度
- `task/`：任务状态机、TaskProvider 客户端
- `router/`：消息路由、参与度控制
- `snapshot/`：流程快照保存与恢复
- `compiler/`：TL 提议 → 编译为可执行流程
- `daemon/`：主进程、事件循环、与 runtime 通信

**两层分离设计：**
```
Pipeline Template（阶段模板）— 定义项目经过哪些阶段、什么门禁
  standard.yaml:  alignment → requirement → design → dev → accept → release
  hotfix.yaml:    fix → verify → release

Workflow Template（工作流模板）— 定义阶段内部怎么一步步做
  requirement_analysis.yaml:    collect → brainstorm → write_prd → review
  iterative_development.yaml:   implement → code_review → testing
```

### 3. quantalithos-chat — 聊天前端

**职责：**
- 用户与 Assistant 的私聊界面
- 项目群聊界面（多 Agent + 用户）
- 频道管理、消息展示
- 门禁确认交互组件
- 产物预览（PRD、代码、测试报告等）
- 看板视图（从任务卡 frontmatter 解析）

**技术栈：** React + TypeScript + TailwindCSS

**核心模块：**
- `private-chat/`：私聊组件
- `group-chat/`：群聊组件
- `channel/`：频道管理
- `message-renderer/`：消息渲染（富文本、代码、产物卡片）
- `gate-confirm/`：门禁确认组件
- `artifact-preview/`：产物预览组件
- `kanban/`：看板视图

---

### 4. quantalithos-platform — 平台数据服务

**职责：**
- 产物 CRUD（PRD、方案、代码、测试报告等）
- 版本控制集成（Git）
- 产物索引与搜索
- 云端资产库对接

**技术栈：** Python / Go + PostgreSQL + S3/MinIO

**核心模块：**
- `artifact-store/`：产物存储
- `version-control/`：版本控制集成
- `search-engine/`：产物搜索
- `cloud-asset-connector/`：云端资产库连接器

---

### 5. quantalithos-gate — API 网关

**职责：**
- 用户认证与授权（SSO/OAuth）
- WebSocket 连接管理（实时消息）
- 请求路由与负载均衡
- 权限校验（RBAC）
- 日志与监控

**技术栈：** Go / Node.js

**核心模块：**
- `auth/`：认证授权
- `websocket/`：WebSocket 连接管理
- `router/`：请求路由
- `rbac/`：权限控制
- `logger/`：日志记录

---

### 6. quantalithos-sync — 工作区同步工具

**职责：**
- 项目工作区的一键恢复与同步
- 从多数据源按需拉取（Git 仓库、云端配置库、快照库、任务库、文档库）
- 本地变更推送到云端
- 项目配置文件（manifest）解析与驱动
- 跨机器项目恢复
- 与 daemon 集成（项目启动时 restore，变更时 push）

**技术栈：** Rust

**核心模块：**
- `manifest/`：项目配置文件解析
- `sync/`：同步引擎（Git 同步、云端同步、快照同步）
- `client/`：云端服务客户端（配置服务、快照服务、任务服务）
- `cli/`：命令行接口

**本地项目目录结构（sync 管理）：**
```
project_files/{project}/
├── agents/          # Agent 配置 → 云端：AI 编排与知识平台（双向同步）
├── docs/            # 项目文档 → 云端：研发协作平台 / 文档库（双向同步）
├── tasks/           # 任务镜像 → 云端：研发协作平台 / 任务库（双向同步）
├── snapshots/       # 快照 → 云端：AI 编排与知识平台 / 快照库（push 为主）
└── workspace/       # 工作区 → 云端：工程执行平台 / 代码库（Git，不走 sync）
```

**命令行接口：**
```bash
quantalithos-sync restore <project>                      # 一键恢复项目
quantalithos-sync restore <project> --only git,agents    # 部分恢复
quantalithos-sync push <project>                         # 推送本地变更到云端
quantalithos-sync status <project>                       # 查看同步状态
```

**项目配置文件（manifest）示例：**
```yaml
# agents/manifest.yaml
project_id: blog-project
project_name: "博客系统"
pipeline_id: standard

task_provider:
  type: platform_api          # platform_api | local_file | jira | zentao
  config:
    base_url: "http://localhost:8080/api"

sources:
  git:
    repo: "git@github.com:company/blog-backend.git"
    branch: "develop"
    target_dir: "workspace/"
  agent_config:
    service: "config-service"
    namespace: "projects/blog-project/agents"
    target_dir: "agents/"
  snapshot:
    service: "snapshot-service"
    namespace: "projects/blog-project/snapshots"
    target_dir: "snapshots/"
  tasks:
    service: "task-service"
    namespace: "projects/blog-project/tasks"
    target_dir: "tasks/"
  docs:
    service: "doc-service"
    namespace: "projects/blog-project/docs"
    target_dir: "docs/"
```

## 三、仓库依赖关系图

```
                    ┌─────────────────┐
                    │  quantalithos-chat   │
                    │   (聊天前端)     │
                    └────────┬────────┘
                             │ HTTP/WebSocket
                             ▼
                    ┌─────────────────┐
                    │  quantalithos-gate   │
                    │   (API 网关)     │
                    └────────┬────────┘
                             │
            ┌────────────────┼────────────────┐
            │                │                │
            ▼                ▼                ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
   │   quantalithos-   │  │   quantalithos-   │  │   quantalithos-   │
   │   runtime    │  │    flow      │  │   platform   │
   │ (Agent运行时) │  │ (流程引擎)    │  │ (平台数据服务) │
   └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                   ┌────────┴────────┐
                   │                 │
                   ▼                 ▼
          ┌──────────────┐  ┌──────────────┐
          │ quantalithos-sync │  │ quantalithos-infra│
          │ (工作区同步)   │  │ (基础设施)    │
          └──────────────┘  └──────────────┘
```

**quantalithos-sync 在架构中的位置：**
- 被 quantalithos-flow（daemon）调用：项目启动时 restore，变更时 push
- 被 quantalithos-runtime 间接依赖：Agent 工作区的文件来自 sync 拉取
- 独立 CLI 工具：用户也可手动执行同步操作

## 四、轻量化方案（5 仓库）

如果初期团队较小，可合并为 5 个仓库：

| 仓库 | 包含 |
|------|------|
| **quantalithos-chat** | 前端 + WebSocket 连接 |
| **quantalithos-platform** | quantalithos-runtime + quantalithos-flow |
| **quantalithos-platform** | 产物服务 + 存储 |
| **quantalithos-sync** | 工作区同步工具（独立，Rust） |
| **quantalithos-infra** | 基础设施 + 网关 |

---

## 五、待确认的扩展需求

以下功能可能需要额外仓库或模块：

1. **代码执行沙箱**
   - 安全运行 Agent 生成的代码
   - 可能独立为模块，或集成到 quantalithos-runtime 的 Rust 模块中

2. **消息队列服务**
   - 异步任务处理、Agent 间消息传递
   - 可使用 Kafka / RabbitMQ

3. **知识库服务**
   - RAG 向量存储、公司内部文档索引
   - 可能独立为模块，或集成到 quantalithos-platform

## 六、开发优先级建议

### Phase 1：最小可用原型（MVP）
1. `quantalithos-chat`（简化版私聊 + 群聊）
2. `quantalithos-runtime`（Assistant + Tech Lead 两个角色）
3. `quantalithos-infra`（基础部署）

### Phase 2：完整流程
4. `quantalithos-flow`（六阶段流程 + daemon）
5. `quantalithos-gate`（认证 + WebSocket）

### Phase 3：产物与同步
6. `quantalithos-platform`
7. `quantalithos-sync`
8. 扩展 Agent 角色

### Phase 4：扩展能力
9. 知识库、沙箱等

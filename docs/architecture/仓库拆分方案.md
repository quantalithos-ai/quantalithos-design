# 项目仓库拆分方案

> 基于 AI 驱动研发协作平台设计文档，梳理完整实现所需的仓库拆分方案。

---

## 一、整体架构概览

本项目是一个 **AI 驱动的软件研发协作平台**，核心交互形态为：

```
用户 ←→ AI助手(Assistant) ←→ 群聊(多个Agent协作)
```

### 核心功能
- 私聊入口：用户与 Assistant 一对一对话
- 群聊协作：项目群组内多 Agent + 用户协作
- 六阶段流程：项目启动 → 需求理解 → 方案拆解 → 迭代开发 → 验收确认 → 发布执行
- 产物管理：PRD、设计文档、代码、测试报告等全生命周期管理
- 工作区管理：项目配置、快照、文档、任务的跨机器同步与恢复

## 二、推荐仓库拆分（7 仓库方案）

### 1. quantalithos-runtime — Agent 运行时

**职责：**
- Agent 生命周期管理（实例化、销毁、持久化）
- Agent 角色定义与 Prompt 管理（三层架构）
- LLM 调用封装（多模型支持、流式输出、成本追踪）
- 工具调用系统（工具注册、执行、沙箱隔离）
- 记忆系统（对话记忆、长期记忆）
- step 内部的 think → act 循环

**技术栈：** Python 为主 + Rust 关键模块（PyO3）

**核心模块：**
- `core/`：Agent 基类、状态定义、消息结构、会话管理
- `llm/`：统一客户端接口、多模型适配、流式输出
- `memory/`：分层记忆架构、记忆压缩
- `tools/`：工具基类、执行器、沙箱、内置工具
- `roles/`：角色定义（数据化，非代码化）
- `prompts/`：三层 Prompt 架构（共享规则 / 角色定义 / 角色权限）
- `runtime/`：执行器、消息路由、群聊管理、生命周期

---

### 2. quantalithos-flow — 流程编排引擎

**职责：**
- 阶段状态机（阶段 0 → 阶段 5 的流转）
- 工作流模板解析与执行（daemon 驱动）
- step 调度器（触发、推进、回退、循环）
- 门禁控制（用户审批、done_when、output_schema 校验）
- 交接包管理（阶段间产物传递）
- 流程模型动态编排（TL 提议 → runtime 编译 → workflow instance）
- 任务树调度（依赖、并行）

**技术栈：** Python / Go

**核心模块：**
- `stage-machine/`：阶段管理与状态流转
- `workflow-engine/`：工作流模板解析、step 调度
- `gate-controller/`：门禁控制（硬门禁 / 软门禁）
- `handoff-manager/`：交接包管理
- `task-scheduler/`：任务树调度
- `flow-compiler/`：WorkflowProposal → CompiledWorkflow

---

### 3. quantalithos-chat — 聊天前端

**职责：**
- 用户与 Assistant 的私聊界面
- 项目群聊界面（多 Agent + 用户）
- 频道管理、消息展示
- 门禁确认交互组件
- 产物预览（PRD、代码、测试报告等）
- 看板视图（从任务卡 frontmatter 解析）

**技术栈：** React + TypeScript + TailwindCSS

**核心模块：**
- `private-chat/`：私聊组件
- `group-chat/`：群聊组件
- `channel/`：频道管理
- `message-renderer/`：消息渲染（富文本、代码、产物卡片）
- `gate-confirm/`：门禁确认组件
- `artifact-preview/`：产物预览组件
- `kanban/`：看板视图

---

### 4. quantalithos-vault — 产物管理服务

**职责：**
- 产物 CRUD（PRD、方案、代码、测试报告等）
- 版本控制集成（Git）
- 产物索引与搜索
- 云端资产库对接

**技术栈：** Python / Go + PostgreSQL + S3/MinIO

**核心模块：**
- `artifact-store/`：产物存储
- `version-control/`：版本控制集成
- `search-engine/`：产物搜索
- `cloud-asset-connector/`：云端资产库连接器

---

### 5. quantalithos-gate — API 网关

**职责：**
- 用户认证与授权（SSO/OAuth）
- WebSocket 连接管理（实时消息）
- 请求路由与负载均衡
- 权限校验（RBAC）
- 日志与监控

**技术栈：** Go / Node.js

**核心模块：**
- `auth/`：认证授权
- `websocket/`：WebSocket 连接管理
- `router/`：请求路由
- `rbac/`：权限控制
- `logger/`：日志记录

---

### 6. quantalithos-sync — 工作区同步工具

**职责：**
- 项目工作区的一键恢复与同步
- 从多数据源按需拉取（Git 仓库、云端配置库、快照库、任务库、文档库）
- 本地变更推送到云端
- 项目配置文件（manifest）解析与驱动
- 跨机器项目恢复
- 与 daemon 集成（项目启动时 restore，变更时 push）

**技术栈：** Rust

**核心模块：**
- `manifest/`：项目配置文件解析
- `sync/`：同步引擎（Git 同步、云端同步、快照同步）
- `client/`：云端服务客户端（配置服务、快照服务、任务服务）
- `cli/`：命令行接口

**命令行接口：**
```bash
quantalithos-sync restore <project>           # 一键恢复项目
quantalithos-sync restore <project> --only git,agent  # 部分恢复
quantalithos-sync push <project>              # 推送本地变更到云端
quantalithos-sync status <project>            # 查看同步状态
```

**项目配置文件（manifest）示例：**
```yaml
# ~/.quantalithos/projects/blog-project.yaml
project_id: blog-project
project_name: "博客系统"
sources:
  git:
    repo: "git@github.com:company/blog-backend.git"
    branch: "develop"
    target_dir: "git/"
  agent_config:
    service: "config-service"
    namespace: "projects/blog-project/agent"
    target_dir: "agent/"
  snapshot:
    service: "snapshot-service"
    namespace: "projects/blog-project/snapshot"
    target_dir: "snapshot/"
  tasks:
    service: "task-service"
    namespace: "projects/blog-project/tasks"
    target_dir: "tasks/"
```

### 7. quantalithos-infra — 基础设施

**职责：**
- Docker / Kubernetes 配置
- CI/CD 流水线
- 监控告警（Prometheus + Grafana）
- 日志收集（ELK）
- 数据库迁移脚本

**技术栈：** Terraform / Helm / Docker Compose

**核心模块：**
- `docker/`：Docker 配置
- `k8s/`：Kubernetes 配置
- `ci-cd/`：CI/CD 流水线
- `monitoring/`：监控配置
- `migrations/`：数据库迁移

## 三、仓库依赖关系图

```
                    ┌─────────────────┐
                    │  quantalithos-chat   │
                    │   (聊天前端)     │
                    └────────┬────────┘
                             │ HTTP/WebSocket
                             ▼
                    ┌─────────────────┐
                    │  quantalithos-gate   │
                    │   (API 网关)     │
                    └────────┬────────┘
                             │
            ┌────────────────┼────────────────┐
            │                │                │
            ▼                ▼                ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
   │   quantalithos-   │  │   quantalithos-   │  │   quantalithos-   │
   │   runtime    │  │    flow      │  │    vault     │
   │ (Agent运行时) │  │ (流程引擎)    │  │ (产物服务)    │
   └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                   ┌────────┴────────┐
                   │                 │
                   ▼                 ▼
          ┌──────────────┐  ┌──────────────┐
          │ quantalithos-sync │  │ quantalithos-infra│
          │ (工作区同步)   │  │ (基础设施)    │
          └──────────────┘  └──────────────┘
```

**quantalithos-sync 在架构中的位置：**
- 被 quantalithos-flow（daemon）调用：项目启动时 restore，变更时 push
- 被 quantalithos-runtime 间接依赖：Agent 工作区的文件来自 sync 拉取
- 独立 CLI 工具：用户也可手动执行同步操作

## 四、轻量化方案（5 仓库）

如果初期团队较小，可合并为 5 个仓库：

| 仓库 | 包含 |
|------|------|
| **quantalithos-chat** | 前端 + WebSocket 连接 |
| **quantalithos-platform** | quantalithos-runtime + quantalithos-flow |
| **quantalithos-vault** | 产物服务 + 存储 |
| **quantalithos-sync** | 工作区同步工具（独立，Rust） |
| **quantalithos-infra** | 基础设施 + 网关 |

---

## 五、待确认的扩展需求

以下功能可能需要额外仓库或模块：

1. **代码执行沙箱**
   - 安全运行 Agent 生成的代码
   - 可能独立为模块，或集成到 quantalithos-runtime 的 Rust 模块中

2. **消息队列服务**
   - 异步任务处理、Agent 间消息传递
   - 可使用 Kafka / RabbitMQ

3. **知识库服务**
   - RAG 向量存储、公司内部文档索引
   - 可能独立为模块，或集成到 quantalithos-vault

## 六、开发优先级建议

### Phase 1：最小可用原型（MVP）
1. `quantalithos-chat`（简化版私聊 + 群聊）
2. `quantalithos-runtime`（Assistant + Tech Lead 两个角色）
3. `quantalithos-infra`（基础部署）

### Phase 2：完整流程
4. `quantalithos-flow`（六阶段流程 + daemon）
5. `quantalithos-gate`（认证 + WebSocket）

### Phase 3：产物与同步
6. `quantalithos-vault`
7. `quantalithos-sync`
8. 扩展 Agent 角色

### Phase 4：扩展能力
9. 知识库、沙箱等

# 项目仓库拆分方案

> 基于 AI 驱动研发协作平台设计文档，梳理完整实现所需的仓库拆分方案。

---

## 一、整体架构概览

本项目是一个 **AI 驱动的软件研发协作平台**，核心交互形态为：

```
用户 ←→ AI助手(Assistant) ←→ 群聊(多个Agent协作)
```

### 核心功能
- 私聊入口：用户与 Assistant 一对一对话
- 群聊协作：项目群组内多 Agent + 用户协作
- 六阶段流程：项目启动 → 需求理解 → 方案拆解 → 迭代开发 → 验收确认 → 发布执行
- 产物管理：PRD、设计文档、代码、测试报告等全生命周期管理

---

## 二、推荐仓库拆分（6 仓库方案）

### 1. chat-frontend — 聊天前端

**职责：**
- 用户与 Assistant 的私聊界面
- 项目群聊界面（多 Agent + 用户）
- 频道管理、消息展示
- 门禁确认交互组件
- 产物预览（PRD、代码、测试报告等）

**技术栈建议：** React / Vue + TypeScript

**核心模块：**
- `private-chat`：私聊组件
- `group-chat`：群聊组件
- `channel`：频道管理
- `message-renderer`：消息渲染（支持富文本、代码、产物卡片）
- `gate-confirm`：门禁确认组件
- `artifact-preview`：产物预览组件

---

### 2. agent-runtime — Agent 运行时

**职责：**
- Agent 生命周期管理（实例化、销毁）
- Agent 角色定义与 Prompt 管理
- LLM 调用封装
- 工具调用（Tool Use）
- 多 Agent 协作编排
- 状态机管理

**技术栈建议：** Python / TypeScript

**核心模块：**
- `agent-core`：Agent 核心抽象
- `roles/`：角色定义（Assistant、Tech Lead、Backend Dev、Frontend Dev、Tester、DevOps）
- `prompt-manager`：Prompt 模板管理
- `llm-client`：LLM 调用封装
- `tool-registry`：工具注册与调用
- `state-machine`：Agent 状态机

---

### 3. workflow-engine — 工作流引擎

**职责：**
- 流程模板定义（YAML/JSON Schema）
- 流程实例化与执行
- 阶段门禁控制
- 阶段间交接包传递
- 回退/升级路由
- 任务树调度

**技术栈建议：** Python / Go / Java

**核心模块：**
- `workflow-schema`：流程定义 Schema
- `stage-manager`：阶段管理
- `gate-controller`：门禁控制
- `handoff-manager`：交接包管理
- `task-scheduler`：任务调度
- `route-handler`：路由处理（回退/升级）

---

### 4. artifact-service — 产物管理服务

**职责：**
- 产物 CRUD（PRD、方案、代码、测试报告...）
- 版本控制集成（Git）
- 产物索引与搜索
- 云端资产库对接

**技术栈建议：** Python / Go + PostgreSQL + S3/MinIO

**核心模块：**
- `artifact-store`：产物存储
- `version-control`：版本控制集成
- `search-engine`：产物搜索
- `cloud-asset-connector`：云端资产库连接器

---

### 5. gateway-service — API 网关

**职责：**
- 用户认证与授权（SSO/OAuth）
- WebSocket 连接管理（实时消息）
- 请求路由与负载均衡
- 权限校验（RBAC）
- 日志与监控

**技术栈建议：** Go / Node.js

**核心模块：**
- `auth`：认证授权
- `websocket`：WebSocket 连接管理
- `router`：请求路由
- `rbac`：权限控制
- `logger`：日志记录

---

### 6. infra — 基础设施

**职责：**
- Docker / Kubernetes 配置
- CI/CD 流水线
- 监控告警（Prometheus + Grafana）
- 日志收集（ELK）
- 数据库迁移脚本

**技术栈建议：** Terraform / Helm / Docker Compose

**核心模块：**
- `docker/`：Docker 配置
- `k8s/`：Kubernetes 配置
- `ci-cd/`：CI/CD 流水线
- `monitoring/`：监控配置
- `migrations/`：数据库迁移

## 四、轻量化方案（4 仓库）

如果初期团队较小，可合并为 4 个仓库：

| 仓库 | 包含 |
|------|------|
| **chat-app** | 前端 + WebSocket 连接 |
| **agent-platform** | agent-runtime + workflow-engine |
| **artifact-store** | 产物服务 + 存储 |
| **infra** | 基础设施 |

---

## 五、待确认的扩展需求

以下功能可能需要额外仓库或模块：

1. **代码执行沙箱**
   - 安全运行 Agent 生成的代码
   - 可能独立为 `sandbox-service`

2. **消息队列服务**
   - 异步任务处理
   - Agent 间消息传递
   - 可使用 Kafka / RabbitMQ

3. **知识库服务**
   - RAG 向量存储
   - 公司内部文档索引
   - 可能独立为 `knowledge-service`

4. **代码仓库服务**
   - Git 仓库托管
   - 或对接现有 GitLab/GitHub

---

## 六、开发优先级建议

### Phase 1：最小可用原型（MVP）
1. `chat-frontend`（简化版私聊 + 群聊）
2. `agent-runtime`（Assistant + Tech Lead 两个角色）
3. `infra`（基础部署）

### Phase 2：完整流程
4. `workflow-engine`（六阶段流程）
5. `gateway-service`（认证 + WebSocket）

### Phase 3：产物与扩展
6. `artifact-service`
7. 扩展 Agent 角色
8. 知识库、沙箱等

# 项目仓库拆分方案

> 基于 AI 驱动研发协作平台设计文档，梳理完整实现所需的仓库拆分方案。

---

## 一、整体架构概览

本项目是一个 **AI 驱动的软件研发协作平台**，核心交互形态为：

```
用户 ←→ AI助手(Assistant) ←→ 群聊(多个Agent协作)
```

### 核心功能
- 私聊入口：用户与 Assistant 一对一对话
- 群聊协作：项目群组内多 Agent + 用户协作
- 六阶段流程：项目启动 → 需求理解 → 方案拆解 → 迭代开发 → 验收确认 → 发布执行
- 工单管理：需求、任务、BUG 全生命周期管理
- 产物管理：PRD、设计文档、代码、测试报告等
- 工作区管理：项目配置、快照、文档、任务的跨机器同步与恢复

## 二、推荐仓库拆分（8 仓库方案）

### 1. quantalithos-runtime — Agent 运行时

**职责：**
- Agent 生命周期管理（实例化、挂起、恢复、销毁）
- Agent 角色定义与 Prompt 管理（shared_rules + role_store，全 YAML，schema + content 分离）
- LLM 调用封装（多模型支持、流式输出、成本追踪）
- 工具调用系统（工具注册、执行、沙箱隔离、两层权限校验）
- 记忆系统（Phase 1 内存、Phase 2 数据库、Phase 3 向量库）
- Agent 级工作流引擎（加载 ProcessDefinition，按 nodes + edges 驱动单 Agent 执行）
- 节点内部的 think → act 循环
- 动态工具注册（submit_step_result、ask_teammate）

**技术栈：** Phase 1 纯 Python，Phase 2 按需引入 Rust（PyO3）

**核心模块：**
- `core/`：Agent 基类、状态定义、消息结构、会话管理
- `llm/`：统一客户端接口、多模型适配、流式输出
- `memory/`：分层记忆架构、记忆压缩
- `tools/`：工具基类、执行器、沙箱、内置工具、submit_step_result、ask_teammate
- `roles/`：角色加载（从 YAML）、注册表、实例化工厂
- `shared_rules/`：系统级共享规则（YAML，schema + content 分离）
- `role_store/`：系统级角色定义（YAML）
- `runtime/`：执行器、Agent 级工作流引擎、群聊管理、生命周期

---

### 2. quantalithos-flow — BPMN 流程引擎

**职责：**
- BPMN 2.0 流程引擎（ProcessDefinition = nodes + edges）
- 三层流程模型：项目流程 → 阶段流程 → Agent 流程，全部是 ProcessDefinition
- 节点处理：EventNode / ActivityNode / GatewayNode
- 门禁控制（Exclusive Gateway + gate_config，hard / soft）
- 任务调度（TaskInstance、依赖图、波次调度、并行执行）
- 三种交互模式：任务执行(solo) / 协作会议(collaboration) / 即时沟通(ask_teammate)
- 项目级快照与恢复

**技术栈：** Python

**核心模块：**
- `engine/`：BPMN 流程引擎（节点处理器、边遍历、实例管理）
- `process/`：ProcessDefinition 加载、编译、实例化
- `task/`：TaskInstance、依赖图、波次调度
- `gate/`：门禁控制（GateRequest / GateCard / 审批流程）
- `session/`：协作会议管理（Ad-Hoc Sub-Process + session 扩展）
- `snapshot/`：流程快照保存与恢复
- `daemon/`：主进程、事件循环、与 runtime 通信

---

### 3. quantalithos-platform — 平台数据服务

**职责：**
- 项目管理（项目 CRUD、团队配置、阶段进度）
- 工单管理（需求、任务、BUG，状态机校验）
- 产物管理（文档、报告、代码，版本控制）
- Agent 配置管理（角色定义、共享规则、流程模板，三级覆盖）
- 快照管理（Agent 快照、流程快照）
- 知识库（Phase 2，RAG、向量存储）
- API 多视图（/views/ai、/views/card、默认完整数据）
- 事件总线（模块间异步通信）

**技术栈：** Rust（axum + sqlx + tokio + PostgreSQL + MinIO）

**核心模块（模块化 crate）：**
- `hub-project/`：项目管理
- `hub-workitem/`：工单管理
- `hub-artifact/`：产物管理
- `hub-agent-config/`：Agent 配置管理
- `hub-snapshot/`：快照管理
- `hub-api/`：统一 API 层（RESTful 资源嵌套路由）
- `hub-common/`：共享类型、事件总线
- `hub-knowledge/`：知识库（Phase 2）

---

### 4. quantalithos-sdk — 跨平台客户端 SDK

**职责：**
- 所有客户端与 platform 交互的统一基础库
- 数据模型定义（所有端共享）
- platform API 客户端（sync 和 chat 复用）
- WebSocket 连接管理（自动重连、订阅）
- 状态管理（聊天、工单、门禁、通知）
- WASM 绑定（浏览器端）
- UniFFI 绑定（iOS/Android，Phase 3）

**技术栈：** Rust（模块化 crate）

**核心模块：**
- `sdk-models/`：数据模型（零依赖，纯 serde）
- `sdk-api/`：platform API 客户端（reqwest）
- `sdk-ws/`：WebSocket 连接管理（tokio-tungstenite）
- `sdk-store/`：状态管理（业务逻辑层）
- `sdk-wasm/`：WASM 绑定（wasm-bindgen）

---

### 5. quantalithos-chat — 聊天前端

**职责：**
- 飞书式三栏布局（功能导航 + 会话列表 + 主内容区）
- 用户与 Assistant 私聊（发起新项目）
- 项目群聊（Agent 消息、内嵌卡片、门禁审批）
- 工单看板（按状态分栏）
- 项目进度（Pipeline 进度条 + 阶段任务流水线）
- 产物查看（文档预览）

**技术栈：** Vue 3 + Vite + Naive UI + Pinia + Tauri(Phase 2)

**核心模块：**
- `sdk/`：SDK 薄封装（初始化 WASM、TS 类型映射）
- `stores/`：Pinia 状态管理（conversation、chat、kanban、progress、gate）
- `layouts/`：布局组件（AppLayout、NavBar、ConvList、MainContent）
- `views/`：页面组件（ChatView、KanbanView、ProgressView、ArtifactView）
- `components/`：通用组件（MessageBubble、GateCard、WorkitemCard、ProgressBar）

---

### 6. quantalithos-gate — API 网关

**职责：**
- JWT 认证（签发、校验、刷新）
- 请求路由（upstream 服务池 + 路径前缀匹配）
- WebSocket 两层管理（外层客户端多路复用 + 内层后端事件通道）
- 限流保护（Token Bucket、请求体限制、超时控制）
- CORS 配置
- 请求日志（JSON 结构化 + X-Request-Id 跨服务追踪）

**技术栈：** Rust（axum）

**核心模块：**
- `auth/`：JWT 签发与校验、认证中间件
- `router/`：路由配置加载、HTTP 反向代理
- `ws/`：WebSocket 会话管理、订阅、事件广播
- `ratelimit/`：Token Bucket 限流
- `logging/`：请求日志中间件

---

### 7. quantalithos-sync — 工作区同步工具

**职责：**
- 项目工作区的初始化、恢复与双向同步
- manifest.yaml 驱动
- 从 platform API 拉取数据到本地目录
- 本地变更推送到 platform
- Git 仓库管理（workspace/ 目录）

**技术栈：** Rust CLI（clap + reqwest + git2）

**核心模块：**
- `cli/`：命令行定义（init / restore / pull / push / status）
- `manifest/`：manifest.yaml 解析
- `sync_engine/`：同步引擎（差异检测、冲突处理）
- `providers/`：数据源适配（agents / docs / tasks / snapshots）
- `git/`：Git 操作（clone / pull / push / branch）
- `client/`：platform API 客户端（Phase 2 迁移到 sdk-api）

**本地项目目录结构（sync 管理）：**
```
project_files/{project}/
├── agents/          # Agent 配置 → 云端（双向同步）
├── docs/            # 项目文档 → 云端（双向同步）
├── tasks/           # 任务镜像 → 云端（双向同步）
├── snapshots/       # 快照 → 云端（push 为主）
└── workspace/       # 工作区 → Git（不走 sync）
```

---

### 8. quantalithos-infra — 基础设施

**职责：**
- Docker Compose 本地开发一键启动
- Dockerfile（gate / platform / flow / runtime / chat）
- 数据库迁移脚本 + 初始数据
- CI/CD 流水线（GitHub Actions）
- 环境变量管理（dev / staging / prod）
- 监控告警（Phase 2，Prometheus + Grafana + Loki）

**技术栈：** Docker Compose + GitHub Actions，Phase 2 K8s

**核心模块：**
- `docker/`：Docker Compose + Dockerfile
- `db/`：数据库迁移 + 初始数据
- `ci/`：CI/CD 配置
- `scripts/`：运维脚本（setup-dev.sh、backup-db.sh）
- `envs/`：环境变量配置
- `k8s/`：Kubernetes 配置（Phase 2）
- `monitoring/`：Prometheus + Grafana（Phase 2）

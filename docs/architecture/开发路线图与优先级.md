# 开发路线图与优先级

> 基于 AI 驱动研发协作平台的 8 个子项目，制定开发步骤与优先级规划。

---

## 一、开发原则

1. **先跑通再迭代**：每个阶段都要有可运行的产物
2. **核心路径优先**：先打通用户 → SDK → gate → platform → flow → runtime → Agent 的主链路
3. **逐步增加复杂度**：从单角色到多角色，从线性流程到 BPMN 完整流程
4. **技术债务可控**：每个阶段结束后进行必要重构

## 三、Phase 1：全链路最小闭环

**目标：** 用户能通过 chat 与 Assistant 对话，发起项目，Agent 按流程执行任务，用户能审批门禁

**周期：** 6-8 周

### 启动顺序

```
Week 1-2: 基础设施 + 数据层
  infra（Docker Compose + DB 迁移）
  platform（项目/工单/产物/Agent配置 CRUD）
  sdk-models + sdk-api（数据模型 + API 客户端）

Week 3-4: 引擎层
  runtime（Agent 基类 + LLM 调用 + 工具系统 + Assistant/TL 角色）
  flow（ProcessDefinition 加载 + 节点调度 + 门禁 + NodeAssignment/NodeResult）

Week 5-6: 接入层
  gate（JWT 认证 + 静态路由 + 反向代理）
  sdk-wasm（WASM 绑定）
  chat（三栏布局 + 私聊 + 群聊 + 门禁卡片）

Week 7-8: 联调 + 修复
  全链路联调
  sync（init + restore 基础功能）
```

### 各子项目 Phase 1 范围

| 子项目 | Phase 1 范围 |
|--------|-------------|
| infra | Docker Compose（PostgreSQL + Redis + MinIO）、DB 迁移、初始数据、setup-dev.sh |
| platform | 6 模块 CRUD API + 多视图（/views/ai、/views/card）+ 事件总线（进程内） |
| sdk | sdk-models（全部数据模型）+ sdk-api（全部 API 客户端）+ sdk-wasm（基础绑定） |
| runtime | Agent 基类、LLM 调用、工具系统、submit_step_result、ask_teammate、Assistant + TL 角色、Agent 级工作流引擎 |
| flow | ProcessDefinition 加载、节点调度（ActivityNode + GatewayNode）、门禁控制、NodeAssignment/NodeResult、TaskInstance 基础调度 |
| gate | JWT 认证、静态路由、HTTP 反向代理、CORS、请求日志 |
| chat | 三栏布局、Assistant 私聊、项目群聊、消息收发（轮询）、门禁审批卡片、工单看板、项目进度 |
| sync | init + restore 基础功能、manifest 解析 |

### Phase 1 验收标准

- [ ] 用户可以在 chat 中与 Assistant 对话
- [ ] Assistant 能按工作流执行启动流程（识别意图 → 收集信息 → 创建项目）
- [ ] 项目群聊创建，Tech Lead 加入
- [ ] TL 能执行目标校准，产出 goal_alignment_brief
- [ ] 阶段能按 ProcessDefinition 推进（alignment → requirement）
- [ ] 门禁卡片能在 chat 中展示，用户能确认/驳回
- [ ] 工单能创建、分配、状态流转
- [ ] 看板能展示工单状态
- [ ] 进度页能展示 Pipeline 进度
- [ ] `quantalithos-sync init` 能创建本地项目目录

### Phase 1 技术栈

```
chat:      Vue 3 + Vite + Naive UI + Pinia + @quantalithos/sdk-wasm
sdk:       Rust (sdk-models + sdk-api + sdk-wasm)
gate:      Rust (axum + jsonwebtoken)
platform:  Rust (axum + sqlx + tokio)
flow:      Python (asyncio)
runtime:   Python (asyncio + Pydantic + structlog)
infra:     Docker Compose + PostgreSQL + Redis + MinIO
```

## 四、Phase 2：完善与扩展

**目标：** BPMN 完整流程、WebSocket 实时推送、多 Agent 并行、Tauri 桌面端

**周期：** 6-8 周

### 各子项目 Phase 2 范围

| 子项目 | Phase 2 范围 |
|--------|-------------|
| infra | K8s 配置、Prometheus + Grafana + Loki、CI/CD 完整流水线 |
| platform | 事件总线（Redis Pub/Sub）、知识库模块、产物搜索、版本历史 |
| sdk | sdk-ws（WebSocket）+ sdk-store（状态管理）+ sdk-wasm 完整绑定 |
| runtime | 更多角色（Backend Dev、Frontend Dev、Tester、DevOps）、记忆持久化（DB）、Agent 快照/恢复 |
| flow | BPMN Level 2（Parallel Gateway、Boundary Event、Service Task）、并行任务调度、动态流程编译 |
| gate | WebSocket 两层管理、OAuth 集成、健康检查 |
| chat | WebSocket 实时推送、Tauri 桌面端、看板拖拽、产物预览、虚拟滚动 |
| sync | pull/push 增量同步、daemon 集成、迁移到 sdk-api |

### Phase 2 验收标准

- [ ] 完整六阶段流程可运行（alignment → release）
- [ ] 多 Agent 并行开发（阶段 3 多任务并行）
- [ ] WebSocket 实时推送（消息、状态变更、门禁通知）
- [ ] Tauri 桌面端可用（系统通知、托盘）
- [ ] Agent 快照/恢复可用（用户隔天回来继续项目）
- [ ] 监控面板可用（Grafana）
- [ ] `quantalithos-sync pull/push` 增量同步可用

## 五、Phase 3：企业级能力

**目标：** 知识库、移动端、多租户、动态流程编排

**周期：** 8-12 周

### 各子项目 Phase 3 范围

| 子项目 | Phase 3 范围 |
|--------|-------------|
| platform | 多租户隔离、审计日志、API 开放平台 |
| sdk | UniFFI 绑定（Swift/Kotlin）、TS 类型自动生成、离线支持 |
| runtime | Rust 框架骨架（PyO3）、代码执行沙箱、技能自进化、长期记忆（向量库） |
| flow | BPMN Level 3（Inclusive GW、Event-based GW、Compensation、Transaction）、规范约束层 |
| gate | 服务发现（Consul/etcd）、负载均衡、熔断器、API 版本管理 |
| chat | 移动端适配、流程图交互（点击节点查看详情）、Agent 配置可视化编辑器 |
| sync | 冲突解决策略、离线操作队列 |
| infra | Helm Chart、蓝绿部署、安全扫描 |

### Phase 3 验收标准

- [ ] Agent 能查询公司内部知识库（RAG）
- [ ] 生成的代码能在沙箱中安全运行
- [ ] 移动端（iOS/Android）可用
- [ ] 多租户隔离
- [ ] 流程可动态编排（TL 提议 → flow 编译）
- [ ] Rust 框架骨架运行（性能热点下沉）

# 开发路线图与优先级

> 基于 AI 驱动研发协作平台的仓库拆分方案，制定开发步骤与优先级规划。

---

## 一、开发原则

1. **先跑通再迭代**：每个阶段都要有可运行的产物
2. **核心路径优先**：先打通用户 → Agent → 产物的主链路
3. **逐步增加复杂度**：从单角色到多角色，从线性流程到动态编排
4. **技术债务可控**：每个阶段结束后进行必要重构

## 三、Phase 1：核心交互原型（MVP）

**目标：** 用户能与 Agent 聊天，Agent 能记住上下文，能在群聊中协作

**周期：** 2-3 周

### 优先级排序

| 优先级 | 任务 | 说明 | 仓库 |
|--------|------|------|------|
| P0 | 项目脚手架搭建 | 初始化 monorepo 或多仓库结构 | infra |
| P0 | 基础聊天界面 | 私聊 + 群聊 UI，消息收发 | chat-frontend |
| P0 | Agent 核心抽象 | Agent 基类、生命周期管理 | agent-runtime |
| P0 | LLM 调用封装 | 统一调用 OpenAI/Claude/本地模型 | agent-runtime |
| P0 | 消息存储 | 基础的聊天记录持久化 | infra |
| P1 | Assistant 角色 | 入口助手，项目启动流程 | agent-runtime |
| P1 | Tech Lead 角色 | 项目负责人，需求讨论 | agent-runtime |
| P1 | 会话上下文管理 | 记忆、历史消息加载 | agent-runtime |
| P1 | WebSocket 实时通信 | 消息实时推送 | chat-frontend |
| P2 | 用户认证（简化版） | 基础登录，暂不复杂化 | infra |

### Phase 1 验收标准

- [ ] 用户可以在私聊中与 Assistant 对话
- [ ] Assistant 能创建群聊并拉入 Tech Lead
- [ ] 群聊中用户和 Agent 消息能实时同步
- [ ] Agent 能记住当前对话上下文
- [ ] 基础的聊天记录持久化

### 技术选型建议

```
chat-frontend:  React + TypeScript + TailwindCSS
agent-runtime:  Python + LangChain/LlamaIndex
infra:          Docker Compose + PostgreSQL + Redis
```

## 四、Phase 2：流程引擎与多角色

**目标：** 六阶段流程可运行，多 Agent 协作可见，门禁可控制

**周期：** 4-5 周

### 优先级排序

| 优先级 | 任务 | 说明 | 仓库 |
|--------|------|------|------|
| P0 | 流程 Schema 定义 | 阶段、节点、边、门禁的 Schema | workflow-engine |
| P0 | 阶段状态机 | 阶段推进、回退、暂停 | workflow-engine |
| P0 | 门禁控制器 | 用户确认门禁的实现 | workflow-engine |
| P0 | 交接包机制 | 阶段间产物传递 | workflow-engine |
| P0 | Backend Dev 角色 | 后端开发 Agent | agent-runtime |
| P0 | Frontend Dev 角色 | 前端开发 Agent | agent-runtime |
| P0 | Tester 角色 | 测试工程师 Agent | agent-runtime |
| P1 | 流程可视化（前端） | 当前阶段、进度展示 | chat-frontend |
| P1 | 门禁确认组件 | 用户点击确认/驳回 | chat-frontend |
| P1 | 阶段产物卡片 | PRD、方案等预览 | chat-frontend |
| P1 | 任务树调度 | 任务依赖、并行执行 | workflow-engine |
| P2 | DevOps 角色 | 部署运维 Agent | agent-runtime |
| P2 | 流程模板库 | 不同项目类型的流程模板 | workflow-engine |
| P2 | 角色动态加载 | 按需实例化 Agent | agent-runtime |

### Phase 2 验收标准

- [ ] 项目能按六阶段流程推进
- [ ] 每个阶段有明确的进入/退出条件
- [ ] 用户门禁需要显式确认
- [ ] 多 Agent 能在群聊中协作讨论
- [ ] 阶段产物（如 PRD）能生成和展示

## 五、Phase 3：产物管理与完整闭环

**目标：** 产物可存储、版本化、追溯，系统完整闭环

**周期：** 3-4 周

### 优先级排序

| 优先级 | 任务 | 说明 | 仓库 |
|--------|------|------|------|
| P0 | 产物存储服务 | CRUD + 元数据管理 | artifact-service |
| P0 | 产物类型定义 | PRD、方案、代码、测试报告等 | artifact-service |
| P0 | Git 集成 | 代码版本管理 | artifact-service |
| P0 | API 网关基础 | 统一入口、路由 | gateway-service |
| P0 | 用户认证完善 | SSO/OAuth、JWT | gateway-service |
| P0 | 权限控制 | RBAC、项目级权限 | gateway-service |
| P1 | 产物搜索 | 全文搜索、标签过滤 | artifact-service |
| P1 | 产物版本历史 | diff、回滚 | artifact-service |
| P1 | WebSocket 网关 | 实时消息推送 | gateway-service |
| P1 | 审计日志 | 操作记录追溯 | gateway-service |
| P2 | 云端资产库连接 | 对接公司现有资产库 | artifact-service |
| P2 | 产物模板 | PRD 模板、方案模板 | artifact-service |

### Phase 3 验收标准

- [ ] 所有阶段产物都能存储和检索
- [ ] 代码能关联 Git 仓库
- [ ] 用户权限正确控制（项目成员、角色权限）
- [ ] 完整的审计日志
- [ ] 系统完整闭环可用

## 六、Phase 4：扩展能力与企业级特性

**目标：** 知识库、代码沙箱、监控告警等企业级能力

**周期：** 4-6 周

### 优先级排序

| 优先级 | 任务 | 说明 | 仓库 |
|--------|------|------|------|
| P0 | 知识库服务 | RAG、向量存储、文档索引 | knowledge-service |
| P0 | 代码执行沙箱 | 安全运行生成代码 | sandbox-service |
| P0 | 监控告警 | Prometheus + Grafana | infra |
| P1 | Agent 工具扩展 | 文件操作、API 调用、数据库查询 | agent-runtime |
| P1 | 动态流程编排 | Tech Lead 提议流程，系统编译执行 | workflow-engine |
| P1 | 多项目并行 | 支持用户同时参与多个项目 | 全局 |
| P2 | CI/CD 集成 | 自动化构建部署 | infra |
| P2 | 日志分析 | ELK Stack | infra |
| P2 | 多租户隔离 | 企业级租户管理 | gateway-service |
| P2 | API 开放平台 | 外部系统集成 | gateway-service |

### Phase 4 验收标准

- [ ] Agent 能查询公司内部知识库
- [ ] 生成的代码能在沙箱中安全运行
- [ ] 系统运行状态可监控、异常可告警
- [ ] 支持多项目并行
- [ ] 流程可动态编排

## 九、风险与应对

| 风险 | 可能性 | 影响 | 应对策略 |
|------|--------|------|----------|
| LLM 调用成本过高 | 高 | 高 | 缓存、流式输出、模型选择策略 |
| Agent 行为不可控 | 中 | 高 | 严格的角色约束、工具权限控制 |
| 流程复杂度爆炸 | 中 | 中 | 先做线性流程，再迭代动态编排 |
| 实时通信稳定性 | 中 | 中 | WebSocket 重连、消息队列 |
| 知识库质量差 | 低 | 高 | 人工审核、反馈循环 |

## 十、下一步行动

### 立即开始（本周）

1. **初始化项目仓库结构**
   - 创建 `chat-frontend` 仓库
   - 创建 `agent-runtime` 仓库
   - 创建 `infra` 仓库（Docker Compose 基础配置）

2. **技术选型确认**
   - 前端框架：React vs Vue
   - Agent 框架：LangChain vs 自建
   - 数据库：PostgreSQL vs MySQL

3. **搭建开发环境**
   - 本地 Docker 开发环境
   - CI/CD 基础配置
   - 代码规范（ESLint、Prettier、Black）

### 需要确认的决策

1. 是否使用 monorepo（如 Nx/Turborepo）？
2. 是否需要对接现有的企业系统（SSO、GitLab）？
3. LLM 提供商选择（OpenAI / Azure / 本地模型）？

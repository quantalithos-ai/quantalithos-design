## 一、测试金字塔

```
          ╱╲
         ╱  ╲         端到端测试（E2E）
        ╱ E2E╲        全链路验证，数量最少，成本最高
       ╱──────╲
      ╱        ╲      集成测试
     ╱ 集成测试  ╲     服务间交互、数据库读写，数量适中
    ╱────────────╲
   ╱              ╲   单元测试
  ╱   单元测试     ╲   纯逻辑验证，数量最多，成本最低
 ╱──────────────────╲
```

| 层级 | 占比目标 | 运行频率 | 外部依赖 |
|------|---------|---------|---------|
| 单元测试 | 70% | 每次 commit | 无（全 Mock） |
| 集成测试 | 20% | 每次 PR / 阶段完成 | 数据库（Docker） |
| 端到端测试 | 10% | 联调阶段 / 发布前 | 全部服务运行 |

## 二、各子项目测试框架

| 项目 | 语言 | 测试框架 | 运行命令 | 测试目录 |
|------|------|---------|---------|---------|
| core | Python | pytest | `cd quantalithos-core && pytest` | `tests/` |
| flow | Python | pytest | `cd quantalithos-flow && pytest` | `tests/` |
| runtime | Python | pytest | `cd quantalithos-runtime && pytest` | `tests/` |
| platform | Rust | cargo test + sqlx::test | `cd quantalithos-platform && cargo test` | `tests/` + 内联 `#[cfg(test)]` |
| gate | Rust | cargo test | `cd quantalithos-gate && cargo test` | 内联 `#[cfg(test)]` |
| sandbox | Rust | cargo test | `cd quantalithos-sandbox && cargo test` | 内联 `#[cfg(test)]` |
| infra | Shell | 脚本级验证 | `cd quantalithos-infra && bash scripts/health-check.sh` | `scripts/` |

### 运行全部测试（Docker 内）

```bash
cd ~/WorkProject/quantalithos-infra

# Rust 项目测试（gate / platform / sandbox）
docker compose exec gate cargo test 2>/dev/null || echo "gate: run locally"
docker compose exec platform cargo test 2>/dev/null || echo "platform: run locally"

# Python 项目测试（core / flow / runtime）
docker compose exec runtime pytest 2>/dev/null || echo "runtime: run locally"
```

> Docker 容器内可能没有测试依赖，建议在本地运行测试。

### 本地运行测试

```bash
# Python 项目
cd ~/WorkProject/quantalithos-core && python -m pytest -v
cd ~/WorkProject/quantalithos-flow && python -m pytest -v
cd ~/WorkProject/quantalithos-runtime && python -m pytest -v

# Rust 项目
cd ~/WorkProject/quantalithos-platform && cargo test
cd ~/WorkProject/quantalithos-gate && cargo test
cd ~/WorkProject/quantalithos-sandbox && cargo test
```

## 三、Mock 策略

### 3.1 为什么需要 Mock

单元测试和部分集成测试不应依赖外部服务（LLM API、sandbox 容器、PostgreSQL）。Mock 让测试快速、确定、可重复。

### 3.2 各项目 Mock 对象

| 项目 | Mock 对象 | 替代什么 | 用途 |
|------|---------|---------|------|
| runtime | MockLLMProvider | Anthropic / OpenAI API | 返回预设的 tool_calls，不消耗 API 额度 |
| runtime | MockSandboxProvider | sandbox HTTP API | 模拟文件读写和代码执行结果 |
| runtime | MockPlatformClient | platform HTTP API | 模拟项目/工单数据 |
| flow | MockRuntimeClient | runtime HTTP API | 模拟 FlowMessage 发送和 NodeResult 返回 |
| flow | MockPlatformClient | platform HTTP API | 模拟事件轮询 |
| platform | sqlx::test | 真实 PostgreSQL | 每个测试用独立数据库（自动创建/销毁） |
| gate | MockUpstream | platform/flow/runtime | 模拟上游服务响应 |

### 3.3 Mock 使用原则

| 原则 | 说明 |
|------|------|
| 单元测试全 Mock | 不依赖任何外部服务 |
| 集成测试部分 Mock | 数据库用真实的（Docker），LLM 用 Mock |
| E2E 测试不 Mock | 全部真实服务，包括 LLM（消耗 API 额度） |
| Mock 行为要真实 | Mock 返回的数据结构必须与真实 API 一致 |

## 四、测试场景分类

### 4.1 核心链路测试（必须通过）

| # | 场景 | 涉及服务 | 类型 |
|---|------|---------|------|
| 1 | platform 项目 CRUD | platform + PostgreSQL | 集成 |
| 2 | platform 工单状态流转 | platform + PostgreSQL | 集成 |
| 3 | runtime Agent 创建 + 执行 | runtime + MockLLM + MockSandbox | 单元 |
| 4 | runtime think-act 循环 | runtime + MockLLM | 单元 |
| 5 | flow 流程启动 + 节点调度 | flow + MockRuntime + MockPlatform | 单元 |
| 6 | flow 门禁控制 | flow + MockPlatform | 单元 |
| 7 | gate JWT 认证 + 路由转发 | gate + MockUpstream | 单元 |
| 8 | gate WebSocket 连接 | gate | 单元 |
| 9 | sandbox 容器生命周期 | sandbox + Docker | 集成 |
| 10 | 全链路：创建项目 → Agent 执行 → 结果返回 | 全部 | E2E |

### 4.2 防御性测试（回归保护）

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | 重复消息幂等 | runtime 收到相同 message_id → 静默忽略 |
| 2 | LLM 超时重试 | runtime LLMClient 指数退避重试 |
| 3 | 并发工单流转 | platform 乐观锁冲突 → 409 |
| 4 | JWT 过期 | gate 返回 401 |
| 5 | sandbox 容器异常退出 | sandbox 检测并清理 |

## 六、CI 测试流水线

```
代码提交 → GitHub Actions 触发
  │
  ├── Rust 构建 + 测试（并行）
  │   ├── cargo build --workspace
  │   ├── cargo test --workspace
  │   └── cargo clippy --workspace
  │
  ├── Python 构建 + 测试（并行）
  │   ├── pip install -r requirements.txt
  │   ├── pytest --cov
  │   └── ruff check
  │
  └── 全部通过 → 允许合并
```

> CI 配置文件位于 `quantalithos-infra/.github/workflows/`。

# 代码审查要求

> 适用于所有阶段的通用代码审查标准。
> 审查者（人工或 AI）在审查代码时必须对照本文档逐项检查。

---

## 一、审查目标

代码审查不是"看一遍代码"，而是回答三个核心问题：

1. **代码是否忠实实现了设计？** — 设计一致性
2. **代码是否健壮、安全、可维护？** — 代码质量
3. **多个服务之间能否正确通信？** — 协议一致性

---

## 二、审查维度

### 维度 A：设计一致性

AI 编码最常见的问题是"偏离设计文档自由发挥"。审查者必须手持详细设计文档，逐项对比。

#### A-1 目录结构

- 代码目录结构与详细设计 §一（目录结构）一致
- 每个设计中定义的目录和文件都存在
- 没有设计中未定义的顶层模块（AI 自行添加的 `utils.rs` / `helpers.py` 需要审查是否必要）

#### A-2 数据模型

- struct / class 字段名、类型、可选性与详细设计 §二 完全匹配
- 枚举变体名称和含义与设计一致
- 没有设计中未定义的字段（AI 不得自行添加字段，除非有充分理由并更新设计）

#### A-3 接口契约

- API 路由路径、HTTP 方法、请求体、响应体与详细设计 §三 一致
- 函数签名（参数名、参数类型、返回类型）与详细设计伪代码一致
- 错误类型枚举变体和 HTTP 状态码映射与详细设计 §六 一致

#### A-4 设计模式

- 使用的设计模式与概要设计 + 设计模式使用规范一致
- 没有引入设计中未规划的模式（如 Singleton / Service Locator）

#### A-5 偏离处理

当发现代码偏离设计时：

| 偏离类型 | 处理方式 |
|---------|---------|
| 字段名/类型不一致 | 修改代码，以设计文档为准 |
| 多了设计中没有的模块 | 审查是否必要；必要则补充设计文档，不必要则删除 |
| 少了设计中要求的模块 | 补充实现 |
| 接口签名不一致 | 修改代码，以设计文档为准 |
| AI 的实现比设计更好 | 先更新设计文档，再保留代码 |

### 维度 B：代码质量与安全

#### B-1 错误处理

**Rust 项目（platform / gate / sandbox / sdk）：**

| 检查项 | 规则 |
|--------|------|
| `unwrap()` / `expect()` | 禁止在非初始化代码中使用。用 `?` + 自定义 Error enum |
| `panic!` | 禁止在库代码中使用。返回 `Result` |
| `todo!()` / `unimplemented!()` | 只允许在明确标注为 Phase 2+ 的占位中使用 |

验证命令：
```bash
grep -rn "\.unwrap()\|\.expect(\|panic!\|todo!\|unimplemented!" src/ --include="*.rs" | grep -v "#\[cfg(test)\]\|#\[test\]\|tests/"
```

**Python 项目（core / flow / runtime）：**

| 检查项 | 规则 |
|--------|------|
| bare `except:` | 禁止。必须捕获具体异常类型 |
| `except Exception:` + `pass` | 禁止静默吞掉错误。至少 log warning |
| `raise NotImplementedError` | 只允许在明确标注为后续阶段的占位中使用 |

验证命令：
```bash
grep -rn "except:" quantalithos_*/ --include="*.py"
grep -rn "except Exception" quantalithos_*/ --include="*.py" | grep "pass"
```

#### B-2 安全

| 检查项 | 规则 | 验证命令 |
|--------|------|---------|
| 无硬编码密钥 | 代码中不含 API Key / 密码 / JWT Secret 字面值 | `grep -rn "sk-\|password.*=.*\"\|secret.*=.*\"" src/ --include="*.rs" --include="*.py"` |
| 无 SQL 拼接 | 所有 SQL 使用参数化查询 | `grep -rn "format!.*SELECT\|format!.*INSERT\|f\".*SELECT\|f\".*INSERT" src/` |
| 输入校验 | API 入参有长度/格式/范围校验 | 审查 handler 层 |
| 敏感信息不入日志 | 日志中不打印 token / password / API Key | `grep -rn "log.*token\|log.*password\|log.*api_key\|tracing.*token" src/` |

#### B-3 注释质量

对照 `docs/design/实施计划书写规范.md` §前置条件 3：

| 检查项 | 判定标准 |
|--------|---------|
| struct / class 有文档注释 | 说明职责和使用场景 |
| 每个成员变量有注释 | 说明语义和约束 |
| 函数有文档注释 | 说明作用、前置条件、返回值语义、可能错误 |
| 关键步骤有行内注释 | 说明"为什么这样做"而非"做了什么" |
| 易错处有标记 | 并发陷阱、超时歧义、边界条件标注 CAUTION / NOTE |

#### B-4 依赖合规

| 检查项 | 判定标准 |
|--------|---------|
| 依赖在概要设计技术选型范围内 | 不得引入设计中未规划的框架或库 |
| 依赖版本锁定 | Cargo.lock / requirements.txt / package-lock.json 已提交 |
| 无可疑依赖 | 依赖名称无拼写异常（防 typosquatting） |

### 维度 C：跨服务协议一致性

#### C-1 共享模型对齐

core 定义的共享模型必须在所有消费方一致使用：

| 模型 | 定义方 | 消费方 | 检查点 |
|------|--------|--------|--------|
| FlowMessage | core | flow（构造）、runtime（解析） | 字段名、类型、必填/可选 |
| FlowMessageType | core | flow（dispatch）、runtime（dispatch） | 枚举值完全一致 |
| NodeExecutePayload | core | flow（构造）、runtime（解析） | 字段完整性 |
| ChatMessagePayload | core | flow（构造）、runtime（解析） | 字段完整性 |
| NodeResult | core | runtime（返回）、flow（解析） | 字段名、类型 |
| NodeResultType | core | runtime（使用）、flow（使用） | 枚举值一致 |
| SandboxProvider | core | runtime（调用）、sandbox（实现） | 方法签名一致 |

#### C-2 API 路径对齐

platform 的 API 路径必须在所有调用方一致：

| 调用方 | 检查方法 |
|--------|---------|
| gate 路由转发 | gate 配置中的 upstream 路径 vs platform 路由表 |
| flow platform_client | flow 中的 API 调用路径 vs platform 路由表 |
| runtime platform_client | runtime 中的 API 调用路径 vs platform 路由表 |

#### C-3 序列化格式对齐

| 检查项 | 规则 |
|--------|------|
| JSON 字段命名 | 统一 snake_case（Rust 用 `#[serde(rename_all = "snake_case")]`） |
| 日期格式 | 统一 ISO 8601（`2026-05-03T12:00:00Z`） |
| ID 格式 | 统一 UUID v4 字符串 |
| 可选字段 | JSON 中缺失 = None / null，不是空字符串 |

## 三、审查流程

```
审查者领取审查任务
    │
    ▼
阅读对应项目的详细设计文档（必须先读设计再看代码）
    │
    ▼
按维度 A → B → C 顺序逐项检查
    │
    ▼
记录发现的问题到审查报告（docs/review/phase-N/审查报告/项目名.md）
    │
    ▼
问题分级：
  · Critical — 阻塞联调，必须修复
  · Major — 影响质量，应该修复
  · Minor — 建议改进，可以延后
    │
    ▼
开发者（AI）修复 Critical + Major 问题
    │
    ▼
审查者确认修复 → 标记通过
```

## 问题清单

| # | 维度 | 级别 | 文件 | 行号 | 问题描述 | 修复建议 | 状态 |
|---|------|------|------|------|---------|---------|------|
| 1 | | | | | | | 待修复 |

## 审查结论

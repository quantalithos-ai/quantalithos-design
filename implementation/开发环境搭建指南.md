# 开发环境搭建指南

> 从零搭建 Quantalithos AI 本地开发环境的完整步骤。
> 适用于：后端联调（7 个服务）

---

## 一、前置工具链

| 工具 | 最低版本 | 用途 | 安装验证 |
|------|---------|------|---------|
| Docker | 24.0 | 容器运行环境 | `docker --version` |
| Docker Compose | 2.20 | 多服务编排 | `docker compose version` |
| curl | 任意 | API 验证 | `curl --version` |
| Git | 2.30 | 版本控制 | `git --version` |

> Rust / Python / Node 工具链在联调阶段**不需要安装**——所有服务通过 Docker 容器运行。
> 只有在需要本地调试单个服务时才需要对应语言的工具链。

### 可选工具链（本地调试用）

| 工具 | 版本 | 用途 |
|------|------|------|
| Rust (rustc + cargo) | stable >= 1.78 | 本地编译 gate / platform / sandbox |
| Python | >= 3.11 | 本地运行 core / flow / runtime |
| Node.js | >= 18 | 本地运行 chat / console（波次 5） |

## 三、一键启动

所有服务通过 `quantalithos-infra` 的 Docker Compose 统一管理。

### 3.1 配置环境变量

```bash
cd ~/WorkProject/quantalithos-infra

# 从模板创建 .env（首次执行）
cp config/.env.example .env

# 编辑 .env，填入 LLM API Key
# 至少配置一个（Anthropic 或 OpenAI）
vim .env
```

**必须配置的变量：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `LLM_API_KEY` | Anthropic API Key | `sk-ant-api03-...` |
| `OPENAI_API_KEY` | OpenAI API Key（可选） | `sk-proj-...` |
| `DB_PASSWORD` | PostgreSQL 密码 | `dev_password`（默认值可用于开发） |
| `JWT_SECRET` | JWT 签名密钥 | `dev-secret-change-me-please-000001`（默认值可用于开发） |

### 3.2 一键启动全部服务

```bash
cd ~/WorkProject/quantalithos-infra
bash scripts/setup-dev.sh
```

`setup-dev.sh` 会自动执行以下步骤：

1. 检查 Docker 可用
2. 创建 `.env`（如不存在）
3. 准备构建上下文（复制各子项目代码到 Docker 构建目录）
4. 启动 PostgreSQL → 等待就绪
5. 执行数据库迁移（`migrate.sh`）
6. 导入初始数据（`seed.sh`）
7. 构建并启动所有后端服务
8. 执行健康检查

### 3.3 验证启动成功

```bash
bash scripts/health-check.sh
```

预期输出：

```
OK   postgres   pg_isready quantalithos
OK   gate       http://127.0.0.1:8000/health
OK   platform   http://127.0.0.1:8001/health
OK   runtime    http://127.0.0.1:8003/health
OK   sandbox    http://127.0.0.1:8004/health
OK   flow       daemon container healthy
Health checks completed successfully.
```

## 四、端口规划

| 服务 | 端口 | 协议 | 说明 |
|------|------|------|------|
| gate | 8000 | HTTP + WebSocket | 外部唯一入口 |
| platform | 8001 | HTTP | 平台数据服务 |
| flow | — | 无端口（daemon 进程） | 流程编排引擎，通过 platform 事件驱动 |
| runtime | 8003 | HTTP | Agent 运行时 |
| sandbox | 8004 | HTTP | 项目沙箱 |
| PostgreSQL | 5432 | TCP | 数据库 |

> flow 是 daemon 进程，不暴露 HTTP 端口。它通过轮询 platform 事件和调用 runtime `/messages` 端点工作。

## 五、常用命令

### 服务管理

```bash
cd ~/WorkProject/quantalithos-infra

# 启动全部服务
docker compose up -d

# 停止全部服务（保留数据）
docker compose down

# 停止并清除数据（重新开始）
docker compose down -v

# 重启单个服务
docker compose restart gate

# 查看服务日志
docker compose logs -f gate          # 跟踪 gate 日志
docker compose logs platform --tail 50  # 最近 50 行
```

### 数据库操作

```bash
cd ~/WorkProject/quantalithos-infra

# 执行迁移
bash scripts/migrate.sh

# 导入初始数据
bash scripts/seed.sh

# 重置数据库（清空 + 重建 + 导入）
bash scripts/reset-db.sh

# 手动连接数据库
docker exec -it quantalithos-infra-postgres psql -U quantalithos -d quantalithos
```

### 健康检查

```bash
# 全部服务健康检查
bash scripts/health-check.sh

# 单个服务检查
curl http://localhost:8000/health   # gate
curl http://localhost:8001/health   # platform
curl http://localhost:8003/health   # runtime
curl http://localhost:8004/health   # sandbox
```

### 数据库备份与恢复

```bash
bash scripts/backup-db.sh     # 备份到 backups/ 目录
bash scripts/restore-db.sh    # 从最新备份恢复
```

# 故障排查手册

> 联调阶段常见问题的排查方法和解决方案。

---

## 一、服务启动失败

### 1.1 setup-dev.sh 执行报错

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| `Required command not found: docker` | Docker 未安装或不在 PATH | 安装 Docker Desktop 或 Docker Engine |
| `Cannot connect to the Docker daemon` | Docker daemon 未启动 | `sudo systemctl start docker` 或启动 Docker Desktop |
| `permission denied while trying to connect` | 当前用户不在 docker 组 | `sudo usermod -aG docker $USER` 然后重新登录 |
| `port is already allocated` | 端口被占用 | `lsof -i :8000` 找到占用进程并关闭，或修改 `.env` 中的端口 |

### 1.2 单个服务启动失败

```bash
# 查看失败服务的日志
docker compose logs <service-name> --tail 50

# 查看容器状态
docker compose ps

# 重启单个服务
docker compose restart <service-name>

# 重新构建并启动
docker compose up -d --build <service-name>
```

| 服务 | 常见启动失败原因 | 排查方式 |
|------|----------------|---------|
| platform | PostgreSQL 未就绪 | `docker compose logs postgres` 检查是否 healthy |
| platform | 迁移未执行 | `bash scripts/migrate.sh` 手动执行 |
| runtime | LLM_API_KEY 未配置 | 检查 `.env` 中 `LLM_API_KEY` 是否填写 |
| sandbox | Docker socket 权限不足 | 确认 `/var/run/docker.sock` 可读写 |
| gate | 上游服务未就绪 | 确认 platform/runtime 已启动且 healthy |
| flow | platform 或 runtime 未就绪 | 确认 depends_on 的服务已 healthy |

## 二、数据库问题

### 2.1 连接失败

```bash
# 检查 PostgreSQL 容器是否运行
docker compose ps postgres

# 手动测试连接
docker exec -it quantalithos-infra-postgres psql -U quantalithos -d quantalithos -c "SELECT 1;"

# 检查端口是否可达
nc -zv localhost 5432
```

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| `connection refused` | PostgreSQL 容器未运行 | `docker compose up -d postgres` |
| `password authentication failed` | 密码不匹配 | 检查 `.env` 中 `DB_PASSWORD` 与容器环境变量一致 |
| `database "quantalithos" does not exist` | 数据库未创建 | `docker compose down -v && docker compose up -d postgres` 重建 |

### 2.2 迁移失败

```bash
# 查看迁移日志
bash scripts/migrate.sh 2>&1

# 检查已执行的迁移
docker exec -it quantalithos-infra-postgres psql -U quantalithos -d quantalithos \
  -c "SELECT * FROM _sqlx_migrations ORDER BY version;"

# 重置数据库（清空重建）
bash scripts/reset-db.sh
```

### 2.3 数据不一致

```bash
# 检查表是否存在
docker exec -it quantalithos-infra-postgres psql -U quantalithos -d quantalithos \
  -c "SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' ORDER BY table_name;"

# 检查初始数据
docker exec -it quantalithos-infra-postgres psql -U quantalithos -d quantalithos \
  -c "SELECT count(*) FROM role_definitions;"
```

## 三、服务间通信失败

### 3.1 gate 转发失败

```bash
# 检查 gate 日志中的上游连接错误
docker compose logs gate --tail 30 | grep -i "error\|upstream\|timeout"

# 直接访问上游服务确认可用
curl -s http://localhost:8001/health   # platform
curl -s http://localhost:8003/health   # runtime

# 检查 gate 配置中的上游地址
docker compose exec gate cat /srv/quantalithos-gate/config/gate.yaml
```

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| `502 Bad Gateway` | 上游服务未运行 | 启动对应服务 |
| `504 Gateway Timeout` | 上游服务响应慢 | 检查上游服务日志，可能是 LLM 调用超时 |
| `401 Unauthorized` | JWT token 无效或过期 | 重新登录获取 token |

### 3.2 flow → runtime 通信失败

```bash
# 检查 flow 日志中的 runtime 调用
docker compose logs flow --tail 30 | grep -i "error\|runtime\|message"

# 确认 runtime 的 /messages 端点可达（容器内网络）
docker compose exec flow python -c "import urllib.request; print(urllib.request.urlopen('http://runtime:8003/health').read())"
```

### 3.3 runtime → sandbox 通信失败

```bash
# 检查 runtime 日志中的 sandbox 调用
docker compose logs runtime --tail 30 | grep -i "error\|sandbox"

# 确认 sandbox 可达
docker compose exec runtime python -c "import urllib.request; print(urllib.request.urlopen('http://sandbox:8004/health').read())"
```

## 四、LLM 调用问题

### 4.1 API Key 无效

```bash
# 检查环境变量是否注入
docker compose exec runtime env | grep -i "llm\|openai\|api_key"

# 检查 runtime 启动日志中的 provider 初始化
docker compose logs runtime | grep -i "provider\|llm\|model"
```

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| `401 Unauthorized` | API Key 无效 | 检查 `.env` 中的 Key 是否正确 |
| `429 Too Many Requests` | 超出速率限制 | 等待后重试，或升级 API 计划 |
| `timeout` | 网络问题或模型响应慢 | 检查网络连通性；增大 timeout 配置 |
| `model not found` | 模型名称错误 | 检查 `.env` 中 `LLM_MODEL` 配置 |

### 4.2 LLM 响应异常

```bash
# 查看 runtime 的 LLM 调用日志
docker compose logs runtime --tail 50 | grep -i "llm\|chat\|tool_call"

# 检查 trace store（如果 6-B 可观测性已启用）
curl -s http://localhost:8003/agents | python3 -m json.tool
```

## 五、Docker 容器问题

### 5.1 容器频繁重启

```bash
# 查看重启次数
docker compose ps

# 查看容器退出原因
docker inspect <container-id> --format='{{.State.ExitCode}} {{.State.Error}}'

# 查看 OOM 情况
docker stats --no-stream
```

### 5.2 磁盘空间不足

```bash
# 检查 Docker 磁盘使用
docker system df

# 清理未使用的镜像和容器
docker system prune -f

# 清理构建缓存
docker builder prune -f
```

### 5.3 sandbox 容器管理问题

```bash
# 查看 sandbox 管理的容器
docker ps --filter "label=managed-by=quantalithos-sandbox"

# 清理 sandbox 创建的孤儿容器
docker ps -a --filter "label=managed-by=quantalithos-sandbox" --filter "status=exited" -q | xargs -r docker rm
```

## 六、日志查看方法

### 6.1 实时跟踪

```bash
# 跟踪所有服务日志
docker compose logs -f

# 跟踪单个服务
docker compose logs -f runtime

# 跟踪多个服务
docker compose logs -f runtime flow
```

### 6.2 按时间过滤

```bash
# 最近 5 分钟的日志
docker compose logs --since 5m

# 指定时间之后的日志
docker compose logs --since "2026-05-03T12:00:00"
```

### 6.3 按关键字过滤

```bash
# 只看错误
docker compose logs | grep -i "error\|exception\|panic\|fatal"

# 看特定请求
docker compose logs gate | grep "POST /api/projects"

# 看 FlowMessage 调度
docker compose logs flow | grep "FlowMessage\|node_execute\|dispatch"
```

### 6.4 日志级别

| 服务 | 日志级别配置 | 调整方式 |
|------|------------|---------|
| platform | `RUST_LOG=info` | `.env` 中设置 `RUST_LOG=debug` |
| gate | `RUST_LOG=info` | 同上 |
| sandbox | `RUST_LOG=info` | 同上 |
| runtime | Python logging | `config/runtime.yaml` 中调整 log_level |
| flow | Python logging | `config/flow.yaml` 中调整 log_level |

## 七、快速恢复

当联调环境出现不可恢复的问题时，可以完全重建：

```bash
cd ~/WorkProject/quantalithos-infra

# 1. 停止所有服务并清除数据
docker compose down -v

# 2. 清理构建缓存（可选，解决镜像构建问题）
docker builder prune -f

# 3. 重新一键启动
bash scripts/setup-dev.sh
```

> 这会清除所有数据（PostgreSQL volume 被删除）。如果需要保留数据，用 `docker compose down`（不加 `-v`）。

```
                     └───────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
     ┌────────────┐  ┌────────────┐  ┌────────────┐

            │               │              ▲
            │               │              │
            │               └──────────────┘
            │                 sandbox API 调用
            ▼
     ┌────────────┐
     │  flow      │  daemon 进程，无 HTTP 端口
     │  (daemon)  │  轮询 platform + 调用 runtime
     └──────┬─────┘
            │
            ▼
     ┌────────────┐
     │  core      │  共享库（pip install）

     └────────────┘
            │
            ▼
     ┌────────────┐
     │ PostgreSQL │  数据持久化
     │  (:5432)   │
     └────────────┘
```

## 二、逐服务验证

启动后按以下顺序逐个验证，确认每个服务独立可用。

### 2.1 PostgreSQL

```bash
# 验证连接
docker exec -it quantalithos-infra-postgres psql -U quantalithos -d quantalithos -c "SELECT count(*) FROM information_schema.tables WHERE table_schema = 'public';"

# 预期：count > 0（迁移创建的表）
```

### 2.2 platform

```bash
# 健康检查
curl -s http://localhost:8001/health | python3 -m json.tool

# 创建项目
curl -s -X POST http://localhost:8001/api/projects \
  -H "Content-Type: application/json" \
  -d '{"name": "test-project", "description": "联调测试项目"}' | python3 -m json.tool

# 查询项目列表
curl -s http://localhost:8001/api/projects | python3 -m json.tool
```

### 2.3 sandbox

```bash
# 健康检查
curl -s http://localhost:8004/health | python3 -m json.tool
```

### 2.4 runtime

```bash
# 健康检查
curl -s http://localhost:8003/health | python3 -m json.tool

# 预期：{"status": "ok", "agents": 0}
```

### 2.5 flow

```bash
# flow 是 daemon 进程，通过容器状态验证
docker compose ps flow

# 预期：State = running, Health = healthy
```

### 2.6 gate

```bash
# 健康检查（不需要认证）
curl -s http://localhost:8000/health | python3 -m json.tool

# 通过 gate 访问 platform（需要 JWT）
# 先获取 token
TOKEN=$(curl -s -X POST http://localhost:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin"}' | python3 -c "import sys,json; print(json.load(sys.stdin).get('token',''))")

# 通过 gate 转发到 platform
curl -s http://localhost:8000/api/projects \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

## 三、核心链路端到端验证

### 3.1 链路概览

```
用户 → gate → platform（创建项目）
                 │
                 ▼ 事件
              flow（启动流程）
                 │
                 ▼ FlowMessage
              runtime（创建 Agent → LLM 调用 → 工具执行）
                 │
                 ▼ sandbox API
              sandbox（文件操作 / 代码执行）
                 │
                 ▼ NodeResult
              flow（推进流程 → 门禁控制）
```

### 3.2 验证步骤

**步骤 1：通过 gate 创建项目**

```bash
# 获取 JWT token
TOKEN=$(curl -s -X POST http://localhost:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin"}' | python3 -c "import sys,json; print(json.load(sys.stdin).get('token',''))")

echo "Token: $TOKEN"

# 创建项目
curl -s -X POST http://localhost:8000/api/projects \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "blog-system",
    "description": "AI 驱动的博客系统开发"
  }' | python3 -m json.tool
```

**步骤 2：验证 flow 接收到项目事件**

```bash
# 查看 flow 日志，确认收到项目创建事件
docker compose logs flow --tail 20
```

**步骤 3：验证 runtime Agent 创建**

```bash
# 查看 runtime 当前 Agent 列表
curl -s http://localhost:8003/health | python3 -m json.tool

# 查看 runtime 日志
docker compose logs runtime --tail 20
```

**步骤 4：验证 sandbox 容器状态**

```bash
# 查看 sandbox 管理的容器
curl -s http://localhost:8004/health | python3 -m json.tool

# 查看 sandbox 日志
docker compose logs sandbox --tail 20
```

## 四、服务间通信协议

### 4.1 FlowMessage（flow → runtime）

flow 通过 HTTP POST 发送 `FlowMessage` 到 runtime 的 `/messages` 端点。

```json
{
  "message_id": "msg-abc123",
  "type": "node_execute",
  "agent_id": "agent-tl-001",
  "project_id": "proj-001",
  "payload": {
    "process_instance_id": "inst-001",
    "node": { "id": "node-1", "type": "ActivityNode", "actor": "tech_lead" },
    "control_level": "guided",
    "allowed_tools": ["file_read", "file_write", "task_read"],
    "input_refs": [],
    "output_schema": null
  },
  "created_at": "2026-05-03T12:00:00Z"
}
```

### 4.2 NodeResult（runtime → flow）

runtime 执行完成后返回 `NodeResult`。

```json
{
  "message_id": "msg-abc123",
  "result_type": "completed",
  "agent_id": "agent-tl-001",
  "output": {
    "summary": "Goal alignment brief completed",
    "artifacts": ["goal_alignment_brief.md"]
  }
}
```

### 4.3 消息类型一览

| 类型 | 方向 | 说明 |
|------|------|------|
| `agent_create` | flow → runtime | 创建 Agent 实例 |
| `node_execute` | flow → runtime | 执行 BPMN 节点任务 |
| `chat_message` | flow → runtime | 群聊消息（reply_to / mention / general） |
| `node_cancel` | flow → runtime | 取消正在执行的节点 |
| `agent_resume` | flow → runtime | 恢复挂起的 Agent |

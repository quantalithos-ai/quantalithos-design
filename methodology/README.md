## 三、14 份标准讨论的统一骨架

所有讨论文档遵循同一套"六层对象体系"叙事:

```
第零阶段  概念地基(术语清单 + 易混辨析 + 最易犯错 + 过关标准)
第一阶段  整体架构(分层系统视角)
第二阶段  对象系统主干(主干对象关系 + 字典表)
第三阶段  主线展开
第四阶段  具体展开(各标准不同)
第五阶段  对象字典 / 关系矩阵 / 工程落地 / 失真模式
第六阶段  与其他标准的关系 + 对 Quantalithos 的意义
```

## 四、阅读顺序

**首次来**:
1. `开发流程标准综述.md` — 四层模型 + 17 标准横向分类
2. `standards-discussion/` 挑感兴趣的专项深入

**针对具体问题找标准**:
- 想画流程 → BPMN 2.0
- 想定义方法 → SPEM 2.0
- 定生命周期过程 → 12207 / 15288 / 29110
- 评估过程能力 → CMMI / 15504 / 330xx
- 质量治理 → 9001
- 敏捷执行 → Scrum / Kanban
- 生命周期模型选型与裁剪 → 24748-2
- AI 治理 → 42001
- 软件质量评估 → 25010

**针对 Quantalithos 设计对齐**:
- 先读 `architecture/标准对齐全景图.md`
- 再按需深入 standards-discussion/ 对应标准

## 五、修订纪律

- 新增标准讨论 = 新建 `standards-discussion/<std>.md`,并在 `开发流程标准综述.md` §六 补入口
- 标准原文更新(新版本) = 原讨论文档顶部加"订正标记",然后逐章更新
- 完整重写 = 走 ADR 说明理由

### 1.4 内容采集提示(先采集,再落文)

在正式写 02 之前,建议先按下面顺序采集内容,不要一上来直接填模板:

#### 第 0 步:先判断“这个仓是什么类型的仓?”

先回答:
- 它是基础设施契约型?
- 业务域型?
- 运行时能力型?
- 端侧产品型?
- 生态扩展型?

**产出**:
- 仓类型标签
- 主类型 / 次类型(如有)
- 对应写法重心

**作用**:
- 不同类型的仓,后续问法和写法都不同
- 先定类型,再定内容深度,避免过早模块化

> 不同类型的仓,后续问法和写法都不同。先定类型,再定内容深度。

#### 第 1 步:先问“它在现实里是什么”

优先回答:
- 这个仓在现实世界里扮演什么角色？
- 为什么它必须单独存在？
- 如果没有它，会乱在哪里？
- 它不是谁？

**产出**:
- 仓定位一句话
- 非目标清单
- 全局角色描述

**作用**:
- 先把“它到底是什么”讲清楚
- 避免后面模块拆分时根基不稳

#### 第 2 步:再问“它在平台里和谁强相关”

要回答:
- 它依赖哪些模块？
- 哪些模块依赖它？
- 哪些交互是核心主链？
- 它是别人真相的消费者,还是别人要消费它的真相？
- 哪些关系是真相源 / 投影层 / 节奏层 / 治理层 / 证据层？

**产出**:
- 上下游模块清单
- 真相源 / 投影层 / 节奏层 / 治理层 / 证据层分类
- 一张总交互图草稿

**作用**:
- 先建立整体关系图谱
- 防止后面只盯着仓内模块,忽略上下游真相边界

#### 第 3 步:再问“它内部由哪些主要部分组成”

> 这里问的是**主要部分**,不是要在 `02-概要设计` 阶段穷举“全部部分”。  
> 目标是先让新人理解:这个仓主要由哪几块核心部分构成、它们为什么单独存在、彼此如何配合。  
> 所有辅助模块、边角适配器、细粒度文件与实现细节,留到 `03-详细设计.md` 继续展开。  
> **拆分原则**:主要部分不是按对象个数、表个数或 CRUD 个数来拆,而是按 **独立职责 + 主交互链位置 + 稳定边界 + 真相/投影/接缝差异** 来拆。

要回答:
- 内部有哪几个主要部分？
- 每个主要部分分别承担什么独立职责？
- 每个主要部分在主流程或关键交互链里处于哪一步？
- 哪些是真相部分,哪些是投影 / 适配 / 支撑 / 接缝部分？
- 每个主要部分为什么单独存在,不能直接并到别的部分？
- 每个主要部分最容易和哪个相邻部分混淆？
- 每个主要部分后续需要在 `03-详细设计.md` 继续展开哪些设计题？

**产出**:
- 主要部分清单
- 每部分一句话职责
- 核心部分与支撑部分划分
- 每个主要部分的边界提示
- `02 → 03` 的展开点提示

**作用**:
- 把“仓的整体组成”讲清楚
- 防止把主要部分误写成对象清单或表清单
- 为后续分层图和模块职责表做准备
- 为 `03-详细设计.md` 提供稳定的模块展开骨架

#### 第 4 步:再问“核心对象是什么”

要回答:
- 这个仓最核心的对象有哪些？
- 哪些是真相对象？
- 哪些是投影对象？
- 哪些是执行对象？
- 哪些对象最容易和旁边仓混淆？

**产出**:
- 对象分层图
- 术语解释清单
- 真相对象 / 投影对象 / 执行对象分类

**作用**:
- 先稳住术语系统
- 防止不同层对象在概要设计里被写混

#### 第 5 步:再问“主流程和关键交互链是什么”

要回答:
- 这个仓最典型的主流程是什么？
- 一个输入进来,经过哪些对象和模块,变成什么输出？
- 哪条是 happy path？
- 哪条是最关键的异常路径？

**产出**:
- 一条主流程图
- 分模块交互图草稿
- 关键输入/输出点列表

**作用**:
- 让概要设计真正回答“这个仓如何工作”
- 为后续详细设计中的 API / 事件 / 数据结构提供骨架

#### 第 6 步:最后才问“哪些规则和边界必须写死”

要回答:
- 哪些规则不能被误解？
- 哪些默认行为必须写死？
- 哪些对象不能互相替代？
- 哪些状态变化不能直接发生？

**产出**:
- 规则清单
- 高风险边界清单
- 需要进入 `00/01/02` 的硬规则列表

**作用**:
- 把成熟讨论沉淀成正式边界
- 为后续详细设计、测试、验收提供稳定前提

#### 内容采集总流程图

```text
进入新仓
  │
  ▼
[0] 先判断仓类型
  │
  ▼
[1] 先问“它在现实里是什么”
  │
  ▼
[2] 再问“它在平台里和谁强相关”
  │
  ▼
[3] 再问“它内部由哪些主要部分组成”
  │
  ▼
[4] 再问“核心对象是什么”
  │
  ▼
[5] 再问“主流程和关键交互链是什么”
  │
  ▼
[6] 最后才问“哪些规则和边界必须写死”
  │
  ▼
把内容落到 02-概要设计
```

> **概要设计的目标不是先给出实现细节,而是先让第一次接触这个仓的人建立正确的系统心智。**

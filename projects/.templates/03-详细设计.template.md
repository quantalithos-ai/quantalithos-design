## 6. 关键函数伪代码

> 粒度要求:开发者可**直接翻译为代码**,不需要再做设计决策

### 6.1 [函数 1 · 如 `create_order`]

```
function create_order(cmd: CreateOrderCmd) -> Result<OrderId, Error>:
    # 前置校验
    if cmd.items.is_empty():
        return Err(InvalidInput)

    # 幂等检查
    key = compute_idempotent_key(cmd)
    if idempotent_cache.exists(key):
        return Ok(idempotent_cache.get(key))

    # 库存预扣(外部调用,带超时)
    deduct_result = stock_proxy.batch_deduct(cmd.items, timeout=3s)
    if deduct_result.timed_out:
        # 超时补偿:查询库存确认
        confirm = stock_proxy.query_deduct_status(key)
        if confirm.not_deducted:
            goto retry_once_else_fail
        # 已扣,继续

    # 创建订单实体
    order = Order::new(cmd, deduct_result)

    # 事务:存订单 + 写 Outbox
    with transaction:
        order_repo.save(order)
        outbox.publish(OrderCreatedEvent::from(order))

    # 幂等缓存
    idempotent_cache.set(key, order.id, ttl=24h)

    return Ok(order.id)
```

## 9. 异常处理与容错

### 9.1 异常分类与处理策略

| 异常类型 | 分类 | 处理策略 |
|---|---|---|
| 参数不合法 | 客户端错误 | 返回 400,不重试 |
| 外部服务超时 | 可恢复异常 | 重试(指数退避)/ 降级 |
| 外部服务不可用 | 可恢复异常 | 熔断 + 降级 |
| 数据库连接失败 | 可恢复异常 | 重试 + 报警 |
| 业务规则违反 | 业务错误 | 返回业务错误码,不重试 |
| 幂等冲突 | 预期"错误" | 返回已有结果 |

### 9.2 重试 / 降级 / 熔断 / 补偿

| 场景 | 策略 | 参数 |
|---|---|---|
| 库存服务调用 | 重试 + 熔断 | max_retries=3, backoff=exp(1s, 2s, 4s), 熔断阈值=50% |
| DB 连接失败 | 重试 | max_retries=3, backoff=linear(100ms) |
| MQ 发布失败 | Outbox 兜底 | 标 `pending`,worker 轮询重发 |

### 9.3 幂等设计

| 操作 | 幂等键 | 幂等窗口 | 实现方式 |
|---|---|---|---|
| CreateOrder | `MD5(user_id + items_hash)` | 24h | Redis SETNX |
| UpdateOrderStatus | `order_id + from_state + to_state` | 永久 | DB unique constraint |

## 10. 并发与一致性

### 10.1 并发控制策略

| 场景 | 策略 | 实现 |
|---|---|---|
| Order 字段更新 | 乐观锁 | version 字段 CAS |
| 库存预扣 | 分布式锁(短时)| Redis SETNX + TTL=5s |
| 批量操作 | 分批队列 | 批次大小 100,串行处理 |

### 10.2 竞态场景分析

| 竞态路径 | 后果 | 防御 |
|---|---|---|
| 同一用户并发下单同一 SKU | 超卖 | 库存服务加锁 + 幂等 |
| 同一订单并发更新状态 | 状态错乱 | 乐观锁 |

### 10.3 事务边界与隔离级别

| 事务 | 边界 | 隔离级别 |
|---|---|---|
| CreateOrder | Order INSERT + Outbox INSERT | READ COMMITTED |
| UpdateOrderStatus | Order UPDATE(乐观锁)| READ COMMITTED |

### 10.4 分布式一致性方案

- 聚合内:强一致(本地事务)
- 聚合间:最终一致(Outbox + 事件驱动)
- 跨服务:Saga(编排型)

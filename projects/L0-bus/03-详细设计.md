## 2. 本次详细设计目标与范围

> 校准来源：
> - `design-calibration/03_ddd_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节，了解 P0 范围、非范围和详细设计深度如何收敛。

### 2.1 设计目标

| 目标 | 说明 | 交付给实现者的结果 |
|---|---|---|
| 收稳 P0 传递闭环 | 覆盖 publication acceptance、delivery progression、feedback、retry、DLQ、replay preparation、read-only output | 实现者知道本轮必须打通哪些主线 |
| 收稳 Rust workspace | 把概要设计代码主体落到 `contracts / domain / application / infra / api / worker / jobs` | 可直接创建目标仓目录和 crate |
| 收稳对象与 port | 展开 bus truth、state、policy、repository、source、publisher、transport、projection、clock、id generator | 可按模块实现类型和 trait |
| 收稳协议与处理流 | 定义 Command / Query / Inbound Event / Outbound Event / Job schema 和函数级 flow | 可实现 handler、consumer、publisher、job runner |
| 收稳横切契约 | 定义状态机、持久化、事务、错误、并发、幂等、配置、观测和测试切口 | 可编写核心测试并进入实施计划 |

### 2.2 P0 展开范围

| 范围项 | 展开深度 |
|---|---|
| Publication acceptance | Command / outbox fact 接入、accepted / rejected 事实、payload boundary、idempotency、audit、outbound event |
| Delivery progression | scheduled / dispatched / completed / failed / retry / DLQ 状态推进、transport backend port、delivery history |
| Feedback recording | subscriber / backend / timeout feedback、duplicate / late feedback、failure material |
| Recovery operations | retry request、retry cycle、dead letter、replay preparation、approval / audit chain ref |
| Read-only output | publication view、delivery status、history、transport view、failure summary、audit trail、backend health view |
| Operations job | outbox relay、delivery progression、retry cycle、projection run / rebuild、backend capability check |
| In-memory default path | P0 使用 in-memory / fake / fixture 保持与 future durable adapter 同语义 |

### 2.3 非范围

| 非范围 | 留给哪一层 / 哪份文档 |
|---|---|
| gateway、登录认证、token 校验、TLS 入口安全 | gateway / identity / security |
| 生产级 Kafka / NATS / Redis / RabbitMQ / durable DB adapter 全量实现 | P1 adapter 专项 |
| 业务 payload 正文真相 | publisher / artifact / 业务仓；L0-bus 只保存 ref、digest、size/type metadata |
| governance decision truth | governance 仓；L0-bus 只保存 approval ref / audit chain ref |
| 长期 observability 存储、dashboard、告警阈值、runbook | observability / 运维文档 |
| SDK 高层开发者体验、重试封装和凭据注入 | L0-sdk |
| 完整 JSON 配置手册、环境变量、部署填写说明 | `04-配置设计.md` |
| 完整测试矩阵、fixture、覆盖率、CI 编排 | `05-测试方案.md` |
| 开发阶段、任务拆分、commit boundary | `07-实施计划.md` |

### 2.4 P1 后置边界

P1 production adapter、生产部署、高可用、真实 MQ / durable store 集成、dashboard / alerting、SDK convenience wrapper 均不阻塞 P0。P0 必须保留 port、adapter、event、projection 和 config binding，使后续生产化可以替换 `infra` 而不破坏 `domain` 和 `application`。

## 3. 实现约束与编码规范承接

> 校准来源：
> - `design-calibration/03_ddd_step_03_coding_runtime_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节，了解 Rust 编码、runtime、仓库、提交和安全边界约束。

### 3.1 Rust 与实现仓约束

| 约束 | 说明 | 影响 |
|---|---|---|
| 语言 | Rust | 对象、trait、DTO、event、job、error、处理流均按 Rust 可实现契约表达 |
| 目标仓 | `/home/aris/Projects/quantalithos-bus` | 不在 design 仓实现业务代码 |
| 编译期依赖 | `core-contracts = { path = "../quantalithos-core/crates/contracts" }` | 只确认依赖 L0-core shared contracts |
| 运行期依赖 | MQ backend、bus store、publisher、source、observability、governance、SDK | 通过 port / adapter / event / query / projection / fake 表达，不写成 Cargo path dependency |
| 源码语言 | 实现仓标识符、普通注释、rustdoc、测试名默认英文 | 本文中文 Rustdoc 是设计说明，落码时转写英文 |
| 设计文档注释 | 本文 Rust 契约片段可用中文 Rustdoc 风格注释 | 便于审查对象、字段、variant 和函数语义 |

### 3.2 模块依赖红线

```text
api / worker / jobs
        |
        v
infra -> application -> domain
   |          |           |
   +----------+-----------+
              |
              v
          contracts
              |
              v
       core-contracts
```

关键说明：

- `domain` 不依赖 `application`、`infra`、`api`、`worker`、`jobs`。
- `application` 定义 use case 和 port trait，依赖 `domain` 与 `contracts`。
- `infra` 实现 application ports，并承接 config、repository、adapter、runtime wiring。
- `api`、`worker`、`jobs` 是入口 crate，不互相依赖，不绕过 application 改写 truth。

### 3.3 安全与边界约束

| 边界 | 规则 |
|---|---|
| gateway / auth | 本仓不实现认证、token 校验、session、TLS、credential parsing |
| actor / metadata | 只接收可信入口传入的 `ActorContext`、metadata、trace、authorization ref |
| payload body | 不保存业务 payload 正文，不写入 event、projection、audit、log、evidence |
| raw secret | 不接受配置文件中的 raw secret，只接受 `SecretRef` |
| backend private body | transport backend 私有响应正文不得进入 bus truth 或观测材料 |
| query side effect | Query 不写 truth，不自动 rebuild projection |

### 3.4 提交与实施前置

实现仓不是 `quantalithos-design`，因此默认使用英文 commit message 和英文源码注释。实施前必须在目标仓确认：

```text

git config user.email
```

目标值：

|---|---|

## 4. 实现单元与文件布局

> 校准来源：
> - `design-calibration/03_ddd_step_04_units_file_layout.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“布局形态决策”“实现单元总表”“文件布局树”和“文件职责表”小节，了解目标仓布局如何从概要设计转译而来。

### 4.1 布局形态

| 候选布局 | 是否采用 | 原因 |
|---|---|---|
| 单 crate 模块分层 | 否 | L0-bus 同时包含公共协议、领域语义、应用编排、infra adapter、API、worker、operations job，单 crate 依赖边界过宽 |
| workspace 多 crate | 是 | Cargo 依赖关系能保护 `contracts / domain / application / infra / api / worker / jobs` 边界 |
| 按业务对象建 crate | 否 | publication、delivery、feedback、recovery 会被 transaction、port、projection、event 横切，易形成循环依赖 |

### 4.2 实现单元总表

| 目录 | 类型 | Cargo package / Rust crate | 职责 |
|---|---|---|---|
| `crates/contracts` | library crate | `bus-contracts` / `bus_contracts` | Command、Query、Event、Job、View、Receipt、protocol error DTO |
| `crates/domain` | library crate | `bus-domain` / `bus_domain` | Publication、Delivery、Feedback、Recovery、ReadOutput、Backend、Audit、Policy、状态 enum |
| `crates/application` | library crate | `bus-application` / `bus_application` | application service、port trait、UnitOfWork 边界、幂等、错误组合 |
| `crates/infra` | library crate | `bus-infra` / `bus_infra` | repository adapter、in-memory store、publisher / source / backend adapter、config、runtime builder |
| `crates/api` | library + binary crate | `bus-api` / `bus_api` | HTTP JSON Command / Query / Recovery API 入口和 DTO mapper |
| `crates/worker` | library + binary crate | `bus-worker` / `bus_worker` | 常驻 consumer / worker loop，承接 outbox fact、backend signal、timeout signal |
| `crates/jobs` | binary crate | `bus-jobs` / `bus_jobs` | 一次性 operations job binary |
| `tests/` | integration tests | - | 跨 crate 集成测试 |
| `scripts/` | scripts | - | gate、report、redaction check |
| `artifacts/test/<run_id>` | artifact root | - | 测试原始证据 |

## 5. 模块实现契约

> 校准来源：
> - `design-calibration/03_ddd_step_05_module_contracts_axis.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 5 的“模块总览表 / 模块职责表”、Step 6 的“逐模块对象契约”和 Step 7 的“Trait / Port / Adapter 契约”。这些中间产物承载完整字段、函数、variant 注释和 trait 签名。

### 5.1 模块总览

| 模块 | 所属实现单元 | 职责 | 对外暴露 | 禁止事项 |
|---|---|---|---|---|
| `contracts` | `crates/contracts` | 定义跨入口和跨仓可复用协议结构 | Command、Query、Event、Job、View、Receipt、protocol error DTO | 不承载领域不变量，不依赖 domain / application |
| `domain` | `crates/domain` | 维护 bus 传递语义、状态、不变量和禁止正文边界 | 领域对象、状态 enum、policy、domain error | 不读取配置，不调用 repository / adapter |
| `application` | `crates/application` | 编排 use case、事务、幂等、port 调用、audit / event 副作用 | application service、port trait、application error | 不直接依赖 HTTP / DB / MQ 框架 |
| `infra` | `crates/infra` | 实现 port、store、adapter、projection、config、runtime wiring | repository adapter、in-memory default path、config loader、runtime builder | 不把 adapter 私有类型泄漏到 domain |
| `api` | `crates/api` | 接收同步 command / query / recovery 请求 | HTTP JSON handler、DTO mapper、`bus-api` binary | 不绕过 application 改写 truth |
| `worker` | `crates/worker` | 承接常驻 event consumer / worker loop | outbox relay consumer、backend signal consumer、timeout consumer | 不直接操作 domain / store |
| `jobs` | `crates/jobs` | 承接一次性 operations job | job runner、operation binary | 不把 job run id 当作业务幂等键 |

### 5.2 `contracts` 模块

| 项 | 内容 |
|---|---|
| 主要责任 | 定义稳定的 Command / Query / Event / Job / View / Receipt DTO |
| 关键文件 | `commands.rs`、`queries.rs`、`events.rs`、`jobs.rs`、`views.rs`、`receipts.rs`、`errors.rs`、`metadata.rs` |
| 关键对象 | `AcceptPublicationCommand`、`RecordDeliveryFeedbackCommand`、`RequestRetryCommand`、`MoveDeliveryToDeadLetterCommand`、`PrepareReplayCommand`、7 个 Query DTO、3 个 inbound event input、9 个 outbound event payload、6 个 job input / output |
| 关键规则 | DTO 字段不得携带 payload body、raw secret、backend private body；event envelope 复用 L0-core contract |
| 测试切口 | JSON roundtrip、必填字段、枚举值、schema version、protocol error DTO |

### 5.3 `domain` 模块

| 项 | 内容 |
|---|---|
| 主要责任 | 维护 bus truth、状态流转、不变量、boundary guard、failure material 和恢复策略 |
| 关键对象 | `PublicationAcceptance`、`PublicationMaterial`、`DeliveryRecord`、`DeliveryAttempt`、`FeedbackResult`、`RetryPlan`、`DeadLetterEntry`、`ReplayPreparation`、`TransportViewProjection`、`FailureSummaryProjection`、`BusAuditEntry`、`IdempotencyAnchor` |
| 关键状态 enum | `PublicationAcceptanceStatus`、`DeliveryStatus`、`FeedbackStatus`、`RetryPlanStatus`、`DeadLetterStatus`、`ReplayPreparationStatus`、`ProjectionStatus` |
| 关键 policy | payload boundary、delivery transition、retry eligibility、dead letter eligibility、replay preparation、read-only projection、backend signal normalization |
| 禁止事项 | 不保存数据库，不发布事件，不调用 governance，不读取配置，不保存 forbidden body |
| 测试切口 | 对象构造、不变量、合法 / 非法状态转换、forbidden body boundary |

完整字段、成员函数、工厂函数、variant 注释见 `03_ddd_step_06_object_contracts.md` §7。

### 5.4 `application` 模块

| 项 | 内容 |
|---|---|
| 主要责任 | 以 use case 为单位编排 transaction、idempotency、domain method、repository、publisher evidence、audit 和 projection |
| 关键 service | `PublicationAcceptanceService`、`DeliveryProgressionService`、`FeedbackRecordingService`、`RecoveryOrchestrationService`、`ReplayPreparationService`、`ReadOutputService`、`BackendCapabilityService`、`OutboxPublisherService` |
| 关键 port | repository ports、`UnitOfWorkPort`、`OutboxFactSourcePort`、`OutboxPublisherPort`、`TransportBackendPort`、`ClockPort`、`IdGeneratorPort`、observability / audit ports |
| 关键错误 | `ApplicationError` 组合 domain / repository / port / UoW 错误，并映射为 API / Consumer / Job 错误 |
| 测试切口 | fake UnitOfWork 调用顺序、idempotency anchor、port error mapping、audit / event 副作用 |

### 5.5 `infra` 模块

| 项 | 内容 |
|---|---|
| 主要责任 | 提供 repository / UoW / adapter / config / runtime builder 的实际实现 |
| 关键实现 | in-memory store、repository adapters、projection store、source adapter、publisher adapter、transport backend adapter、clock、id generator、redaction checker |
| 关键配置 | `RuntimeConfig`、`StoreConfig`、`BackendConfig`、`OutboxSourceConfig`、`PublisherConfig`、`ApiConfig`、`WorkerConfig`、`JobConfig`、`ProjectionConfig`、`RecoveryPolicyConfig` |
| 禁止事项 | 不把具体 DB / MQ / backend 私有类型穿透给 domain / application |
| 测试切口 | in-memory unique constraint、expected version、config validation、adapter error mapping |

### 5.6 `api` / `worker` / `jobs` 入口模块

| 模块 | 主要入口 | 关键职责 | 测试切口 |

> 校准来源：

> 延伸阅读：

### 8.1 处理流总表

| 处理流 | 对应协议 | 主要事务 | 状态变化 | 测试切口 |
|---|---|---|---|---|
| `AcceptPublicationFlow` | `AcceptPublication` | 单命令写事务 | `PublicationAcceptance: draft -> accepted/rejected` | accepted、payload 越界、幂等重复、repository failure |
| `ConsumeCommittedOutboxFactFlow` | `ConsumeCommittedOutboxFact` | 单 fact 写事务 | `PublicationAcceptance: draft -> accepted/rejected` | duplicate event、payload 越界、source ack failure |
| `RunOutboxRelayFlow` | `RunOutboxRelay` | 每个 fact 一个写事务 | 多个 acceptance 创建 | partial success、cursor、source unavailable |
| `RunDeliveryProgressionFlow` | `RunDeliveryProgression` | 每个 delivery 一个写事务 | `scheduled -> dispatched/completed/failed` | dispatch success、backend failure、state conflict |
| `RecordDeliveryFeedbackFlow` | `RecordDeliveryFeedback` | 单 feedback 写事务 | `dispatched -> completed/failed/timed_out` | ack、fail、duplicate、unknown delivery |
| `ConsumeBackendDeliverySignalFlow` | `ConsumeBackendDeliverySignal` | 单 signal 写事务 | attempt finish，delivery 变更 | delivered、failed、private body rejected |
| `ConsumeTimeoutSignalFlow` | `ConsumeTimeoutSignal` | 单 timeout 写事务 | `dispatched -> timed_out/failed` | duplicate timeout、state conflict |
| `RequestRetryFlow` | `RequestRetry` | 单 retry request 写事务 | `RetryPlan: draft -> scheduled` | allowed retry、not eligible、existing active plan |
| `RunRetryCycleFlow` | `RunRetryCycle` | 每个 retry plan 一个写事务 | retry attempt / exhausted | due retry、exhausted、backend failure |
| `MoveDeliveryToDeadLetterFlow` | `MoveDeliveryToDeadLetter` | 单 DLQ 写事务 | `DeliveryRecord: failed -> dead_lettered` | created、not eligible、missing material |
| `PrepareReplayFlow` | `PrepareReplay` | 单 replay preparation 写事务 | `ReplayPreparation: draft -> ready/rejected` | ready、missing approval、audit chain invalid |
| `RunReadOutputProjectionFlow` | `RunReadOutputProjection` | 每个 projection item 一个写事务 | `ProjectionStatus: stale -> current` | incremental update、write failure |
| `RebuildReadProjectionFlow` | `RebuildReadProjection` | 每个 rebuild batch 一个事务 | projection batch replace | dry run、batch replace、version conflict |
| `CheckBackendCapabilityFlow` | `CheckBackendCapability` | 单 capability check 写事务 | backend health projection updated | available、degraded、secret unavailable |
| `QueryReadOnlyFlow` | 7 个 Query API | 无写事务 | 无 truth 状态变化 | not found、projection stale、access audit |
| `OutboundEventPublishFlow` | 9 个 Outbound Event | truth 已提交后发布 | 无 truth 状态变化 | publish success、retryable failure、schema violation |

### 8.2 写路径通用规则

```text
Inbound Adapter / Handler / Job Runner
  |
  v
parse_and_validate(input, actor, metadata)
  |
  v
Application Service
  |
  +-- idempotency lookup
  +-- UnitOfWork.begin
  +-- repository.get_for_update / unique check
  +-- domain method / policy
  +-- save truth + audit/history + outbox/evidence
  v
UnitOfWork.commit
```

关键说明：

- domain method 不访问 repository、event bus、HTTP、MQ、config。
- repository、publisher、source、transport、projection 调用必须通过 application port。
- source ack failure、publisher failure、projection failure 不回滚已提交 truth。
- Query 不进入写事务，不自动 rebuild projection。

## 9. 状态机与转换矩阵

> 校准来源：
> - `design-calibration/03_ddd_step_10_state_matrix.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 10 §7.2~§7.12 获取每个状态机的状态集合、ASCII 状态转换图、转换矩阵、非法转换处理和跨状态机禁止规则。

### 9.1 状态机总览

| 状态机 | 状态 enum | 拥有对象 | 是否影响 bus truth |
|---|---|---|---|
| Publication acceptance | `PublicationAcceptanceStatus` | `PublicationAcceptance` | 是 |
| Delivery lifecycle | `DeliveryStatus` | `DeliveryRecord` | 是 |
| Feedback result | `FeedbackStatus` | `FeedbackResult` | 是，一次生成即终态 |
| Retry plan | `RetryPlanStatus` | `RetryPlan` | 是 |
| Dead letter | `DeadLetterStatus` | `DeadLetterEntry` | 是 |
| Replay preparation | `ReplayPreparationStatus` | `ReplayPreparation` | 是 |
| Read projection | `ProjectionStatus` | `TransportViewProjection` / `FailureSummaryProjection` | 否，派生只读输出 |

### 9.2 关键转换摘要

| 状态机 | 允许转换摘要 | 禁止转换摘要 |
|---|---|---|
| Publication acceptance | `Draft -> Accepted`、`Draft -> Rejected` | accepted / rejected 之间互相改写 |
| Delivery | `Scheduled -> Dispatched -> Completed`；`Dispatched -> Failed/TimedOut`；`Failed -> RetryScheduled/DeadLettered` | 终态 reopen、跳过 attempt、backend raw status 直接写入 |
| Feedback | ack / fail / timeout 生成终态结果 | 把 feedback 当作多步生命周期迁移 |
| Retry plan | `Draft -> Scheduled`，due retry 产生 attempt，耗尽后 exhausted | exhausted 后继续 running，非 failed delivery 创建 retry |
| Dead letter | created 后可 replay prepared 或 archived | archived / closed 后 replay，active DLQ 重复创建 |
| Replay preparation | `Draft -> Ready` 或 `Draft -> Rejected` | 缺失 approval / audit chain 进入 ready |
| Projection | missing / stale / rebuilding / current | Query 触发写入，stale 被当 current 返回 |

### 9.3 跨状态机禁止规则

| 禁止规则 | 原因 |
|---|---|
| Query 不得把 projection missing / stale 自动改为 rebuilding | Query 不能产生隐藏写副作用 |
| Backend capability 不新增 bus truth 状态机 | 外部后端能力不是本仓 truth |
| Retry exhausted 不自动进入 DLQ | DLQ 是独立受控恢复动作 |
| Replay preparation 不直接改 delivery | replay executor 不属于本仓 P0 |
| Failure material 不是 governance decision | governance decision truth 属于 governance 仓 |

## 10. 数据持久化、事务与一致性契约

### 10.1 数据所有权

| 数据 | L0-bus 是否拥有 truth | 说明 |
|---|---|---|
| publication acceptance | 是 | 接入判定事实，包括 accepted / rejected |
| delivery record / attempt / history | 是 | bus delivery 生命周期事实 |
| feedback result | 是 | subscriber / backend / timeout 反馈事实 |
| retry / DLQ / replay preparation | 是 | bus recovery 链事实 |
| bus audit | 是 | append-only 审计事实 |
| read projection | 派生 | 只读输出，可 stale / rebuild |

### 10.2 Repository 到存储对象映射

| Repository | 主要存储对象 | 关键约束 |
|---|---|---|
| `PublicationRepository` | publication acceptances | `source_system + source_record_ref` 唯一；idempotency anchor |
| `DeliveryRepository` | delivery records、attempts、history | `delivery_id` lock / expected version |
| `FeedbackRepository` | feedback results | feedback unique key，防 duplicate / late feedback |
| `RecoveryRepository` | retry plans、dead letters、replay preparations、failure material | active retry / active DLQ / replay approval unique |
| `ReadProjectionRepository` | transport view、failure summary、backend health | projection version / stale marker |
| `BusAuditRepository` | audit entries | append-only sequence |
| `IdempotencyRepository` | idempotency anchors | scope + key + digest |

### 10.3 UnitOfWork 与事务规则

| 规则 | 契约 |
|---|---|
| 写 Command | 单 command 一个 UoW |
| Inbound Event | 单 event / fact 一个 UoW |
| Operations Job | 每个 item 一个 UoW，job summary 单独记录 |
| Query | 无写 UoW |
| publisher | truth 提交后发布，失败写 evidence / retry，不回滚 truth |
| source ack | truth 提交后 ack source；ack 失败不回滚，重复消费走幂等 |
| projection | 异步派生；projection 失败不回滚 truth |
| durable store 未确认 | P0 先实现 in-memory store，保持同语义 |

### 10.4 锁、版本与唯一约束

| 场景 | 控制方式 |
|---|---|
| 同一 delivery 并发推进 | `get_for_update` + `expected_version` |
| 同一 idempotency key 重复请求 | anchor digest 比对 |
| 同一 source fact 重复接入 | source ref 唯一约束 |
| 重复 active retry | active retry unique |
| 重复 active DLQ | active DLQ unique |
| replay preparation 重复提交 | `dead_letter_id + approval_ref` unique |
| projection rebuild / incremental 并发 | projection version |

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 13 §7.1~§7.9 获取并发场景表、幂等数据模型、幂等键计算、重复请求处理和测试切口。

### 12.1 幂等键表

| 来源 | 使用位置 | 说明 |
|---|---|---|
| HTTP header `x-idempotency-key` | 写 Command API | 与 request digest 绑定 |
| `RequestDigest` | 写 Command API | 区分同 key 同请求和同 key 不同请求 |
| Event metadata `event_id` | Inbound Event Consumer | 与 `source_ref` 和事件幂等键组合 |
| Source reference | outbox fact / backend signal / timeout signal | 防重复接入 |
| `job_run_id` | job summary | 标识一次 job run，不是业务 item 幂等键 |
| cursor + target id | job item | 防 job 重跑重复写 truth |
| repository unique constraint | truth / projection / evidence | 最后一层保护 |

### 12.2 重复调用处理

| 重复类型 | 处理方式 |
|---|---|
| same idempotency key + same digest | 返回 existing result |
| same idempotency key + different digest | `409 ConflictError` |
| same event id + same source ref + same digest | existing / duplicate result |
| same event id + different source / digest | rejected / conflict |
| same job run + same item key | skip 或 previous item result |
| new job run 扫描已处理 item | 读取当前状态后 skip / existing |
| publisher duplicate event | 返回 existing receipt，视为成功 |

### 12.3 关键并发场景

| 场景 | 控制方式 | 失败错误 |
|---|---|---|
| 两个 worker 推进同一 delivery | delivery lock + expected version | `VersionConflict` |
| feedback 与 timeout 并发 | feedback unique + delivery lock | duplicate / conflict |
| retry 与 DLQ 并发 | delivery lock + recovery policy | `RecoveryConflict` |
| projection rebuild 与 incremental 并发 | projection version | `ProjectionVersionConflict` |
| source ack 失败后重复消费 | idempotency anchor | existing result |
| publisher retry 重复发布 | publish evidence unique | existing receipt |

| 禁止项 | 原因 |
|---|---|
| raw secret | 只能使用 `SecretRef` |
| payload body fallback | L0-bus 不保存 payload 正文 |
| Query 自动 rebuild | 会产生隐藏写副作用 |
| domain 读取配置文件 | domain 必须保持纯粹 |
| application 直接依赖具体 DB / MQ config | application 只依赖 port trait |

## 14. 可观测性与审计埋点契约

> 校准来源：
> - `design-calibration/03_ddd_step_15_observability_audit.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 15 §7.1~§7.7 获取日志埋点、指标埋点、审计事件、trace 关联和 redaction 规则。

### 14.1 观测边界

```text
Command / Event / Job / Query entry
  |
  +-- structured log
  +-- metrics
  +-- trace context ref
  v
Application service
  |
  +-- BusAuditEntry
  +-- DeliveryHistoryEntry
  +-- publish / ack evidence
  +-- projection marker
```

关键说明：

- 日志用于排错，指标用于统计，审计用于 bus truth / recovery chain，三者不能互相替代。
- trace schema 由 L0-core 提供，L0-bus 只保存引用。
- metrics 只使用低基数标签，单记录定位走 trace / audit ref。
- 日志、审计、指标、evidence、projection 均不得保存 forbidden body。

### 14.2 必须观测的处理流

| 处理流 | 观测要求 |
|---|---|
| Publication acceptance | accepted / rejected / duplicate / boundary violation |
| Delivery progression | scheduled、dispatching、delivered、failed、backend unavailable |
| Feedback recording | ack、fail、timeout、duplicate、late feedback |
| Recovery | retry requested、retry exhausted、DLQ created、replay ready / rejected |
| Projection | stale、source missing、rebuild started / completed / failed |
| Outbound publish | published、retryable failed、schema / boundary rejected |
| Repository / UoW | transaction duration、commit failure、version conflict |

### 14.3 Redaction 规则

| 材料 | 禁止内容 |
|---|---|
| log | payload body、raw secret、backend private response、governance decision body |
| metric label | record id、payload digest 全量、secret ref 明文 |
| audit | payload body、raw secret、长期日志正文、治理决策正文 |
| event | payload body、raw secret、backend private body |
| projection | payload body、raw secret、可反推出 secret 的 backend private detail |
| evidence | 只保存引用化 evidence，不保存 forbidden body |

## 15. 测试切口与最小验证清单

### 15.1 测试切口总表

| 测试切口 | 对应契约 | 建议测试类型 |
|---|---|---|
| module tests | `contracts / domain / application / infra / api / worker / jobs` | unit / adapter / handler / job runner |

| state machine tests | §9 状态机 | domain unit / application |
| consistency tests | §10 transaction / projection / publisher | repository / service |
| idempotency tests | §12 anchor / digest / duplicate | application / concurrency |
| error recovery tests | §11 retryable / non-retryable / manual action | service / adapter |

### 15.2 必须覆盖的关键断言

| 断言 | 原因 |
|---|---|
| same key + same digest 返回 existing | 写 Command 幂等基础 |
| same key + different digest 返回 conflict | 防请求混淆 |
| Query 不写 truth，不自动 rebuild | 只读边界 |
| publisher failure 不回滚 truth | outbox / evidence 语义 |
| source ack failure 后重复消费 existing | at-least-once source recovery |
| projection failure 不回滚 truth | projection 派生边界 |
| forbidden body 不出现在 log / audit / event / projection / evidence | 安全红线 |

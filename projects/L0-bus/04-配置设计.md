## 3. 配置控制面总览

> 校准来源：
> - `design-calibration/04_config_step_03_control_plane_overview.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置来源链图”“配置装配总图”“配置控制面总表”和“模块读取边界表”小节，了解本章控制面如何收敛。

L0-bus 的配置控制面以 `RuntimeConfig` 为根对象，经由 `ConfigLoader`、`ConfigValidator` 和 `RuntimeBuilder` 进入 runtime。配置来源包括 code defaults、JSON config file、environment overrides、secret refs / connection refs 和 job 局部参数。config center / remote config 不进入 P0 默认来源链。

```text
code defaults
  -> JSON config file
  -> environment overrides
  -> secret refs / connection refs
  -> job local args, job entry only
  -> RuntimeConfig
  -> ConfigValidator
  -> ValidatedRuntimeConfig
  -> RuntimeBuilder
  -> RuntimeGraph
```

图后说明：

- `ConfigLoader` 负责读取配置来源并解析为 `RuntimeConfig`。
- `ConfigValidator` 负责类型、范围、交叉字段和禁止配置化边界校验。
- `RuntimeBuilder` 负责把已校验配置转成 repository、adapter、port、policy、handler 和 job runner。
- `contracts` 和 `domain` 不读取配置。

| 模块 | 是否直接读取配置 | 允许接收 | 禁止事项 |
|---|---|---|---|
| `contracts` | 否 | 编译期共享契约 | 不读取 JSON / env / secret |
| `domain` | 否 | 已校验参数、状态、policy 判断结果 | 不依赖 `RuntimeConfig` |
| `application` | 间接 | 已构造 port、policy set、service dependency | 不解析 JSON / env |
| `infra` | 是 | `RuntimeConfig` / `ValidatedRuntimeConfig` | 不把 adapter 私有配置泄漏给 domain |
| `api` | 入口级 | `ApiConfig` / handler graph | 不绕过 `ConfigValidator` |
| `worker` | 入口级 | `WorkerConfig` / worker graph | 不把 worker 参数写入 domain |
| `jobs` | 入口级 | `JobConfig` / job graph | 不绕过 recovery / projection policy |

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_classification_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置分类表”“禁止配置化项表”“热更新边界表”和“禁止配置化边界图”小节，了解本章分类和边界如何收敛。

L0-bus 的配置分为启动配置、运行参数配置、策略引用配置、敏感引用配置、外部接缝配置、测试 / fixture 配置、诊断 / 调试配置和 P1/P2 扩展配置。

| 配置类别 | 说明 | 示例 | 是否允许热更新 | 主要风险 |
|---|---|---|---|---|
| 启动配置 | 决定 runtime graph、adapter、entry 是否构造 | store kind、backend kind、publisher kind、API enabled | 否 | 运行时替换会破坏一致性 |
| 运行参数配置 | 控制 batch、timeout、poll interval 等 | `worker.batch_size`、`api.request_timeout_ms` | 否 | 值不当会影响吞吐和稳定性 |
| 策略引用配置 | 引用 retry、DLQ、replay 等策略 profile | `recovery_policy.retry_profile` | 否 | 绕过审计链或 DLQ |
| 敏感引用配置 | 只保存 secret / connection 引用 | `store.connection_ref`、`transport_backend.secret_ref` | 否 | 泄露敏感信息 |
| 外部接缝配置 | 后续生产 adapter 的稳定接缝 | external store、external backend、external publisher | 否 | 提前写字段会虚构实现 |
| 测试 / fixture 配置 | 支撑 local / CI 可复现测试 | fixed clock、deterministic id generator | 仅测试启动时 | 混入生产 profile |
| 诊断 / 调试配置 | 支撑本地诊断和报告 | validation report、local trace verbosity | local / test 有限允许 | 关闭 redaction 或 audit |
| P1/P2 扩展配置 | 后续 config center、KMS、多后端等 | remote config source、provider fields | 后续专项定义 | 影响 P0 范围 |

禁止配置化项不是普通配置值，而是设计红线。

| 禁止配置化项 | 原因 | 如需改变应走什么流程 |
|---|---|---|
| 保存 payload body | L0-bus 只保存 ref / digest / metadata | 回到需求、架构、详细设计重校准 |
| 保存 backend private body | backend 结果必须归一化 | 回到详细设计和安全设计 |
| 密钥明文写入配置、状态、日志或审计 | 破坏敏感配置边界 | 回到配置 Step 8 和安全门禁 |
| 关闭关键 audit / history | 破坏可追溯性 | 回到需求和详细设计 |
| projection 反写 bus truth | projection 是只读派生 | 回到架构和详细设计 |
| replay 绕过 DLQ / history / audit chain | replay preparation 不是 executor | 回到 recovery 设计 |
| backend raw status 直接写入 `DeliveryStatus` | backend 信号必须 normalization | 回到 backend signal 设计 |
| application 直接读取 DB / MQ / secret config | 破坏 ports and adapters | 回到详细设计 port / adapter 边界 |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置来源优先级表”“冲突处理表”“来源到配置类别映射”和“来源优先级图”小节，了解本章来源和冲突规则如何收敛。

普通配置来源优先级为：

```text
code defaults
  < JSON config file
  < environment variables
```

CLI args 不作为全局最高优先级，只作为 config source selector 或 operations job 的局部入口参数。secret refs / connection refs 不参与普通覆盖链；普通来源最多提供引用，不能提供密钥 material。

| 来源 | 优先级 | 适用配置 | 冲突处理 | 不可用时策略 |
|---|---|---|---|---|
| code defaults | 0 | P0 默认可验证路径、固定安全 policy | 被 JSON / env 覆盖 | 作为默认输入 |
| JSON config file | 1 | 启动配置、运行参数、adapter profile、policy ref、secret ref、connection ref | 覆盖 defaults；重复 key fail-fast | 未指定可用 defaults；指定不可读 fail-fast |
| environment variables | 2 | CI / local / staging override 的普通配置和 ref | 覆盖 JSON；非法值 fail-fast | 缺失则使用低优先级来源 |
| CLI args | 局部入口参数 | config file path、job run id、job profile、dry-run / diagnostic | 不覆盖全局配置 | 局部非法则该命令 fail-fast |
| secret refs / connection refs | 不参与普通优先级 | sensitive reference、credential ref、connection ref | 普通来源只能提供引用 | ref 非法 fail-fast；provider 不可用 fail-closed |
| config center / admin override | P1/P2 | 后续远程配置治理 | 当前不进入 P0 | 若声明为 P0 source 则 unsupported |

冲突规则：

| 冲突场景 | 处理方式 | 是否允许继续 |
|---|---|---|
| 同一 JSON 文件重复 key 或等价别名 | 拒绝配置 | 否 |
| env 提供非法 enum / integer / boolean | fail-fast，不回退 file/default | 否 |
| 普通来源提供密钥明文 | fail-closed | 否 |
| `kind=external` 但缺少 ref | fail-fast | 否 |
| `kind=in_memory` 但提供外部 secret / connection ref | fail-fast | 否 |

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_profiles_matrix.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“环境 / profile 配置矩阵”“profile 到测试验收承接表”“profile 与 P0 / P1 / P2 映射”和“profile 关系图”小节，了解本章 profile 矩阵如何收敛。

profile 是配置矩阵分类，不是本次新增的 `RuntimeConfig.profile` 字段。

| 环境 / profile | 用途 | 配置来源 | 外部依赖 | 敏感配置处理 | 差异说明 |
|---|---|---|---|---|---|
| local-dev | 本地开发和手动验证 | defaults + local JSON | in-memory store / backend / publisher, fixture source | fake ref 或空 ref | P0 |
| ci-test | CI 单元和集成测试 | defaults + fixture JSON + env | in-memory / fake adapters | fake ref | P0 |
| integration-test | 跨模块集成验证 | JSON + env override | fake L0-core outbox source、fake backend | fake provider | P0 |
| operations-recovery | recovery / replay preparation job 验证 | JSON + job local args | in-memory / fake store、fake audit chain | fake ref | P0 |
| staging-like | 后续 real-like adapter 演练 | staging JSON + env + refs | durable store、MQ、secret provider | ref only | P1 |
| production-like | 后续生产部署 | production config + provider refs | 生产 MQ / DB / KMS / observability | ref only | P1/P2 |

P0 只要求 local-dev、ci-test、integration-test 和 operations-recovery 默认可验证。staging-like 和 production-like 适用于后续跨仓集成和生产化，不阻塞当前配置设计。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“敏感配置表”“禁止输出规则”“敏感引用流转图”和“敏感配置失败策略表”小节，了解本章敏感配置规则如何收敛。

L0-bus P0 不接收密钥明文，只接收引用。测试环境也必须使用 fake ref 和 fake resolver，不允许引入明文路径。

| 配置项 | 敏感级别 | 存储方式 | 是否可明文 | 轮换方式 | 审计要求 |
|---|---|---|---|---|---|
| `store.connection_ref` | `sensitive-ref` | JSON / env 中保存 `ConnectionRef`；`ValidatedRuntimeConfig` 中保存已校验引用 | 否 | provider 侧轮换 material；L0-bus 重启或 job restart 后使用 ref | 记录字段路径、ref 类型、短摘要、校验结果 |
| `transport_backend.secret_ref` | `sensitive-ref` | JSON / env 中保存 `SecretRef`；adapter constructor 只接收 ref | 否 | provider 侧轮换 material；backend adapter 重建后生效 | 记录 backend kind、ref 类型、短摘要、构造结果 |
| `publisher.secret_ref` | `sensitive-ref` | JSON / env 中保存 `SecretRef`；publisher adapter 只接收 ref | 否 | provider 侧轮换 material；publisher adapter 重建后生效 | 记录 publisher kind、ref 类型、短摘要、构造结果 |
| `security_boundary.secret_policy` | internal security policy | defaults / JSON / env 中固定为 `ref_only` | 不适用 | 改变该 policy 必须重新设计 | 记录 policy 是否符合固定口径 |
| `security_boundary.redaction_policy` | internal security policy | defaults / JSON / env 中固定为 `required` | 不适用 | 改变该 policy 必须重新设计 | 记录 redaction policy 是否启用 |

禁止输出规则：

| 输出位置 | 允许输出 | 禁止输出 | 失败 / 门禁策略 |
|---|---|---|---|
| log | 字段路径、错误分类、短摘要、trace id | 完整引用值、密钥明文、credential material、backend private detail | redaction check 失败则测试失败 |
| error response | 稳定错误码、字段路径、错误分类 | 完整引用值、密钥明文、provider 返回正文 | 返回前必须脱敏 |
| audit | actor、操作、结果、短摘要、trace id | 密钥明文、完整 DSN、token、private key、provider 私有响应 | 审计写入前执行 redaction |
| metric label | 模块、错误分类、adapter kind | 完整 ref、record id、payload digest 全量、credential 相关值 | 指标注册或测试中拒绝 |
| reports / artifacts | 通过 redaction 的摘要和失败分类 | 可恢复密钥的信息、完整引用值、provider body | redaction check 必须覆盖 |

```text
JSON file / env / job local args
  -> SecretRef / ConnectionRef only
  -> ConfigLoader parses references
  -> ConfigValidator checks shape and security policy
  -> ValidatedRuntimeConfig keeps references
  -> RuntimeBuilder passes references to adapter constructors
  -> provider adapter resolves material behind boundary
  -> logs / audit / reports receive redacted summary only
```

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_load_validate_apply.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置加载流程图”“配置加载校验表”“校验阶段拆分表”和“reload / hot update 拒绝规则”小节，了解本章加载校验机制如何收敛。

P0 配置只在 entry / job 启动时加载。运行中 reload 和 hot update 不进入 P0。

```text
code defaults
  -> JSON config file
  -> environment overrides
  -> job local args, job entry only
  -> ConfigLoader.parse_and_merge
  -> RuntimeConfig
  -> ConfigValidator.type_validate
  -> ConfigValidator.range_validate
  -> ConfigValidator.cross_field_validate
  -> ConfigValidator.forbidden_boundary_validate
  -> ValidatedRuntimeConfig
  -> RuntimeBuilder.build_policy_set
  -> RuntimeBuilder.build
  -> RuntimeGraph
  -> api / worker / jobs entries
```

| 配置项 / 配置组 | 加载时机 | 校验方式 | 生效方式 | 失败策略 |
|---|---|---|---|---|
| `RuntimeConfig` root | entry / job 启动 | 必须包含所有 root 子配置组,缺失则由 defaults 补齐或报错 | 生成 `ValidatedRuntimeConfig` | 不完整且无默认值 fail-fast |
| `store` | entry 启动 | enum、ref shape、`kind` 与 `connection_ref` 交叉校验 | 构造 repository / UnitOfWork | 非法 fail-fast |
| `outbox_source` | worker / job 启动 | enum、cursor ref、batch range | 构造 source adapter | 非法 fail-fast |
| `transport_backend` | entry / worker / job 启动 | enum、capability ref、secret ref、timeout ref、kind/ref 交叉校验 | 构造 backend adapter | 非法 fail-fast；安全违规 fail-closed |
| `publisher` | entry / worker / job 启动 | enum、secret ref、timeout ref、kind/ref 交叉校验 | 构造 publisher adapter | 非法 fail-fast；安全违规 fail-closed |
| `api` | API 入口启动 | enabled、bind profile、timeout range | 启动 API handlers | 非法 fail-fast |
| `worker` | worker 入口启动 | enabled、poll interval、batch range、timeout ref | 启动 worker loop | 非法 fail-fast |
| `jobs` | job invocation 启动 | batch range、cursor ref、retry ref、job local args 局部校验 | 启动 job runner | 非法则该 job 失败 |
| `projection` | entry / job 启动 | enum、rebuild mode、consistency marker | 构造 projection repository / query dependency | 自动 rebuild 或 truth write 相关值 fail-closed |
| `recovery_policy` | entry / job 启动 | retry ref、DLQ policy、replay audit chain policy | 构造 recovery policy set | 绕过 audit / DLQ fail-closed |
| `security_boundary` | entry / job 启动 | 固定 policy 校验 | 构造 payload guard、redaction guard、privileged operation guard | 任一 policy 被放宽 fail-closed |
| `clock` | entry / job 启动 | enum、profile 兼容性 | 构造 clock adapter | prod-like 使用 fixed fail-fast |
| `id_generator` | entry / job 启动 | enum、profile 兼容性 | 构造 id generator adapter | prod-like 使用 deterministic fail-fast |

P0 reload / hot update 行为：

| 请求类型 | P0 行为 | 旧配置 | 新配置 | 审计 / 诊断 |
|---|---|---|---|---|
| runtime reload | 拒绝 | 保留旧 `RuntimeGraph` | 不应用 | 记录 unsupported reload |
| hot update single key | 拒绝 | 保留旧 `RuntimeGraph` | 不应用 | 记录 unsupported hot update |
| job local args change | 仅影响本次 job invocation | 不改变全局配置 | 本次 job 校验后使用 | 记录 job config summary |
| file update on disk | 不自动感知 | 运行中不变 | 下次重启读取 | 可在诊断中显示摘要 |

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置变更表”“审计与回滚规则”和“配置变更流程图”小节，了解本章变更治理如何收敛。

本章不绑定具体工单系统，只定义配置治理要求。

| 变更类型 | 发起方 | 评审要求 | 生效方式 | 审计记录 | 回滚方式 |
|---|---|---|---|---|---|
| local-dev / ci-test fixture 变更 | 开发者 / 测试执行者 | 不需要正式评审,但需通过测试 | 下次测试运行生效 | test report 记录配置摘要 | 恢复 fixture 文件 |
| runtime JSON config file 变更 | 项目维护者 / 部署操作者 | 中高风险项需评审 | 重启 API / worker 后生效 | config path、old/new summary、validation result、trace id | 恢复上一份已知可用配置并重启 |
| environment override 变更 | 部署操作者 / CI 维护者 | 影响外部 adapter、敏感 ref、policy 时需评审 | 重启入口后生效 | env key 映射后的 config path 和摘要 | 移除 override 或恢复旧值并重启 |
| job local args 变更 | operations job 执行者 | 高风险 job 需评审 | 本次 job invocation 生效 | job id、args summary、validation result | 重新发起合法 job |
| secret / connection ref 变更 | 部署操作者 / 安全边界维护者 | 必须评审 | 重启入口或 job restart 后生效 | ref 类型、短摘要、adapter kind、validation result | 恢复旧 ref 或修复 provider 后重启 |
| adapter kind 切换 | 项目维护者 / 部署操作者 | 必须评审,且需要对应测试验收通过 | 重启入口后生效 | old/new kind、capability profile、validation result | 切回上一 adapter kind 并重启 |
| recovery policy 变更 | 项目维护者 / recovery 操作者 | 必须评审 | 重启入口或 job restart 后生效 | policy path、old/new summary、actor、trace id | 恢复旧 policy 并重启 |
| security boundary policy 变更 | 不允许普通发起 | 必须重开设计校准 | 不通过配置生效 | 记录 rejected change attempt | 不应用新值 |
| reload / hot update 请求 | 不允许普通发起 | 不适用 | P0 拒绝 | 记录 unsupported request | 旧 runtime graph 保持不变 |

```text
change request
  -> classify config path and risk
  -> review if required
  -> update JSON / env / job args / ref
  -> ConfigLoader parses and merges
  -> ConfigValidator validates
  -> RuntimeBuilder builds or rejects
  -> restart entry or run job
  -> audit redacted change summary
  -> run smoke / integration check
```

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_modes.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“失效模式表”“fail-fast / fail-closed / degraded / last-known-good 规则”和“失效处理流程图”小节，了解本章失效处理如何收敛。

| 失效模式 | 影响 | 系统行为 | 是否告警 | 测试切口 |
|---|---|---|---|---|
| 未指定配置文件且 defaults 可覆盖 | 使用默认可验证路径 | 使用 code defaults 后继续 validator | 否 | config default path test |
| 指定配置文件不存在 | 无法确认配置来源 | fail-fast,启动失败 | 是 | config file missing test |
| JSON 解析失败 | 无法形成 `RuntimeConfig` | fail-fast,启动失败 | 是 | invalid JSON test |
| env override 类型错误 | 高优先级值非法 | fail-fast,不回退 JSON/file/default | 是 | env parse error test |
| 必填 root 配置组缺失且无默认值 | `ValidatedRuntimeConfig` 不完整 | fail-fast | 是 | missing required group test |
| enum 值不支持 | adapter / policy 不可构造 | fail-fast | 是 | unsupported enum test |
| batch / timeout 范围错误 | worker/job/API 行为不可控 | fail-fast | 是 | range validation test |
| kind/ref mismatch | 外部 adapter 缺少引用或本地 profile 带敏感引用 | fail-fast | 是 | cross-field validation test |
| security policy 被放宽 | 安全边界被破坏 | fail-closed | 是 | forbidden boundary test |
| redaction policy 被关闭 | 输出可能泄露敏感信息 | fail-closed | 是 | redaction config test |
| secret / connection ref 形态非法 | provider 无法解析 | fail-fast | 是 | secret ref shape test |
| provider 不可用 | external adapter 不可构造 | fail-fast,不得自动切回 in-memory | 是 | fake provider unavailable test |
| config center 声明为 P0 source | 来源链超出 P0 | unsupported source,fail-fast | 是 | unsupported source test |
| runtime reload 请求 | P0 不支持运行时替换配置 | 拒绝请求,保留旧 graph | 是 | reload rejection test |
| hot update 单 key 请求 | P0 不支持局部热更新 | 拒绝请求,保留旧 graph | 是 | hot update rejection test |
| reports / artifacts 泄露敏感值 | 安全验收失败 | redaction check 失败 | 是 | redaction report test |

| 策略 | 适用场景 | 本项目口径 |
|---|---|---|
| fail-fast | parse、type、range、missing required、unsupported enum、unsupported source | 立即失败,不构造 `RuntimeGraph` |
| fail-closed | security boundary、redaction、forbidden behavior | 拒绝启动或拒绝请求,不得放宽安全边界 |
| degraded | 仅当用户显式选择 in-memory / fixture profile | 不因外部失败自动降级 |
| last-known-good | 人工恢复上一份已知可用配置并重启 | 不做运行时自动回退 |

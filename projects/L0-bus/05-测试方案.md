### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 bus 能“发消息”,而是系统验证 `L0-bus` 是否真正满足“共享传递主干契约层”的设计要求,尤其要证明以下几点成立:
- EventEnvelope / CommandEnvelope / CallbackEnvelope 构成正式包络真相层
- `Envelope ≠ payload`、`CallbackEnvelope ≠ raw callback` 两条核心边界成立
- RoutingRule / ChannelBinding / DeliverySemantic 构成正式路由与传递语义主干,且 `DeliverySemantic ≠ MQ 配置`
- retry / dead-letter / replay 必须围绕正式幂等锚点与 delivery history 运行
- `DeadLetterEntry ≠ 普通错误日志`、`BusAuditTrail ≠ raw MQ logs` 两条留痕边界成立
- sdk / observability / governance / operators 围绕同一 bus truth 消费只读输出,不会漂移成多套语义
- `SdkConsumeTransportView ≠ bus truth`、`EscalatedFailureMaterial ≠ governance decision` 两条投影边界成立

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 共享包络与消息骨架部分 | 真相对象 | P0 | EventEnvelope、CommandEnvelope、CallbackEnvelope、EnvelopeMetadata |
| 路由与通道约束部分 | 真相对象 | P0 | TopicRef、StreamRef、RoutingRule、ChannelBinding、DeliverySemantic |
| 幂等、重试与死信部分 | 恢复对象 | P0 | IdempotencyKey、RetryHint、DeadLetterEntry、ReplayMaterial |
| 总线审计与可追溯部分 | 真相对象 | P0 | BusAuditTrail、DeliveryHistoryEntry、CausalityLink |
| 观测与上游下游消费接缝部分 | 投影对象 | P0 | BusTraceMaterial、BusMetricsSnapshot、EscalatedFailureMaterial、SdkConsumeTransportView |
| MQ 后端产品内部实现细节 | 非范围 | P2 | 只验证 bus 与 backend 接缝,不验 NATS/Redis/Kafka 内部产品逻辑 |
| observability / governance / sdk 全部仓内正文逻辑 | 非范围 | P2 | 只验 bus 对外输出接缝,不验下游仓全部细节 |
| 业务 payload 语义正确性 | 非范围 | P2 | 只验证 payload 如何被封装与传递,不判定业务正文含义 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和局部不变量 | domain / policy owner | `envelope.validate_envelope_boundary`、`routing_rule.validate_channel_contract`、`failed_delivery.build_idempotency_key`、`escalated_failure.validate_read_only_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + projection 联动 | backend / domain owner | `BuildEventEnvelope`、`ResolveRoutingRule`、`RegisterDeliveryFailure`、`AppendBusAuditTrail`、`BuildSdkConsumeView`、`BuildEscalatedFailureMaterial` | 主写链、恢复链、投影链同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | core metadata → bus envelope、payload → routing、dead-letter → governance consume、audit → observability、transport view → sdk | 输入输出语义一致 |
| 恢复专项测试 | 验证 retry 耗尽、dead-letter、replay、audit chain 断裂等异常链 | architecture / QA | missing metadata、route not found、retry exhausted、replay denied、audit incomplete | 真相不丢失、链路可恢复或被正确阻断 |
| 投影一致性测试 | 验证 trace / metrics / sdk / escalation 视图与 bus truth 一致 | backend / QA | trace rebuild、metrics rebuild、sdk consume rebuild、escalation rebuild | 投影只读且与真相一致 |
| 端到端主线测试 | 验证最小运行闭环 | QA / owner | payload → envelope → routing → delivery → audit；failure → dead-letter → replay → consume views | 主干传递闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `Envelope ≠ payload` | payload 被封装后不能反向改写 envelope truth | 单元 + 集成测试 | 是 | boundary log / DB snapshot |
| `CallbackEnvelope ≠ raw callback` | raw callback 不可直接成为正式总线材料 | 单元 + 集成测试 | 是 | negative flow / error code |
| `DeliverySemantic ≠ MQ 配置` | route 与 semantic 一致,但不退化成 backend 参数 | 单元 + 集成测试 | 是 | contract compare |
| retry / dead-letter / replay 链成立 | retry 耗尽后进入死信并可准备 replay | 集成 + 恢复专项测试 | 是 | retry history / replay material |
| `DeadLetterEntry ≠ 普通错误日志` | 死信记录必须绑定 envelope/history | 集成测试 | 是 | dead-letter record |
| `BusAuditTrail ≠ raw MQ logs` | replay 与 operator review 都依赖 audit chain | 集成 + 事件链测试 | 是 | audit trail / compare report |
| `SdkConsumeTransportView ≠ bus truth` | sdk view rebuild 不影响 bus 主写链 | 投影一致性测试 | 是 | projection diff |
| `EscalatedFailureMaterial ≠ governance decision` | failure material 只能只读消费 | 单元 + 集成测试 | 是 | negative flow / view snapshot |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local DB / fake backend adapter / fake sdk-observe consumers | debug logging / replay enabled / trace visible | 容易只测 happy path |
| test | CI / 集成测试 | test DB / deterministic routing fixtures / fake observability & governance consumers | isolated tables / fixed envelope fixtures / retry thresholds controllable | replay 与 projection 分支样本不足 |
| staging | 端到端演练 | real-like core input / domain payload / backend adapter / observability consume | audit append / dead-letter / replay / metrics projection enabled | 多消费侧时序差异放大 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | BuildEventEnvelope 成功创建正式事件包络 | payload + metadata skeleton 合法 | BuildEventEnvelope | EventEnvelope 写入成功 |
| TC-002 | metadata 缺失时拒绝构造 envelope | trace/source 缺失 | BuildEventEnvelope | 返回 `INVALID_METADATA` |
| TC-003 | raw callback 不得直接进入 CallbackEnvelope | 提供 raw callback 而非 formal draft | BuildCallbackEnvelope | 返回边界错误 |
| TC-004 | ResolveRoutingRule 正常生成 ChannelBinding | envelope 合法 + route 可解析 | ResolveRoutingRule | RoutingRule / ChannelBinding 写入成功 |
| TC-005 | delivery semantic 与 route 不一致时拒绝绑定 | semantic 不匹配 | ResolveRoutingRule | 返回 `ROUTING_RULE_NOT_FOUND` 或 contract error |
| TC-006 | failed delivery 可继续 retry | retry hint 允许 | RegisterDeliveryFailure | 写入 retry record |
| TC-007 | retry 耗尽后进入 DeadLetterEntry | max attempts exhausted | RegisterDeliveryFailure | dead-letter 与 replay material 同时生成 |
| TC-008 | 无 dead-letter 时禁止 PrepareReplay | dead_letter_id 不存在 | PrepareReplay | 返回 `DEAD_LETTER_NOT_FOUND` |
| TC-009 | audit chain 断裂时禁止 replay | history 缺失 | PrepareReplay | 返回 `AUDIT_CHAIN_INCOMPLETE` |
| TC-010 | AppendBusAuditTrail 形成正式审计主链 | delivery result 存在 | AppendBusAuditTrail | BusAuditTrail append 成功 |
| TC-011 | SdkConsumeTransportView 重建不反写真相 | projection rebuild | BuildSdkConsumeView | projection 更新,主写链不变 |
| TC-012 | EscalatedFailureMaterial 只读输出成立 | dead-letter + audit summary 存在 | BuildEscalatedFailureMaterial | governance consume view 可读但不生成 decision |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | Envelope/Payload 混层 / replay 绕过 dead-letter / audit chain 断裂仍被放行 / projection 反写主链 | 阻断放行,必须修复 |
| A | 主线可跑但 retry/dead-letter/replay/audit/projection 语义不稳 | 原则上修复后再放行 |
| B | 非关键 metrics/trace/query 视图异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 envelope / metadata 结构,都必须回归 `Envelope ≠ payload` 与 callback 边界主线
- 每次改动 routing / stream / semantic 规则,都必须回归 route + semantic 一致性主线
- 每次改动 retry / dead-letter / replay,都必须回归 exhausted retry、dead-letter、audit chain、replay deny/allow 主线
- 每次改动 audit / history 逻辑,都必须回归 operator review 与 replay compare 主线
- 每次改动 sdk / trace / metrics / escalation projection,都必须回归只读边界与 projection rebuild 一致性

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| backend adapter 差异后续扩大 | route / semantic 测试矩阵需扩充 | TL / 架构 |
| replay policy 后续细分 | 恢复测试需增加更多授权与策略分支 | bus / governance |
| observability 与 sdk consume 视图继续长胖 | 投影一致性与边界测试需增加更多样本 | Owner / TL |

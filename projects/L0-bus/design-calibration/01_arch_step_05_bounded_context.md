### 3. SOP 问题回答

1. 本仓内部有哪些子域或本地上下文？

   回答：本仓内部划分为传递语义核心、发布材料承接、订阅 delivery 推进、失败恢复、只读输出、后端适配边界和本地引用 / 投影上下文。

2. 哪些是核心子域？

   回答：核心子域是传递语义核心，承载 publication acceptance、transport semantic、delivery lifecycle、ack / fail / timeout、idempotency anchor 和 bus audit 的统一语义。

3. 哪些是支撑子域？

   回答：支撑子域包括发布材料承接、订阅 delivery 推进、失败恢复、只读输出和后端适配边界。它们围绕传递语义核心展开，但有不同变化方向。

4. 哪些只是外部上下文的本地索引 / 投影 / 引用？

   回答：core contract reference、payload reference、outbox fact reference、backend capability reference、transport view、tap / trace / metrics material 和 failure summary material 都属于本地引用或投影，不是业务正文或外部决策真相。

5. 它们之间的上下文映射关系是什么？

   回答：发布材料承接把外部事实入口转为可进入传递语义核心的材料；订阅 delivery 推进和失败恢复围绕同一 delivery truth 演进；只读输出从 bus truth 派生视图；后端适配边界把核心传递语义映射到具体后端能力；本地引用 / 投影只服务边界稳定和可追溯。

6. 为什么这些部分不能混成一个上下文？

   回答：传递语义核心必须最稳定，后端适配随 MQ 能力变化，只读输出随消费方视角变化，失败恢复有独立授权和审计约束，引用 / 投影不能反向定义 bus truth。

### 4. 当前文档问题诊断

| 位置 | 当前问题 | 影响 |
|---|---|---|
| §5.1 | 旧文档以 API context、Adapter context、Outbox、DLQ / Replay、Ops context 等划分 | 混入实现接口、技术适配和运维工具 |

| §5.3 | 以 crate 名和 trait 关系描述上下文映射 | 源码结构和实现依赖误写成语义关系 |
| 全文 | 缺少本地引用 / 投影与 bus truth 的区分 | transport view、tap、failure summary 容易反写真相 |

### 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 划分依据 | API、adapter、outbox、ops 等实现视角 | 传递语义核心、支撑上下文、本地引用 / 投影视角 | 限界上下文应按语义边界划分 |
| 核心子域 | EventBus trait / EventEnvelope 等对象主导 | 传递语义核心主导 | 核心应表达稳定语义 |
| 支撑子域 | 后端适配和运维工具并列 | 发布承接、delivery、失败恢复、只读输出、后端适配边界 | 更贴合需求闭环 |
| 本地影子结构 | 未显式区分 | 单列 contract / payload / outbox / backend 引用和只读投影 | 防止快照和引用误成真相 |

### 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A：沿用 API / Adapter / Outbox / Ops context | 接近旧实现想象 | 把实现形态当成语义边界 | 不采用 |
| 方案 B：按传递语义核心 + 支撑上下文 + 本地引用 / 投影划分 | 与需求闭环和数据归属一致 | 需要后续再映射到容器和代码结构 | 采用 |
| 方案 C：只保留一个 bus 上下文 | 简单 | 无法表达失败恢复、只读输出和后端适配的不同变化方向 | 不采用 |

### 7. 结构化中间产物

#### 7.1 子域 / 上下文划分表

| 名称 | 类型 | 作用 | 与其他部分的关系 |
|---|---|---|---|
| 传递语义核心 | 核心子域 | 承载 publication acceptance、transport semantic、delivery lifecycle、结果留痕、幂等锚点和 bus audit。 | 所有支撑上下文围绕它展开，不被后端或消费方反向定义。 |
| 发布材料承接上下文 | 支撑子域 | 将合法发布材料和已提交 outbox fact 引用带入 bus 传递主线。 | 只承接入口边界，不拥有业务 payload 正文或业务 outbox truth。 |
| 订阅 delivery 推进上下文 | 支撑子域 | 围绕订阅关系和 delivery 推进形成面向订阅方的传递过程。 | 消费传递语义核心，不拥有订阅方业务处理结果正文。 |
| 失败恢复上下文 | 支撑子域 | 承载 retry、dead-letter、replay preparation 和失败材料形成。 | 依赖 delivery history 和 audit chain，不直接生成治理决策。 |
| 只读输出上下文 | 支撑子域 | 派生 transport view、tap output、audit material、failure material 和运行状态材料。 | 只读消费，不反写 bus truth。 |
| 后端适配边界上下文 | 支撑子域 | 把平台传递语义映射到 MQ backend 能力。 | 吸收后端差异，不允许裸后端参数泄漏为上层语义。 |
| 本地引用 / 投影上下文 | 本地索引 / 投影 / 引用 | 保存 core contract、payload、outbox fact、backend capability 等引用和派生视图。 | 不拥有外部正文真相，只服务追溯和边界稳定。 |

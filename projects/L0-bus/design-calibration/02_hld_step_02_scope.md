### 3. SOP 问题回答

1. 本次概要设计最主要要把哪些结构说清？

   回答：本次概要设计最主要要把 `L0-bus` 的事件传递主干从架构边界下沉为可实现结构，包括代码主体框架、主要组成部分、关键对象、能力接口骨架、关键处理流、状态集合与状态流转、异常边界和配置影响轮廓。

2. 这一轮概要设计应停在什么深度，才算足够支撑进入详细设计？

   回答：应停在“可实现结构骨架”深度。可以点名正式对象、服务、port、projection、job、command、query、event 和状态名；可以列关键字段骨架并说明类型方向；可以列函数骨架并说明参数类型方向；但不写完整 Rust struct / enum / trait、协议 schema、HTTP path、topic 命名全集、DDL、索引、完整函数实现和部署参数。

3. 哪些内容属于本次概要设计范围？

   回答：范围包括：把 publication acceptance、transport semantic、delivery progression、feedback result、retry / dead-letter / replay preparation、audit / history、read-only output、backend adapter boundary、durable store boundary 转译为概要设计层结构；说明各结构的职责和边界；为详细设计提供对象、接口、流程和状态机输入。

4. 哪些内容虽然相关，但当前不进入概要设计范围？

   回答：不进入范围的内容包括：生产 MQ adapter 的最终产品选择、durable store 产品细节、授权承接方最终实现、Outbox relay 部署形态、具体配置 schema、性能基准数字、DLQ UI、multi-tenancy、Filter DSL、effectively-once 专项和完整 ops runbook。

5. 哪些内容应留给详细设计，而不应在本章提前展开？

   回答：Rust crate / module / file 目录、完整 DTO、完整 trait、完整 struct / enum、字段全集、函数签名全集、错误码全集、JSON / proto schema、数据库表、索引、事务边界、API 路径、topic 命名、具体 adapter 实现和测试用例细节都应留给详细设计、配置设计、测试方案或实施计划。

### 7. 结构化中间产物

#### 7.1 设计目标表

| 目标 | 说明 | 交付给详细设计的结果 |
|---|---|---|
| 收稳代码主体框架 | 把架构中的事件传递主干、容器和边界转译为概要设计层代码主体骨架 | 代码主体框架图、实现分层视图、业务主要组成部分与实现分层关系 |

| 收稳状态定义与流转 | 明确 delivery、feedback、retry、dead-letter、replay preparation、projection 等状态如何变化 | 状态集合表、状态流转图和不允许流转清单 |

#### 7.3 当前阶段设计深度口径

- 本轮概要设计必须能让详细设计继续 1:1 展开,但不直接替代详细设计。
- 本轮可以使用正式对象名、接口名、状态名、处理流名和 port 名。
- 本轮可以写关键字段骨架,字段必须标明类型方向,但不写完整字段全集和序列化 schema。
- 本轮可以写成员函数 / 工厂函数骨架,参数必须标明类型方向,但不写完整 Rust 签名和实现代码。
- 本轮可以画处理流和状态流转图,但不写完整调用链、事务代码、HTTP path、topic 命名全集或数据库表结构。
- 本轮必须保留未收稳事项的边界,不能把后续专项或 P1/P2 能力写成 P0 当前结论。

## 3. SOP 问题回答

### 3.1 正式文档是否按书写规范章节主链组织？

是。正式 `03-详细设计.md` 使用以下 18 章：

```text
1. 与上游文档的关系声明
2. 本次详细设计目标与范围
3. 实现约束与编码规范承接
4. 实现单元与文件布局
5. 模块实现契约
6. 全局对象 / Trait / API 索引
7. API / Command / Query / Event / Job 协议契约
8. 逐接口函数级处理流
9. 状态机与转换矩阵
10. 数据持久化、事务与一致性契约
11. 错误模型、异常分支与恢复口径
12. 并发、幂等与重入保护
13. 配置引用与外部依赖绑定
14. 可观测性与审计埋点契约
15. 测试切口与最小验证清单
16. 详细设计到实施计划的承接清单
17. 风险与待确认事项
18. 参考
```

### 3.2 第 5 章是否以模块为主轴？

是。第 5 章按 `contracts / domain / application / infra / api / worker / jobs` 展开，每个模块说明职责、文件、主要对象 / trait / 函数和测试切口。第 6 章只做全局索引，不替代第 5 章。

### 3.3 对象、trait、协议、处理流、状态机是否互相可回指？

是。正式文档通过以下链路保证回指：

```text
模块契约 (§5)
  -> 对象 / trait / API 索引 (§6)
  -> 协议契约 (§7)
  -> 函数级处理流 (§8)
  -> 状态机 / 事务 / 错误 / 幂等 (§9~§12)
  -> 配置 / 观测 / 测试 (§13~§15)
```

每章还保留 `design-calibration` 校准来源，重对象和重流程的完整字段、函数、伪代码继续由对应 Step 的结构化中间产物承载，正式文档给出实施入口和索引。

### 3.4 其他 agent 是否可以按本文 1:1 实现代码？

可以，但必须按正式文档要求同步阅读对应 `design-calibration` 中间产物。正式文档是实施入口和主契约，重章节的完整展开位于：

| 内容 | 详细展开位置 |
|---|---|
| 对象字段和函数 | `03_ddd_step_06_object_contracts.md` |
| Trait / Port / Adapter | `03_ddd_step_07_trait_port_adapter_contracts.md` |
| API / Command / Query / Event / Job schema | `03_ddd_step_08_protocol_contracts.md` |
| 函数级处理流和伪代码 | `03_ddd_step_09_function_flows.md` |
| 状态机矩阵 | `03_ddd_step_10_state_matrix.md` |
| 持久化、错误、幂等、配置、观测、测试 | Step 11~16 |

### 3.5 是否有内容误放到测试方案、实施计划、配置设计或运维手册？

没有。正式文档只保留：

| 下游文档 | 本文保留 | 本文不写 |
|---|---|---|
| 配置设计 | config struct、loader、validator、binding point | 完整 JSON 示例、环境变量、部署填写说明 |
| 测试方案 | 最小测试切口、脚本契约 | 完整测试矩阵、覆盖率、CI 编排 |
| 实施计划 | 实施承接清单和前置阅读 | 阶段、任务拆分、commit boundary |
| 运维手册 | 日志、指标、审计埋点切口 | 告警阈值、dashboard、runbook |

## 3. SOP 问题回答

### 3.1 正式文档是否按 15 章主链组织?

是。正式文档使用以下主链:

```text
1. 与上游文档的关系声明
2. 本次测试目标与范围
3. 测试对象与测试切口
4. 测试策略与分层
5. 需求追溯与覆盖矩阵
6. 测试场景与用例设计
7. 测试数据设计
8. 测试环境与配置矩阵
9. 自动化与 CI/CD 门禁
10. 专项测试与非功能验证
11. 缺陷管理与复验规则
12. 进入准则与退出准则
13. 测试报告与证据归档
14. 回归策略与残余风险
15. 参考
```

### 3.2 是否保留所有 P0 测试对象、场景、数据、环境、门禁和证据?

是。正式文档必须保留:

| 内容 | 正式章节 |
|---|---|
| P0 / P0-min 测试目标和非范围 | §2 |
| domain、service、repository、adapter、API、worker、job、config、redaction、reports 切口 | §3 |
| unit / service / integration / contract / release gate 分层 | §4 |
| CL / F / BR 到 TS / TC / EV / RP 的追溯 | §5 |
| `TS-BUS-001`~`010` 和 `TC-BUS-*` 用例族 | §6 |
| `DS-BUS-*` 数据集、fixture、`run_id` 隔离 | §7 |
| `ci-test`、`integration-test`、`operations-recovery` 环境 | §8 |
| PR / main CI / nightly / release gate | §9 |
| security、consistency、recovery、config、observability、report integrity 专项 | §10 |
| S0 / S1 / S2 / S3 / P1-risk | §11 |
| 进入 / 退出清单 | §12 |
| `artifacts/test/<run_id>`、`reports/runs/<run_id>`、`reports/acceptance` | §13 |
| 回归触发和残余风险 | §14 |

### 3.3 是否删除 SOP 问题原文和讨论语气?

是。正式文档不保留“应问的问题”“当前文档问题诊断”“改动前后对比”“测试设计取舍”等中间产物章节标题。正式文档只保留已收敛的测试方案结论和必要表格。

### 3.4 是否所有未确认项都进入残余风险?

是。Step 1~14 没有阻塞正式文档的待确认事项。P1/P2 未覆盖项已进入 §14 残余风险,并绑定责任角色。

### 3.5 是否能被 `06-验收标准.md` 直接消费?

是。正式文档将提供:

- P0 / P0-min 用例矩阵。
- 证据编号和归档路径。
- 进入 / 退出准则。
- S0 / S1 / risk acceptance 规则。
- report / acceptance handoff 结构。

`06-验收标准.md` 可以基于这些内容裁决通过、否决和条件接受。

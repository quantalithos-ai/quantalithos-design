## 3. SOP 问题回答

### 3.1 当前仓是否已经具备完整的 00 / 01 / 02 / 03 / 05 / 06 文档?

具备。当前还额外具备 `04-配置设计.md`,这对实施计划是必要输入,因为 `03`、`05`、`06` 均已经把配置加载、profile、secret ref、runtime graph 和 fail-fast / fail-closed 作为 P0 支撑门禁。

### 3.2 哪些上游文档版本是本轮实施计划的基线?

本轮以 `00` v0.2.0、`01` v0.2.0、`02` v0.2.0、`03` v0.2.0、`04` v0.1.0、`05` v0.2.0、`06` v0.2.0 为实施计划输入基线。

### 3.3 详细设计是否已经足以支持 1:1 实现?

基本足够。`03-详细设计.md` 已明确:

- 目标实现仓: `/home/aris/Projects/quantalithos-bus`。
- 稳定上游: `/home/aris/Projects/quantalithos-core`。
- 编译期依赖: `core-contracts = { path = "../quantalithos-core/crates/contracts" }`。
- workspace / crate / module / scripts / artifacts / reports 目录。
- 对象、trait、API、event、job、处理流、状态机、事务、一致性、错误、配置和测试切口。

但实施前仍需在 Step 3 检查目标实现仓是否存在、core contracts path dependency 是否可用、git config 是否合格、Rust 编码规范是否已读取。

### 3.4 测试方案和验收标准是否足以定义阶段门禁?

足够。`05-测试方案.md` 已定义 TC / EV / RP、gate scripts、report scripts、check scripts、`artifacts/test/<run_id>`、`reports/runs/<run_id>` 和 `reports/acceptance`。`06-验收标准.md` 已定义 AC-FUNC、AC-RED、AC-IF、AC-STATE、AC-NFR、AC-EVID、VETO、缺陷分级、风险接受和签署口径。

### 3.5 是否存在上游文档之间的冲突?

未发现阻塞性冲突。当前主要需要在实施计划中保持以下一致性:

- 实现仓不是 design 仓,源码注释、rustdoc、测试名和 commit message 必须使用英文。
- 只有 `L0-core shared contracts` 是已确认的编译期 path dependency。
- MQ backend、store、publisher、source、observability、governance、SDK 等是运行期、事件协作或只读消费边界,不得写成本地 path dependency。
- reports / artifacts 路径不得带 `<project>` 层级,不得使用 `latest`。

### 3.6 哪些缺口会阻塞实施计划,哪些缺口可以记录为风险继续推进?

没有阻塞制定实施计划的文档缺口。实现仓 `/home/aris/Projects/quantalithos-bus` 当前未发现存在,这不阻塞继续写实施计划,但会影响 Step 3 和 Step 5 之后的实施前置条件:如果目标仓不存在,实施计划必须明确建仓和 workspace 初始化步骤。

## 6. 实施设计取舍

### 6.1 是否在 Step 1 直接规划阶段

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 直接规划阶段 | 速度快 | 会跳过实施目标、前置条件和交付物抽取 |
| B. 只确认输入边界,阶段规划留到 Step 5 | 符合 SOP,边界清楚 | 需要多一步推进 | 采用 |
| C. 把 Step 1~3 合并 | 看似省时 | 违反逐 Step 规则 | 不采用 |

### 6.2 是否把目标实现仓不存在视为 blocker

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 视为 blocker,暂停实施计划 | 严格 | 实施计划本身可以定义建仓步骤 |
| B. 记录为 Step 3 前置条件和 Step 5 初始阶段输入 | 能继续规划 | 需要后续明确初始化步骤 | 采用 |
| C. 忽略 | 简单 | 实施者可能找错目录 | 不采用 |

### 6.3 是否把 design-calibration 全部列为全局必读

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 全部列为必读 | 信息完整 | 成本过高,不符合实施计划书写规范 |
| B. Step 3 按阶段 / commit boundary 建阅读矩阵 | 精准 | 需要阶段拆分后映射 | 采用 |
| C. 完全不读 | 省时间 | 细节追溯不足 | 不采用 |

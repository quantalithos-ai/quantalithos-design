## 3. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 1. 正式文档是否完整覆盖书写规范章节主链 | 必须覆盖 §1~§13,其中 §1~§12 对应 Step 1~12,§13 汇总参考。 |
| 2. 每一章是否来自已确认中间产物 | 是。每章开头必须列出具体 `design-calibration` 文件和延伸阅读小节。 |
| 3. 阶段编号、任务编号和门禁编号是否一致 | 正式文档必须沿用 PH-01~PH-08、commit-01-a~commit-08-b、TC / AC / VETO 编号。 |
| 4. 上游引用、测试引用和验收引用是否准确 | 以 `00`~`06` 和 Step 1~12 为准,不得新增未确认设计。 |
| 5. 是否存在详细设计内容被复制进实施计划 | 正式文档只保留实施顺序、交付物、门禁、提交和完成判定,不复制完整 struct / enum / API / 函数实现。 |
| 6. 是否存在未解释的空表、空图或占位内容 | 不允许。正式文档不得包含占位文本、乱码或空表占位。 |

## 4. 当前文档问题诊断

| 问题 | 表现 | 风险 | 本步处理 |

| 正式 `07-实施计划.md` 尚不存在 | `projects/L0-bus/07-实施计划.md` 当前缺失 | 实施者无统一入口 | 本步创建正式文档 |

| 正式章节必须可追溯 | 规范要求列校准来源 | 读者无法复查决策来源 | 每章显式列校准来源和延伸阅读 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 完整复制 Step 1~12 所有表格 | 信息最全 | 正式文档过长,读者难抓主线 | 不采用 |
| 正式文档只写链接 | 最短 | 实施者无法直接执行 | 不采用 |
| 正式文档保留执行核心,细节通过延伸阅读追溯 | 可读且可执行 | 读者需要按需查看中间产物 | 采用 |

| 规范来源 | 必须遵守的内容 | 对本文的影响 |

| `standards/document/实施计划书写规范.md` | 实施前必须确认阅读清单、编码规范、提交规范和项目级 git 配置 | §16 承接到实施计划 |
| `projects/README.md` §8.2 | 当前 design 仓 commit 使用中文 subject / body；其他实现仓 commit message 使用英文；footer 固定为 Codex | 交付目标实现仓时必须区分提交语言边界 |

| 约束 | 说明 | 影响的模块 / 接口 |
|---|---|---|
| 详细设计以 Rust 契约表达 | 对象、trait、DTO、event、job、错误和伪代码按 Rust 可实现形态描述 | 全文 |
| Domain 不依赖基础设施 | 领域对象和 policy 不依赖 HTTP、DB、bus、blob、gateway 或下游系统 | `domain_*` |
| 外部 I/O 必须走 port | repository、audit、outbox、gate、reference、blob、event publisher、clock、id generator 通过 trait / adapter 承接 | `application_ports` / `infra_adapters` |
| 本仓不实现认证授权 | 入口只接收可信 gateway 传入的 actor / metadata / gate 引用 | Command / Query / Job |
| 本仓不保存凭据正文 | token、session、credential secret 不进入数据模型、日志或审计 | DTO / persistence / audit |
| 本仓不吸收外部正文 | 标准、ADR、业务、运行、观测、归档正文只保存引用、fingerprint、摘要或追溯锚点 | reference / snapshot / trace |
| 本仓不实现 L0-bus runtime | outbox 和 `EventPublisherPort` 只是边界 | event / outbox / jobs |

## 4. 实现单元与文件布局

> 校准来源：
> - `design-calibration/03_ddd_step_04_units_file_layout.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“布局形态决策表”“实现单元总表”“文件布局树”“文件职责表”和“待确认事项”小节，了解目标实现仓布局如何从概要设计转译而来。

### 4.1 布局形态决策

| 候选布局 | 是否采用 | 判断依据 | 影响 |
|---|---|---|---|
| 单 crate 模块分层架构 | 否 | 本仓同时包含共享协议、领域模型、应用服务、infra adapter、CLI 和 jobs，单 crate 会让依赖边界过宽 | 不采用 |
| workspace 多 crate 架构 | 是 | 可以让 contracts / domain / application / infra / cli / jobs 明确依赖方向 | 作为 P0 目标实现布局 |

### 4.2 实现单元总表

命名规则：

- 文件目录使用短语义名，例如 `crates/application`。
- Cargo package 使用 `core-*` 前缀，例如 `core-application`。
- Rust library crate 使用 `core_*` 前缀，例如 `core_application`。
- 目录名不重复写入 `l0`，因为目标实现仓本身已经表达 L0-core 项目边界。

| 目录 / 资产根 | 类型 | Cargo package / Rust crate | 职责 | 对应概要设计章节 |
|---|---|---|---|---|
| `contract-source/` | asset root | - | 结构化契约源码真相 | §4 / §5 |
| `release-snapshots/` | asset root | - | 只读发布快照 | §5 / §8 |
| `crates/contracts` | library crate | `core-contracts` / `core_contracts` | Command / Query / Event / Job / View / Receipt / Error DTO | §7 |
| `crates/domain` | library crate | `core-domain` / `core_domain` | 领域对象、状态、策略和不变量 | §6 / §9 |
| `crates/application` | library crate | `core-application` / `core_application` | application service、port trait、用例编排、事务边界 | §7 / §8 |
| `crates/infra` | library crate | `core-infra` / `core_infra` | 文件型 store、toolchain runner、publisher、resolver、runtime wiring | §10 / §13 |
| `crates/cli` | binary crate | `core-cli` / `core` | CLI command / query / operations trigger | §7 / §8 |
| `crates/jobs` | binary crate | `core-jobs` / `core-*` job binaries | 后台 job 和 outbox relay worker | §7 / §8 |

### 5.2 模块依赖图

```text
[cli_entry] -- call --> [application_services]
[jobs]      -- call --> [application_services]

[application_services] -- use port --> [application_ports]
[infra_adapters]       -- impl port --> [application_ports]

[application_services] -- use --> [domain_definition]
[application_services] -- use --> [domain_packages]
[application_services] -- use --> [domain_release]
[application_services] -- use --> [domain_snapshot]
[application_services] -- use --> [domain_reference_projection]
[application_services] -- use --> [domain_fact]
[application_services] -- use --> [domain_policies]

[domain_packages]             -- use --> [domain_definition]
[domain_release]              -- use --> [domain_definition]
[domain_release]              -- use --> [domain_reference_projection]
[domain_snapshot]             -- use --> [domain_release]
[domain_reference_projection] -- use --> [domain_definition]
```

关键说明：

- `domain_*` 不依赖 `application`、`infra`、`cli`、`jobs`。
- `application_services` 只依赖 port trait，不依赖 concrete adapter。
- `infra_adapters` 实现 port，但不得被 domain / application 反向依赖。
- `cli_entry` 和 `jobs` 是入口适配，不承载领域规则。

### 5.4 对象实现契约示例

```rust
/// 契约定义聚合根，维护共享契约的真相、生命周期、版本和演进记录。
pub struct ContractDefinition {
    /// 契约定义唯一标识。
    pub definition_id: ContractDefinitionId,
    /// 契约所属范围。
    pub scope: ContractScope,
    /// 当前聚合版本，用于乐观锁。
    pub aggregate_version: AggregateVersion,
    /// 当前生命周期。
    pub lifecycle: ContractLifecycle,
    /// 当前正文引用，正文不进入 L0-core。
    pub body_ref: ContractBodyRef,
    /// 当前指纹。
    pub fingerprint: ContractFingerprint,
    /// 外部引用集合。
    pub references: Vec<ExternalReference>,
    /// 演进记录。
    pub evolution: Vec<ContractEvolutionRecord>,
}
```

| 函数签名 | 作用 | 参数说明 | 返回 | 副作用 / 不变量 |
|---|---|---|---|---|
| `ContractDefinition::create_draft(ContractDefinitionId definition_id, ContractDefinitionDraftSpec spec, ActorContext actor, Timestamp now) -> Result<ContractDefinition, DomainError>` | 创建草稿定义 | `spec` 提供范围、正文引用、指纹和引用集合 | 新聚合 | 初始状态必须为 `Draft` |
| `ContractDefinition.update_draft(ContractDefinitionDraftSpec spec, ActorContext actor, Timestamp now) -> Result<(), DomainError>` | 更新草稿 | `spec` 提供新正文引用和指纹 | 成功或领域错误 | 只允许 `Draft` 编辑 |

| `ContractDefinition.retire(LifecycleReason reason, ActorContext actor, Timestamp now) -> Result<(), DomainError>` | 退役定义 | `reason` 必填 | 成功或领域错误 | 终态后不得继续迁移 |

## 8. 逐接口函数级处理流

> 校准来源：
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的每个 flow 伪代码、事务边界、错误映射和副作用说明。

### 8.1 写路径统一调用壳

```text
[CLI / library caller]
  |
  v
[ContractCommandApi]
  |
  v
[ApplicationService]
  |
  +--> IdempotencyRepository.reserve(...)
  +--> UnitOfWork.begin(...)
  +--> Repository.get_for_update(...)
  +--> Domain method
  +--> Repository.save(...)
  +--> AuditLogPort.append(...)
  +--> OutboxPort.append(...)
  +--> UnitOfWork.commit(...)
  +--> IdempotencyRepository.complete(...)
```

关键说明：

- 幂等保护发生在 application service 边界。
- truth、audit、outbox 必须在同一事务边界或等价原子边界内提交。
- projection 更新不得反向阻塞 truth 提交。

### 8.2 Command 处理流表

| 处理流 | 对应协议 | 入口函数 | 主要事务 | 状态变化 | 测试切口 |
|---|---|---|---|---|---|
| `CreateContractDraftFlow` | `CreateContractDraft` | `ContractChangeService.create_contract_draft(...)` | 新建 definition、audit、outbox | 创建 `Draft` | 创建成功 / 幂等冲突 |
| `UpdateContractDraftFlow` | `UpdateContractDraft` | `ContractChangeService.update_contract_draft(...)` | 锁定 definition、更新 body ref / fingerprint | `Draft -> Draft` | stale version / 无效引用 |
| `SubmitContractForReviewFlow` | `SubmitContractForReview` | `ContractChangeService.submit_contract_for_review(...)` | 锁定 definition、提交评审、outbox | `Draft -> InReview` | 非法状态 / 内容不完整 |
| `PublishContractBaselineFlow` | `PublishContractBaseline` | `ContractReleaseService.publish_contract_baseline(...)` | gate、fingerprint、baseline、definition、outbox | `InReview -> Published`，baseline `Prepared -> Released` | gate fail / fingerprint mismatch |
| `UpdateContractLifecycleFlow` | `UpdateContractLifecycle` | `ContractReleaseService.update_contract_lifecycle(...)` | 锁定 definition、生命周期迁移、outbox | `Published / Deprecated -> Deprecated / Retired / Superseded` | 终态保护 / reason 缺失 |

### 8.3 Query 处理流表

| 处理流 | 对应协议 | 入口函数 | 读模型 | 错误 / 边界 |
|---|---|---|---|---|
| `GetContractDefinitionQueryFlow` | `GetContractDefinition` | `ContractTraceService.get_contract_definition(...)` | `ContractReadModel` | not found / stale |
| `ListContractDefinitionsQueryFlow` | `ListContractDefinitions` | `ContractTraceService.list_contract_definitions(...)` | projection index | 空结果不是错误 |
| `GetReleaseBaselineQueryFlow` | `GetContractReleaseBaseline` | release / trace service | baseline view | not found / not released |
| `GetReleaseSnapshotQueryFlow` | `GetContractReleaseSnapshot` | `ContractSnapshotService.get_release_snapshot(...)` | snapshot metadata | building / invalid |
| `TraceContractEvolutionQueryFlow` | `TraceContractEvolution` | `ContractTraceService.trace_contract_evolution(...)` | trace projection | trace 缺口 |
| `GetCompatibilityTraceQueryFlow` | `GetCompatibilityTrace` | `ContractCompatibilityService.get_compatibility_trace(...)` | compatibility trace index | stale / not found |

### 8.4 Job / Relay 处理流表

| 处理流 | 对应 Job | 入口 | 主要动作 | 失败恢复 |
|---|---|---|---|---|
| `ValidateContractChangeJobFlow` | `ValidateContractChangeJob` | job binary | 读取 definition / baseline，调用 validation runner，写 compatibility trace | job 可重跑 |
| `DeriveReleaseSnapshotJobFlow` | `DeriveReleaseSnapshotJob` | job binary | 读取 baseline，导出 snapshot，保存 metadata，写 outbox | 同 fingerprint 重跑幂等 |

| `OutboxRelayFlow` | `OutboxRelayWorker` | relay binary | fetch pending，publish，mark published / failed | 单条失败不终止整批 |

```text
Draft
  | submit_for_review(...)
  v
InReview
  | publish(...)
  v
Published
  | deprecate(...)
  v
Deprecated
  | retire(...)
  v
Retired

Published / Deprecated
  | supersede(...)
  v
Superseded
```

| From | To | 触发函数 | 前置条件 | 非法时错误 |
|---|---|---|---|---|
| 创建 | `Draft` | `ContractDefinition::create_draft(...)` | 范围、正文引用、边界校验通过 | `DomainError::InvariantViolation` |
| `Draft` | `Draft` | `ContractDefinition.update_draft(...)` | 当前状态允许编辑 | `DomainError::IllegalStateTransition` |
| `Draft` | `InReview` | `ContractDefinition.submit_for_review(...)` | 草稿完整、引用有效 | `DomainError::IllegalStateTransition` |
| `InReview` | `Published` | `ContractDefinition.publish(...)` | gate approved、fingerprint 匹配、compatibility passable | `DomainError::IllegalStateTransition` |
| `Published` | `Deprecated` | `ContractDefinition.deprecate(...)` | reason 存在 | `DomainError::IllegalStateTransition` |
| `Published / Deprecated` | `Retired` | `ContractDefinition.retire(...)` | reason 存在 | `DomainError::IllegalStateTransition` |
| `Published / Deprecated` | `Superseded` | `ContractDefinition.supersede(...)` | 新 definition 有效且不是自身 | `DomainError::IllegalStateTransition` |

### 9.3 统一非法转换处理

| 场景 | domain 错误 | application 映射 | 是否保持原状态 |
|---|---|---|---|
| from / to 不在允许矩阵 | `DomainError::IllegalStateTransition` | `ApplicationError::PreconditionFailed` | 是 |
| 终态继续迁移 | `DomainError::IllegalStateTransition` | `ApplicationError::PreconditionFailed` | 是 |
| 缺少 reason / gate / evidence | `DomainError::InvariantViolation` | `ApplicationError::PreconditionFailed` | 是 |
| 乐观锁冲突导致状态保存失败 | 不进入 domain 错误 | `ApplicationError::Conflict` | 是 |
| projection port 状态更新失败 | 不进入 domain 错误 | `ApplicationError::Port` | 是 |

P1 迁移不得伪装为 P0：

| P1 项 | P0 处理方式 |
|---|---|
| `InReview -> Draft` 退回草稿 | 本轮不暴露 command |
| snapshot `Ready -> Superseded` | 本轮只实现 building -> ready / archive 主线 |
| package 写协议 | 本轮只保留领域约束 |
| `EventCatalogReference.mark_stale(...)` | 本轮使用 invalidate / resolve 表达 |

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的存储对象、repository 方法、事务边界和一致性策略。

### 10.1 存储对象总表

| 存储对象 | 所属 root / store | 写入者 | 一致性口径 |
|---|---|---|---|
| `contract_definitions` | `contract-source` / repository | command flow | truth 强一致 |
| `release_baselines` | repository | publish flow | 与 definition 发布同事务 |
| `release_snapshots` | `release-snapshots` + metadata | snapshot job | metadata 与资产原子提交 |
| `audit_records` | `./state/audit` | command / job / relay | 与 truth 同事务或等价原子边界 |
| `outbox_events` | `./state/outbox` | command / job | 与 truth 同事务；relay 最终一致 |
| `projection_indexes` | `./state/projection` | projection / rebuild job | 最终一致，可 stale |
| `idempotency_records` | `./state/idempotency` | command / job | reserve / complete 保护重复进入 |

### 10.2 事务边界

| 处理流 | 事务内 | 事务外 |
|---|---|---|
| Command 写路径 | idempotency reserve、truth save、audit append、outbox append、idempotency complete | projection rebuild、event publish |
| Snapshot derive | metadata save、audit、outbox | toolchain exporter、资产生成准备 |
| Validate change | trace index save、audit、outbox | toolchain validation runner |
| Outbox relay | mark published / failed | event publisher publish |
| Projection rebuild | projection batch write、watermark update | truth 写入 |

### 10.3 一致性规则

| 规则 | 说明 |
|---|---|
| truth 更新必须使用 expected version | 防止并发覆盖 |
| outbox 与 truth 同事务 | 已提交事实必须可恢复发布 |
| projection 不阻塞 truth | projection 失败标记 stale / 重建 |
| audit 不得静默失败 | truth 成功但审计失败会破坏追溯 |
| snapshot asset 与 metadata 必须匹配 fingerprint | 防止下游消费错误快照 |
| idempotency record 保存 payload fingerprint | 防止同 key 不同 payload 复用 |

> - 建议继续阅读上述中间产物的错误类型、错误映射、异常分支和恢复口径。

| 错误类型 | 触发条件 | 对外映射 | 是否可重试 | 恢复方式 |
|---|---|---|---|---|
| `DomainError::InvariantViolation` | 对象不变量失败 | `ApplicationError::PreconditionFailed` | 否 | 修正输入或状态 |
| `DomainError::IllegalStateTransition` | 非法状态迁移 | `ApplicationError::PreconditionFailed` | 否 | 重新读取状态 |
| `ApplicationError::Validation` | DTO / command 校验失败 | `invalid_argument` | 否 | 修正请求 |
| `ApplicationError::Conflict` | expected version / idempotency 冲突 | `conflict` | 视情况 | 重新读取或使用同 key 重试 |
| `ApplicationError::PreconditionFailed` | gate / fingerprint / reference 不满足 | `precondition_failed` | 否 | 补齐前置条件 |
| `ApplicationError::Port` | repository / toolchain / publisher / resolver 失败 | `dependency_unavailable` | 是 | 重试 job 或恢复依赖 |
| `ApplicationError::Internal` | 不变量破坏或未预期错误 | `internal` | 否 | 人工排查 |

异常恢复口径：

| 场景 | 处理 |
|---|---|
| gate / reference / blob 不可用 | fail closed，不发布 |
| toolchain runner 失败 | job 失败，可重跑，不回滚 truth |
| outbox publish 成功但 mark published 失败 | 保持同一 CloudEvent id 可重放 |
| relay 单条失败 | 标记单条 failed，继续处理批次 |
| projection rebuild 失败 | 保持 stale，后续重建 |
| idempotency reserve payload mismatch | 返回 `Conflict` |

## 12. 并发、幂等与重入保护

> 校准来源：

> 延伸阅读：

### 12.1 幂等调用壳

```text
[Command / Job input]
  | includes IdempotencyKey / JobRunId
  v
[IdempotencyRepository.reserve(scope, key, operation, payload_fingerprint)]
  |-- completed same payload --> replay receipt
  |-- same key different payload --> Conflict
  |-- in progress duplicate --> Conflict
  v
[UnitOfWork + Repository + Domain + Audit + Outbox]
  v
[IdempotencyRepository.complete(scope, key, receipt)]
```

### 12.2 并发与幂等表

| 场景 | 控制方式 | 失败错误 | 测试切口 |
|---|---|---|---|
| 两个草稿更新同时修改同一 definition | `save(expected_version)` | `Conflict` | 后者失败 |
| 两个发布请求同时发布同一 definition | definition 锁 + current baseline 唯一键 | `Conflict` | 只生成一个 released baseline |
| command 同 key 同 payload 重复提交 | idempotency record | replay receipt | 返回既有结果 |
| command 同 key 不同 payload | payload fingerprint mismatch | `Conflict` | 拒绝复用 key |
| snapshot derive job 重跑 | baseline + job id / fingerprint | replay / skip | 不生成重复快照 |
| projection rebuild 并发 | `ProjectionRebuildId` + watermark 不倒退 | `Conflict` / `Port` | 旧 rebuild 不覆盖新水位 |
| outbox relay 多 worker 并发 | CloudEvent id + mark 事务 | skip / `Port` | 不重复完成 |

## 14. 可观测性与审计埋点契约

> 校准来源：

> 延伸阅读：
> - 建议继续阅读上述中间产物的日志埋点表、指标埋点表、审计事件表和字段边界说明。

### 14.1 trace 传播规则

```text
[RequestMetadata / CommandMetadata / QueryMetadata]
  trace_id
  request_id
  requested_at
        |
        v
[application_service / job / relay]
        |
        +--> logs
        +--> audit records
        +--> metrics tags
```

规则：

- 所有写路径和关键读路径都要把 `trace_id` 传进日志和审计。
- `span_name` 由协议名或处理流名派生，例如 `CreateContractDraftFlow`。
- `request_id` 用于串联单次请求的入口和回执，不得作为业务主键。
- 日志、指标、审计不得保存原始正文、凭据、token 或外部系统返回全文。

### 14.2 日志埋点表

| 位置 | 日志级别 | 字段 | 目的 |
|---|---|---|---|

| Query 入口开始 | `debug` / `info` | `trace_id`、`request_id`、`query`、`consistency_mode` | 追踪读路径 |
| Job 开始 | `info` | `trace_id`、`job_id`、`job`、`input_ref` | 追踪后台任务开始 |
| Validation / gate / reference failure | `warn` | `trace_id`、`operation`、`error_code`、`reason` | 识别前置条件失败 |
| Conflict / idempotency replay | `warn` / `info` | `trace_id`、`operation`、`idempotency_key`、`result` | 识别重复请求和并发冲突 |
| Port / toolchain / publisher failure | `error` | `trace_id`、`operation`、`dependency`、`error_code` | 识别外部依赖失败 |

## 3. 配置控制面总览

> 校准来源：
> - `design-calibration/04_config_step_03_control_plane_overview.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置来源链图”“配置控制面总表”“对详细设计的影响判定”和“待确认事项”小节，了解控制面如何收敛。

#### 配置来源链图: L0-core P0 配置进入 runtime

```text
[code defaults]
      |
      v
[project config file]
      |
      v
[environment variables]
      |
      v
[CLI flags]
      |
      v
[CoreRuntimeConfig]
      |
      +--> build_cli_runtime(CoreRuntimeConfig config)
      |
      +--> build_job_runtime(CoreRuntimeConfig config)
```

关键说明:

- 本图表达 P0 普通配置来源链,不表达 secret material、config center 或 admin override。
- application service 和 domain object 不直接读取配置源。
- 配置只能影响 runtime 装配和外部依赖绑定,不能绕过领域不变量、审计、gate、fingerprint、outbox 或 idempotency。

### 3.1 配置控制面总表

| 控制面 | 当前 P0 处理 | 进入配置项清单 |
|---|---|---|
| storage roots | 通过 `CoreRuntimeConfig` 装配文件型 source / snapshot / projection / audit / outbox / idempotency store | 是 |
| reference resolver | 通过 `reference_resolver_config` 装配 resolver adapter | 是 |
| event publisher binding | 由 adapter wiring / outbox relay 边界承接 | 否 |
| toolchain runner | 由 runner port / job 实现承接 | 否 |
| gate / blob adapter | 由 adapter wiring 承接,失败 fail closed | 否 |
| domain invariants | 不能配置化 | 否 |
| audit / outbox / idempotency 原子边界 | 不能配置关闭 | 否 |

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_classification_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置分类表”“禁止配置化项表”“对详细设计的影响判定”和“待确认事项”小节，了解分类边界如何收敛。

### 4.1 配置分类表

| 分类 | 说明 | P0 是否纳入 |
|---|---|---|
| 启动配置 | CLI / job 启动前必须解析和校验的配置 | 是 |
| 运行时装配配置 | runtime builder 用来装配 adapter / port 的配置 | 是 |
| 策略配置 | 只允许表达环境差异,不能改变领域不变量 | 部分 |
| 敏感配置 | secret ref / credential ref / adapter-local binding | P0 无 secret 正式项 |
| 调试配置 | local / CI 诊断用途 | 不作为正式 P0 配置项 |
| 演进配置 | config center、admin override 等未来能力 | P2 |

### 4.2 禁止配置化项表

| 禁止配置化项 | 原因 | 如需改变 |
|---|---|---|
| 契约范围判断 | 会让非共享对象进入 L0-core 真相 | 回到 00/01 评审 |
| published 内容不可原地修改 | 会破坏版本、fingerprint 和 audit trace | 回到 02/03 |
| gate / compatibility / fingerprint 约束 | 会破坏发布基线可信度 | 回到 01/03 |
| audit append | 关闭后无法追溯 | 回到 03 并评审 |
| outbox 与 truth 提交边界 | 关闭后事实不可恢复发布 | 回到 03 |
| idempotency 校验 | 关闭后命令 / job 可能重复写入 | 回到 03 |
| raw secret 输出脱敏 | 关闭后泄露敏感信息 | 不允许配置化 |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置来源优先级表”“冲突处理表”“对详细设计的影响判定”和“待确认事项”小节，了解来源规则如何收敛。

P0 普通配置来源按以下顺序覆盖：

```text
code defaults < project config file < environment variables < CLI flags
```

### 5.1 来源优先级表

| 来源 | 优先级 | 用途 | 不可用或非法时 |
|---|---|---|---|
| code defaults | 1,最低 | root path 默认值、基础默认装配 | 默认值必须可构造 |
| project config file | 2 | 项目级配置 | 文件不存在可用 defaults;文件存在但不可读 / 解析失败 fail fast |
| environment variables | 3 | CI / release-like / local override | 值存在但非法 fail fast |
| CLI flags | 4,最高普通来源 | 单次命令 / job override | 值存在但非法 fail fast |
| secret refs | 不参与普通优先级 | future sensitive ref | ref 非法或不可解析时 fail fast / fail closed |
| config center / admin override | P2 | future online config | 当前 P0 不支持 |

### 5.2 冲突处理表

| 冲突场景 | 处理 |
|---|---|
| 同一 key 出现在不同优先级普通来源 | 高优先级覆盖低优先级 |
| 同一来源重复 key 或等价别名 key | fail fast |
| 高优先级值类型错误或路径非法 | fail fast,不得回退低优先级 |
| 普通来源包含 raw secret | 拒绝配置 |
| 出现 P0 不支持的 config center / admin override | fail fast 或未知字段处理 |
| 试图通过配置关闭禁止配置化项 | fail fast + 设计变更流程 |

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_profiles_matrix.md`
>
> 延伸阅读：

L0-core 没有常驻在线 runtime container。本轮 profile 是配置矩阵分类,不是 `CoreRuntimeConfig.runtime_profile` 字段。

### 6.1 profile 配置矩阵

| profile | 用途 | 配置来源 | adapter / 外部依赖口径 | 测试验收承接 |
|---|---|---|---|---|
| local-dev | 本地开发和手工验证 | defaults + file + env + CLI | fake / local file store | 默认配置、非法路径、覆盖顺序 |
| ci-test | 自动化测试 | defaults + test config + env | deterministic fixture / fake adapter | 缺失配置、冲突、失效模式 |
| release-like | 发布前近真实演练 | versioned file + env + CLI | real-like adapter,无真实 secret | 高风险 root、resolver、回滚证据 |
| operations-replay | 运维重放 / 恢复演练 | replay config + env | 脱敏历史引用,不回放 raw secret | replay、projection rebuild、outbox 恢复 |

`staging-integration` 和 `production-ops` 属于 P1/P2 真实部署语境,具体路径、挂载、密钥和告警由 `09-部署与运维手册.md` 承接。

## 7. 配置项清单

> 校准来源：
> - `design-calibration/04_config_step_07_config_items.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“P0 配置项清单”“模块级示例配置”“汇总配置示例”“本地配置 key 到 CoreRuntimeConfig 映射”和“对详细设计的影响判定”小节，了解配置项如何从详细设计收敛。

本轮 P0 正式配置项只覆盖 `03-详细设计.md` 已确认的 7 个 `CoreRuntimeConfig` 输入。项目配置文件默认使用严格 JSON;本地配置 key 按功能模块拆分,不额外包裹 `core` 项目名前缀,并映射到既有 Rust 字段,不新增代码契约。若未来存在系统级聚合配置文件,再使用 `core.<module>.<setting>` 作为聚合 key。

| 配置项 | 类型 | 默认值 | 是否必填 | 来源 | 生效方式 | 敏感级别 | 失败策略 | 关联模块 |
|---|---|---|---|---|---|---|---|---|
| `contract_source.root` | `ContractSourceRoot` | `./contract-source` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 路径非法或不可读 fail fast | runtime builder / source store |
| `release_snapshot.root` | `ReleaseSnapshotRoot` | `./release-snapshots` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 路径非法或不可写 fail fast | runtime builder / snapshot store |
| `projection_index.root` | `ProjectionIndexRoot` | `./state/projection` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 路径非法 fail fast;projection 失败 stale / rebuild | projection store |
| `audit.root` | `AuditRoot` | `./state/audit` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 路径非法或 audit append 不可用 fail fast | audit adapter |
| `outbox.root` | `OutboxRoot` | `./state/outbox` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 路径非法 fail fast;publish 失败 pending / failed | outbox adapter / relay |
| `idempotency.root` | `IdempotencyRoot` | `./state/idempotency` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 路径非法 fail fast;payload mismatch conflict | idempotency repository |
| `reference_resolver.config` | `ReferenceResolverConfig` | `ReferenceResolverConfig::default()` | 外部非必填;runtime 必需 | defaults / file / env / CLI | 启动 / 作业启动读取 | internal | 配置非法 fail fast;引用读取失败 fail closed | reference resolver adapter |

### 7.2 汇总配置示例

以下示例是带注释的 JSONC 文档示例。实际运行时配置文件必须删除注释并保持严格 JSON。

```jsonc
{
  "contract_source": {
    // 契约源码输入目录;必须可读,不得与 release_snapshot.root 相同。
    "root": "./contract-source"
  },

    "root": "./state/projection"
  },
  "audit": {
    // 审计记录目录;审计写入失败不得静默成功。
    "root": "./state/audit"
  },
  "outbox": {
    // 待发布事件 outbox 目录;publish 失败保留 pending / failed。
    "root": "./state/outbox"
  },
  "idempotency": {
    // 幂等记录目录;用于 replay、conflict 和重复提交保护。
    "root": "./state/idempotency"
  },
  "reference_resolver": {
    // ReferenceResolverConfig;空对象表示使用 ReferenceResolverConfig::default()。
    "config": {}
  }
}
```

说明:

- 该示例覆盖当前 7 个 P0 active 配置项。

- 注释只用于文档说明;实际 JSON 配置文件不得包含注释。
- 本示例不包含 `runtime_profile`、publisher mode、toolchain runner mode、secret provider、config center 或 admin override。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“敏感配置表”“禁止输出规则”“profile 敏感配置处理表”和“对详细设计的影响判定”小节，了解密钥边界如何收敛。

本轮 P0 正式配置项没有 `secret` 级配置。`contract_source.root`、`release_snapshot.root`、`projection_index.root`、`audit.root`、`outbox.root`、`idempotency.root` 和 `reference_resolver.config` 均按 `internal` 级配置处理,可以出现在内部配置文件中,但不得对外公开。

### 8.1 敏感配置表

| 配置项 | 敏感级别 | 存储方式 | 是否可明文 | 轮换方式 | 审计要求 |
|---|---|---|---|---|---|
| 各功能模块 root 配置 | internal | 普通内部配置 | 可明文写内部配置,不对外公开 | 变更后重启 CLI / job | 普通配置变更审计 |
| `reference_resolver.config` | internal | 普通内部配置 | 可明文写内部配置,不得包含 raw credential | 变更后重启 CLI / job | 普通配置变更审计 |
| future `*_credential_ref` | sensitive | secret ref / credential ref | 不可写 raw secret | 运维轮换 ref 后重启 | 审计 ref 变化,不得记录 secret |
| raw password / private key / raw token / raw credential | secret | 不允许进入 L0-core 普通配置 | 否 | 外部密钥系统处理 | 不得进入本仓审计正文 |

### 8.2 禁止输出规则

| 输出位置 | 禁止内容 | 允许内容 |
|---|---|---|
| 日志 / 错误返回 | raw secret、token、private key、credential value | redacted ref、dependency name、error code、trace_id |
| 审计正文 | raw secret、token、credential、外部正文全文 | ref id、actor_ref、trace_id、changed_field、reason |
| 指标 label | secret ref 全文、credential value、敏感路径 | dependency kind、result、error class |
| 测试报告 / outbox event | secret、credential、外部正文 | redacted reference、fingerprint、state change |

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_load_validate_apply.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置加载流程图”“配置加载校验表”“cross-field validate 清单”和“对详细设计的影响判定”小节，了解加载机制如何收敛。

P0 配置在 CLI / job 启动时加载。配置来源按 `defaults < file < env < CLI flags` 合并后,必须完成 parse、type validate、cross-field validate,再装配为 `CoreRuntimeConfig`,并交给 runtime builder。

#### 配置加载流程图: L0-core 配置加载与校验

```text
[source merge]
  -> [parse external keys]
  -> [type validate]
  -> [cross-field validate]
  -> [assemble CoreRuntimeConfig]
  -> [build cli/job runtime]
```

关键说明:

- 本图不表达热更新或在线配置中心。
- 高优先级配置非法时 fail fast,不得回退低优先级配置。
- application service 和 domain object 不直接读取配置源。

### 9.1 cross-field validate 清单

| 校验项 | 规则 | 失败处理 |
|---|---|---|
| source / snapshot 隔离 | `contract_source.root` 不得等于 `release_snapshot.root` | fail fast |
| state root 隔离 | `audit.root`、`outbox.root`、`idempotency.root` 不得两两相同 | fail fast |
| projection 隔离 | `projection_index.root` 不得与 source / snapshot / audit / outbox / idempotency root 混用 | fail fast |
| profile 允许范围 | local / CI root 必须落在允许 workspace / temp / CI artifact 范围 | fail fast |
| secret 边界 | 普通配置源不得包含 raw secret | fail fast |
| resolver 安全 | 不得配置为引用失败默认放行或吸收外部正文 | fail fast |
| 禁止配置化项 | 出现绕过 gate / audit / fingerprint / idempotency 的开关 | fail fast + 设计变更 |

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置变更表”“风险分级表”“审计记录规则”“回滚规则”和“对详细设计的影响判定”小节，了解变更治理如何收敛。

P0 配置变更不是在线管理操作。code defaults 通过代码变更生效;project config file 通过版本化文件变更生效;environment variables 和 CLI flags 分别由 CI / runtime environment 和命令执行上下文提供。所有正式配置变更都在下一次 CLI / job 启动时生效。

#### 变更审计链图: L0-core 配置变更、审计与回滚

```text
[propose config change]
        |
        v
[classify source and risk]
        |
        +--> [review if required]
        |
        v
[update config source]
        |
        v
[next CLI / job start]
        |
        v
[load and validate config]
        |
        +--> [success: record effective summary]
        |
        +--> [failure: restore previous source and rerun]
```

关键说明:

- 本图不表达在线配置中心或热更新。
- 回滚通过恢复上一版配置来源并重跑实现。
- 审计只能记录脱敏摘要、fingerprint、来源和校验结果。

### 10.1 高风险变更

| 变更 | 要求 |
|---|---|
| truth source、release snapshot、audit、outbox、idempotency、reference resolver | 必须 review、说明影响、给出回滚方式和验证记录 |
| future sensitive ref | 必须安全或运维评审,不得记录 raw secret |
| local-dev 临时 CLI flags | 可轻量处理,但不得进入正式配置 |

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_modes.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“失效模式表”“处理策略定义表”“漂移与过期处理表”和“对详细设计的影响判定”小节，了解失败策略如何收敛。

P0 配置失效优先采用 fail fast 或 fail closed。配置 parse、type validate、cross-field validate、root path 校验、raw secret 检查和禁止配置化项检查失败时,必须在 runtime builder 前阻断。

### 11.1 失效模式表

| 失效模式 | 系统行为 | 测试切口 |
|---|---|---|
| 显式 config file 缺失、不可读或格式错误 | fail fast | missing / malformed config test |
| env / CLI flag 值为空或类型错误 | fail fast,不回退低优先级 | invalid env / flag test |
| root path 非法、权限不足或混用 | fail fast | path / cross-field test |
| reference resolver config 非法 | fail fast | invalid resolver config test |
| reference / gate / blob 运行时读取失败 | fail closed | external unavailable test |
| raw secret 进入普通来源 | fail fast | raw secret rejection test |
| config center 出现在 P0 配置 | fail fast 或未知字段处理 | unsupported config center test |
| outbox publish 失败 | 保留 pending / mark failed | outbox failure test |
| projection rebuild 失败 | 标记 stale / rebuilding | projection stale test |
| audit append 失败 | 不得静默成功;command / job 失败或事务回滚 | audit append failure test |

### 11.2 不采用的策略

| 策略 | 当前结论 |
|---|---|
| last-known-good | P0 不实现 |
| hot reload | P0 不支持 |
| silent fallback | 高风险配置禁止 |
| degraded | 仅限 projection stale / rebuild 等派生视图类能力 |

## 13. 配置迁移、废弃与演进

> 校准来源：
> - `design-calibration/04_config_step_13_migration_deprecation_evolution.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“当前配置迁移与废弃表”“配置状态定义表”“新配置引入门禁表”“候选配置演进表”和“对详细设计的影响判定”小节，了解配置演进规则如何收敛。

本轮是 L0-core 首版正式配置设计,当前不存在已发布旧配置需要迁移。7 个 P0 配置项作为首版 `active` 配置项进入正式配置设计。

### 13.1 配置状态

| 状态 | 含义 | 允许行为 |
|---|---|---|
| candidate | 候选配置,尚未进入正式 P0 配置项 | 可讨论,不得在正式配置文件中要求使用 |
| active | 当前正式支持配置项 | 可在 file / env / CLI flags 中使用,必须测试和验收 |
| deprecated | 已废弃但仍在兼容窗口内 | 可被读取或迁移,必须提示并给出替代项 |
| removed | 已移除配置项 | 不得继续接受;出现时 fail fast 或未知配置处理 |
| rejected | 明确不允许配置化 | 出现时 fail fast,进入设计变更流程 |

配置新增、重命名、废弃或移除时,必须先判断是否影响代码契约。如果会新增或改变 `CoreRuntimeConfig` 字段、runtime builder 参数、adapter constructor 参数、trait、error enum、DTO、job receipt 或事件字段,必须先回写 `03-详细设计.md`。

`runtime_profile`、publisher mode、toolchain runner mode、gate / blob adapter mode、secret provider / KMS / Vault config、config center / admin override 仍不是本轮 active 配置项。

## 14. 风险与待确认事项

> 校准来源：

> 延伸阅读：
> - 建议继续阅读上述中间产物的“风险表”“待确认事项方案表”“当前生效详细设计回写清单”和“未来触发型回写清单”小节，了解风险和定稿门禁如何收敛。

### 14.1 风险表

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| candidate 配置被误写成 active | 实施者可能新增 03 未定义字段或 adapter 参数 | §7 / §13 明确 candidate 不是 active |

| `07/09` 尚不存在 | 实施和真实运维细节无人承接 | 后续由 07/09 承接 |
| `config fingerprint` 被误实现为字段 / API | 改变 03 代码契约 | 当前只作为证据摘要概念 |
| raw secret 泄露 | 破坏安全边界 | §8 / §11 / §12 写为强门禁 |
| silent fallback | 错误配置被掩盖 | §5 / §9 / §11 明确 fail fast |
| 禁止配置化项被做成开关 | 绕过架构红线 | §4 / §11 明确拒绝配置 |

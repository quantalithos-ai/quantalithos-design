### 3. SOP 问题回答

1. 本次需求结束后，应成立哪些状态、边界或能力？

   回答：本次需求结束后，应成立四类结果：`L0-core` 的跨仓契约来源地位被正式收束；共享契约范围被限制在全仓共同引用的契约基线内；与 `L0-bus`、`L0-sdk`、L1 六域和 `L4-observability` 的边界稳定；后续架构、概要、详细、测试和验收文档能够围绕同一需求基线展开。

2. 这些目标如何被验证？

   回答：验证方式不应写成具体 CI 或实现命令，而应检查后续章节是否能追溯到这些目标：边界章节不再串入相邻仓职责，核心能力闭环能覆盖契约定义到下游消费的最小闭环，功能需求能映射到跨仓契约范围，非目标能阻止 bus / sdk / L1 业务实现进入本仓。

3. 哪些事项虽然相关，但明确不纳入当前范围？

   回答：事件投递实现、SDK 高层客户端封装、L1 业务域实现、观测采集与存储、归档存储、运行时调度、登录认证、权限裁决和具体业务语义都不纳入 `L0-core` 需求范围。

4. 哪些事情必须交给相邻仓或后续阶段处理？

   回答：事件投递交给 `L0-bus`；高层客户端与开发者体验交给 `L0-sdk`；六域业务语义和聚合规则交给 L1 六域服务；trace 采集、审计存储和查询交给 `L4-observability`；归档保留和恢复交给 `L4-archive`；运行时执行、工具调用和成员调度交给 L2 运行层。

### 4. 当前文档问题诊断

| 位置 | 当前问题 | 影响 |
|---|---|---|
| §3.1 目标表 | `proto 覆盖六域全部 service`、`CloudEvent 包络覆盖全部事件`、`三语言 binding 自动生成` 等目标偏功能或交付项 | 目标章节过早进入能力清单，后续功能需求和验收标准边界不清 |
| §3.1 目标表 | `buf generate`、`buf breaking`、CI 自动 bump 等验证方式偏实现 | 需求阶段不应以具体工具链作为目标验证方式 |
| §3.1 目标表 | `≥90% 事件可装入`、`3 个样本仓接入测试` 等指标缺少上游确认 | 容易形成不稳定验收口径 |
| §3.2 非目标表 | 非目标已经列出相邻仓，但表达中混入“proto 生成期保障 + 订阅方校验”等方案解释 | 非目标应只做范围排除，不提前设计解决方式 |
| §3 整体 | 目标与非目标没有直接承接 Step 2 / Step 3 的边界和问题 | 无法作为后续用户、依赖、闭环、功能和验收的稳定前置 |

### 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 目标粒度 | 按 proto、CloudEvent、binding、CI、trace 等能力项列目标 | 按需求完成后应成立的状态、边界和能力范围列目标 | 对齐需求书写规范 4.4 |
| 验证方式 | 使用工具命令、覆盖率比例、样本接入等实现或验收细节 | 使用后续章节可追溯、边界不串线、闭环可展开等文档级验证 | 避免在目标层提前写测试方案或实现方案 |
| 非目标表达 | 带有归属和部分方案说明 | 只写明确不纳入 `L0-core` 的事项及原因 | 非目标的作用是范围收束 |
| binding 口径 | 把三语言 binding 自动生成写成核心目标 | 改为“契约可作为下游 binding 的生成来源”，高层 SDK 封装不属于本仓 | 区分 core 契约来源与 sdk 客户端封装 |
| trace 口径 | 写成所有事件 / RPC 必带 traceparent 的目标 | 改为“追踪上下文契约纳入共享契约范围”，采集存储不属于本仓 | 区分契约字段和观测系统 |

### 7. 结构化中间产物

#### 7.1 目标表

| 目标 | 说明 | 验证方式 |
|---|---|---|
| 建立 `L0-core` 的跨仓契约需求基线 | 明确本仓承载的是所有下游仓共同引用的契约来源，而不是事件投递、SDK 封装或业务实现 | 后续章节均围绕“共享契约来源仓”展开，不再使用 26 仓、下游 25 仓或纯技术设施等旧口径 |
| 收束共享契约能力范围 | 将需求范围限制在跨仓共同引用的基础契约、六域服务契约、事件契约、追踪上下文契约、错误契约和版本兼容契约 | Step 7 核心能力闭环与 Step 9 功能需求能映射到这些契约范围，且不扩展到相邻仓运行职责 |
| 稳定相邻仓边界 | 明确 `L0-core` 与 `L0-bus`、`L0-sdk`、L1 六域、`L4-observability`、`L4-archive`、L2 运行层之间的职责边界 | 后续非目标、使用方与依赖、接口与依赖章节不把相邻仓职责写入 `L0-core` |
| 支撑后续设计文档可追溯 | 为架构、概要、详细、测试和验收文档提供统一需求输入 | 后续文档能从目标、闭环、功能需求和验收标准追溯回本需求文档 |

#### 7.2 非目标表

| 非目标 | 不做原因 |
|---|---|
| 事件总线投递实现 | 属于 `L0-bus`，`L0-core` 只定义事件契约，不负责 publish / subscribe / ack / dead-letter 等运行能力 |
| SDK 高层客户端封装 | 属于 `L0-sdk`，`L0-core` 只提供可派生的契约来源，不负责重试、配置、认证封装或开发者体验 |
| L1 六域业务实现 | 属于各 L1 领域服务，`L0-core` 不实现身份、对话、工作、过程、治理或制品的业务语义 |
| 观测采集、审计存储与追踪查询 | 属于 `L4-observability`，`L0-core` 只约束追踪上下文契约，不保存观测数据 |
| 归档存储与恢复流程 | 属于 `L4-archive`，`L0-core` 不承载归档包、冷热分层或恢复流程 |
| 成员运行时调度与工具调用 | 属于 L2 运行层，`L0-core` 不负责容器、工具、执行循环或调度策略 |
| 登录认证与权限裁决 | 属于安全入口、治理或授权能力，`L0-core` 不做身份校验或权限判定 |

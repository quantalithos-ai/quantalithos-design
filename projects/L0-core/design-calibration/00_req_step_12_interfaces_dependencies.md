### 3. SOP 问题回答

1. 本仓对外提供哪些能力级接口？

   回答：`L0-core` 对外提供共享契约范围收束、跨仓契约语义读取与引用、契约演进兼容处置、契约变化可消费输出、契约检查与派生辅助、契约追溯查看、契约接入说明与示例等能力级接口面。

2. 本仓消费哪些能力级输入？

   回答：`L0-core` 当前不消费其他内部仓的运行能力作为闭环前置。它消费的是候选契约需求、上游标准 / 架构 / ADR 等定义来源引用，以及高影响契约变化所需的正式评审或治理结论。

3. 哪些是同步能力边界，哪些是异步能力边界？

   回答：共享契约范围收束、语义读取与引用、契约演进兼容处置、追溯查看、接入说明与示例属于同步能力边界；契约检查与派生辅助属于后台任务能力边界；契约变化可消费输出属于异步输出能力边界，但不代表 `L0-core` 承担 `L0-bus` 的事件投递、确认、重试或死信职责。

4. 哪些依赖是输入型，哪些结果是输出型？

   回答：候选契约需求、标准 / 架构 / ADR 引用和正式评审 / 治理结论是输入型依赖；共享契约语义、兼容性状态、追溯依据、派生快照和契约变化可感知结果是输出型结果。

5. 哪些能力边界属于当前阶段核心闭环，哪些只是外围增强？

   回答：共享契约范围收束、跨仓契约语义读取与引用、契约演进兼容处置、契约变化可消费输出属于核心闭环能力。契约检查与派生辅助、契约追溯查看、契约接入说明与示例属于外围增强能力。

### 4. 当前文档问题诊断

| 位置 | 当前问题 | 影响 |
|---|---|---|
| §10.1 外部系统依赖列表 | 写 buf CLI、buf registry、crates.io、PyPI、npm、GitHub Actions 及 SLA / 降级 | 这是工具链、发布平台和非功能 / 实施内容，不是需求层能力接口与依赖 |
| §10.2 上游接口约定 | 将 CloudEvents、W3C、domain README、event-catalog 写成上游接口 | 标准 / 草案 / 文档来源与能力级依赖混在一起 |
| §10.2 下游接口约定 | 逐层写下游消费的具体 proto、binding、event type | 粒度偏协议和实现，容易重抄 Step 6 的仓际依赖 |
| 全文 | 没有使用查询接口、变更接口、事件输出、事件输入、后台任务接口等正式接口类型 | 与新版需求规范 4.12 不一致 |
| 全文 | 没有区分核心闭环能力边界与外围增强能力边界 | 后续非功能、验收和详细设计难以判断优先级 |

### 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 接口粒度 | 外部系统、proto、binding、event type、registry | 能力级接口面 | 需求层只定义能力边界，不写协议和实现 |
| 依赖粒度 | 工具链 / 发布平台 SLA | 定义来源依赖、治理结论依赖、下游消费依赖 | 对齐需求规范 4.12 的依赖类型 |
| 上游来源 | CloudEvents、W3C、domain README、event catalog 混写为接口 | 作为定义来源引用或标准约束，不写成运行系统依赖 | 避免和 Step 6、Step 11 串线 |
| 下游关系 | 按仓列表写消费什么 | 只写能力输出面和下游消费依赖 | 避免重抄仓际依赖表 |
| 异步边界 | 未说明 | 明确契约变化可消费输出是异步输出面，但不承担 bus 投递职责 | 同时支持下游感知与边界保护 |

### 3. SOP 问题回答

1. 哪些条件满足后，核心能力闭环算成立？

   回答：当跨仓契约范围能够被统一收束、契约语义能够被稳定表达、契约演进能够保持兼容与可追溯、下游仓能够基于同一契约稳定消费和派生时，核心能力闭环才算成立。

2. 哪些功能能力满足后，本次需求算完成？

   回答：共享契约范围管理、跨仓契约语义表达、契约演进兼容与追溯、下游消费与派生基础四个核心能力必须成立；契约检查与派生辅助、契约追溯查看、契约接入说明与示例应作为外围增强具备清晰入口，但不应替代核心闭环验收。

3. 哪些规则 / 边界被满足后，才算没有串线？

   回答：`L0-core` 必须保持跨仓共享契约正式来源职责，不承担 `L0-bus` 投递、`L0-sdk` 高层客户端封装、L1 业务实现、L4 观测 / 归档、L2 运行层、认证授权等边界外能力；共享契约变化必须显式发生并保留追溯依据。

4. 哪些数据边界被满足后，才算数据归属正确？

   回答：本仓只拥有契约真相；派生产物只能是快照；标准、评审、ADR 和下游消费关系只能是引用；业务数据、事件实例 payload、观测日志 / trace 正文、归档包正文、运行时记录和凭据不得进入本仓正文范围。

5. 哪些非功能要求被满足后，才算质量达标？

   回答：核心契约读取 / 追溯 / 检查 / 派生不成为主链阻塞点；外围能力或工具链异常不破坏核心契约真相；关键契约变化可追溯；共享契约语义保持一致；关键状态、变化和异常可被观察；本仓不越权保存正文或承担边界外职责。

6. 哪些失败情形属于一票否决？

   回答：核心闭环不成立、仓边界被打穿、业务 / 运行 / 观测 / 归档正文进入本仓、契约演进不可追溯或产生冲突真相、下游无法基于同一契约稳定消费和派生，都应作为一票否决。

#### 7.2 一票否决项

- `L0-core` 不能作为跨仓共享契约正式来源成立。
- 跨仓契约范围、语义、演进或下游消费任一核心闭环节点缺失。
- `L0-bus`、`L0-sdk`、L1、L2、L4 等相邻仓职责被写入 `L0-core` 核心职责。
- 业务数据、事件实例 payload、观测日志 / trace 正文、归档包正文、运行时记录或凭据进入本仓正文范围。
- 契约变化不可追溯，或同一共享契约在不同下游仓形成冲突真相。
- 验收标准以工具链、CI、registry、测试脚本替代需求层能力和边界判断。

### 3. SOP 问题回答

1. 哪些数据由本仓拥有真相？

   回答：`L0-core` 拥有共享契约定义、共享契约范围、契约版本 / 兼容性状态、契约演进记录和契约正式发布基线的正式真相边界。其中发布基线是被确认的契约状态，不等同于 SDK 包或注册表产物。

2. 哪些数据只是快照、投影或引用？

   回答：契约发布快照、下游消费派生产物、契约检查摘要、兼容性报告摘要属于快照 / 投影数据；上游标准引用、设计态草案引用、正式评审 / ADR 引用、下游仓消费关系引用属于引用关系数据。

3. 哪些关系必须强一致？

   回答：共享契约定义、范围、版本 / 兼容性状态和演进记录之间必须在正式变更边界内强一致；同一个正式发布基线内的契约真相与发布快照必须通过发布门禁保持一致。

4. 哪些关系可以最终一致？

   回答：真相到下游消费派生产物、检查摘要、兼容性报告摘要以及消费关系视图可以最终一致。它们延迟更新不改变契约真相，但必须显式表现为旧快照、待刷新或失败状态。

5. 失败时靠什么口径约束、补偿或挂起？

   回答：强一致关系失败时必须阻断正式收口，不能形成部分成功的契约真相；快照 / 投影关系失败时保留旧快照或挂起发布；引用关系失效时保持引用失效态，不伪造正文；禁止正文关系出现时必须拒绝进入本仓。

6. 哪些数据边界如果不写清，后续最容易串仓？

   回答：最容易串仓的是把派生产物当真相、把外部标准或 ADR 正文吸收到本仓、把下游实现状态当本仓状态、把事件实例 payload 或 trace 正文当契约样本保存、把 SDK 包发布状态当契约真相。

### 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 数据主语 | proto 文件、binding artifact、event catalog | 契约真相、快照 / 投影、引用关系、明确不拥有正文 | 对齐架构数据所有权规范 |
| 真相边界 | 实现文件是真相 | 契约定义、范围、版本 / 兼容性状态、演进记录和正式发布基线是真相边界 | 不绑定具体文件形态 |
| 快照口径 | generated binding 容易被当成正式数据 | 发布快照、派生产物、检查摘要和报告摘要均为快照 / 投影 | 派生不等于真相 |
| 一致性策略 | CI 检查和发版补偿 | 强一致、发布门禁一致、最终一致、引用有效性一致和边界约束一致 | 用架构口径约束后续设计 |
| 失败处理 | 重试发版或回滚 release | 阻断收口、保留旧快照、标记引用失效、拒绝正文进入 | 更符合数据边界保护 |

### 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A：继续使用 proto 文件 / binding / registry 的数据矩阵 | 贴近旧实现设想 | 会把文件、工具链和发布渠道误写成真相来源 | 不采用 |
| 方案 B：按真相 / 快照 / 引用 / 不拥有正文划分，并补一致性策略 | 边界清晰，能支撑后续详细设计 | 抽象度高，需要后续概要设计再落到具体结构 | 采用 |
| 方案 C：只写“本仓不保存业务数据” | 简短 | 不能说明本仓拥有何种契约真相，也不能约束快照和引用 | 不采用 |

#### 7.2 一致性策略表

| 数据关系 / 场景 | 关联数据类型 | 一致性口径 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| 契约真相内部变更 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 阻断正式收口，不形成部分成功状态。 | 契约定义、范围、版本和演进记录必须同时成立。 |
| 契约真相到正式发布基线 | 正式真相数据 ↔ 正式真相数据 | 发布门禁一致 | 发布基线不得形成，保留上一正式基线。 | 正式基线必须代表已经收口的契约状态。 |
| 契约真相到发布快照 | 正式真相数据 ↔ 快照 / 投影数据 | 发布边界一致 | 挂起快照发布，保留旧快照或标记失败。 | 快照可以落后，但不能伪装成新基线。 |
| 契约真相到派生产物 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 | 保留旧派生产物或标记待刷新。 | 派生产物延迟不改变契约真相。 |
| 契约检查与兼容性报告 | 正式真相数据 ↔ 快照 / 投影数据 | 审查一致 | 检查失败时阻断收口或标记报告失败。 | 检查和报告用于审查，不自动成为真相。 |
| 契约真相到外部引用 | 正式真相数据 ↔ 引用关系数据 | 引用有效性一致 | 标记引用失效，不伪造正文补齐。 | 引用只要求关系有效，不表示拥有正文。 |
| 本仓与明确不拥有正文的边界 | 引用关系数据 ↔ 明确不拥有的正文 / 真相 | 边界约束一致 | 拒绝正文进入本仓，必要时挂起或显式失败。 | 禁止正文进入是数据边界红线。 |
| 下游消费反馈到契约变更 | 引用关系数据 ↔ 正式真相数据 | 接缝审查一致 | 未经接缝审查不得改写契约真相。 | 下游反馈是输入，不是契约真相来源。 |

### 3. SOP 问题回答

1. 哪些交互适合同步能力边界？

   回答：契约范围变更输入、契约演进兼容处置、契约语义读取 / 引用、契约追溯查看和接入说明获取适合同步请求 / 响应类交互。它们需要在一个正式边界上即时给出是否成立、是否可读、是否可引用或是否失败的明确结果。

2. 哪些交互适合异步事件？

   回答：契约变化、正式发布基线成立、兼容性状态变化和追溯结果可消费输出适合异步事件 / 回调类交互。这里表达的是“事实成立后对外可感知”，不表示 `L0-core` 承担 `L0-bus` 的事件投递、确认、重试或死信职责。

3. 哪些交互适合后台任务或补偿路径？

   回答：契约校验、兼容性辅助判断、派生快照生成、检查报告摘要生成和发布快照刷新适合后台任务 / 延后承接类交互。这些处理不应伪装成同步边界内全部完成，只需在正式入口上形成可挂起、可失败、可追溯的承接口径。

4. 哪些交互必须经过总线或正式边界，不能直接穿透？

   回答：下游消费反馈、标准 / 草案输入、正式评审 / ADR 结论、契约变化对外传播都必须经过正式边界。下游反馈不能直接改写契约真相；外部标准和草案不能直接进入核心语义；对外传播不能绕过发布基线与发布快照边界。

5. 关键依赖失效时，本仓如何降级或挂起？

   回答：同步边界失败时明确失败，不伪装为已完成；异步传播失败时保持未传播或待消费状态，不反向撤销契约真相；后台处理失败时挂起对应快照、报告或派生结果，保留上一正式基线；引用失效时标记引用失效，不补造正文。

6. 哪些通信口径若不先写清，后续最容易误入协议细节？

   回答：最容易误入协议细节的是把同步能力边界写成 HTTP API 清单，把异步输出面写成事件目录或 bus 实现，把后台任务写成 CI 脚本步骤，把下游消费写成 SDK 发布流程，把标准 / 草案输入写成运行时外部系统调用。

### 4. 当前文档问题诊断

| 位置 | 当前问题 | 影响 |
|---|---|---|
| §9 / §10 旧交互表 | 旧版容易直接写 proto、事件名、binding、registry 或 CI 任务 | 架构层会滑入接口目录、事件目录或实施细节 |
| 系统上下文相关章节 | 旧版把标准、工具链、下游仓画成编译期依赖链 | 读者容易把通信方式理解成“工具链如何调用” |
| 容器 / 部署相关章节 | 旧版缺少无在线运行时条件下的交互方式判断 | 容易误设计在线 API 服务、消息消费者或常驻 worker |
| 数据所有权相关章节 | 旧版没有把真相、快照、引用的失败边界对应到交互口径 | 后续可能出现异步失败反向改写真相、后台失败伪装发布成功等问题 |
| 全文 | 没有明确 `L0-core` 不承担 `L0-bus` 投递职责 | 容易把“契约变化可感知”误写成事件总线实现 |

### 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 交互主语 | proto / binding / CI / registry 的处理链 | 契约变更、契约读取、事实传播、后台校验与派生 | 对齐架构层交互场景 |
| 同步边界 | 容易写成具体 API 或工具命令 | 只表达需要即时收口的正式边界 | 避免提前进入接口设计 |
| 异步边界 | 容易写成事件目录或 bus 投递机制 | 只表达契约事实成立后的可感知传播 | 避免侵入 `L0-bus` 职责 |
| 后台边界 | 容易写成 CI 脚本或生成步骤 | 只表达不适合同步即时完成的延后承接 | 避免把实施流程写成架构交互 |
| 失败处理 | 发布失败重试或 registry 回滚 | 明确失败、保持未传播、挂起快照、标记引用失效 | 与 Step 8 一致性口径对齐 |

### 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A：按 API / 事件 / 后台任务清单展开 | 贴近实现直觉 | 会提前进入概要 / 详细设计，且容易把 `L0-core` 写成在线服务 | 不采用 |
| 方案 B：按关键交互场景判断同步 / 异步 / 后台承接 | 符合架构规范，能保护 `L0-core` 与 `L0-bus` / `L0-sdk` 边界 | 需要后续概要设计再落到具体接口轮廓 | 采用 |
| 方案 C：只写“无运行时通信”并跳过本章 | 简短 | 无法解释契约变更、消费、传播、校验和失败挂起如何在边界上成立 | 不采用 |

### 7. 结构化中间产物

#### 7.1 关键交互场景表

| 交互场景 | 交互边界 | 交互目的 | 边界说明 |
|---|---|---|---|
| 契约范围与演进变更输入 | 外部接缝角色 -> 契约承接 / 编排角色 | 即时判断候选变更能否进入正式审查和收口边界 | 这是变更进入契约真相的入口，不是下游直接改写核心语义。 |
| 契约语义读取与引用 | 下游契约消费边界 -> 契约发布快照 / 稳定引用入口 | 让下游能读取或引用当前稳定契约基线 | 这是消费边界，不表示下游拥有或改写真相。 |
| 契约变化事实传播 | 契约发布基线 / 兼容性状态 -> 下游契约消费边界 | 让下游感知已经成立的契约变化和兼容性状态 | 这是事实传播，不是 `L0-core` 承担事件总线投递实现。 |
| 契约校验与派生处理 | 契约源码承载 -> 契约校验与派生处理单元 | 延后完成校验、兼容性辅助判断、派生快照和报告摘要 | 这些处理不应被硬塞进同步入口内伪装成立即完成。 |
| 发布快照刷新与消费 | 契约校验与派生处理单元 -> 契约发布快照承载 -> 下游消费边界 | 形成可被下游消费的版本化契约快照 | 快照是消费承载，不是 SDK 包发布中心，也不能反向拥有契约真相。 |
| 标准 / 草案 / 评审结论接入 | 外部输入面 -> 外部接缝角色 | 将标准、草案和评审结论转化为可审查的契约输入 | 外部正文和草案不能直接进入核心契约语义。 |
| 引用失效与待确认暴露 | 引用关系数据 -> 契约承接 / 编排角色 / 下游消费边界 | 显式暴露引用失效、待确认或不可收口状态 | 引用失效时不能伪造正文或继续表现为已确认基线。 |

#### 7.2 通信方式判断表

| 交互场景 | 推荐通信方式 | 不宜采用的方式 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| 契约范围与演进变更输入 | 同步请求 / 响应类交互 | 不宜以异步传播替代正式入口判断 | 明确失败或进入待审查状态，不伪装为已改写真相 | 该场景需要即时判断候选变更是否能进入正式边界。 |
| 契约语义读取与引用 | 同步请求 / 响应类交互 | 不宜依赖异步回调作为主路径 | 明确不可读、旧基线或引用失效状态 | 下游读取需要稳定、明确、可解释的当前视图。 |
| 契约变化事实传播 | 异步事件 / 回调类交互 | 不宜伪装成同步全下游闭环 | 保持未传播 / 待消费状态，不反向撤销契约真相 | 契约事实成立后可以被感知，但不要求所有下游同步完成。 |
| 契约校验与派生处理 | 后台任务 / 延后承接类交互 | 不宜硬写成同步入口内完成 | 挂起派生、保留旧快照或标记处理失败 | 校验与派生可能耗时或依赖工具链，不应阻塞入口完成全部工作。 |
| 发布快照刷新与消费 | 后台任务 / 延后承接类交互 | 不宜把快照刷新写成下游直接改写真相 | 挂起新快照，保留上一正式可消费基线 | 快照可延迟，但不能伪装成已发布的新基线。 |
| 标准 / 草案 / 评审结论接入 | 同步请求 / 响应类交互 | 不宜作为异步事实自动改写核心 | 标记输入不足、待确认或拒绝进入 | 外部输入需要先被正式接缝判断，不得直达核心。 |
| 引用失效与待确认暴露 | 异步事件 / 回调类交互 | 不宜通过同步读取时临时补造正文 | 暴露引用失效或待确认，不伪造正文 | 引用状态变化可以传播给消费方，但不能改变正文归属。 |

```text
| 外部输入 / 下游  | --------------->  | 契约承接 / 编排角色  |

+------------------+                   +----------+-----------+

                                                   v
                                      +------------------------+

                                                 |
                                                 | publish fact
                                                 v
+------------------+       async       +----------------------+
| 下游消费边界     | <---------------  | 发布基线 / 快照 / 状态 |
| L0 / L1~L6       |                   | 可感知输出面           |
+------------------+                   +----------------------+
```

图外说明：
- 图中 `sync` 只表示需要即时判断或读取的边界，不表示具体协议。
- 图中 `async` 只表示事实成立后的可感知传播，不表示 `L0-core` 承担事件总线投递实现。
- 后台延后承接用于校验、派生和快照刷新，不得伪装成同步入口内已全部完成。
- 下游消费边界只消费发布基线或快照，不能反向改写契约真相。

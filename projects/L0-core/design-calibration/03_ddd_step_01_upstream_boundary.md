### 3.1 当前详细设计直接承接概要设计中的哪些结论?

回答:

当前详细设计直接承接 `02-概要设计.md` 中已经收稳的下列结论。

| 概要设计章节 | 已收稳结论 | 详细设计继续展开 |
|---|---|---|
| §4 代码主体框架总览 | 外部接缝、契约编排、共享契约核心、领域契约包、索引 / 投影 / 引用、后台校验、技术承载等代码主体 | crate / module / file tree、实现单元、模块边界 |
| §5 主要组成部分、职责与边界 | 6 个业务主要组成部分 + 1 个支撑主体集合 | 每个模块的对象、trait、adapter、错误和测试切口 |

| §7 API / 接口骨架 | Command / Query / Outbound Event / Operations Job 四类接口骨架 | 请求 / 响应 / event / job schema、handler、service、错误映射、幂等和审计要求 |

| §9 状态定义与状态流转 | 多对象族状态模型、允许迁移和禁止迁移 | 状态转换矩阵、非法转换错误、状态守卫实现 |
| §10 异常与边界场景 | 幂等冲突、非法迁移、兼容性不通过、快照派生失败、读面 stale、事实发布失败、引用失效 | 错误模型、恢复口径、重试和补偿边界 |

### 3.4 哪些内容仍停留在概要设计轮廓,进入详细设计前必须补清?

回答:

这些内容不是概要设计缺口,而是详细设计必须继续展开的实现契约。

| 仍是轮廓的内容 | 对详细设计的要求 |
|---|---|
| `CommandMetadata` / `QueryMetadata` | 决定是否作为正式 value object,并定义字段、约束和使用位置 |
| `ContractChangeReceipt` / `ContractBaselineReceipt` / `ContractLifecycleReceipt` | 决定是否抽统一 receipt 基类或 trait,并定义响应结构 |
| `ContractPackageView` | 决定是否按消费域拆分 view,但不得改动六个 `ContractPackage` 对象族 |
| `ContractGuideSampleView` | 决定静态文档视图还是派生查询视图,不得升级成 SDK 本体 |
| Outbound Event | 明确 event schema、版本策略、发布方和 `L0-bus` 边界 |
| `stale / rebuilding` | 定义 query 输出语义、错误映射和测试切口 |
| 快照派生失败 | 定义作业失败事实、重试口径和状态保持规则,不得新增 snapshot failed lifecycle |
| 文件布局 | 决定采用单 crate 模块分层架构还是 workspace 多 crate 架构 |

### 3.5 哪些需求或架构结论会影响详细设计,但不能在详细设计中重新定义?

回答:

| 来源 | 已收稳结论 | 详细设计处理方式 |
|---|---|---|
| 需求文档 §2 | `L0-core` 是跨仓共享契约来源仓 | 只能展开实现契约,不得改成本仓为 bus / sdk / L1 服务 |
| 需求文档 §7 | 核心闭环是范围收束、语义表达、演进追溯、下游消费派生 | 详细设计必须让模块和接口覆盖这条闭环 |
| 需求文档 §11 | 契约真相、快照、引用、禁止正文四类数据归属 | 持久化和对象设计必须守住数据归属 |
| 架构设计 §6 | 共享契约核心、领域契约包、本地索引 / 投影 / 引用 | 模块拆分必须承接这三类内部语义单元 |
| 架构设计 §8 | 依赖方向从入口到应用、领域、端口、适配器 | 详细设计不得让 domain 依赖 infra / bus / db |
| 架构设计 §9 | 真相强一致、派生最终一致、引用有效性一致 | 事务、outbox、projection 和 job 必须按该口径展开 |
| 架构设计 §10 | 同步入口、异步事实传播、后台延后承接 | 详细设计必须区分 Command / Query / Event / Job |
| 概要设计 §10 | 快照失败不回滚 baseline,读面 stale 必须显式可见 | 错误和恢复模型不得改变这些语义 |

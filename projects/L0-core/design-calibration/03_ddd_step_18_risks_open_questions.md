| 配置文件 schema、环境变量名和 CLI flag 细节未定义 | runtime wiring 可实现,但具体配置加载方式可能后续调整 | 只实现 `CoreRuntimeConfig`、默认 root 和 builder 入口;完整配置文档后补 | 配置设计负责人 |

| 文件型 state store 的锁和原子提交实现复杂 | 并发、幂等、outbox 和 projection 可能因文件写入不当出现污染 | Step 11 / 13 已要求 expected version、唯一键、atomic commit 和 idempotency record;实现阶段必须用测试覆盖 | 实施负责人 |

### 5.3 每个待确认事项需要谁确认？

| P1 `InReview -> Draft` 退回草稿协议 | 影响评审驳回流程 | 产品 / 架构负责人 | P0 不暴露 command;状态矩阵保留 P1 约束 |
| P1 snapshot supersede 协议 | 影响快照替代和版本治理 | 产品 / 架构负责人 | P0 只实现 building -> ready / archive 主线 |
| P1 package 写协议 | 影响契约包管理扩展 | 产品 / 架构负责人 | P0 只保留领域对象约束,不实现外部写入口 |
| 观测告警阈值、日志保留周期、SLO / SLA | 影响运维上线策略 | 运维负责人 | 代码只实现 Step 15 埋点切口,不硬编码告警策略 |
| 完整测试覆盖率目标和环境矩阵 | 影响测试方案验收 | 测试负责人 | 实施计划只引用 Step 16 最小测试切口 |
| 正式 `07-实施计划.md` 阶段顺序和提交边界 | 影响另一个 agent 的实际开发顺序 | 实施计划编写者 | Step 17 只提供承接清单,不替代实施计划 |

### 5.4 未确认前实现者应该如何处理？

| 类型 | 未确认前处理方式 |
|---|---|
| 相邻仓能力 | 只实现本仓 port / DTO / outbox 边界,不实现相邻仓 runtime |
| 配置细节 | 实现类型和 builder 入口,具体解析方式通过配置设计或实施计划补充 |
| P1 功能 | 保留对象和状态约束,不暴露 command / job / CLI 入口 |
| 运维细节 | 实现 trace / log / metric / audit 切口,不写阈值和值班流程 |
| 测试细节 | 实现最小测试切口,完整矩阵由测试方案展开 |
| 正式文档未汇总 | 继续执行 Step 19,完成正式 `03-详细设计.md` 后再交付外部 agent |

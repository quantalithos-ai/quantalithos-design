## 3. SOP 问题回答

1. 哪些配置场景进入测试方案?

   回答：测试方案至少需要承接 5 类配置场景。第一类是默认配置启动和 profile 矩阵,验证 `local-dev`、`ci-test`、`release-like`、`operations-replay` 下的 root path 和 resolver config 能被正确加载。第二类是来源优先级,验证 defaults / file / env / CLI flags 的覆盖顺序和同级重复 key fail fast。第三类是类型与交叉字段校验,验证路径非法、root 混用、resolver fail-open、raw secret、禁止配置化项都会阻断。第四类是外部依赖失效,验证 reference / gate / blob fail closed、outbox pending / failed、projection stale / rebuild。第五类是变更与回滚,验证恢复上一版配置来源并重跑能够恢复。

2. 哪些配置门禁进入验收标准?

   回答：验收标准需要把配置设计中的 P0 红线转成可裁决门禁。必须包括: 7 个正式 P0 配置项可追溯到 `CoreRuntimeConfig`;配置来源优先级可验证;高优先级非法值不得 silent fallback;P0 不依赖 config center / KMS / Vault;raw secret 不得进入普通配置、日志、错误、审计和测试报告;禁止配置化项不能绕过 gate / audit / fingerprint / idempotency;配置变更和回滚有可追溯证据。

3. 哪些配置准备进入实施计划?

   回答：实施计划需要承接配置文件 schema、env / CLI flag 映射、默认目录准备、fixture 目录准备、runtime builder 装配顺序、配置校验实现顺序、测试命令和提交边界。实施计划还需要明确编码前阅读 `04-配置设计.md` 的 Step 7 / 9 / 11 回填内容,并在实现阶段把配置加载、校验、runtime build 和负向测试作为可提交增量。

4. 哪些配置部署细节留给部署与运维手册?

   回答：真实环境路径、容器挂载、权限设置、CI secret store、KMS / Vault 绑定、真实 bus / publisher 绑定、备份恢复命令、告警阈值、轮换步骤和事故处置步骤留给部署与运维手册。04 只定义这些内容的边界和不能违反的规则,不写具体命令或平台操作。

5. 下游文档不应重复定义哪些配置契约?

   回答：下游文档不应重新定义 7 个 P0 配置项名称、类型、默认值、来源优先级、敏感级别、加载时机、失败策略、禁止配置化边界和 03 回写门禁。测试方案可以引用这些契约设计用例,验收标准可以引用这些契约定义门禁,实施计划可以引用这些契约安排编码顺序,运维手册可以引用这些契约配置真实环境,但都不能另造一套配置真相。

### 7.2 进入 `05-测试方案.md` 的配置场景

| 测试方向 | 需要覆盖的配置场景 | 证据输入 |
|---|---|---|
| 默认配置与 profile | 默认 root / resolver config、local-dev、ci-test、release-like、operations-replay | 启动日志、测试报告、配置来源摘要 |
| 来源优先级 | defaults / file / env / CLI flags 覆盖顺序、同级重复 key | 自动化测试结果、失败样例 |
| 配置校验 | parse、type validate、cross-field validate、root 隔离、resolver fail-open 拒绝 | 单元 / 集成测试证据 |
| 敏感配置 | raw secret 拒绝、secret ref 脱敏、日志 / 错误 / 审计不泄露 | 负向测试、日志检查 |
| 失效模式 | fail fast、fail closed、pending / failed、stale / rebuild、job failed | 失败注入测试、job receipt |
| 变更回滚 | 恢复上一版配置来源并重跑 | before / after 证据、config fingerprint 摘要 |

### 7.3 进入 `06-验收标准.md` 的配置门禁

| 验收方向 | 通过条件 | 失败条件 |
|---|---|---|
| 配置项完整性 | 7 个 P0 配置项均可追溯到 `CoreRuntimeConfig` | 下游另造配置项或字段漂移 |
| 来源优先级 | 覆盖顺序稳定且测试可证明 | 高优先级非法值 silent fallback |
| 敏感边界 | raw secret 不进入普通来源、日志、错误、审计、测试报告 | 任一输出泄露 raw secret 或 credential |
| 禁止配置化 | gate / audit / fingerprint / idempotency 不能被配置关闭 | 存在绕过开关并可生效 |
| 失效策略 | fail fast / fail closed / pending / stale 行为与 04 一致 | 错误配置继续运行或默认放行 |
| 变更回滚 | 恢复来源并重跑有证据 | 回滚步骤不可追溯或无验证 |

### 7.4 进入 `07-实施计划.md` 的配置实施输入

| 实施输入 | 用途 |
|---|---|
| 配置 schema 与 key 命名 | 指导配置文件、env、CLI flags 的实现 |
| `CoreRuntimeConfig` 映射 | 保证外部配置只装配到 03 已定义字段 |
| 默认目录准备 | 支撑 local-dev / ci-test 可运行 |
| 加载校验链 | 安排 source merge、parse、type validate、cross-field validate 的实现顺序 |
| 失效模式表 | 安排负向测试和提交门禁 |
| 敏感配置边界 | 防止实现阶段把 raw secret 写入普通来源或输出 |
| 回滚原则 | 安排阶段回退点和问题恢复动作 |

## 3. SOP 问题回答

1. 当前测试方案要承接哪些需求、规则和非功能目标?

   回答：必须承接 `00-需求文档.md` 中的 F-001~F-007、BR-001~BR-014、数据归属要求、非功能要求和一票否决项。测试主线应围绕共享契约范围管理、跨仓契约语义表达、契约演进兼容与追溯、下游消费与派生基础、契约检查与派生辅助、契约追溯查看、契约接入说明与示例展开。

2. 哪些概要 / 详细设计章节直接影响测试对象?

   回答：`02-概要设计.md` §4~§10 是测试对象和流程来源;`03-详细设计.md` §4~§15 是直接测试契约来源,其中 §7 定义协议,§8 定义逐接口处理流,§9 定义状态机,§10 定义事务一致性,§11 定义错误恢复,§12 定义幂等并发,§13 定义配置引用,§14 定义观测审计,§15 定义最小测试切口。

3. 哪些验收项需要测试方案提供证据?

   回答：需求文档 §14 的核心能力闭环、功能能力、规则 / 边界、数据归属和非功能验收项都需要测试证据。当前 `06-验收标准.md` 仍是旧 shared primitive admission 口径,不能直接继承;新版 05 需要先产出证据编号和证据类型,后续 06 再据此重写裁决门禁。

4. 哪些内容不应在测试方案中重新定义?

   回答：05 不重新定义需求目标、职责边界、crate 布局、对象字段、函数签名、协议 schema、配置项、状态迁移、错误模型、实施排期、部署命令或验收裁决。发现上游缺口时只能记录风险或待确认事项,不能在测试方案中静默补设计。

5. 当前上游是否存在会阻塞测试设计的缺口?

   回答：新版 `00/01/02/03/04` 足够启动测试方案校准;不阻塞 Step 2~15。当前主要缺口在下游: `06-验收标准.md` 仍是旧口径,需要在 05 完成后重写。另一个实施侧缺口是具体 CI 命令和真实仓路径尚未在 07 中落地,可在 05 中以门禁口径表达,不阻塞测试方案设计。

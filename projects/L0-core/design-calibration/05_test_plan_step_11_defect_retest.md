## 3. SOP 问题回答

1. 哪些缺陷属于 S 级阻断?

   回答：禁止正文入仓、raw secret 泄露、失败伪成功、发布基线不可追溯、引用失败默认放行、P0 主线无法执行、truth + outbox 非原子、audit 静默失败、release gate 失败都属于 S 级阻断。

2. 哪些缺陷可以风险接受?

   回答：P1 nightly 非发布阻断问题、非 P0 文档链接瑕疵、非阻断性能 baseline 波动、尚未启用的 P1 staging-integration 可在记录 owner、期限和影响范围后风险接受。S 级和 P0 主线缺陷不得风险接受。

3. 修复后必须回归哪些用例?

   回答：修复必须至少回归直接失败用例、同一功能主线的相邻用例、相关专项用例和对应自动化 suite。涉及状态机、事务、幂等、配置或审计的修复必须回归对应矩阵。

4. 缺陷关闭需要哪些证据?

   回答：需要缺陷记录、根因说明、修复提交、复验用例清单、自动化报告、相关 evidence id、残余风险结论。S 级缺陷还必须有 release gate 或 main CI 复验通过证据。

5. 是否需要新增自动化防回归?

   回答：P0 缺陷、S 级缺陷、重复出现缺陷、事务 / 幂等 / 安全 / 配置红线缺陷必须新增或补强自动化用例。仅文案类或一次性环境类问题可不新增,但必须说明原因。

## 6. 测试设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 只按严重程度自由判断 | 灵活 | 不同 agent / 开发者口径不一致 | 不采用 |
| B. 所有缺陷都阻断 | 保守 | 会阻塞非 P0 文档瑕疵和 P1 探索问题 | 不采用 |
| C. S/P0 严格阻断,P1 可控风险接受,并绑定复验证据 | 可执行且守住红线 | 需要维护证据链 | 采用 |

## 7. 结构化中间产物

### 7.1 缺陷分级表

| 级别 | 定义 | 示例 | 处理要求 | 是否阻断 |
|---|---|---|---|---|
| S | 一票否决或破坏核心边界 / 安全 / 一致性 / 追溯 | raw secret 泄露、禁止正文入仓、失败伪成功、truth + outbox 半提交、release gate 失败 | 立即修复;必须补自动化;main / release gate 复验 | 是 |
| A | P0 主线或 P0 自动化失败,但未触发 S 级红线 | create / publish / snapshot / query / outbox relay 主线失败,config P0 fail fast 错误 | 当前迭代内修复;回归相关 suite | 是 |
| B | P1 能力、nightly 风险或非发布阻断专项退化 | 大 fixture benchmark 波动、P1 staging smoke 不稳定 | 记录 owner 和修复计划;必要时风险接受 | 视 release 影响 |
| C | 文档、报告、提示或非 P0 可用性瑕疵 | evidence 命名不一致、非阻断报告字段缺失 | 排期修复;不阻断 P0 | 否 |

### 7.2 复验规则表

| 缺陷类型 | 必须回归 | 自动化要求 | 关闭证据 |
|---|---|---|---|
| S 级缺陷 | 直接失败用例 + 同类红线专项 + release gate | 必须新增或补强自动化 | CI / release report + evidence id + root cause |
| A 级缺陷 | 直接失败用例 + 同一主线相邻用例 + 对应 suite | 必须补自动化或说明已有覆盖 | CI report + 修复提交 + 复验记录 |
| B 级缺陷 | 直接失败用例 + 相关 nightly / P1 用例 | 视重复性决定 | nightly report + 风险接受记录 |
| C 级缺陷 | 变更点检查 | 可不新增 | review 记录 |
| 配置缺陷 | `TC-CONFIG-*` + 相关环境矩阵 | P0 必须自动化 | config report + temp fixture 证据 |
| 幂等 / 并发 / 事务缺陷 | `TC-IDEM-*`、`TC-CONC-*`、`TC-TXN-*` | 必须自动化 | failure injection report |
| 审计 / trace 缺陷 | `TC-AUDIT-*`、`EV-TRACE-*` | 必须自动化扫描或断言 | audit / trace evidence |

### 7.3 风险接受规则

| 条件 | 是否可接受 | 要求 |
|---|---|---|
| S 级缺陷 | 否 | 必须修复并复验 |
| P0 主线失败 | 否 | 必须修复并复验 |
| release gate 失败 | 否 | 不得发布 |
| P1 nightly failure | 可条件接受 | 记录 owner、期限、影响范围、后续用例 |
| 性能数值阈值未最终标定 | 可条件接受 | 必须有 baseline 生成计划,不得声称已满足最终阈值 |
| 文档或报告非阻断瑕疵 | 可接受 | 不影响 P0 证据链 |

## 3. SOP 问题回答

1. 本轮验收依据哪些需求和设计?

   回答：本轮验收依据新版 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`、`04-配置设计.md` 和 `05-测试方案.md`。其中 00 决定需求和红线,01 决定架构边界,02 决定功能结构和处理主线,03 决定实现契约,04 决定配置裁决输入,05 决定测试证据和门禁。

2. 哪些测试证据会支撑验收裁决?

   回答：验收裁决应引用 `05-测试方案.md` 中的 TC 用例 ID 和 EV 证据 ID,尤其是 EV-UNIT-001、EV-SVC-001、EV-CONTRACT-001、EV-CONTRACT-002、EV-INT-001、EV-WORKER-001、EV-CONFIG-001、EV-AUDIT-001、EV-TRACE-001、EV-SEC-001、EV-SEC-002、EV-SCOPE-001、EV-E2E-001。06 不重新设计测试用例,只定义这些证据达到什么状态才算通过。

3. 哪些交付版本、环境和数据会成为基线?

   回答：当前仍处于设计校准阶段,尚无代码实现 build、commit、image 或实际 test run。06 可以先定义基线类型和必填字段,但不得使用“最新版本”作为基线。实际送验 commit、run_id、config_profile、test_run_id、CI artifact 路径应在实施和测试执行后填入。

4. 哪些内容属于测试方案或实施计划,不应写进验收标准?

   回答：测试用例设计、测试数据构造、环境搭建细节、自动化 suite 执行步骤、CI 命令、开发排期、提交拆分、部署步骤和运维 runbook 不应写进 06。06 只引用这些内容形成裁决条件。

5. 是否存在阻塞验收标准生成的上游缺口?

   回答：不阻塞 06 设计校准。当前缺口是实施期缺口:尚无送验版本、真实测试 run、CI artifact 和测试执行结论。06 可以将这些作为验收基线的待填字段和进入条件,不应因此停止编写验收标准。

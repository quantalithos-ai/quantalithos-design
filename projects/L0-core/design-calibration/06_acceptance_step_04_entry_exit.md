## 3. SOP 问题回答

1. 开始验收前哪些基线必须确认?

   回答：必须确认文档基线、实现仓基线、构建产物基线、测试执行基线、配置运行基线、测试数据基线、证据归档基线和缺陷基线。文档基线当前可固定;实现 commit、build artifact、CI run id、test run_id、config_profile、artifact 路径必须在送验时补齐。

2. 哪些测试证据必须先生成?

   回答：进入正式验收前必须至少生成 P0 证据: EV-CI-FMT-001、EV-UNIT-001、EV-SVC-001、EV-CONTRACT-001、EV-CONTRACT-002、EV-INT-001、EV-WORKER-001、EV-CONFIG-001、EV-AUDIT-001、EV-TRACE-001、EV-SEC-001、EV-SEC-002、EV-SCOPE-001、EV-E2E-001。涉及 release candidate 时还必须有 release-like gate 证据。EV-NFR-* 和 EV-NIGHTLY-001 可作为 P1 / 残余风险证据,但若其被标记为本次 release gate 必需,也必须进入。

3. 哪些缺陷会阻断进入验收?

   回答：已知 S 级缺陷、A 级缺陷、P0 用例失败、release gate 失败、P0 证据缺失、raw secret 泄露、禁止正文入仓、失败伪成功、引用失败默认放行、未完成 S/A 复验都会阻断进入正式验收。若团队仍提交,结论只能是“不通过”或“送验不成立”。

4. 退出验收需要哪些结论?

   回答：退出验收必须形成三值结论之一:通过、有条件通过、不通过。无论哪种结论,都必须完成 P0 门禁裁决、一票否决检查、缺陷状态确认、证据完整性检查、风险接受 / 拒绝记录和签署记录。

5. 哪些风险必须先接受?

   回答：真实 L0-bus 投递未覆盖、真实下游仓库联调未覆盖、真实 secret provider / KMS 未覆盖、完整性能容量压测未覆盖、CI artifact 物理存储待固定等残余风险必须在退出前明确接受人、期限、影响范围和后续动作。未接受的 P1/P2 风险不能直接判定为通过。

## 6. 验收裁决取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 允许证据不完整也进入验收 | 可以更早开始评审 | 容易把验收变成补资料过程 | 不采用 |
| B. 进入验收前要求所有 P0 证据和送验基线齐备 | 裁决清楚,减少漂移 | 实施期准备成本更高 | 采用 |
| C. 退出只要求 P0 通过 | 简单 | 无法覆盖一票否决、风险接受和签署 | 不采用 |
| D. 退出必须形成三值结论和完整证据链 | 可审计,可交接 | 文档更严格 | 采用 |

### 7.2 退出条件

- [ ] 已对 §5~§10 的所有 P0 验收门禁给出通过 / 失败裁决。
- [ ] 已完成 §11 一票否决项检查,且结论明确。
- [ ] 已完成缺陷分级、复验和放行判断;S 级和 A 级缺陷状态明确。
- [ ] 已完成证据完整性和 redaction 检查,证据不含 raw secret、外部正文全文或生产敏感数据。
- [ ] 已完成残余风险接受 / 拒绝记录;每个可接受风险都有接受人、期限、影响范围和后续动作。
- [ ] 已形成最终结论:通过、有条件通过或不通过,不得使用“基本通过”“原则上通过”等模糊结论。
- [ ] 最终结论已完成签署或明确缺失签署人及阻断影响。
- [ ] 验收结论、证据索引、缺陷状态和风险接受记录已归档。

### 7.3 阻断进入验收清单

| 阻断项 | 处理 |
|---|---|
| 送验 commit / build artifact 未固定 | 不进入正式验收 |
| test `run_id` 或 P0 suite summary 缺失 | 不进入正式验收 |
| P0 证据 EV 缺失 | 不进入正式验收 |
| S/A 缺陷未关闭或未复验 | 不进入正式验收 |
| 一票否决项已触发 | 不进入正式验收;若强行送验,结论为不通过 |
| 证据含 raw secret 或禁止正文 | 不进入正式验收;必须清理并重跑证据 |
| config_profile 或配置 artifact 不可定位 | 不进入正式验收 |

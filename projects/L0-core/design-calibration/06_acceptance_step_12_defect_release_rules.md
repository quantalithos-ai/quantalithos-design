## 3. SOP 问题回答

1. S/A/B 缺陷如何定义?

   回答：S 级是触发一票否决或破坏核心边界 / 安全 / 一致性 / 追溯的缺陷。A 级是 P0 主线或 P0 自动化失败,但未触发 S 级红线的缺陷。B 级是 P1、nightly 风险或非发布阻断专项退化。C 级是文档、报告、提示或非 P0 可用性瑕疵。

2. 每级缺陷对验收结论有什么影响?

   回答：S 级和 A 级未关闭时不得通过或有条件通过。S 级触发一票否决时直接不通过。B 级可在不影响 P0 和 release gate 的前提下进入风险接受,否则不通过。C 级不阻断 P0,但应记录修复计划。

3. 修复后如何复验?

   回答：修复关闭必须包含缺陷记录、根因说明、修复提交、复验用例、相关 EV ID、自动化防回归说明和残余风险结论。S/A 缺陷必须重跑直接失败用例、相邻主线用例、相关专项和 release gate。

4. 哪些缺陷可以风险接受?

   回答：只有 B/C 级缺陷在不影响 P0 门禁、不触发一票否决、不影响 release gate 且有 owner、接受人、期限和后续动作时,才可以进入 Step 13 风险接受。S/A 缺陷不得风险接受。

5. 哪些缺陷必须阻断下一阶段?

   回答：任一未关闭 S/A 缺陷、任一 AC-BLOCKER、P0 EV 缺失、release gate 失败、P0 用例失败、证据 redaction 失败、缺陷修复无复验证据,均阻断进入下一阶段。

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 缺陷等级 | S/A/B 旧口径 | S/A/B/C 与 05 对齐 | 覆盖文档和非 P0 瑕疵 |
| S 级 | rich model / consume drift | 一票否决或核心边界 / 安全 / 一致性 / 追溯破坏 | 对齐 Step 11 |
| A 级 | 视情况 | P0 主线失败,未触发 S 级;不得放行 | 防止 P0 缺陷风险接受 |

| 复验 | 未定义 | 缺陷记录、根因、修复提交、复验用例、EV、自动化防回归 | 支撑可审计关闭 |

## 6. 验收裁决取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. S/A 均可由负责人风险接受 | 灵活 | 会破坏一票否决和 P0 门禁 | 不采用 |
| B. 任何缺陷都不允许放行 | 最严格 | B/C 类非阻断瑕疵会不必要阻塞 | 不采用 |
| C. S/A 必须关闭并复验,B/C 可在条件满足时风险接受 | 平衡严格性和推进效率 | 需要 Step 13 风险表承接 | 采用 |

## 7. 结构化中间产物

### 7.1 缺陷分级表

| 缺陷级别 | 定义 | 对结论的影响 | 复验要求 |
|---|---|---|---|
| S | 触发 AC-BLOCKER 或破坏核心边界 / 安全 / 一致性 / 追溯 | 直接不通过;不得风险接受 | 修复后重跑直接失败用例、相关专项、release gate;必须补自动化防回归和 EV |
| A | P0 主线、P0 自动化或 P0 证据失败,但未触发 S 级红线 | 未关闭时不得通过或有条件通过 | 当前迭代修复;重跑失败用例、相邻主线、相关 suite;绑定 EV |
| B | P1 能力、nightly 风险、非发布阻断专项退化 | 可有条件通过,前提是不影响 P0 / release gate 且完成风险接受 | 记录 owner、期限、影响范围;必要时补回归用例 |
| C | 文档、报告、提示、非 P0 可用性瑕疵 | 不阻断 P0,但不得影响证据完整性 | 记录修复计划;必要时随文档或报告回归 |

### 7.2 复验规则表

| 缺陷类型 | 最小复验集 | 必须补充的证据 |
|---|---|---|
| 一票否决缺陷 | 触发 AC-BLOCKER 的用例 + 对应专项 + release gate | 缺陷记录、根因、修复提交、复验 EV、自动化防回归说明 |
| P0 Command / Query 缺陷 | 直接失败 TC-CMD / TC-QUERY + 相邻 service suite | EV-SVC-001、相关 TC 结果 |
| 状态机 / 事务缺陷 | TC-CMD、TC-TXN、TC-OUTBOX、TC-CONC | EV-UNIT-001、EV-INT-001、EV-CONC-001 |
| 安全 / 数据边界缺陷 | TC-SCOPE、TC-CONFIG、security scan | EV-SEC-001、EV-SEC-002、EV-SCOPE-001 |
| 配置 fail closed 缺陷 | TC-CONFIG-* + 受影响入口 smoke | EV-CONFIG-001 |
| Outbox / relay 缺陷 | TC-EVENT、TC-OUTBOX、minimal E2E | EV-CONTRACT-002、EV-E2E-001 |
| 证据缺陷 | evidence archive check + redaction scan | AC-EVID 对应 EV 和证据索引 |

### 7.3 放行规则表

| 场景 | 放行口径 |
|---|---|
| S 级缺陷未关闭 | 不通过 |
| A 级缺陷未关闭 | 不通过 |
| S/A 修复但未复验 | 不通过 |
| B 级缺陷影响 P0 或 release gate | 不通过 |
| B 级缺陷不影响 P0,且 owner / 接受人 / 期限 / 后续动作齐备 | 可进入 Step 13 风险接受,支持有条件通过 |
| C 级缺陷不影响证据完整性和 P0 门禁 | 可不阻断,但需记录 |
| 缺陷分级争议无法裁决 | 按更高等级处理 |

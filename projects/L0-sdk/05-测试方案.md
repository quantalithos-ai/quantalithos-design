### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 SDK“能发包”,而是系统验证 `L0-sdk` 是否真正满足“三语言开发者接入面”的设计要求,尤其要证明以下几点成立:
- core / bus 契约能够稳定进入 codegen 与 wrapper 主线
- `binding ≠ developer-facing SDK` 成立,raw binding 不会被误当高层体验层
- `sdk wrapper ≠ core primitive truth`、`sdk wrapper ≠ bus transport truth` 两条核心边界成立
- client / subscription 调用链默认具备 auth / trace / error mapping / redaction 横切能力
- `subscription convenience API ≠ bus consume truth` 成立,高层 helper 不会倒灌 bus truth
- examples / quickstart / migration guide / release manifest 围绕同一 artifact、descriptor 与 version lock 演进
- 三语言同步发版链成立,且任一语言失败都能阻断 stable release

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| Binding 生成与契约对齐部分 | 契约输入对象 | P0 | ProtoRefLock、VersionLock、GeneratedBindingArtifact |
| 三语言高层 Client 封装部分 | 接入对象 | P0 | RustSdkClient、PythonSdkClient、TypeScriptSdkClient、ClientBuilder |
| 认证、Trace 与错误映射横切部分 | 横切对象 | P0 | AuthContext、TraceContextCarrier、SdkErrorMapping、RedactionRuleSet |
| 事件订阅与总线接入封装部分 | 接缝对象 | P0 | PublishRequest、SubscriptionHandle、SubscriptionCallback、ConsumeAckHandle |
| 文档、示例与发版一致性部分 | 发布/证据对象 | P0 | QuickstartSpec、ExampleCase、MigrationGuide、ReleaseManifest |
| crates.io / PyPI / npm 产品内部实现细节 | 非范围 | P2 | 只验证 SDK 发版接缝,不验注册表内部逻辑 |
| `L0-core` / `L0-bus` 真相本体 | 非范围 | P2 | 只验 SDK 如何消费其契约,不验上游仓全部细节 |
| playground / REPL / REST gateway 后置能力 | 非范围 | P2 | 当前不在 P0 接入主链内 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / policy owner | `proto_ref_lock.validate_locked_inputs`、`builder.validate_artifact_compatibility`、`auth_context.validate_safe_shape`、`handle.validate_against_bus_contract`、`manifest.validate_release_consistency` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + codegen + projection 联动 | backend / domain owner | `GenerateBindings`、`BuildRustClient`、`BuildPythonClient`、`BuildTsClient`、`InjectTrace`、`BuildSubscription`、`RunSmoke`、`PublishReleaseManifest` | 契约链、接入链、发版链同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | core/bus contract → sdk binding、sdk subscription → runtime/UI、release manifest → registries | 输入输出语义一致 |
| 恢复专项测试 | 验证 proto-ref 漂移、trace 缺失、redaction 漏命中、单语言发版成功等异常链 | architecture / QA | ref mismatch、bus helper drift、missing trace、redaction miss、partial release | 真相不丢失、错误被正确阻断 |
| 投影一致性测试 | 验证 api diff / capability matrix / smoke report 与真相一致 | backend / QA | cross-lang diff rebuild、smoke report rebuild、descriptor compare | 投影只读且与真相一致 |
| 端到端主线测试 | 验证最小接入闭环 | QA / owner | lock → generate → build client → subscribe with trace → smoke → release | 主干接入闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `binding ≠ developer-facing SDK` | 仅生成 binding 时不得直接宣称 SDK 可用 | 单元 + 集成测试 | 是 | artifact / descriptor compare |
| `sdk wrapper ≠ core primitive truth` | wrapper 不得手写冲突 schema / primitive | 单元 + 集成测试 | 是 | model review / negative flow |
| `sdk wrapper ≠ bus transport truth` | high-level helper 不得改写 bus 契约 | 集成 + 事件链测试 | 是 | contract compare |
| `subscription convenience API ≠ bus consume truth` | helper 只做封装,不扩张底层 truth | 单元 + 集成测试 | 是 | helper/bus compare |
| `examples / docs ≠ contract source` | quickstart 与示例必须从 descriptor 导出或对齐 | 投影一致性测试 | 是 | smoke report / diff |
| trace 自动传播成立 | 缺 trace 时自动生成,已有 trace 时优先透传 | 单元 + 集成测试 | 是 | trace compare |
| redaction 默认安全成立 | secret/token/password 命中即脱敏 | 单元 + 恢复专项测试 | 是 | log / error snapshot |
| 三语言同步发版链成立 | 任一语言失败时 stable release 必须阻断 | 集成 + 端到端测试 | 是 | release manifest / publish log |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local codegen runner / fake registries / fake bus contract | debug logging / smoke enabled / redaction visible | 容易只测 happy path |
| test | CI / 集成测试 | deterministic proto-ref / bus contract fixtures / fake publish targets | isolated manifest tables / fixed artifact outputs / release dry-run | 跨语言样本覆盖不足 |
| staging | 端到端演练 | real-like core/bus input / package build / registry dry-run / runtime-ui example consumers | smoke evidence / release manifest / migration guide enabled | 多语言发布时序差异放大 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | GenerateBindings 成功生成三语言工件 | proto-ref / bus-ref 合法 | GenerateBindings | 三语言 artifact 全部生成 |
| TC-002 | proto-ref 漂移时阻断生成 | core_ref / bus_ref 与 digest 不一致 | VerifyProtoRef → GenerateBindings | 返回 `PROTO_REF_MISMATCH` |
| TC-003 | BuildRustClient 成功构造高层 client | Rust artifact 存在 + service 暴露 | BuildRustClient | client descriptor 创建成功 |
| TC-004 | wrapper 不得绕开 binding 手写冲突契约 | 手工 wrapper 与 artifact 冲突 | BuildTsClient / validation | 返回兼容性错误 |
| TC-005 | trace 缺失时自动补全 | auth 合法 + trace 缺失 | InjectTrace | 生成新 traceparent |
| TC-006 | 已有 trace 时优先透传 | trace 已存在 | InjectTrace | 输出 traceparent 不变 |
| TC-007 | redaction 漏命中时阻断安全输出 | 错误对象包含 secret/token | RedactOutput | 返回安全错误并拒绝原样输出 |
| TC-008 | BuildSubscription 成功构造高层订阅入口 | bus contract 可见 + consumer_group 合法 | BuildSubscription | SubscriptionHandle / Callback 创建成功 |
| TC-009 | convenience helper 不得污染 bus truth | helper 字段超出 bus consume contract | BuildSubscription | 返回 `BUS_CONTRACT_MISMATCH` |
| TC-010 | RunSmoke 成功跑通三语言 quickstart | artifact + descriptors + examples 完整 | RunSmoke | ExampleSmokeReport 全绿 |
| TC-011 | 任一语言 smoke 失败时阻断 release | Python example 失败 | RunSmoke → PublishReleaseManifest | release 不发布 |
| TC-012 | PublishReleaseManifest 仅在三语言一致时成功 | smoke 全绿 + version 一致 | PublishReleaseManifest | ReleaseManifest 创建成功 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | wrapper 越界污染 core/bus truth / redaction 失效泄露敏感值 / 单语言成功仍发布 stable / docs 成为契约源 | 阻断放行,必须修复 |
| A | 主线可跑但 cross-lang drift、trace 默认行为、subscription helper 边界不稳 | 原则上修复后再放行 |
| B | 非关键 diff 视图、低优先级 example 或报告展示异常 | 可带风险进入下一轮 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 proto-ref / version 锁定,都必须回归 GenerateBindings 与 artifact completeness 主线
- 每次改动 Rust/Python/TS wrapper,都必须回归 cross-lang 概念一致性与 descriptor 主线
- 每次改动 auth/trace/error/redaction,都必须回归默认安全链与 sensitive 输出主线
- 每次改动 subscription helper,都必须回归 bus contract 边界与 ack/nack 暴露主线
- 每次改动 docs/examples/release,都必须回归 smoke、release manifest、migration guide 一致性主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| TS transport 方案后续切换 | 测试矩阵需扩充 | TL / 架构 |
| internal-python split 后续落地 | Python SDK 用例需拆分 | sdk / runtime |
| MCP client 后续并入 | bus / client / docs 边界测试需增加样本 | Owner / TL |

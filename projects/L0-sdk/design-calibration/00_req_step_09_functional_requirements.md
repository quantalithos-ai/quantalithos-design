## 3. SOP 问题回答

### 3.1 根据这些用户故事，系统必须提供哪些业务能力？

`L0-sdk` 当前必须提供十类核心能力：

1. 共享契约承接与语言产物一致能力。
2. 三语言官方客户端概念一致能力。
3. 平台能力最小接入能力。
4. 事件语义客户端封装能力。
5. 错误映射与 trace 传播一致能力。
6. redaction 与凭据材料保护能力。
7. 本地 package candidate 与安装验证能力。
8. quickstart、docstring 与示例可运行能力。
9. 跨语言 smoke 与一致性验证能力。
10. 版本兼容、deprecated 与迁移治理能力。

这些能力共同证明 SDK 是官方客户端接入层，而不是只生成类型、只发布包、只提供示例或只做某一种语言封装。

### 3.2 每个能力的输入、输出、触发条件、失败情况是什么？

见 §7.1 功能需求结论表。需求阶段只描述能力边界，不写具体 API path、Rust trait、Python class、TypeScript package 结构、DTO 字段或 CI 脚本实现。

### 3.3 哪些能力共同构成闭环核心？哪些只是外围增强？

F-001~F-010 构成当前核心闭环能力。公共注册表正式发布、完整 MCP Client、REST / GraphQL wrapper、REPL / playground、本地缓存 / 离线状态管理、全量 L1/L2/L3/L4 client 覆盖属于外围增强，不进入当前 P0 主功能表。

## 5. 改动前后对比

| 项 | 旧口径 | 新口径 |
|---|---|---|
| 功能拆分依据 | 按语言包、生成脚本、接口动作、发布平台拆分 | 按官方客户端接入层所需业务能力拆分 |
| codegen 位置 | 独立 P0 功能 | 作为共享契约承接能力的支撑方式之一 |
| 三语言 package | Rust / Python / TS 分别成为功能 | 归入 package candidate 与三语言一致能力 |
| 事件能力 | 写成订阅接口或 callback 能力 | 写成消费 `L0-bus` 语义的事件客户端封装能力 |
| trace / error / redaction | 分散成多个技术功能 | 归并为横切一致与敏感材料保护能力 |
| 公共发包 | crates.io / PyPI / npm 像 P0 前置功能 | 后移为外围增强和发布阶段能力 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 继承旧 F-001~F-017 功能清单 | 迁移最快，旧文档信息保留多 | 粒度混乱，包形态、实现工具、接口动作和外围增强混成 P0 | 不采用 |
| 方案 B: 按核心能力闭环归并为能力主题 | 边界清楚，能支撑后续规则、数据、接口和验收 | 需要在后续设计阶段再展开具体语言包和 API | 采用 |
| 方案 C: 按 Rust / Python / TypeScript 三语言分别列功能 | 语言差异清楚 | 造成重复，也会削弱跨语言一致性的主线 | 不采用 |
| 方案 D: 按 core、bus、service、docs、release 等依赖对象拆功能 | 方便看依赖 | 容易把依赖对象当功能边界，不符合按能力拆分要求 | 不采用 |

### 7.2 外围增强能力结论

| 编号 | 功能需求 | 能力类型 | 说明 | 当前处理 |
|---|---|---|---|---|

### 7.3 能力依赖结论

```text
F-001 共享契约承接与语言产物一致
  -> F-002 三语言官方客户端概念一致
  -> F-003 平台能力最小接入
  -> F-008 quickstart / docstring / examples 可运行
  -> F-009 跨语言 smoke 与一致性验证

F-004 事件语义客户端封装
  -> F-005 错误映射与 trace 传播一致
  -> F-006 redaction 与凭据材料保护

F-007 本地 package candidate 与安装验证
  -> F-008 quickstart / docstring / examples 可运行
  -> F-009 跨语言 smoke 与一致性验证
  -> F-010 版本兼容、deprecated 与迁移治理
```

图示说明：

- 本图表达功能能力之间的依赖关系，不表达 API 调用链、事件流、实现顺序或目录结构。
- F-001 / F-002 是 SDK 作为官方 client 的基础。
- F-003 / F-004 证明 SDK 能接入平台能力和事件语义，但不拥有服务端业务 truth 或 bus runtime。
- F-005 / F-006 是横切一致能力。
- F-007~F-010 保证 SDK 可安装、可学习、可验证、可演进。

## 10. 进入下一步条件

- 每项核心功能都服务至少一个用户故事。
- 每项核心功能都映射到 CL-001~CL-005。
- 功能按业务能力拆分，没有按对象、CRUD、API、Command、语言包目录、生成脚本或公共发布平台拆分。
- 边界外能力和外围增强能力没有混入当前 P0 功能需求主表。

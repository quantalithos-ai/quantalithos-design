## 1. 本步目标

说明 `L0-sdk` 在需求层对外体现为哪些能力级接口面，以及它消费哪些外部能力级输入面；本步不写 API 路径、方法名、DTO、proto、事件 schema、包目录或实现协议。

## 3. SOP 问题回答

### 3.1 本仓对外提供哪些能力级接口？

`L0-sdk` 对外提供的是客户端接入能力面，包括：

- 官方客户端能力引用与版本说明面。
- 平台服务能力客户端访问面。
- bus 事件语义客户端封装面。
- package candidate 本地安装与验证面。
- quickstart、docstring、示例和迁移说明阅读面。
- 跨语言 smoke、redaction、错误和 trace 验证证据面。

这些能力面可以在后续设计中落成具体 Rust / Python / TypeScript 形式，但需求阶段不提前写具体 API。

### 3.2 本仓消费哪些能力级输入？

`L0-sdk` 消费的关键输入面包括：

- `L0-core` 的共享契约、错误、trace、metadata 和基础 envelope。
- `L0-bus` 的事件发布 / 订阅语义、delivery view、failure / replay / tap view。
- L1/L2/L3/L4 的正式服务边界或 fake / fixture endpoint。
- ADR、标准、发布策略和安全规范。
- 下游消费者的 package 使用反馈、示例验证和兼容需求。

### 3.3 哪些是同步能力边界，哪些是异步能力边界？

- 同步能力边界：共享契约承接、服务能力访问、错误映射、trace 传播、文档示例和 package candidate 验证。
- 异步能力边界：bus 事件发布 / 订阅语义封装、跨语言验证证据形成、发布候选验证材料形成。
- 后台任务边界：binding / candidate / example / smoke / compatibility 验证相关工作。

### 3.4 哪些依赖是输入型，哪些结果是输出型？

- 输入型依赖：`L0-core`、`L0-bus`、L1/L2/L3/L4 正式边界、fake / fixture endpoint、标准与设计文档。
- 输出型依赖：L5/L6 产品、`L2-runtime`、内部工具、第三方集成方和发布 / 示例验证流程消费 SDK package、文档和验证证据。

### 3.5 哪些能力边界属于当前阶段核心闭环，哪些只是外围增强？

当前核心闭环能力边界是 `L0-core` / `L0-bus` 承接、三语言官方 client、最小服务 / fake 接入、事件语义封装、横切一致、candidate、文档示例、smoke 和版本兼容。公共注册表正式发布、完整 MCP、REST / GraphQL、REPL 和本地缓存属于外围增强能力边界。

## 4. 当前文档问题诊断

| 位置 | 当前表现 | 问题 | 本步处理 |
|---|---|---|---|
| 旧 `00` §10.1 | 写 core、bus、registry、OTel / W3C Trace Context、MCP ecosystem 和 SLA | 混合依赖、外部标准、发布平台和运行时 SLA，且部分不属于当前 P0 | 改成能力级依赖边界表 |
| 旧 `00` §10.2 | 写上游消费 proto / CloudEvent / ErrorCode，下游消费 Rust / Python / TS SDK | 方向正确，但没有区分编译期 / 运行期 / 事件协作依赖 | 补全全局依赖类型 |
| 旧 `00` §11 | 具体安装、发布和 smoke 验收提前进入接口章节 | 验收内容应留到 Step 14 | 本步只写能力边界，不写验收步骤 |
| 旧文档整体 | 易把 SDK 对外 client 能力误写成服务端 API 本体 | 会让 SDK 变成 gateway / facade | 明确 SDK 只封装正式边界，不拥有服务端 truth |

## 5. 改动前后对比

| 项 | 旧口径 | 新口径 |
|---|---|---|
| 接口表达 | 上下游接口、注册表、标准、MCP 混写 | 分成对外能力接口表和外部依赖边界表 |
| API 粒度 | 旧文档暗示具体 service proto、CloudEvent、package 安装 | 只写能力级接口面，不写协议和 DTO |
| 依赖分类 | 编译期、运行期和事件协作混在一起 | 显式标注全局依赖类型 |
| 公共注册表 | 像当前阶段外部依赖 | 作为外围增强边界，不进入当前核心闭环 |
| MCP | 像当前外部能力依赖 | 作为 P1 候选，不阻塞当前 SDK 主线 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 按旧文档列 core、bus、registry、OTel、MCP | 迁移快 | 依赖类型混乱，公共发布和 MCP 会误升为 P0 | 不采用 |
| 方案 B: 按能力接口面和外部依赖边界重写 | 符合规范，能防止滑入协议层和实现层 | 需要后续架构 / 详细设计展开具体语言 API | 采用 |
| 方案 C: 直接列 Rust / Python / TypeScript API 面 | 方便开发者理解 | 需求阶段过早绑定语言接口设计 | 不采用 |
| 方案 D: 只引用 Step 6 依赖表，不单独写接口章节 | 篇幅少 | 无法说明这些依赖如何表现为能力边界 | 不采用 |

## 7. 结构化中间产物

### 7.1 对外能力接口结论

| 接口类型 | 名称 | 说明 | 所属能力层级 |
|---|---|---|---|
| 查询接口 | 官方客户端能力与版本引用 | 对外体现为开发者可读取 SDK 能力范围、版本兼容和迁移口径的能力面。 | 核心闭环能力 |
| 变更接口 | 平台服务能力客户端访问 | 对外体现为通过 SDK 访问正式服务边界的能力面；SDK 不拥有服务端业务 truth。 | 核心闭环能力 |
| 事件输入 | bus 事件消费客户端封装 | 对外体现为基于 `L0-bus` 语义消费事件的能力面；SDK 不定义 delivery truth。 | 核心闭环能力 |
| 事件输出 | bus 事件发布客户端封装 | 对外体现为基于 `L0-bus` 语义发布事件材料的能力面；SDK 不实现 bus runtime。 | 核心闭环能力 |
| 查询接口 | quickstart、docstring 与示例阅读 | 对外体现为开发者可学习并复现最小接入路径的能力面。 | 核心闭环能力 |
| 查询接口 | candidate 验证证据读取 | 对外体现为维护者和评审者可读取跨语言 smoke、错误、trace、redaction 验证证据的能力面。 | 核心闭环能力 |
| 后台任务接口 | package candidate 与跨语言验证 | 对外体现为形成本地 candidate、示例验证和兼容检查的后台能力入口。 | 核心闭环能力 |
| 变更接口 | 公共注册表正式发布 | 对外体现为将 candidate 发布到公共注册表的能力面。 | 外围增强能力 |
| 变更接口 | 完整 MCP Client 接入 | 对外体现为统一接入 MCP 能力的客户端能力面。 | 外围增强能力 |

### 7.2 外部依赖边界结论

| 依赖方向 | 依赖类型 | 关联方 | 全局依赖类型 | 说明 | 所属能力层级 |
|---|---|---|---|---|---|
| 输入 | 定义来源依赖 | `L0-core` | 编译期依赖 | SDK 依赖 `L0-core` 的共享契约、错误、trace、metadata 和 envelope。 | 核心闭环能力 |
| 输入 | 定义来源依赖 | `L0-bus` | 编译期依赖 / 事件协作依赖 | SDK 依赖 `L0-bus` 的事件语义和 transport view，但不实现 bus runtime。 | 核心闭环能力 |
| 输入 | 外部能力依赖 | L1 服务仓正式 API | 运行期依赖 | SDK 通过正式服务边界封装领域能力，不源码依赖服务仓。 | 核心闭环能力 |
| 输入 | 外部能力依赖 | L2 / L3 / L4 能力仓正式边界 | 运行期依赖 | SDK 按已稳定能力逐步封装 runtime、method、capability、sandbox、observability、archive 等边界。 | 核心闭环能力 / 外围增强能力 |
| 输入 | 外部能力依赖 | fake / fixture endpoint | 运行期依赖 / 不适用 | SDK 依赖受控验证目标支撑 quickstart、smoke 和 package candidate。 | 核心闭环能力 |
| 输入 | 定义来源依赖 | ADR、标准、设计文档、安全规范 | 不适用 | SDK 依赖这些材料确定兼容、文档、安全和发布口径，但不拥有其正文 truth。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | L5 产品仓 | 下游 package / 运行期消费 | L5 产品通过 SDK 消费平台能力，SDK 不依赖产品源码。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-runtime` / 自动化脚本 | 下游 package / 运行期消费 | runtime 与脚本通过 SDK 复用官方客户端体验。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | L6 生态仓 / 第三方集成方 | 下游 package / 运行期消费 | 生态和外部集成通过 SDK、文档和示例接入平台能力。 | 核心闭环能力 / 外围增强能力 |
| 输出 | 下游消费依赖 | Release / validation pipeline | 不适用 | 发布和验证流程消费 SDK candidate、报告和证据。 | 核心闭环能力 |
| 输入 | 外部能力依赖 | 公共注册表 | 不适用 | 公共注册表只在正式发布阶段成为能力边界，当前不阻塞 P0。 | 外围增强能力 |
| 输入 | 外部能力依赖 | external MCP providers | 运行期依赖 | 完整 MCP Client 的外部能力边界，当前作为 P1 候选。 | 外围增强能力 |

### 7.3 能力边界与依赖类型映射结论

| 能力边界 | 主要依赖类型 | 主要关联方 |
|---|---|---|
| 共享契约承接 | 定义来源依赖 / 编译期依赖 | `L0-core` |
| 事件语义客户端封装 | 定义来源依赖 / 编译期依赖 / 事件协作依赖 | `L0-bus` |
| 平台服务能力客户端访问 | 外部能力依赖 / 运行期依赖 | L1/L2/L3/L4 正式 API |
| 最小可验证接入 | 外部能力依赖 | fake / fixture endpoint |
| SDK 下游使用 | 下游消费依赖 | L5/L6、`L2-runtime`、内部工具、第三方集成方 |
| 发布与验证证据 | 下游消费依赖 / 不适用 | Release / validation pipeline |

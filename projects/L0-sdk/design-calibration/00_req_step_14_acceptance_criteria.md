## 3. SOP 问题回答

### 3.1 哪些条件满足后，核心能力闭环算成立？

核心闭环成立必须同时满足：

- 三语言 SDK 能承接同一批稳定上游契约和事件语义，不另造 truth。
- 三语言官方客户端概念语义一致。
- 至少存在本地 package candidate 和稳定服务边界或 fake / fixture endpoint，能证明最小接入路径可运行。
- 错误、trace、redaction 和凭据材料保护跨语言默认一致。
- quickstart、docstring、示例、版本兼容和 deprecated 过渡具备可持续维护口径。

### 3.2 哪些功能能力满足后，本次需求算完成？

F-001~F-010 必须全部具备可判断证据：共享契约承接、三语言概念一致、最小接入、事件语义封装、错误 / trace、redaction、package candidate、文档示例、跨语言 smoke、版本兼容与迁移治理。

### 3.3 哪些规则 / 边界被满足后，才算没有串线？

SDK 不得重定义 core 契约和 bus 语义，不得拥有服务端业务 truth，不得执行认证授权或治理审批，不得包含 UI / runtime 状态，不得把公共注册表、完整 MCP、REST / GraphQL、REPL 当作当前 P0 前置。

### 3.4 哪些数据边界被满足后，才算数据归属正确？

SDK 自身 truth 必须限于客户端接入体验、package candidate、文档示例、横切行为和兼容演进；上游契约和事件语义只能作为快照或引用；业务正文、事件正文、凭据正文、生产请求 / 响应、观测正文、UI / runtime 状态正文不得进入 SDK 数据范围。

### 3.5 哪些非功能要求被满足后，才算质量达标？

质量达标需要证明本地 candidate 可用、外围增强不可用时核心闭环仍成立、敏感信息泄露次数为 0、candidate 可追溯到上游版本、跨语言验证证据存在、三语言概念语义一致、失败材料可定位且不泄露正文。

### 3.6 哪些失败情形属于一票否决？

一票否决项见 §7.2。核心原则是：只要 SDK 破坏上游 truth、无法形成三语言可验证 client、泄露敏感材料、保存禁止正文或越权拥有服务端 / auth / bus runtime truth，就不能判定需求通过。

## 5. 改动前后对比

| 项 | 旧口径 | 新口径 |
|---|---|---|
| 验收组织 | 按旧功能编号和测试场景组织 | 按核心闭环、功能能力、规则边界、数据归属、非功能五类组织 |
| 公共发布 | crates.io / PyPI / npm 验收像 P0 | 当前 P0 验收以本地 package candidate 可验证为准 |
| 接口动作 | 写具体安装、调用和 CI 动作 | 写“怎样算通过”，测试步骤后移到测试方案 |
| 安全验收 | 只看 redaction | 同时看凭据保护、禁止正文、auth 边界和跨语言一致 |
| 失败口径 | 没有一票否决 | 单列破坏核心 truth 和敏感边界的否决项 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 继承旧验收表 | 迁移快，有具体场景 | 仍绑定旧功能编号、公共注册表和测试动作 | 不采用 |
| 方案 B: 按五类验收和一票否决重写 | 对齐规范，可追溯前文章节 | 具体测试脚本需后续测试方案展开 | 采用 |
| 方案 C: 只写一张功能验收表 | 简短 | 会漏掉规则边界、数据归属和非功能质量 | 不采用 |
| 方案 D: 把所有验收都写成 Given-When-Then | 容易给测试人员执行 | 需求阶段会滑入测试步骤和实现细节 | 不采用 |

## 7. 结构化中间产物

### 7.1 验收标准表

| 验收类别 | 验收项 | 验收条件 |
|---|---|---|
| 核心能力闭环验收 | 三语言稳定承接成立 | Rust / Python / TypeScript SDK 都能承接同一批稳定 `L0-core` 契约和 `L0-bus` 语义，不另造 truth。 |
| 核心能力闭环验收 | 官方客户端概念一致成立 | 三语言 SDK 的核心概念语义一致，语言习惯差异不改变平台含义。 |
| 核心能力闭环验收 | 最小可验证接入成立 | 本地 package candidate 能通过稳定服务边界或 fake / fixture endpoint 证明最小接入路径可运行。 |
| 核心能力闭环验收 | 横切默认一致成立 | 错误映射、trace 传播、redaction 和凭据材料保护在三语言中默认一致。 |
| 核心能力闭环验收 | 文档与兼容演进成立 | quickstart、docstring、示例、版本兼容、deprecated 和迁移说明具备可维护口径。 |
| 功能能力验收 | F-001 / F-002 共享契约与官方 client | SDK 能稳定承接上游契约，并形成三语言概念一致的官方 client 能力。 |
| 功能能力验收 | F-003 / F-004 平台与事件接入 | SDK 能访问正式服务边界并封装 bus 事件语义，同时不拥有服务端 truth 或 bus runtime。 |
| 功能能力验收 | F-005 / F-006 横切行为 | 错误、trace、redaction 和凭据保护具备跨语言一致证据。 |
| 功能能力验收 | F-007 / F-008 package 与文档示例 | 本地 package candidate、quickstart、docstring 和示例能够支撑开发者完成最小接入。 |
| 功能能力验收 | F-009 / F-010 验证与演进 | 跨语言 smoke、版本兼容、deprecated 和迁移治理均有可追溯证据。 |
| 规则 / 边界验收 | core / bus truth 不被重定义 | SDK 没有定义替代的 proto / DTO、CloudEvents schema、ErrorCode、TraceContext 或 bus delivery 语义。 |
| 规则 / 边界验收 | 服务端 / auth / UI / runtime 边界清晰 | SDK 不拥有服务端业务 truth、认证授权 truth、治理审批、UI 状态或 runtime loop。 |
| 规则 / 边界验收 | 外围增强未误升 P0 | 公共注册表、完整 MCP、REST / GraphQL、REPL 和本地缓存未被写成当前核心闭环前置。 |
| 数据归属验收 | SDK truth 范围正确 | SDK truth 只包括客户端接入体验、package candidate、文档示例、横切行为和兼容演进。 |
| 数据归属验收 | 上游 truth 只作为快照或引用 | core 契约、bus 语义和服务边界在 SDK 内只表现为快照或引用。 |
| 数据归属验收 | 禁止正文不入仓 | 业务正文、事件正文、凭据正文、生产请求 / 响应、观测正文、UI / runtime 状态正文不进入 SDK 数据范围。 |
| 非功能验收 | candidate 可追溯 | 每个 SDK candidate 都能追溯到上游 core / bus 版本和验证证据。 |
| 非功能验收 | 敏感信息保护达标 | redaction 和凭据保护验证中敏感值泄露次数为 0。 |
| 非功能验收 | 失败可定位 | 示例和 smoke 失败能够定位到 core / bus / 服务边界 / SDK 封装 / 环境问题，且不泄露敏感正文。 |
| 非功能验收 | 外围能力降级不破坏核心闭环 | 公共注册表、完整 MCP、REST / GraphQL、REPL 不可用时，F-001~F-010 仍可判断和验收。 |

### 7.2 一票否决项

- SDK 重定义 `L0-core` 契约 truth 或 `L0-bus` 事件语义 truth。
- SDK 只有单语言或双语言可用，无法形成三语言官方客户端闭环。
- 没有本地 package candidate，或没有稳定服务边界 / fake / fixture endpoint，导致最小接入无法验证。
- 错误、日志、示例、诊断或验证报告中泄露 token、secret、credential、password、private key 等敏感材料。
- SDK 保存业务正文、事件 payload 正文、生产请求 / 响应正文、trace 全量正文、UI 状态或 runtime loop 状态。
- SDK 执行身份认证、权限裁决、治理审批或服务端业务编排。
- deprecated / breaking change 无迁移口径，且三语言兼容状态无法追溯。

|---|---|---|---|---|
| Q-001 | 是否把公共注册表发布失败作为一票否决 | 是 | 否，当前只否决本地 candidate 不可验证 | 推荐 B。原因是公共发布已裁剪为后续增强 |

| Q-003 | 是否把性能具体阈值写进验收 | 写具体初始化 / 包体积阈值 | 先验收可测量和不成为主要瓶颈，测试方案再细化阈值 | 推荐 B。原因是需求阶段不宜拍死实现阈值 |
| Q-004 | 是否将三语言全部可验证作为一票否决 | 否，主语言通过即可 | 是，三语言官方 client 是 SDK 主闭环 | 推荐 B。原因是三语言一致是仓存在的核心理由 |

## 3. SOP 问题回答

### 3.1 每个核心能力闭环节点对应哪些用户故事？

已在 Step 8 收敛：

| 闭环节点 | 对应用户故事 |
|---|---|

| CL-002 官方客户端一致 | US-001 / US-002 / US-003 / US-004 / US-009 |
| CL-003 最小可验证接入 | US-002 / US-003 / US-005 / US-007 |
| CL-004 横切默认一致 | US-003 / US-004 / US-006 |
| CL-005 文档与兼容演进 | US-005 / US-007 / US-008 / US-009 |

### 3.2 每个用户故事对应哪些功能需求？

用户故事通过功能需求主轴承接。US-001 / US-004 / US-009 主要承接 F-001 / F-002 / F-004 / F-010；US-002 / US-003 主要承接 F-002 / F-003 / F-004 / F-005；US-005 / US-007 主要承接 F-003 / F-007 / F-008；US-006 承接 F-005 / F-006 / F-009；US-008 承接 F-007 / F-010。

### 3.3 每个功能需求对应哪些业务规则、数据归属和验收标准？

见 §7.1 主追溯矩阵。本步只做映射，不新增前文未确认的新项。

### 3.4 是否存在没有来源的功能、没有承接的规则、没有验收的能力？

经 §7.2 漏项检查，当前没有发现无故事来源的核心功能、无闭环映射的核心功能、无规则保护的核心功能或无验收标准的核心功能。外围增强能力未进入 F-001~F-010 主矩阵，已在前文章节作为外围增强处理。

## 4. 当前文档问题诊断

| 位置 | 当前表现 | 问题 | 本步处理 |
|---|---|---|---|
| 旧 `00` | 没有正式需求追溯矩阵 | 难以判断故事、功能、规则、数据和验收是否闭合 | 新增矩阵 |
| 旧功能编号 | F-001~F-017 混合能力、包形态、发布平台和接口动作 | 若直接追溯会延续旧粒度问题 | 使用 Step 9 新 F-001~F-010 |
| 前序 Step | 各步骤已形成编号，但分散在多个中间产物中 | 需要统一追溯视图 | 本步集中映射，不新增需求 |

## 5. 改动前后对比

| 项 | 旧口径 | 新口径 |
|---|---|---|
| 追溯结构 | 无正式矩阵 | 以功能需求为主轴的闭环 / 故事 / 规则 / 数据 / 验收矩阵 |
| 功能主轴 | 旧 F-001~F-017 | 新 F-001~F-010 |
| 漏项检查 | 无 | 显式检查孤儿功能、规则、验收和新增项 |
| 外围增强 | 容易混入 P0 | 不进入主矩阵，仅在前文作为外围增强保留 |

---

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 以核心闭环为矩阵主轴 | 能突出 CL-001~CL-005 | 不符合规范固定结构，难以检查每项功能是否有验收 | 不采用 |
| 方案 B: 以功能需求为矩阵主轴 | 对齐规范，便于发现孤儿功能和缺失验收 | 需要把同一闭环映射到多个功能项 | 采用 |
| 方案 C: 只做自然语言总结 | 篇幅短 | 无法结构化检查漏项 | 不采用 |
| 方案 D: 在矩阵里补写新需求 | 看似能补洞 | 违反 Step 16 只做映射的约束 | 不采用 |

### 3. SOP 问题回答

1. 哪些架构决定需要沉淀为 ADR？

   回答：至少包括：将 `L0-sdk` 定义为官方三语言客户端接入层；采用上游派生视图与官方语义封装分层；采用三语言语义基线与 idiomatic 表达分离；通过 formal API / fake adapter 承接服务能力；通过 `L0-bus` 语义事件客户端视图承接事件能力；以本地 package candidate 与验证证据链作为当前 P0；将 error / trace / redaction / credential protection 作为跨语言横切默认；通过兼容治理和上游版本引用约束演进。

2. 每个关键架构决定对应哪些需求、约束或风险来源？

   回答：这些决策分别承接 `00-需求文档.md` 的本仓定位、目标与非目标、使用方与依赖、核心能力闭环、功能需求、业务规则、数据归属、接口与依赖、非功能需求、风险与待确认事项。

3. 是否存在没有需求来源的架构设计？

   回答：当前没有影响主线的孤儿架构判断。具体协议、生成器、包管理、目录结构、runner 命令、报告格式、公共发布渠道和全量 client 覆盖顺序仍保持待确认或后续设计承接，没有被写成已定架构结论。

4. 是否存在没有架构承接的核心需求或关键约束？

   回答：没有核心闭环需求未被承接。外围增强项只被承接为后续演进、重新裁剪或待确认事项，没有被提升为当前 P0 主线。

5. 哪些取舍和红线必须长期可追溯？

   回答：必须长期可追溯的红线包括：SDK 不做 binding-only 仓、不做 server gateway、不做 auth provider、不做 UI / runtime、不重定义 core / bus truth、不保存正文和凭据、不让公共注册表或全量覆盖阻塞当前 P0。

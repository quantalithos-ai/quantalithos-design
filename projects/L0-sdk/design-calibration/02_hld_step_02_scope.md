### 3. SOP 问题回答

1. 本次概要设计最主要要把哪些结构说清？

   回答：本次概要设计最主要要把 `L0-sdk` 的官方三语言客户端接入层落成可实现结构。需要说清代码主体框架如何承接上游契约派生视图、官方语义封装、formal API / fake boundary adapter、`L0-bus` event client view、package candidate 与验证证据链、横切默认和兼容治理；同时要说清主要组成部分、关键对象、接口骨架、关键处理流、状态机、配置影响和详细设计承接边界。

2. 这一轮概要设计应停在什么深度，才算足够支撑进入详细设计？

   回答：本轮概要设计应停在“代码主体骨架”深度：可以点名主要组成部分、代码主体 / 模块、关键对象名、关键字段骨架、成员函数 / 工厂函数骨架、Command / Query / Event / Operations Job 名称、关键处理流和状态集合；但不写完整 Rust / Python / TypeScript 实现、完整字段全集、协议 schema、DDL、完整函数签名、测试用例、脚本命令或发布流程。

3. 哪些内容属于本次概要设计范围？

   回答：属于本次范围的内容包括：代码主体框架总览、主要组成部分职责与边界、对象候选池与关键对象轮廓、API / 接口骨架、关键处理流、状态定义与状态流转、异常与边界场景轮廓、配置影响轮廓、详细设计承接清单、设计风险与待确认事项。

4. 哪些内容虽然相关，但当前不进入概要设计范围？

   回答：公共注册表发布、完整 MCP、REST / GraphQL gateway、REPL / playground、本地缓存 / 离线状态、全量 L1/L2/L3/L4 client 覆盖、具体协议 / transport / 生成器 / 包管理、性能阈值、reports / artifacts 具体格式、测试用例矩阵、实施 commit boundary、目录文件全集不进入当前概要设计范围。它们分别由后续需求重裁剪、详细设计、配置设计、测试方案、验收标准或实施计划承接。

5. 哪些内容应留给详细设计，而不应在本章提前展开？

   回答：详细设计承接完整对象字段、完整 enum / value object、完整函数签名、模块文件结构、language package 组织、adapter trait / class / interface、协议 DTO / JSON / proto schema、错误类型映射细节、trace / redaction 函数细节、状态迁移函数、repository / port 细节、配置加载代码、测试 fixture 和伪代码级调用链。本章只给出这些内容的概要骨架与承接方向。

### 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 设计目标 | 偏向解释 SDK 是什么、为什么需要 SDK | 明确本轮要收敛代码主体框架、主要组成部分、对象、接口、流程、状态、配置影响和详细设计承接 | 概要设计需要服务详细设计,不能停留在背景解释 |

| 后续承接 | 旧文档没有清晰交给 03 的结果 | 每个目标都要求形成可交付给详细设计的结果 | 保证后续 03 能 1:1 承接 |

#### 7.4 当前阶段设计深度口径

- 本轮概要设计收敛到“代码主体骨架层”。
- 可以正式点名主要组成部分、代码主体 / 模块、关键对象、接口名称、关键字段骨架、成员函数 / 工厂函数骨架、处理流、状态集合和配置影响。
- 字段必须写明类型名,函数参数必须写明类型名和参数名,但不写完整语言实现。
- 处理流必须说明关键函数的作用和数据流方向,但不写完整伪代码和分支全集。
- 状态机必须说明状态集合、状态含义和合法流转方向,但不写状态迁移函数实现。
- 配置影响只识别影响面和禁止配置化边界,不写配置文件样例和加载实现。
- 本轮结果必须足以让 `03-详细设计.md` 继续完成 1:1 结构展开。

## 3. 约束条件

> 校准来源:
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_03_constraints.md` 的“约束条件表”和“约束边界说明”小节。

后续章节必须持续受以下结构性约束保护:

| 约束 | 当前要求 |
|---|---|
| 只承接已收稳需求与架构结论 | `02` 不重新定义需求、架构、子域划分、依赖方向或技术取舍 |
| Artifact truth ownership 单一 | `ArtifactFact`、`ArtifactVersion`、`ArtifactLineageLink`、`ArtifactBaseline`、`ArtifactConsumptionBackref` 只能由 `L1-artifact` 拥有 |
| 外部正文和运行材料禁止入仓 | 外部正文、runtime output、archive body、observability body、sync private copy 只能以 ref、summary、mirror state 或 degraded surface 出现 |
| 消费表达不得迁移 ownership | workspace、conversation、archive、observability、sync、console 只能消费 / 展示 / 交接 Artifact truth |
| 派生只读 | preview、report、reconciliation、search 和 handoff preparation 只能消费 committed truth,不得反写真相 |
| 核心强一致,外围最终一致 | fact / version / lineage / baseline / backref 同步成立或拒绝;派生、刷新、交接和报告允许延迟 |
| sync / async / background 三类路径分离 | Command 负责核心 truth 判断;Consumer 负责 ref / resolution / pending / stale;Job 负责 rebuild / refresh / reconcile / handoff |
| 编译依赖不得越过 `L0-core` | 其余仓只能以运行期接缝、summary、snapshot、event 或 handoff 协作 |
| 外围增强不是核心前置 | search、preview、report、archive handoff、observability explain、sync material 不能反向定义核心 truth 主线 |
| 概要设计只停在骨架层 | 不提前写 schema、DDL、完整函数签名、配置项或实施 boundary |
| 配置不可越界 | 配置不得改变 truth owner、正式锚点、Query no-write、Consumer no-truth-write、Job no-truth-repair 和正文排除规则 |

这些约束直接指导后续判断:对象应归 truth 还是 derived,接口应归 Command 还是 Consumer / Job,状态能否进入正式主线,以及哪些异常只能以 degraded / failed surface 暴露。

## 4. 代码主体框架总览

> 校准来源:

概要设计先固定代码主体骨架,不直接决定 crate / module / file。当前已收稳的代码主体如下:

| `Truth Read / Consumption Services` | 编排 truth summary、read surface、trace 和只读消费 | Application Services |
| `Intake / Review Boundary Services` | 承接 intake convergence、review readiness 和 automation boundary | Application Services |

| `Truth Persistence Ports` | 承载 truth / history / backref 的正式持久化边界 | Ports / Persistence |
| `Reference / Snapshot / Body Source Ports` | 承载外部上下文、定义来源、内容来源和 mirror resolver | Ports / Boundary Integration |

| `Event / Audit / Handoff Relay Ports` | 承载 truth change relay、trace、audit 和 handoff delivery | Ports / Handoff |

## 5. 主要组成部分、职责与边界

> 校准来源:
> - `design-calibration/02_hld_step_05_components_boundary.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_05_components_boundary.md` 的“10 个主要组成部分总表”“对象发现维度表”和“各部分交互总图”小节。

`L1-artifact` 的业务主语固定为以下 10 个主要组成部分:

| 组成部分 | 核心职责 | 不承担什么 |
|---|---|---|
| `Artifact fact management` | 建立正式 `ArtifactFact` 和 `ArtifactContentFactContext` | 不拥有外部正文生命周期或相邻仓 truth |
| `Artifact version management` | 形成正式 `ArtifactVersion`、候选修订和历史替代语义 | 不把 current latest、消费副本或自动化结果当正式 version |
| `Artifact lineage management` | 形成正式来源、替代、依赖和影响关系 | 不把 trace、tool result、graph query 或 report 当 lineage truth |
| `Artifact baseline management` | 形成受控正式版本集合和冻结语境 | 不让治理裁决、发布口径或归档包替代 baseline truth |
| `Artifact intake convergence` | 收束人工 / 外部 / work / process / governance / content 来源输入 | 不直接形成 fact、version、lineage 或 baseline |
| `Artifact review and responsibility context` | 让审查、责任和解释围绕同一 Artifact truth 成立 | 不拥有 identity、work、process 或 governance 主体 truth |
| `Automation output control boundary` | 让 runtime / capability / tool 结果只以 candidate 方式进入主线 | 不拥有 runtime 或 capability truth |
| `Artifact consumption and traceability` | 对外提供稳定读取、消费回指和追溯解释 | 不把下游副本或只读视图写回核心 truth |
| `Derived maintenance and handoff preparation` | 维护 preview / report / reconciliation 和 archive / observability / sync handoff 材料 | 不形成新 Artifact truth 或冻结业务事实 |
| `External reference and local mirror support` | 承接定义来源、上下文引用、safe summary、mirror 和解析状态 | 不复制外部正文或拥有外部状态 |

```text
+====================================================================================+
|                           L1-artifact component flow                               |
+====================================================================================+
| Artifact intake convergence ----> Artifact fact management ----> Artifact version  |
|            |                           |                            |               |
|            |                           |                            v               |
|            |                           +--------------------> Artifact lineage      |
|            |                                                        |               |
| Automation output control boundary ---------------------------------+               |
|            |                                                        v               |
| Artifact review and responsibility context -----------------> Artifact baseline     |
|                                                                                    |
| Artifact consumption and traceability <----------- read / backref -----------+     |
|            ^                                                                 |     |
|            |                                                                 |     |
| External reference and local mirror support ----> Derived maintenance and handoff  |
|                                                preparation                         |
+====================================================================================+
```

这些组成部分是概要设计层的正式业务结构主语,后续 `03-详细设计.md` 可以继续落成模块和 service,但不能改写它们的职责归属。

## 7. API / 接口骨架

> 校准来源:
> - `design-calibration/02_hld_step_07_api_interface_skeleton.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_07_api_interface_skeleton.md` 的五类接口骨架表和“接口到主要组成部分映射”小节。

本仓接口按读写和运行形态分为 5 类:

| 接口类别 | 读写性质 | 主要用途 | 必须携带的上下文 | 不得做什么 |
|---|---|---|---|---|
| Command | 改写 truth / history / backref | fact、version、lineage、baseline、review、automation boundary 和消费回指变化 | `ActorContext`、`CommandMetadata`、idempotency key、trace context | 不保存外部正文,不由 Query / Consumer / Job 隐式替代 |
| Query | 只读 | 读取 truth summary、read surface、preview、report、reconciliation、trace 和 resolution surface | `ActorContext`、`QueryMetadata`、page / consistency hint | 不写 truth、pending / stale marker 或 handoff state |
| Inbound Event Consumer | 写 reference / resolution / pending / stale | 承接 work、process、governance、method、runtime、external content 等外部变化 | envelope、source event id、source ref、schema version、dedup key、trace context | 不直接创建 fact / version / lineage / baseline |
| Outbound Event | 输出已成立 truth 或维护状态变化 | 向消费方传播 Artifact 变化和只读面状态 | truth ref、change kind、trace context | 不携带外部正文或下游私有副本 |
| Operations Job | 后台维护 / 对账 / 交接 | rebuild、refresh、reconcile、archive / observability / sync handoff preparation | `JobMetadata`、run id、system / operator actor、job idempotency key | 不作为业务 Command,不修复核心 truth |

正式接口组按主要职责继续展开:

| 接口族 | 代表接口 |
|---|---|
| intake / fact Command | `RegisterArtifactIntake`、`EstablishArtifactFact` |
| version / lineage / baseline Command | `CreateArtifactVersionCandidate`、`PublishArtifactVersion`、`EstablishArtifactLineageLink`、`FreezeArtifactBaseline` |
| review / automation / consumption Command | `OpenArtifactReviewAnchor`、`AssignArtifactResponsibility`、`RegisterAutomationArtifactInput`、`IssueConsumableArtifactReference`、`RecordArtifactConsumptionBackref` |
| truth / read Query | `GetArtifactFact`、`GetArtifactVersion`、`GetArtifactBaseline`、`GetArtifactReadSurface`、`GetArtifactTrace` |
| derived / report Query | `SearchArtifactFacts`、`GetArtifactPreview`、`GetArtifactReport`、`GetArtifactReconciliationReport`、`GetExternalReferenceResolution` |
| 外部事件 Consumer | work / process / governance context changed、method definition changed、runtime signal recorded、external content source changed |
| Operations Job | `RebuildArtifactDerivedViews`、`RefreshExternalReferenceStates`、`RunArtifactReconciliation`、`PrepareArtifactArchiveHandoff`、`PrepareArtifactObservabilityHandoff`、`PrepareArtifactSyncHandoff` |

## 8. 关键处理流 / 重要函数数据流

> 校准来源:
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_08_processing_flows.md` 的“通用处理流骨架”“关键处理流清单”和“处理流覆盖清单”小节。

关键处理流按流族组织,避免对每个接口做机械重复:

| 处理流族 | 覆盖接口 | 核心边界 |
|---|---|---|
| intake register flow | `RegisterArtifactIntake` | 只建立收束语境,不等于正式 truth |
| fact establish flow | `EstablishArtifactFact` | 正式 truth 必须以 accepted intake、definition basis 和必要 review 语境进入 |
| version publish flow | `PublishArtifactVersion` | 正式 version 只能由 candidate / fact 锚点显式形成 |
| lineage establish flow | `EstablishArtifactLineageLink` | lineage 必须锚定正式 fact / version 和 formal basis |
| baseline freeze flow | `FreezeArtifactBaseline` | baseline 只冻结正式 version,不得动态解析 current latest |
| authorized read flow | `GetArtifactReadSurface` | 先做 visibility / freshness / resolution 判断,始终保持 Query no-write |
| state-writing consumer flows | 6 个 Consumers | 只写 context ref、definition ref、automation source ref、resolution、pending / stale marker |
| truth change relay flow | truth change events | 只传播已提交变化,下游失败不回滚 truth |
| derived maintenance flows | rebuild / refresh / reconcile jobs | 只维护 derived freshness、resolution 和 report |
| handoff preparation flows | archive / observability / sync jobs | 只准备交接材料和 receipt / failed / retryable marker |

通用路径保持以下顺序:

- Command 写路径: `validate context -> load refs / truth -> apply domain policy / transition -> save truth + history + trace -> emit committed relay`
- Query 读路径: `validate context -> resolve target -> check visibility / freshness -> read truth / projection -> return ready / restricted / degraded / unavailable surface`
- Consumer 输入路径: `validate envelope -> map to allowed ref / summary / pending / stale semantics -> save resolution / marker -> return accepted / duplicate / delayed / rejected receipt`
- Job 维护路径: `load committed truth / resolution / derived state -> apply maintenance guard -> save rebuilt / refreshed / handoff state -> expose job report`

必须持续保持的处理流红线:

- Query 不得写 `ArtifactConsumptionBackref`、stale marker 或 refresh state。
- Consumer 不得直接创建 `ArtifactFact`、`ArtifactVersion`、`ArtifactLineageLink` 或 `ArtifactBaseline`。
- Job 不得修复、回滚或补造核心 truth。

## 9. 状态定义与状态流转

> 校准来源:
> - `design-calibration/02_hld_step_09_state_machine.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_09_state_machine.md` 的“状态定义表”“状态流转图”和“状态机边界总览”小节。

`L1-artifact` 不是单一全局状态机,而是以下 8 组并列状态机:

| 状态组 | 承载对象 | 主线可消费状态 |
|---|---|---|
| intake / submission convergence | `ArtifactIntakeContext`、`ArtifactSubmissionRecord` | `Resolved`、`Accepted` |
| fact / content truth lifecycle | `ArtifactFact`、`ArtifactContentFactContext` | `Established`、`Verified` |
| version / lineage / baseline lifecycle | `ArtifactVersionCandidate`、`ArtifactVersion`、`ArtifactLineageLink`、`ArtifactBaseline`、`ArtifactBaselineMembership` | `ReadyToPublish`、`Published`、`Frozen`、`Established` |
| review / responsibility lifecycle | `ArtifactReviewAnchor`、`ArtifactResponsibilityAssignment` | `Ready`、`Accepted` |
| automation boundary lifecycle | `AutomationArtifactInput` | `Accepted` 仅表示可进入正式收束链 |
| consumption / read / backref lifecycle | `ConsumableArtifactReference`、`ArtifactReadSurfaceView`、`ArtifactConsumptionBackref` | `Ready`、`Recorded`、`Explained` |
| derived / reference / refresh lifecycle | `ArtifactDerivedViewState`、`ExternalReferenceResolutionState`、preview / report / reconciliation views | `Fresh`、`Resolved`、`Ready`、`Clean` |
| trace / handoff lifecycle | `ArtifactTraceRecord`、`ArtifactHandoffRecord` | `Recorded`、`Prepared`、`Delivered` |

状态传播关系:

```text
+====================================================================+
|                     Artifact State Propagation                     |
+====================================================================+
| Core truth command accepted                                       |
|   +--> change record / trace record                               |
|   +--> derived freshness -> Stale                                 |
|   +--> read surface / preview / report freshness surface          |
|   +--> handoff preparation pending                                |
|                                                                   |
| Inbound external event accepted                                   |
|   +--> context / definition / source refs                         |
|   +--> resolution state / pending reference / stale markers       |
|   +--> affected derived or read surface freshness -> Stale        |
|                                                                   |
| Operations job result                                             |
|   +--> derived freshness -> Fresh / Failed                        |
|   +--> resolution / refresh state -> Resolved / Degraded / Failed |
|   +--> handoff / trace -> Delivered / Retryable / Failed          |
+====================================================================+
```

禁止迁移红线包括:

- `Resolved` intake 不等于 `Established` fact。
- `Accepted` automation input 不等于正式 truth。
- non-formal version 不得进入 `ArtifactBaselineState::Frozen`。
- `Restricted` / `Stale` / `Unavailable` read surface 不得被 Query 内部修复成 `Ready`。
- handoff / relay failure 不得回滚 accepted truth。

## 10. 异常与边界场景轮廓

> 校准来源:
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_10_exceptions_boundaries.md` 的“异常与边界场景总览”“按处理流族归类的异常口径”和“异常影响图”小节。

会改写主线理解的关键异常与边界场景如下:

| 场景 | 处理部分 | 概要口径 |
|---|---|---|
| Command 缺少 actor / metadata / idempotency key | sync entry / application service | 不进入 truth 写路径 |
| content source、definition、work / process / governance context unresolved / stale / unavailable | intake、fact establish、read surface、refresh | 进入 pending / stale / degraded / unavailable surface,不得假装来源已闭口 |
| review not ready 或 responsibility not accepted | review / baseline / high-impact automation accept | 停在前置条件,不得 shortcut 成 ready |
| automation output 试图直接 truth 化 | automation boundary | 拒绝或降为 candidate-only 输入 |
| publish version 缺 candidate / fact 锚点,或 lineage basis 不足 | version / lineage write path | 不得形成正式 version / lineage truth |
| baseline 成员含非 formal version,或试图动态解析 current latest | baseline freeze | 拒绝或保持 candidate,不得进入 frozen |
| Query 命中 restricted / stale / unavailable read surface | read / preview / report / resolution query | 只返回 restricted / degraded / unavailable,不触发 rebuild / refresh |
| Consumer duplicate、unsupported schema、forbidden body、older-source event | inbound consumer | 只写 receipt / resolution / pending / stale,不写核心 truth |
| rebuild / refresh / reconcile / handoff failed | operations jobs | 只写 freshness / report / handoff / trace failed surface,不回滚 truth |

```text
+====================================================================+
|                  Artifact Exception Boundary Map                  |
+====================================================================+
| Command exception  -> reject or pending surface, no accepted truth |
| Query exception    -> restricted / degraded / unavailable only     |
| Consumer exception -> receipt + resolution + stale marker only     |
| Job exception      -> freshness / report / handoff failure only    |
+====================================================================+
```

详细错误码、retry、quarantine、dead-letter、补偿和恢复脚本交由 `03-详细设计.md` 及后续测试 / 验收文档继续定义。

## 11. 配置影响轮廓

> 校准来源:
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_11_configuration_impact.md` 的“配置影响轮廓表”“禁止配置化边界表”和“配置实现契约交给详细设计的方向”小节。

配置只影响运行承载、外围接缝和降级节奏,不得改变 Artifact domain invariant。

| 主要部分 / 接缝 | 是否受配置影响 | 配置影响类型 | 详细设计继续展开 |
|---|---|---|---|
| truth write / read 主体 | 间接受影响 | truth repository、trace / relay adapter、read summary projection refresh policy | 定义 builder 注入和 adapter config,不得改变 accepted truth 条件 |
| intake / review / automation boundary | 受配置影响 | request size / timeout、resolver、source allowlist、pending / rejected surface policy | 定义 intake / consumer / review config owner 和 validator |
| consumption / traceability | 受配置影响 | page limit、consistency hint、restricted / degraded exposure policy、trace export target | 定义 read config,不得允许 Query 写回指或绕过 visibility |
| derived maintenance / handoff | 受配置影响 | rebuild / reconcile scope、schedule、batch、retry、parallelism、handoff target enablement | 定义 job / handoff config,不得让 derived / handoff 修复 truth |
| external reference / mirror | 受配置影响 | source adapter、refresh cadence、stale threshold、degraded exposure strategy | 定义 resolver / refresh config,不得复制外部正文入 truth |

禁止配置化的边界:

| 禁止配置化边界 | 原因 |
|---|---|
| `L1-artifact` 的 truth ownership | 这是本仓存在理由,不能被 runtime 开关改变 |
| 外部正文禁止入仓 | 防止外部内容、运行材料、归档和同步副本污染 Artifact truth |
| Query no-write | 防止 read surface、preview、report、search 和 trace query 反向写状态 |
| Consumer 不写核心 truth | 防止外部事件绕过 actor、review、policy 和 Command 入口 |
| Job 不修复核心 truth | 防止 rebuild / refresh / reconcile / handoff 变成第二写源 |
| baseline 只冻结正式 version | 防止 current latest、候选或自动化临时结果进入 baseline |
| automation candidate-only boundary | 防止 runtime / capability 输出直接变成事实 truth |
| truth、history、trace、relay trigger 同一成立边界 | 防止半成立 truth 和补造成功痕迹 |

未来 `04-配置设计.md` 需继续定义 config owner、builder 注入、validation failure surface、adapter / job / handoff config 分类,但不允许改写上述红线。

## 13. 设计风险与待确认事项

> 校准来源:
> - `design-calibration/02_hld_step_13_risks_open_questions.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_13_risks_open_questions.md` 的“设计风险清单”“设计待确认事项清单”和“进入实现前会阻塞的事项”小节。

### 13.1 设计风险

| 风险 | 影响 | 当前处理口径 |
|---|---|---|
| 相邻仓、派生材料、消费副本或同步副本反向定义 Artifact truth | 影响 Step 5 组成部分、Step 6 truth core、Step 8 写路径和 Step 9 主状态机 | 只有 `ArtifactFact`、`ArtifactVersion`、`ArtifactLineageLink`、`ArtifactBaseline`、`ArtifactConsumptionBackref` 是正式 truth |
| 外部正文、runtime output、archive / observability body、sync private copy 进入 Artifact truth | 影响数据归属、`ArtifactContentFactContext`、异常边界和配置红线 | 正文只允许以 ref / summary / mirror state 承接 |
| current latest、临时清单、治理裁决、trace / graph query、preview / report 取代正式 version / lineage / baseline 锚点 | 影响 version、lineage、baseline、consumption 和验收红线 | formal-only 锚点规则在概要层已收稳 |
| Query、Consumer、Job、projection、report、reconciliation 或 handoff 反写真相 | 影响接口骨架、处理流、状态机和异常边界 | 保持 Query no-write、Consumer no-truth-write、Job no-truth-repair |
| 配置绕过 actor、metadata、visibility、formal-only、candidate-only 或 forbidden-body 门禁 | 影响 Step 11 禁止配置化边界、状态机和测试负例 | 配置只能改变运行承载与节奏,不能改不变量 |
| 未来实现在 `03/04/07` 缺口处自行补 schema、状态、port、配置或 evidence 真相源 | 影响设计真相源闭环和可落码性 | 缺口必须先回设计闭口,不能在实现侧私补 |

### 13.2 待确认事项

| 待确认 | 影响范围 | 当前挂起口径 |
|---|---|---|
| DB、message bus、object store、search、archive、observability、sync、external content source 的具体产品基线 | `04-配置设计.md`、ADR、实施计划、容量验证 | 当前只固定承载角色和产品中立边界 |
| 旧性能 / 容量 / 可用性候选数字是否升级为正式 SLO / 验收目标 | `05-测试方案.md`、`06-验收标准.md`、容量模型 | 当前不把旧数字写成硬指标 |
| 高级 search / preview / report / reconciliation 增强是否进入当前详细设计范围 | Query、derived maintenance、workspace / console / sync 消费面 | 当前按外围增强挂起,不影响核心 truth 主线 |
| content integrity、hash、tamper、content-addressing 是否升级为 ADR 级机制 | content source boundary、configuration、testing、technical mechanism | 当前只保留“正文禁止入仓 + 完整性可作为候选线索”口径 |
| archive / observability / sync handoff 是否需要更深回链验证或双向集成 | handoff jobs、traceability、acceptance evidence、operations | 当前只固定 handoff marker、failed / retryable surface 和 truth 不回滚规则 |
| 正式 `04-配置设计.md` 与 `07-实施计划.md` 何时补齐 | 文档链、项目台账和进入实现的门禁 | 进入配置或实施前必须由对应文档闭口 |

这些待确认事项当前不阻塞正式 `02-概要设计.md` 装配,但其中一部分在进入实现前会转化为正式 blocker。待确认事项不得在后续整理中被润色成定论。

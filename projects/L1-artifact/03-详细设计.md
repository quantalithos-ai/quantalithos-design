## 5. 模块实现契约

> 校准来源:
> - `design-calibration/03_ddd_step_05_module_contracts.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`
>
> 延伸阅读:
> - 建议继续阅读 Step 5 的模块职责表、Step 6 的对象字段级契约,以及 Step 7 的 trait / port / adapter 签名。

第 5 章是本文主轴。实现必须按七个模块组织,不得把所有 struct、trait、函数或 DTO 堆到一个全局文件后再由实现者自行拼装模块边界。

| 模块 | 职责 | 允许依赖 | 禁止事项 |
|---|---|---|---|
| `contracts` | 定义公共 DTO、typed ref、reason、marker、view、event、job、receipt、protocol error 和 fixtures | `core-contracts` | 不依赖 domain / application / infra;不承载领域不变量 |
| `domain` | 定义 truth 对象、value object、state、policy、不变量、trace / audit / outbox 成立对象和 domain error | `contracts`、`core-contracts` | 不读取 repository、config、HTTP、bus、DB、external SDK |
| `application` | 编排 command / query / consumer / job,管理 transaction、幂等、port 调用、outbox / trace / projection 副作用 | `contracts`、`domain`、`core-contracts` | 不依赖具体 infra adapter |
| `infra` | 实现 repository / adapter / store / config / runtime builder 和 fake runtime | `contracts`、`domain`、`application`、`core-contracts` | 不改写 domain 不变量,不替代 application service |
| `api` | 解析同步 Command / Query 请求,调用 application service,映射 error | `contracts`、`application`、`infra`、`core-contracts` | 不直接访问 repository,不直接调用 domain 业务方法 |
| `worker` | 消费入站事件、运行 outbox publisher loop、触发 projection invalidation / maintenance | `contracts`、`application`、`infra`、`core-contracts` | 不绕过 application 写 repository |
| `jobs` | 执行 outbox publish、projection rebuild、reference refresh、reconciliation、trace / archive handoff、external export | `contracts`、`application`、`infra`、`core-contracts` | 不把 report、handoff receipt、external export 反写成核心 truth |

### 5.1 `contracts`

`contracts` 定义 public protocol surface。所有 Command / Query / Event / Job / View / Error DTO 和二级公开类型必须在 `contracts` 或 `core-contracts` 中闭合。Command / Event / Job 中出现的 ref、reason、state-visible marker、page、visibility、freshness、receipt、report 和 schema version 不得只在 domain 或 application 本地定义。

### 5.2 `domain`

`domain` 定义 Artifact truth、状态、policy 和不变量。主要对象包括 Artifact fact、version、lineage、baseline、intake / review / automation / consumption boundary、derived view、external resolution、trace / audit / outbox 记录。领域对象不得读取 repository 或外部 adapter。

### 5.3 `application`

`application` 是唯一定义 repository、resolver、publisher、handoff、UnitOfWork、Clock、IdGenerator、idempotency 和 stored result trait 的模块。所有 accepted command / consumer / job mutation 必须在 application service 内编排 validate、reserve idempotency、load versioned truth、domain transition、save truth、append trace / audit / outbox、mark projection stale、save stored result / receipt / report、commit transaction。Query service 必须 no-write。

### 5.4 `infra`

`infra` 实现 application port。fake adapter 必须遵守 repository version、duplicate replay、projection stale、reference refresh、outbox payload snapshot、handoff marker 和 error mapping 语义;不得因为是 fake 就跳过正式状态或事务口径。durable adapter 的具体 DB / bus / search / object storage 产品不在本文锁定。

### 5.5 `api` / `worker` / `jobs`

`api`、`worker`、`jobs` 都是入口模块。它们只解析 contracts DTO、准备 metadata / operation context、调用 application facade / service 并映射错误。它们不得直接拼写 truth id、直接写 repository、绕过 stored result、绕过 outbox snapshot 或自行构造 projection view ref。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源:
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的协议总表、Envelope、surface、rejection 和 replay 小节。

本节固定 Artifact 的 public protocol 总表口径:

- 16 个 Command
- 13 个 Query
- 6 个 Inbound Event Consumer
- 8 个 Outbound Event
- 6 个 Operations Job

| 协议族 | 角色 | 关键规则 |
|---|---|---|
| Command | 唯一同步写入口 | 必须带 metadata、idempotency、request digest 和 explicit operation name |
| Query | 唯一只读入口 | 必须 no-write;not-visible / stale / degraded 只属于 query surface |
| Inbound Consumer | 外部事实接入 | 只能把 body-free ref、summary、source version 和 receipt 变成本地 snapshot / marker |
| Outbound Event | accepted truth 变化的 relay 面 | publisher 只能读取 stored payload snapshot,不得按 current truth 重建 |
| Operations Job | 维护 / 重建 / 交接 | 只允许维护派生视图、reference state、reconciliation、handoff material 和 stored report replay |

Command / Query / Consumer / Event / Job 的 request / response / receipt / report 必须与 Step 7 application service、Step 6 object、Step 9 flow、Step 11 persistence 和 Step 12 error surface 一一回指。

## 10. 数据持久化、事务与一致性契约

> 校准来源:
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读:

本章固定:

- repository version 规则
- optimistic concurrency 规则
- stored result / receipt / report 持久化语义
- projection stale 与 rebuild 语义
- handoff / relay / trace append-only 语义

核心约束:

| 对象 | 规则 |
|---|---|
| mutable truth | update existing state 必须带 formal version |
| append-only record | trace / audit / outbox / handoff / refresh 只追加不回写 truth |
| query / read model | 可重建、可 stale、但不写真相 |
| replay / duplicate | 只能回放 stored result / report / receipt,不得重跑 mutation |

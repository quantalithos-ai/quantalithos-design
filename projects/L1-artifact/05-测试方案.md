### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 artifact 的接口可调用,而是系统验证 `L1-artifact` 是否真正满足“正式制品真相仓”的设计要求,尤其要证明以下几点成立:
- Artifact / ArtifactVersion / Baseline 构成正式制品真相层
- ArtifactVersion 是正式引用单位,不能被“当前最新内容”替代
- `evidence ref ≠ adopted / approved relation` 必须成立
- baseline freeze 后成员不可静默漂移
- summary / browse / notification 只读且不反写真相
- `ImplementationPlan` 作为 artifact 时只是一种正式制品,不会偷变成 work/runtime 状态对象
- 多下游围绕同一正式 ArtifactVersion / Baseline 消费时,不会出现引用语义漂移

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 制品主语与正文真相部分 | 真相对象 | P0 | Artifact、ArtifactKind、ContentRef、metadata |
| 版本与演化链部分 | 真相对象 | P0 | ArtifactVersion、lineage、supersede、current pointer |
| 证据与采纳接缝部分 | 关系层 | P0 | EvidenceRef、AdoptedRelation、ApprovedRelation |
| 基线与冻结部分 | 冻结层 | P0 | Baseline、BaselineMember、freeze |
| 投影与下游消费接缝部分 | 读模型层 | P0 | summary / history / browse / notification |
| 对象存储底层算法与分块实现 | 非范围 | P2 | 只验证 ContentRef 可达性语义,不验底层存储算法 |
| conversation 前端卡片展示细节 | 非范围 | P2 | 只验证 ArtifactNotificationView,不验 UI 呈现 |
| work / governance / process / runtime 内部正文逻辑 | 非范围 | P2 | 只验证 artifact 与它们的接缝,不验下游仓内部所有实现 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和局部不变量 | domain / policy owner | `artifact.validate_creatable`、`version.validate_publishable`、`version.ensure_referenceable`、`baseline.validate_freezable`、`AdoptedRelation::new` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + relation + projection 联动 | backend / domain owner | `CreateArtifact`、`PublishArtifactVersion`、`SupersedeArtifactVersion`、`SetCurrentVersion`、`AdoptArtifactAsEvidence`、`ApproveArtifactVersion`、`CreateBaseline`、`FreezeBaseline` | 主语、版本、关系、freeze、投影链同时成立 |
| 事件链测试 | 验证上游输入与下游消费接缝 | integration / platform owner | process outputs、runtime reports、governance adopted basis、work done proof、conversation notification consume | 输入输出语义一致 |
| 恢复专项测试 | 验证内容不可达、关系失败、projection drift 与 rebuild | architecture / QA | ContentRef recovery、relation retry、baseline browse rebuild、projection rebuild | 真相不丢失、读链可恢复 |
| 投影一致性测试 | 验证 summary / history / browse / notification 与正式真相一致 | backend / QA | current version summary、history lineage、baseline browse frozen members、notification material | 投影只读且与真相一致 |
| 端到端主线测试 | 验证最小制品闭环 | QA / owner | create artifact → publish version；adopt/approve；freeze baseline；rebuild projection | 主干制品闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| Artifact 与 ArtifactVersion 分层 | create artifact 后再 publish version | 集成测试 | 是 | DB / API / lineage |
| ArtifactVersion 是正式引用单位 | work/governance/process/runtime 只消费稳定 version ref | 集成 + 事件链测试 | 是 | refs trace |
| evidence ref 与 adopted/approved 分离 | evidence ref 存在但未 adopted 不得被当 basis | 集成测试 | 是 | relation compare |
| baseline freeze 后不可漂移 | freeze 后新版本产生不影响旧 baseline members | 集成 + 投影一致性测试 | 是 | baseline compare |
| ContentRef 可达性必须成立 | 正文不可达时不得 publish version | 单元 + 集成测试 | 是 | publish error / content check |
| summary / notification 只读 | rebuild 只重建视图不改 Artifact / Version 真相 | 恢复 + 投影一致性测试 | 是 | rebuild trace |
| ImplementationPlan 只是 artifact | plan artifact 不得被误解释成状态对象 | 边界专项测试 | 是 | relation / type check |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | CreateArtifact 创建正式制品主语 | kind / content ref / metadata 合法 | CreateArtifact | Artifact 创建成功 |
| TC-002 | ContentRef 不可达时拒绝 publish version | content_ref 不可用 | PublishArtifactVersion | 返回 `ARTIFACT_CONTENT_UNAVAILABLE` |
| TC-003 | PublishArtifactVersion 成功 | Artifact 已存在 / content 可达 | PublishArtifactVersion | 正式 ArtifactVersion 发布 |
| TC-004 | SupersedeArtifactVersion 后旧版本仍保留 | 已有 published version | SupersedeArtifactVersion | 新版本 current,旧版本仍可追溯 |
| TC-005 | SetCurrentVersion 更新 current pointer | 有多个合法版本 | SetCurrentVersion | current 指向目标正式版本 |
| TC-006 | AdoptArtifactAsEvidence 建立 adopted relation | ArtifactVersion 可引用 | AdoptArtifactAsEvidence | AdoptedRelation 成立 |
| TC-007 | ApproveArtifactVersion 建立 approved relation | ArtifactVersion 可批准 | ApproveArtifactVersion | ApprovedRelation 成立 |
| TC-008 | duplicated relation 被拒绝或去重 | 同一 version/target/relation 重复输入 | Adopt/Approve again | 不产生重复正式关系 |
| TC-009 | CreateBaseline / FreezeBaseline 成功 | 一组 published version 已就绪 | CreateBaseline → FreezeBaseline | frozen baseline 成立 |
| TC-010 | 非 published version 不得进入 baseline | 包含 pending version | FreezeBaseline | 返回 `ARTIFACT_BASELINE_MEMBER_INVALID` |
| TC-011 | frozen baseline 不因新版本发布而漂移 | baseline 已 frozen | publish newer version | 旧 baseline members 不变 |
| TC-012 | summary/history/browse/notification rebuild | 投影损坏 | RebuildArtifactProjection | 只读投影恢复且真相不变 |
| TC-013 | ImplementationPlan artifact 只作为制品引用 | plan artifact 存在 | 下游 consume | 不被当状态对象解释 |
| TC-014 | conversation 只消费 artifact notification material | version published / relation updated | BuildArtifactNotificationView | 只读通知材料成立 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | Artifact/Version 混层 / evidence ref 替代 adopted relation / baseline freeze 失效 / ContentRef 不可达仍发布正式 version | 阻断放行,必须修复 |
| A | 主线可跑但 relation / projection / baseline browse / current pointer 不稳 | 原则上修复后再放行 |
| B | 非关键浏览视图、通知材料或低优先级查询异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 Artifact / ContentRef 逻辑,都必须回归 CreateArtifact 与 ContentRef 可达性检查
- 每次改动 version / lineage / current pointer,都必须回归 PublishArtifactVersion / Supersede / SetCurrentVersion 主线
- 每次改动 adopted / approved relation,都必须回归 governance/work/process 的正式消费边界
- 每次改动 baseline / freeze,都必须回归“新版本发布不影响旧 baseline”
- 每次改动 summary/history/browse/notification,都必须回归 rebuild 与只读边界

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| baseline family / staged baseline 若后续引入 | 测试矩阵需扩充 | TL / 架构 |
| ImplementationPlan kind 继续细化 | runtime/work/治理接缝测试需增加分支 | artifact + runtime + work |
| search backend 若后续外置 | browse/history 测试需调整 | Owner / TL |

### 1.2 本文回答的问题

本文只定义验收裁决门禁:

- 什么条件算通过。
- 什么条件算有条件通过。
- 什么条件算不通过或暂停验收。
- 哪些问题是一票否决。
- 哪些风险可以接受,由谁接受,需要什么证据和后续动作。
- 最终结论如何签署和归档。

本文不重新定义需求、设计、配置、测试用例、实施任务、真实测试结果或发布 runbook。

### 1.3 历史材料处理

旧版 `06-验收标准.md` 只作为历史诊断输入。旧文档中的 CreateArtifact / PublishArtifactVersion / EvidenceRef / FreezeBaseline 少量主线、旧环境矩阵、旧证据口径和旧最终结论占位不得反推本轮验收标准。

### 1.4 证据口径

当前 authoritative evidence id 是 `EV-CAND-ART-*`。正式验收必须保持:

```text
EV-CAND-ART-* -> artifact_path -> report_path -> run_id
```

可逆追溯。不得引用 `latest`,不得用静态 JSON / Markdown、手写表或默认 passed 伪造 evidence。

## 2. 验收目标与范围

> 校准来源:
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 P0/P1/P2 验收范围、非范围和一票否决候选如何收敛。

### 2.1 验收目标

本轮验收目标是证明 `L1-artifact` 作为正式制品真相仓成立,并能阻断 `VF-ART-001~004`。

验收不是证明若干接口“可调用”,而是证明 Artifact fact、version、lineage、baseline、consumable reference / backref、read surface、event relay、maintenance job、配置和证据链能按正式设计闭合。

### 2.2 P0 验收范围

| 范围 | 验收目标 | 关键证据 |
|---|---|---|
| 制品事实承载 | formal fact truth、review anchor、responsibility context 和 automation input intake 成立 | `EV-CAND-ART-CORE-*`;`EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| 制品版本化 | candidate / publish / supersede / current pointer / history retain 成立 | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-STATE-*`;`EV-CAND-ART-IDEMP-*` |
| 制品血缘关联 | formal lineage link、rejection、trace、backref 和 impact summary 成立 | `EV-CAND-ART-LINEAGE-*`;`EV-CAND-ART-QUERY-*`;`EV-CAND-ART-CONSUMER-*` |
| 制品基线冻结 | baseline candidate / freeze / supersede / history audit 只接正式 version | `EV-CAND-ART-BASELINE-*`;`EV-CAND-ART-JOB-*` |
| 制品事实可消费表达 | consumable ref、backref、read surface、handoff 和 no ownership transfer 成立 | `EV-CAND-ART-CONSUME-*`;`EV-CAND-ART-HANDOFF-*`;`EV-CAND-ART-QUERY-*` |
| 配置与运行门禁 | P0 profiles、strict validation、redaction、topic completeness、replay root 和 no silent fallback 成立 | `EV-CAND-ART-CONFIG-*`;`EV-CAND-ART-REDACTION-*`;`EV-CAND-ART-REPORT-*` |

### 2.3 非范围与后置范围

| 项 | 当前裁决 |
|---|---|
| real-like provider selected-run | P1 residual,不得计入 P0 passed evidence |
| `staging-like` / `production-like` / capacity / hard SLO | P1 / P2 residual,无正式阈值前不得作为 P0 pass/fail |
| 真实 upstream / downstream 产品深度集成 | 当前只验 formal seam contract,产品绑定后补 P1 / E2E |
| 高级 dashboard / analytics / derived UX | P2 residual,基础 read surface / report 为 P0 |
| 长期 evidence retention 天数 | operations residual,当前只要求验收与复验关闭周期可追溯 |

### 2.4 一票否决上游来源

| 来源 | 本文落点 |
|---|---|
| `VF-ART-001` 五个核心能力任一节点无法成立 | `VETO-ART-001` |
| `VF-ART-002` 外部正文、运行材料、派生材料或消费副本进入正式 truth 或正式输出面 | `VETO-ART-002`;`VETO-ART-006` |
| `VF-ART-003` version / lineage / baseline 无法稳定形成、追溯、冻结或历史被静默覆盖 | `VETO-ART-003`;`VETO-ART-005` |
| `VF-ART-004` 下游 / query / consumer / job / handoff / replay 可以反写 Artifact truth | `VETO-ART-004` |
| 证据、依赖、配置等验收过程红线 | `VETO-ART-005~009` |

## 3. 验收基线

> 校准来源:
> - `design-calibration/06_acceptance_step_03_baseline.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 design / implementation / core-contracts / config / run / artifact / report / acceptance handoff 基线如何固定。

### 3.1 必须固定的基线

| 基线 | 必填 | 说明 |
|---|---|---|
| design source refs | 是 | `00`~`05` 的具体提交或 digest |
| implementation commit / build id / image digest | 是 | 送验实现版本,不得漂移 |
| core-contracts / `L0-core` source ref | 是 | 允许的 compile-time upstream 基线 |
| P0 profile 与 config digest | 是 | `local-dev`、`ci-test`、`integration-like`、`operations-replay` 中实际用于验收的 profile 和 digest |
| fixture set / replay root | 是 | 必须 run-scoped、去标识化且不使用 `latest` |
| `run_id` | 是 | 固定运行 ID,不得使用 `latest` |
| artifact root | 是 | `artifacts/test/<run_id>` |
| report root | 是 | `reports/runs/<run_id>` |
| acceptance reports | 是 | `reports/acceptance/handoff.md`、`veto-checklist.md`、`open-issues.md`;存在 residual 或有条件通过时还必须有 `risk-acceptance.md` |

### 3.2 不可裁决基线缺口

缺少以下任一项时,不得填写“通过”或“有条件通过”:

- design source refs 未固定。
- implementation commit / build id / image digest 未固定。
- `run_id` 缺失或使用 `latest`。
- raw artifact root 或 run report root 缺失。
- `EV-CAND-ART-*` 无法回指 raw artifact / report / digest。
- acceptance handoff 或 VETO checklist 缺失。
- P0 profile 无法装配或被标记为 passed 但实际 unavailable。

## 4. 进入条件与退出条件

> 校准来源:
> - `design-calibration/06_acceptance_step_04_entry_exit.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“进入条件”“退出条件”“暂停 / 不可裁决条件”和“进入 / 退出来源追溯”小节,了解验收准入和准出如何收敛。

### 4.1 进入条件

- [ ] `00`~`05` design source refs 已固定。
- [ ] implementation commit / build id / image digest 已固定。
- [ ] core-contracts / `L0-core` source ref 已固定。
- [ ] P0 profile、config digest、runtime config source、fixture set / replay root 已固定。
- [ ] `run_id` 已固定且不是 `latest`。
- [ ] `artifacts/test/<run_id>` 下存在 raw suite artifacts、case JSON、stdout/stderr 和 digest。
- [ ] `reports/runs/<run_id>` 下存在 summary、gate-summary、evidence-index、suite reports、redaction-check、dependency-boundary、report-audit。
- [ ] `reports/acceptance/handoff.md` 和 `reports/acceptance/veto-checklist.md` 已生成。
- [ ] 若存在 residual 或有条件通过可能,`reports/acceptance/risk-acceptance.md` 已生成。
- [ ] 当前无未关闭 S 级缺陷,无未复验的 `VF-ART-*` 相关修复。

### 4.2 退出条件

- [ ] 每个 P0 验收项都有通过 / 失败 / 不适用-with-reason 裁决。
- [ ] `EV-CAND-ART-*`、`TC-ART-*`、suite artifact、report path 和 `run_id` 可逆追溯。
- [ ] `VETO-ART-001~009` 均有真实 evidence / defect / report status 支撑未触发。
- [ ] 所有 P0 blocking suite 均有 raw artifact / run report pairing。
- [ ] redaction-check、dependency-boundary、report-audit 均 clean。
- [ ] `release-main-smoke` 证明业务场景级闭环,不是通用测试计数。
- [ ] Query / projection / report / consumer / job / handoff / relay no-write / no-truth-repair 均有证据覆盖。
- [ ] S=0;A 级缺陷已修复并复验,或已按 §13 严格接受。
- [ ] B/R residual、P1/P2 unavailable 均已记录接受人、影响面、后续动作和触发条件。

### 4.3 暂停 / 不可裁决条件

| 触发 | 处理 |
|---|---|
| baseline、`run_id`、raw artifact 或 report root 缺失 | 不进入正式验收 |
| evidence index 缺失、orphan EV、静态造证据 | 暂停或不通过;不得人工补 passed |
| redaction / dependency / report audit failed | 不通过或暂停修复后重验 |
| S 级缺陷存在 | 不通过或暂停修复后重验 |
| 发现设计闭口缺失导致验收项无法绑定正式契约 | 暂停,回写设计后重做受影响 Step |
| P1/P2 unavailable | 不阻断 P0,但必须进入 residual;不得计入 P0 passed |

## 5. 功能验收门禁

> 校准来源:
> - `design-calibration/06_acceptance_step_05_function_gate.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“功能验收门禁表”“功能验收闭环矩阵”“P1 / P2 功能后置边界”“功能验收项停审记录”和“跨功能门禁裁决审计表”小节,了解功能验收如何从五个核心能力、`FR-ART-*`、设计契约、测试用例和证据收敛。

### 5.1 功能验收门禁表

| 验收项 | 主题 | 通过条件 | 失败条件 | 证据 |
|---|---|---|---|---|
| AC-ART-001 | 制品事实纳管成立 | actor、scope、subject、purpose、responsibility context 能形成正式 fact truth | context / input 缺正式 truth;相邻仓状态或正文隐式创造事实 | `EV-CAND-ART-CORE-*`;`EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-002 | 自动化产出事实收束成立 | automation input register / accept 主线成立,runtime 只作 summary/ref | runtime/output body 直接进入 truth;automation bypass command | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-CONSUMER-*` |
| AC-ART-003 | 事实责任与审查语境成立 | review anchor、responsibility assignment、review summary query 成立 | review responsibility 缺 truth anchor;责任 actor 不可追溯 | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-004 | 真相与派生材料区分成立 | preview / report / outbox / handoff 只能呈现 formal refs / summary | body / secret / full sensitive ref 进入 truth 或输出面 | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-OUTBOX-*`;`EV-CAND-ART-REDACTION-*` |
| AC-ART-005 | 稳定版本事实形成 | candidate / publish / supersede / history retain / current pointer 成立 | current truth 被无声覆盖;历史版本被删除 | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*`;`EV-CAND-ART-IDEMP-*` |
| AC-ART-006 | 自动化迭代版本收束 | automation result enters candidate / publish flow | automation 直接改写 current truth | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-IDEMP-*` |
| AC-ART-007 | 版本审查与责任语境 | get version / list versions / review responsibility around version 成立 | version review 无 formal anchor | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-008 | 历史版本可追溯保留 | history / trace / report / archive explanation 成立 | 历史版本不可追溯或被重写 | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-JOB-*` |
| AC-ART-009 | 正式血缘语境建立 | establish lineage link / reject invalid lineage 成立 | trace / event 被当成 lineage truth | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-010 | 自动化产出关系收束 | runtime / external source signals only become formal lineage by explicit flow | consumer 直接创造 lineage truth | `EV-CAND-ART-CONSUMER-*` |
| AC-ART-011 | 血缘审查与影响理解 | lineage summary / preview / report 可审查 | lineage summary 静默退化为 trace 列表 | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-OUTBOX-*` |
| AC-ART-012 | 血缘审计与跨仓消费边界 | trace / backref / event seam point back to formal lineage | backref 不可回指正式 truth | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-CONSUMER-*` |
| AC-ART-013 | 受控版本集合形成 | create baseline candidate / freeze baseline 成立 | membership 未稳定;current version 动态重算 | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-014 | 基线候选与冻结语境收束 | only formal versions enter baseline,temporary material rejected | 外部集合替代 baseline | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-JOB-*` |
| AC-ART-015 | 冻结责任与审查语境 | baseline review / responsibility coherence 成立 | baseline 无 formal review anchor | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-016 | 历史基线可审计与跨仓边界 | baseline history / report / archive handoff 有稳定 membership | baseline report 直接从 current truth 重算 | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-JOB-*` |
| AC-ART-017 | 稳定 Artifact truth 引用表达 | issue consumable reference and stable read surface 成立 | 下游直接消费正文或 current truth | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-QUERY-*` |
| AC-ART-018 | 消费边界与 truth 不转移 | record backref、consumer / sync / archive / observability seam no ownership transfer | 消费方反写 truth | `EV-CAND-ART-CMD-*`;`EV-CAND-ART-CONSUMER-*` |
| AC-ART-019 | 审查责任与协作消费一致 | review / responsibility and downstream consumption point to same truth anchor | 协作消费与审查责任不一致 | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-CONSUMER-*` |
| AC-ART-020 | 跨仓审计回指与事实解释 | trace、report、archive / observability / sync handoff explain source truth | trace / report / handoff 无来源 | `EV-CAND-ART-QUERY-*`;`EV-CAND-ART-JOB-*` |

任一 `AC-ART-001~020` 失败时,最终结论不得为“通过”。若失败同时命中 `VF-ART-001~004` 或 `VETO-ART-*`,不得风险接受。

## 6. 数据边界与架构红线验收

> 校准来源:
> - `design-calibration/06_acceptance_step_06_data_arch_redlines.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“Artifact 数据红线表”“数据边界闭环矩阵”“不得由本仓保存的数据清单”“P1 / P2 防污染规则”和“跨红线审计表”小节,了解数据边界、truth ownership 和架构红线如何收敛。

### 6.1 数据红线

| 红线 | 主题 | 必须成立 | 禁止情况 |
|---|---|---|---|
| RL-ART-001 | Artifact truth 独立归属 | Artifact fact / version / lineage / baseline / consumable backref 由本仓正式承载 | 相邻仓 truth、运行正文或消费副本成为事实来源 |
| RL-ART-002 | sibling truth 不入仓 | work / process / governance / conversation / workspace / archive / observability / method / runtime / capability 主 truth 不入仓 | 任一相邻仓正文、主 truth 或私有状态被保存为 Artifact truth |
| RL-ART-003 | 外部正文禁止入 truth | 外部正文只能变成 ref / safe summary / snapshot / marker | raw body、full sensitive ref、runtime output body、tool output body、method 正文进入 truth / report / handoff |
| RL-ART-004 | 版本 truth 不无声覆盖 | current pointer、history、candidate、supersede 和 duplicate replay 可追溯 | current truth 被静默覆盖、历史版本被删除或 replay 重算 current truth |
| RL-ART-005 | 血缘 truth 只锚正式版本 | lineage 只能锚定正式 fact / version | trace、event、tool result、runtime signal 或私有追溯链补造 lineage |
| RL-ART-006 | baseline 只收正式 version | baseline candidate、freeze、supersede 和 history audit 只接正式 versions | 非正式材料、临时清单、发布说明或 current latest 替代 baseline |
| RL-ART-007 | consumable ref 不转 ownership | consumer / sync / archive / observability 只能引用、展示、封存、观测或同步正式 truth | 消费方复制、接管、重建或反写 Artifact truth |
| RL-ART-008 | query / projection / report no-write | query、projection、report、reconciliation、maintenance 只能读 truth 或写派生 marker | query refresh / rebuild / repair、report rewrite truth、projection 变成 truth source |
| RL-ART-009 | consumer / job no-truth-repair | inbound consumer 只写 snapshot / marker / receipt,public job 只写 derived / report / handoff | consumer 或 job 直接创建、修复、批准、关闭或覆盖核心 truth |
| RL-ART-010 | compile-time 依赖裁剪 | 除 `L0-core/core-contracts` 外,无 sibling compile-time dependency | `L1-*`、`L3-*`、`L4-*`、`L5-*` sibling 进入 Cargo path 依赖 |
| RL-ART-011 | P1 / P2 不污染 P0 | real-like / production-like / capacity / advanced analytics 只作为 residual / future | P1 / P2 结果替代 P0 fake / controlled / disabled 证据,或未运行被当成通过 |

### 6.2 数据边界验收项

| 验收项 | 主题 | 证据 | 裁决 |
|---|---|---|---|
| AC-ART-021 | Artifact truth 归属正确 | `EV-CAND-ART-CORE-*`;`EV-CAND-ART-STATE-*`;`reports/runs/<run_id>/suites/contract-domain-fast.md` | 失败则不通过 |

## 12. 缺陷分级、复验与放行规则

> 校准来源:
> - `design-calibration/06_acceptance_step_12_defects_retest_release.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“缺陷分级表”“S 级阻断判定表”“修复后复验规则”“放行规则”“缺陷关闭证据清单”和“缺陷 / 复验停审记录”小节,了解缺陷如何影响验收结论、复验和放行。

### 12.1 缺陷分级

| 级别 | 定义 | 对结论的影响 |
|---|---|---|
| S | 命中 VETO、P0 truth / boundary / security / evidence 红线 | 未关闭时只能“不通过”或暂停验收;不可风险接受 |
| A | P0 blocking suite 或主链证明失败,但未直接命中 VETO/S | 未关闭且未批准接受时不得“通过”;通常阻断 release |
| B | 非 P0、不影响当前主证据链或报告可读性 / selected-run 问题 | 不阻断 P0;可进入有条件通过的风险清单 |
| R | 当前范围外或未来能力 residual | 不阻断 P0;必须进入风险接受或后续跟踪 |

### 12.2 修复后复验

修复后必须至少复跑原失败 `TC-ART-*`、同 family 代表用例、相关 suite/check 和必要的 redaction / dependency / report audit。S 级和触及 release 主链的 A 级修复必须触发全量或近全量 P0 regression。

| 缺陷触发面 | 必跑用例 / suite | 必跑 check |
|---|---|---|
| contracts / typed ref / DTO / metadata | 原失败 `TC-ART-*` + `contract-domain-fast` | report pairing |
| domain / state / policy | 原失败 case + same state family + `contract-domain-fast` | redaction if output changed |
| command / UoW / outbox / stored result | 原失败 command family + `service-flow-fast`;相关 `TC-ART-IDEMP-*` | report pairing;redaction if output changed |
| query no-write / read surface / degraded | 原失败 query + representative no-write cases + `service-flow-fast` | write audit;redaction |
| consumer / worker | 原失败 consumer + duplicate / unsupported / delayed cases + `entry-worker-job` | redaction |
| outbox / publisher / relay facade | 原 outbox / relay case + `entry-worker-job` + `operations-replay-core` | report pairing;redaction |
| public operations job / handoff / export | 原 job case + duplicate/no truth repair cases + `operations-replay-core` | redaction;report pairing |
| config / runtime builder | 原 config case + `config-redline`;必要时 `infra-runtime-fake` | report pairing |
| redaction leak | leak fixture + `redaction-boundary` | `check_redaction.sh` |
| dependency boundary | dependency case + `dependency-boundary` | `check_dependency_boundary.sh` |
| evidence / report integrity | `report-generation-audit`;受影响 suite sample | no static evidence;artifact pairing |
| release smoke closure | original scenario + `release-main-smoke` + affected lower suite | release checks |

### 12.3 放行规则

| 条件 | 是否可放行 |
|---|---|
| 存在未关闭 S 级缺陷 | 否 |
| 存在任一 VETO 命中 | 否 |
| 存在未关闭 A 级缺陷 | 通常否;仅在不影响 P0 truth、不命中 VETO/S、证据完整且有正式接受人时可有条件通过 |
| 仅存在 B/R residual | 可有条件通过,但必须进入 risk acceptance |
| P1 selected-run unavailable | 可记录 residual,不得计入 P0 passed evidence |
| evidence/report 缺失、orphan EV、static pass、缺 raw artifact | 否 |

### 12.4 缺陷关闭证据

S/A 缺陷关闭必须包含 defect ref、分级理由、失败前 `run_id`、失败 artifact/report、修复说明、复验 `run_id`、复验 suite/check report、关联 `EV-CAND-ART-*`、report path 和防回归说明。B/R 缺陷至少必须有影响面、接受人、后续动作和触发条件。

## 13. 风险接受与遗留项

> 校准来源:
> - `design-calibration/06_acceptance_step_13_risk_acceptance.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“可接受 Residual 风险表”“严格受限的 A 级接受条件”“不可风险接受项”“风险接受文件要求”“风险到后续文档同步矩阵”和“风险接受停审记录”小节,了解有条件通过所需的 residual 结构和不可接受边界。

### 13.1 可接受 residual

以下风险可在不影响 P0 truth 和证据完整时进入 residual,但不得计入 P0 passed evidence:

| Risk ID | 风险 | 范围 | 后续承接 |
|---|---|---|---|
| RISK-ART-001 | `p1-real-like-selected-run` 不进入当前 P0 主链 | P1 | 产品 / 环境可用后执行 selected-run |
| RISK-ART-002 | 真实 upstream seam 行为未覆盖 | P1 / product binding | 产品绑定后补 upstream selected-run / E2E seam tests |
| RISK-ART-003 | 真实 archive / observability / sync target 未覆盖 | P1 / operations | downstream target 确认后补 handoff integration tests |
| RISK-ART-004 | `staging-like` / `production-like` 未执行 | P1 / P2 | 建立 staging / production-like profile 后补验收 |
| RISK-ART-005 | production-like capacity / hard P95 / SLA 未覆盖 | P2 / performance | 建立负载模型和阈值后重审 `05/06` |
| RISK-ART-006 | 跨仓完整 E2E 协同未覆盖 | P1 / product E2E | 独立建立跨仓 E2E 方案 |
| RISK-ART-007 | 长期 evidence retention 天数未固定 | operations / compliance | 在运维标准中定义保留期、介质、清理和恢复规则 |
| RISK-ART-008 | 高级 dashboard / analytics / derived UX 未覆盖 | P2 / UX | 产品需求明确后补 UI / analytics 验收 |

### 13.2 严格受限的 A 级接受

A 级缺陷只能逐项接受。必须同时满足:

- 不命中 `VETO-ART-*`。
- 不影响 P0 truth、ownership、redaction、dependency 和 evidence integrity。
- 已有 `EV-CAND-ART-*` 或 report 足以证明 P0 门禁可裁决。
- `reports/acceptance/risk-acceptance.md` 中 owner、acceptor、deadline_or_trigger、follow_up_ref 和 p0_contamination_check 完整。
- 后续补验 suite/check 或设计 / 实施文档动作可验证。

### 13.3 不可风险接受项

以下问题不得被风险接受覆盖:

- `VETO-ART-001~009` 任一命中。
- S 级缺陷。
- `VF-ART-001~004` 命中。
- query no-write 失败。
- public job / `PublishPendingArtifactRelays` truth repair。
- redaction leak。
- dependency boundary failed。
- evidence index 静态造证据 / orphan EV / missing raw artifact。
- P0 config silent fallback、partial facade、forbidden override。
- P0 profile unavailable but marked passed。
- accepted truth 缺 trace / audit / outbox / stored result。

### 13.4 `risk-acceptance.md` 字段

每项风险必须包含 `risk_id`、`scope`、`impact`、`acceptance_reason`、`evidence_refs`、`owner`、`acceptor`、`deadline_or_trigger`、`follow_up_ref` 和 `p0_contamination_check`。缺任一字段时,不能作为有条件通过依据。

## 14. 最终结论与签署

> 校准来源:
> - `design-calibration/06_acceptance_step_14_final_decision_signoff.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“最终结论表”“结论判定矩阵”“签署表”“签署含义表”“最终验收包要求”和“最终结论停审记录”小节,了解最终结论和签署口径如何从门禁、VETO、缺陷、证据和风险接受收敛。

### 14.1 三值结论

最终结论只允许:

- 通过
- 有条件通过
- 不通过

禁止使用“基本通过”“原则通过”“大体没问题”“待观察通过”等模糊结论。

### 14.2 结论判定矩阵

| 条件 | 通过 | 有条件通过 | 不通过 / 暂停 |
|---|---|---|---|
| P0 AC-ART 门禁 | 全部通过 | 全部通过 | 任一失败则不通过 |
| `VETO-ART-001~009` | 全部未命中 | 全部未命中 | 任一命中则不通过 |
| S 级缺陷 | 0 | 0 | >0 则不通过 |
| A 级缺陷 | 0 | 已接受且不影响 P0 truth / evidence | 未接受或影响 P0 truth 则不通过 |
| B/R residual | 0 或不影响 | 已记录并接受 | 未记录且影响结论则不得通过 |
| evidence integrity | 完整且 audit clean | 完整且 audit clean | 缺失、伪造、orphan EV、static pass 则不通过 |
| redaction / dependency | clean | clean | failed 则不通过 |
| config / profile | P0 profile 可用且无 silent fallback | P0 profile 可用且无 silent fallback | unavailable but passed / forbidden override 则不通过 |
| P1/P2 unavailable | 不适用或无影响 | 已记录 residual | 被错误写成 P0 pass/fail 则不通过 |
| `reports/acceptance/*` | handoff / veto / risk / open issues 完整 | risk acceptance 完整 | 缺 handoff / veto checklist / required risk acceptance 则暂停或不通过 |

### 14.3 最终验收包

正式验收包必须至少包含:

- `reports/acceptance/handoff.md`
- `reports/acceptance/veto-checklist.md`
- `reports/acceptance/open-issues.md`
- 条件通过或 residual 存在时的 `reports/acceptance/risk-acceptance.md`
- `reports/runs/<run_id>/evidence-index.md`
- `reports/runs/<run_id>/gate-summary.md`
- `reports/runs/<run_id>/redaction-check.md`
- `reports/runs/<run_id>/dependency-boundary.md`
- `reports/runs/<run_id>/report-audit.md`

### 14.4 签署表

| 角色 | 姓名 / 责任 | 必须确认 | 结论 | 日期 |
|---|---|---|---|---|
| Owner / 业务负责人 | `<name>` | 验收目标、P0/P1/P2 范围、业务 residual 和进入下一阶段影响 | `<signoff>` | `<date>` |
| 架构负责人 | `<name>` | truth ownership、依赖裁剪、数据边界、跨仓 seam、VETO 和不可接受风险 | `<signoff>` | `<date>` |
| 测试负责人 | `<name>` | P0 suite、`EV-CAND-ART-*`、raw artifact/report pair、缺陷、复验和 report audit | `<signoff>` | `<date>` |
| 实施负责人 | `<name>` | 送验 commit / build / config、实现范围、known technical risk 和修复承诺 | `<signoff>` | `<date>` |
| 运维 / 安全 / 合规负责人 | `<name>` | redaction、dependency、profile、handoff、evidence retention 和 compliance residual | `<signoff>` | `<date>` |
| 验收负责人 | `<name>` | 最终结论、VETO checklist、risk acceptance、open issues 和签署材料一致 | `<signoff>` | `<date>` |

签署不自动接受风险。风险必须在 `reports/acceptance/risk-acceptance.md` 逐项记录并由接受人确认。

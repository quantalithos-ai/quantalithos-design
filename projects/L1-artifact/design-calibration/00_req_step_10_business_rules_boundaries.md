## 3. 开工确认 / 必读文档:先思考

### 3.1 本步目标诊断

Step 10 要把 Step 2 的仓边界、Step 7 的核心能力闭环和 Step 9 的功能需求,转成需求层硬规则。这里的“规则”不是字段、数据库约束、接口参数、事件 schema、service 校验逻辑或验收用例,而是用来保护 Artifact truth 不串线、不被隐式改写、不被相邻仓反向定义的业务约束。

本步需要优先确认三件事:

- 哪些文档是规则来源,哪些只能作为历史材料或污染审计线索。
- 当前规则应按哪些能力节点组织,并如何回指 FR-ART-001~020。
- 哪些内容必须后置到 Step 11 数据归属、Step 12 接口依赖、Step 13 NFR、Step 14 验收或后续设计文档。

### 3.4 初步关注点

后续 Step 10 需要重点防止以下混层:

- 把 Artifact kind、relation kind、version 状态、baseline members 写成字段表或数据归属矩阵,而不是需求层规则。
- 把 `CreateArtifact`、`PublishVersion`、`AddRelation`、`GetLineage`、`CreateBaseline` 等动作写成接口或命令规则。
- 把 hash、pin、tampered、不可变、完整性证明写成实现校验、算法、存储约束或测试用例。
- 把 work / process / governance / conversation / workspace / archive / observability / method-library / runtime / capability-hub 的 truth 写成本仓规则。
- 把 `L0-bus` 事件协作写成 Artifact truth 存储、正文承载或状态变更来源。
- 把搜索、浏览、projection、报表、通知、SDK / console / sync 通道写成核心规则前置。
- 把 P95、容量、恢复时间、可用性、benchmark 或 Given-When-Then 提前写成业务规则。
- 生成无法回指 FR-ART-001~020 或 Step 2 / 6 边界的孤儿规则。

### 3.5 规则类型初步使用口径

| 规则类型 | Step 10 中的初步用途 | 当前禁区 |
|---|---|---|
| 不变量 | 表达 Artifact truth、version、lineage、baseline、消费引用等必须始终成立的业务条件。 | 不写数据库唯一约束、字段必填或 Rust 类型。 |
| 禁止行为 | 表达不得隐式创建、覆盖、复制、反推、补造或由相邻仓拥有 Artifact truth。 | 不写 API 禁用清单或 handler 分支。 |
| 显式变化 | 表达正式事实、版本、关系、基线和消费边界变化必须显式发生。 | 不写状态机编码、事务流程或事件 payload。 |
| 边界约束 | 表达本仓不拥有相邻仓 truth,相邻仓也不能反向定义 Artifact truth。 | 不写数据归属矩阵或接口依赖表。 |
| 治理约束 | 仅在 Artifact 功能确实需要治理前置或治理引用时使用。 | 不把 governance Gate / approval truth 写成本仓所有。 |
| 审计约束 | 仅用于正式事实变化、消费回指、历史版本 / 基线追溯等需求层审计要求。 | 不写审计日志 schema、observability trace、指标或告警实现。 |

## 15. 模块 5 制品事实可消费表达规则:先思考

### 15.1 本模块规则目标

模块 5 只讨论“制品事实可消费表达”下的业务规则。它承接模块 1~4 已确认的正式 Artifact fact、稳定版本事实、正式血缘事实和 Artifact baseline truth,把 FR-ART-017~020 从功能能力转成需求层硬约束:相邻角色和系统必须稳定引用同一 Artifact truth;消费边界不能导致 truth 转移、复制或重建;审查意见、维护责任和协作消费必须围绕同一制品事实语境成立;跨仓消费必须能回指正式 Artifact truth 并解释消费基于哪份 fact、version、lineage 或 baseline。

本模块不写 API schema、DTO、endpoint、SDK 方法、event name、payload、subscription、projection、read model、workspace view、console page、search / browse、archive package、observability log、metric、sync 协议、权限策略、缓存、分页、NFR 或验收用例。规则候选只表达消费边界层面的必须成立、禁止发生、必须显式发生或不能越界的业务约束。

## 17. 外围增强 / 边界外规则审计:先思考

## 10. 业务规则与边界约束

本章规则用于保护 `L1-artifact` 作为可审计制品真相仓的需求边界。规则只表达业务上必须成立、不得发生、必须显式发生或不能越界的约束,不定义数据库结构、对象字段、接口协议、事件 schema、NFR、验收用例或实现流程。

业务规则围绕五个核心能力节点组织:制品事实承载、制品版本化、制品血缘关联、制品基线冻结、制品事实可消费表达。外围增强只作为规则承接和后续处理项保留,边界外 truth 不进入本仓业务规则对象。

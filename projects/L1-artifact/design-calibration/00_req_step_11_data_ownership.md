## 3. 开工确认 / 必读文档:先思考

### 3.1 本步目标诊断

Step 11 要把 Step 2 的仓级边界、Step 7 的五个核心能力、Step 9 的功能需求和 Step 10 的业务规则,转成需求层数据归属结论。这里的数据归属不是对象模型、字段表、数据库设计或接口 payload,而是回答四类问题:

- 哪些数据由 `L1-artifact` 拥有正式 truth。
- 哪些数据只是为稳定消费保留的快照。
- 哪些数据只是指向外部对象或外部正文的引用。
- 哪些外部正文、运行材料、视图材料或相邻仓 truth 明确不得保存正文。

本步首先需要确定必读文档和禁写边界。后续再按能力节点逐个收敛数据项,并在每个能力节点后停审。

### 3.4 初步关注点

后续 Step 11 需要重点防止以下混层:

- 把数据归属表写成 Artifact / Version / Relation / Baseline 的字段清单、对象模型或数据库表。
- 把 Artifact kind、relation kind、version state、baseline members、hash、pin、quality_tags 写成字段和值域,而不是需求层数据项类别。
- 把 `CreateArtifact`、`PublishVersion`、`AddRelation`、`GetLineage`、`CreateBaseline` 等动作产生的输入输出写成接口 payload。
- 把 work、process、governance、conversation、workspace、archive、observability、method-library、runtime、capability-hub 的正文写成本仓真相数据。
- 把 runtime trace、tool result、model context、observability record、workspace view、archive package 或 event material 写成 Artifact truth。
- 把搜索、浏览、projection、报表、通知、SDK、console、sync 数据提前写成正式核心数据归属。
- 把存储后端、缓存、TTL、保留期、归档策略、outbox、projection rebuild 或 repo / service / port 写入本章。
- 生成无法回指 FR-ART-001~020、BR-ART-001~025 或 Step 2 / Step 6 边界的数据项。

### 3.5 数据类型初步使用口径

| 数据类型 | Step 11 中的初步用途 | 当前禁区 |
|---|---|---|
| 真相数据 | 表达 `L1-artifact` 拥有正式 truth 的 Artifact fact、version fact、lineage truth、baseline truth 和消费回指语境。 | 不写字段、状态机、数据库表、对象结构或实现生命周期。 |
| 快照数据 | 表达来自相邻仓或本仓派生表达、仅服务稳定消费 / 审查 / 追溯解释的摘要、目录、读侧材料。 | 不把快照写成新的业务 truth,不写 projection / cache 实现。 |
| 引用数据 | 表达本仓只保存对外部对象、外部语境或外部正文的引用关系,不拥有正文真相。 | 不写外部对象字段,不接管外部对象生命周期。 |
| 禁止保存正文 | 表达 work、process、governance、conversation、workspace、archive、observability、method-library、runtime、capability-hub 等外部正文不得进入本仓。 | 不把“禁止保存”扩展成接口拒绝码、存储策略或审计实现。 |

本模块只处理“制品事实承载”能力下的数据归属候选。它承接 FR-ART-001~004 和 BR-ART-001~005,回答正式 Artifact fact、Artifact 正文 / 内容事实、自动化输入收束语境、责任 / 审查语境、派生材料和相邻仓正文如何归属。

当前不处理版本事实、血缘事实、基线事实或跨仓消费回指的完整数据归属;这些分别进入后续模块 2~5。

| 输入 | 对模块 1 的意义 | 当前禁区 |
|---|---|---|
| FR-ART-001 正式制品事实纳管 | 需要识别 Artifact fact 作为本仓 truth 入口。 | 不写 `CreateArtifact`、上传接口、对象字段或状态。 |
| FR-ART-002 自动化产出事实收束 | 需要识别自动化产出进入 Artifact truth 前后的数据边界。 | 不写 runtime trace、tool result、capability result 的 schema 或执行记录。 |
| FR-ART-003 制品事实责任与审查语境 | 需要识别责任 / 审查围绕 Artifact fact 的需求层数据语境。 | 不写 owner / reviewer 字段、权限模型、审批流或 reviewer 动作。 |
| FR-ART-004 制品真相与派生材料区分 | 需要识别派生材料、附件、日志、视图、归档和观测材料不能替代 Artifact truth。 | 不写派生材料存储、预览、projection、归档包或观测日志结构。 |
| BR-ART-001~005 | 约束正式 fact 入口、自动化显式收束、审查责任锚点、派生材料边界和相邻仓消费边界。 | 不把规则重写为字段约束、接口约束或验收项。 |

### 7.2 真相数据候选诊断

模块 1 的真相数据候选应围绕“本仓拥有的正式制品事实入口”收束,不能把外部执行材料、视图材料或相邻仓状态一并纳入。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 正式 Artifact fact | 应进入真相数据候选。 | BR-ART-001 要求后续版本、血缘、基线、审查和跨仓消费只能围绕正式 Artifact fact 展开。 | 写成需求层事实语境,不写 Artifact 聚合字段。 |
| Artifact 正文 / 内容事实 | 应进入真相数据候选,但粒度要谨慎。 | Step 2 明确本仓承载 Artifact 正文;FR-ART-001 要求平台产出收束为正式 Artifact truth。 | 不写正文 schema、内容类型、URI、hash、大小或存储后端。 |
| Artifact fact 的正式纳管语境 | 可进入真相数据候选。 | FR-ART-001 / BR-ART-001 需要判断材料是否已经进入正式事实入口。 | 不写创建命令、导入流程或状态机。 |
| 自动化产出显式收束语境 | 可进入真相数据候选或边界语境候选。 | BR-ART-002 要求自动化产出要成为 truth 时必须显式事实收束。 | 不把 runtime output 本身写成本仓 truth。 |
| 制品事实责任 / 审查锚点语境 | 可进入真相数据候选。 | FR-ART-003 / BR-ART-003 要求审查、负责和维护面对同一 Artifact fact。 | 不写 actor 字段、权限关系、审批状态或 reviewer 工作流。 |

### 7.3 快照数据候选诊断

模块 1 的快照候选应只服务稳定消费、审查和追溯解释,不得形成新的业务 truth。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 派生展示摘要 / 预览摘要 | 可作为快照候选或后置外围候选。 | BR-ART-004 允许派生材料辅助展示或审计,但不得替代 Artifact fact。 | 模块 1 若写入,只能作为派生快照;具体预览 / projection 后置。 |
| 审查 / 责任显示摘要 | 可作为快照候选。 | 审查和责任需要面对同一 fact,但显示摘要不应成为新 truth。 | 不写 reviewer 字段、审批流程或 UI 卡片。 |
| 自动化产出来源摘要 | 可作为快照候选或引用候选,需谨慎。 | 自动化材料可作为事实收束输入线索,但 runtime / tool truth 不归 artifact。 | 不写 tool result 正文、trace 结构或模型上下文。 |
| 相邻仓上下文摘要 | 暂不作为模块 1 主数据项,优先后置到模块 5 或外围审计。 | work / process / governance 等上下文通常服务消费和协作,不是 Artifact fact 本体。 | 只在必要时作为快照,不得拥有相邻仓 truth。 |

### 7.4 引用数据候选诊断

模块 1 的引用候选用于说明 Artifact fact 可以关联外部语境,但不接管外部对象正文或生命周期。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 外部 work / process / governance 语境引用 | 可作为引用候选,但不是本模块核心 truth。 | Step 6 允许按需消费 work / process / governance 引用;BR-ART-005 禁止相邻仓反向定义 Artifact fact。 | 不写 WorkItem、Activity、Gate 正文或状态。 |
| 外部 identity / actor 引用语境 | 可作为引用候选或后置项。 | FR-ART-003 需要责任 / 审查语境,但 identity truth 不归 artifact。 | 不写成员资料、角色定义、认证授权或权限模型。 |
| 外部 method-library 定义引用 | 可作为引用候选或待后续审计。 | Step 2 提到 method-library 可定义 work product / artifact kind 语义来源,但不拥有 artifact 实例 truth。 | 不写 MethodContent、WorkProductDefinition 正文或 kind 枚举值。 |
| 外部正文引用 | 可作为引用候选,并要配套禁止保存正文。 | Artifact fact 可能由外部材料收束而来,但外部正文不应被本仓无边界吸收。 | 写引用关系,不写外部正文内容。 |

### 7.5 禁止保存正文候选诊断

模块 1 必须显式写出不得保存或不得当作本仓 truth 的正文类型,否则只写真相数据会无法守住边界。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 运行日志、工具结果、model context、capability result 正文 | 应进入禁止保存正文候选或禁止替代 truth 候选。 | BR-ART-002 / BR-ART-004 要求自动化产出存在本身不形成 Artifact fact,派生材料不得替代 truth。 | 可以作为输入线索或引用,不能作为 Artifact fact 正文。 |
| workspace 视图、对话显化、预览材料正文 | 应进入禁止保存正文候选。 | Step 2 明确 conversation / workspace 不拥有 Artifact 正文;BR-ART-004 禁止视图替代 fact。 | 不写 UI / preview / view schema。 |
| archive package、observability record 正文 | 应进入禁止保存正文候选。 | archive / observability 可消费或记录,但不拥有活跃 Artifact truth 或语义血缘。 | 归档包和观测记录后置相邻仓或 Step 12 / 13。 |
| work、process、governance 正文 | 应进入禁止保存正文候选。 | Step 2 / 6 明确这些仓拥有各自业务 truth;BR-ART-005 禁止相邻仓反向定义 Artifact fact。 | 不写项目、活动、Gate、Policy、AIIA / SoA 治理结论正文。 |
| method-library 定义正文 | 应进入禁止保存正文候选或外部引用候选。 | method-library 可提供定义来源,但定义正文不属于 Artifact 实例 truth。 | 不写标准原文、模板正文或方法定义正文。 |

### 7.6 取舍判断

| 取舍项 | 当前判断 | 原因 |
|---|---|---|
| 是否把 `Artifact` 对象作为单一真相数据项 | 不直接采用。 | 容易变成对象模型;应拆成正式 Artifact fact、Artifact 正文 / 内容事实和正式纳管语境等需求层数据项。 |
| 是否把 Artifact kind 写入模块 1 | 暂不作为模块 1 核心数据项。 | kind 更像定义来源、分类语义或后续规则 / 数据候选,且 method-library 可能提供定义来源;不可在本步写枚举值。 |
| 是否把 owner / reviewer 写入模块 1 | 不写字段,只保留责任 / 审查锚点语境候选。 | 责任语境需要被表达,但身份资料、角色定义和权限模型不属于 artifact truth。 |
| 是否把自动化产出正文直接写成本仓 truth | 不采用。 | 自动化材料必须显式收束后才成为 Artifact fact;runtime / tool / model 正文不能自动进入本仓。 |
| 是否把派生材料列为快照数据 | 谨慎采用。 | 派生材料可辅助展示、审计或消费,但不得形成 truth;若写入需明确“不作为核心 truth”。 |

### 7.7 下一步写入建议

模块 1 再写入应形成制品事实承载数据归属表,建议控制在需求层数据项粒度,至少覆盖:

1. 正式 Artifact fact。
2. Artifact 正文 / 内容事实。
3. Artifact fact 正式纳管语境。
4. 自动化产出显式收束语境。
5. 制品事实责任 / 审查锚点语境。
6. 派生材料摘要 / 展示摘要。
7. 外部语境引用。
8. 外部正文和运行 / 视图 / 归档 / 观测材料禁止保存正文。

再写入时必须为每个数据项补充:

- 数据类型:真相数据、快照数据、引用数据或禁止保存正文。
- 归属说明:一句需求层归属判断。
- 生命周期口径:一句需求层存在 / 变化 / 退出判断。
- FR-ART / BR-ART 映射。
- 边界来源和后续承接。

当前仍不得写字段、字段类型、数据库表、接口 payload、事件 schema、配置、NFR、验收或正式 `00-需求文档.md`。

## 9. 模块 2 制品版本化数据归属:先思考

### 9.1 模块输入范围

本模块只处理“制品版本化”能力下的数据归属候选。它承接模块 1 已确认的正式 Artifact fact、Artifact 正文 / 内容事实和自动化产出显式收束语境,并继续回答 Artifact version fact、候选修订、替代语境、历史版本事实和自动化再生成材料如何归属。

当前不处理血缘关系、基线成员集合或跨仓消费回指的完整数据归属;这些分别进入后续模块 3~5。当前也不写版本字段、版本号格式、current 标记、状态枚举、发布命令、并发策略、保留周期、数据库结构或接口协议。

| 输入 | 对模块 2 的意义 | 当前禁区 |
|---|---|---|
| 模块 1 正式 Artifact fact | 版本事实必须建立在已纳管 Artifact fact 之上,不能从临时材料直接形成版本 truth。 | 不回写事实入口字段、正文 schema 或创建接口。 |
| FR-ART-005 稳定版本事实形成 | 需要识别 Artifact 的修订、更新或替代如何形成可区分的稳定版本事实。 | 不写 version 字段、版本号算法、current flag 或存储唯一约束。 |
| FR-ART-006 自动化迭代版本收束 | 需要识别自动化再生成结果进入受控版本语境前后的数据边界。 | 不写 runtime job、tool output、模型上下文、能力执行记录或自动合并策略。 |
| FR-ART-007 版本审查与责任语境 | 需要识别审查、负责和维护面对确定版本时的数据语境。 | 不写 reviewer 字段、审批状态、权限模型或治理流程。 |
| FR-ART-008 历史版本可追溯保留 | 需要识别历史版本事实与归档、视图、观测和相邻仓状态之间的边界。 | 不写保留周期、归档策略、备份方案、不可变存储或验收指标。 |
| BR-ART-006~010 | 约束稳定版本事实、禁止无声覆盖、自动化再生成入版本语境、确定版本引用和历史版本审计。 | 不把规则重写为字段约束、状态机、接口约束或测试用例。 |

### 9.2 真相数据候选诊断

模块 2 的真相数据候选应围绕“正式 Artifact fact 的稳定版本事实”收束。版本化不能被写成单个字段或发布动作,也不能让新内容、自动化输出或外部状态直接覆盖既有版本 truth。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| Artifact version fact | 应进入真相数据候选。 | FR-ART-005 / BR-ART-006 要求修订、更新或替代形成可区分的稳定版本事实,后续引用、比较、血缘和基线不能依赖可变正文。 | 写成需求层版本事实,不写版本号格式、字段或状态机。 |
| 修订 / 更新 / 替代进入版本语境 | 应进入真相数据候选。 | BR-ART-007 要求新内容、候选修订、替代结果或系统接收的更新不得无声覆盖既有版本。 | 写成显式版本化语境,不写发布命令、diff、merge 或并发策略。 |
| 候选修订语境 | 可进入真相数据候选。 | FR-ART-007 / BR-ART-009 要求能区分当前被引用版本、候选修订和被替代版本的责任语境。 | 不写候选状态枚举、审批流程或工作流。 |
| 被替代版本语境 | 可进入真相数据候选。 | FR-ART-005 / FR-ART-008 要求替代发生后仍能定位被替代版本,并解释后续引用和审计。 | 不写 current 标记、指针字段或迁移实现。 |
| 当前被引用版本语境 | 可进入真相数据候选。 | BR-ART-009 要求审查、负责、维护和项目 / 领域引用锚定确定版本。 | 不写引用字段结构、外部消费协议或权限模型。 |
| 自动化再生成显式入版本语境 | 可进入真相数据候选。 | FR-ART-006 / BR-ART-008 要求自动化再生成结果要成为制品事实时必须进入受控版本语境。 | 不把运行结果正文、tool result 或模型上下文写成版本 truth。 |
| 历史 Artifact 版本事实 | 应进入真相数据候选。 | FR-ART-008 / BR-ART-010 要求历史版本事实稳定保留,供审计、冻结和下游消费定位。 | 不写保留周期、物理归档、备份或不可变存储实现。 |

### 9.3 快照数据候选诊断

模块 2 的快照候选只能辅助比较、审查、解释和消费定位,不得形成新版本 truth,也不得替代历史版本事实。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 版本比较摘要 | 可作为快照候选或后置外围候选。 | 修订、替代和审查需要解释差异,但差异摘要不是版本 truth 本身。 | 不写 diff 算法、比较字段、展示结构或索引。 |
| 当前引用显示摘要 | 可作为快照候选。 | 项目 / 领域或审查语境可能需要稳定显示当前引用的确定版本。 | 不写消费 API、读模型或 workspace view。 |
| 候选修订说明摘要 | 可作为快照候选。 | 候选修订需要被审查和责任定位,但说明摘要不能替代候选修订的版本语境。 | 不写审批意见正文、review workflow 或状态枚举。 |
| 自动化再生成来源摘要 | 可作为快照候选。 | 自动化再生成进入版本语境时,来源摘要可解释为什么产生候选版本。 | 不写 runtime trace、tool output、model context 或 capability result 正文。 |
| 历史版本展示摘要 | 可作为快照候选。 | 审计、冻结和下游消费可需要展示历史版本的稳定摘要。 | 不写归档包、观测记录或历史正文复制策略。 |

### 9.4 引用数据候选诊断

模块 2 的引用候选用于说明版本事实可以被外部审查、责任、项目、领域或自动化语境引用,但本仓不接管这些外部对象的正文和生命周期。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 外部审查 / 责任语境引用 | 可作为引用候选。 | FR-ART-007 要求审查、负责和维护面对确定版本,但身份、角色和治理裁决正文不归 artifact。 | 不写 identity、governance 或审批正文。 |
| 项目 / 领域引用语境 | 可作为引用候选。 | FR-ART-005 / FR-ART-008 要求后续引用定位确定版本,但项目和领域 truth 属于相邻仓。 | 不写 project、domain、work 或 process 正文。 |
| 自动化再生成来源引用 | 可作为引用候选或快照候选。 | 自动化输出进入版本语境前可能需要保留来源引用,但 runtime / capability truth 不归本仓。 | 不写运行日志、工具结果或模型上下文正文。 |
| 外部历史审计材料引用 | 可作为引用候选。 | 历史版本可被审计材料引用,但 archive、observability 或外部报告正文不改写版本 truth。 | 不写归档包正文、观测正文或报告正文。 |

### 9.5 禁止保存正文候选诊断

模块 2 必须显式阻断会污染版本 truth 的正文来源。尤其是自动化再生成、新内容、视图、归档和观测材料,都不能因为“看起来像版本”而直接进入历史版本事实。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 未收束的新内容 / 候选文本正文 | 应进入禁止保存正文候选或禁止替代 truth 候选。 | BR-ART-007 要求新内容和候选修订不得无声覆盖既有版本事实。 | 写成未收束材料不形成版本 truth,不写输入 payload 或暂存区。 |
| 自动化运行结果、工具结果、模型上下文正文 | 应进入禁止保存正文候选。 | BR-ART-008 要求自动化结果存在本身不形成版本替代。 | 不写 runtime、tool、model 或 capability 输出正文。 |
| workspace 视图、conversation 显化、preview 正文 | 应进入禁止保存正文候选。 | 视图材料可展示版本,但不得改写当前被引用版本或历史版本事实。 | 不写 UI / view schema。 |
| archive package / observability record 正文 | 应进入禁止保存正文候选。 | BR-ART-010 明确归档材料、视图和观测记录不得改写当时版本事实。 | 不写归档包结构、观测日志或审计报告正文。 |
| work / process / governance 决策正文 | 应进入禁止保存正文候选。 | 相邻仓可以引用确定版本,但其状态、完成判断或治理决策不能成为 Artifact 版本 truth。 | 不写工作项、过程状态、Gate 或裁决正文。 |

## 11. 模块 3 制品血缘关联数据归属:先思考

### 11.1 模块输入范围

本模块只处理“制品血缘关联”能力下的数据归属候选。它承接模块 1 的正式 Artifact fact 和模块 2 的稳定 Artifact version fact,回答正式 Artifact 血缘事实、来源 / 替代 / 依赖 / 传递关系语境、自动化关系收束语境、血缘影响理解语境和跨仓私有追溯边界如何归属。

当前不处理基线冻结成员集合或跨仓可消费表达的完整数据归属;这些分别进入后续模块 4~5。当前也不写 `ArtifactRelation` 对象、relation kind、关系方向字段、图结构、查询深度、AddRelation / GetLineage 接口、事件 payload、图算法、索引、缓存、NFR 或验收。

| 输入 | 对模块 3 的意义 | 当前禁区 |
|---|---|---|
| 模块 1 正式 Artifact fact | 血缘事实必须锚定正式 Artifact fact,不能挂在附件、日志、视图或外部正文上。 | 不回写 Artifact fact 字段、正文 schema 或创建接口。 |
| 模块 2 Artifact version fact | 血缘事实必须锚定稳定版本事实,不能挂在未区分版本的可变材料上。 | 不写 version 字段、版本号格式、current flag 或状态机。 |
| FR-ART-009 正式血缘语境建立 | 需要识别来源、替代、依赖和传递关系进入正式血缘语境时的数据归属。 | 不写 relation kind、关系表、图模型或 AddRelation。 |
| FR-ART-010 自动化产出关系收束 | 需要识别自动化产出与输入、参考材料或被替代制品之间关系收束的数据边界。 | 不写 runtime trace、tool result、model context 或 observability schema。 |

### 11.2 真相数据候选诊断

模块 3 的真相数据候选应围绕“正式 Artifact fact 与稳定 Artifact version fact 之间的正式血缘语境”收束。血缘不能退化为临时链接、事件流、观测 trace、工具输出或相邻仓私有关系。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 正式 Artifact 血缘事实 | 应进入真相数据候选。 | FR-ART-009 / BR-ART-011 要求来源、替代、依赖和传递关系必须锚定正式 fact 和稳定版本事实。 | 写成需求层血缘事实,不写关系表、字段、relation kind 或图模型。 |
| 来源关系语境 | 可进入真相数据候选。 | FR-ART-009 / FR-ART-012 要求审计和消费能解释制品版本从何而来。 | 不写来源字段、方向枚举或查询接口。 |
| 替代关系语境 | 可进入真相数据候选。 | FR-ART-009 / BR-ART-012 要求替代关系显式进入血缘语境,才能支撑审查、维护和消费。 | 不写替代状态、版本指针或迁移流程。 |
| 依赖关系语境 | 可进入真相数据候选。 | FR-ART-011 要求维护和责任判断理解依赖关系,不能只面对孤立正文或孤立版本。 | 不写依赖图结构、递归算法或完整链查询。 |
| 传递影响语境 | 可进入真相数据候选。 | BR-ART-012 / BR-ART-014 要求关系影响被审查、维护、基线候选或消费使用前显式进入血缘语境。 | 不写影响分析算法、级联更新或基线成员规则。 |
| 自动化产出关系收束语境 | 可进入真相数据候选。 | FR-ART-010 / BR-ART-013 要求自动化产出与输入、参考材料或被替代制品的关系进入正式血缘,而不是停留在 trace 中。 | 不把 runtime trace、tool result 或模型上下文写成血缘 truth。 |

### 11.3 快照数据候选诊断

模块 3 的快照候选只能辅助审查、维护、审计和消费解释血缘事实,不得形成新的血缘 truth,也不得替代正式血缘事实。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|

### 11.4 引用数据候选诊断

模块 3 的引用候选用于说明血缘事实可以引用外部输入、参考材料、审查语境、自动化来源或相邻仓消费语境,但本仓不接管外部对象正文和生命周期。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 外部输入 / 参考材料引用 | 可作为引用候选。 | 自动化或人工产出可能需要说明输入和参考材料,但外部正文不属于 Artifact 血缘 truth。 | 不写外部正文、文件内容或资料库正文。 |
| 被替代外部语境引用 | 可作为引用候选。 | 替代关系可能关联外部语境,但替代事实必须进入本仓正式血缘后才能被使用。 | 不写外部状态、工作项正文或过程状态。 |
| 自动化来源引用 | 可作为引用候选。 | 自动化关系收束可引用 runtime、capability 或 tool 语境,但不拥有其执行正文。 | 不写运行日志、工具结果或模型上下文正文。 |
| 外部审查 / 维护语境引用 | 可作为引用候选。 | 审查和维护理解血缘影响时可引用 identity、governance、work 或 process 语境。 | 不写身份资料、审批裁决、工作项或过程正文。 |

### 11.5 禁止保存正文候选诊断

模块 3 必须显式阻断会污染血缘 truth 的正文来源。尤其是 runtime trace、工具结果、模型上下文、观测记录、事件流、视图和相邻仓私有追溯链,都不能因为“能解释关系”而成为正式血缘事实。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| runtime trace / tool result / model context 正文 | 应进入禁止保存正文候选。 | BR-ART-013 要求自动化产出不得仅凭这些材料形成 Artifact 血缘。 | 可作为输入线索或引用,不能保存为血缘 truth 正文。 |
| observability record / archive package 正文 | 应进入禁止保存正文候选。 | BR-ART-013 / BR-ART-015 要求观测和归档材料不得替代或改写血缘事实。 | 不写观测日志、归档包结构或审计报告正文。 |
| workspace view / conversation 显化 / preview 正文 | 应进入禁止保存正文候选。 | 视图和对话可展示血缘,但不能私造、补写或改写 Artifact 血缘事实。 | 不写 UI、view schema 或 preview 正文。 |
| event flow / SDK / console / sync 私有追溯正文 | 应进入禁止保存正文候选。 | BR-ART-015 要求事件流和工具界面可传递或消费血缘,但不得定义私有血缘 truth。 | 不写 event payload、SDK 状态或同步记录正文。 |

## 13. 模块 4 制品基线冻结数据归属:先思考

### 13.1 模块输入范围

本模块只处理“制品基线冻结”能力下的数据归属候选。它承接模块 2 的稳定 Artifact version fact 和模块 3 的正式 Artifact 血缘事实,回答 Artifact baseline truth、受控 Artifact 版本集合、基线候选语境、冻结语境、冻结责任 / 审查集合语境、历史冻结集合和跨仓基线消费边界如何归属。

当前不处理跨仓可消费表达的完整数据归属;该内容进入后续模块 5。当前也不写 members 字段、pin/hash、集合排序、baseline 编号、审批状态、发布接口、归档包结构、数据库表、事务、NFR 或验收。

| 输入 | 对模块 4 的意义 | 当前禁区 |
|---|---|---|
| 模块 2 Artifact version fact | baseline truth 必须由正式 Artifact 版本组成,不能由可变当前版本、临时材料或未版本化正文替代。 | 不写 version 字段、版本号格式、current flag、pin/hash 或存储约束。 |
| 模块 3 正式 Artifact 血缘事实 | 基线审查和责任理解可结合正式血缘理解成员关系和影响,但基线 truth 不反写血缘 truth。 | 不写 relation kind、影响分析算法、图查询或血缘完整性扫描。 |
| FR-ART-013 受控版本集合形成 | 需要识别正式 Artifact 版本共同进入受控集合时的数据归属。 | 不写 members 字段、集合排序、集合版本号或数据库结构。 |
| FR-ART-014 基线候选与冻结语境收束 | 需要识别哪些候选材料可以进入基线候选和冻结语境,哪些必须禁止。 | 不写候选状态机、审批流程、接口或事件 payload。 |
| FR-ART-015 冻结责任与审查语境 | 需要识别审查、确认、责任理解、维护边界和协作引用围绕同一集合成立的数据语境。 | 不写 owner 字段、review 状态、治理裁决或工作流。 |
| FR-ART-016 历史基线可审计与跨仓边界 | 需要识别历史 baseline truth、审计解释和相邻仓消费边界。 | 不写归档包、恢复策略、项目状态、治理记录或观测 schema。 |
| BR-ART-016~020 | 约束 baseline truth、基线候选过滤、显式冻结、责任集合语境和历史基线审计。 | 不把规则重写为字段约束、接口约束、归档策略、NFR 或测试用例。 |

### 13.2 真相数据候选诊断

模块 4 的真相数据候选应围绕“一组正式 Artifact 版本共同进入受控集合并显式形成冻结语境”收束。基线不能由临时清单、发布说明、治理裁决、项目状态、归档包或 workspace 视图替代。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| Artifact baseline truth | 应进入真相数据候选。 | FR-ART-013 / BR-ART-016 要求 baseline truth 表达正式 Artifact 版本共同进入受控集合的事实。 | 写成需求层基线事实,不写 baseline 表、编号、members 字段或 pin/hash。 |
| 受控 Artifact 版本集合 | 应进入真相数据候选。 | FR-ART-013 / BR-ART-016 要求作者、负责人和项目 / 领域语境理解某版本是否属于同一冻结事实范围。 | 不写集合排序、成员字段、集合版本号或存储结构。 |
| 基线候选语境 | 可进入真相数据候选。 | FR-ART-014 / BR-ART-017 要求候选语境只接纳正式 Artifact 版本,阻止临时产物或视图绕过版本事实。 | 不写候选状态枚举、审批流程或导入接口。 |
| 受控版本集合进入冻结语境 | 可进入真相数据候选。 | BR-ART-018 要求受控集合显式形成冻结语境后才成为可审查、可引用或可审计的 baseline truth。 | 不写冻结命令、事务流程、发布动作或事件。 |
| 冻结责任 / 审查集合语境 | 可进入真相数据候选。 | FR-ART-015 / BR-ART-019 要求审查、确认、责任理解、维护边界和协作引用锚定同一集合。 | 不写 owner 字段、review 状态、审批裁决或治理流程。 |
| 历史 Artifact baseline truth | 应进入真相数据候选。 | FR-ART-016 / BR-ART-020 要求历史冻结集合可回溯并解释当时共同冻结的 Artifact 版本集合。 | 不写保留周期、归档存储、备份或恢复策略。 |
| 跨仓基线消费边界语境 | 可进入真相数据候选。 | BR-ART-020 要求项目、治理、归档和其他相邻仓只能消费 baseline truth,不能复制、反推或补造。 | 不写相邻仓状态、归档包结构、workspace view 或事件流正文。 |

### 13.3 快照数据候选诊断

模块 4 的快照候选只能辅助审查、冻结解释、历史回溯和跨仓稳定消费,不得形成新的 baseline truth,也不得替代受控版本集合事实。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 基线候选展示摘要 | 可作为快照候选。 | 审查者需要理解候选集合,但展示摘要不等于 baseline truth。 | 不写 UI、projection、候选列表字段或排序规则。 |
| 冻结范围说明摘要 | 可作为快照候选。 | 责任理解和协作引用需要解释冻结范围,但说明摘要不能替代受控版本集合。 | 不写发布说明正文、人工说明或治理裁决正文。 |
| 血缘影响辅助摘要 | 可作为快照候选。 | BR-ART-019 允许结合正式血缘理解成员关系和影响,但影响摘要不是基线 truth。 | 不写影响分析算法、图查询或血缘完整性检查。 |
| 历史基线展示摘要 | 可作为快照候选。 | 审计和消费可能需要稳定展示历史冻结集合。 | 不写归档包、封存策略、恢复指标或历史报告正文。 |
| 跨仓基线消费摘要 | 可作为快照候选或模块 5 后续候选。 | 相邻仓可稳定消费 baseline truth,但摘要不迁移本仓 truth。 | 不写 project、governance、archive、workspace 或 event 私有状态。 |

### 13.4 引用数据候选诊断

模块 4 的引用候选用于说明 baseline truth 可以引用项目、领域、治理、归档、审查、责任或发布语境,但本仓不接管这些外部对象正文和生命周期。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 外部审查 / 责任语境引用 | 可作为引用候选。 | FR-ART-015 需要审查、确认和责任理解围绕同一集合成立,但身份和治理正文不归本仓。 | 不写身份资料、审批裁决、review 正文或权限模型。 |
| 项目 / 领域 / 里程碑 / 发布语境引用 | 可作为引用候选。 | FR-ART-016 / BR-ART-020 要求这些语境只能消费 baseline truth,不能补造基线事实。 | 不写项目状态、领域范围、发布说明正文或里程碑状态。 |

### 13.5 禁止保存正文候选诊断

模块 4 必须显式阻断会污染 baseline truth 的正文来源。尤其是自动化临时产物、运行输出、workspace 视图、归档包、发布说明、治理裁决、项目状态和事件流,都不能因为“看起来像冻结范围”而形成基线事实。

|---|---|---|---|
| 自动化临时产物 / 运行输出正文 | 应进入禁止保存正文候选。 | BR-ART-017 要求未成为正式 Artifact 版本的材料不得参与基线事实。 | 不写 runtime、tool、model 或 capability 输出正文。 |
| workspace view / conversation 显化 / preview 正文 | 应进入禁止保存正文候选。 | BR-ART-017 / BR-ART-020 要求视图和对话材料不得误当成基线事实或改写历史基线。 | 不写 UI、view schema 或预览正文。 |
| archive package / observability record 正文 | 应进入禁止保存正文候选。 | BR-ART-017 / BR-ART-020 要求归档和观测材料不得补造或改写 baseline truth。 | 不写归档包结构、观测日志或恢复策略。 |
| 发布说明 / 外部链接 / 人工说明正文 | 应进入禁止保存正文候选。 | BR-ART-018 要求版本列表、发布说明、外部链接或说明存在本身不形成 Artifact baseline truth。 | 不写 release note、链接清单或说明正文。 |
| governance decision / project status / event flow 正文 | 应进入禁止保存正文候选。 | BR-ART-020 要求治理决策、项目状态和事件流不得复制、反推或补造基线事实。 | 不写治理裁决、项目状态、event payload 或私有同步正文。 |

### 15.1 模块输入范围

本模块只处理“制品事实可消费表达”能力下的数据归属候选。它承接模块 1~4 已确认的正式 Artifact fact、version、lineage 和 baseline truth,回答相邻角色和系统如何稳定引用同一 Artifact truth、跨仓消费如何保持 truth 不转移、审查责任和协作消费如何保持一致、消费后如何回指正式制品事实。

|---|---|---|
| 模块 1 正式 Artifact fact | 可消费表达必须回到正式 fact,不能让下游视图或局部副本替代 fact。 | 不回写 Artifact 字段、正文 schema、创建接口或存储结构。 |
| 模块 2 Artifact version fact | 下游消费必须能稳定指向确定版本,不能依赖可变当前材料。 | 不写 version 字段、版本号格式、current flag 或发布接口。 |
| 模块 3 正式 Artifact 血缘事实 | 下游消费 lineage 时必须引用统一血缘 truth,不能形成私有追溯链。 | 不写 relation kind、图查询、事件流或 trace schema。 |
| 模块 4 Artifact baseline truth | 下游消费 baseline 时必须引用正式基线 truth,不能由归档包、发布说明或项目状态补造。 | 不写 members 字段、pin/hash、归档包结构或冻结接口。 |
| FR-ART-017 稳定 Artifact truth 引用表达 | 需要识别同一 Artifact fact、version、lineage、baseline 被稳定引用时的数据归属。 | 不写 API schema、DTO、SDK 方法或查询协议。 |
| FR-ART-018 消费边界与 truth 不转移 | 需要识别相邻仓只能引用、展示、封存、观测或同步,不能拥有或重建 Artifact truth 的边界数据。 | 不写 projection、复制策略、缓存、sync 协议或权限。 |
| FR-ART-019 审查责任与协作消费一致 | 需要识别审查意见、维护责任和项目 / 领域协作围绕同一 Artifact truth 消费的数据语境。 | 不写审批流、owner 字段、工作项状态或治理裁决。 |
| FR-ART-020 跨仓审计回指与事实解释 | 需要识别跨仓消费后回指正式 Artifact truth、解释消费依据的数据语境。 | 不写审计日志 schema、event payload、归档包或观测记录结构。 |
| BR-ART-021~025 | 约束统一 truth 引用、跨仓消费边界、自动化 / runtime 消费边界、责任协作消费和跨仓审计回指。 | 不把规则重写为接口、事件、读模型、NFR 或验收用例。 |

### 15.2 真相数据候选诊断

模块 5 的真相数据候选应围绕“本仓如何对外表达同一 Artifact truth 的正式引用和回指语境”收束。可消费表达不是下游副本、视图对象或事件材料,也不是把 Artifact truth 迁移到相邻仓。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 可消费 Artifact truth 引用语境 | 应进入真相数据候选。 | FR-ART-017 / BR-ART-021 要求相邻角色和系统消费时回到同一 fact、version、lineage 或 baseline 语境。 | 写成需求层引用语境,不写 API、DTO、SDK 或查询协议。 |
| Artifact fact / version / lineage / baseline 回指语境 | 应进入真相数据候选。 | FR-ART-020 / BR-ART-025 要求跨仓消费后能回指正式 Artifact truth 并解释消费基于哪份事实。 | 不写字段、URI、event payload 或审计日志 schema。 |
| 跨仓消费边界语境 | 可进入真相数据候选。 | FR-ART-018 / BR-ART-022 要求相邻仓只能引用、展示、封存、观测或同步,不得拥有、复制、重建、反推或迁移 truth。 | 不写复制策略、projection、缓存或 sync 实现。 |
| 自动化 / runtime 消费边界语境 | 可进入真相数据候选。 | FR-ART-018 / BR-ART-023 要求自动化产出的正式 Artifact 被消费时,不能与 runtime 输出或工具结果混同。 | 不写 runtime trace、tool result、model trace 或 capability result 正文。 |
| 审查 / 责任 / 协作消费一致语境 | 可进入真相数据候选。 | FR-ART-019 / BR-ART-024 要求审查意见、维护责任、项目 / 领域协作和质量判断围绕同一 Artifact truth 成立。 | 不写 owner 模型、review 状态、治理裁决或工作项状态。 |
| 跨仓审计回指语境 | 可进入真相数据候选。 | FR-ART-020 / BR-ART-025 要求消费、展示、封存、观测或同步后仍可解释消费依据。 | 不写审计日志、事件表、归档包或观测 schema。 |

### 15.3 快照数据候选诊断

模块 5 的快照候选只能辅助下游稳定显示、解释、审查、归档或观测消费,不得形成新的 Artifact truth,也不得把 truth 迁移到消费方。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 可消费展示摘要 | 可作为快照候选。 | 相邻角色和系统可能需要稳定展示 fact、version、lineage 或 baseline 的消费视图。 | 不写 workspace view、console 页面、projection 或 DTO。 |
| 消费依据说明摘要 | 可作为快照候选。 | FR-ART-020 需要解释消费基于哪份制品事实。 | 不写审计日志 schema、event payload 或报告结构。 |
| 审查 / 责任消费摘要 | 可作为快照候选。 | FR-ART-019 要求审查和维护责任在消费中围绕同一 truth。 | 不写审批意见正文、owner 字段或工作项状态。 |
| 跨仓消费状态摘要 | 可作为快照候选或外围审计候选。 | 消费方可知道自己引用了哪份 truth,但状态摘要不能拥有 truth。 | 不写 sync 状态、SDK 状态、缓存状态或相邻仓私有状态。 |
| 归档 / 观测消费摘要 | 可作为快照候选或外围审计候选。 | 归档和观测可消费 Artifact truth,但摘要不替代 fact、version、lineage 或 baseline。 | 不写归档包、metric、alert、log 或封存策略。 |

### 15.4 引用数据候选诊断

模块 5 的引用候选用于说明外部角色、系统、仓、通道或消费场景如何回到同一 Artifact truth,但本仓不接管外部对象正文和生命周期。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 跨仓消费方引用 | 可作为引用候选。 | work、process、governance、archive、observability、workspace、SDK、console、sync 等可消费 Artifact truth。 | 不写消费方正文、状态、视图或协议。 |
| 外部审查 / 质量 / 责任语境引用 | 可作为引用候选。 | 审查意见、质量判断和维护责任需要围绕同一 Artifact truth 消费。 | 不写 review 正文、质量报告正文、owner 模型或权限。 |
| 项目 / 领域协作语境引用 | 可作为引用候选。 | 项目 / 领域协作需要稳定引用 Artifact fact、version、lineage 或 baseline。 | 不写项目状态、领域范围、里程碑或发布口径正文。 |
| 归档 / 观测 / 同步通道引用 | 可作为引用候选。 | 归档、观测和同步可以引用 Artifact truth,但不能拥有或重建 truth。 | 不写归档包、观测日志、sync payload 或缓存材料。 |
| 自动化消费来源引用 | 可作为引用候选。 | 自动化产出的正式 Artifact 被消费时,需要与 runtime、tool、model 和 capability 材料保持边界。 | 不写运行输出正文、工具结果或模型上下文。 |

### 15.5 禁止保存正文候选诊断

模块 5 必须显式阻断会污染可消费 truth 的正文来源。尤其是下游局部副本、视图对象、事件材料、runtime 输出、工具结果、归档包、观测日志、SDK / console / sync 私有状态,都不能因为“被消费过”而成为 Artifact truth。

| 候选方向 | 判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 下游局部副本 / 私有当前制品正文 | 应进入禁止保存正文候选。 | BR-ART-021 要求不得以局部副本、视图对象或私有“当前制品”解释替代正式 Artifact truth。 | 不写副本内容、私有状态或同步正文。 |
| workspace / conversation / console / SDK 视图正文 | 应进入禁止保存正文候选。 | BR-ART-022 / 025 要求这些只能展示或访问,不能拥有、复制或反推 Artifact truth。 | 不写 UI、SDK 方法、console 页面或 view schema。 |
| event material / sync payload / projection 正文 | 应进入禁止保存正文候选。 | BR-ART-021 / 022 / 025 要求事件材料、同步材料和派生表达不能替代正式 truth。 | 不写 event payload、projection 字段、缓存或同步协议。 |
| runtime output / tool result / model trace / capability result 正文 | 应进入禁止保存正文候选。 | BR-ART-023 要求自动化产出的正式 Artifact 被消费时不得与运行材料混同。 | 不写运行、工具、模型或能力执行正文。 |
| archive package / observability log / metric / alert 正文 | 应进入禁止保存正文候选。 | BR-ART-022 / 025 要求归档和观测只能封存、观测或回指,不能反推或补造 Artifact truth。 | 不写归档包、日志、metric、alert 或观测 schema。 |
| work / process / governance / project 状态正文 | 应进入禁止保存正文候选。 | BR-ART-022 / 024 要求相邻仓业务状态不能重新定义审查对象、责任边界或 Artifact truth。 | 不写工作项、过程状态、治理裁决、项目状态或发布口径正文。 |

## 17. 外围增强 / 边界外数据审计:先思考

### 17.1 本模块目标

本模块不新增核心 truth 数据项,也不把外围增强改写成新的核心能力。目标是在模块 1~5 已完成的 fact、version、lineage、baseline 和可消费表达数据归属基础上,审计外围增强和边界外候选是否会污染 `L1-artifact` 的数据边界。

本模块只做候选诊断,不写最终数据归属表、保留表或裁剪表。后续再写入时才形成外围增强数据保留表、边界外数据裁剪表和后续 Step / 文档处理项裁剪表。

### 17.2 输入范围

| 输入 | 对本模块的作用 | 当前禁区 |
|---|---|---|
| 模块 1~5 数据归属结论 | 提供正式 Artifact fact、version、lineage、baseline 和可消费表达的数据归属基线。 | 不反写核心数据表,不重命名已完成数据项。 |
| Step 9 外围增强功能保留表 | 提供搜索 / 浏览、预览、projection / 报表、通知、归档、观测、SDK / console / sync 的外围增强候选。 | 不把外围功能写成核心 truth 数据。 |
| Step 9 边界外功能裁剪表 | 提供 work、process、governance、conversation、workspace、archive、observability、method-library、runtime、capability-hub 的裁剪归属。 | 不把相邻仓功能或正文转成本仓数据项。 |
| Step 10 规则裁剪表 | 提供外围增强由 BR-ART-001~025 承接 truth 边界、不新增 BR-ART-026 的规则口径。 | 不新增业务规则、验收条件、接口契约或实现约束。 |
| Step 6 使用方与依赖 | 提供相邻仓只能引用、消费、展示、封存、观测或同步 Artifact truth 的依赖边界。 | 不新增编译期依赖、事件 payload、port 或 adapter。 |

### 17.3 外围增强数据候选诊断

外围增强数据只允许改善发现、展示、通知、归档消费、观测消费或外部访问体验。它们不拥有 Artifact truth,不能作为 fact、version、lineage 或 baseline 的来源,也不能改变模块 1~5 的归属结论。

| 候选方向 | 初步归属判断 | 理由 | 写入时注意 |
|---|---|---|---|
| 搜索 / 浏览 / 列表发现数据 | 可作为快照数据候选。 | 它只帮助发现已有 Artifact facts、versions、lineage 或 baselines,不生成新的制品事实。 | 写成发现摘要或索引线索的需求层归属,不写 search index、排序、分页、权限或性能。 |
| Artifact / lineage / baseline 预览数据 | 可作为快照数据候选。 | 预览辅助消费前理解,但预览不是 Artifact truth 来源。 | 不写 workspace / console 页面、view schema、预览字段或渲染规则。 |

## 11. 数据需求与数据归属

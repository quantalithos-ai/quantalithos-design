## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_position_boundary.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“改动前后对比”和“后移事项”小节，了解本章边界如何从旧定位中收敛而来。

| 字段 | 内容 |
|---|---|
| 一句话定义 | `L1-conversation` 是平台对话真相仓。 |
| 本仓不是什么 | 它不是 Chat UI,不是 Workspace 聚合视图,不是 Bridges 协议适配层,不是 Runtime 推理系统,不是 Governance 决策系统,不是 Artifact 正文仓,也不是 Identity 生命周期仓。 |
| 边界对象列表 | 仓：`L5-chat`;仓：`L1-workspace`;仓：`L6-bridges`;仓：`L2-runtime`;仓：`L1-governance`;仓：`L1-artifact`;仓：`L1-identity`;概念：对话真相 vs 消息展示 |
| 单独成仓原因 | 平台需要独立于 UI、视图、外部平台和运行时的长期对话事实真相。 |

`L1-conversation` 需要单独存在,因为对话是人、AI member 和系统事件共同形成的协作事实,不是某个聊天界面的临时展示状态。它最容易与 `L5-chat`、`L1-workspace`、`L6-bridges` 和 `L2-runtime` 混淆:这些仓可以展示、聚合、映射或消费对话,但不应拥有对话真相。该边界必须先分开,否则后续会把 UI、项目视野、外部协议、推理循环、治理决策和产物正文混进 conversation 需求。

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“改动前后对比”和“当前不纳入 Step 3 的内容”小节，了解本章问题定义如何从旧文档中收敛而来。

### 3.1 业务背景

Quantalithos 要让用户像管理一个软件团队一样管理 AI member,而这个团队协作的默认载体是对话。对话承载需求澄清、项目讨论、关键决策通知、产物反馈和后续追溯,因此 Conversation 不能只是某个客户端的消息缓存。当前 `L0-core`、`L0-bus`、`L0-sdk` 和 `L1-identity` 已稳定,需要把对话域的需求问题独立收束,为 Chat、Workspace、Bridges、Runtime 和审计链路提供共同事实基线。

### 3.2 现状与问题

| 问题 | 当前表现 | 影响范围 / 后果 |
|---|---|---|
| 对话事实缺少新版需求层收束 | 旧文档已有大量四形态、Turn、实时推送、事件和性能内容,但问题、目标、功能、协议和实现线索混写 | 后续架构和详细设计容易把 Chat UI、Workspace 视图、Runtime 推理、Bridges 适配和 Conversation 真相混为一体 |
| 多个下游消费方会各自塑造对话语义 | Chat 需要显示消息,Workspace 需要聚合个人 / 项目视野,Bridges 需要外部平台映射,Runtime 需要读取上下文,Governance / Artifact 需要把关键事件显化 | 同一协作事实可能在不同视角下不一致,导致用户看见的过程、AI member 使用的上下文和审计追溯无法对齐 |
| 对话若被降级为消息表或 UI 附属,产品叙事无法闭环 | 产品叙事要求“先对话后表单”“协作载体是对话”“Conversation 是一等聚合根”,但旧仓定位仍容易被理解成消息服务 | 用户无法稳定通过对话理解、介入和追溯 AI 团队协作,也削弱后续 Workspace、Chat 和 Bridges 的共同基础 |

### 3.3 业务问题 vs 技术问题

| 类型 | 内容 |
|---|---|
| 业务问题 | 平台缺少对“对话作为人、AI member 和系统事件共同协作事实”的正式需求收束,会影响用户理解过程、介入决策、复盘项目和信任 AI 团队协作。 |
| 技术问题 | Conversation 若没有独立真相边界,Chat、Workspace、Bridges、Runtime、Governance、Artifact 和 Observability 会重复定义消息、上下文、通知和审计语义,导致后续设计与实现反复串线。 |

## 4. 目标与非目标

> 校准来源：
> - `design-calibration/00_req_step_04_goals_non_goals.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“改动前后对比”和“后移事项”小节，了解本章如何把旧目标表收束为需求层目标和非目标。

### 4.1 目标

| 目标 | 说明 | 验证方式 |
|---|---|---|
| 建立平台对话真相域的需求边界 | 明确 `L1-conversation` 承载 Conversation / Turn 这类对话事实,而不是 Chat UI、Workspace 视图或 Runtime 推理过程 | 后续章节不再把 UI 展示状态、workspace 聚合视图或 agent loop 写入 Conversation 范围 |
| 收束对话事实可见与可消费的需求范围 | 明确对话事实需要被授权的人类用户、AI member、Chat、Workspace、Bridges 和审计链路稳定消费 | 后续用户、依赖、接口和验收章节能区分消费方与事实所有者 |
| 明确跨域事件进入对话后的边界 | 明确 Governance / Artifact / Work / Identity 等跨域事实可以在对话中形成可见记录,但原始业务真相仍归属对应仓 | 后续功能、规则和数据归属章节不把 Gate、Artifact、Project、Member 生命周期正文写成 Conversation 真相 |
| 支撑用户管理 AI 团队的协作可见性 | 明确 Conversation 需求服务于用户理解、介入和追溯 AI 团队协作过程 | 后续用户故事和验收标准能围绕协作可见、介入、复盘和追溯展开 |
| 为核心能力闭环提供需求锚点 | 为后续“创建 / 维护对话空间、记录对话事实、查询 / 订阅、跨域事件显化、历史追溯”能力闭环提供范围边界 | Step 7 核心能力闭环能够以对话真相为主线收敛,不转向 UI 或运行时主线 |

### 4.2 非目标

| 非目标 | 不做原因 |
|---|---|
| Chat UI 页面、组件和客户端交互状态 | 属于 `L5-chat` 展示和产品交互范围,Conversation 只提供对话事实 |
| Workspace 个人首页、项目视图、inbox 和跨域聚合 | 属于 `L1-workspace` 聚合视图范围,Conversation 不拥有个人 / 项目视野整体真相 |
| 外部聊天平台协议适配和外部平台生命周期 | 属于 `L6-bridges` 范围,Conversation 不直接实现 Mattermost / Slack / Telegram 等平台协议 |
| LLM 推理、agent loop、tool 调用和 runtime memory 写入 | 属于 `L2-runtime` / `L2-tools` 范围,Conversation 只提供 / 记录对话事实 |
| Gate、Policy、Approval 的决策真相 | 属于 `L1-governance` 范围,Conversation 只承载对话中可见的通知、引用或记录 |
| Artifact 正文、版本、证据链和产物生命周期真相 | 属于 `L1-artifact` 范围,Conversation 只承载对话中的引用或通知 |
| 成员创建、成员生命周期、角色定义、认证和授权裁决 | 成员真相属于 `L1-identity`,角色定义属于 method-library,认证 / 授权裁决不属于 Conversation |
| 全局 trace、metrics、audit store、长期归档和冷存策略 | 属于 `L4-observability` / `L4-archive` 或后续非功能与设计范围,Conversation 只保留必要追溯需求 |

## 5. 用户与角色

> 校准来源：
> - `design-calibration/00_req_step_05_users_roles.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“改动前后对比”和“角色分类结论”小节，了解本章如何把旧角色表和权限矩阵收束为需求层角色定义。

### 5.1 角色说明表

| 角色 | 类型 | 使用场景 |
|---|---|---|
| 终端管理者 / 项目负责人 | 人类角色 | 通过对话理解项目进展、提出需求、介入关键决策并复盘历史 |
| 项目参与者 | 人类角色 | 在相关项目、频道、私聊或讨论串中参与协作并读取授权对话事实 |
| AI member | 平台成员角色 | 作为对话参与者读取授权上下文并产生对话事实;身份来自 `L1-identity`,推理来自 `L2-runtime` |
| 系统事件 actor | 系统角色 | 将已发生的跨域事实以系统身份显化为对话可见记录 |
| 审计者 / 合规查看者 | 人类角色 | 查看被授权的对话历史、关键决策上下文和追溯线索 |
| 运维 / 后台任务 | 系统角色 | 执行索引、投影、归档、重建或修复性维护,不直接创造业务对话事实 |
| 下游应用开发者 | 人类角色 | 基于 SDK / client 能力消费 Conversation,用于 Chat、Workspace、Bridge 或 Console 集成 |

### 5.2 能力级权限差异表

| 操作类型 | 终端管理者 / 项目负责人 | 项目参与者 | AI member | 系统事件 actor | 审计者 / 合规查看者 | 运维 / 后台任务 | 下游应用开发者 |
|---|---|---|---|---|---|---|---|
| 参与对话事实形成 | 是,限授权对话 | 是,限授权对话 | 是,限授权上下文 | 仅系统事件显化 | 否 | 否 | 否 |
| 读取对话事实 | 是,限授权范围 | 是,限授权范围 | 是,限授权上下文 | 按系统处理范围 | 是,限审计授权范围 | 受限维护读取 | 通过授权 client 消费 |
| 显化跨域事实 | 否 | 否 | 可作为参与者评论,不拥有原始事实 | 是 | 否 | 可执行修复性重放,不改原始事实 | 否 |
| 审计 / 复盘查看 | 是,限相关范围 | 受限 | 受限 | 否 | 是 | 受限 | 否 |
| 维护处理 | 否 | 否 | 否 | 否 | 否 | 是 | 否 |

本表只表达需求层能力差异,不替代最终权限规则。具体可见性、审计边界、维护限制和系统事件显化规则将在业务规则、数据归属和验收章节继续收敛。

## 6. 使用方与依赖

> 校准来源：
> - `design-calibration/00_req_step_06_consumers_dependencies.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“本仓禁止依赖表”和“依赖裁剪图”小节，了解本章如何从全局依赖基线裁剪出 Conversation 的依赖子图。

### 6.1 内部仓依赖

| 方向 | 对方 | 提供 / 依赖内容 | 是否闭环前置 | 失效影响 |
|---|---|---|---|---|
| 输入 | `L0-core` | 共享 ID、actor 引用、trace、error、metadata 和通用契约 | 是 | 对话事实无法与平台其他仓保持统一引用和追溯口径 |
| 输入 | `L0-bus` | 平台事件协作主干 | 是 | 对话事实无法稳定进入跨仓协作,跨端可见性和订阅能力退化 |
| 输入 | `L1-identity` | 成员、AI member、系统 actor 和参与者引用来源 | 是 | 参与者身份、生命周期和 actor 引用无法闭合 |
| 输入 | `L1-work` | 项目、工作项和项目成员上下文 | 项目型对话是;基础私聊否 | 项目群聊、项目频道和项目视野会缺少项目锚点 |
| 输入 | `L1-governance` | 治理事实引用边界 | 否 | Gate / Policy / Approval 只能显示为缺失或未解析引用,Conversation 不补造决策真相 |
| 输入 | `L1-artifact` | 产物、版本和证据对象引用边界 | 否 | 产物相关对话记录只能保留引用缺失状态,Conversation 不补造产物真相 |
| 输出 | `L0-sdk` | 对话能力的默认封装和下游访问路径 | 否 | 下游仍可存在直接服务边界,但产品和生态接入一致性下降 |
| 输出 | `L5-chat` | 聊天入口消费对话事实 | 否 | 用户聊天体验受影响,但 Conversation 真相仍应成立 |
| 输出 | `L1-workspace` | 个人视野和项目视野聚合消费对话事实 | 否 | Workspace 视图无法完整展示对话相关上下文 |
| 双向协作 | `L6-bridges` | 外部平台输入 / 输出通过正式边界映射为对话事实 | 否 | 外部平台同步退化,但内部对话真相不应依赖外部平台 |
| 双向协作 | `L2-runtime` | AI member 运行时读取授权上下文并产生对话事实 | 否 | AI member 对话参与能力退化,但本仓不接管推理循环 |
| 输出 | `L4-observability` / `L4-archive` | 追溯、审计和归档材料消费 | 否 | 全局观测或归档能力下降,但不改变 Conversation 业务事实 |

### 6.2 外部系统依赖

当前阶段,`L1-conversation` 无需要纳入需求主链的正式外部系统依赖。Mattermost、Slack、Telegram 等外部聊天平台属于 `L6-bridges` 的外部系统依赖,不应直接写入 Conversation 的依赖主链。

## 7. 核心能力闭环

> 校准来源：
> - `design-calibration/00_req_step_07_core_capability_loop.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“改动前后对比”和“功能线索回填映射”小节，了解本章如何从旧功能清单收敛为核心能力闭环。

### 7.1 闭环定义

`L1-conversation` 的核心能力闭环是:平台必须能够独立确立对话空间和参与范围,把多来源协作事实以追加方式沉淀为对话事实,让这些事实按授权视野被稳定消费,把关键跨域事实以引用方式显化到对话中,并让对话历史能够被追溯和复盘。只要这些能力不能共同成立,Conversation 就会退化为 UI 消息缓存、runtime 临时上下文或相邻仓通知副本。

### 7.2 核心能力闭环图

```text
对话空间与参与范围能够被独立确立
  -> 多来源协作事实能够以追加方式沉淀
  -> 对话事实能够按授权视野被稳定消费
  -> 关键跨域事实能够以引用方式显化到对话
  -> 对话历史能够被追溯并持续支撑协作复盘
```

本图只表达核心能力成立的逻辑依赖关系,不表达运行时调用顺序、接口时序、事件传播顺序或开发实施步骤。

### 7.3 能力层级划分表

| 分类 | 内容 |
|---|---|
| 核心能力闭环 | 对话空间与参与范围独立确立;多来源协作事实追加沉淀;授权视野下稳定消费;关键跨域事实引用显化;历史追溯与复盘 |
| 外围增强能力 | 全文检索;复杂通知策略;富媒体和卡片展示细化;细粒度实时流映射;外部平台差异化同步;冷热归档优化;管理后台运营视图;大规模容量优化 |
| 边界外能力 | Chat UI 交互;Workspace 聚合视图;外部平台协议生命周期;LLM 推理循环;治理决策;产物正文和版本真相;成员生命周期;登录认证与权限裁决;全局观测和长期归档策略 |

## 10. 业务规则与边界约束

> 校准来源：
> - `design-calibration/00_req_step_10_rules_boundary_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“规则覆盖核心能力映射”和“改动前后对比”小节，了解本章规则如何保护 Conversation 核心闭环和仓边界。

### 10.1 业务规则表

| 规则编号 | 规则类型 | 规则内容 | 约束对象 |
|---|---|---|---|
| BR-CONV-001 | 不变量 | 对话事实必须归属于明确的对话空间和参与范围,不能成为无归属的散落消息。 | 对话空间与参与范围 |
| BR-CONV-002 | 不变量 | 对话事实必须以追加方式形成历史,已形成的业务事实不得被覆盖、抹除或改写成另一事实。 | 协作事实沉淀 |
| BR-CONV-003 | 不变量 | 对话事实的消费必须受授权视野约束,消费方只能看到其被允许看到的对话事实。 | 授权视野消费 |
| BR-CONV-004 | 不变量 | 跨域事实进入对话视野时只能成为引用型可见记录,原始业务真相仍归属来源仓。 | 跨域事实显化 |
| BR-CONV-005 | 不变量 | 对话历史必须能支撑协作复盘和审计追溯,不能只作为瞬时交互缓存存在。 | 对话历史追溯 |
| BR-CONV-006 | 禁止行为 | 不得把 Chat UI 展示状态视为 Conversation 真相。 | Conversation / Chat 边界 |
| BR-CONV-007 | 禁止行为 | 不得把 Workspace 个人或项目聚合视图视为 Conversation 真相。 | Conversation / Workspace 边界 |
| BR-CONV-008 | 禁止行为 | 不得由 Conversation 直接承担外部聊天平台协议生命周期。 | Conversation / Bridges 边界 |
| BR-CONV-009 | 禁止行为 | 不得由 Conversation 执行 LLM 推理、agent loop 或工具调用。 | Conversation / Runtime 边界 |
| BR-CONV-010 | 禁止行为 | 不得由 Conversation 裁决 Gate、Policy 或 Approval 的业务结论。 | Conversation / Governance 边界 |
| BR-CONV-011 | 禁止行为 | 不得由 Conversation 保存或拥有 Artifact 正文、版本或证据链真相。 | Conversation / Artifact 边界 |
| BR-CONV-012 | 禁止行为 | 不得由 Conversation 创建、退休或改变成员生命周期真相。 | Conversation / Identity 边界 |
| BR-CONV-013 | 显式变化 | 对话空间、参与范围和可见范围的变化必须显式发生,不得由读取、消费或展示动作隐式改变。 | 空间与可见范围变化 |
| BR-CONV-014 | 显式变化 | 新的协作事实进入对话历史必须显式形成追加事实,不得由查询、检索或投影动作隐式生成业务事实。 | 协作事实追加 |
| BR-CONV-015 | 显式变化 | 跨域事实进入对话视野必须显式保留来源引用,不得通过本仓自行推断原始事实。 | 跨域引用显化 |
| BR-CONV-016 | 显式变化 | 索引、投影、检索辅助或变化感知结果只能随既有对话事实派生,不得成为独立业务事实来源。 | 外围增强结果 |
| BR-CONV-017 | 边界约束 | Conversation 只拥有对话中可见的记录和上下文,不拥有治理、产物、项目、成员或外部平台的原始真相。 | 跨仓真相边界 |
| BR-CONV-018 | 边界约束 | 对话事实可以被 Chat、Workspace、Bridges、Runtime、Observability 和 Archive 消费或引用,但这些消费方不能反向定义 Conversation 真相。 | 输出使用方边界 |
| BR-CONV-019 | 治理约束 | 治理相关事实显化到对话时必须保留正式治理结论引用,不得把对话记录本身当作治理结论。 | 治理事实显化 |
| BR-CONV-020 | 审计约束 | 对话事实、参与范围、可见范围和跨域引用显化的关键变化必须形成可追溯记录。 | 对话审计追溯 |
| BR-CONV-021 | 审计约束 | 维护性辅助动作不得改变业务事实,且必须能够说明其依据的既有对话事实范围。 | 维护辅助能力 |

## 11. 数据需求与数据归属

> 校准来源：
> - `design-calibration/00_req_step_11_data_requirements_ownership.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“数据类型结论”和“改动前后对比”小节，了解本章如何从旧实体关系表收敛为数据归属边界。

### 11.1 数据归属表

| 数据项 | 数据类型 | 归属说明 | 生命周期口径 |
|---|---|---|---|
| 对话空间 | 真相数据 | 对话空间由 Conversation 拥有正式真相。 | 从正式建立到正式终止,形成完整本仓生命周期。 |
| 对话参与范围 | 真相数据 | 对话参与范围由 Conversation 拥有对话域内正式真相。 | 随显式参与范围变化而变化。 |
| 对话可见范围 | 真相数据 | 对话可见范围由 Conversation 拥有对话域内正式真相。 | 随显式可见范围变化而变化。 |
| 对话事实历史 | 真相数据 | 对话事实历史由 Conversation 拥有正式真相。 | 从事实正式追加开始进入本仓生命周期,不得被覆盖成另一事实。 |
| 对话内跨域显化记录 | 真相数据 | 对话内可见记录由 Conversation 拥有正式真相,但来源事实不属于本仓。 | 随显式显化进入对话历史,不改变来源事实生命周期。 |
| 对话追溯上下文 | 真相数据 | 对话追溯上下文由 Conversation 在对话域内拥有正式真相。 | 随对话事实和关键变化形成,服务复盘与审计追溯。 |
| 成员展示摘要 | 快照数据 | 成员正式真相不属于 Conversation,但本仓可为稳定消费保留展示级快照。 | 随上游正式真相变化而更新,不形成独立真相生命周期。 |
| 项目 / 工作上下文摘要 | 快照数据 | 项目和工作正式真相不属于 Conversation,但本仓可为稳定消费保留摘要。 | 随上游正式真相变化而更新,不形成独立真相生命周期。 |
| 跨域事实显示摘要 | 快照数据 | 治理、产物或项目事实正文不属于 Conversation,但本仓可保留对话显示所需摘要。 | 随上游正式真相变化而更新,不形成独立真相生命周期。 |
| 成员引用 / 项目引用 / 治理引用 / 产物引用 | 引用数据 | 本仓只保存对外部对象的引用关系,不拥有其正文真相。 | 随引用关系建立、变化或失效而变化,本仓不负责正文生命周期。 |
| Chat UI / Workspace / Bridges / Runtime / Governance / Artifact / Identity / Observability / Archive 正文 | 禁止保存正文 | 相邻仓正文不属于 Conversation 真相范围,本仓不得保存其正文。 | 不进入本仓生命周期。 |

> - 建议继续阅读上述中间产物的“结构化中间产物”“非功能类别适用性检查”和“改动前后对比”小节，了解本章如何从旧指标 / 实现混写收敛为需求层质量底线。

### 13.1 非功能需求表

| 非功能类别 | 要求 | 判断口径 / 目标值 |
|---|---|---|
| 性能 | NFR-CONV-001: 对话事实追加和授权消费不应成为平台核心协作路径的长期瓶颈。 | 后续设计和测试必须证明核心追加、读取和追溯不会因历史规模增长或相邻仓正文不可解析而无法成立。 |
| 性能 | NFR-CONV-002: 外围增强能力不得反向阻塞核心对话真相形成。 | 长历史定位、辅助结果维护或及时感知不可用时,核心空间建立、事实追加和授权消费仍能判断成立。 |
| 可用性 | NFR-CONV-003: 已形成的对话真相不得因下游消费方不可用而丢失或被改写。 | Chat、Workspace、Runtime、Bridges、Observability 或 Archive 降级时,Conversation 已拥有的对话事实仍保持正式语义。 |
| 可用性 | NFR-CONV-004: 相邻真相域不可用时,Conversation 不得补造相邻仓正文。 | Identity、Work、Governance 或 Artifact 暂不可解析时,本仓只能保留自身真相、快照或引用状态,不能生成来源仓正文。 |
| 安全 | NFR-CONV-005: 对话事实消费必须受授权视野约束。 | 任何消费方只能获得其可见范围内的对话事实、快照或引用信息。 |
| 安全 | NFR-CONV-006: 本仓不得越权保存相邻仓正文或敏感凭据。 | Step 11 禁止保存正文清单中的对象不得进入 Conversation 数据归属。 |
| 审计 / 可追溯 | NFR-CONV-007: 对话空间、参与范围、可见范围和事实追加的关键变化必须可追溯。 | 后续验收应能判断关键变化的责任主体、发生时点、来源依据和影响范围是否可复盘。 |
| 审计 / 可追溯 | NFR-CONV-008: 跨域事实显化和维护性辅助动作必须可追溯。 | 后续验收应能判断显化引用来自哪个正式来源,维护动作依据哪些既有对话事实。 |
| 幂等 / 一致性 | NFR-CONV-009: 重复输入或重复消费不得形成互相冲突的对话真相。 | 同一业务意图被重复提交或重复感知时,结果不得产生多个互相矛盾的正式事实。 |
| 幂等 / 一致性 | NFR-CONV-010: 辅助结果和下游消费结果不得替代原始对话事实。 | 索引、投影、检索定位、变化感知和归档引用只能服务消费,不能成为新的业务事实来源。 |
| 可观测性 | NFR-CONV-011: 平台必须能稳定观察 Conversation 核心能力是否成立。 | 至少能判断空间建立、事实追加、授权消费、跨域显化和历史追溯是否成功或异常。 |
| 可观测性 | NFR-CONV-012: 平台必须能稳定观察依赖降级和边界违规风险。 | 至少能判断相邻依赖不可用、越权消费、正文越界保存、重复事实冲突等风险是否发生。 |

## 14. 验收标准

> 校准来源：
> - `design-calibration/00_req_step_14_acceptance_criteria.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“验收类别结论”和“一票否决项”小节，了解本章如何把核心闭环、功能、规则、数据和非功能要求收口为需求验收口径。

### 14.1 验收标准表

| 验收类别 | 验收项 | 验收条件 |
|---|---|---|
| 核心能力闭环验收 | 对话真相闭环成立 | 对话空间与参与范围、事实追加、授权消费、跨域显化、历史追溯五个节点能够共同成立,且任一节点缺失时不能判定为完整通过。 |
| 核心能力闭环验收 | Conversation 不退化为消息缓存 | 对话事实具备正式归属、参与 / 可见边界和可追溯历史,而不是仅作为 UI 消息、通知副本或 runtime 临时上下文存在。 |
| 功能能力验收 | 核心功能能力成立 | 对话空间与参与范围、协作事实追加沉淀、授权视野消费、跨域事实引用显化、对话历史追溯与复盘均能成立。 |
| 功能能力验收 | 外围增强能力不改变真相 | 索引 / 投影维护、长历史定位和及时感知只能提升消费效率,不能改变核心业务事实。 |
| 规则 / 边界验收 | 相邻仓职责不回流 | Chat UI、Workspace、Bridges、Runtime、Governance、Artifact、Identity、Observability、Archive 的正文或生命周期真相不由 Conversation 接管。 |
| 数据归属验收 | Conversation 真相数据归属正确 | 本仓只拥有对话空间、参与 / 可见范围、对话事实历史、对话内显化记录和追溯上下文。 |
| 数据归属验收 | 外部对象仅以快照或引用进入 | 成员、项目、治理、产物、外部平台、trace / audit material、归档对象等只能作为快照或引用进入本仓。 |
| 非功能验收 | 核心路径不被外围增强阻塞 | 外围增强能力或下游消费方降级时,核心空间建立、事实追加、授权消费和追溯仍能判断成立。 |
| 非功能验收 | 授权、安全和一致性达标 | 授权视野有效,重复输入不形成冲突真相,辅助结果不替代原始对话事实。 |
| 非功能验收 | 关键变化和风险可观察 | 对话核心状态、关键变化、依赖降级和边界违规风险能够被平台稳定观察。 |

### 14.2 一票否决项

- 核心能力闭环任一必要节点缺失。
- 对话事实可以脱离明确对话空间、参与范围或可见范围而存在。
- 已形成的对话业务事实可以被覆盖、抹除或改写成另一事实。
- 授权视野失效。
- 跨域事实显化接管来源仓原始真相。
- 相邻仓正文进入 Conversation 真相范围。
- Conversation 直接承担 LLM 推理、治理裁决、成员生命周期或外部平台协议生命周期。
- 关键变化不可追溯。

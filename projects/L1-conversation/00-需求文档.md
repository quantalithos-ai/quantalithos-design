## 1. 与 `product/` 的关系声明

L1-conversation 是**产品叙事直推型**需求仓。`product/最终目的.md` 和 `product/六域模型.md` 已明确:
- 对话是用户与 AI 员工协作的第一入口
- Conversation 是六域之一,不是 UI 附属品
- 对话内容是可审计的 Documented Information(9001 §7.5)

本文把这些叙事细化为仓级需求。

---

## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 的用户和 AI 员工协作首先发生在**对话**里。Conversation 不是简单的聊天记录,而是:
- 需求澄清的工作界面
- Gate 决策通知的载体
- Artifact 生命周期事件的展示面
- 群聊 / 私聊 / thread / channel 四形态统一承载

如果没有独立的对话域:
- work / governance / artifact 的事件无法自然呈现给人
- Turn 无法成为可审计的一等记录
- Chat / Console / Bridges 没有稳定的数据源

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `domain/conversation/README.md` 972 行 | 设计已清晰,仓级需求层未显式定义 |
| 实时推送 | AG-UI 17 事件映射已讨论 | 还没代码落地 |
| 四形态 | group / channel / dm / thread 已定义 | 下游 UI 如何一致消费未验证 |
| Turn 不可变 | 已设计 | 实际编辑/覆盖显示策略未验证 |
| 规模 | 1.5 亿 Turn/月(目标) | 存储/索引/归档压力大 |

### 2.3 为什么要做(量化依据)

- `product/最终目的.md` 的大部分价值都是通过对话体现的
- L5-chat / L5-console / L6-bridges 都直接依赖本仓
- governance.gate.raised / decided 等关键治理动作需要及时推到对话里

### 2.4 业务问题 vs 技术问题

- **业务问题**:用户如何和 AI 员工自然协作,并看到关键事件
- **技术问题**:Turn 不可变、实时推送、全文检索、Thread / visibility / AG-UI 映射

## 4. 用户与角色

### 4.1 目标用户群体

| 用户类型 | 描述 | 使用场景 |
|---|---|---|
| 终端用户 | 与 AI 员工私聊 / 群聊 | 需求、协作、审批 |

| Bridges | 把 Turn 映射到外部平台 | Mattermost / Slack / Telegram |

| 操作 | 普通用户 | Owner | AI Member | Auditor | 系统 |

| 读私聊 | 仅自己 | 仅自己 | 相关成员 | ❌(默认) | ✅ |
| 读 group | 成员可读 | 成员可读 | 成员可读 | 视审计权限 | ✅ |
| 发 Turn | 成员可发 | ✅ | ✅ | ❌ | ✅(系统事件 Turn) |
| 改 Turn | ❌ 原地不可改 | ❌ | ❌ | ❌ | ❌ |
| Archive Conversation | ❌ | ✅ | ❌ | ❌ | ✅(级联) |

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 用户与 Assistant 私聊(需求澄清)
2. 项目 group 中的团队协作
3. Gate 事件转为 decision Turn 推送到相关对话
4. Artifact 批准后在相关对话里广播 Turn
5. 外部桥接(bridges)消费 Turn 推送到 Mattermost / Slack

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **用户**,我想要 **和 Assistant 私聊**,以便 **快速表达需求并收到回应** |
| 优先级 | P0 |
| 验收条件 | **Given** 一个新建私聊 **When** 用户发送文本 **Then** 系统创建 `Turn(kind=user)` 并在 500ms 内推送给前端 |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **项目成员**,我想要 **在 group 里看到 Gate raised/decided 的通知**,以便 **及时参与决策** |
| 优先级 | P0 |
| 验收条件 | **Given** governance 发 `gate.raised` **When** conversation 订阅处理 **Then** 在相关 group 创建 `Turn(kind=gate)` |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **Chat 前端**,我想要 **订阅 AG-UI 17 事件映射流**,以便 **高效实时更新界面而不是全量轮询** |
| 优先级 | P0 |
| 验收条件 | **Given** 前端已订阅 StreamEvents **When** 有新 Turn **Then** 收到对应 AG-UI 事件 |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **审计员**,我想要 **Turn 不可变**,以便 **任何对话历史都可审计** |
| 优先级 | P1 |
| 验收条件 | **Given** 一个已存在 Turn **When** 用户尝试编辑 **Then** 系统创建新的覆盖显示 Turn,而不是原地 UPDATE |

### 5.3 替代流程

- 无权限读某 Conversation → 403 + 不返回任何 Turn 内容
- 网络断开 → StreamEvents 重连,按 last_event_id 续传
- 外部桥接失败 → 内部 Turn 保留,bridge 重试(非本仓实现)

## 8. 交互与界面需求

### 8.1 核心交互流程

- 私聊发送 / 接收
- group 中系统 Turn 插入
- Gate 卡片与决策反馈
- Thread 展开 / 回复
- 重连续传(last_event_id)

### 8.2 UX 约束

| 约束 | 说明 |
|---|---|
| 新 Turn 可见延迟 | < 500ms |
| Gate 决策通知 | 不得依赖手动刷新 |
| 历史编辑 | 仅覆盖显示,保留原始 Turn |
| 空 Conversation | 可展示欢迎 / onboarding message |

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 聚合 / 类型 | 生命周期 |
|---|---|---|
| Conversation | 聚合根 | active / archived / locked |
| Turn | 聚合内实体 | created 后不可变 |
| Participant | 值对象 / 关联 | add / remove |

### 9.2 数据关系

```
Conversation
  ├─ kind(group/channel/dm/thread)
  ├─ participants[]
  └─ turns[]
        ├─ user/member/system/gate/artifact
        └─ trace_id / refs / visibility
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| active turns | 热存 | PG 月分区 |
| 历史 turns | 冷存 | archive |
| archived conversation | 只读 | archive / restore |

## 10. 接口与依赖

### 10.1 外部系统依赖列表

| 依赖 | 类型 | SLA 要求 | 降级策略 | 文档 |
|---|---|---|---|---|
| PostgreSQL | 主库 / 分区表 | 99.95% | 不可用则服务阻断 |

| Chat / Bridges | 下游 UI / 桥接 | 99.9% | 重连 / 补发 |

### 10.2 上下游接口约定

**上游**:
- core(ConversationService proto)
- bus(StreamEvents / event 订阅)
- work / governance / artifact / identity 的事件

**下游**:
- chat / console / runner / sync 消费 StreamEvents
- bridges 消费 Turn / 事件流
- observability 消费审计 tap

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Turn 量增长过快 | 中 | 高 | 月分区 + archive |
| gate / artifact 事件转 Turn 漏转 | 中 | 高 | 事件回归测试 |
| Bridges 消费延迟 | 中 | 中 | retry / last_event_id 续传 |
| 编辑覆盖显示策略被误实现成 UPDATE | 低 | 极高 | 数据库约束 + 测试 |

### 12.2 边缘风险

- visibility / thread inheritance 复杂导致权限漏洞
- 全文检索选型错误导致后期迁移成本高
- AG-UI 17 事件映射语义漂移

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| Turn 编辑 UX 具体策略 | N1 前 | Chat / Console |
| 全文检索用 PG 还是 OpenSearch | N1 前 | conversation + SRE |
| thread visibility 继承规则 | N1 前 | conversation |

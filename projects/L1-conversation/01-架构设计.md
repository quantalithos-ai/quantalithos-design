## 2. 业务背景与驱动力

> 校准来源：
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_02_goals_constraints.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解业务驱动力和架构目标如何从需求边界收敛而来。

### 2.1 结构性驱动力

Quantalithos 的协作默认发生在对话中,但对话不能由 Chat、Workspace、Runtime 或 Bridges 各自复制一份消息语义来承担。随着 `L0-core`、`L0-bus`、`L0-sdk` 和 `L1-identity` 边界逐步稳定,`L1-conversation` 需要在架构层把对话事实收束为独立真相边界,让人类用户、AI member、系统事件和下游应用围绕同一份 Conversation 真相协作。

### 2.2 架构目标表

| 架构目标 | 说明 |
|---|---|
| 承载独立的 Conversation 真相边界 | 防止对话退化为 UI 消息、Runtime 临时上下文或外部平台副本。 |
| 支撑核心对话能力闭环完整成立 | 确保空间建立、事实沉淀、授权消费、跨域显化和历史追溯不断裂。 |
| 稳定区分真相数据、快照数据、引用数据和派生读模型 | 防止相邻仓正文和辅助结果混入 Conversation 真相。 |
| 让所有消费路径受授权视野约束 | 防止 Chat、Workspace、Runtime、Bridges 或审计读取绕过对话可见范围。 |
| 通过事件 / 引用边界显化跨域事实 | 防止 Conversation 接管 Work、Governance、Artifact 或 Identity 的来源真相。 |
| 让索引、投影、检索和变化感知只能从真相派生 | 防止外围增强能力反向改写业务事实。 |
| 保留关键变化的追溯接缝 | 支撑对话空间、参与 / 可见范围和跨域显化的复盘与审计。 |

## 3. 约束条件

> 校准来源：
> - `design-calibration/01_arch_step_01_requirement_baseline.md`
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解架构硬约束、当前阶段取舍和非目标如何形成。

### 3.1 架构硬约束

| 约束编号 | 硬约束 | 架构含义 |
|---|---|---|
| AHC-CONV-001 | Conversation 不能被 Chat / Workspace / Runtime 吸收 | 必须保留独立服务、crate 或 domain 边界。 |
| AHC-CONV-002 | Conversation 不执行 LLM 推理、治理裁决、成员生命周期或外部平台协议生命周期 | 必须通过外部边界协作,不能内聚这些职责。 |
| AHC-CONV-003 | 授权视野失效是一票否决 | 查询、订阅、事件输出和后台维护都必须经过可见范围约束。 |
| AHC-CONV-004 | 相邻仓正文进入 Conversation 是一票否决 | 数据层必须只保存本仓真相、快照或引用。 |
| AHC-CONV-005 | 关键变化必须可追溯 | 架构必须保留 audit / trace / outbox / evidence 接缝。 |

### 3.2 不可变约束

| 约束 | 说明 |
|---|---|
| 不允许 Chat UI 展示状态成为 Conversation 真相 | UI 状态不能反向定义本仓业务事实。 |
| 不允许 Workspace 聚合视图成为 Conversation 真相 | 个人 / 项目视野不能覆盖对话域自身边界。 |
| 不允许 Bridges 外部平台对象成为 Conversation 真相 | 外部平台生命周期不能侵入本仓。 |
| 不允许 Runtime 推理过程、tool 调用或 memory 写入成为 Conversation 真相 | 对话事实不能与 agent loop 内部状态混淆。 |
| 不允许 Governance / Artifact / Identity / Work 正文进入 Conversation 真相 | 来源仓真相不得漂移进 Conversation。 |
| 不允许绕过授权视野消费对话事实 | 这是本仓核心安全边界。 |
| 不允许索引、投影、检索、变化感知反写真相 | 派生结构不能成为第二业务事实来源。 |

### 3.3 当前阶段可接受取舍

| 取舍 | 当前口径 |
|---|---|
| 长历史检索与定位 | 作为外围增强处理,只要求从 Conversation 真相派生且受授权视野约束。 |
| 对话变化及时感知 | 只保留“可感知、可授权、不可反写真相”的能力边界,不提前锁定协议形态。 |
| 索引 / 投影维护 | 作为辅助消费结构处理,不把 projection 设计为独立 truth。 |
| 量化性能 / 容量指标 | 不继承旧 P95 / 月度 Turn 数字作为硬约束,后续测试和验收再量化。 |
| Archive 长期交接 | 只确认 Archive 是下游协作方,不在架构主线展开长期归档和恢复策略。 |

### 3.4 架构非目标

| 非目标 | 不展开原因 |
|---|---|
| 不设计 Chat UI 架构 | 页面、组件和客户端状态属于 `L5-chat`。 |
| 不设计 Workspace 聚合视图架构 | 个人视野、项目视野和 inbox 属于 `L1-workspace`。 |
| 不设计 Bridges 外部平台协议架构 | 外部平台协议生命周期属于 `L6-bridges`。 |
| 不设计 Runtime 推理架构 | agent loop、LLM 调用、tool 调用和 memory 属于 `L2-runtime` / `L2-tools`。 |
| 不设计 Governance 裁决架构 | Gate、Policy、Approval 结论属于 `L1-governance`。 |
| 不设计 Artifact 正文和版本架构 | 产物正文、版本、证据链和生命周期属于 `L1-artifact`。 |
| 不设计 Identity 生命周期和认证授权架构 | 成员生命周期、认证和授权裁决属于 `L1-identity` 或安全 / 治理边界。 |
| 不设计全局 Observability / Archive 架构 | 全局 trace store、metrics、长期归档和恢复属于 `L4-observability` / `L4-archive`。 |

## 4. 职责边界

> 校准来源：
> - `design-calibration/01_arch_step_03_responsibility_boundary.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_03_responsibility_boundary.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解职责边界和边界红线如何收敛。

### 4.1 职责边界表

| 职责项 | 类型 | 说明 |
|---|---|---|
| Conversation 真相边界承载 | 做 | 本仓区别于 Chat、Workspace、Runtime 和 Bridges 的核心职责。 |
| 对话空间、参与范围和可见范围维护 | 做 | 若不由本仓承载,对话事实将失去稳定归属和可见边界。 |
| 对话事实历史追加沉淀 | 做 | 协作过程可追溯的基础职责。 |
| 授权视野内的对话事实消费基础 | 做 | 查询、订阅和下游消费不得绕过可见范围。 |
| 跨域正式事实的对话内引用显化 | 做 | 只负责让来源事实在对话中可见,不拥有来源正文。 |
| 派生辅助结构维护 | 做 | 索引、投影、检索和变化感知只能从 Conversation 真相派生。 |
| 对话关键变化追溯接缝 | 做 | 对话范围、事实追加和跨域显化必须支撑审计与复盘。 |
| Chat UI 展示和客户端交互状态 | 不做 | 属于 `L5-chat`,否则 UI 状态会反向定义 Conversation 真相。 |
| Workspace 个人 / 项目聚合视图 | 不做 | 属于 `L1-workspace`,否则聚合视图会覆盖对话域边界。 |
| 外部平台协议适配和外部消息生命周期 | 不做 | 属于 `L6-bridges`,否则外部平台生命周期会侵入本仓。 |
| Runtime 推理、tool 调用和 memory 写入 | 不做 | 属于 `L2-runtime` / `L2-tools`,否则结果事实与运行过程会混淆。 |
| Governance 裁决 | 不做 | Gate、Policy、Approval 结论属于 `L1-governance`。 |
| Artifact 正文、版本和证据链真相 | 不做 | 产物正文和生命周期属于 `L1-artifact`。 |
| Identity 生命周期、认证和授权裁决 | 不做 | 成员真相属于 `L1-identity`,认证授权属于安全 / 治理边界。 |
| 全局观测、长期归档和恢复主体架构 | 不做 | 属于 `L4-observability` / `L4-archive`。 |

### 4.2 边界红线

- 不得将 Chat UI 展示状态、客户端排序、折叠、已读或草稿状态写成 Conversation 真相。
- 不得将 Workspace personal / project view 写成 Conversation 真相。
- 不得将 Runtime memory、推理过程或 tool 调用轨迹写成 Conversation 业务事实。
- 不得将 Governance、Artifact、Work、Identity 的来源正文复制为 Conversation truth。
- 不得让外部平台 message id、channel lifecycle 或平台账号生命周期成为 Conversation 内部真相。
- 不得让 projection、index、search result、notification state 或 stream cursor 反写真相。
- 不得绕过参与范围和可见范围向下游输出对话事实。
- 不得通过维护任务隐式修复、覆盖或删除业务对话事实。

## 5. 系统边界与上下文

> 校准来源：

> 延伸阅读：

```text
            |                              |                              |
            | 输入 / 依赖                  | 输入                         | 输入
```

该图仅表达本仓与正式上下文对象之间的边界关系与输入 / 输出方向,不表达接口、事件、实现组件或运行时顺序。

### 5.2 上下游与输入 / 输出面表

| 对象 | 关系方向 | 关系类型 | 输入 / 输出面 | 说明 |
|---|---|---|---|---|
| `L0-core` | 输入 | 依赖 | 共享 ID、ActorRef、TraceContext、Error、metadata、通用契约 | 本仓依赖统一引用和追溯口径,不得重新定义 L0 契约。 |
| `L0-bus` | 输入 / 输出 | 依赖 | 平台事件协作主干、变化感知和跨仓协作边界 | Bus 不拥有 Conversation 真相,但承载跨仓协作和下游感知。 |
| `L1-identity` | 输入 | 来源 | 成员、AI member、system actor 和参与者引用 | Conversation 只保存引用 / 展示快照,不拥有成员生命周期。 |
| `L1-work` | 输入 | 来源 | 项目、工作项、项目成员上下文引用 | 项目型对话依赖其锚点,但项目真相仍归 `L1-work`。 |
| `L1-governance` | 输入 | 来源 | Gate、Policy、Approval 等治理结论引用 | Conversation 只显化治理结论引用,不裁决治理结果。 |
| `L1-artifact` | 输入 | 来源 | 产物、版本、证据对象引用 | Conversation 只显化产物引用或摘要,不保存产物正文。 |
| `L0-sdk` | 输出 | 消费 | 默认 client / integration access | SDK 封装消费路径,不反写 Conversation 真相。 |
| `L5-chat` | 输出 | 消费 | 聊天入口所需对话事实和变化感知 | Chat 负责展示和交互状态,Conversation 只提供事实。 |
| `L1-workspace` | 输出 | 消费 | 个人视野、项目视野和 inbox 聚合所需对话事实 | Workspace 只聚合视图,不拥有 Conversation 空间真相。 |
| `L2-runtime` | 输入 / 输出 | 消费 / 协作 | AI member 授权上下文读取和结果性对话事实输入 | Runtime 执行推理和工具循环,Conversation 只记录正式结果事实。 |
| `L6-bridges` | 输入 / 输出 | 协作 | 外部平台输入 / 输出映射边界 | Bridges 负责外部协议生命周期,内部 Conversation 不依赖外部平台对象成立。 |
| `L4-observability` | 输出 | 消费 | trace、audit、运行观察和风险材料 | 观测系统消费追溯材料,不改变业务事实。 |
| `L4-archive` | 输出 | 消费 | 归档、导出和长期留存材料 | Archive 负责长期归档和恢复策略,Conversation 保留交接边界。 |

### 5.3 依赖失效降级口径

| 对象 | 失效情况 | 架构口径 |
|---|---|---|
| `L0-core` | 共享契约、引用或 trace 口径不稳定 | 不新增正式契约语义,不得自行补造共享类型。 |
| `L0-bus` | 事件协作主干不可用 | 已形成 Conversation 真相不得丢失;变化感知、跨仓协作和下游通知可挂起或延迟。 |
| `L1-identity` | 成员或 actor 引用暂不可解析 | 保留既有 actor 引用和展示快照;不得补造成员生命周期结论。 |
| `L1-work` / `L1-governance` / `L1-artifact` | 来源事实暂不可解析 | 保留引用缺失或未解析状态;不得复制或推断来源仓正文。 |
| `L0-sdk` / `L5-chat` / `L1-workspace` | 下游消费方不可用 | 不改变 Conversation 真相,只影响对应消费面体验或聚合结果。 |
| `L2-runtime` / `L6-bridges` | 协作输入方或外部映射不可用 | 相关参与能力降级,内部 Conversation 真相仍独立成立。 |
| `L4-observability` / `L4-archive` | 观测或归档消费不可用 | 本仓保留追溯接缝和交接材料,不接管全局长期存储职责。 |

## 6. 限界上下文与子域划分

> 校准来源：
> - `design-calibration/01_arch_step_05_bounded_context_subdomains.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_05_bounded_context_subdomains.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解核心子域、支撑上下文和本地影子层如何划分。

### 6.1 子域 / 上下文划分表

| 名称 | 类型 | 作用 | 与其他部分的关系 |
|---|---|---|---|

### 7.2 运行单元说明表

| 对象 | 类型 | 主要职责 | 说明 |
|---|---|---|---|
| 下游消费 / 协作入口边界 | 外部边界 | 承接 SDK、Chat、Workspace、Runtime、Bridges 等正式消费或协作进入点。 | 不属于本仓内部运行承载。 |
| 事件协作 / 追溯交接边界 | 外部边界 | 承接跨仓事件协作、变化感知交接、追溯材料交接和归档交接。 | 不代表本仓拥有 bus、observability 或 archive 真相。 |
| Conversation 同步入口 | 同步入口单元 | 承接同步读写、追溯读取和受控维护触发。 | 不在本章定义 API、RPC、command、query 或鉴权细节。 |
| Conversation 异步输入 | 异步消费单元 | 承接来自事件协作边界的正式异步输入或相邻真相域已形成事实的显化触发。 | 不直接接管来源仓正文,不绕过 Conversation 真相核心。 |
| Conversation 后台派生维护 | 后台处理单元 | 承接派生视图、索引、检索辅助、变化感知、重建和交接材料形成。 | 不生成新业务事实,不得覆盖真相。 |
| Conversation 真相存储承载 | 正式存储承载 | 承载对话空间、参与范围、可见范围、事实历史、显化记录和追溯上下文。 | 本仓唯一正式真相承载,不写具体数据库或表结构。 |
| 派生视图 / 索引承载 | 正式存储承载 | 承载查询、检索、变化感知和下游消费所需的派生辅助结果。 | 可重建、可延迟,不得成为第二 truth。 |

### 7.3 部署关系结论

- P0 可以把 `Conversation 同步入口`、`Conversation 异步输入` 和 `Conversation 后台派生维护` 同部署,但逻辑运行职责必须分清。
- `Conversation 真相存储承载` 与 `派生视图 / 索引承载` 即使物理同库,架构语义也必须区分。
- 当吞吐、隔离、恢复、观测或归档压力上升时,异步输入消费和后台派生维护可以拆分为独立 worker。
- `事件协作 / 追溯交接边界` 是外部运行边界,不意味着本仓拥有 `L0-bus`、`L4-observability` 或 `L4-archive` 的主体架构。
- 缓存、具体搜索后端、具体推送协议和具体数据库产品不进入本步主图。

| `外部能力接缝角色` | 正式边界、编排 / 承接角色、必要的运行期协作对象 | 直接依赖核心存储结构;直接改变核心语义;越过授权范围输出事实 | 外部能力只能通过受控接缝进入或消费。 |
| `派生消费辅助角色` | 核心语义角色、授权范围和正式派生规则 | 生成新业务事实;覆盖核心事实;绕过可见范围向下游输出 | 投影、索引、检索和变化感知都只是消费辅助,可重建且不得反写。 |
| `技术承载角色` | 核心定义的正式状态、派生规则和承载契约 | 决定业务状态、可见范围、跨域显化含义或追溯语义 | 存储、事件、索引、缓存等技术选择只能支撑架构,不能定义架构。 |

| `L1-work` | 协作方 | 运行期 / 事件协作 | 是 | 项目型对话依赖项目上下文,但项目真相不归本仓。 |
| `L1-governance` | 依赖方 / 协作方 | 运行期 / 事件协作 | 是 | 治理结论可显化到对话,裁决真相仍归 governance。 |

| `L4-observability` / `L4-archive` | 被依赖方 | 运行期 / 事件协作 | 是 | 观测和归档消费追溯材料,不改变业务事实。 |
| `L5-console` / `L6-marketplace` | 无直接主链关系 | 运行期 / 事件协作 | 否 | 当前对话真相闭环不依赖这些仓。 |

### 8.4 禁止依赖表

| 禁止依赖 | 禁止原因 | 正确协作方式 |
|---|---|---|
| `L1-conversation -> L5-chat` | Chat 是产品入口和展示层,不能反向决定对话真相 | Chat 经 SDK / 正式服务边界消费授权对话事实。 |

| `L1-conversation -> L2-runtime` | Runtime 拥有推理循环和临时上下文,不拥有对话历史 | Runtime 读取授权上下文并通过正式边界追加结果性事实。 |

## 9. 数据所有权与一致性策略

> 校准来源：

> 延伸阅读：

### 9.1 数据归属表

| 数据项 | 数据类型 | 归属说明 | 边界说明 |
|---|---|---|---|
| 对话空间 | 正式真相数据 | 由 `L1-conversation` 拥有正式真相,定义对话事实归属边界。 | 不等同于 Chat 会话窗口或 Workspace 入口。 |
| 对话参与范围 | 正式真相数据 | 由本仓拥有对话域内正式参与范围。 | 成员有效性来源仍归 `L1-identity`,本仓只拥有对话内参与关系。 |
| 对话可见范围 | 正式真相数据 | 由本仓拥有对话域内事实可见边界。 | 不等同于全局授权裁决或 UI 展示状态。 |
| 对话事实历史 | 正式真相数据 | 由本仓拥有正式追加后的对话事实历史。 | 不保存 Runtime 推理过程、外部平台正文或相邻仓正文。 |
| 对话内跨域显化记录 | 正式真相数据 | 由本仓拥有“外部事实在本对话中被显化”的记录。 | 来源事实正文、裁决、产物版本或项目状态仍归来源仓。 |
| 对话追溯上下文 | 正式真相数据 | 由本仓拥有对话域内追溯、复盘和责任边界上下文。 | 不等同于全局 trace store、metrics、长期归档包正文。 |
| 成员 / actor、项目 / 工作、治理 / 产物显示摘要 | 快照 / 投影数据 | 本仓可为历史阅读和降级显示保留快照。 | 来源对象生命周期和正文仍归来源仓。 |
| 对话消费投影 / 检索索引 / 变化感知游标 | 快照 / 投影数据 | 本仓可维护从 Conversation 真相派生的消费辅助数据。 | 可延迟、可重建,不得反写对话事实。 |
| 成员 / actor、项目 / 工作项、治理结论、产物、外部平台消息、trace / archive 对象引用 | 引用关系数据 | 本仓只保存显化、消费、追溯或交接所需引用关系。 | 引用存在不代表本仓拥有外部正文。 |
| Chat UI 展示状态、Workspace 聚合视图、Runtime memory / 推理过程、外部平台协议生命周期、治理裁决正文、Artifact 正文、成员画像、认证凭据、全局观测日志、长期归档包正文 | 明确不拥有的正文 / 真相 | 这些正文或主真相由相邻仓、外部平台或横切系统拥有。 | 如需要在对话中出现,只能通过引用、快照或显化记录表达。 |

### 9.2 一致性策略表

| 数据关系 / 场景 | 一致性口径 | 失败处理口径 | 说明 |
|---|---|---|---|
| 对话空间、参与范围、可见范围与事实追加之间的关系 | 强一致 | 明确失败或保持未成立状态,不得落为部分完成事实 | 核心事实不能脱离空间、参与和可见边界成立。 |
| 跨域显化记录与本对话事实历史之间的关系 | 强一致 + 引用有效性一致 | 显化引用不可接受时挂起或标记不可解析,不得伪造来源正文 | 显化记录属于本仓,来源正文不属于本仓。 |
| 对话追溯上下文与事实历史之间的关系 | 强一致 | 不形成缺失追溯锚点的正式关键事实 | 追溯上下文是复盘和审计的对话域基础。 |
| Conversation 真相到消费投影 / 检索索引 / 变化感知游标 | 最终一致 | 保留旧视图、过期标记或挂起重建,不得反写真相 | 派生辅助可以延迟和重建。 |
| 外部来源真相到本地展示快照 | 最终一致 | 保留旧快照或未解析状态,不得补造外部正文 | 快照服务稳定阅读,不改变来源归属。 |
| Conversation 真相到下游消费 / 观测 / 归档材料 | 最终一致 | 交接可挂起或延迟,已形成的 Conversation 真相不得丢失 | 下游消费失败不能反向改变业务事实。 |
| 外部对象引用有效性变化 | 引用有效性一致 | 表达引用失效、待刷新或不可解析,不得复制正文补齐 | 引用关系成立不等于正文归属转移。 |
| 明确不拥有正文被请求写入 Conversation | 边界约束一致 | 拒绝、挂起或转换为引用 / 快照 / 显化记录,不得作为本仓真相保存 | 这是防止串仓的最高优先级边界。 |

### 9.3 数据边界示意图

```text
+--------------------------------------------------------------+
|                    L1-conversation 数据边界                  |
|                                                              |
|   +--------------------------+                               |
|   | 正式真相数据             |                               |
|   | space / scope / facts    |                               |
|   | manifestation / trace    |                               |
|   +------------+-------------+                               |
|                | 派生 / 引用                                 |
|                v                                             |
|   +------------+-------------+      +----------------------+  |
|   | 快照 / 投影数据          |      | 引用关系数据         |  |
|   | views / indexes / snaps  |      | external object refs |  |

|                | 不反写                         | 只引用       |
+================+===============================+==============+
```

### 9.4 数据边界说明

`L1-conversation` 的数据所有权边界是“拥有对话真相,本地保留消费辅助,引用外部真相,明确排除外部正文”。对话内显化记录属于 Conversation,但被显化的治理、产物、项目、成员或外部平台正文不属于 Conversation。快照、投影和索引可以提升消费体验,但它们的延迟、失效或重建不能改变正式对话事实。

## 10. 关键交互与通信方式

> 校准来源：
> - `design-calibration/01_arch_step_09_interactions_communication.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_09_interactions_communication.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解同步、异步和后台承接口径如何形成。

### 10.1 关键交互场景表

| 交互场景 | 交互边界 | 交互目的 | 边界说明 |
|---|---|---|---|
| 对话空间与范围变更 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 判断对话空间、参与范围或可见范围变化是否正式成立。 | 该场景会改变 Conversation 真相,必须即时收口。 |
| 协作事实追加 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 判断人类、AI member 或系统可见事实能否追加为正式对话事实。 | 事实追加必须受空间、参与范围、可见范围和追溯约束。 |
| 授权读取与追溯读取 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 在授权视野内读取对话事实、历史和追溯上下文。 | 读取需要即时判断可见边界,但不得改变业务事实。 |
| 显式跨域显化请求 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 判断外部引用是否可在当前对话中被显化。 | 显化记录属于本仓真相,来源正文不归本仓。 |
| 相邻真相域事实送达 | 事件协作 / 追溯交接边界 ↔ Conversation 异步输入 | 承接已经由来源仓正式形成、可进入对话视野的事实或引用变化。 | 该场景是外部正式结果送达,不是内部函数流程。 |
| Conversation 事实变化传播 | Conversation 真相边界 ↔ 事件协作 / 下游消费边界 | 将已经成立的对话事实变化传播给下游或协作方。 | 传播失败不能反向取消已经成立的 Conversation 真相。 |
| 派生消费辅助维护 | Conversation 真相边界 ↔ 派生视图 / 索引承载 | 维护投影、检索索引、变化感知游标和消费辅助结果。 | 派生结果服务消费,不得成为第二 truth。 |
| 外部展示快照与引用状态刷新 | 外部能力接缝 ↔ 后台派生维护边界 | 刷新成员、项目、治理、产物等展示快照或引用可解析状态。 | 快照和引用状态可以延迟,不改变来源真相归属。 |
| 追溯 / 观测 / 归档材料交接 | Conversation 真相边界 ↔ 事件协作 / 追溯交接边界 | 将追溯、观测或归档所需材料交给横切系统或归档系统。 | 本仓保留对话域追溯上下文,不拥有全局日志或归档正文。 |

### 10.2 通信方式判断表

| 交互场景 | 推荐通信方式 | 不宜采用的方式 | 失败处理口径 |
|---|---|---|---|
| 对话空间与范围变更 | 同步请求 / 响应类交互 | 不宜以异步事件或后台承接作为主路径 | 明确失败、拒绝或暂不可处理,不得先返回已成立。 |
| 协作事实追加 | 同步请求 / 响应类交互 | 不宜伪装成后台成功后再补写事实 | 明确失败或保持未追加状态,不得落为部分事实。 |
| 授权读取与追溯读取 | 同步请求 / 响应类交互 | 不宜以异步推送替代正式读取判断 | 返回可见结果、不可见、不可解析或暂不可读取。 |
| 显式跨域显化请求 | 同步请求 / 响应类交互 | 不宜由后台随意创建显化记录 | 引用不可接受时拒绝或挂起,不得伪造来源正文。 |
| 相邻真相域事实送达 | 异步事件 / 回调类交互 | 不宜要求来源仓同步穿透本仓核心 | 保持未送达、待显化或不可解析状态。 |
| Conversation 事实变化传播 | 异步事件 / 回调类交互 | 不宜写成同步 fan-out 主路径 | 保持未消费、待交接或延后传播状态。 |
| 派生消费辅助维护 | 后台任务 / 延后承接类交互 | 不宜阻塞核心同步变更 | 保留旧视图、过期标记或挂起重建。 |
| 外部展示快照与引用状态刷新 | 后台任务 / 延后承接类交互 | 不宜把快照刷新写成核心事实成立前置 | 保留旧快照、未解析引用或待刷新状态。 |
| 追溯 / 观测 / 归档材料交接 | 异步事件 / 回调类交互 | 不宜要求横切系统同步决定业务事实 | 保持待交接、未消费或延后归档状态。 |

### 10.3 简化交互示意图

```text
+-----------------------------+        +-----------------------------+
| 下游消费 / 协作入口边界     |        | 事件协作 / 来源事实边界     |
| sdk / chat / workspace      |        | bus / source truth domains  |
| runtime / bridges           |        +-------------+---------------+
+-------------+---------------+                      |
              | [sync request / response]            | [async event / callback]
              v                                      v
+-------------+---------------+        +-------------+---------------+
| Conversation 同步入口       |        | Conversation 异步输入       |
+-------------+---------------+        +-------------+---------------+
              |                                      |
              +------------------+-------------------+
                                 |
                                 v
                      +----------+-----------+
                      | Conversation 真相边界 |
                      +----+-------------+---+
                           |             |
             [async event] |             | [background]
                           v             v
             +-------------+------+   +--+----------------+
             | 下游 / 追溯 / 归档 |   | 派生消费辅助承接 |
             | 交接边界           |   |                  |
             +--------------------+   +-------------------+
```

同步请求 / 响应用于即时判断核心状态是否成立。异步事件 / 回调用于已成立事实传播或外部结果送达。后台任务 / 延后承接用于派生、刷新、重建和交接材料形成,不得反写真相。

## 11. 关键技术选型

> 校准来源：
> - `design-calibration/01_arch_step_10_technology_choices.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_10_technology_choices.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解机制级技术选型如何收敛。

### 11.1 关键技术机制表

| 技术机制 | 解决的问题 | 采用理由 | 代价 / 约束 |
|---|---|---|---|
| 正式承接层隔离外部输入与核心语义 | 防止 Chat、Workspace、Runtime、Bridges 或来源仓输入直接打穿 Conversation 核心。 | 外部能力只能经正式接缝进入,核心语义不能被消费方或来源仓反向定义。 | 增加边界转换、状态解释和后续实现约束。 |
| 引用 / 快照 / 显化记录承接跨域事实 | 防止 Work、Governance、Artifact、Identity 等来源真相漂移进 Conversation。 | Conversation 需要让外部事实在对话中可见,但不能拥有来源正文和生命周期。 | 需要表达未解析引用、旧快照、显化失败和来源不可用状态。 |
| 追加式对话事实历史 | 防止已成立的对话事实被维护任务、投影或下游体验直接覆盖。 | 对话事实历史是审计、复盘和协作基线,必须保持可追溯。 | 后续需要通过显式更正、撤回或补充事实表达变化。 |
| 授权视野作为消费强制边界 | 防止查询、订阅、变化感知和下游读取绕过参与范围或可见范围。 | 授权消费是 Conversation 核心闭环的一部分。 | 所有读模型、变化感知和追溯读取都必须携带可见边界判断。 |
| 派生只读视图 / 索引承接下游消费 | 防止下游直接依赖核心真相结构或把 projection 变成第二 truth。 | 下游需要稳定消费、检索和变化感知,但核心模型不能被展示和聚合需求绑定。 | 增加最终一致、旧视图、重建和延迟解释成本。 |
| 事件最终一致承接跨边界传播 | 防止所有下游消费、观测、归档和来源变化都压入同步强收口链路。 | 已成立事实的传播和外部结果送达适合异步承接。 | 增加未送达、未消费、待交接和追踪状态的表达成本。 |
| 后台延后承接派生、刷新和重建 | 防止投影、检索、快照刷新、引用解析或重建阻塞核心事实成立。 | 派生关系最终一致,适合后台承接。 | 后续必须提供挂起、过期、未解析和重建失败等状态口径。 |
| 追溯 / 审计 / 归档交接接缝 | 防止关键变化不可复盘,也防止 Conversation 接管全局观测和归档正文。 | 本仓需要保留对话域追溯上下文,但 Observability / Archive 主体职责归外部仓。 | 需要维护交接材料和引用状态,并解释交接失败不等于真相失效。 |

### 11.2 当前不采用口径表

| 不采用口径 | 不采用原因 | 正确落点 |
|---|---|---|
| 具体 API / 实时推送 / AG-UI 协议作为架构主线 | 协议形态不应反向决定 Conversation 真相边界。 | 关键交互、概要设计或详细设计。 |
| 具体数据库、搜索后端、消息产品或缓存产品作为本章选型 | 产品选择属于实现承载,当前还未进入产品级技术比较。 | 概要设计、详细设计或实施计划。 |
| 完整事件溯源方案作为当前必选 | Conversation 需要追加式事实历史和事件协作,但不等于已经选择完整 ES 架构。 | 备选方案取舍或详细设计。 |
| 所有数据强一致 | 会让派生视图、下游交接、归档和外部刷新阻塞核心写入。 | 分层一致性策略。 |
| 所有交互异步化 | 会让空间、范围、事实追加和授权读取缺少即时成立 / 失败口径。 | 通信方式判断。 |
| 旧 P95、并发连接数、月度 Turn 容量作为硬性架构选型 | 当前缺少新版需求基线下的正式负载模型。 | 测试方案、验收标准或实施阶段容量验证。 |

## 12. 备选方案与取舍

> 校准来源：
> - `design-calibration/01_arch_step_11_alternatives_tradeoffs.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_11_alternatives_tradeoffs.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解当前主线方案和替代路径为什么这样取舍。

### 12.1 当前主线方案

```text
独立 Conversation 真相核心
  + 正式承接层隔离外部输入
  + 引用 / 快照 / 显化记录承接跨域事实
  + 追加式对话事实历史
  + 授权视野强制消费边界
  + 派生只读视图 / 索引承接下游消费
  + 事件最终一致承接跨边界传播
  + 后台延后承接派生、刷新和重建
  + 追溯 / 审计 / 归档交接接缝
```

该方案的核心判断是:Conversation 的 truth center 必须独立稳定,外部能力只能经正式边界进入,下游消费不能直接绑定核心结构,派生和交接可以延迟收敛但不能反写真相。

### 12.2 方案路径比较表

| 方案路径 | 主要收益 | 主要代价 / 约束 | 当前结论 | 说明 |
|---|---|---|---|---|
| 独立真相核心 + 正式承接 + 引用 / 快照 / 显化 + 派生只读 + 事件最终一致 + 后台承接 | 边界稳定,来源真相不漂移,下游不反向绑定核心。 | 边界层更多,状态解释更严格。 | 采用 | 唯一同时满足数据归属、授权消费和通信方式的主线。 |
| 直连核心路径 | 初期接入更快。 | 外部输入和下游消费会反向绑定核心模型。 | 不采用 | 破坏依赖方向和核心保护边界。 |
| 完整事件溯源优先路径 | 历史表达强,对审计叙事友好。 | 过早锁定实现范式,提高 P0 复杂度。 | 保留观察 | 当前采用追加式事实历史和事件协作,但不把完整 ES 作为 P0 必选。 |
| 全同步收口路径 | 即时结果感强。 | 会把投影、检索、归档、观测和外部快照刷新压入核心链路。 | 不采用 | 与最终一致和后台承接口径冲突。 |
| 全异步命令 / 事件路径 | 解耦和吞吐弹性强。 | 对话空间、范围、事实追加和授权读取缺少即时成立 / 失败判断。 | 不采用 | 核心真相成立判断不能全部异步化。 |
| Projection-first / Search-first 路径 | 下游读取、搜索和实时感知体验更直接。 | 派生结构会靠近 truth center,形成第二事实来源。 | 不采用 | 检索、投影和变化感知只能派生,不得反写。 |
| Source-copy 路径 | 本地读取简单,短期降级显示能力强。 | 直接打穿数据归属边界。 | 不采用 | 与“明确不拥有正文 / 真相”冲突。 |

### 12.3 不进入本章正式比较的方向

| 方向 | 不进入比较的原因 | 正确处理 |
|---|---|---|
| Chat UI 拥有 Conversation truth | Chat 是产品入口和展示层,不是对话真相仓。 | Chat 经 SDK / 正式边界消费对话事实。 |
| Workspace 聚合视图拥有 Conversation truth | Workspace 只聚合个人 / 项目视野,不拥有对话空间真相。 | Workspace 只读消费查询、投影或事件协作结果。 |
| Runtime memory / agent loop 拥有 Conversation truth | Runtime 推理过程和 memory 不属于对话事实历史。 | Runtime 读取授权上下文并通过正式边界追加结果性事实。 |
| Bridges 外部平台副本拥有 Conversation truth | 外部平台协议和生命周期归 Bridges。 | Bridges 映射外部输入 / 输出,Conversation 只承接正式结果。 |
| Governance / Artifact / Identity / Work 正文并入 Conversation | 来源仓拥有各自正文和生命周期真相。 | Conversation 只保存引用、快照或显化记录。 |

## 13. 横切关注点

> 校准来源：
> - `design-calibration/01_arch_step_12_cross_cutting_concerns.md`
>
> 延伸阅读：
> - 建议继续阅读 `design-calibration/01_arch_step_12_cross_cutting_concerns.md` 的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解横切约束如何绑定 Conversation 主线。

### 13.1 横切关注点约束表

| 横切关注点 | 作用范围 | 约束要求 | 保护目标 |
|---|---|---|---|
| 授权视野强制生效 | 同步读取、订阅、变化感知、追溯读取、下游消费和派生视图 | 所有消费都必须受参与范围和可见范围约束。 | 保护 Conversation 事实不被越权消费。 |
| 外部输入正式承接 | Runtime、Bridges、来源仓事件、运维 / 审计入口和相邻真相域输入 | 外部能力必须经正式承接层转换为引用、快照、显化记录或事实追加。 | 保护核心真相不被外部输入反向定义。 |
| 明确不拥有正文 | 跨域显化、历史阅读、快照刷新、归档交接和维护动作 | 禁止通过业务写入、配置、维护、派生或降级路径吸收相邻仓正文。 | 保护来源真相归属和本仓数据边界。 |
| 关键变化可复盘 | 对话空间、参与范围、可见范围、事实追加、跨域显化、维护性动作 | 关键状态变化和关键判断结果必须保留可追溯材料或状态。 | 保护协作复盘、责任边界和来源核验能力。 |
| 核心能力状态可见 | 对话空间建立、范围变化、事实追加、授权消费、跨域显化、历史追溯 | 架构必须能区分成功、失败、不可见、不可解析、暂不可处理和挂起等状态。 | 保护主线是否真实成立的可见性。 |
| 失败不伪成功 | 同步收口、异步送达、后台承接、引用解析和归档交接 | 未成立状态不得返回或记录为已成立。 | 保护核心真相和失败口径。 |

### 14.3 演进边界说明

`L1-conversation` 的演进必须优先保护现有主线,而不是扩张职责。能先在派生层、引用层、交接层、后台承接层解决的问题,不应直接改变核心 truth center;只有当审计重放、容量隔离或恢复要求明确证明当前事实模型不足时,才考虑核心结构演进。每个后续阶段都必须继续满足四条底线:不复制来源正文,不绕过授权视野,不让派生反写,不让下游消费反向绑定核心模型。

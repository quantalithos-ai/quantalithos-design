### 1.2 本文定位

`L1-conversation` 的概要设计不是旧版聊天对象说明,也不是详细设计提前展开。本文位于新版 `00-需求文档.md` 与 `01-架构设计.md` 之后,负责把需求与架构边界转译成可实现的代码主体骨架。

本文的核心定位是:

```text
L1-conversation 是独立 Conversation truth center。
它拥有对话空间、参与范围、可见范围、对话事实、跨域显化记录和对话域追溯上下文。
它不拥有 Chat UI、Workspace 聚合视图、Runtime 推理过程、Bridges 外部消息、来源仓正文、全局观测日志或长期归档包正文。
```

### 3.2 结构性约束

| 约束 | 说明 |
|---|---|
| 独立 Conversation truth center | 后续代码主体、主要组成部分和关键对象必须围绕对话空间、参与范围、可见范围、对话事实历史、跨域显化记录和追溯上下文展开 |
| 编译依赖与跨仓裁剪 | 核心语义只能编译期依赖 `L0-core`;其他仓通过引用、快照、事件、port 或外部接缝协作 |
| 数据归属分层 | 本仓拥有 Conversation truth、派生消费辅助和外部引用关系;不拥有相邻仓正文或外部平台生命周期 |
| 授权视野强制 | 查询、订阅、变化感知、派生输出、追溯读取和下游消费必须受参与范围与可见范围约束 |
| 追加与追溯 | 已成立的对话事实和关键状态变化必须可追溯,不得被投影、维护任务或展示层覆盖 |
| 跨域显化 | 来源事实进入对话只能形成引用、快照、显化记录或结果性事实追加,不得转移来源 truth |
| 派生只读 | 投影、索引、检索、变化感知游标和展示快照只能从 Conversation truth 派生,不能生成新业务事实 |
| 一致性分层 | 对话空间、范围、事实追加、显化和追溯锚点强一致收口;传播、投影、快照刷新、引用解析和交接最终一致 |
| 通信方式分层 | 核心成立和授权读取同步收口;已成立事实传播和外部结果送达异步承接;派生、刷新、重建和交接后台处理 |
| 失败状态显式 | 不可解析引用、过期投影、待传播事件、待重建索引、待交接材料和外部依赖降级必须表达为独立状态或 marker |
| 配置不可越界 | 配置只能影响运行承载、派生策略、刷新节奏、保留期限、限流或外部接缝参数,不得改变核心边界 |
| 协议与产品中立 | 概要设计不提前锁定协议、数据库、搜索、队列、缓存、容量数字或部署产品 |

### 3.3 后续章节门禁

| 后续章节 | 门禁判断 |
|---|---|
| 代码主体框架 | 是否保护核心语义,并把编排、外部接缝、派生辅助和技术承载分开 |
| 主要组成部分 | 是否承担了相邻仓正文、展示层、运行时或归档职责 |
| 关键对象 | 对象是否属于本仓该拥有的对象类型,字段是否暗含外部正文 |
| API / 接口骨架 | 接口是否表达正确读写性质,是否把协议或产品写成 truth |
| 关键处理流 | 是否混淆核心成立、传播、派生和交接 |
| 状态机 | 是否覆盖未解析、过期、待重建、待交接等中间状态 |
| 异常边界 | 是否覆盖授权失败、引用不可解析、正文越界、派生延迟和交接失败 |
| 配置影响 | 配置是否只影响参数和运行装配,不改变核心边界 |

### 4.3 实现分层视图

```text
<Inbound / Operations>
  │ command intake / query intake / event intake / jobs
  ▼
<Application Services>
  │ space scope / fact append / manifestation / query / trace / derived maintenance
  ▼
<Domain Model and Policies>
  │ ConversationSpace / ParticipantScope / VisibilityScope / ConversationFact
  │ CrossDomainManifestation / TraceContext / policy objects
  ▼
<Ports and External Seams>
  │ actor / work / governance / artifact / bus / trace / archive
  ▼
<Persistence / Projection / Outbox>
  │ truth repo / fact history / manifest store / snapshots / read models / cursors / outbox
  ▼
<Downstream Awareness / Handoff>
```

关键说明:

- Inbound / Operations 只负责进入和触发。
- Application Services 负责用例编排、事务边界、幂等、domain 调用、repository / port 调用和 outbox 形成。
- Domain Model and Policies 负责业务不变量,不直接读取配置、协议或外部系统。
- Ports and External Seams 只能表达外部能力边界,不能反向定义 Conversation truth。

### 4.4 业务主体与实现分层的区别

| 实现分层 | 作用 | 为什么不能当业务主要组成部分 |
|---|---|---|
| Inbound adapters | 接收 command、query、event、subscription 或 job trigger | 描述进入方式,不描述业务职责 |
| Operations jobs | 执行投影重建、快照刷新、游标维护和交接 | 描述运行触发形态,不拥有新业务事实 |
| Application services | 编排用例、事务、幂等、domain 调用和 port 调用 | 横跨多个业务组成部分,不是业务分解维度 |
| Domain model | 承载对象、状态、不变量和 policy | 是实现层承载,具体对象归属于不同业务部分 |
| Ports / adapters | 表达外部能力接缝和技术适配 | 不能反向定义 Conversation truth |
| Persistence / projection / outbox | 持久化 truth、派生视图和传播意图 | 是技术承载和一致性边界,不是业务模块名称 |

|---|---|---|---|
| `Conversation truth core` | 保护 Conversation truth 的统一边界、关键不变量、一致性和 outbox 成立口径 | `ConversationTruthState`、`ConversationTruthPolicy`、truth repository、outbox repository | 不定义 UI、外部平台、runtime、governance、artifact、identity 或 archive truth |
| `Space / scope management` | 建立和维护对话空间、参与范围、可见范围 | `ConversationSpaceCommandService`、`ParticipantScopeCommandService`、`VisibilityScopeCommandService`、`ConversationSpace`、`ParticipantScope`、`VisibilityScope` | 不拥有成员生命周期、项目生命周期或全局授权裁决 |

| `Cross-domain manifestation` | 将来源仓正式事实以引用、快照或显化记录方式进入对话视野 | `ConversationManifestationService`、`CrossDomainManifestation`、`ExternalFactRef`、`ExternalFactSnapshot` | 不拥有来源仓正文、裁决、版本、成员或外部平台生命周期 |
| `History trace / review` | 支撑对话历史、关键变化、显化记录的复盘、审计和追溯交接 | `ConversationTraceReviewService`、`ConversationTraceContext`、`ReviewAnchor`、handoff records | 不拥有全局 trace store、metrics、长期归档包正文或恢复主体 |
| `Derived consumption support` | 维护派生视图、索引、变化游标、检索定位和重建状态 | `ConversationDerivedMaintenanceService`、projection rebuild job、`ConversationProjectionState`、search / cursor projection | 不生成新业务事实,不阻塞核心 truth 成立 |
| `Local reference / snapshot / projection support` | 承载外部引用、展示快照、解析状态和本地影子投影 | `ExternalSnapshotRefreshJob`、snapshot repository、`ExternalReferenceProjection`、`ReferenceResolutionState` | 不保存外部正文,不替代 Identity / Work / Governance / Artifact truth |

### 5.3 组成部分交互总图

```text
<Space / scope management>
  │ establishes space / participant / visibility
  ▼
<Conversation truth core>
  ▲
  │ appends committed facts
<Collaborative fact append>
  │
  ▼
<Cross-domain manifestation>
  │ uses refs and snapshots
  ▼
<History trace / review>
  │ handoff
  ▼
<Observability / Archive>

<Authorized consumption>
  ▲
  │ read projections and visible changes
<Derived consumption support>
  ▲
  │ refresh external references
<Local reference / snapshot / projection support>
```

关键说明:

- `Conversation truth core` 是中心边界,但业务操作通过 space / scope、fact append、manifestation、consumption、trace 和 derived support 承接。
- Derived support 和 Local reference / snapshot / projection support 只能支撑读取、显化、追溯和降级显示,不能反写真相。
- Observability / Archive 只作为交接方向出现,不是本仓内部主要组成部分。

### 7.2 接口分类

```text
Command API
  改写 Conversation truth、scope、fact、manifestation、trace 或 handoff intent。

Query API
  读取正式 truth、projection 或 read model,不得改写 truth。

Inbound Event Consumer
  消费来源仓已提交事实或变化通知,转成本地引用、显化、快照、状态推进或投影刷新意图。

Outbound Event
  传播本仓已提交 Conversation truth、变化感知或 handoff 意图,发布失败不得回滚 truth。

Operations Job
  基于已持久化 truth 做投影重建、快照刷新、outbox 发布、交接或一致性检查,不得生成新业务事实。
```

### 8.3 通用 Command 写路径

```text
<Command API>
  │
  ▼
<Command Intake>
  │ validate ActorContext, CommandMetadata, IdempotencyKey
  ▼
<Application Service>
  │ load required truth / reference objects
  │ call policy guard
  ▼
<Domain Object / History / Outbox>
  │ apply domain state change
  │ save truth + history + outbox in one write boundary
  ▼
<Command Result>
```

关键说明:

- Command 成功只表示本仓 truth 或 handoff intent 已提交。
- projection、outbox 发布、快照刷新和 handoff 实际交付不阻塞 Command 成功。
- 完整事务句柄、repository 函数和错误映射留给详细设计。

### 8.4 通用授权 Query 读路径

```text
<Query API>
  │
  ▼
<Query Intake>
  │ validate ActorContext / ConsumerContext and QueryMetadata
  ▼
<Query Service>
  │ load read model / projection / truth refs
  │ apply VisibilityPolicy
  ▼
<Projection / Snapshot / Truth View>
  │ attach stale / unresolved / not visible markers
  ▼
<Query Result>
```

关键说明:

- Query 不追加 fact、不改变 scope、不隐式显化外部事实。
- stale、unresolved、failed、rebuilding、invalidated 必须作为 marker 暴露。
- 详细分页、排序和一致性标记由详细设计继续展开。

### 8.5 通用 Inbound Event Consumer 处理路径

```text
<Inbound Event>
  │
  ▼
<Event Consumer>
  │ validate EventEnvelopeRef, EventId, EventSourceRef, IdempotencyKey
  ▼
<Application Service>
  │ map source event to reference / snapshot / candidate
  │ call ReferenceValidityPolicy
  ▼
<Local State / Projection / Outbox>
  │ update reference state, projection, manifestation candidate, or append input
  ▼
<Consume Result>
```

关键说明:

- Consumer 的核心职责是消化来源仓已提交事实或变化通知。
- Consumer 不能绕过 Command policy 写入不满足 space / scope / visibility 的正式 fact。
- 来源正文、外部平台 message body、runtime 推理过程都不得进入本仓 truth。

### 8.6 通用 Operations Job 处理路径

```text
<Operations Job>
  │
  ▼
<Job Runner>
  │ validate JobMetadata and scoped input
  ▼
<Maintenance Service>
  │ load committed truth / outbox / projection / handoff records
  ▼
<Projection / Handoff / Evidence>
  │ update derived state or operational marker
  ▼
<Job Result>
```

关键说明:

- Job 只能处理已持久化事实、派生状态、outbox 或 handoff record。
- Job 失败必须留下 marker,不能伪装成成功或覆盖 truth。
- 调度策略、重试参数和 runner 实现留给详细设计。

### 9.3 状态定义摘要

| 状态族 | 可进入正常主线 | 受限主线 | 不可进入正常主线 |
|---|---|---|---|
| Truth / space | `Open`、`Active` | `ReadOnly`、`Restricted`、`HandoffPending`、`Archived` | `Closed` |
| Scope / visibility | `Active`、`Open`、`Applied` | `Restricted`、`Sealed` | `Closed`、`Rejected` |
| Fact / receipt | `Accepted`、`Duplicate` | `VisibilityRestricted` | `Rejected`、`Retracted`、`Quarantined` |
| Manifestation / reference | `Manifested`、`Fresh` | `Stale`、`Pending`、`Unresolved` | `Revoked`、`Invalid` |
| Projection / cursor | `Fresh`、`Active` | `Stale`、`Rebuilding` | `Failed`、`Disabled`、`Expired`、`Invalidated` |
| Outbox / handoff | `Published`、`HandedOff`、`Archived` | `Pending`、`RetryPending` | `Failed`、`Suppressed`、`Cancelled` |
| Trace retention | `Open` | `Sealed`、`HandoffPending`、`Expired` | 不单独定义失败态 |

说明:

- 受限主线不是成功或失败的同义词,它要求 Query、Event、Job 或 Handoff 暴露 marker。
- `Published`、`HandedOff`、`Archived` 只说明传播或交接完成,不能反向证明来源 truth 可变更。
- `ConversationReadModel`、`SearchIndexProjection`、`ChangeCursorProjection` 和 `ExternalReferenceProjection` 不另设 truth 状态机,它们通过 projection、cursor 或 reference 状态暴露派生状态。

### 9.4 核心状态传播图

```text
<Conversation Truth / Scope / Fact Change>
  │
  ▼
<Trace / History / Outbox Marker>
  │
  ▼
<Projection / Cursor / Reference State>
  │
  ▼
<Authorized Query / Downstream Awareness>

<Outbox / Handoff Failure>
  │
  ▼
<RetryPending / Failed / Suppressed Marker>
  │
  ▼
<Truth Remains Committed>
```

关键说明:

- truth、scope、fact 和 manifestation 的变化先形成本仓记录,再通过 outbox、projection、cursor 或 handoff 被感知。
- outbox、projection、cursor、reference refresh 和 handoff 的失败不能回滚已提交 truth。
- Query 必须暴露 stale、failed、unresolved、invalidated、suppressed 等 marker,不能把异常派生状态伪装为 fresh。

### 9.5 允许迁移与禁止迁移摘要

| 类别 | 允许迁移摘要 | 禁止迁移摘要 |
|---|---|---|
| Truth / space | initial 创建为 open / active;open 可进入 read only、restricted 或 handoff pending;closed 可进入 archived | closed 不得隐式重开;archived 不得恢复普通写入;handoff pending 不得当作 open 写入 |
| Scope / visibility | active / open 可受限;restricted 可通过显式 release 恢复;applied 可被 superseded | rejected 不得变 applied;sealed 不得被 Query 打开;closed participant 不得隐式恢复 |
| Fact / manifestation | append 可 accepted、visibility restricted、duplicate 或 rejected;manifested 可 stale、revoked 或 unresolved | rejected 不能补写为 accepted;quarantined 不能自动进入 accepted;revoked 不能自动恢复 manifested |
| Reference | pending 可 fresh、unresolved 或 invalid;fresh 可因来源变化变 stale;stale 可重新 pending | invalid 不得自动变 fresh;unresolved 不得补造来源 truth |
| Projection / cursor | fresh 可 stale;stale 可 rebuilding;rebuilding 可 fresh 或 failed;active cursor 可 stale、expired 或 invalidated | failed 不得不经 rebuild 变 fresh;expired / invalidated cursor 不得继续续读 |
| Outbox / handoff | pending 可 published、retry pending、failed 或 suppressed;retry pending 可再次 pending | failed 不得回滚 truth;published / handed off / archived 不得静默重置为 pending |

### 10.2 异常与边界场景表

| 场景 | 应落在哪个部分处理 | 当前概要口径 |
|---|---|---|
| 创建 space 时 owner / actor 引用不满足上游边界 | `Space / scope management` | 不创建 space,不形成 outbox,返回 rejected result |

| external ref 暂不可解析 | `Local reference / snapshot / projection support` | 不补造来源 fact,记录 unresolved 和降级 marker |
| snapshot digest 与来源版本不匹配 | `ReferenceValidityPolicy` | 不标记 fresh,进入 invalid 或 stale |
| projection stale / failed / disabled | `Derived consumption support`、`Authorized consumption` | Query 输出 stale / failed / disabled marker 或 fallback,不得伪装 fresh |
| cursor expired 或因 scope change invalidated | `Authorized consumption` | 不允许续读旧 cursor,必须重新建立读取视图 |
| inbound event 重复消费 | 对应 consumer | 返回 duplicate / consumed marker,不得重复更新 projection、snapshot、fact 或 outbox |
| outbox 因 visibility / boundary 不允许发布 | `PublishConversationOutbox` | 标记 suppressed,保留内部证据,不跨仓发布 |
| outbox / handoff 发布失败 | outbox publisher、handoff job | 标记 retry pending 或 failed,不得回滚 truth |
| consistency validation 发现不一致 | `ValidateConversationConsistency` | 只生成 diagnostic evidence 和 marker,不得自动覆盖 truth |

### 10.4 异常处理边界说明

- 写入前置边界失败必须在 truth mutation 前截断。

| 幂等语义 | duplicate 与 conflict 必须区分,不能通过配置把冲突当成功 |
| 审计与追溯链 | fact append、scope change、manifestation、trace handoff 必须可追溯,不能配置关闭 |

| trace / archive handoff payload 的脱敏材料边界是否需要更细粒度分类 | trace handoff、archive handoff、retention policy、handoff ports | 当前只允许引用和脱敏摘要;详细设计可细分 payload ref 类型,不得允许 forbidden body |
| AI member / human actor / system actor 展示快照是否由 identity resolver 统一供给 | participant scope、fact source、external reference projection、identity event consumer | 当前只保存 actor / participant 引用和展示 snapshot marker;详细设计需与 `L1-identity` 契约核对 |

### 13.4 待确认项方案建议

| 待确认项 | 备选方案 | 推荐方案 | 推荐理由 |
|---|---|---|---|
| 来源仓字段级契约对齐 | A. 概要阶段逐字段锁死;B. 详细设计逐字段核对;C. 实现阶段再对齐 | B | 概要层不写 schema 细节,但详细设计必须在落码前对齐,避免实现阶段 blocker |
| projection / search / cursor 技术承载 | A. 概要阶段选产品;B. 详细设计定义 port / adapter,产品留到配置 / 实施;C. 实现自由选择 | B | 保持概要产品中立,同时让详细设计有可测试的契约 |
| `04-配置说明` 是否独立成文 | A. 不写配置说明;B. 独立成文,若无配置也说明无配置;C. 并入详细设计 | B | 符合已收稳的配置文档规则,也避免后续 agent 误判配置缺失 |
| consistency validation 是否修复 | A. 只诊断;B. 自动修复 projection;C. 自动修复 truth | A | 当前概要没有定义修复命令或补偿状态,只诊断最符合 truth 不被派生反写原则 |
| handoff payload 脱敏边界 | A. 概要层细分全部 payload 类型;B. 概要层固定 forbidden body 红线,详细设计细分 ref 类型;C. 交给实现处理 | B | 红线必须概要层固定,细分类型属于详细设计对象契约 |
| actor 展示快照来源 | A. Conversation 自建 actor truth;B. 依赖 identity resolver / event 快照;C. 下游自行解析 | B | Conversation 不拥有 identity truth,但本仓需要可控展示 snapshot 和 stale marker |

#### 5.3.3 对象实现契约

完整 DTO schema 由 §7 和 `03_ddd_step_08_protocol_contracts.md` 定义。本模块不定义领域状态机，不保存外部正文。

Context / metadata 归属:

- `CommandMetadata`、`QueryMetadata`、`ActorContext`、`ActorRef`、`TraceId` 直接 re-export `core-contracts`,不得复制字段或重建并行类型。
- `TraceContextRef` 是 conversation contracts 中对 core `TraceId` 的 alias / wrapper,只用于本仓日志、event、job 和 handoff 引用。
- `SystemActorRef` 是 conversation contracts 中包装 core `ActorRef` 的受限类型,构造时必须校验 `ActorKind::System`。
- `ConsumerContext` 属于 conversation contracts,最小字段为 `consumer_ref: ConsumerRef`、`actor_ref: Option<ActorRef>`、`visibility_scope_ref: Option<VisibilityScopeId>`、`purpose_ref: Option<ExternalReferenceRef>`。它不承载 request id、trace、page 或 consistency。
- `VisibilityRuleSet` 属于 `contracts/visibility.rs`,是纯数据 DTO / value object;domain `VisibilityScope` 和 `VisibilityPolicy` 只能消费它,不得让 contracts 反向依赖 domain。
- PH-02 共享值对象的字段级 schema 以 `design-calibration/03_ddd_step_06_object_contracts.md` §7.2.1 为准。实现者必须按该节定义 `ConversationOwnerRef`、`ConversationParticipantRef`、`ConversationParticipantRole`、`ConsumerRef`、`VisibilityLevel`、`VisibilityRuleSet` 及子 rule set、`CommandReasonRef`、`ScopeChangeReason`、`SpaceCloseReason`、`RestrictionReason`、`VisibilityRestrictionReason`、`ScopeSnapshotRef` 和 `SpaceCloseMode`。
- `VisibilityLevel` 的正式比较顺序为 `Private < Participants < Project < Workspace < Public`;sealed visibility 后不得扩张 `maximum_visibility`、新增更宽 `Allow` 或删除更窄 `Deny`。
- `SpaceCloseMode::ReadOnly` / `Closed` / `Archived` 分别映射到 `ConversationSpaceLifecycleState::ReadOnly` / `Closed` / `Archived`;`Archived` 必须携带 `archive_intent_ref`。

无。`contracts` 只定义协议结构，不定义 repository 或 adapter trait。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源：
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物 §7 的协议总表、通用协议信封、单协议 schema、字段来源与构造闭环表。

### 7.1 P0 协议形态

| 协议类别 | 传输 / 入口形态 | 说明 |
|---|---|---|
| Command | HTTP / RPC handler boundary | 接收同步写命令，必须携带 actor 和 core `CommandMetadata`;幂等键来自 `metadata.request.idempotency_key`,trace 来自 `metadata.request.trace_id` |
| Query | HTTP / RPC handler boundary | 接收授权读取请求，不写 truth;page / consistency 来自 core `QueryMetadata` |
| Inbound Event Consumer | event envelope | 接收来源仓结果性事件，只保存 ref / safe snapshot / local manifestation |
| Outbound Event | conversation outbox / projection publisher | 发布本仓已提交 truth 或 projection state 变化 |
| Operations Job | job input envelope | 承接批处理、重建、交接、校验和清理 |

### 7.2 通用协议信封

#### Command envelope

```json
{
  "command": {},
  "actor": "ActorContext",
  "metadata": "CommandMetadata"
}
```

Command envelope 不允许再额外携带顶层 `idempotency_key` 或 `trace_ref`。所有 Command API 必须要求 `metadata.request.idempotency_key = Some(...)`;缺失时返回 `ProtocolError::MissingRequiredField`,不进入 application service。trace 权威字段为 `metadata.request.trace_id`。

#### Query envelope

```json
{
  "query": {},
  "consumer": "ConsumerContext",
  "metadata": "QueryMetadata"
}
```

Query envelope 不允许再额外携带顶层 `page` 或 `consistency`。分页和一致性偏好来自 core `QueryMetadata.page` / `QueryMetadata.consistency`;`consumer` 只表达本仓读取方和可见性提示,不承载 trace 或 request id。

#### Inbound event envelope

```json
{
  "event_id": "EventId",
  "event_envelope_ref": "EventEnvelopeRef",
  "event_source_ref": "EventSourceRef",
  "idempotency_key": "IdempotencyKey",
  "occurred_at": "Timestamp",
  "trace_ref": "TraceContextRef",
  "payload": {}
}
```

#### Job envelope

```json
{
  "job_run_id": "JobRunId",
  "job_metadata": "JobMetadata",
  "idempotency_key": "IdempotencyKey",
  "scope": {},
  "batch_size": "BatchSize",
  "trace_ref": "TraceContextRef"
}
```

| 输入类型 | 必须满足 |
|---|---|
| Command request | 必填字段能构造目标 Domain 对象；缺失字段按 `ProtocolError` 或 `ApplicationError` 处理 |
| Query request | 读取对象、consumer、page、consistency 必须闭合；query 不写 truth |
| Inbound event | event id、source ref、idempotency key、payload ref 必须闭合；invalid envelope quarantine |
| Outbound event | 只能来自已提交 truth、projection state 或 handoff intent；payload 必须是 ref / marker，不含正文 |
| Job input | job run id、scope、metadata、idempotency key 必须闭合；invalid input 写 failed job receipt |

`AppendConversationFactRequest`、`RetractConversationFactRequest` 和 `ManifestExternalFactRequest` 的 `visibility_scope_id` 是协议输入上的可选字段,正式类型为 `Option<VisibilityScopeId>`。缺省时 application service 必须按已提交 truth 派生:append / manifest 使用 space 的默认或当前 visibility scope,retract 使用目标 fact 的 `visibility_scope_id`。若调用方传入 `Some(visibility_scope_id)`,该值只作为 scope hint / guard:append / manifest 必须与当前 space visibility scope 匹配,retract 必须与目标 fact 的 `visibility_scope_id` 匹配;不匹配时返回 `ApplicationError::NotVisible`。Domain fact / manifestation 入库前必须持有解析后的具体 `VisibilityScopeId`,不得把可选值透传为 domain truth。

`AppendConversationFactRequest.fact_kind` 是 `ConversationFact.fact_kind` 的正式来源。`AppendConversationFactFlow` 必须在构造 `ConversationFact` 前调用 `FactAppendPolicy::assert_fact_kind_allowed(request.fact_kind)`,并通过 `ConversationFact::from_append_input(space, fact_kind, source, visibility, payload_ref)` 传入 domain factory。`ConsumeRuntimeResultCommitted` 和 `ConsumeBridgeMappedFactReceived` 进入 append fact 路径时也必须显式提供 `fact_kind`;runtime result 只能使用 `ConversationFactKind::RuntimeResult`,bridge append 只能使用 `ConversationFactKind::BridgeMapped`,不匹配时按 `ProtocolError::InvalidEnvelope` quarantine。

完整字段级 schema 和单协议构造闭环表见 `03_ddd_step_08_protocol_contracts.md` §7.3~§7.10。

### 7.5 Command result 最小返回面

PH-02 space / scope command 的 result DTO 必须在 `contracts/commands.rs` 中明确定义,不得只写类型名。

```json
{
  "ConversationSpaceCommandResult": {
    "space_id": "ConversationSpaceId",
    "scope_change_ref": "Option<ScopeChangeRecordRef>",
    "outbox_record_ref": "Option<ConversationOutboxRecordId>",
    "projection_state_ref": "Option<ConversationProjectionStateId>",
    "result_ref": "CommandResultRef",
    "receipt": "CommandReceipt"
  },
  "ParticipantScopeCommandResult": {
    "space_id": "ConversationSpaceId",
    "participant_scope_id": "ParticipantScopeId",
    "scope_change_ref": "ScopeChangeRecordRef",
    "outbox_record_ref": "Option<ConversationOutboxRecordId>",
    "projection_state_ref": "Option<ConversationProjectionStateId>",
    "result_ref": "CommandResultRef",
    "receipt": "CommandReceipt"
  },
  "VisibilityScopeCommandResult": {
    "space_id": "ConversationSpaceId",
    "visibility_scope_id": "VisibilityScopeId",
    "scope_change_ref": "ScopeChangeRecordRef",
    "outbox_record_ref": "Option<ConversationOutboxRecordId>",
    "projection_state_ref": "Option<ConversationProjectionStateId>",
    "result_ref": "CommandResultRef",
    "receipt": "CommandReceipt"
  }
}
```

`CommandResultRef`、`CommandReceipt` 和 `ConversationCommandKind` 属于 `contracts/commands.rs` / `contracts/refs.rs`,不得引用 `application/idempotency.rs` 类型。application service 必须在 validate 后、reserve 前计算 `RequestDigest`,并调用 `IdempotencyRepository.reserve(key, operation, request_digest, uow)`。application service 可以用 `CommandResultRef` 的值构造或映射本地 `IdempotencyResultRef`,再调用 `IdempotencyRepository.complete(...)`。

`CommandReceipt` 最小字段为 `request_id: RequestId`、`idempotency_key: IdempotencyKey`、`command_kind: ConversationCommandKind`、`outcome: accepted | duplicate`、`completed_at: Timestamp`。同 key 同 request digest duplicate 必须返回已完成记录中的 `result_ref` 和原 refs,`receipt.outcome = duplicate`,不得生成新的 scope change 或 outbox。缺失 `metadata.request.idempotency_key` 或同 key 不同 digest 时返回错误,不返回 command result。

```text
[Command / Consumer]
  | commit truth state change
  v

  v
```

### 10.1 数据所有权实现表

| `cross_domain_manifestations` | 保存显化记录 | `manifestation_id` | `space_id`、`external_fact_ref`、`manifestation_state` |
| `external_fact_snapshots` / `external_reference_projections` | 保存安全快照和引用投影 | snapshot / projection id | `external_fact_ref`、`resolution_state` |

### 10.3 事务边界表

| 场景 | 同事务内必须完成 | 回滚条件 |
|---|---|---|
| space / scope command | idempotency reserve、space / scope / visibility / scope change、outbox、idempotency complete | domain invalid、repository failure、outbox failure、idempotency conflict |
| append / retract fact | idempotency、fact、receipt、trace context、outbox | append policy reject、forbidden payload、terminal fact、repository failure |
| manifestation command / consumer | idempotency、safe snapshot、manifestation、optional fact、trace、outbox | resolver required failure、visibility reject、repository failure |
| trace / archive handoff command | idempotency、handoff record、outbox | trace missing、policy reject、repository failure |
| inbound source consumer | event idempotency、local reference / manifestation / fact / projection state、outbox where needed | invalid envelope、quarantine、repository failure |
| query API | 无写入 | repository failure、visibility denied |
| outbox publish job | lock outbox、mark published / retry / failed、save state | locked record missing、invalid state、repository failure |
| projection / cursor / snapshot job | projection、cursor、snapshot 或 unresolved marker 与 state 保存 | resolver failure、source gap、repository failure |
| handoff delivery job | lock handoff、mark handed off / archived / retry / failed | missing record、invalid state、repository failure |
| consistency validation | report / diagnostic marker | job input invalid、repository failure |

### 10.4 一致性策略表

| 一致性对象 | 策略 | 失败时处理 |
|---|---|---|
| truth + outbox | command / consumer 写 truth 时必须同事务 enqueue outbox | outbox enqueue 失败则 truth 写入回滚 |
| truth + idempotency | reserve、business write、complete 必须在同一 UnitOfWork 中闭合 | complete 失败则事务回滚 |
| fact append sequence | 同一 space 内单调递增且唯一 | sequence conflict 返回 repository / concurrency error |
| outbox sequence | 单调递增，支撑 cursor projection | sequence gap 标记 cursor stale |
| projection source position | 只能前进 | regression 返回 domain / repository error |
| state transition | 必须遵守 Step 10 矩阵 | 非法转换返回领域错误 |

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物 §6 的错误类型、错误映射、异常分支和恢复口径表。

### 11.1 错误类型表

| 错误类型 | 所属层 | 典型触发 | 可重试性 |
|---|---|---|---|
| `ProtocolError` | contracts / api / worker / jobs | 缺字段、非法 envelope、unsupported schema | 否 |
| `ApplicationError` | application | not found、not visible、conflict、cursor not resumable | 视场景 |
| `DomainError` | domain | invalid transition、boundary violation、source truth violation、sequence regression、digest mismatch | 多数不可自动重试 |
| `RepositoryError` / `TransactionError` | infra | 存储失败、唯一键冲突、版本冲突、事务失败 | transient 可重试 |
| `IdempotencyError` | application | 同 key 不同请求内容或不同 result | 否 |
| `ResolverError` | infra adapter | 外部来源不可解析、超时、digest 不一致 | 部分可重试 |
| `PublishError` | publisher adapter | event build / transport / topic publish 失败 | transport 可重试 |
| `HandoffError` | handoff adapter | observability / archive 交接失败 | 部分可重试 |
| `JobError` | jobs | invalid input、partial failure | 视场景 |

### 11.2 错误映射表

| 内部错误 | 对外映射 | 调用方处理 |
|---|---|---|
| `ProtocolError::MissingRequiredField` | HTTP 400 / command reject | 修正请求后重试 |
| `ProtocolError::InvalidEnvelope` | consumer quarantine | 修正来源事件或重放合法事件 |
| `ApplicationError::NotFound` | HTTP 404 / job failed evidence | 检查引用是否存在 |
| `ApplicationError::NotVisible` | HTTP 403 或 empty view marker | 不应重试同一权限上下文 |
| `ApplicationError::CursorNotResumable` | HTTP 409 / cursor reset marker | 重新读取 read model 并创建新 cursor |
| `DomainError::InvalidStateTransition` | HTTP 409 / domain audit | 按当前状态重新发起合法 command |
| `RepositoryError` | HTTP 500 / retryable job marker | 按 retry policy 重试 |
| `ResolverError` | unresolved / delayed marker | 等待 refresh job 或人工处理 digest mismatch |
| `PublishError` | outbox `RetryPending` / `Failed` | publish job 重试或 operations 处理 |
| `HandoffError` | handoff `RetryPending` / `Failed` | handoff job 重试或 operations 处理 |
| `JobError::PartialFailure` | `JobRunReceipt` partial failure | 读取 failed refs 后局部重跑 |

### 11.3 异常分支与恢复口径

| 场景 | 处理方式 | 恢复方式 |
|---|---|---|
| command metadata 缺 `request.idempotency_key` | reject request | 调用方修正请求 |
| idempotency duplicate | 返回已完成 result 或 skip | 不需要重试 |
| idempotency conflict | 409 conflict | 排查上游 key 复用 |
| invalid state transition | reject and rollback | 按当前状态重发合法 command |
| forbidden payload body | reject or quarantine | 修正来源或 adapter |
| inbound event invalid | quarantine | 修正事件后 replay |
| resolver unavailable | unresolved / delayed marker | refresh job 重试 |
| digest mismatch | unresolved / manual evidence | 人工确认 |
| publish transport failure | mark retry / failed | publish job 重跑 |
| handoff transport failure | mark retry / failed | handoff job 重跑 |
| projection rebuild failure | mark `ProjectionFreshnessState::Failed` | rebuild job 重跑 |
| cursor expired | reset cursor or cleanup | 重新创建 cursor |

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物 §6 的并发场景表、幂等键表和重入保护表。

### 12.1 并发资源表

| 场景 | 冲突资源 | 控制方式 |
|---|---|---|
| 同一 command 重试 | `IdempotencyRecord` | validate 后计算 request digest,再 reserve key + operation + digest；同 key 同 digest 返回 existing result |
| close space 与 append fact 并发 | `ConversationSpace.truth_state` | `get_space_for_update` 后重新检查 state |
| scope 并发更新 | `ParticipantScope`、`VisibilityScope`、`ScopeChangeRecord` | scope bundle 同事务保存，version 冲突返回 conflict |
| 同一 space 并发 append fact | `ConversationFactSequence` | sequence 单调唯一，冲突返回 repository / domain error |
| inbound duplicate event | `IdempotencyRecord`、source projection | event id + source ref + key reserve，命中 skip |
| outbox publish 并发 | `ConversationOutboxRecord.publication_state` | `get_for_update` 锁定 pending / retry record |
| projection rebuild 并发 | `ConversationProjectionState`、read model | 每 space / consumer 事务，version 控制 |
| handoff delivery 并发 | `TraceHandoffRecord` / `ArchiveHandoffRecord` | 每条 handoff 短事务锁定 |

### 12.2 幂等键表

| 接口 / Job / Event | 幂等键 | 重复请求处理 |
|---|---|---|
| 10 个 Command | `CommandMetadata.request.idempotency_key` + application 计算的 `RequestDigest` | 返回已有 result / receipt；同 key 不同 digest conflict |
| Query APIs | optional request id | 不写状态，返回当前 authorized view 或 cached read marker |
| 6 个 inbound consumer | event id + source ref + `IdempotencyKey` | skip already consumed event |
| Outbound events | outbox record id + event id | 不重复发布，write publish evidence once |
| 9 个 operations job | job run id + `IdempotencyKey` | 返回 existing job receipt |

### 12.3 重入保护表

| 场景 | 保护方式 | 恢复方式 |
|---|---|---|
| command 事务提交前失败后重试 | UnitOfWork rollback；idempotency 未完成时重新 reserve | 重跑整个 command |
| command 已提交但响应丢失 | completed idempotency record 保存 result ref | 返回 existing result / receipt |
| inbound consumer 提交后 ack 丢失 | event id + source ref + key 命中 | skip |
| outbox publish 成功后状态写失败 | event id 稳定，重新锁 outbox 前检查 publication evidence | job 重跑补状态 |
| projection rebuild 部分失败 | 每 space / consumer 一事务，projection state 标记 failed / stale | 下次 job 重扫 |
| snapshot refresh resolver 失败 | 写 unresolved / stale marker | 后续 refresh job 重试 |
| trace / archive handoff 外部成功但状态写失败 | handoff id / destination ref 或 package ref 去重 | job 重跑补写 handed off / archived |
| cleanup expired cursor 重跑 | delete expired cursor 幂等，active cursor skipped | 返回已有或重新计算 |

### 14.1 观测材料输出边界

#### 边界图: Conversation 观测材料输出边界

```text
[API / Consumer / Job / Publisher]
  | call with TraceContextRef / RequestId / Operation
  v
[Application Service]
  | append / tx / publish / handoff / rebuild
  +--> [Structured Logs] : log
  +--> [Metrics Collector] : metric
  +--> [Receipt / Trace / Evidence Refs] : audit
  +--> [Diagnostic Ref] : safe diagnostic
  v
[Repository / Adapter / Port]
  | tx / external-call / retry
  v
[Conversation Truth / Projection / Outbox / Handoff State]
```

关键说明：

- 日志、指标、审计和 diagnostic 从同一处理流分层输出。
- 本章不定义告警阈值、dashboard、日志采集系统或运维处置流程。
- `Receipt / Trace / Evidence Refs` 不是新的全局 audit store。
- 任何输出材料都不得保存 forbidden body 或 secret。

| Query log | authorized read、visibility denied、cursor invalid | `trace_ref`、`query`、`consumer_ref`、`consistency_marker` |
| Consumer log | accepted、duplicate、quarantine | `trace_ref`、`event_id`、`source_ref`、`event_kind`、`result_ref` |
| Outbox log | publish success、retry、failed | `trace_ref`、`outbox_record_id`、`event_kind`、`published_event_ref`、`evidence_ref` |
| Job log | rebuild、cursor、snapshot、handoff、consistency summary | `trace_ref`、`job_run_id`、`job_kind`、`result`、`report_ref` |
| Metrics | command、query、idempotency、consumer、outbox、projection、handoff、job、repository error | low-cardinality `operation`、`result`、`state`、`category` |

| 文档未生成 | 暂停正式移交，不得要求实现 agent 自行补设计 |
| 上游类型不存在 | 暂停对应代码，不得复制或改名上游类型 |
| 协议字段与对象字段冲突 | 回到对应 Step 修文档，不得在代码中选边 |
| 状态名或 enum 变体冲突 | 以 Step 6 + Step 10 为真相源，并修正式文档 / 测试 / 验收 |
| phase boundary 不清 | 回到 `07-实施计划.md`，不得按文件或模块随意提交 |
| fake adapter 覆盖真实依赖 | fake 名称、fixture、测试和报告必须显式标明，不得写成真实集成通过 |

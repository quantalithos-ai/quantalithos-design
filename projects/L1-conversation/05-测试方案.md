### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 conversation 的接口可调用,而是系统验证 `L1-conversation` 是否真正满足“协作对话真相仓”的设计要求,尤其要证明以下几点成立:
- Conversation / Turn / participant 构成正式对话真相层
- Turn append-only 成立,任何编辑都只能通过 supersede 形成新记录
- `work / governance / artifact / process / identity` 的输入只能通过 event→turn 接缝进入可见层,不会污染 conversation 的真相边界
- StreamEvents 只是实时映射层,不是对话真相本体
- summary / history / search / bridge-facing view 都是只读投影,不反写真相
- push 失败、projection 损坏、事件重复等异常场景下,仍能保住正式历史并恢复消费链

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| Conversation 四形态与 participant 边界 | 真相对象 | P0 | group / channel / dm / thread 的空间规则 |
| Turn 事实流与 supersede 机制 | 真相对象 | P0 | append-only 历史链 |
| event→turn 接缝 | 接缝逻辑 | P0 | work / governance / artifact / process / identity 输入 |
| StreamEvents / last_event_id | 推送链 | P0 | 实时推送、补发、续传 |
| summary / history / bridge / search 投影 | 读模型 | P0 | 只读、一致性、重建 |
| bridge 协议适配内部实现 | 非范围 | P2 | 只验证 conversation 侧 bridge-facing 视图 |
| chat / console 前端组件视觉细节 | 非范围 | P2 | 不覆盖像素级 UI |
| 外部域真相正文 | 非范围 | P2 | 不验证 Gate decision / Artifact 正文 / Project 真相内部逻辑 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和规则不变量 | domain / policy owner | `Conversation.validate_participant_mutation`、`Conversation.ensure_post_allowed`、`Turn.validate_related_refs`、`VisibilityPolicy.rebuild`、`EventTurnMappingPolicy.decide` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + projection + stream mapper 联动 | backend / domain owner | `CreateConversation`、`PostTurn`、`AppendSystemTurnFromEvent`、`ArchiveConversation`、`QueryConversationHistory` | 真相写入、只读投影、推送链同时成立 |
| 事件链测试 | 验证上游域事件进入 conversation 的完整落链 | integration / platform owner | `work.project.created`、`work.project.member_assigned`、`governance.gate.raised`、`governance.gate.decided`、`artifact.approved`、progress 类事件 | event→turn 映射正确且可追踪 |
| 恢复专项测试 | 验证推送失败、事件落点缺失、重连续传、projection rebuild | architecture / QA | last_event_id 补发、dead-letter、projection reset/replay | 真相不丢失、链路可恢复 |
| 投影一致性测试 | 验证 summary / history / bridge view / search 与真相一致 | backend / QA | supersede 后默认视图、archived 会话显示、bridge 裁剪、search document 重建 | 投影只读且与真相一致 |
| 端到端主线测试 | 验证最小可运行闭环 | QA / owner | create group → post turn → stream consume；gate event → gate turn；artifact approved → artifact turn；reconnect resume | 主干场景完整跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| Conversation 是正式对话空间真相 | create group / dm / thread | 集成测试 | 是 | DB / API 响应 |
| Turn append-only | supersede 不原地更新旧 Turn | 单元 + 集成 | 是 | DB 审计 / history query |
| 外部事件先翻译成 Turn 再推送 | gate / artifact / work 事件入链 | 事件链测试 | 是 | event log / turn history |
| StreamEvents 不是真相层 | push 失败不影响 Turn 落库 | 恢复专项测试 | 是 | stream lag / turn persisted trace |
| 投影不反写真相 | rebuild projection 后真相不变 | 投影一致性测试 | 是 | rebuild log / truth compare |
| participant 边界成立 | 无权限 participant 不可读/不可发 | 集成 + 边界测试 | 是 | permission error / access log |
| dm 只能双边 | 第三个 participant 被拒绝 | 单元 + 集成 | 是 | validation result |
| archived 会话默认只读 | archived 后普通 post 失败 | 集成测试 | 是 | state log / error response |
| 重复事件不可生成重复 Turn | 同一 gate event 重放 | 事件链 + 恢复测试 | 是 | idempotency log |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local DB / fake push transport / fake subscribers | debug logging / replay enabled | 容易只测 happy path |
| test | CI / 集成测试 | test DB / controlled event bus / deterministic push adapter | isolated tables / fixed event fixtures | 事件顺序抽象不足 |
| staging | 端到端演练 | real-like chat / console / bridges / upstream event wiring | stream reconnect / projection rebuild / bridge view enabled | 实时消费差异放大 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | 创建 group conversation | project/group refs 有效 | CreateConversation | group conversation 创建成功 |

| TC-005 | governance.gate.raised → gate turn | 有目标 conversation | AppendSystemTurnFromEvent | 生成 gate turn |
| TC-006 | artifact.approved → artifact turn | 有目标 conversation | AppendSystemTurnFromEvent | 生成 artifact turn |

| TC-008 | push 失败后补发 | Turn 已落库 / push adapter 故障 | emit stream → reconnect | 正式历史保留,重连后补发 |
| TC-009 | last_event_id 续传 | 有缺失事件片段 | StreamConversationEvents(last_event_id) | 补发缺失流事件 |

| TC-012 | bridge-facing view 只裁剪不改义 | 有 artifact / gate / user turns | Query bridge view | 返回裁剪视图,不改源 Turn |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | Turn append-only 被破坏 / projection 反写真相 / event 污染外域边界 | 阻断放行,必须修复 |
| A | 主线可跑但 stream / projection / idempotency 不稳 | 原则上修复后再放行 |
| B | 非关键桥接视图或低优先级查询异常 | 可带风险进入下一轮 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 Conversation / participant 边界逻辑,都必须回归 dm / group / thread / archived / locked 规则
- 每次改动 Turn 写入逻辑,都必须回归 append-only 与 supersede 链
- 每次改动 event→turn mapping,都必须回归 gate / artifact / work / progress 四类事件
- 每次改动 StreamEvents,都必须回归 push 失败补发与 last_event_id 续传
- 每次改动 projection / search / bridge view,都必须回归 rebuild 一致性

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| thread visibility 继承细则后续若继续细分 | 测试矩阵需扩充 | TL / 架构 |
| search backend 若后续外置 | 部分性能与一致性测试需重写 | conversation + SRE |
| bridges 平台继续扩张 | bridge-facing view 测试需增加平台差异样本 | Owner / TL |

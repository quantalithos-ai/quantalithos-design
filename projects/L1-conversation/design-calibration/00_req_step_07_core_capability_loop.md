## 3. SOP 问题回答

### 3.1 如果没有这个仓,系统会缺什么不可替代的能力或结构？

如果没有 `L1-conversation`,平台会缺少一个独立于 Chat UI、Workspace 视图、Bridges 外部平台、Runtime 推理、Governance 决策和 Artifact 正文的对话事实来源。不同消费方会各自保存消息、上下文、系统通知和审计片段,同一次协作在用户界面、项目视野、外部平台、AI member 上下文和审计视角下会失去共同基线。

因此本仓不可替代的能力不是“发送消息”本身,而是让对话空间、参与范围、对话事实、授权消费、跨域显化和历史追溯共同成立。

### 3.2 这个仓成立必须共同具备哪些能力？

核心能力必须同时覆盖五件事:

1. 对话空间与参与范围能够被独立确立。
2. 多来源协作事实能够以追加方式沉淀。
3. 对话事实能够按授权视野被稳定消费。
4. 关键跨域事实能够以引用方式显化到对话。
5. 对话历史能够被追溯并持续支撑协作复盘。

这些能力共同成立后,Conversation 才既不是 UI 缓存,也不是 runtime 临时上下文,而是平台对话真相域。

### 3.3 哪些能力缺一个,这个仓就不算真正成立？

若缺少对话空间与参与范围,对话事实没有归属和可见边界。若缺少追加沉淀,对话只是瞬时交互而不是事实记录。若缺少授权消费,Chat、Workspace、Runtime、Bridges 和审计链路无法围绕同一事实工作。若缺少跨域显化,治理、产物、项目等关键协作事实无法被用户在对话中看见。若缺少历史追溯,对话不能支撑复盘、审计和信任。

### 3.4 哪些能力只是外围增强,而不是闭环核心？

全文检索、复杂排序、富媒体渲染、AG-UI 细粒度映射、外部平台差异化桥接、复杂通知策略、冷热分层归档、管理后台运营视图和超大规模容量优化都可能很重要,但它们不是 Conversation 作为真相仓成立的最小闭环。它们应在后续功能、接口、非功能、测试或实施计划中分层展开。

### 3.5 哪些能力根本不属于这个仓？

Chat UI 交互、个人 / 项目工作台聚合、外部平台协议生命周期、LLM 推理循环、治理决策、产物正文和版本真相、成员生命周期、登录认证、权限裁决、全局观测和长期归档策略都不属于 Conversation 核心能力。Conversation 可以提供事实、引用、可见记录或追溯材料,但不接管这些相邻仓的真相。

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 把旧功能清单当作核心闭环 | 迁移最快 | 功能、接口、协议和非功能混在一起 | 不采用 |

## 7. 结构化中间产物

### 7.1 闭环定义

`L1-conversation` 的核心能力闭环是:平台必须能够独立确立对话空间和参与范围,把多来源协作事实以追加方式沉淀为对话事实,让这些事实按授权视野被稳定消费,把关键跨域事实以引用方式显化到对话中,并让对话历史能够被追溯和复盘。只要这些能力不能共同成立,Conversation 就会退化为 UI 消息缓存、runtime 临时上下文或相邻仓通知副本。

### 7.2 核心能力闭环图

```text
对话空间与参与范围能够被独立确立
  -> 多来源协作事实能够以追加方式沉淀
  -> 对话事实能够按授权视野被稳定消费
  -> 关键跨域事实能够以引用方式显化到对话
  -> 对话历史能够被追溯并持续支撑协作复盘
```

图示说明:

- 本图只表达核心能力成立的逻辑依赖关系。
- 本图不表达运行时调用顺序、接口时序、事件传播顺序或开发实施步骤。
- 外围增强能力和边界外能力不进入本图。

### 7.3 能力层级划分表

| 分类 | 内容 |
|---|---|
| 核心能力闭环 | 对话空间与参与范围独立确立;多来源协作事实追加沉淀;授权视野下稳定消费;关键跨域事实引用显化;历史追溯与复盘 |
| 外围增强能力 | 全文检索;复杂通知策略;富媒体和卡片展示细化;细粒度实时流映射;外部平台差异化同步;冷热归档优化;管理后台运营视图;大规模容量优化 |
| 边界外能力 | Chat UI 交互;Workspace 聚合视图;外部平台协议生命周期;LLM 推理循环;治理决策;产物正文和版本真相;成员生命周期;登录认证与权限裁决;全局观测和长期归档策略 |

### 7.4 功能线索回填映射

| 旧功能 / 能力线索 | 支撑的能力层级 | 处理口径 |
|---|---|---|
| 群聊、频道、私聊、讨论串等对话形态 | 核心能力闭环: 对话空间与参与范围 | 后续 Step 9 判断具体功能范围和优先级 |
| Turn 追加、不可原地改写、覆盖显示 | 核心能力闭环: 多来源协作事实追加沉淀 / 历史追溯 | 后续 Step 10 写规则,Step 11 写数据归属 |
| 授权查询、订阅、下游消费 | 核心能力闭环: 授权视野下稳定消费 | 后续 Step 12 写接口与依赖,不在本步展开 schema |
| 治理、产物、项目等事实进入对话视野 | 核心能力闭环: 关键跨域事实引用显化 | 原始真相仍归相邻仓,Conversation 只保留对话可见记录和引用 |
| 审计查看、复盘、导出线索 | 核心能力闭环: 历史追溯与复盘 | 后续 Step 14 验收,非功能和 archive 协作后续再细化 |
| AG-UI 细粒度事件映射、SSE / WebSocket | 外围增强能力 / 接口形态 | 后移到 Step 12 / Step 13,不得作为核心闭环节点 |
| 全文检索、分区、冷存、大规模吞吐 | 外围增强能力 / 非功能能力 | 后移到 Step 11 / Step 13 / 后续设计 |
| Chat 页面、Workspace 首页、外部平台适配、LLM 推理 | 边界外能力 | 分别归相邻仓,不得回流成 Conversation 功能 |

### 7.5 本章结论

Conversation 的核心闭环不是“消息发送成功”或“实时推送成功”,而是“对话事实作为平台协作真相持续成立”。因此后续用户故事和功能需求必须围绕对话空间、事实沉淀、授权消费、跨域显化和历史追溯展开;不能把 UI 体验、外部平台协议、推理循环或相邻仓业务真相写回本仓核心。

## 9. 待确认事项

| 编号 | 待确认事项 | 方案 A | 方案 B | 推荐 |
|---|---|---|---|---|
| Q-001 | 是否把实时推送作为核心闭环节点 | 是,无实时推送则对话不成立 | 否,核心是授权消费;实时推送是重要接口 / 非功能形态 | 推荐 B。原因是查询、订阅、推送都服务于“稳定消费”能力 |
| Q-002 | 是否把全文检索作为核心闭环节点 | 是,没有搜索就无法使用历史 | 否,历史追溯是核心,全文检索是增强方式 | 推荐 B。原因是追溯能力不等同于具体检索实现 |
| Q-003 | 是否把外部平台同步放入核心闭环 | 是,因为 Bridges 会消费 Conversation | 否,外部平台同步是协作增强,不决定内部对话真相成立 | 推荐 B。原因是外部平台协议归 `L6-bridges` |
| Q-004 | 是否把跨域事实显化纳入核心闭环 | 否,只做普通消息即可 | 是,但只以引用和可见记录方式纳入,不接管原始真相 | 推荐 B。原因是 Quantalithos 的对话承载人、AI 和系统协作事实 |

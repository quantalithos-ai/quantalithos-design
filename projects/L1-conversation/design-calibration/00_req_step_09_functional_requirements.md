## 3. SOP 问题回答

### 3.1 根据这些用户故事,系统必须提供哪些业务能力？

根据 Step 8 的故事,`L1-conversation` 至少需要五项核心闭环能力:

1. 对话空间与参与范围能力。
2. 协作事实追加沉淀能力。
3. 授权视野消费能力。
4. 跨域事实引用显化能力。
5. 对话历史追溯与复盘能力。

同时可以保留三项外围增强能力:

1. 对话索引 / 投影维护能力。
2. 长历史检索与定位能力。
3. 对话变化及时感知能力。

这些能力从用户故事归并而来,不是从旧对象、接口或命令名推导而来。

### 3.2 每个能力的输入、输出、触发条件、失败情况是什么？

本步只写需求层口径。输入不是 DTO,输出不是响应 schema,触发条件不是接口时序,失败情况不是错误码。它们用于说明能力边界,后续会在业务规则、数据归属、接口与验收步骤中继续细化。

### 3.3 哪些能力共同构成闭环核心？哪些只是外围增强？

前五项能力共同构成 Step 7 的核心闭环,缺一项都会导致 Conversation 退化为消息缓存、临时上下文或通知副本。后三项能力提升消费效率、维护性和实时体验,但不决定对话真相是否成立。

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 功能拆分依据 | 按 Conversation 形态、Turn kind、推送、事件、检索等条目拆 | 按支撑核心闭环的业务能力拆 | 对齐“功能需求不是对象 / 接口清单”的规范 |
| 功能粒度 | 既有核心能力,也有协议、存储和性能实现 | 核心能力优先,外围增强单独列出 | 防止 Step 9 过载 |
| 用户故事关系 | 用户故事与功能一对一或混写验收 | 多条故事可归并为同一能力 | 功能需求要归并故事,不是复述故事 |
| 边界外内容 | Chat、Bridges、Runtime 相关体验容易混入功能 | 仅保留 Conversation 自身能力 | 保护仓边界 |
| 后续承接 | 规则、数据、接口、非功能提前写入 | 分别后移 Step 10~13 | 保持需求主链分工 |

## 7. 结构化中间产物

### 7.1 功能需求表

| 功能需求 | 能力类型 | 说明 | 支撑的核心能力闭环 | 对应的用户故事 |
|---|---|---|---|---|
| FR-CONV-001: 对话空间与参与范围能力 | 核心闭环能力 | 系统必须支持围绕协作上下文形成明确的对话空间、参与范围和可见边界,让对话事实有稳定归属。 | 支撑“对话空间与参与范围能够被独立确立” | US-CONV-001 |
| FR-CONV-002: 协作事实追加沉淀能力 | 核心闭环能力 | 系统必须支持人类、AI member 和系统可见事实以追加方式沉淀为同一对话历史,避免对话事实被覆盖或散落。 | 支撑“多来源协作事实能够以追加方式沉淀” | US-CONV-002, US-CONV-003 |
| FR-CONV-003: 授权视野消费能力 | 核心闭环能力 | 系统必须支持人类、AI member、下游应用和审计角色在授权范围内稳定消费同一份对话事实。 | 支撑“对话事实能够按授权视野被稳定消费” | US-CONV-003, US-CONV-004, US-CONV-007 |
| FR-CONV-004: 跨域事实引用显化能力 | 核心闭环能力 | 系统必须支持治理、产物、项目等关键跨域事实以引用方式进入对话视野,同时保持原始真相归属不变。 | 支撑“关键跨域事实能够以引用方式显化到对话” | US-CONV-005 |
| FR-CONV-005: 对话历史追溯与复盘能力 | 核心闭环能力 | 系统必须支持项目负责人、参与者和审计者围绕对话历史追溯协作过程、关键上下文和责任边界。 | 支撑“对话历史能够被追溯并持续支撑协作复盘” | US-CONV-006, US-CONV-007 |
| FR-CONV-006: 对话索引 / 投影维护能力 | 外围增强能力 | 系统应支持在不改变业务事实的前提下维护用于消费和追溯的辅助结果。 | 支撑外围增强能力 | US-CONV-008 |
| FR-CONV-007: 长历史检索与定位能力 | 外围增强能力 | 系统可支持对较长对话历史进行定位和检索,提升复盘效率。 | 支撑外围增强能力 | US-CONV-009 |
| FR-CONV-008: 对话变化及时感知能力 | 外围增强能力 | 系统可支持消费方及时感知对话事实变化,提升客户端和协作体验。 | 支撑外围增强能力 | US-CONV-010 |

### 7.2 能力输入 / 输出 / 触发 / 失败口径

| 功能需求 | 输入口径 | 输出口径 | 触发条件 | 失败情况口径 |
|---|---|---|---|---|
| FR-CONV-001 | 协作上下文、参与者引用、可见范围意图 | 明确归属和参与范围的对话空间 | 新的协作主题、项目上下文或参与关系需要承载对话 | 协作上下文缺失、参与者引用无效或可见边界无法确定 |
| FR-CONV-002 | 人类发言、AI member 回应、系统可见事实 | 追加后的对话事实历史 | 授权参与方或系统记录方需要沉淀协作事实 | 对话空间不存在、参与方无权写入或来源事实不满足记录条件 |
| FR-CONV-003 | 授权消费方、目标对话范围、可见性上下文 | 按授权视野可消费的对话事实 | 人类、AI member、下游应用或审计角色需要读取 / 消费对话事实 | 消费方未授权、目标事实不可见或对话范围不存在 |
| FR-CONV-004 | 跨域事实引用、来源归属、目标对话上下文 | 对话中可见的引用型系统记录 | 相邻仓事实需要在协作上下文中被人或 AI member 看见 | 来源引用无效、目标对话不匹配或原始真相归属无法确认 |
| FR-CONV-005 | 对话历史范围、追溯目的、授权上下文 | 可用于复盘和审计的历史脉络 | 项目复盘、责任追踪、审计查看或上下文恢复需要发生 | 历史范围不可见、追溯上下文不足或授权不满足 |
| FR-CONV-006 | 既有对话事实、维护任务范围 | 不改变业务事实的辅助消费结果 | 索引、投影或消费辅助结果需要重建 / 修复 | 维护动作试图改变业务事实或来源事实不完整 |
| FR-CONV-007 | 长历史范围、定位意图、授权上下文 | 可定位的相关历史片段 | 参与者或审计者需要减少上下文丢失 | 查询范围不可见、历史不足或定位条件不成立 |
| FR-CONV-008 | 对话变化事实、消费方感知意图 | 对消费方可感知的变化提示 | 下游体验需要避免全量刷新或延迟感知 | 消费方未授权、变化不可见或感知通道不可用 |

### 7.3 功能间依赖

| 功能需求 | 依赖关系 | 说明 |
|---|---|---|
| FR-CONV-001 | 无上游功能依赖 | 对话空间与参与范围是其他核心能力的归属前提 |
| FR-CONV-002 | 依赖 FR-CONV-001 | 协作事实必须沉淀到明确的对话空间和参与范围内 |
| FR-CONV-003 | 依赖 FR-CONV-001、FR-CONV-002 | 消费能力依赖已存在的空间、参与范围和对话事实 |
| FR-CONV-004 | 依赖 FR-CONV-001、FR-CONV-002 | 跨域事实显化需要目标对话空间,并以追加事实形式出现 |
| FR-CONV-005 | 依赖 FR-CONV-002、FR-CONV-003、FR-CONV-004 | 追溯需要历史事实、授权消费和关键跨域上下文 |
| FR-CONV-006 | 依赖 FR-CONV-002、FR-CONV-003 | 维护辅助结果不能脱离原始对话事实和消费边界 |
| FR-CONV-007 | 依赖 FR-CONV-003、FR-CONV-005 | 长历史定位必须遵守授权视野并服务追溯 |
| FR-CONV-008 | 依赖 FR-CONV-002、FR-CONV-003 | 及时感知只提示已形成且可见的对话事实变化 |

### 7.4 边界外功能示例

| 看起来像功能的内容 | 为什么不进入本仓功能需求 |
|---|---|
| Chat 页面渲染、输入框、快捷键、富文本编辑 | 属于 `L5-chat` 交互体验 |
| Workspace 个人首页、项目看板和跨域聚合布局 | 属于 `L1-workspace` 视图聚合 |
| Mattermost / Slack 消息格式和协议生命周期 | 属于 `L6-bridges` 外部平台适配 |
| AI member 自动规划、调用工具和执行任务 | 属于 `L2-runtime` / `L2-tools` |
| Gate 决策、Policy 裁决、Approval 生命周期 | 属于 `L1-governance` |
| Artifact 正文、版本和证据链真相 | 属于 `L1-artifact` |
| 成员创建、角色定义和生命周期 | 属于 `L1-identity` 与方法定义来源 |

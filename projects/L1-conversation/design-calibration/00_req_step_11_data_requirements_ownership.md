## 1. 本步目标

说明 `L1-conversation` 在需求层拥有哪些对话真相数据、只保留哪些稳定消费快照、只保存哪些外部引用,以及哪些正文或原始真相绝不能由本仓保存。本步不写字段清单、表结构、索引、事务、缓存、outbox、projection、repo / service / port 或实现对象。

## 3. SOP 问题回答

### 3.1 哪些数据由本仓拥有真相？

`L1-conversation` 拥有对话空间、参与范围、可见范围、对话事实历史、对话内跨域显化记录和对话追溯上下文的正式真相。这里的“真相”只限于对话域内部:它说明某个对话事实在什么对话空间、面向哪些参与者、以什么可见记录存在,以及如何被追溯。

### 3.2 哪些数据只是快照？

成员展示摘要、项目展示摘要、跨域事实显示摘要、对话消费辅助摘要等可以作为快照数据存在。它们服务稳定消费和历史阅读,但正式真相仍归属 `L1-identity`、`L1-work`、`L1-governance`、`L1-artifact` 或其他来源仓。

### 3.3 哪些数据只是引用？

成员、项目、工作项、治理结论、产物、外部平台消息、全局 trace / audit material、归档对象等都只能作为引用关系进入 Conversation。Conversation 可以保存“对话中引用了哪个外部对象”的关系,但不拥有外部对象正文或生命周期。

### 3.4 哪些内容绝不能保存正文？

Conversation 不得保存 Chat UI 展示状态正文、Workspace 聚合视图正文、外部平台协议生命周期正文、LLM 推理过程正文、Gate / Policy / Approval 决策正文、Artifact 正文 / 版本 / 证据链、成员画像 / 生命周期真相、认证凭据、全局观测日志正文或长期归档包正文。

### 3.5 这些数据在需求层的生命周期口径是什么？

真相数据从对话空间或对话事实正式形成开始,随显式变化更新,直到对话空间正式终止或不再可用。快照数据随上游正式真相变化而刷新,不形成独立真相生命周期。引用数据随引用关系建立、变化或失效而变化,本仓不负责外部正文生命周期。禁止保存正文的数据不进入本仓生命周期。

| 项 | 改动前 | 改动后 | 原因 |

| 禁止保存正文 | 旧文档没有系统列出 | 明确列出相邻仓正文和原始真相不得进入本仓 | 守住仓边界 |

### 7.2 数据类型结论

| 数据类型 | 本步结论 |
|---|---|
| 真相数据 | Conversation 只拥有对话空间、参与 / 可见范围、对话事实历史、对话内显化记录和对话追溯上下文。 |
| 快照数据 | Conversation 可为稳定消费保留成员、项目、跨域事实和消费辅助摘要,但不形成独立真相。 |
| 引用数据 | Conversation 可保存成员、项目、治理、产物、外部平台、trace / audit material、归档对象等引用关系。 |
| 禁止保存正文 | UI、Workspace、外部平台协议、Runtime 推理、Governance、Artifact、Identity、认证、全局观测和长期归档正文不得进入本仓。 |

### 7.3 本章结论

`L1-conversation` 的数据归属边界是“拥有对话真相,引用外部真相,必要时保留消费快照,绝不保存相邻仓正文”。后续接口与依赖讨论必须以该归属边界为前提:对外能力只能围绕 Conversation 真相和引用关系展开,不能把外部正文或相邻仓生命周期纳入本仓能力。

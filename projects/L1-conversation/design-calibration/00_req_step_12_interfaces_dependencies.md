## 3. SOP 问题回答

### 3.1 本仓对外提供哪些能力级接口？

`L1-conversation` 对外提供的不是页面、SDK 函数或协议端点，而是围绕对话真相的能力级接口面。核心接口面包括：确立对话空间与参与范围、追加沉淀协作事实、授权消费对话事实、显化跨域事实引用、追溯与复盘对话历史。外围接口面包括：维护消费辅助结果、长历史检索定位、对话变化及时感知。

### 3.2 本仓消费哪些能力级输入？

本仓消费的能力级输入包括：`L0-core` 的共享契约定义、`L0-bus` 的事件协作主干、`L1-identity` 的 actor / participant 引用来源、`L1-work` 的项目 / 工作上下文、`L1-governance` 的治理结论引用、`L1-artifact` 的产物引用。外部聊天平台、UI 展示和 AI 推理循环不直接成为 Conversation 的输入依赖。

### 3.3 哪些是同步能力边界，哪些是异步能力边界？

同步能力边界主要体现为查询接口和变更接口，用于建立对话空间、追加事实、读取授权视野和追溯历史。异步能力边界主要体现为事件输出和事件输入，用于让对话事实变化被下游持续消费，或让已经被其他仓正式形成的协作事实进入对话可见范围。后台任务接口仅作为维护消费辅助结果、检索辅助结果和一致性修复的按需能力入口。

### 3.4 哪些依赖是输入型，哪些结果是输出型？

输入型依赖包括定义来源依赖、治理结论依赖和外部能力依赖。输出型结果主要是下游消费依赖，表现为 Chat、Workspace、Runtime、Bridges、Observability、Archive 等消费 Conversation 的对话事实、追溯材料或变化感知结果。

### 3.5 哪些能力边界属于当前阶段核心闭环，哪些只是外围增强？

FR-CONV-001~FR-CONV-005 对应的接口面属于核心闭环能力；FR-CONV-006~FR-CONV-008 对应的接口面属于外围增强能力。外围增强能力不能反向改变核心对话真相，也不能把检索、投影、推送或同步体验变成 Conversation 真相成立的前置条件。

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 接口表达 | 写 API / 事件 / AG-UI / 协议细节 | 写查询接口、变更接口、事件输入、事件输出、后台任务接口等能力面 | 需求阶段只收敛能力边界 |

| 全局依赖类型 | 未稳定保留编译期 / 运行期 / 事件协作判断 | 每条内部仓依赖保留 Step 6 的全局依赖类型 | 防止运行期或事件协作关系被误实现为源码依赖 |

## 7. 结构化中间产物

### 7.1 接口类型结论

| 接口类型 | 本仓使用口径 |
|---|---|
| 查询接口 | 面向下游或参与方提供授权读取、历史追溯、引用查看和长历史定位能力。 |
| 变更接口 | 面向授权写入方提供对话空间建立、参与范围调整、协作事实追加、跨域引用显化等正式变化能力。 |
| 事件输出 | 面向下游消费方输出对话事实变化、追溯材料形成或可感知变化。 |
| 事件输入 | 面向相邻真相域接收已经正式形成且可进入对话视野的协作事实或引用变化。 |
| 后台任务接口（按需） | 面向维护场景提供消费辅助结果维护、长历史辅助结果维护和一致性检查入口。 |

### 7.2 依赖类型结论

| 依赖类型 | 本仓使用口径 |
|---|---|
| 定义来源依赖 | Conversation 依赖共享契约、actor / participant、项目 / 工作上下文、产物和治理对象引用来源来确定能力边界。 |
| 治理结论依赖 | Conversation 在治理事实显化、审计复盘或受控可见性场景下依赖外部正式治理结论。 |
| 下游消费依赖 | Conversation 的事实、追溯材料和变化感知需要被 Chat、Workspace、Runtime、Bridges、Observability、Archive 等持续消费。 |
| 外部能力依赖（按需） | Conversation 按场景依赖项目、身份、产物、外部平台适配和归档等能力边界,但不接管这些系统的正文或生命周期。 |

### 7.3 对外能力接口表

| 接口类型 | 名称 | 说明 | 所属能力层级 |
|---|---|---|---|
| 变更接口 | 对话空间与参与范围确立 | 对外体现为正式建立对话空间、参与范围和可见边界的能力入口。 | 核心闭环能力 |
| 变更接口 | 协作事实追加沉淀 | 对外体现为把人类、AI member 或系统可见事实追加进入同一对话历史的能力入口。 | 核心闭环能力 |
| 查询接口 | 对话事实授权消费 | 对外体现为让授权参与方、下游应用或审计角色稳定读取可见对话事实的能力入口。 | 核心闭环能力 |
| 变更接口 | 跨域事实引用显化 | 对外体现为把治理、产物、项目等来源事实以引用方式显化到对话视野的能力入口。 | 核心闭环能力 |
| 查询接口 | 对话历史追溯与复盘 | 对外体现为围绕对话历史追溯协作过程、关键上下文和责任边界的能力入口。 | 核心闭环能力 |
| 事件输出 | 对话事实变化对下游可消费 | 对外体现为对话事实变化可被下游体系持续感知和消费的输出能力。 | 核心闭环能力 |
| 事件输入 | 外部正式事实进入对话视野 | 对外体现为接收已由相邻真相域正式形成、且可在对话中显化的事实输入面。 | 核心闭环能力 |
| 后台任务接口（按需） | 对话消费辅助结果维护 | 对外体现为维护不改变业务事实的索引、投影或辅助消费结果的能力入口。 | 外围增强能力 |
| 查询接口 | 长历史检索与定位 | 对外体现为在授权视野内定位较长对话历史片段的能力入口。 | 外围增强能力 |
| 事件输出 | 对话变化及时感知 | 对外体现为让消费方及时感知可见对话事实变化的输出能力。 | 外围增强能力 |

### 7.4 外部依赖边界表

| 依赖方向 | 依赖类型 | 关联方 | 全局依赖类型 | 说明 | 所属能力层级 |
|---|---|---|---|---|---|
| 输入 | 定义来源依赖 | `L0-core` | 编译期依赖 | 本仓依赖共享 ID、actor、trace、error、metadata 和通用契约来保持平台统一引用和追溯口径。 | 核心闭环能力 |
| 输入 | 外部能力依赖（按需） | `L0-bus` | 事件协作依赖 | 本仓依赖平台事件协作主干,让对话事实变化可进入跨仓协作。 | 核心闭环能力 |
| 输入 | 定义来源依赖 | `L1-identity` | 运行期依赖 | 本仓依赖成员、AI member、系统 actor 和参与者引用来源来确立参与和可见边界。 | 核心闭环能力 |
| 输入 | 定义来源依赖 | `L1-work` | 运行期依赖 / 事件协作依赖 | 本仓在项目型对话中依赖项目、工作项和项目成员上下文。 | 核心闭环能力 |
| 输入 | 治理结论依赖 | `L1-governance` | 运行期依赖 / 事件协作依赖 | 本仓在治理事实显化和受控复盘场景下依赖正式治理结论引用。 | 核心闭环能力 |
| 输入 | 定义来源依赖 | `L1-artifact` | 运行期依赖 / 事件协作依赖 | 本仓在产物事实显化场景下依赖产物、版本或证据对象引用来源。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L0-sdk` | 运行期依赖 | 本仓能力需要被 SDK 作为默认封装边界向产品和外部调用方暴露。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L5-chat` | 运行期依赖 | Chat 作为主要聊天入口消费对话事实,但不拥有对话真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-workspace` | 运行期依赖 / 事件协作依赖 | Workspace 消费对话事实并聚合到个人视野和项目视野。 | 核心闭环能力 |
| 输入 / 输出 | 外部能力依赖（按需） | `L6-bridges` | 运行期依赖 | Bridges 将外部平台输入 / 输出映射到正式边界,Conversation 不直接依赖外部平台协议。 | 外围增强能力 |
| 输入 / 输出 | 下游消费依赖 | `L2-runtime` | 运行期依赖 | Runtime 在授权视野内读取对话上下文并产生新的对话事实,推理循环不属于本仓。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L4-observability` | 事件协作依赖 | Observability 消费对话追溯材料或可观测材料,本仓不接管全局日志正文。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L4-archive` | 运行期依赖 / 事件协作依赖 | Archive 消费对话归档引用或导出材料,长期归档正文不属于本仓。 | 外围增强能力 |

### 7.5 能力边界与全局依赖类型映射结论

| 能力边界 | 主要接口类型 | 主要关联依赖 | 全局依赖类型结论 | 所属能力层级 |
|---|---|---|---|---|
| 对话空间与参与范围确立 | 变更接口 | `L0-core`、`L1-identity`、`L1-work` | 编译期依赖 + 运行期依赖 | 核心闭环能力 |
| 协作事实追加沉淀 | 变更接口 / 事件输入 | `L0-core`、`L0-bus`、`L1-identity`、`L2-runtime`、`L6-bridges` | 编译期依赖 + 运行期依赖 + 事件协作依赖 | 核心闭环能力 |
| 对话事实授权消费 | 查询接口 | `L0-sdk`、`L5-chat`、`L1-workspace`、`L2-runtime` | 运行期依赖 | 核心闭环能力 |
| 跨域事实引用显化 | 变更接口 / 事件输入 | `L1-work`、`L1-governance`、`L1-artifact`、`L0-bus` | 运行期依赖 + 事件协作依赖 | 核心闭环能力 |
| 对话历史追溯与复盘 | 查询接口 / 事件输出 | `L4-observability`、`L4-archive`、`L1-governance` | 运行期依赖 + 事件协作依赖 | 核心闭环能力 |
| 对话消费辅助结果维护 | 后台任务接口（按需） | `L0-core`、`L0-bus` | 编译期依赖 + 事件协作依赖 | 外围增强能力 |
| 长历史检索与定位 | 查询接口 | `L0-sdk`、`L5-chat`、`L1-workspace`、`L4-archive` | 运行期依赖 | 外围增强能力 |
| 对话变化及时感知 | 事件输出 | `L0-bus`、`L5-chat`、`L1-workspace`、`L2-runtime` | 事件协作依赖 + 运行期依赖 | 外围增强能力 |

### 7.6 本章结论

`L1-conversation` 的接口边界应围绕“对话真相如何形成、如何被授权消费、如何显化跨域引用、如何被追溯复盘”来表达。`L0-core` 是唯一编译期依赖；`L0-bus` 是事件协作主干；`L1-identity`、`L1-work`、`L1-governance`、`L1-artifact` 等只作为运行期或事件协作能力输入；Chat、Workspace、Runtime、Bridges、Observability 和 Archive 是下游消费方或协作方。任何运行期或事件协作依赖都不能在需求文档中被转写为源码依赖或协议实现。

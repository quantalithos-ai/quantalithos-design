## 3. SOP 问题回答

### 3.1 哪些条件满足后,核心能力闭环算成立？

当 Conversation 能够明确建立对话空间与参与范围,以追加方式沉淀多来源协作事实,按授权视野稳定消费同一份对话事实,以引用方式显化关键跨域事实,并支撑历史追溯与复盘时,核心能力闭环才算成立。缺少任一节点,都不能判定为通过。

### 3.2 哪些功能能力满足后,本次需求算完成？

FR-CONV-001~FR-CONV-005 必须作为核心能力全部成立。FR-CONV-006~FR-CONV-008 作为外围增强能力,应满足“不改变核心业务事实、不反向阻塞核心闭环、边界清晰”的验收口径。

### 3.3 哪些规则 / 边界被满足后,才算没有串线？

必须证明 Conversation 不接管 Chat UI、Workspace 聚合、Bridges 外部平台协议、Runtime 推理、Governance 决策、Artifact 正文、Identity 生命周期、Observability 全局日志和 Archive 长期正文。任何相邻仓正文或生命周期真相回流,都说明边界串线。

### 3.4 哪些数据边界被满足后,才算数据归属正确？

Conversation 只能拥有对话空间、参与 / 可见范围、对话事实历史、对话内跨域显化记录和追溯上下文。成员、项目、治理、产物、外部平台、trace / audit material、归档对象等只能作为快照或引用。禁止保存正文清单不得进入本仓数据归属。

### 3.5 哪些非功能要求被满足后,才算质量达标？

核心追加、授权消费和追溯不能成为主协作路径长期瓶颈;外围增强和下游消费方降级不能破坏核心真相;授权视野和正文边界必须被遵守;关键变化、跨域显化和维护动作必须可追溯;重复输入不得形成冲突事实;核心状态和边界违规风险必须可观察。

### 3.6 哪些失败情形属于一票否决？

一票否决只用于整体需求不应判定为通过的情况,包括核心闭环不成立、授权视野失效、相邻仓正文进入本仓、关键事实可被覆盖、跨域显化接管原始真相、关键变化不可追溯等。

## 7. 结构化中间产物

### 7.1 验收类别结论

| 验收类别 | 本仓验收关注点 |
|---|---|
| 核心能力闭环验收 | 验证对话空间、事实沉淀、授权消费、跨域显化、历史追溯五个节点是否共同成立。 |
| 功能能力验收 | 验证 FR-CONV-001~FR-CONV-008 是否以业务能力方式成立,且核心 / 外围分层正确。 |
| 规则 / 边界验收 | 验证不变量、禁止行为、显式变化、边界、治理和审计规则是否被满足。 |
| 数据归属验收 | 验证真相、快照、引用和禁止保存正文的归属边界是否正确。 |
| 非功能验收 | 验证性能、可用性、安全、审计 / 可追溯、幂等 / 一致性、可观测性底线是否达标。 |

### 7.2 验收标准表

| 验收类别 | 验收项 | 验收条件 |
|---|---|---|
| 核心能力闭环验收 | 对话真相闭环成立 | 对话空间与参与范围、事实追加、授权消费、跨域显化、历史追溯五个节点能够共同成立,且任一节点缺失时不能判定为完整通过。 |
| 核心能力闭环验收 | Conversation 不退化为消息缓存 | 对话事实具备正式归属、参与 / 可见边界和可追溯历史,而不是仅作为 UI 消息、通知副本或 runtime 临时上下文存在。 |
| 功能能力验收 | 对话空间与参与范围能力 | 系统能够围绕协作上下文形成明确的对话空间、参与范围和可见边界。 |
| 功能能力验收 | 协作事实追加沉淀能力 | 人类、AI member 和系统可见事实能够以追加方式进入同一对话历史,且不会覆盖既有业务事实。 |
| 功能能力验收 | 授权视野消费能力 | 参与方、下游应用和审计角色只能在授权范围内稳定消费可见对话事实。 |
| 功能能力验收 | 跨域事实引用显化能力 | 治理、产物、项目等关键跨域事实能够以引用方式显化到对话中,且原始真相归属不变。 |
| 功能能力验收 | 对话历史追溯与复盘能力 | 对话历史能够支撑协作过程、关键上下文和责任边界的追溯与复盘。 |
| 功能能力验收 | 外围增强能力不改变真相 | 索引 / 投影维护、长历史定位和及时感知只能提升消费效率,不能改变核心业务事实。 |
| 规则 / 边界验收 | 核心不变量成立 | 对话归属、追加历史、授权消费、引用显化和历史追溯五类不变量均被满足。 |
| 规则 / 边界验收 | 相邻仓职责不回流 | Chat UI、Workspace、Bridges、Runtime、Governance、Artifact、Identity、Observability、Archive 的正文或生命周期真相不由 Conversation 接管。 |
| 规则 / 边界验收 | 显式变化边界成立 | 对话空间、参与范围、可见范围、事实追加和跨域显化必须是显式变化,不得由读取、消费、检索或投影隐式改变。 |
| 规则 / 边界验收 | 治理和审计边界成立 | 治理事实显化必须保留正式治理结论引用,关键变化必须能够支撑审计追溯。 |
| 数据归属验收 | Conversation 真相数据归属正确 | 本仓只拥有对话空间、参与 / 可见范围、对话事实历史、对话内显化记录和追溯上下文。 |
| 数据归属验收 | 外部对象仅以快照或引用进入 | 成员、项目、治理、产物、外部平台、trace / audit material、归档对象等只能作为快照或引用进入本仓。 |
| 数据归属验收 | 禁止保存正文未进入本仓 | Chat UI、Workspace、外部平台协议、Runtime 推理、Governance、Artifact、Identity、认证、全局观测和长期归档正文不得进入 Conversation 数据归属。 |
| 非功能验收 | 核心路径不被外围增强阻塞 | 外围增强能力或下游消费方降级时,核心空间建立、事实追加、授权消费和追溯仍能判断成立。 |
| 非功能验收 | 授权、安全和一致性达标 | 授权视野有效,重复输入不形成冲突真相,辅助结果不替代原始对话事实。 |
| 非功能验收 | 关键变化和风险可观察 | 对话核心状态、关键变化、依赖降级和边界违规风险能够被平台稳定观察。 |

### 7.3 一票否决项

- 核心能力闭环任一必要节点缺失,导致 Conversation 不能作为平台对话真相域成立。
- 对话事实可以脱离明确对话空间、参与范围或可见范围而存在。
- 已形成的对话业务事实可以被覆盖、抹除或改写成另一事实。
- 授权视野失效,导致未授权消费方能够读取不可见对话事实。
- 跨域事实显化接管来源仓原始真相,而不是以引用方式进入对话。
- Chat UI、Workspace、Bridges、Runtime、Governance、Artifact、Identity、Observability 或 Archive 正文进入 Conversation 真相范围。
- Conversation 直接承担 LLM 推理、治理裁决、成员生命周期或外部平台协议生命周期。
- 对话空间、参与范围、可见范围、事实追加、跨域显化等关键变化不可追溯。
- 外围增强能力或下游消费方降级会破坏已形成的核心对话真相。

### 7.4 本章结论

`L1-conversation` 的需求验收必须围绕“平台对话真相是否成立”来判断。只要核心闭环缺失、边界串线、数据归属越界、授权视野失效或关键变化不可追溯,就不应判定为需求通过。外围增强能力可以分阶段完善,但不得改变核心真相边界。

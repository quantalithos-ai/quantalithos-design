## 3. SOP 问题回答

### 3.1 当前还有哪些尚未关闭的风险？

当前风险集中在五类:旧详细设计术语回流到需求主链、外围增强能力被误判为核心闭环、相邻仓正文因显示便利进入 Conversation、后续缺少负载模型导致非功能数字被随意补写、以及下游消费方把自己的视图或推理需求反向定义为 Conversation 真相。

这些风险不是当前需求步骤要解决的设计问题,而是需要在正式需求文档中显式约束的边界风险。

### 3.2 这些风险会影响哪一层需求结构？

旧术语回流会影响定位、功能和接口章节。外围增强误判会影响核心闭环、功能、非功能和验收章节。相邻仓正文回流会影响规则、数据归属、安全和一票否决项。非功能数字被随意补写会影响非功能和验收章节。下游消费方反向定义真相会影响使用方、接口和数据归属。

### 3.3 当前还有哪些待确认事项？

仍需挂起的问题主要是后续阶段性范围和设计细节,包括外围增强能力是否进入当前交付阶段、正式协议和事件命名、量化非功能指标、快照新鲜度口径、归档交接边界、外部平台映射粒度、个人 / 项目对话空间的具体形态。

### 3.4 哪些待确认项会影响前文结论是否成立？

这些待确认项不改变当前需求主线:Conversation 是平台对话真相仓,拥有对话真相,只引用外部真相。它们会影响后续架构、详细设计、测试方案和实施计划的具体展开,但当前不能反向推翻已收敛的仓边界。

### 3.5 哪些风险是当前阶段可接受的,哪些会阻塞后续推进？

当前可接受的风险是:外围能力阶段范围、协议命名、量化指标和快照新鲜度尚未细化,因为它们可以在后续设计与测试文档中继续收敛。会阻塞后续推进的风险是:核心闭环定义被推翻、相邻仓正文进入 Conversation、授权视野边界失效、或外部平台 / Runtime / Governance 等职责回流。

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 风险表达 | 各 Step 分散列出 Q-001 等分歧 | 汇总为影响正式需求稳定性的风险 | Step 15 不重复讨论已关闭方案 |
| 待确认事项 | 容易把 TODO、设计细节和阶段范围混写 | 只保留会影响后续文档展开的问题 | 对齐 §4.15 粒度要求 |
| 当前处理口径 | 容易写“后续解决” | 写当前如何约束、暂存或归类 | 避免空泛状态词 |
| 边界风险 | 旧文档中隐含在功能和接口里 | 明确列出正文回流、职责回流和外围能力回流风险 | 保护 Conversation 真相边界 |

## 7. 结构化中间产物

### 7.1 风险清单

| 风险 | 影响范围 | 当前处理口径 |
|---|---|---|
| 旧文档中的 Conversation kind、Turn kind、AG-UI、接口和事件线索可能回流为需求主链。 | 本仓定位、功能需求、接口与依赖 | 当前按历史候选输入暂存,不得高于新版需求 SOP 和 D-001~D-018 决策。 |
| 实时感知、全文检索、外部平台同步等外围增强能力可能被误判为核心闭环。 | 核心能力闭环、功能需求、验收标准 | 当前按外围增强处理,只有破坏核心真相或授权消费时才进入一票否决。 |
| 为了展示便利而保存成员、项目、治理、产物、外部平台或归档正文。 | 数据归属、安全、规则 / 边界验收 | 当前按快照 / 引用边界约束,禁止保存正文已进入数据归属和一票否决项。 |
| 由于当前缺少正式负载模型,后续可能随意补写吞吐、延迟或容量数字。 | 非功能需求、验收标准、测试方案 | 当前保留判断口径,量化目标暂不写入需求主链。 |
| Chat、Workspace、Runtime、Bridges 等下游消费方可能反向定义 Conversation 真相。 | 使用方与依赖、接口与依赖、数据归属 | 当前按使用方 / 协作方处理,不得成为事实所有者。 |
| AI member 个人视野与项目视野需求可能被误写成 Conversation 视图聚合职责。 | 用户与角色、核心能力闭环、数据归属 | 当前按 Conversation 提供对话真相处理,个人 / 项目视野聚合不进入本仓真相范围。 |
| 跨域事实显化可能被过度展开为治理、产物、项目等来源仓的正文管理。 | 功能需求、规则边界、数据归属 | 当前统一按引用显化处理,来源仓原始真相不进入 Conversation。 |

### 7.2 待确认事项

| 待确认事项 | 影响章节 | 当前状态 |
|---|---|---|
| 外围增强能力中哪些进入当前交付阶段,例如长历史检索、及时感知、消费辅助维护。 | §9 功能需求、§12 接口与依赖、§14 验收标准 | 当前暂按外围增强处理,不作为核心闭环成立条件。 |
| 正式协议、事件、DTO、API 名称和字段如何定义。 | §12 接口与依赖、后续架构 / 详细设计 | 当前暂不纳入需求主链,只保留能力级接口边界。 |
| 核心追加、授权消费、追溯等能力的量化非功能目标。 | §13 非功能需求、§14 验收标准、后续测试方案 | 当前保持判断口径,不强行定论具体数字。 |
| 成员、项目、治理、产物等快照数据的新鲜度和失效显示口径。 | §11 数据需求与数据归属、§13 非功能需求 | 当前按快照 / 引用挂起,不把快照视为本仓真相。 |
| Conversation 与 `L4-archive` 的长期归档交接边界。 | §11 数据需求与数据归属、§13 非功能需求、§14 验收标准 | 当前只确认归档正文不归本仓,具体交接后移到后续设计。 |
| 外部平台消息、thread、channel 等外部结构如何映射为内部对话事实。 | §6 使用方与依赖、§12 接口与依赖 | 当前按 `L6-bridges` 边界挂起,Conversation 不直接理解外部协议生命周期。 |
| 个人对话、项目对话、系统记录和审计复盘等对话空间的具体形态。 | §7 核心能力闭环、§9 功能需求、后续概要 / 详细设计 | 当前只确认对话空间与参与范围能力,具体对象形态后移。 |

### 7.3 当前状态结论

| 类型 | 本步结论 |
|---|---|
| 当前可接受风险 | 外围增强范围、协议命名、量化指标、快照新鲜度、归档交接和外部平台映射尚未细化,但已被挂起到后续设计或测试文档。 |
| 当前不可接受风险 | 核心闭环被推翻、相邻仓正文进入本仓、授权视野失效、关键变化不可追溯、下游消费方反向定义 Conversation 真相。 |
| 当前不作为待确认项处理 | 已在 D-001~D-018 中收敛的分歧,例如是否拥有 Chat UI、是否运行 Runtime 推理、是否拥有 Governance / Artifact 真相、是否把 `L0-bus` 写成编译期依赖。 |

### 7.4 本章结论

`L1-conversation` 当前需求主线已经收敛,但后续设计仍需要谨慎处理外围增强范围、协议细化、量化非功能、快照新鲜度、归档交接和外部平台映射。本章不解决这些问题,只明确它们在当前需求阶段如何被约束和挂起。

## 3. SOP 问题回答

### 3.1 每个核心能力闭环节点对应哪些用户故事？

对话空间与参与范围对应 US-CONV-001。多来源事实追加沉淀对应 US-CONV-002 和 US-CONV-003。授权视野稳定消费对应 US-CONV-003、US-CONV-004 和 US-CONV-007。跨域事实引用显化对应 US-CONV-005。历史追溯与复盘对应 US-CONV-006 和 US-CONV-007。

### 3.2 每个用户故事对应哪些功能需求？

US-CONV-001 对应 FR-CONV-001。US-CONV-002 和 US-CONV-003 对应 FR-CONV-002,其中 US-CONV-003 同时对应 FR-CONV-003。US-CONV-004 和 US-CONV-007 对应 FR-CONV-003。US-CONV-005 对应 FR-CONV-004。US-CONV-006 和 US-CONV-007 对应 FR-CONV-005。US-CONV-008、US-CONV-009、US-CONV-010 分别对应 FR-CONV-006、FR-CONV-007、FR-CONV-008。

### 3.3 每个功能需求对应哪些业务规则？

核心功能均有规则保护:FR-CONV-001 对应 BR-CONV-001、BR-CONV-013、BR-CONV-020;FR-CONV-002 对应 BR-CONV-002、BR-CONV-014、BR-CONV-020;FR-CONV-003 对应 BR-CONV-003、BR-CONV-013、BR-CONV-018;FR-CONV-004 对应 BR-CONV-004、BR-CONV-015、BR-CONV-017、BR-CONV-019;FR-CONV-005 对应 BR-CONV-005、BR-CONV-020。外围增强功能对应 BR-CONV-016、BR-CONV-021 或授权 / 输出边界规则。

### 3.4 每个功能需求对应哪些数据归属要求？

FR-CONV-001 对应对话空间、参与范围、可见范围真相。FR-CONV-002 对应对话事实历史。FR-CONV-003 对应对话可见范围、消费快照和引用边界。FR-CONV-004 对应对话内跨域显化记录、跨域事实显示摘要和外部引用。FR-CONV-005 对应对话事实历史、追溯上下文和 trace / audit material 引用。外围增强功能只对应消费辅助摘要、历史片段定位或变化感知结果,不得形成新的业务真相。

### 3.5 每个功能需求对应哪些验收标准？

FR-CONV-001~FR-CONV-005 分别对应功能能力验收中的五项核心能力验收,并共同承接核心能力闭环验收。FR-CONV-006~FR-CONV-008 对应“外围增强能力不改变真相”“核心路径不被外围增强阻塞”“授权、安全和一致性达标”等验收项。

### 3.6 是否存在没有来源的功能、没有承接的规则、没有验收的能力？

本步检查结论为:没有故事来源缺失的功能需求,没有缺少闭环映射的核心功能,没有缺少规则保护的核心功能,没有缺少验收标准的功能需求,也没有在矩阵中新增前文未确认项。BR-CONV-006~BR-CONV-012 属于跨功能边界规则,通过规则 / 边界验收和一票否决项承接,不视为孤儿规则。

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 追溯方式 | 各 Step 分别成立,但缺少横向连接 | 以 FR-CONV-001~FR-CONV-008 为中心建立矩阵 | 对齐 §4.16 主轴要求 |
| 漏项检查 | 依赖人工阅读各章节 | 单独列出漏项检查表 | 明确检查孤儿需求、孤儿规则和孤儿验收项 |
| 边界规则 | 容易看成没有功能对应 | 标注为跨功能边界规则,由边界验收承接 | 避免误删必要规则 |
| 外围增强 | 容易被当成核心缺口 | 在矩阵中标明外围增强能力 | 保持核心 / 外围分层 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 以用户故事为主轴 | 更贴近需求叙事 | 不符合书写规范,难以检查功能和规则承接 | 不采用 |
| 方案 B: 以功能需求为主轴 | 符合 SOP,能连接闭环、故事、规则、数据和验收 | 表格较密 | 采用 |
| 方案 C: 以规则为主轴 | 能突出边界 | 会把业务能力拆散,也不符合固定结构 | 不采用 |
| 方案 D: 只写自然语言总结 | 简短 | 无法发现漏项和孤儿项 | 不采用 |

### 7.2 漏项检查表

| 检查项 | 结果 |
|---|---|
| 是否存在没有故事来源的功能需求 | 否。FR-CONV-001~FR-CONV-008 均映射到 US-CONV-001~US-CONV-010。 |
| 是否存在没有闭环映射的功能需求 | 否。FR-CONV-001~FR-CONV-005 映射到五个核心闭环节点;FR-CONV-006~FR-CONV-008 明确标为外围增强能力。 |
| 是否存在没有规则保护的核心功能 | 否。FR-CONV-001~FR-CONV-005 均有不变量、显式变化、边界或审计规则保护。 |
| 是否存在没有验收标准的功能需求 | 否。每个功能需求都映射到 Step 14 的功能能力验收、规则 / 边界验收、数据归属验收或非功能验收。 |
| 是否存在未进入前文结构却出现在矩阵中的新项 | 否。矩阵只使用 Step 7~Step 14 已确认的闭环、故事、功能、规则、数据和验收项。 |
| 是否存在孤儿规则 | 否。BR-CONV-006~BR-CONV-012 属于跨功能禁止行为规则,通过相邻仓职责不回流、一票否决项和数据归属验收承接。 |
| 是否存在孤儿验收项 | 否。Step 14 的核心闭环、功能能力、规则 / 边界、数据归属和非功能验收均能追溯到前文结构。 |
| 是否存在结构串线项 | 否。Chat、Workspace、Bridges、Runtime、Governance、Artifact、Identity、Observability、Archive 均以边界或依赖方式出现,没有成为 Conversation 真相所有者。 |

### 7.3 本章结论

`L1-conversation` 的需求结构已经形成闭环追溯:核心闭环由用户故事支撑,用户故事归并为功能需求,功能需求受业务规则和数据归属约束,并由验收标准收口。当前矩阵未发现孤儿功能、孤儿核心规则、孤儿验收项或新增未确认项。

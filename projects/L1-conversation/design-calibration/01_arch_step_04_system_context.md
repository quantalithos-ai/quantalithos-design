## 3. SOP 问题回答

### 3.1 这个仓在全局系统中的位置是什么？

`L1-conversation` 位于 L1 领域服务层,是平台对话真相仓。它承接 `L0-core` 的共享契约和 `L0-bus` 的事件协作基础,使用 `L1-identity` 等上游来源的引用来确立对话参与与可见边界,并向 Chat、Workspace、Runtime、Bridges、Observability、Archive 等消费方提供授权范围内的对话事实、上下文和变化感知基础。

### 3.2 它有哪些正式上游？

正式上游分为三类:

- L0 底座: `L0-core` 和 `L0-bus`,提供共享契约、引用、trace、metadata 和事件协作主干。
- 身份与成员来源: `L1-identity`,提供成员、AI member、system actor 和 actor 引用来源。
- 跨域事实来源: `L1-work`、`L1-governance`、`L1-artifact`,提供项目 / 工作、治理、产物等来源事实的正式引用边界。

### 3.3 它有哪些正式下游？

正式下游包括:

- `L0-sdk`,作为默认 client / integration access 封装面。
- `L5-chat` 和 `L1-workspace`,消费对话事实以形成聊天入口、个人视野和项目视野。
- `L2-runtime`,在授权范围内读取对话上下文并把结果性协作事实回写为正式对话事实。
- `L6-bridges`,把外部平台输入 / 输出映射到正式 Conversation 边界。
- `L4-observability` 和 `L4-archive`,消费追溯、审计、归档和导出材料。

### 3.4 它从外部接收哪些输入面？

`L1-conversation` 从外部接收以下输入面:

- 共享契约与事件协作基础。
- 成员、AI member、system actor 和参与者引用。
- 项目、工作、治理、产物等跨域正式事实引用。
- 来自人类、AI member、系统 actor 或外部平台边界的协作事实输入。
- 运维 / 审计所需的受控维护和追溯读取请求。

这些输入面进入本仓后只能形成 Conversation 自身真相、快照、引用或显化记录,不得复制相邻仓正文。

### 3.5 它向外部提供哪些输出面？

`L1-conversation` 向外部提供以下输出面:

- 授权视野内的对话事实读取和上下文消费。
- 对话事实变化感知基础。
- 对话内跨域显化记录和引用材料。
- 对话历史追溯、复盘和审计材料。
- 面向 Chat、Workspace、Runtime、Bridges、SDK、Observability、Archive 的稳定消费边界。

这些输出面不得让消费方反向定义 Conversation 真相。

### 3.6 哪些外部系统或相邻仓构成正式上下文边界？

正式上下文边界包括:

- `L0-core` / `L0-bus`: L0 底座依赖。
- `L1-identity`: 身份、成员和 actor 引用来源。
- `L1-work` / `L1-governance` / `L1-artifact`: 跨域事实来源。
- `L0-sdk` / `L5-chat` / `L1-workspace`: 默认 client、聊天和视图消费方。
- `L2-runtime` / `L6-bridges`: 协作事实输入 / 消费和外部平台映射协作方。
- `L4-observability` / `L4-archive`: 追溯、观测、归档和导出消费方。

### 3.7 依赖失效时,本仓的降级口径是什么？

`L0-core` 契约不稳定时,不得新增或擅自补造共享引用语义。`L0-bus` 不可用时,本仓已形成的 Conversation 真相不得丢失,对外变化感知和跨仓协作可以挂起或延迟。`L1-identity` 或跨域事实来源不可用时,本仓只能保留自身引用、快照或未解析状态,不得补造成员、项目、治理或产物正文。下游消费方不可用时,不得反向改变 Conversation 真相;观测或归档不可用时,本仓保留可追溯接缝,但不接管全局长期存储职责。

|---|---|---|---|

## 7. 结构化中间产物

### 7.1 系统上下文图

```text
+------------------------+     +------------------------+     +------------------------+
| L0-core / L0-bus      |     | L1-identity            |     | L1-work / governance   |
| shared base           |     | actor/member refs      |     | / artifact source refs |
+-----------+------------+     +-----------+------------+     +-----------+------------+
            |                              |                              |
            | 输入 / 依赖                  | 输入                         | 输入
            v                              v                              v
        +---+-------------------------------------------------------------------+---+
        |                         L1-conversation                                |
        |                  platform conversation truth repository                |
        +---+-----------------------------+-----------------------------+---------+
            |                             |                             |
            | 输出                        | 输入 / 输出                 | 输出
            v                             v                             v
+-----------+------------+     +----------+-------------+     +----------+-------------+
| L0-sdk / L5-chat      |     | L2-runtime / L6-bridges|     | L4-observability      |
| / L1-workspace        |     | collaboration boundary |     | / L4-archive          |
| client/view consumers |     | and external mapping   |     | trace/archive consume |
+------------------------+     +------------------------+     +------------------------+
```

该图仅表达本仓与正式上下文对象之间的边界关系与输入/输出方向，不表达接口、事件、实现组件或运行时顺序。

图示说明:

- `L0-core` / `L0-bus` 是本仓成立的底座依赖,但不拥有 Conversation 真相。
- `L1-identity` 和 `L1-work` / `L1-governance` / `L1-artifact` 提供引用或来源事实边界,其正文真相不得进入本仓。
- `L0-sdk`、`L5-chat` 和 `L1-workspace` 是主要消费面,不能反向定义对话事实。
- `L2-runtime` 和 `L6-bridges` 既可能消费授权上下文,也可能通过正式边界输入协作事实。
- `L4-observability` / `L4-archive` 消费追溯和归档材料,不改变本仓业务事实。

### 7.2 上下游与输入 / 输出面表

| 对象 | 关系方向 | 关系类型 | 输入/输出面 | 说明 |
|---|---|---|---|---|
| `L0-core` | 输入 | 依赖 | 共享 ID、ActorRef、TraceContext、Error、metadata、通用契约 | 本仓依赖统一引用和追溯口径,不得重新定义 L0 契约。 |
| `L0-bus` | 输入 / 输出 | 依赖 | 平台事件协作主干、变化感知和跨仓协作边界 | Bus 不拥有 Conversation 真相,但承载跨仓协作和下游感知。 |
| `L1-identity` | 输入 | 来源 | 成员、AI member、system actor 和参与者引用 | Conversation 只保存引用 / 展示快照,不拥有成员生命周期。 |
| `L1-work` | 输入 | 来源 | 项目、工作项、项目成员上下文引用 | 项目型对话依赖其锚点,但项目真相仍归 `L1-work`。 |
| `L1-governance` | 输入 | 来源 | Gate、Policy、Approval 等治理结论引用 | Conversation 只显化治理结论引用,不裁决治理结果。 |
| `L1-artifact` | 输入 | 来源 | 产物、版本、证据对象引用 | Conversation 只显化产物引用或摘要,不保存产物正文。 |
| `L0-sdk` | 输出 | 消费 | 默认 client / integration access | SDK 封装消费路径,不反写 Conversation 真相。 |
| `L5-chat` | 输出 | 消费 | 聊天入口所需对话事实和变化感知 | Chat 负责展示和交互状态,Conversation 只提供事实。 |
| `L1-workspace` | 输出 | 消费 | 个人视野、项目视野和 inbox 聚合所需对话事实 | Workspace 只聚合视图,不拥有 Conversation 空间真相。 |
| `L2-runtime` | 输入 / 输出 | 消费 / 协作 | AI member 授权上下文读取和结果性对话事实输入 | Runtime 执行推理和工具循环,Conversation 只记录正式结果事实。 |
| `L6-bridges` | 输入 / 输出 | 协作 | 外部平台输入 / 输出映射边界 | Bridges 负责外部协议生命周期,内部 Conversation 不依赖外部平台对象成立。 |
| `L4-observability` | 输出 | 消费 | trace、audit、运行观察和风险材料 | 观测系统消费追溯材料,不改变业务事实。 |
| `L4-archive` | 输出 | 消费 | 归档、导出和长期留存材料 | Archive 负责长期归档和恢复策略,Conversation 保留交接边界。 |

### 7.3 依赖失效降级口径

| 对象 | 失效情况 | 架构口径 |
|---|---|---|
| `L0-core` | 共享契约、引用或 trace 口径不稳定 | 不新增正式契约语义,不得自行补造共享类型。 |
| `L0-bus` | 事件协作主干不可用 | 已形成 Conversation 真相不得丢失;变化感知、跨仓协作和下游通知可挂起或延迟。 |
| `L1-identity` | 成员或 actor 引用暂不可解析 | 保留既有 actor 引用和展示快照;不得补造成员生命周期结论。 |
| `L1-work` / `L1-governance` / `L1-artifact` | 来源事实暂不可解析 | 保留引用缺失或未解析状态;不得复制或推断来源仓正文。 |
| `L0-sdk` / `L5-chat` / `L1-workspace` | 下游消费方不可用 | 不改变 Conversation 真相,只影响对应消费面体验或聚合结果。 |
| `L2-runtime` / `L6-bridges` | 协作输入方或外部映射不可用 | 相关参与能力降级,内部 Conversation 真相仍独立成立。 |
| `L4-observability` / `L4-archive` | 观测或归档消费不可用 | 本仓保留追溯接缝和交接材料,不接管全局长期存储职责。 |

### 7.4 边界说明结论

`L1-conversation` 的系统上下文围绕“底座依赖、来源引用、协作输入、授权消费和追溯输出”展开。进入主图的对象都是会影响 Conversation 真相成立、引用显化、消费边界或追溯交接的正式上下文对象;用户角色、UI 组件、接口名、事件名和 DTO 不进入本章。`L1-work`、`L1-governance`、`L1-artifact` 等来源仓只提供正式引用或快照来源,不把正文真相转移给 Conversation。`L5-chat`、`L1-workspace`、`L2-runtime`、`L6-bridges`、`L4-observability` 和 `L4-archive` 可以消费或协作,但不得反向定义本仓业务事实。

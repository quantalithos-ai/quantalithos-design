## 3. SOP 问题回答

### 3.1 本仓内部有哪些子域或本地上下文？

`L1-conversation` 内部应划分为三层:

- 核心子域:`Conversation 真相核心`。
- 支撑子域:`对话空间与范围管理上下文`、`协作事实追加上下文`、`授权消费上下文`、`跨域事实显化上下文`、`历史追溯上下文`、`派生消费辅助上下文`。
- 本地索引 / 投影 / 引用:`成员 / actor 引用与展示快照`、`项目 / 工作上下文引用与摘要`、`治理 / 产物引用与显示摘要`、`对话消费投影 / 检索索引 / 变化感知游标`、`外部平台消息引用`、`追溯 / 归档对象引用`。

### 3.2 哪些是核心子域？

核心子域只有一个:`Conversation 真相核心`。它承载对话域内部最稳定的真相语义,包括对话空间、参与范围、可见范围、对话事实历史、对话内跨域显化记录和对话追溯上下文。

将核心子域收束为一个中心,是为了避免后续把“空间”“事实”“显化”“追溯”拆成互相竞争的多个 truth source。它们可以在后续概要 / 详细设计中分对象和功能展开,但在架构语义上共同属于 Conversation 真相核心。

### 3.3 哪些是支撑子域？

支撑子域围绕 Conversation 真相核心存在:

- 对话空间与范围管理上下文,用于管理空间、参与范围和可见范围的正式变化。
- 协作事实追加上下文,用于承接人类、AI member 和系统可见事实的追加沉淀语义。
- 授权消费上下文,用于确保查询、订阅、变化感知和下游读取都受可见范围约束。
- 跨域事实显化上下文,用于把来源仓正式事实以引用 / 快照 / 显化记录方式带入对话视野。
- 历史追溯上下文,用于支撑复盘、审计和关键变化追溯。
- 派生消费辅助上下文,用于维护索引、投影、检索和变化感知等不反写真相的辅助结构。

### 3.4 哪些只是外部上下文的本地索引 / 投影 / 引用？

以下结构只能作为本地影子层存在:

- 成员 / actor 引用与展示快照。
- 项目 / 工作上下文引用与摘要。
- 治理 / 产物引用与显示摘要。
- 对话消费投影 / 检索索引 / 变化感知游标。
- 外部平台消息引用。
- 追溯 / 归档对象引用。

这些结构服务稳定消费、历史阅读、追溯和降级显示,但不拥有 `L1-identity`、`L1-work`、`L1-governance`、`L1-artifact`、`L6-bridges`、`L4-observability` 或 `L4-archive` 的正文真相。

### 3.5 它们之间的上下文映射关系是什么？

`Conversation 真相核心` 位于中心。对话空间与范围管理、协作事实追加、授权消费、跨域事实显化和历史追溯围绕它形成核心能力闭环。派生消费辅助上下文只能从核心真相派生。所有本地索引 / 投影 / 引用都只能依附支撑上下文或核心真相,不得直接反向定义 Conversation 真相。

### 3.6 为什么这些部分不能混成一个上下文？

这些部分不能混成一个上下文,因为它们的真相归属、变化速率和失败口径不同。Conversation 真相核心必须稳定、可追溯且不被消费方反写;支撑上下文处理不同语义变化,例如范围变化、事实追加、授权消费和跨域显化;本地影子层只用于引用、快照、投影或检索,可以延迟、失效或重建。若全部混成一个上下文,后续会把外部正文、UI 状态、Runtime 上下文、检索结果或归档材料误写成 Conversation 真相。

## 4. 当前文档问题诊断

| 旧架构内容 | 问题 | 本轮处理 |
|---|---|---|
| `Conversation Store` 被写成核心域 | 偏存储 / 实现视角,没有表达内部语义层次 | 改为 `Conversation 真相核心` |
| `StreamEvents` 被写成支撑子域 | 过早把推送协议 / 事件形态当作上下文 | 改为 `授权消费上下文` 和 `派生消费辅助上下文` 的后续实现候选 |
| `Search` 被写成支撑子域 | 检索是外围增强和派生辅助,不能靠近核心 truth | 放入 `派生消费辅助上下文` 和本地投影层 |
| `Bridge-facing projection` 被写成支撑子域 | 容易让外部平台映射反向定义内部 Conversation | 改为本地投影 / 引用边界,外部协议仍归 `L6-bridges` |
| 上下文映射直接写 `work -> conversation`、`governance -> conversation` 等事件关系 | 这是系统上下文或关键交互,不是内部子域关系 | Step 5 只写本仓内部语义关系,不写外部事件名或接口 |

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 核心子域 | Conversation Store / Turn Stream 等实现色彩较强 | `Conversation 真相核心` | 核心应表达本仓最稳定语义,不是存储结构或对象流 |
| 支撑上下文 | StreamEvents、Search、Bridge projection 等功能 / 技术线索 | 范围管理、事实追加、授权消费、跨域显化、历史追溯、派生辅助 | 按语义职责和变化方向划分 |
| 本地影子层 | 未明确区分 ref、snapshot、projection | 单列成员、项目、治理、产物、外部平台、追溯 / 归档等引用和投影 | 防止外部 truth 或派生结果反写核心 |
| 对外关系 | 写成外部事件进入 Turn 的映射 | 只写内部上下文依附、消费和支撑关系 | 对齐 Step 5 不画外部上下文对象的规则 |
| 后续承接 | 容易直接进入代码模块和 API | 为概要设计的主要组成部分提供语义分层 | 让后续设计先按功能 / 语义拆,再落实现 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 将对话空间、事实历史、跨域显化、追溯分别作为多个核心子域 | 每个能力看起来更独立 | 容易形成多个 truth center,后续一致性和归属边界变复杂 | 不采用 |
| 方案 B: 一个 `Conversation 真相核心` + 多个支撑上下文 + 本地影子层 | 保持 truth center 稳定,又能表达能力差异 | 后续概要设计需要继续展开核心内部对象 | 采用 |
| 方案 C: 按旧 `Store / Stream / Search / Projection` 划分 | 接近旧实现想象 | 把技术机制和派生结构当成上下文 | 不采用 |
| 方案 D: 只保留一个 Conversation 上下文 | 最简单 | 无法表达授权消费、跨域显化、追溯和派生辅助的不同变化方向 | 不采用 |

## 7. 结构化中间产物

### 7.1 子域 / 上下文划分表

| 名称 | 类型 | 作用 | 与其他部分的关系 |
|---|---|---|---|
| Conversation 真相核心 | 核心子域 | 承载对话空间、参与范围、可见范围、事实历史、显化记录和追溯上下文的统一语义。 | 是本仓中心上下文,所有支撑上下文围绕它建立关系。 |
| 对话空间与范围管理上下文 | 支撑子域 | 承载对话空间、参与范围和可见范围的正式变化语义。 | 依附 Conversation 真相核心,为事实追加和授权消费提供边界。 |
| 协作事实追加上下文 | 支撑子域 | 承载人类、AI member 和系统可见事实追加进入对话历史的语义。 | 依附 Conversation 真相核心,不能脱离空间和范围独立存在。 |
| 授权消费上下文 | 支撑子域 | 承载对话事实被查询、订阅、读取和变化感知时的可见边界语义。 | 消费 Conversation 真相核心和范围管理结论,不得绕过可见范围。 |
| 跨域事实显化上下文 | 支撑子域 | 承载来源仓正式事实以引用 / 快照 / 显化记录进入对话视野的语义。 | 依附 Conversation 真相核心,只显化来源引用,不拥有来源正文。 |
| 历史追溯上下文 | 支撑子域 | 承载对话历史、关键变化和跨域显化的复盘与审计语义。 | 消费 Conversation 真相核心,为观测和归档提供交接材料。 |
| 派生消费辅助上下文 | 支撑子域 | 承载索引、投影、检索和变化感知等辅助消费语义。 | 只能从 Conversation 真相派生,不得反写真相。 |
| 成员 / actor 引用与展示快照 | 本地索引 / 投影 / 引用 | 为稳定展示和消费参与者身份提供本地引用或摘要。 | 只保存 ref / snapshot,不拥有成员生命周期或身份正文。 |
| 项目 / 工作上下文引用与摘要 | 本地索引 / 投影 / 引用 | 为项目型对话和项目视野消费提供项目 / 工作上下文引用。 | 只保存 ref / snapshot,不拥有项目或工作正文。 |
| 治理 / 产物引用与显示摘要 | 本地索引 / 投影 / 引用 | 为对话内显化治理和产物事实提供引用和展示摘要。 | 服务跨域事实显化上下文,不拥有治理裁决或产物正文。 |
| 对话消费投影 / 检索索引 / 变化感知游标 | 本地索引 / 投影 / 引用 | 为授权消费、长历史定位和变化感知提供派生视图。 | 服务授权消费和派生消费辅助上下文,可重建且不得反写真相。 |
| 外部平台消息引用 | 本地索引 / 投影 / 引用 | 为外部平台映射场景保留必要引用关系。 | 只服务 Bridges 协作边界,不拥有外部平台消息生命周期。 |
| 追溯 / 归档对象引用 | 本地索引 / 投影 / 引用 | 为观测、审计、导出和长期归档交接保留引用入口。 | 服务历史追溯上下文,不拥有全局观测日志或归档正文。 |

```text
                              |

+-----------------------------+------------------------------+
                              |
                              v
+-----------------------------+------------------------------+
| 授权消费上下文               | 跨域事实显化上下文             |
+-----------------------------+------------------------------+
                              |
                              v
+-----------------------------+------------------------------+
| 历史追溯上下文               | 派生消费辅助上下文             |
+-----------------------------+------------------------------+
                              |
                              v
+-----------------------------+------------------------------+
| 本地索引 / 投影 / 引用层                                    |
| member refs / project refs / cross-domain refs / indexes   |
| external message refs / trace refs / archive refs          |
+------------------------------------------------------------+
```

该图只表达本仓内部语义上下文关系,不表达外部上下文对象、角色、接口名、事件名、数据库表、实现组件或运行顺序。

图示说明:

- `Conversation 真相核心` 是唯一核心子域,支撑上下文不能各自形成第二 truth。
- 空间 / 范围、事实追加、授权消费、跨域显化和追溯共同支撑核心能力闭环。
- 派生消费辅助上下文靠近本地投影层,但不得让 projection / index / cursor 反写业务事实。
- 本地索引 / 投影 / 引用层只提供稳定消费、降级显示和追溯入口,不拥有外部正文真相。

### 7.3 本地索引 / 投影 / 引用边界结论

| 本地影子结构 | 允许做什么 | 禁止做什么 |
|---|---|---|
| 成员 / actor 引用与展示快照 | 保存参与者引用和展示摘要 | 不保存成员生命周期、角色定义或认证凭据正文 |
| 项目 / 工作上下文引用与摘要 | 保存项目型对话所需上下文引用 | 不保存项目、工作项或工作状态正文 |
| 治理 / 产物引用与显示摘要 | 保存对话显化所需的治理 / 产物引用和摘要 | 不保存 Gate / Policy / Approval 裁决正文或 Artifact 正文 |
| 对话消费投影 / 检索索引 / 变化感知游标 | 支撑授权消费、定位、重建和变化感知 | 不生成新业务事实,不覆盖对话真相 |
| 外部平台消息引用 | 关联外部平台映射来源或投递目标 | 不拥有外部平台协议生命周期或消息正文真相 |
| 追溯 / 归档对象引用 | 关联 trace、audit、export、archive 入口 | 不拥有全局观测日志正文或长期归档包正文 |

### 7.4 统一语言词汇结论

| 术语 | 含义 |
|---|---|
| Conversation 真相核心 | 本仓唯一核心子域,承载对话域内部最稳定的真相语义。 |
| 对话空间与范围 | 对话事实归属、参与范围和可见范围的语义边界。 |
| 协作事实 | 人类、AI member 或系统可见事实以正式方式追加到对话历史后的记录语义。 |
| 跨域显化 | 来源仓正式事实以引用、快照或可见记录方式进入对话视野,但来源真相不转移。 |
| 授权消费 | 查询、订阅、变化感知和下游读取都必须受参与范围和可见范围约束。 |
| 派生消费辅助 | 从 Conversation 真相派生的投影、索引、检索和变化感知结构。 |
| 本地索引 / 投影 / 引用 | 为稳定消费、降级显示和追溯保留的本地影子结构,不拥有外部正文。 |

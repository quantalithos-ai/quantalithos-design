## 3. SOP 问题回答

### 3.1 这个仓运行时有哪些正式容器或运行单元？

`L1-conversation` 的正式运行承载单元包括:

- `Conversation 同步入口单元`
- `Conversation 异步输入消费单元`
- `Conversation 后台派生维护单元`
- `Conversation 真相存储承载`
- `Conversation 派生视图 / 索引承载`
- `事件协作与追溯交接边界`
- `下游消费 / 协作入口边界`

这些是运行承载角色,不是源码模块、进程名或 crate 名。后续概要 / 详细设计可以再把它们映射到实际应用进程、worker、crate 或 adapter。

### 3.2 同步入口在哪里？

同步入口位于 `Conversation 同步入口单元`。它承接来自 SDK、Chat、Workspace、Runtime、Bridges、审计 / 运维入口等正式消费方或协作方的同步读写、追溯读取和受控维护触发,但本步不定义 API、路由、RPC、command 或 query 名称。

### 3.3 异步消费者或后台任务在哪里？

异步输入由 `Conversation 异步输入消费单元` 承接,用于消费来自事件协作边界的正式输入或相邻真相域已形成的可显化事实。后台派生、投影维护、检索辅助、变化感知、重建和交接材料形成由 `Conversation 后台派生维护单元` 承接。二者都不得直接绕过 Conversation 真相核心写派生结果为业务事实。

### 3.4 数据库 / 缓存 / 总线如何接入？

本步不选择具体数据库、缓存、消息后端或协议。架构层只确认:

- `Conversation 真相存储承载` 是本仓正式状态的必要承载。
- `Conversation 派生视图 / 索引承载` 可承载从真相派生的消费辅助结果。
- `事件协作与追溯交接边界` 是本仓与 `L0-bus`、Observability、Archive 等运行时对接的正式外部边界。
- 缓存不是本步确认的核心运行承载;若后续引入,只能作为派生辅助或性能优化,不得成为真相来源。

### 3.5 哪些运行单元必须分开部署,哪些可以同部署？

架构上必须区分同步入口、异步输入消费、后台派生维护、真相存储和派生承载边界。P0 可以把同步入口、异步输入消费和后台派生维护同部署在一个服务进程或同一运行环境中,但它们的职责边界必须清楚。随着吞吐、隔离、恢复、观测或归档压力增加,异步输入消费和后台派生维护可以拆分为独立 worker;真相存储承载和派生视图 / 索引承载即使物理同库,架构语义也必须分开。

### 3.6 哪些通信关系是正式主路径？

正式主路径包括:

- 下游消费 / 协作入口边界进入 Conversation 同步入口单元。
- 事件协作与追溯交接边界进入 Conversation 异步输入消费单元。
- 同步入口和异步输入消费共同推进 Conversation 真相存储承载。
- 后台派生维护单元从 Conversation 真相派生消费辅助结果,并承载到派生视图 / 索引承载。
- 后台派生维护单元通过正式交接边界输出变化感知、追溯材料或归档材料。

本步只表达运行关系,不表达具体协议、事件主题、接口名称或时序细节。

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 图的主语 | UI / API / application / domain / DB | `L1-conversation` 正式运行承载 | 容器图应表达运行承接角色,不是代码分层 |
| 同步入口 | `conversation-api` + HTTP / gRPC | `Conversation 同步入口单元` | 不提前锁定协议和 API 形态 |
| 异步输入 | subscriptions 直接绑定外部仓 | `Conversation 异步输入消费单元` | 保留运行角色,外部仓已在系统上下文表达 |
| 后台处理 | StreamEvents / search 直接作为容器 | `Conversation 后台派生维护单元` | 派生、投影、检索和变化感知统一按后台承载表达 |
| 存储承载 | PostgreSQL / search 后端 | 真相存储承载 + 派生视图 / 索引承载 | 分清真相与派生结果,技术产品后移 |
| 部署口径 | 单服务 + PG 起步 + push 内嵌 | P0 可同部署但逻辑边界必须分开 | 兼顾起步实现与后续拆分 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 按 API / application / domain / infra 代码层画容器 | 开发者熟悉 | 这是实现分层,不是运行承载图 | 不采用 |
| 方案 B: 按同步入口、异步消费、后台派生、真相存储、派生承载和外部交接边界画图 | 符合运行承载粒度,能保护真相与派生边界 | 后续需要在概要 / 详细设计再映射到代码结构 | 采用 |
| 方案 C: 强制同步入口、异步消费、后台维护全部独立部署 | 隔离清晰 | P0 复杂度过高,也不是架构必须条件 | 不采用 |
| 方案 D: 继续把推送、检索和桥接投影画成独立容器 | 对旧文档迁移最小 | 会让外围增强能力靠近核心运行主链 | 不采用 |

## 7. 结构化中间产物

### 7.1 容器 / 部署架构图

```text
+--------------------------+             +--------------------------+
| 下游消费 / 协作入口边界  |             | 事件协作 / 追溯交接边界  |
| sdk / chat / workspace  |             | bus / trace / archive    |
+------------+-------------+             +------------+-------------+
             | 入口                                   | 消费
             v                                        v

      +==============================================================+
      |              L1-conversation 正式运行承载                    |
      |                                                              |
      |   +-------------------------+     +-------------------------+ |
      |   | Conversation 同步入口   |     | Conversation 异步输入   | |
      |   | sync entry              |     | async intake            | |
      |   +------------+------------+     +------------+------------+ |
      |                | 处理                         | 处理          |
      |                v                              v               |
      |   +------------+------------------------------+------------+  |
      |   |              Conversation 真相存储承载                  |  |
      |   |              truth state carrier                       |  |
      |   +------------+------------------------------+------------+  |
      |                | 处理 / 承载                                |
      |                v                                            |
      |   +------------+------------+     +-------------------------+ |
      |   | Conversation 后台派生   |---->| 派生视图 / 索引承载     | |
      |   | maintenance             |     | derived carrier         | |
      |   +------------+------------+     +-------------------------+ |
      |                | 依赖 / 输出                                |
      +================+=============================================+
                       |
                       v
             +---------+----------------+
             | 事件协作 / 追溯交接边界 |
             | change / trace handoff  |
             +--------------------------+
```

该图表达 `L1-conversation` 的正式运行承载结构,不表达源码目录、接口协议、事件名、数据库表、技术产品或部署参数。

图示说明:

- `Conversation 同步入口` 和 `Conversation 异步输入` 是运行入口差异,不是两套 Conversation 真相。
- `Conversation 真相存储承载` 是唯一正式真相承载,派生视图 / 索引承载不得反写真相。
- `Conversation 后台派生维护` 只从真相派生辅助结果或交接材料,不能生成新的业务事实。
- 外部边界只作为运行时入口、消费或交接边界出现,不重画系统上下文。

### 7.2 运行单元说明表

| 对象 | 类型 | 主要职责 | 运行关系 | 说明 |
|---|---|---|---|---|
| 下游消费 / 协作入口边界 | 运行时对接的正式外部边界 | 承接 SDK、Chat、Workspace、Runtime、Bridges 等对 Conversation 的正式消费或协作进入点。 | 通过入口关系进入同步入口单元。 | 它只作为外部运行边界出现,不属于本仓内部运行承载。 |
| 事件协作 / 追溯交接边界 | 运行时对接的正式外部边界 | 承接跨仓事件协作、变化感知交接、追溯材料交接和归档交接。 | 被异步输入消费单元消费,也接收后台派生维护输出。 | 它表达运行对接边界,不代表本仓拥有 bus、observability 或 archive 真相。 |
| Conversation 同步入口 | 同步入口单元 | 承接同步读写、追溯读取和受控维护触发。 | 处理后推进 Conversation 真相存储承载。 | 不在本章定义 API、RPC、command、query 或鉴权细节。 |
| Conversation 异步输入 | 异步消费单元 | 承接来自事件协作边界的正式异步输入或相邻真相域已形成事实的显化触发。 | 消费外部异步边界并推进 Conversation 真相存储承载。 | 不直接接管来源仓正文,不绕过 Conversation 真相核心。 |
| Conversation 后台派生维护 | 后台处理单元 | 承接派生视图、索引、检索辅助、变化感知、重建和追溯 / 归档交接材料形成。 | 从真相存储承载派生结果,写入派生承载或输出交接材料。 | 不生成新业务事实,不得覆盖真相。 |
| Conversation 真相存储承载 | 正式存储承载 | 承载对话空间、参与范围、可见范围、事实历史、显化记录和追溯上下文。 | 被同步入口、异步输入和后台维护共同依赖。 | 这是本仓唯一正式真相承载,不写具体数据库或表结构。 |
| 派生视图 / 索引承载 | 正式存储承载 | 承载查询、检索、变化感知和下游消费所需的派生辅助结果。 | 由后台派生维护单元生成和维护。 | 可重建、可延迟,不得成为第二 truth。 |

### 7.3 部署关系结论

- P0 可以把 `Conversation 同步入口`、`Conversation 异步输入` 和 `Conversation 后台派生维护` 同部署,但逻辑运行职责必须分清。
- `Conversation 真相存储承载` 与 `派生视图 / 索引承载` 即使物理同库,架构语义也必须区分。
- 当吞吐、隔离、恢复、观测或归档压力上升时,异步输入消费和后台派生维护可以拆分为独立 worker。
- `事件协作 / 追溯交接边界` 是外部运行边界,不意味着本仓拥有 `L0-bus`、`L4-observability` 或 `L4-archive` 的主体架构。
- 缓存、具体搜索后端、具体推送协议和具体数据库产品不进入本步主图。

### 7.4 通信方式结论

| 运行关系 | 当前架构口径 |
|---|---|
| 外部消费 / 协作边界到同步入口 | 只确认存在正式入口关系,不在本步选择 HTTP、gRPC、SDK facade 或其他协议。 |
| 事件协作边界到异步输入 | 只确认存在正式消费关系,不在本步选择 topic、consumer group、event schema 或 relay 机制。 |
| 同步入口 / 异步输入到真相存储承载 | 只确认运行处理会推进 Conversation 真相,不写事务、表结构或 repository。 |
| 真相存储承载到后台派生维护 | 只确认派生维护必须从真相来源出发,不写调度、批处理、增量策略或索引实现。 |
| 后台派生维护到派生承载 / 外部交接边界 | 只确认派生结果和交接材料可以输出,不得反写 Conversation 真相。 |

## 3. SOP 问题回答

### 3.1 哪些数据由本仓拥有真相？

`L1-conversation` 拥有的正式真相数据限于对话域内部:对话空间、参与范围、可见范围、对话事实历史、对话内跨域显化记录和对话追溯上下文。它们共同回答“某个对话事实属于哪个空间、哪些参与者可见、以什么方式进入历史、与哪些外部来源发生显化关系、如何被追溯”。

### 3.2 哪些数据只是快照、投影或引用？

成员 / actor 展示摘要、项目 / 工作上下文摘要、治理 / 产物显示摘要、对话消费投影、检索索引、变化感知游标等只是快照 / 投影数据。成员、项目、工作项、治理结论、产物、外部平台消息、全局 trace / audit material、归档对象等只是引用关系数据。快照 / 投影和引用可以被本仓维护,但不能成为外部对象正文或生命周期的正式真相。

### 3.3 哪些关系必须强一致？

Conversation 真相内部关系必须强一致:对话空间与参与范围、可见范围、事实追加、显化记录和追溯上下文不能互相漂移。一个对话事实如果被正式追加,就必须同时满足所属空间、参与范围、可见范围和追溯锚点的核心约束;否则不能被写成已成立的 Conversation 真相。

### 3.4 哪些关系可以最终一致？

Conversation 真相到快照、投影、检索索引、变化感知游标、下游消费材料、观测材料和归档材料可以最终一致。外部来源仓变化到本地展示快照也可以最终一致,因为本地快照只是稳定消费辅助,上游正式真相不因本地刷新延迟而转移归属。

### 3.5 失败时靠什么口径约束、补偿或挂起？

强一致关系不成立时必须显式失败或保持未成立状态,不能落为部分真相。最终一致关系暂时不成立时,允许保留旧投影、过期快照、未解析引用或挂起交接,但必须保留可识别状态,不得伪造外部正文补齐。引用失效时只能表达引用不可解析、已过期或待刷新,不能把外部对象复制成 Conversation 真相。

### 3.6 哪些数据边界如果不写清,后续最容易串仓？

最容易串仓的边界是:成员快照 vs identity 成员真相、项目摘要 vs work 项目真相、治理 / 产物显化记录 vs governance / artifact 正文、Runtime 结果性事实 vs 推理过程、Bridges 映射结果 vs 外部平台生命周期、派生投影 vs Conversation 真相、追溯上下文 vs 全局观测日志和长期归档正文。

## 4. 当前文档问题诊断

| 旧架构内容 | 问题 | 本轮处理 |
|---|---|---|
| 按 Conversation / Turn / Participant / refs / archive 写数据结构 | 偏对象和字段视角,没有先判定归属 | 改为正式真相、快照 / 投影、引用关系、明确不拥有四类 |
| 把跨域事件、外部对象和对话事实混在同一数据流里 | 容易把来源仓正文写成 Conversation truth | 显化记录归本仓,来源正文和生命周期仍归来源仓 |
| Search、StreamEvents、projection 靠近真相数据 | 派生消费辅助可能被误认为第二 truth | 统一归为快照 / 投影数据,可重建且不得反写 |
| archive / audit / trace 写成存储策略 | 容易接管 observability / archive 主体职责 | 本仓只拥有对话域追溯上下文,全局日志和归档正文不归本仓 |
| 一致性口径缺失 | 后续实现可能把所有关系都做强一致或都做最终一致 | 按数据归属推导强一致、最终一致、引用有效性和边界约束 |

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 数据主语 | Conversation / Turn / Participant 等对象线索 | 对话空间、范围、事实历史、显化记录、追溯上下文等归属类别 | 架构层先判断归属,不提前进入对象模型 |
| 外部来源 | 外部事实可直接进入对话数据结构 | 外部事实只能以引用、快照或显化记录进入 | 防止来源真相转移 |
| 派生数据 | 搜索、投影、变化感知容易被当成核心数据 | 派生数据是快照 / 投影,不得反写 | 防止第二 truth |
| 一致性 | 未区分核心真相内部一致与派生延迟 | 核心真相强一致,派生和交接最终一致 | 保护核心闭环,允许外围延迟 |
| 失败口径 | 容易靠补数据修复 | 明确失败、挂起、旧视图、未解析引用,不得伪造正文 | 防止用补偿越权 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 按旧对象和字段列数据 | 直观接近实现 | 会提前进入详细设计,且无法明确不拥有边界 | 不采用 |
| 方案 B: 先按归属四类划边界,再推导一致性 | 能保护真相边界,可承接后续设计 | 后续概要 / 详细设计还需继续展开对象 | 采用 |
| 方案 C: 所有数据都要求强一致 | 语义最硬 | 会让快照、投影、下游交接和外部来源刷新变得不可实现 | 不采用 |
| 方案 D: 所有数据都最终一致 | 实现弹性大 | 会破坏对话空间、范围和事实历史的核心一致性 | 不采用 |

## 7. 结构化中间产物

### 7.1 数据归属表

| 数据项 | 数据类型 | 归属说明 | 边界说明 |
|---|---|---|---|
| 对话空间 | 正式真相数据 | 由 `L1-conversation` 拥有正式真相,定义对话事实归属边界。 | 不等同于 Chat 会话窗口或 Workspace 入口。 |
| 对话参与范围 | 正式真相数据 | 由本仓拥有对话域内正式参与范围。 | 成员有效性来源仍归 `L1-identity`,本仓只拥有对话内参与关系。 |
| 对话可见范围 | 正式真相数据 | 由本仓拥有对话域内事实可见边界。 | 不等同于全局授权裁决或 UI 展示状态。 |
| 对话事实历史 | 正式真相数据 | 由本仓拥有正式追加后的对话事实历史。 | 不保存 Runtime 推理过程、外部平台正文或相邻仓正文。 |
| 对话内跨域显化记录 | 正式真相数据 | 由本仓拥有“外部事实在本对话中被显化”的记录。 | 来源事实正文、裁决、产物版本或项目状态仍归来源仓。 |
| 对话追溯上下文 | 正式真相数据 | 由本仓拥有对话域内追溯、复盘和责任边界上下文。 | 不等同于全局 trace store、metrics、长期归档包正文。 |
| 成员 / actor 展示摘要 | 快照 / 投影数据 | 本仓可为历史阅读和降级显示保留快照。 | 成员生命周期、角色定义和认证真相仍归身份 / 方法等来源。 |
| 项目 / 工作上下文摘要 | 快照 / 投影数据 | 本仓可保留项目型对话所需展示摘要。 | 项目、工作项和项目成员真相仍归 `L1-work`。 |
| 治理 / 产物显示摘要 | 快照 / 投影数据 | 本仓可保留对话显化所需摘要。 | Gate / Policy / Approval 裁决和 Artifact 正文 / 版本不归本仓。 |
| 对话消费投影 / 检索索引 / 变化感知游标 | 快照 / 投影数据 | 本仓可维护从 Conversation 真相派生的消费辅助数据。 | 可延迟、可重建,不得反写对话事实。 |
| 成员 / actor 引用 | 引用关系数据 | 本仓只保存参与者或 actor 的引用关系。 | 引用存在不代表本仓拥有成员正文。 |
| 项目 / 工作项引用 | 引用关系数据 | 本仓只保存项目型对话所需外部对象引用。 | 引用存在不代表本仓拥有项目或工作项正文。 |
| 治理结论 / 产物引用 | 引用关系数据 | 本仓只保存显化和追溯所需引用。 | 引用存在不代表治理决策或产物正文进入本仓。 |
| 外部平台消息引用 | 引用关系数据 | 本仓只保存 Bridges 映射所需引用关系。 | 外部平台账号、频道、消息生命周期不归本仓。 |
| trace / audit material / archive 对象引用 | 引用关系数据 | 本仓只保存追溯、观测或归档交接所需引用。 | 全局观测日志和长期归档正文不归本仓。 |
| Chat UI 展示状态、Workspace 聚合视图、Runtime memory / 推理过程、外部平台协议生命周期、治理裁决正文、Artifact 正文 / 版本 / 证据链、成员画像 / 生命周期、认证凭据、全局观测日志、长期归档包正文 | 明确不拥有的正文 / 真相 | 这些正文或主真相由相邻仓、外部平台或横切系统拥有,本仓不得吸收为正式真相。 | 如需要在对话中出现,只能通过引用、快照或显化记录表达。 |

### 7.2 一致性策略表

| 数据关系 / 场景 | 关联数据类型 | 一致性口径 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| 对话空间、参与范围、可见范围与事实追加之间的关系 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 明确失败或保持未成立状态,不得落为部分完成事实 | 核心事实不能脱离空间、参与和可见边界成立。 |
| 跨域显化记录与本对话事实历史之间的关系 | 正式真相数据 ↔ 正式真相数据 / 引用关系数据 | 强一致 + 引用有效性一致 | 显化引用不可接受时挂起或标记不可解析,不得伪造来源正文 | 显化记录属于本仓,来源正文不属于本仓。 |
| 对话追溯上下文与事实历史之间的关系 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 不形成缺失追溯锚点的正式关键事实 | 追溯上下文是复盘和审计的对话域基础。 |
| Conversation 真相到消费投影 / 检索索引 / 变化感知游标 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 | 保留旧视图、过期标记或挂起重建,不得反写真相 | 派生辅助可以延迟和重建。 |
| 外部来源真相到本地展示快照 | 明确不拥有的正文 / 真相 ↔ 快照 / 投影数据 | 最终一致 | 保留旧快照或未解析状态,不得补造外部正文 | 快照服务稳定阅读,不改变来源归属。 |
| Conversation 真相到下游消费 / 观测 / 归档材料 | 正式真相数据 ↔ 引用关系数据 / 快照 / 投影数据 | 最终一致 | 交接可挂起或延迟,已形成的 Conversation 真相不得丢失 | 下游消费失败不能反向改变业务事实。 |
| 外部对象引用有效性变化 | 引用关系数据 ↔ 明确不拥有的正文 / 真相 | 引用有效性一致 | 表达引用失效、待刷新或不可解析,不得复制正文补齐 | 引用关系成立不等于正文归属转移。 |
| 明确不拥有正文被请求写入 Conversation | 明确不拥有的正文 / 真相 ↔ 正式真相数据 | 边界约束一致 | 拒绝、挂起或转换为引用 / 快照 / 显化记录,不得作为本仓真相保存 | 这是防止串仓的最高优先级边界。 |

### 7.3 简化关系示意图

```text
+--------------------------------------------------------------+
|                    L1-conversation 数据边界                  |
|                                                              |
|   +--------------------------+                               |
|   | 正式真相数据             |                               |
|   | space / scope / facts    |                               |
|   | manifestation / trace    |                               |
|   +------------+-------------+                               |
|                | 派生 / 引用                                 |
|                v                                             |
|   +------------+-------------+      +----------------------+  |
|   | 快照 / 投影数据          |      | 引用关系数据         |  |
|   | views / indexes / snaps  |      | external object refs |  |
|   +------------+-------------+      +----------+-----------+  |
|                | 不反写                         | 只引用       |
+================+===============================+==============+
                 |                               |
                 v                               v
      明确不拥有的外部正文 / 外部主真相
      identity / work / governance / artifact / runtime / ui
      bridges / observability / archive
```

图示说明:

- `正式真相数据` 是本仓唯一可以主张拥有的业务真相。
- `快照 / 投影数据` 和 `引用关系数据` 可以本地存在,但不能反写真相或吸收外部正文。
- `明确不拥有的外部正文 / 外部主真相` 只能通过引用、快照或显化记录进入对话视野。
- 该图不表达存储设计、同步流程、事件流或对象模型。

### 7.4 数据边界说明

`L1-conversation` 的数据所有权边界是“拥有对话真相,本地保留消费辅助,引用外部真相,明确排除外部正文”。对话内显化记录属于 Conversation,但被显化的治理、产物、项目、成员或外部平台正文不属于 Conversation。快照、投影和索引可以提升消费体验,但它们的延迟、失效或重建不能改变正式对话事实。后续设计若需要写字段、表、事件、补偿或索引,必须从本章归属和一致性口径继续下沉,不能反向修改本章边界。

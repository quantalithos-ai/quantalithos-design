## 3. SOP 问题回答

### 3.1 哪些交互适合同步能力边界？

需要即时判断 Conversation 正式状态是否成立的交互适合同步请求 / 响应类交互。包括对话空间与范围变更、协作事实追加、授权读取、追溯读取、显式跨域显化请求和受控维护触发。这些场景的共同点是调用方必须获得明确结果:已成立、被拒绝、不可见、引用不可接受或暂不可处理,不能先伪装为成功再由后台补齐。

### 3.2 哪些交互适合异步事件？

已经成立的 Conversation 事实向下游传播、相邻真相域已经形成的事实进入对话显化边界、外部映射结果送达、对话追溯或归档材料交接,适合异步事件 / 回调类交互。这些场景的重点是事实传播或结果送达,不要求在原始请求边界内完成所有下游消费。

### 3.3 哪些交互适合后台任务或补偿路径？

派生消费投影、检索索引、变化感知游标、外部展示快照刷新、引用可解析性刷新、长历史辅助结果重建、追溯 / 归档交接材料形成等适合后台任务 / 延后承接类交互。这些交互可以延迟、挂起或重建,但不得反写 Conversation 真相。

### 3.4 哪些交互必须经过总线或正式边界,不能直接穿透？

跨仓事实传播、相邻真相域变化输入、观测 / 归档交接和下游变化感知必须经过正式事件协作或正式边界,不能让来源仓、下游消费方或横切系统直接写 Conversation 核心。Chat、Workspace、Runtime、Bridges 等消费或协作方也只能通过正式入口读写授权事实,不能直接依赖本仓内部真相承载或派生承载。

### 3.5 关键依赖失效时,本仓如何降级或挂起？

同步边界失效时必须返回明确失败、不可见、不可接受或暂不可处理,不得把未成立状态伪装成已完成。异步传播失败时保留未送达、未消费或待交接状态,已成立的 Conversation 真相不得回滚为不存在。后台承接失败时保留旧视图、过期标记、未解析引用或挂起重建状态,不得伪造外部正文或覆盖核心事实。

### 3.6 哪些通信口径若不先写清,后续最容易误入协议细节？

最容易误入协议细节的口径包括:把授权读取写成推送协议、把事实传播写成同步 fan-out、把后台投影重建写成同步请求成功、把外部平台输入写成 Conversation 直接理解外部协议、把总线协作写成事件目录、把失败处理写成重试脚本。本章只定通信类别和边界原因,具体协议、事件命名和重试机制后移。

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 通信主语 | 接口、事件、协议和推送形态 | 正式交互场景与通信方式类别 | 架构层先判断边界语义 |
| 同步边界 | 可能被后台任务伪装成成功 | 必须即时判定成立、失败或不可处理 | 防止伪同步完成 |
| 异步边界 | 容易写成事件目录 | 表达已成立事实传播或外部结果送达 | 防止事件名替代架构判断 |
| 后台承接 | 与核心事实追加混在一起 | 只处理派生、刷新、重建和交接材料形成 | 防止派生辅助阻塞核心真相 |
| 失败口径 | 技术重试细节 | 明确失败、挂起、旧视图、未解析和不得伪造正文 | 对齐 Step 8 一致性策略 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 把所有交互都设计成同步请求 / 响应 | 调用方心智简单 | 会强迫下游传播、投影、归档和外部来源刷新进入核心同步链路 | 不采用 |
| 方案 B: 把所有交互都设计成异步事件 | 解耦程度高 | 对话空间、范围、事实追加和授权读取缺少即时成立 / 失败口径 | 不采用 |
| 方案 C: 同步收口核心成立判断,异步传播已成立事实,后台承接派生和刷新 | 符合数据归属和一致性策略 | 后续设计需要清楚标注状态和边界 | 采用 |
| 方案 D: 先锁定具体协议和中间件,再反推交互方式 | 实施看似直接 | 会让技术选型反向决定架构语义 | 不采用 |

## 7. 结构化中间产物

### 7.1 关键交互场景表

| 交互场景 | 交互边界 | 交互目的 | 边界说明 |
|---|---|---|---|
| 对话空间与范围变更 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 判断对话空间、参与范围或可见范围变化是否正式成立。 | 该场景会改变 Conversation 真相,必须即时收口。 |
| 协作事实追加 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 判断人类、AI member 或系统可见事实能否追加为正式对话事实。 | 事实追加必须受空间、参与范围、可见范围和追溯约束。 |
| 授权读取与追溯读取 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 在授权视野内读取对话事实、历史和追溯上下文。 | 读取需要即时判断可见边界,但不得改变业务事实。 |
| 显式跨域显化请求 | 下游消费 / 协作入口边界 ↔ Conversation 同步入口 | 判断外部引用是否可在当前对话中被显化。 | 显化记录属于本仓真相,来源正文不归本仓。 |
| 相邻真相域事实送达 | 事件协作 / 追溯交接边界 ↔ Conversation 异步输入 | 承接已经由来源仓正式形成、可进入对话视野的事实或引用变化。 | 该场景是外部正式结果送达,不是内部函数流程。 |
| Conversation 事实变化传播 | Conversation 真相边界 ↔ 事件协作 / 下游消费边界 | 将已经成立的对话事实变化传播给下游或协作方。 | 传播失败不能反向取消已经成立的 Conversation 真相。 |
| 派生消费辅助维护 | Conversation 真相边界 ↔ 派生视图 / 索引承载 | 维护投影、检索索引、变化感知游标和消费辅助结果。 | 派生结果服务消费,不得成为第二 truth。 |
| 外部展示快照与引用状态刷新 | 外部能力接缝 ↔ 后台派生维护边界 | 刷新成员、项目、治理、产物等展示快照或引用可解析状态。 | 快照和引用状态可以延迟,不改变来源真相归属。 |
| 追溯 / 观测 / 归档材料交接 | Conversation 真相边界 ↔ 事件协作 / 追溯交接边界 | 将追溯、观测或归档所需材料交给横切系统或归档系统。 | 本仓保留对话域追溯上下文,不拥有全局日志或归档正文。 |
| 受控维护与重建 | 运维 / 审计入口边界 ↔ 后台派生维护边界 | 触发派生结果重建、引用刷新或一致性检查。 | 维护只能修复辅助结构或暴露异常,不得隐式覆盖业务事实。 |

### 7.2 通信方式判断表

| 交互场景 | 推荐通信方式 | 不宜采用的方式 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| 对话空间与范围变更 | 同步请求 / 响应类交互 | 不宜以异步事件或后台承接作为主路径 | 明确失败、拒绝或暂不可处理,不得先返回已成立 | 该场景直接改变核心真相边界。 |
| 协作事实追加 | 同步请求 / 响应类交互 | 不宜伪装成后台成功后再补写事实 | 明确失败或保持未追加状态,不得落为部分事实 | 事实追加必须即时满足核心一致性。 |
| 授权读取与追溯读取 | 同步请求 / 响应类交互 | 不宜以异步推送替代正式读取判断 | 返回可见结果、不可见、不可解析或暂不可读取 | 读取边界要即时执行可见范围判断。 |
| 显式跨域显化请求 | 同步请求 / 响应类交互 | 不宜由后台随意创建显化记录 | 引用不可接受时拒绝或挂起,不得伪造来源正文 | 显化记录一旦成立就是本仓正式真相。 |
| 相邻真相域事实送达 | 异步事件 / 回调类交互 | 不宜要求来源仓同步穿透本仓核心 | 保持未送达、待显化或不可解析状态 | 来源事实已在来源仓成立,进入 Conversation 应通过正式边界送达。 |
| Conversation 事实变化传播 | 异步事件 / 回调类交互 | 不宜写成同步 fan-out 主路径 | 保持未消费、待交接或延后传播状态 | 事实已成立,传播失败不应回滚核心真相。 |
| 派生消费辅助维护 | 后台任务 / 延后承接类交互 | 不宜阻塞核心同步变更 | 保留旧视图、过期标记或挂起重建 | 派生结果最终一致,可延迟和重建。 |
| 外部展示快照与引用状态刷新 | 后台任务 / 延后承接类交互 | 不宜把快照刷新写成核心事实成立前置 | 保留旧快照、未解析引用或待刷新状态 | 快照和引用状态服务稳定消费,不拥有外部正文。 |
| 追溯 / 观测 / 归档材料交接 | 异步事件 / 回调类交互 | 不宜要求横切系统同步决定业务事实 | 保持待交接、未消费或延后归档状态 | 横切消费失败不能反向改变 Conversation 真相。 |
| 受控维护与重建 | 后台任务 / 延后承接类交互 | 不宜伪装成同步业务变更成功 | 挂起、失败或输出异常状态,不得覆盖业务事实 | 维护任务只修复派生或暴露问题,不是业务事实来源。 |

### 7.3 简化交互示意图

```text
+-----------------------------+        +-----------------------------+
| 下游消费 / 协作入口边界     |        | 事件协作 / 来源事实边界     |
| sdk / chat / workspace      |        | bus / source truth domains  |
| runtime / bridges           |        +-------------+---------------+
+-------------+---------------+                      |
              | [sync request / response]            | [async event / callback]
              v                                      v
+-------------+---------------+        +-------------+---------------+
| Conversation 同步入口       |        | Conversation 异步输入       |
+-------------+---------------+        +-------------+---------------+
              |                                      |
              +------------------+-------------------+
                                 |
                                 v
                      +----------+-----------+
                      | Conversation 真相边界 |
                      +----+-------------+---+
                           |             |
             [async event] |             | [background]
                           v             v
             +-------------+------+   +--+----------------+
             | 下游 / 追溯 / 归档 |   | 派生消费辅助承接 |
             | 交接边界           |   |                  |
             +--------------------+   +-------------------+
```

图示说明:

- 同步请求 / 响应用于即时判断核心状态是否成立,不是表达具体协议。
- 异步事件 / 回调用于已成立事实传播或外部结果送达,不是事件目录。
- 后台任务 / 延后承接用于派生、刷新、重建和交接材料形成,不得反写真相。
- 该图不表达接口路径、事件名、处理顺序或运行部署拓扑。

### 7.4 边界说明

`L1-conversation` 的通信方式按边界语义选择:核心真相是否成立需要同步收口,已成立事实或外部结果送达适合异步传播,派生和刷新适合后台延后承接。同步返回成功只能表示该同步边界内的正式判断已经成立,不能代替后续投影、下游消费或归档交接完成。异步和后台失败只能表现为未送达、待交接、旧视图、未解析或挂起,不能回滚已经成立的 Conversation 真相。具体协议、事件命名、重试策略和运行单元分配留到后续设计。

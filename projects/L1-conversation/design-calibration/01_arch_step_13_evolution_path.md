## 3. SOP 问题回答

### 3.1 当前阶段做到哪里才算足够？

当前阶段只要能稳定成立 `L1-conversation` 的独立对话真相仓主线,就算架构成立。具体边界是:对话空间、参与范围、可见范围、对话事实历史、跨域显化记录和对话追溯上下文由本仓拥有;外部输入必须经正式承接层进入;下游消费必须经授权视野和派生只读边界;跨仓传播、派生、索引、快照刷新和追溯交接可以最终一致或后台延后承接,但不得反写真相。

当前阶段不要求完整事件溯源、强实时推送协议、搜索后端、长期归档策略、具体容量数字或完整外部平台特化全部落入架构主线。

### 3.2 第一批必须守住哪些结构？

第一批必须守住以下结构:

- 独立 Conversation 真相核心。
- 正式承接层。
- truth / snapshot / reference / derived read model 数据边界。
- 授权视野消费边界。
- 追加式事实历史和显式更正 / 撤回 / 补充口径。
- 事件最终一致传播边界。
- 后台派生、刷新、重建和交接承接边界。
- 审计 / trace / evidence / archive handoff 接缝。

这些结构不一定在当前阶段全部细化到字段、接口或协议,但架构方向必须固定,后续概要设计和详细设计不能反向推翻。

### 3.3 哪些能力或约束留到后续阶段演进？

后续才进入演进主线的能力包括:

- 完整事件溯源 / CQRS 是否成为主体实现范式。
- 更强的搜索、长历史定位和变化感知能力。
- 更细粒度的实时推送协议、AG-UI / SSE / WebSocket 等下游交互形态。
- 更严格的引用解析、新鲜度、快照生命周期和引用失效恢复策略。
- 与 `L4-observability`、`L4-archive` 的长期追溯 / 归档交接协议。
- 明确负载模型后的容量分层、分区、冷热路径和读写隔离策略。
- 更多来源仓和外部平台接入后的显化映射扩展。

这些能力都必须以“不改变 Conversation 真相归属、不绕过授权视野、不复制来源正文、不让派生反写”为前提进入。

### 3.4 哪些设计债务当前可接受,哪些不可接受？

当前可接受债务:

- 暂不量化吞吐、延迟、连接数和月度事实容量,因为新版需求尚未形成正式负载模型。
- 暂不锁定实时推送协议和 AG-UI 映射,因为架构只需先固定变化感知边界。
- 暂不把完整事件溯源作为 P0 主体范式,因为对象、状态、事件契约和重放需求仍需详细设计继续验证。
- 暂不展开长期 Archive 交接协议,因为当前只需要保留追溯 / 归档接缝和待交接状态。
- 暂不选择具体数据库、搜索、队列、缓存和调度产品,因为这些是实现承载,不能反向改变主线。

当前不可接受债务:

- 不允许核心真相边界不清。
- 不允许相邻仓正文或外部平台正文进入本仓 truth。
- 不允许绕过授权视野消费。
- 不允许派生视图、检索索引或变化感知成为第二 truth。
- 不允许同步成功伪装下游传播、归档交接或投影重建已经完成。
- 不允许缺少关键变化追溯接缝。

### 3.5 未来哪些触发条件会迫使架构调整？

触发条件必须来自边界压力、规模压力、一致性压力、恢复压力或下游消费压力,而不是模糊的“以后可能需要”。典型触发包括:

- 对话事实规模、历史追溯深度或长历史定位压力让当前派生 / 索引承接不足。
- 下游变化感知和实时消费开始反压核心同步链路。
- 跨域显化来源增多,引用解析、快照新鲜度和来源不可用状态需要更强生命周期管理。
- 审计、复盘或合规要求明确需要事件级重放、时间旅行或更强不可变事实模型。
- Archive / Observability 要求从简单交接引用升级为正式交接协议和恢复验证。
- 量化负载模型证明单一读写承载或当前分层无法保持核心事实成立路径稳定。

### 3.6 当前主线演进时,最先改变的结构面是什么？

最先改变的结构面通常不是核心 truth center,而是外围承接层:派生只读视图、索引、变化感知、引用解析、新鲜度管理、追溯 / 归档交接和事件传播恢复。只有当审计重放、容量隔离或强恢复要求明确压到核心事实模型时,才考虑把完整事件溯源、分区冷热路径或更强状态生命周期纳入核心主线。

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 演进主语 | 功能、协议、性能数字和实现方案混杂 | 架构主线阶段、结构债务和触发条件 | 对齐书写规范 §4.14 |
| 当前阶段边界 | 容易理解为所有能力都要现在完成 | 当前先让独立 truth center、边界、归属、一致性和交互成立 | 架构不是项目排期 |
| 后续演进项 | 像愿望池或 TODO | 只保留会改变架构承接方式的结构演进项 | 避免扩张主线 |
| 设计债务 | 未区分可接受和不可接受 | 可接受债务有理由,不可接受债务是边界红线 | 防止实现阶段绕过核心约束 |
| 触发条件 | 泛泛“后续再优化” | 以规模、边界、一致性、恢复、审计压力触发 | 演进必须由事实驱动 |

## 7. 结构化中间产物

### 7.1 演进路线表

| 阶段 | 当前目标 / 范围 | 当前可接受债务 | 后续演进项 | 触发条件 | 说明 |
|---|---|---|---|---|---|
| 当前主线成立阶段 | 让独立 Conversation 真相核心、正式承接层、数据归属、授权消费、派生不反写、事件传播和后台承接边界成立。 | 暂不量化容量数字;暂不锁定实时协议、搜索产品、完整 ES 和长期归档协议。 | 后续再增强搜索、长历史、变化感知、引用新鲜度、归档交接和容量隔离。 | 当下游消费、长历史、引用解析、归档或容量压力开始影响核心边界判断时。 | 当前不是“所有能力全做完”,而是先让对话真相仓主线稳定成立。 |
| 派生消费增强阶段 | 在不改变 truth center 的前提下增强只读投影、检索索引、变化感知和长历史定位。 | 允许核心真相模型不按 UI / 搜索需求组织;允许投影有旧视图和重建状态。 | 更细粒度授权投影、搜索索引生命周期、变化感知游标、长历史定位辅助。 | 当 Chat、Workspace、Runtime 或审计读取需要稳定高频消费,且直接读取核心或简单投影开始反压核心链路时。 | 该阶段优先改变派生承接层,不改变核心真相归属。 |
| 引用 / 快照生命周期增强阶段 | 加强外部引用可解析性、展示快照新鲜度、来源不可用状态和显化记录恢复能力。 | 允许当前只表达旧快照、未解析、待刷新和挂起状态,不做完整生命周期策略。 | 引用状态机、快照新鲜度策略、来源不可用降级、显化恢复和引用失效审计。 | 当跨域显化来源增多,未解析引用和旧快照开始影响对话复盘、授权消费或下游稳定展示时。 | 该阶段仍不复制来源正文,只强化引用和快照承接。 |
| 事件 / 追溯增强阶段 | 在追加式事实历史基础上评估是否需要更强事件模型、重放、时间旅行和审计追溯能力。 | 当前不把完整 ES / CQRS 作为 P0 主体范式,只保留追加式事实和事件协作。 | 完整事件溯源、事件版本治理、重放窗口、时间旅行读取、审计 replay evidence。 | 当合规、复盘、恢复或跨仓重放明确要求事件级重放,且简单追加事实历史不足以解释状态变化时。 | 该阶段才考虑改变核心事实模型的内部表达方式。 |
| 归档 / 观测交接增强阶段 | 将对话追溯材料从简单交接引用升级为更正式的 Observability / Archive 协作协议。 | 当前只保留对话域追溯上下文、交接引用和待交接状态。 | 归档交接协议、观测材料 schema、交接失败恢复、归档回链验证。 | 当 `L4-observability` / `L4-archive` 需要稳定消费和恢复验证,且简单事件或引用交接不足以支撑审计要求时。 | 该阶段不让 Conversation 拥有全局日志或长期归档正文。 |
| 容量 / 隔离增强阶段 | 基于正式负载模型增强读写隔离、分区、冷热路径、后台重建和容量保护。 | 当前不继承旧 P95、连接数、月度 Turn 数字作为硬约束。 | 容量分层、读写隔离、冷热历史策略、投影重建隔离、批量维护限流。 | 当测试、验收或生产负载模型证明核心同步路径、派生维护或历史读取存在结构瓶颈时。 | 该阶段由量化事实触发,不是凭旧数字提前定方案。 |

### 7.2 当前阶段边界说明

当前阶段的目标不是把所有外围体验、协议、搜索、归档和容量策略一次性定完,而是先让 `L1-conversation` 作为独立对话真相仓的结构成立。只要核心 truth center、正式承接层、数据归属、授权视野、派生不反写、事件传播和后台承接边界稳定,后续能力就可以在不打穿边界的前提下演进。当前可接受债务之所以可接受,是因为它们暂不影响本仓是否拥有正确的对话真相;一旦这些债务开始影响核心边界、授权消费、追溯复盘或容量稳定,就必须进入下一阶段。

### 7.3 可接受债务与不可接受债务表

| 债务类型 | 当前是否可接受 | 理由 | 后续处理 |
|---|---|---|---|
| 未量化吞吐 / 延迟 / 连接数 / 月度事实容量 | 可接受 | 当前缺新版正式负载模型,提前继承旧数字会形成伪约束。 | 测试方案、验收标准和实施计划形成量化依据后触发容量增强阶段。 |
| 未锁定 SSE / WebSocket / AG-UI 等实时协议 | 可接受 | 架构已固定变化感知必须受授权视野和派生边界约束,协议不应反向定义真相。 | 概要 / 详细设计按接口边界继续选择。 |
| 未把完整 ES / CQRS 作为 P0 主体范式 | 可接受 | 当前已采用追加式事实历史和事件协作,但完整 ES 需要对象、状态、事件和重放需求共同支撑。 | 审计 / 重放压力明确后进入事件 / 追溯增强阶段。 |
| 未展开长期 Archive 交接协议 | 可接受 | 当前只需保留追溯上下文、交接引用和待交接状态,不接管 Archive 主体职责。 | Archive / Observability 形成正式消费需求后进入归档 / 观测交接增强阶段。 |
| 未选择具体数据库、搜索、队列、缓存产品 | 可接受 | 产品选择属于实现承载,不能反向改变架构边界。 | 概要 / 详细设计和实施计划中继续收敛。 |
| 核心真相边界不清 | 不可接受 | 会使本仓退化为 UI 消息缓存、Runtime memory 或外部平台副本。 | 必须在当前阶段修正。 |
| 授权视野消费边界不清 | 不可接受 | 会直接打穿需求一票否决项。 | 必须在当前阶段修正。 |
| 外部正文或来源真相进入 Conversation truth | 不可接受 | 会造成数据归属漂移和串仓。 | 必须在当前阶段修正。 |
| 派生视图 / 检索索引反写真相 | 不可接受 | 会形成第二 truth。 | 必须在当前阶段修正。 |
| 同步成功伪装异步传播 / 归档 / 投影已完成 | 不可接受 | 会破坏一致性和失败可解释性。 | 必须在当前阶段修正。 |

### 7.4 触发条件小表

| 触发条件 | 触发的演进方向 | 最先改变的结构面 | 不应改变的边界 |
|---|---|---|---|
| 下游高频读取、搜索或变化感知反压核心链路 | 派生消费增强 | 只读投影、索引、游标、重建承接 | 不直接暴露核心 truth 结构 |
| 长历史追溯和定位无法由当前辅助结构支撑 | 派生消费增强 / 容量增强 | 历史读模型、冷热读取、索引生命周期 | 不按 UI / 搜索需求重塑核心模型 |
| 跨域显化来源增多导致未解析 / 旧快照影响复盘 | 引用 / 快照生命周期增强 | 引用状态、快照新鲜度、显化恢复 | 不复制来源仓正文 |
| 合规或恢复要求明确事件级重放 / 时间旅行 | 事件 / 追溯增强 | 事实事件模型、版本治理、重放窗口 | 不让事件流接管外部仓 truth |
| Observability / Archive 要求正式恢复验证和回链 | 归档 / 观测交接增强 | 交接协议、回链验证、待交接恢复 | 不拥有全局日志或归档正文 |
| 正式负载模型证明单一承载不足 | 容量 / 隔离增强 | 读写隔离、分区、冷热路径、后台重建隔离 | 不降低核心一致性和授权边界 |
| 新外部平台或来源仓接入造成显化语义压力 | 引用 / 快照生命周期增强 / 事件增强 | 正式承接层、显化映射、来源事件适配 | 不让 Bridges 或来源仓直接写核心 |

### 7.5 不作为演进项的事项

| 事项 | 不作为演进项的原因 | 正确归属 |
|---|---|---|
| Chat UI 组件、页面、交互体验 | 前文已确认 Chat 是消费方,不是 Conversation 主体职责。 | `L5-chat` |
| Workspace 个人首页、项目首页、inbox 聚合 | 前文已确认 Workspace 是视野聚合方,不是 Conversation truth owner。 | `L1-workspace` |
| Runtime agent loop、LLM 推理、tool 调用和 memory | 前文已确认 Runtime 是协作方和事实来源之一,不拥有 Conversation truth。 | `L2-runtime` / `L2-tools` |
| Bridges 外部平台账号、频道和协议生命周期 | 前文已确认外部平台适配归 Bridges。 | `L6-bridges` |
| Governance Gate / Policy / Approval 裁决主线 | 前文已确认治理裁决不属于本仓。 | `L1-governance` |
| Artifact 正文、版本、证据链生命周期 | 前文已确认 Artifact 正文不进入 Conversation truth。 | `L1-artifact` |
| Identity 成员生命周期、认证和角色定义 | 前文已确认本仓只引用成员 / actor。 | `L1-identity` / security |
| 全局日志平台和长期归档正文管理 | 前文已确认本仓只做追溯交接,不拥有全局日志或归档正文。 | `L4-observability` / `L4-archive` |

### 7.6 演进边界说明

`L1-conversation` 的演进必须优先保护现有主线,而不是扩张职责。能先在派生层、引用层、交接层、后台承接层解决的问题,不应直接改变核心 truth center;只有当审计重放、容量隔离或恢复要求明确证明当前事实模型不足时,才考虑核心结构演进。每个后续阶段都必须继续满足四条底线:不复制来源正文,不绕过授权视野,不让派生反写,不让下游消费反向绑定核心模型。

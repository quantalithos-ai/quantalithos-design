## 3. SOP 问题回答

### 3.1 当前还有哪些尚未关闭的架构风险？

当前尚未关闭的架构风险集中在八类:

- 旧 `Conversation kind`、`Turn kind`、AG-UI、接口和事件细节回流为架构主线。
- Chat、Workspace、Runtime、Bridges 或外围增强能力反向定义 Conversation truth center。
- 成员、项目、治理、产物、外部平台或归档正文因展示便利进入 Conversation truth。
- 派生视图、检索索引、变化感知或订阅结果绕过授权视野。
- 派生读模型、搜索或变化流成为第二 truth。
- 同步成功被误写成异步传播、投影重建、归档交接或观测交接已经完成。
- 缺少正式负载模型导致旧 P95、连接数、月度事实容量等数字回流。
- Observability / Archive 交接被扩张成 Conversation 拥有全局日志或长期归档正文。

### 3.2 这些风险会影响哪一层架构结构？

这些风险分别影响职责边界、系统上下文、依赖方向、数据所有权、一致性策略、关键交互、横切关注点和演进路线。最严重的风险会直接破坏 `L1-conversation` 作为独立对话真相仓的成立条件,因此必须在架构风险章节中显式列出。

### 3.3 当前还有哪些待确认事项？

当前待确认事项主要是还缺后续设计或测试阶段输入的问题,包括正式 API / event / DTO / protocol 字段、外围增强当前交付范围、量化容量模型、引用与快照生命周期、Archive / Observability 交接协议、完整 ES / CQRS 是否升级为主体范式、实时消费协议、具体数据库 / 搜索 / 队列 / 缓存产品。

### 3.4 哪些待确认项会影响前文结论是否成立？

这些待确认项不会推翻当前已收稳的架构边界:Conversation 仍是对话真相仓,只保存自身 truth、引用、快照、显化和派生读模型,不拥有外部正文。它们会影响后续概要设计、详细设计、测试方案和实施计划如何落地;如果后续选择打穿外部正文排除、授权视野、派生不反写或同步 / 异步边界,才会反向破坏前文结论。

### 3.5 哪些风险是当前阶段可接受的,哪些会阻塞后续推进？

当前可接受并可带约束推进的风险是:协议 / 产品未定、量化负载模型未定、完整 ES / CQRS 未定、Archive / Observability 交接格式未定、外围增强交付范围未定。会阻塞后续推进的是:核心 truth 边界不清、外部正文进入本仓 truth、授权视野被绕过、派生结构反写真相、同步成功伪装异步 / 后台工作完成、下游消费方反向拥有 Conversation 真相。

## 4. 当前文档问题诊断

| 旧 / 前序内容 | 问题 | 本轮处理 |
|---|---|---|
| 旧文档中的四形态、Turn kind、AG-UI、接口事件细节 | 容易回流为架构第一层结构 | 只作为历史候选输入,不得高于新版架构主线 |
| 旧性能数字和实时推送口径 | 缺少新版需求确认的负载模型和协议裁剪 | 写成待确认事项或演进触发条件,不作为当前硬指标 |
| Search、projection、change stream 靠近主线 | 可能成为第二 truth | 明确只作为派生只读能力,不得反写真相 |
| Archive / Observability 相关内容 | 容易扩张成本仓长期归档或全局日志职责 | 当前只保留追溯 / 归档交接接缝 |
| 外部正文和来源快照混写 | 展示便利可能诱导保存来源正文 | 当前用引用 / 快照 / 显化记录约束,正文不得进入 truth |
| 授权消费和派生消费边界 | 后续实现可能只在核心接口检查,投影 / 订阅绕过 | 当前把授权视野提升为所有消费路径的横切约束 |

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 风险表达 | 分散在需求风险、演进债务和旧文档问题中 | 汇总成正式风险表,写清影响范围、当前处理口径和阻塞性 | 对齐书写规范 §4.15 |
| 待确认事项 | 容易混入 TODO、方案或演进愿望 | 只保留缺确认且会影响后续主线判断的问题 | 防止脑补确定性结论 |
| 阻塞判断 | 可接受债务和不可接受债务容易混淆 | 明确阻塞 / 不阻塞 / 有条件阻塞 | 支撑是否能进入 ADR 与需求追溯 |
| 旧口径处理 | 旧细节可能继续影响架构主线 | 统一按历史输入暂存,不得反向定义 truth center | 防止旧文档回流 |
| 边界红线 | 分散在多个 Step | 在风险表中集中约束 | 便于后续概要 / 详细设计继承 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 只写“暂无阻塞风险” | 文档短,推进快 | 会掩盖旧口径回流、授权绕过、派生第二 truth 等关键风险 | 不采用 |
| 方案 B: 风险与待确认事项拆成两张表,并给出阻塞判断 | 可审查,能承接后续设计和测试 | 文档更长,需要避免重复前文已定结论 | 采用 |
| 方案 C: 把所有未定能力都写成风险 | 显得谨慎 | 会把可接受债务、演进项和技术选型缺口误写成阻塞风险 | 不采用 |
| 方案 D: 在本步直接解决全部待确认事项 | 看似闭环 | 违反本步边界,会把详细设计、测试和实施问题提前脑补成架构定论 | 不采用 |

## 7. 结构化中间产物

### 7.1 风险表

| 风险项 | 影响范围 | 当前处理口径 | 是否阻塞 | 说明 |
|---|---|---|---|---|
| 旧四形态、Turn kind、AG-UI、接口和事件细节回流为架构主线 | 需求基线、系统上下文、关键技术选型、演进路线 | 当前只作为历史候选输入暂存,不得高于新版需求和 Step 1~13 已收稳结论 | 不阻塞 | 只要不重新成为主线,该风险可带约束推进;若回流为 truth center 结构,则阻塞。 |
| Chat、Workspace、Runtime、Bridges 或外围增强反向定义 Conversation truth center | 职责边界、系统边界、依赖方向、核心能力闭环 | 当前坚持 Conversation 是独立对话真相仓,外部方只能通过正式接缝输入或消费 | 阻塞 | 该风险一旦发生,本仓会退化为 UI 缓存、Runtime memory 或外部平台副本。 |
| 相邻仓或外部平台正文进入 Conversation truth | 数据所有权、安全边界、跨域显化、追溯读取 | 当前只允许引用、快照、显化记录和派生读模型,禁止保存来源正文或长期归档正文 | 阻塞 | 该风险会造成 Work / Governance / Artifact / Identity / Bridges / Archive 真相漂移。 |
| 授权视野被投影、订阅、变化感知或追溯读取绕过 | 授权消费、派生视图、下游订阅、历史追溯 | 当前要求所有消费路径都受参与范围和可见范围约束 | 阻塞 | 授权视野是核心闭环的一部分,不能只在核心同步接口检查。 |
| 派生视图、检索索引或变化流成为第二 truth | 数据一致性、派生读模型、搜索、变化感知 | 当前将派生结构限定为只读、可重建、最终一致,不得反写核心事实 | 阻塞 | 一旦派生结构可反写或被视为权威,会破坏 truth / derived 分层。 |
| 同步成功伪装异步传播、投影重建、归档交接或观测交接已完成 | 关键交互、一致性策略、韧性 / 恢复、验收口径 | 当前同步只证明核心事实或授权读取成立,传播、派生和交接必须表达独立状态 | 阻塞 | 该风险会制造伪一致,使失败不可解释。 |
| 缺少正式负载模型导致旧性能数字或任意容量数字回流 | 性能 / 容量约束、测试方案、验收标准、实施计划 | 当前只保留结构性性能口径,量化数字后移到测试和验收 | 不阻塞 | 当前不阻塞架构收口,但后续不能无依据继承旧 P95、连接数或月度事实容量。 |
| Archive / Observability 交接扩张为本仓拥有全局日志或长期归档正文 | 横切关注点、追溯交接、数据归属、演进路线 | 当前只保留对话域追溯上下文、交接引用和待交接状态 | 有条件阻塞 | 交接协议未定不阻塞;若本仓接管外部主体职责,则阻塞。 |
| 完整 ES / CQRS 被过早锁定或被完全遗忘 | 技术机制、备选方案、演进路线、后续详细设计 | 当前只固定追加式事实历史和事件协作,完整 ES / CQRS 保留观察 | 不阻塞 | 当前阶段可不锁定实现范式,但详细设计需继续评估状态、事件和重放压力。 |

### 7.2 待确认事项表

| 待确认事项 | 影响范围 | 缺失确认 | 当前挂起口径 | 说明 |
|---|---|---|---|---|
| 正式 API、event、DTO、protocol 名称和字段 | 概要设计、详细设计、测试方案、实施计划 | 缺接口级协议、字段和错误语义确认 | 架构层只保留交互类别和边界,不预支接口签名 | 这些内容应在概要 / 详细设计中逐接口展开。 |
| 外围增强能力中哪些进入当前交付范围 | 功能裁剪、演进路线、测试与验收 | 缺当前阶段交付边界和优先级确认 | 当前按外围增强挂起,不作为核心 truth 成立条件 | 包括长历史检索、强实时感知、搜索增强和消费辅助维护。 |
| 量化吞吐、延迟、连接数、历史容量和重建窗口 | 横切性能、测试方案、验收标准、实施计划 | 缺正式负载模型和测量方法 | 当前只保留“核心链路不被外围拖重”的结构性口径 | 不能继承旧数字或随意补数。 |
| 引用解析、快照新鲜度、失效显示和恢复生命周期 | 数据所有权、一致性策略、派生读模型、历史追溯 | 缺具体状态机、刷新策略和来源不可用处理口径 | 当前只确认引用 / 快照不等于来源 truth,生命周期后移 | 该事项会影响概要和详细设计对象 / 状态定义。 |
| `L4-observability` / `L4-archive` 交接协议 | 横切追溯、归档交接、事件协作、验收证据 | 缺交接 schema、回链验证和失败恢复确认 | 当前只保留交接接缝和待交接状态 | 不影响当前架构边界,但影响后续审计和验收。 |
| 完整 ES / CQRS 是否成为后续主体实现范式 | 技术机制、备选方案、详细设计、重放能力 | 缺对象、状态、事件契约、容量模型和审计 / 重放压力确认 | 当前保持追加式事实历史 + 事件协作,不锁定完整范式 | 若后续进入主线,需要 ADR 级决策。 |
| 实时消费协议选择 | 下游订阅、变化感知、Chat / Workspace 消费、SDK surface | 缺 SSE / WebSocket / AG-UI / 其他协议的后续裁剪确认 | 当前只固定变化感知必须经授权视野和派生边界 | 协议不能反向定义 Conversation 核心模型。 |
| 具体数据库、搜索、消息队列、缓存和调度产品 | 容器部署、技术承载、实施计划、容量验证 | 缺实现环境、容量模型和代码仓约束确认 | 架构层只定义承载职责和一致性口径,不锁产品 | 产品选择应在概要 / 详细 / 实施阶段承接。 |

### 7.3 当前处理口径说明短文

本章把已经明确会打穿 Conversation 主线边界的问题写成风险,把仍缺接口、协议、量化模型、产品或后续仓协作确认的问题写成待确认事项。风险的当前处理口径只说明现在如何约束或暂存,不写最终解决方案;待确认事项只说明缺什么确认和如何挂起,不预支后续设计结论。已被前文确认的边界红线不再伪装成待确认项,但一旦后续实现打穿这些红线,就会转化为阻塞问题。

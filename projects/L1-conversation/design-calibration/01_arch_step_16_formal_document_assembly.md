## 3. SOP 问题回答

### 3.1 哪些已确认结论应分别回填到哪些正式章节？

Step 1 支撑来源承接、约束条件和需求追溯矩阵。Step 2 回填业务背景与驱动力、约束条件。Step 3 ~ Step 15 分别回填职责边界、系统上下文、限界上下文、容器 / 部署、依赖方向、数据所有权、关键交互、关键技术机制、备选方案、横切关注点、演进路线、风险与待确认、需求追溯和 ADR 索引。参考章节只收纳正式参考材料,不承接新的架构判断。

### 3.2 哪些结论需要拆分吸收到多个章节,而不是机械复制？

需求基线需要拆分到 §1、§3 和 §16。依赖失效降级口径既支撑 §5 系统上下文,也支撑 §13 横切关注点和 §15 风险。外部正文排除规则需要同时进入 §4 职责边界、§8 依赖方向、§9 数据所有权、§13 横切关注点和 §15 风险。授权视野既是职责边界、数据一致性、关键交互和横切关注点,也必须在追溯矩阵中长期保留。

### 3.3 哪些术语、编号或交叉引用需要统一？

正式文档统一使用 `L1-conversation`、`Conversation 真相核心`、`对话空间`、`参与范围`、`可见范围`、`对话事实历史`、`跨域显化记录`、`授权视野`、`派生消费辅助`、`本地索引 / 投影 / 引用层`、`追溯 / 归档交接接缝` 等术语。旧版 `Conversation 四形态`、`Turn kind`、`AG-UI 17 事件映射`、旧 P95 / 月度 Turn 容量等只作为历史风险,不得回流为正式架构主线。

### 3.4 哪些内容仍应继续保留为风险或待确认,不能润色成定论？

正式 API / event / DTO / protocol 字段、实时消费协议、量化容量模型、引用与快照生命周期、Archive / Observability 交接协议、具体数据库 / 搜索 / 队列 / 缓存产品、完整 ES / CQRS 是否升级为主体范式,都必须继续保留为待确认或后续设计承接项,不能在 Step 16 写成已定方案。

### 3.5 参考项应如何收口,不与 ADR 或追溯重复？

参考章节只保留正式参考材料和用途说明,包括当前需求文档、架构 SOP、架构书写规范、全局依赖裁剪规则以及已完成的 L0 / L1 上游设计材料。ADR 候选保留在 §17,需求到架构的承接关系保留在 §16,参考章节不重复追溯矩阵或 ADR 索引。

## 6. 术语统一结论

| 正式术语 | 统一含义 | 禁止替代表达 |
|---|---|---|
| `L1-conversation` | 平台对话真相仓 | Chat 消息服务、StreamEvents 服务、Conversation 四形态服务 |
| Conversation 真相核心 | 本仓唯一核心子域 | Conversation Store、Turn Stream、Search core |
| 对话事实历史 | 正式追加后的对话域事实历史 | Runtime memory、外部平台消息正文、UI 消息状态 |
| 跨域显化记录 | 外部正式事实在对话中被引用 / 快照 / 显化的记录 | 来源仓正文副本、事件转 Turn |
| 授权视野 | 查询、订阅、变化感知、追溯和派生消费必须遵守的可见边界 | 仅查询权限、UI 过滤 |
| 派生消费辅助 | 投影、索引、检索、变化感知等只读辅助结构 | 第二 truth、反写来源 |
| 本地索引 / 投影 / 引用层 | 为稳定消费和降级显示保留的本地影子结构 | 外部正文缓存、来源真相副本 |
| 追溯 / 归档交接接缝 | 向 Observability / Archive 交接对话域追溯材料的边界 | 全局日志仓、长期归档正文 |

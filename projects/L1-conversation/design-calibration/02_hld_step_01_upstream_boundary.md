## 3. SOP 问题回答

### 3.1 当前概要设计要承接哪些需求结论？

当前概要设计要承接以下需求结论:

- `L1-conversation` 是平台对话真相仓,不是 Chat UI、Workspace 聚合、Bridges 协议适配、Runtime 推理、Governance 决策、Artifact 正文或 Identity 生命周期仓。
- 核心能力闭环是:对话空间与参与范围独立确立 -> 多来源协作事实追加沉淀 -> 授权视野下稳定消费 -> 关键跨域事实引用显化 -> 对话历史追溯与复盘。
- 使用方包括终端管理者、项目参与者、AI member、系统事件 actor、审计者 / 合规查看者、运维 / 后台任务、下游应用开发者。
- 功能需求覆盖对话空间 / 范围、协作事实追加、授权消费、跨域显化、历史追溯、派生辅助、长历史定位和变化感知。
- 数据归属要求本仓拥有对话空间、参与范围、可见范围、对话事实历史、显化记录和追溯上下文,只保存外部对象的引用、快照或派生投影。
- 验收红线包括核心能力闭环缺失、授权视野失效、外部正文进入 Conversation truth、派生结果替代 truth、关键变化不可追溯。

### 3.2 当前概要设计要承接哪些架构结论？

当前概要设计要承接以下架构结论:

- `L1-conversation` 的架构主线是独立 Conversation truth center。
- 内部语义结构是一个 `Conversation 真相核心` 加多个支撑上下文,并保留本地索引 / 投影 / 引用层。
- 正式运行承载包括同步入口、异步输入、后台派生维护、真相存储承载、派生视图 / 索引承载和事件协作 / 追溯交接边界。
- 依赖方向以核心语义角色为中心,外部能力通过正式接缝进入,派生消费辅助只能从核心真相派生,技术承载不能定义业务语义。
- `L0-core` 是唯一编译期依赖;`L0-bus`、`L1-identity`、`L1-work`、`L1-governance`、`L1-artifact`、`L0-sdk`、`L5-chat`、`L1-workspace`、`L2-runtime`、`L6-bridges`、`L4-observability`、`L4-archive` 都按运行期或事件协作边界处理。
- 数据一致性要求核心真相内部强一致,派生视图、外部快照、变化感知、观测和归档交接最终一致,引用有效性必须显式表达。
- 通信方式要求核心成立判断同步收口,已成立事实和外部结果异步传播,派生、刷新、重建和交接后台延后承接。
- 架构机制包括正式承接层、引用 / 快照 / 显化记录、追加式事实历史、授权视野、派生只读视图、事件最终一致、后台延后承接和追溯 / 归档交接接缝。

### 3.3 哪些结论已经足够稳定,可以直接作为概要设计输入？

足够稳定、可以直接作为概要设计输入的结论包括:

- 仓定位、职责边界、非目标和边界红线。
- 核心能力闭环和核心 / 外围增强 / 边界外能力分层。
- 上下游关系和跨仓依赖裁剪。
- `Conversation 真相核心`、支撑上下文、本地索引 / 投影 / 引用层的语义结构。
- 同步入口、异步输入、后台派生维护、真相承载和派生承载的运行承载角色。
- truth / snapshot / reference / derived read model 的数据归属口径。
- 同步 / 异步 / 后台承接的通信方式。
- 风险和待确认事项中对旧四形态、Turn kind、AG-UI、旧性能数字、具体协议和具体产品的挂起口径。

### 3.4 哪些结论虽然相关,但仍未收稳,因此当前不能直接往下展开？

以下结论仍未收稳,当前不能作为已定概要设计输入直接展开:

- 正式 API、event、DTO、protocol 名称和字段。
- 实时消费协议选择,例如 SSE、WebSocket、AG-UI 或其他协议。
- 量化吞吐、延迟、连接数、历史容量和重建窗口。
- 引用解析、快照新鲜度、失效显示和恢复生命周期的具体状态机。
- `L4-observability` / `L4-archive` 交接协议、schema、回链验证和失败恢复。
- 完整 ES / CQRS 是否成为后续主体实现范式。
- 具体数据库、搜索、消息队列、缓存、调度和部署产品。
- 旧 `Conversation 四形态`、`Turn kind`、`StreamEvents`、`AG-UI 17 事件映射` 能否成为对象 / 接口 / 协议层细节,需要后续 Step 重新筛选,不能直接继承为概要主线。

### 3.5 哪些边界、非目标和约束会直接决定概要设计当前不该展开到哪里？

以下边界直接决定概要设计当前不该越界:

- 不重新定义需求目标、用户故事、验收标准和上游仓定位。
- 不重新定义系统上下文、子域划分、数据所有权原则、关键技术机制和方案取舍。
- 不展开完整 Rust 字段、完整函数实现、DDL、协议 schema、部署参数或运维脚本。
- 不让 Chat UI、Workspace 聚合、Runtime memory、Bridges 外部平台对象、Governance / Artifact / Work / Identity 正文进入 Conversation truth。
- 不让派生视图、检索索引、变化感知游标或推送结果反写真相。
- 不把配置设计、测试方案、验收标准和实施计划提前写进概要设计。

- 状态集合和状态流转如何表达对话空间、事实追加、显化、派生、交接等关键状态。

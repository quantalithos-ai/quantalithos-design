## 3. SOP 问题回答

### 3.1 哪些约束会直接影响本仓对象、接口、处理流或状态机设计？

会直接影响后续概要设计的约束包括:

- 独立 Conversation truth center 约束:对象和模块必须围绕对话空间、参与范围、可见范围、事实历史、显化记录和追溯上下文展开。
- 编译依赖约束:核心语义只能编译期依赖 `L0-core`,其他仓通过引用、快照、事件、port 或外部接缝协作。
- 数据归属约束:本仓只拥有 Conversation truth、派生消费辅助和外部引用关系,不拥有相邻仓正文。
- 授权视野约束:所有查询、订阅、变化感知、派生输出、追溯读取和下游消费必须受参与范围与可见范围约束。
- 追加与追溯约束:正式对话事实和关键状态变化必须可追溯,不得被投影、维护任务或展示层覆盖。
- 跨域显化约束:外部正式事实进入对话只能成为引用、快照或显化记录,来源真相不转移。
- 派生只读约束:索引、投影、检索、变化感知和消费辅助视图只能从 Conversation truth 派生,不得成为第二 truth。
- 一致性分层约束:核心成立强一致,传播、派生、快照刷新、引用解析和交接最终一致或引用有效性一致。
- 通信方式约束:核心成立和授权读取同步收口,已成立事实传播和外部结果送达异步承接,派生 / 刷新 / 重建 / 交接后台处理。
- 配置边界约束:配置不得改变 truth 归属、正文排除、授权视野、同步 / 异步 / 后台分工或派生不反写原则。

### 3.3 哪些边界如果不先写清，后续最容易串到相邻仓或详细设计？

最容易串线的边界包括:

- Chat UI / Workspace 聚合视图与 Conversation truth 的边界。
- Runtime 推理过程、tool 调用、memory 与对话事实历史的边界。
- Bridges 外部平台 message、channel、account 生命周期与内部 Conversation 空间 / 事实的边界。
- Governance / Artifact / Work / Identity 的来源正文与对话内显化记录的边界。
- Observability / Archive 的全局日志、归档包正文与 Conversation 追溯上下文的边界。
- 派生视图、检索索引、变化感知游标与核心 truth 的边界。
- 同步成立状态与异步传播 / 后台派生 / 归档交接状态的边界。
- 概要设计骨架与详细设计完整字段、DTO、函数、事务、状态矩阵、配置项的边界。

### 3.4 哪些约束只是泛化工程原则，不应进入本章？

以下内容不进入本章约束条件:

- “代码要清晰”“模块要解耦”“可维护性要好”这类泛化工程原则。
- 具体数据库、搜索、消息队列、缓存、调度器或部署拓扑选择。
- 完整 Rust module layout、crate name、trait 签名和 repository 函数。
- 具体 API 字段、JSON / proto / CloudEvent schema、错误码、幂等键格式。
- 具体测试覆盖率、性能数值、压测规模和验收证据路径。
- 具体配置项默认值、配置文件格式和配置加载实现。

### 3.5 每条约束是否能指导后续章节的设计判断？

本步保留的约束都必须能回答至少一个后续设计判断:

- Step 4 用它判断代码主体框架是否围绕核心语义、编排承接、外部接缝、派生辅助和技术承载展开。
- Step 5 用它判断主要组成部分是否越权承接相邻仓职责。
- Step 6 用它判断关键对象是否是本仓 truth、snapshot、reference、derived view 或 forbidden body。
- Step 7 用它判断接口是 Command、Query、Event、Operations Job 还是外部接缝,以及是否越过授权 / 数据归属边界。
- Step 8 用它判断处理流是否把同步成立、异步传播和后台承接混写。
- Step 9 用它判断状态机是否表达未解析、过期、待交接、待重建等非核心完成状态。
- Step 10 用它判断异常和边界场景是否覆盖授权失败、引用不可解析、正文越界、派生延迟和交接失败。
- Step 11 用它判断配置是否只影响技术承载和策略参数,不得改变核心边界。

## 7. 结构化中间产物

### 7.1 约束条件表

| 约束 | 说明 |
|---|---|
| 独立 Conversation truth center 约束 | 后续代码主体、主要组成部分和关键对象必须围绕对话空间、参与范围、可见范围、对话事实历史、跨域显化记录和追溯上下文展开,不能被 Chat、Workspace、Runtime、Bridges 或来源仓吸收。 |
| 编译依赖与跨仓裁剪约束 | 核心语义只能编译期依赖 `L0-core` 共享契约;`L0-bus`、`L1-identity`、`L1-work`、`L1-governance`、`L1-artifact`、`L0-sdk`、`L5-chat`、`L1-workspace`、`L2-runtime`、`L6-bridges`、`L4-observability`、`L4-archive` 必须按运行期、事件协作、外部接缝或下游消费裁剪。 |
| 数据归属分层约束 | 本仓正式拥有 Conversation truth;可以保存快照 / 投影和引用关系;不得保存 Chat UI、Workspace 视图、Runtime memory、外部平台对象、Governance / Artifact / Work / Identity 正文、全局观测日志或长期归档包正文。 |
| 授权视野强制约束 | 查询、订阅、变化感知、派生输出、追溯读取、下游消费和维护性读取都必须受参与范围与可见范围约束,不得由 projection、index、event 或 SDK facade 绕过。 |
| 追加与追溯约束 | 已成立的对话事实和关键状态变化必须以可追溯方式保留;更正、撤回、显化失败、补充说明或维护动作不得直接覆盖既有正式事实。 |
| 跨域显化约束 | Work、Governance、Artifact、Identity、Runtime、Bridges 等来源事实进入对话时只能形成引用、快照、显化记录或结果性事实追加,不得转移来源正文、裁决、版本、成员生命周期或外部平台生命周期真相。 |
| 派生只读约束 | 投影、索引、检索、变化感知游标、下游消费视图和展示快照只能从 Conversation truth 派生,可延迟、可重建、可过期,但不能生成新业务事实或反写核心。 |
| 一致性分层约束 | 对话空间、范围、可见边界、事实追加、显化记录和追溯锚点必须强一致收口;传播、投影、检索、快照刷新、引用解析、观测和归档交接只能按最终一致或引用有效性一致表达。 |
| 通信方式分层约束 | 核心成立判断和授权读取使用同步请求 / 响应收口;已成立事实传播和外部正式结果送达使用异步事件 / 回调承接;派生、刷新、重建和交接材料形成使用后台任务 / 延后承接。 |
| 失败状态显式约束 | 不可解析引用、旧快照、过期投影、待传播事件、待重建索引、待交接追溯材料和外部依赖降级都必须表达为独立状态或边界场景,不得伪装成核心成功。 |
| 配置不可越界约束 | 配置只能影响运行承载、派生策略、刷新节奏、保留期限、限流或外部接缝参数,不得改变 truth 归属、正文排除、授权视野、同步 / 异步 / 后台分工或派生不反写原则。 |
| 协议与产品中立约束 | 概要设计不得提前锁定 SSE、WebSocket、AG-UI、具体数据库、搜索产品、队列产品、缓存产品或容量数字;这些只能在后续详细设计、配置设计、测试、验收或实施计划中基于本约束展开。 |

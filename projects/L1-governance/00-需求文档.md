## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 不只是让 AI 和人聊天,而是要让 AI 员工在**受控、可审计、可追责**的框架下工作。这要求平台具有:
- Gate 六段式结构化决策
- Policy 规则下发与优先级
- AIIA / SoA / Control / Nonconformity 的治理闭环
- shared_rules 不可被低 scope 覆盖

L1-governance 就是这个治理中心。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `domain/governance/README.md` 1798 行 | 设计完整,仓级需求层未显式化 |
| Gate 六段式 | 已设计 | 仓级样板尚未验证实际可读性 |
| Policy 下发 | bus / capability-hub 依赖明确 | DSL 选型未定 |
| Control / SoA / AIIA | 合规语义明确 | 仓级成功标准需细化 |
| 47 条不变量 | 已定义 | 代码阶段需高覆盖率约束 |

### 2.3 为什么要做(量化依据)

- 没有 governance,AI 可以绕过关键决策点,平台不满足 42001 的核心承诺
- 所有六域都会消费 `gate.decided` 或 Policy 结果,治理仓是跨域放射中心
- README 目标是 200w Gate / 1000w Policy 历史记录,这是平台级基础能力

### 2.4 业务问题 vs 技术问题

- **业务问题**:AI 决策如何被限制、审计、回溯并符合标准
- **技术问题**:Gate 六段式、Policy 优先级 / shared_rules、AIIA / SoA 双身份、Nonconformity 纠正闭环

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 起 Gate(raise)并等待决策
2. decide Gate(approve / reject / request_changes)
3. 发布 / 激活 Policy,下发到 runtime / capability-hub
4. 管理 AIIA / SoA / Nonconformity
5. 各域消费 `gate.decided` 结果推进状态

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **Owner**,我想要 **在关键节点收到结构化 Gate 请求并做决策**,以便 **关键变更不被 AI 自动越权推进** |
| 优先级 | P0 |
| 验收条件 | **Given** process / work / artifact 触发 RaiseGate **When** 查询 Gate **Then** 六段完整、候选项 ≥ 2 且含 reject 语义 |

| 字段 | 内容 |

| 验收条件 | **Given** project scope + role scope 的 Policy 已 active **When** 调 `GetApplicablePolicies` **Then** 返回按优先级合并后的最终有效规则 |

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 聚合 / 类型 | 生命周期 |
|---|---|---|
| Gate | 聚合根 | pending → in_review → decided / expired / cancelled |
| Approval | Gate 内实体 | vote cast → frozen |
| Policy | 聚合根 | draft → active → superseded / retired |
| Control | 聚合根 | declared → reviewed / violated |
| AIIA | 聚合根 | created → submitted → approved / superseded |
| SoA | 聚合根 | drafted → published → superseded |
| Nonconformity | 聚合根 | raised → corrective_action_added → resolved / closed |

### 9.2 数据关系

```
Gate
  ├─ approvals[]
  ├─ related_artifacts[]
  ├─ related_activities[]
  └─ related_workitems[]

Policy
  ├─ rules[]
  └─ scope / priority / shared_rules

Control
  └─ may trigger Nonconformity

AIIA / SoA
  └─ artifact 双身份
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| Gate / Approval | 7 年 | 冷存可查 | 不提前删 |
| Policy 历史 | 7 年 | 长期保留 | retired 不删 |
| SoA / AIIA | 7 年 | 与 artifact 同步归档 | 不删 |
| Nonconformity | 长期 | 审计保留 | 只读归档 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Policy 冲突导致下游行为不可预测 | 中 | 高 | priority + shared_rules 硬约束 |
| Gate 候选项设计不合理 | 中 | 高 | 至少 2 选项 + reject 语义必有 |
| SoA 控制项覆盖错误 | 低 | 极高 | 静态校验 |
| autonomy_level=5 越权 | 低 | 极高 | policy_auto 硬校验 |

### 12.2 边缘风险

- Gate rollback 需求出现
- 多组织继承使 Policy 求值爆炸
- AIIA 自动草拟引入错误偏见

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| Policy DSL 选 CEL 还是 Rego | N2 前 | governance + capability-hub |
| Gate kind 扩展机制 | N2 前 | governance |
| Nonconformity 阈值自动化 | N2 后 | governance |

## 3. 约束条件

> 校准来源:
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_03_constraints.md` 的“约束条件表”“后续章节门禁表”和“待确认事项”小节。

`L1-governance` 的概要设计受以下结构性约束保护:

| 约束 | 说明 |
|---|---|
| 独立 Governance truth | Gate / Decision、Approval / responsibility、Policy effective fact、shared rules、Control、AIIA / SoA conclusion、Nonconformity 和 traceability 归 Governance |
| 编译依赖裁剪 | 核心语义只编译期依赖 `L0-core`;其他仓通过 ref、snapshot、summary、event、port 或 handoff 协作 |
| 数据归属分层 | 本仓拥有 Governance truth,可保存外部引用、摘要、快照和派生视图,不得保存相邻仓正文 |
| Gate / Decision 正式性 | process waiting state、conversation card、work lifecycle、runtime cache、report row 或 external GRC record 不得替代正式裁决 |
| Approval / responsibility 边界 | 审批责任、投票、授权和风险承担归 Governance 裁决语境,不接管 identity truth |
| Policy / shared rules 边界 | Policy 生效事实、scope、priority、conflict 和 shared rules 归 Governance,低 scope 不得覆盖组织硬约束 |
| Control / compliance conclusion 边界 | 只保存适用性、覆盖、排除、批准和责任结论,不保存标准、artifact、evidence 或 archive body |
| Nonconformity 闭环 | 必须表达不符合、原因、纠正、复验、关闭和责任语境,不得退化为 bug、blocker、alert 或备注 |
| 派生只读 | dashboard、report、projection、reconciliation、archive preparation 和 external GRC export 不得反写真相 |
| 一致性分层 | 核心治理事实强一致;外部快照、引用解析、事件传播、派生视图和交接最终一致或引用有效性一致 |
| 通信方式分层 | 核心变化同步收口;已成立事实传播异步承接;派生、刷新、重建、对账和 handoff 后台处理 |
| 配置不可越界 | 配置不得改变 truth 归属、正文排除、正式裁决、shared rules、状态机红线、依赖方向或派生不反写 |

这些约束指导后续章节判断对象是否越权、接口是否混写读写、处理流是否把同步成立和异步传播混淆、状态机是否缺少失败态、配置是否绕过核心边界。

## 4. 代码主体框架总览

> 校准来源:
> - `design-calibration/02_hld_step_04_code_subject_framework.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_04_code_subject_framework.md` 的“架构模块到代码主体映射图”“实现分层视图”和“业务主要组成部分与实现分层关系说明”小节。

架构层语义上下文不直接等同源码目录。本文先收稳代码主体骨架,后续详细设计再决定 crate、module、file、trait 和 repository 细节。

```text
+==================================================================+
|                 L1-governance code subject map                   |
+==================================================================+
| Governance truth core              -> domain truth / trace / outbox|
| Governance context and input       -> context service / resolver   |
| Gate and decision management       -> decision service / policy    |
| Approval and responsibility        -> approval coordination service|
| Policy and shared rules            -> policy service / conflict    |
| Control and compliance conclusion  -> control compliance service   |
| Nonconformity corrective loop      -> nonconformity service        |
| Consumption and traceability       -> query / trace / handoff      |
| Maintenance and reconciliation     -> rebuild / refresh / report   |
| External context mirrors           -> snapshot / reference support |
+==================================================================+
```

实现分层如下:

| 分层 | 职责 | 边界 |
|---|---|---|
| Inbound / Operations | command、query、event、callback、job trigger 进入系统 | 不做业务判定 |
| Application Services | 编排用例、事务、幂等、domain 调用、repository / port 和 outbox | 不替代 domain invariant |
| Domain Model and Policies | 承载对象、状态、不变量和 guard | 不直接读取配置或外部正文 |
| Ports and External Seams | 表达 identity、process、work、artifact、method、runtime、conversation、bus、handoff 外部能力 | 不让外部 truth 进入本仓 |
| Persistence / Projection | 保存 truth、trace、audit、snapshot、projection 和 report | projection 不反写真相 |
| Outbox and Handoff | 传播已成立 Governance fact 和追溯 / 归档 / external GRC 交接 | 发布失败不回滚 truth |

## 5. 主要组成部分、职责与边界

> 校准来源:
> - `design-calibration/02_hld_step_05_components_boundary.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_05_components_boundary.md` 的“结构化中间产物”“各主要组成部分”和“对象发现维度表”小节。

`L1-governance` 的业务主要组成部分共 10 个:

| 组成部分 | 核心职责 | 不承担什么 |
|---|---|---|
| `Governance truth core` | 保护 Governance truth、不变量、trace、audit 和 outbox 成立边界 | 不定义相邻仓 truth、正文或生命周期 |
| `Governance context and input management` | 让 actor、scope、subject、source、purpose 和可裁决输入正式成立 | 不拥有外部对象生命周期或正文 |
| `Gate and decision management` | 形成 Gate、Decision、裁决结果、替代 / 修正和不可原地改写历史 | 不等同 process waiting、conversation card、work lifecycle 或 runtime cache |
| `Approval and responsibility management` | 表达审批、投票、授权、责任链、risk owner 和责任变化 | 不拥有 GlobalMember、role、platform auth 或 tool permission truth |
| `Policy and shared rules management` | 维护 Policy 生效事实、scope、priority、conflict、override 和 shared rules | 不拥有 AIPolicyDef、runtime policy cache 或 project local config truth |
| `Control and compliance conclusion management` | 维护 Control 适用 / 复核、AIIA / SoA 治理结论和批准 / 排除 | 不保存 ControlDefinition、standard、artifact、evidence、AIIA / SoA 正文 |
| `Nonconformity corrective loop` | 维护不符合、原因、纠正、复验、关闭和责任语境 | 不等同 bug、work blocker、runtime failure、alert 或维护备注 |
| `Governance consumption and traceability` | 提供授权查询、事实消费、审计复盘、trace / archive / external GRC 交接 | 不拥有 workspace truth、observability ledger、archive package 或 external GRC truth |
| `Derived maintenance and reconciliation` | 维护 projection、dashboard、report、snapshot refresh、reconciliation 和 export preparation | 不生成新业务事实,不批准 / 关闭 / 覆盖 truth |
| `External context mirror support` | 承载外部引用、safe summary、snapshot、stale / unresolved / invalid marker | 不保存外部正文,不替代来源仓 lifecycle |

主要组成部分之间的交互方向:

```text
+====================================================================+
|                    L1-governance component flow                    |
+====================================================================+
| Governance context and input management                            |
|       | establishes governed context and decisionable input         |
|       v                                                            |
| Governance truth core <---- Gate / Decision / Approval / Policy     |
|       ^                 Control / Compliance / Nonconformity        |
|       |                                                            |
| Consumption and traceability <---- Derived maintenance              |
|       ^                              ^                             |
|       |                              |                             |
| External context mirror support -----+                             |
+====================================================================+
```

## 7. API / 接口骨架

> 校准来源:
> - `design-calibration/02_hld_step_07_api_interface_skeleton.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_07_api_interface_skeleton.md` 的 Command、Query、Inbound Event Consumer、Outbound Event、Operations Job 骨架表和接口到主要组成部分映射。

本仓接口按读写性质分为 5 类:

| 接口类别 | 读写性质 | 主要用途 | 必须携带的上下文 | 不得做什么 |
|---|---|---|---|---|
| Command | 改写 Governance truth / history / trace / outbox | context、decision、approval、policy、control、compliance、nonconformity 的正式变化 | `ActorContext`、`CommandMetadata`、idempotency key、trace context | 不保存相邻仓正文,不绕过 policy |
| Query | 只读 | 读取 truth summary、projection、trace、snapshot 或 degraded surface | `ActorContext`、`QueryMetadata` | 不写 truth、projection、snapshot、outbox |
| Inbound Event Consumer | 写 snapshot / reference / pending input / stale marker | 承接 identity / process / work / artifact / method / runtime / conversation / observability 外部事实 | envelope、source event id、source ref、schema version、dedup key、trace context | 不直接创建裁决、Policy、Control、Nonconformity |
| Outbound Event | 输出已成立事实或维护状态 | 向相邻仓和消费面传播 Governance fact | outbox event id、truth ref、trace context | 不携带外部正文,不让下游失败回滚 truth |
| Operations Job | 后台维护 / 派生 / 对账 / 交接 / 导出准备 | publish、rebuild、refresh、reconcile、handoff、external GRC export | job metadata、system / operator actor、job idempotency key | 不作为业务 command,不静默修正 truth |

正式 Command 组包括 context / input、gate / decision、approval / responsibility、policy / shared rules、control / compliance、nonconformity。Query 组包括 context、input、decision、approval、policy、conflict、control coverage、conclusion、nonconformity、search、trace、dashboard 和 reconciliation report。Consumer、Outbound Event 和 Job 骨架按 Step 7 表继续展开。

## 8. 关键处理流 / 重要函数数据流

> 校准来源:
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_08_processing_flows.md` 的通用 Command / Query 路径、11 个处理流图和接口到处理流族映射。

关键处理流按流族组织,避免逐接口机械重复:

| 处理流族 | 覆盖接口 | 核心边界 |
|---|---|---|
| Governance Context and Input Command Flow | `CreateGovernanceContext`、`SubmitGovernanceInput`、`UpdateGovernanceInputState` | 外部 source 只能以 ref / summary / snapshot 进入 |
| Gate and Decision Command Flow | `OpenGovernanceGate`、`RecordGovernanceDecision`、`SupersedeGovernanceDecision` | Decision 不可原地改写,修正必须显式记录 |
| Approval and Responsibility Command Flow | `AssignApprovalResponsibility`、`RecordApprovalVote`、`DelegateApprovalResponsibility` | 投票和责任满足不自动形成 Decision |
| Policy and Shared Rules Command Flow | `ActivatePolicyEffectiveFact`、`UpdateSharedRuleSet`、`ResolvePolicyConflict` | Policy fact 归 Governance,shared rules 不可被低 scope 覆盖 |
| Control and Compliance Conclusion Command Flow | `AssessControlApplicability`、`RecordControlReview`、`SubmitAIIAConclusion`、`SubmitSoAConclusion` | 正文归 artifact / method,Governance 只保存结论和引用 |
| Nonconformity Corrective Command Flow | `RaiseNonconformity`、`PlanCorrectiveAction`、`VerifyNonconformity` | 关闭必须基于通过复验 |
| Authorized Governance Query Flow | 14 个 Query | Query no-write,返回 visibility / freshness / degraded surface |
| External Context Consumer Flow | 9 个 Consumer | 只写 mirror / marker / stale,不写核心 truth |
| Publish Governance Outbox Flow | outbox publish job | publisher 只复制 outbox payload snapshot,失败不回滚 truth |
| Rebuild / Refresh / Reconcile Job Flow | projection、snapshot、reconciliation jobs | 只维护 derived / reference / report,不修复 truth |
| Trace / Archive / External GRC Handoff Flow | handoff / export jobs | 只保存 marker、receipt、package ref 或 target ref |

通用 Command 写路径必须按 `inbound validation -> application service -> domain policy / object -> truth persistence -> trace / audit / outbox / stale marker -> stored result` 收口。Query 只读路径必须按 `request -> authorized query service -> read repository / projection -> response assembler` 收口,不得打开写事务。

## 9. 状态定义与状态流转

> 校准来源:
> - `design-calibration/02_hld_step_09_state_machine.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_09_state_machine.md` 的状态定义表、状态流转图、允许迁移清单、禁止迁移清单和状态传播关系。

本仓存在多个正式状态机,不是单一全局状态机:

| 状态组 | 承载对象 | 主线可消费状态 |
|---|---|---|
| Context / input readiness | `GovernanceContext`、`GovernanceInput` | `Ready`、`Accepted` |
| Gate / decision | `Gate`、`GovernanceDecision` | `PendingDecision`、`Decided`、`Approved`、`Rejected`、`Waived` |
| Approval responsibility | `ApprovalResponsibility`、`ResponsibilityChain` | `Assigned`、`Accepted`、`Voted`、`Delegated`、`Satisfied` |
| Policy / shared rules | `PolicyEffectiveFact`、`SharedRuleSet`、`PolicyConflictRecord` | `Effective`、`Active`、`Resolved`、`Waived` |
| Control / compliance | `ControlApplicability`、`ControlReview`、`AIIAConclusion`、`SoAConclusion` | `Applicable`、`NotApplicable`、`Excluded`、`Passed`、`Approved`、`Rejected` |
| Nonconformity corrective | `NonconformityRecord`、`CorrectiveAction`、`VerificationResult` | 正在纠正的非终态、`Closed`、`Passed` |
| Derived / reference / publication | `DerivedGovernanceViewState`、`ReferenceResolutionState`、`GovernanceOutboxRecord` | `Fresh`、`Resolved`、`Pending`、`Published` |

状态传播关系:

```text
+====================================================================+
|                    Governance State Propagation                    |
+====================================================================+
| Core truth command accepted                                        |
|   +--> GovernanceTraceRecord / GovernanceAuditTrail                |
|   +--> GovernanceOutboxRecord(Pending)                             |
|   +--> DerivedGovernanceViewState(Stale)                           |
|   +--> Query response freshness / visibility surface               |
|                                                                    |
| Inbound external event accepted                                    |
|   +--> ReferenceResolutionState / local snapshot state             |
|   +--> DerivedGovernanceViewState(Stale)                           |
|   +--> Consumer receipt / delayed / duplicate surface              |
|                                                                    |
| Operations job result                                              |
|   +--> OutboxPublicationState or DerivedGovernanceViewFreshnessState |
|   +--> ReconciliationReport / handoff marker / job report          |
+====================================================================+
```

禁止迁移红线包括:input accepted 不等于 decision approved;pending reference 不得进入正式裁决;responsibility voted 不自动 approve;shared rules 不可被配置降级;corrective action completed 不自动 close nonconformity;query / consumer / job 不得修改核心 truth;outbox failure 不回滚 accepted truth。

## 10. 异常与边界场景轮廓

> 校准来源:
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_10_exceptions_boundaries.md` 的异常与边界场景总览、按处理流族归类的异常口径和异常影响图。

关键异常必须落在正确边界:

| 场景 | 处理部分 | 概要口径 |
|---|---|---|
| actor、metadata、idempotency 缺失 | Inbound / application | 不进入 truth 写路径 |
| subject / source / evidence 不可解析 | Context / input、External mirror | 进入 pending / unresolved / degraded,不得直接裁决 |
| context 未 `Ready`、gate expired、decision superseded | 对应 command service | 拒绝非法迁移或保持历史状态 |
| approval responsibility 不满足 | Approval and responsibility | 不得推动 decision approved |
| policy conflict 或 shared rules 违背 | Policy and shared rules | 阻断变更或形成 conflict / pending decision |
| control / conclusion evidence 缺口 | Control / compliance | 不得 approve,保持 pending / in review / rejected surface |
| verification failed / inconclusive | Nonconformity | 不得 close,回到 correction / evidence 补充 |
| query not visible、projection stale / failed | Authorized query / derived policy | 返回 not visible / degraded / freshness surface,不写状态 |
| consumer duplicate / unsupported version / forbidden body | Consumer boundary | 不写核心 truth,只写 receipt / reference / stale marker |
| outbox / rebuild / refresh / handoff failure | Operations job | 写 publication / derived / reference / report / marker 状态,不修复 truth |

异常影响边界:

```text
+====================================================================+
|                    Governance Exception Boundary                   |
+====================================================================+
| Command exception  -> reject or pending surface, no accepted truth  |
| Consumer exception -> receipt + reference + stale marker only       |
| Job exception      -> publication / derived / report / marker only  |
+====================================================================+
```

详细错误码、retry、quarantine、dead letter、恢复脚本和测试断言由 `03-详细设计.md` 和后续测试 / 验收文档继续定义。

## 11. 配置影响轮廓

> 校准来源:
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_11_configuration_impact.md` 的配置影响轮廓表、禁止配置化边界表和配置实现契约方向。

配置只影响运行承载和外围接缝,不得改变 Governance domain invariant。

| 主要部分 / 接缝 | 是否受配置影响 | 配置影响类型 | 交给详细设计展开 |
|---|---|---|---|
| `Governance truth core` | 间接受影响 | repository / outbox / trace 承载选择 | 配置只能选择承载和接缝,不得改变 truth 成立边界 |
| context / input、approval、control、nonconformity | 间接受影响 | resolver / adapter / notification / source enablement | 定义 adapter config 和 unavailable / degraded surface |
| Gate / Decision | 禁止直接受配置影响 | 不允许配置改变状态机或 outcome 语义 | 只允许配置显化、通知或下游传播 |
| Policy / shared rules | 严格受控影响 | method snapshot adapter、runtime export adapter、refresh cadence | 不得改变 shared rules 优先级或低 scope 覆盖红线 |
| consumption / traceability | 受配置影响 | query read model、handoff target、adapter 启停 | 不得改变 visibility 和 trace truth |
| derived / reconciliation / external mirror | 受配置影响 | rebuild / refresh / reconcile scope、schedule、batch、stale threshold | 不得允许 job 修复 truth |
| command / query / consumer / job / bus / handoff adapter | 受配置影响 | endpoint enablement、page limits、schema allowlist、retry class、target adapter | 不得关闭 actor / metadata / idempotency / visibility 等门禁 |

禁止配置化边界包括 truth 归属、外部正文排除、编译依赖裁剪、Gate / Decision 正式性、Decision 不可原地改写、responsibility guard、shared rules、Policy conflict、Control evidence、AIIA / SoA 正式评审、Nonconformity closure、Query no-write、Consumer 不写核心 truth、Job 不修复 truth、派生不反写、outbox failure 不回滚 truth 和 visibility 门禁。

## 13. 设计风险与待确认事项

> 校准来源:
> - `design-calibration/02_hld_step_13_risks_open_questions.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_13_risks_open_questions.md` 的设计风险清单、设计待确认事项清单和当前设计层未闭环项说明。

### 13.1 设计风险

| 风险 | 影响 | 当前处理口径 |
|---|---|---|
| 旧 Gate / Decision / Request 教学线索回流 | 影响代码主体、组成部分、接口和处理流 | 旧线索只作历史背景,正式主线以 Step 4~12 结论为准 |
| 相邻状态或 UI / runtime / report 替代 `GovernanceDecision` | 影响 Gate / Decision、状态机、outbox 和验收红线 | Governance 拥有正式裁决;相邻仓只能提供语境、等待、显化或消费 |
| Policy / shared rules 被定义层、执行层、配置或 external GRC 反向定义 | 影响 Policy、runtime consumption、配置和安全 | Policy fact 归 Governance;定义、执行和外部系统只可引用或消费 |
| Control / AIIA / SoA 或 evidence 正文进入 Governance truth | 影响数据归属、compliance 和 handoff | Governance 只保存结论、引用、摘要和批准关系 |
| Nonconformity 退化为 bug / blocker / alert / task | 影响纠正闭环和关闭依据 | 保留原因、纠正、复验、关闭和责任语境 |
| Query / Consumer / Job / projection / report / handoff 反写真相 | 影响处理流、异常和状态传播 | 读 / 消费 / 维护路径不得写核心 truth |
| 非 `L0-core` sibling repo 成为核心编译期依赖 | 影响依赖裁剪和实现边界 | 只能通过 ref、snapshot、summary、event、port 或 handoff 协作 |
| 实现侧在详细设计缺口处自行补 schema、状态、port、产品或容量口径 | 影响 `03`~`07` 和可落码性 | 缺口必须回设计闭口,不得在实现中私补 |

### 13.2 待确认事项

| 待确认 | 影响范围 | 当前挂起口径 |
|---|---|---|
| 具体 DB、message bus、cache、search、object storage、audit store、external GRC 产品 | `04`、`07`、ADR、容量验证 | 当前只固定承载角色和产品中立边界 |
| 旧性能数字是否升级为正式 SLO | 测试方案、验收标准、容量模型 | 当前不作为硬指标 |
| 高级治理看板、Policy DSL、复杂 Gate 编排、自动 AIIA / SoA 草拟 | derived、policy、decision、artifact seam | 当前作为外围增强挂起 |
| external GRC 深度集成是否升级为双向集成 | handoff、configuration、security | 当前 external GRC 只能消费或导出 facts |
| 完整 ES / CQRS、event replay、rule engine 或 simulation 是否需要 ADR | persistence、outbox、trace、reconciliation | 当前不提前锁定范式 |
| 高风险配置变更是否需要正式 Governance decision 或 operator approval | configuration、security、operations | 当前只要求可审计和不可越界 |

待确认事项不得在 Step 14 整理时润色成已确认结论。若后续发现某个待确认事项影响 Step 4~12 主语稳定性,必须回退对应 Step 修正。

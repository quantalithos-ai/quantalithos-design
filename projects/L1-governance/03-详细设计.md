## 3. 实现约束与编码规范承接

目标实现仓采用 Rust workspace,edition 使用 Rust 2024。Rust 源码标识符、普通注释、rustdoc、错误说明和测试名默认使用英文;设计正文使用中文说明。实现仓 commit message 默认使用英文,标题采用 `type(scope): subject`;实现前必须确认项目级 `git config user.name=quantalithos-labs` 和 `git config user.email=quantalithos.ai@gmail.com`。

当前唯一允许的编译期 sibling 依赖是 `L0-core` 的 `core-contracts`:

core-contracts = { path = "../quantalithos-core/crates/contracts" }

Identity、process、work、artifact、method-library、runtime、conversation、observability、archive、bus、SDK 和 external GRC 等相邻仓或外部系统不得成为当前 Cargo path dependency。它们只能通过 event、port、adapter、snapshot、safe summary、external ref、handoff、export target、API 或 fake 测试边界表达。

| 约束 | 说明 | 影响 |
|---|---|---|

| 源码英文 | 标识符、注释、rustdoc、测试名默认英文 | Step 6 对象、Step 8 DTO、Step 16 测试 |

| 运行期 / 事件依赖隔离 | 相邻仓、bus、SDK、external GRC 不得成为 Cargo dependency | port / adapter / event / handoff / export |
| 正文排除 | 不保存相邻仓或外部系统正文 | snapshot / ref / persistence |
| 状态机红线不可配置化 | 配置不能改变 truth 边界和合法迁移 | state matrix / config |
| query / projection 不反写 | Query、projection rebuild、reconciliation、handoff、external GRC export 不写 core truth | query / job / transaction |

## 5. 模块实现契约

> 校准来源:
> - `design-calibration/03_ddd_step_05_module_contracts.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`
>
> 延伸阅读:
> - 建议继续阅读 Step 5 的“模块职责表”“文件与代码主体映射表”,Step 6 的对象字段级契约,以及 Step 7 的 trait / port / adapter 签名。

第 5 章是本文主轴。实现必须按七个模块组织,不得把所有 struct、trait、函数或 DTO 堆到一个全局文件后再由实现者自行拼装模块边界。

| 模块 | 职责 | 允许依赖 | 禁止事项 |
|---|---|---|---|
| `contracts` | 定义公共 DTO、typed ref、reason、marker、view、event、job、receipt、protocol error 和 fixtures | `core-contracts` | 不依赖 domain / application / infra;不承载领域不变量 |
| `domain` | 定义 truth 对象、value object、state、policy、不变量、trace / audit / outbox 成立对象和 domain error | `contracts`、`core-contracts` | 不读取 repository、config、HTTP、bus、DB、external SDK |
| `application` | 编排 command / query / consumer / job,管理 transaction、幂等、port 调用、outbox / trace / projection 副作用 | `contracts`、`domain`、`core-contracts` | 不依赖具体 infra adapter |
| `infra` | 实现 repository / adapter / store / config / runtime builder 和 fake runtime | `contracts`、`domain`、`application`、`core-contracts` | 不改写 domain 不变量,不替代 application service |
| `api` | 解析同步 Command / Query 请求,调用 application service,映射 error | `contracts`、`application`、`infra`、`core-contracts` | 不直接访问 repository,不直接调用 domain 业务方法 |
| `worker` | 消费入站事件、运行 outbox publisher loop、触发 projection invalidation / maintenance | `contracts`、`application`、`infra`、`core-contracts` | 不绕过 application 写 repository |
| `jobs` | 执行 outbox publish、projection rebuild、reference refresh、reconciliation、trace / archive handoff、external GRC export | `contracts`、`application`、`infra`、`core-contracts` | 不把 report、handoff receipt、external GRC export 反写成核心 truth |

### 5.1 `contracts`

`contracts` 定义 public protocol surface。所有 Command / Query / Event / Job / View / Error DTO 和二级公开类型必须在 `contracts` 或 `core-contracts` 中闭合。Command / Event / Job 中出现的 ref、reason、state-visible marker、page、visibility、freshness、receipt、report 和 schema version 不得只在 domain 或 application 本地定义。

### 5.2 `domain`

`domain` 定义 Governance truth、状态、policy 和不变量。主要对象包括 Governance context、input、gate、decision、approval responsibility、policy effective fact、shared rule set、policy conflict、control applicability、control review、AIIA / SoA conclusion、nonconformity、corrective action、verification result、reference resolution state、derived governance view state、trace / audit / outbox record。

领域对象不得读取 repository 或外部 adapter。需要外部 snapshot、capability、method policy、evidence summary、process / work governance context、runtime signal、conversation context 或 observability alert 时,由 application 通过 Step 7 port 先解析成 body-free ref / snapshot / summary,再传入 domain factory 或 transition。

### 5.3 `application`

`application` 是唯一定义 repository、resolver、publisher、handoff、UnitOfWork、Clock、IdGenerator、idempotency 和 stored result trait 的模块。所有 accepted command / consumer / job mutation 必须在 application service 内编排 validate、reserve idempotency、load versioned truth、domain transition、save truth、通过 `GovernanceTruthChangeSubjectMapper` 映射同源的 trace / audit / outbox accepted subject refs、通过同一 `GovernanceUnitOfWork.assign_truth_change_cursor()` 分配 accepted truth boundary cursor、append trace / audit / history、append outbox、mark projection stale、save stored result / receipt / report、commit transaction。

Query service 必须 no-write,只加载 truth / projection / trace / report,执行 visibility / freshness / degraded 判断并返回 query response。

### 5.4 `infra`

`infra` 实现 application port。fake adapter 必须遵守 repository version、duplicate replay、projection stale、reference refresh、outbox payload snapshot、handoff marker 和 error mapping 语义;不得因为是 fake 就跳过正式状态或事务口径。durable adapter 的具体 DB / bus / search / object storage 产品不在本文锁定。

### 5.5 `api` / `worker` / `jobs`

`api`、`worker`、`jobs` 都是入口模块。它们只解析 contracts DTO、准备 metadata / operation context、调用 application facade / service 并映射错误。它们不得直接拼写 truth id、直接写 repository、绕过 stored result、绕过 outbox snapshot 或自行构造 projection view ref。

### 7.3 Inbound / Outbound Event

Inbound consumers cover 9 external change surfaces: identity actor capability, process governance context, work governance context, artifact evidence, method policy definition, method control definition, runtime signal, conversation context and observability alert. Inbound event accepted path writes local snapshot / reference state / stale marker / receipt;unsupported schema version enters dead-letter or rejected disposition as defined in Step 12.

## 8. 逐接口函数级处理流

> 校准来源:
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的 §7~§20,获取每个 Command、Query、Consumer、Outbox publish 和 Job 的函数级调用链、事务边界和异常分支。

Step 9 为 23 个 Command、14 个 Query、9 个 Inbound Consumer、13 个 Outbound Event publish path 和 7 个 Operations Job 定义了函数级处理流。实现不得把同构模板泛化成无法回指单个接口的黑盒 flow。

### 8.1 Command accepted transaction template

```text
validate command request
reserve idempotency
begin unit of work
load versioned truth and required snapshots
call domain factory or transition
save truth with expected version
append trace / audit / history
build and append outbox payload snapshot
mark affected projections stale
save stored command result
commit unit of work
return command response
```

Command 可跳过不适用的 history record,但不得改变 truth、trace、outbox、projection stale 和 stored result 的相对语义。id、time、version、snapshot、visibility 和 outbox source identity 都必须来自 Step 7 / Step 11 定义的正式读取面或生成面。

### 8.2 Query read template

```text
validate query request
authorize read and compute visibility decision
load truth or projection through repository
compute freshness / degraded / missing / failed status
redact according to read visibility and protocol rules
return query response without write transaction
```

Query 不开启写事务。任何 query-time 发现的不一致只能通过 degraded / stale / failed / missing surface 表达,不得修复 truth、projection、reference snapshot、outbox 或 report。

### 8.3 Consumer template

```text
validate event envelope and schema version
reserve event idempotency
resolve body-free source snapshot or marker
begin unit of work
upsert local reference or snapshot state
mark affected projections stale
save consumer receipt
commit unit of work
return receipt disposition
```

Consumer 不保存外部正文,不把外部 event 当成本仓 truth mutation command。重复 event 读取 stored receipt 并返回;unsupported version 进入正式 rejected / dead-letter / delayed surface。

### 8.4 Job / outbox / handoff template

Operations job 必须使用 job metadata、page / batch cursor、stored report 和 duplicate replay。Outbox publish path 只读取 pending outbox record 及 stored payload snapshot,发布结果按 expected version 更新 publication state。Handoff / export job 只写 handoff / export marker、report 或 receipt,不得把下游接收状态改写为 Governance truth。

## 9. 状态机与转换矩阵

> 校准来源:
> - `design-calibration/03_ddd_step_10_state_matrix.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的 §8~§18,获取每个状态 enum 的 allowed / forbidden 转换、触发方、错误和测试入口。

状态集合、合法迁移、非法迁移错误和副作用由 Step 10 固定。实现不得用字符串状态、口语状态、测试专用状态或配置项替代正式 enum。

| 状态族 | 主要状态对象 | 实现规则 |
|---|---|---|
| context / input / decision | `GovernanceContextState`、`GovernanceInputState`、`GateState`、`GovernanceDecisionState` | command transition 才能改变 truth;query 不修复状态 |
| approval / responsibility | `ApprovalResponsibilityState`、`ResponsibilityChainState` | vote / delegation / assignment 必须受 actor capability snapshot 和 responsibility policy 约束 |
| policy / shared rules / conflict | `PolicyEffectiveState`、`SharedRuleSetState`、`PolicyConflictState` | low-scope policy 不得覆盖 organization hard constraint |
| control / compliance / corrective | `ControlApplicabilityState`、`ControlReviewState`、`ComplianceConclusionState`、`NonconformityState`、`CorrectiveActionState`、`VerificationState` | conclusion、cause、action、verification 必须保持纠正闭环顺序 |
| derived / reference / outbox / report / handoff | `DerivedGovernanceViewFreshnessState`、`ReferenceResolutionKind`、`OutboxPublicationState`、`ReconciliationReportState`、`GovernanceHandoffState`、`GovernanceJobReportState` | marker / report / handoff 状态不得反写真相 |
| technical state | idempotency、adapter availability、runtime build、API / worker / job disposition states | 技术状态只控制执行与返回 surface,不替代 business state |

所有 forbidden transition 必须返回正式 domain / application error,并在 Step 16 对应状态测试中覆盖。状态迁移若需要外部 snapshot、policy summary 或 evidence marker,必须由 application 先加载正式对象再调用 domain transition。

## 10. 数据持久化、事务与一致性契约

> 校准来源:
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的 §8.1~§8.27,获取 logical store、repository 函数语义、transaction ordering、version / cursor 规则和 persistence schema。

Governance owns its truth、local snapshot / reference state、trace / audit / history、outbox、projection freshness、reconciliation report、handoff marker、idempotency 和 stored result / receipt / report。相邻仓正文、external GRC truth、archive body 和 observability body 不属于本仓持久化 truth。

| Store 类别 | 写入规则 | 读取规则 |
|---|---|---|
| truth store | command accepted transaction 内写入,使用 expected version | mutation 前必须 `get_*_with_version` |
| trace / audit / history | accepted mutation 或 consumer / job marker append-only 写入 | query / handoff / reconciliation 可分页读取 |
| projection store | command / consumer / refresh mark stale;job rebuild replace view | query 读取 freshness / degraded / failed surface |
| reference snapshot store | consumer / refresh upsert reference state and snapshot summary | refresh scope 和 query degraded 判断使用正式 list / get |
| outbox store | command transaction 内 append record and stored payload snapshot | publisher 读取 pending record + stored snapshot |
| idempotency / result store | reserve、complete、stored result / receipt / report 与 transaction 一致 | duplicate replay 必须读取 stored surface |
| handoff / export marker store | handoff / export job 写 marker / receipt / report | duplicate / retry 根据 marker state 执行 |

核心一致性规则:

- Cursor 不得当 optimistic version 使用。
- 所有修改已有 state 的写路径必须使用正式 version 来源或 Step 11 明确的 append-only / upsert 语义。
- Accepted command 的 truth、trace、audit/history、outbox、projection stale、stored result 必须在同一 UoW 内按 Step 9 顺序提交。
- Accepted command 的 `GovernanceTruthChange.subject_ref`、`GovernanceTraceRecord.subject_ref` 和 `GovernanceAuditTrail.subject_ref` 只能由 `GovernanceTruthChangeSubjectMapper` 从 typed truth ref 映射,三者必须包装同一个 canonical key,格式为 `governance:<truth-kind>:<id>`;不得拼 `ExternalSourceRef` 字符串、route path、title、topic 或外部正文。
- `RecordControlReview` accepted flow 必须使用 `GovernanceTruthChangeSubjectMapper.control_review_subjects(review_ref)` 和 `ControlReviewChangedPayload`;不得复用 `control_applicability_subjects(applicability_ref)` 或 `ControlApplicabilityChangedPayload` 表达 review truth。
- Accepted command 更新 `GovernanceAuditTrail` 时必须先用 `GovernanceAuditHistoryRepository.get_audit_trail_by_subject_with_version(audit_subject_ref)` 按 `GovernanceAuditSubjectRef` 唯一键读取既有 trail 和 version;存在则 append trace 后以 `Some(version)` 保存,不存在才用 `new_audit_trail_id()` + `GovernanceAuditTrail.start_for_subject(...)` 创建并以 `None` 保存;不得从 `audit_subject_ref` 推导或拼接 `GovernanceAuditTrailRef`。
- Accepted command 的 `GovernanceTruthChange.source_cursor` 只能来自同一 UoW 在 truth save 已成功 staged 后分配的 committed truth boundary cursor;不得用 page cursor、optimistic version、timestamp、id generator、trace id 或 hard-coded string 代替。
- Outbox publisher 不现查 current truth 拼 payload,只发布 stored payload snapshot。
- Projection rebuild、reference refresh、reconciliation、handoff 和 export job 不反写 core truth。

## 11. 错误模型、异常分支与恢复口径

> 校准来源:
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的 §6~§19,获取错误层级、错误映射、异常分支、恢复口径、dead-letter 和反模式。

错误模型分为 domain error、application error、port / infra error、protocol / worker / job surface。实现不得使用泛化 string error 替代正式错误 enum 或 disposition。

| 场景 | 正式处理 |
|---|---|
| invalid request / missing required metadata | protocol reject,不进入 mutation |
| domain forbidden transition / policy reject | domain error -> application reject / conflict |
| repository version conflict | application conflict,rollback UoW |
| query not visible | 返回 query not visible surface 和 visibility marker |
| query missing / stale / degraded / failed | 返回正式 status,不修复 truth |
| inbound unsupported schema version | rejected / dead-letter disposition |
| external resolver unavailable | delayed / degraded / failed marker,不得保存正文 |
| outbox publish failure | mark failed / retry marker,不修改 truth |
| job partial failure | stored job report with failed refs / diagnostics refs |
| commit status unknown | 按 Step 13 recovery 读取 stored result / idempotency / truth state |

Forbidden field、external body、secret、token、raw artifact、conversation body、method body、runtime body 和 external GRC body 不得进入 log、audit、trace、outbox、report 或 safe diagnostic ref 之外的持久化 surface。

## 12. 并发、幂等与重入保护

> 校准来源:
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的 §8~§17,获取并发场景、幂等 key、canonical digest、重复处理矩阵和 commit unknown 口径。

Command、Consumer 和 Job 都必须先 reserve idempotency,再进入 mutation 或 marker 更新。Duplicate replay 读取 stored command result、consumer receipt 或 job report;不得重新运行 mutation。Idempotency conflict 必须比较 canonical request digest,不能只比较 operation name 或 business ref。

| 协议 / 场景 | 幂等键来源 | 重复处理 |
|---|---|---|
| Command | `CommandMetadata` idempotency key + canonical request digest | 返回 stored command result |
| Inbound Event | event id / source event ref / schema version / consumer namespace | 返回 stored consumer receipt |
| Operations Job | job metadata idempotency key + input digest | 返回 stored job report |
| Outbox publish item | outbox record version + publication state | item-level marker 防重 |
| Projection rebuild | projection set + scope + cursor / snapshot version | replace view with versioned marker |
| Reference refresh | reference ref + state version + scope | versioned upsert / failure marker |
| Handoff / export | handoff / export target + trace / scope + idempotency key | marker state + stored report replay |

Commit status unknown 时,实现必须通过 idempotency record、stored result / receipt / report、truth state、outbox record 或 marker state 重建结果;不得盲目重跑 accepted mutation。

| `core-contracts` baseline 可能不匹配 | 阻塞依赖 core shared type 的代码 | 开工前检查 core baseline;缺失即暂停 |
| durable DB / broker / search / HTTP 产品未锁定 | 不阻塞 P0 fake;阻塞 production adapter | P0 使用 in-memory / fake;产品化前由配置 / 实施 / ADR 固定 |
| metric backend、DLQ、diagnostic store 未锁定 | 不阻塞埋点契约;阻塞真实运维 evidence | 实现安全字段、marker 和 fake disposition |
| 真实相邻仓 runtime adapter 未全部可用 | 不阻塞 P0 truth center;阻塞 integration evidence | 使用 fake / fixture / stub,真实 adapter 后续 phase 接入 |
| external GRC 产品和导出格式未锁定 | 不阻塞 P0 disabled / fake;阻塞真实 export | 默认 disabled / fake,不写死产品格式 |

未确认前处理规则:

- 正式下游文档未同步时,不把旧测试、验收、配置或 phase 口径交给实现者。
- 实现仓未确认时,不写代码、不提交实现仓 commit。
- 字段 / DTO / 状态 / flow 缺口出现时,暂停并回写对应 design Step,不得在代码中补 placeholder。
- 上游 typed contract 缺失时,暂停对应代码,不得复制上游类型。
- 运行期依赖不可用时,使用 fake / fixture / stub,并保留正式 failure / marker 语义。

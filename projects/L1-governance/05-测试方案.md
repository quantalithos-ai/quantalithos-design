### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 governance 的接口可调用,而是系统验证 `L1-governance` 是否真正满足“治理决策真相仓”的设计要求,尤其要证明以下几点成立:
- GovernanceRequest / Gate / Decision / RiskAcceptance 构成正式治理真相层
- `request ≠ decision`、`waiting_gate ≠ decision`、`gate turn ≠ decision` 三条核心边界成立
- approver chain / delegated authority / eligibility 形成正式审批资格约束
- `exception / waiver / risk acceptance` 独立成立,不会退化成普通 approve
- emitted result 由 governance 统一输出,process / work / conversation / runtime 消费同一正式结论语义
- drift 可检测、可 replay,而且 replay 修复的是传播链,不是伪造新 decision

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 治理请求与 Gate 主语部分 | 真相对象 | P0 | request、Gate、target ref、request 状态 |
| 决策与裁决真相部分 | 真相对象 | P0 | approve / reject / request_change / waive / accept_risk |
| 责任链与审批关系部分 | 规则对象 | P0 | approver chain、delegation、eligibility |
| 例外、豁免与风险接受部分 | 例外裁决 | P0 | risk acceptance / waiver / exception |
| 治理审计与下游通知接缝部分 | 输出/审计链 | P0 | emitted result、audit trail、drift / replay |
| conversation 前端视觉细节 | 非范围 | P2 | 只验证 notification input,不验 UI 组件 |
| artifact 正文语义充分性本体 | 非范围 | P2 | 只验证 governance 如何消费 refs,不验 artifact 内部正文逻辑 |
| process / work / runtime 内部状态机正文 | 非范围 | P2 | 只验证 governance 输出结果接缝,不验下游内部全部实现 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和局部不变量 | domain / policy owner | `request.validate_enter_governance`、`request.ensure_open_for_decision`、`eligibility.ensure_can_decide`、`acceptance.validate_boundary`、`Decision::from_request` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + audit + emit 联动 | backend / domain owner | `RaiseGovernanceRequest`、`CheckApproverEligibility`、`DecideGate`、`RequestChange`、`RejectDecision`、`RecordRiskAcceptance`、`RecordWaiver`、`EmitDecisionResult` | request、decision、例外、输出链同时成立 |
| 事件链测试 | 验证上游输入与下游输出的完整治理链 | integration / platform owner | process waiting_gate、work gated action、artifact evidence refs、identity capability 输入；emitted result 到 process/work/conversation/runtime 的输出 | 输入与输出语义一致 |
| 恢复专项测试 | 验证 emitted result 失败、drift、replay、audit rebuild | architecture / QA | partial emit failure、replay emitted result、audit trail replay | 真相不丢失、传播链可恢复 |
| 审计一致性测试 | 验证 request→decision→exception→emission→audit 可回放 | backend / QA | decision history、risk acceptance 单独审计、replay chain | 审计链完整且可追溯 |
| 端到端主线测试 | 验证最小治理闭环 | QA / owner | waiting_gate → approve → process resume；work gated action → reject/request_change；risk acceptance → controlled continue | 主干治理闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| request 与 decision 分层 | Raise request 后再独立 DecideGate | 集成测试 | 是 | DB / API / audit log |
| waiting_gate 不等于 decision | waiting_gate 进入后若无 decision 不得继续 | 事件链 + 集成测试 | 是 | process signal / request state |
| gate turn 不等于 decision | conversation 通知不能替代正式 decision | 边界专项测试 | 是 | notification trace / decision record |
| approver eligibility 成立 | 无资格 actor 不可决策 | 单元 + 集成测试 | 是 | eligibility result / error code |
| required approver 不全不可 approve | all-of / chain completeness 成立 | 集成测试 | 是 | audit / decision refusal |
| evidence ref 不等于 basis 充分 | evidence 不足时进入 request_change / waiting / reject | 集成 + 事件链测试 | 是 | rationale / basis trace |
| risk acceptance 独立成立 | accept_risk 不退化成普通 approve | 集成测试 | 是 | risk_acceptance record / decision action |
| emitted result 统一输出 | process / work / conversation / runtime 消费统一结论 | 事件链测试 | 是 | emitted result compare |
| drift 可 replay | 部分下游未消费后可重放修复 | 恢复专项测试 | 是 | replay log / consistency compare |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local DB / fake policy / fake publishers | debug logging / replay enabled | 容易只测 approve happy path |
| test | CI / 集成测试 | test DB / controlled event bus / deterministic emit adapter | isolated tables / fixed request fixtures | 资格链和证据样本不足 |
| staging | 端到端演练 | real-like process/work/conversation/runtime/artifact/identity wiring | emitted result replay / audit compare enabled | 多下游解释差异放大 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | RaiseGovernanceRequest 创建标准 request | target ref / request kind 合法 | RaiseGovernanceRequest | request + gate 创建成功 |
| TC-002 | 无效 target ref 被拒绝 | target ref 缺失/不合法 | RaiseGovernanceRequest | 返回请求错误 |
| TC-003 | 无资格 approver 无法 DecideGate | actor 无 capability 或不在 chain 中 | DecideGate | 返回 `GOVERNANCE_APPROVER_NOT_ELIGIBLE` |
| TC-004 | required approver 不全时不可 approve | chain 缺少必要 approver | DecideGate | 返回 `GOVERNANCE_REQUIRED_APPROVER_MISSING` |
| TC-005 | evidence 充分时 approve | request open + basis 足够 | DecideGate(approve) | Decision(action=Approve) |
| TC-006 | evidence 不足时 request_change | request open + evidence 不足 | RequestChange | Decision(action=RequestChange) |
| TC-007 | request 已 closed 后不可重复决策 | request.status=closed | DecideGate | 返回 `GOVERNANCE_REQUEST_ALREADY_CLOSED` |
| TC-008 | risk acceptance 缺 acceptor/scope/rationale 被拒绝 | acceptance 边界不完整 | RecordRiskAcceptance | 返回 scope/boundary 错误 |
| TC-009 | risk acceptance 成功并发出 controlled continue | acceptor / scope / rationale 完整 | RecordRiskAcceptance | risk_acceptance + accept_risk decision 成立 |
| TC-010 | waiver/exception 独立成立 | normal no 场景 | RecordWaiver | ExceptionDecision 成立 |
| TC-011 | emitted result 发给 process/work/conversation/runtime | 已 committed decision | EmitDecisionResult | 多下游消费统一语义 |
| TC-012 | emitted result 部分失败后 replay | 某一 target_domain 故障 | emit → replay | drift 修复,下游重新一致 |
| TC-013 | gate turn 只是通知,不替代 decision | conversation 收到通知输入 | consume notification | decision 真相仍只在 governance |
| TC-014 | waiting_gate 只是等待,不替代 decision | process waiting_gate entered | no decision yet | process 不能默认继续 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | request/decision 混层 / waiting_gate 替代 decision / risk acceptance 边界失效 / 下游绕过 governance | 阻断放行,必须修复 |
| A | 主线可跑但 emitted result / audit / delegation / evidence 分支不稳 | 原则上修复后再放行 |
| B | 非关键历史视图、通知材料或低优先级查询异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 request / Gate 入口逻辑,都必须回归 `RaiseGovernanceRequest` 主线
- 每次改动 approver chain / delegation,都必须回归 eligibility 与 required approver completeness
- 每次改动 decision 分支,都必须回归 approve / reject / request_change / waive / accept_risk 五类动作
- 每次改动 emitted result,都必须回归 process / work / conversation / runtime 多下游一致性
- 每次改动 replay / audit,都必须回归 drift detection 与 replay 修复链

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 多 approver 策略若后续从 all-of 扩展到 ordered chain | 测试矩阵需扩充 | TL / 架构 |
| delegated authority 若继续细化 | eligibility / exception 测试需增加更多分支 | governance + identity |
| emitted result 下游越来越多 | replay / drift 对账样本需扩容 | Owner / TL |

## 2. 本步目标

定义最终验收结论只能如何表达、何时允许进入下一阶段、哪些角色需要签署、签署是否代表风险接受。

本 Step 只回答:

- 最终结论只能是通过、有条件通过、不通过。
- 各结论与 P0 门禁、VETO、缺陷、risk acceptance 的关系。
- 哪些签署角色必须确认哪些内容。
- 签署和风险接受的边界。

本 Step 不填写真实结论,不代表当前 L1-governance 已通过或未通过。

## 4. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 结论只能有哪些取值? | 只允许“通过”“有条件通过”“不通过”。禁止“基本通过”“原则上通过”“大体没问题”等模糊结论。 |
| 何时允许进入下一阶段? | 全部 P0 门禁通过、VETO 未命中、S 级为 0、证据完整时可进入;若仅有已接受 residual,可有条件进入。 |
| 何时允许发布准备? | 必须通过或有条件通过,且条件不影响 P0 truth、安全、证据、配置和依赖红线。 |
| 哪些角色必须签署? | 至少 Owner / 产品或业务负责人、架构负责人、测试负责人、实施负责人、运维/安全或合规负责人按职责签署。 |
| 签署是否代表风险接受? | 不是自动代表。风险接受必须在 `reports/acceptance/risk-acceptance.md` 中逐项由接受人确认;最终签署只确认验收结论和已接受风险清单。 |

## 8. 结构化中间产物

### 8.1 最终结论表

| 维度 | 结论 | 说明 |
|---|---|---|
| 全部 P0 门禁通过、VETO 未命中、S=0、证据完整、无未接受 A 级 | 通过 | 可进入下一阶段或发布准备 |
| P0 主线成立、VETO 未命中、S=0、证据完整,但存在已接受 A/B/R residual | 有条件通过 | 可进入下一阶段,但必须跟踪条件和截止 |
| 任一 P0 门禁失败、VETO 命中、S 未关闭、证据不可裁决、redaction/dependency/report audit failed | 不通过 | 必须修复并复验 |
| 缺 run_id、缺 baseline、缺 evidence index、缺 raw artifact/report pair | 不通过或暂停验收 | 不得填写通过或有条件通过 |

### 8.2 结论判定矩阵

| 条件 | 通过 | 有条件通过 | 不通过 |
|---|---|---|---|
| P0 AC-GOV 门禁 | 全部通过 | 全部通过 | 任一失败 |
| VETO-GOV-001~013 | 全部未命中 | 全部未命中 | 任一命中 |
| S 级缺陷 | 0 | 0 | >0 |
| A 级缺陷 | 0 | 已接受且不影响 P0 truth | 未接受或影响 P0 truth |
| B/R residual | 0 或不影响 | 已记录接受 | 未记录且影响结论 |
| evidence integrity | 完整 | 完整 | 缺失 / 伪造 / failed |
| P1/P2 unavailable | 不适用或无影响 | 已记录 residual | 被错误写成 P0 pass/fail |

正式 `06-验收标准.md` §14 应回填:

- 最终结论只允许“通过”“有条件通过”“不通过”。
- 通过要求全部 P0 门禁通过、VETO 未命中、S=0、证据完整且无未接受 A 级缺陷。
- 有条件通过只允许 P0 主线成立且 residual 已被逐项接受;VETO/S 不得有条件通过。
- 不通过适用于任一 P0 门禁失败、VETO 命中、S 未关闭、证据不可裁决或 hard gate failed。
- 签署不自动接受风险;风险必须在 `reports/acceptance/risk-acceptance.md` 逐项记录。

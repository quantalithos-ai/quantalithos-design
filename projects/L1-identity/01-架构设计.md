## 1. 业务背景与驱动力

### 1.1 业务背景

Quantalithos 的核心设定不是"临时 Agent",而是**有身份的 AI 员工**。员工必须具有:
- 持续存在的身份(GlobalMember)
- 职业 / 能力 / 生涯路径(Role / Capability / career_history)
- 可归档的记忆引用(semantic / episodic memory refs)
- 可被审计的生命周期(hired / active / paused / retired / tombstoned)

L1-identity 是承载这套语义的唯一仓。没有它,work / conversation / runtime / governance 会各自维护身份碎片,导致责任链断裂。

### 1.2 业务驱动力

**业务驱动力**:
- `product/最终目的.md` §3.2 明确"员工是有身份的个体"
- 42001 / 9001 需要角色和责任链可追溯
- 产品叙事要求"成长中的成员",不是一次性进程

**技术驱动力**:
- 双层 Member 模型(GlobalMember / ProjectMember)需要严格边界
- memory 持久化位置已由 ADR-0006 锁定,需要 identity 提供 ref 承载
- method-library 的 RoleDefinition 要有运行时索引落点

### 1.3 成功标准(可量化)

| 维度 | 指标 | 目标值 | 测量 |
|---|---|---|---|
| 生命周期完整性 | hired→active→paused/retired→tombstoned | 100% 按状态机执行 | 状态机测试 |
| Role 索引同步 | method_library.role_definition.published → identity.role.catalog_updated | < 5s | 集成测试 |
| 读性能 | P95 读 | < 50ms | benchmark |
| 写性能 | P95 写 | < 200ms | benchmark |
| 事件联动 | 下游 5 仓消费成功率 | 100% | E2E |

## 2. 约束条件

### 2.1 不可变约束(必须遵守)

| 约束 | 来源 | 影响 |
|---|---|---|
| GlobalMember 是聚合根 | ADR-0004 | 本仓不持有 ProjectMember |
| Role 内容在 method-library,本仓只存索引 + 生命周期元数据 | `domain/identity/README.md` §1.2 | 不在本仓存 RoleDefinition 正文 |
| semantic / episodic memory 只存 ref | ADR-0006 | 不在本仓存向量 / 原文 |
| career_history append-only | `domain/identity/README.md` INV-4 | 历史不可改 |
| tombstoned 单向 | INV-2 | 终态不可恢复 |
| Rust + PostgreSQL + axum + sqlx | ADR-0003 | 技术栈锁定 |

### 2.2 可变约束

| 约束 | 当前值 | 可调整空间 |
|---|---|---|
| 向量库 | Qdrant / pgvector 候选 | 只要 ref 契约不变可换 |
| full-text | PostgreSQL tsvector | 可后续换 OpenSearch |
| UI 身份展示 | Console / Chat | 只要 ViewProfile 接口稳定可演进 |

### 2.3 容量规划

| 资源 | 上限 | 量化依据 |
|---|---|---|
| 活跃 Member | 10w | `projects/L1-identity/README.md` 既定目标 |
| career entries | 50w | 每 Member 平均 5 项目 |
| role catalog | < 500 | Role 是稀缺对象 |
| memory refs | per Member < 100 | 项目级 episodic refs |

## 3. 架构风格与选型

### 3.1 变化维度识别

| 维度 | 变化频率 | 应对策略 |
|---|---|---|
| RoleDefinition 发布 / 退役 | 中 | spec_source + fingerprint 索引 |
| CareerEntry 增长 | 高频 append | append-only 表 + 分离 career_entries |
| Memory provider 切换 | 中 | ref 抽象,只存 URI / handle |
| 生命周期动作 | 中 | 明确状态机 + 事件驱动同步 |

### 3.2 架构风格决策框架

**候选风格**:

| 风格 | 优势 | 劣势 | 适用性 |
|---|---|---|---|
| **聚合驱动 + 事件编织**(当前)| 与六域模型一致,边界清晰 | 需要事件一致性治理 | ✅ 最匹配 |
| 纯 CRUD 服务 | 开发快 | 无法承载状态机 / append-only / audit | ❌ 不够表达身份语义 |
| event-sourced 全量事件溯源 | 审计最强 | 实现复杂,超出当前需求 | ⚠️ 过重 |

**最终选择**:**聚合根(GlobalMember / Role)+ append-only CareerEntry + 事件驱动同步**

### 3.3 约束-收益分析

| 约束 | 收益 | 成本 |
|---|---|---|
| ProjectMember 不在本仓 | 双层边界清晰 | 需要跨域同步事件 |
| career_history append-only | 审计强、成长轨迹清楚 | 查询模型稍复杂 |
| memory 只存 ref | 仓边界稳定,不绑底层向量库 | 调试时要跳转外部系统 |

## 4. 系统边界与上下文

### 4.1 系统上下文图(C4 Context 级)

```
┌───────────────────────────────────────────────────────────┐
│                     quantalithos-identity                  │
│                 employee identity source of truth          │
└──────┬───────────────┬──────────────┬─────────────────────┘
       │               │              │
       ▼               ▼              ▼
 method-library      work         member-service
 RoleDefinition      ProjectMember 容器启停
 spec_source         career sync   role / lifecycle sync
       │               │              │
       ▼               ▼              ▼
 conversation      governance      archive / observability
 participants      actor chain     tombstone / audit
```

### 4.2 职责边界(做什么 / 不做什么)

**做什么**:
- ✅ GlobalMember 聚合 CRUD + 生命周期状态机
- ✅ Role 聚合索引与生命周期元数据
- ✅ CapabilityProfile 声明与更新
- ✅ career_history append-only
- ✅ semantic / episodic memory ref 存储
- ✅ 身份事件发布(identity.member.* / identity.role.*)

**不做什么**:
- ❌ ProjectMember(work)
- ❌ RoleDefinition 正文(method-library)
- ❌ 容器编排(member-service)
- ❌ 对话推送(conversation)
- ❌ 事件审计落库(observability)

### 4.3 外部系统可用性约束

| 外部依赖 | SLA | 降级 |
|---|---|---|
| PostgreSQL | 99.95% | 无(身份服务不可用则阻断) |
| method-library | 99.9% | Role 索引短时陈旧可接受 |
| vector store | 99.9% | memory ref 可延迟更新 |
| bus | 99.95% | Outbox backlog 短时积压可接受 |

### 4.4 关键依赖风险

- RoleDefinition 漂移 → source_drift
- member-service 接收 lifecycle 事件延迟 → 容器状态不同步
- tombstone 后下游未清缓存 → 旧身份残留

## 6. 容器/部署架构

### 6.1 容器图(C4 Container 级)

```
┌──────────────────────────────────────────────────────────────┐
│                  quantalithos-identity                       │
├──────────────────────────────────────────────────────────────┤
│  API / gRPC entry                                            │
│      │                                                       │
│      ▼                                                       │
│  application layer                                           │
│      │                                                       │
│      ▼                                                       │
│  domain(GlobalMember / Role / Career / MemoryRef)            │
│      │                          ▲                             │
│      ▼                          │ subscriptions               │
│  PostgreSQL + outbox ───────────┼──────────────▶ bus          │
│      │                          │                              │
│      ▼                          │                              │
│ observability tap          method-library / work events      │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 每个容器的职责与技术栈

| 容器 / 进程 | 职责 | 技术栈 |
|---|---|---|
| identity-api | gRPC/HTTP 入口 | Rust + axum/tonic |
| identity-domain | 聚合规则 | Rust |
| identity-db | 主库 | PostgreSQL |
| outbox worker | 发事件 | Rust |
| subscriptions | 消费 work / method-library 事件 | Rust |

### 6.3 通信方式与选择理由

| 场景 | 选择 | 理由 |
|---|---|---|
| 下游仓调 identity | gRPC / proto | 类型明确 |
| identity → 下游仓 | 事件 | 六域平权 + 最终一致 |
| memory provider 对接 | ref 级 RPC | 不绑定底层存储 |

### 6.4 数据存储归属

| 数据 | 写入方 | 读取方 |
|---|---|---|
| `global_members` | identity | identity / read-only consumers via RPC |
| `roles` | identity(索引)| identity |
| `career_entries` | identity(由 work 事件驱动 append)| identity |
| `identity_events_outbox` | identity | outbox worker |

### 6.5 部署拓扑

- 单仓单服务部署
- PostgreSQL 主从或单节点均可(视环境)
- Outbox worker 默认内嵌同进程

## 7. 依赖方向与层间约束

### 7.1 依赖方向图

```
api / rpc
   │
   ▼
application
   │
   ▼
domain (GlobalMember / Role)
   ▲
   │ interfaces / ports
infra (pg / bus / observability / vector-ref adapter)
```

### 7.2 层间约束规则

- domain 不直接依赖 infra
- application 编排用例,不持久化具体细节
- subscriptions 只调 application / domain 公开用例,不直接改 DB
- role spec_source 只存索引,不拉取正文内容入库

### 7.3 依赖倒置的接口点

| 接口 | 定义位置 | 实现位置 |
|---|---|---|
| RoleCatalogSync | domain/application | infra subscriber |
| MemoryRefStore | domain | infra adapter |
| AuditPublisher | application | infra bus/outbox |

### 7.4 依赖健康度评估

| 指标 | 当前预期 |
|---|---|
| 传入耦合 | 高(5 仓直接消费事件 / RPC) |
| 传出耦合 | 中(method-library / bus / pg / vector ref) |
| 不稳定性 | 中 |
| 抽象度 | 中高(domain 纯,infra 隔离) |

## 8. 数据所有权与一致性策略

### 8.1 数据所有权矩阵

| 数据 | 拥有者 | 消费者 | 一致性策略 | 风险 |
|---|---|---|---|---|
| GlobalMember | identity | work/member-service/... via RPC/event | 聚合内强一致 | 无 |
| Role 索引 | identity(同步自 method-library)| identity / read-only 下游 | 最终一致 | source drift |
| CareerEntry | identity(append) | audit / owner | append-only + 最终一致 | 顺序延迟 |
| Memory refs | identity | runtime / archive | ref 最终一致 | provider 失效 |

### 8.2 一致性层次

- 聚合内:GlobalMember / Role 本地事务强一致
- 聚合间:career_history / role sync / memory ref 更新通过事件最终一致
- 跨服务:不做 2PC,靠 Outbox + 订阅方幂等

### 8.3 补偿机制设计

| 场景 | 补偿 |
|---|---|
| method-library 事件迟到 | 重放事件 + fingerprint 对账 |
| career append 失败 | work 事件重放 |
| memory ref provider 故障 | 允许空 ref + 后台重试 |

## 12. 演进路线

### 12.1 当前状态与已知债务

| 债务项 | 影响 | 优先级 |
|---|---|---|
| vector provider 未定 | 只影响 memory ref adapter | P1 |
| UI 中同名成员展示策略未定 | Console / Chat 用户体验 | P2 |
| tombstone 延迟期未定 | 合规策略待治理域确认 | P1 |

### 12.2 触发条件

| 指标 | 阈值 | 动作 |
|---|---|---|
| 活跃成员 > 10w | 1 周持续 | 评估读优化 / 分库 |
| role.source_drift 事件 > 3 / 月 | 1 月 | 增加 reconciliation worker |
| career_entries > 1e7 | 1 月 | 评估 archive/cold table |

### 12.3 演进步骤

```
阶段 1: GlobalMember / Role / Career 基础落地
阶段 2: Role 索引自动同步 + source drift 对账
阶段 3: memory ref provider 统一接口
阶段 4: tombstone / archive 深度联动
```

### 12.4 目标架构

目标不是把身份域做成"万能员工中心",而是成为:
- 语义清晰的身份单一真相源
- append-only 审计友好的成长轨迹仓
- 通过事件与其他域解耦的稳定锚点

## 13. 风险与待确认事项

### 13.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| role 索引与 method-library 漂移 | 中 | 高 | fingerprint + source_drift |
| career_history 顺序错乱 | 中 | 中 | append-only + trace_id |

- secondary_roles 与 role change 并发冲突
- memory provider 切换导致旧 ref 无法解析
- 一个 Member 在大量并发项目中的 career history 爆炸增长

|---|---|---|

| capability 是否允许自由文本扩展 | N1 前 | identity + method-library |
| semantic / episodic ref 的 URI 规范 | N1 前 | identity + archive |

## 1. 业务背景与驱动力

### 1.1 业务背景

Quantalithos 的核心设定不是"临时 Agent",而是**有身份的 AI 员工**。员工必须具有:
- 持续存在的身份(GlobalMember)
- 可运行的角色索引(RoleCatalogEntry,引用 method-library 的 RoleDefinition)
- 结构化能力画像(CapabilityProfile + evidence refs)
- append-only 生涯路径(career_history)
- 可归档的记忆引用(semantic / episodic memory refs)
- 可被审计的生命周期(hired / active / paused / retired / tombstoned)

L1-identity 是承载这套语义的唯一仓。没有它,work / conversation / runtime / governance / archive 会各自维护身份碎片,导致成员可用性、责任链、能力证据和记忆引用断裂。

### 1.2 业务驱动力

**业务驱动力**:
- `product/最终目的.md` §3.2 明确"员工是有身份的个体"
- 42001 / 9001 需要角色和责任链可追溯
- 产品叙事要求"成长中的成员",不是一次性进程

**技术驱动力**:
- 双层 Member 模型(GlobalMember / ProjectMember)需要严格边界
- memory 持久化位置已由 ADR-0006 锁定,需要 identity 提供 ref 承载
- method-library 的 RoleDefinition 要有运行时索引落点(RoleCatalogEntry)
- identity 事件必须通过 outbox 保证不丢失,并支持下游幂等消费
- Auditor / Console / governance 需要可重建的审计投影和 trace 查询

### 1.3 成功标准(可量化)

| 维度 | 指标 | 目标值 | 测量 |
|---|---|---|---|
| 生命周期完整性 | hired / active / paused / retired / tombstoned 合法转移 | 100% 按状态机执行,非法转移拒绝 | 状态机测试 |
| 双层 Member 边界 | 本仓只持有 GlobalMember,不持有 ProjectMember | 100% 依赖检查通过 | 代码审查 + 依赖检查 |
| Role 索引同步 | method_library.role_definition.published → identity.role.catalog_updated | < 5s | 事件集成测试 |
| 查询性能 | `GetMemberSummary` P95 | < 50ms | benchmark |
| 列表性能 | `ListMembersByLifecycle` P95 | < 100ms | benchmark |
| 写性能 | Command 写操作 P95 | < 200ms | benchmark |
| 事件可靠性 | outbox 发布延迟 P95 | < 30s | fault injection |
| 审计完整性 | lifecycle / role / capability / memory / career trace 覆盖 | 100% | 审计查询 + 事件回放 |
| 安全边界 | 非授权写操作拦截率 / Gate 绕过率 | 100% / 0 | 权限测试 + Gate 测试 |

### 1.4 本轮架构校准口径

本文从 v0.1.2 起以 `00-需求文档.md` v0.1.6 为基线。后续章节如果仍出现旧口径,需要按下表校准。

| 主题 | 旧口径 | 新口径 |
|---|---|---|
| identity 定位 | GlobalMember / Role / Capability 服务 | AI 员工身份真相源 |
| Role | identity 持有 Role 聚合 | identity 只持有 RoleCatalogEntry,RoleDefinition 正文在 method-library |
| Capability | 泛称 Capability | 成员 CapabilityProfile + evidence refs |
| Career | 成员生涯路径 | append-only career_history,由 work 事件驱动 |
| Memory | 记忆引用 | semantic / episodic memory refs,identity 不存向量 / 原文 |
| Runtime | 身份变化通知运行时 | identity 只发布事件和查询投影,不负责容器编排和工具执行 |
| 审计 | identity.audit.* 粗粒度事件 | lifecycle / role / capability / memory / career trace + audit projection |
| 事件 | 普通事件发布 | 写模型事务 + outbox + 下游幂等消费 |
| Gate | 未明确进入架构主线 | 高风险 lifecycle 写操作必须受 Gate / 授权约束 |

**架构含义**:
- 后续不能把 `RoleDefinition` 正文、`ProjectMember` 真相、memory 内容或 runtime 工具执行放进 identity。
- 后续容器图必须显式表达 Command API、Query API、Subscribers、Outbox Worker、Projection 和 Domain Model。
- 后续数据所有权必须区分真相层、追加记录层、引用层和投影层。

## 2. 约束条件

### 2.1 不可变约束(必须遵守)

| 约束 | 来源 | 影响 |
|---|---|---|
| GlobalMember 是聚合根 | ADR-0004 | 本仓不持有 ProjectMember |
| Role 内容在 method-library,本仓只存索引 + 生命周期元数据 | `domain/identity/README.md` §1.2 | 不在本仓存 RoleDefinition 正文 |
| semantic / episodic memory 只存 ref | ADR-0006 | 不在本仓存向量 / 原文 |
| career_history append-only | `domain/identity/README.md` INV-4 | 历史不可改 |
| tombstoned 单向 | INV-2 | 终态不可恢复 |
| Rust + PostgreSQL + axum + sqlx | ADR-0003 | 技术栈锁定 |

### 2.2 可变约束

| 约束 | 当前值 | 可调整空间 |
|---|---|---|
| 向量库 | Qdrant / pgvector 候选 | 只要 ref 契约不变可换 |
| full-text | PostgreSQL tsvector | 可后续换 OpenSearch |
| UI 身份展示 | Console / Chat | 只要 ViewProfile 接口稳定可演进 |

### 2.3 容量规划

| 资源 | 上限 | 量化依据 |
|---|---|---|
| 活跃 Member | 10w | `projects/L1-identity/README.md` 既定目标 |
| career entries | 50w | 每 Member 平均 5 项目 |
| role catalog | < 500 | Role 是稀缺对象 |
| memory refs | per Member < 100 | 项目级 episodic refs |

## 3. 架构风格与选型

### 3.1 变化维度识别

| 维度 | 变化频率 | 应对策略 |
|---|---|---|
| RoleDefinition 发布 / 退役 | 中 | spec_source + fingerprint 索引 |
| CareerEntry 增长 | 高频 append | append-only 表 + 分离 career_entries |
| Memory provider 切换 | 中 | ref 抽象,只存 URI / handle |
| 生命周期动作 | 中 | 明确状态机 + 事件驱动同步 |

### 3.2 架构风格决策框架

**候选风格**:

| 风格 | 优势 | 劣势 | 适用性 |
|---|---|---|---|
| **聚合驱动 + 事件编织**(当前)| 与六域模型一致,边界清晰 | 需要事件一致性治理 | ✅ 最匹配 |
| 纯 CRUD 服务 | 开发快 | 无法承载状态机 / append-only / audit | ❌ 不够表达身份语义 |
| event-sourced 全量事件溯源 | 审计最强 | 实现复杂,超出当前需求 | ⚠️ 过重 |

**最终选择**:**聚合根(GlobalMember / Role)+ append-only CareerEntry + 事件驱动同步**

### 3.3 约束-收益分析

| 约束 | 收益 | 成本 |
|---|---|---|
| ProjectMember 不在本仓 | 双层边界清晰 | 需要跨域同步事件 |
| career_history append-only | 审计强、成长轨迹清楚 | 查询模型稍复杂 |
| memory 只存 ref | 仓边界稳定,不绑底层向量库 | 调试时要跳转外部系统 |

### 4.2 交互分类

| 交互类型 | 方向 | 说明 | 关键约束 |
|---|---|---|---|
| Command API | 外部 → identity | hire / activate / pause / retire / role / capability / memory ref 写操作 | 必须鉴权,高风险操作受 Gate 约束 |
| Query API | 外部 → identity | GetMemberSummary / GetRoleCatalog / GetMemberAuditTrace | 按调用方权限裁剪字段 |
| Inbound events | method-library / work / memory / archive / governance → identity | RoleDefinition、ProjectMember、memory ref、Gate 决策事件 | 订阅方幂等,append-only 记录不得改写 |
| Outbound events | identity → work / member-service / conversation / governance / archive | identity.member.* / identity.role.* / identity.audit.* | 写模型事务后经 outbox 发布 |
| Persistence | identity → PostgreSQL | write model / append-only records / projections / outbox | 本地事务强一致 |
| Observability | identity → observability | audit refs、metrics、security trace | audit 不得静默丢失 |

### 4.3 职责边界(做什么 / 不做什么)

| 边界项 | identity 负责 | identity 不负责 |
|---|---|---|
| Member | GlobalMember 档案、全局生命周期、身份审计 | ProjectMember 分配和项目内成员状态 |
| Role | RoleCatalogEntry 运行时索引、spec_source、fingerprint、lifecycle 摘要 | RoleDefinition 正文和方法内容编排 |
| Capability | CapabilityProfile、evidence refs、能力变化 trace | 能力定义库和自动评级算法 |
| Career | career_history append-only 记录和投影 | 项目计划、任务分配、ProjectMember 真相 |
| Memory | semantic / episodic memory refs | 向量、原文、对话内容和检索算法 |
| Runtime | 发布 lifecycle / role / capability / memory 事件,提供查询投影 | 容器编排、工具执行、skill 调度 |
| Governance | 记录 Gate 决策引用并执行受控状态转移 | Policy 判断和 Gate 决策本身 |
| Observability | 提供 audit refs、security trace、metrics | 全局日志存储和审计原始事件中心 |

### 4.4 外部系统可用性约束

| 外部依赖 | 关系 | 降级 / 失败策略 |
|---|---|---|
| PostgreSQL | 主写模型和查询投影 | 不可用时写操作失败,不得假成功 |
| bus | 事件发布 / 订阅 | 不可用时写 outbox 并重试,不得丢 identity 事件 |
| method-library | RoleDefinition 来源 | 可使用本地 RoleCatalogEntry 缓存,不得创建未知 Role |
| work | ProjectMember 真相和项目事件来源 | work 事件乱序 / 重复时按 source_event_id 幂等处理 |
| member-service/runtime | lifecycle / role / capability 事件消费者 | 消费延迟只影响运行时刷新,不反写 identity 真相 |
| memory service / archive | memory 内容和冷存归属 | memory ref 可延迟;tombstone 冷存不可假完成 |
| governance | Gate 决策来源 | Gate 不可用时受控写操作不得绕过 |
| observability | audit / metrics 消费方 | 不可用时保留 audit outbox / compensation record 并告警 |

### 4.5 关键依赖风险

| 风险 | 影响 | 架构缓解 |
|---|---|---|
| RoleDefinition 漂移 | 新成员创建或 role change 用到错误角色索引 | fingerprint 对账 + `identity.role.source_drift` |
| work 事件乱序 / 重复 | career_history 重复或状态投影错误 | source_event_id / trace_id 幂等 + projection 计算状态 |
| member-service 消费 lifecycle 事件延迟 | 容器状态刷新滞后 | outbox 可重放 + consumer 幂等 |
| archive 不可用 | tombstone 冷存流程卡住 | tombstone operation pending / failed 可见,不假完成 |
| observability 不可用 | 审计链断裂风险 | audit outbox / compensation record + 告警 |

### 5.3 上下文映射关系

```
method-library
  └─▶ Role Catalog
        └─▶ Member Identity
              ├─▶ Capability Profiling
              ├─▶ Career Tracking ◀── work
              ├─▶ Memory Linking ◀── memory service / archive
              ├─▶ Audit Projection ──▶ console / auditor / governance
              └─▶ Event Publication ─▶ work / member-service / conversation / archive

governance ──Gate decisions──▶ Member Identity
```

| 来源 / 目标 | 映射类型 | 说明 |
|---|---|---|
| method-library → Role Catalog | Conformist / Published Language | identity 按 method-library 发布的 RoleDefinition 建 RoleCatalogEntry |
| work → Career Tracking | Customer-Supplier / Event-driven | work 拥有 ProjectMember 真相,identity 消费项目成员事件追加 career_history |
| memory service / archive → Memory Linking | Supplier / Ref-only | memory 内容不进入 identity,只同步 ref |
| governance → Member Identity | Control / Gate decision | 高风险 lifecycle 转移由 Gate 决策约束 |
| Member Identity → Event Publication | Internal domain event | 写模型变化转为 outbox 事件 |
| Audit Projection → console / auditor / governance | Query model | 只读投影服务查询,不得反写真相 |
| Event Publication → member-service / work / conversation / archive | Published Language | identity.member.* / identity.role.* / identity.audit.* |

### 6.2 每个容器的职责与技术栈

| 容器 / 进程 | 职责 | 技术栈 |
|---|---|---|
| identity-api | 承载 Command API 和 Query API,做认证、授权入口和请求校验 | Rust + axum/tonic |

| identity-domain | GlobalMember、LifecycleStateMachine、RoleCatalogEntry、CapabilityProfile 等领域规则 | Rust |
| identity-db | write model、append-only records、query projections、identity_events_outbox | PostgreSQL |
| outbox-worker | 读取 outbox,发布 identity 事件到 bus,支持重试和幂等标记 | Rust |
| observability-adapter | 输出 audit refs、metrics、security trace | Rust / OpenTelemetry |

### 6.3 通信方式与选择理由

| 场景 | 选择 | 理由 |
|---|---|---|
| 外部写入 identity | Command API(gRPC / HTTP) | 写操作需要明确鉴权、Gate 和错误语义 |
| 外部查询 identity | Query API(gRPC / HTTP) | 查询投影可控,按调用方权限裁剪字段 |
| 上游域通知 identity | bus event subscriber | method-library / work / memory / governance 与 identity 最终一致 |
| identity 通知下游 | outbox → bus events | 写模型事务与事件发布解耦,避免事件丢失 |
| memory / archive 对接 | ref 级 API / event | identity 只存 ref,不绑定底层记忆存储 |
| observability 对接 | trace / metrics / audit adapter | 审计和指标从主流程解耦,但不得静默丢失 |

| 数据 | 写入方 | 读取方 |

| `global_members` | identity command handlers | identity query handlers / projections |
| `role_catalog_entries` | identity subscriber(method-library events) | identity command/query handlers |
| `capability_profiles` | identity command handlers | identity query handlers / audit projection |
| `career_entries` | identity subscriber(work events) | identity query handlers / audit projection |
| `memory_refs` | identity command handlers / memory/archive events | member-service / archive / audit projection |

| `identity_events_outbox` | identity application services | outbox-worker |
| query projections | identity application / projection service | Query API / console / auditor |

### 6.5 部署拓扑

- 第一批采用单仓单服务部署,`identity-api`、`identity-subscriber`、`outbox-worker` 可同进程运行。
- PostgreSQL 是唯一主存储,可按环境选择单节点或主从。
- outbox-worker 可先内嵌,当事件量增大或发布延迟超标时可拆成独立进程。
- query projection 与 write model 同库不同表,后续如查询压力过大再评估只读副本或搜索引擎。
- observability-adapter 不参与主事务提交,但 audit outbox / compensation record 必须保留失败事实。

## 7. 依赖方向与层间约束

### 7.1 依赖方向图

```
inbound adapters
  ├─ command api
  ├─ query api
  └─ event subscribers
        │
        ▼
application services
  ├─ command use cases
  ├─ query use cases
  ├─ sync handlers
  └─ projection builders
        │
        ▼
domain model
  ├─ GlobalMember
  ├─ LifecycleStateMachine
  ├─ RoleCatalogEntry
  ├─ CapabilityProfile
  ├─ CareerEntry
  └─ MemoryRef / Trace
        ▲
        │ ports
outbound adapters
  ├─ postgres repositories
  ├─ outbox / bus publisher
  ├─ observability adapter
  └─ memory / archive ref adapter
```

### 7.2 层间约束规则

- domain 不直接依赖 PostgreSQL、bus、observability、memory service、archive 或外部 SDK。
- application services 编排 use case、事务边界、outbox 写入和 projection 更新,但不写 SQL 细节。
- inbound adapters 只做协议转换、认证授权入口和 DTO 校验,不得绕过 application 直接改 DB。
- event subscribers 必须调用 application use case,不得绕过状态机或 append-only 规则。
- query handlers 只读 projection 或 repository query port,不得反写真相。
- RoleCatalogEntry 只保存 spec_source / fingerprint / lifecycle 摘要,不得拉取 RoleDefinition 正文入库。
- MemoryRef 只保存 ref,不得通过 adapter 把向量、原文或对话内容写入 identity。
- outbox 发布必须由写模型事务产生,不得由 domain 直接调用 bus。
- Gate 决策由 governance 提供,identity 只消费决策引用并执行受控状态转移。

### 7.3 依赖倒置的接口点

| 接口 | 定义位置 | 实现位置 |
|---|---|---|
| MemberRepository | application port | postgres repository |
| RoleCatalogRepository | application port | postgres repository + method-library subscriber |
| CareerEntryRepository | application port | postgres append-only repository |
| MemoryRefRepository | application port | postgres repository + memory/archive adapter |
| ProjectionRepository | application port | postgres projection repository |
| OutboxPublisher | application port | postgres outbox + bus publisher |
| AuditTracePort | application port | observability adapter + audit projection |
| GateDecisionPort | application port | governance event subscriber / query adapter |

### 7.4 入站适配器约束

| 入站适配器 | 允许调用 | 禁止事项 |
|---|---|---|
| Command API | MemberCommandService / Role change / Capability / MemoryRef use case | 直接写 repository 或绕过 Gate |
| Query API | MemberQueryService / AuditProjectionService | 直接读取 write model 敏感字段并绕过权限裁剪 |
| method-library subscriber | RoleCatalogSyncService | 存储 RoleDefinition 正文 |
| work subscriber | CareerEventHandler | 创建或修改 ProjectMember 真相 |
| memory / archive subscriber | MemoryRefService / Tombstone flow use case | 写入 memory 内容 |
| governance subscriber | lifecycle use case with GateDecisionRef | 自行判断政策是否通过 |

### 7.5 依赖健康度评估

| 指标 | 当前预期 |
|---|---|
| 传入耦合 | 高(work / member-service / conversation / governance / archive / console 都依赖 identity 查询或事件) |
| 传出耦合 | 中(PostgreSQL / bus / method-library events / memory refs / observability / governance Gate) |
| 不稳定性 | 中,通过 ports 和 outbox 降低外部依赖震荡 |
| 抽象度 | 中高,domain 纯净,application 通过 ports 依赖外部能力 |
| 主要风险 | 入站适配器绕过 application 或 outbox,导致状态机、审计、事件一致性失效 |

## 8. 数据所有权与一致性策略

### 8.1 数据所有权矩阵

| 数据层 | 数据 | identity 所有权 | 来源 | 一致性策略 | 主要消费者 |
|---|---|---|---|---|---|
| 真相层 | GlobalMember | 主真相 | Command API | 聚合内强一致 | work / member-service / console / governance |
| 真相层 | RoleCatalogEntry | 运行时索引真相,不拥有 RoleDefinition 正文 | method-library events | 最终一致 + fingerprint 对账 | Command API / runtime / work |
| 真相层 | CapabilityProfile | 主真相 | Command API + evidence refs | 聚合内强一致 + 审计 trace | member-service / governance / auditor |
| 追加记录层 | CareerEntry | append-only 生涯记录 | work events | 事件最终一致 + 幂等 append | console / auditor / governance |
| 追加记录层 | LifecycleTraceEntry | append-only 状态变化记录 | lifecycle use case | 与生命周期写事务同提交 | auditor / governance / console |
| 追加记录层 | RoleCapabilityChangeEntry | append-only 角色和能力变化记录 | Command API | 与变更事务同提交 | auditor / governance |
| 追加记录层 | MemoryRefChangeEntry | append-only memory ref 变化记录 | Command API / memory events / archive events | 事件最终一致 + trace | auditor / archive |
| 引用层 | ProjectRef / ProjectMemberRef | 只保存引用 | work events | 不反写 work 真相 | career projection |
| 引用层 | SemanticMemoryRef / EpisodicMemoryRef | 只保存 ref | memory service / archive | ref 最终一致 | member-service / archive |
| 引用层 | EvidenceRef / AuditLogRef | 只保存 ref | artifact / observability | ref 最终一致 | auditor / governance |
| 投影层 | MemberSummaryProjection | 可重建查询视图 | write model + append-only records | 最终一致,可重建 | Query API / console |
| 投影层 | LifecycleTraceProjection | 可重建审计视图 | trace records | 最终一致,可重建 | Auditor / governance |
| 事件层 | identity_events_outbox | identity 持有待发布事件 | application services | 与写模型同事务,发布后标记 | outbox-worker |

### 8.2 一致性层次

- 聚合内:GlobalMember lifecycle、role_id、CapabilityProfile、当前 memory refs 在单个写事务内保持强一致。
- 追加记录:LifecycleTraceEntry、CareerEntry、RoleCapabilityChangeEntry、MemoryRefChangeEntry 只 append,不得就地改写。
- 投影层:MemberSummaryProjection / LifecycleTraceProjection 允许短暂滞后,但必须可由真相层和追加记录层重建。
- 跨服务:不做 2PC,通过 outbox + 订阅方幂等 + source_event_id / trace_id 达成最终一致。
- RoleCatalogEntry:以 method-library 为定义源,identity 只维护运行时索引和 fingerprint,通过 source_drift 事件处理漂移。
- MemoryRef:identity 只保证 ref 的一致性,不保证外部 memory 内容可用性;外部不可用时保留失败事实。
- Tombstone:GlobalMember.lifecycle 只允许 retired → tombstoned 单向变化;冷存迁移是受控协作流程,不能假完成。

### 8.3 补偿机制设计

| 场景 | 补偿机制 | 不允许的做法 |
|---|---|---|
| method-library 事件迟到 | 重放事件 + fingerprint 对账 + `identity.role.source_drift` | 直接复制 RoleDefinition 正文解决漂移 |
| work 事件重复 | source_event_id 幂等去重 | 重复 append 同一 CareerEntry |
| work 事件乱序 | append 原始事实,由 projection 计算当前状态 | 改写旧 career_history |
| outbox 发布失败 | 保留 pending outbox,后台重试,暴露 max age 指标 | 写模型成功但丢弃事件 |
| projection 更新失败 | 保留源记录,后台重建 projection | 让 projection 反写真相 |
| memory service 故障 | memory ref 更新延迟,保留失败 trace | 把 memory 内容写入 identity 绕过外部服务 |
| archive 冷存失败 | tombstone operation pending / failed 可见,等待补偿 | 标记冷存完成但实际未迁移 |
| observability 不可用 | audit outbox / compensation record 保留并告警 | 静默丢审计 trace |

### 8.4 数据边界红线

| 红线 | 说明 |
|---|---|
| 不保存 ProjectMember 真相 | identity 只能保存 ProjectRef / ProjectMemberRef 和 career_history 记录 |
| 不保存 RoleDefinition 正文 | identity 只能保存 RoleCatalogEntry |
| 不保存 memory 内容 | identity 只能保存 SemanticMemoryRef / EpisodicMemoryRef |
| 不由 projection 反写真相 | projection 是查询优化和审计视图,可删可重建 |
| 不绕过 outbox 发事件 | identity.member.* / identity.role.* / identity.audit.* 必须可追溯 |
| 不把 tombstone pending 写进 lifecycle | pending 属于 tombstone 协作流程,不是 GlobalMember lifecycle |

## 9. 关键技术选型

### 9.1 技术栈:Rust + PostgreSQL + axum/tonic + sqlx

| 维度 | 内容 |
|---|---|
| 当前选择 | Rust + PostgreSQL + axum + sqlx |
| 备选方案 | Go + pgx / Java + Spring |
| 选择理由 | ADR-0003 已锁;性能 / 类型安全 / SQL 可控 |
| 架构影响 | 支撑单服务内 Command API、Query API、Subscribers、Outbox Worker、Projection Builder |
| 演进路径 | Query projection 压力过大时可引入只读副本或 OpenSearch,主写模型不变 |
| 不可逆程度 | 高 |

### 9.2 Outbox + 事件最终一致

| 维度 | 内容 |
|---|---|
| 当前选择 | 写模型事务内写 `identity_events_outbox`,由 outbox-worker 发布 identity 事件 |
| 备选方案 | 写事务后直接发 bus / 全量 event sourcing |
| 选择理由 | 避免写模型成功但事件丢失;复杂度低于全量 event sourcing |
| 架构影响 | 所有 `identity.member.*` / `identity.role.*` / `identity.audit.*` 必须经 outbox |
| 演进路径 | 第一批内嵌 worker;事件量增大后拆独立 worker |
| 不可逆程度 | 中高 |

### 9.3 Query Projection

| 维度 | 内容 |
|---|---|
| 当前选择 | 同库维护 MemberSummaryProjection / LifecycleTraceProjection / RoleCatalogProjection |
| 备选方案 | 每次查询实时 join write model / 独立搜索服务 |
| 选择理由 | 查询 API 需要稳定 P95 和权限裁剪;projection 可重建,不污染真相层 |
| 架构影响 | Query API 读 projection,不得通过 projection 反写真相 |
| 演进路径 | 压力增大时迁到只读库或搜索引擎 |
| 不可逆程度 | 中 |

### 9.4 Append-only Records

| 维度 | 内容 |
|---|---|
| 当前选择 | career / lifecycle / role-capability / memory ref 变化都写 append-only records |
| 备选方案 | 只维护当前状态字段 / 全量 event sourcing |
| 选择理由 | 满足审计、追溯、乱序补偿和投影重建,复杂度可控 |
| 架构影响 | 不允许就地改写历史;当前状态由 write model 或 projection 表达 |
| 演进路径 | 数据量增长后可冷表或 archive 分层 |
| 不可逆程度 | 中高 |

### 9.5 RoleCatalogEntry + fingerprint drift

| 维度 | 内容 |
|---|---|
| 当前选择 | identity 只存 RoleCatalogEntry(spec_source / fingerprint / lifecycle 摘要),不存 RoleDefinition 正文 |
| 备选方案 | 完整复制 RoleDefinition |
| 选择理由 | method-library 单一真相源 |
| 架构影响 | 创建成员和 role change 只能引用已同步且非 retired 的 RoleCatalogEntry |
| 演进路径 | 如性能问题,可增 materialized cache,但仍不得成为 RoleDefinition 真相 |
| 不可逆程度 | 中 |

### 9.6 Memory ref 外部化

| 维度 | 内容 |
|---|---|
| 当前选择 | 只存 SemanticMemoryRef / EpisodicMemoryRef |
| 备选方案 | 本仓直接存向量 / 本仓存全文 |
| 选择理由 | 边界清晰,不绑定向量库或记忆服务 |
| 架构影响 | identity 不负责检索算法、不保存 memory 内容,只维护 ref 和 trace |
| 演进路径 | provider 可替换,ref 协议不变 |
| 不可逆程度 | 中 |

### 9.7 Gate / Tombstone flow

| 维度 | 内容 |
|---|---|
| 当前选择 | 高风险 lifecycle 写操作受 Gate / 授权约束;tombstone 冷存作为协作流程处理 |
| 备选方案 | lifecycle API 直接改状态 / 把 pending 放进 GlobalMember.lifecycle |
| 选择理由 | lifecycle 必须保持五态纯净;pending 是协作流程状态,不是成员生命周期 |
| 架构影响 | identity 消费 GateDecisionRef,执行受控状态转移;archive 不可用时 tombstone flow pending / failed 可见 |
| 演进路径 | 后续可把 tombstone operation 独立成显式流程对象 |
| 不可逆程度 | 中 |

## 10. 备选方案与取舍

### 10.1 仓级归属取舍

| 维度 | 方案 A:身份域独立(当前)| 方案 B:并入 work | 方案 C:并入 member-service |
|---|---|---|---|
| 语义清晰度 | 高 | 中 | 低 |
| 审计性 | 高 | 中 | 低 |
| 下游耦合 | 低 | 高 | 高 |
| 运行时依赖 | 低 | 中 | 高 |
| ProjectMember 边界 | 清晰,work 只引用 GlobalMember | 容易混淆 GlobalMember / ProjectMember | 运行时状态和身份真相混淆 |
| RoleCatalogEntry 边界 | 清晰指向 method-library | work 需要理解角色定义同步 | member-service 会耦合方法库和运行时 |
| memory refs 边界 | identity 只保存 ref | work 容易混入项目记忆内容 | runtime 容易混入 memory 内容 |

**最终选择**:方案 A。双层 Member 模型是核心边界,不能并仓。

### 10.2 架构机制取舍

| 机制 | 方案 A(采用) | 方案 B | 方案 C | 选择理由 |
|---|---|---|---|---|
| 事件发布 | 写模型事务 + outbox | 写完 DB 后直接发 bus | 全量 event sourcing | outbox 能防止事件丢失,复杂度低于全量 event sourcing |
| 查询模型 | 同库 query projection | 每次实时 join write model | 独立搜索服务 | projection 满足 P95 与权限裁剪,第一批复杂度可控 |
| 历史记录 | append-only records | 只覆盖当前状态 | 全量事件溯源 | append-only 满足审计与重放,比 event sourcing 更轻 |
| Role 定义 | RoleCatalogEntry + fingerprint | 完整复制 RoleDefinition | 每次实时查 method-library | 保持 method-library 真相,同时保证 identity 可运行 |
| Memory | 只保存 memory refs | identity 存向量 / 原文 | 每次实时调用 memory service | ref-only 边界最清晰,不绑定 provider |
| Gate / lifecycle | API / 事件携带 GateDecisionRef,状态机执行转移 | lifecycle API 直接改状态 | Gate 服务直接改 identity DB | identity 保持生命周期真相,Gate 保持决策真相 |
| Tombstone | lifecycle 五态 + tombstone operation 流程 | 把 pending 放进 lifecycle | 直接 hard delete | 保持 lifecycle 纯净,并保留审计和冷存协作能力 |

### 10.3 明确不采用的方案

| 不采用方案 | 不采用原因 |
|---|---|
| identity 直接持有 ProjectMember | 破坏 GlobalMember / ProjectMember 双层模型 |
| identity 复制 RoleDefinition 正文 | 破坏 method-library 单一真相源 |
| identity 存 memory 向量或原文 | 破坏 ADR-0006 的 ref-only 边界 |
| domain 直接发布 bus 事件 | 绕过 outbox,写模型成功但事件丢失风险高 |
| projection 反写真相 | 破坏投影可重建性和数据所有权 |
| 把 tombstone pending 作为 lifecycle 状态 | 污染 hired / active / paused / retired / tombstoned 五态模型 |

## 11. 横切关注点

### 11.1 韧性与失败隔离

identity 的横切设计目标不是"所有依赖都在线时流程顺畅",而是外部依赖异常时仍能守住身份真相源边界:

| 失败场景 | 处理策略 | 架构约束 |
|---|---|---|
| PostgreSQL 不可用 | Command 写失败,返回明确错误 | 不得假成功,不得只写缓存 |
| bus 不可用 | outbox 保留待发布事件并重试 | 写模型提交与事件投递解耦 |
| method-library 不可用 | 使用本地 RoleCatalogEntry 缓存读取 | 不得创建未知 role,不得复制 RoleDefinition 正文 |
| work 事件乱序或重复 | 使用 source_event_id / trace_id 幂等处理 | projection 可重放、可重建 |
| memory service 不可用 | memory ref 更新延迟或失败记录补偿 | hire 主流程不依赖 memory 原文或向量 |
| archive 不可用 | tombstone flow 标记 pending / failed | 不得把未归档完成伪装为 tombstoned 完成 |
| observability 不可用 | audit compensation record / outbox 保留并告警 | 关键写操作必须可追溯 |
| governance Gate 不可用 | 需要 Gate 的受控写操作失败或等待 | 不得绕过 Gate 修改敏感状态 |

### 11.2 可观测性

可观测性围绕"身份状态是否可信、事件是否送达、投影是否滞后、敏感操作是否可追溯"展开:

| 观测对象 | 推荐信号 | 用途 |
|---|---|---|
| command 写入 | success / failure / reject count,latency | 判断身份写路径是否健康 |
| lifecycle transition | from / to / actor / rejection reason | 追踪非法状态迁移与治理拒绝 |
| outbox | pending count,max pending age,publish failure | 发现事件堆积与 bus 故障 |
| query projection | lag,rebuild count,last source event | 发现读模型陈旧或重建异常 |
| role catalog sync | source_drift,unknown_role_reference | 发现 method-library 与 identity 本地索引漂移 |
| unauthorized write | actor,command,resource,decision | 安全审计与异常行为分析 |
| tombstone flow | pending count,failed count,archive ref status | 发现销毁流程未闭环 |
| consumer replay | replay count,idempotency hit | 验证事件消费幂等性 |

### 11.3 安全与授权

identity 管理的是 AI 员工身份,安全策略必须按 command 边界和敏感字段边界设计:

| 维度 | 策略 |
|---|---|
| 服务认证 | 外部入口使用 OAuth2 / OIDC,内部服务调用使用 mTLS 或 service token |
| Command 授权 | hire / pause / retire / tombstone / role attach 等写操作必须校验 actor 权限 |
| Assistant 权限 | Assistant 只能发起建议、创建请求或触发受控流程,不能绕过授权直接改写身份真相 |
| Gate 绑定 | 需要治理审批的操作必须记录 GateDecisionRef |
| 读权限 | GetMemberSummary 可做字段裁剪,敏感 memory refs / audit refs 需要额外权限 |
| 数据最小化 | tombstone 后只保留最小身份、归档引用和审计引用 |
| 安全审计 | 未授权写、Gate 拒绝、敏感字段读取必须进入 audit trace |

### 11.4 配置管理

| 配置项 | 说明 | 调整原则 |
|---|---|---|
| PostgreSQL 连接 | write model / append-only / projection / outbox 共用存储配置 | 需要支持连接池、超时和迁移版本 |
| outbox worker | poll interval,batch size,retry backoff | 优先保证可靠投递,再优化延迟 |
| bus endpoint | 事件发布目标与 topic 映射 | 不写入 domain 层,只在 adapter 配置 |
| role sync reconciliation | 与 method-library 的同步周期和漂移检测阈值 | 不影响 RoleDefinition 单一真相源 |
| projection rebuild | batch size,checkpoint interval | 支持可控重建和回放 |
| memory / archive adapter | memory ref 与 archive ref 的服务端点 | identity 只保存 ref,不保存内容 |
| Gate policy mapping | 哪些 command 需要 GateDecisionRef | 由 governance 策略驱动 |
| observability sink | metrics / logs / traces / audit sink | 故障时不得丢失关键审计线索 |
| tombstone retention | 延迟期、归档窗口、最小保留字段 | 与治理和合规策略保持一致 |

### 11.5 性能预算表

性能预算只约束 identity 自身能控制的路径。外部审批、归档和人工决策不伪装成同步低延迟能力:

| 环节 | 预算 | 说明 |
|---|---|---|
| GetMemberSummary | < 50ms P95 | 走 query projection,避免跨域实时 join |
| ListMembersByLifecycle | < 100ms P95 | 依赖 lifecycle 索引和分页 |
| Command 写入 | < 200ms P95 | 覆盖校验、写模型、append-only、outbox 写入 |
| RoleCatalogEntry 同步滞后 | < 5s | method-library 正常可用时的目标 |
| outbox 发布滞后 | < 30s P95 | bus 正常可用时的目标 |
| projection 滞后 | < 30s P95 | work / identity 事件正常消费时的目标 |
| tombstone flow | 不承诺同步完成 | 归档、Gate、延迟期完成前不得假成功 |

## 12. 演进路线

### 12.1 当前状态与已知债务

identity 的演进债务集中在跨域契约和运营闭环,而不是身份模型本身:

| 债务项 | 影响 | 优先级 | 处理方向 |
|---|---|---|---|
| RoleCatalogEntry 同步契约待冻结 | role attach / role drift / reconciliation 无法稳定实现 | P0 | 与 method-library 固定 role_id、version、fingerprint、source_ref |
| Gate policy mapping 待冻结 | hire / pause / retire / tombstone 等受控写操作授权边界不稳定 | P0 | 与 governance 固定哪些 command 必须带 GateDecisionRef |
| tombstone 延迟期与归档窗口待定 | 无法判断何时从 retired 进入最终 tombstoned | P1 | 与 governance / archive 固定 retention、archive ref、失败补偿 |
| MemoryRef URI 规范待冻结 | semantic / episodic ref 无法跨服务解析 | P1 | 与 memory / archive 固定 ref scheme 和权限语义 |
| projection rebuild 策略待细化 | 查询投影异常时恢复路径不清晰 | P1 | 固定 checkpoint、batch size、replay 范围 |
| audit event taxonomy 待对齐 | 安全审计和跨域追溯粒度不一致 | P1 | 与 L0-audit / L0-bus 对齐事件名、trace_id、actor 字段 |
| Console / Chat 同名成员展示策略待定 | 用户体验和人工选择可能歧义 | P2 | 由 query projection 提供稳定 display_name + global_member_id |

### 12.2 演进原则

| 原则 | 说明 |
|---|---|
| 先闭环身份核心 | 先让 GlobalMember、RoleCatalogEntry、CapabilityProfile、career_history、outbox 能独立工作 |
| 再接跨域协作 | method-library / work / governance / memory / archive 通过端口和事件逐步接入 |
| 先可靠再复杂 | projection rebuild、outbox retry、audit trace 稳定后,再扩展复杂查询和批量运营能力 |
| 不扩大所有权 | 演进过程中仍不得持有 ProjectMember、RoleDefinition 正文、memory 原文或向量 |
| 每阶段可验收 | 每个阶段都必须有可运行 API、可观察事件、可回放数据和失败补偿路径 |

### 12.3 阶段路径

```
N0 文档基线
  |
  v
N1 Identity Core
  - GlobalMember lifecycle
  - RoleCatalogEntry 本地索引
  - CapabilityProfile
  - append-only career_history
  - write model + outbox
  |
  v
N2 Cross-domain Contracts
  - method-library role sync
  - work 投影与 career entry 联动
  - governance GateDecisionRef
  - memory / archive ref adapter
  |
  v
N3 Reliability & Operations
  - outbox retry / replay
  - projection rebuild
  - audit trace / compensation record
  - tombstone flow 闭环
  |
  v
N4 Scale & Governance
  - 大规模成员查询优化
  - career_history 冷热分层
  - role drift 自动对账
  - 合规保留策略自动化
```

### 12.4 触发条件

| 指标或事件 | 阈值 | 动作 |
|---|---|---|
| RoleCatalogEntry source_drift | > 3 次 / 月 | 增强 reconciliation worker 与告警 |
| outbox max pending age | > 30s 持续 10 分钟 | 检查 bus / publisher,必要时扩容 worker |
| projection lag | > 30s 持续 10 分钟 | 启动 replay / rebuild 诊断 |
| lifecycle command reject rate | > 1% 持续 1 小时 | 检查调用方、权限策略和 Gate policy |
| tombstone failed count | > 0 | 进入人工审查,不得自动标记完成 |
| 活跃成员数量 | > 10w 且持续增长 | 评估 projection 索引、分页和归档策略 |
| career_history entries | > 1e7 | 评估冷热分层或归档表 |

### 12.5 目标架构

目标不是把 identity 做成"万能员工中心",而是成为 AI 员工身份的稳定锚点:

| 目标能力 | 目标状态 |
|---|---|
| 身份真相源 | GlobalMember lifecycle、role catalog ref、capability、career、memory refs 语义清晰 |
| 跨域解耦 | 通过端口、事件和 projection 与 method-library / work / governance / memory / archive 协作 |
| 审计友好 | 关键变化 append-only,敏感操作有 actor / trace_id / GateDecisionRef |
| 运营可恢复 | outbox 可重试,projection 可重建,consumer 可幂等回放 |
| 所有权克制 | 不吞并 ProjectMember、RoleDefinition、memory 内容、runtime 执行状态 |

## 13. 风险与待确认事项

### 13.1 风险总览

identity 的主要风险不是单个字段设计错误,而是身份真相源与外部域协作时出现边界漂移、事件丢失、权限绕过或销毁流程未闭环:

| 风险 | 概率 | 影响 | 触发信号 | 缓解 |
|---|---|---|---|---|
| RoleCatalogEntry 与 method-library 漂移 | 中 | 高 | source_drift / fingerprint mismatch | 固定 role_id、version、fingerprint,增加 reconciliation worker |
| lifecycle 状态迁移非法 | 中 | 高 | command reject rate 上升 / 异常 from-to | domain 层集中校验状态机,敏感迁移绑定 GateDecisionRef |
| Gate 被绕过或不可用 | 中 | 高 | 缺失 GateDecisionRef / Gate timeout | 需要 Gate 的 command 失败或等待,不得降级为直接写 |
| outbox 堆积或发布失败 | 中 | 高 | pending age 超阈值 / publish failure | outbox retry、告警、人工 replay,写模型不直接发 bus |
| 事件乱序或重复导致投影错误 | 中 | 中 | idempotency miss / projection lag | source_event_id 幂等、checkpoint、rebuild |
| career_history 顺序或体量失控 | 中 | 中 | append count 激增 / 查询变慢 | append-only 记录 trace_id,按成员分页,后续冷热分层 |
| tombstone flow 未闭环 | 中 | 高 | tombstone pending / failed > 0 | archive ref、retention、Gate、audit 全部完成后才进入 tombstoned |
| MemoryRef 无法解析或权限不匹配 | 中 | 中 | ref resolve failure / unauthorized ref read | 固定 ref scheme,读取时做权限裁剪,不保存原文和向量 |
| ownership 边界被扩大 | 低 | 高 | identity 出现 ProjectMember / RoleDefinition 正文字段 | 架构评审阻断,保持 ref-only / catalog-only |

### 13.2 高风险场景处置

| 场景 | 正确处置 | 禁止做法 |
|---|---|---|
| method-library 暂时不可用 | 使用已有 RoleCatalogEntry 缓存读取,写入未知 role 时拒绝 | 临时复制 RoleDefinition 正文到 identity |
| governance Gate 不可用 | 需要审批的 command 进入失败或等待,保留 trace | 绕过 Gate 直接 hire / pause / retire / tombstone |
| bus 不可用 | 业务写入和 outbox 同事务提交,等待 publisher 重试 | domain 直接调用 bus 并在失败时丢弃事件 |
| projection 数据异常 | 从 append-only / outbox checkpoint 重建投影 | 手工修改 projection 反写真相 |
| tombstone 归档失败 | 标记 flow failed / pending,暴露给人工审查 | 提前删除身份或提前标记 tombstoned |
| MemoryRef 解析失败 | 保留 ref 和失败证据,由 adapter 补偿 | 将 memory 内容复制进 identity 临时兜底 |

### 13.3 边缘风险

| 边缘风险 | 影响 | 建议处理 |
|---|---|---|
| secondary_roles 与 main_role 并发变更 | 角色视图短暂不一致 | role attach / detach 使用版本号或乐观锁 |
| 同名 GlobalMember 在 Chat / Console 中混淆 | 人工操作误选成员 | query projection 提供 display_name + global_member_id + lifecycle |
| 一个 Member 跨大量项目产生 career_history 爆炸增长 | 查询和归档压力上升 | career entry 分页查询,后续冷热分层 |
| memory / archive provider 迁移 | 旧 ref 无法解析 | ref scheme 带 provider / version,迁移时保留 alias |
| audit sink 暂时不可用 | 审计链不完整 | compensation record / outbox 保留,恢复后补投 |
| 消费方长期未 replay | 下游缓存仍看到旧身份 | 通过 bus consumer lag 与 audit trace 暴露滞后 |

### 13.4 待确认问题

| 问题 | 截止 | 负责人 | 未确认影响 |
|---|---|---|---|
| RoleCatalogEntry 同步契约字段 | N1 前 | identity + method-library | role attach、source drift 和 reconciliation 无法稳定开发 |
| 哪些 command 必须绑定 GateDecisionRef | N1 前 | identity + governance | 敏感生命周期操作授权边界不清 |
| tombstone 延迟期与归档窗口 | N2 前 | identity + governance + archive | retired 到 tombstoned 的完成条件不清 |
| MemoryRef URI / 权限语义 | N2 前 | identity + memory + archive | semantic / episodic ref 无法统一解析和裁剪 |
| audit event taxonomy | N2 前 | identity + L0-audit + L0-bus | 跨域追溯和安全审计粒度不一致 |
| projection rebuild 策略和 SLA | N3 前 | identity | 读模型损坏后的恢复路径不清 |
| Chat / Console 成员展示字段 | N3 前 | identity + conversation + console | 同名成员选择和人工操作体验不稳定 |

## 14. 上线策略

### 14.1 上线前置条件

| 前置项 | 必须满足的条件 | 不满足时处理 |
|---|---|---|
| schema migration | write model、append-only、projection、outbox 表结构可迁移、可回滚 | 不上线写路径 |
| Command API | hire / pause / resume / retire / tombstone / role attach 基础校验可运行 | 禁止接入 Console / Assistant 写入口 |
| lifecycle state machine | 五态模型和非法迁移拒绝已测试 | 不开放生命周期写操作 |
| RoleCatalogEntry | 与 method-library 的 role_id / version / fingerprint 契约冻结 | 不允许创建或绑定未知 role |
| outbox publisher | 事件写入、重试、失败告警可观测 | 可上线写模型,但 publisher 需开关控制 |
| query projection | GetMemberSummary / ListMembersByLifecycle 可重建 | 读入口只允许内部验证 |
| Gate policy mapping | 需要审批的 command 已配置 | 受控 command 默认关闭 |
| audit / observability | command、outbox、projection、tombstone 关键指标可见 | 不进入灰度 |
| memory / archive ref adapter | ref-only 写入和解析失败补偿路径明确 | memory ref / tombstone 能力延后开放 |

### 14.2 灰度路径

```
P0 Local / Dev
  - identity 单服务启动
  - 数据迁移与基础 Command API 验证
  |
  v
P1 Identity Core 内部灰度
  - GlobalMember lifecycle
  - RoleCatalogEntry 本地索引
  - CapabilityProfile / career_history
  - outbox 写入但可暂缓对外发布
  |
  v
P2 Read Projection 灰度
  - Console / Chat 只读接入
  - GetMemberSummary / ListMembersByLifecycle
  - projection lag / rebuild 验证
  |
  v
P3 Cross-domain 灰度
  - method-library role sync
  - work career entry 联动
  - bus consumer 幂等 replay
  |
  v
P4 Controlled Operations 灰度
  - governance GateDecisionRef
  - memory / archive ref adapter
  - tombstone flow 闭环
```

### 14.3 上线开关

| 开关 | 控制范围 | 默认策略 |
|---|---|---|
| identity.command.write.enabled | Command 写入口 | N1 内部开启,生产灰度逐步开启 |
| identity.outbox.publisher.enabled | outbox 对 bus 发布 | 可独立暂停,不得影响 write model |
| identity.projection.consumer.enabled | 读模型消费与重建 | 可暂停并触发 rebuild |

| identity.memory_ref.write.enabled | semantic / episodic ref 更新 | adapter 未稳定前关闭 |

### 14.4 回滚与降级策略

| 触发条件 | 等级 | 处理策略 | 不允许的处理 |
|---|---|---|---|
| lifecycle command 产生错误状态 | S | 立即停写,保留数据与 audit trace,人工修复或补偿 | 直接删除 append-only 记录 |
| outbox 发布错误事件 | S | 暂停 publisher,标记事件,修复后按 trace replay | 让 domain 直接绕过 outbox 重发 |
| projection 读模型错误 | A | 暂停 projection consumer,从 checkpoint 重建 | 手工改 projection 并反写真相 |
| role sync 错误 | A | 暂停 role sync,回到 last good RoleCatalogEntry | 复制 RoleDefinition 正文兜底 |
| Gate policy 配置错误 | A | 关闭受控 command 或回退 policy 配置 | 绕过 Gate 继续写敏感状态 |
| memory / archive ref 写错 | A | 暂停 adapter,保留失败证据,由补偿任务修正 ref | 把 memory 内容写入 identity |
| tombstone flow 失败 | S | 标记 failed / pending,进入人工审查 | 提前物理删除或假完成 |

### 14.5 监控与验收指标

| 指标 | 阈值 | 告警 | 验收意义 |
|---|---|---|---|
| Command 写入错误率 | > 0.1% | major | 判断写路径是否稳定 |
| lifecycle 非法迁移拒绝数 | 异常升高 | warning | 判断调用方或状态机是否异常 |
| outbox max pending age | > 30s 持续 10 分钟 | major | 判断事件发布是否阻塞 |
| projection lag | > 30s 持续 10 分钟 | major | 判断读模型是否可信 |
| RoleCatalogEntry source_drift | > 1 / day | major | 判断 role 契约是否漂移 |
| unauthorized write attempt | > 0 | major | 判断授权边界是否被触碰 |
| tombstone failed count | > 0 | critical | 判断销毁流程是否未闭环 |
| GetMemberSummary P95 | > 50ms | warning | 判断查询投影是否满足预算 |

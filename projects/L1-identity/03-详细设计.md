## 1. 模块职责描述

**本模块做什么**:
- 保存平台级 `GlobalMember` 真相与生命周期状态
- 维护 `RoleCatalogEntry` 本地索引,但不保存 `RoleDefinition` 正文
- 维护成员级 `CapabilityProfile`
- 以 append-only 方式记录 `career_history`
- 保存 semantic / episodic / archive memory refs,但不保存记忆原文或向量
- 提供 Command API、Query API、Inbound Event Consumer 和 Outbox Publisher 的实现骨架
- 通过 outbox 发布 identity 领域事件,通过 query projection 提供高频只读查询
- 为敏感操作记录 audit trace 和 `GateDecisionRef`

**本模块不做什么**:
- 不负责登录、token、session 或凭证校验;入口安全由 Gateway / API Layer 完成
- 不在查询接口里自动创建成员;创建必须走显式 command
- 不负责 `ProjectMember` 真相
- 不负责 `WorkItem` assignee 历史真相
- 不保存 `RoleDefinition` 正文
- 不保存 memory 原文、embedding 或检索索引
- 不直接承担 process / runtime 的业务状态正文
- 不把投影视图反向当成身份真相写源
- 不把项目级角色分配当成平台级角色真相

## 3. 代码目录结构

### 3.1 先按模块组织,再按文件展开

`03-详细设计` 优先采用“**先模块,后文件**”的写法。
不要一上来只堆完整目录树,否则新人容易看到很多文件名,却不知道这些文件共同支撑哪条主流程。

推荐顺序:
1. 先列技术分层:`inbound / application / domain / persistence / outbound / operations`
2. 再说明这些技术分层分别承接概要设计中的哪些交互链
3. 最后把目录树与文件职责对齐到主要部分、接口族和数据流

### 3.2 模块到概要交互链映射

| 技术模块 | 承接的概要交互链 / 主流程 | 服务的主要部分 | 主要职责 |
|---|---|---|---|
| `inbound/http_command_api` | Gateway / API Layer -> Command API | 全局成员真相与生命周期、角色索引与能力画像、记忆引用与归档协作 | 接收写请求,解析 payload,传递 `ActorContext`,调用 application service |
| `inbound/http_query_api` | Console / runtime / process -> Query API | 审计、事件与只读投影部分 | 接收查询请求,调用 query service,返回 projection DTO |
| `inbound/event_consumers` | method-library / work / process / memory / governance -> identity | 角色索引、项目生涯记录、记忆引用、Gate/Tombstone | 幂等消费外部事实事件,转成应用服务调用 |
| `application` | command / event / query 编排 | 所有主要部分 | 编排事务、domain、repository、outbound port、outbox |
| `domain` | 业务规则与不变量 | 全局成员真相、角色索引、能力画像、生涯、记忆引用、Gate 引用 | 维护 lifecycle、append-only、ref-only、Gate 约束等核心规则 |
| `persistence` | write model / append-only / outbox / projection | 全局成员真相、审计事件与只读投影 | 提供 repository、unit of work、outbox store、projection store |
| `outbound` | identity -> 外部模块 | 对外协作边界部分 | 封装 method-library、governance、memory/archive、L0-bus、audit sink 调用 |
| `operations` | replay / rebuild / reconciliation | outbox、projection、role catalog、tombstone | 提供 outbox replay、projection rebuild、role drift 对账、补偿任务 |

本表的阅读方式:
- `inbound` 与 `outbound` 都是 adapter,只处理协议、DTO 转换和外部依赖封装
- `application` 是用例入口,负责决定一次 command / query / event 处理要调用哪些 domain、repository、port 和 outbox
- `domain` 只放业务规则与不变量,不直接引用 HTTP、DB、MQ 或外部服务 SDK
- `persistence` 是本地数据事实与投影的落点,不定义业务语义
- `operations` 不参与在线业务决策,只承接可恢复任务,例如 replay、rebuild、reconciliation、compensation

- `tests` 按测试层级分目录,后续 `05-测试方案.md` 再展开具体测试矩阵

### 3.5 技术分层调用骨架

```text
Caller / External Event
        │
        ▼
Gateway / API Layer
        │
        │ trusted ActorContext
        ▼
Inbound Adapters
  - HTTP Command API
  - HTTP Query API
  - Event Consumers
        │
        ▼
Application Services
  - command / query / event use case orchestration
  - transaction boundary
  - repository + port + outbox coordination
        │
        ├──────────────▶ Domain Model
        │                 - lifecycle rules
        │                 - RoleCatalogEntry rules
        │                 - CapabilityProfile rules
        │                 - append-only career rules
        │                 - ref-only memory rules
        │                 - GateDecisionRef rules
        │
        ├──────────────▶ Persistence
        │                 - write model
        │                 - append-only records
        │                 - outbox
        │                 - query projection
        │
        └──────────────▶ Outbound Adapters
                          - method-library
                          - governance
                          - memory / archive
                          - L0-bus
                          - observability / audit
```

图例与边界:
- `▼` 表示同步调用或同一处理链上的控制流
- `├─▶` 表示 application service 对某一类内部能力的调用方向
- Gateway / API Layer 只在图外完成入口安全,进入 identity 后只传递可信 `ActorContext`
- Inbound Adapters 不能越过 application service 直接写 repository
- Domain Model 不能调用 Outbound Adapters,也不能发布 bus event
- Outbox event 由 application service 在事务内写入,由 `operations/outbox_publisher` 异步发布
- Query projection 是读优化结构,只能被 query service 读取,不能反向覆盖 write model

**总解释**:
- `L1-identity` 的实现主线不是“同步外部成员”,而是“显式 command / query / event 进入应用服务,由应用服务编排 domain、persistence、outbox、projection 与外部 port”
- `inbound` 只处理协议和输入转换,不写业务规则
- `application` 是用例编排中心,负责事务边界和 outbox 写入点
- `domain` 只维护业务规则,不依赖 HTTP、数据库、消息队列或外部服务
- `persistence` 负责 write model、append-only records、outbox 和 projection
- `outbound` 隐藏外部模块协议,避免外部协议泄漏进 domain

### 4.2 四类入口

| 入口类型 | 进入目录 | 典型入口 | 主要规则 |
|---|---|---|---|
| Command | `inbound/http_command_api` | `HireGlobalMember`、`UpdateLifecycle`、`UpdateCapabilityProfile`、`UpdateMemoryRefs`、`TombstoneMember` | 改写真相;必须有 `ActorContext`;事务内写 write model、append-only records、outbox |
| Query | `inbound/http_query_api` | `GetMemberSummary`、`GetRoleCatalog`、`GetMemberAuditTrace` | 只读;查询不到返回 NotFound;不得自动创建成员 |
| Inbound Event | `inbound/event_consumers` | `SyncRoleCatalog`、`AppendCareerEntry`、`HandleMemoryArchiveEvent`、`HandleGateDecisionEvent` | 幂等消费外部事实;必要时追加本地记录或更新本地状态 |
| Operations Job | `operations/*` | `PublishOutboxEvents`、`RebuildMemberSummaryProjection`、`ReconcileRoleCatalog` | 只基于已持久化事实恢复;不得绕过 application service 改写真相 |

### 4.3 写路径骨架

```text
HTTP Command / Inbound Event
  │
  ▼
Application Service
  │
  ├─ load / validate domain objects
  ├─ call domain member methods
  ├─ append history / audit records
  ├─ write outbox events
  └─ commit transaction
        │
        ▼
operations/outbox_publisher
        │
        ▼
L0-bus downstream consumers
```

### 4.4 读路径骨架

```text
HTTP Query
  │
  ▼
QueryProjectionService
  │
  ├─ read member_summary_projection
  ├─ read audit_trace_projection
  ├─ apply field trimming by caller policy
  └─ return DTO or NotFound
```

### 4.5 主流程约束

- `identity` 不做入口安全校验,只消费 Gateway / API Layer 注入的可信 `ActorContext`
- Command 与 Query 必须分离;Query 不得隐式创建成员
- Domain Model 不直接访问 DB、MQ、HTTP client 或外部服务 SDK
- 所有领域事件先写 outbox,再由 publisher 异步发布
- projection 是读优化结构,不能反向覆盖 write model
- `ProjectMember`、`RoleDefinition` 正文、memory 原文和 runtime state 都不属于 identity 真相

## 5. 按主要部分展开实现要点

### 5.1 为什么要先按主要部分展开

`03-详细设计` 不应直接从“字段表 / API / 表结构”开始。
在 Quantalithos 这类平台型系统中,更稳的写法是:
- 先承接 `02-概要设计.md` 已经确认的主要部分
- 再说明每个主要部分分别落到哪些对象、命令/函数、状态约束、存储与事件
- 最后再进入横向的对象模型、流程、存储、投影、异常与测试细节

> 这里的“主要部分”,不是“单个对象”或“单张表”。它应按 **独立职责 + 主交互链位置 + 稳定边界 + 真相/投影/事件/外部端口差异** 来组织。
> 同时还应区分三层函数: **对象成员函数**(维护不变量)、**静态/工厂函数**(创建、重建、从外部事实转入)、**应用服务函数**(组织事务、repo、port、outbox、projection)。

### 5.2 全局成员真相与生命周期部分

#### 5.2.1 该部分承接的概要输入
- 来自 `02` 的“全局成员真相与生命周期部分”
- `GlobalMember` 是平台级 AI member 的身份真相锚点
- `hired / active / paused / retired / tombstoned` 是 identity 自己维护的全局生命周期

- tombstone 必须引用 `GateDecisionRef`,不能由普通 lifecycle command 直接完成
- 查询接口只能读 projection 或 repository,查询不到返回 NotFound,不能隐式调用 hire

### 6.2 基础类型与引用类型约定

本节定义的是实现时需要统一理解的轻量类型。它们不是独立业务对象,主要用于避免把 ID、ref、hash、正文对象混成一层。

#### 6.2.1 ID 类型

| 类型 | 所属来源 | 含义 | 约束 |
|---|---|---|---|
| `GlobalMemberId` | identity | 全局成员 ID | identity 生成并拥有 |
| `CapabilityProfileId` | identity | 能力画像 ID | identity 生成并拥有 |
| `MemoryRefsId` | identity | memory refs 聚合 ID | identity 生成并拥有 |
| `CareerEntryId` | identity | career history entry ID | identity 生成并拥有 |
| `PendingFlowId` | identity | pending tombstone flow ID | identity 生成并拥有 |
| `OutboxEventId` | identity | outbox event ID | identity 生成并拥有 |
| `AuditTraceId` | identity | audit trace ID | identity 生成并拥有 |
| `DeadLetterId` | identity | dead-letter ID | identity 生成并拥有 |
| `RoleId` | method-library | role catalog 稳定 ID | 外部拥有,identity 只引用 |
| `ProjectId` | work | 项目 ID | 外部拥有,identity 只引用 |
| `EventId` | event source / bus | 来源事件 ID | 作为 inbound event 幂等键 |
| `GateDecisionId` | governance | Gate 决策 ID | 外部拥有,identity 只引用 |

约束:
- identity 拥有的 ID 可以作为本仓主键
- 外部拥有的 ID 只能作为弱引用或本地索引键,不能被 identity 重新解释为正文对象

#### 6.2.2 Ref 类型

| 类型 | 指向对象 | 正文归属 | identity 用途 |
|---|---|---|---|
| `ArtifactRef` | artifact / evidence | artifact 域 | 能力画像 evidence、role source 引用 |
| `MemoryRef` | memory 内容或索引 | memory 域 | semantic / episodic memory 引用 |
| `ArchiveRef` | archive job / cold storage result | memory / archive 域 | tombstone / 归档状态引用 |
| `WorkRef` | work 域对象 | work 域 | career history 记录 work 事实来源 |
| `ProcessRef` | process 域对象 | process 域 | career history 记录 process 事实来源 |
| `PolicyRef` | governance policy | governance 域 | Gate 决策证据引用 |
| `TargetRef` | 被操作对象 | 目标对象所属域 | audit trace 记录操作目标 |
| `ActorRef` | 操作者 | Gateway / identity context | 创建者、审计操作者引用 |
| `ResultRef` | command / event 处理结果 | 结果所属域 | 幂等记录复用既有结果 |

约束:
- `Ref` 只保存可追溯引用,不保存外部正文
- 需要验证 ref 是否存在时,通过 outbound port 完成,不能由 domain object 直接调用外部模块

#### 6.2.3 Hash / Version / Time 类型

| 类型 | 含义 | 用途 |
|---|---|---|
| `RequestHash` | command 或 event 入站 payload 指纹 | 幂等冲突判断 |
| `PayloadHash` | inbound event payload 指纹 | 事件去重和冲突判断 |
| `Fingerprint` | 外部定义或快照内容指纹 | role catalog source drift 检测 |
| `Version` | 乐观锁版本 | 防止并发覆盖 write model |
| `Timestamp` | 时间戳 | created / updated / occurred / decided 时间 |

约束:
- hash 只用于一致性和冲突判断,不能替代权限或业务状态判断
- `Version` 只保护并发写入,不表达 lifecycle 业务含义

#### 6.2.4 名称、分页与结果类型

| 类型 | 含义 | 用途 |
|---|---|---|
| `CommandName` | command 名称 | audit trace / metrics |
| `EventName` | event consumer 名称 | audit trace / metrics |
| `SourceModule` | 来源模块名 | inbound event、audit、dead-letter |
| `ActionName` | 高风险动作名 | governance Gate 请求 |
| `FailureReason` | 失败原因摘要 | audit、dead-letter、retry、archive failed |
| `CommandResult` | command 处理结果 | audit trace |
| `EventConsumeResult` | event 消费结果 | audit trace |

### 6.4 非本仓契约的最小消费字段视图

本节专门处理一类容易混淆的对象:
- 它们会出现在 identity 的函数签名、伪代码和适配层里
- 但它们不是 identity 自己拥有的真相对象
- identity 只声明“最小消费字段”,不在这里定义上游模块的完整 schema

边界原则:
- command / query DTO 由 API 契约或共享传输层拥有,identity 只消费本节列出的字段
- inbound event 先统一进入 `InboundEventEnvelope`;本节只定义 `payload` 的最小可解析视图
- 上游可以增加字段,但不能删除、重命名或改变这里已被 identity 消费字段的语义

```text
  v
```

### 6.6 真相 / 投影 / 执行 / 证据边界提示

| 对象 | 所属层 | 能否反向成为写源 | 典型误用 |
|---|---|---|---|
| `GlobalMember` | 真相层 | 是 | 把 `ProjectMember`、聊天用户或前台展示对象当全局真相 |
| `RoleCatalogEntry` | 本地索引层 | 否 | 把 role 索引当 `RoleDefinition` 正文 |
| `CapabilityProfile` | 真相层 | 是 | 把 runtime 临时能力推断直接写成永久能力 |
| `CareerEntry` / `CareerHistory` | append-only 记录层 | 只允许追加 | 让 identity 反向修正 work / process 事实 |
| `MemoryRefs` | 引用层 | 是 | 保存 memory 正文或 embedding |
| `PendingTombstoneFlow` | 运维 / 流程等待层 | 否 | 把 pending flow 当作 `GlobalMember` 真相本体 |
| `OutboxEvent` | 事件发布记录层 | 否 | 把 outbox 当业务状态源 |
| `IdempotencyRecord` | 幂等去重层 | 否 | 把幂等记录当业务审批结果 |
| `MemberSnapshot` | 投影组装输入层 | 否 | 修改 snapshot 试图回写真相 |
| `MemberSummaryProjection` | 投影层 | 否 | 直接修改摘要反写真相 |
| `AuditTraceEntry` | 审计层 | 否 | 用审计记录替代状态机 |
| `ActorContext` | 调用上下文层 | 否 | 在 identity 内做登录态或 token 校验 |
| `CommandMetadata` | 调用元信息层 | 否 | 把幂等键和 trace 当业务字段 |
| `InboundEventEnvelope` | 入站事件信封层 | 否 | 跳过 event consumer 直接进入 domain |
| `ProjectionCheckpoint` | 运维进度层 | 否 | 用 checkpoint 决定业务状态 |
| `InboundDeadLetter` | 失败事件留存层 | 否 | 把 dead-letter 当成功消费记录 |

### 6.7 关键数据结构生命周期图(异步资源必须标注)

```text
HireGlobalMember command
      |
      v
GlobalMember(hired)
      |
      +--> UpdateLifecycle -> active / paused / retired
      |
      +--> TombstoneMember + GateDecisionRef -> tombstoned
      |
      +--> RoleCatalogEntry ref check
      |
      +--> CapabilityProfile create/update
      |
      +--> CareerEntry append from work/process events
      |
      +--> MemoryRefs update / archive status
      |
      +--> OutboxEvent pending -> published / failed
      |
      +--> MemberSummaryProjection rebuild
```

> identity 这里要特别区分四种生命周期: `GlobalMember` 生命周期、append-only history 追加生命周期、outbox 发布生命周期、projection rebuild 生命周期。不要把它们混成一条状态线。

| 类型 | 入口 | 是否改写真相 | 是否产生 side effect | 说明 |
|---|---|---|---|---|
| HTTP Command API | `HireGlobalMember`、`UpdateLifecycle`、`UpdateCapabilityProfile`、`UpdateMemoryRefs`、`TombstoneMember` | 是 | 是 | 显式写接口,必须带 `ActorContext` 和 `CommandMetadata` |
| HTTP Query API | `GetMemberSummary`、`GetMemberAuditTrace`、`GetRoleCatalog` | 否 | 否 | 只读接口,查询不到返回 NotFound,不得自动创建成员 |
| Inbound Event Consumer | `SyncRoleCatalog`、`AppendCareerEntry`、`HandleMemoryArchiveEvent`、`HandleGateDecisionEvent` | 视事件而定 | 是 | 幂等消费外部事实事件,转换为本地记录或状态 |
| Outbox Publisher / Operations | `PublishOutboxEvents`、`RebuildMemberSummaryProjection`、`ReconcileRoleCatalog` | 否 | 是 | 基于已持久化事实发布、重建、对账 |

边界说明:
- identity 不做登录、token、session、credential 校验;入口安全在 Gateway / API Layer 完成
- create 和 get 必须分离;任何 query 都不能隐式创建成员
- 写路径统一由 application service 编排 domain、repository、outbox、audit
- 对外事件统一先写 outbox,再由 publisher 发布

伪代码注释规范:
- `// [对象.函数(参数对象 参数名)]` 表示对已有对象、服务、仓储或端口的成员函数调用
- `// [类型::函数(参数对象 参数名)]` 表示静态函数、工厂函数或构造函数调用
- 无参数调用统一写成 `// [对象.函数()]` 或 `// [类型::函数()]`
- 参数必须写出“对象类型 + 参数名”,例如 `// [CareerHistory.append(CareerEntry entry)]`
- 注释中必须说明该调用的用途
- `unit_of_work` 是 application service 持有的事务边界对象,不是 domain object

### 7.2 支撑组件最小接口

本节补齐伪代码中会用到、但不适合放进 §6.3 作为领域对象定义的支撑组件。

边界原则:
- repository / store 只负责持久化读写,不实现业务状态机
- parser / builder 只负责转换结构,不决定业务是否允许
- policy 只负责字段可见性或读取权限判断,不改写真相
- port 只隐藏外部协议,domain object 不能直接依赖 port
- `UnitOfWork` 只表达本地事务边界,不是业务对象

#### 7.2.1 事务与幂等

| 组件 | 所属层 | 最小函数 | 作用 |
|---|---|---|---|
| `UnitOfWork` | application infrastructure | `begin()`、`commit()`、`rollback()` | 包裹 write model、append-only、audit、outbox、idempotency 的本地事务 |
| `IdempotencyStore` | persistence port | `seen(IdempotencyKey key)`、`record_success(IdempotencyKey key, RequestHash hash, ResultRef result_ref)` | command / inbound event 去重和结果复用 |

约束:
- `record_success(...)` 必须与业务写入同事务提交
- `seen(...)` 只能做去重判断,不能替代业务状态校验

#### 7.2.2 Repository / Store

| 组件 | 所属层 | 最小函数 | 作用 |
|---|---|---|---|
| `GlobalMemberRepository` | persistence port | `get(id)`、`get_for_update(id)`、`insert(member)`、`save(member, expected_version)` | 读写 `GlobalMember` write model |
| `RoleCatalogRepository` | persistence port | `get_active(role_id)`、`list(filter)`、`upsert(entry)` | 读写本地 role catalog 索引 |
| `CapabilityProfileRepository` | persistence port | `get_for_update_by_member(member_id)`、`insert(profile)`、`save(profile, expected_version)` | 读写成员能力画像 |
| `MemoryRefsRepository` | persistence port | `get_for_update_by_member(member_id)`、`insert(memory_refs)`、`save(memory_refs)` | 读写成员 memory refs |
| `CareerHistoryRepository` | persistence port | `get_for_update(member_id)`、`save(history)` | 追加式保存成员 career history |
| `PendingTombstoneRepository` | persistence port | `get_by_gate_decision(gate_decision_id)`、`save(pending_flow)` | 读写等待 Gate 回流的 tombstone flow |
| `AuditTraceRepository` | persistence port | `append(entry)`、`list_by_member(member_id, page)` | 追加审计记录并提供审计查询 |
| `OutboxStore` | persistence port | `append(event)`、`list_pending(batch_size)`、`list_after(event_id)`、`save(event)` | 保存、扫描和更新 outbox event |
| `MemberSummaryProjectionRepository` | persistence port | `get(member_id)`、`upsert(projection)` | 读写成员摘要投影 |
| `ProjectionCheckpointRepository` | persistence port | `get_or_create(name)`、`save(checkpoint)` | 维护 projection rebuild checkpoint |
| `LifecycleHistory` | append-only store / domain history helper | `append(event)` | 追加生命周期历史事件 |

约束:
- repository 不能隐式创建 `GlobalMember`
- projection repository 不能反写 write model
- `OutboxStore.append(...)` 只能保存 application service 已经决定产生的事件

#### 7.2.3 Parser / Builder / Policy

| 组件 | 所属层 | 最小函数 | 作用 |
|---|---|---|---|
| `RoleCatalogEventParser` | inbound parser | `parse(Json payload)` | 把 method-library 事件 payload 转成 `RoleDefinitionSnapshot` |
| `MemoryArchiveEventParser` | inbound parser | `parse(Json payload)` | 把 memory/archive 事件 payload 转成 archive status update |
| `GateDecisionParser` | inbound parser | `parse(Json payload)` | 把 governance 事件 payload 转成 `GateDecisionRef` |
| `RoleCatalogDtoBuilder` | query DTO builder | `build(Vec<RoleCatalogEntry> entries)` | 构造 role catalog 查询返回 DTO |
| `MemberSummaryProjectionBuilder` | projection builder | `apply(OutboxEvent event)` | 基于 outbox event 计算成员摘要投影 |
| `FieldPolicy` | query policy | `trim_member_summary(projection, actor)`、`trim_audit_trace(traces, actor)` | 按调用方裁剪查询返回字段 |
| `AuditPolicy` | query policy | `can_view_member_trace(actor, member_id)` | 判断调用方是否可查看成员审计轨迹 |

约束:
- parser 失败进入 dead-letter 或返回明确错误,不能静默丢事件
- builder 只能生成 DTO / projection,不能改写 domain object
- policy 只能裁剪输出或拒绝读取,不能补写缺失字段

#### 7.2.4 外部端口补充

| 组件 | 所属层 | 最小函数 | 作用 |
|---|---|---|---|
| `ArtifactPort` | outbound port | `validate_refs(Vec<ArtifactRef> refs)` | 校验证据 artifact ref 是否存在且可引用 |
| `GovernancePort` | outbound port | `require_gate_decision(action, target, actor)` | 请求或校验高风险操作 Gate 决策 |
| `MemoryArchivePort` | outbound port | `validate_ref(ref)`、`request_archive(member_id, reason)` | 校验 memory ref 并请求归档 |
| `BusPublisherPort` | outbound port | `publish(event)` | 将 outbox event 发布到 L0-bus |

约束:
- outbound port 不把外部正文写入 identity domain
- 外部端口失败不能留下半提交的业务真相;写路径需按 §10 事务边界处理

### 7.3 总调用路径

#### 写路径

```text
HTTP Command / Inbound Event
      |
      v
Inbound Adapter
  - parse DTO / envelope
  - build ActorContext
  - build CommandMetadata
      |
      v
Application Service
  - check idempotency
  - load write model
  - call domain methods
  - append history / audit
  - write outbox
  - write idempotency result
      |
      v
UnitOfWork.commit()
      |
      v
Outbox Publisher -> L0-bus
```

幂等记录落库规则:
- `IdempotencyStore` 对应 §9 / §10 的 `idempotency_records`
- `seen(...)` 只代表读取既有记录;成功处理后必须写入或更新 `idempotency_records`
- command 成功路径必须把 `idempotency_key`、`request_hash`、`result_ref_json`、`status=succeeded` 与 write model / audit / outbox 放在同一个本地事务内提交
- inbound event 成功路径必须把 `source_event_id` 作为幂等键写入 `idempotency_records`,并与本地事实、audit、outbox 同事务提交
- 如果幂等键已存在但 `request_hash` 不一致,必须返回 `IDENTITY_IDEMPOTENCY_CONFLICT`,不能复用旧结果
- 如果事务回滚,不能留下 `succeeded` 幂等记录;允许保留 `failed` 或由重试重新进入 `processing`

#### 读路径

```text
HTTP Query
      |
      v
Inbound Query Adapter
  - build ActorContext
  - parse query
      |
      v
QueryProjectionService
  - read projection
  - apply field trimming
  - return DTO or NotFound
```

### 7.4 HTTP Command API

#### `HireGlobalMember`

| 项 | 内容 |
|---|---|
| 入口 | `POST /identity/global-members` |
| 应用服务函数 | `MemberLifecycleCommandService.hire_global_member(HireGlobalMemberCommand cmd, ActorContext actor, CommandMetadata meta)` |
| 主要部分 | 全局成员真相与生命周期 |
| 输入 | `display_name`、`main_role_id`、`secondary_role_ids?`、`initial_capabilities?`、`initial_memory_refs?` |
| 返回 | `GlobalMember` 摘要或 `global_member_id` |
| side effect | 创建 `GlobalMember`;可创建初始 `CapabilityProfile` / `MemoryRefs`;写 outbox 与 audit |

伪代码:

```text
hire_global_member(cmd, actor, meta):
  # 作用:
  #   显式创建一个平台级 GlobalMember。
  #   它是创建入口,不能被查询接口或事件消费流程隐式触发。

  1. assert meta.idempotency_key exists
     # 关键时机:进入写流程前先检查幂等键,避免重复创建成员。
     // [CommandMetadata.idempotency_key()]
     // 用途:读取 command 幂等键,用于去重和 outbox 关联。

  2. role_entry = role_catalog_repo.get_active(cmd.main_role_id)
     # 关键时机:事务前先校验 role 是否有效,减少无效写事务。
     // [RoleCatalogRepository.get_active(RoleId main_role_id)]
     // 用途:读取可用 RoleCatalogEntry,作为 GlobalMember 主角色引用。

  3. if role_entry missing:
       return IDENTITY_ROLE_NOT_FOUND

  4. if idempotency_store.seen(meta.idempotency_key):
       return previous_result
     # 关键时机:构造领域对象前判断是否已处理过同一 command。
     // [IdempotencyStore.seen(IdempotencyKey idempotency_key)]
     // 用途:避免同一创建请求重复生成 GlobalMember。

  5. member = GlobalMember.hire(cmd, role_entry, actor)
     # 关键时机:由 domain factory 建立对象,集中执行创建不变量。
     // [GlobalMember::hire(HireGlobalMemberCommand cmd, RoleCatalogEntry role_entry, ActorContext actor)]
     // 用途:创建 GlobalMember 聚合并校验创建不变量。

  6. unit_of_work.begin()
     # 关键时机:从这里开始,write model / history / audit / outbox 必须同事务提交。
     // [UnitOfWork.begin()]
     // 用途:开启本地事务边界。

  7. global_member_repo.insert(member)
     // [GlobalMemberRepository.insert(GlobalMember member)]
     // 用途:持久化新成员真相。

  8. if cmd.initial_capabilities exists:
       profile = CapabilityProfile.create_for_member(member.id, cmd.initial_capabilities, actor)
       // [CapabilityProfile::create_for_member(GlobalMemberId member_id, Vec<CapabilityItem> initial_items, ActorContext actor)]
       // 用途:创建成员初始能力画像。
       capability_profile_repo.insert(profile)
       // [CapabilityProfileRepository.insert(CapabilityProfile profile)]
       // 用途:持久化能力画像。
       member.link_capability_profile(profile.id)
       // [GlobalMember.link_capability_profile(CapabilityProfileId profile_id)]
       // 用途:把成员与能力画像引用关联起来。
       # 关键时机:初始能力画像必须与成员创建在同一事务内建立引用。

  9. if cmd.initial_memory_refs exists:
       memory_refs = MemoryRefs.create_empty(member.id)
       // [MemoryRefs::create_empty(GlobalMemberId member_id)]
       // 用途:为成员创建空 memory refs 聚合。
       memory_refs.apply_initial_refs(cmd.initial_memory_refs, actor)
       // [MemoryRefs.apply_initial_refs(InitialMemoryRefs initial_refs, ActorContext actor)]
       // 用途:写入初始 memory ref,不写 memory 正文。
       memory_refs_repo.insert(memory_refs)
       // [MemoryRefsRepository.insert(MemoryRefs memory_refs)]
       // 用途:持久化 memory refs 聚合。
       member.link_memory_refs(memory_refs.id)
       // [GlobalMember.link_memory_refs(MemoryRefsId memory_refs_id)]
       // 用途:把成员与 memory refs 引用关联起来。
       # 关键时机:初始 memory refs 只保存 ref,并与成员创建保持一致。

  10. lifecycle_history.append(member.created_event(actor, meta))
      # 关键时机:成员创建事实必须追加到历史记录,用于审计和重放。
      // [LifecycleHistory.append(DomainEvent created_event)]
      // 用途:追加成员创建历史。
      // [GlobalMember.created_event(ActorContext actor, CommandMetadata meta)]
      // 用途:生成成员创建领域事件。

  11. audit_repo.append(AuditTraceEntry.for_command("HireGlobalMember", actor, member.ref, success))
      # 关键时机:记录是谁创建了成员,不能只依赖业务表字段。
      // [AuditTraceEntry::for_command(CommandName command_name, ActorContext actor, TargetRef target, CommandResult result)]
      // 用途:构造 command 审计记录。
      // [AuditTraceRepository.append(AuditTraceEntry audit_trace_entry)]
      // 用途:追加审计记录。

  12. outbox_store.append(OutboxEvent.from_domain_event(member.created_event, meta.idempotency_key))
      # 关键时机:事件只写 outbox,不在事务内直接发布到 bus。
      // [OutboxEvent::from_domain_event(DomainEvent event, IdempotencyKey idempotency_key)]
      // 用途:构造待发布 outbox 事件。
      // [OutboxStore.append(OutboxEvent outbox_event)]
      // 用途:在本地事务内保存待发布事件。

  13. idempotency_store.record_success(meta.idempotency_key, meta.request_hash, member.ref)
      # 关键时机:成功结果必须与成员真相和 outbox 同事务落库。
      // [IdempotencyStore.record_success(IdempotencyKey idempotency_key, RequestHash request_hash, ResultRef result_ref)]
      // 用途:写入 command 幂等成功记录,供重复请求返回既有结果。

  14. unit_of_work.commit()
      # 关键时机:commit 成功后,成员真相、history、audit、outbox 同时可见。
      // [UnitOfWork.commit()]
      // 用途:提交本地事务。

  15. return member.summary()
      # 关键时机:返回写模型摘要,外部读侧摘要可由 projection 后续刷新。
      // [GlobalMember.summary()]
      // 用途:构造 command 返回摘要。
```

#### `UpdateLifecycle`

| 项 | 内容 |
|---|---|
| 入口 | `POST /identity/global-members/{global_member_id}/lifecycle` |
| 应用服务函数 | `MemberLifecycleCommandService.update_lifecycle(UpdateLifecycleCommand cmd, ActorContext actor, CommandMetadata meta)` |
| 主要部分 | 全局成员真相与生命周期 |
| 输入 | `global_member_id`、`target_lifecycle`、`reason` |
| 返回 | 更新后的成员摘要 |
| side effect | 更新 lifecycle;追加 history;写 outbox 与 audit |

伪代码:

```text
update_lifecycle(cmd, actor, meta):
  # 作用:
  #   修改 GlobalMember 的普通生命周期状态。
  #   tombstone 是高风险流程,必须走 TombstoneMember。

  1. unit_of_work.begin()
     # 关键时机:生命周期变更需要锁读取、保存、history、audit、outbox 同事务。
     // [UnitOfWork.begin()]
     // 用途:开启 lifecycle 写事务。

  2. member = global_member_repo.get_for_update(cmd.global_member_id)
     # 关键时机:使用 for_update 防止并发生命周期迁移互相覆盖。
     // [GlobalMemberRepository.get_for_update(GlobalMemberId global_member_id)]
     // 用途:带锁读取成员真相。

  3. if member missing:
       return IDENTITY_MEMBER_NOT_FOUND

  4. if not member.can_transition_to(cmd.target_lifecycle):
       return IDENTITY_LIFECYCLE_TRANSITION_INVALID
     # 关键时机:迁移判断必须在 domain object 上完成,避免规则散落。
     // [GlobalMember.can_transition_to(GlobalMemberLifecycle target_lifecycle)]
     // 用途:判断 lifecycle 迁移是否合法。

  5. match cmd.target_lifecycle:
       active  -> member.activate(actor)
                  // [GlobalMember.activate(ActorContext actor)]
                  // 用途:进入 active 状态。
       paused  -> member.pause(actor, cmd.reason)
                  // [GlobalMember.pause(ActorContext actor, LifecycleReason reason)]
                  // 用途:进入 paused 状态。
       retired -> member.retire(actor, cmd.reason)
                  // [GlobalMember.retire(ActorContext actor, LifecycleReason reason)]
                  // 用途:进入 retired 状态。
       tombstoned -> return IDENTITY_USE_TOMBSTONE_COMMAND
     # 关键时机:只允许普通 lifecycle 迁移;tombstone 强制进入 Gate 流程。

  6. global_member_repo.save(member, expected_version=cmd.expected_version)
     # 关键时机:保存时校验 expected_version,防止旧请求覆盖新状态。
     // [GlobalMemberRepository.save(GlobalMember member, Version expected_version)]
     // 用途:乐观锁保存成员状态。

  7. lifecycle_history.append(member.lifecycle_changed_event(actor, meta))
     # 关键时机:状态变化必须可追溯。
     // [LifecycleHistory.append(DomainEvent lifecycle_changed_event)]
     // 用途:追加 lifecycle 变化历史。
     // [GlobalMember.lifecycle_changed_event(ActorContext actor, CommandMetadata meta)]
     // 用途:生成生命周期变化事件。

  8. audit_repo.append(AuditTraceEntry.for_command("UpdateLifecycle", actor, member.ref, success))
     // [AuditTraceEntry::for_command(CommandName command_name, ActorContext actor, TargetRef target, CommandResult result)]
     // 用途:构造审计记录。
     // [AuditTraceRepository.append(AuditTraceEntry audit_trace_entry)]
     // 用途:追加审计记录。

  9. outbox_store.append(OutboxEvent.from_domain_event(member.lifecycle_changed_event, meta.idempotency_key))
     # 关键时机:下游收缩通过 outbox 事件驱动,不是同步改写下游真相。
     // [OutboxEvent::from_domain_event(DomainEvent event, IdempotencyKey idempotency_key)]
     // 用途:构造 lifecycle outbox 事件。
     // [OutboxStore.append(OutboxEvent outbox_event)]
     // 用途:保存待发布事件。

  10. idempotency_store.record_success(meta.idempotency_key, meta.request_hash, member.ref)
      // [IdempotencyStore.record_success(IdempotencyKey idempotency_key, RequestHash request_hash, ResultRef result_ref)]
      // 用途:写入 lifecycle command 幂等成功记录。

  11. unit_of_work.commit()
      // [UnitOfWork.commit()]
      // 用途:提交 lifecycle 写事务。

  12. return member.summary()
      // [GlobalMember.summary()]
      // 用途:返回更新后的成员摘要。
```

#### `UpdateCapabilityProfile`

| 项 | 内容 |
|---|---|
| 入口 | `PUT /identity/global-members/{global_member_id}/capability-profile` |
| 应用服务函数 | `CapabilityProfileService.update_capability_profile(UpdateCapabilityProfileCommand cmd, ActorContext actor, CommandMetadata meta)` |
| 主要部分 | 角色索引与能力画像 |
| 输入 | `global_member_id`、`capabilities`、`evidence_refs`、`expected_version` |
| 返回 | `CapabilityProfile` 摘要 |

伪代码:

```text
update_capability_profile(cmd, actor, meta):
  # 作用:
  #   更新成员能力画像。
  #   能力画像是 identity 的持久事实,不是 runtime 临时推断。

  1. unit_of_work.begin()
     // [UnitOfWork.begin()]
     // 用途:开启能力画像写事务。

  2. member = global_member_repo.get(cmd.global_member_id)
     # 关键时机:先确认成员存在,能力画像不能脱离 GlobalMember。
     // [GlobalMemberRepository.get(GlobalMemberId global_member_id)]
     // 用途:读取成员真相并确认成员存在。

  3. if member missing:
       return IDENTITY_MEMBER_NOT_FOUND

  4. if member.lifecycle.is_terminal():
       return IDENTITY_MEMBER_NOT_MUTABLE
     # 关键时机:终态成员不允许再更新能力画像。
     // [GlobalMemberLifecycle.is_terminal()]
     // 用途:判断成员是否已处于不可变终态。

  5. profile = capability_profile_repo.get_for_update_by_member(cmd.global_member_id)
     # 关键时机:锁定 profile,防止并发能力更新互相覆盖。
     // [CapabilityProfileRepository.get_for_update_by_member(GlobalMemberId global_member_id)]
     // 用途:带锁读取成员能力画像。

  6. if profile missing:
       profile = CapabilityProfile.create_for_member(cmd.global_member_id, [], actor)
       # 关键时机:首次更新时允许创建空画像,但必须显式 command 触发。
       // [CapabilityProfile::create_for_member(GlobalMemberId member_id, Vec<CapabilityItem> initial_items, ActorContext actor)]
       // 用途:为已有成员创建空能力画像。

  7. artifact_port.validate_refs(cmd.evidence_refs)
     # 关键时机:保存前校验证据引用,identity 只保存 ref 不保存正文。
     // [ArtifactPort.validate_refs(Vec<ArtifactRef> evidence_refs)]
     // 用途:校验证据引用存在且可被当前调用使用。

  8. profile.replace_capabilities(cmd.capabilities, cmd.evidence_refs, actor)
```

```text
      // 用途:追加 tombstone 历史。
      // [GlobalMember.tombstoned_event(ActorContext actor, GateDecisionRef gate_ref, CommandMetadata meta)]

      // [AuditTraceRepository.append(AuditTraceEntry audit_trace_entry)]
      // 用途:追加审计记录。

      // 用途:构造 tombstone outbox 事件。
      // [OutboxStore.append(OutboxEvent outbox_event)]
      // 用途:保存待发布事件。

  14. idempotency_store.record_success(meta.idempotency_key, meta.request_hash, member.ref)
      // [IdempotencyStore.record_success(IdempotencyKey idempotency_key, RequestHash request_hash, ResultRef result_ref)]
      // 用途:写入 tombstone command 幂等成功记录。

  15. unit_of_work.commit()
```

### 7.7 Outbound Event / Operations

#### Outbox 发布

| 操作 | 函数 | 说明 |
|---|---|---|
| 扫描待发布事件 | `outbox_store.list_pending(BatchSize batch_size)` | 只读取 `pending` 事件 |
| 发布事件 | `bus_publisher_port.publish(OutboxEvent event)` | 对接 L0-bus |
| 标记成功 | `outbox_event.mark_published(Timestamp now)` | 更新发布状态 |
| 标记失败 | `outbox_event.mark_failed(FailureReason reason)` | 保留失败原因和重试次数 |

伪代码:

```text
publish_outbox_events(batch_size):
  # 作用:
  #   将本地 outbox 中的 pending event 发布到 L0-bus。
  #   它不能创造业务事件,只能发布已经持久化的事件。

  1. events = outbox_store.list_pending(batch_size)
     # 关键时机:只扫描 pending 事件,避免重复发布已完成事件。
     // [OutboxStore.list_pending(BatchSize batch_size)]
     // 用途:批量读取待发布事件。

  2. for event in events:
       try:
         bus_publisher_port.publish(event)
         # 关键时机:事务外发布,避免外部 bus 影响业务写事务。
         // [BusPublisherPort.publish(OutboxEvent event)]
         // 用途:发布 outbox event 到 L0-bus。

         event.mark_published(now)
         # 关键时机:发布成功后才标记 published。
         // [OutboxEvent.mark_published(Timestamp now)]
         // 用途:更新事件发布状态。

       catch error:
         event.mark_failed(error.reason)
         # 关键时机:失败时保留原因和 retry 状态,供 replay 使用。
         // [OutboxEvent.mark_failed(FailureReason reason)]
         // 用途:记录发布失败原因和重试状态。

       outbox_store.save(event)
       // [OutboxStore.save(OutboxEvent event)]
       // 用途:保存 outbox 发布状态。

  3. return publish_summary
```

#### Projection rebuild

```text
rebuild_member_summary_projection(checkpoint_name):
  # 作用:
  #   基于已持久化事件重建 MemberSummaryProjection。
  #   projection 是读模型,不能反向修改 write model。

  1. checkpoint = checkpoint_repo.get_or_create(checkpoint_name)
     # 关键时机:先读取 checkpoint,确保 rebuild 可以断点续跑。
     // [ProjectionCheckpointRepository.get_or_create(CheckpointName checkpoint_name)]

  2. events = outbox_store.list_after(checkpoint.last_processed_event_id)
     # 关键时机:只处理 checkpoint 之后的事件,避免重复全量扫描。
     // [OutboxStore.list_after(EventId last_processed_event_id)]
     // 用途:读取 checkpoint 之后的事件。

  3. for event in events:
       snapshot = projection_builder.apply(event)
       # 关键时机:事件只影响读模型快照,不修改 GlobalMember 真相。
       // [MemberSummaryProjectionBuilder.apply(OutboxEvent event)]

       // 用途:写入或更新成员摘要投影。

       checkpoint.advance_to(event.outbox_event_id)
       // [ProjectionCheckpoint.advance_to(EventId outbox_event_id)]
       // 用途:推进 rebuild 进度。
       checkpoint_repo.save(checkpoint)
       # 关键时机:每处理成功一个事件就推进 checkpoint,保证可恢复。
       // [ProjectionCheckpointRepository.save(ProjectionCheckpoint checkpoint)]
       // 用途:持久化 checkpoint。
```

### 8.3 场景 B · 生命周期变更: `UpdateLifecycle`

函数作用:
- 修改成员普通生命周期
- 允许 `hired / active / paused / retired` 之间的受控迁移
- 不处理 `tombstoned`,墓碑化必须走 `TombstoneMember`

```text

      |

      +--> global_members save(expected_version)
      |
      +--> lifecycle_history_entries append
      |
      +--> audit_trace_entries append
      |
      +--> outbox_events append: identity.member.lifecycle_changed
      |
      v
UnitOfWork.commit()
```

开发者关注点:
- lifecycle 迁移规则属于 domain object,不要散落在 application service
- `ProjectMember` 只能消费 lifecycle event,不能反写 `GlobalMember`
- 保存时必须使用版本检查,避免旧请求覆盖新状态

### 8.4 场景 C · 墓碑化高风险流程: `TombstoneMember`

函数作用:
- 执行成员不可逆墓碑化
- 获取或校验 governance Gate 决策
- 请求 memory/archive 执行归档协作
- 更新 `GlobalMember` 与相关 `MemoryRefs` 状态

```text

      |

      |
      +--> audit_trace_entries append

      v
UnitOfWork.commit()
```

开发者关注点:
- `tombstoned` 是不可逆终态
- Gate 决策引用必须进入 history / audit / outbox 证据链
- identity 只请求归档并保存 archive ref,不执行 memory/archive 的正文归档

函数作用:

## 9. 数据与存储设计

### 9.1 数据分层原则

identity 的数据层分成五类,每一类的写入来源和使用方式不同。

```text
Command / Inbound Event
      |
      v
write model tables
  - global_members
  - role_catalog_entries
  - capability_profiles
  - memory_refs
      |
      +--> append-only records
      |      - lifecycle_history_entries
      |      - career_history_entries
      |      - audit_trace_entries
      |
      +--> reliable event records
      |      - outbox_events
      |      - idempotency_records
      |      - pending_tombstone_flows
      |
      v
query / operations tables
  - member_summary_projection
  - projection_checkpoints
  - inbound_dead_letters
```

| 数据层 | 是否是真相 | 写入来源 | 说明 |
|---|---|---|---|
| write model | 是 | Command / Event Consumer | 当前业务状态,由 repository 持久化 |
| append-only records | 是,但只追加 | Command / Event Consumer | 历史、审计、生涯记录,不能覆盖旧记录 |
| outbox / idempotency | 发布与去重事实 | Application Service / Operations | 保证可靠发布和幂等处理 |
| query projection | 否 | Projection Builder | 高频查询视图,可重建,不能反写真相 |
| operations records | 否 | Operations Job / Consumer | checkpoint、dead-letter、replay 状态 |

### 9.2 表与对象映射总览

| 表 / 集合 | 承载对象 | 数据层 | 主要写入口 |
|---|---|---|---|
| `global_members` | `GlobalMember` | write model | `HireGlobalMember` / `UpdateLifecycle` / `TombstoneMember` |
| `role_catalog_entries` | `RoleCatalogEntry` | write model / local index | `SyncRoleCatalog` / `ReconcileRoleCatalog` |

| `updated_at` | `timestamp` | 投影更新时间 | not null |

### 9.7 不落库内容

| 内容 | 不落库原因 | 正确做法 |
|---|---|---|
| 登录 token / session / credential secret | identity 不做身份校验 | Gateway / API Layer 持有 |
| `RoleDefinition` 正文 | 属于 method-library | 只保存 `source_ref_json` 和 `fingerprint` |
| memory 原文 / embedding / 检索索引 | 属于 memory / archive | 只保存 `MemoryRef` / `ArchiveRef` |
| work / process 原始对象正文 | 外部域真相 | 只保存 `WorkRef` / `ProcessRef` 和最小摘要 |
| projection 反向修正字段 | projection 非真相 | 通过 rebuild 从 write model / outbox 重建 |

### 10.3 事务边界

| 流程 | 同事务内必须写入 | 事务外动作 |
|---|---|---|
| `HireGlobalMember` | `global_members`、可选 `capability_profiles` / `memory_refs`、`lifecycle_history_entries`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | outbox 发布 |
| `UpdateLifecycle` | `global_members`、`lifecycle_history_entries`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | outbox 发布 |
| `TombstoneMember` | `global_members`、可选 `memory_refs`、`lifecycle_history_entries`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | memory/archive 执行、outbox 发布 |
| `UpdateCapabilityProfile` | `capability_profiles`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | evidence 正文读取不在 identity 内发生 |
| `UpdateMemoryRefs` | `memory_refs`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | memory/archive 引用校验可以在事务前完成 |
| `AppendCareerEntry` | `career_history_entries`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | projection rebuild |
| `SyncRoleCatalog` | `role_catalog_entries`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | method-library 正文查询 |
| `HandleGateDecisionEvent` | `pending_tombstone_flows`、`audit_trace_entries`、`outbox_events`、`idempotency_records` | 不得直接改写 `global_members` |

事务原则:
- write model、append-only、audit、outbox、idempotency 必须在一个本地事务里提交
- 外部 bus 发布不能放在业务事务内
- projection rebuild 不能和 command 写事务混在一起
- query API 不开启写事务,也不能隐式创建 write model

### 10.4 并发控制

| 对象 / 表 | 并发策略 | 冲突处理 |
|---|---|---|
| `global_members` | `version` 乐观锁 + 必要时 `get_for_update` | 返回 `IDENTITY_VERSION_CONFLICT` 或按最新状态重新判断 |
| `capability_profiles` | `version` 乐观锁 | 调用方重新读取后再提交 |
| `memory_refs` | `version` 乐观锁 + archive 状态迁移检查 | 拒绝乱序归档状态 |
| `career_history_entries` | `source_event_id` 唯一约束 | 重复事件返回 skipped |
| `outbox_events` | publisher 按 batch claim pending 记录 | 发布失败标记 failed 并设置 `next_retry_at` |
| `projection_checkpoints` | checkpoint row 锁 | 同一 projection 只允许一个 rebuild worker 推进 |

### 10.5 outbox 与 projection 重建顺序

```text
command transaction committed
      |
      v
outbox_events(status=pending)
      |
      +--> OutboxPublisher
      |      - publish to L0-bus
      |      - mark published / failed
      |
      +--> ProjectionRebuild
             - read outbox_events after checkpoint
             - apply to member_summary_projection
             - advance projection_checkpoints
```

顺序要求:
- projection 可以读取 `pending` 或 `published` outbox,但必须以 checkpoint 保证幂等
- bus 发布失败不能回滚 write model
- projection rebuild 失败只更新 checkpoint / dead-letter,不能修改 write model

### 10.6 初始 schema 落地原则

当前还没有开始开发,本节不展开历史数据迁移方案。第一版实现应把 §9 的表结构作为初始 schema,重点保证初始模型清晰、边界正确、后续实现不被旧模型污染。

| 原则 | 说明 |
|---|---|
| 先按当前对象模型建表 | `GlobalMember`、`RoleCatalogEntry`、`CapabilityProfile`、`MemoryRefs`、append-only、outbox、projection 是第一版主干 |
| 核心状态字段结构化 | `lifecycle`、`archive_status`、`outbox.status`、`version` 等必须是明确字段,不能只塞进 JSON |
| JSON 只承载 refs / summary / payload | `source_ref_json`、`evidence_refs_json`、`payload_json` 等保存引用或载荷快照,不保存外部正文真相 |
| 初始约束一次建清楚 | 主键、唯一约束、幂等键、`global_member_id` 维度唯一关系在第一版就建立 |
| 不提前设计复杂演进机制 | 第一批开发先保证模型可实现、可测试、可审计,后续真实 schema 演进再单独补文档 |

### 10.7 数据设计红线

- 不建立 `credential_bindings`、`platform_roles` 这类旧模型表作为 identity 第一批主干
- 不把 `RoleDefinition`、memory 正文、work/process 正文保存进 identity 表
- 不允许 projection 表被 command service 当成写源
- 不允许 dead-letter replay 绕过 application service 直接改 write model
- 不允许 outbox publisher 自行创造业务事件

## 11. 异常、并发、一致性与性能设计

本节只处理当前 command / query / inbound event / outbox / projection 架构下的失败模式。
旧的外部认证绑定、成员自动同步、下游成员分身回写等模型不再作为 identity 第一批实现的异常主线。

### 11.1 异常分类总览

```text
Request / Event / Job
      |
      v
Classify Failure
      |
      +--> Business rejection
      |      - member not found
      |      - lifecycle invalid
      |      - role not found
      |      - Gate rejected
      |
      +--> Idempotency / concurrency
      |      - duplicate same hash
      |      - duplicate different hash
      |      - version conflict
      |      - locked row conflict
      |
      +--> External dependency
      |      - method-library unavailable
      |      - governance unavailable
      |      - memory/archive unavailable
      |      - artifact ref invalid
      |
      +--> Event / operations
             - payload parse failed
             - outbox publish failed
             - projection rebuild failed
             - dead-letter replay failed
```

| 异常类别 | 典型入口 | 是否重试 | 是否进入 dead-letter | 处理原则 |
|---|---|---|---|---|
| 业务拒绝 | Command / Query | 否 | 否 | 返回明确错误码,调用方修正输入 |
| 幂等重复且 hash 相同 | Command / Event | 否 | 否 | 返回既有结果或 skipped |
| 幂等键冲突且 hash 不同 | Command / Event | 否 | Event 可进 dead-letter | 返回 `IDENTITY_IDEMPOTENCY_CONFLICT` |
| 乐观锁 / 行锁冲突 | Command / Operations | 可重试 | 否 | 调用方重新读取后再提交,job 可退避重试 |
| 入站事件解析失败 | Inbound Event | 否 | 是 | 保存原始 payload 与失败原因 |
| 外部依赖暂不可用 | Command / Event | 视场景 | Event 可进 dead-letter | 不写半成品真相,必要时 pending / retry |
| outbox 发布失败 | Operations | 是 | 否 | 不回滚 write model,标记 failed 后重试 |
| projection 构建失败 | Operations / Query | 是 | 否 | 保留 checkpoint,query 可返回 not ready |

### 11.2 Command 异常处理

Command 是显式写入口,失败处理必须遵守三条规则:
- 不隐式创建成员
- 不绕过 domain 状态机
- 不在本地事务提交前发布外部事件

```text
HTTP Command
      |
      v
CommandMetadata
      |
      v
IdempotencyStore.seen(idempotency_key)
      |
      +-- same key + same hash -----> return previous_result
      |
      +-- same key + different hash -> IDENTITY_IDEMPOTENCY_CONFLICT
      |
      v
Domain Validation
      |
      +-- invalid ------------------> business error
      |
      v
Local Transaction
  - write model
  - history / audit
  - outbox
  - idempotency record
      |
      v
commit
```

| Command | 主要失败点 | 错误码 / 结果 | 恢复策略 |
|---|---|---|---|
| `HireGlobalMember` | role 不存在 | `IDENTITY_ROLE_NOT_FOUND` | 先执行 `SyncRoleCatalog` 或修正 role id |
| `HireGlobalMember` | 幂等键冲突 | `IDENTITY_IDEMPOTENCY_CONFLICT` | 返回旧结果或更换幂等键 |
| `UpdateLifecycle` | member 不存在 | `IDENTITY_MEMBER_NOT_FOUND` | 调用方修正 id,不得自动创建 |
| `UpdateLifecycle` | lifecycle 迁移非法 | `IDENTITY_LIFECYCLE_TRANSITION_INVALID` | 调用方重新选择目标状态 |
| `UpdateLifecycle` | tombstone 目标走错入口 | `IDENTITY_USE_TOMBSTONE_COMMAND` | 改走 `TombstoneMember` |
| `UpdateCapabilityProfile` | evidence ref 无效 | `IDENTITY_ARTIFACT_REF_INVALID` | 修正 evidence ref 后重试 |
| `UpdateMemoryRefs` | memory ref 无效 | `IDENTITY_MEMORY_REF_INVALID` | 修正 ref 后重试 |
| `TombstoneMember` | Gate 未批准 | `IDENTITY_GATE_REJECTED` | 停止 tombstone 或重新发起治理流程 |
| `TombstoneMember` | memory/archive 暂不可用 | `IDENTITY_MEMORY_ARCHIVE_UNAVAILABLE` | 不进入 tombstoned,稍后重试 |

事务回滚规则:
- 只要 write model、history、audit、outbox、idempotency 任一关键写入失败,整个 command 事务必须回滚
- 回滚后不能留下 `status=succeeded` 的 `idempotency_records`
- 外部 bus 发布不在 command 事务内执行,因此 bus 失败不能影响 command commit

### 11.3 Query 异常与降级

Query 只能读取 projection 或 append-only 审计记录,不能触发写入、重建或成员创建。

| Query | 失败点 | 返回 | 说明 |
|---|---|---|---|
| `GetMemberSummary` | projection 不存在 | `IDENTITY_MEMBER_NOT_FOUND` 或 `IDENTITY_PROJECTION_NOT_READY` | 如果 write model 存在但 projection 未追上,返回 not ready 更准确 |
| `GetMemberAuditTrace` | 调用方不可见 | `IDENTITY_AUDIT_TRACE_NOT_VISIBLE` | 只做字段裁剪或拒绝读取 |
| `GetRoleCatalog` | 本地索引为空 | 空列表 | 不实时拉取 method-library 正文 |

降级原则:
- projection 延迟不能导致 command 失败
- query 不负责修复 projection
- 如需修复,由 `RebuildMemberSummaryProjection` 运维任务处理

### 11.4 Inbound Event 异常处理

Inbound Event 是外部事实进入 identity 的入口,处理重点是幂等、解析、dead-letter 和 replay。

```text
Raw Event
      |
      v
InboundEventEnvelope::parse(raw_event)
      |
      +-- parse failed -----------> inbound_dead_letters
      |
      v
IdempotencyStore.seen(source_event_id)
      |
      +-- same hash --------------> skipped
      |
      +-- different hash ---------> dead-letter / idempotency conflict
      |
      v
Application Service
      |
      +-- business target missing -> dead-letter
      |
      v
Local Transaction
  - local fact update / append
  - audit
  - outbox
  - idempotency record
```

| Event Consumer | 失败点 | 处理策略 | replay 条件 |
|---|---|---|---|
| `SyncRoleCatalog` | payload 解析失败 | dead-letter | 修复 payload / parser 后 replay |
| `SyncRoleCatalog` | method-library 正文不可用 | retry 或 dead-letter | method-library 恢复后 replay |
| `AppendCareerEntry` | member 不存在 | dead-letter | 成员被显式创建后可 replay |
| `AppendCareerEntry` | source_event_id 重复 | skipped | 不需要 replay |
| `HandleMemoryArchiveEvent` | memory refs 不存在 | dead-letter | 补齐 refs 或确认忽略 |
| `HandleMemoryArchiveEvent` | archive 状态乱序 | dead-letter 或 skipped | 根据 archive_ref 和 occurred_at 判断 |
| `HandleGateDecisionEvent` | pending flow 不存在 | skipped 或 record-only | 后续不自动触发 tombstone |

dead-letter 必须保存:
- `source_event_id`
- `source_module`
- `event_type`
- `payload_json`
- `failure_reason`
- `replay_status`
- `created_at`

### 11.5 Outbox / Bus 异常处理

outbox 的目标是保证“业务事实已经提交”和“事件最终能发布”解耦。

```text
Command / Event Transaction
      |
      v
outbox_events(status=pending)
      |
      v
PublishOutboxEvents
      |
      +-- publish success -> mark published
      |
      +-- publish failed  -> mark failed + retry_count + next_retry_at
```

处理规则:
- outbox event 只能由 command / event 本地事务创建
- `PublishOutboxEvents` 不能创造新的业务事件
- L0-bus 发布失败不能回滚 `GlobalMember`、`CapabilityProfile`、`MemoryRefs` 等 write model
- publisher 失败后只更新 outbox 状态,不修改业务真相
- retry 必须使用 outbox 自身的 `idempotency_key`

| 状态 | 含义 | 下一步 |
|---|---|---|
| `pending` | 已提交,待发布 | publisher 扫描 |
| `published` | 已成功发布 | 不再发布 |
| `failed` | 最近一次发布失败 | 退避后重试 |
| `dead` | 达到最大重试或被人工终止 | 人工处理或指定 replay |

### 11.6 Projection 异常处理

projection 是只读优化结构,不是身份真相。

```text
outbox_events
      |
      v
ProjectionRebuild
      |
      v
MemberSummaryProjectionBuilder.apply(event)
      |
      +-- failed -> keep checkpoint unchanged
      |
      v
member_summary_projection.upsert(snapshot)
      |
      v
checkpoint.advance_to(event_id)
```

处理规则:
- projection 构建失败不能修改 write model
- checkpoint 只能在单个 event 成功应用后推进
- query 可以返回 `IDENTITY_PROJECTION_NOT_READY`
- projection 可通过 `RebuildMemberSummaryProjection` 从 outbox / write model 重建
- projection 字段错误时,优先 rebuild,不能直接手改 projection 当成真相修复

### 11.7 外部依赖异常处理

| 外部模块 | 调用入口 | 失败影响 | 处理策略 |
|---|---|---|---|
| method-library | role catalog 同步 / role 校验 | 新成员创建可能因 role 不存在被拒绝 | 不复制 RoleDefinition 正文;等待同步或重试 |
| governance | `TombstoneMember` / Gate event | tombstone 不能继续 | Gate unavailable 时不进入 tombstoned |
| memory / archive | `UpdateMemoryRefs` / `TombstoneMember` / archive event | memory refs 或归档状态无法确认 | 不保存无效 ref;归档失败保留状态并告警 |
| artifact | `UpdateCapabilityProfile` evidence ref 校验 | 能力画像无法保存证据引用 | 拒绝更新,调用方修正 evidence refs |
| L0-bus | outbox publish | 下游延迟感知 identity 事件 | outbox failed + retry,不回滚业务事实 |

外部依赖调用边界:
- 外部依赖返回的正文不能直接成为 identity 真相
- identity 只保存稳定 ref、snapshot 摘要或 fingerprint
- 不把外部服务调用放进必须长期持锁的代码段

### 11.8 并发控制

| 对象 / 流程 | 并发策略 | 冲突处理 |
|---|---|---|
| `GlobalMember` 普通更新 | `version` 乐观锁 | 返回版本冲突,调用方重新读取 |
| lifecycle / tombstone | `get_for_update` + 状态机校验 | 后到请求按最新状态重新判断 |
| `CapabilityProfile` | `version` 乐观锁 | 返回冲突,调用方重新提交 |
| `MemoryRefs` | `get_for_update_by_member` + archive 状态迁移校验 | 拒绝乱序归档状态 |
| `CareerHistory` | `source_event_id` 唯一约束 + 事务内重复检查 | 重复事件 skipped |
| `OutboxPublisher` | batch claim pending event | 同一 outbox event 只能被一个 worker 发布 |
| `ProjectionRebuild` | checkpoint row lock | 同一 projection 同时只允许一个 worker 推进 |
| `RoleCatalogEntry` | role_id upsert | 后到 snapshot 覆盖本地索引,保留 source fingerprint |

并发红线:
- 不允许两个 command 在不知道对方结果的情况下覆盖 `GlobalMember.lifecycle`
- 不允许 tombstone 与普通 lifecycle update 并行落成互相覆盖
- 不允许 projection rebuild 反向修正 write model

### 11.9 一致性语义

| 范围 | 一致性级别 | 说明 |
|---|---|---|
| 单个 command 本地写入 | 本地事务强一致 | write model、history、audit、outbox、idempotency 同事务 |
| inbound event 本地处理 | 本地事务强一致 | 本地事实更新、audit、outbox、idempotency 同事务 |
| identity -> 下游模块 | 事件最终一致 | 下游通过 L0-bus 消费 outbox event |
| query projection | 最终一致 | projection 可能滞后 write model |
| memory/archive 归档 | 跨模块最终一致 | identity 保存 archive ref / status,不保存正文 |
| Gate 决策 | 跨模块协作一致 | governance 负责决策真相,identity 保存 GateDecisionRef |

本地事务写集:

```text
Command / Event Local Transaction
      |
      +-- write model
      +-- append-only history
      +-- audit_trace_entries
      +-- outbox_events
      +-- idempotency_records
```

不进入本地事务的动作:
- 发布 L0-bus
- projection rebuild
- dead-letter replay
- 外部模块正文修复
- 长耗时归档处理

### 11.10 性能与降级

| 场景 | 性能策略 | 降级策略 |
|---|---|---|
| 高频成员摘要查询 | 读取 `member_summary_projection` | projection 未就绪返回 not ready |
| command 写入 | 只写本地必要事实和 outbox | 外部发布异步化 |
| role 查询 | 读取本地 `role_catalog_entries` | 不实时拉 method-library 正文 |
| career history | append-only + 分页查询 | 大列表走分页,不在 summary 中全量展开 |
| outbox 发布 | batch 扫描 + retry backoff | bus 失败时保留 failed 状态 |
| projection rebuild | checkpoint 增量处理 | 失败时从 checkpoint 继续 |
| archive 协作 | 保存 ref/status | 归档正文和检索由 memory/archive 承担 |

性能红线:
- `GetMemberSummary` 不能实时拼装全部 write model、career history 和外部模块正文
- command 不能等待 outbox 被 bus 成功发布后才返回
- event consumer 不能在同一事务内执行长耗时外部修复
- projection rebuild 不能持有 write model 锁

## 12. 实现红线 / 开发禁止事项

本节是开发实现时必须遵守的禁止事项。
如果代码实现违反本节,即使单测通过,也应视为架构偏离。

### 12.1 入口与职责红线

| 禁止事项 | 原因 | 正确做法 |
|---|---|---|
| Query 自动创建 `GlobalMember` | 破坏 create / get 分离 | 创建必须走 `HireGlobalMember` |
| identity 内部做 token / session / credential 校验 | 入口安全属于 Gateway / API Layer | identity 只消费可信 `ActorContext` |
| Event consumer 直接写数据库 | 绕过 application service 和事务规则 | 事件必须转成 application service 调用 |
| Operations job 直接改业务真相 | replay / rebuild 可能绕过不变量 | job 只能基于已持久化事实恢复 |
| Outbox publisher 创造业务事件 | publisher 不是业务决策点 | 业务事件只能由 command / event 事务写入 outbox |

### 12.2 真相层红线

| 禁止事项 | 原因 | 正确做法 |
|---|---|---|
| `ProjectMember` 回写 `GlobalMember` | 项目级成员不是平台级成员真相 | work / process 只能引用 `GlobalMemberId` |
| `WorkItem` / process 反写 identity 生命周期 | lifecycle 属于 identity | 外部模块通过事件表达事实,identity 自己消费 |
| projection 反向覆盖 write model | projection 不是真相 | 从 outbox / write model rebuild projection |
| audit / summary 被当成写源 | 审计和摘要只读 | 写入必须经过 command / event use case |

### 12.3 外部正文与 ref-only 红线

| 禁止事项 | 原因 | 正确做法 |
|---|---|---|
| 保存 `RoleDefinition` 正文 | 正文属于 method-library | identity 保存 `RoleCatalogEntry` 摘要、ref、fingerprint |
| 保存 memory 原文、embedding 或检索索引 | 正文和索引属于 memory / archive | identity 只保存 `MemoryRef` / `ArchiveRef` |
| 保存 work / process 对象正文 | 外部域真相不能被复制 | identity 只保存 career entry 所需摘要和来源 ref |
| 把 external auth / org source 字段塞进主模型 | identity 不做认证源绑定 | 外部安全信息留在 Gateway / API Layer 或专门安全层 |

### 12.4 事务与一致性红线

| 禁止事项 | 原因 | 正确做法 |
|---|---|---|
| command 事务内直接发布 L0-bus | 外部发布失败会污染本地事务 | 先写 outbox,再异步发布 |
| write model 与 outbox 分开提交 | 会造成事实已变但事件丢失 | write model / audit / outbox / idempotency 同事务 |
| `idempotency_records` 成功记录晚于业务提交 | 重试时可能重复写入 | 成功记录与业务事实同事务提交 |
| tombstone 跳过 Gate | tombstone 是不可逆高风险状态 | 必须保存 `GateDecisionRef` |
| 长耗时外部调用持有 write model 锁 | 放大锁冲突和超时 | 外部校验尽量在事务前,长任务异步化 |

测试组织应按入口族和横切风险组织,不要按数据库表逐个堆测试。

## 14. 最小可运行闭环

第一版最小闭环的目标是验证 identity 主干可运行,不是一次性覆盖全部高风险增强流程。
因此第一批必须优先打通“显式创建、生命周期、role 索引、outbox、projection 查询”。

### 14.1 第一批必须闭环

```text
SyncRoleCatalog
      |
      v
RoleCatalogEntry ready
      |
      v
HireGlobalMember
      |
      +--> global_members
      +--> lifecycle_history_entries
      +--> audit_trace_entries
      +--> outbox_events
      +--> idempotency_records
      |
      v
PublishOutboxEvents
      |
      v
RebuildMemberSummaryProjection
      |
      v
GetMemberSummary
```

| 闭环 | 必须打通的函数 | 验证内容 |
|---|---|---|
| role catalog 准备 | `SyncRoleCatalog`、`GetRoleCatalog` | 本地 role 索引可写、可查、可幂等消费 |
| 成员显式创建 | `HireGlobalMember` | 成员只能由 command 创建,不能由 query 创建 |
| 生命周期更新 | `UpdateLifecycle` | 普通 lifecycle 迁移由 domain 状态机约束 |
| 事件发布 | `PublishOutboxEvents` | outbox event 能可靠发布或标记失败 |
| 摘要投影 | `RebuildMemberSummaryProjection`、`GetMemberSummary` | projection 可重建、可查询、可延迟降级 |
| 审计追踪 | `GetMemberAuditTrace` | command / event 处理可审计 |

### 14.2 第一批增强闭环

第一批主干稳定后,再进入增强闭环:

| 增强闭环 | 函数 | 进入条件 |
|---|---|---|
| 能力画像 | `UpdateCapabilityProfile` | artifact ref 校验端口稳定 |
| memory refs | `UpdateMemoryRefs`、`HandleMemoryArchiveEvent` | memory/archive ref 契约稳定 |
| tombstone / Gate | `TombstoneMember`、`HandleGateDecisionEvent` | governance Gate 契约稳定 |
| career history | `AppendCareerEntry` | work / process 事实事件契约稳定 |
| 对账恢复 | `ReconcileRoleCatalog`、dead-letter replay | operations 基础设施稳定 |

### 14.3 最小闭环验收线

第一批最小闭环完成时,至少应证明:
- `GlobalMember` 能被显式创建并持久化
- lifecycle 能被合法更新且非法迁移被拒绝
- role catalog 能从 method-library 事件进入本地索引
- outbox 能保存、发布、失败重试
- projection 能从已持久化事实重建
- query 能从 projection 读取摘要,且不会自动创建成员
- audit trace 能证明每次 command / event 的处理来源

## 15. 结论

本详细设计的核心结论是:
- `L1-identity` 不是认证系统,不负责 token、session、credential 校验
- `L1-identity` 不是项目成员系统,不保存 `ProjectMember` 真相
- `L1-identity` 不是外部成员自动同步器,成员创建必须显式走 `HireGlobalMember`
- `L1-identity` 的核心职责是维护平台级 `GlobalMember` 真相、生命周期、role catalog 本地索引、能力画像、career history、memory refs、audit、outbox 和 query projection
- 实现结构应按 `inbound / application / domain / persistence / outbound / operations` 分层
- 写入口应按 Command API、Inbound Event Consumer 和 Operations job 分开处理
- 读入口应只读取 projection 或 append-only records,不能反向创建或修复 write model
- 事件发布必须采用 outbox,跨模块协作默认是最终一致
- 外部模块正文只能通过 ref、snapshot 或 fingerprint 被引用,不能复制成 identity 真相
- 后续 `05-测试方案.md` / `06-验收标准.md` 应围绕 command、query、event、outbox、projection、ref-only 和架构红线建立测试与验收映射

> 校准来源:

> 延伸阅读:

### 3.1 语言、runtime 与主要依赖

本仓按 Rust 实现约束展开。当前实现仓 reality check 是 Rust edition `2024`,并已出现 `axum`、`tokio`、`serde`、`serde_json`、`sqlx`、`thiserror`、`time`、`tower` 等依赖线索。它们只作为当前实现 reality 和外层约束,不等于所有 crate 都可直接依赖。

| 约束 | 正式口径 |
|---|---|
| 默认语言 | Rust |
| Rust edition | `2024` |
| async runtime | Tokio 仅能在入口、infra、worker、jobs 等外层使用;domain 不依赖 runtime |
| HTTP / inbound | Axum 可用于 API entry;handler / route 只做 mapping 和 dispatch |
| durable persistence | SQLx 只能进入 infra / persistence adapter;domain 和 public contracts 不依赖 SQLx |
| serialization | `serde` / `serde_json` 可用于 public DTO / marker / evidence,不得成为保存 forbidden body 的理由 |
| error helper | `thiserror` 可用于内部错误;public rejection / error DTO 由协议与错误章节定义 |
| unsafe | 默认不使用;若后续确需使用,必须单独设计安全不变量、封装边界和测试切口 |

### 3.2 Rust 编码规范承接

实现仓源码标识符、模块名、类型名、函数名、变量名、测试名、rustdoc 和普通注释默认使用英文。设计文档可以中文说明契约,但 Step 6~8 中出现的 Rust 片段应使用英文代码与英文注释。

公开 crate / module 使用 `//!` 说明职责、边界和禁止事项。public struct、enum、enum variant、trait 和 function 使用 `///` 说明语义、字段来源、不变量、错误、side effect 和 fake parity。公开 enum variant 不得省略注释。domain 层对象、policy 和状态迁移应保持同步纯逻辑;async 边界放在 application / infra / handler / jobs。

### 3.3 仓库与依赖裁剪

项目 slug 是 `identity`。代码内部不得使用 `l1_identity`、`L1Identity`、`quantalithos_identity` 作为 module / crate / type 前缀。设计路径可以保留 `L1-identity`;实现仓目录是 `/home/aris/Projects/quantalithos-identity`。

当前已确认的编译期依赖候选只有 `L0-core` 的 shared contracts crate:

```toml
core-contracts = { path = "../quantalithos-core/crates/contracts" }
```

该 dependency 应放在 workspace root `[workspace.dependencies]`,member 通过 `core-contracts.workspace = true` 引用。`quantalithos-bus`、method-library、work、governance、memory / archive、observability、runtime 和 downstream consumers 都不得作为 Cargo path dependency 写入 business crate;只能通过 resolver port、event envelope、publisher adapter、handoff adapter、projection consumer 或 config binding 表达。

### 3.4 安全与外部边界

本仓不实现认证、账号、token、session、credential、secret truth、授权 / 治理裁决 truth、API gateway、Project / WorkItem / ProjectMember truth、RoleDefinition / CapabilityDefinition body、memory body、embedding、archive package、artifact body、conversation body、runtime body、raw log、外部来源正文复制、共享数据库事务或跨仓 truth 修复。

缺来源时必须进入 rejected、pending、stale、unavailable、degraded 或 report-only surface,不得用默认值伪造成功。

### 3.5 实施前置约束

实施者开始前必须阅读 Rust 编码规范、项目目录组织规范、全局依赖裁剪规则、实施计划书写规范中的 git config / 提交约束,以及目标实现仓近期合格提交记录。项目级 git config 要求:


### 4.5 文件职责边界

`contracts` 文件定义 DTO、typed ref、public marker、view、event payload、job input / output、receipt 和 public error。`domain` 文件定义 truth object、state enum、policy、guard、domain change 和 domain error。`application` 文件定义 service、port trait、command result assembly、idempotency / stored result boundary 和 transaction orchestration。`infra` 文件定义 repository implementation、in-memory fake、external resolver adapter、publisher / handoff adapter、projection store、reference store、report writer 和 runtime wiring。`api`、`worker`、`jobs` 只做 runtime entry、handler dispatch 和 wiring。

### 4.6 Dependency

workspace root 统一声明 `core-contracts` path dependency。运行期 / 事件协作仓库不进入 Cargo dependency。正式依赖方向摘要:

```text
identity-api / identity-worker / identity-jobs -> identity-application -> identity-domain -> identity-contracts -> core-contracts
identity-infra -> identity-application / identity-domain / identity-contracts
```

图表达 crate dependency direction,不表达函数调用时序。

### 5.2 模块职责

| 模块 | 允许承接 | 禁止承接 |
|---|---|---|
| `identity-contracts` | public request / response / event / job / view / receipt / error schema;typed refs and markers | domain policy、repository trait、adapter implementation、SQLx / Axum / Tokio wiring |
| `identity-domain` | truth object、state enum、policy、guard、domain change、domain error | repository implementation、external resolver、handler、job runner、runtime config |

| `identity-infra` | durable / fake repository、resolver adapter、publisher / handoff adapter、projection store、report writer、runtime config binding | business invariant、new public DTO、direct handler logic |
| `identity-api` | route、handler、request context mapping、service dispatch | business transition、repository access、event publish、projection rebuild |
| `identity-worker` | event / callback intake mapping、consumer loop、service dispatch | external truth ownership、domain transition outside service、store bypass |
| `identity-jobs` | job arg parsing、run metadata / scope / cursor mapping、service dispatch | business truth mutation outside service、silent remediation、store bypass |

### 5.3 依赖方向

允许依赖方向:

```text
api / worker / jobs -> application -> domain -> contracts -> core-contracts
api / worker / jobs -> infra -> application / domain / contracts
infra -> application / domain / contracts
```

禁止方向:

- `contracts` 不依赖任何 identity 内部 crate。
- `domain` 不依赖 `application`、`infra`、`api`、`worker`、`jobs`、SQLx、Axum、Tokio、bus 或相邻业务仓 implementation。
- `application` 不依赖 `infra`、`api`、`worker`、`jobs` 或 durable adapter implementation。
- `infra` 不定义业务规则、不新增 domain invariant、不反向修改 domain state。
- `api` / `worker` / `jobs` 不直接访问 repository implementation,必须经 application service。

### 5.6 Trait / Port / Adapter 归属规则

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源:
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 Command、Query、Inbound / Callback、Outbound Event 和 Operations Job 协议面。

### 7.1 协议契约边界

本章定义 API / Command / Query / Event / Job 的 public protocol surface。协议契约采用分批停审方式执行:先建立 shared protocol helper 和协议总表,再分别展开 Command、Query、Inbound Event Consumer / Callback、Outbound Event 和 Operations Job,最后进行跨协议 public surface 审计。

每个协议必须定义实际需要的 request、response、result、view、page、marker、payload、receipt、report DTO schema,并说明字段来源、缺失处理、empty、not visible、degraded、rejected、duplicate、stale、missing、retryable、permanent failed 等 public surface。Step 8 不得新增 Step 6/7 没有来源的 DTO 字段,不得让 public DTO 直接依赖 domain-only type,不得把 application-local helper 暴露为 public contracts。

### 7.2 Shared Protocol Helper

Shared protocol helper 定义 public protocol naming、metadata、digest、command outcome、query surface、public page DTO、protocol rejection、consumer receipt、outbound event envelope 和 job report surface。Step 7 的 `IdentityRepositoryPage`、`Page<T>`、`IdentityOperationContext`、stored result 和 facade dispatch 均为 application-local surface,不得直接暴露到 public DTO;Step 8 通过 public page、metadata、digest、result、receipt、report shell 建立正式映射。

所有 protocol surface 均使用 HLD 已审核名称作为 canonical name。Command、Query、Inbound Consumer / Callback、Outbound Event 和 Operations Job 均建立 HLD name -> Request / Payload / Result / View / Receipt / Report DTO -> handler target -> Step 9 flow 的一对一映射。后续批次和实现不得再引入同义接口名。

### 7.3 Command Protocols

| Command | Request / result 口径 | 关键闭环 |
|---|---|---|
| `EstablishGlobalMember` | request 只承载 optional requested member ref、body-free source ref、optional anchor reason 和 initial lifecycle reason;accepted typed result 返回 member ref、anchor state、initial lifecycle state 和 source ref;accepted effect summary 只由 `IdentityCommandResponse<T>.effect` 承载 | DTO 能构造 `IdentityAnchorPolicy::for_create(...)`、`GlobalMember::establish(...)`、`GlobalLifecycleState::initial_available(...)` |
| `UpdateGlobalLifecycleState` | request 承载 member ref、target lifecycle state、reason、optional governance basis 和 optional action risk;accepted typed result 返回 lifecycle state、reason、optional basis 和 optional anchor state;accepted effect summary 只由 `IdentityCommandResponse<T>.effect` 承载 | 高风险处置必须通过 `GovernanceBasisSummary` 证明 basis valid for action risk |
| `MaintainRoleCapabilitySummary` | request 承载 member ref、summary/source/evidence/safe summary/reason/material marker;accepted typed result 返回 summary、snapshot、source/evidence refs 和 safe marker;accepted effect summary 只由 `IdentityCommandResponse<T>.effect` 承载 | source/evidence validity 来自 resolver summary;不保存 RoleDefinition / CapabilityDefinition / evidence body |
| `AppendCareerRecord` | request 承载 member、append/correction intent、work participation/source marker、safe summary、reason、optional original record 和 material marker | duplicate source 不新增 history;correction 追加新 record;不保存 Project / WorkItem / ProjectMember body |
| `MaintainMemoryReference` | request 承载 member、memory reference/change intent、memory/archive/handoff refs、source、safe summary、reason 和 material marker | 不保存 memory body、embedding、archive package、receipt body 或 external carrier truth |
| `PrepareTraceHandoff` | request 承载 member、非空 trace refs、optional audit trail、target/scope、safe material、visibility context 和 reason | 只创建 pending intent,不执行 delivery;Delivered 只能由 formal `HandoffReceiptRef` 驱动 |

### 7.4 Query Protocols

Query 均沿用 `IdentityQueryRequest<T>`、`IdentityQueryResponse<T>`、`IdentityPageResponse<T>` 和 `IdentityQuerySurface`。`visibility_context_ref` 来自 `IdentityQueryMetadata`;read subject、scope、access summary 和 stable view ref 必须来自 Step 7 visibility / projection lookup port,不得从 route、member id、view id 或 source token 拼接。

Core truth query 包括 `GetGlobalMemberAnchor`、`GetGlobalLifecycleSummary`、`GetRoleCapabilitySummary`、`ListCareerRecords`、`ListMemoryReferences`。这些 query 只返回 typed refs、state kind、safe summary marker、reason/basis marker 和 optional projection slice refs;missing、empty、not visible、degraded、stale visible 均通过 `IdentityQuerySurface` 表达,不得创建 truth、刷新外部 source、rebuild projection、mark fresh、append trace/audit/outbox 或返回外部正文。

Trace / audit / summary query 包括 `ReadMemberSummary`、`ReadIdentityTrace`、`ReadAuditTrail`。它们必须先 resolve visibility,再通过正式 repository / projection lookup 读取 view、trace 或 audit page。Trace after-cursor 只能使用 `IdentityTruthCursor`,不得与 public page cursor 混用。Audit read 当前限定为 member canonical audit subject;若未来需要聚合子 truth audit trail,必须新增正式聚合规则或读取面。

Maintenance / outbox / handoff query 包括 `GetProjectionState`、`GetReferenceResolutionState`、`ReadReconciliationReport`、`ListPendingIdentityOutbox`、`GetIdentityOutboxState`、`GetTraceHandoffState`。它们只读取 state、report、outbox 或 handoff view,不得 rebuild、refresh、generate report、publish、retry、deliver 或查询下游消费状态。

### 7.5 Inbound Event / Callback Protocols

五条 inbound event / callback protocol 均沿用 `IdentityInboundEventEnvelope<T>` 和 `IdentityConsumerReceipt`。Envelope 承载 consumer name、envelope marker、binding ref、source event ref、idempotency key、schema version、occurred/received time、trace context 和 typed payload。`source_event_ref` 与 `idempotency_key` 是 duplicate guard 的正式输入,payload hash、broker offset 或 raw callback body 不得替代。

| Consumer / Callback | Payload 口径 |
|---|---|
| `HandleRoleCapabilitySourceChanged` | role/capability source ref、source version/state、safe summary、evidence、reference bundle、reason 和 material marker;不保存 method/evidence/scoring body |
| `HandleWorkParticipationAccepted` | member、project participation、work source、career source marker、safe summary、reason 和 material marker;不保存 Project / WorkItem / ProjectMember body |
| `HandleMemoryReferenceSourceStateChanged` | memory reference/source/ref state/safe summary/reference bundle/reason/material marker;不保存 memory body、embedding、archive package 或 carrier truth |
| `HandleArchiveHandoffResult` | memory relation or handoff target、archive ref、archive handoff ref、target relation state、issue/reason/material marker;不保存 archive package 或 receipt body |
| `HandleTraceHandoffResult` | handoff intent、target/scope、attempt、result kind、receipt/issue marker;Delivered 必须带 `HandoffReceiptRef` |

### 7.6 Outbound Event Protocols

十条 outbound event 均沿用 `IdentityOutboundEventEnvelope<T>`。Envelope 承载 event name、event ref、outbox record ref、topic key、schema version、payload marker、trace ref、published subject ref 和 typed payload。Payload DTO 不重复 envelope 字段,只承载 event-specific refs、state kind、safe summary marker、reason/basis marker 和 accepted cursor。

Outbound event 只能来自 accepted identity fact 的 outbox material。Publisher 后续只能使用 saved outbox record、topic binding 和 payload marker,不得回读 current truth 重构 event。Step 8 只闭合 payload DTO 与 body-free marker 的协议真相;若后续需要 durable serialized envelope snapshot,必须在 persistence / idempotency Step 正式定义 marker -> snapshot 的保存、读取和 replay surface。

### 7.7 Operations Job Protocols

六条 operations job 均沿用 `IdentityJobRequest<T>`、`IdentityJobResponse<T>` 和 `IdentityJobReportSurface`。Job request 承载 job name、run ref、metadata marker、scope marker、idempotency key、optional job cursor、schema version、system actor 和 typed input;job response 返回 stored result ref、typed output 和 replayable report surface。

| Job | Protocol 口径 |
|---|---|
| `RebuildIdentityProjection` | 通过 explicit projection refs 或 maintenance scope 选择 target,输出 rebuilt/failed projection refs、report refs、issue refs 和 counts |
| `RefreshExternalReferenceState` | 选择 `ExternalReferenceRef` bundle,输出 refreshed/failed reference refs;business source ref 或 source version 不得当 bundle key/version |
| `RunIdentityReconciliation` | 承载 maintenance scope、target scope、finding intent 和 body-free finding material;report-only policy 禁止 repair truth |
| `PublishIdentityOutbox` | 按 topic/page 读取 pending outbox,经 topic binding 和 publisher outcome 更新 outbox state;Published 不代表 downstream consumed |
| `DeliverTraceHandoff` | 选择 handoff intent,经 target resolution 和 delivery outcome 更新 handoff state;Delivered 必须带 formal receipt |
| `RetryIdentityPropagationFailures` | 单次只选择 outbox retryable 或 handoff retryable 一种 family,组合调度留配置/运行层 |

Job duplicate replay 必须读取 stored job report surface 和 `IdentityJobRunReport` item refs,不得重跑 job body或重扫 repository 反推 item refs。

### 7.8 Cross-Protocol Audit Rules

Step 8 cross protocol audit 确认所有 command、query、inbound consumer/callback、outbound event 和 operations job 的 public secondary types 均有 owner、字段 schema、closure source 和 Step 9 flow 入口。Public DTO 不暴露 domain-only object、application-local `IdentityOperationContext`、repository `Page<T>` 或 raw adapter/config/body。

若 flow 或实现需要额外字段、状态、port、stored result variant、visibility mapping、reference bundle version、payload snapshot 或 job report item refs,必须回 Step 6/7/8 对应批次闭口,不得在 function flow 或实现阶段自行补 schema、port、状态或 boundary。

## 8. 逐接口函数级处理流

> 校准来源:

> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 command、query、consumer/callback、outbound material 和 operations job 的函数级处理流。

### 8.1 Flow Coverage

本章逐接口定义 command、query、inbound consumer/callback、outbound publish material 和 operations job 的函数级处理流。所有 flow 均从第 7 章 protocol DTO 出发,回指第 5/6 章 object、state、policy、port、repository、resolver、publisher、handoff、stored result 和 application facade。

Step 9 覆盖 6 个 Command flow、14 个 Query flow、5 个 Inbound Event Consumer / Callback flow、10 个 Outbound Event accepted material 审计和 6 个 Operations Job flow。十条 outbound event 不各自拥有独立 publish flow,它们在 accepted transaction 内创建 outbox material,统一由 `PublishIdentityOutboxFlow` 发布。

### 8.2 Command Write Discipline

Command 写路径必须在同一 UnitOfWork 中完成 idempotency reserve、truth transition、accepted cursor、trace/audit/outbox/projection stale、stored result 和 idempotency complete。通用顺序是:

```text
validate entry / canonical digest
  -> begin UnitOfWork
  -> reserve idempotency
  -> load current truth / versioned state
  -> run domain policy / transition helper
  -> save truth / append-only material
  -> assign accepted truth cursor
  -> append trace / audit / outbox / projection stale / effect summary
  -> save stored result
  -> complete idempotency
  -> commit
```

Rejected branch 不写 accepted truth、success trace、outbox 或 projection stale。只有 Step 12/13 判定可 replay 的 rejected surface 才保存 stored rejected result。Duplicate replay 只能读取 stored result,不得重跑 mutation。

### 8.3 Query No-Write Discipline

All query flows are read-only and visibility-first. Query missing/stale/degraded material is surfaced through `IdentityQueryResponse` / `IdentityPageResponse`;queries never trigger projection rebuild,reference refresh,reconciliation generation,outbox publish,handoff delivery,retry,trace append,audit repair or stored result save.

Query priority 固定为:visibility unavailable -> `Degraded`;not visible -> `NotVisible` without leaking existence;exact requested object missing -> `Missing`;visible list empty -> `Empty`;loaded item missing/mismatch -> degraded partial;all loaded list items denied -> `NotVisible`;mixed visible/denied -> redacted partial。字段级 redaction 和 transport mapping 由错误 / 测试章节承接。

### 8.4 Consumer / Callback Discipline

Consumer and callback flow 必须使用 envelope 的 `source_event_ref`、`idempotency_key` 和 canonical digest reserve idempotency。Duplicate replay 必须读取 typed `IdentityConsumerReceiptEnvelope` 并返回 stored `receipt`;consumer 使用 `get_consumer_receipt(...)`,callback 使用 `get_handoff_callback_receipt(...)`。`StoredIdentityOperationResult` 只是 stored shell,不能单独重建 public receipt。

Unsupported schema 在 payload parse 前失败,不得写 application store。Forbidden body rejected、transient dependency delayed、missing/untrusted/manual-review quarantined、source duplicate noop 和 accepted mutation 都必须通过正式 receipt / issue surface 表达。Callback target 冲突必须 rejected/quarantined;missing target 不创建 relation。

### 8.5 Outbound Accepted Material

Accepted outbox material is created only from accepted command/consumer/callback facts. Accepted flow 保存 truth/state 后分配 truth cursor,通过 `IdentityTruthChangeSubjectMapper` 得到 outbox subject,构造 body-free payload marker,再保存初始 `PendingPublish` 的 `IdentityOutboxRecord`。Payload marker 必须绑定 event name、schema version、topic key、subject、trace 和 cursor。

`OutboxState::Published` represents outbound publish boundary only and does not prove downstream consumption. Publisher 不得查询 current truth 重构 payload。如果实现需要 durable marker-to-envelope reconstruction,必须由 persistence / idempotency Step 定义正式 payload snapshot store 和 replay/read semantics。

### 8.6 Operations Job Discipline

Operations job 必须经 application job service,并保存可 replay 的 job report。通用骨架是:

```text
validate job request / canonical digest
  -> begin UnitOfWork
  -> reserve job idempotency
  -> load explicit or expanded targets
  -> execute maintenance / publish / deliver action through formal ports
  -> save state/report item refs
  -> save IdentityJobRunReport and stored JobReport
  -> complete idempotency
  -> commit
```

Rebuild / refresh / reconciliation job 不修 core identity truth。Publish / handoff job 只推进 outbox/handoff marker state。Duplicate replay 只能返回 stored `IdentityJobRunReport`,不得重新 list targets、rerun publisher/handoff 或 recompute item refs。

### 8.7 Cross-Flow Rules

All command、consumer/callback and operations job write paths enter through application facade,open a UnitOfWork,reserve idempotency before mutation,save replayable stored surfaces before idempotency completion,and commit only after trace/audit/outbox/projection/reference/job report side effects are staged. Duplicate replay never reruns mutation,resolver calls,publisher delivery or repository scans.

`HandoffState::Delivered` requires formal attempt and receipt markers;request sent,HTTP 2xx,adapter success or job log success cannot create delivered state. All public,stored,trace,audit,outbox,view,receipt and report surfaces remain body-free unless a later persistence/idempotency step defines a formal body snapshot store.

## 9. 状态机与转换矩阵

> 校准来源:
> - `design-calibration/03_ddd_step_10_state_matrix.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 business truth、source/reference、read/visibility、projection/report、outbox/handoff、idempotency/job 和 runtime/entry 状态族。

### 9.1 State Matrix Boundary

本章定义正式状态集合、转换矩阵、非法转换占位错误和跨状态副作用边界。状态名必须来自第 5/6 章对象契约中的 enum / state value;状态迁移必须回指第 8 章 function flow 和第 6/7 章对象函数或 repository marker update。实现侧只能按本章写状态校验、transition helper 和非法转换处理;如果 Step 6/8/9 与本章冲突,必须回设计修正。

Step 10 不定义 DDL、最终错误 enum 全集、HTTP status、retry/backoff 数字、topic 名称、transport route、adapter config 或实施 commit boundary。非法转换在本章统一作为 domain/application invalid state transition 占位,精确错误 taxonomy 和 public mapping 由错误章节闭合。

### 9.2 State Families

| 状态族 | 状态机 |
|---|---|
| Member / lifecycle truth states | `IdentityAnchorStateKind`, `GlobalLifecycleStateKind`, lifecycle high-risk precheck disposition |
| Role / career / memory truth and source states | role source, role summary, work participation source, career record, memory source, memory reference |
| Read / visibility / trace surface states | read disposition, query surface priority, member summary freshness, core truth query surface, trace/audit read surface |
| Projection / reference / reconciliation states | `ProjectionStateKind`, `ReferenceResolutionStateKind`, `ReconciliationReportStateKind`, maintenance issue / finding disposition |
| Outbox / handoff propagation states | `OutboxStateKind`, outbound material/policy disposition, `HandoffStateKind`, handoff material/target disposition |
| Application support states | idempotency state, stored result kind, job result kind, command effect / replay dispositions |
| Runtime / adapter / entry states | config validation, runtime assembly, adapter availability, API/worker/job validation and dispatch |

Pure refs、value objects、operation context、request digest、external truth、cache、lock、retry counter 不进入状态矩阵。

### 9.3 General State Rules

| 规则 | 正式口径 |
|---|---|
| 状态名来源 | 必须使用 Step 6 已定义 enum / state value;不得新增同义状态 |
| trigger 来源 | 只能是 Step 6 factory/member method/policy、Step 7 repository marker update 或 Step 9 flow |
| precheck 边界 | precheck 只能校验已有状态;若要推进状态,必须成为正式 transition step |
| terminal 状态 | terminal 不直接 reopen;需要后续处理时必须创建新 truth、new marker 或正式 replacement transition |
| query 状态 | query 只能读取并表达 surface,不得 refresh、rebuild、append、mark stale/fresh 或保存 result |
| job 状态 | job 只能维护 projection/reference/report/outbox/handoff/report helper,不得修复 core identity truth |
| version 来源 | update existing state 必须回指 Step 7 / Step 11 versioned read/list 来源 |

### 9.4 Truth State Rules

Anchor state 只表达 `GlobalMemberRef` 不可复用的 hold 状态,不等同 lifecycle。Lifecycle state 表达成员业务可用性,不表达 runtime health、ProjectMember state 或 governance truth。Terminal lifecycle accepted flow 可同步推进 anchor hold,但不得释放或复用 member ref。

Role summary/source state 只表达 body-free source/safe summary 的本地状态,不保存 method-library body。Career record 保持 append-only;duplicate、rejected、no-op 不写入 record state。Memory reference state 不等同 trace handoff delivery state;Delivered 仍属于 `HandoffStateKind` 并要求 formal receipt marker。

### 9.5 Derived / Reference / Report State Rules

Projection state 表达 derived view 的 freshness、pending、rebuilt、degraded 或 failed,不保存 projection body,query 不触发 rebuild。Reference resolution state 表达 identity 对 `ExternalReferenceRef` bundle 的解析状态,不表示 external truth lifecycle,也不允许把 unavailable/unrecognized source 伪装成 usable source。Reconciliation report 是 report-only material,finding 不等于 repair action。

### 9.6 Propagation / Handoff State Rules

Outbox state 独立于 accepted truth。`Published` 只代表 outbound boundary 成功,不代表 downstream consumed。Handoff state 独立于 memory relation state和 job dispatch state。`Delivered` 必须来自 formal `HandoffAttemptRef` 和 `HandoffReceiptRef`;HTTP 2xx、request sent、adapter success 或 job log success 都不得创建 delivered state。

### 9.7 Application / Entry State Rules

Idempotency state 只描述同一 operation name + channel + idempotency key 下的 replay/control 状态,不表示 command accepted truth或 job succeeded。Stored result kind 是 replay surface discriminator,保存后 immutable。Entry validation / dispatch 技术状态不得混同 application accepted/rejected、query visible/degraded、consumer receipt 或 job report。

### 9.8 Cross-State Audit

同名或近似状态均绑定到具体 owner,本设计不创建 `IdentityGlobalState` 或统一 global lifecycle table。每个状态迁移都有唯一 owner;跨 owner 的副作用必须通过 Step 9 flow 和 Step 7 port surface,不能由 repository 或 entry 层自动迁移。除状态矩阵明确允许的 recovery path 外,terminal state 不直接 reopen。

## 10. 数据持久化、事务与一致性契约

> 校准来源:
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 store、repository、transaction、optimistic version、cursor、stored replay 和 fake/durable parity。

### 10.1 Persistence Boundary

本章定义数据所有权、logical store、repository persistence semantics、transaction boundary、version / cursor / key separation、一致性恢复和 fake/durable parity。函数签名以第 6/7 章 port 为准;状态迁移以第 9 章状态矩阵为准。

本章不定义物理数据库产品、DDL 语法、SQL index 名称、migration 文件、HTTP status、retry/backoff 数字、broker topic、transport route、adapter config schema、最终错误 enum 全集或实施 commit boundary。物理 schema 可由 infra 设计或实施计划细化,但 durable adapter 与 in-memory fake 必须保留本章的 logical key、unique key、index、version、transaction、append-only 和 no-write/no-repair 语义。

### 10.2 Data Ownership and Logical Stores

| Store family | 持久化口径 |
|---|---|
| Core truth | member、lifecycle、role/capability、career、memory 等 identity-owned truth;mutable truth 使用 optimistic version |
| Append-only history / trace / audit | career record、trace record、audit entry 等 append-only material;不得覆盖旧 material |
| Projection / read model | member summary view、projection state、visibility/read support;query 只读 |
| External reference / sidecar | `ExternalReferenceRef` bundle、typed sidecar、source version、safe summary marker;external body 不入仓 |
| Report-only maintenance | reconciliation report、finding、issue marker;不得保存 remediation plan 或修复 truth |
| Outbox / handoff | outbox record/state、handoff intent/state、attempt/receipt/issue marker;失败不回滚 accepted truth |
| Replay support | idempotency record、stored result、consumer/callback receipt、job report;duplicate replay 唯一来源 |
| Runtime / entry technical marker | config shell、assembly state、adapter availability、entry validation/dispatch marker;不得写业务 truth |

### 10.3 Repository Persistence Semantics

Repository read 不接 UoW,只读取 committed state,不 hidden write。Write 必须接收同一 UnitOfWork 或等价 transaction handle。需要 optimistic update 的 save 必须使用 loaded `IdentityVersion` 作为 expected version;source version、cursor、timestamp、digest、idempotency key 不得替代 optimistic version。

Core truth repository 支撑 versioned read/save、business unique lookup 和 duplicate source lookup。Append-only repository 支撑 create-only / correction marker,不得覆盖或删除旧 record。Projection repository 提供 stable view lookup、state versioned read/save、stale mark 和 affected projection expansion,不得由 query 拼 view ref。Reference repository 以 explicit `ExternalReferenceRef` bundle key 保存 reference state 与 typed sidecar。Stored result、receipt 和 job report repository 必须提供 save/get 对称面。

### 10.4 Transaction Boundaries by Flow Family

| Flow family | Transaction rule |
|---|---|
| command accepted | idempotency reserve、truth save、cursor、trace/audit/outbox/stale/effect summary、stored result、idempotency complete 同 UoW |
| command replayable rejected | 仅当错误/幂等矩阵允许 replay 时,保存 stored rejected result 并 complete rejected idempotency;不写 truth/trace/outbox |
| query | no UoW write;不 reserve idempotency;不保存 stored result;不 repair |
| consumer / callback | idempotency reserve、owned truth/reference/marker update、typed receipt、stored shell、idempotency complete 同 UoW |
| outbox / handoff job | item state update、attempt/issue/receipt marker、job report、stored report、idempotency complete 同 UoW |
| projection / reference / reconciliation job | projection/reference/report item update、issue refs、job report、stored report、idempotency complete 同 UoW |

Commit failure 或 commit status unknown 时,application 不得报告 accepted/receipt/job success,除非 durable stored surface 能证明结果已提交。Rollback failure 和 replay missing/wrong-kind 属于恢复 / 人工处理口径,不得重跑 mutation。

### 10.5 Consistency, Recovery and Fake Parity

Mutable truth 使用 optimistic update,conflict 不 overwrite。Append-only material 不可变;correction 必须创建新 record 或 formal correction marker。Stored result kind immutable;missing/wrong-kind replay 是 replay error,never rerun command/consumer/job。

Accepted truth -> projection stale 与 accepted transaction 同 UoW;如果 stale mark 在 commit 前失败,accepted transaction rollback。Outbox / handoff failure 只更新 propagation marker 或 job report,不回滚 accepted truth。All persisted diagnostics remain body-free:raw request/event/config/adapter/receipt/log body、secret、target private path、archive package、external truth body 不进入 identity store。

Fake runtime 必须与 durable adapter 使用同一 logical store、key、version、cursor、index、transaction、stored replay 和 no-write/no-repair 语义;不得通过私有 map、string scan、current truth reconstruction 或 hidden writes 补正式 port 缺口。

### 10.6 Cross-Step Persistence Audit

Step 11 已确认 Step 6 object fields、Step 7 repository / UoW / port surface、Step 9 transaction order 和 Step 10 state matrix 均有 persistence 语义承接。Step 12 继续定义 invalid transition、version conflict、stored replay missing/wrong-kind、query surface priority、consumer/callback receipt、publisher/handoff failure、entry pre-dispatch failure 和 forbidden body mapping。

## 11. 错误模型、异常分支与恢复口径

> 校准来源:
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 domain / application / entry / adapter error owner、public mapping、retry、terminal、degraded 和 quarantined 口径。

### 11.1 Error Layering and Type Taxonomy

本章定义 domain / application / port / protocol / worker / job / infra 错误层级、对外映射、异常分支、恢复口径和审计/事件写入规则。错误处理必须遵守 query no-write、duplicate no-rerun、accepted-only side effect、body-free diagnostics 和 fake/durable parity。

错误 owner 分层如下:

| Layer | Owner | 说明 |
|---|---|---|
| contracts / protocol construction | `identity-contracts` | request/envelope/page/body marker 缺失、字段组合非法、forbidden body |
| domain | `identity-domain` | invariant violation、policy denied、invalid transition、missing trusted input |
| application | `identity-application` | orchestration error、idempotency conflict/in-flight、stored replay defect、commit unknown |
| port / adapter | `identity-infra` through application ports | repository unavailable、version conflict、resolver outcome、publisher/handoff outcome、serialization/body boundary failure |
| entry / runtime | `identity-api` / `identity-worker` / `identity-jobs` / runtime assembly | pre-dispatch validation、runtime unavailable、dispatch target disabled |

### 11.2 Public Mapping by Protocol Family

Command error 映射为 accepted/rejected/conflict/dependency/replay consistency 等 command outcome,但 `Rejected` 不自动意味着 stored rejected result;是否 replayable 由异常分支和幂等矩阵确定。Query not-visible、missing、degraded、stale、empty 使用 `IdentityQuerySurface`,不使用 command rejection。Consumer/callback 使用 typed receipt / issue surface;unsupported schema、quarantine、delayed、noop 与 accepted 都必须可区分。Outbox / handoff publish/delivery failure 只推进 marker/report surface,不得回滚 accepted truth。Job error 映射到 job report result kind 和 safe issue refs。

Entry pre-dispatch failure 不创建 application idempotency、stored result、trace、outbox、receipt 或 job report。HTTP/RPC status、worker ack/dead-letter 和 transport code 留给后续 transport/config/test binding。

### 11.3 Exception Branches by Flow Family

Shared exception rules:

- same key / different digest -> duplicate conflict,不得 overwrite original digest 或保存 incoming raw body。
- idempotency in-flight -> delayed / temporary surface,不得 parse/reapply payload。
- stored result / receipt / report missing or wrong kind -> replay consistency failure,不得重跑 command、consumer、callback 或 job。
- formal unique conflict -> rollback current write unless flow owns formal noop branch。
- commit status unknown -> 不报告 success,先通过 idempotency/stored surface 检查。
- rollback failure -> consistency defect / manual recovery,不得假设 clean rollback 后盲重试。

Command guard rejected before truth save 不写 accepted trace/outbox/stale。Query branch 全程 no-write。Consumer/callback replay 不重算 receipt。Outbox/handoff failure 不回滚 accepted truth。Projection/reference/reconciliation job failure 只写 report/issue,不 repair truth。

### 11.4 Recovery, Audit and Marker Rules

| Recovery class | 可写 material | 禁止 material |
|---|---|---|
| RetryableMarker | safe issue marker、retryable outbox/handoff state、job report issue、delayed receipt | raw adapter/source/error body |
| Terminal/manual recovery | consistency defect surface、safe issue marker、manual recovery note marker | auto repair、current truth reconstruction、raw diagnostic body |
| Query degraded recovery | query degraded/not visible/missing/empty surface | query-side write、trace append、projection rebuild |
| Forbidden body recovery | safe forbidden body issue / rejection / quarantine surface | raw request/event/source/archive/receipt/config/log body |
| Accepted command recovery | accepted trace/audit/outbox/stale/effect/stored refs | forbidden body、external body、secret |

Accepted truth / marker / job report 按 Step 9/11 写入;entry pre-dispatch、not-visible query、invalid envelope、unsupported schema、forbidden body persistence attempt 不写 accepted trace/outbox。日志、指标和安全审计字段留观测章节。

### 11.5 Cross-Step Error / Recovery Audit

Step 12 已覆盖 Step 6 object/state/policy error owner、Step 6 query/read/degraded markers、Step 6 outbox/handoff states、Step 7 fake/durable parity、Step 9 function flow branches、Step 10 invalid transition 和 Step 11 persistence / transaction handoff。Step 13 必须继续承接 command、consumer/callback、job 的 idempotency key/digest/replay/in-flight/commit unknown/no-rerun 规则,不得新增 Step 12 之外的 public error mapping。

## 12. 并发、幂等与重入保护

> 校准来源:
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 operation context、idempotency key、request digest、duplicate replay、commit unknown 和 reentry guard。

### 12.1 Concurrency Resource Inventory

本章定义并发资源、幂等键、稳定 digest、重复处理、in-flight protection、commit unknown recovery 和 job/outbox/handoff reentry guard。并发保护必须遵守 query no-write、duplicate no-rerun、stored replay only、body-free digest 和 fake/durable parity。

并发资源分为 mutable versioned truth、append-only truth/history、versioned aggregate + entry append、read model / projection、external reference bundle / sidecar、report-only maintenance、propagation marker、replay / idempotency support、runtime / entry technical marker 和 query read-only surface。

Mutable truth 更新必须使用 loaded `IdentityVersion`。Append-only record 不覆盖旧 material。Projection/reference/report 只能由 accepted stale side effect 或 maintenance job 更新。Outbox/handoff 只表达 propagation marker,失败不回滚 accepted truth。Idempotency / stored replay surface 是 duplicate replay 的唯一来源。Query 重复读取不创建 idempotency、不写 trace/audit、不修 projection/reference/report/outbox/handoff。

### 12.2 Concurrency Scenario Matrix

Command、consumer/callback 和 operations job 必须先 reserve idempotency,再进入 mutation/job body。Optimistic conflict 使用 loaded version 失败处理;business unique conflict 不等于 duplicate replay。Consumer/callback redelivery 通过 typed receipt envelope replay。Operations job duplicate replay 使用 stored job report,不得重跑 body。Query repeated reads are current authorized reads only.

Outbox/handoff retry 只能选择 retryable marker state,terminal state 需要新的正式 operation。Projection/reference/reconciliation job race 通过 loaded version、formal target expansion 和 stored job report 控制,不得 last-writer-wins 或 private fake scan。

### 12.3 Idempotency Key and Digest Matrix

Command key 来自 `IdentityCommandMetadata.idempotency_key`。Consumer/callback key 来自 `IdentityInboundEventEnvelope.idempotency_key`,并按 `Consumer` 或 `HandoffCallback` channel 命名空间化。Operations job key 来自 `IdentityJobRequest.idempotency_key`。Query 没有 idempotency key、stored result 或 replay matrix。

Digest 来自 body-free `IdentityRequestDigestMarker`,包含稳定 operation、actor、target ref、typed material marker、event/job scope 等语义字段,排除 idempotency key、request marker、trace context、current time、generated refs、raw body、transport ack 和 adapter response。`source_event_ref` 可以是 stable digest material,但不是 idempotency key。Business duplicate marker 也不得替代 envelope/job/command idempotency key。

### 12.4 Duplicate, In-Flight and Reentry Handling

Reserve priority:

1. entry validation fails before application facade -> no UoW,no idempotency,no stored result。
2. replay available -> load stored surface and return it。
3. stored missing / wrong-kind -> replay consistency defect。
4. different digest -> duplicate conflict。
5. in-flight same digest -> delayed / temporary surface。
6. reserved first-run -> execute mutation/job body。

First-run accepted command saves truth、cursor、trace/audit、outbox、projection stale、effect summary、stored accepted result,then completes idempotency。First-run accepted consumer/callback saves typed receipt envelope and stored shell before complete。First-run job saves `IdentityJobRunReport`,then stored `JobReport`,then complete idempotency。Completed duplicate replay returns previously stored public surface even if current truth has changed.

Commit unknown must check idempotency/stored surface before retry. Blind retry with new key、current truth reconstruction、payload reparse、job rerun or repository rescan is forbidden.

### 12.5 Cross-Step Concurrency / Idempotency Audit

Step 13 closes Step 6~12 key/digest/replay/version/query/fake-parity boundaries and hands Step 14 the remaining configuration-only decisions: idempotency retention, in-flight timeout, digest algorithm binding, retry schedule, worker transport binding, adapter timeout/availability and job scheduling. Configuration cannot change identity invariants: idempotency reserve、visibility、body-free digest、query no-write、job no-truth-repair、stored replay and fake/durable parity are non-configurable design rules.

### 13.3 External Dependency Binding

外部依赖通过 Step 7 ports 和 adapter surface 注入。Store、idempotency/result、projection/reference/report、bus publisher、role/governance/work/artifact/memory resolver、handoff、audit、clock/id、fake/controlled/disabled adapter 均只能返回 body-free safe refs、state kinds、attempt/receipt/issue markers 或 formal outcome。

除 `core-contracts` 外,method-library、work、governance、bus、memory/archive、artifact、observability、runtime 和 downstream consumers 均不得作为 Cargo path dependency。跨仓协作必须停留在 port、adapter、event、handoff 或 shared contract 边界。

### 13.4 Runtime Builder and Validation Boundary

Runtime builder 负责把 validated config refs 装配为 repositories、UnitOfWork、clock/id、resolver、publisher、handoff、audit、adapter availability registry、application facade 和 entry surfaces。

Builder order 必须先完成 raw config parse、type/range/cross-field validation,再解析 sensitive refs,再创建 `IdentityRuntimeConfigShell`,最后装配 store、base adapters、external adapters、facade 和 entry modules。`IdentityRuntimeAssemblyState::Assembled` 只表示 wiring ready,不代表 adapter healthy、publisher delivered、handoff delivered 或 business accepted。

### 13.5 Cross-Repo and Forbidden Configuration Boundary

Only `core-contracts = { path = "../quantalithos-core/crates/contracts" }` is allowed as current compile-time sibling dependency。Runtime、event、handoff、projection、fake and downstream collaboration must stay behind ports/adapters/events。

Config validation must fail or return explicit disabled/degraded/unavailable surfaces instead of silently substituting fake success。Configuration cannot weaken identity truth ownership、state matrices、transaction order、idempotency/stored replay、query no-write、job no-truth-repair、terminal retry guard or body-free/secret-free boundaries。

## 14. 可观测性与审计埋点契约

> 校准来源:
> - `design-calibration/03_ddd_step_15_observability_audit.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 runtime log、metric、business audit、identity trace、handoff、redaction 和 forbidden material guard。

### 14.1 Observability Principles

本章定义代码埋点契约,包括 log、metric、business trace、audit、report、handoff marker、runtime/config/adapter/fake redaction 和 forbidden material guard。它不定义 alert threshold、SLO、dashboard、runbook、metric backend、日志采样率、保留周期、测试编号或部署产品。

Logs are not business audit。Business audit is not observability ledger。Query no-write、duplicate no-rerun、failed path is not accepted trace、low-cardinality labels、body-free material 和 fake/durable parity 是观测实现必须保持的红线。

### 14.2 Log Instrumentation Cuts

日志用于运行期诊断,不得替代业务 trace/audit/report。Entry、application、worker、jobs、repository、resolver、outbox、handoff、runtime、fake/controlled/disabled adapter 均应在边界切换、validation failure、visibility denial、degraded branch、retryable failure、terminal failure、duplicate replay、stored replay missing/wrong-kind 和 runtime assembly 处提供安全日志切口。

日志字段只能使用 operation/ref/state/kind/channel/attempt/result/error category 等 safe fields。不得记录 request/event/job raw body、RoleDefinition body、ProjectMember truth、memory text、archive package、artifact body、governance policy body、broker payload body、secret、adapter raw response 或 fake private fixture map。

### 14.3 Metric Instrumentation Cuts

指标用于可聚合的运行状态观察。Metric cut 必须覆盖 command/query/event/callback/outbound/job/runtime/adapter 的 accepted、rejected、not-visible、degraded、duplicate replay、retryable、terminal、disabled、unavailable 和 fake/controlled outcome 等低基数结果。

Metric label 只能使用固定枚举或低基数字段,例如 operation kind、channel、state kind、adapter kind、failure class、profile kind。不得把 actor id、member id、role id、external ref、trace id、request digest、raw source name、topic body、secret 或高基数 error message 作为 label。

### 14.4 Business Trace / Audit / Report / Marker Cuts

Accepted truth、marker、outbox、handoff 和 job report 的业务审计写入必须沿 Step 6~13 已定义对象、flow、state、transaction 和 stored replay surface 执行。Accepted command 才写 accepted trace/audit/outbox/projection stale/effect summary。Accepted consumer/callback 才写 typed receipt / marker。Accepted operations job 才写 job report 或正式 handoff/report marker。

Entry pre-dispatch、not-visible query、invalid envelope、unsupported schema、forbidden body persistence attempt、retryable publish failure、terminal handoff failure 和 failed job branch 不得伪装成 accepted business trace。Query 只能返回当前授权 read surface,不得为了观测写 trace、audit、projection、reference、outbox 或 report。

### 14.5 Runtime / Config / Adapter / Fake Redaction Boundary

Runtime/config observability 只能暴露 config source selector、profile kind、adapter mode、validation issue kind、assembly state 和 dependency availability state 等 safe marker。Adapter observability 只能暴露 formal outcome kind、attempt refs、receipt refs、issue refs、state and safe failure class。

Fake、controlled 和 disabled adapter 必须与 durable adapter 暴露同构 outcome、state、issue 和 metric cut,但不得输出 private fixture map、raw configured body、secret 或默认 success。Runtime assembled 不能被观测材料解释为 resolver valid、publisher delivered、handoff delivered 或 business accepted。

### 14.6 Forbidden Material and Step 16 Handoff

Step 16 必须把本章 observability/redaction 规则转成最小测试切口:log/metric/audit/report/handoff cut、low-cardinality labels、forbidden body scan、secret scan、fake private material scan、query no-write observability 和 duplicate replay no business trace。

本章禁止把测试编号、fixture、CI、evidence、alert threshold、SLO、dashboard 或 runbook 写成详细设计正文。后续测试方案和验收材料必须从本章读取 redaction 与 observability contracts,不得反向放宽。

## 15. 测试切口与最小验证清单

### 15.1 Module and Command Test Cuts

本章定义 L1-identity 的最小测试切口,用于指导后续测试方案、验收标准和实施计划复核。它不分配正式测试编号、优先级、fixture、CI job、coverage threshold、evidence 或执行排期。

### 15.2 Query, Event, Outbound Material and Job Test Cuts

Query 测试必须覆盖 visibility-first、not-visible、missing/empty、degraded/stale-visible 和 query no-write。Inbound Event / Callback 测试必须覆盖 typed receipt replay、unsupported、delayed、quarantined、noop 和 forbidden body。

### 15.3 State Machine Test Cuts

状态机测试以 Step 10 的正式 enum、state value、transition matrix 和 cross-state audit 为唯一真相源。每个状态族至少覆盖合法转换、非法转换、terminal guard、owner boundary、query no-write、job no-repair、Published not consumed、Delivered requires receipt、duplicate no-rerun 和 fake/durable parity。

### 15.4 Transaction, Error, Idempotency and Concurrency Test Cuts

事务与一致性测试必须覆盖 accepted same-UoW、rollback/commit visibility、stored replay save-before-complete、commit unknown、rollback failure、version/unique conflict、append-only、reference bundle version、projection rebuild race、outbox/handoff reentry 和 partial job report。

错误与恢复测试必须覆盖 public rejection、degraded、unsupported、delayed/quarantined、retryable/terminal/manual recovery、stored replay missing/wrong-kind 和 forbidden body persistence attempt。Command、consumer/callback 和 job 的 duplicate path 必须返回 stored public surface,不得重跑 mutation、重读当前 truth 拼结果或扫描 repository 反推。

### 15.5 Config, Runtime, Adapter, Observability and Redaction Test Cuts

配置与 runtime 测试必须覆盖 raw config ownership、redline validation、profile/adapter compatibility、runtime builder order、runtime assembled vs adapter healthy、disabled/fake no-success 和 non-core dependency guard。

观测与 redaction 测试必须覆盖 log/metric/audit/report/handoff cut points、low-cardinality metric labels、business audit not replaced by logs、query no-write observability、duplicate replay no business trace,以及 raw request/event/job/config/source/archive/receipt/adapter/fake private material 不落盘。

### 15.6 Step 17 Handoff

实施计划必须承接本章所有最小切口,并在后续 `05-测试方案.md`、`06-验收标准.md` 和 `07-实施计划.md` 中再分配正式测试编号、priority、fixture、CI、evidence 和 commit boundary。

- 发现实现条件与设计 baseline 不一致时,必须暂停并回报具体 blocker、证据、影响范围和建议闭口点。

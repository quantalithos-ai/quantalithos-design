## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 identity 的接口可调用,而是系统验证 `L1-identity` 是否真正满足当前设计中的“平台级成员真相仓”要求,尤其要证明以下几点成立:
- `GlobalMember` 只能通过 `HireGlobalMember` 显式创建,query 不会自动创建成员
- lifecycle 由 `GlobalMember` 状态机维护,普通迁移和 tombstone 高风险流程边界清晰
- `RoleCatalogEntry` 只是 method-library role 的本地索引,不复制 `RoleDefinition` 正文
- `CapabilityProfile` 只保存能力画像和 evidence refs,不保存 artifact 正文
- `MemoryRefs` 只保存 memory/archive 引用和归档状态,不保存 memory 原文、embedding 或检索索引
- work / process 事实只能通过 inbound event 追加 `CareerEntry`,不能反写外部域真相
- command / event 本地事务必须同时写入 write model、audit、outbox、idempotency record
- outbox 发布失败不能回滚业务事实,projection rebuild 不能反写真相
- identity 不做登录、token、session、credential 校验,入口安全由 Gateway / API Layer 完成

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| `HireGlobalMember` / `GlobalMember` | Command / 真相对象 | P0 | 显式创建平台级成员,禁止 query 自动创建 |
| `UpdateLifecycle` | Command / 状态机 | P0 | 验证 `hired / active / paused / retired` 合法迁移和非法迁移 |
| `SyncRoleCatalog` / `RoleCatalogEntry` | Inbound Event / 本地索引 | P0 | 验证 role catalog 同步、幂等和不复制正文 |
| `PublishOutboxEvents` | Operations / 事件发布 | P0 | 验证 outbox 可靠发布、失败标记和重试 |
| `RebuildMemberSummaryProjection` / `GetMemberSummary` | Operations + Query / 投影 | P0 | 验证 projection 可重建、可查询、延迟可降级 |
| `GetMemberAuditTrace` | Query / 审计视图 | P0 | 验证 command / event 处理可审计且字段可裁剪 |
| `UpdateCapabilityProfile` / `CapabilityProfile` | Command / 能力画像 | P1 | 验证能力画像和 evidence refs,不保存 artifact 正文 |
| `UpdateMemoryRefs` / `MemoryRefs` | Command / 引用集合 | P1 | 验证 memory refs 更新和 ref-only 规则 |
| `AppendCareerEntry` / `CareerEntry` | Inbound Event / append-only | P1 | 验证 work / process 事实事件只能追加 career history |

## 2. 测试策略与分层

测试策略采用“入口族 + 风险分层”的方式组织。
低层测试负责快速验证 domain 规则和应用服务编排,高层测试只覆盖关键协作闭环和架构红线,避免所有风险都堆到端到端测试里。

```text
                  +-----------------------------+
                  |  最小闭环 / 验收冒烟测试     |
                  |  SyncRoleCatalog -> Summary |
                  +--------------+--------------+
                                 |
                  +--------------v--------------+
                  |  契约 / Operations / 恢复测试 |
                  |  ports / outbox / projection |
                  +--------------+--------------+
                                 |
                  +--------------v--------------+
                  |  集成 / 应用服务测试          |
                  |  command / query / event      |
                  +--------------+--------------+
                                 |
                  +--------------v--------------+
                  |  单元测试                     |
                  |  domain rules / value object  |
                  +-----------------------------+
```

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证 domain object、value object 和状态机不变量 | domain owner | `GlobalMember` lifecycle、`MemoryRefs` archive 状态、`CareerHistory` append-only、`GateDecisionRef` 校验 | 核心规则不依赖 DB / bus 也能被验证 |
| 应用服务测试 | 验证 command / query / event handler 编排 | application owner | `HireGlobalMember`、`UpdateLifecycle`、`GetMemberSummary`、`SyncRoleCatalog`、`AppendCareerEntry` | 正确调用 domain、repo、outbox、idempotency、audit |
| 集成测试 | 验证 repository、事务、outbox、projection、dead-letter 联动 | backend / integration owner | 本地事务回滚、`idempotency_records`、`outbox_events`、`member_summary_projection`、`inbound_dead_letters` | 持久化事实、事件记录和投影行为一致 |
| 契约测试 | 验证外部 port 的输入输出语义 | platform integration owner | method-library、governance、memory/archive、artifact、L0-bus stub / contract | identity 只保存 ref / snapshot / fingerprint,不复制外部正文 |
| Operations / 恢复测试 | 验证可恢复任务和失败路径 | ops / backend owner | `PublishOutboxEvents`、`RebuildMemberSummaryProjection`、`ReconcileRoleCatalog`、dead-letter replay | bus 失败、projection 失败、坏事件都能恢复或留证 |
| 最小闭环测试 | 验证第一批主干可以端到端跑通 | QA / module owner | `SyncRoleCatalog -> HireGlobalMember -> PublishOutboxEvents -> RebuildMemberSummaryProjection -> GetMemberSummary` | P0 主干完整跑通,且没有违反架构红线 |
| 架构红线专项测试 | 验证禁止事项不会被实现绕过 | architecture / QA | query 自动创建、projection 反写、outbox publisher 创造事件、保存外部正文、跳过 Gate | 红线场景 100% 被阻断或留证 |

### 2.1 层级与入口族映射

| 入口族 / 风险 | 优先测试层级 | 自动化优先级 | 说明 |
|---|---|---|---|
| Command API | 应用服务测试 + 集成测试 | P0 | 重点验证事务、幂等、状态机和 outbox |
| Query API | 应用服务测试 + projection 集成测试 | P0 | 重点验证只读、字段裁剪、not ready |
| Inbound Event | 应用服务测试 + dead-letter 集成测试 | P0 | 重点验证 source_event_id、payload_hash、坏事件处理 |
| Outbox / Projection | Operations / 恢复测试 | P0 | 重点验证发布失败、checkpoint、rebuild |
| 外部依赖 port | 契约测试 | P1 | 重点验证 ref-only 和不可复制正文 |
| 架构红线 | 专项测试 + 回归门禁 | P0 | 作为发布阻断条件 |

### 2.2 最小闭环测试流

```text
SyncRoleCatalog
      |
      v
RoleCatalogEntry ready
      |
      v
HireGlobalMember
      |
      +--> global_members
      +--> audit_trace_entries
      +--> outbox_events
      +--> idempotency_records
      |
      v
PublishOutboxEvents
      |
      v
RebuildMemberSummaryProjection
      |
      v
GetMemberSummary
```

最小闭环只验证第一批主干:
- role catalog 可同步并被创建成员流程引用
- member 可显式创建
- outbox 可发布或记录失败
- projection 可重建
- query 可读取摘要且不自动创建成员

## 3. 需求追溯与覆盖矩阵

覆盖矩阵以 `03-详细设计.md` §13.6 为主线。
每个设计点必须能追到测试场景、测试层级、自动化候选和证据类型。

| 设计点 | 测试场景 | 测试层级 | 自动化 | 证据 | 残余风险 |
|---|---|---|---|---|---|
| Command API | command 成功、失败、幂等、事务回滚 | 应用服务 + 集成 | 是 | command result、DB rows、audit、outbox、idempotency record | 外部 port 未接入前只能用 stub |
| Query API | projection 查询、字段裁剪、not ready | 应用服务 + projection 集成 | 是 | query response、projection row、field trim log | projection 真实延迟需在集成环境复核 |
| Inbound Event | 事件幂等、payload 解析失败、dead-letter、replay | event handler + 集成 | 是 | inbound envelope、dead-letter row、audit、outbox | 上游事件契约变化需单独回归 |
| Outbox / Projection | outbox 发布失败、retry、checkpoint rebuild | operations + 恢复测试 | 是 | outbox status、publish log、checkpoint row、projection row | L0-bus 真实 SLA 需 staging 复核 |
| 外部依赖 | method-library、governance、memory/archive、artifact、L0-bus 契约 | contract test | 是 | stub contract report、request/response snapshot | 外部模块真实实现未完成时只能验证契约 |
| 架构红线 | query 自动创建、projection 反写、保存外部正文、publisher 创造事件、跳过 Gate | 专项 + 回归门禁 | 是 | negative test report、DB absence check、audit trace | 新增入口需持续加入红线测试 |
| 最小闭环 | `SyncRoleCatalog -> HireGlobalMember -> PublishOutboxEvents -> RebuildMemberSummaryProjection -> GetMemberSummary` | e2e smoke | 是 | end-to-end trace、outbox event、projection row、query response | 增强闭环不在第一批主干内 |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地单元、应用服务和基础集成测试 | local DB / in-memory bus stub / fake clock | debug logging、deterministic id、transaction rollback enabled | 容易只覆盖 happy path |
| test | CI 自动化、contract、repository、outbox、projection 测试 | test DB / L0-bus stub / method-library stub / governance stub / memory-archive stub / artifact stub | deterministic fixtures、idempotency keys、dead-letter replay enabled | stub 契约可能落后真实服务 |
| staging | 最小闭环、发布前冒烟、跨模块契约复核 | real-like DB / L0-bus / method-library / governance / memory-archive / artifact | bus delay、projection rebuild、retry backoff、observability enabled | 下游模块状态差异会放大问题 |

环境约束:
- 测试必须能控制 `trace_id`、`idempotency_key`、`source_event_id`、`payload_hash`
- 测试必须能观察 write model、audit、outbox、projection、dead-letter
- 外部依赖优先使用 stub / contract fixture,真实环境只用于 staging 冒烟和契约复核
- identity 测试环境不需要认证源模拟器,只需要 Gateway / API Layer 注入后的可信 `ActorContext`

## 5. 测试数据设计

| 数据类型 | 来源 | 用途 | 隔离方式 |
|---|---|---|---|
| `RoleCatalogEntry` fixture | method-library event snapshot | `SyncRoleCatalog`、`HireGlobalMember` role 校验 | 每用例独立 `role_id` / fingerprint |
| `GlobalMember` fixture | command builder | lifecycle、query、audit、projection 测试 | 每用例独立 `global_member_id` |
| `CapabilityProfile` fixture | command builder + artifact refs | 能力画像更新和 ref-only 测试 | 每用例独立 `capability_profile_id` |
| `MemoryRefs` fixture | memory/archive stub refs | memory refs 更新、archive status 测试 | 每用例独立 `memory_refs_id` / `archive_ref` |
| `CareerEntry` / fact event fixture | work / process event snapshot | `AppendCareerEntry`、append-only、dead-letter | 每用例独立 `source_event_id` |
| `OutboxEvent` fixture | command / event transaction | outbox publish、retry、projection rebuild | 每用例独立 `outbox_event_id` / `idempotency_key` |
| `idempotency_records` fixture | request metadata builder | command / event 幂等和冲突测试 | 每用例独立 key;冲突用同 key 不同 hash |
| `inbound_dead_letters` fixture | bad event builder | 解析失败、member 缺失、payload 冲突 | 每用例独立 `dead_letter_id` |
| `projection_checkpoints` fixture | operations builder | projection rebuild 断点续跑 | 每套 projection 独立 `checkpoint_name` |

数据规则:
- 所有测试数据必须可重复生成,不能依赖当前时间和随机外部状态
- 涉及并发和幂等的用例必须显式标注 key、hash、version
- 涉及外部正文的 fixture 只能保存 ref / snapshot / fingerprint,不能把正文落入 identity 表

## 6. 核心测试场景

### 6.1 Command 测试

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| CMD-001 | 显式创建成员 | active role catalog 已存在 | `HireGlobalMember` | 创建 `GlobalMember`,写 history / audit / outbox / idempotency |
| CMD-002 | 创建成员 role 不存在 | role catalog 缺少目标 role | `HireGlobalMember` | 返回 `IDENTITY_ROLE_NOT_FOUND`,不写业务事实 |
| CMD-003 | 创建成员幂等重复 | 同 key 同 request hash 已成功 | 重放 `HireGlobalMember` | 返回既有结果,不重复创建 |
| CMD-004 | 创建成员幂等冲突 | 同 key 不同 request hash | `HireGlobalMember` | 返回 `IDENTITY_IDEMPOTENCY_CONFLICT` |
| CMD-005 | 普通生命周期迁移 | member 已存在 | `UpdateLifecycle(active/paused/retired)` | 合法迁移成功,非法迁移被拒绝 |
| CMD-006 | tombstone 走错入口 | member 已存在 | `UpdateLifecycle(tombstoned)` | 返回 `IDENTITY_USE_TOMBSTONE_COMMAND` |
| CMD-007 | 更新能力画像 | member 非终态,evidence refs 可用 | `UpdateCapabilityProfile` | 保存能力画像和 evidence refs,不保存 artifact 正文 |
| CMD-008 | 更新 memory refs | member 存在,memory refs 可用 | `UpdateMemoryRefs` | 保存 refs,不保存 memory 正文 |
| CMD-009 | tombstone 高风险流程 | Gate approved,memory/archive 可用 | `TombstoneMember` | member 进入 tombstoned,写 GateDecisionRef / outbox / audit |
| CMD-010 | Gate rejected | Gate 返回 rejected | `TombstoneMember` | 返回 `IDENTITY_GATE_REJECTED`,不进入 tombstoned |

### 6.2 Query 测试

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| QRY-001 | 查询成员摘要 | projection 已生成 | `GetMemberSummary` | 返回摘要 DTO |
| QRY-002 | projection 未就绪 | write model 已提交但 projection 未追上 | `GetMemberSummary` | 返回 `IDENTITY_PROJECTION_NOT_READY` 或约定 not ready |
| QRY-003 | 查询不存在成员 | 无 projection / 无成员 | `GetMemberSummary` | 返回 `IDENTITY_MEMBER_NOT_FOUND`,不创建成员 |
| QRY-004 | 查询审计轨迹 | audit trace 已存在 | `GetMemberAuditTrace` | 返回审计轨迹并按 actor 裁剪字段 |
| QRY-005 | 审计轨迹不可见 | actor 无权查看 | `GetMemberAuditTrace` | 返回 `IDENTITY_AUDIT_TRACE_NOT_VISIBLE` |
| QRY-006 | 查询 role catalog | 本地 role index 已同步 | `GetRoleCatalog` | 返回本地摘要,不读取 RoleDefinition 正文 |

### 6.3 Inbound Event 测试

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| EVT-001 | 同步 role catalog | method-library 事件有效 | `SyncRoleCatalog` | upsert `RoleCatalogEntry`,写 audit / outbox / idempotency |
| EVT-002 | role 事件重复 | 同 `source_event_id` 同 hash | 重放 `SyncRoleCatalog` | skipped,不重复写 outbox |
| EVT-003 | role 事件 payload 失败 | payload 不可解析 | `SyncRoleCatalog` | 写 dead-letter |
| EVT-004 | 追加 career entry | work / process fact event 有效 | `AppendCareerEntry` | 追加 career entry,不反写 work / process |
| EVT-005 | career event member 缺失 | event 指向不存在 member | `AppendCareerEntry` | 写 dead-letter |
| EVT-006 | archive 状态更新 | memory refs 存在 | `HandleMemoryArchiveEvent` | 更新 archive status,写 outbox |
| EVT-007 | archive 状态乱序 | 旧事件晚到 | `HandleMemoryArchiveEvent` | skipped 或 dead-letter,不覆盖新状态 |
| EVT-008 | Gate 决策记录 | pending flow 存在 | `HandleGateDecisionEvent` | 记录 Gate decision,不直接创建 tombstone |

### 6.4 Operations 测试

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| OPS-001 | 发布 outbox 成功 | pending outbox 存在,L0-bus 可用 | `PublishOutboxEvents` | event 标记 published |
| OPS-002 | 发布 outbox 失败 | L0-bus 失败 | `PublishOutboxEvents` | 标记 failed / next_retry_at,不回滚 write model |
| OPS-003 | projection 增量重建 | outbox event 和 checkpoint 存在 | `RebuildMemberSummaryProjection` | projection upsert,checkpoint 前进 |
| OPS-004 | projection apply 失败 | 某 event 无法应用 | `RebuildMemberSummaryProjection` | checkpoint 不前进,保留失败证据 |
| OPS-005 | role catalog 对账 | method-library fingerprint 变化 | `ReconcileRoleCatalog` | 标记 drift 或更新本地索引摘要 |

### 6.5 横切风险测试

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| X-001 | 本地事务回滚 | outbox 或 audit 写入失败 | 执行任一 command | write model / audit / outbox / idempotency 全部回滚 |
| X-002 | lifecycle 并发冲突 | 两个请求持有同一 expected_version | 并发 `UpdateLifecycle` | 一个成功,另一个返回版本冲突或按最新状态重判 |
| X-003 | query 自动创建红线 | 不存在 member id | `GetMemberSummary` | 不创建 `GlobalMember` |
| X-004 | projection 反写红线 | projection 被手动改错 | rebuild / query | 不修改 write model,通过 rebuild 修复 |
| X-005 | 外部正文落库红线 | 提供 RoleDefinition / memory 正文 | command / event | identity 表只保存 ref / snapshot / fingerprint |
| X-006 | tombstone 跳 Gate 红线 | 无 approved GateDecisionRef | `TombstoneMember` | 拒绝进入 tombstoned |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | 身份真相污染、query 自动创建、projection 反写、outbox 丢事件、idempotency 失效、tombstone 跳 Gate、保存外部正文 | 阻断放行,必须修复 |
| A | 主线可跑但 audit、projection、event、external contract、dead-letter replay 不稳定 | 原则上修复后再放行;特殊情况需风险接受 |
| B | 非 P0 查询、报告格式、低优先级恢复体验或非阻断性可观测性问题 | 可带风险进入下一轮 |

缺陷分类要求:
- 每个缺陷必须标注入口族:Command / Query / Inbound Event / Operations / Contract / Redline
- 每个 S / A 级缺陷必须附证据:request、trace、DB snapshot、outbox / dead-letter / projection 记录
- 修复后必须回归对应入口族和横切风险用例

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 `GlobalMember` lifecycle,必须回归 `UpdateLifecycle`、`TombstoneMember` 和 lifecycle 并发测试
- 每次改动 idempotency,必须回归 command / event 的 same key same hash 与 same key different hash
- 每次改动 outbox,必须回归发布成功、发布失败、retry、projection rebuild
- 每次改动 projection,必须回归 `GetMemberSummary`、checkpoint、not ready、projection 反写红线
- 每次改动 inbound event,必须回归 source_event_id、payload_hash、dead-letter、replay
- 每次改动 external port,必须回归 method-library、governance、memory/archive、artifact、L0-bus contract
- 每次新增入口,必须补充 query 不自动创建、外部正文不落库、outbox publisher 不创造事件等架构红线测试

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 外部模块真实实现未完成时,contract 只能基于 stub 验证 | staging 后仍可能发现契约偏差 | TL / 平台 owner |
| 第一批最小闭环不覆盖全部增强流程 | memory/archive、tombstone、career history 需分阶段强化 | TL / 模块 owner |
| 性能阈值第一批只能记录基线 | 后续需要基于真实数据量设定 SLO | TL / SRE |
| dead-letter replay 依赖运维工具成熟度 | 第一批可能只能验证数据和手动 replay 路径 | TL / Ops |

### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 identity 的接口可调用,而是系统验证 `L1-identity` 是否真正满足“全局身份真相仓”的设计要求,尤其要证明以下几点成立:
- `GlobalMember` 是平台级唯一身份锚点
- 身份凭证 / 认证接缝不会污染核心身份真相
- platform role / capability 不与 project role 混层
- 下游仓消费的是稳定 ref / sync 接缝,不会复制一份新的全局成员真相
- summary / trace / audit projection 只读且不反写真相
- work / process / runtime / conversation 都能基于同一身份锚点协作

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| `GlobalMember` 真相层 | 真相对象 | P0 | 全局身份锚点与生命周期 |
| credential binding | 接缝对象 | P0 | 外部认证源与内部身份绑定 |
| platform role / capability mapping | 能力映射 | P0 | 平台级角色能力边界 |
| downstream member ref / sync | 接缝逻辑 | P0 | work / process / runtime / conversation 身份消费 |
| summary / trace / audit projection | 读模型 | P0 | 只读展示与审计轨迹 |
| work / process 身份边界联动 | 跨仓边界 | P1 | `GlobalMember` 与 `ProjectMember` 等接缝 |
| 外部认证源内部实现细节 | 非范围 | P2 | 只验证接缝,不验证外部服务内部逻辑 |
| 前端视觉细节 | 非范围 | P2 | 不覆盖控制台像素级展示 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和规则不变量 | domain / policy owner | `GlobalMember.pause/retire`、`CapabilityPolicy`、binding uniqueness rule | 状态与边界符合设计 |
| 集成测试 | 验证 service + repo + sync + projection 联动 | backend / domain owner | SyncGlobalMember、BindCredentialSource、RefreshCapabilityMapping、ResolveMemberRef | 真相写入、同步与投影刷新都成立 |
| 事件链测试 | 验证 lifecycle / capability / sync 事件链 | integration / platform owner | `identity.member.*`、`identity.lifecycle.*`、`identity.capability.*` | 输入输出语义正确 |
| 边界专项测试 | 验证真相/接缝/投影分层 | architecture / QA | `GlobalMember` vs `ProjectMember`、platform role vs project role、projection 只读 | 红线不被突破 |
| 端到端主线测试 | 验证最小可运行闭环 | QA / owner | bind credential → sync member → lifecycle change → capability refresh → resolve ref → build summary | 主干场景完整跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `GlobalMember` 是唯一身份锚点 | 同步成员后 identity 持有唯一真相 | 集成测试 | 是 | DB / API / sync event |
| `ProjectMember` 不回写 `GlobalMember` | lifecycle 变化后下游分身收缩但不反向改写 | 边界专项测试 | 是 | sync trace / no reverse write |
| auth source 与主真相分层 | credential binding 独立持久化 | 集成测试 | 是 | binding record / member truth |
| platform role 不与 project role 混层 | capability refresh 不影响 project role | 边界专项测试 | 是 | mapping record / negative test |
| 投影只读 | summary / trace / audit 不反写真相 | 投影专项测试 | 是 | query trace / no write side effect |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地身份同步与边界验证 | local DB / fake auth source / fake event bus | debug logging / replay enabled | 容易只测单仓 happy path |
| test | CI / 集成测试 | test DB / controlled auth source / event bus | deterministic source fixtures | 外部 source 行为抽象不足 |
| staging | 端到端演练 | real-like work / process / runtime / conversation | sync delay / projection rebuild | 下游消费差异放大 |

## 5. 测试数据设计

| 数据类型 | 来源 | 用途 | 隔离方式 |
|---|---|---|---|
| GlobalMember 样本 | fixture | 验证全局身份真相与 lifecycle | 每用例独立 member_id |
| CredentialBinding 样本 | fixture + builder | 验证外部 source 绑定与冲突 | source_id + external_subject 隔离 |
| CapabilityMapping 样本 | policy fixture | 验证 role / capability 推导 | 独立 capability set |
| MemberSyncEvent 样本 | event fixture | 验证下游同步接缝 | event_type / member_id 隔离 |
| Summary / trace projection 样本 | projection builder | 验证只读投影与审计轨迹 | 独立 projection rebuild context |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | 同步一个新成员 | 外部 source 有新成员事件 | SyncGlobalMember | 创建/更新 `GlobalMember` 真相 |
| TC-002 | 建立 credential binding | 外部 auth source 可用 | BindCredentialSource | binding 落库且可回链 |
| TC-003 | lifecycle 变化后下游同步 | member 已存在 | UpdateGlobalLifecycle | `GlobalMember` 收缩,下游收到 sync |
| TC-004 | platform capability 刷新 | member 已存在 | RefreshCapabilityMapping | capability 映射更新且不污染 project role |
| TC-005 | resolve stable member ref | member 已存在 | ResolveMemberRef | 返回稳定 `MemberRef` |
| TC-006 | summary / trace projection 查询 | member / lifecycle / binding 已存在 | QueryIdentitySummary | 返回只读摘要与 trace |
| TC-007 | binding 冲突拦截 | 同一 source+subject 指向不同成员 | BindCredentialSource | 返回冲突错误 |
| TC-008 | 下游 ref 不得回写真相 | downstream sync 后试图反向写 | negative flow | 被阻断 |
| TC-009 | projection 不一致可重建 | projection 延迟或损坏 | rebuild projection | summary / trace 可恢复 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | 全局身份真相混层 / auth source 污染真相 / 投影反写真相 | 阻断放行,必须修复 |
| A | 主线可跑但 sync / capability / audit 轨迹不稳 | 原则上修复后再放行 |
| B | 非关键摘要视图或低优先级场景异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 `GlobalMember` lifecycle 逻辑,都必须回归下游 sync 与只读投影
- 每次改动 credential binding / auth source 接缝,都必须回归 binding uniqueness 与主真相隔离
- 每次改动 capability mapping,都必须回归 platform role 与 project role 分层检查

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 后续接入更多 auth source 可能需要扩展 binding 矩阵 | 05 测试矩阵需扩充 | TL / 架构 |
| 下游仓对 sync 事件消费实现仍可能细化 | 部分 contract 测试需后续迭代 | Owner / TL |

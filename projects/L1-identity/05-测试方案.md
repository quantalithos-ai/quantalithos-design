## 2. 本次测试目标与范围

> 校准来源:
> - `design-calibration/05_test_plan_step_02_scope.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/05_test_plan_step_02_scope.md` 的“SOP 问题回答”“范围 / 非范围表”“P0 / P1 / P2 优先级口径”和“一票否决关联表”小节,了解测试目标与范围如何收敛。

本轮测试目标是证明 `L1-identity` 作为平台级 AI 员工身份真相仓成立,并能以可执行测试和可归档证据阻断 `VETO-ID-001~006`。

### 2.1 P0 范围

P0 覆盖以下能力和规则:

| 范围 | 测试目标 |
|---|---|
| 核心闭环 | 覆盖 `C-ID-1~C-ID-5`,证明 identity anchor、lifecycle、role/capability summary、career/memory refs 和 consumption traceability 成立 |
| 功能需求 | 覆盖 `FR-ID-001~014`,包括建立身份、读取摘要、生命周期、角色能力摘要、生涯追加、memory refs、消费追溯和投影 / 引用对账 |
| 业务规则 | 覆盖 `BR-ID-001~015`,验证 ref 稳定、显式变化、来源边界、append-only、report-only reconciliation 和 forbidden material |
| 非功能 | 覆盖 `NFR-ID-001~009`,以 sample / trend、degraded/no-write、redaction、traceability、idempotency 和 observability 验证为主 |
| 验收方向 | 覆盖 `AC-ID-001~015`,为新版 `06-验收标准.md` 提供可消费 evidence |
| 一票否决 | 覆盖 `VETO-ID-001~006`,任一命中不得风险接受 |
| 入口族 | 6 Command、14 Query、5 Inbound Event / Callback、10 Outbound Material、6 Operations Job |
| 横切规则 | state matrix、UoW、stored replay、duplicate no-rerun、query no-write、job no truth repair、dependency boundary、P0 profile config、redaction |

### 2.2 P1 / P2 范围

| 优先级 | 内容 | 处理方式 |
|---|---|---|
| P1 | durable-like / real-like adapter seam、real-like bus/resolver/handoff/archive/governance basis/source selected-run | 只在明确 selected-run 环境存在时执行;不可用时记录 residual,不计 P0 pass |
| P2 | production-like profile、capacity、hard SLO、external HR / IdP、advanced employee homepage / dashboard、complex organization、full event-sourcing-first | 当前只作为 residual 或 future trigger,不得作为 P0 阻断 |

### 2.3 非范围

| 非范围 | 原因 | 当前处理 |
|---|---|---|
| 真实 DB / bus / archive / metric / secret provider 产品行为 | 产品未锁定 | P0 只验证 port / adapter seam;真实产品进入 P1/P2 |
| 完整跨仓端到端业务流程 | sibling 仓真实状态机和权限语义不属于 identity P0 | P0 使用 refs、safe snapshots、events、adapters 和 replay fixtures |
| 外部 HR / IdP 深度集成 | 外部身份系统不得反向定义 identity truth | P2 处理 |
| 生产容量和硬性能阈值 | 当前无正式容量模型和 deployment baseline | P0 只要求 duration/count sample |
| UI / dashboard / report 体验 | 产品体验不影响本轮 truth center 成立 | P2 处理 |

### 2.4 VETO 承接

| VETO | P0 断言方向 |
|---|---|
| `VETO-ID-001` | 成员身份 ref 不得复用给另一个成员 |
| `VETO-ID-002` | Query、consumer、callback、projection、maintenance job 不得隐式创建 identity truth |
| `VETO-ID-003` | 外部正文、credential、token、raw secret 不得进入 identity truth、event、trace、audit、report 或 artifact |
| `VETO-ID-004` | 高风险 lifecycle 缺少治理 / 授权依据时不得 accepted |
| `VETO-ID-005` | Reconciliation / maintenance job 只能 report-only,不得修复相邻仓 truth |
| `VETO-ID-006` | 除 `L0-core` / core contracts 外不得引入 sibling business compile-time dependency 或 truth mixing |

| `contracts_body_free_command_schema` | `03` protocol + redaction contracts | 6 个 Command DTO 只含 refs、markers、safe summary refs | P0 |

P0 入口族数量固定如下:

| 入口族 | 数量 | 测试要求 |
|---|---:|---|
| Command | 6 | 每个覆盖 accepted 或主线,并通过 common negative 覆盖 duplicate、digest conflict、version / rollback |
| Query | 14 | 每个覆盖 hit / missing 或 representative branch;query family 必测 no-write |
| Inbound Event / Callback | 5 | 覆盖 accepted、duplicate receipt、unsupported、delayed / quarantined |
| Outbound Material | 10 | 覆盖 payload snapshot、topic/target binding、body-free marker 和 publish failure |
| Operations Job | 6 | 覆盖 completed、partial / failed、duplicate report replay 和 no truth repair |

测试对象不得从 query、consumer、callback、projection 或 job 反向扩展业务 truth schema。若某切口无法通过正式 ref、state、view、repository 或 mapper 构造,该切口进入 blocker,不得用 ad hoc string ref 或 fake 私有 map 绕过。

## 4. 测试策略与分层

> 校准来源:
> - `design-calibration/05_test_plan_step_04_strategy_layers.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/05_test_plan_step_04_strategy_layers.md` 的“测试分层图”“测试分层表”“切口到测试层级映射”和“E2E / release gate 使用边界”小节,了解各层测试职责如何划分。

#### 测试分层图: L1-identity 测试金字塔

```text
                    [release gate / evidence summary]
                 main smoke, reports, redaction, dependency
              -----------------------------------------------
                  [API / worker / operations job entry]
              handler mapping, worker disposition, job report
              -----------------------------------------------
              [integration with fake / controlled adapters]
          repository semantics, runtime builder, failure injection
              -----------------------------------------------
                       [application service tests]
             command/query/consumer/job orchestration, UoW
              -----------------------------------------------
                    [unit / contract / domain tests]
             DTO, value object, policy, state, config parser
```

### 4.1 分层职责

| 层级 | 主要目标 | 典型内容 | 阻断规则 |
|---|---|---|---|
| Unit / Contract | 尽早发现 schema、状态、不变量和纯函数错误 | DTO roundtrip、metadata required、domain factory、policy reject、state matrix、config parser、redaction helper | 失败则不进入 service 测试 |
| Application service | 验证正式 flow 编排、UoW、幂等、错误映射和副作用顺序 | command accepted transaction、query no-write、consumer/callback receipt、stored result / report、commit unknown、rollback | P0 阻断 |
| Integration with fake / controlled adapters | 验证 repository / adapter 语义、runtime builder 和 failure injection | version conflict、rollback、projection lookup、reference bundle version、outbox marker、publisher / handoff failure、profile assembly | P0 阻断;real-like 缺口只作 residual |
| API / Worker / Job entry | 验证入口 DTO 解析、handler mapping、worker disposition、job runner report | required fields、query response surface、worker unsupported / delayed / quarantined、job duplicate replay | P0 阻断 |
| Release gate / evidence summary | 验证最小跨入口闭环、报告生成、redaction、依赖裁剪和 evidence 汇总 | release smoke、config digest、redaction scan、dependency check、artifact / report completeness | P0 失败阻断送验 |

### 4.2 切口到主发现层级

| 测试切口 | 主发现层级 | 辅助层级 |
|---|---|---|
| Contract / body-free schema | Unit / Contract | Entry validation |
| Domain factory / state guards | Unit / Domain | Service negative tests |
| Command accepted / rejected flow | Application service | Integration repository fault |
| Query no-write / degraded | Application service | Release smoke representative case |
| Consumer / callback | Worker entry | Application service / receipt store |
| Outbound material / publish | Operations job / integration | Redaction / report audit |
| Operations job | Job entry / operations replay | Fault injection matrix |
| Idempotency / UoW / repository | Integration with fake / controlled adapters | Service / operations replay |
| Config / runtime builder | Unit / config + integration runtime | Release config check |
| Redaction / dependency | Dedicated checks | Release gate |

### 4.3 Release gate 使用边界

Release gate 只用于证明跨入口最小闭环、profile 装配、redaction scan、dependency scan、artifact/report completeness 和 evidence 汇总。它不替代 unit、service、integration、worker 或 job 层的具体断言。

P0 integration 使用 fake / controlled adapters,不要求真实 DB、bus、archive、metric、secret provider 或 external HR / IdP 产品。P1 real-like selected-run 和 P2 capacity 不得在环境缺失时伪装成 P0 pass。

### 7.2 数据构造规则

| 规则 | 正式口径 |
|---|---|
| deterministic ids | test builders use deterministic id ranges scoped by `test_run_ref`;assertions cannot depend on random ids |
| fixed clock | time-dependent states use fake clock seeded by run;expected values cannot use real current time |
| canonical digest | idempotency and request digest fixtures use the Step 13 canonicalization profile;volatile metadata excluded |
| body-free snapshots | external resolver fixtures return refs, safe summaries, digest refs and state only |
| forbidden body isolation | RoleDefinition、ProjectMember、memory text、archive package、credential、token、raw secret 只允许出现在 isolated negative fixture 中 |
| versioned state | existing state update fixtures include expected version;cursor is not used as optimistic version |
| formal refs only | projection/handoff/outbox fixtures use formal refs and marker refs;no ad hoc string refs |
| data minimality | dataset only carries fields needed by target assertion;hidden happy-path state must not mask negative assertions |
| fake fidelity | fake repositories/adapters enforce formal version、unique、rollback、failure and redaction behavior |

### 7.3 数据隔离与清理

| 数据类型 | 隔离键 | 清理方式 |
|---|---|---|
| in-memory truth / projection / reference / outbox / report stores | `test_run_ref` + subject/ref namespace | drop run namespace or reset store |
| idempotency / stored result / receipt / report | operation namespace + idempotency/event/job key | drop run namespace |
| fake resolver / publisher / handoff fault profiles | adapter slot + fault case id | reset fake profile after case |
| config parser / runtime builder fixtures | config case id + digest | no persistent cleanup |
| artifact / redaction leak corpus | leak case id | delete isolated fixture |
| dependency metadata | package graph digest | no persistent cleanup |
| future durable-like stores | `test_run_ref` + schema namespace | transaction rollback or run-scoped cleanup;not P0 until specified |

P0 数据不得从真实 sibling repo、真实 DB / bus / archive / secret provider、真实 HR / IdP 或真实 external body 读取。所有 sibling collaboration 只通过 refs、safe snapshots、events、adapters 或 replay fixtures 表达。

## 11. 缺陷管理与复验规则

> 校准来源:
> - `design-calibration/05_test_plan_step_11_defects_retest.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/05_test_plan_step_11_defects_retest.md` 的“缺陷分级表”“S 级阻断判定表”“修复后复验矩阵”“风险接受规则”“缺陷关闭证据清单”和“自动化防回归新增规则”小节,了解缺陷如何分级、修复、复验和关闭。

### 11.1 缺陷分级

| 等级 | 定义 | 示例 | 处理 |
|---|---|---|---|
| S | 一票否决、P0 truth 破坏、安全 / redaction / dependency / evidence integrity 红线 | `VETO-ID-001~006`;redaction 泄露;query/job 写 truth;non-core sibling compile dependency;duplicate rerun mutation;static evidence pass | 必须修复;不得风险接受;关闭需修复后 artifact/report |
| A | P0 用例失败但未命中 VETO,或 blocking suite 因实现 / 测试工具缺陷无法稳定证明 | accepted flow 少写非关键 report field;operations partial count 错;fake fault profile 不稳定 | 通常阻断 release;临时接受需证明不影响 P0 语义并有接受人 |
| B | 非 P0、P1/P2 selected-run、文档/报告清晰度、非阻断可维护性问题 | P1 real-like unavailable;候选 performance sample 偏高;report 文案不清但 raw artifact 完整 | 可排期或风险接受;不得影响 P0 pass |
| R | 已确认范围外或 future capability 风险 | production-like capacity、真实 HR/IdP behavior、真实 observability backend、complex organization、full event-sourcing-first | 记录 residual 和接受人;不得伪装已验证 |

### 11.2 S 级阻断判定

| 条件 | 来源 | 等级 |
|---|---|---|
| 成员身份 ref 被复用给另一个成员 | `VETO-ID-001` | S |
| query / consumer / callback / job 隐式创建 `GlobalMember` 或 identity truth | `VETO-ID-002` | S |
| identity 保存 RoleDefinition、ProjectMember、memory、artifact、conversation、runtime、archive body 或 credential/token/raw secret | `VETO-ID-003`;`AC-ID-014` | S |
| 高风险 lifecycle 缺少治理 / 授权依据仍 accepted | `VETO-ID-004` | S |
| reconciliation / maintenance job 修复相邻仓 truth 或 identity business truth | `VETO-ID-005` | S |
| 非 `L0-core` sibling business compile dependency 或 truth mixing | `VETO-ID-006` | S |
| P0 blocking suite 失败且不能证明为测试脚本自身错误 | Step 9 | S |
| report / evidence 静态伪造、缺 raw artifact/report 配对、failed artifact 被删除 | Step 13 | S |

### 11.3 修复后复验矩阵

| 缺陷触发面 | 必跑用例 / suite | 必跑 check | 关闭证据 |
|---|---|---|---|
| contracts DTO / metadata / schema / body-free | 原 TC + `TC-ID-CONTRACT-*` + `contract-domain-fast` | report pairing;redaction if body/output changed | suite report + case artifact |
| domain invariant / state / policy | 原 TC + same state/domain family + `contract-domain-fast` | redaction if error output changed | domain suite report |
| command accepted / rejected / UoW / outbox enqueue | 原 TC + related command family + `service-flow-fast` | report pairing;redaction | service suite report + UoW assertion artifact |
| query no-write / visibility / degraded | 原 TC + representative query no-write + `service-flow-fast` | write-audit;redaction | write-audit report + query suite report |
| inbound consumer / callback | 原 TC + duplicate/unsupported/delayed family + `entry-worker-job` | redaction | worker suite report |
| outbox / publisher / topic | 原 TC + `operations-replay-core` | redaction;topic/dependency if changed | operations report |
| job / replay / report | 原 TC + `entry-worker-job` or `operations-replay-core` | report-generation-audit | job report + replay artifact |
| idempotency / commit unknown / rollback | original idempotency TC + `infra-runtime-fake` + affected suite | report pairing | idempotency/fault artifact |
| redaction leak | failing leak case + `redaction-boundary` + affected suite | `check_redaction.sh` | clean redaction report |
| dependency boundary | `TC-ID-ARCH-001` + `dependency-boundary` | `check_dependency_boundary.sh` | dependency graph digest/report |
| release smoke closure | original scenario + `release-main-smoke` + affected lower suite | release redaction/dependency/report checks | release gate summary |

### 11.4 风险接受规则

P0 truth、VETO、redaction、dependency、config fail-fast、query no-write、job no-repair、stored replay 和 evidence integrity 不允许风险接受。

允许风险接受的范围仅限 P1/P2、future real-like selected-run unavailable、候选性能 sample、真实 product adapter 深度行为、production-like capacity、报告可读性或非阻断维护性问题。所有风险接受必须记录接受人、影响范围、触发条件和后续处理。

### 11.5 自动化防回归

以下情况必须新增或扩展自动化:

- 手工发现 P0 缺陷。
- Release smoke 发现但 lower suite 未发现。
- Redaction、dependency、report audit、write-audit 漏检。
- Query no-write 或 job no-repair 漏检。
- Duplicate/idempotency/fault injection 漏断言。
- P1/P2 风险升级为 P0。

### 12.1 进入准则

开始执行正式 P0 测试前必须满足:

- 新版 `00/01/02/03/04` 已作为测试真相源;若 `03/04` 发生影响 P0 contract/state/flow/port/config/redaction/gate 的变更,受影响 Step 已复审。
- P0 `TC-ID-*` 用例族均有数据前置、断言点、自动化候选和 `EV-CAND-ID-*` 候选证据。
- `DS-ID-*` P0 数据集可通过 fixture / builder / seed 构造,并具备 run namespace 隔离、fake reset 或 isolated fixture delete 规则。
- `ci-test`、`integration-like`、`operations-replay` profile 可装配;`local-dev` 仅作本地调试。
- P0 不依赖真实 sibling repo、真实 DB / bus / archive / object storage / secret provider / observability backend / HR / IdP 产品。
- P0 blocking suite、check scripts 和 report scripts 可运行。
- Artifact root 使用 `artifacts/test/<run_id>`;report root 使用 `reports/runs/<run_id>`;不得使用 `latest`。
- 缺陷分级和复验规则已可执行。

### 12.2 退出准则

P0 退出必须满足:

- 所有 P0 `TC-ID-*` 用例族通过,或明确属于 P1/P2 / future / residual 且不影响 P0 truth。
- `VETO-ID-001~006` 对应正负向测试、redaction check、dependency check、query no-write、job no-repair 和 release smoke 均通过。
- 所有 P0 blocking suite 通过:`contract-domain-fast`、`service-flow-fast`、`config-redline`、`dependency-boundary`、`infra-runtime-fake`、`entry-worker-job`、`operations-replay-core`、`redaction-boundary`、`release-main-smoke`、`report-generation-audit`。
- 所有 release checks 通过,包括 redaction、dependency、artifact/report pairing 和 no static evidence。
- 所有 blocking suite 均有 raw artifact 和 run report 配对。
- `reports/runs/<run_id>/gate-summary.md`、suite reports、redaction-check、dependency-boundary、report-audit 和 evidence index 可生成。
- 当前无 S 级缺陷。
- 当前无未接受且影响 P0 release 的 A 级缺陷。
- B/R 或 P1/P2 residual 风险均记录接受人、影响范围和后续触发条件。
- 性能结构性 sample 存在;旧 P95/SLA 候选未达不作为 P0 退出失败。

| `EV-ID-ARCH-001` | `dependency-boundary`;`check_dependency_boundary.sh` | `artifacts/test/<run_id>/suites/dependency-boundary/`;`reports/runs/<run_id>/dependency-boundary.md` | `TC-ID-ARCH-001` | `AC-ID-011~015`;`VETO-ID-006` |
| `EV-ID-NFR-001` | release / operations / redaction samples | `artifacts/test/<run_id>/suites/<suite>/` | related `TC-ID-QUERY/JOB/REDACTION/CONFIG-*` | `AC-ID-015` |

### 13.3 Artifact 目录结构

```text
artifacts/test/<run_id>/
  meta/context.json
  meta/config-digest.json
  meta/source-commits.json
  evidence-index.json
  suites/<suite>/report.json
  suites/<suite>/stdout.log
  suites/<suite>/stderr.log
  suites/<suite>/cases/<case_id>.json
  suites/<suite>/artifacts/<safe_artifact_name>.json
```

Raw artifact 是测试证据 schema,不是产品 DTO。固定规则:

- Schema owner: identity test artifact writer local schema;不进入 public contracts、application DTO、domain object 或 adapter port。
- `status`: `passed`,`failed`,`partial`,`skipped`,`unavailable`
- `assertion_status`: `passed`,`failed`,`skipped`,`not_run`
- `redaction_status`: `clean`,`failed`,`not_applicable`
- `review_status`: `pending`,`reviewed`,`disputed`
- `artifact_digest_algorithm`: `sha256`
- `artifact_digest`: `sha256:<64 lowercase hex chars>`

Digest input 是同一 JSON object 去掉 `artifact_digest` 字段后的 canonical UTF-8 JSON。Canonical JSON 使用字典序 object keys、数组保持原顺序、无无意义空白。

### 13.4 Raw artifact 必填字段

| Artifact | 必填字段摘要 |
|---|---|
| `meta/context.json` | `schema_version=identity.artifact.v1`,`run_id`,`suite_refs`,`config_profile`,`started_at`,`tool_version`,`redacted_environment`,`artifact_root`,`report_root`,`artifact_digest_algorithm`,`artifact_digest` |
| `meta/source-commits.json` | `schema_version`,`run_id`,`design_source_ref`,`implementation_source_ref`,`core_contracts_source_ref`,`additional_source_refs`,`generated_at`,`artifact_digest_algorithm`,`artifact_digest` |
| `meta/source-commits.json.additional_source_refs[]` | `source_name`,`source_role`,`source_ref`,`source_digest`,`dirty_state` |
| `meta/config-digest.json` | `schema_version`,`run_id`,`config_applicability`,`config_profile`,`config_digest_algorithm`,`config_digest`,`config_digest_material`,`config_sources`,`config_reason_ref`,`redaction_status`,`generated_at`,`artifact_digest_algorithm`,`artifact_digest` |
| `meta/config-digest.json.config_sources[]` | `source_kind`,`source_ref`,`source_digest`,`required` |
| `suites/<suite>/report.json` | `schema_version`,`run_id`,`suite`,`status`,`case_refs`,`case_digests`,`failure_reason_ref`,`duration_ms`,`config_profile`,`started_at`,`finished_at`,`stdout_digest`,`stderr_digest`,`artifact_digest_algorithm`,`artifact_digest` |
| `suites/<suite>/cases/<case_id>.json` | `schema_version`,`run_id`,`suite`,`case_id`,`tc_refs`,`status`,`assertions`,`failure_reason_ref`,`evidence_candidate_refs`,`evidence_refs`,`duration_ms`,`artifact_digest_algorithm`,`artifact_digest` |
| `suites/<suite>/cases/<case_id>.json.assertions[]` | `assertion_id`,`assertion_ref`,`assertion_status`,`assertion_kind`,`safe_message`,`safe_message_ref`,`safe_detail_refs`,`failure_reason_ref` |
| `evidence-index.json` item | `evidence_id`,`run_id`,`suite_refs`,`tc_refs`,`ac_refs`,`veto_refs`,`artifact_paths`,`artifact_digests`,`report_paths`,`status`,`redaction_status`,`review_status`,`safe_summary` |

`source_role` 允许值为 `design`,`implementation`,`core-contracts`,`dependency`,`test-tool`,`other`。`dirty_state` 允许值为 `clean`,`dirty`,`unknown`。`config_applicability` 允许值为 `applicable`,`not_applicable`;`commit-02-b` 这类不使用正式运行时配置面的 contract/domain run 可使用 `not_applicable`,此时 `config_profile=not_applicable`,`config_sources=[]`,`config_digest` 为 canonical `{}` 的 sha256 digest,且必须填写安全 `config_reason_ref`。`source_kind` 允许值为 `default`,`file`,`env`,`cli`,`generated`,`test-fixture`,`none`。`assertion_kind` 允许值为 `contract`,`domain`,`state`,`flow`,`redaction`,`dependency`,`evidence`,`config`,`other`。`assertion_status=failed` 时必须填写 `failure_reason_ref`。

### 13.5 Reports 目录结构

```text
reports/
  README.md
  runs/<run_id>/
    summary.md
    evidence-index.md
    gate-summary.md
    redaction-check.md
    dependency-boundary.md
    report-audit.md
    suites/<suite>.md
    evidence/EV-ID-<TYPE>-<NNN>.md
  acceptance/
    handoff.md
    veto-checklist.md
    risk-acceptance.md
    open-issues.md
  review/
    reviewer-notes.md
    agent-review.md
```

`reports/runs/<run_id>/*` 必须从 `artifacts/test/<run_id>` 推导。`reports/acceptance/*` 可以由脚本生成初稿,但必须保留审查补充区。任一 report 不得包含 raw secret、token、credential value、private key、完整外部业务正文或 full sensitive ref。

### 13.6 失败证据规则

| 场景 | 必须保留 | 处理 |
|---|---|---|
| suite failed | `report.json`、stdout/stderr、failure reason、已执行 case JSON | report 标记 failed,不得删除 |
| suite timeout | partial `report.json` 或 timeout artifact、stdout/stderr | status=`failed` 或 `partial`,不得 pass |
| redaction failed | safe failure ref、scan summary、泄漏位置的脱敏标记 | 不得输出 raw secret/body |
| dependency failed | dependency graph digest、安全摘要、违规 dependency ref | 不得隐藏 sibling dependency |
| report generation failed | generation failure report、输入 artifact digest | 阻断退出,不得手写补 pass |
| P1 selected-run unavailable | unavailable marker、safe reason、residual entry | 不计 P0 pass |

> 延伸阅读:

### 14.2 全量 P0 回归集

全量 P0 regression 至少包含:

- `contract-domain-fast`
- `service-flow-fast`
- `config-redline`
- `dependency-boundary`
- `infra-runtime-fake`
- `entry-worker-job`
- `operations-replay-core`
- `redaction-boundary`
- `report-generation-audit`
- `release-main-smoke`
- release config / redaction / dependency / report audit checks
- Step 13 evidence index generation and review-ready acceptance draft

触发全量 P0 regression 的条件:

- 任何 `VETO-ID-001~006` 相关修复或变更。
- `03-详细设计.md` 对 truth object、public protocol、state matrix、UoW/idempotency/outbox/job/report 语义变更。
- `04-配置设计.md` 对 P0 profile、adapter availability、source priority、topic map、fail-fast / degraded 规则变更。
- Redaction、dependency、report integrity 或 release gate 脚本变更。
- 任一 S 级缺陷修复。

### 14.3 最小回归选择规则

| 规则 | 说明 |
|---|---|
| 原失败 TC 必跑 | 修复缺陷时原失败用例必须通过 |
| 同 family 必跑 | 同一 `TC-ID-*` family 下的正向、负向、duplicate、no-write 或 partial case 必须覆盖代表项 |
| 相邻 suite 必跑 | contract/domain 变更带 service;service 变更带 outbox/report;job 变更带 report audit |
| 相关 check 必跑 | redaction/dependency/report/evidence 相关变更必须跑对应 check |
| 不能用 P1 代替 P0 | P1 selected-run 不能替代 P0 fake/controlled regression |

### 14.4 残余风险

| 风险 | 未覆盖原因 | 影响 | 缓解方式 | 接受人 |
|---|---|---|---|---|
| P1 real-like selected-run 不作为 P0 阻断 | 真实产品 / 环境未锁定 | 不能证明真实 adapter 端到端行为 | P0 使用 fake/controlled;P1 available 时 selected-run | 验收负责人待确认 |
| 真实 DB / bus / archive / metric / secret provider 产品行为未覆盖 | 产品选型未锁定 | 不能证明具体产品性能和故障模式 | 产品绑定后补 P1/P2 | 架构负责人待确认 |
| 完整跨仓端到端业务流程未覆盖 | sibling 仓真实状态机和权限语义不在 identity P0 | 不能证明真实全链路业务消费体验 | 后续 cross-repo integration 补测 | 验收负责人待确认 |
| external HR / IdP 深度集成未覆盖 | 外部身份系统非 P0 依赖 | 不能证明 vendor identity semantics | 真实集成走 P2 | 产品负责人待确认 |
| production-like capacity 未覆盖 | 无正式容量模型和部署基线 | 不能证明高并发 / 长时间运行容量 | 只保留 duration/count sample;容量基线后补 P2 | 架构负责人待确认 |
| 旧 P95 / SLA 数字未硬化 | 当前需求声明为候选目标 | 不能按 numeric threshold 裁决 pass | 保留 sample/trend;硬化需新版 `06` 定义 | 验收负责人待确认 |
| advanced employee homepage / dashboard / analytics 未覆盖 | 当前 P0 只证明基础 query/read model | 不能证明复杂消费体验 | 高级产品体验 P2 | 产品负责人待确认 |
| complex organization、automatic capability rating、performance scoring 未覆盖 | 当前 P0 禁止外围增强反向定义 identity truth | 不能证明复杂人力模型 | future capability | 产品负责人待确认 |
| full event-sourcing-first 未覆盖 | P0 采用当前 detailed design truth + trace + replay 口径 | 不能证明全量事件溯源架构 | 架构演进风险 | 架构负责人待确认 |
| 证据保留天数未固定 | 属于归档运维策略 | 不能证明长期审计保留满足外部要求 | 保留到验收和复验关闭;具体天数进新版 `06` 或运维标准 | 验收负责人待确认 |

### 14.5 不可风险接受项

以下项目不得进入 residual 或风险接受:

- `VETO-ID-001~006` 命中。
- Forbidden body / secret / credential / token / full sensitive ref 泄露。
- 非 core sibling compile dependency。
- Query、consumer、callback、job 反写真相或隐式创建 identity truth。
- Accepted truth missing trace/audit/outbox/stored result。
- Static evidence pass、缺 raw artifact/report pairing、failed artifact 被删除。
- P0 profile unavailable but marked passed。
- Duplicate replay reruns mutation or recomputes from current truth。

### 14.6 必须转入新版 `06-验收标准.md` 的事项

| 事项 | 原因 |
|---|---|
| VETO 正式通过 / 不通过裁决矩阵 | `05` 只定义测试证据 |
| P1 selected-run 是否强制 | 当前非 P0 |
| performance threshold 是否硬化 | 当前只保留 sample/trend |
| evidence retention days | 当前未固定天数 |
| risk acceptance approval role | 当前用角色待确认 |
| production-like / capacity gate | 当前 P2 |

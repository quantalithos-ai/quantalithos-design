### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L1-identity` 的第一批核心设计主线展开。当前 `02-概要设计.md` 与 `03-详细设计.md` 已经明确:
- `L1-identity` 是全局身份真相仓
- `GlobalMember` 是平台级唯一身份锚点
- 身份凭证与认证接缝、平台级角色能力、对外身份映射、审计投影必须分层
- `ProjectMember` 不回写 `GlobalMember`
- summary / trace / audit projection 只读不反写真相
- work / process / runtime / conversation 都应通过稳定 ref 或 sync 消费 identity

因此,本次验收的目的不是笼统判断“成员信息能不能读到”,而是判断 identity 的全局身份真相、认证接缝、平台级能力边界、下游分身接缝和只读投影是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 全局成员主语部分 | 是 | `GlobalMember` 真相与生命周期 |
| 身份凭证与认证接缝部分 | 是 | auth source / credential binding |
| 全局角色与能力映射部分 | 是 | platform role / capability |
| 对外身份映射与分身接缝部分 | 是 | downstream stable ref / sync |
| 身份审计与只读投影部分 | 是 | summary / trace / audit projection |
| work / process / runtime 身份边界 | 是 | 下游消费 identity 方式 |
| 外部认证源内部实现细节 | 否 | 只验接缝,不验外部服务内部逻辑 |
| 前端视觉细节 | 否 | 不在本次仓级验收范围内 |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|

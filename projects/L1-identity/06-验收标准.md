### 读前说明 · 验收标准生产流程

`06-验收标准` 不是测试用例清单,而是仓级裁决文档。它回答的是:

```text
该仓是否达到约定?
是否可以签收?
是否可以进入开发 / 发布 / 下一阶段?
哪些问题会阻断?
哪些证据可以支撑结论?
```

本文从 `00/02/03/05` 已明确的目标、边界、主流程、异常流、测试门禁和架构红线反推验收门禁。

建议按以下流程执行验收:

1. **先固定基线**
   - 确认需求、概要设计、详细设计、测试方案版本
   - 确认送验 commit、配置、环境、测试数据和证据目录
2. **再确认验收对象**
   - Command API
   - Query API
   - Inbound Event Consumer
   - Operations Job
   - 数据真相、outbox、projection、audit 和 redline
3. **按门禁裁决**
   - 每条验收项必须可判定、可阻断、可留证
   - P0 项失败即不得通过
   - 有条件通过必须记录接受人、失效条件和后续处理计划

> 本文不重复 `05-测试方案.md` 的全部测试场景,只定义放行必须满足的验收条件和证据要求。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L1-identity` 第一批实现主干展开。当前设计已经明确:

- `L1-identity` 是平台级 AI 员工身份真相仓
- `GlobalMember` 只能通过 `HireGlobalMember` 显式创建
- 查询接口只读,查询不到成员时不得自动创建
- lifecycle 普通迁移与 tombstone 高风险流程分离
- `RoleCatalogEntry` 只是 method-library role 的本地索引,不复制 `RoleDefinition` 正文
- `CapabilityProfile` 只保存能力画像和 evidence refs,不保存 artifact 正文
- `MemoryRefs` 只保存 memory/archive 引用,不保存 memory 原文、embedding 或检索索引
- career history 以 append-only 方式记录项目经历输入
- command / event 事务内必须写 write model、audit、outbox、idempotency record
- outbox publisher 只发布已持久化事件,projection rebuild 只重建查询视图
- identity 不做登录、token、session、credential 校验,入口安全由 Gateway / API Layer 完成

因此,本次验收不是笼统判断“成员信息能不能读到”,而是裁决 identity 是否真的形成了可审计、可事件联动、可被下游稳定消费的身份真相源。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| `GlobalMember` 真相与 lifecycle | 是 | 显式创建、普通生命周期迁移、不可逆 tombstone |
| `RoleCatalogEntry` 本地索引 | 是 | 从 method-library 同步索引和 fingerprint,不复制正文 |
| `CapabilityProfile` | 是 | 成员能力画像、证据引用、版本更新 |
| `CareerHistory` | 是 | append-only 记录 work / process 输入的项目经历 |
| `MemoryRefs` | 是 | semantic / episodic / archive refs 与归档状态 |
| Command API | 是 | `HireGlobalMember`、`UpdateLifecycle`、`UpdateCapabilityProfile`、`UpdateMemoryRefs`、`TombstoneMember` |
| Query API | 是 | `GetMemberSummary`、`GetMemberAuditTrace`、`GetRoleCatalog` |
| Inbound Event Consumer | 是 | `SyncRoleCatalog`、`AppendCareerEntry`、`HandleMemoryArchiveEvent`、`HandleGateDecisionEvent` |
| Operations Job | 是 | `PublishOutboxEvents`、`RebuildMemberSummaryProjection`、`ReconcileRoleCatalog` |
| Outbox / Projection / Audit | 是 | 事件发布、只读投影、审计追踪和恢复证据 |
| Gateway 登录 / token / session / credential 校验 | 否 | 属于 Gateway / API Layer 或安全层 |
| `ProjectMember` 分配和项目内成员状态 | 否 | 属于 member-service / work 等下游域 |
| `RoleDefinition` 正文和方法内容编排 | 否 | 属于 method-library |
| memory 原文、embedding、检索算法 | 否 | 属于 memory / archive |
| 前端视觉细节 | 否 | 不在本仓级验收范围内 |

## 4. 功能验收门禁

### 4.1 P0 最小闭环门禁

| 验收 ID | 验收对象 | 通过标准 | 阻断条件 | 证据 |
|---|---|---|---|---|
| AC-P0-001 | 第一批最小闭环 | `SyncRoleCatalog -> HireGlobalMember -> PublishOutboxEvents -> RebuildMemberSummaryProjection -> GetMemberSummary` 可端到端跑通 | 任一环节不可执行或证据链断裂 | end-to-end trace / DB rows / outbox log / query response |
| AC-P0-002 | 显式创建原则 | `GlobalMember` 只能由 `HireGlobalMember` 创建 | query、projection rebuild、event handler 隐式创建成员 | API 记录 / DB diff / negative test |
| AC-P0-003 | 真相与投影分离 | write model 是成员真相,projection 只读且可重建 | projection 反写 write model 或被当作真相源 | projection rebuild 证据 / DB 权限或代码检查 |
| AC-P0-004 | 事件可靠发布 | command / event 事务内写 outbox,发布失败不回滚业务事实 | bus 失败导致业务事实回滚或事件丢失 | outbox status / publish log / retry 记录 |

### 4.2 Command API 验收

| 验收 ID | 验收对象 | 前置条件 | 通过标准 | 阻断条件 | 证据 |
|---|---|---|---|---|---|
| AC-CMD-001 | `HireGlobalMember` | active `RoleCatalogEntry` 存在,幂等键存在 | 创建 `GlobalMember`,写 lifecycle history、audit、outbox、idempotency record | 重复创建、未写审计、未写 outbox、role 不存在仍创建 | API response / DB rows / audit trace / outbox event |
| AC-CMD-002 | `HireGlobalMember` 幂等 | 同一 idempotency key 重放 | 相同 request 返回既有结果,不同 request 返回冲突 | 幂等键失效导致重复成员或静默覆盖 | idempotency record / response compare |
| AC-CMD-003 | `UpdateLifecycle` | member 存在,目标状态合法 | 按状态机完成 hired / active / paused / retired 等合法迁移 | 非法迁移成功、普通 lifecycle 入口进入 tombstoned | lifecycle history / error code / audit trace |
| AC-CMD-004 | `UpdateCapabilityProfile` | member 存在,evidence refs 合法 | 更新能力画像并保留 evidence refs,不保存 artifact 正文 | 写入 artifact 正文或无版本追踪 | capability row / audit trace / negative data check |
| AC-CMD-005 | `UpdateMemoryRefs` | member 存在,memory/archive refs 合法 | 更新 semantic / episodic / archive refs,不保存 memory 原文或 embedding | 保存 memory 正文、无效 ref 被接受 | memory_refs row / negative data check |
| AC-CMD-006 | `TombstoneMember` | Gate approved,memory/archive 可确认 | 成员进入 tombstoned,记录 GateDecisionRef、history、audit、outbox | 无 Gate 进入 tombstoned、tombstone 可逆、归档失败仍完成 | Gate ref / lifecycle row / audit / outbox |

### 4.3 Query API 验收

| 验收 ID | 验收对象 | 前置条件 | 通过标准 | 阻断条件 | 证据 |
|---|---|---|---|---|---|
| AC-QRY-001 | `GetMemberSummary` | projection 已生成 | 返回成员摘要 DTO,字段符合可见性裁剪规则 | 查询直接拼装外部正文或绕过 projection | query response / projection row |
| AC-QRY-002 | `GetMemberSummary` not ready | write model 已提交但 projection 未追上 | 返回约定的 not ready / not found 语义,不触发创建或 rebuild | 查询自动创建成员或写 projection | response / DB diff / negative test |
| AC-QRY-003 | `GetMemberAuditTrace` | audit trace 存在 | 返回可追溯的 command / event / actor / result 链路 | 缺少关键操作记录或无法关联 actor | audit response / audit rows |
| AC-QRY-004 | `GetRoleCatalog` | role catalog 已同步 | 返回 role 索引摘要和 fingerprint,不返回 `RoleDefinition` 正文 | 复制或暴露 method-library 正文 | query response / payload check |

### 4.4 Inbound Event Consumer 验收

| 验收 ID | 验收对象 | 前置条件 | 通过标准 | 阻断条件 | 证据 |
|---|---|---|---|---|---|
| AC-EVT-001 | `SyncRoleCatalog` | method-library event 可消费 | upsert `RoleCatalogEntry`,保存 spec_source / fingerprint,写 outbox / audit | 复制 RoleDefinition 正文或重复事件导致重复记录 | role row / event log / audit |
| AC-EVT-002 | `AppendCareerEntry` | work / process 事件可消费 | append-only 追加 career entry,不改写 work/process 真相 | 覆盖历史、反写外部域、重复事件重复追加 | career rows / idempotency record |
| AC-EVT-003 | `HandleMemoryArchiveEvent` | memory/archive 事件可消费 | 更新 archive 状态和 refs,保留外部 ref | 保存 memory 正文或事件乱序导致状态倒退 | memory_refs row / event sequence evidence |
| AC-EVT-004 | `HandleGateDecisionEvent` | governance Gate 事件可消费 | 记录 Gate 决策并唤醒 pending 高风险流程,不替代 command | event handler 直接 tombstone 或绕过 command | pending flow record / audit trace |
| AC-EVT-005 | dead-letter / replay | 坏事件或依赖失败可构造 | 消费失败进入 dead-letter 或可重试状态,replay 可留证 | 坏事件丢失、无限重试无告警 | dead-letter row / replay log |

### 4.5 Operations Job 验收

| 验收 ID | 验收对象 | 前置条件 | 通过标准 | 阻断条件 | 证据 |
|---|---|---|---|---|---|
| AC-OPS-001 | `PublishOutboxEvents` | pending outbox 存在,L0-bus 可用 | 发布成功后标记 published,保留 publish trace | 先标记后发布、重复发布不可识别 | outbox row / bus log |

## 5. 非功能验收门禁

| 维度 | 验收条件 | 第一批阈值 / 口径 | 阻断条件 | 证据 |
|---|---|---|---|---|
| 性能 | `GetMemberSummary` 读取 projection | 第一批记录 P95 基线,不得退化为实时拼装全量 write model | 高频查询依赖外部域正文或全表扫描 | benchmark / query plan |
| 一致性 | command / event 本地事务 | write model、append-only 记录、audit、outbox、idempotency 同事务成功或失败 | 部分成功导致事实、审计、事件不一致 | integration test / DB transaction evidence |
| 可用性 | outbox 发布失败可恢复 | bus 故障不影响已提交业务事实,可重试 | bus 失败导致 command 不可恢复或事实丢失 | failure injection / retry log |
| 可恢复性 | projection 可重建 | projection 可从持久化事实重建,checkpoint 可断点续跑 | projection 损坏后无法恢复 | rebuild report / checkpoint rows |
| 可观测性 | 关键操作可追踪 | command、event、outbox、projection、dead-letter 均有 trace / log | P0 路径无 trace 或无法定位失败点 | log / trace / dashboard |
| 可审计性 | 敏感操作有 audit | lifecycle、tombstone、capability、memory refs、role sync 留痕 | tombstone 或 lifecycle 无审计 | audit rows / audit query |
| 兼容性 | 下游消费 stable ref | work / process / runtime / conversation 通过 ref 或 query 消费 identity | 下游需要复制 identity 真相或反写 identity | contract test / interface review |

## 6. 架构红线验收门禁

| 红线 | 验收条件 | 一票否决条件 | 证据 |
|---|---|---|---|
| 不做身份校验 | identity 不实现登录、token、session、credential 校验,只消费可信 `ActorContext` | identity 内出现 credential secret、token 校验、session 管理主逻辑 | 代码检查 / 数据检查 / negative test |
| 创建 / 查询分离 | 成员创建只能走 `HireGlobalMember`,查询不存在返回错误或 not ready | query、projection、event handler 自动创建 `GlobalMember` | DB diff / negative test |
| ref-only | Role、Memory、Artifact、Work、Process 只保存稳定 ref 或摘要索引 | 保存外部正文、memory 原文、embedding、RoleDefinition 正文 | payload / DB schema / 代码检查 |
| projection 只读 | projection 只服务查询,可重建,不得反写 write model | projection builder 修改业务真相 | rebuild test / 代码检查 |
| outbox 不做业务决策 | outbox publisher 只发布已持久化事件 | publisher 创造业务事件或修改 lifecycle | outbox log / 代码检查 |
| tombstone 必须经过 Gate | tombstone 只能由 `TombstoneMember` 在 approved Gate 后执行 | 无 Gate 进入 tombstoned 或 event handler 直接 tombstone | Gate ref / negative test |
| 下游不得反写真相 | work / process / runtime / conversation 只能消费 stable ref 或发事件请求 | 下游直接覆盖 `GlobalMember` 真相 | contract test / data ownership check |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 阻断条件 | 证据 |
|---|---|---|---|
| 入口安全边界 | identity 入口信任 Gateway / API Layer 注入的 `ActorContext`,不持有认证实现 | identity 内实现外部登录接入、credential 校验或 token 解析 | 代码检查 / 接口检查 |
| 操作人可追踪 | command / event handler / operations job 必须能追踪 actor 或 system actor | 关键变更无法追踪执行主体 | audit trace |
| 高风险操作治理 | `TombstoneMember` 必须记录 `GateDecisionRef` | tombstone 无 gate 证据或 gate rejected 仍完成 | Gate record / audit |
| 字段可见性 | query 输出必须经过字段策略裁剪 | 低权限调用者看到不可见字段或外部正文 | query response / field policy test |
| 数据最小化 | 不保存 secret、外部正文、memory 原文、embedding | 数据库或日志出现敏感正文 | data scan / log scan |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | 破坏身份真相、自动创建成员、identity 做认证、projection 反写真相、无 Gate tombstone、outbox 事件丢失 |
| A | 视情况 | 主线可跑但幂等、审计、dead-letter、projection rebuild、对账恢复存在局部不稳定 |
| B | 可带着走 | 非关键字段展示、低优先级查询摘要、日志格式、非阻断性 dashboard 问题 |

### 8.1 放行裁决规则

| 结论 | 条件 | 后续动作 |
|---|---|---|
| 通过 | P0 全部通过,无 S 缺陷,A 缺陷已关闭或不存在 | 进入下一阶段 |
| 有条件通过 | P0 全部通过,无 S 缺陷,少量 A/B 缺陷被正式风险接受 | 记录接受人、期限、复验条件 |
| 不通过 | 任一 P0 失败,存在 S 缺陷,或证据链无法支撑裁决 | 修复后重新送验 |

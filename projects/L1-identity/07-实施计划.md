## 2. 实施目标与范围

> 校准来源: `design-calibration/07_implementation_plan_step_02_scope.md`

本轮目标是按正式 `03/04/05/06` 契约实现 `L1-identity` 的 P0 主干,使身份锚定、生命周期、角色能力摘要、生涯记录、memory/archive refs、事实消费、追溯、维护、传播、配置、证据和验收材料均可裁决。

### 2.1 实施范围

| 范围项 | 覆盖内容 | 完成口径 |
|---|---|---|
| 核心身份真相 | 身份锚定、显式建立、稳定 ref、不复用、读取不隐式创建 | Command / Query / duplicate replay / no-create evidence 可裁决 |
| 生命周期与高风险依据 | 显式迁移、非法迁移拒绝、高风险依据缺失不 accepted | 状态矩阵、command flow 和 VETO 证据一致 |
| 角色能力摘要 | source ref、safe summary、evidence ref、source unavailable / unrecognized 处理 | 不保存外部定义正文,redaction clean |
| 生涯与 memory/archive refs | career append-only、重复来源不重复历史、memory/archive 只保存 refs/state/handoff receipt | 不保存正文、向量或 archive package |
| 消费与追溯 | 14 Query、trace/audit、projection、reference、report、outbox/handoff read surface | query no-write、not-visible、degraded/stale/missing 可测 |
| Inbound / Callback / Outbound | 5 Consumer/Callback、typed receipt replay、10 Outbound material、accepted-only payload marker | missing target 不隐式创建,body-free payload |
| Operations Job | 6 Job、stored job report replay、maintenance report-only、publish/deliver/retry | job no business truth repair |
| Config / runtime / adapter | strict config、profile、adapter mode、runtime builder、fake/controlled/disabled failure | config redline gate 可裁决 |
| Evidence / report | run-scoped artifact、run report、evidence index、handoff、veto checklist、risk acceptance | 不接受静态 pass 或 `latest` |

### 2.2 非范围与优先级

| 非范围 | 处理 |
|---|---|
| 认证主体、账号、session、credential 校验 | 不进入 P0;只消费正式 actor/context |
| 相邻业务 truth 或 external truth 修复 | 不拥有;只保存 refs、safe summary、markers、issue refs 或 report-only finding |
| 外部定义正文、memory 原文、embedding、archive package、artifact body | 不保存、不传播、不进入 report/artifact |
| 真实 DB / bus / archive / metric / external provider 产品端到端 | P1/P2 selected-run 或 residual;P0 只验 formal port + fake / controlled / disabled parity |
| UI、dashboard、advanced employee homepage、production-like capacity、runbook | P2 或后续产品化能力 |

P0 失败、VETO 命中、redaction / dependency / evidence integrity 失败、query 写 truth、job 修 truth、stored replay 重跑 mutation 均不得风险接受。

### 6.2 通用开工前设计闭环复核表

每个 commit boundary 开工前必须复核下表。失败项不得在实现侧补口。

| 复核项 | 检查内容 | 失败处理 |
|---|---|---|
| 字段闭环 | 必填字段能回指 request/event/job、repository read、resolver summary、Clock、IdGenerator、cursor 或 formal mapper | 暂停并回写 object/protocol/flow |
| DTO 构造闭环 | public request / envelope / job input 能构造目标 domain input 或明确只读取 view/report | 暂停并回写 protocol/flow |
| Query response 闭环 | query view/page/marker 有正式字段、来源、empty/not visible/degraded/stale/missing surface | 暂停并回写 query schema/flow |
| ref identity 闭环 | lookup ref、subject ref、view ref、report ref、handoff ref 有正式 type、key 和 mapper/lookup | 暂停并回写 ref schema/port |
| validation truth 闭环 | 每条校验有 truth source / resolver / repository / policy 输入 | 暂停并回写 port 或 flow |
| 状态闭环 | enum / state matrix / factory / transition helper / test cut 使用同一状态名 | 暂停并回写 object/state matrix |
| persistence / version 闭环 | save/update expected version 来自正式 versioned read 或 create result | 暂停并回写 repository/persistence |
| cursor 闭环 | truth cursor / reference marker cursor 来自 UoW / formal assigner,不来自 timestamp/version/digest | 暂停并回写 UnitOfWork/cursor source |
| idempotency / stored replay 闭环 | context/channel/key/digest、reserve、stored result/receipt/report save/get、duplicate replay 均闭合 | 暂停并回写 Step 7/8/11/13 |
| side-effect inventory 闭环 | accepted trace/audit/outbox/stale/effect/stored result 已逐项列明 | 暂停并回写 flow/outbound material |
| query no-write 闭环 | query 不开写 UoW、不 reserve idempotency、不 repair projection/reference/report/outbox/handoff | 暂停并调整 boundary 或回写 flow |
| job no-repair 闭环 | job 只写 projection/reference/report/outbox/handoff/job report,不修 business truth | 暂停并调整 boundary 或回写 job flow |
| adapter outcome 分类闭环 | resolver/publisher/handoff 返回面可判定 retryable/permanent/skipped/unsupported/unavailable | 暂停并回写 port/error mapping |
| machine artifact schema 闭环 | 机器 artifact/report 字段、required、status、digest、writer owner 和 redaction 边界来自 `05` | 暂停并回写测试方案 |
| phase boundary | 当前 boundary 不依赖后续才实现的 DTO、port、state、stored report、artifact、evidence 或 runner | 调整 boundary 或先回写设计 |

### 6.3 Commit boundary 停审规则

| 判断项 | 通过条件 | 失败处理 |
|---|---|---|
| 一句话描述 | commit boundary 目标能用一句话说明 | 拆分或改名 |
| 独立 review | reviewer 不需要阅读后续未提交代码才能判断正确性 | 拆分前置 surface |
| 独立验证 | 至少有 compile/check/unit/suite direction 能验证主要风险 | 补 Step 7 门禁或调整 boundary |
| 独立回退 | 回退该 commit 不破坏已完成前序 boundary 的概念完整性 | 拆出无关改动 |
| 不混入后续 | 不提前实现后续 phase 的 DTO、port、runner、script、evidence | 移出当前 commit |

每个 boundary 的经验复核已在 `07_implementation_plan_step_06_tasks_commit_boundaries.md` 完成。实现 agent 开工时只做二次校验;若实现仓条件、design baseline 或正式文档与复核不一致,继续暂停并回报,不得自行补口。

## 10. 回退、暂停与变更控制

> 校准来源: `design-calibration/07_implementation_plan_step_10_rollback_change_control.md`

### 10.1 动作词表

| 动作 | 含义 | 允许范围 |
|---|---|---|
| pause | 暂停当前 phase / commit boundary,不继续写实现或正式装配 | 设计缺口、门禁失败、红线命中、证据缺口 |
| rollback | 回退当前未验证 boundary 的 WIP 或重新组织本 boundary,保留已验证 boundary 和证据 | 当前 boundary 未通过或范围错误 |
| change | 修改正式真相源、实施 boundary、gate 映射或标准经验 | 必须有新 baseline 和重审 |
| resume | 在恢复条件满足后继续当前或重审后的 boundary | 需要复核记录和门禁结果 |
| residual | 非 P0 或已验收允许遗留的风险记录 | 不得证明 P0 pass |

### 10.2 暂停和回写规则

| 触发条件 | 动作 | 恢复条件 |
|---|---|---|
| `03` schema / DTO / state / flow / port / repository / persistence / error / idempotency 缺口 | pause + change | `03` 或校准文件补齐并固定 baseline;boundary 重审通过 |
| `04` config key / loader / adapter constructor / profile 语义缺口 | pause + change | `04` 补齐;commit-08-a 或相关 boundary 重审 |
| `05` suite / TC / fixture / artifact JSON / report / evidence 字段缺口 | pause + change | `05` 补齐;GATE-11 口径重审 |
| `06` AC / VETO / risk acceptance / final conclusion 缺口 | pause + change | `06` 补齐;acceptance handoff 重审 |
| phase / commit boundary 越界或引用后续 surface | pause + change | Step 6/10 重审并更新 baseline |
| P0 gate failed | pause | 修复并按 `05` 复跑最小或全量回归 |
| VETO / S 级红线命中 | pause | 修复、复跑相关 gate、VETO 不触发 |
| raw artifact / report 缺失、static pass 或使用 `latest` | pause | 修复 writer/check scripts,重跑 GATE-11/12 |
| compile dependency core 缺失或非 core sibling 进入 Cargo | pause | 修复 dependency boundary,GATE-01 通过 |
| fake / controlled adapter 使用 private map、默认成功或错误字符串分类 | pause | 补正式 port/outcome 或回写 `03`;fake/durable 等价测试通过 |
| query/job/consumer missing target 隐式创建 truth 或写 truth | pause | 修复 no-write/no-repair/no-create;复跑相关 gate |

### 10.3 Baseline 更新顺序

```text
发现变更触发
  -> pause affected boundary
  -> 写 blocker / change note
  -> 回写对应真相源
  -> 固定新的 design baseline
  -> 重审受影响 phase / commit boundary
  -> 重审 gate / evidence / risk / rollback 表
  -> 必要时更新经验标准
  -> resume with new baseline
```

回退约束:

- 不得回滚用户已有未提交改动。
- 不得删除 failed/partial artifact 来制造 clean history。
- 不得为了回退而破坏上一已验证 phase / commit boundary。
- 不得使用 destructive git 操作作为默认回退方式;需要时必须由用户明确授权。

## 11. 提交、评审与交付纪律

> 校准来源: `design-calibration/07_implementation_plan_step_11_commit_review_delivery.md`

### 11.1 提交纪律

| 项 | 要求 | 检查方式 |
|---|---|---|
| git user.name | `quantalithos-labs` | `git config user.name` |
| git user.email | `quantalithos.ai@gmail.com` | `git config user.email` |
| git config 范围 | 使用项目级配置,不得用 `--global` | `git config --show-origin user.name` |
| 提交粒度 | 一笔提交对应一个 Step 6 commit boundary | 对照 §6 |
| 暂存范围 | 只暂存当前 boundary 相关文件 | `git status --short`;`git diff --cached --name-only` |
| 用户改动保护 | 不回滚、不暂存、不改写用户已有未提交改动 | 开工前 / 提交前 status 对比 |
| 证据记录 | 对应 gate report 或说明不可执行原因 | `reports/runs/<run_id>` / `reports/review` |

### 11.2 Commit message 结构

| 部分 | design 文档仓 | 实现代码仓 |
|---|---|---|
| title | `type: 中文 subject`;`type` 英文 | `type(scope): subject`;全英文;scope 必填 |
| body summary | 中文一句话说明本 design boundary 或文档更新 | 英文一句话说明本 commit boundary |
| body groups | 中文分组;文件名 + 改动量 + 文件级说明 | 英文分组;文件名 + 改动量 + 文件级说明 |
| footer | 固定 `Co-Authored-By: Codex <noreply@openai.com>` | 默认同左;目标仓更严格规则只能叠加 |
| 语言边界 | 文档正文和伪代码说明可中文 | 源码标识符、rustdoc、普通注释、测试名默认英文 |

实现仓允许 type: `feat` / `fix` / `refactor` / `docs` / `test` / `chore` / `ci`。scope 必须从当前 boundary 所属面选择,如 `workspace`、`contracts`、`domain`、`application`、`infra`、`api`、`worker`、`jobs`、`config`、`scripts`、`reports`、`evidence`、`release`。

Commit body 文件条目规则:

| 项 | 规则 |
|---|---|
| 文件名 | 只写文件名,不写完整路径 |
| 改动量 | 使用 `(+3)`、`(-35)`、`(~38)`、`(~+330/-60)` |
| 分组 | 按 Step 6 子功能分组,不按文件类型平铺 |
| 换行 | 使用真实换行,不得写字面量 `\n` |
| 空行 | title 后空一行;footer 前空一行;bullet 之间不插空行 |

需要精确控制格式时,使用 `git commit -F <message-file>` 或 `git commit --amend -F <message-file>`。

### 11.3 提交前检查清单

| 检查项 | 通过条件 |
|---|---|
| git 配置 | `user.name` 和 `user.email` 符合项目要求 |
| 工作区状态 | 已识别用户已有未提交改动,且不暂存不相关文件 |
| diff 范围 | 当前 diff 只覆盖一个 Step 6 commit boundary |
| 门禁结果 | 对应 fmt / lint / test / acceptance 已执行并记录结果 |
| 文档同步 | 设计偏离、接口变化、验收口径变化已回写真相源 |
| 源码语言 | 实现仓源码标识符、rustdoc、普通注释和测试名未混入中文 |
| title 格式 | 实现仓固定为 `type(scope): subject`;design 仓 `type` 英文 |
| body summary | body 第一段一句话说明本 commit boundary |
| body 分组 | body 分组回指 Step 6 子功能分组 |
| footer | 固定 footer 存在且前方有真实空行 |
| 证据记录 | report/artifact 路径存在,不引用 `latest` |

设计 blocker 修复后必须显式检查是否需要总结可复用经验。标准已有覆盖则记录“无新增经验”;标准未覆盖且可复用时,更新标准 / SOP / 项目记忆种子并加入具体示例,再继续后序任务。

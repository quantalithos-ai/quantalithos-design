## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 目标组织 | 按旧对象、接口和实现能力组织 | 按身份真相闭环组织 | 对齐 Step 7 能力节点 |
| 目标数量 | 可能包含大量实现和质量目标 | 保留 `G-ID-001`~`G-ID-005` 五个需求目标 | 便于追溯和验收 |
| 非目标 | 散落在边界说明中 | 单独列出并解释不做原因 | 防止相邻仓 truth 被纳入 |
| 高风险 lifecycle | 可能直接写具体 Gate 机制 | 只要求授权 / 治理依据 | 不在需求层发明协议 |
| 角色能力 | 可能拥有完整 Role / Capability | 只收束身份侧摘要、来源和证据 | 保护 method-library 边界 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 沿用旧目标表并补校准来源 | 改动小 | 旧技术、接口和性能口径会残留 | 不采用 |
| 方案 B: 以五个身份真相目标组织需求 | 目标可追溯,能牵引能力闭环 | 后续需要重新映射旧内容 | 采用 |
| 方案 C: 只写一个“管理 AI 员工身份”的总目标 | 简洁 | 无法区分生命周期、角色能力、生涯记忆和消费追溯 | 不采用 |

## 7. 结构化中间产物

### 7.1 目标表

| 目标 | 说明 | 验证方式 |
|---|---|---|
| G-ID-001 建立平台级成员身份真相边界 | 明确 identity 管的是长期存在的 AI 员工身份,不是认证主体、项目成员或运行实例 | 后续章节不再把认证、ProjectMember 或 runtime instance 写入 identity truth |
| G-ID-002 收束成员生命周期需求范围 | 明确成员从建档、可用、暂停、退役到墓碑化的需求主题和风险边界 | 生命周期相关故事、功能、规则和验收均能稳定落在 identity |
| G-ID-003 收束角色与能力身份侧需求 | 明确 identity 只承载成员身份侧角色引用、可用性摘要和能力画像,不拥有方法定义正文或评估算法 | 角色能力相关数据归属不保存 method body 或评估模型 |
| G-ID-004 收束生涯与记忆引用需求 | 明确 identity 可保存成员生涯轨迹和 memory refs,但不拥有项目真相、记忆正文或向量 | 数据归属表能区分 career truth、外部 truth ref 和禁止正文 |
| G-ID-005 支撑身份事实消费与追溯 | 明确相邻仓可以稳定消费成员摘要、状态变化、身份引用和审计追溯 | 接口与依赖、验收标准覆盖消费边界和追溯边界 |

### 7.2 非目标表

| 非目标 | 不做原因 |
|---|---|
| 登录、token、session、credential 校验 | 属于认证入口或 gateway / API layer,不是成员身份真相。 |
| 授权裁决和高风险决策真相 | 属于 governance 或安全入口,identity 只消费授权 / 治理结论。 |
| ProjectMember 和项目内角色分配 | 属于 `L1-work`,identity 只提供 GlobalMember 身份锚点。 |
| RoleDefinition / CapabilityDefinition 正文 | 属于 `L3-method-library`,identity 只保存身份侧引用和摘要。 |
| memory 原文、向量、检索索引和 archive package | 属于 memory / archive / artifact 等外部或相邻承载方。 |
| runtime 容器、工具执行和成员进程编排 | 属于 `L2-member-service`、`L2-runtime` 和工具层。 |
| Conversation / Console / Workspace UI 展示状态 | 属于 conversation、workspace 和 L5 产品层。 |
| 数据库、框架、消息总线实现和代码目录 | 属于架构、详细设计和实施计划,不进入需求目标。 |

### 7.3 目标闭环

```text
G-ID-001 身份主语成立
  -> G-ID-002 全局可用性可判断
  -> G-ID-003 身份侧职业 / 能力可解释
  -> G-ID-004 生涯和记忆引用可沉淀
  -> G-ID-005 相邻仓可消费并追溯
```

如果只实现 `G-ID-001`,系统只是成员目录;如果缺少 `G-ID-002`,下游无法判断成员是否可用;如果缺少 `G-ID-003`,成员没有职业能力语义;如果缺少 `G-ID-004`,成员无法体现长期个体;如果缺少 `G-ID-005`,identity 会成为孤立仓。

```md
## 4. 目标与非目标

> 校准来源:
> - `design-calibration/00_req_step_04_goals_non_goals.md`

本需求文档的目标是建立平台级成员身份真相边界、收束成员生命周期范围、收束角色能力身份侧摘要、收束生涯与记忆引用,并支撑相邻仓消费与追溯。它不负责登录认证、授权裁决、ProjectMember、RoleDefinition 正文、memory / artifact / archive 正文、runtime 编排、UI 展示或具体技术实现。

这些目标形成递进闭环:先有稳定身份主语,再有全局可用性,再有职业 / 能力解释,再有长期生涯和记忆引用,最后能被相邻仓消费并被审计追溯。
```

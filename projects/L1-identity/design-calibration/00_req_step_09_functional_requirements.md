## 4. 当前文档问题诊断

| 旧表现 | 问题 | 新处理 |
|---|---|---|
| 以 `hire`、`activate`、`GetMemberSummary` 等接口式表达作为功能 | 需求层过早锁定 protocol | 改为能力需求 |
| 功能项包含 outbox、projection、repository、state enum | 内部实现进入需求 | 后移概要 / 详细设计 |
| 角色定义、项目成员和 memory 正文能力可能混入 | 边界越界 | 用非目标和失败场景排除 |
| 功能缺少失败场景 | 后续错误语义和验收难以闭合 | 每条功能列输入、结果和失败场景 |
| 功能与故事追溯不足 | 容易形成孤儿功能 | 功能表加入支撑故事 |

---

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 功能命名 | 接口 / 动词导向 | 业务能力导向 | 需求层不锁 protocol |
| 功能分组 | CRUD 或对象导向 | `C-ID-*` 能力节点导向 | 支撑能力小循环 |
| 输入输出 | 字段或 DTO 倾向 | 输入边界 / 结果边界 | 后续可转译为多个 protocol |
| 失败场景 | 不稳定或后置 | 每项功能显式列出 | 支撑规则与验收 |
| 实现细节 | outbox / projection / repo 可能提前 | 不写内部实现 | 符合需求 SOP |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 按 CRUD / Command / Query 直接列功能 | 与实现接近 | 会提前锁协议和对象,也容易漏业务失败场景 | 不采用 |
| 方案 B: 按核心能力节点列业务功能 | 可追溯到故事、规则、数据和验收 | 需要后续设计再拆 API / event / job | 采用 |
| 方案 C: 只列高级功能大项 | 简洁 | 无法支撑后续可验收和可落码拆分 | 不采用 |

## 7. 结构化中间产物

### 7.1 功能需求表

| 功能编号 | 核心能力节点 | 功能需求 | 输入边界 | 结果边界 | 失败场景 | 支撑故事 |
|---|---|---|---|---|---|---|
| FR-ID-001 | C-ID-1 | 平台必须能建立新的 AI 员工身份主语。 | 管理意图、成员基本身份信息、操作者上下文 | 产生可长期引用的成员身份 | 身份信息无效、操作者无权、来源不可信 | US-ID-001 |
| FR-ID-002 | C-ID-1 | 平台必须能按身份引用读取成员摘要。 | 成员身份引用、读取场景 | 返回身份摘要或不可见 / 不存在结果 | 引用不存在、不可见、读取范围不合法 | US-ID-002, US-ID-003 |
| FR-ID-003 | C-ID-1 | 平台必须保证成员身份引用稳定且不复用。 | 成员创建、归档和墓碑化场景 | 同一身份在生命周期内稳定可追溯 | 试图复用或重写 identity anchor | US-ID-001, US-ID-014 |
| FR-ID-004 | C-ID-2 | 平台必须能表达成员全局生命周期和可用性。 | 生命周期调整意图、操作者上下文、原因 | 成员进入新的全局可用性状态 | 非法状态变化、缺少原因、缺少授权 / 治理约束 | US-ID-004, US-ID-005 |
| FR-ID-005 | C-ID-2 | 平台必须能对高风险生命周期处置保留依据。 | 高风险处置请求、治理 / 授权结论引用 | 高风险处置可追溯 | 缺少有效依据、依据不匹配、处置越界 | US-ID-006 |
| FR-ID-006 | C-ID-3 | 平台必须能维护成员身份侧角色摘要。 | 成员引用、角色来源引用、变更原因 | 成员身份关联到可解释职业语义 | 角色来源不可用、角色已失效、来源正文被错误写入 | US-ID-007, US-ID-008 |
| FR-ID-007 | C-ID-3 | 平台必须能维护成员能力画像摘要。 | 成员引用、能力变化、证据或来源引用 | 成员能力摘要可查询和追溯 | 缺少证据、能力来源不明、试图写入评估算法结果正文 | US-ID-007, US-ID-009 |
| FR-ID-008 | C-ID-3 | 平台必须能响应角色 / 能力定义来源变化。 | 定义来源变化、成员或角色引用 | 身份侧摘要进入更新、失效或待对账状态 | 来源不可识别、变更无法映射、重复处理 | US-ID-008, US-ID-009 |
| FR-ID-009 | C-ID-4 | 平台必须能追加成员生涯记录。 | 正式项目参与事实或授权追加来源 | 成员生涯追加可追溯记录 | 来源不可信、试图改写历史、项目事实不匹配 | US-ID-010 |
| FR-ID-010 | C-ID-4 | 平台必须能保存成员相关 memory refs。 | 成员引用、memory ref 来源、更新原因 | 成员身份关联到外部 memory refs | ref 无效、试图保存 memory 正文 / 向量、来源不可信 | US-ID-011, US-ID-012 |
| FR-ID-011 | C-ID-4 | 平台必须能支持记忆引用迁移或冷存协作。 | 退役 / 墓碑化场景、归档或迁移引用 | 记录迁移后的引用状态或待处理状态 | 迁移结果缺失、外部正文泄漏、归档边界不清 | US-ID-011, US-ID-012 |
| FR-ID-012 | C-ID-5 | 平台必须能向相邻仓提供身份事实消费边界。 | 相邻仓读取或订阅需求 | 提供成员锚点、状态摘要和变更提示 | 消费方越权、字段越界、版本不兼容 | US-ID-013 |
| FR-ID-013 | C-ID-5 | 平台必须能提供身份变化追溯。 | 成员引用、追溯读取场景 | 返回身份变化、角色能力变化、生涯和引用变化摘要 | 追溯记录缺失、不可见、正文泄漏 | US-ID-014 |
| FR-ID-014 | C-ID-5 | 平台必须能对身份投影和外部引用做维护对账。 | 维护任务、时间范围或引用范围 | 输出漂移、缺失或待修复摘要 | 任务越界、试图修复相邻仓 truth、重复维护 | US-ID-015 |

### 7.2 功能分组说明

| 功能组 | 功能范围 | 后续设计必须保留的需求约束 |
|---|---|---|
| 身份锚定 | FR-ID-001~003 | 创建和读取必须分离;读取不得隐式写入;身份引用不得复用 |
| 生命周期 | FR-ID-004~005 | 生命周期变化必须显式、有原因、有操作者上下文;高风险处置必须有依据 |
| 角色能力 | FR-ID-006~008 | 只维护身份侧摘要、来源和证据引用;来源变化不能静默污染摘要 |
| 生涯记忆 | FR-ID-009~011 | 生涯只能追加;memory / archive 只保存引用和状态,不保存正文 |
| 消费追溯 | FR-ID-012~014 | 相邻仓只能消费身份事实;追溯和对账不能反向修复相邻仓 truth |

### 7.3 功能停审

| 检查项 | 结论 |
|---|---|
| 每项功能是否回指能力节点 | 通过 |
| 每项功能是否回指用户故事 | 通过 |
| 是否按 CRUD / API / Command 拆分 | 否 |
| 是否提前写实现组件或 DTO | 否 |
| 是否存在故事无功能承接 | 否 |
| 是否存在功能无失败场景 | 否 |

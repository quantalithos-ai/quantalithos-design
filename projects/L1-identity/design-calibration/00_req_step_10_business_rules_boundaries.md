## 3. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 哪些不变量必须成立 | 成员身份引用稳定不复用、ProjectMember 不归 identity、外部正文不入 identity、历史追加不可改写。 |
| 哪些行为必须禁止 | 查询隐式建档、保存 RoleDefinition / memory 正文、从 runtime instance 反推 identity truth、维护任务修复相邻仓 truth。 |
| 哪些状态变化必须显式发生 | 生命周期变化、角色能力摘要变化、生涯追加、memory ref 更新和追溯记录形成都必须显式可追溯。 |
| 哪些边界不能打穿 | identity 与 work、method-library、governance、runtime、memory/archive、UI/observability 的 truth 边界。 |
| 规则是否写实现机制 | 否。规则只写需求约束,不写 domain method、repository version、event payload、数据库唯一键或错误码。 |

## 4. 当前文档问题诊断

| 旧表现 | 问题 | 新处理 |
|---|---|---|
| 不变量包含对象字段、状态机细节和 event payload | 过早进入详细设计 | 保留需求层规则,字段后移 |
| 规则与功能映射不清 | 后续无法验收 | 每条规则映射 `FR-ID-*` |
| 禁止正文规则分散 | 容易在事件、报告或诊断中泄漏正文 | 集中为边界和禁止行为 |
| 高风险生命周期规则不清 | 可能由后台任务静默执行 | 规定需授权 / 治理依据 |
| 对账维护规则不清 | 可能反修相邻仓 truth | 规定 report-only / 不绕过正式能力 |

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 规则层级 | 字段、状态机、event 和需求规则混写 | 只写需求不变量、禁止行为和边界约束 | 保持需求层抽象 |
| 身份引用 | 旧材料中稳定性存在但散落 | `BR-ID-001` 明确不复用 | 支撑 veto |
| 查询路径 | 可能隐式 create | `BR-ID-002` 明确查询不写入 | 防止读写混层 |
| 外部正文 | 分散在 memory / role / artifact | `BR-ID-007` / `BR-ID-012` 明确禁止 | 防泄漏 |
| 维护对账 | 未明确权限上限 | `BR-ID-015` 明确不得修复相邻仓 truth | 防止 ops 越界 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 把旧状态机和字段约束直接列为规则 | 详细 | 会提前锁定实现,且可能与后续设计冲突 | 不采用 |
| 方案 B: 只保留需求层不变量、禁止行为和边界约束 | 抽象稳定,可被后续详细设计承接 | 后续还需扩展状态矩阵和错误语义 | 采用 |
| 方案 C: 只写边界原则,不列编号规则 | 简洁 | 无法形成追溯矩阵和验收来源 | 不采用 |

### 7.2 规则解释与反例

| 规则组 | 正确口径 | 反例 |
|---|---|---|
| 身份锚定规则 | 成员身份建立后可改名、暂停或墓碑化,但身份引用不复用 | 删除旧成员后把同一个 ref 分配给新成员 |
| 读取 / 写入边界 | 查询只返回可见摘要或失败结果,不产生 truth | 下游读取未知成员时自动创建 GlobalMember |
| 生命周期规则 | 生命周期变化来自显式意图、原因和可信操作者上下文 | 后台定时任务静默退役成员且没有依据 |
| 角色能力规则 | 成员能力摘要必须有来源或证据引用 | 管理员直接填写“高级能力等级”且没有任何来源 |
| 生涯记忆规则 | 历史追加、正文外部归属、引用可追溯 | 直接修改旧项目经历或把 memory 原文写入 identity |
| 消费追溯规则 | 下游消费身份事实,维护任务报告漂移 | 对账任务直接修改 work、method-library 或 archive truth |

### 7.3 跨能力规则审计

| 检查项 | 结论 |
|---|---|
| 规则是否全部回指能力节点和功能需求 | 通过 |
| 是否存在字段 / 表结构 / DTO 级规则 | 无 |
| 是否存在相邻仓 truth 被收进 identity | 无 |
| 是否存在规则冲突 | 未发现 |
| 是否覆盖外部正文禁止保存 | 已覆盖 BR-ID-007 / BR-ID-012 |

## 10. 业务规则与边界约束

> 校准来源:
> - `design-calibration/00_req_step_10_business_rules_boundaries.md`

业务规则用于保护功能需求不越界。它们不是实现校验代码,也不是字段约束清单,而是后续设计必须保留的需求不变量和禁止行为。成员身份引用不得复用,查询不得隐式建档,生命周期变化必须显式可追溯,角色能力摘要必须有来源或证据,生涯记录只能追加,memory / artifact / archive 正文不得进入 identity,消费方和维护任务不得反向写 identity truth 或相邻仓 truth。

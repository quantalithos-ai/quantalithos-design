## 3. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 哪些非功能要求能回指能力节点 | 身份唯一性、生命周期一致性、来源追溯、append-only、生效消费和投影对账可回指能力节点。 |
| 哪些覆盖全仓 | 安全、审计、幂等、一致性、可观测和正文排除覆盖全仓。 |
| 是否继承旧 P95 / 容量数字 | 不直接继承;作为后续性能基线候选,当前给判断口径。 |
| 哪些要求可量化 | 重复写入幂等、非法越界 0 容忍、正文泄漏 0 容忍可量化;性能后移测试方案 / 验收标准基线评审。 |
| 哪些底线不能降级 | 身份 ref 不复用、查询不写入、外部正文不保存、高风险变化有依据、对账不反修相邻 truth。 |

## 4. 当前文档问题诊断

| 旧表现 | 问题 | 新处理 |
|---|---|---|
| 固定旧 P95、容量和技术栈指标 | 未经新版架构和测试评审 | 不直接继承,后移基线 |
| 安全要求散落在字段和接口中 | 难以形成 veto | 集中为写入可信上下文和正文泄漏 0 容忍 |
| 幂等 / 一致性只在实现中出现 | 需求追溯不足 | 明确重复来源不得产生重复身份或历史 |
| 可观测性可能包含外部正文 | 有泄漏风险 | 诊断信息必须安全裁剪 |
| 可用性与外围依赖耦合 | 外部不可用可能拖垮基础身份读取 | 核心身份锚点和生命周期读取具备降级口径 |

---

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 性能 | 旧数字倾向直接继承 | 只保留可设基线要求 | 避免伪验收 |
| 可用性 | 未区分核心和外围依赖 | C-ID-1 / C-ID-2 基础能力不因外围失败整体失效 | 支撑降级 |
| 安全 | 与实现鉴权混写 | 可信上下文和正文泄漏 0 容忍 | 需求层可验收 |
| 审计 | 可能依赖 observability store | identity 自身变化必须可追溯 | 不拥有外部审计正文 |
| 幂等 | 实现细节 | 重复来源不产生重复 truth | 支撑事件 / job 后续设计 |

---

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 直接继承旧 P95 / 容量 | 看起来可验收 | 未经新版设计和测试复核,易变成虚假门禁 | 不采用 |
| 方案 B: 需求层写质量类别和判断口径,硬阈值后移 | 稳定且诚实 | 后续 `05/06` 必须补基线 | 采用 |
| 方案 C: 非功能全部后移 | 需求文档简洁 | 安全、正文排除和追溯底线会缺失 | 不采用 |

## 7. 结构化中间产物

### 7.1 非功能需求表

| 编号 | 类别 | 范围 | 非功能要求 | 判断口径 / 目标值 | 映射 |
|---|---|---|---|---|---|
| NFR-ID-001 | 性能 | 全仓 | 身份摘要读取和管理写入必须具备可设基线的响应时间。 | 当前不继承旧固定阈值;后续测试方案必须给出 P0 基线或 sample 口径。 | IF-ID-001, IF-ID-002 |
| NFR-ID-002 | 可用性 | C-ID-1/C-ID-2 | 核心身份锚点读取和生命周期读取不可因外围依赖不可用而整体失效。 | method-library、archive、observability 不可用时,基础身份摘要仍应可按降级口径返回。 | FR-ID-002, FR-ID-004 |
| NFR-ID-003 | 安全 | 全仓 | 写入身份 truth 的能力必须受可信操作者上下文和授权边界约束。 | 无可信上下文或越权写入必须拒绝;不得由 query 或维护任务绕过。 | BR-ID-002, BR-ID-005 |
| NFR-ID-004 | 安全 | 全仓 | 禁止保存外部正文、credential、token、raw secret。 | 正文泄漏、secret 泄漏为 0 容忍。 | BR-ID-007, BR-ID-012 |
| NFR-ID-005 | 审计 / 可追溯 | 全仓 | 身份变化、生命周期变化、角色能力变化、生涯追加和 memory ref 更新必须可追溯。 | 每类变化都能追到安全可见原因、来源或操作者摘要。 | BR-ID-014 |
| NFR-ID-006 | 幂等 / 一致性 | C-ID-1/C-ID-5 | 重复处理创建、来源变化、项目事实或维护任务不得产生重复身份或重复历史。 | 重放同一业务来源不会新增重复 truth;冲突必须显式暴露。 | FR-ID-001, FR-ID-008, FR-ID-009, FR-ID-014 |
| NFR-ID-007 | 幂等 / 一致性 | C-ID-4 | 生涯记录和追溯记录必须保持追加语义。 | 已确认历史不得被原地改写;纠错必须以追加形式表达。 | BR-ID-010 |
| NFR-ID-008 | 可观测性 | 全仓 | 身份能力必须暴露足够的安全诊断信息,用于排查引用、消费和投影漂移。 | 诊断不得包含外部正文或 secret;必须能定位失效能力和安全 issue ref。 | FR-ID-014 |
| NFR-ID-009 | 可观测性 | C-ID-5 | 消费与对账能力必须能产出可审计的漂移摘要。 | 对账报告只描述 identity 自身投影 / 引用问题,不得修复相邻仓 truth。 | BR-ID-015 |

### 7.2 非功能停审

| 检查项 | 结论 |
|---|---|
| 是否覆盖性能、可用性、安全、审计、幂等、一致性、可观测性 | 通过 |
| 是否把实现方案写成非功能要求 | 未写 |
| 是否继承未评审旧性能硬指标 | 未继承 |
| 是否每项都有能力节点或全仓来源 | 通过 |
| 是否能被 Step 14 验收承接 | 通过 |

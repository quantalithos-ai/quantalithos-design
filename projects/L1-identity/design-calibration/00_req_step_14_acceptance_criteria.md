## 3. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 核心能力闭环怎么算成立 | `C-ID-1`~`C-ID-5` 均有故事、功能、规则、数据、接口和验收承接。 |
| 功能能力怎么算完成 | `FR-ID-001`~`FR-ID-014` 的能力边界可被测试或评审验证。 |
| 规则边界怎么算满足 | 不发生认证、ProjectMember、RoleDefinition、memory body、runtime truth 等串仓。 |
| 数据边界怎么算正确 | 真相 / 快照 / 引用 / 禁止正文四类边界均可验证。 |
| 哪些失败是一票否决 | 身份引用复用、查询隐式创建、保存外部正文、ProjectMember 反写、无授权高风险处置、L1 循环依赖。 |
| 是否写测试步骤或 suite | 否。测试方案和正式验收 gate 后移 `05/06`。 |

## 4. 当前文档问题诊断

| 旧表现 | 问题 | 新处理 |
|---|---|---|
| 验收混入 benchmark、E2E、具体事件和测试步骤 | 需求验收与测试方案混层 | 只写验收条件和 veto |
| 性能旧数字可能直接变 pass 线 | 基线未评审 | 要求后续 `05/06` 给出基线或 sample 口径 |
| 规则边界没有形成 veto | 严重串仓也可能被条件通过 | 明确一票否决项 |
| 数据归属验收不足 | 正文泄漏和外部 truth 入仓风险 | 增加数据归属和正文泄漏验收 |
| 维护对账越界未验收 | ops 能力可能修改相邻仓 | 增加 VETO-ID-005 |

---

## 5. 改动前后对比

| 项 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 验收粒度 | 具体测试 / benchmark 倾向 | 需求层 AC / VETO | 后续测试再细化 |
| 核心能力 | 未必逐节点验收 | `AC-ID-001`~`005` 覆盖 C-ID-1~5 | 保证闭环完整 |
| 规则边界 | 可能只作为说明 | 明确 AC 和 VETO | 可阻断串仓 |
| 性能 | 旧硬指标 | 后续基线或 sample 口径 | 防止虚假 pass |
| 依赖裁剪 | 不一定验收 | VETO-ID-006 | 防止 L1 循环和 truth 混层 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 需求阶段直接写测试用例和 suite | 可执行感强 | 会与 `05-测试方案.md` 重复且易锁错误 evidence | 不采用 |
| 方案 B: 写 AC / VETO,测试和 evidence 后移 | 层级清楚,便于后续测试承接 | 需要后续 `05/06` 细化 | 采用 |
| 方案 C: 只写能力完成,不写 veto | 简洁 | 严重边界错误无法阻断 | 不采用 |

## 7. 结构化中间产物

### 7.1 验收标准表

| 验收编号 | 类别 | 能力节点 | 验收条件 | 映射 |
|---|---|---|---|---|
| AC-ID-001 | 核心能力闭环 | C-ID-1 | 能够证明平台存在稳定成员身份锚点,且引用不因生命周期变化而复用。 | FR-ID-001~003, BR-ID-001 |
| AC-ID-002 | 核心能力闭环 | C-ID-2 | 能够证明成员全局生命周期可被显式管理、读取和追溯。 | FR-ID-004~005, BR-ID-004~006 |
| AC-ID-003 | 核心能力闭环 | C-ID-3 | 能够证明成员角色能力摘要有来源或证据引用,且不保存定义正文。 | FR-ID-006~008, BR-ID-007~009 |
| AC-ID-004 | 核心能力闭环 | C-ID-4 | 能够证明成员生涯记录追加可追溯,memory refs 可维护且不保存正文。 | FR-ID-009~011, BR-ID-010~012 |
| AC-ID-005 | 核心能力闭环 | C-ID-5 | 能够证明相邻仓可消费身份事实,身份变化可追溯,维护对账不修复相邻仓 truth。 | FR-ID-012~014, BR-ID-013~015 |
| AC-ID-006 | 功能能力 | C-ID-1 | 创建和读取成员身份摘要的能力边界清楚区分,读取不存在身份不会产生写入。 | FR-ID-001~002, BR-ID-002 |
| AC-ID-007 | 功能能力 | C-ID-2 | 非法生命周期变化被拒绝,高风险处置缺少依据时不被接受。 | FR-ID-004~005 |
| AC-ID-008 | 功能能力 | C-ID-3 | 来源失效或无法识别的角色能力变化不会静默污染成员摘要。 | FR-ID-006~008 |
| AC-ID-009 | 功能能力 | C-ID-4 | 项目参与来源可以追加生涯记录,重复来源不会生成重复历史。 | FR-ID-009, NFR-ID-006 |
| AC-ID-010 | 功能能力 | C-ID-4 | memory ref 更新和迁移只记录引用状态,不保存原文或向量。 | FR-ID-010~011 |
| AC-ID-011 | 规则边界 | 全仓 | 认证 / 授权 / gateway 不被写成 identity truth。 | BR-ID-003 |
| AC-ID-012 | 规则边界 | 全仓 | ProjectMember、runtime instance、RoleDefinition、memory body、artifact body 不进入 identity truth。 | BR-ID-006~012 |
| AC-ID-013 | 数据归属 | 全仓 | 正式数据归属表能区分真相、快照、引用和禁止正文,且每项有功能或规则来源。 | Step 11 |
| AC-ID-014 | 非功能验收 | 全仓 | 正文泄漏、secret 泄漏、查询隐式写入和身份引用复用均为 0 容忍。 | NFR-ID-003~004 |
| AC-ID-015 | 非功能验收 | 全仓 | 性能、可用性和可观测性在测试方案中有明确基线、sample 或评审口径,不得用旧数字直接宣告通过。 | NFR-ID-001~002, NFR-ID-008~009 |

### 7.2 一票否决项

| 否决编号 | 一票否决情形 | 来源 |
|---|---|---|
| VETO-ID-001 | 成员身份引用被复用给另一个成员。 | BR-ID-001 |
| VETO-ID-002 | 查询或消费路径隐式创建成员身份。 | BR-ID-002 |
| VETO-ID-003 | Identity 保存 RoleDefinition、ProjectMember、memory、artifact、conversation 或 runtime 正文。 | BR-ID-007, BR-ID-011, BR-ID-012 |

## 4. 当前材料 / 旧文档问题诊断

| 诊断项 | 当前风险 | 处理方式 |

| 旧 `01` 已经有完整正式正文 | 容易让后续继续沿用旧结论,掩盖它未按最新版 Step 内计划形成 | 正式 `01` 已替换为重建占位;不再从旧正文增量修补 |

## 5. 改动前后对比

| 维度 | 旧处理 | 新处理 | 原因 |
|---|---|---|---|
| 架构真相源 | 旧 `01` 正文和旧校准文件可被继续引用 | 旧 `01` 清空,新版 `00` 是唯一需求基线 | 防止历史结论污染 |
| 中间产物结构 | 部分 Step 直接给结论 | 每个 Step 必须保留计划、问题回答、诊断、取舍、结构化、回填和自检 | 对齐最新版 SOP |
| 架构组织轴 | 容易按组件 / 技术 / 旧对象组织 | 按需求能力节点和架构单元逐步收敛 | 保证需求到架构可追溯 |
| 依赖关系 | 可能把运行期或事件协作写成源码依赖 | 只允许 `L0-core` 作为编译期候选,其他走正式边界 | 避免 L1 循环依赖 |
| 未闭口事项 | 可能散落在正文中 | 统一挂到风险 / 待确认事项 | 避免实现阶段脑补 |

## 7. 结构化中间产物

### 7.1 架构需求基线

| 基线项 | 来源 | 架构承接方式 |
|---|---|---|
| 平台级 AI 员工身份真相仓 | `G-ID-001`, `C-ID-1`, `FR-ID-001`~`FR-ID-003` | 转译为核心子域、数据所有权和依赖边界 |
| 全局生命周期可用性 | `C-ID-2`, `FR-ID-004`~`FR-ID-005` | 转译为生命周期上下文、治理依据引用和高风险处置红线 |
| 身份侧角色能力摘要 | `C-ID-3`, `FR-ID-006`~`FR-ID-008` | 转译为来源引用、摘要边界和 method-library 运行期 / 事件协作 |
| 生涯与记忆引用 | `C-ID-4`, `FR-ID-009`~`FR-ID-011` | 转译为 append-only 生涯语义、ProjectMember ref 和 memory / archive ref-only 边界 |
| 消费与追溯 | `C-ID-5`, `FR-ID-012`~`FR-ID-014` | 转译为消费边界、追溯读取、投影 / 引用对账和 report-only 维护 |

### 7.2 架构硬约束

| 约束 | 需求来源 | 架构影响 |
|---|---|---|
| 成员身份引用不得复用 | `BR-ID-001`, `VETO-ID-001` | 身份主语必须是唯一核心 truth |
| 查询不得隐式创建身份 | `BR-ID-002`, `VETO-ID-002` | 读写路径和运行单元必须分离语义 |
| 认证、credential、token 不归 identity | `BR-ID-003`, `NFR-ID-004` | 不设计 auth / gateway 架构 |
| ProjectMember / Project truth 不归 identity | `BR-ID-006`, `BR-ID-011`, `VETO-ID-003` | work 只能作为外部来源或消费方 |
| RoleDefinition / CapabilityDefinition 正文不归 identity | `BR-ID-007`, `VETO-ID-003` | method-library 只能通过来源引用进入 |
| memory / artifact / conversation / runtime 正文不归 identity | `BR-ID-012`, `VETO-ID-003` | 外部正文只能 ref-only 或 handoff |
| 对账不得修复相邻仓 truth | `BR-ID-015`, `VETO-ID-005` | 维护任务只能报告、重建本仓派生状态或挂起 |
| 除 `L0-core` 外不得形成业务仓编译期依赖 | `VETO-ID-006` | 跨仓能力必须 runtime/event/handoff/ref |

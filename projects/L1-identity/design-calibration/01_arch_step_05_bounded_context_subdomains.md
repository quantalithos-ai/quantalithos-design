## 4. 当前材料 / 旧文档问题诊断

| 诊断项 | 旧处理风险 | 本步处理 |
|---|---|---|
| 把需求能力节点直接等同子域 | `C-ID-1`~`C-ID-5` 都可能被写成同等核心子域 | 本步只把 C-ID-1 的身份真相定为核心子域,其余能力按支撑或影子结构归类 |
| 把对象名清单写成上下文划分 | GlobalMember、RoleCatalogEntry、MemoryRef 等名词被直接列为子域 | 本步按语义责任划分,不写字段级对象或结构体清单 |
| 把代码模块写成子域 | service、repo、projection、worker 被当成限界上下文 | 本步禁止实现层结构,这些留给容器 / 详细设计 |
| 把外部来源索引写成核心子域 | role source、ProjectMember ref、memory ref 被误认为 identity truth 本体 | 本步将它们归为本地索引 / 投影 / 引用 |
| 把消费投影当成主 truth | 为下游读取便利维护的摘要可能反向支配核心 identity | 本步明确消费投影只依附核心 truth,可重建、可失效、可对账 |
| 把对账报告写成修复子域 | 维护任务可能被设计成跨仓修复中心 | 本步把对账归为支撑消费追溯的报告结构,不得修改相邻仓 truth |
| 把事件协作边界写成内部核心语义 | L0-bus / event handling 可能成为业务子域 | 本步仅保留事件协作影子结构,用于传播与重建,不承载业务真相本体 |

## 5. 改动前后对比

| 维度 | 旧处理风险 | 新处理 |
|---|---|---|
| 核心子域 | 多个能力并列为核心,核心 truth 不聚焦 | 唯一核心为平台级成员身份真相 |
| 生命周期 | 与 runtime / work 状态混成同一个状态上下文 | 作为支撑子域,只表达全局身份可用性 |
| 角色能力 | 与 method-library 定义正文混成一个上下文 | 作为支撑子域,只承载身份侧摘要和来源引用 |
| 生涯记忆 | 与项目 truth、memory body 混层 | 作为支撑子域,只追加身份侧经历和 refs |
| 消费追溯 | 与 outbox、projection、observability 实现混写 | 作为支撑子域,承接可见消费、追溯和对账语义 |
| 外部引用 | 可能被当成 truth | 明确为本地索引 / 投影 / 引用 |

## 6. 设计取舍

| 方案 / 取舍点 | 采用与否 | 理由 |
|---|---|---|
| 五个核心能力节点全部转成核心子域 | 不采用 | 需求能力是闭环路径,架构核心子域必须聚焦 identity truth 本体。 |
| 单核心 + 多支撑子域 | 采用 | 能保持平台级成员身份真相唯一,同时承接生命周期、角色能力、生涯记忆和消费追溯。 |
| 把外部来源引用作为支撑子域 | 不采用 | 它们只是消费外部上下文的本地影子,不拥有独立业务语义。 |
| 把投影 / 对账作为核心子域 | 不采用 | 投影和对账依赖核心 truth,可重建或 report-only,不应成为核心真相。 |
| 把事件协作作为内部子域 | 不采用 | 事件协作是传播与同步边界,不是 identity 业务语义本体。 |
| 在 Step 5 细化对象字段和状态机 | 不采用 | 字段、状态机和协议属于后续概要 / 详细设计,本步只划分语义结构。 |

## 7. 结构化中间产物

### 7.1 子域 / 上下文划分表

| 名称 | 类型 | 作用 | 与其他部分的关系 |
|---|---|---|---|
| 平台级成员身份真相 | 核心子域 | 承载 AI 员工平台级身份主语和不可复用身份锚点。 | 是 identity 的中心上下文,其他部分都围绕它建立语义关系。 |
| 成员生命周期边界 | 支撑子域 | 承载成员全局可用性和高风险处置依据的身份侧语义。 | 依附于平台级成员身份真相,不替代项目状态或 runtime 状态。 |
| 角色能力摘要 | 支撑子域 | 承载成员身份侧职业、角色和能力摘要的可解释语义。 | 依附于成员身份真相,只消费 method-library 来源,不拥有定义正文。 |
| 身份生涯与记忆引用 | 支撑子域 | 承载成员长期身份经历和外部记忆引用的延续语义。 | 依附于成员身份真相,只保存项目 / memory / archive refs 和身份侧追加历史。 |
| 身份事实消费与追溯 | 支撑子域 | 承载下游稳定消费、变化追溯和对账报告的边界语义。 | 消费核心 truth 和支撑子域变化,不允许下游反写核心 truth。 |
| 外部来源引用 | 本地索引 / 投影 / 引用 | 为稳定消费 method、work、governance、memory / archive 来源提供本地引用影子。 | 只保存 ref、来源摘要或状态 marker,不拥有外部上下文 truth。 |
| 消费投影与对账 | 本地索引 / 投影 / 引用 | 为下游读取、投影失效和漂移发现提供可重建影子结构。 | 依附于身份事实消费与追溯,不得替代核心 truth 或修复相邻仓 truth。 |
| 事件协作影子 | 本地索引 / 投影 / 引用 | 为身份变化事实传播、重放和订阅协作保留边界语义。 | 依附于消费追溯,不把 `L0-bus` 或 event transport 写成本仓核心子域。 |

| 审计项 | 结论 | 处理 |
|---|---|---|
| 核心子域是否唯一 | 是 | 只有平台级成员身份真相为核心子域 |
| 生命周期是否误作 runtime 状态 | 否 | 已归为身份侧全局生命周期支撑子域 |

| memory refs 是否误作正文 ownership | 否 | memory / archive 只进入引用和状态 marker |

| 待确认事项是否被润色为定论 | 否 | method 来源协议、governance action、memory handoff、visibility 字段和性能阈值仍后移 |

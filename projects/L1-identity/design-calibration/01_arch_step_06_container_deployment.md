## 4. 当前材料 / 旧文档问题诊断

| 诊断项 | 旧处理风险 | 本步处理 |
|---|---|---|
| 把容器图写成代码分层图 | handler -> service -> domain -> repository 这类实现结构可能进入架构图 | 本步只使用同步入口、后台承接、维护承接、存储承载和基础设施依赖等运行角色 |
| 把容器图写成协议时序图 | command、event、query、topic 或 API path 被画入图中 | 本步只写入口 / 处理 / 消费 / 承载 / 依赖关系,不写协议名 |
| 把容器图写成基础设施部署手册 | 数据库主从、消息集群、K8s workload、资源参数被提前确定 | 本步只保留正式存储承载和基础设施依赖角色,产品选型后移 |
| 把子域图重画成容器图 | 平台级成员身份真相、生命周期等语义子域被误当运行单元 | 本步运行单元承接语义,但不以子域名作为容器节点 |
| 维护任务绕过写入边界 | 对账或重建单元可能被赋予跨仓修复或直接写核心 truth 的能力 | 本步把维护 / 对账限定为 report-only 或本仓派生状态维护,不得修复相邻仓 truth |
| 外部正文承载合并进 identity 存储 | memory / archive / artifact body 可能随部署便利被放入 identity storage | 本步明确外部正文承载不属于 identity 正式存储承载 |
| 运行单元与部署实例绑定过早 | 当前阶段若写死单进程 / 多进程 / 独立服务,后续实施边界会僵化 | 本步只定义逻辑运行承载角色,允许后续按阶段同部署或分部署 |

## 5. 改动前后对比

| 维度 | 旧处理风险 | 新处理 |
|---|---|---|
| 运行单元命名 | 使用 handler/service/repo/worker/crate 等实现名 | 使用同步入口、异步 / 后台承接、维护 / 对账承接等运行角色 |
| 存储表达 | 直接选择数据库或表结构 | 只表达 identity 正式存储承载和 trace / audit / outbox 承载 |
| 总线表达 | 直接选择消息产品或 topic | 只表达正式基础设施依赖和事件协作边界 |
| 部署边界 | 过早要求单独进程或具体 deployment | 只要求逻辑职责隔离,同部署 / 分部署后移实施计划 |
| 维护任务 | 被写成万能修复器 | 限定为本仓派生状态维护、对账发现和 report-only |
| 外部对接 | 重写 Step 4 的系统上下文 | 只把已确认上下文作为运行时外部对接边界出现 |

## 6. 设计取舍

| 方案 / 取舍点 | 采用与否 | 理由 |
|---|---|---|
| 按代码层画运行结构 | 不采用 | 架构层容器图不是实现模块图,代码组织留给后续概要 / 详细设计。 |
| 按同步入口、异步承接、维护承接划分运行角色 | 采用 | 能对应需求中的同步写入 / 查询、事件协作和后台维护能力,同时不绑定实现。 |
| 单独画 query 和 command 两个入口单元 | 不采用 | 当前架构层只需要同步入口角色;读写分离语义后续可在详细设计和部署计划中细化。 |
| 单独画 projection worker、outbox publisher、reconciliation runner 等细单元 | 不采用 | 这些属于后续关键交互、详细设计或实施计划;本步收敛为维护 / 对账承接和异步 / 后台承接。 |
| 直接确定数据库 / 消息 / 缓存产品 | 不采用 | 技术产品选择属于后续技术选型和实施计划,当前只定义承载角色。 |
| 允许初期同部署但保持逻辑隔离 | 采用 | 可降低早期部署复杂度,同时保留后续拆分空间。 |
| 外部正文承载与 identity 存储同仓部署 | 不采用 | 会打穿正文排除边界,违反 `BR-ID-012` / `VETO-ID-003`。 |

### 7.2 运行单元说明表

| 对象 | 类型 | 主要职责 | 运行关系 | 说明 |
|---|---|---|---|---|
| 外部入口 / 来源边界 | 运行时对接的正式外部边界 | 承接受控管理入口、来源变化和外部协作触发。 | 作为入口或异步输入进入本仓运行承载。 | 它只代表 Step 4 已确认的外部对接边界,不定义具体入口协议。 |
| 同步入口单元 | 同步入口单元 | 承接成员建档、读取、生命周期管理、角色能力维护、memory ref 管理和追溯读取等同步入口流量。 | 通过处理关系进入本仓正式运行承接链,并依赖正式存储承载。 | 它是运行入口角色,不是 handler、API route 或具体进程。 |
| 异步 / 后台承接单元 | 异步消费单元 / 后台处理单元 | 承接来源变化、项目参与、生涯追加、memory / archive 状态和身份变化传播等异步或后台推进。 | 消费外部来源边界,处理后依赖正式存储和基础设施承载。 | 它不拥有外部 truth,只处理 identity 可接受的 ref / 状态 / marker。 |
| 维护 / 对账承接单元 | 后台处理单元 | 承接投影重建、引用对账、漂移发现和 report-only 维护。 | 消费本仓 truth、投影和引用状态,输出对账或维护结果。 | 它不得绕过正式能力修改相邻仓 truth。 |
| identity 正式存储承载 | 正式存储承载 | 承载平台级成员身份真相、身份侧状态、摘要、引用和本仓派生状态。 | 被同步入口、异步 / 后台承接、维护 / 对账承接共同依赖。 | 它不承载 RoleDefinition、ProjectMember、memory body、runtime body 或 credential。 |
| trace / audit / outbox 承载 | 正式存储承载 | 承载身份变化追溯、审计、安全可见原因和跨仓变化传播准备。 | 被运行单元写入和读取,并依赖正式基础设施边界进行传播或观测。 | 它保存 refs、摘要和安全 marker,不保存外部正文。 |
| 正式基础设施依赖 | 正式基础设施依赖 | 支撑事件协作、外部来源接入、观测承接和运行诊断。 | 为 trace / audit / outbox 和异步承接提供运行基础。 | 本步不选择具体产品、topic、队列、缓存或部署拓扑。 |
| 下游消费 / 运维边界 | 运行时对接的正式外部边界 | 承接身份事实消费、追溯读取和对账报告消费。 | 从本仓运行承载获得输出或 report-only 结果。 | 它不拥有 identity truth,也不能反向写本仓核心状态。 |

### 7.3 部署隔离原则

| 原则 | 当前口径 | 后续承接 |
|---|---|---|
| 逻辑隔离优先 | 同步入口、异步 / 后台承接、维护 / 对账承接可同部署,但职责不得合并 | 实施计划可按 phase 决定是否拆进程或部署单元 |
| 外部正文隔离 | 外部正文承载不得进入 identity 正式存储承载 | Step 8 数据所有权和 Step 12 安全约束继续细化 |
| 维护不绕写 | 维护 / 对账承接不得绕过正式能力修复相邻仓 truth | Step 9 交互和 `05/06` 测试验收继续约束 |
| 基础设施产品后移 | 本步不选择数据库、消息、缓存、对象存储或部署平台 | Step 10 技术选型和 `07` 实施计划承接 |
| 读写降级分离 | 核心身份读取不应因外围来源不可用整体失效,但写入和高风险动作必须守住依据 | Step 8 一致性策略和 Step 12 韧性约束继续细化 |
| 事件协作不等于源码依赖 | 基础设施依赖支撑事件协作,不得变成 L1/L2/L3 业务仓编译期依赖 | Step 7 依赖方向继续闭口 |

### 7.4 运行单元与语义结构映射

| 运行单元 | 承接的语义结构 | 不承接 |
|---|---|---|
| 同步入口单元 | 平台级成员身份真相、成员生命周期边界、角色能力摘要、身份事实消费与追溯 | 不承接外部正文存储、治理裁决 truth、项目 truth |
| 异步 / 后台承接单元 | 外部来源引用、身份生涯与记忆引用、事件协作影子 | 不承接 transport ownership、外部对象正文或跨仓事务 |
| 维护 / 对账承接单元 | 消费投影与对账、身份事实消费与追溯 | 不承接跨仓 truth 修复 |
| identity 正式存储承载 | 核心 truth、支撑子域状态、引用和可重建影子状态 | 不承接 method / work / memory / runtime / credential 正文 |
| trace / audit / outbox 承载 | 追溯、审计和变化传播准备 | 不承接外部证据正文或下游消费方私有状态 |

### 7.3 部署说明

当前阶段只要求运行职责逻辑隔离,不要求同步入口、异步承接和维护承接必须立刻拆成不同进程或不同部署单元。外部正文承载不得与 identity 正式存储承载合并,维护 / 对账承接不得绕过正式能力修复相邻仓 truth。数据库、消息、缓存、对象存储和部署平台的具体产品选型后移 Step 10 和实施计划。

## 1. 模块职责描述

**本模块做什么**:
- 保存平台级 `GlobalMember` 真相与生命周期状态
- 接收并映射外部认证源 / 成员来源
- 定义平台级角色与能力映射
- 向 work / process / runtime / conversation 暴露稳定身份引用与投影
- 提供身份相关的审计与只读摘要

**本模块不做什么**:
- 不负责 `ProjectMember` 真相
- 不负责 `WorkItem` assignee 历史真相
- 不直接承担 process / runtime 的业务状态正文
- 不把投影视图反向当成身份真相写源
- 不把项目级角色分配当成平台级角色真相

```text

            │                 - downstream sync
            │
            └──────────────▶ 身份审计与只读投影部分
                              - summary
                              - lifecycle trace
                              - audit projection
                                          │
                                          ▼
                         work / process / runtime / conversation / console consume
```

**总解释**:
- `L1-identity` 的运行主线不是“先有成员对象,后面再补别的”,而是“外部身份输入进入 → 映射成全局成员真相 → 刷新平台级角色能力 → 对外暴露稳定接缝 → 刷新只读审计投影”
- 真正承载真相写入的是: 身份凭证与认证接缝部分、全局成员主语部分、全局角色与能力映射部分
- 对外身份映射与分身接缝部分负责把 identity 主真相稳定暴露给其他仓,但不让下游回写真相
- 身份审计与只读投影部分只消费真相变化,不反向成为写源

## 5. 按主要部分展开实现要点

### 5.1 为什么要先按主要部分展开

`03-详细设计` 不应直接从“字段表 / API / 表结构”开始。
在 Quantalithos 这类平台型系统中,更稳的写法是:
- 先承接 `02-概要设计.md` 已经确认的主要部分
- 再说明每个主要部分分别落到哪些对象、命令/函数、状态约束、存储与事件
- 最后再进入横向的对象模型、流程、存储、投影、异常与测试细节

> 这里的“主要部分”,不是“单个对象”或“单张表”。它应按 **独立职责 + 主交互链位置 + 稳定边界 + 真相/投影/接缝差异** 来组织。
> 同时还应区分三层函数: **对象成员函数**(维护不变量)、**外层编排函数**(组织流程)、**repo / projection / policy 调用**(持久化、只读、策略校验)。

### 5.2 全局成员主语部分

#### 5.2.1 该部分承接的概要输入
- 来自 `02` 的“全局成员主语部分”
- `GlobalMember` 是平台级身份真相锚点
- 全局生命周期状态与项目内承担关系必须分层

#### 5.2.2 输入 / 输出 / 外部交互图

```text
┌────────────────────────────┐
│ 身份凭证与认证接缝部分      │
│ - auth source mapping      │
│ - credential binding       │
└────────────┬───────────────┘
             │ identity resolved
             ▼
┌────────────────────────────┐
│ 全局成员主语部分            │
│ - GlobalMember             │
│ - lifecycle state          │
└────────────┬───────────────┘
             ├──────────────▶ 全局角色与能力映射部分
             ├──────────────▶ 对外身份映射与分身接缝部分
             └──────────────▶ 身份审计与只读投影部分
```

#### 5.2.3 涉及的对象定义

```rust
/// 全局成员主语，表示平台里唯一稳定的身份真相。
pub struct GlobalMember {
    /// 全局成员唯一标识。
    pub global_member_id: GlobalMemberId,
    /// 成员展示名。
    pub display_name: String,
    /// 当前全局生命周期状态。
    pub lifecycle: GlobalMemberLifecycle,
    /// 当前绑定的主认证源引用。
    pub primary_auth_source_ref: AuthSourceRef,
}
```

这里把 `GlobalMember` 单独放在“全局成员主语部分”里,是因为它承担的是 identity 最核心的真相责任: 回答“平台里谁是谁”。这层不能被 `ProjectMember`、执行代理身份、前台用户展示等下游概念替代。

#### 5.2.4 关键函数代码片段

```rust
/// 全局成员对象，负责维护全局生命周期不变量。
impl GlobalMember {
    pub fn pause(&mut self) {
        // GlobalMember.pause
        // 把全局成员切到 paused，表示其不应继续承接新的全局协作动作。
        self.lifecycle = GlobalMemberLifecycle::Paused;
    }

    pub fn retire(&mut self) {
        // GlobalMember.retire
        // 把全局成员切到 retired，表示其已退出平台身份语义。
        self.lifecycle = GlobalMemberLifecycle::Retired;
    }
}

/// 同步外部成员变化到 `GlobalMember` 真相。
fn sync_global_member(source_event: MemberSourceEvent) -> GlobalMember {
    // MemberSourceParser::parse
    // 把外部成员源事件解析成 identity 可消费的标准输入。
    let parsed = MemberSourceParser::parse(source_event);

    // GlobalMemberBuilder::build_or_merge
    // 构造新成员或合并到已有全局成员真相。
    let member = GlobalMemberBuilder::build_or_merge(parsed);

    // GlobalMemberRepository.save
    // 持久化全局成员真相。
    global_member_repo.save(&member);
    member
}
```

#### 5.2.5 该部分的边界与非职责
- 不负责项目内承担关系真相
- 不负责前台摘要展示逻辑
- 不直接承担平台级角色映射细节
- 不把外部认证源正文直接并入身份真相

#### 5.2.6 该部分与其他主要部分的接缝
- 从 **身份凭证与认证接缝部分** 接收外部解析后的身份输入
- 向 **全局角色与能力映射部分** 提供稳定身份锚点
- 向 **对外身份映射与分身接缝部分** 提供下游引用基础
- 向 **身份审计与只读投影部分** 提供生命周期变化输入

#### 5.2.7 该部分的状态 / 约束 / 易错点
- `GlobalMember` 生命周期不能由下游仓直接改写
- `GlobalMember` 与 `ProjectMember` 必须严格分层
- lifecycle 变化必须可追溯
- 最容易把“全局身份真相”和“项目承担分身”混成一层

### 5.3 身份凭证与认证接缝部分

#### 5.3.1 该部分承接的概要输入
- 来自 `02` 的“身份凭证与认证接缝部分”
- “系统怎么认出这个成员”和“这个成员是谁”不是一回事
- 外部 auth source 变化不应直接拖动核心身份模型

#### 5.3.2 输入 / 输出 / 外部交互图

```text

│ external auth / org source │
│ - login source             │
│ - member directory         │
└────────────┬───────────────┘
             │ credential / auth input
             ▼
┌────────────────────────────┐
│ 身份凭证与认证接缝部分      │
│ - credential binding       │
│ - auth source mapping      │
└────────────┬───────────────┘
             │ resolved member identity
             ▼
┌────────────────────────────┐
│ 全局成员主语部分            │

└────────────────────────────┘
```

#### 5.3.3 涉及的对象定义

```rust
/// 认证源引用，表示身份来自哪个外部认证或目录系统。
pub struct AuthSourceRef {
    /// 外部源唯一标识。
    pub source_id: String,
    /// 外部源类型,如 sso / directory / local.
    pub source_type: String,
}

/// 凭证绑定对象，表示外部凭证如何稳定映射到全局成员。
pub struct CredentialBinding {
    /// 凭证绑定唯一标识。
    pub binding_id: String,
    /// 对应的全局成员。
    pub global_member_id: GlobalMemberId,
    /// 来自哪个认证源。
    pub auth_source_ref: AuthSourceRef,
    /// 外部身份键。
    pub external_subject: String,
}
```

这一部分不保存“成员是谁”的最终真相,而是负责把外部认证输入映射成 identity 主真相可消费的绑定关系。它的意义在于隔离外部源格式变化,保护 `GlobalMember` 模型稳定。

#### 5.3.4 关键函数代码片段

```rust
/// 建立一条稳定的外部凭证到全局成员的绑定关系。
fn bind_credential_source(source: AuthSourceRef, subject: String) -> CredentialBinding {
    // CredentialBindingBuilder::build
    // 基于外部认证源和 subject 构造绑定对象。
    let binding = CredentialBindingBuilder::build(source, subject);

    // CredentialBindingRepository.save
    // 持久化凭证绑定接缝对象。
    credential_binding_repo.save(&binding);
    binding
}
```

#### 5.3.5 该部分的边界与非职责
- 不负责全局成员真相本体
- 不负责项目级角色分配
- 不负责只读展示摘要
- 不负责平台级能力推导

#### 5.3.6 该部分与其他主要部分的接缝
- 从外部认证源接收输入
- 向 **全局成员主语部分** 提供稳定身份绑定结果
- 向 **身份审计与只读投影部分** 提供绑定变更记录

#### 5.3.7 该部分的状态 / 约束 / 易错点
- 认证源变化不能直接改写 `GlobalMember` 核心模型结构
- binding 必须可追溯到外部 source
- 最容易把“认证方式”和“身份真相”写成同一层

#### 5.4.3 涉及的对象定义

```rust
/// 平台级角色对象，表示某个成员在平台范围内承担的角色。
pub struct PlatformRoleBinding {
    /// 绑定唯一标识。
    pub binding_id: String,
    /// 对应全局成员。
    pub global_member_id: GlobalMemberId,
    /// 平台角色名称。
    pub role_name: String,
}

/// 平台能力映射对象，表示某个成员在平台级被授予的能力边界。
pub struct CapabilityMapping {
    /// 对应全局成员。

    pub capabilities: Vec<String>,
}
```

这里的关键不是“角色字段长什么样”,而是把 platform role / capability 明确独立于 project role。它们服务于平台级权限与能力语义,不是项目内承担分配。

#### 5.4.5 该部分的边界与非职责
- 不负责项目内承担角色分配
- 不负责只读展示摘要

- 从 **全局成员主语部分** 读取稳定身份锚点
- 向 **对外身份映射与分身接缝部分** 提供平台级角色能力输入
- 向 **身份审计与只读投影部分** 提供角色变化记录

#### 5.4.7 该部分的状态 / 约束 / 易错点
- platform role / capability 不得与 project role 混层
- 角色和能力变更必须有审计链
- 最容易把权限策略和项目承担关系混写

```rust
    /// 对应全局成员。

    /// 当前生命周期状态摘要。
    pub lifecycle: GlobalMemberLifecycle,
}

/// 下游同步事件，表示 identity 向其他仓广播身份变化的输出。
pub struct MemberSyncEvent {
    /// 对应成员。
    pub member_ref: MemberRef,
    /// 事件类型,如 lifecycle_changed / capability_changed。
    pub event_type: String,
}
```

这一部分不是再造一份真相,而是把 identity 主真相变成其他仓可以稳定消费的 ref 与 sync 事件。它是多仓边界里最容易被偷懒写坏的一层。

#### 5.5.4 关键函数代码片段

```rust
/// 为下游仓构造稳定成员引用。
fn resolve_member_ref(member: &GlobalMember) -> MemberRef {
    // MemberRefBuilder::build
    // 把全局成员真相压缩成下游可稳定消费的引用对象。
    MemberRefBuilder::build(member)
}
```

#### 5.5.5 该部分的边界与非职责
- 不负责只读展示摘要
- 不回写下游仓局部真相
- 不直接承担平台角色映射计算
- 不重新定义一份全局成员真相

#### 5.5.6 该部分与其他主要部分的接缝
- 从 **全局成员主语部分** 读取身份真相
- 从 **全局角色与能力映射部分** 读取平台能力边界
- 向 work/process/runtime/conversation 输出 ref / sync 事件
- 向 **身份审计与只读投影部分** 提供对外同步轨迹

#### 5.5.7 该部分的状态 / 约束 / 易错点
- 下游 ref 不能替代 identity 主真相
- 下游同步必须是可追踪的,不能静默写入
- 最容易让各仓再复制一份自己的全局成员真相

### 5.6 身份审计与只读投影部分

#### 5.6.1 该部分承接的概要输入
- 来自 `02` 的“身份审计与只读投影部分”
- summary / trace / audit projection 是只读层
- conversation / console / admin 不应直接读 identity 真相对象

```text
             ▼
┌────────────────────────────┐

             │ read-only views
             ▼

└────────────────────────────┘
```

- 不拥有 GlobalMember 真相
- 不反向成为写源
- 不负责项目分身同步
- 不承担平台级能力计算

#### 5.6.6 该部分与其他主要部分的接缝
- 从前四个主要部分读取输入
- 向 conversation / console / observability 输出只读视图
- 不反向影响任何真相对象

#### 5.6.7 该部分的状态 / 约束 / 易错点
- summary / trace / audit 都应只读
- 外部展示延迟允许最终一致,但不允许反写真相
- 最容易把展示投影误当真相对象继续传播

## 8. 运行期主线场景

### 8.1 场景 A · 外部认证源同步一个新成员

```text
external auth / org source sends member event
      │
      ▼
身份凭证与认证接缝部分 ingest auth source
      │
      ▼
BindCredentialSource(auth_source_ref, external_subject)
      │
      ▼
SyncGlobalMember(source_event)
      │
      ▼
GlobalMember truth created / updated
      │
      ▼
summary / audit projection refresh
```

**开发者关注点**:
- 外部 auth source 输入必须先经过接缝层,不能直接构造 `GlobalMember`
- 同步成员真相时要同时保证 binding 和 member truth 的稳定回链
- 成员摘要和审计投影只能在真相更新后刷新,不能反向驱动真相

### 8.2 场景 B · 成员生命周期变化后下游分身收缩

```text
external lifecycle changed
      │
      ▼
UpdateGlobalLifecycle(global_member_id, lifecycle event)
      │
      ▼
GlobalMember active → paused / retired
      │
      ▼
MemberSyncPublisher emits lifecycle change
      │
      ├──────────────▶ work updates ProjectMember state
      ├──────────────▶ process refreshes actor context
      └──────────────▶ conversation / console refresh summary
```

**开发者关注点**:
- `GlobalMember` lifecycle 是根状态,下游只能消费不能回写
- `ProjectMember` 的收缩是下游映射结果,不是 identity 真相本体
- lifecycle 更新必须带着下游同步与审计链一起看,不能只改一张表

### 8.3 场景 C · 角色/能力变化后摘要与审计投影刷新

```text
platform role / capability refresh request
      │
      ▼
RefreshCapabilityMapping(global_member_id)
      │
      ▼
CapabilityMapping updated
      │
      ▼
MemberSyncPublisher emits capability change
      │
      ▼
BuildIdentitySummary / collect lifecycle trace
      │
      ▼
conversation / console / observability consume projection
```

**开发者关注点**:
- platform role / capability 更新不能混成 project role 更新
- capability 变化既要能被下游消费,也要能进入审计投影
- projection 刷新失败不应回滚成员真相,但必须告警并可重建

### 8.4 外部交互入口归属

| 外部来源 | 进入入口 | 落到哪个主要部分 | 结果 |
|---|---|---|---|
| external auth / org source event | `identity_controller.sync_global_member` | 身份凭证与认证接缝部分 → 全局成员主语部分 | 形成/更新 `GlobalMember` |
| external lifecycle change | `identity_controller.update_global_lifecycle` | 全局成员主语部分 | lifecycle 更新并触发下游同步 |
| capability refresh request | `identity_service.refresh_capability_mapping` | 全局角色与能力映射部分 | 更新平台能力映射 |
| downstream member ref request | `identity_service.resolve_member_ref` | 对外身份映射与分身接缝部分 | 返回稳定 `MemberRef` |
| summary / trace query | `projection_query_service.get_identity_summary` | 身份审计与只读投影部分 | 返回只读摘要 / trace / audit view |

- **全局成员主语部分**:
  - `GlobalMember` 必须是平台级唯一身份锚点
  - lifecycle 变化必须留痕且可追溯
- **身份凭证与认证接缝部分**:
  - `CredentialBinding` 必须可回链到外部 source
  - 同一 source + external_subject 不能映射到多个 `GlobalMember`
- **全局角色与能力映射部分**:
  - platform role 不得和 project role 混层
  - capability 变化必须与对应成员真相关联
- **对外身份映射与分身接缝部分**:
  - 下游 ref 不得反写 identity 真相
  - sync 事件必须可追踪
- **身份审计与只读投影部分**:
  - summary / trace / audit projection 只读
  - 投影异常不影响主真相层写入

## 11. 异常与补偿设计

### 11.1 重试 / 降级 / 熔断 / 补偿

- **全局成员主语部分**: 外部成员源异常时,优先保留最后一次稳定的 `GlobalMember` 真相,不伪造新成员状态
- **身份凭证与认证接缝部分**: 认证源绑定失败时,拒绝新 binding 落库,并保留原有稳定 binding
- **全局角色与能力映射部分**: capability 计算失败时,保留上一次稳定映射并告警,不写空值覆盖
- **对外身份映射与分身接缝部分**: 下游同步失败时允许重放 sync 事件,但不得由下游反写 identity 真相
- **身份审计与只读投影部分**: projection 构建失败时允许只读降级,不影响主真相层写入

### 11.2 高风险跨仓失败模式

| 场景 | 主要落点部分 | 失败点 | 补偿 / 对账 / replay |
|---|---|---|---|
| external auth source subject 漂移 | 身份凭证与认证接缝部分 | binding 冲突 | 冻结旧 binding + 人工合并 / replay source event |
| `GlobalMember` lifecycle 与 `ProjectMember` 收缩不同步 | 对外身份映射与分身接缝部分 | downstream sync 延迟 | replay member sync event |
| capability 变化未传递到 runtime / governance | 全局角色与能力映射部分 | capability sync 丢失 | replay capability event |
| projection 错误地覆盖真相展示 | 身份审计与只读投影部分 | summary / trace 不一致 | 重建 projection / audit compare |

### 11.3 按主要部分归属的失败模式

| 主要部分 | 典型失败 | 检测点 | 处理策略 | 补偿 / replay |
|---|---|---|---|---|
| 全局成员主语部分 | `GlobalMember` 被局部字段替代 | truth / ref consistency check | 阻断错误写入 | replay source sync |
| 身份凭证与认证接缝部分 | 同一外部 subject 绑定到多个成员 | binding uniqueness check | 拒绝 binding | 人工合并 / replay |
| 全局角色与能力映射部分 | platform role 与 project role 混层 | role boundary check | 拒绝写入 | 修正规则重算 |
| 对外身份映射与分身接缝部分 | 下游 ref 回写真相 | ref write guard | 阻断写入 | replay member sync |
| 身份审计与只读投影部分 | summary / trace 被误作写源 | projection write guard | 阻断并告警 | rebuild projection |

## 12. 实现红线 / 开发禁止事项

- 不要让 `ProjectMember`、`WorkItem`、`ActorContext` 等下游对象回写 `GlobalMember` 真相
- 不要把 external auth / org source 的原始正文结构直接并入 `GlobalMember` 主模型
- 不要把 platform role / capability 与 project role / project assignment 混成一层
- 不要让 summary / trace / audit projection 反写真相
- 不要在下游仓各自复制一份新的全局成员真相,必须通过稳定 ref / sync 接缝消费 identity

## 15. 结论

本详细设计的核心结论是:
- `L1-identity` 的实现结构应按 5 个主要部分组织,而不是按对象顺排
- 全局成员主语部分负责“平台里谁是谁、当前身份是否仍有效”
- 身份凭证与认证接缝部分负责“系统如何认出这个成员并稳定绑定外部身份源”
- 全局角色与能力映射部分负责“平台级角色与能力边界”
- 对外身份映射与分身接缝部分负责“下游仓如何稳定消费 identity 而不复制真相”
- 身份审计与只读投影部分负责“外部如何只读查看 summary / trace / audit”
- `GlobalMember` 与 `ProjectMember`、platform role 与 project role、真相层与投影层都必须严格分层
- 后续 `05-测试方案.md` / `06-验收标准.md` 应围绕这 5 个主要部分建立测试与验收映射

| `AuthSourceRef` / `GateRef` / 其他稳定引用 | 引用对象 | 是 | 只保存稳定引用 |

| 主要部分 | 表/集合 | 关键索引 |
|---|---|---|
| 全局成员主语部分 | `global_members` | `(global_member_id)`, `(lifecycle)` |
| 身份凭证与认证接缝部分 | `credential_bindings` | `(binding_id)`, `(external_subject, source_id)` |
| 全局角色与能力映射部分 | `platform_roles` | `(global_member_id, role_name)` |
| 全局角色与能力映射部分 | `capability_mappings` | `(global_member_id)` |
| 对外身份映射与分身接缝部分 | `member_sync_events` | `(global_member_id, event_type)` |
| 身份审计与只读投影部分 | `member_summary_projection` | `(global_member_id)` |
| 身份审计与只读投影部分 | `lifecycle_trace_projection` | `(global_member_id)` |

### 9.3 持久化建议

| 主要部分 | 对象 | 存储方式 | 理由 |
|---|---|---|---|
| 全局成员主语部分 | `GlobalMember` | `global_members` | 保持平台级身份真相独立稳定 |
| 身份凭证与认证接缝部分 | `CredentialBinding` | `credential_bindings` | 外部认证接缝需与主真相分离 |
| 全局角色与能力映射部分 | `PlatformRoleBinding` / `CapabilityMapping` | `platform_roles` / `capability_mappings` | 角色和能力边界需独立演化 |
| 对外身份映射与分身接缝部分 | sync event / stable ref | event log + ref store | 下游同步链需可追踪 |
| 身份审计与只读投影部分 | summary / trace / audit projection | projection 表或可重建视图 | 只读、最终一致 |

### 9.4 关键校验

- **全局成员主语部分**:
  - `GlobalMember` 必须是平台级唯一身份锚点
  - lifecycle 变化必须留痕且可追溯
- **身份凭证与认证接缝部分**:
  - `CredentialBinding` 必须可回链到外部 source
  - 同一 source + external_subject 不能映射到多个 `GlobalMember`
- **全局角色与能力映射部分**:
  - platform role 不得和 project role 混层
  - capability 变化必须与对应成员真相关联
- **对外身份映射与分身接缝部分**:
  - 下游 ref 不得反写 identity 真相
  - sync 事件必须可追踪
- **身份审计与只读投影部分**:
  - summary / trace / audit projection 只读
  - 投影异常不影响主真相层写入

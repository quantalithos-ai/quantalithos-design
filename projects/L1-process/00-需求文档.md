## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 不是一个纯聊天产品,而是一个有阶段、有里程碑、有 Gate、有恢复能力的软件工程系统。用户和 AI 员工的协作必须按过程模板推进:
- 需求阶段做什么
- 设计阶段做什么
- 编码/评审阶段做什么
- 什么时候必须停下来请人决策(Gate)
- 崩溃后如何从 Checkpoint 恢复

L1-process 就是把这些问题变成可执行的 BPMN 2.0 / SPEM / 29110 过程引擎。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `domain/process/README.md` 1706 行 | 设计完整,仓级需求层未显式定义 |
| completion_policy | ADR-0008 已定 | 样板代码还没验证交汇点行为 |
| Checkpoint | ADR-0007 已定 | 仓级实施顺序未落地 |
| 刚度分层 | ADR-0010 Proposed | GUIDED / ADVISORY 尚未代码验证 |
| 流程嵌套 | ADR-0011 Proposed | SubProcess / CallActivity 尚未验证 |

### 2.3 为什么要做(量化依据)

- 没有 process 仓,work / governance / artifact / member-service 只是分散的能力,不会形成"可推进的过程"
- 过程域是 N2 的核心仓之一,其启动决定了"从项目到交付"是否能跑通
- README 目标是支撑 **10w 活跃 Instance / 5000w Activity/年**,这是平台级主干能力

### 2.4 业务问题 vs 技术问题

- **业务问题**:如何让项目按模板推进,在关键节点停下来,在失败时恢复
- **技术问题**:BPMN 引擎、三段式、Tailoring、Checkpoint、Token、waiting_gate、AutoAction / completion_policy、嵌套

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 选择 Template,激活 Profile,启动 ProcessInstance
2. runtime 接收 Activity,完成后写 Checkpoint
3. 过程遇到关键节点时进入 waiting_gate,governance 决策后恢复
4. 崩溃恢复:从最近 Checkpoint 恢复
5. Parallel / Exclusive Gateway 正确推进 Token

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **Owner**,我想要 **基于模板启动一个项目过程**,以便 **项目按规矩推进** |
| 优先级 | P0 |
| 验收条件 | **Given** 一个 active ProcessProfile **When** 调用 StartInstance **Then** 创建 running 的 ProcessInstance |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **runtime**,我想要 **Activity 完成时立刻写 Checkpoint**,以便 **崩溃后不重跑已完成步骤** |
| 优先级 | P0 |
| 验收条件 | **Given** Activity complete **When** 事务提交 **Then** 必产生新的 checkpoint |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **governance**,我想要 **在 Activity 进入 waiting_gate 时收到结构化请求**,以便 **创建 Gate 并等待人类决策** |
| 优先级 | P0 |
| 验收条件 | **Given** Activity 转 waiting_gate **When** process 发事件 **Then** governance 能自动 RaiseGate |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **Owner**,我想要 **看到项目当前在哪个阶段、哪些 Activity 在跑、哪些 Gate 在等**,以便 **知道系统在做什么** |
| 优先级 | P0 |
| 验收条件 | **Given** 查询 InstanceState **When** 请求当前快照 **Then** 返回 stage / current_activities / pending_gates / tokens |

| 字段 | 内容 |
|---|---|
| ID | US-005 |
| 用户故事 | 作为 **SRE**,我想要 **服务崩溃后从 Checkpoint 恢复到最近状态**,以便 **把停机时间控制在几十秒级** |
| 优先级 | P0 |
| 验收条件 | **Given** 服务重启 **When** 扫描 active Instance **Then** 30 秒内恢复小 Instance |

## 6. 功能需求

### 6.1 功能清单与优先级

| ID | 功能名称 | 优先级 | 依赖 | 描述 |
|---|---|---|---|---|
| F-001 | ProcessTemplate 索引 | P0 | method-library | 读取执行所需结构化 Template |
| F-002 | ProcessProfile Tailoring | P0 | F-001 | 29110 Profile + effective graph |
| F-003 | ProcessInstance 状态机 | P0 | F-002 | draft/running/paused/completed/failed/cancelled |
| F-004 | Activity 状态机 | P0 | F-003 | scheduled / in_progress / waiting_gate / completed / failed / skipped |
| F-005 | Token/Gateway 推进 | P0 | F-003 | Exclusive / Parallel / Inclusive / EventBased |
| F-006 | Checkpoint 链 | P0 | F-003 | 每 Activity 完成后写入 |
| F-007 | waiting_gate → governance 流转 | P0 | governance | 自动 RaiseGate / Resume |
| F-008 | Artifact outputs 事件 | P0 | artifact | activity.artifact_produced |
| F-009 | WorkItem 交汇(`completion_policy`) | P0 | work | 两轨交汇 |
| F-010 | RecoverInstance | P0 | F-006 | 小 Instance < 30s |
| F-011 | 两种初始模板 | P0 | method-library | iterative-standard / waterfall-classic |
| F-012 | Nested process(SubProcess/CallActivity) | P1 | ADR-0011 | 本阶段可占位 |
| F-013 | Template 刚度 | P1 | ADR-0010 | STRICT/GUIDED/ADVISORY,可先占位 |

### 6.2 业务规则表

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-001 | Profile active 后 | `effective_activity_graph` 冻结 |
| BR-002 | Activity complete | 必写 checkpoint |
| BR-003 | Gate pending | Activity 进 waiting_gate |
| BR-004 | ProcessInstance.completed | 不代表项目完成(项目完成看 WorkItem) |
| BR-005 | mandatory Gate | 不得被 Tailoring 去掉 |
| BR-006 | source_fingerprint 不一致 | `process.template.source_drift` |

### 6.3 功能依赖图

```
Template → Profile → Instance
                     ├─ Activity state machine
                     ├─ Token/Gateway
                     ├─ Checkpoint chain
                     ├─ waiting_gate ↔ governance
                     ├─ artifact outputs
                     └─ workitem completion_policy
```

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 聚合 / 类型 | 生命周期 |
|---|---|---|
| ProcessTemplate | 聚合根 | draft → published → deprecated / retired |
| ProcessProfile | 聚合根 | draft → active → superseded / retired |
| ProcessInstance | 聚合根 | draft → running / paused → completed / failed / cancelled |
| Activity | Instance 内实体 | scheduled → in_progress → waiting_gate / completed / failed / skipped |
| Token | 值对象 | active / consumed |
| Checkpoint | 值对象 / 记录 | append-only |

### 9.2 数据关系

```
Template
  └─ Profile
      └─ Instance
          ├─ current_activities[]
          ├─ active_tokens[]
          ├─ pending_gates[]
          └─ checkpoint chain
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| active Instance | 热存 | active |
| completed / failed Instance | 冷存可查 | archive |
| checkpoint inline | 常用热存 | >256KB 外置 |
| template/profile 历史 | 长期 | 永久审计 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| checkpoint 写频繁拖慢主流程 | 中 | 高 | inline/external 分层 |
| method-library drift | 中 | 高 | fingerprint 对账 |
| waiting_gate 恢复链断裂 | 低 | 高 | replay + observability |
| Token/Gateway 语义实现错误 | 中 | 高 | exhaustive tests |

### 12.2 边缘风险

- Nested process(CallActivity/SubProcess)实现复杂度过高
- GUIDED 模式 / Deviation 后续引入导致状态机膨胀
- large Instance checkpoint chain 过长

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| Assignee 算法(负载 / 能力 / 轮询) | N2 前 | process + member-service |
| GUIDED / Deviation 何时真正落地 | N2 后 | process + governance |
| Token timeout 策略 | N2 前 | process |

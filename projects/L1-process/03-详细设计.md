## 5. 模块实现契约

> 校准来源:
> - `design-calibration/03_ddd_step_05_module_contracts.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`

> 延伸阅读:

L1-process 的详细设计模块主轴与 workspace member 对齐,包括 `contracts`、`domain`、`application`、`infra`、`api`、`worker`、`jobs` 七个模块。业务主要组成部分不直接变成 crate;它们跨模块实现。

| 模块 | 所属实现单元 | 职责 | 对外暴露 | 依赖对象 |
|---|---|---|---|---|
| `contracts` | `process-contracts` | 公共协议、typed ref、view、event、job、receipt 和 protocol error | DTO / ref / view / event / job / error | `core-contracts` |
| `domain` | `process-domain` | Process truth 对象、value object、state、policy、不变量和 domain error | aggregate / policy / state / DomainError | `contracts`、`core-contracts` |
| `application` | `process-application` | 用例编排、事务、幂等、port 调用和 application error mappers | services / ports / UoW / idempotency | `contracts`、`domain`、`core-contracts` |
| `infra` | `process-infra` | repository / adapter / config / runtime builder | adapters / stores / runtime builder | `contracts`、`domain`、`application`、`core-contracts` |
| `api` | `process-api` | 同步 Command / Query handler | handlers / routes / ApiError | `contracts`、`application`、`infra`、`core-contracts` |
| `worker` | `process-worker` | inbound consumer、outbox publisher loop、projection maintenance trigger | consumers / worker runners | `contracts`、`application`、`infra`、`core-contracts` |
| `jobs` | `process-jobs` | projection rebuild、reference refresh、reconciliation、recovery maintenance、trace / archive handoff job | job runners | `contracts`、`application`、`infra`、`core-contracts` |

```text
contracts -> core-contracts
domain -> contracts -> core-contracts
application -> domain -> contracts -> core-contracts
infra -> application -> domain -> contracts -> core-contracts
api / worker / jobs -> infra -> application
```

禁止方向:

- `contracts` 不依赖 `domain`、`application`、`infra`、`api`、`worker` 或 `jobs`。
- `domain` 不依赖 repository、adapter、config、HTTP、bus、DB 或 job runner。
- `application` 不依赖 `infra`、`api`、`worker` 或 `jobs`。
- `api`、`worker`、`jobs` 不互相依赖。

### 5.1 `contracts`

`contracts` 定义跨入口和下游可复用协议 DTO,不承载领域不变量。文件主体包括 `refs.rs`、`metadata.rs`、`commands.rs`、`queries.rs`、`events.rs`、`jobs.rs`、`views.rs`、`errors.rs` 和 `fixtures.rs`。它只能依赖 `core-contracts`。

### 5.2 `domain`

`domain` 定义 Process truth 对象、状态、policy、不变量和 domain error。正式对象包括 `RuntimeProcessShape`、`ProcessProfile`、`ProcessInstance`、`Activity`、`Token`、`Gateway`、`WaitingGate`、`PauseContext`、`ProcessCheckpoint`、`RecoveryAttempt`、`ProcessStageState`、`ProcessTimeboxBinding`、reference / snapshot、projection、trace、audit 和 outbox。`domain` 只能消费 contracts / core 类型,不得读取 config 或直接调用外部 adapter。

### 5.3 `application`

`application` 编排 command / query / consumer / job 用例、事务、幂等、operation result replay、repository / port 调用、outbox / trace / projection 副作用。port trait、UnitOfWork、IdempotencyRepository、OperationResultRepository、ClockPort、IdGeneratorPort 和 application services 均在本模块定义。

### 5.4 `infra`

`infra` 实现 application ports,提供 repository / projection / idempotency / resolver / publisher / handoff adapter、config loader、runtime builder 和 fake runtime。`infra` 不向 domain 泄漏 adapter 细节。

### 5.5 `api` / `worker` / `jobs`

`api` 只承载同步 Command / Query handler 和 route assembly;`worker` 承载 inbound event consumer、outbox publish loop 和 projection invalidation worker;`jobs` 承载 operations job runner。三者通过 `infra::runtime_builder` 获得 application service 装配,不得互相依赖。

共享约束:

- Command request 使用 `CommandMetadata.idempotency_key`;缺失时 reject。

- Command result、Query view / page、Inbound Event envelope / payload / receipt、Outbound Event payload、Job input / output / report 中引用的 enum / ref / helper 必须属于 `process-contracts` 或 `core-contracts`,不得引用 domain-only 类型。
- PH-06 Query / view helper refs 包括 `PageCursorRef`、`DegradedReasonRef`、`ProcessConsumerRef`、`VisibilityReasonRef`、`ReferenceResolutionStateId`、`ReferenceResolutionStateRef`、`DerivedProcessViewStateId`、`DerivedProcessViewStateRef`、`ProcessReadSubjectRef`、`ProcessSearchFilterRef`、`ProcessReadModelId`、`ProcessReadModelRef`、`ActivityStatusViewId`、`ProcessTimelineEntryRef`、`ProcessTimelineEntryRefSet`、`ProcessProgressSummaryId`、`ProcessProgressSummaryRef`、`ReconciliationReportId`、`ReconciliationReportRef`、`ReconciliationIssueRef`、`ReconciliationIssueRefSet`、`RecoveryStatusSubjectRef`、`ProcessTimelineFilterRef`、`ProcessSummarySubjectRef`、`ProcessTraceSubjectRef`、`ProcessAuditSubjectRef`。这些类型的字段级 schema 以 `design-calibration/03_ddd_step_08_protocol_contracts.md` §7.4.1 为准,全部归 `contracts::refs`,不得由 query service、projection fake 或 handler 用裸字符串临时补。`ProjectionFreshnessState` 是 Step 6 §9.7 定义的 public enum,Step 8 query marker 复用同一 enum。`ProcessViewStatus::NotVisible` 的 marker 只能来自 Step 7 `ReadVisibilityPolicy.evaluate_read_visibility(...) -> ProcessReadVisibilityDecision`;`Hidden` 和 filtered-to-empty 返回 `NotVisible`,普通 `ApplicationError::NotAuthorized` 不得替代 visibility marker。
- `SearchProcessInstances` 的正式返回类型是 `ProcessSearchResultPage`,必须包含 `status`、`page_info`、`visibility_marker`、`projection_marker` 和 `degraded_marker`;`GetProcessTrace` 的正式返回类型是 `ProcessTraceView`,必须包含 `status`、`page_info` 和 `visibility_marker`。实现不得把两者降级成缺少 marker surface 的泛型 wrapper。

- `WaitingGate.waiting_gate_id` 和 `PauseContext.pause_context_id` 必须由 application 分别通过 `IdGeneratorPort::new_waiting_gate_id()` / `new_pause_context_id()` 生成后传入 `PauseContext::from_activity(...)` 与 `WaitingGate::open_for_activity(...)`;不得字符串拼接、复用其他 id generator 或由 domain 工厂自行生成。

- `ProcessStageState.stage_id` 和 `ProcessTimeboxBinding.binding_id` 必须由 application 分别通过 `IdGeneratorPort::new_process_stage_id()` / `new_process_timebox_binding_id()` 生成后传入 `ProcessStageState::from_profile_stage(...)` 与 `ProcessTimeboxBinding::bind(...)`;domain 不得自行生成 PH-05 rhythm id。
- `StartProcessInstanceRequest.start_intent_ref` 是结构化 `ProcessStartIntentRef`,归 `contracts::refs`,必须承载 start node、可选 initial gateway 和 start reason。bootstrap 映射以 `design-calibration/03_ddd_step_06_object_contracts.md` §7.2.2 / §7.3 为准;实现必须通过 `ProcessShapeRepository.get_start_bootstrap_summary(profile.shape_ref, start_intent_ref.start_node_ref)` 读取 body-free start summary 来校验 start node membership、取得 `ActivityKind`、判断是否需要 gateway tracking,并取得 optional gateway node/kind。实现不得用裸字符串、opaque ref、runtime shape body 或 adapter 私有字段推断 initial `Activity` / `Token` / `Gateway`。

- `ProfileStageRef` 是结构化 body-free ref,归 `contracts::refs`,必须包含 `stage_kind: ProcessStageKind`;`ProcessStageState::from_profile_stage(...)` 直接复制该字段,不得从 ref 字符串、profile body 或 adapter 私有字段推断 stage kind。`BindProcessTimeboxRequest.process_subject_ref` 是结构化 `ProcessTimingSubjectRef::{ProcessInstance, ProcessProfile}`;`BindProcessTimeboxRequest.work_context_ref` 是 `WorkContextSnapshot` 的唯一解析输入面,service 必须用它调用 `WorkContextResolverPort.resolve_work_context(...)`,不得从 `process_subject_ref`、`process_timebox_ref` 或 `external_timebox_ref` 字符串反推 work context。`UpdateProcessStageStateRequest.stage_target` 必须与结构化 `StageChangeReason` variant 一致,否则 reject。完整 PH-05 schema 和 target-to-domain-method 映射以 `design-calibration/03_ddd_step_06_object_contracts.md` §7.2.5 为准。

## 8. 逐接口函数级处理流

> 校准来源:
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“处理流总表”“通用 Command 写路径模板”“通用 Query 读路径模板”“通用 Consumer 写路径模板”“通用 Job 写路径模板”和逐接口流明细。

所有 Command 写路径必须在 application service 中开启 `UnitOfWork`,先执行 command idempotency reservation,再加载依赖、调用 policy 和 domain object,最后保存 truth、trace、outbox、operation result 并完成 idempotency。duplicate replay 必须读取 `OperationResultRepository`,不得重放 domain transition。

```text
[API Command Handler]
  | validate Command DTO and metadata
  v
[Application Command Service]
  | begin UnitOfWork
  | reserve command idempotency
  | duplicate -> load stored result and return
  | conflict -> rollback + error
  | load truth / snapshot / policy inputs
  v
[Domain object / policy]
  | factory / transition
  v
[Repositories]
  | save truth / trace / outbox / projection marker
  | save StoredProcessOperationResult
  | complete idempotency
  | commit
```

所有 Query 只读,不得开启 write unit of work,不得刷新外部 snapshot,不得修复 projection。Query response 必须使用 Step 8 的 `ProcessViewStatus`、visibility marker、degraded marker 和 projection marker。

所有 Inbound Consumer 必须先验证 `InboundEventEnvelope<T>`,再执行 event dedup。trusted source actor 只在 consumer 内用于 source isolation 和 marker 写入,不得推进核心 command state。Consumer 只写 snapshot、reference、pending、stale 或 no-op marker。

所有 Operations Job 必须携带 `JobMetadata.job_idempotency_key`。outbox publish / handoff job 可采用 per-item transaction,确保单条失败不回滚已完成条目。Job 不得静默修复 Process truth。

## 10. 数据持久化、事务与一致性契约

> 校准来源:
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“数据所有权实现表”“表 / collection / projection 契约表”“Repository 函数表”“事务边界表”“一致性策略表”和“恢复与补偿表”小节。

持久化设计只锁定逻辑存储契约,不锁定具体数据库产品或 DDL。实现可以使用 SQL table、document collection 或 in-memory adapter,但必须保留本章定义的主键、唯一键、索引、版本、UoW 和一致性语义。

| 类型 | 对象 | 一致性口径 |
|---|---|---|
| 业务 truth | RuntimeProcessShape、ProcessProfile、ProcessInstance、Activity、Token、Gateway、WaitingGate、Checkpoint、RecoveryAttempt、StageState、TimeboxBinding | 强一致,由 Command flow 在同一 UoW 内成立或 rollback |
| history / trace / outbox | ProfileChangeRecord、ActivityProgressionRecord、WaitingGateChangeRecord、RecoveryHistoryRecord、ProcessTraceRecord、ProcessOutboxRecord | accepted truth 同 UoW 写入;outbox publication 最终一致 |
| reference / snapshot | ReferenceResolutionState、MethodDefinitionSnapshot、WorkContextSnapshot、ActorCapabilitySnapshot 等 | 最终一致,不得复制外部正文 |
| operation result replay | StoredProcessOperationResult、ApplicationResultRef | accepted command / consumer / job 同 UoW 保存;duplicate 只读 replay |
| projection / report / handoff | ProcessReadModel、ProcessTimelineView、ProcessProgressSummary、ReconciliationReport、TraceHandoffRecord | 只读 / 可重建 / 最终一致,不得反写业务 truth |

写路径必须通过 `UnitOfWork`。所有修改已有 truth / state 的 repository 函数必须使用 optimistic version;version mismatch 映射为 repository conflict,不得 silent overwrite。所有 Command、Inbound Event Consumer 和 Operations Job 的写入必须先 reserve idempotency key / dedup key。Command 成功路径必须在同一 UoW 内保存 operation result surface,再 complete result ref。

Query 不开启写 UoW,不写 audit,不写 outbox,不触发 projection rebuild。Query 读取 stale / failed / rebuilding projection 时必须返回对应 surface,不能在读路径修复状态。

## 11. 错误模型、异常分支与恢复口径

> 校准来源:
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“错误类型表”“错误映射表”“异常分支处理表”“恢复口径表”和 Command / Consumer / Job 映射规则。

错误模型采用分层错误边界。Domain 层只返回 `DomainError`;repository / port / UoW / idempotency 层分别返回 `RepositoryError`、`ResolverError`、`PublishError`、`HandoffError`、`UnitOfWorkError`、`IdempotencyError`;protocol surface 使用 `ProcessApiError`、`ConsumerReceipt`、`JobRunReceipt` / `JobError` 和 query `ProcessViewStatus`。

同步 Command 的失败不得写 accepted truth、trace 或 outbox。Query 失败不得触发修复写入。Inbound Event 的 invalid envelope / unsupported schema / digest mismatch / body rejected 进入 quarantine;source unavailable 进入 delayed。Operations Job 区分 job-level reject 和 item-level failure;item-level failure 必须进入 report 或 failed marker。

| 错误类别 | 恢复方式 |
|---|---|
| request / metadata / visibility / domain policy 错误 | 调用方修正输入或权限,不可自动原样重试 |
| repository conflict | reload latest version,重新校验 policy 后重试 |
| idempotency duplicate | 通过 `OperationResultRepository.get_result` 返回 stored result / receipt,不得重放 domain transition |
| idempotency conflict | reject,调用方使用新 key 或原 request digest |
| external reference unresolved / unavailable | command temporary unavailable、consumer delayed、job partial / dependency unavailable |
| publisher / handoff retryable failure | 写 retry / failed marker,后续 job 重试 |
| commit status unknown | 不盲重试;先查 idempotency result / operation result |

## 12. 并发、幂等与重入保护

> 校准来源:
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“并发场景表”“幂等 value object 与 digest 规则”“幂等键表”“重入保护表”和“Repository / UoW ordering rules”小节。

写路径使用三层保护:第一层是 `IdempotencyRepository` 对 `ProcessIdempotencyOperation + key` 的 atomic reserve;第二层是 `RequestDigest` / `EventDigest` / `JobDigest` 区分 same request 与 key reuse conflict;第三层是 repository optimistic `StorageVersion`、唯一键和 cursor monotonicity 防止并发覆盖。`ApplicationResultRef` 必须指向 `OperationResultRepository` 中同 UoW 保存的 stored result / receipt,用于 duplicate replay。

Command key 来自 `CommandMetadata.idempotency_key`;Event key 来自 envelope `EventMetadata.dedup_key`;Job key 来自 `JobMetadata.job_idempotency_key`。Query 无幂等键。

Canonical digest v1 rules:

- 使用 deterministic field ordering 和稳定 enum variant names。
- Include `ProcessIdempotencyOperation`。
- Exclude volatile metadata:`request_ref`、`event_envelope_ref`、`job_run_ref`、`trace_context`、`requested_at`、transport retry counter 和 adapter delivery attempt count。
- Include 会影响语义的 actor / authority / source / typed payload 字段;`expected_version` 只在 Step 8 command expected-version matrix 允许或要求时进入 digest,forbidden command 携带该字段必须先被 request validation reject。
- Never hash or store forbidden source body。

| 情况 | 结果 |
|---|---|
| same operation + same key + same digest + completed | 返回 stored result / receipt,不重放 domain / resolver / publisher / handoff / projection |
| same operation + same key + different digest | conflict |
| completed but result missing | result missing error,manual repair,不得重算 |
| job partial rerun intentionally | 必须使用新 `JobIdempotencyKey` |
| publish per-record retry | 通过 outbox state 和 record version 控制 |

## 13. 配置引用与外部依赖绑定

配置不得改变 Process truth 归属、外部正文排除、metadata / idempotency 必填、核心 audit / outbox、query no-write、projection 不反写、state matrix 和唯一编译期依赖纪律。违反这些边界的配置必须在 validation 阶段 reject。

## 14. 可观测性与审计埋点契约

> 校准来源:
> - `design-calibration/03_ddd_step_15_observability_audit.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“日志埋点表”“指标埋点表”“审计事件表”“Trace / span cut table”和“Redaction / forbidden-field table”小节。

可观测性契约只定义代码必须暴露的日志、指标、trace 和审计切口,不定义告警阈值、dashboard、日志采集系统、保留周期或运维处置流程。

accepted Process truth change 必须写 `ProcessTraceRecord`、更新 `ProcessAuditTrail` 或 audit ref、enqueue `ProcessOutboxRecord`,并记录 structured log / metric。invalid request、domain reject、not visible、not found、idempotency conflict、repository conflict、external resolver failure 不写 business success trace / outbox,只记录日志和指标。Query 是只读入口,不得写 audit、outbox、idempotency、freshness marker 或 reference state。

日志必须使用 operation kind、request / event / job ref、actor / source actor ref、trace context、subject ref、result / error ref、state / disposition、dependency ref 和 count 等字段。指标只允许 low-cardinality 标签,如 `operation_group`、`result`、`event_kind`、`job_kind`、`repository`、`error_kind`。审计材料只保存 stable refs、state transition、reason 和 marker refs,不得保存外部正文、raw payload、secret、token、credential、observability ledger body 或 archive package body。

### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 process 的接口可调用,而是系统验证 `L1-process` 是否真正满足“项目过程节奏与运行实例真相层”的设计要求,尤其要证明以下几点成立:
- `Template / Profile / ProcessInstance` 三层结构边界成立
- `planning / refinement / review / retro / gate` 只是节奏时机,不越界写入 work 真相
- `waiting_gate / checkpoint / recovery` 形成独立可恢复闭环
- timeline / trace / progress summary 是只读投影,不反写真相
- process 不接管 governance 决策真相、artifact 正文真相、runtime 执行正文真相
- timing signal、checkpoint、recovery 和 projection 都能在运行主线中正确协同

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| Template / Profile | 真相对象 | P0 | 模板同步、裁剪、冻结与 drift |
| ProcessInstance / Activity / Token | 真相对象 | P0 | 实例启动、推进、状态迁移 |
| timing node / timing signal | 节奏触发 | P0 | planning/review/gate 等外部信号 |
| waiting_gate / checkpoint / recovery | 恢复能力 | P0 | suspend → resume / recover 闭环 |
| timeline / trace / progress summary | 读模型 | P0 | 只读展示与最终一致 |
| work 接缝 | 跨仓边界 | P1 | process 只发时机,不写真相 |
| governance 接缝 | 跨仓边界 | P1 | gate request / decision / resume |
| artifact 接缝 | 跨仓边界 | P1 | outputs / baseline refs |
| runtime 内部执行正文 | 非范围 | P2 | 只验证 feedback / retry / resume 接缝 |
| 前端视觉细节 | 非范围 | P2 | 不在本次仓级测试范围内 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和规则不变量 | domain / policy owner | `ProcessInstance::start`、`TimingPolicy`、`ProcessRecovery`、`Profile.freeze` | 状态与边界符合设计 |
| 集成测试 | 验证 service + repo + checkpoint + projection 联动 | backend / domain owner | StartProcessInstance、AdvanceActivity、WriteCheckpoint、RecoverInstance | 真相写入、状态切换、恢复链都成立 |
| 事件链测试 | 验证跨仓 timing / gate / output 事件流 | integration / platform owner | planning timing、gate entry、checkpoint written | 输入事件被正确消费,输出语义正确 |
| 恢复专项测试 | 验证 suspend / resume / recovery 闭环 | architecture / QA | waiting_gate、checkpoint restore、recovery failure | 恢复链不漂移 |
| 投影一致性测试 | 验证 timeline / trace / summary 与真相一致 | backend / QA | projection rebuild、stale projection、只读门禁 | 投影不反写真相 |
| 端到端主线测试 | 验证最小可运行闭环 | QA / owner | Template → Profile → Instance → timing → checkpoint → recover → timeline | 主干场景完整跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| frozen Profile 才能启动实例 | BindProfile → StartProcessInstance | 集成测试 | 是 | profile state / instance state |
| ProcessInstance/Activity/Token 构成运行态真相 | StartProcessInstance / AdvanceActivity | 集成测试 | 是 | DB / state history |
| planning timing 只提供时机不写真相 | EmitTimingSignal → work consume | 事件链测试 | 是 | timing event / no work write |
| waiting_gate 前必须写 checkpoint | EnterWaitingGate / WriteCheckpoint | 集成测试 | 是 | checkpoint record / suspended state |
| RecoverInstance 能恢复 token / activity 状态 | checkpoint restore | 恢复专项测试 | 是 | restored instance snapshot |
| projection 只读 | GetProcessTimeline / summary query | 投影一致性测试 | 是 | query trace / no write side effect |
| process 不接管 governance / artifact / runtime 正文 | gate / output / feedback 边界测试 | 边界专项测试 | 是 | ref-only / no body merge |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地运行与恢复链验证 | local DB / fake event bus | debug logs / replay enabled | 容易只测 happy path |
| test | CI / 集成测试 | test DB / controlled event bus | deterministic snapshots / isolated tables | 跨仓事件顺序不稳定 |
| staging | 端到端主线演练 | real-like governance / work / runtime / artifact | checkpoint persistence / event replay | suspend / resume 延迟放大 |

## 5. 测试数据设计

| 数据类型 | 来源 | 用途 | 隔离方式 |
|---|---|---|---|
| Template / Profile 样本 | fixture | 验证 sync / freeze / drift | 按 template_id/version 隔离 |
| ProcessInstance / Activity / Token 样本 | builder | 验证运行态推进 | 每用例独立 instance |
| waiting_gate / checkpoint 样本 | fixture + runtime hook | 验证 suspend / resume / recover | 独立 checkpoint_id |
| governance decision 事件样本 | event fixture | 验证 resume | 隔离 gate_ref / event id |
| timing signal 样本 | event fixture | 验证 work / governance / artifact / runtime 接缝 | topic + idempotency key 隔离 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | 模板同步与 drift 记录 | method-library 有模板源 | SyncTemplateIndex | Template 落库且 fingerprint 可追踪 |
| TC-002 | Profile 冻结后启动实例 | template 已同步 | BindProcessProfile → StartProcessInstance | ProcessInstance 进入 running 且 initial token 创建 |
| TC-003 | 未冻结 Profile 拒绝启动实例 | profile=frozen false | StartProcessInstance | 返回 `PROCESS_PROFILE_NOT_FROZEN` |
| TC-004 | Activity 推进与 token 移动 | running instance 已存在 | AdvanceActivity | Activity 状态推进,token 移到下个节点 |
| TC-005 | planning timing 正确发出 | 运行到 planning 节点 | EmitTimingSignal | 发出 planning_timing,不写真相 |
| TC-006 | 进入 waiting_gate 前写 checkpoint | gate entry reached | WriteCheckpoint → suspend_for_gate | checkpoint 落库,instance 转 suspended |
| TC-007 | governance 决策后恢复实例 | waiting_gate 已存在 | RecoverInstance / resume | token / activity 恢复,instance 回 running |
| TC-008 | checkpoint 不存在时恢复失败 | checkpoint 缺失 | RecoverInstance | 返回 `PROCESS_CHECKPOINT_NOT_FOUND` |
| TC-009 | timeline / trace / summary 只读可重建 | instance 有推进与恢复记录 | GetProcessTimeline | projection 正确,无真相写入副作用 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | 恢复链断裂 / projection 反写真相 / process 接管外部真相 | 阻断放行,必须修复 |
| A | 主线可跑但 checkpoint / trace / timing 信号不稳 | 原则上修复后再放行 |
| B | 非关键投影延迟或低优先级场景异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 ProcessInstance / Activity / Token 推进逻辑,都必须回归最小可运行闭环
- 每次改动 waiting_gate / checkpoint / recovery 逻辑,都必须回归 suspend-resume 链
- 每次改动 timeline / trace / summary 投影逻辑,都必须回归只读一致性

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| GUIDED / Deviation 后续若纳入,测试矩阵需扩展 | 节奏节点与 profile 相关测试需迭代更新 | TL / 架构 |
| runtime / governance 外部实现差异可能影响 staging 行为 | 恢复链测试需持续补回归样本 | Owner / TL |

## 2. 验收目标与范围

> 校准来源:
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解 P0/P1/P2 验收边界如何收敛。

本轮验收的核心目标是裁决 `L1-process` 是否能作为过程执行事实真相仓成立。

| 验收目标 | 优先级 | 裁决说明 | 主要证据入口 |
|---|---|---|---|
| 核心闭环成立 | P0 | C-1~C-5 必须全部成立 | `EV-E2E-001`;`EV-SERVICE-*`;`EV-DOMAIN-001` |
| 功能需求成立 | P0 | `FR-PROC-001`~`008` 必须可被正式接口、状态和证据支撑 | `TC-PROC-CMD-*`;`TC-PROC-EVENT-*`;`TC-PROC-E2E-001` |
| 规则 / 边界成立 | P0 | `BR-PROC-001`~`032` 的不变量、禁止行为、显式变化、相邻仓边界、治理和审计约束成立 | `EV-SERVICE-*`;`EV-INTEGRATION-*`;`EV-SCRIPT-*` |
| 数据归属成立 | P0 | Process truth、外部快照、外部引用和禁止正文边界成立 | `EV-DOMAIN-001`;`EV-SCRIPT-001`;redaction report |
| 详细设计契约可验 | P0 | 协议、对象、状态、事务、错误、幂等、观测契约能被测试覆盖 | `EV-CONTRACT-001`;`EV-DOMAIN-001`;`EV-SERVICE-*` |
| 配置红线成立 | P0 | P0 profile、strict config、source priority、sensitive、fail-fast / marker 成立 | `EV-INTEGRATION-002`;`EV-SCRIPT-001` |
| 证据可复核 | P0 | `EV / TC / AC / design_contract_refs` 可追溯,路径固定且无 `latest` | `reports/runs/<run_id>/evidence-index.md` |
| controlled integration seams | P1 | 真实或半真实接缝选测,失败进入风险 | `EV-E2E-002` |
| production-like 和容量专项 | P2 | 当前只记录,不裁决 | 后续专项 |

P0 是当前硬验收范围。P1 只覆盖 controlled integration seams 和 selected runs。P2 的 production-like deployment、remote config、hot reload、容量模型、完整 BPMN / 嵌套过程、完整 operations runbook 不进入当前硬验收。

## 6. 数据边界与架构红线验收

> 校准来源:
> - `design-calibration/06_acceptance_step_06_data_architecture_redline.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解数据归属和架构红线如何收敛。

本章裁决 `L1-process` 是否仍然是过程执行事实真相仓。红线失败不得被风险接受覆盖。

| 红线 ID | 红线 | 通过条件 | 失败条件 | 证据来源 | 一票否决候选 |
|---|---|---|---|---|---|
| `RL-PROC-DATA-001` | Process truth ownership | RuntimeProcessShape、ProcessProfile、ProcessInstance、Activity、Token / Gateway、waiting gate、checkpoint / recovery、stage / timebox binding、trace / audit 归 Process | Process truth 缺失、转交外仓拥有或被外部事件直接定义 | `EV-SERVICE-001`;`EV-DOMAIN-001` | 是,`VF-PROC-001` |
| `RL-PROC-DATA-002` | 外部正文禁止入仓 | method / work / governance / artifact / runtime / identity / conversation / workspace / observability / archive 正文均不保存 | 任一外部正文、raw payload、source body 或 runtime execution body 入仓 / 入 report | `EV-SCRIPT-001`;`EV-INTEGRATION-002` | 是,`VF-PROC-002`;`VF-PROC-005` |
| `RL-PROC-ARCH-001` | Process / Work / Runtime 分离 | Activity、Token、Gateway 只表达过程节点与流控位置 | Activity / Token / Gateway 被直接视为 Project、WorkItem、Iteration 或 runtime step truth | `EV-DOMAIN-001`;`EV-E2E-001` | 是,`VF-PROC-003` |
| `RL-PROC-ARCH-002` | Process / Governance 分离 | waiting gate / pause context 只保存 Process 等待语境和治理引用 | waiting gate 或 pause context 被写成 governance Gate / Policy / decision truth | `EV-INTEGRATION-001`;`EV-WORKER-001` | 是,`VF-PROC-004` |
| `RL-PROC-ARCH-003` | Query / projection / report / maintenance no-write | Query、projection、report、reconciliation、recovery maintenance 和 operations job 不隐式推进过程事实 | 任一消费 / 维护入口创建、推进、暂停、恢复或完成 Process truth | `EV-SERVICE-002`;`EV-JOB-001` | 是,`VF-PROC-006` |
| `RL-PROC-ARCH-004` | 恢复连续性 | commit unknown、checkpoint、recovery attempt 只能延续同一过程事实 | 恢复产生第二份过程真相或关键变化不可追溯 | `EV-INTEGRATION-001`;`EV-SERVICE-004` | 是,`VF-PROC-007` |
| `RL-PROC-ARCH-005` | 唯一编译期上游 | 编译期只依赖 `L0-core` / core contracts | bus 或其他 L1 / L2 / L3 / L4 仓成为 package dependency | dependency scan;`EV-SCRIPT-002` | 是,`VF-PROC-008` |

## 8. 状态机、事务与一致性验收

| 验收项 ID | 主题 | 通过条件 | 失败条件 | 证据来源 |
|---|---|---|---|---|
| `ST-PROC-STATE-001` | 16 组状态机 | 11 组核心 truth 状态和 5 组派生 / 引用 / 发布 / handoff / report 状态按正式 enum 推进 | 使用旧状态名、临时状态或未定义 variant | `TC-PROC-STATE-001~016`;`EV-DOMAIN-001` |

| `ST-PROC-TX-002` | Reject / rollback | metadata reject、domain reject、policy reject、version conflict、idempotency conflict 后无 accepted side effect | reject path 写入 accepted truth、business trace、outbox 或 projection marker | `TC-PROC-TX-001`;`EV-SERVICE-003` |
| `ST-PROC-QUERY-001` | Query no-write | 11 Query 在 hit / missing / not visible / degraded / stale / failed / rebuilding 时均不写状态 | Query 写 truth、audit、outbox、idempotency、projection state 或触发 rebuild | `TC-PROC-QUERY-001~011`;`EV-SERVICE-002` |
| `ST-PROC-JOB-001` | Job no truth repair | Operations job 只写允许的 marker、report、projection 或 publication state | Job 自动修复 ProcessProfile、ProcessInstance、Activity、Token、WaitingGate 或 RecoveryAttempt truth | `TC-PROC-JOB-001~007`;`EV-JOB-001` |
| `ST-PROC-IDEM-001` | Command duplicate replay | same key + same digest + completed 通过 `OperationResultRepository` 返回 stored result | duplicate 重放 domain transition 或创建第二正式事实 | `TC-PROC-IDEMP-001~003`;`EV-SERVICE-004` |
| `ST-PROC-IDEM-002` | Idempotency conflict | same key + different digest 返回 conflict,无业务副作用 | different digest 被 accepted 或覆盖原 result | `TC-PROC-IDEMP-001~003`;`EV-SERVICE-004` |

## 10. 可观测性、审计与证据门禁

## 12. 缺陷分级、复验与放行规则

| 级别 | 定义 | 放行规则 | 复验要求 |
|---|---|---|---|

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L1-process` 的第一批核心设计主线展开。当前 `02-概要设计.md` 与 `03-详细设计.md` 已经明确:
- `L1-process` 是项目过程节奏与运行实例真相层
- `Template / Profile / ProcessInstance` 三段式是稳定骨架
- planning / review / retro / gate 只是节奏节点,不是工作事实真相写入点
- waiting_gate / checkpoint / recovery 构成独立恢复能力链
- timeline / trace / progress summary 是只读投影,不反写真相
- process 不接管 governance 决策真相、artifact 正文真相、runtime 执行正文真相

因此,本次验收的目的不是笼统判断“流程能不能跑”,而是判断 process 的定义层、运行态、节奏层、恢复层和投影层是否真的边界清晰、运行闭环成立、可进入下一阶段。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 过程定义与裁剪部分 | 是 | Template / Profile 的同步、裁剪与冻结 |
| 过程实例运行部分 | 是 | ProcessInstance / Activity / Token 启动与推进 |
| 节奏节点管理部分 | 是 | planning / review / retro / gate 时机触发 |
| 挂起与恢复部分 | 是 | waiting_gate / checkpoint / recovery 闭环 |
| 协作视图与投影部分 | 是 | timeline / trace / progress summary 只读投影 |
| work 接缝 | 是 | process 只提供时机,不写 work 真相 |
| governance 接缝 | 是 | gate request / decision / resume |
| artifact 接缝 | 是 | outputs / baseline refs |
| runtime 内部执行正文 | 否 | 只验 feedback / retry / resume 接缝,不验内部执行细节 |
| 前端视觉细节 | 否 | 不在本次仓级验收范围内 |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | 恢复链断裂 / projection 反写真相 / process 接管 work/governance/artifact/runtime 正文真相 |
| A | 视情况 | 主线可跑但 checkpoint / trace / timing signal 不稳 |
| B | 可带着走 | 非关键投影延迟或低优先级场景异常 |

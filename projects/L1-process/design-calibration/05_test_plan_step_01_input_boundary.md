## 3. SOP 问题回答

1. 当前测试方案要承接哪些需求、规则和非功能目标?

   回答:承接 `L1-process` 作为 Process truth center 的仓定位,重点验证 runtime shape / profile / instance / activity / gate / checkpoint / recovery / rhythm / projection / outbox / trace / archive 等对象和协议是否按设计闭环;验证数据归属、外部正文排除、幂等、事务一致性、错误恢复、配置安全和证据可追溯。

2. 哪些概要 / 详细设计章节直接影响测试对象?

   回答:`03-详细设计.md` §3~§15 全部直接影响测试对象,其中 §5 模块、§6 对象、§7 协议、§8 函数流、§9 状态机、§10 事务、§11 错误恢复、§12 幂等并发、§13 配置绑定、§14 观测审计、§15 测试切口是 `05` 的直接输入。

3. 哪些验收项需要测试方案提供证据?

   回答:P0 主链、字段 / DTO / 状态闭环、no-write query、duplicate replay、outbox publish、inbound quarantine / delayed、job partial failure、redaction、config validation、forbidden dependency、report generation 和 evidence index 均需要提供证据。正式 AC 编号等待新版 `06-验收标准.md` 重建后回填。

4. 哪些内容不应在测试方案中重新定义?

   回答:`05` 不重新定义需求、对象字段、DTO schema、trait、adapter、状态机、错误 enum、配置字段、生产拓扑、实施批次或验收裁决。测试方案只定义如何验证这些既有契约,以及证据如何交给 `06`。

5. 当前上游是否存在会阻塞测试设计的缺口?

   回答:当前 `03/04` 已足以生成测试方案。唯一未闭合的是新版 `06/07` 尚未同步,因此 `05` 中验收引用只能使用待定 AC 占位口径,不阻塞测试方案重建。

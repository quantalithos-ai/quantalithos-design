## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 的用户并不是直接管理一堆孤立的 Agent,而是管理**项目(Project)**。项目包含:
- 成员(ProjectMember)
- 任务(WorkItem)
- 待办池(Backlog)
- 迭代(Iteration)
- tool_scope / policy_overrides / context_of_use 等项目语义

work 域是整个系统的业务主干。没有它:
- 对话无法知道"在聊哪个项目"
- 过程无法知道"哪个 Project 在走哪个 Template"
- 治理无法知道"Gate 属于哪个项目"
- 制品无法知道"Artifact 属于哪个 WorkItem / Project"

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `domain/work/README.md` 1776 行 | 设计已完整,仓级需求层未显式化 |
| 双层 Member | ADR-0004 已锁 | 代码未验证 role/tool_scope/生命周期同步 |
| Backlog / Iteration | 语义已澄清 | 批次实施前缺仓级目标与验收口径 |
| WorkItem DAG | 设计支持 depends_on / blocks | 复杂依赖场景尚未实现验证 |
| completion_policy | ADR-0008 已定 | Activity 和 WorkItem 两轨交汇点需要真实样例验证 |

### 2.3 为什么要做(量化依据)

- Project 是 SoI,没有 work 域,系统就没有“项目”这一核心业务对象
- 10w 项目 × 50 WorkItem = 500w 活跃 WorkItem,需要明确的仓级性能和演化目标
- conversation / process / governance / artifact / archive 五仓都直接依赖 work 事件或 RPC

### 2.4 业务问题 vs 技术问题

- **业务问题**:如何让用户管理项目、成员、任务、迭代,并将软件工程实践落到系统里
- **技术问题**:双层 Member 边界、WorkItem DAG、一致性、与 process/governance/artifact 的事件交织

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 用户立项并启动 Project
2. Owner/PM 在 Backlog 中维护 WorkItem
3. Backlog 先作为空池创建,Owner/PM 在 Backlog 中维护 WorkItem
4. 创建 Iteration,把 WorkItem 从 Backlog 拉入 Sprint
5. 分配 ProjectMember,更新 tool_scope / policy_overrides
6. 收到 process / artifact / governance 事件后联动更新

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **Owner**,我想要 **创建一个项目并选 process profile**,以便 **启动完整的软件交付流程** |
| 优先级 | P0 |
| 验收条件 | **Given** 提供项目基本信息 + active process profile **When** 调用 CreateProject / StartProject **Then** 创建 Project,state=active 并发 `work.project.started` |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **项目成员**,我想要 **在 Backlog 中看到所有待办并能按优先级排序**,以便 **决定下一步做什么** |
| 优先级 | P0 |
| 验收条件 | **Given** backlog 有 10 个 WorkItem **When** 调用 GetBacklog **Then** 返回按 priority 排序的列表 |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **Scrum 团队**,我想要 **创建 Iteration 并把 WorkItem 拉进去**,以便 **形成本 Sprint 的承诺子集** |
| 优先级 | P0 |
| 验收条件 | **Given** 6 个 backlog 项 **When** DraftIteration + StartIteration **Then** 6 个 WorkItem 出现在 `planned_workitems` |

| 字段 | 内容 |
|---|---|
| ID | US-004 |

| 优先级 | P1 |

|---|---|
| ID | US-005 |

## 6. 功能需求

### 6.1 功能清单与优先级

| ID | 功能名称 | 优先级 | 依赖 | 描述 |
|---|---|---|---|---|
| F-001 | Project CRUD | P0 | — | draft / active / paused / archived / dissolved |
| F-002 | ProjectMember 管理 | P0 | identity | assign / activate / pause / resume / retire |
| F-003 | Backlog 管理 | P0 | — | ordered_workitems, refinement |
| F-004 | WorkItem CRUD | P0 | — | story / task / bug / prototype / spike / review / nfr |
| F-005 | WorkItem 依赖 DAG | P0 | F-004 | depends_on / blocks,无环 |
| F-006 | Iteration / Sprint | P0 | F-003 / F-004 | planned / in_progress / closed / retrospective |
| F-007 | tool_scope / policy_overrides | P1 | F-002 | 29110 Profile 语义 |
| F-008 | GetProjectBoard 看板 | P0 | F-004 | Kanban 视图 / 依赖图 |
| F-009 | artifact 关联 | P0 | artifact 事件 | WorkItem.done 判据 |
| F-010 | process 事件联动 | P0 | process | project.started / activity.completed 等 |
| F-011 | kickoff / archive Gate 联动 | P0 | governance | draft→active / active→archived |
| F-012 | dissolved / restore 流程 | P1 | archive | 生命周期收口 |

### 6.2 业务规则表

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-001 | `state=done` | related_artifacts 中必须有 ≥1 个 approved Artifact |
| BR-002 | WorkItem 依赖图形成环 | 拒绝写入 |
| BR-003 | Project.dissolved | 单向,不可恢复 |
| BR-004 | ProjectMember 对应 GlobalMember paused | 本仓 ProjectMember 自动 paused |
| BR-005 | Project active | 必须绑定 active ProcessProfile / ProcessInstance |
| BR-006 | Backlog 初始化 | 可以为空池,不要求创建时已有 WorkItem |
| BR-007 | Sprint/Iteration 规划 | 从 Backlog 选择 WorkItem 形成 `planned_workitems`,不创建 Backlog |
| BR-008 | Iteration.started | `planned_workitems` 冻结(默认不再改) |
| BR-009 | tool_scope 超出 Role 默认 | 必须有 evidence + Policy 允许 |

### 6.3 功能依赖图

```
Project
  ├─▶ ProjectMember
  ├─▶ Backlog
  │      └─▶ WorkItem
  │             └─▶ depends_on / blocks (DAG)
  ├─▶ Iteration(planned_workitems / actual / spillover)
  ├─▶ process_profile_id / process_instance_id
  ├─▶ gate decisions(kickoff / archive)
  └─▶ artifact refs / baseline_ids
```

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 聚合 / 类型 | 生命周期 |
|---|---|---|
| Project | 聚合根 | draft → active → paused → archived / dissolved |
| ProjectMember | 聚合内实体 | assigned → active / paused / retired_from_project |
| Backlog | 聚合 / 实体 | 常驻 |
| WorkItem | 聚合根 | todo → in_progress → blocked / in_review → done |
| Iteration | 聚合根 | planned → in_progress → closed |

### 9.2 数据关系

```
Project
  ├─ members[] (ProjectMember)
  ├─ backlog (Backlog)
  │    └─ workitems[] (WorkItem)
  ├─ iterations[] (Iteration)
  ├─ process_profile_id
  └─ process_instance_id
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| active project | 热存 | 活跃 |
| archived project | 冷存可恢复 | archive |
| dissolved project | 归档后不可恢复 | archive + hard policy |
| WorkItem history | 永久(默认) | 归档时保留 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| WorkItem DAG 查询成本高 | 中 | 中 | 递归 CTE + 索引 |
| done 判据和 artifact 事件延迟 | 中 | 高 | 最终一致 + 重放 |

### 12.2 边缘风险

- 多 owner 语义不清
- project restore 后 process 对齐复杂
- 跨项目依赖需求增长

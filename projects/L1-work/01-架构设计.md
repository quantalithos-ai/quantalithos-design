## 2. 业务背景与驱动力

> 校准来源:
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解业务驱动力和架构目标如何从需求边界收敛而来。

Quantalithos 的协作对象最终需要落在可追溯的软件项目上,但项目工作事实不能散落在 conversation、process、runtime、artifact 或 workspace 的局部视图中。随着 `L0-core`、`L0-bus`、`L0-sdk`、`L1-identity`、`L1-conversation` 和 `L3-method-library` 已经稳定,`L1-work` 需要在架构层把 Project、ProjectMember、Backlog、WorkItem、child WorkItem、Iteration 和 formalize / promote 边界收束为独立项目工作事实真相。

| 架构目标 | 说明 |
|---|---|
| 承载独立的项目工作事实真相边界 | 避免项目退化为对话主题、流程实例、执行上下文或 workspace 视图。 |
| 支撑核心 Work 能力闭环完整成立 | 项目主语、成员承担、正式工作全集、承诺子集和追溯消费必须共同成立。 |
| 稳定区分真相数据、快照数据、引用数据和派生视图 | 防止相邻仓正文和辅助结果混入 Work 真相。 |
| 守住 ProjectMember 与 GlobalMember 生命周期边界 | Work 只表达项目内承担事实,不接管身份仓生命周期。 |
| 守住 Backlog 与个人执行步骤 / 对话建议 / runtime plan item 的边界 | 正式工作全集不得被非协作级步骤污染。 |
| 允许 ImplementationPlan 来源通过显式 formalize / promote 升级 | Work 可承接正式升级结果,但不拥有 ImplementationPlan 正文或执行推进。 |
| 让查询、看板、投影和维护报告只能从真相派生 | 消费增强能力不得成为新的业务写源。 |
| 保留关键变化的追溯接缝 | 项目、成员承担、工作拆分、承诺范围和完成依据必须可复盘。 |

## 3. 约束条件

> 校准来源:
> - `design-calibration/01_arch_step_01_requirement_baseline.md`
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解约束条件如何从需求基线和目标取舍收敛而来。

### 3.1 不可变约束

| 约束 | 说明 |
|---|---|
| 不允许 Work 拥有 GlobalMember、Role、Actor 生命周期或身份正文 | `L1-identity` / `L0-core` 保持身份和 actor 主体职责。 |
| 不允许 conversation 正文、聊天消息或 UI 动作直接成为 Work 真相 | 对话来源必须通过 formalize / promote 或引用边界进入。 |
| 不允许 method-library 定义正文进入 Work 真相 | Work 只消费任务、产物、流程模板和视图定义引用。 |
| 不允许 process planning、review 或 Activity 推进直接维护 Backlog 真相 | 流程节奏只能作为外部输入或引用。 |
| 不允许 governance / artifact / workspace / runtime 反向持有或改写 Work 正式任务真相 | 外部仓只能通过正式边界协作。 |
| 不允许 query、projection、对账或 report generation 写业务真相 | 派生和维护能力不得成为隐藏写源。 |
| 不允许除 `L0-core` 外形成编译期依赖 | 其他仓通过运行期、引用、快照或事件协作进入。 |
| 不允许关键变化不可追溯 | 项目工作事实必须支撑审计、复盘和责任解释。 |

### 3.2 当前阶段取舍

高级看板、多视图展示、自动解除阻塞、自动 spillover、自动维护建议、容量趋势、跨项目依赖理解和旧性能 / 容量指标均不作为当前核心 truth 成立条件。它们可以作为派生消费、后台承接、演进路线或后续测试 / 验收输入继续收敛。

### 3.3 架构非目标

本文不设计 Identity 生命周期、Conversation truth、Method Library 定义、Process 执行、Governance 裁决、Artifact 正文和证据链、Runtime 执行推进、Workspace 聚合视图、全局 Observability 日志或 Archive 长期归档主体架构。

## 4. 职责边界

> 校准来源:
> - `design-calibration/01_arch_step_03_responsibility_boundary.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解职责边界和边界红线如何收敛。

| 分类 | 内容 |
|---|---|
| 做 | Work 真相边界;Project;ProjectMember;Backlog / WorkItem / child WorkItem;依赖阻塞;Iteration;formalize / promote;授权消费与追溯;派生辅助 |
| 不做 | Identity 生命周期;Conversation truth / Chat UI;Method definition;Process execution;Governance decision;Artifact / evidence / ImplementationPlan body;Runtime execution;Workspace aggregation;Archive / Observability 主体 |

`L1-work` 的核心职责是承载项目工作事实真相。它维护 Project 正式项目锚点、ProjectMember 项目内承担事实、Backlog / WorkItem / child WorkItem 正式工作全集、工作依赖和阻塞解释、Iteration 承诺子集、formalize / promote 后结果以及项目工作事实消费和追溯基础。

易混淆职责必须按以下口径隔离:

- Project 不等同于 workspace project view、process instance、runtime context 或 conversation topic。
- ProjectMember 是项目内承担事实,不等同于 GlobalMember 生命周期。
- WorkItem / child WorkItem 是协作级正式工作,不等同于个人 checklist、PlanItem、tool step 或 chat suggestion。
- Iteration 是 Work 正式工作全集中的承诺子集,不由 process planning 直接维护。
- 完成依据可以保存引用或摘要,但 evidence body 不归 Work。
- 派生视图、看板、任务摘要、对账和维护报告只能从 Work 真相派生,不得反写。

## 6. 限界上下文与子域划分

> 校准来源:
> - `design-calibration/01_arch_step_05_bounded_context_subdomains.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解子域划分、本地影子层和统一语言如何收敛。

| 名称 | 类型 | 作用 |
|---|---|---|
| 项目工作事实真相核心 | 核心子域 | 承载本仓成立所需的项目工作事实统一语义。 |
| 项目主语上下文 | 支撑子域 | 承载软件项目成为正式工作对象的项目锚点语义。 |
| 项目成员承担上下文 | 支撑子域 | 承载 GlobalMember 在项目内承担工作的正式语义。 |
| 正式工作全集上下文 | 支撑子域 | 承载 Backlog 和协作级正式工作全集的收束语义。 |
| 工作拆分与升级边界上下文 | 支撑子域 | 承载正式 child WorkItem 与外部计划步骤之间的 formalize / promote 边界。 |
| 工作依赖与阻塞上下文 | 支撑子域 | 承载正式工作之间依赖、阻塞和解除依据的协作语义。 |
| Iteration 承诺子集上下文 | 支撑子域 | 承载从正式工作全集中选择当前承诺范围的语义。 |
| 项目工作事实消费与追溯上下文 | 支撑子域 | 承载成员、审计者和相邻仓理解同一份 Work 真相的语义。 |
| 派生消费辅助上下文 | 支撑子域 | 承载看板、投影、索引、对账和维护报告等辅助消费语义。 |
| 本地索引 / 投影 / 引用层 | 本地影子层 | 承载成员、定义、来源、依据、消费投影和交接引用,但不拥有外部正文。 |

Project、ProjectMember、Backlog、WorkItem、child WorkItem 和 Iteration 不拆成多个核心 truth center,而是共同归入一个项目工作事实真相核心。看板、投影、任务摘要、对账和维护报告属于派生消费辅助,只能从核心真相派生。

## 8. 依赖方向与层间约束

> 校准来源:
> - `design-calibration/01_arch_step_07_dependency_direction.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解依赖方向、跨仓裁剪和禁止依赖如何收敛。

| 依赖类型 | 关联项目 | 本仓如何使用 / 提供能力 |
|---|---|---|
| 编译期依赖 | `L0-core` | 使用共享 ID、ActorRef、TraceContext、Error、CloudEvents、metadata 和通用契约。 |
| 事件协作 / 追溯交接依赖 | `L0-bus`、`L1-conversation`、`L2-member-service`、`L4-observability`、`L4-archive` | 传播或消费项目工作事实变化、成员承担变化、trace / audit 材料和 archive handoff 材料。 |
| 运行期依赖 | `L1-identity`、`L3-method-library`、`L1-process`、`L1-governance`、`L1-artifact`、`L2-runtime` | 运行时消费成员、定义、流程节奏、治理结论、证据依据和执行推进边界。 |
| 下游消费 / 运行期提供 | `L0-sdk`、`L1-workspace`、`L4-archive`、`L5` / `L6` 经正式边界 | 提供项目工作事实能力、快照来源或 export 来源。 |

`L0-core` 是 `L1-work` 当前唯一编译期依赖。`L0-bus` 是事件协作依赖,不得因事件协作关系写成 Work 业务核心源码依赖。`L1-identity`、`L1-conversation`、`L3-method-library`、`L1-process`、`L1-governance`、`L1-artifact`、`L2-runtime`、`L1-workspace` 等都不能作为 `L1-work` 编译期业务依赖。

`L4-archive` 在架构中允许双角色出现:archive handoff / 归档完成回链属于事件协作 / 追溯交接;snapshot / export 消费属于下游消费 / 运行期提供。`L4-observability` 只作为 trace、audit、维护状态的消费和交接目标出现,不得反向定义 Work truth 或作为运行期上游来源。

内部依赖方向以核心语义为中心:外部能力接缝和编排 / 承接角色必须服从 Work 核心语义;派生消费辅助只能依赖核心事实和派生规则;技术承载角色不得定义业务状态、成员承担、formalize / promote、Iteration 承诺或完成依据含义。

## 9. 数据所有权与一致性策略

> 校准来源:
> - `design-calibration/01_arch_step_08_data_ownership_consistency.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解数据归属、一致性策略和数据边界如何收敛。

| 数据类型 | 数据项 | 归属说明 |
|---|---|---|
| 正式真相数据 | Project、ProjectMember、Backlog 正式工作全集、WorkItem、child WorkItem、工作依赖 / 阻塞关系、Iteration 承诺子集、promote 结果与来源引用关系、工作事实审计 / 追溯记录 | 由 `L1-work` 拥有项目工作事实真相。 |
| 快照 / 投影数据 | ProjectMember 可承担性快照、方法定义目录级快照、planning / review / timing 摘要、治理结论摘要、完成依据摘要、promote 来源摘要、conversation context 摘要、消费视图 / 看板 / 任务摘要 | 为判断、降级解释、稳定消费和派生展示服务,不得转移来源 truth。 |
| 引用关系数据 | GlobalMemberRef / ActorRef、方法定义 Ref、process Ref、governance Ref、artifact / evidence / baseline Ref、ImplementationPlanRef / PlanItemRef、conversation / trace / handoff Ref、runtime / archive Ref | 只保存引用关系,引用存在不代表正文归属转移。 |
| 明确不拥有的正文 / 真相 | identity 正文、conversation 正文、method-library 定义正文、process 正文、governance 正文、artifact / evidence / baseline / ImplementationPlan 正文、runtime 执行正文、workspace 聚合正文、observability 全局日志正文、archive 长期归档包正文 | 本仓不得吸收为正式真相。 |

核心正式真相之间保持强一致:Project 与 ProjectMember / Backlog / WorkItem / Iteration 的归属、正式工作全集、工作依赖 / 阻塞、Iteration 承诺子集、promote 来源与正式结果必须在同步边界明确成立、失败、拒绝或挂起。外部快照、引用解析、Work 事实传播、派生视图、对账材料、观测和归档交接可以最终一致,但必须暴露旧快照、未解析、待刷新、过期、待重建、未消费或待交接等状态。

## 10. 关键交互与通信方式

> 校准来源:
> - `design-calibration/01_arch_step_09_interactions_communication.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解关键交互、通信方式和失败口径如何收敛。

| 交互场景 | 推荐通信方式 | 失败处理口径 |
|---|---|---|
| 项目主语与成员承担变更 | 同步请求 / 响应类交互 | 明确失败、拒绝或暂不可处理,不得先返回已成立。 |
| 正式工作全集变更 | 同步请求 / 响应类交互 | 明确失败或保持未成立状态,不得落为部分正式工作。 |
| 正式拆分与 promote | 同步请求 / 响应类交互 | 来源不可接受时拒绝或保持待 formalize,不得吸收来源正文。 |
| 依赖阻塞与完成依据判断 | 同步请求 / 响应类交互 | 引用不可解析或依据不足时保持未满足、待处理或拒绝。 |
| Iteration 承诺范围变更 | 同步请求 / 响应类交互 | 候选不合法时拒绝或保持原承诺范围。 |
| 项目工作事实查询与追溯读取 | 同步请求 / 响应类交互 | 返回可见结果、不可见、不可解析或暂不可读取。 |
| 相邻真相域结果送达 | 异步事件 / 回调类交互 | 保持未送达、待解析、待刷新或不可接受状态。 |
| Work 事实变化传播 | 异步事件 / 回调类交互 | 保持未消费、待交接或延后传播状态;传播失败不回滚核心真相。 |
| 派生消费辅助维护 | 后台任务 / 延后承接类交互 | 保留旧视图、过期标记或挂起重建。 |
| 外部快照与引用状态刷新 | 后台任务 / 延后承接类交互 | 保留旧快照、未解析引用或待刷新状态。 |
| 追溯 / 观测 / 归档材料交接 | 异步事件 / 回调类交互 | 保持待交接、未消费或延后归档状态。 |
| 受控维护与重建 | 后台任务 / 延后承接类交互 | 挂起、失败或输出异常状态,不得覆盖业务事实。 |

核心真相成立判断必须同步收口;已成立事实传播适合异步;派生、刷新、重建、对账和交接适合后台延后承接。本章不定义 API、topic、event 名称或 DTO 字段。

## 11. 关键技术选型

> 校准来源:
> - `design-calibration/01_arch_step_10_technology_choices.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解关键技术机制和不采用口径如何收敛。

| 技术机制 | 解决的问题 | 当前口径 |
|---|---|---|
| 正式承接层隔离外部输入与 Work 核心语义 | 防止外部来源、下游消费和运行层输入直接打穿项目工作事实真相 | 外部能力必须转换为引用、快照、摘要、正式变化或 promote 结果。 |
| 显式 formalize / promote 边界 | 防止 conversation suggestion、ImplementationPlan step、runtime plan item 或 artifact 来源直接污染正式工作全集 | Work 只拥有显式升级后的正式协作级结果。 |
| truth / snapshot / reference / derived separation | 防止来源正文、外部生命周期、消费视图和维护材料混入 Work 真相 | 外部能力只能通过快照、引用、摘要或派生结果参与。 |
| Work 核心真相内部强一致 | 防止 Project、ProjectMember、Backlog、WorkItem、child WorkItem、依赖、Iteration 和 promote 结果形成孤儿状态 | 核心写路径必须明确成立或失败。 |
| 只读派生视图 / 对账承接下游消费 | 防止 workspace、runtime、member-service、看板或报告直接依赖核心真相结构 | 派生结果可延迟、可重建、不得反写。 |
| 事件最终一致承接跨仓传播 | 防止传播、外部结果送达、观测和归档交接全部压入同步链路 | 传播失败不应回滚已经成立的业务真相。 |
| 后台延后承接派生、刷新和重建 | 防止投影、快照刷新、引用解析、对账、维护报告或归档准备阻塞核心写入 | 外围能力服务消费和解释,不作为核心成立前置。 |
| 追溯 / 审计 / 归档交接接缝 | 防止项目工作事实变化不可复盘 | Work 保留本域关键变化解释,不接管全局日志或长期归档正文。 |
| 单一编译期依赖与运行期 / 事件协作依赖纪律 | 防止 L1 平权真相域因源码依赖形成循环 | `L0-core` 是唯一编译期依赖。 |

当前不把具体数据库、递归 CTE、图数据库、board 物化视图、read model 产品形态、outbox worker、consumer group、topic 命名、完整事件溯源、旧 P95 或旧容量数字写成架构硬选型。这些内容必须在不破坏上述机制的前提下进入后续概要 / 详细设计、测试方案或实施计划。

## 12. 备选方案与取舍

> 校准来源:
> - `design-calibration/01_arch_step_11_alternatives_tradeoffs.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解主线方案、替代路径和取舍如何收敛。

当前主线采用:

```text
独立 Work truth
  + 正式承接
  + formalize / promote
  + 数据分层
  + 派生只读
  + 事件最终一致
  + 后台延后承接
```

| 方案路径 | 当前结论 | 说明 |
|---|---|---|
| 独立 Work truth + 正式承接 + promote + 数据分层 + 派生只读 + 事件最终一致 + 后台承接 | 采用 | 唯一同时满足职责边界、数据归属、通信方式和技术机制的主线。 |
| 外部来源和下游消费直接读写核心真相结构 | 不采用 | 会让外部输入和下游消费反向绑定核心模型。 |
| process / workspace / runtime / conversation / artifact 主导 Work 事实形成 | 不采用 | 会使 Work 退化为流程视图、workspace task card、runtime progress、conversation suggestion 或 artifact 依据副本。 |
| 完整事件溯源 / CQRS 优先路径 | 保留观察 | 当前采用追溯、事件协作和派生重建机制,但不把完整 ES / CQRS 作为 P0 必选。 |
| Graph-first / DAG-first 路径 | 不采用为主组织核心 | 复杂关系必须可解释,但图或递归实现只是后续详细设计候选。 |
| 全同步收口路径 | 不采用 | 会把投影、对账、归档、观测和外部快照刷新压入核心链路。 |
| 全异步命令 / 事件路径 | 不采用 | Project、WorkItem、Iteration、promote 和追溯读取缺少即时成立 / 失败判断。 |
| Projection-first / Board-first 路径 | 不采用 | 看板、投影和任务摘要只能从 Work 真相派生,不得形成第二 truth。 |
| Source-copy 路径 | 不采用 | 会让外部正文漂移进本仓。 |

当前主线牺牲了最短直接接入路径、完全同步的即时全链路完成感和直接复用相邻仓源码对象的便利,换来稳定独立的 Work truth center、来源正文不漂移、正式任务全集不被污染、下游不反向绑定核心、关键变化可追溯和依赖纪律稳定。

## 13. 横切关注点

> 校准来源:
> - `design-calibration/01_arch_step_12_cross_cutting_concerns.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解横切约束如何作用于主线。

| 横切关注点 | 约束要求 | 保护目标 |
|---|---|---|
| 安全边界:项目内承担和可见边界强制生效 | 所有读取、变更、追溯和派生消费都必须受 ProjectMember / Actor / 项目可见边界约束 | 防止越权消费或越权修改项目工作事实。 |
| 安全边界:外部输入正式承接 | 外部能力必须经正式承接层转换为引用、快照、摘要、正式变化或 promote 结果 | 防止外部输入反向定义 Work 核心。 |
| 数据边界:明确不拥有正文 | 禁止通过业务写入、配置、维护、派生或降级路径吸收相邻仓正文 | 保护来源 truth 归属。 |
| 正式升级边界:formalize / promote 可审查 | 外部来源形成 WorkItem / child WorkItem 时必须显式升级,并说明来源、理由、结果和拒绝状态 | 保护 Backlog / child WorkItem 的正式协作级边界。 |
| 审计与可追溯 | 关键状态变化和关键判断结果必须保留可追溯材料或状态 | 支撑协作复盘、责任边界和来源核验。 |
| 可观测性 | 必须能区分成功、失败、拒绝、不可见、不可解析、暂不可处理、挂起、旧视图、过期、待重建和交接失败等状态 | 让同步、最终一致和后台承接可解释。 |
| 韧性 / 恢复能力 | 未成立状态不得伪装为已成立;外围失败不得污染核心 | 保护核心 truth 和失败口径。 |
| 性能 / 容量约束 | 派生、看板、对账、归档、观测、快照刷新和下游 fan-out 不得成为核心事实成立的同步前置 | 保护核心协作路径。 |
| 配置与变更控制 | 配置不得改变 Work 真相归属、正文排除、formalize / promote、同步 / 异步 / 后台边界、派生不反写或依赖类型 | 防止实施和运维暗改架构主线。 |

Identity 认证凭据、Method-library 定义版本治理、Process checkpoint、Governance 审批制度、Artifact 内容扫描、Runtime 工具沙箱、Workspace UI 体验、全局观测日志存储和长期归档恢复手册不属于本章主体横切范围。

## 14. 演进路线

> 校准来源:
> - `design-calibration/01_arch_step_13_evolution_path.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解演进阶段、债务和触发条件如何收敛。

| 阶段 | 当前目标 / 范围 | 后续演进项 | 触发条件 |
|---|---|---|---|
| 当前主线成立阶段 | 让独立 Work 真相核心、Project / ProjectMember / Backlog / WorkItem / child WorkItem / Iteration、formalize / promote、数据归属、派生不反写、事件传播和后台承接边界成立 | 复杂关系、看板投影、引用新鲜度、事件重放、归档交接和容量隔离 | 下游消费、复杂关系、引用解析、归档或容量压力开始影响核心边界判断 |
| 复杂关系增强阶段 | 在不改变 Work truth center 的前提下增强依赖、阻塞、影响分析、无环判断和关系可视化承接 | 关系查询辅助、影响分析投影、无环验证策略、关系重建和异常关系对账 | 依赖关系规模、阻塞链路、影响分析或审计复盘超过当前关系承接能力 |
| 派生消费增强阶段 | 增强只读投影、看板、任务摘要、变化感知和对账维护 | 更细粒度投影、看板状态、任务摘要、变化感知游标、对账和重建隔离 | 高频消费或产品入口反压核心链路 |
| 引用 / 快照生命周期增强阶段 | 加强外部引用可解析性、快照新鲜度、来源不可用状态和 promote 来源恢复能力 | 引用状态机、快照新鲜度策略、来源不可用降级、promote 来源恢复 | 外部来源增多,未解析引用和旧快照影响判断、复盘或展示 |
| 事件 / 追溯增强阶段 | 评估是否需要更强事件模型、重放、时间旅行和审计追溯能力 | 完整事件溯源、事件版本治理、重放窗口、时间旅行读取 | 合规、复盘、恢复或跨仓重放明确要求事件级重放 |
| 归档 / 观测交接增强阶段 | 将 Work 追溯材料升级为更正式的 Observability / Archive 协作协议 | 归档交接协议、观测材料 schema、交接失败恢复、归档回链验证 | `L4-observability` / `L4-archive` 需要稳定消费和恢复验证 |
| 容量 / 隔离增强阶段 | 基于正式负载模型增强读写隔离、分区、冷热路径、后台重建和容量保护 | 容量分层、读写隔离、冷热历史策略、投影重建隔离、批量维护限流 | 正式负载模型证明核心同步路径、派生维护、关系查询或历史读取存在结构瓶颈 |

当前可接受债务包括:未量化吞吐 / 延迟 / 项目数 / WorkItem 数 / 依赖关系规模;未锁定 PostgreSQL / 递归 CTE / 图数据库 / 物化视图 / 缓存 / 搜索 / 消息产品;未把完整 ES / CQRS 作为 P0 主体范式;未展开长期 Archive / Observability 交接协议;未展开所有外部来源生命周期策略。

不可接受债务包括:核心真相边界不清、ProjectMember 与 GlobalMember 生命周期混写、Backlog / WorkItem / child WorkItem 被外部计划步骤污染、外部正文进入 Work truth、派生视图反写真相、同步成功伪装外围传播完成、除 `L0-core` 外形成编译期业务依赖。

## 15. 风险与待确认事项

> 校准来源:
> - `design-calibration/01_arch_step_14_risks_open_questions.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”小节,了解风险、待确认事项和阻塞判断如何收敛。

| 风险项 | 当前处理口径 | 是否阻塞 |
|---|---|---|
| 旧 Project / WorkItem / Iteration 聚合、PostgreSQL、递归 CTE、board projection 和 P95 指标回流为架构主线 | 只作为历史候选输入暂存,不得高于新版需求和 Step 1~13 已收稳结论 | 不阻塞 |
| process、workspace、runtime、conversation、artifact 或 governance 反向定义 Work truth | 坚持 Work 是独立项目工作事实真相仓,外部方只能通过正式接缝输入或消费 | 阻塞 |
| ProjectMember 与 GlobalMember / Role / Actor 生命周期混写 | Work 只拥有项目内承担事实,平台身份生命周期归 identity / core | 阻塞 |
| ImplementationPlan step、runtime plan item、personal checklist 或 conversation suggestion 污染 Backlog / child WorkItem | 只允许显式 formalize / promote 后结果成为正式 WorkItem / child WorkItem | 阻塞 |
| 相邻仓正文、external evidence body 或 runtime 执行正文进入 Work truth | 只允许引用、快照、摘要、派生辅助和 promote 后结果,禁止保存来源正文 | 阻塞 |
| 派生视图、看板、任务摘要、对账或维护报告成为第二 truth | 派生结构限定为只读、可重建、最终一致,不得反写核心事实 | 阻塞 |
| 同步成功伪装异步传播、投影重建、归档交接或观测交接已完成 | 同步只证明核心事实或授权读取成立,传播、派生和交接必须表达独立状态 | 阻塞 |
| 除 `L0-core` 外的仓被实现或配置变成编译期业务依赖 | 固定 `L0-core` 为唯一编译期依赖 | 阻塞 |
| 缺少正式负载模型导致旧性能数字或任意容量数字回流 | 量化数字后移到测试和验收 | 不阻塞 |
| Archive / Observability 交接扩张为本仓拥有全局日志或长期归档正文 | 当前只保留 Work 域追溯记录、交接引用和待交接状态 | 有条件阻塞 |
| 完整 ES / CQRS 或 Graph-first 被过早锁定或被完全遗忘 | 保持追溯记录 + 事件协作 + 复杂关系可解释,完整范式保留观察 | 不阻塞 |

| 待确认事项 | 当前挂起口径 |
|---|---|
| 正式 API、command、query、event、DTO 名称和字段 | 架构层只保留交互类别和边界,不预支接口签名。 |
| Project、WorkItem、child WorkItem、Iteration 的详细状态集和迁移规则 | 架构层只固定显式变化、强一致和不可伪成功。 |
| formalize / promote 的对象、输入来源、拒绝原因和追溯材料 | 当前只固定外部来源必须显式升级,不吸收来源正文。 |
| 复杂关系、依赖、阻塞和无环约束的实现口径 | 当前只确认关系必须可解释、不得非法成环,不锁定 Graph-first 或递归实现。 |
| 外部引用解析、快照新鲜度、失效显示和恢复生命周期 | 当前只确认引用 / 快照不等于来源 truth,生命周期后移。 |
| `L4-observability` / `L4-archive` 交接协议 | 当前只保留交接接缝和待交接状态。 |

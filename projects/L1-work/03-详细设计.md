## 5. 模块实现契约

> 校准来源:
> - `design-calibration/03_ddd_step_05_module_contracts.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`
> - `design-calibration/03_ddd_step_16_test_cuts.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“模块职责表”“对象归属总表”“Trait / Port / Adapter 总览”和“模块测试切口汇总表”小节,了解每个模块内部对象、trait、错误和测试切口。

L1-work 的详细设计模块主轴与 workspace member 对齐,包括 `contracts`、`domain`、`application`、`infra`、`api`、`worker`、`jobs` 七个模块。业务主要组成部分不直接变成 crate;它们跨模块实现。

| 模块 | 所属实现单元 | 职责 | 对外暴露 | 依赖对象 |
|---|---|---|---|---|
| `contracts` | `work-contracts` | 公共协议、typed ref、view、event、job、receipt 和 protocol error | DTO / ref / view / event / job / error | `core-contracts` |
| `domain` | `work-domain` | Work truth 对象、value object、state、policy、不变量和 domain error | aggregate / policy / state / DomainError | `contracts`、`core-contracts` |
| `application` | `work-application` | 用例编排、事务、幂等、port 调用和 application error | services / ports / UoW / idempotency | `contracts`、`domain`、`core-contracts` |
| `infra` | `work-infra` | repository / adapter / config / runtime builder | adapters / stores / runtime builder | `contracts`、`domain`、`application`、`core-contracts` |
| `api` | `work-api` | 同步 Command / Query handler | handlers / routes / ApiError | `contracts`、`application`、`infra`、`core-contracts` |
| `worker` | `work-worker` | inbound consumer、outbox publisher loop、projection maintenance trigger | consumers / worker runners | `contracts`、`application`、`infra`、`core-contracts` |
| `jobs` | `work-jobs` | projection rebuild、reference refresh、reconciliation、trace / archive handoff job | job runners | `contracts`、`application`、`infra`、`core-contracts` |

```text
contracts -> core-contracts
domain -> contracts -> core-contracts
application -> domain -> contracts -> core-contracts
infra -> application -> domain -> contracts -> core-contracts
api / worker / jobs -> infra -> application
```

禁止方向:

- `contracts` 不依赖 `domain`、`application`、`infra`、`api`、`worker` 或 `jobs`。
- `domain` 不依赖 repository、adapter、config、HTTP、bus、DB 或 job runner。
- `application` 不依赖 `infra`、`api`、`worker` 或 `jobs`。
- `api`、`worker`、`jobs` 不互相依赖。

### 5.1 `contracts`

`contracts` 定义跨入口和下游可复用协议 DTO,不承载领域不变量。文件主体包括 `refs.rs`、`commands.rs`、`queries.rs`、`events.rs`、`jobs.rs`、`views.rs`、`errors.rs` 和 `fixtures.rs`。它只能依赖 `core-contracts`。

### 5.2 `domain`

`domain` 定义领域对象、状态、policy、不变量和 domain error。正式对象包括 Project、ProjectMember、Backlog、WorkItem、ChildWorkItem、WorkDependency、WorkBlocker、Iteration、IterationCommitment、PromoteResult、reference / snapshot、trace / audit / outbox 和 policy。`domain` 只能消费 contracts / core 类型,不得读取 config 或直接调用外部 adapter。

### 5.3 `application`

`application` 编排 command / query / consumer / job 用例、事务、幂等、command result replay、job report replay、repository / port 调用、outbox / trace / projection 副作用。port trait、UnitOfWork、IdempotencyRepository、CommandResultRepository、JobResultRepository、ClockPort、IdGeneratorPort 和 application services 均在本模块定义。

### 5.4 `infra`

`infra` 实现 application ports,提供 repository / projection / idempotency / resolver / publisher / handoff adapter、config loader、runtime builder 和 fake runtime。`infra` 不向 domain 泄漏 adapter 细节。

### 5.5 `api` / `worker` / `jobs`

`api` 只承载同步 Command / Query handler 和 route assembly;`worker` 承载 inbound event consumer、outbox publish loop 和 projection invalidation worker;`jobs` 承载 operations job runner。三者通过 `infra::runtime_builder` 获得 application service 装配,不得互相依赖。

Backlog archive 这类 service 内部级联写路径不得临时生成或猜测 optimistic version。凡是 `BacklogRepository.save(backlog, expected_version, &uow)` 的 `expected_version` 不是 public request 字段时,必须来自正式 repository 读取口径,例如 `BacklogRepository.get_by_project_with_version(project_ref) -> Option<(Backlog, Version)>`。普通 query / read-only 路径继续使用 `get_by_project(project_ref) -> Option<Backlog>`。

Dependency / blocker command 需要从 `FormalWorkRef` 得到 project / member scope 时,必须通过 `WorkItemRepository.get_formal_work_scope(work_ref) -> Option<FormalWorkScope>`。该 scope 由 repository 根据 backlog membership / parent root relation 解析,不得由 service 解析 id 字符串或实现临时 `project_ref_from(...)`。Relation 写路径当前只标记 project-board 与可解析 assignee 的 member-work stale;`WorkSearchProjection` 不承载 relation state,不因 dependency / blocker 变化标脏。

Query visibility 的唯一 P0 裁决来源是 Work-owned ProjectMember responsibility。`AuthorizedWorkQueryService` 先通过 `ActorMemberResolverPort.resolve_actor_member(ActorContext)` 得到 `GlobalMemberRef`,再用 `ProjectMemberRepository.get_by_member(project_ref, member_ref)` 查 actor 在目标 project 内的承担;`Active` / `Paused` 可读,`Proposed` / `Released`、actor-member not found / rejected、scope unresolved 均返回 `QuerySurface::NotVisible` 且不返回业务数据;actor-member resolver temporary unavailable 映射 `TemporarilyUnavailable`。Formal work / iteration / relation / trace subject 必须先通过正式 repository scope 解析到 owning project,不得解析 id 字符串、解释 `role_refs`、使用 `ActorKind::System` / `Integration` 或 `ProjectOwnerRef` 绕过 membership。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源:
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“共享协议约束”“Command 协议契约”“Query 协议契约”“Event 协议契约”“Operations Job 协议契约”和“DTO / Event / Job 到 Domain 构造闭环汇总”小节。

协议入口分为 18 个 Command、8 个 Query、7 个 Inbound Event Consumer、10 个 Outbound Event 和 6 个 Operations Job。所有写入入口必须携带 metadata / idempotency 或 event dedup 信息;Query 不写 truth。

| 类别 | 数量 | 入口 |
|---|---:|---|
| Command | 18 | `CreateProject`、`UpdateProjectLifecycle`、`UpdateBacklogAvailability`、`AssignProjectMember`、`UpdateProjectMemberResponsibility`、`CreateWorkItem`、`CreateChildWorkItem`、`UpdateWorkItemLifecycle`、`RequestWorkPromotion`、`ReviewWorkPromotion`、`LinkWorkDependency`、`UpdateWorkDependencyState`、`OpenWorkBlocker`、`ResolveWorkBlocker`、`OpenIteration`、`CommitIterationScope`、`UpdateIterationCommitment`、`UpdateIterationLifecycle` |
| Query | 8 | `GetProjectWorkFacts`、`GetBacklog`、`GetWorkItem`、`ListMemberWork`、`GetIterationSummary`、`SearchWork`、`GetWorkTrace`、`GetProjectBoardView` |
| Inbound Event Consumer | 7 | `ConsumeIdentityMemberChanged`、`ConsumeMethodDefinitionChanged`、`ConsumeConversationWorkContextChanged`、`ConsumeProcessTimingChanged`、`ConsumeGovernanceDecisionChanged`、`ConsumeArtifactEvidenceChanged`、`ConsumeRuntimePromoteRequested` |
| Outbound Event | 10 | `ProjectChanged`、`BacklogChanged`、`ProjectMemberChanged`、`WorkItemChanged`、`PromoteResultRecorded`、`WorkDependencyChanged`、`WorkBlockerChanged`、`IterationChanged`、`WorkTraceAvailable`、`DerivedWorkViewChanged` |
| Operations Job | 6 | `PublishWorkOutbox`、`RebuildWorkProjections`、`RefreshExternalReferenceSnapshots`、`RunWorkReconciliation`、`PrepareWorkTraceHandoff`、`PrepareArchiveHandoff` |

共享约束:

- Command request 使用 core `CommandMetadata.request.idempotency_key`;缺失时 reject。
- Query request 使用 core `QueryMetadata`;Query 不写 idempotency、audit、outbox 或 freshness marker。
- Inbound Event 使用 event id、source ref、dedup key 和 payload digest;malformed / unsupported 输入进入 dead-letter 或 quarantine。
- Outbound Event 只能由 committed truth、outbox 或 projection state 构造,payload 不携带相邻仓正文。`WorkOutboxRecord` 必须携带 typed `source_ref`、`trace_context_ref` 和 `occurred_at`;publisher service 按 `source_ref` 回查 committed source object 并构造 typed outbound envelope,不得从 `outbox_id`、event kind 或 latest state 猜 payload source。
- Operations Job 必须定义 input / output / report DTO、retry 语义和 failed marker。
- Command result、Query view / page、Inbound Event envelope / payload / receipt、Outbound Event payload、Job input / output / report 中引用的 enum / ref / helper 必须属于 `work-contracts` 或 `core-contracts`,不得引用 domain-only 类型。
- `EventSchemaVersion` 归 `work-contracts::events`,是字符串 newtype。P0 唯一支持值为 `v1`;outbound envelope 必须使用 contracts 常量 / fixture 构造 `v1`,inbound envelope 的 missing、parse failure、非 `v1` 或与 topic suffix major version 不一致均进入 `DeadLetter`,不得写 Work truth、snapshot、trace 或 outbox。
- `WorkTitle`、`WorkSearchText`、`WorkSearchCriteriaDigest`、`ProjectWorkTruthSnapshot`、`ProjectProjectionBatch`、`ReconciliationReport`、Job scope / handoff target 等协议传递类型的字段级 schema 已收敛在 Step 6 / Step 8,不得退回“类型名占位”。`ProjectWorkTruthSnapshot` 是 contracts shared / body-free rebuild DTO,只能由 `ProjectTruthSummary`、`BacklogTruthSummary`、`ProjectMemberTruthSummary`、`FormalWorkTruthSummary`、`WorkRelationTruthSummary`、`IterationTruthSummary` 和 `WorkTruthCursor` 组成;不得引用 domain-only `Project`、`Backlog`、`ProjectMember`、`Iteration` 或 `IterationCommitment`。
- `Project.source_ref`、`WorkItem.title/source_ref/method_definition_ref`、`ChildWorkItem.title/source_ref/method_definition_ref` 是 committed Work truth 字段;projection rebuild、search rows 和 project reference refresh 不得从 request history、旧 projection 或临时 local index 反推这些字段。
- `RefreshExternalReferenceSnapshots.reference_scope` 的 `Project` branch 只能通过 `ReferenceSnapshotRepository.list_project_references(project_ref, page)` 展开为 typed `ExternalReferenceRef`;该读取面从 committed Work truth / local reference snapshot indexes 枚举,先去重稳定排序再分页,不得从 projection、字符串 id 或外部正文临时派生 refs。
- `RefreshExternalReferenceSnapshots` 成功 refresh 后的 affected public projections 只能通过 `ProjectionRepository.list_views_affected_by_references(changed_refs, page)` 枚举 existing `DerivedWorkViewRef`;service 不得组合 consumer-local helper,不得按 `ExternalReferenceRef` variant 临时拼 project-board / member-work / iteration-summary / work-search ref。返回空页时只保存 reference state,不调用 `mark_stale(...)`。

## 8. 逐接口函数级处理流

> 校准来源:
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“Command 写路径模板”“Query 读路径模板”“Inbound Event Consumer 模板”“Outbound Event 发布模板”和每个 flow 小节,了解函数级调用链、事务边界、错误映射、状态副作用和测试切口。

所有 Command 使用同一事务和幂等模板。具体 command 只替换 `operation`、domain method、repository 和 result DTO。

```text
[api::WorkCommandHandlers.handle_<command>]
  | validate WorkCommandEnvelope<T>
  | require CommandMetadata.request.idempotency_key
  | compute canonical RequestDigest from stable business input
  v
[application::<CommandService>.<operation>]
  | UnitOfWork.begin()
  | IdempotencyRepository.reserve(key, operation, digest, &uow)
  | duplicate -> return stored result without truth write
  | conflict -> mark_conflict + rollback + IdempotencyConflict
  | lookup / resolver / id generation
  v
[domain object / policy]
  | call Object.factory_or_transition(...)
  | call WorkTruthPolicy.assert_truth_change_allowed(...)
  v
[repositories + audit + outbox]
  | save truth with expected_version when present
  | WorkTraceRecord::from_truth_change(trace_id, change, trace_context_ref)
  | WorkOutboxRecord::from_truth_change(outbox_id, change, trace_context_ref, occurred_at)
  | ProjectionRepository.mark_stale(affected_views, cursor, &uow) when affected public DerivedWorkViewRef exists
  | CommandResultRepository.save_result(result_ref, StoredCommandResult::<kind>(result), &uow)
  | IdempotencyRepository.complete(reservation, result_ref, &uow)
  | UnitOfWork.commit()
```

Flow 分组:

| 分组 | Flow |
|---|---|
| Command | 18 条写路径,对应 §7 Command 列表 |
| Query | 8 条读路径,必须 no-write,并显式暴露 missing / not visible / degraded / stale |
| Inbound Event | 7 条 consumer 写路径或 marker 写路径,必须使用 dedup |
| Outbound Event | 10 条 outbox dispatch path,只更新 publication state |
| Operations Job | 6 条 job path,区分 job-level reject 和 item-level failure |

Handler 不直接开启事务、不直接访问 repository、不自行判重。Domain 不直接发布事件、不访问系统时间、不读取配置。Query 不自动 rebuild projection。

## 9. 状态机与转换矩阵

> 校准来源:
> - `design-calibration/03_ddd_step_10_state_matrix.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“状态机总表”“状态集合表”“核心业务 truth 状态转换矩阵”“辅助状态转换矩阵”“非法转换处理表”和“状态矩阵到测试切口映射”小节。

状态机分为业务 truth 状态和辅助状态。业务 truth 状态由 domain object method 修改,并经 application command flow 在同一 UnitOfWork 内保存 truth、正式定义的 history 或 audit、outbox、已定义 public derived view 的 projection stale marker 和 idempotency result。没有 query / projection identity 的 truth 或 marker 不得临时派生 `DerivedWorkViewRef`。辅助状态包括 derived projection freshness、external reference resolution 和 outbox publication,它们不得反向修改业务 truth。

| 状态机 | 归属对象 / store | 状态字段 | 触发入口 | 是否业务 truth | 终态 |
|---|---|---|---|---|---|
| `ProjectLifecycleState` | `Project` / `ProjectRepository` | `Project.lifecycle_state` | `CreateProjectFlow`、`UpdateProjectLifecycleFlow` | 是 | `Archived` |
| `ProjectMemberResponsibilityState` | `ProjectMember` / `ProjectMemberRepository` | `ProjectMember.responsibility_state` | `AssignProjectMemberFlow`、`UpdateProjectMemberResponsibilityFlow` | 是 | `Released` |
| `BacklogState` | `Backlog` / `BacklogRepository` | `Backlog.backlog_state` | `CreateProjectFlow`、`UpdateBacklogAvailabilityFlow`、project archive path | 是 | `Archived` |
| `WorkItemState` | `WorkItem` / `ChildWorkItem` / `WorkItemRepository` | `work_state` | create / lifecycle / iteration / promote flows | 是 | `Completed`、`Cancelled`、`Superseded` |
| `PromoteResultState` | `PromoteResult` / `PromoteRepository` | `PromoteResult.result_state` | `RequestWorkPromotionFlow`、`ReviewWorkPromotionFlow` | 是 | `Superseded` |
| `DependencyState` | `WorkDependency` / `DependencyRepository` | `WorkDependency.dependency_state` | `LinkWorkDependencyFlow`、`UpdateWorkDependencyStateFlow` | 是 | `Satisfied`、`Waived`、`Cancelled` |
| `BlockerState` | `WorkBlocker` / `BlockerRepository` | `WorkBlocker.blocker_state`;`WorkBlocker.resolved_evidence_ref` | `OpenWorkBlockerFlow`、`ResolveWorkBlockerFlow`、future mitigation / close command | 是 | `Closed` |
| `IterationState` | `Iteration` / `IterationRepository` | `Iteration.iteration_state` | `OpenIterationFlow`、`CommitIterationScopeFlow`、`UpdateIterationLifecycleFlow` | 是 | `Closed`、`Cancelled` |
| `CommitmentState` | `IterationCommitment` / `IterationRepository` | `IterationCommitment.commitment_state` | `CommitIterationScopeFlow`、`UpdateIterationCommitmentFlow`、iteration close path | 是 | `Closed` |
| `DerivedFreshnessState` | `DerivedWorkViewState` / `ProjectionRepository` | `freshness_state` | truth change / consumer stale mark / rebuild job | 否 | 无 |
| `ReferenceResolutionStatus` | `ReferenceResolutionState` / `ReferenceSnapshotRepository` | `resolution_state` | inbound consumer / reference refresh job | 否 | 无 |
| `OutboxPublicationState` | `WorkOutboxRecord` / `WorkOutboxRepository` | `publication_state` | `PublishWorkOutboxFlow` | 否 | `Published` |

非法转换统一由 domain method 返回 `DomainError::InvalidStateTransition`,application 映射为 `ApplicationError::DomainRejected`,handler 映射为 `WorkProtocolError::DomainRejected`。非法转换不得写 truth、outbox 或 projection stale marker。

`WorkItem` 与 `ChildWorkItem` 共用 `WorkItemState` 完整生命周期。二者进入 `Completed` 时都必须写入 `completion_ref: Option<ExternalEvidenceRef>` 的 verified evidence 引用;缺失或未验证 evidence 不得形成 truth / outbox。`CommitIterationScopeFlow` 允许 unified `FormalWorkRecord` candidate,root work 调用 `WorkItem::mark_committed(...)`,child work 调用 `ChildWorkItem::mark_committed(...)`。

`DependencyTarget::Active` 是 `UpdateWorkDependencyState` 的正式 public target。`UpdateWorkDependencyStateFlow` 必须覆盖 `Proposed -> Active`,并要求 `DependencyChangeReason.reason_kind = Activated`;`Satisfied`、`Waived`、`Cancelled` 也必须分别校验同族 reason kind。`LinkWorkDependencyFlow` 可以在创建后立即激活 dependency,但必须通过 `DependencyChangeReason::from_link_reason(...)` 形成 activation history reason,不得把 creation-only `DependencyReason` 当作 state-change reason。

Dependency / blocker 的 graph snapshot scope 和 projection stale scope 均来自 `FormalWorkScope`。`LinkWorkDependency` 以 downstream formal work scope 读取 graph 并标记 downstream project-board / member-work;`OpenWorkBlocker` 和 `ResolveWorkBlocker` 以 blocked work scope 标记 blocked project-board / member-work。缺失 formal work scope 映射为 `NotFound` 或 repository failure,不得 fallback 到未定义 scope。

`IterationChangeRecord` 只记录 commitment scope / changed formal work refs history,由 `CommitIterationScopeFlow` 和 `UpdateIterationCommitmentFlow` 构造。`UpdateIterationLifecycleFlow` 不追加 `IterationChangeRecord`;lifecycle-only change 由 iteration save、close path optional commitment save、trace / audit、`IterationChanged` outbox、projection stale 和 command result / idempotency 表达,不得构造空 `changed_work_refs`。

## 10. 数据持久化、事务与一致性契约

> 校准来源:
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“数据所有权实现表”“表 / collection / projection 契约表”“Repository 函数表”“事务边界表”“一致性策略表”和“失败恢复口径”小节。

持久化设计只锁定逻辑存储契约,不锁定具体数据库产品或 DDL。实现可以使用 SQL table、document collection 或 in-memory adapter,但必须保留本章定义的主键、唯一键、索引、版本、UoW 和一致性语义。

| 类型 | 对象 | 一致性口径 |
|---|---|---|
| 业务 truth | Project、ProjectMember、Backlog、WorkItem、ChildWorkItem、PromoteResult、Dependency、Blocker、Iteration、Commitment | 强一致,由 Command flow 在同一 UoW 内成立或 rollback |
| history / trace / outbox | promote / dependency / iteration commitment history、WorkTraceRecord、WorkOutboxRecord | accepted truth 同 UoW 写入;outbox record 保存 event kind、typed payload source、trace context 和 occurred_at;outbox publication 最终一致 |
| reference / snapshot | ReferenceResolutionState、MemberCapabilitySnapshot、MethodDefinitionSnapshot | 最终一致,不得复制外部正文 |
| result replay | StoredCommandResult、StoredJobResult、ApplicationResultRef | accepted command / job 同 UoW 保存;duplicate 只读 replay |
| projection / report / handoff | ProjectBoardView、MemberWorkView、IterationSummaryView、WorkSearchProjection、ReconciliationReport、handoff marker | 只读 / 可重建 / 最终一致,不得反写业务 truth |

写路径必须通过 `UnitOfWork`。所有修改已有 truth / state 的 repository 函数必须使用 optimistic version;version mismatch 映射为 repository version conflict,不得 silent overwrite。每个 `expected_version` 必须有正式来源:public request 字段、前置 create 返回值,或 repository 带 version 的读取函数;service 内部级联更新不得引用未定义的临时 version。`UpdateIterationLifecycleFlow` close path 的 commitment save 必须使用 `IterationRepository.get_commitment_with_version(...)` 返回的 version。`PublishWorkOutboxFlow` 的 publication marker 必须使用 `WorkOutboxRepository.list_pending(page)` / `get(outbox_id)` 返回的 `Versioned<WorkOutboxRecord>.version`。Reference refresh / inbound consumer 修改已有 `ReferenceResolutionState`、`MemberCapabilitySnapshot` 或 `MethodDefinitionSnapshot` 时,必须使用 `ReferenceSnapshotRepository.get_reference_state_with_version(...)`、`get_member_snapshot_with_version(...)`、`get_method_snapshot_with_version(...)` 返回的 version;仅当对应 state / snapshot 原先不存在并执行 create/upsert 时,`expected_version` 才能为 `None`。所有 Command、Inbound Event Consumer 和 Operations Job 的写入必须先 reserve idempotency key / dedup key。Command 成功路径必须在同一 UoW 内保存 command result surface,再 complete result ref;Job 成功路径必须在同一 UoW 内保存 job report surface,再 complete result ref。

```text
IdempotencyRepository.reserve(...)
  -> load truth / snapshot / reference as needed
  -> domain factory / transition
  -> save truth with expected_version
  -> append formally defined history and/or trace
  -> WorkOutboxRepository.enqueue(...)
  -> ProjectionRepository.mark_stale(...) when affected public DerivedWorkViewRef exists
  -> CommandResultRepository.save_result(...)
  -> IdempotencyRepository.complete(...)
  -> UnitOfWork.commit()
```

Query 不开启写 UoW,不写 audit,不写 outbox,不触发 projection rebuild。Query 读取 stale / failed / rebuilding projection 时必须返回对应 surface,不能在读路径修复状态。

## 11. 错误模型、异常分支与恢复口径

> 校准来源:
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“错误类型表”“内部错误映射表”“异常分支处理表”和“恢复口径表”小节。

错误模型采用分层错误边界。Domain 层只返回 `DomainError`;repository / port / UoW / idempotency 层分别返回 `RepositoryError`、`PortError`、`UnitOfWorkError`、`IdempotencyError`;application service 将这些错误映射为 `ApplicationError`;handler / runner 最终映射为 `WorkProtocolError`、query surface、consumer disposition 或 job report。

同步 Command 的失败不得写 accepted truth、trace 或 outbox。Query 失败不得触发修复写入。Inbound Event 的 malformed / unsupported 输入进入 dead-letter,临时 store / resolver failure 进入 retry。Operations Job 区分 job-level reject 和 item-level failure;item-level failure 必须进入 report 或 failed marker。

| 错误类别 | 恢复方式 |
|---|---|
| request / metadata / visibility / domain policy 错误 | 调用方修正输入或权限,不可自动原样重试 |
| version conflict | reload latest version,用同一业务意图重试 |
| idempotency duplicate | Command 通过 `CommandResultRepository.get_result` 返回 stored result;Job 通过 `JobResultRepository.get_report` 返回 stored report;不得重放 domain transition / job side effect |
| idempotency conflict | reject,调用方更换 key |
| external reference unresolved | 等待 upstream / resolver 恢复或写 failed / unresolved marker |
| store / publisher / handoff temporary unavailable | bounded retry;保留 failed marker / report |
| commit status unknown | 不盲重试;先查 idempotency result / reconciliation |

## 12. 并发、幂等与重入保护

> 校准来源:
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“并发场景表”“幂等键表”“重入保护表”和“CommitStatusUnknown 审计口径”小节。

写路径使用三层保护:第一层是 `IdempotencyRepository` 对 `(operation, idempotency_key)` 的 atomic reserve;第二层是 `RequestDigest` 区分 same request 与 key reuse conflict;第三层是 repository optimistic `Version`、唯一键和 cursor monotonicity 防止并发覆盖。Command 的 `ApplicationResultRef` 必须指向 `CommandResultRepository` 中同 UoW 保存的 `StoredCommandResult`;Job 的 `ApplicationResultRef` 必须指向 `JobResultRepository` 中同 UoW 保存的 `StoredJobResult`,用于 duplicate replay。

Command 和 Operations Job 的幂等键来自 core `CommandMetadata.request.idempotency_key`。Inbound Event 的 dedup key 来自 `topic + source_event_id + source_ref`。Query 不写幂等记录。Outbound publish 不使用 public idempotency key,而以 `WorkOutboxId + expected_version` 保护单条 publication state;`expected_version` 来自 `Versioned<WorkOutboxRecord>` pending / get 读取。

`RequestDigest` 只包含稳定业务输入:operation、route scope、actor effective scope、command body / job body / event payload digest 等会改变结果的字段。它不得包含 `idempotency_key`、`request_id`、`requested_at`、`trace_id`、`job_run_id` 或 retry counter。

| 情况 | 结果 |
|---|---|
| same key + same digest + completed | Command 通过 `CommandResultRepository.get_result(ApplicationResultRef)` 返回 stored result;Job 通过 `JobResultRepository.get_report(ApplicationResultRef)` 返回 stored report;只 overlay duplicate receipt,不重放 domain transition |
| same key + same digest + reserved / unknown | 返回 temporarily unavailable,稍后重试或 reconciliation |
| same key + different digest | `IdempotencyConflict` |
| duplicate inbound event same digest | `AckDuplicate` |
| duplicate outbox publish worker | 使用 pending / get 读取的 `Versioned<WorkOutboxRecord>.version` 标记 publication state;version conflict treated as already handled / item failure,不改 truth |

`CommitStatusUnknown` 不允许盲重试。重试前必须调用 `IdempotencyRepository.get(key, operation)`。若记录已 completed 且 digest 匹配,Command 通过 `CommandResultRepository.get_result(result_ref)` 读取既有 result,Job 通过 `JobResultRepository.get_report(result_ref)` 读取既有 report;stored surface 缺失时返回 temporarily unavailable 并进入 reconciliation。

## 13. 配置引用与外部依赖绑定

> 校准来源:
> - `design-calibration/03_ddd_step_14_config_external_binding.md`
>
> 延伸阅读:
> - 建议继续阅读本中间产物的“配置引用表”“外部依赖绑定表”“跨仓 Rust 依赖绑定表”和“Runtime builder 绑定顺序”小节。

## 14. 可观测性与审计埋点契约

> 校准来源:

> 延伸阅读:

可观测性契约只定义代码必须暴露的日志、指标、trace 和审计切口,不定义告警阈值、dashboard、日志采集系统、保留周期或运维处置流程。

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L1-work` 的第一批核心设计主线展开。当前 `02-概要设计.md` 与 `03-详细设计.md` 已经明确:
- `L1-work` 是项目工作事实真相层
- `Backlog / WorkItem / child WorkItem / Iteration` 构成正式协作事实主线
- `ImplementationPlan` 只是执行计划接缝,不是正式工作事实真相
- promote 必须通过正式入口,不能静默污染 Backlog
- board / tree / rollup / summary 只读且不反写真相

因此,本次验收的目的不是笼统判断“功能是否存在”,而是判断这些边界、主流程和红线是否真的成立,是否可以作为第一批正式设计基线继续进入后续阶段。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 项目主语与成员承担部分 | 是 | Project / ProjectMember 及其生命周期边界 |
| Backlog 与正式工作项管理部分 | 是 | 正式协作事实与 child WorkItem 流程 |
| Iteration 承诺子集管理部分 | 是 | planning / freeze / spillover |
| 协作视图与投影部分 | 是 | board / tree / rollup / summary 只读边界 |
| ImplementationPlan / promote 接缝部分 | 是 | plan item → child WorkItem 正式化路径 |
| artifact done criterion 接缝 | 是 | approved evidence 与完成判据联动 |
| process timing 内部实现细节 | 否 | 只验边界成立,不验 process 内部正文实现 |
| runtime 执行正文 | 否 | 只验 promote 接缝,不验 runtime 内部执行逻辑 |
| 前端视觉与交互细节 | 否 | 不在本次仓级验收范围内 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateProject → 空 Backlog | 创建项目后必须生成空 Backlog 容器 | API 响应 / DB 记录 / 测试报告 | [] |
| CreateWorkItem | 顶层 WorkItem 创建后必须进入 Backlog 且状态为 accepted + todo | 集成测试日志 / backlog 顺序快照 | [] |
| CreateChildWorkItem proposal | child WorkItem 创建后必须先处于 proposed,不得直接 accepted | 状态流日志 / 事件记录 | [] |
| AcceptChildWorkItem | accepted 后才允许进入 Backlog / Iteration | planning_status 变更记录 / backlog 记录 | [] |
| RejectChildWorkItem | rejected 后不得进入 Backlog / Iteration,但必须保留审计链 | 审计记录 / board 过滤结果 | [] |
| DraftIteration / StartIteration | 只有 accepted workitems 才能进入 Iteration,启动后 planned_workitems 冻结 | iteration 快照 / 事件记录 | [] |
| PromotePlanItemToChildWorkItem | plan item 只有满足 promote 条件时才允许升级为 child WorkItem | promote request / child 回链 / 审计日志 | [] |
| Artifact approved → done criterion | approved evidence 到达后才能使 workitem 满足 done 条件 | artifact.approved 事件 / workitem 状态变更 | [] |
| Board / tree / summary 查询 | 只读视图必须能正确展示真相,且 rejected child 不进入主协作板 | 查询结果 / projection 重建日志 | [] |

> 若本系统涉及 WorkItem / child WorkItem / ImplementationPlan,验收文档应明确:
> - Backlog 是否作为空池先存在
> - Sprint Planning 是否只做选择而不创建 Backlog 真相
> - child WorkItem 是否通过正式流程进入 Backlog / Iteration
> - ImplementationPlan 是否仅作为执行计划/证据视图存在,而不与 WorkItem 真相混淆

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | 真相层混层 / promote 越界 / done 判据失效 / projection 反写真相 |

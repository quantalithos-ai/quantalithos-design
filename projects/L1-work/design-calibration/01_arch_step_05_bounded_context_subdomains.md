## 3. SOP 问题回答

### 3.1 本仓内部有哪些子域或本地上下文？

`L1-work` 内部应划分为三层:

- 核心子域:`项目工作事实真相核心`。
- 支撑子域:`项目主语上下文`、`项目成员承担上下文`、`正式工作全集上下文`、`工作拆分与升级边界上下文`、`工作依赖与阻塞上下文`、`Iteration 承诺子集上下文`、`项目工作事实消费与追溯上下文`、`派生消费辅助上下文`。
- 本地索引 / 投影 / 引用:`成员 / actor 引用与承担快照`、`方法定义引用与目录快照`、`conversation / runtime 来源引用`、`process / governance / artifact 控制与依据引用`、`工作消费投影 / 看板 / 对账材料`、`observability / archive 追溯交接引用`。

### 3.2 哪些是核心子域？

核心子域只有一个:`项目工作事实真相核心`。

它承载 `L1-work` 成立所需的统一 truth center,包括项目作为正式工作对象、项目内承担、正式工作全集、正式工作拆分、依赖阻塞、Iteration 承诺子集、promote 后正式结果和关键变化追溯的统一语义。

将核心子域收束为一个中心,是为了避免后续把 Project、ProjectMember、Backlog、WorkItem、child WorkItem、Iteration 或 promote 结果拆成互相竞争的多个 truth source。它们可以在概要 / 详细设计中分对象、功能和状态展开,但在架构语义上共同属于项目工作事实真相核心。

### 3.3 哪些是支撑子域？

支撑子域围绕项目工作事实真相核心存在:

- 项目主语上下文,用于表达软件项目进入正式工作管理语境的项目锚点。
- 项目成员承担上下文,用于表达 GlobalMember 在项目内承担工作的正式事实。
- 正式工作全集上下文,用于表达 Backlog、WorkItem 和正式协作级工作全集。
- 工作拆分与升级边界上下文,用于保护 child WorkItem 与 ImplementationPlan step、runtime plan item、个人执行步骤之间的边界。
- 工作依赖与阻塞上下文,用于表达正式工作之间的依赖、阻塞、解除依据和协作关系。
- Iteration 承诺子集上下文,用于表达从正式工作全集中选择出的当前时间窗口承诺范围。
- 项目工作事实消费与追溯上下文,用于支撑成员、审计者和相邻仓按同一份 Work 真相理解项目状态。
- 派生消费辅助上下文,用于维护看板、投影、索引、对账和维护报告等不反写真相的辅助结构。

### 3.4 哪些只是外部上下文的本地索引 / 投影 / 引用？

以下结构只能作为本地影子层存在:

- 成员 / actor 引用与承担快照。
- 方法定义引用与目录快照。
- conversation / runtime 来源引用。
- process / governance / artifact 控制与依据引用。
- 工作消费投影 / 看板 / 对账材料。
- observability / archive 追溯交接引用。

这些结构服务稳定消费、业务判断、降级显示、追溯解释和跨仓协作,但不拥有 `L1-identity`、`L3-method-library`、`L1-conversation`、`L2-runtime`、`L1-process`、`L1-governance`、`L1-artifact`、`L4-observability` 或 `L4-archive` 的正文真相。

### 3.5 它们之间的上下文映射关系是什么？

`项目工作事实真相核心` 位于中心。项目主语、项目成员承担、正式工作全集、工作拆分与升级、工作依赖与阻塞、Iteration 承诺子集共同围绕它形成正式工作事实闭环。项目工作事实消费与追溯、派生消费辅助上下文只能消费核心真相和支撑上下文的正式结果。所有本地索引 / 投影 / 引用都只能依附核心真相或支撑上下文,不得直接反向定义 Work 真相。

### 3.6 为什么这些部分不能混成一个上下文？

这些部分不能混成一个上下文,因为它们的真相归属、变化生命周期、失败口径和反写风险不同。项目工作事实真相核心必须稳定、可追溯且不被消费方反写;支撑上下文处理不同语义变化,例如项目成立、成员承担、正式工作收束、promote、依赖阻塞和承诺范围;本地影子层只用于引用、快照、投影、对账或追溯交接,可以延迟、失效或重建。若全部混成一个上下文,后续会把 identity 成员生命周期、method-library 定义、conversation 建议、runtime 执行步骤、process planning、governance 决策、artifact 正文或 workspace 视图误写成 Work 真相。

## 4. 当前文档问题诊断

| 旧架构内容 | 问题 | 本轮处理 |
|---|---|---|
| `Project`、`Backlog`、`WorkItem`、`Iteration` 被直接当作子域主线 | 容易把对象清单误写成限界上下文,也容易形成多个 truth center | 改为一个 `项目工作事实真相核心`,对象线索后续概要 / 详细设计再展开 |
| `Planning` 被写成 Work 内部子域 | 容易吞入 process planning / review / timing 语义 | 改为 `Iteration 承诺子集上下文`,process 只作为外部节奏引用 |
| `Assignment` 容易和 identity 成员管理混写 | ProjectMember 是项目内承担事实,不是 GlobalMember 生命周期 | 改为 `项目成员承担上下文`,并将成员来源放入本地引用 / 快照层 |
| `View` / `Board` 被写成核心结构 | 看板、投影和对账是派生消费辅助,不是业务 truth | 改为 `派生消费辅助上下文` 和本地投影层 |
| ImplementationPlan / PlanItem promote 没有独立边界语义 | 容易让 child WorkItem 吞入 runtime / artifact 执行计划正文 | 增加 `工作拆分与升级边界上下文` |

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 核心子域 | Project / Backlog / WorkItem / Iteration 分散表达 | `项目工作事实真相核心` | 保护唯一 Work truth center |
| 支撑上下文 | Planning、Assignment、View 等旧功能线索 | 项目主语、成员承担、正式工作全集、拆分升级、依赖阻塞、Iteration、消费追溯、派生辅助 | 按语义职责和反写风险划分 |
| 本地影子层 | 未集中区分 ref、snapshot、projection | 单列成员、定义、conversation/runtime、process/governance/artifact、消费投影、追溯交接引用 | 防止外部 truth 或派生结果反写核心 |
| promote 边界 | 混在 WorkItem / child WorkItem 线索中 | 独立为工作拆分与升级边界上下文 | 防止 runtime plan item 或 ImplementationPlan step 污染 Backlog |
| 看板 / 对账 | 容易被视为 Work 内部核心能力 | 放入派生消费辅助和本地投影层 | 读模型和维护结果不得成为第二 truth |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 将 Project、ProjectMember、Backlog、WorkItem、Iteration 分别作为多个核心子域 | 每个对象线索看起来清晰 | 容易形成多个 truth center,后续一致性和归属边界复杂 | 不采用 |
| 方案 B: 一个 `项目工作事实真相核心` + 多个支撑上下文 + 本地影子层 | 保持 truth center 稳定,又能表达能力差异和边界风险 | 后续概要设计需要继续展开核心内部对象 | 采用 |
| 方案 C: 沿用旧 `Project / Planning / Assignment / View` 划分 | 接近旧实现想象 | 过于接近功能 / 模块命名,且 planning / view 容易越界 | 不采用为主结构,仅吸收其中线索 |
| 方案 D: 只保留一个 Work 上下文 | 最简单 | 无法表达成员承担、promote、Iteration、依赖阻塞和派生消费的不同变化方向 | 不采用 |

## 7. 结构化中间产物

### 7.1 子域 / 上下文划分表

| 名称 | 类型 | 作用 | 与其他部分的关系 |
|---|---|---|---|
| 项目工作事实真相核心 | 核心子域 | 承载本仓成立所需的项目工作事实统一语义。 | 是本仓中心上下文,所有支撑上下文围绕它建立关系。 |
| 项目主语上下文 | 支撑子域 | 承载软件项目成为正式工作对象的项目锚点语义。 | 依附项目工作事实真相核心,为成员承担、正式工作和 Iteration 提供归属。 |
| 项目成员承担上下文 | 支撑子域 | 承载 GlobalMember 在项目内承担工作的正式语义。 | 围绕项目主语建立,消费成员引用与承担快照,不拥有成员生命周期。 |
| 正式工作全集上下文 | 支撑子域 | 承载 Backlog 和协作级正式工作全集的收束语义。 | 依附项目主语和项目成员承担,为拆分、依赖和 Iteration 提供全集来源。 |
| 工作拆分与升级边界上下文 | 支撑子域 | 承载正式 child WorkItem 与外部计划步骤之间的升级边界语义。 | 消费正式工作全集和来源引用,只把显式 promote 后的结果写入核心真相。 |
| 工作依赖与阻塞上下文 | 支撑子域 | 承载正式工作之间依赖、阻塞和解除依据的协作语义。 | 消费正式工作全集和完成 / 阻塞依据引用,支撑消费追溯。 |
| Iteration 承诺子集上下文 | 支撑子域 | 承载从正式工作全集中选择当前承诺范围的语义。 | 依附正式工作全集,消费 process 节奏引用,不拥有 process planning 真相。 |
| 项目工作事实消费与追溯上下文 | 支撑子域 | 承载成员、审计者和相邻仓理解同一份 Work 真相的语义。 | 消费核心真相和各支撑上下文,为追溯交接和下游消费提供边界。 |
| 派生消费辅助上下文 | 支撑子域 | 承载看板、投影、索引、对账和维护报告等辅助消费语义。 | 只能从项目工作事实真相派生,不得反写真相。 |
| 成员 / actor 引用与承担快照 | 本地索引 / 投影 / 引用 | 为项目内承担判断和稳定展示提供成员引用或摘要。 | 只保存 ref / snapshot,不拥有身份正文或生命周期。 |
| 方法定义引用与目录快照 | 本地索引 / 投影 / 引用 | 为任务、工作产物、流程模板和视图定义使用提供本地引用。 | 只保存 ref / snapshot,不拥有方法定义正文。 |
| conversation / runtime 来源引用 | 本地索引 / 投影 / 引用 | 为对话建议、handoff、PlanItem promote 和执行来源提供追溯入口。 | 服务工作拆分与升级边界,不拥有对话正文或运行时执行正文。 |
| process / governance / artifact 控制与依据引用 | 本地索引 / 投影 / 引用 | 为 planning 节奏、治理结论和完成依据提供引用或摘要。 | 服务 Iteration、风险变化、完成和阻塞解释,不拥有外部正文。 |
| 工作消费投影 / 看板 / 对账材料 | 本地索引 / 投影 / 引用 | 为查询、看板、维护和一致性解释提供可重建消费结构。 | 服务消费追溯和派生消费辅助上下文,不得成为业务真相写源。 |
| observability / archive 追溯交接引用 | 本地索引 / 投影 / 引用 | 为观测、审计、导出和长期归档交接保留引用入口。 | 服务消费追溯上下文,不拥有全局观测日志或归档正文。 |

### 7.3 本地索引 / 投影 / 引用边界结论

| 本地影子结构 | 允许做什么 | 禁止做什么 |
|---|---|---|
| 成员 / actor 引用与承担快照 | 保存项目内承担判断和展示所需的成员引用或摘要 | 不保存 GlobalMember 生命周期、role definition、认证凭据或身份正文 |
| 方法定义引用与目录快照 | 保存任务、工作产物、流程模板和视图定义引用 | 不保存 method-library 定义正文或标准流程正文 |
| conversation / runtime 来源引用 | 保存正式化来源、handoff、promote 来源和执行上下文引用 | 不保存 conversation fact 正文、聊天消息、PlanItem progress 或 tool execution step |
| process / governance / artifact 控制与依据引用 | 保存 planning 节奏、治理结论、完成依据、阻塞依据和 baseline 引用或摘要 | 不保存 ProcessInstance、Gate、Policy、Approval、Artifact、evidence 或 ImplementationPlan 正文 |
| 工作消费投影 / 看板 / 对账材料 | 支撑授权消费、看板、维护、重建和一致性解释 | 不生成新业务事实,不覆盖 Project、ProjectMember、WorkItem、child WorkItem 或 Iteration 真相 |
| observability / archive 追溯交接引用 | 关联 trace、audit、export、archive 和长期留存入口 | 不拥有全局观测日志正文或长期归档包正文 |

### 7.4 统一语言词汇结论

| 术语 | 含义 |
|---|---|
| 项目工作事实真相核心 | 本仓唯一核心子域,承载项目工作事实内部最稳定的 truth 语义。 |
| 项目主语 | 软件项目作为正式工作对象的项目锚点。 |
| 项目内承担 | GlobalMember 在具体项目内承担工作的正式事实,不同于平台成员身份。 |
| 正式工作全集 | Backlog 和协作级 WorkItem 组成的正式工作范围,不包含默认个人步骤或运行时步骤。 |
| 工作拆分与升级边界 | 协作级 child WorkItem 与 ImplementationPlan step、PlanItem、tool step 之间的 formalize / promote 边界。 |

| 本地索引 / 投影 / 引用 | 为稳定消费、降级显示、判断和追溯保留的本地影子结构,不拥有外部正文。 |

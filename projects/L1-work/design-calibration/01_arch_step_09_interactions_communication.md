## 3. SOP 问题回答

### 3.1 哪些交互适合同步能力边界？

需要即时判断 Work 正式真相是否成立的交互适合同步请求 / 响应类交互。包括项目主语建立或调整、ProjectMember 承担变化、正式工作全集变更、WorkItem / child WorkItem 形成、依赖阻塞变更、Iteration 承诺范围变更、显式 formalize / promote 请求、项目工作事实查询、追溯读取和受控维护触发。这些场景的共同点是调用方必须获得明确结果:已成立、被拒绝、引用不可接受、无权读取或暂不可处理,不能先伪装为成功再由后台补齐。

### 3.2 哪些交互适合异步事件？

已经成立的 Work 事实向相邻仓传播、相邻真相域已经形成的事实或结论进入 Work 边界、ProjectMember 承担变化供 member-service 消费、观测 / 归档材料交接适合异步事件 / 回调类交互。这些场景的重点是事实传播或结果送达,不要求在原始同步请求边界内完成所有下游消费。

### 3.3 哪些交互适合后台任务或补偿路径？

消费视图、看板、任务摘要、投影滞后状态、对账、维护报告、外部快照刷新、引用可解析性刷新、归档准备和一致性检查适合后台任务 / 延后承接类交互。这些交互可以延迟、挂起或重建,但不得反写 Work 真相。

### 3.4 哪些交互必须经过总线或正式边界,不能直接穿透？

跨仓事实传播、相邻真相域变化输入、ProjectMember 变化供运行层消费、observability / archive 交接和下游变化感知必须经过正式事件协作或正式边界,不能让来源仓、下游消费方或横切系统直接写 Work 核心。Workspace、Runtime、Conversation、Process、Governance、Artifact、Member-service 和 SDK 等消费或协作方也只能通过正式入口读写授权事实,不能直接依赖本仓内部真相承载或派生承载。

### 3.5 关键依赖失效时,本仓如何降级或挂起？

同步边界失效时必须返回明确失败、拒绝、不可解析、无权或暂不可处理,不得把未成立状态伪装成已完成。异步传播失败时保留未送达、未消费或待交接状态,已成立的 Work 真相不得回滚为不存在。后台承接失败时保留旧视图、过期标记、未解析引用、挂起重建或对账异常状态,不得伪造外部正文或覆盖核心事实。

### 3.6 哪些通信口径若不先写清,后续最容易误入协议细节？

最容易误入协议细节的口径包括:把 WorkItem 写入写成事件目录、把 Work 事实传播写成同步 fan-out、把看板投影重建写成同步请求成功条件、把 runtime promote 写成 PlanItem 直接落 Backlog、把 artifact evidence 写成 Work 同步拉取正文、把 process planning 写成直接维护 Iteration、把失败处理写成重试脚本。本章只定通信类别和边界原因,具体协议、事件命名和重试机制后移。

## 5. 改动前后对比

| 维度 | 改动前 | 改动后 | 原因 |
|---|---|---|---|
| 通信主语 | 接口、事件、补偿和流程顺序 | 正式交互场景与通信方式类别 | 架构层先判断边界语义 |
| 同步边界 | 可能被事件或后台补偿伪装成成功 | 必须即时判定成立、失败、拒绝或不可处理 | 防止伪同步完成 |
| 异步边界 | 容易写成事件目录或订阅列表 | 表达已成立事实传播或外部结果送达 | 防止事件名替代架构判断 |
| 后台承接 | 与核心写入混在一起 | 只处理派生、刷新、重建、对账和交接材料形成 | 防止维护任务反写真相 |
| 失败口径 | 技术重试细节 | 明确失败、挂起、旧视图、未解析和不得伪造正文 | 对齐 Step 8 一致性策略 |

## 6. 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案 A: 把所有交互都设计成同步请求 / 响应 | 调用方心智简单 | 会强迫事件传播、投影、对账、归档和外部来源刷新进入核心同步链路 | 不采用 |
| 方案 B: 把所有交互都设计成异步事件 | 解耦程度高 | Project、ProjectMember、WorkItem、Iteration 和 promote 缺少即时成立 / 失败口径 | 不采用 |
| 方案 C: 同步收口核心成立判断,异步传播已成立事实,后台承接派生和刷新 | 符合数据归属和一致性策略 | 后续设计需要清楚标注状态和边界 | 采用 |
| 方案 D: 先锁定具体协议和中间件,再反推交互方式 | 实施看似直接 | 会让技术选型反向决定架构语义 | 不采用 |

## 7. 结构化中间产物

### 7.1 关键交互场景表

| 交互场景 | 交互边界 | 交互目的 | 边界说明 |
|---|---|---|---|
| 项目主语与成员承担变更 | 下游消费 / 协作入口边界 ↔ Work 同步入口 | 判断 Project 或 ProjectMember 变化是否正式成立。 | 该场景会改变 Work 真相,必须即时收口。 |
| 正式工作全集变更 | 下游消费 / 协作入口边界 ↔ Work 同步入口 | 判断 WorkItem 或 Backlog 正式工作全集变化是否成立。 | 必须阻断个人步骤、聊天建议和 runtime 局部计划项直接进入。 |
| 正式拆分与 promote | runtime / artifact / conversation 来源边界 ↔ Work 同步入口 | 判断外部计划步骤、对话来源或协作拆分能否形成 child WorkItem。 | promote 后结果属于 Work,来源正文不归 Work。 |
| 依赖阻塞与完成依据判断 | 外部依据 / 工作事实边界 ↔ Work 同步入口 | 判断依赖、阻塞、解除或完成依据是否可被正式表达。 | 需要即时保护正式工作关系和引用有效性。 |
| Iteration 承诺范围变更 | process / planning 协作边界 ↔ Work 同步入口 | 判断当前承诺子集能否从正式工作全集中形成或调整。 | Iteration 是 Work 真相,process planning 只是节奏输入。 |
| 项目工作事实查询与追溯读取 | 下游消费 / 协作入口边界 ↔ Work 同步入口 | 读取 Project、ProjectMember、WorkItem、Iteration、依赖和追溯信息。 | 读取需要即时判断授权、可见性和引用可解析状态,但不得改变业务事实。 |
| 相邻真相域结果送达 | 事件协作 / 外部能力边界 ↔ Work 异步输入 | 承接 identity、conversation、process、governance、artifact、runtime 等已经成立的外部结果或变化。 | 该场景是外部正式结果送达,不是同步穿透来源仓。 |
| Work 事实变化传播 | Work 真相边界 ↔ 事件协作 / 下游消费边界 | 将已经成立的项目工作事实变化传播给相邻仓或消费方。 | 传播失败不能反向取消已经成立的 Work 真相。 |
| ProjectMember 承担变化消费 | Work 真相边界 ↔ member-service / runtime 消费边界 | 将 ProjectMember 与项目承担变化供运行编排或成员容器消费。 | 下游编排消费不能反写 ProjectMember 真相。 |
| 派生消费辅助维护 | Work 真相边界 ↔ 派生视图 / 对账承载 | 维护看板、任务摘要、投影滞后状态、对账和维护报告。 | 派生结果服务消费,不得成为第二 truth。 |
| 外部快照与引用状态刷新 | 外部能力接缝 ↔ 后台维护与派生边界 | 刷新成员、定义、流程、治理、产物、对话、runtime 等快照或引用可解析状态。 | 快照和引用状态可以延迟,不改变来源真相归属。 |
| 追溯 / 观测 / 归档材料交接 | Work 真相边界 ↔ 事件协作 / 追溯交接边界 | 将追溯、观测、维护证据或归档所需材料交给横切系统或归档系统。 | 本仓保留 Work 域追溯记录,不拥有全局日志或归档正文。 |
| 受控维护与重建 | 运维 / 审计入口边界 ↔ 后台维护与派生边界 | 触发派生结果重建、引用刷新、一致性检查或维护报告生成。 | 维护只能修复辅助结构或暴露异常,不得隐式覆盖业务事实。 |

### 7.2 通信方式判断表

| 交互场景 | 推荐通信方式 | 不宜采用的方式 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| 项目主语与成员承担变更 | 同步请求 / 响应类交互 | 不宜以异步事件或后台承接作为主路径 | 明确失败、拒绝或暂不可处理,不得先返回已成立 | 该场景直接改变核心真相边界。 |
| 正式工作全集变更 | 同步请求 / 响应类交互 | 不宜伪装成后台成功后再补写事实 | 明确失败或保持未成立状态,不得落为部分正式工作 | 正式工作全集必须即时满足边界规则。 |
| 正式拆分与 promote | 同步请求 / 响应类交互 | 不宜由 runtime / artifact 事件直接创建 child WorkItem | 来源不可接受时拒绝或保持待 formalize,不得吸收来源正文 | promote 一旦成立就是本仓正式真相。 |
| 依赖阻塞与完成依据判断 | 同步请求 / 响应类交互 | 不宜用后台补偿制造已完成或已解除状态 | 引用不可解析或依据不足时保持未满足、待处理或拒绝 | 依赖、阻塞和完成会影响正式协作判断。 |
| Iteration 承诺范围变更 | 同步请求 / 响应类交互 | 不宜让 process planning 事件直接维护承诺子集 | 候选不合法时拒绝或保持原承诺范围 | Iteration 必须从正式工作全集中形成。 |
| 项目工作事实查询与追溯读取 | 同步请求 / 响应类交互 | 不宜以异步推送替代正式读取判断 | 返回可见结果、不可见、不可解析或暂不可读取 | 读取边界要即时执行授权和可见判断。 |
| 相邻真相域结果送达 | 异步事件 / 回调类交互 | 不宜要求来源仓同步穿透本仓核心 | 保持未送达、待解析、待刷新或不可接受状态 | 来源事实已在来源仓成立,进入 Work 应通过正式边界送达。 |
| Work 事实变化传播 | 异步事件 / 回调类交互 | 不宜写成同步 fan-out 主路径 | 保持未消费、待交接或延后传播状态 | 事实已成立,传播失败不应回滚核心真相。 |
| ProjectMember 承担变化消费 | 异步事件 / 回调类交互 | 不宜让 member-service 同步绑定 Work 内部真相承载 | 保持未消费或待同步状态,不得反写 ProjectMember | 运行编排消费是下游感知,不是 Work 真相来源。 |
| 派生消费辅助维护 | 后台任务 / 延后承接类交互 | 不宜阻塞核心同步变更 | 保留旧视图、过期标记或挂起重建 | 派生结果最终一致,可延迟和重建。 |
| 外部快照与引用状态刷新 | 后台任务 / 延后承接类交互 | 不宜把快照刷新写成核心事实成立前置 | 保留旧快照、未解析引用或待刷新状态 | 快照和引用状态服务稳定消费,不拥有外部正文。 |
| 追溯 / 观测 / 归档材料交接 | 异步事件 / 回调类交互 | 不宜要求横切系统同步决定业务事实 | 保持待交接、未消费或延后归档状态 | 横切消费失败不能反向改变 Work 真相。 |
| 受控维护与重建 | 后台任务 / 延后承接类交互 | 不宜伪装成同步业务变更成功 | 挂起、失败或输出异常状态,不得覆盖业务事实 | 维护任务只修复派生或暴露问题,不是业务事实来源。 |

### 7.3 简化交互示意图

```text
+-----------------------------+        +-----------------------------+
| 下游消费 / 协作入口边界     |        | 事件协作 / 来源事实边界     |
| sdk / workspace / peers      |        | bus / source truth domains  |
+-------------+---------------+        +-------------+---------------+
              | [sync request / response]            |
              v                                      | [async event / callback]
+-------------+---------------+                      v
| Work 同步入口               |        +-------------+---------------+
+-------------+---------------+        | Work 异步输入消费          |
              |                        +-------------+---------------+
              +------------------+-------------------+
                                 |
                                 v
                      +----------+-----------+
                      | Work 真相边界        |
                      +----+-------------+---+
                           |             |
             [async event] |             | [background]
                           v             v
             +-------------+------+   +--+----------------+
             | 下游 / 追溯 / 归档 |   | 派生 / 对账承接  |
             | 交接边界           |   |                  |
             +--------------------+   +-------------------+
```

图示说明:

- 同步请求 / 响应用于即时判断 Work 核心状态是否成立,不是表达具体协议。
- 异步事件 / 回调用于已成立事实传播或外部结果送达,不是事件目录。
- 后台任务 / 延后承接用于派生、刷新、重建、对账和交接材料形成,不得反写真相。
- 该图不表达接口路径、事件名、处理顺序或运行部署拓扑。

### 7.4 边界说明

`L1-work` 的通信方式按边界语义选择:核心真相是否成立需要同步收口,已成立事实或外部结果送达适合异步传播,派生、刷新和对账适合后台延后承接。同步返回成功只能表示该同步边界内的正式判断已经成立,不能代替后续投影、下游消费、观测或归档交接完成。异步和后台失败只能表现为未送达、待交接、旧视图、未解析、对账异常或挂起,不能回滚已经成立的 Work 真相。具体协议、事件命名、重试策略和运行单元分配留到后续设计。

- 已明确同步请求 / 响应、异步事件 / 回调、后台任务 / 延后承接的适用场景。
- 已明确不宜采用的方式和失败处理口径。
- 未写接口目录、事件目录、时序图、协议选型、技术产品或失败机制实现。
- 可以进入 Step 10“关键技术选型”。

## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_position_boundary.md`
>
> 延伸阅读：
> - 建议阅读该文件的“问题回答”“拥有与不拥有”和“诊断与取舍”小节。

| 字段 | 结论 |
|---|---|
| 一句话定义 | `L1-workspace` 是跨 L1 真相域的只读工作区视图与投影局部状态仓。 |
| 单独成仓原因 | 为产品、同步和成员入口提供统一、可解释、可重建的跨域 read model，并隔离业务 truth、授权裁决和 UI/client state。 |
| 本仓拥有 | view partition、projection revision/generation、source cursor/application record、coverage/gap、InboxItem 派生状态、ReadCursor、unread、pin/mute、preference、last-opened、focus。 |
| 本仓不拥有 | identity、work、conversation、process、governance、artifact、runtime、tools、capability registry、sandbox、archive、SDK cache 或产品 UI truth。 |
| 查询边界 | 所有 source query 保持 no-write。 |
| 写入边界 | 只允许 workspace-owned local state；不得通过投影反写任何上游 truth。 |

`PersonalWorkspace` 与 `ProjectWorkspace` 是同一 read-model 框架的两种 scope，不是新的业务生命周期主体。`InboxItem` 是来源事实的派生投影；本地 read/pin/mute/preference 不能替代消息、任务、流程、治理或项目成员事实。

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：
> - 建议阅读该文件的“问题回答”“业务问题与技术问题”和“旧材料诊断”小节。

平台需要让成员在个人和项目语境中查看多个 L1 真相域的安全摘要、引用和 attention 输入。若产品、同步入口或运行层各自聚合，会形成重复 read model、来源版本不可解释、可见性裁剪不一致和局部状态反写风险。

当前主要问题是：跨域读取缺少统一 workspace read model；来源版本、水位和覆盖范围难以解释；事件重复、乱序和缺口容易被压成一个“当前状态”；本地未读/置顶状态容易被误认为业务事实；授权/可见性可能被视图层自行推断；下游缺少稳定的只读消费面。

业务问题是成员无法获得可信且按 scope 裁剪的工作区视野。技术问题是 query、event、version、cursor、visibility 和 rebuild seam 尚未形成统一消费合同，无法在没有 owner-safe 输入时证明完整性。

## 5. 用户与角色

> 校准来源：
> - `design-calibration/00_req_step_05_users_roles.md`
>
> 延伸阅读：
> - 建议阅读该文件的“角色结论”和“权限边界”小节。

| 角色 | 类型 | 使用场景 |
|---|---|---|
| 成员/产品用户 | 人类或受限系统主体 | 读取 Personal/Project workspace，更新 workspace-owned local state。 |
| 产品/同步调用方 | 系统角色 | 通过正式 read surface 消费 workspace model。 |
| Workspace maintainer | 人类/系统维护角色 | 观察 cursor、gap、projection status，发起 refresh/rebuild。 |
| 审计/安全查看者 | 人类角色 | 查看 provenance、visibility 裁剪、失效和降级原因。 |
| Projection worker | 系统角色 | 应用 owner event、维护投影和幂等记录。 |
| Owner query/event provider | 外部系统角色 | 提供正式 query、event、visibility 或 replay/baseline seam。 |

用户只能修改 workspace-owned local state；维护者不能修复上游 truth；审计者只读；owner provider 只提供自身事实；任何角色都不能通过 workspace 形成 authorization truth 或业务命令。

|---|---|---|---|---|---|

### 6.2 依赖类型与禁止依赖

只有 `L0-core` 是编译期候选。L1 owner 的 query/ref/event 是运行期或事件协作；SDK/product/sync/archive 是下游 adapter/ref；fake 只用于后续受控测试。禁止共享 L1 内部表、建立 L1 path dependency、projection 反写 owner truth、本地 allowlist、把 read cursor 写为 conversation receipt、把 bus delivery 或 archive acceptance 写成 workspace state。

### 6.3 依赖裁剪图

```text
L0-core --[compile]--> L1-workspace
L0-bus --[event]-----> L1-workspace
L1 owners --[runtime/ref]--> L1-workspace --[adapter/ref]--> SDK/product/sync/archive
```

## 7. 核心能力闭环

> 校准来源：
> - `design-calibration/00_req_step_07_core_capability_loop.md`
>
> 延伸阅读：
> - 建议阅读该文件的“能力节点与顺序”“进入/退出条件”和“外围/边界外能力”小节。

### 7.1 闭环定义

```text
C-WS-1 scope/principal 语境
        -> C-WS-2 owner query 与 visibility 裁剪
        -> C-WS-3 event/cursor 投影维护
        -> C-WS-4 可解释 read model
        -> C-WS-5 workspace-only attention state
        -> C-WS-6 refresh/rebuild/degraded closure
```

| 能力节点 | 成立条件 | 失败上限 |
|---|---|---|
| `C-WS-1` | principal、scope/ref、visibility 基础可验证。 | invalid/unauthorized/fail-closed。 |
| `C-WS-2` | owner query 返回 source version/watermark/coverage。 | partial/blocked/unavailable。 |
| `C-WS-3` | baseline/event 可按 cursor、幂等和版本规则应用。 | duplicate/late/conflict/gap。 |
| `C-WS-4` | view revision 可回链 provenance 与 visibility binding。 | stale/partial/blocked。 |
| `C-WS-5` | local state 绑定 principal/scope。 | conflict/unauthorized。 |
| `C-WS-6` | refresh/rebuild 有 generation、cutover 或 blocked 结论。 | rebuilding/blocked/failed。 |

搜索、统计、历史比较、预测性 ranking 和 archive freeze 是外围增强；上游 truth、授权裁决、业务命令、运行/工具/sandbox、SDK/UI/cache 和 archive truth 是边界外能力。

## 10. 业务规则与边界约束

> 校准来源：
> - `design-calibration/00_req_step_10_business_rules_boundaries.md`
>
> 延伸阅读：
> - 建议阅读该文件的“业务规则表”和“一票否决候选”小节。

| ID | 类型 | 规则 |
|---|---|---|
| `BR-WS-001` | 不变量 | workspace 只拥有 view/projection/local state，不拥有任何 L1 truth。 |
| `BR-WS-002` | 边界 | source query 必须 no-write，不共享表或跨仓事务。 |
| `BR-WS-003` | 安全 | visibility/membership/治理决定来自 owner；缺失、冲突或撤销时 fail-closed。 |
| `BR-WS-004` | 一致性 | source cursor、view revision、read cursor 不可互相替代。 |
| `BR-WS-005` | 幂等 | 重复输入不得重复投影事实或 unread。 |
| `BR-WS-006` | 乱序 | 无法证明版本顺序时保留 conflict/gap，不猜补。 |
| `BR-WS-007` | 显式变化 | invalidation、refresh、rebuild 和 generation cutover 可追溯。 |
| `BR-WS-008` | 局部状态 | local state 只能作用于绑定 principal/scope。 |
| `BR-WS-009` | Inbox | 只有 owner 明示 attention input 才形成 InboxItem。 |
| `BR-WS-010` | 降级 | stale、partial、blocked、fail-closed 必须可区分。 |
| `BR-WS-011` | 禁止 | query、projection、维护和导出不得反写上游 truth。 |
| `BR-WS-012` | 依赖 | runtime/event/ref/adapter/fake 不得写成 compile；fake 不证明集成。 |

一票否决：把 workspace 当身份/成员/授权/业务 truth；缺 visibility 默认展示；query 修改事实；静默跳过 cursor gap；stale 冒充 fresh；projection 反写 owner；伪造未闭合 event/query 合同。

## 13. 非功能需求

> 校准来源：
> - `design-calibration/00_req_step_13_non_functional_requirements.md`

| 类别 | 要求 | 判断口径 |
|---|---|---|

| 一致性 | 三类 cursor 分离，跨域结果声明水位和覆盖。 | 不承诺无 barrier 的全局强一致。 |
| 可用性 | 依赖不可用时保留 stale/partial/blocked/unavailable。 | 不伪造 ready 或完整。 |
| 安全 | visibility 不可验证时 fail-closed。 | 只有正式 owner decision/ref 可展示。 |
| 可追溯 | projection、Inbox、local state、rebuild、export 可回链。 | 具备 source ref/version、revision 和原因。 |
| 可演进 | 新域/事件/字段不迫使复制 source schema。 | 通过 ref/adapter 和 pending 承接。 |

具体 P95、吞吐、容量、SLA、缓存命中率和保留期等待正式 workload/measurement baseline。

## 5. 模块实现契约

> 校准来源：[Step5 模块契约](design-calibration/03_ddd_step_05_module_contracts.md)、[Step6 对象](design-calibration/03_ddd_step_06_object_contracts.md)、[Step7 ports](design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md)。

第 5 章是实现主轴。模块依赖方向为：`contracts → domain → application`；`infra → application/domain/contracts`；`api → application/contracts`；`worker/jobs → application/contracts`，仅 composition root 使用 infra。

| 模块 | 职责 | 对外边界 | 禁止 |
|---|---|---|---|
| contracts | DTO、typed ref/version/state、safe view、receipt、error | 受控 public constructors/getters | 不复制 owner schema，不依赖 domain/application |
| domain | WorkspacePartition、Projection、Coverage、Inbox、Local、Recovery、ReadView 等局部 truth | 私有字段、验证工厂、纯 projector | 不读 repository/config，不实现 authorization |
| application | 七 service、read/write 能力 ports、UoW、幂等与错误编排 | 具名 service 方法 | 不依赖具体 infra，不提供万能 dispatcher |
| infra | 本地存储、owner/visibility/bus/recovery 技术绑定、config/builder | builder 与能力句柄 | 不决定 owner allow，不以 fake fallback |
| api | 2 Command + 6 Query handler | typed library handler | 不直连 store/domain，不增加 HTTP truth |
| worker | 2 inbound consumer、受控 loop | consumer callable | 不发布 outbound、不写 owner |
| jobs | 4 有界 operation handler/binary | Request/Advance/Supersede/Invalidate | 不自动循环、不创建 archive handoff |

每模块的文件、对象映射、错误与测试入口以 Step5 §7.1~7.8 为准。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源：[Step8](design-calibration/03_ddd_step_08_protocol_contracts.md)。

协议均为 typed library surface；外部 route/topic/schema 尚未绑定。QueryMetadata.consistency 仅接受 Eventual；Strong 输入按 InvalidRequest，不承诺跨域线性一致。写入 metadata 必须有幂等键，Query metadata 必须无写字段。

### 7.1 公共 key、digest 与错误

`WorkspaceOperationKey = { actor_id, scope, channel, kind, key }`；partition、expected、budget 属于 digest，不属于 key。  
`SourceApplicationKey = { owner, stream, event, partition, generation }`。  
Source invalidation child key 使用 canonical event identity + partition UUID + target principal canonical 的 length-prefixed 编码；source actor 仍是认证 actor。

SafeInputDigest 使用 SHA-256 length-prefixed canonical encoding；不含 idempotency key、trace/request id、时间或随机结果 ID。owner ref/basis 没有正式 canonical codec 时返回 ContractBlocked，不用 String/JSON 代替。

| ApplicationError | public mapping |
|---|---|
| InvalidInput | InvalidRequest / Blocked |
| ScopeUnavailable、VisibilityUnavailable、NotFound、SafetyBlocked | NotAvailable / Blocked |
| ContractBlocked | ContractBlocked / Blocked（scope 未公开时降为 NotAvailable） |
| SourceUnavailable、StorageUnavailable | SourceUnavailable / Unavailable |
| Conflict | Conflict / Blocked |
| CursorInvalid | CursorInvalid / Blocked |
| OutcomeUnknown | OutcomeUnknown / Unavailable |
| InvariantViolation | NotAvailable / Blocked |

### 7.2 14 个协议摘要

| 协议 | 成功结果 | 关键门禁 |
|---|---|---|
| ProvisionWorkspacePartition | WorkspaceWriteResult | resolver、principal、stable scope；不初始化 projection/local |
| ChangeWorkspaceLocalState | WorkspaceWriteResult | explicit expected_local；attention binding；只改 local |
| GetWorkspaceView | WorkspaceViewResponse | Materialized/Transient；现时 visibility；不刷新 |
| ListWorkspaceInbox | WorkspaceInboxResponse | owner attention relation；local 缺失不初始化 |
| GetWorkspaceLocalState | WorkspaceLocalStateResponse | 无 partition 返回 Absent；不更新 last_opened |
| GetWorkspaceOperationResult | WorkspaceOperationResponse | immutable original result；缺行不等 rollback |
| GetWorkspaceRecoveryStatus | WorkspaceRecoveryResponse | 只读 snapshot；不自动 Advance |
| ExportWorkspaceReadModel | WorkspaceExportResponse | 只读导出；不生成 archive artifact |
| ConsumeSourceChange | SourceChangeReceipt | identity/order/digest/visibility；Applied/LateIgnored terminal |
| ConsumeSourceInvalidation | SourceInvalidationPageReceipt | owner proof、bounded fanout；每 target 独立结果 |
| RequestWorkspaceRecovery | WorkspaceWriteResult | 新 candidate/attempt；current 不变 |
| AdvanceWorkspaceRecovery | WorkspaceWriteResult | 一次一个 bounded phase/budget；不自动循环 |
| SupersedeWorkspaceRecovery | WorkspaceWriteResult | 同 partition replacement、无环 |
| InvalidateWorkspaceView | WorkspaceWriteResult | target/basis 全量校验；DataStale 与 SafetyBlocked 分离 |

完整 request/response 字段、工厂与 receipt 见 Step8 §7.3~7.6；不把摘要当完整 schema。

## 8. 逐接口函数级处理流

> 校准来源：[Step9](design-calibration/03_ddd_step_09_function_flows.md)。

所有写/consumer flow 遵守：认证 actor → resolver/visibility → operation lookup（如适用）→ coherent snapshot → domain validation → named commit → resolve unknown。Query 只读 owner/source/store port，不创建或更新任何本地状态。

| Flow | 关键步骤 | 原子/失败姿态 |
|---|---|---|
| ProvisionWorkspacePartitionFlow | resolve scope → find/operation → create partition | partition+operation+commit result 同事务 |
| ChangeWorkspaceLocalStateFlow | resolve → relation/binding → expected local CAS | local+operation 同事务 |
| GetWorkspaceViewFlow | resolve → materialized snapshot或owner safe slice → bind/revalidate → compose | stale/partial可显式返回；安全未知 fail-closed |
| ListWorkspaceInboxFlow | snapshot → current item visibility → attention relate → classify/order/page | 无 local 零写；关系未知为 Unknown |
| GetWorkspaceLocalStateFlow | resolve → snapshot local → safe crop | Absent 不隐式创建 |
| GetWorkspaceOperationResultFlow | authorize → operation_by_ref → immutable result | 缺行 NotAvailable/OutcomeUnknown，不重跑 |
| GetWorkspaceRecoveryStatusFlow | authorize → recovery snapshot → safe response | 不启动 Advance |
| ExportWorkspaceReadModelFlow | 同 safe read → schema v1 response | 不写 artifact/archive |
| ConsumeSourceChangeFlow | validate envelope → key/digest → classify → projector → apply | Gap 不占 source terminal key；unknown Pending |
| ConsumeSourceInvalidationFlow | validate owner proof → bounded targets → per-target invalidate | 无全局原子假设；每目标独立 commit |
| RequestWorkspaceRecoveryFlow | snapshot → create candidate/attempt | current 保留；Requested/Unverified |
| AdvanceWorkspaceRecoveryFlow | one baseline/catch-up/validate/cutover branch | 缺 proof blocked；终态不可复活 |
| SupersedeWorkspaceRecoveryFlow | validate replacement same partition/no cycle | 只更新旧 attempt |
| InvalidateWorkspaceViewFlow | validate basis/targets → append invalidation → apply safety effects | target 集合变化或缺 basis 拒绝 |

函数签名和伪代码以 Step7 §7.5、逐 flow 事务明细以 Step9 §7.2~7.10 为准。

## 10. 数据持久化、事务与一致性契约

> 校准来源：[Step11](design-calibration/03_ddd_step_11_persistence_transaction_consistency.md)。

### 10.1 逻辑存储

| 存储 | 唯一键/版本 |
|---|---|
| partitions | partition_id；(principal, StableScopeKey) unique；PartitionVersion |
| projections | (partition, generation)；ViewRevision |
| source_applications | SourceApplicationKey unique；result_ref unique |
| coverage | (partition, generation, stream)；随 projection view revision |
| inbox_items | (partition, generation, InboxItemId)；view revision |
| local_attention | partition；LocalRevision |
| read_cursors | (partition, AttentionStreamRef)；local revision |
| recovery_attempts | attempt_id；AttemptVersion |
| generations | (partition, generation)；每 partition 一个 Current |
| invalidations | invalidation_id；append-only |
| operation_records | WorkspaceOperationKey unique；result_ref unique |
| commit_results / gap_results / baseline_applications | CommitAttemptId 或 binding unique；技术 carrier，不是新业务 truth |

### 10.2 一致性规则

- 写事务在 partition 内用行锁或等价串行冲突控制；网络 owner read 在事务前完成。
- 所有本地效果与 immutable operation/commit result 同事务；partial write 不可见。
- SourceApplicationRecord 终局仅 Applied/LateIgnored；Gap 是独立 receipt，不能占用 source success key。
- Cutover 需 candidate Validated、完整 CutoverBasis、当前失效集合与 owner proof 全部匹配；变化则保留 current。
- Query 使用 coherent MVCC snapshot，绝不持写锁或持久化 page snapshot；超限整体失败，不截断为 Complete。
- 无 TTL/GC/key reuse；容量不足拒绝受影响写，不删除证据后接受重复。

## 11. 错误、异常与恢复

> 校准来源：[Step12](design-calibration/03_ddd_step_12_error_recovery.md)。

ApplicationError 是 12 变体：InvalidInput、ScopeUnavailable、VisibilityUnavailable、ContractBlocked、SourceUnavailable、NotFound、Conflict、CursorInvalid、SafetyBlocked、OutcomeUnknown、StorageUnavailable、InvariantViolation。公共映射见 §7.1；公开错误先经过 scope publicability gate，不泄露隐藏存在性、计数、主体或 raw cause。

恢复原则：

1. durable commit 缺行、超时、进程死亡、只读副本未见结果均为 Pending/OutcomeUnknown，先 `resolve_commit`，不得换 key 自动重做。
2. technical failure 不自动把 RebuildAttempt 写成 Blocked/Failed；只有具名 failure basis 才能持久化该状态。
3. Recovery 四终态不可复活；Ready 仅可因 lawful changed basis 返回 Validating，不得绕过 SafetyBlocked。
4. source gap 不声称 terminal source application；missing owner proof、schema 或 visibility 时 fail-closed。
5. InvariantViolation 不向外暴露内部诊断；storage/source unavailable 不伪造空成功。

详见 [Step12](design-calibration/03_ddd_step_12_error_recovery.md)。

## 12. 并发、幂等与重入保护

> 校准来源：[Step13](design-calibration/03_ddd_step_13_concurrency_idempotency.md)。

| 场景 | 规则 |
|---|---|
| 相同 WorkspaceOperationKey | 先 lookup；同 digest 返回 immutable 原结果，异 digest Conflict |
| 相同 SourceApplicationKey | 先 lookup；Applied/LateIgnored 返回原记录；Gap/Unknown 不伪造 terminal |
| 不同 key 并发 | 同 partition 串行 CAS；expected mismatch Conflict |
| 重复/乱序事件 | canonical identity + digest 去重；late 只能在 owner proof 支持时 LateIgnored；gap 保守停留 |
| commit outcome | 新分配 tentative result_ref 与已存 result_ref 区分；碰撞拒绝；unknown 先 resolve |
| Query 并发 | 无写能力、无 refresh、无 read cursor 更新；现时 authorization 在输出屏障复核 |
| Recovery | 不设置 running reservation、TTL 或自动 retry；每次 Advance 有界且显式 |

Digest 包含 expected/budget 等影响行为字段；修改 expected 必须新显式意图/新 key，旧 unknown 先解析。

## 13. 配置引用与外部依赖绑定

> 校准来源：[Step14](design-calibration/03_ddd_step_14_config_external_binding.md)。

计划 `WorkspaceLimits` 字段：
`max_request_bytes`、`max_page_items`、`max_page_token_bytes`、`max_snapshot_rows`、`max_snapshot_bytes`、`max_commit_rows`、`max_commit_bytes`、`max_recovery_items`、`max_invalidation_targets`、`max_in_flight`、`owner_read_timeout`、`store_read_timeout`、`store_commit_timeout`、`shutdown_timeout`。数量使用 NonZeroUsize/NonZeroU32，Duration 必须 >0；本章不发明默认值，04 负责来源、优先级、profile、driver/transport/schema。

Cursor envelope 采用 AES-256-GCM：96-bit 随机 nonce、128-bit tag、16-byte key id、32-byte secret；header `WSCP/version1/key_id` 作为 AAD，base64url 无 padding。plaintext 必须使用 owner codec，不能 arbitrary JSON；密钥不实现 Debug/Serialize/Clone，不提供 public secret getter。

WS-LOCAL-002（配置/transport/endpoint/schema）和 WS-LOCAL-003（crypto/UUID/CSPRNG/dependency pin/MSRV 验证）未关闭；未闭合时受影响 capability 返回 blocked/unavailable。

## 14. 可观测性与审计埋点

> 校准来源：[Step15](design-calibration/03_ddd_step_15_observability_audit.md)。

默认日志仅记录固定 entry/stage/outcome/slot、duration、safe read axes，以及经宿主批准的 trace/request 维度。禁止 actor、scope、partition、generation、item、event、stream、result、commit attempt、owner proof/body、cursor、key、digest、DSN 或 secret。

metrics 只使用固定 cardinality：entry、stage、outcome、slot、availability、safe failure category、duration buckets、bounded resource category；不建立跨 partition view revision gauge。audit 复用同事务 operation/source/gap/commit 记录，不新增审计 truth。sink 丢失不改变业务结果、不触发 replay。Telemetry 不是测试 evidence。

## 17. 风险与待确认事项

> 校准来源：[Step18](design-calibration/03_ddd_step_18_risks_open_questions.md)。

### 17.1 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| source coverage、cursor、delivery 混同 | 错误去重/吞 gap | typed 轴分离；Gap 非 terminal |
| visibility/撤销缺口 | 泄露正文或元信息 | owner 当前决定；缺失 fail-closed |
| unknown commit 误判 rollback | 双写/结果漂移 | resolve；Pending 不换 key |
| cutover 与 invalidation 竞争 | 不安全候选提升 | partition 串行化、全量 fence、SafetyBlocked |
| attention 被投影反造 | 污染 Inbox/read truth | 仅消费 owner 明示 attention |
| 配置/token/日志旁路泄露 | 越权或凭据泄露 | AEAD、redaction、无业务 ID 默认日志 |
| 下游反向定义 workspace | 吞并 archive/runtime/seed truth | 仅提供 read model；archive 串行后续 |
| 无限增长/无界 fanout | 恢复与存储不可控 | typed limits；超限失败、不截断 Complete |

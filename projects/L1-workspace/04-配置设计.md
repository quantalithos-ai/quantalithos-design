## 1. 与上游文档的关系声明

> 校准来源：[Step1](design-calibration/04_config_step_01_upstream_boundary.md)。

本设计承接 [03-详细设计](03-详细设计.md) §13 的 WorkspaceLimits、cursor envelope、runtime builder、adapter availability，以及 §10~16 的事务、错误、观测和测试边界。配置不重新定义对象、trait、协议、状态、授权或事件 schema；具体 owner/driver/provider 未闭合处保持 pending/blocker。

## 2. 本次配置设计目标与范围

> 校准来源：[Step2](design-calibration/04_config_step_02_02_scope.md)。

目标是为资源预算、超时、技术绑定、密钥引用、运行 profile 和可观测性提供显式 typed 控制面。非范围包括业务 truth、owner authorization、source identity/digest、projection 状态、SDK/cache、产品 UI、archive、部署命令和运维值班流程。

## 3. 配置控制面总览

> 校准来源：[Step3](design-calibration/04_config_step_03_03_control_plane.md)。

| 配置域 | 控制内容 | 消费模块 |
|---|---|---|
| resource | 请求、页、快照、提交、恢复、失效和并发限额 | infra/application/api |
| timeout | owner/store读写与shutdown超时 | infra/runtime builder |
| storage | driver、隔离与事务能力引用 | infra/store adapter |
| owner/bus | owner safe read、visibility、event transport绑定 | infra adapters/worker |
| cursor crypto | AES-256-GCM key reference、key id | infra cursor codec |
| observability | redaction profile、固定采样 | infra/入口 |
| lifecycle | profile、加载/变更/回滚策略 | runtime builder |

## 4. 配置分类与边界

> 校准来源：[Step4](design-calibration/04_config_step_04_04_categories_boundaries.md)。

允许配置：容量、超时、并发、技术端点引用、driver/transport选择、profile、secret reference、日志采样。禁止配置：actor/scope/visibility授权、source event identity、digest/key算法、状态迁移、projection字段、owner正文、archive接收语义、fake-success开关。feature flag不得改变这些禁止项。

## 5. 配置来源、优先级与冲突处理

> 校准来源：[Step5](design-calibration/04_config_step_05_05_sources_priority.md)。

来源优先级由低到高为：编译时固定安全常量、受控配置文件、环境变量/secret reference、宿主显式覆盖（仅允许覆盖项）。未知键、重复键、类型错误、profile冲突和同优先级不一致均 fail-fast；不以最后写入胜出消除冲突。具体文件路径、环境变量名称和平台注入属于后续部署/运维资料，不在本文伪造。

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：[Step6](design-calibration/04_config_step_06_06_environment_matrix.md)。

| profile | store/owner能力 | 安全姿态 | 允许 |
|---|---|---|---|
| local | typed fake仅用于局部开发验证 | 不代表真实授权/投递 | 明确fixture；禁止生产 fallback |
| test | 受控 fake/fixture与故障注入 | 正向外部slot可标blocked | 配置边界与负例验证 |
| staging | durable/真实接缝待绑定 | fail-closed | 仅经批准的非生产凭据 |
| production | durable、owner/bus正式绑定 | 无fake、secret provider必需 | 真实部署由实施/运维定义 |

表中不填写真实 DSN、数值 baseline、拓扑或部署命令；profile 不能改变业务状态、授权或 no-write 规则。

## 7. 配置项清单

> 校准来源：[Step7](design-calibration/04_config_step_07_07_item_inventory.md)。

所有项均为显式必填、类型化、无默认值；数值必须为正并满足资源关系约束。WorkspaceLimits 项与 03 §13 一一对应。

| 配置项 | 类型 | 必填 | 来源/作用域 | 敏感 | 生效/失败 |
|---|---|---:|---|---|---|
| resource.max_request_bytes | NonZeroUsize | 是 | profile | 否 | 启动校验；超限拒绝 |
| resource.max_page_items / max_page_token_bytes | NonZeroUsize | 是 | profile | 否 | 启动校验；Cursor/请求超限拒绝 |
| resource.max_snapshot_rows / max_snapshot_bytes | NonZeroUsize | 是 | profile | 否 | 启动校验；不截断Complete |
| resource.max_commit_rows / max_commit_bytes | NonZeroUsize | 是 | profile | 否 | 提交前校验；超限失败 |
| resource.max_recovery_items / max_invalidation_targets | NonZeroUsize | 是 | profile | 否 | 单次有界；超限拒绝 |
| resource.max_in_flight | NonZeroUsize | 是 | profile | 否 | 运行期并发上限 |
| timeout.owner_read / store_read / store_commit / shutdown | Duration>0 | 是 | profile | 否 | 超时按03错误映射 |
| binding.store_driver | typed driver ref | 是 | profile | 否 | 缺失Unavailable |
| binding.owner_transport / bus_transport | typed transport ref | 条件必填 | profile | 否 | 未闭合slot blocked |
| binding.cursor_key_ref | typed secret ref | 是 | global/profile | 是引用 | provider不可用则Unavailable |
| observability.redaction_profile | typed profile | 是 | process | 否 | 未知值fail-fast |

完整字段约束与构造见 03 Step14。

### 完整配置 demo

~~~json
{
  "schema_version": 1,
  "profile": "<local|test|staging|production>",
  "resource": "<see resource demo>",
  "timeout": "<required durations>",
  "binding": {
    "store_driver": "<required typed ref>",
    "owner_transport": "<blocked until owner contract>",
    "bus_transport": "<blocked until event contract>",
    "cursor_key_ref": "<secret reference only>"
  },
  "observability": { "redaction_profile": "<required>" }
}
~~~

## 8. 敏感配置与密钥管理

> 校准来源：[Step8](design-calibration/04_config_step_08_08_secrets.md)。

只存 secret reference，不存明文 key/password/DSN/private key。cursor 使用 03 已定 AES-256-GCM envelope；provider 按 key id 读取，密钥对象不得 Debug/Serialize/Clone 或提供公开 secret getter。轮换须保留旧 key 解码窗口；移除前确认无旧 token 依赖。日志、审计和配置快照不记录 secret/value/body。provider、rotation API 和实际凭据尚未确定，标 WS-LOCAL-003。

## 9. 配置加载、校验与生效机制

> 校准来源：[Step9](design-calibration/04_config_step_09_09_loading_validation.md)。

流程：解析来源 → profile 合并 → schema/未知键检查 → 类型与正数/关系校验 → secret reference 解析 → capability binding → runtime builder 构造读写能力。启动校验失败 fail-fast；安全、driver、limits 和 schema 变更需重启。仅经批准的非安全热更新可在版本化快照上切换，不能写 projection、cursor 或 operation。

## 10. 配置变更、审计与回滚

> 校准来源：[Step10](design-calibration/04_config_step_10_10_change_audit.md)。

配置快照带单调 revision；原子校验通过后切换，失败保留旧快照。审计仅记录操作者类别、配置域、revision、结果和安全摘要，不记录 secret/value/body。回滚只能回到已验证快照，不回滚业务状态、projection、cursor、operation；持久化审计若超出技术日志需先回写03，当前未新增对象。

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：[Step11](design-calibration/04_config_step_11_11_failure_modes.md)。

| 失效 | 结果 |
|---|---|
| 必填缺失、未知键、类型/profile冲突 | 启动 fail-fast |
| owner/visibility/bus不可达 | 受影响能力 Unavailable/Blocked；不返回空成功 |
| store不可达或提交 unknown | StorageUnavailable/OutcomeUnknown；先权威 resolve |
| cursor key/provider不可用 | CursorInvalid/Unavailable；禁止明文降级 |
| limits超限 | InvalidRequest；不得截断为 Complete |
| telemetry sink丢失 | 不改变业务结果，不触发 replay |
| production fake/missing capability | Disabled/Missing；不自动替换 |

错误枚举和公开映射复用 03 §7/§11，不新增 ApplicationError。

## 12. 测试、验收、实施与运维承接

> 校准来源：[Step12](design-calibration/04_config_step_12_12_handoff.md)。

05 需覆盖来源优先级、未知键/类型拒绝、边界与关系校验、secret redaction、四 profile 能力矩阵、故障姿态和热更新限制；06 将其转为验收条件；07 按配置域/profile建立 planned boundary 与 implementation ledger。部署注入、凭据轮换、监控和值班属于运维资料。当前不创建05~07、不写 case ID、run、baseline 或 readiness。

## 13. 配置迁移、废弃与演进

> 校准来源：[Step13](design-calibration/04_config_step_13_13_evolution.md)。

schema 带版本；新增配置先扩展校验，再在获准 profile 启用，不提供隐式默认。废弃项先告警后拒绝的窗口需运维批准。迁移只转换配置，不迁移 projection/cursor/operation；driver、transport、算法或 token plaintext 变更需兼容性、密钥轮换和回滚审查。若改变03字段、状态或port，必须停止并回写03。

### 1.2 权责与依赖边界

- L1-workspace 只拥有 workspace view、projection、coverage、cursor、generation、recovery record 和 local attention state。
- identity、conversation、work、process、governance、artifact、runtime、tools、member、SDK/cache、产品UI和archive truth均在仓外。
- 六个 Query 与 owner safe query 都是 no-write；查询不得初始化local state、刷新projection、推进read cursor或反写owner。
- L0-core仅是compile dependency候选；L0-bus为event主干；其他跨仓关系必须保持runtime/event/ref/adapter，test double明确标fake。
- owner query/event/visibility/attention/baseline的成功输入必须来自正式版本化合同；fake只能证明workspace本地机制和失败分类。
- L4-archive只能在本项目停审后作为下游只读消费者继续设计，不能反向定义workspace export或archive truth。

## 2. 本次测试目标与范围

> 校准来源：
> - [Step2 测试目标、范围和非范围](design-calibration/05_test_step_02_02_scope.md)
>
> 延伸阅读：

### 2.1 测试目标

| 目标 | 必须证明 |
|---|---|
| owner边界 | workspace存储、协议和副作用不拥有或反写上游/runtime/archive truth |
| 安全只读视图 | principal/scope、provenance、revision、coverage、freshness、availability可解释；现时visibility不可验证即fail-closed |
| 连续投影 | duplicate、late、gap、conflict和commit unknown不产生猜测、二次效果或半提交 |
| local state | Inbox只来自owner明示attention；read/pin/mute/preference/focus只属于绑定principal/scope |
| 恢复与失效 | generation隔离、每次Advance有界、basis重验、cutover原子、终态不复活 |
| 配置/观测/依赖 | strict config、secret/redaction、低基数、fake隔离和依赖分类不打穿边界 |

### 2.2 优先级与执行状态双轴

| 优先级 | 含义 | 当前口径 |
|---|---|---|
| P0 | 主链、安全、所有权、一致性和证据红线 | 必须有用例和证据路径；缺正式seam时仍是P0但状态blocked |
| P1 | 真实产品接缝、durable产品和下游兼容加固 | 当前多为blocked，不得替代P0或由fake证明 |
| P2 | 量化性能、容量、长稳、灾难恢复或外围增强 | 无workload/baseline时pending，不发明数值 |

| 执行状态 | 含义 | 能否算通过 |
|---|---|---:|
| planned | 设计已定义，尚未实现/执行 | 否 |
| blocked | 必需前置未闭合 | 否 |
| pending | 等待基线、选择或后续文档 | 否 |
| not_scheduled | 当前无执行授权 | 否 |
| passed/failed | 只能由未来真实固定run产生 | 当前不存在 |

### 2.3 范围表

| 范围 | 优先级 | 当前状态 | 证明上限 |
|---|---|---|---|
| typed contract、key/ref/version/digest/DTO/error | P0 | planned；owner codec正向blocked | 本地类型、roundtrip、拒绝和canonical规则 |
| 16个对象、纯projector与正式状态族 | P0 | planned；proof型构造blocked | workspace局部不变量和迁移 |
| 2 Command、6 Query、2 Consumer、4 Operation | P0 | local planned；外部正向部分blocked | 逐入口flow、错误、写集和phase |
| local store/UoW/CAS/commit resolution | P0 | controlled planned；durable blocked | 本地编排和故障分类 |
| scope/visibility/owner read/attention | P0 | 负向planned；正向blocked | fail-closed/no-write；不测owner引擎内部 |
| event/cursor/baseline/replay/rebuild | P0 | 分类planned；正向blocked | gap、幂等、有界恢复；不承诺任意offset |
| config/secret/binding/redaction/dependency | P0 | schema/check planned；真实binding blocked | strict失败、无fallback、无泄漏 |
| owner/bus/durable真实接缝 | P0风险/P1产品加固 | blocked | 正式conformance selected-run |
| SDK/product/sync/archive只读消费 | P1 | blocked | 兼容性；不测UI/cache/archive package |
| 量化性能/容量/SLO/长稳 | P2 | pending baseline | 未来正式workload与环境 |

### 2.4 非范围

- 不测试任何L1 owner内部正文、状态机、业务命令、授权算法或事件生产正确性。
- 不测试L0-bus内部delivery/ACK实现，不把consumer receipt写成ACK truth。
- 不测试runtime/tools execution、capability registry、sandbox或member生命周期。
- 不测试SDK cache、产品UI、sync私有状态、archive package/freeze/restore/accepted state。
- 不创建实现仓、测试脚本、CI、环境、fixture、artifact、report或真实证据。

### 2.5 一票否决

| 风险 | 必须由哪些族阻断 |
|---|---|
| workspace拥有或反写上游/runtime/archive truth | BOUND、DEP |
| visibility缺失/冲突/撤销仍展示 | VIS、QRY、SEC |
| Query产生任何持久写或隐式refresh | QRY、BOUND |
| Gap静默跳过、duplicate二次效果、Unknown盲重做 | SRC、IDEM、TXN |
| stale/partial/blocked冒充fresh/Complete/ready | QRY、STATE、RES |
| generation/cursor混轴或unsafe cutover | CONTRACT、PAGE、REC、STATE |
| fake/缺口/静态EV冒充正式集成或readiness | DEP、CONFIG、report-integrity |
| 正文、secret、credential或隐藏标识泄漏 | SEC、BOUND、redaction |

| 层 | 验证目标 | 典型断言 | 当前姿态 |

### 6.1 公共执行与判定口径

公共 phase 约束：Query 不 refresh；Request 不 baseline；Advance 不跨 phase；Gap 不是 terminal；Export 不归档；receipt 不等于 bus ACK；OutcomeUnknown 只能经权威 resolve 终结；任何 blocked/pending 不能被汇总为 passed。

### 7.2 构造、替身与清理规则

- builder 必须显式填写 required 字段，禁止 `Default` 偷补 scope、proof、version、expected、budget 或安全状态；合法对象只能经正式 factory/public constructor 构造。
- 负向数据一次只做一个主要变异；ID 按类型分段；same-key replay 复用完整 key+digest，异 digest 只变一个语义字段。
- owner/event/baseline 成功输入只能来自带 owner、schema、version、order/proof 的正式 conformance vector；缺 vector 即 `blocked`。failure stub 可模拟 ContractBlocked、Unavailable、missing、conflict、revoked、fault、调用顺序，但不得制造 authorization truth、event identity、replay proof 或 durable finality。
- 每个 case 使用独立实例/namespace；同 partition、operation key、event key、key ring 或 capture sink 的竞态由 case 内 barrier 控制。未来 cleanup 失败使 suite 非通过，不扩大删除目标。

## 11. 缺陷管理与复验规则

> 校准来源：

### 11.1 三轴与级别

优先级（P0/P1/P2）、执行状态（planned/blocked/pending/not_run/passed/failed）和缺陷级别（S/A/B）相互独立。当前没有真实执行，因此没有真实 defect、failed case、closed 或 signoff。

| 级别 | 触发示例 | 处置 |
|---|---|---|
| S | 越权展示、Query 写、Gap terminal、Unknown 盲重做、unsafe cutover、secret/body 泄漏、fake/静态 EV 冒充通过 | 一票否决，必须修复；不得风险接受 |
| A | P0 主线/测试 harness/报告完整性无法证明但未观察 S 后果 | 修复并跑原 TC+同族+CUT+suite/check；正常退出前为 0 |
| B | 非 P0 可读性、P1 hardening、无正式 baseline 的样本问题 | 具名角色、缓解、期限与复验后才可由 06 讨论接受 |

### 11.2 复验与关闭

契约/游标变化重跑 CONTRACT/PAGE 及所有入口；对象/状态变化重跑 STATE 与消费入口；scope/visibility/query 变化重跑 SCOPE/VIS/QRY、API 与 redaction；Consumer/Recovery/事务变化重跑对应族、相邻 suite 和 formal seam；配置/依赖/报告变化加入 CONFIG/DEP/BOUND/report-integrity。S 缺陷或影响范围不明时升级全量 13 suite。关闭需有固定 raw/report、根因/owner、原 TC 与扩大回归、防回归断言；planned EV 不能关闭缺陷。

## 2. 验收目标与范围

> 校准来源：
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“验收目标”“范围与非范围”和“一票否决关联”小节。

### 2.1 验收目标

| 目标 | 必须裁决 |
|---|---|
| 所有权 | workspace 只保存 view/projection/coverage/generation/recovery/local attention 和安全引用 |
| 安全只读 | Personal/Project scope、current visibility、provenance、freshness、coverage、availability 可解释 |
| 连续投影 | duplicate、late、gap、conflict、commit unknown 不猜测、不二次效果、不半提交 |
| 局部状态 | read/unread/pin/mute/preference/focus 绑定 principal/scope/stream，不改变 owner truth |
| 恢复失效 | generation、basis、phase、cutover、invalidation 可回链且有界 |
| 证据真实性 | 每个 P0 AC 有固定 run 的 raw/report/EV 追溯，blocked 不被改为 passed |

### 2.2 范围 / 非范围

| 范围项 | 优先级 | 当前裁决上限 |
|---|---:|---|
| 16 局部对象、7 service、14 入口 | P0 | 需要 05 对应 TC/EV；外部成功接缝可 blocked |
| 六 Query no-write 与现时 visibility | P0 | 缺 owner decision 时必须 fail-closed |
| 两 Consumer、四 Recovery Operation | P0 | Gap/Unknown/phase/幂等必须可判定；正式 replay/durable 仍 blocked |
| 配置、profile、secret、redaction、依赖 | P0 | strict/fail-fast/边界可裁决；真实部署待实施 |
| SDK/product/sync/archive compatibility | P1/P0 seam | 仅在正式下游合同和 selected run 存在时裁决 |
| 量化性能、容量、长稳、RTO/RPO、retention | P2 | 无 workload/baseline 时 pending，不发明数字 |

### 2.3 非范围

不验任何 owning domain 内部正文、授权算法、业务命令、事件生产、L0-bus 内部 ACK/delivery 实现、runtime/tools/capability/sandbox、SDK cache、产品 UI、sync 私有状态或 archive package/freeze/restore/accepted state。非范围风险由相应 owning project 或下游负责，workspace 不得自行补真相。

### 2.4 P0/P1/P2 裁决关系

P0 是主链、安全、所有权、一致性和证据红线；缺正式 seam 仍保留为 blocked。P1 是兼容和产品加固，不能替代 P0。P2 没有正式 baseline 时只能 pending。任何 VETO、S/A 或 required P0 not_run 都禁止“通过”。

## 4. 进入条件与退出条件

> 校准来源：
> - `design-calibration/06_acceptance_step_04_entry_exit.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“分层进入条件”“退出条件”和“暂停/不可裁决”小节。

### 4.1 分层进入条件

| 层 | 必要条件 | 当前 |
|---|---|---|
| 设计送验 | 00~05 停审；AC/TC/EV/VETO 映射完整 | 满足设计条件 |
| local/test | 实现仓、runner、builder、profile、隔离/清理可用 | 未满足 |
| controlled | named fault points、write spy、adapter 可执行 | planned |
| formal seam | owner query/visibility/event、L0-bus、durable、secret、downstream manifest 固定 | blocked |

### 4.2 完整退出条件

只有同时满足以下条件才允许裁决通过或有条件通过：

- 所有 P0 AC 有同一 fixed run 的真实 raw/report/EV；
- 13 个 P0 suite 状态完整，S=0、A=0，required P0 无 `blocked/not_run/infrastructure_failed`；
- 59 个 EV 的 source case、suite report、digest、redaction、integrity 可复算；
- formal seam、配置、依赖和边界检查不再 blocked；
- 十项 VETO 均有真实检查结论且未触发；
- 风险接受文件由具名授权角色审查，签署记录真实存在。

### 4.3 暂停与不可裁决

缺实现 revision、owner schema/decision、event order/replay proof、durable resolution、redaction scan、报告或 VETO source 时暂停。`blocked`、`pending`、`not_run` 和 `infrastructure_failed` 不得升级为通过；当前正式验收尚未进入运行阶段。

| AC-NFR-006 | 可演进/依赖 | unknown version 安全拒绝；无 shadow schema、非 core compile、fake fallback | 猜字段、依赖类型错误 | CONTRACT/DEP |

### 9.2 数值基线限制

P95、吞吐、容量、SLA、RTO/RPO、retention 没有正式 workload/baseline，均为 pending；local fake、日志或 telemetry 不能形成量化通过结论。

### 10.3 固定路径与真实性

优先读取 `reports/runs/<run_id>/evidence-index.md`，再回指 `artifacts/test/<run_id>/...`；`reports/acceptance/*` 只是交接草案，必须有人/Agent审查。禁止 `latest`、静态表、日志片段、跨 run 拼接、手写 passed 或把 telemetry 当业务证据。

## 12. 缺陷分级、复验与放行规则

> 校准来源：
> - `design-calibration/06_acceptance_step_12_defects_release.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“缺陷与结论”“放行规则”和“复验扩大集”小节。

### 12.1 缺陷分级

| 级别 | 定义 | 验收影响 | 复验要求 |
|---|---|---|---|
| S | VETO、安全、所有权、一致性终局或证据真实性破坏 | 必须不通过，不可接受 | 原 TC+同族+CUT+全量 P0，新 run |
| A | P0 主线、harness 或报告无法证明但未观察 S 后果 | 不通过；正常退出前为 0 | 原 TC、相邻 suite、integrity |
| B | 不影响 P0 的一般问题/P1/P2 | 仅在具名角色、期限、动作齐全时可条件接受 | 相关范围与风险记录 |

`blocked`、`pending`、`not_run`、`infrastructure_failed` 是执行状态，不等于缺陷级别；formal seam 缺失不能被伪造为产品失败或放行。

### 12.2 三值放行

| 结论 | 必要条件 |
|---|---|
| 通过 | 全部 P0 AC、VETO、证据、S/A、formal seam 满足 |
| 有条件通过 | P0 真实满足；仅有具名角色接受的 B/P2，且无 VETO、S、未裁决 formal blocker |
| 不通过 | 任一 VETO、S/A、required evidence 缺失、formal blocker 或 P0 not_run |

原始失败 run 必须保留；修复后使用新 run_id，不能在原目录改写 passed。planned EV 不能关闭缺陷。

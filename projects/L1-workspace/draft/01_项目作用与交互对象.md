## 1. 一句话定位（已确认的讨论方向）

`L1-workspace` 是跨 L1 真相域的**只读工作区视图与投影局部状态仓**：它围绕一个成员和一个工作区 scope，读取拥有域的正式事实、可见性结论与变化信号，维护可重建的 workspace read model，并向产品、同步和后续归档边界提供稳定、可解释的读取面。

它回答的是“在当前可验证 scope 下，这个成员现在可以安全地看见哪些已获授权的跨域摘要、引用和本地注意力状态”；它不回答“业务事实是什么、谁被授权、流程是否已推进、任务是否已完成、运行是否已执行”。

### 1.1 为什么必须单独存在

| 易混淆对象 | 边界结论 |
|---|---|
| `L1-identity` | identity 拥有 `GlobalMember` 身份、生命周期和身份摘要；workspace 只以正式身份锚点组织个人视图，不拥有成员身份或其生命周期。 |
| `L1-work` | work 拥有 `Project`、`ProjectMember`、`WorkItem` 等工作事实；workspace 只显示其可消费引用/摘要，不能创建、分配、推进或修复工作事实。 |
| `L1-conversation` | conversation 拥有 Conversation、Turn、Participant 等对话真相；workspace 可以投影已获准的摘要、未读语境或引用，不能把 inbox、read cursor 当作对话真相或回写消息已读事实。 |
| `L1-process` | process 拥有 ProcessInstance、Activity 和过程执行事实；workspace 只读取可见的当前状态/引用，不编排或推进流程。 |
| `L1-governance` | governance 拥有 Policy、Gate、Decision、授权/治理结论；workspace 只消费正式的可见性、适用性或安全结论，绝不形成第二套 authorization truth。 |
| `L1-artifact` | artifact 拥有 Artifact 正文、版本、血缘和基线事实；workspace 只能保留安全摘要和稳定引用，不能复制正文、版本链或基线。 |
| `L0-bus` | bus 拥有事件传递、delivery、ack/fail、retry、dead-letter、replay 等总线事实；workspace 拥有自己对事件的消费游标、幂等记录和投影结果，不拥有 delivery truth。 |
| `L0-sdk` 与 L5 产品 | SDK 提供客户端/访问封装，产品拥有 UI、交互和本地客户端体验；workspace 提供服务侧 read model，不拥有 SDK cache 或任何产品 UI truth。 |
| L2 member/runtime/tools | 它们分别拥有成员门面、受控运行和工具执行事实；workspace 不是执行主语、运行上下文、capability registry、sandbox 或 tool execution 的 owner。 |
| `L4-archive` | archive 是后续归档/恢复 owner；workspace 可以成为其只读输入消费者之一，但 archive 不反向定义 workspace truth，也不能把归档包当 workspace 当前真相。 |

若没有独立 workspace 层，产品、同步或成员入口会各自拼接跨域缓存、未读和可见性解释，既造成重复投影，也会把 UI/SDK cache 错当业务事实。若 workspace 越界，则会变成第七个业务真相域或隐性授权中心，这两种结果都不可接受。

### 1.2 两种 scope，不是两套真相生命周期

| 工作区形态 | 锚点（候选语义） | 解决的问题 | 明确不代表 |
|---|---|---|---|
| `PersonalWorkspace` | `GlobalMember` 的正式引用 | 个人首页、跨项目入口、私聊/通知语境、跨项目 attention 汇总和个人局部偏好。 | 新的 GlobalMember 生命周期、独立执行主体或跨项目授权。 |
| `ProjectWorkspace` | `Project` 与当前 `ProjectMember` 的正式引用 | 进入一个项目后所需的项目摘要、成员、对话、工作、流程、制品和治理入口。 | 新的 Project/ProjectMember 生命周期、项目权限裁决或项目业务状态。 |

二者采用同一 workspace read-model 框架，只是 `scope key`、可消费分区和可见性输入不同。`ProjectWorkspace` 不以 workspace view 替代 `ProjectMember`；特别是当前 `L2-member-service` 的项目型执行主语约束，不会被 PersonalWorkspace 或任何 workspace view 绕过。

## 2. 本仓拥有 / 只消费 / 禁止拥有（候选）

| 主题 | `L1-workspace` 拥有 | 只消费 / 回链 | 禁止拥有 |
|---|---|---|---|
| 工作区分区 | 按 principal 与 scope 划分的 view partition、局部 view revision、覆盖范围与失效记录。 | `GlobalMember`、`Project`、`ProjectMember` 的正式 ref。 | 身份、项目或项目成员 truth。 |
| 聚合投影 | 跨域摘要/引用的本地 materialization、投影 identity、来源版本/水位、重建世代和投影状态。 | 各 owning domain 的正式 query 结果、事件和安全摘要。 | 任一源域实体的正文、生命周期、版本或业务状态。 |
| Inbox | `InboxItem` 的派生表示、来源回链、局部展示排序/隐藏状态和可重算 attention projection。 | 仅 owner 明确给出的 attention/visibility 输入及其 source ref。 | 业务优先级推断、消息/任务/gate 的真相、独立通知裁决。 |
| 本地注意力状态 | `ReadCursor`、unread projection、pin/mute、偏好、last-opened、focus/attention、局部 inbox disposition。 | 调用方的正式 principal/scope 语境。 | conversation read receipt、上游业务确认、项目成员资格或 authorization truth。 |
| 事件消费 | source consumption cursor、去重/幂等记录、gap、重放/重建请求和本地应用结果。 | `L0-bus` 传递的已授权事实变化与 owner replay/query 能力。 | bus delivery、ack、dead-letter、原始事件 schema authority。 |
| 可见性 | 对正式可见性/治理结论的消费、绑定、失效和 fail-closed 裁剪。 | identity/work/conversation/governance/artifact 等 owner 的正式决定或 ref。 | allow/deny、成员资格、政策解释、授权默认值。 |
| 对外读面 | workspace read model、来源版本集合、覆盖/降级状态和稳定引用。 | 下游请求语境、正式服务/SDK 访问边界。 | 产品 UI 状态、SDK client/cache、同步真相、archive truth。 |

`InboxItem` 的关键区分是：其**投影载体、来源回链和局部展示状态**属于 workspace；它所指向的消息、工作、活动、制品或治理事实始终属于来源域。workspace 不能因为拥有一个 inbox projection 就拥有其业务含义。

## 3. 交互对象总览（系统上下文草图）

```text
                       +--------------------+
                       | L0-core            |
                       | shared contracts   |
                       +---------+----------+
                                 | [compile candidate]
                                 v
 +------------------+      +-----+--------------------------+      +-------------------+
 | L0-bus           |----->|        L1-workspace            |----->| L0-sdk / L5       |
 | delivery backbone |event | read model + local view state | read  | product consumers |
 +------------------+      +-----+--------------------------+      +-------------------+
                                 ^                  |
                  no-write query/ref                | safe read model / ref
                                 |                  v
       +-------------------------+----------+  +-------------------+
       | identity / work / conversation /    |  | L4-archive        |
       | process / governance / artifact     |  | downstream only   |
       | owning truth domains                 |  +-------------------+
       +--------------------------------------+
```

图示说明：

- 从真相域进入 workspace 的读取面必须保持 no-write；workspace 不共享数据库事务，也不读取对方内部表。
- 事件只通过 `L0-bus` 的正式协作边界进入；workspace 的 cursor、dedupe 和投影提交不等于 bus delivery/ack truth。
- `L0-sdk`、L5 产品、L5-sync 和 `L4-archive` 是读模型消费者/交接边界，不反向提供 workspace truth。
- L2 member、runtime、tools、member-service、member-images 不在 workspace 的跨 L1 主输入链上；未来如有安全摘要消费，仍必须按 ref/runtime/event seam 单独闭口。

## 4. 本仓依赖裁剪表（候选）

| 关联项目 | 全局关系 | 本仓角色 | 依赖类型 | 是否进入当前主链 | 裁剪理由 |
|---|---|---|---|---|---|
| `L0-core` | L1 shared-contract base | 依赖方 | `compile` | 是，条件型 | 只使用已正式化的共享 ref、错误、trace、版本/事件契约；workspace 专用类型未闭口前不得本地 shadow。 |
| `L0-bus` | 全平台事件主干 | 订阅协作方 | `event` | 是 | 维护跨域投影所需的变化协作；delivery/replay carrier truth 仍归 bus。 |
| `L1-identity` | GlobalMember owner | 只读消费者 | `runtime + event + ref` | 是 | 个人 scope 身份锚点、成员摘要及其变化输入；不持有身份生命周期。 |
| `L1-work` | Project/ProjectMember/WorkItem owner | 只读消费者 | `runtime + event + ref` | 是 | 项目 scope、项目入口和工作摘要的正式来源；不把 view 当 ProjectMember。 |
| `L1-conversation` | 对话 owner | 只读消费者 | `runtime + event + ref` | 是，受契约门禁 | 只消费可见对话摘要、引用和正式 attention 输入；不回写 Turn 或 read receipt。 |
| `L1-process` | 流程/Activity owner | 只读消费者 | `runtime + event + ref` | 是，受契约门禁 | 只显示被允许的过程摘要/引用；不推进流程。 |
| `L1-governance` | Gate/Decision/Policy owner | 只读消费者 | `runtime + event + ref` | 是，受契约门禁 | 消费正式可见性/适用性/治理结论；不得自行解释或默认授权。 |
| `L1-artifact` | Artifact fact/version/lineage/baseline owner | 只读消费者 | `runtime + event + ref` | 是，受契约门禁 | 只显示安全摘要和稳定 ref；正文、版本链、血缘和基线均外置。 |
| `L0-sdk` | 客户端/服务访问封装 | 被依赖方 | `adapter / ref` | 否，非输入主链 | SDK 可承接 workspace 的正式读面；workspace 不实现 client/cache，也不把 SDK 当 truth source。 |
| `L2-member` / `L2-runtime` / `L2-tools` | 运行层相邻边界 | 可能的安全摘要消费者或被消费方 | `ref` | 否，future | 不把 member/runtime/tool execution 纳入跨 L1 视图；任何未来 safe-view seam 均需独立闭口。 |
| `L2-member-service` | 项目型宿主执行边界 | 边界参考方 | `ref` | 否 | workspace 不替代其 `ProjectMember` 执行主语，也不定义 personal execution subject。 |
| `L2-member-images` | 静态镜像输入边界 | 无直接运行期关系 | `ref` | 否 | workspace seed/template 与 live workspace read model 完全不同；不得混用。 |
| `L4-archive` | 后续归档/恢复层 | 下游提供方 | `runtime + ref`（候选） | 否，后续消费者 | archive 的消费/export 协议尚未闭口，且不得反向定义 workspace view truth。 |
| `L5-chat` / `L5-console` / `L5-sync` | 产品/同步消费方 | 下游提供方 | `adapter / ref` | 否 | 通过正式 SDK/API 消费稳定 read model；不直接订阅内部投影事件或拥有 workspace UI truth。 |

依赖术语补充：`ref` 只表达安全引用、摘要或来源绑定，不转移 authority；`adapter` 只承接实现载体，不成为真相 owner；`fake` 只可在后续受控测试中模拟 seam，绝不证明真实集成、readiness 或上游合同已闭口。

### 4.1 禁止依赖（候选）

| 禁止依赖/做法 | 禁止原因 | 正确协作方式 |
|---|---|---|
| workspace 对任一 L1 域建立源码/path 依赖、共享表或跨仓事务 | 会把运行期/事件协作伪装为 compile 依赖，并破坏 source ownership。 | 经正式 no-write query、event、safe ref 或 adapter seam 协作。 |
| workspace projection 反写 identity、work、conversation、process、governance 或 artifact | 投影不是写源，反写会制造多真相。 | 由产品/调用方直接向 owning domain 发起正式命令。 |
| workspace 将本地 pin/mute/read/unread 当作业务授权、对话已读或任务完成 | 局部体验状态不能改变上游事实或权限。 | 分离 workspace local state 与 owner truth；需要业务变化时走 owner 的正式命令。 |
| workspace 本地 allowlist、成员资格推断或默认可见 | 会形成第二 authorization truth 并可能 fail-open。 | 仅消费 owner 提供的正式可见性/治理结论；未知即 fail-closed。 |
| workspace 直接消费 runtime execution、tool execution、capability registry、sandbox 或 archive truth | 超出跨 L1 工作区 read-model 边界。 | 如未来需要，先由相应 owner 提供安全、正式的消费面。 |
| workspace 作为 SDK cache、Chat/Console UI 或 sync private state 的 owner | 会混淆服务侧投影与客户端/产品状态。 | workspace 提供稳定 read model；SDK/产品各自拥有其本地状态。 |

## 5. 可见性与数据所有权边界（候选）

workspace 只能把“正式决定已允许消费”转化为“该投影分区可展示”，不能从项目归属、消息引用、历史缓存、默认角色或用户偏好自行推出可见性。

| 所需输入 | 可能 owning domain | workspace 的允许行为 | workspace 的禁止行为 |
|---|---|---|---|
| 当前成员身份锚点与身份摘要 | `L1-identity` | 绑定个人 scope、显示安全摘要、标记来源失效。 | 创建 GlobalMember、解释身份授权。 |
| 项目与 ProjectMember 关联 | `L1-work` | 绑定项目 scope、裁剪项目分区、回链稳定 ref。 | 创建/修复项目成员资格，或以 workspace 代替 ProjectMember。 |
| 对话 participant/可见性和 attention 输入 | `L1-conversation` | 投影获准摘要/引用，生成 workspace local unread。 | 推断私聊可见性、读取正文、写入 read receipt。 |
| 工作/过程的可见摘要和 attention 输入 | `L1-work` / `L1-process` | 显示正式 summary/ref，标记 coverage。 | 推进任务或 Activity，推断优先级。 |
| Gate/Decision/Policy 的可消费结论 | `L1-governance` | 按结论裁剪/失效投影，回链 decision ref。 | 发布 allow/deny、批准/拒绝或另建 policy cache。 |
| Artifact 可消费引用与版本语境 | `L1-artifact` | 显示安全引用、摘要、状态和 source version。 | 复制 Artifact 正文、形成版本/血缘/基线 truth。 |

可见性决定失效、冲突、缺失或无法验证时，受影响内容必须被移除/遮蔽并标记 `fail-closed`；既有投影不得因“曾经看过”而继续作为授权依据。

## 7. 上游 pending / blocker 候选清单

| ID（候选） | 未闭合边界 | 影响与当前上限 |
|---|---|---|
| `WS-UP-001` | 六个 L1 owner 的 workspace-safe query、摘要字段、版本/水位与一致性 barrier 未形成统一正式消费面。 | 只能定义 no-write source-query 原则；不能承诺具体字段、全局快照或 fresh 语义。 |
| `WS-UP-002` | 各来源事件的 family、订阅、cursor、保留、replay 和 rebuild cutover 合同未逐项闭口。 | 可定义幂等/缺口/重建纪律；不得假定可实时订阅或可从任意 offset 重放。 |
| `WS-UP-003` | 跨域 visibility / authorization decision 的 owning chain、撤销、时效和安全传递方式未统一。 | 未验证内容必须 fail-closed；不得本地 default allow。 |
| `WS-UP-004` | Inbox 的正式 attention input、去重语义、生命周期和 source reference 尚未由各 owner 对齐。 | 首版只允许接纳 owner 显式提供的输入；不得从消息、任务或 gate 自行猜测 attention。 |
| `WS-UP-005` | Personal / Project scope 所需 GlobalMember、Project、ProjectMember 的 exact safe ref/query surface 未闭口。 | scope 可作为模型方向，具体 key/字段/错误语义仍 pending。 |
| `WS-UP-006` | workspace 对 `L4-archive`、SDK 和产品/同步消费者的稳定 export/read contract 尚未形成。 | 可保留下游消费者边界，但不定义 archive snapshot、SDK method 或产品 UI 协议。 |
| `WS-UP-007` | `L0-core` 中 workspace 特有共享类型、错误和 event contract 是否/何时出现尚未确认。 | `L0-core` 只是 compile candidate；不在本地复制跨仓 schema。 |
| `WS-UP-008` | L2 项目型执行边界尚未定义非项目型 personal execution subject。 | 不影响 workspace 作为 read view；但 workspace 不得被拿来替代该执行主语。 |

## 8. 本篇讨论结论

本轮已确认 `L1-workspace` 的唯一核心是“只读跨域 materialization + 本地 view state”，并已确认 Personal/Project 是同框架 scope、Inbox 只承接 owner 明示输入、查询 no-write、可见性 unknown fail-closed。下一篇将以这些边界推演能力闭环、投影一致性、游标和降级语义；所有 exact contract 继续保持 pending，而不由 workspace 自行补造。

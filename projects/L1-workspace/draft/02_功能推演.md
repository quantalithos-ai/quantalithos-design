## 1. 核心能力闭环（候选）

Workspace 的存在性不是“把六个域的列表拼在一起”，而是以下六个节点共同成立：

```text
[C-WS-1 scope 与 principal 语境可验证]
                 |
                 v
[C-WS-2 owner query 只读取数与可见性裁剪]
                 |
                 v
[C-WS-3 event/cursor 驱动的投影维护]
                 |
                 v
[C-WS-4 可解释、可重建的 workspace read model]
                 |
                 v
[C-WS-5 workspace 局部注意力状态]
                 |
                 v
[C-WS-6 刷新、缺口、重建与降级闭环]
                 ^                    |
                 +---- read/export ----+
```

| 节点 | 能力成立描述 | workspace owner 边界 | 外部 owner 边界 | 缺失后果 |
|---|---|---|---|---|
| `C-WS-1` | 能识别请求主体、`Personal`/`Project` scope、目标视图和可用的可见性语境。 | scope key 的本地绑定、请求语境校验结果。 | GlobalMember、Project、ProjectMember、授权/治理决定。 | 无法安全裁剪时不得读取或展示受影响内容。 |
| `C-WS-2` | 以 no-write query 取得 owner 正式摘要/ref，并按 source version 与 visibility decision 形成可消费输入。 | 查询编排、来源绑定、输入完整性和局部结果状态。 | 各域事实正文、版本、权限、业务规则。 | 缺 source 时只能返回明确的 partial/blocked/unavailable。 |
| `C-WS-3` | 订阅获准事件并以 source cursor、版本、幂等和乱序规则维护本地投影。 | 消费游标、去重、gap、投影应用记录。 | bus delivery/ack/retry、事件 schema、owner event truth。 | 投影停在可解释的 stale/partial/blocked，不得静默跳过缺口。 |
| `C-WS-4` | 对 Personal/Project scope 提供带来源版本、覆盖范围、更新时间和状态的稳定 read model。 | 投影结果、view revision、来源追溯和 read surface。 | 下游产品、SDK、sync、archive 的消费协议。 | 下游只能得到降级结果或暂不可用，不得猜测缺失事实。 |
| `C-WS-5` | 保存 read cursor、unread、pin/mute、preference、last-opened、focus 等 workspace-only 状态。 | 局部状态及其更新历史/版本。 | 对话已读、任务完成、治理决定、业务通知真相。 | 体验状态可延迟或重算，但不能改变上游事实。 |
| `C-WS-6` | 能以 owner query 重建基线、接续事件、标记失效并恢复或保守降级。 | rebuild generation、refresh outcome、失效范围与原因。 | owner 的 snapshot/query、bus replay、archive recovery truth。 | 不能证明完整性时保持 blocked/fail-closed，不能以缓存冒充新鲜。 |

### 1.1 核心闭环的进入 / 退出条件（候选）

| 能力节点 | 进入条件 | 成立条件 | 退出 / 降级 |
|---|---|---|---|
| Scope | 调用方提供可验证 principal 与 scope selector。 | scope 锚点、可见性语境和目标 view type 均可解释。 | invalid / unauthorized / blocked；不得默认 Personal 或 Project。 |
| Query | 至少一个所需 source partition 被请求。 | owner query 成功返回安全摘要/ref，并能记录 source version/watermark。 | missing source、partial、unavailable；不得写回 source。 |
| Projection | 有已验证的 baseline 或已授权事件输入。 | 事件按版本/cursor/idempotency 规则应用，形成新 view revision。 | duplicate/late 可留痕；gap/conflict 进入 blocked 或 rebuilding。 |
| Read model | projection revision 与 visibility decision 可关联。 | 返回内容、来源、覆盖范围和 freshness/degradation 状态。 | stale/partial/blocked/fail-closed；不返回无法验证的敏感内容。 |
| Local state | principal、scope 和目标 local state 已验证。 | 只修改 workspace-owned state，并与 view revision/作用域绑定。 | invalid/conflict/unauthorized；不得转译为上游命令。 |
| Rebuild | 发现 gap、source invalidation、contract change 或人工 refresh 请求。 | 取 owner baseline，建立新 generation，完成 cutover 或留下明确 gap。 | blocked/failed/partial；旧 revision 只可标记 stale，不可默认为 current。 |

## 2. 候选功能清单

### 2.1 核心功能（候选 FR）

| ID（候选） | 功能 | 说明 | 能力节点 |
|---|---|---|---|
| `FR-WS-001` | Scope 与 principal 解析 | 解析 `PersonalWorkspace` / `ProjectWorkspace` 的请求语境，绑定正式 identity/work ref；不创建业务主语。 | C1 |
| `FR-WS-002` | Scope 成员资格与可见性前置校验 | 消费 owner 的正式 membership/visibility/governance 结果；决定缺失或冲突时保守拒绝受影响分区。 | C1/C2 |
| `FR-WS-003` | 跨域 no-write query 聚合 | 并行或顺序读取 owner 的安全摘要/ref，保留每个来源的版本、水位和结果状态；查询本身不得改变投影或业务事实。 | C2 |
| `FR-WS-004` | 来源引用与版本追溯 | 每个 view item 能回链 owning domain、source ref、source version/watermark 和读取语境；不得保存外部正文。 | C2/C4 |
| `FR-WS-005` | Projection identity 与 view revision | 为“principal × scope × view partition/type”建立稳定 projection identity，并以新 revision 表达显式变化。 | C3/C4 |
| `FR-WS-006` | 事件订阅与 source cursor | 仅订阅已授权的 owner event，通过独立 source cursor 推进投影；不把 bus delivery cursor 当 workspace truth。 | C3 |
| `FR-WS-007` | 幂等、重复、迟到与乱序处理 | 重复事件不得重复产生局部事实；迟到/乱序按 source version、事件序或冲突规则处理，无法判断时保留 conflict/gap。 | C3 |
| `FR-WS-008` | 缺口检测与安全停写 | 检测 cursor gap、版本跳跃、撤销/失效通知缺失；受影响 partition 停止冒进，进入 blocked/rebuilding，而不是猜补。 | C3/C6 |
| `FR-WS-009` | Personal read model | 聚合个人可见的项目入口、私聊/通知语境、明确 attention 输入和身份摘要；不得泄露其他不可见 scope。 | C4 |
| `FR-WS-010` | Project read model | 聚合项目、ProjectMember、对话、工作、过程、制品和治理的已授权摘要/ref；不承担项目动作。 | C4 |
| `FR-WS-011` | InboxItem 派生投影 | 只接纳 owner 明示的 attention/visibility 输入，保存来源回链和局部 disposition；不自行推断业务优先级。 | C4/C5 |
| `FR-WS-012` | Read cursor 与 unread projection | 维护按 principal × scope × view stream 绑定的 workspace read cursor，并重算 unread；不写 conversation read receipt。 | C5 |
| `FR-WS-013` | Pin/mute/preference/last-opened/focus | 提供受限 local-state 更新，只作用于 workspace view；更新需有 scope、版本和冲突语义。 | C5 |
| `FR-WS-014` | 稳定读取与分页/覆盖说明 | 对外返回可解释的 view revision、来源版本集合、覆盖范围、freshness 和降级状态；具体分页协议后置。 | C4/C5 |
| `FR-WS-015` | Refresh / invalidate | 接受受控 refresh 或 source invalidation，区分局部刷新、全分区失效与全量重建请求。 | C6 |
| `FR-WS-016` | Baseline rebuild 与 cutover | 从 owner query/snapshot 建立新 generation，校验可见性和 source watermark 后再切换；失败保留旧 revision 与 gap。 | C6 |
| `FR-WS-017` | Projection status 与诊断 | 暴露 fresh/stale/partial/blocked/rebuilding/fail-closed、来源缺口和最后成功水位等安全诊断摘要。 | C4/C6 |
| `FR-WS-018` | 下游 read/export 交接 | 为产品、SDK、sync 和后续 archive 提供只读、带 provenance 的稳定消费语义；不声明下游已接收或归档成功。 | C4 |

| ID | 能力 | 裁剪边界 |
|---|---|---|
| `FR-WS-E01` | 跨域搜索/排序 | 只在所有相关 owner 的检索与可见性合同闭口后引入；不以本地相关性分数重写业务优先级。 |
| `FR-WS-E02` | 历史快照比较 | 只比较已验证的 view revision/source version，不把历史 projection 当 owner truth。 |

### 2.3 InboxItem 语义（候选）

`InboxItem` 不是新的业务实体，而是一个带来源回链的派生条目。其最小语义分成三层：

| 层 | workspace 可拥有 | 不可拥有 |
|---|---|---|
| 来源层 | source domain、source ref、source version/watermark、产生该条目的 owner-provided attention reason ref。 | 消息、任务、活动、Gate、Artifact 的正文和业务生命周期。 |
| 投影层 | projection identity、当前 view revision、可见性裁剪结果、coverage/freshness 状态。 | owner 的 priority、assignment、approval、completion 或 notification truth。 |
| 局部体验层 | read cursor 关联、unread、pin/mute、dismiss/hide 等 workspace-local disposition。 | conversation read receipt、work item close、治理决策、业务通知确认。 |

首版只允许聚合已经具有正式 attention/visibility 输入的条目。没有 owner 输入时，workspace 必须返回“无可验证 attention 输入”或保持该分区缺口，不能依据时间、文本关键词、缓存热度或本地模型自行生成高优先级结论。

### 2.4 Read cursor 与 source cursor 分离（候选）

| 游标 | owner | 作用 | 是否可替代另一游标 |
|---|---|---|---|
| `source_cursor` | workspace 的 projection maintenance 子域 | 记录某个来源事件流已消费到的版本/位置，支撑幂等、gap、重放和重建。 | 不可替代用户 read cursor。 |
| `view_revision` | workspace projection | 标识一次 view materialization 的显式修订，供读取与并发控制。 | 不代表任何上游 source offset。 |
| `read_cursor` | workspace local-state 子域 | 表示某个 principal 在某个 scope/view stream 的阅读位置，用于 unread projection。 | 不代表事件已被消费，也不写上游 read receipt。 |
| `source_watermark` | workspace 对每个 source partition 的安全摘要 | 表示该分区在特定版本/时间语境下的覆盖边界。 | 不承诺跨域全局强一致。 |

三类游标必须在数据、更新事务和失败语义上分离。`read_cursor` 前进不能掩盖 `source_cursor` 缺口；projection 重建也不能自动把用户 `read_cursor` 推到最新。

## 3. 失败与降级语义（候选统一口径）

workspace 的状态必须表达“内容是否可见”“来源是否完整”“是否可继续刷新”三个维度，不能把所有异常压成空列表或一个 `error`。

| 姿态 | 适用条件 | 允许返回 | 禁止行为 |
|---|---|---|---|
| `fresh` | 所需来源、visibility decision、版本/水位均可验证，当前 view revision 已覆盖声明范围。 | 正常 read model 与 provenance。 | 把局部 fresh 说成全局强一致。 |
| `stale` | 旧 revision 曾经验证，但 source/visibility 尚未确认到最新；旧内容仍不违反已知撤销。 | 标记过时的安全旧摘要，附最后验证版本/时间。 | 以 stale 作为当前授权依据；忽略撤销。 |
| `partial` | 某些非关键分区缺 source、超时或暂不可用，缺失范围可明确列出。 | 已验证分区 + 缺失分区清单/状态。 | 用空值掩盖缺口；把局部结果宣称完整。 |
| `blocked` | 关键 source watermark、跨域一致性 barrier、visibility decision 或 rebuild cutover 无法建立。 | 安全状态、原因、重试/重建线索；必要时不返回受影响数据。 | 猜测版本、默认放行、继续推进受影响 projection。 |
| `fail-closed` | principal/authorization/visibility 基础不成立，或数据可能越权。 | 最小安全错误/遮蔽结果，不泄露被裁剪对象存在性（视正式安全合同）。 | 返回缓存正文、默认可见、以历史曾见替代当前决定。 |
| `rebuilding` | 新 generation 正在从 owner baseline 重建，旧 revision 可被安全保留。 | 旧安全 revision（标 stale）或明确不可用状态。 | 混合不同 generation 造成不可解释的半新半旧快照。 |
| `conflict` | 同一 projection identity 的 source version、visibility decision 或 local-state 版本互相冲突。 | 冲突摘要、旧 revision、人工/维护处理线索。 | 以最后写入或本地默认覆盖冲突。 |
| `unavailable` | 所需服务/事件/存储暂时无法访问，但尚未证明权限或数据错误。 | 明确不可用与历史安全摘要（若允许）。 | 伪造 ready、fresh 或 accepted。 |

建议的保守优先级为：`fail-closed` > `blocked/conflict` > `partial` > `stale` > `fresh`；该优先级仍须在正式需求校准中结合安全与产品消费语义确认，不代表已锁定实现状态机。

### 3.1 事件与投影异常矩阵（候选）

| 场景 | 本地处理 | 对外状态上限 |
|---|---|---|
| 重复事件 | 依据 event identity/source version 幂等吸收，保留重复计数/诊断。 | 不产生重复 item；维持原状态。 |
| 迟到事件 | 若仍低于已应用版本则留痕忽略；若影响撤销/可见性则触发失效或重建。 | stale/blocked，视 owner 语义而定。 |
| 乱序事件 | 只有可证明的版本序列才可重排；否则进入 pending/conflict。 | 不宣称 fresh。 |
| cursor 缺口 | 停止受影响 partition 的乐观推进，尝试 replay 或 baseline rebuild。 | blocked/rebuilding。 |
| owner query 失败 | 保留旧安全 revision（若未发生撤销）并标 stale；新 partition 不补默认值。 | stale/partial/unavailable。 |
| visibility 撤销 | 立即使受影响条目失效/遮蔽，等待新决定时 fail-closed。 | fail-closed。 |
| 重建中断 | 保留旧 generation 的历史与新 generation 的失败原因，不能半切换。 | rebuilding/blocked。 |
| 本地状态写冲突 | 依据 local-state version 返回 conflict，要求显式重试/刷新。 | conflict；不改 source truth。 |

## 5. 关键设计问题与 pending（正式校准时逐项收口）

1. 六个 L1 owner 各自的 workspace-safe query 是否提供统一摘要、source version、visibility decision 和 watermark；若不统一，workspace 的最小 adapter contract 是什么。
2. `PersonalWorkspace` 的跨项目列表、私聊/通知和 attention 分区，是否全部需要 identity/work/conversation 的独立可见性 barrier；任何缺口如何避免泄露“对象存在性”。
3. `ProjectWorkspace` 是否必须同时得到 Project、ProjectMember 和治理决定，还是允许按分区 partial；ProjectMember 缺失时哪些内容必须整体 fail-closed。
4. owner event 的 identity/version/cursor 语义、保留期、replay 能力和撤销事件是否足以支持 projection rebuild；不足时采用 query-only refresh 还是保持 blocked。
5. projection identity 的维度是否固定为 principal × scope × view partition/type，还是需要加入 source-domain partition；如何避免同一来源被多个 projection 重复解释。
6. `InboxItem` 的 owner-provided attention input 具体由哪些域提供；dismiss/hide 的生命周期与 source item 删除/撤销如何分离。
7. `read_cursor` 的 stream 粒度、跨设备并发、回退/跳读、未读重算和 retention 如何定义；是否需要独立的 source sequence 语义。
8. visibility decision 更新是否要求主动撤销事件；事件缺失时 query refresh 的安全上限是什么。
9. 下游需要统一 snapshot、分区 feed 还是两者兼有；`L4-archive` 需要的冻结视图是否与产品 read model 同一 revision。
10. `L0-core` 是否收纳 workspace 专用 ref/error/event contract；在正式确认前，本仓只保留 capability-level seam，不本地复制 schema。

这些问题没有闭口前，正向能力只能声明为“候选语义 + pending seam”。fake/adapter 可以用于验证局部状态机和失败分类，但不能计入真实跨仓集成完成度。

## 6. 本篇讨论结论

本篇把 workspace 的核心从“聚合多个列表”收束为：验证 scope → no-write 取数与可见性裁剪 → 事件/游标维护投影 → 提供可解释 read model → 管理 workspace-only 注意力状态 → 可重建和保守降级。查询 no-write、Inbox 只接纳 owner 明示输入、`source_cursor` 与 `read_cursor` 分离、visibility 缺失 fail-closed 是本轮已确认方向；具体合同、字段与传输仍留待正式 `00~07` 校准。

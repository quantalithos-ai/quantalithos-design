## 1. 业务主要组成部分（候选，9 个）

| # | 组成部分 | 核心职责 | 不承担什么 | 承接能力 |
|---|---|---|---|---|
| 1 | `Workspace truth core` | 保护 workspace-owned local facts：view partition、view revision、projection generation、source application record、local attention state、失效/重建结论及其不变量。 | 不拥有任何 L1 source truth，不把 projection 变成上游写源。 | 全部横切，尤其 C3/C4/C5/C6。 |
| 2 | `Scope and visibility gateway` | 受理 principal/scope 语境，绑定正式 identity/work ref，消费正式 visibility/governance 结论，执行 fail-closed 裁剪。 | 不创建身份、项目成员关系、policy 或 authorization decision。 | C1、FR-WS-001/002。 |
| 3 | `Source query aggregation` | 编排跨域 no-write query、校验来源版本/水位、形成 source-safe snapshot/ref 集合。 | 不发上游命令，不读取内部表，不自行补全缺失业务字段。 | C2、FR-WS-003/004。 |
| 4 | `Projection maintenance` | 将已验证 baseline 与事件变更物化到 workspace partition；维护 source cursor、dedupe、乱序/gap 结果。 | 不拥有 bus delivery/ack/retry，也不重新定义事件 schema。 | C3、FR-WS-005~008。 |
| 5 | `Personal workspace composition` | 组成个人 scope 的身份摘要、项目入口、私聊/通知语境、显式 attention feed 与 coverage 信息。 | 不推断跨项目权限、业务优先级或个人执行身份。 | C4、FR-WS-009。 |
| 6 | `Project workspace composition` | 组成项目 scope 的项目、成员、对话、工作、过程、制品、治理安全摘要与稳定 ref。 | 不维护 Project/ProjectMember 或推进任何项目事实。 | C4、FR-WS-010。 |
| 7 | `Inbox and local attention` | 维护 InboxItem projection、read cursor、unread、pin/mute、preference、last-opened、focus 等局部状态。 | 不向 conversation 写 read receipt，不把 dismiss 解释为 source item 已关闭。 | C5、FR-WS-011~013。 |
| 8 | `Read surface and consumer handoff` | 以可解释的 revision、provenance、coverage、分页/排序语义和降级状态提供 read model。 | 不实现 SDK client/cache、产品 UI、sync 私有状态或 archive truth。 | C4、FR-WS-014/018。 |
| 9 | `Refresh, rebuild and diagnostics` | 处理 invalidate、refresh、baseline rebuild、generation cutover、状态诊断与维护对账。 | 不修复 owner truth，不把 maintenance result 当 source 事实。 | C6、FR-WS-015~017。 |

### 1.1 组成部分交互方向（候选）

```text
                 [Scope and visibility gateway]
                     | validated principal / scope / decision refs
                     v
              [Source query aggregation] <--- owner no-write queries
                     | baseline snapshot/ref set
                     v
                [Projection maintenance] <--- L0-bus owner events
                     | committed workspace projection facts
          +----------+-----------------------+-----------+
          v                                  v           v
[Personal composition]          [Project composition] [Inbox/local attention]
          \                                  |           /
           +---------------[Read surface]---+----------+
                              |
                              v
                   product / SDK / sync / archive boundary

 [Workspace truth core] protects local facts and invariants across all parts
 [Refresh, rebuild and diagnostics] consumes committed facts and source seams;
 it may create a new workspace generation, never repair source-domain truth.
```

图示说明：

- 上方主链是依附关系，不代表所有 query、事件和 local-state 更新必须串行执行。
- `Personal composition` 与 `Project composition` 是同一框架下的两个 scope composer，不是两个业务真相子域。
- Inbox/local attention 可以消费已提交 projection facts 与正式 attention input；它不直接读取上游正文，更不能反向触发业务写入。
- refresh/rebuild 在 source gap 或失效时可能重新进入 aggregation/maintenance，但只能形成新的 workspace generation。

## 2. 实现分层（候选）

| 分层 | workspace 内职责 | 边界与纪律 |
|---|---|---|
| Inbound / Operations | 接收 read request、受控 local-state change、owner event 通知、invalidate/refresh/rebuild trigger、维护任务触发。 | 不在入口直接写 source truth；不把 transport/SDK/UI 问题混入领域语义。 |
| Application Services | 编排 scope 校验、query aggregation、投影应用、局部状态变更、读取组装、重建/cutover；定义事务、幂等和失败分类。 | 不替代 domain invariant；跨域调用只能经 port/seam。 |
| Domain Model and Policies | 定义 workspace-owned aggregate/state：partition、projection revision、cursor、attention disposition、generation、gap、freshness/coverage policy。 | 不读取外部正文或基础设施；visibility guard 只消费正式决定/ref。 |
| Ports and External Seams | owner query port、visibility decision resolver、event subscription/replay port、consumer read/export port、clock/scheduler/lock 等 adapter seam。 | port 不是 external owner；未闭口 seam 返回 pending/blocked/fail-closed，不发明字段。 |
| Persistence / Projection | 保存 workspace local truth、投影、source application record、rebuild checkpoint、查询侧索引/分页辅助状态。 | 持久化投影不变成 source truth；不得存外部正文或共享 owner 表。 |
| Outbox / Read Handoff | 仅在正式被授权时输出 workspace 局部变化/投影更新的安全材料，或提供 read/export handoff。 | 不能自行创造事件 family；下游 accepted/archive completed 不反写 workspace truth。 |
| Maintenance / Diagnostics | 发现 gap、对账 source watermark、刷新、重建、清理可删除局部状态、输出安全诊断。 | 不在维护中默认修复、授权或覆盖 owner truth；fake 只验证局部行为。 |

### 2.1 组成部分到代码主体的候选映射

```text

+========================================================================+
| Workspace truth core            -> domain local facts / invariants     |

| Projection maintenance          -> event applier / cursor service      |
| Personal/Project composition    -> scoped view composers               |
```

## 3. 关键对象方向（只列类别，字段后置到正式 02/03）

### 3.1 Workspace 自有 truth / state 候选

| 对象类别 | 作用 | 核心边界 |
|---|---|---|
| `WorkspacePartition` | 表达 principal、scope kind、scope ref、view partition/type 与本地 ownership 边界。 | 不复制 GlobalMember、Project 或 ProjectMember 正文。 |
| `WorkspaceProjection` | 一个 partition 在某 generation/revision 下的已提交 read-model materialization。 | 只含安全摘要/ref 和 source provenance，不等于上游实体真相。 |
| `ProjectionRevision` | 标识 workspace 投影的显式变化与并发控制语境。 | 不等于 source event offset 或业务版本。 |
| `ProjectionGeneration` | 表示 rebuild 前后不可混用的 materialization 世代。 | 不表示 archive snapshot 或全局系统 epoch。 |
| `SourceApplicationRecord` | 记录某 source partition/event 被何时、以何种 idempotency 结果应用。 | 不替代 bus delivery、ack/fail 或 source event truth。 |
| `SourceCursorState` | 每 source stream 的消费位置、gap、watermark 与重放/重建需求。 | 不与用户 read cursor 混用。 |
| `VisibilityBinding` | 已消费的 visibility/governance decision ref、有效性/失效状态与适用 scope。 | 不包含本地 allow/deny 规则或 authorization decision。 |
| `ProjectionCoverage` | 记录哪些 source partition 被覆盖、哪些缺失、何时验证。 | 不把 partial 当 complete。 |
| `RebuildAttempt` / `RefreshAttempt` | workspace 自有维护尝试、checkpoint、结果/gap 和 cutover 决定。 | 不把外部 query/replay 成功或 archive 完成直接写为本地成功。 |

### 3.2 局部注意力 / 体验状态候选

| 对象类别 | 作用 | 核心边界 |
|---|---|---|
| `InboxItemProjection` | owner 明示 attention input 的派生条目、source ref、投影状态和安全摘要。 | 不是 source domain 的通知、消息、任务或 Gate truth。 |
| `ReadCursor` | 按 principal × scope × stream 记录用户在 workspace 内的阅读位置。 | 不回写 conversation receipt，不证明事件已消费。 |
| `UnreadProjection` | 由 read cursor 与可见 InboxItem/view item 重算的局部结果。 | 不成为业务未读或优先级真相。 |
| `WorkspacePreference` | 针对 workspace view 的排序/过滤/呈现偏好。 | 不改变 source visibility、工作状态或治理结论。 |
| `PinMuteDisposition` | 对 source ref 或 workspace item 的局部置顶、静音、隐藏等状态。 | 不删除/关闭/静音上游事实或其他用户视图。 |
| `LastOpened` / `FocusState` | 最近访问、当前 attention/focus 的局部体验状态。 | 不成为 runtime context、执行主语或组织业务事实。 |

### 3.3 外部 ref / safe snapshot 候选

| 类别 | workspace 如何使用 | 禁止保存 |
|---|---|---|
| Identity anchor / summary ref | 组织 Personal scope、显示安全成员摘要。 | GlobalMember truth、credential、身份正文。 |
| Project / ProjectMember ref | 建立 Project scope、裁剪项目分区。 | 项目成员生命周期或授权规则。 |
| Conversation / work / process safe summary ref | 形成可见入口、摘要和 source provenance。 | Turn/message body、WorkItem truth、Activity truth。 |
| Governance / visibility decision ref | 执行可见性裁剪、失效和 fail-closed。 | policy/decision 正文、allowlist。 |
| Artifact consumable ref | 显示安全制品入口及其版本语境。 | Artifact body、lineage、baseline truth。 |
| Bus event / replay ref | 驱动 projection maintenance 和 gap diagnosis。 | delivery/ack/DLQ/replay carrier truth。 |

## 4. 状态组与一致性边界（候选）

### 4.1 状态组

| 状态组 | 承载对象 | 主线状态候选 | 不变量 |
|---|---|---|---|
| Scope resolution | `WorkspacePartition` / `VisibilityBinding` | unresolved / verified / restricted / invalid / revoked | visibility 不可验证时不得转为 verified。 |
| Source ingestion | `SourceCursorState` | idle / advancing / duplicate / late / gap / replaying / blocked | cursor gap 不得被 read cursor 或默认值掩盖。 |
| Projection | `WorkspaceProjection` / `ProjectionRevision` | absent / building / current / stale / partial / invalidated / blocked | current 必须可回链 generation、coverage 与 visibility binding。 |
| Rebuild generation | `ProjectionGeneration` / `RebuildAttempt` | requested / baselining / catching-up / validating / cutover / failed / superseded | 不得混合两个 generation 的未验证分区形成伪快照。 |
| Inbox item | `InboxItemProjection` | visible / hidden-local / muted-local / read-local / stale / suppressed | local disposition 不改变 source attention truth；visibility revoke 优先于 local state。 |
| Local cursor | `ReadCursor` / `UnreadProjection` | unset / advanced / conflict / recalculating / unavailable | read cursor 不等于 source cursor，不可越权跨 scope 使用。 |
| Read response | `WorkspaceReadStatus`（候选） | fresh / stale / partial / blocked / fail-closed / rebuilding / unavailable | 任何状态都须指明 coverage/原因，敏感内容按 fail-closed 裁剪。 |

### 4.2 关键一致性规则（候选）

1. **source-owned vs workspace-owned 分离**：同一用户动作若意图改变消息、任务、流程或治理结论，不能借 workspace local-state transaction 完成；只能形成独立的 owner command。
2. **query no-write**：所有 workspace read query 不得创建 projection、推进 source cursor、更新 read cursor、触发隐式 refresh 或改变 source/local truth。若实现需要缓存预热，必须通过显式维护路径并与 query 结果分层。
3. **visibility first**：更新、读取、重建和输出任何外部 summary/ref 前，均以当前可验证 visibility binding 为门槛；撤销和冲突优先导致遮蔽/失效。
4. **generation isolation**：rebuild generation 未完成 cutover 前，不能和当前 generation 混写为同一个 complete view；切换必须是可追溯的 workspace-local 变化。
5. **cursor separation**：source cursor 推进、view revision 更新、read cursor 更新是三条不同的事务主线，不能用任一条成功推断另两条成功。
6. **idempotent application**：相同 source event/snapshot 在等价语境下重复应用不能产生重复 InboxItem、重复 unread 或不一致 view revision；来源变化需形成显式新 revision/generation。
7. **cross-domain consistency is declared, not assumed**：read response 至少需要声明各来源的 version/watermark、coverage 和 degraded status；第一版不承诺跨域全局强一致快照，除非正式 owner contracts 后续提供可证明 barrier。
8. **local-state scope confinement**：pin/mute/read/preference/focus 必须绑定 principal 与 scope；不能因同一 source ref 在多个 scope 出现就默认跨 scope 同步。

### 4.3 建议的事务 / 交接边界（候选）

| 用例 | workspace 内可原子收口 | 外部边界 / 禁止假设 |
|---|---|---|
| 应用一个已验证 source event | source application record、source cursor、受影响 projection revision、coverage/gap 状态。 | bus delivery/ack、source domain 真相变化已在外部完成。 |
| 更新一个 local disposition | disposition、local-state version、相关 unread projection（若属于同一 local scope）。 | 不更新 conversation receipt、任务状态或其他成员状态。 |
| 读取 workspace view | 纯读取现有 partition/revision/coverage/local-state。 | 不隐式刷新、不推进任何 cursor、不发源域命令。 |
| 发起 refresh/rebuild | 创建本地 attempt/generation、冻结目标 source scope 与起始语境。 | owner snapshot/replay 是否可用、外部任务调度与真实 completion 都需独立反馈。 |
| rebuild cutover | 新 generation 的已验证 projection、coverage、visibility binding 与 old/new lineage。 | 不等于 archive snapshot、下游消费确认或 bus replay completion。 |
| 对外 read/export handoff | 提供带 revision/provenance/status 的安全读取材料或本地 handoff attempt。 | SDK/client/cache、sync 结果、archive acceptance 归下游 owner。 |

## 5. 关键 port / seam 类别（候选，不锁协议）

| seam | 方向 | 能力语义 | 当前约束 |
|---|---|---|---|
| Principal/scope resolver | 入站 | 获取或验证请求主体、scope ref 和调用语境。 | 不自行认证或创建身份。 |
| Visibility/governance resolver | 入站 | 获取正式可见性/适用性/撤销结论或安全 ref。 | unknown/conflict 必须 fail-closed。 |
| Owner safe-query ports | 出站 | 从 identity/work/conversation/process/governance/artifact 读取安全 summary/ref 与版本/水位。 | no-write；exact query surface pending。 |
| Event subscription port | 入站 | 接收获准 owner 事件，形成可应用输入或 gap。 | L0-bus 承载 delivery；event family/cursor contract pending。 |
| Replay/baseline port | 出站 | 在 gap/rebuild 时请求 source replay 或 baseline snapshot。 | 不保证存在；无合同时 blocked。 |
| Local-state command port | 入站 | 更新 read/pin/mute/preference/focus 等 workspace-only 状态。 | 不能承接上游业务命令。 |
| Workspace read port | 出站 | 返回 Personal/Project read model、coverage、provenance、degradation。 | 不锁 API/DTO/分页/transport。 |
| Consumer/export handoff port | 出站 | 向 SDK、产品、sync、archive 边界提供受控只读材料。 | 下游合同未闭口时只保留 ref/adapter seam。 |
| Maintenance scheduler/lock port | 双向 | 发起/协调 refresh/rebuild/cleanup/diagnostics。 | adapter 不是 truth owner；不能把 job 成功当 source truth。 |

`fake` seam 在未来测试中只能模拟上述 port 的允许输出、延迟、缺口和失败，用于验证本地状态与降级逻辑。它不得生成“真实 owner 已确认”“bus 已送达”“archive 已完成”之类的证据。

## 6. 模块裁剪与推进顺序建议（供正式 07 参考，不构成计划承诺）

| 阶段方向 | 最小组成部分 | 进入条件 | 当前状态 |
|---|---|---|---|
| A. local truth foundation | 1、2 的最小子集、7 的 local-state 语义 | principal/scope 与 visibility 失败边界可表达。 | 可讨论；exact owner resolver pending。 |
| B. single-source safe read | 3、4、8 的最小子集 | 至少一个 owner 有正式 no-write query、version 与 visibility 输入。 | `WS-UP-001/003/007` 控制。 |
| C. scoped composition | 5 或 6 的一个最小分区 | 该 scope 的 identity/work ref 和 source safe summary 合同闭口。 | `WS-UP-005` 控制。 |
| D. event maintenance | 4、9 的事件/cursor/rebuild子集 | event identity、cursor、replay/baseline 与保留语义可验证。 | `WS-UP-002` 控制。 |
| E. Inbox/unread | 7 的 attention/read-cursor 子集 | owner 明示 attention input 与 local disposition 边界已闭口。 | `WS-UP-004` 控制。 |
| F. cross-domain view | 3~9 的多来源组合 | 每个加入域有独立 query/event/visibility/coverage 结论。 | 逐域推进，不能以一个域闭口代替其他域。 |
| G. downstream export | 8、9 的 handoff 子集 | SDK/product/sync/archive consumer contract 已正式定义。 | `WS-UP-006` 控制。 |

因此，第一版的正确裁剪方向不是“先把所有六域画到 UI 上”，而是先证明一个最小 scope/一个或少数 source partition 能在 no-write、visibility、version、gap 和 rebuild 语义下成立。任何域的正向接入必须独立获得其 owner 合同，不得由 workspace adapter 或 fake 补齐。

## 7. 本篇讨论结论

候选结构已把 `L1-workspace` 划分为 workspace local truth、scope/visibility、source query、projection maintenance、Personal/Project composition、Inbox/local attention、read handoff 和 rebuild/diagnostics 九类职责，并以应用服务、领域模型、外部 seam、持久化投影、维护等分层隔离 source truth。后续正式 01~03 必须逐一收敛对象字段、状态转换、事务、port、事件、配置与测试切口；在 `WS-UP-001~008` 未闭口前，本篇任何模块都只是方向，不能被解释为已实现或已集成。

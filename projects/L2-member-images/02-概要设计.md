## 2. 本次设计目标与范围

> 校准来源：
> - `design-calibration/02_hld_step_02_goals_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述文件的“目标 / 非目标矩阵”“范围分层”和“回填草稿”小节，了解 current、conditional、future 与 excluded 的裁剪依据。

### 2.1 设计目标

| 目标 | 本概要收稳的结构结果 |
|---|---|
| 镜像定义与装配可追溯 | family / variant、persona binding、mapping snapshot、component pin、seed placement、baseline 与 revision 形成独立 local truth。 |
| 构建候选可判定 | intent、attempt、immutable input snapshot、outcome conclusion 与 candidate 分层，外部副作用未知时保守停留。 |
| 资格与来源链可审计 | provenance、applicable gate、eligibility 与 Artifact handoff 分开，缺 authority 时 fail closed。 |
| 下游供给可交接 | availability history 与 immutable pinned InstantiableEntry 独立成立；未来 consumer 仅可经 neutral entry / gap seam 交接，exact consumer contract 仍 pending。 |
| 派生维护不制造第二真相 | external snapshot、contract gap、trace、projection freshness 与 read model 可重建且只读。 |
| 详细设计有稳定入口 | 对象、Command / Query / conditional Event / Job、处理流、状态、异常与配置影响均有唯一承接章节，并保留 pending 上限。 |

### 2.2 当前范围

| 范围层 | 纳入内容 | 结果边界 |
|---|---|---|
| current | image family / variant 定义、persona binding、Role mapping ref / snapshot、component / extras / base pin、policy / memory / workspace seed 的 ref / placement、revision、build intent / attempt / candidate、provenance / gate / eligibility、availability / entry / gap、trace / projection | 仅保存本仓拥有的静态、派生和阶段性事实；外部正文与 live state 不进入。 |
| conditional | verified build-request inbound event、owner-safe conclusion refresh、Artifact / consumer handoff reconciliation、受控 adapter / profile | 需要正式 owner authority；当前可表达 neutral、pending、blocked、unavailable 与 gap，不声明 positive contract。 |
| future | hardened base、restricted / read-only variant、multi-architecture dimension、镜像域 outbound event | 仅保留触发条件和重开位置，不进入当前能力分母。 |
| excluded | member / runtime / tool execution、capability / governance / Artifact / Sandbox / container / observability / marketplace truth，以及 UI / 产品入口 | 由相邻 owner 或后续产品文档负责，本仓只提供受控 ref / adapter seam。 |

### 2.3 关键取舍

- 采用五个业务主要组成部分与正交实现分层，不按 prompt、tool、memory、workspace 等内容种类平铺。
- 采用 staged decisions：candidate、eligibility、availability、Artifact handoff、consumer / container state 永不合并成一个 ready。
- 采用 append / supersede / new context 恢复；不原地覆盖历史，也不以 latest、缓存或 ACK 补齐缺失真相。

## 3. 约束条件

> 校准来源：
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述文件的“约束矩阵”“依赖分类”“static / live 红线”和“回填草稿”小节，了解每条硬约束对对象、接口、流程和状态的限制。

### 3.1 Owner 与 truth 约束

| 事实 / 资产 | 真相 owner | 本仓可承接的形式 |
|---|---|---|
| RoleDefinition、Role -> image variant mapping | L3-method-library | MappingSourceSnapshot、source ref、validity / freshness；不复制 body。 |
| runtime、tools、member component、extras | 各自 owner | 已验证的 immutable component / capability / release ref；不保存执行或 live body。 |
| policy / memory / workspace seed semantic body | 正式 owner 待双方闭合 | owner-neutral template ref、static placement、contract gap；MI-UP-006 未关闭时 baseline 可保持 incomplete。 |
| Artifact version / lineage / formal consumable ref | L1-artifact | ArtifactHandoffRecord、optional owner ref、gap；不 mint Artifact truth。 |
| member host / container / launch / health | L2-member-service（并行 owner，合同待闭口） | InstantiableEntry 与 ConsumerHandoffGap；不写回 consumer / container state。 |
| local image definition / revision / build / qualification / availability history | L2-member-images | 正式 domain truth 与 append-only history。 |

### 3.2 Static / live 与安全边界

- 进入 baseline / input snapshot 的只能是可验证的静态 ref、pin、snapshot、placement 和 safe summary。
- secret、credential、live memory、checkpoint、workspace live content、observed container state、raw logs / reports 不进入本仓 truth。
- latest、mutable selector、猜测版本、默认值或缓存不能把缺失 pin 转成可构建或可供给状态。

### 3.3 依赖与接缝分类

| 类别 | 当前允许 | 当前不允许 |
|---|---|---|
| compile | 仅正式 L0-core shared contract | 由物理装配、adapter 或兄弟项目内容推导新的 compile dependency。 |
| runtime | 消费 runtime / tools / member 的正式 pinned ref 或 safe runtime conclusion | 把运行时消费写成源码 owner 或把 live loop 纳入本仓。 |
| event | 仅 conditional inbound verified build-request / source refresh seam | 未获 authority 的 event family、schema、outbound delivery 或 readiness。 |
| ref | immutable ref、snapshot、validity、freshness、correlation | 外部正文复制、ref mint 越权或猜测 digest。 |
| adapter | product-neutral builder / registry / evidence / Artifact / consumer port | 将 adapter ACK、registry presence 或 callback 直接当 local success。 |
| fake | 后续测试中的 source / adapter parity seam | fake、cache、projection 参与正式 truth 写入。 |

### 3.4 阶段、历史与失败约束

- definition / baseline / revision、intent / attempt / snapshot / candidate、provenance / gate / eligibility、availability / entry、Artifact handoff、consumer handoff、projection freshness 各自成立。
- missing、stale、conflict、failed、unknown、unavailable、gap 均为可见结果类别；受影响的新决策 lane fail closed，既有历史保持可读。
- 恢复必须创建新的 revision、attempt、evaluation、transition 或 superseding context；不覆盖旧结论、不盲重试未知副作用。
- projection / cache / manifest view 只读、可重建、显式 freshness，不反写任何 local truth。

### 3.5 当前挂起上限

MI-UP-001~007 只允许 neutral port、typed ref、safe conclusion、gap / blocked / unavailable 和重开点；MI-UP-008~009 仅记录 future / absence；Q-MI-001~004 仅保持 conditional、product-neutral、authority-driven。任何 exact DTO、route、topic、产品、gate inventory、digest、report、evidence、readiness 或 positive confirmation 均不得由本概要补齐。

## 5. 主要组成部分、职责与边界

> 校准来源：
> - `design-calibration/02_hld_step_05_components_boundary.md`
>
> 延伸阅读：
> - 建议继续阅读上述文件的“主要组成部分总表”“对象发现维度表”“各部分交互总图”和五个组成部分小节，了解第 6 章对象如何从本章候选池正式化。

### 5.1 五个主要组成部分

| 组成部分 | 核心职责 | 主要代码主体 | 不承担什么 |
|---|---|---|---|
| DefinitionAssembly | 形成 family / variant / persona assembly identity、完整 pinned baseline、revision / derivation 关系 | DefinitionAssemblyCoordinator、family / variant / baseline / revision subjects | 不定义 RoleDefinition / mapping truth，不拥有 component / seed 正文、live state 或 build outcome。 |
| BuildCandidate | 形成 build intent、attempt、immutable input snapshot，并将外部 outcome 转为 candidate / failed / blocked / unknown | BuildIntentCoordinator、BuilderPort、RegistryPort、intent / attempt / snapshot / outcome / candidate | 不拥有 scheduler、builder、registry job truth，不把 ACK 或 registry presence 当 candidate。 |
| Qualification | 绑定 digest / provenance，消费 applicable gate safe conclusion，形成 eligibility 或保守阻断 | QualificationCoordinator、EvidenceConclusionPort、provenance / gate / eligibility / handoff subjects | 不拥有 evidence / policy / Artifact 正文或治理审批真相，不把 eligibility 当 availability。 |
| SupplyEntry | 管理 availability history、publish / replace / rollback / retire 与 immutable pinned entry / consumer gap | AvailabilityCoordinator、MemberServiceSupplyPort、transition / entry / gap subjects | 不创建容器，不判定 launch / health / upgrade，不拥有 Artifact / consumer truth。 |
| ReferenceDerived | 校验 ref / snapshot / safe conclusion / gap，维护 trace、catalog、manifest、freshness 与对账 | ReferenceIntakeCoordinator、ProjectionRebuilder、snapshot / gap / trace / freshness subjects | 不创建核心 positive truth，不保存外部正文，不让 projection / cache / fake 反写。 |

### 5.2 组成部分交互

```text
DefinitionAssembly
  | mapping / component / seed refs + complete pinned baseline
  v
BuildCandidate
  | builder / registry outcome -> candidate or explicit uncertainty
  v
Qualification
  | provenance + applicable gate + Artifact handoff gap
  v
SupplyEntry
  | immutable entry / availability history / consumer gap
  v
future consumer seam (host / container truth remains external)

ReferenceDerived 横向支撑：
  external snapshots -> guards / decisions; truth -> trace / projections;
  projection / reconciliation failures never write back to the stages above.
```

### 5.3 对象发现候选池

| 组成部分 | Truth / state 候选 | Policy / guard 候选 | Reference / projection / history 候选 |
|---|---|---|---|
| DefinitionAssembly | family、variant、baseline、revision | AssemblyCompletenessGuard、PinIntegrityGuard | mapping snapshot、component pin、seed placement、derivation history |
| BuildCandidate | intent、attempt、candidate | CandidateFormationGuard | input snapshot、outcome conclusion、build trace |
| Qualification | provenance、gate evaluation、eligibility | ProvenanceCompletenessGuard、ApplicableGateGuard | evidence ref、Artifact handoff、qualification history |
| SupplyEntry | availability transition、instantiable entry、consumer gap | EntryPinGuard、AvailabilityTransitionGuard | registry / Artifact ref、availability / rollback history、entry view |
| ReferenceDerived | external snapshot、contract gap、projection freshness | ReferenceValidityGuard、ProjectionReadOnlyGuard | image trace、derived read model、gap / maintenance view |

### 5.4 边界规则

- 一个业务部分可跨多个实现层；一个实现层也可承接多个业务部分，不能据此推导物理服务数量。
- 外部正文、live state、审批、container outcome 和产品协议均通过 owner-controlled ref / adapter / gap 进入，不转移 ownership。
- 第 6 章逐对象展开字段类型、状态、成员函数、工厂函数和禁止事项；API、处理流和状态传播分别在第 7~9 章展开。

## 7. API / 接口骨架

> 校准来源：
> - design-calibration/02_hld_step_07_api_interface_skeleton.md
>
> 延伸阅读：
> - 建议继续阅读上述文件的“Command API”“Query API”“Inbound Event Consumer”“Outbound Event”和“Operations Job”小节，了解每个接口的对象承接与 pending 结果边界。

### 7.1 接口分类与共性

| 接口类别 | 作用 | 本仓写入 / 读取边界 |
|---|---|---|
| Command | 改写本仓正式 truth，携带 metadata、幂等语境及必要 actor | 只能写本仓 owner 的对象与 history；外部 adapter、projection、consumer 不直接写 truth。 |
| Query | 读取正式 truth 或可重建的 derived view | 只读；stale、rebuilding、unavailable、gap 必须显式返回。 |
| Inbound Event Consumer | 条件性地把已验证的外部触发转换为本地 command / snapshot | 先验证 authority、event identity、correlation 与幂等；arrival / ACK 不等于 intent 或 candidate。 |
| Outbound Event | 对外发布本域事实 | 当前没有已授权的镜像域 outbound build / publish event；不可由 transition 推导。 |
| Operations Job | 基于已持久化事实做 nightly、refresh、rebuild、reconciliation | 不替代同步合法性判断，不以 job 完成推导业务 readiness。 |

Command 的共同骨架为 CommandMetadata、必要时的 ActorContext、IdempotencyKey 与对象 ref；Query 默认带 ActorContext 和 freshness 语境；Event 带 EventEnvelope、source identity、event id、correlation；Job 带 JobContext 和持久化对象范围。完整协议、路由、序列化、错误码留给 03。

### 7.2 Command 骨架

| Command | 输入骨架 | 输出 / 写入结果 | 关键边界 |
|---|---|---|---|
| DefineImageVariant | actor、metadata、idempotency、family ref、MappingSourceSnapshot | variant definition ref 或 ContractGap | 不写 mapping body。 |
| CaptureAssemblyBaseline | variant ref、受控 component pins、seed placements、base ref | baseline ref 或 incomplete / conflict | static pin 缺失时不生成 buildable revision。 |
| ProposeVariantRevision | baseline ref、derivation ref | revision ref 或 invalid | append / supersede，不覆盖旧 revision。 |
| RequestBuildIntent | buildable revision、BuildTriggerContext | intent ref 或 pending / blocked | accepted 不等于外部构建完成。 |
| RecordBuildOutcome | attempt ref、BuildOutcomeConclusion | candidate ref 或 failed / unknown / gap | 必须能回链 output、attempt、snapshot。 |
| EvaluateCandidateEligibility | candidate、provenance、gate evaluation refs | eligibility decision ref 或 pending / blocked | applicable gate 未闭合时 fail closed。 |
| RecordArtifactHandoff | candidate、eligibility、optional Artifact ref | handoff record 或 ContractGap | 不自造 ArtifactVersion / lineage / formal ref。 |
| PublishInstantiableEntry | eligibility、immutable image ref、provenance | entry ref 或 rejected / blocked | 生产入口必须 pinned。 |
| TransitionAvailability | variant ref、transition kind、target refs | transition ref | publish / replace / rollback / retire 只追加 history。 |
| RollbackOrRetireEntry | entry ref、reason | 新 transition ref | 不删除 candidate、digest 或旧 entry。 |

### 7.3 Query 骨架

| Query | 输出骨架 | 读取来源与边界 |
|---|---|---|
| GetImageVariantDefinition | safe definition summary / derived read model | 不返回 Role、component 或 seed 正文；freshness 显式。 |
| GetAssemblyDerivation | derivation view | 只读 baseline / revision / trace。 |
| GetBuildTrace | build trace view / gap | 不暴露 raw job、log 或 report body。 |
| GetProvenanceAndEligibility | provenance / gate / eligibility safe view | eligibility 不改写 availability 或 Artifact accepted。 |
| ResolveInstantiableEntry | pinned entry view / ConsumerHandoffGap / unavailable | 不解析 mapping、不等待 launch / health；MI-UP-001 未闭口时 positive resolve blocked。 |
| ListAvailableVariants | availability catalog view | 只列本地 available 语义并标 freshness。 |
| GetAvailabilityHistory | append-only transition history | 不删除、重排或覆盖历史。 |
| GetImageTrace | trace view | trace 不是 source truth。 |
| GetContractGaps | gap summary view | 只读解释，不关闭 gap。 |
| GetProjectionFreshness | ProjectionFreshness | freshness 不代表业务 ready。 |

### 7.4 条件入站事件与运维 Job

| 入口 | 当前状态 | 处理边界 |
|---|---|---|
| ConsumeVerifiedBuildRequest | conditional；MI-UP-005 未闭口时 unavailable / rejected | 验证 envelope 后最多调用 RequestBuildIntent；未知事件不产生 intent / candidate。 |
| ConsumeVerifiedSourceRefresh | conditional；exact owner contract pending | 只形成 ExternalReferenceSnapshot 更新候选或 gap，不直接写 definition / eligibility / availability。 |
| RunNightlyBuildSweep | current intent source | 选择已持久化 buildable revision；nightly 不代表 build / candidate / eligibility / availability 完成。 |
| ReconcileBuildAttempts | current maintenance | 追加 outcome / resolution / new attempt context；unknown 不盲重试。 |
| ReevaluatePendingQualifications | current maintenance | 追加 evaluation / eligibility 或 blocked；不默认关闭 gate。 |
| RefreshExternalReferenceSnapshots | current maintenance | 更新 snapshot、validity、freshness 或 gap；不反写 owner truth。 |
| RebuildImageDerivedViews | current maintenance | 从正式 truth 重建 read model；projection 不写回 domain。 |
| ReconcileArtifactAndConsumerHandoffs | current but contract-bounded | 只维护 handoff / gap；MI-UP-001/007 未闭口时不声明 confirmation。 |

### 7.5 Outbound event 现状

当前无已授权的镜像域 outbound event。availability、eligibility、publish 等事实通过 Query、immutable ref、handoff seam 提供；不伪造 event family、topic、outbox、delivery 或 observation success。若 MI-UP-009 将来关闭，必须重开第 2、3、7、8、9、11~13 章对应 calibration Step。

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - design-calibration/02_hld_step_08_processing_flows.md
>
> 延伸阅读：
> - 建议继续阅读上述文件的“通用处理流骨架”“处理流覆盖清单”和各独立处理流小节，了解每条流的 guard、port、history 与 gap 分支。

~~~text
Command / Query / Event / Job
  |
  v
Inbound / Consumer / Operations
  - 读取 metadata、幂等语境和 actor / source context
  - 拒绝未验证来源，不把 arrival / ACK 当领域成功
  |
  v
Application Service
  - 读取已提交事实与受控 refs
  - 编排 domain guard、local decision 和 inward ports
  |
  v
Domain Object / Policy
  - 追加本仓 truth、history、gap 或 stage decision
  - 不读取 external body，不改变相邻 owner truth
  |
  v
Persistence / Projection / Handoff
  - 保存 local truth 或从 truth 重建只读视图
  - external handoff 只记录 ref / outcome / gap
  |
  v
Result / Projection / Pending
~~~

### 8.2 定义、baseline 与 revision

~~~text
DefineImageVariant / CaptureAssemblyBaseline
  -> 校验 actor、metadata、idempotency
  -> 读取 MappingSourceSnapshot、component pin、seed placement
  -> AssemblyCompletenessGuard + PinIntegrityGuard
  -> complete / incomplete / conflict
  -> 追加 definition / baseline history；不完整则 ContractGap
  -> DefinitionTruthRepositoryPort -> ref / derivation view

ProposeVariantRevision
  -> 读取 variant 与 baseline
  -> VariantRevision.propose(...)
  -> validate(AssemblyCompletenessGuard)
  -> proposed -> buildable 或 invalid / blocked
  -> append supersedes / derivation，不覆盖旧 revision
~~~

关键规则：mapping、component、seed 只以 ref / snapshot / placement 进入；buildable 只表示可请求构建，不代表 candidate、eligibility 或 availability。

### 8.3 intent、attempt 与 candidate

~~~text
RequestBuildIntent / RunNightlyBuildSweep
  -> 选取已持久化 buildable revision
  -> 建立 trigger context / idempotency
  -> BuildIntent.request(...)
  -> BuildIntent + BuildInputSnapshot
  -> accepted / pending / blocked
  -> BuildTruthRepositoryPort

RecordBuildOutcome
  -> 校验 attempt、correlation、idempotency、outcome ref
  -> BuildAttempt.record_outcome(...)
  -> CandidateFormationGuard
  -> CandidateImage 或 failed / blocked / unknown
  -> BuildTruthRepositoryPort
~~~

nightly 只是 intent 来源；builder success、registry presence、callback 或 transport ACK 不能直接形成 candidate。未知副作用必须停在 attempt.unknown 或 candidate.unknown，等待 resolution / 新语境。

### 8.4 条件事件、资格与 Artifact handoff

~~~text
ConsumeVerifiedBuildRequest
  -> 验证 EventEnvelope、source authority、event id、correlation、幂等
  -> verified event 转 BuildTriggerRef
  -> RequestBuildIntent
  -> accepted / pending / blocked；arrival 不产生 candidate

EvaluateCandidateEligibility
  -> 读取 CandidateImage、provenance 与 owner safe conclusions
  -> ProvenanceCompletenessGuard
  -> ApplicableGateGuard
  -> GateEvaluation + EligibilityDecision
  -> eligible 或 pending / ineligible / blocked

RecordArtifactHandoff
  -> 验证 candidate / eligibility 与 MI-UP-007 状态
  -> ArtifactHandoffRecord.open(...)
  -> optional owner ref 或 ContractGap
  -> 不写 ArtifactVersion / lineage truth
~~~

### 8.5 supply、resolve 与派生视图

~~~text
PublishInstantiableEntry / TransitionAvailability
  -> 读取 eligible candidate、provenance、immutable image ref
  -> EntryPinGuard + AvailabilityTransitionGuard
  -> transition proposed / committed / rejected
  -> InstantiableEntry + availability history
  -> pinned entry 或 blocked

ResolveInstantiableEntry
  -> 读取 availability truth、entry view、ConsumerHandoffGap、ProjectionFreshness
  -> pinned entry / unavailable / contract-gap / stale view
  -> future consumer boundary；不等待 launch / health

RebuildImageDerivedViews
  -> 读取 truth watermark、trace、gap
  -> ProjectionFreshness=rebuilding
  -> 从 definition / candidate / qualification / supply truth 重建
  -> fresh / stale / unavailable；不反写 truth
~~~

### 8.6 外部引用刷新与对账

RefreshExternalReferenceSnapshots 和 ReconcileArtifactAndConsumerHandoffs 读取 owner ref、safe conclusion、handoff record 与 gap，分类 valid / stale / conflict / unavailable / pending，追加 snapshot、gap、trace 或 freshness。外部 source 变化只影响受影响的新 decision lane；既有成立事实和历史不删除，positive confirmation 未到达时不自行推断。

### 8.7 处理流统一边界

- 每条同步 Command 先做本地 guard，再决定是否创建外部 handoff；accepted 不等于 completed。
- 外部 side effect 的结果必须有 attempt、input snapshot、output ref 和 correlation 的可验证关联，才能形成 candidate。
- projection、cache、fake、ACK、registry presence 和 consumer observed state 不参与核心正向写入。
- 完整 adapter、repository、事务、并发、retry / timeout、错误映射和序列化留给 03。

> 校准来源：

> 延伸阅读：

### 9.1 状态模型

### 9.2 状态定义

| 状态轴 | 主要状态集合 | 语义边界 |
|---|---|---|
| definition | definition.draft、definition.resolved、definition.blocked、definition.superseded | resolved 只表示来源 / 必要 pin / placement 可验证；旧语境 superseded 仍可读但不可作新输入。 |
| baseline | baseline.incomplete、baseline.complete、baseline.conflict、baseline.superseded | complete 是静态输入完整，不代表 revision、build 或 candidate。 |
| revision | revision.proposed、revision.buildable、revision.invalid、revision.superseded | buildable 只开启 intent 判断；invalid 恢复必须新 revision。 |
| intent | intent.accepted、intent.pending、intent.blocked、intent.cancelled | accepted 只表示本地 trigger guard 通过。 |
| snapshot | snapshot.complete、snapshot.incomplete、snapshot.invalid | complete 才能建立 attempt；不表示 external handoff 成功。 |
| attempt | attempt.created、attempt.handoff_pending、attempt.outcome_pending、attempt.succeeded、attempt.failed、attempt.unknown | unknown 不得普通 retry 或 success；succeeded 仍需 candidate guard。 |
| candidate | candidate.formed、candidate.rejected、candidate.blocked、candidate.unknown | formed 只进入 qualification。 |
| provenance | provenance.complete、provenance.incomplete、provenance.conflict | complete 只供 gate / eligibility 判断。 |
| gate | gate.pending、gate.passed、gate.failed、gate.blocked、gate.unknown | applicable gate 缺 authority 或 unknown 时不通过。 |
| eligibility | eligibility.pending、eligibility.eligible、eligibility.ineligible、eligibility.blocked | eligible 只表示 image 资格，不表示 Artifact 或 availability。 |
| transition | transition.proposed、transition.committed、transition.rejected、transition.superseded | committed 是本地 availability 变化，不是 consumer / container 完成。 |
| supply | supply.unavailable、supply.available、supply.superseded、supply.retired | available 需要 immutable entry；retired 不复活旧 entry。 |
| Artifact handoff | artifact_handoff.pending、artifact_handoff.gap、artifact_handoff.accepted | 当前 MI-UP-007 未闭口，不假设 accepted。 |
| consumer handoff | consumer_handoff.open、consumer_handoff.resolved、consumer_handoff.stale | 当前 MI-UP-001 未闭口，不假设 resolved；resolved 也不等于 container started。 |
| contract gap | contract_gap.open、contract_gap.blocked、contract_gap.resolved、contract_gap.expired | 只有正式 authority 与 resolution ref 才能 resolved。 |
| reference | reference.valid、reference.stale、reference.conflict、reference.unavailable | validity 取决于消费语境；stale / conflict / unavailable 不能支持新 positive decision。 |
| projection | projection.fresh、projection.stale、projection.rebuilding、projection.unavailable | 只表达读侧 freshness，不代表业务 ready。 |

### 9.3 正向骨架与传播

~~~text
definition.draft
  -> definition.resolved
  -> revision.buildable
  -> intent.accepted
  -> snapshot.complete
  -> attempt.created
  -> attempt.handoff_pending
  -> attempt.succeeded
  -> candidate.formed
  -> eligibility.eligible
  -> transition.committed
  -> supply.available
  -> supply.superseded / supply.retired

local transition
  -> append local history / trace
  -> refresh projection (fresh / stale / rebuilding / unavailable)
  -> expose pinned entry or ContractGap
  -> consumer acts independently; no container state writeback
~~~

图仅表示可行的正向骨架。任一阶段都可能进入 pending、blocked、failed、unknown、rejected 或 unavailable；eligibility.eligible 不自动生成 supply.available，supply.available 不传播为 launch、health 或 confirmation。

### 9.4 允许与禁止迁移

| 允许迁移 | 条件 |
|---|---|
| definition.draft -> definition.resolved | source、必要 pin、static placement 可验证。 |
| baseline.incomplete / conflict -> revision.invalid | baseline 不满足必要输入或存在冲突。 |
| revision.proposed -> revision.buildable | completeness / pin guard 通过。 |
| revision.buildable -> intent.accepted | request / nightly 本地 guard 通过。 |
| intent.accepted -> snapshot.complete -> attempt.created | immutable snapshot 成立。 |
| attempt.outcome_pending -> succeeded / failed / unknown | 获得可验证 outcome、明确失败或未知结论。 |
| attempt.succeeded -> candidate.formed | candidate formation guard 通过。 |
| provenance.complete -> gate.pending -> gate.passed / failed / blocked / unknown | safe gate conclusion 完成或保守失败。 |
| eligibility.pending -> eligible / ineligible / blocked | provenance / gate 结论可验证或保守失败。 |
| eligibility.eligible -> transition.proposed -> committed -> supply.available | entry pin、transition 与 history guard 通过。 |
| supply.available -> superseded / retired | 新 entry 替换或明确退役。 |

禁止迁移包括：attempt.unknown -> candidate.formed、attempt.unknown -> attempt.succeeded、candidate.formed -> supply.available、gate.unknown -> gate.passed、eligibility.blocked -> eligibility.eligible、supply.unavailable -> supply.available（latest / 猜版本 / ACK 均不例外）、supply.retired -> supply.available、projection.* -> 任一核心 truth，以及任何旧 revision / attempt / evaluation / transition 的原地改写。




## 10. 异常与边界场景轮廓

> 校准来源：
> - design-calibration/02_hld_step_10_exceptions_boundaries.md
>
> 延伸阅读：
> - 建议继续阅读上述文件的“异常与边界场景表”“异常影响图”“异常归属与恢复边界”和“异常与状态 / 接口反查”小节，了解失败如何隔离到受影响的新 lane。

### 10.1 异常场景与归属

| 场景 | 处理部分 / guard | 概要结果 |
|---|---|---|
| Role / mapping source missing、stale、conflict | ReferenceDerived + DefinitionAssembly | ExternalReferenceSnapshot / ContractGap；受影响 definition / revision blocked，不 fallback 或 hardcode。 |
| 必要 component / extras / base pin 缺失 | AssemblyCompletenessGuard、PinIntegrityGuard | baseline.incomplete；不能创建 buildable revision，旧 revision 不覆盖。 |
| member component shape / compatibility 未闭口 | DefinitionAssembly + ReferenceDerived | MI-UP-002 pending；positive assembly lane blocked，不自造 compatibility report。 |
| seed owner / placement 不可验证 | DefinitionAssembly | owner-neutral ref / placement gap；semantic body 与 live state 外置。 |
| static input 含 secret、live memory、checkpoint、workspace live content | boundary guard | 拒绝 baseline / snapshot，不得用 config 绕过。 |
| latest、mutable selector、guessed version | completeness / entry guard | 立即 fail closed，不转换为 immutable identity。 |
| duplicate / replayed command | application idempotency guard | 返回既有语境或显式 conflict，不创建第二份 truth。 |
| unknown event source / family / envelope | conditional Event Consumer | rejected / unavailable；arrival 不产生 intent / candidate。 |
| builder / registry handoff timeout / unavailable | BuildCandidate | attempt.handoff_pending / unknown / blocked；不推断 digest / candidate。 |
| side effect 已发生但 outcome unknown | BuildCandidate | attempt.unknown，等待 resolution / 新语境；禁止盲重试。 |
| output ref 无法关联 input snapshot / attempt | CandidateFormationGuard | 不形成 CandidateImage，记录 failed / blocked / unknown。 |
| digest / provenance 不完整或冲突 | Qualification | provenance.incomplete / conflict；eligibility 不得 positive。 |
| applicable gate 缺失、失败、冲突、unknown | ApplicableGateGuard | gate.pending / failed / blocked / unknown；不默认 pass。 |
| Artifact handoff schema / ref 未闭口 | Qualification + ReferenceDerived | ArtifactHandoffRecord.pending / gap；不定义 ArtifactVersion / lineage / formal ref。 |
| eligible candidate 缺 immutable entry | SupplyEntry | 不提交 availability；blocked / unavailable，保留 eligibility history。 |
| transition 与 history 冲突 | AvailabilityTransitionGuard | rejected；旧 availability 不变，恢复走新 transition。 |
| rollback target 不可验证或已 retired | SupplyEntry | rejected / blocked，不复活旧 entry、不删除历史。 |
| consumer manifest / confirmation 缺失 | SupplyEntry + ConsumerHandoffGap | MI-UP-001 open / unavailable；不声明 launch、health、confirmation。 |
| consumer / container observed failure | SupplyEntry boundary | 只记录 consumer gap / external conclusion，不反写 image availability。 |
| late / duplicate / out-of-order outcome | BuildCandidate + ReferenceDerived | 按 attempt / correlation 关联；ignored / linked / new decision input，不覆盖较新 truth。 |
| projection lag / rebuild failure | ReferenceDerived | ProjectionFreshness.stale / rebuilding / unavailable；不从 projection 回填核心。 |
| Artifact / consumer 对账发现新 gap | ReferenceDerived + 对应阶段 | 追加 ContractGap / handoff record，冻结受影响新 lane，不删除已成立历史。 |
| future hardened base、restricted、multi-arch、outbound event 被提前请求 | Scope boundary | 记录 future / conditional，不创建 current object、接口、状态或 readiness。 |

### 10.2 跨阶段失败隔离

~~~text
External source / adapter / owner gap
              |
              v
     +----------------------+
     | ReferenceDerived      |
     | snapshot / gap        |
     +----------+-----------+
                | blocks only affected new lane
                v
     +----------------------+       +----------------------+
     | Definition / Build   | ----> | Qualification /      |
     | pending / blocked    |       | Supply pending       |
     +----------------------+       +----------+-----------+
                                                v
                                     +----------------------+
                                     | Entry / consumer gap |
                                     | no launch assertion   |
                                     +----------------------+

Existing committed truth / history remains readable and is not overwritten.
~~~

外部故障只冻结受影响的新 decision lane；ContractGap、blocked、unknown、unavailable 是正式结果类别，不是暂时日志标签。

### 10.3 恢复边界

| 异常类别 | 允许的概要级恢复 | 禁止的恢复 |
|---|---|---|
| 来源不可用 / stale | refresh、new snapshot、new decision context | latest、copied body、cached default 直接转 positive。 |
| 本地 invariant 不完整 | 保留 failed / blocked，补齐后新 revision / attempt / evaluation / transition | partial candidate / eligibility / available。 |
| 外部 side effect unknown | resolution 或显式新 attempt | 无证据推断 success、盲重试。 |
| gate / Artifact / consumer gap | 新 owner ref / safe conclusion 到达后新判断 | 自造 ref、confirmation、launch 或 readiness。 |
| projection / read model 故障 | 从正式 truth rebuild，表达 freshness | projection 反写核心、隐藏 stale。 |
| 历史冲突 / late result | append linked fact、supersede 或 new context | 原地覆盖较新 truth。 |

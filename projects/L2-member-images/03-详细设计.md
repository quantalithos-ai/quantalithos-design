## 1. 模块职责描述

**本模块做什么**:
- 持有正式 MemberImage / ImageRoleBinding / ImagePersona / ImageToolset / PolicyOverlay / MemorySeed / WorkspaceSeed / ImageVersion / ImageDerivation / InstantiateBundle 真相
- 把成员 persona、prompt、toolset、policy overlay、memory/workspace seed 收束成统一镜像资产
- 管理镜像版本、派生、publish / activate / retire 主线
- 向 member / runtime / conversation / UI / observability 提供稳定实例化与只读目录出口

**本模块不做什么**:
- 不持有 Member 正式实例真相
- 不持有 identity role truth、capability contract truth、live memory、workspace truth 或 conversation history
- 不直接推进 runtime 执行状态或对话主状态
- 不替代 method-library、capability-hub、governance 的源真相本体

## 2. 前置设计前提 / 内容采集提示

### 2.1 为什么在写 03 前要先采集内容

`03-详细设计` 的目标不是再讲 member-images“为什么存在”,而是让开发者可以直接开始实现:
- image definition 如何统一承载 role、persona、toolset、seed 和 derivation 主线
- persona/prompt/style 怎样作为 seed 被稳定装配给 runtime / member
- capability refs / policy overlay 怎样只做装配而不污染 source truth
- memory/workspace seed 怎样进入实例化 bundle 而不混成 live state
- version / derive / publish / retire / instantiate 怎样形成统一镜像资产主线

如果不先把这些内容采集清楚,03 很容易退化成:
- prompt 模板列表
- workspace seed 文件清单
- capability refs 配置表
- member/runtime 初始化脚本笔记
- 派生和替换各写一套没有共同证据链的逻辑

## 5. 按主要部分展开实现要点

### 5.1 为什么要先按主要部分展开

`03-详细设计` 不能直接从 `MemberImage / PromptSeed / ImageToolset / WorkspaceSeed / ImageVersion` 这些对象平铺开始。
更稳的写法是:
- 先承接 `02-概要设计.md` 已确认的五个主要部分
- 再说明每个主要部分分别落到哪些对象、命令/函数、状态约束、存储与对外消费
- 最后再进入横向的对象模型、流程、存储、异常与测试细节

```rust
/// 根据 role 和镜像元信息创建正式 MemberImage 草稿。
fn create_member_image(
    image_repo: &dyn MemberImageRepo,
    role_binding: ImageRoleBinding,
    metadata: ImageMetadata,
) {
    // [role_binding.校验绑定边界]
    // 先确认这是对 role truth 的引用绑定,而不是 role truth 本体复制。
    role_binding.validate_role_binding_boundary();

    // [MemberImage::从元信息创建]
    // 再把 role 绑定与元信息收束成正式镜像草稿对象。
    let image = MemberImage::from_metadata(role_binding, metadata);

    // [image_repo.保存镜像草稿]
    // 最后把镜像草稿写入模板真相层,供 persona/toolset/seed 主线继续装配。
    image_repo.save_draft(image);
}
```

这段实现守住的边界是:
- image 先作为模板资产成立,后续人格、能力、seed 才能稳定附着
- role binding 只表达适配关系,不持有 role truth 本体
- image 草稿与 member 实例生命周期必须分层

#### 5.2.5 该部分的边界与非职责
- 不持有 Member 正式实例真相
- 不负责 prompt/style 种子本体
- 不负责 capability contract 真相
- 不负责 runtime live state

#### 5.2.6 该部分与其他主要部分的接缝
- 向 `Persona 与交互种子装配部分` 提供 image 锚点输入
- 向 `工具、能力与策略覆盖装配部分` 提供 image / role 范围输入
- 向 `版本、派生与实例化出口部分` 提供 image 主记录输入

```rust
/// 为镜像构建正式 persona 与 prompt/style 种子包。
fn build_persona_bundle(
    persona_repo: &dyn ImagePersonaRepo,
    image: MemberImage,
    seed: PromptSeed,
    style: InteractionStyle,
) {
    // [seed.校验 persona 边界]
    // 先确认 prompt/style 只是默认种子,不是 conversation 历史或 live runtime state。
    seed.validate_persona_seed_boundary();

    // [ImagePersona::从种子创建]
    // 再把 persona、prompt、style 收束成正式 persona bundle。
    let persona = ImagePersona::from_seed(image.member_image_id, seed, style);

    // [persona_repo.保存 persona bundle]
    // 最后把种子包写入镜像层,供 instantiate 与 UI 摘要消费。
    persona_repo.save_bundle(persona);
}
```

- persona/prompt/style 只是模板起点,不替代 runtime live state
- conversation history 不能倒灌回 image persona truth
- image persona 必须先于实例化输出稳定存在

- 不持有 conversation history
- 不直接持有 runtime live persona state
- 不负责 capability / policy overlay 本体
- 不负责 workspace/memory seed 本体

#### 5.3.6 该部分与其他主要部分的接缝

```rust
fn resolve_image_toolset(
```

```rust
fn build_instantiate_bundle(
```

```text
  - member_image_id
  - requester_ref
  - instantiate_reason

returns:
  - instantiate_ticket_id
  - error: IMAGE_NOT_PUBLISHED / IMAGE_RETIRED / IMAGE_BUNDLE_INCOMPLETE

side effects:
  - 写入 InstantiateTicket
  - 触发 instantiate bundle 输出
```

### 7.5 关键函数/命令级伪代码

#### `PublishImage`

```text
function PublishImage(input):
    1. 校验 image draft 存在
    2. 校验 role binding、persona、toolset、seed bundle 都已齐备
    3. 校验 capability / policy / starter refs 都未越界
    4. 生成新的 ImageVersion
    5. 写入 ImagePublishRecord
    6. 切换 image status=Published
    7. 返回 published image id / version
```

#### `BuildWorkspaceSeed`

```text
function BuildWorkspaceSeed(input):
    1. 校验 starter refs 存在且完整
    2. 校验这些材料只是初始化 seed,不是 active workspace truth
    3. 生成 WorkspaceSeed
    4. 计算 SeedIntegrityDigest
    5. 写入 StarterMaterialBundle
    6. 返回 workspace seed bundle
```

## 8. 运行期主线场景

### 8.1 场景 A · 正式镜像从定义进入装配主线

```text
Role / method / capability inputs ready

   ▼

   │
   ▼

   ▼
```

**开发者关注点**:
- image 是否只持有模板资产真相
- role/capability/policy refs 是否稳定
- bundle 是否在发布前齐备

### 8.2 场景 B · 已发布镜像进入派生和版本演进主线

```text
Published image exists
   │
   ▼
ImageDerivation created
   │
   ▼
child image bundle updated
   │
   ▼
lineage and catalog refreshed
```

**开发者关注点**:
- 派生链是否保留 lineage
- 子镜像是否只是覆盖差异而不污染父镜像
- 退役后 catalog 是否正确变化

### 8.3 场景 C · 镜像实例化为 member/runtime 启动材料包

```text
Instantiate request
   │
   ▼
image bundle resolved
   │
   ▼
InstantiateTicket created
   │
   ▼
member/runtime bootstrap consumes bundle
```

**开发者关注点**:
- instantiate 是否只消费 image truth
- memory/workspace seeds 是否仍保持 seed 语义
- member / runtime 是否没有反写 image 主真相

## 11. 异常与补偿设计

| 场景 | 处理 |
|---|---|
| role binding 缺失 | 拒绝 image publish |
| capability 引用越权 | 拒绝 toolset 装配 |
| starter refs 缺失或 digest 失配 | 阻断 seed bundle / instantiate |
| retired image 仍被请求实例化 | 拒绝实例化 |
| derivation lineage 断裂 | 阻断派生或发布 |
| instantiate backlog | 保留 ticket 并重试发 bundle |

### 11.1 重试 / 降级 / 熔断 / 补偿
- instantiate bundle 生成失败时可重试,但不得伪造默认 bundle
- catalog/summary 视图失败可重建投影,但不回滚 image truth
- capability/policy 引用短暂失联时可阻断发布或实例化,不允许静默降级成空能力集

### 11.2 按主要部分归属的失败模式

| 主要部分 | 典型失败 | 检测点 | 处理策略 | 补偿 / replay |
|---|---|---|---|---|
| 镜像定义与身份适配部分 | role binding 漂移 / image-instance 混层 | role binding boundary validate | 拒绝发布/实例化 | 修正 binding 后重试 |
| Persona 与交互种子装配部分 | prompt/style 与 live state 混层 | persona seed boundary validate | 拒绝保存或发布 | 重建 persona bundle |
| 工具、能力与策略覆盖装配部分 | capability 越权 / overlay 覆盖源规则 | capability refs / overlay validate | 拒绝装配 | 修正 refs/overlay 后重试 |
| 记忆与工作区初始化材料部分 | seed 缺失 / digest 失配 | seed boundary / integrity validate | 阻断 instantiate | 重建 seed bundle |
| 版本、派生与实例化出口部分 | retired image 实例化 / lineage 断裂 | instantiable state / lineage validate | 拒绝实例化或派生 | 重建 lineage / 重新发布 |

## 12. 实现红线 / 开发禁止事项

- 不允许 MemberImage 反向替代 Member 真相
- 不允许 role truth、capability contract、governance policy 被复制进 image 层冒充源真相
- 不允许 memory seed / workspace seed 冒充 live state
- 不允许 retired image 继续默认实例化
- 不允许派生链无 lineage 记录
- 不允许实例化时绕过 image truth 靠脚本临时拼 bundle

- identity / method / capability 输入至少装配出一份正式 MemberImage,并形成 persona/toolset/seed bundles

## 15. 结论

本详细设计的核心结论是：
- `L2-member-images` 的实现主轴必须按 image / persona / capability / seed / rollout 五个主要部分组织,而不是按 prompt/tool/memory/workspace 技术片段平铺
- member-images 真相层只持有镜像模板、装配结果、版本与实例化出口,不接管 member、identity、runtime、capability-hub 的活跃真相
- 所有 catalog、summary、instantiate、derive、retire 输出都必须建立在正式 MemberImage、bundle、lineage 与 ticket 证据链之上

后续测试与验收文档,应直接围绕这套镜像资产主链、种子边界、能力装配与实例化出口主线展开.

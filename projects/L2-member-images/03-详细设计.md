## 4. 实现单元与文件布局

> 校准来源：
> - `design-calibration/03_ddd_step_04_file_layout.md`
>
> 延伸阅读：
> - 请继续阅读该文件的“布局形态决策表”“实现单元总表”“目录 / Package / Crate / Binary 映射表”“Planned 文件布局树”“文件职责与禁止方向表”和“Planned 依赖方向”。

本仓采用 planned workspace 多 crate 架构。选择它是为了用 Cargo 方向约束 `contracts -> domain -> application`、infra port implementation 与三类逻辑 entry；它不表示七个服务、七个进程、已存在 binary 或部署拓扑。五 capability 是业务责任切片，不是 crate 边界。

| 候选布局 | 是否采用 | 判断依据 | 影响 |
|---|---|---|---|
| 单 crate 模块分层架构 | 否 | staged truth、inward port、projection / adapter 和多 logical entry 需要更强边界 | 不使用单一 `src/*` 顶层承载所有责任。 |
| workspace 多 crate 架构 | 是（planned） | 可强制职责型依赖，并隔离 contracts、domain、application、infra 与 entry | 未来 07 才能创建 seven members；当前不表示 manifest / binary 已激活。 |
| 每个 capability 一个 crate | 否 | capability 横跨 domain/application/infra/entry，拆分会引入循环与重复 carrier | capability 保留为模块内业务组织轴。 |

| 实现单元目录 | 类型 | Cargo package | Rust crate / binary | 职责 | 是否对外暴露 |
|---|---|---|---|---|---|
| `crates/contracts` | library | `member-images-contracts` | `member_images_contracts` | workspace 内 typed ref、metadata、protocol carrier、safe view/error | 仅 workspace-internal。 |
| `crates/domain` | library | `member-images-domain` | `member_images_domain` | local truth、state、guard、history | 否。 |
| `crates/application` | library | `member-images-application` | `member_images_application` | use case、port、UoW、idempotency | 否。 |
| `crates/infra` | library | `member-images-infra` | `member_images_infra` | port implementation、config、composition、fake | 否。 |
| `crates/api` | logical-entry library | `member-images-api` | `member_images_api` | logical command/query mapping | 否；transport pending。 |
| `crates/worker` | conditional-entry library | `member-images-worker` | `member_images_worker` | conditional inbound boundary | 否；worker process pending。 |
| `crates/jobs` | library + planned action binary candidates | `member-images-jobs` | `member_images_jobs`; bounded action names | bounded operations entry | action binary only planned，非 scheduler。 |

#### 模块调用图：L2-member-images 模块实现主轴

```text
 [api] ------ call ------> [application] ------ pure call ------> [domain]
 [worker] --- call ------> [coordinators / ports / UoW]             ^
 [jobs] ----- call ------>        |                                |
                                  | implements                     | typed carrier
                                  v                                |
                              [infra] -----------------------------+
                                  |
                                  | rebuild / read-only
                                  v
                    [existing derived views / freshness / gaps]

 [contracts] ---- typed carriers used by every permitted module
 external owner/product seams -- verified / safe / gap only --> application / infra
```

关键说明：

- `contracts` 是 workspace carrier，不自动成为任何 sibling 的 compile-time public contract。
- entry 模块只经 application facade；不得直写 domain/repository，api、worker、jobs 互不调用。
- infra 实现 application-owned ports；adapter ACK、cache、configuration 或 fake 不能改变 domain truth 或升级阶段状态。
- derived view 只从 committed local truth 重建；图不表示 HTTP、broker、scheduler、container 或部署拓扑。

#### 5.1.4 对象实现契约

`NonEmptyText`、`ImageLocalId`、`UtcTimestamp`、`LocalObjectVersion`、`IdempotencyKey`、`CorrelationRef`、`CausationRef`、`ActorOrSourceRef`、`SafeReason`、`OperationMetadata`、`LocalObjectKind`、local/external typed refs、public gap/ref/page/freshness carrier 与所有 protocol state enum 的定义、字段、constructor、variant Rustdoc和禁止事项，见 Step 6 §6.2~§6.8。其共同不变量如下：

- 外部值只可携带 owner、kind、opaque identity、可选 immutable revision 与 safe verification source；不得携带 body、secret、provider response、live state或未验证 JSON。
- `OperationMetadata` 的 idempotency/correlation 必须显式输入；query 不创建写 metadata 或 reservation；actor/source ref不等授权。
- `SafeDisposition::VerifiedUsable` 只对声明的窄用途有效，绝不直接成为 candidate、eligibility、availability、Artifact acceptance或 consumer readiness。
- `StaticSeedKind` 与 `StaticPlacementKind` 只允许 policy/memory/workspace/role-extra 的静态 template placement；绝不承载 live memory/checkpoint、mounted workspace或 runtime extras state。

#### 5.1.5 Trait / Port / Adapter 契约

contracts 不拥有 repository 或 external adapter trait；它为 Step 7 的 application-owned port 提供参数、返回、error 与 typed identity。详细索引见第 6 章和 Step 7 §15.1。

#### 5.2.4 对象实现契约

上述每个对象均已在 Step 6 §8~§12 给出独立类型定义、字段、成员函数、factory、状态与禁止事项。实现者必须按该来源逐对象实现，尤其遵守以下字段 / 构造闭环：

| 对象组 | 必填字段来源 | 缺失时行为 |
|---|---|---|
| baseline / revision | typed local family/variant ref、mapping snapshot、immutable component pin、static seed placement、base safe ref、safe reason | `Incomplete` / `Blocked` / `Conflict`；不得从 `latest`、tag、body或 live state补齐。 |
| intent / snapshot / attempt / outcome / candidate | persisted revision/baseline、local trigger ref、static snapshot、safe execution/output identity | `Pending` / `Blocked` / `Unknown`；ACK、tag、cache或猜测 digest不产生 candidate。 |
| provenance / gate / eligibility / Artifact record | candidate/snapshot local ref、safe source/gate/Artifact ref或 gap | missing authority/evidence保持 pending/blocked/gap；不 default-pass。 |
| transition / entry / consumer gap | local eligible/pin/history refs、immutable image identity、formal consumer slot | `Unavailable` / `Open` / `Stale`；local entry不构成 consumer confirmation。 |
| snapshot / gap / freshness / view | named external safe ref、committed local truth watermark、typed subject | stale/conflict/unavailable/gap显式返回；不由 projection/cache/fake反推 truth。 |

#### 5.2.5 Trait / Port / Adapter 契约

domain 不定义 infrastructure port。它只接受已验证的 typed local ref、safe conclusion、operation metadata或纯 guard input；所有 repository、resolver、builder、qualification、consumer与 projection 访问均由 application-owned port 承接，见 Step 7 §7~§12。

#### 调用图：共享 write-flow stop

```text

  | call validate_request(ImageCommandRequest<T> / ImageOperationsJobRequest<T>)

  | call validate_context(...)
```

- 该图是当前 write-class flow 的 fail-closed 规则，不是 future mutation伪代码。
- B01/B02不能被 metadata、fake、configuration、scheduler、Query或 marker绕过。
- future/reopen write sequence必须先补齐 canonical input、UoW、result/replay与per-flow状态/持久化契约。

| `ConsumeVerifiedBuildRequestFlow`、`ConsumeVerifiedSourceRefreshFlow` | 2 inbound | worker boundary | none | marker only | `accepted_input=false` / no intent。 |
| six `*JobFlow` | 6 Job | `run_*_job` | current none；future local ReadWrite only | current zero | bounded scope/B01/B02/no report。 |

future/reopen的通用写顺序只能在所有关联 blocker关闭后使用：`canonicalize -> begin ReadWrite UoW -> reserve -> exact versioned reads -> domain transition -> local truth/trace/existing freshness write -> stored result -> complete -> commit`。duplicate必须 rollback当前UoW并只读取既有 stored shell/body；不得重跑 domain、adapter、page scan或projection rebuild。该序列目前不可被实际调用。

#### 状态依赖图：阶段性 guard 关系

```text

  + [BaselineCompleteness::Complete]
  + [VariantRevisionLifecycle::Buildable]
```

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - `design-calibration/03_ddd_step_11_persistence_consistency.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`

> 延伸阅读：
> - 请继续阅读 Step 11 的“数据所有权实现表”“Logical store / collection / projection 契约表”“Repository、UoW 与 adapter的持久化语义”“事务边界与函数级处理顺序”及 blocker ledger。physical DB/DDL/migration不在本文定义。

本仓采用 logical store 契约，不选择数据库、collection、KV namespace、cache或 migration。durable adapter与fake可有不同物理形态，但必须保持 typed identity、business uniqueness、stable sort、same-object version、transaction与body-free约束。external owner body和live state永不成为本仓 persisted truth。

| 数据对象 | 拥有模块 | future/reopen 写入方 | 读取方 | 一致性要求 |
|---|---|---|---|---|
| family / variant / baseline / revision / mapping snapshot | DefinitionAssembly | DefinitionAssemblyCoordinator | definition/revision/query/projection | local mutable/immutable分离；existing save使用同对象version；mapping只存snapshot ref。 |
| intent / snapshot / attempt / outcome / candidate | BuildCandidate | BuildIntentCoordinator | reconciliation/qualification/query | attempt/outcome/candidate独立；candidate relation不可多义。 |
| provenance / gate / eligibility / Artifact record | Qualification | QualificationCoordinator | supply/query/projection | external evidence/gate body不入库；empty gate不等Passed。 |
| transition / entry / consumer gap | SupplyEntry | AvailabilityCoordinator | history/resolve/catalog/query | transition append-only；entry/gap versioned；local Available不等consumer truth。 |
| external snapshot / contract gap / trace / read model / freshness | ReferenceDerived | reference/projection coordinator | guard/query/rebuild/reconcile | snapshot declared-use；trace append-only；projection仅committed truth source。 |
| idempotency / stored result | application | future Command/Job facade | duplicate replay only | reserve/result/complete同UoW；B01/B02前零写。 |
| runtime/tools/member/supervisor/extras/policy/memory/workspace body | external owner | 不可写入 | only typed ref/safe conclusion/gap | 不成为local persisted body/default input。 |
| Artifact、consumer/container、governance、observability truth | respective owner | 不可写入 | typed ref/local gap only | 不mint、不confirm、不由local state替代。 |

| logical store 类别 | 保存 / 读取规则 | version / history 规则 |
|---|---|---|
| DefinitionAssembly store | exact family/variant/baseline/revision/snapshot read、typed relation lookup、stable list | new=Absent；existing=its `Versioned<T>.version`；baseline input immutable、revision relation versioned。 |
| BuildCandidate store | intent/snapshot/attempt/outcome/candidate exact and scoped read | snapshot immutable；unknown不自动retry；candidate unique relation fail-closed。 |
| Qualification / Supply store | evaluation/decision/handoff/entry/gap exact and scoped read | Artifact/consumer positive terminal state不得在owner contract缺失时保存；transition append-only。 |
| Reference / projection store | snapshot/gap/trace、existing view/freshness、committed truth snapshot | direct truth/history与projection分离；page cursor不是version/watermark。 |
| idempotency / result store | reservation、stored shell/body、exact replay lookup | current B01/B02不得写；future duplicate仅读stored result。 |

所有已存在 mutable object更新必须从同一对象 `Versioned<T>.version` 取得 `ExpectedLocalObjectVersion::Exact`；新对象只可使用 `Absent`。cursor、timestamp、external revision、tag、digest、watermark、idempotency key和trace id都不是 optimistic version。`ImageTraceRecord`与`AvailabilityTransition` append-only；baseline/build snapshot input不可变；修复产生new context或supersede，不能overwrite历史。

| 场景 | 开始位置 | 提交位置 | 回滚条件 | 同事务内必须完成 |
|---|---|---|---|---|
| current Command / Job | 不开始 | 无 | B01/B02前停止 | 无 UoW、reservation、read/write、adapter、trace、gap、freshness、result或commit。 |
| future/reopen Command / Job | canonical input后 `ReadWrite UoW` | complete reservation与stored result后commit | version/guard/store/result/complete失败 | canonicalize、reserve、exact versioned reads、domain transition、local truth/trace/existing freshness、stored result、complete。 |
| Query | ReadOnly read | 无 write | missing/visibility/preference/store failure映射safe surface | 不reserve、不trace、不gap、不refresh/rebuild。 |
| conditional inbound | marker inspection only | 无 write | authority/schema不可用 | `accepted_input=false`；无 envelope/receipt/dedup/intent。 |
| projection rebuild | future bounded job only | future existing view/marker保存若路径闭合 | source/view/version failure | only from `CommittedImageTruthSnapshotPort`; never core truth repair。 |

外部 adapter call不构成local commit evidence。本仓没有outbox、publisher、delivery或outbound persistence。`DDD-S9-B01`、`DDD-S9-B02`、`DDD-S11-B03`、`PF-UNAVAILABLE-RECOVERY`、`MI-UP-*`与`Q-MI-*`均保持显式 blocker。

| `Unavailable` / external safe conclusion | port / infra | owner/adapter/store/projection不可验证 | 不盲重试；保持safe state | `Unavailable` / gap / unknown。 |
| marker/action boundary error | worker / jobs | inbound authority未闭合、job boundary不可用 | no write，等待reopen | marker disposition / safe protocol error。 |

| 场景 | 检测位置 | 处理方式 | 是否写审计 / 事件 |
|---|---|---|---|
| Command/Job invalid shape或B01/B02 | entry/application | safe reject/blocked，零UoW/zero effect | 只可安全runtime diagnostic；不写trace/history/gap/freshness/result。 |
| Query missing/partial/stale/rebuilding/unavailable | query mapper | 用正式 surface呈现；不修复truth/view/marker | 可log/metric；不写local trace。 |
| conditional inbound未验证 | worker boundary | `Unavailable` / `Rejected` / `ReopenRequired`，`accepted_input=false` | marker diagnostic；无receipt/dedup/write。 |
| version/conflict | future application UoW | rollback；reload同一对象后才可重新guard | future safe diagnostic；不last-write-wins。 |
| stored replay缺失/commit unknown | future replay/UoW | `ReplayUnavailable`或`Unknown`/manual consistency | 不从truth/adapter/cache补旧result。 |
| external builder/gate/Artifact/consumer未知 | adapter/coordinator | safe `Unknown`/`Blocked`/`Gap` | 不假设retry、positive conclusion或owner success。 |
| projection unavailable | query/job boundary | 保持unavailable/stale；不query-time repair | `Unavailable -> Fresh/Rebuilding`被PF blocker禁止。 |

|---|---|---|
| 可重新验证 | 使用same typed ref/operation identity，重新读取explicit local/owner-safe source | 以new key、latest、cache或body替代原identity。 |

本章只定义 future/reopen 写路径在关联 blocker 闭合后必须遵守的保护模型；它不授权当前 Command 或 Job 开启 UoW、reservation、repository、adapter、trace 或 commit。保护模型由三项不可互换的规则组成：reservation/replay identity、same-object optimistic version，以及 append-only history / committed-truth projection direction。

| 场景 | 冲突资源 | future/reopen 控制方式 | 当前行为 | 失败语义 | 计划测试切口 |
|---|---|---|---|---|---|
| 同 family / variant / baseline / revision 的定义写入 | family name、family-variant relation、variant、immutable baseline input、prior revision | existing object 取自身 `Versioned<T>.version`；new object 仅 `Absent`；relation / unique 在同一 UoW 验证 | B01 前停止，无读取或写入 | `VersionConflict` / `Conflict` / `ContractViolation` | `TC-MI-S13-CONC-DEF-*`。 |
| build intent / outcome / reconciliation 相互重叠 | revision、intent、attempt、outcome、candidate relation | exact version read；candidate relation 必须无歧义；unknown 不能被另一 writer 盲重试 | B01/B02 前停止 | `VersionConflict` / `Conflict` / `Unknown` | `TC-MI-S13-CONC-BUILD-*`。 |
| evaluate 与 reevaluate qualification | candidate、provenance、gate、eligibility context | 每个改变的 local context exact-load / version；缺 authority/evidence 不得转 `Passed` / `Eligible` | B01/B02 前停止 | `VersionConflict` / `Blocked` / `Unavailable` | `TC-MI-S13-CONC-QUAL-*`。 |
| entry / transition / rollback / retire 并发 | entry、current-facts relation、append-only transition | existing entry exact version；new transition `Absent`；不得覆盖 history | B01/B02 与 `DDD-S11-B03` 前停止 | `VersionConflict` / `Conflict` / `InvalidTransition` | `TC-MI-S13-CONC-SUPPLY-*`。 |
| projection rebuild 与 local truth / dual rebuild 并发 | committed truth snapshot、existing view、freshness marker | 只能从 committed local truth 读取；older/stale writer 不得覆盖 marker/view | `PF-UNAVAILABLE-RECOVERY` 前不做 recovery write | `Unavailable` / `VersionConflict` / `TransactionBoundary` | `TC-MI-S13-CONC-PROJ-*`。 |
| same-key first / second writer、crash re-entry | reservation、stored result、same operation identity | 必须先按 reservation lookup 取得确定结果；second writer 不得调用 domain/adapter | `DDD-S13-OPEN-01` 前不得 reservation | safe blocked / reopen，而非临时 in-flight response | `TC-MI-S13-INFLIGHT-001`。 |

| 接口 / Job / Event | 幂等键或 identity | 幂等窗口 | 重复请求处理 |
|---|---|---|---|
| 每个 10 Command | `ImageWriteMetadata.idempotency_key` 与 channel、operation name；future 还需同一 `StableOperationInputRef` | 仅由 future durable reservation/result contract 定义；当前不存在窗口 | 当前 B01/B02 前 zero-effect stop；future 仅同 identity 才可读既有 stored shell/body。 |
| 每个 6 Operations Job | Job request 的 write metadata、job operation name 与 opaque stable input | 仅限同一 bounded logical Job；不从 scheduler run、cursor、page 或 report 派生 | 当前 B01/B02 前 zero-effect stop；future duplicate 不得重扫 page、重跑 domain 或 adapter。 |
| 10 Query | 无 reservation | 不适用 | repeated read 仍 strict no-write；不创建 key、trace、gap、freshness 或 rebuild。 |
| 2 conditional inbound | 无 event identity / dedup / receipt | 不适用 | 每次只返回 `accepted_input=false` marker disposition；不升级为 event replay。 |
| outbound | `ImageOutboundEventInventory::NoneAuthorized` | 不适用 | 不存在 outbound key、outbox、delivery 或 receipt surface。 |

`StableOperationInputRef` 是 body-free opaque identity，不是 image / Artifact digest、payload hash、tag、timestamp、external revision、route、clock、live state 或 provider result。existing mutable object 只能使用该对象的 `ExpectedLocalObjectVersion::Exact`；不得用 cursor、watermark、idempotency key、trace ID、tag 或 digest 替代 optimistic version。business unique conflict 不是 upsert 或 last-write-wins 的授权。

| 重入来源 | 保护方式 | 恢复方式 | 当前限制 |
|---|---|---|---|
| 已完成的同一 future operation | `reserve -> Duplicate { result_ref } -> rollback -> get_stored_result -> get_replay_body` | 只返回原 stored shell/body/effects；不重算 current truth | `DDD-S9-B02` 未闭合，当前不可形成 replay。 |
| same key、different stable input | 以 deterministic `IdempotencyConflict` 拒绝 | 保留旧 record / body；零 mutation | canonical carrier / mapper 未闭合。 |
| stored shell/body 缺失或 kind/name 不匹配 | 返回 `ReplayUnavailable` | 不从 cache、adapter 或 current truth 补建 response | 不生成新 result ref 或补偿写。 |
| commit / rollback unknown | 以同一 operation/key/stable input 审计 reservation/result | 无法证明时维持 `Unknown` / manual consistency | 不换 key、不补偿、不重发 external effect。 |

| cross channel/name raw-key reuse | 需要统一 namespace、lookup 与 conflict policy | 仅在重开设计后定义 | `DDD-S13-OPEN-02`；不得假定 raw key 全局唯一或 cross replay。 |

trace 与 `AvailabilityTransition` 始终 append-only；projection 只能从 committed local truth rebuild。Query、marker-only inbound、config/composition、current B01/B02 Command/Job 都不得以“并发保护”为由写入 trace、history、gap、freshness、reservation 或 result。任何需要在上述未闭合项上自行选择 lock、isolation、lease、TTL、retry、outbox 或 cleanup 的实现必须停下并重开对应 Step。

|---|---|---|---|

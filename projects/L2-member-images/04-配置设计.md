## 2. 本次配置设计目标与范围

> 校准来源：
> - `design-calibration/04_config_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“P0 / P1 / P2 范围表”“配置设计目标与下游结果”“范围与非范围去向”“配置范围图”和“非范围残余风险”小节，了解范围分层与取舍。

本项目不是“无配置项目”。本轮 P0 的目标是让成员镜像静态装配在不泄漏敏感材料、不偷渡外部成功、也不改变详细设计代码契约的前提下，形成唯一、严格、可解释的 startup configuration control plane。

| 级别 | 范围 | 本轮状态 |
|---|---|---|
| P0 | profile/mode、local store binding、静态 mapping/component/seed/base reference、保守 build/Artifact/Member Service boundary selector、TestOnly fake 隔离、redaction、严格加载、startup freeze、fail-closed。 | 本文完整定义。 |
| P1 | owner 批准后的 real-like / staging-like binding、secret-provider 接线、真实 build/registry/qualification/consumer adapter、受控运维分发。 | 仅记录 future direction 与 reopen 条件。 |
| P2 | production-like 产品化、多环境运维、remote config、在线控制、continuous drift、复杂发布/回滚与高级安全设施。 | 非范围；不得以 disabled key 预先伪装为支持。 |

P0 的唯一正向结论是：给定已验证的本地配置输入，builder 可以判断 local composition 是否 `Assembled` 或 `Blocked`。`Assembled` 只表示 mandatory local composition validation 已通过；它不表示 image build、image digest、registry presence、qualification、Artifact、Member Service consumer、runtime loop、container、发布或 overall readiness。

| 本轮非范围 | 应由谁/哪份文档回答 |
|---|---|
| RoleDefinition、Role-to-variant mapping 正文、member 主体真相 | `L3-method-library` 和相应 owner；本仓仅消费 body-free ref。 |
| runtime loop、tool execution、capability registry、MCP/A2A/API adapter truth | Runtime、Tools 和相应 adapter owner。 |
| live memory、checkpoint、workspace、容器和 sandbox backend/policy | Member/Service/Sandbox owner；本文件仅允许 static seed/base ref。 |
| build result、digest、provenance、gate、Artifact、release/rollback result | Builder/Registry、Artifact、qualification/security owner。 |
| consumer manifest、confirmation、instance launch/health | `L2-member-service` owner。 |
| 完整测试、验收、实施、部署和运维动作 | 后续 `05/06/07/09` 按各自 SOP 承接。 |

## 3. 配置控制面总览

> 校准来源：

>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置来源链图”“配置控制面总表”“配置域 / 功能模块总表”“模块读取与注入责任矩阵”和“跨控制面审计表”小节，了解配置读取与注入边界。

#### 配置加载链图：L2-member-images P0 startup composition

```text
safe absence + project JSON + allowlisted environment selector
                    |
                    v
       infra/config.rs: strict parse / schema / redaction
                    |
                    v
      typed, body-free validated configuration binding
                    |
                    v
    infra/runtime_builder.rs: cross-field validation / slot wiring
                    |
                    v
ImageRuntimeAssemblyState::{Unassembled, Assembled, Blocked}
                    |
                    v
existing typed facade / conservative availability marker only
```

关键说明：

- `infra/config.rs` 是唯一可读取 raw configuration 的 planned private module；它不把 raw value、secret、endpoint 或 provider body 传出。
- `infra/runtime_builder.rs` 不是第二个 parser。它只消费已经校验的 binding，执行跨域约束并向既有 local/static/external slot 注入实现或保守 marker。
- `contracts`、`domain`、`application`、`api`、`worker`、`jobs` 不读取 raw config；它们只接收 typed carrier、assembled facade 或安全 disposition。
- 图不表达外部调用、镜像构建、Artifact handoff、consumer confirmation、runtime/container 启动或部署完成。

| 配置域 | 作用 | P0 配置数 | 本地消费位置 | 不可越过的边界 |
|---|---|---:|---|---|
| `composition` | 显式选择 profile、mode 和 body-free configuration authority。 | 3 | `infra/config.rs`、`infra/runtime_builder.rs` | 不从 profile 推断 fake，不将 config ref 当作正文或 readiness。 |
| `local_persistence` | 选择 private truth/projection/idempotency implementation binding。 | 3 | local store adapters、`runtime_builder.rs` | 不选 DB 产品、DSN、schema、UoW、lease、TTL、retry 或 recovery。 |
| `static_references` | 选择 mapping、component、seed 和 base 的 immutable/boundary ref。 | 11 | source adapters、`runtime_builder.rs` | 不携带 Role/mapping/component/template body 或任何 live state。 |
| `external_boundaries` | 选择 build/registry、qualification/Artifact、Member Service supply 的保守 adapter seam。 | 3 | external adapters、`runtime_builder.rs` | 不调用 provider，不产生 candidate/digest/gate/Artifact/consumer result。 |
| `diagnostics` | 保持或加强固定 redaction floor。 | 1 | config/builder 的安全诊断边界 | 不配置 backend、alert、sampling、retention、debug raw output。 |

P0 不存在 config center、admin override、公开 CLI flag、run-local 覆盖、raw secret reader、online source、hot reload 或 output-oriented configuration。任何这样的新增项均属于设计变更，而不是本配置文件的可选值。

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_categories_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置分类表”“按配置域组织的分类边界表”“禁止配置化项表”“禁止项与既有详细设计不变量映射”和“跨分类 / 禁止项审计表”小节，了解可配置性与禁止项。

所有 21 个 P0 key 都是 startup-only configuration：有效配置在 builder assembly 前校验并冻结。P0 不支持 reload、hot update、online override、partial apply 或 last-known-good (LKG) 语义。轮换或回退只能提供新的 body-free selector，经完整重新校验后重启。

| 类别 | 允许的内容 | 生效边界 | 明确禁止 |
|---|---|---|---|
| composition identity / mode | profile、显式 Production/TestOnly mode、opaque config ref。 | startup composition。 | 从环境名推断 mode、隐式 fake、动态切换。 |
| private local binding | opaque local truth/projection/idempotency implementation ref。 | startup composition。 | physical backend、DSN、schema、UoW/version、lease/TTL/retry/recovery policy。 |
| static reference binding | immutable mapping/component/seed/base selector 或受控集合。 | startup composition。 | `latest`/mutable selector、RoleDefinition、mapping/template/component body、live state。 |
| conservative external boundary | typed external seam selector。 | startup composition。 | endpoint、credential、provider request/response、result body、online probe/retry。 |
| diagnostics/redaction | fixed floor 或更严格 opaque policy selector。 | startup composition。 | raw output、debug bypass、observability backend、alert routing。 |
| TestOnly fixture | explicit `ci-test` harness 的 opaque deterministic ref。 | test startup only。 | 进入 Production 或成为 Production fallback。 |

以下是设计不变量，不能被任何 P0 配置项覆盖：

- RoleDefinition、Role-to-image-variant mapping、member truth、image identity/history、required immutable pin 和 no-`latest` 规则。
- Runtime/Tools/Member/Supervisor/role-extra 正文，policy/memory/workspace/role-extra template 正文，以及 live memory/checkpoint/workspace。
- state machine、append-only history、UoW、version、idempotency identity、replay、recovery、query no-write 和 projection no-repair。
- sandbox policy/backend、容器生命周期、external MCP/A2A/API adapter truth、capability registry、governance approval truth、observability backend 与 marketplace/product entry。
- inbound event activation、outbound publisher、event schema/topic、build/digest/provenance/gate/Artifact/consumer confirmation 和任何 readiness。

`null` 只表示 safe absence。它不是“关闭 required slot”、不是 successful default，也不会自动产生 `Bound`、`Available`、`Assembled`、candidate、gate、Artifact 或 consumer result。

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“P0 配置来源链”“配置来源优先级表”“冲突处理表”“按配置域组织的来源覆盖表”和“跨来源冲突审计表”小节，了解来源准入与冲突语义。

普通来源优先级是唯一且固定的：

```text
safe absence < project JSON < allowlisted environment selector
```

| 来源 | 准入范围 | 覆盖规则 | 不可用或非法时的处理 |
|---|---|---|---|
| safe absence | `null` 与代码固定的最小安全语义。 | 最低；只表示没有提供值。 | required/scope-required 项保持 `Blocked`/`Gap`，不会生成成功默认。 |
| project JSON | 严格 JSON 的项目本地五域 schema。 | 覆盖 safe absence。 | 缺失、不可读、语法/shape/duplicate/unknown 错误均拒绝有效配置。 |
| allowlisted environment selector | 仅允许覆盖已定义的 profile/ref selector；值仍必须是合法 opaque selector 或允许的 enum。 | 覆盖同 key 的 JSON。 | 值存在但为空、非法、敏感材料、unknown 或不兼容时，拒绝整份 effective configuration；不得回退 JSON 或 safe absence。 |
| explicit TestOnly fixture | 仅 `ci-test` 的 explicit harness；只提供允许的 opaque deterministic ref。 | 不属于 Production 普通来源。 | fixture 缺失或非法时测试 lane fail-fast；绝不回退为 Production 或真实成功。 |

P0 拒绝 JSONC、注释、trailing comma、重复 key、alias key、未知字段、错误层级与未授权 source。JSON schema 不接受任意 map、provider body、raw secret、URL、DSN、credential、manifest、Artifact/consumer body 或 live-state body。

| 冲突或违规 | 正式处理 | 禁止处理 |
|---|---|---|
| 同 key 在 JSON 与合法 allowlisted env 中同时出现 | env selector 覆盖 JSON，再走完整校验。 | 按值猜测来源或合并两个 ref。 |
| 高优先级 env 值非法 | reject whole effective configuration。 | 静默忽略 env、回退 JSON、回退 `null`、保留旧值。 |
| JSON 内重复/未知/alias key 或错误层级 | strict parse/schema reject。 | 忽略、自动拼写修正或 partial apply。 |
| raw secret/body/endpoint/credential 出现在任意来源 | sensitive boundary reject。 | 转成 selector、写日志或继续组装。 |
| TestOnly fake/fixture 与 Production 或非 `ci-test` 组合 | profile/mode cross-field reject，assembly `Blocked`。 | 自动切换 profile、把 fake 视为受控真实 adapter。 |
| remote config、admin override、reload 或 LKG 请求 | `UnsupportedSource` / `UnsupportedReload` 的安全拒绝。 | 在线覆盖、缓存回退或隐式持久化。 |

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：

>
> 延伸阅读：

`local-dev` 与 `ci-test` 是当前 P0 profile。`integration-like` 是受控接缝验证 profile，不改变 P0 的 owner/pending 边界。`staging-like` 与 `production-like` 仅是 P1/P2 future direction，不能被写作本轮 must-pass 或 production-ready 事实。本项目没有 replay 或 live-state profile。

| Profile | 用途与状态 | 来源 | 外部依赖口径 | 敏感与 fake 边界 |
|---|---|---|---|---|
| `local-dev` | P0 本地检查 configuration shape 和 local composition。 | safe absence、可选 project JSON、allowlisted selector。 | local store 可被选择；owner 未闭合 static/external slot 仅 `Blocked`/`Unknown`/`Gap`。 | 无 raw secret；TestOnly fake 不属于该 profile。 |
| `ci-test` | P0 deterministic config/contract/redaction/negative seam 测试。 | test JSON、CI-safe selector、explicit TestOnly fixture。 | isolated local binding、deterministic fake/fixture 仅用于协议与失败映射。 | 唯一可使用 `test_only` fake 的 lane；结果不证明真实成功。 |
| `integration-like` | 受控 adapter seam、unavailable/unknown/gap 和 no-fake-fallback 验证。 | project JSON、allowlisted selector。 | controlled/real-like seam 可存在；不得新增 sibling Cargo dependency。 | 只使用 opaque reference；不接受 raw credential/body，不产生正向外部结果。 |
| `staging-like` | P1 dry-run/pre-production 方向。 | 经部署批准的 JSON/selector，具体分发留 09。 | 只有 owner 合同闭合后才可接真实 adapter。 | 禁止 fixture/fake；当前所有受影响正向 lane 仍 pending。 |
| `production-like` | P1/P2 生产语境方向。 | 经运维批准的 JSON/selector。 | 仅在 owner、policy、产品与运维闭合后才可使用 approved adapter。 | 必须显式 `production` mode；禁止 fake、fixture、replay、debug/raw bypass。 |

| Profile | Local store | Static refs | External boundary | 05/06 的计划性承接 |
|---|---|---|---|---|
| `local-dev` | local implementation；缺失则 `Blocked`。 | 不可验证时 `Unknown`/`Gap`。 | conservative marker 或不装配。 | 仅开发辅助的 strict parse/local assembly 检查。 |
| `ci-test` | isolated deterministic implementation。 | explicit TestOnly fixture。 | fake 不能返回 `Passed`、`Accepted`、digest 或 confirmation。 | 配置安全、隔离和 no-side-effect 测试切口。 |
| `integration-like` | local/controlled test implementation。 | controlled resolver 或 owner gap。 | controlled seam；无 consumer confirmation。 | unavailable/gap/marker 和 no-fake-fallback 切口。 |
| `staging-like` | future approved binding。 | future approved pin。 | future approved seam。 | 仅 owner 闭合后的 P1 direction。 |
| `production-like` | future approved binding。 | future approved pin。 | future approved seam。 | 仅 P1/P2 direction；当前无验证或放行事实。 |

profile 不会改变 static/live、pin、state、UoW、owner、依赖类别、inbound marker-only 或 outbound `NoneAuthorized` 的不变量。尤其不能由 profile 激活 event consumer、publisher、scheduler、runtime loop 或 container。

### 7.3 `static_references`（11 项）

该域只承接 static, body-free, immutable selector。`mapping_ref` 指向 Method Library 的 mapping source identity；component ref 只表示 release identity；seed ref 只表示 static template identity；`base_ref` 只表示 base-image boundary identity。它们永远不携带 body、mount、path、live memory/checkpoint/workspace 或 runtime extras。

| 配置项 | 类型 | 默认值 | 是否必填 | 来源 | 作用域 / 生效 | 敏感级别 | 失败策略 | 关联模块 |
|---|---|---|---|---|---|---|---|---|
| `static_references.mapping_ref` | opaque reference selector | `null` | scope 需要 definition/mapping 输入时 | JSON；allowlisted env；TestOnly fixture。 | startup；验证 `MethodLibrary` / `RoleVariantMapping` 后交 resolver。 | sensitive | missing/wrong owner-kind/mutable/unknown -> `Blocked`/`Unknown`；不生成 mapping snapshot。 | `source_adapters.rs`；`runtime_builder.rs`。 |
| `static_references.runtime_component_ref` | opaque reference selector | `null` | 是（Runtime slot） | JSON；allowlisted env；TestOnly fixture。 | startup；验证 Runtime `ComponentRelease`，注入 Runtime slot。 | sensitive | invalid/mutable/unverifiable -> required slot `Blocked`；拒绝 `latest`。 | `source_adapters.rs`；`runtime_builder.rs`。 |
| `static_references.tools_component_ref` | opaque reference selector | `null` | 是（Tools slot） | JSON；allowlisted env；TestOnly fixture。 | startup；验证 Tools `ComponentRelease`，注入 Tools slot。 | sensitive | invalid/mutable/unverifiable -> required slot `Blocked`；不打开 tool execution。 | `source_adapters.rs`；`runtime_builder.rs`。 |
| `static_references.member_component_ref` | opaque reference selector | `null` | scope 需要 Member slot 时 | JSON；allowlisted env；TestOnly fixture。 | startup；验证 Member `ComponentRelease`，注入 Member slot。 | sensitive | `MI-UP-002` 未闭合或 ref 不可验证 -> `Blocked`/`Gap`。 | `source_adapters.rs`；`runtime_builder.rs`。 |

| `static_references.memory_seed_ref` | opaque reference selector | `null` | memory seed 在 scope 时 | JSON；allowlisted env；TestOnly fixture。 | startup；绑定 static `MemoryTemplate` / `MemoryLayer`。 | sensitive | missing/unknown -> `Blocked`/`Gap`；不承接 live memory/checkpoint。 | `source_adapters.rs`；`runtime_builder.rs`。 |
| `static_references.workspace_seed_ref` | opaque reference selector | `null` | workspace seed 在 scope 时 | JSON；allowlisted env；TestOnly fixture。 | startup；绑定 static `WorkspaceTemplate` / `WorkspaceSeedLayer`。 | sensitive | missing/unknown -> `Blocked`/`Gap`；不挂载 path/volume/live workspace。 | `source_adapters.rs`；`runtime_builder.rs`。 |
| `static_references.role_extra_seed_refs` | ordered opaque selector collection | `null` | role-extra seed 在 scope 时 | JSON；allowlisted env；TestOnly fixture。 | startup；canonical identity 排序去重后绑定 RoleExtra template/layer。 | sensitive | duplicate/wrong kind/owner pending/数量不符 -> `Blocked`/`Gap`。 | `source_adapters.rs`；`runtime_builder.rs`。 |
| `static_references.base_ref` | opaque reference selector | `null` | 是（需要 base input 时） | JSON；allowlisted env；TestOnly fixture。 | startup；作为 baseline/build input 的 body-free BaseImage binding。 | sensitive | `MI-UP-008` 未闭合、missing/mutable/unknown -> `Blocked`/`Gap`。 | `source_adapters.rs`；`runtime_builder.rs`。 |

`role_extra_component_refs` 与 `role_extra_seed_refs` 是受控集合，不是任意 map。角色名、RoleDefinition、mapping 正文、manifest、template 正文与 runtime injection parameters 都不进入 schema；集合排序、去重、scope/cardinality、owner/kind 检查由 builder 的跨字段校验负责。

### 7.4 `external_boundaries`（3 项）

这三个 selector 只让 builder 选择已批准的 conservative adapter seam，不能直连对端、读取 provider body 或把 availability marker 解释为业务结果。

| 配置项 | 类型 | 默认值 | 是否必填 | 来源 | 作用域 / 生效 | 敏感级别 | 失败策略 | 关联模块 |
|---|---|---|---|---|---|---|---|---|
| `external_boundaries.build_registry_ref` | opaque typed boundary selector | `null` | profile/scope 声明 build/registry seam 时 | JSON；allowlisted env；TestOnly deterministic fixture。 | startup；验证 Builder/Registry owner + boundary kind，注入 `BuildAndRegistry` slot。 | sensitive | missing/unknown/owner-kind mismatch/pending -> `Blocked`/`Unknown`；不形成 candidate/digest/release。 | `build_adapters.rs`；`runtime_builder.rs`。 |
| `external_boundaries.qualification_artifact_ref` | opaque typed boundary selector | `null` | profile/scope 声明 qualification/Artifact seam 时 | JSON；allowlisted env；TestOnly deterministic fixture。 | startup；验证 Governance/Artifact boundary ref，注入 `QualificationAndArtifact` slot。 | sensitive | `Q-MI-004`/`MI-UP-007` pending 或 invalid -> `Blocked`/`Gap`；不返回 gate pass/Artifact acceptance。 | `qualification_adapters.rs`；`runtime_builder.rs`。 |
| `external_boundaries.member_service_supply_ref` | opaque typed boundary selector | `null` | profile/scope 声明 consumer seam 时 | JSON；allowlisted env；TestOnly deterministic fixture。 | startup；验证 `MemberService` consumer-contract selector，注入 `MemberServiceSupply` slot。 | sensitive | `MI-UP-001` pending 或 invalid -> `ConsumerHandoffGap`/`Unavailable`/`ReopenRequired`；不返回 manifest/confirmation/launch/health。 | `supply_adapters.rs`；`runtime_builder.rs`。 |

允许的 boundary kind 仅是既有 opaque vocabulary 中的窄用途 selector：Builder/Registry 可为 `BuildHandoff`、`BuildExecution` 或 `ImmutableImage`；qualification 可为 `GateAuthority`、`ApplicableGateSet`、`EvidenceConclusion` 或 `ArtifactConsumable`；Member Service 可为 `ConsumerContract`。格式合法也只代表待校验 identity，绝不代表已获得 candidate、digest、Artifact、gate 或 consumer confirmation。

### 7.5 `diagnostics`（1 项）

| 配置项 | 类型 | 默认值 | 是否必填 | 来源 | 作用域 / 生效 | 敏感级别 | 失败策略 | 关联模块 |
|---|---|---|---|---|---|---|---|---|
| `diagnostics.redaction_policy_ref` | opaque restrictive policy selector | `null`（fixed redaction floor） | 否；提供时必须可验证 | JSON；只能提供更严格的 project selector，禁止 env 降级。 | startup；`config.rs` 校验 floor 后传给安全诊断边界。 | sensitive | absent 使用 fixed floor；invalid/unknown/weaker -> reject，且不输出 raw value。 | `config.rs`；`runtime_builder.rs`；observability boundary。 |

该 key 不承载 raw config、secret、credential、endpoint、provider error、stack trace、Role/mapping/component/seed body、manifest、digest、gate/evidence、Artifact 或 consumer body；它也不能开启 `debug`、`log_level`、`raw_output` 等旁路。

下列示例仅展示完整 schema 形状。它不描述真实配置、资源、凭据、external response 或部署文件；所有 `opaque-ref:*` 均为文档符号。

```json
{
  "composition": {
    "profile": "ci-test",
    "mode": "test_only",
    "config_ref": "opaque-ref:ci-composition"
  },
  "local_persistence": {

    "projection_store_ref": "opaque-ref:ci-projection-store",

  },
  "static_references": {
    "mapping_ref": "opaque-ref:method-library-role-variant-map",
    "runtime_component_ref": "opaque-ref:runtime-release",
    "tools_component_ref": "opaque-ref:tools-release",
    "member_component_ref": "opaque-ref:member-release-pending",
    "supervisor_component_ref": "opaque-ref:supervisor-release-pending",
    "role_extra_component_refs": [
      "opaque-ref:role-extra-release-a"
    ],
    "policy_seed_ref": "opaque-ref:policy-template",
    "memory_seed_ref": "opaque-ref:memory-template",
    "workspace_seed_ref": "opaque-ref:workspace-template",
    "role_extra_seed_refs": [
      "opaque-ref:role-extra-template-a"
    ],

  },

    "build_registry_ref": "opaque-ref:builder-registry-seam",
```

6. diagnostics selector 只能保持或加强 fixed redaction floor。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“敏感配置识别与分层”“敏感配置逐项表”“Profile 敏感配置处理表”“读取、轮换与审计承接表”“禁止输出规则”和“跨敏感配置泄露风险审计表”小节，了解 selector、secret 和输出面的隔离。

本项目 P0 配置只保存 opaque selector，不保存 raw secret、credential、DSN、endpoint、provider body、manifest、Artifact body、consumer body 或 live state。`sensitive` 表示 selector 可能暴露部署或运营边界，因此不能进入日志和普通诊断；它不表示本仓拥有 secret provider 或能解析 selector。

### 8.1 存储、读取与轮换原则

| 原则 | P0 口径 |
|---|---|
| 存储 | project JSON 或 allowlisted environment 中只允许 body-free selector、enum 或 `null`；raw material 直接拒绝。 |
| 读取 | 只有 `infra/config.rs` 执行 raw input parse、schema/sensitive scan 和 redaction；builder 只消费已验证 binding。 |
| 传播 | selector 经过 owner/kind、immutable、scope 与 profile 校验后，才可注入既有 slot；domain/application 不接触 raw value。 |
| 轮换 | 使用新 selector，重新走完整 source/schema/type/ref/sensitive/cross-field 校验，再以 restart 使其生效。P0 不支持在线替换。 |
| 审计 | 仅记录配置域、slot/seam 类别、profile、校验 disposition、reason/change ref（若外部提供）和 redacted identity；不记录完整 ref 或原值。 |
| 缺省 | `null` 是 safe absence；对于 required scope 产生 `Blocked`/`Gap`，不是 provider 成功、LKG 或默认资源。 |

### 8.2 敏感配置族处理

| 配置族 | 可保存的表示 | 禁止内容 | 轮换与失败 |
|---|---|---|---|
| `composition.config_ref` | opaque composition selector。 | config body、endpoint、credential。 | 新 selector + restart；非法则 `Blocked`。 |
| `local_persistence.*_store_ref` | opaque local implementation ref。 | DSN、schema、lease、TTL、credential。 | 新 binding + restart；required slot 失败则 `Blocked`。 |
| `static_references.*` | mapping/component/seed/base 的 opaque identity 或受控集合。 | Role/mapping/component/template body、`latest`、live state。 | 新 immutable selector + restart；owner/kind/mutable 失败为 `Blocked`/`Gap`。 |
| `external_boundaries.*` | typed boundary selector。 | endpoint、credential、provider request/response、candidate/digest/gate/Artifact/consumer body。 | 新 selector + restart；未闭合 seam 只保留 `Unknown`/`Unavailable`/`Gap`/`ConsumerHandoffGap`。 |
| `diagnostics.redaction_policy_ref` | opaque restrictive selector 或 `null`。 | raw field allowlist、debug/raw bypass、sink/endpoint。 | 更严格 selector + restart；weaker/unknown 直接拒绝，继续 fixed floor。 |

### 8.3 Profile 约束

| Profile | 允许 | 禁止与失效 |
|---|---|---|
| `local-dev` | safe absence 或本地实现的 opaque ref。 | raw secret/endpoint/body；required selector 缺失则 local composition `Blocked`。 |
| `ci-test` | explicit TestOnly harness 的 deterministic fixture/opaque ref。 | production credential、raw fixture body、隐式 fake；fixture 不符则 fail-fast。 |
| `integration-like` | controlled/real-like adapter、store、target 的 opaque selector。 | raw material、sibling response、fake success fallback；不可用则 marker 或 blocked。 |
| `staging-like` | owner 批准后的 future secret/reference selector。 | TestOnly fixture、debug override、provider response；当前只作 pending direction。 |
| `production-like` | future approved secret/reference selector，且显式 production mode。 | fake、fixture、replay、raw secret/body、隐式降级；required 不可用即 `Blocked`。 |

### 8.4 禁止输出面

| 输出面 | 允许 | 禁止 |
|---|---|---|
| structured log / error | profile、slot/seam 类别、safe error code、issue ref、redacted identity。 | full ref、secret、endpoint、credential、body、provider response。 |
| audit | domain/key category、old/new redacted identity、change/reason ref、validation disposition。 | raw config、完整 selector、approval/signoff、外部正文。 |
| trace / metric | operation/profile/slot、低基数 outcome、safe diagnostic ref。 | secret、endpoint、route、高基数原文或 payload。 |
| worker/job marker | action identity、safe disposition、issue ref、计数类别。 | event payload、receipt、consumer confirmation、provider body。 |
| outbound | 当前 `ImageOutboundEventInventory::NoneAuthorized`。 | 因配置生成 outbox、publisher、receipt、topic 或 secret。 |

出现 raw secret、raw endpoint、provider body、manifest、Artifact/consumer body、live memory/checkpoint/workspace 或完整敏感 selector 时，候选配置在 builder 前 fail-closed；不得转译为 selector、写入诊断、回退低优先级值或继续启动。`diagnostics.redaction_policy_ref` 缺失使用固定 floor，任何试图降低 floor 的 selector 都被拒绝。

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_loading_validation_activation.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置加载流程图”“Source merge 与 effective configuration 规则”“Strict parse、type、ref-shape 与 sensitive 校验表”“Cross-field validation matrix”“Runtime builder assemble target 与模块暴露”“生效方式与 assembly 生命周期”和“配置失败与不可用处理表”小节，了解从原始输入到 typed slot 的完整链路。

### 9.1 加载顺序

```text
source precheck
  -> strict JSON parse / schema-known merge
  -> type / enum / opaque-ref / owner-kind / mutable / sensitive validation
  -> cross-field and scope validation
  -> infra/runtime_builder.rs slot assembly
  -> typed module exposure
```

`infra/config.rs` 是唯一 raw reader。它拒绝 JSONC、注释、trailing comma、重复 key、alias key、未知字段、错误层级和未授权 source；高优先级 env 值存在但非法时拒绝整份 effective configuration，不回退 JSON 或 safe absence。`infra/runtime_builder.rs` 只接收已验证 binding，不重新解释 raw input，也不在线探测 provider。

### 9.2 校验层级

| 校验层 | 必须检查 | 失败处理 |
|---|---|---|
| source/schema | source allowlist、严格 JSON、section/key shape、duplicate/unknown/alias。 | reject whole effective config；不 partial apply。 |
| scalar/enum | profile、mode、非空 selector、允许的 enum。 | `InvalidType`/`InvalidEnum`；不回退低优先级。 |
| ref shape | opaque、body-free、immutable、expected owner/kind；拒绝 URL/DSN/`latest`/mutable。 | `InvalidRefShape`/`OwnerKindMismatch`；受影响 slot `Blocked`/`Unknown`/`Gap`。 |
| collection/scope | role-extra 集合排序、去重、元素合法、数量和 scope 关系。 | `DuplicateRef`/`CollectionScopeConflict`；不得用空集合关闭 required slot。 |
| sensitive | raw secret、credential、endpoint、provider body、manifest、Artifact/consumer/live-state body。 | `ForbiddenSecretMaterial`；builder 前 fail-closed，不回显。 |
| cross-field | profile↔mode↔harness、required local completeness、static scope、external mandatory、redaction floor。 | `CrossFieldConflict`/`ForbiddenInvariantOverride`；assembly `Blocked`。 |

### 9.3 组装状态与暴露边界

| 状态 | 进入条件 | 允许动作 | 禁止动作 |
|---|---|---|---|
| `Unassembled` | 启动但尚未完成有效配置。 | parse、validate、保存安全 issue ref。 | 暴露业务 facade、启动 worker/scheduler/container、begin UoW、调用外部正向 adapter。 |
| `Assembled` | source/schema/type/ref/sensitive/cross-field 通过，mandatory local/static scope 已绑定，optional seam marker 已冻结。 | 暴露既有 typed facade/port；保留保守 marker。 | 将其解释为 build、digest、gate、Artifact、consumer、runtime、container 或 readiness。 |
| `Blocked` | 任一必填、类型、敏感、scope、owner/kind、mutable、profile/mode 或 mandatory slot 失败。 | 输出安全错误类别/issue ref；fail-closed。 | partial apply、LKG、cache、fake fallback、domain write、trace/event/result、provider call。 |

所有 P0 key 在 startup composition 时冻结。P0 不支持 reload、hot update、online override 或 LKG；轮换与回退都必须用新的、当前可验证的 body-free input 重启。entry-local 参数不能覆盖 profile/mode、slot ownership、redaction floor、static/live、state/UoW 或 owner boundary。

### 9.4 安全 issue surface

允许的 issue 只包含 source/section/key/slot/seam/profile/mode 类别、expected type/kind 类别、safe disposition 和 opaque issue ref。它们不等于 domain error、trace、audit event、report、evidence、result 或 readiness，也不得携带 raw file、匹配片段、完整 selector、外部响应或 live state。

配置加载失败不得产生 domain truth、mutation、UoW、result、trace、event、candidate、image digest、Artifact、consumer confirmation、launch、health 或 readiness。

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“角色分类与责任边界”“Safe audit surface 与禁止输出”“五域 P0 变更、审查、审计与回滚矩阵”“配置变更与 restart 回退链图”“回退规则矩阵”和“跨变更审计 / 回滚审计表”小节。

所有 P0 effective-input 变更都是离线、restart-only 的变更。外部 configuration / release process 可以准备 project JSON 或 allowlisted environment selector 的候选输入；`ci-test + explicit TestOnly harness` 仅可以准备其范围内的 deterministic fixture selector。 `contracts`、`domain`、`application`、`api`、`worker`、`jobs`、`infra/config.rs` 和 `infra/runtime_builder.rs` 都不是配置写入者。

| 变更类别 | 允许的发起方式 | 复核与关联输入 | 生效方式 | 明确禁止 |
|---|---|---|---|---|
| 非 TestOnly P0 effective-input 变更 | 外部过程离线替换 body-free JSON/env selector。 | high-risk；外部过程应可关联 scoped `change_ref`、`reason_ref`、`review_ref`。 | fresh validation 后的新启动。 | 在线修改、无验证成功宣称、把关联 ref 写成 approval/signoff。 |
| TestOnly fixture 变更 | 仅 explicit harness 在 `ci-test + test_only` 准备 deterministic selector。 | `test_context_ref` 与安全校验 disposition。 | 重新运行该 harness 前的完整校验。 | 流入其他 profile、成为真实 adapter 或回退输入。 |
| 不变量、source 或生命周期变更 | 不属于普通配置变更。 | 记录为 `design-change-required`。 | 先回写 `03-详细设计.md`，再重开受影响的 04 Step。 | 以 hidden key、emergency override 或 disabled flag 偷渡。 |

### 10.1 五域变更与回退规则

| 配置域 | 变更时必须重新确认 | 可保留的安全审计类别 | 回退输入与失败处理 |
|---|---|---|---|
| `composition` | profile、mode、harness 与 `config_ref` 一致；不隐式 fake。 | domain/key、profile/mode、safe issue 和外部 opaque change/review ref。 | prior validated 且仍相容的 body-free input 重新校验、重启；不可验证即 `Blocked`。 |
| `local_persistence` | truth/projection/idempotency 三个 required binding 的完整性与 owner/kind。 | slot 类别、profile、safe disposition/issue。 | 使用先前完整、仍可验证的三 binding 重启；不得单槽回退、cache、fake 或 repair。 |
| `static_references` | immutable、owner/kind、scope、集合去重与 static/live 边界。 | static slot/layer、gap/issue 类别。 | 使用先前 immutable 且仍符合当前 scope 的 selector；不可验证时 `Unknown`/`Gap`/`Blocked`。 |
| `external_boundaries` | seam kind、profile/fake 相容性和 mandatory scope；不探测 provider。 | seam 类别、conservative marker/issue。 | prior selector 仍须重新校验；owner contract 未闭合时保持 `Unavailable`、`Gap` 或 `ConsumerHandoffGap`。 |
| `diagnostics` | supplied selector 不弱于 fixed redaction floor。 | diagnostics policy 类别与安全 issue。 | 可退回先前 restrictive selector 或 fixed floor；weaker/unknown selector 始终 reject。 |

### 10.2 安全审计面

本仓只定义可安全关联的 audit surface，而不创建 durable audit truth、审批系统、审计后端、发布记录或回滚编排。外部 opaque reference 的存在不证明身份、授权、审批、留存或操作已经发生。

| 可关联内容 | 可记录的最小信息 | 禁止内容 |
|---|---|---|
| 变更关联 | `change_ref`、`actor_ref`、`reason_ref`、`review_ref`、`rollback_input_ref` 等外部 opaque ref。 | 工单/审批正文、身份凭证、governance approval truth、signoff。 |
| 配置定位 | domain/key/slot/seam、profile/mode、activation disposition。 | JSON body、完整 selector、endpoint、route、provider/consumer/Artifact body。 |
| 校验与回退 | accepted/rejected/blocked 类别、safe issue ref、可选 owner-provided redacted configuration identity。 | 原始非法值、secret、credential、stack trace、image/build/Artifact digest、provenance、manifest。 |
| 操作语义 | `rejected_before_activation`、`blocked_during_assembly`、`restart_required`、`rollback_requested` 或 `rollback_rejected`。 | host/container command、traffic/health result、live-state snapshot 或实际操作完成声明。 |

### 10.3 候选、激活与回退链

```text
[offline candidate JSON / allowlisted selector]
                    |
                    v
[strict load + source merge + validation]
       | rejected                         | validated
       v                                  v
[safe issue / no activation]   [new startup + local assembly]
                                         |
                               +---------+---------+
                               |                   |
                               v                   v
                       [Assembled (local)]      [Blocked]

[later rollback] = prior validated body-free input -> same validation chain
```

回退不修改正在运行的 configuration、domain truth、UoW、history、live memory/checkpoint/workspace、trace、event、candidate、Artifact 或 consumer truth。所谓 prior validated input 必须在新的 source collection 中仍能取得，并按当前 schema、profile、scope、owner/kind 和敏感规则重新通过验证；它不是 LKG、cache、复制的 raw body 或 TestOnly fake。host/container 生命周期、流量切换、健康判断和实际回滚执行属于外部运维职责，本文件不声称任何此类操作已发生。

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_degradation.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“失效策略术语与总原则”“P0 失效模式表”“按配置域组织的 failure / degraded matrix”“生效方式到失效处理矩阵”“安全观测与测试承接切口”和“跨失效策略审计表”小节。

`fail-fast` 表示在 source collection、parse、validation 或 required-slot assembly 阶段拒绝 effective configuration，且不暴露可执行业务 facade。`fail-closed` 表示遇到敏感材料、不变量覆盖、weak redaction 或 fake leak 时拒绝并只输出安全类别。`conservative marker` 仅适用于可选 external boundary 的 `Unknown`、`Unavailable`、`Gap` 或 `ReopenRequired`；它不是降级成功、provider health、外部结果或 readiness。`explicit restart recovery` 则是另一份候选输入重新经过全链路验证，绝不是原地修复。

| 失效模式 | 配置层行为 | 可见安全结果 | 禁止推导 |
|---|---|---|---|
| project JSON 缺失、严格 JSON syntax/shape 错误、duplicate/unknown key、错误层级 | `fail-fast`，拒绝整份 effective configuration。 | source/schema 类别与 safe issue ref。 | partial apply、facade、UoW 或已启动服务事实。 |
| 高优先级 env selector 为空、非法、含 body/raw material 或冲突 | `fail-fast`，不回退 JSON/safe absence。 | source/key 类别与 safe issue ref。 | 静默忽略、低优先级 fallback。 |
| profile/mode/harness 冲突、Production + fake 或 fixture leak | `fail-closed`，assembly `Blocked`。 | composition 类别。 | 隐式 profile 切换、fake 作为真实 seam。 |
| required composition/local/static slot 缺失、mutable、owner/kind/scope 不符 | required scope `fail-fast`，不暴露 facade。 | slot/layer `Blocked`、`Gap` 或 `Unknown`。 | begin UoW、query-time repair、`latest` 或空集合绕过。 |
| 可选 external selector 不可验证、owner contract pending 或不可用 | 冻结 conservative marker；mandatory scope 才 `fail-fast`。 | seam 类别及 `Unavailable`/`Gap`/`ConsumerHandoffGap`/`ReopenRequired`。 | provider call、retry、candidate、digest、gate、Artifact 或 confirmation。 |
| raw secret、credential、DSN、endpoint、provider/manifest/Artifact/consumer/live-state body | builder 前 `fail-closed`。 | forbidden-material 类别；不回显。 | 转换为 selector、日志记录、继续装配。 |
| redaction selector weaker、unknown、含 body 或尝试清空 floor | `fail-closed`；缺省仍使用 fixed floor。 | diagnostics policy 类别。 | debug/raw bypass、策略降级。 |
| reload、hot、online override、partial apply、LKG 请求 | `Unsupported`；frozen input 保持不变。 | activation 类别。 | 在线生效、自动回退。 |
| candidate/rollback input 已过期或当前无法重新验证 | 新启动 `Blocked` 或受影响 lane `Gap`。 | rollback/source/slot 类别。 | cache、旧 body、fake 或删除校验。 |

### 11.1 按域处理与恢复边界

| 域 | required input 失败 | optional / 缺省语义 | 恢复边界 |
|---|---|---|---|
| `composition` | whole config reject，`Blocked`。 | 不存在 profile/mode 成功默认；`config_ref=null` 仅是 safe absence。 | 修正候选或可验证 prior input 后重启。 |
| `local_persistence` | local composition 不成立；不得 begin UoW 或补偿 repair。 | 无 optional success slot。 | 重新提供三项完整 binding。 |
| `static_references` | current scope required 时 `Blocked`/`Gap`。 | 非 required affected lane 仅保持 `Unknown`/`Gap`。 | 重新验证 immutable selector；不读取 body。 |
| `external_boundaries` | mandatory scope `Blocked`。 | 可选 seam 仅 marker，且 builder 不 probe provider。 | owner 合同或可验证 selector 到位后，另一次启动再评估。 |
| `diagnostics` | unsafe supplied selector reject。 | 缺失时 fixed redaction floor。 | 使用同等或更严格 selector，或继续 fixed floor。 |

运行中的 frozen P0 input 不做连续 drift detection、在线 reconciliation 或自动修复。外部替换、过期或漂移只会在下一次显式启动时通过当前 validation chain 被重新评估。P0 没有 remote config center、secret provider reader、health API、retry/backoff、alert backend、cache、LKG 或 live repair；如这些能力进入范围，属于 `design-change-required`。

安全信号只能携带 source/domain/key/slot/seam/profile/mode 类别、safe disposition 和 opaque issue/marker ref。它们不是告警结果、报告、evidence、run、domain error、trace truth、candidate、Artifact、consumer confirmation 或 readiness。

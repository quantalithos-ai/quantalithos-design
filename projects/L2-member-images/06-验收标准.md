## 2. 验收目标与范围

> 校准来源：
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“验收目标”“验收范围表”“P0/P1/P2 裁决口径”和“范围项与 VETO 候选映射”小节，了解本轮分母与接缝上限。

本轮目标是判断镜像资产供给层是否形成可归责、可追溯、可裁剪的本地契约：

```text
C-MI-1 受控定义
  -> C-MI-2 静态装配与派生
  -> C-MI-3 构建候选与不确定性
  -> C-MI-4 provenance / eligibility
  -> C-MI-5 local supply / pinned entry
```

### 2.1 In Scope

| 范围 | 验收内容 |
|---|---|
| 五 capability | `C-MI-1~C-MI-5` 的本地 truth、状态、失败上限和链路可追溯性 |
| 逻辑协议 | 10 Command、10 Query、2 条 conditional inbound、6 个 bounded Operations Job、0 outbound |
| 数据边界 | static/template/seed/build input 与 live memory、checkpoint、workspace、container/observed state 的隔离；body-free ref/snapshot/gap 语义 |
| 版本和供给 | immutable pin、revision/derivation、candidate/provenance/eligibility、availability/history、pinned entry 和 consumer handoff gap 的分层 |
| 一致性和恢复 | 正式 state matrix、UoW/version/history、幂等/replay、unknown/blocked/unavailable 和 no-write 约束 |
| 配置与证据 | 五域配置的 strict/fail-closed、redaction、依赖裁剪、same-run artifact/report/EV 真实性 |

### 2.2 Out of Scope / 只验接缝

| 非范围 | 本文允许的最小验收面 |
|---|---|
| `L3-method-library` | body-free Role/mapping ref、snapshot、validity 或 gap；不验 Role 正文 |
| `L2-runtime` / `L2-tools` / `L2-member` | immutable component/extras release ref、pin、placement、compatibility gap；不验 loop、tool execution 或 member truth |
| `L1-artifact` | local handoff relation、formal-ref gap 或 owner safe conclusion；不验 ArtifactVersion/lineage truth |
| `L2-member-service` | local pinned entry 与 `ConsumerHandoffGap`；不验 manifest、container、launch、health、confirmation |
| builder / registry / gate / evidence provider | typed ref、safe outcome、unknown/blocked/unavailable 和分层；不验 vendor/backend truth |
| Bus / inbound / outbound | marker-only inbound 与 `ImageOutboundEventInventory::NoneAuthorized`；不验 topic、envelope、receipt、publisher 或 delivery |
| Sandbox / observability backend / product | body-free ref、safe field、boundary marker；不验 policy/backend、告警、dashboard 或产品入口 |

### 2.3 P0/P1/P2 口径

| 优先级 | 可进入的内容 | 结论上限 |
|---|---|---|
| P0 | 当前正式契约可判断的本地 truth、数据/依赖红线、协议边界、状态/UoW/幂等、配置安全和证据真实性 | 任一 P0 失败、VETO、过程硬门禁失败或不可裁决均阻断总体通过 |
| P1 | owner 已闭合的 real-like adapter、选定下游接缝和受控环境 | 未选入 P0 时可作为 residual；不得替代 P0 证据 |
| P2 | 多架构、特殊 variant、hardened base、性能/容量/SLO/retention、产品和运维增强 | 仅作 future/residual；污染 P0 时按红线失败处理 |

`MI-UP-001~009`、`Q-MI-001~004`、`DDD-S9-B01/B02`、`DDD-S11-B03`、`DDD-S13-OPEN-01/02` 和 `PF-UNAVAILABLE-RECOVERY` 未闭合时，受影响正向 lane 只能是 `blocked`、`gap`、`unknown` 或 `unavailable`，不得写成 pass、ready、accepted、digest 或 consumer confirmation。

## 3. 验收基线

> - 建议继续阅读该文件的“验收基线表”“证据入口基线表”“P0 profile 与依赖 disposition”和“不可接受的基线引用”小节，了解实际送验前必须固定的身份。

实际验收只能使用一个明确的、不可变且可复查的送验基线。下表是必须在 future execution 前填写的槽位；当前全部未生成。

| 基线维度 | 必须固定的内容 | 当前状态 |
|---|---|---|
| 文档 source | 正式 `00~05` 的版本/ref 与对应 calibration revision | `<formal-source-refs>`；未填写 |
| delivery / implementation | 实现来源、immutable build/image/delivery ref、必要的 commit 或等价不可变身份 | `<delivery-ref>`；不存在 |
| profile / configuration | `local-dev`/`ci-test`/选定 profile、严格校验后的 config identity/digest、fake mode | `<profile>` / `<config-digest>`；不存在 |
| fixture / seed | 可重复 fixture、seed/template identity、隔离键和脱敏声明 | `<fixture-ref>` / `<seed-identity>`；不存在 |
| dependency disposition | compile/runtime/event/ref/adapter/fake 分类、owner contract 状态和 selected seam | `<dependency-disposition>`；未确认 |
| run | 唯一 `<run_id>`，不可使用 `latest` 或跨 run 聚合 | `<run_id>`；不存在 |
| raw artifact | `artifacts/test/<run_id>/...` 下的 context、case、suite raw material | 未生成 |
| run report | `reports/runs/<run_id>/...` 下由 raw 派生的 report、index、gate/audit | 未生成 |
| acceptance handoff | `reports/acceptance/handoff.md`、未来 `veto-checklist.md`、`risk-acceptance.md`、`open-issues.md` | 未创建 |

### 3.1 固定路径与拒绝规则

```text
artifacts/test/<run_id>/...
reports/runs/<run_id>/...
reports/acceptance/...
reports/review/...
```

以下引用一律不能作为正式基线：`latest`、泛化“test/staging”、无 delivery identity 的报告、无 raw artifact 的 EV、`artifacts/test/<project>/<run_id>`、`reports/<project>/...`、跨 run 拼接、历史报告、手写 JSON/Markdown passed、stdout 或单个 trace。缺任一必要基线时，实际验收状态为 `not_entered` 或 `not_evaluable`，不是通过。

当前声明：正式 06 仅定义基线规则；没有真实 source ref、delivery ref、config digest、fixture、run、artifact、report 或 handoff。

| 条件 ID | 退出条件 | 裁决影响 |

### 4.3 暂停与不可裁决

| 情况 | 状态 | 处理 |
|---|---|---|
| 无 delivery/profile/fixture/run | `not_entered` | 固定基线后重新进入；不填写结果 |
| artifact/report/EV index/handoff 缺失或不一致 | `suspended` / `not_evaluable` | 修复生成链，使用新固定 run；保留原始失败/缺失记录 |
| observed S、VETO、redaction leak、unauthorized outbound、Query write、fake positive | `not_passable` | 修复并执行受影响 P0/全量回归；不可风险接受 |
| owner/design blocker 未闭 | `blocked` | 只保留 negative/no-write/marker/gap；owner 闭合后重开 |
| P1/P2 未选入本轮 | `residual` / `future` | 不进入 P0 分母；不能借此生成 ready |

### 8.2 事务、版本、历史与幂等统一规则

## 12. 缺陷分级、复验与放行规则

> 校准来源：
> - `design-calibration/06_acceptance_step_12_defects_release.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“记录类型：状态、finding、缺陷、阻塞与 residual 分离”“S/A/B/R 分级表”“新 run 和首次失败不可变规则”“修复后复验矩阵”和“放行规则”小节，了解 observed failure 与 design blocker 的区别。

### 12.1 记录类型与严重度

| 记录类型/等级 | 定义 | 对结论的影响 | 复验/处置 |
|---|---|---|---|
| `planned` | 设计中的 TC/EV/path 或 future contract | 不是执行结果 | 执行后才产生 instance |
| `design_blocker` / `dependency_blocker` | `DDD-*`、`PF-*`、`MI-UP-*`、`Q-MI-*` 或未闭 owner/设计合同 | 不得当 defect 或 risk accepted；受影响 positive lane blocked/not_evaluable | owner/设计闭合后重开 owning Step |
| `expected_negative` | 按 oracle 预期的 Blocked/Unavailable/Unknown/marker/zero outbound/no-write | 不等失败，也不等 positive pass | 用同 run evidence 证明 oracle |
| `not_evaluable` / `absent` | 缺 baseline、run、pair、owner oracle 或当前没有实际执行 | 不能通过；不是 observed defect | 先补基线或明确 blocker，不手写证据 |
| `S` | VETO 或 P0 truth、安全、证据、依赖、配置/阶段红线破坏 | 未关闭只能不通过/暂停；不可风险接受 | 保留首次失败，按原 TC、同 family、blocking suite、redaction/dependency/report audit 新 run 复验 |
| `A` | 未命中 S/VETO，但影响 P0 主线、状态/UoW/幂等、strict config 或可信证明 | 未关闭且未正式接受不得通过；仅可严格条件通过候选 | 原 TC + 同 family + affected P0 suite + artifact/report pair；Step 13 逐项审查 |
| `B` | 已证明不影响 P0 truth/VETO/过程硬门禁的一般问题 | 不改变 P0 结论；可进风险候选但不计 P0 passed | 受影响 suite/review/抽样复验并登记 owner/acceptor/action |
| `R` | 范围外、future、无正式阈值或 owner-controlled residual | 不写成已验证/readiness；可作为候选 | 记录 authority、触发条件、重开 Step 和 follow-up |

`05` 的 `C` 仅是测试方案编辑标签：纯排版/文案问题归 `B`，范围外归 `R`，改动正式字段、状态、路径或 P0 语义时按影响重新评为 `S` 或 `A`。

### 12.2 复验与关闭证据

1. 每次 targeted/impacted/full retest 使用新的固定 `<run_id>`，以 `prior_run_id` 回指首次失败；禁止同 run 重跑、`latest`、best-of-run、cherry-pick 或跨 run 拼接。
2. 首次失败的 safe raw artifact、suite report、failure reason、case mapping 和审查记录必须保留；不得删除失败材料形成绿色结果。
3. 关闭证据至少包括：首次失败、适用 AC/VETO/TC、修复后的新 run、原 TC、受影响 P0 suite、同 run artifact/report pair、redaction/dependency/pairing/report audit 和 closure review。
4. `S` 或 VETO 只能在新 run 证明修复并满足所有适用门禁后关闭；`A` 只有修复复验或 Step 13 合资格接受才可影响条件结论；B/R 必须有后续入口。

### 12.3 放行矩阵

| 条件 | 是否可通过 | 是否可有条件通过 | 说明 |
|---|---:|---:|---|
| 任一未关闭 S 或 VETO 命中 | 否 | 否 | 只能修复、复验或暂停；不可风险接受 |
| P0 evidence/report/redaction/dependency/config hard gate 失败 | 否 | 否 | 缺证据不是 residual |
| P0 not_evaluable 或 selected baseline 缺失 | 否 | 否 | 先补基线/证据，不得 manual pass |
| 未关闭且影响 P0 的 A | 通常否 | 否，除非 Step 13 逐项确认不影响 P0 且正式接受 | 默认不可接受 |
| 已证明不影响 P0 的 B/R | 不计入 P0 passed | 可以作为候选 | 必须有 risk_id、owner、acceptor、动作和 deadline/trigger |
| P1/P2/owner positive lane 未选入或未闭 | 不影响已定义 P0 分母 | 可作为 residual | 不得写成 positive readiness |

当前没有 observed defect、复验、关闭证据或 release verdict；以上均是 future contract。

## 13. 风险接受与遗留项

> 校准来源：
> - `design-calibration/06_acceptance_step_13_risk_acceptance.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“风险接受资格谓词”“风险/遗留项登记表”“不可风险接受清单”“未来风险接受记录的最小字段与不变量”和“后续动作、问题记录与跨文档同步”小节，了解 residual 的资格、责任和重开规则。

风险接受只适用于已证明不影响当前 P0 truth、VETO、过程硬门禁和证据完整性的 B/R residual，或经逐项严格审查、影响范围受控的 A candidate。它不改变原始 defect、VETO、artifact/report、digest、availability 或 owner truth。

### 13.1 资格与不可接受边界

```text
eligible_residual(r) :=
  stable_risk_id(r)
  && scope_is_not_current_P0(r)
  && no_veto_or_process_hard_gate(r)
  && bounded_impact(r)
  && evidence_or_formal_ref(r)
  && named_owner(r)
  && named_authorized_acceptor(r)
  && verifiable_action(r)
  && decidable_deadline_or_trigger(r)
  && follow_up_record(r)
```

不可风险接受：`VETO-MI-001~007`、S、redaction leak、evidence/report-audit/dependency/zero-outbound/config hard gate failure、P0 not_evaluable、Query/Job/inbound 反写真相、无 authority 生成 candidate/digest/ref、不合格版本进入 availability、历史覆盖、local state 冒充 Artifact/consumer/container/readiness，以及仍影响 P0 的 design/dependency blocker。

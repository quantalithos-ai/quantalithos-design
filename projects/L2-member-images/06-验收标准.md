### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L2-member-images` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L2-member-images` 是成员镜像资产层 / persona-image 供给层,不是 member 实例仓、runtime live state 仓或 capability-hub 合同仓
- MemberImage / ImageRoleBinding / ImageVersion 构成正式镜像模板真相层
- `MemberImage ≠ Member`、`ImageRoleBinding ≠ identity role truth` 两条核心边界必须成立
- persona / prompt / style 种子装配只表达默认交互起点,且 `ImagePersona ≠ live runtime persona state`、`default prompt/style ≠ conversation history`
- toolset / capability refs / policy overlay 只做装配,且 `ImageToolset ≠ capability contract truth`
- memory/workspace seeds 只表达初始化材料,且 `MemorySeed ≠ live memory store`、`WorkspaceSeed ≠ active workspace truth`
- version / derivation / publish / retire / instantiate 构成正式镜像演进与交付主线,且 `ImageVersion / Derivation ≠ member lifecycle`
- instantiate bundle 必须可被 member/runtime 稳定消费,同时不反向改写镜像真相

因此,本次验收的目的不是笼统判断“能不能存一套 prompt 配置”,而是判断 member-images 的 image definition 主线、persona 主线、capability/overlay 主线、seed bundle 主线与 version/instantiate 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 镜像定义与身份适配部分 | 是 | MemberImage、ImageMetadata、ImageRoleBinding、ImageUsageScope、ImageStatus |
| Persona 与交互种子装配部分 | 是 | ImagePersona、PromptSeed、InteractionStyle、StarterBehaviorBundle |
| 工具、能力与策略覆盖装配部分 | 是 | ImageToolset、CapabilityRef、PolicyOverlay、ProviderPreference、RestrictionEntry |
| 记忆与工作区初始化材料部分 | 是 | MemorySeed、WorkspaceSeed、StarterFileRef、StarterMaterialBundle、SeedIntegrityDigest |
| 版本、派生与实例化出口部分 | 是 | ImageVersion、ImageDerivation、ImagePublishRecord、InstantiateBundle、InstantiateTicket |
| member 正式实例真相、runtime live state、conversation history、本地 memory store | 否 | 只验镜像如何提供模板和 seed bundle,不验下游运行态全部实现 |
| identity role truth / capability contract / governance policy source truth | 否 | 只验 image 如何消费这些来源,不验上游仓全部实现 |
| UI catalog 视觉展示细节 | 否 | 只验只读 catalog/summary 结果,不验具体界面表现 |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | image 替代 member 真相 / capability 越权装配成功 / live state 回写 seed truth / retired image 继续实例化 |
| A | 视情况 | 主线可跑但 lineage、bundle 完整性、catalog summary 或 instantiate 稳定性不稳 |
| B | 可带着走 | 非关键视图、低优先级 style / summary 展示异常 |

## 2. 实施目标与范围

> 校准来源：
> - `design-calibration/07_implementation_plan_step_02_scope.md`
>
> 延伸阅读：
> - 请继续阅读该文件的“P0 目标表”“范围/非范围矩阵”“owner boundary”和“不得宣称清单”。

### 2.1 实施目标

本轮实施计划的目标是把成员镜像资产层与构建产物供给层转译为可验证、可回退、可追溯的代码落地顺序：

| 目标 | 计划交付方向 |
|---|---|
| `C-MI-1` 受控定义 | definition、variant、Role mapping 的 body-free ref/source validity |
| `C-MI-2` 静态装配与派生 | runtime/tools/member/supervisor/extras/base/seed 的 immutable pin、placement、revision/derivation |
| `C-MI-3` 构建候选 | intent、snapshot、attempt、outcome、candidate 的 typed relation 与保守停止 |
| `C-MI-4` provenance/eligibility | provenance、gate、qualification、Artifact handoff gap 的分层 |
| `C-MI-5` local supply | availability/history、pinned entry、consumer handoff gap、strict Query/view |
| 交付纪律 | 24 boundary、72 planned batch、implementation ledger、same-run evidence contract |

### 2.2 本轮 P0 范围

- 七职责 workspace 的 planned 目录、package/crate 命名与依赖方向。
- contracts/domain/application/infra/api/worker/jobs 的 typed carrier、pure guard、safe error、logical entry 和 no-write surface。
- 10 Command 的合法 shape 与当前 B01/B02 前 zero-effect；10 Query strict read-only；2 条 marker-only inbound；6 个 bounded Job；outbound inventory 固定为 `NoneAuthorized`。
- 五域 21 key 的 strict/fail-closed binding、profile/fake 隔离和启动时冻结。
- planned test/gate/check/report/evidence/handoff 的输入输出契约，不生成实际实例。

### 2.3 不在本轮交付

| 非范围 | 责任方/处理 |
|---|---|
| RoleDefinition、Role-to-image mapping body、method asset body | `L3-method-library`；本仓只消费 ref/snapshot/gap |
| member 主体、component/extras release、runtime loop、tool execution | `L2-member`、`L2-runtime`、`L2-tools`；本仓只保存 typed pin/ref |
| policy/memory/workspace seed body、live state | 对应 owner；本仓不读取或保存 live state |
| builder/registry、gate/evidence、Artifact truth | external owner / `L1-artifact`；本仓只保留 adapter/gap |
| member-service manifest、container、launch、health、confirmation | `L2-member-service`；本仓只提供 pinned entry/ref/gap |
| event envelope/receipt/topic/publisher/outbox | Bus/Core/event owner；本仓 inbound marker-only、outbound zero |
| scheduler、lease、retry、in-flight recovery、projection recovery | 需正式 03 回写；当前 B01/B02/OPEN/PF blocked |
| 多架构、性能容量、生产部署、marketplace/product entry | P1/P2/future；需新 scope、baseline 和验收 |

### 2.4 结论上限

任何 `planned`、`blocked`、`unknown`、`unavailable`、`gap` 或 `not_evaluable` 都不能被改写为 `pass`、`ready`、`accepted`、digest、release、consumer confirmation 或 readiness。当前只能规划 pure contract、negative/no-write、marker、gap 和 bounded selector。

### 6.3 Boundary 开工与停审规则

每个 boundary 开工前必须检查字段/DTO/support carrier、状态、ref identity、validation truth、metadata/idempotency、projection/artifact source、测试切口和 phase boundary；设计者先复核，实现者只做二次校验。任一 blocker 未闭，boundary 只能处于 `blocked / wait_design` 或 `planned / wait_until_current`。

当前项目级 ledger 位于 `design-calibration/implementation_execution_ledger.md`；24 个 boundary ledger 位于 `design-calibration/implementation-boundaries/`。每个 boundary skeleton 均包含 Required Checks、Gate Matrix、Commit/Handoff Gate、Blockers 与 Commit Record；仅项目级 ledger 可把一个 future boundary 变为 current。

## 11. 提交、评审与交付纪律

> 校准来源：
> - `design-calibration/07_implementation_plan_step_11_commit_review_delivery.md`
>
> 延伸阅读：
> - 请继续阅读该文件的“仓库/语言边界”“Commit message 结构”“boundary body 分组映射”“提交前检查清单”和“Commit/Handoff Gate”小节。

### 11.1 提交粒度

一笔 future implementation commit 对应一个 `commit-xx-y` boundary。boundary 内的 contracts、domain/application、infra/entry 和 targeted tests 如果共同构成同一可验证增量，保留为一笔提交并在 body 中按子功能分组；不得按文件、struct、repository、route 或当天工作量拆分。当前 `commit-01-a` 不能提交，因目标仓不存在且 Gate-01 blocked。

### 11.2 实现仓提交格式

```text
<type>(<scope>): <english subject>

<one-sentence boundary summary>

<sub-feature group>:
- <file_name.rs> (+/-N): <functional note>.
- <file_name.rs> (~+N/-M): <functional note>.

Co-Authored-By: Codex <noreply@openai.com>
```

实现仓 `type` 可用 `feat/fix/refactor/test/chore/ci/docs/perf/style`；scope 使用 `workspace/config/definition/assembly/build/qualification/supply/query/entry/job/evidence/handoff` 等稳定词，不使用层号。标题、body、源码标识符、rustdoc、注释和测试名默认英文；标题后、footer 前必须有真实空行；禁止字面量 `\n`、跨 boundary 改动和未经授权的额外 footer。

设计仓本轮不提交 commit；若未来获得单独授权，设计仓提交语言遵循设计仓既有规则，不得反向放宽实现仓英文源码/commit 约束。

### 11.3 评审与移交

| Gate | 必查内容 | 当前 |
|---|---|---|
| Design Gate | formal 03~07、calibration、字段/DTO/state/ref/phase 一致 | `pass-designed` 或 `blocked` |
| Scope Gate | allowed/forbidden scope、依赖和用户改动 | `pending`（目标仓缺失） |
| Build/Test Gate | fmt/check/targeted TC/受影响 suite | `not_run` |
| Evidence Gate | same-run raw/report/EV、redaction、pairing、NOSTATIC | `not_generated` |
| Commit Gate | diff、identity、message、staged files、gate result | `blocked` |
| Handoff Gate | post-status、baseline、hash、blocker、next boundary、报告 refs | `not_started` |

Handoff 只能生成 `review_required` 输入给正式 06；不能关闭 blocker、签署 acceptance、生成 release/consumer/runtime readiness 或冒充 Artifact/外部成功。

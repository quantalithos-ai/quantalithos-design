## 3. SOP 问题回答

1. 当前讨论哪个节点?

   回答:严格按 C-MI-1、C-MI-2、C-MI-3、C-MI-4、C-MI-5 推进,每个节点完成故事表后立即停审。

2. 哪些角色目标支撑核心闭环?

   回答:镜像资产维护者关心定义和装配基线;构建 / 发布运维者关心候选和供给;供应链 / 安全审查者关心 provenance 与 eligibility;审计者关心全链追溯;系统消费者关心 pinned 可实例化入口。

3. 哪些只是外围增强?

   回答:多架构、特殊收缩 variant、安全补丁快速通道、加固基础镜像和使用分析只增强适配性、响应或可视性,不决定五节点闭环是否成立。

4. 哪些看似故事但不进入本仓?

   回答:修改 Role mapping、执行工具 / runtime loop、维护 live memory / checkpoint、启动容器、定义 Sandbox policy、发布 ArtifactVersion、经营 marketplace 等目标属于相邻 owner。

5. 每条故事是否有唯一节点?

   回答:15 条核心故事均有唯一主节点;跨节点价值通过能力逻辑依赖表达,不复制同一角色目标。

## 4. 当前文档问题诊断

| “作为 CI,我要 build / scan / sign / push” | 把实现步骤和系统组件当用户目标 | 改为运维 / 安全 / 审计角色的结果目标 |

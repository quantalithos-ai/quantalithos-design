# 03 · L2-member-images 功能与能力闭环(draft)

> 状态: approved draft / 仅作正式 00 的 historical input

## 1. 核心能力闭环草案(6 节点)

```text
[C-MI-1 Variant 定义与映射承接]        <- method-library RoleDefinition / mapping (ref)
            |
            v
[C-MI-2 装配定义与 seed 模板承接]      <- runtime/tools/member 产物 ref + seed 模板 ref
            |
            v
[C-MI-3 镜像域版本绑定与派生管理]      (variant revision / pin / Artifact ref / availability)
            |
            v
[C-MI-4 构建触发、执行编排与记录]      -> builder/registry adapter (blocked 时 fail-closed)
            |
            v
[C-MI-5 Provenance / digest / 证据承接] -> policy-required evidence adapters (pending kinds)
            |
            v
[C-MI-6 发布 / 回滚交接与可实例化入口]  -> member-service manifest/variant/ref (pending)
            |
            +---- 新映射 / 新版本 / 安全触发 ----> 回到 C-MI-1 / C-MI-3

[ADR-0005 nightly schedule] ----------------------> C-MI-4
[L0-bus 镜像构建事件消费(schema pending)] --------> C-MI-1 / C-MI-2 / C-MI-4
```

| 节点 | 能力成立描述 | 本仓 owner | 外部 owner 边界 |
|---|---|---|---|
| `C-MI-1` Variant 定义与映射承接 | 以受控 ref / pinned snapshot 消费 RoleDefinition 与 Role -> image variant 映射,形成本仓 variant 目录(image family、variant 身份、persona 装配定义) | variant 目录、image/persona 装配定义、映射消费记录(stale / missing / conflict 显式) | RoleDefinition 正文与映射定义真相(method-library);Role 业务语义(identity 方向,pending) |
| `C-MI-2` 装配定义与 seed 模板承接 | 每个 variant 有可追溯的装配清单:装配哪些组件产物(member / runtime / tools + 角色 extras)、承接哪些 policy / memory / workspace seed 模板 | 装配清单、组件产物 pin 事实、seed 模板身份 / 版本 / 落位事实 | 组件产物发布真相(各组件仓);工具契约(tools);seed 内容定义来源(governance / method-library / workspace owner,pending) |
| `C-MI-3` 镜像域版本绑定与派生管理 | 管理 variant definition revision、base -> variant 装配派生规则、组件版本 pin、正式 Artifact 消费引用绑定和镜像供给可用性变化;不原地改写历史绑定 | variant revision、装配派生规则、pin binding、release eligibility / supersede / retire 状态 | 上游组件发布真相;`L1-artifact` 的 Artifact 正文、版本、血缘与基线真相;`ConsumableArtifactReference` 的 image handoff 用法 / schema pending |
| `C-MI-4` 构建触发、执行编排与记录 | 承接 ADR-0005 nightly 触发及有效变化 / 构建事件输入;一次构建有输入快照、构建请求、执行交接、候选输出 digest / ref 和失败分类;builder 不可用 / 失败时 blocked,不伪造产物 | nightly 构建意图、构建请求 / 记录 / 输入快照 / 候选输出绑定 / 失败分类 | CI 调度与 builder 后端真相(adapter);registry 存储真相(adapter);L0-bus 事件 schema pending |
| `C-MI-5` Provenance / digest / 供应链证据承接 | 每个候选输出都有输入到 digest 的 provenance 绑定;若正式适用策略要求 BOM、扫描、签名或其他证据,则只承接其 ref / conclusion 并 fail-closed;当前具体证据种类和门禁 authority 待 00 确权 | digest / provenance 绑定、适用门禁的承接与 eligibility 判定 | Artifact 版本 / 血缘(`L1-artifact`);BOM / 漏洞库 / 扫描器 / 签名密钥与具体结论 owner(pending / adapter) |
| `C-MI-6` 发布 / 回滚交接与可实例化入口 | 满足已确权门禁的镜像形成镜像供给 publish 事实与可用 variant 目录;提供 manifest / variant / ref 解析入口;rollback / retire 显式;下游是否升级由下游决定 | 镜像供给 availability、publish / rollback / retire 状态、manifest 查询语义、交接 attempt / gap | `ArtifactVersion` 发布与 baseline truth(`L1-artifact`);member-service 实例化决定与容器生命周期(pending);出站事件合同未确权 |

进入 / 退出约束:C1 需正式映射 ref(stale / missing 时 blocked);C2 需组件产物 ref 可验证(缺失即 blocked,不猜版本);C4 必须承接 ADR-0005 nightly 意图,但具体 CI 产品与调度配置后置;C5 的 digest / provenance 绑定是主链,具体 BOM / 扫描 / 签名种类待 00 确权,凡被正式声明为适用门禁者均不可配置化绕过;C6 只允许满足已确权门禁且 Artifact handoff 状态可解释的镜像进入可用目录;任一 pending seam 未闭口时,受影响正向路径 fail-closed。

## 2. 功能清单草案

### 2.1 功能候选与当前 authority

本表编号仅用于 draft 追踪;优先级必须在 00 重新推导。`accepted` 表示已有当前 authority,`task_boundary` 表示用户明确要求的职责方向,`pending` 表示不得写成已闭合正向合同。

| ID(草案) | 功能 | 说明 | authority / 状态 | 节点 |
|---|---|---|---|---|
| F-MI-01 | image family / variant 目录管理 | 承接“一 Role 一镜像”,建立、变更、退役 variant 定义;每个 variant 回指映射来源,但不固化 Role 枚举 | ADR-0005 accepted + task_boundary | C1 |
| F-MI-02 | Role -> variant 映射消费 | 以 pinned snapshot 消费方法库映射;stale / missing / conflict 显式 | method-library formal + ADR accepted | C1 |
| F-MI-03 | persona / 装配定义管理 | variant 的装配组成定义(组件 + extras + seed 落位) | task_boundary | C1/C2 |
| F-MI-04 | 组件产物 pin | member / runtime / tools 产物 ref 与版本 pin 绑定 | ADR pinned constraint + task_boundary;具体 ref pending | C2 |
| F-MI-05 | 角色 extras 装配清单 | 按 variant 差异化装配工具产物集合(owner 在本仓,工具契约归 tools) | task_boundary;输入 contract pending | C2 |
| F-MI-06 | seed 模板承接 | policy / memory / workspace seed 模板的身份、版本与进入 variant 的落位事实 | task_boundary;source owner pending | C2 |
| F-MI-07 | 镜像域版本绑定与派生 | variant revision、base -> variant 装配派生、pin、正式 Artifact 消费引用、availability / supersede / retire;不拥有通用 ArtifactVersion / Lineage | task_boundary;`ConsumableArtifactReference` handoff pending | C3 |
| F-MI-08 | nightly / 变化触发与输入快照 | 每晚形成构建意图;有效变化或构建事件按需触发;全部输入固化为可追溯快照 | nightly accepted;event schema pending | C4 |
| F-MI-09 | 构建执行交接与记录 | 向 builder adapter 交接、承接候选 digest / ref、结果与失败分类;不拥有 builder 真相 | task_boundary;adapter contract pending | C4 |

| F-MI-12 | 策略要求的供应链证据门禁承接 | 可承接 BOM / scanner / signer 等证据 ref 与结论;只有经 00 确认适用的门禁才进入当前 P0 合同 | pending,不得预写通过或 readiness | C5 |
| F-MI-13 | 镜像供给 publish / rollback / retire | 管理可实例化入口的可用性变化与交接,不替代 `ArtifactVersion` publish / baseline truth | task_boundary;Artifact handoff pending | C6 |
| F-MI-14 | manifest / variant / ref 供给 | 向 member-service 提供可实例化镜像入口的查询 / 解析语义 | task_boundary;消费合同 pending | C6 |

## 3. 失败语义方向(需求层)

区分至少:映射 stale / missing / conflict、组件产物 ref 缺失、seed 模板缺失、构建 blocked / failed / unknown、兼容门禁 pending / fail、适用供应链证据 missing / fail、Artifact handoff pending / rejected、publish blocked、registry unavailable、rollback pending、下游合同 pending。这些状态不得互相压平;正式适用门禁失败一律 fail-closed,不得配置化绕过;尚未确权的 BOM / 扫描 / 签名候选不得被伪报为 passed 或 ready。

## 4. 设计取舍(功能层)

| 取舍点 | 采用 | 未采用 | 理由 |
|---|---|---|---|
| 能力组织方式 | 按资产生命周期主线组织 6 节点闭环 | 按旧 README 的 CI 步骤清单(拉 tag -> build -> scan -> sign -> push)组织 | CI 步骤是实现流水线,不是能力真相;生命周期主线能承载 owner / seam 分层 |
| 兼容性检查 | 作为构建门禁**承接**,检查定义归属记 pending | 直接继承旧"IPC schema 兼容性检查"为本仓功能 | member / runtime 未重校准,接口版本语义 owner 未定,不能私造 |
| Bus 协作方向 | 按全局矩阵先固定“消费镜像构建事件”;manifest / ref 供给由下游自行决定是否升级;出站构建 / 发布事件保留 pending 候选 | 直接继承旧“通知 member-service”或假设本仓已发布构建 / 发布事件 | 当前 authority 只明确入站消费方向;出站 family / schema 未闭口,不能倒置依赖 |
| Role 清单 | 不在本仓固化 Role 枚举 | 旧 9-Role 硬清单 | Role 目录真相在 method-library / identity;本仓只有 variant 目录 |

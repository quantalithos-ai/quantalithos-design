## 2. 业务背景与驱动力

> 校准来源：
> - `design-calibration/01_arch_step_01_requirement_baseline.md`
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“稳定需求结论”“SOP 问题回答”“架构目标”和“回填草稿”小节，了解需求问题如何转译为架构目标。

AI 成员要成为可运行执行体，需要同时承接项目成员边界、身份锚、正式镜像供给、宿主凭据、隔离绑定、容器承载、Member 注册、Runtime 协作和事实交接。这些能力分别属于不同 owner；若宿主状态散落在 Work、Member、Runtime、Sandbox 或编排平台中，就会出现多写源、恢复归责不清、外部结果反写和第二活动实例。

本仓因此独立承担宿主控制面和宿主侧事实：从正式意图与编排决定开始，沿宿主装配、注册 / Host Session、健康 / 恢复、下线 / 对账直至安全交接形成连续历史。它解决的是“这个项目成员是否具有可用且可归责的执行宿主”，不是“成员是谁”“成员如何思考”“工具如何执行”或“隔离后端如何实现”。

| 目标 ID | 架构目标 | 成立判断 |
|---|---|---|
| `AG-MS-001` | 建立唯一宿主控制面与 Host Truth Center | 宿主决定、实例、会话、健康和收束事实只有本仓可写。 |
| `AG-MS-002` | 保证项目型主语到宿主世代的可追溯连续性 | 每个决定和实例均能回指正式意图、ProjectMemberRef 与 GlobalMemberRef。 |
| `AG-MS-003` | 建立 owner-safe 装配与 fail-closed readiness | 分项来源、状态和缺口可区分；partial / unknown 不能成为 ready。 |
| `AG-MS-004` | 建立唯一注册、endpoint 与 Host Session 关联 | 同一宿主语境没有竞争活动关联，替换与失效历史连续。 |
| `AG-MS-005` | 建立分层健康与宿主侧恢复闭环 | host / session / backend / unknown 可区分，新世代不改写旧历史。 |
| `AG-MS-006` | 建立 local-first 清理、对账与事实交接 | 本地结论、外部尝试、gap 和外部完成状态不混写。 |
| `AG-MS-007` | 建立可替换的外部 seam 与单向依赖 | sibling、Bus、Sandbox 和基础设施只能经 runtime / event / ref / adapter 接入。 |
| `AG-MS-008` | 建立证据诚实且可演进的架构基线 | pending / fake / unknown 始终显式，产品与规模演进不改变 owner。 |

当前目标采用结构性判断，不宣称任何服务、adapter、持久化、测试或正向集成已经存在。性能、容量和健康数值仍缺 workload、环境与测量 authority，不进入架构完成条件。

## 3. 约束条件

> 校准来源：
> - `design-calibration/01_arch_step_01_requirement_baseline.md`
> - `design-calibration/01_arch_step_02_goals_constraints.md`
> - `design-calibration/01_arch_step_14_risks_open_questions.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“硬约束”“不可变约束”“当前阶段取舍”“Blocker 分层”和“Gate 自检”小节，了解约束与挂起上限。

### 3.1 不可变约束

| 约束 ID | 约束 | 架构含义 |
|---|---|---|
| `HC-MS-001` | control plane、host truth、runtime session 与 execution handoff 不得合并 | 每类结论必须可定位 owner，宿主决定不得被 run 或执行结果替代。 |
| `HC-MS-002` | 当前只接受 ProjectMemberRef 执行主语和一致 GlobalMemberRef 身份锚 | 非项目型意图 fail closed，不能以身份锚或 Workspace view 代替执行主语。 |
| `HC-MS-003` | 本仓不得拥有相邻仓或基础设施 truth | Runtime、Member、Images、Tools、Sandbox、Governance、Observability 与 L1 正文均外置。 |
| `HC-MS-004` | required qualification 缺失、陈旧、冲突或未知时 fail closed | 不得使用默认值、本地 allowlist、旧缓存或 host fallback 声明 ready。 |
| `HC-MS-005` | external body、secret、credential body 与运行 / 隔离 / 证据正文不得入仓 | 只允许 typed ref、safe snapshot、redacted marker 和 body-free material。 |
| `HC-MS-006` | 重复、并发、迟到和 unknown 不得制造第二活动宿主、注册或 Host Session | 活动关联唯一；替换形成新世代和新事实，不覆盖历史。 |
| `HC-MS-007` | local truth、attempt / gap、delivered、observed 与 accepted 必须分层 | 外部传播、观测和接受状态不得反写本仓正式结论。 |
| `HC-MS-008` | compile / runtime / event / ref / adapter / fake 必须保持分类 | 运行期协作不得伪装源码依赖，fake 不证明真实集成。 |
| `HC-MS-009` | 无 authority 的产品、协议、schema、阈值和部署参数不得锁定 | 历史材料和实现便利不能反向决定架构。 |

### 3.2 当前阶段取舍

| 取舍 | 当前接受原因 | 保护条件 |
|---|---|---|
| 正向 sibling 合同尚未闭口 | owner 与失败边界足以稳定架构 | 受影响路径 blocked / waiting，不写字段、协议或 readiness。 |
| 容器、数据库、消息、RPC 和 registry 产品未选 | 产品不是 host truth 的前提 | 先固定 ports、数据和交互机制，产品不得改变 owner。 |
| 三个运行角色可同部署 | 当前无 workload 或 fault-isolation 证据要求拆分 | 逻辑职责、失败和扩缩边界保持独立。 |
| 性能、容量和健康窗口未量化 | 缺少正式场景、环境与测量 authority | 只保留结构性 guard 和测量维度，不使用旧数字。 |
| 容量优化、预热、forensic 和聚合视图后移 | 不影响 C-MS-1~5 核心成立 | 外围增强不得成为核心前置或写源。 |

### 3.3 架构非目标

- 不设计 Runtime 的 LLM loop、goal / plan、memory / checkpoint、tool orchestration、run recovery 或 outcome truth。
- 不设计 Member 主体、presence、入站过滤、交互、请求 / 信号 / 报告正文及本地 IPC 实现。
- 不设计镜像内容、构建、签名、BOM、provenance evidence 或 Role -> image 映射。
- 不设计逐动作 Tool execution、Capability registry、外部 MCP / A2A / API truth。
- 不设计 Sandbox backend、policy、enforcement、capture、cleanup truth或 Governance approval / policy truth。
- 不设计 Observability backend、Artifact / Archive / Evidence / report / verdict 正文或任何 L1 领域状态机。
- 不选定语言、框架、数据库、消息、RPC、容器平台、部署拓扑、资源参数或性能数字。
- 不预建 policy 传递能力，不把非项目型宿主、warm pool 或复杂调度写成未来默认承诺。

## 4. 职责边界

### 4.1 做与不做

| 职责项 | 类型 | 正式边界 |
|---|---|---|
| 宿主意图受理、项目型范围判定和编排决定 | 做 | 形成 accepted / rejected / waiting / conflict / no-action 及 launch / restart / stop / terminate / relocate / hold 决定。 |
| 宿主实例、世代、装配分项与 Host Readiness | 做 | 拥有 host-side truth，只关联外部供给、凭据、binding 和承载 ref。 |
| 注册接受、endpoint registry 与 Host Session 壳 | 做 | 维护唯一活动关联和替换 / 失效历史，不创建或推进 Runtime run。 |
| 宿主健康、失败分类与宿主侧恢复 / 终止 | 做 | 区分 host / session / backend / unknown，不处理 run 内恢复。 |
| 本地下线、cleanup / release、残留对账和 handoff gap | 做 | 拥有本地决定、attempt、gap、residual 与 reconciliation，不冒认外部完成。 |
| Identity / Work / Governance truth | 不做 | 只消费正式 ref / safe snapshot / 变化材料，不创建、修改、修复或反推。 |
| Runtime / Member / Images / Tools / Capability truth | 不做 | 只经正式 seam 协作，不吸收正文、私有状态机或源码模型。 |
| Sandbox isolation 与基础设施产品 truth | 不做 | 只保存宿主级关联和允许反馈，adapter 产品状态不成为 host truth。 |
| Bus delivery、Observability observed、Artifact / Archive / Evidence truth | 不做 | 只形成 body-free local material、attempt / gap 和只读视图。 |
| policy 传递与非项目型宿主 | 当前不做 | 没有当前 FR；纳入时必须先重开需求和受影响架构。 |

### 4.2 易混淆职责

| 易混淆对 | 本仓职责 | 相邻 owner 职责 |
|---|---|---|
| ProjectMember 分配 vs 宿主意图 | 受理正式来源后的宿主意图并形成决定 | Work 拥有 ProjectMember 分配 / 回收 truth。 |
| GlobalMember identity vs 执行主语 | 验证身份锚与 ProjectMemberRef 一致 | Identity 拥有 GlobalMember lifecycle 与正文。 |
| Host Readiness vs Runtime readiness | 判定宿主装配 required qualification | Runtime 判定 run / execution 内部状态。 |
| Host Session vs Runtime session / run | 维护宿主关联壳和可用性 | Runtime 拥有运行会话内容、run、checkpoint 与 outcome。 |
| registration acceptance vs Member report | 接受 / 拒绝并维护 registry 与活动关联 | Member 拥有请求、信号、报告和本地发送尝试。 |
| SandboxBinding 装配 vs isolation truth | 保存宿主级 binding 关联与本地结果 | Sandbox 拥有 enforcement、capture 和 cleanup truth。 |
| host cleanup attempt vs external completion | 记录本地决定、attempt、gap 和 residual | Sandbox / carrier 各自拥有实际完成事实。 |
| host health vs business / runtime / observed | 形成宿主层四类健康结论 | Runtime、业务域和 Observability 各自拥有内部 / observed truth。 |
| image qualification vs image supply | 消费 pinned supply 并形成本地资格结论 | Images 拥有内容、构建、发布和供给 truth。 |
| handoff material vs delivery / observed / accepted | 形成 body-free 材料和 local attempt / gap | Bus / Observability / 下游拥有各自完成状态。 |

| 红线 ID | 红线 |

| `BL-MS-007` | 不得让 adapter 产品状态、fake 或历史方案取得 domain authority。 |

## 5. 系统边界与上下文

> 校准来源：
> - `design-calibration/01_arch_step_04_system_context.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“系统上下文图”“上下游与输入 / 输出面表”“依赖失效口径”和“Gate 自检”小节，了解系统位置与开放边界。

`L2-member-service` 位于 Identity / Work 已成立的成员与项目事实、Member Images 正式供给、Sandbox 隔离能力和宿主基础设施之间，将正式项目型意图转化为可追溯的宿主决定与事实。Member 与 Runtime 是双向运行协作方，Bus 与 Observability 是材料 carrier / consumer；任何一方都不能单独定义 Host Readiness。

### 5.1 系统上下文图

```text
              +----------------------+   +----------------------+
              | L1-identity          |   | L1-work              |
              | identity anchor      |   | execution subject    |
              +----------+-----------+   +-----------+----------+
                         | input                    | input
                         +-------------+------------+
                                       |
                                       v
+----------------------+   +-----------+----------+   +----------------------+
| L2-member-images     |-->| L2-member-service   |<--| L4-sandbox           |
| pinned supply        |   | host control/truth  |   | isolation ability    |
+----------------------+   +-----------+----------+   +----------------------+
                                       ^
                                       | input / output
                         +-------------+-------------+
                         |                           |
              +----------+---+             +---------+----+
              | L2-member   |             | L2-runtime  |
              | host source |             | run owner   |
              +--------------+             +--------------+
```

- 箭头只表示输入、输出或依赖，不表示协议、运行顺序或 package dependency。
- `L2-member` 与 `L2-member-images` 只采用正式 00 的需求级方向，进行中的 01 不表示 exact contract ready。
- 宿主基础设施、Core / SDK、Bus 和 Observability 由关系表承接，未画入主图不表示不存在正式边界。
- Method Library 只经 Member Images 间接影响供给，本仓没有 Role -> image 的直接边。

### 5.2 上下文关系

| 上下文对象 | 方向 | 输入 / 输出面 | owner 与失效上限 |
|---|---|---|---|
| `L1-identity` | 输入 | GlobalMember 身份锚、生命周期和可运行性安全摘要 | 身份正文外置；不可验证时新受理 / 装配 fail closed。 |
| `L1-work` | 输入 | ProjectMember 执行主语、分配 / 回收来源和项目边界摘要 | Work truth 外置；输入出现不等于宿主已创建。 |
| `L2-member-images` | 输入 | pinned instantiable supply 与允许引用 | exact handoff 未闭口或 ref 不可验证时装配 blocked。 |
| `L4-sandbox` | 输入 / 输出 | 宿主级 binding / release 请求语境和允许反馈 | 本仓拥有装配关联，Sandbox 拥有 isolation / cleanup truth；positive blocked。 |
| 宿主承载 / 镜像 registry | 输入 / 输出 | 物理承载、生命周期动作和 pinned 资产获取能力 | 只经 adapter 参与；不可用时 blocked / degraded / unknown。 |
| `L2-member` | 输入 / 输出 | 请求、信号、报告；acceptance、registry、Host Session、health | 需求级 owner 分工成立；字段、IPC、credential context waiting。 |
| `L2-runtime` | 输入 / 输出 | Host Session、允许的运行关联和 execution handoff | entry surface blocked；本仓不创建或推进 run。 |
| `L0-core` | 输入 | 共享 ID、ref、metadata、error、trace、envelope 类别 | 专项 schema pending，不得本地 shadow。 |
| `L0-sdk` | 输入 | 受限 compile / Server 自测试基线 | exact target pending，不是宿主运行期 truth 上游。 |
| `L0-bus` | 输入 / 输出 | 上游变化材料与已提交宿主材料传播 | delivery 不归本仓；失败形成 local gap。 |
| `L4-observability` | 输出 | body-free 宿主、失败、清理与 handoff 材料 | observed truth、backend 和报告正文外置。 |

Method Library、Tools、Capability Hub、Artifact、Archive、Workspace 和产品入口不决定当前 C-MS-1~5 的 Host Truth，因此不进入关键上下文主链。未来只读消费或材料交接也不得反向定义本仓。

## 6. 限界上下文与子域划分

> 校准来源：
> - `design-calibration/01_arch_step_05_bounded_context_subdomains.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“划分取舍”“子域 / 上下文划分表”“统一语言”“逐项停审”和“跨上下文语义边界审计”小节。

五个核心子域分别承接 C-MS-1~5，三个支撑子域承接外部资格、宿主能力和安全消费，三个本地影子层只保存 snapshot / ref / projection。它们共同构成一个 Host Truth Center，不是五个仓、十一套 truth、十一项代码模块或十一项部署服务。

### 6.1 子域 / 上下文划分

### 8.1 内部依赖方向

```text
      +======================================================+
      |              L2-member-service dependency           |
      |   +----------------------------------------------+   |
      |   | external boundary intake                     |   |
```

| A1~A5 核心语义 | Core 类别与本仓稳定语义 | SDK runtime client、sibling 源码、外部产品模型 | Host Truth 保持技术中立。 |
| S1~S3 支撑语义 | 核心公开语义与正式外部能力端口 | 外部正文、核心覆盖、外部 truth 生成 | 只承接、映射或派生。 |

|---|---|---|---|
| `L0-core` | compile | 是 | 共享契约 authority；专项 schema pending，不本地 shadow。 |
| `L0-sdk` | limited compile / fake support | 受限 | exact target / Server 自测试 pending，不进入 A1~A5 runtime。 |
| `L1-identity` / `L1-work` | runtime + event + ref | 是 | 提供双锚与来源，L1 truth 不转移。 |
| `L2-member-images` | runtime + ref | 是，positive blocked | 需求级 supply 成立，exact handoff pending。 |
| `L2-member` | runtime + event / signal | 是，positive waiting | owner 分工成立，字段 / IPC / credential context pending。 |
| `L2-runtime` | runtime + ref | 是，positive blocked | Host Session / entry surface pending，run truth 外置。 |
| `L4-sandbox` | runtime + ref | 条件性是，positive blocked | required binding no-fallback；caller / receipt pending。 |

### 8.3 依赖类型与禁止转换

| 类型 | 允许对象 | 正式口径 | 禁止转换 |
|---|---|---|---|
| compile | Core；受限 SDK target | 只有二者可进入 package dependency 讨论 | 未闭口 schema、runtime client 或 sibling 不得进入。 |
| runtime | Identity、Work、Images、Member、Runtime、Sandbox | 通过正式 capability boundary | 不转成 sibling path / package dependency。 |
| event | Bus、上游变化、本仓材料、Observability | 传播已提交事实 / safe material | 不以事件到达推断决定或完成。 |
| ref | 全部外部 truth owner | typed ref + resolver / freshness | 不复制正文或取得 owner。 |
| adapter | 宿主承载、registry、Sandbox technical boundary | 吸收产品差异 | 产品状态不得进入领域语义。 |
| fake | runtime / event / adapter seam 的受控替身 | 验证本仓边界和失败语义 | 不证明真实 owner、合同、backend、route 或 readiness。 |

| 禁止依赖 | 原因 | 正确协作方式 |
|---|---|---|
| A1~A5 -> sibling 源码 / 私有模型 | 迁移外部 truth，破坏并行边界 | runtime / event / ref port。 |
| A1~A5 -> SDK runtime client / Server facade | SDK 不是 host core authority | Core contract + 正式边界；SDK 仅受限 compile / 自测试。 |
| A1~A5 -> DB / 消息 / 容器 / registry / Sandbox 产品 | 产品状态机反向定义宿主语义 | 内向端口 + 技术承载。 |
| 本仓 -> Method Library 直接解析 | 绕过 Images supply owner | 只消费 Images pinned supply。 |
| 本仓 -> ToolInvocation / Capability registry | 吞并逐动作执行和能力 truth | Runtime / Tools / Hub 正式边界。 |
| P1~P3 -> A1~A5 | snapshot / projection 成为第二写源 | 只读派生、显式 stale / gap / rebuild。 |
| fake -> production truth / readiness | 替身不能证明真实集成 | 标记 fake-qualified，等待真实 evidence。 |
| delivery / observed receipt -> local truth | 外围状态覆盖本地事实 | local truth 与 external outcome 分层。 |

### 9.2 数据边界图

```text
        +--------------------------+      +--------------------------+
        | external truth owners    |      | external raw bodies      |
        +------------+-------------+      | forbidden: no input edge |
                     |                    +--------------------------+
                     | typed ref / safe snapshot
                     v
        +------------+-------------+
        | P1 / P2 shadow boundary  |
        | stale / unknown explicit |
        +------------+-------------+
                     | qualified context
                     v
        +------------+-------------+
        | A1~A5 / S3 local truth   |
        +------------+-------------+
                     | read-only derivation
                     v
        +------------+-------------+
        | P3 safe projection       |
        +--------------------------+
```

- A1~A5 与 S3 承载本仓正式 truth，P1~P3 均不得反写。
- 外部 owner 只通过 typed ref / safe snapshot 进入，stale / unknown 必须显式。
- external raw body 没有输入连线，表示任何排障或审计诉求都不能例外吸收正文。
- 图不表达数据库、事务实现、缓存、同步任务、事件流或字段结构。

### 9.3 一致性策略

| 数据关系 / 场景 | 一致性口径 | 失败处理口径 | 保护目标 |
|---|---|---|---|
| 意图结论 -> 编排决定 -> 追溯 | 本仓内强一致 | 整体拒绝或保持未决定，不形成孤儿决定 | 决定可回指主语与来源。 |
| 当前宿主实例 -> 世代历史 | 本仓内强一致 + single-active fence | conflict / unknown 时不建立竞争当前实例 | restart 建新实例，不覆盖旧史。 |
| 分项装配 -> Host Readiness | 本仓结论强一致；外部来源时点一致 | missing / stale / conflict / unknown 均非 ready | partial 不覆盖整体缺口。 |
| registration -> endpoint -> Host Session | 本仓内强一致 + 活动唯一 | 重放稳定；冲突拒绝或挂起 | 防止第二活动关联。 |
| 来源信号 -> 健康结论 | 时点判断 + 顺序 / freshness | 迟到不覆盖；证据不足为 unknown | 原始信号不成为健康 truth。 |
| 恢复 / 终止决定 -> 实例世代 | 本仓内强一致 + generation fence | 结果 unknown 则 hold / reconciliation | 旧结果不污染新世代。 |
| 下线失效 -> local cleanup / residual | 本仓内强一致；外部完成最终一致 | 保留 gap / residual，不回滚终止 truth | attempt 不冒充 external completed。 |
| local truth -> safe view | 最终一致 | stale / unavailable，可重建 | 投影不阻塞或反写核心。 |
| local truth -> Bus / Observability / consumer | 最终一致 + local attempt 追溯 | 保留 gap，不声明 delivered / observed / accepted | 外部状态不参与本地原子性。 |
| local truth <-> backend / binding snapshot | 对账最终一致 | mismatch 形成 orphan / drift / unknown 和处置决定 | 不以删历史消除差异。 |
| duplicate / concurrent / late / out-of-order | 幂等 + 顺序 / 世代约束 | 稳定重放、拒绝冲突或追加关联事实 | 不盲重放不可逆副作用。 |
| ref -> external body | 边界约束一致 | unresolved / stale / blocked，不本地补正文 | 引用不转移 ownership。 |

本仓内强一致不表示与外部 owner 建立分布式事务。跨边界刷新、外部副作用、传播和观察必须保留 stale、partial、unknown、gap、residual、not delivered 或 not observed，直到正式 owner 结果可关联。

| 当前宿主安全查询 | 正式入口 -> A1~A5 / P3 | 返回当前 truth、safe view 与 stale / unknown | 查询只读，不隐式修复或触发变化。 |
| 外部资格按需解析 | A1 / A2 -> S1 | 为范围、装配和 readiness 获得可判定资格 | 只消费 ref / snapshot；contract pending 时 blocked。 |
| 上游正式变化承接 | Identity / Work 等 -> S1 / P1 | 更新 freshness 并形成重新判断输入 | 变化材料本身不直接改写 A1~A5。 |
| 宿主生命周期副作用推进 | A2 / A4 / A5 -> S2 | 推进承载、装配、恢复、终止和 cleanup 能力请求 | 本仓决定与外部完成分层，unknown 可对账。 |
| 外部能力结果回送 | S2 外部边界 -> A2 / A4 / A5 | 将 carrier / binding / release 允许结果纳入本地判断 | result contract pending，不吸收外部 truth。 |
| Member 注册受理 | Member -> A3 | 建立 / 替换 / 拒绝当前实例注册关联 | owner 分工成立；字段 / IPC / credential context waiting。 |
| Host Session 关联建立 | Runtime 边界 <-> A3 | 建立宿主与外部运行对象的关联壳 | Runtime surface blocked；不创建或推进 run。 |
| 宿主存活与状态信号承接 | Member / carrier / Sandbox -> A4 | 形成来源明确、可排序的健康判断输入 | 原始信号不等于健康或业务成功。 |
| 健康、恢复与对账推进 | A4 / A5 延后边界 | 评估 missing、unknown、fence、residual 和 drift | 阈值 / 调度后移，结论必须可追溯。 |
| 宿主事实与材料传播 | S3 -> Bus / Observability / consumer | 传播已提交 body-free fact 和 safe material | 只拥有 local attempt / gap，不声明外部完成。 |
| 投影刷新与 gap 复核 | S3 / P3 延后边界 | 重建 safe view 并复核交接缺口 | 投影与传播失败不反写真相。 |

### 10.2 通信方式判断

| 交互场景 | 推荐方式 | 不宜方式 | 失败处理口径 |
|---|---|---|---|
| 宿主意图与控制受理 | 同步请求 / 响应类 | 异步接受替代即时范围判断 | rejected / waiting / conflict / unknown；不隐式动作。 |
| 当前宿主安全查询 | 同步请求 / 响应类 | 临时事件回放拼当前值 | safe / stale / unavailable / unknown。 |
| 外部资格按需解析 | 同步请求 / 响应类 | 默认使用旧 snapshot 后先放行 | unresolved / stale / blocked。 |
| 上游正式变化承接 | 异步事件 / 回调类 | 把所有来源变化绑入同步入口 | 未消费 / stale，等待正式承接。 |
| 宿主生命周期副作用推进 | 后台 / 延后承接类 | 同步入口宣称外部动作完成 | pending / partial / timeout / unknown，进入对账。 |
| 外部能力结果回送 | 异步事件 / 回调类 | 跨 owner 长事务或猜测完成 | 未送达保持 unknown / gap；具体合同 pending。 |
| Member 注册受理 | 同步请求 / 响应类 | 先成功再后台验证实例 | rejected / blocked / conflict。 |
| Host Session 关联建立 | 同步请求 / 响应类 placeholder | 事件到达即推断关联建立 | contract blocked，不伪造 session。 |
| 宿主存活与状态信号承接 | 异步事件 / 回调类 | 等待本仓健康判断完成 | late / duplicate / stale / conflict 显式。 |
| 健康、恢复与对账推进 | 后台 / 延后承接类 | 每个信号同步触发不可逆恢复 | hold / unknown / reconciliation。 |
| 宿主事实与材料传播 | 异步事件 / 回调类 | receipt 纳入本地提交成功 | local gap / not delivered / not observed。 |
| 投影刷新与 gap 复核 | 后台 / 延后承接类 | 阻塞核心写路径或让投影成为写源 | stale / unavailable / rebuild pending。 |

本章不画时序图：同一生命周期可能跨同步接受、后台推进和异步结果三个边界，单线图会被误读为正式运行顺序或正向合同已闭口。具体 API、event family、callback、source、route、receipt、载荷与处理流留给后续合同设计。

## 11. 关键技术选型

> 校准来源：
> - `design-calibration/01_arch_step_10_technology_choices.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“关键技术机制”“机制状态与开放合同”“当前不采用口径”和“Gate 自检”小节。

本章的“技术”只指持续约束边界、数据和失败语义的机制，不指产品栈。

| 技术机制 | 解决的问题 | 采用理由 | 代价 / 约束 |
|---|---|---|---|
| 独立 Host Truth Center | 宿主决定 / 生命周期散落到外部 owner | 上游从多侧排除 host lifecycle，本仓需要 single writer | 维护完整历史和边界解释。 |
| Ports and Adapters | sibling 与基础设施实现侵入核心 | 非 Core 关系均为 runtime / event / ref / adapter | 增加端口、映射和 qualification 成本。 |
| Typed Ref + Safe Snapshot + Freshness | 外部正文复制和旧数据隐式放行 | 核心需要可追溯时点上下文但不能拥有源 truth | 需要 resolver、stale / unknown 和刷新语义。 |
| Fail-closed Qualification | partial / unknown / pending 冒充 ready | required 主语、supply、credential、binding、carrier 缺一不可 | 依赖故障时降低可用性，必须显式 blocked。 |
| Immutable Generation + Single-active Fence | restart 覆盖历史、迟到反馈和竞争当前宿主 | A2~A5 需要稳定实例锚与世代顺序 | 增加 generation、fence 和 reconciliation 复杂度。 |
| Local Transaction + External Eventual Consistency | 跨 owner 伪原子和外围失败回滚 truth | 本仓只能保证自己的提交 | 需要 gap、stale、residual 与对账。 |
| Idempotent Command / Feedback Correlation | duplicate / concurrent / late / unknown 导致重复副作用 | 宿主动作跨长时边界 | 需要稳定相关锚、重复判定与冲突处理。 |
| Sync / Async / Background Separation | 同步伪完成或全事件化失去即时拒绝 | 三类交互具有不同收口语义 | 增加运行角色与跨边界追踪。 |
| Read-only Rebuildable Projection | consumer 绑定核心或查询反写 | P3 提供安全消费面 | 接受延迟、stale、rebuild 和额外承载。 |
| Body-free Handoff + Outcome Layering | 敏感正文泄漏及 attempt 冒充外部完成 | 本仓只对 local material / attempt / gap 负责 | consumer 必须理解多层状态。 |

| 机制范围 | 当前状态 | 不得误读为 |
|---|---|---|
| 上述十项架构机制 | `architecture_selected` | 已实现、已测试或已 ready。 |
| Member / Runtime / Images / Sandbox / credential / Core / SDK 具体端口 | `contract_placeholder / pending` | 字段、协议、适配或真实集成已经存在。 |
| 语言、框架、存储、消息、RPC、容器平台和部署产品 | `deferred` | 架构缺失；它们是后续受机制约束的实现选择。 |

共享数据库 / 外部正文复制、直接 sibling 源码依赖、backend state 驱动 Host Truth、跨 owner 分布式事务、全同步生命周期链、全事件化入口、本地 allowlist / host fallback 和 fake 充当真实资格均不采用。

## 12. 备选方案与取舍

> 校准来源：
> - `design-calibration/01_arch_step_11_alternatives_tradeoffs.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“当前主线方案”“方案路径比较”“当前取舍结论”和“Gate 自检”小节。

| 方案路径 | 主要收益 | 主要代价 / 约束 | 当前结论 | 说明 |
|---|---|---|---|---|
| 显式决定驱动的独立 Host Truth Center + 分层生命周期 + ports / background / reconciliation | 决定可追溯；状态不压平；unknown / gap 可归责；pending 可 fail closed；后端可替换 | 语义和状态较多，需要 fence、幂等、端口、后台推进和对账 | 采用 | 完整承接 C-MS-1~5 与 HC-MS-001~009。 |
| 单一宿主生命周期上下文 / 统一状态模型 | 初期对象少、查询直接、事务边界简单 | readiness、registration、health、cleanup 和 external completion 易压平 | 不采用 | 无法保护五节点的不同 owner、失败和变化频率。 |
| 全事件编舞的 Host Truth Center | 写入路径松耦合，长时过程天然异步 | 即时主语 / 冲突 / 注册判断变弱，事件易被误解为决定或完成 | 不采用 | 事件适合变化 / 结果传播，不适合作为全部权威入口。 |
| 持续期望态控制 + reconciliation 主导 | 对 drift、orphan 与规模调度有优势 | 逐次决定可能被 desired state 覆盖，observed / backend 易反向统治 truth | 不采用为当前主线 | reconciliation 保留在 A5，不能替代 A1 和 A2~A4 事实链。 |

| 当前方案得到 | 当前方案承担 |
|---|---|
| 唯一 Host Truth owner 与清晰外部边界 | 更多显式状态和边界适配成本。 |
| 意图、决定、实例世代和结果可追溯 | generation fence、幂等与历史维护成本。 |
| 同步接受、后台推进、异步反馈分离 | 跨路径追踪和 unknown / gap 展示成本。 |
| 外部合同 pending 时仍可 fail closed | 合同闭口前正向能力持续 blocked。 |
| 后端和协议可替换 | 端口、adapter、qualification 和 fake 维护成本。 |
| 本地 truth 不被 delivery / observed 反写 | reconciliation、投影重建和外围状态解释成本。 |

把宿主生命周期并入 Work / Identity / Member / Runtime / Sandbox / backend，或采用共享数据库、直接 sibling dependency、host fallback，已违反不可变边界，不构成有效备选。产品横评以及 policy、非项目型、warm pool、容量调度和 forensic backend 也不属于当前路径比较。

### 13.1 横切关注点

| 类别 | 作用范围 | 架构约束 | 判断口径 | 保护目标 |
|---|---|---|---|---|
| 主语、授权与控制安全 | A1、A4、A5、正式入口 | 每次变化有 principal / source / scope；项目型双锚；高影响动作显式决定 | 无正式主语 / 授权 / 依据即 rejected / waiting / blocked | 防止越权、隐式和非项目型宿主。 |
| Qualification 与 fail closed | A1、A2、S1、S2 | required source / supply / credential / binding / carrier 缺一不可 | missing / stale / conflict / unknown / pending 均非 ready | 防止默认放行和 host fallback。 |
| 数据最小化与 forbidden body | 全部单元，重点 P1~P3 / S3 | 只保留 typed ref、safe snapshot、redacted marker、body-free material | secret / external body 进入 truth / view / material 即违反 | 防止敏感泄漏和 owner 迁移。 |
| 审计与追溯 | A1~A5、S3 | 决定、世代、变化、attempt 和 gap 可回链且历史不覆盖 | 关键结论不能回指 source / instance / prior fact 即不合格 | 支撑调查、恢复和责任归属。 |
| 幂等、顺序与并发 | A1~A5、正式入口、S2 | single-active、稳定相关锚、generation fence、迟到不覆盖 | duplicate / concurrent / late / out-of-order 不产生第二 truth 或盲重放 | 防止竞争宿主、session 和重复副作用。 |
| 可用性与韧性 | 三运行角色、状态承载、S1~S3 | 核心 truth 优先；source / backend 故障显式；外围失败隔离 | 无法提交则拒绝；外部失败为 blocked / degraded / unknown / gap | 不生成不可追溯状态，不 fail open。 |
| 可观测与本地可诊断 | A1~A5、S3、运行角色 | 输出最小 body-free material；本地判断不依赖 observed | Observability 不可用仍能定位 local state / gap 且不声明 observed | 保持诊断能力并守住外部 owner。 |
| 性能与容量结构 | 同步入口、后台推进、信号 / 维护、投影 | 同步轻量；长时与派生分离；角色可独立扩缩 | 指标必须有 workload、环境、口径与证据；当前无伪数字 | 防止长时副作用拖垮入口。 |
| 配置与变更控制 | 全部单元及 adapter | 配置只改可调参数，不改 owner、红线、状态语义或 pending | 配置不能扩范围、绕过 qualification、改写 truth 或伪造 ready | 防止配置暗改架构。 |
| 合同兼容与开放边界 | S1~S3、A3、技术承载 | version / capability 不识别时 unsupported / blocked；placeholder 不冒充兼容 | 未闭口 Member / Runtime / Images / Sandbox / Core / SDK 无正向声明 | 防止 schema drift 与 sibling WIP 升格。 |
| 投影与外围消费隔离 | P3、S3 | 只读、可迟滞、可重建；external receipt 不反写 | view stale / unavailable 不改变 A1~A5；delivery / observed 独立 | 防止消费便利成为第二写源。 |

### 13.2 架构单元适用性

| 单元 | 重点横切项 | 单元级判断口径 |
|---|---|---|
| A1 | 主语 / 授权、审计、幂等、配置 | 无双锚和正式 source 不受理；重复决定稳定；查询不触发变化。 |
| A2 | qualification、最小化、审计、并发、韧性、兼容 | required 前置共同成立；partial / pending 非 ready；实例世代唯一。 |
| A3 | 安全、审计、single-active、兼容 | 注册来源可信；endpoint / session 活动唯一；pending 不伪造。 |
| A4 | 控制安全、审计、顺序、韧性、诊断、配置 | signal freshness 与 generation 明确；unknown 不盲恢复；阈值不硬编码。 |
| A5 | 控制安全、审计、幂等、韧性、诊断 | local cleanup / gap / residual 分层；对账不删历史；不冒认外部完成。 |
| S1 | qualification、最小化、兼容、配置 | 只消费 ref / safe snapshot；unresolved / stale fail closed。 |
| S2 | qualification、幂等、韧性、兼容、配置 | adapter 不泄漏产品语义；unknown 副作用 fenced；no fallback。 |

| P1 | 最小化、freshness、配置 | snapshot 有 owner / scope / captured-at 语义；不反写。 |
| P2 | 最小化、顺序、对账 | ref / summary 可失效；迟到 / 冲突显式；不保存正文。 |

## 14. 演进路线

> 校准来源：
> - `design-calibration/01_arch_step_13_evolution_path.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“演进阶段”“可接受 / 不可接受设计债务”“演进触发条件”和“Gate 自检”小节。

### 14.1 结构演进阶段

| 阶段 | 架构目标 | 进入条件 | 结构变化 | 明确不代表 |
|---|---|---|---|---|
| `E0` 当前架构基线 | 固定 Host Truth、上下文、依赖、数据、交互、机制和风险上限 | 正式 00 获批；Step 1~16 静态审计完成 | 正式 01 与完整 calibration chain | 实现、测试、artifact、evidence、signoff 或 readiness。 |
| `E1` 正向合同闭口 | 用正式双侧合同替换 placeholder，同时保持 owner 与 fail-closed | owner 正式文档停审；field / semantic / failure / compatibility 可追溯 | 回校验 Core / SDK、Member、Images、Runtime、Sandbox、credential、backend / receipt 边界 | 合同存在即真实集成通过。 |
| `E2` 最小项目型宿主闭环 | 使 C-MS-1~5 在真实 owner / adapter 上具备可验证正向路径 | E1 相关合同闭口；02~07 完成；真实实现和测试 authority 存在 | 最小 intent -> closure 路径、真实失败语义和证据诚实 | 所有 backend、规模、SLA 或非项目范围 ready。 |
| `E3` 韧性与规模增强 | 基于实证增强扩缩、reconciliation、容量、投影和运维边界 | workload、drift、故障隔离或消费压力达到正式触发条件 | 运行角色按需物理拆分、持续对账增强、capacity guard / safe view 扩展 | owner、五核心语义或 local-first 被替换。 |
| `E4` 条件性范围扩展 | 在新 authority 下评估 policy、非项目主语和外围增强 | 正式需求 / owner / ADR 触发并重开受影响 Step | 新主语或支撑上下文按重新校准结果进入 | 当前架构已经承诺这些能力。 |

### 14.2 设计债务边界

| 可接受债务 | 保护条件 | 关闭入口 |
|---|---|---|
| MSVC-UP-001~008 exact contract / schema / route / qualification pending | 受影响路径 blocked / waiting，不声明 ready | E1 对应 owner 正式合同。 |
| 产品、协议、storage 和部署拓扑 deferred | 不推翻 ports、owner、数据和交互机制 | 02~04 / 07 正式门禁。 |
| 三运行角色逻辑分离但可同部署 | failure 与 scale boundary 保持独立 | E3 workload / fault evidence。 |
| 性能、容量、健康窗口未量化 | 不使用旧数字，不宣告性能通过 | 04~06 的正式指标与证据。 |
| 外围增强未进入核心 | 不成为 C-MS-1~5 前置或写源 | E3 / E4 正式触发。 |

| 不可接受债务 | 为什么不可接受 | 当前处置 |
|---|---|---|
| 多 Host Truth owner / backend-driven truth | 造成状态分叉和责任不明 | 立即阻塞并回退 A1~A5 owner 边界。 |
| 无双锚或 qualification 缺失仍启动 | 打穿项目和隔离边界 | fail closed，不允许配置 / fallback 放行。 |
| 外部 truth / forbidden body 入仓 | 迁移 ownership 并泄漏敏感内容 | 禁止保存、输出和证据化。 |
| sibling compile dependency / shared storage | 破坏裁剪和独立演进 | 改为 runtime / event / ref / adapter。 |
| 活动关联分叉、历史覆盖或盲重放 | 破坏生命周期 truth 和不可逆动作安全 | single-active、generation fence、幂等和对账。 |
| attempt / fake / receipt 冒充完成 | 伪造集成、观测、验收或 readiness | 保持 outcome 和 evidence 状态分层。 |
| 单一状态压平五核心语义 | 丢失 owner、失败和变化边界 | 维持 A1~A5 独立语义。 |

E1~E4 均是满足进入条件后的结构演进，不是已排期、已承诺或已完成事项。正式 owner 合同、真实 workload 或范围变化是复核触发条件，不能借机改变 Host Truth owner、五核心语义或 fail-closed 红线。

| 未建立 | 同步权威接受、后台副作用推进和异步结果反馈三类交互分离 | 防止全同步伪完成或全事件化丢失即时拒绝与冲突判断 | 部署承载 / 关键交互 / 技术机制 | 决定运行职责和完成语义，不等于固定进程拓扑。 |
| 未建立 | safe projection 只读可重建，handoff 采用 body-free material 与 local / external outcome 分层 | 防止消费面成为第二写源以及 attempt 冒充 delivered / observed / accepted | 数据 / S3-P3 / 可观测 / 验收 | 长期保护消费隔离、数据最小化和证据诚实。 |

`ADR-0007` 的 checkpoint persistence 决定属于 Runtime / Process truth 边界，只用于证明 checkpoint 不归本仓，不进入本项目 ADR 索引。未来若建立上述九项专项 ADR，必须经过独立评审并回链本章；本章当前状态不得被反向解释为 ADR 已创建或已接受。

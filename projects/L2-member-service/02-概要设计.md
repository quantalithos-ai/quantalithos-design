## 3. 约束条件

> 校准来源：
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“结构性约束条件表”“约束到后续章节的影响矩阵”和“正式第 3 章回填草稿”小节。

| 约束 | 说明 |
|---|---|
| 项目型双锚不可替代 | `ProjectMemberRef` 是执行主语，`GlobalMemberRef` 是一致身份锚；其他主语 fail closed。 |
| Host Truth 单一写源 | 本仓拥有宿主意图、决定、实例、装配、注册、会话、健康、收束和本地交接事实；相邻 owner 不成为第二写源。 |
| 四个语义层不合并 | control plane、Host Truth、Runtime Session 和 execution handoff 保持可区分；`HostSession` 不扩成 Runtime run。 |
| required qualification fail closed | subject、identity、supply、credential、binding、carrier 任一 missing / stale / conflict / unknown / pending，均不得推导 `ready`。 |
| 外部 truth 最小化 | 只允许 typed ref、safe snapshot、freshness、redacted marker、body-free material 和匹配的 safe outcome；secret / external body 禁止入仓。 |
| generation immutable 与 single-active | replacement 形成新 generation；旧 generation 不覆盖 current，不产生第二活动 host / registration / session。 |
| local-first 与 outcome layering | local decision / attempt / gap / submitted 先提交；external completion、delivery、observation、acceptance 由各 owner 分层反馈。 |
| 入口权限固定 | Command 写 owner truth；Query 只读；Consumer 只写允许的 snapshot / matching feedback；Job 只推进已提交 work。 |
| projection / material / history 不反写 source | 派生视图、材料、历史、outbox 和对账记录不成为第二领域写源。 |
| seam 类型不可转换 | compile、runtime、event、ref、adapter、fake seam 各自保持语义；兄弟仓不成为源码、共享数据库或隐式 SDK 依赖。 |
| 宿主不拥有外部执行 truth | 不解析 Role -> image，不提交逐动作 ToolInvocation，不推进 Sandbox execute，不拥有 Runtime / Member / Images / Sandbox truth。 |
| 历史和 blocker 必须诚实 | 事实以 append-only / supersede 表达；placeholder、fake、局部 receipt、observed signal 不等于 ready；`MSVC-UP-001~008` 持续显式。 |
| 产品、数字和配置不改语义 | 产品和参数只能影响 adapter、运行装配、刷新节奏或降级，不改变 owner、状态、no-fallback、审计或安全门禁。 |

关键说明：

- 图只表达主体映射，不表达文件路径、完整类型、协议、数据库、产品或部署拓扑。

#### 实现分层视图

```text
External command / query / registration / signal / feedback / job
                              |
                              v
Inbound / Operations
  command + query entries | consumers | maintenance jobs
                              |
                              v
Application Services
  intent | qualification | assembly | progression | session
  health | recovery | closure | reconciliation | material | read
                              |
                              v
Domain Model / Policies
  Host Truth objects | state axes | decisions | guards | history
                 +--------------------+
                 |                    |
                 v                    v
Application Ports              Persistence / Projection / Outbox
  resolver | carrier |          truth | history | idempotency
  session | handoff | clock     safe view | projection | publication
                 |                    |
                 +---------+----------+
                           v
Adapters / Runtime Wiring
  runtime / event / ref / adapter / fake bindings
```

关键说明：
- 依赖方向向内；Domain 不依赖外部产品，Application 通过本仓声明的 Port 协作。
- Persistence / Projection / Outbox 是技术承载角色，不是第八个业务组成部分。
- 同步入口、异步 Consumer 和 Operations Job 可以同部署，但写权限和完成语义独立。

| 项 | 说明 |
|---|---|
| 业务主要组成部分 | 回答 Host Truth 生命周期的哪段业务责任由谁承担。 |
| 实现分层 | 回答这些主体在代码依赖中如何安放。 |
| 二者关系 | 一个业务组成部分横跨多个实现层，一个实现层也承载多个业务组成部分；两者不能混用。 |
| 共享机制 | correlation、generation、idempotency、history、outbox、projection 和 UoW 横切多个部分，但不成为独立业务 truth owner。 |

## 7. API / 接口骨架

> 校准来源：
> - `design-calibration/02_hld_step_07_interface_skeleton.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“接口分类与统一判断”“IB-MS-001~017 覆盖索引”“Application Port / Persistence Port seam 矩阵”和“跨接口一致性审计”小节。

### 7.1 接口分类说明

| 类别 | 语义 | 写入 / 完成边界 |
|---|---|---|
| Command API | 由正式 actor 或已授权内部语境显式调用，改写本仓 truth | 必须带 `ActorContext`、`CommandMetadata` 和稳定幂等身份；不宣称 external completion |
| Query API | 读取 source truth、history 或 `SafeHostView` | 必须带 `ActorContext`；不 refresh、repair、publish 或创建决定 |
| Inbound Event Consumer | 消费外部 safe change / signal / feedback | 保留 message identity、source、correlation、generation；只写允许的 snapshot / matching record |
| Outbound Event | 传播本仓已提交 material | 从 material / outbox 产生；local submitted 不等于 delivered / observed / accepted |
| Operations Job | 扫描并推进已持久化 attempt、outbox、projection 或 reconciliation work | 不创建 formal intent / decision，不把 schedule 解释为授权 |
| Application / Persistence Port | 本仓声明、外部 adapter 或本地 infrastructure 实现的协作边界 | 依赖类型保持 compile / runtime / event / ref / adapter / fake 分类 |

| API | IB | 归属 | 输入骨架 | 输出骨架 | 写入结果与边界 |
|---|---|---|---|---|---|

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“通用本地写路径”“接口 / 处理流覆盖清单”和 CMP-MS-01~07 的关键处理流与停审记录小节。

### 8.1 通用处理流骨架

#### 通用本地写路径

```text
Command / explicit local decision
  |
  v
Inbound Entry / Application Service
  - map ActorContext, CommandMetadata, stable key, subject and correlation
  - load owner facts and expected revision
  |
  v
Domain Object / Policy / Guard
  - validate scope, generation, idempotency and local invariant
  - form truth, decision, attempt or closure fact
  |
  v
Local Persistence + History / Material Marker
  - commit owner truth and append-only history
  - enqueue outbox marker only for committed change
  |
  v
Local Result
  - return ref + local status + conflict / waiting / gap if any
  - external action, delivery and observation remain separate
```

关键说明：
- 图只表达本地强一致写入与外部副作用的相对位置，不表达数据库或 UoW 实现。
- 跨 owner side effect 必须在 local attempt / outbox 提交后经 Port / Job / Consumer 处理。
- local committed、external completed、delivered、observed、accepted 不由一条写路径压平。

#### 通用只读路径

```text
Query + ActorContext + visibility / freshness request
  |
  v
Query Entry / Read Application Service
  - authorize at boundary and select source / projection
  - never create command, refresh or repair
  |
  v
Source Truth / Safe Projection / Append-only History
  - read owner facts and projection freshness
  - apply safe-field and visibility slicing
  |
  v
Safe View / History Result
  - include stale / degraded / unavailable / unknown markers
  - omit forbidden body and external raw state
```

关键说明：
- Query 不写入、不调用 resolver、不修复 projection、不创建 lifecycle action。
- projection stale 可显式返回 stale / degraded / unavailable；不能用默认值伪装 fresh。
- 具体分页、缓存和授权实现留给 03。

#### 通用外部事实消费路径

```text
Inbound Event / Feedback Envelope Placeholder
  |
  v
Consumer Entry
  - validate message identity, source, idempotency and generation
  - classify duplicate / late / stale / conflict / unknown
  |
  v
Snapshot / Attempt / Association / Handoff Record
  - append safe summary or matching local outcome
  - preserve source ref and captured time
  |
  v
Local Fact / Gap / Re-evaluation Marker
  - update only the owning local record
  - do not implicitly create formal command or external action
```

#### 通用运维任务路径

```text
Operations Job
  |
  v
Due persisted work selector
  - load attempt / outbox / projection / case
  - recheck stable key, revision and generation
  |
  v
Port / Projection / Reconciliation boundary
  - perform only the owned maintenance action
  - classify safe result / unknown / gap
  |
  v
Updated local work record
  - append history or marker
  - never create hidden lifecycle decision
```

### 8.2 处理流覆盖清单

| 接口 / Job | 独立流 | 原因 |
|---|---|---|
| `AcceptHostIntentCommand` | 是 | P0 Command，拥有意图受理和双锚 guard。 |
| `DecideHostOrchestrationCommand` | 是 | P0 Command，形成唯一宿主控制决定。 |
| `ResolveHostQualificationCommand` | 是 | P0 Command，收束 required source 和 freshness。 |
| `CoordinateHostAssemblyCommand` | 是 | P0 Command，冻结 required item 并形成 readiness。 |
| `EstablishHostGenerationCommand` / `PrepareHostActionCommand` | 是 | 内部 P0 use case，建立 generation 和 local attempt。 |
| `DispatchPendingHostActionsJob` / `HostActionOutcomeConsumerPlaceholder` | 是 | 影响外部副作用和 matching outcome。 |
| `AcceptHostRegistrationCommandPlaceholder` / `MaintainHostSessionCommandPlaceholder` | 是 | P0 Command，维护 registration / session 唯一性。 |
| `HostHealthSignalConsumerPlaceholder` / `EvaluateDueHostHealthJob` | 是 | 改写 signal / assessment local state。 |
| `DecideHostRecoveryCommand` | 是 | P0 Command，显式拥有 recovery decision。 |
| `CloseHostCommand` / `ProgressPendingHostCleanupJob` / cleanup feedback | 是 | 改写 closure / cleanup / residual 层。 |
| `ReconcileHostResidualsJob` | 是 | 影响 reconciliation consistency。 |
| `HostFactMaterialEventCandidate` / `PublishHostFactOutboxJob` / handoff feedback | 是 | 影响 publication / handoff reliability。 |

### 9.1 状态模型总原则

本仓不存在可替代所有语义的单一 `HostStatus`。acceptance、qualification、assembly、readiness、host lifecycle、registration、endpoint、session、health、failure、recovery、closure、cleanup、residual、handoff、outbox 和 projection 分别由其 owner 对象承载。

#### 状态轴依赖图

```text

      v

      |
      v

      |
      v

      |
      v
health / failure / recovery decision
      |
      v
closure / cleanup / finding / reconciliation
      |
      v
material / outbox / handoff / projection
```

关键说明：
- `ready`、`active`、`healthy`、`locally-closed`、`submitted`、`delivered`、`observed`、`accepted` 各有独立 owner，不相互替代。
- `stale`、`blocked`、`waiting`、`unknown`、`gap`、`residual` 和 `degraded` 是可审计的不确定性或边界语义，不是默认成功。

### 9.6 CMP-MS-07 状态流转与传播

| 状态轴 | 允许的核心迁移 | 禁止的核心迁移 |
|---|---|---|
| `HostHandoffRecord` | pending -> attempted -> feedback-linked / gap -> closed / unknown | submitted 直接 delivered / accepted；反馈覆盖 source |
| `HostProjectionState` | fresh -> stale -> rebuilding -> fresh / degraded / unavailable | Query 直接标 fresh；projection 反写 source |
| `HostOutboxRecord` | pending -> attempted -> submitted / gap / unknown -> closed | publisher ack 直接 observed / accepted；换 key 掩盖 unknown |
| `HostFactMaterial` | committed immutable material 通过新 material supersede | 原地编辑、由 projection / external body 反推 |
| `SafeHostView` | 从 source / projection 形成 immutable safe view，freshness 显式返回 | Query refresh / repair；返回 forbidden body |
| `HostHistoryEntry` | append 新条目、通过 prior / supersedes 纠正 | 原地修改或删除历史 |

#### 状态传播关系图

```text
Committed owner truth
  |
  +--> HostHistoryEntry
  +--> HostFactMaterial
  +--> HostOutboxRecord / HostHandoffRecord
  +--> HostProjectionState -> SafeHostView
  |
  +--> external port / Consumer feedback
          |
          +--> matching attempt / association / assessment / closure layer
          +--> gap / unknown / residual / reconciliation marker
```

关键说明：
- 传播是从 committed source 向 history、material、outbox、handoff 和 projection 的单向派生。
- feedback 只更新匹配的 local record，不回滚 source、不把局部 receipt升格为 accepted。
- projection、material、history 和 handoff 不成为第二写源。

### 9.7 状态一致性门禁

- Query 不写入；Consumer 不隐式创建 formal lifecycle decision；Job 不隐式创建 lifecycle action。
- `ready` 只来自同一 generation 的 required qualification + assembly；`healthy` 只来自 `HostHealthAssessment`；`active` 只来自 host / association / session 各自 owner。
- `locally-closed`、`succeeded`、`submitted`、`delivered`、`observed` 和 `accepted` 必须保留各自层级。
- `MSVC-UP-001~008` 和 sibling exact contract 未闭口时，相关正向状态只能 pending / blocked / waiting / unknown。

## 10. 异常与边界场景轮廓

> 校准来源：
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“统一异常处置语义”“异常与边界场景总表”“按主要组成部分的异常落点”和“异常影响图”小节。

概要层统一使用以下语义：`rejected` 表示输入不能进入主线；`conflict` 表示锚、scope、generation 或 revision 矛盾；`waiting` 表示等待新正式事实；`blocked` 表示必需 owner / 合同 / 资格缺失；`stale / late` 表示不能覆盖 current；`unknown` 表示外部 effect 或反馈不可判定；`gap` 表示传播 / 合同 / 投影缺口；`residual` 表示本地收束后的外部差异。

| ID | 场景 | 应落在哪个部分处理 | 当前概要口径 |
|---|---|---|---|
| `EX-MS-001` | 非项目型主语、缺少 `ProjectMemberRef` 或双锚不一致 | CMP-MS-01 intent acceptance | `rejected` / `conflict`；不创建 host 或 decision。 |
| `EX-MS-002` | 相同 intent / decision key 重放或同锚异意图 | CMP-MS-01 intent / decision | 等价重放返回既有结论；异意图追加 conflict，不生成第二 truth。 |
| `EX-MS-003` | current host / closure / policy revision 竞争 | CMP-MS-01 decision service | expected revision guard 拒绝过期提交，保留 conflict / superseded history。 |
| `EX-MS-004` | subject、identity、supply、credential、binding 或 carrier 缺失 / stale / conflict / unknown | CMP-MS-02 qualification / assembly | context 记录缺口；assembly blocked / unknown；readiness 非 ready。 |
| `EX-MS-005` | Images pinned ref、manifest 或 provenance 无法验证 | CMP-MS-02 qualification seam | 只消费 typed pinned ref；不可验证即 blocked，不解析 Role -> image。 |
| `EX-MS-006` | credential 缺失、撤销、过期、scope 不匹配或无法证明 instance binding | CMP-MS-02 / 04 | 不保存 secret；qualification / registration blocked / rejected / unknown。 |
| `EX-MS-007` | SandboxBinding bind / release 合同缺失、冲突或未知 | CMP-MS-02 / 06 | required binding 不闭合即 blocked；release unknown 转 cleanup unknown / residual。 |
| `EX-MS-008` | carrier / container / orchestration adapter 不可用或能力不匹配 | CMP-MS-02 / 03 | neutral adapter result；能力缺失 blocked / failed，未知效果 unknown。 |
| `EX-MS-009` | generation 建立或 replacement 与 active generation 并发 | CMP-MS-03 generation fence | single-active 只保留一个 current；竞争者 held / conflict，replacement 建新 generation。 |
| `EX-MS-010` | external action 已越过 port 但 response 丢失或 effect unknown | CMP-MS-03 attempt / association | 保持 dispatched / unknown 和原 effect key；不盲重放。 |
| `EX-MS-011` | old generation action outcome 或 signal 迟到 | CMP-MS-03 Consumer / fence | 记为 late / stale / rejected，最多进入旧记录 / history，不覆盖 current。 |
| `EX-MS-012` | registration 重放、来源冒用、credential mismatch 或 generation mismatch | CMP-MS-04 registration | rejected / invalidated；endpoint / heartbeat 不能直接 accepted。 |
| `EX-MS-013` | 两个 endpoint / session 同时声称 current | CMP-MS-04 session policy | single-active guard 选择有正式依据的 current，其余 replaced / stale / invalid / conflict。 |
| `EX-MS-014` | heartbeat / health signal 重复、迟到、stale、冲突或来源缺失 | CMP-MS-05 signal Consumer | 只形成 snapshot 分类；不直接写 healthy / recovery / Runtime state。 |
| `EX-MS-015` | health basis 不完整、四轴冲突或 Observability 不可用 | CMP-MS-05 assessment | 保留 uncertainty / degraded / unknown；可形成 hold，不破坏本地 Host Truth。 |
| `EX-MS-016` | recovery / restart / terminate 与新 signal、closure 或 replacement 竞争 | CMP-MS-05 recovery + CMP-MS-03 / 06 | 仅 committed recovery decision 可下游；竞争决定 superseded / voided。 |
| `EX-MS-017` | closure 期间仍有 in-flight action、active session 或未确认 association | CMP-MS-06 closure | 先 invalidating，cleanup-pending / blocked / unknown；不宣称 external cleanup complete。 |
| `EX-MS-018` | cleanup / release unknown、失败或 route / owner 缺口 | CMP-MS-06 cleanup / finding / case | attempt unknown / failed / gap；形成 residual / case，不自动删除或重放。 |
| `EX-MS-019` | residual 摘要冲突、owner 不明或 reconciliation 无 resolution basis | CMP-MS-06 finding / case | finding disputed / unknown，case holding / escalated；Job 不隐式 action。 |
| `EX-MS-020` | committed material 已形成但 outbox route、schema、publisher 或目标不可用 | CMP-MS-07 material / outbox | source、history、material 仍提交；outbox gap / pending，handoff 不宣称 delivered。 |
| `EX-MS-021` | publication effect unknown 或 publisher receipt 重复 / 不可验证 | CMP-MS-07 outbox / handoff | 保持 publication key 与 unknown / attempted；不换 key 盲重发。 |
| `EX-MS-022` | handoff feedback 迟到、重复、目标或 generation 不匹配 | CMP-MS-07 handoff Consumer | 只更新匹配 handoff 的 feedback layer，标记 gap / unknown / late。 |
| `EX-MS-023` | projection cursor 落后、change gap、rebuild 失败或 store 不可用 | CMP-MS-07 projection / Query | projection stale / rebuilding / degraded / unavailable；Query 明示不可用，不改 source。 |
| `EX-MS-024` | Query freshness / visibility 超出安全范围 | CMP-MS-07 safe Query | 返回 safe slice + stale / unavailable / forbidden marker 或拒绝；不补默认值。 |
| `EX-MS-025` | Consumer / Job 收到 forbidden body、secret 或未授权正文 | entry guard、material / history boundary | 拒绝或裁剪为 safe summary；正文不进入 truth、projection、event、log 或 history。 |
| `EX-MS-026` | Runtime、Member、Images、Sandbox 或 Bus 合同仍讨论，单侧出现 ready 草稿 | 对应 host-side port / handoff seam | 只记录 pending / blocked / waiting / placeholder；sibling WIP、fake、receipt 不关闭 blocker。 |
| `EX-MS-027` | local persistence / history / outbox 提交冲突或部分提交 | 各 owner local transaction boundary | 未 committed 不越过 external port；已 committed source 不因 outbox / projection 失败回滚。 |
| `EX-MS-028` | 时钟、freshness 或顺序依据不足 | qualification / health / handoff / projection | 以 stale / unknown / waiting 处理，保留时间缺口；不以本地接收时间伪造 current。 |

详细错误码、重试次数、quarantine、dead-letter、补偿脚本、数据库异常和运维步骤留给 `03-详细设计.md` 及后续测试 / 验收文档；本章只固定边界和落点。

## 11. 配置影响轮廓

> 校准来源：
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读：
> - 建议继续阅读该文件的“配置影响轮廓表”“只能间接受配置影响的模块”“禁止配置化边界表”和“配置实现承接”小节。

配置只影响运行装配、入口限制、Consumer / Job 节奏、adapter / store / projection / publisher / handoff binding 和 safe read surface；Domain object、policy、状态转换和历史规则只接收已验证 context，不直接读取原始配置。

| 主要部分 / 接缝 | 是否受配置影响 | 配置影响类型 | 交给详细设计展开 |
|---|---|---|---|
| CMP-MS-01 command / query entry | 是 | runtime profile、entry enablement、request / read limit、store ref | `RuntimeConfig`、loader、validator、entry builder |
| CMP-MS-02 resolver / assembly | 是 / 间接 | source adapter、freshness policy、capability availability、blocked surface | `AdapterConfig`、qualification builder；exact source contract 仍 pending |
| CMP-MS-03 carrier / registry / action Job | 是 | adapter ref、capability profile、schedule、batch、retry class、unknown handling | adapter / job config 与 stable effect key 注入 |
| CMP-MS-04 registration / session | 是 | source binding、credential adapter、association profile、freshness limit | builder、compatibility guard、disabled / blocked disposition |
| CMP-MS-05 signal / health Job | 是 | source class、schema-version class、dedup store、schedule、sampling window | Consumer / Job config；具体阈值需 measurement authority |
| CMP-MS-06 cleanup / reconciliation | 是 | cleanup adapter、target class、scan scope、cursor、retry / escalation class | `AdapterConfig` / `JobConfig` 和 local-first mapping |
| CMP-MS-07 material / outbox / handoff | 是 / 间接 | redaction profile、target class、publisher ref、route binding、retry class | `HandoffConfig`、publisher builder、feedback placeholder |
| CMP-MS-07 projection / safe Query | 是 | projection scope、store adapter、cursor / rebuild cadence、visibility / freshness profile | `ProjectionConfig`、`ReadConfig`、unavailable handling |
| local stores / clock / ID / operations seam | 是 | adapter ref、availability profile、clock / ID / job context binding | startup validation、fake seam、disabled / degraded behavior |
| Member / Runtime / Images / Sandbox / Bus seam | 是 | seam enablement、capability profile、endpoint / ref binding、contract allowlist | 仅绑定 placeholder slot；合同未闭口时保持 blocked / waiting |

| 禁止配置化边界 | 原因 | 若需改变应回到哪里 |
|---|---|---|
| `ProjectMemberRef` 执行主语与 `GlobalMemberRef` 锚 | 范围和授权语义，不是 profile | 正式 00 / 01 |
| 七个 CMP、29 个对象和 owner 归属 | 配置不能产生第二 Host Truth 或合并状态轴 | Step 4~6、正式 01 |
| 显式 intent / decision、required qualification、no-fallback | 防止 flag / 默认值 / 旧缓存放行 | Step 3、7~10 |
| generation immutable、single-active、late / unknown fence | 并发和副作用安全不能关闭 | Step 3、9、03 |
| local-first、attempt / gap / delivery / observation / acceptance 分层 | 防止 receipt / timeout 伪造完成 | Step 8~10、03 |
| Query no-write、Consumer 限权、Job no-hidden-command | 入口角色是架构边界，不是 feature | Step 7~10 |
| Host Session 不扩为 Runtime run / checkpoint / memory / outcome | 防止 session profile 侵入 Runtime truth | 正式 01、`MSVC-UP-001` |
| Member、Images、Sandbox、Governance、Observability 和 L1 truth owner | adapter 选择不能迁移 owner | 对应正式上游文档 |
| secret / endpoint / image / signal / report / external body 禁止入仓 | 数据所有权与安全红线 | 正式 00 / 01、Step 3、10 |
| immutable material、append-only history、source revision anchor | 审计连续性不能被 profile 破坏 | Step 6 / 9、03 |
| projection / outbox / handoff 不反写 source | 读侧和传播侧不能成为第二写源 | Step 8~10、03 |
| 当前范围不扩展到非项目型、warm pool 或复杂调度 | 没有正式 FR / owner / 主语 | 先重开正式 00，再回退 01 / 02 |

本章不定义配置 key、默认值、JSON / YAML / TOML、环境变量、secret 名称、部署挂载、热更新、timeout / retry / heartbeat 数值或产品 endpoint。03 定义实现注入契约，04 定义可填写配置分类和激活规则。

如果详细设计发现需要新增、删除、合并或重命名主要组成部分、对象、接口、处理流、状态、owner 或禁止配置化边界，必须先回退到对应概要 Step 修正，不能在 `03-详细设计.md` 中暗改。

### 13.1 设计风险

| 风险 | 影响 | 当前处理口径 |
|---|---|---|
| `HR-MS-001` placeholder / fake / 局部 receipt 被写成 positive contract 或 readiness | CMP-MS-02~07、exact contract 和下游正向路径 | 只证明边界已点名；受影响路径保持 blocked / waiting / unknown。 |
| `HR-MS-002` 相邻 owner / backend truth 被复制为 Host Truth | 七个 CMP、对象、resolver、Consumer、projection | 仅允许 typed ref、safe snapshot、freshness、redacted marker、body-free material、matching outcome。 |
| `HR-MS-003` required qualification 被默认值、旧缓存、fallback 或配置放行 | qualification / assembly / readiness | missing / stale / conflict / unknown / pending 全部非 ready；保持 no-fallback。 |
| `HR-MS-004` 正交状态压成 `HostStatus` | 对象状态、Query、handoff 和 03 transition model | 各对象保留 owner-specific 状态；若需合并必须回退 Step 6 / 9。 |
| `HR-MS-005` duplicate / late / concurrent / unknown effect 形成第二 current | generation、registration、session、cleanup | immutable generation、single-active、expected revision、stable key、hold / reconciliation。 |
| `HR-MS-006` local attempt / submitted / gap 被写成 external complete / delivered / observed / accepted | CMP-MS-03、06、07 和 handoff | 分离 local、publisher、external outcome 和 acceptance；缺 owner feedback 即 gap / unknown。 |
| `HR-MS-007` Query / Consumer / Job / projection / reconciliation 成为 second writer | 接口分类、状态 writer、source facts | Query no-write；Consumer 限写；Job 只推进 committed work；派生不反写 source。 |
| `HR-MS-008` secret、endpoint、image、signal、Runtime / Sandbox / report body 入仓 | 所有对象、history、material、projection、event | forbidden body 拒绝或裁剪为 safe ref / summary。 |
| `HR-MS-009` 产品、RPC、事件、SDK、数据库或 profile 反向定义 owner / state | code skeleton、ports、persistence、configuration | product-neutral port、adapter-neutral result；产品只能影响承载和节奏。 |
| `HR-MS-010` seam 转换为 sibling 源码依赖、共享 DB 或 runtime SDK client | 03 dependency、并行演进和隔离 | 只允许正式 compile / runtime / event / ref / adapter seam；不共享 private model / storage。 |
| `HR-MS-011` 历史 worker、action execution、capability mount、Sandbox execution、协议和数字回流 | 正式 02、03~07 承接 | historical material 只用于污染审计；新结论须有当前 authority 并重开 Step。 |
| `HR-MS-012` 无 FR 的 policy 传递、非项目型、warm pool、调度或 forensic body 进入核心 | 范围、组成部分、接口 / 对象分母 | 当前只支持项目型 C-MS-1~5；扩展先重开 00 / 01 / 02。 |
| `HR-MS-013` projection / publication / Observability 不可用被解释为 source failure | CMP-MS-07、safe Query、核心 write availability | projection 可 stale / degraded / unavailable；外围失败不回滚 source。 |

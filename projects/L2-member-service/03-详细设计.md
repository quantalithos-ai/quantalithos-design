### 2.1 四个语义层

```text
control plane
  -> local Host Truth / host decision / lifecycle records
  -> runtime session association (external-safe placeholder only)
  -> execution handoff (submitted/delivered/observed/accepted layers)
```

关键说明：

- 图表达本仓由控制意图到宿主事实再到交接层的语义分层。
- 图不表达 Runtime loop、member 主体、Sandbox backend 或 Bus 的内部实现。
- `submitted`、`delivered`、`observed`、`accepted` 必须由各自 owner 的反馈推进，不能跨层推导。

## 3. 实现约束与编码规范承接

> 校准来源：
> - `design-calibration/03_ddd_step_03_runtime_constraints.md`
> - `design-calibration/03_ddd_step_14_config_dependencies.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“Rust-facing 约束”“依赖分类”“运行期绑定”和“不可配置化边界”小节。

目标实现形态为 Rust 2024 planned workspace。源码标识符、模块名、公开 rustdoc、错误类型和测试名默认使用英文；设计正文使用中文。公开 struct、enum、variant、trait、函数和字段必须有 Rustdoc 风格注释，字段必须给出类型、来源和不变量。任何产品 client、数据库模型、broker envelope、外部正文或 secret 都不得进入 domain / public contracts。

依赖按以下类别严格区分：

| 类别 | 允许形式 | 本仓约束 |
|---|---|---|
| compile | 已确认的 `L0-core` shared contract | 仅作为 planned `core-contracts` seam，目标实现仓确认前不写实际依赖声明 |
| runtime | Identity、Work、Member、Runtime、Images、Sandbox、carrier | application port + infra adapter；不成为 sibling Cargo path dependency |
| event | Core / Bus inbound、outbox publication、feedback | transport-neutral envelope / candidate；exact route、receipt 和 schema 仍 pending |
| ref | external safe ref、source version、safe summary | opaque typed carrier；不展开 source body |
| adapter | store、clock、id、publisher、handoff、observability | infra 实现 application port；产品和 endpoint 留给后续配置 |
| fake | deterministic local store、fake adapter、fixture | 必须保持 revision、rollback、duplicate、unknown、redaction parity；fake 不证明真实边界可用 |

不可被配置改变的规则包括：`ProjectMemberRef` 执行主语、Host Truth owner、状态合法迁移、Query no-write、Job no-authorization、accepted history / material / outbox 约束、generation fence、幂等 replay、正文排除和四层 handoff 分离。

当前不写：实现仓路径的创建事实、Cargo lock、编译结果、运行结果、提交记录、测试报告或部署参数。目标实现仓和 `core-contracts` baseline 在实施前必须由后续 `07` 门禁确认。

## 5. 模块实现契约

> 校准来源：
> - `design-calibration/03_ddd_step_05_module_contracts.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`

> 延伸阅读：
> - Step 5 的“逐模块职责”“文件 owner”“seam 分类”与依赖审计。
> - Step 6 的对象卡、字段来源、factory / method 与 invariants。
> - Step 7 的 Port 分层、返回载体、adapter 绑定和 fake parity。

本章规定每个实现模块的唯一职责、输入输出边界和可调用方向。模块间通过 typed contract、application Port 和 validated builder 连接；具体产品、外部正文和 sibling Cargo 路径不属于本章实现契约。

### 5.1 `contracts`

`contracts` 是跨入口共享的安全 carrier 层，负责 typed ref、metadata、command/query/consumer/job DTO、safe view、receipt、stored-result ref、error category 和 redaction marker。它不读取配置、不持有 repository、不执行 domain transition，也不保存 Member、Runtime、Images 或 Sandbox 正文。

### 5.2 `domain`

`domain` 是 Host Truth 领域层，负责 29 个业务对象、值对象、policy、generation / revision / effect-key guard 和纯状态迁移。domain method 只接收显式 typed input；不调用 clock、数据库、消息、RPC、容器、编排或外部 client。所有不变量违反都返回 `DomainError`。

### 5.3 `application`

`application` 负责 command/query/consumer/job use-case 编排、operation context、幂等 reservation、UoW 边界、mapper 和 stored result。它只依赖 Port trait，不依赖 infra 实现；它不能把 Job 调度变成授权，也不能把 Query 变成修复流程。所有会写 local truth 或 marker 的 use-case 都必须遵循 Step 11 的原子写集。

### 5.4 `infra`

`infra` 负责 logical store 的物理实现、UoW adapter、typed config validation、外部 seam adapter、clock/id、publication、observability sink 以及 deterministic fake assembly。physical co-location 不改变 logical owner；adapter 的 `Ok` 只表示 adapter 自身返回，不得升级为 external completion 或 readiness。

### 5.5 `api`

`api` 只提供同步 Command / Query entry。它负责 metadata、visibility、body-free error 和 transport-neutral outcome 映射；不直接写 repository、不构造 domain 对象、不读取 raw config。具体 HTTP/RPC/IPC 绑定留给部署层和 `04-配置设计.md`，当前不锁定。

### 5.6 `worker`

`worker` 负责 Inbound Consumer、outbox publisher loop、projection trigger 和 worker context。它只消费已验证 envelope，写入协议允许的 local marker，并返回 receipt / disposition。consumer 不创建 intent、decision、generation、recovery、closure 或新的 effect key；publisher 只发送 immutable outbox snapshot。

### 5.7 `jobs`

`jobs` 负责七种 operations job 的 entry、selector、单项 UoW 和 report。Job 只能推进已经 committed 的 attempt、cleanup、outbox、projection、reconciliation 或 handoff marker；scheduler `run_id` 不是 actor、authorization、lifecycle decision 或新的 business key。

### 5.8 模块契约矩阵

| 调用方 | 允许调用 | 禁止调用 | 失败上限 |
|---|---|---|---|
| `api` | `application` facade 的 command/query 方法 | repository、domain constructor、外部 adapter | safe outcome / visibility |
| `worker` | consumer、publisher、projection application service | 直接改 source truth、直接调用 sibling client | receipt / delayed / rejected |
| `jobs` | 已提交 work selector 与对应 application job handler | 创建 intent/decision/generation、换 effect key 盲重试 | item report / unknown / gap |
| `application` | domain、Port、UoW、mapper、idempotency | 具体数据库、broker、容器、RPC client | application error |
| `infra` | 实现 application Port、组装 entry | 改写 domain 规则、暴露 raw external body | typed infra / port error |
| `domain` | 纯 policy、factory、transition | I/O、配置、日志后端、transport | domain error |

所有实现单元必须能回指唯一 file owner；若新增文件会造成第二个 owner、万能 context 或重复 carrier，应暂停并回写 Step 4~7，而不是在实现阶段临时扩张模块。

|  | `SafeHostView` | `contracts/src/views.rs` | 向授权读取方暴露脱敏宿主事实和 freshness |
|  | `HostProjectionState` | `domain/src/projection.rs` | 保存派生 projection 的 cursor、revision 和 freshness |
|  | `HostOutboxRecord` | `domain/src/outbox.rs` | 保存 immutable material snapshot 和 publication marker |
|  | `HostHistoryEntry` | `domain/src/history.rs` | 追加 accepted local transition、relation 和审计引用 |

所有对象必须携带可验证的 project/member 双锚、适用的 host/generation、来源 ref、reason、revision 或 correlation；字段级 optionality、redaction 和 factory 前提只以 Step 6 对象卡为准。

### 6.2 主要 Trait / Port family

| Port family | 典型 owner | 作用 | 正向上限 |
|---|---|---|---|

### 7.1 公共 metadata、结果与 envelope

Command 必须携带 `HostCommandMetadata`（actor、command_id、idempotency_key、correlation_id、captured_at）；Query 使用无幂等键的 `HostQueryMetadata`。Inbound event/job envelope 的 schema version、message/run identity、source、correlation 和 payload 仍是 transport-neutral placeholder，Core/Bus exact schema 未闭合时不得补写。

| 结果类型 | 允许值 | 语义 |
|---|---|---|
| `HostCommandOutcome<T>` | `Accepted` / `Rejected` / `Duplicate` / `Conflict` / `Blocked` | 本地 command disposition，不代表外部完成 |
| `HostQueryOutcome<T>` | `Visible` / `NotVisible` / `Degraded` / `Unavailable` | 安全读取面和 freshness，不触发修复 |
| `HostConsumerReceipt` | `Accepted` / `Duplicate` / `Delayed` / `Rejected` / `UnsupportedVersion` | 本地消费 disposition，不代表目标接受 |
| `HostJobDisposition` | planned run/item disposition | 只报告已提交 work 的推进结果 |

`Rejected`、`Blocked`、`Unavailable` 不产生 accepted truth；`Duplicate` 只回放对应入口的 stored result/receipt/report；`Degraded` 不等于 ready/healthy。任何 raw payload、secret、endpoint、manifest、外部错误正文都必须在边界被拒绝或脱敏。

### 7.2 Command inventory（10）

| Command | 类型 | 负责模块 | 本地写入 ceiling | 上游未闭合时 |
|---|---|---|---|---|
| `AcceptHostIntentCommand` | public | CMP-MS-01 | intent、history/material、result | 缺双锚/source/scope -> rejected |
| `DecideHostOrchestrationCommand` | public | CMP-MS-01 | decision、history/material、result | current/version 不符 -> conflict |
| `ResolveHostQualificationCommand` | public | CMP-MS-02 | qualification、marker、result | source unknown -> blocked/partial |
| `CoordinateHostAssemblyCommand` | public | CMP-MS-02 | assembly/readiness（若可评估）、result | required item 缺失 -> blocked |
| `EstablishHostGenerationCommand` | internal | CMP-MS-03 | host、generation/current pointer | 竞争或条件不足 -> conflict/held |
| `PrepareHostActionCommand` | internal | CMP-MS-03 | prepared action attempt | 不调用 external seam |
| `AcceptHostRegistrationCommandPlaceholder` | public placeholder | CMP-MS-04 | registration/session shell | `MSVC-UP-002/006` -> waiting/blocked |
| `MaintainHostSessionCommandPlaceholder` | public placeholder | CMP-MS-04 | endpoint/session shell | Runtime association缺失 -> blocked/unknown |
| `DecideHostRecoveryCommand` | public | CMP-MS-05 | recovery decision | 缺 formal control source -> blocked |
| `CloseHostCommand` | public | CMP-MS-06 | local closure、invalidation、cleanup attempt | 不声明外部 cleanup |

所有 Command 都遵守 `validate -> reserve -> load versioned records -> domain transition -> same-UoW local write -> sidecar/result -> complete -> commit`；internal 只限制 transport 暴露，不降低 actor、幂等、审计和 generation 约束。

### 7.3 Query inventory（6）

| Query | 读取面 | 返回重点 | 明确禁止 |
|---|---|---|---|
| `QueryCurrentHostDecision` | control + current pointer + safe projection | decision safe slice、freshness/gap | 创建/修改 decision |
| `QueryHostAssemblyReadiness` | qualification/assembly/readiness | per-axis status、basis、freshness | resolver、重评估、refresh |
| `QueryHostAccessSession` | registration/endpoint/session | redacted session/endpoint ref | 接受 registration、建立 association |
| `QueryHostHealthFailure` | signal/assessment/failure/recovery | 四轴 health、failure、recovery safe ref | 评估、恢复、写 marker |

| `QueryHostHistory` | append-only history | safe page + opaque public cursor | append、推断 current |

Query 没有 idempotency key；若 transport 强制提供，entry 只记录结构性拒绝并忽略该字段。所有 query 严格 no-write：不得 reserve、refresh、repair、rebuild、append、publish、mark stale 或反写 source。

### 7.4 Inbound Consumer inventory（5）

| Consumer | 允许写入 | 禁止写入 |
|---|---|---|
| `QualificationSourceChangedConsumerPlaceholder` | safe source snapshot、qualification stale marker、receipt | intent/decision/ready |
| `HostActionOutcomeConsumerPlaceholder` | matching attempt、association、safe outcome、late/gap | 新 attempt、current replacement |

### 7.5 Material helper 与 Operations Job inventory

唯一 outbound material helper 为 `HostFactMaterialEventCandidate`，只能从 committed `HostFactMaterial` 构造 immutable safe payload，并由 outbox record 保存；它不是已闭合的 Core/Bus event family。

| Job | 只可推进 | 禁止 |
|---|---|---|
| `DispatchPendingHostActionsJob` | prepared action attempt | 创建 decision/generation、换 key |
| `EvaluateDueHostHealthJob` | accepted signal -> assessment/failure | 隐式 recovery |
| `ProgressPendingHostCleanupJob` | prepared cleanup attempt | external cleanup complete |
| `ReconcileHostResidualsJob` | finding/case | 修改 sibling/backend truth |

Job `run_id` 只标识本轮运行；Job 不能产生 intent、decision、authorization、generation 或新的 external/publication/handoff key。

### 7.6 四层 handoff 协议

`submitted`、`delivered`、`observed`、`accepted` 是四个独立记录层。每层必须有明确 owner feedback、target、handoff key 和 marker revision；本地 receipt、adapter `Ok`、日志、trace 或 outbox `submitted` 都不能推导后续层。缺少 exact target feedback 时保持 `unknown / gap / waiting`。

## 8. 逐接口函数级处理流

> 校准来源：
> - `design-calibration/03_ddd_step_09_function_flows.md`
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
> - `design-calibration/03_ddd_step_11_persistence_tx_consistency.md`

> 延伸阅读：
> - Step 9 的每条 flow 卡提供完整函数顺序、Port 调用、UoW 与负向分支。
> - Step 8 的协议卡提供 DTO 必填字段、结果和 receipt。
> - Step 11 的写集定义 commit / rollback 和 cursor 可见性。

### 8.1 统一入口模板

```text
validate metadata + typed input
  -> build operation context and deterministic digest
  -> reserve idempotency (command/consumer/job only)
       duplicate -> rollback current UoW; load exact stored surface; replay
       conflict  -> return stable conflict; no mutation
       in-flight -> delayed/blocked; no second writer
  -> begin required local UoW
  -> load versioned records and verify subject/generation/effect key
  -> invoke one domain factory/transition
  -> save only the allowed local truth/marker
  -> append history/material/outbox or mark projection stale when required
  -> save stored result/receipt/report
  -> complete reservation and commit
```

Query 使用只读快照，不执行 reservation 或写 UoW。外部 call 只发生在已提交的 action / cleanup / outbox / handoff record 之后；timeout、adapter `Ok` 或 commit unknown 均不能直接形成成功事实。

### 8.2 Command flows

| 接口 | 处理顺序 | accepted 写集 | 关键负向分支 |
|---|---|---|---|
| `AcceptHostIntentCommand` | validate 双锚/source/scope -> reserve -> 读取 current -> `HostIntent::accept` -> save intent -> history/material -> result -> commit | intent、accepted history/material、stored result、受影响 projection stale | 缺字段 rejected；同 key 同 digest duplicate；同 key 异 digest conflict；不触发 host/action |
| `DecideHostOrchestrationCommand` | 读取 accepted intent/current -> policy -> propose/commit decision -> save expected revision -> sidecar/result -> commit | decision 及对应 sidecar | current/version 不符 conflict/superseded；commit 不代表宿主已建立 |
| `ResolveHostQualificationCommand` | 读取 committed decision/target -> 依次读取 Identity、Work、Images、credential、Sandbox、carrier safe seam -> policy evaluate -> record context -> sidecar/result | qualification context、source markers、history/material、result | stale/unknown/placeholder 保持 partial/blocked/unknown，不 fallback 成 ready |
| `CoordinateHostAssemblyCommand` | 读取 qualification -> freeze required item set -> 记录 item safe outcome/gap -> 独立 readiness evaluate -> save -> sidecar/result | assembly，及可评估的 readiness | 缺 required item blocked；`Complete` 不推导 `Ready` |
| `EstablishHostGenerationCommand`（internal） | 读取 committed decision/current pointer -> generation fence -> 建立逻辑 host/generation -> save current pointer -> sidecar/result -> commit | host、generation、current pointer | 竞争建立 conflict/held；不创建容器、进程或 Runtime session |
| `PrepareHostActionCommand`（internal） | 读取 decision/host/generation -> guard action target -> 生成稳定 `ExternalEffectKey` -> prepare attempt -> sidecar/result -> commit | `HostActionAttempt(Prepared)` | target/generation 不符 rejected/blocked；不调用外部 seam |
| `AcceptHostRegistrationCommandPlaceholder` | 读取 host/generation/qualification -> Member registration safe ref + credential safe ref -> session policy -> accept/block -> save -> sidecar/result | registration/session shell | exact Member/credential contract 缺失 waiting/blocked；不保存 body/secret |
| `MaintainHostSessionCommandPlaceholder` | 读取 accepted registration/current endpoint/session -> optional Runtime association placeholder -> endpoint/session local transition -> sidecar/result | endpoint/session shell | association unavailable blocked/unknown；不创建 Runtime run/turn/checkpoint |
| `DecideHostRecoveryCommand` | 读取 current host/generation + assessment/failure -> load formal control context -> propose/commit recovery decision -> sidecar/result | recovery decision | 缺正式 control source blocked；Recover/Restart/Stop/Terminate 只形成 host-side decision |
| `CloseHostCommand` | 读取 host/generation/current registration/session/association -> open closure -> local invalidate -> prepare cleanup with stable key -> sidecar/result -> commit | closure、local invalidation、cleanup attempt | stale generation/closed host conflict；不声明 Sandbox/carrier cleanup |

每个 Command 的 accepted 写集必须在同一 local UoW 中提交；任何保存、sidecar、stored result 或 reservation completion 失败都整体 rollback。`Conflict`、`Blocked` 和 `Rejected` 不得偷偷执行外部动作。

### 8.3 Query flows（严格 no-write）

| Query | 读取顺序 | 结果与负向分支 |
|---|---|---|
| `QueryCurrentHostDecision` | visibility -> control repo/current pointer -> safe mapper | visible 或 not-visible/degraded/unavailable；不创建 decision |
| `QueryHostAssemblyReadiness` | visibility -> qualification/assembly/readiness repo -> per-axis mapper | 返回每轴 freshness/gap；不调用 resolver、不重评估 |
| `QueryHostAccessSession` | visibility -> registration/endpoint/session repo -> redaction mapper | endpoint/session safe ref；不刷新 endpoint、不建 association |
| `QueryHostHealthFailure` | visibility -> signal/assessment/failure/recovery repo -> four-axis mapper | stale/unknown 原样暴露 safe marker；不评估、不 recovery |
| `QuerySafeHostFacts` | visibility -> projection/material reader -> projection state -> `SafeHostView` | stale/degraded/unavailable 不触发 rebuild 或 repair |
| `QueryHostHistory` | visibility -> append-only history page by subject -> safe page mapper | opaque public cursor；不追加 history、不推断 current |

Query 读取异常只映射为 safe `Unavailable`/`Degraded`；空结果不被解释成 healthy、ready、closed 或外部不存在。Query 不 reserve、refresh、repair、rebuild、append、publish、mark stale 或反写任何 truth。

### 8.4 Inbound Consumer flows

| Consumer | 处理顺序 | 允许写入 | 负向分支 |
|---|---|---|---|
| `QualificationSourceChangedConsumerPlaceholder` | 验证 version/message/source -> 映射 safe snapshot -> 保存 source marker -> `CommittedChangeCursor` -> stale -> receipt | qualification source snapshot/marker | unsupported version body-free；旧 source/冲突 -> delayed/duplicate/conflict |
| `HostActionOutcomeConsumerPlaceholder` | 验证 effect key/target/generation -> 查 matching attempt -> 记录 safe outcome/association -> marker/stale -> receipt | matching attempt、association、late/gap | old generation/unknown key 不覆盖 current；不创建新 attempt |
| `HostHealthSignalConsumerPlaceholder` | 验证 source sequence/freshness -> `HealthSignalSnapshot::capture` -> append signal -> mark assessment due -> receipt | signal snapshot、due marker | duplicate/late/stale/rejected；不直接写 healthy/recovery |
| `HostCleanupFeedbackConsumerPlaceholder` | 验证 cleanup key/target/generation -> 查 matching cleanup -> 记录 outcome -> residual/case（必要时）-> receipt | cleanup marker、residual/gap | timeout/ack 为 unknown；不写 external cleanup complete |
| `HostHandoffFeedbackConsumerPlaceholder` | 验证 handoff key/target/layer -> 更新 exactly one layer -> receipt/history marker | handoff layer、gap/feedback ref | layer 越级、target mismatch、unknown 保持 gap；不推导 accepted |

Consumer 是本地 marker / feedback 写入者，不是 lifecycle decision writer；其 receipt 在同一 UoW 中 durable 后才能完成 reservation。

### 8.5 Material helper 与 Job flows

| 接口 | 处理顺序 | 允许写入 | 负向分支 |
|---|---|---|---|
| `HostFactMaterialEventCandidate` | 读取已 committed local change -> `HostFactMaterial::from_change` -> immutable payload -> outbox record -> stale marker | material、outbox、history relation | source cursor 未确认或 payload 不安全 -> blocked；不从 current truth 临时组包 |
| `DispatchPendingHostActionsJob` | validate job -> reserve -> 选择 Prepared attempts -> 每项短 UoW 调 carrier/placeholder -> 记录 dispatched/failed/unknown -> report | matching action attempt、job report | unavailable/delivery unknown 保留原 key；不新建 decision/generation |
| `EvaluateDueHostHealthJob` | 选择 accepted signals/current facts -> read basis -> evaluate assessment -> optional classify failure -> save/report | assessment/failure、history/material marker | basis stale/unknown -> delayed/blocked；不隐式 recovery |
| `ProgressPendingHostCleanupJob` | 选择 Prepared cleanup -> release Port（若合同可用）-> 记录结果 -> 更新 local closure -> report | cleanup attempt、closure local status、report | unknown/blocked 进入 gap/reconcile；不换 key |
| `ReconcileHostResidualsJob` | 选择 open finding/case -> 比对 local 与 safe external summary -> 追加 finding/case disposition -> report | finding/case、report | summary unavailable -> held/escalated；不删资源或改 sibling truth |
| `PublishHostFactOutboxJob` | 选择 pending outbox + immutable payload -> publication Port -> 写 submitted/unknown/gap + handoff -> report | outbox marker、handoff、report | publisher failure/unknown 保持 pending/unknown/gap；不回查 current truth |
| `RebuildSafeHostProjectionJob` | 选择 committed source cursor + stale projection -> 读 material/history -> 构造 projection -> 保存 state/view -> report | derived projection state/view、report | older cursor no-op；rebuild failure 保持 stale/degraded/unavailable |
| `ReconcileHostHandoffGapsJob` | 选择 unknown/gap -> matching target/key -> waiting link 或 bounded retry marker -> report | handoff marker/gap、report | key/target 不匹配 held；不可盲重放、不可声明 accepted |

### 8.6 跨 flow 证据顺序

接受的 local transition 顺序固定为：`truth -> HostChangeCursor -> history/material -> outbox/projection marker -> stored result -> idempotency complete -> commit`。reference、feedback 和 maintenance marker 使用 `CommittedChangeCursor`，不伪造 Host Truth change。任何 `submitted`、`delivered`、`observed`、`accepted` 层均必须由其 owner 的单独反馈推进。

## 9. 状态机与转换矩阵

> 校准来源：
> - `design-calibration/03_ddd_step_10_state_machine.md`
> - `design-calibration/03_ddd_step_06_object_contracts.md`
> - `design-calibration/03_ddd_step_09_function_flows.md`

> 延伸阅读：
> - Step 10 的完整状态枚举、合法迁移、禁止矩阵和 writer 对齐表。
> - Step 6 的对象级状态 invariant。

本仓不定义一个万能 `HostStatus`。控制、资格、装配、宿主、动作、关联、注册、端点、会话、健康、恢复、关闭、清理、差异、交接、outbox 和 projection 均为正交状态轴。

### 9.1 正交状态轴

| 状态轴 | 正式状态族 | 主要 writer | 禁止推导 |
|---|---|---|---|
| intent acceptance | `Received / Accepted / Rejected / Conflicted / Superseded` | Accept intent | Accepted 不等于 decision/ready |
| orchestration decision | `Proposed / Committed / Voided / Superseded` | Decide orchestration | Committed 不等于 host/action success |
| qualification | `Pending / Resolving / Resolved / Partial / Blocked / Unknown` | Resolve qualification/source consumer | Resolved 不等于 Ready |
| assembly | `Building / Complete / Blocked / Superseded` | Coordinate assembly | Complete 不等于 Ready |
| readiness | `Unevaluated / Ready / NotReady / Blocked / Unknown / Superseded` | readiness evaluation | Ready 不等于 process/session/healthy |
| host lifecycle | `Established / Current / Closing / Closed / Superseded` | generation/close | Current 不等于 process running |
| action attempt | `Prepared / Dispatched / Succeeded / Failed / Unknown / Held / Superseded` | prepare/job/feedback | Succeeded 不等于 ready/healthy |
| external association | `Pending / Associated / Stale / Invalid / Unknown / Released` | feedback/close | Associated 不等于 Runtime session active |
| registration | `Proposed / Accepted / Blocked / Rejected / Replaced / Invalidated` | registration/close | Accepted 不等于 Ready |
| endpoint | `Pending / Active / Stale / Invalidated` | session maintenance/close | Active 不等于 reachable |
| Host Session | `Pending / Associated / Active / Stale / Closed / Blocked` | session/feedback/close | Active 不等于 Runtime run |
| health signal | `Captured / Accepted / Duplicate / Late / Stale / Rejected` | signal consumer | Accepted 不等于 healthy |
| assessment | `Pending / Evaluated / Stale / Superseded` | health job | Evaluated 不等于 recovery |
| failure | `Unclassified / Classified / Uncertain / Superseded` | health job | Classified 不等于 action |
| recovery decision | `Proposed / Committed / Voided / Superseded / Blocked` | recovery command | Committed 不等于 recovered |
| closure | `Proposed / LocallyClosed / PendingCleanup / Blocked / Superseded` | close command | LocallyClosed 不等于 external cleanup |
| cleanup attempt | `Prepared / Dispatched / Succeeded / Failed / Unknown / Held` | close/job/feedback | Succeeded 只表示 safe local outcome |
| residual finding | `Open / Observed / Resolved / Invalidated` | reconciliation | Resolved 不等于 backend repaired |
| reconciliation case | `Open / Investigating / Held / Resolved / Escalated` | reconciliation | Resolved 不等于 external completion |
| handoff | `Prepared / Submitted / Delivered / Observed / Accepted / Unknown / Gap` | publication/feedback | 一层不能推导下一层 |
| outbox | `Pending / Submitted / Unknown / Gap / Superseded` | publication job | Submitted 不等于 delivered |
| projection | `Unbuilt / Fresh / Stale / Rebuilding / Degraded / Unavailable` | projection job | Fresh 不等于 source committed |

### 9.2 关键合法迁移

- intent 只能由 `Received` 进入 `Accepted/Rejected/Conflicted`，accepted 后只能由替代关系进入 `Superseded`。
- decision 只能由显式 command 从 `Proposed` 进入 `Committed/Voided`；Job 和 Consumer 不得提交 decision。
- readiness 只有在 required source/item 全部 positive、fresh、同一 project/member + host/generation 且 policy 允许时才能 `Ready`；任一 unknown/stale/conflict 保持非正向。
- host current pointer 由 generation fence 单一获胜者写入；旧 generation 的反馈只能 `Late/Unknown/Gap`。
- attempt/cleanup/outbox/handoff 的 unknown 必须保留原 stable key；重试先读取 matching record，不能自动换 key。
- closure、local cleanup、finding、case 的 resolved 语义彼此独立，不表示 Runtime、Sandbox、carrier 或 registry 的外部完成。

### 9.3 状态转换禁止矩阵

| 禁止转换 | 原因 |
|---|---|
| Query -> 任意生命周期或 marker 写入 | Query 是严格 read-only |
| Consumer arrival -> `Ready`/`Healthy`/`Recovery`/`Closure` | 信号或反馈只形成 matching local fact |
| Job trigger -> intent/decision/authorization/generation | scheduler 没有业务授权语义 |
| registration `Accepted` -> session `Active` | endpoint、Runtime association、generation 条件独立 |
| attempt `Succeeded` -> assembly `Ready` | 外部动作结果与资格轴不同 |
| outbox `Submitted` -> handoff `Delivered/Accepted` | 目标反馈 owner 尚未确认 |
| projection `Fresh` -> source `Committed` | 派生视图不能反写 source truth |
| cleanup `Succeeded` -> external cleanup complete | local safe outcome 不等于外部清理真相 |
| old generation feedback -> current state | generation fence 防止覆盖 |

### 9.4 状态与持久化闭环

每个状态迁移必须由唯一 domain method / application use-case 写入，并携带 expected revision、适用 generation、reason 和来源 ref。状态与相应 history/material/stale marker 在规定 UoW 内提交；rollback 不得泄漏新状态、cursor、stored result 或 outbox。上游 exact contract 未闭合时，正向迁移保持 `Blocked/Unknown/Waiting`，不以缓存、默认值、timeout 或 fake positive 越过门禁。

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - `design-calibration/03_ddd_step_11_persistence_tx_consistency.md`
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
> - `design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`

> 延伸阅读：
> - Step 11 的 logical store owner、原子写集、cursor visibility、outbox/projection/history 规则。
> - Step 13 的 reservation、expected revision、single-winner 和 commit-unknown 恢复顺序。

### 10.1 Logical store owner

| Logical store | 主要内容 | 唯一 application writer | 物理实现 owner |
|---|---|---|---|
| control | intent、orchestration decision | control use-case | `infra/src/persistence/control_store.rs` |
| qualification | qualification、assembly、readiness | qualification/assembly use-case | `qualification_store.rs` |
| progression | host、attempt、association、current pointer | generation/action/feedback service | `progression_store.rs` |
| session | registration、endpoint、Host Session | registration/session service | `session_store.rs` |
| health | signal、assessment、failure、recovery | consumer/health/recovery service | `health_store.rs` |
| closure | closure、cleanup | close/cleanup service | `closure_store.rs` |
| reconciliation | residual finding、case | reconciliation service/job | `reconciliation_store.rs` |
| material/history | immutable material、handoff、history | accepted flow/feedback | `material_store.rs`、`history_store.rs` |
| outbox | immutable payload、publication marker | accepted flow/publisher job | `outbox_store.rs` |
| projection | derived state/view | projection job/read assembly | `projection_store.rs` |
| idempotency/result | reservation、stored outcome/receipt/report | application facade/job | `idempotency_store.rs`、`result_store.rs` |

物理共址不改变逻辑 owner、对象 revision、状态语义或 UoW 写集。禁止使用动态字段的 generic `host_store` 淹没对象边界。

### 10.2 UoW 原子写集

accepted local command 的最小写集为：

```text
reserve idempotency
  -> load versioned records
  -> save changed domain truth with expected revision
  -> allocate HostChangeCursor after truth is staged
  -> append HostHistoryEntry / HostFactMaterial when applicable
  -> append HostOutboxRecord from immutable material snapshot when applicable
  -> mark affected HostProjectionState stale
  -> save StoredHostOperationResult
  -> complete idempotency reservation
  -> commit
```

source-change、feedback、maintenance marker 使用独立的 reference/marker 写集：保存 safe snapshot/attempt/handoff/gap、分配 `CommittedChangeCursor`、mark projection stale、保存 receipt/report；它们不创建 Host Truth change，不写新 intent/decision。

Query 只读 source/projection/history 快照；不得调用 write UoW、reserve、mark stale、refresh resolver、append trace/outbox 或 repair。

### 10.3 Revision、current pointer 与 cursor

所有 mutable object、projection、outbox、handoff、reference marker 更新都携带 `HostRevision` expected value；冲突返回 `Conflict`，不自动 merge、不用 timestamp 解决。single-active current pointer 与 generation fence 采用等价的唯一约束/Port 语义。

`HostChangeCursor` 只表示 accepted Host Truth change boundary；`CommittedChangeCursor` 只表示 reference/material marker boundary。两者均在相应写集 stage 后、UoW commit 后才可见；rollback 不得泄漏。exact type、序列化和跨仓兼容性仍 pending，禁止 alias、转换、第三种 cursor 或以 history id/page cursor/broker offset/CAS/version/generation 替代。

### 10.4 Outbox、projection、history 与 handoff

1. accepted command 在同一 UoW 保存 immutable material 与 outbox payload snapshot；payload 绑定 source change，不从 current truth 延迟重建。
2. publisher 只读取带 payload 的 pending outbox，短事务更新 submission marker；失败保持 `Pending/Unknown/Gap`。
3. feedback 以 target-specific `HandoffKey` 更新单一层；`submitted/delivered/observed/accepted` 不互推。
4. projection 从 committed source material/history 重建，成功更新 derived state；失败保持 stale/degraded/unavailable，不反写 source。
5. history append-only；replacement 通过 relation / supersedes ref 表达，不删除旧条目。

### 10.5 一致性与故障处置

| 交互 | 本地保证 | 可接受的非一致性 |
|---|---|---|
| command -> local truth | atomic commit + expected revision | 无，失败整体 rollback |
| command -> outbox | same-UoW append | publisher delivery 延迟/unknown |
| source change -> marker | atomic marker + receipt | projection 暂时 stale |
| dispatch -> feedback | attempt 先提交 | feedback late/unknown |
| close -> cleanup | closure/invalidation + attempt atomic | 外部 cleanup pending |
| projection rebuild | derived atomic replacement | read surface degraded/unavailable |
| duplicate replay | durable reservation + stored result | result store 不可用则 blocked，不重跑 |

missing stored result、payload、history 或 material 是 consistency defect；不得从 current truth 临时重算，不得覆盖 reservation 或重新执行不可逆外部动作。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - `design-calibration/03_ddd_step_12_errors_recovery.md`
> - `design-calibration/03_ddd_step_10_state_machine.md`
> - `design-calibration/03_ddd_step_11_persistence_tx_consistency.md`

> 延伸阅读：
> - Step 12 的 domain/application/Port/entry error catalog、结果映射和恢复责任矩阵。
> - Step 10 的状态禁止矩阵。
> - Step 11 的 rollback、stored result 和 unknown commit 规则。

错误是稳定的本地 disposition，不是新的业务对象或外部系统真相。对外只暴露 category、safe reason ref、correlation、retryability 和 visibility/freshness marker；raw adapter error、stack、secret、endpoint、外部正文和 transport 数字码必须留在边界内。

### 11.1 分层错误模型

```text
domain factory / transition / policy
  -> DomainError
application use-case / UoW / idempotency
  -> ApplicationError
repository / resolver / publisher / handoff / adapter
  -> typed PortError
api handler       -> HostCommandOutcome / HostQueryOutcome
worker consumer   -> HostConsumerReceipt / worker disposition
operations job    -> HostJobDisposition / item report
```

| 错误类别 | 典型触发 | 稳定处置 | 允许副作用 |
|---|---|---|---|
| `InvalidStateTransition` | 不在合法矩阵、terminal 再迁移 | reject，不重试原输入 | 不写 accepted truth |
| `MissingRequiredValue` | 双锚、scope、source、basis、target、generation、reason、stable key 缺失 | reject，修正输入 | 无业务写入 |
| `PolicyRejected` | control/qualification/readiness/recovery/closure guard 不满足 | rejected 或 blocked | 仅允许受控 redacted rejection marker |
| `ExternalBodyRejected` | raw sibling body、secret、manifest、endpoint 进入边界 | reject/fail-closed | 不保存 raw body |
| `ReferenceNotResolved` | required safe ref stale/unavailable/invalid | stale 可等待 refresh；invalid 不盲重试 | 仅写 reference marker |
| `GenerationMismatch` | 反馈、attempt、session 与当前 generation 不符 | late/held/gap | 不覆盖 current |
| `UnknownEffectProtected` | timeout、commit unknown、不可确认 external effect | unknown/held/reconcile，保留原 key | 不换 key、不补偿重放 |
| `VersionConflict` | expected revision 失败 | conflict/reload | 无 partial write |
| `IdempotencyConflict` | 同 key 不同 digest | stable conflict | 不执行 domain/effect |
| `StoredResultMissing` | reservation 完成但 result 不存在/类型不符 | consistency defect/manual recovery | 不从 current truth 重算 |
| `UnsupportedVersion` | envelope schema 未支持 | body-free receipt | 不解析 payload、不写 accepted truth |
| `PortUnavailable` | resolver/store/publisher/handoff unavailable | retryable 或 blocked | 不伪造 positive result |
| `CommitUnknown` / `RollbackUnknown` | UoW 状态不可确认 | 查询原 key并进入 reconciliation | 不发送补偿 mutation |

### 11.2 入口结果映射

| 入口 | accepted | 输入/策略失败 | 并发/幂等 | 外部或存储未知 |
|---|---|---|---|---|
| Command | `Accepted` | `Rejected` / `Blocked` | `Conflict` / `Duplicate` | `Blocked` / `Unknown` safe reason |
| Query | `Visible` | `NotVisible` | 不适用 | `Degraded` / `Unavailable` |
| Consumer | `Accepted` | `Rejected` / `UnsupportedVersion` | `Duplicate` / `Delayed` | `Delayed` / local `Unknown` receipt |
| Outbox publisher | submitted marker | rejected payload | duplicate marker replay | pending/unknown/gap |
| Operations Job | item progressed | item rejected/held | stored report replay | retryable/unknown/escalated |

`Duplicate` 必须回放同一 operation kind 的 stored result/receipt/report；不得把 Command 结果改成 Query view，也不得因 stored result 缺失而重新执行。`Unavailable` 不暴露具体 adapter 产品或异常正文。

### 11.3 异常分支与恢复矩阵

| 场景 | 本地动作 | 下一责任者 | 禁止动作 |
|---|---|---|---|
| validation/policy reject | 返回 safe rejection；若规范允许，写 redacted marker | caller 修正输入 | 默认值补齐、外部 call |
| expected revision conflict | rollback 当前写集，返回 conflict | caller 重读并生成新 operation | 自动 merge/最后写入覆盖 |
| resolver unavailable/stale | 保存 blocked/unknown/stale marker（仅在该 flow 允许） | resolver refresh/job 或 owner | 用旧缓存变 Ready |
| external effect timeout | attempt/cleanup/outbox/handoff 标记 unknown | matching-key reconciliation | 新 key 盲重放 |
| feedback late/duplicate | matching history/gap/receipt | reconciliation | 覆盖 current generation |
| UoW commit unknown | 查询原 reservation/result；必要时 open case | consistency/reconciliation owner | 补偿写、猜测 rollback |
| rollback unknown | freeze affected operation / manual marker | 运维或 reconciliation | 继续执行相关 effect |
| projection failure | 保持 stale/degraded/unavailable | projection job | Query 内 rebuild、反写 source |
| payload/material/result 缺失 | consistency defect + manual marker | persistence/infra owner | 从 current truth 重算 |
| permanent publication/handoff failure | gap/escalated，保留 immutable payload/key | target/Bus owner | 改写历史或声明 accepted |

### 11.4 恢复红线

恢复只能推进已经存在的 Host、attempt、cleanup、outbox、projection、handoff 或 reconciliation 记录。它不能创建 intent、orchestration/recovery decision、authorization、generation 或 Runtime/Sandbox truth；Job 也不能代替正式 actor 或 approval。

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
> - `design-calibration/03_ddd_step_11_persistence_tx_consistency.md`
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`

> 延伸阅读：
> - Step 13 的 key/digest matrix、reservation 算法、commit unknown 顺序和重入场景。
> - Step 11 的 expected revision、cursor 和 outbox 约束。

### 12.1 并发保护层次

| 资源 | 保护 | 竞争失败语义 |
|---|---|---|
| intent/decision current | operation reservation + expected revision | conflict，不覆盖新版本 |
| project-member current host | single-active pointer + generation fence | loser held/conflict，不生成第二 current |
| qualification/assembly/readiness | object revision + same generation | stale/blocked，重新评估 |
| action/cleanup attempt | immutable effect key + attempt revision | duplicate replay；unknown 保留原 key |
| registration/endpoint/session | fingerprint/target uniqueness + replacement plan | conflict/blocked，旧记录不静默覆盖 |
| signal/assessment/failure | source sequence/time/generation + revision | duplicate/late/stale |
| closure/reconciliation | causal key + same-key fence | held/unknown/gap |
| material/history | immutable ref + append-only relation | duplicate append 由 replay 抑制 |
| outbox | record ref + marker revision | single winner；另一 worker reload/skip |
| projection | projection revision + committed source cursor | older cursor no-op |
| handoff | target-specific key + marker revision | per-layer conflict，不越级 |

### 12.2 Operation namespace 与 digest

幂等唯一性为 `operation_name + normalized_key`。Command 使用 metadata 的 idempotency key；Consumer 使用 envelope dedup key；Job 使用 job envelope key；Query 不带幂等 key。digest 必须包含 operation 名、双锚/subject、host/generation、target、scope、稳定 DTO 字段、source version/sequence 和影响结果的 policy/config ref；必须排除 command/query/message/run id、trace/span、时间、broker offset、retry counter、随机 local id、secret、endpoint、外部正文和 adapter error text。

### 12.3 Reservation 与 replay

```text
validate -> compute deterministic digest -> reserve
  Duplicate  -> rollback; load exact stored surface; replay
  InFlight   -> delayed/blocked; no second writer
  Conflict   -> idempotency conflict; no mutation
  Reserved   -> execute one flow; save truth + sidecars + result
             -> complete reservation only after durable result
             -> commit
```

同 key 同 digest 只能得到同一 stored surface；同 key 异 digest 必须稳定冲突。stored result 缺失、类型不符或 payload 缺失属于 consistency defect，不能从 current truth 重建。

### 12.4 Unknown、重入与 single-winner

- UoW commit unknown：先查原 operation key 的 reservation/result，再决定 replay、reconciliation 或保持 unknown；不能发送补偿 mutation。
- external call unknown：attempt、cleanup、outbox、handoff 均保留原 effect/publication/handoff key，进入 `Unknown/Held/Gap`。
- 双 dispatcher / publisher / projection worker：通过 expected revision、cursor 和 stable key 只允许一个 winner；失败方 reload，不再次调用不可逆 effect。
- 旧 generation feedback：只写 late/unknown/gap/history，不覆盖 current。
- Job rerun：同 key 回放；新 run 只能选择未完成或 policy 明确允许的 item，不扫描 current truth 重建已完成副作用。

### 12.5 fake parity

Fake 与 durable adapter 必须保持 revision conflict、single-active、same-key replay、different-digest conflict、in-flight、rollback 不泄漏 cursor/result/outbox、unknown key preservation、forbidden body rejection 和 missing sidecar defect 的相同行为。fake 通过不证明真实 Runtime、Member、Images、Sandbox、store、broker 或 delivery ready。

| `worker` | envelope validation、consumer receipt、publisher/projection trigger | duplicate/late/unknown 与 marker 边界 | broker delivery 已确认 |
| `jobs` | selector、single-item UoW、report、rerun | 只推进已提交 work | scheduler 或 external completion |

### 15.2 协议测试切口

必须为 10 个 Command、6 个 Query、5 个 Consumer、material helper 和 7 个 Job 各保留至少一个 accepted 与一个负向切口。负向最小集合为：缺双锚/source/scope、unsupported version、同 key 异 digest、in-flight、expected revision conflict、generation mismatch、source stale/unknown、forbidden body、stored result missing、payload missing、external timeout/commit unknown、query stale 和 job 无已提交 work。

| 测试组 | 核心断言 |
|---|---|
| Command | accepted truth 与 history/material/outbox/result 同 UoW；duplicate 精确 replay；rejected/blocked 不触发 external call |
| Query | 只读 source/projection/history；绝不 reserve、refresh、repair、rebuild、append、publish 或 mark stale |
| Consumer | envelope 先验证；只写允许的 snapshot/attempt/handoff/gap；late/duplicate 不覆盖 current |
| Material helper | 只从 committed local change 生成 immutable safe payload；cursor 未确认则 blocked |
| Job | 只选择已提交 attempt/outbox/projection/reconciliation/handoff；不创建授权、decision、generation 或新 effect key |

### 15.3 状态、一致性与并发切口

- 每个状态轴覆盖所有合法迁移、非法迁移、terminal 再迁移和 supersedes 关系；验证不出现万能 `HostStatus`。
- 验证 `HostChangeCursor` 与 `CommittedChangeCursor` 语义分离；exact type 未闭合时测试只能验证 type hole/禁止 alias，不得构造第三种 cursor。
- 模拟 accepted UoW 任一阶段失败，确认 truth、cursor、history、material、outbox、projection marker、stored result 和 reservation 按规则整体 rollback。
- 验证 source change/feedback marker 不产生 Host Truth change；Query 不打开写事务。
- 覆盖 same-key same-digest replay、different-digest conflict、in-flight、commit unknown、rollback unknown、dual dispatcher/publisher、projection old cursor、old generation feedback、cleanup/handoff unknown key preservation。
- 验证 missing sidecar、missing payload、missing result 一律进入 consistency defect/manual recovery，不从 current truth 重算。

### 15.4 错误、配置与观测切口

验证 domain/application/Port/API/worker/job 错误分层；retryable、rejected、blocked、held、unknown、gap、manual recovery 不互相冒充。配置测试覆盖 raw config 不进入 domain/application、builder section 缺失/禁止值 fail-closed、unresolved sibling seam 保持 blocked/disabled/unknown、不可配置边界不被 feature flag 绕过。观测测试覆盖 low-cardinality、trace correlation 继承、accepted audit 引用和 forbidden-field redaction。

### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 member-service 的接口可调用,而是系统验证 `L2-member-service` 是否真正满足“成员执行宿主仓”的设计要求,尤其要证明以下几点成立:
- MemberExecutionHost / session / worker / health 构成正式宿主真相层
- `MemberExecutionHost ≠ ExecutionInstance`、`host failure ≠ business execution failure` 两条核心边界成立
- capability / tool scope / actor context / sandbox bind 形成正式装配结果,且未 bind 完成不得执行动作
- runtime action 能被正式承接到宿主层执行,并形成 execution handle
- host crash / restart / recycle / recoverable host fault 可以被正式区分和处理
- runtime 消费的是正式 callback material,而不是原始宿主日志
- observability 消费的是宿主观测输出,但不反向成为宿主真相写源

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 成员执行宿主与运行会话部分 | 真相对象 | P0 | host / session / worker / health |
| 能力挂载与上下文绑定部分 | 装配对象 | P0 | capability / tool scope / actor / sandbox bind |
| 动作承接与实际执行部分 | 执行对象 | P0 | runtime action intake / host dispatch / execution handle |
| 失败、重启与宿主恢复部分 | 恢复对象 | P0 | host crash / restart / recycle / recoverable fault |
| 执行反馈与宿主观测接缝部分 | 输出/观测层 | P0 | callback material / health report / metrics |
| 工具内部逻辑与 sandbox 内部算法 | 非范围 | P2 | 只验 member-service 与能力层接缝,不验能力内部实现 |
| runtime / work / process / governance / artifact 内部业务正文 | 非范围 | P2 | 只验 member-service 与它们的接缝,不验下游全部内部实现 |
| 前端 UI 展示细节 | 非范围 | P2 | 只验证 callback / health / view 材料,不验 UI 组件 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和局部不变量 | domain / policy owner | `host.validate_assignable`、`capability_mount.validate_bindable`、`host.transition_to_unhealthy`、`RuntimeCallbackMaterial::from_feedback` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + bind + adapter + callback 联动 | backend / domain owner | `AllocateExecutionHost`、`CheckHostAssignable`、`BindExecutionContext`、`ValidateCapabilityMount`、`ExecuteRuntimeAction`、`HandleHostCrash`、`RecycleExecutionHost`、`RestartHostSession`、`ReportExecutionFeedback`、`ReportHostHealth` | 宿主、装配、执行、恢复、反馈链同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | runtime action → host allocate/bind/execute、identity capability → mount、tools invoke → callback、sandbox bind fail → host unavailable、host crash → runtime callback + observability output | 输入输出语义一致 |
| 恢复专项测试 | 验证宿主故障与 callback/material 失败时是否可恢复 | architecture / QA | crash / restart / recycle、bind retry、raw result 已有但 callback 未写成、old handle invalidation | 宿主真相不丢失、反馈链可恢复 |
| 投影一致性测试 | 验证 host health / failure / callback view 与正式真相一致 | backend / QA | degraded/unhealthy 展示差异、failure report rebuild、callback 只读边界 | 读模型只读且与真相一致 |
| 端到端主线测试 | 验证最小宿主执行闭环 | QA / owner | allocate host → bind context → execute → callback；host crash → recycle/restart；sandbox bind fail 阻断执行 | 主干宿主闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| MemberExecutionHost 独立于 ExecutionInstance | host 真相独立建立 | 集成测试 | 是 | DB / API / trace |
| capability mount 与 capability 定义分层 | mount 结果与 snapshot 一致但不改定义真相 | 单元 + 集成测试 | 是 | binding record / snapshot compare |
| sandbox bind 未完成不得执行 | bind fail 后 execute 被拒绝 | 集成测试 | 是 | bind trace / error code |
| host failure ≠ business failure | host crash 不直接等于 runtime business fail | 恢复专项测试 | 是 | host failure report / runtime callback |
| runtime 消费正式 callback material | raw log 不作为正式反馈输入 | 边界专项测试 | 是 | callback record / compare |
| recycled host 不复用旧 session/handle | recycle 后旧句柄失效 | 集成 + 恢复测试 | 是 | handle trace / negative flow |
| observability 只消费观测输出 | health/metrics 不能反写宿主真相 | 投影一致性测试 | 是 | metrics output / no reverse write |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | AllocateExecutionHost 成功创建宿主/会话 | member / actor / snapshot 合法 | AllocateExecutionHost | host + session 建立成功 |
| TC-002 | 不可承载宿主被拒绝 | host busy/unavailable/conflict | CheckHostAssignable / Allocate | 返回宿主不可用/冲突 |
| TC-003 | BindExecutionContext 成功 | host ready + snapshots 完整 | BindExecutionContext | capability/tool/sandbox bind 成功 |
| TC-004 | capability bind 失败阻止执行 | capability snapshot 缺失/非法 | BindExecutionContext → Execute | execute 被拒绝 |
| TC-005 | sandbox bind 失败阻止受限动作 | sandbox bind failed | BindExecutionContext → Execute | host unavailable / bind failure |
| TC-006 | ExecuteRuntimeAction 成功生成 execution handle | host bound ready | ExecuteRuntimeAction | handle 建立成功 |
| TC-007 | host crash 产生 HostFailureReport | active host 正在执行 | crash → HandleHostCrash | host failure 正式记录 |
| TC-008 | RestartHostSession / RecycleExecutionHost 成功 | host failure recoverable/unrecoverable | Restart / Recycle | host 状态正确迁移 |
| TC-009 | raw host result 已有但 callback material 写回失败后补写成功 | execute 已成功 | ReportExecutionFeedback fail → retry | runtime 最终收到正式 callback |
| TC-010 | recycled host 旧 session/handle 失效 | host recycled | query old handle | 旧 handle 不再有效 |
| TC-011 | HostHealthReport / metrics 输出正常 | host health changed | ReportHostHealth | observability 得到正式观测输出 |
| TC-012 | runtime 只消费正式 callback material | raw log 与 callback 都存在 | compare consume path | 只使用 callback material |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | Host truth 与 execution truth 混层 / bind 未完成仍执行 / host failure 替代 business failure / callback material 不正式回流 | 阻断放行,必须修复 |
| A | 主线可跑但 host restart/recycle/bind/callback 语义不稳 | 原则上修复后再放行 |
| B | 非关键健康视图、日志材料或低优先级查询异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 host/session/lifecycle 逻辑,都必须回归 AllocateExecutionHost 与 session 失效链
- 每次改动 capability/tool/sandbox bind,都必须回归 bind success/fail 与 execute gate
- 每次改动 execute / handle 逻辑,都必须回归 action intake / handle persist / callback 主线
- 每次改动 crash/recycle/restart,都必须回归 recoverable / unrecoverable 分支
- 每次改动 callback/health/metrics,都必须回归 runtime consume 与 observability 输出一致性

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 一个宿主是否允许并发承载多个 runtime action 若后续放开 | 测试矩阵需扩充 | TL / 架构 |
| capability mount 若支持热更新 | bind / execute 边界测试需增加分支 | member-service + identity + tools |
| sandbox / tools 能力差异继续扩张 | 宿主执行路径测试需增加适配器样本 | Owner / TL |

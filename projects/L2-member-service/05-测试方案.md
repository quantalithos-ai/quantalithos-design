## 2. 本次测试目标与范围

> 校准来源：
> - `design-calibration/05_test_plan_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“范围 / 非范围表”“P0 / P1 / P2 口径”和“一票否决关联表”小节，了解本轮验证边界如何从核心能力和风险收敛。

本轮测试目标是证明 `L2-member-service` 作为成员执行宿主控制面能够在本地保持 Host Truth、装配、会话、健康、恢复、清理、对账和安全交接的分层语义，并能在依赖不可用、重复、并发、迟到、unknown 和输出泄漏时 fail-closed。测试不是证明某个 HTTP/RPC 接口“可调用”，也不是证明外部 sibling 或基础设施产品已 ready。

### 2.1 测试目标表

| 测试目标 | 来源 | P0 判定 |
|---|---|---|
| 项目型宿主意图与编排决定独立成立 | C-MS-1；FR-MS-001~002；`03` control flows | 双锚、scope、source、显式决定、稳定重复 / 冲突和审计关系可判定 |
| 装配条件与 readiness 分层成立 | C-MS-2；FR-MS-003~005 | required owner/ref/freshness/项集共同成立；partial、unknown、pending 不得 ready |
| 注册、endpoint 与 Host Session 壳可控 | C-MS-3；FR-MS-006~007 | 当前实例 single-active、失效、旧世代拒绝；不创建 Runtime run truth |
| 健康、失败与恢复控制分层成立 | C-MS-4；FR-MS-008~009 | host/session/backend/unknown 可区分；显式 recovery/stop/hold；不把心跳或进程等同业务进度 |
| 清理、对账和 handoff 分层成立 | C-MS-5；FR-MS-010~012 | local invalidation、cleanup attempt、residual、四层 handoff、immutable material 可追溯 |
| 协议和一致性可 1:1 验证 | `03` §7~§13、Step 16 | 10/6/5/1/7 入口均有正向上限和负向用例；UoW、revision、幂等、unknown 可审计 |

| registration accepted 被当 session active | `session_state_non_transitive` | endpoint、association、generation 条件分别判定 |
| attempt/receipt/timeout 被当 external complete | `adapter_ok_not_completion` | local attempt / submitted / unknown / gap 保持分层 |
| old generation / late feedback 覆盖 current | `old_generation_feedback_is_late` | late/unknown/gap；current 不变 |
| raw body、secret、manifest、endpoint、stack 进入输出 | `forbidden_body_rejected` | 不保存、不输出、不进入 artifact/report |
| Query 触发 refresh/rebuild/repair | `query_write_audit` | 无写 UoW、reservation、stale marker、audit append |
| Job 创建 intent/decision/generation/new key | `job_no_authorization_or_new_key` | 只推进既有 work / report |
| cursor / page cursor / revision / generation 混用 | `cursor_separation_guard` | 保持正式类型分离；exact type pending 时不 alias |

## 4. 测试策略与分层

> 校准来源：
> - `design-calibration/05_test_plan_step_04_strategy_layers.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“测试分层图”“高风险断言发现层级”和“E2E / Release Gate 使用边界”小节，了解为什么状态、UoW、no-write 和 redaction 不应只靠 E2E 发现。

测试分层以风险最早可发现位置为原则。Unit / Contract 发现 schema、状态和纯安全规则；Application service 发现编排、UoW、幂等、no-write 和 no-truth-repair；fake / controlled integration 发现 repository、adapter、rollback、builder 和 failure mapping；API / Worker / Job 验证入口 disposition；E2E / release gate 只验证最小跨入口闭环和证据完整性。

### 4.1 测试分层图

#### 测试分层图：L2-member-service 测试金字塔

```text
[Release gate / evidence summary]
  - minimal host-control smoke
  - profile / redaction / dependency / report checks
                ^
[API / Worker / Job entry]
  - command/query mapping
  - consumer/publisher/job disposition
                ^
[Integration with fake / controlled seams]
  - logical stores / UoW / revision / rollback
  - external availability / failure markers
                ^
[Application service]
  - command orchestration / query no-write
  - receipt / report / idempotency
                ^
[Unit / Contract]
  - refs / DTO / domain states / config / redaction
```

关键说明：

- 单元和服务层优先发现字段、状态、写集和边界错误。
- E2E 只证明最小组合链，不代表 sibling 正向合同、容器、Bus 或 Sandbox backend 已 ready。
- `integration-like` 使用 controlled seam；其结果不能升级为真实外部完成。

### 4.2 测试分层表

| 层级 | 目标 | 典型内容 | 执行时机 | 失败处理 |
|---|---|---|---|---|
| Unit / Contract | schema、ref、状态、纯规则 | DTO roundtrip、metadata、factory、state、digest、config parser、redaction | PR / local / CI fast | P0 阻断 |
| Application service | 编排、写集、幂等和安全读取 | 10 Command、6 Query、5 Consumer、stored result、Job report | PR / CI service | P0 阻断 |
| Integration fake / controlled | store / UoW / adapter / builder | revision、rollback、material/outbox、projection、failure injection | CI integration / replay | P0 阻断；P1 缺口记录 |
| API / Worker / Job | 入口和异步 disposition | handler、unsupported version、receipt、publisher、7 Job runner | CI entry / nightly | P0 阻断 |
| E2E / Release gate | 最小闭环与证据汇总 | intent→decision→qualification→safe view/material、profile/redaction/dependency | release candidate | 阻断送验 |

### 4.3 切口到层级映射

| 切口 | 主发现层级 | 辅助层级 | P0 失败是否阻断 |
|---|---|---|---|
| contracts / domain / state | Unit / Contract | Application | 是 |
| command / query / consumer | Application service | API / Worker | 是 |
| material / outbox / job | Integration / runner | Worker / release | 是 |
| consistency / idempotency / recovery | Application + integration | operations replay | 是 |
| config / redaction | Unit + builder | release scan | 是 |
| dependency boundary | Architecture check | release evidence | 是 |
| real-like sibling seam | controlled integration | selected release run | 否，除非后续升为 P0 |

### 4.4 高风险断言发现层级

| 高风险断言 | 最早发现层级 | 不应只靠 | 原因 |
|---|---|---|---|
| 非法状态迁移被接受 | Domain Unit | E2E | 状态矩阵和 policy 可直接判定 |
| accepted command 漏 sidecar/result | Application service | Release gate | 需要检查同一 UoW 写集顺序 |
| Query 修改 source/projection | Application + write audit | E2E | no-write 是负向副作用属性 |
| duplicate 从 current truth 重算 | Application service | API smoke | 需要控制 stored result 缺失 |
| old generation 覆盖 current | Service + integration | E2E | 需要 generation fixture 和并发写入 |
| adapter `Ok` 冒充完成 | Fake integration | Release gate | 需要注入 unknown / timeout |
| body / secret 泄漏 | Unit + artifact scan | 人工抽查 | 输出面需自动扫描 |
| 非 Core sibling compile dependency | Architecture check | E2E | 依赖图是静态风险 |

### 4.5 E2E / Release Gate 使用边界

| 场景 | 是否进入 | 只证明什么 | 不承担 |
|---|---|---|---|
| minimal host-control smoke | 是 | 入口组合和本地 safe material 流 | 不替代每个 Command / Query |
| profile matrix smoke | 是 | P0 profile 可装配或按规则拒绝 | 不替代 parser / validator unit |
| redaction artifact scan | 是 | 实际输出面无 forbidden body | 不替代 redaction helper |
| dependency boundary scan | 是 | compile seam 裁剪可留证 | 不替代架构审查 |
| full cross-repo E2E | P1/P2 | 真实协作差异 | 不作为当前 P0 前置 |

### 7.5 数据前置与清理规则

- 所有 revision、cursor、generation、digest、timestamp 和 ID 由注入 Clock / IdGenerator / builder 提供；handler 不自行合成。
- projection、history、outbox、report 只能通过其 owner 写入路径准备；不得直接写 source truth 以伪造前置。
- 真实 sibling 正文、credential value、endpoint、manifest、运行结果正文不进入 fixture；只允许安全 ref、summary、availability、freshness 和 reason ref。
- `deterministic_fixture.*` 只能由 `ci-test` test-entry 或 `operations-replay` replay run 构造；`local-dev` 和 `integration-like` 不得使用。
- 清理失败必须产出 safe cleanup issue；清理不得删除历史证据或跨 run 数据。

```text
  -> release-main-smoke
  -> redaction-boundary
  -> dependency-boundary
  -> artifact/report audit
```

关键说明：

- 图只表达计划 suite 关系，不锁 CI 产品、部署命令或 scheduler。
- 每个 gate 必须接收 `--run-id`、`--artifact-root`、`--config-profile`；正式路径不使用 `latest`。
- P1 selected run 不可用时保留 unavailable / residual，不能改写为 P0 passed。

## 11. 缺陷管理与复验规则

> 校准来源：
> - `design-calibration/05_test_plan_step_11_defects_retest.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“缺陷分级”“S 级阻断判定”“复验矩阵”“关闭规则”和“自动化防回归规则”小节，了解缺陷如何影响本仓 P0 门禁以及未闭合 sibling 合同如何保持 residual。

本章定义测试缺陷如何分级、升级、修复、复验和关闭。缺陷管理必须保护 `VF-MS-001~009`、Host Truth / owner truth 边界、Query no-write、Job no-truth-repair、generation / effect key fence、redaction、dependency boundary 和 evidence integrity 红线，不得通过改名、静态报告或人工说明降级。

本章不定义工单平台字段、负责人排期、验收裁决、正式 EV 实例或风险签署；正式证据结构由 §13 定义，验收裁决由后续 `06-验收标准.md` 承接。

### 11.1 缺陷分级

| 级别 | 定义 | 本仓示例 | 处理要求 | 是否阻断 |
|---|---|---|---|---|
| S | 违反一票否决、破坏 P0 truth / safety boundary、或使证据失真 | 非 ProjectMember 主语创建 Host；required binding 缺失仍 `Ready`；raw secret/body 泄漏；Query/Job 反写真相；第二 current host；静态 evidence 宣告通过 | 立即阻断；修复设计/实现或测试门禁；全量 P0 复验；不得风险接受 | 是 |
| A | P0 主线或一致性失败但尚未直接命中不可接受红线 | accepted Command 少写 sidecar；old generation 覆盖 marker；UoW rollback 泄漏；immutable material 可变；报告字段与真实 case 不一致 | 修复后跑原用例、同族用例及受影响 suite；release 前必须关闭或升级 | 是，直到复验 |
| B | 非 P0 或局部质量问题，不改变 truth、边界和证据语义 | 非关键 safe view 排序；诊断文案不清；P1 controlled seam 局部映射不足 | 建立记录并排期；保留影响范围；不得影响 P0 结论 | 否 |
| R | 已确认范围外、依赖合同未闭合或未来能力风险 | `MSVC-UP-001~008` 正向联调 unavailable；真实存储 / Bus / Sandbox / observability 产品未锁定；性能 authority 缺失 | 记录 blocked/waiting/unavailable、owner 和触发条件；不得写成 defect fixed、pass 或 ready | 视影响；对应 P0 正向路径保持阻断 |

### 11.2 S 级阻断判定

以下任一条件均判为 S，不得降级为 A/B/R：

| 触发条件 | 相关断言 / 来源 | 判定 |
|---|---|---|
| `VF-MS-001~009` 任一红线实际违反 | §2.5、§5.4、§10.3 | S |
| ProjectMemberRef / GlobalMemberRef / scope / authorization 被绕过，或非项目主语创建、迁移、停止宿主 | `TC-DOMAIN-001`、`TC-INTENT-*`、`VF-MS-002` | S |
| required qualification / binding / credential / pinned asset 缺失、stale、unknown 仍推导 `Ready` 或 fallback | `TC-DOMAIN-003`、`TC-QUAL-*`、`TC-CONFIG-005`、`VF-MS-004` | S |
| Host Truth、外部 owner truth、attempt、receipt、delivery、observed、accepted 或 projection 语义混层 | `TC-MATERIAL-001`、`TC-IDEMP-010`、`VF-MS-003/007` | S |
| Query 写入、Job 创建 intent/decision/generation/new key，或 projection / reconciliation 反写 source | `TC-QUERY-NEG-001`、`TC-JOB-NEG-001`、`VF-MS-006/007` | S |
| duplicate / concurrent / late / unknown 导致第二 current、第二 active session、盲重放或历史抹写 | `TC-STATE-003`、`TC-IDEMP-*`、`VF-MS-006` | S |
| forbidden body、secret、credential、manifest、endpoint、stack 或外部正文进入 store/log/report/outbox/trace/artifact | `TC-REDACTION-*`、`VF-MS-005` | S |
| 非 `L0-core` / 已批准 core-contract 的 sibling 被加入 compile graph，或 runtime/event/ref/adapter/fake 被伪装成 compile | `TC-ARCH-001`、`VF-MS-008` | S |
| evidence index 缺 raw artifact/report、存在 orphan EV、失败 suite 被手写为 passed 或使用 `latest` | `TC-REPORT-001`、`VF-MS-009` | S |

### 11.3 修复后复验矩阵

| 缺陷触发面 | 必跑最小集合 | 额外检查 | 关闭证据 |
|---|---|---|---|
| subject / control / decision | `TC-INTENT-*`、`TC-DECISION-*`、`TC-IDEMP-001~003` | dependency / redaction（若边界或输出改变） | core + command suite artifact/report |
| qualification / assembly / readiness | `TC-QUAL-*`、`TC-ASSEMBLY-*`、`TC-DOMAIN-003`、`TC-CONFIG-*` | config-redline、redaction-boundary | assembly + config evidence |
| registration / endpoint / session | `TC-REG-*`、`TC-SESSION-*`、`TC-CONSUMER-002`、`TC-IDEMP-007` | generation / single-active assertion | session + recovery evidence |
| health / recovery | health state cases、`TC-RECOVERY-*`、`TC-IDEMP-005~008` | operations-replay-core | health + recovery evidence |
| closure / cleanup / reconciliation | `TC-CLOSE-*`、`TC-JOB-003/004/007` | handoff layer and redaction checks | closure + handoff evidence |
| material / outbox / projection | `TC-MATERIAL-*`、`TC-JOB-005/006`、`TC-IDEMP-009/010` | report pairing; cursor separation | material/outbox/projection report |
| Query no-write / Job no-repair | `TC-QUERY-001~006`、`TC-QUERY-NEG-001`、`TC-JOB-NEG-001` | write spy and source revision diff | write-audit artifact/report |
| config / redaction / dependency | `TC-CONFIG-*`、`TC-REDACTION-*`、`TC-ARCH-001` | release checks | config/redaction/architecture evidence |
| report / evidence integrity | `TC-REPORT-*` and report audit checks | pairing + no-static-evidence | report-audit artifact/report |

默认复验顺序为：原失败 case → 同一 TC family 的正向/负向/duplicate/unknown 代表项 → 受影响 suite → 全量 P0。涉及 state、UoW、idempotency、owner boundary、redaction、dependency 或 evidence integrity 的 S 级修复，直接触发全量 P0。

### 11.4 复验与关闭规则

1. 缺陷记录必须关联失败前的 `run_id`、suite、case、artifact path、report path 和 safe failure reason；截图或聊天结论不能单独作为关闭依据。
2. 修复后必须生成新的 run 和新的 artifact/report/evidence 实例；不得覆盖历史运行或复用 `latest`。
3. 若原因属于 `MSVC-UP-001~008`、产品未锁定或 exact contract 未闭合，应记录为 R 级 blocked/waiting/unavailable，不得写成“已修复”。
4. same key / same digest 的复验必须证明精确 replay；different digest、in-flight、commit unknown、rollback unknown 必须保留原 key 并进入 conflict/hold/reconcile。
5. 关闭至少需要：复验结果、raw artifact、run report、evidence index 更新、受影响 TC/AC/VF 追溯，以及必要的 reviewer note。
6. S 级、forbidden output、owner truth 越界、Query/Job 反写真相、静态造证据均不可风险接受。

### 11.5 风险接受规则

| 项 | 是否可接受 | 条件 |
|---|---|---|
| S 级缺陷或 `VF-MS-*` 实际违反 | 否 | 必须修复并全量 P0 复验 |
| P0 redaction / dependency / evidence integrity 失败 | 否 | 必须保留失败材料并修复门禁 |
| P0 blocking suite 因测试工具自身缺陷不稳定 | 原则上否 | 仅可暂记 A；须有独立安全 artifact 证明并修复工具 |
| P1 real-like seam unavailable | 是，作为 R | 不计 P0 通过；记录 owner、影响和触发条件 |
| 性能 / 容量候选未达但无 authority | 是，作为 R | 保留 sample/trend；不得写硬阈值结论 |
| B 级可维护性或报告文案问题 | 是 | 不影响 raw artifact、断言和追溯 |

#### `meta/context.json`

| 字段 | 必填 | 类型 / 约束 |
|---|---|---|
| `schema_version` | 是 | `member_service.artifact.v1` |
| `run_id` | 是 | 固定且非 `latest` 的 run id |
| `suite_refs` | 是 | suite 字符串数组 |
| `config_profile` | 是 | P0 profile 或 future approved profile |
| `started_at` | 是 | timestamp |
| `tool_version` | 是 | gate/report writer 版本或安全 source ref |
| `redacted_environment` | 是 | 仅允许 safe key / safe value |
| `artifact_root` | 是 | `artifacts/test/<run_id>` |
| `report_root` | 是 | `reports/runs/<run_id>` |
| `artifact_digest_algorithm` | 是 | `sha256` |

### 13.4 Evidence index 最小字段

根对象最少包含：

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | 是 | `member_service.artifact.v1` |
| `run_id` | 是 | 固定 run id，不得为 `latest` |
| `items` | 是 | 只能从真实 raw artifact / generated report 关系推导 |
| `artifact_digest_algorithm` / `artifact_digest` | 是 | sha256 |

每个 evidence item 最少包含：

| 字段 | 必填 | 约束 |
|---|---|---|
| `evidence_id` | 是 | `EV-MS-*` |
| `suite` | 是 | 真实来源 suite / check |
| `status` | 是 | `passed` / `failed` / `partial` / `skipped` / `unavailable` / `not_run` |
| `blocker_status` | 条件 | `blocked` / `waiting` / `pending`；不得替代真实执行状态 |
| `tc_refs` | 是 | `TC-*` |
| `ac_refs` | 是 | `AC-MS-*`；供新版 `06` 消费 |
| `veto_refs` | 条件 | 涉及 `VF-MS-*` 时必填 |
| `artifact_path` | 是 | `artifacts/test/<run_id>/...` |
| `report_path` | 是 | `reports/runs/<run_id>/...` |
| `artifact_digest` | 是 | source raw artifact digest |
| `generated_from` | 是 | 生成脚本和输入 artifact refs |
| `redaction_status` | 是 | `clean` / `failed` / `not_applicable` |
| `review_status` | 是 | `pending` / `reviewed` / `disputed` |

Evidence index 必须由 raw artifact、suite report 和生成脚本关系推导。静态映射表只能提供证据族候选，不能生成 `passed` item；缺 artifact、report、digest、TC/AC/VF 追溯或 redaction 状态时，item 只能为 incomplete/failed/unavailable 的报告结论，不能为 passed。

### 13.5 Digest 与真实性规则

- P0 artifact digest algorithm 固定为 `sha256`；输入为移除自身 `artifact_digest` 字段后的 canonical UTF-8 JSON，object key 按 lexicographic order，array 保持存储顺序。
- stdout/stderr 必须先脱敏再保存；suite report 只引用其 digest，不内嵌完整日志或 raw JSON。
- material、outbox、handoff、case 和 report 的 evidence snapshot 必须来自已保存对象，不从 current truth 现查现组包。
- evidence index 只能由真实 artifact/report pair 推导，不能消费手写默认状态、静态 pass JSON 或 `latest` 指针。
- failed、partial、unavailable、not_run 的 suite 仍必须按适用范围保留 report、case、stdout/stderr、blocker marker 和 safe failure reason。
- 任何 raw secret/body/manifest/endpoint/stack 泄漏使对应 evidence 的 redaction 状态为 failed，并阻断其作为验收正向证据。

| 报告 | 输入 | 计划脚本 | 输出 | 审查要求 |
|---|---|---|---|---|
| suite report | suite `report.json` + case artifacts | `scripts/reports/generate_reports.sh` | `reports/runs/<run_id>/suites/<suite>.md` | 检查 case refs、safe failure reason 和 blocker 分类 |
| gate results | suite reports | `scripts/reports/build_gate_summary.sh` | `reports/runs/<run_id>/gate-results.md` | 检查 blocking / non-blocking 与 P0/P1/P2 边界 |
| evidence index | raw artifacts + reports | `scripts/reports/generate_evidence_index.sh` | `reports/runs/<run_id>/evidence-index.md` | 检查 EV/TC/AC/VF/path/digest 配对 |
| redaction report | artifact/report scan | `scripts/checks/check_redaction.sh` | `reports/runs/<run_id>/redaction-check.md` | 扫描 artifacts、reports 和脱敏 logs |
| dependency report | dependency graph artifact | `scripts/checks/check_dependency_boundary.sh` | `reports/runs/<run_id>/dependency-boundary.md` | 证明 compile/runtime/event/ref/adapter/fake 分类 |
| report audit | raw/report pairing | `scripts/checks/check_artifact_report_pairing.sh`; `scripts/checks/check_no_static_evidence.sh` | `reports/runs/<run_id>/report-audit.md` | 阻断 orphan EV、静态 evidence 和缺失 pair |
| acceptance handoff | run reports + evidence index + residual | `scripts/reports/generate_acceptance_handoff.sh` | `reports/acceptance/handoff.md` | 只生成待审初稿；不得默认通过 |
| veto checklist draft | evidence index + VF / defect / audit | planned `generate_veto_checklist.sh` | `reports/acceptance/veto-checklist.md` | 每个 VF 必须等待真实 evidence 与人工裁决 |
| risk acceptance draft | residual / unavailable markers | planned `generate_risk_acceptance.sh` | `reports/acceptance/risk-acceptance.md` | 必须列 owner、范围、触发条件 |
| open issues draft | defects + failed / pending reports | planned `generate_open_issues.sh` | `reports/acceptance/open-issues.md` | 不得遗漏 S/A blocker |

上述脚本和输出均为 planned contract，不表示脚本、实现仓、运行目录或报告当前已存在。

### 13.7 失败 suite 与审查补充

| 失败 / 未执行类型 | 必须保留 | 禁止行为 |
|---|---|---|
| assertion failed | report、case、stdout/stderr、safe failure reason | 删除失败材料或改写 passed |
| config invalid / builder unavailable | validation artifact、safe issue ref | 输出 env、secret、endpoint 值或 fallback 通过 |
| redaction leak | failed scan artifact、脱敏诊断 | 回显 sentinel/body 或忽略失败 |
| dependency violation | dependency graph、safe offending ref | 隐藏 edge 或生成 passed VF |
| report generation failed | partial audit、缺失路径清单 | 手写 evidence index 补洞 |
| sibling positive unavailable | unavailable / blocker marker、受影响 TC/AC | 计为 P0 passed、ready 或“已修复” |

人工或 Agent 审查只能解释运行范围、边界、争议和 residual，不能替代 raw artifact：

| 审查材料 | 审查重点 | 可否替代 raw artifact |
|---|---|---|
| `reports/acceptance/handoff.md` | source refs、运行范围、P0/P1/P2、未覆盖项 | 否 |
| `reports/acceptance/veto-checklist.md` | 每个 VF 是否有真实 EV 和 raw artifact | 否 |
| `reports/acceptance/risk-acceptance.md` | residual 的 owner、影响、触发条件 | 否 |
| `reports/acceptance/open-issues.md` | S/A blocker、failed suite、missing report | 否 |
| `reports/review/reviewer-notes.md` | 人工评审结论和争议 | 否 |
| `reports/review/agent-review.md` | 追溯、redaction、boundary、static evidence 复核 | 否 |

## 14. 回归策略与残余风险

> 校准来源：
> - `design-calibration/05_test_plan_step_14_regression_risks.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“回归触发表”“全量 P0 回归集”“最小回归选择规则”“残余风险表”“不可风险接受项”和“必须转入新版 `06-验收标准.md` 的事项”小节，了解设计、实现、配置、测试和证据变化如何触发回归，以及未闭合合同如何进入后续验收。

本章定义 `L2-member-service` 在需求、架构、详细设计、配置、实现、测试门禁或证据脚本发生变化时的回归策略，并汇总当前不阻断 product-neutral P0 设计、但必须交给 `06` / `07` 或后续运维承接的 residual。本章不执行回归、不填写真实缺陷状态、不裁决 release pass/fail，也不替代 `06` 的风险接受流程。

### 14.1 回归触发表

| 变更类型 | 最小回归集 | 全量 P0 触发条件 | 责任 owner |
|---|---|---|---|
| `contracts` ref / DTO / error / schema | `contract-domain-fast`、`entry-worker-job` | public field/enum/version、metadata、digest 或 redaction 边界变化 | contracts owner |
| domain object / policy / state | `contract-domain-fast`、`service-flow-fast` | state axis、owner、invariant、generation 或 no-fallback 变化 | domain owner |
| Command / application flow | `service-flow-fast`、`release-main-smoke` | UoW 写集、sidecar、idempotency、phase 或 accepted disposition 变化 | application owner |
| Query / projection / history | `service-flow-fast`、`operations-replay-core` | no-write、cursor、visibility、freshness 或 source relation 变化 | application / query owner |
| Consumer / worker / publisher | `entry-worker-job`、`operations-replay-core` | envelope、receipt、outbox snapshot、publication / handoff layer 变化 | worker owner |
| Operations Job / selector / report | `entry-worker-job`、`operations-replay-core` | job authorization、stable key、report schema 或 no-truth-repair 变化 | jobs owner |
| persistence / UoW / store | `infra-runtime-fake`、`service-flow-fast` | revision、rollback、cursor、logical owner、atomicity 或 commit-unknown 变化 | infra owner |
| adapter / sibling seam | `infra-runtime-fake`、affected negative suites | availability、error mapping、opaque ref、exact contract 或 body boundary 变化 | adapter / contract owner |
| config / profile / sensitive value | `config-redline`、`redaction-boundary`、`release-main-smoke` | P0 profile、source priority、builder、fixture guard、sensitive class 或 fail-fast 变化 | config owner |
| observability / artifact / report | `redaction-boundary`、`dependency-boundary`、report audit | evidence schema、path、digest、redaction、label allowlist 或 gate behavior 变化 | test / evidence owner |
| S 级缺陷修复 | 原失败 TC、同族 suite、release checks | 任一 VF、truth boundary、redaction、dependency 或 evidence integrity 修复 | responsible owner + reviewer |

任一变更若同时影响两个或更多主线（例如 generation 与 outbox、config 与 redaction、projection 与 report），取各最小回归集的并集，不得只跑单一代表 case。

### 14.2 全量 P0 回归集

全量 P0 regression 至少包括：

1. `contract-domain-fast`
2. `service-flow-fast`
3. `infra-runtime-fake`
4. `entry-worker-job`
5. `operations-replay-core`
6. `config-redline`
7. `redaction-boundary`
8. `dependency-boundary`
9. report-audit checks（artifact/report pairing、no-static-evidence、evidence index integrity）
10. `release-main-smoke`
11. release redaction / dependency checks
12. evidence index generation 和 review-ready acceptance handoff draft

以下情况必须触发全量 P0：

- 任一 `VF-MS-001~009` 相关修复或语义变化。
- `03-详细设计.md` 对对象、协议、函数流、状态矩阵、UoW、幂等、material/outbox、Job report、redaction、配置或观测口径的变化。
- `04-配置设计.md` 对 P0 profile、source priority、binding availability、fixture guard、fail-fast / degraded 规则的变化。
- 任一 S 级缺陷修复，或 evidence / report / gate 逻辑发生可能影响结论真实性的变化。

每次回归必须生成新的固定 `run_id`，写入新的 `artifacts/test/<run_id>` 和 `reports/runs/<run_id>`；不得覆盖旧 run 或引用 `latest`。

### 14.5 不可风险接受项

以下事项不得以任何角色的风险接受替代修复、重设计或重新回归：

- `VF-MS-001~009` 任何实际违反。
- forbidden body、secret、credential、endpoint、manifest、stack 或外部正文泄漏。
- 非 ProjectMember 主语、scope 不匹配或未授权输入创建、迁移、停止、重启宿主。
- required seam 缺失仍产生 `Ready`，或 Query / Job / projection / reconciliation 反写真相。
- duplicate / unknown 盲重放不可逆动作、第二 current host / active session、旧 generation 覆盖 current 或历史抹写。
- fake、placeholder、planned、blocked、unavailable 被写成真实 ready、evidence、verdict 或 signoff。
- evidence index 缺 raw artifact/report、digest 或追溯关系却宣告通过，或用 `latest` 指向证据。

### 14.6 必须转入新版 `06-验收标准.md` 的事项

| 事项 | 交给 `06` 的内容 |

| P1/P2 residual | 风险接受人、影响范围、触发条件和 selected-run 要求 |
| evidence integrity | raw artifact/report pairing、redaction、digest、no-static-evidence |
| performance candidate | workload、authority、环境、统计口径齐备后才可量化 |
| retention / approval role | 证据保留期限、验收与风险接受角色和签署条件 |

### 14.7 回归证据归档规则

| 回归类型 | 证据要求 |
|---|---|
| 最小回归 | 生成新的 run artifact、受影响 suite report、evidence index；标记 regression scope |
| 全量 P0 回归 | 完整 `reports/runs/<run_id>/`、acceptance handoff draft、redaction/dependency/report audit |
| 缺陷复验 | 关联 failed run、fixed run、原 TC、复验 suite、是否新增防回归测试 |
| residual review | 生成 `reports/acceptance/risk-acceptance.md` 和 `reports/review/*` 补充 |
| sibling positive unavailable | 生成 unavailable/blocker marker，不计入 P0 passed evidence |

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L2-member-service` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L2-member-service` 是成员执行宿主仓,不是 runtime、tools 或 sandbox 的附属层
- MemberExecutionHost / session / worker / health 构成正式宿主真相层
- `MemberExecutionHost ≠ ExecutionInstance`、`host failure ≠ business execution failure` 两条核心边界必须成立
- capability / tool scope / actor context / sandbox bind 形成正式装配结果,且未 bind 完成不得执行动作
- runtime action 能被正式承接到宿主层执行,并形成 execution handle
- host crash / restart / recycle / recoverable host fault 可以被正式区分和处理
- runtime 消费的是正式 callback material,而不是原始宿主日志

因此,本次验收的目的不是笼统判断“能不能跑一个 worker”,而是判断 member-service 的宿主真相、装配边界、动作承接、宿主恢复和正式反馈是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 成员执行宿主与运行会话部分 | 是 | host / session / worker / health |
| 能力挂载与上下文绑定部分 | 是 | capability / tool scope / actor / sandbox bind |
| 动作承接与实际执行部分 | 是 | runtime action intake / host dispatch / execution handle |
| 失败、重启与宿主恢复部分 | 是 | host crash / restart / recycle / recoverable fault |
| 执行反馈与宿主观测接缝部分 | 是 | callback material / health report / metrics |
| 工具内部逻辑与 sandbox 内部算法 | 否 | 只验 member-service 与能力层接缝,不验能力内部实现 |
| runtime / work / process / governance / artifact 全部内部正文逻辑 | 否 | 只验 member-service 与它们的接缝,不验下游仓全部细节 |
| 前端 UI 展示细节 | 否 | 只验证 callback / health / view 材料,不验 UI 组件 |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| bind 未完成不可执行 | 未完成 capability / tool scope / sandbox bind 的宿主不得执行正式动作 | negative flow / bind trace | [] |
| host failure 不可替代 business failure | 宿主故障只能作为 member-service 正式反馈,不得直接篡改 runtime 执行业务真相 | failure compare / runtime callback trace | [] |
| callback material 不可被原始日志替代 | runtime 正式消费路径必须落在 callback material 上 | consume path compare / model review | [] |
| recycled host 不可复用旧 session/handle | 回收后旧句柄必须失效 | handle invalidation trace | [] |
| capability mount 不可反写 capability 定义真相 | 宿主装配结果不能被误当 identity/tools 真相来源 | binding compare / negative test | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | Host truth 与 execution truth 混层 / bind 未完成仍执行 / host failure 替代 business failure / callback material 不正式回流 |
| A | 视情况 | 主线可跑但 host restart/recycle/bind/callback 语义不稳 |
| B | 可带着走 | 非关键健康视图、日志材料或低优先级查询异常 |

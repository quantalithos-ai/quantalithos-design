### 6.3 Boundary 开工前设计闭环

每个 boundary 开工前，设计者和实现者都必须复核下表。设计者负责先闭口；实现者只做二次校验，发现不一致时以 `blocked / wait_design` 回报。

| 复核项 | 必须确认 | 失败处理 |
|---|---|---|
| 字段 / DTO / 状态 | 必填字段、variant、source、validation、合法迁移和测试名称一致 | 回写 `03/05/06`，不在代码临时补字段 |
| ref identity / scope | `ProjectMemberRef + GlobalMemberRef`、generation、target、correlation 各有唯一 owner | 暂停；禁止字符串拼接或第二 truth |
| validation truth | owner、freshness、version、scope 有正式 resolver 或 safe input | 保持 blocked/unknown，回写 03 |
| metadata / idempotency | operation context、digest、reservation、stored result、UoW 顺序闭合 | durable/receipt 缺口为 blocker |
| cursor / consistency | `HostChangeCursor` 与 `CommittedChangeCursor` 不 alias；sidecar 缺失进入 consistency defect | 不造第三 cursor，不从 current truth 重算 |
| state / history | domain transition、history/material/outbox 写集与 rollback 窗口一致 | 回写 03；不得绕过 domain |
| projection / query | committed source、freshness、degraded、rebuild source、no-write 已固定 | Query 写入即阻断 |
| job / evidence | selector、report、artifact root、run pairing、redaction、no-truth-repair 已固定 | 无 run 不生成 evidence |
| phase boundary | 不引用 successor 的对象、结果、授权或 evidence | 重切 boundary 或回写 07 |
| Rust / naming | public Rustdoc、标识符、测试名英文；无 L0/L1/L2 命名泄漏 | PH-01 或相关 boundary 阻断 |

## 10. 回退、暂停与变更控制

> 校准来源：
> - `design-calibration/07_implementation_plan_step_10_rollback_pause_change_control.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“暂停规则表”“回退规则表”“变更控制表”和“恢复实施流程”小节。

### 10.1 必须暂停的情形

- 目标实现仓、Core baseline、字段、DTO、状态、Port、scope、version、cursor、写集、config binding、job report 或 evidence source 无法 1:1 回指正式设计。
- 当前改动越过 allowed scope、混入用户未授权改动或提前使用 successor phase 的对象/结果/evidence。
- blocking suite、redaction、dependency、report audit、release smoke 或 VETO 失败。
- sibling、broker、store、sandbox、member、images、runtime 或 observability unavailable 且没有正式 disabled/blocked 姿态。

暂停时必须在项目级与 boundary 级台账记录行号、错误、diff 范围、失败 artifact/report、owner 和建议回写点。不得用临时字段、临时状态、假 adapter、换 effect key 或 current truth 重算继续。

### 10.2 回退规则

当前 boundary 未提交失败时，只回退该 boundary 的授权改动；不得破坏其他 phase、用户改动或已验证提交。已提交 boundary 的设计缺口优先新增修复提交或回写设计；未经用户明确不得 amend、rebase、reset 或删除失败证据。修复后必须固定新 baseline 和新 run_id，再重跑受影响 gate。

### 10.3 变更传播

| 变更 | owning source | 传播 |
|---|---|---|
| object/protocol/flow/state/persistence/idempotency | `03-详细设计.md` | boundary、05、06、07 controlled reopen |
| profile/default/adapter/CLI/env/secret | `04-配置设计.md` | config gate、boundary baseline |
| suite/TC/artifact/report/gate | `05-测试方案.md` | 07 gate matrix、06 evidence |
| AC/VF/risk/final decision | `06-验收标准.md` | completion/handoff |
| phase/boundary/order/commit | `07-实施计划.md` | project/boundary ledger |
| reusable experience | standards/SOP/project memory | 先判断归属，再补标准/示例 |

### 10.4 恢复流程

```text
blocker recorded
  -> owning source fixed or explicitly remains blocked
  -> new design baseline fixed
  -> current boundary Design/Scope Gate repeated
  -> worktree scope checked
  -> failed gate rerun with new run_id
  -> Commit/Handoff Gate
  -> successor activation
```

## 11. 提交、评审与交付纪律

> 校准来源：
> - `design-calibration/07_implementation_plan_step_11_commit_review_delivery.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“提交纪律”“Commit message 结构”“Boundary 到 body 分组映射”“Commit/Handoff Gate”和“交付检查表”小节。

### 11.1 提交规则

未来实现仓一笔 commit 对应一个 §6 boundary。标题固定英文 `type(scope): subject`，scope 必填；body 英文，第一段说明 boundary summary，随后按子功能分组列文件名与近似改动量；禁止字面量 `\\n`、完整文件路径和 bullet 间空行；footer 前须有真实空行并使用 `Co-Authored-By: Codex <noreply@openai.com>`。当前 design 仓本轮不提交；若未来仅提交文档，英文 type、中文 subject/body 的项目规则只能作用于 design 仓。

允许 type：`feat`、`fix`、`refactor`、`docs`、`test`、`chore`、`perf`、`ci`、`style`。scope 应与 boundary 功能一致，如 `workspace`、`config`、`control`、`qualification`、`assembly`、`host`、`session`、`health`、`recovery`、`closure`、`reconcile`、`material`、`projection`、`query`、`consumer`、`publisher`、`job`、`release`、`report`、`handoff`。

### 11.2 合格与不合格示例

合格示例：

```text
feat(session): wire host session application slice

Wire the host session slice for PH-03 commit-03-c:

Session application and fake seam:
- services.rs (~+80/-0): assemble the planned session use case.
- fake_session.rs (~+65/-0): preserve generation and duplicate semantics.

Entry and negative tests:
- command_handlers.rs (~+40/-0): map safe outcomes without runtime body.
- session_tests.rs (~+90/-0): cover stale and cross-generation registration.

Co-Authored-By: Codex <noreply@openai.com>
```

不合格示例：

```text
feat(session): add changes\n\n- crates/member/src/session.rs: done
```

原因是使用了字面量 `\\n`、完整路径、无 boundary summary、无子功能分组和无 footer 空行。需要精确控制格式时，先写 message 文件，再使用 `git commit -F <message-file>`。

### 11.3 评审与交付检查

评审必须覆盖 truth owner、字段/DTO/状态/Port、UoW/revision/idempotency/cursor、redaction、phase boundary、dependency edge、staged scope 和 evidence pairing。Commit Gate 必须检查 git identity、fmt/check/test、staged diff、message、whitespace、设计同步和适用 artifact/report；Handoff Gate 必须回写 commit hash、design baseline、next boundary、未跑检查、blocker、user changes、recovery point 和 ledger。

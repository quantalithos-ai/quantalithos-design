## 3. SOP 问题回答

1. 当前按哪些核心能力节点组织故事？

   回答：严格按 C-MS-1 宿主意图与执行主语、C-MS-2 宿主装配与隔离就绪、C-MS-3 注册与运行会话、C-MS-4 健康恢复与终止、C-MS-5 生命周期闭合五个节点组织。故事不是运行时步骤链。

2. 哪些角色目标支撑核心闭环？

   回答：宿主意图触发方需要安全受理；正式事实提供方需要 owner-safe 消费；宿主内来源需要可信注册和健康表达；平台运维 / SRE 需要可判定的装配、恢复与清理；调查者和安全审查者需要失败分层、边界与历史可追溯；宿主事实消费方需要稳定的 safe handoff。

3. 哪些目标只是外围增强？

   回答：跨宿主容量 / 放置优化、镜像预热、丰富 forensic 关联和聚合 safe view 不决定基础宿主闭环是否成立，单列为外围增强。

4. 哪些看起来像故事但不应进入本仓？

   回答：run / goal / plan / checkpoint、member 内部门面、工具执行、镜像构建、隔离 enforcement、身份 / 工作 / 治理 truth、observability backend、编排平台产品管理以及当前版非项目型宿主均为边界外或未来范围，见 §7。

5. 当前节点故事是否足以进入功能需求讨论？

   回答：是。每个节点有三条互不重复的目标级核心故事，均有唯一主节点；字段合同 pending 只限制后续协议和 readiness 声明，不阻止需求级故事成立。

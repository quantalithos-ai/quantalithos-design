## 1. 与 `product/` 的关系声明

L2-member 是**运行时能力型**需求仓。它不直接对终端用户暴露,而是平台里每个 AI 成员容器中的“门面进程”。

| 章节 | 本文来源 | 对应文档 |
|---|---|---|
| 背景与问题 | `architecture/ai-member设计.md` §三 六子模块 | ai-member 设计 |
| 目标 | launch_token / Event Subscriber / Publisher / UDS / attention / external rpc | 同上 |
| 功能需求 | B1-B6 六子模块落地 | README |
| 非功能需求 | 低延迟、崩溃可恢复、Prompt Injection 预过滤 | README + 安全红线 |

## 2. 背景与问题定义

### 2.1 业务背景

AI 成员容器里不只有一个 runtime 进程。为了把:
- 身份与角色
- 入站事件筛选
- 出站事件发布
- member-service 心跳与注册
- Prompt Injection 预过滤
- IPC(和真正思考执行的 Runtime 进程通信)

这些能力从“大脑”里拆出去,需要一个**门面进程**。这就是 `quantalithos-member`。

它像人的"嘴耳"——负责听、说、连接外界,但不负责思考。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `architecture/ai-member设计.md` 已把 B1~B6 讲清 | 仓级需求层还没成文 |
| 事件过滤 | Prompt Injection 组合防御只在设计里 | 无仓级验收标准 |
| IPC | 只在设计里说 UDS gRPC | 接口边界未固化到仓级需求 |
| member-service | 只在设计里说 external rpc | 责任边界未在仓级需求中明确 |

### 2.3 为什么要做(量化依据)

- 没有 member 门面进程,runtime 要同时承担身份、网络、发布/订阅、心跳、attention 等职责,会变成过厚的“万能进程”
- 所有 AI 成员容器都要跑它,它是 **L2 五仓里的运行时入口层**
- README 目标明确:订阅到过滤 P95 < 20ms,发布到 bus P95 < 50ms,heartbeat < 5ms

### 2.4 业务问题 vs 技术问题

- **业务问题**:如何让 AI 成员安全、稳定、可审计地接入整个系统
- **技术问题**:六子模块拆分、launch_token、bus 过滤、Prompt Injection 预过滤、UDS IPC、member-service 心跳

### 4.1 目标用户群体

| 用户类型 | 描述 | 使用场景 |
|---|---|---|
| Runtime 进程 | 容器内大脑 | 通过 IPC 与门面通信 |

### 4.2 角色权限矩阵

| 读写外部网络事件 | 只通过 member | ✅ | ❌ | ✅ |
| 修改 attention 规则 | ❌ | ❌ | ✅ | ❌ |

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 成员容器启动时校验 launch_token,建立身份卡
2. 订阅 bus 事件,做 attention 预过滤后投递给 runtime
3. runtime 通过 IPC 发请求到 member 门面,再由门面对外发布事件
4. member 定期向 member-service 发心跳和状态
5. 遇到 Prompt Injection / 高危输入时预过滤并告警

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **Runtime**,我想要 **通过 UDS IPC 与 member 门面通信**,以便 **不直接接触外部网络和 bus 协议** |
| 优先级 | P0 |
| 验收条件 | **Given** runtime 进程已启动 **When** 通过 UDS 发请求 **Then** member 正确转发并返回结果 |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **member-service**,我想要 **收到 member 的 register / heartbeat**,以便 **维护容器注册表和健康状态** |
| 优先级 | P0 |
| 验收条件 | **Given** member 启动 **When** 发 register/heartbeat **Then** member-service 记录成功 |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **平台安全系统**,我想要 **在 Runtime 收到危险输入前先做 Attention 预过滤**,以便 **减少 Prompt Injection 风险** |
| 优先级 | P0 |
| 验收条件 | **Given** 一个命中规则的危险输入 **When** 事件进入 member **Then** 被标注/阻断/降级并发审计事件 |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **SRE**,我想要 **在 member 崩溃时让 supervisord 捕获并重启**,以便 **不出现静默死亡** |
| 优先级 | P1 |
| 验收条件 | **Given** member 进程崩溃 **When** supervisord 检测 **Then** 自动重启并发失败事件 |

### 5.3 辅助流程

- 初始化身份卡(identity + role + member_id)
- bus 订阅过滤(consumer_group / type patterns)
- 发布 CloudEvents
- member-service external rpc

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 类型 | 生命周期 |
|---|---|---|
| IdentityCard | 内存对象 | 启动后常驻 |
| SubscriptionState | 内存对象 | 运行期 |
| PublishEnvelope | 临时对象 | request-scope |
| HeartbeatState | 内存对象 | 运行期更新 |

### 9.2 数据关系

```
Member Process
  ├─ IdentityCard
  ├─ SubscriptionState
  ├─ Attention pipeline
  ├─ IPC session(s)
  └─ HeartbeatState
```

### 9.3 数据生命周期与归档

主要是运行期内存态,持久化依赖下游:
- 事件日志 → observability
- 注册状态 → member-service
- 本地 crash 不保状态,靠 runtime / bus 重建

## 10. 接口与依赖

### 10.1 外部系统依赖列表

| 依赖 | 类型 | SLA 要求 | 降级策略 | 文档 |
|---|---|---|---|---|
| `quantalithos-core` | proto / ErrorCode / CloudEvent | 100%(编译期)| 版本锁 |
| `quantalithos-bus` | 订阅 / 发布 | 99.95% | reconnect / backlog |
| `quantalithos-member-service` | register / heartbeat | 99.9% | retry + local degraded state |
| supervisord | 进程管理 | 高 | crash restart |
| runtime(同容器) | IPC peer | 高 | restart / reconnect |

### 10.2 上下游接口约定

**上游**:
- core(proto, CloudEvent, ErrorCode)
- bus(订阅 / 发布)
- member-service(register / heartbeat)

**下游**:
- runtime(UDS IPC)
- observability(审计事件)
- conversation(间接通过 bus)

## 11. 验收标准

### 11.1 功能验收标准

| 功能 ID | 验收场景 | Given-When-Then | 执行方式 |
|---|---|---|---|
| F-001 | launch_token 校验 | **Given** 一个无效 token **When** member 启动 **Then** 立即失败且不进入 active loop |
| F-002/F-003 | 订阅/发布 | **Given** bus 正常 **When** member 订阅和发布 **Then** 收发事件成功 |
| F-004 | register / heartbeat | **Given** member 启动 **When** 连接 member-service **Then** 周期性 heartbeat 成功 |
| F-005 | attention 过滤 | **Given** 命中高危输入 **When** 经过 attention pipeline **Then** 阻断或降级 |
| F-006 | UDS IPC | **Given** runtime 已启动 **When** 发 gRPC over UDS **Then** 返回正确响应 |

### 11.2 非功能验收标准(量化)

| 维度 | 指标 | 验收方式 | 阈值 |
|---|---|---|---|
| 性能 | subscribe→filter P95 | benchmark | < 20ms |
| 性能 | publish→bus P95 | benchmark | < 50ms |
| 性能 | heartbeat RTT | benchmark | < 5ms |
| 安全 | 外网监听端口 | netstat / ss | 0 |
| 安全 | invalid token rejection | 回归测试 | 100% |

### 11.3 主功能完成口径

| 维度 | 标准 |
|---|---|
| 功能 | F-001~F-006(P0) 通过 |
| 稳定性 | 崩溃可被 supervisord 拉起 |
| 安全 | launch_token / attention / UDS 边界成立 |
| 文档 | 01 / 02 / 03 / 04 完整 |
| 测试 | 单元 + 集成 + 安全回归 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| attention 误拦截正常输入 | 中 | 中 | 分级策略 + telemetry |
| runtime / member IPC 协议漂移 | 中 | 高 | core proto 版本锁 |
| member-service 不可用 | 中 | 中 | retry + degraded mode |

### 12.2 边缘风险

- UDS 文件权限配置错误
- launch_token 续期机制未定义
- 双向 backpressure 在 IPC 边界传播不清

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| launch_token TTL / refresh 机制 | L2 前 | member + governance |
| attention 规则是否可热更新 | L2 后 | member + security |
| runtime 与 member 的 backpressure 协议 | L2 后 | member + runtime |

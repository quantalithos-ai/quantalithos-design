## 1. 业务背景与驱动力

### 1.1 业务背景

member 进程不是“AI 成员本身”,而是 AI 成员容器里的**门面与接入层**。它把:
- 身份卡
- 总线订阅/发布
- 对外 member-service 心跳
- 对内 runtime IPC
- Attention 预过滤

从真正负责思考和执行的 runtime 进程中拆出来,避免 runtime 过厚。

### 1.2 业务驱动力

**业务驱动力**:
- 成员容器需要一个统一的外界接口,否则 runtime 会同时承担接入层和决策层职责
- 安全要求 Prompt Injection 必须在“进入大脑前”先经过一层预过滤

**技术驱动力**:
- UDS gRPC 内部通信
- launch_token 身份卡
- bus CloudEvent 收发
- member-service register/heartbeat

### 1.3 成功标准(可量化)

| 维度 | 指标 | 目标值 | 测量 |
|---|---|---|---|
| 性能 | subscribe→filter P95 | < 20ms | benchmark |
| 性能 | publish→bus P95 | < 50ms | benchmark |
| 性能 | heartbeat RTT | < 5ms | benchmark |
| 安全 | 外网监听端口 | 0 | `ss -tulpn` |
| 安全 | invalid token rejection | 100% | 测试 |

## 2. 约束条件

### 2.1 不可变约束

| 约束 | 来源 | 影响 |
|---|---|---|
| launch_token 必校验 | MB1 | 启动顺序固定 |
| Attention 做 Prompt Injection 预过滤 | MB2 | 事件必须先过 B5 |
| Publisher 只发 CloudEvents | MB3 | 不允许发布裸 payload |
| IPC 用 UDS,不监听外部网络 | MB4 | 通信方式固定 |
| 崩溃被 supervisord 捕获 | MB5 | 启动模式固定 |

### 2.2 可变约束

| 约束 | 当前值 | 可调整空间 |
|---|---|---|
| Attention 规则模型 | 当前规则型 | 可后续升级 |
| IPC 序列化 | gRPC over UDS | 可局部优化 |
| heartbeat 内容 | 最小集 | 可扩字段 |

### 2.3 容量规划

| 资源 | 上限 | 量化依据 |
|---|---|---|
| 订阅过滤延迟 | < 20ms | README |
| publish 延迟 | < 50ms | README |
| heartbeat | < 5ms | README |

## 3. 架构风格与选型

### 3.1 变化维度识别

| 维度 | 变化频率 | 应对策略 |
|---|---|---|
| attention 规则 | 中高 | 独立模块 |
| IPC 协议 | 中 | core proto 锁定 |
| bus topic/filter | 中 | subscriber/publisher 分层 |
| heartbeat 内容 | 中 | external_rpc 模块演进 |

### 3.2 架构风格决策框架

**候选**:

| 风格 | 优势 | 劣势 | 适用性 |
|---|---|---|---|
| **门面进程 + 大脑分离**(当前)| 职责清晰、可审计、易隔离 | 进程数增加 | ✅ |
| runtime 一体化单进程 | 实现简单 | 运行时过厚,边界模糊 | ❌ |
| 反向:member 只转发,无 attention | 更薄 | 安全缺口大 | ❌ |

**最终选择**:**member(门面) / runtime(大脑) 双进程同容器**

### 3.3 约束-收益分析

| 约束 | 收益 | 成本 |
|---|---|---|
| 先过 Attention 再进 runtime | 安全边界清晰 | 20ms 内延迟预算压力 |
| 外网只 member 可见 | 容器边界更稳 | IPC 增加一步 |
| supervisord 管理双进程 | 崩溃恢复清晰 | 运维稍复杂 |

## 4. 系统边界与上下文

### 4.1 系统上下文图(C4 Context 级)

```
bus / member-service / sandbox policy / runtime
                 │
                 ▼
         ★ quantalithos-member ★
         - identity card
         - subscribe/publish
         - attention
         - IPC bridge
         - external rpc
                 │
            runtime process
```

### 4.2 职责边界(做什么 / 不做什么)

**做什么**:
- ✅ launch_token 校验与身份卡
- ✅ CloudEvent 订阅 / 发布
- ✅ Prompt Injection 预过滤
- ✅ member-service register / heartbeat
- ✅ runtime UDS IPC

**不做什么**:
- ❌ 真的推理/决策(runtime)
- ❌ tool 业务实现(tools)
- ❌ 容器编排(member-service)
- ❌ 镜像构建(member-images)

### 4.3 外部系统可用性约束

| 外部依赖 | SLA | 降级 |
|---|---|---|
| bus | 99.95% | reconnect / backlog |
| member-service | 99.9% | degraded heartbeat |
| runtime(peer) | 高 | restart / reconnect |
| sandbox policy | 99.9% | deny by default |

### 4.4 关键依赖风险

- runtime 与 member 协议漂移
- attention 误杀正常流量
- member-service 心跳中断导致容器被误判死亡

## 5. 限界上下文与子域划分

### 5.1 子域分类

| 子域 | 分类 | 说明 |
|---|---|---|
| Identity Card | 核心域 | launch_token + role/member id |
| Event Gateway | 核心域 | subscribe / publish |
| Attention Filter | 核心域 | pre-runtime guard |
| IPC Bridge | 支撑子域 | UDS gRPC |
| External RPC | 支撑子域 | member-service 通信 |

### 5.2 限界上下文划分

| 上下文 | 职责 | 核心对象 |
|---|---|---|
| Identity | 身份卡 | IdentityCard |
| Event IO | CloudEvent 收发 | SubscriptionState / PublishEnvelope |
| Attention | 风险预过滤 | AttentionDecision |
| IPC | runtime 连接 | IPCSession |
| External | member-service 对外接口 | HeartbeatState |

### 5.3 上下文映射关系

- bus ↔ Event IO
- runtime ↔ IPC
- member-service ↔ External
- governance/capability-hub → Attention / Event IO(间接)

### 5.4 统一语言词汇表

| 术语 | 定义 | 上下文 |
|---|---|---|
| launch_token | 成员启动令牌 | Identity |
| IdentityCard | 运行时成员身份卡 | Identity |
| Attention | 进入 runtime 前的安全与优先级预过滤 | Attention |
| IPC Bridge | 容器内 UDS gRPC 边界 | IPC |
| Heartbeat | member→member-service 健康信号 | External |

## 6. 容器/部署架构

### 6.1 容器图(C4 Container 级)

```
container entry (supervisord)
        │
   ┌────┴────────────┐
   ▼                 ▼
member process     runtime process
(B1~B6)            (thinking / acting)
   │                 ▲
   ├─ bus            │ UDS gRPC
   ├─ member-service │
   └─ sandbox policy │
```

### 6.2 每个容器/进程职责与技术栈

| 进程 / 模块 | 职责 | 技术栈 |
|---|---|---|
| member main | supervisord 入口 / bootstrap | Rust |
| identity module | launch_token + identity card | Rust |
| subscriber module | bus inbound filtering | Rust |
| publisher module | bus outbound publish | Rust |
| external_rpc module | member-service RPC | Rust |
| attention module | Prompt Injection pre-filter | Rust |
| ipc_bridge module | UDS gRPC | Rust |

### 6.3 通信方式与选择理由

| 场景 | 选择 | 理由 |
|---|---|---|
| member ↔ runtime | UDS gRPC | 容器内高效 + 不暴露外网 |
| member ↔ bus | EventBus API | 统一 CloudEvents |
| member ↔ member-service | gRPC | 结构化 register/heartbeat |

### 6.4 数据存储归属

| 数据 | 写入方 | 读取方 |
|---|---|---|
| IdentityCard | member | runtime(member 内转发) |
| SubscriptionState | member | member |
| HeartbeatState | member | member-service |
| audit events | member | observability |

### 6.5 部署拓扑

- 每个成员容器内固定双进程:member + runtime
- supervisord 管理两个进程
- 不监听宿主机外部端口

## 7. 依赖方向与层间约束

### 7.1 依赖方向图

```
bootstrap / external edge
         │
         ▼
B1 Identity ──▶ B2 Subscriber ──▶ B5 Attention ──▶ B6 IPC Bridge ──▶ runtime
         │                                          ▲
         ├────────▶ B3 Publisher ───────────────────┘
         └────────▶ B4 External RPC(member-service)
```

### 7.2 层间约束规则

- B5 Attention 必须位于 runtime 之前
- B6 只能绑定 UDS,不开放 TCP listen
- B3 只能发 CloudEvents,不允许裸结构
- B4 只与 member-service 通信,不直接操作容器编排

### 7.3 依赖倒置的接口点

| 接口 | 定义位置 | 实现位置 |
|---|---|---|
| EventSubscriber | member | bus adapter |
| EventPublisher | member | bus adapter |
| RuntimeBridge | member | ipc adapter |
| HeartbeatClient | member | member-service RPC adapter |

### 7.4 依赖健康度评估

| 指标 | 当前预期 |
|---|---|
| 传入耦合 | 中(bus / runtime / member-service) |
| 传出耦合 | 中(bus / member-service / observability) |
| 不稳定性 | 中 |
| 抽象度 | 中高(六模块职责清晰) |

## 8. 数据所有权与一致性策略

### 8.1 数据所有权矩阵

| 数据 | 拥有者 | 消费者 | 一致性策略 | 风险 |
|---|---|---|---|---|
| IdentityCard | member | runtime | 进程内强一致 |
| inbound events | bus | member | at-least-once |
| outbound events | member | bus/downstream | at-least-once |
| heartbeat state | member | member-service | 最终一致 |
| attention decisions | member | observability | append-only 事件 |

### 8.2 一致性层次

- member 内部模块状态强一致(单进程内)
- bus 交付 at-least-once
- member-service 心跳最终一致
- 审计事件 append-only

### 8.3 补偿机制设计

| 场景 | 补偿 |
|---|---|
| publish 失败 | retry / backlog |
| heartbeat 短时失败 | retry + degraded mode |
| IPC 断开 | reconnect / runtime restart |

## 9. 关键技术选型

### 9.1 Rust 门面进程

| 维度 | 内容 |

| 演进路径 | 如需要可加 shm 优化 |
| 不可逆程度 | 中 |

|---|---|
| 当前选择 | 规则 + 优先级判定前置 |

| 选择理由 | 安全边界前移 |
| 演进路径 | 规则热更新 / model assist |
| 不可逆程度 | 中 |

## 12. 演进路线

### 12.1 当前状态与已知债务

| 债务项 | 影响 | 优先级 |
|---|---|---|
| attention 规则热更新未定 | 安全演进 | P1 |
| launch_token 刷新机制未定 | 长时运行稳定性 | P1 |
| IPC backpressure 语义未细化 | 复杂负载场景 | P2 |

### 12.2 触发条件

| 指标 | 阈值 | 动作 |
|---|---|---|
| 订阅→过滤 P95 > 20ms | 持续 1 周 | 拆分 attention pipeline |
| heartbeat RTT > 5ms | 持续 1 周 | 优化 external_rpc |
| invalid token 错误率异常 | > 阈值 | 排查启动链路 |

### 12.3 演进步骤

```
阶段 1: Identity + Subscribe/Publish + IPC 跑通
阶段 2: Attention 预过滤稳定
阶段 3: member-service 深度协作
阶段 4: 热更新 rules / finer-grained metrics
```

### 12.4 目标架构

member 的目标是:
- 作为容器内统一门面
- 把 runtime 从外部依赖、安全、事件 IO 中解放出来
- 稳定承接“嘴耳”角色,不侵入“大脑”

## 2. 业务背景与驱动力

> 校准来源：
> - `design-calibration/01_arch_step_01_requirements_baseline.md`
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 1 的“稳定需求基线”和 Step 2 的“SOP 问题回答”“架构驱动力”“结构化中间产物”小节,了解需求如何收束为架构目标。

### 2.1 背景

AI Member 容器需要一个独立的成员交互边界,把“成员在场、允许听什么、向 Runtime 提交什么、哪些 Runtime 结果可以离开容器、交互如何追溯”从 Runtime 推理与执行真相中分离。若该边界只是透明 Event / IPC 管道,筛选、投递、出站与发布将被压成技术动作;若该边界并入 Runtime 或 host,外部失败和生命周期判断又会侵入运行主线。

`L2-member` 因而不是 LLM 大脑、容器 supervisor 或通用 gateway。它是 AI Member 容器内对成员交互边界事实负责的架构主体:向内消费 Runtime 的正式边界,向外通过 host、Bus 及正式 owner seam 协作,并以最小暴露、可归责和 fail-closed 为结构下限。

### 2.2 架构驱动力

| 驱动力 | 当前结构问题 | 架构响应 |
|---|---|---|
| 单一 owner | member、Runtime、host、Bus 容易各自定义“成功”与交互状态 | member 只拥有本地交互边界 truth,外部 truth 通过 ref / snapshot / feedback 保持外置。 |
| 最小暴露 | 入站正文与 Runtime 输出可能穿透容器边界 | 授权瞬时检查、body-free handoff、forbidden-body veto。 |
| 可归责 | outcome、decision、attempt、delivery、observed / accepted 容易压平 | 关键事实绑定 subject、source、scope、purpose、correlation 与 result category。 |
| 可演进 | host、Runtime、member-specific schema / route 尚未全部闭口 | 先固定 transport-neutral / blocked-aware seam 与依赖倒置,正式合同触发后再激活 carrier。 |
| 可裁剪 | summary、outlet、diagnostics 可能拖累核心 | 派生路径与 BC01~05 隔离;Member Summary 保留,capability outlet 可显式裁剪。 |

### 2.3 架构目标

| ID | 架构目标 | 成立口径 |
|---|---|---|
| `AG-L2M-001` | 成员门面 truth 单一且可归属 | 每个本地 presence、screening、delivery、outbound、attempt 或 trace fact 只有 member owner,并关联项目型主语。 |
| `AG-L2M-002` | Runtime 决策边界不被打穿 | 输入停在 entry seam,输出始于 committed safe material;run / context / plan / checkpoint / outcome truth 外置。 |
| `AG-L2M-003` | 筛选、投递与 Runtime 受理可区分 | 四态筛选、member delivery decision 和 Runtime acceptance 各有独立来源与失败语义。 |
| `AG-L2M-004` | 出站状态分层且本地事实优先 | outcome、outbound decision、attempt、delivery、observed / accepted 不压平;外部失败不回滚本地决定。 |
| `AG-L2M-005` | host 协作与本地在场分层 | member 只拥有 presence 与请求 / 信号 / 报告 attempt;host truth 外置。 |
| `AG-L2M-006` | 交互边界最小暴露且可追溯 | 持久化、出站、trace、observation 与 projection 均 body-free,关键事实可回链。 |
| `AG-L2M-007` | 摘要 / 能力出口派生边界成立 | 视图可重建、不反写,stale / unresolved / gap 显式,不形成 registry。 |
| `AG-L2M-008` | 跨仓依赖可裁剪且类型真实 | 只有 Core 可成为 compile dependency;runtime / event / ref / adapter / fake 分类清楚。 |
| `AG-L2M-009` | 开放 seam 不产生伪成功 | 未闭口关系只进入 blocked / waiting / degraded / fail-closed,不生成 integration 或 readiness。 |

| `AIC-L2M-010` | pending / fake / planned / not_run 不表达为 integration、evidence 或 readiness。 | 设计真相源与证据闭环失真。 |

### 3.2 当前阶段取舍

| ID | 当前取舍 | 代价 | 退出条件 |

### 3.3 架构非目标

| 非目标 | 正式 owner / 后续位置 |
|---|---|
| LLM 推理、计划、记忆、checkpoint、recovery、outcome | `L2-runtime` |
| tool contract、invocation、execution、normalized outcome | `L2-tools` |
| capability registry 与外部 MCP / A2A / API adapter | 正式 capability / adapter owner |
| 容器启停、registry、host session、health verdict、credential issue / revoke | `L2-member-service` / credential owner |
| image build、manifest / compatibility、Sandbox isolation truth | `L2-member-images` / `L4-sandbox` |
| Governance approval、Conversation / Artifact / observed truth | 对应 L1 / L4 owner |
| API、DTO / event schema、字段、数据库、状态迁移 | 后续 02 / 03 |
| 配置 key / default / secret source / retention number | 后续 04 |
| workload、测试结果、evidence、verdict、readiness | 后续 05 / 06,且必须来自真实执行 |
| 实施任务、代码、commit、部署 / 上线 / 回滚执行 | 后续 07 / 实施仓 |

当前可明确判断 owner 是否唯一、正文是否越界、状态是否压平、依赖类型是否真实、派生视图是否反写、pending 是否被伪装。吞吐、延迟、SLA、retry、heartbeat 与资源数字在没有 workload 和测量证据时不进入本架构基线。

### 5.1 系统位置

`L2-member` 位于 AI Member 容器内的交互边界:向内隔离 `L2-runtime` 的运行决策,向外承接 host collaboration、event fact、rule result、project / identity anchor 和派生能力来源。它只形成 member 本地交互事实、安全材料与只读派生视图,不成为相邻系统 truth 的代理写源。

## 9. 数据所有权与一致性策略

> 校准来源：
> - `design-calibration/01_arch_step_08_data_ownership_consistency.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“数据归属总表”“一致性策略总表”“跨数据边界审计”和“物理数据合同后移清单”小节。

### 9.1 数据分类与所有权

| 数据组 | 类型 | 唯一 owner | 边界 |
|---|---|---|---|
| subject acceptance / presence / host local attempt | member truth | BC01 | Work / Identity / host 只提供 ref / safe result,不反写 |
| subscription / screening / disposition | member truth | BC02 | Policy / fact source 只提供 ref / snapshot,Bus / Runtime 不反写 |
| delivery / submission / Runtime reception local fact | member truth | BC03 | Runtime acceptance / outcome 只以 ref 最终关联 |
| outbound / material gate / publication attempt / gap | member truth | BC04 | Bus / downstream feedback 只追加关联 |
| trace link / correlation gap / observation material / attempt | member truth | BC05 | source fact 只被引用;observed / evidence 外置 |
| external ref resolution / freshness / mirror gap | member support truth | BC06 | 不等于 external business truth |
| summary / outlet / diagnostic / explanation / projection state | member projection | BC07 | 最终一致、可重建、不可反写 |
| ProjectMember / GlobalMember / policy / host / Runtime / tool / delivery / downstream fact | external truth | 各正式 owner | member 只持 typed ref / safe snapshot / feedback link |
| raw / hidden / secret / definition / complete log / evidence / conversation / artifact body | forbidden | 外部 owner / 不进入 member | 授权瞬时 inspection 不产生副本 |

正式真相数据只对 member 自身交互边界有权威性;快照 / 投影必须带 source、scope、freshness 与 stale / gap;引用只保留 owner 与 correlation;forbidden body 不进入 truth、snapshot、trace、projection、handoff 或 state carrier。

### 9.2 一致性策略

| 关系 / 场景 | 一致性口径 | 失败处理 |
|---|---|---|
| local decision + subject / source / scope / correlation / reason | 逻辑本地强一致 | incomplete / conflict -> reject / blocked;physical commit unknown -> fenced |
| presence / screening / delivery / outbound history | append / supersede,不原地抹写 | correction 形成新事实,旧历史保留 |
| local decision -> external submission / handoff | local truth first,外部最终一致 | attempt / gap;external failure 不回滚 local decision |
| host / Runtime / Bus / downstream feedback | source-correlated eventual | late / duplicate / out-of-order -> idempotent link / new fact / pending |
| external truth -> ref / safe snapshot | point-in-time consumption | stale / conflict / missing -> conservative / gap,不猜测刷新或合并 |
| source fact -> trace link | eventual,source 含 minimal correlation anchor | trace failure -> gap,不回滚 source |
| source fact -> projection | eventual、rebuildable | stale / rebuild gap,不反写 |
| duplicate command / event / feedback | idempotent classification | identity 不足 -> pending,不 replay unknown side effect |
| commit / side-effect unknown | unknown fence | 等待正式 resolution / evidence,禁止盲重试 |

本仓不与 host、Runtime、Bus、Conversation 或 Observability 建立 distributed transaction。跨 owner 正确性由 local truth first、source-correlated feedback、explicit gap 与 immutable history保证,不依赖 shared database 或 two-phase commit 假设。

### 9.3 物理合同后移边界

database / volume、aggregate / transaction、outbox / handoff carrier、concurrency / idempotency key、retention / archive / backup / restore、encryption / secret ref 的具体设计全部后移。后续选择必须保护唯一 owner、body-free、truth / projection 分离、append history 与 unknown fence;本章不声明任何 store、transaction 或 recovery readiness。

| unknown side effect 自动继续 | 否 | 只记录 unknown feedback | 否,需 resolution / idempotency |
| 可声明 delivered / observed / accepted | 否 | 仅正式 owner feedback 自身可被引用 | 否 |

host admission 不等于 health,screening 不等于 Runtime acceptance,entry accepted 不等于 run complete,outbound attempt 不等于 delivery / observed / accepted。transport、API、event family、topic、schema、ack、retry algorithm 与 guarantee 全部后移或 pending。

## 11. 关键技术选型

> 校准来源：
> - `design-calibration/01_arch_step_10_technology_choices.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“当前正式采用哪些关键架构机制”“当前明确不采用 / 不锁定”“设计取舍结论”和“门禁自检”小节。

本章的“技术机制”是长期影响 owner、依赖、数据、一致性、失败与演进的架构机制,不是语言、framework、database、transport 或 SDK 产品清单。

### 11.1 采用的架构机制

| ID | 技术机制 | 解决的问题 | 采用理由 | 代价 / 约束 |
|---|---|---|---|---|
| `TM-L2M-001` | bounded contexts + inward dependency inversion | external owner 侵入 core | Core 只依赖 shared primitive / local rule,adapter 服从 inward boundary | translation / error classification 增加 |
| `TM-L2M-002` | Core-authoritative shared contracts | 各仓复制 ID / ref / envelope / trace / error | Core 是唯一 compile authority | member-specific contract 必须等待 owner 闭口 |
| `TM-L2M-003` | truth / snapshot / projection / ref / forbidden-body separation | external truth 与正文入仓、projection 成第二写源 | owner、freshness、rebuild 与 data ban 清楚 | data classification / stale / gap 状态增加 |
| `TM-L2M-004` | anti-corruption External Context Mirror | external schema / language 扩散到 core | source-specific input 转 neutral ref / safe result / gap | 必须防止 Mirror 膨胀为 registry / hub |
| `TM-L2M-005` | source-anchored local decision | 决定无法解释依据 | 决定绑定 subject、source、scope、correlation 与安全分类 | incomplete handling 成本增加 |
| `TM-L2M-006` | local-truth-first + explicit attempt / gap | external result 回滚 local fact | local decision 先成立,external collaboration 独立收敛 | 消费者必须理解多层状态 |
| `TM-L2M-007` | immutable / append-oriented history | late / duplicate / correction 覆盖历史 | feedback / correction 成为新关联事实 | physical retention / compaction 后移 |
| `TM-L2M-008` | idempotency / ordering / correlation boundary | duplicate / out-of-order 引发 truth fork | 按 source identity / correlation 分类,unknown 不 replay | physical key / ordering contract pending |
| `TM-L2M-009` | fail-closed precondition + unknown-side-effect fence | unknown subject / rule / external result 仍继续 | correctness 优先,所有缺口可审查 | availability 降低,需要 resolution path |
| `TM-L2M-010` | sync admission / async fact / background continuation separation | 全同步级联或全异步无即时判断 | 即时边界只回答 admission,长时结果与 maintenance 解耦 | correlation / failure handling 更复杂 |
| `TM-L2M-011` | transport-neutral Runtime / host seams | UDS / gRPC / direction 反向定义业务 | 先锁 acceptance / result / handoff 语义 | mapping 闭口前不能声明 adapter ready |
| `TM-L2M-012` | body-free safe material gate | body / reasoning / secret / definition 扩散 | inspection、truth、handoff 分层,只输出最小材料 | 调查依赖 ref 回源与安全分类 |
| `TM-L2M-013` | derived read model / projection isolation | read / diagnostics 阻塞 core 或反写 | async projection + sync safe read + background rebuild | projection lag / gap 显式化成本 |
| `TM-L2M-014` | capability outlet as optional ref-derived projection | member 形成第二 registry | 只从 Tool / method ref 派生,可裁剪且非 authorization | 初期 outlet 可能 not_available / stale |

### 11.2 当前不锁定或禁止的选择

| 候选 | 当前结论 | 原因 |
|---|---|---|
| Rust / Go / Python、framework | 不锁定 | 无 implementation / workload / toolchain authority |
| UDS / TCP / pipe / shared memory、gRPC / HTTP | 不锁定 | entry / failure / backpressure mapping pending |
| member-service server / client / port | 不锁定 | direction、fields、credential contract pending |
| supervisord / sidecar / single / dual process | 不锁定 | 只锁 logical boundary,physical topology 后移 |
| JWT / `launch_token` / credential TTL | 不锁定 | issue / revoke owner 与 credential shape pending |
| DB / object store / cache / queue / scheduler / retry library | 不锁定 | transaction、durability、retention、idempotency、workload pending |
| full event sourcing | 不作为当前硬机制 | append history 不要求全部 state replay,external side effect 也不可重演 |
| shared DB / two-phase commit | 不采用 | 破坏 owner separation,无 cross-repo atomicity authority |
| member-specific CloudEvent / AG-UI family / route | 不锁定 | shared envelope category 可承接,具体 family / route pending |
| generic listener / provider adapter | 禁止 | 绕过 capability / Runtime -> Tools 正式链 |

## 12. 备选方案与取舍

> 校准来源：
> - `design-calibration/01_arch_step_11_alternatives_tradeoffs.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“当前主线方案”“方案路径比较”“关键取舍对照”“历史方案审计”和“最终选择结论”小节。

### 12.1 当前主线

采用 `ALT-L2M-A`:

```text
Independent member interaction-boundary truth
  + BC01~05 core semantics
  + BC06 anti-corruption mirror
  + BC07 isolated read projection
  + inward dependency boundaries
  + local-truth-first / immutable history / unknown fence
  + sync admission / async committed facts / background continuation
  + body-free safe material / external truth by ref
```

它允许 member 与 Runtime 位于同一 AI Member 容器,但不共享 truth;physical topology 与 transport 后移。

### 12.2 路径比较

| 方案 | 主要收益 | 主要代价 / 不采用原因 | 当前结论 |
|---|---|---|---|
| `ALT-L2M-A` independent truth + bounded contexts + inward seams | owner 清楚、可审计、transport 可替换、pending seam 可表达 | 状态、correlation、adapter、projection 复杂度较高 | 采用 |
| `ALT-L2M-B` transparent Event / IPC pipe | 初期模块与调用链简单 | 无法解释 screening / delivery / outbound decision,body / delivery 边界失控 | 不采用 |
| `ALT-L2M-C` merge into Runtime | 少一个逻辑组件,局部调用短 | external interaction 侵入 Runtime core,违反 Runtime 非目标 | 不采用 |
| `ALT-L2M-D` merge into host control | control plane 集中 | host failure 接管 local truth,lifecycle 与 interaction 混合 | 不采用 |
| `ALT-L2M-E` all-event member | async scaling 与 decoupling 自然 | startup / Runtime entry 无即时 admission,Bus 成为所有路径前置 | 不采用 |
| `ALT-L2M-F` all-sync RPC facade | caller 心智简单 | long-running result 伪同步、级联失败、无法 local truth first | 不采用 |
| `ALT-L2M-G` shared state / shared DB | 查询和 join 表面简单 | double truth、cross-repo schema coupling、recovery 不可归责 | 不采用 |
| `ALT-L2M-H` generic agent gateway / capability adapter | external entry 集中 | 吞并 registry / provider adapter / Runtime -> Tools 职责 | 不采用 |

### 12.3 关键取舍

| 当前选择 | 放弃 | 换得 | 可接受条件 |
|---|---|---|---|
| independent member truth | shortest call chain / fewest states | unique owner 与 interaction accountability | BC01~05 不吸收 external truth |
| local truth first | cross-system one-success illusion | external failure 不污染 local decision | attempt / gap / feedback 可读 |
| eventual external feedback | immediate global consistency | 无 shared DB / distributed transaction | duplicate / late / unknown 可分类 |
| fail-closed / unknown fence | 部分 availability / auto recovery | 避免 unauthorized 或 duplicate side effect | 后续必须设计 resolution path |
| body-free safe material | full context 就地调查 | minimal exposure 与 owner back-reference | ref / source / category 足以追溯 |
| anti-corruption Mirror | 直接复用 external schema 的速度 | stable core language、stale / conflict 显式 | Mirror 不膨胀为 hub |
| isolated projection | strong read consistency / direct core query | read failure 不拖垮 core,可重建 | freshness / gap 对 consumer 可见 |
| transport-neutral seam | early protocol certainty | 可等待正式 host / Runtime contract | contract closure 后显式回开设计 |
| project-scoped only | non-project / personal coverage | subject 唯一、identity 与 execution 分层 | 第三种主语出现时重开 BC01 及关联面 |
| optional capability outlet | early complete capability visibility | C1~C4 不依赖 Tools / method refs | 裁剪显式且不把 stale 写成 available |

语言、transport、protocol、store、process manager、outlet 首批开关与固定指标是下游实现或阶段裁剪问题,不构成架构级替代路径。

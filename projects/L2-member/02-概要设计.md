## 3. 约束条件

> 校准来源：
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读该中间产物的“概要设计硬约束表”和“约束到后续 Step 的覆盖”小节，了解每项约束如何限制对象、接口、流程、状态和配置。

| 约束 | 说明 |
|---|---|
| 项目型正向主语 | 正向路径必须使用可验证的 `ProjectMemberRef`，并关联 `GlobalMemberRef` 身份锚；presence 不替代二者，非项目型输入 fail-closed。 |
| 单一 local truth owner | member 只拥有 local presence / interaction / support / derived-read truth；Runtime、Tools、host、Bus、Governance、Conversation、Identity、Work 等 truth 外置。 |
| 全生命周期 body-free | 授权检查只能瞬时发生；truth、handoff、trace、projection、event 与 Query 均不保存或透明转发 raw body、hidden reasoning、secret、definition、complete log 或 evidence body。 |
| source / scope / correlation 前置 | subscription、screening、delivery、outbound、trace 和 resolution 均需可回链的 source、scope、purpose、correlation 与安全分类。 |
| 决定与外部事实分层 | screening 不是 Policy / Bus truth；delivery 不是 Runtime admission；publication attempt 不是 delivery / accepted / observed；outlet availability 不是 authorization。 |
| local-truth-first 与历史 | 本地决定先提交，外部 handoff / feedback 最终一致；decision、attempt、gap、snapshot、resolution 等采用 append / successor，外部失败不回滚 source fact。 |
| duplicate / late / unknown fence | duplicate、late、out-of-order 只分类或形成新关联；unknown side effect 不盲重放、不因时间或 Query 升级。 |
| Mirror / projection 隔离 | Mirror 只做 neutral resolution / freshness / gap；Trace、Read Model 和 Job 只消费 committed refs，不修复 source truth。 |
| Core-only compile | 只有 Core shared primitive 是 compile candidate；host、Runtime、Bus、owner、sibling 通过 runtime / event / ref / adapter / fake seam 协作。 |
| 正式 seam 限定 | 禁止 generic listener、provider、MCP / A2A / API 或 Sandbox 直连；只允许正式 host / Runtime / Bus / owner seam。 |
| 同步、异步与后台分离 | Command / Query 处理即时 local judgement，Consumer 处理已到事实，Job 只做 relay / refresh / rebuild / reconcile continuation。 |
| pending 不闭口 | `L2M-UP-001~008` 只产生 blocked / waiting / stale / gap / fail-closed 姿态；配置、default 或 adapter 不得把它们变成 closed contract。 |
| 非伪造纪律 | design、fake、planned 或文件存在不代表实现、integration、test、evidence 或 readiness。 |

### 4.1 架构模块到代码主体映射

```text
L2-member
|
+-- 1. Presence and Host Collaboration
|   +-- PresenceCommandApi / PresenceApplicationService
|   +-- HostCollaborationService / HostFeedbackConsumer
|   +-- admission, presence, material, attempt, policy
|
+-- 2. Inbound Boundary
|   +-- InboundFactConsumer / SubscriptionScopeService / InboundBoundaryService
|   +-- scope, fact, screening, policies
|
+-- 3. Runtime Mediation
|   +-- RuntimeDeliveryCommandApi / RuntimeMaterialConsumer
|   +-- RuntimeMediationService / delivery, submission, link, reception
|
+-- 4. Outbound Boundary
|   +-- OutboundBoundaryService / DeliveryFeedbackConsumer / PublicationRelayJob
|   +-- decision, material, attempt, gap, policy
|
+-- 5. Interaction Trace
|   +-- InteractionTraceService / InteractionTraceQueryApi / ObservationRelayJob
|   +-- trace, observation material, attempt, gap, policy
|
+-- 6. External Context Mirror
|   +-- ExternalContextMirrorService / source Consumers / refresh Job
|   +-- snapshot, resolution, gap, policy
|
`-- 7. Member Read Model
    +-- MemberReadModelService / MemberQueryApi / rebuild and reconcile Jobs
    +-- summary, outlet, diagnostics, projection state, policy
```

关键说明：

- 图表达从正式七个 BC 到代码主体骨架的映射，不表达源码目录、部署单元、物理进程或固定调用顺序。
- `Member truth core` 是全部组成部分共同遵守的 owner / body / history invariant，不是第八个业务组成部分。
- Runtime、host、Bus、Governance、Work、Identity、Tools / Method 和 downstream 只经 inward Port / typed ref 出现，不成为内部模型。

### 4.2 实现分层视图

```text
External command / query / event / feedback / scheduled trigger
                              |
                              v
+------------------------------------------------------------------+
| Inbound / Operations                                             |
| APIs / Consumers / Relay, Refresh, Rebuild, Reconcile Jobs       |
+------------------------------+-----------------------------------+
                               |
                               v
+------------------------------------------------------------------+
| Application Services                                             |
| Presence / Host / Scope / Inbound / Runtime / Outbound / Trace / |
| Mirror / Read Model coordination                                 |
+------------------------------+-----------------------------------+
                               |
                               v
+------------------------------------------------------------------+
| Domain Model and Policies                                        |
| member local truth / support truth / guards / append history     |
+------------------+---------------------------+-------------------+
                   |                           |
                   v                           v
+--------------------------------+  +------------------------------+
| Ports and External Seams       |  | Persistence / Projection     |
| host / Bus / Runtime / owners  |  | truth stores / support store |
| event / observation handoff    |  | rebuildable read projections |
+----------------+---------------+  +---------------+--------------+
                 |                                  ^
                 v                                  |
+------------------------------------------------------------------+
| Local Handoff Continuation                                       |
| host signal / publication / observation attempt and gap relay    |
+------------------------------------------------------------------+
```

关键说明：

- Inbound / Operations 不作领域裁决；Application 不绕过 Domain 直接改 truth；Domain 不读取 transport 或 config。
- Port、Persistence、Projection 与 Handoff 是承载和边界角色，不取得外部 truth 或新业务 owner。
- local handoff 只继续已成立事实，external feedback 作为新事实回到 owner-specific Consumer，不逆写 source decision。

| 项 | 说明 |
|---|---|
| 业务主要组成部分 | CP01~CP07 回答 member 在 presence、inbound、Runtime seam、outbound、trace、mirror 和 read model 上做什么。 |
| 实现分层 | Inbound / Operations、Application、Domain / Policy、Ports、Persistence / Projection、Local Handoff 回答代码如何承载这些主体。 |
| 二者关系 | 每个业务组成部分跨多个实现层；同一实现层服务多个组成部分。二者正交，不能互相替代或直接推导为目录。 |

关键判断：入口、Job、Port、Store、Projection、adapter 都不是业务主要组成部分；Application Service 也不是第八业务模块。adapter 只在 Port 外侧翻译 owner-specific carrier，其局部成功不能直接成为 domain success。

### 7.1 接口分类说明

```text
Command API
  显式发起 member local truth / support truth 变化；需要 ActorContext、CommandMetadata、IdempotencyKey。

Query API
  读取 projection、trace 或 neutral resolution surface；需要 ActorContext、QueryMetadata；不得改写状态。

Inbound Event Consumer
  消费 formal envelope、source event、feedback 或 committed local fact；先完成 source、version、dedup、body gate。

semantic Outbound Event
  传播本仓已提交 local fact / support fact / projection change 的语义；只冻结最小 ref 方向。

Operations Job
  基于已持久化事实继续 relay、refresh、rebuild 或 reconcile；不得成为业务 Command 或修复 source truth。

Inward Port / Persistence Interface
  隔离外部 owner 与物理 carrier；是本仓 logical contract，不是 package dependency 或 integration 结论。
```

所有 Command 均要求 `ActorContext`、`CommandMetadata` 与 `IdempotencyKey`；所有 Query 均要求 `ActorContext`、`QueryMetadata` 且 no-write；外部 Consumer 要求 `EventEnvelope`、`SourceEventId`、`SchemaVersion`、`DeduplicationKey`、`TraceContext`；本仓 committed-fact Consumer 使用逻辑 `MemberFactEnvelope`、`MemberFactId`、版本、dedup 与 trace context。`JobRunRef` 只是 Job 输入类型，不表示存在真实 run。exact event carrier、type、source、subject、payload、route 与 adapter activation 继续受 `L2M-UP-005` 约束。

### 8.1 通用处理流骨架

#### 通用 Command 写路径

```text
<Command>
  │
  ▼
<Command Boundary>
  - 校验 ActorContext、CommandMetadata、IdempotencyKey、subject 与 scope
  - 解析 typed refs / correlation
  │
  ▼
<Application Service>
  - 读取 current local truth 与必要 neutral external resolution
  - 调用 domain policy / guard
  │
  ▼
<Domain Object + Store>
  - 追加 decision / revision / attempt / support fact
  - 在单一本地提交边界保存 source fact 与 local semantic-event candidate
  │
  ▼
<Result / Continuation>
  - 返回 local result 或 blocked / unknown
  - 外部 side effect、feedback、projection、trace 由后续 owner flow 继续
```

关键设计点：

- Command 只保证本仓可证明的 local result，不能将 host、Runtime、Bus、downstream 或 observation acceptance 当作同步成功。
- 幂等与 expected revision 在入口 / domain 边界显式处理；外部 side effect 发生在 local commit 之后。
- transaction、outbox、Store 的物理协议和错误映射留给 03。

#### 通用 Query 读路径

```text
<Query>
  │
  ▼
<Query Boundary>
  - 校验 ActorContext、QueryMetadata、visibility / subject scope
  - 解析 ProjectionConsistencyHint
  │
  ▼
<Application Query Service>
  - 读取 local store / rebuildable projection
  - 识别 current、stale、degraded、unavailable、unknown
  │
  ▼
<Read Surface Assembler>
  - 只组装 body-free refs、safe categories、watermark 与 freshness
  │
  ▼
<Query Result>
  - 返回 view / page 或显式 not-ready / unavailable
```

Query 不开启隐式写事务，不触发 refresh、rebuild、gap repair 或 external resolver。

#### 外部 Event Consumer 路径

```text
<External Event / Feedback>
  │
  ▼
<Owner-specific Consumer>
  - 验证 EventEnvelope、SourceEventId、SchemaVersion、DeduplicationKey、TraceContext
  - 执行 source / version / body / duplicate gate
  │
  ▼
<Application Incorporation Service>
  - 转为 typed ref、snapshot、feedback link 或 gap
  - late / duplicate / conflict 只追加分类，不覆盖 source truth
  │
  ▼
<Local Record + Store>
  - 提交本仓可归属的 support / link / gap fact
  │
  ▼
<Projection / semantic Event Candidate>
```

#### 本仓 committed-fact Consumer 路径

```text
<Committed Member Fact>
  │
  ▼
<Local Fact Consumer>
  - 验证 logical MemberFactEnvelope、MemberFactId、版本、dedup、trace
  - 确认 fact 已提交且 source ref / watermark 可回链
  │
  ▼
<Application Propagation Service>
  - 追加 trace link、projection stale marker 或下游 preparation fact
  - 不复制 source body，不回滚 source commit
  │
  ▼
<Trace / Projection / Handoff Store>
```

`MemberFactEnvelope` 是 transport-neutral 槽位，不代表 member-specific Core carrier 已闭口。

#### 通用 Operations Job 路径

```text
<Operations Job>
  │
  ▼
<Job Boundary>
  - 校验 JobMetadata、JobRunRef、system / operator ActorContext、IdempotencyKey
  - 读取 committed facts、gaps、watermark 或 prepared attempts
  │
  ▼
<Continuation / Reconciliation Service>
  - 形成新 local revision、successor gap、relay attempt 或 projection revision
  - unknown side effect 进入 blocked / unknown，不猜测补齐
  │
  ▼
<Domain Object / Projection / Port>
  - 只追加本仓事实或调用明确 external seam
```

### 8.2 CP01 入场、在场与 host 协作流

#### `AdmitMemberStartup`

```text
<AdmitMemberStartup Command>
  │
  ▼
<Presence Command Boundary>
  - 校验 ActorContext actor、CommandMetadata metadata、IdempotencyKey idempotency_key
  - 确认 ProjectMemberRef subject_ref 与 GlobalMemberRef identity_anchor_ref
  │
  ▼
<PresenceApplicationService>
  - 读取 ProjectMemberSourcePort / IdentityAnchorSourcePort safe resolution
  - 读取 StartupCredentialVerifierPort verification ref（若适用）
  - 调用 PresenceAdmissionPolicy.evaluate(ProjectMemberRef subject_ref, GlobalMemberRef identity_anchor_ref, StartupContextRef startup_context_ref, SourceResolutionSet resolutions)
  │
  ▼
<StartupAdmission + PresenceStore>
  - 提交 accepted / rejected / blocked decision 与 local semantic-event candidate
  │
  ▼
<Admission Result>
  - accepted 只赋予 EstablishMemberPresence 资格；不创建 host acceptance / session
```

关键设计点：项目型 `ProjectMemberRef` 是唯一正向执行主语；任一必要 resolution 缺失、冲突、过期或未知时必须 blocked / rejected；不保存 startup / credential body。

### 9.1 状态定义表

| 状态族 / 对象 | 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|---|
| `StartupAdmission` | `accepted` | 启动双锚与必要来源可验证。 | 是；仅能建立 local presence。 | 不等于 host accepted / healthy。 |
|  | `rejected` / `blocked` | 输入已知无效，或 source / contract 不可判定。 | 否。 | blocked 必须 fail-closed。 |
| `MemberPresence` | `starting` | accepted admission 后的本地准备。 | 受限。 | 不表示容器 / Runtime ready。 |
|  | `ready` | member local 前置满足。 | 是；受 `can_accept_inbound()` 限定。 | 不等于 host health。 |
|  | `degraded` / `draining` | 协作受限，或已停止新交互。 | 受限 / 否。 | 都需要 explicit local reason。 |
|  | `terminated` / `unknown` | local 在场终止，或状态完整性不可证明。 | 否。 | unknown 是 fence。 |
| `HostCollaborationAttempt` | `prepared` / `submitted` / `feedback_linked` | 本地材料已就绪、已调用 seam、已关联外部 ref。 | 仅同 owner continuation。 | submitted / feedback-linked 均不等于 host accepted。 |
|  | `blocked` / `unknown` | seam 前置不成立或副作用不可证明。 | 否。 | unknown 不得盲重放。 |
| `SubscriptionScopeDecision` | `active` | 当前 project-scoped inbound 匹配范围。 | 是；仅可作为 scope match basis。 | 不等于 Bus subscription / authorization。 |
|  | `superseded` / `rejected` / `blocked` | 历史范围、无效范围或来源不可判定。 | 否。 | scope 变化采用 successor。 |
| `InboundFactRecord` | `accepted` | envelope / source / scope 可识别的 body-free local intake。 | 是；仅能形成 screening。 | 不等于 Bus delivered。 |
|  | `duplicate` / `unsupported` / `blocked` | 重复、范围外或前置不可判定。 | 否。 | 不创建第二主线。 |
| `ScreeningDecision` | `passed` | accepted fact、active scope、rule resolution 与 inspection summary 满足筛选。 | 是；仅可进入 CP03 evaluation。 | 不等于 Governance decision / Runtime admission。 |
|  | `degraded` | 正式收窄规则明确允许的有限语境。 | 受限。 | 不能在 read 面改写为 passed。 |
|  | `blocked` / `pending` | 已知违反边界，或必要 rule / freshness 未闭口。 | 否。 | 不得提交 Runtime。 |
| `RuntimeDeliveryDecision` | `eligible` | screening 与 formal entry mapping 足以创建 attempt。 | 是；仅能提交 logical Runtime seam。 | 不等于 Runtime accepted。 |
|  | `rejected` / `blocked` / `pending` | 前置无效、mapping / source 未闭口。 | 否。 | 不私造 trigger schema。 |
| `RuntimeSubmissionAttempt` | `prepared` / `submitted` / `result_linked` | 本地准备、已调用 entry、已关联 Runtime result ref。 | 同 owner continuation。 | submitted 不等于 run created。 |
|  | `blocked` / `unknown` | seam 不可用或副作用不可证明。 | 否。 | unknown 是 retry fence。 |
| `RuntimeResultLink` | `accepted` / `rejected` / `waiting` / `blocked` / `unknown` classification | 所引用 Runtime result 的安全分类。 | 不适用。 | immutable link，不构成 member lifecycle。 |
| `RuntimeMaterialReception` | `accepted` | committed、body-free material ref 可证明。 | 是；仅可进入 CP04 evaluation。 | 不转移 Runtime outcome / material owner。 |
|  | `rejected` / `duplicate` / `late` / `blocked` / `unknown` | 材料不安全、重复 / 迟到或 source 不可判定。 | 否。 | 不创建第二 outbound 主线。 |
| `OutboundDecision` | `eligible` | source、target、purpose、body gate 均满足。 | 是；仅可创建 material。 | 不等于 submitted / delivered。 |
|  | `rejected` / `blocked` / `pending` | source / route / resolution 未满足。 | 否。 | 不猜测默认 target。 |
| `PublicationAttempt` | `prepared` / `submitted` / `feedback_linked` | 材料就绪、已调用 seam、关联 downstream ref。 | 同 owner continuation。 | 不等于 Bus delivery / downstream accepted。 |
|  | `blocked` / `unknown` | route / precondition 不成立或副作用未知。 | 否。 | unknown 形成 gap / fence。 |
| `PublicationGap` | `open` / `resolution_pending` / `resolved` / `superseded` | publication route / feedback 的本地未闭合关系。 | 受限 / 否。 | resolved 不等于 publication success。 |
| `InteractionGap` | `open` / `blocked` / `resolution_pending` / `resolved` / `unknown` / `superseded` | 交互 correlation 的缺失或解释姿态。 | 受限 / 否。 | 不补造 source fact。 |
| `ObservationAttempt` | `prepared` / `submitted` / `feedback_linked` / `blocked` / `unknown` | observation material 的本地交接姿态。 | 同 owner continuation。 | 不等于 observed / evidence。 |
| `ExternalContextResolution` | `resolved` | ref、owner、purpose、scope、freshness 足以供 consumer policy 判断。 | 受限。 | 绝不等于 authorization / health / acceptance。 |
|  | `stale` / `conflict` / `unresolved` / `unavailable` / `unknown` | 来源不充分、冲突、不可用或不可证明。 | 否。 | consumer 必须保守处理。 |
| `ExternalContextGap` | `open` / `blocked` / `resolution_pending` / `resolved` / `unknown` / `superseded` | source-resolution 缺口及其本地历史。 | 受限 / 否。 | gap resolved 仍需 consumer 自身 policy。 |
| `MemberProjectionState` | `current` | 同 kind 的 required sources 完整覆盖 target watermark。 | 是；仅对相同 projection kind。 | 不代表 member / host / Runtime currentness。 |
|  | `stale` / `rebuilding` / `degraded` / `failed` / `disabled` / `unknown` | 投影落后、重建、有限可读、失败、裁剪或完整性未知。 | 受限 / 否。 | 不能静默变 current。 |
| `CapabilityOutletView` | `available` | outlet active 且 safe refs / CP06 resolution / watermark 足够。 | 是；仅 body-free display。 | 不等于 registry / authorization / invocation。 |
|  | `not_available` / `stale` / `gap` | 可选面未激活、来源落后或合同 / refs 不充分。 | 受限 / 否。 | 不影响 summary。 |

`HostCollaborationMaterial`、`MemberOutboundMaterial`、`InteractionTraceEntry`、`ObservationMaterial`、`ExternalContextSnapshot`、`MemberSummaryView`、`MemberDiagnosticView` 与 policy 都是 immutable / derived / guard 主体；它们没有独立可变生命周期。

### 9.2 状态流转图

#### CP01~CP04 主线状态流转

```text
StartupAdmission
  <new> -> accepted / rejected / blocked
                 │ accepted only
                 ▼
MemberPresence
  starting -> ready / degraded / draining / unknown -> terminated
                 │ active local presence
                 ▼
SubscriptionScopeDecision
  active / rejected / blocked -> superseded (only after new active successor)
                 │ active scope + accepted intake
                 ▼
InboundFactRecord -> accepted -> ScreeningDecision
                          │       passed / controlled degraded
                          ▼
RuntimeDeliveryDecision -> eligible -> RuntimeSubmissionAttempt
                                      prepared -> submitted -> result_linked
                 │ accepted Runtime material reception
                 ▼
OutboundDecision -> eligible -> PublicationAttempt
                              prepared -> submitted -> feedback_linked
```

关键说明：

- 图只表达 member local qualification；箭头不表示单一全局状态机或 external success。
- `blocked`、`pending`、`unknown`、duplicate、late、conflict 都必须在各自对象中保持显式，不可跨对象自动升级。
- `accepted reception -> CP04 evaluation` 是明确的 CP03→CP04 资格链；screening passed 仍不是 Runtime admission。

#### CP05~CP07 support 与派生状态流转

```text
Committed member fact -> InteractionTraceEntry / InteractionGap
                                │
                                ▼
                        ObservationAttempt
                     prepared -> submitted -> feedback_linked

Owner-specific safe source -> ExternalContextSnapshot (immutable)
                                │ purpose / scope / freshness
                                ▼
ExternalContextResolution: resolved / stale / conflict / unresolved / unavailable / unknown
                                │ non-usable or gap detected
                                ▼
ExternalContextGap: open / blocked / unknown -> resolution_pending -> resolved / superseded

Committed facts / neutral resolutions -> MemberProjectionState
  current -> stale -> rebuilding -> current
                    └-> degraded / failed / unknown
  optional <new> -> disabled -> rebuilding
```

关键说明：

- `ExternalContextSnapshot` 不可变；refresh / source update 产生新 snapshot / resolution / successor gap。
- projection 的 `current` 只在 watermark 覆盖可证明时成立；outlet `available` 是 immutable view revision 分类。
- `GapReconciliationJob` 只能更新 projection 所见 gap / freshness，不能关闭 CP04、CP05、CP06 source gap。

### 9.3 允许的核心迁移

| 对象 | 允许迁移 | 触发动作 / 前置 | 本地结果与边界 |
|---|---|---|---|
| `StartupAdmission` | `<new> -> accepted / rejected / blocked` | `AdmitMemberStartup` 与可验证或失败的 source basis | 追加 admission decision；blocked / rejected 不建立 presence。 |
| `StartupAdmission` | `blocked -> successor accepted / rejected` | 新显式 command 与正式 resolution | 新 decision，不原地覆盖旧记录。 |
| `MemberPresence` | `<new> -> starting` | `EstablishMemberPresence` 引用 accepted admission | 建立 initial revision。 |

### 9.4 禁止的核心迁移

| 禁止迁移或行为 | 原因 |
|---|---|
| `StartupAdmission.blocked` 自动变 accepted，或非 accepted admission 建立 presence | 无法验证的 subject / credential / source 必须 fail-closed。 |
| heartbeat、process signal、host health / session / registry 直接迁移 `MemberPresence` | 外部 truth 不能覆盖 local history。 |
| `MemberPresence.unknown` 自动到 ready / terminated；draining / terminated 自动恢复新入站主线 | unknown 是 fence；重新在场需要新受理链。 |
| submitted / feedback-linked 直接等同 host accepted、Runtime accepted、Bus delivered、downstream accepted、observed 或 evidence | local attempt / ref link 与外部 truth 必须分层。 |
| scope 原地扩权、superseded scope 再用于 current match、non-active scope intake accepted | 必须用正式 source basis 与新 revision。 |
| duplicate / unsupported / blocked intake 创建 screening；pending / blocked screening 自动 passed | 防止第二主线与 fail-open。 |
| mapping pending 时创建 Runtime run、unknown attempt 自动 retry | member 不拥有 Runtime run，unknown 无重放权。 |
| `RuntimeMaterialReception.accepted` 直接变 outbound / publication success | CP04 要独立 decision / material / attempt。 |
| publication / observation failure 回滚 decision、material、source fact 或 trace | local-truth-first；应追加 gap / attempt。 |
| snapshot 原地 refresh，或 resolution 跨 purpose / scope 复用 | support truth 必须 append-only、purpose-isolated。 |
| Mirror resolved 自动授予 authorization、health、acceptance、outlet availability | neutral resolution 不拥有业务裁决。 |
| CP02 接第二个 Governance Consumer，CP07 直连 Tools / Method source event | CP06 是唯一 member-side source update owner。 |
| `MemberProjectionState.failed / unknown / degraded / stale` 因时间、Query、默认值变 current | current 需要 complete coverage proof。 |
| outlet available 自动授权 invocation / execution；reconciliation 关闭 source gap | outlet / projection 都没有 registry、action、source gap write 权。 |
| 任意 Query 创建、迁移或修复 truth / gap / projection | Query no-write。 |

### 9.5 状态传播关系图

```text
<Committed local state revision>
        │
        ▼
<semantic Event Candidate / local trace link>
        │
        ├─ <same-owner continuation> -> <attempt / gap / resolution>
        │
        ├─ <MemberFact Consumer> -> <trace or projection stale marker>
        │
        └─ <Read Query> -> <body-free status / freshness surface>
```

关键说明：

- CP01~04 local facts 可单向进入 CP05 trace 与 CP07 projection；CP06 resolution / gap 只影响后续 policy posture 和 projection。
- 外部 feedback 只能形成 owner-specific ref / classification，不能反向改写 source decision。
- semantic Event 只表达语义候选；图不表示 Bus carrier、outbox delivery、SDK mapping 或 downstream receipt。

## 10. 异常与边界场景轮廓

> 校准来源：
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读该中间产物的“异常与边界场景轮廓表”“跨部分异常影响图”和“不在本步展开的异常细节”，了解下表如何保持对象化状态、local-truth-first 与外部 owner 边界。

本章只固定会改变主线资格、状态传播或跨组成部分协作关系的异常口径。它不定义错误码、重试参数、补偿脚本、物理 carrier、存储恢复或运维流程；`L2M-UP-001~008` 的精确合同仍在第 13 章保持挂起。

| 场景 | 应落在哪个部分处理 | 当前概要口径 |
|---|---|---|
| 非项目型、不可解析或冲突的执行主语、身份锚或启动凭据 | CP01 `AdmitMemberStartup`，必要时经 CP06 的 subject / identity resolution | `StartupAdmission` 只能形成 `rejected` 或 `blocked`，不得建立 `MemberPresence`；正向只接受 `ProjectMemberRef + GlobalMemberRef`。 |
| host 不可达、反馈不可证明，或 host 合同未闭口 | CP01 host collaboration；CP06 host-route resolution；CP07 diagnostics | 保留本地 `blocked` / `unknown` attempt 或可回链 feedback link；presence 仅依据明确 local basis 降级，不代答 host acceptance、registry、session 或 health。 |
| subscription source、scope 或 screening rule 为 unknown、stale 或 conflict | CP02 scope / intake / screening；CP06 policy resolution；CP03 delivery 前置 | scope / screening 形成 `rejected`、`blocked` 或 `pending`；仅在正式规则明确许可时才可能形成受控 `degraded`，不得 default-pass 或本地 allowlist。 |
| 授权瞬时检查失败，或 forbidden body 企图持久化、投递、追溯或展示 | CP02~CP05 的各自 gate，以及 CP07 Query / view 边界 | 形成安全分类或阻断 disposition；raw body、hidden reasoning、secret、definition body、complete log 与 evidence body 均不得进入 local record、semantic Event、material、projection 或 Query。 |
| Runtime entry mapping / seam 不可用、被拒绝或 side effect unknown | CP03 delivery decision / submission attempt / result link | local decision / attempt 保持 `rejected`、`blocked`、`pending` 或 `unknown`；不得创建 Runtime run、代答 Runtime admission，且 unknown 不得盲重放。 |
| Runtime material 的 source、correlation 或 body gate 不成立，或 material 为 duplicate / late | CP03 `RuntimeMaterialReception`；CP04 outbound evaluation；CP05 trace | reception 分类为 `rejected`、`duplicate`、`late`、`blocked` 或 `unknown`；只有 `accepted` reception 才能形成新的 CP04 evaluation。 |
| publication / observation handoff 失败、route pending 或 side effect unknown | CP04 `PublicationAttempt` / `PublicationGap`；CP05 `ObservationAttempt` / `InteractionGap` | attempt 与 gap 分层追加；source decision、material 和 trace 不回滚。`submitted` 或 `feedback_linked` 不表示 Bus delivered、downstream accepted、observed 或 evidence。 |
| duplicate、late、out-of-order 或 conflict 的 feedback / source update | 对应 owner-specific Consumer：CP01、CP03~CP06 | 以 dedup、immutable link、安全分类、gap 或 successor revision 承接；不得覆盖已提交事实，也不得把 late input 静默提升为 current。 |
| correlation 或 trace relation 不完整 | CP05 `InteractionTraceEntry` / `InteractionGap`；CP07 diagnostics / freshness surface | CP05 追加 open / blocked / unknown gap；source fact 继续成立，Query 与 projection 显式暴露不完整，而不修复 source truth。 |
| external context snapshot / resolution stale、conflict、unavailable 或 unknown | CP06 resolution / gap；CP07 projection / outlet | 形成 purpose-specific resolution 或 gap 并收紧后续 policy posture；不重裁历史 decision，不以 last-known snapshot 伪装 resolved，也不把 resolution 写成 authorization。 |
| projection rebuild 失败、watermark 不完整或来源不可证明 | CP07 `MemberProjectionState` 与 summary / diagnostics Query | 显式呈现 `stale`、`rebuilding`、`degraded`、`failed` 或 `unknown`；只有完整覆盖 target watermark 才可为 `current`，且不反写 CP01~CP06。 |
| capability outlet 的 safe ref、resolution 或 exact consumer contract 缺失 / 过期 | CP06 capability resolution；CP07 `CapabilityOutletView` | outlet 呈现 `not_available`、`stale` 或 `gap`；不自建 registry、不复制 definition、不授权 invocation，也不宣称 execution readiness。 |
| member-specific carrier / route、image release / entry 或其他 exact seam 尚未闭口 | 受影响的 CP01~CP07 Consumer、Event、Port 与 Job | 只保留 transport-neutral logical seam 与 object-bound `blocked` / `waiting` / `gap` 姿态；不私造 schema、route、adapter、IPC、manifest 或已连通关系。 |

异常首先由所属 owner 分类并提交 body-free local history；外部 side effect 无法证明时，`unknown` 是 fence。后续只能由新的 formal basis、matching feedback 或 successor 形成新的关联，不能由时间、Query、配置或默认值自动放行。

| 禁止配置化边界 | 原因 | 若需改变应回到哪里 |
|---|---|---|
| `ProjectMemberRef` 执行主语、`GlobalMemberRef` 身份锚及其一致性 | 是 CP01 admission invariant，不能由 profile 或环境覆盖。 | 正式 `00`、Work / Identity owner、ADR-0004 与 CP01 校准。 |
| member 与 Runtime、host、Bus、Governance、Tools、Conversation、Observability 等 owner 的 truth 边界 | 配置不能创造第二 run、policy、registry、health、delivery 或 observed truth。 | 对应 owner 合同与正式 `01` 架构边界。 |
| fail-closed、unknown fence、blocked / pending / stale / gap 的显式性 | 配置化放行会把未证明 source 或 side effect 伪装为成功。 | 正式 `00` / `01`、Step 3 约束与第 9 章状态口径。 |
| screening rule truth、authorization 与 allowlist / denylist 裁决 | member 只消费正式结果或 safe snapshot，不取得本地 policy truth。 | Governance owner 与 CP02 / CP06 设计。 |
| forbidden-body、body-free 与低敏低基数边界 | 正文、secret、definition、complete log 等不得因运行差异穿越数据边界。 | 正式 `00` / `01` 与 CP02~CP07 对象、流和接口。 |
| 状态迁移、append / successor history、dedup 与 unknown-side-effect fence | 这些是领域结构，不能通过开关启用覆盖历史、盲重放或 late upgrade。 | Step 3、Step 8、Step 9；具体受约束实现留给 `03`。 |
| local-truth-first、CP06 唯一 source update owner、CP07 no-write 与 Query no-write | 不能用配置改变 owner、回滚语义或 projection 写权。 | 正式 `01` 及 CP06 / CP07 的接口、流程和状态。 |
| Core-only compile 分类与 `L2M-UP-001~008` 的 pending 语义 | 配置不能闭合未定的 host、image、Runtime、event、credential、policy 或 subject 合同。 | 全局依赖裁剪规则、第 7 章与第 13 章及对应上游 / sibling 正式合同。 |

本章只识别配置影响轮廓，不定义配置项清单、格式、默认值、环境变量、secret 名称、加载器实现或 adapter constructor 参数。上述影响应先在 `03-详细设计.md` 收敛为 effective configuration、validation、provenance 与 injection 的实现契约；`04-配置设计.md` 才在其门禁满足后说明填写、校验和使用。

| 新增状态族、改变状态含义 / 禁止迁移，或静默升级 unknown / gap / stale | Step 9 | 用 retry、时间、缓存、默认成功或 feature flag 修改状态语义。 |
| 放宽 forbidden-body、fail-closed、duplicate / late、projection 或 pending seam 边界 | Step 10 | 将 raw body、secret、definition、complete log 或 external success 写入 record / view。 |
| 改变配置影响面或允许配置绕过 owner、状态、安全、history、source-owner 或 pending 红线 | Step 11 | 以 environment key、profile 或 deployment 参数突破领域约束。 |

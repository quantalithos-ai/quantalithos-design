### 4.1 布局决策与依赖方向

采用 planned **workspace 多 crate 架构**，不采用单 crate，也不按 CP01～CP07 分 crate。CP 是业务责任轴；crate 是编译依赖和实现分层轴。`api`、`worker`、`jobs` 都是 library-only logical entry，当前没有已锁定 binary、route、server、worker loop 或 scheduler。

```text
core-contracts
      ^
      |
  contracts
      ^
      |
    domain
      ^
      |
 application  <---- infra implements application-owned ports
      ^                    ^
      |                    |
 api / worker / jobs -------+
```

关键说明：

- 图只表达 planned code / crate dependency，不表达 network、event route、IPC、host assembly 或部署拓扑。
- `application` 定义 Port、UoW、idempotency；`infra` 向内实现。`application` 不依赖 concrete infra。
- `api`、`worker`、`jobs` 只通过 facade / named service 调 application，不直写 Store 或 mutation domain。

本章以 crate / 模块为组织轴；CP01～CP07 是横跨模块的业务责任轴，不能被机械地变成 crate。所有模块均为 planned library contract。`application` 是所有 infrastructure-facing Port 的唯一抽象 owner，`infra` 是唯一实现层；`api`、`worker`、`jobs` 只通过 named service 或 facade 进入 application。

### 5.1 共用模块边界

| 规则 | 实现约束 |
|---|---|
| 正向执行主语 | 所有正向操作均以匹配的 `ProjectMemberRef + GlobalMemberRef` 双锚为前提；不得加入 personal、匿名或第三执行主语。 |
| truth 边界 | local / support / derived-read truth 仅由对应 domain object、application 编排与 local Store 承接；外部 owner 只以 typed ref、safe resolution、attempt、gap 或 blocked outcome 进入。 |
| 入口边界 | `api`、`worker`、`jobs` 不直接调用 Store、domain transition、resolver、handoff 或 UoW；它们不得自行构造 business ID、digest、result 或 receipt。 |
| Query | 16 个 Query 永远 no-write：不得 digest、reserve、refresh、rebuild、reconcile、append、save result / audit / projection，亦不得调用 resolver 或 handoff。 |
| replay | Command、Consumer、Job 的 duplicate 只能读取同 channel、同 operation、同 relation、同 digest、同 typed stored carrier；carrier 缺失或不匹配即 fail-closed。 |
| external seam | `Blocked`、`Waiting`、`Unknown` 是保守业务 surface；adapter 可返回安全结果，但不把 local attempt 或 slot availability 升格为 host、Runtime、downstream 或 source owner 的正向事实。 |
| dependency | `core-contracts` 是唯一 planned sibling compile candidate；runtime、event、ref、adapter、fake 与 persistence 关系均不等于 Cargo dependency。 |

### 5.2 `contracts`

| 项 | 模块契约 |

| capability → object | 将 local ID、external typed ref、双锚、metadata、safe reason / marker、state value、page / view、typed result、receipt、Job report 和 semantic candidate 收敛为 public carrier。 |
| 允许依赖 | 仅可使用已经核验且确有需要的 `core-contracts` primitive。 |
| 禁止依赖 | 不依赖 `domain`、`application`、`infra`、entry crate 或任何 sibling business crate；不拥有 foreign body、route、topic、authorization、delivery 或 Runtime outcome。 |
| Port / Adapter 位置 | 不定义 infrastructure Port，不实现 adapter。外部 carrier 的 exact schema 未闭合时只保留 opaque typed ref / safe category，不建立 local shadow schema。 |
| 错误与测试切口 | 使用 `MemberContractError` 与 protocol-safe issue 表达 missing、unsafe carrier、owner mismatch；planned cut 覆盖 DTO construction、二级 public type、body-free、metadata、receipt / report 与 enum compatibility。 |

`events.rs` 中的 24 项只表示 semantic outbound candidate 的名称和 local source-fact 语义。`L2M-UP-005` 未关闭前，它们不是 Event envelope、payload、publisher、outbox record、route、topic、retry、DLQ 或 delivery contract。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源：
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 8 的“Shared protocol helpers”“Command / Query / Consumer / Job cards”“canonical digest closure”及“typed stored-result / replay closure”。该文件是每个 DTO 字段、二级类型、selector / source map 和 callable signature 的唯一细节来源。

所有 public protocol 位于 planned `contracts` crate。公共 carrier 只能包含双锚、typed ref、safe summary / category、有限 state、metadata、receipt、report、marker 与 body-free view；不得包含 foreign body、secret、credential material、Runtime context / plan / outcome、tool input / output、conversation truth、evidence body、route 或 transport detail。

### 7.1 共享协议纪律

| 项 | 固定契约 |
|---|---|
| operation identity | `MemberCommandName`、`MemberQueryName`、`MemberConsumerName` 与 `MemberOperationsJobKind` 是有限集合；entry 先完成 name 与 typed body 的显式映射，不能按字符串、route、字段顺序或 ref 顺序动态派发。 |
| subject / metadata | Command、Consumer、Job 使用 `MemberSubjectAnchor` 双锚及可信 metadata；Query 使用可信 actor / query metadata，但不携带 idempotency key。 |
| public outcome | Write surface 仅使用 `Accepted`、`Rejected`、`Blocked`、`Waiting`、`Unknown`、`DuplicateReplayed`、`InFlight`、`Conflict` 等有限 disposition；safe issue 不携带 SQL、SDK、HTTP、payload 或 stack trace。 |
| page / view | Query 只返回 body-free visibility / freshness / page surface；repository cursor、Store version、watermark 和 external offset 不直接外露。 |
| canonical digest | 仅 Command、Consumer、Job 形成 canonical typed input；稳定 business field 可参与，request ID、idempotency key、trace、timestamp、random ID、raw body、secret、route / topic、scheduler / run identity 与 adapter private state 必须排除。 |
| Query no-write | Query 没有 digest、reservation、stored-result relation 或 refresh / rebuild / reconcile / handoff 资格。 |
| stored replay | result kind 与 channel 固定配对：Command result / rejection、Consumer receipt、Job report；duplicate 必须从 matching completed relation 读取完整 carrier。 |

### 7.2 Command（10）

每个 Command 先验证 `MemberCommandRequest<T>`、双锚、metadata 与 typed body，再建立 `MemberOperationContext`、canonical digest 和 idempotency relation。只有 `Reserved` 可进入对应 named service；accepted 或 valid non-positive result 均必须以完整 typed value / rejection、result shell 和 reservation completion 在同一 logical UoW 内闭合。入口 pre-gate 拒绝不建立 relation。

| Command | typed body 的选择键 | accepted result carrier | 唯一 application owner |
|---|---|---|---|
| `AdmitMemberStartup` | double anchor、startup context ref、credential ref | `StartupAdmission` | `PresenceApplicationService` |
| `EstablishMemberPresence` | double anchor、admission ID、start context | `MemberPresence` | `PresenceApplicationService` |
| `TransitionMemberPresence` | double anchor、presence ID、target state、reason、expected revision | `MemberPresence` successor | `PresenceApplicationService` |
| `PrepareHostCollaboration` | double anchor、presence ID、kind、purpose、safe category | material + attempt typed value | `HostCollaborationService` |
| `EstablishSubscriptionScope` | double anchor、presence ID、body-free scope、resolution ID | `SubscriptionScopeDecision` | `SubscriptionScopeService` |
| `ReplaceSubscriptionScope` | double anchor、decision ID、expected revision、scope、resolution ID | `SubscriptionScopeDecision` | `SubscriptionScopeService` |
| `SubmitScreenedFactToRuntime` | double anchor、screening / inbound IDs、Runtime boundary / resolution ref | delivery decision + local attempt value | `RuntimeMediationService` |
| `LinkRuntimeAdmissionResult` | double anchor、attempt ID、formal admission ref、classification、source ref | `RuntimeResultLink` | `RuntimeMediationService` |
| `ResolveExternalContext` | double anchor、owner-typed source ref、kind、purpose、scope、freshness | snapshot + neutral resolution / gap value | `ExternalContextMirrorService` |
| `RequestExternalContextRefresh` | double anchor、source ref、kind、purpose、scope、safe reason | refresh relation + gap value | `ExternalContextMirrorService` |

`ReplaceSubscriptionScope` 的 old decision supersede lane 受 `scope_supersede_gap` 阻塞；implementation 不得将 Store save 当作 domain transition。涉及 host、credential、Runtime 或 screening exact contract 的 positive lane 同时受相应 `L2M-UP-*` blocker 约束。

### 7.4 Consumer（14）

Consumer 以 owner transport 已验证后的 transport-neutral logical envelope 进入 `worker`；它不是 Core / Bus wire envelope，也没有 CloudEvents、topic、route、ack、DLQ、IPC 或 delivery semantics。10 个 external Consumer 使用 verified external source identity；4 个 committed-fact Consumer 只接受已提交的 `MemberCommittedFactRef` source。

| Consumer 分组 | 名称 | application owner | 本地允许结果 |

| CP06 source update | `SubjectIdentityContextUpdateConsumer`、`PolicyContextUpdateConsumer`、`RuntimeBoundaryContextUpdateConsumer`、`CapabilityContextUpdateConsumer`、`HostRouteContextUpdateConsumer` | ExternalContextMirror | owner-specific snapshot / neutral resolution / gap；不建立 generic resolver、registry、route 或 source-owner truth。 |

### 7.6 Operations Job（5）

Job 以 `MemberJobRequest<T>`、double anchor、logical invocation ref、idempotency key 和 finite typed input 进入 `jobs`。`Completed` 仅表示 member-local continuation 已形成可回放 report，不表示 scheduler run、Runtime / host / downstream acceptance、delivery、observation、evidence、authorization、health 或 readiness。

Step 9 为 10 Command、16 Query、14 Consumer、24 blocked semantic candidate 和 5 Job 分别收口函数级处理；实现不得以 generic dispatcher 或同构模板掩盖单个接口的 owner、source、状态或 failure branch。

### 8.1 Non-Query fresh 与 duplicate 顺序

```text
validated typed entry
  -> construct MemberOperationContext
  -> canonical typed digest
  -> begin logical UoW
  -> reserve idempotency relation
  -> only Reserved enters named service
  -> load Versioned local truth or safe resolution
  -> domain factory or successor / allowed local seam step
  -> save complete typed value / rejection / receipt / report
  -> complete matching reservation
  -> commit local UoW
  -> map typed surface
```

关键规则：

- `Reserved` 不等于 accepted；typed carrier 与 relation completion 必须在同一 UoW 中先于 commit。
- duplicate 仅读取 exact stored carrier；`InFlight` 与 `Conflict` 不进入 service body。
- any external handoff 先有合法 local attempt，再得到 local `Submitted`、`Blocked`、`Waiting` 或 `Unknown` posture；不会产生 external acceptance / delivery / observation conclusion。
- Command、Consumer、Job 的逐接口 implementation 遇到 `L2M-DDD-003~007` 或 `scope_supersede_gap` 时必须停在 blocked / wait_design，不能自补 helper、gap、version 或 receipt。

### 8.2 Query read path

```text
validated typed query
  -> assert_query_no_write
  -> read visibility basis
  -> read named Store / projection / safe resolution
  -> assemble body-free visible, not-visible, not-ready,
     stale, degraded, not-available, or empty surface
```

Query 不开启 write UoW，不做 digest、reservation、result replay、refresh、rebuild、reconcile、append、successor save、audit、resolver 或 handoff。任何 inconsistency 只能以安全 reading surface 表达。

### 8.3 接口 inventory 与局部 flow owner

| family | 数量 | flow owner / implementation rule |
|---|---:|---|
| Command | 10 | `AdmitMemberStartupFlow` 至 `RequestExternalContextRefreshFlow`；每条只调用其 Step 8 named service。 |
| Query | 16 | `GetMemberPresenceFlow` 至 `GetMemberDiagnosticsFlow`；每条执行 visibility + named read，始终 no-write。 |
| Consumer | 14 | `HostFeedbackConsumerFlow` 至 `CapabilityOutletSourceUpdateConsumerFlow`；每条先做 source / schema / body / dedup gate，再走 typed receipt path。 |
| semantic candidate | 24 | `BlockedSemanticEventCandidateFlow`；全部停于 `L2M-UP-005`，无 DTO / Port / UoW / effect。 |
| Job | 5 | `PublicationRelayFlow`、`ObservationRelayFlow`、`ExternalContextRefreshFlow`、`MemberProjectionRebuildFlow`、`GapReconciliationFlow`；只能处理 finite local continuation。 |

### 8.4 函数级禁止事项

| 情形 | 禁止事项 |
|---|---|
| entry | 不由 route、actor display name、page cursor、adapter state 或 raw body 推断 subject、service、scope、resolution、state或 version。 |
| Store | 不把 `MemberStoreVersion` 以外的 revision、watermark、cursor、source version、trace、timestamp 或 result ref 当 CAS token。 |
| duplicate | 不重新执行 factory、transition、inspection、resolver、handoff、scan、refresh、rebuild或 reconciliation。 |
| external seam | 不把 local `Submitted`、feedback ref、attempt、gap 或 safe ref 标记为 Runtime executed、host accepted、downstream delivered、observation observed 或 evidence。 |
| event candidate | 不生成 event / outbox side effect；其唯一处理流是 blocked disposition。 |

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 11 的“28 个状态主语与数据所有权实现表”“logical store / collection / projection 契约”“repository 函数持久化语义”“事务边界与处理顺序”与“append-only、projection 与 replay 细则”。本章只固定逻辑持久化约束，不选择任何 physical product。

### 10.1 数据所有权与 logical Store

本仓只持久化 CP01～CP07 的 member-local truth、local material / attempt / gap、body-free snapshot / neutral resolution、trace / history、projection state / view revision、idempotency relation 与 complete typed stored carrier。Work、Identity、credential、Governance、Runtime、Tools / Method、host、downstream、Conversation、Artifact 与 observability backend 的 body、live state、authorization、health、delivery 或 execution truth 不入本仓 Store。

| logical Store / read group | 主要对象 | 持久化语义 |
|---|---|---|
| presence / host | admission、presence、host material / attempt | admission / material append-only；presence / attempt 使用 versioned successor。 |
| inbound | scope、body-free inbound fact、screening | scope successor、fact / screening append-only；不保存 raw body、Bus ack 或 policy body。 |
| Runtime mediation | delivery decision、submission attempt、result link、reception | decision / link / reception append-only；attempt versioned；不创建 Runtime run / outcome。 |
| outbound / trace | decision、material、publication / observation attempt、gap、trace | material / trace append-only；attempt / gap versioned；local handoff record 不等 external effect。 |
| external mirror | safe snapshot、neutral resolution、gap | snapshot / resolution append-only；gap versioned；不保存 owner definition、rule或 capability body。 |
| projection | summary / outlet / diagnostic view、projection state | view revision append-only；state versioned，可由 committed sources rebuild。 |
| operation relation | idempotency record、Command result / rejection、Consumer receipt、Job report | reservation 与 complete carrier 保持 exact same-relation pairing；不得用 current truth 代替 carrier。 |

pure policy、ID、ref、digest、cursor、source version、revision、watermark 与 runtime-local entry carrier 不因存在于对象中就自动成为独立 durable truth。physical DB、DDL、ORM、migration、lock、isolation、cache、queue、broker、outbox、topic、route、retention 与 scheduler 均未选择。

### 10.2 一致性不变量

| 不变量 | 强制实现口径 |
|---|---|
| identity | 新 local ID 只能来自 `MemberIdGeneratorPort`；不得由 route、event name、digest、row ID、timestamp、fake counter 或 run identity生成。 |
| mutable save | 必须按“same Store `Versioned<T>` read → domain successor → same `MemberStoreVersion` expected save → same UoW commit”执行。 |
| version separation | `MemberStoreVersion` 不能用 domain revision、source version、watermark、cursor、timestamp、trace、digest、result ref 或 idempotency key 替代。 |
| append-only | immutable decision、fact、material、snapshot、resolution、view、trace、history 与 result carrier 不得 update / delete；新 basis 使用新 ID / revision。 |
| staging | staged values 只可在同 UoW 内 read-your-own-write；commit 前对其他 UoW、Query 与 duplicate replay 不可见；rollback 后一并不可见。 |
| projection direction | 仅 committed CP01～CP06 fact / CP06 neutral resolution → CP07 state / view；projection、diagnostic、stored result 和 cache 不反写 source truth。 |
| external fence | resolver、handoff、feedback 与 Runtime / Bus seam 不参加 local 2PC；它们最多产生 local safe resolution、attempt、gap 或 typed outcome。 |
| fake parity | future durable adapter 与 deterministic fake 必须共享 PK / unique、stable order、version conflict、UoW staging / rollback、append-only、Query no-write 与 exact replay semantics。 |

### 10.3 UoW 与 protocol transaction boundary

```text
validate typed request, source, and metadata
  -> canonical digest (Command / Consumer / Job only)
  -> begin logical MemberUnitOfWork
  -> reserve idempotency relation
  -> load required Versioned local truth / safe resolution
  -> domain factory or legal successor helper
  -> append or save allowed local truth
  -> append required local trace / affected projection marker
  -> save complete typed result, receipt, or report
  -> complete the matching idempotency relation
  -> commit
```

| path | transaction rule |
|---|---|
| Command accepted | local truth / successor、required trace / projection effect、complete Command carrier 与 reservation completion在同一 UoW；当前不写 Event / outbox。 |
| Command rejection / blocked / waiting / unknown | 如合法 relation 需要保存 non-positive result，保存 complete typed rejection 后再 complete；不得写 accepted truth / positive attempt。 |
| Consumer accepted | worker source / schema / body gate 后，fact / snapshot / feedback link / gap / projection successor、complete receipt 与 completion 同 UoW。 |
| committed-fact Consumer | 只能读取 already committed finite local fact；trace / projection local effect 与 receipt 同 UoW，不从 event body推断事实。 |
| Job | local continuation、allowed attempt / gap / snapshot / resolution / projection effect、complete report 与 completion 同 UoW；Job 不修复 CP01～CP06 source truth。 |
| duplicate | reserve 分类命中后，不产生 business commit；只读取 exact stored carrier。 |
| Query | 不开始 write UoW，只读 Store / projection / resolution / trace / visibility。 |
| external handoff | local prepared material / attempt 必须先存在；external return 后才以短 local UoW 保存 Submitted / Unknown / gap successor。不得声称分布式事务或 external commit proof。 |

### 10.4 Replay、projection 与 external effect

- `Duplicate` 只接受 channel、operation、relation record、digest、result kind、result ref 与 carrier-specific identity 都匹配的 complete carrier。缺失、wrong kind、wrong relation、wrong digest 或 wrong pointer 是 consistency defect，必须 fail-closed。
- Query、duplicate replay 与 reconciliation read 不得补写缺失 history、projection、gap、snapshot 或 result。
- projection rebuild 只读取 committed fact / neutral resolution；view revision append-only，projection state versioned。source missing、gap、stale 或 assembly failure 只能映射 local read-side posture，不能回滚或修复 CP01～CP06 truth。
- external handoff 的 `Submitted`、`FeedbackLinked` 或 `Unknown` 只表示 member-local relation；不得表述为 host、Runtime、downstream 或 observation owner 已 accepted、delivered、observed、healthy、authorized 或 ready。
- `L2M-UP-005` 未关闭时，member outbound Event / outbox / publisher 的 logical persistence inventory 为零；24 项 candidate 继续 blocked。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 12 的“错误层级与可见性”“错误类型表”“内部错误映射表”“异常分支处理表”“恢复口径表”与“consistency defect catalog”。本章汇总 mapping 与恢复红线，不替代 owner-specific error carrier。

### 11.1 分层错误模型

```text
contracts guard -> MemberContractError
domain factory / policy / state -> DomainError
application orchestration -> MemberApplicationErrorCategory
Store / resolver / handoff / UoW -> MemberPortError or MemberExternalSeamOutcome
api / worker / jobs mapper -> typed protocol surface
```

| 层 | 输入 / 输出 | 禁止事项 |
|---|---|---|
| `contracts` | typed primitive、opaque ref、safe category → `MemberContractError` | 不含 transport status、payload、secret 或 foreign body。 |
| `domain` | loaded local / support truth、safe owner-bound value → `DomainError` | 不接触 Port、UoW、adapter 或 protocol error。 |
| `application` | domain result、Port error、seam outcome、operation context → finite application category / typed result | 不拼 raw adapter detail，不创造 external owner truth。 |
| `infra` | typed Port input / UoW → `MemberPortError` / conservative seam outcome | 不透传 DB / SDK / private map exception。 |
| entry module | named service output → Command outcome、Query surface、Consumer receipt、Job report | 不直接序列化 domain / Port error，不声称 transport ack / scheduler run。 |

错误与 issue 只能携带 `SafeReasonCategory`、safe typed ref、blocker ID、finite error kind 或 redacted diagnostic ref；不得包含 raw source body、credential、prompt、plan、tool content、SQL、stack trace、endpoint、route、topic 或 free-form external error text。

### 11.2 主要映射

| 条件 | Command / Consumer / Job mapping | Query mapping | 恢复类别 |
|---|---|---|---|
| invalid context、double anchor、unsafe carrier、owner mismatch | `Rejected(InvalidContext / ContractViolation)`；pre-gate 时不建立 relation | safe invalid request surface | 调用方以正式 typed input 修正；不可原样重试。 |
| domain invariant / illegal transition | `Rejected` 或 `Conflict` | 不创建 error truth | 等合法 trigger 或 targeted design repair；不得直写 state。 |
| missing local object / dependency unavailable | `Blocked` / `Waiting` / partial Job | `NotAvailable` | 依赖恢复或正式 source 到达后，以同一规则重新评估。 |
| expected version conflict | `Conflict` / later partial surface | safe unavailable / stale surface | 新 UoW reload exact version并完整 re-evaluate；不得 merge / overwrite。 |
| named upstream blocker | `Blocked(BlockedDependency)` | corresponding not-available / degraded surface | 等 owner formal contract；不得 default-pass / fake complete。 |
| waiting source / feedback | `Waiting(WaitingForSource)` | not-ready / stale surface | 等新的 formal input / controlled continuation；timeout不转成功。 |
| seam or commit unknown | `Unknown(UnknownSideEffect)` | constrained safe posture | inspect-first: only same relation、attempt、gap、stored carrier and formal owner resolution may drive later action。 |
| matching duplicate | `DuplicateReplayed` with complete typed carrier | Query 不适用 | 不运行 service / resolver / handoff / scan / rebuild。 |
| missing / wrong stored carrier | conservative `Blocked` / `Unknown` + `StoredResultUnavailable` | not applicable | manual consistency repair；绝不从 current truth重算。 |

### 11.3 异常分支与恢复红线

| 场景 | 强制处理 |
|---|---|
| write path failure before commit | rollback current local staging；不得返回 Accepted、success trace 或 external success。 |
| commit status unknown | 不换 key、不补偿性写 truth、不重新执行。先检查 same idempotency / result relation；其后只能 replay、in-flight、manual consistency defect 或正式后续 flow。 |
| rollback failure / impossible relation / forbidden persisted body | 作为 `ConsistencyDefect`，停止正向暴露并进入人工 / design repair；不静默清除 history或伪造 recovery success。 |
| `Blocked` / `Waiting` / `Unknown` | 可保存已被 Step 8 / 9 / 11 明确定义的 local non-positive carrier、attempt、gap 或 marker；不得写 external acceptance / delivery / evidence。 |
| unsupported Consumer schema / forbidden body | worker pre-gate refuse；不解析 / persist body、不进入 service、不声称 DLQ / quarantine delivery结果。 |
| 24 outbound candidate | 统一 `Blocked(L2M-UP-005)`；不存在 publish failure、retry、dead-letter或 delivery recovery contract。 |
| targeted DDD gap | 遇 `L2M-DDD-003~007` 或 `scope_supersede_gap` 立即停在 named blocker，回到 owning Step；不在 error handler、adapter、fake 或 repository 中补 helper / schema。 |

### 11.4 反模式

- 不以 `Completed` seam outcome、adapter 2xx、last-known snapshot、timeout 或 fake 成功替代 owner truth。
- 不把 `Rejected`、`Blocked`、`Waiting` 或 `Unknown` 记为 Runtime outcome、host health、delivery confirmation、observation、approval、conversation、capability truth 或 readiness。
- 不因 duplicate、missing carrier、version conflict 或 commit unknown重新运行 mutation、inspection、source resolution、handoff、scan、refresh、rebuild或 reconciliation。
- 不让 Query 因读取异常进入 retry writer、lazy refresh、projection rebuild、audit write或 other repair path。

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：
> - 建议继续阅读 Step 13 的“并发场景表”“幂等键与 canonical digest”“重复处理矩阵”“重入保护表”及“CommitStatusUnknown 重入口径”。该 Step 是 operation relation、digest include / exclude 与冲突资源的唯一细节来源。

### 12.1 统一 reservation 顺序

```text
validated typed context
  -> canonical typed digest
  -> MemberUnitOfWorkManager::begin
  -> MemberIdempotencyStore::reserve
  -> only Reserved enters named service or Job body
  -> load Versioned local records and append / produce legal successor
  -> save complete typed value, receipt, or report
  -> complete matching reservation
  -> commit
```

`Duplicate`、`InFlight`、`Conflict` 永不进入业务 body。Query 无 digest、reservation、stored-result、mutation 或 external side effect。fresh relation、result shell、complete carrier 与 completion 的 channel、operation、key、digest、result kind、result ref 必须一致。

### 12.2 幂等与 replay

| channel | stable key / identity | duplicate 必须回放 | 禁止重入 |
|---|---|---|---|
| 10 Command | `CommandMetadata.idempotency_key` + exact operation + canonical input | same Command value 或 rejection carrier | 不重新 factory、transition、credential / source resolution、host / Runtime handoff。 |
| 10 external Consumer | consumer name + normalized formal source dedup identity + canonical body-free source input | same `MemberConsumerReceipt` | 不重检 raw body、不重建 snapshot / feedback / screening / projection。 |
| 4 committed-fact Consumer | consumer name + committed fact identity + canonical input | same `MemberConsumerReceipt` | 不扫描 arbitrary Store、不重写 source fact或 projection。 |
| 5 Job | Job metadata key + job kind + canonical finite input | same `MemberJobReport` | 不重复 listing、scan、relay、resolution、rebuild、reconcile或 report assembly。 |

matching duplicate 必须同时验证 relation、channel、operation、digest、kind、result pointer 和 carrier-specific identity。`InFlight` 只等 existing relation 完成；`Conflict` 不覆盖既有 relation。missing / wrong carrier 不是“空成功”，而是 consistency defect。

### 12.3 并发资源与 CAS

| 冲突资源 | 保护方式 | loser / recovery |
|---|---|---|
| presence、scope、host / Runtime / publication / observation attempt、gap、mirror、projection state | same Store `Versioned<T>.version` + expected save in same UoW | `VersionConflict`；new UoW reload + full policy re-evaluation only。 |
| immutable fact / material / snapshot / trace / view | typed PK / business unique append guard | duplicate key / relation defect，不转换为 business duplicate replay。 |
| idempotency reservation / typed carrier | exact key + relation / digest + complete-carrier pairing | `InFlight`、`Conflict` 或 `StoredResultUnavailable`；不建立 second writer。 |
| projection cursor / watermark | committed-source coverage marker，独立于 Store version | older source不能覆盖 newer state；映射 stale / conflict / partial，不修复 source。 |
| external unknown side effect | attempt / gap / stored relation fence | inspect same relation / formal feedback；不得 resend、换 key或产生 second claim。 |

### 12.4 Commit-unknown 与 fake parity

当 UoW commit 的 durable status 不可证明时，唯一允许的重入口径是读取同一 reservation / result relation、local attempt / gap 与正式 owner feedback / resolution。禁止以新 key重新 mutation、compensating truth、blind resend或删除 Unknown marker。future fake 与 durable adapter 均必须保留此顺序、same-relation replay、CAS、missing-carrier、unknown fence 与 no-write Query 语义；fake 不能凭 private map 默认 `Completed`。

本章只定义代码绑定点，不定义完整配置手册、部署参数或物理产品。配置不得改变执行主语、truth owner、body-free、状态迁移、幂等 / CAS、Query no-write 或 `L2M-UP-005` 的 blocked 语义。

### 13.1 配置读取与注入边界

```text
raw config source
  -> infra::config::load
  -> validate_and_redact
  -> MemberRuntimeConfigRef / section refs / provenance
  -> infra::runtime_builder

```

关键说明：

- 只有 `infra/runtime_builder.rs` 将 validated ref 绑定到 local Store、UoW、idempotency / typed-result、Clock、ID、digest、owner-specific resolver、host / Runtime / publication / observation handoff 或 `BlockedSeamState`。
- `application` 只接收 Port 和 validated typed parameter；`domain`、`contracts` 不读取配置，也不接收 secret、URL、topic、cron、retry policy body 或部署拓扑。

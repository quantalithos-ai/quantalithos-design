## 1. 模块职责描述

**本模块做什么**:
- 持有正式 member runtime persona / interaction endpoint / exposed capability / execution actor binding / visible member summary 真相或正式材料
- 把 identity 的静态身份输入收束为运行态成员主体
- 把 runtime、conversation、member-service、tools/capability-hub 之间的成员侧接缝稳定化
- 向下游提供成员主体层接口、可见材料和能力出口

**本模块不做什么**:
- 不持有 `GlobalMember` 静态身份真相
- 不持有 `ExecutionInstance` / `CurrentStep` 真相
- 不持有 `MemberExecutionHost` / session / worker 真相
- 不持有 `Conversation` / `Turn` 真相
- 不持有 `tool definition / capability catalog` 真相

## 2. 前置设计前提 / 内容采集提示

### 2.1 为什么在写 03 前要先采集内容

`03-详细设计` 的目标不是再讲 member“为什么存在”,而是让开发者可以直接开始实现:
- runtime persona 如何从 identity 输入构造
- interaction endpoint 如何接住对外交互
- exposed capability 如何从 capability-hub / tools 输入映射出来
- execution actor binding 如何给 runtime 提供正式成员主体绑定
- visible member summary / member-facing material 如何给 conversation / UI 提供只读材料

如果不先把这些内容采集清楚,03 很容易退化成:
- 把 member 写成 identity 的运行态投影表
- 把 member 写成 runtime actor ID 的包装层
- 把 member 写成 conversation sender 材料的拼装层
- 把 capability definition 和 exposed capability 混成一层

### 4.2 总解释

- **真相写入**发生在: MemberRuntimePersona、MemberMode、MemberAvailability、ExecutionActorBinding、ExposedCapability 的正式持久化
- **主体生成**发生在: static identity / capability profile 被收束成 runtime persona
- **交互入口形成**发生在: caller/runtime/conversation 对某成员的正式入口被解析
- **能力出口形成**发生在: tools/capability-hub 的能力输入被裁剪为当前可暴露出口
- **只读输出**发生在: visible summary / profile view / member-facing material 向 conversation/UI 提供材料
- **同步路径**主要是: CreateMemberPersona / BindExecutionActor / ExposeMemberCapability 主写链
- **异步最终一致**主要是: visible summary / profile / outlet views 的刷新与重建

## 5. 按主要部分展开实现要点

### 5.1 为什么要先按主要部分展开

`03-详细设计` 不能直接从 `Persona / Endpoint / Capability / Summary` 这些对象平铺开始。
更稳的写法是:
- 先承接 `02-概要设计.md` 已确认的五个主要部分
- 再说明每个主要部分分别落到哪些对象、命令/函数、状态约束、存储与视图
- 最后再进入横向的对象模型、流程、存储、异常与测试细节

这样可以避免:
- `02` 讲的是主体 / 交互 / 能力 / execution bind / visible summary,`03` 却只剩 profile 字段表
- 实现者知道有 visible summary,却不知道它归哪个责任单元控制
- persona、exposed capability、execution actor binding 三条链路脱节

- 承接 `identity` → `member persona` 主线
- 承接 `persona ≠ static identity` 这条硬边界

#### 5.2.2 输入 / 输出 / 外部交互图

```text
│ identity                   │
│ - static member profile    │
│ - role / capability input  │
└────────────┬───────────────┘

┌────────────────────────────┐
│ member                     │
│ - MemberRuntimePersona     │
```

#### 5.2.3 涉及的对象定义

```rust
/// 表示一个 AI 成员在运行态对外出现的主体画像。
pub struct MemberRuntimePersona {
    /// 成员主体唯一标识。
    pub member_persona_id: MemberPersonaId,
    /// 关联的静态成员引用。
    pub global_member_ref: GlobalMemberRef,
    /// 当前运行态模式。
    pub mode: MemberMode,
    /// 当前可见可用状态。
    pub availability: MemberAvailability,
    /// 主体行为画像。
    pub behavior_profile: MemberBehaviorProfile,
}

/// 表示成员当前运行态模式。
pub enum MemberMode {
    /// 标准协作模式。
    Normal,
    /// 受限模式。
    Restricted,
    /// 只读 / 只观察模式。
    ObserveOnly,
}

/// 表示成员当前对外可见可用状态。
pub enum MemberAvailability {
    /// 当前可对外交互。
    Available,
    /// 当前可见但暂不可执行。
    VisibleButUnavailable,
    /// 当前暂不对外开放。
    Hidden,
}

/// 表示成员行为画像,用于约束当前主体如何对外表现。
pub struct MemberBehaviorProfile {
    /// 行为画像自身标识。
    pub behavior_profile_id: BehaviorProfileId,
    /// 当前主体对外行为摘要。
    pub behavior_summary: String,
}
```

这些对象在该部分里分别承担:
- `MemberRuntimePersona` 负责把静态身份收束为运行态主体本体
- `MemberMode` 负责表达当前运行态约束模式
- `MemberAvailability` 负责把“是否对外可见”和“是否可交互”区分开
- `MemberBehaviorProfile` 负责把主体在运行态的行为边界和外显方式固定下来
- 它们都不替代 GlobalMember 真相本体

#### 5.2.4 关键函数代码片段

```rust
/// 根据静态身份与能力输入构造一个运行态成员主体。
fn create_member_persona(
    persona_repo: &dyn MemberPersonaRepo,
    draft: CreateMemberPersonaDraft,
) {
    // [MemberRuntimePersona::从草稿创建]
    // 先把 identity 输入和运行态要求收束成正式 persona 对象。
    let persona = MemberRuntimePersona::from_draft(draft);

    // [persona.校验可生成]
    // 再校验静态引用、mode、availability 与基础行为画像是否成立。
    persona.validate_creatable();

    // [persona_repo.保存主体画像]
    // 最后把运行态成员主体写入正式真相层。
    persona_repo.save(persona);
}
```

这段实现守住的边界是:
- persona 必须独立于 static profile 存在
- static identity 是输入,不是运行态主体本体
- 可见模式和主体画像都应在 member 真相层落定,而不是在 UI 临时拼接

#### 5.2.5 该部分的边界与非职责
- 不负责 execution actor binding 真相
- 不负责 member-service host/session 真相
- 不负责 visible summary 读模型本体
- 不负责 capability definition 真相

#### 5.2.6 该部分与其他主要部分的接缝
- 向 `成员对外交互接口部分` 提供主体锚点
- 向 `成员能力暴露与行为出口部分` 提供 mode / availability 输入
- 向 `成员可见摘要与下游消费接缝部分` 提供 persona 本体

#### 5.2.7 该部分的状态 / 约束 / 易错点
- 可见主体不等于可执行主体
- persona 不能被 conversation sender material 反向替代
- static profile 变更后,不能假定 visible summary 自动同步成功

这些对象在该部分里分别承担:

- `MemberInboundInteraction` 负责把外界输入显式化
- `MemberReplyContract` 负责约束成员对外如何回复或回应
- `MemberActionContract` 负责约束成员当前允许对外触发哪些动作出口

#### 5.3.4 关键函数代码片段

```rust
/// 解析当前成员的正式交互入口,让上游通过主体层而不是静态身份或消息层访问成员。
fn resolve_member_interaction_endpoint(
    endpoint_repo: &dyn EndpointRepo,
    persona: &MemberRuntimePersona,
) {
    // [MemberInteractionEndpoint::从主体创建]
    // 先从正式主体画像构造当前有效的成员交互入口。
    let endpoint = MemberInteractionEndpoint::from_persona(persona);

    // [endpoint.校验可暴露]
    // 再校验当前 mode / availability 是否允许暴露该 endpoint。
    endpoint.validate_exposable();

    // [endpoint_repo.保存交互入口]
    // 正式保存 member interaction endpoint 给下游消费。
    endpoint_repo.save(endpoint);
}
```

这段实现守住的边界是:
- member endpoint 必须由正式主体层导出
- conversation 消息不定义 member 入口
- runtime 也不应直接绕过 endpoint 去“假装拥有成员主体”

#### 5.3.5 该部分的边界与非职责
- 不负责 Conversation / Turn 真相
- 不负责 execution truth
- 不负责宿主承载真相
- 不负责 capability 定义真相

#### 5.3.6 该部分与其他主要部分的接缝
- 从 `成员主体与运行态画像部分` 获取 persona
- 向 `成员与执行主线接缝部分` 提供 execution-facing 入口材料
- 向 `成员可见摘要与下游消费接缝部分` 提供 sender-facing 输入

#### 5.3.7 该部分的状态 / 约束 / 易错点
- endpoint 暴露与否受 persona mode / availability 约束
- inbound interaction 是主体层输入,不等于消息真相本体
- reply/action contract 不能越过 exposed capability 边界

```rust
/// 为 runtime 构造正式的成员执行主体绑定。
fn bind_execution_actor(
    binding_repo: &dyn ExecutionActorBindingRepo,
    persona: &MemberRuntimePersona,
    execution_ref: RuntimeExecutionRef,
) {
    // [ExecutionActorBinding::从主体与执行引用创建]
    // 先把“哪个成员主体”与“哪个执行主线”正式绑定起来。
    let binding = ExecutionActorBinding::new(persona.member_persona_id, execution_ref);

    // [binding.校验绑定合法性]
    // 再校验该主体当前是否允许成为执行 actor。
    binding.validate_bindable();

    // [binding_repo.保存执行主体绑定]
    // 正式保存 execution actor binding,供 runtime 和 member-service 消费。
    binding_repo.save(binding);
}
```

```text
    2. 构造 profile/ui-facing material
    3. 保存只读画像材料
```

### 7.5 命令前置校验清单

| 命令 | 权限校验 | 审批校验 | 责任链校验 | 不通过时处理 |
|---|---|---|---|---|
| CreateMemberPersona | identity 输入合法 | 无 | static member ref 合法 | 拒绝创建 |
| ResolveMemberInteractionEndpoint | 当前 persona 可见 | 无 | endpoint context 合法 | 拒绝暴露 |
| ExposeMemberCapability | capability input 合法 | 无 | outlet 规则合法 | 拒绝暴露 |
| BindExecutionActor | persona 当前可绑定为 actor | 无 | execution ref 合法 | 拒绝绑定 |
| BuildMemberVisibleSummary | visible rule 合法 | 无 | material 边界合法 | 拒绝生成 |

### 7.6 关键状态机 / 非法转换与约束

#### 状态机图

```text
MemberAvailability:
available → visible_but_unavailable → hidden
hidden → available (after re-enable)

ExecutionActorBinding:
active → inactive

ExposedCapability:
available → unavailable
unavailable → available (after re-enable)
```

#### 非法转换与约束表

| 场景 | 是否允许 | 说明 |
|---|---|---|
| static identity 直接充当 runtime persona | ❌ | 运行态主体必须独立构造 |
| exposed capability 直接等于 capability catalog 全量 | ❌ | 必须经过 member 侧裁剪 |
| conversation visible summary 反向覆盖 persona 真相 | ❌ | summary 只读 |
| inactive actor binding 被继续复用 | ❌ | 旧 binding 失效后不得再用 |
| 宿主 unavailable 仍把成员标记为可执行且不解释 | ❌ | 可见与可执行必须显式分层 |
| hidden persona 继续暴露 interaction endpoint | ❌ | hidden 不得继续对外暴露主体入口 |
| unavailable capability 被 member 继续宣称为当前可用 | ❌ | 当前暴露能力必须与 outlet 真相一致 |

#### 关键约束说明

- `MemberAvailability.visible_but_unavailable` 只表示“仍可见,但暂不可执行/交互”,不等于 hidden
- `ExecutionActorBinding.inactive` 后,只能重建新 binding,不能直接重新激活旧 binding
- `ExposedCapability.available=false` 不代表能力定义消失,只代表当前 member 不对外暴露该出口

## 11. 运行期主线场景

### 11.1 场景 A · identity 输入形成 runtime persona

```text
identity static member ready
      │
      ▼
create runtime persona
      │
      ▼
生成 mode / availability / behavior profile
      │
      ▼
刷新 visible summary 与 capability outlet
```

**开发者关注点**:
- static identity 只是输入,不是 persona 本体
- persona 与 visible summary 必须分层
- capability outlet 必须跟随 persona 当前模式裁剪

### 11.2 场景 B · runtime 绑定执行 actor

```text
runtime needs actor
      │
      ▼
bind execution actor
      │
      ▼
生成 execution-facing member context
      │
      ▼
runtime / member-service 消费该 context
```

**开发者关注点**:
- binding 不等于 execution truth
- member-service 只能消费 member-facing execution context
- 旧 binding 失效后不得复用

### 11.3 场景 C · 成员暴露能力并生成可见摘要

```text
tools/capability-hub input changed
      │
      ▼
expose capability
      │
      ▼
build visible member summary
      │
      ▼
conversation / UI 读取可见材料
```

**开发者关注点**:
- capability definition 不等于 exposed capability
- visible material 只是读侧
- 同一成员在 runtime / conversation / UI 看到的主体语义必须一致

### 11.4 场景 D · persona 变化后多下游同步

```text
identity / capability input changed
      │
      ▼
MemberRuntimePersona updated
      │
      ├─ exposed capability rebuilt
      ├─ execution actor binding remains valid or is invalidated
      └─ visible summary / UI material rebuilt
                │
                ▼
conversation / runtime / UI 重新消费同一成员主体语义
```

**开发者关注点**:
- persona 更新后,visible summary 与 outlet 必须同步重建
- binding 若不再合法必须显式失效,不能继续悬挂旧值
- 同一成员在 runtime / conversation / UI 三侧看到的主体语义必须重新对齐

### 11.5 外部交互入口归属

| 外部来源 | 进入入口 | 落到哪个主要部分 | 结果 |
|---|---|---|---|
| identity profile | CreateMemberPersona | 成员主体与运行态画像部分 | runtime persona |
| runtime actor bind request | BindExecutionActor | 成员与执行主线接缝部分 | actor binding |
| tools/capability-hub input | ExposeMemberCapability | 成员能力暴露与行为出口部分 | exposed capability |
| conversation/UI render demand | BuildMemberVisibleSummary | 成员可见摘要与下游消费接缝部分 | visible summary / material |

## 12. 数据与存储设计

### 12.1 先分清写模型 / 读模型 / 证据引用

| 对象 | 类型 | 是否持久化 | 说明 |
|---|---|---|---|
| MemberRuntimePersona / Mode / Availability | 写模型 | 是 | 成员主体真相 |
| ExecutionActorBinding | 接缝写模型 | 是 | runtime actor bind |
| ExposedCapability / MemberCapabilityOutlet | 写模型 | 是 | 成员能力出口 |
| VisibleSummary / ProfileView / ConversationMaterial | 读模型 | 是/可重建 | 成员可见层 |
| GlobalMemberRef / CapabilitySnapshotRef / RuntimeExecutionRef | 引用 | 随真相持久化 | 只存 ref / snapshot |

### 12.2 关系与索引建议

| 表/集合 | 关键索引 |
|---|---|
| member_runtime_personas | `member_persona_id`, `global_member_ref`, `availability` |
| member_outlets | `member_persona_id`, `capability_ref`, `available` |
| execution_actor_bindings | `member_persona_id`, `execution_ref`, `active` |
| member_visible_materials | `member_persona_id`, `visible_state` |
| member_profile_views | `member_persona_id` |

**索引理由**:
- `global_member_ref` 支撑 static identity → runtime persona 的稳定映射
- `capability_ref + available` 支撑可暴露能力过滤与越界检测
- `execution_ref + active` 支撑 runtime actor bind 查询与旧 binding 失效校验
- `visible_state` 支撑 UI / conversation 高频读取当前可见状态

### 12.3 持久化建议

| 对象 | 存储方式 | 理由 |
|---|---|---|
| MemberRuntimePersona | 主表 | 主体真相 |
| ExposedCapability / Outlet | 主表 | 当前能力出口真相 |
| ExecutionActorBinding | 主表 | runtime 接缝不可丢 |
| Visible materials | 可重建读模型 | 读侧外显与真相解耦 |

**存储边界说明**:
- `MemberRuntimePersona` 保存运行态主体真相,但不得回写 static identity 真相
- `ExposedCapability / MemberCapabilityOutlet` 建议快照化存储当前可暴露结果,避免 caller/UI/runtime 各自即时拼装
- `ExecutionActorBinding` 应保留失效历史,避免旧 binding 漂移时无法审计
- `VisibleSummary / ProfileView / ConversationMaterial / UIFacingMaterial` 都属于外显读模型,允许重建,不得反写 persona/outlet 真相

### 12.4 关键校验

- persona 构建前必须校验 static identity / capability input 最小成立条件
- exposed capability 必须经过当前 persona mode / availability 裁剪
- execution actor binding 必须绑定合法 persona 与 execution ref
- visible summary / material 不能越出当前主体外显边界

### 12.5 建议表结构草案

#### `member_runtime_personas`

| 字段 | 类型 | 说明 |
|---|---|---|
| member_persona_id | uuid | 主键 |
| global_member_ref | jsonb/text | 静态成员引用 |
| mode | enum | normal/restricted/observe_only |
| availability | enum | available/visible_but_unavailable/hidden |
| behavior_profile | jsonb | 行为画像 |

#### `execution_actor_bindings`

| 字段 | 类型 | 说明 |
|---|---|---|
| binding_id | uuid | 主键 |
| member_persona_id | uuid | 归属成员主体 |
| execution_ref | jsonb/text | runtime execution 引用 |
| active | bool | 当前绑定是否有效 |

## 13. 读模型与投影设计

### 13.1 总体结构

```text
Persona / Outlet / Binding write model
   │
   ▼
projection builders
   ├─ visible summary
   ├─ profile view
   └─ conversation member material
```

### 13.2 关键读模型说明

| 读模型 | 输入 | 输出 |
|---|---|---|
| MemberVisibleSummary | persona + availability + visible rules | 高频可见摘要 |
| MemberProfileView | persona + exposed capability | UI 画像材料 |
| MemberConversationMaterial | persona + visible capability + sender rules | conversation sender / participant 材料 |

### 13.3 一致性说明

- 读模型允许最终一致
- visible summary / profile / material 都只读
- runtime / conversation / UI 看到的是 member 主体真相的投影,而不是主体真相本体
- visible material 漂移时必须能从 persona / outlet 正式真相重建
- execution actor binding 失效后,相关 member-facing execution context 也必须同步失效或重建
- member-service 消费的是 execution-facing member context,而不是 persona 全量真相

## 14. 异常与补偿设计

| 场景 | 处理 |
|---|---|
| static identity 缺失 | 拒绝 create persona |
| capability input 不足 | 降级 exposed capability 或拒绝暴露 |
| actor binding 非法 | 拒绝 binding |
| visible summary 漂移 | 以 persona/outlet 真相重建 |

### 14.1 重试 / 降级 / 熔断 / 补偿
- capability-hub / tools 延迟时允许降级为基础能力出口,但不得错误扩权
- runtime bind 暂不可建时允许重试 binding,但不得伪造 active binding
- visible material 构建失败时允许稍后重建,但不得覆盖主体真相
- static identity 输入更新后,persona/outlet/visible summary 应支持重建与重新对账,防止多下游主体漂移
- execution actor binding 失效后,旧 runtime/member-service consume context 必须失效或重建,不能继续使用旧主体上下文

### 14.2 按主要部分归属的失败模式

| 主要部分 | 典型失败 | 检测点 | 处理策略 | 补偿 / replay |
|---|---|---|---|---|
| 成员主体与运行态画像部分 | persona 构建失败 / static input 缺失 | persona trace | 拒绝创建 / 修正输入 | replay persona build |
| 成员对外交互接口部分 | endpoint 暴露错误 / reply contract 越界 | endpoint trace | 收紧 endpoint / 拒绝暴露 | replay endpoint build |
| 成员能力暴露与行为出口部分 | exposed capability 越界 / 漂移 | outlet trace | 收紧暴露范围 / rebuild outlet | replay outlet |
| 成员与执行主线接缝部分 | actor bind 非法 / 旧 binding 漂移 | binding trace | 拒绝 bind / 失效旧 binding | replay binding |
| 成员可见摘要与下游消费接缝部分 | visible material 漂移 / 越界 | summary compare | 重建 material | full rebuild |

## 15. 实现红线 / 开发禁止事项

- 不允许把 MemberRuntimePersona 简化成 identity 静态 profile 的副本
- 不允许把 execution actor binding 当作 runtime execution truth 本体
- 不允许把 exposed capability 直接等同 capability catalog 全量
- 不允许把 visible summary / sender material 反向定义 persona 真相
- 不允许让 member-service 宿主真相反向覆盖 member 主体真相
- 不允许在 binding inactive 后继续把旧 actor context 暴露给 runtime / member-service
- 不允许让 visible member 直接等同 executable member 而不显式区分 availability

## 18. 结论

本详细设计的核心结论是：
- `L2-member` 的实现必须围绕五个主要部分展开,而不是按 persona/profile/summary/capability 几个对象平铺
- MemberRuntimePersona / ExposedCapability / ExecutionActorBinding 是正式真相或正式接缝对象,visible summary / profile / conversation material 是只读消费层
- identity / runtime / member-service / tools / capability-hub / conversation 的输入与输出都必须围绕 member 的正式主体层收口,不能再各自拼出一套“成员是谁”的解释
- 后续测试与验收文档,应直接围绕主体真相、能力出口、execution actor binding 和 visible material 边界展开

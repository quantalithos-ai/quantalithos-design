## 3. 配置控制面总览

> 校准来源：
> - `design-calibration/04_config_step_03_control_plane.md`

#### 配置来源链图：L2-member 配置覆盖链

```text
[code defaults]
        |
        v
[strict JSON file]
        |
        v
[allowlisted environment selectors / bounded scalars / opaque refs]
        |
        v
[infra::config.rs: load -> parse -> validate -> redact]
        |
        v
[validated refs + provenance + redacted issue refs]
        |
        v
[infra::runtime_builder.rs: composition root]
        |
        +--> [local Store / UoW / idempotency / typed-result]
        +--> [Clock / ID / digest technical slots]
        +--> [Command / Query / Consumer / projection / Job posture]
        +--> [owner resolver / handoff / logical registry slots]
        +--> [blocked / unavailable / test-only seams]
        |
        v
[application Ports and named services]
        |
        +--> [api]
        +--> [worker]
        +--> [jobs]
```

关键规则：

- 唯一 raw config 读取与校验入口是 `infra/config.rs`。
- 唯一 composition root 是 `infra/runtime_builder.rs`；它只把 validated ref 装配为 Port、adapter、logical registry 或 blocked seam。
- `application`、`domain`、`contracts`、`api`、`worker`、`jobs` 不读取 raw config、环境变量或 secret。
- 普通来源顺序固定为 `code defaults < strict JSON file < allowlisted environment variables`；受控 secret provider 不参与普通覆盖排序。
- `runtime`、`event`、`ref`、`adapter`、`fake` 和 persistence relation 是运行期 / 协作关系，不因此成为 Cargo package dependency；唯一 planned sibling compile candidate 仍是 `core-contracts`。

| 控制面 | 主要作用 | 绑定入口 | P0 语义 | 禁止越过的边界 |
|---|---|---|---|---|
| composition / provenance | profile、来源可解释性、validation issue | `infra/config.rs`、builder | 是 | 不改 owner / state / truth |
| local consistency stores | logical Store、UoW、CAS、idempotency / result | `infra/*_store.rs`、application UoW | 是 | 不选 DB、不改事务顺序 |
| technical identity | Clock、ID、digest | technical Port / builder | 是 | domain 不自行生成 |
| command / query boundary | body、page、freshness、safe surface | API / application boundary | 是 | 不关闭 metadata、visibility、no-write |
| consumer / projection | dedup、watermark、stale posture | worker / read model | 保守 | 不把 event 当 command、不修 source |
| operations jobs | runner、batch、retry、timeout、parallelism 类别 | jobs / worker | 是 | 不盲重试、不修核心 truth |
| owner resolvers | Work、Identity、Governance、Runtime、Tools、Method、Host-route | source Ports / adapter | 保守 | 不建 generic resolver、不保存 foreign body |
| handoff availability | host、Runtime、publication、observation、archive / export | handoff Port / blocked seam | 保守 | 不把 attempt 升格 accepted / delivered / observed |
| logical registry | API、worker、Job entry posture | builder registry | 是 | 不创建 listener / process / scheduler |
| diagnostics / redaction | safe issue、provenance、low-cardinality telemetry | infra diagnostics | 是 | 不输出 secret / body / endpoint |
| test fixture / replay | deterministic fake、fixed Clock / ID、typed replay | test-only builder | 仅测试 | 不当真实 integration / readiness |
| outbound semantic publication | 24 candidate 的静态 blocker | blocked marker | 禁止正向配置 | 不生成 event / publisher / outbox / route |

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_categories_boundaries.md`

| 配置类别 | 说明 | 示例 | 是否允许热更新 | 默认生效边界 |
|---|---|---|---:|---|
| `startup` | profile、Store / technical / resolver / handoff / registry 组合 | `composition.profile`、`stores.truth_ref` | 否 | 启动校验成功后对新 runtime 生效 |
| `job-run-start` | 单次 Job invocation 的策略类别 | `jobs.batch_class`、`jobs.retry_class` | 否 | 仅下一次 Job；不影响运行中 Job |
| `entry-local` | 当前授权入口的边界限制 | Command body / Query page limit | 否 | 当前 entry；不得覆盖全局 composition |
| `sensitive-ref` | opaque Store / adapter / target / resolver ref | `handoff.host_ref` | 否 | startup 或新 Job；raw secret 由 provider 内部处理 |
| `diagnostic-redaction` | 安全输出和标签约束 | strict redaction、low-cardinality | 否 | 启动后本地诊断 |
| `test-fixture-deterministic` | 测试专用 fake、fixed Clock / ID、replay fixture | `fixtures.*` | 不适用于生产 | test assembly |
| `feature-peripheral` | 可裁剪外围 surface / handoff posture | optional projection / export | 否 | startup 或外围 Job |
| `static-invariant` | 非配置化设计不变量 | 双锚、CAS、Query no-write、24 candidate block | 不适用 | 设计版本固定；变更需回开 |

| 禁止配置化项 | 原因 | 如需改变的流程 |
|---|---|---|
| `ProjectMemberRef + GlobalMemberRef` 双锚、非 project subject | 执行主语与身份边界 | 回开需求 / 架构 / 03 subject contract |
| truth owner、local / support / derived-read ownership | 配置不能转移数据责任 | 修改正式 owner / data ownership 设计 |
| screening / policy taxonomy、allowlist / denylist、approval truth | `L2M-UP-007` owner 未闭合 | 由 Governance / security owner 发布正式结果 |
| body-free、forbidden body、raw external body、prompt / plan / tool content | 数据与安全红线 | 回开数据归属和安全设计 |
| Runtime / Tools / LLM / memory / checkpoint / capability registry | 明确非本仓职责 | 由对应上游 owner 和范围变更处理 |
| host lifecycle / IPC / health、image build / release / sandbox truth | sibling / host truth | 由 owner 正式合同与 ADR 处理 |
| metadata、idempotency key、canonical digest、typed replay | 协议与重放不变量 | 回开 03 protocol / persistence contract |
| UoW 顺序、expected version、CAS、append-only、state transition | 一致性不变量 | 回开 state / persistence / flow 设计 |
| Query no-write、projection / mirror 单向边界 | 防止读路径修复真相 | 回开 query / persistence / flow 设计 |

| redaction deny list、low-cardinality、审计链 | 安全与审计完整性 | 回开 observability / security design |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`

| 来源 | 优先级 | 适用配置 | 冲突处理 | 不可用 / 非法策略 |
|---|---:|---|---|---|
| code defaults | 10（最低） | 非敏感、结构性安全默认、P0 local posture | 可被合法 file / env 覆盖 | 缺少必要默认属于设计缺口，不用空值伪造 |
| strict JSON file | 20 | 模块配置、typed scalar、opaque ref | 合法值覆盖 default；重复 key / alias 冲突拒绝 | 文件 / JSON / schema / cross-field 错误 fail-fast |
| allowlisted environment variables | 30（普通最高） | selector、bounded scalar、opaque ref | 合法值覆盖 file / default | 非法高优先级值不回退，直接 fail-fast |
| controlled secret provider | 独立来源 | provider 返回的 credential / secret material | 不参与普通覆盖；普通值不能替代材料 | critical slot fail-fast，外围 slot blocked |
| test-fixture-deterministic | test-only | fake、fixed Clock / ID、fixture selector | 仅 test builder 内有效 | production-like 检测到即 reject |
| config center / admin override | 不支持 | 无 | 不进入来源链 | reject；不保留 online LKG |
| 通用 CLI flag / owner feedback | 不属于全局来源 | entry-local / 业务 carrier 各自处理 | 不覆盖全局配置 | 被当作全局配置时 reject |

### 5.1 冲突与缺失规则

1. 每个配置项只有一个 canonical 名称；不把历史别名自动接纳为 alias。
2. 每层先完成 parse / type / range 校验，再允许更高层覆盖。
3. 同一优先级出现多个值、JSON 重复 key 或 alias 重叠时，全部拒绝，不使用顺序或“最后写入优先”。
4. 高优先级 env 非法时不回退 file / default。
5. 普通来源出现 password、private key、raw token、完整 DSN、endpoint 或 foreign body 时直接拒绝；redaction 不能把不安全值变成合法值。
6. `entry-local` 与 `job-run-start` 输入不覆盖 startup composition，必须分别通过 typed boundary / Job metadata 校验。
7. provenance 只记录来源类别、模块、版本 / fingerprint、validation 和 safe issue ref，不记录 raw value、完整文件、endpoint、topic 或 body。

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_environment_profiles_matrix.md`

| 环境 / profile | 用途 | 配置来源 | 外部依赖 / adapter posture | 敏感配置处理 | 当前状态 |
|---|---|---|---|---|---|
| `local-dev` | 本地开发、契约探索、手工调用 | defaults + 项目 JSON + 显式 local env selector | local / deterministic fake；未闭合 owner seam blocked / unavailable | 不允许 raw secret；仅 test ref / local stub | P0，可验证 local contract，不证明 integration |
| `ci-test` | contract / domain / application / seam 测试 | defaults + checked-in test JSON + CI allowlisted env | deterministic Store、fixed Clock / ID、fake resolver / handoff | fixture / ephemeral ref；输出脱敏 | P0，可重复，不产生 external evidence |
| `integration-like` | owner 合同存在时的边界联调 | defaults + environment JSON + allowlisted env + controlled ref | 逐 owner contract gate 的 real-like adapter；当前仍 blocked-aware | provider required；无 provider fail-fast / blocked | P0 语义 / P1 激活，当前无正向完成结论 |
| `operations-replay` | 诊断、replay、gap / receipt / report 对账 | defaults + operations JSON + job metadata | 只读已提交 carrier / marker；不重放未知副作用 | 受控 ref；不保存 raw secret / body | P0，不执行 mutation |
| `staging-like` | 未来发布前组合验证 | 受审计 defaults / JSON / env + provider | 需全部 owner / product 合同；未满足 blocked | provider only，禁止 fixture | P1 future，未激活 |
| `production-like` | 未来正式运行形态 | 受控 JSON / env + provider + change audit | 需 physical adapter 与 owner handoff 合同 | provider、轮换、最小权限 | P1/P2 future，未激活 |

Profile 之间共享不变量但不共享 raw config。任何 profile 都不能改变双锚、truth owner、状态、UoW / CAS、typed replay、Query no-write、Unknown fence 或 24 candidate 的 zero-configuration；`production-like` 不得继承 `ci-test` fixture。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`

### 8.1 敏感级别

| 级别 | 含义 | 可否进入普通配置 | 处理要求 |
|---|---|---:|---|
| `public` | 不揭示安全、拓扑或 owner 信息的公开 label | 是 | 仍须 schema / provenance 校验 |
| `internal` | 运行姿态、bounded class、redaction、logical registry | 是 | 不对外暴露；高风险变更需审计 |
| `sensitive` | opaque Store / adapter / target / resolver ref | 仅 ref 形式 | 不记录完整值；来源、读取和变更须审计 |
| `secret` | password、private key、raw token、证书私密材料或 provider 返回值 | 否 | 只在受控 provider / adapter 内短暂使用，禁止进入本仓配置对象与观测面 |

`diagnostics.redaction_mode`、`provenance_visibility` 和 `metric_label_mode` 属于 `internal` 的安全关键设置；P0 固定为 `strict`、`internal-only`、`low-cardinality`，不能由 debug、profile、admin 或 env 关闭。

### 8.2 敏感配置表

| 配置项族 | 敏感级别 | 存储方式 | 是否可明文 | 轮换方式 | 审计要求 |
|---|---|---|---:|---|---|
| `stores.truth_ref` | sensitive | JSON / env 只存 opaque ref | 否 | 新 ref + restart | slot、profile、old/new fingerprint、validation |
| `stores.support_ref` / `projection_ref` / `continuation_ref` | sensitive | opaque ref 或 null | 否 | 新 ref + restart | slot、watermark / gap compatibility |
| `stores.idempotency_ref` / `result_ref` | sensitive | opaque ref | 否 | 新 ref + restart | reservation / replay carrier compatibility |
| `consumer.source_ref` | sensitive | owner-specific opaque ref | 否 | 新 ref + restart | source family、scope、schema posture |
| `projection.rebuild_target_ref` | sensitive | opaque job target ref | 否 | 新 ref + new job-run | target、scope、watermark compatibility |
| `resolvers.*_ref` | sensitive | owner-specific opaque ref | 否 | 新 ref + restart | owner kind、scope、safe availability |
| `handoff.*_ref` | sensitive | opaque handoff / target ref | 否 | restart 或 new job-run | handoff kind、attempt / gap compatibility |
| `diagnostics.*` safety settings | internal / safety-critical | ordinary JSON 的有限 enum | 仅 enum | P0 不允许放宽 | 每次拒绝 / 变更均审计 |
| raw password / private key / token / certificate private material | secret | approved external provider only | 否 | provider-side rotation + ref rebind | 只记录 provider ref fingerprint 与 safe result |

### 8.3 读取路径与输出红线

```text
[JSON / allowlisted env]
        |
        v
[opaque sensitive ref]
        |
        v
[infra/config.rs: parse + type / owner / scope validate]
        |
        v
[redacted Member*ConfigRef]
        |
        v
[infra/runtime_builder.rs]
        |
        +--> [Store / resolver / handoff adapter slot]
        +--> [BlockedSeamState / MemberAdapterAvailability]
        |
        v
[application Port]

[approved secret provider] --(adapter-internal lookup)--> [transient secret material]
                                      |
                                      +--> never enters domain / contracts / Store / audit / log
```

| 输出面 | 允许 | 禁止 |
|---|---|---|
| structured log | profile、slot kind、source class、safe error kind、redacted issue ref、one-way fingerprint | full ref、raw secret、endpoint、route、provider response、body |
| API / worker / Job error | public / internal error code、safe diagnostic ref | secret、DSN、header、stack trace、foreign body |
| logical audit | actor / change ref、slot、old/new redacted fingerprint、validation、activation | raw config、secret、完整 endpoint、provider body、external truth |
| trace / metric | 有限 profile / slot / outcome / error class | secret、credential、ref、actor、identity、endpoint、topic、raw config |
| typed result / receipt / report | safe marker、issue ref、local disposition、counts | secret、external response、raw config、body |
| test artifact | 脱敏 fingerprint、safe fixture id | raw config file、provider response、raw historical body |

无法证明已脱敏时，省略字段并返回 safe diagnostic ref；任何 debug flag、异常包装器或 serializer 都不得绕过 deny list。

### 8.4 Profile 级处理

| Profile | 允许表示 | 禁止项 | 不可用策略 |
|---|---|---|---|
| `local-dev` | fake / in-memory opaque ref、test selector | raw secret、生产 credential | invalid ref fail-fast；optional slot blocked |
| `ci-test` | deterministic fixture / ephemeral ref | production secret、真实 credential | fixture / provider 缺失使 test setup fail |
| `integration-like` | owner-approved ref、controlled credential ref | raw credential、default fake fallback | required owner slot fail-fast；外围 blocked |
| `operations-replay` | de-identified replay root / read-only target ref | raw historical body、未知副作用 target | missing ref reject；safe report |
| `staging-like` / `production-like` | approved provider ref only | fixture、明文 secret、admin override | provider / permission failure fail-fast |

轮换只替换 adapter slot 或 provider binding，不修改 local fact、状态、append-only history、typed replay、external Unknown 或 owner truth。

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`

### 10.1 变更分级与职责

| 变更类型 | 发起 / 评审方 | 生效方式 | 审计记录 | 回滚方式 |
|---|---|---|---|---|
| non-sensitive bounded class / logical registry posture | 模块 owner；必要时架构 / 运维复核 | startup 或 entry-local / new job | canonical key、scope、validation、activation | reject-new-value 或 prior verified snapshot |
| profile 变更 | 配置 owner + 架构 / 测试 / 运维 | startup restart | profile、矩阵影响、blocked slots、review ref | 恢复旧 profile；不继承 fixture |
| required Store / UoW / idempotency / result ref | owner + security / operations | startup restart | slot、old/new fingerprint、兼容检查 | 旧 verified ref；缺失则 no-write |
| resolver / handoff / credential ref | owner + security / operations | startup 或 new job-run | owner kind、scope、availability、issue ref | 旧 verified ref 或 blocked |
| projection activation / rebuild target | read-model / operations owner | startup / new job-run | target、watermark basis、job metadata | stale / disabled；禁止 Query repair |
| Job batch / retry / timeout / parallelism class | operations + safety owner | 下一次 job-run | job kind、class、reason、validation | 旧 class 仅用于新 invocation |
| diagnostics / redaction / metric safety | security owner | startup；P0 仅 strict | changed setting、rejection、issue ref | 只能恢复更严格 snapshot |
| forbidden change / publication candidate | 不可批准 | never | rejection audit | 无；保持设计红线 |

### 10.2 审计记录最小字段

| 字段 | 要求 |
|---|---|
| change / actor reference | typed / opaque ref；不含正文、token 或个人敏感资料 |
| profile / scope | 有限 profile、process / job / entry scope |
| changed key / module | canonical key；未知 key 不进入 accepted record |
| old / new fingerprint | 高风险必填，一次性脱敏 fingerprint；不记录完整 ref / secret |
| validation / review decision | 有限 accepted / rejected / blocked / deferred 类别；不伪造 signoff |
| activation mode | `startup`、`job-run-start`、`entry-local` 或 `rejected`；P0 不支持 hot |
| rollback reference | 仅指向 prior verified snapshot；不假设在线 LKG |
| safe issue ref | 失败或敏感变更必填；不含 raw config / provider body |

### 10.3 回滚与不可逆边界

| 场景 | 可做的回滚 | 不可做的动作 |
|---|---|---|
| parse / validate 失败 | 不应用新值；保留当前 verified snapshot | 回退到非法低优先级值或 partial Ready |
| startup assembly 失败 | 停止暴露受影响写 facade；恢复 verified snapshot 并 restart | 绕过 required slot |
| Job 配置失败 | 拒绝该 invocation；已开始 Job 不变 | 中途修改 retry / report 语义 |
| credential provider 失败 | 旧 ref 若仍有效则保留，否则 blocked | raw file / env / fake credential fallback |
| external handoff Unknown | 保留 local attempt / gap / Unknown | 假造 delivery、撤销或盲 resend |
| projection 异常 | stale / disabled；等待受控 rebuild Job | Query 写 Store、删除 source fact |
| redaction 放宽请求 | reject；保持 strict | debug bypass、输出敏感材料 |
| 24 candidate activation 请求 | 永不应用 | 创建 event、publisher、outbox、topic、route、retry、DLQ |

变更回滚只改变配置 snapshot、adapter slot 或可选姿态，不撤销 append-only history、local truth、typed result / receipt / report 或 external Unknown。

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：

### 11.1 失效模式总表

| 失效模式 | 影响 | 系统行为 | 告警方向 | 测试切口 |

### 11.2 失效策略分类

| 策略 | 适用场景 | 允许结果 | 禁止结果 |
|---|---|---|---|
| `fail-fast` | profile、required Store / UoW / replay / technical、非法高优先级值 | 阻止启动、mutation 或 invocation | 低优先级非法回退、partial Ready |
| `fail-closed` | owner、policy、subject、body-free、unknown、authorization 前置 | 保守拒绝、Blocked / Unknown | default-pass、关闭 guard |
| `degraded` | optional projection、handoff、observation、export、read surface | 有限 safe view、marker、report、NotAvailable | 改写 truth、声称 external success |
| `stale` | projection / mirror 未达 committed watermark | 明确 Stale / NotReady | 以旧值标 current |
| `gap` | continuation / handoff / observation 未闭合 | 保存 local gap / reason | 盲重试、删除 gap |
| `reject-new-value` | reload 请求、非法 entry / job 值、unsafe redaction | 保留 verified snapshot | 运行中替换策略 |
| `default-fallback` | 仅 strict redaction、deterministic-single 等结构性安全默认 | 有限安全默认 | 用 default 补 external owner / credential / truth |

### 11.3 不变量保护

- required local truth、UoW、idempotency、typed result、Clock、ID、digest 任一不可用时，相关 mutation `fail-fast / no-write`。
- Query 在 stale / degraded / missing source 时仍然 no-write，不触发 refresh、rebuild、reconcile、handoff 或 truth repair。
- duplicate 只回放同一 relation 的完整 typed carrier；Unknown 必须 inspect-first，不盲重试、不换 key。
- external / optional seam 只返回 `Blocked`、`Waiting`、`Unknown`、`Stale`、`Gap` 或 `NotAvailable`；不把 local `Ready` 解释为外部成功。
- 24 个 outbound semantic candidate 在 `L2M-UP-005` 关闭前永远 zero configuration。

### 13.2 迁移门禁与不变量

1. 新旧 key 必须分别列在配置设计中；同名或 alias 冲突显式拒绝，不依赖文件遍历顺序。
2. sensitive ref 迁移只迁移 ref identity / provider binding，不复制 raw secret。
3. 迁移不改变双锚、truth owner、state、UoW / CAS、append-only、typed replay、Query no-write、Unknown fence、local / external truth 或 24 candidate zero configuration。
4. 配置 rollback 只恢复 prior verified snapshot；不撤销业务 history，不伪造 external side-effect resolution。
5. 未满足 owner / product / security / `03` contract 时保持 `blocked`，不得由 default、fake 或 online LKG 解除。

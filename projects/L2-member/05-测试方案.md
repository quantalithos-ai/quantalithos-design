### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 member 的接口可调用,而是系统验证 `L2-member` 是否真正满足“AI 成员运行态主体仓”的设计要求,尤其要证明以下几点成立:
- MemberRuntimePersona / MemberMode / MemberAvailability 构成正式成员主体真相层
- `persona ≠ static identity`、`visible summary ≠ persona truth`、`execution actor binding ≠ ExecutionInstance truth` 三条核心边界成立
- exposed capability 必须是 member 当前对外出口,不能等于 capability catalog 全量
- execution actor binding 只能作为 runtime/member 接缝存在,不能反向变成 execution 主线真相
- visible summary / profile / conversation material 只读且不反写真相
- member-service 只能消费 execution-facing member context,不能反向覆盖成员主体真相
- runtime / conversation / UI / member-service 对“同一个成员”的解释必须一致

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 成员主体与运行态画像部分 | 真相对象 | P0 | persona / mode / availability / behavior profile |
| 成员对外交互接口部分 | 接口对象 | P0 | endpoint / inbound interaction / reply/action contract |
| 成员能力暴露与行为出口部分 | 能力出口层 | P0 | exposed capability / outlet / visible capability |
| 成员与执行主线接缝部分 | 接缝对象 | P0 | execution actor binding / execution-facing context |
| 成员可见摘要与下游消费接缝部分 | 读模型层 | P0 | summary / profile / conversation material / UI material |
| runtime / member-service / tools / capability-hub 内部实现细节 | 非范围 | P2 | 只验 member 与它们的接缝,不验下游内部实现 |
| conversation / UI 前端组件表现 | 非范围 | P2 | 只验 visible material,不验 UI 像素级行为 |
| identity 静态身份正文逻辑 | 非范围 | P2 | 只验它作为输入真相被消费的边界 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数和局部不变量 | domain / policy owner | `persona.validate_creatable`、`endpoint.validate_exposable`、`outlet.validate_exposable`、`binding.validate_bindable`、`summary.validate_visible_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + mapping + projection 联动 | backend / domain owner | `CreateMemberPersona`、`UpdateMemberPersonaMode`、`ResolveMemberInteractionEndpoint`、`ExposeMemberCapability`、`BindExecutionActor`、`DeactivateExecutionActorBinding`、`BuildMemberVisibleSummary`、`RefreshMemberConversationMaterial`、`RefreshMemberProfileView` | 主体、出口、接缝、外显链同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | identity profile → persona、capability input → outlet、runtime bind demand → actor binding、member-facing execution context → member-service、visible material → conversation/UI | 输入输出语义一致 |
| 恢复专项测试 | 验证 persona/outlet/material 漂移或延迟时是否可恢复 | architecture / QA | identity 晚到、outlet 重建、visible summary rebuild、binding 失效与重建 | 主体真相不丢失、投影可恢复 |
| 投影一致性测试 | 验证 summary / profile / conversation material 与正式真相一致 | backend / QA | visible member vs executable member 区分、UI material / conversation material 边界、只读重建 | 读模型只读且与真相一致 |
| 端到端主线测试 | 验证最小成员主体闭环 | QA / owner | persona → visible summary、outlet expose、actor bind、member-service consume context、conversation/UI consume material | 主干主体闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| persona 与 static identity 分层 | static input 进入后独立生成 runtime persona | 集成测试 | 是 | DB / API / trace |
| exposed capability ≠ capability catalog | catalog 有定义但当前不应暴露 | 单元 + 集成测试 | 是 | outlet compare / negative flow |
| execution actor binding ≠ execution truth | binding 只作为接缝对象存在 | 集成测试 | 是 | binding record / runtime compare |
| visible summary ≠ persona truth | summary 重建不改主真相 | 投影一致性测试 | 是 | rebuild trace / compare |
| visible member ≠ executable member | member 可见但暂不可执行状态成立 | 集成测试 | 是 | availability / visible summary compare |
| member-service 不反向替主体真相 | execution-facing context 只被消费不回写主体本体 | 事件链 + 边界测试 | 是 | downstream trace |
| 同一成员在 runtime / conversation / UI 三侧一致 | persona/outlet/summary 更新后多下游一致 | e2e / compare | 是 | compare report |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | CreateMemberPersona 成功创建运行态主体 | static profile / capability input 合法 | CreateMemberPersona | MemberRuntimePersona 创建成功 |

| TC-005 | ExposeMemberCapability 只暴露当前可用能力 | capability inputs 完整 | ExposeMemberCapability | outlet 只包含当前可暴露能力 |
| TC-006 | capability catalog 有定义但 member 当前不应暴露 | capability 存在但 mode 不允许 | ExposeMemberCapability | 返回 `MEMBER_CAPABILITY_EXPOSE_DENIED` 或 capability unavailable |
| TC-007 | BindExecutionActor 成功建立 execution actor bind | persona 可绑定 / runtime ref 合法 | BindExecutionActor | active binding 成立 |
| TC-008 | inactive binding 不得继续被 runtime 复用 | binding 已失效 | runtime consume old binding | 拒绝复用旧 binding |

| TC-010 | visible summary 漂移后 rebuild | projection 损坏 | rebuild summary/material | 只读材料恢复,真相不变 |
| TC-011 | member-service 只消费 execution-facing member context | binding/material 已生成 | member-service consume | 不直接读取 persona 全量真相 |
| TC-012 | UI / conversation 只消费 member-facing material | visible materials 已生成 | UI / conversation render | 不拼 static identity + sender 临时材料 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | persona 退化成 static identity / execution actor binding 替代 execution truth / visible summary 反写真相 / capability 越权暴露 | 阻断放行,必须修复 |
| A | 主线可跑但 outlet / summary / binding / downstream consume 语义不稳 | 原则上修复后再放行 |
| B | 非关键 profile 材料或低优先级外显查询异常 | 可带风险进入下一轮 |

---

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 persona / mode / availability 逻辑,都必须回归 persona 构建与 visible summary 主线
- 每次改动 capability outlet,都必须回归 exposed capability 裁剪和越界暴露阻断
- 每次改动 execution actor binding,都必须回归 runtime/member-service consume 与旧 binding 失效链
- 每次改动 visible summary / profile / conversation material,都必须回归只读重建和多下游一致性
- 每次改动 capability-hub / tools consume path,都必须回归 outlet 生成与外显一致性

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| member mode / availability 若后续继续细分 | 测试矩阵需扩充 | TL / 架构 |
| 一对多角色呈现或多入口主体若放开 | binding / summary / endpoint 测试需增加分支 | member + runtime |
| capability-hub 组合能力继续扩张 | outlet 和 visible summary 测试需增加更复杂样本 | Owner / TL |

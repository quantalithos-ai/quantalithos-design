### 1.4 Blocker 传递原则

| blocker | 对测试的影响 | 当前姿态 |
|---|---|---|
| `L2M-UP-001` | host IPC、注册 / signal / report、acceptance / session / health exact contract 未闭合 | local formation、拒绝和 blocked seam 可设计；positive host qualification blocked |
| `L2M-UP-002` | image release、manifest、entry、compatibility 未闭合 | 只测 opaque ref / availability / waiting；release qualification blocked |
| `L2M-UP-003` | Runtime entry / trigger mapping 未闭合 | 可测 missing mapping refusal；positive admission blocked |
| `L2M-UP-004` | Runtime handoff / feedback source family 未闭合 | 只测 attempt / gap / unknown fence；不得声称 delivered / observed |
| `L2M-UP-005` | member-specific Core / Bus schema、route 和 24 candidate 未闭合 | 只测 zero configuration / non-materialization；不得创建事件设施 |
| `L2M-UP-006` | credential / identity anchor owner shape 未闭合 | 缺失、冲突、不可验证必须 fail closed；positive proof blocked |
| `L2M-UP-007` | screening taxonomy / policy source 未闭合 | unknown / stale / conflict 保守；positive allow lane blocked |
| `L2M-UP-008` | non-project / personal execution subject 未定义 | 只测项目型双锚；其他 subject reject / blocked |

这些 blocker 不阻塞 P0 的 member-local、负向、故障注入、redaction、依赖和非物化设计；它们阻塞受影响的真实正向 qualification、执行结果、正式 evidence instance、验收 verdict 和 readiness。

## 4. 测试策略与分层

> 校准来源：

> 延伸阅读：

测试按“最早可定位的风险层级”组织。上层 smoke / E2E 不能替代下层字段、状态、UoW、redaction 和 no-write 断言；P1 real-like 只在 owner 合同闭合后选定运行，`blocked` / `not_run` 不得记为通过。

### 4.1 测试分层图：L2-member 风险发现层级

```text
                    [P1 real-like / cross-owner selected-run]
                    [only after exact contracts are closed]
                                  ^
                                  |
                [P0 release gate / local composition smoke]
                [redaction + dependency + report integrity]
                                  ^
                                  |
                  [API / Worker / Job entry contract]
                  [pre-gate + typed result / receipt / report]
                                  ^
                                  |
             [Store / UoW / adapter / builder integration-like]
             [deterministic fake + controlled / blocked seam]
                                  ^
                                  |
                  [Application service / query tests]
                  [flow + replay + no-write + error mapping]
                                  ^
                                  |
               [Contract + domain + config unit tests]
               [field + factory + policy + state + redaction]
```

关键说明：

- 字段、状态、owner、配置和 redaction 错误必须在最早可定位层阻断。
- P0 integration-like 只证明 member-local contract，不证明外部 owner 成功。
- release gate 负责组合、依赖和证据完整性，不替代 service / worker / Job 用例。
- 24 个 candidate 只进入静态 non-materialization 检查，不进入 event E2E。

### 4.4 P0 / P1 分层资格

| 能力 | P0 可执行姿态 | P1 解锁条件 | 当前状态 |
|---|---|---|---|
| host collaboration | local material / attempt、unavailable / unknown | `L2M-UP-001/006` exact contract | positive qualification blocked |

### 4.5 执行顺序与 oracle 规则

1. 先运行 contract / domain / config，再运行 application / entry，最后运行 local composition smoke。
2. 任何失败先保留最早层的 failure reason；不得用 E2E 绿色覆盖下层红线。
3. 外部 seam 只能以 typed ref、safe snapshot、attempt、gap、blocked、waiting 或 unknown 作为 member oracle。
4. `Ready` 仅表示 local facade composition 可用；不表示 image、container、host、Runtime、Bus、downstream 或 system readiness。
5. 任何测试层级都不得把 fake、planned 或 blocked 变成 positive integration、evidence、verdict 或 signoff。

## 7. 测试数据设计

> 校准来源：
> - `design-calibration/05_test_plan_step_07_test_data.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“数据集总表”“Fixture / builder / seed 规则”“用例到数据前置映射”“数据安全与隔离规则”和“跨数据隔离 / 清理审计表”小节，了解数据可重复性与替身边界。

测试数据必须由正式 contracts、domain factory、state helper、UoW 和 config 约束生成。数据设计阶段不创建 fixture 文件、seed 脚本或真实数据；这里只定义 planned 数据集、隔离键、清理方式和替身边界。

### 7.1 数据设计原则

| 原则 | 要求 |
|---|---|
| 双锚优先 | 正向数据必须有匹配 `ProjectMemberRef + GlobalMemberRef`；匿名、GlobalMember 代主语、personal / non-project 只作为拒绝输入 |
| 契约生成 | DTO、truth object、state、payload、report 和 config 数据由正式 schema / factory / builder 生成，不临时拼字段 |
| 正负向分离 | invalid、unsupported、digest conflict、commit unknown、rollback、redaction leak 和 dependency violation 使用独立数据集 |
| body-free | 外部正文、Runtime context / plan / outcome、tool / conversation / artifact body、credential value 和完整 stack trace 不进入共享 fixture |
| deterministic | test profile 使用 deterministic Clock / ID / digest；生产 profile 不假设固定时间或 ID |
| fake fidelity | fake Store / adapter 也执行正式 version、unique、rollback、failure、receipt、report 和 redaction 语义 |
| run isolation | 每个运行使用 `run-scope`、operation namespace、subject anchor、relation identity 和独立 fault / profile |

### 7.3 Fixture / builder / seed 规则

| 规则 | 约束 |
|---|---|
| baseline builder | 只生成正式 contracts carrier 和 domain factory 所需字段；不生成 foreign body、外部成功或未定义状态 |
| state builder | 只能通过正式 factory / successor helper 生成合法状态；非法 / reserved 数据通过受控错误构造，不直改 status 字段 |
| protocol builder | name、typed body、双锚、metadata、trace、idempotency 和 result-kind 显式配对；Query 不生成 idempotency key |
| stored-result seed | 仅为 duplicate / missing / wrong-kind 场景创建 typed stored carrier；不从 projection 反推 carrier |
| adapter seed | 只返回 `Blocked`、`Waiting`、`Unknown`、unavailable 或安全 ref；不返回伪造 host / Runtime / Bus / observed success |
| fault injector | 只注入 UoW、CAS、adapter、schema、digest 和 slot fault；不改变 domain owner 或补齐 DDD gap |

### 7.4 用例到数据前置映射

| 用例族 | 主要数据集 | 必须隔离的 mutable relation | 替身 / 清理 |
|---|---|---|---|
| `TC-L2M-CMD-*` | BASE + 对应 CP 数据集 | command relation、successor、attempt、resolution | 每用例新 operation namespace |
| `TC-L2M-QRY-*` | 对应 committed snapshot / projection | reader cursor；禁止写 relation | read-only snapshot + write spy reset |
| `TC-L2M-CON-*` | source descriptor + receipt seed | receipt、fact / feedback / projection successor | source / receipt namespace reset |
| `TC-L2M-JOB-*` | continuation selector + item set | per-item relation、report | job invocation namespace reset |
| `TC-L2M-COMMON-*` | INVALID / REPLAY / CONFLICT / FAULT | idempotency / UoW / version | fake UoW rollback + reset |
| `TC-L2M-EVT-*` | EVENT-BLOCK | 不允许任何 event relation | 断言不存在物化对象 |

### 7.5 数据安全、隔离与清理

- 外部正文、Runtime context / plan / outcome、tool input / output、conversation / artifact body、credential value、private key 和完整 stack trace 不进入 fixture、snapshot、report 或 diagnostic。
- digest、idempotency 和 dedup key 使用 deterministic 且不可逆的测试值；原始 key 不进入日志、指标或 view 断言。
- 并发数据拥有不同加载版本但相同 relation identity，验证单赢家；不同 operation namespace 不得互相 replay。
- happy-path 只共享 immutable baseline；mutable / fault 数据独立复制。清理以 run namespace 或 fake lifecycle 为界，不对用户数据做广泛删除。
- `DS-L2M-EVENT-BLOCK` 不创建 event store、topic 或 publisher；它只提供 candidate 名称和 blocked marker，供静态边界检查。

| invalid / boundary / concurrency / recovery 独立 | `covered` |
| fake / controlled / disabled 边界明确 | `covered_with_blockers` |
| Query 与 writer 数据隔离 | `guarded` |
| raw body / secret 不进入共享数据 | `prevented` |

> - `design-calibration/05_test_plan_step_10_nonfunctional.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化专项测试矩阵”“安全与 owner 边界”“一致性与恢复”“观测与审计”和“专项停审与跨项审计”小节，了解专项方法与阈值来源。

专项测试验证普通功能用例难以覆盖的安全、所有权、一致性、恢复、观测、配置和依赖风险。专项 oracle 仍限定为 member-local contract；不把 external delivery、accepted、observed、health 或 readiness 纳入本仓通过条件。

### 10.1 专项测试矩阵

| 专项 | 指标 / 风险 | 方法 | 环境 | 通过条件 | 候选证据族 |
|---|---|---|---|---|---|
| 性能阶段分解 | local 与外部等待混淆（NFR-001~003） | 对 Command / Consumer / Job 记录阶段 duration、等待 posture、item count | `ci-test` / `operations-replay` | 能区分各阶段；无权威硬数字 | `EV-CAND-L2M-NF-PERF-*` |

| 出站安全 | foreign body、hidden reasoning、secret | safe-material gate、serializer / Store / log scan | `ci-test` | forbidden field 不出现；不创建 outbound success | `EV-CAND-L2M-NF-SEC-002` |
| 外联边界 | generic listener、arbitrary provider（NFR-008） | static dependency / endpoint / adapter inventory scan | `ci-test` / release | 仅正式 seam；违规直边阻断 | `EV-CAND-L2M-NF-DEP-001` |
| UoW / CAS | partial commit、stale overwrite | fake UoW、two-writer deterministic scheduler | `ci-test` | carrier-before-complete、one CAS winner、失败回滚 | `EV-CAND-L2M-NF-CONS-*` |

| 观测基数 | trace / ref / actor 进入 label（NFR-014/015） | metric label inventory + log schema scan | `ci-test` / release | 仅有限 enum；无 secret / body / high cardinality | `EV-CAND-L2M-NF-OBS-*` |
| 配置失效 | required slot、非法 profile、unsafe redaction | malformed config / provider unavailable | `ci-test` | fail-fast / blocked；无 silent fallback | `EV-CAND-L2M-NF-CONFIG-*` |

### 10.2 安全与 owner 边界断言

- 双锚、source owner、scope、purpose 或 credential ref 任一不可验证时，入口 / service 以拒绝或 blocked 结束。
- 入站正文仅允许受控瞬时检查；Store、receipt、trace、projection、report 和 outbound material 不含 raw body。
- Runtime context / plan / outcome、tool input / output、conversation / artifact body、secret、private key 和完整 stack trace 不进入 member-local output。
- `Blocked`、`Waiting`、`Unknown`、`Stale`、`Gap` 和 `NotAvailable` 不映射为 external accepted / delivered / observed / health / readiness。
- 不存在 generic external listener、arbitrary provider、MCP / A2A / API 直连；正式 host / Runtime / Bus seam 保持可区分。

### 10.3 一致性与恢复断言

- pre-gate 失败不 begin write UoW、不 reserve、不调用 side-effect adapter。
- carrier 保存先于 idempotency completion；任一失败不留下可见 completed relation。
- mutable successor 只使用加载时 `MemberStoreVersion`；immutable identity collision 不是 duplicate replay。
- duplicate 只回放同 relation typed carrier；missing / wrong carrier 返回保守 consistency issue。
- commit unknown 只检查同 key / 同 relation；rollback failure 不做隐藏补偿或假成功。
- Projection / Job 只影响自身 derived / continuation relation，不修改 CP01～CP06 source truth。

### 10.4 观测、审计与配置断言

- log / metric / trace / local audit 仅含安全 refs、fingerprint、有限 enum 和 committed relation。
- 原始 idempotency / dedup key 不作为 label 或明文日志字段；不得出现高基数 actor / project / trace ref。
- Query、pre-gate、duplicate conflict 不写 accepted business audit；telemetry 不变成新 event / ledger。
- report 只表达 local continuation item / disposition / counts，不表达 scheduler completion、evidence、verdict 或 signoff。
- required slot 缺失、profile 非法、redaction / dependency check 失败均 fail-fast 或 blocked；不 silent fallback。

### 10.5 性能与容量口径

`NFR-L2M-001~003` 当前没有正式 workload、SLO 或硬阈值 authority。测试仅规划阶段 duration、依赖等待 posture、item count、失败分布和趋势样本；不得继承旧 README 的 P95、SLA 或吞吐数字，也不得以样本声明性能通过。生产容量、压测模型和阈值进入 P2 / 后续验收确认。

### 10.6 专项停审结论

| 审计项 | 结论 |
|---|---|
| P0 安全红线有负向入口 | `covered / blocking` |
| 一致性 / 恢复有 fault injection | `covered` |
| 性能阈值有权威来源 | `sample_only`；硬阈值 pending |
| 观测、审计、redaction 可验证 | `covered` |
| 配置 / 依赖边界 | `covered` |
| 外部 positive qualification | `blocked` by `L2M-UP-*` |

## 11. 缺陷管理与复验规则

> 校准来源：
> - `design-calibration/05_test_plan_step_11_defects_retest.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“缺陷分级表”“缺陷状态与 disposition 分离”“复验规则矩阵”“复验与防回归停审记录”和“待确认事项”小节，了解阻断级别与关闭证据。

缺陷记录必须区分测试事实、缺陷状态和风险处理。`blocked`、`not_run`、`unknown` 是测试 disposition，不等于通过、已修复或可接受风险；P0 红线不能由风险接受隐藏。

### 11.1 缺陷分级

| 级别 | 定义 | 典型示例 | 处理要求 | 是否阻断 |
|---|---|---|---|---|
| S | 命中 `VF-L2M-001~009` 或 P0 安全 / truth / consistency / evidence integrity 红线 | 错主语放行、raw body / secret 泄漏、foreign truth 反写、Query 写入、duplicate 分叉、非 Core package、静态伪 EV | 立即阻断受影响 gate；修复后全量 P0 + redline 复验；不得风险接受 | 是 |
| A | 影响 P0 功能或跨层编排，但未直接命中 VF；或 P1 selected-run contract 失败 | local successor 丢失、CAS 未回滚、Job partial 误吞、required slot posture 错误、real-like seam incompatibility | P0 影响必须修复；P1 需 owner / 验收角色接受或转 blocker | 通常是 |
| B | 不影响 P0 truth / safety 的外围、文档或可读性问题 | 非关键 diagnostic 字段、P2 view、未硬化性能样本格式 | 记录并排期；按影响切口复验 | 否 |

### 11.2 缺陷状态与测试 disposition 分离

| 维度 | 允许值 | 说明 |
|---|---|---|
| 缺陷状态 | `open`、`triaged`、`fix-planned`、`fixed-awaiting-retest`、`verified`、`accepted-risk`、`deferred` | 记录流程，不代表 suite 通过 |
| 测试 disposition | `passed`、`failed`、`blocked`、`not_run`、`unknown` | 只能由真实执行产生；本文不填写实例 |
| 风险处理 | `must_fix`、`owner_acceptance_required`、`pending_confirmation` | S 不得进入 `accepted-risk` |

### 11.3 复验规则矩阵

| 失败类型 | 最小复验集 | 全量触发条件 | 关闭要求 |
|---|---|---|---|
| contract / DTO / enum / state | 失败 case + `contract-domain-fast` + 受影响 entry | public protocol / state matrix 变更 | fixed run artifact / report + schema diff + review |
| Command / Query flow | 失败 case + 同 operation family + `service-flow-fast` | UoW / replay / Query no-write 变更 | fixed run + no-write / replay check |
| Consumer / Job | 失败 case + source / receipt / report family + entry / Job suite | receipt kind、dedup、partial isolation 或 source gate 变更 | fixed run + receipt / report pairing |
| Store / CAS / rollback | 失败 case + `infra-fake-parity` + `replay-recovery` | Store version / UoW / commit-unknown 变更 | fixed run + ordering / rollback trace |
| config / builder | 失败 profile + `config-redline` + `dependency-boundary` | required slot / redaction / invariant 可配置性变更 | fixed run + redacted issue + profile diff |
| security / redaction | 失败 corpus + `redaction-boundary` + `release-redline` | deny list / serializer / output surface 变更 | no forbidden field + reviewer note；S 不可接受 |
| dependency / evidence | failed check + `report-generation-audit` + `release-redline` | package / script / artifact / report schema 变更 | raw artifact / report pair + provenance check |
| P1 external seam | failed selected-run + local blocked posture | owner contract / schema / route 变更 | owner qualification evidence；未闭合则保留 blocked |

### 11.4 风险接受规则

只允许不影响 P0 truth、safety 和 evidence integrity 的 P1 / P2 residual 进入 `accepted-risk`，并且必须有责任角色、接受人或待确认项。`L2M-UP-*`、`L2M-DDD-*` 和 `scope_supersede_gap` 的未闭合状态不能被写成缺陷修复；任何 VF、raw body / secret 泄漏、foreign truth 反写、Query / Job 越权、duplicate 分叉或静态伪证据均不可接受。

### 11.5 缺陷关闭证据

关闭至少需要：原始失败 run 的 artifact / report、修复后 run 的 artifact / report、复验 TC / suite、变更关联、差异说明、redaction / dependency check 和 reviewer note。正式 EV 由 §13 从真实 artifact / report 推导；不能以“代码已修复”、静态截图、planned、blocked 或 not_run 代替。

### 11.6 复验与停审结论

| 审计项 | 结论 |
|---|---|
| S 级不可降级 | `defined` |
| A 级复验 | `defined`：失败 case + family + suite |
| B 级处理 | `defined`：记录后排期 |
| blocked / not_run 与缺陷分离 | `defined` |
| 关闭证据 | `defined`：failed / fixed run pair + review |

## 12. 进入准则与退出准则

> 校准来源：
> - `design-calibration/05_test_plan_step_12_entry_exit.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“进入准则”“退出准则”“进入 / 退出审计”“回填草稿”和“待确认事项”小节，了解 planned 测试运行何时可开始、暂停或退出。

本章是测试执行的 planned gate，不是当前执行结果。没有满足进入条件不得开始相应 suite；没有满足退出条件不得将结果交给验收裁决。外部合同未闭合时，受影响 lane 必须以 `blocked` / `not_run` 记录，不能以 fake 或静态映射代替。

### 12.1 进入准则

- [ ] 当前正式 `00/01/02/03/04` 版本和来源入口已固定，且没有未评估的 P0 设计变更。
- [ ] Step 1～14 中间产物均已完成并通过各自停审；`TC-L2M-*`、`DS-L2M-*`、suite / gate 版本可追溯。
- [ ] 选定 `local-dev`、`ci-test` 或 `operations-replay` profile 与测试目的匹配；profile 校验无未处理 error。
- [ ] 所需双锚、typed ref、正式状态、version、replay carrier 和 invalid / fault corpus 可重复构造，隔离键已分配。
- [ ] 相关 P0 blocking suite 和 planned `scripts/checks/*` 可启动；预期输出根为 `artifacts/test/<run_id>` 与 `reports/runs/<run_id>`。
- [ ] strict redaction、low-cardinality、dependency classification、no-write / no-repair spy 已启用。
- [ ] 已确认 `L2M-UP-001~008`、`L2M-DDD-001~007`、`scope_supersede_gap` 的当前 disposition；受影响 external positive lane 不被误列为可执行。

### 12.2 退出准则

- [ ] 每个 P0 测试切口至少有真实执行结果，或有明确的 `blocked` / `not_run` 原因；不得只有静态映射。
- [ ] 所有 P0 blocking suite 已完成，或失败已按 §11 形成 S / A 缺陷；没有未处理 P0 失败。
- [ ] `VF-L2M-001~009` 对应负向测试，以及 dependency / redaction / evidence integrity checks 没有未解释失败。
- [ ] Command / Consumer / Job 的 duplicate、conflict、in-flight、commit-unknown、CAS、rollback、partial isolation 和 Query no-write 结果可回指 raw artifact / report。
- [ ] 没有 raw body、secret、hidden reasoning、foreign body、full stack trace、高基数 label 或外部 success 伪装。
- [ ] 每个 suite 有 `report.json`、stdout / stderr 和 failure reason（即使失败）；artifact / report root 配对且不使用 `latest`。
- [ ] S 级缺陷为零；影响 P0 的 A 级缺陷已修复并复验，或测试不能退出。
- [ ] P1/P2 与 `L2M-UP-*` / `L2M-DDD-*` residual 均有 owner 角色、接受人或待确认项，并交给 `06` / `07`。
- [ ] 没有将 fake、blocked、not_run、planned 或报告初稿写成 integration pass、evidence、verdict、signoff 或 readiness。

### 12.3 暂停 / 阻断准则

| 条件 | 处理 |
|---|---|
| required local slot、配置校验、测试数据隔离或 redaction check 不可用 | 立即阻断；保留原因，不继续写结果 |
| P0 blocking suite 失败且原因未分类 | 暂停后按 §11 分级；不得先跑 release smoke 覆盖 |
| 外部 owner contract / schema / route 未闭合 | 受影响 lane 标 `blocked` / `not_run`；继续只允许 local / negative / blocked-aware cut |
| artifact / report 不配对、缺 failure reason 或使用 `latest` | evidence integrity 阻断；不生成正式 EV |
| 发现字段、状态、version、source 或 helper 无法 1:1 落码 | 回写 owning `03` / `04` Step；测试方案不能临时补 schema |

### 12.4 进入 / 退出审计结论

| 审计项 | 结论 |
|---|---|
| checklist 可判定 | `defined` |
| P0 外部 blocker | `explicit`；blocked / not_run 不伪造通过 |
| evidence 真实性 | `required`；raw artifact / report pairing 是前置 |

| suite report | suite `report.json`、case result、stdout / stderr | `scripts/reports/generate_suite_reports.sh` | `reports/runs/<run_id>/suites/` | case / failure 对齐 |
| gate summary | suite reports、gate metadata | `scripts/reports/generate_gate_summary.sh` | `gate-results.md` | blocked / not_run 不伪 pass |
| evidence index | raw suite artifact + report pair | `scripts/reports/generate_evidence_index.sh` | artifact + report index | TC / cut / AC / VF / path 回指 |
| redaction report | redaction scan output | `scripts/reports/generate_redaction_report.sh` | `redaction-check.md` | 泄漏即 S |
| dependency report | dependency scan + candidate inventory | `scripts/reports/generate_dependency_report.sh` | checks report | Core-only / non-materialization |

| review notes | reports / checks / diff | 人 / Agent 审查 | `reports/review/*` | 解释异常、阻塞和风险接受 |

### 13.5 证据真实性与追溯规则

- 每个正式 EV 必须回指至少一个真实 TC、suite、固定 artifact、固定 report、digest、disposition 和 AC / VF。
- 失败 suite 也必须保留 `report.json`、stdout / stderr、case result 和 failure reason。
- `blocked`、`not_run`、`unknown`、fake、planned 或缺来源关系不得生成正向 EV；外部 selected run 未闭合时只生成 blocker / residual 记录。
- 24 个 outbound semantic candidate 只能生成 non-materialization / dependency evidence，不能出现 event / publisher / outbox artifact。
- 验收交接脚本只能生成初稿；验收 verdict、signoff、readiness 由后续 `06` / `07` 和授权审查承接。

### 13.6 证据归档停审结论

| 证据 / 报告 | 真实来源约束 | path / 回指 | 结论 |
|---|---|---|---|
| P0 suite EV families | 是 | artifact + report + TC / AC / VF | `planned_schema_only` |
| failed suite outputs | 是 | raw pair + failure reason | `required` |
| redaction / dependency checks | 是 | check output + review | `blocking` |
| acceptance handoff | 仅初稿 | reports / acceptance | `review_required` |
| owner selected EV | 条件化 | 合同闭合后 | `blocked` |

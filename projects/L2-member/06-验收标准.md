### 1.1 本仓职责与明确外置真相

`L2-member` 负责 AI Member 容器内运行态主体和成员门面的 member-local 交互边界：在场与宿主协作本地面、入站订阅与筛选、向 Runtime 的受控投递、出站决定与安全材料、交互追溯、成员可见摘要和安全能力出口。它通过正式 ref、safe snapshot、typed result、attempt、gap 或 blocked posture 与其他模块协作。

以下真相不属于本仓，验收只检查接缝和禁止越权：

| 外部 owner | 本仓只可验 | 本仓不验 / 不拥有 |
|---|---|---|
| `L2-runtime` | entry / handoff 的 typed ref、safe material、local attempt / gap、缺映射拒绝 | runtime loop、context、goal / plan、memory、checkpoint、tool execution、outcome |
| `L2-tools` | 工具 / 方法 capability ref、safe view、freshness / gap | 工具执行、定义正文、capability registry、授权和外部调用 |
| `L2-member-service` | 注册请求、存活信号、状态报告、本地 host attempt / blocked | host acceptance、endpoint registry、session、health、容器生命周期、凭据签发 |
| `L2-member-images` | pinned opaque ref、availability、waiting / blocked handoff | 镜像构建、manifest、compatibility、release readiness |
| `L0-core` / `L0-bus` / `L0-sdk` | shared primitive、typed carrier、event / handoff seam 的边界 | member-specific schema / route 未闭合时的事件设施、broker delivery、SDK 内部状态 |
| `L1-identity` / `L1-work` | `GlobalMemberRef`、`ProjectMemberRef` 和 safe resolution | 身份 / 工作生命周期、凭据签发和授权后端 |
| `L1-governance` | Policy effective safe result、规则来源、freshness / conflict | policy / approval truth、allowlist 和治理裁决 |
| `L1-conversation` / `L1-artifact` | body-free material、正式 ref、handoff attempt / gap | 对话 / 制品正文、ordering、archive / evidence truth |
| observability | safe observation material、低基数诊断、local attempt / gap | backend ingest、dashboard、observed truth 和 readiness |

## 2. 验收目标与范围

> 校准来源：
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“P0/P1/P2 裁决关系”“验收范围表”“只测接缝的下游与外部能力”和“范围项到一票否决候选”小节。

本轮验收裁决 `L2-member` 是否形成可落码、可追溯且 fail-closed 的 member-local 主线，而不是是否完成任何外部系统的内部功能。五个核心能力如下：

| 核心能力 | 验收目标 | P0 口径 |
|---|---|---|
| `C-L2M-1` 在场与宿主协作 | 项目型 `ProjectMemberRef` + `GlobalMemberRef` 双锚和可验证启动语境形成在场；注册请求、存活信号、状态报告与本地尝试可区分 | local / negative / blocked-aware 必须成立；host acceptance / session / health 外置 |
| `C-L2M-2` 入站筛选与受控投递 | scope 有来源，筛选有通过 / 降级 / 阻断 / 待定四态，投递携带 typed ref / safe snapshot / safety context | unknown / stale / conflict 保守；不得透明转发正文或代答 |
| `C-L2M-3` 出站承接与安全发布 | 只承接 Runtime committed safe material，形成出站决定、body-free 材料、attempt / gap | outcome、decision、attempt、delivery、accepted 分层；外部失败不逆写 |
| `C-L2M-4` 交互追溯与安全观测 | 在场、筛选、投递、出站和观测材料可按同一 correlation 回链 | body-free、低基数、attempt / gap 可解释；不声称 observed |
| `C-L2M-5` 摘要与能力出口 | 从 committed local fact 和上游 safe ref 派生 summary / outlet，支持 freshness、stale、gap 和重建 | projection 不写源；能力出口不形成 registry / invocation truth |

### 2.1 范围 / 非范围

| 范围项 | 类型 | 优先级 | 裁决目标 | 非范围 / 说明 |
|---|---|---:|---|---|
| CP01 双锚、presence、host local material | 功能 / 状态 / 边界 | P0 | 双锚、startup context、presence successor 和 host 本地尝试可判定 | host acceptance、session、health、编排和凭据签发外置 |
| CP02 scope、inbound fact、screening | 功能 / 安全 | P0 | scope 来源、四态筛选、瞬时检查、无正文持久化 | policy truth、taxonomy owner、Bus delivery 外置 |
| CP03 Runtime mediation | 功能 / 接缝 | P0（负向）/ P1（正向） | typed delivery、attempt、result link、reception 与 unknown fence | Runtime loop / context / plan / outcome 外置 |
| CP04 outbound | 功能 / 安全 / 一致性 | P0 | committed safe material、decision、body-free material、attempt / gap | delivery / accepted、Conversation / Artifact truth 外置 |
| CP05 trace / observation | 追溯 / 观测 | P0 | correlation、append-only trace、safe observation、redaction | observability backend 和 observed truth 外置 |
| CP06 external context mirror | 依赖 / 派生 | P0（保守）/ P1（正向） | owner-specific ref、purpose、scope、freshness、stale / gap | generic resolver、authorization、health、registry 外置 |
| CP07 summary / capability outlet | 派生读模型 | P0（summary / boundary）/ P1（outlet 正向） | committed-only projection、cursor / watermark、rebuild no-write | UI、definition body、registry、invocation readiness 外置 |
| 七模块与 public surface | 架构 / 协议 | P0 | `contracts`、`domain`、`application`、`infra`、`api`、`worker`、`jobs` 和有限协议分母可审计 | 具体物理产品、部署拓扑和 binary 不在本轮 |

### 2.2 P0 / P1 / P2 裁决关系

| 优先级 | 内容 | 结论使用方式 |
|---|---|---|
| P0 | member-local truth、fail-closed、安全暴露、状态 / UoW / replay、配置、redaction、依赖和证据完整性；外部接缝的负向 / blocked-aware 语义 | 必须具备真实可执行的验收证据才能通过 |
| P1 | owner 合同闭合后的 host、Runtime、Bus、resolver、durable-like Store、image、outlet 正向 qualification | 可作为 selected-run 或 residual；blocked / not_run 不得计为 pass |
| P2 | 非项目型主语、生产容量 / 硬 SLO、深度产品集成、未来体验增强 | 不作为当前验收前置；需要新需求 / 设计授权 |

P1 或 P2 缺失本身不自动导致 P0 失败，但必须在送验范围和风险接受文件中明确；任何 P1/P2 结果都不能替代 P0 local truth、红线或证据门禁。

### 2.3 七模块分层验收面

验收以七模块的依赖方向检查实现边界，不把 CP01～CP07 机械地拆成独立 package。`contracts → domain → application` 是向内的编译 / 业务抽象层，`infra` 实现 application-owned Port，`api`、`worker`、`jobs` 仅作为受控入口调用 facade / named service。

| 模块 | 分层职责 | 必须成立的边界 | 禁止误判 |
|---|---|---|---|
| `contracts` | public typed carrier / ref / metadata / result / receipt / view | 只依赖已核验 Core primitive；协议有限且 body-free | 不拥有 domain、Store、transport 或 foreign body |
| `domain` | CP01～CP07 local / support / derived-read 对象、policy、state、invariant | factory / successor / illegal edge 可判定；不发起 I/O | 不读 repository、config、clock、Bus、adapter 或外部 truth |
| `application` | facade、named service、Port、UoW、idempotency、错误映射 | 所有 non-Query 编排和 no-write Query 规则集中可审计 | 不依赖 concrete infra、entry 或 provider |
| `infra` | logical Store、resolver / handoff adapter、config、builder、availability / fake | 只实现 application Port；失败返回 safe posture | 不把 adapter 或 fake 变成 source owner / compile dependency |
| `api` | Command / Query logical entry | pre-gate、typed result、safe error mapping；不直写 Store | 不创建 business ID、digest、状态或 reservation |
| `worker` | 14 Consumer entry、receipt、dispatch context | source / schema / body / dedup gate；receipt 仅是本地结果 | 不声称 Bus delivery 或下游 accepted |
| `jobs` | 5 Operations Job、item result、report / replay | finite selector、partial isolation、no-source-repair | 不修复 CP01～CP06 truth 或伪造 readiness |

模块分层属于 P0 架构门禁；具体 crate、文件和 trait 仍以 `03-详细设计.md` 为唯一来源，实际 package / build 证据在执行期由 `EV-L2M-DEPENDENCY-*` 和 `EV-L2M-CONTRACT-*` 提供。

### 4.3 暂停 / 不可裁决条件

| 条件 | 必须处理 |
|---|---|
| source ref、run、artifact、report 或 handoff 缺失 | 暂停，不填写通过或有条件通过 |
| P0 suite 失败但未分级 | 先按 §12 分级，不能直接放行 |
| owner schema、route、credential、subject 或 helper 未闭合 | 受影响 lane 标记 blocked / not_run；不得补 schema |
| redaction、dependency 或 report audit 失败 | 直接阻断；不可风险接受 |
| 设计字段 / 状态无法 1:1 落码 | 回写 `03` / `04` owning Step，重新固定基线 |
| blocked / not_run 被声明为 passed | 视为 evidence integrity defect，至少 S 级 |

## 5. 功能验收门禁

> 校准来源：

> 延伸阅读：

### 6.1 不得由本仓保存的外部真相

以下数据即使被本仓读取，也只能以正式 ref、safe snapshot、neutral resolution、marker、attempt、gap 或 body-free summary 形式出现：

- Runtime loop、context、goal / plan、memory、checkpoint、execution outcome 和 tool execution；
- ToolDefinition、method body、capability registry、grant、invocation 和 provider body；
- host acceptance、registry、session、health、restart / orchestration 和 credential material；
- image build、manifest、compatibility、release、sandbox isolation 和 deployment truth；
- Governance policy / approval / allowlist truth；
- Conversation / Artifact 正文、ordering、archive 和 evidence truth；
- Bus broker、topic / route、delivery、retry、DLQ、observed truth 和 observability backend；
- Identity / Work 生命周期以及非项目型执行主语的未定义扩展。

任何 Query、projection、Consumer、Job、report 或 adapter 都不得成为上述真相的第二写源。

## 12. 缺陷分级、复验与放行规则

> 校准来源：
> - `design-calibration/06_acceptance_step_12_defects_release.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“缺陷分级表”“缺陷状态与测试 disposition 分离”“复验规则矩阵”“放行规则”和“缺陷关闭证据”小节。

### 12.1 缺陷分级

| 级别 | 定义 | L2-member 典型例子 | 对结论的影响 | 复验要求 |
|---|---|---|---|---|
| S | 命中 `VF-L2M-001~009` 或 P0 truth / security / consistency / evidence integrity | 错主语放行、raw / secret 泄露、foreign truth 反写、Query 写入、duplicate 分叉、非 Core package、静态伪 EV | 立即不通过；不可风险接受 | 修复后失败 case + 同 family + 全量 P0 + redline + report audit |
| A | 影响 P0 功能 / 跨层编排或 selected seam，但未直接命中 VETO | successor 丢失、CAS 未回滚、partial item 误吞、required slot posture 错误 | 影响 P0 时必须修复；非 P0 A 只有逐项接受才可条件通过 | 失败 case + 受影响 family；必要时全量 P0 |
| B | 不影响 P0 truth / safety 的外围、文档或可读性问题 | 非关键 diagnostics、P2 view、报告可读性 | 可记录 / 排期，不改变 P0 结论 | 受影响 cut |
| R | 范围外、future、production-like、容量或 vendor residual | 未定义非项目型主语、硬 SLO、长期 retention | 进入风险接受或后续跟踪 | 升级为 P0/P1 时新基线复验 |

缺陷状态（open、triaged、fix-planned、fixed-awaiting-retest、verified、accepted-risk、deferred）与测试 disposition（passed、failed、blocked、not_run、unknown）必须分开。blocked / not_run 不表示 defect fixed，也不表示 passed。

### 12.2 复验与放行

| 失败类型 | 最小复验集 | 触发全量 P0 的条件 | 关闭证据 |
|---|---|---|---|
| contract / DTO / enum / state | 失败 case + `contract-domain-fast` + 受影响 entry | public protocol / state matrix 变更 | failed / fixed run pair、schema diff、review |
| Command / Query flow | 失败 case + operation family + `service-flow-fast` | UoW / replay / Query no-write 变更 | fixed run + no-write / replay evidence |
| Consumer / Job | 失败 case + source / receipt / report family + `api-worker-entry` / `job-continuation` | receipt、dedup、partial isolation 或 source gate 变更 | receipt / report pairing |
| Store / CAS / rollback | 失败 case + `infra-fake-parity` + `replay-recovery` | version / UoW / commit-unknown 变更 | ordering / rollback trace |
| config / builder | 失败 profile + `config-redline` + `dependency-boundary` | required slot / redaction / invariant 可配置性变更 | profile diff + redacted issue |
| security / redaction | 失败 corpus + `redaction-boundary` + release redline | deny / serializer / output surface 变更 | clean scan + reviewer note；S 不可接受 |
| dependency / evidence | failed check + `report-generation-audit` + release redline | package / artifact / report schema 变更 | raw pair + provenance check |
| P1 external seam | failed selected-run + local blocked posture | owner contract / schema / route 变更 | owner evidence；未闭合则仍 blocked |

放行只允许以下三值：

| 条件 | 允许结果 |
|---|---|
| 全部 P0 AC 通过、VETO 未命中、S=0、证据完整、无未接受 A | 通过 |
| P0 全部成立、VETO 未命中、S=0、证据完整，仅有已接受 residual | 有条件通过 |
| 任一 P0 失败、VETO 命中、S 未关闭、证据不可裁决或 hard gate failed | 不通过 |

缺少固定 run、baseline、artifact / report pair、VETO checklist、redaction / dependency / report audit 时，不得填写通过或有条件通过。

### 13.1 不可风险接受项

- `VF-L2M-001~009` 任一命中；
- S 级缺陷、redaction / dependency / evidence integrity 失败；
- 缺固定 run、artifact / report pair、evidence index、handoff 或 VETO checklist；
- Query / Job / projection / report 反写 source truth；
- external accepted / delivered / observed / healthy / ready 被伪装成本地成功；
- 影响 P0 的 DDD helper、schema、version 或 owner contract 缺口；
- fake、planned、blocked、not_run 被伪装为正向证据、verdict、signoff 或 readiness。

`reports/acceptance/risk-acceptance.md` 至少必须包含：`risk_id`、`scope`、`impact`、`acceptance_reason`、`evidence_refs`、`owner`、`acceptor`、`deadline_or_trigger`、`follow_up_ref`。缺少接受人或后续动作的 residual 不得支撑有条件通过。

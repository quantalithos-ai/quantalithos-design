### 10.1 暂停与失败处理

| 触发 | 状态 / 唯一允许动作 | 责任 / 回写 | 恢复条件 |
|---|---|---|---|
| repo、authorization、baseline或 Core compatibility缺失 | `blocked / wait_design` | project / Core / design authority | exact repo + immutable baseline + compatibility重核 |
| field / DTO / factory / state / Port / receipt / version / report source缺口 | `blocked / wait_design` | 回写 03 owning source | 新 baseline + current boundary closure review |
| config / slot / secret / redaction binding缺口 | `blocked / wait_design` | 回写 04，必要时同步03 | config / redaction mapping复核 |
| suite / artifact-report / EV contract缺口 | `blocked / wait_design` | 回写 05 | gate与 materialization规则重映射 |
| AC / VF / VETO / risk / reviewer缺口 | `blocked / wait_design` | 回写 06 | acceptance source和职责闭合 |
| phase / boundary越界、无关用户改动混入 | `blocked`；只隔离 current scope | 回写07或清理 staged selection | Scope / Worktree Gate重新核验 |
| local slot、P0 fake、pairing checker或 fmt / build / targeted test失败 | `blocked / fix_gate_failure` | current implementation boundary | 修最小 defect并重跑适用 gates |
| external positive seam unavailable | local P0可继续；positive lane `blocked / not_run` | owner coordination | owner正式合同后独立 selected run |
| redaction leak、non-Core dependency、candidate materialization、static evidence、VETO / S | `blocked`; `fix_gate_failure`或`wait_design` | implementation + security / design / acceptance | 修复并复验；不可风险接受 |

### 10.2 回退与用户改动保护

- 默认只回退 current boundary 内、尚未提交、可明确归因且不含用户改动的试探修改；不得 broad reset / checkout或删除用户文件。
- staged 范围混入无关文件时，只撤出错纳入的 staging selection；不清空工作区。
- 已提交 boundary 出现实现缺陷时，默认新增受控 fix boundary / commit；未经明确授权不得 amend、rebase、reset 已验证历史。
- design truth gap 可保留安全诊断，但不得提交半成品或在实现仓补 schema / Port / state。
- generator错误必须从真实 raw重新生成 report；不得删除失败 raw或手写 pass。

### 10.3 变更回写与恢复

| 变化类型 | Truth source | 必须同步 |
|---|---|---|
| object / protocol / flow / state / Store / UoW / replay / version / receipt / Job report | `03-详细设计.md` + owning calibration | 05/06/07受影响 mapping与 boundary ledger |
| config source / profile / raw-validated binding / slot / secret / redaction | `04-配置设计.md` | 03 binding、05 config gate、07 §8 |
| suite / fixture / script / artifact-report / EV | `05-测试方案.md` | 06 evidence / acceptance、07 §7 |
| AC / VF / VETO / defect / residual / reviewer | `06-验收标准.md` | 07 §7/§9/§12 |
| phase / batch / boundary / gate / rollback / delivery | `07-实施计划.md` + calibration | implementation ledger及相关 skeleton |
| host / image / Runtime / Core-Bus / domain owner exact contract | respective owner；本仓记录 blocker | 03～07 drift audit与新 baseline |

恢复路径固定为：分类并保留安全诊断 → 修 implementation 或等待 truth owner → 固定新 baseline → 重读 current ledger / required sources → 重做 closure / worktree / dependency检查 → 重跑当前 boundary适用 gates → 只恢复同一 boundary。`blocked` 不得直接跳到 implement / commit。

### 11.1 Future commit contract

| 项 | 规则 |
|---|---|
| identity | target repo项目级 `user.name=quantalithos-labs`、`user.email=quantalithos.ai@gmail.com`；不修改 global config |
| 粒度 | 一笔 commit只对应 §6 一个 boundary；同一 boundary的协作子功能合并，不同 boundary必拆 |
| title | English `<type>(<scope>): <subject>`；scope必填；target repo更严格规则只能叠加 |
| type / scope | type: `feat/fix/refactor/docs/test/chore/perf/ci/style`; scope须为 workspace/config/presence/screening/inbound/runtime/outbound/trace/mirror/projection/consumer/jobs/release/handoff |

| footer | Codex实际参与时：`Co-Authored-By: Codex <noreply@openai.com>`；前置真实空行；不虚构参与者 |
| source language | identifiers、rustdoc、normal comments、errors与 test names默认英文 |
| exact formatting | 使用完整 message file和 `git commit -F`；amend只在独立明确授权下使用 |

禁止 scope `event/outbox/publisher/route/topic/retry/dlq/adapter/all`：前六项会误导 24 candidate 物化，后两项掩盖 owner-specific boundary。planned title完整映射位于 Step 11 §7.3；title存在不是 commit授权。

### 11.2 Commit Gate / review / Handoff Gate

| Gate | Future pass 条件 | 当前状态 |
|---|---|---|
| Design Gate | immutable baseline、required reads、fields / DTO / state / Port / evidence闭合 | `blocked / not_run` |
| Scope / Worktree Gate | touched / staged只含 current boundary；用户无关改动未触碰 | `not_run` |
| Build / Test / Evidence Gate | §7适用 checks真实运行；raw/report可回链；无 redaction / dependency / candidate violation | `not_run` |
| Commit Gate | git identity、staged diff、whitespace、message、required checks均有真实记录 | `blocked / not_run` |
| Handoff Gate | real hash / message、gates run、tests not run原因、blockers、next boundary、用户改动保护完整 | `not_entered` |

Review 必须核验 boundary identity、设计闭环、only-Core dependency、P0 safety、gate provenance、acceptance draft人工职责、用户工作区和语言 / message。交付只引用真实 `artifacts/test/<run_id>`、`reports/runs/<run_id>`、`reports/acceptance/*`与 review records；不粘贴日志、不手写证据、不自动写 verdict / signoff / readiness。

### 12.2 Outcome matrix

| Future outcome | 必要条件 | 禁止简写 / 边界 |
|---|---|---|
| `implementation_complete_and_ready_for_acceptance` | P0 / 18 boundaries / checks完成；VETO未命中；S=0；evidence、review、closure完整 | 只表示实现可送验，不等于验收 verdict、release、signoff或 readiness |
| `implementation_conditionally_complete_and_ready_for_acceptance` | 上述硬条件全部成立，只剩被正式接受且不影响P0的 A/B/R或P1/P2 residual | 不可接受 blocked P0、VETO/S、missing run/report或 owner truth gap |
| `implementation_not_complete` | 任一 P0 / gate / evidence / closure缺失或失败，repo / baseline缺失，或用户改动混入 | 不得写“基本完成”“待小修”“预计可送验” |
| `acceptance_pending_or_not_decidable` | 实现证据不足，或正式验收尚未执行 | planned / fake / blocked / not_run不能替代验收结论 |

### 12.3 交付前 closure audit 与未完成项

每个 boundary 变为 current 前、每个 Phase 交付前和最终 handoff 前，必须按 §6.4 对正式 `03/05/06/07` 执行可落码闭环审计。当前审计姿态为：PH-01受 repo / baseline / Core mapping阻塞；PH-02受 repo、credential / host seam与 Store decision影响；PH-03受 scope successor / receipt / screening source影响；PH-04受 Runtime mapping影响；PH-05～07受 `L2M-DDD-003~007` 和 external sources影响；PH-08没有真实 run / report / review。

P0缺失、P0 gate失败、VETO / S、evidence integrity、target repo / baseline、affected DDD / scope gap、redaction / dependency / candidate violation和用户改动混入都不可风险接受。仅不影响 P0 claim的 P1 selected seam unavailable、B/R / accepted A、P1/P2 enhancement或 workload / SLO authority缺失可成为明确 residual；不得声明相应能力通过。

当前结论固定为 `implementation_not_complete`，且正式验收为 `acceptance_pending_or_not_decidable`。这是对现状缺失的诚实描述，不是测试或验收 verdict。

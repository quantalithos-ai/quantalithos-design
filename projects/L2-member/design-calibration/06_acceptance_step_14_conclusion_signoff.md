## 2. 本步目标

固定最终结论只允许“通过 / 有条件通过 / 不通过”，明确进入下一阶段和发布准备的条件、签署角色、风险接受关系及当前设计阶段不填真实结论。

## 4. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 结论只能有哪些值？ | 通过、有条件通过、不通过；禁止“基本通过”“原则上通过”“大体没问题”“后补即可”。 |
| 何时允许进入下一阶段？ | 全部 P0 门禁通过、VETO 未命中、S=0、证据完整时；若只剩合法且已接受 residual，可有条件进入。 |
| 何时允许发布准备？ | 结论为通过或有条件通过，且条件不影响 P0 truth、安全、依赖、证据、配置和外部成功分层。 |
| 哪些角色必须签署？ | Owner / 产品或业务、架构、测试、实施、运维 / 安全 / 合规、验收负责人按职责签署。 |
| 签署是否自动代表风险接受？ | 不代表。风险必须在 reports/acceptance/risk-acceptance.md 逐项由 acceptor 确认；最终签署只确认结论与清单一致。 |

## 8. 结构化中间产物

### 8.1 最终结论表

| 条件 | 允许结论 | 说明 |
|---|---|---|
| 全部 P0 通过、VETO 未命中、S=0、证据完整、无未接受 A | 通过 | 可进入下一阶段或发布准备 |
| P0 全部通过、VETO 未命中、S=0、证据完整，仅有已接受 residual | 有条件通过 | 必须跟踪 owner、acceptor、deadline / trigger |
| 任一 P0 失败、VETO 命中、S 未关闭、证据不可裁决或 hard gate failed | 不通过 | 修复并复验后重新裁决 |

### 8.2 判定矩阵

| 条件 | 通过 | 有条件通过 | 不通过 |
|---|---|---|---|
| P0 AC / gate | 全部通过 | 全部通过 | 任一失败 |
| VF-L2M-001~009 | 全部未命中 | 全部未命中 | 任一命中 |
| S 级 | 0 | 0 | 大于 0 |

### 8.4 签署含义

| 签署 | 表示 | 不表示 |
|---|---|---|
| 通过 | 本轮 P0 和证据满足进入下一阶段 | P1/P2/future 已完成 |
| 有条件通过 | P0 成立，指定 residual 已逐项接受 | VETO / S / P0 gap 被接受 |
| 不通过 | 当前有阻断或证据不可裁决 | 项目永久终止 |
| risk acceptance | 接受指定 residual 与后续动作 | 接受未列风险、VETO 或 S |

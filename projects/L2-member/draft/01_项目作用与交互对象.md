## 1. 一句话定位(候选)

`L2-member` 是 AI Member 容器内的**成员门面真相仓**:它拥有一个运行态成员的对外交互边界——入站事件的受控筛选与投递决定、出站交互的受控发布决定、成员侧 IPC / adapter 语境、成员可见摘要与能力出口——但不做推理、计划、记忆、工具执行或生命周期编排。

对照旧 README 的"嘴耳"比喻:方向仍然成立(听、说、连接外界,不思考),但本轮必须用当前上游语言重述——它不是"6 子模块的 Rust 进程",而是**入站 / 出站 / IPC / 摘要四类成员侧交互语义的 owner**,协议与技术载体后移。

### 1.1 为什么必须单独存在(与谁最容易混淆)

| 易混淆对象 | 区分口径 |
|---|---|
| `L2-runtime` | Runtime 拥有 controlled run / goal / plan / context / decision / checkpoint / outcome truth;member 拥有"什么进入 Runtime 视野、什么以何种形态离开容器"的交互边界 truth。member 不是第二个 loop owner,Runtime 也不应直接接触 bus 协议与外部网络。 |
| `L2-member-service` | member-service(pending)拥有容器编排、注册、心跳监控、policy 下发通道等宿主生命周期;member 只是容器内被编排的一方,向宿主暴露最小的注册 / 存活 / 状态面。 |
| `L2-member-images` | images(pending)拥有打包与构建资产;member 只是被打包的运行部件之一。 |
| `L0-bus` | bus 拥有传递 truth;member 拥有"订阅哪些、过滤结论是什么、发布决定是什么"的成员侧协作语义,delivery / observed 不归 member。 |
| `L1-conversation` | 对话真相归 conversation;member 出站交互只是形成 handoff material,不拥有对话事实。 |
| `L1-identity` | 平台级成员身份真相归 identity;member 只持有运行态身份锚点 / 凭据的受控消费视图("我是哪个 member、哪个 role 的运行实例"),不拥有身份生命周期。 |
| `L1-governance` | 入站筛选(如注入防御分级)只消费正式 Policy effective 结果;member 不形成 approval / allow-deny truth,不建本地 allowlist。 |

若 member 缺位,Runtime 将同时承担接入、协议、过滤、发布、心跳职责(边界外职责在 L2-runtime 需求 §2 已明确排除 member host lifecycle,且其 Entry consumers 把 Member 列为下游入口边界);若 member 越位,则会形成第二个 run truth 或第二个 policy truth。

## 2. 本仓拥有什么 / 只消费什么 / 禁止拥有什么(候选)

| 主题 | member 拥有 | 只消费 / 交接 | 禁止拥有 |
|---|---|---|---|
| 运行态成员主体 | member runtime presence(本容器内"这个成员实例"的运行态主体、启动 / 就绪 / 降级 / 终止语义) | identity 身份锚点 ref、member-service 启动语境 | GlobalMember truth、容器生命周期 truth |
| 入站 | 订阅范围决定、入站筛选结论(通过 / 降级 / 阻断 / 待定)、向 Runtime 投递的决定与记录 | bus 事件、Policy effective safe snapshot | bus delivery truth、policy truth、Runtime 对输入的处置 |
| 出站 | 出站交互决定、发布材料准备、提交尝试 / gap | Runtime 的 committed outcome / safe material | delivery / observed / accepted、对话真相、Artifact 正文 |
| 成员侧 IPC / adapter | 容器内 member↔runtime 交互语境的成员侧一端(受理、拒绝、关联、背压语义) | Runtime entry 合同(IF-L2R-001~003 类能力) | Runtime run / decision truth;IPC 物理协议在 draft 阶段不锁定 |
| 事件订阅与发布 | 成员侧订阅 / 发布语义与本地记录 | L0-bus 事件协作 | 事件 schema authority(归 L0-core / owner 仓) |
| 成员可见摘要 | body-free 的成员状态 / 交互摘要投影 | — | hidden reasoning、raw body、secret |
| 能力出口 | 成员对外声明"我能承接什么"的安全出口视图(从上游 ref / safe view 派生) | L2-tools 工具契约 ref、method/role definition ref | ToolDefinition truth、capability registry、method body |

禁止合并进本仓(任务书红线,逐条对应 owner):LLM 推理 / 计划 / 记忆 / checkpoint(L2-runtime)、tool execution(L2-tools)、capability registry 与外部 MCP/A2A/API adapter(L3-capability-hub)、容器生命周期(L2-member-service)、镜像构建(L2-member-images)、sandbox 隔离 truth(L4-sandbox)、governance approval truth(L1-governance)、conversation truth(L1-conversation)、observability backend(L4-observability)。

### 4.1 禁止依赖(候选)

| 禁止依赖 | 原因 | 正确协作方式 |
|---|---|---|
| `L2-member -> L2-runtime` 源码 / package 依赖 | 会吸收 run / decision truth,破坏容器内双 owner 分层 | 容器内 runtime seam(具体载体后移),各自保留 truth |
| `L2-member -> L1-governance` 本地 policy 缓存作为裁决 | 形成第二 policy truth,fail-open 风险 | 只消费正式结果 / safe snapshot,unknown fail closed |
| `L2-member -> 外部网络 / provider / MCP` 直连 | 越过 capability-hub / tools / sandbox owner | 一律经 Runtime→Tools 正式合同;member 不做外呼 adapter |
| `L2-member -> conversation / artifact 正文写入` | 反写下游真相 | 只发布 body-free handoff material |
| 任一 sibling(除 Core)成为 path dependency | 违反全局裁剪 | runtime / event / ref / adapter seam |

## 5. 与 Runtime 的分界(本仓最关键的一条边)

L2-runtime 正式文档已单方面锁定其一侧:Runtime entry 只受理"正式主体、scope、目标、约束"的受控触发(IF-L2R-001~003),Member 是 Entry consumers / downstream,不得反向成为 Runtime truth owner(其 §4.2 红线第一条)。据此推演 member 一侧:

| 交互 | member 职责 | Runtime 职责 | 待确认(记 blocker 候选) |
|---|---|---|---|
| 入站事件 → Runtime | 订阅、筛选、形成"是否投递、以何种安全形态投递"的决定 | 受理 / 拒绝 trigger,决定是否推进 run | member 投递物与 Runtime formal trigger 的 mapping(对应 Runtime `Q-L2R-001` 开放项) |
| Runtime 出站 → 外界 | 承接 committed outcome / safe material,形成出站交互决定与发布尝试 | 形成 local outcome、handoff eligibility | Runtime handoff source family 未闭口(`L2R-UP-002/006`) |
| 状态查询 | 消费 Runtime safe view 形成成员可见摘要 | 提供 body-free status / safe summary | 摘要字段类别 |
| 背压 / 不可用 | Runtime 不可用时入站进入 waiting / degraded,不代答 | member 不可用时 Runtime 只感知 entry seam 失效 | 双向失效语义 |

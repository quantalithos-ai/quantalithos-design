## 1. 核心能力闭环(候选,五节点)

参照 L2-runtime / L2-tools 的能力闭环写法,member 的存在性由五类能力共同支撑:

```text
[C-L2M-1 运行态成员主体与宿主协作语境成立]
        |
        v
[C-L2M-2 入站订阅、筛选与受控投递成立]
        |
        v
[C-L2M-3 成员侧 IPC / runtime 交互语境成立]
        |
        v
[C-L2M-4 出站交互决定与安全发布成立]
        |
        v
[C-L2M-5 成员可见摘要与能力出口成立]
        |
        +-- 已提交本地事实 --> 回到 C-L2M-2 / C-L2M-4(持续在场)
```

| 节点 | 能力成立描述 | member owner | 外部 owner 边界 | 缺失后果 |
|---|---|---|---|---|
| `C-L2M-1` 运行态成员主体 | 一个成员实例能以可验证身份锚点与启动语境进入在场状态,并有就绪 / 降级 / 终止语义 | presence 状态、启动语境受理、对宿主的注册 / 存活面 | identity 身份 truth、member-service 编排 truth、凭据签发 | 容器内进程无成员语义,入站出站无主体可归属 |
| `C-L2M-2` 入站筛选与投递 | 订阅范围、筛选结论(通过 / 降级 / 阻断 / 待定)与向 Runtime 的投递决定可解释、可追溯 | 订阅决定、筛选结论、投递记录 | bus delivery、policy truth、Runtime 受理处置 | Runtime 直接暴露于 bus,注入防御与订阅边界失守 |
| `C-L2M-3` 成员侧 IPC 语境 | 容器内 member↔runtime 交互有受理 / 拒绝 / 关联 / 背压语义,且不监听外部网络 | member 侧交互语境与本地记录 | Runtime entry 合同与 run truth;IPC 载体后移 | 入站投递与出站承接无落点,双进程边界靠隐式约定 |
| `C-L2M-4` 出站决定与发布 | 从 Runtime committed safe material 形成出站交互决定、发布材料、提交尝试 / gap | 出站决定、材料准备(body-free)、attempt / gap | Runtime outcome truth、bus delivery、conversation / artifact truth | 成员输出各处直发,delivery 状态与本地决定压平 |
| `C-L2M-5` 摘要与能力出口 | 形成 body-free 成员状态 / 交互摘要投影,以及从上游 ref 派生的能力出口安全视图 | 摘要投影、能力出口视图(派生,可重建) | Runtime safe view、tools / method definition truth | 宿主与下游只能各自猜测成员状态 / 能力 |

## 2. 候选功能清单

### 2.1 核心功能(候选 FR)

| ID(候选) | 功能 | 说明 | 节点 |
|---|---|---|---|
| `FR-L2M-001` | 启动语境受理与运行态主体建立 | 以可验证身份锚点 ref + 启动凭据语境建立 presence;不完整 / 不可验证时拒绝进入在场,fail closed | C1 |
| `FR-L2M-002` | Presence 状态与终止语义 | 区分 starting / ready / degraded / draining / terminated / unknown;宿主或 Runtime 状态不覆盖本地 presence 记录 | C1 |
| `FR-L2M-003` | 宿主注册 / 存活面 | 向 member-service 提供注册与存活 / 状态语境(seam,契约 pending);宿主不可用时进入 degraded,不伪装在场 | C1 |
| `FR-L2M-004` | 订阅范围管理 | 按成员身份 / role 语境决定订阅范围;来源不可验证的订阅请求拒绝 | C2 |
| `FR-L2M-005` | 入站筛选 | 对入站事件形成通过 / 降级 / 阻断 / 待定结论(含注入类风险预筛);规则来源回链正式 Policy / 安全边界,unknown 保守处置,不自建 allowlist | C2 |
| `FR-L2M-006` | 受控投递 | 将通过筛选的入站语境以安全形态提交 Runtime entry;Runtime 拒绝 / 不可用时 waiting / degraded,不代答不重放未知副作用 | C2 / C3 |
| `FR-L2M-007` | 入站记录与追溯 | 每条入站事件的筛选结论、投递决定、Runtime 受理结果 ref 可关联追溯(body-free) | C2 |
| `FR-L2M-008` | 成员侧 IPC 受理与关联 | member 侧受理 Runtime 的出站请求 / 状态通报,维护 correlation;重复 / 迟到 / 乱序形成新事实不逆写 | C3 |
| `FR-L2M-009` | IPC 边界安全 | 容器内交互不暴露外部网络;forbidden body(hidden reasoning / secret / raw provider body)不经 member 转发 | C3 |
| `FR-L2M-010` | 出站交互决定 | 基于 Runtime committed safe material 形成"发布什么、向哪个正式边界、以什么安全形态"的决定;材料不合格(含正文 / secret)拒绝出站 | C4 |
| `FR-L2M-011` | 出站发布与 attempt / gap | 向 bus 提交发布尝试,记录 attempt / gap;delivery 失败不回滚出站决定,不声明 delivered / observed / accepted | C4 |
| `FR-L2M-012` | 出站审计 | 出站决定、材料准备、尝试与反馈 ref 可追溯 | C4 |
| `FR-L2M-013` | 成员可见摘要投影 | 从本地已提交事实 + Runtime safe view 派生 body-free 状态 / 交互摘要;可延迟可重建,不成为写源 | C5 |
| `FR-L2M-014` | 能力出口视图 | 从 tools / method definition refs 派生"本成员可承接能力"的安全出口视图;ref 失效显式 stale / gap,不复制定义正文 | C5 |
| `FR-L2M-015` | 安全观测材料 | 形成 body-free、低基数、可关联的 member 域观测 / 审计材料交 Bus / Observability;route 未闭口只保留 local attempt / gap | 横切 |

### 2.2 外围增强候选(不阻塞核心)

| ID(候选) | 功能 | 边界 |
|---|---|---|
| `FR-L2M-E01` | 入站筛选统计 / 误拦截诊断摘要 | 只读派生,不改筛选 truth |
| `FR-L2M-E02` | 成员交互历史浏览 | body-free 只读,不替代 conversation / observability |
| `FR-L2M-E03` | 订阅 / 出站配置的可解释视图 | 展示生效配置来源,不成为配置 truth |

### 2.3 失败语义(候选,统一口径)

所有能力必须区分:invalid、unauthorized、missing source、stale、conflict、unavailable、waiting、blocked、degraded、duplicate、late、unknown、delivery gap。禁止互相压平;外部不可用不得伪装 ready / delivered;凭据 / policy / 筛选来源 unknown 一律 fail closed。

## 4. 关键设计问题(正式校准时需逐个收口)

1. **入站筛选的裁决权分层**:member 的筛选是"预过滤 + 保守处置",不是 policy 裁决——通过 / 阻断的规则来源必须可回链;member 自身只拥有"结论 + 处置记录"这层 truth。需要与 governance 的 Policy effective 消费口径对齐(参照 L2-tools `FR-L2T-011` 的 fail-closed 写法)。
2. **投递物形态**:member 交给 Runtime 的是"安全入站语境"(带来源、scope、筛选结论),不是 raw event body 的透明转发,也不是替 Runtime 做的解释。mapping 依赖 Runtime `Q-L2R-001`,先冻结为 seam。
3. **出站的双阶段分层**:Runtime local outcome(归 Runtime)→ member 出站决定(归 member)→ bus delivery(归 bus)→ 下游 accepted(归下游)。四层不得压平,这是本仓最重要的 local-truth-first 应用。
4. **presence 与 heartbeat 的关系**:presence 语义归 member,健康裁决(如"连续 N 次失败标记 crashed")归 member-service;member 只提供可靠的存活面。旧 30s×3 数字不继承。
5. **能力出口是否进入第一批**:它是派生视图而非新 truth,可裁剪;若上游 ref 语义不稳可整体后置,不阻塞 C1~C4。

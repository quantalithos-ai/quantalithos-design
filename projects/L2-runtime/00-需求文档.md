## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_position_boundary.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化边界产物”“Owner / consumer 边界”和“历史材料差异审计”小节。

`L2-runtime` 是平台 AI 成员运行层中负责受控运行循环、运行时决策、上下文工作态、行动编排、恢复与运行结果交接语义的真相仓。它拥有一次 Runtime run 的工作语义和可恢复历史，但不吞并定义、裁决、执行基础设施、观测后端或成员宿主生命周期。

| 主题 | Runtime 拥有 | 只消费 / 交接 | 禁止拥有 |
|---|---|---|---|
| loop | run / loop / turn 运行语义 | 外部触发、终止请求 | member host lifecycle |
| goal / plan | 目标分解、计划工作态、推进决定 | Work / Process / Method / Artifact refs | 正式业务正文、ProcessInstance、WorkItem |
| context / memory | working set、composition decision、检索 / 候选语境 | safe snapshot / ref | 外部正文、durable memory body |
| model | provider-neutral intent、逻辑选择、turn disposition | adapter capability / availability summary | secret、physical route、quota、cost、raw response |
| action | action choice、Tools orchestration、sub-agent delegation | Tools outcome、Governance result、Sandbox seam | 工具执行、approval、Sandbox run |
| recovery | checkpoint、resume、reflection / recovery decision | 外部结果与 immutable refs | 外部 truth repair |
| handoff | Runtime outcome、safe material、local attempt / gap | Bus / Observability / downstream feedback | delivery、observed、accepted、evidence verdict |

边界外职责包括：`L2-tools` tools execution、`L3-capability-hub` registry / adapter descriptor truth、`L3-method-library` method body、`L1-governance` approval / policy truth、`L4-sandbox` isolation truth、`L4-observability` backend、member-service 生命周期、member-images 打包、marketplace、产品入口、provider secret / route / quota / cost 以及 Artifact / Evidence 正文。

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化问题定义”“当前文档问题诊断与前后对比”和“回填草稿”小节。

上游已经分别收束方法定义、能力接入、工具行动合同、治理裁决、隔离执行和观测边界，但平台仍缺少一个 owner 将这些受控输入组织成持续、可暂停、可恢复的 AI 成员决策运行。

| 问题 | 后果 |
|---|---|
| 受控运行循环缺少当前需求真相 | 产品入口、member host 或 adapter 各自定义 loop，运行语义分叉 |
| Model 逻辑选择与 provider physical route 混淆 | Runtime 吞并 secret / quota / cost，或丧失 model decision 可追溯性 |
| Context / memory / method / policy 混写 | 外部正文被复制，working / episodic / semantic 语义漂移 |
| Checkpoint / resume / recovery owner 不清 | 重启可能重做副作用、跳过未确认结果或改写历史 |
| Tool / sub-agent / event handoff 串仓 | accepted、executed、outcome、delivered、observed 被压成一个成功状态 |

业务问题是 AI 成员无法形成一致、受控、可恢复且不越权的运行行为边界；技术问题是 Runtime run / turn / working state 的唯一 owner、model / tool / sub-agent decision、context composition、checkpoint / resume、source correlation 与 local-truth-first handoff 尚未按当前上游合同闭合。当前没有可信实现、workload 或测量 authority，因此不继承旧性能数字。

## 4. 目标与非目标

> 校准来源：
> - `design-calibration/00_req_step_04_goals_non_goals.md`
>
> 延伸阅读：

### 4.1 目标

| ID | 目标 | 完成方向 |
|---|---|---|
| `G-L2R-001` | 运行循环真相成立 | 一次 run 有触发、目标、上下文、决策、行动 / 等待、结果、暂停和终止语义 |
| `G-L2R-002` | Context 与 memory 边界成立 | working context、外部 refs、检索候选与禁止正文可区分 |
| `G-L2R-003` | Model / action decision 可解释且保守失败 | 逻辑选择可回链约束；依赖不明时 blocked / fail-closed |
| `G-L2R-004` | Checkpoint / resume / reflection / recovery 可区分 | 稳定点可恢复，unknown side effect 不盲重试，历史不被原地改写 |
| `G-L2R-005` | 运行事件与外部交接不反写真相 | 已提交事实可交接，delivery / observed / accepted 独立 |

### 4.2 非目标

| ID | 非目标 | Owner / 原因 |
|---|---|---|
| `NG-L2R-001` | Tools execution、ToolDefinition、normalized outcome | `L2-tools` |
| `NG-L2R-002` | Capability identity / registry / descriptor / formal exposure | `L3-capability-hub` |
| `NG-L2R-003` | Method / Role / Process definition body | `L3-method-library` |
| `NG-L2R-004` | Effective governance / approval / policy truth | `L1-governance` |
| `NG-L2R-005` | Sandbox environment / run / capture / cleanup / isolation truth | `L4-sandbox` |
| `NG-L2R-006` | Observability backend / retention / audit projection truth | `L4-observability` |
| `NG-L2R-007` | Provider secret / route / quota / cost / billing / failover truth | provider / security / finance / adapter owner |
| `NG-L2R-008` | Member-service、member-images、marketplace、product UI | sibling / product owner |
| `NG-L2R-009` | Artifact / evidence / report 正文与正式验收 verdict | `L1-artifact` / 验收流程 |
| `NG-L2R-010` | 固定框架、语言、部署、SLA 和性能数字 | 无当前 authority，后续阶段收敛 |

所有正向 seam 在 owner contract、字段 / route、adapter / fake parity 和真实证据闭口前只能是 `pending`、`blocked`、`waiting`、`degraded` 或 `fail-closed`。

## 5. 用户与角色

> 校准来源：
> - `design-calibration/00_req_step_05_users_roles.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“角色说明表”“能力级权限差异”和“历史角色审计”小节。

### 5.1 人类角色

| 角色 | 使用场景 |
|---|---|
| Runtime 运维 / 维护者 | 维护运行输入边界、诊断能力和安全停机 / 恢复入口，不修改业务 truth |
| 运行问题调查者 | 沿 run、turn、decision、action、checkpoint、handoff 关联定位等待、失败或未知副作用 |
| 安全 / 边界审查者 | 审查正文、secret、隐藏推理、越权 action、fail-open、重复副作用和 owner 串线 |

### 5.2 系统角色

| 角色 | 使用场景 |
|---|---|
| 运行触发方 | 以正式主体、目标和约束触发、暂停、取消或查询 Runtime run |
| 正式上下文提供方 | 以 typed ref、safe snapshot、effective decision 或 definition summary 提供输入，仍拥有源 truth |
| 模型适配协作方 | 承接 provider-neutral model turn，返回关联结果或明确失败 |
| 工具行动协作方 | 按 `L2-tools` 正式合同承接 invocation，返回 normalized outcome |
| 运行材料消费方 | 消费 body-free status / outcome / event，不反写 Runtime truth |

角色表只描述职责与接触场景，不授予 authorization。具体 principal、scope、allow / deny 必须来自 Governance / Identity 等正式 owner；任何角色都不得声明 delivered、observed 或 accepted。

## 6. 使用方与依赖

> 校准来源：
> - `design-calibration/00_req_step_06_consumers_dependencies.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“本仓依赖裁剪表”“依赖类型分类表”“依赖裁剪图”和“禁止依赖表”小节。

Runtime 向受控触发方提供 run 受理 / 控制、状态与安全摘要、恢复请求以及 outcome / handoff 语义；向 Bus / Observability 提供已提交、body-free 的 Runtime safe material。Runtime 不反向依赖 SDK、产品入口或 member-service 生命周期。

### 6.1 依赖裁剪

| 关联项目 / seam | Runtime 使用内容 | 依赖类型 | 未就绪处理 |
|---|---|---|---|
| `L0-core` | shared ID / ref / actor / metadata / error / trace / envelope 类别 | `compile` | Runtime-specific 类型未闭口时保持 pending，不本地复制 |
| `L2-tools` | canonical invocation、normalized result / error、工具审计引用 | `runtime` + `adapter` | no-execution / blocked，不直连工具或 Sandbox |
| `L3-capability-hub` | identity、registry descriptor、formal exposure 的 controlled ref / safe summary | `runtime` + `ref` | candidate unavailable / blocked |
| `L3-method-library` | method / role / process definition ref / safe view | `runtime` + `ref` | stale / missing / waiting |
| `L1-governance` | Decision、Policy effective、approval 的正式结果 / safe summary | `runtime` + `event` | unknown / conflict 时 fail closed |
| `L4-sandbox` | isolation-required action 的 run / failure / capture / handoff ref | `runtime` + `adapter` | sandbox-required action blocked，不 host fallback |
| `L1-artifact` | goal / plan / output / evidence ref / safe summary | `runtime` + `ref` | waiting / degraded，不保存正文 |
| `L0-bus` | 已提交 Runtime fact 的事件协作 | `event` | delivery failure 不回滚本地 truth |
| `L4-observability` | body-free observation / audit material | `event` + `ref` | local attempt / gap，不声明 observed |
| model provider adapter | provider-neutral turn 的关联结果 | `adapter` | unavailable / blocked，不猜 provider fallback |
| durable episodic / semantic memory | retrieval ref、candidate handoff、availability | `ref` + `adapter` | working-only / retrieval degraded，不声称 durable write |
| `L0-sdk`、Member、Products | future consumer / client surface | 下游消费 | 不反向进入 Runtime package 依赖 |

只有 `L0-core` 是编译期依赖候选。`runtime`、`event`、`ref`、`adapter`、`fake` 均不是 Cargo / package 依赖类型；fake 只用于后续受控语义验证，不证明真实 integration readiness。

### 6.2 禁止依赖

- Runtime 不得加入非 Core sibling 的 Cargo / path / package 依赖。
- Runtime 不得直连外部 MCP / A2A / API registry、provider endpoint、secret、quota、billing。
- Runtime 不得 host fallback、旁路 Sandbox、维护 Governance local allowlist、保存 Method / Artifact / memory 正文。
- Runtime 不得写 Observability backend、member-service / image 生命周期或 SDK client。

## 7. 核心能力闭环

> 校准来源：
> - `design-calibration/00_req_step_07_core_capability_loop.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“核心能力节点”“核心能力闭环图”“进入 / 退出条件与条件路径”小节。

Runtime 的核心闭环由五个能力节点组成：

| 节点 | 能力成立描述 | Runtime owner | 外部 owner 边界 |
|---|---|---|---|
| `C-L2R-1` 受控运行与 goal/plan 工作语境 | 正式触发、主体、目标、约束和终止条件形成可推进 run | run identity / status、goal decomposition、plan working state | Work / Process / Artifact / Method 正文和正式业务状态 |
| `C-L2R-2` Context composition 与 memory mediation | refs、safe snapshots、working memory、episodic / semantic candidates 按来源、scope、时点和预算组合 | context working set、composition decision、working memory、query / candidate / use record | 外部正文、method / policy truth、durable memory body |
| `C-L2R-3` Provider-neutral model decision 与 turn 解释 | 表达 model intent、候选约束、逻辑选择、关联结果和明确失败 | model intent / selection、turn correlation、semantic disposition | Hub registry、provider route / secret / quota / cost、raw billing |
| `C-L2R-4` Tool / sub-agent action orchestration | 选择 no-action、Tool 或 child delegation，承接治理 / 工具 / Sandbox 前置并区分未知副作用 | action choice、orchestration、delegation scope / budget、incorporation decision | Tool outcome、approval、Sandbox run、member/container lifecycle |
| `C-L2R-5` Checkpoint、reflection / recovery 与 outcome handoff | 保存 stable point，支持 pause / resume / recovery / reflection，并安全交接结果 | checkpoint chain、recovery decision、runtime outcome、local handoff attempt / gap | 外部 truth repair、Bus delivery、Observed、Artifact / Evidence / acceptance truth |

```text
[C-L2R-1 Controlled run + goal/plan]
                    |
                    v
[C-L2R-2 Context + memory mediation]
                    |
                    v
[C-L2R-3 Model decision + turn disposition]
                    |
                    v
[C-L2R-4 Tool / sub-agent action orchestration]
                    |
                    v
[C-L2R-5 Checkpoint + reflection/recovery + handoff]
                    |
                    +---- committed continuation ----+
                    |                                |
                    +--------> C-L2R-1 / C-L2R-2 <---+
```

进入与退出约束如下：C1 需正式 trigger、actor / scope、目标语境；C2 需可验证 source；C3 允许 `no_model_action / blocked`；C4 允许 `no_action / waiting / rejected`，但工具行动必须经正式 Tools 合同；C5 在 stable、uncertain 或 terminal boundary 保存最小恢复事实。任一正向 seam 未闭口时，只能进入 blocked / unavailable / waiting 路径。

### 11.2 Snapshot、ref 与 candidate 约束

所有 snapshot 必须带来源、freshness 和 scope，所有 ref 由对应 owner 解析，所有 candidate 保持未提交语义；任一解析失败、stale、conflict 或 owner unknown 都必须显式呈现，不得由 Runtime 生成第二 truth。

### 11.3 禁止保存正文

Runtime 不得持久化或交接 Method / Role / Process body、Governance Decision / Policy body、ToolDefinition / provider raw response / external API body、Sandbox stdout / stderr / file / capture、Artifact / Evidence / report 正文、durable memory body、secret / token / credential / raw headers、hidden chain-of-thought / full private reasoning。正确形态是 typed ref、safe snapshot、normalized outcome summary、redacted marker、decision summary 或 candidate handoff。

## 2. 背景与问题定义

### 2.1 业务背景

runtime 是 AI 成员容器内真正的“大脑”。它负责:
- 思考(LLM loop)
- 组织提示词(prompt composer)
- 管理目标和计划(goal/plan)
- 调用工具(tool invoker)
- 记忆和反思(memory)
- 在每步后 checkpoint

它的任务不是“连接外界”(那是 member),而是**在边界内做出高质量决策与行动**。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `ai-member设计.md` 已详述 C1~C9 | 仓级需求层未显式化 |
| StateGraph | 只在设计里 | 仓级验收口径未落地 |
| 三层记忆 | ADR-0006 已锁 | 仓级边界未显式写成需求 |
| Checkpoint | ADR-0007 已锁 | 运行时何时写 / 如何恢复未进入仓级样板 |
| Sub-Agent | 设计里有 | 何时用 / 隔离边界未成仓级需求 |

### 2.3 为什么要做(量化依据)

- 没有 runtime,整个系统只有门面(member)而没有真正的思考引擎
- README 已给出硬指标:LLM Loop 单步延迟(不含模型调用) < 50ms,checkpoint P95 < 100ms,记忆检索 P95 < 500ms
- capability-hub、sandbox、member、process 都需要和它形成闭环

### 2.4 业务问题 vs 技术问题

- **业务问题**:AI 员工如何在边界内做出正确、可解释、可恢复的行动
- **技术问题**:StateGraph、Prompt 分层、三层记忆、Policy Cache、Checkpoint、Sub-Agent、Tool Guardrails

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 收到 IPC 请求后进入 ReAct 循环
2. 组合 shared_rules → role → policy → context 四层 prompt
3. 查询 working / episodic / semantic 记忆
4. 调工具前后做 Guardrails
5. 每步写 checkpoint,崩溃后恢复
6. 起独立上下文 Sub-Agent 处理局部复杂任务
7. 读取或生成 ImplementationPlan,在执行中更新 plan item 证据
8. 必要时将某个 plan item 升级为 child WorkItem 并回写 work 域正式流程

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |

| 优先级 | P0 |
| 验收条件 | **Given** 一个任务请求 **When** 进入 loop **Then** 状态转移必须符合 StateGraph,不能纯 prompt 自由跳转 |

| 优先级 | P0 |
| 验收条件 | **Given** 冲突规则 **When** 组合 prompt **Then** shared_rules 优先且不可被覆盖 |

| 字段 | 内容 |
|---|---|
| ID | US-003 |

## 6. 功能需求

### 6.1 功能清单与优先级

| ID | 功能名称 | 优先级 | 依赖 | 描述 |
|---|---|---|---|---|
| F-001 | C1 LLM Loop | P0 | member IPC | ReAct + StateGraph |
| F-002 | C2 Prompt Composer | P0 | role/policy/context | 四层 prompt |
| F-003 | C3 Memory Store | P0 | identity / archive / vector store | working / episodic / semantic |
| F-004 | C4 Goal / Plan | P1 | loop | 目标栈 + 步骤 |
| F-005 | C5 Context Manager | P0 | conversation / work / time | 聚合上下文 |
| F-006 | C6 Policy Cache | P0 | governance | 本地规则缓存 |
| F-007 | C7 Checkpoint Store | P0 | ADR-0007 | 每步持久化 |
| F-008 | C8 Sub-Agent Spawner | P1 | member / sandbox | 独立上下文子代理 |
| F-009 | C9 Tool Invoker | P0 | tools / sandbox / capability-hub | Guardrails + Policy + Schema |
| F-010 | reasoning_trace 持久化 | P0 | observability | 42001 可解释性 |
| F-011 | ImplementationPlan 读写 | P1 | work / artifact | 读取或生成当前 WorkItem 的执行路线图 |
| F-012 | PlanItem → child WorkItem promote | P1 | work | 符合协作条件时升级为正式工作项 |

### 6.2 业务规则表

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-001 | shared_rules / role / policy / context 冲突 | shared_rules 优先 |
| BR-002 | 工具调用前不满足 Policy | 拒绝调用 |
| BR-003 | 每步完成 | 写 checkpoint |
| BR-004 | memory 三层 | 不混写 |
| BR-005 | Sub-Agent | 独立上下文,不共享 working memory |
| BR-006 | ImplementationPlan | 不是 WorkItem 真相源,只承载当前执行路线图与 PlanItem 证据 |
| BR-007 | PlanItem 满足协作/依赖/验收/风险条件 | promote 为 child WorkItem,走 work 正式流程 |

```

 ├─▶ Goal/Plan
 ├─▶ Memory Store
```

## 11. 验收标准

### 11.1 功能验收标准

| 功能 ID | 验收场景 | Given-When-Then | 执行方式 |
|---|---|---|---|
| F-001 | StateGraph loop | **Given** 一个目标请求 **When** 进入循环 **Then** 状态转移严格按图,无自由跳步 |
| F-002 | prompt 分层 | **Given** 冲突规则 **When** 组合 prompt **Then** shared_rules 覆盖 role/policy/context |
| F-003 | 三层记忆 | **Given** 一次任务和一段长期历史 **When** 读写记忆 **Then** working / episodic / semantic 不混用 |
| F-007 | checkpoint | **Given** 一步完成 **When** 写 checkpoint **Then** 新记录写入且可恢复 |
| F-009 | tool invoker | **Given** 高危工具调用 **When** pre-check **Then** 未授权时拒绝 |
| F-010 | reasoning trace | **Given** 任意一步推理 **When** 完成 **Then** 产生 trace 记录 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| prompt 层优先级写错 | 中 | 高 | tests + rules snapshot |
| checkpoint 过于频繁 | 中 | 中 | batching / threshold |
| tool invoker 拦截过严 | 中 | 中 | dry-run / telemetry |
| memory provider 变慢 | 中 | 高 | cache / fallback |

### 12.2 边缘风险

- Sub-Agent 泛滥导致上下文爆炸
- vector store 不可用时行为退化难预测
- reasoning trace 量过大带来存储压力

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| LLM routing 是否内建到 runtime | L2 后 | runtime + capability-hub |
| checkpoint 粒度细化 | L2 后 | runtime + process |
| memory 反思式检索策略 | L2 后 | runtime |

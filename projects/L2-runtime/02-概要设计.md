## 3. 约束条件

> 校准来源：
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读：建议继续阅读该中间产物的“约束条件表”“约束到后续章节的作用矩阵”和“历史污染约束”小节，了解每条约束如何限制主体、对象、接口、流程和状态。

| ID | 约束 | 概要设计影响 |
|---|---|---|
| `HLC-L2R-001` | Runtime local truth 单一 owner | Entry、projection、adapter 和 consumer 不得直接写 run / decision / checkpoint / outcome truth |
| `HLC-L2R-002` | 外部 owner 只经 typed boundary | 外部输入必须是 typed ref、safe snapshot、formal result、candidate、availability 或 gap |
| `HLC-L2R-003` | forbidden body 贯穿所有结构 | method / policy / tool / capture / artifact / evidence / memory body、secret、raw response、hidden reasoning 不进入对象 / DTO / checkpoint / event / view |
| `HLC-L2R-004~005` | 只有 Core 是 compile 候选；seam 不伪装 package dependency | Tools / Hub / Method / Governance / Sandbox / Artifact / model / memory 用 runtime / ref / adapter，Bus / Observability 用 event |
| `HLC-L2R-006` | 前置不可验证即 fail closed | missing / stale / conflict / unknown 只能 reject / waiting / blocked / unavailable |
| `HLC-L2R-007` | action choice 与 external execution 分层 | ActionDecision、submission、receipt、executed、outcome、incorporation 不合并 |
| `HLC-L2R-008` | logical model decision 与 provider control 分层 | Runtime 不拥有 endpoint、route、secret、quota、cost、billing 或 physical failover |
| `HLC-L2R-009` | working memory 与 durable memory 分层 | owner pending 时允许 working-only / unavailable，不拥有 durable body / index / retention / deletion |
| `HLC-L2R-010` | history immutable，recovery 形成新决定 | feedback、reflection、resume、retry、recovery 不逆写旧 turn / action / outcome |
| `HLC-L2R-011~012` | stable point 是 checkpoint 前置；unknown side effect 不盲重试 | commit / effect unknown 进入 explicit unknown / block / manual review |
| `HLC-L2R-013` | late / duplicate / out-of-order 不逆写 | 只能 ignored / pending / linked-new-fact |
| `HLC-L2R-014~015` | local outcome first；safe views 只读可重建 | handoff / delivery / observed / acceptance 与 local outcome 分层；stale / gap 可见 |
| `HLC-L2R-016~017` | context / delegation 有 scope / budget；parent / child 不共享 mutable body | child result 经 feedback / incorporation 进入 parent |
| `HLC-L2R-018~019` | 同步 / 异步 / Job 分离；identity / correlation 前置 | Command / Query 即时判断，Event 传播事实，Job 做 continuation / rebuild / reconcile |
| `HLC-L2R-020` | pending contract 只生成 candidate / blocked boundary | 不固定公共 schema、positive adapter、route、receipt、observed 或 readiness |
| `HLC-L2R-021~023` | 配置不改红线；evidence 不伪造；语言未选择 | 配置不能 fail-open；目录 / fake / 文档不是 readiness；类型保持语言中立 |

## 4. 代码主体框架总览

> 校准来源：
> - `design-calibration/02_hld_step_04_code_skeleton.md`
>
> 延伸阅读：建议继续阅读该中间产物的“代码主体总表”“实现分层视图”“主体到主要组成部分映射”和“边界审计”小节，了解业务组成部分与实现分层的不同组织轴。

### 4.1 业务主体框架

```text
L2-runtime
│
├─ Runtime Entry & Control
├─ Run & Goal-Plan
├─ Context & Memory Mediation
├─ Model Decision
├─ Action & Delegation Orchestration
├─ Checkpoint, Recovery & Handoff
├─ External Truth Views
└─ Safe Runtime Views
```

### 4.2 实现分层

```text
External Commands / Queries / Events / Jobs
                │
                ▼
┌─────────────────────────────────┐
│ Inbound / Operations            │
└────────────────┬────────────────┘
                 ▼
┌─────────────────────────────────┐
│ Application Services            │
└────────────────┬────────────────┘
                 ▼
┌─────────────────────────────────┐
│ Domain Model                    │
└────────────────┬────────────────┘
                 ▼
┌─────────────────────────────────┐
│ Ports / Persistence             │
└────────────────┬────────────────┘
                 ▼
┌─────────────────────────────────┐
│ Projection / Handoff            │
└─────────────────────────────────┘
```

业务组成部分按职责和 owner 切分，实现分层按代码协作职责切分；二者不能合并成目录或部署结论。Domain Model 只拥有 Runtime local truth，Ports 只定义边界责任，Projection / Handoff 只从 committed local facts 派生。

| 代码主体 | 类型 | 主要作用 | 边界 |
|---|---|---|---|
| RuntimeCommandAcceptance / RuntimeControlService / RuntimeQueryService | inbound / application | admission、control、safe query | 不拥有 product / principal truth |
| RunCoordinator / ContextCompositionService / ModelDecisionService / ActionOrchestrationService / RecoveryCoordinator | application services | 编排本地对象与 typed seam | 不接管外部 owner truth |
| ControlledRun / GoalPlanWorkspace / decisions / checkpoint / outcome | domain model | Runtime local truth 与不变量 | 不保存 forbidden body |
| RuntimeStateRepositoryPort / external source / model / tools / governance / sandbox / memory ports | ports | 持久化和外部 typed boundary | pending seam 仅 candidate / blocked |
| SafeViewProjectionService / SafeMaterialAssembler / handoff ports | projection / handoff | body-free view、material、attempt / gap | 不反写 domain / external truth |

## 5. 主要组成部分、职责与边界

> 校准来源：
> - `design-calibration/02_hld_step_05_main_parts.md`
>
> 延伸阅读：建议继续阅读该中间产物的“逐部分 capability 与对象发现”“各部分交互总图”“对象发现维度表”和“跨组成部分闭环审计”小节。

| 主要组成部分 | 核心职责 | 主要代码主体 | 不承担什么 |
|---|---|---|---|
| Runtime Entry & Control | 受理 / 拒绝 trigger、control、resume intent 与 safe query | RuntimeCommandAcceptance、RuntimeControlService、RuntimeQueryService | product API / UI、principal truth、member / SDK lifecycle |
| Run & Goal-Plan | controlled run、goal / plan working state 与推进决定 | RunCoordinator、ControlledRun、GoalPlanWorkspace | Work / Process / Method / Artifact 正文与正式业务状态 |
| Context & Memory Mediation | source composition、working context / memory、retrieval candidate 使用 | ContextCompositionService、WorkingContext、WorkingMemory | durable memory body / index / retention |
| Model Decision | provider-neutral intent、turn、disposition 与 safe summary | ModelDecisionService、ModelIntent、ModelDecision、ModelTurn | provider route / secret / quota / cost、raw response、hidden reasoning |
| Action & Delegation Orchestration | action choice、正式前置、Tool / child 编排与 result incorporation | ActionOrchestrationService、ActionDecision、Delegation | Tool execution / audit、approval、Sandbox run、member lifecycle |
| Checkpoint, Recovery & Handoff | stable checkpoint、recovery / reflection、local outcome、attempt / gap | RecoveryCoordinator、RuntimeCheckpoint、RecoveryDecision、RuntimeOutcome、HandoffAttempt | external truth repair、delivery / observed / acceptance truth |
| External Truth Views | 维护带 owner / freshness 的 ref / snapshot / availability | ExternalTruthResolutionService、SourceReference、SourceSnapshot、SourceAvailability | registry / body / policy / artifact / memory source truth |
| Safe Runtime Views | 派生 body-free status / outcome / decision / handoff views | SafeViewProjectionService、SafeMaterialAssembler | Runtime truth mutation、Observability observed / retention truth |

```text
External trigger / control / query
                │
                ▼
[Entry & Control] -> [Run & Goal-Plan] <-> [Context & Memory]
                            │                      ▲
                            ▼                      │
                     [Model Decision] ─────────────┘
                            │
                            ▼
                  [Action & Delegation]
                            │
                            ▼
             [Checkpoint / Recovery / Handoff]
                   │             │
                   ▼             ▼
        [Safe Runtime Views]   local handoff ports
                   ▲
                   │
          [External Truth Views]
```

External Truth Views 是 owner-anchored 消费边界，不是外部 truth 副本；Checkpoint / Recovery / Handoff 横切整条运行历史；Safe Runtime Views 只读、可重建。

## 7. API / 接口骨架

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读：建议继续阅读该中间产物的“通用处理流骨架”“关键处理流覆盖清单”“15 条独立处理流”和“跨处理流一致性审计”小节。

### 8.1 通用写 / 读 / 事件 / Job 路径

```text
Command
  ▼
Inbound: actor / scope / metadata / idempotency
  ▼
Application Service: load local truth + typed external views
  ▼
Domain Object: explicit decision / immutable history
  ▼
Repository commit: committed / blocked / unknown
  ▼
Result + outbound / projection candidate after local commit
```

```text
Query -> Query Boundary -> Safe View / ProjectionState -> safe result / stale / unavailable

Inbound Event -> envelope / identity / ordering -> incorporation -> new local record -> projection / event candidate

Operations Job -> committed history / checkpoint / gap -> new decision or rebuild -> completed / waiting / blocked / degraded / unknown
```

### 8.2 核心运行闭环

```text
AcceptRuntimeTrigger
  │ accepted
  ▼
ControlledRun + GoalPlanWorkspace
  │
  ▼
ComposeWorkingContext
  │ frozen context
  ▼
StartModelTurn -> ModelDecision
  │ propose_action / reflect / recover / stop
  ▼
ActionDecision -> ActionPreconditionDecision
  │ allowed candidate / feedback
  ▼
RunProgressDecision + RuntimeHistoryEntry
  │
  ├─► Prepare / Commit RuntimeCheckpoint
  ├─► RequestRecoveryDecision
  └─► FinalizeRuntimeOutcome -> SafeHandoffMaterial / HandoffAttempt / Gap
```

关键设计点：
- 每一步只使用 Step 6 已定义对象和 Step 7 正式接口；外部 owner 输入必须经 typed seam。
- action choice、guard、dispatch candidate、external feedback、side-effect marker 与 incorporation 分层。
- checkpoint 只有在 stable + committed 可证明时可恢复；unknown effect / commit 进入 block / manual review。
- local outcome 先于 handoff / delivery / observed / acceptance 成立，外围失败不回滚 local fact。

### 8.3 关键异常分支

```text
missing / stale / conflict / unknown source
  └─► waiting / blocked / unavailable

late / duplicate / out-of-order feedback
  └─► ignored or linked-new-fact, never overwrite

commit / side-effect unknown
  └─► unknown fence -> recovery wait / block / manual_review

projection / outbound failure
  └─► stale / degraded / gap, local truth remains committed
```

简单 Query 与只传播已提交 safe fact 的 Outbound Event 复用通用路径；完整函数调用链、事务隔离、错误码、retry 参数和 compensation 留给详细设计。

## 9. 状态定义与状态流转

> 校准来源：
> - `design-calibration/02_hld_step_09_state_machine.md`
>
> 延伸阅读：建议继续阅读该中间产物的“状态定义表”“主状态流转图”“允许 / 禁止迁移清单”和“跨状态一致性审计”小节。

本仓采用多个相互关联但不合并的局部状态集合。`ControlledRun` 承载主运行状态；ModelTurn、Action / Precondition、Checkpoint / Recovery、Outcome / Handoff、Projection / Availability 各自保留状态，外部 execution / approval / observed / acceptance 不并入 Runtime 状态机。

| 状态对象 | 状态集合 | 主线含义 |
|---|---|---|
| RuntimeAdmissionDecision | accepted / rejected / waiting / blocked | accepted 才能创建 run |
| ControlledRun | active / waiting / blocked / cancelled / completed / failed / unknown | Runtime local posture |
| ModelTurn / ModelDisposition | pending / submitted / classified / failed / unknown；propose_action / ask_input / reflect / recover / stop / blocked | classified 后才可进入下一 decision |
| ActionDecision / Precondition | proposed / deferred / blocked / cancelled；allowed / denied / waiting / unknown | allowed 仅允许 dispatch candidate |
| SideEffectMarker | none / requested / completed / failed / unknown / compensated | unknown 建立副作用围栏 |
| RuntimeCheckpoint / RecoveryDecision | preparing / committed / invalid / unknown；resume / restart / wait / block / manual_review | stable + closed fence 才 resume |
| RuntimeOutcome | succeeded / partial / blocked / failed / cancelled / unknown | local outcome，不是 external verdict |
| HandoffAttempt / Gap | candidate / submitted / acknowledged / rejected / unknown；open / closed / blocked / unknown | delivery / acknowledgement 与 outcome 分层 |
| ProjectionState / SourceAvailability | current / stale / rebuilding / degraded / unknown；available / unavailable / pending / stale / unknown | query / guard 显式看见 freshness / gap |

```text
Admission.accepted
  ▼
Run.active
  ├─ missing input / feedback ─► waiting
  ├─ unknown / conflict guard ─► blocked
  ├─ commit / effect unknown ──► unknown
  └─ terminal local decision ──► completed / failed / cancelled

waiting / blocked
  └─ new verified fact + new decision ─► active

unknown
  └─ recovery decision + stable proof ─► wait / block / manual_review / active candidate
```

明确禁止 admission accepted 直接到 completed、unknown 直接到 retry / success、action proposed 直接到 completed、precondition unknown 到 allowed、checkpoint preparing 无提交证明到 stable、handoff acknowledged 反写 outcome、projection stale / degraded 无重建证明到 current，以及 late feedback 覆盖旧 decision / outcome。

状态传播只从 committed local history 派生 SafeRuntimeView、Outbound Event 和 Operations Job；external feedback 只能经 typed consumer 形成新 local record / decision。

## 10. 异常与边界场景轮廓

> 校准来源：
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读：建议继续阅读该中间产物的“异常与边界场景轮廓表”“Unknown side effect 影响图”“Local outcome / handoff gap 影响图”和“组成部分停审”小节。

| 场景 | 应落在哪个部分处理 | 当前概要口径 |
|---|---|---|
| actor / scope / source 缺失、冲突或重复请求结果未知 | Entry & Control | rejected / waiting / blocked；不创建第二 run |
| goal / definition stale、context budget overflow / conflict | Run、Context | 不推进 completed；partial / omission / gap 显式 |
| durable memory unavailable / snapshot partial / unknown | Context、External Truth Views | working-only / degraded / unavailable；不正向使用 |
| model adapter / result unknown 或 late | Model Decision | turn unknown / blocked；新事实不逆写旧 decision |
| action precondition missing / stale / conflict / unknown | Action & Delegation | waiting / denied / unknown；不得 dispatch |
| external ACK 但 execution / receipt unknown | Action、Recovery | SideEffectMarker unknown；block / manual review，禁止盲 retry |
| parent / child scope / budget 越界或 result 未闭合 | Delegation、Run | reject / waiting / blocked；不共享 mutable body |
| checkpoint 依赖未提交或 commit-unknown | Checkpoint、Recovery | preparing / unknown；不宣称 stable / resume |
| local outcome 已成立但 handoff 未提交 / ack unknown | Outcome、Handoff | local truth 保留，gap open / unknown |
| projection stale / rebuilding，Bus / Observability 不可用 | Safe Views、Outbound | stale / degraded / gap；不回滚 local truth |
| forbidden body / secret / raw response 进入输入 | 所有边界 | reject / redact / blocked；不得持久化或 handoff |
| pending contract 被配置强行启用 | 所有相关 flow | 忽略正向企图，保持 candidate / blocked / fail-closed |

```text
External action or checkpoint commit = unknown
  ▼
SideEffectMarker / RuntimeCheckpoint = unknown
  ├─► no ordinary retry or success
  ├─► RecoveryDecision = wait / block / manual_review
  ├─► RuntimeOutcome = unknown / handoff ineligible
  └─► SafeRuntimeView exposes unknown / gap
```

该图只表达异常如何改变主线和状态，不表达错误码、retry 参数、补偿脚本或运维处置。

## 11. 配置影响轮廓

> 校准来源：
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读：建议继续阅读该中间产物的“配置影响轮廓表”“仅间接受配置影响的结构”“禁止配置化边界”和“03 / 04 配置实现契约方向”小节。

| 主要部分 / 接缝 | 是否受配置影响 | 配置影响类型 | 交给详细设计展开 |
|---|---|---|---|
| Entry & Control | 是 | admission / read-scope / idempotency policy profile | validator、profile 注入、生效记录 |
| Run & Goal-Plan | 间接 | progress / continuation policy | policy injection，不改变 owner |
| Context & Memory | 是 | source precedence、budget、working window、candidate availability | composition / freshness policy contract |
| Model Decision / adapter seam | 是，正向 pending | logical selection / capability / availability profile | provider-neutral policy / adapter boundary |
| Action & Delegation | 是 | action policy、scope / budget、guard availability | precondition / scope validator；不得 fail-open |
| Checkpoint / Recovery / Handoff | 是 | checkpoint / recovery / handoff posture | stable / transaction / unknown policy seam |
| External Truth Views / Safe Views | 是或间接 | freshness、redaction、degradation、rebuild cadence | source / projection validator / builder |
| Operations Jobs | 是 | enablement、continuation、rebuild / reconciliation cadence | JobConfig 概念、lease / validation contract |

禁止通过配置改变 Runtime local truth owner、把 unknown guard 变 allowed、把 provider route / secret / cost 纳入 domain、允许 forbidden body、关闭 unknown-side-effect fence、覆盖 immutable history、把 commit-unknown 当 stable、把 delivery / observed 写回 outcome、隐藏 stale / gap、引入非 Core sibling compile dependency，或用 fake / 文档 / 静态目录声明 readiness。

03 详细设计定义 profile / validator / builder / policy injection / JobConfig 等实现契约；04 配置设计再定义具体来源、填写、校验和环境分层。本文不定义 key、默认值、格式、环境变量、secret 名称、挂载或热更新。

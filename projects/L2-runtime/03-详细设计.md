### 1.2 Runtime owned truth

Runtime owns only local runtime truth: `ControlledRun`、`GoalPlanWorkspace`、`WorkingContext`、working-memory window、provider-neutral `ModelIntent/ModelTurn/ModelDecision`、action choice/guard/attempt/effect marker、delegation boundary/result incorporation、checkpoint/recovery/outcome、handoff attempt/gap、history/inbox/outbox/projection/job state.

It consumes but does not own tools execution, capability registry, governance approval, method body, durable memory body/lifecycle, sandbox isolation/cleanup, provider route/secret/quota/cost, observability backend, member/product lifecycle or artifact/evidence body.

### 1.3 Dependency category rules

| 类别 | 允许内容 | 禁止误用 |
|---|---|---|
| `compile` | Core-compatible IDs/refs/traits/errors after exact schema review | 引入 provider SDK、vector store、外部 owner repository |
| `runtime/ref` | typed refs、scope、version、availability view、local adapter trait | 把 runtime ref 当 Cargo/package 依赖 |
| `event` | envelope、inbox/outbox、ordering、receipt、wakeup | 把 event delivery/observed 当 local fact |
| `adapter` | owner-neutral request/receipt/status-only reconcile | 写 owner truth、route/secret、positive readiness |
| `fake` | deterministic finite success-candidate、reject、pending、unavailable、unknown | fake execution、sandbox success、observed/evidence/readiness |

### 5.1 双轴分层与调用方向

Runtime 的实现边界同时使用技术层和业务能力切片。业务能力决定“需要完成什么”，技术层决定“由哪一类代码完成”；能力不得机械映射为 crate，技术层也不得成为无 owner 的共享状态池。

```text
[api / worker / jobs]
        | decode / event / lease
        v
[contracts] -- typed DTO/ref/envelope --> [application]
        |                                      |
        |                                      | one service per operation
        |                                      v
        |                               [loop kernel]
        |                                      |
        |                                      | pure decision input
        v                                      v
 [domain objects] <---- domain methods ---- [application UoW]
        |                                      |
        | local truth                          | injected Ports
        v                                      v
 [history / repositories / projection]   [infra adapters]
                                                |
             event / ref / adapter seams       |
      +------------------+----------------------+------------------+
      |                  |                      |                  |
   L2-tools        governance/capability   model/memory       sandbox/obs
```

关键说明：
- `contracts` 只验证和承载数据；`domain` 只执行同步纯函数；只有 `application` 可以决定 UoW 写集和 Port 调用顺序。
- `loop kernel` 只选择下一个有界 operation，不直接调用 Tools、Model、Sandbox 或 repository。
- `infra` 实现 Port，但不产生业务状态迁移；外部 owner 的结果必须带 source/version/digest 才能进入 domain。
- 任一 `Unknown`、`PendingContract`、`Blocked`、`ManualReview` 都在本地保持负向姿态，不能由 mapper 或 fake 升级。

### 5.3 Loop kernel：Runtime 的唯一推进点

Loop kernel 是跨能力的最小协调模块。它拥有 `LoopActivation`、`LoopStep`、`RuntimeLoopCursor`、`RuntimeWakeup`、`LocalContinuation` 和 `HardYield` 的本地事实，但不拥有各专业能力的业务真相。

#### 5.3.1 Loop kernel 文件与对象

| 文件 | 对象 | 责任 | 依赖 |
|---|---|---|---|
| `domain/loop_kernel.rs` | `RuntimeLoopCoordinator`、`NextOperationPlanner`、`LoopOperationInvoker`、`LoopReplayResolver` | 纯规划、单 operation dispatch、结果映射、replay 分支 | domain enums、typed refs |
| `domain/loop.rs` | `RuntimeLoopCursor`、`LoopSnapshot`、`NextOperationDecision`、`LoopBudgetSnapshot` | 一致性 anchor、下一步决定、预算 | state registry、version binding |
| `domain/wakeup.rs` | `RuntimeWakeup`、`ClaimedWakeupBatch`、`WakeCondition`、`WakeupDisposition` | 防丢唤醒、claim/finish/coalesce/quarantine | event identity、history ref |
| `domain/continuation.rs` | `LocalContinuation`、`HardYield`、`YieldResolution` | 跨调度继续和精确等待 | cursor、fence、reason |
| `application/ports/loop.rs` | `LoopStateRepositoryPort`、`LoopSnapshotReaderPort`、`RuntimeWakeupInboxPort`、`StoredStepResultRepositoryPort`、`LoopLeasePort` | loop local truth 的 I/O seam | `RuntimeUnitOfWorkPort`、lease epoch |
| `application/loop_engine.rs` | `RuntimeLoopApplicationService` | claim activation、T1/T2/T3、结束/恢复 | all capability service traits |
| `infra/loop_state.rs` | repository/UoW implementation and blocked fake | CAS、unique key、epoch fence | selected store remains not_selected |

#### 5.3.2 Loop kernel 的调用约束

```text
ConsumeRuntimeWakeupFlow
  -> StartLoopActivationFlow
  -> LoadConsistentLoopSnapshotFlow
  -> PlanNextOperationFlow
  -> PrepareLoopStepFlow                 (T1)
  -> InvokeLoopOperationFlow             (T2, one service only)
  -> ApplyLoopStepResultFlow             (T3)
       +-> ScheduleLocalContinuationFlow
       +-> PersistHardYieldFlow
       +-> EndLoopActivationFlow
```

| 阶段 | 输入 | 必须写入 | 禁止行为 |
|---|---|---|---|
| wakeup consume | envelope/fact identity/high watermark | inbox disposition、claim binding | claim 即 consume；丢弃未知 event |
| activation start | run ref、lease epoch、budget | one active activation CAS | 把 activation 当 run lifecycle |
| snapshot load | committed heads、versions、cursor | `LoopSnapshot` read marker | sequential best-effort read、projection 当 truth |
| plan | snapshot、control posture、wake conditions、budget | immutable `NextOperationDecision` | 从字符串或外部结果猜 operation |
| T1 prepare | operation identity、typed input、expected versions | active step、reservation、cursor fence | active step 已存在时重新规划 |
| T2 invoke | prepared step | service-owned local facts/result | 一个 step 调多个专业 service |
| T3 apply | typed stored result | step result、cursor、budget、wakeup/yield | 从 current aggregate 重建旧 result |

#### 5.3.3 Loop kernel 不变量

1. 一个 `RunId` 同时最多有一个 `LoopActivationState::Executing`，一个 activation 同时最多有一个 `LoopStepState::Prepared` 或 `Invoking`。
2. `LoopLease.lease_epoch` 只递增不复用；旧 epoch 的 T1/T2/T3 写入统一返回 `StaleLease`。
3. `NextOperationKind` 是封闭枚举；每个 variant 映射一个 service method 或一个显式 `HardYield`，没有 fallback `execute_any`。
4. 若 T2 可能产生外部副作用，必须先在 service 内提交 `ActionSubmissionAttempt`/`SideEffectMarker`/对应 fence；未知结果只能进入 status-only reconcile。
5. `NoProgressGuard` 检查 stored result 是否改变 decision-relevant version/digest 或产生新 committed fact；无变化时只允许 yield/block，禁止 self-wakeup spin。
6. activation budget 是 run budget 的子集；新 activation 不重置 run 累计预算。

| service | `application/services/goal_plan_service.rs` | `initialize`、`evaluate_progress`、`incorporate_fact` | `DefinitionResolverPort`、`SourceResolverPort` | revision/progress/history/wakeup | missing dependency -> Waiting/Blocked；terminal proof explicit |

Goal/plan 的实现顺序是 `workspace shell -> PlanRevision candidate -> graph validation -> CAS activation -> item eligibility -> progress fact incorporation`。Runtime 只能保存结构化 definition ref/view、version、digest、availability 和 safe summary，不保存 method/process body，也不把外部 Work/Product success 映射为 `LocallyVerified`。

### 5.7 CAP-04 Context Composition

| 组件 | 文件 | 精确责任 | 事务/状态 |
|---|---|---|---|
| candidate input | `contracts/command.rs`, `domain/context.rs` | `CandidateQuery`、`ContextBudget`、`SourceSnapshot`、`ContextSegmentRef` | 只读 source/memory refs；SM-15 |
| decision | `domain/context.rs` | `ContextCompositionDecision::decide`：scope -> freshness -> ordering -> budget -> redaction | `Assembling` factory -> SM-04 `Assembled/Rejected/Degraded` |
| context | `domain/context.rs` | `WorkingContext::assemble`、`freeze`、`expire`、`mark_degraded` | context/window/use/history/outbox 一个 UoW；Frozen 不可原地修改 |
| service | `application/services/context_service.rs` | `compose` | `SourceResolverPort`、`MemoryRetrievalPort`、`ContextRepositoryPort` | mandatory gap blocks；optional omission 才可 Partial |
| query | `RuntimeQueryApplicationService::get_working_context` | safe segment refs、digest、redaction、freshness | no UoW、no refresh |

组合必须保存每个 considered candidate 的 `MemoryUseRecord`，并为每个排除项写入明确 `SafeReason`。预算超限不得 silent truncation；stale/unknown mandatory source 不得进入 accepted context；frozen context 的 segments、digest、source versions 和 ordering 永不原地变更。

### 5.8 CAP-05 Working/Episodic/Semantic Memory Mediation

Runtime 只拥有 run-scoped `WorkingMemory` window、entry refs、use/disposition facts 和 compaction decision。`MemoryRetrievalPort` 只能返回 candidate/snapshot/ref/status；durable episodic/semantic body、index、retention、delete、rebuild 和 owner lifecycle 由外部 owner 管理。

| 对象/服务 | 文件 | 关键函数/Port | 约束 |
|---|---|---|---|
| `RetrievalRequest` | `domain/memory.rs` | `validate`、`canonical_digest_input` | query_ref、scope、freshness、cursor、budget typed；无 prompt body |
| `MemoryCandidate` | `domain/memory.rs` | `from_source`、`is_eligible` | source/version/safe_size/ordering；unknown 不可选入 |
| `WorkingMemory` | `domain/memory.rs` | `add`、`begin_compaction`、`apply_compaction`、`freeze`、`mark_degraded` | SM-05；window CAS；旧窗口在 commit unknown 时保持权威 |
| `MemoryUseRecord` | `domain/memory.rs` | `record`、`idempotency_identity` | `run + candidate + decision` 唯一；每个 considered candidate 一条 |
| `CompactWorkingMemoryFlow` | `application/jobs/` | `LeasePort` + `ContextRepositoryPort` + `HistoryRepositoryPort` | explicit retained/removed refs；不能删历史/调用 durable delete |

### 5.9 CAP-06 Provider-neutral Model Decision

Model 模块拆为 `ModelInputBinding`、ephemeral materialization、`ModelIntent`、`ModelTurn`、`ModelSubmission`、`ModelSemanticResult`、`ModelDecision` 和 `SafeDecisionSummary`。`ModelInputBinding` 只持久化 context/material/submission digest、refs、版本和 redaction，不持久化正文；materialization body 只能在调用栈短暂存在。

| 阶段 | 服务/函数 | local write | 外部边界 | unknown 规则 |
|---|---|---|---|---|
| bind | `ModelContextMaterializationService::materialize` + `ModelTurn::start` | binding、intent、pending turn | frozen context read | binding pending/blocked，不调用 provider |
| T1 | `StartModelTurnFlow` | turn/submission candidate/history/outbox/result | `ModelDecisionPort::availability` | no `Ready` adapter state |
| T2 | `ModelDecisionPort::submit` | call-time request only | provider/model owner | same submission identity；timeout -> Unknown |
| classify | `ClassifyModelResultFlow` / event consumer | decision、safe summary、turn classification/history | semantic result ref | raw output/body/hidden reasoning rejected |
| query | `GetModelTurnFlow` | none | no provider call | Pending/Unknown remains visible posture |

`ModelSemanticDisposition` 只能是有限的 `ProposeAction`、`AskForInput`、`Reflect`、`Recover`、`Delegate`、`Stop`、`Blocked`、`Failed`。任何 action/delegation candidate 都只是 ref；治理、capability、Tools、Sandbox guard 必须由 CAP-07/08 独立执行。

### 5.10 CAP-07 Action Orchestration

Action lane 的唯一正向外部 Port 是 `InvocationCallerPort`。Runtime 不直接调用 Sandbox execution 或 handoff Port；若历史调用者仍提供 direct route，只能由 `BlockedCompatibilityAdapter` 返回 `DirectSandboxForbidden`，且零外部调用。

| 子模块 | 对象/函数 | 依赖 | 写入/状态 |
|---|---|---|---|
| proposal | `ActionDecision::propose`、`ActionApplicationService::propose` | model decision、run scope | action/history/result；SM-07 Proposed |
| guard | `ActionPreconditionInputs`、`ActionPreconditionDecision::evaluate` | Governance、Capability、Tools contract、Sandbox requirement ref、SourceResolver | guard/action/history/result；SM-07 Guarded/Blocked |
| attempt | `ActionSubmissionAttempt::record`、`SideEffectMarker::record_attempt` | action guard、InvocationCallerPort | attempt/marker/history/outbox before call；SM-08/31 |
| submit | `ActionApplicationService::submit` | `InvocationCallerPort` exactly once | Submitted/Rejected/Blocked/Unknown posture；never Executed |
| feedback | `FeedbackApplicationService::consume_action` | normalized Tools feedback event | feedback/marker/progress/wakeup; once-only |

Guard `Allowed` 只表示所有 formal views 在 expected versions 下通过；任何 missing/pending/unknown view 均为 Waiting/Blocked/Unknown。`Submitted` 只表示有可归属 submission ref；只有后续 verified Tools feedback/source 才能产生 `FeedbackIncorporated`。

### 5.11 CAP-08 Sub-agent Delegation

`Delegation` 保存 parent/child scope、boundary digest、budget、request/submission/result refs 和一次性 incorporation marker。`ChildRuntimePort` 是唯一 child call seam；Runtime 不拥有 child member/container lifecycle、child image、scheduler 或 product entry。

| Flow | 关键 guard | 写集 | 禁止 |
|---|---|---|---|
| `ProposeDelegationFlow` | child scope 是 parent 子集；depth/budget/context boundary valid | delegation、child admission candidate、history/result | 直接调用 child service |
| `SubmitDelegationCandidateFlow` | parent action guard valid、stable request digest | attempt/fence，然后 one `ChildRuntimePort::create` | 第二 child submit、scope expansion |
| `ConsumeChildResultAvailableFlow` | source/correlation/delegation match | inbox、child result ref、incorporation/history/wakeup | child result 直接 parent terminal |
| `GetDelegationStateFlow` | read visibility、scope containment | none | child/member lookup |

### 5.12 CAP-09 Feedback Incorporation

Feedback record immutable；`FeedbackIncorporationDisposition` 是分类而不是 aggregate state。Consumer 先 reserve `(source_owner,event_id,digest)`，再按 action/submission/marker/order 校验；重复、late、out-of-order、mismatch 只产生 receipt/quarantine/history，不反写旧 marker/outcome。

| 分类 | 触发条件 | 允许写入 | 后续 |
|---|---|---|---|
| `Apply` | source、correlation、sequence、marker version 全匹配 | feedback + marker transition + optional progress/wakeup | next loop step |
| `RecordOnly` | 新事实但不满足 progress guard | feedback/history/inbox | wait/replan |
| `IgnoreDuplicate` | same event/digest 已有 receipt | existing receipt | ACK after known commit |
| `QuarantineLate` | older sequence/version | quarantine/history/inbox | no target mutation |
| `QuarantineOutOfOrder` | predecessor gap | quarantine/history/inbox | await predecessor |
| `BlockMismatch` | target/digest/correlation mismatch | safe rejection/history | manual/owner correction |
| `ManualReview` | ambiguity may hide external effect | unknown fence/recovery fact | status-only reconcile |

### 5.13 CAP-10 Checkpoint & Recovery

Checkpoint 分为 local `Preparing`/`Prepared`/`CommitPending` 与 physical `Committed`/`CommitUnknown`。`Prepared` 永远不等于 stable；`CheckpointCommitPort` 未闭合时只能返回 pending/unknown，并阻止 positive resume qualification。

| 子模块 | 对象/服务 | 读取 | 写入 | 关键禁止 |
|---|---|---|---|---|
| prepare | `StableStateCandidate`、`EffectFenceSummary`、`RuntimeCheckpoint::prepare` | run/workspace/context/history/effect fence | checkpoint/history/result | 不声明 physical stability |
| commit | `CheckpointCommitRequest`、`CommitRuntimeCheckpointFlow` | prepared checkpoint、expected digest/version | status/history/outbox/result | repository return 不等 receipt |
| recovery | `RecoveryInputs`、`RecoveryDecision::decide` | run/checkpoint/effect/source | immutable decision/history/continuation | unknown -> ordinary resume/retry |
| continuation | `RecoveryContinuation::schedule/claim/apply` | lease, checkpoint, fence, versions | continuation state/report | lease loss 继续写 |

### 5.14 CAP-11 Local Outcome

`RuntimeOutcome` 是 Runtime local terminal fact，状态独立于 `ControlledRunState`。`FinalizeRuntimeOutcomeFlow` 必须验证 terminal progress、closed effect fence、result/safe-summary refs 和 expected run version；提交 outcome/run/history/outbox/result 后才能创建 handoff candidate。handoff acknowledgement、observability observed、artifact acceptance 不得改变 outcome。

允许的 `RuntimeOutcomeState`：`Succeeded`、`Partial`、`Blocked`、`Failed`、`Cancelled`、`Unknown`。`Unknown` 需要 fence/ref，不能由 timeout 自动变为 Failed 或 Succeeded。

### 6.1 对象契约总规则

每个对象必须同时声明 owner、生命周期类别、字段来源、可见性、序列化边界、构造函数、变更函数、版本 guard、持久化入口和测试切口。字段来源只允许下列五类：

| 来源 | 含义 | 允许写入 | 例 |
|---|---|---|---|
| `Caller` | canonical DTO/EntryAuthority 明确提供 | request carrier、expected version、scope | `ApplyRuntimeControl.expected_run_version` |
| `Metadata` | envelope/config snapshot/operation metadata | correlation、schema、config ref、lease ref | `CommandMetadata.config_snapshot_ref` |
| `Repository` | 已提交 Runtime local truth 的读取 | aggregate、history head、cursor | `ControlledRun.version` |
| `Derived` | domain pure function 或 application binding 计算 | digest、next disposition、new local ID | `ContextDigest`、`NextOperationDecision` |
| `OwnerView` | 外部 owner typed ref/version/posture | source availability、governance view、submission ref | `CapabilityExposureView` |

`Caller` 不得覆盖 `Repository` 当前版本；`OwnerView` 不得被转写为 Runtime owner truth；`Derived` 不得从字符串、当前 wall clock 或 provider body 推断。所有外部 body、secret、hidden reasoning、artifact/evidence body 和 raw provider response 均为 forbidden field。

#### 6.7.2 Canonical action boundary

The canonical `InvocationCallerPort`, `RuntimeToolInvocationRequest` and `ToolInvocationSubmission` definitions are in §6.8.1 and §6.8.4. This subsection fixes the action semantics and call ordering; it does not introduce a second trait or enum definition.

Runtime 调用顺序固定为 `UoW-1 attempt/marker/history/outbox/reservation -> InvocationCallerPort::submit exactly once -> UoW-2 matching posture`。`Accepted` 只表示 Tools seam 返回了可归属提交姿态；不产生 `Executed`、`CleanupCompleted`、Sandbox `Started` 或业务成功。Runtime 不拥有 Sandbox execution truth；direct route 只能写 `DirectSandboxForbidden` blocked record 且零调用。

2. There is no `save(value)`, last-write-wins update, untyped map, or adapter-owned version counter.
3. Append-only records reject caller-selected sequence numbers; history assigns the next sequence inside the UoW.
4. `NotVisible` is resolved before existence-sensitive reads when the entry authority requires leak-safe behavior.
5. Commit uncertainty returns a typed fence and never a successful result.

> - `projects/L2-runtime/design-calibration/03_ddd_step_09_flows_commands_07_12.md`
> - `projects/L2-runtime/design-calibration/03_ddd_step_09_flows_commands_13_17.md`
> - `projects/L2-runtime/design-calibration/03_ddd_step_09_flows_queries.md`
> - `projects/L2-runtime/design-calibration/03_ddd_step_09_flows_events_jobs.md`
> - `projects/L2-runtime/design-calibration/03_ddd_step_12_errors_recovery.md`
>
> 每条 Flow 都是一个独立实施单元。以下 `UoW-1`、`UoW-2` 不是数据库产品名称，而是逻辑提交窗口；物理事务能力未选定时，正向 qualification 仍由 `L2R-CP-001` 等 blocker 控制。

### 8.1 Mutation Flow common skeleton

```text
EntryAuthority
  -> decode/schema/body-free validation
  -> canonical digest
  -> reservation lookup/reserve
       +-- replay: return exact StoredOperationResult
       +-- digest conflict: stop
  -> declared owner/local reads under scope + expected versions
  -> pure domain constructor/transition
  -> local UoW writes (CAS + append + outbox snapshot)
  -> commit known / commit unknown
  -> [only when specified] external call after local candidate commit
  -> matching local posture UoW
  -> typed result + wakeup/yield/reconcile
```

The handler never loops to another operation. `RuntimeLoopApplicationService` consumes the typed result and chooses the next `NextOperationKind`; an operation that is waiting, blocked, unknown, budget-exhausted or lease-lost returns a `HardYield` or `LocalContinuation` instead of spinning.

### 8.2 Command flows C01~C17

#### 8.2.1 `AcceptRuntimeTriggerFlow` (C01)

**Authority and input.** `RuntimeCommandHandler` accepts only `EntryAuthority::CommandApi`. It validates `CommandMetadata`, `trigger_scope`, non-empty goal refs, source authority and precondition ref scope. The digest preimage contains metadata operation/schema/idempotency key, scope, goal refs, source ref/version and precondition refs; generated IDs and wall-clock values are excluded.

**Processing contract.**

1. `AdmissionApplicationService::accept` opens `UoW-1`, calls `OperationReservationRepositoryPort::reserve`, and branches before any domain mutation.
2. It reads `SourceResolverPort::availability` and each declared `GovernancePreconditionPort::read`. A missing or stale required view is a negative decision, not a guessed acceptance.
3. It calls `RuntimeTriggerContext::create` and `RuntimeAdmissionDecision::decide`. Only `AdmissionDisposition::Accepted` permits `ControlledRun::create`, `GoalPlanWorkspace::create_shell` and initial `PlanRevision` candidate.
4. It appends admission/run/workspace/history and an `O01 RuntimeFactCommitted` snapshot in the same local UoW. `OperationReservationRepositoryPort::complete` stores the typed `AdmissionResult` before commit.
5. A known commit exposes the exact result. A commit-unknown outcome stores a reservation fence and returns `OperationPosture::Unknown`; it cannot return a run-created positive result.

**Write set.** `operation_reservation_record`, admission decision, optional run/workspace/revision, history sequence, outbox snapshot. **External call:** owner reads only; no external mutation. **Replay:** same identity/digest returns the original result and refs; a different digest is `IdempotencyConflict`. **Tests:** negative admission has no run ref; source/governance pending; duplicate replay; digest collision; history/outbox atomicity; commit unknown.

#### 8.2.2 `ApplyRuntimeControlFlow` (C02)

1. Validate control kind, run scope, expected `RunVersion`, optional checkpoint ref and command digest; reserve identity.
2. Load run with `RunRepositoryPort::get_for_update`. For `Resume`, load a physically `Committed` checkpoint and all unresolved effect markers; for `Pause`, `Cancel` and `Stop`, load only the local control guard and effect fence.
3. Call `RuntimeControlIntent::validate_against` and `ControlledRun::apply_control`. `Resume` is rejected when the run is terminal, unknown, manual-review, the checkpoint digest differs, or an effect fence is open.
4. Save run/control history/outbox/result in one UoW with expected run version. No cancellation or cleanup call is made to Tools/Sandbox.
5. On CAS conflict, return `VersionConflict` without retrying the external world. On commit unknown, mark the run `Unknown` only if the local write outcome cannot be determined and create a recovery candidate.

**Result mapping.** `Applied`, `WaitingForCheckpoint`, `Blocked`, `AlreadyTerminal`, `Replayed` are result dispositions; none asserts external cancellation. **Tests:** terminal freeze, resume proof, unknown fence, stale version, idempotent replay.

#### 8.2.3 `EvaluateRunProgressFlow` (C03)

1. Validate run/workspace refs, `DecisionInputs`, cursor and all expected versions; reserve identity.
2. Read a single consistent local anchor: run, workspace, current `PlanRevision`, eligible item page, source/definition safe views and unresolved effect markers. `DefinitionResolverPort` returns refs/views only; Method body is never loaded.
3. Build `DecisionInputs` and call `RunProgressDecision::decide`. The result is one `PlanEvaluationDisposition`: `Ready`, `Partial`, `Waiting`, `Blocked` or `TerminalCandidate`.
4. Apply progress facts with `PlanItemIncorporation::incorporate_once`, update workspace/run CAS and append history, wakeup and outbox in one UoW. `TerminalCandidate` does not finalize outcome.
5. If an item fact is late or has a duplicate identity, append a classification and preserve prior item state. If required definition/source is pending, create `Waiting`/`Blocked` plus a wake condition.

**Tests:** dependency closure, deterministic candidate ordering, same fact replay, stale workspace conflict, missing terminal proof, unknown effect fence, no external completion inference.

#### 8.2.4 `ComposeWorkingContextFlow` (C04)

1. Validate retrieval query ref, mandatory segment refs, budget, policy ref and expected memory-window version; reserve identity.
2. Read the run scope and working window. Call `MemoryRetrievalPort::retrieve` with a bounded cursor, then resolve each candidate's safe snapshot/availability through `SourceResolverPort`.
3. Classify every considered candidate as selected, optional-excluded, stale, duplicate, policy-denied, budget-excluded or pending. Mandatory unsafe or unknown input stops assembly.
4. Call `ContextCompositionDecision::decide`, assemble deterministic ordered `ContextSegment`s and create `WorkingContext`. Freeze only when the request requires a model-ready context and all mandatory sources satisfy freshness.
5. Append one `MemoryUseRecord` for every considered candidate, context/window/history/outbox and typed result in one UoW. A durable memory owner is never written.

`Partial` is valid only for optional exclusions. Commit unknown keeps the previous window authoritative and returns an unusable/unknown context posture. **Tests:** budget overflow, mandatory/optional matrix, candidate ordering, redaction, memory pending, frozen immutability, replay.

#### 8.2.5 `RecordWorkingMemoryFlow` (C05)

1. Validate candidate scope, source version and expected window version; reserve identity.
2. Load `WorkingMemory` with CAS guard and call `MemoryCandidate::is_eligible` followed by `WorkingMemory::add`.
3. Create `MemoryUseRecord` with identity `(run_id, candidate_id, decision_id)` and append history/outbox/result in one UoW.
4. A duplicate use identity returns the existing result. A frozen, compacting, degraded or unavailable window rejects positive insertion. Commit unknown leaves the old window current.

**Tests:** duplicate candidate, stale source, frozen window, CAS conflict, no durable owner write, body-free record.

#### 8.2.6 `StartModelTurnFlow` (C06)

1. Validate intent purpose, logical selection, frozen context ref/digest and expected run version; reserve identity.
2. Read run and `ContextRepositoryPort::get_frozen_context`. Query adapter availability; `PendingContract`, `Blocked` or `Unavailable` creates a blocked turn without calling the adapter.
3. Call `ModelContextMaterializerPort::materialize`, create body-free `ModelInputBinding`, `ModelTurn::start` and a submission candidate. Commit binding/turn/history/outbox in `UoW-1`.
4. Call `ModelDecisionPort::submit(ModelSubmissionRequest)` exactly once using the committed turn/binding identity.
5. In `UoW-2`, match the returned submission identity: `Accepted` -> `Submitted`; rejection -> `Rejected/Failed`; unknown -> `Unknown` with fence. A UoW-2 commit unknown does not infer acceptance.

**Tests:** materialization body never persists, commit-before-call crash, one adapter call, response identity mismatch, unknown no retry, provider-field absence.

#### 8.2.7 `ClassifyModelResultFlow` (C07)

1. Validate turn/result refs, schema, expected turn version and event/request digest; reserve identity.
2. Load the turn and retrieve `ModelSemanticResult` by ref. Validate turn, submission, correlation and body-free schema.
3. Call `ModelTurn::classify` and `ModelDecision::from_semantic_result`, then redact to `SafeDecisionSummary`.
4. Save turn/decision/summary/history/outbox/result atomically. A duplicate semantic result maps to the existing decision; late or mismatched results are durable quarantine facts.

**Tests:** semantic enum mapping, duplicate result, late result, raw body rejection, turn CAS, exact replay.

#### 8.2.8 `ProposeActionFlow` (C08)

1. Validate model decision/run identity, candidate target, canonical intent digest, effect class, scope and action budget; reserve identity.
2. Read the committed `ModelDecision` and require `permits_action_proposal`.
3. Call `ActionDecision::propose`, save action/history/outbox/result in one UoW and return `ActionDecisionState::Proposed`.

This Flow never calls Governance, Capability Hub, Tools or Sandbox and cannot produce `Submitted`, `Completed` or business outcome. **Tests:** model disposition guard, forbidden input body, scope mismatch, supersession, replay.

#### 8.2.9 `EvaluateActionPreconditionsFlow` (C09)

1. Validate action ref, expected action version and typed precondition inputs; reserve identity.
2. Read Governance effective decision, Capability exposure, Tools contract, conditional isolation requirement and source versions independently.
3. Build `ActionPreconditionDecision::evaluate`; every required `PendingContract`, `Unknown`, stale or missing view yields `Waiting`, `Blocked` or `Unknown`, never `Allowed`.
4. Attach guard to action only with unchanged checked versions; save guard/action/history/outbox/result in one UoW.

The guard expires when any checked version changes. **Tests:** each owner view posture, stale guard, formal denial, direct-Sandbox forbidden route, no submit call.

#### 8.2.10 `ProposeDelegationFlow` (C10)

1. Validate parent run/action, child scope containment, immutable context allow-list/exclusion, depth and budgets; reserve identity.
2. Read parent action/context and call `Delegation::create`; optionally create a child admission candidate.
3. Commit delegation, candidate, history/outbox/result before any child call. The next operation may submit through `ChildRuntimePort`, but this Flow does not.

**Tests:** scope escape, mutable boundary rejection, depth/budget expansion, parent/child identity, no member/container lifecycle fields, replay.

#### 8.2.11 `IncorporateActionFeedbackFlow` (C11)

1. Validate `EventEnvelope<ActionFeedbackReceived>` source owner, digest, ordering and action/marker/submission identity; reserve inbox and operation identity.
2. Load marker/action and latest ordering anchor. Existing event ID+digest returns a duplicate receipt; event ID with another digest becomes a collision quarantine.
3. Call `ActionFeedbackRecord::incorporate` and `FeedbackIncorporationDecision::decide`. Only `Apply` can transition the marker; late/out-of-order/mismatch are record-only or quarantine.
4. Optionally create a new progress/wakeup fact when the decision permits it; never overwrite an outcome.
5. Commit inbox receipt, feedback, marker/progress, history/outbox and typed result together, then ACK the source event.

**Tests:** source validation, sequence ordering, duplicate/collision, marker transition matrix, unknown effect fence, ACK-after-commit.

#### 8.2.12 `PrepareRuntimeCheckpointFlow` (C12)

1. Validate run, candidate anchor, state digest and effect-fence summary; reserve identity.
2. Read run/workspace/memory/context/history heads and unresolved markers under one `ExpectedVersionSet`.
3. Call `StableStateCandidate::permits_prepare` and `RuntimeCheckpoint::prepare`; save `Preparing -> Prepared`, history/outbox/result locally.
4. Never call the physical commit Port and never label `Prepared` as stable/resumable.

**Tests:** inconsistent anchor, unresolved effect, history sequence, digest mismatch, local commit unknown, prepared-vs-committed distinction.

#### 8.2.13 `CommitRuntimeCheckpointFlow` (C13)

1. Validate prepared checkpoint, request digest and expected checkpoint version; reserve identity.
2. Mark local checkpoint `CommitPending` with fixed request digest, then call `CheckpointCommitPort::commit` under `L2R-CP-001`.
3. Match receipt ID/digest: only a proven matching receipt transitions to `Committed`; rejection transitions to `Invalid`/`Blocked`; unknown transitions to `CommitUnknown` with fence.
4. Persist status/history/result; emit an outbox event only for proven committed status. Reconciliation uses the same checkpoint/request identity.

**Tests:** receipt mismatch, physical pending, commit unknown, no resume from unknown, same-request reconcile, duplicate replay.

#### 8.2.14 `RequestRecoveryDecisionFlow` (C14)

1. Validate trigger, requested mode, checkpoint/effect refs and expected versions; reserve identity.
2. Read run, checkpoint, effect fence, source availability and prior recovery decisions.
3. Call `RecoveryDecision::decide`. `Resume` and `RestartFromStable` require committed checkpoint and closed fence; `ReconcileOnly`, `WaitForFact`, `Blocked` and `ManualReview` are explicit alternatives.
4. Append immutable decision/history/outbox/result. Schedule a `LocalContinuation` only for a locally eligible disposition.

**Tests:** each disposition, no stable point, unknown effect, lease loss, immutable decision, no blind external retry.

#### 8.2.15 `FinalizeRuntimeOutcomeFlow` (C15)

1. Validate terminal progress ref, requested `RuntimeOutcomeState`, result/safe-summary refs, fence and expected run version; reserve identity.
2. Read run/workspace/progress and all unresolved effect markers.
3. Require terminal proof and closed fence for `Succeeded` or `Partial`; map unresolved uncertainty to `Blocked`, `Failed`, `Unknown` or manual review according to policy.
4. Call `RuntimeOutcome::finalize`, update run to `Terminal`, append outcome/history/outbox/result in one UoW.
5. Handoff is a later operation; no downstream acknowledgement can mutate the outcome.

**Tests:** nonterminal rejection, one outcome per run, unknown fence, terminal freeze, local-first ordering, replay.

#### 8.2.16 `CreateHandoffCandidateFlow` (C16)

1. Validate committed outcome, safe result/summary refs, target scope, redaction profile and material digest; reserve identity.
2. Build `SafeHandoffMaterial`, `HandoffAttempt` and optional `HandoffGap`. Pending route/producer is represented as a local gap.
3. Save material/attempt/gap/history/outbox/result in one UoW. Submission is a later `SubmitHandoffCandidate` internal operation through `HandoffSubmissionPort`.

**Tests:** forbidden body, outcome absence, redaction, target mismatch, gap retention, no delivery/acceptance claim.

#### 8.2.17 `CaptureSourceSnapshotFlow` (C17)

1. Validate source owner/scope/freshness and expected source version; reserve identity.
2. Call `SourceResolverPort::resolve`; map complete/partial/metadata-only/rejected/unknown to `SourceSnapshot` and `SourceAvailability` without copying owner body.
3. Save snapshot metadata, marker/history/outbox/result atomically. Pending/stale/unknown stays negative.

**Tests:** authority mismatch, stale version, forbidden body, partial marker, duplicate source identity, commit unknown.

### 8.3 Query flows Q01~Q12

Queries do not reserve mutation identity, begin a UoW, refresh an owner, advance a cursor, or invoke an external side effect. Each handler first applies `ReadVisibilityPort`, then reads only its declared local repository/projection surface.

#### 8.3.1 `GetRunStatusFlow` (Q01)

`RuntimeQueryHandler -> QueryMetadata::validate -> visibility(run) -> RunRepositoryPort::get -> HistoryRepositoryPort::head -> RunStatusView`. Missing after visibility maps to `NotFound`; hidden maps to `NotVisible`; repository unknown maps to `FreshnessClaim::Unknown`. No write or reconcile.

#### 8.3.2 `GetRunHistoryFlow` (Q02)

Validate cursor/filter/limit, check run visibility, call `HistoryRepositoryPort::list_by_run`, redact each fact to `HistoryItemView`, and return the repository-owned next cursor/watermark. Invalid cursor is `CursorConflict`; no append or projection rebuild.

#### 8.3.3 `GetGoalPlanFlow` (Q03)

Check run/workspace containment, read workspace/revision/item refs, map local progress and `PlanEvaluationDisposition`, and return source versions. Method/Role/Process bodies are never resolved. Cross-run refs are `NotVisible`/`ProtocolMismatch`.

#### 8.3.4 `GetWorkingContextFlow` (Q04)

Check context visibility, read immutable context/projection, verify digest and segment ordering, map safe fragment refs/redaction and state. Expired/degraded context remains visible as such; no source refresh or model materialization.

#### 8.3.5 `GetMemoryUseFlow` (Q05)

Check run visibility, read local memory-use page by cursor/limit, map candidate/source/decision/context refs and use disposition. Durable memory owner body is not queried.

#### 8.3.6 `GetModelTurnFlow` (Q06)

Check turn visibility, read turn and optional decision summary, map binding/submission/result refs and `ModelTurnState`. Provider adapters and raw model material are never called.

#### 8.3.7 `GetActionStateFlow` (Q07)

Check action visibility, read action/guard/attempt/marker/feedback headers, map each owner-separated state and version. Missing marker is legal for a proposed action; no execution inference is allowed.

#### 8.3.8 `GetDelegationStateFlow` (Q08)

Check delegation and child scope containment, read delegation/boundary/result refs, map local state and version. No child runtime/member lookup is performed.

#### 8.3.9 `GetCheckpointStateFlow` (Q09)

Check run visibility, load explicit checkpoint or latest local checkpoint, map `Prepared`, `CommitPending`, `CommitUnknown`, `Committed` distinctly. Do not call `CheckpointCommitPort::reconcile`.

#### 8.3.10 `GetRuntimeOutcomeFlow` (Q10)

Check run visibility, read local outcome by run, map optional state/result/safe-summary refs and fence. No handoff, artifact or observation owner call.

#### 8.3.11 `GetHandoffStateFlow` (Q11)

Require an attempt or gap ref, check visibility, read local material/attempt/gap and acknowledgement ref, and return open/unknown gap explicitly. ACK is not acceptance.

#### 8.3.12 `GetProjectionStateFlow` (Q12)

Check projection visibility and call `ProjectionStorePort::read`. Return `Empty`, `Current`, `Stale`, `Rebuilding`, `Degraded` or `Unknown` from the projection store; never synthesize a current view from domain tables.

### 8.4 Inbound event flows E01~E06

#### 8.4.1 `ConsumeModelResultAvailableFlow` (E01)

Decode `EventEnvelope`, validate source/schema/digest/order, reserve inbox identity, load turn by submission, and classify the semantic result. A duplicate returns its stored `EventReceipt`; late/out-of-order/mismatch creates a quarantine receipt; a known commit is required before ACK. Unknown commit leaves the inbox receipt unresolved and schedules reconcile.

#### 8.4.2 `ConsumeActionFeedbackReceivedFlow` (E02)

Accept only normalized Tools feedback source, reserve inbox, load marker/order anchor, classify feedback, append immutable record, conditionally transition marker/progress, commit receipt/history/outbox and ACK. Raw Sandbox events, mismatched IDs and unknown effects never mutate the marker positively.

#### 8.4.3 `ConsumeChildResultAvailableFlow` (E03)

Validate delegation/child scope/correlation, reserve inbox, enforce once-only result identity, call `Delegation::incorporate_once`, append parent history/outbox and receipt, then ACK. Child disposition does not finalize parent.

#### 8.4.4 `ConsumeSourceSnapshotChangedFlow` (E04)

Validate owner/version/order, reserve inbox, compare source marker version, classify duplicate/late/conflict, append a newer availability/snapshot ref and stale facts where applicable, commit receipt, then ACK. No owner body copy.

#### 8.4.5 `ConsumeGovernancePreconditionChangedFlow` (E05)

Validate formal decision/policy scope and effective version, reserve inbox, import a read-only Governance view, append a new local block/progress fact for affected actions/runs, commit receipt/history/outbox and ACK. It cannot create approval truth.

#### 8.4.6 `ConsumeHandoffAcknowledgementReceivedFlow` (E06)

Validate attempt/ack/source identity, reserve inbox, load attempt/gap CAS, close only the matching gap with a verified acknowledgement, append reconciliation/history/outbox and receipt, then ACK. Local outcome stays unchanged.

### 8.5 Outbound materialization flows O01~O06

#### 8.5.1 `MaterializeRuntimeFactCommittedFlow` (O01)

Inside the producing local UoW, map the committed fact ref/kind/run/version/correlation/safe refs to an immutable outbox snapshot, compute event ID/digest, and append it before commit. Publisher delivery is later and independent.

#### 8.5.2 `MaterializeRuntimeDecisionCommittedFlow` (O02)

Map the immutable decision ref/kind/disposition/source refs/version to an outbox snapshot in the decision UoW. Governance approval and action authorization fields are rejected by schema validation.

#### 8.5.3 `MaterializeActionSubmissionAttemptedFlow` (O03)

Map local action/attempt/marker/target and `OperationPosture` after attempt/marker commit. `Executed` or cleanup-complete is not representable.

#### 8.5.4 `MaterializeRuntimeOutcomeCommittedFlow` (O04)

Map the immutable local outcome and safe refs after outcome commit. Delivery, acceptance, observed and product-completion fields are absent.

#### 8.5.5 `MaterializeHandoffAttemptedFlow` (O05)

Map material/attempt/digest/local state/optional gap after candidate or submission posture commit. A gap may be emitted; event name does not mean delivery.

#### 8.5.6 `MaterializeProjectionMarkedStaleFlow` (O06)

Map projection ID, source run version, history sequence and safe reason when a committed fact invalidates a derived view. It never writes domain truth or claims rebuild.

### 8.6 Operations job flows J01~J07

Every job claims `(operation, partition, lease_epoch, cursor)` before reading a page. Page item changes, report and next cursor commit together; lease loss, page conflict or commit unknown stops the runner and preserves the last committed cursor.

#### 8.6.1 `RebuildSafeRuntimeViewsFlow` (J01)

Claim projection lease, load/restart rebuild ID and cursor, read contiguous history page, map safe views, write page under projection CAS, append `JobPageReport`, and advance cursor. A history gap yields degraded projection/gap ref; no domain write.

#### 8.6.2 `RefreshSourceSnapshotsFlow` (J02)

Claim source partition, page source refs, call `SourceResolverPort::refresh` with expected versions, record each availability/snapshot marker, mark dependent contexts/projections stale, commit page/report/cursor, and release lease. Pending/stale/unknown remains explicit.

#### 8.6.3 `CompactWorkingMemoryFlow` (J03)

Claim run/window lease, load expected window, create `CompactionDecision`, apply a complete partition, save new window/history/report/cursor. Commit unknown keeps the old window authoritative; no durable delete or retention call.

#### 8.6.4 `ResumeEligibleRunsFlow` (J04)

Claim recovery partition, page candidates, reload each run/checkpoint/fence, create immutable recovery decision, and schedule only locally eligible continuation. Unknown/manual candidates are isolated; no external submit.

#### 8.6.5 `ReconcileUnknownEffectsFlow` (J05)

Claim effect/checkpoint partitions, page unknown markers, query status-only owner Ports using the same identity, record verified feedback/checkpoint receipt or retain unknown, and commit report/cursor. It never issues a second side effect.

#### 8.6.6 `ReconcileHandoffGapsFlow` (J06)

Claim gap partition, page open/unknown gaps, query matching acknowledgement/status, close only with a verified matching ref, and commit reconciliation/report/cursor. Missing status leaves the gap open.

#### 8.6.7 `PublishRuntimeOutboxFlow` (J07)

Claim outbox partition, read exact immutable snapshots in cursor order, call publisher, record known/rejected/unknown receipt, and advance cursor only according to the job policy. Unknown keeps the same event ID/payload digest pending; payload is never regenerated.

### 9.1 Four-axis rule

| Axis | Owner | Persistence | Meaning | Example |
|---|---|---:|---|---|
| `FactoryPhase` | object construction | optional audit marker | object 尚未成为 aggregate | `Assembling` |
| `DomainState` | Runtime-owned mutable object | yes, CAS version | 可由 domain method 产生的本地 truth | `ControlledRunState::Waiting` |
| `Disposition` | immutable decision/result/classification | append-only/result | 对一次判断或事实的分类 | `PlanEvaluationDisposition::Partial` |
| `Posture` | operation/adapter/lease/owner observation | safe ref/summary | 外部或操作边界观察，不创造 owner truth | `OperationPosture::Unknown` |

`Ready` 不是任何 adapter/source/sandbox/observability canonical state；`Completed` 只可用于明确的 continuation/job page 操作状态。`Unknown`、`PendingContract`、`Blocked`、`ManualReview` 都是负向姿态，只有匹配的事实、reconcile 或显式 recovery 才能关闭。

| SM-22 Binding | candidate -> bound | context/material/submission digest/version match | binding metadata/history | content field or missing binding |
| SM-22 Binding | candidate/bound -> blocked/unknown/released/expired | redaction/authority uncertainty; call scope end; TTL | reason/fence/release marker | released == provider success; reuse expired |
| SM-23 Materialization | resolving -> resolved | mandatory fragments resolved, digest built | ephemeral envelope only | durable body/log/event |
| SM-23 Materialization | resolving -> degraded/pending/rejected/unknown; resolved -> released/expired | optional omission, owner gap, unsafe input, deadline | bounded marker/reason | pending -> model call; released == execution |
| SM-24 Reflection | factory -> recorded -> applied | trigger/fact anchor, explicit local action | reflection/proposal/history | hidden reasoning/direct activation |
| SM-24 Reflection | recorded -> blocked/manual/superseded | stale/unknown fence or newer decision | reason/fence/successor/history | mutate old decision |
| SM-25 Wakeup | pending -> claimed -> consumed-for-step | inbox dedupe + run lease + T3 anchor | wakeup/inbox/step/history | claim == consume |
| SM-25 Wakeup | claimed -> coalesced/observed-no-resume/run-terminal/quarantined | duplicate/no eligible op/terminal/mismatch | disposition/receipt/history | unknown event dropped |
| SM-26 Activation | claimed -> executing -> yielded/completed | one live run lease, bounded budget | activation/lease/step | two active activations; run lifecycle merge |
| SM-26 Activation | executing -> lease-lost/unknown | lease expiry or commit ambiguity | fence/history | continue after lease loss |
| SM-27 Step | prepared -> invoking -> applied | T1 reservation then one service call then T3 result | step/cursor/result/history | two services in one step; current-state rebuild |
| SM-27 Step | invoking -> yielded/reconciliation-required/unknown | wait/block/external or commit ambiguity | yield/fence/reconcile | unknown treated success |
| SM-28 Continuation | pending -> claimed -> consumed | eligible time + lease + cursor match | continuation/lease/history | continuation grants external retry |
| SM-28 Continuation | pending/claimed -> stale-noop/quarantined | superseded cursor or invalid source | disposition/history | mutate current cursor backward |
| SM-29 HardYield | open -> resolved/superseded/quarantined | matching wake fact, replacement decision or invalid source | yield resolution/history | self-wakeup spin |
| SM-30 Reservation | reserved -> result-stored | typed result committed with same digest | reservation/result | result without local commit |
| SM-30 Reservation | reserved -> reconciliation-required -> released | commit/external ambiguity then explicit reconcile/retention | fence/reconcile/expiry marker | expiry permits duplicate domain fact |
| SM-31 Attempt | factory -> recorded -> submitted | local attempt UoW then matching `InvocationCallerPort` result | attempt/marker/history/outbox | external call before record |
| SM-31 Attempt | recorded -> rejected/blocked/unknown | deterministic owner response or ambiguity | reason/fence/history | `Executed`, cleanup, Sandbox success variants |

### 9.6 State-machine closure rules

1. Every transition increments the subject's typed version and appends a history fact; derived projections may lag but cannot authorize a transition.
2. `CAS` includes expected version, scope, lease epoch where applicable, state/digest anchor and operation identity. A stale writer returns `VersionConflict` and does not merge.
3. Every `Unknown` transition creates a fence or reconciliation reference. No ordinary retry, timeout heuristic or fake response can close it.
4. Query mappers expose the state subject and its version; they never substitute a disposition or posture for a domain state.
5. `SM-01~SM-31` each map to at least one object, Flow, persistence record and test module; no global “state manager” may bypass the owner method.

### 10.2 UoW and external side-effect ordering

| Operation family | Local-before-call set | External call | Post-call set | Unknown posture |
|---|---|---|---|---|
| model turn | binding/turn/submission candidate/history/outbox/reservation | `ModelDecisionPort::submit` | matching turn/binding posture | turn/binding fence; status-only reconcile |
| action invocation | attempt/marker/history/outbox/reservation | `InvocationCallerPort::submit` exactly once | matching attempt/marker posture | effect fence; no retry |
| child delegation | delegation submission candidate/history | `ChildRuntimePort::create` | child submission/acceptance | delegation unknown; lookup same identity |
| checkpoint | `CommitPending` request/history | `CheckpointCommitPort::commit` | committed/unknown status | CP-001 reconcile; no resume |
| handoff | attempt/gap/material/history | `HandoffSubmissionPort::submit` | attempt/ack/gap posture | same attempt reconcile |
| outbox publish | immutable outbox entry already committed | publisher | publish receipt marker | republish exact payload |

The local UoW and external call are never represented as one distributed transaction in Runtime. If the physical store cannot provide the required atomic local set, the profile remains blocked.

### 10.3 Consistency and crash rules

| Crash/failure point | Durable fact | Next safe operation | Forbidden operation |
|---|---|---|---|
| reservation commit unknown before effect | reservation fence | load/reconcile same identity | external call |
| UoW-1 committed, process dies before effect | candidate/attempt/binding | resume same step under lease | new key/candidate |
| external call unknown | attempt/submission fence | status-only reconcile | second submit |
| UoW-2 commit unknown | external identity + local fence | reconcile local commit and owner status separately | infer acceptance |
| inbox duplicate/late/collision | receipt/quarantine | replay receipt or await predecessor | target reverse-write |
| lease loss | lease epoch/fence | stop and reload cursor | stale write |
| job page commit unknown | prior cursor + page digest | replay exact page | skip cursor |

### 10.4 Persistence gate

Physical database, isolation level, broker and checkpoint serialization are not selected. `L2R-CP-001`, `L2R-UP-006` and `L2R-IMPL-001` therefore block positive implementation qualification; this chapter specifies logical CAS, append, unique-key and local-first guarantees only.

### 11.2 Deterministic mapping and recovery actions

| Layer condition | Public code/posture | Recovery action | Forbidden action |
|---|---|---|---|
| invalid field/schema/digest/body | `InvalidRequest` / rejected | caller correction | retry unchanged |
| scope/visibility denied | `NotVisible`/`Blocked` | policy/source change | existence leak |
| missing aggregate after visibility | `NotFound` | read retry only | mutation from absent |
| version/CAS conflict | `Conflict` | reload and new identity before effect | LWW merge |
| pending owner contract | `Waiting`/`Blocked` | wait/block | fake readiness |
| stale/unavailable owner view | `Waiting`/`Degraded` | refresh same ref/version | promote stale |
| deterministic owner rejection | `Blocked` | record refusal/new decision | retry same effect blindly |
| external call may have happened | `Unknown` | status-only reconcile/manual review | ordinary retry |
| local commit known failure | `InternalFailure`/failed | bounded local retry if no effect | claim committed |
| local commit unknown | `Unknown` | reservation/aggregate reconcile | second effect |
| stored result missing/corrupt | `Unknown`/manual | reservation metadata audit | re-execute command |
| late/order/mismatch event | `Degraded`/quarantined | await predecessor/owner correction | reverse write |
| lease loss/cursor conflict | `Conflict`/blocked | stop; next owner reloads | stale page commit |

Recovery action vocabulary is finite: `ReturnReplay`, `RetryLocalBeforeEffect`, `WaitForFact`, `BlockFailClosed`, `QuarantineEvent`, `ReconcileStatusOnly`, `ManualReview`, `RebuildProjection`. A service must select one explicitly; “retry” without a phase is invalid.

### 11.3 State-specific recovery

| State/posture | Safe action | Required new fact | Forbidden |
|---|---|---|---|
| run Waiting/Blocked | wait or evaluate after new verified input | new progress/recovery decision | direct Active write |
| run Unknown/ManualReview | reconcile/manual only | matching effect/commit fact | ordinary resume |
| context Expired/Degraded | new composition/context identity | source/freshness fact | mutate frozen context |
| model Unknown | status reconcile same submission | result/owner status | new submit without proof |
| action/marker Unknown | status/feedback reconcile | normalized owner fact | retry action |
| checkpoint CommitUnknown | same request reconcile | matching commit receipt | resume/new commit key |
| outcome Unknown | recovery/terminal decision | closed fence/proof | promote success |
| handoff open/unknown gap | same attempt status/ack reconcile | matching ack | self-close/new payload by default |
| projection stale/unknown | history rebuild | contiguous cursor | domain repair from projection |

### 11.4 Public error and recovery test anchors

`TC-ERR-01` validates body-free mapping; `TC-ERR-02` distinguishes known failure from unknown; `TC-ERR-03` rejects retry after external call; `TC-ERR-04` preserves unknown fence; `TC-ERR-05` quarantines event collision/late; `TC-ERR-06` stops stale lease/page; `TC-ERR-07` refuses corrupt stored-result re-execution.

## 12. Concurrency, idempotency and re-entry protection

> 校准来源：
> - `projects/L2-runtime/design-calibration/03_ddd_step_13_concurrency_idempotency.md`
> - `projects/L2-runtime/design-calibration/03_ddd_step_11_persistence_consistency.md`

### 12.1 Identity and replay matrix

| Surface | Identity | Digest input | Replay behavior |
|---|---|---|---|
| C01~C17 command | operation + authority + scope + actor + idempotency key + request digest | all body-free semantic fields and expected versions | exact typed stored result; different digest conflict |
| Q01~Q12 query | request/read scope + query cursor | query fields; no mutation reservation | no stored mutation result; observed query envelope only |
| E01~E06 inbound | source owner + event ID + payload digest | envelope identity/order/schema/payload refs | existing receipt; collision quarantine |
| O01~O06 outbound | outbox/event ID + payload digest | commit-time snapshot | exact snapshot republish |
| J01~J07 job page | operation + partition + lease epoch + input cursor + page digest | page inputs and item identity | replay exact page; cursor advances once |

### 12.2 Aggregate CAS and merge rules

| Aggregate | Guard | Concurrent operations protected | Merge |
|---|---|---|---|
| run/workspace/revision/item | typed version + history anchor | progress/control/recovery/plan | no implicit merge |
| context/window | context/window version | compose/freeze/compact | frozen immutable |
| model turn/binding | turn/binding version + digest | submit/classify/reconcile | duplicate same result only |
| action/marker/attempt | action/marker/attempt version + guard versions | guard/submit/feedback | no different external fact merge |
| delegation/feedback | delegation version + event ordering | child/result/incorporation | once-only |
| checkpoint/outcome/handoff | typed version + state digest | commit/finalize/ack | matching receipt only |
| projection/job | version + cursor + lease epoch | page/rebuild/publish | exact page replay |

All writes fail on stale version; there is no last-write-wins domain update. A retry is permitted only before any possible external effect or as status-only reconciliation with the same identity.

### 12.3 External re-entry and lease fencing

| Seam | Local fence before call | Same identity for reconcile | Retry policy |
|---|---|---|---|
| model | binding/turn candidate | turn + material/request digest | status reconcile; no blind submit |
| Tools action | attempt/marker | canonical intent/correlation | no second submit |
| child | delegation candidate | delegation/request digest | child lookup |
| checkpoint | `CommitPending` | checkpoint/request digest | same commit reconcile |
| handoff | attempt/gap/material digest | attempt/material digest | status/ack only |
| publisher | immutable outbox snapshot | event ID/payload digest | exact republish |

Every lease claim returns a monotonic fencing epoch. `LoopActivation`, `LoopStep`, `LocalContinuation` and every Job page write must validate the live epoch and expected cursor; lease loss stops the actor immediately.

### 12.4 Retention and uniqueness

Idempotency retention values belong to §13/04, but cleanup must preserve permanent uniqueness for run, outcome, checkpoint, action attempt, delegation and event identity. Expiry cannot permit a duplicate domain fact or change a previously stored digest.

### 14.3 State-transition audit and redaction

Every `SM-01~SM-31` transition records subject ref, from/to typed variant, expected/new version, operation identity, causation/history ref, safe reason and relevant source/fence refs. Special redaction rules are:

- plan and method objects store definition refs, never Method/Role/Process body;
- context and model objects store safe fragment refs, digests and redaction markers, never assembled body;
- action objects store canonical intent ref/digest, never execution payload;
- model objects store semantic result refs, never provider response or route;
- checkpoints/outcomes/handoffs store stable refs and digests, never artifact/evidence body;
- adapter and job records store slot/lease/cursor posture, never endpoint, secret or scheduler lifecycle.

If an observation adapter is pending or unavailable, the local candidate/outbox remains pending or gapped. An observation receipt is not `observed`, and an audit candidate is not evidence or an acceptance verdict.

### 14.4 Semantic telemetry binding

Implementation may expose bounded counters/timers for operation disposition, local transaction result, external seam posture, consumer disposition, job page result, state transition and open unknown/gap counts. Labels are operation/phase/profile/owner class/posture only; actor IDs, run IDs, prompt/body, endpoint, provider product, cost and full refs are forbidden metric labels. Concrete backend and syntax are unselected.

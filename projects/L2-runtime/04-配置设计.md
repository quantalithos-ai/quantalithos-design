#### 配置加载流程图：raw source 到 typed runtime

```text
[entry source selector + optional profile assertion]
                         |
                         v
                [one strict JSON]
                         |
                         v
 [infra::config load / parse / validate / assemble]
                         |
                         v
           [RuntimeConfigSnapshot candidate]
                         |
                         v
 [RuntimeBuilder + injected dependency compatibility]
                         |
          +----------------+----------------+
          |                |                |
       Invalid      required-path       compatible
          |            Blocked             Bound
          |                |                |
   no exposure       no entry facade    publish once
                                           |
                                           v
                         optional Blocked path may expose
                         an explicit negative-only facade
```

关键说明：

- 只有 `infra::config` 可读取 raw source；domain/application/repository/job 不读取 file/env。
- `Bound` 只表示配置与注入依赖可装配，不是 operational/qualified/Ready。
- Required path 为 Blocked 时 builder 返回 Blocked 且不暴露 entry facade；optional path 为 Blocked 时，只有既有 entry contract 明确允许该路径返回有限负向结果，整体 composition 才可为 Bound，并在已发布 facade 中保留该路径的 negative-only facade。
- builder/adapter constructor 不得通过网络调用或 ping 制造 availability。
- P0 每个进程只发布一次 snapshot；operation 捕获后不读取可变 current policy。

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_precedence.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“SOP 问题回答”“来源类别”“来源优先级和冲突规则”及“十二配置域来源矩阵”。

P0 不存在 leaf-value precedence chain。配置内容只来自一份 selected strict JSON；source selector 在 load 前选择该 document，可选 entry assertion 只与 document 的 `profile.entry_profile` 做相等校验。static-derived values 在 typed assembly 阶段补齐，既不是 default，也不能被覆盖。

#### 配置来源链图：单文档选择与装配

```text
[runtime_config_source selector]
              |
              v
    [one strict JSON document] <---- [optional entry assertion]
              |                              |
              |                      equality check only
              v
 [strict parse + exact validation]
              |
              v
 [add 39 static-derived semantics]
              |
              v
 [one RuntimeConfigSnapshot candidate]
```

关键说明：

- zero/multiple selected documents 均失败；P0 不 merge。
- selector/locator raw value 不进入 snapshot、log 或 audit。
- assertion 缺失可继续；存在但不相等则拒绝，不能改写 document。
- operation input 不是配置源，只能在 typed upper bound 内收窄。

| ID | Source | Content authority | Relation | Failure |
|---|---|---|---|---|
| SRC-01 | entry-supplied `runtime_config_source` | locator identity only | selection before load | missing/ambiguous -> `SourceUnavailable` |
| SRC-02 | selected strict JSON | all 153 exposed leaves | sole external content authority | unreadable/malformed -> fail-fast |
| SRC-03 | optional `runtime_entry_profile_assertion` | one closed enum | equality check only | mismatch -> `CrossFieldConflict` |
| SRC-04 | static-derived design values | 39 typed semantics | assembly, not override | matching external key -> `ForbiddenKey` |
| SRC-05 | isolated TestFake fixture source | same strict JSON + finite fake realization | replaces SRC-01/02 only in CI/TestFake | any other profile -> `FakeBindingForbidden` |
| SRC-06 | command/query/event/job input | operation-local typed values | narrow only, not config | expansion -> current operation reject |

153 个 exposed leaf 全部 required。nullable leaf 必须显式为 JSON `null`；delegation disabled 时五个 bound 必须显式 `0`；Disabled/Blocked slot/job 仍保留完整 exact shape。assembler 不因 posture 或 condition 补字段、补默认值或把 omission 转换为 `None`。

| 共同属性 | 适用范围 | 唯一规则 |
|---|---|---|
| 内容来源 | 全部 153 个 exposed leaf | `SRC-02` selected strict JSON；仅 CI/TestFake 可由 `SRC-05` 提供同一 strict shape 的隔离 fixture，其他来源不得覆盖 leaf |
| 作用域 | 全部 153 个 exposed leaf | process-local composition；不得成为 tenant/user/request 级 mutable override |
| 生效方式 | 全部 153 个 exposed leaf | startup V0~V12 全量校验并装配进一个 immutable snapshot；facade 发布后进程内不 reload/hot update |
| 默认与缺失 | 全部 153 个 exposed leaf | external default 为 none；全部 required；`null`/`0` 只能按各字段既定语义显式提交 |

| Conflict | Required behavior |
|---|---|
| duplicate key at any depth | reject whole document；no last-key-wins |
| unknown/missing/alias/case-variant key | reject whole document |
| multiple documents | reject；no merge/precedence guess |
| assertion mismatch | reject；document unchanged |
| static-derived synonym appears | `ForbiddenKey` |
| raw secret/provider-shaped key/value | `SecretMaterialDetected` or `ForbiddenKey` |
| TestFake source outside CI/TestFake | `FakeBindingForbidden` |

### 7.1 Strict schema 总则与计数

- 输入必须是 UTF-8 strict JSON；不接受 JSONC/YAML/TOML/HCL/CUE。
- 顶层必须且只能包含 `profile`、`scope`、`context`、`working_memory`、`model_decision`、`action_guard`、`delegation`、`checkpoint_recovery`、`handoff_projection`、`idempotency`、`adapter_slots`、`jobs`。
- 每层 object closed；unknown、duplicate、alias、case variant、extra/missing 均拒绝。
- 所有 153 exposed leaf 必须出现；nullable 显式 `null`；无 external content default。
- enum 使用 exact snake_case；不 coercion、case-fold、旧名兼容。
- slot/job identity 由 object key 派生；不得在 object 内重复 identity。
- 本章全部逐字段表共同继承 §5 的来源与生效规则：内容 authority 为 `SRC-02` selected strict JSON（仅 CI/TestFake 可由 `SRC-05` 提供同 shape fixture），作用域为 process-local composition，生效方式为 startup V0~V12 -> one immutable snapshot；不得 merge、leaf override、request override 或进程内 reload/hot update。

| Batch | Domains | Exposed | Static-derived |
|---|---|---:|---:|
| A | profile/scope/context/working_memory/model_decision | 24 | 3 |
| B | action_guard/delegation/checkpoint_recovery/handoff_projection/idempotency | 22 | 9 |
| C | 13 adapter slots | 65 | 13 |
| D | 7 jobs | 42 | 14 |
| Total | 12 roots | 153 | 39 |

表中 `default=none` 表示没有 external/code content default 且字段 required；不是 nullable 或 runtime fallback。示例数值/ref 只用于 parser/relationship fixture，不是容量、性能、SLA、formal ref 或 readiness。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“敏感级别”“Step 7 反向索引”“Detection and rejection rules”“Rotation protocol”和“Audit allow-list”。

Runtime v1 schema 中 secret leaf 数量为 0。`sensitive` typed ref 是 body-free identity，不是 credential；password/private key/token/cert/DSN/authorization header/provider credential 不得出现在 Runtime JSON、snapshot、example 或 Runtime-owned buffer。

| Level | Meaning | Allowed | Forbidden |
|---|---|---|---|
| public | schema/profile version、closed enum/path | JSON/snapshot/safe diagnostics | readiness implication |
| internal | counts/weights/durations/postures/environment | JSON/snapshot/redacted summary | broad body-free material unless allow-listed |
| sensitive | typed contract/schema/redaction/blocker/capability ref、source locator | declared JSON fields/loader context；snapshot only for declared refs | full value in log/error/metric/event/report/handoff |
| secret | raw credential material | nowhere in Runtime | every Runtime surface |

| Material | JSON | Snapshot | Persistent output | Rule |
|---|---:|---:|---:|---|
| public/internal leaf | yes | yes | safe summary/digest | normal validation |
| declared sensitive typed ref | yes | yes | category/fingerprint only | typed owner/kind/version parser |
| source locator | selector only | no | fingerprint only | loader-local transient |
| raw JSON bytes | selected source | no | never | parser-local transient；no body echo |
| raw secret/credential | no | no | never | `SecretMaterialDetected`/`ForbiddenKey` |
| adapter-resolved credential | no | no | no Runtime output | owning adapter/security boundary |

#### 敏感配置读取图：ref-only 与 adapter authority

```text
[selected strict JSON]
        |
        | typed opaque refs only
        v
[shape/owner/kind/version validation]
        |
        v
[RuntimeConfigSnapshot] ---> [RuntimeBuilder compatibility]
                                      |
                                      v
                         [owning adapter/security]
                           resolves credential/route

raw secret/credential -------- X Runtime snapshot
```

关键说明：

- Runtime validates ref syntax/compatibility but cannot resolve a secret or prove owner availability。
- source locator/raw document/full ref never enters broad diagnostics。
- adapter failure never triggers credential copy/fallback into Runtime config。
- This boundary does not claim any KMS/Vault/adapter implementation exists。

| Detection | Result | Safe diagnostic |
|---|---|---|
| forbidden key such as password/token/secret/private_key/credential/dsn/endpoint/route/quota/cost | reject whole document | stable path category only |
| secret-shaped ref value, bearer/JWT/key/cert/query secret | reject whole document | `SecretMaterialDetected` + safe field path |
| ref embeds raw path/endpoint/route | typed ref reject | parse category only |
| fixture contains production-like secret | CI config/test fail-fast | fixture fingerprint only |
| unknown provider/vendor extension | unknown/forbidden key reject | path only |

Ref/credential changes are startup-only. Owner/deployment prepares the new binding/document, runs full validation, compares redacted fingerprints, starts a replacement process, then retires the prior process. Revoked/expired refs make affected operations Blocked/Unavailable/Unknown；captured ref remains identity, never authority to use a revoked secret. No actual rotation completion is claimed.

## 9. 配置加载、校验与生效机制

> 延伸阅读：

配置只在 process composition startup 加载一次，发生在任何 Api/Worker/Jobs/TestFake facade 暴露之前。任何失败都不发布 snapshot、不构造可见 facade、不调用 external Port，也不从旧值、默认值或部分对象回退。

#### 配置加载流程图：V0~V12 与 startup publication

```text
[selector + optional assertion]
  -> V0 source cardinality
  -> V1 bounded UTF-8 load
  -> V2 duplicate-aware strict JSON
  -> V3 closed shape/security
  -> V4 exact primitive types
  -> V5 typed conversion
  -> V6 field constraints
  -> V7 domain relations
  -> V8 profile/authority/fake matrix
  -> V9 exact 13-slot tuples
  -> V10 exact 7-job tuples

        | Invalid ----------------------> no exposure
        | required-path Blocked --------> no entry facade
        + compatible Bound ------------> publish once
              optional Blocked path ----> negative-only facade if entry permits
```

关键说明：

- 每阶段只消费前阶段 candidate；任何 issue 终止 publication。
- `Bound` means compatible composition only；it does not mean adapter operational or Ready。
- Optional Blocked path 只有在既有 entry contract 允许有限负向结果时才可随 Bound composition 发布；它自身仍不具备正向调用资格。
- Builder construction/compatibility performs zero external calls。
- publish is a one-time local visibility boundary, not Bus/config-center/owner publication。

| Stage | Required work | Success output | Existing error mapping | Zero-side-effect boundary |
|---|---|---|---|---|
| V0 | exactly one allowed source；fixture only CI/TestFake；selector/assertion names known | redacted source identity + handle | `SourceUnavailable`/unknown env/fake build error | no default discovery/locator output |
| V1 | complete bounded UTF-8 single document | transient bytes | `SourceUnavailable`/`MalformedJson` | no persist/body/path log |
| V2 | strict JSON, duplicate detection at every depth | duplicate-checked tree | `MalformedJson`/`DuplicateKey` | no tolerant parse/last-write-wins |
| V3 | exact 12 roots/closed objects/153 presence/forbidden+secret scan | raw domain nodes | `UnknownKey`/`MissingRequired`/`ForbiddenKey`/`SecretMaterialDetected` | no extension value retained |
| V4 | exact scalar/null/array/object and enum spelling | primitive candidates | `TypeMismatch`/`RangeViolation` | no coercion/case fold |
| V5 | versions/refs/blockers/counts/weights/durations wrappers | typed leaves | `SchemaMismatch`/type/range/secret errors | no owner body/credential/endpoint resolution |
| V6 | required/nullability/positive/nonnegative/nonempty/unique | field-valid domains | missing/range/schema errors | no default/dedupe/clamp |

| V11 | X/S/J gates, blocker truth, dependency direction | coherent typed candidate | cross-field/forbidden；`SlotMismatch`/direction error | no blocker closure/qualification |
| V12 | add 39 derived semantics, canonicalize, version/ref/fingerprint, issues=0 | immutable snapshot candidate | schema/publication conflict | no raw output/pre-full assembly publish |

Issues may aggregate within one safe stage, but contain only stable code、safe path、expected/actual type category、stage and body-free reason. Secret detection switches diagnostics to minimal mode. Ordering is stable by stage/root/path. Parser-library raw messages never pass through directly. `ConfigValidationSummary.issue_count` must equal zero before candidate construction.

### 9.1 Assembly and fingerprint

V12 constructs one `RuntimeProfile` with nine policies, one `RuntimePolicyVersionSet`, exact `AdapterSlotConfigSet`, exact `JobControlSet`, and `ConfigValidationSummary` with schema `v1`, body-free source fingerprint, validation time and zero issues.

Fingerprint preimage contains exact schema version、canonical typed 12-root content、39 derived semantics and redacted source identity fingerprint. It excludes raw locator、JSON whitespace/key order、assertion transport、timestamps、generated snapshot ref、credential and full sensitive display. Set-like arrays canonicalize by canonical enum/ref order；semantically ordered arrays preserve their declared order；duplicates reject. `snapshot_ref` identifies an immutable assembled instance；it is not evidence/artifact/readiness alias. Concrete ID algorithm remains implementation-time design.

### 9.2 Builder and publication

```text
[validated candidate]
  -> validate local Ports/stores/mappers/config reader
  -> match 13 slot configs to RuntimeDependencySlots
  -> construct explicit blocked realization where allowed
  -> reject fake outside TestFake
  -> construct services without I/O
  -> construct one EntryAuthority facade
  -> publish snapshot + facade atomically once
```

| Disposition | Publication | Entry behavior | Fact ceiling |
|---|---|---|---|
| Invalid | discard；nothing visible | composition fails | safe `BuildError` only |
| `Blocked` because a required slot/path is Blocked | no entry facade exposure | no positive operation | blocker refs only |
| `Bound` with explicitly negative optional Blocked paths | snapshot + compatible facade locally visible；affected paths use negative-only realization | affected calls deterministically return Blocked/Disabled；other allowed paths may proceed | config compatibility only；no operational qualification |
| `Bound` without exposed Blocked paths | snapshot + compatible facade locally visible | allowed entry accepts operations | config compatibility only |

P0 has no second in-process publication, pointer swap, mixed old/new module or rollback state machine.

### 9.3 Snapshot capture and by-ref behavior

| Flow | Selection/capture point | Stable carrying | Missing/mismatch |
|---|---|---|---|
| new Command | resolve current once before reservation/UoW and bind `CommandMetadata.config_snapshot_ref` | operation context/result/history as existing contract permits | reject before mutation/external call |
| Query | resolve current once before reads | local execution context；safe response ref where allowed | fail closed；no unvalidated fallback |
| Inbound Event | after envelope validation, before inbox/UoW | local operation/receipt-side records where defined | durable negative/Unknown before ACK |
| Continuation/InternalLoop | use recorded source operation/step ref；new boundary may capture current only under existing contract | operation context/stored identity | missing historical ref -> manual/fail-closed；no current substitution |
| new Job page | verify Candidate and bind ref before lease/page read | `JobRunContext`/page report/state | reject/Blocked before lease or stop without cursor advance |
| replay/reconcile/by-ref | exact recorded ref via `snapshot_by_ref` | historical immutable snapshot | `SnapshotNotFound`; preserve Blocked/Unknown/fence |

One operation or claimed job page uses one snapshot. No stage after capture recaptures per step/item. Failure before V12 yields no snapshot/build/call；V12/build failure yields no publication；capture failure precedes reservation/UoW/lease/external call.

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“Authority 与评审等级”“十二域变更规则”“Canonical diff”“Audit requirements”“Cold rollback rules”。

P0 的变更单位是一份完整 reviewed strict JSON；不支持 leaf patch、document merge、admin override 或 in-process mutation。新进程独立执行 V0~V12 与 builder，外部 deployment owner 才能决定进程替换事实。回退也是重新选择 prior reviewed document、重新验证并冷启动，不是在线 pointer switch。

| Actor category | Allowed | Forbidden | Required safe record |
|---|---|---|---|
| `configuration_author` | submit complete candidate + body-free reason ref | activate/bypass/claim approval | actor category/change ref/candidate fingerprint |
| `release_operator` | select reviewed document and execute start/replace/rollback | edit values/suppress blocker/claim readiness | operator/release-attempt/fingerprint/disposition refs |
| `upstream_contract_delegate` | provide owner contract/schema/blocker decision ref | provide credential/body/route or Runtime qualification | owner category/ref fingerprint/schema category |
| `test_fixture_author` | change CI/TestFake document/fake registry | use fixture outside CI/TestFake | fixture fingerprint/scope/review ref |
| Runtime/model/tool/child/event | immutable read only | author/review/activate/rollback global config | rejection category only |

| Review | Typical changes | Required gate | Pending/failure posture |
|---|---|---|---|
| R0 | documentation only, no runtime contract | normal document review | no runtime change |
| R1 | restrictive authority/purpose/effect/budget；disable optional slot/job | config owner + full validation + affected-flow analysis | not activated |
| R2 | context/memory/page/lease/freshness bounds；retention extension | config + module owner；rollback target；cross-domain validation | not activated |
| R3 | scope expansion、delegation/recovery/action policy、Candidate、retention decrease | architecture/domain/safety + owner refs | reject/pending review |
| R4 | contract/schema/redaction ref、blocker removal、schema/fake boundary | formal owner + security/migration + 03 impact check | reject/design change |
| Forbidden | secret/provider/Ready/static invariant/online lifecycle | cannot be approved as ordinary config | reject whole candidate |

#### 变更审计链图：whole-document cold replacement

```text
[complete candidate + change ref]
              |
       [risk + review]
              |
        [V0~V12 validation]
              |
      [builder compatibility]
              |
 [external replacement attempt]
      | failed | unknown | succeeded
      v        v         v
 old known   manual/   new process
 unchanged  reconcile  serves by owner fact

Cold rollback = select prior reviewed document and repeat the same chain.
```

关键说明：

- Validation/build candidate never mutates old process, captured operations or committed truth。
- Replacement success/failure/Unknown belongs to deployment owner, not snapshot/builder inference。
- Unknown cannot become success or automatic retry。
- Rollback is a new attempt and never reverses facts/effects produced under either snapshot。

Canonical diff compares independently validated typed representations, not raw text. It ignores whitespace/key order, includes all 39 derived semantic effects, reports exact canonical paths and redacted set/ref deltas, and chooses the maximum of field risk、direction risk and cross-domain impact. Blocker removal or Blocked-to-Candidate requires formal owner closure input；without it, the candidate rejects or remains Blocked.

| Surface | Risk focus | Additional gate | Cold rollback ceiling |
|---|---|---|---|
| profile/scope | entry/authority exposure | 4x4 matrix、authority subset、security review on expansion | prior whole document only if still compatible |
| context/working memory | bound direction、freshness、compaction backlog | domain relations and in-flight isolation | old decisions/windows unchanged |
| model/action/delegation/recovery | authority/effect/external refs/fence | R3/R4 owner/safety refs and slot compatibility | no submitted effect/child/checkpoint relabel |
| handoff/redaction | page/freshness/material exposure | redaction/handoff/projection owner refs | no delivery/observed reversal |
| idempotency | retention decrease/digest schema | permanent proof + external window qualification | cannot resurrect deleted data/proof |
| adapter slots | posture/ref/blocker/dependency direction | exact tuple + upstream owner + fake isolation | incompatible prior becomes Blocked, not forced |
| jobs | activation/bounds/lease/retry/dependencies | profile/slot/fence/page gates | no active page/report/cursor rewrite |

| Audit information | Meaning | Forbidden payload |
|---|---|---|
| change/actor/review/reason refs | product-neutral attempt and authority identities | free-text body/credential/fabricated approval |
| risk/source classes | R1~R4/Forbidden and normal/CI source category | arbitrary downgrade/raw locator |
| old/new source/content fingerprints | reviewed identity and canonical typed digest | full config/raw source/full sensitive refs |
| changed paths/value fingerprints | exact Step 7 paths and redacted ref/set deltas | raw values/diff hunks |
| affected domains/slots/jobs | bounded canonical impact | owner body |
| validation/build disposition | existing issue codes and Invalid/Blocked/Bound | Ready/readiness |
| release/replacement disposition | future external attempt ref and not_started/failed/unknown/succeeded | inferred success from config/ping |
| rollback target ref/fingerprint | prior reviewed candidate identity | raw prior document |

These are information requirements for future release/audit ownership, not a new Runtime DTO. This design contains no actual change/ref/release record.

Cold rollback requires current V0~V12、current owner/blocker refs、builder compatibility and external review. An invalid/revoked/unsupported prior document is not eligible merely because it once ran. Unknown replacement/rollback has no automatic next attempt. Every in-flight operation retains its captured snapshot. Rollback never rewrites Runtime history/result/inbox/job report/outbox/idempotency, restores a credential, or bypasses current security/schema gates.

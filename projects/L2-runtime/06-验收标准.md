## 2. 验收目标与范围

> 校准来源：
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读：继续阅读该中间产物的“Scope axes”“Acceptance scope registry”“AC/VF scope posture”。

### 2.1 核心裁决目标

1. 对一个 immutable candidate tuple 裁决 Runtime local semantics、owner/data boundary、protocol/state/UoW/config/evidence 是否满足 `AC-L2R-001~036`。
2. 对 `VF-L2R-001~008` 逐项形成 `not_triggered`、`triggered` 或 `not_evaluable`；`triggered` 和适用的 `not_evaluable` 都不能被风险接受掩盖。
3. 分离 G0 design handoff、G1 local deterministic、G2 named integration candidate、G3 per-slot qualification 与 product/release readiness。
4. 固定 evidence eligibility、缺陷复验、风险字段、条件期限、verdict/signoff 的角色和证据边界。

### 2.2 分层结论模型

| 层 | 裁决对象 | 必须绑定 | 结论上限 |
|---|---|---|---|
| `G0_design` | 00~06 source/contract 是否可交接 | source、denominator、case/data/env/evidence schema | 设计可交接；不等于代码存在 |
| `G1_local` | 172 raw + 5 same-run aggregate 的 Runtime local contract | 177 rows、9 checks、local profile、同 run evidence | local contract only |
| `G2_candidate` | 一个 named real adapter/profile seam | owner contract、real adapter、独立 run/evidence | named seam compatibility |
| `G3_slot` | 一个 external slot 的正向资格 | `TC-QUAL-SLOTnn`、owner/env、独立 evidence | 该 slot qualification |
| `product_release` | mandatory lanes + release authority | immutable child packages、operational package | product/release readiness only |

上层只能引用下层 immutable package digest，不能复制、筛选、改写或跨 run 合并子结论。

### 2.3 Scope registry

| Scope | 本轮裁决 | 优先级 | 非范围 / 上限 |
|---|---|---:|---|
| `SCP-L2R-01` | admission/run/goal/plan/loop | P0 | 不裁 Work/Process/ImplementationPlan |
| `SCP-L2R-02` | context/source/working-memory/durable mediation | P0 | 不拥有 source/body/index/retention |
| `SCP-L2R-03` | provider-neutral model intent/turn/summary | P0 | 不裁 provider route/secret/quota/cost/quality |
| `SCP-L2R-04` | action choice/guard/invocation/delegation/feedback orchestration | P0 | 不拥有 Tools execution、Governance approval、Sandbox isolation |
| `SCP-L2R-05` | checkpoint/recovery/reflection/outcome/handoff phase | P0 | 不裁 physical durability、delivery、Observed |
| `SCP-L2R-06` | owner/data/dependency boundary | P0 | 不持有 external body/backend/container/image |
| `SCP-L2R-07` | 17 C + 12 Q + 6 inbound E + 6 outbound O + 7 J | P0 | 不裁 transport/deployment readiness |
| `SCP-L2R-08` | 31 state、UoW、replay、CAS、lease、cursor、error | P0 | 不选 DB/broker/scheduler |

### 2.4 明确非范围

Provider physical routing and secrets、durable episodic/semantic body/index lifecycle、Tools execution and Sandbox isolation、Governance approval truth、Observability backend/Observed truth、method body/source、member-service/container/image lifecycle、Artifact/evidence body、marketplace listing、产品入口和实施排期均不属于 Runtime 的拥有范围。缺失的 mandatory positive seam 会压低 readiness ceiling 或使该 lane `not_evaluable`，但不会缩减 G1 的 177 分母。

### 3.1 Immutable baseline tuple

未来验收必须绑定同一 `acceptance_instance_id` 的以下 tuple；任何字段变化默认生成新 run 和新 package：

| 基线 | 必须固定 | 当前状态 |
|---|---|---|
| 需求/设计/测试 | current 00~05 path + content digest + source status | 设计来源存在；送验 tuple absent |
| 实现/build | actual revision、workspace、Rust/toolchain、build identity | absent；`L2R-IMPL-001/LANG-001` open |
| config/profile | 04 snapshot pair、entry/profile、slot/job posture、bounds | absent |

| data/fault | fixture/seed/clock/workload/fault digest | absent |
| run | non-moving unique `run_id` | absent；不得使用 `latest` |

### 3.2 Canonical denominators

```text
37 CUT
172 owning raw TC + 5 same-run aggregate TC = 177 TC
177 planned EV identities (M0 only)
8 owning suites = 35/32/32/16/25/15/17/5

```

G2/G3 `TC-QUAL-SLOTnn` identities不属于 G1 177，必须独立 rebaseline、run、artifact、report 和 evidence namespace。

### 3.3 固定证据路径

| 内容 | 正式路径 | 语义 |
|---|---|---|
| run metadata/checks/raw | `artifacts/test/<run_id>/meta|checks|suites/...` | 机器原始证据；不可手写 pass |
| suite/report/evidence detail | `reports/runs/<run_id>/suites/...`、`evidence/<evidence_id>.md` | 同 run 人读 projection |
| acceptance handoff | `reports/acceptance/handoff.md` | 送验说明；不自动形成结论 |
| VETO | `reports/acceptance/veto-checklist.md` | VF001~008 逐项 review |
| risk | `reports/acceptance/risk-acceptance.md` | 仅记录 future authorized residual |
| issues/review | `reports/acceptance/open-issues.md`、`reports/review/*` | 保留失败、阻塞、争议 |

禁止 `latest`、`artifacts/test/<project>/<run_id>`、`reports/<project>`、绝对/逃逸/符号链接路径以及跨 run evidence。

### 3.4 Baseline change invalidation

需求、设计协议/state/UoW/config、实现/build/toolchain、owner contract/schema、profile/config/data、selector/runner/report/evidence schema、缺陷修复、blocker owner fact 或 review authority 变化，都必须执行影响审计并按 05 的 targeted/impacted/full 规则生成新 run；旧 package 只读保留，不得原地修改或 best-of-run 合并。

## 4. 进入条件与退出条件

> 校准来源：
> - `design-calibration/06_acceptance_step_04_entry_exit.md`
>
> 延伸阅读：继续阅读该中间产物的“Acceptance process state”“Acceptance entry conditions”“Acceptance exit conditions”。

### 4.1 验收过程状态

| 状态 | 含义 | 允许动作 | 禁止推导 |
|---|---|---|---|
| `not_entered` | 无 valid immutable candidate package | 补齐 baseline/entry | 任一三值 verdict |
| `entry_review` | 校验 tuple/schema/authority/denominator | 只做准入审查 | P0 已通过 |
| `in_review` | package 冻结并逐项裁决 | AC/VF/defect/risk review | 自动总体通过 |
| `paused` | source/scope/authority/evidence 冲突 | 保留 package，建 re-entry | 风险接受绕过冲突 |
| `not_decidable` | mandatory item 无法可靠判定 | 补 evidence、新 package/run | 当作不通过或条件通过 |
| `decision_ready` | AC/VF/defect/risk/dimension 已闭合 | 授权角色形成结论 | 未签署即 readiness |
| `closed` | verdict、signoff、archive digest 同 tuple | 只读复查或新 instance | 旧结论适用新 revision |

### 4.2 Common entry conditions

进入 `entry_review` 前，未来 package 必须同时满足：

- [ ] 唯一 `acceptance_instance_id`、scope、included/excluded AC/VF 已固定。
- [ ] current 00~06 source manifest、implementation/build/toolchain、config/profile、data/fault、12 blocker snapshot 可复查。
- [ ] only-Core compile graph 和六类依赖分类已通过 source/dependency check。
- [ ] G1 selector 精确包含 172 raw + 5 aggregate、8 suite、9 checks，无 hidden filter/skip。
- [ ] fixed `run_id` 绑定新 `artifacts/test/<run_id>` 与 `reports/runs/<run_id>` roots。
- [ ] raw case、suite report、check、redaction、pairing、evidence-index 均同 run 且 digest 一致。
- [ ] `reports/acceptance/handoff.md`、`veto-checklist.md`、`open-issues.md` 存在并未预填 green verdict。
- [ ] first-failure、defect、retest lineage 和 authority snapshot 完整。

### 4.3 Lane-specific entry and exit ceiling

| Lane | 额外准入 | 缺失时 | 最大结论 |
|---|---|---|---|
| G1 | 177 eligible instances、9 checks、local profile、无 S/A、适用 VF 可判定 | `not_entered`/`not_decidable` | local contract |
| G2 | named owner contract、real adapter revision、non-TestFake profile、独立 run | lane blocked | named seam candidate |
| G3 | dedicated `TC-QUAL-SLOTnn`/QUAL EV、owner/env/reviewer | slot `not_evaluable` | named slot qualification |
| product/release | G1 + all mandatory G2/G3 + release authority | product `not_entered` | product/release disposition |

### 4.4 Exit conditions

- [ ] 36 AC 在 scope 内逐项有 disposition、正式设计源、canonical TC、eligible EV/report 和影响。
- [ ] 8 VF 逐项为 `not_triggered/triggered/not_evaluable`，无适用项被隐藏。
- [ ] six dimensions、raw/report/index/check/redaction/pairing、source-to-evidence 双向 trace 无 orphan/duplicate/cross-run。
- [ ] S/A=0 才能讨论通过或有条件通过；修复必须 new run + targeted/impacted/full retest。
- [ ] residual risk 有 owner/acceptor/authority/action/deadline/expiry/reopen trigger；VETO/S/A/P0 不可接受。
- [ ] overall verdict 仅取 `通过`、`有条件通过`、`不通过`，并绑定统一 package digest 和 signoff。

### 4.5 Pause、re-entry 与当前状态

设计、实现、config、data、evidence schema、VETO、S/A、owner fact 或 authority 变化时暂停并生成新 manifest/run；旧 package 不原地修复。当前值为 `process_state=not_entered`、baseline/run/artifact/report/evidence=none，不代表实际“不通过”。

## 5. 功能验收门禁

> 校准来源：
> - `design-calibration/06_acceptance_step_05_function_gate.md`
>
> 延伸阅读：继续阅读该中间产物的“Five aggregate functional loops”“Detailed functional gates AC006~020”“Exact TC/EV mapping”。

### 5.1 共同裁决合同

功能验收主语是 `AC-L2R-001~020`。每一项必须消费 registry 中的全部 mapped rows，而不是只选择代表性 case：

```text
functional_ac_pass(AC) :=
  AC is in formal AC-L2R-001..020
  AND every mapped TC/EV row is eligible in one fixed G1 run
  AND each row has raw case + owning suite report + EV detail + required checks
  AND valid/negative/replay/fault/unknown variants satisfy the formal oracle
  AND state/write/call/phase/idempotency assertions pass
  AND mapped applicable VF is not_triggered
```

任何 mapped row 缺失、failed、blocked、infra、invalid、cross-run 或适用 VETO triggered，都使该 AC 不能通过。`not_evaluable` 不是 pass；aggregate 只能由同 run child raw rows 派生，不能替代 child rows。

## 10. 可观测性、审计与证据门禁

> 校准来源：

### 10.1 Observation、audit、artifact、EV 与 verdict 分层

| Material | Runtime / local owner | External/test owner | 验收语义 |
|---|---|---|---|
| `RuntimeObservation` | body-free candidate、phase、disposition、correlation、safe refs/reason | L4-observability owns backend/delivery/Observed/retention | candidate 不是 EV |
| local history/audit fact | 与 domain UoW 同提交的 transition/causation/version refs | external audit may consume snapshot | local fact 不等于 backend audit truth |
| test artifact/report | test runner/check/generator writes fixed-run material | suite/check/report owner | eligibility 前不是 evidence |
| EV detail/index | canonical planned identity from 05；generator derives same-run pair | evidence generator | `derived` 不等于 accepted |
| acceptance draft/review | Runtime 无写 verdict 权限 | generator + authorized review | 不得反写 raw status 或 owner truth |

```text
Runtime observation candidate
  != Observed
  != audit backend fact
  != test artifact
  != EV instance
  != acceptance verdict
```

### 10.2 Local observation/audit carrier

适用 Flow 的 future raw evidence 必须证明 carrier 只含：

```text
observation_id(candidate only), operation, phase, disposition,
correlation, actor_ref?, scope_ref?, object_refs, source_refs,
version_refs, safe_reason?, config_snapshot_ref, occurred_at, redaction
```

允许 phase 仅为 `Entry/Validation/Reservation/Read/Decision/LocalCommit/ExternalAttempt/Incorporation/Projection/Publish/Completion`。Command/loop、state transition、external attempt、inbound/outbound event、job/page、checkpoint/handoff 和 error/recovery 都必须保留 identity、version、fence、phase、typed disposition；禁止 full input/current dump、endpoint/secret/route/quota/cost/raw owner result、ACK promotion 和 implicit retry。

Metric labels 只允许 operation、phase、bounded disposition、profile、slot class、event/job kind 和 bounded state variants。Actor/run/object ID、prompt/body、provider/user value、endpoint、secret、query text、full cursor 都不能成为 metric label。Redaction 必须在 serialization 前完成；Markdown 后编辑不能修复 evidence。

## 12. 缺陷分级、复验与放行规则

> 校准来源：

>
> 延伸阅读：继续阅读该中间产物的“S/A/B/C 严重度与结论影响”“复验身份与证据规则”“Targeted / impacted / full 回归矩阵”。

### 12.1 Record-kind boundary

| Record kind | 判定 | 可否算通过 | 后续路径 |
|---|---|---|---|
| `product_defect_candidate` | canonical oracle 与实现不一致，已排除 fixture/runner 误用 | 否 | S/A/B/C、修复、复验 |
| `test_tooling_defect_candidate` | selector/fixture/fake/runner/check/report generator 违约 | 否 | tooling 修复 + new run；可升级 S |
| `execution_incident` | toolchain/namespace/cleanup/environment 失败，产品归因未定 | 否 | 保留 `infra_error`，调查后 new run |
| `dependency_blocker` | owner contract/adapter/profile/environment/implementation 缺失 | 否 | blocker ledger；不得 retry-to-green |
| `residual_risk_candidate` | P1/P2/future 或无 numeric threshold 的明确暴露 | 否 | 进入 §13 future review |

Expected `Blocked/Unknown/Unavailable` negative case 可在 G1 local 作为通过，但永远不关闭相应 G2/G3 positive blocker。

### 12.2 S/A/B/C severity

| Level | 精确定义 | 典型例子 | Gate impact | 风险接受 |
|---|---|---|---|---|
| `S` | VF001~008，或可伪造不可逆/已接受 truth 的 security/phase/evidence/dependency failure | owner reverse-write、fail-open、secret leak、unknown retry、fake/static evidence、sibling package | stop affected lane；通常 full 177 + 9 checks new run | 禁止 |
| `A` | 未达到 S，但为 P0 protocol/state/UoW/idempotency/config/entry/denominator failure | illegal transition、partial UoW、query write、cursor skip、denominator gap | blocks affected G1；targeted + impacted，必要时 full | 本轮 P0 禁止 ad hoc 接受 |
| `B` | 无 P0 truth/security 影响的 P1/P2/future 或有界 tooling issue | characterization 字段、非阻断报告可读性、future adapter mismatch | affected lane non-qualified | 仅 future authority 可接受 |
| `C` | 已证明不影响语义、evidence、执行的文档/可用性问题 | 非规范 typo、可恢复引用问题 | 修订后关闭 | 不需验收风险接受 |

严重度按影响而非 exit code。能隐藏失败、缩减分母、泄漏材料或合成 evidence 的 tooling failure 至少为 S。

### 12.3 Defect record and lifecycle

Future defect record 必须包含：`defect_id`、record kind、severity、first-failure run/artifact/report/EV refs、affected AC/VF/surface/state/config/slot、expected/actual safe summary、root-cause status、owner、fix revision、retest plan、prior/new run、closure evidence、review role/time。First failure immutable；不得删除、覆盖或 cherry-pick 绿色片段。

```text
detected -> triaged -> fix_planned -> fixed_candidate
         -> retest_running -> verified_closed
         -> reopened
```

`fixed_candidate` 不是关闭；只有 new run 的 required retest、evidence eligibility 和 reviewer closure 才能 `verified_closed`。重现不了保持 open/infra，不得按 C 关闭。

### 12.4 Retest identity and minimum scope

每次复验必须生成新 `run_id` 和新 artifact/report/EV instances，引用 `prior_run_id`，保留首败。Selector 按 05 的 exact registry 做集合并集：

| Change/failure | Targeted | Impacted | Full escalation |
|---|---|---|---|
| single local oracle | exact failed case + all declared variants | adjacent CAP/Flow/state/UoW/error/AC/VF cases + owning checks | shared/public semantic or uncertain impact |
| protocol/schema/Port | changed C/Q/E/O/J/slot + envelope/error companions | all consumers/producers、source/dependency/redaction | public schema/version/identity change |
| state/UoW/CAS | affected SM/UoW/replay/error | every mutating Flow and relevant job/event | shared transaction/fence/order change |
| config/profile/builder | changed CFG/entry/slot/job | all consumers of changed leaf/derived value | 12/153/39、13x5、7x6、V0~V12 semantics change |
| evidence tooling | failed generator/check + synthetic non-green corpus | one case from each 7 raw suites + all aggregates + 9 checks | status/schema/digest/path/selector truth change |
| VETO/S defect | exact trigger case/check | every affected AC/VF/boundary/output surface | full 177 + 9 checks by default |

任何 unresolved impact 自动升级 full 177；uncertainty 不能缩小回归。G2/G3 继续使用独立 run，不能并入 G1 或借 fake evidence。

## 14. 最终结论与签署

> 校准来源：
> - `design-calibration/06_acceptance_step_14_verdict_signoff.md`
>
> 延伸阅读：继续阅读该中间产物的“总体结论判定矩阵”“`not_decidable` 与三值 verdict 的边界”“签署角色与职责”“最终验收包与归档”。

### 14.1 结论 vocabulary

正式 verdict 只允许：

```text
通过
有条件通过
不通过
```

禁止“基本通过”“原则上通过”“大体没问题”“待观察通过”，也禁止把 `not_entered/not_decidable` 当三值 verdict。只有一个 valid immutable baseline、eligible evidence、closed defect/risk disposition 和授权裁决全部绑定后才能形成 verdict。

### 14.2 Dimension isolation

| Dimension | 裁决对象 | 必须独立记录 | 不得推导 |
|---|---|---|---|
| `G0_design` | formal contract 可交接性 | source、denominator、test/evidence contract | implementation exists/pass |
| `G1_local` | 177 local rows + 9 checks | AC/VF/defect/evidence/risk disposition | owner adapter、delivery、Observed、product ready |
| `G2_candidate` | named real integration candidate | owner contract/schema、adapter/profile、independent run | G3 or whole Runtime |
| `G3_slot` | named slot/owner/version/env qualification | dedicated QUAL identity/evidence | other slot/product |
| `product_release` | mandatory child packages + operational/release review | immutable refs、release authority | G1 alone |

每个 dimension 使用独立 `acceptance_instance_id`、`execution_run_id` 和 evidence namespace。上层只能引用下层 package digest。

### 14.3 Verdict decision matrix

| Dimension | `通过` | `有条件通过` | `不通过` |
|---|---|---|---|
| baseline/entry | one valid immutable tuple；all mandatory entry satisfied | same | absent/invalid run、authority、manifest、scope |
| AC | all applicable AC eligible and passed | all P0 passed；only eligible B/C residual outside P0 truth | any applicable P0 failed/not_evaluable |
| VF | all applicable VF reviewed `not_triggered` | same as pass | any triggered；mandatory VF hidden/not reliably evaluable but declared green |
| defects | S=0、A=0；required B/C disposed | only authorized eligible B/C | open S/A、invalid execution、unclosed P0 |
| evidence | raw/report/check/digest/redaction/pairing complete | complete plus reviewable residual package | missing/cross-run/static/orphan/duplicate/redaction failure |
| risk | accepted=0 or all eligible residual fields authorized | each eligible residual has acceptor/reason/action/expiry/trigger | VETO/S/A/P0/evidence gap accepted or fields missing |
| blockers | mandatory lane owner fact closed or formally not applicable | optional lane explicitly excluded without P0 pollution | mandatory seam hidden/shrunk/treated pass |
| signoff | all required roles bind same package digest | same package + explicit conditions | authority/role/digest/scope missing or conflicting |

`有条件通过` 不能接受 VF、S/A、P0 failure、invalid evidence 或 mandatory lane `not_evaluable`。

### 14.4 Process state vs verdict

| Process state | Meaning | Allowed next action | Forbidden conclusion |
|---|---|---|---|
| `not_entered` | no valid candidate | build baseline/run/package | any verdict |
| `entry_review` | tuple/schema/authority review | entry checks only | P0 passed |
| `in_review` | frozen package under item review | AC/VF/defect/risk disposition | automatic pass |
| `paused` | drift/conflict/authority/evidence issue | preserve and re-enter | risk override |
| `not_decidable` | mandatory item cannot be reliably judged | new evidence/package/run | fail or conditional pass |
| `decision_ready` | all item/dimension dispositions closed | authorized verdict/signoff | unsigned readiness |
| `closed` | verdict/signoff/archive fixed to tuple | read-only review/supersession | apply to new revision |

### 14.5 Verdict、next stage 与 readiness 分离

| Result | 可允许动作 | 明确不包含 |
|---|---|---|
| G1 local candidate accepted | hand to implementation/integration review with blockers | owner readiness、Sandbox isolation、Bus delivery、Observed |
| G2 candidate validated | prepare that seam's G3 qualification | owner truth transfer、global readiness |
| G3 slot qualified | hand off that named slot result | other slot or whole product |
| `通过` | enter authorized next-stage/release preparation for exact scope | automatic deploy/go-live/product acceptance |
| `有条件通过` | proceed under explicit conditions/owners/expiry | VETO/P0/mandatory gap waiver |
| `不通过` | fix、rebaseline、new run/retest | reuse old verdict or delete failures |

Readiness 必须由 product/release/operations owner 使用独立 package 和 scope 声明；验收签署不自动等于 implementation、deployment、marketplace、member-service 或 product readiness。

### 14.6 Signoff roles

以下是 future role contract，不是当前人员、签名或日期：

| Role | 必须确认 | 不得代替 |
|---|---|---|
| Runtime/product owner | scope、P0/P1/P2、business residual、next-stage impact | technical evidence、owner truth、安全红线 |
| Architecture owner | ownership、dependency、13 slots、phase/VETO、cross-repo seam | business risk acceptance、test execution |
| Test/evidence owner | 177 denominator、suite/check、pairing、defect/retest、evidence integrity | source owner、product release authority |
| Implementation owner | actual revision/build/config/workspace、implementation scope/risk | design truth 或单独 verdict |
| Security/operations/compliance owner | redaction、profile、handoff、retention/compliance residual | Runtime domain truth、business acceptance |
| External seam owner(s) | named owner contract、adapter/profile/env、G2/G3 evidence | G1 verdict 或其他 owner truth |
| Acceptance authority | final verdict、VETO checklist、risk acceptance、open issues、archive | modify raw artifact、fabricate evidence、owner implementation |

所有签署必须绑定同一 `acceptance_instance_id`、baseline tuple、run/evidence package digest、review version 和 date。缺角色、authority、digest 或 scope consistency 时不能 `closed`。

### 14.7 Signoff、risk acceptance、blocker 与 readiness

| Action | Required record | Semantics |
|---|---|---|
| verdict signoff | verdict、scope、package digest、next-stage disposition | confirms exact acceptance conclusion |
| risk acceptance | risk ID、evidence、impact、reason、action、owner、acceptor、expiry、reopen trigger | accepts one eligible residual |
| blocker disposition | owner fact/provenance、affected lane、re-entry | closes/retains blocker |
| readiness declaration | product/release/operations authority、independent package/scope | separately declares readiness |

任何签署都不能覆盖 VETO、S/A、invalid evidence、owner truth leak、fail-open、unknown retry、dependency disguise 或 mandatory seam `not_evaluable`。

### 14.8 Final package and archive

Future closed package must contain:

```text
acceptance_instance_id + immutable baseline tuple
design/source/implementation/config/dependency manifests
fixed run(s), artifact roots, suite/check reports, evidence-index
AC disposition table (36), VF checklist (8), defect/retest registry
risk-acceptance.md, handoff.md, open-issues.md, review notes
final verdict, next-stage disposition, signoff role records
archive/content digests and prior/superseding package links
```

任何 acceptance/review 文件变更都创建新 review version/instance 或明确 supersession；旧 package 只读保留。

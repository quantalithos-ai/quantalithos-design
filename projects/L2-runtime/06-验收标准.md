### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L2-runtime` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L2-runtime` 是正式执行主脑仓,不是流程仓、工具仓或消息仓
- ExecutionInstance / CurrentStep / ExecutionFeedback 构成正式执行真相层
- `ExecutionInstance ≠ Process Activity`、`ImplementationPlan ≠ runtime state` 两条核心边界必须成立
- blocked / waiting_input / suspended / retry / failed 必须严格分层
- governance 未 allow 的高风险动作不能被 dispatch
- promote 只能正式回流给 work,不能在 runtime 内部偷造 child WorkItem 真相
- artifact / process / work / conversation 围绕同一 execution truth 接收回流,不会漂移成多套语义

因此,本次验收的目的不是笼统判断“能不能执行工具调用”,而是判断 runtime 的执行真相、步骤推进、阻断恢复、治理边界、协作升级与多下游回流是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 执行主语与运行实例部分 | 是 | ExecutionInstance、execution context、主状态 |
| 执行计划展开与步骤推进部分 | 是 | CurrentStep、PlanItemBinding、step progression |
| 动作调度与执行反馈部分 | 是 | dispatch、feedback、tool/member-service/sandbox 接缝 |
| 阻断、恢复与治理接缝部分 | 是 | blocked / waiting_input / suspended / retry / recover |
| 结果回流与协作升级接缝部分 | 是 | artifact/process/work/conversation 回流与 promote |
| tool SDK / sandbox 内部实现细节 | 否 | 只验 runtime 与能力层接缝,不验工具内部逻辑 |
| process / work / governance / artifact / conversation 全部内部正文逻辑 | 否 | 只验 runtime 与它们的接缝,不验下游仓全部细节 |
| 前端展示像素级行为 | 否 | 只验证 execution summary material,不验 UI 组件 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| StartExecutionInstance | work ref + process timing + plan ref + governance allow 条件齐备后,必须形成正式 ExecutionInstance | API 响应 / DB 记录 / trace | [] |
| ExecutionInstance vs Process Activity 边界 | 执行真相必须独立于 process activity,不得被 process 节点状态替代 | compare trace / model review / negative test | [] |
| ImplementationPlan consume | ImplementationPlan 只能作为 artifact 输入真相被展开为 step,不得被当作 runtime 内部状态本体 | binding trace / object compare | [] |
| AdvanceExecutionStep | 当前 step 推进后必须形成正式 feedback 与新状态,不能只停留在 tool/member-service 日志里 | feedback record / state transition / step trace | [] |
| blocked / waiting_input / suspended / retry / failed 分层 | 非 happy path 必须能区分阻断、等待、暂停、重试和失败,不能混成一个失败态 | state compare / regression / negative flow | [] |
| governance allow/block consume | 未 allow 的高风险动作不得被 dispatch; allow/waive 后才可恢复推进 | governance trace / dispatch log | [] |
| RaisePromoteRequest | 局部执行超界时必须形成正式 promote request 回流给 work | promote signal / work consume trace | [] |
| Promote 边界 | runtime 不得直接制造 child WorkItem 真相,只能发 promote request | model review / negative flow | [] |
| PublishExecutionResult | step 完成后的 output/report/result 必须正式回流 artifact,同时回报 process | artifact signal / process progress signal | [] |
| PublishExecutionSummary | conversation 只能消费只读 execution summary / failure / wait / promote material,不得反写真相 | summary compare / notification trace | [] |
| RecoverExecutionInstance | 恢复必须回到稳定执行点,不得任意跳点 | recover trace / stable point compare | [] |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| governance 未 allow 不可 dispatch | 高风险动作不得先执行再补治理 | governance trace / dispatch log | [] |
| promote 不可绕过 work | runtime 不得直接制造 child WorkItem 真相 | negative flow / promote trace | [] |
| summary 不可替代 execution truth | conversation / progress view 不得反向作为 execution 状态来源 | summary compare / architecture check | [] |
| recover 不可乱跳点 | 恢复只能回到稳定执行点 | recover trace / stable point compare | [] |
| artifact backflow 不可吞 execution truth | output/report 回流失败不能抹掉已存在 execution 结果真相 | fault injection / execution record compare | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | ExecutionInstance/ProcessActivity 混层 / governance 未 allow 仍执行 / promote 绕过 work / recover 漂移 |
| A | 视情况 | 主线可跑但 blocked/retry/resume/recover/backflow 语义不稳 |
| B | 可带着走 | 非关键摘要视图、通知材料或低优先级查询异常 |

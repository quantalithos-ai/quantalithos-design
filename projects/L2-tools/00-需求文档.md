## 1. 与 `product/` 的关系声明

L2-tools 是**运行时能力型**需求仓。它不是终端用户产品,而是 runtime 的“手脚”——提供真正被调用的工具集合。

## 2. 背景与问题定义

### 2.1 业务背景

runtime 不能直接写 shell 命令或随意访问外部服务。它需要通过一组**可描述、可校验、可审计**的工具来行动。L2-tools 就是这套能力的实现仓。

它需要同时支持:
- 内置工具(file / code / git / test / docs)
- 需要沙箱执行的危险工具
- 通过 capability-hub 白名单代理的外部 MCP Tool

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 工具分类 | README 已有大类 | 仓级需求未显式化 |
| schema 要求 | TL1 已定 | 具体验收标准未成文 |
| sandbox 集成 | 方向已清晰 | 哪些工具必须沙箱尚需落地 |
| MCP 白名单 | capability-hub 已定 | tools 如何遵守未仓级化 |

### 2.3 为什么要做(量化依据)

- 没有 tools 仓,runtime 无法行动
- 没有 schema 化,AI 调工具不可控、不可验证
- 没有 sandbox / capability-hub 集成,安全边界会破

### 2.4 业务问题 vs 技术问题

- **业务问题**:AI 成员如何安全、稳定、可审计地“做事”
- **技术问题**:工具分类、schema、沙箱、MCP、白名单、输出结构化

## 5. 核心用例与用户故事

### 5.1 核心用例

1. runtime 调内置 file/code/git/test/docs 工具
2. 危险工具通过 sandbox 执行
3. 外部 MCP Tool 通过 capability-hub allowlist 调用
4. 每次工具调用产生 ToolInvoked / ToolCompleted / ToolFailed 事件
5. Role extras 决定哪些工具被装进镜像

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **runtime**,我想要 **调用一个声明了 input/output schema 的工具**,以便 **调用前后都可做校验** |
| 优先级 | P0 |
| 验收条件 | **Given** 任意 ToolDescriptor **When** 调用 **Then** 输入输出都通过 schema 校验 |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **Security**,我想要 **危险工具默认要求 sandbox + policy check**,以便 **阻止宿主机直接暴露给 AI** |
| 优先级 | P0 |
| 验收条件 | **Given** 标记为 `requires_policy_check=true` 的工具 **When** 未授权调用 **Then** 拒绝 |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **runtime**,我想要 **调用外部 MCP Tool 时统一走 capability-hub**,以便 **白名单和审计都集中** |
| 优先级 | P0 |
| 验收条件 | **Given** 外部 Tool 请求 **When** 调用 **Then** 必经 capability-hub 查询与代理 |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **member-images**,我想要 **按 Role extras 装配可选工具集**,以便 **不同角色容器只带需要的工具** |
| 优先级 | P1 |
| 验收条件 | **Given** backend-dev image build **When** 安装 extras/backend_dev **Then** 可用工具清单正确 |

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 类型 | 生命周期 |
|---|---|---|
| ToolDescriptor | 注册项 | active / deprecated / retired |
| ToolInvocation | 调用记录 | started / completed / failed |
| ExtraBundle | 角色工具包 | versioned |

### 9.2 数据关系

```
ToolDescriptor
  ├─ schema
  ├─ risk flags
  ├─ execution mode(in-process / sandbox / mcp)
  └─ extras group(optional)
```

### 9.3 数据生命周期与归档

大部分元数据可长期保留;调用事件交给 observability 归档。

## 11. 验收标准

### 11.1 功能验收标准

| 功能 ID | 验收场景 | Given-When-Then | 执行方式 |
|---|---|---|---|
| F-001 | ToolDescriptor | **Given** 一个新工具定义 **When** 缺 schema **Then** 注册失败 |
| F-007 | sandbox_exec | **Given** 危险工具 **When** 执行 **Then** 走 sandbox 而非宿主机 |
| F-008 | MCP client | **Given** 外部 MCP tool **When** capability-hub allow **Then** 调用成功 |
| F-009 | 审计事件 | **Given** 工具调用任一结果 **When** 完成 **Then** 发对应事件 |
| F-010 | Role extras | **Given** QA role 镜像 **When** 构建 **Then** 只带 qa extras |

### 11.2 非功能验收标准(量化)

| 维度 | 指标 | 验收方式 | 阈值 |
|---|---|---|---|
| 安全 | schema 覆盖率 | 测试 | 100% |
| 安全 | 危险工具绕过 sandbox | 测试 | 0 |
| 可追溯性 | 调用事件覆盖 | 回归测试 | 100% |
| 可用性 | extras 构建成功率 | CI | 100% 样本角色 |

### 11.3 主功能完成口径

| 维度 | 标准 |
|---|---|
| 功能 | F-001~F-007, F-009(P0) 通过 |
| 安全 | TL1~TL5 全成立 |
| 文档 | 01 / 02 / 03 / 04 完整 |
| 测试 | 单元 + 集成 + 安全回归 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| schema 不完善导致 AI 调用失败 | 中 | 中 | descriptor validation |
| 工具分类错误(危险工具当安全工具) | 低 | 高 | security review |
| MCP client 与 hub 协议漂移 | 中 | 高 | sdk/version lock |

### 12.2 边缘风险

- 某 Role extras 包过大
- 工具依赖与镜像依赖冲突
- local tool 与 sandbox tool 行为不一致

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| sandbox 集成深度(Tool 自声明 vs Policy override) | L2 后 | tools + sandbox |
| MCP client transport 选型 | L2 后 | tools + capability-hub |
| AG-UI tool result 类型 | L2 后 | tools + conversation |

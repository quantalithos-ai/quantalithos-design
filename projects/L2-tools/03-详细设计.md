### 2.2 实现范围

L2 只实现工具调用行动契约的本地语义层：

1. 稳定 `ToolId`、正式定义、修订演进和兼容影响；
2. 本地工具与 Hub formal ref 的 body-free Binding 关系及消费时点评估；
3. canonical invocation、context、admission 和 no-execution 结果；
4. execution requirement、authorization consumption assessment、Sandbox readiness/handoff seam 和 local attempt；
5. formal source mapping、不可拆的 outcome/audit pair、safe material 和 external submission attempt；
6. reference assessment、consistency gap、watermark projection、diagnostic/guidance view；
7. 对应 Commands/Queries/Consumers/Events/Jobs 的入口、存储、错误、幂等和观测契约。

### 2.3 明确非范围

| 不在 L2 | 处理位置 |
|---|---|
| agent loop、LLM plan、runtime orchestration、checkpoint | Runtime owner |
| registry、provider inventory、marketplace、builtin/MCP/A2A/API client | Hub/adapter/SDK/分发 owner |
| effective authorization、approval、policy、risk taxonomy | Authorization owner，当前 blocked |
| environment/run/capture/failure/receipt/cleanup/DLQ | Sandbox owner，当前 blocked |
| Bus delivery/retry/DLQ/replay、Observability store/retention/route | Bus/Observability owner，当前 blocked |
| 完整配置 key/value、环境矩阵、部署挂载 | `04-配置设计.md` |
| 完整测试计划、真实测试结果、验收签署 | `05-测试方案.md`、`06-验收标准.md` |
| phase/commit 排期、implementation ledger、真实 boundary skeleton | `07-实施计划.md` |

### 2.4 Phase discipline

- 同步 Command 先完成合同、Binding、context 和执行前判断；不得先进行真实外部执行。
- 外部 clue、source、feedback 通过 Consumer 或 continuation 产生新的 assessment/ref/gap；不得原地改写历史 invocation/admission/outcome。
- Projection、reference integrity、status refresh 和 report 由 bounded Job 维护；Job 不修复 Contract、Binding、Invocation、Outcome 或 Audit truth。
- `CF-10`、`CF-12` 和 `OF-01~04` 使用 `Prepared -> one Port call -> phase-2 local disposition`；`CallOutcomeUnknown`/`SubmissionOutcomeUnknown` 不自动重试。

### 3.2 依赖分类与方向

```text
Core compile candidate
        |
        v
contracts -> domain -> application -> api/worker/jobs
                 ^          ^
                 |          |
              contracts   infra (implements application seams)
```

允许的编译依赖只有已核对的 Core candidate：

```toml
[workspace.dependencies]
core-contracts = { path = "../quantalithos-core/crates/contracts" }
```

该行是 planned candidate，不表示 L2 实现仓已有 manifest。Hub、Authorization、Sandbox、Runtime 是 runtime seam；Bus、Observability 是 event collaboration；SDK 是 future consumer，均不得写入 sibling Cargo dependency。

### 3.3 不可配置化的安全不变量

配置、feature、adapter availability 或环境变量不得改变：

- Tool identity/definition/current revision 的 owner；
- Binding active/explicit-unbound/history 语义；
- canonical invocation、admission、outcome/audit pair 的字段和状态；
- authorization/sandbox required 时的 fail-closed 与不可旁路；
- `Prepared`、unknown、late material、duplicate replay 的行为；
- forbidden-body、redaction、correlation、source attribution 和 low-cardinality 规则；
- Query no-write、Job no-repair、Projection/reference/status 不反写真相；
- Core-only compile 和三类依赖裁剪；
- semantic key、expected version、CAS、UoW 原子性和 external call fence。

旧 README、旧正式 03/05/06、旧 Rust service、RPC/HTTP、PostgreSQL/Redis/NATS、registry/policy/executor/MCP/builtin 等只保留在 calibration 的 historical audit；正式本文不复制旧路径、旧状态、旧 SLA、旧事件或旧错误码。

### 5.1 模块总规则

六个业务组成部分跨七个工程模块实现。`contracts` 只拥有 public carrier，`domain` 只拥有 41 个业务对象的语义和状态，`application` 拥有 use-case 顺序、Store/Port trait、UoW 和幂等，`infra` 只实现这些 seam，`api`/`worker`/`jobs` 只负责入口转换和 bounded runner。

所有模块遵守以下调用纪律：

```text
entry validation
  -> application facade
  -> canonical domain factory/guard
  -> named Store/Port method
  -> shared ToolsUnitOfWork (when writing)
  -> typed public mapper / replay surface
```

入口不传递 `&mut` domain aggregate 给外部 Port；Port 不接收 UoW；domain 不读取配置、时钟实现或外部客户端。任何无法在本章找到 owner、field source、callable、error 或 test cut 的新增类型必须先回退到对应 calibration Step，不由实现者临时补定义。

### 5.2 `contracts` 模块

**实现位置：** `crates/contracts/src/refs.rs`, `metadata.rs`, `commands.rs`, `queries.rs`, `consumers.rs`, `events.rs`, `jobs.rs`, `views.rs`, `errors.rs`。

**唯一职责：** 提供 13 Command、11 Query、5 Consumer、4 Event、4 Job 的 public DTO；typed ID/ref、metadata、page、visibility/freshness、receipt/report、stored replay value 和 `ProtocolError`。该模块不定义领域迁移、不执行 I/O、不暴露 transport/backend 类型。

| capability | canonical carrier | 必填来源 | 禁止 |
|---|---|---|---|
| identity/ref | `ToolId`, `DefinitionRevision`, `ToolInvocationId`, `CorrelationRef`, `SourceEventId`, `ExternalLocatorSummary` 等 | owning Command、validated envelope 或 formal Port | 从显示名、URL、inventory、provider body 推导 identity |
| metadata | `CommandMetadata`, `QueryMetadata`, `JobMetadata`, `ConsumerMetadata` | entry boundary | 重复嵌入 request body、携带认证实现或 transport header |
| public views | `ToolContractView`、`CapabilityBindingView`、`ToolInvocationView`、`ExecutionPreconditionView`、`OutcomeAuditView`、`ConsistencyGapView` | application mapper 的完整 read bundle | 直接导出 domain/private field、外部状态推断 |
| replay | `StoredCommandResult`, `StoredCommandValue`, `ConsumerReceipt`, `JobReport` | 已确认的 local commit candidate | 从当前可变 truth 重建历史响应 |
| degraded surface | `ConsumptionVisibility`, `FreshnessState`, `EntryDisposition`, `RetryHint` | resolver/Store/application | 用空值吞掉 stale/rebuilding/unavailable/unknown |

公共 carrier 的实现约束如下：

```rust
/// Metadata required by every truth-changing command.
pub struct CommandMetadata {
    /// Trusted actor reference for the command.
    pub actor_ref: ActorRef,
    /// Caller request identity used for correlation and diagnostics.
    pub request_id: RequestId,
    /// Correlation shared by all facts from this operation.
    pub correlation_ref: CorrelationRef,
    /// Channel-scoped idempotency identity.
    pub idempotency_key: IdempotencyKey,
    /// Application boundary time captured after validation.
    pub submitted_at: DecisionTime,
}

impl CommandMetadata {
    /// Validates non-empty typed metadata before idempotency lookup.
    pub fn validate(&self) -> Result<(), MetadataError>;

    /// Returns a transport-free frame used by canonical request hashing.
    pub fn canonical_frame(&self) -> MetadataDigestFrame;
}
```

`QueryMetadata::validate` 只产生 `VisibilityInput`，不启动 transaction；`EventEnvelope<T>::validate_envelope` 检查版本、source authority、correlation 和 forbidden-body；`Page<T>` 保留 `next_cursor`、`source_watermark`、`freshness`，空页与不可用页分型；`ProtocolError::from_application_error` 只输出 stable code/class/safe message/retry hint/correlation/ref。所有 public enum variant 必须有英文 Rustdoc，具体字段以 Step 6 shared carrier annex 为唯一 authority。

**最小测试切口：** unknown protocol/version、缺 actor/key/correlation、raw body 拒绝、same-key same-digest replay、same-key different-digest conflict、empty/stale/rebuilding/unavailable/failed page、错误映射不泄露 lower-layer detail。测试只验证契约，不声称真实 transport 或 provider 可用。

### 5.3 `domain` 模块

**实现位置：** `crates/domain/src/contract.rs`, `binding.rs`, `invocation.rs`, `precondition.rs`, `handoff.rs`, `outcome.rs`, `safe_handoff.rs`, `integrity.rs`, `shared.rs`, `policies.rs`, `errors.rs`。

### 5.4 `application` 模块

**实现位置：** `crates/application/src/*_service.rs`, `ports.rs`, `unit_of_work.rs`, `idempotency.rs`, `mapping.rs`, `errors.rs`。

`application` 是唯一的 use-case 编排层。它读取 metadata、计算 canonical digest、预检幂等、载入完整 read bundle、调用 domain factory/guard、协调 Store 与 external Port、提交 UoW，并将结果映射到 public carrier。它不依赖具体数据库、HTTP/RPC、broker、SDK 或 scheduler。

#### 5.4.1 Facade 与 callable

#### 5.4.2 Application foundation

`ToolsUnitOfWorkManager` 提供 `begin`, `commit`, `rollback`, `resolve_commit` 和 `commit_candidate`；`ClockPort` 和 `IdGeneratorPort` 是唯一应用边界时钟/ID 来源；`ReadVisibilityResolverPort` 只做本地 owner/consumer scope decision；`IdempotencyStore` 先 reserve/lookup，再存 typed result/receipt/report，最后完成 claim。

所有 mutable Store read 返回 `Loaded<T>`，其中 `expected_version` 是 adapter-issued CAS token。所有 append 返回 `AppendResult::{Appended, ExistingEqual, Conflict}`。`ProjectionStore` 使用 `ProjectionRead`/`ProjectionPageRead` 区分 Missing、Readable Fresh/Stale、Rebuilding、Unavailable、Failed。任何 Query mapper 都不能调用 `begin`, `mark_stale`, `begin_rebuild` 或 external Port。

#### 5.4.3 Port 与 Store 编排边界

external Port 调用发生在 local UoW 之外；side-effect Port 之前必须有已确认的 Prepared marker。`CF-10` 使用 `ExecutionHandoffAttempt`，`CF-12/OF-01~04` 使用 `ExternalSubmissionAttempt`。Port 返回 `PortResolution<T>` 表示 blocked/unavailable/unsupported/conflicting/unverifiable；`PortCallError::SideEffectOutcomeUnknown` 表示可能越过副作用边界，必须保持 unknown/manual。

### 5.5 `infra` 模块

**实现位置：** `crates/infra/src/config.rs`, `runtime_builder.rs`, `repositories.rs`, `projection_store.rs`, `idempotency_store.rs`, `reference_store.rs`, `source_resolvers.rs`, `publishers.rs`, `handoff_adapters.rs`, `clock_id.rs`, `fakes.rs`, `errors.rs`。

`infra` 只实现 application-owned traits。它必须能提供 durable/fake/blocker 三种绑定，但不能把 adapter availability 变成 external readiness，也不能在 adapter 内部隐藏 retry、transaction 或 body transformation。

| adapter 组 | 实现 trait | 当前允许的结果 | 禁止 |
|---|---|---|---|
| repositories | 7 logical Stores | loaded value、append result、CAS/version、watermark/page、unavailable | 业务迁移、last-write-wins、隐式 transaction |
| idempotency | `IdempotencyStore` | claim/replay/conflict/in-flight/commit unknown | generic cache fallback、重建历史结果 |
| source resolvers | Core/Hub/Auth/Sandbox/source Ports | `Available` 仅在 formal contract closed；当前相关项 blocked-aware | provider readiness、local registry、default allow、host fallback |
| publishers/feedback | `SafeEventCollaborationPort` | local submitted/rejected/route-blocked/status ref resolution | delivery/retry/DLQ/Observation store |
| builder/config | `ToolsRuntimeConfig` -> validated refs | composition、feature、page/timeout/retry class、adapter availability | 改 truth/state/security invariant |
| fakes | 同一 trait 契约 | deterministic success/negative/unknown branches | 把 fake 结果写成 integration evidence |

`infra/runtime_builder.rs` 必须在装配前验证 seven Stores + UoW + technical ports + seven external Port slots 是否存在；缺失的 external owner 绑定只能得到 blocked adapter，不得用空实现伪造 positive path。具体 typed config candidate 见 §13。

### 5.6 `api` 模块

**实现位置：** `crates/api/src/command_handlers.rs`, `query_handlers.rs`, `routes.rs`, `errors.rs`, `bin/tools_api.rs`。

API handler 的唯一顺序是：解码 logical version -> `CommandMetadata/QueryMetadata::validate` -> 调 application facade -> 映射 `ToolCommandResponse`/`ToolQueryResponse` 或 `ProtocolError`。handler 不读 Store、不调用 external Port、不持有 UoW/domain aggregate、不记录 body。HTTP/RPC method/path/codec 留给后续边界，不在本设计中选择。

### 5.7 `worker` 模块

**实现位置：** `crates/worker/src/consumers.rs`, `collaboration_worker.rs`, `projection_worker.rs`, `errors.rs`, `bin/tools_worker.rs`。

worker 负责五类 envelope 的版本/source/body 校验、dedup claim、application dispatch 和 receipt/attempt view 输出。`IF-03` 是唯一可以重新进入 subject-owning `CF-11` 的 Consumer，且只接受 committed/replayed command result；其余 Consumer 只能追加 assessment/ref/gap。Worker 不拥有 broker ack、DLQ、Sandbox run 或 Observability store。

### 5.8 `jobs` 模块

**实现位置：** `crates/jobs/src/runners.rs`, `errors.rs` 及四个 action binary。

Job runner 只接受显式 bounded scope、cursor、watermark、system actor/job key。`JF-01~04` 的 allowed writes 仅为 snapshot、assessment、ref、gap、projection、report/status marker。Job 不调用 Contract/Binding/Invocation/Outcome/Audit owning Command 进行自动修复，不创建 run/evidence/signoff，重复执行只 replay 已存 `JobReport`。

### 5.9 模块间闭环门禁

| 检查 | 正式结论 |

| 41 对象唯一 owner | `domain`；contracts 只提供 view/ref，application 只编排 |

### 7.1 公共协议规则

所有 public schema 使用 `ToolProtocolSchemaVersion(1)` 和 closed semantic enum。逻辑名称分别为 `tools.command.<operation>.v1`、`tools.query.<operation>.v1`、`tools.event.<event>.v1`、`tools.job.<action>.v1`；Consumer 使用 envelope 中的 `contract_version`。entry 的固定顺序为：

```text
decode logical version
  -> validate typed metadata / envelope / request
  -> canonical digest (write families only)
  -> application facade
  -> typed result / receipt / report
  -> redacted protocol mapping
```

请求体只表达业务意图、稳定 subject/ref、safe reason、bounded candidate 或 scope；actor、trace、correlation、idempotency、entry time 由 metadata 提供，不重复进入 body。`ToolCommandResponse<T>` 的 `value`、`result_refs`、`committed_version` 和 `gap_refs` 必须对称；duplicate 必须返回 immutable stored value/error/receipt/report；不同 digest 不得覆盖。

### 7.2 Shared carriers

```rust
/// Public result of one committed or deterministically classified Command.
pub struct ToolCommandResponse<T> {
    /// Closed semantic command name.
    pub command: ToolCommandName,
    /// Version used to decode and encode this response.
    pub schema_version: ToolProtocolSchemaVersion,
    /// Local entry disposition, not external execution or delivery status.
    pub disposition: EntryDisposition,
    /// Exact typed result for accepted or replayed branches.
    pub value: Option<T>,
    /// References to committed local facts and views.
    pub result_refs: CommandResultRefSet,
    /// Adapter-confirmed local version or watermark when applicable.
    pub committed_version: Option<CommittedVersion>,
    /// Gaps known at the response boundary.
    pub gap_refs: ConsistencyGapRefSet,
    /// Correlation carried through every local fact.
    pub correlation_ref: CorrelationRef,
}

/// Public result of one no-write Query.
pub struct ToolQueryResponse<T> {
    /// Closed semantic query name.
    pub query: ToolQueryName,
    /// Version used to decode and encode this response.
    pub schema_version: ToolProtocolSchemaVersion,
    /// Visibility, freshness and degraded surface.
    pub surface: QuerySurface,
    /// Optional body-free read view.
    pub value: Option<T>,
    /// Correlation for diagnostics only.
    pub correlation_ref: CorrelationRef,
}

/// Body-free result of one bounded operations Job.
pub struct JobReport {
    /// Canonical Job operation name; no second job-kind field exists.
    pub job: ToolJobName,
    /// Stable operation key, not a scheduler or run identifier.
    pub job_key: JobRunKey,
    /// Requested local source watermark.
    pub requested_watermark: LocalTruthWatermark,
    /// Watermark actually processed by this bounded slice.
    pub processed_watermark: LocalTruthWatermark,
    /// Completed, partial, duplicate, blocked or failed disposition.
    pub disposition: JobDisposition,
    /// Low-cardinality safe counts.
    pub counts: JobSafeCounts,
    /// Typed refs to reports, projections, assessments and gaps.
    pub output_refs: JobOutputRefSet,
    /// Typed gaps discovered by this slice.
    pub gap_refs: ConsistencyGapRefSet,
    /// Explicit bounded continuation cursor.
    pub next_cursor: Option<JobCursor>,
    /// Operation correlation.
    pub correlation_ref: CorrelationRef,
}
```

`ConsumerReceipt` 的 disposition 只允许 `Accepted`, `Duplicate`, `Rejected`, `Quarantined`, `GapRecorded`；它不是 broker ack、DLQ、delivery status 或 evidence。`ToolEventEnvelope<T>` 只允许 safe material 产生的四个 semantic payload，包含确定性 `ToolEventId`、source material/ref set、schema 和 correlation，不含 route/topic/retry/delivery/observation。`ProtocolError` 只输出 stable `ToolErrorCode`, `ProtocolErrorClass`, safe message, retry hint, typed subject/gap/blocker refs 和 correlation；禁止 lower-layer text、body、secret、stack trace。

### 7.4 Query protocols `QF-01~QF-11`

> 校准来源：
> - `projects/L2-tools/design-calibration/03_ddd_step_08_protocol_recalibration_annex.md` §4~§5
> - `projects/L2-tools/design-calibration/03_ddd_step_08_query_protocols_annex.md`
> - `projects/L2-tools/design-calibration/03_ddd_step_09_query_flows_annex.md`
>
> Query 是独立的只读通道。每个 Query 必须通过 owner/collection visibility 读取，再读取
> named Store 的 exact bundle/page。Query 不建立 UoW、不调用 external Port、不刷新 source、
> 不重建 projection、不关闭 gap、不写 idempotency 或 telemetry truth。

#### 7.4.1 Query 公共构造规则

| 阶段 | 规则 | 禁止 |
|---|---|---|
| metadata | QueryMetadata.validate 生成 VisibilityInput、consumer scope、trace/correlation | 把 actor、trace、认证实现或 transport header 复制到 request body |
| visibility | 先读 owner scope 或 collection seed，再调用 ReadVisibilityResolverPort.resolve | 用返回行推断可见范围、调用 AuthorizationConsumptionPort、用 not-visible 行泄露存在性 |
| read | 只调用本表列出的 Store/ProjectionStore read method；bundle 必须带同一 watermark | 用 current truth 拼装历史 view、调用 refresh/rebuild、使用未命名 finder |
| mapping | 纯 map_* 函数验证 identity/ref/watermark/freshness 对称 | 在 mapper 中写 gap、修复 projection、回写 status 或生成新 fact |
| surface | Found、Empty、NotFound、NotVisible、Stale、Rebuilding、Unavailable、Failed 必须分型；不可读 surface 不携带推断 value | 把缺失/过期/不可用吞成空成功或假设“没有结果” |
| parity | durable/fake 采用相同 selector、排序、cursor digest、watermark 和损坏检测 | 由 fake 插入顺序或 backend 默认排序定义 public 顺序 |

#### 7.4.2 Query protocol cards

| Flow / logical schema | DTO 与字段来源 | exact read seam 与 pure mapper | surface、错误、replay 与最小测试 |

### 7.5 Inbound Consumer protocols `IF-01~IF-05`

> 校准来源：
> - `projects/L2-tools/design-calibration/03_ddd_step_08_consumer_protocols_annex.md`

Inbound Consumer 的 source/topic/group/ack/delivery/DLQ 不属于 L2 schema。每个 Consumer 的固定顺序为：

    validate envelope/version/source/body
      -> derive consumer-scoped digest
      -> phase-1 ConsumerClaimUow reserve and commit

ack、delivery receipt、run id、DLQ locator 或 evidence。phase-2 commit unknown 时 receipt 不得标记
committed；不得以 source presence 推断 owner truth。

### 8.1 公共 flow guard

写通道固定为：

    entry decode/version/metadata/body gate
      -> canonical scope + digest
      -> IdempotencyStore.get
      -> same digest stored replay / divergent conflict / in-flight recovery
      -> exact local reads and blocked-aware source resolution
      -> named UoW reserve + domain factory/transition
      -> named Store writes + stored value/error/receipt/report
      -> commit; unknown => same-authority resolve_commit
      -> response only after result/refs/commit symmetry

Query 固定为 visibility-first、exact read bundle/page、pure mapping，零 UoW/Port/write。Consumer
先提交 claim，再进行 observational read；Event 先提交 Prepared marker；Job 先提交 claim，再逐
target 有界处理。任何 phase 失败均按 Step 11/12 的 rollback/unknown 规则处理。

### 9.2 合同演进

ToolContract 只能 Active -> RetirementPending -> Retired。Retired 是 terminal，不允许回 Active。
FormalToolDefinition 只能 Candidate -> Current -> Superseded，或 Candidate/Current -> Withdrawn；
Superseded 不回 Current。DefinitionSourceRef 的 Resolved 才允许 formalize，Stale、Conflicting、
Unverifiable 只能形成新的 source assessment/gap。

| 转换 | owning callable / flow | 前置与原子副作用 | 非法行为 |
|---|---|---|---|
| none -> Active | ToolContract.establish / CF-01 | first identity、definition、initial BindingMode、有效 clock；同一 UoW 写 contract、current definition、Established fact、stored result | duplicate identity、invalid revision、source blocker；不写 truth |
| Active -> RetirementPending | request_retirement / CF-04 | reason 非空、Loaded expected_version；写 retirement fact、第一有界 stale page、gap/replay | terminal/reverse/version conflict rollback |
| RetirementPending -> Retired | complete_retirement / CF-04 | Current report、覆盖 watermark、无 blocking gap、CAS 成功；写 terminal fact | closure missing/stale/partial 或 invocation fence 冲突；不复活 |
| Candidate -> Current | promote_to_current / CF-03 | Active contract、Compatible 或已验证 Conditional closure、expected semantic revision 匹配 | Incompatible/Unverifiable/mismatch；旧 current 不得单独更新 |
| Current -> Superseded | mark_superseded / CF-03 | successor 是同 tool 新 current；与 contract pointer/adoption fact 同 UoW | 单独调用、回滚为 Current |
| Candidate/Current -> Withdrawn | withdraw correction branch | reason、authority、CAS 有效；append fact | Superseded 回 Current；改写历史 anchor |

### 9.3 Binding 与受控来源

CapabilityBinding 的生命周期为 Active -> ReplacementPending -> Replaced，或 Active/ReplacementPending
-> Invalidated。ExplicitUnbound 是 BindingMode，不是 lifecycle state；空 capability_ref 不能推断
ExplicitUnbound。

| 状态/转换 | 前置与副作用 | 禁止 |
|---|---|---|
| declare -> Active | active contract、mode/ref 对称、tool 无 current relation；Bound 必须 Hub snapshot，ExplicitUnbound 必须 typed reason；写 relation/fact/replay | local registry、name lookup、null inference |
| Active -> ReplacementPending | begin_replacement 使用 Loaded.expected_version；仅构造 local pending claim | 在 pending 阶段调用 Hub side effect 或创建第二 current |
| ReplacementPending -> Replaced | replace 使用 distinct successor；old/new/fact/stale/replay 一个 UoW | partial old/new、two-current、旧 anchor rewrite |
| Active/ReplacementPending -> Invalidated | invalidate(reason)；保留 history，追加 fact/stale/gap/replay | delete、fabricate explicit-unbound、Hub repair |
| assessment snapshot | AcceptedBound 需要 active relation + matching HubSnapshotRef；AcceptedExplicitUnbound 需要显式 relation；Missing/Stale/Conflicting/Unverifiable 只可 conservative/fail-closed | assessment 原地变更 relation 或旧 invocation anchor |
| Hub snapshot/ref | Resolved 才能支持 positive local assessment；当前 blocker 默认 Unverifiable/Blocked | provider inventory 或 capability registry truth |

### 9.4 调用受理

InvocationContextRefs 为 Sufficient、Degraded、Insufficient。InvocationAdmission 为 Admitted、
AwaitingPrecondition、Rejected、Unavailable。

| 转换 | 条件与副作用 | 非法/迟到规则 |
|---|---|---|
| request -> Admitted | active contract、supported canonical intent、context acceptable、无 applicable external precondition；immutable admission，无 external call | 不允许第二 admission |
| request -> AwaitingPrecondition | contract invocation 成立但 auth/Sandbox requirement 适用；保存历史 admission，CF-09 产生新 assessment | AwaitingPrecondition 不直接转 Admitted |
| request -> Rejected | deterministic contract/context/binding failure；同 UoW 写 NoExecutionRejected outcome/audit pair 与 stored error | terminal re-admission 拒绝 |
| request -> Unavailable | required source/contract unavailable/unverifiable；同 UoW 写 NoExecutionUnavailable pair/gap/error | 不用默认值或 allowlist |
| context | blocking ref 缺失或 forbidden body 为 Insufficient；non-blocking 缺失才可 Degraded | late ref 不修改原 context |

### 9.5 执行前置与交接

ExecutionRequirement 是从 definition/binding/invocation 纯派生的闭合分类：NoExternalGovernance、
AuthorizationRequired、SandboxRequired、AuthorizationAndSandboxRequired、Unsupported。它不是
authorization decision。

| 主语 | 合法转换 | 强制边界 |
|---|---|---|
| AuthorizationConsumptionAssessment | consume/fail_closed -> AcceptedAllow、AcceptedConstrained、AcceptedDeny、Missing、Stale、Conflicting、Unverifiable | invocation-bound authority/subject/revision 对称；append-only；AcceptedDeny 不等 Admission Rejected；不保存 policy truth |
| SandboxReadinessSnapshot | Port result -> Available、Unavailable、MappingBlocked、Conflicting、Unverifiable | 正向状态受 L2T-UP-003~004 阻塞；不含 run/capture/receipt/cleanup |
| ExecutionHandoff | factory -> Preparing；evaluate_eligibility -> Eligible；mark_blocked -> Blocked；invalidate -> Invalidated | Eligible 只表示 L2 可创建一次 local attempt，不是 Sandbox accepted |
| ExecutionHandoffAttempt | factory -> Prepared；一次 post-commit Port result -> AttemptedLocally、LocallyFailed、CarrierUnavailable、MappingBlocked、CallOutcomeUnknown | Prepared 先 confirmed commit；terminal 不回 Prepared；CallOutcomeUnknown manual only |

### 9.6 Outcome、审计与安全交接

| 主语 | 合法转换与原子性 |
|---|---|
| ExecutionSourceAssessment | Accepted 才能 normalize execution outcome；其它状态只追加 assessment/gap/error；迟到 source 不改旧 assessment |
| ToolInvocationOutcome | 一个 invocation 只能有一个 terminal outcome；result/error XOR；CF-08/11 与 ToolAuditEntry 由 OutcomeAuditStore.insert_outcome_audit_pair 同一 UoW 写入 |
| late/duplicate | terminal 后迟到 source、不同 digest、第二 pair 只产生 TerminalConflict gap/IntegrityFailure，不覆盖 outcome/audit |
| SafeHandoffEligibility | evaluate 是 target-specific 四项合取：minimal、body-free、redacted、correlated；非 Eligible 不创建 material |
| SafeHandoffMaterial | 只接受已提交 source truth + Eligible；immutable，不能从 current truth 重建 |
| ExternalSubmissionAttempt | Prepared 必须持久化 event id/name/schema/material/target；一次 collaboration call 后写 local disposition；SubmittedLocally 不表示 delivered/observed；Unknown 不自动重调 |
| external status refs | BusDeliveryStatusRef 与 ObservationMaterialRef 独立 append；Unknown/Stale/Conflicting/Unverifiable 不升级 local attempt |

### 9.7 完整性与派生

ConsistencyGap 只能 Open -> ResolutionPending -> Resolved，或 Open/ResolutionPending -> Superseded。
Resolved 必须有 formal owner re-read、decision/evidence symmetry；Query/Job 不能自行 resolve。
ReferenceConsistencyReport 为 Current、Partial、Stale、Failed；derived projections 为 Fresh、Stale、
Rebuilding、Unavailable、Failed；Core authority 当前为 CandidateOnly/Blocked。

| 状态 | 规则 |
|---|---|
| ReferenceValidity Valid/Stale/Conflicting/Missing/Unverifiable | 每次 consumption 产生 immutable assessment；blocking state fail closed，不改 owner |
| Gap Open | attributable subject/basis/class/impact；可请求 ResolutionPending |
| Gap ResolutionPending | evidence locator 已提交，等待 owner re-read；不代表修复 |
| Gap Resolved | owner authority、subject、revision、decision 与 evidence 对称且 re-read 通过 |
| Gap Superseded | newer gap 覆盖相同或更完整 scope；old/new 一次 UoW |
| Report Current/Partial/Stale/Failed | derived coverage only；不表达健康/readiness/subject repair |
| Projection freshness | QF-08~11 只读；JF-03 才 begin/replace/failed；older watermark 不覆盖 newer |
| Shared authority | 无 exact package/type/revision 时保持 CandidateOnly/Unverifiable，不复制 Core schema |

### 9.8 状态门禁

每个状态必须有唯一 owner、Step 6 callable、Step 8/9 flow、非法错误和 Step 16 test cut。terminal
state 不重开；unknown 不变成成功/失败；late material 只能追加 assessment/ref/gap/fact；Query 永远
zero-write。

### 10.2 UoW boundary and write ordering

| Boundary | 允许写入 | 禁止 | confirmed commit 含义 |
|---|---|---|---|
| ReadSnapshot | named read bundle/page | UoW、写、external Port、repair | watermark 仅描述性 |
| AcceptedCommandUow | owner truth、fact/assessment/ref、bounded stale/gap、stored result/error | external side effect、broker ack、hidden retry | 一个 confirmed local decision |
| ConsumerClaimUow | idempotency claim + technical marker | source interpretation、domain mutation、side effect | source message durable ownership |
| ConsumerEffectUow | assessment/ref/gap、IF-03 formal Command result、receipt/claim completion | 先 ack、改 external owner | local consumption durable |
| PreparedSideEffectUow | ExecutionHandoffAttempt.Prepared 或 ExternalSubmissionAttempt.Prepared、claim/material ref | call Port | side-effect fence |
| SideEffectDispositionUow | local attempt disposition、status ref、gap、stored result | second Port call、source rewrite | one call local attribution |
| MaintenanceUow | bounded projection/report/gap/status ref | unbounded scan、core repair | one bounded slice |
| CF-13 pending/decision | gap Pending -> owner re-read -> CAS decision | self-resolve、subject repair | only verified resolution |

固定排序：validate -> digest/idempotency -> exact reads -> begin UoW/reserve -> domain transition ->
Store writes -> append facts/assessment/pair/material/stale/gap -> store immutable result -> commit ->
resolve unknown -> response. CF-10/OF-01~04 是唯一 side-effect fence；CF-12 只提交 material；
Consumer claim 先于 observational Port；Job claim 先于 target enumeration。

### 10.3 CAS、append、page、watermark

- mutable save 只接受同一 Store 返回的 Loaded.expected_version；不得硬编码版本、使用时间戳或 source revision 作为 CAS。
- AppendResult 只有 Inserted、ExistingEqual、Conflict；ExistingEqual 必须 canonical 完整相等，不更新时间、不升级版本、不再发 fact/event/audit。
- list/search/rebuild/stale 方法接收 typed scope、cursor、limit、filter digest、source watermark；不接受 all 或隐式全扫。
- LocalTruthWatermark 是读快照，不是 CAS；projection compare subject/schema/watermark，older write 返回 Stale。
- OutcomeAuditStore.insert_outcome_audit_pair 是 outcome/audit 唯一终端写口；half pair 是 integrity defect。
- BusDeliveryStatusRef/ObservationMaterialRef 按 attempt、authority、source_revision append，不覆盖 ExternalSubmissionAttempt。

### 10.4 Cross-store invariants

### 10.5 Isolation and fake parity

ProjectionStore.mark_affected_stale 使用 reverse dependency index 处理一个 bounded page，continuation
产生 PropagationIncomplete gap；JF-03 只比较写 D1 projection。ReferenceValidityAssessment 是消费
快照，不是 owner 可写字段；缺少 Core authority seam 只能 Unverifiable/Blocked。Bus/Observation status
是独立 ref，缺失/过期/冲突不把 SubmittedLocally 变成 delivered/observed。Fake 必须与 durable adapter
保持 CAS、semantic uniqueness、rollback、commit unknown、watermark race 和 pair atomicity 同序列同结果。

## 12. 并发、幂等与重入保护

> 校准来源：
> - projects/L2-tools/design-calibration/03_ddd_step_13_concurrency_idempotency.md
> - projects/L2-tools/design-calibration/03_ddd_step_11_persistence_transaction_consistency.md
> - projects/L2-tools/design-calibration/03_ddd_step_12_error_recovery.md
>
> 本节保证 local truth 单赢家、immutable replay、CAS 和 side-effect fence；不承诺外部 exactly-once。

### 12.1 Namespace 与 digest

namespace 为 entry_kind、operation_name、actor_or_source_scope、idempotency_key。

| family | key/scope | digest 包含 | digest 排除 |
|---|---|---|---|
| Command | CommandMetadata.idempotency_key + operation/actor scope | canonical typed intent、stable refs、safe reason/candidate、schema | transport header、arrival time、raw body、retry metadata |
| Consumer | consumer、source authority、source event、dedup key | validated payload、source revision/class | received_at、broker count/topic/group/ack |
| Event | material_id、event_id、target_class、continuation_key | material class/source refs、event name/schema/id、target | route/topic/partition/retry/delivery response |
| Job | JobMetadata.job_key + job/actor scope | bounded scope、target kinds、cursor/limit、watermark、schema | scheduler run/lease/arrival time、external body |

Raw input 不直接 hash；typed mapper 产生 canonical frame。same key/digest replay，same key/different
digest 为 IdempotencyConflict；digest change 必须新 key/operation。

### 12.2 Mutable CAS 与 semantic uniqueness

| 资源 | 保护 | winner | loser/恢复 |
|---|---|---|---|
| Contract pointer/lifecycle | Loaded.expected_version + revision key | one adoption/retirement | VersionConflict；reload/re-evaluate |
| Binding current | expected version + one-current key | one declare/replace/invalidate | conflict；不建第二 current |
| Invocation/admission | invocation identity + one admission key | one canonical admission | equal replay；divergent conflict |
| Handoff/attempt | generation key + attempt CAS | one Prepared + one terminal local result | stale CAS；Prepared/unknown manual |
| Outcome/audit | invocation terminal key + pair key | one pair | TerminalConflict；no half pair |
| Gap | open-gap key + expected version | one resolve/supersede | stale conflict；newer gap may supersede |
| Projection | subject/schema/watermark compare | newest compatible source | older write Stale |
| External status | attempt/authority/source revision append | equal ref reuse | divergent gap；attempt unchanged |
| Idempotency claim | scoped key/digest reserve | one claim | replay/in-flight/conflict |

### 12.3 Duplicate/replay matrix

| record | digest | behavior |
|---|---|---|
| no record | new | reserve and run flow |
| Claimed/in-flight | same | retry-same-input or named phase continuation；不抢 claim、不重复 side effect |
| Claimed/in-flight | different | IdempotencyConflict；zero mutation |
| Committed | same + stored surface valid | load exact immutable result/receipt/report/attempt view |
| Committed | result missing/wrong kind | DuplicateResultMissing/manual；不从 current truth 重建 |
| Committed | different | conflict；old unchanged |
| Aborted | same | unavailable/manual unless explicit expiry later authorized |
| Prepared/Unknown attempt | same | return marker/manual；不 generic resubmit |
| terminal subject + late material | any | append assessment/ref/gap only；不覆盖 terminal |

Duplicate 不重跑 domain transition、fact、audit、outbox、projection refresh 或 external Port。Result/
receipt/report 必须在 claim completion 前保存；否则 claim 无效。

### 12.4 Phase/re-entry matrix

| Flow | phase-1 marker | allowed continuation | forbidden |
|---|---|---|---|
| CF-10 | handoff + ExecutionHandoffAttempt.Prepared | one SandboxExecutionPort call then phase-2 CAS | generic retry submit、host fallback |
| CF-12 | eligibility/material + command claim | delegate exact OF flow | current truth rebuild |
| OF-01~04 | material + ExternalSubmissionAttempt.Prepared + event identity | one collaboration call then disposition | second call from Prepared/Unknown |
| IF-01/02/04/05 | ConsumerClaim committed | source observation + phase-2 refs/receipt | Port before claim、direct core mutation |
| IF-03 | ConsumerClaim + derived CF-11 key | replay/commit CF-11 then receipt | alternate key/direct outcome write |
| JF-01~04 | Job claim + bounded cursor | deterministic page + final report | unbounded scan/memory report/duplicate rescan |

CommitOutcomeUnknown 必须通过同 authority resolve_commit；Committed 读取 durable result/marker，RolledBack
才可在 flow 明确允许时同 key 重入，仍 Unknown 则 manual、不新 key、不再调用 side-effect Port。

### 12.5 Projection/reference/status race

JF-03 older watermark 不覆盖 newer projection；Query 在 rebuild 期间只返回 Stale/Rebuilding/Unavailable/
Failed。JF-02/IF-02 assessment 按 consumption frame append；status ref 按 authority/revision 去重，冲突保留
双方并开 gap。CF-10/OF phase-2 使用 phase-1 loaded CAS token；late material 只能追加 assessment/ref/gap，
不得改 admission、outcome、audit 或 terminal attempt。

| L2T-CONC-006~009 | Consumer redelivery receipt replay；altered payload quarantine/conflict；unsupported schema pre-write reject；IF-03 derived key at-most-once |

## 13. 配置引用与外部依赖绑定

> 校准来源：
> - `projects/L2-tools/design-calibration/03_ddd_step_14_config_external_binding.md`
> - `projects/L2-tools/design-calibration/03_ddd_step_03_constraints.md`
> - `projects/L2-tools/design-calibration/03_ddd_step_07_trait_port_adapter_contracts.md`
> - `projects/L2-tools/design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：Step 14 §4~§15 的 typed candidate、builder、Port binding、fallback、timeout/retry 和 `NC-L2T-001~025`。本节不选择具体 backend、endpoint、secret platform、topic、scheduler 或数值。

### 13.1 配置 ownership 与边界

配置是 infra composition 的输入，不是 public protocol、domain truth 或外部 authority。只有
`infra/config.rs`、`infra/runtime_builder.rs`、entry wiring（`api`、`worker`、`jobs`）以及具体
infra adapter/store wrapper 可以读取配置。`contracts`、`domain` 不读取配置；`application` 不持有
raw config object，只接收 application-owned Store/UoW/Port 和已验证的 typed parameter。

配置可以选择 adapter、限制 page/batch、关闭外围 event/projection/status runner 或把某个外部 seam
显式置为 `Blocked`；配置不能产生 `ToolId`、current definition、Binding、admission、outcome、audit、
delivered、observed、readiness 或任何 source authority。配置文件存在、endpoint 已填写、adapter health
marker 已返回，均不等于 `PortResolution::Available`。

### 13.2 Typed candidate 到 runtime surface

以下类型是 planned Rust composition types，必须在实现时位于 `infra/config.rs`，不代表目标仓已有源码：

```rust
/// Untrusted configuration input before cross-section validation.
pub struct ToolsConfigCandidate {
    pub profile: ToolsProfileCandidate,
    pub boundary: ToolsBoundaryConfigCandidate,
    pub stores: ToolsStoreConfigCandidate,
    pub idempotency: ToolsIdempotencyConfigCandidate,
    pub projection: ToolsProjectionConfigCandidate,
    pub jobs: ToolsJobConfigCandidate,
    pub adapters: ToolsAdapterConfigCandidate,
    pub handoff: ToolsHandoffConfigCandidate,
    pub clock_id: ToolsClockIdConfigCandidate,
    pub features: ToolsFeatureConfigCandidate,
}

/// Validated infra-local references injected by the runtime builder.
pub struct ToolsRuntimeConfig {
    pub profile_ref: ToolsProfileRef,
    pub config_ref: ToolsConfigRef,
    pub boundary: ValidatedToolsBoundary,
    pub stores: ValidatedToolsStoreRefs,
    pub idempotency: ValidatedToolsIdempotency,
    pub projection: ValidatedToolsProjection,
    pub jobs: ValidatedToolsJobs,
    pub adapters: ValidatedToolsAdapterRefs,
    pub handoff: ValidatedToolsHandoff,
    pub clock_id: ValidatedToolsClockId,
    pub features: ValidatedToolsFeatures,
}
```

`ToolsConfigCandidate` 可以带 `ConfigSourceRef` 和 redacted issue reference，但不得包含 raw request、
prompt、capture、provider response、secret plaintext、credential、SQL 或完整 endpoint body。
`ToolsRuntimeConfig` 只包含已验证的 typed ref、limit、timeout/retry/degraded category、feature gate 和
capability marker；不得包含业务对象或可改变 truth 的值。

配置校验错误必须是稳定且 body-free 的 typed surface：

| 类型 | 触发 | 输出 | 禁止 |
|---|---|---|---|
| `MissingRequiredSection` | 必需 section 缺失 | `ToolsConfigSectionRef` + stable issue code | 用空值或旧配置补齐 |
| `InvalidTypedValue` | 类型、范围或有界性非法 | redacted issue reference | 输出 parser/backend 原文 |
| `CrossSectionConflict` | Store/UoW、feature、target、schema 互相矛盾 | 冲突 section refs | 静默选择一方 |
| `UnsupportedCapability` | adapter 缺少 required CAS/page/pair/replay 能力 | adapter slot + capability code | 隐式降级 |
| `BlockedExternalContract` | owner/schema/mapping/route 未闭口 | blocked category | 把 fake/endpoint 当 positive |
| `UnsafeOverrideAttempt` | feature/profile 试图放宽安全红线 | override code | emergency/debug bypass |
| `MissingUnitOfWorkCapability` | 无共享本地原子能力 | affected flow family | half-state 或补偿写 |
| `MissingReplaySurface` | result/receipt/report 无法持久化 | replay surface code | 从 current truth 重算 |

### 13.3 配置读取与 builder 顺序

配置装配顺序必须保持单一且可审计：

```text
ConfigSource::load
  -> parse ToolsConfigCandidate (no body/secret)
  -> attach ConfigSourceRef and redacted issue refs
  -> validate section-local typed values
  -> validate cross-section invariants and forbidden overrides
  -> validate seven Store/UoW/idempotency/replay capabilities
  -> validate adapter operation/version/authority/body policy
  -> validate enabled event/target/feature completeness
  -> produce ToolsRuntimeConfig or ToolsConfigValidationError

ToolsRuntimeBuilder::from_validated_config
  -> build seven logical Store adapters and adapter registry
  -> build one ToolsUnitOfWorkManager
  -> build IdempotencyStore and typed result/receipt/report sidecar
  -> build ClockPort and IdGeneratorPort independently
  -> build ReadVisibilityResolverPort
  -> build SharedContractAuthorityPort / Hub / Authorization adapters
  -> build SandboxExecutionPort / ExecutionSourceIntakePort adapters
  -> build SafeEventCollaborationPort and handoff target registry
  -> construct domain/application facades from owned traits
  -> construct API, worker and Job entry bundles
  -> run forbidden-boundary and total-event-key audit
  -> expose runtime bundle only after all required slots validate
```

Builder 规则如下：

1. 任一 required local Store、UoW、idempotency、Clock 或 ID slot 缺失时，不暴露 entry bundle。
2. 开放的 external seam 绑定完整的 production blocked-aware adapter；不得绑定 null、panic、silent no-op、host fallback 或未标记 fake。
3. deterministic fake 只允许在 test/fixture profile；fake 与 durable adapter 必须共享 typed error、CAS、semantic key 和 redaction 语义。
4. `api`、`worker`、`jobs` 只收到 application facade，不直接收到 Store 或 external Port handle。
5. feature flag 只能影响外围 route/job/event projection registration，不得关闭 identity、admission、audit、outcome、idempotency、Query no-write 或 fail-closed gate。
6. target ref 与 adapter ref 分离；空 target 集表示“没有目标”，不表示提交成功。

### 13.4 七个 logical Store 与技术依赖绑定

| Logical Store | 注入 trait | 必需能力 | UoW/版本约束 | 配置失败 surface |
|---|---|---|---|---|
| `ToolContractStore` | contract/history store | current bundle、immutable definition/evolution append、CAS | `(tool_id, revision)` semantic key；`Loaded<T>.expected_version` | owning command unavailable；不切换半 current |
| `CapabilityBindingStore` | relation/source store | relation、snapshot、assessment、change fact、one-current uniqueness | relation CAS；current key 唯一 | blocked/unavailable/gap；不启本地 registry |
| `ToolInvocationStore` | invocation/admission store | immutable invocation、admission、no-execution result | invocation identity/immutable anchor | no-execution unavailable/rejected |
| `ExecutionHandoffStore` | requirement/handoff/attempt store | requirement、auth/readiness、handoff、attempt CAS | generation/attempt key；Prepared/unknown fence | blocked/unavailable/manual |
| `OutcomeAuditStore` | outcome/audit store | source assessment 与 pair-atomic outcome/audit | 只能调用 `insert_outcome_audit_pair` | integrity defect；不得半写 |
| `ExternalSubmissionStore` | safe material/attempt/status store | eligibility/material、attempt、status ref append/CAS | `(material,event,target)` semantic key | ineligible/route-blocked/unknown |
| `ProjectionStore` | projection/reference/report store | gap、reference、projection、watermark、JobReport | watermark 单调；bounded page | stale/rebuilding/unavailable/failed |

`IdempotencyStore` 是技术 sidecar，不计入七个业务 Store。它必须与 typed
`StoredCommandResult`、`ConsumerReceipt`、`JobReport` 的持久化顺序相容，不能通过再次运行 flow 或
读取 mutable current truth 重建 replay surface。`ToolsUnitOfWorkManager` 是唯一 local transaction
authority；Store adapter 不得启动隐藏 transaction、自动 retry 或 compensating write。

`ClockPort` 与 `IdGeneratorPort` 独立注入。domain factory 只接收显式 time/ID 或 application factory
调用；clock 不生成 semantic identity，生成的 ID 不进入 Step 12/13 canonical digest。

### 13.5 七个 external Port 的 adapter seam

所有 Port 都由 application-owned trait 定义，具体实现位于 `infra`（`InvocationCallerPort` 保持
application-owned logical server seam）。适配器一次只做一个 logical call，并将结果映射为 typed
`PortResolution::{Available, Unavailable, Blocked, Unsupported, Conflicting, Unverifiable}` 或
`PortCallError`。任何 provider response body、credential、capture、prompt 都在 mapper 前后禁止进入
本地 surface。

| Port | planned adapter | 正向前置 | 当前生产绑定 | 测试 fallback | 禁止责任 |
|---|---|---|---|---|---|
| `SharedContractAuthorityPort` | `infra/source_resolvers.rs` | Core tools-specific schema/package/revision 已验证 | `CandidateOnly`/`Blocked`（`L2T-UP-008`） | typed candidate/resolved/conflict fake | 复制 Core schema、改变 owner |
| `HubControlledSourcePort` | `infra/source_resolvers.rs` | Hub authority、source ref、revision、summary symmetry | blocked-aware | snapshot/clue fake | local registry、关系 mutation、authorization |
| `InvocationCallerPort` | application invocation seam | canonical submit mapping | SDK seam 未闭（`L2T-UP-009`） | facade fake | loop/planning、raw prompt/body |
| `AuthorizationConsumptionPort` | `infra/source_resolvers.rs` | owner/source/schema/freshness 已正式闭合 | blocked（`L2T-UP-001~002`） | typed allow/constrained/deny fake | self-authorization、default allow |
| `SandboxExecutionPort` | `infra/source_resolvers.rs` | mapping、receipt、feedback boundary 已闭合 | blocked（`L2T-UP-003~004`） | readiness/local disposition/unknown fake | host execution、run/capture/cleanup truth |
| `ExecutionSourceIntakePort` | `infra/source_resolvers.rs` | source/mapping/correlation authority 已闭合 | blocked（`L2T-UP-003~004`） | source mapping/blocked/conflict fake | 直接推断 outcome、保存 capture |
| `SafeEventCollaborationPort` | `infra/publishers.rs` | Bus/Obs producer/source/route contract 已闭合 | route/source blocked（`L2T-UP-004~006`） | submitted/rejected/unknown fake | delivery/retry/DLQ/observed store |

Port call fence：观察型 resolver 可以在 local UoW 前按 category retry；Sandbox handoff 和 safe event
submit 必须先提交 `Prepared` marker，再调用一次 Port，最后以 phase-2 CAS 写 local disposition。
`CommitOutcomeUnknown`、`CallOutcomeUnknown`、`SubmissionOutcomeUnknown` 不允许 generic retry；必须
经同一 authority 的 `resolve_commit` 或命名人工恢复。`Prepared` 不代表 call 已发生，local submitted
不代表 delivered/observed/executed。

### 13.6 依赖分类与 fallback

| 依赖类别 | L2 表达 | Cargo 规则 | 未闭合时的安全面 |
|---|---|---|---|
| compile-time | Core shared contract candidate | 只允许逐 type 核验的 `core-contracts` path candidate | candidate-only/blocked；不复制 Tools-specific type |
| runtime | Hub/Auth/Sandbox/Runtime resolver/caller/execution Port | 不引入 sibling Cargo | blocked/unavailable/unverifiable/fail-closed |
| event collaboration | semantic event envelope + publisher/feedback Port | 不引入 Bus/Obs sibling Cargo | local attempt/status ref/route-blocked/unknown |
| handoff/export | target ref + adapter registry + one-call fence | 不把 target 当 route/delivery | local material/attempt；不升级 external acceptance |
| downstream client | canonical server contract/guidance | SDK 仅 future consumer | 不声明现成 client/coverage |

Durable adapter 必须提供 CAS、semantic uniqueness、bounded page/watermark、pair atomicity、commit
resolution 和 body-free error。deterministic fake 可以验证 local behavior，但不得被用作 provider、route、
readiness、delivery 或 observed evidence。缺 required capability 时 builder 返回 typed config error，而不是
切换到 memory/cache/file/host fallback。

### 13.7 Timeout、retry 与 degraded surface 类别

本节只固定类别，不填具体数值；后续 `04-配置设计.md` 负责格式、profile、具体值和部署绑定。

| Timeout class | 适用 | 映射 |
|---|---|---|
| `NoExternalCall` | domain、validation、Query mapper | 无 timeout/retry |
| `LocalStore` | Store/UoW/idempotency sidecar | `RepositoryError::Unavailable` 或 `UnitOfWorkError`；不得半写 |
| `ObservationalPort` | Core/Hub/Auth/readiness/status/visibility read | timeout -> unavailable/blocked assessment |
| `SideEffectPort` | Sandbox handoff、safe event submit | 有 call proof 时 local failure；无 proof 时 unknown |
| `JobSlice` | bounded Job item/runner | item retry 或 partial report；不修 truth |

| Retry class | 允许 | 禁止 |
|---|---|---|
| `None` | deterministic validation、conflict、terminal state | 所有 deterministic reject 的盲重试 |
| `SameInputBounded` | 明确 retryable 的观察读取、同 key/digest 的 redelivery | changed digest/key、semantic conflict |
| `ClaimContinuation` | 同一 claim/phase 的命名 continuation | 抢占 ambiguous claim |
| `ManualResolution` | commit unknown、Prepared、call/submission unknown | worker generic retry |
| `JobItemRetry` | Step 12 标为 retryable 的 bounded item | whole-job scan 或 truth repair |

| Degraded surface | 含义 | 绝不表示 |
|---|---|---|
| `Blocked` | owner/contract/mapping/route 未闭口 | provider success/failure |
| `Unavailable` | dependency 暂时不能回答 | allow、accepted、delivered、observed |
| `Stale` | view/ref 低于请求 watermark | current truth 或自动 refresh |
| `Rebuilding` | projection maintenance 进行中 | Query 可写 |
| `GapRecorded` | 缺失/冲突材料可归因地记录 | subject 已修复或 evidence 已签署 |
| `Unknown` | call/outcome/status 无法证明 | failure、success 或 retry permission |
| `Partial` | bounded Job 混合 item disposition | all success 或 core truth repaired |

### 14.1 观测层次与 ownership

L2 的观测面分成八层，各层有不同的事实权限：

| 层 | L2 载体 | 产生位置 | 可以表达 | 明确不表达 |
|---|---|---|---|---|
| Runtime log | structured body-free record | `api`/`worker`/`jobs`/`infra` boundary | operation、safe ref、state、error kind、duration、diagnostic ref | truth history、raw body、provider/transport body |
| Metric | counter/histogram/gauge | boundary 返回或本地状态保存后 | 低基数调用量、结果类别、耗时、freshness/availability | actor、subject、trace、secret、endpoint |
| Trace/span | `TraceContext` + boundary span | entry 到 result/error | parent/child correlation、phase、safe attrs | 新业务 identity、完整 payload、业务决策 |
| Tool audit | `ToolAuditEntry` | accepted outcome pair | invocation/anchor/judgment/source/gap/outcome refs | runtime log、Bus history、Observation store、capture |
| History/fact | evolution/change fact、assessment、gap、attempt、receipt、report | local UoW 或消费/Job UoW | 已提交的 from/to、basis、source、local result ref | 外部 owner truth、验收签署 |
| Projection/report | `ReferenceConsistencyReport`、D1 projection、`JobReport` | bounded Job target UoW | freshness、coverage、counts、output/gap refs | subject repair、readiness、实现成功 |
| External status ref | `BusDeliveryStatusRef`、`ObservationMaterialRef` | IF-04/05、JF-04 | 外部 authority/status 的 typed ref 或 unknown/blocked | local delivered/observed truth |
| Handoff marker | `ExecutionHandoffAttempt`、`ExternalSubmissionAttempt` | Prepared、one call、phase-2 | local call disposition、attempt correlation、unknown | Sandbox run/capture、delivery、retry/DLQ |

`ToolAuditEntry` 是 L2 业务审计 authority，但不是通用 audit ledger。日志和 metric 可以在 rejected、
duplicate、query 或 config error 路径产生；它们不能升级为 accepted truth。外部 status ref 只能保存
可归属的 typed reference/status-safe-summary，不能改变本地 attempt 或 outcome。

### 14.2 TraceContext 与 span 约束

`TraceContext` 的唯一输入是 `CommandMetadata`、`QueryMetadata`、`InboundEventEnvelope` 或
`JobMetadata`。入口可以在已有 context 下建立 `command`、`query`、`consumer`、`continuation`、
`job`、`uow`、`repository`、`resolver`、`collaboration` 和 `config` span；span attributes 只允许
closed kind、state、result、safe ref、count 和 duration。domain factory、Store 和 adapter 不得
生成替代 business trace，也不得把 `parent_span_ref` 当作业务 parent object。

缺少必填 context 必须在 protocol validation 阶段拒绝，不能随机生成或从 endpoint/actor 推断。
`TraceSamplingHint` 只能影响可选 span，不能抑制 required error log、required metric、已提交 fact 或
`ToolAuditEntry`。span 完成不代表 UoW commit、external delivery 或 observation 成功。

### 14.3 结构化日志埋点表

所有日志字段必须经过 typed redaction；`*_ref` 是 safe typed ref，`*_hash` 只能是不可逆 fingerprint。

| 埋点位置 | 级别 | 必填字段 | 实现断言 |
|---|---|---|---|
| Command handler entry | `info` | `trace_context_ref`, `request_ref`, `command_kind`, `actor_kind`, `idempotency_key_hash` | 只记录 metadata 关联，不记录 body |
| Command validation reject | `warn` | `trace_context_ref`, `request_ref`, `command_kind`, `error_kind`, `validation_issue_ref`, `diagnostic_ref` | 不进入 domain/UoW |
| Idempotency reserve/replay/conflict | `debug`/`info`/`warn` | `command_kind`, `idempotency_key_hash`, `reservation_state`, `replay_kind`, `error_kind` | replay 只读 stored surface |
| Accepted Command after commit | `info` | `trace_context_ref`, `command_kind`, `actor_ref`, `subject_ref`, `result_refs`, `gap_refs`, `duration_ms` | commit 未确认不得写 accepted summary |
| UoW begin/commit/rollback/unknown | `debug`/`error` | `operation`, `request_ref`, `uow_phase`, `transaction_ref`, `resolution_state`, `diagnostic_ref` | unknown 进入 manual surface |
| Query entry/completion/degraded | `info`/`debug`/`warn` | `request_ref`, `query_kind`, `surface_disposition`, `freshness_state`, `source_watermark_ref`, `gap_refs`, `duration_ms` | 不触发 write/refresh |
| Consumer reject/accept/replay | `warn`/`info` | `consumer_name`, `source_event_ref`, `event_version`, `disposition`, `local_result_refs`, `receipt_ref`, `replay_kind` | duplicate 不二次 Port/page/write |
| External resolver/feedback | `debug`/`warn` | `resolver_kind`, `adapter_slot`, `subject_ref`, `resolution_state`, `error_kind`, `retryable`, `duration_ms` | semantic blocked 与 adapter failure 分开 |
| Prepared marker | `info` | `flow_kind`, `attempt_ref`, `material_ref_or_handoff_ref`, `event_kind`, `phase` | 只证明 marker 已提交 |
| Local attempt terminal/unknown | `info`/`warn`/`error` | `flow_kind`, `attempt_ref`, `attempt_state`, `local_failure_ref`, `gap_refs`, `duration_ms` | 不写 delivered/observed/executed |
| Job claim/summary/replay | `info`/`warn` | `job_kind`, `job_key_hash`, `disposition`, `counts`, `output_refs`, `gap_refs`, `report_ref` | 不声称 scheduler run/evidence |
| Projection/status item | `info`/`warn` | `view_kind`/`status_family`, `target_ref`, `source_watermark_ref`, `status_ref`, `write_result_kind`, `resolution_state` | Bus/Observation refs 独立 |
| Config/builder failure | `error` | `config_source_ref`, `config_section`, `adapter_slot`, `validation_issue_ref`, `diagnostic_ref` | 不泄露 raw config/secret |
| Adapter availability observation | `info`/`warn` | `adapter_slot`, `adapter_kind`, `availability_state`, `failure_ref`, `checked_at` | 不升级 provider readiness |

日志级别规则固定为：accepted/replay/summary 用 `info`；validation/domain/blocked/conflict 用 `warn`；
commit unknown、rollback failure、missing stored result、ambiguous side effect 和 config reject 用 `error`；
高频 claim/resolver 细节可用 `debug`。错误字段使用 Step 12 stable category，不能把底层 stack、body 或
transport status 原文直接上抛。

### 14.4 指标与低基数规则

实现至少需要以下 backend-neutral 指标族；具体命名空间和后端由后续文档决定：

| 指标族 | 类型 | 低基数标签 |
|---|---|---|
| command total/duration | counter/histogram | `command_kind`, `result`, `error_kind` |
| truth change | counter | `truth_kind`, `subject_kind` |
| query total/duration | counter/histogram | `query_kind`, `surface_disposition`, `freshness_state` |
| consumer total/duration | counter/histogram | `consumer_name`, `disposition`, `error_kind` |
| outbound continuation | counter/histogram | `event_kind`, `attempt_state` |
| job total/item/duration | counter/histogram | `job_kind`, `disposition`, `item_result` |
| idempotency/UoW/repository | counter | `operation_group`, `reservation_result`, `uow_phase`, `repository_kind`, `error_kind` |
| external resolution | counter/histogram | `port_kind`, `resolution_state`, `error_kind` |
| projection/reference/status | counter/gauge | `view_kind`, `freshness_state`, `reference_kind`, `status_family`, `result` |
| gap/local attempt | counter/gauge | `gap_class`, `gap_state`, `impact_class`, `attempt_kind`, `attempt_state` |
| config/adapter availability | counter/gauge | `config_section`, `issue_kind`, `adapter_slot`, `adapter_kind`, `availability_state` |

禁止把 actor、subject、request、trace、correlation、result/outbox/marker/source-event、idempotency/dedup
key、payload digest、job key、free text、endpoint、topic、secret、credential 或 provider response 放进
metric label。高基数关联必须通过 structured log、span、typed ref、audit 或 report 提供。

### 14.5 业务审计与本地事实形成点

下表只复用已有对象，不新增 `AuditEvent` 聚合：

| Flow/入口 | 必须形成的 local carrier | 原子性/边界 |
|---|---|---|
| `CF-01~04` | `ToolContractEvolutionFact` + stored result | accepted UoW commit 后才可返回；duplicate 不追加第二 fact |
| `CF-05~07` | `CapabilityBindingChangeFact`、snapshot/assessment/gap | relation CAS 与 fact 在 owning UoW；不改 Hub registry |
| `CF-08` | `InvocationAdmission`；no-execution 分支的 outcome/audit pair | pair 只能经 `insert_outcome_audit_pair` |
| `CF-09~10` | `ExecutionRequirement`、auth/readiness assessment、`ExecutionHandoffAttempt` | Prepared 只表示本地 marker；不写 external accepted |
| `CF-11` | `ExecutionSourceAssessment` + `ToolInvocationOutcome`/`ToolAuditEntry` pair | source 未验证只写 assessment/gap；terminal pair immutable |
| `CF-12` | `SafeHandoffEligibility` + `SafeHandoffMaterial` | 四门未全通过不生成 material、不调用 Port |
| `CF-13` | `ConsistencyGap` state/fact | 只验证 owner repair；不修 subject truth |

`ToolAuditEntry` 必须与 `ToolInvocationOutcome` 在同一 local UoW 通过
`OutcomeAuditStore::insert_outcome_audit_pair` 成对保存。它只引用 invocation/anchor/judgment/source/gap
typed refs、actor/correlation/time；不复制 result/error body、provider response、Sandbox capture、
Observation body 或 runtime checkpoint。pair 缺失、refs 不对称或 commit unknown 时，Query 返回
integrity/unknown surface，而非“已审计成功”。

### 14.6 Redaction 与 forbidden-field 契约

以下字段在日志、span、metric、audit、fact、receipt、report、error、material 和 event envelope 中永久禁止：

- raw request/query/event/job body、prompt、capture、provider response、HTTP/RPC body、SQL；
- secret、token、credential、URL credential、完整 endpoint/topic/path；
- stack trace、broker ack/receipt/DLQ、scheduler run/lease、外部 retention record；
- local attempt 以外的 delivered、observed、executed、run、cleanup 或 readiness claim。

允许的字段仅限 closed enum、typed safe ref、one-way hash、safe summary、count、duration、watermark ref
和 redacted diagnostic ref。无法证明字段经过 typed forbidden-body guard 时，写入必须 fail closed。fake
与 durable adapter 必须共享同一 redaction contract；fake 安全输出只证明 L2 mapping，不证明外部 readiness。

| Flow family | 必须观察的切口 | 不得产生的副作用 |
|---|---|---|
| `CF-01~07` | entry、authority/Hub resolution、CAS、accepted/rejected、fact、gap、UoW | duplicate 不重写 history；blocked 不造 authority |
| `CF-08~13` | admission、requirement、Prepared、source mapping、pair、material、gap、unknown | 不把 log/marker 当 accepted/executed/delivered |
| `QF-01~11` | entry、visibility、freshness、stale/rebuilding/unavailable/failed | zero write、zero external refresh、zero repair |
| `IF-01~05` | envelope/version、claim、Port resolution、local refs、receipt、quarantine | 不直接改 core truth（IF-03 只重入 CF-11） |
| `OF-01~04` / `JF-01~04` | material/claim、Prepared、one call、phase-2、bounded report、watermark | 不写 Bus/Obs store、Delivered/Observed、subject repair 或 evidence |

### 15.3 Commands `CF-01~13` 最小切口

每个 Command 至少覆盖一次本地确定性 accepted/eligible 或 blocked-aware success，以及 invalid/domain

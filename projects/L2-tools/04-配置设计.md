## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_classification_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置分类总表”“禁止配置化项总表”“按配置域分类边界表”和“跨分类/禁止项审计表”。

### 4.1 配置类别与生效方式

| 类别 | 含义 | 示例 | P0 生效 | 主要风险 |
|---|---|---|---|---|
| `startup` | runtime builder 前加载并冻结 | Stores、adapters、profile、features | 支持 | partial graph/漂移 |
| `entry-local` | 只选择当前 API/worker entry 的完整 snapshot | profile/source selector、query bound selector | 支持 | 越权覆盖 global |
| `job-startup` | Job 开始前冻结 bounded scope/target/limits | batch、target snapshot、job retry class | 支持 | mid-run drift/whole scan |
| `store-binding` | 选择既有 logical Store/UoW capability | adapterRef、bindingRef | startup | atomicity/second truth |
| `adapter-binding` | 选择既有 Port adapter/mode/ref | blocked-aware/ref | startup | endpoint-as-ready/host bypass |
| `bounded-runtime-parameter` | 有界技术参数或 category | page、batch、timeout/retry/retention policy ref | startup/entry/job | unbounded/semantic override |
| `feature-registration` | 只注册外围 runner/route/status | outbound/projection/status flags | startup | 关闭核心 gate |
| `policy-binding` | 选择已登记安全/phase policy | bodyPolicyRef、phasePolicyRef | startup/static | 放松红线 |
| `sensitive-locator` | typed opaque locator，不含材料 | Store/target/connection/cert ref | startup/job | topology/credential泄露 |
| `test-only-deterministic` | 显式 Local/CI fixture、Clock/ID | deterministic refs | test assembly | fake进入real-like |
| `diagnostic` | body-free、低基数诊断类别 | diagnosticClass | startup/static | raw/high-cardinality |
| `static/design-invariant` | 设计不变量，不是普通配置 | `NC-L2T-*`、no-write、one-call | 不可覆盖 | 误配置成开关 |

P0 不支持 `reload`、`hot`、config center、admin override、watcher、online LKG 或 generic CLI value override；出现对应 key/source 直接 reject。

### 4.2 禁止配置化项

| 禁止项组 | 具体边界 | 改变路径 |
|---|---|---|
| truth/identity | Tool identity、definition、invocation、admission、outcome/audit ownership；ToolId/revision生成 | 需求/03 domain/flow controlled reopen |
| dependency/authority | Core compile、Hub/Auth/Sandbox/Bus/Obs/SDK owner和依赖裁剪 | upstream owner/ADR/03/04/07重审 |
| authorization | Hub visibility/inventory 不得当 authorization；不得 default allow/self-authorize | Authorization owner/schema正式变更 |
| body/secrets | raw prompt/request/capture/provider response/external body/secret/credential/stack trace | 安全和数据边界正式变更；不允许 debug例外 |
| admission/execution | admission-before-execution、Sandbox-required、no host/direct bypass | Sandbox/Auth owner与03 phase/Port变更 |
| handoff/status | local attempt不等 accepted/run/receipt；delivery/observed独立于local truth | external owner/03 phase contract |
| outcome/audit | source assessment、single terminal outcome、outcome/audit pair atomicity | 03 Store/UoW/outcome重设计 |
| async/query | Query no-write、Consumer no-core-write、Job no-repair、projection不替代truth | owning Command/03 flow/state变更 |
| state/concurrency | state vocabulary、append-only/immutable、CAS、semantic key、digest/replay、unknown/manual fence | 03 state/persistence/concurrency重设计 |
| responsibility | runtime planning/orchestration/retry/recovery、Sandbox recovery、Bus retry/DLQ/replay | 回到相应 owner；不增加 L2 switch |

以上分组覆盖 `NC-L2T-001~025`。任何 profile、feature、debug、emergency、adapter override 都不能放宽。

### 4.3 `NC-L2T-001~025` 显式禁止配置化对照

| ID | 不可配置化边界 | validator / builder 必须拒绝的尝试 |
|---|---|---|

| `NC-L2T-002` | Core compile、Hub/Runtime/Sandbox runtime、Bus/Observability event collaboration 的依赖裁剪 | 用配置引入 sibling、反向依赖或第二条协作主链。 |
| `NC-L2T-003` | `ToolId`、definition identity、revision identity 的生成规则 | 用 Clock/ID adapter 改变 semantic identity。 |
| `NC-L2T-004` | current definition 只能由 formal establish/assess/adopt/retire flow 变化 | 以配置、alias 或 reload 直接切换 current definition。 |
| `NC-L2T-005` | Binding active/explicit-unbound/history 语义 | 以 adapter availability 或 feature 改写 Binding truth。 |
| `NC-L2T-006` | Hub visibility/inventory 不得当 authorization | 以 Hub 可见、inventory 命中或 local fake 推导 allow。 |
| `NC-L2T-007` | caller/carrier 共用 canonical invocation/result/error 语义 | 按 entry/profile 定义第二套 DTO 或错误语义。 |

| `NC-L2T-010` | authorization missing/stale/conflicting/unverifiable 必须 fail closed | default allow、旧 decision fallback 或 fake allow。 |

| `NC-L2T-012` | Sandbox-required 不得 host/direct bypass | 启用 host callback、direct executor 或本地兜底执行。 |
| `NC-L2T-013` | local handoff/attempt 不等 external accepted/run/receipt | 由 target/ref/health/local attempt 推导外部状态。 |
| `NC-L2T-014` | source 经 authority/correlation/mapping assessment 后才能 normalized outcome | 直接把 provider/source body 映射为 terminal outcome。 |
| `NC-L2T-015` | 每个 invocation 只有一个 immutable terminal outcome | 允许覆盖、重建或追加第二终态。 |
| `NC-L2T-016` | outcome 与 `ToolAuditEntry` 必须同一 UoW 原子收口 | 拆分 Store/UoW、补偿写或允许半成功。 |
| `NC-L2T-017` | safe handoff 必须同时 minimal、body-free、redacted、correlated | 放宽任一安全检查或启用 raw diagnostic。 |
| `NC-L2T-018` | local outcome/audit first；submission/delivery/observation 不参与终态 | 让外发、delivery 或 observed 决定 local terminal truth。 |
| `NC-L2T-019` | Bus delivery 与 Observation status 分离 | 合并 route/delivery/observed status 或互相推断。 |
| `NC-L2T-020` | Query no-write、Consumer clue no-core-write、Job no-subject-repair | 以 feature/profile 开启异步或读路径写 core。 |
| `NC-L2T-021` | gap resolution 需 subject owner formal repair 后由 L2 验证 | Job 自动修复或自动关闭 gap。 |
| `NC-L2T-022` | projection/report stale/unavailable 不得替代 core truth | Query live fallback、projection repair 或 report-as-truth。 |
| `NC-L2T-023` | 状态词表、合法迁移、append-only/immutable 纪律 | 自定义状态、跳转、overwrite 或 history rewrite。 |
| `NC-L2T-024` | logical/candidate/pending/blocked/fake 不等于 implementation ready | 由 profile、fake、ref 或 health marker 产生 readiness。 |
| `NC-L2T-025` | runtime planning/orchestration/retry/recovery、Sandbox recovery、Bus retry/DLQ/replay 不归 L2 | 增加 agent loop、scheduler、generic retry/recovery 或 DLQ 开关。 |

### 4.4 分类边界审计

| 审计项 | 结论 |
|---|---|
| 同一行为在不同分类是否冲突 | 无 unresolved；timeout/retry 使用 bounded category，sensitive ref 不进 ordinary override。 |
| P1/P2 是否污染 P0 | 未污染；production positive、config center、hot/reload 只作 inactive/reject/future。 |

| feature 是否关闭核心 identity/admission/outcome/audit/idempotency/no-write | 不允许。 |
| 当前是否影响 `03` | 无回写；future lifecycle/root 变化先回写。 |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“来源通道与覆盖顺序”“来源优先级与冲突处理总表”“21 个配置域来源矩阵”和“跨来源冲突审计”。

### 5.1 普通来源覆盖链

```text
[code defaults: safe bounded non-sensitive only]
        <
[strict JSON file: canonical candidate]
        <
[allowlisted environment: canonical leaf only]
        -> [typed parse/validate]
        -> [ToolsRuntimeConfig or typed error]
```

`R`（opaque secret/connection/certificate ref）、`X`（显式 Local/CI fixture）和 `L`（entry/job snapshot selector）不参加普通值的第四/第五层覆盖。P0 不支持 config center、admin、generic CLI value、watch/reload 或 online LKG。

### 5.2 来源规则

1. code default 只能填不创造事实的非敏感、有界 category/value；required Store/UoW/adapter/ref 没有隐式 default。
2. JSON 必须是严格 JSON；duplicate key、unknown field、未登记 alias、null 替代必填、类型 coercion、raw secret 均拒绝。
3. allowlisted env 只能覆盖已登记 canonical leaf；存在但非法时直接 fail-fast，不回退 file/default。
4. opaque ref 只能是已登记 typed locator；真实材料不进入 candidate、日志、错误或审计正文。
5. fixture 只在显式 Local/CI profile；不得因普通 source/adapter 不可用而静默切换 fake。
6. entry-local 只能选择完整 validated profile/source snapshot 或 Job snapshot；不能逐字段覆盖 global runtime、metadata、identity、actor、cursor、idempotency key 或 target。
7. unsupported source/key 产生 `UnsupportedCapability` 或 `UnsafeOverrideAttempt`，不静默忽略。

### 5.3 冲突处理表

| 冲突场景 | 处理 | 结果 |
|---|---|---|
| 同一 JSON object duplicate key | parser 拒绝，不 last-write-wins | startup fail-fast |
| canonical key + unknown alias | 拒绝 alias，不猜迁移 | startup fail-fast |
| 两 env 名映射同一 canonical item | ambiguous source reject | startup fail-fast |
| file + 合法 env | env 覆盖 file并记 safe source class | 继续校验 |
| file + 非法 env | 不回退 file | startup fail-fast |
| 缺失且有安全 default | 使用 default并记 source class | 继续校验 |
| required item 无有效来源/ref | 不用空值、旧配置、缓存 | startup fail-fast |
| feature enabled 但 adapter/target缺失 | cross-section conflict整体拒绝 | fail-fast/blocked按既有规则 |
| entry selector 与 profile identity不一致 | 只拒绝当前 entry/job | global runtime不变 |
| ordinary field 与 secret lane冲突 | sensitivity conflict reject | startup fail-fast |

### 5.4 21 个配置域来源矩阵

约定：`D/F/E` 为 code default、strict JSON file、allowlisted environment；`R` 为 opaque ref lane；`X` 为显式 Local/CI fixture；`L` 为 entry/job 完整 snapshot selector。`R/X/L` 不进入普通来源覆盖顺序。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“敏感级别归一规则”“敏感配置读取图”“敏感配置总表”“读取、生命周期与轮换规则”“禁止输出规则”和“跨敏感配置泄露风险审计”。

### 8.1 敏感级别

| 规范级别 | L2-tools 定义 | Step 7 标签 | 允许输入 | 输出规则 |
|---|---|---|---|---|
| `public` | 无 topology/identity/credential 意义的 closed technical label | public | 按字段允许 D/F/E/X/L | 仅 fixed allowlist。 |
| `internal` | 非秘密但具有运行含义的 bounded parameter/category | internal | protected JSON/env | 只输出 category/section，不输出原值。 |
| `sensitive` | topology、adapter/store/target/policy identity 或 provider locator | sensitive-ref、secret-ref-only | typed opaque ref only | 禁 full value；仅 slot/kind/safe projection。 |
| `secret` | 可授权或含受保护正文的材料 | 不得成为配置项 | 不允许进入 L2 config | 任意 L2 output surface 均禁止。 |

`secret-ref-only` 表示“只能保存 locator，禁止内联 material”。password、token、private key、certificate/trust body、DSN credential、URL userinfo、provider response、raw endpoint body 都是 `secret` non-item。

### 8.2 敏感配置读取图：ref-only startup binding

```text
[protected strict JSON / allowlisted env]
              |
              | typed opaque ref only
              v
[infra/config loader + safe source attribution]
              |
[type/profile/family/cross-section validation]
              |
[validated ref + redacted config identity]
              |
[runtime builder -> pre-registered adapter/target/policy registry]
              |
[typed Store/UoW/Port/Clock/ID handle]
              |
[complete runtime graph exposed]

Never enters candidate/runtime/output:
raw token/password/private key/cert body/DSN credential/provider body
```

这里的 registry 仅是 `03` 已定义的 composition seam，不是 L2-owned capability registry 或 secret store。Loader/validator 不解析材料；builder 只用 validated ref 选择已登记 handle。ref 合法也不证明 provider authority、readiness、delivery 或 observation。

### 8.3 敏感配置总表

| 配置项 / 配置组 | 级别 | 存储 | 轮换方式 | 审计要求 |
|---|---|---|---|---|
| seven `stores.*.adapterRef` | sensitive | protected source 中 typed ref | 新完整 Store graph + restart | slot/kind/safe digest/result；无 full ref。 |
| `stores.uow.bindingRef` | sensitive | typed capability ref | 与七 Store 原子重装配 | pair/CAS capability class/result。 |
| idempotency adapter refs | sensitive | typed sidecar ref | 与 retention/replay 同组重装配 | sidecar/replay class/safe digest/result。 |
| `adapters.core.adapterRef` | sensitive | typed adapter ref | 新 blocked-aware binding + restart | slot/blocked category/result；不称 ready。 |
| `adapters.visibility.adapterRef` | sensitive | typed resolver ref | 新 resolver graph + restart | slot/result/safe issue；无 scope material。 |
| `adapters.bodyPolicyRef` | sensitive | typed policy ref | 只可等强或收紧；新 assembly | policy class/safe digest/result。 |
| `handoff.targetRefs` | sensitive | bounded typed ref list | startup registry；Job 选 validated snapshot | count/class/set safe digest；无 endpoint。 |
| `clockId.clockRef/idGeneratorRef` | sensitive | typed adapter ref | 新 assembly；deterministic 仅 CI | slot/profile/result；无 seed/time body。 |
| `features.redactionFloor` | sensitive when external | typed policy ref | 只可等强或收紧；新 assembly | floor class/result/issue ref。 |
| credential/cert/provider materials | secret non-item | provider-owned only | provider/ops 动作后新 assembly | provider-owned audit；L2 仅引用 safe ref。 |

### 8.4 Profile、生命周期与轮换

| Profile | 允许 | 禁止 | 不可用时 |
|---|---|---|---|
| `local-dev` | local/deterministic/fake typed refs | raw secret、隐式 real credential、未标记 fixture | required ref/capability fail-fast。 |
| `ci-test` | run-scoped fixture/Clock/ID refs | 真实 secret、production target、fake-as-ready | test assembly 不成立。 |
| `integration-like` | controlled adapter/target refs | raw material、CI fake fallback、endpoint-as-ready | local binding fail-fast；external gap blocked。 |
| `staging-like` | future approved opaque refs only | 当前启用、fixture、raw material | inactive/blocked。 |
| `production-like` | 当前无成功配置 | 所有 fake/fixture/ref-only readiness claim | inactive/blocked。 |

P0 全部 startup-frozen。轮换必须创建完整新 candidate，重走全量 validation/build，再由部署 owner 切换 assembly；不在线替换旧 graph。旧 Job、attempt、receipt、result、report 均不改写。compromised/revoked/expired material 只能 fix-forward，不能回滚复活。

### 8.5 审计与禁止输出

| 输出面 | 允许字段 | 禁止字段 |
|---|---|---|
| validation log/error | source ref、section、slot、profile、issue kind/ref | raw config/value、full ref、secret、parser/backend body、stack。 |
| metric/span | section、slot、result、issue class、low-cardinality availability | address/target/actor、secret-derived hash、高基数 body。 |
| config change audit | actor/change/reason refs、section、activation kind、safe digest、result、rollback ref | raw old/new document/diff、full ref、material、provider response。 |
| `ToolAuditEntry` | 仅 `03` 已允许的业务安全字段 | config ref/material；配置审计不得混入业务审计。 |
| event/receipt/report | 既有 body-free carrier、safe ref/count | config body、target credential、secret、provider body。 |
| document/demo | symbolic non-operational refs | 真实 endpoint、credential、route、evidence alias。 |

输出使用固定 allowlist，不使用“先打印后正则脱敏”。无法证明字段已通过 typed redaction/forbidden-body guard 时必须 fail closed。secret-derived digest 永远禁止；sensitive ref digest 仅在 canonical safe projection 已定义时允许，否则省略。

敏感域审计通过：raw material 不进入 JSON/env/demo/candidate/runtime；locator 统一为 sensitive；没有新增 secret resolver；fake 只限显式 Local/CI；轮换不修改 in-flight truth；ref 不升级 readiness/evidence。Future 若引入 material resolver、credential-bearing constructor 或 live rotation，必须先回写 `03`。

### 10.5 回滚规则

| 作用域 | 失败/异常 | 回滚 | 禁止 |
|---|---|---|---|
| startup | validation/builder/activation owner失败 | previous approved candidate 全量重校验/装配/切换 | partial graph、skip validation、invalid fallback |

## 11. 失效模式与降级 / fail-fast 策略

### 11.1 失效语义词表

| 语义 | 定义 | 适用 | 绝不表示 |
|---|---|---|---|
| `fail-fast` | candidate 或 required local capability 无效，阻止 assembly/scope 启动 | parse/type/Store/UoW/replay/Clock-ID | degraded ready 或旧/default继续 |
| `fail-closed` | 安全/authority 前置不可证明，拒绝危险动作 | auth/source/body/redaction/visibility | deny truth、provider failure、可重试许可 |

| `entry/job reject` | global graph有效，但当前 selector/scope/target无效 | entry-local/job-startup | global graph 被修改 |

### 11.4 告警安全字段

| 场景 | 允许 | 禁止 |
|---|---|---|
| validation/builder reject | source ref、profile、section、slot、issue kind/ref、safe digest | raw JSON/env/full ref/secret/backend text |
| unsafe override/raw secret | forbidden class、section、issue ref | attempted value/hash |
| external blocked/unavailable | slot/kind、availability/blocked category、diagnostic ref | endpoint/provider body/readiness claim |
| projection degraded | query/view/freshness class、gap refs | subject/body/high-cardinality key |
| side-effect unknown | phase、attempt/material safe ref、resolution state | request/response/target credential |
| config drift | expected/actual safe digest、profile | raw diff/config body |

这里的“应观测”是下游实现与测试要求，不声明当前已有告警、阈值、SLO 或运行结果。跨策略审计确认：config-invalid、blocked、unavailable、degraded、unknown、partial 不混淆；高风险无 silent fallback；没有新增 `03` failure state/error variant。

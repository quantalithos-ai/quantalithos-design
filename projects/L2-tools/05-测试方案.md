> 校准来源：

> 延伸阅读：

### 2.1 测试目标

本方案验证 L2-tools 作为 runtime 行动契约层是否在当前边界内形成可落码、可追溯、可安全交接的本地真相链：

- tool identity、definition、contract evolution 和 terminal history 稳定且不被 capability/provider/inventory 替代；
- Capability Binding 只保存正式 relation、snapshot、assessment、gap 和 CAS 事实，不复制 capability registry 或把 visibility 当 authorization；
- canonical ToolInvocation/admission 独立于 caller、carrier、runtime action、LLM planning 和 agent loop，拒绝/不可用路径不执行；
- authorization、Sandbox requirement、Prepared/one-call/phase-2 和 unknown fence 在执行前置与交接边界闭合；
- `ToolInvocationOutcome`、`ToolAuditEntry`、safe handoff material 和 local submission disposition 形成原子、body-free、可回链的本地事实；
- Query zero-write/zero-refresh/zero-external-Port，Job bounded/no-repair，Bus/Observability 状态不反写本地终态；
- 七模块、五类协议族、六状态族、事务/UoW/CAS、幂等/并发/replay、错误恢复、配置装配和观测红线均有可执行测试入口；
- 失败、blocked、unknown、not_evaluated、invalid artifact 和 residual 不被伪装成 pass、accepted、delivered、observed 或 readiness。

### 2.2 范围表

| 范围项 | 类型 | 优先级 | 验证目标 | 非目标 / 说明 |
|---|---|---:|---|---|
| `contracts`、typed refs、metadata、protocol carriers | 契约/对象 | P0 | 字段、kind、version、body-free、错误和 roundtrip 稳定 | 不实现 shared Core schema |
| `domain` identity/definition/evolution/binding/invocation/precondition/outcome/handoff/integrity | 领域规则 | P0 | 不变量、状态、terminal、digest、safe handoff 和 source separation | 不拥有 Hub/Auth/Sandbox truth |
| `application` facade、Store/UoW/Port 编排 | 服务/一致性 | P0 | CF/QF/IF/OF/JF 顺序、写集、CAS、pair、phase/unknown | 不做 runtime orchestration 或 agent loop |
| `infra` Store、UoW、idempotency/replay、adapter seams | 集成 | P0 | append/CAS/page/watermark、commit outcome、fake parity、blocked mapping | durable provider 选择未定 |
| `api`、`worker`、`jobs` entry | 协议/入口 | P0 | metadata、envelope、source/version、claim/receipt、bounded/no-repair | 不验证下游内部实现 |
| Query/projection/visibility | 读模型 | P0 | Found/NotFound/NotVisible/Stale/Unavailable 分型，zero-write | 不在 Query 中 rebuild/repair |
| configuration V0~V8/B0~B8、CFG-T/A/F/X | 配置/安全 | P0 | strict parse、source/profile isolation、fail-fast、no partial graph、redline | 不新增配置 key 或部署值 |
| observability/audit/redaction | 横切安全/审计 | P0 | safe fields、low cardinality、TraceContext、pair/status separation、forbidden sweep | 不拥有 Observability store/route |
| Hub/Auth/Sandbox/Bus/Observability/Core/SDK typed seams | 外部接缝 | P0 negative / P1 positive conditional | blocked/unavailable/unknown/no-host/route gap 和 carrier parity | 不测对方完整实现或 readiness |
| provider positive、Sandbox receipt/cleanup/DLQ、Bus delivery、Observed、SDK client | 外部能力 | P1/P2/future | 仅在 owner 闭合后条件启用 | 当前不进入 P0 positive denominator |
| production-like、容量、P95/P99/QPS/SLA、长期 retention | 非功能扩展 | P2/future | 只保留方法和 residual | 无 measurement authority，不写数字结论 |
| agent loop、LLM planning、runtime orchestration、marketplace/UI/具体工具库存 | 非范围 | excluded | 不在 L2-tools 测试 | 由对应 owner/下游文档负责 |

### 2.3 优先级与阻断口径

| 级别 | 纳入条件 | 未来执行口径 |
|---|---|---|
| P0 | 当前 `03/04` 可由 deterministic fixture/fake 断言，失败破坏 truth、边界、一致性或安全 | 缺失、失败、unverifiable、invalid artifact、redaction 或 mandatory check 失败均阻断对应 gate |
| P1 | 外部 owner typed seam 已有本地契约，但 positive provider 尚未闭合 | blocked/unavailable/unknown 单列；owner 闭合后才可启用 positive |
| P2/future | production-like、量化测量、SDK、生态或产品深度行为 | 不进入 P0 denominator；记录 residual、owner 和 reopen trigger |

一票否决 `VF-L2T-001~013`、P0 truth/security/consistency/evidence/dependency/config redline 不得风险接受。

## 4. 测试策略与分层

> 校准来源：

>
> 延伸阅读：

#### 测试分层图: L2-tools 测试金字塔

```text
                    [E2E / release smoke]
              local truth-first minimal closure
             (conditional external seam only)
                           |
                 [API / Worker / Job contract]
            metadata, envelope, version, receipt,
              bounded scope and response mapping
                           |
                    [Adapter integration]
       Store/CAS/UoW/idempotency + fake/durable parity
             + blocked external Port resolution
                           |
                    [Application service]
       CF/QF/IF/OF/JF order, phase fence, no-write,
                replay, error and recovery mapping
                           |
                       [Domain / contract unit]
      refs, fields, invariants, state transitions, safety,
                canonical digest and redaction predicates
```

关键说明：

- 每层只断言该层拥有的事实；高层不重新定义下层 oracle。
- E2E 只证明本地 truth-first 最小闭环，不证明 provider、Bus delivery、Observed 或 production readiness。
- release smoke 是 planned suite，不表示已执行或已通过。

| 层级 | 目标 | 典型内容 | 执行时机 | 失败处理 |
|---|---|---|---|---|
| `L0-contract-unit` | typed ref、metadata、version、body-free、safe error | FOUNDATION、协议构造负向 | PR | P0 阻断 |
| `L1-domain-unit` | invariant、状态、terminal、四门、digest、pure mapper | STATE、NC、对象 factory | PR | P0 阻断 |
| `L2-service` | flow order、UoW、CAS、replay、error、no-write | CF/QF/IF/OF/JF service cuts | PR/main CI | P0 阻断；unknown 保留 |
| `L3-adapter-integration` | Store/Port/UoW、fake parity、blocked mapping | infra、TX、CONC、CFG | main/nightly | P0 阻断；外部不可用单列 |
| `L4-entry-contract` | metadata、envelope、version、receipt、bounded entry | API/worker/job | PR/main CI | P0 阻断 |
| `L5-cross-module` | DTO 到 local outcome/audit/handoff 的组合 | local closure、carrier parity | main/nightly | P0 阻断 |
| `L6-e2e-smoke` | 最小本地闭环和跨入口一致性 | selected `C-L2T-*` paths | 条件 release | 当前不执行 |
| `L7-conditional-provider` | owner 闭口后的 positive seam | Hub/Auth/Sandbox/Bus/Obs/SDK | 条件 nightly/staging | blocker 时 `blocked_dependency` |

失败处理统一区分 `failed`、`blocked_dependency`、`unavailable`、`unknown`、`not_evaluated`、`invalid_artifact` 和 `cancelled`；不得自动重试或改名为 pass。

### 6.2 共同 oracle 与禁止断言

| 共同规则 | 断言 |
|---|---|
| Oracle priority | `03` 正式字段/enum/flow/state/error > `03` §15 > `04` 配置契约 > `00` 需求方向；旧 05/06 和外部 positive 猜测不进入。 |
| Determinism | 使用 §7 typed fixture、fixed Clock/ID、canonical digest、Store/UoW/Port spy；不以 wall clock、随机值或字符串状态判定。 |
| Transaction | 检查 exact write set、StoredResult/Receipt/JobReport、CAS token、commit known/unknown 和 rollback；不只检查返回值。 |
| External effect | CF-10/CF-12/OF 必须 Prepared commit 后最多一次 Port call，再做 phase-2 local disposition。 |
| Query/Job | Query zero-write/zero-refresh/zero-Port；Job bounded/no-repair，partial disposition 保留。 |
| Evidence | 每个 case 预留 candidate EV；只有 §13 fixed-run raw/report 可派生实例。 |

| 禁止断言 | 正式替代断言 |
|---|---|
| local attempt 推导 `Delivered`/`Observed` | `SubmittedLocally` 或对应 local disposition + 独立 status ref/gap |
| endpoint/ref/health marker 推导 `Accepted`/ready | `Blocked`/`Unavailable`/`Unverifiable` 或正式 `PortResolution` |
| 通用 `Completed` 作为所有终态 | 使用具体状态族正式 enum 和当前 phase terminal |
| raw stdout/provider body 等于 tool outcome | `ExecutionSourceAssessment` + `ToolInvocationOutcome` |
| Query/Job 成功后修复 truth | no-write/no-repair + `Stale`/`Partial`/`Failed` surface |
| unknown 自动 retry | `CallOutcomeUnknown`/`SubmissionOutcomeUnknown`/`CommitOutcomeUnknown` + manual/resolve fence |

### 7.1 Dataset manifest contract

每个逻辑数据集必须实现下列 manifest；这是未来 fixture/runner 的设计合同，不表示当前已有数据文件或数据库。

| 字段 | 规则 |
|---|---|

| `test_case_ids` | 一个或多个稳定 TC ID；合计必须覆盖该 family 的完整编号范围。 |
| `scenario_id` | `<dataset_id>/<positive|negative|boundary|concurrency|recovery>/<token>`。 |
| `test_run_ref` | future opaque run namespace；本文不分配真实值。 |
| `clock_vector` | 固定相对时间向量；禁止 wall clock 或 sleep 推进。 |
| `typed_id_vector` | 按 object/ref kind 分区的 deterministic ordinal；禁止裸字符串替代 typed ref。 |
| `metadata_vector` | actor/source/correlation/trace/scope/idempotency 的正式 metadata 变体。 |
| `seed_frame` | canonical object/protocol/Store row/UoW marker typed baseline。 |
| `mutation_or_fault` | 相对 baseline 的单变量 mutation 或命名 fault phase。 |
| `expected_surface` | 正式 state/error/view/result/receipt/report 类型；不是测试结果。 |
| `effect_probe` | expected write set、Port call、UoW outcome、history、redaction count。 |
| `substitute_profile` | `pure`、`contract_fake`、`controlled_script`、`disabled` 或 conditional `real_like_candidate`。 |
| `cleanup_profile` | `pure_reset`、`run_drop`、`fake_reset`、`corpus_delete` 或 future durable cleanup。 |
| `sensitivity_class` | `safe`、`body_free`、`dummy_forbidden`；不允许真实 secret/body。 |

### 7.2 Deterministic primitive registry

| Primitive | 提供内容 | 允许 | 禁止 / 清理 |
|---|---|---|---|
| `TD-L2T-RUN` | opaque test namespace、case/scenario partition | future run-scoped isolation | 禁止 global singleton/真实 run ID/跨 case key；drop namespace |
| `TD-L2T-CLOCK` | fixed `T0` 与 phase-relative vector | explicit ClockPort injection | 禁止 system time/sleep；reset vector |

### 9.4 Closed execution status

| Status | 含义 | Gate behavior |
|---|---|---|
| `passed` | suite full denominator 执行且全部 oracle 成立 | 只对该 run/suite/profile 有效；不等验收/readiness |
| `failed` | 至少一个 executed case oracle 不成立 | blocking suite 阻断；保留失败材料 |
| `blocked_dependency` | 所需 owner/schema/mapping/route open | 不算 pass；negative suite 可继续；positive gate blocked/skipped |
| `not_evaluated` | 未运行、被过滤、环境 invalid 或不可判定 | 不算 pass；formal gate 阻断 |
| `invalid_artifact` | raw/context/pair/schema/redaction 不合规 | 即使 process exit 0 也阻断 |
| `cancelled` | external cancellation/infrastructure interruption | 不算 pass；新 run 重试；旧记录不改 |

不存在 `flaky_pass`、`expected_fail_as_pass`、`latest_pass` 或 `health_ready`。任何重跑都创建新 run，不覆盖旧 artifact，也不择优拼接多个 run。

Suite/gate aggregation precedence is fixed as `invalid_artifact > failed > blocked_dependency > cancelled > not_evaluated > passed`. Denominator/schema/digest/path/pairing/redaction integrity is checked first; an integrity failure yields `invalid_artifact`. Otherwise select the first present child status in that order. `passed` requires every declared case/suite/check to be present and passed; an empty or incomplete denominator never passes.

Acceptance generators 只由 `release_gate.sh` 对一个 fixed run 调用，并且只写 run-scoped `acceptance-draft`；其它 formal gate 不生成或发布 acceptance projection。release publisher 在全部 required check（含对 staging tree 的 redaction check）完成后，对 `reports/acceptance/.projection.lock` 执行 non-blocking OS advisory exclusive lock，逐个以 same-directory temporary file + single-file replace 把四份已扫描的 exact bytes 投影到 `reports/acceptance/*.md`，最后以同样的单文件替换写 `reports/acceptance/projection-manifest.json` 作为唯一 publication marker。锁从第一次 fixed-path 写入前一直持有到本 run `gate-summary.json` 写完；publisher 必须持有打开的 lock descriptor，文件存在与内容都不表示已加锁，该文件也不进入 evidence/digest/retention。lock acquire 失败不得等待后偷偷并发发布，而以 `invalid_artifact` 结束本 run。manifest 绑定 source run、index digest、四个 staging/published path 与 exact-byte digest；它不是多文件原子替换声明。发布中断、文件/tuple/digest 不一致或 manifest 缺失时，固定视图整体为 `invalid`；finalizer 写入 diagnostic invalid release seal（无 manifest ref/digest、所有 eligibility item 为 `invalid`），而不是可消费 seal。run-scoped staging 与旧 run facts 仍保留，但不得声称旧固定视图仍可用；任何重生成使用新 release run。

Raw root 固定为 `artifacts/test/<run_id>/suites/<suite>/`，human suite report 固定为 `reports/runs/<run_id>/suites/<suite>.md`。所有 P0 suite 都使用该配对；`conditional-provider` 和 `release-local-smoke` 也不得获得静态 evidence slot 或省略 fixed-run context。

### 11.1 Severity and execution status

| Severity | 定义 / 典型触发 | 处置 | Release blocking |
|---|---|---|---|

### 11.2 Direct S triggers

这些触发分别由 `VETO`、`FOUNDATION/CONTRACT/BIND/INV/PRE/OUTCOME/HANDOFF`、`QUERY/JOB/OBS`、`TX/CONC/ERR` 和 `CFG-F/X` concrete cases 证明，不能以 B/R 或 residual 接受。

| dependency/evidence | original VETO/static + history/package/pairing | static；dependency/pair/no-static checks | no sibling compile；fixed-run linkage；no static pass |

修复必须使用新 fixed run；原 failure artifact/report 保持只读，不覆盖、不改 status、不择优拼接。设计阶段不创建 defect ID 或 run。

### 11.4 Risk acceptance and closure evidence

- S、任一 VF、P0 redaction/dependency/evidence/config-safety 均不可接受。
- P0 blocking failure 原则上不可接受；若独立证据证明只是 harness fault，可暂列 A，但仍阻断相关 gate 直至修复。
- open upstream 只能 `blocked_dependency`，不计 pass；P1 real-like 可作为 residual；P2/future/capacity/SDK 可列 R。
- 无 measurement authority 的 sample 只作 B/R provenance input，不能按旧数字开缺陷或宣布通过。

future closure record 必须包含 defect identity/scope/trigger TC/suite/status、修复设计来源与范围、新 run case/suite/check artifacts、相关 redaction/dependency/phase/pair result 和防回归变更。若曾执行，还须保留 failure run；S 不允许用 risk acceptance 关闭。本文不生成这些实例。

手工发现 P0 必须固化到既有或经重开 Step 6 后新增的 concrete TC、dataset 和主 suite；release 才发现的低层缺陷必须下沉；scanner/dependency/evidence/duplicate 漏检必须扩展对应 corpus/check。不得仅保留人工 checklist。

### 13.4 Planned raw artifact DTO、schema 与 digest

这些 schema 是 `test_support::artifacts` 拥有的 local test-infrastructure DTO，不进入 public contracts、domain 或业务持久化。gate supervisor、suite/check runner 必须通过共享 serializer 写，report/check/06 consumer 必须通过共享 parser 读；禁止各 binary 自建兼容 schema。

#### 13.4.1 Common envelope and encoding

| Field | Required | Type / closed value | Rule |
|---|---|---|---|
| `schema_version` | yes | string=`l2-tools.test-artifact.v1` | mismatch=`invalid_artifact`；no version fallback |
| `run_id` | yes | non-empty opaque string | non-`latest`；all refs same run |
| `artifact_digest_algorithm` | yes | string=`sha256` | only supported P0 algorithm |
| `artifact_digest` | yes | `sha256:<64 lowercase hex>` | digest of this object after omitting top-level `artifact_digest` only |

Shared closed enums:

| Enum | Values |
|---|---|
| `L2TestArtifactStatus` | `passed`,`failed`,`blocked_dependency`,`not_evaluated`,`invalid_artifact`,`cancelled` |
| `L2AssertionStatus` | `passed`,`failed`,`blocked_dependency`,`not_evaluated` |
| `L2RedactionStatus` | `clean`,`failed`,`not_evaluated` |
| `L2SourceStatus` | `committed`,`uncommitted`,`not_available` |
| `L2WorkspaceStatus` | `clean`,`dirty`,`not_available` |
| `L2DerivationStatus` | `derived`,`ineligible`,`unavailable`,`invalid` |
| `L2EvidenceStatus` | `eligible`,`ineligible`,`unavailable`,`invalid`,`pending_review` |
| `L2JournalKind` | `effect`,`call`,`cas`,`uow`,`provenance` |
| `L2JournalEventKind` | `begin_uow`,`read`,`write`,`append`,`cas`,`commit`,`rollback`,`port_call`,`port_return`,`emit`,`projection_write`,`job_target`,`no_op` |

Digest input 是省略顶层 `artifact_digest` 后的 canonical UTF-8 JSON；`artifact_digest_algorithm` 仍参与计算。object keys 按 Unicode code point lexicographic order，array 保持 stored order，无 insignificant whitespace，number 用最短 JSON 十进制且禁止 NaN/Infinity，string 用标准 JSON escaping，文件末尾无附加换行。语义集合在写入前按 canonical ref 升序去重；assertion、journal entry 和 derivation source 等有序记录不得重排。

`stdout.log`/`stderr.log` 先经 allowlist redaction，再保存 redacted exact bytes；它们不嵌入 digest。suite report 的 required `stdout_digest`/`stderr_digest` 对保存后的 exact bytes 直接计算 SHA-256，禁止编码/换行/空白归一化；空输出创建零字节文件并记录 digest。schema、枚举、条件字段或任一 referenced digest 不匹配时，reader 返回 `invalid_artifact`，不得猜字段、跨版本回退或手工补 report。

#### 13.4.4 Evidence index and ownership

Root `evidence-index.json` adds required `generation_status:succeeded|failed` and `items:array<L2EvidenceItem>`，plus `safe_failure_reason_ref` required only when failed. With `succeeded`, `candidate_slot` is unique across items and items are ordered by that field; one item aggregates all same-run owning suites/cases for the slot. The item set equals the context suite-manifest candidate projection; release requires the complete §13.2 planned candidate registry. Empty items are allowed only when that projection is empty and never mean pass. With `failed`, items must be empty and the root remains a digestible failure artifact; generator/schema/registry discovery failure must not fabricate a candidate item.

| `L2EvidenceItem` field | Required type | Rule |
|---|---|---|
| `candidate_slot` | `EV-CAND-L2T-*` string | must exist in §13.2 |
| `derivation_status` | `L2DerivationStatus` | derived means source derivation only, never final eligible |
| `tc_refs` | unique sorted non-empty concrete TC array | derived theme expands to concrete refs |
| `suite_refs` | unique sorted non-empty suite array | same run/profile only |
| `artifact_refs`,`report_refs` | unique sorted relative path arrays | raw paths under this run；report refs only pre-index suite reports；empty only for `unavailable` with no produced source |
| `artifact_digests`,`report_digests` | exact ref-to-`sha256:<hex>` maps | keys equal refs；artifact map only contains self-digest-verified sources；report digest uses exact UTF-8 bytes |
| `ac_refs`,`veto_refs` | unique sorted arrays of AC/VF refs | at least one combined ref; no verdict implication |
| `review_requirement_refs` | unique sorted array<safe current formal ref> | empty means no machine-known manual prerequisite; non-empty refs only current §14 residual or future-06 rule projection, never free-text review input |
| `derivation` | `L2EvidenceDerivation` object | no handwritten/cross-run merge |
| `redaction_status` | `L2RedactionStatus` | only clean may be derived；pre-check item has no review/final eligibility status |

`L2EvidenceDerivation` has `generator_id="generate_evidence_index"`,`rule_version="l2-tools.evidence-derivation.v1"`,`source_artifact_digests:array<digest>` in source processing order (empty only for unavailable/no-source), and `generated_at:RFC3339 UTC`. Derivation mapping is closed: complete valid/clean source whose candidate oracle holds=`derived`; complete valid source with a failed oracle=`ineligible`; blocked/not-evaluated/cancelled or absent required source=`unavailable`; a self-valid source declaring `invalid_artifact` or disagreement among valid source path/run/profile/refs=`invalid`. An unparseable source, invalid source schema/self-digest, or generator/schema/registry discovery failure sets root `generation_status=failed`, empty items and a safe reason. This index is pre-check and has no `eligible` value: items may not reference pairing/no-static/final-redaction checks or `gate-summary.json`.

| `evidence_index_ref`,`evidence_index_digest` | fixed `evidence-index.json` + digest | same run pre-check index |
| `evidence_eligibility` | ordered array<`L2FinalEligibilityItem`> | candidate-slot set/order exactly equal successful index items；failed index forces empty array and invalid gate |
| `acceptance_projection_status` | conditional `published\|invalid` | release required、其它 gate forbidden；`published` 只表示 current manifest/four-file projection 可验证，不表示 acceptance；`invalid` forces release `invalid_artifact` |
| `acceptance_projection_manifest_ref`,`acceptance_projection_manifest_digest` | conditional path + digest | release `published` 时 required，分别固定为 `reports/acceptance/projection-manifest.json` 和其 verified self-digest；release `invalid` 及其它 gate forbidden |
| `redaction_status` | `L2RedactionStatus` | non-clean cannot pass |
| `started_at`,`finished_at`,`duration_ms` | RFC3339 UTC, RFC3339 UTC, integer>=0 | provenance only; finish >= start |
| `safe_failure_reason_ref` | conditional safe ref | forbidden when passed; required otherwise |

`L2FinalEligibilityItem` has required `candidate_slot`,`status:L2EvidenceStatus`,`source_index_digest` equal to the root index digest, plus `safe_status_reason_ref` forbidden for eligible and required otherwise. Final priority is `invalid > ineligible > unavailable > pending_review > eligible`: source/check integrity, missing or cross-run/schema/digest/path/invalid artifact yields invalid; otherwise a valid semantic failure yields ineligible; otherwise blocked/not-evaluated/cancelled/required-source absence yields unavailable; otherwise a derived item with all checks passed is pending_review when `review_requirement_refs` is non-empty and eligible when empty. A pre-check non-derived status cannot be promoted. A release projection publication failure is release integrity failure：root status becomes `invalid_artifact` and every item is `invalid`，不得保留可交接 eligibility。Future 06 accepts only a passed `gate_id=release` seal and matching committed acceptance projection; it dereferences the index for traceability but never treats an index item as evidence eligibility.

`reports/acceptance/projection-manifest.json` 使用独立 `schema_version=l2-tools.acceptance-projection-manifest.v1`，不是 common raw-artifact envelope，也不是 evidence item。其字段闭集如下；parser 必须拒绝未知字段：

| Field | Required type | Rule |
|---|---|---|
| `source_run_id` | non-empty opaque string | equal release context，非 `latest` |
| `source_evidence_index_ref`,`source_evidence_index_digest` | fixed same-run path + digest | ref 固定为 `artifacts/test/<run_id>/evidence-index.json`；digest 等于已验证 pre-check index |
| `files` | exactly four ordered `L2AcceptanceProjectionFile` items | 按 `role` 升序；role 闭集为 `handoff`,`open_issues`,`risk_acceptance`,`veto_checklist`，各出现一次 |
| `published_at` | RFC3339 UTC | publication provenance only |
| `manifest_digest_algorithm`,`manifest_digest` | `sha256` + digest | 使用 §13.4.1 canonical JSON，计算时只省略顶层 `manifest_digest` |

每个 `L2AcceptanceProjectionFile` 只含 `role`,`staged_ref`,`published_ref`,`content_digest`。两个 path 必须分别是 `reports/runs/<run_id>/acceptance-draft/<fixed-name>.md` 与 `reports/acceptance/<fixed-name>.md`；`content_digest` 对 staging/published exact UTF-8 bytes 计算并且两者必须相等。manifest 不含 gate status、eligibility、free-text finding 或 seal digest，因此不会形成反向依赖。

Writer order is fixed and acyclic:

```text
metadata
  -> case / journal / redacted logs / suite report
  -> pre-index human suite reports
  -> evidence-index.json
  -> evidence pages + run-scoped acceptance staging
  -> non-redaction checks + their safe JSON
  -> redaction check over the frozen pre-seal tree including staging
  -> release-only acquire exclusive publication lock
  -> release-only four fixed-file replacements
  -> release-only projection-manifest.json (single-file publication marker)
  -> gate-summary.json binds manifest when release; invalid failure seal otherwise
  -> release-only unlock
  -> safe-ref-only final check/gate human projections
```

The seal is never an input to any referenced suite/report/index/check/projection. `projection-manifest.json` is the release-only post-check safe-field publication marker；`redaction-check.md` and final gate/check projections are the other fixed self/post-seal exceptions. These surfaces may use only schema-bound refs/timestamps/counts/status/digests from already-redacted inputs and never raw diagnostics. They do not rewrite the seal or eligibility; all other artifact/report/acceptance content is generated before and included in the redaction scan denominator.

| Artifact | Writer owner | Reader owner | Failure retention |
|---|---|---|---|
| metadata JSON | gate supervisor + shared serializer | every gate/check/report entry | keep written prefix; missing=`invalid_artifact`; never fill fake refs |
| suite/case/journal/stdout/stderr | suite runner adapter + shared serializer/redactor | suite report/pairing/redaction/evidence readers | failed/blocked/cancelled also persist; crash prefix retained |
| check JSON | owning §9.5 root check + shared serializer | gate finalizer/final report audit/future release-seal consumer | root `checks/<check_name>.json`; failed check writes safe finding; missing blocks gate；pre-check index generator never reads checks |
| `evidence-index.json` | evidence generator + shared serializer | acceptance draft/no-static-evidence/finalizer/future 06 trace reader | verified same-run inputs only; no handwritten replacement；06 gets eligibility only from matching release seal |
| acceptance staging | release-owned three generators | required checks、release publisher、future trace reader | 四文件只写 `reports/runs/<run_id>/acceptance-draft`；source input 明确为 pre-seal raw/report/index/blocker/residual；seal/final reports 禁止成为输入；failed publish 不删除 staging |
| fixed acceptance files + manifest | single locked release publisher + manifest serializer | release finalizer/future 06 | exclusive lock 覆盖 fixed files、manifest 与 seal write；checks 后逐文件替换 exact bytes，manifest 最后单文件替换；缺失/mixed/digest drift=`invalid`，不声称多文件原子性或旧 fixed set 可用 |
| `gate-summary.json` | gate finalizer + shared serializer | final human gate report generator/future 06 | checks 和 release manifest（适用时）冻结后写一次；`single_suite` cannot write it；only matching passed release seal is acceptance input |
| review blocks | review recorder | future 06 under its own validation rule | append-only safe records after seal；never current-run machine evidence |

All writers apply `03` §14、`04` safe-output floor and §10 forbidden-body allowlist before persistence. Retention duration remains residual `L2T-RR-013`; this does not relax schema/digest or authorize deleting failure artifacts.

Fixed acceptance/review paths have distinct lifecycle rules:

| Surface | Required provenance | Update/retention | Authority |
|---|---|---|---|
| `reports/runs/<run_id>/acceptance-draft/*.md` | front matter: `projection_schema=l2-tools.acceptance-draft.v1`, fixed `source_run_id`, `source_evidence_index_ref=artifacts/test/<run_id>/evidence-index.json`, `source_evidence_index_digest`, `generated_at`, `generation_mode=regenerated_working_projection`；共同 `(source_run_id,source_evidence_index_digest)` 是 projection-set key | release generators complete four run-scoped files before checks；files freeze once checks start；redaction scans these exact bytes | pre-check staging only；no final eligibility/verdict/signoff/risk acceptance |
| `reports/acceptance/*.md` + `projection-manifest.json` | 四个 Markdown exact-byte copy staging；manifest 使用上述 closed schema/self-digest 并绑定四对 path/digest | one release publisher holds `.projection.lock` through seal write，replaces each Markdown through a same-directory temporary file，then replaces manifest last；consumer reads manifest M1、matching seal/index/four staging+published byte snapshots/front matter、rereads manifest M2 and requires `digest(M1)=digest(M2)`，then uses only captured bytes；missing/mixed/concurrent drift rejects whole set | fixed working projection only；future 06 requires matching passed release seal；publication marker does not sign or accept risk |
| `reports/review/reviewer-notes.md`,`agent-review.md` | each appended block: `review_schema=l2-tools.review-note.v1`, unique safe `review_block_id`, fixed `source_run_id`, `source_evidence_index_digest`, `source_gate_summary_digest`, `reviewed_at`, `reviewer_role`, `disposition=supplemented|disputed|needs_followup` | append-only per source tuple; correction appends a block with `supersedes_review_block_id`; never overwrite/reorder history | human explanation only; not an index/seal input and never rewrites machine status/digest |

Acceptance staging is generated only by release before checks and included in that release run's redaction denominator, so it must not prefill a gate-summary digest or final status. Fixed files become usable only after the manifest marker and matching passed release seal both exist；a crash before manifest replacement leaves the fixed view invalid even though immutable run staging remains recoverable。A consumer's verified object is its captured manifest/seal/index/Markdown byte snapshot, not the mutable fixed paths；after the second manifest read it must not reopen those paths for the same decision. Other gates neither scan a stale acceptance set as current-run input nor overwrite it. Review blocks are post-seal material and cannot become machine evidence for that run; if future 06 consumes them, 06 must define its own validation/redaction gate.

### 13.5 Traceability and final-seal eligibility

| Direction | Required linkage | Missing disposition |
|---|---|---|
| TC -> evidence | `tc_ref,DS,suite,run,case artifact,candidate slot` | slot 保持 planned/unavailable |
| evidence -> design | 03 object/protocol/flow/state/error 或 04 CFG/V/B refs | 不允许“核心流程”泛名 |
| evidence -> requirement | 至少一个 AC/VF；design-only risk 指向 §14 | 无 consumer 不送验 |
| suite -> gate | gate/profile/script/status/check refs | missing provenance=`invalid_artifact` |
| report -> raw | same-run artifact ref/digest | no latest/cross-run/profile |
| defect -> retest | failed/fixed run、original TC、family、suite/check | 缺失保持 open |

Pre-check index item 只写 `derivation_status`。只有 finalizer 消费同 run index 与 §9.5.1 required check 闭集后，final seal item 才可写 `L2EvidenceStatus`。`eligible` 要求 fixed run/profile/suite/dataset provenance、full denominator/no hidden filter、raw case/suite/stdout/stderr/human report/check pairing、redaction clean、required checks 全部 passed、local pair/Query purity/Job bound/phase-unknown/safe handoff oracle 成立、只引用本 run，且未升级 fake/endpoint/health/open blocker，并且 `review_requirement_refs` 为空。机器条件满足但该数组非空=`pending_review`；有效语义失败=`ineligible`；blocked/not-evaluated/cancelled/required source absent=`unavailable`；缺项、跨 run、schema/digest/path/invalid artifact=`invalid`。review 只能补解释，不能替代 raw、final seal 或签署；未来 06 只接收 matching release seal。

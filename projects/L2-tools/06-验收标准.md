### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L2-tools` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L2-tools` 是正式工具能力、调用约束、结果结构与观测审计的真相层,不是 runtime、member-service、sandbox 或 capability-hub 的附属层
- ToolDefinition / ToolContract / ToolPolicy / ToolInvocationRequest / ToolInvocationResult 构成正式工具能力主链
- `ToolDefinition ≠ capability catalog`、`ToolInvocationRequest ≠ runtime action`、`ToolInvocationResult ≠ raw stdout` 三条核心边界必须成立
- governed / restricted tool 调用必须经过显式 policy / scope 裁决
- ToolAuditEntry 必须独立存在,不能只依赖 observability 原始日志
- runtime / member / member-service / observability / governance 必须消费统一工具调用语义

因此,本次验收的目的不是笼统判断“工具能不能调起来”,而是判断 tools 的能力定义、调用入口、权限边界、结果分流与审计观测是否真的成立,是否可作为后续运行链和入口层的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 工具定义与契约部分 | 是 | ToolDefinition / ToolContract / ToolKind |
| 工具调用入口与请求校验部分 | 是 | invocation request / preflight / validation |
| 工具权限与策略约束部分 | 是 | ToolPolicy / ToolScope / governed/restricted split |
| 工具执行结果与失败分流部分 | 是 | structured result / retryable / denied / blocked / fatal |
| 工具审计与观测接缝部分 | 是 | ToolAuditEntry / trace / metrics / escalated failure |
| sandbox / member-service / capability-hub 内部实现细节 | 否 | 只验 tools 与它们的接缝,不验下游内部实现 |
| UI 展示与聊天表现 | 否 | 只验 member-facing capability consume 和 structured result 输出,不验 UI |
| runtime / member 业务主线正文 | 否 | 只验 tools 与它们的接缝,不验上游业务主线全部细节 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| RegisterToolDefinition | capability/adapters 输入后必须形成正式 ToolDefinition / ToolContract | definition record / contract trace | [] |
| ToolDefinition vs capability catalog 边界 | ToolDefinition 不能退化成 capability-hub 标签或目录项 | model review / compare trace | [] |
| ValidateToolInvocation | runtime/member 调用必须进入正式 ToolInvocationRequest 并完成 preflight | invocation record / validation trace | [] |
| ToolInvocationRequest vs runtime action 边界 | runtime action 文本不得直接替代正式 invocation request | compare trace / negative flow | [] |
| QueryToolPolicy | governed / restricted tool 必须明确返回 allow / deny / governance_required / blocked | policy trace / result compare | [] |
| ToolPolicy / ToolScope 边界 | policy/scope 不能隐藏在 sandbox 或宿主实现细节里 | model review / negative flow | [] |
| InvokeTool | host-side 执行必须在 policy/scope 判定通过后发生 | execute trace / policy trace | [] |
| NormalizeToolResult | structured result 必须正式形成,不能被 raw stdout 替代 | result compare / normalize trace | [] |
| Retryable / denied / blocked / fatal 分流 | 工具失败语义必须明确分层,不得合并为一个错误字符串 | result_kind compare / failure matrix | [] |
| ToolAuditEntry | 每次正式工具调用必须形成独立 ToolAuditEntry | audit entry record / replay trace | [] |
| Escalated governed failure | 需要升级的 governed/restricted failure 必须形成正式 escalated failure 输出 | escalation material / governance consume trace | [] |
| Metrics / trace output | observability 必须拿到与 invocation/result 可对账的指标和 trace 材料 | metrics trace compare | [] |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| ToolDefinition 不可退化成 capability catalog | capability 目录与正式工具契约必须分层 | definition compare / model review | [] |
| governed/restricted tool 不可绕过 policy | 未经 allow/治理分支不得执行 | policy trace / negative flow | [] |
| structured result 不可被 raw stdout 替代 | runtime/member 只能消费正式 ToolInvocationResult | result compare / consume path | [] |
| ToolAuditEntry 不可缺失 | 原始日志不能替代正式审计条目 | audit record / replay trace | [] |
| host-side callback 不可替 tools 正式结果 | 宿主原始输出只是输入材料,不能直接作为上游正式结果 | callback compare / normalize trace | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | ToolDefinition 退化成 capability catalog / governed tool 绕过 policy / ToolInvocationResult 被 raw stdout 替代 / ToolAuditEntry 缺失 |
| A | 视情况 | 主线可跑但 policy/result/audit/escalation 语义不稳 |
| B | 可带着走 | 非关键 invocation history、trace、metrics 视图异常 |

### 2.1 实施目标

| 目标 ID | 本轮目标 | 完成方向 |
|---|---|---|
| `OBJ-01` | 稳定 Tool identity、formal definition 与 contract evolution | identity/revision/current/history/CAS/replay 均由正式 contract 和测试闭合。 |

| `OBJ-07` | 建立 inbound/outbound collaboration 与 bounded jobs | claim/receipt/re-entry/continuation/report/replay 不接管外部 truth。 |
| `OBJ-08` | 建立 strict config/runtime assembly 和 release evidence tooling | 54 items、V0~V8/B0~B8、234 TC、11 suite/check 和交付门禁闭合。 |

| 范围 | 优先级 | 来源 | 本轮处理 |

### 5.3 阶段执行纪律

1. 当前 Phase 的 predecessor Handoff Gate 未关闭，不得激活后续 Phase。
2. 每个 Phase 内按 boundary 顺序执行；一个 boundary 必须有真实 Commit 和 Handoff Gate 后才能推进项目 ledger。
3. 业务测试与 owning boundary 同步落地；PH-11 只完善 runner、report、check、aggregation 和 handoff，不得补写此前遗漏的业务语义。
4. External positive seam 不作为 local P0 的隐式前置；对应 owner 未闭合时只运行 negative/blocked-aware/fake parity，并记录 `blocked_dependency`。
5. 配置 composition 后置，不能由 builder 便利反向决定字段、Port、状态或 fallback。
6. Phase 门禁失败保留失败事实并停止推进，不得以“后续统一修复”激活下一阶段。

### 5.4 Phase 停审门禁

| 停审项 | 通过标准 | 失败动作 |
|---|---|---|
| Increment | 有可构造输入、可观察输出、明确非范围和 targeted selector | 重拆 Phase/boundary，回写 Step 5/6。 |
| Dependency | 只依赖 predecessor 已交付 surface；later surface 只能 reserved/uninvoked | `blocked / wait_design`。 |
| Owner boundary | 未实现 Runtime/Hub/Auth/Sandbox/Bus/Obs/SDK truth | 删除越界实现，必要时回写正式 00~03。 |
| Test ownership | owning TC 与实现同阶段，失败/unknown 口径明确 | 当前 Phase 不得完成。 |
| Evidence | planned path 未被写成 pass；真实材料可 same-run 回链 | `invalid_artifact`，保留并重跑。 |
| Handoff | boundary ledger、commit、not-run、blocker、next action 完整 | 当前 Phase 保持 current。 |

设计期 PH-01~11 均为 `pass-designed`；这只是静态可落码复核，不是任何 Phase 已实现或门禁已通过。

## 6. 阶段任务拆分、编写顺序与提交边界

> 校准来源：
> - `design-calibration/07_implementation_plan_step_06_tasks_commit_boundaries.md`
>
> 延伸阅读：
> - 继续阅读该文件的 26 个“阶段任务、批次与边界卡”“开工前设计闭环复核”“Commit boundary 经验复核摘要”和“跨 boundary 审计”；每个 boundary 的执行入口是 `design-calibration/implementation-boundaries/<boundary_id>.md`。

### 6.1 通用编写顺序

每个 capability boundary 固定遵循以下依赖方向；不适用步骤须在 ledger 说明理由，不能静默跳过：

```text
formal contracts / typed refs / metadata / errors
  -> domain objects / factories / transitions / pure policies
  -> Store and Port traits / UnitOfWork / idempotency
  -> deterministic fake / blocked adapter / parity fixtures
  -> application service / facade / mapper
  -> api, worker or jobs entry
  -> targeted positive, negative, replay and concurrency tests
  -> required checks / staged review / commit / handoff
```

单批目标为 100~300 行的局部可验证增量；超过该规模或涉及 public schema、事务、side effect、unknown fence、redaction、evidence 时继续拆批，但仍在同一 boundary 完成闭环。

| DTO construction | request/event/job/result/receipt/report 可由 metadata/envelope/typed source 构造 | 回正式 03 §7~§8；禁止 local alias/default。 |
| callable/Port | domain member、Store/Port method、mapper、entry callable exact | 回正式 03 §5~§8。 |

| config binding | key/source/profile/activation/failure/adapter capability 有正式 04 source | 回正式 04。 |
| test/evidence | selector、dataset、raw/report builder、pairing、redaction 和 failure retention 闭合 | 回正式 05/06。 |

### 7.5 Evidence 与报告生成顺序

```text
real fixed run + immutable context
  -> suite case/journal/stdout/stderr raw
  -> same-run suite JSON and human reports
  -> pre-check evidence-index derivation
  -> 11 required checks and redaction scan
  -> release-only acceptance staging
  -> exact-byte fixed projections + manifest
  -> gate-summary final machine eligibility
  -> authorized human/agent review records
  -> future formal 06 decision and signoff
```

| 规则 | 固定口径 |
|---|---|
| raw root | `artifacts/test/<run_id>`；禁止 project subdir、`latest` 和覆盖失败 run。 |
| report root | `reports/runs/<run_id>`；必须回指同 run raw、context 和 digest。 |
| candidate slots | 30 个 `EV-CAND-L2T-*` 只能从 same-run concrete TC 派生；slot 不是 evidence instance。 |
| acceptance output | generator 只能生成 `draft / review_required`；不得预填 verdict、accepted risk、签署。 |
| failure | failed/blocked/cancelled/timeout/invalid 均保留；新 fixed run 不覆盖旧材料。 |
| hard stop | 任一 VF、open S、current P0 A、redaction/dependency/pair/phase/no-static failure 均阻塞 release handoff。 |

正式 05 是 concrete case 和 artifact schema authority，正式 06 是 eligibility、VETO、风险和裁决 authority；本章只把它们嵌入实施顺序，不建立第二 registry。

> - `design-calibration/07_implementation_plan_step_10_rollback_pause_change_control.md`
>
> 延伸阅读：
> - 继续阅读该文件的“暂停规则”“回退规则”“变更控制表”和“Blocker 记录与恢复协议”；状态和值域以 `代码实施台账与门禁规范.md` 为准。

### 10.1 Ledger 状态机

```text
planned / wait_until_current
  -> current + read_docs
  -> design/scope/worktree gates
  -> edit_and_test
  -> fix_gate_failure | wait_design
  -> prepare_commit
  -> commit
  -> handoff
  -> next boundary planned becomes current
```

本项目初始状态是例外的 pre-implementation fence：`commit-01-a` 已是唯一 current，但 repo/baseline blocker 使其直接处于 `blocked / wait_design`。设计文档完成不自动将其转为 `read_docs` 或 `edit_and_test`。

### 10.2 Pause Rules

| ID | Trigger | 动作 / state | 保留事实 | 恢复条件 |
|---|---|---|---|---|
| `PAUSE-L2T-01` | target repo/git/Core/toolchain 缺失 | 停 PH-01；`blocked / wait_design` | preflight facts | authorized repo/baseline/toolchain ready。 |
| `PAUSE-L2T-02` | field/DTO/Port/state/config/evidence/phase 冲突 | 停当前 boundary，写 blocker；`wait_design` | exact source/path/conflict | owning design fixed + new baseline。 |
| `PAUSE-L2T-03` | touched/staged path 越 scope | 停止编辑/暂存，拆 scope；`fix_gate_failure` | status/diff names | 无损移除 out-of-scope work。 |
| `PAUSE-L2T-04` | 未知用户/其他 agent 改动 | 停止重叠文件工作并回报 | initial/current status | ownership 明确或采用 non-overlap plan。 |
| `PAUSE-L2T-05` | fmt/check/test/TC failure | 只修 current boundary；`fix_gate_failure` | command/raw failure | 修复并重跑 applicable gates。 |
| `PAUSE-L2T-06` | redaction/dependency/profile/pair/phase/no-static failure | hard stop，不进下一 boundary | failed check/report | new clean run/check；旧失败保留。 |
| `PAUSE-L2T-07` | VF/S/current P0 A | stop release/handoff | finding/TC/run refs | fix + independent retest + VF not_triggered。 |
| `PAUSE-L2T-08` | external owner/selected dependency unavailable | 只停 affected positive scope；`blocked_dependency` | dependency record | owner/product ready 或正式排除 scope。 |
| `PAUSE-L2T-09` | design/source/config baseline drift | invalidate eligibility；`wait_design` | old/new baseline refs | freeze new baseline + impact rerun。 |
| `PAUSE-L2T-10` | Spike/OQ deadline 逾期 | 停 affected boundary；`wait_design` | pending item/ref | adopt/reject/reopen decision。 |

### 10.3 Rollback 与历史保护

| ID | 场景 | 允许动作 | 禁止动作 | 恢复验证 |
|---|---|---|---|---|
| `RB-L2T-01` | 未提交 current boundary 错误 | allowed scope 内 fix-forward，保留失败测试 | reset/checkout 用户文件、清空 worktree | rerun boundary gates。 |
| `RB-L2T-02` | 已提交 boundary 缺陷 | 新 fix boundary/commit 或 owner 明确授权 revert | 未授权 amend/rewrite 已交付历史 | impact matrix + affected/full regression。 |
| `RB-L2T-03` | 设计修正 | 新 design baseline、同步所有 ledgers 后继续 | 代码兼容两套 truth | Design Gate full reread。 |
| `RB-L2T-04` | config assembly failure | dispose partial graph；仅正式规则允许时保留 valid prior candidate | invalid-high fallback、hot patch、partial entry | V0~V8/B0~B8 全重跑。 |
| `RB-L2T-05` | side-effect outcome unknown | 保持 Prepared/Unknown/manual，用同 marker 解析 | blind retry/new key/guess success | same-authority resolution。 |
| `RB-L2T-06` | test/release run failure | 保留 failed run，创建 new fixed run | overwrite/delete/cross-run stitching | new run 完整分母。 |
| `RB-L2T-07` | acceptance projection publish failure | whole projection invalid，保留 staging | partial/old fixed projection | new release run/publish/manifest/seal。 |
| `RB-L2T-08` | selected product capability failure | reject product 或 reopen design | fallback fake 并宣称 selected | selected proof rerun。 |

### 10.4 Change Authority

| Change class | Authority | 必须更新 | 恢复 Gate |
|---|---|---|---|
| documentation-only clarification | owning formal doc | formal + calibration + ledger refs；证明无 semantic delta | doc review / diff check。 |
| field/type/variant/callable | 正式 03 | 03/05/06/07 + affected ledgers | new baseline + full affected audit。 |
| state/TX/idempotency/unknown | 正式 03 | all writers/readers/replay/evidence、05/06/07 | affected + P0 escalation。 |
| config key/profile/source/activation | 正式 04，semantic 时先 03 | 04/05/06/07 | CFG full matrix。 |
| TC/suite/artifact/report schema | 正式 05 | denominator/writers/readers、06/07 | full evidence audit。 |
| AC/VF/risk/signoff authority | 正式 06 | 06/07 | acceptance design review。 |
| Phase/boundary split/merge/order | 正式 07 | Step 5/6/7/11、project ledger、all affected skeletons | cross-boundary audit。 |
| private adapter/product only | infra/config binding | 证明无 semantic/public delta；implementation + targeted test | boundary review。 |

### 10.5 Blocker 与恢复协议

每个 blocker 至少记录：`blocker_id`、`boundary`、`gate`、`status`、`reason`、`affected_files`、`design_sources`、`forbidden_workarounds`、`requested_closure`、`next_allowed_action`。关闭时补充 `design_fix_baseline`、`resolution_summary`、关闭 evidence 和恢复 action。

恢复顺序固定为：关闭 blocker -> 冻结新的 immutable baseline -> 更新 formal/calibration/project/boundary ledgers -> current boundary 全量重读 -> 重跑所有受影响 gate -> 重新进入原状态机。用户“同意”或对话摘要不能替代 gate evidence。

### 11.1 通用提交纪律

### 11.3 Commit Gate

| Check | Pass 条件 | 当前设计期状态 |
|---|---|---|
| activation/design | 唯一 current、immutable baseline、required reads、Design Gate pass | current `01-a` blocked。 |
| staged scope | `git diff --cached --name-only` 只含 allowed scope | `pending` |
| unrelated changes | 用户/其他 agent 文件不在 staged set | `pending` |
| message | title/body groups/file entries/footer/英文符合 §11.1~§11.2 | `pending` |
| whitespace | target repo `git diff --cached --check` pass | `pending` |
| Rustdoc/source language | public items/fields/variants/payloads/traits/methods/callables 完整英文 `///`；identifier/comment/test 英文 | `pending` |
| required gates | actual commands/results/paths 写入 current ledger；没有 pending/blocked required gate | `pending` |

任何一项不满足均不得 commit。不得为了满足“一 boundary 一 commit”而把不完整 vertical slice 提交；也不得把两个独立 boundary 合并到同一提交。

### 11.4 评审纪律

| Review | 必查 | 失败动作 |
|---|---|---|
| design | 正式 03/04/05/06/07 与 exact calibration source | `wait_design`。 |
| scope | included/excluded paths、owner 和 phase fence | split/fix scope。 |
| behavior | positive/negative/replay/concurrency/unknown/no-write/no-repair | fix and rerun。 |
| security | body/secret/ref/redaction/dependency/authorization/owner leakage | hard stop / VF review。 |
| evidence | same-run raw/report/check/digest/no-static | `invalid_artifact` / new run。 |
| commit | staged diff、message/body/footer、whitespace | commit 前修正。 |
| handoff | hash、gates、not-run、blockers、next、user changes | 当前 boundary 保持 current。 |

### 11.5 Handoff 与交付

| 项 | 必须记录 |
|---|---|
| Commit Record | 仅真实 commit 后写 `committed_hash`、exact message、staged scope 和 post-status。 |
| Handoff Gate | actual gates、tests not run 及理由、remaining blockers、next boundary、user-owned changes。 |
| artifact/report | 只引用 fixed run safe paths；不粘贴 raw secret/body/full log。 |
| acceptance | drafts 经 actual review；scripts 不生成 verdict、risk acceptance 或 signoff。 |
| future activation | 当前 Commit/Handoff Gate pass 后，project ledger 才能把下一 skeleton 从 planned 变 current。 |

当前没有 implementation commit、hash、message execution fact 或 handoff；所有 §11.2 内容均为 planned contract。

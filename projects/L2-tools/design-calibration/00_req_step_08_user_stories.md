## 4. 当前文档问题诊断

### 4.1 C-L2T-1 稳定身份与完整定义

| 项 | 结论 |
|---|---|
| 核心角色目标 | 维护者需要建立并演进同一工具合同;审查者需要理解风险和正文边界;消费方需要在行动前理解同一正式定义。 |
| 进入故事 | `US-L2T-001~004`。 |
| 不进入 | 具体 builtin、注册命令、schema 字段、技术 registry、CRUD、发布接口。 |
| 节点判断 | 故事覆盖建立、演进、边界审查和下游消费四个目标,且未用库存反向定义合同。 |

### 4.2 C-L2T-2 受控外部能力关联

| 项 | 结论 |
|---|---|
| 核心角色目标 | 维护者区分 capability-bound / unbound;消费方确认关联来自受控语境;维护任务暴露 stale / invalid relation 而不补造外部 truth。 |
| 进入故事 | `US-L2T-005~007`。 |
| 不进入 | 本地 capability registry / allowlist、external descriptor 正文、Hub 可见性即调用资格、provider route / secret。 |
| 节点判断 | 故事同时保护纯本地路径和受控关联路径,没有把所有工具强制绑定外部能力。 |

### 4.3 C-L2T-3 统一规范调用语义

| 项 | 结论 |
|---|---|
| 核心角色目标 | 消费方围绕正式合同表达调用语境并获得一致受理语义;维护者保护 definition / invocation 演进一致;执行协作方承接同一工具语义。 |
| 进入故事 | `US-L2T-004`;`US-L2T-008~010`。 |
| 不进入 | agent loop、动作选择、LLM planning、orchestration、retry / recovery、API path、DTO 或调用函数。 |
| 节点判断 | 故事建立下游统一消费目标,但没有把 Runtime 主线或执行事实收入本仓。 |

### 4.4 C-L2T-4 执行前置与条件化隔离交接

| 项 | 结论 |
|---|---|
| 核心角色目标 | 审查者区分风险声明、正式外部裁决和隔离前置;消费方在前置不成立时获得保守终态;执行协作方在自身 truth 边界内承接 / 反馈执行材料。 |
| 进入故事 | `US-L2T-010~013`。 |
| 不进入 | 本仓 self-authorization、allow / deny 算法、Sandbox mapping / receipt / cleanup、宿主直跑或 capture owner。 |
| 节点判断 | 角色目标足以驱动后续 fail-closed 与不可旁路规则;`L2T-UP-001~004` 继续约束后续,不阻塞故事收敛。 |

### 4.5 C-L2T-5 Outcome、工具域审计与安全交接

| 项 | 结论 |
|---|---|
| 核心角色目标 | 消费方获得统一结果 / 错误;审计角色回链工具域事实;调查者区分多 owner 故障;安全材料消费方获得去正文、脱敏、可关联材料。 |
| 进入故事 | `US-L2T-012~017`。 |
| 不进入 | 把 capture / delivery / observation 当结果,事件名 / schema / route、retention、replay、真实 evidence alias 或恢复编排。 |
| 节点判断 | 成功、失败、执行前保守收束和外部 handoff 均有目标来源;`L2T-UP-005~007` 继续后移。 |

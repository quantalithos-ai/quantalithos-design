## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 的 AI 成员要调用外部能力时,不能直接随便访问外部服务。平台需要一个统一能力入口来管理:
- 哪些 MCP Server 可用
- 哪些 A2A Node 可连
- 哪些 LLM Provider 可调用
- API key / 配额 / 成本 / 白名单如何管理
- governance Policy 如何下发到这些能力边界

L3-capability-hub 就是这个统一能力入口。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | 只有仓 README 骨架,无 domain 级详细设计 | 仓级需求未显式定义 |
| MCP / A2A | 目标已明确 | 具体 registry / directory 模型未沉淀 |
| LLM provider 合同 | 只在 README 点到 | API key / quota / cost 语义未落地 |
| Policy 下发 | governance 会下发 | 白名单 / deny 行为还无仓级验收口径 |

### 2.3 为什么要做(量化依据)

- 没有 capability-hub,`runtime` / `tools` 就要直接持有外部服务配置和 key,安全边界会碎裂
- 所有外部调用都必须有统一审计与成本记账入口
- MCP / A2A / LLM provider 数量会增长,不可能分散在各仓各自管理

### 2.4 业务问题 vs 技术问题

- **业务问题**:平台如何安全、可审计地使用外部能力和第三方提供商
- **技术问题**:MCP registry / A2A directory / provider contract / cost accounting / whitelist + Policy 联动

## 3. 目标与非目标

### 3.1 目标(可验证)

| ID | 目标 | 验收指标 | 验收方式 |
|---|---|---|---|
| G-1 | MCP Server 白名单注册 | allow / deny 生效率 100% | 集成测试 |
| G-2 | A2A Node 注册需身份校验 | 匿名注册拦截率 100% | 安全测试 |

### 3.2 非目标(明确不做)

| ID | 非目标 | 原因 | 归属 |
|---|---|---|---|
| NG-1 | **执行工具调用** | 本仓只做注册/校验/分发,真正调用在 L2 tools/runtime |

| NG-3 | **持有终端用户会话** | 不做 UI / conversation 逻辑 |

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 注册 / 启停一个 MCP Server 白名单项
2. 注册一个 A2A Node
3. 配置一个 LLM Provider Contract(API key / quota / route / cost)
4. runtime 查询当前项目/角色可用能力
5. 外部调用产生成本记账事件

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **runtime**,我想要 **查询当前可用 MCP Server 白名单**,以便 **只调用被许可的外部工具** |
| 优先级 | P0 |
| 验收条件 | **Given** 某项目 / role 的 Policy 已下发 **When** runtime 调 QueryCapabilities **Then** 返回只含 allow 的 server |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **Owner**,我想要 **注册一个 Anthropic/OpenAI Provider Contract**,以便 **给团队提供模型能力** |
| 优先级 | P0 |
| 验收条件 | **Given** provider 配置 + API key **When** RegisterProvider **Then** key 加密存储且状态为 active |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **Security**,我想要 **阻止未白名单的 MCP Server 被调用**,以便 **防止越权外连** |
| 优先级 | P0 |
| 验收条件 | **Given** MCP Server 不在 allowlist **When** runtime 请求调用 **Then** 立即拒绝 + 发严重审计事件 |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **Auditor**,我想要 **看到每次外部调用的成本记账**,以便 **核算模型/API 成本** |
| 优先级 | P1 |
| 验收条件 | **Given** 任意 Provider 调用成功 **When** 事务提交 **Then** cost_accounting 记录 + bus 事件发出 |

| 字段 | 内容 |
|---|---|
| ID | US-005 |
| 用户故事 | 作为 **platform**,我想要 **治理域 Policy 更新后 30 秒内刷新能力白名单**,以便 **外部能力边界可动态收紧** |
| 优先级 | P0 |
| 验收条件 | **Given** policy-update 影响 MCP allowlist **When** capability-hub 订阅处理 **Then** 30s 内 QueryCapabilities 返回新结果 |

## 6. 功能需求

### 6.1 功能清单与优先级

| ID | 功能名称 | 优先级 | 依赖 | 描述 |
|---|---|---|---|---|
| F-001 | MCP Registry | P0 | core / bus | server 注册 + 白名单 |
| F-002 | A2A Directory | P1 | core / bus | node 注册 + 身份校验 |
| F-003 | Provider Contract | P0 | KMS/Vault | LLM/API provider 配置 |
| F-004 | QueryCapabilities | P0 | governance policy | runtime 查询当前可用能力 |
| F-005 | Cost Accounting | P1 | F-003 | 外部调用成本记账 |
| F-006 | Policy 消费与白名单刷新 | P0 | governance | policy-update 动态生效 |
| F-007 | 审计事件发出 | P0 | observability | 未白名单 / 调用成功 / 调用失败 |
| F-008 | Secret envelope encryption | P0 | KMS/Vault | API key 不落盘明文 |
| F-009 | capability marketplace metadata | P2 | marketplace | 发布 MCP Tool / Role 镜像的注册 |
| F-010 | LLM routing(可选) | P2 | runtime | 按任务复杂度选模型 |

### 6.2 业务规则表

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-001 | MCP Server 不在 allowlist | 拒绝调用 |
| BR-002 | A2A Node 匿名注册 | 拒绝 |
| BR-003 | Provider key 未加密 | 拒绝持久化 |
| BR-004 | Policy 更新影响白名单 | 30s 内刷新 |
| BR-005 | 外部调用成功/失败 | 都要发成本/审计事件 |
| BR-006 | shared_rules 禁止某能力 | 项目级 allow 不得放开 |

### 6.3 功能依赖图

```
Provider Contract
  ├─▶ Cost Accounting
  └─▶ QueryCapabilities

MCP Registry
  ├─▶ QueryCapabilities
  ├─▶ Policy 消费刷新
  └─▶ 审计事件

A2A Directory
  ├─▶ QueryCapabilities
  └─▶ 身份校验
```

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 聚合 / 类型 | 生命周期 |
|---|---|---|
| MCPServer | 聚合根 | registered → active / paused / retired |
| A2ANode | 聚合根 | registered → verified / retired |
| ProviderContract | 聚合根 | active / paused / retired |
| CapabilityDecision | 查询结果视图 | 即时生成 |
| CostRecord | 记账记录 | append-only |

### 9.2 数据关系

```
Policy / shared_rules
      │
      ▼
CapabilityDecision
  ├─ allowed MCP servers
  ├─ allowed A2A nodes
  └─ allowed providers

ProviderContract
  └─ CostRecord[]
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| active registry entries | 热存 | active |
| cost records | 长期 | 冷存可查 | 不随意删 |
| retired servers/providers | 冷存只读 | archive | 不删审计历史 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 白名单刷新不及时 | 中 | 高 | last-known-good + lag 告警 |
| key 管理不当泄露 | 低 | 极高 | KMS/Vault 强制 |
| cost accounting 不准确 | 中 | 中 | 统一计费事件模型 |
| runtime 绕过 hub 直连外部能力 | 中 | 高 | 审计 + 代码规范 + deny by default |

### 12.2 边缘风险

- MCP / A2A 协议未来变化较快
- 多 Provider failover 策略过于复杂
- capability marketplace 和 runtime 权限边界交叉

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| LLM routing 是本仓内建还是独立服务 | N3 后 | capability-hub + runtime |
| A2A 节点认证模型(证书 / token / DID) | N3 前 | capability-hub |
| 成本记账粒度(请求级 / token 级 / 分钟级) | N3 前 | finance + platform |

### 2.1 P0 / P1 / P2

| 级别 | 当前含义 | 进入本文 | 是否代表已实现/部署 |

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_categories_boundaries.md` §§8~12
>
> 延伸阅读：
> - 上述中间产物的“配置分类表”“加载、生效与变更边界”“禁止配置化项与变更路径”。

| 配置类别 | 说明 | 示例 | 允许热更新 | 主要风险 |
|---|---|---|---|---|
| static design boundary | 不是 operator config 的 invariant | truth owner、state/UoW/protocol identity | 不适用 | 被 flag 绕过正式设计 |
| startup runtime config | 构造 immutable root 和 Stage 0~7 graph | 27 canonical rows | 否 | partial graph、跨 profile fallback |
| invocation-scoped frozen view | 从 root 借用/复制的只读 entry view | API/Worker/Jobs technical parameters | 否 | 被误作 per-request/per-run override |
| entry-local technical parameter | 只限定 selected entry 的技术资源 | bytes/page/parallelism/deadline | 否 | 混入业务 scope/target |
| policy-like technical knob | 不改变业务语义的 bounded policy | timeout/retry/internal scan | 否 | blind retry、取消 future、改写终态 |
| sensitive reference config | symbolic ref 与非秘密连接约束 | credential/TLS/feed/route refs | 否 | raw material 泄漏 |
| diagnostic/redaction config | 选择已有 safe observation mode | `off`、`redacted` | 否 | 可编辑 allowlist/第二 authority |
| deterministic fixture config | explicit parity fake/clock/ID fixture | Local/Integration fixtures | 否 | Deployment fake/fallback |
| peripheral enablement | exact named Configured/Fake/Disabled | external Port/source slot | 否 | generic feature flag 改写 accepted path |

所有 raw source 仅在 process startup 读取、校验并冻结。entry construction 产生恰好一个 typed handoff；invocation 和 Job run 不重读 file/env/secret。变更通过新 immutable artifact 和新 process 完整装配，不原地 mutation、watch 或 graph swap。

### 4.1 禁止配置化项

| 禁止配置化项 | 原因 | 如需改变应走什么流程 |
|---|---|---|
| capability identity/registry/descriptor state、guard、truth owner | Hub domain invariant | 重开正式 00/01/02 与 DDD object/flow/state |
| governance approval/Policy/workflow | Hub 只持 body-free seam/ref | 重开跨仓责任和 protocol；不能新增 approval flag |
| method body/source/publication/execution lifecycle | method-library authority | 重开责任/Port/protocol/data boundary |
| runtime/tools invocation/result、marketplace listing、SDK lifecycle | 外部 bounded context | 需求/架构责任变更，不得以 enable key 并入 |
| provider route/quota/cost/failover | 非 capability access truth | 外部 runtime/provider owner；Hub 配置拒绝 |
| raw token/password/DSN/private key/certificate/body/provider response | body/secret boundary | 只能更换 symbolic provider binding，raw material 仍禁止 |
| public protocol/DTO/event/source identity | compile-time/public contract | 重开 formal 03 protocol/flow；补全英文 `///` |
| state variants/transitions、UoW/CAS/commit/idempotency/replay | consistency invariant | 重开 DDD state/persistence/concurrency Steps |
| Job kind/run/key/scope/target/journal identity | scheduler input 不能定义业务 truth | 重开 Job protocol/flow/state/transaction |
| observer allowlist/business outcome/evidence/signoff | observer 无业务 authority | 重开 observability design；evidence/signoff 仍归 05/06 执行期 |
| fixed codec/digest algorithm and canonical order | compatibility invariant | versioned compatibility design，不是 runtime selector |
| Cargo dependency/crate feature graph | compile-time implementation design | DDD dependency binding + formal 07 |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md` §§8~10
>
> 延伸阅读：
> - 上述中间产物的“来源层次与优先级”“冲突与不可用处理表”“跨来源冲突审计”。

内容优先级固定为 `design/parser constants < strict JSON < bounded environment overlay`。Bootstrap selector 不参与内容覆盖，只选择唯一文档或断言 profile/entry；symbolic resolver 不改变 raw candidate，只把已验证 ref 解析为 constructor-private material；fixture 是显式 profile-limited binding，不是 fallback。

| 来源 | 优先级 / 作用 | 适用配置 | 冲突处理 | 不可用时策略 |
|---|---|---|---|---|
| design/parser constants | 最低，非 operator source | schema v1、grammar/bounds、fixed compatibility | source 不得改算法/版本 | 设计/实现不一致即阻塞，不 fallback |
| CLI/env bootstrap selector | 只选择/断言 | config file、expected profile、expected entry | selector 间或与 root 不一致即拒绝 | 显式 selector 不可读/非法则启动失败 |
| strict JSON document | content priority 1 | 18 modules、named slots/refs/scalars | duplicate/alias/unknown/forbidden 即拒绝 | 不可读/解析失败/required missing 即启动失败 |
| bounded environment | content priority 2 | §7 的 21 个 allowlisted leaf | 合法值覆盖 JSON；invalid present value 不回退 | 类型/范围/结构越权即启动失败 |
| symbolic ref resolver | 不参与 precedence | endpoint/credential/feed/actor/route/fixture refs | kind/family/registration mismatch 即拒绝 | Configured material 不可用即 assembly fail-fast |
| deterministic fixture | 独立 Local/Integration lane | fake external/source、clock/ID fixture | 必须 explicit 且 parity-complete | 缺失/不匹配即失败，绝不切换真实/Disabled |
| config center/admin override | unsupported | 无 | 声明即 unsupported | 启动拒绝 |

CLI 只允许单值 `--config-file`、`--expected-profile`、`--expected-entry` 等价 selector；不允许 `--set path=value`、JSON pointer、重复 merge、raw secret argument。

### 5.1 冲突与不可用

| 冲突场景 | 处理规则 | 阻断启动 / 操作 |
|---|---|---|
| JSON duplicate key、canonical key + alias、unknown field | 严格拒绝，不采用 last-write-wins | 启动 |
| valid JSON + invalid present env | present intent 无效；不回退低优先级 JSON | 启动 |
| env 新增 section/array/member/named registry | 超出 allowlist | 启动 |
| reserved prefix 下未知 env | 视为配置拼写/越权错误；诊断不含 value | 启动 |
| selector 与 JSON profile/entry 不一致 | selector 是 assertion，不覆盖 root | 启动 |
| required item 在有效来源中缺失 | 无 semantic default | 启动 |
| Configured ref/constructor/provider/probe 缺失 | enabled graph 不完整 | 启动/entry exposure 前 |
| Disabled branch 带 adapter/feed/route material | union shape 冲突 | 启动 |
| Fake/fixture/inMemory/deterministic 出现在 Deployment 禁止位置 | profile violation | 启动 |
| raw secret/body 出现在 file/env/CLI/fixture | security violation，value-free safe diagnostic | 启动/安全门禁 |
| active process 后 source 漂移/过期 | 当前 root 不变；仅下一次 activation/release gate 发现并拒绝 | 不热更；下一次启动/切换 |

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_environment_profiles_matrix.md` §§8~10
>
> 延伸阅读：
> - 上述中间产物的“Canonical runtime profile matrix”“Environment-purpose mapping”“Complete activation predicates”。

runtime profile 只有 `local`、`integration`、`deployment`。local development、CI、replay、staging-like 和 production-like 是 environment purpose，不是额外 Rust enum 或配置 variant。

| 环境 / profile | 用途 | 配置来源 | 外部依赖 | 敏感配置处理 | 差异说明 |
|---|---|---|---|---|---|
| local development / Local | 本地 typed behavior 和手工探索 | JSON + bounded env + explicit fixture | inMemory/durable；Configured/Fake/Disabled | fake/symbolic refs，无 raw secret | 不证明真实连通 |
| deterministic CI / Local or Integration | contract、fake parity、negative branch | test JSON + bounded CI env + fixture | parity fake；声明后可受控 Configured | fixture refs only | CI purpose 不新增 profile |
| integration-like / Integration | adapter seam、family/schema/unavailable | JSON + bounded env + typed refs | Configured/Fake/Disabled | credential/endpoint/route refs only | inMemory/durable 均需 semantic parity |
| operations replay / Integration | Job replay/reentry/report/no-repair | replay JSON + typed invocation input | Configured/Fake/Disabled | historical ref only，无 raw body | invocation 不覆盖 root |
| staging-like / Deployment direction | 未来 real-like gate | operations-owned JSON/env/ref | durable；Configured/Disabled | approved secret-provider refs | 仅方向，不声称当前可运行 |
| production-like / Deployment direction | 未来运行准备 | deployment-owned material | durable；Configured/Disabled；fake=0 | approved provider refs | 不声称产品、连接或验收已就绪 |

### 6.1 Canonical profile matrix

| Configuration group | Local | Integration | Deployment | Hard failure |
|---|---|---|---|---|
| runtime | schema v1 + one selected entry | same | same | mismatch/unknown blocks Stage 0 |
| local authority | inMemory or durable with full parity | inMemory or durable with full parity | durable only | missing/second authority/Deployment inMemory blocks |
| 9 external Port slots | configured/fake/disabled | configured/fake/disabled | configured/disabled | any Missing or Deployment fake blocks |
| 6 Worker source slots | configured/fake/disabled when Worker selected | same | configured/disabled | incompleteness or Deployment fake blocks |
| configured collaboration routes | 10/10 exact routes | same | same | fewer/more/wrong family blocks |
| clock / ID | system or deterministic | system or deterministic | system only | Deployment deterministic blocks |
| compatibility | `stableSurfaceV1 + sha256V1` | same | same | any alternative blocks |
| policy/entry scalars | explicit and in range | same | same | no profile-specific implicit default |
| diagnostics | off or redacted | off or redacted | off or redacted | raw/full/verbose blocks |
| endpoint/transport/credential/TLS | selected refs exact | selected refs exact | authenticated network TLS + approved provider | orphan/wrong-kind/missing blocks |
| fixtures | selected fake/deterministic branches only | same | none selected | Deployment or orphan fixture blocks |

### 6.2 Binding states and complete predicate

| Binding state | Eligible profile | Startup | Invocation | Fallback |
|---|---|---|---|---|
| `Configured` | all allowed surfaces | exact constructor/probe/family must pass | typed outcome/failure | none |
| `DeterministicFake` | Local/Integration only | fixture and parity validation | same typed boundary；no real-world fact | never automatic |
| `Disabled` | allowed external/source surfaces | explicit concrete unavailable/no-runner branch | existing `NotConfigured` or no source invocation | never Fake/Missing conversion |
| `Missing` | none | graph incomplete and rejected | no invocation identity | never Disabled/Fake |

```text
complete(profile, entry) =
    validated_schema_and_profile
 && exactly_one_selected_entry
 && profile_binding_matrix_passes
 && one_local_authority
 && local_base_ports_27_of_27
 && external_ports_9_of_9
 && selected_entry_parameters_match
 && worker_slots_resolved_or_explicit_disabled
 && configured_outbound_routes_10_of_10
 && technical_and_diagnostic_policy_valid
 && selected_entry_factory_complete
 && one_nonclone_handoff
 && entry_runtime_ownership_complete
```

`complete=false` 时不得启动 API listener、Worker source task、Jobs runtime 或 application invocation。Explicit Disabled 只满足允许 Disabled 的 peripheral surface；它不能替代 local authority、entry parameter 或 Missing slot。

## 7. 配置项清单

> 校准来源：
> - `design-calibration/04_config_step_07_config_items.md` §§8~35
>
> 延伸阅读：
> - 上述中间产物的“Catalog notation and common semantics”“Complete configuration demo”“Cross-configuration closure audit”。

本章是 operator-facing configuration schema 的主要可落码输入。所有配置文件必须是 UTF-8 strict JSON object，最大编码大小为 `1,048,576` bytes；BOM、注释、尾逗号、重复 key、未知 key、`null`、浮点/指数/字符串数字和隐式 trim/case-fold 均拒绝。正式示例中的 JSONC 只用于解释，运行时必须删除注释并保持 strict JSON。

### 7.1 命名、格式与公共语义

| 规则 | 约束 |
|---|---|
| 顶层模块 | 18 个固定功能模块；本地文档不使用 `capabilityHub` wrapper |
| key style | ASCII lowerCamelCase；每层 unknown/duplicate key reject |
| symbolic name | 1..128 ASCII bytes；首字符为字母或数字；其余允许字母、数字、`.`、`_`、`-` |
| enum wire value | closed lowerCamelCase，大小写敏感，无 alias |
| integer | JSON integer；不接受 float、exponent 或字符串 coercion |
| duration | 正整数毫秒；不接受带单位字符串 |
| bytes/count | 每项使用明确 inclusive bound；不 silent clamp |
| conditional field | 仅在所属 variant 需要时出现；其他 variant 必须省略而不是写 `null` |
| raw secret | 任意模块都禁止；只能出现 symbolic credential/provider/locator/certificate/key ref |
| named registry | 每个成员必须从 selected graph 可达；orphan、大小写冲突、cycle 均 reject |

### 7.4 Technical policy shape and bounds

| Value family | Bound | Cross-field rule |
|---|---:|---|
| API/Worker phase timeout | `1..600000 ms` | narrower phase cannot exceed owning whole deadline |
| Jobs run timeout | `1..86400000 ms` | delay plus attempt must fit remaining deadline; no extension |
| external/local/commit timeout | `1..600000 ms` | observation timeout does not imply mutation retry |
| byte limit | `1..16777216` | complete encoded bytes checked before decode; no truncation |
| public page limit | `1..1000` | caller over limit rejected, not clamped |
| planning/fetch/internal page | `1..10000` | stable cursor and collect-before-mutate remain mandatory |
| Worker parallelism | `1..1024` | one global permit gate; never multiplied by six sources |
| total attempts | `1..8` | includes initial call; retry count is `attempts - 1` |

Every retry object has required `attempts`, `delay.initialMs`, `delay.maximumMs`, `delay.multiplierNumerator`, `delay.multiplierDenominator` and `delay.maximumJitterMs`. `initialMs <= maximumMs`; rational multiplier is checked integer arithmetic in `1..16`; no library default or floating-point coercion is permitted. A policy ceiling never independently authorizes retry.

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md` §§8~10
>
> 延伸阅读：
> - 上述中间产物的“Sensitivity normalization”“Sensitive material flow”“Cross-sensitive leakage audit”。

| 级别 | 精确定义 | 示例 | 存储与输出规则 |
|---|---|---|---|
| `public` | closed schema/family/technical value，无 topology/credential identity | profile、entry、kind、constructorRef、bounded numeric policy | protected config；仅按 fixed allowlist 输出 |
| `internal` | 非秘密但未经控制的改变有运营风险 | selected path class、registry cardinality、TLS mode | protected config；只输出 low-cardinality category |
| `sensitive` | 暴露 topology、identity、route、fixture 或 credential inventory 的 metadata/ref | endpoint、store/adapter/feed/actor/route/transport/TLS/credential/fixture refs | protected file only；full value 不进任何 output |
| `secret` | 授予访问或包含受保护正文的 material | token、password、DSN credential、private key、cert/trust body、decrypted provider response | 禁止进入 JSON/env/CLI/doc/fixture metadata/root/output；只从 provider 直达 exact constructor |

Symbolic grammar 只降低解析风险，不会把 operational identity 变成 public。敏感级别由语义决定，审计不得记录整个 object。

#### 敏感配置读取图：ref-only startup injection

```text
[protected strict JSON: metadata/ref only]
  -> [grammar/kind/family/reachability/profile validation]
  -> [deployment-injected provider registration]
  -> [credential/TLS material resolution]
  -> [same-family exact constructor]
  -> [adapter-private opaque runtime handle]
  -> [complete graph activation]

Never enters:
  CapabilityRuntimeConfig / application / domain / contracts
  log / error / metric / span / report / event / audit body
```

Provider registration 由 composition boundary 注入；JSON 不能下载 plugin、创建 dynamic Port 或选择 arbitrary locator。Material 只交给引用它的 exact constructor，并保持 constructor 所需的最短生命周期；不得放入 generic bag 或 application service。任一 required material、provider、TLS pair、constructor 或 probe 失败时丢弃 partial graph 并阻断 activation，绝不 fallback Fake/Disabled/inMemory/plaintext。

### 8.1 敏感配置清单

| 配置组 | 敏感级别 | 存储方式 | 可明文进入 protected JSON | 轮换方式 | 审计要求 |
|---|---|---|---|---|---|
| store/adapter/feed/actor/route/transport refs | sensitive | symbolic name | 仅 ref | new complete ref graph + restart | family/path class、approved safe digest、result；不记录 full ref |
| `trustedActors.*.actorRefs` | sensitive | bounded opaque actor refs | 是，protected only | new matcher section/ref + restart | family、count/set digest；不记录 values |
| endpoint address | sensitive | bounded no-userinfo URI | 是，non-secret locator only | new endpoint/ref + restart | scheme category + approved digest；不记录 address |
| provider/locator/version refs | sensitive | `credentialRefs` metadata | 仅 ref | provider-side new version/ref + restart | credential kind、approved digests、resolution class |
| trust/cert/key refs and TLS policy | sensitive | credential refs + closed TLS branch | 仅 ref | atomic trust or cert/key set + restart | mode、set digest、validation result |
| fixture artifact refs | sensitive | test-owned artifact ref | 仅 ref | new schema-compatible ref + restart/test rerun | kind/schema/digest；不声称测试/evidence |
| token/password/DSN/private key/cert/trust body/provider response | secret | provider-owned material | 否 | provider operation + validated restart | provider-side access audit；Hub 无 value field |

Credential kind 必须与 constructor capability 精确匹配：`token`、`password`、`connectionCredential` 只交给声明支持该 kind 的 transport/store；`trustBundle` 只交给 server-auth/mTLS；`clientCertificate` 与 `privateKey` 只作为同一 mTLS constructor 的原子配对。不得 kind coercion、拼接 DSN、从 endpoint userinfo 提取 credential，或让 constructor 查询未被 validated graph 选择的 locator。

### 8.2 Resolution、lifetime 与 rotation

| 阶段 | 允许 material | owner / retention | 失败行为 |
|---|---|---|---|
| parse/merge | bounded ref 与 non-secret endpoint metadata | `infra/config.rs` candidate lifetime | raw-secret pattern/forbidden key value-free reject |
| graph validation | ref/kind/family/reachability/profile | validator；validated metadata only | mismatch/orphan/cycle reject |
| provider lookup | registration handle + credential metadata | private composition startup operation | missing/unavailable registration blocks configured graph |
| material resolution | provider-owned secret material | provider -> exact constructor；shortest lifetime | expired/forbidden/unavailable fail-closed |
| adapter construction | resolved material + endpoint/TLS | opaque adapter handle only | failure disposes whole partial graph |
| application handoff | exact trait objects | process lifetime | ref/material/root 不跨 boundary |
| shutdown/replacement | opaque handles | old process owner | no config dump/secret-derived report |

Rotation 使用完整新 artifact 和新 process。Endpoint/ref、credential version、trust bundle、mTLS cert/key pair、actor matcher、ten-route graph 和 fixture 均重新执行完整 validation/assembly/barrier。Cert/key 必须原子更换；compromised/revoked/expired material 只允许 fix-forward，不允许 rollback 恢复。当前没有 secret watcher、live refresh 或 online last-known-good。

### 8.3 禁止输出

| 输出面 | 允许 | 禁止 |
|---|---|---|
| validation issue | stable category、path class、expected type/kind、profile、safe issue ref | raw value、sensitive member、endpoint/locator/actor、secret-derived digest |
| log/error | family/slot/profile/binding kind/low-cardinality result | raw config/ref、provider response、body、credential identity |
| metric/span/event | formal 03 allowlisted fields and low-cardinality counts | ref/address/actor labels、raw cause、baggage material |
| Job/report/receipt/outbound capture | existing body-free typed carriers | config/provider/TLS/fixture material |
| config control-plane audit | change/actor/reason refs、path class、approved safe projection/digest、outcome | raw old/new document/diff、full sensitive refs、secret/hash |
| future evidence index | owner-generated alias/digest only after real run | fabricated alias/result、raw config/inventory |

“Redacted” 不等于对任意 forbidden value 求 hash。Secret-derived hash 永远禁止；sensitive metadata digest 只有在 implementation boundary 定义 exact canonical safe projection 后才允许，否则省略该字段。Provider access audit 和 config change audit 属不同 owner；本文不创建 Hub-owned audit repository、run_id、evidence alias、ticket、signature 或 signoff。

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_loading_validation_activation.md` §§8~22
>
> 延伸阅读：
> - 上述中间产物的“Validation phase order”“Whole-graph cross-field validation”“Stage 0~7 runtime assembly”“Failure atomicity”。

#### 配置加载流程图：L3-capability-hub 配置加载与校验

```text
[selector/assertions]
  -> [one strict JSON byte source]
  -> [duplicate/unknown/forbidden structural parse]
  -> [bounded environment overlay]
  -> [V0..V8 closed validation]
  -> [immutable CapabilityRuntimeConfig]
  -> [provider-to-constructor resolution]
  -> [Stage 0..7 complete graph]
  -> [entry-specific barrier]
  -> [one API | Worker | Jobs exposure]
```

### 9.1 Source merge contract

1. Resolve at most one CLI/env file selector and expected profile/entry assertions; conflicting selectors reject.
2. Read one byte source with the `1,048,576` byte cap; no directory scan, multi-file include or remote source.
3. Strict-decode JSON while preserving duplicate detection; reject BOM/comment/trailing comma/unknown/forbidden/null/wrong type.
4. Enumerate only the 21 bounded content env names; reject unknown reserved-prefix names without reading them into diagnostics.
5. Apply each present env leaf to its exact candidate slot. Empty or invalid values are present-invalid and reject; no fallback to JSON.
6. Validate the complete candidate and all refs before constructing any runtime object.

Raw source ownership ends in `infra/config.rs`; candidate/provenance is private infrastructure state. Application/domain/contracts never read source names or raw paths.

### 9.2 V0~V8 validation order

| Phase | Validation | Failure disposition |
|---|---|---|
| `V0` | document byte/UTF-8/JSON shape/duplicate/unknown/forbidden | aggregate value-free issue refs；no candidate exposure |
| `V1` | schema version and fixed compatibility literals | unsupported/mismatch reject |
| `V2` | primitive type、enum、length、numeric range | no coercion/clamp/default |
| `V3` | closed union shape and conditional-field presence | irrelevant payload/missing branch field reject |
| `V4` | root selected entry/policy refs and one-member cardinality | mismatch/orphan/multiple reject |
| `V5` | profile matrix: durable/system/fake/TLS constraints | incompatible graph reject before constructor |
| `V6` | registry reachability、family/kind、sharing、cycle、9/6/10 cardinality | any orphan/wrong-family/cycle reject |
| `V7` | endpoint/transport/TLS/credential and provider-registration metadata | malformed/downgrade/unregistered reject |
| `V8` | whole-graph technical policy/deadline/retry and complete predicate | unsafe/incomplete graph reject |

The existing formal 03 validation carrier remains authoritative. Parser/validator may aggregate deterministic safe issue refs, but this design does not authorize a new public error enum or raw parse text carrier.

### 9.3 Cross-field gates

| Gate | Exact predicate |
|---|---|
| selected sections | exactly one entry and one technical policy, both selected by root and kind-symmetric |
| local authority | exactly one; Deployment durable; no selected orphan store |
| external graph | 9/9 slots; branch refs exact; no Missing |
| Worker | selected Worker has 6/6 source decisions; configured feed/actor pair atomic and same family |
| collaboration | configured family has exactly 10 distinct route refs/families |
| material graph | every selected registry member reachable; no cycle/case collision/wrong-kind sharing |
| endpoint/TLS | no userinfo/forbidden query；Deployment network uses server-auth or mTLS/TLS 1.3 |
| credentials | provider registered；kind matches consumer；mTLS trust/cert/key branch complete |
| retry/deadline | integer bounds and ratios valid；policy only caps already-authorized retry |
| diagnostics | off/redacted only；allowlist remains non-configurable |

### 9.4 Stage 0~7 assembly

| Stage | Constructed prefix | Required gate | On failure |
|---:|---|---|---|
| 0 | validated immutable root identity | V0~V8 zero issues | no runtime object |
| 1 | one local authority family | exact inMemory/durable branch and store material | close/dispose prefix |
| 2 | clock、ID、codec/digest | profile-compatible exact branches | dispose all prefix |
| 3 | 27 local/base Ports and UoW composition | all 27 present from same authority | no partial local graph |
| 4 | 9 external Ports and collaboration route constructors | 9/9 plus configured 10/10 routes | no configured-to-fake/disabled fallback |
| 5 | technical policy projections and diagnostic wrapper | exact selected policy | no entry handoff |
| 6 | selected API/Worker/Jobs factory material | entry-specific complete predicate | close source/adapter prefixes |
| 7 | single non-Clone handoff and runtime ownership | one exact entry barrier ready | no listener/task/request exposed |

Provider material is resolved only for selected Configured branches and injected into exact constructors. Disabled/Fake branches never read production credentials. Constructor capability proof is product-specific, but it must deterministically satisfy the existing Port/transaction/failure contract before Stage 7; inability to prove compatibility is an implementation prerequisite or controlled reopen, not permission to weaken the gate.

### 9.5 Entry activation barriers

| Entry | Barrier before exposure | Forbidden early effect |
|---|---|---|
| API | local/external graph complete；typed parameters and non-cancelling wrappers ready；listener still closed | bind/listen/accept request before ownership transfer |
| Worker | all six runners resolved or explicit Disabled；configured feed/actor constructors ready；tasks parked | fetch/decode/call application before all runners parked |
| Jobs | one-shot decoder、all 8 Job dispatches、planning/reentry policy and graph ready | accept/run Job before exact dispatch set ready |

Only after the selected barrier passes may ownership move to the entry runtime and exposure begin. Failure closes every object created in reverse ownership order; no partial listener/source/job graph remains. The active root is immutable. File/env/provider drift or expiry is checked only by a future activation/release gate unless the concrete adapter reports its existing typed runtime failure; there is no in-process source reread or graph mutation.

| 配置组 | 加载时机 | 校验方式 | 生效方式 | 失败策略 |
|---|---|---|---|---|
| root/profile/entry | startup | V0~V5 + selected symmetry | new process | fail-fast |
| local/external/source/route graph | startup | V3~V8 + constructor proof | Stage 1~7 | all-or-nothing；no fallback |
| numeric policy/entry scalars | startup | type/range/cross-deadline | frozen typed projection | fail-fast；runtime effect remains formal 03 |
| credential/TLS material | startup exact branch | ref/provider/kind/pair/constructor | opaque handle | fail-closed；prefix disposal |
| diagnostics | startup | closed enum + fixed allowlist | frozen wrapper | invalid fails startup；observer failure non-cancelling |

### 10.3 Product-neutral change chain

```text
Proposed -> Classified -> Reviewed -> CandidateComplete
  -> V0..V8 Validated -> Stage 0..7 Assembled
  -> EntryBarrierReady -> CutoverRequested
  -> [CutoverConfirmed | CutoverRejected | CutoverUnknown]

Any pre-cutover failure -> CandidateRejected -> BaselineRetained

Confirmed + abnormal effect -> RollbackOrFixForwardReviewed
  -> eligible complete candidate
  -> full validation/assembly/barrier again
  -> new external cutover decision
```

These labels are control-plane semantics, not implemented Hub enums/states. `CutoverUnknown` pauses automation until the external owner establishes actual process state; it must not be inferred from first request、log absence or Hub business truth.

### 10.4 Rollback rules

| Scenario | Candidate action | Allowed target | Forbidden shortcut |
|---|---|---|---|
| parse/V0~V8 failure | reject before construction | running approved baseline unchanged | edit-and-continue/lower-source fallback |
| provider/constructor failure | dispose prefix and reject | approved baseline if externally retained | Fake/Disabled/inMemory/TLS downgrade |
| entry barrier failure | close non-exposed graph | baseline retained | reduced listener/source/job exposure |
| cutover rejected/unknown | external owner closes or investigates | only externally confirmed artifact | claim rollback or blind second cutover |
| post-cutover anomaly | classify and review rollback/fix-forward | previous approved, still compatible artifact or new candidate | in-place patch/business truth rewrite |
| credential compromise/revocation | revoke and fix-forward | no unsafe previous ref | restore compromised material |
| route/source anomaly | new complete 10-route/6-source artifact | previous complete valid graph | partial live disable/swap |
| local authority anomaly | operations pause + data compatibility review | compatible previous authority | config-only migration/split authority |

Rollback target must pass artifact integrity、schema/binary compatibility、profile/entry purpose、current dependency/material validity、data compatibility、risk review, and a fresh full activation. Prior success is not reused as current proof. Rollback never edits capability identity/registry/descriptor/relation/exposure/trace/impact/reference/material records, idempotency winners, Job journal/report, snapshots/captures/intents or prior typed outcomes; restarting a process does not authorize mutation replay.

### 10.5 Audit boundary

| Phase | Minimum future record semantics | Forbidden |
|---|---|---|
| proposal/review | change/actor/reason/reviewer refs、scope/risk、baseline/candidate identity | raw config/diff/body/signature claim |
| validation | schema/profile/entry、result、safe issue refs/path classes | parser text/offset/raw env/ref |
| assembly/barrier | stage/entry/result class、counts `27/9/6/10` | graph/material/endpoint/provider details |
| cutover | external result class/time/target class | fabricated deployment/run evidence |
| rollback/fix-forward | from/to identity、reason、eligibility/result | raw documents/business truth diff |

Retention、access-control、tamper evidence and storage product are formal 07/09 prerequisites. If satisfying them requires a Hub-owned repository、Port、DTO、event or state, implementation must stop and reopen formal 03; this chapter does not authorize such code.

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_degradation.md` §§8~23
>
> 延伸阅读：
> - 上述中间产物的“策略术语与判定顺序”“全局失效模式表”“分层运行行为矩阵”“下游测试切口合同”。

### 11.1 策略术语

| 术语 | 精确定义 | 适用层 | 不表示 |
|---|---|---|---|
| `fail-fast` | source parse、V0~V8、Stage 0~7 或 entry barrier 确定失败即停止 candidate，dispose owned prefix，不暴露 facade/listener/task/source | startup/new activation | crash-loop policy、business rejection、automatic retry |
| `fail-closed` | 安全/身份/credential/TLS/trust/redaction 条件无法证明满足时拒绝 material/constructor/candidate，不选宽松 branch | security/provider/constructor gate | 无 TLS、旧 secret、业务 `Forbidden` |
| `degraded` | formal 03 已定义的正常 typed read/reference/consumer surface，表达部分信息不可用但保持 no-write/no-fabrication | activated Query/read/reference/handoff | 配置非法、consistency defect、generic swallow |
| `delayed` | formal 03 已允许且有 effect/reentry proof 的 pending/retryable prerequisite surface | activated Worker/Jobs | sleep loop、无界重试、永久失败延期 |
| `failed marker` | formal 03 已定义并由 owning journal/report/collaboration protocol 持久化或返回的 terminal typed outcome | activated Jobs/Outbound/handoff | 配置层新增 marker、伪造 receipt/report/evidence |
| `not applicable` | 能力不在 P0 control plane，因此不存在依赖、fallback 或告警要求 | config center/admin/hot reload/online LKG | “暂时不用”的隐式 Disabled |

判定顺序固定为：

```text
[raw source / candidate]
  -> parse or V0..V8 invalid?
       yes -> fail-fast / InfraError::RuntimeAssembly / no graph
  -> required security/provider/material cannot be proven safe?
       yes -> fail-closed + fail-fast candidate / no constructor exposure
  -> Stage 0..7 or entry barrier fails?
       yes -> RuntimeAssembly / dispose complete owned prefix
  -> selected entry activated with frozen root
  -> external call fails?
       yes -> existing ApplicationPortFailureKind + formal effect-proof retry
  -> typed normal incomplete/unavailable result?
       yes -> existing degraded/delayed/failed-marker surface only
  -> persisted relation/commit/rollback invariant fails?
       yes -> existing ConsistencyDefect / CommitOutcomeUnknown /
              TransactionRollbackFailed; never downgrade
```

前三层是配置失效策略；激活后的 typed surface 只用于防止错误转换。配置 loader/builder 不创建 degraded、delayed 或 failed marker；也不新增 error enum、API response、receipt、Job report、observer profile 或 recovery flow。

### 11.2 错误分层与禁止转换

| 失败位置 | 既有分类/表面 | 允许动作 | 禁止转换 |
|---|---|---|---|
| raw source/parser/V0~V8 | `InfraError::RuntimeAssembly` | stop candidate；safe issue observation | API response、receipt、report、business marker |
| Stage/provider/constructor/entry assembly | `InfraError::RuntimeAssembly` | dispose complete prefix | partial graph、Fake/Disabled/inMemory fallback |
| activated external Port | existing `ApplicationPortFailureKind` | exact mapping；effect proof 后 bounded retry | generic config error、silent degradation |
| temporary/timeout Port failure | exact Port kind | only formal flow-authorized retry | attempts value alone as retry proof |
| permanent/invalid/unexpected source failure | exact Port kind | fail current flow | automatic retry、marker fabrication |
| normal typed unavailable/partial/reference/handoff | existing typed surface | preserve exact state/reason/result owner | config exception |
| persisted relation/index/sidecar defect | `ConsistencyDefect` | stop affected flow；owner repair | Missing/degraded/auto repair/current-truth fallback |
| commit durability uncertain | `CommitOutcomeUnknown` | exact durable observation | blind mutation retry/claimed success/failure |
| rollback failure | `TransactionRollbackFailed` | preserve source chain/operator inspection | claim rollback success/continue candidate |
| observer/redaction/sink failure | existing non-cancelling observer rule | suppress unsafe field | alter business result/recursive body logging |

### 1.2 真相源优先级与回开

1. 正式 `00/01/02` 决定 scope、responsibility、owner 和 architecture。
2. 正式 `03` 决定 exact implementation contract 和 business oracle。
3. 正式 `04` 决定 operator-facing configuration contract。
4. 本文决定 test identity、data/environment、automation、report/evidence 和 regression contract。
5. `design-calibration/05_test_plan_step_*.md` 是本文每章 exact 展开和机械审计来源。

若测试无法从 `03/04` 唯一确定 typed terminal、state/version/history、effect/zero-effect 或 failure oracle，必须停止 affected cut 并回开 owning design Step；不得用日志文本、mock count、elapsed time、外部产品状态或实现者猜测补真相。

旧版 `05-测试方案.md`、旧版 `06-验收标准.md`、README 的执行/provider/cost/approval简写、旧 `TC-001..012`、旧对象/拓扑/阈值和无 provenance 的结果均只属于 historical material。它们不建立 alias，不参与 scope/case/oracle/evidence，也不通过同义词迁移回流。

## 4. 测试策略与分层

> 校准来源：
> - `design-calibration/05_test_plan_step_04_strategy_layers.md` §§4~11
>
> 延伸阅读：
> - 上述中间产物的“七层测试策略”“family placement”“earliest-discovery”“selected-entry smoke”和“cross-layer duplication audit”。

#### 测试分层图：风险最早发现与信心累积

```text
L0 static / compile
  -> L1 unit / property / generated tables
     -> L2 service semantics with deterministic Ports and UoW
        -> L3 adapter / runtime contract and fault seams
           -> L4 API / Worker / Jobs entry runtime
              -> L5 selected product integration (P1)
                 -> L6 release evidence aggregation
```

关键说明：L0~L4拥有P0 semantic discovery；L5只证明selected product parity；L6只汇总真实低层raw evidence，不重新定义business pass。

### 4.1 Layer contract

| Layer | Primary objects | Finds earliest | Cannot replace |
|---|---|---|---|
| L0 static/compile | manifests/imports/public signatures/protocol inventory/Rustdoc/config schema | dependency、naming、inventory、forbidden field/owner、documentation drift | runtime behavior |
| L1 unit/property | object factories、canonical codec/digest、24 state registries、config parser/validator | invariant、all638 pairs、boundary/illegal、strict source/profile | UoW/Port call order |
| L2 service | 26 C + 33 Q、UoW/idempotency、derived semantics | typed terminal、write-set、sidecar symmetry、Query no-write | entry mapping/product parity |
| L3 adapter/runtime contract | repositories、9 external Ports、Stage 0~7、Outbound、fault barriers | persistence parity、commit/fault/retry/cleanup/binding | public entry lifecycle |
| L4 entry runtime | API、6 Worker sources、8 Job dispatches | decode/header/barrier/non-cancelling invocation/drain/final report | lower semantic oracle |
| L5 selected integration | selected durable/transport/source/route/TLS/observer products | product-specific parity、availability、safe cleanup | P0 controlled evidence |
| L6 release evidence | release smoke、checks、reports/evidence bundle | missing/raw-report/redaction/provenance/release manifest gap | acceptance decision |

### 4.2 Primary placement

| Cut family | Primary layer | Secondary confidence | Rule |
|---|---|---|---|
| module/dependency/doc/protocol | L0 | L1 codec/compile | no runtime-only discovery |
| object/state/digest | L1 | L2 consumer | all pairs below E2E |
| Command/Query | L2 | L4 mapping | entry success cannot self-prove service semantics |
| Inbound/Job lifecycle | L4 | L2 owned service + L3 runtime | entry owns header/barrier/lifecycle only |
| Outbound/TX/repository | L2/L3 | L4 trigger | phase/commit authority stays below release |
| binding/config | L1/L3/L4 by detection phase | L5 product parity | Missing/Disabled/fallback remains exact |
| observation/redaction | L0/L1/L3 | L4/L6 scan | report scan cannot replace producer oracle |
| config failure | earliest of L1/L3/L4 | L6 provenance | each `CFG-F-*` remains independently traceable |

### 4.3 Duplication and missing-result rules

- A semantic assertion has exactly one primary owner；secondary layers reference its TC/EV and add only mapping/parity/lifecycle confidence。
- P0 high-risk behavior cannot be deferred solely to L5/L6 or manual review。
- Fast PR may reduce noncanonical permutations,never a canonical TC identity；main remains full denominator owner。
- Missing suite/check/environment/artifact/report is`blocked_dependency|invalid_artifact|not_evaluated`as applicable,neverpassed。
- Selected product unavailable cannot compensate or invalidate an otherwise separate P0 semantic result；it blocks selected/release claims where required。

### 6.2 Oracle precedence 与共同执行纪律

```text
typed public/application terminal
  -> exact repository/stored carrier state when persistence is expected
  -> exact sidecar/capture/journal symmetry
  -> exact zero-write / zero-call spy for prohibited effects
  -> observer projection only for observer-contract assertions
```

1. `DomainError::InvalidStateTransition`只表示正式domain state错误；其他public/application failure使用既有closed typed surface，不从prose创建新枚举。
2. `ApplicationError::ConsistencyDefect`只用于已加载typed relation不可能成立；正常missing/empty/not-visible/degraded不是corruption。
3. `ApplicationError::CommitOutcomeUnknown`必须通过exact transaction/idempotency/truth resolution判定；timeout、日志或一次missing不能代替resolution。
4. Command duplicate只读immutable stored command result；Inbound duplicate只读stored receipt；Job duplicate只读matching typed report。
5. Query的UoW/reserve/save/append/capture/handoff/collaboration/refresh/rebuild调用均为0。
6. Outbound Phase A/B/C独立；local capture不拥有physical delivery/attempt/retry/DLQ lifecycle。
7. Job使用frozen plan、ordinal target terminal cell和final report symmetry；不得rescan scope、replan或修复core truth。
8. log/error text/`Debug`/elapsed time/private fake map/external product state/manual observation均不是business oracle。

### 6.3 Command 与 Query shared branches

### 10.2 Performance and availability

Performance采用structure-first hard gates：core call independence、zero peripheral call/write、UoW/idempotency/version preservation必须通过；每次真实运行还须记录workload/data/profile/entry/topology、sample count、duration/throughput/percentile fields和resource context，但所有数值裁决当前均为`not_evaluated`。本文没有P95/P99、throughput、availability percentage、cost coverage或capacity threshold；一次sample不得推导验收线。

Numeric threshold只能由named owner在selected environment/profile/entry/topology、workload distribution、warmup/sample/window/resource envelope和failure budget明确后受控回开formal 00/05/06/07/09。

Availability注入search/export/ecosystem/SDK enhancement、external resolver、governance/method/secret/audit/document refs、event collaboration、runtime/tools consumer和observer sink的delay/unavailable/failure。Required behavior是typed degraded/wait/failure和core truth isolation；禁止synthetic truth、fallback authority、local delivery state或observer-driven rollback/retry。

### 10.3 Security、responsibility and trace

Forbidden corpus覆盖secret/token/key/cert、MCP/A2A/API/provider body、governance Policy/approval、method source/body、runtime/tools execution、marketplace transaction、provider route/cost、SDK client/cache及audit backend body。扫描面包含protocol/domain/store/event、log/metric/span/durable observer、raw artifact、report、stdout/stderr；matched material允许计数、class和source digest，不得被复制到finding。

Accepted change必须形成`source/context -> exact truth/change -> trace -> result/capture`；rejected/no-op不得生成success chain。Derived/output必须保存source scope/version/result/ref subset，不能成为current truth。Recorded review和active governance seam、Accepted descriptor和policy-complete exposure、consumer ref和formal applicability必须通过差分用例证明不是同一事实。

### 10.4 Consistency、recovery、observation and configuration

| Specialty | Mandatory fault / differential | Blocking oracle |
|---|---|---|
| UoW | begin/load/save、Durable/NotDurable/Unknown、rollback/cleanup | whole set atomic；Unknown exact resolution；original error retained |
| replay/race | same/different digest、CAS/unique winner、corrupt sidecar/index/cursor | one winner/stored replay；no overwrite/scan/repair |
| Outbound | every A source/snapshot/capture、B Port、C bind/race/Unknown point | A atomic；B nonrollback；C one stable intent；no delivery truth |
| Job | reserve/plan/target effect+journal/final report/complete faults | frozen plan、ordinal recovery、safe terminal only；no replan/reexecute |
| lifecycle | every Stage/start/spawn/barrier/stop/drain/join point | complete prefix disposal and owned terminal；no detached task |
| observation | 60 logs/48 metrics/27 spans+3 events/20 durable/11 readers | exact presence + forbidden absence；Off byte-equivalent；sink neutral |
| config | strict source/graph/Missing/material/Stage/barrier/runtime/frozen/dynamic/rollback | fail-fast/closed、no fallback/partial root/hot reload/unsafe cutover |
| dependency/Rustdoc | manifest/import/public surface and source declaration scan | only allowed edge；complete English`///` including every nested field/variant/method |

Observation profile presence与redaction scan必须同时成立；scan alone不能证明required profile存在。Off与Redacted基线的business terminal、write-set、carrier bytes和call order相等；required field invalid时whole affected emission按正式规则omit/reject，optional absent不补null，atomic correlation group不得partial，sink/redactor fault最多产生一个safe nonrecursive fallback且不得改变business flow。

20/20 NFR均有P0 method、environment、oracle、suite和既有`EVC-CH-*` candidate source；candidate不是formal EV。Selected product parity只增加置信度，不能补main canonical结果。当前benchmark、suite、sample、scan和NFR verdict均未执行。

## 11. 缺陷管理与复验规则

> 校准来源：

>
> 延伸阅读：

### 11.1 Observation classification before severity

只有在valid baseline、case/data/environment/harness下违反正式00~04 oracle的`OBS-CLASS-IMPLEMENTATION`才进入S/A/B。其他non-pass仍可能阻断gate，但不得冒充implementation defect或pass。

| Observation class | Exact condition | Required disposition | Result relationship |
|---|---|---|---|
| `OBS-CLASS-IMPLEMENTATION` | observed behavior违反formal oracle | 确认影响后分S/A/B、修复、复验 | usually `failed` |
| `OBS-CLASS-TEST-SYSTEM` | manifest/fixture/fake/runner/check/report本身错误或不稳定 | 保留原run非pass，修测试系统并重跑affected scope | failed/timeout/flaky/invalid |
| `OBS-CLASS-DESIGN-BLOCKER` | active sources矛盾、缺oracle或无法一一落码 | 停affected cut，回开exact owning design Step并同步下游 | no pass |
| `OBS-CLASS-PREREQUISITE` | repo/core dependency/selected product/environment尚不可用 | 记录exact prerequisite和scope | `blocked_dependency` |
| `OBS-CLASS-NUMERIC-SAMPLE` | sample存在但active numeric threshold不存在 | 保留sample，numeric status=`not_evaluated` | structural result独立 |
| `OBS-CLASS-EXPECTED-ORACLE` | scripted unavailable/timeout/error符合typed + zero-effect oracle | 仅该declared negative case可pass | raw-derived only |
| `OBS-CLASS-INCOMPLETE-RUN` | cancel/unexpected timeout/missing cell/report fault且根因未定 | 保留partial raw并继续归因 | non-pass |

归因必须带raw input、immutable config/profile/entry、TC/DS/parameter和harness provenance。“无法复现”不能把既有valid failure改成pass或closed。

### 11.2 Severity and veto policy

| Level | Definition | Required action | Current-exit effect |
|---|---|---|---|
| S | veto、truth/ownership/security/evidence-integrity破坏，或可能产生second/unexplainable truth | 必修；不得风险接受；affected regression + R2/R4按触发执行 | immediate block |
| A | P0 typed/zero-effect/config/observation/Rustdoc contract失败且未达到S | 当前退出前必修；重跑family/suite/check | block |
| B | confirmed non-P0或presentation/maintainability issue，且无P0/provenance影响 | 修复或由formal 06授权角色基于真实证据裁决 | no automatic P0 block |

Rustdoc遗漏任何declaration、struct field、enum variant/payload field、trait、method或callable至少为A；enum struct-variant field-level `pub`同样阻断。若同时改变public schema、dependency或ownership，则按更高影响升级。

| Veto | Mandatory S trigger | Required minimum regression direction |
|---|---|---|
| `VF-CH-001` | 五个core closure任一不能闭合或canonical obligation orphan | all owner families + full main/release closure |
| `VF-CH-002` | URL/provider/runtime/tool/SDK/listing/derived view替代identity | identity/domain/service + responsibility/redaction |
| `VF-CH-003` | registry变成allowlist/runtime/cache/listing/availability bit | registry Command/Query/state + responsibility/config |
| `VF-CH-004` | descriptor持有secret/provider route/cost/quota/failover/runtime truth | descriptor/state/OBS + redaction/responsibility/config |
| `VF-CH-005` | Hub拥有approval/Policy/shared rules或review替代approval | governance/exposure families + responsibility/redaction |
| `VF-CH-006` | method relation持有body/source/type/lifecycle truth | method/exposure + responsibility/redaction/dependency |
| `VF-CH-007` | Query/downstream/derived/event/Job反写core truth | affected Q/I/O/J/TX + responsibility/pairing + main |
| `VF-CH-008` | incomplete capability成为formal visible/consumable | exposure/state + state registry/responsibility |
| `VF-CH-009` | source/scope/impact/change/trace/capture缺失或不对称 | mutation/outbound paths + case manifest/pairing/redaction |
| `VF-CH-010` | duplicate/race/replay产生多winner或重复truth | state/TX/repository/service/outbound/jobs + main |
| `VF-CH-011` | cost/finance/telemetry/audit/listing/production body进入Hub truth | full store/output scan + redaction/responsibility/no-static |
| `VF-CH-012` | forbidden sibling compile ownership或copied replacement | full dependency/static/main/release |
| `VF-CH-013` | historical object/number/topology/ID进入active mainline | full static/config/responsibility/no-static/release audit |

全部13项不可waive。证明veto negative的check不可用时仍阻断退出，不表示veto已观测，也不能通过风险说明补偿。

### 11.3 Retest scope and immutable defect lifecycle

```text
observed non-pass
  -> preserve raw run
  -> classify observation and impact
  -> assign S/A/B only after implementation attribution
  -> identify exact formal source, TC/DS/EV and regression surface
  -> fix implementation/test system or reopen design owner
  -> execute a new explicit retest run
  -> compare immutable old/new artifacts
  -> execute required family/suite/check regression
  -> close or submit only eligible residual to formal 06
```

| Changed/fixed surface | Targeted retest | Mandatory expansion | Full-main trigger direction |
|---|---|---|---|
| protocol/codec/digest/public schema | failed vector + all negative vectors | static + direct service/entry consumers and checks | public semantics/provenance change |
| domain/state guard | failed member/pair | whole affected family；shared generator means all638 | shared invariant/terminal/exposure change |
| Command/Query | failed flow and shared branches | service suite + repository/entry/obs consumers as applicable | write-set/UoW/idempotency/no-write/visibility change |
| Inbound/Outbound/Job | failed source/phase/target | entire affected flow family + TX/bind/config/pairing | barrier/body/A-B-C/reentry/report semantic change |
| repository/UoW | failed method/fault | exact 22/110 surface and every direct consumer | authority/commit/winner/result-store change |
| binding/config | failed stage/row | affected BIND/CONFIG plus entries/static/checks | graph/profile/source/fallback/barrier/safety change |
| observation/redaction | failed profile/corpus | all changed producers + OBS/CONFIG16 + redaction | selector/schema/neutrality/provenance change |
| gate/check/report/evidence | failing and passing tool fixtures | actual suite-to-report chain + pairing/no-static/case manifest | aggregation/status/digest/schema change |
| Rustdoc/dependency | failed member/edge then full scanner/graph | compile/static and consumers if signature changed | public shape or ownership direction change |

未来defect record必须包含first failing run、safe expected/observed class、classification/severity、formal/veto/AC/NFR impact、root-cause category、fix scope、new run、exact regression set、raw/report refs和remaining cells。旧失败和新复验使用不同显式run，禁止覆盖、删除、拼接或伪造commit。当前不存在真实defect、fix、retest run或closure bundle。

### 11.4 Automation closure

既有cut漏分支时在同一TC/DS增加parameter/assertion，canonical count仍为189；common helper/check缺口扩充deterministic fixture；release发现的问题必须补最低层primary reproducer。只有真正新增formal obligation且没有owner时，才受控回开00~05并分配新identity。Manual P0 discovery在closure前必须自动化，flaky用deterministic barrier复现且保留每个attempt。

### 13.6 Redaction, review and archive lifecycle

1. Redaction覆盖raw、stdout/stderr、reports、index、review和acceptance drafts；safe finding只包含class/location/digest，不复制matched material。
2. Pairing要求case raw、suite raw/report、EV page和digests全部same-run；no-static禁止手写pass map、raw-less page、cross-run stitching和implicit current run。
3. Human review核对scope、denominator、typed assertions、zero effects、failure retention、AC/VF refs和open disputes；Agent review只能辅助一致性检查，不能自签验收或接受风险。
4. Review status不改变raw status；dispute保留原材料并阻断affected conclusion，直到新证据或正式裁决。

尚无numeric retention policy，因此采用event-based minimum：保留所有用于current acceptance/release的raw/report/digests/index/reviews、所有未关闭defect和risk相关bundle、最近被取代但仍处于争议/回滚/审计窗口的baseline，以及所有failed/flaky/invalid/security finding直到owner按formal policy确认可处置。删除前必须验证无active reference、legal/security hold、open issue或rollback dependency，并留下body-free deletion manifest；本文不声称backend、days、archive或deletion已实现。

当前只建立189个formal evidence contracts；真实evidence instance、alias、artifact、report、digest、review和signoff数量均为0。

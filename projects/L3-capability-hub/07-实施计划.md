### 2.1 总体目标

本轮实施目标是建立可编译、可测试、可送验的Capability Hub capability access truth center。最小可交付结果不是单个MCP注册接口或白名单，而是以下五个闭环及其受控接缝：

| 核心闭环 | 实施结果 |
|---|---|
| `C-CH-1` capability identity | stable typed identity、source/ref、lifecycle/access review和accepted/rejected/replay路径 |
| `C-CH-2` capability registry | current/history/version/visibility和受控目录真相 |
| `C-CH-3` adapter descriptor | MCP/A2A/API接入descriptor、risk/safe summary、typed secret ref和failure mapping；无执行或provider truth |
| `C-CH-4` governance/method relation | governance result/approval seam ref、access review separation、method-library body-free relation |
| `C-CH-5` formal exposure | applicability/visibility、controlled consumer view、server exposure boundary、freshness/degraded语义 |

上述闭环还必须有trace/impact/reference、33个只读Query、6个Inbound、10个Outbound、8个Job、strict config、fake parity、run-scoped test/evidence和acceptance handoff支持。

### 2.2 P0覆盖范围

| 范围层 | 必须覆盖 | 实施含义 |
|---|---|---|
| 核心能力 | `C-CH-1..C-CH-5` | 五个closure均形成实现、测试和evidence trace |
| 功能需求 | `FR-CH-001..FR-CH-016` | 映射到26 Command、33 Query、6 Inbound、10 Outbound、8 Job或foundation cut |
| 业务规则 | `BR-CH-001..BR-CH-037` | 进入domain guard、ownership、redaction、consistency、dependency和failure gate |
| 非功能需求 | `NFR-CH-001..NFR-CH-020` | 使用结构性performance/availability/security/trace/idempotency/observation门禁；无active threshold时保持`not_evaluated` |
| 验收项 | `AC-CH-001..AC-CH-037` | 每项映射真实TC/DS/EV consumer；本文不填写verdict |
| 一票否决 | `VF-CH-001..VF-CH-013`及过程VETO | 每个boundary前置规避；不可风险接受 |

### 6.3 通用Gate与批次规模

| Gate | 最低记录 | 未通过 |
|---|---|---|
| Design | project/current boundary ledger、required reads、immutable design baseline、closure review | `wait_design` |

| Commit | staged scope、message、whitespace、required checks | 不得commit |
| Handoff | hash/message、gates、tests not run、blockers、next boundary、用户改动 | 不得推进下一boundary |

`BATCH-*`是编写和局部验证单位，不是独立commit。每批目标100~300行；预计超过300行继续拆分，超过500行禁止作为单批。状态矩阵、事务/commit resolution、idempotency/reentry、redaction、cross-repo binding、Job terminalization和evidence builder必须独立批次。

### 10.1 Ledger状态机

| 条件 | `gate_status` | `next_allowed_action` | 允许工作 |
|---|---|---|---|
| 尚未读取docs/boundary | `pending` | `read_docs` / `open_boundary` | 只读取和初始化planned record |
| design/source缺口 | `blocked` | `wait_design` | 记录blocker并回设计仓，不改业务实现 |
| build/test/check/evidence实现失败 | `blocked` | `fix_gate_failure` | 只修当前失败及受影响测试工具 |
| external decision等待且无可继续scope | `blocked` | `handoff` | 记录等待方、deadline和safe state |
| all pre-commit gates有真实证据 | `pass` | `commit` | 只提交当前staged boundary |
| commit/handoff完成 | `pass` | `start_next_boundary` | 进入唯一next boundary |

禁止`blocked -> implement`、`pending -> commit`或绕过Handoff Gate直接进入下一boundary。当前设计期没有任何boundary是`pass`。

### 10.2 Pause trigger table

| ID | 触发条件 | 动作与恢复条件 |
|---|---|---|
| `PAUSE-CH-01` | target repo/core/toolchain/P0 root缺失 | pause prerequisite；真实建立后重跑preflight |
| `PAUSE-CH-02` | formal冲突，或field/DTO/Port/flow/state/TX/config/evidence authority缺失 | `blocked + wait_design`；owning design回写并冻结新baseline |
| `PAUSE-CH-03` | 越过allowed scope、合并/split boundary或吸收禁止责任 | pause change control；同步formal07/ledgers或移除越界改动 |
| `PAUSE-CH-04` | worktree有无法归属的用户/其他agent改动或staging混入无关文件 | pause并保护worktree；只在ownership清晰后恢复 |
| `PAUSE-CH-05` | fmt/build/test/check/Rustdoc失败 | `blocked + fix_gate_failure`；修复并按R0/R1/R2复验 |
| `PAUSE-CH-06` | artifact/report/pairing/redaction/no-static/dependency/responsibility失败 | 修工具或等设计；保留failed raw/report/digest，按影响R2/R4 |
| `PAUSE-CH-07` | 任一VETO/S/current P0 A命中 | pause；修复、新run、必要R2/R4；不可waiver |
| `PAUSE-CH-08` | source/config/dependency baseline在run或boundary中漂移 | 当前eligibility失效；冻结新baseline并重跑适用gate |
| `PAUSE-CH-09` | selected product/TLS/source/route不可用 | non-required只记selected blocked；required阻断selected/release |
| `PAUSE-CH-10` | Spike/OQ到期未决或结果不兼容 | pause affected scope；完成adopt/reject/reopen/handoff后恢复 |

### 10.3 Rollback与保存合同

| ID | 场景 | 允许动作 | 禁止 |
|---|---|---|---|
| `RB-CH-01` | current boundary未提交试探失败 | 只清理明确agent-owned edits，或保留WIP等设计 | 触碰用户改动、hard reset、回退其他boundary |
| `RB-CH-02` | 已提交后发现implementation defect | 新fix-forward boundary/commit并保留历史 | 未授权amend/rebase/reset或删除失败记录 |
| `RB-CH-03` | design change使WIP失效 | pause、保留blocker/diff，待新design重作 | private workaround或提交半成品 |
| `RB-CH-04` | config candidate在activation前失败 | reject candidate；approved baseline不变 | lower-source fallback、partial graph或降级Fake/inMemory |
| `RB-CH-05` | cutover后config异常 | compatible previous完整artifact或reviewed fix-forward | in-place patch、partial swap、business truth rewrite |
| `RB-CH-06` | credential compromise/revocation | 新atomic credential/TLS set fix-forward | 恢复compromised/revoked material |
| `RB-CH-07` | test/check/builder/run失败 | 保留failed attempt；new attempt/run复验 | 覆盖failed raw、cross-run拼接、手写pass |
| `RB-CH-08` | selected产品不满足semantic matrix | reject/unselect；保留P0 product-neutral baseline | cache/sleep/retry/generic error补偿 |
| `RB-CH-09` | Spike代码/配置不采纳 | 从planned boundary排除并保留safe decision | 当canonical evidence或偷偷merge |

必须保存用户改动ownership、structured blocker、failed/flaky/invalid raw、superseded baseline/run、rejected candidate safe ref、Spike decision和已提交历史。真实retention policy未建立前，不得通过删除历史简化当前结论。

### 10.4 Change authority与复验级别

| 变化 | 第一authority | 必须同步 | 最低复验 |
|---|---|---|---|
| requirement/scope/AC/VF | formal `00` | `01~07`、cases/gates/ledgers | design restart + R2；release时R4 |
| context/owner/dependency | formal `01` | `02~07`、dependency checks | architecture review + R2/R4 |
| object responsibility | formal `02` | `03~07` | HLD/DDD和受影响tests |
| public type/field/Port/flow/state/TX/error | formal `03` | `04~07`、Rustdoc、affected skeletons | affected families + R2 |
| config/profile/source/binding | formal `04` | `05~07`、fixtures | config proof + R2/R4 |
| TC/DS/EV/suite/check/builder/path | formal `05` | `06/07`、boundary gates | manifest/provenance R2；evidence变化R4 |
| AC/VF/VETO/risk/signoff | formal `06` | `07`、handoff/review schema | acceptance design review + R4 |
| phase/order/boundary/gate/completion | formal `07` Steps 5~12 | flow、project/implementation ledgers、affected skeletons | plan traceability review |
| local implementation bug | current implementation boundary | tests/ledger/defect | R0/R1；影响不明则R2 |
| selected private product | selected manifest/config | selected tests/risk/ops | Spike + R3；release-required时R4 |

raw/report/evidence/status/path语义变化必须从raw重建并执行R2+R4；source/config在run开始后漂移时，旧run只保留历史，禁止cross-run stitching。

### 10.5 Recovery workflow

```text
pause trigger
  -> freeze current boundary and protect user changes
  -> classify prerequisite / design / gate / selected / VETO
  -> preserve blocker, diff, raw, report and baseline references
  -> set blocked + wait_design|fix_gate_failure|handoff
  -> fix implementation/tooling or write back owning authority
  -> freeze new design/source/config/impact baseline
  -> repeat Design/Scope/Worktree closure review
  -> execute required R0/R1/R2/R3/R4 with a new attempt/run
  -> verify failed history and provenance remain complete
  -> pass Commit Gate and Handoff Gate before advancing
```

恢复记录至少包含trigger、boundary、old/new baseline、protected user files、failed history、fix/change refs、regression selection、actual commands/results和唯一next action。设计期不预填这些执行事实。

### 11.3 Commit Gate

提交前必须同时满足：

1. target repo、branch/worktree、git identity和design baseline已真实记录。
2. project ledger仅有一个current boundary，当前skeleton已激活；future skeleton仍为`planned / wait_until_current`。
3. required reads完成，Design Gate和§6.2闭环复核无blocker。
4. staged diff只包含当前allowed scope；用户与其他agent改动未stage或回退。
5. format、build、targeted tests、mandatory checks和必要evidence gates有真实结果。
6. 所有public declaration、struct field、enum variant/payload field、trait、method和callable英文`///`完整；缺任一项即阻止提交。
7. `git diff --check`与`git diff --cached --check`通过，message file格式符合§11.1~11.2。
8. failed/invalid attempt保留，未跑或`not_applicable`项有精确理由；不得只依据用户口头确认提交。

每个boundary独立完成Design、Scope、Worktree、Build、Test、Evidence、Commit和Handoff Gate。任何必要Gate为`pending`或`blocked`时，`next_allowed_action`只能是读取、等待设计、修复失败或handoff，不能是`commit`。

### 11.4 评审责任

| 评审面 | 主要责任 | Blocking问题 |
|---|---|---|
| contracts/domain/state | contracts/domain owner + design closure reviewer | source、field、variant、state、Rustdoc或invariant缺口 |
| application/UoW/replay | application/transaction reviewer | Port/repository parity、same-UoW、Unknown、duplicate replay错误 |
| adapter/config/security | adapter/config/security reviewer | body/secret泄漏、silent fallback、partial graph、provider/runtime责任泄漏 |
| query/exposure/reference | query/exposure/reference owner | no-write、visibility、freshness、typed-ref或SDK boundary错误 |
| inbound/outbound/jobs | entry/collaboration/jobs owner | header-first、post-commit、capture、terminalization或truth repair错误 |
| reports/evidence | test tooling/evidence reviewer | static/cross-run/orphan、digest、redaction、dependency或pairing错误 |
| release/acceptance handoff | release owner + authorized acceptance/review roles | default verdict、risk auto-acceptance、fake signature或missing VETO direction |

Reviewer必须检查设计closure、实现scope、negative/replay/no-write branches、responsibility和evidence provenance，不能只做style review。评审意见若要求新增schema、Port、config、test identity、acceptance语义或boundary拆并，先触发§10变更控制。

### 11.5 Handoff与交付

每个boundary完成后，boundary ledger至少记录真实commit hash/message、实际执行命令、未运行检查及原因、artifact/report paths、open blockers、用户改动保护和唯一next boundary。`commit-11-a`只能交付raw-derived report/evidence candidate index，`commit-11-b`只能交付release aggregation与pending-review acceptance/review shell；两者都不能生成final verdict、risk acceptance或signoff。

Handoff Gate固定检查：

| 检查 | 通过条件 |
|---|---|
| boundary identity | staged/committed内容只属于当前boundary |
| implementation facts | hash、message、commands和paths真实存在 |
| gates | required gate有真实status/evidence，failed历史未覆盖 |
| Rustdoc | public声明与所有结构体字段/variant/payload/callable扫描完整 |
| reports | 只引用same-run canonical paths，无`latest`或alias |
| blockers | 未关闭项有owner/source/next action，blocking项阻止advance |
| worktree | 用户或其他agent改动未触碰 |
| next state | project ledger与下一skeleton同步，只有一个current |

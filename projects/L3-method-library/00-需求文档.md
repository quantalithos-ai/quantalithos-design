## 1. 与 `product/` 的关系声明

L3-method-library 是**运行时能力型 / 方法资产型**需求仓。它不是终端用户产品,也不是纯基础设施,而是把平台的方法论、技能 / 胜任力、模板、角色、任务、制品定义抽象成可发布、可版本化、可同步、可分发的正式方法资产。

## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 不只是代码系统,还是**方法系统**。它需要管理:
- 技能 / 胜任力定义(Qualification)
- 角色定义(RoleDefinition)
- 任务定义(TaskDefinition)
- 制品定义(WorkProductDefinition)
- 过程模板(ProcessTemplateDef)
- 视图策略(ViewProfile)
- AI Policy(AIPolicyDef)
- 方法资产打包 / 组装(MethodPlugin / MethodConfiguration)

没有 method-library:
- identity 不知道 Qualification / RoleDefinition 的权威源
- identity 的 QualificationProfile 缺少可追溯的定义来源
- capability-hub 的 QualificationBinding 缺少统一语义锚点
- identity 不知道 RoleDefinition 的权威源
- process 不知道 Template 内容从哪来
- governance 不知道 AIPolicy 的源头
- UI 不知道 ViewProfile 从哪消费

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `domain/method-library/README.md` 1543 行 | 设计极完整,仓级需求层尚未显式化 |
| 7 类 MethodContent | 已定义 6 类,Qualification 需按 ADR draft 0014 补入 | 样板代码和验收口径未落地 |
| 8 种 Template 家族 | 已定 | 真正的种子数据和发布链未实现 |
| ViewProfile | ADR-0009 已定 | 下游 UI 还未消费 |
| Rigidity / Nested | ADR-0010 / 0011 Proposed | 需要在 Template 层预留字段 |

### 2.3 为什么要做(量化依据)

- 所有 L1 / L2 / L5 / L6 仓都直接或间接依赖方法资产
- method-library 是段 3 之后 N3 节点的核心仓之一
- 没有它,平台没有"怎么做"的统一源,所有方法论都散落在文档里,不能执行

### 2.4 业务问题 vs 技术问题

- **业务问题**:如何把方法论和治理要求变成可管理、可发布、可复用的资产
- **技术问题**:MethodContent 元模型、Qualification / Role / Task / WorkProduct / Template / View / Policy 的定义边界、版本化、fingerprint、Plugin / Configuration、下游同步、ViewProfile / AIPolicy 的特殊性

## 3. 目标与非目标

### 3.1 目标(可验证)

| ID | 目标 | 验收指标 | 验收方式 |
|---|---|---|---|
| G-1 | MethodContent 7 类可 CRUD + 发布 | 7/7 | 集成测试 |
| G-2 | 8 种 Template 家族入种子数据 | 8/8 | seed 验证 |
| G-3 | 9 种 RoleDefinition 种子 | 9/9 | seed 验证 |
| G-4 | ViewProfile 可供下游消费 | ResolveViewProfile 成功 | 集成测试 |
| G-5 | ProcessTemplate 发布后 process 可同步索引 | process.template.published 事件流转成功 | E2E |
| G-6 | role_definition.published 后 identity 刷索引成功 | role.catalog_updated 事件发出 | E2E |
| G-7 | fingerprint drift 检测可用 | 100% 触发 | 回归测试 |
| G-8 | Qualification 定义真相可发布、可版本化、可同步 | Qualification draft / publish / retire、fingerprint 生成、identity / capability-hub 可消费 snapshot | 集成测试 + E2E |

### 3.1.1 P0 最小闭环

`L3-method-library` 的 P0 不是完成全部方法资产生态,而是先跑通“定义资产可发布、可追溯、可被下游建立本地索引”的最小闭环:

```text
方法作者
  -> Draft MethodContent
  -> Publish Gate Approved
  -> Publish MethodContent
  -> Generate Fingerprint
  -> Emit Definition Event / Snapshot
  -> Downstream Sync
```

P0 覆盖的 MethodContent:

```text
Qualification
RoleDefinition
TaskDefinition
WorkProductDefinition
ProcessTemplateDef
ViewProfile
AIPolicyDef
```

P0 下游同步口径:

```text
Qualification       -> identity / capability-hub
RoleDefinition      -> identity
TaskDefinition      -> process
WorkProductDefinition -> artifact
ProcessTemplateDef  -> process
ViewProfile         -> UI / console
AIPolicyDef         -> governance
```

其中 `TaskDefinition` 的 P0 下游是 `process`:process 必须能够同步并在 `ProcessTemplateDef` / Activity / TaskUse 中引用。`work` 是否直接消费 `TaskDefinition` 作为 WorkItem 模板来源,先标记为 P1 / 待确认消费方,待 `L1-work` 需求校准时再决定。

P1 后置:

```text
MethodPlugin
MethodConfiguration
Plugin dependency DAG
Variability application
Marketplace package distribution
```

这些能力属于方法资产组装、组织级生效和生态分发,重要但不阻塞 P0 的定义发布与下游同步闭环。

### 3.2 非目标(明确不做)

| ID | 非目标 | 原因 | 归属 |
|---|---|---|---|
| NG-1 | **流程编排执行** | 只定义,不执行 | process |
| NG-2 | **角色生命周期状态机** | 只定义角色内容,不管成员状态 | identity |
| NG-3 | **Policy enforce 执行** | 只存 AIPolicyDef / MethodConfiguration,运行时规则在 governance/runtime |
| NG-4 | **Marketplace 交易逻辑** | 只提供资产源,不做购买 / 计费 | marketplace |
| NG-5 | **UI 渲染** | 只提供 ViewProfile,不做前端实现 | L5/L6 |
| NG-6 | **成员 QualificationProfile 管理** | 只定义 Qualification,不记录某个成员实际具备哪些 Qualification | identity |
| NG-7 | **QualificationBinding / tool-provider 接入绑定** | 不保存 Qualification 到 tool / provider / MCP / A2A 的运行接入关系 | capability-hub |
| NG-8 | **CapabilityAccessDecision / 能力访问裁决** | 不判断当前上下文是否允许访问某个工具、provider 或外部能力入口 | capability-hub / governance |

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 方法作者维护方法定义资产草稿
2. 方法审核者 / 批准者发布方法定义资产,生成 fingerprint 并记录发布历史
3. identity 同步身份相关定义(RoleDefinition / Qualification)
4. process 同步流程与任务定义(ProcessTemplateDef / TaskDefinition)
5. capability-hub 同步能力接入语义锚点(Qualification)
6. artifact 同步制品定义(WorkProductDefinition)
7. governance 同步 AI Policy 定义(AIPolicyDef)
8. UI / console 解析视图策略(ViewProfile)
9. Auditor 查询方法资产追溯链
10. Owner / Admin 激活组织方法集(P1)
11. Marketplace 上架方法资产包(P1)

### 6.2 业务规则表

#### 6.2.1 生命周期与发布规则

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-LC-001 | MethodContent 被创建 | 初始状态必须是 `draft`,不得直接进入 `published` |
| BR-LC-002 | `draft` 内容提交审核 | 状态进入 `in_review`,并记录提交人、提交时间和审核入口 |
| BR-LC-003 | `in_review` 通过发布门禁 | 才允许进入 `published` |
| BR-LC-004 | `published` 内容需要修改核心语义字段 | 不允许原地修改,必须创建新版本并通过 `supersede` 关联旧版本 |
| BR-LC-005 | `deprecated` 内容被新流程引用 | 允许保留历史引用,但新建引用应优先使用替代版本 |
| BR-LC-006 | `retired` 内容被新流程引用 | 拒绝新建引用,仅保留历史追溯 |

#### 6.2.2 指纹、审计与可追溯规则

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-PUB-001 | MethodContent 发布 | 必须生成 version、fingerprint、published_at、published_by 和 audit record |
| BR-PUB-002 | fingerprint 变化 | 必须发布 `method_library.content.fingerprint_changed` 或对应子类事件 |
| BR-PUB-003 | 发布、废弃、退役、supersede | 必须记录审计链,可追溯到操作者、原因、前后版本和 gate 结果 |
| BR-PUB-004 | 下游请求 snapshot | 返回内容必须包含 content_id、kind、version、fingerprint 和 lifecycle |

#### 6.2.3 Qualification 边界规则

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-QUAL-001 | 平台需要定义技能 / 胜任力 | 只能在 method-library 中创建和发布 `Qualification` |
| BR-QUAL-002 | identity 需要记录成员能力画像 | identity 只能维护 `QualificationProfile`,并引用已发布的 `Qualification` |
| BR-QUAL-003 | capability-hub 需要绑定工具 / provider / MCP / A2A | capability-hub 只能维护 `QualificationBinding`,并引用已发布的 `Qualification` |
| BR-QUAL-004 | identity 或 capability-hub 发现缺少 Qualification | 不得反向自动创建 Qualification 定义,只能提出新增定义请求或等待 method-library 发布 |
| BR-QUAL-005 | Qualification 被退役 | 新的 QualificationProfile / QualificationBinding 不得继续引用该退役版本 |

#### 6.2.4 方法资产关系规则

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-REL-001 | RoleDefinition 声明 `provided_qualifications` | 每个 qualification_id 必须引用已发布的 Qualification |
| BR-REL-002 | TaskDefinition 声明 `required_qualifications` | 每个 qualification_id 必须引用已发布的 Qualification |
| BR-REL-003 | TaskDefinition 声明输入 / 输出制品 | 每个 work_product_definition_id 必须引用已发布的 WorkProductDefinition |
| BR-REL-004 | ProcessTemplateDef 引用 TaskDefinition | 只能引用已发布或明确允许预览的 TaskDefinition |
| BR-REL-005 | AIPolicyDef 被 governance 消费 | method-library 只提供定义源,不执行 policy enforce |
| BR-REL-006 | WorkProductDefinition 被 artifact 消费 | method-library 只提供制品定义,不保存具体 artifact 正文 |

#### 6.2.5 下游同步与反向改写规则

| BR-SYNC-005 | AIPolicyDef 发布 | governance 必须能同步 policy source index |
| BR-SYNC-006 | ViewProfile 发布 | UI / console 必须能解析 active ViewProfile |
| BR-SYNC-007 | 任一下游同步定义 | 下游不得反向改写 method-library 的定义正文 |
| BR-SYNC-008 | 事件重复投递或 snapshot 重放 | 下游同步必须按 content_id + version + fingerprint 幂等处理 |

#### 6.2.6 ViewProfile 规则

| BR-VIEW-003 | ViewProfile 发生版本变化 | ResolveViewProfile 必须返回 active 版本及其 fingerprint |

#### 6.2.7 P1 Plugin / Configuration 规则

## 7. 非功能需求

`L3-method-library` 的非功能重点不是单纯追求低延迟,而是保证 definition truth 可靠、可审计、可重放、可同步、可演进。

### 7.1 性能要求

| 指标 | 目标值 | 测量方式 | 说明 |
|---|---|---|---|
| GetMethodContent P95 | < 50ms(缓存命中) / < 200ms(PG) | benchmark | 定义读取是高频下游依赖 |
| ListMethodContents P95 | < 300ms | benchmark | 支持 Console / Auditor 查询 |
| ResolveViewProfile P95 | < 30ms | benchmark | UI / console 渲染前置路径 |
| ExportDefinitionSnapshot P95 | < 300ms | benchmark | 下游同步和对账路径 |
| PublishMethodContent P95 | < 500ms | benchmark | 发布包含校验、fingerprint、审计与 outbox 写入,不以极低延迟为首要目标 |

### 7.2 可用性与降级要求

| 场景 | 要求 | 降级策略 |
|---|---|---|
| 读接口 | 优先保证可用 | 可使用只读副本或缓存,但必须返回 version / fingerprint |
| 写接口 | 必须保证定义真相一致 | 主库不可用时阻断写入 |
| Event Bus 不可用 | 不得丢失定义变化事件 | 写入 outbox / backlog,待恢复后重放 |
| object storage 不可用 | 不阻断元数据查询 | guidance / example / package blob 正文稍后恢复 |
| 下游系统不可用 | 不阻断本仓发布 | 通过事件重放或 snapshot query 恢复下游索引 |

### 7.3 一致性、幂等与重放要求

| 要求 | 说明 |
|---|---|
| 发布原子性 | PublishMethodContent 成功后,content state、version、fingerprint、audit record、outbox event 必须一致 |
| 事件可重放 | published / retired / fingerprint_changed 事件必须支持重放 |
| Snapshot 稳定性 | 同一 content_id + version 导出的 snapshot 在定义未 supersede 前应稳定 |
| 下游幂等 | 下游可按 content_id + version + fingerprint 幂等处理事件或 snapshot |
| Seed 幂等 | SeedInitialMethodAssets 重复执行不得制造重复定义 |
| Replay 幂等 | ReplayDefinitionEvents 不得改变定义正文,只重放已存在事件或重新导出 snapshot |
| Fingerprint 可复算 | RecalculateFingerprint 必须能复算并与已发布 fingerprint 对比 |

### 7.4 审计与可追溯要求

以下操作必须记录审计链:

| 操作 | 必须记录 |
|---|---|
| Create / Update Draft | actor_ref、时间、前后版本摘要 |
| Submit For Review | actor_ref、时间、提交版本 |
| Publish | actor_ref、approved_gate_ref、version、fingerprint、发布时间 |
| Deprecate / Retire | actor_ref、原因、影响版本 |
| Supersede | old_content_id、new_content_id、原因、操作者 |
| Fingerprint Changed | old_fingerprint、new_fingerprint、触发原因 |
| PublishMethodPlugin(P1) | actor_ref、approved_gate_ref、package metadata |
| ActivateMethodConfiguration(P1) | actor_ref、configuration_id、effective_content_set |

审计查询必须能回答:

```text
谁改了定义
什么时候改
为什么改
从哪个版本变到哪个版本
是否经过 gate
fingerprint 前后是什么
哪些下游需要同步
```

### 7.5 边界与安全要求

`method-library` 不负责统一身份认证,但接口必须携带可审计的 actor_ref 和必要的 gate_ref。

边界红线必须可验证:

| 红线 | 验证要求 |
|---|---|
| 不保存 QualificationProfile | 数据模型、接口和测试中不得出现成员能力画像写入路径 |
| 不保存 QualificationBinding | capability-hub 的 tool / provider / MCP / A2A 绑定不得写入本仓 |
| 不保存 ProcessInstance | process runtime state 不得写入本仓 |
| 不保存 WorkItem / Backlog / Iteration | work 事实层不得写入本仓 |
| 不保存具体 Artifact 正文 | 本仓只保存 WorkProductDefinition,不保存实际产物 |
| 不执行 Policy Enforce | 本仓只保存 AIPolicyDef,不保存 enforce result |

### 7.6 兼容性与演进要求

| 对象 | 要求 |
|---|---|
| definition schema | 必须具备 schema version,支持后续字段演进 |
| snapshot schema | 必须具备 snapshot version,下游可识别兼容范围 |
| event schema | 必须具备 event version,支持消费者滚动升级 |
| published content | 已发布版本不得被破坏性修改 |
| historical snapshot | 历史版本必须可查询和导出 |
| P1 Plugin / Configuration | 后续引入时不得改变 P0 MethodContent 的定义真相边界 |

### 7.7 可观测性要求

| 指标 | 用途 |
|---|---|
| publish_success_total / publish_failure_total | 观察发布稳定性 |
| fingerprint_changed_total | 观察定义变化和 drift 风险 |
| outbox_backlog_size | 观察事件积压 |
| event_replay_total | 观察重放与恢复情况 |
| downstream_sync_lag_seconds | 观察下游同步延迟 |
| snapshot_export_total | 观察下游拉取和对账频率 |
| definition_drift_detected_total | 观察 source drift |
| resolve_view_profile_deny_total | 观察 ViewProfile 未匹配或拒绝情况 |
| seed_success_total / seed_failure_total | 观察初始化稳定性 |

日志必须至少覆盖:

```text
Command 接收与完成
Publish gate 引用
fingerprint 生成与变化
outbox 写入与重放
snapshot 导出
边界违规拒绝
```

### 7.8 合规要求

| 合规项 | 要求 | 对齐标准 / 原则 |
|---|---|---|
| Definition vs Use 分离 | 本仓只定义不执行 | SPEM 2.0 |
| Qualification 定义归属 | Qualification 定义真相在 method-library | SPEM Qualification |

## 9. 数据需求

### 9.1 数据归属原则

`L3-method-library` 的数据边界按以下原则划分:

| 类型 | 含义 | 本仓处理方式 |
|---|---|---|
| 定义真相 | 方法资产的正文、版本、fingerprint、生命周期和发布历史 | 本仓拥有并持久化 |
| 外部引用 | 指向 identity / governance / object storage / standards 的引用 | 本仓只保存引用 ID 或 URI,不保存外部正文 |
| 下游 snapshot | 为 identity / process / capability-hub / artifact / governance / UI 提供的定义快照 | 本仓生成并输出,不拥有下游本地索引 |
| 禁止保存数据 | 成员画像、工具绑定、流程实例、任务事实、具体产物正文、交易数据等 | 本仓不得保存为业务真相 |

核心口径:

```text
method-library 定义“方法资产是什么”。
下游系统记录“谁使用它、如何执行它、如何绑定它、实际产生了什么”。
```

### 9.2 本仓拥有的数据真相

| 实体 | 聚合 / 类型 | 优先级 | 生命周期 | 归属说明 |
|---|---|---|---|---|
| MethodContent | 抽象聚合 | P0 | draft → in_review → published / deprecated / retired | 7 类方法定义资产的统一抽象 |
| Qualification | 子类聚合 | P0 | 同 MethodContent | 技能 / 胜任力定义真相 |
| RoleDefinition | 子类聚合 | P0 | 同 MethodContent | 角色定义真相 |
| TaskDefinition | 子类聚合 | P0 | 同 MethodContent | 任务定义真相 |
| WorkProductDefinition | 子类聚合 | P0 | 同 MethodContent | 制品定义真相 |
| ProcessTemplateDef | 子类聚合 | P0 | 同 MethodContent | 流程模板定义真相 |
| ViewProfile | 子类聚合 | P0 | 同 MethodContent | 视图策略定义真相 |
| AIPolicyDef | 子类聚合 | P0 | 同 MethodContent | AI Policy 定义真相 |
| MethodPlugin | 聚合根 | P1 | draft → published → deprecated / retired | 方法资产包定义真相 |
| MethodConfiguration | 聚合根 | P1 | draft → active → superseded / retired | 组织方法集组装与激活真相 |

### 9.3 本仓只保存外部引用的数据

| 引用字段 / 类型 | 指向系统 | 本仓保存内容 | 本仓不保存内容 |
|---|---|---|---|
| created_by / updated_by / published_by | identity | global_member_id 或 project_member_id | 成员档案、成员生命周期、QualificationProfile |
| approved_gate_ref | governance | gate_id / approval_result_ref | gate 执行过程、policy enforce 结果 |
| guidance_blob_ref / example_blob_ref | object storage | blob URI、hash、content type | 大段说明文档、示例包正文 |
| source_standard_ref | standards / references | 标准编号、章节、版本 | 标准全文 |
| related_artifact_definition_ref | artifact | WorkProductDefinition 对 artifact 的定义引用 | 具体 artifact 实例正文 |

### 9.4 本仓输出给下游的数据形态

`method-library` 对下游输出的是 definition event 或 definition snapshot,不是下游业务对象。

| 下游 | 消费内容 | 输出形态 | 下游拥有的数据 |
|---|---|---|---|
| identity | Qualification / RoleDefinition | QualificationSnapshot / RoleDefinitionSnapshot / published event | QualificationProfile、RoleCatalogEntry、QualificationCatalogEntry |
| process | ProcessTemplateDef / TaskDefinition | ProcessTemplateSnapshot / TaskDefinitionSnapshot / published event | ProcessProfile、ProcessInstance、Activity runtime index |
| capability-hub | Qualification | QualificationSnapshot / published event | QualificationBinding、CapabilityAccessDecision |
| artifact | WorkProductDefinition | WorkProductDefinitionSnapshot / published event | Artifact 实例、证据、验收记录 |
| governance | AIPolicyDef | AIPolicyDefinitionSnapshot / published event | policy enforce runtime、gate result |
| UI / console | ViewProfile | ResolveViewProfile response / ViewProfileSnapshot | 前端视图状态、用户会话状态 |
| marketplace | MethodPlugin(P1) | package metadata / plugin published event | listing、交易、安装记录 |

snapshot 必须至少包含:

```text
content_id
kind
version
fingerprint
lifecycle
published_at
published_by
```

### 9.5 本仓禁止保存的数据

| 数据 | 禁止原因 | 正确归属 |
|---|---|---|
| QualificationProfile | 这是某个成员实际具备哪些 Qualification | identity |
| ProjectMember / GlobalMember 生命周期 | 成员身份与生命周期事实不属于方法定义 | identity |
| QualificationBinding | 这是 Qualification 到 tool / provider / MCP / A2A 的运行接入绑定 | capability-hub |
| CapabilityAccessDecision | 这是运行时能力访问裁决 | capability-hub / governance |
| ProcessInstance / Activity runtime state | 这是流程运行实例 | process |
| WorkItem / Backlog / Iteration | 这是项目任务事实 | work |
| 具体 Artifact 正文和证据文件 | 本仓只定义 WorkProductDefinition,不保存实际产物 | artifact |
| Policy enforce 结果 | 本仓只定义 AIPolicyDef,不执行治理 | governance |
| Marketplace 交易 / 安装记录 | 本仓只提供资产源或 package metadata | marketplace |

```
MethodContent(abstract)
```

### 9.7 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|

## 10. 接口与依赖

### 10.1 接口设计原则

`L3-method-library` 对外接口只围绕方法定义资产展开:

```text
Command 负责改变定义真相
Query 负责读取定义真相或导出 snapshot
Event 负责通知下游定义变化
Operations Job 负责 seed、重建、重放和一致性维护
```

接口边界:

```text
method-library 不通过接口创建 QualificationProfile
method-library 不通过接口创建 QualificationBinding
method-library 不通过接口创建 ProcessInstance
method-library 不通过接口创建 WorkItem
method-library 不通过接口保存具体 Artifact 正文
```

### 10.2 Command 需求

P0 Command 聚焦 7 类 MethodContent 的定义生命周期。

| Command | 优先级 | 调用方 | 作用 | 关键输入 | 关键结果 |
|---|---|---|---|---|---|
| CreateMethodContentDraft | P0 | 方法作者 / Admin | 创建方法资产草稿 | kind、draft_body、actor_ref | content.state=draft |
| UpdateMethodContentDraft | P0 | 方法作者 / Admin | 更新草稿内容 | content_id、expected_version、draft_body、actor_ref | draft version 更新 |
| SubmitMethodContentForReview | P0 | 方法作者 / Admin | 提交发布审核 | content_id、expected_version、actor_ref | content.state=in_review |
| PublishMethodContent | P0 | 方法审核者 / 批准者 / Admin | 发布方法资产 | content_id、expected_version、approved_gate_ref、actor_ref | state=published、生成 fingerprint、发 published event |
| DeprecateMethodContent | P0 | 方法审核者 / 批准者 / Admin | 废弃方法资产 | content_id、reason、actor_ref | state=deprecated、记录审计 |
| RetireMethodContent | P0 | 方法审核者 / 批准者 / Admin | 退役方法资产 | content_id、reason、actor_ref | state=retired、拒绝新建引用 |
| SupersedeMethodContent | P0 | 方法审核者 / 批准者 / Admin | 用新版本替代旧版本 | old_content_id、new_content_id、reason、actor_ref | 建立 supersede 链 |
| SeedInitialMethodAssets | P0 | 系统 / 运维 | 初始化基础方法资产 | seed_version、actor_ref | Qualification、Role、Template、ViewProfile、AIPolicyDef 基线可用 |
| PublishMethodPlugin | P1 | 方法审核者 / Admin | 发布方法资产包 | plugin_id、approved_gate_ref、actor_ref | plugin.state=published |
| ActivateMethodConfiguration | P1 | Owner / Admin | 激活组织方法集 | configuration_id、actor_ref | configuration.state=active |

Command 的共同要求:

```text
必须携带 actor_ref
必须校验 expected_version 或等价并发控制字段
必须记录 audit record
发布类 Command 必须校验 approved_gate_ref
不得让下游系统绕过 Command 直接改写定义正文
```

事件规则:

```text
通用 content 事件用于统一订阅
子类事件用于下游精确订阅

事件载荷应携带 snapshot_ref,避免在事件中塞入大段定义正文
```

## 11. 验收标准

### 11.1 P0 主链路验收

P0 必须跑通以下定义发布闭环:

```text
CreateMethodContentDraft
  -> SubmitMethodContentForReview
  -> PublishMethodContent
  -> Generate Fingerprint
  -> Write Audit Record
  -> Write Outbox Event
  -> Emit Published Event
  -> Export Definition Snapshot
  -> Downstream Sync
```

该闭环必须覆盖 7 类 P0 MethodContent:

```text
Qualification
RoleDefinition
TaskDefinition
WorkProductDefinition
ProcessTemplateDef
ViewProfile
AIPolicyDef
```

### 11.2 功能验收标准

| 功能 ID | 验收场景 | Given-When-Then | 执行方式 |
|---|---|---|---|
| F-001 | 方法资产内容管理 | **Given** 7 类 MethodContent 草稿字段完整 **When** Create / Update draft **Then** state=draft,version 更新,audit record 存在 | 单元 + 集成 |
| F-002 | 方法资产发布治理 | **Given** draft 已通过 gate **When** PublishMethodContent **Then** state=published,version / fingerprint 生成,published event 写入 outbox | 集成 |
| F-002 | 发布 Gate 前置 | **Given** 无 approved_gate_ref **When** PublishMethodContent **Then** 发布被拒绝,内容状态不变 | 单元 + 集成 |
| F-003 | 方法资产关系建模与校验 | **Given** RoleDefinition / TaskDefinition 引用 Qualification **When** 发布 **Then** 引用的 Qualification 必须已 published,否则拒绝发布 | 单元 + 集成 |
| F-003 | WorkProduct 关系校验 | **Given** TaskDefinition 声明输入 / 输出制品 **When** 发布 **Then** 引用的 WorkProductDefinition 必须已 published | 单元 + 集成 |
| F-004 | 版本与指纹管理 | **Given** published 内容需要修改核心语义字段 **When** 保存变更 **Then** 不允许原地修改,必须通过新版本 + supersede | 单元 + 集成 |
| F-004 | fingerprint changed | **Given** 新版本 fingerprint 与旧版本不同 **When** 发布 **Then** 记录 old / new fingerprint,并发布 fingerprint_changed 事件 | 集成 |
| F-005 | 下游定义同步 | **Given** 任一 P0 MethodContent 发布 **When** 下游消费事件或 ExportDefinitionSnapshot **Then** 可获取 content_id、kind、version、fingerprint、lifecycle | 集成 |
| F-006 | 查询与审计追溯 | **Given** 内容经历 draft、publish、supersede 或 retire **When** GetDefinitionTrace **Then** 返回版本历史、发布历史、fingerprint 和 audit records | 集成 |
| F-007 | ViewProfile 解析 | **Given** role + object_kind + scope **When** ResolveViewProfile **Then** 返回 active ViewProfile + fingerprint;未匹配时生产环境默认 deny | 单元 + 集成 |
| F-008 | 初始方法基线装载 | **Given** 空库 **When** SeedInitialMethodAssets **Then** 基础 Qualification、9 Role、8 Template 家族、基础 ViewProfile / AIPolicyDef 可用 | 集成 |
| F-009 | 方法资产打包管理(P1) | **Given** MethodPlugin 依赖无环 **When** PublishMethodPlugin **Then** plugin.state=published,package metadata 可被 marketplace 消费 | P1 集成 |
| F-010 | 组织方法集组装与激活(P1) | **Given** MethodConfiguration 配置有效 **When** ActivateMethodConfiguration **Then** configuration.state=active,effective_content_set 可查询 | P1 集成 |
| F-011 | 下游主动对账增强(P1) | **Given** 下游回报 fingerprint **When** CompareFingerprint / DetectDefinitionDrift **Then** 返回 match 或 drift result | P1 集成 |

### 11.3 跨仓同步验收

| 下游 | 验收内容 | 成功标准 |
|---|---|---|
| identity | 同步 Qualification / RoleDefinition | 可更新 QualificationCatalogEntry / RoleCatalogEntry,且不反向改写定义 |
| process | 同步 ProcessTemplateDef / TaskDefinition | 可建立流程与任务定义索引,且不创建 ProcessInstance |
| capability-hub | 同步 Qualification | QualificationBinding 可引用 qualification_id,但不复制 Qualification 正文 |
| artifact | 同步 WorkProductDefinition | 可对齐 artifact kind、acceptance template 或 evidence 类型 |
| governance | 同步 AIPolicyDef | 可更新 policy source index,但 enforce result 不写回本仓 |
| UI / console | 解析 ViewProfile | 可按 role + object_kind + scope 获取 active ViewProfile |
| marketplace(P1) | 消费 MethodPlugin metadata | 可创建 listing,但不拥有 MethodContent 正文真相 |

### 11.4 数据边界验收

以下边界红线必须通过自动化测试或架构检查验证:

| 红线 | 验收标准 |
|---|---|
| 不保存 QualificationProfile | 本仓数据模型和写接口不存在 QualificationProfile 写入路径 |
| 不保存 QualificationBinding | 本仓数据模型和写接口不存在 tool / provider / MCP / A2A 绑定写入路径 |
| 不保存 ProcessInstance | 本仓接口不能创建或更新流程运行实例 |
| 不保存 WorkItem / Backlog / Iteration | 本仓接口不能创建或更新项目任务事实 |
| 不保存具体 Artifact 正文 | 本仓只保存 WorkProductDefinition,不得保存 artifact 实例正文或证据文件 |
| 不保存 Policy Enforce 结果 | 本仓只保存 AIPolicyDef,不得保存 governance runtime 裁决结果 |

### 11.5 非功能验收标准

| 维度 | 验收项 | 阈值 / 标准 |
|---|---|---|
| 性能 | GetMethodContent P95 | < 50ms(cache) / < 200ms(PG) |
| 性能 | ListMethodContents P95 | < 300ms |
| 性能 | ResolveViewProfile P95 | < 30ms |
| 性能 | ExportDefinitionSnapshot P95 | < 300ms |
| 性能 | PublishMethodContent P95 | < 500ms |
| 一致性 | 发布原子性 | state、version、fingerprint、audit record、outbox event 必须同时成立 |
| 幂等 | SeedInitialMethodAssets | 重复执行不得创建重复定义 |
| 幂等 | ReplayDefinitionEvents | 重放不得改变定义正文,下游可幂等消费 |
| 追溯 | GetDefinitionTrace | 可查询操作者、时间、原因、gate、版本、fingerprint |
| 兼容 | historical snapshot | 历史版本 snapshot 可导出 |
| 可观测 | outbox_backlog_size 等指标 | 指标存在并可被监控采集 |

### 11.6 P1 验收口径

`MethodPlugin`、`MethodConfiguration`、主动 drift 检测和 marketplace 分发属于 P1。

```text
P1 未完成不阻塞 P0 验收。
如果实现 P1,必须满足对应业务规则、审计要求和边界红线。
P1 能力不得改变 P0 MethodContent 的定义真相边界。
```

### 11.7 一票否决项

出现以下任一情况,本仓 P0 验收不通过:

| 否决项 | 原因 |
|---|---|
| Qualification 不能发布或不能导出 snapshot | 破坏身份与能力语义锚点 |
| Qualification 发布后 identity / capability-hub 不能同步 | P0 下游链路不成立 |
| published 内容可被原地修改 | 破坏版本、审计和追溯 |
| 发布成功但没有 fingerprint、audit record 或 outbox event | 破坏定义真相一致性 |
| identity 可反向创建或改写 Qualification | 破坏 method-library 定义真相 |
| capability-hub 可反向创建或改写 Qualification | 破坏 Qualification / Binding 边界 |
| 本仓保存 QualificationProfile / QualificationBinding / ProcessInstance / WorkItem | 跨仓数据归属错误 |
| 事件不可重放 | 下游恢复与一致性无法保证 |
| SeedInitialMethodAssets 不幂等 | 初始化不可重复执行 |

## 12. 风险与待确认事项

### 12.1 主要风险

| 风险 ID | 风险类型 | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|---|
| R-001 | 边界风险 | Qualification / QualificationProfile / QualificationBinding 边界被混淆 | 中 | 高 | 在需求、架构、概要、详细和测试中持续保留边界红线;自动化检查本仓不存在画像或绑定写入路径 |
| R-002 | 边界风险 | 下游系统反向创建或改写 Qualification | 中 | 高 | 所有下游只能消费 snapshot / event;新增 Qualification 必须回到 method-library 发布流程 |
| R-003 | 同步风险 | 事件丢失或不可重放导致下游索引不一致 | 中 | 高 | 使用 outbox / backlog;要求事件可重放;下游按 content_id + version + fingerprint 幂等消费 |
| R-004 | 同步风险 | snapshot schema 或 event schema 演进破坏下游兼容 | 中 | 高 | definition / snapshot / event schema 均携带版本;历史 snapshot 可导出 |
| R-005 | 模型风险 | ProcessTemplateDef 与 process runtime 模型无法直接映射 | 中 | 高 | 架构设计阶段单独校准 ProcessTemplateDef / TaskDefinition 到 process 的索引模型 |

| R-007 | 模型风险 | AIPolicyDef 与 governance Policy DSL 分叉 | 中 | 高 | 明确 method-library 保存 policy 定义源;governance 保存 enforce runtime;后续确认 schema/ref 关系 |
| R-008 | 视图风险 | ViewProfile 匹配规则过早复杂化 | 中 | 中 | P0 只保留 role + object_kind + scope 与唯一 active 约束;复杂优先级后置 |
| R-009 | P1 反向污染风险 | MethodPlugin / MethodConfiguration 反向拖慢 P0 MethodContent 发布闭环 | 中 | 中 | P1 不阻塞 P0;P1 不得改变 P0 定义真相边界 |
| R-010 | 标准映射风险 | Qualification 与 SPEM Qualification 的语义对齐不足 | 低 | 中 | 后续正式 ADR 或架构设计中补充标准映射与字段解释 |
| R-011 | 实施节奏风险 | 初始 seed 范围过大导致第一批开发无法收敛 | 中 | 中 | P0 seed 只保留最小基线;扩展方法资产放入后续迭代 |
| R-012 | 审计风险 | 发布成功但 audit / fingerprint / outbox 之一缺失 | 低 | 高 | 发布事务必须同时写 state、version、fingerprint、audit record 和 outbox event |

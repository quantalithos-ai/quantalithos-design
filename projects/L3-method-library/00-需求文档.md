## 1. 与 `product/` 的关系声明

L3-method-library 是**运行时能力型 / 方法资产型**需求仓。它不是终端用户产品,也不是纯基础设施,而是把平台的方法论、模板、角色、制品定义抽象成可发布、可版本化、可分发的资产。

| 章节 | 本文来源 | 对应文档 |
|---|---|---|
| 背景与问题 | 直接细化 `product/六域模型.md` §9.3 方法库横切 | product/六域模型 |
| 目标 | 细化 SPEM / 24748-2 / 29110 / 42001 §5.2 的落地 | domain/method-library README |
| 功能需求 | MethodContent 6 子类 + Plugin + Configuration | domain/method-library README |
| 非功能需求 | 版本化 / drift / 发布 / 分发 | standards + event-catalog |

## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 不只是代码系统,还是**方法系统**。它需要管理:
- 角色定义(RoleDefinition)
- 任务定义(TaskDefinition)
- 制品定义(WorkProductDefinition)
- 过程模板(ProcessTemplateDef)
- 视图策略(ViewProfile)
- AI Policy(AIPolicyDef)
- 方法资产打包 / 组装(MethodPlugin / MethodConfiguration)

没有 method-library:
- identity 不知道 RoleDefinition 的权威源
- process 不知道 Template 内容从哪来
- governance 不知道 AIPolicy 的源头
- UI 不知道 ViewProfile 从哪消费

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 设计文档 | `domain/method-library/README.md` 1543 行 | 设计极完整,仓级需求层尚未显式化 |
| 6 子类 | 已定义 | 样板代码和验收口径未落地 |
| 8 种 Template 家族 | 已定 | 真正的种子数据和发布链未实现 |
| ViewProfile | ADR-0009 已定 | 下游 UI 还未消费 |
| Rigidity / Nested | ADR-0010 / 0011 Proposed | 需要在 Template 层预留字段 |

### 2.3 为什么要做(量化依据)

- 所有 L1 / L2 / L5 / L6 仓都直接或间接依赖方法资产
- method-library 是段 3 之后 N3 节点的核心仓之一
- 没有它,平台没有"怎么做"的统一源,所有方法论都散落在文档里,不能执行

### 2.4 业务问题 vs 技术问题

- **业务问题**:如何把方法论和治理要求变成可管理、可发布、可复用的资产
- **技术问题**:MethodContent 元模型、版本化、fingerprint、Plugin / Configuration、下游同步、ViewProfile / AIPolicy 的特殊性

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 方法作者起草 RoleDefinition / TaskDefinition / Template
2. 审批通过后发布 MethodContent
3. process / identity / governance / UI 订阅对应发布事件
4. 组织激活一套 MethodConfiguration
5. Marketplace 上架 MethodPlugin

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **方法作者**,我想要 **起草一个新的 ProcessTemplateDef**,以便 **定义团队的工作流程** |

### 6.2 业务规则表

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-001 | MethodContent published | 核心字段不可修改,要改发新版本 + supersede |
| BR-002 | fingerprint 变化 | 发 `method_library.content.fingerprint_changed` |
| BR-003 | role_definition.published | identity 必须能同步 Role 索引 |
| BR-004 | process_template.published | process 必须能同步执行索引 |
| BR-005 | view_profile 未匹配 | 生产环境默认 deny |
| BR-006 | 同一 role+object+scope 有两个 active ViewProfile | 拒绝激活 |
| BR-007 | plugin 依赖成环 | 拒绝发布 |
| BR-008 | configuration active 后 | selected_plugins / variability 不可修改 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| fingerprint drift 传播延迟 | 中 | 高 | replay + source_drift 对账 |
| ViewProfile 匹配规则混乱 | 中 | 中 | unique active + 明确优先级 |
| Plugin 依赖环 | 低 | 高 | DAG 校验 |
| Configuration 过度复杂 | 中 | 中 | active 后冻结 + 限制 override |

### 12.2 边缘风险

- ProcessTemplateDef 与 process 索引模型无法 1:1 映射
- AIPolicyDef 与 governance Policy DSL 分叉
- Marketplace 对 Plugin 的商业化诉求反向影响内容模型

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| ProcessTemplateDef 的 XML/BPMN 表示与 process engine 映射 | N3 前 | method-library + process |
| AIPolicyDef 与 governance Policy DSL 的关系 | N3 前 | method-library + governance |
| Plugin / Configuration 的 UI 复杂度 | N3 前 | Console + method-library |

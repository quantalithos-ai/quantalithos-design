| 建立追溯与一致性保护核心契约 | 将 trace material、impact summary、audit trail、evidence lineage、protection decision 和一致性保护边界补成可实现契约。 | 可实现 trace / impact / audit / lineage 对象、处理流、状态、safe failure 和最小验证切口。 |

本章定义 L3-method-library 的模块实现契约主轴。它固定模块 owner、依赖方向、对外暴露、禁止职责和后续章节闭口入口,但不定义对象字段、trait 方法、DTO schema、函数级 flow、状态矩阵、持久化 schema、配置 key 或测试 evidence schema。

### 5.1 模块主轴裁决

本仓详细设计采用七个实现单元作为顶层模块实现契约主轴:

```text
contracts -> domain -> application -> infra -> api / worker / jobs
```

其中:

- `contracts` 是 public surface 和 typed contract owner。
- `domain` 是 method-library truth、policy、state 和 domain error owner。
- `application` 是 use case orchestration、port trait、UoW、idempotency 和 degraded branch owner。
- `infra` 是 repository / adapter / runtime builder / config binding 的实现 owner。
- `api`、`worker`、`jobs` 是并列 entry / runner,只负责装配和边界转译,不得互相依赖。

当前 `02-概要设计.md` 的八个业务组成部分不作为顶层 crate 主轴,而作为横向校验轴。后续章节必须按“模块 + capability 小循环”展开对象、port、protocol、flow、state、persistence、error、config、observability 和 test。

### 5.2 模块总览

| 模块 | 实现单元 | 核心职责 | 对外暴露 | 直接依赖 |
|---|---|---|---|---|
| `contracts` | `crates/contracts` / `method-library-contracts` | 定义 body-free public surface、typed ref、safe marker、command / query / event / job / view 壳。 | public external surface。 | `core-contracts`。 |
| `domain` | `crates/domain` / `method-library-domain` | 定义 definition truth、catalog、formalization、consumption、trace、relation、external summary、package / set 的领域对象、policy、state、guard 和 error。 | internal library surface。 | `contracts`。 |
| `application` | `crates/application` / `method-library-application` | 编排 command、query、consumer、job use case,定义 port、UoW、idempotency、boundary coordination 和 degraded / unavailable 分支。 | internal orchestration surface。 | `contracts`;`domain`。 |
| `infra` | `crates/infra` / `method-library-infra` | 实现 repository、material store、external adapter、publisher adapter、runtime builder、config binding、clock / id / fake。 | internal adapter / runtime assembly surface。 | `contracts`;`domain`;`application`。 |
| `api` | `crates/api` / `method-library-api` | 承接同步 command / query handler assembly 和 transport-neutral entry boundary。 | binary-capable entry surface。 | `contracts`;`application`;`infra`。 |
| `worker` | `crates/worker` / `method-library-worker` | 承接 inbound consumer runner、event candidate publisher runner 和 background loop assembly。 | binary-capable runner surface。 | `contracts`;`application`;`infra`。 |

### 7.1 协议范围与禁入边界

| 范围 | 当前结论 |

| page / cursor | Query、Job、report | page cursor、checkpoint cursor、optimistic version 必须分离。 |
| public marker | Query、Outbound、Job、rejection | degraded / unavailable / stale / not-visible / blocked marker 只能复制正式 mapper / resolver / availability 输出。 |
| receipt / report | Inbound、Outbound、Job | 只承载 typed refs、safe summary、marker,不得承载 raw body。 |

| Group | Execution guarantee |
|---|---|
| 方法资产定义与目录 | definition/catalog writes 使用 versioned repository、domain creation / transition、idempotency replay、body-free history/event refs;不得恢复 `MethodContent` 或 catalog view 反写真相。 |

### 8.4 Query Flow Groups

Query flow 只能读取和组装 public surface。所有 Query 必须 no-write,不得创建 material、刷新 view、append trace/audit、publish event、reserve command idempotency 或启动 job。

| Group | Read guarantee |

| 受控消费 | consumption material、availability view、context ref、boundary、definition-use diagnostic 和 consumable contexts 复制 availability / boundary marker,不得准备 material。 |
| 追溯与一致性保护 | trace material、impact summary、protection diagnostic、audit trail 和 evidence lineage 只返回 body-free chronology、refs、safe diagnostic 和 page。 |
| 关系与分发语义 | relation、relation list、integrity diagnostic、distribution ref/material 和 distribution context 只从 relation / distribution repositories 与 builder 读取。 |
| 外部摘要与引用 | external summary/source/artifact/boundary diagnostic/basis history/lineage hint 必须 body-free;不得返回 external body、archive body 或 provider payload。 |
| 后台维护与收敛 | progress、task summary、run history、pending scopes 和 recovery task 只读取 progress/run/task/issue view;不得读取 worker log、metrics body 或执行 repair。 |
| 外围包与方法集组织 | package、assembly、composition diagnostic、discovery context 和 package/assembly history 只返回 package/assembly refs、availability marker 和 safe page。 |

### 8.5 Inbound Consumer Flows

Inbound Consumer flow 只承接外部 body-free fact,不直接创建或修改 definition、formal version、relation、package 或其他 core truth。

| Flow | Execution guarantee |
|---|---|
| `ConsumeBodyFreeExternalSummaryAcceptedFlow` | validate envelope/schema/dedup -> body-free source adapter -> save intake summary / safe receipt / optional event hint;duplicate replay stored receipt。 |
| `ConsumeExternalSourceRefRegisteredFlow` | validate source ref envelope -> reserve dedup -> record safe typed source ref intake;unresolved source returns delayed/rejected safe receipt。 |
| `ConsumeArtifactArchiveRefRegisteredFlow` | validate artifact ref/digest -> record archive ref intake and lineage hint;archive body/path rejected。 |
| `ConsumeExternalBodyBoundaryViolationFlow` | validate violation envelope and safe reason -> record boundary violation intake/audit hint;body excerpt is never stored。 |

| Branch | Required surface |
|---|---|
| accepted | stored safe receipt with intake summary ref and source refs。 |
| duplicate | stored receipt replay;no source reprocessing。 |
| unsupported schema | safe unsupported receipt;no payload parse beyond envelope。 |

### 8.6 Outbound Event / Publication Flows

| External / maintenance / peripheral | external summary/source/artifact/body-boundary/lineage、maintenance requested/progress/refresh/recovery、package/assembly/composition/peripheral availability 事件不携带 provider body、report body、package body 或 marketplace transaction。 |

Publisher 只能消费 candidate shell、target registry 和 safe availability outcome。Publication failure、blocked target 或 unavailable target 不回滚 accepted truth,也不得触发 hidden repair。

### 8.7 Operations Job Flows

### 9.1 状态机定义原则

## 10. 数据持久化、事务与一致性契约

> 校准来源：

>
> 延伸阅读：

本章定义 L3-method-library 的 logical persistence contract、repository 持久化语义、transaction boundary 和 consistency strategy。本章不绑定物理数据库、SQL 方言、migration 文件、索引语法、cache 产品或 object storage。public error code、retry count、TTL、lock lease、scheduler lease、config key、topic / URL / secret、metric label、trace payload、test fixture 和 evidence artifact schema 均不在本章定义。

### 10.1 数据所有权与 logical store family

| Family | Persistence kind | Write authority | Read authority | Body-free rule |
|---|---|---|---|---|
| core business truth | mutable truth | command / formalization / relation / package / assembly service | command、query、job | typed refs、summary、version only |
| source / reference / boundary summary | summary / marker-only / watch | resolver、intake、boundary guard | query、maintenance、precheck | no raw external body |
| trace / audit / lineage / impact | projection / append-only | trace、audit、lineage、impact service | query、export、job | refs、marker、safe reason only |
| read / projection / material | projection / marker-only | projection / refresh job and read resolver | query service | copy-only marker;query no-write |
| maintenance / job / report | stored shell / append-only | job runner | operations query、report replay | checkpoint / report shell only |
| idempotency / replay / receipt | stored shell | command / consumer / job service | duplicate replay path | stored safe surface only |
| outbound / publication / handoff | append-only / stored shell | publisher / handoff service | audit、operations | candidate / outcome marker only |
| runtime / entry binding | runtime-local | infra/runtime | precheck / facade | config refs and availability marker only |

### 10.2 Repository 与持久化语义

Repository and persistence ports must be those defined by §6 / §7. 本章可以说明正式 port 的持久化语义,但不得创建 implementation-only save / get / list 方法。Mutable truth writes use versioned read plus `expected_version` save semantics. Append-only records use append identity and must not be mutated into current truth.

Stored result、receipt、report、candidate、outcome 和 handoff shell 是 durable replay / observation surface,不是 public DTO body、external payload store 或 raw report body。

Query flows open no write UoW. Query service 可以读取 committed truth、projection、material、summary、report 和 resolver output,然后返回 safe visible / empty / not-visible / stale / degraded / unavailable surface。Query 不得 repair stale material、refresh projections、append audit、publish events、start jobs 或 store query replay。

#### 10.2A `commit-03-b` persistence closure

For `commit-03-b`, `method_asset_definitions` and `method_asset_catalog_entries` are the only mutable truth stores in scope. Definition create/update uses `save_definition(definition, expected_version, uow)`, catalog create/update uses `save_catalog_entry(catalog_entry, expected_version, uow)`, and update `expected_version` must be copied from the matching `Versioned<T>` repository read. Create uses `None` expected version. Repository versions are opaque application tokens,not timestamps,cursors,digests or parsed typed refs.

`method_asset_definitions` must persist `MethodAssetDefinition.definition_lifecycle` as part of the truth object. Fake and durable repositories must return the same lifecycle through `get_definition_with_version(...)` and `find_definition_by_identity_key(...)`; they must not reconstruct `Active` / `Retired` from stored result kind、catalog status、formal version state、effect refs、string prefixes、timestamps or private side maps. `save_definition(...)` is the only current-boundary write surface for the lifecycle transition.

The duplicate replay store for this boundary is `method_asset_stored_operation_results` keyed by `(idempotency_key_ref,dedup_scope_ref)` and addressed by `stored_result_ref`. It stores only replay-safe refs and markers from `MethodAssetStoredOperationResult`;it must not store public command DTO body,raw shell body,raw error,DB row snapshot,event payload,provider body,report body,transport status or config value.

Accepted command transaction order is: begin command UoW -> read idempotency/stored result -> read required truth -> save definition/catalog with expected version -> save stored accepted/rejected/conflict result for idempotency -> commit. Rollback must leave no truth row,version advance,stored accepted result or effect summary visible. Duplicate replay reads stored result and returns the stored safe surface without domain mutation or repository save.

For `commit-03-b`, `retire_definition` reads only the definition truth required to prove `definition_lifecycle = Active` and expected version. It must not add a formal-version precheck, active formal-version conflict lookup, history scan or consumption-material surrogate; those checks are deferred to PH-04 formalization/version boundaries.

### 10.3 Version / Append / Checkpoint 规则

| Concept | Rule |
|---|---|
| expected version | optimistic guard for mutable truth / support / material loaded through formal repository reads。 |
| append identity | audit、lineage、candidate、run history、report、evidence refs 的 append identity;不替代 mutable truth version。 |
| stored replay surface | duplicate command / inbound / job branch 必须读取 stored result / receipt / report / checkpoint,不得 rerun mutation。 |
| checkpoint / cursor | job resume / page progress anchor only;不得替代 optimistic version 或 accepted truth freshness。 |
| runtime availability marker | 可复制到 blocked / degraded surface;不得成为 business lifecycle truth。 |

### 10.4 Transaction Boundary

| Boundary | Atomic rule | Rollback / no-rollback rule |
|---|---|---|
| Command accepted mutation | accepted truth / support / material writes、stored accepted result、body-free candidate refs 在一个 logical UoW 或等价 formal atomic boundary 内提交。 | rollback 后不得留下 accepted replay surface 或 event candidate。 |
| Command rejected / conflict | replayable rejection / conflict result 与 idempotency decision 共享 minimal UoW。 | rollback 后不得留下 durable replay surface。 |
| Query read | no write UoW。 | 无 rollback state;只返回 safe read surface。 |
| Inbound consumer receipt | receipt 与 intake decision 共享 receipt UoW;不改 core truth。 | rollback 表示 duplicate 不能 replay accepted receipt。 |
| Outbound publication | publication outcome 独立于 accepted truth;candidate 是 reload source。 | failure 不回滚 accepted truth / candidate。 |
| Operations job item / page | derived writes、progress、checkpoint、report shell 按 item/page UoW 提交。 | rollback 只回滚该 item/page 的 derived material、progress、checkpoint、report。 |
| Handoff / archive / observability | handoff outcome 独立于 local truth/report/candidate。 | external failure 不回滚 local committed truth。 |
| Runtime / entry precheck | entry 不拥有 business UoW。 | entry 只返回 safe facade surface。 |

### 10.5 Consistency Strategy

本仓采用 accepted mutation boundary 的 local strong consistency 与 outbound publication、handoff、derived material、observability 的 eventual consistency 组合。Local truth remains command-owned。Jobs may rebuild derived material and reports but cannot repair core truth. Publication / handoff / adapter failures produce safe outcome or diagnostic refs,never rollback committed local facts. Duplicate replay reads durable stored surfaces and never reruns side effects.

### 10.6 Body-free 与 Replay 红线

Persistence must not store raw external body、transport payload、report body、raw exception text、public DTO body or synthetic marker。可持久化的 artifact 只能是 typed refs、version refs、summary refs、digests、markers、safe reasons 和 replay-safe shells。

本章定义 domain、application、port、protocol、worker、job 与 side-effect 层的错误模型、异常分支和恢复口径。错误恢复必须回指正式 object / helper / marker、port / mapper / resolver、protocol surface、function flow、state matrix 或 transaction contract。本章不定义 HTTP/RPC 数字、retry count、TTL、lock lease、scheduler lease、config key、topic / URL / secret、metric label、trace payload、evidence path、test case ID 或 implementation code。

### 11.1 错误层级与类型族

| Layer | Type family | Public handling |
|---|---|---|
| domain | invalid transition、domain / policy rejected、body-boundary violation、manual intervention required | safe rejection or manual / blocked surface;no raw body |
| application | idempotency conflict、stored replay missing、commit unknown、material missing、consistency defect | conflict / manual / consistency-safe surface;no rerun |
| port / infra | repository unavailable、resolver unavailable、publisher / handoff unavailable、runtime binding unavailable | unavailable / blocked surface copied from formal marker |
| protocol | invalid request、unsupported command / query / inbound envelope、public surface mismatch | safe invalid / unsupported rejection |
| worker / job | duplicate receipt / report、checkpoint missing / corrupt、partial item failure、report persistence failure | replayed / partial / manual / job failed surface |
| side-effect | audit append failure、candidate invalid、publication / handoff outcome failure、outcome persistence failure | no rollback for committed truth;safe outcome / issue only |

Retryability is semantic,not adapter-driven。Retryable 只来自 formal temporary / unavailable marker 和 §12 later guard。Non-retryable 包括 invalid request、domain rejected、forbidden body、idempotency conflict 和 not-visible。Manual / consistency 包括 stored surface missing、commit unknown、marker/source missing、body leak 和 outcome persistence ambiguity。

对当前 implementation boundary `commit-02-b`,本章进一步收窄为 pure domain error foundation only。实现端当前只允许落码 domain layer 的最小错误集,不得把 application / port / worker / job error 提前放进 `crates/domain`:

| allowed current-boundary domain error kind | source | implementation rule |
|---|---|---|
| `MissingRequiredTypedInput` | Step 6 factory / policy shell required typed input | 只用于 pure domain constructor / helper 缺少 formal typed input;不得包装 request DTO、route 或 config raw value。 |
| `InvariantViolation` | Step 6 object invariant | 只用于 pure domain invariant failure;不得替代 version conflict、stored replay missing 或 adapter failure。 |
| `InvalidTransition` | Step 10 legal / illegal judgement transition | 只用于当前 boundary judgement-state illegal transition;不得扩成 business truth lifecycle or job/report transition。 |
| `PolicyRejected` | Step 6 policy / guard rejection plus Step 10 judgement branch | 只用于 current policy shell reject branch;safe reason 复制 formal marker,不得暴露 raw exception / payload / provider detail。 |
| `BodyFreeBoundaryViolation` | Step 6 `ExternalBodyBoundaryRule` plus Step 10 no-body judgement | 只用于 raw body would cross domain boundary;不得保存 raw body to explain failure。 |

以下错误家族明确后移,不属于 `commit-02-b`:

| deferred error family | defer reason |
|---|---|
| idempotency conflict、stored replay missing、commit unknown、consistency defect | application / replay / UoW owning boundary 在 `commit-02-c`+。 |
| dependency / adapter unavailable、publisher / handoff failed | port / infra / worker owning boundary later。 |
| not found、not visible、stale / degraded / unavailable public surface | query / material / mapper owning boundary later。 |
| checkpoint / report / partial job defect | jobs owning boundary later。 |

### 11.2 Command 错误恢复

| Command branch | Recovery rule |
|---|---|
| invalid request before reserve | return safe invalid request rejection;no UoW、truth、stored accepted result or event candidate。 |
| domain / policy rejected | return safe rejection;only store replayable rejection when protocol / persistence define stored surface。 |
| version conflict | rollback accepted UoW and return reload-required conflict;retry algorithm belongs to §12。 |
| accepted UoW failure | accepted not proven;stored accepted result and event candidate must not survive rollback。 |
| duplicate replay | copy stored accepted / rejected result;never rerun command or re-emit side effect。 |
| stored result missing / wrong kind | manual consistency failure;do not rebuild response from current truth。 |
| commit unknown | manual / consistency-safe surface;do not run post-commit side effect until resolved by formal source。 |

### 11.3 Query 错误恢复

Query is always no-write。Query may return visible、empty、safe absent、not-visible、stale-visible、degraded、unavailable、partial or consistency defect surface,using only formal read resolver、availability / degraded mapper、repository summary and safe diagnostic source。Query must not repair material、refresh projection、append audit、publish event、start job or store query replay。

Missing marker / source is a design blocker or consistency defect。Implementation must not synthesize marker from route、exception text、SQL/HTTP code or private state。

### 11.4 Inbound / Outbound / Handoff 错误恢复

Inbound workers only validate body-free envelopes,store intake decision / receipt,copy duplicate receipt and optionally emit candidate hint when formal。They do not mutate core truth from raw inbound signal。

Outbound publication is split into candidate assembly and publisher outcome。Candidate source must be accepted command effect、completed / partial job report or bounded inbound receipt / body-free fact。Publisher failure never rolls back source truth or candidate。Publication outcome must be body-free and copied from publisher / target registry output。

Handoff outcome is local body-free marker state。Prepared is not delivered;delivered means formal receipt marker only,not downstream business truth。Handoff failure、blocked or unavailable never rolls back local source truth / report / candidate。Outcome persistence failure is consistency unknown / manual。

### 11.5 Job / Operations 错误恢复

Operations Job errors split by invalid input、unsupported family、runtime blocked、duplicate / replay、checkpoint missing / wrong / corrupt、target planning empty / unavailable、partial item failure、derived save failure、report / progress / checkpoint persistence failure、stored report / run history missing、body-free report violation and manual intervention required。

Jobs may write derived material、progress、checkpoint、run history、safe issue、stored report and event candidate hint。Jobs must not create、update、delete or repair core business truth。Partial item failure must be explicit through safe issue / progress / report marker。Duplicate / replay / resume must not rerun job body or rebuild report from current truth。

### 11.6 Audit / Side-effect Failure Rules

Accepted success side effects inside command / job UoW are atomic with that UoW。Failure before commit prevents accepted success。Rejected command、query branch and duplicate replay cannot emit success event / audit / job side effect unless a formal observation-only rule later exists。

Audit / trace / lineage append failure inside accepted UoW rolls back with the UoW。Post-commit / deferred observation failure does not roll back committed truth / report / candidate and must be represented as safe side-effect failure / issue when formal source exists。

Event candidate assembly、publication outcome and handoff outcome are separate layers。Candidate assembled is not publication delivered。Handoff delivered means formal body-free receipt marker only。

### 11.7 Closure, Blocker and Handoff

If a required source、marker、mapper、port、stored surface or schema is missing,implementation must pause and return to owning design truth source。§12 receives retryability、replay、commit-unknown、checkpoint and duplicate classifications and must define idempotency、retry、re-entry、lock、lease and checkpoint resume behavior without changing §11 public surface semantics。§13 owns config binding;§14 owns observability / audit / evidence;§15 owns test cuts and evidence validation。

本章定义 L3-method-library 的并发、幂等与重入保护边界。保护对象包括 Command mutation、Query repeat read、Inbound redelivery、Outbound publication retry、Handoff retry、Operations Job resume 和 runtime entry guard。本章不定义 physical lock table、DB isolation、retry numeric policy、TTL、lease duration、config key、observability payload、test case schema 或 implementation code。

所有 key、digest、version、checkpoint、stored replay surface、marker、outcome 和 runtime binding 只能来自已正式定义的 object、port、protocol、flow、state、persistence 和 recovery surface。缺正式来源时,实现必须暂停回设计闭口。

### 12.1 Protection Layers

| Layer | Rule |
|---|---|
| request idempotency | same formal operation key + same digest 的 duplicate 复制 stored surface;同 key 不同 digest 是 conflict;in-flight 不允许第二 writer。 |
| resource concurrency | mutable truth 使用 formal version / expected_version;append-only side effect 使用 append identity;checkpoint、cursor、freshness、lease 不替代 version。 |
| worker reentry | Inbound、Outbound、Handoff、Operations Job 只能从 formal receipt、candidate、outcome、checkpoint、report 或 issue source 恢复。 |
| runtime guard | entry / scheduler / lease 只能表达 runtime ownership 或 unavailable / blocked classification,不得成为 business truth、checkpoint、stored replay proof 或 idempotency key。 |

### 12.2 Command Idempotency and Concurrency

Command accepted / rejected duplicate path must first read formal idempotency guard and stored surface。same key + same digest + completed returns stored result / rejection / effect summary。same key + different digest returns conflict。in-flight returns retryable or blocked public surface only when formal marker exists。

stored surface missing、wrong kind or unreadable enters consistency / manual;Command body must not rerun to rebuild response。Command mutation path uses repository version / expected_version to prevent lost update。version conflict can only retry after formal reload。commit unknown cannot be judged successful from timeout、log、current truth or adapter note;it requires stored surface、read-back or formal recovery source。

### 12.3 Query Repeatability and No-write

Query 重复调用不写 idempotency store,不修复 projection / material,不创建 missing marker。Query only reads current formal safe surface and copies visibility、freshness、degraded、unavailable、not-visible or safe absent marker。page cursor only expresses page position and cannot replace version、checkpoint or freshness marker。

When Query finds material missing、partial page、marker missing or source mismatch,it may only return public surface already defined by protocol / recovery sections。If a formal marker source is missing,the branch is a design blocker。

### 12.4 Inbound / Outbound / Handoff Reentry

Inbound redelivery uses formal source binding and stored receipt to identify duplicate。same source + same semantic material copies stored receipt。digest / source mismatch or receipt missing follows §11 recovery surface。broker ack、topic、offset or dead-letter state cannot become receipt truth。

Outbound publication retry can only recover from durable event candidate and target publication outcome shell。Handoff retry can only recover from handoff-safe refs and local outcome marker。publication / handoff are post-commit side-effect layers;failure or retry must not roll back committed truth、stored result、receipt、report or checkpoint。

### 12.5 Operations Job Checkpoint Resume

Operations Job duplicate completed path returns stored report。resume can only continue from formal task / run / checkpoint / progress / report / issue source。partial retry can only target failed subset marked by formal issue / progress。checkpoint missing、checkpoint corrupt、report missing or issue source missing enters blocked / manual。

Job must not use scheduler lease、queue offset、timestamp、current material scan or adapter note as substitute for checkpoint、report or idempotency proof。Job does not own core truth repair unless §8 / §10 already defines the write as formal maintenance output。

### 12.6 Retry / Lock / Lease Boundary

Retry is allowed only when formal safe outcome / classification says temporary、unavailable or retryable。same digest completed is replay,not retry。different digest conflict is not auto-retry。commit unknown and missing stored surface enter manual / consistency。

Lock in this section means semantic guard owner: idempotency reservation、expected_version、append identity、candidate / outcome identity and job checkpoint / report guard。Physical lock table、row lock、DB isolation and scheduler implementation remain outside this chapter。

Lease is runtime execution ownership only。lease expiry / renewal does not prove rollback、completion、checkpoint advance or report write。retry number、backoff、TTL、lease duration、target registry and adapter binding are handled by later configuration / dependency work.

### 12.7 Closure, Blocker and Handoff

§12 closes the main concurrency / idempotency boundary for object source、port usage、protocol surface、function flow、state owner、persistence transaction and recovery behavior。Later chapters must preserve these source rules:

| Target | Constraint |
|---|---|
| §13 config / dependency | may bind runtime values and dependencies,not change semantic source rules。 |
| §14 observability / audit | may define safe observations,not leak raw body、secret、unsafe external response or private adapter detail。 |
| §15 test cut | may define verification and evidence,not use fixture to补 formal source、port、mapper or marker。 |

## 3. 实现约束与编码规范承接

### 3.1 Rust 编码规范承接

| 规范来源 | 必须遵守的内容 | 对本文的影响 |

| `standards/document/详细设计书写规范.md` | 伪代码调用必须写 `对象.函数(Type 参数名)` 或 `Type::函数(Type 参数名)` | 处理流必须标注调用对象、函数、参数类型和用途 |

### 3.2 实现约束

| 约束 | 说明 | 影响模块 |
|---|---|---|
| 语言以 Rust 契约表达 | 所有对象、trait、DTO、schema 和伪代码以 Rust 可实现形态描述 | 全文 |
| PostgreSQL 是 Definition truth 主存储 | definition truth、version、fingerprint、audit、outbox 保存在 PostgreSQL | infra / persistence |
| L0-bus 是定义事件传播目标 | outbox-relay 通过事件总线传播已提交定义事实 | worker / bus adapter |

| 本仓不实现统一认证 | 安全入口由 gateway / nginx-like 层负责 | api |
| 本仓必须保存审计上下文 | Command / Query / Job / Event Consumer 必须传递 `ActorContext`、`RequestMeta`、`ApprovedGateRef` 等 | application / audit |
| 下游 Use truth 不进入本仓 | QualificationProfile、QualificationBinding、ProcessInstance、WorkItem、Artifact instance 等不得成为本仓对象或表 | domain / persistence |
| Command 不直接发布 L0-bus | 写路径只同事务写 outbox,由 worker relay 发布 | application / worker |

## 4. 实现单元与文件布局

本文使用 `method-library/` 表示目标实现仓根目录。若代码实现发生在其他目录,应把以下 workspace / crate / file tree 套用到目标实现仓。

### 4.1 实现单元总表

| 实现单元 | 类型 | 职责 |
|---|---|---|
| `method_library_domain` | library crate | 定义 MethodContent、7 类 P0 definition、value object、domain policy、domain error |
| `method_library_contracts` | library crate | 定义 Command / Query / Event / Snapshot / Job DTO、ActorContext、metadata、error response |
| `method_library_application` | library crate | 编排 command / query / job service,定义 port trait,维护事务用例边界 |
| `method_library_infra` | library crate | 实现 PostgreSQL repository / unit of work / audit / outbox / projection、L0-bus publisher、外部 adapter |
| `method_library_api` | binary crate | 暴露 Command / Query / Snapshot / Operations HTTP JSON 入口,提取 gateway context,映射错误 |
| `method_library_worker` | binary crate | 运行 outbox relay 与 operations job,包括 seed、replay、rebuild、recalculate |

关键说明:

- 文件树表达 P0 必须落地的实现单元,不是最终仓库中所有文件的完整清单。

### 4.3 布局边界

- `method_library_domain` 不允许依赖 HTTP、PostgreSQL、L0-bus、object storage、configuration source 或下游系统。
- `method_library_application` 只依赖 domain、contracts 和 ports,不直接依赖 concrete adapter。
- `method_library_infra` 实现 application ports。
- `method_library_api` 只做入口、context extraction、handler 和 error mapping,不做领域判断。
- `method_library_worker` 只运行 relay / job,不得绕过 application / domain 规则直接改写真相。
- P1 的 `MethodPlugin` / `MethodConfiguration` 不进入 P0 必建文件树。

## 5. 模块实现契约

### 5.1 模块总览

| 模块 | 所属实现单元 | 职责 | 对外暴露 |
|---|---|---|---|
| `domain::content` | `method_library_domain` | 定义 P0 MethodContent 共同聚合、生命周期、版本、fingerprint、reference | `MethodContent`、`MethodContentKind`、`MethodContentLifecycle`、`ContentVersion`、`CanonicalFingerprint`、`ContentRef` |
| `domain::definitions` | `method_library_domain` | 定义 7 类 P0 definition subtype 的专属语义 | `Qualification`、`RoleDefinition`、`TaskDefinition`、`WorkProductDefinition`、`ProcessTemplateDef`、`ViewProfile`、`AIPolicyDef` |
| `domain::policies` | `method_library_domain` | 定义发布、引用校验、边界保护、fingerprint、ViewProfile 匹配规则 | `PublishPolicy`、`ReferenceValidationPolicy`、`DefinitionUseBoundaryGuard`、`FingerprintPolicy`、`ViewProfileMatchPolicy` |
| `contracts` | `method_library_contracts` | 定义外部和内部协议 DTO | Command / Query / Event / Snapshot / Job DTO、`ActorContext`、`RequestMeta`、error response |
| `application::command_services` | `method_library_application` | 编排草稿、提交审核、发布、废弃、退役、supersede 写路径 | `MethodContentCommandService`、`PublishGovernanceService` |
| `application::sync_services` | `method_library_application` | 编排 event、snapshot、replay、resync | `DefinitionSyncService`、`SnapshotExportService` |
| `application::query_services` | `method_library_application` | 编排列表、详情、trace、ResolveViewProfile 只读路径 | `MethodContentQueryService`、`ViewProfileResolveService`、`DefinitionTraceQueryService` |
| `application::operations_services` | `method_library_application` | 编排 seed、replay、rebuild、recalculate operations job | `MethodOperationsService` |
| `application::ports` | `method_library_application` | 定义外部能力抽象和事务边界 | repository、unit_of_work、audit、outbox、gate、blob、event、projection、clock、id_generator trait |
| `infra::persistence` | `method_library_infra` | 实现 PostgreSQL write model、audit、outbox、projection、transaction | PostgreSQL repository / UnitOfWork / projection adapters |
| `infra::outbound_adapters` | `method_library_infra` | 实现 L0-bus、object storage、governance gate 等外部 adapter | `L0EventPublisher`、`ObjectStorageBlobRefAdapter`、`GateDecisionClient` |
| `api` | `method_library_api` | 暴露 Command / Query / Snapshot / Operations 入口,提取 gateway context,映射错误 | routes、handlers、extractors、response mapper |
| `worker` | `method_library_worker` | 运行 outbox relay 和 operations jobs | outbox relay runner、seed / replay / rebuild / recalculate job runner |

### 5.2 模块依赖图

#### 模块依赖图: L3-method-library 模块实现主轴

```text

  | call command/query
  v
[application::command_services] ---- call ----> [domain::policies]
  | use trait                                  | call
  v                                           v
[application::ports]                   [domain::content]
  ^ impl                                      ^
  |                                           | owns payload
[infra::persistence]                 [domain::definitions]

[worker]
  | call sync/job
  v
[application::sync_services] + [application::operations_services]
  | use trait
  v
[application::ports] <--- impl --- [infra::outbound_adapters]
```

关键说明:

- `domain::*` 不依赖 `contracts`、`application::*`、`infra::*`、`api` 或 `worker`。
- `infra::*` 实现 `application::ports`,application 不反向依赖 infra。
- `api` 和 `worker` 必须通过 application service 进入业务主链,不得直接写 repository 或 domain truth。

#### 5.3.2 `MethodContentKind` 枚举契约

枚举摘要:

| 项 | 内容 |
|---|---|
| 所属层 | domain enum |
| 建议文件 | `method_library_domain/src/content/kind.rs` |
| 主要责任 | 表达 P0 方法定义资产的 7 类正式 kind,并约束 `MethodContent.kind` 与 `MethodContentPayload` 的对应关系 |
| 禁止事项 | 不表达下游 Use truth 类型,不把 `MethodPlugin` / `MethodConfiguration` 纳入 P0 kind |

状态集合:

| Variant | Rustdoc 注释 | persisted / JSON value | 必须匹配的 payload variant | 主要消费者 |
|---|---|---|---|---|
| `MethodContentKind::Qualification` | SPEM Qualification 语义的胜任力定义。 | `qualification` | `MethodContentPayload::Qualification` | identity / capability-hub |
| `MethodContentKind::RoleDefinition` | SPEM RoleDefinition 语义的角色定义。 | `role_definition` | `MethodContentPayload::RoleDefinition` | identity / process / UI |
| `MethodContentKind::TaskDefinition` | SPEM TaskDefinition 语义的任务定义。 | `task_definition` | `MethodContentPayload::TaskDefinition` | process;work direct 待确认 |
| `MethodContentKind::WorkProductDefinition` | SPEM WorkProductDefinition 语义的工作产品定义。 | `work_product_definition` | `MethodContentPayload::WorkProductDefinition` | artifact / process |
| `MethodContentKind::ProcessTemplateDef` | 流程模板定义,作为 ProcessTemplate 的定义来源。 | `process_template_def` | `MethodContentPayload::ProcessTemplateDef` | process |
| `MethodContentKind::ViewProfile` | 角色视图策略定义,用于按角色和对象解析展示规则。 | `view_profile` | `MethodContentPayload::ViewProfile` | UI / console / downstream |
| `MethodContentKind::AIPolicyDef` | AI 策略定义,作为治理策略来源。 | `ai_policy_def` | `MethodContentPayload::AIPolicyDef` | governance |

#### 5.4.3 `MethodContentPayload` 枚举

```rust
/// P0 方法定义正文的联合类型。
///
/// variant 必须与 `MethodContent.kind` 一致;不得在 payload 中保存下游 Use truth。
pub enum MethodContentPayload {
```

#### 5.11.2 代表性 Trait 契约

```rust
/// 管理 command、event、job 写路径中的数据库事务边界。
///
/// 该端口只负责开启、提交和回滚事务,不承载业务规则。
pub trait UnitOfWork {
    /// 开启一次事务,并绑定请求追踪元信息。
    async fn begin(&self, meta: RequestMeta) -> Result<UnitOfWorkTx, MethodLibraryError>;
}

/// 读写 MethodContent write model 的 repository port。
///
/// 实现方必须通过乐观锁保护 revision,不得在 repository 内部决定 lifecycle 迁移。
pub trait MethodContentRepository {
    /// 在事务内带锁读取 MethodContent 聚合。
    async fn get_for_update(
        &self,
        tx: &mut UnitOfWorkTx,
        content_id: ContentId,
    ) -> Result<Option<MethodContent>, MethodLibraryError>;

    /// 插入新的 MethodContent 聚合。
    async fn insert(
        &self,
        tx: &mut UnitOfWorkTx,
        content: MethodContent,
    ) -> Result<(), MethodLibraryError>;

    /// 按 expected_revision 保存 MethodContent 聚合,并返回新 revision。
    async fn save(
        &self,
        tx: &mut UnitOfWorkTx,
        content: MethodContent,
        expected_revision: Revision,
    ) -> Result<Revision, MethodLibraryError>;
}

/// 保存并推进 outbox event 状态的 repository port。
///
/// 该端口不决定业务事件是否应该产生;事件只能由 application service / factory 创建后传入。
pub trait OutboxRepository {
    /// 在同一业务事务内追加待发布事件。
    async fn append(
        &self,
        tx: &mut UnitOfWorkTx,
        event: OutboxEvent,
    ) -> Result<(), MethodLibraryError>;

    /// 原子 claim 可发布的 pending / retryable / expired publishing events。
    async fn claim_pending(
        &self,
        limit: BatchSize,
        worker_id: WorkerId,
        now: Timestamp,
        lease: LeaseDuration,
    ) -> Result<Vec<OutboxEvent>, MethodLibraryError>;
}
```

#### 5.11.4 Port 红线

- repository 不得实现 lifecycle 状态机。
- repository 不得发布 event 或调用 outbound port。
- outbound port 不得写本仓数据库。
- `BusPublisherPort` 不得由 command service 直接调用,必须经 outbox relay / replay job。
- projection repository 可以清空重建,但不能作为 write model 来源。
- support port 是时间、ID、hash、feature flag、observability 的唯一入口。

## 8. 逐接口函数级处理流

### 8.1 通用处理规则

#### 处理流图: 通用入口到响应骨架

```text
[Inbound adapter]
  | parse DTO + GatewayHeaders
  | call application service
  v
[Application service]
  | enforce idempotency / read policy
  | tx begin when write path
  | call domain object / domain policy
  | call repository / outbox / snapshot / projection port
  | tx commit or rollback
  v
[Response DTO / Event Ack / Job Result]
```

关键说明:

- Inbound adapter 只做 DTO / header / response 映射,不判断 definition 生命周期。
- Application service 是事务、幂等、端口调用和领域对象编排的唯一入口。
- Command 写 truth 时必须先本地事务提交,再由 outbox relay 异步发布事件。

- `api` handler 只做协议转换,不承载业务规则。
- `worker` runner 只触发 job / relay,不直接改 write model。
- 所有写 truth 的路径必须进入 application service 和 domain method。
- Query 只读,不创建 audit / outbox / lifecycle history。
- Command 只 append outbox,不直接 publish L0-bus。

### 8.2 Command 写路径通用骨架

```rust
// [MethodContentCommandService.<command>(CommandDto command, ActorContext actor, RequestMeta meta)]
// Command 写路径统一入口:校验幂等、开启事务、调用领域对象、写 audit/outbox、提交事务。
async fn handle_command(
    command: CommandDto,
    actor: ActorContext,
    meta: RequestMeta,
) -> Result<ResponseDto, MethodLibraryError> {
    // [UnitOfWork.begin(RequestMeta meta)]
    // 开启本次写路径事务,后续 write model、audit、outbox、idempotency result 必须同事务提交。
    let mut tx = unit_of_work.begin(meta.clone()).await?;

    // [IdempotencyRepository.try_begin(UnitOfWorkTx tx, IdempotencyKey key, IdempotencyScope scope, RequestHash request_hash)]
    // 根据幂等键和请求 hash 防止重复执行或同 key 不同 payload。
    idempotency_repository
        .try_begin(&mut tx, meta.idempotency_key(), command.scope(), meta.request_hash())
        .await?;

    // [具体领域调用]
    // 每个 Command 在独立小节中定义差异调用。

    // [UnitOfWorkTx.commit()]
    // 提交全部本地写入;中途 Err 必须回滚或由 UnitOfWork drop rollback。
    tx.commit().await?;

    Ok(response)
}
```

### 8.3 P0 Command 处理流

#### 8.3.1 流程图: `CreateMethodContentDraftFlow`

```text
[Command Handler]
  | call ActorContext::from_gateway_headers(GatewayHeaders headers)
  | call RequestMeta::from_http_request(HttpRequest request, GatewayHeaders headers)
  | call MethodContentCommandService.create_draft(CreateMethodContentDraftCommand command, ActorContext actor, RequestMeta meta)
  v
[MethodContentCommandService]
  | tx UnitOfWork.begin(RequestMeta meta)
  | call IdempotencyRepository.try_begin(UnitOfWorkTx tx, IdempotencyKey key, IdempotencyScope scope, RequestHash request_hash)
  | call IdGenerator.new_content_id()
  | call MethodContent::create_draft(ContentId content_id, ContentFamilyId family_id, MethodContentKind kind, String name, Option<String> description, MethodContentPayload payload, ActorContext actor, Timestamp now)
  | call MethodContent.ensure_payload_matches_kind()
  | call MethodContent.ensure_definition_boundary()
  | call MethodContentRepository.insert(UnitOfWorkTx tx, MethodContent content)
  | call AuditRepository.append(UnitOfWorkTx tx, AuditRecord record)
  | call IdempotencyRepository.mark_completed(UnitOfWorkTx tx, IdempotencyKey key, IdempotencyScope scope, ResultRef response_ref, Timestamp now)
  | tx commit
```

关键说明:

- `CreateMethodContentDraftFlow` 是唯一创建 draft MethodContent 的入口。
- 此流程只写 draft truth、普通 refs、audit 和 idempotency result,不写 outbox event。
- `MethodContent::create_draft(...)` 必须同时校验 kind / payload 对应关系和 definition-only 边界。

错误: `IDEMPOTENCY_KEY_REQUIRED`、`IDEMPOTENCY_CONFLICT`、`PAYLOAD_KIND_MISMATCH`、`BOUNDARY_VIOLATION`、`CONTENT_VERSION_CONFLICT`。

#### 8.3.2 流程图: `UpdateMethodContentDraftFlow`

```text
[MethodContentCommandService.update_draft(UpdateMethodContentDraftCommand command, ActorContext actor, RequestMeta meta)]
  | tx begin
  | call MethodContentRepository.get_for_update(UnitOfWorkTx tx, ContentId content_id)
  | call MethodContent.ensure_revision(Revision expected_revision)
  | call MethodContent.update_draft(String name, Option<String> description, MethodContentPayload payload, ActorContext actor, Timestamp now)
  | call DefinitionUseBoundaryGuard.ensure_definition_only(MethodContentPayload payload)
  | call MethodContentReferenceRepository.replace_refs(UnitOfWorkTx tx, ContentId source_content_id, Vec<ContentRef> refs)
  | call MethodContentRepository.save(UnitOfWorkTx tx, MethodContent content, Revision expected_revision)
  | append audit + mark idempotency completed
  | tx commit
```

关键说明:

- 此流程只允许更新 `Draft` 状态的 definition。
- `replace_refs(...)` 是原子替换,不得在失败时留下部分引用。
- `Revision expected_revision` 是调用方并发保护入口,repository 保存时必须二次校验。

错误: `METHOD_CONTENT_NOT_FOUND`、`REVISION_CONFLICT`、`PUBLISHED_CONTENT_IMMUTABLE`、`LIFECYCLE_TRANSITION_NOT_ALLOWED`、`BOUNDARY_VIOLATION`。

```text
[MethodContentCommandService.submit_for_review(SubmitMethodContentForReviewCommand command, ActorContext actor, RequestMeta meta)]
  | tx begin
  | call MethodContentRepository.get_for_update(UnitOfWorkTx tx, ContentId content_id)
```

关键说明:

- 此流程只负责 `Draft -> InReview`,不自动调用 governance。
- 生命周期变化、history、audit 和 idempotency result 必须同事务提交。
- 第一版不支持驳回回到 draft;如需要必须新增 review decision command。

错误: `METHOD_CONTENT_NOT_FOUND`、`REVISION_CONFLICT`、`LIFECYCLE_TRANSITION_NOT_ALLOWED`。

#### 8.3.4 流程图: `PublishMethodContentFlow`

```text
[MethodContentCommandService.publish(PublishMethodContentCommand command, ActorContext actor, RequestMeta meta)]
  | tx begin
  | call MethodContentRepository.get_for_update(UnitOfWorkTx tx, ContentId content_id)
  | call PublishGovernanceService.validate_publish_gate(MethodContent content, ApprovedGateRef gate_ref, ActorContext actor, RequestMeta meta)
  | call ReferenceValidationPolicy.validate_published_refs(MethodContent content, Vec<ContentRef> refs, Vec<PublishedContentRef> resolved_refs)

  | call DefinitionSnapshotRepository.insert(UnitOfWorkTx tx, DefinitionSnapshot snapshot)
  | call OutboxRepository.append(UnitOfWorkTx tx, OutboxEvent event)
```

关键说明:

- publish 必须先通过 gate、reference、fingerprint 和 snapshot 构建校验。
- `OutboxRepository.append(...)` 与 published truth 同事务提交,但 bus publish 不在该事务内发生。
- snapshot metadata 写入 DB,大正文写 object storage,二者通过 `SnapshotRef / SnapshotBlobRef` 关联。

错误: `METHOD_CONTENT_NOT_FOUND`、`REVISION_CONFLICT`、`PUBLISH_GATE_REQUIRED`、`PUBLISH_GATE_INVALID`、`REFERENCE_NOT_PUBLISHED`、`FINGERPRINT_BUILD_FAILED`、`SNAPSHOT_BUILD_FAILED`、`OUTBOX_APPEND_FAILED`。

关键说明:

- deprecate 只改变本仓 definition 生命周期,不清理下游引用。
- deprecated event 通过 outbox 通知下游停止新增引用或触发本地策略调整。
- 废弃原因必须进入 lifecycle history / audit。

错误: `METHOD_CONTENT_NOT_FOUND`、`REVISION_CONFLICT`、`LIFECYCLE_TRANSITION_NOT_ALLOWED`。

#### 8.3.6 流程图: `RetireMethodContentFlow`

```text
[MethodContentCommandService.retire(RetireMethodContentCommand command, ActorContext actor, RequestMeta meta)]
  | tx begin
  | call MethodContentRepository.get_for_update(UnitOfWorkTx tx, ContentId content_id)
  | call MethodContent.ensure_revision(Revision expected_revision)
  | call MethodContent.retire(String reason, ActorContext actor, Timestamp now)
  | call MethodContentRepository.save(UnitOfWorkTx tx, MethodContent content, Revision expected_revision)
  | call OutboxRepository.append(UnitOfWorkTx tx, OutboxEvent retired_event)
  | append audit + lifecycle history + mark idempotency completed
  | tx commit
```

关键说明:

- retire 表示 definition 只保留追溯,默认不再允许新增使用。
- `retire_policy` 是下游处理提示,method-library 不执行下游清理。
- 已 retired 后重复 retire 的具体响应语义仍在 §17 待确认。

错误: `METHOD_CONTENT_NOT_FOUND`、`REVISION_CONFLICT`、`LIFECYCLE_TRANSITION_NOT_ALLOWED`。已 retired 重复请求语义见 §17 待确认。

#### 8.3.7 流程图: `SupersedeMethodContentFlow`

```text
[MethodContentCommandService.supersede(SupersedeMethodContentCommand command, ActorContext actor, RequestMeta meta)]
  | tx begin
  | call MethodContentRepository.get_for_update(UnitOfWorkTx tx, ContentId old_content_id)
  | call MethodContentRepository.get_for_update(UnitOfWorkTx tx, ContentId new_content_id)
  | call PublishGovernanceService.validate_publish_gate(MethodContent new_content, ApprovedGateRef gate_ref, ActorContext actor, RequestMeta meta)
  | call MethodContent.mark_superseded_by(ContentId next_content_id, String reason, ActorContext actor, Timestamp now)
  | call MethodContent.publish(ApprovedGateRef gate_ref, ContentVersion version, CanonicalFingerprint fingerprint, ActorContext actor, Timestamp now)
  | call SupersedeLinkRepository.insert(UnitOfWorkTx tx, SupersedeLink link)
  | call DefinitionSnapshotRepository.insert(UnitOfWorkTx tx, DefinitionSnapshot snapshot)
  | call OutboxRepository.append(UnitOfWorkTx tx, OutboxEvent old_event)
  | call OutboxRepository.append(UnitOfWorkTx tx, OutboxEvent new_event)
  | save old/new content + append audit/history + mark idempotency completed
  | tx commit
```

关键说明:

- supersede 是 old content 状态变化与 new content 发布的同事务双聚合流程。
- old / new 必须 kind 一致,并且 new definition 通过 publish 同等 gate、fingerprint、snapshot 校验。
- 替代链通过 `SupersedeLink` 固化,不能只靠两个 content 字段隐式表达。

错误: `METHOD_CONTENT_NOT_FOUND`、`REVISION_CONFLICT`、`PUBLISH_GATE_INVALID`、`SUPERSEDE_KIND_MISMATCH`、`SUPERSEDE_CONFLICT`。

## 9. 状态机与转换矩阵

### 9.1 状态机总表

| 状态机 | 类型 | Rust enum / value object | 覆盖范围 |
|---|---|---|---|
| MethodContent 生命周期 | 业务状态机 | `LifecycleState` / `MethodContentLifecycle` | definition 从 draft 到 published / retired / superseded |
| Outbox 发布状态 | 可靠事件状态机 | `OutboxStatus` | outbox event 从 pending 到 published / dead-letter |
| 幂等处理状态 | 可靠请求状态机 | `IdempotencyStatus` | command / job / inbound event 去重处理状态 |
| Job 运行状态 | 运维任务状态机 | `JobRunStatus` | seed / replay / recalculate / rebuild job 运行结果 |

#### 9.1.1 Rust enum 实现契约

本节只定义状态集合和序列化值。状态迁移校验必须由 `MethodContentLifecycle`、`OutboxEvent`、`IdempotencyRepository`、`JobRunRepository` 或对应 application service 承担,不得只依赖 enum 自身。

```rust
/// MethodContent 的生命周期状态集合。
///
/// 该枚举表达 definition truth 的当前状态;合法迁移由
/// `MethodContentLifecycle` 和 `MethodContent` 领域函数控制。
pub enum LifecycleState {
    /// 草稿,允许更新正文和普通引用。
    Draft,
    /// 已提交评审,等待发布 gate 或后续评审动作。
    InReview,
    /// 已发布,可作为下游权威 definition 引用。
    Published,
    /// 已废弃,历史可追溯,默认不允许新增引用。
    Deprecated,
    /// 已退役,只保留追溯。
    Retired,
    /// 已被新 definition 替代,必须保留替代链。
    Superseded,
}

/// Outbox 事件可靠发布状态集合。
///
/// 该枚举只表达 event relay 状态;业务事件是否产生由 application service 决定。
pub enum OutboxStatus {
    /// 已写入本地事务,等待 worker claim。
    Pending,
    /// 已被某个 worker claim 并处于发布中。
    Publishing,
    /// 已收到 bus 发布成功确认。
    Published,
    /// 发布失败但允许按 next_retry_at 重试。
    RetryableFailed,
    /// 达到重试上限或不可重试,等待人工或 operations 恢复。
    DeadLettered,
}

/// 幂等记录处理状态集合。
///
/// 该枚举保护 command、job、inbound event 不被重复执行。
pub enum IdempotencyStatus {
    /// 已占用幂等键,业务处理仍在进行。
    Processing,
    /// 已成功完成,重复请求应返回既有结果引用。
    Succeeded,
    /// 已失败并记录原因;第一版按终态处理。
    Failed,
}

/// Operations job 运行状态集合。
///
/// 该枚举表达一次 job run 的最终结果,不替代 checkpoint。
pub enum JobRunStatus {
    /// Job 正在执行。
    Running,
    /// 全部 item 成功。
    Succeeded,
    /// 部分 item 成功,部分失败。
    PartiallySucceeded,
    /// Job 整体失败。
    Failed,
}
```

### 9.2 状态机关系图

#### 状态关系图: 生命周期、Outbox、幂等与 Job

```text
[MethodContentLifecycle]
  Draft -> InReview -> Published -> Deprecated / Retired / Superseded
        |
        | publish / deprecate / retire / supersede append outbox
        v
[OutboxStatus]
  Pending -> Publishing -> Published
                  |
                  v
             RetryableFailed -> Pending
                  |
                  v
             DeadLettered

[IdempotencyStatus]
  Processing -> Succeeded
       |
       v
    Failed

[JobRunStatus]
  Running -> Succeeded / PartiallySucceeded / Failed
```

关键说明:

- MethodContent 生命周期变化可能追加 outbox event,但 outbox 状态机不反向决定业务生命周期。
- 幂等状态保护请求执行边界,不表达 MethodContent 的业务状态。
- Job 状态只记录 operations run 结果,checkpoint 仍由 projection / replay 组件单独维护。

### 9.3 `LifecycleState`

#### 9.3.1 状态集合

| Rust enum variant | Rustdoc 注释 | persisted / JSON value | 作用 | 是否终态 |
|---|---|---|---|---|
| `LifecycleState::Draft` | 草稿,允许更新正文和普通引用。 | `draft` | 草稿定义,可修改但不能被下游作为权威引用 | 否 |
| `LifecycleState::InReview` | 已提交评审,等待发布 gate 或后续评审动作。 | `in_review` | 已提交评审,等待 gate 或发布动作 | 否 |
| `LifecycleState::Published` | 已发布,可作为下游权威 definition 引用。 | `published` | 已发布权威 definition,默认可被新增引用 | 否 |
| `LifecycleState::Deprecated` | 已废弃,历史可追溯,默认不允许新增引用。 | `deprecated` | 已弃用,历史可追溯,默认不允许新增引用 | 否 |

#### 9.3.2 状态转换图: MethodContent 生命周期

```text

        |
        v
LifecycleState::Draft
        |
        | MethodContent.submit_for_review(ActorContext actor, Timestamp now)
        v
LifecycleState::InReview
        |
        | MethodContent.publish(ApprovedGateRef gate_ref, ContentVersion version, CanonicalFingerprint fingerprint, ActorContext actor, Timestamp now)
        v

     |              |
```

## 10. 数据持久化、事务与一致性契约

### 10.1 数据分层与所有权图

#### 数据所有权图: 真相、可靠记录、投影与外部引用

```text
[Command / Inbound Event / Operations Job]
        |
        v
[UnitOfWork transaction]
        |
        +-- write model
        |     method_contents
        |     method_content_references
        |     method_content_versions
        |     supersede_links
        |
        +-- append-only / audit
        |     lifecycle_history_entries
        |     audit_records
        |
        +-- reliable records
        |     outbox_events
        |     idempotency_records
        |
        +-- sync metadata
              definition_snapshots

[Async / recoverable side]
        |
        +-- projection
        |     content_summary_projection
        |     definition_trace_projection
        |
        +-- operations
              projection_checkpoints
              inbound_dead_letters
              job_runs

[External refs only]
        |
        +-- governance gate ref
        +-- object storage blob ref
        +-- artifact / actor / downstream refs
```

关键说明:

- `write model`、append-only、outbox、idempotency、snapshot metadata 是本仓可写真相或可靠记录。
- projection / checkpoint / job run 是可重建或运维数据,不得反写 write model。
- governance、object storage、artifact、actor、downstream 只保存 ref,不建立跨仓数据库外键。

### 10.5 一致性策略表

| 主题 | 策略 | 恢复方式 |
|---|---|---|
| write model | 本地强一致;Command 通过 `UnitOfWork` 同事务写入 | 事务失败整体回滚 |
| lifecycle history / audit | 与业务状态变化同事务追加 | append 失败时 P0 command 整体失败 |
| snapshot metadata | publish / supersede 成功时必须同事务保存 metadata | metadata 写失败阻断 publish |
| snapshot payload | object storage 保存 payload,DB 保存 ref | payload 写失败阻断 publish;DB commit 失败后的 orphan blob 可清理或忽略 |
| outbox | 与业务变更同事务写 pending event | relay 重试 / dead-letter / replay |
| bus publish | 事务外最终一致 | `OutboxRelayWorker` 重试;不回滚 truth |
| projection | 最终一致、可重建 | `RebuildReadModels` 从 write model / outbox 重建 |
| downstream sync | 最终一致 | downstream replay / snapshot resync |
| query | 只读,不修复数据 | 返回 not found / stale / unavailable,由 command 或 operations job 修复 |
| idempotency | `(scope,idempotency_key)` 唯一,request_hash 校验 | 同 key 同 hash 返回既有结果;不同 hash 返回冲突 |
| optimistic lock | `method_contents.revision` 控制并发修改 | `REVISION_CONFLICT`,调用方重新读取后重试 |
| job checkpoint | 成功后推进,失败不跳跃 | resume 从 last successful cursor 继续 |

### 10.6 数据设计红线

| 红线 | 说明 |
|---|---|
| 不保存下游 Use truth | process instance、work item、identity member profile 不属于本仓 |
| 不用 projection 反写 truth | projection 只能从 write model / outbox 重建 |
| 不允许 write model 提交但 outbox 缺失 | publish/deprecate/retire/supersede 必须同事务写 outbox |
| 不把 bus publish 放入 command 事务 | 外部依赖失败不能污染本地强一致提交 |
| 不绕过 revision 保存 MethodContent | 修改已有 content 必须校验 expected_revision 或加锁 |
| 不用跨仓数据库外键 | governance / artifact / identity / object storage 只能保存 ref |
| 不在 repository 实现状态机 | 状态迁移由 domain object / application service 决定 |
| 不在 query 中写库修复 | Query 只读,恢复走 Operations Job 或 Command |

## 11. 错误模型、异常分支与恢复口径

### 11.1 内部错误模型

```rust
/// method-library 统一错误类型。
///
/// 该类型必须能映射到 HTTP / RPC / Event / Job 失败语义,并保留可恢复性信息。
pub enum MethodLibraryError {
    /// 协议层错误,承载 HTTP/RPC path、body、header 或请求格式解析失败。
    Protocol(ProtocolError),

    /// 输入校验错误,承载字段、payload、schema 或命令参数不满足契约的失败。
    Validation(ValidationError),

    /// 边界违规错误,承载 Method truth 混入 Use truth 或跨仓事实污染等边界问题。
    Boundary(BoundaryError),

    /// 生命周期错误,承载非法状态迁移或当前状态不允许执行目标操作的失败。
    Lifecycle(LifecycleError),

    /// 定义引用错误,承载引用不存在、引用类型不允许或引用版本不满足发布要求的失败。
    Reference(ReferenceError),

    /// 治理门禁错误,承载 approved gate 缺失、无效、过期或与目标内容不匹配的失败。
    Governance(GovernanceError),

    /// 并发控制错误,承载 revision 冲突、锁冲突或并发写入导致的一致性失败。
    Concurrency(ConcurrencyError),

    /// 幂等处理错误,承载 idempotency key 缺失、请求 hash 冲突或幂等状态不一致。
    Idempotency(IdempotencyError),

    /// 快照错误,承载 definition snapshot 生成、读取、校验或对象存储引用失败。
    Snapshot(SnapshotError),

    /// 指纹错误,承载 canonical fingerprint 计算、比对或持久化值不一致的失败。
    Fingerprint(FingerprintError),

    /// Outbox 错误,承载事件追加、claim、发布确认、重试或 dead-letter 状态失败。
    Outbox(OutboxError),

    /// 投影错误,承载 read model 更新、checkpoint 推进或 projection rebuild 失败。
    Projection(ProjectionError),

    /// 运维作业错误,承载 seed、replay、recalculate 或 rebuild job 的启动和执行失败。
    Job(JobError),

    /// 外部依赖错误,承载 governance、L0-bus、object storage 等外部端口调用失败。
    Dependency(DependencyError),

    /// 持久化错误,承载数据库事务、repository 读写或存储层不可用的失败。
    Persistence(PersistenceError),
}
```

错误必须携带 `code`、`retryable`、`target`、`details`、`trace_id` 或等价结构。`message` 面向开发 / 运维,不是唯一判断依据。

| `OUTBOX_EVENT_INVALID` | `application::sync_services` | outbox payload 不可发布 | 需人工 | dead-letter |
| `PROJECTION_NOT_READY` / `STALE_PROJECTION` | `application::query_services` | 投影未准备或落后 | 是 | HTTP 503 or stale marker |
| `PROJECTION_UPDATE_FAILED` | `application::operations_services` | rebuild/upsert projection 失败 | 是 | Job `Failed` |
| `CHECKPOINT_CONFLICT` | `application::operations_services` | 多 worker 推进同一 checkpoint | 是 | Job retry / skip |
| `JOB_REQUEST_INVALID` | `application::operations_services` | job 参数、scope、dry_run 写入非法 | 否 | HTTP 400 |
| `JOB_STATUS_CONFLICT` | `application::operations_services` | job_run 状态非法推进 | 否 | HTTP 409 |
| `JOB_DRY_RUN_WRITE_FORBIDDEN` | `application::operations_services` | dry_run 试图写 truth/checkpoint | 否 | HTTP 409 |
| `PERSISTENCE_UNAVAILABLE` / `TRANSACTION_COMMIT_FAILED` | `infra::persistence` | DB 不可用或提交失败 | 是 | HTTP 503 |
| `P1_FEATURE_DISABLED` | `application` / feature flag | P1 endpoint 未启用 | 否 | HTTP 404 |

### 11.3 异常分支处理表

| 场景 | 检测位置 | 处理方式 | 是否写审计 / 事件 |
|---|---|---|---|
| DTO / Gateway headers 缺失 | API handler | 返回 400,不进入 application service | 不写业务 audit;写 access log / metric |
| command 缺幂等键 | API handler / application service | 返回 `IDEMPOTENCY_KEY_REQUIRED` | 不写业务 audit |
| payload/kind 不匹配 | `MethodContent::create_draft` / validation service | 回滚事务,返回 422 | 不写 lifecycle history/outbox |
| boundary violation | `DefinitionUseBoundaryGuard` | 回滚事务,返回 422 | 不写 truth/outbox |
| content not found | repository / query service | 返回 404 | Query 不写 audit;Command 可写失败 log |
| revision conflict | repository save | 回滚事务,返回 412 | 不写 lifecycle history/outbox |
| lifecycle illegal transition | domain lifecycle method | 回滚事务,返回 409 | 不写 lifecycle history/outbox |
| gate required / invalid | `PublishGovernanceService` | publish 不提交,返回 424 | 可写失败 audit/log,不写 outbox |
| governance unavailable | `GovernancePort` | publish 不提交,返回 503 | 可写 failure metric,不写 outbox |
| snapshot payload write failed | `ObjectStoragePort` | publish 不提交,返回 503/500 | 不写 outbox;orphan blob 后续清理 |
| outbox append failed | `OutboxRepository.append` | 回滚业务事务 | 不写 published truth |

| bus publish failed | `BusPublisherPort.publish` | 已提交 truth 不回滚;mark retryable failure | 写 outbox failure status / metric |
| inbound event malformed | event consumer | 不改 truth,写 dead-letter | 写 inbound dead-letter |
| job dry_run 写 truth | job service guard | 阻断,返回 `JOB_DRY_RUN_WRITE_FORBIDDEN` | 写 job failure,不写 truth |

### 11.4 恢复口径

| 错误 / 场景 | 恢复责任方 | 恢复方式 | 是否自动 |
|---|---|---|---|
| validation / payload / boundary | 调用方 / 方法作者 | 修正请求内容后重新提交 | 否 |
| lifecycle illegal | 调用方 / maintainer | 读取当前状态,选择合法 Command | 否 |
| revision conflict | 调用方 | 重新读取最新 revision 后重试 | 否 |
| idempotency same key different hash | 调用方 | 使用新的 idempotency key | 否 |
| gate missing / invalid | maintainer / governance | 申请或更新 approved gate | 否 |
| governance unavailable | 平台 / 调用方 | 等外部依赖恢复后重试 | 可按调用方策略 |
| object storage unavailable | 平台运维 | 修复 storage 后重试 publish/export | 可重试 |
| bus publish failed | worker / operations | outbox retry,超过阈值 dead-letter | 自动优先 |
| outbox dead-letter | operations | 修复 payload/依赖后 replay | 人工介入 |
| downstream missed event | downstream / operations | `ReplayDefinitionEvents` 或 snapshot resync | 可自动触发 |
| fingerprint mismatch | maintainer / operations | `RecalculateFingerprint(dry_run=true)` 形成报告,再决定 resync 或修复 | 人工确认 |
| projection stale/rebuild failed | operations | `RebuildReadModels` 从 write model / outbox 重建 | 可自动或人工 |
| persistence unavailable | platform | 等 DB 恢复后重试未提交请求 | 可重试 |

### 11.5 错误处理红线

| 红线 | 说明 |
|---|---|
| 不允许捕获异常后返回成功 | 除非已有明确幂等成功结果 |
| 不允许 validation / boundary 失败后留下半条 MethodContent | 失败必须回滚 |
| 不允许无 gate 发布或先发布后补 gate | gate 是 publish 前置条件 |
| 不允许 snapshot 失败后生成 published snapshot_ref | snapshot 必须可读取或 publish 失败 |
| 不允许 bus 失败回滚已提交 truth | 通过 outbox retry / replay 恢复 |
| 不允许 replay 创造新的业务 event_id | replay 必须复用原 event_id |
| 不允许 fingerprint mismatch 自动改 published fingerprint | 必须先 dry_run 报告和治理确认 |
| 不允许 projection rebuild 反写 write model | projection 非 truth |
| 不允许 Query 为了恢复数据而写库 | 恢复走 Command 或 Operations Job |

## 12. 并发、幂等与重入保护

### 12.1 三层保护模型

#### 保护模型图: 幂等、并发与 Worker 重入

```text
Client / Worker / Event Source
        |
        v
[Request Idempotency]
  - x-idempotency-key + request_hash
  - source event_id + payload_hash
  - job scope_hash
        |
        v
[Resource Concurrency]
  - MethodContent.revision
  - row lock for publish / retire / supersede
  - unique(content_family_id, version)
  - unique(old_content_id) for supersede link
        |
        v
[Worker Reentry Protection]
  - outbox status claim + lease
  - checkpoint compare-and-swap
  - job_run status transition
  - dry_run write guard
```

关键说明:

- Request idempotency 防止同一请求或 job 被重复执行。
- Resource concurrency 防止同一 MethodContent、版本或替代链被并发破坏。
- Worker reentry protection 防止 relay / replay / rebuild 在崩溃恢复后重复推进。

### 12.2 并发场景表

| 场景 | 冲突资源 | 控制方式 | 失败错误 |
|---|---|---|---|
| 两个 `UpdateMethodContentDraft` 同时更新同一 draft | `method_contents.content_id` / `revision` | `expected_revision` + repository 乐观锁 | `REVISION_CONFLICT` |
| `UpdateMethodContentDraft` 与 `SubmitMethodContentForReview` 并发 | 同一 lifecycle / revision | `get_for_update` 或 save revision check + lifecycle guard | `REVISION_CONFLICT` 或 `LIFECYCLE_TRANSITION_NOT_ALLOWED` |
| `PublishMethodContent` 与 draft 更新 / submit 并发 | 同一 lifecycle / revision | 写路径锁定 aggregate + expected_revision | `REVISION_CONFLICT` / `LIFECYCLE_TRANSITION_NOT_ALLOWED` |
| 两个 `PublishMethodContent` 使用同一 `content_family_id + version` | `method_content_versions` 唯一键 | unique `(content_family_id, version)` | `CONTENT_VERSION_CONFLICT` |
| `DeprecateMethodContent` 与 `RetireMethodContent` 并发 | 同一 lifecycle / revision | 写路径锁定 + revision check | `REVISION_CONFLICT` 或 `LIFECYCLE_TRANSITION_NOT_ALLOWED` |
| 两个 `SupersedeMethodContent` 替代同一 old content | `old_content_id` / `supersede_links.old_content_id` | old content lock + unique old_content_id | `SUPERSEDE_CONFLICT` / `REVISION_CONFLICT` |
| 多个 outbox relay worker claim 同一 event | `outbox_events.event_id` / `status` | status compare-and-swap + worker lease | `OUTBOX_STATUS_CONFLICT` |
| 多个 replay job 推进同一 checkpoint | `projection_checkpoints.checkpoint_name` | checkpoint compare-and-swap,只允许单调推进 | `CHECKPOINT_CONFLICT` |
| seed job 重复创建同一资产版本 | seed asset identity / version unique | seed scope hash + content family/version unique | `CONTENT_VERSION_CONFLICT` 或幂等返回 |

### 12.3 幂等键表

| 接口 / Job / Event | 幂等键 | 重复请求处理 |
|---|---|---|
| P0 Command 通用 | `IdempotencyScope(command_name + target_id_or_family) + x-idempotency-key + request_hash` | 同 key 同 hash 成功则返回既有 `ResultRef`;processing 返回 `IDEMPOTENCY_STATUS_CONFLICT`;同 key 不同 hash 返回 `IDEMPOTENCY_CONFLICT` |
| `CreateMethodContentDraft` | `command_name + content_family_id_or_client_request_id + x-idempotency-key + request_hash` | 不重复创建 draft;返回既有 `content_id` |
| `UpdateMethodContentDraft` | `command_name + content_id + x-idempotency-key + request_hash` | 不重复 bump revision;返回既有 result |
| `PublishMethodContent` | `command_name + content_id + version + x-idempotency-key + request_hash` | 不重复写 version / snapshot / outbox |
| `SupersedeMethodContent` | `command_name + old_content_id + new_content_id + new_version + x-idempotency-key + request_hash` | 不重复创建 supersede link、version、snapshot 和 outbox |
| Query | 无 | 只读重复调用,不写幂等记录 |
| Outbound Event relay | `outbox_event_id / event_id` | 已 published 则跳过;retry 复用原 event_id |
| Inbound governance event | `source_module + external_event_id + payload_hash` | 同 event_id 同 hash ack / skip;同 event_id 不同 hash 写 dead-letter 或冲突 |
| Operations Job | `job_name + scope_hash + x-idempotency-key` | 同 key 同 scope 返回既有 job result;dry_run 不推进正式 checkpoint |

### 12.4 重入保护表

| 场景 | 重入来源 | 保护方式 | 恢复方式 |
|---|---|---|---|
| 客户端超时后重试 Command | HTTP/RPC timeout,调用方不确定结果 | `IdempotencyRepository.try_begin(...)` + `request_hash` + result_ref | 同 key 同 hash 返回既有结果 |
| Command 执行中重复提交 | 同 key 同 hash 仍为 `Processing` | `IdempotencyStatus::Processing` 阻止第二次进入业务写入 | 返回 `IDEMPOTENCY_STATUS_CONFLICT` 或处理中响应 |
| Command 失败后原 key 重试 | `IdempotencyStatus::Failed` | failed 作为终态 | 调用方修正原因后使用新 idempotency key |
| outbox worker crash 于 `Publishing` | worker 中断或 bus ack 未返回 | `claim_pending` 使用 status CAS + `lease_until` | lease 过期后其他 worker 可重新 claim |
| replay job 重跑 | 下游反复请求补偿或 job 中断后 resume | checkpoint CAS + 原 event_id replay | 从最新 checkpoint 继续 |
| rebuild projection 重跑 | scheduler 重复触发或人工重试 | projection upsert by key + checkpoint CAS | 可覆盖 projection,不改 truth |
| seed job 重跑 | bootstrap 重复执行 | job scope 幂等 + deterministic child command key + version unique | 已存在资产跳过或返回既有结果 |
| dry_run job 重跑 | 人工反复演练 | dry_run scope 独立;禁止写 truth/outbox/checkpoint | 返回 report |

### 12.5 Repository / Port 并发契约补充

| 契约 | 函数签名 | 作用 |
|---|---|---|
| 幂等开始 | `IdempotencyRepository.try_begin(UnitOfWorkTx tx, IdempotencyKey key, IdempotencyScope scope, RequestHash request_hash)` -> `Result<IdempotencyBeginResult, MethodLibraryError>` | 创建 processing 记录或返回既有状态;同 key 不同 hash 返回冲突 |
| 幂等完成 | `IdempotencyRepository.mark_completed(UnitOfWorkTx tx, IdempotencyKey key, IdempotencyScope scope, ResultRef response_ref, Timestamp now)` -> `Result<(), MethodLibraryError>` | 与业务写入同事务保存结果引用 |
| outbox claim | `OutboxRepository.claim_pending(BatchSize limit, WorkerId worker_id, Timestamp now, LeaseDuration lease)` -> `Result<Vec<OutboxEvent>, MethodLibraryError>` | 原子 claim pending / retryable_due / expired publishing event |
| outbox 发布成功 | `OutboxRepository.mark_published(OutboxEventId event_id, WorkerId worker_id, Timestamp now)` -> `Result<(), MethodLibraryError>` | 只有持有 lease 的 worker 可标记成功 |
| checkpoint 推进 | `ProjectionCheckpointRepository.advance_if_current(CheckpointName name, Option<OutboxEventId> expected_cursor, OutboxEventId next_cursor, Timestamp now)` -> `Result<(), MethodLibraryError>` | CAS 推进 checkpoint,防止并发跳跃 |
| job 开始 | `JobRunRepository.start_once(UnitOfWorkTx tx, JobName job_name, JobScopeHash scope_hash, IdempotencyKey key, Timestamp now)` -> `Result<JobRunStartResult, MethodLibraryError>` | 防止同 job scope 被同 key 重复启动 |

## 14. 可观测性与审计埋点契约

### 14.1 三类记录关系

#### 观测关系图: Log、Metric 与 AuditRecord

```text
[Command / Query / Event / Job]
        |
        +--> Structured Log
        |      - request_id / trace_id
        |      - operation / target / error_code
        |      - duration / dependency / retryable
        |
        +--> Metrics
        |      - count / latency / gauge
        |      - low-cardinality labels
        |
        +--> AuditRecord
               - only business facts
               - lifecycle / version / fingerprint / gate / outbox refs
               - append-only, queryable by trace
```

关键说明:

- structured log 和 metrics 用于运行观测,默认不阻断业务主线。
- `AuditRecord` 只记录业务事实,必须 append-only 且可按 trace 追溯。
- 三类记录都不得保存完整 payload、secret 或 raw idempotency key。

### 14.2 日志埋点表

| 位置 | 日志级别 | 字段 | 目的 |
|---|---|---|---|
| API handler 收到请求 | `info` | `request_id`、`trace_id`、`operation`、`method`、`path_template`、`actor_ref`、`idempotency_key_hash` | 建立入口访问日志,不记录完整 body |
| Gateway context 缺失或不可信 | `warn` | `request_id`、`trace_id`、`operation`、`error_code`、`header_presence` | 排查 gateway / ingress 配置错误 |
| Command 开始处理 | `info` | `request_id`、`trace_id`、`operation`、`content_id`、`kind`、`expected_revision`、`actor_ref` | 追踪写路径入口 |
| Command 成功提交 | `info` | `request_id`、`trace_id`、`operation`、`content_id`、`kind`、`from_state`、`to_state`、`new_revision`、`duration_ms` | 追踪写路径成功和状态变化 |
| Command 业务校验失败 | `warn` | `request_id`、`trace_id`、`operation`、`target_ref`、`error_code`、`retryable=false` | 排查 validation / boundary / lifecycle 失败 |
| Command 本地事务失败 | `error` | `request_id`、`trace_id`、`operation`、`error_code`、`tx_phase` | 排查 DB / commit / repository 失败 |
| Query 成功 | `info` | `request_id`、`trace_id`、`operation`、`read_mode`、`page_size`、`consistency`、`duration_ms` | 观察查询性能和一致性状态 |
| Outbox relay claim | `info` | `trace_id`、`worker_id`、`batch_size`、`claimed_count`、`lease_timeout_ms` | 观察 relay worker 工作量 |
| Outbox publish 失败 | `warn` / `error` | `trace_id`、`event_id`、`event_type`、`topic`、`attempt_count`、`error_code`、`next_retry_at` | 排查 bus 故障和重试 |
| Outbox dead-letter | `error` | `trace_id`、`event_id`、`event_type`、`failure_reason`、`attempt_count` | 触发人工恢复入口 |
| Operations Job 完成 | `info` | `trace_id`、`job_name`、`job_run_id`、`status`、`processed_count`、`failed_count`、`duration_ms` | 记录 job 结果 |

### 14.3 指标埋点表

| 完整环境变量 / secret / TLS / retry 曲线 | 影响部署配置 | 配置设计 / SRE | 留 `04-配置设计.md` |
| 完整测试 fixture / CI / 覆盖率目标 | 影响测试执行 | QA / 测试方案负责人 | 留 `05-测试方案.md` |

### 17.4 未确认前默认原则

| 原则 | 默认处理 |
|---|---|
| 不扩大 P0 | 未确认事项不得进入 P0 必实现 |
| 不保存 Use truth | WorkItem、ProcessInstance、QualificationProfile、QualificationBinding 等对象不得入 method-library |
| 不绕过发布治理 | publish / supersede 必须校验 gate、version、fingerprint、snapshot、audit、outbox |
| 不绕过 outbox | Command 不直接发布 L0-bus |
| 不让 Query 写库 | Query 不写 audit、outbox、idempotency 或修复数据 |
| 不把失败写成业务事实 | 失败请求写 log / metric,失败 audit 如启用必须标 `result=failed` |
| 不硬编码运维参数 | timeout、retry、topic、secret、threshold 留配置 / 运维文档 |

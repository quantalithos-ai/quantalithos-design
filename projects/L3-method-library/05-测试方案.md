### 1.2 本方案不重新回答

- 不重新定义为什么需要 `L3-method-library`。
- 不重新定义 7 类 P0 MethodContent。
- 不重新设计 API / Event / Job schema。
- 不重新划分 P0 / P1。
- 不把 P1 `MethodPlugin` / `MethodConfiguration` 作为 P0 放行前置。
- 不测试下游仓自身的完整实现,只测试 method-library 对下游提供的 definition event / snapshot / query / trace 入口。

### 1.3 本方案必须验证

- 7 类 P0 MethodContent 均可进入草稿、评审、发布、废弃、退役和替代链路。
- 发布链必须生成 version、fingerprint、snapshot、audit、outbox。
- Definition / Use 边界不可被接口、数据模型或 payload 绕过。
- 下游通过 event 或 snapshot 可建立本地定义索引。
- Query / ResolveViewProfile / Trace 必须只读。
- Outbox relay、replay、rebuild、recalculate 具备恢复测试切口。

## 4. 测试策略与分层

### 4.1 测试分层图

#### 测试分层图: 从领域规则到跨仓契约

```text
[Unit Tests]
  | domain / policy / value object / DTO
  v
[Application Service Tests]
  | fake ports / deterministic clock / id / hasher
  v
[Persistence + Adapter Integration Tests]
  | PostgreSQL / outbox / projection / object storage stub / bus stub
  v
[API + Worker Contract Tests]
  | HTTP JSON / gateway headers / worker job / error mapping
  v
[Cross-repo Contract / E2E Tests]
  | fake downstream index / event replay / snapshot resync
```

关键说明：
- 单元测试负责规则正确性,不能替代事务和 adapter 测试。
- 应用服务测试必须验证调用顺序和副作用集合。
- 跨仓测试只验证 method-library 输出契约,不要求下游完整业务实现。

### 4.2 分层策略表

| 层级 | 目标 | 必测内容 | 失败处理 |
|---|---|---|---|
| Unit | 快速验证领域规则 | lifecycle、payload kind、boundary guard、reference policy、fingerprint canonical | 阻断提交 |
| Application | 验证用例编排 | Command / Query / Job service, fake repository / fake outbox / fake audit | 阻断提交 |
| Persistence | 验证真实存储约束 | UnitOfWork、unique key、revision、outbox claim、checkpoint CAS | 阻断合并 |
| API Contract | 验证协议稳定 | headers、JSON、status code、ErrorResponse、idempotency key | 阻断合并 |
| Worker | 验证异步恢复 | outbox relay、replay、rebuild、recalculate、dead-letter | 阻断发布 |
| Cross-repo Contract | 验证下游消费契约 | identity / capability-hub / process / artifact / governance / UI fake consumer | 阻断 P0 验收 |
| Nonfunctional | 验证性能和可靠性 | GetContent、ResolveViewProfile、PublishContent、event propagation | 阻断放行或进入风险接受 |

## 11. 缺陷管理与复验规则

| 缺陷级别 | 定义 | 处理要求 | 复验范围 |
|---|---|---|---|
| S | 破坏定义真相、边界红线、发布一致性、outbox 可靠性、Query 只读或下游同步主链 | 阻断放行,必须修复 | 相关全链路 + 回归矩阵 |
| A | 主链可跑但幂等、replay、projection stale、ResolveViewProfile、seed、性能阈值不稳定 | 原则上修复后进入验收 | 对应套件 + 受影响接口 |
| B | 非关键摘要、报告展示、低频 operations 体验问题 | 可风险接受 | 定点复验 |

复验规则：

- 修复 lifecycle / publish / supersede 必须重跑 TC-CMD、TC-STATE、TC-TX、TC-IDEM。
- 修复 outbox / bus / replay 必须重跑 TC-EVT、TC-WRK、TC-JOB、TC-SYNC。
- 修复 query / projection 必须重跑 TC-QRY、TC-JOB-004。
- 修复 boundary guard 必须重跑 TC-DOM-004 和所有跨仓负向测试。

## 14. 回归策略与残余风险

### 14.1 回归策略

| 变更类型 | 必回归范围 |
|---|---|
| MethodContent / lifecycle / payload 变更 | TC-DOM、TC-CMD、TC-STATE |
| Publish / supersede / fingerprint 变更 | TC-CMD-004~010、TC-TX、TC-IDEM、TC-SYNC |
| Reference / boundary guard 变更 | TC-DOM-003~004、TC-BOUND、TC-SYNC |
| Query / projection / trace 变更 | TC-QRY、TC-JOB-004 |
| Outbox / bus / replay 变更 | TC-EVT、TC-WRK、TC-JOB-002 |
| Seed / operations job 变更 | TC-JOB、TC-IDEM、TC-STATE |
| Gateway / API / error mapper 变更 | API contract + negative tests |

### 14.2 残余风险

| 风险 | 影响 | 本方案处理 |
|---|---|---|
| `ResolveViewProfile` 无匹配时返回空视图还是错误码仍需实现前确认 | 影响 TC-QRY-005/006 断言 | 测试用例保留 no-match 分支,最终断言跟随实现前决策 |
| 已 retired 再 retire 的幂等语义仍需实现前确认 | 影响 lifecycle negative test | 测试必须固定一种结果,不可双语义通过 |
| governance gate 校验模式可能有远程 / 投影 / ref-only 分叉 | 影响 publish gate 集成测试 | 测试按配置矩阵覆盖至少一种正式 P0 模式 |
| 完整配置、secret、TLS、retry 曲线不在详细设计中固化 | 影响部署级测试 | 本方案只约束绑定点,部署测试由配置 / 运维文档补齐 |

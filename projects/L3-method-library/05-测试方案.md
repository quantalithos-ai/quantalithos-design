### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 method-library“能存内容”,而是系统验证 `L3-method-library` 是否真正满足“方法资产中心”的设计要求,尤其要证明以下几点成立:
- MethodContent 6 子类构成正式方法资产真相层
- `Definition ≠ Use` 成立,method-library 不会退化成 process / identity / governance / UI 的运行时真相层
- `RoleDefinition ≠ RoleCatalogEntry`、`ProcessTemplateDef ≠ ProcessInstance`、`ViewProfile ≠ UI 本地规则`、`AIPolicyDef ≠ governance enforce runtime` 等核心边界成立
- publish / supersede / fingerprint / drift 构成完整版本治理主线
- Plugin / Configuration 只做打包与组装,不复制正文、不冒充交易或运行时状态
- fingerprint_changed / source_drift / replay 链成立,下游能知道何时发生漂移
- ResolveViewProfile / content query / package distribution 都只消费正式已发布资产,且不反写真相

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 方法内容定义部分 | 资产真相对象 | P0 | MethodContent、RoleDefinition、TaskDefinition、WorkProductDefinition、ProcessTemplateDef、ViewProfile、AIPolicyDef |
| 方法版本与发布治理部分 | 治理对象 | P0 | ContentVersion、PublishGateRef、Fingerprint、SupersedeLink、ContentLifecycleState |
| 资产打包与配置组装部分 | 组装对象 | P0 | MethodPlugin、MethodPluginItem、MethodConfiguration、VariabilityApplication、EffectiveContentSet |
| 下游同步与漂移防护部分 | 同步对象 | P0 | FingerprintChangedSignal、SourceDriftRecord、DownstreamSyncCheckpoint |
| 查询解析与分发出口部分 | 读取/分发对象 | P0 | ViewProfileResolveRequest、ViewProfileResolveResult、ContentSummaryView、PackageBlobRef |
| process / identity / governance / UI / marketplace 真相本体 | 非范围 | P2 | 只验 method-library 如何向它们提供定义与同步信号,不验下游仓全部实现 |
| marketplace 交易 / 购买 / 计费流程 | 非范围 | P2 | 只验 plugin 分发接缝,不验商业流程 |
| UI 渲染像素级行为 | 非范围 | P2 | 只验 ResolveViewProfile 输出,不验前端组件细节 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / policy owner | `content.validate_definition_boundary`、`gate_ref.validate_publishable`、`plugin.validate_dependency_dag`、`signal.validate_target_contract`、`result.validate_unique_resolution` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + storage + publisher + projection 联动 | backend / domain owner | `DraftContent`、`PublishContent`、`SupersedeContent`、`CreatePlugin`、`ActivateConfiguration`、`EmitFingerprintChanged`、`ResolveViewProfile` | 内容链、治理链、组装链、同步链同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | role_definition.published → identity、process_template.published → process、ai_policy.published → governance、view_profile.* → UI、plugin publish → marketplace | 输入输出语义一致 |
| 恢复专项测试 | 验证 fingerprint 丢失、source_drift、object storage 失败、下游同步失败等异常链 | architecture / QA | missing gate、direct published edit、drift detected、sync lag、blob write fail | 真相不丢失、错误被正确阻断或留证 |
| 投影一致性测试 | 验证 summary / plugin catalog / effective set / drift report 与真相一致 | backend / QA | summary rebuild、catalog rebuild、effective set rebuild、drift report rebuild | 投影只读且与真相一致 |
| 端到端主线测试 | 验证最小方法资产闭环 | QA / owner | draft → publish → fingerprint_changed → downstream sync；published content → plugin → configuration → resolve/query/distribution | 主干资产闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `Definition ≠ Use` | 方法资产不得混入下游运行时使用真相 | 单元 + 集成测试 | 是 | model review / negative flow |
| `RoleDefinition ≠ RoleCatalogEntry` | 角色定义发布后 identity 只形成索引,不复制正文 | 事件链 + 集成测试 | 是 | sync contract / payload compare |
| `ProcessTemplateDef ≠ ProcessInstance` | template 发布只同步定义,不形成执行实例 | 事件链测试 | 是 | process sync trace |
| `ViewProfile ≠ UI 本地规则` | resolve 结果必须来自权威定义而非 UI 本地规则 | 集成 + 投影一致性测试 | 是 | resolve compare / cache diff |
| `AIPolicyDef ≠ governance enforce runtime` | policy 发布只提供定义源,不直接执行业务裁决 | 事件链 + 集成测试 | 是 | governance sync log |
| published 内容不可直接修改 | published 后修改必须 supersede | 单元 + 集成测试 | 是 | version / history / negative flow |
| Plugin / Configuration 不复制正文 | plugin/config 只引用 content_id/fingerprint | 单元 + 集成测试 | 是 | plugin row / content diff |
| fingerprint_changed / source_drift 链成立 | drift 可识别、可留痕、可 replay | 集成 + 恢复专项测试 | 是 | drift report / replay log |
| ResolveViewProfile 唯一命中 | 多个 active profile 时必须报错 | 单元 + 集成测试 | 是 | resolve result / error snapshot |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local PG / fake object storage / fake bus / fake downstream consumers | debug logging / fingerprint visible / resolve cache enabled | 容易只测 happy path |
| test | CI / 集成测试 | deterministic content fixtures / fake identity-process-governance-UI-marketplace consumers / object storage stub | isolated content tables / fixed fingerprints / replay enabled | 下游消费样本覆盖不足 |
| staging | 端到端演练 | real-like PG / object storage / bus / downstream sync dry-run / UI resolve consumers | publish gate / drift alert / package distribution / replay evidence enabled | 多下游时序差异放大 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | DraftContent 成功创建正式方法资产草稿 | content_kind 合法 +字段完整 | DraftContent | 形成 draft 内容 |
| TC-002 | PublishContent 在 Gate 通过后成功发布 | content in_review + gate approved | PublishContent | state=published + fingerprint 生成 |
| TC-003 | published 内容不得直接修改 | content 已 published | 普通 Update 而非 Supersede | 返回 `CONTENT_SUPERSEDE_REQUIRED` |
| TC-004 | SupersedeContent 建立新旧版本链 | old content published + new draft ready | SupersedeContent | 新版本发布并形成 SupersedeLink |
| TC-005 | CreatePlugin 成功打包一组已发布内容 | selected contents published | CreatePlugin | MethodPlugin 创建成功 |
| TC-006 | plugin 依赖成环时拒绝发布 | plugin items 形成 cycle | VerifyPluginDag / PublishPlugin | 返回 `PLUGIN_DEPENDENCY_CYCLE` |
| TC-007 | ActivateConfiguration 成功解析有效内容集 | selected_plugins 合法 | ActivateConfiguration | configuration active + effective content set 生成 |
| TC-008 | active configuration 后禁止随意改 selected_plugins | configuration active | UpdateConfiguration | 返回冻结错误 |
| TC-009 | EmitFingerprintChanged 成功向下游发信号 | content published + target valid | EmitFingerprintChanged | checkpoint 写入 + signal 发布 |
| TC-010 | drift 检测失败时形成 SourceDriftRecord | downstream fingerprint mismatch | VerifyContentFingerprint | drift 记录落地 |
| TC-011 | ResolveViewProfile 成功唯一命中 | role/object/scope 存在唯一 active profile | ResolveViewProfile | 返回权威解析结果 |
| TC-012 | ResolveViewProfile 命中多个 active profile 时拒绝成功 | duplicate active profiles exist | ResolveViewProfile | 返回 `VIEW_PROFILE_AMBIGUOUS` |
| TC-013 | object storage 写失败时不得发布内容 | blob write fail | PublishContent | 保持 draft / publish 阻断 |
| TC-014 | downstream sync 失败时可 replay 且留证 | signal publish fail / consumer lag | EmitFingerprintChanged → replay | replay 成功或 drift 证据完整 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | published 内容被直接改写 / drift 不留证 / plugin 复制正文 / ViewProfile 解析越权 / 下游使用真相倒灌 method-library | 阻断放行,必须修复 |

| B | 非关键摘要视图、低优先级 blob 分发或报告展示异常 | 可带风险进入下一轮 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 MethodContent / publish / supersede,都必须回归版本治理与 fingerprint 主线
- 每次改动 RoleDefinition / ProcessTemplateDef / AIPolicyDef / ViewProfile,都必须回归对应下游同步链
- 每次改动 plugin / configuration,都必须回归 DAG、effective content set 与 active freeze 主线
- 每次改动 sync / drift,都必须回归 checkpoint、source_drift 与 replay 主线
- 每次改动 resolve / query / package,都必须回归 active-only、unique resolve、只读出口主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| ProcessTemplateDef 与 process 引擎映射后续细化 | 测试矩阵需扩充 | TL / 架构 |
| AIPolicyDef 与 governance DSL 对齐继续演进 | policy 测试需增加更多样本 | method-library / governance |
| Marketplace 商业化诉求增长 | plugin/package 边界测试需扩充 | Owner / TL |

## 4. 测试策略与分层

> 校准来源:

#### 测试分层图: L3-method-library P0 验证层级

```text
contract / domain / state
  -> service / flow / UoW
  -> fake runtime / controlled adapter
  -> entry / worker / job shell
  -> operations replay / report audit
  -> release representative smoke
```

关键说明:

- 高风险契约优先在 contract / domain / service 层发现,不全部推给 E2E。
- fake / controlled seam 是 P0 主路径;real-like selected-run 只作 P1 residual。
- release smoke 只代表送验前最小闭环,不得替代底层 suite 和 evidence。

| 层级 | 目标 | 主要 suite |
|---|---|---|
| Contract / domain | 验证 typed ref、DTO shell、truth invariant、state matrix。 | `contract-domain-fast` |
| Service / flow | 验证 command / query / consumer / job 编排、UoW、duplicate、no-write。 | `service-flow-fast` |
| Runtime / adapter | 验证 fake repository、controlled adapter、runtime assembly。 | `infra-runtime-fake` |
| Entry / worker / job | 验证 entry shell、runner envelope、safe response / report。 | `entry-worker-job` |
| Operations / replay | 验证 stored replay、checkpoint/report、partial failure、no truth repair。 | `operations-replay-core` |
| Cross-cutting | 验证 config、dependency、redaction、observability、report integrity。 | `config-redline`;`dependency-boundary`;`redaction-boundary`;`observability-boundary`;`report-generation-audit` |

## 7. 测试数据设计

> 校准来源:
> - `design-calibration/05_test_plan_step_07_test_data.md`
>
> 延伸阅读:

| 数据族 | 用途 | 约束 |
|---|---|---|
| definition / catalog fixture | truth owner、catalog、public shell、pollution guard。 | 使用 body-free / refs-only safe sample;不得引入旧材料为真相源。 |
| formalization / version / state fixture | formal state、version、change、illegal transition、idempotency。 | 使用 deterministic clock/id/hash;不得静默覆盖正式语义。 |

- 每个 fixture / seed 必须有可重复构造和清理边界。
- 测试数据不得携带真实 secret、endpoint body、provider response body 或完整敏感 ref。
- P1/P2 selected-run 数据不可回填为 P0 fixture。

| 专项 | P0 验证方向 | 禁止误用 |
|---|---|---|
| Redaction / body-free | log、trace、audit、report、artifact、diagnostic 均不得含 raw body、secret、provider response 或 full sensitive ref。 | 不用人工目测替代 redaction-boundary。 |
| Dependency boundary | 只允许正式依赖方向;non-core sibling compile dependency 必须阻断。 | 不把 runtime/event/replay 协作写成 compile dependency。 |
| Observability | metric label 低基数、trace/span body-free、audit refs-only、diagnostic not truth。 | 不让 observability 修复 truth 或成为 recovery source。 |
| Consistency / recovery | UoW、stored replay、checkpoint/report、commit unknown、partial failure。 | 不用 query/job hidden write 修复 truth。 |
| Performance sample / trend | 仅保留 duration/count/sample/trend。 | 不写无来源 P95/SLO/capacity pass/fail。 |
| Evidence integrity | artifact/report pair、no latest、no static evidence、failed suite evidence。 | 不用静态 JSON 或手写报告宣告 pass。 |

若后续要把性能阈值、真实产品容量或外部 SLA 硬化为验收项,必须在新版 `06-验收标准.md` 或后续基线中重新闭口。

## 11. 缺陷管理与复验规则

> 校准来源:
> - `design-calibration/05_test_plan_step_11_defects_retest.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”“stop-review”和“待确认事项”小节,了解缺陷分级、复验矩阵、风险接受和防回归规则。

| 级别 | 判定 | 处理 |
|---|---|---|
| S | 一票否决、P0 truth / boundary / security / evidence integrity 破坏,或 P0 阻断证据失真。 | 必须修复,不得风险接受,复跑相关 blocking suite / release check。 |
| A | P0 主线或 blocking suite 风险,未命中 S,但影响核心闭环可信证明。 | 修复或明确临时风险接受;release 前通常阻断。 |
| B | P1/P2、selected-run、文档可读性、非阻断报告体验或维护性问题。 | 可排期处理或风险接受,不得影响 P0 pass。 |
| R | 范围外、future、设计未闭口或 residual 风险。 | 记录 owner / 接受角色,若升级为 P0 必须回写前序 Step。 |

修复后复验至少覆盖:

- 原失败 `TC-ML-*`。
- same family representative。
- owning suite。
- 相关 redaction / dependency / report audit。
- 是否需要新增或扩展自动化防回归。

缺陷关闭证据必须能关联 failed run、fixed run、suite status、修复说明和复验结果方向;正式字段和值域留给 run-scoped artifact/report 设计。

## 12. 进入准则与退出准则

> 校准来源:

### 12.1 进入准则

| 准则 | 判定 |
|---|---|
| 当前 `00`~`04` 正式文档可读取且与 Step 1~14 中间产物一致。 | 必须满足 |

### 12.2 退出准则

| 准则 | 判定 |
|---|---|
| P0 blocking suite 均有可信 artifact/report pair。 | 必须满足 |

| S 级缺陷和 P0 evidence integrity 缺口均已关闭。 | 必须满足 |

## 14. 回归策略与残余风险

> 校准来源:
> - `design-calibration/05_test_plan_step_14_regression_risks.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“结构化中间产物”“回填草稿”“stop-review”和“待确认事项”小节,了解回归触发、全量 P0、residual 和转入 `06` 的事项。

### 14.1 回归触发

| 变更类型 | 最小回归集 | 全量回归触发条件 | 责任人 |
|---|---|---|---|
| requirement / BR / NFR / acceptance direction | 受影响 `TC-ML-*` family + traceability review + release representative + evidence index audit。 | P0 范围或红线语义改变。 | 设计负责人 + 测试负责人 |
| architecture / truth owner / Definition vs Use | `dependency-boundary` + affected contract/service suite + report audit。 | truth owner、data ownership、compile dependency 或相邻仓职责变化。 | 架构负责人 |
| object / protocol / state / flow | owning suite + adjacent suite + related redline audit。 | public schema、state matrix、UoW、idempotency、query no-write 或 no truth repair 变化。 | domain / application 负责人 |
| config / dependency / redaction / report | corresponding blocking audit + affected suite sample。 | config redline、dependency boundary、redaction 或 evidence integrity 变化。 | config / tooling / observability 负责人 |
| S 级缺陷修复或 source-missing stop 修复 | 原失败 TC + same family + owning suite + related redline check。 | 任一 P0 truth / redaction / dependency / evidence integrity 修复。 | 缺陷 owner + 测试负责人 |

全量 P0 回归至少包含 `contract-domain-fast`、`service-flow-fast`、`infra-runtime-fake`、`entry-worker-job`、`operations-replay-core`、`config-redline`、`dependency-boundary`、`redaction-boundary`、`observability-boundary`、`report-generation-audit`、`release-main-smoke` 和 release audit checks。

### 14.2 残余风险

| 风险 | 未覆盖原因 | 缓解方式 | 接受人 |
|---|---|---|---|
| P1 real-like selected-run 不作为 P0 阻断 | 真实产品、环境和数据未锁定。 | P0 使用 fake / controlled seam;selected-run 不可用进入 residual。 | 验收负责人待确认 |
| durable storage / bus / external resolver 产品行为未覆盖 | 产品选型和部署基线未锁定。 | P0 证明 port / repository / seam 语义;产品绑定后补 P1/P2。 | 架构负责人待确认 |
| production-like capacity / long-run 未覆盖 | 无正式容量模型、负载模型和部署基线。 | 只保留 sample/trend;容量基线后补验收 gate。 | 架构负责人待确认 |
| performance hard threshold 未定义 | 当前只有 sample/trend。 | 若要 pass/fail,新版 `06` 定义环境、负载和阈值。 | 验收负责人待确认 |
| advanced package / marketplace / dashboard 未覆盖 | 当前为 peripheral / future 能力。 | 不阻断 core P0,后续产品基线另行验收。 | 产品负责人待确认 |
| evidence retention period 未固定 | 属于验收 / 运维归档策略。 | 新版 `06` 或运维标准定义保留周期。 | 验收负责人待确认 |

### 14.3 不可风险接受

以下项不得风险接受: truth 不归属本仓、下游替代定义、正式版本语义静默覆盖、source-missing stop 被私补、query/job/observability 反写真相、raw body/secret 泄露、non-core sibling compile dependency、artifact/report pairing 缺失、`latest` 正式引用、static evidence 伪 pass、P0 profile unavailable 却标记 passed。

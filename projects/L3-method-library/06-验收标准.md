### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L3-method-library` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L3-method-library` 是方法资产中心,不是执行仓、文档仓或 UI 规则临时仓
- MethodContent 6 子类构成正式方法资产真相层
- `Definition ≠ Use` 必须成立,method-library 不得退化成 process / identity / governance / UI 的运行时真相层
- `RoleDefinition ≠ RoleCatalogEntry`、`ProcessTemplateDef ≠ ProcessInstance`、`ViewProfile ≠ UI 本地规则`、`AIPolicyDef ≠ governance enforce runtime` 等核心边界必须成立
- publish / supersede / fingerprint / drift 构成完整版本治理主线
- Plugin / Configuration 只做打包与组装,不复制正文、不冒充交易或运行时状态
- fingerprint_changed / source_drift / replay 链必须成立,下游能知道何时发生漂移
- ResolveViewProfile / content query / package distribution 都只能消费正式已发布资产,且不反写真相

因此,本次验收的目的不是笼统判断“能不能存方法资产”,而是判断 method-library 的资产定义链、发布治理链、组装分发链、同步漂移链与查询解析链是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 方法内容定义部分 | 是 | MethodContent、RoleDefinition、TaskDefinition、WorkProductDefinition、ProcessTemplateDef、ViewProfile、AIPolicyDef |
| 方法版本与发布治理部分 | 是 | ContentVersion、PublishGateRef、Fingerprint、SupersedeLink、ContentLifecycleState |
| 资产打包与配置组装部分 | 是 | MethodPlugin、MethodPluginItem、MethodConfiguration、VariabilityApplication、EffectiveContentSet |
| 下游同步与漂移防护部分 | 是 | FingerprintChangedSignal、SourceDriftRecord、DownstreamSyncCheckpoint |
| 查询解析与分发出口部分 | 是 | ViewProfileResolveRequest、ViewProfileResolveResult、ContentSummaryView、PackageBlobRef |
| process / identity / governance / UI / marketplace 真相本体 | 否 | 只验 method-library 如何向它们提供定义与同步信号,不验下游仓全部实现 |
| marketplace 交易 / 购买 / 计费流程 | 否 | 只验 plugin 分发接缝,不验商业流程 |
| UI 渲染像素级行为 | 否 | 只验 ResolveViewProfile 输出,不验前端组件细节 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| DraftContent | 合法输入时必须形成正式 draft 方法资产 | API 响应 / DB 记录 / trace | [] |
| 方法内容定义边界 | 内容对象只承载定义语义,不得混入 process / identity / governance / UI 的使用真相 | model review / negative flow / payload compare | [] |
| PublishContent | Gate 通过后必须形成正式 published 内容并生成 fingerprint | publish log / content row / fingerprint record | [] |
| Publish 边界 | published 内容核心字段不得被直接修改,只能 supersede | version history / negative test | [] |
| SupersedeContent | 新旧版本必须形成可追溯 supersede 链 | supersede history / compare report | [] |
| CreatePlugin | 只能打包已发布内容,并通过依赖 DAG 校验 | plugin row / DAG report | [] |
| ActivateConfiguration | 只能在 selected_plugins 与 variability 合法时生成 active configuration 与 effective content set | configuration row / effective set snapshot | [] |
| Configuration 边界 | active 后不得随意修改 selected_plugins 或让运行态反向成为配置真相 | negative flow / model review | [] |
| EmitFingerprintChanged | 发布后必须形成 checkpoint 并发出正式 fingerprint 变化信号 | signal log / checkpoint row | [] |
| drift 边界 | 下游不得靠本地猜测 drift,必须能回指 method-library 的权威 fingerprint 与 source_drift 记录 | drift report / replay evidence | [] |
| ResolveViewProfile | role + object_kind + scope 合法且唯一时,必须返回权威 ViewProfile 解析结果 | resolve result / compare report | [] |
| ResolveViewProfile 边界 | 命中多个 active profile 或读到未发布内容时不得返回成功 | negative flow / error snapshot | [] |
| Package / blob 分发出口 | guidance / example / package blob 只作为分发引用输出,不得混入交易状态 | blob ref / distribution log | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | published 内容被直接改写 / drift 不留证 / plugin 复制正文 / ViewProfile 解析越权 / 下游使用真相倒灌 method-library |
| A | 视情况 | 主线可跑但 sync lag、resolve 规则、configuration freeze 或 replay 语义不稳 |
| B | 可带着走 | 非关键摘要视图、低优先级 blob 分发或报告展示异常 |

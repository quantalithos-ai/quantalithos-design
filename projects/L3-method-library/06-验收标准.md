## 2. 验收目标与范围

### 2.1 验收目标

| 目标编号 | 验收目标 | 裁决口径 |
|---|---|---|
| AG-001 | 7 类 P0 MethodContent 定义资产可创建、评审、发布、废弃、退役、替代 | 任一 P0 kind 缺失即不通过 |
| AG-002 | 发布链可审计、可追溯、可恢复 | state、version、fingerprint、snapshot、audit、outbox、idempotency 任一缺失即不通过 |
| AG-003 | Definition / Use 边界成立 | 出现下游 Use truth 写入路径即不通过 |
| AG-004 | 下游同步契约成立 | identity / process / capability-hub / artifact / governance / UI fake consumer 至少通过 event 或 snapshot 建立索引 |
| AG-005 | Query / Resolve / Trace 只读且可消费 | Query 写 truth 或偷偷修复数据即不通过 |
| AG-006 | 状态机、事务、幂等、并发保护可验证 | 关键非法迁移、revision conflict、idempotency conflict、outbox claim 无测试即不通过 |
| AG-007 | P1 不污染 P0 | P1 未完成不得阻塞 P0,但 P1 入口不得破坏 P0 边界 |

### 2.2 验收范围

| 范围项 | 是否纳入 P0 验收 | 说明 |
|---|---|---|
| `Qualification` | 是 | 定义真相和下游 identity / capability-hub 同步 |
| `RoleDefinition` | 是 | 定义真相和 identity 同步 |
| `TaskDefinition` | 是 | 定义真相和 process 同步 |
| `WorkProductDefinition` | 是 | 定义真相和 artifact 同步 |
| `ProcessTemplateDef` | 是 | 定义真相和 process 同步 |
| `ViewProfile` | 是 | 服务端解析视图策略 |
| `AIPolicyDef` | 是 | governance policy source |
| `MethodPlugin` | 否 | P1,只验未启用时不影响 P0 |
| `MethodConfiguration` | 否 | P1,只验未启用时不影响 P0 |

## 5. 功能验收门禁

| 验收项 | 功能范围 | 通过条件 | 失败条件 | 证据 |
|---|---|---|---|---|
| AC-P0-001 | 7 类 MethodContent 管理 | 7 类均可 create draft、update draft、submit review,且 kind / payload 校验稳定 | 任一 P0 kind 缺失或 payload 可错配 | EV-001 / EV-002 |
| AC-P0-002 | 发布治理 | `PublishMethodContent` 必须 gate approved,发布后生成 version、fingerprint、snapshot、audit、outbox | 无 gate 可发布,或发布后缺少任一核心记录 | EV-004 / EV-005 |
| AC-P0-003 | 生命周期治理 | deprecate / retire / supersede 按状态矩阵运行,终态不可非法迁移 | retired / superseded 可被继续修改,或非法迁移成功 | EV-001 / EV-003 |
| AC-P0-004 | 关系校验 | 发布前引用必须指向允许的 published definition 版本 | 未发布引用可发布成功,或 target kind 不合法仍成功 | EV-003 |
| AC-P0-005 | Query / Trace | Get/List/GetVersion/Trace 返回正确视图、分页、consistency,且只读 | Query 写 audit/outbox/idempotency 或修复 truth | EV-007 |
| AC-P0-006 | Snapshot export | 下游可按 snapshot_id 或 content_id + version 导出 snapshot,并校验 fingerprint | snapshot 不可导出,或 fingerprint mismatch 被静默忽略 | EV-006 |
| AC-P0-007 | ResolveViewProfile | 唯一 active published ViewProfile 可解析,多命中或未发布内容不得成功 | UI 本地规则替代权威解析,或多命中返回成功 | EV-006 |
| AC-P0-008 | Seed baseline | seed 可生成基础 Qualification、9 Role、8 Template 家族、基础 ViewProfile / AIPolicyDef | 基线资产缺失,或 seed 破坏 P0 发布链 | EV-009 |

## 6. 数据边界与架构红线验收

| 验收项 | 红线 | 通过条件 | 失败条件 | 证据 |
|---|---|---|---|---|
| AC-BND-001 | Definition / Use 分离 | 本仓只保存 definition truth、引用、可靠记录、投影、job 记录 | 出现 ProcessInstance、WorkItem、Artifact instance、policy enforce result 写入路径 | EV-003 |
| AC-BND-002 | Qualification 三仓边界 | method-library 只保存 Qualification 定义;identity 保存 QualificationProfile;capability-hub 保存 QualificationBinding | 本仓保存 QualificationProfile 或 QualificationBinding | EV-003 / EV-010 |
| AC-BND-003 | 下游不可反写真相 | 下游只能消费 event / snapshot / query,不能创建或修改 MethodContent truth | fake downstream 可反向创建或改写 definition | EV-010 |
| AC-BND-004 | Command 不直接发布 bus | Command 只同事务写 outbox,publish bus 由 worker relay | Command 绕过 outbox 直接 publish bus | EV-005 / EV-010 |
| AC-BND-005 | Projection 不反写 truth | projection / rebuild 只读 write model / outbox,不改 MethodContent truth | rebuild 修改 write model | EV-007 |
| AC-BND-006 | P1 不污染 P0 | P1 disabled 时 P0 endpoint 全部可用,P1 endpoint 返回稳定 disabled 响应 | P1 未完成导致 P0 command / query / worker 失败 | EV-002 / EV-009 |

| AC-API-002 | Command DTO | path/body mismatch、kind mismatch、revision conflict 均返回稳定错误 | EV-003 |
| AC-API-003 | Query DTO | Query 不要求幂等键,返回 `ReadConsistency` 或等价一致性标记 | EV-007 |
| AC-API-004 | ErrorResponse | 错误响应包含 code、message、retryable、details、trace_id | EV-003 |
| AC-JOB-001 | Operations Job | seed、replay、recalculate、rebuild 支持 dry_run 并遵守不写 truth 规则 | EV-009 / EV-011 |

| 验收项 | 下游 | 通过条件 | 证据 |

## 8. 状态机、事务与一致性验收

| 验收项 | 范围 | 通过条件 | 失败条件 | 证据 |
|---|---|---|---|---|
| AC-ST-001 | MethodContent lifecycle | Draft / InReview / Published / Deprecated / Retired / Superseded 合法迁移按矩阵执行 | 任一非法迁移成功 | EV-001 / EV-003 |
| AC-ST-002 | Outbox status | Pending / Publishing / Published / RetryableFailed / DeadLettered 状态按规则推进 | 非持有 worker 可标记成功,或 dead-letter 丢失证据 | EV-010 / EV-011 |
| AC-ST-003 | Idempotency status | 同 key 同 hash 返回既有结果,同 key 不同 hash 冲突 | 重复写 audit/outbox/version 或覆盖结果 | EV-008 |
| AC-ST-004 | Job status | Running -> Succeeded / PartiallySucceeded / Failed,terminal 不可再改 | terminal job 可重复 complete/fail | EV-009 |
| AC-TX-001 | 本地事务 | publish 成功时 content/version/snapshot/audit/outbox/idempotency 同时存在 | 业务 truth 已提交但 outbox 或 audit 缺失 | EV-005 |
| AC-TX-002 | 失败回滚 | gate invalid、reference invalid、snapshot failure、outbox append failure 不留下 published truth | 失败后留下半成品 | EV-005 |
| AC-TX-003 | 最终一致 | bus failure 不回滚 truth,只进入 retry / dead-letter / replay | bus failure 回滚已提交 definition truth | EV-010 / EV-011 |
| AC-TX-004 | 并发保护 | revision conflict、unique version、outbox claim、checkpoint CAS 均可触发并稳定失败 | 并发下双写成功或 checkpoint 跳跃 | EV-008 |

## 11. 一票否决项

出现以下任一情况,本仓 P0 验收结论必须为“不通过”:

| 否决项 | 说明 |
|---|---|
| VETO-001 | 任一 P0 MethodContent kind 不可创建或发布 |
| VETO-002 | 无 approved gate 可成功 publish |
| VETO-003 | published 核心字段可被原地修改 |
| VETO-004 | publish 成功但缺少 audit、snapshot、outbox、fingerprint 任一核心记录 |
| VETO-005 | Command 直接发布 L0-bus,绕过 outbox |
| VETO-006 | Query 写 truth、audit、outbox、idempotency 或自动修复数据 |
| VETO-007 | 本仓保存 QualificationProfile、QualificationBinding、ProcessInstance、WorkItem、Artifact instance 或 policy enforce result |
| VETO-008 | 下游无法通过 event 或 snapshot 同步任一 P0 definition |
| VETO-009 | fingerprint mismatch 被静默忽略且无 mismatch / drift 证据 |
| VETO-010 | P1 未完成导致 P0 主链不可用 |

## 12. 缺陷分级、复验与放行规则

| 缺陷级别 | 定义 | 放行规则 | 复验要求 |
|---|---|---|---|
| S | 触发一票否决项,或破坏 definition truth、发布一致性、边界红线、同步主链 | 不允许放行 | 修复后重跑相关全链路和一票否决检查 |
| A | 主链可跑但幂等、replay、projection、ResolveViewProfile、seed、性能阈值不稳定 | 原则上不放行;如有条件通过必须风险接受 | 定点复验 + 相关回归 |
| B | 非关键摘要、报告展示、低频 operations 体验问题 | 可带风险放行 | 定点复验 |

放行规则:

- S 级缺陷为 0 才可进入通过或有条件通过。
- A 级缺陷若未修复,必须记录影响范围、接受人、截止点和补救计划。
- B 级缺陷不得影响 AC-P0、AC-BND、AC-SYNC、AC-TX 任一验收项。

## 13. 风险接受与遗留项

| 风险编号 | 风险 | 影响 | 接受条件 | 后续动作 |
|---|---|---|---|---|
| RA-001 | `ResolveViewProfile` no-match 语义仍需实现前确认 | 影响 no-match API 断言 | 唯一命中、多命中、未发布内容三类门禁已固定;no-match 选择前不得发布正式 API | 实现前由 UI / console / Owner 固定 |
| RA-002 | 已 retired 再 retire 的幂等语义仍需实现前确认 | 影响生命周期重入测试 | P0 不允许双语义同时通过;实现前固定冲突或幂等结果 | 实现前由 Owner / TL 固定 |
| RA-003 | governance gate 校验模式可能分叉 | 影响 publish 集成测试环境 | P0 至少覆盖一种正式校验模式,并禁止无 gate 发布 | 配置设计中固定 validation mode |
| RA-004 | 完整 TLS / retry / secret / deployment 参数不在本文验收 | 影响部署级验收 | P0 验收只覆盖代码契约与测试环境;部署验收另行承接 | 配置 / 运维文档补齐 |
| RA-005 | P1 MethodPlugin / MethodConfiguration 未实现 | 不影响 P0 资产定义闭环 | P1 disabled 不影响 P0,且不会反向污染 MethodContent truth | P0 完成后单独规划 P1 |

## 14. 最终结论与签署

### 14.1 验收结论规则

| 结论 | 使用条件 |
|---|---|
| 通过 | 所有 P0 验收项通过,无 S 级缺陷,A 级缺陷为 0 或不影响 P0 且已有风险接受 |
| 有条件通过 | P0 主链通过,无一票否决项,但存在已记录并被接受的 A / B 级遗留项 |
| 不通过 | 任一一票否决项触发,或 P0 主链无法被证据证明成立 |

### 14.2 签署表

| 角色 | 责任 | 签署内容 |
|---|---|---|
| Owner | 确认 P0 / P1 范围和风险接受 | 验收结论 |
| Tech Lead / Architect | 确认架构红线、事务一致性、下游同步契约 | 技术验收 |
| QA | 确认测试报告、证据编号、缺陷复验 | 测试验收 |
| SRE / Platform | 确认 staging-like 环境、worker、bus、object storage 验证证据 | 运行验收 |
| Security / Governance | 确认 gate、audit、actor context、敏感信息约束 | 治理验收 |

### 14.3 当前文档结论

| 项 | 结论 |
|---|---|
| 当前状态 | 验收标准已定义,尚未执行验收 |
| 可进入实施计划 | 是,前提是实施计划引用本文 AC / VETO / EV 规则 |

## 2. 实施目标与范围

### 2.1 本轮实施目标

| 类别 | 内容 | 来源 | 是否本轮实施 | 说明 |
|---|---|---|---|---|
| P0 功能能力 | 7 类 MethodContent 定义资产草稿、评审、发布、废弃、退役、替代 | F-001 / F-002 / AC-P0-001~003 | 是 | 本轮核心 |
| P0 功能能力 | 关系校验、Definition / Use 边界保护、fingerprint 生成 | F-003 / F-004 / AC-BND-* | 是 | 必须先于发布闭环稳定 |
| P0 功能能力 | snapshot、audit、outbox、idempotency 同事务写入 | F-002 / F-004 / AC-TX-001~003 | 是 | 发布主链门禁 |
| P0 功能能力 | Query、ExportDefinitionSnapshot、ResolveViewProfile、GetDefinitionTrace | F-006 / F-007 / AC-P0-005~007 | 是 | 支撑下游消费和审计 |
| P0 功能能力 | Outbox relay、ReplayDefinitionEvents、RecalculateFingerprint、RebuildReadModels | F-005 / F-008 / AC-SYNC-007 / AC-JOB-001 | 是 | 支撑恢复与运维 |
| P0 功能能力 | SeedInitialMethodAssets 基线装载 | F-008 / AC-P0-008 | 是 | 覆盖 Qualification、9 Role、8 Template 家族、ViewProfile、AIPolicyDef |
| P0 边界能力 | P1 feature disabled 不影响 P0 | AC-BND-006 / VETO-010 | 是 | P1 不实现完整功能 |
| P1 能力 | MethodPlugin / MethodConfiguration 完整发布、激活、marketplace 分发 | F-009 / F-010 / RA-005 | 否 | P0 后单独规划 |
| 非目标 | 下游 Use truth、UI 像素渲染、governance enforce、marketplace 交易 | NG-1~NG-8 / §06 VETO-007 | 否 | 只做边界负向测试和契约输出 |

### 2.2 本轮完成标准

```text
P0 代码可以在目标实现仓中完成:
  7 类 definition truth
  Command / Query / Event / Job 协议入口
  publish -> snapshot -> audit -> outbox -> relay -> downstream contract
  Query / Resolve / Trace 只读出口
  seed / replay / recalculate / rebuild operations
  GATE-T-01~GATE-T-07 通过
  AC-P0 / AC-BND / AC-SYNC / AC-ST / AC-TX 均可判定
```

### 3.2 项目级 Git 配置

实现如果发生在其他目录,必须在目标实现仓根目录重新确认:

```bash
git config user.name "quantalithos-labs"
git config user.email "quantalithos.ai@gmail.com"
git config user.name
git config user.email
```

要求:

- 使用项目级 `git config`,不使用 `--global`。
- 当前 design 文档仓提交前阅读 `projects/README.md` §8.2 和本仓历史提交。
- 目标实现仓提交前必须在目标仓内阅读其提交规范和历史提交。
- 当前 design 文档仓固定 footer 为 `Co-Authored-By: Codex <noreply@openai.com>`。
- 目标实现仓 footer 按目标仓规范执行;若无单独规定,使用通用 AI 注脚规则。
- 注意语言边界:当前 `quantalithos-design` design 仓提交遵循 `projects/README.md` §8.2;目标实现仓 commit message 使用英文,源码标识符、rustdoc、普通注释和测试名也必须使用英文。
- 不提交不可审查的 `WIP`。


## 12. 实施完成判定

| 判定项 | 标准 | 证据 | 结论 |
|---|---|---|---|
| P0 范围覆盖 | F-001~F-008 已实现或有明确风险接受;F-009~F-011 不阻塞 P0 | trace matrix / implementation report | 通过 / 不通过 |
| 7 类 MethodContent | 7 类均可走 create/update/submit/publish 主链 | EV-001 / EV-002 / EV-004 | 通过 / 不通过 |
| 发布一致性 | publish / supersede 同事务写 content/version/snapshot/audit/outbox/idempotency | EV-005 | 通过 / 不通过 |
| 边界红线 | 无 Use truth 写入路径,无 P1 污染 P0 | EV-003 / VETO report | 通过 / 不通过 |
| Query / Resolve / Trace | 只读出口可用且不修复 truth | EV-006 / EV-007 | 通过 / 不通过 |
| Worker / Operations | relay、seed、replay、recalculate、rebuild 可用 | EV-009 / EV-011 | 通过 / 不通过 |
| 下游契约 | fake downstream event / snapshot contract 全部通过 | EV-010 | 通过 / 不通过 |
| 非功能 | AC-NF 达标或有风险接受 | EV-012 | 通过 / 有条件通过 / 不通过 |
| 一票否决 | VETO-001~010 均未触发 | veto checklist | 通过 / 不通过 |
| 提交与证据 | 阶段提交边界清晰,EV-001~EV-012 可追溯 | git log / CI artifacts | 通过 / 不通过 |

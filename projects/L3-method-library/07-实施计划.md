## 2. 实施目标与范围

> 校准来源: `design-calibration/07_implementation_plan_step_02_scope.md`

### 2.1 实施目标

本轮实施目标是把 `/home/aris/Projects/quantalithos-method-library` 落地为可编译、可测试、可验收的 L3 方法资产定义 truth center。它必须覆盖方法资产定义与目录、正式化与版本、受控消费、追溯与一致性保护、关系与分发语义、外部摘要与引用、后台维护与收敛、外围包与方法集组织的有界能力,并能按 `TC-ML-*` / `EV-ML-*` / ML-FG / ML-RL / ML-SYNC / VETO-ML 生成执行期证据。

### 2.2 本轮范围

| 类别 | 内容 | 是否 P0 | 处理 |
|---|---|---:|---|
| 核心需求 | FR-ML-001~FR-ML-009 | 是 | 必须通过 phase / commit boundary 落地并产生门禁证据 |
| 业务规则 | BR-ML-001~BR-ML-022 | 是 | 转为 domain / service / dependency / redline 门禁 |
| 非功能 | NFR-ML-001~NFR-ML-016 | 是 | 以 sample、boundary、redaction、consistency、observability 和 evidence gate 判定 |
| 详细设计契约 | 七实现单元、八业务组成、58 Command、57 Query、4 Consumer、34 Outbound Event / sender、8 Job | 是 | 按 PH-01~PH-11 和 commit boundary 分批落地 |
| 测试证据 | `TC-ML-*`、`EV-ML-*`、suite/report/artifact | 是 | 由 run-scoped artifact/report 推导 |
| 验收门禁 | ML-FG、ML-RL、ML-SYNC、ML-STATE/TX/READ/JOB/IDEMP/CHKPT/NFR、VETO-ML | 是 | 由 `06` 裁决,本文件嵌入实施门禁 |
| 外围增强 | FR-ML-E-001~004 | 否,有界支持 | 只作为 peripheral / residual / future,不得阻塞 P0 |

### 2.3 非范围与防误入

| 非范围项 | 当前处理 |
|---|---|
| 流程执行、ProcessInstance、runtime orchestration | 留给 `L1-process` / `L2-runtime` |
| 成员身份、成员生命周期、成员实际角色状态 | 留给 `L1-identity` 或成员相关仓 |
| 治理裁决、Gate 执行、policy enforce | 本仓只保存 safe conclusion / basis ref / marker |
| marketplace 定价、订单、购买、安装、履约 | 留给 marketplace / peripheral 后续规划 |
| UI 页面渲染、会话、组件状态、交互执行 | 留给体验层 |
| artifact/archive 正文生命周期 | 本仓只保存 summary/ref/marker/digest hint |
| 真实 DB/bus/provider/secret backend、production-like capacity、hard SLO | P1/P2 selected-run 或 future,不得作为 P0 pass 条件 |
| 旧 MethodContent / publish / snapshot / outbox / fingerprint 主线 | historical material only |

## 6. 阶段任务拆分、编写顺序与提交边界

> 校准来源: `design-calibration/07_implementation_plan_step_06_tasks_commit_boundaries.md`

### 6.1 通用写入顺序

| 顺序 | 写入层 | 内容 | 不得越界 |
|---:|---|---|---|
| 1 | contracts | typed refs、metadata、safe marker、request/result/view/event/job shell、fixtures | 不写 domain truth 或 adapter |
| 2 | domain | truth object、state、policy、guard、domain error、unit tests | 不读 config、repository 或 runtime |
| 3 | application | ports、UoW、idempotency、service flow、mapper、application error | 不实现 concrete storage / transport |
| 4 | infra | in-memory/fake/controlled adapter、repository、runtime builder、config binding | 不新增未设计 port 或 truth |
| 5 | entry | api / worker / jobs runner,只调用 application facade | 不直连 repository / domain / adapter |
| 6 | tests/evidence | suite slice、script dry-run、artifact/report path | 不静态造 pass,不写 `latest` |

### 6.2 通用开工前设计闭环复核

每个 commit boundary 开工前必须复核字段、DTO、port/repository、state/transition、idempotency/replay、query surface、event/publisher、job report、config binding、evidence schema 和 phase scope。任一项不闭合时暂停并回写 owning source,不得在实现仓自行补。

## 10. 回退、暂停与变更控制

> 校准来源: `design-calibration/07_implementation_plan_step_10_rollback_pause_change_control.md`

### 10.1 暂停规则

目标仓 layout、`core-contracts`、设计真相源、P0 profile、artifact/report root、blocking suite、redaction、dependency、report audit、VETO 和 static evidence 任一失败时,必须暂停当前 boundary。暂停时保留错误、artifact/report、文件行号、diff 范围和建议 owning source;不得用 placeholder、private map、synthetic marker、raw string、timestamp、SQL/HTTP code 或 fake-only shortcut 继续。

### 10.2 回退规则

回退默认只作用于当前 boundary 未提交改动。不得擅自回退用户改动、已验证历史提交或其他 phase 文件。已提交 boundary 需要修复时,优先新增修复 commit;只有用户明确要求时才 amend/rebase。

### 10.3 变更控制

| 触发条件 | 回写目标 |
|---|---|
| object / protocol / flow / state / persistence / idempotency 缺口 | `03-详细设计.md` and calibration |
| config profile / adapter / CLI / env / failure strategy 缺口 | `04-配置设计.md` |
| suite / artifact / report / EV mapping / gate 缺口 | `05-测试方案.md` |
| AC / VETO / risk acceptance / final decision 缺口 | `06-验收标准.md` |
| phase / commit boundary / allowed scope / required checks 冲突 | `07-实施计划.md` calibration and formal §6~§12 |
| 可复用经验缺失 | `standards/document/设计真相源闭环与可落码性标准.md` 或相关规范 |

恢复实施必须同时满足:新 baseline 固定、当前 boundary closure review 通过、工作区只含授权改动、提交前 gate 重跑通过、failed artifact/report 保留且 fixed run 可追溯。

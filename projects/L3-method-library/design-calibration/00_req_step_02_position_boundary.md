## 3. 模块思考记录

### 3.1 一句话定义

问题回答:

- 本仓不是通用内容库,而是 L3 方法能力层里承载方法资产定义、版本发布和分发语义的仓。
- 上游材料反复使用的核心词是 Method Content / 方法库 / 方法资产,因此定义应围绕“方法资产定义与分发真相”收敛。
- 需求层可以说本仓拥有方法资产定义和发布身份的真相边界,但不能在 Step 2 进一步展开具体资产类型、字段或状态。

诊断:

- 如果只说“方法库”,读者容易误以为它只是静态文档或模板下载仓。
- 如果照旧稿写“承载 Qualification / RoleDefinition / TaskDefinition / ...”,会把后续数据归属和功能清单提前写入 Step 2。
- 如果强调 CRUD 或 seed,会滑入功能需求和实施计划。

取舍:

- 使用“方法资产定义与分发真相仓”作为最短定位。
- 在说明文字中保留 SPEM Method Content 的来源语义,但不展开 MethodContent 子类。

### 3.2 非职责边界

问题回答:

- 本仓不执行流程、不管理成员身份、不裁决治理策略、不注册外部工具能力、不处理交易和 UI 渲染。
- 这些排除项不是功能列表,而是防止后续需求把 process、identity、governance、capability-hub、marketplace、console 等仓的职责混入本仓。

诊断:

- 旧 README 把 marketplace 上架 / 下载写入核心职责,容易把资产源与交易系统混在一起。
- 旧 00 把下游同步和 P0 消费方写得很早,容易在边界章节提前进入依赖与功能讨论。
- AIPolicy 容易与 governance 的策略执行混淆,RoleDefinition 容易与 identity 的成员身份混淆,ProcessTemplate 容易与 process 的运行时实例混淆。

取舍:

- Step 2 只保留仓级排除句。
- 下游消费、事件、同步、查询和具体功能全部推迟到 Step 6/9/12。

### 3.3 混淆对象

问题回答:

- 最容易混淆的相邻仓是 `L1-process`、`L1-identity`、`L1-governance`、`L3-capability-hub` 和 `L6-marketplace`。
- 最容易混淆的概念是“方法定义”和“运行时使用”的分离。

诊断:

- `L1-process` 会使用过程模板,但不应成为模板定义源。
- `L1-identity` 会引用角色 / 能力定义语义,但不应拥有方法定义正文。
- `L1-governance` 会执行或裁决治理策略,但不应替代方法库成为 AIPolicy 定义来源。
- `L3-capability-hub` 负责外部能力、MCP/A2A 和 provider 注册治理,不等同于方法资产定义。
- `L6-marketplace` 可以面向资产分发和交易体验,但不应拥有方法资产定义真相。

取舍:

- 边界对象列表只列对象,不解释混淆原因。
- 解释统一放到结构化中间产物和回填短文字中。

### 3.4 单独成仓原因

问题回答:

- 方法资产需要跨 process、identity、governance、member-images、UI/console 和 marketplace 被稳定引用。
- 如果把方法资产定义并入任一消费仓,定义真相会被运行时实例、成员状态、治理执行或交易流程绑死。
- 因此本仓需要作为独立定义源,把“怎么做 / 用什么方法资产”从“谁在执行 / 谁在使用 / 谁在交易”中分离。

诊断:

- 若并入 process,模板定义会被流程执行状态污染。
- 若并入 identity,角色定义会与成员身份和成员生命周期混同。
- 若并入 governance,AIPolicy 定义会与治理裁决和执行结果混同。
- 若并入 marketplace,方法资产定义会被上架、购买、计费或分发体验牵引。

取舍:

- 单独成仓原因只写“独立、版本化、可分发的方法资产定义源”。
- 不在 Step 2 展开依赖方向、事件流或具体发布机制。

### 5.2 边界说明结论

`L3-method-library` 需要单独存在,因为平台的方法资产必须先作为可版本化、可发布、可分发的定义真相成立,再被相邻仓消费。它最容易与 `L1-process` 的执行实例、`L1-identity` 的成员身份、`L1-governance` 的治理裁决、`L3-capability-hub` 的外部能力注册以及 `L6-marketplace` 的交易分发混淆;这些边界如果不分开,后续需求会把“方法定义”误写成“运行时使用”或“交易体验”。

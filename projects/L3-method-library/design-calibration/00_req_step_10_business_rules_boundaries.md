## 4. 模块思考记录

### 4.1 不变量规则

问题回答:

- 本仓成立的硬前提是方法资产定义真相归 `L3-method-library`,下游只能消费或引用。
- 方法资产必须具备稳定身份和适用语境,否则版本、消费和追溯都没有锚点。
- 正式版本语义必须稳定,否则正式消费无法建立可信引用。

诊断:

- 旧材料中的 fingerprint、snapshot、event 都是后续设计机制,不能作为需求规则正文。
- 若规则写成字段必须存在或数据库唯一,会越过 Step 11 和详细设计。

取舍:

- 不变量写成需求层条件:定义真相归属、身份语境稳定、Definition vs Use、正式版本语义稳定。

### 4.2 禁止行为规则

问题回答:

- 下游消费仓不得创建、修改或替代方法资产定义。
- 未正式化的方法资产不得作为正式消费依据。
- 运行期消费、事件协作、生态发现都不得被写成源码级拥有关系。

诊断:

- 如果写“某接口拒绝请求”或“service 校验”,就落入实现校验。
- 如果不写禁止行为,后续 Step 11/12 容易把定义真相迁移到消费仓。

取舍:

- 禁止行为只写“不得发生什么”和“约束对象”,不写如何阻止。

### 4.3 显式变化规则

问题回答:

- 方法资产正式化必须显式发生,不能因读取、引用、同步或运行时使用而隐式触发。
- 正式版本语义变化必须显式形成新版本或等价正式变化口径。
- 影响既有消费的变化必须能被显式识别,否则一致性保护无从成立。

诊断:

- publish、supersede、retire、fingerprint_changed 等是旧设计线索,但具体状态和事件名不应进入需求规则。

取舍:

- 显式变化规则只说明必须显式发生的业务变化,不定义状态机。

### 4.4 边界 / 治理 / 审计规则

问题回答:

- 相邻仓红线需要在规则层钉住,防止 process、identity、governance、capability-hub、marketplace、UI、artifact 职责回流。
- 若正式化需要治理结论,治理结论只能是前置或引用依据,本仓不执行治理裁决。
- 正式化、版本语义变化、消费引用和证据线索需要可追溯,否则 Step 14 无法验收。

诊断:

- Gate、outbox、audit record、evidence JSON、event payload 都是后续设计或测试 schema。

取舍:

- 保留治理约束和审计约束作为需求层硬规则。
- 具体治理协作和审计产物留给 Step 12/14/15 及后续设计。

## 7. 回填草稿

### 10. 业务规则与边界约束

> 校准来源:
> - `design-calibration/00_req_step_10_business_rules_boundaries.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/00_req_step_10_business_rules_boundaries.md` 的“结构化中间产物”“旧材料差异审计”和“自检与停审”小节,了解本章规则如何由功能需求和仓边界收敛。

| 规则编号 | 规则类型 | 规则内容 | 约束对象 |
|---|---|---|---|
| BR-ML-001 | 不变量 | 方法资产定义真相必须归属 `L3-method-library`,不能退化为下游消费仓的私有定义或散落文档。 | 方法资产定义真相 |
| BR-ML-002 | 不变量 | 方法资产必须具备可被人类和系统稳定识别的定义身份与适用语境,否则不能支撑正式版本、消费和追溯。 | 方法资产身份与目录语义 |
| BR-ML-003 | 不变量 | Definition vs Use 必须始终成立:本仓负责定义,相邻仓只能按边界使用、执行、索引或展示。 | 本仓与消费仓关系 |
| BR-ML-004 | 不变量 | 已进入正式使用语境的方法资产必须保持版本语义稳定,不得让既有正式引用在未显式变化的情况下改变含义。 | 正式方法资产版本 |
| BR-ML-005 | 禁止行为 | 下游消费仓不得创建、修改或替代方法资产定义作为自身真相。 | 下游消费行为 |
| BR-ML-006 | 禁止行为 | 不得把流程执行状态、成员状态、治理裁决、外部能力注册、交易流程、UI 渲染或 artifact 正文作为方法资产定义成立条件。 | 边界外运行职责 |
| BR-ML-007 | 禁止行为 | 未正式化或仍处于调整语境的方法资产不得作为正式消费依据。 | 正式消费依据 |
| BR-ML-008 | 禁止行为 | 不得把运行期消费关系、事件协作关系或生态分发关系写成消费仓对本仓业务实现的源码级拥有关系。 | 仓际依赖边界 |
| BR-ML-009 | 显式变化 | 方法资产从非正式语境进入正式使用语境必须通过显式正式化发生,不得由读取、引用、同步或运行时使用隐式触发。 | 方法资产正式化 |
| BR-ML-010 | 显式变化 | 会改变正式方法资产版本语义的修改必须显式形成新的版本或等价正式变化口径,不得静默覆盖既有正式语义。 | 版本语义变化 |
| BR-ML-011 | 显式变化 | 可能影响既有下游消费的一类变化必须能被显式识别,不得让消费影响只存在于实现细节或人工约定中。 | 消费影响变化 |
| BR-ML-012 | 边界约束 | `L1-process` 负责流程执行和过程运行状态;`L3-method-library` 只定义过程模板、任务和方法语义。 | method-library / process 边界 |
| BR-ML-013 | 边界约束 | `L1-identity` 负责成员身份、成员生命周期和成员实际具备的角色状态;`L3-method-library` 只定义角色等方法语义。 | method-library / identity 边界 |
| BR-ML-014 | 边界约束 | `L1-governance` 负责治理裁决和策略执行;`L3-method-library` 只定义可被引用的方法方针或 AI 方针语义。 | method-library / governance 边界 |
| BR-ML-015 | 边界约束 | `L3-capability-hub` 负责外部工具、MCP、A2A、provider 等能力注册和访问语义;`L3-method-library` 不接管外部能力接入。 | method-library / capability-hub 边界 |
| BR-ML-016 | 边界约束 | `L6-marketplace` 负责定价、购买、订单、结算和商业履约;`L3-method-library` 只作为方法资产定义或资产包来源被消费。 | method-library / marketplace 边界 |
| BR-ML-017 | 边界约束 | UI/console 负责渲染和交互执行;`L3-method-library` 可以定义视图策略语义,但不执行前端渲染。 | method-library / UI 边界 |
| BR-ML-018 | 边界约束 | artifact/archive 负责正文、证据文件和制品生命周期;`L3-method-library` 可以定义 work product 语义,但不拥有 artifact 正文真相。 | method-library / artifact 边界 |
| BR-ML-019 | 治理约束 | 若方法资产正式化需要治理结论,该治理结论只能作为正式化前置或引用依据,不得把治理裁决执行迁入本仓。 | 正式化治理边界 |
| BR-ML-020 | 审计约束 | 方法资产正式化、版本语义变化和影响既有消费的变化必须具备可追溯依据,以支撑后续验收和审计。 | 方法资产追溯 |
| BR-ML-021 | 审计约束 | 正式消费应能回溯到被消费的方法资产定义来源和版本语境,避免下游只留下不可解释的本地约定。 | 正式消费追溯 |
| BR-ML-022 | 审计约束 | 方法资产版本、发布和引用相关证据线索必须能承接到正式验收或审计语境,不得只存在于人工说明中。 | 方法资产证据线索 |
| BR-ML-E-001 | 边界约束 | MethodPlugin、MethodConfiguration、marketplace 生态分发、高级策略变体和标准映射材料属于外围增强时,不得改变核心方法资产定义真相边界。 | 外围增强能力 |

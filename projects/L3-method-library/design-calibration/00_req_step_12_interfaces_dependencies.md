## 2. 整体模块骨架

Step 12 按能力边界而不是实现接口组织:

| 模块 | 输出 | 不输出 |
|---|---|---|
| 对外能力接口 | 本仓对人类角色、系统消费者和后台维护提供哪些能力级入口。 | 不写 API 路径、方法名、DTO、字段或协议。 |
| 外部依赖边界 | 本仓消费哪些输入,本仓输出被哪些下游能力消费。 | 不重抄 Step 6 仓依赖表。 |
| 事件协作边界 | 哪些变化需要成为下游可感知的能力输出,哪些外部变化可作为输入。 | 不写 event topic、payload、outbox、relay 或重试。 |
| 能力映射与停审 | 每个接口/依赖如何回指功能需求和核心能力节点。 | 不按旧 API 清单逐项映射。 |

## 3. 模块思考记录

### 3.1 对外能力接口

问题回答:

- 本仓对外主要体现为四类能力面:定义变更、正式化与版本变化、定义读取 / 目录识别、变化感知 / 追溯消费。
- 后台任务能力可以保留为需求层入口,但只能写成维护类能力,不能写具体 Job 名或重放机制。
- 外围增强的资产包、方法集和高级策略变体可以单列,但不能改变核心闭环。

诊断:

- 旧稿把 Create/Publish/Get/Resolve/Export/Replay 等名称直接写入需求,已经进入接口或应用服务命名层。
- 若 Step 12 继承旧 API 名称,后续实现会被未校准的旧 schema 绑定。

取舍:

- 使用“能力主题名”表达接口面。
- 不使用旧 API / RPC / Event / Job 名称。

### 3.2 外部依赖边界

问题回答:

- `L0-core` 是编译期定义来源依赖。
- `L0-bus` 是事件协作能力边界,承载变化可感知输出,不成为业务实现源码依赖。
- process、identity、runtime、member-images 是下游消费依赖,它们消费本仓输出但不拥有定义真相。
- governance、artifact、marketplace、console、SDK 等关系需要按 Step 6 的“候选 / 外围”口径谨慎表达。

诊断:

- Step 6 已经判断主链与非主链关系;Step 12 不能把所有旧下游都强行拉进核心闭环。

取舍:

- 主表保留进入当前主链的能力边界。
- 条件型或外围协作单独标注,不把待确认关系伪装为已闭口核心依赖。

### 3.3 事件协作边界

问题回答:

- 方法资产正式化、版本语义变化和可能影响消费的一类变化,需要对下游形成可感知输出。
- 本仓可以消费外部正式结论或回报摘要,但这些输入不能变成本仓拥有外部运行真相。

诊断:

- 旧材料中事件名和 payload 很完整,但当前需求层只需要写“能力输出面”,否则会提前锁定 Step 12 不应回答的 schema。

取舍:

- 事件协作写为“变化感知输出”和“外部结论 / 消费影响输入”的能力边界。

## 4. 结构化中间产物

### 4.1 对外能力接口表

| 接口类型 | 名称 | 说明 | 所属能力层级 |
|---|---|---|---|
| 变更接口 | 方法资产定义建立与调整 | 对外体现为正式建立或调整方法资产定义的能力入口。 | 核心闭环能力 |
| 变更接口 | 方法资产正式化与版本变化 | 对外体现为让方法资产进入正式使用语境,以及显式处理版本语义变化的能力入口。 | 核心闭环能力 |
| 查询接口 | 方法资产目录与身份识别 | 对外体现为识别方法资产身份、目录语义和适用语境的读取能力。 | 核心闭环能力 |
| 查询接口 | 正式方法资产定义读取 | 对外体现为读取正式方法资产定义语义,支撑下游按边界消费。 | 核心闭环能力 |
| 查询接口 | 方法资产版本与追溯查看 | 对外体现为查看方法资产版本语境、变更依据和消费影响线索的能力。 | 核心闭环能力 |
| 事件输出 | 方法资产变化可感知输出 | 对外体现为正式化、版本语义变化和消费影响变化可被下游体系感知。 | 核心闭环能力 |
| 事件输入 | 外部治理结论和消费影响输入 | 对内体现为可接收正式治理结论或下游消费影响回报,但不拥有外部运行真相。 | 核心闭环能力 |
| 后台任务接口 | 方法资产一致性维护 | 对外体现为支持方法资产目录、变化感知和追溯材料维护的后台能力入口。 | 核心闭环能力 |
| 查询接口 | 方法资产包发现与分发语义读取 | 对外体现为读取方法资产包和分发语义的能力。 | 外围增强能力 |
| 变更接口 | 组织级方法集组装与调整 | 对外体现为建立或调整组织级方法集语义的能力入口。 | 外围增强能力 |
| 查询接口 | 高级策略变体消费支撑 | 对外体现为读取更复杂视图策略或 AI 方针变体的能力。 | 外围增强能力 |

### 4.2 外部依赖边界表

| 依赖方向 | 依赖类型 | 关联方 | 全局依赖类型 | 说明 | 所属能力层级 |
|---|---|---|---|---|---|
| 输入 | 定义来源依赖 | `L0-core` | 编译期依赖 | 本仓需要共享契约和基础引用能力,以稳定表达方法资产身份、引用和跨仓一致性边界。 | 核心闭环能力 |
| 输出 | 外部能力依赖 | `L0-bus` | 事件协作依赖 | 本仓通过事件协作通道让方法资产变化成为平台级可感知信号。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-process` | 运行期依赖 | process 消费过程模板、任务和方法定义语义,但不拥有定义真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-identity` | 运行期依赖 | identity 消费角色等身份相关方法语义,但不拥有方法资产定义正文。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-runtime` | 运行期依赖 | runtime 消费方法、角色和模板语义形成执行语境,但不拥有定义真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-member-images` | 运行期依赖 | member-images 消费 Role 到 image variant 的定义来源,不得 hardcode 角色镜像映射。 | 核心闭环能力 |
| 输入 | 治理结论依赖 | `L1-governance` | 运行期 / 事件协作候选 | 若方法资产正式化需要外部治理结论,本仓只消费正式结论或引用,不执行治理裁决。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L6-marketplace` | 运行期 / 事件协作候选 | marketplace 可消费方法资产包或分发语义,但交易和履约不进入本仓。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L5-console` / `L0-sdk` | 运行期候选 | 管理体验或 SDK 可消费本仓能力,但不成为方法资产定义真相成立的前置。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L1-artifact` | 运行期候选 | artifact 可按边界消费 WorkProductDefinition 语义,但 artifact 正文和生命周期不归本仓。 | 外围增强能力 |

### 4.3 事件协作边界结论

| 事件协作能力 | 方向 | 能力说明 | 不得包含 |
|---|---|---|---|
| 方法资产正式化变化感知 | 输出 | 方法资产进入正式使用语境时,下游体系应能感知其可消费语义。 | 不写事件名、payload、outbox、重试或订阅实现。 |
| 方法资产版本语义变化感知 | 输出 | 正式方法资产版本语义发生显式变化时,下游体系应能感知变化。 | 不写 fingerprint 算法或事件字段。 |
| 方法资产消费影响变化感知 | 输出 | 可能影响既有下游消费的变化应能被下游体系识别。 | 不写 drift 状态机或告警实现。 |
| 外部治理结论输入 | 输入 | 本仓可接收方法资产正式化所需的正式治理结论或引用。 | 不写治理事件 schema 或裁决流程。 |
| 下游消费影响回报输入 | 输入 | 本仓可接收下游消费影响摘要,用于支撑一致性保护。 | 不写回报协议、轮询、订阅或对账算法。 |

### 4.4 接口 / 依赖与功能需求映射

| 功能需求 | 对应接口 / 依赖 | 映射说明 |
|---|---|---|
| FR-ML-001 方法资产定义建模能力 | 方法资产定义建立与调整;`L0-core` 定义来源依赖 | 定义能力需要正式变更入口和共享契约基线。 |
| FR-ML-002 方法资产身份与目录识别能力 | 方法资产目录与身份识别;正式方法资产定义读取 | 目录和身份识别需要查询能力面承接。 |
| FR-ML-003 方法资产正式化能力 | 方法资产正式化与版本变化;外部治理结论输入 | 正式化需要显式变更入口,并可按边界消费治理结论。 |
| FR-ML-004 方法资产版本稳定边界能力 | 方法资产正式化与版本变化;方法资产版本语义变化感知 | 版本稳定边界需要显式变化和下游可感知输出。 |
| FR-ML-005 正式方法资产受控消费支撑能力 | 正式方法资产定义读取;方法资产变化可感知输出;process / identity / runtime / member-images 下游消费依赖 | 受控消费需要读取能力、变化输出和下游消费边界共同成立。 |
| FR-ML-006 方法资产追溯能力 | 方法资产版本与追溯查看;方法资产一致性维护 | 追溯需要查询和后台维护能力支撑。 |
| FR-ML-007 方法资产消费一致性保护能力 | 方法资产消费影响变化感知;下游消费影响回报输入;方法资产一致性维护 | 一致性保护需要变化感知、影响回报和维护入口。 |
| FR-ML-E-001 方法资产包与方法集组织能力 | 方法资产包发现与分发语义读取;组织级方法集组装与调整 | 外围增强能力需要包和方法集能力边界。 |
| FR-ML-E-002 方法资产生态发现能力 | 方法资产包发现与分发语义读取;marketplace 外围消费依赖 | 生态发现只保留分发语义,不进入交易实现。 |
| FR-ML-E-003 高级策略变体表达能力 | 高级策略变体消费支撑;console / SDK 外围消费依赖 | 高级策略变体可供体验或 SDK 消费,但不改变核心闭环。 |

### 4.5 能力级接口停审结论

| 核心能力节点 | 接口 / 依赖承接 | 停审结论 |
|---|---|---|
| 方法资产能够被统一定义和识别 | 定义建立与调整、目录与身份识别、`L0-core` 定义来源依赖。 | 已有能力接口承接,未写 API 或字段。 |
| 方法资产能够以稳定版本进入正式使用语境 | 正式化与版本变化、外部治理结论输入、版本变化感知输出。 | 已表达显式正式化和条件型治理输入,未写状态机或治理流程。 |
| 正式方法资产能够被下游按边界消费 | 正式定义读取、变化可感知输出、process/identity/runtime/member-images 消费边界。 | 已承接主链下游消费,未把运行期依赖写成源码依赖。 |
| 方法资产变化能够被追溯并保护消费一致性 | 版本与追溯查看、消费影响变化感知、下游消费影响回报输入、一致性维护。 | 已表达追溯和一致性保护能力,未写 event schema、重试或对账算法。 |

### 4.6 跨能力接口审计

| 检查项 | 结论 | 说明 |
|---|---|---|
| 是否存在没有功能来源的接口边界 | 无 | 所有接口能力均映射到 FR-ML-001~007 或 FR-ML-E-*。 |
| 是否存在 Step 6 依赖类型冲突 | 未发现 | 主链依赖类型与 Step 6 一致;候选关系明确标注候选或外围。 |

| 是否泄漏协议或实现细节 | 未发现 | 未写 API 路径、RPC、DTO、event payload、repository、outbox、handler 或事务。 |
| 是否遗漏核心下游消费边界 | 未发现 | process、identity、runtime、member-images 均有能力边界承接。 |

### 5.1 可保留为接口能力的旧方向

| 旧方向 | 本轮吸收方式 |
|---|---|
| 创建 / 更新方法资产定义 | 抽象为“方法资产定义建立与调整”变更接口。 |
| 发布、废弃、替代等正式版本动作 | 抽象为“方法资产正式化与版本变化”变更接口。 |
| 查询方法资产和目录 | 抽象为“方法资产目录与身份识别”“正式方法资产定义读取”查询接口。 |
| 导出定义快照给下游 | 抽象为“正式方法资产定义读取”和下游消费依赖,不写 snapshot schema。 |
| 方法资产变化事件 | 抽象为“方法资产变化可感知输出”,不写事件名或 payload。 |
| 治理 Gate 结果输入 | 抽象为“外部治理结论输入”,不迁入治理裁决执行。 |
| 重建、重放、对账类后台能力 | 抽象为“方法资产一致性维护”,不写 Job 名或实现流程。 |

#### 12.1 对外能力接口

| 接口类型 | 名称 | 说明 | 所属能力层级 |
|---|---|---|---|
| 变更接口 | 方法资产定义建立与调整 | 对外体现为正式建立或调整方法资产定义的能力入口。 | 核心闭环能力 |
| 变更接口 | 方法资产正式化与版本变化 | 对外体现为让方法资产进入正式使用语境,以及显式处理版本语义变化的能力入口。 | 核心闭环能力 |
| 查询接口 | 方法资产目录与身份识别 | 对外体现为识别方法资产身份、目录语义和适用语境的读取能力。 | 核心闭环能力 |
| 查询接口 | 正式方法资产定义读取 | 对外体现为读取正式方法资产定义语义,支撑下游按边界消费。 | 核心闭环能力 |
| 查询接口 | 方法资产版本与追溯查看 | 对外体现为查看方法资产版本语境、变更依据和消费影响线索的能力。 | 核心闭环能力 |
| 事件输出 | 方法资产变化可感知输出 | 对外体现为正式化、版本语义变化和消费影响变化可被下游体系感知。 | 核心闭环能力 |
| 事件输入 | 外部治理结论和消费影响输入 | 对内体现为可接收正式治理结论或下游消费影响回报,但不拥有外部运行真相。 | 核心闭环能力 |
| 后台任务接口 | 方法资产一致性维护 | 对外体现为支持方法资产目录、变化感知和追溯材料维护的后台能力入口。 | 核心闭环能力 |
| 查询接口 | 方法资产包发现与分发语义读取 | 对外体现为读取方法资产包和分发语义的能力。 | 外围增强能力 |
| 变更接口 | 组织级方法集组装与调整 | 对外体现为建立或调整组织级方法集语义的能力入口。 | 外围增强能力 |
| 查询接口 | 高级策略变体消费支撑 | 对外体现为读取更复杂视图策略或 AI 方针变体的能力。 | 外围增强能力 |

#### 12.2 外部依赖边界

| 依赖方向 | 依赖类型 | 关联方 | 全局依赖类型 | 说明 | 所属能力层级 |
|---|---|---|---|---|---|
| 输入 | 定义来源依赖 | `L0-core` | 编译期依赖 | 本仓需要共享契约和基础引用能力,以稳定表达方法资产身份、引用和跨仓一致性边界。 | 核心闭环能力 |
| 输出 | 外部能力依赖 | `L0-bus` | 事件协作依赖 | 本仓通过事件协作通道让方法资产变化成为平台级可感知信号。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-process` | 运行期依赖 | process 消费过程模板、任务和方法定义语义,但不拥有定义真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-identity` | 运行期依赖 | identity 消费角色等身份相关方法语义,但不拥有方法资产定义正文。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-runtime` | 运行期依赖 | runtime 消费方法、角色和模板语义形成执行语境,但不拥有定义真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-member-images` | 运行期依赖 | member-images 消费 Role 到 image variant 的定义来源,不得 hardcode 角色镜像映射。 | 核心闭环能力 |
| 输入 | 治理结论依赖 | `L1-governance` | 运行期 / 事件协作候选 | 若方法资产正式化需要外部治理结论,本仓只消费正式结论或引用,不执行治理裁决。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L6-marketplace` | 运行期 / 事件协作候选 | marketplace 可消费方法资产包或分发语义,但交易和履约不进入本仓。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L5-console` / `L0-sdk` | 运行期候选 | 管理体验或 SDK 可消费本仓能力,但不成为方法资产定义真相成立的前置。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L1-artifact` | 运行期候选 | artifact 可按边界消费 WorkProductDefinition 语义,但 artifact 正文和生命周期不归本仓。 | 外围增强能力 |

| 检查项 | 结论 | 说明 |

| 是否明确主要对外能力接口面 | 通过 | 已覆盖变更、查询、事件输出、事件输入和后台任务接口。 |

### 7.3 进入下一步条件

Step 12 已满足进入 Step 13 的条件:

- 已明确能力接口边界和外部依赖边界。
- 每个接口 / 依赖都能回指能力节点和功能需求。
- 运行期依赖和事件协作依赖没有被写成源码依赖。
- 未滑入协议层、字段层或实现层。

下一步 Step 13 将只处理:

- 本仓必须满足哪些非功能质量约束。
- 哪些约束回指核心能力节点,哪些约束覆盖全仓。
- 每条非功能需求的判断口径。

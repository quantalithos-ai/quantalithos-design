## 4. 模块思考记录

### 4.1 对外能力接口

问题回答:

- FR-ML-001~009 需要变更、查询、事件输出、事件输入和后台任务五类能力面。
- 对外能力接口应描述“方法资产定义建立与调整”“正式化与版本变化”“目录识别”“正式定义读取”“追溯查看”“证据线索承接”等能力主题。
- 后台任务可作为需求层能力入口,但不能写 Job 名、重放机制或调度实现。

诊断:

- 旧稿中 Create/Publish/Get/Resolve/Export/Replay 等名称已经接近应用服务或协议命名。
- 若继承旧 API 名称,后续设计会被旧 schema 绑定。

取舍:

- 用能力主题名表达接口面。
- 不使用旧 API、RPC、Event、Job 名称。

### 4.2 外部依赖边界

问题回答:

- `L0-core` 是编译期定义来源依赖,支撑共享契约和引用基线。
- `L0-bus` 是事件协作能力边界,支撑方法资产变化成为平台级可感知信号。
- `L1-process`、`L1-identity`、`L2-runtime`、`L2-member-images` 是当前主链下游消费边界。
- `L1-governance`、`L1-artifact`、`L0-sdk`、`L5-console`、`L6-marketplace` 等关系需要按候选 / 外围表达。

诊断:

- Step 12 不能把 Step 6 已裁剪掉的候选关系重新提升为核心主链。
- 运行期和事件协作边界不能写成源码依赖。

取舍:

- 主表列核心主链边界,候选和外围边界单独标注。
- 不复制 Step 6 依赖矩阵,只写能力级输入 / 输出边界。

### 4.3 事件协作边界

问题回答:

- 方法资产正式化、版本语义变化、消费影响变化需要对下游形成可感知输出。
- 本仓可以接收治理结论和下游消费影响摘要,但这些输入不能成为本仓拥有外部运行真相的依据。

诊断:

- 旧事件名、payload、idempotency、outbox、relay 都属于后续详细设计。

取舍:

- 事件协作只写“能力输出 / 输入”,不写协议。

### 5.3 事件协作边界结论

| 事件协作能力 | 方向 | 能力说明 | 不得包含 |
|---|---|---|---|
| 方法资产正式化变化感知 | 输出 | 方法资产进入正式使用语境时,下游体系应能感知其可消费语义。 | 不写事件名、payload、outbox、重试或订阅实现。 |
| 方法资产版本语义变化感知 | 输出 | 正式方法资产版本语义发生显式变化时,下游体系应能感知变化。 | 不写 fingerprint 算法或事件字段。 |
| 方法资产消费影响变化感知 | 输出 | 可能影响既有下游消费的变化应能被下游体系识别。 | 不写 drift 状态机或告警实现。 |
| 方法资产证据线索可感知 | 输出 | 方法资产版本、发布和引用相关证据线索应能进入验收或审计协作语境。 | 不写证据 JSON、artifact schema 或报表字段。 |
| 外部治理结论输入 | 输入 | 本仓可接收方法资产正式化所需的正式治理结论或引用。 | 不写治理事件 schema 或裁决流程。 |
| 下游消费影响回报输入 | 输入 | 本仓可接收下游消费影响摘要,用于支撑一致性保护。 | 不写回报协议、轮询、订阅或对账算法。 |

### 12. 接口与依赖

> 校准来源:
> - `design-calibration/00_req_step_12_interfaces_dependencies.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/00_req_step_12_interfaces_dependencies.md` 的“结构化中间产物”“旧材料差异审计”和“自检与停审”小节,了解本章接口能力如何由功能、数据和依赖边界收敛。

#### 12.1 对外能力接口

| 接口类型 | 名称 | 说明 | 所属能力层级 |
|---|---|---|---|
| 变更接口 | 方法资产定义建立与调整 | 对外体现为正式建立或调整方法资产定义的能力入口。 | 核心闭环能力 |
| 变更接口 | 方法资产正式化与版本变化 | 对外体现为让方法资产进入正式使用语境,以及显式处理版本语义变化的能力入口。 | 核心闭环能力 |
| 查询接口 | 方法资产目录与身份识别 | 对外体现为识别方法资产身份、目录语义和适用语境的读取能力。 | 核心闭环能力 |
| 查询接口 | 正式方法资产定义读取 | 对外体现为读取正式方法资产定义语义,支撑下游按边界消费。 | 核心闭环能力 |
| 查询接口 | 方法资产版本与追溯查看 | 对外体现为查看方法资产版本语境、变更依据和消费影响线索的能力。 | 核心闭环能力 |
| 查询接口 | 方法资产证据线索查看 | 对外体现为查看方法资产版本、发布和引用相关证据线索的能力。 | 核心闭环能力 |
| 事件输出 | 方法资产变化可感知输出 | 对外体现为正式化、版本语义变化和消费影响变化可被下游体系感知。 | 核心闭环能力 |
| 事件输入 | 外部治理结论和消费影响输入 | 对内体现为可接收正式治理结论或下游消费影响回报,但不拥有外部运行真相。 | 核心闭环能力 |
| 后台任务接口 | 方法资产一致性维护 | 对外体现为支持方法资产目录、变化感知、追溯材料和证据线索维护的后台能力入口。 | 核心闭环能力 |
| 查询接口 | 方法资产包发现与分发语义读取 | 对外体现为读取方法资产包和分发语义的能力。 | 外围增强能力 |
| 变更接口 | 组织级方法集组装与调整 | 对外体现为建立或调整组织级方法集语义的能力入口。 | 外围增强能力 |
| 查询接口 | 高级策略变体消费支撑 | 对外体现为读取更复杂视图策略或 AI 方针变体的能力。 | 外围增强能力 |
| 查询接口 | 标准映射材料查看 | 对外体现为查看方法资产相关标准映射材料的能力。 | 外围增强能力 |

#### 12.2 外部依赖边界

| 依赖方向 | 依赖类型 | 关联方 | 全局依赖类型 | 说明 | 所属能力层级 |
|---|---|---|---|---|---|
| 输入 | 定义来源依赖 | `L0-core` | 编译期依赖 | 本仓需要共享契约和基础引用能力,以稳定表达方法资产身份、引用和跨仓一致性边界。 | 核心闭环能力 |
| 输出 | 外部能力依赖 | `L0-bus` | 事件协作依赖 | 本仓通过事件协作通道让方法资产变化成为平台级可感知信号。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-process` | 运行期依赖 | process 消费过程模板、任务和方法定义语义,但不拥有定义真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L1-identity` | 运行期依赖 | identity 消费角色等身份相关方法语义,但不拥有方法资产定义正文。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-runtime` | 运行期依赖 | runtime 消费方法、角色和模板语义形成执行语境,但不拥有定义真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L2-member-images` | 运行期依赖 | member-images 消费 Role 到 image variant 的定义来源,不得 hardcode 角色镜像映射。 | 核心闭环能力 |
| 输入 | 治理结论依赖 | `L1-governance` | 运行期 / 事件协作候选 | 若方法资产正式化需要外部治理结论,本仓只消费正式结论或引用,不执行治理裁决。 | 核心闭环能力 |
| 输入 | 下游消费依赖 | `L1-process` / `L1-identity` / `L2-runtime` / `L2-member-images` | 运行期 / 事件协作候选 | 本仓可接收下游消费影响摘要,用于一致性保护,但不拥有下游运行真相。 | 核心闭环能力 |
| 输出 | 下游消费依赖 | `L6-marketplace` | 运行期 / 事件协作候选 | marketplace 可消费方法资产包或分发语义,但交易和履约不进入本仓。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L5-console` / `L0-sdk` | 运行期候选 | 管理体验或 SDK 可消费本仓能力,但不成为方法资产定义真相成立的前置。 | 外围增强能力 |
| 输出 | 下游消费依赖 | `L1-artifact` | 运行期候选 | artifact 可按边界消费 WorkProductDefinition 语义,但 artifact 正文和生命周期不归本仓。 | 外围增强能力 |

## 4. 模块思考记录

### 4.1 核心能力闭环验收

问题回答:

- 核心闭环必须验能力共同成立,不是验旧流程或旧 API。
- 四个节点都要可判断:统一定义与识别、稳定版本正式化、下游边界消费、变化追溯和一致性保护。

诊断:

- 旧 Create -> Publish -> Event -> Snapshot -> Downstream Sync 是流程/接口/事件线索,不适合作为需求验收表达。

取舍:

- 用能力条件写验收。
- 不写测试动作、旧 API 名或事件名。

### 4.2 功能能力验收

问题回答:

- FR-ML-001~009 都要被承接。
- 功能验收可按能力组合收敛,不需要照抄每条功能说明。
- 外围增强只验“不阻塞核心闭环”和“若实现则遵守核心边界”。

诊断:

- 旧稿只覆盖 FR-ML-001~007,遗漏当前 FR-ML-006 消费语境分发和 FR-ML-009 证据线索承接。

取舍:

- 增加分发语境和证据线索功能验收。

### 4.3 规则 / 边界验收

问题回答:

- 验收必须证明方法资产真相不串仓、Definition vs Use 不破、边界外职责不进入本仓。
- 治理结论和审计要求只验边界是否清楚,不验治理流程实现。

诊断:

- 旧验收强调“自动化检查”和“接口不存在”,容易变成测试或实现检查。

取舍:

- 验收条件写需求层边界清楚且未混入。

### 4.4 数据归属验收

问题回答:

- 真相数据必须归本仓。
- 快照和引用不得形成第二真相源。
- 禁止保存正文项必须不进入本仓生命周期。

诊断:

- Step 11 当前新增“方法资产证据线索”和“认证登录与鉴权实现正文”,Step 14 必须承接。

取舍:

- 数据验收覆盖真相、快照/引用、禁止正文和证据线索。

### 4.5 非功能验收

问题回答:

- 质量验收要覆盖性能、可用性、安全、追溯、一致性和可观测性。
- 不继承旧 P95 和指标名。

诊断:

- 旧稿 NFR 编号过期,缺少当前 NFR-ML-014~016 的显式版本变化、证据线索/异常观察和观测材料边界。

取舍:

- 用当前 NFR-ML-001~016 组织验收。

### 5.2 一票否决项

| 否决项 | 否决原因 |
|---|---|
| 方法资产定义真相不能明确归属本仓 | 核心能力闭环第一节点不成立,本仓会退化为下游私有模型集合。 |
| 方法资产正式版本语义可被静默覆盖 | 破坏版本稳定、审计追溯和正式消费一致性。 |
| 下游消费仓可以创建、修改或替代方法资产定义真相 | 破坏 Definition vs Use 和本仓存在边界。 |
| 未正式化或不稳定的方法资产可作为正式消费依据 | 破坏正式使用语境和受控消费能力。 |
| process、identity、governance、capability-hub、marketplace、UI、artifact/archive 或认证鉴权实现正文进入本仓真相范围 | 造成跨仓数据归属错误和职责串线。 |
| 正式化、版本语义变化、消费影响变化或证据线索不可追溯 | 破坏审计、验收和消费一致性保护。 |
| 运行期依赖或事件协作依赖被写成本仓与消费仓的源码级拥有关系 | 破坏全局依赖裁剪规则并导致仓际耦合错误。 |
| 外围增强能力被作为核心闭环成立的前置 | 使当前边界失控,无法判断核心需求是否完成。 |
| 可观测材料被作为方法资产定义真相的替代存储 | 破坏定义真相归属和数据边界。 |

#### 14.2 一票否决项

- 方法资产定义真相不能明确归属本仓。
- 方法资产正式版本语义可被静默覆盖。
- 下游消费仓可以创建、修改或替代方法资产定义真相。
- 未正式化或不稳定的方法资产可作为正式消费依据。
- process、identity、governance、capability-hub、marketplace、UI、artifact/archive 或认证鉴权实现正文进入本仓真相范围。
- 正式化、版本语义变化、消费影响变化或证据线索不可追溯。
- 运行期依赖或事件协作依赖被写成本仓与消费仓的源码级拥有关系。
- 外围增强能力被作为核心闭环成立的前置。
- 可观测材料被作为方法资产定义真相的替代存储。

Step 2 按“目标、约束、取舍、非目标”四类输出组织。目标回答架构必须确保什么成立;约束回答绝不能打穿什么边界;取舍回答当前有意识不做深什么;非目标回答当前架构不展开什么范围。

| 不可变约束 | 哪些边界不可被后续架构方案改变。 | 不写普通偏好或性能口号。 |
| 当前阶段取舍 | 哪些潜在本仓能力当前收缩处理。 | 不把边界外能力写成延期 TODO。 |
| 架构非目标 | 当前架构设计明确不展开哪些范围。 | 不重复取舍,不替相邻仓设计。 |

## 3. 模块思考记录

### 3.1 架构目标

#### 问题回答

`L3-method-library` 单独做架构设计的原因不是需要更多对象或接口,而是方法资产定义源如果没有独立结构,会被 process、identity、runtime、governance、marketplace、UI、artifact 等消费语境分别私有化。架构目标必须确保定义真相、正式版本、受控消费和追溯一致性在结构上成立。

#### 诊断

旧架构目标中有“7 类 P0 MethodContent”“下游同步可靠”“publish 写 audit/outbox”“fingerprint drift”等说法。这些方向中有可保留的结构含义,但旧表述混入对象范围、实现机制和协议/事务方案。新版 Step 2 不能直接继承。

#### 取舍

架构目标采用结构性动词表达:承载、守住、支撑、隔离、允许。目标不写“支持创建/查询/发布”,也不写 fingerprint、outbox、PG、缓存或具体 P95。

### 3.2 不可变约束

#### 问题回答

不可变约束来自 Step 1 的硬约束:本仓不做运行时使用状态、不让下游拥有定义真相、不把条件型 governance 或候选 artifact/marketplace/UI 写成核心前置、不继承旧实现机制。

#### 诊断

旧架构把 Qualification、CapabilityBinding、WorkProductDefinition、AIPolicy、ViewProfile 等边界写得过细,且把某些旧对象归属写成已定结论。新版 00 已把其中部分主题重新收缩为待确认或外围增强。

#### 取舍

约束表只写仓级边界和对象类别边界,不写具体 Rust 类型、状态机、发布流程或同步机制。后续 Step 可以选择不同通信和一致性方案,但不能改变这些红线。

### 3.3 当前阶段取舍与架构非目标

#### 问题回答

当前阶段需要收缩的对象是“可能属于本仓但尚未进入核心闭环”的能力,例如 MethodPlugin、MethodConfiguration、高级 ViewProfile、AIPolicy override、下游消费影响回报。明确非目标则是本仓绝不设计的相邻仓运行职责,例如流程执行、成员状态、治理执行、交易履约、UI 渲染和 artifact 正文。

#### 诊断

若把外围增强写成非目标,后续演进会失去承接点;若把边界外职责写成取舍,后续会被误认为只是延期实现。两者必须分开。

#### 取舍

本 Step 把“潜在本仓范围但当前不做深”的内容列为取舍,把“相邻仓职责或边界外正文”列为非目标。

## 6. 结构化中间产物

### 6.1 业务背景与驱动力

`L3-method-library` 的架构需要独立收敛,因为方法资产同时会被流程、身份、运行时、成员镜像、治理、体验和生态分发语境引用。如果架构层不先固定定义真相、正式版本和受控消费边界,方法资产会散落到消费仓或被旧实现同步链反向定义。

核心驱动力:

- 平台需要一个独立于运行时实例、成员状态、治理执行和交易流程的方法资产定义源。
- 方法资产必须能在正式版本语境中被稳定消费,而不是被下游本地约定替代。
- 方法资产变化需要可追溯,并能保护既有消费不被静默破坏。
- 外围增强和条件型依赖必须与核心闭环隔离,避免 P0 架构范围失控。

### 6.2 架构目标表

| 架构目标 | 说明 |
|---|---|
| 承载独立的方法资产定义真相 | 否则方法定义会退化为 process、identity、runtime 或 UI 的本地私有模型。 |
| 守住 Definition vs Use 的结构边界 | 否则本仓会吸收流程执行、成员状态、治理执行、交易或正文生命周期等相邻仓职责。 |
| 支撑正式方法资产版本稳定 | 否则下游正式引用会被静默变化破坏,无法形成可靠消费语境。 |
| 支撑下游按边界受控消费 | 否则消费仓需要复制或改写方法定义正文,定义真相会出现多源。 |
| 允许方法资产变化被追溯并保护消费一致性 | 否则正式化、版本语义变化和消费影响只能依赖人工约定或实现细节。 |
| 隔离核心闭环与外围增强 | 否则 MethodPlugin、MethodConfiguration、marketplace、高级策略变体等外围能力会拖垮核心架构判断。 |
| 保留条件型外部协作的可接入位置 | 否则 governance 结论、artifact 引用、console/SDK 体验等后续协作会被误写成核心前置或完全无法承接。 |

### 6.3 不可变约束表

| 约束 | 说明 |
|---|---|
| 不将相邻仓消费结果视为方法资产定义真相 | 否则本仓会失去定义源地位,下游会形成第二真相。 |
| 不拥有流程执行、过程运行状态或运行时编排 | 这些属于 `L1-process` / runtime 职责,进入本仓会打穿 Definition vs Use。 |
| 不拥有成员身份、成员生命周期或成员实际具备角色状态 | 这些属于 `L1-identity` 或成员相关仓,本仓只定义角色等方法语义。 |
| 不承载治理裁决执行、Gate 流程或 policy enforce 结果 | 本仓可以消费治理结论或引用依据,但不能迁入治理执行。 |
| 不承载外部能力注册、绑定和访问裁决 | MCP/A2A/provider/tool 等外部能力语义属于 `L3-capability-hub` 和治理协作边界。 |
| 不承载 marketplace 定价、订单、结算、购买、安装或履约记录 | marketplace 交易职责不属于方法资产定义源。 |
| 不承载 UI 会话、渲染执行或前端交互状态 | 本仓最多定义 ViewProfile 等视图策略语义,不执行渲染。 |
| 不保存 artifact、证据文件、archive 或外部文档正文 | 本仓只可保存定义性引用或摘要,不得成为正文生命周期仓。 |
| 不把运行期消费或事件协作写成源码级依赖 | 运行期和事件关系必须与编译期依赖分离,避免跨仓耦合。 |
| 不从旧 API、事件、fingerprint、snapshot、outbox、P95 或目录结构反推架构 | 这些旧机制需要在后续 Step 重新论证,不能成为 Step 2 约束。 |

### 6.4 当前阶段可接受取舍表

| 取舍 | 当前口径 |
|---|---|
| Qualification / CapabilityDefinition 不作为当前核心资产独立项 | 当前保持待确认;不进入 Step 2 架构目标和核心约束,若纳入需回写需求与架构后续 Step。 |
| MethodPlugin / MethodConfiguration 不进入核心闭环 | 当前作为外围增强和演进方向处理,不影响核心定义、正式化、消费和追溯目标。 |
| marketplace 生态发现只保留分发语义 | 当前不展开上架、交易、购买、安装和履约架构。 |
| AIPolicy override 和高级 ViewProfile 匹配不做深 | 当前只保留定义主题和外围增强承接,不作为核心架构目标。 |
| governance 正式化不写成强制主链 | 当前按条件型治理结论或依据引用处理,不让核心定义真相依赖治理执行可用性。 |
| artifact 核心消费关系不提前闭口 | 当前只保留 WorkProductDefinition 语义和正文禁止边界,artifact 是否核心消费后续裁剪。 |
| 下游消费影响回报机制不在本 Step 定义 | 当前只保留一致性保护需求和快照候选,不定义协议、事件或存储机制。 |
| 具体 P95 / SLO / 指标集不在架构目标层固定 | 当前只保留不阻塞主链、追溯可判断、关键状态可观察的架构要求。 |

### 6.5 架构非目标表

| 非目标 | 不展开原因 |
|---|---|
| 不设计流程执行架构 | 流程执行、实例状态和编排属于 `L1-process` / runtime,不属于方法定义源。 |
| 不设计成员身份和成员能力画像架构 | 成员身份、生命周期和成员实际能力属于 `L1-identity` 或相关成员仓。 |
| 不设计治理执行和授权裁决架构 | 治理裁决、policy enforce、权限系统属于 governance / security 语境。 |
| 不设计外部能力注册和访问绑定架构 | 外部工具、provider、MCP、A2A 能力注册属于 `L3-capability-hub`。 |
| 不设计 marketplace 交易履约架构 | 定价、订单、购买、结算、安装和商业履约属于 `L6-marketplace`。 |
| 不设计 UI 渲染和体验交互架构 | UI/console 负责渲染与交互,本仓仅保留视图策略定义边界。 |
| 不设计 artifact / archive 正文存储架构 | artifact、证据、归档和外部正文生命周期属于相邻仓或外部系统。 |
| 不设计认证登录、权限矩阵或操作主体鉴权实现 | 这些属于身份、安全或治理后续设计,不是方法资产架构主线。 |

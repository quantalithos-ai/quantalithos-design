## 5. 模块思考记录

### 5.1 数据归属:先思考

问题回答:

- 本仓正式 truth 只围绕方法资产定义源成立:方法资产定义、身份目录、正式化与版本、定义性关系、受控消费前提、追溯依据、分发语义和外围方法集组织语义。
- 治理结论、外部标准、下游消费影响和外部协作材料如果本地存在,只能是摘要、投影或引用关系。
- 流程执行、成员状态、治理执行、外部能力注册、marketplace 交易、UI 会话、artifact/archive 正文和鉴权实现必须明确排除。

诊断:

- 旧材料把数据所有权和实现机制混在一起,例如 fingerprint、snapshot、outbox、audit record、PostgreSQL、cache、replay 等。这些名词可能在后续设计出现,但不能在 Step 8 成为数据归属主语。
- `WorkProductDefinition`、`ViewProfile`、`AIPolicy` 等定义语义与 artifact、UI、governance 执行强相关,容易让正文或执行 truth 借定义关系进入本仓。
- MethodPlugin / MethodConfiguration 当前只能作为外围增强 truth,不能扩大核心闭环。

取舍:

- 使用 4.9 的四类数据类型表达归属,不继承旧对象字段和存储名词。
- 本仓自己的读取材料虽然由本仓派生,仍作为快照 / 投影数据处理,不得成为第二 truth。
- 对未闭口的 Qualification / CapabilityDefinition 不写成核心独立 truth,仅保留待确认。

| 是否先判断正式 truth | pass | truth 集中在方法资产定义源和正式化 / 追溯语义。 |

### 5.3 一致性策略:先思考

问题回答:

- 正式 truth 内部必须强一致,否则方法资产定义、正式化、版本、关系和受控消费前提会互相漂移。
- 正式 truth 到读取材料、消费材料和下游影响摘要可以最终一致,但延迟收敛不得反向改变 truth。
- 正式 truth 与外部治理依据、标准、artifact、marketplace 和外部正文之间只能要求引用有效性或前置一致,不能要求本仓拥有外部正文。

诊断:

- 若把所有跨边界协作写成强一致,会把下游运行状态和治理执行压回本仓,破坏 Definition vs Use。
- 若把外部正文不可用写成“本仓补齐正文”,会直接形成第二 truth source。
- 若把消费材料延迟视为正式 truth 未成立,会让投影反写核心语义。

取舍:

- 内部 truth 变化失败时不形成部分完成。
- 派生读取和下游消费材料允许显式待收敛。
- 外部依据缺失时挂起或不可用,不得伪造结论、正文或下游状态。

本模块门禁:

| 检查项 | 结论 | 说明 |
|---|---|---|
| 是否从数据归属推导一致性 | pass | 一致性口径均建立在四类数据类型之上。 |
| 是否区分强一致和最终一致 | pass | 内部 truth 强一致;派生和下游承接最终一致。 |
| 是否避免实现补偿 | pass | 未写事务、outbox、retry、projection worker 或恢复脚本。 |
| 是否可进入“一致性策略:再写入” | pass | 可形成一致性策略表。 |

### 5.4 一致性策略:再写入

| 数据关系 / 场景 | 关联数据类型 | 一致性口径 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| 方法资产定义内部变化 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 明确失败,不形成部分完成的正式定义变化。 | 核心 truth 漂移会直接破坏定义源边界。 |
| 正式化与版本语义建立 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 未能同时成立时保持非正式或未完成口径。 | 正式使用语境和版本稳定必须一起成立。 |
| 定义性关系变化 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 不接受只改一侧语义的部分完成口径。 | 方法资产之间的定义关系不能靠消费仓隐式修正。 |
| 受控消费前提形成 | 正式真相数据 ↔ 正式真相数据 | 强一致 | 消费前提未成立时不得形成正式消费语义。 | 正式消费需要稳定定义、版本和边界前提共同成立。 |
| 正式 truth 到正式读取材料 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 | 读取材料可保持旧视图或显式待收敛,不得改写 truth。 | 只读承接延迟不等于正式 truth 失效。 |
| 正式 truth 到下游消费材料 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 | 下游暂未感知时保持待收敛或不可感知口径,不阻止 truth 成立。 | 受控消费不要求下游即时同步成功。 |
| 正式化依赖外部治理结论 | 正式真相数据 ↔ 快照 / 投影数据 / 引用关系数据 | 前置一致 / 引用有效性一致 | 结论缺失或不可判定时挂起正式化,不得伪造治理结论。 | 外部治理可作为前置依据,但不迁入治理执行 truth。 |
| 方法资产与外部标准来源关系 | 正式真相数据 ↔ 快照 / 投影数据 / 引用关系数据 | 引用有效性一致 / 摘要一致 | 来源缺失时显式未知或不可用,不得复制标准正文补齐 truth。 | 标准来源支撑说明和追溯,不属于本仓正文。 |
| 方法资产与外部正文关系 | 正式真相数据 ↔ 引用关系数据 | 引用有效性一致 | 引用失效时显式失效或挂起相关能力,不得复制正文补齐。 | 引用关系有效不等于本仓拥有正文。 |
| 方法资产与 artifact / archive 关系 | 正式真相数据 ↔ 引用关系数据 | 引用有效性一致 | 引用缺失或不可用时保持显式不可用,不吸收 artifact 正文。 | WorkProductDefinition 与制品正文必须分离。 |
| 下游消费影响承接 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 / 摘要一致 | 下游影响摘要缺失时保留未知或待确认口径,不得读取下游内部状态补齐。 | 本仓只承接正式摘要,不拥有下游运行 truth。 |
| 外围包 / 方法集组织与核心定义 | 正式真相数据 ↔ 正式真相数据 | 边界内强一致 | 不满足核心定义引用时不形成有效外围组织语义。 | 外围增强不能独立漂移为第二方法资产来源。 |
| 本仓与明确不拥有正文的边界 | 引用关系数据 ↔ 明确不拥有的正文 / 真相 | 边界约束一致 | 不回填为本仓 truth;必要时挂起、拒绝或显式不可用。 | 外部正文和运行 truth 只能被引用或排除。 |
| 技术承载与核心 truth 关系 | 正式真相数据 ↔ 快照 / 投影数据 | 承载一致 | 承载材料不可用时不能反向改变核心语义。 | 技术承载只支持保存和读取,不定义业务 truth。 |

#### 5.4.1 数据边界说明

`L3-method-library` 的数据所有权以方法资产定义 truth 为中心,本地存在的读取材料、摘要和引用都不能被误读成第二 truth source。治理、标准、artifact、marketplace、console / SDK、process、identity、runtime、member-images 等相关关系只能通过正式摘要、引用或消费材料进入,不得把它们的正文和运行状态保存为本仓数据。正式 truth 内部变化要求强一致,跨边界读取、下游消费和外部摘要承接允许最终一致或引用有效性一致。当前 Step 不决定数据库、缓存、投影、事件、outbox、事务或重试实现。

                         |
                         | 派生 / 承接
                         v
+--------------------------------------------------+
| 快照 / 投影数据                                  |
| 读取材料 / 治理摘要 / 标准摘要 / 下游影响摘要    |
+------------------------+-------------------------+
                         |
                         | 只保存关系
                         v
+--------------------------------------------------+
| 引用关系数据                                     |
| 治理 / 标准 / 外部正文 / artifact / marketplace  |
+------------------------+-------------------------+
                         |
                         | 明确不拥有
                         v
+--------------------------------------------------+

- 正式真相数据是本仓数据边界的中心,其他数据存在都不得反向改写它。
- 快照 / 投影数据可以支撑读取和消费,但只能从 truth 派生或从外部正式摘要承接。
- 引用关系数据只保存关系,不保存外部正文。
- 明确不拥有的正文 / 真相不得因引用、快照或运行需要进入本仓。

### 5.5 架构单元数据规则:先思考

问题回答:

- Step 5 的核心子域拥有正式 truth;支撑子域拥有围绕核心存在的定义性 truth 或外围增强 truth;本地索引 / 投影 / 引用单元只拥有影子、摘要或引用关系。
- 外部依据摘要与引用、下游消费影响摘要最容易被误读为外部 truth 入仓,因此必须在单元级明确 forbidden body。
- 每个架构单元的数据规则都必须能回到职责边界和依赖方向,不能靠旧对象清单推导。

诊断:

- “外部依据摘要与引用”不是治理、标准、artifact 或 marketplace 的本地子系统。
- “下游消费影响摘要”不是 process、identity、runtime 或 member-images 的同步副本。
- “方法资产包与方法集组织语义”可作为外围增强 truth,但不能让 marketplace 交易或组织运行状态入仓。

取舍:

- 按 Step 5 的 8 个架构单元逐项列出 truth、snapshot / projection、reference 和 forbidden body。
- 每个单元都给停审结论,避免后续 Step 9 通信方式讨论时重新串线。

本模块门禁:

| 检查项 | 结论 | 说明 |
|---|---|---|
| 是否覆盖 Step 5 单元 | pass | 覆盖 4 个核心子域、2 个支撑子域、2 个本地影子边界。 |
| 是否逐单元定义 forbidden body | pass | 每个单元均明确不拥有的正文 / truth。 |
| 是否避免重划子域 | pass | 只给既有架构单元补数据规则。 |
| 是否可进入“架构单元数据规则:再写入” | pass | 可形成架构单元数据所有权表和停审记录。 |

| 正式 truth 到正式读取材料 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 | 读取材料可保持旧视图或显式待收敛,不得改写 truth。 | 只读承接延迟不等于正式 truth 失效。 |
| 正式 truth 到下游消费材料 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 | 下游暂未感知时保持待收敛或不可感知口径,不阻止 truth 成立。 | 受控消费不要求下游即时同步成功。 |
| 正式化依赖外部治理结论 | 正式真相数据 ↔ 快照 / 投影数据 / 引用关系数据 | 前置一致 / 引用有效性一致 | 结论缺失或不可判定时挂起正式化,不得伪造治理结论。 | 外部治理可作为前置依据,但不迁入治理执行 truth。 |
| 方法资产与外部正文关系 | 正式真相数据 ↔ 引用关系数据 | 引用有效性一致 | 引用失效时显式失效或挂起相关能力,不得复制正文补齐。 | 引用关系有效不等于本仓拥有正文。 |
| 下游消费影响承接 | 正式真相数据 ↔ 快照 / 投影数据 | 最终一致 / 摘要一致 | 下游影响摘要缺失时保留未知或待确认口径,不得读取下游内部状态补齐。 | 本仓只承接正式摘要,不拥有下游运行 truth。 |
| 本仓与明确不拥有正文的边界 | 引用关系数据 ↔ 明确不拥有的正文 / 真相 | 边界约束一致 | 不回填为本仓 truth;必要时挂起、拒绝或显式不可用。 | 外部正文和运行 truth 只能被引用或排除。 |

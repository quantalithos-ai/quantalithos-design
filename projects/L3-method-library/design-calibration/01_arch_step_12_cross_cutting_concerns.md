## 4. 模块思考记录

### 4.1 横切类别:先思考

问题回答:

- 本仓真正需要进入架构层的横切关注点是安全边界、审计与可追溯、可观测性、韧性 / 恢复能力、性能 / 容量约束、配置与变更控制、兼容性 / 演进控制。
- 这些要求都横切方法资产定义 truth、正式化、稳定版本、受控消费、追溯、异步传播、后台维护和外围增强边界。
- “安全、性能、观测”只有在影响多个架构单元、边界或交互时才进入本章;单点实现要求不能提升为横切结论。

诊断:

- 旧架构材料里有 trace 字段、actor、gate、fingerprint、outbox、cache TTL、batch size、P95、告警阈值和恢复动作。
- 这些方向有后续价值,但当前若直接继承,会把横切关注点写成实现手册。
- 需求 NFR 已明确不授权具体指标名、缓存策略、监控配置或测试脚本。

取舍:

- 保留横切约束与判断口径。
- 不保留具体实现承载、字段、指标、配置项或运行步骤。
- 所有横切项都必须回答作用范围、约束要求和保护目标,否则不进入本章。

### 4.2 横切类别:再写入

| 横切关注点 | 作用范围 | 约束要求 | 保护目标 | 说明 |
|---|---|---|---|---|
| 安全边界 | 外部入口、外部依据、下游消费、核心 truth、引用 / 摘要边界 | 外部能力和下游消费必须通过正式边界进入或使用,不得直接触达、替代或改写核心方法资产定义。 | 保护 Definition vs Use 和方法资产定义 truth。 | 该要求持续作用于职责、依赖、数据和交互,不是单个接口鉴权规则。 |
| 审计与可追溯 | 正式化、版本语义变化、消费影响变化、外部依据承接、正式消费读取 | 关键判断和关键变化必须留下可追溯依据,不得只保留瞬时结果或下游本地约定。 | 保护正式版本、消费一致性和边界争议审查能力。 | 该要求横切数据、交互和验收,不是日志字段清单。 |
| 可观测性 | 同步裁定、异步传播、后台收敛、读取材料、引用 / 摘要缺失和外围不可用 | 架构必须能判断关键状态是否成立、传播是否待承接、材料是否待收敛、失败是否显式暴露。 | 保护主线是否按预期成立的可见性。 | 该要求不是监控平台配置,而是对架构状态可见性的约束。 |

| 性能 / 容量约束 | 目录识别、正式定义读取、受控消费、变化传播、后台维护 | 不得让读取材料缺失、同步等待下游或外围增强前置导致核心消费路径不可接受地放大或阻塞。 | 保护核心下游消费和同步裁定边界。 | 当前只给架构判断口径,不继承旧 P95、QPS 或 cache 参数。 |
| 配置与变更控制 | 正式化规则、版本变化、外围能力启用、外部依据接入、传播 / 维护策略 | 配置或变更不得绕过核心边界、改变 truth 归属、隐式正式化资产或把外围增强升级为核心前置。 | 保护已收稳架构主线不被配置层绕开。 | 该要求不是配置项清单,而是对变更控制边界的架构约束。 |
| 兼容性 / 演进控制 | 正式版本、下游消费材料、外部引用、外围增强进入、后续资产范围变化 | 影响正式引用、消费材料或资产范围的变化必须显式承接,不能静默破坏既有消费语义。 | 保护长期引用稳定和后续演进可控。 | 该要求承接稳定版本与显式变化机制,不指定 schema version 或算法。 |

### 4.3 架构单元适用性:先思考

问题回答:

- 核心子域最强调安全边界、审计追溯、配置 / 变更控制和兼容性 / 演进控制。
- 受控消费和追溯一致性同时需要可观测、韧性和性能口径,否则下游消费材料、影响摘要和恢复状态会不可解释。
- 支撑 / 引用类单元强调引用有效性、外部摘要缺失和外围不可用时的显式处理。

诊断:

- 如果所有单元都写“适用全部横切项”,就失去审查价值。
- 不同单元的主要风险不同:定义单元怕外部 truth 污染,读取单元怕材料过期不可见,引用单元怕外部正文复制,外围单元怕反向拖垮核心。

取舍:

- 逐架构单元写重点横切项,并说明停审结论。
- 非重点项不强行罗列。

### 4.4 架构单元适用性:再写入

| 架构单元 | 重点横切关注点 | 约束要求 | 停审结论 |
|---|---|---|---|
| 方法资产定义与目录语义 | 安全边界、配置与变更控制、兼容性 / 演进控制 | 不得由外部入口、下游消费或配置变化隐式改变定义 truth 或目录身份。 | 通过 |
| 正式化与版本语义 | 审计与可追溯、安全边界、配置与变更控制、兼容性 / 演进控制 | 正式化和版本变化必须显式、可追溯,不得由治理执行或配置开关绕过。 | 通过 |
| 受控消费语义 | 性能 / 容量约束、安全边界、兼容性 / 演进控制 | 下游按边界消费,不得绑定核心 truth 结构或静默破坏正式引用。 | 通过 |
| 追溯与一致性保护语义 | 审计与可追溯、可观测性、韧性 / 恢复能力 | 消费影响、追溯材料和恢复状态必须可见、可解释、可延后收敛。 | 通过 |

| 外部依据摘要与引用 | 安全边界、审计与可追溯、韧性 / 恢复能力 | 外部依据只能以摘要 / 引用承接;缺失或失效时显式挂起、未知或不可用。 | 通过 |

## 5. 跨横切约束审计

### 5.1 审计思考

问题回答:

- 横切约束不能和 Step 8 / 9 冲突:审计不能变成外部正文入仓,可观测不能变成第二 truth,韧性不能伪造成功,性能不能牺牲正式化一致性,配置不能绕过边界或改变主线。
- 旧材料中“cache 不可用回源”“outbox backlog”“fingerprint drift”等有方向价值,但都已经超出当前架构横切层。

取舍:

- 在跨横切审计中明确禁区。
- 具体指标、日志、配置、恢复步骤和测试切口留给后续 03/04/05/06/07。

## 7. 回填草稿

### 13. 横切关注点

> 校准来源:
> - `design-calibration/01_arch_step_12_cross_cutting_concerns.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/01_arch_step_12_cross_cutting_concerns.md` 的“模块思考记录”“跨横切约束审计”和“旧材料差异审计”小节,了解本章横切约束如何从目标、数据、交互、技术机制和方案取舍收敛。

#### 13.1 横切关注点约束

| 横切关注点 | 作用范围 | 约束要求 | 保护目标 | 说明 |
|---|---|---|---|---|
| 安全边界 | 外部入口、外部依据、下游消费、核心 truth、引用 / 摘要边界 | 外部能力和下游消费必须通过正式边界进入或使用,不得直接触达、替代或改写核心方法资产定义。 | 保护 Definition vs Use 和方法资产定义 truth。 | 持续作用于职责、依赖、数据和交互。 |
| 审计与可追溯 | 正式化、版本语义变化、消费影响变化、外部依据承接、正式消费读取 | 关键判断和关键变化必须留下可追溯依据,不得只保留瞬时结果或下游本地约定。 | 保护正式版本、消费一致性和边界争议审查能力。 | 横切数据、交互和验收。 |
| 可观测性 | 同步裁定、异步传播、后台收敛、读取材料、引用 / 摘要缺失和外围不可用 | 架构必须能判断关键状态是否成立、传播是否待承接、材料是否待收敛、失败是否显式暴露。 | 保护主线是否按预期成立的可见性。 | 不等同于监控平台配置。 |
| 韧性 / 恢复能力 | 异步传播、后台维护、读取材料、外部引用、下游影响摘要、外围增强 | 可恢复失败必须允许挂起、延后承接、待恢复或显式不可用,不得伪装为已完成或改写 truth。 | 保护失败后的正式恢复边界和 truth 稳定性。 | 横切通信方式和数据一致性。 |
| 性能 / 容量约束 | 目录识别、正式定义读取、受控消费、变化传播、后台维护 | 不得让读取材料缺失、同步等待下游或外围增强前置导致核心消费路径不可接受地放大或阻塞。 | 保护核心下游消费和同步裁定边界。 | 当前只给架构判断口径,不固定数值。 |
| 配置与变更控制 | 正式化规则、版本变化、外围能力启用、外部依据接入、传播 / 维护策略 | 配置或变更不得绕过核心边界、改变 truth 归属、隐式正式化资产或把外围增强升级为核心前置。 | 保护已收稳架构主线不被配置层绕开。 | 不是配置项清单。 |
| 兼容性 / 演进控制 | 正式版本、下游消费材料、外部引用、外围增强进入、后续资产范围变化 | 影响正式引用、消费材料或资产范围的变化必须显式承接,不能静默破坏既有消费语义。 | 保护长期引用稳定和后续演进可控。 | 不指定 schema version 或算法。 |

#### 13.2 横切影响说明

这些横切关注点进入架构层,是因为它们持续作用于多个边界、交互和数据关系。安全、审计、观测、韧性、性能、配置和兼容性都直接保护方法资产定义 truth、稳定版本和受控消费,不能只留给实现层或运维层事后补齐。当前不写指标、日志、配置、权限矩阵或恢复脚本,因为那些内容需要在后续详细设计、配置、测试和实施文档中按已收稳边界继续落码。

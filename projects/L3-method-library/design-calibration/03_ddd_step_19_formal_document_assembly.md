## 3. SOP 问题回答

1. 正式文档是否按书写规范章节主链组织？

   回答：当前旧版 `03-详细设计.md` 不是新版 18 章主链。正式回填后应改为 `§1~§18`，其中 `§5 模块实现契约` 是正文核心，`§6 全局对象 / Trait / API 索引` 只提供查找入口，`§7~§15` 展开协议、处理流、状态、数据、错误、并发、配置、观测和测试切口。

2. 第 5 章是否以模块为主轴？

   回答：正式文档必须以 Step 5 确认的 13 个实现模块为主轴：`domain::content`、`domain::definitions`、`domain::policies`、`contracts`、`application::command_services`、`application::sync_services`、`application::query_services`、`application::operations_services`、`application::ports`、`infra::persistence`、`infra::outbound_adapters`、`api`、`worker`。每个模块内写对象、trait、函数、错误、持久化或测试切口，不再把对象和函数堆到全局章节。

3. 对象、trait、协议、处理流、状态机是否互相可回指？

   回答：需要在正式文档中建立回指关系。对象在 §5 模块内定义，在 §6 进入索引；协议在 §7 定义，在 §8 的逐接口处理流中引用；状态机在 §9 定义，§8 / §10 / §11 / §12 需要回指状态变化、事务边界和错误分支；测试切口在 §15 按模块与接口回指前文章节。

4. 其他 agent 是否可以按本文 1:1 实现代码？

   回答：正式文档回填后应达到可 1:1 实现。关键判断标准是：文件路径明确、对象字段有类型和中文 Rustdoc 说明、函数签名有参数类型和返回类型、trait / port / adapter 有边界、每个 Command / Query / Event / Job 有协议和处理流、状态转换和事务边界可直接转代码、错误码和测试切口可直接转断言。

5. 是否有内容误放到测试方案、实施计划、配置设计或运维手册？

   回答：需要裁剪。完整测试策略、CI、fixture、覆盖率目标应留给 `05-测试方案.md`；开发顺序、任务拆分、提交计划应留给 `07-实施计划.md`；完整环境变量、secret、TLS、retry 曲线应留给 `04-配置设计.md`；告警阈值、dashboard、runbook 应留给运维相关文档。正式 03 只保留代码实现需要的绑定点、测试切口、埋点契约和实施承接清单。

## 1. 与上游文档的关系声明

> 校准来源：
> - `design-calibration/00_req_step_01_upstream_relation.md`
>
> 延伸阅读：
> - 建议阅读上述文件的“来源映射表”“持续 blocker 承接”“回填草稿”和“待确认事项”小节。

`L4-archive` 承接全局依赖与裁剪规则、已停审的 `L1-workspace` 正式 00~07、各 L1 truth owner 的当前正式边界、`L1-artifact` 的制品/版本/血缘 authority、`L4-observability` 的审计/观测 authority，以及 `L0-core`、`L0-bus`、`L0-sdk` 的共享契约、事件传递和访问边界。

本文只把上游允许归档的 approved snapshot/export/ref、版本/水位/fence/coverage、正式治理决定和获准审计材料，收束为归档请求与作业、Archive Bundle/manifest、内容闭包、完整性与兼容状态、存储/生命周期执行记录、恢复计划/材料和 owner handoff 结果。本文不重新定义 identity、conversation、work、process、governance、artifact、workspace 或 observability 的业务真相、授权、状态或正文，也不把 workspace projection 升格为 canonical truth。

## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_position_boundary.md`
>
> 延伸阅读：
> - 建议阅读上述文件的“问题回答”“拥有与不拥有”“边界声明表”和“回填草稿”小节。

| 边界项 | 结论 |
|---|---|
| 一句话定义 | `L4-archive` 是受控的跨域归档与恢复材料边界，管理请求/作业、Bundle/manifest、来源绑定、内容闭包、完整性/存储状态、生命周期执行记录、恢复计划/材料及 owner handoff。 |
| 单独成仓原因 | 让长期保存、验证、取回和恢复交接独立于活跃业务 truth，并提供统一、可追溯的包边界。 |
| 本仓拥有 | 归档请求与作业、Archive Bundle/manifest/切片清单、source binding/capture/coverage、closure/integrity/compatibility 结果、存储与生命周期执行状态、恢复请求/计划/材料、handoff/outcome/retry/compensation 记录。 |
| 本仓不拥有 | identity、conversation、work、process、governance、artifact、workspace、observability 的业务 truth、正文、授权裁决、项目状态或事件 carrier truth。 |
| 外部位置 | 对象存储、签名/KMS、压缩、密钥与产品 UI 均为外部能力或适配边界，不在本仓拥有。 |

Archive 只消费正式决定并执行受控归档/恢复材料流程；它不能自行决定项目 archived/dissolved/restored、保留期限、legal hold、删除授权、风险接受、销毁权限或 owner 的业务提交结果。

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：
> - 建议阅读上述文件的“问题证据”“业务问题与技术问题”“历史材料诊断”和“回填草稿”小节。

平台业务事实由多个 owning domain 持有，而归档、审计、争议复盘和灾难恢复需要一份能够说明来源、覆盖、完整性和交接结果的历史材料包。当前缺少统一的归档请求、逐源 source binding、内容闭包、完整性/兼容状态、存储位置状态、恢复计划和 owner handoff 记录。

主要业务问题是：无法证明一份历史材料包涵盖了哪些来源、版本和范围，哪些内容可信，谁批准了保存或删除，以及恢复后哪些 owner 实际接受了哪些材料。主要技术问题是：多来源 snapshot/export/ref 的 fence、coverage、schema/version、digest/signature、storage commit 和 restore feedback 尚未形成统一可判别的消费合同。

旧 README 中的规模、耗时、SLA、保留年限和供应商信息没有当前 workload、policy 或 measurement authority，因此不作为本需求的量化依据。

### 4.2 非目标

| 非目标 | 归属/原因 |
|---|---|
| 拥有或反写任何 L1 业务 truth、项目状态或治理决定 | 归各 owning domain / governance。 |
| 自动生成 SoA、AIIA、Conformance Claim 或合规结论 | 归 governance/明确 owner；Archive 只保存获准 decision/ref。 |
| 固定六域强制收集、固定七年保留、自动 purge 或销毁 | 范围、RetentionPolicy、legal hold 和删除授权均需正式输入。 |
| 一键恢复 Active、发布 `project.restored` 或直接写上游数据库 | 恢复必须通过 owner-specific import/restore/command/handoff。 |
| 通用 Artifact 正文/血缘、完整 observability backend、workspace canonical truth | 分别归 `L1-artifact`、`L4-observability`、各 L1 owner；workspace 仅可作明确标注的辅助快照。 |
| 跨包全文搜索、趋势/RCA、跨区域灾备编排、产品 UI、SDK cache、runtime/tools/sandbox/marketplace | 作为外围或其他项目能力，不进入本需求主链。 |

## 5. 用户与角色

| 角色 | 类型 | 使用场景 | 可执行范围 | 明确禁止 |
|---|---|---|---|---|
| 归档请求发起者 | 人类/受限系统 | 提交归档范围、依据和幂等语境。 | 发起归档请求、查看请求结果。 | 不授予 Archive 业务批准权。 |
| 恢复申请者 | 人类/受限系统 | 提交恢复范围、目标 owner、依据和兼容约束。 | 发起 restore request、查看计划/结果。 | 不直接写任何 owner truth。 |
| 归档审计者 | 人类 | 审阅 manifest、来源、闭包、验证、生命周期和 handoff。 | 只读查询与验证。 | 不修改 Bundle 或批准治理决定。 |
| Archive 运维者 | 人类/系统 | 处理迁移、取回、重试、补偿和对账。 | 执行受控后台操作、查看状态。 | 不决定保留、删除或业务恢复。 |
| Source owner provider | 外部系统 | 提供 approved snapshot/export/ref、版本/fence/coverage。 | 维护自身 truth 并返回来源结果。 | 不因提供材料转移真相所有权。 |

| Storage/integrity adapter | 外部系统 | 提供存储、摘要、签名、密钥或压缩能力。 | 返回能力和提交状态。 | 不拥有业务决定或密钥 truth。 |
| Owner restore receiver | 外部系统 | 接收 owner-specific 材料并反馈结果。 | 接受、拒绝或部分处理材料。 | 业务提交仍由 owner 决定。 |
| 下游只读 consumer | 系统 | SDK、Console、Sync、审计/法务/运营读取归档结果。 | 消费 read/export 面。 | 不把 Archive read model 当上游写权。 |

缺少正式授权或 receiver 反馈时，对应动作必须保持 blocked/unknown；本表不定义认证、token、角色继承或治理 policy 语法。

## 6. 使用方与依赖

> 校准来源：
> - `design-calibration/00_req_step_06_consumers_dependencies.md`
>
> 延伸阅读：
> - 建议阅读上述文件的“依赖裁剪表”“依赖类型分类表”“禁止依赖表”和“依赖裁剪图”小节。

### 6.1 使用方

归档/恢复操作者、审计者和 Archive 运维者是直接使用方；`L0-sdk`、Console、Sync 以及审计/法务/运营 consumer 是下游只读或操作适配方；各 L1 owner、治理 provider、存储/完整性 adapter 和 restore receiver 是协作方。

### 6.2 本仓依赖裁剪表

| 关联方 | 本仓角色 | 关系分类 | 是否主链 | 依赖失效后果 | 当前处理 |
|---|---|---|---|---|---|
| `L0-core` | 共享引用/错误/版本契约候选 | compile | 条件 | 类型无法核验 | 仅复用正式导出；未闭合不建立 path dependency。 |
| `L0-bus` | 触发与变化提示协作 | event/adapter | 是 | 触发延迟或缺失 | delivery/retry/replay truth 归 bus。 |
| L1 identity/conversation/work/process | source provider / restore receiver | runtime/ref/event | 是，逐 slice | 来源缺失或恢复阻断 | owner 返回 approved material/ref 和 coverage。 |
| `L1-governance` | decision provider | runtime/ref/event | 条件 | 生命周期/删除动作阻断 | 只消费正式 decision/ref。 |
| `L1-artifact` | Artifact material/ref provider | runtime/ref/event | 是，逐 slice | 内容闭包不成立 | 不把 ref 集合当正文闭包。 |
| `L1-workspace` | projection 辅助 provider | runtime/ref | 受限 | 辅助视图缺失 | projection 永不升格。 |
| `L4-observability` | audit/evidence provider | runtime/ref/event | 受限 | 审计材料不完整 | 只接收脱敏材料/ref。 |
| 对象存储/签名/KMS/压缩 | 外部 adapter | runtime/adapter | 条件 | location/integrity unknown | 供应商、算法、密钥保持 pending。 |
| `L0-sdk`/Console/Sync | 下游消费 adapter | adapter/ref | 否 | 消费延迟 | 不拥有 Archive truth。 |

### 6.3 依赖类型与禁止依赖

| 类型 | 本仓约束 |
|---|---|
| compile | 仅经核验的 `L0-core` 共享契约候选。 |
| runtime | owner query/export/restore、治理读取和外部设施；不共享数据库。 |
| event | bus 触发、owner 变化和受控回执；不把事件写成包内真相。 |
| ref | source、decision、artifact、audit、workspace、handoff 引用；不转移 authority。 |
| adapter | 存储、签名/KMS、SDK/product/receiver 能力；不拥有业务决定。 |
| fake | 仅用于测试替身，不证明真实接入或 readiness。 |

禁止共享 L1 表或跨域事务，禁止 projection 冒充 canonical truth，禁止把对象存储/KMS、SDK cache、UI、runtime/tools/sandbox、marketplace、capability registry 合并为本仓业务依赖，禁止 Archive 反写上游。

```text

L0-bus  --[event/adapter]-----> L4-archive
```

## 7. 核心能力闭环

> 校准来源：
> - `design-calibration/00_req_step_07_core_capability_loop.md`
>
> 延伸阅读：
> - 建议阅读上述文件的“核心能力闭环图”“能力节点表”“跨节点红线”和“回填草稿”小节。

Archive 的核心链路是：受理请求 → 逐源采集 → manifest/内容闭包 → 完整性/兼容评估 → 存储/生命周期执行 → 只读验证 → 恢复计划 → owner-specific 材料与 handoff → 逐项结果/补偿。

```text
[A1 request + scope + authority ref]
              |
              v
[A2 per-source capture + fence/version/coverage]
              |
              v
[A3 manifest + slice binding + content closure]
              |
              v
[A4 integrity + compatibility assessment]
              |
              v
[A5 storage placement + lifecycle execution seam]
              |
              +------> [A6 read / verify / audit-safe query]
              |
              v
[A7 restore request + validation + plan]
              |
              v
[A8 owner-specific material + handoff]
              |
              v
[A9 item outcome + retry / compensation / unknown]
```

| 节点 | Archive 拥有 | 进入条件 | 外部结果 | 失败上限 |
|---|---|---|---|---|
| A1 请求与范围 | request、scope、authority ref、幂等语境 | 主体/范围/依据可解释 | accepted 或 rejected/blocked | rejected/blocked |
| A2 source capture | source binding、capture attempt、coverage | owner-safe snapshot/export/ref 可调用 | 逐 source 版本/fence/coverage | partial/stale/missing/conflicting |
| A3 manifest/closure | Bundle、manifest、slice inventory、closure result | capture 结果可比对 | 闭包一致或明确缺口 | incomplete/overfull/invalid |
| A4 integrity/compatibility | verification result、兼容状态 | 正式验证输入存在 | digest/signature/version 结论 | unknown/unsupported-version/integrity-failed |
| A5 storage/lifecycle | location、tier、迁移、取回、执行记录 | 允许保存且有外部反馈 | 可取回状态和治理执行结果 | pending/unavailable/commit-unknown/blocked |
| A6 read/verify | 只读 manifest、来源、coverage、验证结果 | 有 Archive material | provenance/status read model | stale/partial/blocked |
| A7 restore planning | restore request、兼容验证、owner plan | 包验证、权限、目标 owner 可解释 | per-owner restore plan | rejected/blocked/unsupported-version |
| A8 material/handoff | owner-specific material、handoff record | plan 和 source binding 可用 | receiver handoff 状态 | partial/commit-unknown |
| A9 outcome/recovery | item outcome、retry、compensation、冲突记录 | A8 有结果或未知 | 每项结果可追溯 | conflicting/compensation-required/failed |

`sealed` 只表示 Archive 自有 closure/integrity 条件满足；`eligible` 只表示收到可解释 decision ref；`material-ready` 只表示材料可交接。三者均不能推导项目状态、治理批准、owner committed 或全局恢复成功。

|---|---|---|---|

### 14.1 一票否决项

- Archive 直接改写任一 owning domain 的业务状态、数据库或治理结论。
- 将 `sealed`、`verified`、`eligible`、`material-ready` 或局部成功解释为项目 archived/dissolved/restored、owner committed 或全局完整可信。
- 缺少 authority、范围、版本/fence/coverage、摘要/签名或授权时仍宣称完整归档或恢复成功。
- 将 workspace projection、observability 摘要、Artifact ref 或 fake 输入冒充 canonical truth/真实集成。
- 关键记录不可追溯，或对 commit-unknown 静默重放造成重复副作用。

## 2. 本次设计目标与范围

> 校准来源：

### 2.1 设计目标

| 目标 | 说明 | 交付给详细设计 |
|---|---|---|
| 双轴代码主体 | 六个业务 CP 与 Inbound/Application/Domain/Ports 实现层正交 | 可继续划分模块/文件，不机械地把 U1~U6 变成 crate/部署 |
| 归档请求到 Bundle | 稳定 request/job、source binding/capture、manifest/closure、assessment 主语 | 完整字段、函数、事务与持久化输入 |
| 存储与治理执行 | location/tier/commit/retrieval 与 decision/execution 分开 | adapter、状态映射、幂等、probe/reconcile 与配置契约 |
| owner-safe 恢复 | plan/material/handoff/outcome 按 owner/item 展开 | receiver port、逐项事务、冲突/unknown/补偿协议 |
| 接口、流程和状态闭环 | 入口有归属，关键流只用已定义对象，多轴状态不越权 | 协议 schema、完整签名、事务、错误与测试矩阵 |
| 配置与风险交接 | blocker、禁止配置化与回退层级显式 | 03/04 不暗补 authority、provider 或 readiness |

### 2.2 非范围

| 非范围 | 归属 / 后续层 |
|---|---|
| identity/conversation/work/process/governance/artifact/workspace/observability 业务 truth 和状态机 | 各 owning project |
| runtime/member/tools execution、capability registry、sandbox、marketplace、产品 UI、SDK client/cache | 相邻仓、产品或分发层 |
| 语言、数据库、对象存储、KMS、算法、压缩和 schema registry 产品选择 | blocker 关闭后由 03/04/07 核验 |
| 完整字段、序列化 schema、HTTP/topic、DDL/索引、源码目录/文件 | `03-详细设计.md` |
| 配置项、默认值、环境变量、secret 名与部署挂载 | `04-配置设计.md` |
| 完整测试、验收 verdict、实施计划、commit boundary 与 readiness | 05~07，按后续用户授权 |
| 任意保留期、销毁许可、项目 archived/restored 或 receiver committed 结论 | governance/work/receiver 正式 owner |

### 2.3 设计深度

本文点名 service/aggregate/value/history/reference/port/job 等主体骨架；关键对象独立成节，字段给概要类型，函数参数用 `TypeName param_name`。接口不定 transport schema，流程不写完整实现，配置不给实际值。外部合同缺口只交付 required seam 与 blocked/unknown/unsupported/commit-unknown 语义。

## 3. 约束条件

> 校准来源：
> - [design-calibration/02_hld_step_03_constraints.md](design-calibration/02_hld_step_03_constraints.md)
>
> 延伸阅读：
> - 阅读上述中间产物的“结构化中间产物”“回填草稿”和“待确认事项”。

| 约束 | 说明 |
|---|---|
| HC-AR-01 Archive truth 唯一 | 本仓只拥有 request/job、binding/capture、Bundle/manifest/closure、assessment、storage/lifecycle execution、restore plan/material/handoff 记录。 |
| HC-AR-02 外部材料带 authority | owner snapshot/export、workspace projection、Artifact/audit material 与 ref 必须显式分类，并绑定 source/version/fence/coverage。 |
| HC-AR-03 projection/ref 不补 canonical | workspace、audit summary、Artifact ref 或 cache 不得使 missing/partial canonical source 变 Complete。 |
| HC-AR-04 manifest-first | closure 只对固定声明集和 material/ref inventory；不静默后补、忽略越界项或覆写旧 revision。 |
| HC-AR-05 成功分轴 | closure、integrity、compatibility、storage commit/retrieval、lifecycle、handoff 使用独立对象/状态。 |
| HC-AR-06 局部成功无业务状态权 | sealed/verified/eligible/material-ready/committed 不推导 archived/dissolved/restored 或 owner committed。 |
| HC-AR-07 Query no-write | Query 不触发 capture、repair、placement、retrieval、handoff、retry 或外部写入。 |
| HC-AR-08 Event 只触发/反馈 | event arrival 不替代 authority query/export、Bundle body、delivery truth 或 commit。 |
| HC-AR-09 intent/result 分离 | storage/lifecycle/receiver 外部效果先保存可追溯意图，再独立保存 ack/commit/failure。 |
| HC-AR-10 unknown-first | commit-unknown、unknown、unsupported-version、integrity-failed 不得乐观推进；先核对，无法安全自动恢复时保留人工/补偿姿态。 |
| HC-AR-11 per-source/per-item | 一个 source/item 失败不覆盖其他结果；汇总不压平 partial/stale/missing/conflicting。 |
| HC-AR-12 decision/execution 分离 | retention/hold/delete/risk 决定只作 versioned ref；Archive 只拥有适用检查和执行反馈。 |
| HC-AR-13 Restore no-write | Bundle/plan/material 不是跨域权限；只有 owner receiver 可接受、拒绝、提交或返回未知。 |
| HC-AR-14 配置不创造 authority | 配置不生成 owner、policy、key、algorithm、receiver、许可或 success，不关闭安全/闭包/幂等 guard。 |
| HC-AR-15 依赖类别显式 | 只有核验 Core 契约可 compile；L1/L4 sibling、Bus、SDK、provider 保持 runtime/event/ref/adapter/fake。 |
| HC-AR-16 证据上限 | fake、文档自检或对象存在不证明集成、真实 Bundle/digest、测试、验收、signoff 或 readiness。 |

#### 架构模块到代码主体映射图

```text
L4-archive
├─ CP1 Request / Job       → request service + request/job truth
├─ CP2 Source Capture      → capture service + binding/attempt
├─ CP3 Manifest / Closure  → assembly service + bundle/manifest
├─ CP4 Verify / Compat     → verification service + assessments
├─ CP5 Storage / Lifecycle → placement/lifecycle services + executions
└─ CP6 Restore / Handoff    → restore service + plan/item/handoff
```

该图表达业务责任映射，不表达六个 crate、进程、部署或事务。`ArchiveQueryService` 是 CP3~CP5 的只读组合面，不是第七个 truth CP。

#### 实现分层视图

```text
command / query / trusted event / scheduled work
                      │
                      ▼
             Inbound / Operations
                      │
                      ▼
             Application Services
                      │
                      ▼
          Domain Model + Local Contracts
                      │
                      ▼
    Ports / Persistence / External Adapters
```

六 CP、四类实现层与“同步受理/读取、后台执行、异步反馈”三类运行角色是三条正交轴。Domain 不依赖 provider/SDK/sibling 实现；Port 只声明本地需求，Adapter 是否可实现受 blocker 限制。

### 5.1 组成部分总表

| CP | 核心职责 | 主要主体 | 不承担 |
|---|---|---|---|
| CP1 请求与作业协调 | 受理 archive/restore、冻结范围/依据/幂等语境、协调阶段 | ArchiveRequestService、ArchiveRequest、ArchiveJob | 不批准业务状态或治理决定 |
| CP2 来源绑定与采集 | 逐 source 获取 approved material/ref，记录 authority/fence/coverage | SourceCaptureService、ArchiveSourceBinding、CaptureAttempt | 不拥有 source truth，不用 projection/ref 补 canonical |
| CP3 Bundle 清单与闭包 | 形成 Bundle/manifest revision 并评估声明集与实际集闭合 | BundleAssemblyService、ArchiveBundle、BundleManifest | 不定义 owner schema，不以 storage/verification 反推 closure |

### 5.3 source-authority matrix

| 归档切片 / 材料类别 | canonical / formal authority | Archive 可持有的 approved 输入 | 恢复 handoff / 明确禁止 |
|---|---|---|---|
| identity | `L1-identity` | snapshot/ref + owner version/fence/coverage | 只交 `L1-identity` 正式 receiver；不拥有 identity truth/正文。 |
| conversation | `L1-conversation` | snapshot/ref + owner coverage | 只交 conversation receiver；不复制未授权对话正文。 |
| work/project | `L1-work` | Project/WorkItem snapshot/ref + lifecycle decision ref | 只交 work receiver；不改项目/成员/archived/restored 状态。 |
| process | `L1-process` | Process/Activity snapshot/ref + checkpoint ref | 只交 process receiver；不拥有运行 truth/replay 权。 |
| governance | `L1-governance` | policy/gate/decision/hold/delete/risk decision ref 或获准材料 | 只交 governance receiver；不裁决/修改政策、期限、hold、删除或风险接受。 |
| artifact | `L1-artifact` | Artifact version/lineage/baseline approved material/ref | 只交 artifact receiver；ref 不冒充正文/血缘闭包。 |
| workspace projection | `L1-workspace`（projection owner，非 canonical business authority） | 明确标记的 read-only projection snapshot/ref + revision/generation/coverage | 只作 Auxiliary/恢复辅助；不得补任何 L1 canonical slice 或回写 workspace truth。 |
| audit/evidence material | `L4-observability` | 获准、脱敏的 audit/evidence material/ref + coverage/redaction basis | 只按正式 seam 交接；摘要不冒充完整审计链，不拥有 backend truth。 |

矩阵中的 `Archive 可持有` 是材料保管和本地 provenance 权，不转移业务真相所有权。每个 source binding、manifest entry 与 restore item 必须保留 source authority、material class、owner-specific version/fence/coverage 和 target owner；不同 owner 的 opaque version 不互相比较。

### 5.4 CP1 请求与作业协调

capability 为 archive/restore admission 和 job stage coordination。代码主体为 `ArchiveRequestService`、`ArchiveRequest`、`ArchiveJob`、`ArchiveStorePort`。它向其他 CP 交付冻结 request/job context，不交付业务批准或全局成功。

### 5.5 CP2 来源绑定与采集

capability 为 source plan expansion、owner material capture 和 source reconcile。`SourceExportPort` 是 per-owner runtime port family，不表示对端 exact API 已存在。交给 CP3 的 inventory 必须保留 canonical/auxiliary/material/ref 分类。

### 5.6 CP3 Bundle 清单与闭包

capability 为 immutable manifest revision、closure evaluation 与 read composition input。闭包仅由确定声明集与实际集决定，不由签名、存储或 receiver 结果反向决定。

### 5.7 CP4 完整性与兼容评估

capability 为 fixed-input integrity assessment、target-specific compatibility assessment 和 no-write verification read。算法、key、secret、schema authority 位于外部；缺口只能形成 Unknown/Blocked/Unsupported。

### 5.8 CP5 存储与生命周期执行

capability 为 placement/retrieval、decision applicability 和 lifecycle execution/reconcile。存储 intent/result、governance decision/execution、ACK/commit 分开；本仓不选择默认 provider/tier/保留期。

### 5.9 CP6 恢复计划与交接

capability 为 plan formation、owner-specific materialization、receiver handoff、reconcile 和 compensation。每个 owner/item 独立记录 outcome；任意 Succeeded 都不把 Bundle 升格为跨域写权或业务 restored。

### 6.2 ArchiveRequest

#### 基本信息

| 项 | 内容 |
|---|---|
| 所属部分 | CP1 |
| 对象类型 | domain aggregate |
| 主要责任 | 固定归档申请的声明、依据、幂等语境与受理结果。 |

#### 关键字段骨架

| 字段 | 类型 | 作用 |
|---|---|---|
| `request_id` | `ArchiveRequestId` | 本地稳定身份。 |
| `scope` | `DeclaredArchiveScope` | 冻结声明目标/切片。 |
| `requested_by` | `ActorRef` | 主体引用，不复制 identity truth。 |
| `authority_ref` | `AuthorityRef` | 正式受理依据。 |
| `idempotency_key` / `input_digest` | `IdempotencyKey` / `SafeInputDigest` | 去重与同 key 异输入冲突。 |
| `admission` | `RequestAdmissionState` | Accepted/Rejected/Blocked。 |

#### 状态集合

| 状态 | 作用 |
|---|---|
| Accepted | 本地受理，可关联 job；不表示业务批准。 |
| Rejected | 明确不满足受理条件。 |
| Blocked | authority/owner/合同前提不可证明，fail-closed。 |

#### 成员/工厂函数骨架

| 类别 | 函数 | 作用 |
|---|---|---|

### 7.1 接口分类与共同上下文

| 类别 | 共同上下文 | 允许效果 | 禁止替代 |
|---|---|---|---|
| Command API | `ActorContext`、`CommandMetadata`、typed idempotency key、typed request | 受理/复用本地请求、作业或获准 lifecycle 意图 | 不同步声称 archive/restore 完成，不写 owner truth |
| Query API | `ActorContext`、`QueryMetadata`、typed selector | 只读组合 Archive-owned state/view | 不 capture、repair、retrieve、verify、handoff、retry 或写 cache |
| Inbound Consumer | `TrustedEventEnvelope`、`ExternalEventId`、source/schema/version/ref、消费幂等语境 | 将正式触发或反馈绑定到既有本地语境 | event arrival 不等 authority、delivery truth 或 commit |
| Operations Job | `WorkerContext`、persisted intent/attempt ref、expected version | 推进后台阶段并保存局部结果 | 不无意图调用外部效果，不盲重放 `commit-unknown` |
| Outbound Event candidate | 已提交本地事实与待核验 event envelope | 合同闭合后传播 Archive-owned posture | 不代发 owner 业务事实，不伪造 topic/receipt/readiness |

接口名是本仓稳定用例主语，不声明对端存在同名 API、event 或 job。

### 7.2 Command API（3）

| Command | 输入骨架 | 输出骨架 | Archive-owned 写入与边界 |
|---|---|---|---|
| `RequestArchive` | `ActorContext`、`CommandMetadata`、`IdempotencyKey`、`DeclaredArchiveScope`、`AuthorityRef` | `ArchiveRequestResult` | 原子写 `ArchiveRequest + ArchiveJob + initial ArchiveJobStageRecord`；Accepted 只表示本地受理。 |
| `RequestRestore` | `ActorContext`、`CommandMetadata`、`IdempotencyKey`、`ArchiveBundleRef`、`RestoreTargetOwnerSet`、`RestoreAuthorityRef` | `RestoreRequestResult` | 原子写 `RestoreRequest + ArchiveJob + initial ArchiveJobStageRecord`；Bundle/请求不授予跨域写权。 |
| `RequestLifecycleExecution` | `ActorContext`、`CommandMetadata`、`IdempotencyKey`、`BundleRevisionRef`、`GovernanceDecisionRef`、`LifecycleActionKind` | `LifecycleRequestResult` | 写 `LifecycleExecution` 和必要的初始 intent；只核验正式决定适用性，不生成 policy/hold/delete/risk 决定。 |

三个 Command 对同 key/同 digest 返回既有安全结果；同 key/异 digest 返回 conflict。若本地提交结果未知，按稳定 request/action ref 核对，不能重复产生副作用。

### 7.3 Query API（5，全部 no-write）

| Query | 输入骨架 | 读取对象 | 安全输出与边界 |
|---|---|---|---|
| `GetArchiveJobStatus` | `ArchiveJobRef` 或 `OperationRequestRef` | request/job/stage 及各 CP 已提交姿态 | `SafeArchiveJobStatusView` / `SafeNotAvailable`；不推导项目状态。 |
| `GetArchiveBundle` | `ArchiveBundleRef`、optional `ManifestRevisionId` | Bundle/manifest/entry/closure/finding | `SafeArchiveBundleView` / `SafeNotAvailable`；不自动 assembly/repair。 |
| `VerifyArchiveBundle` | `ArchiveBundleRef`、`ManifestRevisionId`、`VerificationReadSelection` | matching assessments/findings | `SafeBundleVerificationView` / `SafeNotAvailable`；“Verify”仅为读面，不触发重验。 |
| `GetRestorePlan` | `RestorePlanRef` | plan/item/handoff/outcome/compensation | `SafeRestorePlanView` / `SafeNotAvailable`；保持 per-owner 结果。 |
| `GetRestoreHandoffStatus` | `RestoreHandoffRef` 或 `RestoreItemRef` | handoff/outcome/compensation history | `SafeRestoreHandoffView` / `SafeNotAvailable`；不 probe/retry/compensate。 |

所有 Query 都先核验当前访问与披露决定，再对正文、ref、数量、provenance 和 finding 做一致裁剪。隐藏与不存在统一为 `SafeNotAvailable`；旧成功不复活已撤销权限。

### 7.4 Inbound Event Consumer（5）

| Consumer | 正式来源候选 | 本地承接 | 失败边界 |
|---|---|---|---|
| `ConsumeArchiveTrigger` | 项目状态/治理等明确 owner 的正式触发 | 去重 trigger finding，唤醒 `RequestArchive` admission | exact family 受 `AR-UP-002/003` 阻塞；不绕过 authority。 |
| `ConsumeSourceExportFeedback` | owner export/query 异步反馈 | `CaptureAttempt/Coverage/Finding` | 必须匹配 source/attempt/fence；unknown 不当 empty。 |
| `ConsumeGovernanceDecisionChange` | governance/明确 owner 决定变化 | 重新判定或阻塞相关 execution | 旧 release/delete 不覆盖新 hold；不解释 policy。 |
| `ConsumeStorageActionFeedback` | storage capability 正式反馈 | placement/lifecycle/action 保守更新 | ACK 不等 commit；重复/乱序按 action id 与 digest 核对。 |
| `ConsumeRestoreReceiverFeedback` | owner-specific receiver feedback | `HandoffOutcome` 及 item/plan 姿态 | receiver-specific；event arrival/Succeeded 不等 project restored。 |

### 7.5 Operations Job（17）

| CP | Operations Job | 持久输入与结果 | 核心边界 |
|---|---|---|---|
| CP1 | `AdvanceArchiveJob` | job + expected version → stage/posture/history | 只协调已提交局部结果。 |
| CP2 | `PlanArchiveSources` | accepted request/scope → source bindings | canonical/conditional/auxiliary 分类不可配置替换。 |
| CP2 | `CaptureArchiveSource` | binding + persisted attempt/fence → material refs/coverage/findings | 经 owner runtime port；逐 source 保存。 |
| CP2 | `ReconcileSourceCapture` | existing attempt + formal probe/result → settled/replacement-required | 不盲 recapture。 |
| CP3 | `AssembleBundleManifest` | bundle + frozen inventory → immutable manifest revision/closure | 只从已保存 CP2 结果构造。 |
| CP3 | `SealArchiveBundle` | ClosureReady bundle + fixed assessment/placement basis → Sealed/Blocked | Sealed 不等项目 archived。 |
| CP4 | `AssessBundleIntegrity` | fixed verification input → assessment/findings | 无正式 capability 时 Blocked/Unknown，不生成摘要/签名。 |
| CP4 | `AssessBundleCompatibility` | manifest/schema refs + target context → assessment/findings | 不自动迁移，不跨 target 复用。 |
| CP5 | `PlaceArchiveBundle` | persisted placement/action intent → commit/failure/unknown | intent-before-effect；timeout 进入 `CommitUnknown`。 |
| CP5 | `RetrieveArchiveBundle` | placement + retrieval intent → retrieval posture | 只更新 retrieval 轴。 |
| CP5 | `ExecuteArchiveLifecycle` | eligible execution + persisted action intent → execution result | dispatch 前重读 decision/hold。 |
| CP5 | `ReconcileExternalAction` | commit-unknown action + probe context → commit/failure/still unknown | probe-first，禁止盲重放。 |
| CP6 | `BuildRestorePlan` | accepted restore request + fixed Bundle inputs → immutable per-owner plan/items | 不创建跨域事务。 |
| CP6 | `PrepareRestoreMaterial` | item + approved entries + current eligibility → material ref/Blocked | missing/stale/conflicting/unsupported/integrity-failed 不放行。 |
| CP6 | `DispatchRestoreHandoff` | MaterialReady item + persisted handoff intent → outcome/unknown | 只经 owner-specific receiver。 |
| CP6 | `ReconcileRestoreHandoff` | commit-unknown handoff + receiver probe → terminal/still unknown | 不支持 probe 时转人工或正式补偿决定。 |
| CP6 | `ExecuteRestoreCompensation` | authorized compensation record → result/history | 不抹除原 handoff，不自行授权 reverse/cancel/retry。 |

### 7.6 Required ports（非公开 API）

| Required port | 关系分类 | 本地需求 | 合同上限 |
|---|---|---|---|
| `ArchiveStorePort` | local persistence port | request/job、manifest、assessment、action、handoff 的本地 UoW 与核对读取 | 03 才定义 repository/UoW exact methods，不预设数据库。 |
| `SourceExportPort` family | runtime + adapter + ref | owner-approved material、version/fence/coverage | `AR-UP-001/006~008` 未闭合时正向 adapter blocked。 |
| `IntegrityCapabilityPort` | runtime + adapter + ref | fixed input 的 digest/signature verification feedback | provider/算法/key/KMS 未闭合。 |
| `CompatibilityCapabilityPort` | runtime + adapter + ref | target-specific schema/version 支持反馈 | 不拥有 schema evolution authority。 |
| `GovernanceDecisionPort` | runtime + ref | 决定适用性、版本和有效性 | 不读取/复制 policy engine truth。 |
| `ArchiveStoragePort` | runtime + adapter + ref | placement/retrieval/lifecycle ack/commit/probe | provider/tier/SLA/secret 未确定。 |
| `RestoreReceiverPort` family | runtime + adapter + ref | owner-specific handoff/outcome/probe/compensation | `AR-UP-009` 未闭合时不得构造成功。 |

### 7.7 Outbound Event 候选（3）

| Candidate | 事实来源 | 明确上限 |
|---|---|---|
| `ArchiveJobPostureChanged` | 已提交 job stage/posture | 只传播本地作业姿态。 |
| `ArchiveBundleSealed` | 已提交 Bundle Sealed | 不代表项目 archived。 |
| `RestoreHandoffPostureChanged` | per-owner handoff/outcome | 不代表 owner committed 或项目 restored。 |

三类均为 candidate，不是 ready contract。是否需要 committed-fact/outbox、event family、schema 和 Bus 接入由 `AR-HLD-Q-001` 挂起；合同未闭合时不发送、不创建 delivery evidence。

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - [design-calibration/02_hld_step_08_processing_flows.md](design-calibration/02_hld_step_08_processing_flows.md)
>
> 延伸阅读：
> - 阅读上述中间产物的 30 条入口逐项处理流、CP1~CP6 停审、跨处理流一致性审计和 outbound candidate 取舍。

### 8.1 通用执行骨架

| 路径 | 处理骨架 | 必须保留的分支 |
|---|---|---|
| Command | actor/authority/idempotency → domain admission/intent → local atomic commit → safe result | rejected、blocked、same-key-different-input、version conflict、local commit unknown |
| Consumer | trusted envelope → source/event/input binding → existing-result check → domain apply → local atomic commit | duplicate、stale、conflicting、unknown、unmatched feedback |
| Operations Job | persisted intent/attempt → prerequisite/fence → external call 或 local calculation → result/reconcile → stage update | partial、unsupported、integrity-failed、commit-unknown、superseded |
| Query | current access → read committed Archive truth → redaction/visibility → safe response | not-available、partial、stale、blocked、unknown；所有分支 no-write |

外部 I/O 不进入 Archive 本地事务。外部调用前必须已有本地 attempt/intent；返回后按 expected version 和固定输入绑定提交。若外部动作后本地提交结果未知，先读本地稳定 key/ref，再做正式 probe，禁止直接重发。

### 8.2 请求受理与作业协调流

```text
RequestArchive / RequestRestore
  │ actor + metadata + typed key + declared input + authority
  ▼
current access / shape / authority / key-digest check
  ├─ invalid or unauthorized ─────────────> Rejected / Blocked
  ├─ same key + same digest ──────────────> existing safe result
  └─ new admissible input
           ▼
request.admit(...) + ArchiveJob.queue(...)
           ▼
ArchiveStorePort / one local transaction
request + job + initial stage record
           ▼
Accepted result; background work only
```

关键函数骨架：

- `ArchiveRequest.admit(ArchiveRequestId request_id, DeclaredArchiveScope scope, ActorRef actor, AuthorityRef authority_ref, IdempotencyKey idempotency_key, SafeInputDigest input_digest)`。
- `RestoreRequest.admit(RestoreRequestId request_id, ArchiveBundleRef bundle_ref, RestoreTargetOwnerSet owners, ActorRef actor, RestoreAuthorityRef authority_ref, IdempotencyKey idempotency_key, SafeInputDigest input_digest)`。
- `ArchiveJob.advance(ArchiveJobStage next_stage, ArchiveJobVersion expected_version, StageBasis basis)` 与 `ArchiveJob.recompute(JobComponentPostureSet component_postures)` 只使用已提交局部结果；stage 与 `ArchiveJobStageRecord` 同一局部事务提交。

受理成功不执行 capture、storage 或 handoff，也不形成 archived/restored 结论。

### 8.3 source capture、manifest 与 assessment 流

```text
Accepted ArchiveRequest + frozen DeclaredArchiveScope
  ▼ PlanArchiveSources
per-source ArchiveSourceBinding
  │ canonical owner / conditional / auxiliary classification
  ▼ CaptureArchiveSource
persist CaptureAttempt ── external owner export ──> result/probe
  ▼
material refs + owner version/fence + CaptureCoverage + findings
  ▼ AssembleBundleManifest
declared entries vs actual approved entries
  ▼ ManifestClosure.evaluate(...)
immutable BundleManifest revision
  ├─ non-Complete ─────────────────────────> Blocked / new explicit revision
  └─ Complete
       ▼ AssessBundleIntegrity / Compatibility
fixed-input assessments
       ▼ SealArchiveBundle
Archive-owned Sealed only when required fixed inputs pass
```

关键函数与 fence：

- `CaptureAttempt.start(CaptureAttemptId attempt_id, SourceBindingId binding_id, OptionalSnapshotFenceRef requested_fence)` 必须先保存；`settle(ArchivedMaterialRefSet materials, SourceVersionRef version, CaptureCoverage coverage)` 只接受匹配 binding/attempt 的 owner 反馈。
- `CaptureCoverage.assess(DeclaredScopeRef declared_scope_ref, OwnerCoverageEvidence evidence, SourceCaptureFindingRefSet findings)` 不按 material count 或跨 owner 版本排序推导 Complete。
- `ManifestClosure.evaluate(ManifestRevisionId revision, ManifestEntrySet declared_entries, ManifestEntrySet actual_entries)` 对确定集合纯计算；修正通过新 revision，不回源隐式修复。
- `VerificationAssessment.settle(IntegrityCapabilityFeedback feedback)` 与 compatibility assessment 必须绑定 exact manifest/material revision 和 target context；旧 revision 结果不可复用。
- `ArchiveBundle.seal(BundleSealBasis seal_basis, ArchiveBundleVersion expected_version)` 只核对同一 fixed revision 的 required basis；任何 required Unknown/Blocked/Failed 都拒绝推进。

workspace projection、Artifact ref 与 observability material 在入口、manifest 和读取中保持原类别；它们不能补 canonical/body/lineage/audit-chain 缺口。

### 8.4 storage placement 与 lifecycle 外部效果流

```text
fixed Bundle revision + formal decision (if lifecycle)
  ▼ current applicability / hold / input checks
ArchivePlacement.intend(...) or LifecycleExecution + ExternalActionRecord
  ▼ local commit: stable action id + key + intent digest
ArchiveStoragePort call outside transaction
  ├─ definite commit ───────────────> Committed
  ├─ definite failure ──────────────> Failed
  ├─ acknowledgement only ─────────> Acknowledged / Dispatched
  └─ timeout or ambiguous result ──> CommitUnknown
                                       ▼
                           ReconcileExternalAction
                           local lookup + formal probe
```

`ExternalActionRecord.record_intent(ExternalActionId action_id, ExternalActionTargetRef target_ref, ExternalIdempotencyKey idempotency_key, SafeInputDigest intent_digest, ExternalAttemptNumber attempt_no)` 是所有 storage/lifecycle 副作用的先决条件。`LifecycleExecution.reconcile(ExternalActionProbeResult probe_result)` 只能把正式 probe 映射成 committed/failed/still-unknown；不支持 probe 时保持未知并等待正式人工/补偿决定。

`RetrieveArchiveBundle` 只改变 retrieval 轴；Requested 不等 Retrievable，placement Committed 也不证明当前可取回。危险 lifecycle action 派发前必须重读 `GovernanceDecisionRef` 的适用性/版本/hold 冲突；Archive 不解释或创造决定。

### 8.5 per-owner restore 与 handoff 流

```text
Accepted RestoreRequest + fixed Bundle revision + explicit owners
  ▼ BuildRestorePlan
immutable RestorePlan revision + per-owner RestoreItem
  ▼ per item: closure / integrity / compatibility / retrieval / authority
PrepareRestoreMaterial
  ├─ missing/stale/conflicting/unsupported/integrity-failed ─> Blocked
  └─ approved minimal owner material ─────────────────────────> MaterialReady
       ▼ persist RestoreHandoff intent
       ▼ owner-specific RestoreReceiverPort call
       ├─ success/reject/fail ─────────> HandoffOutcome
       └─ ambiguous/timeout ───────────> CommitUnknown
                                           ▼
                              probe / authorized compensation
```

关键函数骨架：

- `RestorePlan.freeze(RestoreItemRefSet item_refs, RestorePlanRevision plan_revision)` 固定 item 集；输入变化创建新 revision。
- `RestoreItem.bind_material(RestoreMaterialRef material_ref, RestoreEligibilityBasis basis)` 只绑定 target-owner 最小材料；Bundle/ref 不转化为写权。
- `RestoreHandoff.record_intent(RestoreHandoffId handoff_id, RestoreItemId item_id, RestoreReceiverRef receiver_ref, RestoreMaterialRef material_ref, ReceiverIdempotencyKey idempotency_key, SafeInputDigest input_digest)` 必须先于 receiver 调用。
- `HandoffOutcome.observe(HandoffOutcomeId outcome_id, RestoreHandoffId handoff_id, ReceiverFeedback feedback, RecordedAt observed_at)` 记录 Archive 观察，不替代 owner 当前 truth。
- `CompensationRecord.plan(CompensationRecordId compensation_id, RestoreHandoffRef handoff_ref, CompensationAuthorityRef authority_ref, CompensationAction action)` 只接受正式处置依据。

每个 owner/item 独立提交 outcome；单项 Succeeded、全部 `HandoffComplete` 或补偿 Completed 都不设置 owner/project restored 状态。

### 8.6 Consumer 与乱序反馈处理

| Consumer | 输入绑定顺序 | 本地事务 | 不匹配/乱序处置 |
|---|---|---|---|
| archive trigger | trusted source → event id → decision/version → admission authority | dedupe/trigger finding 或 admission 唤醒语境 | quarantine/safe blocker；不直接建 Completed job |
| source feedback | source binding → attempt → fence/version → coverage/material refs | attempt + coverage + findings | 不跨 attempt；unknown 不当 missing/empty |
| governance change | owner/version/validity → affected targets | per-target re-evaluation | fan-out 不宣称全局原子；新 hold 优先 |
| storage feedback | action id → target → key/digest/attempt | action + placement/execution result | unmatched quarantine；ACK/transport success 不升格 commit |
| receiver feedback | owner receiver → handoff → material/input digest | outcome + handoff + item + plan posture | 不跨 owner/item；重复结果稳定，冲突显式 |

Consumer 只有在 exact event family 和可信 envelope 合同闭合后才能接入；当前名称不构成 Bus schema 或订阅 readiness。

### 8.7 no-write 读取流

```text
typed Query + ActorContext
  ▼
current authorization / purpose / disclosure check
  ▼
read committed Archive-owned records at requested revision
  ▼
input-match + multi-axis composition + uniform redaction
  ▼
safe view or SafeNotAvailable

No capture / verify / retrieve / repair / retry / handoff / cache write
```

五个 Query 使用同一约束，但分别由 §7.3 点名的对象组成。查询可安全暴露 Partial/Stale/Missing/Conflicting/Unsupported/IntegrityFailed/CommitUnknown，却不得把未知压成默认值；无记录不证明外部回滚。

### 8.8 一致性切面与处理流覆盖

| 切面 | 写前固定 | 外部调用 | 写后核对 | 恢复姿态 |
|---|---|---|---|---|
| request/job | key + input digest + authority + scope | 无 | request/job/stage 同事务 | local commit unknown 读回 |
| capture | binding + attempt + optional fence | owner export/query | attempt/version/coverage input match | new attempt/supersede 显式 |
| manifest/assessment | immutable manifest/input revision | integrity/compatibility capability | assessment 只适用固定输入 | 新 revision/new assessment |
| placement/lifecycle | target + action id + key/digest + decision version | storage capability | ack/commit 分层 | probe-first/authorized compensation |
| restore handoff | plan/item/material/receiver + key/digest | owner receiver | per-owner outcome input match | probe/manual/authorized compensation |

正式入口覆盖为 3 Command、5 Query、5 Consumer、17 Job。required ports 是这些流的需求接缝，不是已实现外部 API；outbound candidates 在合同闭合前没有合法 publisher 成功流。

## 9. 状态定义与状态流转

> 校准来源：
> - [design-calibration/02_hld_step_09_state_machine.md](design-calibration/02_hld_step_09_state_machine.md)
>
> 延伸阅读：
> - 阅读上述中间产物的 CP1~CP6 逐轴状态表、允许/禁止迁移、跨轴传播图和一致性审计。

### 9.1 状态主语与总原则

本仓不存在“全局归档状态机”。状态必须带对象或轴语境；同名 `Blocked`、`Failed`、`Completed` 不共享含义。持久迁移只能由 §7/§8 的 Command、Consumer 或 Operations Job 触发；Query 只派生响应。

| CP | 状态主语 / 轴 | 不代表什么 |
|---|---|---|
| CP1 | request admission；ArchiveJob stage/posture | 业务批准、项目 archived/restored |
| CP2 | source binding；capture attempt；coverage | source truth 生命周期、跨 owner 统一版本 |
| CP3 | Bundle；immutable manifest revision；closure | 完整性、storage commit、项目状态 |
| CP4 | verification；target-specific compatibility | 业务真实性、schema authority、receiver 成功 |
| CP5 | placement；retrieval；lifecycle execution；external action | governance/provider truth |
| CP6 | restore plan；item；handoff；compensation | owner business commit、全域 restored |

### 9.2 CP1 request admission 与 job

请求 admission 在创建时确定为 `Accepted | Rejected | Blocked`，不原地从 Rejected/Blocked 变 Accepted；前提变化创建明确新请求语境，幂等读回不产生迁移。

```text
Queued ── legal stage start ──> Running
Running ├─ mixed/incomplete local results ──> Partial
        ├─ missing formal prerequisite ─────> Blocked
        ├─ definite current failure ────────> Failed
        └─ all required local endpoints committed ─> Completed
Partial ── explicit advance ────────────────> Running / Blocked / Failed / Completed
Blocked ── same frozen input formally unblocked ───> Running
```

禁止 Rejected 请求创建 job、Query 推进 job、Completed 回到 Running，或以单 CP success 推导 Completed。ArchiveJob Completed 只是本仓作业终点。

### 9.3 CP2 binding、capture 与 coverage

```text
ArchiveSourceBinding
Planned ├─ formal authority/contract bound ─> Bound
        ├─ prerequisite absent/conflicting ─> Blocked
        └─ explicit replacement ────────────> Retired
Blocked ── formal resolution ───────────────> Bound
Bound ─── explicit replacement ─────────────> Retired

CaptureAttempt
Requested ── capture starts ──> InProgress
InProgress ├─ formal result ──> Settled
           ├─ missing prerequisite ─> Blocked
           ├─ definite failure ─────> Failed
           └─ explicit replacement ─> Superseded
```

Retired/Superseded 不原地复活。Blocked attempt 仅在同一固定 binding/fence 仍成立时恢复，否则创建新 attempt。timeout 或本地提交未知不直接写 Failed。

`CaptureCoverage = Complete | Partial | Missing | Stale | Conflicting | Unknown`。Complete 必须由该 owner 对声明范围的正式覆盖证明形成；Missing 不能由空响应推导，Stale 不跨 owner 比版本，任何非 Complete 不得由材料数量或 projection/ref 补齐。

### 9.4 CP3 Bundle、manifest revision 与 closure

```text
Draft ── assembly begins ──> Assembling
Assembling ├─ Complete closure ───────> ClosureReady
           ├─ missing proof ─────────> Blocked
           └─ definite assembly fail ─> Failed
ClosureReady ── all fixed seal guards pass ─> Sealed
Blocked ── new immutable manifest revision ─> Assembling
```

已固定 `BundleManifest` 不迁移；修正创建由 `previous_revision_ref` 串联的新 revision。`ManifestClosure = Complete | Incomplete | Overfull | Invalid | Unknown`，且 closure 状态只由该 revision 的声明集与实际集决定。Sealed 为本仓封存状态，不等于项目 archived，也不保证未来可恢复。

### 9.5 CP4 verification 与 compatibility

```text
VerificationAssessment
Pending ── assessment starts ──> InProgress
InProgress ├─ formal valid feedback ─────> Verified
           ├─ mismatch/invalid signature ─> IntegrityFailed
           ├─ insufficient feedback ──────> Unknown
           └─ capability/key/input absent ─> Blocked
```

`CompatibilityAssessment = Supported | Unsupported | Unknown | Conflicting`，并绑定确定 manifest revision 和 `CompatibilityTargetContext`。两类 assessment 都是不可变结果；重验、新 revision、新 reader/receiver context 建立新 assessment。Unknown/Blocked/Unsupported 不可由配置或 fake 提升为通过。

### 9.6 CP5 placement、retrieval 与 lifecycle

```text
ArchivePlacement / placement axis
IntentRecorded ── dispatch ──> Dispatched
Dispatched ├─ formal commit ────────> Committed
           ├─ uncertain result ─────> CommitUnknown
           ├─ missing prerequisite ─> Blocked
           └─ definite failure ─────> Failed
CommitUnknown ── formal probe ──────> Committed / Failed / CommitUnknown

ArchivePlacement / retrieval axis
NotRequested ── retrieval intent ──> Requested
Requested ── formal feedback ──────> Retrievable / Unavailable / Failed
```

retrieval 初始也可为 Unknown；placement Committed 不推导 Retrievable。

```text
LifecycleExecution
Eligible ── persist action intent ──> IntentRecorded
IntentRecorded ── dispatch ────────> Dispatched
Dispatched ├─ ack only ────────────> Acknowledged
           ├─ formal commit ───────> Committed
           ├─ ambiguous result ────> CommitUnknown
           ├─ new hold/conflict ───> Blocked
           └─ definite failure ────> Failed
CommitUnknown ── probe ────────────> Committed / Failed / CommitUnknown
Failed/Blocked ── formally authorized compensation ─> Compensated
```

新的 governance decision/hold 可阻止尚未形成明确外部 commit 的危险动作；已发生效果不能靠本地 Blocked 抹除。无正式决定不进入 Eligible，Acknowledged 不等 Committed，CommitUnknown 不回到盲目 Dispatched。

### 9.7 CP6 restore plan、item、handoff 与 compensation

```text
RestorePlan
Draft ├─ fixed per-owner items ready ─> Ready
      └─ prerequisite missing ────────> Blocked
Ready ── first item dispatch ─────────> InProgress
InProgress ├─ mixed/unfinished ───────> Partial
           ├─ all required outcomes known ─> HandoffComplete
           └─ plan-level failure ─────> Failed
non-terminal plan ── new plan revision ─> Superseded
```

```text
RestoreItem
Planned ├─ safe prerequisites ─> MaterialReady
        └─ unsafe/unknown input ─> Blocked
MaterialReady ── persisted handoff intent ─> HandoffPending
HandoffPending ── dispatch ────────────────> InProgress
InProgress ─> Succeeded | Rejected | Failed | CommitUnknown
CommitUnknown ── reconcile ─> Succeeded | Rejected | Failed |
                              CommitUnknown | CompensationPending
CompensationPending ── authorized action ─> Compensated
```

```text
RestoreHandoff
IntentRecorded ── dispatch ──> Dispatched
Dispatched ─> Acknowledged | Succeeded | Rejected | Failed | CommitUnknown
CommitUnknown ── reconcile ──> ReconcileRequired ─> terminal / still unknown

CompensationRecord
Planned ── execute ──> InProgress
InProgress ─> Completed | Failed | CommitUnknown | Blocked
```

同一 handoff 不改变 receiver/material/input digest；变化时新建 handoff 并显式关联计划或补偿。Succeeded 只表示 receiver-specific outcome；HandoffComplete 只表示必需 item 的交接结果已明确；Compensation Completed 不抹除原 handoff。

### 9.8 跨轴传播与禁止推导

```text
Archive-owned committed facts
  job / capture / closure / assessment /
  placement / lifecycle / handoff / compensation
                         │
                         ▼
safe read composition keeps
partial / stale / missing / conflicting /
unsupported / integrity-failed / commit-unknown
                         │
                         ▼
optional outbound committed-fact seam (contract pending)
                         │
                         ▼
authorized consumer; no owner truth mutation
```

以下推导一律禁止：`Complete closure → Verified`、`Verified → Committed`、`Committed → Retrievable`、`Sealed → project archived`、`MaterialReady → receiver authorized`、`HandoffComplete/Succeeded → owner or project restored`、`Compensated → original effect absent`。

| `AR-UP-007` | `L4-observability` | audit/evidence export、redaction、coverage/verification | 仅获准脱敏 material/ref；摘要不等完整审计链。 |
| `AR-UP-008` | `L1-workspace` | archive read/export 与 projection coverage | 永远是 Auxiliary；不能补 canonical，缺合同时相关 capture Blocked。 |
| `AR-UP-009` | 各 truth owner | restore receiver import/command/handoff、outcome/probe/compensation | per-owner unsupported/blocked/pending/commit-unknown；无合同不造成功。 |
| `AR-ARCH-001` | 全局依赖规则 owner + `L0-sdk` | `L0-sdk` 对 Archive 的 compile/runtime 方向冲突 | 本仓不依赖 SDK；待权威对齐后解锁。 |
| `AR-HLD-Q-001` | Archive + Bus/consumer contract owners | committed-fact/outbox 必要性与 outbound event family | 合同前不发送、不建 delivery evidence；若需要，03 回补对象/UoW 并回退 Step 6~9。 |
| `AR-HLD-Q-002` | workload/environment/test authority | workload、Bundle 规模、latency/capacity/recovery target | 不固定 throughput、分钟级 RTO、page/batch 默认。 |

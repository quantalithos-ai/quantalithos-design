## 3. 实现约束与编码规范承接

> 校准来源：
> - [Step 03 编码、runtime 与仓库约束](design-calibration/03_ddd_step_03_coding_runtime_constraints.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“编码规范承接表”“实现约束表”“Core compile dependency 与符号上限”“本地多仓依赖约束表”。

| 规范 / 约束 | 实现契约 | 影响 |
|---|---|---|
| Rust | planned edition 2024、MSRV 1.93；实施前重新核验 | 全部 crate；当前不是 manifest/build 事实 |
| 源码语言 | 标识符、源码注释、rustdoc 和测试名使用英文；设计说明使用中文 | public type/field/variant/function 必须可转写且有注释 |
| domain 纯净 | domain 同步、无 I/O/executor/config/provider | 领域函数只接完整 typed input |
| async 边界 | application 表达 async port；Tokio 1 系列只在 infra/api/worker runtime | 取消与 may-have-dispatched 不能伪装 definite failure |
| transport neutral | api 是 library handler；未选择 HTTP/gRPC framework/server | 不造 route/status code 或网关合同 |
| provider neutral | DB、Bus、object storage、KMS、signing、compression、schema provider 未选择 | 只定义 local port、typed outcome 和 blocked adapter slot |
| Query no-write | Query 只获得 `ArchiveReadStorePort` 和 visibility capability | telemetry 开/关时本仓 durable write 都为零 |
| fake 边界 | fake 仅 test support；必须与 durable contract 语义等价 | 不作为 production fallback/integration proof |
| 安全 | raw secret/body/provider response/SQL/HTTP/panic 不进入公开 DTO 或 durable safe reason | infra 负责脱敏映射；失败时 fail-closed |

唯一允许的 sibling compile candidate 是已核验的 Core contracts：

```toml
[workspace.dependencies]
core-contracts = { path = "../quantalithos-core/crates/contracts" }
```

该片段是 planned 契约，不表示目标 `Cargo.toml` 已存在或已解析。只允许逐 symbol 使用已核验并适合 Archive 语义的 `ActorContext`、`ActorRef`、`CommandMetadata`、`QueryMetadata`、`IdempotencyKey`、`RequestId`、`TraceId`、`Timestamp` 等；不得引入 Core domain/application/infra。

| 关系 | 分类 | 本仓表达 | 禁止 |
|---|---|---|---|
| L1 snapshot/export/query | runtime + ref + adapter | `SourceExportPort` family 与 typed source binding | Cargo sibling 依赖、复制 owner schema |
| workspace view | runtime + ref + adapter | `WorkspaceProjection/Auxiliary` material | 当 canonical fallback |
| Artifact/evidence | runtime + ref + adapter | owner-approved material/ref | 保存 Artifact truth/完整审计链 |
| Bus inbound | event + adapter | trusted envelope validation 与 consumer mapping | transport ACK 当业务 commit |
| storage/integrity/schema/receiver | runtime + ref + adapter | required slots 与 typed outcome | provider 直接进入 domain/application |
| SDK | downstream client | 仅记录消费方向 | Archive 服务端 compile 依赖 SDK |
| fake | test-only | contract/negative test support | readiness 或正向集成证明 |

### 5.1 `contracts` 模块

#### 5.1.1 模块职责与 capability

`contracts` 定义跨模块可见但仍由 Archive 解释的纯类型。它不得依赖 domain/application/infra，也不得把 external ref 展开为 owner schema。公共 protocol 中出现的 ref/enum/view/page/receipt/report 必须在 contracts 或经核验的 Core contracts 中闭合。

| capability | 输入 | 输出 / 对象 | 禁止 |
|---|---|---|---|
| scope declaration | project ref、slice selectors、explicit exclusions、version | `DeclaredArchiveScope` | 推断 source 存在/完整或改写项目状态 |
| governance decision binding | mapped opaque owner decision binding | `GovernanceDecisionRef` | 保存 policy/hold/delete/risk 正文或决定其有效性 |
| public protocol | trusted context/metadata + typed payload | 3C/5Q/5E/17J DTO 与完整 result/receipt/report | 把 transport 字段、raw body/secret 当 authority |
| safe read | committed Archive records + current visibility/redaction | 五类 safe view/page/marker | 直接暴露 domain-only type/private cursor |

#### 5.1.2 文件、正式对象与关键契约

| 文件 | 代码主体 | 核心字段 / 能力 | 来源与不变量 |
|---|---|---|---|
| `scope.rs` | `DeclaredArchiveScope`（1/26） | `project_ref`, `requested_slices`, `explicit_exclusions`, `scope_version`; `declare`, `requires` | caller + validated selectors；不可变，不证明 capture/coverage |
| `governance_decision.rs` | `GovernanceDecisionRef`（2/26） | `decision_id`, `owner_ref`, `decision_kind`, `decision_version`, `scope_ref`, `validity_ref`; `bind`, `applies_to`, `same_version` | 仅正式 owner mapping；opaque ref，不是 Governance truth |
| `views.rs` | safe metadata + 10 summaries + 5 views | freshness/redaction、job/bundle/verification/restore safe surface | 仅 current visibility 下从同一 committed snapshot 组装 |
| `commands.rs` / `queries.rs` | request/result/view/page | 3 Command、5 Query | 完整字段与 variant 见 Step 08 §5～6 |
| `consumers.rs` / `operations/*` | envelope-mapped payload、receipt、17 Job I/O | typed issue/disposition/continuation | envelope 与 payload 分离；duplicate 完整 replay |

完整 Rust 定义、每个字段类型、Rustdoc、constructor 和 variant 在 Step 06 §5～6、Step 08 §4～8。实现不得从本表省略 `scope_version`、decision applicability、safe metadata 或 page/cursor binding。

#### 5.1.3 Trait、错误与测试

contracts 不定义 repository/provider adapter。`ContractError` 覆盖 invalid value/ref/set/state combination、unsupported mapping 和 `ContractBlocked`，不得携带 raw external error。测试入口为 `contracts/tests/protocol_boundaries.rs`：校验公开 DTO 完整性、safe serialization、domain-only type 泄漏、envelope/payload 分离和完整 replay schema。

### 5.2 `domain` 模块

#### 5.2.1 模块职责与 capability

domain 只拥有 Archive 专属 request/job、source binding/capture、Bundle/manifest/closure、assessment、placement/lifecycle execution、restore plan/handoff/history。不读取 repository、raw config、clock/ID provider、Bus、SDK、storage/KMS 或 owning-domain database。

| CP | capability | 正式对象 | 核心不变量 |
|---|---|---|---|
| CP1 | admission 与 job coordination | `ArchiveRequest`, `ArchiveJob`, `ArchiveJobStageRecord` | Accepted 只表示本地受理；阶段从已提交 component posture 保守推进 |
| CP2 | source binding/capture/coverage | `ArchiveSourceBinding`, `CaptureAttempt`, `CaptureCoverage`, `SourceCaptureFinding` | authority/fence/version/coverage 保真；partial/missing/stale/conflicting/unknown 不抹平 |
| CP3 | Bundle/manifest/closure | `ArchiveBundle`, `BundleManifest`, `ManifestEntry`, `ManifestClosure`, `ClosureFinding` | manifest revision immutable；declared/actual exact set；seal 绑定 exact basis |
| CP4 | integrity/compatibility | `VerificationAssessment`, `CompatibilityAssessment`, `VerificationFinding` | fixed input；compatibility target 隔离；外部能力未知不造 Verified |
| CP5 | placement/lifecycle | `ArchivePlacement`, `LifecycleExecution`, `ExternalActionRecord` | placement/retrieval 独立；decision-bound；intent/ACK/commit/unknown 分离 |
| CP6 | restore/handoff | `RestoreRequest`, `RestorePlan`, `RestoreItem`, `RestoreHandoff`, `HandoffOutcome`, `CompensationRecord` | owner set/revision 固定；per-owner outcome；不推导项目 restored |

| `restore_handoff.rs` | `RestoreHandoff`, `HandoffOutcome`, `CompensationRecord` | receiver/material/effect key/digest/state/history/commit/authority；`record_intent/apply/probe/observe/plan/reconcile` |

这些 24 个对象加 contracts 两对象形成唯一 26 分母。support carrier、safe view、DTO、application/infra/api/worker helper 不得升格为第 27 个业务 truth object。完整逐字段类型、factory precondition、member return、enum variant 与禁止事项见 Step 06 §7～9。

#### 5.2.3 错误与测试

`DomainError` 只表达 invalid value/invariant/transition、missing required basis、version/input conflict；不包装 SQL/HTTP/provider payload。`domain/tests/domain_invariants.rs` 覆盖 24 对象不变量，`state_axis_boundaries.rs` 覆盖多轴状态不可传播、ACK≠commit、Bundle Sealed≠项目 archived、handoff Succeeded≠项目 restored。

### 5.3 `application` 模块

#### 5.3.1 capability、service 与稳定 carrier

| Service | capability / 主体 | required capability | 禁止 |
|---|---|---|---|
| `ArchiveRequestService` | archive/restore admission、job/stage | local store/idempotency/context | Accepted 当 archived/restored |
| `SourceCaptureService` | source plan/capture/reconcile | store + source export | workspace/ref 补 canonical；unknown blind recapture |
| `BundleAssemblyService` | manifest/closure/seal guard | store only | storage/verification 反推 closure |
| `BundleVerificationService` | integrity/compatibility assessment | store + integrity + compatibility | 自选 algorithm/key/schema；Query 触发重验 |
| `PlacementService` | placement/retrieval/reconcile | store + archive storage | ACK 当 commit；unknown blind retry |
| `LifecycleExecutionService` | decision-bound action/reconcile | store + governance decision + storage | 决定 policy/期限/hold/delete/risk |
| `RestoreService` | per-owner plan/material/handoff/reconcile/compensation | store + eligible source/integrity/compat/storage + receiver | 直写 owner DB；统一跨 owner transaction |

#### 5.3.2 Trait / Port / Adapter 契约

| family | 定义位置 | 调用方 / 实现方 | 核心契约 |
|---|---|---|---|

### 5.4 `infra` 模块

#### 5.4.1 capability 与对象

infra 实现 application port、唯一读取 raw config，并构造 validated runtime。稳定 carrier 为 `ArchiveRuntimeBindings`、`AdapterAvailabilityMarker`、`ArchiveRuntimeAssembly`；它们记录 slot/availability/required-set/assembly posture，不拥有业务 truth，也不把 endpoint/secret/provider response 带入 domain。

| 文件 | 实现面 | 边界 |
|---|---|---|
| `store_adapter.rs` | `ArchiveStorePort` durable/fake contract | backend/schema 未选；必须支持 Step 11 UoW/CAS/probe/fence |
| `*_adapter.rs` | 六 external required port families | exact owner/provider contract 未闭合时不得构造 Enabled handle |
| `config.rs` | raw source → typed config refs | 全仓唯一 raw config reader；secret 只作 opaque binding |
| `runtime_builder.rs` | fixed required slots → capability-limited facade | begin 后 required set 冻结；缺任一 required Enabled 即不暴露 facade |
| `errors.rs` | `InfraError` | 保存 safe context，不泄漏 raw provider/credential/body |

fake 与 durable adapter 在 duplicate、version、rollback、commit unknown、range/negative read-set、claim fence、cursor/result round-trip 上必须等价；fake 不得静默替代 production missing slot。测试切口为 assembly completeness、wrong-slot handle、raw config isolation、fake/durable parity 和 fail-closed construction。

### 5.5 `api` 模块

api 只承接 3 Command 和 5 Query typed library handler：验证 trusted actor/metadata 与 DTO shape，构造 `ArchiveOperationContext`，调用 capability-limited service，再映射 `ApplicationError` 为 `ApiError`/protocol surface。它不定义 transport route/status number，不直接访问 store/domain/provider，不把 request body actor/authority 当可信事实。

| 入口组 | 能力句柄 | 写入上限 | 测试 |
|---|---|---|---|
| 3 Command | request/lifecycle capability | 仅 application UoW；返回 accepted/duplicate/rejected/blocked/conflict/unknown | metadata、key/digest、safe error/replay |
| 5 Query | query-only capability | 严格零 durable write、零 external effect | hidden=absent、current redaction、cursor binding、telemetry on/off zero write |

`ArchiveCommandEntry<C>`、`ArchiveQueryEntry<Q>` 与 `ApiEntryDisposition` 是稳定 entry carrier，不扩充业务对象分母。完整字段、factory 和 disposition variant 见 Step 06 §12；handler 协议见 Step 08。

### 5.6 `worker` 模块

worker 承接 5 个 trusted inbound Consumer 与 17 个有界 Operations Job。它校验 envelope/schema、加载 `WorkerClaim`/fence/fixed target、调用 application service、保存 checkpoint 与完整 receipt/report；不直接写 store/domain/provider，不自动把 17 Job 变成 binary 或 scheduler contract。

| capability | 入口 | 状态 / 副作用 | 关键约束 |
|---|---|---|---|
| inbound consumption | E01～E05 | 本地 receipt/result 与受控 domain transition | ACK 只表示消费处理，不等 owner/storage/restore commit |
| bounded operation | J01～J17 | claim/fence/checkpoint/report；必要时 external intent/effect/reconcile | duplicate replay；external unknown probe-first；partial 只处理未决 target |
| loop/shutdown | `archive-worker` | 进程内 WorkerEntry state | lease 不是业务锁或 commit 证明；终态不是 durable business truth |

`ArchiveWorkerEntry<I>`、`WorkerItemDisposition` 与 runner state 是技术 entry carrier；持久 `WorkerClaim`/`WorkerCheckpoint` 定义归 application。`WorkerError` 只映射 envelope/claim/service/shutdown 的安全错误。测试覆盖 wrong claim/fence、late worker、duplicate receipt/report、cancellation at each commit boundary 和无 direct provider/store bypass。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源：
> - [Step 08 协议契约](design-calibration/03_ddd_step_08_protocol_contracts.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的 shared protocol helpers、Command/Query/Consumer/Job 各独立小节、DTO→domain/port 构造闭环和最终协议审计。完整字段、variant、错误与 logical route 以该文件为准。

所有名称都是 transport-neutral logical contract；外部 route/topic/RPC、provider、订阅、重试和 ACK deadline 尚未绑定。Command/Consumer/Job 用 `ArchiveOperationKey + ArchiveOperationInputDigest`；Query 不携带写幂等键。envelope 持有 actor/trace/event/run/claim/idempotency metadata，payload 不重复。完整 result/receipt/report 必须持久保存并在 duplicate 时原样重放；缺失返回 `ResultMissing/CorruptRecord`，禁止重跑或从当前 truth 重构。

### 7.1 三个 Command

| ID / 协议 | request → response | 目标对象 / transaction | 关键错误与边界 |
|---|---|---|---|
| C01 `RequestArchive` | `RequestArchivePayload` → `RequestArchiveResponse` | `ArchiveRequest + ArchiveJob + initial stage + stored result` 原子写 | authority/scope 缺失 Blocked；Accepted 只表示本地受理 |
| C02 `RequestRestore` | `RequestRestorePayload` → `RequestRestoreResponse` | `RestoreRequest + ArchiveJob + initial stage + stored result` 原子写 | owner set/revision/authority 固定；不解析 receiver、不授予写权 |
| C03 `RequestLifecycleExecution` | `RequestLifecycleExecutionPayload` → `RequestLifecycleExecutionResponse` | decision-bound `LifecycleExecution` + result | decision missing/stale/conflicting/hold → Blocked；不创造 policy/delete 权限 |

三者均区分 `Accepted / Duplicate / Rejected / Blocked / Conflict / CommitUnknown`，同 key/同 digest 才重放；同 key/异 digest 返回 Conflict 且不修改旧 reservation。

### 7.2 五个 Query（全部 no-write）

| ID / 协议 | request → response body | 读取与 safe surface | 禁止 |
|---|---|---|---|
| Q01 `GetArchiveJobStatus` | selector/page → `SafeArchiveJobStatusViewDto` | job/stage/components；Visible/NotAvailable/Partial/Stale/Blocked/Unknown | 推导 project lifecycle |
| Q02 `GetArchiveBundle` | bundle/revision/page → `SafeArchiveBundleViewDto` | Bundle/manifest/closure/placement/lifecycle | assembly、repair、retrieve |
| Q03 `VerifyArchiveBundle` | bundle/revision/selection → `SafeBundleVerificationViewDto` | 读取 matching committed assessments/findings | 触发新的 integrity/compatibility assessment |
| Q04 `GetRestorePlan` | plan selector/page → `SafeRestorePlanViewDto` | plan/items/handoffs/outcomes/compensations | 构造 material、dispatch 或 retry |
| Q05 `GetRestoreHandoffStatus` | handoff/item selector/page → `SafeRestoreHandoffViewDto` | 单 item/owner 的历史 | probe、compensate、推导 restored |

`ArchiveQueryResponse<T>` 总是显式携带 surface、optional body、optional page 与 safe issue refs。public cursor 与 private repository cursor 由 `ArchiveRepositoryCursorMapping` 绑定 selector digest、principal、visibility basis、snapshot、order 与 read-model kind；二者不得互传或用临时 JSON/base64 默认 codec。隐藏、撤权和不存在统一 `NotAvailable`，旧结果不复活已撤销权限。

### 7.3 五个 Inbound Consumer

| ID / 协议 | typed payload | 本地承接 | 失败 / receipt |
|---|---|---|---|
| E01 `ConsumeArchiveTrigger` | owner-issued trigger | trigger/admission 语境 | 不绕 authority；unsupported/quarantined/blocked 显式 |
| E02 `ConsumeSourceExportFeedback` | attempt/fence/version/coverage/material feedback | capture/coverage/finding | wrong attempt/fence、stale/conflicting/unknown 不当 empty |
| E03 `ConsumeGovernanceDecisionChange` | decision ref/change basis | lifecycle block/re-evaluation | event 不等新 decision；dispatch 前仍重核 current |
| E04 `ConsumeStorageActionFeedback` | effect key/target/typed outcome | placement 或 lifecycle 的互斥 method surface | 从 persisted target 路由；ACK≠commit；不广播两个 service |
| E05 `ConsumeRestoreReceiverFeedback` | owner/receiver/effect key/outcome | handoff/outcome/item posture | per-owner；Succeeded 不等 project restored |

所有 consumer 返回完整 `ArchiveConsumerReceipt`，覆盖 applied/ignored/duplicate/rejected/quarantined/delayed/blocked/conflict/commit-unknown 等允许结果。transport ACK 不能替代本地 commit、storage commit 或 receiver commit。

### 7.4 十七个 Operations Job

| ID / Job | input → report | 主要主体 / effect | fail-closed 关键点 |
|---|---|---|---|
| J01 `AdvanceArchiveJob` | job/version → stage report | job/stage local only | 只按 committed components 推进 |
| J02 `PlanArchiveSources` | request/scope → binding report | committed Planned binding → source bind | workspace 不补 canonical；bind unknown 不 blind retry |
| J03 `CaptureArchiveSource` | binding/attempt/fence → capture report | capture intent → source capture | exact version/fence/coverage；unknown 转 reconcile |
| J04 `ReconcileSourceCapture` | attempt/fixed input → report | source probe | probe NotFound 不等 no effect |
| J05 `AssembleBundleManifest` | frozen inventory → manifest report | immutable revision/closure | required exact set 不完整不能 ready |
| J06 `SealArchiveBundle` | exact seal basis → seal report | Bundle transition local only | 重读 revision/closure/assessment/placement basis；不造 digest |
| J07 `AssessBundleIntegrity` | fixed verification binding → report | capability assess | 无 algorithm/key/signature contract 不造 Verified |
| J08 `AssessBundleCompatibility` | revision/schema/target → report | capability assess | target-specific；Unsupported/Unknown 保真 |
| J09 `PlaceArchiveBundle` | sealed revision/storage input → report | storage effect | intent-before-effect；ACK≠commit；unknown→J12 |
| J10 `RetrieveArchiveBundle` | placement/revision → report | storage retrieval | retrieval commit 与 retrievability evidence 分离 |

每个 report 携带 operation name、stable target、processed items、related refs、continuation、stage、issues 和 typed disposition；`Advanced/Applied` 只说明本次局部推进，不表示 archived/restored。worker claim/fence/expected version 是每次写入前提；partial resume 只处理显式未决 target。

### 7.5 Source-authority matrix

| source/material class | formal authority | Archive 可持有 | requiredness / 恢复边界 |
|---|---|---|---|
| Identity canonical snapshot | `L1-identity` | owner-approved ref/material + version/fence/coverage | Canonical/Conditional；只交 identity receiver |
| Conversation canonical snapshot | `L1-conversation` | approved snapshot/ref + coverage/redaction | Canonical/Conditional；不复制未授权正文 |
| Work/project canonical snapshot | `L1-work` | work/project ref + version/fence + lifecycle decision ref | Canonical；不改 project state |
| Process canonical snapshot | `L1-process` | process/activity ref + checkpoint/fence/coverage | Canonical/Conditional；无 replay 权 |
| Governance formal material | `L1-governance` 或明确 owner | decision/policy/gate/hold/delete/risk ref 或获准材料 | Canonical/Formal；Archive 不裁决 |
| Artifact material/lineage | `L1-artifact` | approved body/ref/lineage material with provenance | Material/Reference；ref 集合不等闭包 |
| Workspace projection | `L1-workspace` projection owner | read-only projection ref + revision/generation/coverage | 永远 Auxiliary；不能填任何 canonical gap |
| Audit/evidence material | `L4-observability` | approved redacted material/ref + coverage/redaction basis | Material/Reference；摘要不等完整审计链 |

每个 binding、manifest entry、restore item 都必须保存 class、authority、requiredness、owner-specific version/fence/coverage 和 provenance。不同 owner opaque version 不比较；Archive 的材料保管权不转移业务 truth ownership。

### 7.6 Outbound Event candidates（全部 blocked）

`ArchiveJobPostureChanged`、`ArchiveBundleSealed`、`RestoreHandoffPostureChanged` 仅是候选名。`AR-HLD-Q-001` 未关闭前没有正式 payload、topic、publisher、outbox、delivery state 或 delivery evidence。若解锁，必须至少回退正式 02 和本详细设计 Step 06～16，重新核验 event owner/schema/version、UoW/outbox、consumer 与测试；不能从 command response、receipt 或 report 自动生成事件。

### 8.1 共享处理骨架

```text
Command / Consumer / Job write flow:
entry --call--> context + canonical input validation
      --tx----> reserve operation + load fixed guards
      --call--> domain transition / save local intent
      --commit> durable intent + complete local-only result, or
      --call outside tx--> exact external port
      --tx----> map typed outcome + save history/result/checkpoint
      --commit> complete stored result/receipt/report

Query flow:
entry --call--> current visibility resolution
      --read snapshot--> ArchiveReadStorePort
      --call--> safe view + public cursor mapping
      --return> no UoW, no reserve, no cache/audit write, no external effect
```

关键说明：

- 外部 effect 永远先提交 immutable intent，再在 transaction 外调用，再以新 transaction reconcile；不得持锁跨网络调用。
- local commit `Unknown` 只凭 `ArchiveTransactionRef + probe_commit` 核验；external `MayHaveDispatched` 只凭 exact effect key/probe/reconcile，禁止 blind retry。
- duplicate 读取并重新做 current disclosure 后重放原完整 payload；不扫描当前 truth 重算。
- 每条 flow 的 Rust 风格伪代码和 typed call 以 Step 09 为准。

## 9. 状态机与转换矩阵

> 校准来源：
> - [Step 10 状态机与转换矩阵](design-calibration/03_ddd_step_10_state_matrices.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物 §2 的状态主语筛选、§4 的 18 个完整转换矩阵、§5 非法转换处理和 §6 跨状态审计。下表是索引，完整 From/To/guard/副作用/error 以 Step 10 为准。

纯 ref/id/marker、immutable classification、DTO/API surface、owner canonical truth、cache/lock/retry counter 和 blocked outbound delivery 不创建状态机，也不存在一个全局 Archive success 状态。

#### 状态族图：18 个状态主语互不越权

```text
Admission: RequestAdmissionState
     | local accepted only
     v
Job: JobAggregatePosture + ArchiveJobStage
     | committed component references
     +--> SourceBindingState + CaptureAttemptState
     +--> ArchiveBundleState
     +--> VerificationPosture
     +--> PlacementState + RetrievalState
     +--> LifecycleExecutionState + ExternalActionPosture
     +--> RestorePlanState + RestoreItemState
                              +--> RestoreHandoffState
                                      +--> CompensationState

Control only: ArchiveIdempotencyState | WorkerEntryState | WorkerClaimState
```

关键说明：

- 箭头表示作业读取已提交子状态，不表示子状态自动传播为全局成功。
- `ArchiveBundleState::Sealed` 不等项目 archived；`RestoreHandoffState::Succeeded` 不等 owner/project restored。
- `Acknowledged`、`Committed`、`CommitUnknown`、`ReconcileRequired`、`Compensated` 均是不同语义。
- WorkerEntry 终态为进程内状态；持久并发由 WorkerClaim/fence 和 repository CAS 控制。

| # | 状态主语 | 核心允许迁移 | 禁止传播 / 非法处理 |
|---:|---|---|---|
| 1 | `RequestAdmissionState` | none → Accepted/Rejected/Blocked；三者均终态 | Accepted 不转 archived/restored；终态改写拒绝 |
| 2 | `JobAggregatePosture` | Queued → Running；Running ↔ Partial；Running/Partial → Blocked/Failed/Completed；Blocked → Running | 只从 exact committed components 保守聚合 |
| 3 | `ArchiveJobStage` | archive 与 restore 各自按已定义 ordered stages 从 Queued 推进至 Completed | 不跳阶段、不混 archive/restore kind；Blocked/Failed 属 aggregate posture 而非 stage |
| 4 | `SourceBindingState` | Planned/Blocked → Bound；Planned/Bound → Blocked；Planned/Bound/Blocked → Retired | 无正式 authority/contract 不 Bound；Retired 不复活 |
| 5 | `CaptureAttemptState` | Requested/Blocked → InProgress；InProgress → Settled/Blocked/Failed；Requested/InProgress/Blocked → Superseded | old attempt 不覆盖 replacement；未知外部效果不私造 attempt variant |
| 6 | `ArchiveBundleState` | Draft/Blocked → Assembling；Assembling → ClosureReady/Blocked/Failed；ClosureReady → Sealed/Blocked/Failed | exact basis 不匹配拒绝 seal；Sealed 终态 |
| 7 | `VerificationPosture` | Pending → InProgress → Verified/IntegrityFailed/Unknown/Blocked | 不从 digest ref 存在推导 Verified；重验创建新 assessment |
| 8 | `PlacementState` | IntentRecorded → Dispatched；Dispatched/CommitUnknown → Committed/CommitUnknown/Blocked/Failed | ACK 不能转 Committed；CommitUnknown 只允许 exact probe |
| 9 | `RetrievalState` | Unknown/NotRequested → Requested；Requested → Retrievable/Unavailable/Failed/Unknown | placement commit 不自动证明 retrievable；Unknown 不生成 restore material |
| 10 | `LifecycleExecutionState` | Eligible → IntentRecorded → Dispatched；Dispatched → Acknowledged/Committed/CommitUnknown/Blocked/Failed；Failed/Blocked → Compensated | current decision/hold guard 必须重核；Acknowledged 不等 Committed |
| 11 | `ExternalActionPosture` | IntentRecorded → Dispatched；Dispatched/CommitUnknown → Acknowledged/Committed/CommitUnknown/Failed | effect target/key/digest 不匹配拒绝；unknown 只允许 probe |
| 12 | `RestorePlanState` | Draft/Blocked/Ready/InProgress/Partial → Ready/Blocked/InProgress/Partial/HandoffComplete；非终态可 Failed/Superseded | plan 聚合不隐藏 per-item unknown；HandoffComplete 不等 restored |
| 13 | `RestoreItemState` | Planned/Blocked → MaterialReady；Planned/MaterialReady → Blocked；MaterialReady → HandoffPending → InProgress → Succeeded/Rejected/Failed/CommitUnknown；Failed/CommitUnknown → CompensationPending → Compensated | one item 不改变其他 owner |
| 14 | `RestoreHandoffState` | none → IntentRecorded → Dispatched；Dispatched/Acknowledged → Succeeded/Rejected/Failed/CommitUnknown/ReconcileRequired；CommitUnknown → ReconcileRequired | ACK 不等 receiver commit；reconcile 只读 exact handoff key |
| 15 | `CompensationState` | none → Planned → InProgress → Completed/Failed/CommitUnknown/Blocked；CommitUnknown 经 probe 可保持或落定 | compensation Completed 不重写原 handoff |
| 16 | `ArchiveIdempotencyState` | absent → Reserved → Completed/Conflict；异输入 duplicate 只返回 Conflict 且原记录不变 | Completed 缺完整 result 视为 corrupt；Completed/Conflict 终态 |
| 17 | `WorkerEntryState` | Registered/Delayed → Running → Completed/Failed；Registered/Running/Delayed → Stopped | 仅进程内，不作为 durable business truth；无 Blocked 状态 |
| 18 | `WorkerClaimState` | none → Active；Active → Active（renew）/Released/Expired/Superseded | lease expiry 不证明 external rollback；旧 fence 不得继续 effect |

非法转换由 `DomainError::InvalidTransition`、`VersionConflict`、`InputConflict`、`StaleFence` 或 application safe mapping 拒绝；不使用 last-write-wins、状态回退或“后到反馈覆盖历史”。Query 永不触发状态迁移。

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - [Step 11 持久化、事务与一致性](design-calibration/03_ddd_step_11_persistence_transaction_consistency.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“数据所有权实现表”“Logical store / collection 契约”“Repository 持久化语义”“逐入口事务边界”“一致性策略与失败恢复”。本章不指定物理数据库或 DDL。

### 10.1 所有权与 logical collections

26 个正式对象的持久归属保持 §5/§6 唯一 owner；物理 adapter 可以合并或规范化，但必须完整 round-trip 下列逻辑族并维持 key/index/version/transaction 等价。

| logical family | 主要内容 | key / version / immutable 约束 |
|---|---|---|
| admission/job | archive/restore requests、job、stage history | request immutable；request→job unique；job CAS；stage append-only ordinal |
| source capture | bindings、attempts、coverage、findings、fixed source inputs | binding/attempt CAS；coverage exact nested；finding/sidecar immutable |
| Bundle | bundle、manifest/entries/closure、closure findings | Bundle CAS；manifest revision aggregate immutable、exact set 原子 append |
| assessments | verification/compatibility assessments + findings | fixed input exact；verification CAS；compatibility/finding immutable |
| storage/lifecycle | placement、lifecycle execution、external action、dispatch input | mutable CAS；full effect key unique；intent input immutable |
| restore | plan/items/material/handoffs/outcomes/compensations/dispatch inputs | per-owner CAS；plan item set frozen；outcome append-only；effect key family 隔离 |
| operation replay | reservation + complete result/surface | full structured key unique；Completed 必须有 immutable complete result |
| worker control | claim + checkpoint + ordinals | target exclusion/fence；checkpoint append-only且与 result 原子可见 |
| transaction outcome | `ArchiveTransactionRef` stable probe surface | local commit Unknown 可跨进程 exact probe，不等 external effect truth |
| cursor mapping | authenticated stateless codec 或 durable mapping（pending） | public/private 分离；绑定 principal/visibility/selector/snapshot/order/kind |

五类 safe views、protocol DTO、operation context、current visibility decision、runtime assembly 和 entry/runner state不作为第二份 business projection 持久化。Archive 当前没有独立 projection store。

### 10.2 Repository 与 UoW 规则

- `Absent` 只用于 create，`Exact(version)` 只来自当前 read snapshot/Tx；禁止 upsert、hard-coded version、timestamp/owner version替代本地 `RecordVersion`。
- mutable aggregate 使用 CAS，并将 guard row、negative lookup、range predicate、claim fence 纳入 serializable-equivalent read-set；backend 做不到即 `ContractBlocked`。
- immutable append 仅在同 key 且完整内容相同时幂等复用；异内容 `UniqueConflict`，不覆盖或 silent merge。
- result save → reservation complete → business/history/checkpoint 必须在同一 UoW 原子提交；Completed 缺 payload/surface 是 consistency defect。
- manifest/entries/closure/source sidecar 是一个 fixed revision aggregate；分页/范围未尽或 phantom 变化不能 `Complete/Sealed`。
- Query 只通过 owned `ArchiveReadSession` 读取一个 committed snapshot；无 UoW、reserve、cache repair、result save 或 external I/O。

### 10.3 事务边界

| 场景 | transaction 顺序 | 同事务必须完成 | 失败处理 |
|---|---|---|---|
| local-only Command/Consumer/Job | reserve/read guards → domain transition → save truth/history/result/checkpoint → complete → commit | full result relation 与所有本地变更 | Aborted 可安全返回；Unknown 只 probe |
| external effect | Tx1 reserve + fixed intent/input + commit → Tx 外 exact port → Tx2 re-read guards + typed outcome/history/result + commit | 每个 Tx 各自局部原子；不跨网络持锁 | MayHaveDispatched→CommitUnknown/reconcile |
| Query | open committed read → current visibility → reads/view/cursor → close | 无写集 | expired/mismatch→Stale/NotAvailable，重新首读 |
| worker | acquire claim → begin Tx → protect with fence → business/result/checkpoint → commit → release/renew | fence 与 write read-set 同 commit 检查 | old worker 全部拒绝；lease 不替代 CAS |

### 10.4 一致性红线

Archive-local transaction/snapshot/version/fence 不替代 owner snapshot fence、storage commit 或 receiver commit。workspace projection 始终 Auxiliary；manifest 数量、projection generation 或 audit summary 都不能补 canonical 缺口。`AR-HLD-Q-001` 未关闭前不存在 outbox/publisher/delivery store/evidence；若新增 projection 或 outbox，必须回退对象、UoW、protocol、flow、error 和 test 设计。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - [Step 12 错误模型与恢复](design-calibration/03_ddd_step_12_error_recovery.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的六模块错误 enum、底层到 application 的 contextual mapping、Command/Query/Consumer/Job surface、异常矩阵和恢复表。

| 错误类型 | 模块 | 典型触发 | 重试 / 恢复 | 对外上限 |
|---|---|---|---|---|
| `ContractError` | contracts | invalid/missing/wrong kind/unsupported/mismatch | 同输入不可重试或等待兼容合同 | Rejected/Quarantined/Unsupported/Conflicting |
| `DomainError` | domain | invalid transition/precondition/input/result/version/closure/probe/claim/corrupt | 按新依据、re-read、probe 或人工；绝不绕 guard | Blocked/Conflict/IntegrityFailed/Unknown |
| `ApplicationError` | application | invalid/not available/contract blocked/dependency/commit unknown/result missing/consistency | 必须带 operation/channel/dispatch knowledge 做 contextual mapping | safe protocol disposition/surface |
| `InfraError` | infra | store/port/support/config binding | NotDispatched 可依政策；MayHaveDispatched 只 reconcile | 不泄漏 raw SQL/HTTP/provider/secret |
| `ApiError` | api | envelope/response/transport mapping | caller/host 按未来 transport 合同 | 不替代业务 Rejected/Blocked |
| `WorkerError` | worker | envelope/claim/handler/report/shutdown | reacquire/host policy；已表达业务结果进入 receipt/report | 不以进程错误吞掉完整 result |

不绑定虚构 HTTP/RPC 数字码。Query 对 absent/hidden/revoked/unsafe-to-decide 统一 `NotAvailable`；内部 reason 不出站。Consumer unsupported schema 不解析 payload；只有本地 receipt/result commit 可证明后 host 才能按正式 transport 合同 ACK。

| 异常 | 检测位置 | 恢复姿态 | 禁止 |
|---|---|---|---|
| same key/same digest complete | result read | 完整 replay + current disclosure | 重跑 body/effect |
| same key/different digest | reservation | Conflict，原记录不变 | 改写旧 reservation |
| CAS/read-set/fence conflict | UoW commit | Aborted；重读/新 claim/新显式 invocation | last-write-wins |
| local commit Unknown | UoW | `probe_commit(transaction_ref)` + exact result read | absence 当 Aborted、重做 mutation |
| external MayHaveDispatched | adapter | exact J04/J12/J16/probe，仍未知则保留/manual | timeout→Failed、blind redispatch |
| manifest/sidecar/result/correlation 缺损 | rehydrate/replay | consistency defect、隔离、人工/未来 repair design | current truth 重构历史 |
| authority/hold/delete/compatibility 缺失 | guard | Blocked/Unsupported/IntegrityFailed | default allow、风险接受 |
| partial operation | report/checkpoint | 新 operation 显式选未决 target | 重扫已成功项 |
| receiver rejection/failure | per-owner outcome | owner/formal authority 决定新 handoff 或 compensation | Archive 直接改 owner DB |
| visibility revoked | query/replay output | NotAvailable，不改 truth | 暴露旧 payload |

恢复不是把状态改成成功；若允许的恢复动作不在 C/E/J 正式入口集合中，必须回退设计新增协议，而不是实现通用 Repair/Retry command。

## 12. 并发、幂等与重入保护

> 校准来源：
> - [Step 13 并发、幂等与重入](design-calibration/03_ddd_step_13_concurrency_idempotency.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的 3C/5E/17J canonical input 表、并发矩阵、duplicate/in-flight 表、重入保护、external effect key 分离和 fake/durable parity。

`ArchiveOperationKey = { scope, channel, operation_name, idempotency_key }`。scope 必须来自正式 subject/source/target，channel 仅为 Command/InboundEvent/OperationJob，operation name 来自有限 registry，key 来自 trusted metadata/envelope/job metadata；event id、run id、trace id、result id 不能替代。Query 无 operation key。

canonical input 是 typed tuple，包含 channel/name/scope、全部语义 payload、target variant、expected local versions、fixed authority/evidence/source/receiver/storage identity；排除 key 本身、request/event/run/result/transaction/trace IDs、时间、delivery attempt、retry count、claim/lease 和随机本地 ID。集合按 typed key 稳定排序，`None` 与空集合必须不同编码。具体 codec/hash 尚未闭合，禁止使用 debug/JSON/URL/string concatenation 或 Bundle digest 代替。

| 场景 | 冲突资源 | 控制方式 | 失败 / 恢复 |
|---|---|---|---|
| 同入口并发 | operation reservation/result | atomic unique reserve；一个 writer | Existing/Replay/Conflict |
| request/job、manifest、plan 并发 | unique relation + aggregate/range | CAS + negative/range read-set + ordinal | Version/Unique/Input conflict |
| feedback vs probe/replacement | fixed attempt/action/handoff + observation | CAS + immutable input + append history | late result 保留，不覆盖 |
| hold 变化 vs dispatch | current governance guard | dispatch 前重查且 commit read-set 验证 | ContractBlocked/Conflict |
| 多 owner restore | per-item/handoff target | owner-isolated CAS/effect key | 一 owner结果不传播 |
| worker lease loss | claim/fence + business record | commit-time fence + CAS | stale worker 不提交或派发 |
| Query vs mutation | committed snapshot | no-write + snapshot/cursor binding | expired 时重新首读 |

Completed same key/same input 必须 byte/field-equivalent 重放原 result/receipt/report；Reserved 不允许第二 writer 或按超时抢占；Completed 缺 result 直接 consistency defect。外部 effect 使用独立 key namespace并随持久 intent 固定；后续 reconcile 是新的 application operation，但必须使用原 external key/input。partial resume 使用新 key + explicit unresolved target set + old report/checkpoint ref，只处理未决项。

| public/private cursor mapping | query boundary/store | continuation Blocked | 不回传 repository cursor或临时 codec |
| page/batch/worker/timeout/retry/probe budgets | owning wrapper | 无 | 不使用零值/隐式值，不截断后标 Complete |
| result retention/lifecycle schedule | cleanup/worker registration | cleanup/action Blocked | schedule 不授权，未决 result 不清理 |
| observability sink/handoff | safe telemetry adapter | 仅正式 optional 才可 Disabled | 不建 backend/audit truth |

`ArchiveAdapterSlot` 固定为：`Store`、`ContextSource`、`Authority`、`Visibility`、`SourceExport(SourceClass)`、`Integrity`、`Compatibility`、`GovernanceDecision`、`ArchiveStorage`、`RestoreReceiver(RestoreOwnerRef)`、`InboundConsumer(ArchiveInboundFamily)`。required set 在 `ArchiveRuntimeAssembly::begin` 冻结，构造失败后不得删除 required slot；missing/mismatch/Degraded/required Disabled 均不产生 facade。`Ready` 只表示该 local assembly 的真实 required handles 已构造，不是产品或 integration readiness。

跨仓关系继续按 §3 分类：唯一 Cargo path candidate 为 `core-contracts`；Bus/L1/workspace/artifact/observability/SDK/provider/receiver 不进入 Cargo graph。fake 只在 test support 注册，production builder 永不 fallback fake。source authority、project state、governance decision、closure、integrity success、commit、恢复成功和写权限均禁止配置化。

## 14. 可观测性与审计埋点契约

> 校准来源：
> - [Step 15 可观测性与审计](design-calibration/03_ddd_step_15_observability_audit.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的信号分层、字段 allowlist/denylist、日志/指标/span、native durable audit、30 入口覆盖和 sink/redaction 失败规则。

| 层 | owner / durability | 内容 | 不可替代 |
|---|---|---|---|
| A runtime telemetry | 当前进程/外部 sink；可丢失 | low-cardinality logs/metrics/spans、safe refs/category/posture | Archive truth、commit、receipt/report、验收 evidence |
| B Archive native durable review | Archive store；随业务 UoW | request/stage/finding/intent/outcome/result/checkpoint 等既有对象 | 独立通用 audit ledger 或 observability backend |
| C audit/evidence material | `L4-observability` owner | 获准、脱敏 material/ref + coverage/redaction basis | 完整审计链、backend truth；受 `AR-UP-007` 阻塞 |

安全 allowlist 只允许 operation/channel、module、有限 disposition/posture/error category、source class、target kind、attempt phase 和 body-free safe reference（仅确有需要）。默认禁止 raw request/event/provider body、conversation/artifact content、selector values、actor attributes、idempotency/effect key、digest/signature/key material、storage location、receiver payload、endpoint/credential/secret、free-text reason、stack/SQL/HTTP response。

| 信号 | 位置 | 必须表达 | 约束 |
|---|---|---|---|
| entry start/end | api/worker | operation/channel/disposition/duration category | duplicate 与 first execution 分离；不含 raw input |
| UoW/commit | application/infra | tx phase + committed/aborted/unknown category | Unknown 不记录 success/failure |
| external effect | before/after adapter | target kind + dispatch knowledge + outcome category | intent 必须已 durable；不记录 payload/key |
| state transition | domain/application boundary | subject kind + from/to + safe basis ref | log 不替代 append-only history |
| Query | handler | query kind + safe surface + page posture | telemetry 开/关都零本仓 durable write |
| worker claim | worker/control | operation/target kind + claim posture | holder/fence 可仅 safe ref；不当业务完成 |

metric labels 只能取有限 enum，不含 ID、free text、ref、owner arbitrary string 或 digest。span 传播 trusted trace context，但不能把 source/receiver/secret 作为 attributes。sink failure 不 rollback、retry 或改变业务结果，也不能形成 self-observation recursion；mandatory native record 写失败则整个 accepted UoW 不成立。`AR-HLD-Q-001` 前不为 telemetry 创建 outbound event/outbox。

## 15. 测试切口与最小验证清单

> 校准来源：
> - [Step 16 测试切口](design-calibration/03_ddd_step_16_test_cuts.md)
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的六模块 suite、3C/5Q/5E/17J 表、18 状态表、事务/幂等 ID、配置/观测边界和验证能力分级。这里是 planned test input，不是已创建 case 或执行证据。

### 15.1 模块与协议切口

| suite | 覆盖 | 最小断言 |
|---|---|---|
| contracts | typed refs/DTO/view/receipt/report | checked construction、variant 完整、无 domain/private/raw 泄漏 |
| domain | 26 正式对象中的 24 domain objects + shared inputs | factory/invariant/18 状态合法与非法迁移、多轴不传播 |
| application | 8 services + 7 port families | 30 flow 顺序、UoW、完整 replay、unknown/partial、Query no-write |
| infra | store/adapters/config/builder | fake/durable parity、required slot、safe error、binding mismatch |
| api | 3C + 5Q | trusted metadata、safe mapping、current disclosure、Query zero write |
| worker | 5E + 17J | envelope、claim/fence/checkpoint、crash/restart、ACK boundary |

每个 Command/Consumer/Job 至少覆盖 positive（只在正式 external fixture 齐备时）、invalid/blocked、same/same duplicate、same/different conflict、commit unknown 与完整 replay。每个 Query 覆盖 visible、absent/hidden/revoked、partial/stale/unknown、cursor mismatch，并用 spies 断言 `begin_uow/reserve/save/append/complete/claim/external_port = 0`，telemetry enabled/disabled 两组均相同。

### 15.2 关键一致性与恢复切口

| ID / family | 注入 | 必须断言 |
|---|---|---|
| TX | admission或manifest/outcome/result任点中断 | 全部原子可见或全部回滚；无半 manifest/Completed-without-result |
| CAS/RANGE | 并发 version 或 required member phantom | stale writer abort；range/negative read-set 阻止漏项 seal |
| IDEM | parallel same/same、same/different、missing result | exactly-one body；完整 replay；冲突不改原；缺损零 effect |
| FENCE | claim expiry/new fence before commit | old worker truth/result/checkpoint 全不提交 |
| EFFECT | crash before/after intent/external call | fixed input/key 保留；MayHaveDispatched 只 exact probe |
| PARTIAL | multi-source/multi-owner 部分完成 | report 保留全部 item；新 invocation 只处理显式未决 target |
| RESTORE | owner outcomes 并发、receiver mapping drift | owner 隔离；J15 drift 时零 intent/dispatch，需新 plan revision |
| QUERY | mutation between pages / visibility revoke | 不混 snapshot；NotAvailable；无写/repair |
| AUTHORITY | workspace/artifact/audit material 尝试补 canonical | 全部拒绝；Archive 不写 owner truth |
| TELEMETRY | denylist canary / sink failure | 敏感值零出现；业务结果和 native records 不因 sink 改变 |

### 15.3 证明上限

local unit/property 与 scripted fake 只能证明本地纯逻辑和编排契约；durable store、owner/source、governance/security/schema/storage、Bus、restore receiver、SDK/outbound、workload/NFR 的 positive integration 均因对应 blocker 或 provider 未选而 blocked。fake positive 不能关闭任何 blocker。

当前不交付 gate/report/check 脚本，未定义真实 `run_id`、artifact/report/evidence。正式 05 若决定需要脚本，必须另行定义路径、参数、输入、`artifacts/test/<run_id>`、`reports/` 和非零失败语义，再由正式 07 规划实现。

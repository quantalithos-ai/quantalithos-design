### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 archive“能存东西”,而是系统验证 `L4-archive` 是否真正满足“历史保留、归档沉淀与冷存追溯层”的设计要求,尤其要证明以下几点成立:
- ArchivedSnapshot / ArchiveRecord 构成正式归档快照真相层
- `Archived snapshot ≠ active source truth`、`archive request ≠ source state transition` 两条核心边界成立
- archive index / timeline / refs 构成统一冷检索主线,且 `Archive index ≠ primary business index`、`Cold query ≠ operational query`
- retention / legal hold / purge guard 构成统一生命周期治理主线,且 `Evidence preservation ≠ infinite retention`
- restore / export / replay material 只做取回与取证,且 `Restored material ≠ source system rollback`
- archive 的 historical query / RCA / review 面只能消费归档层与只读投影,且 `Archive record ≠ observability event stream`
- digest / custody / ticket / evidence package / review 视图形成长期可信证据链

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 归档对象接入与快照固化部分 | snapshot / ingest 对象 | P0 | ArchiveRequest、ArchivedSnapshot、ArchiveRecord、SnapshotDigest、CustodyChainEntry |
| 归档索引与检索定位部分 | cold index / query 对象 | P0 | ArchiveIndex、ArchiveLookupKey、TimelineAnchor、ArchiveQueryResult |
| 保留策略、分层存储与 legal hold 部分 | retention / lifecycle 对象 | P0 | RetentionClass、StorageTier、LegalHold、PurgeEligibility、DestructionGuard |
| 恢复、导出与审计取证部分 | restore / export 对象 | P0 | RestoreRequest、ExportRequest、EvidencePackage、RestoreTicket、ReplayMaterialExport |
| 历史观察与长期复盘出口部分 | historical review 对象 | P0 | HistoricalTimelineView、ArchivedEvidenceView、LongRangeTrendSlice、PostmortemEvidencePack |
| artifact / observability / source systems 活跃真相本体 | 非范围 | P2 | 只验 archive 如何冻结、索引和输出历史材料,不验 source truth 全部实现 |
| 对象存储 / 备份平台本体 | 非范围 | P2 | 只验 archive 的接缝、索引、票据、规则和导出主线 |
| 业务系统实时查询主路径 | 非范围 | P2 | 只验 cold query / historical review,不验 operational query |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / policy owner | `request.validate_archive_request`、`record.validate_indexable_record`、`request.validate_export_boundary`、`query.validate_historical_query_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + storage + projection + export/restore worker 联动 | backend / domain owner | `CreateArchiveRequest`、`FreezeSnapshot`、`BuildArchiveIndex`、`ApplyRetentionClass`、`ApplyLegalHold`、`CreateRestoreTicket`、`BuildEvidencePackage`、`BuildHistoricalTimeline` | snapshot、index、retention、restore、review 主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | artifact/sandbox/obs → archive snapshot、governance → hold/export approval、archive → audit/legal/ops evidence output | 输入输出语义一致 |
| 恢复专项测试 | 验证 digest 失配、hold 冲突、cold index backlog、restore 越权、retention 越界等异常链 | architecture / QA | digest mismatch、hold over purge、query stale、export incomplete、restore denied | 真相不丢失、错误被正确阻断或留证 |
| 投影一致性测试 | 验证 cold query / timeline / evidence pack / trend slice 与 archive 主记录一致 | backend / QA | query rebuild、timeline rebuild、evidence pack rebuild、trend rebuild | 投影只读且与 archive 主线一致 |
| 端到端主线测试 | 验证最小历史沉淀闭环 | QA / owner | source material → archived snapshot → archive index → retention/hold → export/timeline | 归档闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `Archived snapshot ≠ active source truth` | 归档快照只冻结副本,不回写或替代活跃真相 | 单元 + 集成测试 | 是 | snapshot / source compare |
| `archive request ≠ source state transition` | 归档请求不会驱动源仓状态迁移 | 单元 + 事件链测试 | 是 | request trace / negative flow |
| `Archive index ≠ primary business index` | archive index 只服务 cold query,不承接业务主查询 | 单元 + 集成测试 | 是 | index/query contract |
| `Cold query ≠ operational query` | 冷查询必须走 archive 主线,不能依赖源仓实时主查 | 单元 + 集成测试 | 是 | query boundary / source access check |
| `Restored material ≠ source system rollback` | 恢复和导出只取回材料,不直接改写 source truth | 单元 + 恢复测试 | 是 | restore/export trace |
| `Archive record ≠ observability event stream` | archive 只输出历史沉淀层视图,不冒充实时观测流 | 单元 + 投影一致性测试 | 是 | review/projection compare |
| `Evidence preservation ≠ infinite retention` | retention / purge / hold 按正式规则执行 | 单元 + 恢复测试 | 是 | retention/hold history |
| digest / custody 链成立 | 快照冻结后摘要与 custody chain 可校验 | 集成 + 端到端测试 | 是 | digest compare / custody log |
| restore/export 必须带 ticket + evidence chain | 无 ticket、无 hold 校验、证据不完整时不得导出 | 集成 + 恢复测试 | 是 | restore ticket / evidence pack |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | CreateArchiveRequest 成功创建正式归档请求 | source_ref 合法 + retention class 存在 | CreateArchiveRequest | ArchiveRequest 创建成功 |
| TC-002 | FreezeSnapshot 成功冻结归档快照并生成 digest | request 已存在 + source material 完整 | FreezeSnapshot | ArchivedSnapshot / ArchiveRecord / SnapshotDigest 创建成功 |
| TC-003 | digest 校验失败时阻断归档 sealing | material 被篡改或摘要不一致 | FreezeSnapshot / seal | 返回 `EVIDENCE_DIGEST_MISMATCH` |
| TC-004 | BuildArchiveIndex 成功建立冷检索索引 | archive record 已固化 | BuildArchiveIndex | ArchiveIndex 创建成功 |
| TC-005 | cold query 不得回退为业务实时主查询 | source system 临时不可用 | QueryArchive | 返回 archive 结果或 backlog,不回源做主查 |
| TC-006 | ApplyLegalHold 成功冻结归档材料 | archive record 已存在 + governance input 合法 | ApplyLegalHold | LegalHold 创建成功 |

| TC-008 | CreateRestoreTicket 成功建立恢复票据 | archive record 可恢复 | CreateRestoreTicket | RestoreTicket 创建成功 |

| TC-010 | BuildEvidencePackage 成功构建证据包 | archive records 可定位 + hold/retention 允许 | BuildEvidencePackage | EvidencePackage 创建成功 |
| TC-011 | restored material 不得直接回写 source truth | restore material 已生成 | negative flow | 无 source rollback 行为 |
| TC-012 | BuildHistoricalTimeline 成功输出历史时间线 | archive index / evidence refs 完整 | BuildHistoricalTimeline | HistoricalTimelineView 创建成功 |
| TC-013 | review 结果若缺 snapshot/index/evidence 三层引用则拒绝成功 | refs 缺失 | BuildHistoricalTimeline | 返回 query/ref 错误 |
| TC-014 | retention / tiering 改变后不丢失检索能力 | tier from hot→cold | ApplyRetentionClass → QueryArchive | query 仍可定位 archive record |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 archive request / snapshot / digest,都必须回归快照固化与 custody 主线
- 每次改动 archive index / timeline / cold query,都必须回归冷检索与 refs 主线
- 每次改动 retention / hold / purge,都必须回归 lifecycle 治理与误删防护主线
- 每次改动 restore / export / replay material,都必须回归 ticket / approval / evidence chain 主线
- 每次改动 historical review / RCA / trend slices,都必须回归长期消费与 archive refs 主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 跨区域冷备与多存储层策略后续细化 | 验收矩阵需扩充 | TL / 架构 |
| 法务与审计导出模型继续演进 | export / hold 验收需增加更多样本 | archive / governance |
| 长周期 trend / RCA 需求增长 | historical review 与 cold query 验收需扩充 | owner / ops |

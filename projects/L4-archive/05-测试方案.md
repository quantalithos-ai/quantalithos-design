### 1.1 所有权与完成上限

Archive 只拥有归档请求/作业、Bundle/manifest/closure、source binding/capture/coverage、assessment、placement/lifecycle execution、restore plan/material/handoff/outcome/compensation。它不拥有或反写 identity、conversation、work、process、governance、artifact、workspace、observability 的业务真相；不决定项目 `archived/dissolved/restored`；不决定 RetentionPolicy、legal hold、删除、销毁或风险接受；不拥有 Artifact 正文/血缘或 observability backend。

`L1-workspace` projection 始终为 `Auxiliary`，不得补任一 L1 canonical source 缺口。恢复只经各 owner 的正式 import/restore/command/handoff seam；Bundle 不是跨域写权限。`Accepted`、`Sealed`、`Verified`、item `Succeeded` 均不推出 owner/project/global success。

`AR-UP-001～009`、`AR-ARCH-001`、`AR-HLD-Q-001～002` 与 `AR-03-LOCAL-001～006` 全部开放。它们不阻止测试设计，但每项同时形成：P0 required 正向 lane=`blocked`、本地 negative/fail-closed 测试、证据证明上限、entry/exit/VETO 或 residual 条件。fake、ACK、日志、配置存在或静态矩阵均不能关闭 blocker。

本轮要证明 Archive 自有 truth、协议、状态、事务和外部效果边界可验证；逐源 authority 与包闭包不越权；Query 严格 no-write；恢复按 owner 隔离并只 handoff；重复、冲突、partial、stale、missing、unsupported、integrity-failed、commit-unknown 可判别；配置、依赖、脱敏和证据链不能制造成功。

### 2.1 优先级与执行状态

| 轴 | 值 | 含义 |
|---|---|---|
| 优先级 | P0 | 主链、不变量、所有权、安全、一致性、证据真实性和 VETO；缺正式接缝仍保持 P0 |
| 优先级 | P1 | provider/产品选定后的组合、兼容与下游 hardening；不替代 P0 |
| 优先级 | P2 | 依赖 workload、长期环境或跨区域设计的容量、长稳、RTO/RPO |
| 执行状态 | `planned` / `pending` / `not_run` | 已设计、待条件或未运行；均不可计通过 |
| 执行状态 | `blocked` | 正式合同、实现、环境或 authority 不具备；requiredness 不删除 |
| 执行状态 | `infrastructure_failed` | harness/环境未完成测试；不可改写为预期负向或 passed |
| 执行状态 | `passed` / `failed` | 只能由固定 run 的真实 raw artifact 产生；当前不存在 |

### 2.3 非范围与 VETO

非范围包括各 L1 owner 内部状态机和授权算法、governance 决策正确性、Artifact/observability 正文与后端、对象存储/KMS/签名/压缩供应商实现、产品 UI、SDK client/cache、部署运维、跨区域灾备，以及无 authority 的数值 SLO。本文只验证 Archive 一侧 seam、mapping、失败、依赖分类与无反写；非范围风险进入 §14。

以下五类为 P0 一票否决方向，正式编号留给 06：跨域写；本地/单轴状态越级为 owner/project/global success；缺 authority/integrity/storage/receiver/schema 仍成功；workspace/ref/summary/fake 冒 canonical/material/formal；result/history/effect/raw 链缺失仍 complete、盲重放或造 evidence。敏感泄漏、SDK/provider compile 偷渡和 ready outbound 同样按 S 级阻断。

### 7.2 构造、double、隔离与清理规则

1. 每个 case 从 immutable baseline builder 开始；负向只变一个主要轴并带 mutation tag。checked factory 构造合法对象；非法 persisted state 只能标为 corruption fixture。
2. `None`/empty、missing/hidden、Unknown/Failed、ACK/commit、ref/body、Auxiliary/Canonical 使用不同 typed fixtures。source version 只在同 owner 的正式 comparator/vector 内解释。
3. same/same 复用 canonical semantic tuple；same/different 只改变一个语义字段；trace/time/run/attempt 是不影响业务 digest 的对照。
4. multi-source/multi-owner 数据保留 total target set、stable ordinal 和独立 outcome；partial resume 使用新 operation key、unresolved subset、prior report ref。
5. store fake 只证明 staging/UoW 调用序、CAS 分类和 rollback；source/governance/integrity/storage/receiver/event double 只可提供 negative/typed failure，不得自造 authority、Verified、commit、delivery 或 restored。
6. pure values 每 case 新建并 drop；fake store 每 case 新实例；controlled store 仅删除预校验的 exact run namespace；fault/barrier 必须 reset；canary capture 必须 delete/zeroize。cleanup failure=`infrastructure_failed`，禁止复用环境。
7. formal vector 必须给出 owner/provider、contract/schema version、target、正负结果和 provenance；缺任一项即 unavailable/blocked。不得用真实 secret、生产正文或人工 JSON 补齐。

## 11. 缺陷管理与复验规则

> 延伸阅读：

### 11.1 分级与升级

| 级别 | 定义 / 示例 | 处理与阻断 |
|---|---|---|
| S | VETO、truth/security/authority/consistency/evidence 基础破坏，或不可逆跨域效果；如 owner DB write、状态越级、缺 hold 仍删除、泄漏、盲重派、静态 EV、production fake | 立即阻断；必须修复、补自动化、全量 P0；不可降级或风险接受 |

| B | 不影响 truth/security/required evidence 的非 P0 局部缺陷 | 排期，保留运行证据；进入 P0 时升级 |
| R | 无正式阈值的 future/非范围风险，如 P2 吞吐、RTO、provider 未选 | 登记 residual、owner、解锁条件；不得计 passed；required formal lane仍 blocked |

### 13.1 全局 schema 与 digest

| 类型 | exact 值域 / 约束 |
|---|---|
| schema | `archive.test-artifact.v1` |
| `ArchiveTestRunId` | 1～128 ASCII `[a-z0-9][a-z0-9._-]*`；不得含 `/`、`\\`、`..` 或路径段 `latest` |
| execution status | `passed`,`failed`,`blocked`,`infrastructure_failed`,`not_run` |
| assertion status | `passed`,`failed`,`not_run` |

| redaction / qualification / review | `clean|failed|not_run`；`qualified|unqualified|blocked|not_evaluated`；`pending|reviewed|disputed` |
| digest | algorithm 唯一 `sha256`；值为 `sha256:` + 64 lowercase hex；只保护 test artifact |
| safe path/ref/time | root 内 POSIX relative path；无 empty/`.`/`..`/`latest`；opaque safe ref；RFC3339 UTC `Z` |

聚合顺序固定：任一 `infrastructure_failed` → aggregate same；否则 `failed`；否则 required `blocked`；否则 required `not_run`；只有全部 required cases `passed` 才为 `passed`。业务 Partial/Unknown/CommitUnknown 只能进入 assertion category。

JSON canonicalization：拒绝 duplicate key、invalid UTF-8、float/non-finite/undeclared field；计算副本仅去最外层 `artifact_digest`，保留 algorithm；object key 依 Unicode code point 排序，array 保序，整数最短十进制，string 按 JSON 转义且不 Unicode normalize；生成无空白/BOM/尾换行 UTF-8 后 SHA-256。stdout/stderr 对 redacted bytes 计算外部引用 digest。该 hash 不得冒充 Bundle digest、signature、owner proof 或业务 idempotency digest。

### 14.2 全量 P0 回归

全量 P0 包含 11 个主体 suite：`archive-contract-domain`、`archive-service-flow`、`archive-config-boundary`、`archive-dependency-boundary`、`archive-entry-worker`、`archive-consistency-replay`、`archive-authority-restore-negative`、`archive-security-observe`、`archive-resource-bounds`、`archive-report-audit`、`archive-formal-seam`。还必须执行 release smoke/config/redaction/dependency/report/blocked-lane checks、五类 exact VETO、Step 13 context/case/suite/evidence-index 与 pairing/redaction 审计，并核对 102 TC、18 states、55 keys、19 EV families 分母。

`archive-formal-seam` 前置缺失时必须为 `blocked` 而非 skip/pass；这意味着当前不能达到完整测试退出，但不会删除 P0 requiredness。

|---|---|---|---|
| `AR-UP-001/006/008` source/export/material/workspace | 不能证明跨域 capture/closure | owner/class/mismatch/Auxiliary/ref-body negative；formal 后补 | 各 truth owner、artifact/workspace；待确认 |

| `AR-UP-007` observability material | 不能证明完整 audit/evidence chain | native/runtime/material 分层；formal handoff blocked | `L4-observability`；待确认 |
| `AR-UP-009` restore receiver/probe/compensation | 不能证明 owner committed/restored | per-owner isolation、mapping drift、unknown/compensation negative | 各 owning domain；待确认 |

| `AR-HLD-Q-002` workload/threshold | 无 numeric pass/fail/readiness | structural bounds/progress；measured not_run | workload/验收 owner；待确认 |
| `AR-03-LOCAL-001～005` | codec/cursor/store/config/telemetry fake 与生产可能不等价 | local contract/negative parity；production exit blocked | L4 implementation owner；待确认 |

残余风险不是通过清单。P0 红线均不可风险接受；P1/P2/R 也必须由正式 06 指定角色、scope、basis evidence、期限和再触发条件，本文不写 `accepted` 或 `closed`。

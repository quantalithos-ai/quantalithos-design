### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L4-archive` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L4-archive` 是历史保留、归档沉淀与冷存追溯层,不是 artifact 真相仓、observability 实时流仓或业务主查询仓
- ArchivedSnapshot / ArchiveRecord 构成正式归档快照真相层
- `Archived snapshot ≠ active source truth`、`archive request ≠ source state transition` 两条核心边界必须成立
- archive index / timeline / refs 构成统一冷检索主线,且 `Archive index ≠ primary business index`、`Cold query ≠ operational query`
- retention / legal hold / purge guard 构成统一生命周期治理主线,且 `Evidence preservation ≠ infinite retention`
- restore / export / replay material 只做取回与取证,且 `Restored material ≠ source system rollback`
- archive 的 historical query / RCA / review 面只能消费归档层与只读投影,且 `Archive record ≠ observability event stream`
- digest / custody / ticket / evidence package / review 视图必须形成长期可信证据链

因此,本次验收的目的不是笼统判断“能不能把文件存冷层”,而是判断 archive 的 snapshot 主线、cold index 主线、retention/hold 主线、restore/export 主线与 historical review 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 归档对象接入与快照固化部分 | 是 | ArchiveRequest、ArchivedSnapshot、ArchiveRecord、SnapshotDigest、CustodyChainEntry |
| 归档索引与检索定位部分 | 是 | ArchiveIndex、ArchiveLookupKey、TimelineAnchor、ArchiveQueryResult |
| 保留策略、分层存储与 legal hold 部分 | 是 | RetentionClass、StorageTier、LegalHold、PurgeEligibility、DestructionGuard |
| 恢复、导出与审计取证部分 | 是 | RestoreRequest、ExportRequest、EvidencePackage、RestoreTicket、ReplayMaterialExport |
| 历史观察与长期复盘出口部分 | 是 | HistoricalTimelineView、ArchivedEvidenceView、LongRangeTrendSlice、PostmortemEvidencePack |
| artifact / observability / source systems 活跃真相本体 | 否 | 只验 archive 如何冻结、索引和输出历史材料,不验 source truth 全部实现 |
| 对象存储 / 备份平台本体 | 否 | 只验 archive 的接缝、索引、票据、规则和导出主线 |
| 业务系统实时查询主路径 | 否 | 只验 cold query / historical review,不验 operational query |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateArchiveRequest / FreezeSnapshot | 合法 source material 时必须形成正式 ArchiveRequest / ArchivedSnapshot / ArchiveRecord | API 响应 / DB 记录 / digest 报告 | [] |
| Snapshot 边界 | archive 只冻结 source 副本,不得替代或回写 active source truth | snapshot/source compare / negative flow | [] |
| BuildArchiveIndex / QueryArchive | snapshot 固化后必须形成统一冷检索索引,并可通过 cold query 定位材料 | archive index / query result / timeline refs | [] |
| Index / query 边界 | archive index 不得成为业务主索引,cold query 不得退回 operational query 主路径 | query contract / source access check / negative flow | [] |
| ApplyRetentionClass / ApplyLegalHold / EvaluatePurgeEligibility | retention / hold / purge guard 必须形成正式治理记录并按优先级生效 | retention state / hold record / purge eligibility log | [] |
| Retention / hold 边界 | evidence preservation 不等于无限保留,legal hold 生效时 purge 必须被阻断 | hold conflict / purge guard / retention compare | [] |
| CreateRestoreTicket / ExportRequest / BuildEvidencePackage | restore/export 必须形成正式 ticket 与 EvidencePackage,并可回指 archive refs/digest | restore ticket / export ticket / evidence package / digest compare | [] |
| Restore / export 边界 | restored material 只能取回和取证,不得直接回写 source truth 或充当 rollback 命令 | restore/export trace / negative flow | [] |
| BuildHistoricalTimeline / Historical review | historical query / RCA / review 必须形成只读 timeline/evidence 视图 | timeline view / RCA pack / query result | [] |
| Historical review 边界 | Archive record 不得冒充 observability event stream,historical analytics 不得替代 live dashboard truth | compare report / negative flow | [] |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| archive 不可反写真相 | archive 副本与恢复材料不得回写 source truth | snapshot/source compare / restore trace | [] |

| legal hold 不可绕过 | hold 生效后 purge、export、destroy 都必须受控 | hold log / purge guard / approval trace | [] |

| archive review 不可冒充 live systems | historical review / RCA 只能消费 archive 层只读视图 | review projection / negative flow | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | archive 副本反向替代 source truth / legal hold 被误删 / restore/export 绕过票据或审批 / cold query 越权回源主查 |
| A | 视情况 | 主线可跑但 index backlog、tiering 后检索不稳、evidence pack 不完整 |
| B | 可带着走 | 非关键视图、低优先级 trend / RCA 展示异常 |

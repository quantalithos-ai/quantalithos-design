## 2. 验收目标与范围

> 校准来源：
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“验收目标”“范围矩阵”“明确非范围与边界验收”“跨范围审计”和“回填草稿”小节，了解优先级、required seam 与非范围如何收敛。

验收目标是判断一个固定送验交付是否实现 Archive 自有归档/恢复闭环，是否保持八类 source authority 与 owner write boundary，是否在 partial、stale、missing、conflicting、unsupported-version、integrity-failed、commit-unknown 下保守失败，并且是否留下可复验、不可反向改写的真实证据。

| 级别 | 裁决语义 | 本文当前姿态 |
|---|---|---|
| P0 | 核心能力、所有权、formal seam、状态/一致性、安全、配置与证据真实性；完整验收必须满足 | required；外部正向和本地实现前置仍 `blocked`，不得 skip、N/A、降级或由 fake 替代 |
| P1 | 具名 storage/integrity/KMS/compression、SDK/client/product 组合兼容或 hardening | 只有被具体 release 纳入并具备独立基线/run 时才裁决；不替代 P0 |
| P2 | workload、容量、时延、RTO/RPO、长稳、跨区与 DR | `AR-HLD-Q-002` 关闭前保持 `blocked/not_run`，不得形成数值或 readiness 结论 |

| 验收范围项 | 类型/来源 | 优先级 | 裁决目标 | 非范围/当前上限 |
|---|---|---:|---|---|
| A1 / `F-AR-001` 归档请求受理 | 功能 | P0 | scope、authority、operation identity、原子受理与幂等可解释 | owner 项目状态决定非范围 |
| A2 / `F-AR-002` source capture | 功能/formal seam | P0 | 8 source 逐项 version/fence/coverage/provenance 与 partial 保真 | owner exporter 内部非范围；正向 blocked |
| A3 / `F-AR-003` Bundle closure | 功能/一致性 | P0 | declared/actual exact closure，incomplete/overfull 不得 `Sealed` | provider 格式非范围；source 正向 blocked |
| A4 / `F-AR-004` integrity/compatibility | 功能/external seam | P0 | `Verified/Unknown/Unsupported/IntegrityFailed` 与 target 隔离 | 算法/KMS/provider 内部非范围；正向 blocked |
| A5 / `F-AR-005` placement/lifecycle | 功能/governance/storage | P0 | intent、ACK、commit、probe、decision 与 hold 分离 | tier/provider/policy engine 非范围；正向 blocked |
| A6 / `F-AR-006` safe read | 功能/安全 | P0 | provenance、coverage、visibility、single snapshot 与 Query zero-write | UI/client cache 非范围；cursor binding pending |
| A7 / `F-AR-007` restore plan | 功能/authority | P0 | frozen Bundle/owner/item set、eligibility、compatibility 与 receiver mapping | owner 恢复政策非范围；正向 blocked |
| A8 / `F-AR-008` material/handoff | 功能/receiver seam | P0 | owner-specific minimum material/ref、intent-before-effect、owner DB zero-write | receiver 内部非范围；正向 blocked |
| A9 / `F-AR-009` outcome/recovery | 功能/一致性 | P0 | per-owner/item outcome、exact probe、partial resume 与 compensation | owner `restored` 判断非范围；正向 blocked |
| ownership/source authority | 数据/架构 | P0 | canonical、Auxiliary、material、ref 与 Archive-owned truth 不混同 | owner 内部 schema 非范围 |
| 30 logical/32 method surfaces | 协议 | P0 | 3C/5Q/5E/17J 全覆盖，E04/J12 双路互斥 | transport/framework 未固定 |
| 18 states + consistency | 状态/UoW | P0 | 正式边、CAS/read-set/fence、replay、unknown 与 partial | DB/provider 选择非范围 |
| 12 config domains/55 keys | 配置/安全 | P0 | exact requiredness、priority、binding、assembly 与 fail-closed | secret/provider 值非范围 |
| 19 EV + acceptance package | 证据 | P0 | same-run raw/report/EV、redaction、pairing、review、no-static | 当前全部 absent |
| selected provider/SDK/product | 组合 | P1 | target-specific conformance/consumer compatibility | 不关闭任何 P0 formal seam |
| measured workload/RTO/RPO/DR | 非功能 | P2 | authority、方法、阈值和环境固定后另行裁决 | 当前不产生数值结论 |

对 L1 truth owners、governance、artifact、workspace、observability、Bus、storage/integrity/KMS/compression 和 restore receivers，只验正式合同与 Archive 一侧行为，不验其内部实现。`L1-workspace` projection 永远是 `Auxiliary`；Archive Bundle 永远不是跨域写权限；局部 `Accepted`、`Sealed`、`Verified`、`Committed`、item `Succeeded` 或 `HandoffComplete` 不得传播为 owner/project/global success。

runtime/member/tools execution、capability registry、sandbox、marketplace、产品 UI、SDK client/cache、对象存储供应商、KMS/secret truth 和 observability backend 均不并入本项目。非范围不等于无边界验收：若其 formal seam 是 P0 prerequisite，缺失仍阻断完整验收。

## 3. 验收基线

> 校准来源：
> - `design-calibration/06_acceptance_step_03_baseline.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“验收基线表”“Profile 与证明上限”“证据入口基线”“基线变更规则”和“基线拒绝清单”小节，了解 fixed-run 与不可拼接规则如何收敛。

正式验收必须先固定以下不可变基线。表中“当前状态”是事实边界，不是失败 verdict。

| 基线类型 | 必须固定的内容/标识 | 当前状态 | 裁决用途 |
|---|---|---|---|
| 需求与设计 | 正式 00～06 的 document refs/digests 与同一 immutable `design_revision` | 文档内容可用；revision 未固定 | AC、红线、状态和配置来源 |
| 适用标准 | 验收 SOP/规范、中间产物、真相源与依赖裁剪标准 revision | 未固定 | 生成和裁决规则 |
| 交付 | target implementation repository、immutable `source_revision`、build/image/artifact identity（适用时） | absent | 送验对象 |
| compile contract | 经核验的 `L0-core` symbol/package/version/lock identity | absent | 唯一 compile candidate；无环证明 |
| formal seams | 每个 owner/export/event/governance/integrity/storage/receiver/observability target 的 owner、contract/schema version、binding/config identity、vector set 与 finality | absent | target-specific authority/finality |
| 环境与配置 | profile、environment/namespace、12 域/55 key effective config identity、source resolution、adapter slots、secret-ref resolution、cleanup ref | absent | 可重复装配与隔离 |
| 数据 | 26 个 `DS-AR-*` logical set、owner/provider vectors、generator/revision refs | absent | case 分母与 formal vectors |
| 测试运行 | 一个 primary `ArchiveTestRunId`、start/end、runner/gate revision；不得使用 mutable alias | absent | 102 TC、19 EV、suite/gate 与 report pairing |
| 验收审查 | acceptance package version、primary/supplemental runs、reviewer identities/timestamps | absent | VETO、risk 与 signoff 输入 |

| 证据入口 | 固定路径 | 必须绑定 | 缺失影响 |
|---|---|---|---|
| Run context | `artifacts/test/<run_id>/meta/context.json` | source/design/config/suite/time/digest | 不可裁决 |
| Raw evidence index | `artifacts/test/<run_id>/evidence-index.json` | 19 EV、suite/case refs、blocker/redaction/digest | evidence gate 失败 |
| Case/suite raw | `artifacts/test/<run_id>/suites/<suite>/...` | 102 exact TC、assertions、status、DS、digest | 对应 AC 不可通过 |
| Run summary | `reports/runs/<run_id>/summary.md` | 同 run aggregate/limitations | 交接不完整 |
| Human EV index | `reports/runs/<run_id>/evidence-index.md` | EV→TC→raw→AC/VETO | evidence gate 失败 |
| Gate results | `reports/runs/<run_id>/gate-results.md` | 5 gates、required checks 与真实分母 | release 裁决失败 |
| Redaction check | `reports/runs/<run_id>/redaction-check.md` | raw/report/acceptance/review scan | 失败触发 VETO |
| Dependency check | `reports/runs/<run_id>/dependency-boundary.md` | actual graph/classification/outbound absence | 失败触发 VETO |
| Report audit | `reports/runs/<run_id>/report-audit.md` | pairing/digest/no-static/no-mutable-alias/orphan | 失败触发 VETO |
| Blocked lanes | `reports/runs/<run_id>/blocked-lanes.md` | required blocked/not_run denominator 与 closure refs | 任一 P0 blocked 不得通过 |
| Acceptance package | `reports/acceptance/{handoff,veto-checklist,risk-acceptance,open-issues}.md` | runs、review、范围、风险和裁决输入 | 不得签署 |

一个 EV instance 只属于一个 fixed run。补验 run 必须作为 immutable supplemental run 显式列入 handoff，并按验收项替换/复核；不得跨 run 选择最好结果、覆盖旧失败、拼接 case 或构造一个 passed EV。测试 artifact 的 digest 只证明测试输出配对，不是 Bundle digest、签名、KMS 或 owner proof。

影响 P0 的需求/设计、实现/Core、config/profile/target/vector/data、TC/suite/gate/check/EV schema 或 report generator 发生变化时，默认创建新 run 并按正式 05 §14 执行受影响回归；旧 raw 保持 immutable，只能作为历史。无 immutable revision、无 target/version、无 digest raw、静态/手写 passed、fake/ACK/config 冒 formal、泛化环境名称或绝对本机路径均不得成为验收基线。

- [ ] 正式 05 的完整测试退出已满足：102 required TC、11 个 P0 suites、formal seam 与 release gate 无 `failed/blocked/infrastructure_failed/not_run`。
- [ ] primary `<run_id>` 明确且 immutable；raw/report 同 run，schema/digest/redaction/pairing 合格。

### 4.2 验收退出条件

- [ ] 全部 P0 AC 均有真实、qualified、可复核的结果；不得以不适用移除 required 项。
- [ ] `VETO-AR-001～010` 均有真实 evidence review，且全部为 `not_triggered`。
- [ ] `F-AR-001～009`、`BR-AR-001～012`、30/32 protocols、18 states、55 keys、102 TC、19 EV 的分母一致且无 orphan/duplicate/conflict。
- [ ] source authority、workspace Auxiliary、owner zero-write、Query no-write、状态不传播、formal finality 和 evidence authenticity 均通过。
- [ ] 所有 required P0 blocker 均有 owning-project closure proof，并已在实际 formal run 验证；不存在开放的 P0 blocked lane。
- [ ] S=0、未接受 A=0；每个关闭缺陷均有失败 run 与新 fixed run 的复验配对。
- [ ] 仅 B/R/P1/P2 residual 可进入风险接受，且具名 authority、依据、动作、期限/触发与复验计划完整。
- [ ] handoff、VETO checklist、open issues、risk acceptance 与 reviewer notes 对同一 package 相互一致。
- [ ] 最终结论只取“通过/有条件通过/不通过”，所有必要职责已签署；签署不替代证据。

### 4.3 暂停与不可裁决分流

| 触发 | 过程姿态/裁决影响 | 恢复条件 |
|---|---|---|
| delivery/design/config/data/run identity 未固定 | `not_entered / 不可裁决` | 固定完整基线后重新进入 |
| formal prerequisite 缺失 | P0 `blocked`；不能进入完整裁决 | owner closure proof + formal run |
| runner/harness 意外失败 | `infrastructure_failed`；不可裁决 | 修复基础设施并创建新 run |
| baseline 在 run 后漂移 | `paused` | 影响分析 + required regression/new run |
| raw/report/EV 缺失、跨 run、digest 不符或静态 pass | evidence gate 失败；适用时 VETO | 从真实 runner 生成新证据并保留旧历史 |
| 泄漏、跨域写、状态越级或 blind replay | S/VETO，实际已进入时只能“不通过” | 隔离/修复、owner 处置与全量新 run；不得风险接受 |
| measured P2 无 authority | `not_run/blocked`；禁止数值/readiness 声明 | workload、方法、阈值与 owner 正式化后执行 |

当前 `acceptance_execution=not_entered`：实现、环境、数据、run、EV、handoff 与 review 实例均为 0；18 个 blocker/pending 仍开放。该过程姿态不是一次“不通过”或“有条件通过”裁决。正式 06 停审只表示裁决规则设计完成，不满足本章任一实际进入条件。

## 5. 功能验收门禁

> 校准来源：
> - `design-calibration/06_acceptance_step_05_function_gate.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“功能验收门禁表”“功能验收闭环矩阵”“P1 / P2 功能后置边界”“功能验收项停审记录”和“跨功能门禁裁决审计表”小节，了解九项功能如何逐项收敛。

`AC-AR-FUNC-001～009` 全部为 P0。每项实际通过都要求 exact TC 在同一 fixed run 中取得 qualified 结果、对应 EV 和专项 report 可回到同 run raw、所有受影响 formal prerequisite 有 owning-project closure proof，且无 VETO/S。`blocked`、`infrastructure_failed`、`not_run`、local/fake negative 均不能形成通过。

| 验收项 ID | 功能/场景 | 通过条件 | 失败条件 |
|---|---|---|---|

### 6.1 数据分类与所有权

| 分类 | Archive 允许持有 | authority/语义 | 禁止解释或变化 |
|---|---|---|---|

### 10.2 证据生成与只读派生链

```text
runner / gate writer
        |
        v
artifacts/test/<run_id>/ immutable raw
        |
        v
raw finalizer: schema + digest + same-run + redaction + denominator
        |
        v
evidence-index.json -> read-only report generators
        |
        v
reports/runs/<run_id>/{suite,EV,index,gate,checks}.md
        |
        v
reports/acceptance/* draft -> reports/review/* named review
        |
        v
future formal verdict (never writes backward)
```

关键说明：任何反向写入、隐式跨 run、mutable alias、无 raw EV、无 digest raw 或无具名 review 的 acceptance 初稿都使链路失败。一个 EV family 可在多个 run 各有实例，但单个 instance 只属于一个 run；local passed 不能更名为 formal passed。

## 11. 一票否决项

任一 `triggered` 都把总体结论锁为“不通过”，建立 S 缺陷并停止受影响 release/effect。修复后必须创建新 fixed run，执行原 TC、同 family、相邻 suite/check 和全量 P0；旧 trigger raw/report 不得删除或改写。所有 VETO 都不能由 risk acceptance、fake、ACK、日志、配置、签字或后续 clean run 覆盖。当前没有任何 VETO posture 实例，不得将其默认记作 `not_triggered`。

## 12. 缺陷分级、复验与放行规则

> 校准来源：
> - `design-calibration/06_acceptance_step_12_defects_retest_release.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“执行状态先于缺陷定级”“缺陷分级与结论影响”“复验范围矩阵”“缺陷记录与关闭证据合同”“缺陷处理与复验流”和“三值放行规则”小节，了解缺陷与 release gate 如何收敛。

执行姿态先于缺陷级别：assertion 真实不满足才是 `failed` 并按 S/A/B 定级；formal prerequisite 缺失是 `blocked` 并保留 owning blocker；runner/environment/writer/cleanup 意外失败是 `infrastructure_failed`；计划项未执行是 `not_run`。后三者都不能伪装为产品缺陷已修复、预期负向或 N/A，也都阻止 required P0 通过。

### 12.1 缺陷分级

| 级别 | 定义/示例 | 对结论与阶段的影响 | 复验要求 | 风险接受 |
|---|---|---|---|---|
| S | 任一 VETO triggered；跨域写、假 global/owner success、缺 basis 成功、blind effect、Query 写、泄漏、compile/fake/outbound 偷渡、evidence forgery | 总体必须“不通过”；停止受影响 gate/release/effect，不得进入下一阶段 | 修复和补强自动化；原 TC + 同族 + 相邻 + 全量 P0；保留旧 trigger raw | 禁止 |
| A | 未命中 S，但任一 P0 功能、state、protocol、config、recoverability 或 report assertion 失败 | 默认“不通过”；修复前不得完整放行；仅严格证明不触 P0 truth/security/authority/finality/evidence 后才可能条件通过 | 原 TC、同 family 正/负/边界、直接和相邻 suite/check；核心语义变化时全量 P0 | 极少数逐项；禁止批量/口头接受 |
| B | 非 P0、局部、可诊断且已证明不影响 required evidence/P0 行为 | 完全不在 scope 可不影响；否则仅具名接受后“有条件通过” | 受影响 TC/suite，必要时相邻抽样；保留 raw/report | 可以；须 owner/acceptor/action/deadline |
| R | future/P2/operations 改进或无正式 threshold 的记录项 | 不形成 P0 pass；若实为 required blocker 仍阻断，不能以 R 绕过 | authority 解锁后建立/执行测试；scope 改变时回写设计 | 仅真正 residual；不可吸收 P0/VETO |

任一 VETO 必须定 S 且禁止降级。A 若涉及 owner truth、安全、unknown finality、formal authority、evidence authenticity 或不可逆 effect，升级为 S。formal prerequisite 永远保持 blocker；定级/根因/影响争议时状态为 `disputed` 并按较高风险阻断。若发现没有正式字段/state/error/flow，必须暂停并回写 owning design/test/acceptance Step 后再复验。

### 12.2 复验范围

| 缺陷/变化面 | 最低复验 | 追加检查 | 全量 P0 触发条件 |
|---|---|---|---|
| contract/DTO/ref/schema/object | 原 TC + CONTRACT/OBJECT 同族及受影响 entry | contract-domain、entry-worker、redaction | public shape、authority、26-object invariant 或 evidence schema 变化 |
| 18 state/聚合 | 原 STATE + 全部相邻合法/非法/不传播边 | contract-domain、service-flow、VETO-002 | propagation、terminal 或 owner/global success 语义 |
| Command/Query | 原 entry 正负/duplicate；五 Query×telemetry 两姿态 | service-flow、consistency、authority/security | UoW、no-write、visibility、owner boundary |
| Consumer/Job/claim/report | 原 entry + envelope/receipt/claim/fence/checkpoint/report/duplicate | entry-worker、consistency、report audit | ACK/finality、phase、owner/effect boundary |
| UoW/store/idempotency/effect | UOW/IDEMP/EFFECT + fault/barrier/probe | consistency、resource、formal seam、VETO-005 | commit/replay/unknown/effect 语义 |
| source/governance/storage/restore | AUTHORITY/EFFECT/RESTORE + related E/J | authority-negative、formal-seam、blocked lanes | fail-open、cross-domain、receiver/outcome/compensation |
| config/runtime/fake | CONFIG-001～004 + affected capability | config、dependency、security | 55-key requiredness、priority、production fake |
| telemetry/redaction | SECURITY/OBSERVE + representative entry/error | security-observe、redaction、report audit | leakage、visibility、non-interference |

| evidence/report/review | REPORT-001～002 + failed/blocked/infra samples | report-audit、link/digest/blocked-lane/VETO checklist | raw schema、status aggregate、EV registry、review mutation |

### 12.3 缺陷记录与关闭合同

| 字段/材料 | 必须记录 |
|---|---|
| identity | stable defect ref、发现时间、gate/suite/exact TC、severity、execution posture |
| traceability | VETO/blocker/requirement/design/AC/EV refs、受影响 owner/phase/denominator |
| observation | redacted expected/actual category 与 safe ref；禁止 raw body/secret |
| failed evidence | immutable failed run、raw/report path+digest、review；blocked/infra 列 prerequisite/harness evidence |
| repair | root cause、change/source/config identity、changed boundary、设计回写与增强 assertion/vector |
| retest | original TC、same family、adjacent/full P0 scope、新 fixed run raw/report/EV/check refs |
| closure | reviewer identity/time，状态只可为 `open/disputed/fixed_pending_retest/closed_after_retest/accepted_with_conditions`；S 不允许 accepted |
| conditional acceptance | 仅 eligible A/B/R，引用 §13 的 owner/acceptor/reason/action/deadline/trigger |

关闭必须同时满足：repair identity 可定位；新 fixed run 的 required scope 全部 qualified；原 failed raw 与 fixed raw 均可读；无新/残留 VETO；具名 review 通过；required formal lane 未被删除。报告、commit message、人工评论、配置 `Ready` 或静态表均不能关闭缺陷。

### 12.4 三值放行规则

| 结论 | 必要且同时满足 | 允许 | 禁止 |
|---|---|---|---|
| 通过 | 所有 P0 AC qualified passed；formal lanes passed；10 VETO 有证据 `not_triggered`；S=0、A=0；evidence/review 完整；无未接受影响项 | 可进入正式下一阶段准备；不代表生产 readiness/owner success | 带 blocker、undetermined VETO、缺 report/signoff |
| 有条件通过 | P0/formal/VETO/evidence 与 S=0 仍全部满足；只有逐项正式接受、不触 P0 redline 的 eligible A/B/R residual | 只在列明条件/scope 内进入；到期/触发自动重审 | 接受 VETO/S/P0 blocked/not_run/infra、泄漏、fake 或静态 evidence |
| 不通过 | 任一 P0 failed/blocked/infra/not_run；VETO triggered/undetermined；S>0；未接受 A；evidence/review/baseline 缺失 | 修复/解阻后新 fixed run 复验 | 以“基本通过”“风险已知”“本地通过”替代 |

尚未满足 §4 进入条件时使用 `acceptance_execution=not_entered`，不制造一次“不通过”裁决；一旦实际进入且满足“不通过”条件，结论只能是不通过。当前 defect、repair、retest、release 和 verdict 实例均为 0。

## 13. 风险接受与遗留项

> 校准来源：
> - `design-calibration/06_acceptance_step_13_risk_acceptance.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“风险接受的资格边界”“当前 18 个 blocker / pending 的风险 disposition”“Future residual 类别”“风险接受记录与 authority 合同”和“风险接受停审与跨项审计”小节，了解遗留项为何不能替代 P0 门禁。

风险接受不是关闭 blocker、修改测试结果、改变需求优先级或绕过 P0 的机制。一个事项只有同时满足以下条件，才有资格在未来支持“有条件通过”：

1. 不命中 `VETO-AR-001～010`，不是 S，也不是 required P0 formal seam、baseline、evidence 或 implementation prerequisite。
2. 受影响的全部 P0 AC 已由 qualified fixed-run evidence 独立通过；风险只影响明确纳入的 P1/P2/future/operations 范围，或已证明不污染 P0 的极少数 A/B/R。
3. 影响边界、不可接受边界和证明上限可写成可复查断言；影响未知不具资格。
4. 存在 Archive 之外、具有正式权限的具名 risk owner 与具名 acceptor；Archive runtime、报告脚本、本文作者和 test fake 均不是接受 authority。
5. 存在 immutable baseline/run/evidence refs、后续动作、责任人、绝对截止时间或可判定 trigger、复验范围、follow-up 入口和自动失效条件。
6. `reports/acceptance/risk-acceptance.md` 已有具名 review，且 review 不修改 raw、EV、defect、VETO 或 owner truth。

任一条件缺失时，事项只能保持 `blocked`、`pending` 或 `proposed`，不能支撑有条件通过。当前 risk acceptance instance 为 0。

## 14. 最终结论与签署

> 校准来源：
> - `design-calibration/06_acceptance_step_14_final_decision_signoff.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“过程姿态与正式结论”“裁决聚合顺序”“三值裁决矩阵”“最终维度结论表模板”“签署角色与职责”和“结论与签署停审 / 跨项审计”小节，了解三值聚合与签署权限如何收敛。

### 14.1 过程姿态与 verdict 分离

| 类别 | 合法值 | 使用时机 | 当前事实 |
|---|---|---|---|
| acceptance process posture | `not_entered/in_review/paused/decision_ready/decided` | 表示是否具备真实 baseline/run/package 与裁决进度 | `not_entered`；不是三值 verdict |
| dimension/overall verdict | `通过/有条件通过/不通过` | 只有实际验收已进入且证据可裁决时填写 | absent；禁止预填 |
| VETO posture | `not_triggered/triggered/undetermined` | 每个 VETO 的真实 evidence review | absent；禁止默认全绿 |
| risk posture | `proposed/under_review/accepted/rejected/expired/superseded` | 每个 eligible residual 的具名决定 | absent |
| signoff posture | `pending/signed/rejected/withdrawn/superseded` | 对 fixed decision package 的具名签署 | absent |

正式 06 的 `formal / stop_review` 只表示裁决规则设计完成，可作为未来 07 的规划输入；它不把 acceptance posture 改为 `in_review/decided`，不产生 verdict、release permission 或 production readiness。06→07 仍必须由用户另行明确授权。

### 14.2 裁决聚合顺序

```text
fixed baseline + acceptance entry
             |
             v
P0 AC / formal seam / evidence completeness
             |
             v
10 VETO: all evidenced not_triggered?
             |
             v
defects: S=0, A disposition valid?
             |
             v
eligible residuals individually accepted and unexpired?
             |
             v
dimension verdicts -> overall worst-result aggregation
             |
             v
named responsibility reviews and signoffs on the same package
```

任一节点失败都不能由后续节点修补。任一维度“不通过”则总体“不通过”；没有不通过但存在有效条件时总体“有条件通过”；只有所有维度通过且无 active condition 时总体“通过”。签署在最后确认同一 immutable package，不参与多数投票，也不是风险接受。

### 14.3 三值裁决矩阵

| 判定面 | 通过 | 有条件通过 | 不通过 |
|---|---|---|---|
| P0 AC | FUNC/RL/CMD/QUERY/EVENT/JOB/SYNC/STATE/TX/IDEM/CONC/EFFECT/NFR/EVID 全部适用项 qualified passed | 仍须全部 passed | 任一 failed/blocked/infra/not_run/unqualified/missing |
| formal seams | 每个 required target 独立 formal passed，owner closure 可核验 | 同左 | 缺 target/contract/vector/binding/finality 或被 fake/local 替代 |
| VETO | 001～010 全部有证据 `not_triggered` | 同左 | 任一 `triggered` 或 `undetermined` |
| defects | S=0、A=0；B/R 不在 scope 或已关闭 | S=0；仅 eligible A/B/R 有合格、未过期接受 | S>0、未接受/越界 A 或争议影响未知 |
| evidence/review | fixed-run raw/report/19 EV、7 类 run report、4 类 acceptance file 与具名 review 全有效 | 同左 | 缺失、泄漏、static、mutable alias、cross-run、匿名或争议未解 |
| risk acceptance | 无 active condition | 每项 eligible、具名、basis/action/deadline/re-entry 完整且未过期 | 接受 P0/VETO/S 或缺 acceptor/evidence/action/time |
| baseline | delivery/design/Core/env/config/data/run/target package 完整且未漂移 | 同左 | 缺失、漂移或旧证据支撑新 baseline |

### 14.4 最终维度结论模板

以下表格只定义未来实际裁决的字段，不是已填写的 verdict。

| 维度 | 未来合法结论 | 最小输入 | 聚合约束 |
|---|---|---|---|
| 功能验收 | `<通过\|有条件通过\|不通过>` | `AC-AR-FUNC-001～009` + related C/Q/E/J/EV | 9/9 P0 required；局部能力不覆盖其他项 |
| 数据/架构/依赖 | `<通过\|有条件通过\|不通过>` | `RL-AR-001～012`、source matrix、SYNC-003/004、dependency report | owner zero-write、Auxiliary、compile/fake/outbound 红线 |
| 接口/事件/状态/一致性 | `<通过\|有条件通过\|不通过>` | 30/32 surfaces、18 states、TX/IDEM/CONC/EFFECT | ACK/local/external/owner finality 与 unknown 分离 |
| 非功能验收 | `<通过\|有条件通过\|不通过>` | `AC-AR-NFR-001～008`、structural P0、formal targets | measured P2 不得产生无来源 verdict |
| 证据/审计 | `<通过\|有条件通过\|不通过>` | `AC-AR-EVID-001～010`、19 EV、report/review | raw-first、same-run、redaction、no-static |
| 发布准备 | `<通过\|有条件通过\|不通过>` | 上述维度 + defects/risk/signoff + release scope | 只表示可进入准备，不等于部署/生产 ready |
| 总体结论 | `<通过\|有条件通过\|不通过>` | 所有维度最严格聚合 | 禁止平均、投票或模糊语言 |
| 是否允许进入下一实施/发布阶段 | `<是\|有条件\|否>` | overall verdict 与有效条件清单 | 不是额外 verdict；必须与总体一致 |

### 14.5 签署角色与职责

| 角色 | 必须确认 | 不得代表 | 当前 |
|---|---|---|---|
| 验收负责人 | entry/exit、三值聚合、VETO/risk/signoff package 一致，作最终裁决 | 补 raw、替 owner 接受 formal gap | unset |
| L4-archive implementation owner | immutable source/build、实现 scope、repair/change identity、无越界写面 | 测试结果或上游 truth | unset |
| 测试与证据 owner | 102 TC、suite/gate、19 EV、raw/report/digest、failed/fixed pairing 与 review 完整 | 手改 status、决定业务风险 | unset |
| 架构与依赖 owner | truth boundary、30/32、12 RL、dependency type、outbound posture | 接受安全泄漏或 owner finality | unset |
| 安全/数据/records owner | visibility/redaction、secret/body、custody、evidence retention operation 与安全 residual | 决定 project state、retention/delete truth（除非同时具有正式权限） | unset |
| Source/governance/artifact/workspace/observability seam owner（按 scope） | 自己 target 的 contract/version/fence/coverage/material/decision/closure proof | 其他 target 或 Archive 总体验收 | unset |
| Storage/integrity/restore receiver seam owner（按 scope） | 自己 target 的 binding/finality/probe/compatibility/compensation | 用 ACK/config 代 commit/Verified/restored | unset |
| 产品/业务 owner（若 scope 要求） | scope、用户价值、P1/P2 纳入与 eligible residual | 降级 P0 或接受 VETO/S | unset |

签署顺序为：测试/证据 owner 确认 fixed raw/report/EV 与复验，implementation owner 确认 delivery/change；架构、安全/数据/records 与每个适用 seam owner 审查各自边界，任何拒绝/争议都使 package 未就绪；eligible residual 由对应具名 acceptor 单独处理；最后由验收负责人核对同一 immutable package 并填写三值。不得先签后补 evidence/risk。

任一签署 `rejected/withdrawn`、baseline/package 改变、risk 过期、new VETO/S/evidence conflict 出现时，决定自动失效或暂停。影响回归与重新签署使用新 package version，旧签署和证据保持历史。

### 1.1 专项上游与 source authority

| source class | 正式 truth owner | Archive 允许消费 | 明确禁止 |
|---|---|---|---|
| identity | `L1-identity` | owner-approved snapshot/export/ref、version/fence/coverage | identity/member/authorization truth |
| conversation | `L1-conversation` | owner-approved material/ref | conversation 正文、索引或恢复状态 |
| work | `L1-work` | lifecycle/source ref、正式 restore receiver seam | 推导或反写 `archived/dissolved/restored` |
| process | `L1-process` | process material/ref 和正式版本信息 | process state、执行权或 owner DB 写 |
| governance | `L1-governance` 或明确 owner | current decision/hold/delete opaque ref | RetentionPolicy、期限、legal hold、删除或风险接受裁决 |
| artifact | `L1-artifact` | approved artifact material/ref、lineage ref | 通用 Artifact 正文或血缘 truth |
| workspace | `L1-workspace` | 明确标记的 `WorkspaceProjection/Auxiliary` | canonical fallback、补齐任一 source truth |
| observability | `L4-observability` | 获准且脱敏的 audit/evidence material/ref | audit chain 或 observability backend truth |

Archive 只拥有归档专属的请求/作业、source binding/capture/coverage、Bundle/manifest/closure、assessment、placement/lifecycle execution、restore plan/material/handoff/outcome/compensation 及其本地 result/receipt/report/checkpoint。Archive Bundle 不是跨域写权限；恢复只能经各 owning domain 的正式 receiver/import/command/handoff，逐 owner 记录 `partial/stale/missing/conflicting/unsupported-version/integrity-failed/commit-unknown` 与补偿/重试姿态。

### 1.2 依赖分类与 historical material

只有经过实际 package/export/version/lock 核验的 `L0-core` shared contracts 才可能成为编译期依赖。L1 snapshot/export、workspace view、Artifact/evidence、Bus、storage/integrity/KMS/schema、restore receiver、observability 和 SDK 必须按实际关系归为 `runtime/event/ref/adapter/fake`；不得将 sibling repo 的存在写成 Cargo dependency。`L0-sdk` 是下游 client/runtime 方向，不进入 Archive 服务端编译图；`AR-ARCH-001` 关闭前对此 fail-closed。

`README.md`、旧正式 00/01/02/03/05/06 与 `draft/` 只保留 `historical_material` 或 `pre-calibration_input` 身份。固定 S3/MinIO/Glacier/PostgreSQL、固定保留期、算法、性能数字、旧 snapshot/index/timeline/RCA/restore-ticket 主线均未被继承。

`AR-UP-001～009`、`AR-ARCH-001`、`AR-HLD-Q-001～002`、`AR-03-LOCAL-001～006` 共 18 项持续开放。它们不阻止本文完成设计停审，但阻止对应 positive adapter、formal conformance、量化 NFR、测试退出、验收和 readiness。目标仓、immutable baseline 和用户实施授权也尚不存在；因此当前实施状态是 `not_entered / blocked / not_ready_for_acceptance`。

本轮 P0 实施目标是把 Archive 自有归档/恢复设计落成可编译、可测试、可审查的纵切：请求与作业协调、逐 source 采集、Bundle exact closure、完整性/兼容性评估、placement/lifecycle 执行、安全查询、恢复计划/材料/owner handoff，以及 raw-first evidence 能力。每条纵切必须同时守住 owner truth、Query no-write、事务/fence、intent-before-effect、exact probe/reconcile、per-owner isolation 和 no-outbound 边界。

| 目标面 | P0 可验证增量 | 当前证明上限 |
|---|---|---|
| 请求与作业 | C01/C02/C03 admission、request/job/stage、reservation/result replay | 只证明 Archive 本地受理，不代表业务批准、archived 或 restored |
| source capture | 8 source class 的 binding/capture/coverage/finding 与异常保真 | owner 正向合同缺失时 blocked；workspace 不补 canonical |
| Bundle closure | immutable manifest revision、declared/actual exact set、closure finding、seal basis | 不由 storage/verification 反推 closure 或项目状态 |
| assessment | fixed input/target、integrity/compatibility finding、Unknown/Unsupported/IntegrityFailed | 算法、key、schema authority 未闭合时不得写 Verified/Supported |
| placement/lifecycle | intent、ACK、Committed、CommitUnknown、probe/reconcile、current governance decision/hold | 不选 provider/tier，不决定 retention/delete/risk/project state |
| safe query | Q01～Q05、current visibility、single snapshot、safe cursor/marker、zero write/effect | cursor/visibility formal binding 未闭合时 positive continuation blocked |
| restore | frozen owner set/plan/item/material/handoff/outcome/compensation | 不直写 owner DB，不跨 owner transaction，不推导 project restored |
| evidence | targeted raw/report、same-run final EV、acceptance handoff 草稿与 review | 当前只规划能力；没有真实实例或 verdict |

### 6.1 统一编写顺序、闭环复核与提交规则

每个 boundary 依次执行：读取 project/current-boundary ledger 和正式 input → 固定 immutable baseline、scope 与 blocker → 锁定 typed contract/ref/DTO/state 与最小测试切口 → 建立 test/fault/spy 入口 → domain invariant/transition → application port/UoW/CAS/idempotency/result/receipt/report → controlled fake 或经核验 adapter → 本 boundary API/worker/job entry → error/recovery/concurrency/redaction/negative case → required checks 与同 run raw/report（适用时）→ Gate 逐项停审 → 用户授权后才可能 commit。

开工前的 Design Gate 必须逐项确认：字段与 DTO 构造、support carrier/schema、typed-ref kind/owner scope、18-state/错误映射、authority/visibility/compatibility/hold 的 validation truth、metadata/idempotency/UoW、Query view/page/marker、source/material/`Auxiliary`、accepted side effect、artifact/report/evidence 的 writer-reader/path/digest/redaction/same-run，以及不会引用后续 Phase 的对象、结果或证据。缺任何一项都 `wait_design`；不得以 private map、default、string parsing、fake 或 outbox 偷补。

每个批次一般保持 100～300 行；超过 300 行应拆，超过 500 行必须拆；UoW/CAS/idempotency/effect/cursor/redaction/evidence 等高风险逻辑即使不足 300 行也必须独立批次。最终仍是一 boundary 一笔未来 commit；批次不是独立提交授权。

### 10.1 统一控制状态机

```text
planned / waiting / blocked
        | owner closure + user implementation authorization
        v
read_docs -> design_gate -> implement -> run_gates -> commit_gate -> handoff_gate
                |             |            |              |
                +---- blocker/pause <------+--------------+
                              |
             +----------------+----------------+
             |                                 |
       wait_design                      fix_gate_failure
             |                                 |
       new baseline + audit               new immutable run
             +----------------+----------------+
                              |
                       reopen same boundary
```

禁止跳转：`planned→implement`、`pending/blocked→commit`、`CommitUnknown→redispatch`、`failed raw→手写 pass report`、`owner contract missing→fake production`、current boundary 未过 Handoff Gate 就进入下一 boundary。

### 10.2 暂停触发与恢复

| 触发条件 | 立即动作与保留 | 恢复条件 |
|---|---|---|
| 03～07 字段/DTO/state/port/error/flow 不闭合 | 当前 boundary=`blocked/wait_design`；记录行号、diff、复现输入 | 正式回写、新 immutable baseline、闭环审计 |
| owner source/version/fence/material/receiver 缺失/冲突 | 停对应 positive lane，不调用/不写 owner；保留 typed mismatch/ref | owner 正式 contract/vector/binding |
| source 缺失拟用 workspace fallback | 停 capture/closure；记录 Auxiliary 违规证据 | exact owner source；workspace仍 Auxiliary |

| UoW 半提交、CAS/read-set/fence/result 丢失 | 停 current 和依赖 boundary；保留 transaction probe/raw | 同 boundary 修复并 fault/restart/race/replay 重跑 |
| external `MayHaveDispatched/CommitUnknown` | 冻结原 intent/key，禁止换 key/盲重派 | exact probe/reconcile 或正式补偿授权 |
| governance decision 缺失/过期/冲突/legal hold | effect=0，暂停 lifecycle/delete | current owner decision + dispatch-time recheck |
| receiver/material 缺失/漂移/unknown | 只暂停对应 owner item；保留 frozen set/plan/outcome | exact receiver/material closure；必要时新 plan revision |
| integrity/schema/key/algorithm 缺失或失败 | assessment/placement/restore positive blocked；不得 Verified | formal capability/schema/vector |
| outbox/topic/publisher/delivery 意外出现 | 停 release，VETO-009，移除或回开 02～07 | 全面 absence，或正式 ADR 级联回写 |
| dependency 反向 SDK/non-Core sibling | 停 PH-01/Build/Release，保留 graph/manifest | owner docs 对齐、actual graph clean |
| redaction leak/secret/body 进入输出 | 隔离输出，暂停交付，保留 scanner/incident ref | 清理、修复、新 run 全量重验 |
| Gate failed/blocked/not_run/infrastructure_failed | 不进下一 boundary，状态保真并保留 raw/report | 同 boundary 修复/解阻后新 run |
| 无用户 implementation/commit 授权 | 保持 design-only/working tree；不实现、不提交 | 新明确授权且其他 Gate 独立满足 |

### 10.3 回退、补偿、对账与变更回写

代码回退、业务补偿和知识对账是三个不同动作：代码回退不撤销外部 effect；补偿不抹除原 outcome；对账不自动重派命令。未提交本地失败只能在 current allowed scope 内修复，不能 destructive reset/checkout 覆盖用户改动；已提交 boundary 的修复/revert 需新授权、新记录，不 amend/rebase 共享历史。immutable manifest/assessment/plan 只能创建新 revision 并 supersede，不能 in-place overwrite。

涉及 requirement/owner/policy、依赖类型、object/DTO/state/port/flow、codec/store/config、source/material/integrity/storage/receiver、TC/EV/VETO、AC 或 phase/boundary 的变化，必须回写相应正式真相源并级联重开受影响 `00～07`/Gate。outbound 从 0 变为非零必须重开 `02` Step 6～9 并级联；不能只在 adapter/config/script 中偷偷加入。设计变更完成后必须固定新 immutable baseline、重跑 16-row 闭环审计并使用新 run；旧 raw/report/EV 保留且不能证明新 baseline。

| boundary group | 主要恢复前置 |
|---|---|
| 01-a/01-b | target repo、Core graph、55-key/schema、artifact writer/reader、clean scope |
| 02-a/02-b | operation codec/digest、字段/状态、durable UoW/CAS/read-set/probe/fence |
| 03-a/03-b | visibility source、cursor mapping/codec/key、redaction、zero-write |
| 04-a/04-b | 8 source conformance、material closure、Auxiliary、exact-set/read-set |
| 05-a/05-b | integrity/schema/capability vector、fixed input、immutable save/replay |
| 06-a/06-b | storage outcome/probe、current governance/hold decision、zero-effect |
| 07-a/07-b | exact owner set、Artifact material、receiver/outcome/compensation |
| 08-a/08-b | machine schema、same-run raw/report/EV、all required lanes、named review |

恢复只能重开同一 boundary；`pending`/`blocked`/`not_run`/`infrastructure_failed` 不得转换为 `pass`。保留已验证阶段必须由影响分析证明，不能仅凭已有 commit 推定。

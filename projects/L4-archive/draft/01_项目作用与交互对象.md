## 1. 一句话定位

`L4-archive` 是一个**受控的跨域归档与恢复材料边界**：它接受各 owning domain 明确授权的快照/导出或引用输入，围绕归档请求与作业建立 Archive Bundle、manifest、内容闭包、来源绑定、完整性/签名状态、存储层级、生命周期记录，以及恢复验证、恢复计划、恢复材料和向各真相 owner 的 handoff 记录。

Archive 解决的是“如何把已获准、可验证、可追溯的跨域材料封装为可验证的历史包，并在恢复申请时安全地把材料交回各 owning domain”。它不解决“项目是否 archived/dissolved/restored、是否批准归档、保留多久、是否允许删除、业务事实如何恢复”。这些决定属于相应正式 owner。

### 1.1 为什么必须单独存在

| 易混淆对象 | 当前边界结论 |
|---|---|
| `L1-work` | 拥有 `Project`、`ProjectMember`、`WorkItem` 等工作事实和项目生命周期。Archive 只消费已授权快照/导出，不能写入或发布 `Project` 状态。 |
| `L1-identity` | 拥有 `GlobalMember` 身份真相。Archive 可封装 identity snapshot/ref，不拥有身份正文或生命周期。 |
| `L1-conversation` | 拥有 Conversation/Turn/Participant 对话真相。Archive 可接收允许归档的对话切片引用或安全导出，不把 Archive Bundle 当对话真相。 |
| `L1-process` | 拥有 ProcessInstance/Activity/checkpoint 等过程事实。Archive 只封装获准材料，不推进或回滚过程。 |
| `L1-governance` | 拥有 Policy、Gate、Decision、风险接受及正式治理结论。RetentionPolicy、legal hold、删除/销毁授权和风险接受不由 Archive 解释；当前缺少完整正式接缝时保持 blocker。 |
| `L1-artifact` | 拥有 Artifact 正文、版本、血缘、baseline。Archive 只保存允许归档的 artifact ref/版本/摘要/内容引用或受控材料，不拥有通用 Artifact truth。 |
| `L1-workspace` | 只拥有跨域只读 projection 与局部 view state。Workspace projection 可作为明确标注的只读输入，不能冒充 L1 canonical snapshot，也不能成为恢复写权限。 |
| `L4-observability` | 拥有审计链、观测材料和观测后端边界。Archive 只消费获准的审计材料/引用，不承接实时 telemetry、后端或审计链真相。 |
| `L0-bus` | 拥有事件传递、delivery、ack、retry、replay carrier truth。Archive 可通过正式事件协作接收归档触发或变化提示，但不拥有 bus 事实。 |
| `L0-sdk` / 产品 | SDK、Console、Sync 等是访问或消费方。Archive 不拥有 SDK client/cache、产品 UI 或同步私有状态。 |

## 2. 本仓拥有、只消费、禁止拥有

### 2.1 Archive owned local truth（候选）

| 主题 | Archive 可以拥有 | 明确不包含 |
|---|---|---|
| 归档入口 | `ArchiveRequest`、归档作业、作业阶段/结果/重试记录 | 业务归档批准、项目生命周期迁移、治理 decision |
| Bundle | `ArchiveBundle`、manifest、bundle schema/version、内容闭包、slice inventory、source binding、coverage 和完整性状态 | 各域 canonical entity truth、共享数据库事务 |
| 完整性 | digest/signature verification result、签名/摘要引用、校验历史、commit-unknown/失败状态 | 私造 digest 算法、KMS/secret truth、签名服务内部密钥 |
| 存储 | archive-owned storage location ref、hot/warm/cold tier 状态、迁移作业记录、可取回性状态 | 对象存储供应商、bucket/key 体系、备份平台本体 |
| 生命周期执行接缝 | 由正式 owner 提供的 retention/hold/delete decision ref、执行记录、阻断原因 | RetentionPolicy、legal hold 规则、销毁授权、风险接受决定 |
| 恢复 | `RestoreRequest`、包验证结果、恢复计划、恢复材料、每个 owner 的 handoff/ack 状态和 compensation/retry 记录 | 直接改写 L1 数据库、发布 `project.restored` 业务事实、替 owner 做 partial merge |
| 归档读取 | 归档索引/manifest 查询、验证结果和安全状态 | operational query、实时 observability、产品 UI truth |

### 2.2 不可越界的恢复原则

恢复是材料交接，不是跨域写权限。Archive Bundle 只能向 owning domain 的正式 `import` / `restore` / `command` / `handoff` 边界提供恢复材料；每个 owner 必须自己决定接受、拒绝、部分接受、冲突处理和最终业务状态。Archive 不得直接重写上游数据库，不得把“材料已生成”解释为“业务已恢复”。

## 3. Source-authority matrix（候选）

每个切片必须单独记录 source authority、版本/水位、快照 fence、覆盖范围、摘要/正文边界和恢复目标。不存在跨域全局强一致快照的前提；“bundle complete”只能在请求声明的来源集合均有可证明输入时成立。

| 归档切片 | Canonical truth owner | Archive 允许接收 | `L1-workspace` 只读投影的地位 | `L1-artifact` / 血缘地位 | `L4-observability` 地位 | Archive 禁止声称 |
|---|---|---|---|---|---|---|
| identity | `L1-identity` | owner-approved identity snapshot/ref、版本/水位、覆盖和安全摘要 | workspace member projection 只能作辅助索引，不能替代 identity snapshot | 若存在制品关联，只能作 ref | 审计材料仅作 provenance | Archive 不得声称身份状态由自身决定 |
| conversation | `L1-conversation` | owner-approved conversation/turn slice ref 或受控导出、版本/fence、缺口 | workspace 对话摘要是只读 projection，不能替代对话 canonical | 对话引用的 Artifact ref 仍由 artifact owner 解释 | 审计链不替代对话历史 | Archive 不得声称对话已读、参与者或可见性由自身决定 |
| work | `L1-work` | Project/ProjectMember/WorkItem approved snapshot/export/ref、生命周期状态和 version fence | ProjectWorkspace projection 只能作为辅助视图，不能证明 Work truth | 完成依据中的 Artifact ref 仍回链 artifact | 操作审计材料不替代 Work history | Archive 不得发布或改变 `archived/dissolved/restored` 状态 |
| process | `L1-process` | ProcessInstance/Activity/checkpoint approved snapshot/ref、版本和覆盖 | workspace process 摘要不能作为过程事实 | process 产物引用回链 artifact | trace/audit 仅作过程观察材料 | 流程已经推进或回滚 |
| governance | `L1-governance` 或明确治理 owner | Gate/Decision/Policy/retention/legal-hold decision ref、适用范围和有效性 | workspace governance projection 不能作授权/治理真相 | 治理证据中的 Artifact ref 回链 artifact | 审计材料只证明观察/留痕 | Archive 不得批准、延长保留或解除 hold |
| artifact | `L1-artifact` | Artifact fact/version/baseline/lineage refs、owner-approved content/export、digest/版本上下文 | workspace artifact projection 仅是消费视图 | Artifact 正文、版本、血缘、baseline 的 canonical authority 仍在 artifact | artifact 观测/审计材料不能替代 artifact truth | Archive 不得将 Bundle manifest 变成 Artifact baseline |
| workspace projection | `L1-workspace`（只读 projection owner） | 明确标注的 projection/ref、generation/revision、coverage/status | 只能证明 workspace view 在某语境下的 materialization | 其中的 Artifact ref 不转移 authority | projection 变化可作为 provenance | projection 是 L1 canonical truth 或完整跨域快照 |
| observability/audit | `L4-observability` | approved audit/evidence material ref、source version、redaction/coverage 状态 | workspace audit 摘要不替代 observability | evidence/Artifact ref 仍由各 owner 解释 | 审计链、观测材料和后端归 observability | Archive 不得将 record 当作实时审计流或观测后端 |

### 3.1 切片的最小 source binding

候选 binding 至少表达：`source_owner`、`source_kind`、`source_ref`、`source_schema_version`、`source_version_or_watermark`、`snapshot_fence`、`coverage`、`visibility_basis_ref`（如适用）、`material_kind`（ref/summary/export/blob）、`integrity_status` 和 `captured_at`。这些只是需求讨论字段类别，不能在本 draft 中私造正式 DTO 或算法。

|---|---|---|---|---|

### 5.1 依赖裁剪图与 path dependency 判定

```text
Global baseline
      |
      | crop L4-archive related edges only
      v
L0-core --[compile candidate]--> L4-archive
L0-bus  --[event/adapter]-----> L4-archive
L1 owners --[runtime/ref/event]--> L4-archive
L1-artifact / L4-observability --[ref/runtime]--> L4-archive
L4-archive --[adapter/ref]--> SDK / Console / Sync / restore receivers
external storage/signature/KMS --[runtime/adapter]--> L4-archive
```

结论：只有 `L0-core` 在正式契约核验通过后可作为 compile candidate。任何 L1 sibling、`L4-observability`、`L1-workspace`、对象存储供应商、签名/KMS、SDK 或产品均不得被写成本地业务 package/path dependency。`fake` 仅用于未来测试隔离，不证明真实 owner、存储、签名或恢复方已可用。

## 6. 生命周期与权责边界（候选）

| 决定/事实 | owning authority | Archive 允许行为 | Archive 禁止行为 |
|---|---|---|---|
| 项目 archived/dissolved/restored | 当前正式项目/工作 owner（`L1-work` 及其正式协作） | 读取状态作为前置条件，记录 source ref/version | 自行转换、发布或反写状态 |
| 归档是否获准 | 明确的业务/治理 owner | 执行已批准请求；拒绝缺少决定的请求 | 以请求者角色或历史状态推断批准 |
| RetentionPolicy | `L1-governance` 或待明确 owner | 消费 policy ref，执行已明确的动作并记录结果 | 创建/解释/延长/缩短 policy |
| legal hold | governance/法律明确 owner | 消费 active/released hold decision，阻断不允许动作 | 自行施加、解除或覆盖 hold |
| 删除/销毁授权 | governance/明确 owner | 在正式授权下执行受控处置，保存执行状态 | 自行决定 purge、销毁或风险接受 |
| Artifact 正文/血缘 | `L1-artifact` | 保存归档材料的引用/闭包成员 | 反写 Artifact、重建血缘真相 |
| 审计链/观测后端 | `L4-observability` | 保存获准审计材料引用与 provenance | 成为实时观测后端或审计链 owner |
| 恢复业务状态 | 各 truth owner | 验证包、准备材料、按 owner seam handoff | 直接重写数据库或把 bundle 当通用写权限 |

## 8. 当前 blocker / pending（候选编号）

| ID | 未闭合边界 | 影响 | 当前安全上限 |
|---|---|---|---|
| `AR-UP-001` | 各 L1 owner 的 snapshot/export/query 合同、source version/watermark、fence、coverage 尚未统一 | 无法承诺跨域完整快照或固定切片字段 | 逐 source binding、unknown/partial/block 状态 |
| `AR-UP-002` | `L1-work` 项目 archived/dissolved/restored 状态与 Archive 触发/恢复 handoff 的正式接缝不足 | 不能自行判断生命周期或发布恢复状态 | 读取正式 owner 决定；缺失即 blocked |
| `AR-UP-003` | Governance 的 RetentionPolicy、legal hold、删除授权、风险接受与 Archive 执行接缝未闭合 | 不能安全执行保留、迁移、删除、销毁 | fail-closed，不默认保留 7 年或允许 purge |
| `AR-UP-004` | digest、签名、密钥、加密、压缩和 schema evolution authority 未确定 | 无法声称 bundle 可验证、长期可读或可恢复 | 保存待验证状态/ref；不私造算法、key 或 digest |
| `AR-UP-005` | 对象存储位置、冷热层级、迁移与取回语义未确定 | 不能承诺 hot/warm/cold、可用性或 RTO | storage adapter seam + pending 状态 |
| `AR-UP-006` | Artifact archive handoff 的内容闭包、正文/引用边界和版本兼容接缝需逐项核验 | 不能把 Artifact ref 集合当完整包内容 | 只接收 owner-approved ref/material，缺口可见 |
| `AR-UP-007` | Observability audit/evidence material 的归档 export、redaction、保留和验证接缝未闭合 | 不能把 audit 摘要当完整审计链 | 只消费安全材料/ref，未知即 blocked |
| `AR-UP-008` | Workspace archive read/export contract（WS-UP-006）未闭口 | workspace projection 不能成为稳定归档源 | projection 只能作明确标注的辅助输入 |
| `AR-UP-009` | 各 owning domain 的恢复接收方、partial/stale/missing/conflicting/unsupported/integrity-failed/commit-unknown 反馈与补偿语义未闭合 | Restore 不能声称成功 | 分 owner handoff 记录和独立状态 |

## 9. 本篇讨论结论

当前 draft 仅收束以下方向：Archive 拥有归档专属 bundle/manifest、作业、存储/完整性状态、恢复计划/材料和交接记录；跨域切片必须按 source authority 分开记录；workspace projection、artifact lineage/ref、observability audit material 不能冒充各 L1 canonical truth；项目生命周期、治理保留/删除权、Artifact 正文/血缘和 observability 后端均由外部 owner 保持；恢复必须通过 owner 正式边界完成。

下一篇 draft 将围绕归档请求到 Bundle sealing、验证、存储迁移、恢复申请到 owner handoff 的能力闭环推演；仍不进入正式 `00` Step，也不锁定 schema、算法、供应商、时间数字或成功结论。

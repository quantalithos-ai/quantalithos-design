# 03 · L4-archive 模块划分与分层（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源\
> 前置：`draft/01_项目作用与交互对象.md`、`draft/02_功能推演.md`\
> 本文用途：为后续正式 `01/02/03` 提供模块、分层、对象类别、状态组和 seam 的候选骨架。\
> 约束：不创建 crate、文件、trait、表、路由、事件 schema、配置键、测试报告或实施 boundary；所有名称均为候选。

## 1. 业务主要组成部分（候选）

| # | 组成部分 | Archive-owned 职责 | 不承担什么 | 主要能力 |
|---|---|---|---|---|
| 1 | `Archive request & scope` | 受理请求、范围、依据、幂等语境和 source matrix 版本 | 不批准业务归档、不改变 Project 状态 | `FR-AR-001/002` |
| 2 | `Source capture & fence` | 编排 owner-safe snapshot/export/ref，保存 version/watermark/fence/coverage | 不读内部表、不提供全局强一致幻觉 | `FR-AR-003` |
| 3 | `Bundle manifest & content closure` | 组装 Bundle/manifest、切片 inventory、条目闭包和 source binding | 不复制未授权正文、不将 projection 当 truth | `FR-AR-004/005` |
| 4 | `Integrity & compatibility` | digest/signature/版本兼容验证状态、失败隔离和历史 | 不拥有密钥、算法、KMS 或 schema authority | `FR-AR-006/015` |
| 5 | `Storage placement & lifecycle` | location ref、hot/warm/cold 状态、迁移/取回作业和执行记录 | 不拥有对象存储、RetentionPolicy、legal hold 或销毁授权 | `FR-AR-008/009` |
| 6 | `Archive read & verification` | manifest、bundle、来源、coverage、integrity、兼容性和作业状态只读查询 | 不回源冒充 operational query，不写查询副作用 | `FR-AR-010` |
| 7 | `Restore planning & materialization` | 恢复请求、目标 owner 计划、包验证、分 owner 材料和缺口 | 不直接写上游库，不产生项目 restored truth | `FR-AR-011/012` |
| 8 | `Owner handoff & outcome` | 向 owner 正式边界交接，记录 accepted/rejected/partial/unknown/compensation | 不替 owner 决定业务提交、状态或冲突胜者 | `FR-AR-013/014` |
| 9 | `Operations, audit & reconciliation` | 作业重试/幂等、校验、对账、失败报告、安全诊断和局部维护 | 不把 report、audit 或指标升级为业务 truth | `FR-AR-016` |

### 1.1 组成部分关系图

```text
 [Request & scope]
          |

 [Source capture + fence] ---> [Integrity + compatibility]
          |                                  |
          v                                  v
 [Manifest + content closure] --------> [Storage placement]
          |                                  |
          +--------------> [Archive read/verify]
                                             |
                                             v
```

图中箭头表示候选数据/控制依赖，不表示跨仓事务或成功传递。任何阶段均可产生 blocked/partial/unknown；只有满足明确的本地前置条件才可推进下一阶段。

## 2. 实现分层（候选）

| 分层 | 本仓职责 | 边界纪律 |
|---|---|---|
| Inbound / Operations | 接收 archive/restore request、verify、migration、retry、reconcile 触发 | 入口不直接访问 owner DB；不把 transport/UI 混入领域语义 |
| Application services | 编排 source capture、manifest、integrity、storage、restore、handoff、幂等和错误映射 | 跨域调用只能经正式 port；阶段状态不可互相冒充 |
| Domain model & policies | 定义 ArchiveRequest、Bundle、Manifest、SliceBinding、Closure、Verification、Storage/Restore/Handoff 状态与不变量 | 不定义治理 policy、业务 lifecycle、签名算法或外部 owner 状态 |
| Ports / external seams | owner snapshot/export/query、bus event、storage、digest/signature、KMS/secret、restore receiver、clock/lock | seam 未闭口时只返回 pending/blocked/fail-closed；adapter 不拥有 authority |
| Persistence / index | 保存 archive local truth、manifest/index、source binding、integrity、location、job、restore/handoff record | 不存共享 owner 表、未经允许的外部正文或 raw secret |
| Material / storage adapter | 将 approved material 写入外部存储并读回验证 | 不决定 placement policy、保留期或销毁权；commit unknown 必须显式 |
| Handoff / reconciliation | 生成 owner-specific material/ref、记录结果、重试/补偿和对账报告 | 不直接命令上游；report 不是业务结论 |

## 3. 关键对象类别（候选，字段后置）

### 3.1 Archive-owned truth

| 对象 | 作用 | 关键约束 |
|---|---|---|
| `ArchiveRequest` | 归档请求与声明范围 | 不等于业务批准或 Project 状态变化 |
| `ArchiveJob` | 归档处理阶段、attempt、幂等和结果 | job complete 不等于 source/owner complete |
| `ArchiveBundle` | 归档包局部锚点 | 不成为任何 L1 truth 的替代 |
| `BundleManifest` | schema/version、slice inventory、内容闭包声明 | 每个条目必须有来源绑定；缺失/多余显式失败 |
| `ArchiveSliceBinding` | source owner、ref、version/fence、coverage、material kind | 不把 workspace projection 或 audit 摘要升级为 canonical |
| `BundleContentClosure` | manifest 与材料/引用闭包的验证结果 | 不允许缺片后补或隐式默认 |
| `IntegrityVerification` | digest/signature/密钥引用和校验状态 | 不存私钥、raw secret 或私造算法结论 |
| `StoragePlacement` | location ref、tier、可取回性和迁移记录 | 供应商、bucket、冷热阈值待配置阶段闭合 |
| `LifecycleExecutionRecord` | retention/hold/delete decision 的执行结果 | 只引用 owner decision，不拥有规则 |
| `RestoreRequest` / `RestorePlan` | 恢复范围、目标 owner、阶段和材料计划 | 不改变上游业务 lifecycle |
| `RestoreMaterial` | owner-specific 恢复材料和 source binding | 不把 bundle 作为通用写权限 |
| `HandoffRecord` | 交接目标、输入、结果、重试/补偿状态 | accepted/committed 由 owner 产生 |

### 3.2 状态与支持对象

| 对象类别 | 作用 | 禁止混用 |
|---|---|---|
| `SourceCoverage` | 记录每个 slice 的 coverage、缺口、版本和 fence | 不等于全局完整性 |
| `CompatibilityAssessment` | schema/source version 的支持/未知/迁移需求 | 不自动转换未知版本 |
| `ArchiveOperationResult` | 本地 command/job 的 result/ref/status | 不写 owner 成功或恢复成功 |
| `RetryOrCompensationRecord` | 记录副作用不确定、owner partial 或补偿路径 | 不以 retry 次数推断成功 |
| `AuditMaterialRef` | 指向安全审计/观测材料 | 不成为 observability 链本体 |

## 4. 状态组与状态机方向（候选）

| 状态机 | 候选状态 | 主要守卫 |
|---|---|---|
| `ArchiveJobState` | `requested → collecting → assembling → verifying → sealed`；任意阶段可 `blocked/failed` | request scope、source coverage、closure、integrity 通过；不可跨阶段跳成功 |
| `SliceState` | `requested / captured / partial / stale / missing / conflicting / unsupported-version / invalid` | owner response、version/fence、visibility/coverage 证明 |
| `ClosureState` | `open / complete / incomplete / overfull / invalid` | manifest 与材料/引用集合一致 |
| `IntegrityState` | `unchecked / pending / verified / integrity-failed / unknown` | 正式 digest/signature/KMS 合同；未知 fail-closed |
| `StorageState` | `location-pending / hot / warm / cold / retrieval-pending / unavailable / commit-unknown` | 外部存储反馈和读回验证 |
| `LifecycleState` | `not-requested / eligible / held / blocked / executed / unknown` | 正式 retention/hold/delete decision ref |
| `RestoreState` | `requested / validating / planning / materializing / handing-off / partial / completed / failed / blocked` | 包完整性、兼容、owner target 和各 item outcome |
| `OwnerHandoffState` | `planned / material-ready / handed-off / accepted / rejected / partial / commit-unknown / compensation-required` | owner receiver response；Archive 不代填 committed |

### 4.1 状态转换红线

1. `sealed` 只证明 Archive 本地 manifest/closure/integrity 条件，不证明 Project archived。
2. `eligible` 只证明收到可解释 decision ref，不证明 Archive 自有权力销毁。
3. `material-ready` 不证明 owner 已接收；`accepted` 不必然等于 owner 已提交业务 truth。
4. `commit-unknown`、`conflicting`、`integrity-failed`、`unsupported-version` 不能被 retry 隐藏或自动变成成功。
5. `partial` 必须按 slice/owner item 暴露范围；不能把已完成局部合并成全局 complete。

## 5. 关键 port / seam 类别（候选）

| seam | 方向 | 能力 | 分类与约束 |
|---|---|---|---|
| Owner snapshot/export/query port | 出站 | 获取 approved snapshot/export/ref、version/fence/coverage | `runtime/ref`；no-write；各 owner 独立闭合 |
| Owner restore receiver | 出站 | 交接 source-specific restore material | `runtime/adapter`；owner 决定接受/提交 |
| Bus subscription port | 入站 | 接收 archive trigger/change/replay signal | `event`；bus 负责 delivery/ack/retry truth |
| Storage object port | 出站 | put/get/move/verify archive material | `runtime/adapter`；供应商和 location schema pending |
| Digest/signature verification port | 出站 | 计算/验证摘要、签名和 key reference | `runtime/adapter`；算法/KMS/secret authority pending |
| Retention/hold decision port | 出站 | 读取治理决定和有效性 | `runtime/ref/event`；Archive 只执行，不解释 policy |
| Clock / id / lock port | 入站 | 本地时间、ID、并发和 lease | `adapter`；不改变 truth ownership |
| Archive read/export port | 出站 | 提供 manifest、验证、coverage、restore material ref | `adapter/ref`；下游不得反向写 Archive truth |

`fake` 仅用于后续测试验证本地状态和失败分类；不能生成真实 owner approval、storage commit、签名有效、retention decision、restore acceptance 或 readiness。

## 6. 一致性、事务和失败切面（候选）

| 本地原子边界 | 可原子收口 | 外部不变量 |
|---|---|---|
| Request admission | request、scope snapshot、idempotency reservation、初始 job state | 不改变 Project 或 governance truth |
| Slice capture application | source binding、coverage、slice state、capture attempt | owner snapshot 是否完整由 owner 证明 |
| Bundle assembly | manifest、closure result、bundle revision、job result | 不把对象存储上传成功当 sealed |
| Integrity verification | verification result、failure finding、bundle state | signer/KMS 真实验证由 adapter 返回 |
| Storage placement | location ref、tier state、migration attempt | 外部 put/move 的 commit unknown 不能靠重复 write 解决 |
| Restore planning | restore request、compatibility、plan、per-owner item | 不创建上游业务实体 |
| Handoff outcome | handoff record、item outcome、retry/compensation marker | owner accepted/committed/restored 由 owner truth 决定 |

## 7. 模块推进裁剪（供正式文档参考）

| 方向 | 最小进入条件 | 当前状态 |
|---|---|---|
| A. request/scope | owner identity、归档授权和范围语义可验证 | `AR-UP-001/002` blocker |
| B. single-slice capture | 一个 owner 提供 no-write snapshot/export + version/fence | 逐 owner pending |
| C. bundle/closure | source binding、内容闭包和完整性字段闭合 | `AR-UP-001/004/006/007` blocker |
| D. storage/lifecycle | location/tier、签名/KMS、retention/hold/delete 接缝闭合 | `AR-UP-003/004/005` blocker |
| E. restore/handoff | owner receiver、兼容和 partial/unknown/compensation 反馈闭合 | `AR-UP-009` blocker |
| F. cross-domain package | 每个纳入 slice 逐项通过 source-authority matrix | 不得以“六域 6/6”替代 |

## 8. 历史污染审计与待确认

| 污染/待确认 | 影响模块 | 处理 |
|---|---|---|
| Rust/S3/MinIO/Glacier/PostgreSQL 固定选型 | 所有 infra/storage | 仅作 historical material；后续架构/配置重新裁决 |
| 7 年、5 分钟、2 分钟、99.9% 等数字 | storage/job/restore NFR | 无来源 baseline 不继承，保持 pending |
| ComplianceDeclaration/SoA/AIIA 自动生成 | governance/integrity | 等正式 authority；Archive 只保存 ref |
| dissolved 不可恢复、archived→active、project.restored event | lifecycle/restore | 与 owner boundary 冲突，禁止写入当前结论 |
| archive index 作为业务索引、workspace projection 作为 snapshot | read/source binding | 明确禁止，query 与 source matrix 分层 |
| 缺片后补、缓存降级算完整 | closure/verification | 显式 incomplete/blocked，fail-closed |

## 9. 本篇讨论结论

候选模块可收束为：请求与范围、逐 source capture/fence、manifest/内容闭包、完整性/兼容、存储/生命周期执行、归档读/验证、恢复计划/材料、owner handoff/outcome、运维对账。后续正式文档必须逐模块完成字段来源、状态转换、事务/UoW、port、错误、测试切口和实施 boundary 闭环；在上游 blocker 未解除前，所有模块只能标记 pending/blocked，不得生成实现或 readiness。

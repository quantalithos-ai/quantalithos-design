### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L4-observability` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L4-observability` 是平台观测与证据汇聚层,不是 source truth 仓或控制命令仓
- ObservabilityEvent 构成统一观测接入主线
- `observability projection ≠ source truth` 必须成立,投影视图不会反写 runtime / sandbox / capability-hub / method-library / governance / artifact 真相
- `Trace / metric / log ≠ execution truth`、`Audit aggregation ≠ governance decision`、`Cost dashboard ≠ finance ledger truth`、`Drift report ≠ method-library truth` 等核心边界必须成立
- execution / drift / cost 三类观察面必须可以统一聚合并彼此对账
- health summary / alert / diagnostic 必须始终建立在正式观测证据链之上,且 `Health summary ≠ operational command`、`Alert rule ≠ source policy truth`
- retention / replay / source gap 主线必须成立,不能越权清理仍需诊断或对账的证据材料

因此,本次验收的目的不是笼统判断“能不能看图表”,而是判断 observability 的 ingest 主线、execution/resource 主线、audit/drift 主线、cost/usage 主线与 query/alert/diagnostic 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 观测事件采集与统一接入部分 | 是 | ObservabilityEvent、SourceTag、ContextBinding、EventEnvelopeRef |
| 执行与资源观测部分 | 是 | ExecutionHealthView、ResourceUsageView、RetryReplayView、QueueLatencyView |
| 治理、审计与漂移观测部分 | 是 | AuditAggregationView、DriftReport、PolicyRefreshTrace、DenyTrendView |
| 成本、用量与经营观察部分 | 是 | CostDashboard、UsageTrendView、ProviderCostSlice、ProjectCostSlice |
| 查询、告警与诊断出口部分 | 是 | HealthSummary、AlertRule、AlertTriggerRecord、DiagnosticView、DashboardQuery |
| runtime / sandbox / capability-hub / method-library / governance / artifact 真相本体 | 否 | 只验 observability 如何消费其观测材料,不验这些仓的 source truth 全部实现 |
| 自动化响应执行逻辑 | 否 | 只验告警输出与证据链,不验下游执行命令 |
| finance 正式总账 | 否 | 只验成本观察面,不验财务系统本体 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| IngestObservation | 合法 source tag / context binding 时必须形成正式 ObservabilityEvent | API 响应 / DB 记录 / trace | [] |
| Ingest 边界 | ingest 只接收观测材料,不得推进 source truth 状态迁移 | model review / negative flow / payload compare | [] |
| BuildExecutionHealth / BuildUsageViews | execution / usage 主线材料齐全时必须形成统一运行观察面 | execution health view / usage view / compare report | [] |
| Execution 观察边界 | execution 健康面不得冒充 runtime/sandbox 真相,trace/log/metric 只作为观察结果 | compare report / negative flow | [] |
| BuildAuditView / BuildDriftReport / BuildDenyTrend | audit / drift / refresh 事件齐全时必须形成统一合规观察面 | audit view / drift report / deny trend | [] |
| Compliance 边界 | audit aggregation 不能替代 governance decision,drift report 不能替代 method-library 真相 | model review / negative flow / ref compare | [] |
| BuildCostDashboard / BuildUsageTrend | cost / usage 事件齐全时必须形成统一经营观察面 | dashboard view / trend view / slices | [] |
| Cost 边界 | cost dashboard 只能表达经营观察面,不得替代 finance ledger 或 provider 原始账单 | compare report / negative flow | [] |
| BuildHealthSummary | execution/drift/cost 三类观察面上下文一致时必须形成统一健康摘要 | health summary / evidence refs / compare report | [] |
| EvaluateAlertRules | 阈值命中且规则作用范围合法时必须形成 AlertTriggerRecord | trigger record / alert history / notification trace | [] |
| Alert/summary 边界 | health summary 不能冒充运维命令,alert rule 不能替代 source policy truth | negative flow / rule scope / response compare | [] |
| DashboardQuery / BuildDiagnosticView | 只读查询必须成功返回 dashboard / diagnostic 视图,且可回指原始证据链 | query result / diagnostic view / evidence refs | [] |
| Retention / replay 边界 | retention 不得越权清理仍需诊断/对账的材料,replay 必须有证据链 | retention conflict log / replay history | [] |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| projection 不可反写真相 | 所有视图和摘要只能消费 source event,不得回写 source systems | compare report / negative flow | [] |
| alert 不可污染 source policy | AlertRule 只能基于观测视图求值,不得替代 governance/runtime/capability policy | rule scope / negative test | [] |
| summary 不可越界成命令 | HealthSummary 只能给出观察结果,不得直接驱动 kill/retry 等动作 | summary/command separation report | [] |
| retention 不可越权 | retention 不得清理仍需诊断/审计/重放的材料 | retention conflict log / negative flow | [] |
| cost/drift 视图不可冒充真相 | CostDashboard / DriftReport 必须回指 source refs,不得充当 source truth | compare report / evidence refs | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | 投影视图反写真相 / health summary 越界成控制命令 / drift 报告冒充权威真相 / retention 越权清理证据 / alert 污染 source policy |
| A | 视情况 | 主线可跑但 source gap、dashboard stale、alert backlog、cost/drift 对账不稳 |
| B | 可带着走 | 非关键视图、低优先级 trend 或展示异常 |

### 1.3 Observability 的 truth 与协作边界

Observability 只拥有 observation-side fact、projection、marker、history、outbox、stored result、handoff input 和 derived maintenance。它只承载观测与审计投影，不拥有业务 source truth，不反写业务 truth，也不把 log、metric、trace、audit、evidence 或 report 自动提升为业务结论。

跨仓协作通过 typed ref、safe summary、event、runtime resolver、handoff、fake、controlled 或 disabled adapter 完成。只有 `core-contracts` 可以作为编译期 sibling dependency 候选；Bus、Identity、Governance、Artifact、Runtime、Sandbox、Archive 和外部产品不得进入 Cargo 编译图。

### 5.3 Phase 停审规则

每个 phase 结束时必须重新确认：功能增量可独立验证；没有依赖后续 phase 才能解释的对象或结果；required gate 可执行；affected 分支仍为 open/controlled/conditional；失败可以暂停、保留材料并从本 phase 恢复。任一项不满足，phase 不得进入下一 phase。

### 6.1 通用编写顺序和批次规则

### 8.1 配置和 profile

current 配置由 typed root、strict source capture、profile/legal validation、private sensitive reference、store qualification、capability/availability builder 和 complete-or-error activation 组成。13-stage assembly 不能暴露 partial runtime；config 不能关闭 redaction、body-free、truth ownership、no-write 或 dependency boundary。

| Profile | 合法 lane | 允许的实现类 | 当前现实/不可用处理 |
|---|---|---|---|
| `LocalTest` | ENV-LCL-ISO | InMemory/Durable、System/Runtime 或 Fixed/Deterministic、Fake/Controlled/Disabled | instance 未建立则 planned/not_run |
| `IntegrationLike` | ENV-LCL-INT、ENV-CI-INT | Durable + System/Runtime、Controlled/Endpoint/Disabled | durable/INT 缺失 blocked/not_run；不由 ISO 替代 |
| `RuntimeLike` | ENV-STG-RT、ENV-PRD-RT | Durable + System/Runtime、Endpoint/Disabled、managed locator | instance 未建立 not_evaluated；不由 CI/fixture 冒充 |

非法组合必须返回 InvalidConfiguration，例如 IntegrationLike + InMemory/Fake 或 RuntimeLike + InMemory/Fake/Controlled/Fixed/Deterministic。Disabled 只适用于正式 optional surface，不能把 required capability 缺失变成成功。

### 8.2 外部依赖分类

| 依赖族 | 类型 | 使用阶段 | 最小输入 | 不可用处置 |
|---|---|---|---|---|
| source observation/audit material | event/runtime | PH-03~04 | body-free envelope、producer/schema、safe ref/context | required binding 缺失则 slot 不激活，I05 blocked |
| identity/governance/artifact context | runtime/event | PH-03~04 | typed ref、safe summary、visibility/gap | unavailable/rejected/gap，不补 truth |
| runtime/sandbox signal | runtime/event | PH-03~05 | safe summary、correlation、availability | explicit unavailable/degraded，无 raw result |
| bus/publisher | event collaboration | PH-04~07 | committed immutable snapshot、binding/token | pending/failed/dead-letter/manual，不重建 payload |
| reference resolver | runtime | PH-04~06 | body-free snapshot outcome、source position | unresolved/unavailable/gap，不保存 body |
| report/archive handoff | runtime/handoff | PH-06~08 | immutable preparation/input、retention/no-write readiness | blocked/manual/failed，Delivered 非 verdict |
| external audit/peripheral export | runtime/handoff | PH-06~08 | local preparation/view、stable token/binding | unsupported/unknown/manual，不盲重试 |
| store/UoW backend | runtime infrastructure | PH-03~07 | atomic UoW、CAS/cursor/fence/claim | mismatch fail-fast，不降级 mutex/InMemory |
| telemetry sink | runtime optional | PH-05~08 | safe schema、finite labels、body-free output | optional sink degraded，不改业务结果 |

### 8.3 Readiness 规则

目标仓缺失时只允许 PH-01/`commit-01-a` 处理 bootstrap；core path/package/type 不匹配时 blocked，禁止 vendor/shadow type；CI ISO 缺失时 required subset blocked/not_run；durable INT 缺失不能由 ISO/InMemory 升级；RuntimeLike 缺失为 not_evaluated；external unknown 只能 same-token probe/manual/finalize-only；telemetry sink failure 不控制 truth、retry 或 acceptance。

### 10.1 必须暂停

| 触发条件 | 动作 | 必须保留 | 恢复条件 |
|---|---|---|---|
| target repo absent、workspace/core 不可定位 | pause 当前 boundary | path check、ledger、用户改动说明 | target/worktree/toolchain/dependency 通过 |
| 字段/DTO/state/port/ref/source/version/marker/report ref 缺口 | pause + wait_design | 文件/章节/行号、影响 ID、建议闭口点 | 真相源回写、新 baseline、closure review |
| phase/boundary 越界或无关用户改动进入 diff | pause + change | diff、scope、git status | scope/staging 重新通过 |
| compile/unit/service/query/consumer/job gate failed | pause 当前 boundary | failed raw/report、命令和 diff | 修复或设计回写后重跑 |
| redaction/body-free/secret、truth write、writer capability | pause + hard_block | scanner/writer trace、相关 VF | 修复并重跑 GATE-OBS-08/09 和 VF |
| latest、cross-run、static pass 或 fake evidence | pause + hard_block | report audit、input manifest、失败材料 | generator 修复，同 run provenance 通过 |
| required INT/durable/runner unavailable | pause 相关 boundary | capability/lane 状态 | 依赖可用并重新执行；不得 ISO 替代 |
| RuntimeLike unavailable | not_evaluated | unavailable marker、scope | 真实 lane 建立后独立 run |
| inherited affected 未闭合 | controlled/blocked 对应 surface | exact affected register | 上游 owner/source/test/evidence closure |
| VF-OBS-001~010 或 EVG hard failure | pause + no_release | raw/report/checklist | 修复、复验、授权审查 |

### 10.2 回退范围

默认只允许清理当前 boundary 的未提交试探改动；不得触碰用户已有改动、其他 phase、已验证历史或其他 boundary。已提交 boundary 的缺陷默认新增修复 commit，未经用户明确要求不 amend/rebase。失败 raw/report 必须保留，修复后以新的真实 invocation 建立可回链材料，不覆盖旧失败。

外部结果为 indeterminate 时不盲重试业务 truth，不更换 token、target、binding 或 intent；只允许 same-token probe、manual 或 finalize-only 路径。Query、rebuild、handoff、job、exporter 获得 writer capability 时必须硬阻断。

### 10.3 设计变更分流

| 变更内容 | 回写真相源 | 必须同步 |
|---|---|---|
| object/protocol/flow/state/persistence/idempotency/source owner | `03-详细设计.md` | affected、boundary、gate、test cut |
| profile/ENV/CLI/entry/adapter binding | `04-配置设计.md`，必要时 03 | readiness、runtime boundary、config gate |
| TC/DS/suite/artifact/report/script | `05-测试方案.md` | gate、manifest、evidence path |
| AC/NFR/VF/EVG/reviewer/risk authority | `06-验收标准.md` | phase gate、completion、handoff |
| phase/boundary/batch/commit/ledger rule | 本正式 07 与 Step 产物 | flow、project ledger、boundary ledgers |
| 可泛化设计经验 | 设计真相源闭环标准/SOP | Step 03 memory seed、正反例和参考索引 |

### 10.4 恢复流程

    pause trigger
      -> classify failure and freeze current boundary
      -> preserve error/raw/report/diff/design line references
      -> fix implementation/tool or write back correct truth source
      -> record new baseline if changed
      -> repeat closure and experience review
      -> rerun affected boundary gates
      -> update project and implementation ledgers
      -> continue same boundary or explicitly activate next boundary

设计期没有真实恢复、回退、测试或 runner 结果；上述流程只是实施合同。

### 11.2 评审门禁

评审必须回答：boundary identity 是否唯一；功能增量是否内聚；字段/DTO/state/ref/source 是否闭合；是否越过 phase；Query/job/handoff/projection 是否取得 writer；是否有 raw/secret/body；report 是否同 run；affected 是否仍 open/controlled/conditional；是否误 stage 用户改动。失败时暂停、修复或回写真相源，不口头放行。

### 11.3 交付台账

设计仓必须保留：

- `projects/L4-observability/design-calibration/implementation_execution_ledger.md`

### 11.4 Artifact / report 交付

raw 只能写入 `artifacts/test/<run_id>`，run report 只能由同一 run 的 raw 生成到 `reports/runs/<run_id>`；acceptance/review 只产生待审输入。禁止 `latest`、跨 run 拼接、静态 passed、空 artifact、伪造 alias 或 generator 代签。

| P1/P2/future 未实现 | residual/future，有 owner/action/trigger | 可不计入 P0，但不得伪称完成 |
| 无来源性能/容量/retention 数字 | not_evaluated/residual | 不得宣称数字通过 |

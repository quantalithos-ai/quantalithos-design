## 3. 开工确认 / 必读文档:先思考

### 3.1 本步目标诊断

Step 03 的任务是回答 "`L4-observability` 为什么值得被当前阶段单独讨论",而不是提前写出它打算怎样做。对这个仓来说,最容易滑错的地方不是背景不够长,而是太快把背景写成 OTel、Prometheus、Grafana、TimescaleDB、append-only 审计链、hash linkage、retention policy、diagnostic API 或 report DTO 之类的实现与对象词。

本步另一个高风险点是把 Step 02 的仓边界或 Step 04 的目标重写一遍。Step 02 已经回答了“本仓是什么 / 不是什么”,Step 04 已经回答了“本次需求要达成什么 / 不达成什么”。Step 03 只负责把产品 / 系统背景、当前主要问题和业务问题 vs 技术问题说清楚,让后续目标、能力、规则、数据和验收都有稳定的问题起点。

## 5. 问题收敛:先思考

## 6. 问题收敛:再写入

### 6.1 写入原则

正式问题表只记录当前值得收束的背景和问题,不记录解决路径。每条问题都必须能被读者理解为“当前有什么矛盾,不解决会造成什么后果”,而不是“接下来我们要定义什么 schema / 功能 / 规则”。因此本节只写背景、问题和分类,不写能力闭环、不写接口动作、不写对象字段。

### 6.2 业务背景结论

Quantalithos 正在形成由事件协作、治理裁决、制品证据、身份引用、运行执行、审计复核和验收报告共同组成的平台链路。该链路中的关键活动需要被观察、审计、脱敏、关联和交接,但这些材料不属于任一单一业务 truth owner。当前讨论 `L4-observability`,是为了先把横切观测材料和审计投影的问题定义收束清楚,避免后续设计继续从产品栈、局部日志、临时 dashboard 或旧实现假设倒推需求。

### 6.2.1 背景约束小表

| 约束 | 当前结论 |
|---|---|
| 平台背景 | 多个 truth owner 都会产出需要被观察、审计和交接的材料。 |
| 当前讨论原因 | 这些横切材料没有统一需求基线,不能继续分散在各仓本地日志、外部工具和历史假设中。 |
| 本步边界 | 只定义为什么值得做,不定义怎样接入、怎样查询、怎样留存。 |

### 6.3 现状与问题结论

| 问题 | 当前表现 | 影响范围 / 后果 |
|---|---|---|
| 横切观测材料缺少统一需求基线 | 旧材料把 audit chain、trace、metrics、logs、dashboard、外部产品、性能数字和目录结构混在同一层讨论,没有先定义哪些属于 observation material,哪些只是实现或消费形态。 | 后续架构、概要和详细设计容易继承实现假设,难以先判断哪些材料属于观察面投影、哪些仍属于上游 truth owner。 |
| 审计投影与业务 truth 容易混层 | governance audit、artifact evidence、identity actor refs、bus receipt 和 runtime observation 各有来源,但旧材料缺少统一的 no-write truth 问题陈述。 | 本仓容易被误写成治理裁决、制品 / 证据正文、身份正文或执行结果的替代来源,导致多真相。 |
| 脱敏与关联口径缺少前置问题收束 | log、metric、trace、audit material、diagnostic summary 和 report handoff 都会携带跨仓上下文,但旧材料更关注采集、存储、展示和产品栈,没有先把安全输出与关联语义定义成需求问题。 | 若需求层不先说明该问题,后续实现会用 raw label、full ref、opaque id 或临时映射补齐关联,造成泄露、不可审计或难以对账。 |
| 留存标记与报告交接边界缺少正式问题定义 | 旧 README 只列冷存策略、hash chain 分片和 dashboard,没有说明材料被诊断、审计、报告或验收引用时的冲突表现。 | 后续可能把归档恢复、报告证据、验收签署和观测材料生命周期混写,造成误删、误保留、活动引用失效或静态造证据。 |

### 6.4 问题分类结论

| 类型 | 内容 |
|---|---|
| 业务问题 | 平台缺少统一的横切观测问题基线,难以稳定回答关键活动发生了什么、如何与治理 / 制品 / 身份 / 运行上下文关联、输出是否已脱敏、材料是否仍可审计以及能否安全交给报告或验收使用。 |
| 技术问题 | 旧材料把产品栈、存储、dashboard、性能候选、schema 语境和 truth 边界混在需求层,会导致后续架构、概要、详细、测试和验收反复补写 redaction、correlation、evidence linkage、retention marker、report handoff 与 no-write truth 口径。 |

## 3. 开工确认 / 必读文档:先思考

### 3.1 本步目标诊断

Step 09 的任务是把 Step 08 已按 `C-OBS-1~5` 收束的用户故事,归并为系统必须提供的业务能力。对 `L4-observability` 来说,这里的“功能需求”不是对象操作、查询名、topic、event、DTO 或 dashboard 能力列表,而是能稳定支撑观测材料入口、审计投影、运行观察面、只读诊断 / 交接和留存 / no-write 边界成立的能力主题。

这一章最容易犯五类错。第一类是把 `CreateObservation`、`SearchTrace`、`GetAuditProjection` 一类 CRUD / API / Command 名直接写成功能项。第二类是把 Step 08 的故事逐条改写成功能,导致没有真正做故事归并。第三类是把 `ObservationEnvelope`、`MetricPoint`、`AuditHashLink`、`ReportHandoffRecord`、`RetentionMarker` 这类对象词当成功能主题。第四类是把 OTel、Prometheus、Grafana、TimescaleDB、alert sink、冷存或外部 APM 绑定写进核心功能。第五类是把业务 truth 写回、正文保存、最终 verdict、真实 evidence 或 archive package ownership 混入本仓功能表。

## 5. 功能收敛:先思考

### 5.1 收敛目标

本模块只诊断“哪些功能应该正式进入 Step 09,哪些不应该”,不直接写最终功能表。对 `L4-observability` 来说,合格的功能必须同时满足四个条件。第一,它必须直接支撑某个核心能力节点成立。第二,它必须能回指一个或多个已收敛用户故事。第三,它必须保持 body-free、只读 handoff 和 no-write truth 边界不串层。第四,它不能抢 Step 10 规则、Step 11 数据、Step 12 接口、Step 13 非功能或 Step 14 验收的内容。

### 5.2 功能候选分层

| 类别 | 判断标准 | 当前处理方式 |
|---|---|---|
| 核心闭环功能 | 直接决定 `C-OBS-1~5` 是否成立,且可写成外部可见业务能力主题。 | 保留进正式功能表。 |
| 外围增强功能 | 有明确业务价值,但不决定核心闭环是否成立。 | 保留进外围增强功能表。 |
| 当前应裁剪的候选 | 实际是对象操作、接口动作、产品绑定、正文 ownership、相邻仓 truth、真实证据或验收结论。 | 不进入正式功能表,只进入排除结论。 |

### 5.3 核心闭环功能方向诊断

| 能力节点 | 需要保留的能力主题方向 | 原因 |
|---|---|---|
| `C-OBS-1` 安全观测材料入口 | 安全观测材料准入、来源与关联语境表达、观测材料安全处置 | 没有这三类能力,观测材料无法被统一识别、解释、脱敏或隔离。 |
| `C-OBS-2` 审计投影与证据关联 | 审计投影表达、body-free 证据关联 | 没有这些能力,审计材料会退化为 source truth 副本或不可解释引用。 |
| `C-OBS-3` 运行观察面安全表达 | 运行观察面安全表达、观察输出降级表达 | 没有这些能力,log / metric / trace 会退化为 raw 输出或被误用为执行 truth。 |
| `C-OBS-4` 只读诊断与报告交接 | 只读观测查询、只读诊断视图、报告与证据交接、证据真实性提示 | 没有这些能力,查询和交接会退化为控制面、裁决面或伪证入口。 |
| `C-OBS-5` 留存与不反写真相边界 | 留存约束与活动引用保护、观察面重放 / 重建与 no-write 防护 | 没有这些能力,观察材料会被越权清理、错误重放或反写 source truth。 |

### 5.4 外围增强与裁剪候选

| 候选 | 当前处理 | 理由 |
|---|---|---|
| 高级 dashboard、可视化编排、管理视图 | 归入外围增强 | 有价值,但不决定核心观察面成立。 |
| 告警规则、通知渠道、订阅体验 | 归入外围增强 | 提升响应效率,但 alert 不等于业务 truth。 |
| 管理指标报表、趋势分析、经营视图 | 归入外围增强 | 属于扩展消费能力,不应挤占核心闭环。 |
| 外部 APM / Collector / 存储 / 展示产品绑定 | 归入外围增强或后续候选 | 属于产品和架构选择,不是需求主链功能。 |
| 外部审计 / GRC 导出 | 归入外围增强 | 是外部协作增强,不改变本仓 truth 边界。 |
| 异常检测、根因建议 | 归入外围增强 | 能提升诊断效率,但不能替代只读观察面本身。 |
| `trace/correlation 查询`、`hash linkage`、`evidence index`、`redaction status`、`legal hold` | 改写吸收到核心功能主题 | 这些更适合作为功能内部语义或后续规则 / 数据项,不应直接作为 Step 09 功能名。 |
| real `run_id`、real evidence alias、final verdict、signoff | 裁剪 | 属于真实执行与验收阶段,不能进入需求层功能表。 |
| `L0-bus`、`L1-*`、runtime、archive、console、外部监控产品 | 裁剪 | 它们是协作边界或消费边界,不是本仓功能主题。 |

### 5.5 功能写法与双映射判断

| 项 | 当前口径 |
|---|---|
| 功能命名 | 保持“能力主题”写法,例如“安全观测材料准入”“只读诊断视图”,不写 `Create...`、`Get...`、`Search...`。 |

| 一功能多故事 | 允许。一个功能可以同时承接多个角色目标。 |
| 一功能多节点 | 允许,但只在确实跨节点时使用,例如“观察输出降级表达”同时影响 `C-OBS-3` 与 `C-OBS-4`。 |
| 旧功能改写 | 保留旧 `FR-OBS-*` 的能力方向,去掉对象词、输入输出细节和边界反例。 |
| 排除功能写法 | 只写“看似功能 / 排除原因 / 正确归属”,不写详细替代设计。 |

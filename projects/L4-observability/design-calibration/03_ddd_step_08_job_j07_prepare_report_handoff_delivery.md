## 1. Protocol identity and phase boundary

J07 prepares and, where separately authorized, advances the local report-handoff delivery phases. It
does not create a final report, verdict, signoff, evidence alias, external acceptance or real run identity.
Preparation, delivery attempt, delivery result and consumer feedback are distinct phases and owners.

| item | exact contract |
|---|---|
| public protocol | `ObservationJobRequest<PrepareReportHandoffDeliveryJobInput>` |
| internal operation | `ObservationJobOperation::PrepareReportHandoffDelivery` |
| entry callable | `ObservationOperationsJobService::prepare_report_handoff_delivery(PrepareReportHandoffDeliveryInput)` |
| work-key variant | `ObservationJobWorkKey::ReportHandoff(ReportHandoffRecordRef)` |
| planned material | handoff scope/record, immutable `EvidenceIndexInputView`, consumer relation, historical binding and phase capabilities |
| Step 09 flow | `PrepareReportHandoffDeliveryFlow` |

## 2. Input/output schema

```rust
pub struct PrepareReportHandoffDeliveryJobInput {
    pub handoff_scope_ref: ReportHandoffScopeRef,
    pub handoff_ref: ReportHandoffRecordRef,
    pub consumer_ref: ReportConsumerRef,
}

pub struct PrepareReportHandoffDeliveryJobOutput {
    pub handoff_record_refs: HandoffLifecycleRecordRefSet,

    pub delivery_refs: PeripheralDeliveryRefSet,

```

The input identifies one exact handoff within a typed scope and consumer relation. It cannot contain a
final visibility, verdict, provider response, endpoint, credential, report body or caller-created delivery
token. The immutable evidence-index input, readiness decision, gap revisions and historical effect binding
are loaded and frozen into plan material; they are not rebuilt during item execution.

## 3. Plan, claim and preparation/delivery separation

The `ReportHandoff` item captures the exact handoff record, scope relation, consumer, immutable evidence
input, readiness/visibility/gap basis, source cursor/version and any typed preparation/delivery capability.
The global work key prevents concurrent executions from preparing the same handoff twice.

```text
reserve -> load exact handoff/evidence/consumer relation
  -> evaluate P6/P7/P14 readiness and visibility
  -> freeze immutable plan item and Draft report
  -> claim handoff
  -> prepare local handoff material
  -> only then perform an authorized delivery phase
```

Preparation success is not delivery success. A local `Delivered` result is not external acceptance. A
consumer feedback event is handled by I08/I09 and is not generated by J07 as a shortcut.

## 4. Item flow and external effect accounting

```text
claim ReportHandoff
  -> validate current handoff state, evidence input, gaps, retention/protection and binding
  -> apply P6/P7/P14 preparation decision and persist local preparation marker
  -> if delivery phase is enabled, call the exact historical binding with stable token
  -> probe same token on unknown outcome
  -> record local delivery result/failure under claim/fence
  -> append H4/H9/E06/E12 followers only from accepted post-state
  -> classify item and fold report
```

The external call receives only the body-free prepared material and historical binding. It never receives
raw evidence, report body, provider-specific free text or current config. Stable token, attempt ordinal and
phase accounting remain application-private and are not public output.

## 5. Result, replay and error matrix

| condition | behavior | forbidden shortcut |
|---|---|---|
| missing handoff/evidence/consumer relation | reject/blocked before external effect | search latest or rebuild evidence input |
| policy not ready / gap blocked | local blocked/preparation state | call delivery anyway |
| preparation accepted | local preparation ref/state | claim external acceptance |
| delivery positive | local delivery state/result | claim consumer accepted report |
| delivery retryable | retryable item with same binding/token phase rules | change payload/binding or blind resend |
| delivery unknown | blocked/manual/probe state | default failure or resend |
| duplicate terminal request | exact stored report replay | prepare/deliver again |
| result/report save unknown | no reservation completion | fabricate handoff completion |

J07 report output is a lossless fold of handoff item outcomes. It distinguishes preparation refs,
delivery refs, failures and gaps. Duplicate replay uses the original stored `JobReport` surface and does
not expose or regenerate external phase identity.

## 6. Redaction and no-backwrite

Telemetry permits phase, finite handoff/readiness/delivery/recovery tokens, presence and bounded counts.
It excludes evidence body, report body, provider response, endpoint, credential, token, digest bytes,
consumer identity labels, actor and raw trace. J07 does not write source/business truth, archive truth,
evidence verdict, retention cleanup or signoff.

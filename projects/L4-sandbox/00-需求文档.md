## 1. 与 `product/` 的关系声明

L4-sandbox 是**架构反推型**需求仓。它不是对终端用户的产品功能,但它承载了平台对外部能力和 AI 产出代码执行的安全底线。

| 章节 | 本文来源 | 对应文档 |
|---|---|---|
| 背景与问题 | sandbox 仓 README + 标准对齐 | 标准对齐全景图 sandbox 条目 |
| 目标 | Docker + gVisor + no-egress + audit | sandbox README |
| 非功能需求 | 启动时延 / 安全基线 | README |

## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 的 AI 成员需要运行:
- 代码生成后的测试 / 构建 / lsp / git / shell
- 外部工具 / MCP client
- Runner 里执行 AI 产出的应用

这些行为如果直接在宿主机上执行,安全边界无法接受。sandbox 需要提供:
- 隔离执行
- CPU / 内存 / 磁盘 / 时间限制
- 默认无出网
- 白名单出网需 Policy
- 全量审计事件

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 2 末) | 痛点 |
|---|---|---|
| 仓设计 | 只有 README 骨架 | 仓级需求未显式化 |
| backend | Docker + gVisor 目标 | 具体接口与运行边界未落地 |
| Runner 复用 | 原则已定 | 共享接口尚未成文 |
| 无出网 | 安全基线已写 | 白名单粒度未定 |

### 2.3 为什么要做(量化依据)

- 没有 sandbox,runtime/runner 直接在宿主机执行代码 → 不符合平台安全底线
- README 已给出目标:沙箱启动 < 1s(Docker) / < 2s(gVisor),说明这是平台级硬能力
- capability-hub 的 allow/deny 决策必须有落地承载点

### 2.4 业务问题 vs 技术问题

- **业务问题**:AI 成员如何安全执行代码与工具
- **技术问题**:隔离后端、资源限制、无出网默认、白名单策略、审计事件、Runner 复用

## 5. 核心用例与用户故事

### 5.1 核心用例

1. runtime 在沙箱中执行危险工具
2. runner 在沙箱中启动 AI 产出的 app
3. 白名单出网能力在 policy 授权后生效
4. 超时 / 内存超限 / 磁盘超限时强制中止
5. escape 检测告警

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **runtime**,我想要 **用统一 SandboxService 在受限环境里执行代码**,以便 **不污染宿主机并限制风险** |
| 优先级 | P0 |
| 验收条件 | **Given** Docker backend **When** 调用 ExecuteSandboxed **Then** 正常返回 stdout/stderr/exit_code |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **Security**,我想要 **默认阻断一切出网**,以便 **防止越权访问外部网络** |
| 优先级 | P0 |
| 验收条件 | **Given** 未授权出网 **When** 程序尝试访问外部地址 **Then** 连接失败且有审计事件 |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **Runner**,我想要 **复用与 Member Runtime 相同的沙箱接口**,以便 **不造第二套隔离系统** |
| 优先级 | P0 |
| 验收条件 | **Given** runner 请求执行应用 **When** 调 sandbox API **Then** 行为与 runtime 调用保持一致 |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **SRE**,我想要 **在资源超限时拿到明确的退出原因与审计事件**,以便 **排查问题和报警** |
| 优先级 | P1 |
| 验收条件 | **Given** 沙箱进程超 RAM/CPU/time limit **When** 被 kill **Then** 返回 limit_exceeded + 发审计事件 |

### 5.3 辅助流程

- Docker backend → gVisor backend 的切换
- local_process backend 只在测试环境启用
- Firecracker 作为未来候选,当前不实现

## 6. 功能需求

### 6.1 功能清单与优先级

| ID | 功能名称 | 优先级 | 依赖 | 描述 |
|---|---|---|---|---|
| F-001 | SandboxService trait | P0 | core | 统一执行接口 |
| F-002 | Docker backend | P0 | Docker / containerd | 默认后端 |
| F-003 | gVisor backend | P0 | gVisor | 强隔离后端 |
| F-004 | local_process backend | P1 | 测试 | 仅测试用 |
| F-005 | 资源限制 | P0 | backend | CPU / RAM / disk / timeout |
| F-006 | 默认无出网 | P0 | firewall / policy | deny-by-default |
| F-007 | 白名单出网 | P1 | capability-hub / policy | allowlist 生效 |
| F-008 | 审计事件 | P0 | observability | invoked / exited / escape_detected |
| F-009 | Runner 复用 | P0 | runner | 与 runtime 同接口 |
| F-010 | escape detection hooks | P1 | security | 发现异常逃逸迹象时告警 |

### 6.2 业务规则表

| 规则 ID | 条件 | 结果 |
|---|---|---|
| BR-001 | 未授权出网 | 拒绝 |
| BR-002 | backend 不支持某资源限制 | 拒绝启动,而不是 silent ignore |
| BR-003 | 超时 | 强制 kill + 审计事件 |
| BR-004 | runner 请求执行 | 必须走同一 SandboxService,不造第二套 |
| BR-005 | local_process backend | 只能测试环境启用 |

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 类型 | 生命周期 |
|---|---|---|
| SandboxExecution | 记录 | created → running → exited / killed |
| SandboxPolicyView | 查询视图 | 即时 |
| SandboxAuditEvent | 审计记录 | append-only |

### 9.2 数据关系

```
SandboxExecution
  ├─ backend
  ├─ resource limits
  ├─ network policy
  ├─ stdout/stderr refs
  └─ audit events
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| execution metadata | 热存 | observability / archive |
| stdout/stderr refs | 短期 | 冷存可选 |
| audit events | 长期 | append-only |

## 11. 验收标准

### 11.1 功能验收标准

| 功能 ID | 验收场景 | Given-When-Then | 执行方式 |
|---|---|---|---|
| F-001 | 统一执行接口 | **Given** Docker/gVisor backend **When** 调 ExecuteSandboxed **Then** 返回统一结果结构 |
| F-006 | 默认无出网 | **Given** 未授权网络访问 **When** 发请求 **Then** 被拒绝 |

## 12. 风险与待确认事项

### 12.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Docker 隔离不够 | 中 | 高 | gVisor 作为强隔离选项 |
| allowlist 刷新不及时 | 中 | 高 | deny by default |
| Runner 与 runtime 行为分叉 | 中 | 中 | 共享 trait + 测试 |

### 12.2 边缘风险

- 多层 sandbox 嵌套
- rootless 环境限制
- Firecracker 后续引入复杂度

### 12.3 待确认问题

| 问题 | 截止 | 负责人 |
|---|---|---|
| Firecracker 是否纳入 | L4 后 | sandbox + SRE |
| allowlist 粒度(domain / IP / port) | L4 前 | sandbox + capability-hub |
| local_process backend 范围 | L4 前 | sandbox |

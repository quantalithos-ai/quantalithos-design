## 3. 约束条件

> 校准来源:
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_03_constraints.md` 的“约束条件表”和“约束边界说明”小节。

后续章节必须持续受以下结构性约束保护:

| 约束 | 当前要求 |
|---|---|
| execution isolation truth 独立拥有 | sandbox 只拥有受控执行隔离事实,不重建 tools、runtime、member、artifact、observability 或 policy source truth |
| 不承认宿主直跑或旁路执行为正式成功 | host-run、匿名执行、弱测试路径和 bypass path 不能升格为 formal sandbox path |
| 外部正文禁止入仓 | identity / work / tool / runtime / policy / investigation 等外部正文只能以 ref、safe summary、snapshot 或 marker 进入 |
| coherent boundary 必须整体成立 | resource / filesystem / network / process / workspace / mount 任一必需边界不可 silent degrade |
| backend capability 只是判断输入 | 后端能力摘要只服务 boundary 可落实性判断,不能反向定义业务边界 |
| policy 来源与 policy 执行分离 | sandbox 只消费给定 policy / authorization / capability 摘要并 fail-closed,不拥有 allowlist、approval、DSL 或 capability truth |
| capture / candidate / observability / handoff 分层 | `CaptureFact`、候选材料、观测材料和 `HandoffFact` 必须显式分层,下游 formal truth 外部拥有 |
| 非 happy path 是一等主线 | timeout、deny、kill、capture failure、lease expiry、orphan、cleanup guard 和 redline containment 不能降级为运维补丁 |
| cleanup / reaper 先守证据再回收 | cleanup 不得先删材料,reaper 不得绕过 cleanup guard 与 investigation handoff |
| truth / snapshot / ref / derived / forbidden body 分层 | query、projection、trend、comparison、reconciliation 只能消费已提交 truth,不反写主线 |
| sync / async / background 路径分离 | Command 负责正式 truth 判断;Consumer 负责 ref / summary / feedback;Job 负责 refresh / retry / rebuild / reconcile / reap |
| Query 只读 | Query 不触发 refresh、repair、handoff、cleanup、release 或 policy 放行 |
| 依赖裁剪固定 | `L0-core` 是唯一编译期依赖;其他仓和 backend 只通过运行期接缝、summary、snapshot、event 或 handoff 协作 |
| 配置不得改写核心语义 | 配置只影响承载、节奏、接缝 enablement 和 degraded surface,不能改写 truth owner、fail-closed、cleanup guard 或 redline semantics |

这些约束直接决定后续判断:对象应归 truth 还是 derived,接口应归 Command 还是 Consumer / Job,状态能否进入正式主线,以及哪些异常只能以 pending / blocked / failed / degraded surface 暴露。

## 5. 主要组成部分、职责与边界

> 校准来源:
> - `design-calibration/02_hld_step_05_components_boundary.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_05_components_boundary.md` 的“组成部分总表”“对象发现维度表”和“各部分交互总图”小节。

`L4-sandbox` 的业务主语固定为以下 6 个主要组成部分:

| 组成部分 | 核心职责 | 不承担什么 |
|---|---|---|
| `Controlled execution intake and identity` | 形成正式受控执行入口、受理 / 拒绝归责、调用方 refs 闭口、execution environment identity 和责任链绑定 | 不拥有 ToolInvocation、ExecutionInstance、SandboxBinding、RunnerRun、identity / work 正文或第二套入口语义 |
| `Boundary establishment and enforcement` | 建立正式隔离环境,把 resource / filesystem / network / process / workspace / mount 限制作为 coherent boundary 整体裁定和施加 | 不拥有 Docker / gVisor / Firecracker / k8s / local_process 产品 truth、host / cluster lifecycle 或 backend 配置 |
| `Policy execution decision` | 消费给定 launch / isolation policy、authorization、approval 或 capability 摘要,形成 accepted / rejected / blocked / pending / fail-closed 裁定 | 不生成 allowlist truth、approval truth、policy definition truth、capability truth、policy DSL 或 tools semantic policy |
| `Execution capture and material handoff` | 在已成立语境、边界和 policy 下承接受控执行,捕获 output / candidate material / observability material,并显式形成 handoff fact | 不拥有 tools semantic execution、runtime agent loop、Artifact / baseline / evidence truth、runtime result、runner UI state 或 observability store |
| `Failure control and safety closure` | 把 timeout、deny、kill、cancel、backend failure、capture failure、lease expiry、orphan、cleanup guard、reaper 和 redline containment 作为正式收束链 | 不推进 runtime recover、不执行业务 replay、不拥有 artifact retention、investigation lifecycle、operator UI 或运维脚本 truth |
| `Local reference, projection and derived support` | 维护 refs、safe summary、snapshot、read projection、inspect / preview / trend、backend comparison 和 reconciliation 等只读 / 可重建支持面 | 不新建或覆盖 execution isolation truth,不把 query / inspect / derived / trend 变成写路径或核心通过前提 |

```text
+--------------------------------------------------------------------+
| Controlled execution intake and identity                           |
+---------------------------+----------------------------------------+
                            |
                            v
+---------------------------+----------------------------------------+
| Boundary establishment and enforcement                             |
+---------------------------+----------------------------------------+
                            |
                            v
+---------------------------+----------------------------------------+
| Policy execution decision                                         |
+---------------------------+----------------------------------------+
                            |
                            v
+---------------------------+----------------------------------------+
| Execution capture and material handoff                            |
+---------------------+-------------------------------+--------------+
                      |                               |
                      v                               v
+---------------------+---------------+   +-----------+------------+
| Failure control and safety closure  |   | Local reference,       |
| cleanup / reaper / redline / guard  |   | projection and derived |
+-------------------------------------+   | support                |
                                          +------------------------+
```

这些组成部分是概要设计层的正式业务结构主语。`03-详细设计.md` 可以继续把它们落成模块和 service,但不能改写职责归属或把外部 truth 拉进 sandbox 本地。

## 7. API / 接口骨架

> 校准来源:
> - `design-calibration/02_hld_step_07_api_interface_skeleton.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_07_api_interface_skeleton.md` 的“接口分类说明”“按主要组成部分组织的接口骨架表”“Command / Query / Consumer / Job / Port 骨架表”小节。

本仓接口按读写性质分为 6 类:

| 接口类别 | 读写性质 | 主要用途 | 必须携带的上下文 | 不得做什么 |
|---|---|---|---|---|
| Command API | 改写 sandbox truth / decision / fact / guard state | 正式受理、边界建立、policy 裁定、运行承接、capture、handoff、failure、control、cleanup、redline | `ActorContext` 或 `SystemActorContext`;`CommandMetadata`;`IdempotencyKey`;trace context | 不宣布下游 truth,不写外部正文,不把 SDK raw response 当 domain truth |
| Query API | 只读 | 读取 status view、summary view、projection、derived view、audit trace 和 reconciliation report | `ActorContext`;`QueryMetadata`;scope / pagination / consistency hint | 不写 truth,不 refresh,不 repair,不 handoff,不 cleanup |
| Inbound Event Consumer | 写 ref / summary / marker / feedback / stale state | 承接外部 safe summary、backend capability、handoff ack、control signal、调查反馈 | event envelope;source event id;source ref;schema version;dedup key;trace context | 不直接创建核心 success,不保存外部正文 |
| Outbound Event | 输出已成立 fact 或维护状态 | 向 tools、runtime、member-service、artifact、observability、runner、安全调查和读侧消费面传播变化 | truth ref;change kind;trace context | 不让下游失败回滚 source truth |
| Operations Job | 后台维护 / 发布 / 重试 / 重建 / 对账 / 保守回收 | relay、refresh、retry、cleanup、reaper、derived、reconciliation | `JobMetadata`;system / operator actor;job idempotency key;trace context | 不作为业务 command,不修核心 truth |
| External / Infrastructure Port | 外部能力 / 基础设施接缝 | refs 解析、policy summary、backend capability、isolation backend、material / observability / event / investigation handoff、truth / projection persistence | typed refs;request context;trace context | 不形成编译期 sibling 依赖,不引入外部 truth ownership |

关键接口骨架如下:

- Command:
  `OpenControlledExecutionContext`、`EstablishExecutionBoundary`、`EvaluatePolicyExecution`、`StartControlledExecutionRun`、`RecordCaptureResult`、`OpenMaterialHandoff`、`SubmitSandboxControl`、`ClassifySandboxFailure`、`EvaluateCleanupReadiness`、`RecordRedlineContainment`
- Query:

## 8. 关键处理流 / 重要函数数据流

> 校准来源:
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_08_processing_flows.md` 的“通用处理流骨架”“按主要组成部分组织的关键处理流清单”“状态主题反查清单”小节。

本章按 flow family 组织处理流,避免逐接口机械重复。通用路径如下:

```text
Command request
  -> Sync Entry validates actor / metadata / idempotency
  -> Application Service loads refs / summaries / current truth
  -> Domain object + guard applies accept / establish / decide / capture / contain
  -> Truth persistence saves committed fact + audit trace + relay marker
  -> Result surface returns without declaring downstream truth

Query request
  -> Read service resolves subject
  -> Visibility / freshness guard applies no-write rule
  -> Projection / status / trace view returns stale / degraded / unavailable surface

Inbound event
  -> Async consumer validates envelope / version / dedupe
  -> Reference / marker handler updates local summary / feedback / stale state
  -> Persistence stores marker or receipt, never core success

Operations job
  -> Job loads committed truth / relay / handoff / lease / projection
  -> Maintenance guard or port performs publish / refresh / retry / rebuild / reap
  -> Report + marker update stored without repairing core truth
```

关键 flow family 如下:

| 处理流族 | 覆盖接口 | 核心边界 |
|---|---|---|
| intake 受理 / 拒绝 / refs 解析 | `OpenControlledExecutionContext`;`ConsumeCallerContextReferenceChanged`;`RefreshSandboxReferenceStates` | 只形成 accepted / rejected / pending / unresolved 语境,不补写外部正文 |
| boundary requirement / capability / establish | `EstablishExecutionBoundary`;`ConsumeBackendCapabilitySummaryChanged`;`RefreshBackendCapabilitySummaries` | accepted context、active identity、显式四维requirements、同代profile / template与capability形成boundary;不得读取后序policy或permissive fallback |
| policy snapshot / fail-closed / high-risk decision | `EvaluatePolicyExecution`;`ConsumePolicySummaryChanged` | policy 缺失、冲突、不支持或高风险未授权只能 rejected / blocked / pending / fail-closed |
| run start / capture / material + observability handoff | `StartControlledExecutionRun`;`RecordCaptureResult`;`OpenMaterialHandoff`;handoff consumers | capture 与 handoff 分层;handoff failure 不回滚 capture truth |
| failure / control / lease / orphan / cleanup / reaper / redline | `SubmitSandboxControl`;`ClassifySandboxFailure`;`EvaluateCleanupReadiness`;`RecordRedlineContainment`;相关 jobs 和 consumers | cleanup 先看 evidence / investigation,redline 不能 advisory-only,reaper 不绕 guard |
| projection / derived / relay feedback / reconciliation | read queries、`PublishSandboxEventRelay`、`MaintainDerivedInspectPreviewTrend`、`RunSandboxReconciliation`、relay feedback consumer | 只读或维护可重建面,不反写核心 truth |

关键处理流约束:

- `OpenControlledExecutionContext` 只建立正式受控执行语境和 execution identity,不补写 identity / work / runtime 正文。
- `EstablishExecutionBoundary` 只消费 accepted context、matching identity、显式 resource / filesystem / network / process requirements、builder 注入的 boundary profile / limit template、同代 runtime generation 和 backend capability;不得要求后序 policy snapshot / decision。
- `EvaluatePolicyExecution` 只消费给定 policy / authorization 摘要,不拥有 policy source truth。
- `StartControlledExecutionRun` 必须同时验证 coherent boundary、active handle 和 Accepted policy;Boundary 的成立不等于允许 launch。
- `RecordCaptureResult` 与 `OpenMaterialHandoff` 必须分离,避免 capture 直接升级为下游 truth。
- `SubmitSandboxControl`、`ClassifySandboxFailure`、cleanup 和 redline flow 不推进 runtime recover 或业务 replay。
- Query / derived / comparison / reconciliation 只能读或维护可重建 projection,不得反写核心 truth。

## 9. 状态定义与状态流转

> 校准来源:
> - `design-calibration/02_hld_step_09_state_machine.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_09_state_machine.md` 的“状态定义表”“状态流转 ASCII 图”“传播关系”和“禁止迁移清单”小节。

`L4-sandbox` 采用并行状态机,而不是单一全局执行状态。当前概要层收稳 6 组正式状态主题:

| 状态组 | 主要对象 | 代表状态 | 关键传播 |
|---|---|---|---|
| Intake / Identity / Intake Reference | `ControlledExecutionContext`;`ExecutionEnvironmentIdentity`;`ExecutionContextResolution`;`ContextReferenceResolution` | `PendingResolution`、`Accepted`、`Rejected`、`Unresolved`、`Active`、`Invalidated`、`Complete`、`Stale`、`Unavailable` | `Accepted` 才允许进入 boundary / policy 主线;ref invalidation 会阻断后续执行 |
| Boundary / Capability / Environment Lifecycle | `CoherentBoundary`;`BoundaryEstablishmentDecision`;`BackendCapabilitySummary`;`IsolationEnvironmentHandle` | `Required`、`Established`、`Rejected`、`PendingCapability`、`Failed`、`Fresh`、`Unsupported`、`Active`、`ReleasePending`、`OrphanSuspected` | boundary 未 established 时 run 不得启动;handle / lease 异常会传播到 failure / cleanup |
| Policy / High-Risk Launch Decision | `PolicyApplicabilitySnapshot`;`PolicyExecutionDecision`;`HighRiskActionDecision` | `Applicable`、`Missing`、`Conflicted`、`Accepted`、`Rejected`、`Blocked`、`Pending`、`FailClosed`、`Allowed`、`Unsupported` | policy 非 accepted 或高风险非 allowed 时 launch 必须阻断 |
| Run / Capture / Material Handoff | `ControlledExecutionRun`;`CaptureFact`;`CapturedMaterialRef`;`ObservabilityMaterial`;`HandoffFact` | `Preparing`、`Running`、`Completed`、`Failed`、`Terminated`;`Complete`、`Partial`、`Unavailable`;`Pending`、`Delivered`、`Failed`、`Retryable` | capture 与 handoff 分层;handoff 只影响 cleanup guard / relay,不回滚 source truth |
| Failure / Control / Cleanup / Redline | `FailureClassification`;`ControlFact`;`LeaseRecord`;`OrphanRecoveryRecord`;`CleanupGuard`;`RedlineContainment` | `PendingInput`、`Classified`、`Terminal`;`Accepted`、`Conflicted`、`Completed`;`Expiring`、`Expired`;`Blocked`、`Allowed`;`Detected`、`Contained`、`HandoffPending` | failure / cleanup / containment 共同决定终态收束,不得被 query / job silent override |
| Reference / Projection / Relay / Read Surface | `ReferenceResolutionState`;`SandboxReadProjection`;`DerivedInspectPreviewTrendState`;`SandboxEventRelayRecord`;`SandboxReconciliationReport` | `Fresh`、`Stale`、`Unavailable`;`Fresh`、`Rebuilding`、`Degraded`;`Pending`、`Delivered`、`Failed`;`IssuesFound` | 这些状态只镜像或解释 truth,不成为核心 truth 写源 |

```text
Accepted context
   -> Established boundary
      -> Accepted policy
         -> Preparing / Running run
            -> Capture complete / partial / failed
               -> Handoff pending / delivered / failed
                  -> Cleanup allowed / blocked

Any point:
  control / backend loss / lease expiry / orphan / redline
    -> failure classification / containment / guarded cleanup

Read side:
  truth change -> projection / derived / relay / reconciliation state
  read side never promotes success back into core truth
```

关键判断:

- `SandboxExecutionStatusView`、`BoundaryStatusView`、`CaptureSummaryView`、`FailureControlStatusView` 等只读 view 不是第二套 truth 状态机。
- Consumer 只能刷新摘要、feedback、stale marker 或 lifecycle marker,不得直接创建核心 success。
- Job 只能基于已持久化 truth 推动传播、重建、对账或回收,不得修复核心 success。

## 10. 异常与边界场景轮廓

> 校准来源:
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_10_exceptions_boundaries.md` 的“异常与边界场景表”“异常影响图”“状态机影响清单”和“按处理流族归类的异常口径”小节。

本章只保留那些会改写 sandbox 主线理解、状态推进或跨部分协作关系的关键异常路径。

| 场景 | 应落在哪个部分处理 | 当前概要口径 |
|---|---|---|
| actor / responsibility / trace / idempotency 缺失 | `Controlled execution intake and identity` | 不进入 `ControlledExecutionContext::Accepted`,只返回 rejected / pending surface |
| caller / identity / work refs unresolved、conflicted 或 forbidden body 越界 | `Controlled execution intake and identity` + `Local reference, projection and derived support` | 只能停在 pending / unresolved / rejected,正文拒绝入仓 |
| backend capability stale / unknown / unsupported | `Boundary establishment and enforcement` | 必须 pending / unsupported / rejected / failed,不得 permissive fallback |
| 任一 resource / filesystem / network / process 限制不可落实 | `Boundary establishment and enforcement` | `CoherentBoundary` 不得 established;这是 silent degrade 红线 |
| policy summary missing / conflicted / stale / unsupported | `Policy execution decision` | 只能 pending / rejected / fail-closed,不得继续 launch |
| 高风险动作未授权或当前边界 / 后端不支持 | `Policy execution decision` | 进入 `Blocked` 或 `Unsupported`,不得靠普通 accepted policy 绕过 |
| boundary / handle / policy 未闭口时试图启动 run | `Execution capture and material handoff` | 不得创建 `Running`,只能失败、拒绝或保持 preparing / blocked |
| capture partial / failed / unavailable | `Execution capture and material handoff` | 必须显式落在 `Partial` / `Failed` / `Unavailable`,不能被 handoff 或 query 成功掩盖 |
| handoff pending / failed / retryable / 无 receipt | `Execution capture and material handoff` | 进入 `Pending` / `Failed` / `Retryable`,但不回滚 capture truth |
| cleanup 在 capture / handoff / investigation 未放行前被请求 | `Failure control and safety closure` | 只能 `PendingEvidence`、`PendingInvestigation` 或 `Blocked`,不得先删材料 |
| lease expiry / orphan suspected / backend lifecycle 丢失 | `Failure control and safety closure` | 必须进入 failure / orphan / reaper 路径,不得继续假装环境可用 |
| redline 在 run / capture / cleanup 期间被检测到 | `Failure control and safety closure` | 至少 `Detected -> Contained`,并阻断 cleanup / release 直到调查交接 |
| read projection stale / degraded / unavailable,或 relay publish failed / retryable | `Local reference, projection and derived support` | 只能显式返回 degraded / unavailable / issues-found surface,不得借 query 或 job 修核心 truth |

这些异常只推动 rejected / pending / failed / blocked / degraded / terminal 等状态,不得由 Query、Consumer、Job 或外围 UI silently repair。

## 11. 配置影响轮廓

> 校准来源:
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_11_configuration_impact.md` 的“配置影响分层原则”“配置影响轮廓表”“禁止配置化边界表”和“交给详细设计的配置实现契约方向”小节。

配置在概要层只影响承载、节奏、接缝 enablement 和 degraded surface,不能改写 sandbox 正式语义。

| 主要部分 / 接缝 | 是否受配置影响 | 允许受影响的内容 | 不允许被改写的内容 |
|---|---|---|---|
| `Controlled execution intake and identity` | 是 | intake profile、request body limit、sync timeout、idempotency backend profile、resolver source set | `Accepted` / `Rejected` / `Unresolved` 语义和第二入口禁止线 |
| `Boundary establishment and enforcement` | 是 | backend profile ref、boundary profile ref、limit template ref、capability stale threshold、lease profile | coherent boundary 整体成立条件、host-run / weak fallback 禁止线 |
| `Policy execution decision` | 是 | policy summary source routing、freshness threshold、high-risk summary profile | policy source ownership、fail-closed、未授权高风险阻断语义 |
| `Execution capture and material handoff` | 是 | capture size class、export class、handoff target enablement、receipt profile、retry class | capture truth / handoff truth 分层,receipt 不得升格为下游 formal truth |
| `Failure control and safety closure` | 是 | control timeout、orphan scan cadence、cleanup evaluation cadence、reaper concurrency、redline escalation target ref | cleanup guard、reaper、redline containment 的保守收束语义 |
| `Local reference, projection and derived support` | 是 | projection stale threshold、rebuild cadence、page limit、comparison scope、degraded exposure policy | Query no-write、derived no-repair、read-side 不反写核心 truth |

禁止配置化边界如下:

| 禁止配置化边界 | 原因 |
|---|---|
| execution isolation truth ownership | 这是 `L4-sandbox` 的存在理由,不能由 profile、flag 或 adapter wiring 改变 |
| `ControlledExecutionContext::Accepted` 最小闭口前提 | 不能通过配置跳过 actor / refs / responsibility / idempotency 门禁 |
| coherent boundary 必须整体成立 | 不能让任一必需边界因配置 silent degrade |
| fail-closed 与高风险阻断 | 不能以“临时放行”或 feature flag 弱化 missing / conflicted / unsupported / unauthorized 语义 |
| capture truth 与 handoff truth 分层 | 不能让 candidate material、observability material、receipt 或 downstream ack 静默升级为 formal truth |
| cleanup guard 先于删除动作 | retention / force cleanup / reaper schedule 不能绕过证据与调查门禁 |
| Query / Consumer / Job 的 no-write 红线 | 不能把 read / consumer / maintenance 变成隐藏写源 |
| `L0-core` 之外不得变成编译期依赖 | 不能用配置包装 sibling repo 或 backend SDK 进入 core 编译期主线 |

配置快照、validator、builder 注入关系和错误面属于 `03` 与未来 `04` 的继续展开内容。

## 13. 设计风险与待确认事项

> 校准来源:
> - `design-calibration/02_hld_step_13_risks_open_questions.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/02_hld_step_13_risks_open_questions.md` 的“设计风险清单”“设计待确认事项清单”和“当前设计层未闭环项说明”小节。

Step 4~12 已把 `L4-sandbox` 的代码主体、对象、接口、处理流、状态机和配置边界收稳,但仍有一部分会影响后续详细设计展开的风险与待确认事项需要显式保留。

### 13.1 设计风险

| 风险 | 影响 | 当前处理口径 |
|---|---|---|
| tools semantic execution、runtime agent loop、member lifecycle orchestration 或 runner host lifecycle 反向定义 sandbox 正式主线 | 污染 intake、run、failure 和 read-side 主语 | sandbox 只拥有 execution isolation truth;外部语义只能作为输入语境 |
| 弱后端、测试承载、fallback 或 host-run 路径反向定义 `CoherentBoundary` | 打穿 boundary 主线和一票否决线 | 必需边界不可落实时只能 rejected / pending / unsupported / failed |
| sandbox 反向拥有 policy definition、approval、allowlist 或 capability truth | 导致高风险动作 fail-open | sandbox 只形成执行裁定;来源 truth 外部拥有,缺失或冲突时 fail-closed |
| capture、candidate material、observability material、handoff fact 或 investigation handoff 的 ownership 分层被打穿 | 让输出或回执静默升级为下游 formal truth | 继续坚持 capture / handoff / investigation 分层,formal truth 仍由下游确认 |
| Query、Consumer、Job、relay、projection 或 reconciliation 反写核心 truth | 形成隐藏写源和多套语义 | 长期坚持 Query no-write、Consumer 不写核心 truth、Job 不修核心 truth、relay / handoff no-rollback |
| failure classification、lease / orphan、cleanup guard、reaper 和 redline containment 被弱化成 best-effort 运维辅助 | cleanup 先删证据、orphan 脱管、containment advisory-only | failure / cleanup / containment 是一等正式语义 |
| 配置越界改写 truth ownership、coherent boundary、fail-closed、cleanup guard 或 redline semantics | 配置变成第二套业务真相源 | 配置只影响承载和 degraded surface,不能改写 domain invariant |
| 历史 Docker / gVisor / Firecracker、旧 allowlist / security profile、旧 P95 / SLA 和旧 README 术语回流为默认基线 | 旧结论污染 `03~07` | 继续作为 historical material / 候选输入处理,不得默认继承 |
| 实现侧绕过已形成的 `03~07` current contract，自行补第二套 schema、状态、port、product、evidence 或 boundary 口径 | 形成设计链断裂和实现私补真相源 | 遇到契约缺口必须回到对应设计文档闭口；不得用实现偏好覆盖current contract |

### 13.2 待确认事项

| 待确认 | 影响范围 | 当前挂起口径 |
|---|---|---|
| 具体 isolation backend 组合、正式 / 测试承载边界和 stronger isolation profile 触发条件 | boundary、capability、`04/05/07`、ADR | 当前只固定抽象 backend contract 和 coherent boundary |
| backend capability matrix、同等边界证明和 capability stale / unsupported 解释材料 | `BackendCapabilitySummary`;验收与测试方案 | 当前按能力缺失或不支持即拒绝 / 等待 / 失败处理 |
| policy / authorization 来源矩阵与 high-risk action taxonomy | policy snapshot、decision、`04/05/06` | 当前只固定“给定 policy / authorization + fail-closed” |
| network allowlist、mount 清单、seccomp / AppArmor / cap-drop / process profile 分类 | boundary profile、配置说明、高风险测试 | 当前只固定 deny-by-default 和“限制不可 silent degrade” |
| material class、partial capture、retention、safe summary、cleanup release 与 deletion guard 细化 | capture、cleanup、容量与验收 | 当前只固定 capture / handoff / cleanup 分层和 cleanup 不得先删证据 |
| handoff receipt / failed / retryable / reconciliation 协议、relay dead-letter 协议,以及 investigation handoff 回链确认方式 | handoff、relay、cleanup、`05/06` | material handoff只允许`Pending / Attempting / Delivered / Retryable / Failed`进展并机械派生aggregate，material不使用`DeadLetter`；`DeadLetter`只属于relay；坚持no-rollback / no-auto-release |

### 13.3 当前不阻塞项与进入实现前阻塞项

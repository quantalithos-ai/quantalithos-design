### 3.5 Exact Rust / core dependency baseline


#### Application port helper

```rust
/// Stable application-local optimistic version attached to persisted sandbox truth.
pub struct SandboxRepositoryVersion(pub u64);

/// Persisted value paired with an optimistic version.
pub struct Versioned<T> {
    /// Persisted value.
    pub value: T,
    /// Version required by the next optimistic write.
    pub version: SandboxRepositoryVersion,
}

/// Committed cursor assigned by sandbox persistence after staged writes.
pub struct SandboxTruthCursor(pub String);
```

`SandboxRepositoryVersion` 不得由 page cursor、timestamp、trace id、digest 或 stored result ref 替代。`SandboxTruthCursor` 只能由 UoW 在 staged writes 后分配。

## 8. 逐接口函数级处理流

> 校准来源:
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读:
> - 建议继续阅读 `design-calibration/03_ddd_step_09_function_flows.md` 的“Flow inventory”“shared templates”和每个协议 flow 小节,确认 exact 调用链、事务顺序和测试切口。

### 8.1 处理流总表

| Flow family | 协议数 | 入口 facade | 主要事务 | 状态变化 | 停审 |
|---|---:|---|---|---|---|
| Command flows | 10 | `SandboxCommandService` | command UoW + idempotency + stored result | core truth / marker 状态 | pass |
| Query read flows | 13 | `SandboxQueryService` | no-write read only | none | pass |
| Inbound consumer flows | 9 | `SandboxConsumerService` | consumer UoW where accepted | reference / handoff / relay marker only | pass |
| Outbound relay flows | 13 payloads + publish | relay append / `SandboxEventPublisherPort` | append in source tx;publish exact frozen relay attempt in relay-local tx | `SandboxEventRelayStatus` | pass |
| Operations job flows | 10 | `SandboxJobService` | per-job or per-item UoW | maintenance / projection / derived / relay only | pass |

### 8.2 Shared command transaction template

```text
[api/worker entry]
  | call SandboxApiEntryAdapter.map_command_context(...)
  | call validate(CommandRequestDto)
  v
[SandboxCommandService::<command>]
  | call SandboxUnitOfWorkManager.begin()
  | call SandboxIdempotencyRepository.reserve(&uow, ctx)
  | if Duplicate -> map stored result and rollback/no-op
  | call repository / resolver / adapter ports
  | call DomainObject.factory_or_transition(...)
  | save truth group
  | append audit trace
  | append pending relay where canonical payload exists
  | list affected projections and mark stale
  | save stored command result
  | complete idempotency
  | call uow.assign_truth_change_cursor()
  | commit
  v
[SandboxCommandResultDto]
```

关键规则:

| 规则 | 约束 |
|---|---|
| duplicate replay | 不调用 resolver / backend / repository mutation;直接从 `SandboxStoredOperationResult` 映射 result |
| rejected before mutation | rollback UoW;需要 replayable result 时只保存 rejected public result |
| accepted mutation | truth、audit、relay、projection stale、stored result、idempotency complete、cursor 必须同一 UoW staged 后 commit |
| projection stale | 只能通过 `list_projections_affected_by_truth(...)` 返回 existing projection refs;不得拼 projection ref |
| relay append | 只有 Step 8 有 canonical outbound payload 的 accepted path 才 append |

### 8.3 Shared query read template

```text
[api query entry]
  | call SandboxApiEntryAdapter.map_query_context(...)
  | call validate(QueryRequestDto)
  v
[SandboxQueryService::<query>]
  | no write UoW
  | normalize selector only through Step 7 read ports
  | call snapshot/projection/derived/audit repository
  | assemble contracts view DTO
  | map empty / not visible / stale / degraded / missing projection
  v
[SandboxQueryResponseDto<T> or SandboxPagedResponseDto<T>]
```

Query 禁止:

- begin write UoW。
- save truth、append audit、append relay、mark stale。
- refresh reference、rebuild projection、retry handoff、cleanup release、redline release。
- 缺 finder 时扫描 storage 或拼 ref。

### 8.4 Consumer / Relay / Job 关键流规则

| Flow | 关键顺序 | 硬边界 |
|---|---|---|
| Inbound consumer | validate envelope -> source / schema / digest / forbidden body gate -> reserve dedup -> load target state when port exists -> apply reference / feedback transition -> save receipt / stored result -> commit | trusted source 不能绕过 command gate;reference-only receipt 可 `trace_record_ref=None` |

## 9. 状态机与转换矩阵

### 9.1 通用状态矩阵规则

| 规则 | 正式口径 |
|---|---|
| 状态名来源 | 必须使用 Step 6 已定义 enum variant;不得新增同义状态或中文口语状态 |
| trigger 来源 | 必须是 Step 6 factory / member method、Step 7 repository marker update、Step 9 flow 中已列 application service 或 adapter outcome mapper |
| 副作用边界 | domain method 只改对象字段;trace、audit、relay、projection stale、stored result、cursor 和 commit 顺序由 application flow 编排 |
| 非法转换错误 | domain object 返回 `DomainError::InvalidStateTransition` 或细分 variant;application / job 层映射为 public surface |
| terminal 状态 | 终态不得重新打开;需要重新处理时必须创建新 truth / marker / replacement flow |
| query 状态 | Query 只能读取并暴露状态,不得写 truth、refresh、rebuild、handoff、cleanup、redline |
| maintenance 状态 | reference / projection / derived / relay / job report 状态不得反写 context / boundary / policy / run / capture core truth |
| source cursor | accepted truth cursor 只来自 UoW committed cursor;reference marker cursor 只来自 `assign_reference_marker_cursor()` |

### 9.5 非法转换处理表

| 禁止迁移 | 非法原因 | 错误 | 恢复 / handoff |
|---|---|---|---|
| terminal reopen,如 `Rejected -> Accepted`,`Closed -> Active`,`Released -> Active`,`DeadLetter -> Pending` | 终态不得重开 | `DomainError::TerminalStateReopen` | 新建正式 replacement flow 或人工 review |
| policy missing / stale / conflicted -> allow | 违反 fail-closed | `DomainError::PolicyFailClosedBypass` | 上游 policy summary 恢复后新评估 |
| unsupported boundary -> coherent | weak fallback | `DomainError::WeakBoundaryFallbackRejected` | backend / profile / capability 修复后重试 |
| query write / rebuild / cleanup / handoff | query no-write | `ApplicationError::NoWriteViolation` | 修实现;query 只返回 degraded / missing |
| relay publish failure -> rollback source truth | no-rollback | `DomainError::NoRollbackInvariantViolation` | 更新 relay status / report |
| job repair core truth | job no-repair | `ApplicationError::JobNoRepairViolation` | report failure;回设计或 command path |
| duplicate missing result -> recompute | 破坏 idempotency | `ApplicationError::DuplicateMissingResult` | manual integrity review |
| external body persistence | 安全红线 | `DomainError::ForbiddenExternalBodyPersistence` | quarantine / reject / safe diagnostic |

### 10.5 一致性策略表

| 一致性主题 | 策略 |
|---|---|
| Core truth | command path 强一致;existing object update 必须 expected version |
| Boundary -> Policy -> Run顺序 | boundary group先持久化identity/profile/template/generation绑定的immutable requirement、handle和bounded lease;policy只按typed requirement ref消费;run按exact refs同时要求coherent boundary、active handle、active non-expired lease与Accepted policy |
| References / snapshots | 本地 body-free snapshot,不拥有外部 truth;stale / unavailable 进入 degraded / fail-closed surface |
| Relay / outbox | source transaction append immutable frozen relay bundle;publisher consumes exact committed bundle + attempt and never rebuilds payload from latest truth;success=`Published`;failure only changes relay record / report |
| Capture / handoff | capture has no `Pending` lifecycle and is immutable after `record`;handoff opening has zero delivery calls;per-target attempt-before-call and post-call CAS own retry / failure without changing capture |

| Fake / durable parity | fake 必须模拟 UoW staging、rollback、version conflict、unique key、cursor、stored result、page order 和 no-scan |

### 12.1 通用并发与幂等规则

| 规则 | 正式口径 | 禁止替代 |

### 12.5 Canonical machine artifact implementation contract

> 校准来源:
> - `design-calibration/07_implementation_plan_step_15_technical_baseline_decisions.md` §3
> - `design-calibration/03_ddd_step_19_formal_document_assembly.md` §11

Canonical machine artifact 只有一个 primitive owner，由 `CB-SBX-02C` 在 test-support/evidence module 建立，后续
writer、report generator 与 `CB-SBX-14B` 只复用，不得各自格式化或 hash。依赖精确固定为：

```toml
serde_json_canonicalizer = "=0.3.2"
serde_json = { version = "=1.0.145", features = ["float_roundtrip"] }
sha2 = "=0.10.9"
```

Writer 算法固定为：typed value 先完成 schema / number / string / path 校验；只从 root 删除
`artifact_digest`；使用 `serde_json_canonicalizer::to_vec` 生成 material bytes；对该 bytes 计算 SHA-256 并写入
`sha256:<64 lowercase hex>`；重建完整 typed artifact、再次 RFC 8785 canonicalize，再原子写入固定 run-relative path。
不得接受 raw JSON string 作为 authoritative input，不得依赖 map insertion order、pretty formatter、`Debug`、`jq`、
`sha256sum` 或 Shell 字符串拼接。

Verifier 必须按以下顺序 fail-closed：bounded bytes -> UTF-8/no BOM -> recursive duplicate-member-rejecting parse ->
no trailing byte/newline -> exact schema/status/path/forbidden-carrier validation -> 保存并移除 root self digest -> RFC 8785 +
SHA-256 recompute -> exact lowercase digest compare -> 完整对象 RFC 8785 bytes 与原 bytes 完全相等。普通
`serde_json::from_slice<Value>` 会吞 duplicate key，不得作为唯一 parser；必须使用 `Deserializer` + recursive custom map
visitor 和 seen-key set。

Machine schema 只允许字段声明范围内的整数；浮点、NaN、Infinity 与 arbitrary-precision 外形禁止。set-like array 由
typed builder 排序去重；路径必须仓根相对且拒绝空段、`.`、`..`、absolute 与 symlink escape。验证失败保留原文件的
安全 ref，不得静默重写。该合同是设计事实，required fixture 仍未运行。

### 15.6 Shell runtime、lint 与退出状态合同

> 校准来源:
> - `design-calibration/07_implementation_plan_step_15_technical_baseline_decisions.md` §4
> - `design-calibration/03_ddd_step_19_formal_document_assembly.md` §11

17 个正式脚本统一使用 `#!/usr/bin/env bash`，最低 GNU Bash `5.2`。shebang 后首个可执行设置必须为
`set -Eeuo pipefail`，随后设置 `IFS=$'\n\t'`、`umask 077`、`LC_ALL=C`。静态检查固定为 17/17 `bash -n` 与
ShellCheck `0.10.0`：`shellcheck --shell=bash --severity=warning <scripts>`。禁止全局 exclusion；单行 suppression
必须紧邻、绑定 exact SC code、写明原因并经 automation/security review。

脚本只做编排和状态传播；machine JSON、RFC 8785 bytes 与 digest 必须调用 §12.5 Rust helper。禁止 `eval`、动态
`source`、`curl | sh`、解释未验证路径、heredoc/`jq`/`printf` 手写权威 JSON、泛化 `|| true`，以及 stdout/stderr
回显 secret、raw body、process output、provider response、stack 或敏感绝对路径。cleanup trap 必须保留主体 first
failure，不得覆盖退出状态。

| exit | semantic status | 父流程处理 |
|---:|---|---|
| `0` | `Passed` 或成功生成不带裁决的 draft/report | 仍读取 paired raw status，不仅凭 exit 0 宣布通过 |
| `2` | invocation/input schema invalid | `InfraFailed` |
| `3` | required prerequisite missing | `Blocked`，不得转 Skipped |
| `4` | harness/tool/environment failure | `InfraFailed` |
| `5` | assertion/check/gate failure | `Failed` |
| `6` | formally conditional source not activated | `NotRunConditional`，不得补偿 P0 |
| `>=7` | unclassified failure | `InfraFailed`，不得猜测 Passed/Failed |

ShellCheck 当前未安装于观察环境，目标脚本也不存在，因此语法、lint 与 negative fixture 都是 `NotRun`。

本文没有声明任何测试已运行,没有真实 run_id,没有 evidence alias,没有验收签署。

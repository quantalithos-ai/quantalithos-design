## 2. 本次测试目标与范围

> 校准来源:
> - `design-calibration/05_test_plan_step_02_scope.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“P0 / P1 / P2优先级口径”“测试目标表”“范围 / 非范围主表”“Profile到测试优先级与证明上限”“只测接缝的相邻仓 / 外部能力”“VF / VETO映射”和“当前执行与资格blocker分层”,确认P0-C / P0-Q不可替代关系及后置风险。

本轮测试目标是证明 `L4-sandbox` 的受控执行隔离闭环在正式需求、详细设计与配置契约上可验证:统一受理并建立 execution environment identity;形成resource / filesystem / network / process coherent boundary;在给定launch policy内fail-closed执行;分层形成capture与handoff事实;提供safe observability和formal audit材料;稳定分类failure;按lease / cleanup / reaper和security redline完成保守收束。

P0内部使用两个审查标签。P0-C验证deterministic contract、domain invariant、fake / controlled seam、状态、事务、幂等、配置、失败与安全语义;P0-Q验证candidate real backend在dedicated environment中真实落实四维隔离、launch、lifecycle、capture / inspect / release与no-host-fallback。两者同属P0且不可相互替代:P0-C不能证明真实隔离,P0-Q不能替代协议、状态、事务和配置契约覆盖。任何适用P0-Q保持 `Blocked` 时,整体P0不得被声明通过。

## 4. 测试策略与分层

> 校准来源:
> - `design-calibration/05_test_plan_step_04_strategy_layers.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“测试分层图”“测试分层策略表”“CUT到层级映射”“Profile到测试层级映射”和“双门禁反替代审计”,了解L1~L6如何承担最早发现层与资格证明层。

测试层级按风险最早可判定的位置划分。L1~L4共同构成P0-C,L5独立构成P0-Q,L6只汇总最小闭环和证据身份。任何上层结果都不能覆盖下层的`Failed`、`Blocked`、`NotEvaluated`或`NotRunConditional`;E2E不拥有新增领域断言权。

### 4.1 六层风险发现模型

| L3 | Repository / Adapter / Runtime Builder Integration | rollback / version / cursor / race、adapter mapping、complete generation、write audit | parity fake、controlled seam、failure injection | candidate真实四维限制、跨仓完整语义 | CI integration候选;失败阻断对应P0-C |

## 11. 缺陷管理与复验规则

> 校准来源:

>
> 延伸阅读:

测试状态、问题归因和缺陷等级是三个独立维度。`Failed`只表示固定run观察到断言不成立,不得在归因前自动创建产品缺陷;`Blocked`、`InfraFailed`和`NotRunConditional`也不得改写为产品失败、Skipped或Passed。缺陷实例、真实修复revision和复验run只在后续执行中产生,本文仅固定判定规则。

### 11.1 状态、归因与缺陷等级

| 测试 / Gate状态 | 含义 | 归因要求 | Gate处置 |
|---|---|---|---|
| `Failed` | 用例断言或完整性检查不成立 | 保留raw,再定位产品、测试基础设施、环境或设计责任 | 受影响gate保持Failed,不得用重跑绿色覆盖 |
| `InfraFailed` | harness、fixture、runner、scanner、report generator或环境装配不可信 | 建立测试基础设施问题;P0相关时按A级起步,吞掉红线或伪造结果时升S | 修复前相关结果无效,必须重新执行有效产品断言 |
| `Blocked` | candidate、identity、provider、lab、前置suite或必需输入缺失 | 记录前置blocker,不创建产品缺陷 | 保持Blocked并向上游gate传播,不得转Skipped / Passed |
| `NotRunConditional` | P1 / P2激活条件不成立 | 记录未激活原因和未来trigger | 不阻断P0,也不得补偿P0或声称已验证 |
| `Passed` | 当前固定run完成全部适用断言 | 只对该subject / identity / raw成立 | 不覆盖其他Failed / Blocked run或不同qualification identity |

| 归因类型 | 判定 | 管理去向 | 对正式测试的影响 |
|---|---|---|---|
| 产品 /契约缺陷 | 实现行为违反当前正式`00~04`的唯一契约 | 按S / A / B管理 | 按等级阻断受影响suite / gate |
| 测试基础设施缺陷 | 测试代码、fixture、scheduler、scanner、runner或report工具不可信 | 独立修复并使相关结果失效 | P0相关时至少A级阻断;伪造 /吞掉红线时S级 |
| design-reopen | 无法由正式字段、状态、flow、error或config得到唯一断言,或上游互相冲突 | 回写owner文档和对应测试Step | 相关切口暂停,测试方案不得补语义 |
| execution blocker | 目标仓、suite、environment、candidate、provider或lab未形成 | 保留项目blocker | 对应P0-Q / release保持Blocked,不生成缺陷结果 |
| conditional residual | P1 / P2 /量化基线尚未激活 | §14残余风险承接 | 不阻断P0,但不得写成已关闭风险 |

正式缺陷等级只使用`S / A / B`;`ResidualTracked`是处置状态,不是第四等级。

### 11.2 S级不可降级项与Suite升级

以下命题一经证实即为S级,不因发生在fake、test、nightly或conditional环境而降级:

- `VF-SBX-001~010`或`VETO-CFG-01~16`任一命中。
- host / caller-local / anonymous / bypass被冒充formal execution,或resource / filesystem / network / process任一维度未落实仍继续launch。
- policy / authorization missing、stale、conflicted、unsupported或unauthorized时fail-open。
- 外部正文、raw output、secret、provider response或full sensitive ref进入truth、audit、report、log、metric或其他carrier。
- capture / receipt / telemetry升格为artifact、evidence或其他下游truth;query / job / maintenance形成第二truth writer。
- cleanup / reaper在handoff、audit或investigation guard非Allowed时release,或lease / orphan / redline脱离托管收束。
- 事务partial visibility、duplicate重算 /二次副作用、双winner、stored result被当前truth重算。
- accepted mutation缺formal audit、raw / report / digest失配、静态文件宣告pass、Blocked被吞掉或evidence被伪造。
- partial / mixed config generation对外可用、unsupported安全面静默成功、或引入非`core-contracts` sibling编译依赖。

### 11.4 生命周期、关闭与证据失效

```text
Detected -> Preserve -> Attribute -> Classify -> Contain / Block
  -> Fix or Design Writeback -> ReadyForRetest -> New Fixed Run
  -> RetestFailed: Reopen
  -> RetestPassed + Closure Material Complete: Closed
```

关闭S / A缺陷至少需要:原失败固定run及TC / parameter / suite / gate / raw / report引用;归因与AC / VF / VETO / PER影响;真实修复revision或设计回写引用;新固定run中§11.3必跑集合;相关redaction / dependency / pairing / cleanup / identity结果;旧证据invalidated / superseded处置;自动化新增、扩展或无需新增的可审理由。本文不创建这些实例。

| 变化 /发现 | 既有结果处理 | 最低复验 |
|---|---|---|
| 产品、shared contract、state、UoW或error mapping变化 | 受影响Passed不再证明当前revision | 按§11.3新run |
| assertion、fixture、fake parity或scheduler变化 | 旧结果不能证明新harness | 重跑受影响参数和suite |
| redaction / scanner变化 | 旧scan结果失效 | immutable raw完整则重扫;否则重跑producer |
| report generator变化 | raw产品结果可保留,旧report失效 | 同raw重生成并复跑pairing / no-static |
| config generation、profile或dependency binding变化 | 旧结果不代表新组合 | 重跑受影响gate,禁止混用generation |
| P0-Q qualification identity任一变化 | 整个旧packet不能证明新identity | 完整SUITE-013和P0Q checks |
| 已交接证据关联缺陷重开 | 相关evidence不得继续作为通过输入 | 标记invalidated / superseded并通知后续`06` |

一次绿色重跑不能覆盖原失败。相同identity下间歇变绿必须保留原run、标记intermittent candidate并扩大scheduler / timing / fixture隔离调查;无根因和防回归断言不得关闭。

### 11.5 风险接受与自动化补强

- S级、VF、VETO、安全、truth或evidence完整性问题不可风险接受。
- A级可获得不改变gate的临时“继续开发 /诊断”例外,但open A不得计入P0退出或release。
- 只有不影响P0的B级可由明确owner记录理由、影响、期限和重开trigger后接受;不得补偿P0。
- ENV-05、目标仓或suite缺失属于Blocked,不是可接受风险;`NotRunConditional`也不是缺陷关闭。
- 手工 /安全调查发现P0、release / P0Q才发现而低层漏检、redaction / dependency / pairing / blocked check漏检、间歇性race或fault path缺断言时必须补自动化。
- 既有场景只缺参数或副作用断言时扩展原TC且不换义改号;新独立正式场景先回写Step 5 /6和254基线;缺正式契约时先design-reopen。

### 14.2 Scope、选择与升级

| Scope | 最低执行集合 | 效力上限 |
|---|---|---|
| `Targeted` | 全部直接受影响TC参数、原负向fixture与直接check | 快速反馈;不能单独关闭S / A或证明suite / P0 |
| `Family` | 受影响protocol / state / error / owner family全部TC及相邻副作用 | 不得以代表case替代完整family |
| `Suite` | 受影响suite完整manifest及checks | 不替代其他受影响suite或gate |
| `P0-C` | 新MAIN的SUITE-001~011 /014、新OPS的012及007~010 /014补强、016 scope guard、237 P0-C与checks | 不证明candidate-real,不替代P0-Q / Release |
| `P0-Q` | 同一packet的SUITE-013 13条TC及identity / redaction / cleanup / blocked / pairing | 不证明237 P0-C,不接受低profile或历史packet |
| `Release` | 同一送验基线的新MAIN-CONTRACT + MAIN-SEAM + OPS + P0Q四源、250 P0、全部checks / reports / evidence / draft | 只形成新版`06`输入,不等于验收通过 |
| `Conditional` | 已正式激活的SUITE-015参数,同时运行SUITE-016 scope guard | 不影响或补偿P0 |
| `DesignReopen` | 暂停测试,回写`00~04`并重开Step 2 /5~14 | 不是可执行scope,禁止测试私有语义绕过 |

```text
freeze immutable change set and identities
  -> map formal IDs and all RT rows
  -> union affected TC parameters / suites / checks
  -> expand negative / side-effect / error / race / adjacent coverage
  -> invalidate old results as required
  -> evaluate DesignReopen first
  -> derive P0-C scope and independent P0-Q-required flag
  -> Release intent forces complete P0-C + P0-Q + evidence checks
  -> persist exact selection before execution
  -> missing / unreviewed extra / identity mismatch => Blocked
```

多项change取并集且scope只升级不取交集;无法映射formal ID时转DesignReopen。shared contract / truth / state / UoW / generation至少P0-C;candidate packet identity变化完整P0-Q;VF / VETO / S / evidence伪造或跨gate缺陷完整Release。release intent不消费此前局部绿色替代新固定MAIN-CONTRACT / MAIN-SEAM / OPS / P0Q四源。

- target repo、suite、CI、ENV-02~05、candidate、provider或lab缺失属于execution / P0-Q blocker,不得接受为“已覆盖”。

建议按以下流程产出:

   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`

   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 sandbox“能跑命令”,而是系统验证 `L4-sandbox` 是否真正满足“受控执行隔离层”的设计要求,尤其要证明以下几点成立:
- SandboxExecution / SandboxSession 构成正式隔离执行真相层
- `SandboxExecution ≠ runtime execution truth`、`session lifecycle ≠ business task lifecycle` 两条核心边界成立
- fs / network / quota / env injection 构成统一隔离环境主线,且 `Isolation boundary ≠ capability access control`
- SandboxCommand / tool bridge / provider bridge 只做执行承载,不反向定义 ToolDefinition 或 capability decision 真相
- `SandboxOutput ≠ Artifact truth`,stdout / stderr / output files / usage snapshot / audit trail 必须形成统一证据链
- kill / timeout / retry / replay / cleanup / inspect 构成一致控制链,且 `Replay / retry execution ≠ repeat business decision`
- 未授权网络、路径、provider 访问必须被阻断,并且 deny / control / replay 都留痕

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 执行请求与会话建立部分 | execution/session 对象 | P0 | SandboxExecution、SandboxSession、ExecutionRequest、SessionLifecycleState、ExecutionBinding |
| 隔离环境与资源约束部分 | isolation 对象 | P0 | IsolationPolicy、FilesystemMount、NetworkPolicy、ResourceQuota、EnvironmentBinding |
| 命令执行与外部能力接缝部分 | command / bridge 对象 | P0 | SandboxCommand、CommandBridge、ExternalCapabilityBridge、ExecutionResultHandle |
| 输出回收与审计留痕部分 | output / audit 对象 | P0 | SandboxOutput、OutputFileRef、UsageSnapshot、ExecutionAuditTrail、ExecutionSummary |
| 失败恢复与运维控制部分 | control 对象 | P0 | TimeoutRecord、KillRequest、ReplayRequest、CleanupRecord、OperatorInspection |
| runtime 业务状态推进逻辑 | 非范围 | P2 | 只验 sandbox 如何承接执行请求,不验 runtime 主状态机全部实现 |
| ToolDefinition / provider contract / capability decision 真相本体 | 非范围 | P2 | 只验 sandbox 消费其输入并在执行面落实,不验上游仓全部实现 |
| artifact 最终入库与 UI 渲染细节 | 非范围 | P2 | 只验输出材料与摘要出口,不验下游消费全部逻辑 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / policy owner | `request.validate_execution_request`、`policy.validate_isolation_boundary`、`command.validate_command_boundary`、`result.validate_capturable_result`、`request.validate_control_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + runtime_host + projection + publisher 联动 | backend / domain owner | `CreateSession`、`ApplyIsolationPolicy`、`RunCommand`、`CaptureStdout`、`KillSession`、`ReplayExecution` | execution、isolation、command、output、control 五条主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | runtime request → sandbox session、tool binding → command bridge、capability allowlist → network/provider gate、output → artifact/observability/conversation | 输入输出语义一致 |
| 恢复专项测试 | 验证 timeout、orphan session、cleanup 提前删除、provider 越权、output 丢失等异常链 | architecture / QA | timeout fail、bridge deny、capture fail、replay compare、cleanup guard | 真相不丢失、错误被正确阻断或留证 |
| 投影一致性测试 | 验证 execution status / usage / output summary / control history 与真相一致 | backend / QA | status rebuild、usage rebuild、summary rebuild、control history rebuild | 投影只读且与真相一致 |
| 端到端主线测试 | 验证最小受控执行闭环 | QA / owner | request → session → isolation → command → output → replay/cleanup | 主干执行闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `SandboxExecution ≠ runtime execution truth` | sandbox 只表达隔离执行记录,不推进业务主状态 | 单元 + 集成测试 | 是 | model review / payload compare |
| `session lifecycle ≠ business task lifecycle` | 会话结束或 replay 不得直接等于业务任务结束/重做 | 单元 + 集成测试 | 是 | control history / negative flow |
| `SandboxCommand ≠ ToolDefinition` | tool binding 只映射命令,不等于命令真相本体 | 单元 + 集成测试 | 是 | command bridge / compare report |
| `Isolation boundary ≠ capability access control` | capability allowlist 是外部输入,sandbox 只执行边界落实 | 集成 + 事件链测试 | 是 | network policy / provider gate trace |
| `SandboxOutput ≠ Artifact truth` | 输出材料只回收为候选材料,不直接变 artifact 真相 | 集成 + 事件链测试 | 是 | output capture / artifact candidate compare |
| `Replay / retry execution ≠ repeat business decision` | replay 只重做执行壳,不重做治理/业务决策 | 单元 + 恢复专项测试 | 是 | replay evidence / control trace |
| 未授权网络/路径/provider 必须阻断 | deny-by-default on network/fs/provider | 集成 + 安全测试 | 是 | deny audit / error snapshot |
| stdout/stderr/output files 回收完整 | 输出回收率达到目标 | 集成 + E2E | 是 | output records / compare report |
| kill / timeout / cleanup 必留痕 | 所有控制动作进入 append-only 证据链 | 集成 + 恢复专项测试 | 是 | control history / audit trail |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | CreateSession 成功建立正式 execution/session 锚点 | request 合法 | CreateSession | SandboxExecution / SandboxSession 创建成功 |
| TC-002 | 无正式 session 不得执行命令 | execution 锚点缺失 | RunCommand | 返回 session 缺失错误 |
| TC-003 | ApplyIsolationPolicy 成功绑定 fs/network/quota 规则 | session 已创建 + policy 合法 | ApplyIsolationPolicy | 隔离策略成功落地 |
| TC-004 | 未授权网络访问被阻断 | network_mode=Disabled 或 target 不在 allowlist | RunCapabilityBridge | 返回网络/能力拒绝错误 |
| TC-005 | RunCommand 成功执行并产生结果句柄 | session ready + command 合法 | RunCommand | ExecutionResultHandle 创建成功 |
| TC-006 | ToolDefinition 不得被当作直接执行命令 | tool binding 未映射到 SandboxCommand | RunToolBridge | 返回命令边界错误 |
| TC-007 | CaptureStdout / CaptureFiles 成功回收输出与审计材料 | result handle 已存在 | CaptureStdout / CaptureFiles | SandboxOutput / OutputFileRef / UsageSnapshot / AuditTrail 创建成功 |
| TC-008 | 输出文件不得直接当 artifact 真相入库 | output captured but artifact not confirmed | negative flow | 仅形成 artifact candidate |
| TC-009 | KillSession 成功终止会话并写入控制证据 | running session 存在 | KillSession | session 停止 + control history 追加成功 |
| TC-010 | ReplayExecution 成功重放执行壳并保留原始证据 | replay request 合法 | ReplayExecution | replay 成功且原始执行证据未丢失 |
| TC-011 | cleanup 不得提前删除仍需回放/审计材料 | replay pending 或 audit open | CleanupSession | 返回 cleanup 拒绝错误 |
| TC-012 | orphan session 被回收且留证 | orphan detected | CleanupSession / GC | 会话回收成功且 evidence 完整 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | runtime 绕过 sandbox 直执行 / 未授权网络或 provider 被放行 / 输出证据链丢失 / cleanup 先删证据后留痕 | 阻断放行,必须修复 |
| A | 主线可跑但 replay、quota、output capture、artifact candidate 边界不稳 | 原则上修复后再放行 |
| B | 非关键摘要视图、低优先级 usage 或展示异常 | 可带风险进入下一轮 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 SandboxExecution / Session,都必须回归执行接入与会话生命周期主线
- 每次改动 fs / network / quota,都必须回归隔离与拒绝访问主线
- 每次改动 command / bridge,都必须回归 ToolDefinition 边界与 provider allowlist 主线
- 每次改动 output capture / summary / audit,都必须回归 Artifact truth 边界与证据链主线
- 每次改动 timeout / kill / replay / cleanup,都必须回归控制链与 replay 可追溯主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 多集群 / 多宿主执行后续细化 | 测试矩阵需扩充 | TL / 架构 |
| provider bridge 模型继续演进 | capability-hub 接缝测试需增加更多样本 | sandbox / capability-hub |
| output file 大体积与长时会话增长 | 回收与清理策略测试需扩充 | platform / observability |

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L4-sandbox` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L4-sandbox` 是受控执行隔离层,不是 runtime 主真相仓、tools 定义仓或 provider contract 仓
- SandboxExecution / SandboxSession 构成正式隔离执行真相层
- `SandboxExecution ≠ runtime execution truth`、`session lifecycle ≠ business task lifecycle` 两条核心边界必须成立
- fs / network / quota / env injection 构成统一隔离环境主线,且 `Isolation boundary ≠ capability access control`
- SandboxCommand / tool bridge / provider bridge 只做执行承载,不反向定义 ToolDefinition 或 capability decision 真相
- `SandboxOutput ≠ Artifact truth`,stdout / stderr / output files / usage snapshot / audit trail 必须形成统一证据链
- kill / timeout / retry / replay / cleanup / inspect 构成一致控制链,且 `Replay / retry execution ≠ repeat business decision`
- 未授权网络、路径、provider 访问必须被阻断,并且 deny / control / replay 都必须留痕

因此,本次验收的目的不是笼统判断“能不能执行命令”,而是判断 sandbox 的 execution/session 主线、isolation 主线、command 主线、output/evidence 主线与 control/recovery 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 执行请求与会话建立部分 | 是 | SandboxExecution、SandboxSession、ExecutionRequest、SessionLifecycleState、ExecutionBinding |
| 隔离环境与资源约束部分 | 是 | IsolationPolicy、FilesystemMount、NetworkPolicy、ResourceQuota、EnvironmentBinding |
| 命令执行与外部能力接缝部分 | 是 | SandboxCommand、CommandBridge、ExternalCapabilityBridge、ExecutionResultHandle |
| 输出回收与审计留痕部分 | 是 | SandboxOutput、OutputFileRef、UsageSnapshot、ExecutionAuditTrail、ExecutionSummary |
| 失败恢复与运维控制部分 | 是 | TimeoutRecord、KillRequest、ReplayRequest、CleanupRecord、OperatorInspection |
| runtime 业务状态推进逻辑 | 否 | 只验 sandbox 如何承接执行请求,不验 runtime 主状态机全部实现 |
| ToolDefinition / provider contract / capability decision 真相本体 | 否 | 只验 sandbox 消费其输入并在执行面落实,不验上游仓全部实现 |
| artifact 最终入库与 UI 渲染细节 | 否 | 只验输出材料与摘要出口,不验下游消费全部逻辑 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateSession / AttachSession | 合法 request 时必须形成正式 SandboxExecution / SandboxSession 锚点 | API 响应 / DB 记录 / trace | [] |
| Execution/Session 边界 | sandbox 只表达隔离执行记录与会话,不得推进 runtime 业务执行真相 | model review / negative flow / payload compare | [] |
| ApplyIsolationPolicy | session 建立后必须形成正式 fs / network / quota / env 约束 | policy row / mount/net/quota report | [] |
| Isolation 边界 | isolation 只负责执行面约束,不得替代 capability access 决策或 finance 成本真相 | compare report / negative flow | [] |
| RunCommand / RunToolBridge / RunCapabilityBridge | 受控环境 ready 后必须形成正式 SandboxCommand 与结果句柄 | result handle / execution trace | [] |
| Command 边界 | SandboxCommand 只能表达真实执行动作,不得等同 ToolDefinition 或 provider contract 真相 | command compare / negative flow | [] |
| CaptureStdout / CaptureFiles / EmitExecutionSummary | 执行完成后必须形成 stdout / stderr / output files / usage snapshot / audit trail / summary | output records / audit trail / summary log | [] |
| Output 边界 | 输出材料不得直接确认为 Artifact truth,必须保持 candidate / evidence 语义 | artifact candidate compare / negative flow | [] |
| KillSession / RetryExecution / ReplayExecution / CleanupSession | timeout / kill / replay / cleanup 必须形成正式控制记录并可回放 | control history / replay evidence / cleanup log | [] |
| Control 边界 | replay / retry 只能重做执行层,不得重做业务裁决或删除仍需审计材料 | negative flow / replay compare / cleanup guard | [] |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| runtime 不可绕过 sandbox | 所有正式执行都必须进入 SandboxSession / Execution 主线 | execution trace / negative flow | [] |
| isolation 不可退化 | 未授权网络、路径、provider 访问必须被阻断 | deny report / fs/net compare | [] |
| output 不可越权成 truth | stdout/stderr/files 只能形成 candidate / evidence,不得直接变 artifact 真相 | compare report / negative flow | [] |
| replay 不可重做业务裁决 | replay / retry 只重做执行壳,不改 runtime/gov 业务真相 | replay trace / negative flow | [] |
| cleanup 不可先删证据 | 所有 cleanup 必须在审计与 replay 安全后执行 | cleanup guard / evidence check | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | runtime 绕过 sandbox 直执行 / 未授权网络或 provider 被放行 / 输出证据链丢失 / cleanup 先删证据后留痕 |
| A | 视情况 | 主线可跑但 replay、quota、output capture、artifact candidate 边界不稳 |
| B | 可带着走 | 非关键摘要视图、低优先级 usage 或展示异常 |

## 1. 与上游文档的关系声明

> 校准来源:
> - `design-calibration/07_implementation_plan_step_01_input_boundary.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“实施输入边界表”“Sandbox责任边界预检查”“可落码闭环预判”和“权威顺序与冲突处理”。

本实施计划承接L4-sandbox当前已审查的正式`00-需求文档.md`至`06-验收标准.md`。需求和架构定义execution isolation truth、职责、依赖与安全红线;概要设计定义主要组成部分和处理主线;详细设计定义可落码对象、port、55协议、flow、30个owner-level state machines、31个Step 10 canonical status enum entries、39个Step 6 shared status declarations、38 typed error和一致性契约;配置设计定义运行输入、profile、material和不可弱化边界;测试方案与验收标准定义测试、evidence、VETO与裁决门禁。本计划只把这些设计组织为可验证phase和commit boundary,不得形成第二套字段、DTO、状态、配置、测试或验收真相源。

Sandbox实现必须持续闭合execution environment identity、resource limits、filesystem / network / process coherent boundary、workspace requirement、tool / runtime launch policy enforcement、run / capture / handoff、observability hooks、failure classification、control、lease / cleanup / reaper和security redline。以下职责始终不属于Sandbox:

- tools semantic execution、tool registry和planner truth。
- runtime agent loop、planning和recovery orchestration。
- member / host / session / worker lifecycle orchestration。
- Artifact正文 /版本 /归档truth、Observability正式truth和Policy正式truth。

上述领域只能通过typed ref、body-free summary、port、adapter、event、handoff、fake或controlled seam协作。旧`README.md`、重建前旧正式文档和L2相邻仓旧Draft均为`historical_material`,不得恢复旧Docker /gVisor硬选型、旧阈值、旧对象或旧实施路线。

权威顺序固定为:

```text
current formal 00~07
  -> current boundary exact sections and identifiers
  -> corresponding design-calibration explanation
  -> normative standards for execution discipline
  -> unresolved or contradictory
  -> gate_status = blocked; next_allowed_action = wait_design
```

## 2. 实施目标与范围

> 校准来源:
> - `design-calibration/07_implementation_plan_step_02_scope.md`
>
> 延伸阅读:
> - 建议继续阅读上述中间产物的“最小可交付结果定义”“核心实施范围表”“明确非范围表”和“双向覆盖审计”。

本轮目标是在`quantalithos-sandbox`建立可编译、可测试、可由P0-C与P0-Q分别裁决的execution isolation truth center。范围覆盖C-SBX-1~5和FR-SBX-001~018,包括:

1. 统一受理、caller reference resolution与execution environment identity。
2. resource / filesystem / network / process四维隔离与workspace requirement的同代coherent decision。
3. 给定外部policy / authorization truth下的fail-closed launch enforcement。
4. controlled run、body-free capture和material handoff,失败不回滚source truth。
5. failure classification、control、lease / orphan、cleanup / reaper和redline containment。
6. 55协议、30个owner-level state machines /31个Step 10 canonical status enum entries /39个Step 6 shared status declarations、38 typed error、UoW /幂等 /并发、配置、审计、观测与evidence producer。

P0必须同时覆盖:

| 轴 | 范围 | 不可替代规则 |
|---|---|---|
| P0-C | PROFILE-01~04的contract、semantic fake、controlled seam与operations simulation | 证明正式语义,不证明真实candidate isolation |
| P0-Q | PROFILE-05 / ENV-05固定candidate packet下的单一concrete binding与13条CONF | 不能由fake、controlled seam、PROFILE-06或host fallback替代 |

237项P0-C和13项P0-Q均mandatory,合计250项P0。4项conditional单独披露,不得补偿P0。

以下不进入当前P0实施:

- PROFILE-06 durable / real-like /联合E2E,除非后续正式激活。
- PROFILE-07 production、capacity、DR、fleet、zero-downtime和生产运营能力。
- advanced replay /operator、rich preview /analytics、多backend选择、多宿主调度、operator console。
- production migration /seed、物理retention数值 /介质和部署运维runbook。
- 相邻仓业务语义、真实验收结论、签署和发布授权。

### 6.3 设计闭环Profile与九类Gate

## 10. 回退、暂停与变更控制

> 校准来源:
> - `design-calibration/07_implementation_plan_step_10_rollback_pause_change_control.md`
> - `design-calibration/07_implementation_plan_step_10_boundary_control_matrix.md`
> - `design-calibration/07_implementation_plan_step_10_invalidation_recovery_register.md`
>
> 延伸阅读:
> - 建议继续阅读统一控制状态机、32 boundary控制矩阵和generation /P0-Q /RELEASE /acceptance失效传播。

### 10.1 暂停与合法动作

遇到design冲突、scope越界、gate失败、现实依赖缺失、安全红线、用户改动冲突或identity失效时,冻结当前boundary并保留worktree /失败材料。`gate_status=blocked`时,next action只能是`wait_design`、`fix_gate_failure`或`handoff`。

### 10.2 回退与恢复

默认回退单位是当前boundary的未提交授权改动。已验证前序boundary不因当前失败自动回退;已提交缺陷优先forward-fix,只有明确授权并完成依赖 /evidence影响审计后才可revert。配置回退形成新complete generation;证据复验形成新run;验收identity变化形成新batch。旧事实保持immutable。

恢复前必须关闭owner blocker、固定baseline /dependency identity、确认单current与worktree ownership、完成失效传播、重跑受影响Gate。恢复点是同一boundary首个未通过Gate,不是自动进入下一boundary。

### 10.3 变更owner

| 变化 | 回写owner |
|---|---|
| 字段 /DTO /port /flow /state /UoW | 正式`03` |
| source /generation /profile /material | 正式`04` |
| TC /suite /schema /artifact /report | 正式`05` |
| AC /VETO /defect /risk /batch /signoff | 正式`06` |
| phase /boundary /scope /ledger | 正式`07` |
| 需求 /架构 /ownership /非目标 | 正式`00~02`对应owner |

任一四source、RELEASE、subject、config、claim或stage identity变化都必须使旧证据 /decision失效,不得覆盖旧失败材料。

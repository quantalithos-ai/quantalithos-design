## 2. 本次设计目标与范围

> 校准来源：
> - `design-calibration/02_hld_step_02_scope.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“设计目标表”“非范围表”和“当前阶段设计深度口径”小节，了解本章的结构深度和边界取舍。

本次概要设计在已收稳的需求与架构边界内，收敛一个 Desktop-first、可共享跨端语义的协作客户端结构。它负责展示 owner-safe 材料并发起受控协作意图；它不取代领域服务或 SDK。

### 2.1 设计目标

| 目标 | 说明 | 交付给详细设计的结果 |
|---|---|---|
| 收稳共享客户端代码主体 | 组织应用壳、页面/路由、体验编排、view model、store、reducer、SDK adapter、缓存/恢复和平台接缝。 | 主要组成部分、实现分层和职责边界。 |
| 收稳 Desktop-first 入口骨架 | 覆盖对话/线程、compose、GateCard、Artifact、项目列表/详情和公司目录；项目详情含概览、项目进度、关联群聊、工作项、证据五标签。 | 页面/路由族、组件职责和 view model 输入输出类别；进度不再是独立顶级入口。 |
| 收稳项目只读流程与关系消费 | 整体→阶段→节点，分叉/分支/汇聚及独立Gate；项目↔群聊往返，目录/项目成员/参与者分别可见。 | 分层图/等价列表、局部导航、来源隔离、关联查询、撤销/恢复骨架；缺合同即blocked。 |
| 收稳 Chat-local 对象、接口和处理流 | 区分局部状态与 owner-safe material/result/change。 | 03 可继续定义字段、协议、函数、事务、错误、幂等和测试输入。 |
| 收稳多轴状态与配置影响 | 保持结果门控、恢复、可见性、安全和跨端语义一致。 | 03/04 可继续定义状态实现、配置契约和清理规则方向。 |

### 2.2 当前范围

- 共享客户端语义 core：view model、store、reducer、SDK adapter、恢复协调和安全策略。
- Desktop-first 应用壳，以及可复用到 Web 的 shared UI 语义；Mobile 只保留临时 shell 候选，不作为 V1 前置。
- group/channel/dm/thread 入口、Turn 类型呈现、发送与重试姿态、formal change 消费、GateCard、Artifact safe preview、成员/项目/运行摘要和 Workspace safe view 消费。
- 跨端焦点/公告、离线和重启恢复、受限本地缓存、清理和可访问性边界。
- 项目详情内分层流程只读展示、节点安全关联与证据引用、双向群聊入口和公司目录；“一群至多一项目、项目可有多群”是产品约束目标，正式绑定owner/contract未确认，不能据本地选择建立绑定。

## 3. 约束条件

> 校准来源：
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“结构化约束条件表”“按后续章节的约束影响”和“禁止配置化边界线索”小节，了解每条硬约束如何约束对象、接口、流和状态。

| 约束 | 说明 |
|---|---|
| 业务能力只能经 `L0-sdk` 正式 seam 进入 | 页面、view model、store 和平台 shell 不直连 owner 私有 API、内部 bus 或共享数据库；未闭合 surface 只按能力类别保留。 |
| owner truth 与 Chat-local truth 分离 | Conversation、Turn、Participant、Project、Member、ProcessInstance/Activity/Token/Gateway、Gate/Decision、Artifact、Workspace、Runtime 和 Observability truth 归各 owner；Chat只持有route、selection、draft、attempt、恢复和受限展示材料。 |
| visibility/scope 无法验证时 fail-closed | 不从深链、缓存、空列表、对象名或错误差异推断可见性或存在性；入口和内容转入 `restricted`、`blocked` 或 `unavailable`。 |
| 业务结果必须由正式 owner result/change 或具有业务确认含义的receipt门控 | 普通接收/排队receipt、按钮、表单通过、transport acknowledgement、通知、连接恢复和缓存命中不能生成 `confirmed`；optimistic仅为可撤销本地表现。 |
| `unknown` 不得自动重放副作用 | 未知结果只能进入 query/probe/wait/user decision；不能以重试按钮或连接恢复隐式重放。 |
| 变化只消费 SDK formal change/event/resume | reducer 保留来源、版本/水位、幂等和 gap/expired/revoked 语义，不直订内部 bus 或猜 delivery 顺序。 |
| 展示材料必须最小披露并保留 provenance/freshness | safe view/ref/summary/preview 只进入允许的 view model/缓存；raw body、credential、raw log 和未脱敏 payload 不进入持有面。 |
| 平台 shell 与业务语义隔离 | Desktop/Web/Mobile 只提供宿主能力；宿主 acknowledgement、通知、深链和窗口生命周期不能改变 owner 权限、结果或恢复上限。 |
| 本地恢复有界且可清理 | 重启/离线只恢复最小安全材料和草稿；撤销、登出、scope 改变或过期时裁剪/清理，不延长授权。 |
| 未闭合合同和配置影响保持显式 | 不伪造 exact API、测试、验收或 readiness；配置不得绕过结果门控、redaction、幂等、安全清理和 owner 边界。 |
| 项目进度归项目详情，流程只读 | 整体→阶段→节点；分叉/分支/汇聚显示Process正式拓扑和状态，Governance Gate独立，不按颜色/工作项完成数计算汇聚。 |
| 绑定和成员集合分别验证 | 群聊绑定须正式关系，目标项目/群聊各自授权；公司目录、ProjectMember、Participant、Member在场分立，目录可见不等于DM或项目访问获准。 |
| source-local版本与消费语境隔离 | 不宣称跨owner原子快照；迟到query/event必须核对actor/scope/project/source和请求代次，不能覆盖新语境或复活撤销材料。 |

### 4.3 业务主要组成部分与实现分层关系

| 项 | 说明 |
|---|---|
| 业务主要组成部分 | §5 的协作体验语境、受控协作意图、安全语境与导航、变化与恢复连续性、平台体验与可访问性、owner-safe 材料镜像、本地展示与恢复投影；它们回答 Chat “做什么”。 |
| 实现分层 | Inbound、Application Services、Local Semantic、Projection/View Model、Ports/Adapters/Persistence；它们回答代码“如何安放”。 |
| 关系 | 一个主要组成部分可以横跨多个实现层；实现层不能被误读为 owner domain，也不能替代业务边界。 |

### 4.4 关键判断

- 页面、路由、view model、store、reducer、adapter 和平台 shell 是实现主体，不是 Conversation、Governance 或 Runtime 的领域聚合。
- `SdkQueryAdapter`、`SdkCommandAdapter`、`SdkChangeAdapter` 和平台 adapter 是正式接缝；它们不能绕过 `L0-sdk` 或把宿主反馈升级为业务结果。
- `LocalProjectionRepository` 和 `DraftStore` 只承载最小安全材料；本地持久化不延长授权，也不产生 owner truth。
- 具体目录、文件路径、完整 trait/struct、数据库表和协议 schema 留给详细设计及上游合同。

## 5. 主要组成部分、职责与边界

> 校准来源：
> - `design-calibration/02_hld_step_05_components_boundary.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“组成部分总表”“对象发现维度表”“各部分交互总图”“主要组成部分逐一展开”和“跨组成部分闭环审计”小节，了解 7 个业务结构主语如何收敛。

### 5.1 组成部分总表

| 主要组成部分 | 核心职责 | 主要代码主体 | 不承担什么 |
|---|---|---|---|
| 协作体验语境 | 组织对话、Turn、项目详情五标签、分层流程、关联群聊和公司目录 | `CollaborationSurfaceCoordinator`、`ConversationSurfaceViewModel`、`ProjectContextCoordinator`、`ProcessDrilldownCoordinator`、`DirectoryCoordinator` | 不拥有Conversation/Process/Project/关系/目录truth或授权。 |
| 受控协作意图 | 管理 draft、选择、发送/治理意图、attempt 和结果反馈 | `UserIntentCoordinator`、`DraftCoordinator`、`CommandResultGate` | 不执行 owner command、不生成 Decision、不把 ACK 当成功。 |
| 安全语境与导航 | 建立 actor/scope/visibility 语境，保护 route、深链、返回和清理 | `RouteContextCoordinator`、`VisibilityGuard`、`ScopeEntryGuard` | 不认证、不授予权限、不拥有 scope truth。 |
| 变化与恢复连续性 | 消费 formal change/resume，处理重复、乱序、gap、重连和 unknown | `SdkChangeAdapter`、`ChangeReducer`、`ResumeCoordinator` | 不直订内部 bus、不拥有 delivery cursor、不修复 owner truth。 |
| 平台体验与可访问性 | 提供 Desktop-first shell、宿主能力和等价辅助技术表达 | `PlatformCapabilityAdapter`、`AccessibilitySemanticAdapter`、`ShellLifecycleCoordinator` | 不改变业务语义、权限、结果或恢复上限。 |
| owner-safe 材料镜像 | 组合带来源、可见性和新鲜度的 safe view/ref/summary/preview | `SafeMaterialComposer`、`ProvenanceMapper`、`PreviewBoundary` | 不复制正文、owner schema、权限或跨域 truth。 |

#### 5.9.3 本部分对象发现线索

| 维度 | 候选对象 | §6 展开要求 |
|---|---|---|
| Truth / State | safe material disclosure/freshness state | 不重建 owner lifecycle。 |
| Policy / Invariant | material disclosure、freshness policy | visibility 不明时 fail-closed。 |
| Projection / Read model | `SafeMaterialSnapshot` | 独立定义 body-free 材料容器。 |

#### 5.9.4 本部分不承担什么

- 不复制 owner schema、正文、权限、版本链或跨域 truth。
- 不从引用猜正文或授权，不把 safe summary 拼成统一领域实体。
- 不把本地材料的 freshness 当 owner 生命周期。

#### 5.9.5 与其他部分的接缝

从 SDK/owner safe view/ref/result/change 接收材料，向协作体验、Artifact preview、成员/项目/运行卡片和恢复 view model 提供带来源的安全投影。

### 5.10 本地展示与恢复投影

#### 5.10.1 本部分职责

承载最小安全缓存、草稿、选择和恢复上下文，表达本地写入、恢复、过期、撤销和清理姿态；所有材料都受 `PersistenceSafetyGuard` 和 scope/visibility 约束。

#### 5.10.2 本部分包含的代码主体 / 模块

本部分 capability 与局部停审：

| capability | 输入 | 输出 | 状态/副作用 | 后续展开 |
|---|---|---|---|---|
| 局部导航store | ProjectNavigationState/SelectionState/context | ClientStateStore安全局部切片 | tab/阶段/节点/viewport/return不写owner | §6/8/9 |
| 持久化与恢复 | 安全草稿/最小缓存/恢复ref | LocalProjectionEntry/CacheLifecycleRecord | 恢复前重验语境与关系；不恢复授权或批准 | §6/8/11 |
| 清理 | revoke/logout/expiry/scope change | 不可见姿态+清理记录 | 先阻断展示/失效消费代次，再持久清理；失败不恢复展示 | §8/10 |

停审结论：图材料与目录按来源/访问缓存切分；不用本地ref补图/补成员；无原型数据持久化。 功能、对象来源和接缝通过结构审查，未确认正向能力保持blocked；不表示实现或测试通过。

| 代码主体 / 模块 | 类型 | 作用 | 后续展开位置 |
|---|---|---|---|
| `ClientStateStore` | Local state store | 维护 Chat-local reducer state | §7、§8、§9 |

| `DraftStore` | Local persistence component | 保存可恢复草稿的最小安全子集 | §6、§8、§11 |
| `CacheEvictionCoordinator` | Operations component | 执行过期、撤销、登出和容量触发清理 | §8、§9、§10、§11 |

#### 5.10.3 本部分对象发现线索

| 维度 | 候选对象 | §6 展开要求 |
|---|---|---|
| Truth / State | `LocalProjectionEntry` | 独立表达 Chat-local 投影生命周期。 |
| Policy / Invariant | `PersistenceSafetyGuard` | 阻止 credential/raw body/越权材料落地。 |
| Projection / Read model | Local display/recovery projection | 作为 `LocalProjectionEntry` 的用途，不复制 owner read model。 |
| Reference / Boundary | Cache/storage scope ref | 只表达本地存储边界。 |
| Audit / History | `CacheLifecycleRecord` | 记录本地生命周期，不冒充 Observability audit。 |

#### 5.10.4 本部分不承担什么

- 不保存 credential、raw body、raw log 或未脱敏 payload。
- 不延长授权，不把本地写入当 owner 成功，不自行生成 cross-domain projection。
- 清理失败时不能继续展示无法验证的新鲜度或可见性的敏感材料。

#### 5.10.5 与其他部分的接缝

接收 reducer、draft、recovery 和 platform storage 能力；向路由、页面和平台恢复提供最小安全材料；在 revoke/logout/expiry/scope change 时接受清理指令。

### 5.11 总体边界与后续展开门禁

- 7 个主要组成部分是 Chat 的业务体验结构，不是 7 个新的领域 owner。
- §6 必须从本章对象发现线索筛选对象；§7、§8、§9 只能使用本章和 §6 已出现的主语。
- `L0-sdk`、平台宿主和低敏诊断是边界接缝；它们不成为 Chat 的 truth 或跨域服务。
- 如果详细设计需要新增主要组成部分或改变上述主语，必须先回到本概要设计修正。

| 跨部分检查 | 当前结构结论 |
|---|---|
| capability与候选来源 | 七部分已逐一复核；新项目/流程/关系/目录候选来自本章对应capability |
| 重复对象与owner冲突 | SelectionState负责通用/对话选择，ProjectNavigationState负责项目下钻；ClientConsumptionContext隔离当前消费，ResumeContext保存恢复线索；无Process/治理/关系实体 |
| SDK/平台/存储接缝 | adapter只经正式SDK，renderer只读，局部store仅安全投影；不以平台/配置反馈改变owner |
| 后续展开位置 | 新独立对象§6、query/局部入口§7、独立流§8、局部轴§9；完整coordinator/adapter/策略实现留03 |
| 未闭合能力 | 章节结构审查完成；CHAT-UP001～009等仍blocked，不表示可集成或readiness |

### 6.2 对象正式化原则

- 本章对象均属于 Chat-local state、safe projection、reference、policy、context 或 local history；外部 owner truth 不在 Chat 内复制。
- 字段类型使用概要层类型名，不复制上游 DTO、wire schema、数据库列或序列化定义。
- 状态集合表达客户端语义；UI 文案、transport 状态和 owner 生命周期不混成同一状态轴。
- 成员函数和工厂函数只写参数类型骨架与责任，不写完整签名、实现和调用链。
- `ResumeContext` 是变化与恢复的 canonical Chat-local 上下文；`LocalProjectionEntry` 只能保存其可持久化安全子集。

### 6.35 接口边界类型说明

下列名称在 §7～§8 作为输入、输出或 envelope 的概要类型出现，但不作为 Chat 关键对象独立建模。它们代表 SDK/owner/platform 提供的安全边界材料或接口结果；完整字段和序列化形式留给上游合同与 03。

| 边界类型类别 | 代表名称 | 不独立成 Chat 关键对象的原因 |
|---|---|---|
| actor、命令和查询输入 | `ActorContext`、`CommandMetadata`、`IdempotencyKey`、`QueryMetadata`、`PageRequest`、`SummaryRequest`、`ProbeMetadata` | 由 SDK/owner 约束的调用语境或请求元数据，不由 Chat 持有领域生命周期。 |
| owner/安全引用 | `EntryReference`、`GateRef`、`IntentRef`、`ResumeContextRef`、`ChangeSourceRef`、`GapRef`、`RevisionMarker`、`ContextReference` | 只回链正式来源或消费范围，不能转化为 shadow entity。 |
| safe view/result | `EntryViewModel`、`PageSafeView`、`TurnSafeView`、`SubmissionReceiptView`、`PendingResultView`、`CommandResultView`、`FormalProbeResult`、`PreviewResultView`、`PreviewUnavailableView`、`ResumeResultView` | 是 adapter/result 的安全材料，实际权威和完整结构归 SDK/owner；Chat 只映射到已定义的 local object。 |

## 7. API / 接口骨架

> 校准来源：
> - `design-calibration/02_hld_step_07_api_outline.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“接口分类”“Command API 骨架”“Query API 骨架”“Inbound Event Consumer 骨架”“Outbound Event 骨架”和“Operations Job 骨架”小节，了解每类接口的读写性质和边界。

### 7.1 接口分类

```text
Command API
  由 Chat-local intent 进入 L0-sdk 正式 command seam；可能产生 owner 副作用，必须有正式结果门控。

Query API
  读取 owner safe view/ref/summary/preview 或 Chat-local projection；不改写真相。

Inbound Event Consumer
  消费 L0-sdk formal change/result/resume/lifecycle envelope；按来源、EventId 和版本/水位处理。

Outbound Event
  只允许低敏客户端诊断/支持 handoff；不产生 owner truth event。

Operations Job
  执行 resume、requery、unknown probe、stale refresh、local persist/evict 和重启恢复；不修复 owner truth。
```

### 7.2 Command API 骨架

以下均是Chat-local用例入口，SDK映射仍待合同确认；不是公开SDK方法或网络API。局部导航与请求代次操作独立于owner业务command。

| API | 输入骨架 | 输出骨架 | 主要处理 | 写入结果 |
|---|---|---|---|---|
| `SubmitConversationIntent` | `ConversationIntent` + `ActorContext` + `CommandMetadata` + `IdempotencyKey` | `SubmissionReceiptView` / `PendingResultView` / `UnknownEffectView` | 检查 `AccessPosture`、创建 `CommandAttemptState`、经 SDK command seam 发起 | 只写 Chat-local attempt；Conversation/Turn 结果由正式 receipt/result/change 确认。 |
| `SubmitGovernanceIntent` | `GovernanceIntent` + `ActorContext` + `CommandMetadata` + `IdempotencyKey` + `GateRef` | `SubmissionReceiptView` / `PendingResultView` / `CommandResultView` / `UnknownEffectView` | 检查 GateCard 可操作姿态并提交受控治理意图 | 不写 Decision，不本地批准/拒绝。 |
| `RequestSafePreview` | `PreviewRequest` + `ActorContext` + `CommandMetadata`（若上游定义为受控 request） | `PreviewResultView` / `PreviewUnavailableView` | 通过正式 reference/preview seam 获取安全预览 | 只更新 `PreviewReference`/snapshot，不保存正文。 |
| `AcknowledgeLocalRecoveryAction` | `RecoveryAction` + `RouteContext` + `CommandMetadata` | `LocalRecoveryResult` | 记录用户选择 resume/requery/clear/wait | 只写 Chat-local recovery context。 |

Command 共通边界：`SubmissionReceiptView` 只表示正式边界接收或关联；`UnknownEffectView` 只能进入 query/probe/wait/user decision；`RequestSafePreview` 的最终 Query/Command 分类由上游合同确认。

| `LoadStageProcessFlow` | `OwnerReference(stage) + RevisionMarker + ActorContext + ClientConsumptionContext` | `ProcessFlowViewModel` | ProcessDrilldownCoordinator → SDK正式阶段拓扑 | 重验父层关系/版本，不按图坐标生成阶段 |
| `LoadProcessNodeDetail` | `OwnerReference(node) + RevisionMarker + ActorContext + ClientConsumptionContext` | `ProcessNodeDetailViewModel` | ProcessDrilldownCoordinator → 正式节点关联及目标owner query | 每section独立访问/版本；缺关系不按名称关联 |
| `LoadProjectConversationLinks` | `OwnerReference(project/conversation) + ActorContext + QueryMetadata + ClientConsumptionContext` | `ProjectConversationLinkViewModel` | ProjectContextCoordinator → SDK正式关系读取能力 | CHAT-UP009；关系和各目标access分别验证，解绑/撤销清入口 |
| `LoadCompanyDirectory` | `ActorContext + LocalDirectorySearchState + PageRequest + ClientConsumptionContext` | `CompanyDirectoryViewModel` | DirectoryCoordinator → SDK正式目录provider | CHAT-UP009；人类/AI覆盖/分页需确认，不合并成员集合 |
| `LoadMemberContext` | `OwnerReference(person/project/conversation/member) + ActorContext + QueryMetadata + ClientConsumptionContext` | `SafeMaterialSnapshot[] + AccessPosture` | DirectoryCoordinator → 各正式owner独立摘要/对话入口 | 目录/ProjectMember/Participant/在场分源；DM须Conversation正式能力 |

涉及业务读取一律携带正式ActorContext及当前ClientConsumptionContext；本地LoadDraft/LoadLocalProjection不调用owner，但恢复/展示前仍须验证当前actor/scope。Query读取不写owner；响应应用到局部store属于客户端投影步骤。所有新安全边界view名称只是required capability，未确认为SDK DTO。

### 7.7 接口边界与反查

- Command 必须显式判断 `ActorContext`、`CommandMetadata` 和幂等关联候选；精确必填关系由 SDK/owner 合同决定。
- Query 只读 safe view/ref/summary/preview 或 local projection；不通过空结果推断不存在。
- Event Consumer 必须有 event identity、来源和版本/水位语境；具体 envelope/schema 留给上游合同。
- Operations 不执行 owner workflow、不修复 owner truth；本地 persist/evict 只改变 Chat-local projection。
- 每个 P0 Command、状态改写 Consumer 和一致性/恢复 Job 均在 §8 有独立处理流。

### 7.8 局部导航入口与消费隔离

| 局部用例 | 输入骨架 | 输出/局部写入 | 边界 |
|---|---|---|---|
| `NavigateProjectContext` | `ProjectNavigationState` + `OwnerReference` + `RouteContext` + `ClientConsumptionContext` | 新navigation/消费代次，待验证入口 | tab/整体/阶段/节点/往返只改Chat-local；正式关系及目标访问另验 |
| `UpdateDirectorySearch` | `LocalDirectorySearchState` + `ClientConsumptionContext` | 新搜索状态/请求代次 | 防迟到页覆盖新搜索，不扩大目录覆盖或访问 |

这两项由coordinator接入用户动作，不作为owner Command API，不需要owner幂等键；本地代次仅隔离并发消费。Command保留SDK正式幂等关联，EventId/revision/resume按各source正式合同，二者不可互换。

### 7.9 归属与跨接口停审

| 部分 | 正式入口/对象承接 | 结构审查结论 |
|---|---|---|
| 协作体验语境 | 新增八Query、两个局部入口；ConversationSurface/ProjectDetail/ProcessFlow/NodeDetail/Link/Directory VM | Query和导航分立，无流程或绑定写入 |
| 受控协作意图 | Submit*Intent、LoadIntentCapability、ProbeCommandAttempt → Draft/Attempt/ResultGate | ordinary receipt与transport ACK不能confirmed |
| 安全语境与导航 | ResolveEntryAccess、ConsumeVisibilityChange → Route/Access/VisibilityGuard/ClientConsumptionContext | 项目/群聊/节点/人员各自访问，旧消费者失效 |
| 变化与恢复连续性 | ConsumeFormalChange/ReceiptOrResult/ResumeResult、Resume/Requery/ResolveUnknown → Continuity/Resume/Acceptance/Recovery | source-local幂等与gap，缺恢复合同blocked |
| 平台体验与可访问性 | ProbePlatformCapability/LoadAccessibilityContext/ConsumeShellLifecycle → Platform/Accessibility/Announcement | 图/列表共享状态，不赋权 |
| owner-safe材料镜像 | LoadOwnerSummary/LoadArtifactPreview/ConsumeMaterialRevisionChange → Snapshot/OwnerRef/Provenance/Freshness/Preview | source分立；统计/commit/test不成为验收 |
| 本地展示与恢复投影 | LoadLocalProjection/LoadDraft/Persist/Evict → LocalProjection/Lifecycle/SafetyGuard | 仅局部读写，清理不取消owner命令 |

七部分独立归属审查完成；API/对象名称可反查§5/6，无新owner命令或跨source原子结果；正式消费面仍见CHAT-UP001～009。

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“通用处理流骨架”、各关键接口处理流、“处理流覆盖清单”和“跨处理流一致性审计”小节，了解每条流的边界、禁止事项和 03 承接点。

### 8.1 通用 Query 读路径

```text
Query API
  │
  ▼
Inbound / Query Adapter
  - 读取 ActorContext（如涉及 owner visibility）
  - 调用正式 SDK query/ref/preview 能力
  │
  ▼
Application Service
  - 建立 RouteContext / AccessPosture
  - 建立当前 ClientConsumptionContext，读取前后核对actor/scope/project/target/source/请求代次
  - 调用 VisibilityGuard.evaluate_material(SafeMaterialSnapshot safe_material, RouteContext route_context)
  │
  ▼
SafeMaterialSnapshot / Projection / ViewModel
  - 绑定 ProvenanceMetadata、FreshnessMarker、DisclosurePosture
  - 组合页面或预览模型
  │
  ▼
Result / Local Projection
  - 返回安全 view model
  - 响应应用由局部store/reducer承接；持久化单独进入PersistLocalProjection，不写owner
```

关键设计点：Query 只读取安全材料或 Chat-local projection；visibility、scope、来源或 freshness 无法验证时显式降级；空结果不等于不存在；详细设计继续展开 response mapping、分页、错误映射和持久化事务边界。

### 8.2 通用 Command 读写路径

```text
Command API
  │
  ▼
Inbound / UserIntentCoordinator
  - 接收 DraftState、ActorContext、CommandMetadata、IdempotencyKey
  - 建立 CommandAttemptState
  │
  ▼
Application Service
  - 检查 AccessPosture
  - 调用 SdkCommandAdapter
  - 等待 submission/receipt/result，不把 transport ACK 映射为 confirmed
  │
  ▼
CommandAttemptState / CommandResultGate / ClientStateStore
  - 记录 submitted/pending/unknown
  - 后续 receipt/result/change 进入正式门控
  │
  ▼
SubmissionReceiptView / IntentFeedbackViewModel / Formal Result Consumer
```

关键设计点：Chat 只创建 local intent/attempt，不写 owner truth；`CommandResultGate.evaluate(CommandAttemptState attempt, FormalResultMaterial result_material)` 是概要层唯一结果门控入口；unknown 不自动重放。

```text
  ▼
```

### 8.4 `SubmitConversationIntent`

#### `SubmitConversationIntent` 处理流

```text
SubmitConversationIntent Command
  │
  ▼

  - 生成 CommandAttemptState
  │
  ▼
```

#### `SubmitGovernanceIntent` 处理流

```text
SubmitGovernanceIntent Command
  │
  ▼
```

### 8.6 `ConsumeFormalChange`

#### `ConsumeFormalChange` 处理流

```text
ConsumeFormalChange Event
  │
  ▼
Inbound / SdkChangeAdapter
  - 接收 EventEnvelope event_envelope、EventId event_id、ChangeSourceRef source_ref
  - 读取 RevisionMarker revision_marker 和 scope/visibility context
  │
  ▼
Application Service / ChangeReducer
  - 调用 ChangeAcceptanceRecord.evaluate(FormalChangeView change_view, ContinuityState continuity_state, ClientConsumptionContext context)
  - 先核对当前actor/scope/project/target/source/代次，再按本来源正式合同去重/版本检查
  - 检查 duplicate/out_of_order/gap/restricted
  │
  ▼
ChangeAcceptanceRecord / SafeMaterialSnapshot / ContinuityState
  - accepted 才更新 local projection/view model
  - gap/expired/revoked 转入 ResumeContext 或清理
  │
  ▼
ConversationSurfaceViewModel / IntentFeedbackViewModel / RecoveryViewModel
```

关键设计点：只消费SDK正式change；同source/scope的版本可比性由合同决定，不按到达时间或跨owner水位排序。旧代次响应不写当前store，正式撤销仍按其受影响scope执行安全裁剪。Process拓扑变化先失效旧stage/node选择；状态版本不兼容则partial/stale并重查，不补图或计算汇聚。duplicate不重复应用，gap不推进fresh；缺SDK surface blocked。

### 8.7 `ConsumeCommandReceiptOrResult`

#### `ConsumeCommandReceiptOrResult` 处理流

```text
ConsumeCommandReceiptOrResult Event
  │
  ▼
Inbound / SdkChangeAdapter
  - 接收 EventEnvelope event_envelope、EventId event_id、IntentRef intent_ref
  - 读取 ResultAuthority result_authority 和安全结果材料
  │
  ▼
Application Service / UserIntentCoordinator
  - 找到 CommandAttemptState
  - 调用 CommandResultGate.evaluate(CommandAttemptState attempt, FormalResultMaterial result_material)
  │
  ▼
CommandAttemptState / IntentFeedbackViewModel / ClientStateStore
  - confirmed/rejected/failed/unknown 显式更新
  - Draft 清理依据正式结果，不依据 ACK
  │
  ▼
IntentFeedbackViewModel / ConversationSurfaceViewModel / RecoveryViewModel
```

关键设计点：只有具业务确认含义的receipt或正式result/change支持confirmed；接收/排队receipt只submitted/pending。按actor/scope/intent及正式关联核对结果，切换页面不丢失unknown但不可污染当前目标；重复结果幂等、旧结果不得倒退终态。连接恢复不确认unknown；不产生owner audit/evidence。

### 8.8 `ResumeChangeContext` / `RequeryAfterGap`

#### `ResumeChangeContext` / `RequeryAfterGap` 处理流

```text
ResumeChangeContext / RequeryAfterGap Job
  │
  ▼
Operations / ResumeCoordinator
  - 接收 ResumeContext resume_context、ContinuityState continuity_state
  - 判断 resume/requery capability、visibility 和 gap posture
  │
  ▼
Application Service / RecoveryCoordinator
  - 调用 SDK formal resume 或 requery
  │
  ▼
ContinuityState / ChangeAcceptanceRecord / SafeMaterialSnapshot
  - 应用 formal result
  - ContinuityPhase收敛fresh/stale/restricted/blocked/needs_action；FreshnessState可为partial
  │
  ▼
RecoveryViewModel / ConversationSurfaceViewModel / ClientStateStore
```

关键设计点：resume/requery只恢复受影响source，重新建立当前消费代次并验证actor/scope/project/目标及关系；按各source cursor/coverage独立收口，不跨owner原子恢复。不重放原command，不从Work/Runtime补Process图；缺合同blocked。重查仍须拒绝迟到响应，版本变化使旧节点选择失效。

#### `EvictLocalMaterial` 处理流

```text

  │

  - evicting → restricted/cleared
```

## 9. 状态定义与状态流转

> 校准来源：
> - `design-calibration/02_hld_step_09_state_machine.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“状态定义表”“状态流转图”“状态传播关系”“允许的核心迁移”“禁止的核心迁移”和“跨状态一致性审计”小节，了解 Chat-local 多轴状态如何与正式结果/变化边界分离。

`L5-chat` 没有 Conversation、Governance、Artifact、Workspace、Runtime 或其他 owner 的独立业务状态机。它维护互相隔离的客户端状态轴；owner 业务状态由正式 owner 通过 SDK 结果/change 提供。

### 9.1 状态定义表

#### 9.1.1 `CommandResultPosture`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `draft` | 只有本地意图/草稿 | 受限 | 不代表已发送、审批或写入 owner。 |
| `submitted` | SDK 正式接收或已发起 attempt | 是（等待结果） | 不代表 owner committed。 |
| `pending` | owner/SDK 明确仍在处理 | 是（等待结果） | 不能当 confirmed。 |
| `confirmed` | 正式result/change或具业务确认含义的receipt满足门控 | 是 | 普通接收/排队receipt不足；只由CommandResultGate允许。 |
| `rejected` | 正式结果明确拒绝 | 受限 | 显示安全原因，不自动重试。 |
| `failed` | 正式失败且副作用语义可解释 | 受限 | 是否重试需 capability/guard。 |
| `unknown` | 无法判断副作用是否成立 | 否（需查询/决定） | 禁止自动重放。 |

#### 9.1.2 `AccessPosture`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `available` | 正式语境允许安全查看/按能力操作 | 是 | 每个 command 仍需 capability。 |
| `read_only` | 可读但不能执行当前操作 | 受限 | 不推断对象不存在。 |
| `restricted` | 只能展示有限材料/原因 | 受限 | 保护 scope/visibility。 |
| `unavailable` | 能力或依赖暂不可用 | 否 | 可保留安全入口/恢复提示。 |
| `blocked` | 继续会越过安全/合同边界 | 否 | 必须 fail-closed。 |
| `hidden` | 正式结果要求不暴露入口/材料 | 否 | 清理或遮蔽相关材料。 |

#### 9.1.3 `FreshnessState`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `fresh` | 在已知来源水位内可解释 | 是 | 不代表业务动作完成。 |
| `stale` | 可能落后于正式来源 | 受限 | 需 requery/resume。 |
| `partial` | 只有部分范围/字段/变化 | 受限 | 不当完整历史。 |
| `unknown` | 无法判断来源水位 | 否/受限 | 需正式查询或等待。 |
| `expired` | 超过可安全使用范围 | 否 | 清理或重新获取。 |

#### 9.1.4 `DisclosurePosture`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `visible` | 正式结果允许展示安全材料 | 是 | 仍受 freshness/redaction 约束。 |
| `redacted` | 只能展示脱敏/最小摘要 | 受限 | 不暴露原文/隐藏字段。 |
| `restricted` | scope/policy 只允许受限入口 | 受限 | 不从缓存补全。 |
| `unavailable` | 没有安全可用材料 | 否/受限 | 显示安全原因或恢复提示。 |
| `cleared` | 因撤销/登出/过期已清理 | 否 | 旧材料不得继续渲染。 |

#### 9.1.5 `ContinuityPhase`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `fresh` | formal change/resume 水位连续 | 是 | 只代表客户端来源连续性。 |
| `stale` | 尚未确认最新变化 | 受限 | 触发 resume/requery。 |
| `gap` | 发现变化缺口 | 否/受限 | 暂停把后续变化当连续。 |
| `reconnecting` | SDK/宿主连接恢复中 | 否/受限 | 不代表业务恢复。 |
| `resuming` | 正在执行 formal resume/requery | 受限 | 等待正式结果。 |
| `restricted` | scope/visibility 变化要求收紧 | 受限 | 与 Access/Disclosure 联动。 |
| `blocked` | 缺少安全/合同能力 | 否 | 不私自 fallback。 |
| `needs_action` | 需要用户/支持角色决定 | 否/受限 | 例如 unknown 或宿主权限。 |

#### 9.1.6 `DraftState`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `empty` | 没有本地草稿 | 是 | 等待输入。 |
| `editing` | 用户正在编辑 | 是 | 只影响本地。 |
| `locally_valid` | 通过本地可检查条件 | 是（可创建 intent） | 不代表 owner 接受。 |
| `invalid` | 本地可解释地不能提交 | 否/受限 | 不替代 owner validation。 |
| `submitting` | 已关联提交 attempt | 受限 | 由命令结果轴继续收敛。 |
| `restored` | 从本地安全存储恢复 | 受限 | 需重新验证语境。 |
| `cleared` | 已清除 | 是 | 不代表 owner 取消或失败。 |

#### 9.1.7 `LocalProjectionState`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `absent` | 没有本地材料 | 是（走正式 query） | 不推断 owner 不存在。 |
| `cached` | 有来源绑定的安全缓存 | 受限 | 需验证 freshness/visibility。 |
| `restored` | 已恢复到页面 | 受限 | 不等于 fresh/current。 |
| `stale` | 来源可能过期 | 受限 | 需 requery/resume。 |
| `restricted` | 只能显示受限材料 | 受限 | 保护 scope/visibility。 |
| `evicting` | 正在清理 | 否/受限 | 不继续渲染受影响材料。 |
| `cleared` | 已删除 | 是（需正式 query） | 不代表 owner 删除。 |

#### 9.1.8 `CapabilityAvailability`

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `available` | 宿主能力可用 | 是 | 不改变业务授权。 |
| `restricted` | 受宿主权限/策略限制 | 受限 | 可提供等价路径或提示。 |
| `unavailable` | 宿主不提供 | 否/受限 | shared core 保持语义。 |
| `needs_action` | 需要用户完成宿主动作 | 否/受限 | 不当业务结果。 |
| `unknown` | 无法确定能力 | 否/受限 | fail-closed。 |

#### 9.1.9 新增局部状态轴

| 对象/字段轴 | 状态 | 含义/正常主线 | 触发及边界 |
|---|---|---|---|
| 六新增VM的`PageLoadPosture` | `loading` | 受限，等待正式安全读取 | 对应Load* Query；不是owner processing |
| 六新增VM的`PageLoadPosture` | `ready` | 是，当前获准材料可展示 | 当前context匹配且safe来源可解释，不代表项目/流程完成 |
| 六新增VM的`PageLoadPosture` | `partial/stale` | 受限，部分来源缺失/版本不兼容 | 每section独立标记；不产生跨owner原子fresh |
| 六新增VM的`PageLoadPosture` | `blocked/unavailable` | 否，缺合同/无法安全取得材料 | 不推not-found；访问撤销按Access/Disclosure先裁剪 |
| `ProjectNavigationState.selection_posture` | `empty/selected` | 是，无选择/有局部目标 | NavigateProjectContext，不推进Activity或批准 |
| `ProjectNavigationState.selection_posture` | `stale/cleared` | 受限/否，旧选择待验或已清理 | 父拓扑变化/解绑/撤销/登出；不得恢复未经授权ref |
| `ClientConsumptionContext.context_posture` | `active` | 受限，当前局部代次可消费 | 还须正式Access/visibility及source检查，非授权 |
| `ClientConsumptionContext.context_posture` | `invalidated/cleared` | 否，旧消费者禁止应用 | 切project/node/search/scope及撤销；active恢复须新建上下文 |
| `CommandAttemptState.optimistic_material` | `optimistic` | 受限，可撤销本地占位 | 与submitted/pending并存，不放入正式Turn/Gate事实 |
| `CommandAttemptState.optimistic_material` | `confirmed-presentation/failed-presentation/removed` | 本地表现 | 由正式结果轴驱动替换/恢复草稿/移除；表现不是第二业务终态 |

上述最后一轴是语义表现标签，完整局部字段枚举留03；不要求将连字符标签编译为SDK/owner状态。

### 9.4 允许的核心迁移

- `DraftState.empty -> editing -> locally_valid -> submitting`。
- `CommandResultPosture.draft -> submitted -> pending`。
- `pending -> confirmed` 只由 `CommandResultGate` 接受正式 owner result/change。
- `submitted -> confirmed/rejected/failed/unknown` 允许立即正式结果或安全不确定性；无需人为先pending。业务确认receipt须正式合同明确，不接受接收/排队receipt。
- `pending -> rejected/failed/unknown` 只由正式 authority 或安全不确定性触发。
- `unknown -> confirmed/rejected` 只由正式 probe/query/result/change 收敛；未收敛保持 unknown。
- `unknown -> failed` 仅正式探测证明可解释的失败及副作用边界；无正式证明仍unknown，不自动创建新attempt。
- `failed -> 新draft/attempt` 只由用户选择、重新验证正式capability及SDK幂等/重试合同；原attempt保留，不由网络重连/缓存/配置自动重发。
- `fresh -> stale/gap/reconnecting` 由正式缺口、生命周期或 freshness 失效触发；`stale/gap/reconnecting -> resuming` 由恢复作业触发。
- `ContinuityPhase.resuming -> fresh/stale/restricted/blocked/needs_action` 由正式结果/guard触发；部分覆盖对应FreshnessState.partial。
- `visible -> redacted/restricted/unavailable/cleared` 由 visibility/scope/revocation/expiry 触发。
- `cached -> restored -> stale`，以及 `cached/restored/stale/restricted -> evicting -> cleared`。
- `CapabilityAvailability.unknown -> available/restricted/unavailable/needs_action` 由平台 capability probe 触发。

### 9.5 禁止的核心迁移

- 仅凭按钮、表单、transport acknowledgement、toast、通知或连接恢复将命令状态变为 `confirmed`。
- 仅凭重试按钮、缓存命中、socket reconnect 或页面刷新将 `unknown` 变为 `submitted/confirmed`。
- 无正式来源水位或 resume/requery 结果将 `reconnecting/resuming` 变为 `fresh`。
- 仅凭本地 cache、墙上时间或 transport connected 将 `stale/unknown/expired` 变为 `fresh`。
- 无新的正式 visibility/scope 结果将 `restricted/cleared` 变为 `visible`。
- 任何 Chat-local 状态直接迁移为 Conversation/Turn/Gate/Decision/Artifact/Workspace/Runtime/Observability owner 状态。
- 任何迁移绕过 `VisibilityGuard`、`CommandResultGate`、`ChangeAcceptanceRecord` 或 `PersistenceSafetyGuard`。
- 分支颜色/WorkItem完成/Runtime outcome迁移为Process join确认或Governance批准；拓扑ready不代表实例运行完成。
- 关系/目录可见迁移为项目/群聊/DM权限；旧代次query/event使cleared材料重新visible。

### 9.6 状态归属与反查

| 主要组成部分 | 状态轴/对象 | 触发接口或流 | 不能混用 |
|---|---|---|---|
| 协作体验语境 | `SelectionState`、Turn presentation、页面 freshness | `LoadConversationSurface`、formal change | 不等于 Turn lifecycle、attention 或确认。 |
| 协作体验语境（项目/流程/目录） | `PageLoadPosture`、`ProjectNavigationState` | LoadProject*/LoadStage*/LoadProcessNodeDetail/LoadCompanyDirectory/LoadMemberContext/NavigateProjectContext/UpdateDirectorySearch | 不等于Process/Gateway/Gate状态、正式关系或成员资格。 |
| 受控协作意图 | `DraftState`、`CommandResultPosture` | `Submit*Intent`、receipt/result、unknown probe | 不等于 transport、Decision/Turn result。 |
| 安全语境与导航 | `AccessPosture`、`DisclosurePosture` | entry access、visibility change、evict | 不等于 owner authorization。 |
| 安全语境与导航（消费隔离） | `ClientConsumptionContext` | Query/导航/search/ConsumeVisibilityChange/清理 | 本地代次不替代owner版本/SDK幂等键。 |
| 变化与恢复连续性 | `ContinuityPhase`、`FreshnessState` | formal change、resume/requery | 不等于 bus delivery 或 reconnect success。 |
| 平台与可访问性 | `CapabilityAvailability`、`AccessibilityState` | platform probe、shell lifecycle | 不等于 owner result。 |
| 本地投影 | `LocalProjectionState` | restore、persist、evict | 不等于 current truth、授权或 evidence。 |

### 9.7 局部选择与消费语境迁移

```text
<empty selection> -- NavigateProjectContext --> <selected>
<selected> -- parent revision / unlink / access change --> <stale / cleared>
<stale> -- formal relationship + target revalidation --> <selected>

<active consumption> -- route/search/scope/revoke --> <invalidated> -- cleanup --> <cleared>
<invalidated / cleared> -- fresh request + formal revalidation --> <new active context>

<loading VM> -- current safe response --> <ready / partial / stale>
<loading / ready> -- missing contract / invalid access --> <blocked / unavailable>
```

- 选择、VM加载和消费语境为三个局部轴，active或selected不证明访问。
- 迟到响应不能使旧context恢复active；新请求生成新代次。
- 页面清理由Access/Disclosure轴优先控制，不等待VM加载或持久删除。

### 9.8 状态停审

七部分分别核对：协作新增VM/选择轴，意图保持结果与optimistic分立，安全新增消费轴，恢复按source-local水位，平台/AT只表达状态，材料按独立freshness/access，本地投影不延长授权。触发均回指§7/8；同名fresh/ready/confirmed有不同对象轴，不能替换或汇总。没有Process/Work/Governance业务状态机；结构审查完成，合同仍blocked。

| 跨端能力差异 | 平台体验与可访问性、共享语义 core | 保持 shared state semantics；宿主差异只映射 capability posture。 |

### 11.2 禁止配置化边界表

| 禁止配置化边界 | 原因 | 若需改变应回到哪里 |
|---|---|---|
| Conversation/Turn/Participant/Project/Member/ProcessInstance/Activity/Token/Gateway/Gate/Decision/Artifact/Workspace/Runtime/Observability truth owner | 配置不能创建第二truth或转移生命周期/授权。 | 对应owner与01 |
| `VisibilityGuard` fail-closed 规则 | 未知 visibility 不能被配置成 visible/available。 | Identity/Governance/SDK 合同与 03 |
| `CommandResultGate` formal authority 要求 | ACK/cache/button/notification 不能变 confirmed。 | SDK/owner command contract 与 03 |
| unknown 副作用禁止自动重放 | 配置不能绕过副作用不确定性。 | owner probe/query contract 与 03 |
| formal change/resume 来源、幂等和 gap 语义 | 内部 bus/offset/arrival time 不能变事实。 | SDK/Conversation owner 与 03 |
| body-free、redaction、credential/secret/raw body 禁存 | 安全和最小披露是硬边界。 | SDK/owner security contract 与 04 |
| logout/revoke/expiry/scope-change 清理 | 配置不能延长授权或恢复失效材料。 | Identity/SDK 与 04 |
| 跨端业务状态、结果和权限语义 | platform profile 不得造成语义分叉。 | `01-架构设计.md` 与后续平台设计 |

| 本地 projection 反写 owner、diagnostic 变 audit/evidence | 保护单向消费和证据权威。 | `01-架构设计.md`、L4-observability |
| 分层流程/并行汇聚与Governance Gate分立 | 不以图库、feature flag或分支颜色生成join/批准/项目完成。 | Process/Work/Governance及01 ADR009 |
| 绑定关系、公司目录provider/覆盖及成员集合分界 | 配置不能创建正式关联/人员或继承目标权限。 | 正式关系owner/目录provider、SDK与01 ADR010 |
| source-local版本与ClientConsumptionContext检查 | 不可关闭actor/scope/project/target/source/请求代次/撤销隔离；无跨source原子fresh。 | SDK/owner合同及03 |
| 原型/fixture与生产材料隔离 | 配置不得将演示图/名单/测试/commit摘要写为业务或验收truth。 | 03～07证据边界 |

### 11.3 配置读取与边界说明

配置应由运行装配层读取、校验并以受限 profile 注入 adapter、store、job、platform 和 presentation seam；核心语义对象不直接读取原始配置。配置缺失、冲突或不兼容时，相关能力进入 `blocked`、`unavailable`、`needs-action` 或安全默认姿态，不能自动放宽权限、结果或持有面。

本章只识别配置影响轮廓，不定义配置项清单、JSON/YAML/TOML、默认值、环境变量、密钥名称、部署挂载、`RuntimeConfig` 字段全集、`ConfigError` 枚举全集或 adapter constructor 完整参数。03 收口配置实现契约，04 说明填写、校验、覆盖、敏感值引用和平台使用。

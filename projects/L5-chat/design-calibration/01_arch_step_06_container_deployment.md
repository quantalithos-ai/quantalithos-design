## 2. SOP 问题回答

### 2.1 这个仓运行时有哪些正式容器或运行单元？

`L5-chat` 由三个本仓运行承载单元构成：

1. `客户端同步入口单元`：承接平台输入、页面呈现、导航和同步的用户交互。
2. `客户端连续性承接单元`：承接正式变化/恢复输入、后台连续性处理、重连、缺口和恢复提示。
3. `本地受限状态承载`：保存 Chat-owned 的草稿、选择、恢复上下文和带来源语境的展示材料。

这三个单元形成一个安装在用户设备上的客户端运行结构。同步入口和连续性承接在职责上必须分开，但 V1 可以在同一客户端部署中共同承载；本地受限状态是独立的持久化边界，不是共享服务或业务数据库。

### 2.2 同步入口在哪里？

同步入口是 `客户端同步入口单元`。平台 shell 将用户输入、窗口/页面生命周期和宿主能力交给它；正式业务材料和受控意图也只能经 `L0-sdk` 的正式运行时对接边界进入或离开。该单元负责呈现当前 Chat-local 语境，不直接接入 owner 私有 API、内部 bus 或共享数据库。

### 2.3 异步消费者或后台任务在哪里？

异步变化、恢复和局部补偿由 `客户端连续性承接单元` 承接。它只处理 SDK 暴露的正式变化/恢复语义以及客户端本地恢复工作，不成为服务端 worker、内部 bus consumer 或 owner repair worker。它可以与同步入口同部署、同设备运行；是否获得后台执行机会由平台宿主能力决定，不能因此改变业务结果语义。

### 2.4 数据库 / 缓存 / 总线如何接入？

- Chat 只依赖 `本地受限状态承载`，用于草稿、选择、恢复上下文和受限展示材料；它不是共享数据库，也不承载 owner truth。
- 展示缓存是本地受限状态的一种承载形态，必须带来源、可见性、版本/水位和新鲜度语境；缓存失效、撤销或 scope 改变时收紧或清理。
- 业务读取、受控意图、正式变化和恢复只经 `L0-sdk` 正式运行时边界；Chat 不直接订阅内部 bus，不使用 broker/topic/offset，不自建共享缓存。

### 2.5 哪些运行单元必须分开部署，哪些可以同部署？

- `客户端同步入口单元` 与 `客户端连续性承接单元` 必须在职责和状态语义上分开，但 V1 可以同部署在一个客户端包或宿主运行中；同部署不意味着可以合并业务真相。
- `本地受限状态承载` 必须与远端 owner truth 隔离，通常随用户设备或平台存储承载，不单独部署成服务。
- Desktop、Web、Mobile 的 shell 可能分别打包和部署，但都应复用相同的客户端语义边界；平台差异只能体现在宿主能力，不能形成不同的业务状态定义。当前只有 Desktop-first 是 V1 范围。
- `L0-sdk`、各 owner 和低敏诊断对接边界不属于 Chat 的部署单元；它们只能作为正式运行时对接边界出现。

### 2.6 哪些通信关系是正式主路径？

正式主路径只有四类运行关系：平台宿主能力把输入送入同步入口；`L0-sdk` 正式边界把安全业务材料、受控结果和正式变化接入客户端；同步入口与连续性承接单元共同处理用户体验连续性；两个运行单元依赖本地受限状态承载保存和恢复 Chat-local 状态。低敏诊断是可选外部交接，不能成为业务主路径；内部 bus、共享数据库和 owner 私有 API 均不是正式主路径。

## 3. 历史材料与边界污染诊断

| 历史表达 | 污染风险 | 本 Step 处理 |
|---|---|---|
| 将 `Web UI / Desktop / Mobile` 画成多个业务服务 | 把平台打包形态误写成不同业务运行单元。 | 统一为同一客户端语义承载模式，按 shell 适配；V1 只收敛 Desktop-first。 |
| 将 `timeline registry / view / reducer / adapter` 画成容器 | 把代码模块或实现角色误写成运行承载。 | 只保留同步入口、连续性承接和本地受限状态三类运行单元。 |
| 将 SDK、owner 服务、内部 bus 画进 Chat 容器 | 混淆外部对接边界与本仓部署范围。 | SDK/owner/bus 只作为外部运行时边界或明确禁止的路径，不并入 Chat。 |
| 将浏览器缓存或本地数据库写成 Workspace/Conversation 数据库 | 可能形成第二真相、跨设备共享或反写 owner。 | 只保留 Chat-local 受限状态承载，明确不保存 owner truth。 |
| 将 websocket/SSE/AG-UI 或 topic/offset 作为容器间通信 | 把协议候选和内部 bus 细节提前固化。 | 只保留“正式 SDK 运行时对接”和“客户端内部处理/消费”关系。 |
| 将诊断日志/Observability backend 作为同步下游 | 让低敏诊断交接改变业务主路径或成为审计真相。 | 诊断边界可选、低敏、失败隔离，不纳入业务主路径。 |
| 将客户端后台 worker 设计成可独立确认业务成功的服务 | 可能把离线/重连机制误写成 owner 执行者。 | 连续性承接单元只能处理正式变化/恢复和本地提示，不能确认或重放副作用。 |

## 6. 部署关系结论

### 6.1 V1 Desktop-first 部署模型

V1 的正式部署形态是用户设备上的 Desktop 客户端包。客户端同步入口、连续性承接和本地受限状态在同一产品部署范围内协同运行；前两者的职责和状态源必须分开，即使共享宿主生命周期或同一安装包。Chat 不需要独立的服务端业务容器，也不把任何 owner truth 复制成 Chat 服务。

### 6.2 Web 与 Mobile 的承载关系

Web 和 Mobile 后续可以各自拥有平台 shell 与打包边界，但沿用同一同步入口、连续性承接和本地受限状态的语义分工。当前 Web/Mobile 只作为候选承载面，不产生兼容矩阵、后台执行能力或正式 readiness 结论；平台宿主差异通过 `unavailable`、`needs-action`、受限恢复或只读姿态表达。

### 6.3 外部对接边界

`L0-sdk`、Conversation/Identity/Work/Governance/Artifact/Workspace/Member/Runtime 等 owner 以及可选的 Observability 诊断边界均在 Chat 部署范围之外。Chat 只将它们作为正式运行时对接边界消费，不把 owner 服务、内部 bus、共享数据库、外部平台桥接或诊断后端包装进客户端容器。

## 7. 通信方式结论

本节只描述运行承接类别，不固化协议、API、事件 schema 或传输机制。

| 运行关系 | 类型 | 正式主路径 | 失败时的 Chat 姿态 |
|---|---|---|---|
| 平台宿主能力 → 客户端同步入口单元 | 入口 | 用户输入、页面生命周期和宿主能力进入客户端体验。 | 能力缺失时保持页面路径并显示 `unavailable` / `needs-action`；不另造业务结果。 |
| `L0-sdk` 正式业务对接边界 → 客户端同步入口单元 | 入口 | 安全业务材料、受控结果和同步用户意图的正式运行时接入。 | SDK 不可用或合同未闭合时对应入口 `blocked` / `unavailable` / `read-only`；不 fallback 到私有 API。 |
| `L0-sdk` 正式业务对接边界 → 客户端连续性承接单元 | 入口 | 正式变化、恢复提示和可消费的连续性输入进入后台承接。 | cursor/visibility/resume 不明时进入 `stale` / `gap` / `unknown` / `requery`；不猜顺序或直订内部 bus。 |
| 客户端同步入口单元 ↔ 客户端连续性承接单元 | 处理 / 消费 | 页面语境与变化/恢复姿态在客户端运行承载内协同。 | 局部处理失败时隔离受影响语境；不将连接恢复显示为业务确认。 |
| 客户端同步入口单元、连续性承接单元 → 本地受限状态承载 | 承载 / 依赖 | 保存草稿、选择、恢复上下文和受限展示材料。 | 读写失败时保留最小内存状态，显示恢复受限；不把本地写入当 owner 成功。 |
| 客户端运行承载 → 低敏诊断对接边界 | 入口 | 仅在正式能力存在时交接低敏错误类别和关联提示。 | sink 不可用时保持本地安全提示；不影响业务结果、授权或恢复上限。 |

## 8. 运行失效与部署降级

| 失效对象 | 受影响运行单元 | 部署/通信口径 |
|---|---|---|
| Desktop/Web/Mobile shell 宿主能力缺失 | 同步入口、本地状态承载 | 不拆出替代业务服务；沿用共享语义，局部进入 `unavailable` / `needs-action`。 |
| `L0-sdk` 能力未提供或正式合同未闭合 | 同步入口、连续性承接 | 不部署 Chat 私有接入服务；相关入口保持 `blocked` / `read-only` / `deferred`。 |
| formal change/resume 不可消费 | 连续性承接、受影响页面 | 保留安全局部快照和 `stale` / `gap` / `reconnecting` / `unknown`；不直连 bus、不盲重放。 |
| 本地受限状态承载损坏或不可用 | 两个客户端运行单元 | 可降级为内存态或重新查询；不得把缓存缺失补成 owner truth，也不得扩大本地保存面。 |
| scope/visibility 撤销或失效 | 同步入口、连续性承接、本地状态承载 | 收紧/清理受影响展示和恢复材料；不因同部署而继续保留或展示。 |
| 低敏诊断边界不可用 | 可选诊断交接 | 诊断交接降级为本地安全提示；不改变主路径、业务结果或授权。 |

## 10. 正式回填草稿

### 10.1 §7 容器 / 部署架构

`L5-chat` 的运行承载由三个本地运行角色构成：`客户端同步入口单元`、`客户端连续性承接单元` 和 `本地受限状态承载`。同步入口承接平台和用户输入、页面与导航；连续性承接单元承接经正式 SDK 边界提供的变化/恢复输入以及本地连续性处理；本地受限状态承载保存草稿、选择、恢复上下文和带来源/可见性/新鲜度语境的展示材料。同步入口与连续性承接职责必须分开，但 V1 可在同一 Desktop 客户端部署中共同承载；本地受限状态随设备或宿主存储，不构成共享数据库或 owner truth。

`L0-sdk`、正式 owner 和可选低敏诊断能力只作为运行时对接边界存在，不属于 Chat 部署单元。Web/Mobile 后续可以分别打包平台 shell，但沿用同一客户端运行承载语义；当前仅 Desktop-first 进入 V1 范围。Chat 不部署服务端业务 worker、内部 bus consumer、共享缓存或 owner projection 服务。

### 10.2 §7 通信与降级

正式运行关系只有平台宿主能力到同步入口、`L0-sdk` 正式边界到同步/连续性承接、同步入口与连续性承接的客户端处理/消费、本地受限状态承载以及可选低敏诊断交接。协议、传输和事件 schema 后置到 SDK/后续设计；SDK、scope、visibility、cursor、resume 或本地状态不可用时局部进入 `blocked`、`stale`、`gap`、`unknown`、`unavailable` 或 `needs-action`，不以连接恢复、缓存命中或本地写入宣称业务成功。

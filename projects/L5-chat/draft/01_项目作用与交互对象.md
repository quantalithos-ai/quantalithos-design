# 01 · L5-chat 项目作用与交互对象（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源  
> 日期：2026-09-25  
> 输入：已停审的上游 `L0-sdk`、`L1-conversation`、`L1-identity`、`L1-work`、`L1-governance`、`L1-artifact`、`L1-workspace`、`L2-member`、`L2-runtime`、`L4-observability` 正式文档；`L5-chat/design-calibration/` 当前校准材料；旧 Chat README 与旧正式文档仅作 `historical_material`。  
> 本文回答：L5-chat 为什么需要独立存在、它是否包含 UI、它拥有哪些客户端状态、它如何通过 SDK 与其他系统交互，以及哪些能力明确不属于本项目。

本文是需求校准前的项目草稿，不替代后续 `00~07` 正式文档、正式接口契约、实现、测试或集成证据。任何尚无正式 SDK、query、command、event、visibility 或 preview 合同的正向路径，都保持 `pending / blocked / waiting`，不得由本稿补造。

## 1. 一句话定位

`L5-chat` 是基于 `L0-sdk` 的跨平台协作客户端产品边界。V1 以 Desktop 为主目标，使用共享客户端 core 和桌面 shell 承载页面、导航、展示、客户端交互状态、草稿、选择状态、本地展示缓存、离线阅读与恢复体验；Web 保留为共享 UI/开发和后续扩展面，Mobile 暂定以 Capacitor 复用 Web UI，待移动端需求明确后再重新评估。所有平台都通过 SDK 消费各正式 owner 的安全查询、受控命令结果和变化能力。

它回答的是：

> “当前用户在当前可见语境下，哪些协作内容可以安全呈现，用户正在编辑或选择什么，某个操作处于待确认、已确认、失败还是未知状态，以及恢复后应如何继续显示？”

它不回答的是：

> “Conversation、Turn、Participant、Project、Member、Gate、Decision、Artifact、Workspace、Runtime 或 Observability 的正式事实是什么，以及这些事实是否已经由 owner 提交或完成。”

### 1.1 关于 UI 与 SDK 的取舍

本项目应包含 UI 和客户端产品层。V1 先收敛 Desktop 体验：共享产品语义、view model、客户端 store、reducer 和 SDK adapter 由 TypeScript 客户端 core 承载，Tauri 作为桌面 shell 候选；Web shell 作为共享 UI 和开发/预览面保留，Mobile 暂以 Capacitor 作为临时复用方案，不在本 draft 中锁死移动端最终路线。

`L0-sdk` 是正式系统访问边界，负责把 owner 的 query、command、event、认证语境、重试、错误、追踪和脱敏能力以稳定的 typed surface 提供给客户端。Chat 不再建设第二套通用 SDK，也不直接连接服务私有 API、共享数据库或内部 bus。

“只做展示”在本项目中应理解为：Chat 不拥有业务事实和业务规则，但它仍需要负责用户可见的草稿、选择、发送/重试入口、GateCard 受控操作入口、optimistic/confirmed/failed/unknown 展示和跨端恢复。这些是展示层的交互状态，不是 Conversation、Governance 或 Runtime 的业务真相。

## 2. 为什么必须单独存在

| 易混淆对象 | L5-chat 的边界结论 |
|---|---|
| `L0-sdk` | SDK 提供正式访问能力和协议适配；Chat 负责页面、路由、view model、客户端 store、渲染和交互体验，不把 SDK 变成 UI，也不在 Chat 复制 SDK 通用实现。 |
| `L1-conversation` | Conversation、Turn、Participant、scope、visibility、cursor 和对话变化归 conversation；Chat 展示 group/channel/dm/thread，提交消息意图并显示 owner 返回的结果，不创建或确认 Turn。 |
| `L1-identity` | GlobalMember、actor、身份生命周期和身份授权归 identity；Chat 只显示安全身份摘要、成员入口和受限状态，不创建成员或解释权限。 |
| `L1-work` | Project、ProjectMember、WorkItem、Iteration 和项目进度归 work；Chat 只显示项目摘要和协作入口，不推进项目或工作项。 |
| `L1-governance` | Gate、Approval、Decision、Policy、Control 与治理结论归 governance；Chat 显化 GateCard 并提供受控提交入口，但按钮点击、transport ACK 或 UI toast 都不代表批准成功。 |
| `L1-artifact` | Artifact 正文、版本、血缘、Evidence 和 Baseline 归 artifact；Chat 只显示安全引用、摘要、预览入口或不可预览状态，不猜正文和权限。 |
| `L1-workspace` | Workspace read model、attention、跨域 view、freshness 和 cursor 归 workspace；Chat 只消费已正式提供的 safe view/export，不自行拼 Inbox 或跨域投影。 |
| `L2-member` | 容器内成员在场、交互边界、筛选/投递/出站尝试语义归 member；Chat 只显示安全成员状态，不把 UI presence 当作身份或宿主健康真相。 |
| `L2-runtime` | Runtime run、decision、checkpoint、outcome 和 handoff attempt 归 runtime；Chat 只显示安全摘要和 waiting/blocked/failed/unknown 状态，不执行推理或工具。 |
| `L4-observability` | 观测、审计投影、evidence linkage、report handoff 和 no-write 违例归 observability；Chat 只发起低敏诊断意图和显示正式返回的状态，不建设观测后端。 |
| `L6-bridges` | Bridges 负责外部平台映射；Chat 不直接接外部平台事件、正文或账号映射，只接受内部 owner/SDK 已收敛的事实。 |

Chat 单独存在的价值，是把多个真相 owner 提供的安全结果组织成一套可理解、可访问、可恢复的协作入口，同时让不同端共享相同的业务状态语义。没有 Chat，用户仍可能通过各服务 API 看到零散结果，但缺少统一入口、跨端状态、草稿、重连和可访问交互；如果 Chat 越过边界，它又会变成第二个业务真相域。

## 3. 本项目拥有 / 只消费 / 禁止拥有

| 主题 | Chat 可拥有 | 只消费 / 回链 | 禁止拥有 |
|---|---|---|---|
| 页面与导航 | V1 Desktop route、页面生命周期、当前 scope 选择、group/channel/dm/thread 入口、返回与深链语义；Web/Mobile 复用同一产品语义。 | owner 提供的安全 ref、scope、visibility 和入口可用性。 | Conversation、Project、Workspace 或 Member 的生命周期和权限。 |
| 展示模型 | view model、列表/详情组合、来源标签、fresh/stale/partial/unavailable/blocked 状态、可访问文本和焦点关系。 | typed query 结果、safe summary、provenance、version/watermark 和错误分类。 | 复制 owner 正文、重解释 owner 规则或用本地默认值补齐缺失事实。 |
| 客户端 store | 当前路由、选择/展开/焦点、draft、local cache、reducer 状态、重连和恢复上下文。 | SDK session/actor 语境、owner cursor、command receipt、event resume 信息。 | 服务端业务对象、授权缓存、source event delivery truth 或共享数据库状态。 |
| 草稿与发送 | 文本/附件引用草稿、编辑状态、提交前校验提示、发送中与失败后的重试意图。 | conversation command 的 accepted/pending/confirmed/rejected/unknown 结果。 | 直接写 Turn、确认消息已提交、把本地草稿当已发送事实。 |
| GateCard 交互 | 显示 Gate、请求授权的表单/选择、提交前提示、状态标签和结果链接。 | governance 提供的 Gate/Decision/Policy safe view、receipt 和状态事件。 | 批准/拒绝、授权解释、Policy 计算或以按钮点击作为审批成功。 |
| Artifact 交互 | 引用卡片、摘要卡片、预览占位、下载/打开入口、不可见/不可预览提示。 | artifact 的 safe ref、preview result、visibility 和版本语境。 | Artifact 正文、版本链、血缘、Evidence 或 Baseline truth。 |
| 多端体验 | V1 Desktop shell、Web 共享 UI/开发面，以及 Mobile 临时 Capacitor adapter 的平台输入、通知、窗口/深链、离线阅读和恢复姿态。 | SDK 正式变化消费、session、错误、重试和恢复能力。 | 把平台通知 ACK 或 websocket 连接状态当成业务提交结果。 |
| 客户端安全 | 最小化展示、敏感字段遮蔽、缓存失效、受限态和登出后的本地清理策略。 | identity/governance/SDK 的正式可见性和脱敏结论。 | 本地 allowlist、权限推断、credential 签发、审计后端或安全策略真相。 |

## 4. 交互对象总览（候选）

```text
                          +-------------------------+
                          |        L0-sdk           |
                          | typed query/command/event|
                          | auth/error/trace/retry  |
                          +------------+------------+
                                       |
                              formal client surface
                                       v
+------------------+        +---------+----------+        +----------------------+
| Desktop users    |  UI    |       L5-chat       | SDK    | owner truth domains  |
| Web dev/preview  +------->| route/view/store/   +------->| conversation         |
|                  |        | draft/reducer/shell |        | identity/work        |
+------------------+        +---------+----------+        | governance/artifact |
                                       |                 | workspace/member    |
                                       |                 | runtime/observability|
                                       |                 +----------------------+
                                       |
                              safe view / result / ref
                                       v
                           cross-platform user experience
```

图示说明：

- Chat 的所有业务读取、命令和变化消费都经过 `L0-sdk` 或 SDK 明确暴露的正式 adapter；Chat 不直接访问 owner 私有 API、内部 bus、共享数据库或外部 Bridges 平台。
- owner 返回的是事实、结果、引用和状态语境；Chat 将其转化为页面和交互状态。页面刷新、网络 ACK、websocket 连接成功、AG-UI ACK 或本地 optimistic state 都不能代替 owner committed result。
- V1 主要验证 Desktop shell；Web 只作为共享 UI/开发和后续扩展面，Mobile 的 Capacitor 方案是临时方向。无论平台如何变化，route、view model、reducer、visibility 和 command result 语义必须保持一致。

## 5. 依赖裁剪表（候选）

| 关联项目 | 全局关系 | Chat 角色 | 依赖类型 | 是否进入当前主链 | 裁剪理由 |
|---|---|---|---|---|---|
| `L0-sdk` | 跨端正式访问封装 | 唯一应用接入边界 | `compile + runtime + event + adapter` | 是 | 所有 owner 能力通过 typed client、formal event、command result、错误和脱敏 surface 接入。 |
| `L0-core` | 共享契约候选 | 条件型 compile 来源 | `compile` | 条件 | 只有 SDK 正式 re-export 稳定 shared ref/error/metadata 时才可使用；不得在 Chat 复制 shadow schema。 |
| `L1-conversation` | 对话真相 owner | 查询、命令和变化的消费方 | `runtime + event + ref` | 是，受合同门禁 | 提供 Conversation/Turn/Participant 的安全读取和发送结果；exact cursor/visibility/resume 仍受 `CHAT-UP-002` 约束。 |
| `L1-identity` | 平台身份 owner | 安全身份摘要消费方 | `runtime + event + ref` | 是 | 只显示 actor/member 摘要和生命周期姿态；不创建或管理 GlobalMember。 |
| `L1-work` | 项目工作真相 owner | 项目/进度摘要消费方 | `runtime + event + ref` | 是 | 只显示 Project/ProjectMember/WorkItem/Iteration 的安全摘要和入口。 |
| `L1-governance` | Gate/Decision/Policy owner | 显化与受控命令消费方 | `runtime + event + ref` | 是，受合同门禁 | GateCard 只提交正式意图并等待 receipt/decision；不作本地审批。 |
| `L1-artifact` | Artifact/Evidence owner | 引用与预览消费方 | `runtime + event + ref` | 是，受合同门禁 | 只显示 safe ref、summary、preview 或 unavailable；不存正文。 |
| `L1-workspace` | 跨域只读 view owner | safe view/export 消费方 | `runtime + event + ref` | 条件 | Chat 不自行聚合 Inbox/attention；`WS-UP-001~008` 未闭合时保持 stale/blocked/unavailable。 |
| `L2-member` | 成员容器交互 owner | 安全成员状态消费方 | `runtime + event + ref` | 条件 | 只显示最小成员在场/投递姿态，不推断 identity 或 runtime health。 |
| `L2-runtime` | Runtime 执行真相 owner | 运行摘要消费方 | `runtime + event + ref` | 条件 | 只显示 run/turn/decision/outcome safe summary，不执行推理、工具或 handoff。 |
| `L4-observability` | 观测与审计 owner | 低敏诊断/报告入口消费方 | `runtime + event + ref` | 条件 | 只显示正式返回的 observation/report handoff；不直接订阅 backend 或生成 verdict。 |
| `L6-bridges` | 并行外部映射兄弟 | 非正式依赖 | 不接入 | 否 | Chat 不吸收外部平台映射、账号、事件或正文。 |

### 5.1 禁止依赖（候选）

| 禁止做法 | 禁止原因 | 正确方式 |
|---|---|---|
| 页面直接调用各 L1/L2/L4 服务私有 API | 绕过 SDK 的认证、错误、重试、脱敏和版本边界。 | 通过 `L0-sdk` 的正式 typed surface。 |
| Chat 直接订阅内部 bus 或自造 topic | Chat 不拥有 delivery、cursor、replay 和 event schema authority。 | 使用 SDK 明确提供的 formal event/resume 能力；没有能力时保持 blocked。 |
| 在客户端复制 Conversation、Gate、Artifact 或 Workspace schema | 形成 shadow truth，并会把缓存误当业务对象。 | 只保存客户端 view model、safe ref 和展示状态。 |
| 用按钮点击、HTTP/websocket ACK、AG-UI ACK 或 toast 作为业务成功 | transport/交互确认不等于 owner committed。 | 等待正式 command result、receipt 或后续 owner query/event。 |
| 用缓存、空列表或 UI 隐藏推导可见性 | 可能泄露对象存在性或 fail-open。 | 以正式 visibility/Policy 结果为准，未知即受限。 |
| Chat 内建设 BFF、运行编排、工具执行或观测后端 | 会形成第二服务层并吞并其他 owner 的真相。 | 由 SDK 组合正式 owner 能力，Chat 只负责体验。 |

## 6. 数据与可见性边界（候选）

Chat 的本地状态可以为了跨端体验而持久化，但它们必须绑定客户端语境，并且可被重新拉取、失效或清除。缓存存在不代表当前可见，也不代表业务动作已经提交。

| 输入或状态 | Chat 允许行为 | Chat 禁止行为 |
|---|---|---|
| actor/session 语境 | 建立页面访问上下文、处理过期、登出和受限显示。 | 签发 credential、解释角色继承或自行授权。 |
| owner query / safe view | 构造 view model、来源标签、分页/选择和降级提示。 | 复制完整正文、填充缺失事实、把 partial 当 complete。 |
| owner event / change | 通过 SDK reducer 更新已知页面状态、标记重连/缺口、触发重新查询。 | 直接把事件当 source truth、从时间戳猜顺序或绕过 cursor。 |
| draft / selection / focus | 保存本地草稿、选中项、展开状态、焦点和恢复位置。 | 把草稿当 Turn、Approval、Decision 或 Project 更新。 |
| command receipt / result | 呈现 submitted/pending/confirmed/rejected/failed/unknown 等状态。 | 因 accepted、网络成功或 optimistic state 宣称已完成。 |
| visibility / redaction | 对已知敏感内容遮蔽、清除或显示 unavailable。 | 从历史缓存、对象名或错误差异猜测隐藏事实。 |
| artifact preview | 显示安全摘要、预览成功/失败和打开入口。 | 读取 raw body、缓存正文或绕过 Artifact 权限。 |

### 6.1 客户端状态与 owner truth 分层

```text
owner truth / decision / event
              |
              v
      L0-sdk typed adapter
              |
              v
Chat client store / reducer
  - route and scope selection
  - view model and local cache
  - draft / selection / focus
  - optimistic / confirmed / failed / unknown
              |
              v
Desktop rendering (V1) / Web shared UI / Mobile provisional wrapper
```

客户端 store 只拥有其列出的体验状态。若 reducer 收到无法确认来源、版本、可见性或幂等关系的输入，应转入 `unknown / stale / blocked / unavailable`，不得自行升级为完成状态。

## 7. 平台策略与跨平台边界（候选）

| 平台层 | 共享内容 | 平台差异由 Chat shell 承担 | 不得改变的业务边界 |
|---|---|---|---|
| Desktop（V1 主目标） | route、view model、store、reducer、accessibility semantics、SDK adapter 语义。 | Tauri 窗口、多窗口、系统托盘、桌面通知、系统返回、本地恢复和文件选择。 | 不因宿主能力扩展 owner 权限或绕过 SDK。 |
| Web（共享 UI/开发和后续扩展面） | 与 Desktop 相同的协作语义、状态机和页面模型。 | 浏览器缓存、标签页、键盘、浏览器通知、刷新和深链。 | 不因浏览器 transport 状态把业务命令当成功。 |
| Mobile（临时 Capacitor 方向） | 复用 Web view model、store、reducer、draft 和结果语义。 | 生命周期挂起、推送入口、输入法、系统返回、离线阅读和原生插件。 | 不因后台/推送 ACK 把 Gate、发送或 Runtime 操作当已提交。 |

V1 不以同时交付 Mobile 为前置条件。跨平台仍不是三套业务实现：产品核心必须共享相同的 view model、状态语义、可见性处理和 command result 解释；差异只落在 Desktop/Web/Mobile adapter 和 shell 体验层。Capacitor 只是移动端当前的复用假设，正式架构阶段仍可根据移动输入、通知和性能要求改为 React Native 或其他方案。

### 7.1 当前技术取舍记录

| 决策项 | 当前候选 | 状态 | 原因 |
|---|---|---|---|
| V1 主平台 | Desktop | `accepted for draft` | 先验证完整协作入口、GateCard、Artifact preview、离线恢复和桌面交互。 |
| Desktop shell | Tauri | `candidate` | 可复用 Web UI，并保留桌面窗口、通知、文件和本地能力；正式架构仍需核对安全与 SDK 绑定。 |
| Web surface | React/TypeScript shared UI | `candidate` | 作为共享 UI、开发/预览和后续 Web surface，不单独扩大 V1 业务范围。 |
| Mobile 临时方案 | Capacitor | `temporary candidate` | 最大化复用 Web UI，避免 V1 同时维护原生移动组件；移动需求成熟后重新评估。 |
| Chat client core | TypeScript shared core | `candidate` | 共享 reducer、view model、SDK adapter 和状态语义，避免平台层复制业务逻辑。 |

## 9. Pending / blocker（候选登记）

| ID | 未闭合主题 | 对 Chat 的当前上限 |
|---|---|---|
| `CHAT-UP-001` | SDK typed query/command/event public surface 与 owner adapter 尚未统一 | 只定义能力级 adapter；不写具体方法名、包名或 transport。 |
| `CHAT-UP-002` | Conversation visibility、change cursor、resume 和消费 scope 未完全闭口 | group/channel/dm/thread 可作为页面能力候选；实时、分页和恢复保持 pending。 |
| `CHAT-UP-003` | Governance command result、receipt、幂等和 Decision event 仍需 SDK 暴露 | GateCard 只能显示和提交意图；不能宣称审批成功。 |
| `CHAT-UP-004` | Artifact safe preview、reference、visibility contract 需确认 | 只保留 ref/summary/preview unavailable 语义。 |
| `CHAT-UP-005` | Workspace safe view、freshness、attention、cursor、export 未完全闭合 | 不自行构造 Inbox/attention；缺失时显示 unavailable/stale/blocked。 |
| `CHAT-UP-006` | Identity、Work、Member、Runtime 的摘要层级需对齐 | 不跨 owner 推断成员、项目或运行状态。 |
| `CHAT-UP-007` | Observability 前端交互观测和安全 handoff surface 未闭合 | 不直连观测 backend；只记录低敏客户端事件意图。 |

## 10. 本篇结论

本 draft 将 `L5-chat` 收束为 Desktop-first 的跨平台协作客户端产品，而不是通用 SDK 或业务真相服务。V1 先验证 Desktop；Web 保留为共享 UI/开发和后续扩展面，Mobile 暂以 Capacitor 作为临时方向。Chat 必须包含 UI、页面、导航、展示和客户端交互状态；所有正式业务读取、命令和变化消费经 `L0-sdk` 进入，Conversation、Governance、Artifact、Workspace、Member、Runtime 等 owner 保留各自真相。Chat 可以保存草稿、选择、缓存和 optimistic 状态，也可以提供发送、重试和受控审批入口，但只有 owner 的正式结果、receipt 或事件才能把状态推进为 confirmed。

后续校准应以本 draft 作为讨论输入，继续按 `00` 的 Step 7~17 收敛核心能力、故事、功能、规则、数据、接口、非功能和验收；本稿本身不授权实现、测试、提交或对 SDK/owner 合同作未确认的承诺。

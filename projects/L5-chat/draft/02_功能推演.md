# 02 · L5-chat 功能推演（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源  
> 前置：`draft/01_项目作用与交互对象.md`。本文只推演客户端产品能力，不替代正式 `00~07`，不锁定框架、路由库、SDK 方法名、DTO、事件 topic、缓存产品、性能数字或实现结果。V1 以 Desktop 为主目标，Mobile 仅保留 Capacitor 临时方向。

## 1. 功能边界原则

L5-chat 的每项能力都必须同时满足以下条件：

1. 功能属于用户可见的页面、导航、展示、草稿、选择、客户端状态或跨端体验；
2. 所有业务事实、命令和变化输入均来自 `L0-sdk` 的正式 surface；
3. 能区分本地体验状态、传输结果和 owner committed result；
4. 在 visibility、版本、幂等、cursor、preview 或 command result 不明时安全停下；
5. V1 Desktop 与共享 Web UI 共享同一业务状态语义，Mobile 的临时 Capacitor 方向也只能复用该语义，平台差异只落在 shell/adapter；
6. 不因“只做展示”而删除发送、重试、GateCard 受控入口等必要交互，但这些交互不拥有业务真相。

### 1.1 V1 平台范围

| 范围 | 当前处理 |
|---|---|
| Desktop | V1 主验证面，优先覆盖完整协作入口、GateCard、Artifact preview、草稿、发送/重试、变化消费、离线阅读和恢复。 |
| Web | 保留共享 React/TypeScript UI、开发/预览和后续扩展能力，不作为 V1 额外业务范围。 |
| Mobile | 不作为 V1 交付前置；暂定以 Capacitor 复用 Web UI，待移动端输入、通知、生命周期和性能要求明确后重新选择。 |

Desktop-first 只调整交付优先级，不改变 Chat 的 owner 边界、状态语义或 SDK 接入纪律。

## 2. 核心能力闭环（候选）

```text
安全协作语境可被进入与保持
              ->
正式协作事实可被安全、可解释地显化
              ->
用户意图可被受控发起并获得可区分反馈
              ->
变化、失败、离线与恢复可维持展示连续性
```

图示只表达能力成立的逻辑依赖，不表达接口时序、事件传播顺序或开发阶段。最后一个节点让用户可以重新进入已更新或已明确降级的协作语境，形成产品意义上的闭环。

### C-CHAT-1：安全协作语境可被进入与保持

**意图**：用户可以在当前 actor、scope 和 visibility 语境下进入 group/channel/dm/thread 以及项目、成员、Gate、Artifact 等协作入口，并在刷新、深链、重连和跨端切换后保留可解释的选择状态。

**候选能力**：

- 解析 SDK 提供的 actor/session/scope/ref，形成客户端 route 和 selection；
- 展示入口可用、不可见、暂不可用、需要重新连接或等待上游的区别；
- 保存当前 conversation/project/member/artifact/gate 的安全引用，不把引用升级为业务对象；
- 在页面恢复时重新验证 visibility、版本和可用性；
- 在 scope 变化、登出或权限撤销后清除不再可见的本地展示材料。

**禁止**：从 URL、缓存、对象名称或空列表猜测 scope、权限、Conversation 或 Project 是否存在。

### C-CHAT-2：正式协作事实可被安全、可解释地显化

**意图**：把 owner 提供的 Conversation/Turn、安全成员摘要、项目进度、GateCard、Artifact 引用和 Runtime/Workspace 摘要组织成用户可以理解的 view，而不复制其真相。

**候选能力**：

- 按 owner 提供的 conversation/turn safe view 渲染不同 Turn 类型或表现类别；
- 显示来源、时间、版本、可见性、freshness、partial/stale/unavailable 等状态；
- 显化 Gate/Decision 的当前正式状态和受控下一步入口；
- 显示 Artifact 引用、摘要、预览成功/失败和打开入口；
- 显示成员状态、项目进度、Runtime safe summary 和 Workspace safe view；
- 让屏幕阅读器、键盘、窄屏和低带宽场景获得与视觉界面一致的状态语义。

**禁止**：用客户端组合结果替代 owner 的 Policy、Decision、Member、Project、Artifact、Runtime 或 Workspace truth。

### C-CHAT-3：用户意图可被受控发起并获得可区分反馈

**意图**：用户可以编辑草稿、选择目标、发送消息、重试失败操作或进入受控 Gate 操作，且界面能区分意图已生成、请求已接收、owner 已确认、被拒绝、失败和结果未知。

**候选能力**：

- 保存文本、引用、附件 ref、回复目标、选择项和提交前校验状态；
- 经 SDK 发起 conversation send/retry 或 governance request intent；
- 为每个可能产生外部副作用的操作维护客户端 request/attempt 关联和明确的幂等输入；
- 对 optimistic、submitted、pending、confirmed、rejected、failed、unknown、cancelled 等客户端状态进行渲染；
- unknown outcome 时先显示待探测/待查询，不盲目重放；
- 将 owner 返回的 receipt、result ref 或后续 event 绑定到页面上的操作卡片。

**禁止**：按钮点击、表单本地校验通过、HTTP 200、websocket 连接成功、AG-UI ACK 或本地 optimistic state 直接升级为业务完成。

### C-CHAT-4：变化、失败、离线与恢复可维持展示连续性

**意图**：在正式变化、网络中断、应用挂起、多端并行、缓存失效和结果不明时，客户端仍能保留可解释的已知内容，并在恢复后按正式 cursor/版本重新校准。

**候选能力**：

- 消费 SDK 提供的正式 change/event surface，按 owner cursor/resume 语义更新 store；
- 通过 reducer 处理 duplicate、out-of-order、gap、expired cursor、visibility revoked 和 version conflict；
- 缓存安全展示快照、draft 和恢复上下文，明确其版本和过期姿态；
- 断线时标记 reconnecting/stale，恢复时先重新验证，再更新页面；
- 多端同时变更时显示最新可验证状态，不把本地旧状态强行覆盖 owner 事实；
- 对无法恢复的内容显示 unavailable/blocked/unknown，并提供用户可理解的下一步。

**禁止**：直接订阅内部 bus、从时间戳猜 cursor、用本地缓存继续授权、将离线操作显示为已提交或自行重建 owner 事件。

## 3. 核心能力到功能候选映射

| 候选功能 | 支撑能力 | 用户可见结果 | 主要边界 |
|---|---|---|---|
| `F-CHAT-001` route 与 scope 入口 | C-CHAT-1 | 可进入 group/channel/dm/thread、项目和相关安全入口 | route 不创建 Conversation/Project/Workspace。 |
| `F-CHAT-002` conversation view | C-CHAT-1/2 | 显示 Turn 表现类别、线程关系、来源和降级状态 | Turn truth 归 conversation。 |
| `F-CHAT-003` Turn 类型渲染 | C-CHAT-2 | 按正式 safe view 渲染文本、系统变化、引用、状态卡等表现 | 不由 Chat 发明新的业务 Turn 类型。 |
| `F-CHAT-004` member/project/runtime summary | C-CHAT-2 | 显示最小安全摘要和入口状态 | 不推断生命周期、进度或执行完成。 |
| `F-CHAT-005` GateCard | C-CHAT-2/3 | 显示 Gate/Decision 状态、请求语境和受控操作入口 | 点击不等于批准，结果以 Governance 为准。 |
| `F-CHAT-006` Artifact reference/preview | C-CHAT-2 | 显示引用、摘要、预览和不可用原因 | 不复制正文、版本链或权限。 |
| `F-CHAT-007` draft/composer | C-CHAT-3 | 编辑、保存、恢复和清理本地草稿 | 草稿不等于 Turn 或提交。 |
| `F-CHAT-008` send/retry intent | C-CHAT-3 | 显示发送/重试操作的多阶段状态 | 仅经 SDK；unknown 不盲重试。 |
| `F-CHAT-009` selection/focus state | C-CHAT-1/3 | 保存线程、引用、成员、Gate 或 Artifact 选择 | 选择不改变 owner truth。 |
| `F-CHAT-010` formal change consumption | C-CHAT-4 | 页面接收已授权变化并更新 view | 不直订内部 bus。 |
| `F-CHAT-011` reconnect/resume | C-CHAT-4 | 断线、恢复、cursor 失效和重拉取姿态 | 依赖 SDK/owner resume contract。 |
| `F-CHAT-012` offline display/recovery | C-CHAT-4 | 离线阅读、草稿保留、恢复后校准 | 离线不产生业务成功。 |
| `F-CHAT-013` multi-device continuity | C-CHAT-4 | 多端显示可解释的最新/过期/冲突状态 | 不假设本地状态先于 owner。 |
| `F-CHAT-014` accessibility/security surface | 全部 | 键盘、屏幕阅读、敏感字段遮蔽、缓存清理和登出 | 正式授权和安全策略归 owner/SDK。 |

## 4. 页面与入口候选

| 页面/入口 | 必需输入 | 主要展示 | 可能动作 | 失效姿态 |
|---|---|---|---|---|
| 协作入口/导航 | actor、scope、safe ref、visibility | group/channel/dm/thread、项目和成员入口 | 选择、返回、深链、刷新 | unavailable / restricted / reconnecting |
| Conversation workspace | conversation safe view、Turn page/cursor | Turn 列表、线程、来源、状态卡、Artifact 引用 | 草稿、发送、重试、引用 | stale / partial / cursor-expired |
| GateCard / decision panel | Governance safe view、command capability | Gate、责任语境、当前状态、下一步 | 提交受控请求、查看结果 | blocked / pending / rejected / unknown |
| Artifact preview panel | safe ref、summary、preview result | 摘要、版本语境、预览或不可用原因 | 打开/下载/回到对话 | not-visible / unavailable / stale |
| Member/project/runtime side panel | owner safe summaries | 成员、项目进度、运行状态 | 查看、切换、回链 | partial / stale / blocked |
| Offline/recovery surface | local cache metadata、resume context | 已知内容、过期原因、恢复进度 | 重连、重拉取、清理本地状态 | reconnecting / unknown / fail-closed |

页面名称只是产品候选，不锁定最终路由、组件或平台实现。

## 5. 失败与降级矩阵（候选统一口径）

| 情况 | Chat 可显示 | Chat 不得显示/执行 |
|---|---|---|
| SDK 不可用或版本不匹配 | 明确不可用、重试或等待配置 | fallback 到私有 API、旧包名或直连服务 |
| Query timeout / owner unavailable | 保留已知快照并标记 stale/unavailable | 静态填充当前状态或显示 fresh |
| visibility denied / revoked | 隐藏敏感内容，显示受限或不可见 | 依据缓存、对象名或错误差异猜测对象存在 |
| event stream lost | reconnecting、已知历史、待恢复 cursor | 从时间戳猜位置或继续宣称实时 |
| duplicate/out-of-order event | 去重、等待正式 cursor、标记 conflict/gap | 重复渲染 Turn、Gate 或 Artifact 变化 |
| command result unknown | unknown、查询/探测入口、避免重放 | 盲目重试或显示 confirmed |
| command rejected/failed | 原因、重试条件或用户下一步 | 隐藏拒绝或改成本地成功 |
| preview unavailable | 引用、摘要、不可预览原因 | 读取 raw body 或生成替代正文 |
| offline | 已缓存且有版本标记的安全内容、draft | 把本地操作宣称已提交 |
| logout / scope changed | 清除受影响本地状态并回到安全入口 | 继续显示旧 scope 的敏感内容 |

## 6. 外围增强候选（不阻塞核心闭环）

| 能力 | 价值 | 为什么不进入核心闭环 |
|---|---|---|
| 全局搜索与高级过滤 | 缩短入口定位时间 | 核心闭环可以先依赖 owner query 的基本分页和选择。 |
| 富文本/多格式编辑 | 提升表达能力 | 不决定事实能否被安全展示和受控提交。 |
| 推送通知、系统托盘、桌面徽标 | 提升跨端到达率 | 依赖宿主能力，且通知 ACK 不代表业务提交。 |
| 多窗口、分屏、布局同步 | 提升重度使用体验 | 属于 shell/偏好状态，不是 owner truth。 |
| 本地全文索引和智能预取 | 提升阅读速度 | 受敏感内容、缓存保留和版本失效约束。 |
| 高级诊断面板 | 提升支持效率 | Observability backend 和安全 handoff 仍归正式 owner。 |
| 个性化主题、快捷键和动效 | 提升体验 | 不影响核心协作事实闭环。 |

## 7. 明确不属于 Chat 的能力

- 创建、修改、删除或重放 Conversation、Turn、Participant、Project、Member、Gate、Decision、Artifact、Workspace 或 Runtime 真相；
- 实现通用 SDK、内部 bus、服务私有 RPC、数据库访问、Runtime 推理、Tools 执行或外部平台映射；
- 在客户端计算 Policy/Authorization、审批、项目进度、成员生命周期、Artifact 版本/血缘、Runtime outcome 或 Observability verdict；
- 以离线队列、transport ACK、页面刷新、通知送达或 websocket 连接状态替代 owner committed result；
- 通过 Chat UI 形成跨域 Inbox、attention、Workspace projection 或治理审计后端。

## 9. 本篇结论

Chat 的功能闭环不是“把消息画在屏幕上”，而是：安全进入协作语境、把正式事实显化、把用户意图经 SDK 受控发起并准确反馈、在变化/失败/离线/恢复时保持可解释的展示连续性。V1 先用 Desktop 验证这条闭环；Web 是共享 UI/开发和后续扩展面，Mobile 暂以 Capacitor 作为临时方向。草稿、选择、缓存和 optimistic 状态是客户端产品状态；Conversation、Governance、Artifact、Workspace、Member、Runtime 和 Observability 的业务真相不进入 Chat。

后续正式需求校准应以四个核心能力为主轴逐节点收敛用户故事、功能、规则、数据、接口、非功能和验收，不应直接把本篇候选功能表当作已确认的正式需求。

# 03 · L5-chat 模块划分与分层（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源  
> 前置：`draft/01_项目作用与交互对象.md`、`draft/02_功能推演.md`。本文是客户端产品职责图和可落码方向预演，不授权创建代码模块、package、路由、DTO、事件 schema、数据库、worker 或平台集成。V1 以 Tauri Desktop 为主 shell，Web 是共享 UI/开发面，Mobile 暂保留 Capacitor adapter。

## 1. 模块划分原则

模块边界围绕“跨平台协作展示与受控交互”划分，而不是围绕 Conversation、Governance、Artifact、Workspace 或 Runtime 的服务端真相划分。每个候选模块都必须能够说明：

1. 它拥有哪一种 Chat-local 状态；
2. 它消费哪个 `L0-sdk` formal surface；
3. 它如何把 `pending / confirmed / failed / unknown / stale / blocked` 显示给用户；
4. 它如何避免把 transport、缓存或 UI 点击升级为 owner truth；
5. 它如何在 V1 Desktop、共享 Web UI 和 Mobile 临时 Capacitor shell 间保持相同业务语义。

## 2. 业务主要组成部分（候选，11 个）

| # | 组成部分 | 核心职责 | 不承担什么 | 承接能力 |
|---|---|---|---|---|
| 1 | `Client product core` | 维护跨平台共享的 view model、页面语义、状态标签、错误/降级映射和可访问语义。 | 不拥有任何 owner truth、SDK 通用实现或平台窗口能力。 | C-CHAT-1~4 |
| 2 | `Session and scope gateway` | 接收 actor/session/scope/ref 语境，处理登录过期、登出、visibility 重新验证和安全入口。 | 不认证、不签发 credential、不创建成员或权限。 | C-CHAT-1 |
| 3 | `Navigation and conversation surface` | 组织 group/channel/dm/thread 路由、历史选择、线程关系和页面生命周期。 | 不创建 Conversation、Turn、Participant 或 read receipt。 | C-CHAT-1/2 |
| 4 | `Owner-safe view composer` | 将 Conversation、Identity、Work、Governance、Artifact、Workspace、Member、Runtime 的安全结果组合为 view model。 | 不跨 owner 推断业务状态，不复制正文、Policy 或版本链。 | C-CHAT-2 |
| 5 | `Turn and card renderer` | 渲染 Turn 表现类别、GateCard、Artifact card、成员/项目/运行状态卡和降级卡。 | 不发明 owner 业务类型，不把卡片状态当真相。 | C-CHAT-2 |
| 6 | `Draft and selection state` | 保存草稿、引用、回复目标、附件 ref、选择/展开/焦点和提交前提示。 | 不把 draft、selection 或 optimistic 状态写成业务提交。 | C-CHAT-1/3 |
| 7 | `Command intent coordinator` | 将发送、重试、受控 Gate 操作等用户意图经 SDK 发起，并关联 receipt/result/probe 状态。 | 不执行 Conversation/Governance 命令本体，不确认 owner committed。 | C-CHAT-3 |
| 8 | `Change consumer and reducer` | 消费 SDK formal event/change，处理 cursor/resume、duplicate、gap、冲突和 view 更新。 | 不直订内部 bus，不拥有 event delivery/replay truth。 | C-CHAT-4 |
| 9 | `Local cache and recovery` | 保存带版本/可见性语境的展示缓存、草稿和恢复上下文，处理离线和重连。 | 不把缓存当权限，不离线宣称业务成功。 | C-CHAT-4 |
| 10 | `Platform shell adapters` | V1 承接 Tauri Desktop 的路由宿主、窗口、通知、输入、系统返回、存储和深链；同时保留 Web shell 与 Mobile Capacitor adapter 的边界。 | 不改变业务状态语义，不绕过 SDK。 | 全部横切 |
| 11 | `Accessibility and client security surface` | 提供键盘/屏幕阅读、敏感字段遮蔽、登出清理、缓存失效和低带宽姿态。 | 不定义正式 Policy、授权、审计或服务端安全真相。 | 全部横切 |

## 3. 客户端实现分层（候选）

| 分层 | Chat 内职责 | 边界纪律 |
|---|---|---|
| Platform shell | 路由宿主、窗口/页面生命周期、系统输入、通知、深链、存储能力、平台返回。 | 只提供宿主能力；不决定业务状态或授权。 |
| Presentation | 页面、组件、可访问性树、卡片、空/错/受限/过期状态和交互提示。 | 不直接调用 SDK；不从 UI 事件推导 owner result。 |
| View model / selector | 将 SDK safe view、局部选择、缓存和状态轴组合为页面可读模型。 | 不复制 owner DTO 为第二真相；来源和版本必须可追踪。 |
| Client state / reducer | 保存 route、selection、draft、optimistic、confirmed、failed、unknown、reconnect 和 cache 状态。 | reducer 只能依据正式输入或明确的本地动作变化；不能伪造业务成功。 |
| Application intent | 编排页面动作、query、command、resume、retry、probe 和本地恢复。 | query、command、event 和 local-only 动作必须分开；副作用结果未知时先保持 unknown。 |
| SDK adapter | 把客户端需要的 typed query/command/event/auth/error/trace/retry surface 接到 `L0-sdk`。 | 不实现通用 SDK，不调用私有 API，不直连内部 bus。 |
| Local persistence | 保存受限的展示缓存、draft、选择、版本/可见性 metadata 和恢复 checkpoint。 | 不保存 credential 或未授权 raw body；失效/登出可清理。 |
| Diagnostics handoff | 产生低敏 client event、correlation 和用户可见诊断入口。 | 不把 UI log 当 Observability truth，不直接写 backend。 |

## 4. 页面、路由与 view model 矩阵（候选）

| 页面/路由族 | 输入 view | 主要组件 | Chat-local 状态 | SDK/owner 边界 |
|---|---|---|---|---|
| `conversation-entry` | actor/scope、入口 safe ref、visibility | 入口列表、scope switcher、空/受限卡 | route、selection、last-opened | 不推断 Conversation/Project 存在性。 |
| `conversation-space` | conversation safe view、Turn page/cursor、change status | Turn list、thread navigator、source label、status banner | page selection、scroll/focus、cache marker | Turn 与 cursor 归 conversation；变化经 SDK。 |
| `conversation-compose` | draft、reply target、allowed action hint | composer、attachment ref、send/retry action | draft lifecycle、attempt state | 发送 result 以 owner receipt/result 为准。 |
| `gate-card` | governance safe view、command capability、decision ref | GateCard、responsibility/condition view、action sheet | selected decision action、submission state | 不本地 approve/reject，不把 click 当 confirmed。 |
| `artifact-panel` | artifact safe ref、summary、preview result | reference card、preview panel、open/download entry | selected artifact、preview loading/status | 不读取 raw body 或版本链。 |
| `member-project-panel` | identity/work/member safe summaries | member card、project progress、runtime status | panel state、selection、freshness label | 不推断成员生命周期、项目完成或 runtime outcome。 |
| `workspace-attention` | workspace safe view/export、attention input | inbox/attention list、cross-project entry | local read/hidden/pin/focus | 不自行拼 Workspace truth；受 `WS-UP-001~008` 约束。 |
| `recovery-surface` | cache metadata、resume/cursor result、unknown attempts | reconnect banner、restore panel、retry/probe actions | recovery phase、pending request map | 不盲目重放副作用，不以网络恢复代替业务确认。 |

页面名和路由族是草稿层候选。正式架构需进一步决定共享产品 core 与各平台 shell 的边界，但不能因此把 owner truth 搬进客户端。

## 5. 客户端对象类别（字段后置到正式设计）

### 5.1 Chat-owned local state

| 对象类别 | 可能承载 | 关键隔离 |
|---|---|---|
| `RouteContext` | platform、scope ref、route、query params、return path、deep-link provenance。 | 不等于 Conversation/Project/Workspace scope truth。 |
| `SelectionState` | 当前 conversation/thread/Turn/Gate/Artifact/member/project 选择、展开和焦点。 | 不改变 owner 事实和权限。 |
| `DraftState` | draft body/ref、reply target、local validation、last edited、restore marker。 | 不等于 Turn、Approval、Decision 或 Artifact。 |
| `ViewModelSnapshot` | safe display data、source refs、version/watermark、visibility marker、freshness/degradation。 | 不复制 raw body，不成为 source truth。 |
| `CommandAttemptState` | intent ref、request/idempotency association、submitted/pending/confirmed/rejected/failed/unknown。 | 不等于 owner command result，除非有正式 result/receipt。 |
| `EventResumeState` | SDK cursor/resume token、last accepted revision、gap/conflict/expired 标记。 | 不等于 bus delivery cursor 或 Conversation truth。 |
| `LocalCacheEntry` | 可安全缓存的 view、source version、visibility expiry、redaction marker。 | 不作为离线授权或当前 fresh 依据。 |
| `RecoveryContext` | 恢复阶段、route、draft、pending probe、下一步提示。 | 不证明外部副作用完成。 |
| `AccessibilityState` | focus order、announced status、expanded/collapsed、reduced motion。 | 不改变业务状态或权限。 |

### 5.2 外部 safe view / result 类别

| 类别 | Chat 如何使用 | 禁止保存/推断 |
|---|---|---|
| Conversation/Turn view | 显示已授权文本、表现类别、线程关系、source ref 和 cursor 状态。 | 不拥有 Conversation/Turn lifecycle、participant 或正文版本。 |
| Governance view/result | 显示 Gate/Decision 当前结论、receipt、理由引用和下一步。 | 不本地计算 Policy、批准或授权。 |
| Artifact ref/preview | 显示 ref、summary、preview availability、version context。 | 不保存正文、血缘、Evidence 或 Baseline。 |
| Identity/Member summary | 显示安全 actor/member 摘要和生命周期姿态。 | 不创建 GlobalMember、ProjectMember 或宿主 session。 |
| Work/Project summary | 显示项目/工作/迭代摘要和入口状态。 | 不推进 WorkItem、Project 或进度。 |
| Runtime summary | 显示 run/decision/checkpoint/outcome safe status。 | 不执行 runtime、tool 或 handoff。 |
| Workspace view/export | 显示安全 attention/cross-project view。 | 不拼 projection、cursor、Inbox 或授权。 |

## 6. 状态轴与状态机候选

### 6.1 页面数据多轴表达

页面状态不能用一个 `status` 字段压缩所有语义，至少要区分：

| 状态轴 | 候选值 | 说明 |
|---|---|---|
| availability | available / restricted / unavailable / blocked | 是否有资格和条件显示入口或内容。 |
| freshness | fresh / stale / partial / unknown | 内容是否仍与正式来源一致。 |
| transport | idle / loading / reconnecting / timed-out / failed | SDK 访问或连接的技术状态。 |
| command | idle / submitted / pending / confirmed / rejected / failed / unknown | 用户意图和 owner 结果的分层。 |
| local | draft / selected / expanded / cached / restored / cleared | Chat-owned 体验状态。 |
| visibility | visible / redacted / revoked / not-visible | 正式可见性和客户端裁剪结果。 |

### 6.2 Draft 生命周期（候选）

```text
empty -> editing -> locally_valid -> submitting
  |         |            |              |
  |         |            |              +-> submitted/pending
  |         |            +-> invalid       |
  |         +-> restored                    +-> confirmed
  +-> cleared                               +-> rejected/failed/unknown
```

`locally_valid` 只表示客户端输入满足本地可检查条件，不表示 owner 接受；`unknown` 必须进入探测/查询或用户决策路径，不能自动跳到 `confirmed`。

### 6.3 View / event 恢复状态（候选）

```text
fresh -> stale -> reconnecting -> resuming -> fresh
  |       |          |             |
  |       |          |             +-> partial/blocked
  |       |          +-> failed    +-> cursor-expired -> requery
  |       +-> visibility-revoked -> restricted/cleared
  +-> local-cache-only -> unavailable/expired
```

### 6.4 命令结果与 transport 分离

| 客户端观察 | 允许推进 | 不得推导 |
|---|---|---|
| 按钮已点击 | local intent created | owner accepted |
| SDK 请求已发出 | submitted / pending | committed |
| transport/HTTP ACK | transport acknowledged | Gate approved、Turn appended、Artifact created |
| receipt/result ref 返回 | 进入正式结果映射 | 后续 workflow 已完成，除非结果明确说明 |
| owner change/event 可见 | 更新 view/reducer | 当前页面所有其他状态已同步 |
| probe/query 确认 | confirmed 或正式 rejected | 未确认的副作用可盲重试 |

## 7. Adapter / seam 类别（候选，不锁协议）

| seam | 方向 | 能力语义 | 当前约束 |
|---|---|---|---|
| Actor/session seam | 入站 | 获取当前 actor、session 过期和登出语境。 | Chat 不认证、不签发 credential。 |
| Owner query adapter | 出站 | 查询 Conversation、Identity、Work、Governance、Artifact、Workspace、Member、Runtime safe view。 | 只能经 SDK；exact surface pending。 |
| Owner command adapter | 出站 | 发起发送、重试、Gate request 等正式意图并取得 receipt/result。 | 需要 idempotency、authorization、unknown 语义。 |
| Formal change adapter | 入站 | 接收 SDK 暴露的 owner event/change、cursor/resume、gap 和 visibility 失效。 | 不直订内部 bus；不伪造 topic/offset。 |
| Preview/reference adapter | 出站 | 获取 Artifact/Conversation/Observability safe ref、summary、preview。 | body-free、redaction、provenance 必须明确。 |
| Local storage adapter | 双向 | 保存 draft、cache、selection、recovery metadata。 | 不保存敏感 raw body/credential；支持失效清除。 |
| Platform capability adapter | 双向 | 通知、窗口、文件选择、输入、网络、系统返回、深链。 | 只提供宿主能力；不得把平台 ACK 当业务结果。 |
| Diagnostic handoff adapter | 出站 | 记录低敏 client interaction、error correlation、用户支持入口。 | Observability backend/审计 truth 不在 Chat。 |
| Fake/fixture adapter | 测试 | 模拟 query/command/event 延迟、缺口、拒绝和 unknown。 | 不证明真实 SDK/owner 集成或 readiness。 |

## 8. 配置与客户端安全边界预演

### 8.1 配置候选类别

| 类别 | 可能配置 | 约束 |
|---|---|---|
| Platform | V1 Tauri shell、Web shared UI、deep-link、notification、window、storage capability；Mobile Capacitor 临时 adapter | 平台配置不改变业务状态语义；Mobile 不构成 V1 交付前置。 |
| SDK | SDK version、formal capability enablement、timeout/retry policy、redaction profile | 只有正式 SDK capability 才可启用；不得用 feature flag 绕过 owner。 |
| Cache | scope、大小、保留、过期、clear-on-logout | cache 不是授权；敏感内容默认最小化。 |
| Recovery | resume/requery policy、unknown probe、offline read policy | 不盲目重放可能产生副作用的命令。 |
| Accessibility | keyboard、screen-reader、reduced-motion、contrast | 可访问语义与业务状态一致。 |
| Diagnostics | low-sensitivity event allowlist、redaction、trace handoff | 不记录 raw body、credential 或未授权 source。 |

### 8.2 客户端安全红线

- 不把本地缓存、隐藏按钮、空列表或路由不可见当成授权判断；
- 不在浏览器/桌面/移动端日志中写入 raw credential、Artifact 正文、敏感会话材料或未脱敏对话内容；
- scope、visibility、logout 或版本撤销后清除/遮蔽相关页面与缓存；
- 任何客户端错误提示都要避免泄露被拒绝对象的存在性；
- 平台 deep link、通知和剪贴板内容必须经过 safe ref/redaction 边界；
- 客户端安全姿态不能替代 Identity、Governance、SDK 或 Observability 的正式决定。

## 11. 跨模块红线审计

| 红线 | 审计问题 |
|---|---|
| 真相边界 | 模块是否把 owner object/status 存成 Chat-local truth？ |
| SDK 边界 | 是否存在页面直连 API、内部 bus、共享数据库或隐藏私有 adapter？ |
| 状态语义 | 是否把 transport/optimistic/local success 当 owner confirmed？ |
| 可见性 | scope、撤销、过期、redaction 和 unknown 是否 fail-closed？ |
| 恢复 | cursor、view revision、read cursor、draft 和 command attempt 是否混用？ |
| 跨端一致性 | 平台差异是否仅在 shell；是否改变业务状态解释？ |
| 证据边界 | fake/fixture 是否被误写成真实集成、测试结果或 readiness？ |
| 兄弟边界 | 是否吸收 Bridges、Runtime、Tools、Workspace backend 或 Observability backend？ |

## 12. Historical material 差异结论

| 旧材料方向 | 本 draft 处置 |
|---|---|
| 固定 React/Svelte/Tauri/RN 方案 | 当前 draft 采用 React/TypeScript shared UI + Tauri Desktop 候选；Capacitor 仅为 Mobile 临时方向，正式技术栈仍后移校准。 |

| GateCard 点击=审批成功、ACK=发送成功 | 改为多轴 result/receipt/unknown 语义。 |
| 由 Chat 聚合 Workspace、Runtime、Artifact 或 Observability | 改为 safe view/ref 消费；owner 保持真相。 |
| 旧指标、性能阈值和实现目录 | 不进入 draft 的承诺，后续由正式 NFR/配置/实施校准。 |

## 13. 本篇结论

L5-chat 的模块边界应围绕共享客户端产品 core、SDK adapter、view model/reducer、草稿/选择、受控命令反馈、变化消费/恢复和 Desktop-first shell 展开。V1 以 Tauri Desktop 验证；Web shared UI 保留为开发/后续扩展面，Mobile Capacitor 只作为临时 adapter。模块可以组织体验和状态，但不能创建 Conversation、Governance、Artifact、Workspace、Member 或 Runtime 真相。

这份候选分层为后续 `00` 需求校准和 `01~03` 正式设计提供讨论入口；在 `CHAT-UP-001~007` 未闭合前，模块名称、字段、路由、协议、存储和实现技术均保持待确认，不应被当作已实现或已集成。

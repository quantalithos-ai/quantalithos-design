# L5-chat 原型信息架构记录

> 阶段：P1 信息架构
> 状态：`completed_for_prototype`
> 日期：2026-09-30

## 1. 顶层导航

```text
工作区
├── 对话
├── 项目
└── 成员
```

### 对话

承载 group / channel / dm / thread。对话顶部显示当前语境、成员摘要、恢复入口和绑定项目入口。

### 项目

承载项目列表和项目详情。项目进度不是独立顶层导航，而是项目详情中的一个标签。

### 成员

承载公司级人员目录。人员详情可进入直接对话，但公司成员目录不推断项目或群聊可见性。

## 2. 项目详情层级

```text
项目列表
  -> 项目详情
      ├── 概览
      ├── 项目进度
      │   ├── 项目整体 BPMN
      │   ├── 阶段工作流程图
      │   └── 节点详情
      ├── 关联群聊
      ├── 工作项
      └── 证据
```

项目详情是项目相关展示的稳定容器。流程、群聊、工作项和证据都以当前项目作为上下文，避免让用户在全局导航中区分“项目”和“项目进度”。

## 3. 对话与项目双向入口

```text
对话顶部绑定项目
  -> 项目详情 / 项目进度

项目详情 / 关联群聊
  -> 对话
```

一个群聊最多绑定一个项目；一个项目可以关联多个群聊。群聊成员集合独立于项目成员摘要，页面必须分别标示来源和可见性。

## 4. 流程下钻层级

```text
项目进度
  -> 选择阶段
      -> 阶段工作流程
          -> 选择工作流节点
              -> 节点详情 / 关联对话 / 证据摘要
```

项目整体流程和阶段子流程共享“只读流程投影”语义。返回项目整体流程时保留项目上下文；返回对话时回到原绑定群聊。

## 5. 并行流程的信息层级

并行流程在项目进度画布中作为流程结构显示：

```text
阶段
  -> 并行分叉
      ├── 分支工作流
      ├── 分支工作流
      └── 分支工作流
  -> 并行汇聚
  -> Governance Gate
```

并行网关表达流程控制结构；Governance Gate 表达正式治理决策。二者在视觉和交互上分开，Chat 不根据分支颜色自行计算汇聚结果。

## 6. 主要页面状态

| 页面 | 空状态 | 受限状态 | 主要返回路径 |
|---|---|---|---|
| 对话 | 无可见对话 | 内容遮蔽 / 需重新验证 | 对话列表 |
| 项目列表 | 无可见项目 | 列表部分受限 | 工作区 |
| 项目详情 | 项目摘要不可用 | 项目或某标签受限 | 项目列表 / 关联群聊 |
| 项目进度 | 流程投影不可用 | 节点或分支受限 | 项目详情 |
| 成员目录 | 无可见成员 | 身份或成员摘要受限 | 工作区 |

## 7. 信息架构边界

- 不把流程画布提升为独立顶层业务入口。
- 不在项目详情中混入群聊成员的完整真相。
- 不在公司成员目录中默认展示所有项目、群聊或权限。
- 不让流程节点详情替代 Work、Governance、Artifact 或 Runtime 正式页面。
- 不把项目绑定、成员可见性或流程状态由客户端本地推断。

## 8. P1 结论

P1 信息架构通过原型级审查。`index.html` 已能表达顶层导航、项目详情标签、对话与项目双向入口、公司成员目录和流程下钻层级。正式需求与架构中的 owner、projection、权限和深链接合同仍待后续正式文档校准。

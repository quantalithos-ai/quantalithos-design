# L5-chat HTML 原型完成计划

> 状态：prototype_available_for_review；范围：Desktop-first交互原型。
> 位置：`projects/L5-chat/draft/prototype/`。
> 本计划用于安排HTML原型与产品评审，不是正式设计基线、实现计划或验收结果。

## 1. 目标

用简单HTML验证桌面协作客户端的页面结构、信息层级和主要交互状态，尽早发现导航、内容密度、结果反馈、恢复和可访问性方面的问题。

原型回答“用户在哪里、看到了什么、能做什么、状态变化如何表达”。它不定义Conversation或Governance truth、SDK DTO/method、owner权限、持久化机制或生产技术实现。

## 2. 范围

### 2.1 本轮覆盖

| 领域 | 覆盖内容 |
|---|---|
| 应用壳 | Desktop单窗口、导航区、当前协作语境、主内容、详情/恢复辅助面板 |
| 协作入口 | group/channel/dm/thread入口；选择、进入、返回；加载、空、受限、不可用 |
| 对话 | 消息时间线、Turn表现类别、来源/新鲜度、thread入口、composer |
| GateCard | 正式状态展示、受控操作入口、等待结果反馈、拒绝/失败/未知 |
| Artifact | 安全引用、preview可用/受限/过期/不可用 |
| 跨域摘要 | identity与member分开、work项目进度、runtime摘要、workspace safe view占位 |
| 草稿与发送 | 草稿编辑、回复目标、pending/confirmed/rejected/failed/unknown |
| 连续性与恢复 | offline/stale/gap/reconnecting/resuming/restricted/blocked及安全下一步 |
| 可访问性 | 键盘焦点路径、焦点返回、语义区域、状态播报和窄窗口布局 |

### 2.2 明确不覆盖

- 不连接SDK、服务API、内部bus或任何owner系统。
- 不使用真实用户、项目、Conversation、Gate或Artifact数据。
- 不伪造真实审批、发送成功、权限、可见性或跨端同步。
- 不实现登录、授权、真实缓存、离线队列、文件上传或download。
- 不扩展Workspace inbox/unread/pin、全局搜索、通知托盘、多窗口或Mobile页面。
- 不把HTML/CSS/JS原型目录当作最终React/Tauri项目骨架。

所有内容和结果均为演示数据，必须在页面上标注为原型模拟状态。

## 3. 原型页面和交互清单

| 页面/页面变体 | 主要内容 | 必须走查的交互 |
|---|---|---|
| 协作入口 | group/channel/dm/thread入口、选中语境、空/受限/不可用状态 | 选择入口、进入对话、返回入口、切换语境 |
| 对话页 | 时间线、来源/新鲜度、composer、摘要区 | 滚动消息、选中Turn、打开thread、打开详情、编辑草稿 |
| Thread变体 | parent context、thread时间线、返回位置 | 进入thread、返回原对话并恢复焦点/位置 |
| GateCard变体 | Gate safe summary、可用性、受控动作、结果状态 | 发起操作后先进入pending；展示confirmed/rejected/failed/unknown模拟分支 |
| Artifact preview变体 | 引用、preview区域、来源/新鲜度、限制原因 | 打开、关闭；演示可预览、restricted、stale、unavailable |
| 恢复面板 | 离线/缺口/重连/重新查询、unknown attempt、安全下一步 | 模拟offline、resume/requery、probe、clear；检查撤销后遮蔽 |

GateCard、Artifact preview和恢复面板优先作为对话页中的侧栏或弹层状态；只有走查证明需要独立页面时才扩展路由。

## 4. 关键用户路径

### 4.1 导航与thread

```text
协作入口
  -> 选择group/channel/dm
  -> 打开对话
  -> 进入thread
  -> 返回原对话
```

检查所选语境是否持续可辨，返回后焦点/位置是否合理，以及受限/不可用时是否不暴露隐藏条目内容。

### 4.2 草稿与发送反馈

```text
编辑草稿
  -> 选择回复目标
  -> 发起演示发送
  -> pending
      -> confirmed / rejected / failed / unknown
```

检查本地草稿和owner结果的表达是否分开。unknown只提供probe、wait或用户决策，不出现自动重发行为或成功暗示。

### 4.3 GateCard受控入口

```text
查看GateCard
  -> 选择受控操作
  -> pending
      -> confirmed / rejected / failed / unknown
```

检查操作前的正式状态、当前能力和提交后状态能否区分。按钮点击、弹窗关闭或toast不得表示已批准。

### 4.4 Artifact预览

```text
查看引用
  -> 打开preview
      -> available / restricted / stale / unavailable
  -> 关闭并返回对话
```

检查不可见时不展示推测信息，不生成替代正文或虚构下载地址。

### 4.5 离线与恢复

```text
当前对话
  -> offline/stale/gap
  -> reconnecting/resuming
  -> fresh / partial / restricted / blocked / needs_action
```

检查旧材料遮蔽、恢复动作和恢复后重新验证提示。技术连接恢复不得表现为业务结果已确认。

## 5. 页面状态矩阵

| 状态轴 | 原型变体 | 表达要求 |
|---|---|---|
| access/visibility | available、read_only、restricted、unavailable、blocked、hidden | 不从空列表或隐藏按钮推断不存在/授权 |
| freshness | fresh、stale、partial、unknown、expired | 与访问姿态和命令结果分开呈现 |
| command result | pending、confirmed、rejected、failed、unknown | 每种状态有独立标签、说明和允许动作 |
| continuity | offline、reconnecting、gap、resuming、needs_action | 不用一个“连接中”状态覆盖所有原因 |
| local draft | editing、locally_valid、invalid、submitting、restored、cleared | 本地校验不表示owner接受 |
| preview | visible、restricted、stale、unavailable | 不展示未经验证的正文或URL |

这些状态是原型走查数据，不代表新增或改写正式状态枚举。

## 7. 评审维度与记录格式

评审按以下维度逐项记录：

| 维度 | 检查问题 |
|---|---|
| 信息层级 | 当前语境、主要内容和次要摘要是否容易区分？ |
| 导航 | 入口、thread进入/返回和辅助面板关闭后是否保持位置感？ |
| 状态可辨识 | pending、unknown、failed、stale、restricted等是否不会混为一谈？ |
| 安全边界 | 隐藏/撤销后是否及时遮蔽？是否暗示本地判断拥有权限？ |
| 操作反馈 | 操作后的下一步是否明确，是否把点击或ACK表现成成功？ |
| 可访问性 | 键盘操作、焦点顺序/返回、语义标签和状态播报是否完整？ |
| 窗口适配 | 窄窗口中导航、时间线、composer和详情是否仍可用？ |

每项发现记录：ID、页面/路径、观察到的问题、影响、建议决定、状态（open/resolved/deferred）、是否要求回退正式文档。原型走查发现不直接修改正式文档；需要改变正式结论时登记回到相应文档/Step处理。

## 9. 正式设计和实现的承接边界

- 原型是draft产品讨论材料，不是真相源，不替代正式00～07。
- 原型中的演示数据、交互按钮、状态切换不能成为owner schema、SDK method、授权逻辑或测试结果。
- 原型评审若改变需求、架构、概要结论，必须回到对应正式文档校准；若只调整布局/反馈表达，可记录为UI设计决定。
- 原型冻结后，真实实现仍按正式文档、实际SDK/owner合同和另行授权开展。
- 不将prototype HTML直接作为React组件或正式前端代码使用；可复用的是经评审确认的交互决策，而非原型实现事实。

# L5-chat 原型评审记录

> 评审阶段：P0 范围冻结与差异审查
> 状态：`reviewed_for_scope; formal_design_not_updated`
> 日期：2026-09-30
> 原型：`index.html`

## 1. 评审结论

当前原型可以作为 Desktop-first 协作客户端的产品探索版本继续评审。它已覆盖：

- 对话、thread、草稿、发送反馈和恢复状态；
- 项目列表与项目详情；
- 项目详情内的概览、项目进度、关联群聊、工作项和证据标签；
- 一个项目关联多个群聊；
- 群聊顶部进入绑定项目；
- 公司级成员目录，并区分身份、项目成员和群聊成员；
- 项目整体 BPMN 流程、阶段子流程和节点详情；
- 并行分叉网关、并行分支、并行汇聚网关和独立 Governance Gate；
- GateCard、Artifact 安全预览、Runtime / Agent / 工具活动安全摘要。

所有数据、状态和操作结果均为本地虚构演示。原型不连接 SDK、owner、内部 bus、服务 API 或正式缓存。

## 2. 已确认的产品决定

| ID | 决定 | 原型表现 | 正式设计处理 |
|---|---|---|---|
| PROTO-001 | 项目与项目进度合并 | 左侧只有“项目”，进度是项目详情标签 | 回到正式需求、架构和概要设计校准 |
| PROTO-002 | 一个群聊最多绑定一个项目，一个项目可关联多个群聊 | 群聊顶部有“项目”入口，项目详情列出多个关联群聊 | 由 Conversation / Work / SDK 合同确认 owner 与投影 |
| PROTO-003 | 群聊成员不从项目成员推断 | 群聊和项目分别显示成员范围提示 | 由 Conversation、Identity、Member 的可见性合同确认 |
| PROTO-004 | 软件提供公司级成员目录 | 成员标签展示公司人员安全摘要 | 由 Identity / Member 提供正式读取能力 |
| PROTO-005 | 项目流程支持层级下钻 | 项目进度 -> 阶段子流程 -> 节点详情 | 需求和架构中增加流程层级与深链接边界 |
| PROTO-006 | BPMN 并行结构使用独立分叉和汇聚网关 | 三条分支从并行分叉进入，经并行汇聚后进入治理 Gate | 不把并行网关与 Governance Gate 合并 |
| PROTO-007 | Chat 只读展示跨域摘要 | 节点、工作项、Agent、Artifact、测试均为安全摘要 | 不在 Chat 私造 owner truth 或完成判断 |

## 5. 原型边界审计

- 未把 HTML 节点坐标、颜色或演示状态写成正式 schema。
- 未把按钮点击、ACK、toast 或缓存命中表示为业务成功。
- 未把并行分支全部可见表示为汇聚完成。
- 未把并行汇聚网关和 Governance Gate 合并。
- 未展示真实 Artifact 正文、凭证、内部工具参数或内部 bus 事件。
- 未把项目成员推断为所有群聊成员。
- 未把公司成员目录当作授权目录；正式可见性仍归 Identity / Member / Conversation。
- 未关闭 L0-sdk 或 owner 的上游 blocker。

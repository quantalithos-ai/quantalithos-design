## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_position_boundary.md`
>
> 延伸阅读：
> - 建议阅读该文件的“边界声明表”“拥有 / 只呈现 / 禁止拥有摘要”和“关键边界反例”小节。

| 项目 | 结论 |
|---|---|
| 一句话定义 | `L5-console` 是组织治理与管理操作台的产品边界，负责把正式服务的管理查询和受控操作组织成可导航、可理解、可恢复且可访问的客户端体验。 |
| Console 拥有 | 页面导航与入口选择、客户端会话壳、表单草稿、筛选/排序/布局、view model、请求交互状态、错误恢复、焦点与可访问性呈现、有限且可失效的客户端偏好。 |
| Console 只呈现/编排 | 正式 actor/scope/visibility、owner query result、owner command receipt/result、source/version/freshness/coverage，以及治理、审计、指标、能力、归档和 sandbox 的安全状态/引用。 |
| Console 禁止拥有或推导 | 成员、项目、工作、过程、治理决定、制品/evidence、workspace projection、方法资产、能力注册、观测审计、归档、sandbox 执行、授权/审批/合规/readiness 结论及外部正文。 |
| 单独成仓原因 | 跨域管理入口、客户端交互状态和高风险反馈具有独立产品生命周期，必须与各 owner 的正式 truth 和日常协作产品分离。 |

最容易混淆的边界是：客户端 session 不是认证主体，菜单/route 不是授权，缓存不是当前业务事实，联合卡片不是治理结论，草稿不是正式对象，transport 成功不是业务完成，客户端诊断不是审计或 evidence。

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：
> - 建议阅读该文件的“业务背景”“现状诊断”“业务问题与技术问题”和“历史材料问题”小节。

### 3.1 业务背景

组织需要一个面向管理者、合规/审计人员、方法资产管理员和平台运营者的统一治理入口，用于理解员工、项目与 Workspace、方法资产、治理决定、审计/指标、能力、归档和 sandbox 的正式状态，并在资格允许时发起受控管理意图。日常协作和执行主流程由相邻产品或服务承接，Console 的价值在于可信地组织管理视图和入口。

### 3.2 当前问题

| 问题层 | 当前表现 | 造成的影响 |
|---|---|---|
| 业务体验 | 多个正式 owner 的状态和入口分散，用户难以确认当前语境、可见范围、结果来源和下一步。 | 管理判断慢，容易把缺失、过期或受限误读为不存在或正常。 |
| 权限与治理 | 页面、按钮、缓存或旧角色表可能被误当成授权/Policy/Gate 决定。 | 存在越权、对象存在性泄露和错误操作风险。 |
| 结果可信度 | 请求受理、页面刷新或 toast 可能被当成业务完成；跨域卡片可能被合成为单一健康/合规结论。 | 业务结果、治理 verdict、审计和 readiness 语义被伪造。 |
| 依赖与数据 | owner 合同、scope、safe-field、状态时效和降级语义尚未完全统一。 | 无法诚实声明所有正向页面已经可集成；原始正文复制会制造第二真相。 |

### 3.3 技术问题（需求层表达）

需要定义一个经 SDK/正式服务边界消费多 owner 结果的客户端产品边界，保留来源和状态语义，区分客户端交互事实与 owner truth，并在权限撤销、部分/过期/冲突/未知和辅助技术路径下保持安全、可理解和可恢复。具体协议、数据结构、组件与实现组织不在本需求层确定。

## 4. 目标与非目标

> 校准来源：
> - `design-calibration/00_req_step_04_goals_non_goals.md`
>
> 延伸阅读：
> - 建议阅读该文件的“目标表”“非目标表”和“目标验证口径”小节。

### 4.1 目标

| ID | 目标 | 判断口径 |
|---|---|---|
| `G-CON-001` | 建立可信的会话与正式访问语境。 | 受保护视图/意图可确认 actor/scope；语境不可验证时安全收紧。 |
| `G-CON-002` | 使导航、入口和动作资格可理解且不越权。 | 可见性/资格来自正式 owner；客户端不能放宽，受限解释遵守最小披露。 |
| `G-CON-003` | 提供来源保真的 owner-safe 管理查询和探索。 | 结果保留 source、当前性、coverage、availability、consistency，并区分空、缺失、裁剪和不可得。 |
| `G-CON-004` | 建立受控意图与正式结果确认边界。 | 草稿、提交/受理、处理中、确认、拒绝和 unknown 可区分；只有 owner 正式结果表示完成。 |
| `G-CON-005` | 覆盖组织治理与管理入口的主题范围。 | 八类管理主题均有 owner、可裁剪视图和回链；未闭口正向面保持 blocked/read-only/partial。 |
| `G-CON-006` | 建立保守降级、恢复和可访问底线。 | 失败状态可区分、局部故障隔离、恢复不重复副作用，适用核心目标可由键盘/辅助技术完成。 |
| `G-CON-007` | 建立可追溯且可继续设计的需求基线。 | 所有正式需求可追到故事、功能、规则、数据、接口、NFR 和验收；pending 不被写成 ready。 |

### 4.2 非目标

| ID | 非目标 | 归属/理由 |
|---|---|---|
| `NG-CON-001` | 成员、项目、工作、过程、治理、制品、workspace、方法、能力、观测、归档或 sandbox 真相维护本体。 | 归相应正式 owner。 |
| `NG-CON-002` | 本地认证、RBAC/Policy/Gate/审批/合规/readiness 裁决。 | 归 identity/governance 等正式 owner；Console 只呈现决定。 |
| `NG-CON-003` | 数据库、内部 repository/bus、服务源码直连或服务端跨域聚合替身。 | 违反 SDK/正式服务边界并制造第二真相。 |
| `NG-CON-004` | 证据、审计、报告、归档包、能力注册或 sandbox 执行正文的生成与保存。 | 归 artifact/observability/archive/capability/sandbox owner。 |
| `NG-CON-005` | Chat、Runner、Sync、Marketplace、Bridges 等相邻产品的主流程。 | 未停审项目仅保留 pending 协作候选。 |
| `NG-CON-006` | 固定控制项/指标集合、无 authority 的性能/SLA 阈值、Provider Contract 或前端技术框架。 | 需求不锁定无来源数字和实现选型。 |

## 5. 用户与角色

> 校准来源：
> - `design-calibration/00_req_step_05_users_roles.md`
>
> 延伸阅读：
> - 建议阅读该文件的“角色说明表”“能力级权限差异矩阵”和“角色边界”小节。

### 5.1 人类与系统角色

| 角色 | 类型 | 典型场景 |
|---|---|---|
| 组织管理者 | 人类 | 查看组织成员、项目/Workspace 和总体治理状态，发起正式开放的管理请求。 |
| 合规 / 审计角色 | 人类 | 审阅 Governance、SoA、AIIA、Control、Gate、审计、指标和 evidence 引用。 |
| 方法资产管理员 | 人类 | 浏览方法资产及版本，编辑客户端草稿，在资格允许时提交管理意图。 |
| 平台运营者 | 人类 | 查看能力、Archive、Sandbox 和平台诊断状态，发起正式开放的运维请求。 |
| 受限查看者 | 人类 | 查看其正式 scope 内的安全摘要、限制姿态和可达回链，不进行未获准管理操作。 |
| 可信会话/身份上下文提供方 | 系统 | 提供 actor/session/scope 语境和失效姿态；不由 Console 签发或推导。 |
| SDK 与正式 owner 服务 | 系统 | 提供 query、visibility/资格、command receipt/result 和安全引用；各自保有业务 truth。 |
| 异步结果/状态提供方 | 系统 | 在正式边界允许时提供状态变化或结果回查输入；不要求 Console 直接订阅内部事件主干。 |
| 安全诊断消费者 | 系统 | 接收经裁剪的客户端交互诊断；其输出不等于业务审计或 evidence。 |

角色名称表达使用意图，不是固定 role enum、认证主体或授权证明。“组织管理者”不自动拥有全组织数据，“审计角色”不自动拥有全部审计正文；实际可见性和动作资格由正式 owner 每次决定。

### 5.2 能力级权限差异

| 能力 | 组织管理者 | 合规/审计 | 方法资产管理员 | 平台运营者 | 受限查看者 |
|---|---|---|---|---|---|
| 查看 scope 内安全摘要 | 正式决定 | 正式决定 | 正式决定 | 正式决定 | 正式决定/受限 |
| 发起成员、项目或组织管理意图 | 意图相关/正式决定 | 通常只读 | 不适用 | 受限/正式决定 | 不适用 |
| 编辑并提交方法资产草稿 | 受限/正式决定 | 通常只读 | 意图相关/正式决定 | 不适用 | 不适用 |
| 查看治理、审计、指标和证据引用 | 正式决定 | 意图相关/正式决定 | 受限/正式决定 | 正式决定 | 受限/正式决定 |
| 发起能力、Archive 或平台运维意图 | 受限/正式决定 | 通常只读 | 不适用 | 意图相关/正式决定 | 不适用 |
| 理解受限、过期、部分和未知原因 | 必须可理解 | 必须可理解 | 必须可理解 | 必须可理解 | 按安全合同可理解 |

矩阵只说明产品需求差异，不授予权限、不定义继承，也不替代 Policy/Gate/visibility 决定。

## 6. 使用方与依赖

> 校准来源：
> - `design-calibration/00_req_step_06_consumers_dependencies.md`
>
> 延伸阅读：
> - 建议阅读该文件的“依赖裁剪表”“依赖类型分类”“禁止依赖”和“依赖裁剪图”小节。

### 6.1 依赖裁剪表

| 关联方 | 本仓消费/提供的能力边界 | 全局关系 | 主链范围 | 失效姿态 |
|---|---|---|---|---|
| `L0-core` | 共享安全引用、错误和关联语境定义。 | 编译期 | 核心前置 | 无法稳定解释来源/错误时收紧。 |
| `L0-sdk` | 官方 query、command、result、ref 和状态封装。 | 编译期 + 运行期 | 核心前置 | 不得改为私有直连；正向面 blocked。 |
| `L1-identity`、`L2-member-service` | actor/member、宿主和生命周期安全结果。 | 运行期 | 员工/语境主题 | 语境不可验证时整体 fail-closed；主题局部不可用。 |
| `L1-work`、`L1-process`、`L1-workspace` | 项目、工作、过程和 Workspace 安全视图/引用。 | 运行期 | 项目/Workspace 主题 | 分 owner partial/stale/unavailable；不推导进度 truth。 |
| `L1-governance`、`L1-artifact` | Policy/Gate/治理决定、状态和 evidence/artifact 引用。 | 运行期 | 治理主题 | 动作 blocked；缺引用不生成 verdict。 |
| `L3-method-library` | 方法资产目录/版本及正式管理结果。 | 运行期 | 方法主题 | 浏览或入口保持只读/blocked。 |
| `L3-capability-hub` | 注册、暴露、适配和访问复核状态/引用。 | 运行期 | 能力主题 | 局部降级；不推导 capability readiness。 |
| `L4-observability` | 审计、指标、lineage、验证和报告结果/引用。 | 运行期 | 审计/指标主题 | 只读 partial/unavailable；不自建审计。 |
| `L4-archive`、`L4-sandbox` | 归档/恢复/交接和隔离/运行/清理安全状态。 | 运行期 | 条件主题 | 保留多轴 blocked/unknown；不执行或推导 readiness。 |
| SDK 正式状态提示 | 失效/刷新提示，收到后重新查询。 | 事件协作（可选） | 增强路径 | 无提示时使用显式 query/revalidation。 |
| 其他未停审 L5/L6 | 未来安全 link/ref 候选。 | 运行期/不适用 | 非主链 | 仅 pending，不消费私有状态。 |

### 6.2 禁止依赖

Console 不得依赖任一 owner 的数据库、内部 repository、服务源码或内部 bus 私有订阅；不得维护业务 projection/cursor/replay；不得以本地 RBAC/Policy/Gate/合规/readiness 引擎替代正式决定；不得把 UI state 作为 owner truth；不得依赖未停审项目的私有状态。

### 6.3 裁剪关系图

```text
人类用户 --> L5-console [客户端交互与受控呈现]
                 ^
                 | compile/runtime
             L0-core / L0-sdk
                 ^
                 | runtime via SDK
       L1/L2/L3/L4 正式 truth owners

L0-bus --(仅由 SDK 封装的可选提示)--> 重新查询/失效呈现
未停审 L5/L6 --(未来正式 link/ref)--> pending，不是当前 truth
```

图示表达裁剪关系，不表示调用顺序、事件链或实施计划。

## 7. 核心能力闭环

> 校准来源：
> - `design-calibration/00_req_step_07_core_capability_loop.md`
>
> 延伸阅读：
> - 建议阅读该文件的“仓存在必要性”“核心能力节点”“闭环图”和“节点停审顺序”小节。

### 7.1 仓存在必要性

Console 的不可替代性不是拥有更多业务事实，而是把多个正式 owner 的管理能力安全转译成人类可使用的组织操作台：用户能确认语境、理解可见/可操作范围、读取带来源和状态的数据、形成受控意图、区分请求与正式结果，并在部分、过期、冲突、未知或权限撤销时得到保守且可访问的反馈。

### 7.2 六个核心能力节点

| 节点 | 成立描述 | 进入条件 | 退出结果 | 缺失后果 |
|---|---|---|---|---|
| `C-CON-1` 可信会话与访问语境 | 承接正式 actor/scope 语境并安全响应过期、撤销、不可验证。 | 产品壳可启动且语境可提供或明确不可用。 | 当前语境可判别；不可验证时不暴露受保护内容。 | 后续读取/操作整体失去可信主体，必须收紧。 |
| `C-CON-2` 导航、可见性与动作资格 | 依据正式 visibility/资格呈现 visible/restricted/disabled/unknown。 | C1 语境存在。 | 用户理解入口和动作上限及正式允许的解释。 | UI 可能被误当成权限决定。 |
| `C-CON-3` owner-safe 查询与视图解释 | 读取带 owner/source、freshness、coverage、availability、consistency 的安全结果。 | C1/C2 且有正式 read surface。 | 可理解、不可反写的视图和安全回链。 | 页面可能伪造完整性、当前性或强一致。 |
| `C-CON-4` 受控意图与正式结果确认 | 隔离草稿、提交意图、呈现 receipt/pending/confirmed/rejected/unknown。 | C1/C2 且 owner 正式开放 command（如适用）。 | 用户知道提交经历和 owner 正式结果。 | toast/HTTP/乐观状态会冒充业务成功。 |
| `C-CON-5` 管理主题视图、回链与受控入口 | 在 C1~C4 基础上组织八类主题的可裁剪消费面。 | 对应 owner read/command/ref 合同。 | 授权用户理解正式状态并到达 owner 结果。 | 产品只剩通用壳，无法承接管理入口价值。 |
| `C-CON-6` 保守降级、恢复与可访问交互 | 区分 partial/stale/missing/unavailable/conflict/unknown，提供安全恢复和等价辅助技术路径。 | C1~C5 任一状态，包括失败。 | happy/non-happy path 可理解、可恢复、不误导。 | 失败时泄露、误放行或使用户无法操作。 |

### 7.3 逻辑依赖与层级

```text
C1 -> C2 -> C3 -> C4 -> C5 -> C6
 ^                         |
 +------ revalidate/requery+
```

箭头只表示能力成立依赖和反馈闭合，不表示运行时调用、路由顺序或实施顺序。只读主题可在 C1→C2→C3→C5→C6 下成立；没有正式 command 的页面必须明确只读/blocked。

| 能力层级 | 范围 |
|---|---|
| 核心闭环 | `C-CON-1~6`；启用的每个主题都经过适用节点。 |
| 外围增强 | 个性化 dashboard、趋势/比较、批量处理/导出、评审模板、跨产品快捷入口。 |
| 边界外 | owner truth、授权/治理/合规/readiness 裁决、数据库/服务端聚合、证据/归档/sandbox 执行本体及其他产品主流程。 |

### 7.4 C5 管理主题范围

### 9.3 共同行为与逻辑依赖

- 每项功能的输入只可来自用户意图、Console 自有交互状态或正式 owner-safe 结果；输出只形成交互呈现、受控请求姿态或正式结果的忠实显示。

- 只读主题不要求正向 command 成立；没有正式 command 时必须明确只读或 blocked。
- 功能成立依赖为 `FR-CON-001/002 → 003/004 → 005/006 → 007/008/009（仅适用写能力）→ 010~015`；`FR-CON-016~018` 横切并闭合全链。该顺序不是页面、调用、网络或实施顺序。

| `BR-CON-017` | 边界约束 | Console 只拥有意图草稿和请求交互状态；副作用、领域校验、幂等决定和最终结果归 owner。 |

| `BR-CON-019` | 审计约束 | 对 owner 要求可追溯的请求，只展示正式 receipt/result/audit/evidence 引用；不得自制引用或用客户端诊断冒充审计。 |

### 10.3 管理主题真相规则

| ID | 类型 | 规则 |
|---|---|---|
| `BR-CON-020` | 不变量 | 每个管理区域保留正式 owner、来源引用和能力上限；联合视图不产生跨域 truth。 |
| `BR-CON-021` | 禁止行为 | Console 不得拥有、重定义或裁定 identity/member、project/work/process、governance、artifact、workspace、method、capability、observability、archive 或 sandbox truth。 |
| `BR-CON-022` | 禁止行为 | 不得以 UI 状态、固定控制/指标数量、客户端阈值、颜色、缓存或局部结果推导审批、合规、审计、能力、归档、运行或 readiness。 |
| `BR-CON-023` | 显式变化 | owner 区域从 blocked/read-only/partial 变为正向可用，必须依据该 owner 当前正式合同和资格，不得由计划或前端开关启用。 |
| `BR-CON-024` | 边界约束 | Governance/SoA/AIIA/Control/Gate 决定归 governance，evidence/artifact 正文归 artifact；Console 只呈现正式状态和安全引用。 |

| `BR-CON-026` | 治理约束 | 管理页面不得绕过 owner Policy/Gate/visibility；正式决定 unknown、冲突、撤销或过期时采用保守上限。 |
| `BR-CON-027` | 审计约束 | 客户端诊断只说明交互/请求经历，不能替代 Observability audit、Artifact evidence 或 owner 正式历史。 |

### 10.4 降级、恢复与外围规则

| ID | 类型 | 规则 |
|---|---|---|
| `BR-CON-028` | 不变量 | 非理想状态须以文本/语义可判别且不只依赖颜色；无法安全分类时标为 unknown 并收紧。 |
| `BR-CON-029` | 禁止行为 | partial、stale、missing、restricted、unavailable、conflict 或 unknown 不得归一为空、成功、绿色、合规或 ready。 |
| `BR-CON-030` | 显式变化 | 重试、重验、回查或来源恢复后的状态必须显式更新；旧状态不能继续被当作当前事实。 |
| `BR-CON-031` | 边界约束 | 一个 owner 的故障/过期只影响可证明依赖它的区域；不得覆盖其他 owner 状态或用其他成功掩盖该失败。 |
| `BR-CON-032` | 不变量 | 可访问交互覆盖与视觉路径等价的语境、资格、读取、确认、结果、错误和恢复目标。 |

| `BR-CON-E01` | 边界约束 | 个性化布局和快捷入口只改变呈现偏好，不得改变 visibility、资格、数据优先级或 owner truth。 |
| `BR-CON-E02` | 不变量 | 趋势/比较只在来源正式声明可比较语义和 coverage 时成立，否则保持不可比较。 |
| `BR-CON-E03` | 禁止行为 | 批量受理或批次摘要不得解释为每项正式成功；部分失败必须逐项可判别。 |

### 11.5 Forbidden-body 总边界

以下正文不得成为 Console 持久 truth、离线替身、诊断载荷或第二业务仓：credential/secret/identity-authority proof；Policy/Gate 内部规则或授权证明；hidden/redacted/raw service payload；member/project/work/process/workspace/method 正文；governance decision internals；artifact/evidence/audit/metric/report 正文；capability registration、archive package、sandbox execution 正文；以及含上述内容的 diagnostic/error/export/log payload。owner-safe 查询可临时呈现获准内容，但 exact safe-field 未闭口时采用更小上限。

### 12.3 同步、异步与结果语义

| 边界 | 需求口径 | 明确不代表 |
|---|---|---|
| query / visibility / qualification | 页面或用户需要时取得可判别结果；失败按 identity fail-closed 或 owner 局部降级。 | 不承诺协议或延迟阈值。 |
| command submission | 用户明确确认后提交；返回可为 rejected/accepted/pending/unknown。 | accepted 或 transport success 不等于 committed。 |
| result reconciliation | owner 支持时按正式 receipt/ref 回查；不支持则保持 unknown/blocked。 | 不允许无依据重放或本地推导。 |
| SDK state notification | 可选失效/刷新提示，收到后重新校验/查询。 | 不是业务事件 truth、projection、cursor 或完成证明。 |
| owner asynchronous work | 只呈现正式 task/result/ref 当前状态。 | Console 不执行后台任务或决定终态。 |
| Console output | 当前无业务事件；只有条件化安全诊断或产品链接。 | UI 状态、草稿和缓存不供下游作业务 truth。 |

| `NFR-CON-003` | 性能 | 不得以无界跨域 fan-out、重复自动查询或 unknown 命令重放放大 owner 负载。 | 用户意图可归因到必要 owner；局部刷新不要求无关 owner 同步完成。 |
| `NFR-CON-004` | 可用性 | 正式 actor/scope 不可验证、过期或撤销时，受保护内容和动作 fail-closed。 | 所有受保护路径停止披露/提交，旧缓存不能放行。 |
| `NFR-CON-005` | 可用性 | 单一 owner 故障、过期或部分结果不得无依据拖垮其他区域，也不得被其他成功掩盖。 | 影响按来源隔离；壳、本地草稿及不依赖该 owner 的已授权区域保持明确姿态。 |
| `NFR-CON-006` | 可用性 | 未开放/未激活的 query/command/export/report 稳定呈现 read-only/partial/blocked。 | 不使用假接口、私有直连、静默 fallback 或伪数据。 |
| `NFR-CON-007` | 安全 | 所有业务读取和意图提交经 SDK 或正式服务边界，客户端可见性只能更保守。 | 无 DB/repository/内部 bus/服务源码旁路、本地 RBAC 放宽或 Policy/Gate 绕过。 |
| `NFR-CON-008` | 安全 | credential、授权/治理证明、隐藏字段及 forbidden body 不得进入 Console 自有数据、诊断、错误、日志或导出。 | 仅 owner-safe snapshot/ref 可进入；无法证明安全则拒绝或裁剪。 |
| `NFR-CON-009` | 安全 | scope、visibility、资格或对象可见性变化须在后续显示/动作前重新约束，受限解释不得泄露对象存在性。 | 撤销/过期/冲突/unknown 后旧允许姿态失效，直接入口与已开页面同样受限。 |
| `NFR-CON-010` | 审计/可追溯 | 业务状态、治理决定、evidence、audit/metric 和运行状态声明须回指 owner/source/version 或安全引用。 | 无正式引用时明确 unknown/missing，不由页面补造。 |
| `NFR-CON-011` | 审计/可追溯 | 管理意图区分草稿、提交经历、owner receipt、处理中与正式结果，并在 owner 提供时保留引用。 | “完成/拒绝”均有正式 result/ref；HTTP、toast、缓存刷新和诊断不能独立证明结果。 |
| `NFR-CON-012` | 审计/可追溯 | 客户端诊断与正式 audit/evidence/业务历史在语义和呈现上分离。 | 诊断只证明经裁剪的交互/请求经历，除非 owner 正式接纳，否则不构成正式结论。 |
| `NFR-CON-013` | 幂等/一致性 | 同一业务事实只采用正式 owner 单一语义；snapshot、view model、缓存和联合视图不形成第二 truth。 | 保留 source/freshness/coverage/availability/consistency；跨 owner 不宣称原子、完整或统一当前。 |
| `NFR-CON-014` | 幂等/一致性 | 未提交、submitted/accepted、pending、confirmed、rejected、unknown 保持不同；unknown 时不得无正式依据重放。 | 有副作用意图始终有不夸大的姿态；优先正式回查，不可回查则保持 unknown。 |
| `NFR-CON-015` | 幂等/一致性 | 草稿、筛选和布局只影响客户端交互，不得改变 owner 数据、资格、治理结论或业务优先级。 | 查询、刷新、恢复和偏好变化无业务副作用，只有明确受控提交可触发意图。 |
| `NFR-CON-016` | 可观测性 | 安全地区分并关联客户端语境、owner 依赖、查询、提交、回查、降级和恢复姿态。 | 用户可见失败可定位能力/owner、客户端阶段与安全关联引用，不暴露正文。 |
| `NFR-CON-017` | 可观测性 | 诊断 sink 缺失、延迟或失败不得改变业务结果、放宽权限、阻断安全恢复或被当成 owner 失败。 | 诊断故障不改变相同输入下的业务呈现与正式结果语义。 |
| `NFR-CON-018` | 可观测性 | partial、stale、restricted、unavailable、conflict、unknown、回查中和恢复结果须在产品与安全诊断中一致可区分。 | 无法分类统一使用 unknown，不归一成空或成功。 |
| `NFR-CON-019` | 可访问性 | C1~C6 的语境、导航、查询、草稿/确认、主题、错误和恢复须能由键盘及受支持辅助技术完成。 | 每条适用核心路径有等价非指针路径；任一关键目标不能完成即不通过。 |
| `NFR-CON-020` | 可访问性 | 资格、状态、来源、错误、危险确认和结果变化不得只依赖颜色、位置、动画或瞬时提示。 | 每种语义有可感知文本/名称/状态，动态变化适当播报且不丢焦点。 |
| `NFR-CON-021` | 可访问性 | partial/stale/unknown、validation error 和提交结果为辅助技术用户提供与视觉用户相同的恢复选择和安全上限。 | 非视觉路径能理解、定位并执行同一获准恢复，不形成越权或死路。 |

旧文档中的首屏 `<2s`、过滤/导航 P95、`99.9%/99.95%` 可用率或 SLA、固定 `38` 个控制项和 `8` 个指标均无当前 authority，不进入目标。精确性能、负载、兼容和可用率数字只有在场景、测量边界、环境、窗口、owner 与证据来源明确后才可后续定义；forbidden body、本地授权放宽和 unknown 自动重放保持零容忍语义底线。

## 14. 验收标准

> 校准来源：
> - `design-calibration/00_req_step_14_acceptance_criteria.md`
>
> 延伸阅读：
> - 建议阅读该文件的“核心能力闭环验收”“功能/规则/数据/NFR 验收”“一票否决项”和“跨能力验收审计”小节。

本章定义未来验证条件，不声明测试、证据采集、报告、verdict 或 signoff 已发生。

### 14.1 核心能力闭环验收

| ID | 验收条件 |
|---|---|
| `AC-CON-001` | 受保护视图/意图均可确认正式 actor/scope；语境不可验证、过期、撤销或冲突时停止披露/动作，并给出最小披露恢复方向。 |
| `AC-CON-002` | 入口和动作不超过正式 visibility/资格；restricted/unknown/unavailable 可理解且不泄露存在性；route/menu/button/本地角色不能授权。 |
| `AC-CON-003` | 查询保留 owner/source、freshness、coverage、availability、consistency，区分空、未覆盖、裁剪、过期、部分和不可得；探索不改变事实。 |
| `AC-CON-004` | 草稿、提交/受理、处理中、confirmed、rejected、unknown 可区分；只有 owner 正式结果表示完成；unknown 不自动重放。 |
| `AC-CON-005` | 八类管理主题在 owner 范围内呈现安全状态/回链；未闭口面为 read-only/partial/blocked，不生成第二 truth、verdict 或 readiness。 |
| `AC-CON-006` | 非理想状态可感知区分，并能安全重验、重试、回查或退出；键盘、读屏及其他受支持辅助技术能完成全部适用核心目标。 |
| `AC-CON-007` | C1~C6 整体闭合；owner 局部故障不被错误扩散或掩盖；重新验证/查询反馈回语境、资格和视图；无 command 时只读闭环仍诚实成立。 |

### 14.2 功能验收

| ID | 验收条件 | 功能来源 |
|---|---|---|
| `AC-FR-001` | 语境锚定、显式转换与失效保护可观察；不可验证时安全收紧。 | `FR-CON-001~002` |

| `AC-FR-003` | owner-safe 读取、筛选、排序、分页、摘要和下钻保留来源/状态并区分空与缺失。 | `FR-CON-005~006` |
| `AC-FR-004` | 草稿、复核、条件提交、结果分层和 unknown 回查不把 transport/UI 状态当成业务完成。 | `FR-CON-007~009` |
| `AC-FR-005` | 员工消费面仅呈现 identity/member-service 正式摘要、引用和开放入口；缺 surface 时只读/partial/blocked。 | `FR-CON-010` |
| `AC-FR-006` | 项目/工作/过程/Workspace 分 owner 呈现安全结果、coverage 和回链，不生成进度或 Workspace truth。 | `FR-CON-011` |

| `AC-FR-012` | 页面结构、状态、确认、错误和恢复对键盘、读屏及其他受支持辅助技术可感知、可操作并与视觉目标等价。 | `FR-CON-018` |
| `AC-FR-013` | 外围能力只在正式合同具备时启用；偏好不改权限，趋势不伪造可比性，批量结果不冒充整体成功。 | `FR-CON-E01~E03` |

外围增强无需以正向实现证明当前核心闭环；合同未闭口时，安全不启用或 blocked 即是当前需求边界。

### 14.3 规则、数据与质量验收

| ID | 类别 | 验收条件 |
|---|---|---|
| `AC-BR-001` | 语境边界 | 受保护内容/意图绑定正式语境；Console 不签发 credential 或定义 identity/role/scope；变化显式生效。 |
| `AC-BR-002` | 资格边界 | 入口/动作不超过正式结果；route/menu/button/flag/local role/cache 不授权；受限原因最小披露。 |
| `AC-BR-003` | 查询边界 | 查询与客户端聚合 no-write，来源和状态语义不被消平，所有业务读取经 SDK/正式边界。 |
| `AC-BR-004` | 意图边界 | 草稿、受理、处理中和正式结果分层；UI/transport 不代表完成；unknown 不自动重放；治理与引用不被替代。 |
| `AC-BR-005` | truth 边界 | Console 不拥有列明 owner 的 truth、不以 UI/固定数量/阈值推导结论，owner 执行与 projection 不迁入。 |
| `AC-BR-006` | 降级/a11y | 非理想状态不归一成成功/合规/ready；故障局部隔离、恢复显式更新、辅助技术目标等价。 |
| `AC-BR-007` | 外围边界 | 个性化不改权限；比较仅在 owner 声明可比时成立；批量逐项可判别；缺合同时不启用。 |
| `AC-DR-001` | 自有交互真相 | 会话壳、导航/布局、探索意图、草稿、请求呈现、恢复/a11y 状态与偏好只表示 Console 交互事实。 |
| `AC-DR-002` | owner-safe 快照 | 语境/资格及 owner 摘要只在安全合同允许时存在，并随 owner/语境/可见性更新或撤除。 |
| `AC-DR-003` | 外部引用 | 对象、版本、receipt/result、治理、artifact/evidence、audit/metric/report、capability/archive/sandbox 只作安全引用。 |
| `AC-DR-004` | forbidden body | credential/secret、授权/治理证明、raw/hidden payload 及业务/证明/执行正文不进入数据、日志、诊断、错误或导出生命周期。 |
| `AC-DR-005` | 归属无重复 | 同一正式事实不被 Console 同时声称为 truth 或替代 owner 的快照；联合视图保留分域来源、coverage 和状态。 |
| `AC-NFR-001` | 性能/负载 | 本地交互不因无关 owner 阻塞；查询/回查有可解释进展或局部降级；无界 fan-out、重复自动查询和 unknown 重放不是默认行为。 |
| `AC-NFR-002` | 可用性 | 语境不可验证时 fail-closed；owner 故障局部隔离；未开放能力稳定为 read-only/partial/blocked。 |
| `AC-NFR-003` | 安全 | 业务访问经正式边界，无本地授权放宽、Policy/Gate 绕过、forbidden body 或撤销后沿用旧权限。 |
| `AC-NFR-004` | 可追溯 | 管理声明回指 source/version/ref；意图结果分层；客户端诊断与正式 audit/evidence 分离。 |
| `AC-NFR-005` | 幂等/一致性 | owner truth 单一；snapshot/view model 不成为第二 truth；unknown 不自动重放；本地交互无副作用；跨 owner 不伪装原子一致。 |
| `AC-NFR-006` | 可观测性 | 能安全区分语境、owner、query、submit、reconciliation、degradation、recovery；诊断故障不改变业务结果、权限或恢复安全。 |
| `AC-NFR-007` | 可访问性 | 所有适用 C1~C6 路径可由键盘及受支持辅助技术完成；状态不只靠视觉；非视觉路径具有等价恢复与安全上限。 |

### 14.4 一票否决项

| ID | 一票否决情形 |
|---|---|
| `VETO-CON-001` | 通过 DB、内部 repository/bus、服务源码旁路或本地聚合规则取得/修改业务事实，或形成 owner truth 替代投影。 |
| `VETO-CON-002` | actor/scope/visibility/资格不可验证、撤销或冲突时仍披露受保护内容、对象存在性或危险动作。 |
| `VETO-CON-003` | 用 HTTP/SDK 成功、toast、缓存、刷新或乐观状态宣称完成，或对 unknown 副作用请求无依据重放。 |

| `VETO-CON-005` | UI、固定控制/指标数量、客户端阈值或局部结果被用于生成审批、合规、审计、能力、归档、运行或 readiness 结论。 |

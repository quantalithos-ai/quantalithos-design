## 1. 与 `product/` 的关系声明

L5-console 是**产品叙事直推型**需求仓。`product/产品矩阵.md` 已明确:
- Console 是与 Chat 互补的**治理视角**产品

本文把这些产品叙事收敛为 Console 仓的可执行需求与验收口径。

## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 不只需要协作入口,还需要一个让组织能**管理 AI 员工、审查治理资产、查看合规证据、追踪跨项目状态**的治理操作台。Chat 擅长承载“正在发生的协作”,但不适合承载跨组织员工管理、方法资产维护、SoA/AIIA 评审、哈希链验证、DORA/EBM 指标分析等治理任务。L5-console 因此必须成为组织级治理与观测入口：企业管理者、合规官、方法论制定者和审计角色都应能在这里获得高密度、低歧义、可追责的操作与查询能力。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 3 当前) | 痛点 |
|---|---|---|
| 仓文档 | 只有 README 骨架 | 端侧产品型第二份样板尚未建立 |
| 治理真相源 | `L1-governance` 已完成 00/01 | UI 如何消费 Gate/Policy/SoA/AIIA 尚未仓级化 |
| 审计中心 | `L4-observability` 已完成 00/01 | 管理评审、哈希链验证、lineage 查询入口未产品化 |
| 能力池 | `L3-capability-hub` 已完成 00/01 | MCP/Provider 管理体验未落到 Console 需求 |
| 方法库 | `L3-method-library` 已完成 00/01 | Role / Template / ViewProfile / Policy 资产编辑入口未定义 |

### 2.3 为什么要做(量化依据)

- `product/产品矩阵.md` 把 Console 定义为 **⑤ 组织治理中心**，不是附属页面
- `L1-governance` 已定义 SoA 必须覆盖 **38 控制项**、Policy 下发生效 `< 30s`、Gate/Policy/Nonconformity 全链留痕,这些都需要一个组织级可视化与操作入口
- `L4-observability` 已要求 DORA / EBM / 42001 §9.1 指标可查,Console 是这些能力的首要消费者
- 若没有 Console,平台只能协作不能治理,企业场景无法闭环

### 2.4 业务问题 vs 技术问题

- **业务问题**:组织如何高效治理 AI 员工、方法资产、合规证据与运行指标
- **技术问题**:多域数据聚合、显式权限模型、审计回放、哈希链验证、SoA/AIIA 视图、能力池管理、跨项目/跨域 drill-down、指标大盘与管理评审流

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 管理者招聘 / 暂停 / 退休员工并查看成员状态
2. 方法制定者编辑 Role / Template / Policy / ViewProfile
3. 合规官查看 SoA / AIIA / Nonconformity 全链路状态
4. 审计员按项目/成员/域/时间窗口回放审计事件并验证哈希链
5. 平台运营查看 DORA / EBM 指标与告警

## 9. 数据需求

### 9.1 核心业务实体

| 实体 | 归属域 | 聚合根 | 生命周期 |
|---|---|---|---|
| GlobalMember | identity | GlobalMember | hired → active → paused / retired |
| Project | work | Project | draft → active → archived / dissolved |
| Gate | governance | Gate | pending → decided / expired |
| Policy | governance | Policy | draft → active → superseded / retired |
| SoA | governance | SoA | drafted → published → superseded |
| AIIA | governance | AIIA | created → approved / superseded |
| Nonconformity | governance | Nonconformity | raised → resolved / closed |
| AuditEvent | observability | append-only | 长期保留 |
| CapabilityDecision / ProviderContract | capability-hub | CapabilityDecision / ProviderContract | active / paused / retired |

### 9.2 数据关系图

```text
Console
  ├─ identity: members / roles
  ├─ work/process: projects / stage / progress
  ├─ governance: gate / policy / SoA / AIIA / nonconformity
  ├─ observability: audit / lineage / metrics / hash verify
  └─ capability-hub: MCP / provider / cost summary
```

### 9.3 数据生命周期与归档

| 数据类型 | 保留期 | 归档策略 | 删除策略 |
|---|---|---|---|
| 本地筛选/布局状态 | 会话级 | 本地存储可重建 | 自动淘汰 |
| 审计查询结果缓存 | 短期 | 前端短缓存 | 自动失效 |
| 导出报告索引 | 短中期 | 由下游服务管理工件 | 前端不长期持有 |
| 管理偏好设置 | 中期 | 用户级配置 | 可重建或手动清除 |

### 9.4 隐私与合规要求

| 数据字段 | 敏感级别 | 保护措施 | 合规依据 |
|---|---|---|---|
| 全量审计事件正文 | 高 | 仅授权角色可见 | 审计最小权限 |
| 员工职业生涯与上下文摘要 | 中高 | 按组织权限控制 | 隐私与审计基线 |
| Provider/能力池成本明细 | 中高 | 仅管理与审计角色可见 | 财务/治理要求 |
| AIIA/SoA 证据链接 | 高 | 受限显示与导出审计 | ISO 42001 |

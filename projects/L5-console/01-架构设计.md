## 2. 业务背景与驱动力

> 校准来源：
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“业务背景与结构性驱动力”“架构目标表”“设计取舍”和“待确认事项”小节。

`L5-console` 是 L5 产品/分发层的组织治理与管理入口。它的架构价值不在于拥有跨域业务事实，而在于把多个正式 owner 的管理查询和受控意图安全地转译为可导航、可理解、可恢复且可访问的客户端体验。多 owner 的来源、时效、覆盖、一致性和正式结果语义彼此独立，权限撤销、部分数据、过期、冲突和 unknown 又必须跨页面保持同一安全上限，因此需要独立的客户端边界、来源保真结构和恢复语义。

结构性驱动力包括：多个 owner 能力需要统一的人类入口；正式语境和资格可能撤销或冲突；查询结果不能被压成单一当前性；受控意图可能在受理后延后完成或保持 unknown；owner 合同成熟度不同；客户端自身仍需维护导航、草稿和恢复连续性；失败与辅助技术路径必须属于产品主链，而非事后补丁。

| 架构目标 | 说明 |
|---|---|
| 承载独立的 Console 客户端交互真相边界 | 防止导航、会话壳、筛选/布局、草稿、请求呈现和偏好散落到业务 owner，或被误当成业务 truth。 |
| 支撑正式 actor/scope/visibility/资格约束下的管理入口 | 防止失效语境或客户端状态继续放行受保护内容和动作。 |
| 保持 owner-safe 查询的来源、多轴状态和安全回链 | 防止缺失、过期、部分或冲突被误读为完整、当前或一致事实。 |
| 分离客户端意图、请求经历与 owner 正式结果 | 防止 transport/accepted/toast 冒充业务完成并触发重复副作用。 |
| 以 owner 分域方式承载八类管理主题的可裁剪消费面 | 防止管理入口退化为空壳，或形成成员、治理、审计、能力和运行的第二真相。 |
| 支撑局部故障隔离、保守恢复和可访问等价路径 | 防止单一 owner 故障扩散，以及用户在 partial/stale/unknown 或撤销状态下无法安全操作。 |
| 允许外部合同逐步闭口时保持可替换、可追溯的架构接缝 | 防止 pending 被伪装成 integrated/ready，并为后续设计保留诚实的演进边界。 |

## 3. 约束条件

> 校准来源：
> - `design-calibration/01_arch_step_01_requirement_baseline.md`
> - `design-calibration/01_arch_step_02_goals_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“架构硬约束清单”“不可变约束表”“当前阶段可接受取舍表”“架构非目标表”和“待确认事项”小节。

### 3.1 不可变约束

| 约束 | 说明 |
|---|---|
| 不拥有或重定义外部 truth | identity/member、project/work/process、governance、artifact/evidence、workspace、method、capability、observability、archive 和 sandbox truth 均归相应 owner。 |
| 不绕过正式访问边界 | 所有业务读取和受控意图必须经 `L0-sdk` 或正式服务边界；不得直连数据库、repository、服务源码、私有 bus 或自建跨域聚合后端。 |
| 客户端只能收紧正式决定 | 菜单、route、按钮、feature flag、角色字符串、缓存命中和 UI 状态都不得放宽 visibility、资格、Policy 或 Gate。 |
| 不压平来源和多轴状态 | owner/source、freshness、coverage、availability、consistency，以及正式空、缺失、裁剪和 unknown 必须保持可区分；不得合成统一 verdict/readiness。 |
| 请求经历与正式结果分层 | 草稿、提交、receipt/accepted、pending、confirmed、rejected 和 unknown 必须可区分；只有 owner 正式结果表示业务完成，unknown 无正式依据不得自动重放。 |
| Forbidden body 零进入 | credential、secret、授权/治理证明、raw/hidden payload、外部正文、内部规则和 audit/evidence/report/package 正文不得进入 Console 持久、缓存、错误、日志、诊断或导出生命周期。 |
| 安全前置 fail-closed，业务故障局部隔离 | actor/scope/visibility/资格不可验证、过期、撤销或冲突时必须收紧；单一 owner 的故障、过期和部分结果不得无依据扩散或被其他成功掩盖。 |
| 本地状态只改变交互呈现 | 导航、筛选、布局、草稿、偏好、安全影子和诊断不得改变 owner 数据、资格、治理决定、业务优先级或 readiness。 |
| Pending 不得伪装为完成 | 未闭口的 exact surface、字段、scope、activation、量化 authority 和外围产品合同不得被写成 integrated/ready，也不得由 mock 或历史协议补齐。 |

### 3.2 当前阶段可接受取舍

| 取舍 | 当前口径 |
|---|---|
| Owner exact query/command/result/ref 尚未统一 | 只定义能力级接缝和安全上限；相关主题按 owner 独立保持 `pending/blocked/read-only/partial`。 |
| Scope、visibility/资格 reason 和 safe-field 尚未统一 | 只承接外部正式语境、最小披露与客户端收紧，不发明共同字段模型。 |
| Unknown reconciliation/幂等尚未闭口 | 允许正式回查或保守挂起；没有正式依据时不自动重试潜在副作用。 |
| 多 owner 状态不作原子联合 | 接受分域、不同步和局部降级，不生成统一健康、合规或 readiness。 |
| SDK 状态提示不是成立前置 | 显式 query/revalidation 是基线；只有 SDK 正式封装的提示可作为失效优化。 |
| 客户端状态生命周期和介质未定 | 只确认有界交互事实与可失效安全影子；TTL、跨设备和持久化介质后移。 |
| 性能、可用率、浏览器/辅助技术组合和诊断 envelope 无 authority | 先采用有界、可归因、局部隔离与可访问等价的行为口径，不写数值承诺。 |

### 3.3 架构非目标

| 非目标 | 不展开原因 |
|---|---|
| 不设计认证、credential、身份签发、scope 模型或本地 RBAC | 属于身份、安全入口及正式授权 owner；Console 只消费允许呈现的安全语境。 |
| 不设计 Policy/Gate/审批、合规、审计 verdict 或 readiness 引擎 | 属于治理、观测、能力、归档、Sandbox 等正式 owner。 |
| 不承载外部业务、治理、证明或执行正文 | 各对象已有单一 owner；Console 只呈现安全快照、引用与正式入口。 |
| 不设计数据库、repository、内部 bus、服务端聚合、projection/cursor/replay/rebuild 或跨域事务 | 这些会把客户端产品变成隐性后端或第二真相。 |
| 不设计相邻 L5/L6 产品的主流程和私有状态 | 尚未停审内容只能是未来正式 link/ref 候选。 |
| 不在本章体系固定框架、图库、API path、DTO、源码目录、数据表或配置参数 | 它们属于后续概要、详细或配置设计，且必须先有正式合同。 |
| 不生成验证或交付事实 | 当前不生成或声称 baseline、测试结果、run、artifact、report、evidence、verdict、signoff 或 readiness。 |

## 4. 职责边界

> 校准来源：
> - `design-calibration/01_arch_step_03_responsibility_boundary.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“职责边界表”“做 / 不做清单”“易混淆职责表”“边界红线清单”和“待确认事项”小节。

`L5-console` 的职责是把多个正式 owner 的管理能力组织成可信、可导航、可恢复且可访问的客户端体验。Console 拥有会话壳、导航、筛选/布局、表单草稿、请求经历、错误/恢复、可访问交互和有限偏好等交互事实；它只消费并忠实呈现正式语境、资格、owner-safe 快照、结果和引用，不拥有或推导外部业务、治理、证明或运行 truth。

| 职责项 | 类型 | 说明 |
|---|---|---|
| 客户端会话壳、导航与交互连续性 | 做 | 管理当前入口、探索选择和连续体验，但不把连续性解释为认证或持续授权。 |
| 正式 actor/scope/visibility/资格姿态的安全呈现 | 做 | 忠实呈现正式决定及获准解释粒度，不生成 allow/deny。 |
| Owner-safe 查询、来源状态与安全回链的客户端组织 | 做 | 让 source、freshness、coverage、availability 和 consistency 可理解，不改变来源事实。 |
| 筛选/排序/布局、未提交草稿和提交前复核 | 做 | 维护用户探索与意图的交互事实；草稿不是正式对象、批准或命令受理。 |
| 请求经历与 owner 正式结果的分层呈现 | 做 | 区分提交、受理、处理中、确认、拒绝和 unknown，不替 owner 宣布完成。 |
| 八类管理主题的 owner-partitioned 消费入口 | 做 | 组织员工、项目/Workspace、方法、治理/evidence、审计/指标、Capability、Archive 和 Sandbox 的安全消费面。 |
| 局部错误、部分/过期/冲突/未知的解释与恢复 | 做 | 提供遮蔽、重验、重查、退出和安全草稿保持，不修复 owner truth。 |
| 焦点、键盘、读屏与非颜色语义的等价路径 | 做 | 使语境、资格、数据、确认、错误和恢复可感知、可操作。 |
| 安全裁剪的客户端交互诊断 | 做 | 可说明交互/请求经历，但诊断不升级为 audit、evidence 或业务历史。 |
| 身份、认证、credential、actor/session/scope 正式 truth | 不做 | 归身份或安全入口 owner；Console 只消费安全语境。 |
| 成员、项目、工作、过程、Workspace、方法等对象 truth | 不做 | 生命周期、正文、版本和业务规则归相应 owner。 |
| Governance/SoA/AIIA/Control/Gate/Policy 决定与审批裁决 | 不做 | Console 只能呈现正式决定和安全引用，不能生成、放宽或替代。 |
| Artifact/evidence/audit/metric/report 正文、版本链与正式 verdict | 不做 | Console 只消费安全摘要/引用和正式结果。 |
| Capability 注册/适配/secret/readiness，Archive 包体/恢复事实，Sandbox 执行隔离 | 不做 | 执行、注册、生命周期和终态归各 owner。 |
| 领域副作用、服务端校验、幂等决定、reconciliation 和最终结果 | 不做 | Console 只提交受控意图并呈现 owner 结果，不复制服务端规则。 |
| 数据库、repository、私有 bus、服务源码和相邻产品私有状态 | 不做 | 这些会绕过正式边界或引入未停审真相。 |

易混职责必须按以下上限理解：客户端 session 壳不是认证主体；入口可见不等于授权；view model 或安全快照不是业务 truth；联合视图不是跨域 verdict/readiness；草稿、receipt 和 pending 不是正式对象或 committed result；客户端诊断不是 audit/evidence；管理入口不接管 owner 主流程；分域状态不推导整体 readiness。任何 route、按钮、颜色、缓存、toast、固定数字或历史合同都不能改变这些职责边界。

### 5.3 失效与降级边界

| 失效条件 | Console 姿态 | 禁止行为 |
|---|---|---|
| actor/scope 不可验证、过期、撤销或冲突 | 受保护内容和提交整体 fail-closed，仅保留最小恢复入口 | 不得用旧 session、URL、缓存或偏好继续放行。 |
| visibility/资格/Policy/Gate unknown 或不可得 | 相关入口保持 restricted/unknown/blocked | 不得由本地配置、角色或页面规则补 allow。 |
| 单一 owner 超时、不可用、过期或部分 | 只降级可证明依赖该 owner 的区域，保留状态轴 | 不得扩散为全局失败或由其他成功掩盖。 |
| SDK 或正式 surface 未开放 | 相应能力 read-only/blocked，安全壳仍可成立 | 不得改走数据库、私有 API/bus、mock 或服务源码。 |
| Command 响应中断或结果 unknown | 有正式能力才回查，否则挂起 unknown 并阻止无依据重放 | 不得用 receipt、transport success 或刷新宣布完成。 |
| Safe-field/redaction/状态语义无法证明 | 裁剪到更小摘要/ref，必要时不呈现 | 不得透传 raw/hidden body 或猜测完整性。 |
| 诊断 sink 缺失或失败 | 诊断独立降级，核心交互与安全恢复不变 | 不得把诊断故障当作 owner 业务失败。 |

Console 当前不向任何外部系统提供可作为业务 truth 的输出；它的输出限于入口体验、经正式边界提交的受控意图，以及条件化的安全诊断或正式链接。

| 请求经历、等待、需回查、错误和恢复选择 | Console 正式真相 | Console 只拥有本客户端交互经历 | 以 owner 正式结果或安全终止结束呈现；不拥有副作用。 |
| 焦点、播报、非颜色状态和可访问恢复选择 | Console 正式真相 | Console 拥有当前体验的 a11y 事实 | 随呈现变化；不得覆盖 owner 状态或放宽资格。 |
| 明确保存的布局、入口和视图偏好 | Console 正式真相 | Console 拥有产品呈现偏好 | 跨设备/跨会话范围 pending；不得改变权限或业务优先级。 |
| Actor/session/scope 显示摘要与 visibility/资格姿态 | 快照 / 投影 | 正式语境和决定归 identity/治理等 owner | 仅保留获准的最小摘要；撤销、冲突或过期即更新、撤除或收紧。 |
| Owner-safe 查询结果、来源和多轴状态 | 快照 / 投影 | 业务/治理/运行 truth 归各 owner | 按 owner 分区并保留 source/freshness/coverage/availability/consistency；可失效、可撤除。 |
| 八类管理主题安全摘要 | 快照 / 投影 | 各主题 owner 分别拥有 truth | 各自独立变化或失效；一个 owner 成功不得掩盖另一个的 stale/partial/unavailable。 |
| 最小安全客户端诊断上下文 | 快照 / 投影 | 只描述客户端交互和请求经历 | 无法证明安全时不保存或不上送；不形成 audit、evidence 或 owner 历史。 |
| 语境、对象/版本/lineage、Policy/Gate 决定引用 | 引用关系 | 指向正式 owner 的对象和决定 | 引用失效时显示 invalid/unknown，不补入正文。 |
| Receipt/result/reconciliation/audit/evidence/report/export/capability/archive/sandbox 引用 | 引用关系 | 只保存正式提供且允许显示的安全引用 | 仅用于回链和解释；不作为本地幂等、提交或完成依据。 |
| Credential、secret、身份/授权证明、Policy/Gate 内部依据 | 明确不拥有的正文 / truth | 归正式身份、授权和治理 owner | 不进入任何 Console 生命周期、缓存、错误、诊断或导出。 |
| Raw/hidden/redacted 载荷、跨域完整对象及各 owner 正文 | 明确不拥有的正文 / truth | 归相应业务、治理、证明或执行 owner | 无法证明安全即拒绝或裁剪到 ref/最小摘要；不进入持久、日志或外围输出。 |
| 领域校验、幂等依据、副作用、正式 verdict、合规/readiness 与 owner 后台状态机 | 明确不拥有的正文 / truth | 归正式 owner 的决定、执行或运行语义 | Console 只能呈现正式 result/ref 或 unknown/blocked，不能本地重建。 |

Console 的正式真相严格限于“用户与客户端如何交互”。本地存在快照不改变其 owner，引用可回链不等于正文进入本仓，明确禁止的正文没有 Console 生命周期。

### 9.3 一致性策略

| 数据关系 / 场景 | 一致性口径 | 失败处理口径 | 说明 |
|---|---|---|---|
| 当前 actor/scope 与受保护视图或意图 | 边界即时一致 / 强安全约束 | 无法重验、过期、撤销、冲突或 unknown 时 fail-closed | 安全资格不能依赖最终收敛的旧影子。 |
| Console 会话选择、草稿、确认与请求呈现 | 单客户端交互内强一致 | 语境失效或状态冲突时暂停受保护交互，安全保留草稿并要求重验 | 这是交互连贯性，不是 owner 业务事务。 |
| Owner truth 到 owner-safe 视图影子 | 最终一致，带来源和新鲜度 | 标示 stale/partial/unavailable，显式重查或撤除；旧影子不覆盖新结果 | 只读消费允许延迟，但不压平状态轴。 |
| 多 owner truth 到联合视图 | 分 owner 最终一致，不承诺跨域原子性 | 按 owner 隔离 partial/stale/unknown；缺项不补造完整、健康、合规或 ready | 联合呈现是组织方式，不是新 truth。 |
| Owner truth 到对象/决定/结果引用 | 引用有效性一致 | 引用过期、撤销、不可见或无法回查时 invalid/unknown/blocked | 引用不保证正文可离线使用。 |
| 草稿/确认到受控意图提交 | 提交前语境与资格即时约束；草稿本地连贯 | 资格变化、确认缺失或 surface 未开放时保持草稿/blocked | 草稿不是正式命令或批准。 |
| Transport/receipt/accepted 到 owner 结果 | 以 owner confirmed/rejected 为准 | pending/中断/unknown 时正式回查或挂起；无 reconciliation 时禁止自动重放 | 保护副作用与幂等边界。 |
| Owner 状态变化到 SDK 失效提示 | 最终一致的可选提示协作 | 提示缺失不改变主链；收到后只触发失效、重验或重查 | 不建立事件投影或 cursor。 |
| 用户偏好跨会话/设备承接 | 非安全关键的条件最终一致 | 冲突时采用更保守或当前会话明确选择 | 介质、同步范围和生命周期 pending。 |
| 错误/降级/a11y 呈现与 owner 状态 | 呈现与已知正式状态一致；诊断可最终收敛 | 无法分类时 unknown 并收紧；诊断失败不改变业务状态 | 视觉成功、播报或日志不覆盖正式结果。 |
| 安全诊断到正式接收边界 | 最终一致 / 尽力而为，不进入业务主链 | Sink 不可用时独立丢弃或降级，不伪造 audit/evidence | Exact envelope 与保留边界 pending。 |

### 9.4 失败、补偿与挂起

| 失败类别 | 架构层处理 | 明确禁止 |
|---|---|---|
| 语境/资格不可验证或撤销 | 收紧视图与动作，保留最小退出、重验或重选入口 | 用旧 session、URL、菜单、偏好或快照继续放行。 |
| 安全影子 stale/partial/unavailable/conflict | 按来源保留多轴状态，显式重查、等待或撤除 | 压平为空、成功、绿色或 ready。 |
| 引用失效或正文不可见 | 保留 invalid/unknown/blocked 和安全回链 | 从缓存、日志、诊断或相邻 owner 猜测正文。 |
| Command 中断或 unknown | 优先正式 reconciliation；没有正式依据则挂起 | 用 toast、刷新、optimistic state 或本地 key 宣布完成或重放。 |
| 跨 owner 缺项或版本不对齐 | 保留分 owner coverage/freshness/consistency，允许无关区域继续 | 伪造原子快照、统一健康、合规、审计或 readiness。 |
| 诊断/提示缺失 | 使用显式 query/revalidation 或保持保守姿态 | 将没有提示解释为没有变化。 |
| 草稿/偏好冲突或不再支持 | 要求复核、保守清除或按明确选择收敛 | 静默覆盖、转为正式对象或扩展权限。 |

补偿在本章只表示重查、重验、撤除、保守呈现、挂起、退出或重新选择，不规定重试次数、队列、事务、缓存 TTL 或具体组件。

### 10.1 关键交互场景

| 交互场景 | 交互边界 | 交互目的 | 边界说明 |
|---|---|---|---|
| 当前访问语境确认与重验 | Console ↔ 正式身份/语境边界 | 在受保护内容或动作前取得可判别 actor/scope 姿态 | Session 壳不能代替正式语境。 |
| 入口可见性与动作资格 | Console ↔ visibility/资格/Policy/Gate 边界 | 确定入口/动作的安全上限 | 菜单、route、角色字符串或 feature flag 不能给出 allow。 |
| Owner-safe 管理读取与探索 | Console ↔ 各正式 owner 查询边界 | 取得带来源、多轴状态和安全引用的结果 | 不创造或改变 owner truth，也不承诺跨 owner 原子一致。 |
| 筛选、布局与草稿编辑 | 交互编排 ↔ 有界客户端状态 | 保持 Console-owned 探索意图、呈现选择和未提交意图 | 不授予权限、不触发副作用。 |
| 受控管理意图提交 | Console ↔ 正式 owner 受理边界 | 在语境、资格与确认成立时提交意图并取得受理姿态 | rejected/accepted/pending/unknown 均不自动等于业务完成。 |
| 正式结果确认与 reconciliation | Console ↔ 正式 owner 结果边界 | 确认 submitted 意图的 confirmed/rejected/unknown | 无正式回查或幂等依据时不能重放。 |
| 状态变化或快照失效提示 | SDK 正式提示 ↔ Console 重验边界 | 提醒安全影子失效、重验或重查 | 提示不是正文、结果证明或 projection 输入。 |
| Owner 长时工作承接 | Console 结果呈现 ↔ owner 延后工作边界 | 呈现审批、验证、报告/导出、归档/恢复或 Sandbox 的正式状态/ref | 工作由 owner 推进，Console 不执行 job 或决定终态。 |
| 跨 owner 联合监督视图 | 管理主题组织 ↔ 多个独立 owner | 在同一页面组织安全结果并保留各自状态 | 不建立共享事务、统一时间点或 readiness。 |
| 安全诊断上送 | Console 外围输出 ↔ 正式诊断接收边界 | 条件化传递无 forbidden body 的最小交互诊断 | 不构成 audit/evidence，接收失败不改变业务。 |
| 外部安全链接/回链 | Console 导航 ↔ 正式对象或相邻产品链接边界 | 在合同允许时导航到引用目标 | 未停审产品保持 pending，不传递私有状态。 |

### 10.2 通信方式判断

| 场景组 | 推荐通信方式 | 不宜采用 | 失败处理口径 |
|---|---|---|---|
| 访问语境、visibility 与资格 | 同步请求 / 响应类交互 | 仅依赖异步提示、后台收敛或本地缓存授予资格 | 不可判别、过期、撤销、冲突或 unknown 时 fail-closed。 |
| Owner-safe 读取与探索 | 按 owner 独立的同步请求 / 响应 | 共享存储、后台补造或事件投影作为唯一来源 | 分区显示 loading/partial/stale/unavailable/unknown，允许有界重查。 |
| 客户端筛选、布局与草稿 | 客户端内部同步交互 | 每次本地变化都发 owner 命令或事件 | 冲突时要求复核、保守清除或安全保留草稿。 |
| 受控意图提交 | 同步请求 / 响应，返回即时受理姿态 | 异步发出即视为成功或后台静默提交 | 无 surface/资格/确认时 blocked；中断时 unknown。 |
| 正式结果确认 | 正式支持时同步回查 result/ref/reconciliation | 客户端推导、固定轮询或无依据重放 | 可回查则采用正式结果，否则保持 unknown/blocked。 |
| Owner 状态变化提示 | SDK 封装的可选异步提示 | 替代同步查询或直接改写结果 | 缺失时仍显式重验；收到后只失效/重查。 |
| Owner 长时工作 | 由 owner 拥有的后台 / 延后承接 | 同步响应伪装完成，或 Console worker 推进 | 忠实保留 owner 的 accepted/pending/failed/unknown/ref。 |
| 跨 owner 联合视图 | 多个独立同步读取，不要求统一收口 | 跨域事务、全源成功门禁或事件投影合成 truth | 每个 owner 独立成功/失败，缺项明确 coverage。 |
| 安全诊断 | 条件化异步或延后外围交互 | 同步阻断业务或携带正文 | Sink 失败时诊断独立降级，业务结果不变。 |
| 外部安全链接 | 当前导航确认类同步交互；合同未闭口时不启用 | 私有状态同步或未停审回调 | 引用无效或合同缺失时 unavailable/blocked。 |

### 10.3 交互边界图

```text
 +----------------------+        +--------------------------+
 | browser / assistive |        | L0-sdk / formal owners   |
 | entry boundary       |        | access and result boundary|
 +----------+-----------+        +------------+-------------+
            | [local/sync interaction]         ^
            v                                  | [sync query /
 +----------+----------------------------------+  intent / result]
 |               L5-console client boundary   |
 |  context / qualification / owner-safe view |
 |  controlled intent / result presentation   |
 +----------+----------------------+-----------+
            ^                      |
            | [optional async      | [conditional diagnostics]
            |  invalidation hint]  v
 +----------+-----------+   +------+-----------------------+
 | SDK formal hint      |   | safe diagnostics receiver  |
 +----------------------+   +-----------------------------+

 owner pending / delayed work -> formal result or ref -> Console presentation
```

同步交互只保证当前语境、资格、查询、受理和正式回查具有可判别响应，不表示业务工作即时完成。可选提示只触发失效或重查；长时工作始终由 owner 延后承接；诊断是独立外围旁路。

### 10.4 通信红线

- 业务 query、资格、受控意图和结果必须经 `L0-sdk` 或正式服务边界。
- 同步 response/receipt/accepted 不得解释为 owner committed；只有 confirmed/rejected 正式结果收口。
- 异步提示不得生成业务状态、权限、verdict 或 readiness；Console 不直连 `L0-bus`，不维护 cursor/replay/rebuild。
- Owner 后台工作不得迁入 Console worker/job；跨 owner 页面不得要求共享事务或合成统一结论。
- 任何通信材料都不得把 forbidden body 带入状态、错误、日志、诊断或导出。
- 诊断和外部链接不得成为核心同步前置或未停审私有状态通道。

| 技术机制 | 解决的问题 | 采用理由 | 代价 / 约束 | 说明 |
|---|---|---|---|---|
| 正式接缝与依赖倒置 | 防止 owner、协议、浏览器介质或诊断 sink 反向定义核心，并阻断数据库/repository/私有 bus 穿透 | 面向成熟度不同的 owner 时，只有通过 `L0-sdk` / 正式服务接缝进入，核心才能稳定表达可信交互而不复制领域规则 | 增加边界映射、失败语义保真和合同适配成本；正向能力受 surface/activation 约束 | 改变所有外部能力进入核心的方式，是跨页面架构决定。 |
| 按 owner 分区的来源保真组合 | 防止多域结果被聚合为无来源的健康、合规、审计或 readiness | 各 owner 独立拥有 truth、版本和可用性，只有保留多轴状态才能避免第二真相 | 用户必须面对非原子、不同步和局部缺项；比较仅在 owner 明确支持时成立 | 同时改变数据组织、故障边界和主题呈现结构。 |
| 交互真相与可失效安全影子分离 | 防止导航、草稿、缓存和请求呈现升级为外部 truth | Console 需要交互连续性，但外部内容只能以安全快照/ref 进入 | 必须处理失效、撤除和安全保留上限；不默认离线或跨会话连续性 | 规定客户端状态类型上限，不是存储产品选择。 |
| 披露与提交边界即时重验、fail-closed | 防止过期、撤销、冲突或 unknown 的正式语境继续放行内容与动作 | 在实际披露或产生副作用前重验，才能保持正式决定优先 | 增加等待和依赖可用性要求；无法判别时牺牲部分可用性 | 横跨入口、视图和命令，不可由局部 guard 代替。 |
| 请求经历、受理姿态与 owner 正式结果分层 | 防止 receipt/accepted/pending/toast/transport success 冒充完成，并避免 unknown 重复副作用 | Console 只拥有请求经历，终态由 owner confirmed/rejected 提供 | 状态更显式，可能长期 pending/unknown；无正式回查时必须挂起 | 改变所有受控意图的完成和恢复语义。 |
| 同步当前交互、可选提示与 owner 延后工作分离 | 防止把所有工作压入同步闭环，或让 Console 通过 consumer/worker 接管任务与事件 truth | 当前交互需要可判别反馈，提示只协助失效，长时工作天然归 owner | 需同时处理提示缺失、延迟结果和显式重查；不承诺即时新鲜 | 不绑定 HTTP、RPC、MQ、轮询或具体事件产品。 |
| 按 owner 区域化故障隔离与有界交互 | 防止单一 owner 慢、错或缺失扩散成全局失败，或被统一 loading/error/green 压平 | 多 owner 管理面不存在跨域原子性，独立读取和区域状态同时保护可用性与事实差异 | 需要区域级等待、恢复和可归因诊断；预算与超时仍需 authority | 改变页面组合、失败传播和运行承载。 |
| Forbidden-body 最小化与诊断旁路隔离 | 防止敏感依据、raw/hidden payload 和 owner 正文通过缓存、错误、日志、诊断或导出复制 | Console 只需最小安全摘要、ref 和请求经历；诊断不是业务 truth | 排障上下文受限，需依靠安全标识与 owner 正式追踪；无法证明安全的诊断须丢弃 | 同时约束正常、失败和外围输出路径。 |
| 视觉与辅助技术共享正式语义 | 防止键盘、焦点、播报或非颜色路径在资格、状态、确认和恢复上形成不同业务语义 | 可访问路径必须与视觉路径共享同一正式状态模型与安全上限 | 核心交互从结构阶段保留语义、焦点和恢复能力；支持矩阵仍 pending | 这是跨 C1～C6 的主线约束，不是样式补丁。 |
| 正式合同门控的保守能力激活 | 防止旧文档、mock、历史 API 或草案把未闭口能力伪装成 integrated/ready | Exact surface、safe-field、scope、activation 和量化 authority 成熟度不同，需逐面诚实开放 | 首批可能 hidden/read-only/partial/blocked；需持续维护依赖来源与激活条件 | 决定能力何时进入产品边界，不等同某个 feature-flag 产品。 |

这些机制均跨页面或跨 owner 改变边界接入、可进入数据、一致性、完成语义或故障传播，因此属于架构层决定。本文不选择前端框架、图库、通信协议、缓存/存储产品、TTL、轮询/重试参数、目录或类；任何后续载体都必须服从 truth、Policy/Gate、forbidden-body 与正式结果边界。

## 12. 备选方案与取舍

> 校准来源：
> - `design-calibration/01_arch_step_02_goals_constraints.md`
> - `design-calibration/01_arch_step_10_technology_choices.md`
> - `design-calibration/01_arch_step_11_alternatives_tradeoffs.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“有效替代路径判定”“方案路径比较表”“方案边界说明”“当前取舍收束”和“待确认事项”小节。

| 方案路径 | 解决的问题 | 主要收益 | 主要代价 / 约束 | 当前结论 | 说明 |
|---|---|---|---|---|---|
| 单一可信管理交互客户端，以公共不变量组织 owner 分区能力 | 在多个 owner 之上提供一致入口而不建立跨域 truth | 导航、重验、来源状态、结果、恢复和 a11y 共享安全语义 | 中央客户端承担较高组合与解释复杂度，公共语义必须保持狭窄 | 采用 | 当前主线；公共部分只拥有交互不变量。 |
| Owner 对齐的联邦管理前台，由各 owner 独立承载页面 | 在共同入口下让领域管理体验独立演进 | Owner 自主性强，中央客户端更薄 | 重复语境、状态、命令恢复和 a11y；跨主题连续性碎片化，运行边界增加 | 不采用 | 是合法相邻路径，但当前没有相应组织/运行 authority，且削弱统一交互价值。 |
| 单一客户端内以公共可信交互语义约束所有页面 | 防止每页自行解释权限、partial、unknown、确认与完成 | 跨页行为可预测，安全和结果不变量可审计 | 需要前置抽象与治理，公共语义不得吸收 owner 规则 | 采用 | 与单一客户端共同构成当前内部约束主线。 |
| 页面局部自治，仅共享导航外壳 | 以较少公共抽象承接差异化页面 | 单页实现直接，局部变化隔离 | visibility、状态轴、结果、恢复和 a11y 易漂移 | 不采用 | 即便 SDK-only，也不足以证明跨页核心不变量。 |
| 按正式 owner 合同独立门控、渐进激活 | 在合同成熟度不同的情况下交付诚实子集 | 已闭口能力不被最慢依赖拖住，故障和变更按 owner 隔离 | 能力集合不齐，需解释来源、覆盖和激活条件 | 采用 | 这是产品边界机制，不是版本排期。 |
| 等待所有 owner 合同闭口后一次激活 | 以统一时点提供表面整齐的管理面 | 能力集合较易说明 | 所有能力被最慢 owner 耦合，无法利用已闭口只读价值，故障域扩大 | 不采用 | 不违反 truth 边界，但不适合当前成熟度差异。 |
| 显式 query/revalidation 为基线，SDK 提示只作增强 | 在没有可靠推送合同下维持安全读取主链 | 不依赖事件送达，无需本地 cursor/projection | 新鲜度感知较慢，需显式重验/重查 | 采用 | 允许未来正式提示，但不把它当当前成立前提。 |
| SDK 推送失效作为所有视图必要前置 | 更快发现 owner 状态变化 | 提示可靠时可缩短旧影子停留 | 强耦合未闭口的提示覆盖、恢复和语义，且仍不能替代查询 | 不采用 | 合同成熟后可作增强，不承担正确性。 |
| Owner 独立有界读取、分区展示、局部降级 | 在无跨域事务下提供联合入口 | 单一 owner 失败不阻断其他区域，状态差异保持可见 | 用户需理解 partial/stale/unavailable，不提供单一“当前”结论 | 采用 | 与 owner truth 分治一致。 |
| 只有所有 owner 同时成功才展示联合视图 | 避免用户直接面对部分与不同步 | 展示时表面更整齐 | 最弱依赖决定全页可用性，“同时成功”仍非原子一致 | 不采用 | 扩大故障域并制造整体一致感。 |

本章只比较仍服从正式 owner、SDK-only、客户端只收紧和 forbidden-body 边界的相邻路径。数据库直连、本地治理裁决、跨域第二 truth、Console BFF/worker 等已被前文排除，不能借“备选方案”重新打开；框架、协议、存储和刷新参数属于后续局部实现。

| 当前主线得到什么 | 当前主线失去或承担什么 |
|---|---|
| 单一且可审计的客户端交互边界 | 公共交互语义的设计与维护成本 |
| Owner truth 独立、来源和状态可解释 | 不提供跨域原子快照或统一 readiness |
| 已闭口能力可渐进开放 | 页面可能呈现 hidden/read-only/partial/blocked |
| 单一 owner 故障局部化 | 需要区域级错误、恢复和 a11y 设计 |
| 不依赖提示即可成立 | 牺牲部分即时新鲜感并增加显式重查 |
| Owner 正式结果与 unknown 安全恢复 | 不能用乐观完成隐藏延迟或不确定性 |
| 后续技术载体可替换 | 当前不提前锁定框架、协议或缓存便利性 |

| Forbidden-body 与外围输出最小化 | 安全结果、状态、草稿、错误、日志、诊断、链接和导出 | 只允许任务所需摘要/ref；无法证明安全即裁剪或拒绝 | 保护外部正文单一归属和最小披露 | 横跨正常与失败路径，不是局部过滤器规则。 |
| 正式结果与来源可追溯 | 读取、组合、意图、结果回查和审阅入口 | 可被解释为正式状态的声明必须保留 owner/source/version/freshness/coverage 或 result/ref；无引用时 missing/unknown | 区分来源事实、客户端经历和正式结果 | 不要求 Console 生成或保存正式审计正文。 |
| 最小安全可观测性 | 语境、owner 依赖、query、submit、receipt、reconciliation、degradation/recovery | 在不暴露正文下可判别 owner、客户端阶段、已知状态和安全关联；诊断失败不改业务 | 保护可定位性及诊断与业务/审计隔离 | 不规定监控产品、字段 schema、采样、告警或保留。 |
| 局部故障隔离与保守恢复 | 安全前置、owner 查询区、命令结果、提示、诊断、草稿和安全影子 | 安全前置失败即收紧；owner 故障分区隔离；unknown 仅正式回查或挂起 | 防止故障扩大、掩盖或重复副作用 | 不是重试脚本或 on-call 手册。 |
| 有界且可归因的交互负载 | 本地交互、多 owner 查询、分页/下钻、资格重验、结果回查、提示刷新 | 只向必要 owner 有界发起；慢源不无说明阻断全页；禁止无界 fan-out、重复自动刷新和 unknown 重放 | 防止请求放大、尾依赖扩散和性能优化绕过安全 | 不伪造延迟、并发、频率、TTL 或 SLA 数值。 |
| 正式合同下的配置与变更控制 | Owner 接入、激活、入口/动作、安全字段、状态、失效/诊断和偏好 | 正向能力以正式合同/资格为上限；route、菜单、flag 和偏好不得授权、补合同或改变结果/truth | 防止运行配置偷偷改写架构主线 | 不定义配置中心、文件格式、键名或发布流程。 |
| 可访问等价的正式交互语义 | C1～C6 的语境、导航、资格、读取、草稿/确认、结果、错误和恢复 | 键盘和受支持辅助技术应完成相同获准目标；状态不只靠颜色/位置/动画；焦点、播报和恢复不改变正式语义 | 保护不同交互方式共享安全边界、状态解释和结果判断 | 不能等视觉实现完成后补齐。 |

这些要求持续作用于多个上下文、边界和交互类型，不能留给单一组件、运维手册或制度文本。安全优先于不可验证时的可用性；性能不得绕过即时重验；可观测性不得突破数据最小化；追溯依赖正式 result/ref 而非客户端日志；配置不得补合同；a11y 不形成第二套业务路径。诊断 envelope、量化预算、精确配置与支持矩阵仍 pending。

|---|---|---|---|---|---|
| 阶段 A：边界与交互骨架成立 | 单一客户端边界、公共交互不变量、正式接缝、owner 分区、交互真相/安全影子分离、即时重验、结果分层、局部降级、最小化和 a11y 语义成立 | 写能力不齐；部分区域 read-only/partial/blocked；没有跨域原子视图、固定数值预算或必需提示 | 按正式合同逐面开放已闭口的 query/command/result/ref，并承接可验证的 safe-field、scope/visibility 与结果回查 | 任一正向能力的 surface、safe-field、资格和 activation 有可核验来源，或只读消费已无法支撑安全管理闭环 | 当前成立标准是任何页面都不打穿 truth、资格和结果边界，而非“所有页面已实现”。 |
| 阶段 B：合同门控与可恢复消费增强 | 逐 owner 形成更完整的读取、受理、回查、引用与外围入口，并保持 pending/blocked/read-only 上限和局部隔离 | 失效提示可缺失；unknown 仍需显式回查；跨会话偏好、批量、比较、诊断和量化可能受限 | 正式依据成立后增强 reconciliation/幂等承接、SDK 提示、逐项批量结果、可比较趋势/评审和诊断回链 | Owner 提供正式 reconciliation、幂等、提示、比较、批量或诊断合同，或显式查询产生可证明压力 | 增强正式承接和恢复解释，不改变外部 truth 与后台执行归属。 |
| 阶段 C：规模与传播压力下的边界增强 | 在 owner 数量、组合或用户规模增长时，维持公共语义、来源保真与局部故障，同时增强有界读取、失效协作和可归因诊断 | 只接受不影响安全、结果与最小化的承载效率债务 | 根据正式边界评估更强的 owner-safe 组合、分区预取/失效承接、诊断承接或跨主题组织；仍不引入业务 projection 或新 truth | Fan-out、尾延迟、故障归因、状态传播或 a11y 压力经正式测量超过阶段 A/B 的有界口径 | 先改变承接/隔离结构，再选择载体；始终保留来源与多轴状态。 |
| 阶段 D：合同和治理边界变化时复核 | 正式 owner 合同、scope/visibility、结果或相邻产品边界结构性变化时，重审上下文、接缝、影子与交互主链 | 可保留历史兼容/只读姿态，但不能把新语义静默塞入旧影子或配置 | 有新 authority 时调整映射、能力门控与演进主线；必要时收缩或移除不安全入口 | Owner truth、Policy/Gate、对象生命周期、link/ref 责任或 L5/L6 正式边界改变，现有结构无法保真 | 结构变化要求重新校准，不能由兼容 UI 掩盖。 |

当前先确保“即使只有部分 owner 能力可用，Console 仍安全、诚实、可恢复且可访问”，所以 read-only/partial/blocked 是合同未闭口时的合法上限。后续只由正式合同、恢复依据、SDK 提示合同、量化规模压力、可访问性压力或语义/责任变化触发；若所谓演进需要本地授权、正文复制、统一 verdict、Console 后台业务或无依据自动恢复，则不属于合法路线。

## 3. 约束条件

> 校准来源：
> - `design-calibration/02_hld_step_03_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“约束条件表”“约束到后续 Step 的绑定”和“待确认事项”小节。

| 约束 | 说明 |
|---|---|
| Console 不拥有外部 truth | 成员、项目、工作、过程、治理、制品/evidence、Workspace、方法、能力、观测、归档和 sandbox 只作 owner-safe view/ref；不得出现其 domain aggregate。 |
| 业务访问 SDK-only/formal-boundary-only | Query/Command/Result/Ref 只经 `L0-sdk` 或正式服务；禁止 DB、repository、服务源码、私有 bus 和 BFF 旁路。 |
| actor/scope/visibility/资格先于披露与副作用 | 不可验证、过期、撤销、冲突或 unknown 时 fail-closed；route/menu/button/flag/cache 不授权。 |
| 来源与状态轴不得压平 | 保持 owner/source、freshness、coverage、availability、consistency，并区分 empty/missing/restricted/partial/stale/unavailable/conflict/unknown。 |
| 草稿、受理、正式结果分层 | transport/receipt/toast/refresh 不代表 committed；只有 owner 正式 result/ref 可确认终态。 |
| Query no-write | 查询、筛选、预取、排序、分页和下钻不改 owner truth、不触发隐式 command 或本地业务 projection。 |
| Unknown 无依据不重放 | 无正式 reconciliation/幂等依据时保持 unknown/blocked；本地 key、时间、刷新均不构成依据。 |
| Owner 故障局部隔离 | 单一 owner/topic 失败不扩散全局，也不被其他成功掩盖；不存在统一 health/compliance/readiness。 |
| Forbidden body 零进入 | credential/secret、授权/治理依据、raw/hidden payload、业务/evidence/audit/report/执行正文不进入持久化、缓存、错误、日志、诊断或导出。 |
| 客户端状态只表达交互事实 | Session 壳、导航、草稿、偏好、request presentation、recovery/a11y state 不改变权限、业务优先级、治理决定或 owner truth。 |
| 可访问路径共享正式语义 | 键盘、读屏和非颜色路径与视觉路径共享同一资格、状态、结果和恢复上限。 |
| 主题按 owner 独立激活 | 未闭口 exact surface/safe-field/activation 的主题只能 pending/blocked/read-only/partial。 |
| 配置不可改写不变量 | 配置可选择或收紧 adapter/呈现，不可放宽资格、改变状态迁移、伪造结果或 evidence/audit 语义。 |
| 量化与兼容须有 authority | 不继承旧首屏/P95/SLA、控制项/指标数量或兼容矩阵；未测量不写 pass/ready。 |
| 未停审产品仅 future link/ref | Chat/Runner/Sync/Marketplace/Bridges 的私有状态、页面/API/指标不进入当前主体。 |

│   ├─ AccessContextService / AccessContext
│   ├─ NavigationService / NavigationState
│   └─ DisclosureGuard / VisibilityQualificationPort

├─ 来源保真视图
│   ├─ OwnerViewCompositionService
│   ├─ OwnerQueryPort / SdkAccessPort
│   └─ OwnerViewSnapshot / SourceStatusAxes / OwnerViewModel / ReferenceSet

├─ 受控意图与结果
│   ├─ IntentReviewService / DraftIntent
│   ├─ OwnerCommandPort / ResultReconciliationPort

├─ 管理主题组织

- `L0-sdk`、owner、浏览器与辅助技术是外部边界，不是 Console 内部业务主体。

### 4.2 实现分层视图

```text
用户输入 / 直接入口 / 正式 SDK 提示 / 显式重验
                         │
                         ▼
┌────────────────────────────────────────────┐
│ Inbound / Operations                        │
│ ConsoleEntry · QueryEntry · SubmitEntry     │
│ ReconcileTrigger · RecoveryActionEntry      │
└──────────────────────┬─────────────────────┘
                       ▼
┌────────────────────────────────────────────┐
│ Application Services                        │
│ Access · Navigation · View · Intent · Topic │
│ Result · Degradation · Accessibility        │
└──────────────────────┬─────────────────────┘
                       ▼
┌────────────────────────────────────────────┐
│ Domain / Policy                             │
│ Interaction states · guards · source axes   │
│ draft/result separation · disclosure rules  │
└──────────────────────┬─────────────────────┘
                       ▼
┌────────────────────────────────────────────┐
│ Ports / Adapters / bounded state carrier    │
│ SDK/owner query+command · reconciliation    │
│ safe-link · diagnostics · a11y · local state│
└────────────────────────────────────────────┘
```

关键说明：

- Inbound/Operations 只接收用户意图、正式提示和显式重验；不直接读 owner 内部存储。
- Application Services 编排，Domain/Policy 保护客户端交互不变量，Ports/Adapters 承接正式边界和有界状态。
- 每个业务主要组成部分跨越多个实现层；实现层不是额外业务部分，也不拥有 owner truth。
- 不建立 Console BFF、后台 worker、业务数据库、owner projection、outbox 或内部 event consumer。

### 4.3 关键判断

- `AccessContext` 是正式语境的安全引用/呈现对象，不是 actor、credential 或 scope owner。
- `OwnerViewSnapshot`/`OwnerViewModel` 是可失效消费结果，不是业务 projection/current truth。
- `DraftIntent`/`RequestPresentation`/`ResultReference` 分离本地交互与正式结果，不拥有副作用、幂等或 owner terminal。
- `TopicAdapter` 仅是按 owner 合同门控的正式接缝，不形成跨域聚合服务。
- `DegradationState`/`AccessibilityState` 只改变本地呈现和恢复，不改变资格、业务状态、审计或 readiness。

### 5.4 访问语境与导航

| capability | 输入 | 输出 / 状态影响 | 关键边界 |
|---|---|---|---|
| 语境锚定与重验 | 正式 actor/scope 安全引用、session lifecycle | `AccessContext`；verified/restricted/unknown/expired/revoked | 不签发 credential、不推导 scope |
| 显式语境转换 | 用户选择、正式 scope/visibility result | 新语境候选与重验经历 | 选择不是授权，失败即收紧 |
| 导航与直接入口防护 | route/deep-link、visibility/qualification | `NavigationState`、visible/restricted/disabled/unknown | URL/menu/local role 不放行，不泄露存在性 |

与其他部分的接缝：向 owner-safe view、受控提交和主题组织提供当前语境/披露上限；向韧性部分提供失效和恢复提示。

| `NavigationService` | Application Service | 组织入口、路由选择和可见性姿态 | §6 `NavigationState`；§7 导航 Query |

## 7. API / 接口骨架

> 校准来源：
> - `design-calibration/02_hld_step_07_api_interface_skeleton.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“接口分类说明”“按主要组成部分的接口骨架总表”“Port / Adapter 边界摘要”和“待确认事项”小节。

### 7.1 接口分类与适用性

```text
Command API
  更新 Console interaction truth，或将受控意图委托给正式 owner command seam；不在 Console 改写 owner truth。

Query API
  读取正式 context/visibility/owner-safe result/ref 或 Console presentation；筛选、分页、下钻和回查 no-write。

Inbound Event Consumer
  仅条件化消费正式 SDK invalidation hint，转换为本地失效/待重验姿态；当前 contract pending。

Outbound Event
  不适用：Console 没有需要向下游传播的自有业务事实。

Operations Job
  不适用：Console 不拥有 worker、projection rebuild、发布、对账或长时业务作业。
```

### 7.2 Command API 骨架

| API | 所属部分 | 输入骨架 | 输出骨架 | 主要处理 / 写入边界 |
|---|---|---|---|---|
| `RequestAccessContextSwitch` | 访问语境与导航 | `ContextSwitchIntent intent`、`AccessContext current_context`、`CommandMetadata metadata` | `ContextSwitchPresentation presentation` | 记录切换意图并请求正式重验；只改 context/navigation presentation，不写 scope/授权 truth |
| `SaveClientPreference` | 受控意图与结果 | `ClientPreferenceCommand command`、`CommandMetadata metadata` | `PreferenceSavePresentation presentation` | 只写获准布局/筛选/入口偏好；不改变资格、业务优先级或结果 |
| `DiscardDraftIntent` | 受控意图与结果 | `DraftReference draft_ref`、`DiscardReason reason`、`CommandMetadata metadata` | `DraftDisposition disposition` | 清理本地草稿；不通知 owner 改写业务对象 |
| `SubmitControlledIntent` | 受控意图与结果 | `ControlledIntentCommand command`、`AccessContext context`、`CommandMetadata metadata`、`OptionalIdempotencyKey idempotency_key` | `RequestPresentation presentation` | 重验语境/资格后经 `OwnerCommandPort` 提交；Console 只写 request presentation，幂等/receipt/result/truth 归 owner |
| `ApplyRecoveryAction` | 韧性与可访问交互 | `RecoveryActionCommand command`、`RecoveryReference plan_ref`、`AccessContext context`、`CommandMetadata metadata` | `RecoveryPresentation presentation` | 执行获准 requery/revalidate/reconcile/keep-draft/exit；只改局部交互状态 |

`IdempotencyKey` 只有 owner 正式 contract 明确提供时才传递；Console 不自行制造幂等依据。`AccessContext`/`ActorContext` 只承接正式上下文，不在本仓实现认证或授权。

### 7.3 核心 Query API 骨架

| API | 所属部分 | 输入骨架 | 输出骨架 | 读取来源与边界 |
|---|---|---|---|---|
| `ResolveAccessContext` | 访问语境与导航 | `AccessContextQuery query`、`SessionReference session_ref`、`ActorContext actor_context` | `AccessContextView view` | 正式 identity/scope 边界；无法验证/过期/撤销/冲突时 restricted/unknown |
| `GetNavigationVisibility` | 访问语境与导航 | `NavigationVisibilityQuery query`、`AccessContext context`、`ActorContext actor_context` | `NavigationViewModel view` | 正式 visibility/qualification；menu/route/flag 只能收紧 |
| `QueryOwnerView` | 来源保真视图 | `OwnerViewQuery query`、`AccessContext context`、`FilterIntent filter`、`PaginationRequest page` | `OwnerViewModel view` | owner-safe formal Query；保留五轴，所有探索 no-write |
| `GetSourceStatus` | 来源保真视图 | `SourceStatusQuery query`、`OwnerReference owner_ref`、`AccessContext context` | `SourceStatusAxes status` | 只读正式 result/ref 元数据；不合成 verdict/readiness |
| `GetSafeLink` | 来源保真视图 | `SafeLinkQuery query`、`SafeLinkReference link_ref`、`AccessContext context` | `SafeLinkView view` | 只返回可导航安全 ref；失效/撤销/受限即移除或阻断 |
| `GetRequestPresentation` | 受控意图与结果 | `RequestStatusQuery query`、`RequestReference request_ref`、`AccessContext context` | `RequestPresentation presentation` | 只读本地经历与获准正式 ref；不能本地生成终态 |
| `ReconcileRequestResult` | 受控意图与结果 | `ReconciliationQuery query`、`RequestReference request_ref`、`OptionalReceiptReference receipt_ref`、`AccessContext context` | `ResultReference result_ref` | 正式 reconciliation；无 surface/依据时 unknown/blocked，不重放 |
| `GetTopicActivation` | 管理主题组织 | `TopicActivationQuery query`、`TopicReference topic_ref`、`AccessContext context` | `TopicActivationView view` | 正式 contract/activation metadata；mock/flag 不提升 active |

| Query | Owner | 输出 | 当前姿态 / 边界 |
|---|---|---|---|
| `QueryMemberManagementTopic` | identity/member-service | `TopicViewModel view` | pending；仅 safe summary/ref，不维护 lifecycle/role inheritance |
| `QueryProjectWorkspaceTopic` | work/process/workspace | `TopicViewModel view` | pending/partial；不生成 progress/Workspace projection/cursor/rebuild |

### 7.5 Event、Job 与 Port 边界

| 类别 / 主语 | 输入/用途 | 当前结论 |
|---|---|---|
| `ConsumeSdkInvalidationHint` | 正式 `SdkInvalidationHintEvent event`、`EventId event_id`、`EventSourceReference source_ref`、`InvalidationEnvelopeReference envelope_ref`、`OptionalIdempotencyKey idempotency_key` | 条件化 pending；只标 stale/invalidated/revalidate，不消费私有 bus/保存 payload/推进 owner state |
| Outbound Event | 不适用 | 无 Console-owned 业务事实；诊断须走正式 safe sink，不是业务事件 |
| Operations Job | 不适用 | requery/revalidate/reconcile 是显式 Query/Recovery；owner 长时 job 不迁入 |
| `SdkAccessPort` / `OwnerQueryPort` | 正式 Query/Command/Result/Ref 访问 | 不作为公开 API；定义 SDK/owner adapter、错误映射和安全上下文 |
| `OwnerCommandPort` / `ResultReconciliationPort` | 正式提交与结果回查 | 不实现 owner command/幂等/终态；exact surface pending |
| visibility/link/diagnostic/a11y ports | 正式资格、安全链接、最小诊断和等价呈现 | 不生成授权、私有 link、audit/evidence 或第二业务路径 |

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“通用处理流骨架”“处理流覆盖清单”“关键设计点”和“待确认事项”小节。

### 8.1 通用处理流骨架

```text
用户意图 / 直接入口 / 正式 SDK 提示
                  │
                  ▼
Inbound Entry
  - 绑定 AccessContext / CommandMetadata
  - 阻止未验证语境和 forbidden body
                  │
                  ▼
Application Service
  - 调用 disclosure / no-write / completion / recovery guards
  - 选择正式 SDK / owner port，不访问数据库或私有 bus
                  │
                  ▼
Interaction Object / Safe View / Reference
  - 只更新 Console interaction truth
  - 或构造可失效 owner-safe snapshot/ref
                  │
                  ▼
Presentation + AccessibilityState
  - 保留 source/freshness/coverage/availability/consistency
  - 呈现 submitted/accepted/pending/confirmed/rejected/unknown
```

关键说明：所有路径先受正式语境与最小披露约束；Query 只构造 view/ref；owner 副作用只经正式 port 委托；末端是呈现和 a11y 状态，不是 owner truth/audit/evidence/readiness。

### 8.2 语境 bootstrap 与导航收紧

```text
AccessContextQuery / DirectEntry / ContextSwitchIntent
                  │
                  ▼
ConsoleEntry
  - 读取 SessionReference session_ref
  - 不从 URL / menu / local role 推导权限
                  │
                  ▼
AccessContextService
  - resolve(AccessContextQuery query, ActorContext actor_context)
  - 经 SdkAccessPort / VisibilityQualificationPort 取得正式结果
                  │
                  ▼
AccessContext + DisclosureGuard
  - check(AccessContext context, DisclosureTarget target)
  - restricted/expired/revoked/conflict/unknown 全部收紧
                  │
                  ▼
NavigationState + AccessibilityState
  - 清理敏感选择/旧 ref，呈现重验或最小恢复方向
```

关键设计点：语境切换是正式重验请求而非签发 scope；direct entry 与普通导航共用 guard；只有新的正式结果可恢复披露。

### 8.3 Owner-safe Query

```text
OwnerViewQuery + AccessContext + FilterIntent / PaginationRequest
                  │
                  ▼
QueryEntry
  - QueryNoWriteGuard.assert_read_only(QueryIntent query)
  - 应用 disclosure 和 activation 上限
                  │
                  ▼
OwnerViewCompositionService
  - query(OwnerViewQuery query, AccessContext context)
  - 经 OwnerQueryPort / L0-sdk 获取 owner-safe result
                  │
                  ▼
OwnerViewSnapshot.from_owner_result(OwnerSafeResult result, AccessContext context)
  - 保留 owner/source/version 和 SourceStatusAxes
  - 不填补 missing/partial 字段
                  │
                  ▼
OwnerViewModel + DegradationState + AccessibilityState
  - 区分 empty/missing/restricted/partial/stale/unavailable/conflict/unknown
```

关键设计点：筛选、排序、分页、预取和下钻全部 no-write；snapshot 不是 current truth；单一 owner 故障局部隔离；safe-field、cache invalidation 和分页能力协商留给 03 与正式合同。

### 8.4 本地草稿、偏好与复核

```text
DraftEdit / ClientPreferenceCommand / DiscardDraftIntent
                  │
                  ▼
IntentEntry
  - 绑定 AccessContext context / CommandMetadata metadata
  - 拒绝 forbidden body
                  │
                  ▼
IntentReviewService
  - edit(DraftPatch patch)
  - validate(ClientValidationContext context)
  - prepare_submission(AccessContext context) 或 discard(DiscardReason reason)
                  │
                  ▼
DraftIntent / ClientPreference
  - 只更新 Console interaction truth
                  │
                  ▼
IntentReviewView + AccessibilityState
```

关键设计点：本地校验不替代 owner 业务校验或 Policy/Gate；偏好不影响权限、状态解释或结果；草稿介质和跨会话生命周期仍 pending。

### 8.5 受控意图提交

```text
ControlledIntentCommand + DraftReference + AccessContext + CommandMetadata
                  │
                  ▼
SubmitEntry
  - 用户显式确认
  - 重新解析 actor/scope/visibility/qualification
                  │
                  ▼
IntentReviewService
  - SubmissionEligibilityGuard.check(
      AccessContext context,
      TopicVisibility visibility,
      CommandReference command_ref)
                  │
                  ▼
OwnerCommandPort / L0-sdk
  - 仅正式 surface active 时提交
  - 仅 owner 正式提供时传 OptionalIdempotencyKey idempotency_key
                  │
                  ▼
RequestPresentation
  - submitted / accepted / pending / rejected / unknown
  - 只有正式 ResultReference 可进入 confirmed/rejected
```

关键设计点：这是 P0 委托 Command；Console 本地状态与 owner 业务事务分离；按钮曾可见、receipt、transport success、toast、刷新和 cache 均不表示完成；unknown 无依据不重放。

### 8.6 正式结果回查

```text
RequestStatusQuery / ReconciliationQuery
                  │
                  ▼
ReconcileTrigger
  - 重验 AccessContext
  - UnknownReplayGuard.block_without_basis(UnknownRequest request)
                  │
                  ▼
ResultReconciliationPort / L0-sdk
  - 只按正式 receipt/result/ref 回查
  - 无 surface -> unknown/blocked
                  │
                  ▼
ResultReference + CompletionGuard
  - assert_terminal(ResultReference result_ref)
                  │
                  ▼
RequestPresentation + RecoveryPlan + AccessibilityState
```

关键设计点：reconciliation 是 Query，不重发 Command；Request phase 与 Owner result state 分离；无正式回查能力时诚实停在 unknown/blocked。

### 8.7 Owner-partitioned 管理主题组合

```text
TopicViewQuery + TopicReference + AccessContext
                  │
                  ▼
OwnerActivationGuard.check(OwnerContractStatus contract, AccessContext context)
  - pending/read_only/partial/blocked 先于页面内容
                  │
                  ▼
TopicCompositionService
  - 按 owner 拆分 member / project-workspace / method / governance
    / observability / capability / archive / sandbox Query
                  │
                  ▼
OwnerViewSnapshotSet
  - 每个 owner 独立 SourceStatusAxes / ReferenceSet / DegradationState
                  │
                  ▼
TopicViewModel
  - action entry 仅在正式 command surface + qualification 成立时出现
  - 不合成 health/compliance/audit/readiness
```

关键设计点：八类主题共享编排骨架但不共享 truth/status；主题 action 最终仍走受控提交流；exact owner adapters 与 positive activation 均 pending。

### 8.8 条件化失效提示

```text
SdkInvalidationHintEvent + EventId + SourceRef + EnvelopeRef
                  │
                  ▼
SdkHintConsumer
  - 验证正式 SDK 来源，丢弃 raw payload/forbidden body
                  │
                  ▼
DegradationRecoveryService
  - 相关 snapshot -> stale/invalidated
  - 生成 RevalidationRequiredMarker
                  │
                  ▼
Navigation/View/StatusPresentation 收紧
  - 等待显式 ResolveAccessContext / QueryOwnerView / ReconcileRequestResult
```

关键设计点：只有正式 SDK event contract 激活后才启用；当前 pending。事件只使安全影子失效，不代表 owner 状态或 Command 终态；不维护 cursor/replay/projection。

### 8.9 恢复与可访问反馈

```text
RecoveryActionCommand + RecoveryReference + AccessContext
                  │
                  ▼
RecoverySafetyGuard + AccessibilityEquivalenceGuard
                  │
                  ▼
DegradationRecoveryService
  - requery -> QueryOwnerView
  - revalidate -> ResolveAccessContext
  - reconcile -> ReconcileRequestResult
  - keep-draft / exit -> 仅本地交互状态
  - unsafe retry -> blocked
                  │
                  ▼
RecoveryPlan + DegradationState + AccessibilityState
  - focus / announcement / keyboard 路径与视觉共享同一安全语义
```

关键设计点：恢复按原因分流，不统一成 retry；unknown 副作用缺正式依据时 blocked；诊断只发送安全 `DiagnosticContext`，sink 失败不改主线。

### 9.1 状态所有权

| 主要组成部分 | 状态主语 | 所有权 / 状态机边界 |
|---|---|---|
| 访问语境与导航 | `ContextLifecycleState`、`NavigationState`、`TopicVisibility` | Console 客户端安全状态；正式 actor/scope/visibility truth 归 owner |
| 来源保真视图 | `SourceStatusAxes`、snapshot validity | owner-safe 结果的多轴保真 + 本地影子失效；不可本地推进 owner truth |
| 受控意图与结果 | `DraftIntent`、`RequestPhase`、`OwnerResultState` ref | draft/request 经历归 Console；owner result 只读映射 |
| 管理主题组织 | `TopicActivationState` | Console 消费 surface 姿态；不等于 owner/capability readiness |
| 韧性与可访问交互 | `DegradationState`、`RecoveryPlan`、`AccessibilityState` | 局部客户端交互与呈现状态 |

相同词必须带主语：context unknown、source unknown、request unknown、activation pending 不可合为全局 `ConsoleStatus`。

### 9.2 语境生命周期

| 状态 | 含义 | 正常主线 |
|---|---|---|
| `unresolved` | 尚无可验证正式语境 | 否，仅最小壳/重验 |
| `verified` | actor/scope/visibility ref 当前可验证 | 是，但仍受 visibility 上限 |
| `restricted` | 只允许最小披露/有限入口 | 受限 |
| `expired / revoked` | 旧语境已过期或被撤销 | 否，立即收紧并重验 |
| `conflict / unknown` | 材料冲突或不可判定 | 否，fail-closed |

```text
<unresolved> ── ResolveAccessContext（正式可验证） ──> <verified / restricted>
<verified> ── visibility 收紧 ──> <restricted>
<verified / restricted> ── 过期/撤销/冲突/不可判定 ──> <expired / revoked / conflict / unknown>
<restricted / expired / revoked / conflict / unknown>
  ── 显式重验且获得新正式结果 ──> <verified / restricted>
```

禁止无正式重验的 `expired/revoked/conflict/unknown -> verified`，也禁止 route/menu/cache/flag 触发 verified。

### 9.3 Owner view 多轴状态

| 主语 | 状态集合 | 语义 |
|---|---|---|
| freshness | `fresh / stale / expired / unknown` | 不写固定 TTL，以 owner/SDK 当前性为准 |
| coverage | `complete / partial / missing / not_covered` | 正式空与 missing/not-covered 分离 |
| availability | `available / degraded / unavailable / unknown` | 仅描述该 owner surface，不代表整体可用性 |
| consistency | `coherent / conflict / unknown` | Console 不解决 owner 冲突 |
| snapshot validity | `current / stale / invalidated / revoked` | 只描述本地影子是否可呈现 |

这些是正交状态轴，不强画为线性状态机。正式 Query 可更新各轴；失效提示只能收紧为 stale/invalidated；只有新 owner-safe result 能恢复。任一轴失败都必须保留。

### 9.4 Draft 状态

```text
<editing> ── 本地检查失败 ──> <invalid> ── 修正 ──> <editing>
    │ 检查通过
    ▼
<reviewable> ── 当前前置通过且显式确认 ──> <submitted>
<editing / invalid / reviewable> ── 放弃/安全清理 ──> <discarded>
```

`reviewable` 不表示 owner-valid/authorized；`submitted` 只连接 RequestPresentation；`discarded` 不删除任何 owner 对象。禁止 `invalid/discarded -> submitted` 和 draft→confirmed。

### 9.5 请求经历与正式结果分层

| Request 状态 | 含义 | 正式来源要求 |
|---|---|---|
| `submitted` | 已发起交互尝试 | Console entry record |
| `accepted` | owner receipt 表示已受理 | `ReceiptReference`；不是完成 |
| `pending` | owner 工作尚未形成终态 | 正式 status/result ref |
| `confirmed / rejected` | owner 正式终态的本地呈现 | `ResultReference` + `CompletionGuard` |
| `unknown` | 提交/响应中断或无法判定 | transport ambiguity 或缺正式回查 |

```text
<submitted> ── formal receipt ──> <accepted> ── owner working ──> <pending>
      │ formal result                  │ formal result              │ formal result
      ├──> <confirmed / rejected>      ├──> <confirmed / rejected> ├──> <confirmed / rejected>
      └── interruption/ambiguous ──────┴───────────────────────────> <unknown>
<unknown> ── formal reconciliation ──> <pending / confirmed / rejected / unknown>
```

禁止 transport/toast/refresh/cache→confirmed、accepted 无正式 result→confirmed、unknown 自动回到 submitted。

### 9.6 Topic activation

| 状态 | 含义 | 正常主线 |
|---|---|---|
| `pending` | exact contract/activation 未闭口 | 否/仅说明 |
| `read_only` | 正式安全 Query 可用、Command 不成立 | 是（只读闭环） |
| `partial` | 只有部分 owner/能力/safe-field 可用 | 受限 |
| `active` | 适用 surface、safe-field、资格和结果语义可判别 | 是；不表示 readiness/实现/测试 |
| `blocked` | 缺安全前置、资格、合同或 reconciliation | 否 |

`pending` 可在正式 authority 下进入 read-only/partial/active；任何状态在合同撤销、资格不可验或结果冲突时收紧。禁止 feature flag/mock/page/plan→active 或一个 owner active→整个主题 active。

### 9.7 Degradation 与 Recovery

```text
<local normal posture>
  ── query/command/visibility failure、invalidation、conflict ──>
<degraded / stale / partial / unavailable / conflict / unknown>
  ├─ requery ─────> 等待 owner-safe Query
  ├─ revalidate ──> 等待正式 AccessContext
  ├─ reconcile ───> 等待正式 ResultReference
  ├─ keep-draft ──> 保留安全本地草稿
  ├─ exit ────────> 清理敏感呈现
  └─ blocked ─────> 无安全恢复，不推进
```

Recovery 不统一为 retry；正式新结果到达前不提升为正常。A11y focus/announcement 跟随同一状态变化，不改变迁移规则。

### 9.8 状态传播边界

正式 context/visibility/query/receipt/result/invalidation 输入只传播到 Navigation/OwnerView/Topic/Result presentation、RecoveryPlan、AccessibilityState 和最小 `DiagnosticContext`。不存在 Console outbox、业务事件、owner projection 或下游 truth 传播。

## 10. 异常与边界场景轮廓

> 校准来源：
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“异常与边界场景表”“异常影响图”“异常到状态/恢复映射”和“待确认事项”小节。

### 10.1 关键场景

| 场景 | 处理部分 | 当前概要口径 |
|---|---|---|
| actor/scope 无法验证、过期、撤销或冲突 | 访问语境与导航 + 全部受保护部分 | fail-closed；清理敏感入口/选择/旧 ref；只在正式重验后恢复 |
| direct/deep-link 指向受限对象 | 访问语境与导航 | 与普通导航共用 guard；不泄露对象存在性，安全回退 |
| visibility/qualification/reason 不可判定 | 导航、主题、受控意图 | `unknown/disabled`，提交 blocked；reason 最小披露 |
| owner 正式空 | 来源保真视图 | 显示“正式为空”并保留来源/时间依据；不当 missing/unavailable |
| missing/not-covered/restricted | 来源保真视图 | 分别呈现缺失、未覆盖和裁剪；不推导不存在 |
| partial/stale/unavailable/conflict | 来源视图、主题、恢复 | 保留各轴和安全信息，局部禁用动作；不合成全局状态 |
| safe-field/redaction 不清或 forbidden body 出现 | 所有 boundary mapper/output seam | 采用更小上限；丢弃正文，不缓存/日志/诊断/播报/导出 |
| 草稿含禁止字段或绑定旧语境 | 受控意图与结果 | `invalid` 或安全清理；重新绑定当前语境后才可复核 |
| 提交前语境/资格变化 | 受控意图与结果 + context | eligibility blocked；不得沿用旧按钮/reviewable 状态 |
| transport/response 中断 | 受控意图与结果 | `RequestPhase=unknown`；不成功、不重放，转 formal reconciliation/blocked |
| receipt 只有 accepted/pending | 受控意图与结果 | 保持处理中；只有正式 result 收口 |
| reconciliation 缺失/失败 | 结果与恢复 | unknown/blocked；允许 safe exit/keep-draft/support direction，禁止猜测 |
| result/ref 过期、撤销或 owner 不匹配 | 结果与来源 | 撤除链接/敏感呈现并重查；不可移植 scope/owner |
| topic contract/activation 缺失 | 管理主题 | pending/blocked/read-only/partial；mock/flag 不开放正向动作 |
| 单一 owner 故障、其他成功 | 管理主题 | 只降级相关区域；成功不掩盖失败，失败不拖垮无关主题 |
| invalidation hint 缺失/重复/乱序 | 韧性 | 显式 Query 为 fallback；无正式 envelope 不启用 consumer，不维护 cursor/replay |
| safe-link 失效或外围项目未停审 | 来源/主题导航 | 移除/阻断，不猜 URL、不携带私有状态 |
| diagnostic sink 失败 | 韧性/诊断 | 不改变结果、资格或 recovery；不补发敏感正文 |
| focus/announcement/keyboard/非颜色语义不等价 | 可访问交互 | 视为核心路径未闭合；视觉路径不能抵消 |
| state carrier 不可用/清理失败 | 韧性/state carrier | 收紧为会话内最小状态；不改变 owner truth 或放宽安全 |
| 多标签页/旧视图并发 | context/view/intent | 提交前重验，旧 view 标 stale/conflict；不假定客户端原子一致 |

### 10.2 语境失效影响

```text
正式撤销 / 过期 / 冲突 / 无法验证
                 │
                 ▼
AccessContext -> revoked / expired / conflict / unknown
                 │
                 ├─ NavigationState：清理敏感入口/选择
                 ├─ OwnerViewModel：撤除/收紧旧 snapshot/ref
                 ├─ DraftIntent：阻止提交，按安全规则保留/清理
                 ├─ Request/Result：阻止新动作，不改写已有正式结果
                 └─ AccessibilityState：焦点回到安全入口并播报
                                      │
                                      ▼
                           显式 ResolveAccessContext
```

收紧优先于恢复；旧 cache、route 或页面状态不能继续放行。

### 10.3 部分/冲突数据影响

```text
Owner A：fresh + complete + available
Owner B：stale + partial + degraded
Owner C：conflict / unavailable
                 │
                 ▼
OwnerViewCompositionService
  - 每个 owner 独立 SourceStatusAxes
  - 不补齐、不择优、不合成全局绿色
                 │
                 ▼
TopicViewModel
  - A 正常呈现
  - B 标 partial/stale，禁用依赖动作
  - C blocked/unavailable，保留安全回链/恢复入口
```

### 10.4 Unknown command 影响

```text
SubmitControlledIntent ── transport/response ambiguous ──> RequestPresentation=unknown
      │
      ├─ 正式 reconciliation 可用 ──> pending / confirmed / rejected / unknown
      └─ 无正式 reconciliation / idempotency basis ──> RecoveryPlan=blocked
                                                        - 禁止自动 retry
                                                        - 允许 safe exit/keep-draft
```

Unknown 是副作用是否发生不可判定，不是失败或成功的别名。本地 request id、随机 key、refresh 或 toast 不构成幂等依据。

### 10.5 Forbidden-body 影响

```text
Owner result / error / event hint / user draft
                 │
                 ▼
Boundary mapper + ForbiddenBodyPolicy
       ┌─────────┴─────────┐
       │ safe summary/ref   │ forbidden body
       ▼                    ▼
Safe object/ref           丢弃正文 + 最小安全错误标记
                              ├─ 不缓存
                              ├─ 不日志/诊断正文
                              ├─ 不播报/导出正文
                              └─ 不改变 owner result
```

不能先存储后脱敏。具体 safe-field/error mapping 由正式 owner contract 与 03 承接。

## 11. 配置影响轮廓

> 校准来源：
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置影响轮廓表”“禁止配置化边界”“03 详细设计承接方向”和“待确认事项”小节。

### 11.1 配置影响

| 主要部分 / 接缝 | 是否受配置影响 | 配置影响类型 | 允许影响范围 / 03 承接 |
|---|---|---|---|
| session shell / access provider | 间接 | profile、endpoint、state-carrier policy | 选择正式 provider/adapter；失败 fail-closed；03 定义 composition/cleanup |
| `AccessContext` / disclosure guards | 否 | 不适用 | 规则不可配置；仅接收正式输入和验证后的依赖 |
| 导航、布局、筛选、有限偏好 | 是 | feature/preference/layout policy | 只影响顺序/布局/默认探索并可收紧；03 定义 typed preference/migration |
| SDK/owner adapters | 是 | endpoint、profile、adapter registry、technical timeout | 只选正式 adapter，不得切 DB/private bus；03 定义 validation/error mapping |
| owner-safe Query | 间接 | concurrency/budget/page/cache/cancellation policy | 有界 fan-out/技术行为；不改状态语义/coverage；03 定义 invalidation |
| `SourceStatusAxes` / safe-field mapping | 否 | 不适用 | 语义来自正式合同；缺失时 fail-closed/partial |
| draft/request/view state carrier | 是 | medium/store scope、retention/cleanup/migration | 只影响本地交互状态；03 定义 carrier/lifecycle，04 说明具体项 |
| eligibility/completion/unknown guards | 否 | 不适用 | 资格、终态、unknown 重放红线不可绕过 |
| command/reconciliation adapters | 是（仅接缝） | endpoint、profile、timeout、retry policy | retry 仅在 owner 正式幂等依据内；03 定义 propagation/mapping |
| topic registry/routes | 间接 | feature/topic registration/safe-link policy | 可隐藏/分组/收紧已激活主题；配置不提升 activation |
| optional invalidation consumer | 是 | feature/subscription profile/endpoint | 仅有正式 envelope 才启用；否则显式 Query fallback |
| safe-link / diagnostic sink | 条件化 | allowlist/endpoint/redaction/retention policy | 只用正式 link/ref 和安全诊断；sink 失败隔离 |
| accessibility adapters | 是（细节） | focus/announcement/locale/support profile | 只影响呈现机制；语义等价和安全上限不可关闭 |
| technical budgets | 间接 | timeout/concurrency/page/batch/retry | 只有 authority 完整时配置；不成为业务阈值/verdict |
| Outbound Event / Operations Job | 不适用 | 不适用 | 当前不存在；若未来新增须回退 01/02，不通过配置创建 |

### 11.2 禁止配置化边界

| 禁止配置化边界 | 原因 / 变更入口 |
|---|---|
| Console 与 owner 的 truth 归属、SDK-only | 单一真相和依赖根边界；只能回退正式 00/01/ADR，不可由 endpoint 绕过 |
| actor/scope/visibility/qualification 来源与 fail-closed | 防止本地授权、旧权限和存在性泄露 |
| Query no-write、五个来源状态轴 | 防止读取推进业务或压平为统一结论 |
| draft/request/receipt/result/unknown 分层 | 防止 UI/transport/cache 伪造完成 |
| unknown 无正式 reconciliation/幂等依据不重放 | 防止重复副作用 |
| forbidden-body 零进入 | 配置只能进一步收紧，不能允许正文旁路 |
| owner 局部故障隔离 | 防止全局错误扩散或成功掩盖失败 |
| a11y 与视觉共享语义和恢复上限 | 防止第二资格/业务路径 |
| 未停审 L5/L6 只作 pending link/ref | 防止私有状态成为本仓 truth |
| 无 BFF/worker/projection/outbox/business DB | 防止配置创造未设计运行单元和第二 truth |
| 无 authority 的 SLA/阈值/控制项/指标数字 | 防止配置值伪装验收、合规或 readiness |

本章不定义配置项、默认值、JSON/YAML、环境变量、文件路径、secret、加载器或部署/热更新。03 应收口 runtime composition、typed validation、adapter registry、state carrier/cache invalidation、command/reconciliation、safe-link/diagnostic/a11y 和 technical-budget authority；04 才说明具体项如何填写、校验和使用。

### 13.1 设计风险

| 风险 | 影响 | 当前处理口径 |
|---|---|---|
| Owner exact Query/Command/Result/Ref 与 activation 未闭口 | API/adapter/flow/result/activation/03 协议 | 能力级 seam；逐 owner/主题 pending/blocked/read-only/partial，不继承旧接口/Provider/mock |
| Scope owner/层级/切换/撤销不明 | context/navigation/direct-link/all protected flows | 外部正式 ref；不可验证/冲突 fail-closed，不本地建模 |
| Visibility/qualification/reason/redaction 不一致 | navigation/topic/action/submit/disclosure | 客户端只收紧，unknown/撤销阻断，更小披露上限 |
| Safe-field 与来源五轴不统一 | view/cache/error/diagnostic/export | per-owner mapping、多轴保真；exact 未闭口只允许最小 summary/ref |
| Unknown 缺 reconciliation/幂等 | request/result/recovery/repeat effect | 不重放、不成功；无正式回查时 unknown/blocked |
| 多 owner 时效/覆盖/一致性/可用性不同 | TopicView、联合摘要、恢复 | 分 owner 状态和局部降级，不合成 health/compliance/audit/readiness |
| Workspace/Method/Capability/Observability/Archive/Sandbox surface 成熟度不同 | 八类主题/正向入口/link/result | 条件消费；只读/partial/blocked；不阻塞公共安全壳 |

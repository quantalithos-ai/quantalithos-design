## 1. 模块职责描述

**本模块做什么**:
- 持有正式 ConsoleWorkspace / GlobalNavState / PanelState / CrossPanelContext / ConsoleActionEntry / UnifiedSummaryCard / PermissionHint / WorkspacePreference 等工作台层真相
- 把 chat、runtime、artifact、observability、archive、capability 等多个产品面组织成统一的工作台体验
- 管理 panel orchestration、quick actions、workspace-level summaries、permission/stale hints 和个性化工作台布局
- 向用户、operators、owners、console shell、analytics 提供统一的工作台入口、只读消费面与交互事件面

**本模块不做什么**:
- 不持有 chat、runtime、artifact、observability、archive、capability-hub 的 source truth
- 不直接执行 source actions 成功状态推进
- 不替代 authorization truth、source policy truth、shared UI library 本体或 analytics 本体

## 2. 前置设计前提 / 内容采集提示

### 2.1 为什么在写 03 前要先采集内容

`03-详细设计` 的目标不是再讲 console“为什么存在”,而是让开发者可以直接开始实现:
- workspace entry / global nav 怎样把多个能力面组织成统一工作台入口
- panel state / split / cross-context 怎样在不污染 source truth 的前提下联动多个产品面
- quick actions / command palette / jump / handoff 怎样成为安全的操作入口
- unified dashboard / preview / summary 怎样聚合 chat、runtime、artifact、observability、archive、capability 的只读结果
- permission hint / stale warning / personalized layouts 怎样帮助用户理解当前状态并形成自己的工作台

如果不先把这些内容采集清楚,03 很容易退化成:
- 页面组件树和导航配置表
- layout / tab / panel 状态机笔记
- dashboard 卡片清单
- 各个子面板各写一套上下文逻辑,彼此脱节

### 5.1 为什么要先按主要部分展开

`03-详细设计` 不能直接从 `ConsoleWorkspace / PanelState / UnifiedSummaryCard / PermissionHint` 这些对象平铺开始。
更稳的写法是:

#### 5.2.4 关键函数代码片段

```rust
/// 根据当前用户上下文打开正式控制台工作台入口。
fn open_console_workspace(
    workspace_repo: &dyn ConsoleWorkspaceRepo,
    input: OpenWorkspaceInput,
) {
    // [input.校验入口边界]
    // 先确认 workspace 入口只消费 source refs 和可见入口集合,不反向定义源仓真相。
    input.validate_workspace_entry_boundary();

    // [ConsoleWorkspace::从输入创建]
    // 再把入口、导航和最近访问上下文收束成正式工作台对象。
    let workspace = ConsoleWorkspace::from_input(input);

    // [workspace_repo.保存工作台状态]
    // 最后把工作台和导航状态写入 console 层,供 panels/actions/summaries 主线消费。
    workspace_repo.save_workspace(workspace);
}
```

这段实现守住的边界是:
- workspace 只是工作台入口层,不反写 source truth
- 全局导航状态只表达 UX 状态,不冒充授权真相
- recent/pinned 只是体验组织,不替代正式对象目录真相

- 不持有 domain source truth
- 不替代 authorization truth
- 不负责 panel 内业务视图本体
- 不负责 source action 成功与否

#### 5.2.6 该部分与其他主要部分的接缝
- 向 `多面板组织与上下文联动部分` 提供 workspace 锚点
- 向 `操作入口与工作流辅助部分` 提供当前 section 与入口上下文
- 向 `状态提示、权限反馈与个性化工作台部分` 提供导航提示输入

#### 5.2.7 该部分的状态 / 约束 / 易错点

```rust
/// 根据当前用户选择同步多个面板之间的共享上下文。
fn sync_cross_panel_context(
    panel_repo: &dyn ConsolePanelRepo,
    context: CrossPanelContext,
) {
    // [context.校验上下文边界]
    // 先确认共享上下文只是工作台联动信息,而不是 source systems 的共享真相。
    context.validate_cross_panel_boundary();

    // [panel_repo.同步面板上下文]
    // 再把上下文同步到相关面板,触发 drilldown、summary 和 action 可见性更新。
    panel_repo.sync_context(context);

    panel_repo.save_panel_state();
```

- 不持有业务状态真相
- 不替代 runtime/process orchestration
- 不负责 source object 状态推进

- summary、dashboard、stale hints、panel projections 属于可最终一致读路径
- workspace_summary_view / panel_projection_view / dashboard_slice_view 绝不能反向成为 source truth 写源
- action / summary / permission 的分歧必须回收到 action history、source refs 与 workspace state 对账主线

### 7.4 API / 命令签名

#### `OpenWorkspace`

```text

  - entry_refs
  - current_user_ref

  - workspace_id
  - error: WORKSPACE_ENTRY_INVALID / ENTRY_REF_MISSING / SECTION_SWITCH_INVALID

side effects:
  - 写入 ConsoleWorkspace / GlobalNavState
  - 触发默认 panel 组装
```

#### `TriggerQuickAction`

```text
  - 发起 source action 调用
  - 刷新 permission/stale/status hints
```

### 7.5 关键函数/命令级伪代码

#### `SaveWorkspaceLayout`

```text
function SaveWorkspaceLayout(input):
    1. 校验 workspace 存在
    2. 校验布局只包含 UI 层状态
    3. 收束 panel 排列、split 布局、默认入口为 SavedLayout
    4. 写入 WorkspacePreference
    5. 追加 layout change history
    6. 返回 saved layout id
```

#### `BuildUnifiedSummary`

```text
function BuildUnifiedSummary(input):
    1. 校验 summary 输入都可回指 source refs
    2. 读取 health/cost/chat/artifact/archive/capability 只读视图
    3. 生成 UnifiedSummaryCard / DashboardSlice
    4. 标记 stale 或 incomplete 状态
    5. 写入 summary projection
    6. 返回 summary ids
```

### 7.10 错误码定义

| 错误码 | 含义 | HTTP / RPC 映射 | 恢复策略 |
|---|---|---|---|
| `WORKSPACE_ENTRY_INVALID` | 工作台入口非法 | 400 / INVALID_ARGUMENT | 修正入口或 source refs |
| `PANEL_CONTEXT_MISMATCH` | 跨面板上下文不一致 | 409 / FAILED_PRECONDITION | 重新同步上下文 |

| 可恢复异常 | stale summary、panel 未同步、action backlog、layout restore 延迟 | 重试或刷新 |

## 11. 异常与补偿设计

| 场景 | 处理 |
|---|---|
| source refs 缺失 | 阻断工作台打开或标记 panel unavailable |
| cross-panel context 不一致 | 阻断同步并标记 stale |
| quick action 可见但 source target 不可用 | 拒绝触发并刷新 permission/stale hints |
| unified summary 缺失部分 source inputs | 标记 incomplete/stale,不伪造结果 |
| saved layout 非法 | 拒绝保存或恢复 |

### 11.1 重试 / 降级 / 熔断 / 补偿
- panel source 短暂失联时可保留工作台壳并显示 stale,但不伪造 summary
- action dispatch 失败时可重试,但必须将“已触发”和“已成功”分层展示
- summary/hint 投影失败时可重建,但不回滚 workspace truth

### 11.2 按主要部分归属的失败模式

| 主要部分 | 典型失败 | 检测点 | 处理策略 | 补偿 / replay |
|---|---|---|---|---|
| 工作台入口与全局导航部分 | 入口 refs 失效 / nav 状态漂移 | workspace entry boundary validate | 拒绝打开或标记 stale | 刷新入口后重试 |
| 多面板组织与上下文联动部分 | cross-panel context 不一致 / split 布局失真 | cross-panel boundary validate | 阻断同步 | 重建 shared context |
| 操作入口与工作流辅助部分 | action 可见但不可执行 / success 展示误导 | action entry boundary validate | 拒绝触发或分层提示 | 重试 dispatch |
| 统一视图消费与摘要呈现部分 | summary 缺 refs / unified view 错配 | summary source boundary validate | 标记 incomplete/stale | 重建 projections |
| 状态提示、权限反馈与个性化工作台部分 | permission/stale hint 与 source 冲突 / layout 非法 | assist source boundary validate | 阻断保存或显示 conflict | 重建 hints / 恢复默认布局 |

## 15. 结论

本详细设计的核心结论是：
- `L5-console` 的实现主轴必须按 workspace / panel / action / summary / assist 五个主要部分组织,而不是按导航、面板、表格、组件树平铺
- console 真相层只持有工作台状态、面板编排、动作入口、统一摘要和个性化偏好,不接管 chat/runtime/artifact/observability/archive 的 source truth
- 所有 unified summary、quick action、permission hint、saved layout、cross-panel context 都必须建立在稳定 source refs、只读消费和 append-only 行为证据之上

后续测试与验收文档,应直接围绕这套统一工作台主链、跨面板联动、动作入口分层和解释层边界展开.

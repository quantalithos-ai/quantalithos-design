## 3. 实现约束与编码规范承接

> 校准来源：
> - `design-calibration/03_ddd_step_03_coding_runtime_constraints.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“语言/runtime 事实”“依赖裁剪”“编码规则”“未锁定技术项”和“待确认事项”。

| 维度 | 约束 |
|---|---|
| 语言/runtime | planned TypeScript/ESM 浏览器客户端；严格类型、具名导出、导出符号中文 JSDoc、readonly carrier、不可变更新 |
| SDK | 仅消费官方 `@quantalithos/sdk` package/public formal surface；禁止引用 SDK 私有源码或 sibling owner source |
| 查询 | 所有 Query 零 owner/local 隐式写入；筛选和 `ClientPageWindow` 只作用于已取得的安全材料 |
| 命令 | 唯一 owner side effect 是 `OwnerCommandPort.submit`；receipt/transport/toast 不是终态；可能已 dispatch 时进入 `unknown` |
| 安全 | route/menu/button/flag/cache 不授权；actor/scope/visibility/qualification/safe-field 只能来自正式观察；forbidden body 零进入 |
| 状态 | positive `verified/visible/fresh/current/confirmed/active` 只由新 formal observation 建立；本地只保持或收紧 |
| 外部 truth | 不直连数据库、服务源码或私有 bus，不复制 Policy/Gate/owner rule，不创建 owner projection |
| 未锁定项 | framework、router、bundler、package manager、browser matrix、carrier medium/TTL、diagnostic envelope、exact owner methods/schema 均 pending |
| Rust/Cargo | 对当前客户端 `N/A (non-Rust)`；不得机械迁入 crate、binary、Rustdoc 或服务端分层 |

TypeScript 代码块是 planned contract，不代表源文件已存在或编译通过。`unknown` 只允许存在于 transport intake，并须在进入正式对象前由 adapter/schema guard 收窄；业务对象不得使用 `any` 或裸 `unknown`。任何需要新增字段、状态、Port、owner path、错误码或固定阈值的实现，都必须先回写对应设计 Step。

### 4.3 文件职责与依赖方向

| 文件组 | 定义 | 不得定义 |
|---|---|---|
| `entry/*` | composition root、local ref/host seam、session shell | 认证、授权、owner rule |
| `access/*` / `navigation/*` | context/ref/guard、route/selection/visibility | credential、Policy/Gate、route-derived permission |
| `views/*` | safe payload/ref/source axes、Query guards | raw response、owner aggregate、统一 health |
| `intent/*` | local draft、request phase、formal result ref | owner validation、idempotency、终态猜测 |
| `features/*` | topic descriptor、owner partitions、page semantic regions/actions | 八个 owner 的 domain copy |
| `recovery/*` | local degradation、explicit action、a11y semantic | 自动 replay、补偿 job、全局故障态 |
| `adapters/*` | 窄 Port implementation、formal mapping、availability | DB、private API/bus、第二业务层 |

| `diagnostics/*` | typed body-free context/sink facade | audit/evidence/report/verdict |

依赖方向为 `entry → public module seams → consumer-owned ports ← adapters/host/state/diagnostic implementations`。业务模块不得 import concrete adapter；adapter 只 type-only 消费安全输入/输出，不依赖页面、router/store 或 DOM。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源：
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“Shared protocol surface”“Command protocols”“Query protocols”“Conditional inbound consumer”和“字段来源与构造闭环”，获取逐字段 TypeScript schema。

### 7.1 共享 surface

```ts
export interface ConsoleOperationMetadata {
  readonly operationRef: LocalReference<'query' | 'request' | 'invalidation'>;
  readonly sessionRef: LocalReference<'session'>;
  readonly contextRef?: LocalReference<'context'>;
}

export type LocalCommandOutcome<T> =
  | Readonly<{kind: 'applied'; value: T}>
  | Readonly<{kind: 'blocked'; error: ConsolePortError}>
  | Readonly<{kind: 'cancelled'; error: ConsolePortError}>;

export type QuerySurface<T> =
  | Readonly<{kind: 'value'; value: T}>
  | Readonly<{kind: 'empty'}>
  | Readonly<{kind: 'blocked' | 'unavailable' | 'unknown'; reasonRef?: OwnerReference<'reason'>}>;
```

`operationRef` 是本地 correlation，不是 owner request/event/idempotency id；`QuerySurface.empty` 只能来自 formal empty 或明确本地 missing。`ClientPageWindow` 是本地安全切片，不是 owner cursor/page token/version。

### 7.2 Command 契约

| Command | 必需输入 | 输出/副作用 | 失败与当前上限 |
|---|---|---|---|
| `RequestAccessContextSwitch` | metadata、current context、optional target local ref | formal resolve 后清理旧 scope、替换 shell；无 owner write | missing/transport/cancel→restricted/blocked；不从 route 构造 context |
| `SaveClientPreference` | metadata、exact scope、typed topic/filter/window patch | whole-record local replace | unsafe authority field/scope mismatch/carrier unavailable；当前仅 session-volatile |
| `DiscardDraftIntent` | metadata、nonterminal draft、controlled reason key | draft→discarded + local replace；无 owner call | submitted/discarded 为非法转换；reason key 非 owner reason/evidence |
| `SubmitControlledIntent` | reviewable draft、current context、command、qualified observation、exact contract ref | 恰好一次 `OwnerCommandPort.submit`，映射 request presentation | exact DTO/idempotency 缺失时调用前 blocked；可能 dispatch 后 unknown；禁止自动 replay |
| `ApplyRecoveryAction` | current plan/action/context、optional request | 恰好一个 requery/revalidate/reconcile/keep-draft/exit 分支 | stale/mismatch/blocked action fail-closed；无 generic retry/loop/job |

所有 topic Query 的 outer request 为 `metadata + TopicDescriptor + AccessContext + optional FilterIntent/ClientPageWindow`，response 为 `QuerySurface<TopicPageModel>`。每个协议按 §5.6 固定 owner partitions 独立读取与组合；完成顺序不改变 canonical 输出。只有所有适用 owner 均 formal empty，且没有 partial/blocked/unavailable/unknown，页面才可 `empty`。

### 7.5 Conditional consumer 与不适用族

`ConsumeSdkInvalidationHint` 的 candidate envelope 只允许 body-free contract/source/local invalidation/context refs。因 event id、schema version、order、dedup、replay 与 payload authority 未闭口，production branch 必须是 `disabled/pending-contract` 且零写入；未来只有验证 source/contract/scope 后才能映射 marker 并执行单调收紧。

Console 无 Outbound Event、无 Operations Job、无 admin/internal server API。diagnostic emission 不是业务 event；用户显式 requery/revalidate/reconcile 不是 job。不得新增 event bus、outbox、consumer receipt、DLQ、scheduler、BFF 或后台 repair。

## 8. 逐接口函数级处理流

> 校准来源：
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“Shared execution template”“Command flows”“Core Query flows”“Management topic Query flows”和“Cross-flow audit”，获取逐调用顺序、分支与测试入口。

### 8.1 统一执行纪律

```text
protocol entry
  -> validate metadata / context / scope
  -> pure guard or typed mapper
  -> one narrow Port call
  -> preserve value / empty / blocked / unavailable / unknown / cancelled
  -> explicit local immutable replace only when Command permits
  -> optional presentation/diagnostic/a11y side path (failure isolated)
```

formal call 与 local carrier operation 从不构成分布式事务。formal success、local install failure时只返回安全 observation/ref 和 local failure，禁止反向补偿 owner。Query 不安装结果；安装必须由调用方另行校验当前 scope/correlation。

### 8.2 五个 Command flow

| Flow | 顺序 | side effect / 失败语义 |
|---|---|---|
| `RequestAccessContextSwitchFlow` | validate→formal resolve→cleanup old record→replace shell/context→host present | local cleanup/replace；host failure不撤销安全 cleanup；旧 context 不恢复 verified |
| `SaveClientPreferenceFlow` | scope guard→typed patch validate→build next record→carrier replace | local whole-record only；重复等值可 unchanged；不影响 formal states |
| `DiscardDraftIntentFlow` | draft transition→build next record→carrier replace | local only；保存失败不声称已持久 |
| `SubmitControlledIntentFlow` | qualification→create submitted request→owner submit→map observation→carrier replace | 唯一 owner write；receipt/result/ambiguous 分层；install 失败不重发 |
| `ApplyRecoveryActionFlow` | plan guard→exactly one narrow action→a11y map→optional focus/announce | formal reads/local/host effects；a11y failure不改结果；`retry-command` 当前 blocked |

### 8.3 八个 Core Query flow

| Flow | 主要调用链 | 保守分支 |
|---|---|---|
| `ResolveAccessContextFlow` | context resolver→validate refs/lifecycle→QuerySurface | 不安装；cancel/invalid 保守 |
| `GetNavigationVisibilityFlow` | visibility resolver→topic/context同源 | 无 route/menu fallback |
| `QueryOwnerViewFlow` | no-write guard→disclosure→owner query→safe mapper/status→view compose→local filter/window | forbidden whole reject；无 cache/projection repair |
| `GetSourceStatusFlow` | snapshot/source/owner validation→status map | 不压为 health/readiness |
| `GetSafeLinkFlow` | intent/context validate→formal revalidate | 只返回 typed ref；不导航 |
| `GetRequestPresentationFlow` | scope guard→carrier load→exact request lookup | missing 是 local empty；不隐式 reconcile |
| `ReconcileRequestResultFlow` | request/context/ref validate→formal reconcile | 只读；cancel/timeout unknown；不 submit |
| `GetTopicActivationFlow` | activation observe→map→owner membership/six-facet guard | 无 capability/current facet 不 active |

### 8.4 八个 Topic Query flow

每个 public topic protocol 是下列参数化算法的独立实例：验证 current context→查询 topic visibility→按 descriptor canonical owner order 逐分区获取 activation→允许 read 时执行 `QueryOwnerViewFlow`→保留每个分区 blocked/unavailable/unknown→组合 `TopicViewModel`→组合语义 page→映射 a11y。独立 reads 可在 §12 约束下并发，但聚合顺序固定，单一 owner 失败不取消已安全完成分区，也不产生 global normal。

| Public flow | owner partitions | 专项禁止事项 |
|---|---|---|
| `QueryMemberManagementTopicFlow` | identity、member-service | 不读取/推导 member lifecycle、role 或正文 |
| `QueryProjectWorkspaceTopicFlow` | work、process、workspace | 不建立 projection/cursor/rebuild 或项目 readiness |
| `QueryMethodAssetTopicFlow` | method-library、artifact | 无正式 command map 时保持 read-only |
| `QueryGovernanceControlTopicFlow` | governance、artifact | Gate/SoA/AIIA/Control 仅 formal ref/view，无 verdict/evidence body |
| `QueryObservabilityTopicFlow` | observability | metrics/audit view 只读，无 threshold verdict |
| `QueryCapabilityHubTopicFlow` | capability-hub | 不推导 registration/readiness |
| `QueryArchiveTopicFlow` | archive | 不执行 archive/restore command |
| `QuerySandboxTopicFlow` | sandbox | 不执行 run/start/cleanup 或推导 runtime readiness |

### 8.5 Conditional invalidation flow

```text
SdkInvalidationPort.observe
  -> disabled/pending-contract: return, zero write
  -> observed (future): validate contract/source/scope/context
  -> map body-free marker
  -> ClientStateCarrierPort.invalidate (monotonic tighten)
```

当前可绑定分支仅 disabled/pending-contract。重复 hint 最多产生等价或更保守状态；不创建 cursor、receipt store、owner transition 或命令调用。

## 9. 状态机与转换矩阵

> 校准来源：
> - `design-calibration/03_ddd_step_10_state_matrix.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的逐主语转换矩阵、“非法 shortcut”和“Cross-state audit”；实现与测试必须逐字使用其中状态名。

统一规则：Query 不推进状态；diagnostic/presentation success 不推进业务状态；本地仅保持或收紧 formal-derived 状态；positive recovery 只能来自新 formal observation；非法迁移返回 typed `invalid-state-combination` 或 `consistency-defect`。

| 状态主语 | 状态/主线 | 合法触发 | 禁止触发 |
|---|---|---|---|
| context | `unresolved→verified/restricted→expired/revoked/conflict/unknown`；非 current 可由新 formal observation 替换 | resolve/revalidate/invalidate/restrict | route、carrier、render、cache 恢复 verified |
| qualification/visibility | positive→restricted/not-qualified/disabled/unknown/unavailable；新 formal observation 可重算 | formal observation、本地 tightening | role/menu/flag/page→qualified/visible |
| navigation | empty↔guarded selected；visibility/context→restricted/empty；cleanup→empty | select/apply/clear | host navigate success 提升 visibility |
| source/ref | fresh/complete/available/coherent/current 只可本地向 conservative 值移动 | formal material、invalidation、新 formal query | timer/cache/DOM→fresh/current；合成 health |
| draft | editing↔invalid；→reviewable；reviewable→submitted；非terminal→discarded | edit/validate/submit/discard | submitted/discarded 编辑或复活；reviewable→authorized |
| request/result | submitted→accepted/pending/confirmed/rejected/unknown；unknown 经 formal reconcile | formal receipt/result/reconciliation、ambiguity | toast/2xx/cache→terminal；unknown 自动 replay |
| activation | pending→read-only/partial/active/blocked；local 只能收紧；新 formal facets 可重算 | capability + mode + six facets + context | flag/adapter/package/page→active |
| degradation/recovery | non-normal axes→degradation→immutable plan→one explicit action→new observation | status/invalidation/formal observation/user action | timer/action completion→recovered；hidden retry loop |
| carrier | missing→loaded；loaded replace/invalidate；any clear→missing；ambiguous→caller unknown | exact-scope carrier operation | scope migration、CAS/version 假设、load 恢复 formal positive |
| shell | bootstrapping→presentable/restricted/closed；presentable↔safe replacement/restricted；closed terminal | validated page/context/cleanup/close | state load→presentable；closed reopen |
| a11y/diagnostic | semantic focus/announcement 与 emitted/disabled/failed | same guard/binding/emission | 改变 context/result/activation/recovery allowance |

`SourceStatusAxes` 的 freshness、coverage、availability、consistency 与 reference validity 独立；`not-covered` 只能来自 formal mapping。`confirmed/rejected` 是同一次 formal result observation 的 presentation terminal；本地不能重开。`active` 是 consumption posture，绝非系统、服务或能力 readiness。

| Operation | 契约 | 不确定/失败恢复 |
|---|---|---|
| `load(scope)` | 全对象验证后才暴露 loaded；missing 与 scope mismatch 区分 | malformed 整体拒绝，必要时清 exact scope；不 salvage |
| `replace(record)` | 单 carrier instance 的 whole-record immutable replacement | completion unknown 必须 reload；不假定旧/新胜出 |
| `invalidate(record, marker)` | exact scope、单调收紧、再 whole-record replace | duplicate 等价；无 ordering proof 保持 stale/unknown |
| `clear(scope)` | exact-scope forget；不是 owner revoke | 失败时先移除内存敏感呈现并保持 restricted |
| `observe()` | 只报告 carrier binding posture | 当前不得正向声称 configured durable medium |

formal query/command 与 carrier replace 不原子。Query 全部零写入；safe installation 是独立 caller operation，并须重检 scope/correlation。controlled submit 的 owner side effect 与 local request save 不构成事务；local save 失败只允许 formal reconciliation，不允许重新 submit。

同 scope mutation 当前采用单 writer、顺序执行；设计没有 revision/CAS，因而不承诺跨 tab 并发安全。context switch/logout/revoked 默认清 navigation/page/request/recovery/invalidation，draft 默认清；owner invalidation 只收紧对应 partition。carrier load 永远不能单独恢复 `verified/current/active/confirmed`。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“Error layers”“definitive semantics”“Protocol error mapping”“Recovery ceilings”“Redaction”和“Exceptional branches”。

错误层次为：factory/state transition→`ObjectConstructionViolation`；module guard/adapter/host/carrier→`ConsolePortError`；protocol→`LocalCommandOutcome/QuerySurface/RequestPresentation`；page/a11y→受控语义状态；diagnostic→`emitted/disabled/failed`。裸 `Error`、SDK 私有异常、HTTP body/status、stack、credential 与业务正文不得越过 adapter。

| Error kind | 安全语义 | 恢复上限 |
|---|---|---|
| `missing-formal-surface` / `unsupported-operation` | required contract absent/not approved | pending/blocked；等待设计/合同，不调用 |
| `context-not-current` / `visibility-not-current` / `qualification-unknown` | 正式前置不可证明 | revalidate/requery/exit；绝不本地判 allow/deny |
| `malformed-safe-material` / `forbidden-body` | 输入违反 safe schema | 整份受影响材料丢弃；不保存/诊断正文 |
| `transport-unavailable` / `cancelled` | 无可用正式观察或本地等待取消 | Query 可显式再查；command 依据 dispatch 边界判 cancelled/unknown |
| `ambiguous-outcome` | owner side effect 可能已发生 | request `unknown`；只 formal reconciliation |
| `reconciliation-unavailable` | 无正式 result lookup | wait/exit；无 replay |
| `state-scope-mismatch` / `state-carrier-unavailable` | 本地 scope/介质不可用 | exact cleanup/reload/minimal shell |
| `host-binding-unavailable` / `diagnostic-sink-failed` | host/optional side path 失败 | 业务结果不变；提供等价通道或 disabled/failed |
| `invalid-state-combination` / `consistency-defect` | 对象或跨 ref 关系非法 | fail closed、丢弃 affected material、修复设计/adapter |

错误呈现只能从 typed kind/posture 选择受控 message key；不得泄露对象存在性、Policy/Gate rationale、正文或任意 error text。恢复动作必须按 subject 限定：context→revalidate/exit，view→requery，unknown request→reconcile/wait/exit，carrier→reload/clear，host/a11y→等价 fallback；不存在 retry-all、后台修复或命令补偿。

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“mutable resource map”“Concurrency rules”“Unknown and owner replay protocol”“Invalidation order rules”和“Test cuts”。

| 竞态/重入 | 保护 | 安全结果 |
|---|---|---|
| same-scope local mutation | 单 writer、顺序 whole-record replace | 定义范围内无 lost update；不伪造 CAS/version |
| context switch 与 late Query | 捕获 operation/context/owner/topic refs，安装前重检 | 旧结果丢弃；不得写入新 scope |
| owner partition fan-out | 独立调用、descriptor canonical aggregation | completion order 不改变 page；失败局部化 |
| 多通道 double submit | visual/keyboard/AT 共用 action key 与 single-flight；draft submitted transition | 至多一次 owner submit；第二入口 blocked |
| command cancel/timeout | adapter 区分可证明未 dispatch 与可能 dispatch | 前者 cancelled；后者 unknown，无 replay |
| local save outcome unknown | reload carrier | 不因 reload 或保存失败重发 owner command |
| overlapping reconciliation | request/context/result correlation + terminal ordering guard | older pending 不覆盖 newer formal terminal |
| duplicate invalidation | exact scope + monotonic function | 等价或更保守；无 receipt/cursor store |
| invalidation/query race | 无 formal order proof 时保持 conservative | 禁止 local timestamp/LWW 恢复 freshness |
| diagnostic recursion | sink failure 不触发新 emission | failed 后停止；业务不变 |

本地 ref/hash/timestamp/UUID 均不是 owner idempotency key。`CON-Q-038` 未闭口前没有 production replay path；未来若启用，必须先正式定义 owner operation、key authority、digest coverage、window、duplicate result surface 和 cancellation boundary，并回写 Step 7/8/13。

## 13. 配置引用与外部依赖绑定

>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“Typed binding objects”“配置引用表”“External dependency matrix”“Binding order”和“Forbidden configuration matrix”。

配置只在 `entry` composition root、adapter registry、state/host/diagnostic binding 被读取，业务模块不读 config。完整文件格式、profile 来源、endpoint、secret、timeout/TTL 和默认数值留给正式 04。

| Binding point | 注入接口 | 当前安全上限 |
|---|---|---|

## 14. 可观测性与审计埋点契约

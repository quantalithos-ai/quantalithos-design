## 3. 配置控制面总览

> 校准来源：
> - `design-calibration/04_config_step_03_control_plane.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置来源链图”“配置控制面总表”“配置域 / 功能模块表”“每域小循环与停审”和“跨控制面审计”。

#### 配置来源链图: L5-console 配置覆盖与装配链

```text
[safe defaults for optional fields]
          |
          +------> [one host-provided strict JSON document
                    providing required runtime.profile]
                              |
                              v
                    [merge / strict parse]
                              |
                    [type + cross-field + forbidden checks]
                              |
                    [ConsoleClientBindingConfig]
                              |
          +-------------------+--------------------+
          |                   |                    |
 [adapter registry]   [optional side paths]  [runtime profile]
          |                   |                    |
          +----------> [observe availability] <----+
                              |
                    [buildConsoleRuntime]
                              |
             [injected narrow module dependencies]
```

关键说明：

- external document 必须提供 `runtime.profile`；optional defaults 不能单独组成 runtime，也不能隐式进入 `local-fake`。
- 只有 entry/config pipeline 读取 raw config；业务模块只消费已校验的 typed values 与 narrow Ports。
- `ConsoleRuntimeDependencies` 是宿主注入实例，不是 JSON 字段；SDK client、host/router、carrier、sink 或 credential 不得序列化进配置。
- flag、binding、package 或 route 存在均不能将 slot 标为 `bound`，更不能证明 capability active、数据 current 或系统 ready。

| 控制面 | 作用 | 对应模块 / 对象 | P0 | 禁止控制 |
|---|---|---|---|---|
| source / validation / assembly | 取得一个文档、合并 optional defaults、严格校验并构造 typed config | `entry`、`ConsoleClientBindingConfig`、`buildConsoleRuntime` | 是 | 新增字段、绕过 validator、partial activation |
| runtime profile | 选择既有 runtime posture | `entry` / adapter registry | 是 | readiness、权限、owner truth 或状态机 |
| adapter binding correlation | 将封闭 slot 在指定 profile 下关联 local ref | `entry` / `adapters` | 是 | endpoint、secret、SDK method、owner body；配置即 `bound` |
| optional invalidation | 请求装配 SDK hint side path | `adapters` / `state` | 是 | 直连 bus、cursor/replay、owner write 或 positive restore |
| optional diagnostics | 请求装配 body-free diagnostic path | `diagnostics` | 是 | raw error/body/secret、formal audit/evidence、改变业务结果 |
| dependency injection（非 JSON 域） | 注入 host、formal adapter、volatile carrier 和 diagnostic facade | `ConsoleRuntimeDependencies` | 是（装配） | 把 instance、URL、DOM 或 credential 写入配置 |

| 配置域 | 对应 03 字段 | 允许配置 | 当前安全上限 |
|---|---|---|---|
| `runtime` | `profile` | 选择既有三种姿态 | 名称不等 readiness |
| `bindings` | `adapterBindings[]` | 封闭 slot、profile 与 body-free local ref | owner positive binding 继续 `pending-contract` |
| `invalidation` | `enableSdkInvalidation` | 请求 optional hint path | 默认且当前正式上限为 `false/disabled` |
| `diagnostics` | `enableDiagnostics` | 请求 optional body-free path | 默认 `false`；production positive sink blocked |

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_categories_boundaries.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置分类”“更新时机”“禁止配置化项”“按域分类边界”和“跨分类审计”。

| 配置类别 | 说明 | 示例 | 是否允许热更新 | 主要风险 |
|---|---|---|---|---|
| static design boundary | 不是普通配置，只声明不可变红线 | truth、guard、Query no-write、unknown/no-replay | 不适用 | 被伪装成 flag 会绕过设计 |
| startup runtime selector | runtime 构造前选择 posture | `runtime.profile` | 否 | profile 名被误当 readiness |
| startup binding correlation | runtime 构造前登记封闭 slot 与 local ref | `bindings.adapterBindings` | 否 | 任意 endpoint/method 或虚假 `bound` |
| startup optional-path switch | 请求装配可禁用的旁路 | invalidation / diagnostics boolean | 否 | 合同缺失仍启用或旁路改变业务结果 |
| future sensitive ref | 当前 P0 不适用 | endpoint/credential/provider ref | 否 / 待设计 | 浏览器泄密；必须先回写 03/04 |
| future runtime policy | 当前 P0 不适用 | TTL、sampling、timeout、threshold | 待设计 | 无 authority 数字或改变生命周期 |

四个 P0 配置域全部只在 startup 读取，并在单个 runtime 生命周期内冻结。当前没有 reload、hot 或 build-time 配置；static boundary 只能通过正式设计变更调整。

| 禁止配置化项 | 原因 | 如需改变应走什么流程 |
|---|---|---|
| owner / truth / data ownership | 防止 Console 形成第二真相 | 回写 00/01/02/03 与相应 owner 设计 |
| DB、repository、private bus、BFF、worker/job 或 sibling private schema | 防止绕过 SDK / 正式服务边界 | 架构与详细设计重开 |
| context、visibility、qualification、safe-field / redaction guard | 权限和最小披露红线 | 正式安全合同与 03/05/06 变更 |
| Query zero-write 与唯一 owner submit side effect | 防止读取或 flag 隐式写入 | 协议与 flow 重新设计 |
| receipt/transport/toast/cache/route → confirmed/current/active | 防止 UI 推导 formal state | 状态与 owner 合同重开 |
| unknown/no replay/reconciliation ceiling | 防止重复副作用 | owner 幂等/结果合同与 03 变更 |
| 无 exact contract 的 command、activation 或 invalidation | 防止配置冒充能力 | 合同到达后回写 adapter/protocol/flow |
| forbidden body、credential、secret、raw error、URL 或 DOM | 防止敏感材料进入生命周期 | 默认不可兼容；安全设计变更 |
| state load 恢复 verified/current/active/confirmed | carrier 不是 formal truth | 状态与一致性设计变更 |
| configured durability、TTL、migration 或 cross-session 声明 | `CON-Q-044` 未闭口 | 先回写 03/04/05/06 |
| diagnostic = audit/evidence/report/readiness | Console 不拥有正式证明 | owner/观测合同与架构变更 |
| a11y 通道运行独立动作或放宽 guard | 三通道必须语义等价 | 03/05/06 a11y 设计重开 |
| 未停审 L5/L6 私有 link/ref | 平行项目内容不是本仓真相 | 等双方正式合同后回设计 |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“来源优先级”“冲突处理”“按域来源覆盖”“域内停审”和“跨来源审计”。

普通配置来源只有两层：

```text
safe defaults for optional fields
  < one host-provided strict JSON document with required runtime.profile
```

host 或部署层未来可以选择“哪一份完整文档”，但 Console 收到后只有一个 external document，不支持多个文档逐键 overlay，也不允许 env / CLI 直接覆盖叶子配置。URL、query、hash、DOM、cookie、browser storage、SDK response、config center 和 admin override 均不是 P0 来源。

| 来源 | 优先级 | 适用配置 | 冲突处理 | 不可用时策略 |
|---|---:|---|---|---|
| safe code defaults | 1 | `bindings=[]`、两个 `enabled=false`；不提供 profile | 被 external document 同名字段覆盖 | defaults 自身须合法；单独使用因缺 profile 而 fail-fast |
| one host-provided strict JSON document | 2 | 四域全部；`runtime.profile` 必填 | 覆盖 optional defaults；非法/unknown/duplicate/alias 全部拒绝 | 未提供、不可取得或 parse 失败 → bootstrap fail-fast |
| host/deployment document selector | source-of-source，不进入叶子优先级 | 未来选择完整 artifact | 不允许同时向 Console 传多份文档 | selector 错误阻断当前 bootstrap |
| env / CLI leaf override | P0 unsupported | 无 | 不得映射为叶子覆盖 | 不适用 |
| URL/query/hash/DOM/cookie/browser storage | forbidden | 无 | 绝不合并 | 检测到即拒绝 |
| config center/admin override/hot patch | P2 unsupported | 无 | 不能进入 P0 | 需要先回写 03/04 |
| secret provider/raw secret | 当前不适用 / forbidden | 无 P0 secret item | raw material 不得进入 document | 检测到即安全拒绝 |

| 冲突场景 | 处理规则 | 是否阻断启动 / 操作 |
|---|---|---|
| external 合法字段与 default 同名 | external 覆盖 default | 否 |
| 高优先级值类型、enum 或 ref 非法 | 不回退 default；reject whole document | 是 |
| `runtime.profile` 缺失 | required-field reject；不得隐式 `local-fake` | 是 |
| `bindings` 缺失 | 使用 `[]` | 否 |
| invalidation / diagnostics `enabled` 缺失 | 使用 `false` | 否 |
| JSON duplicate key | strict parser reject | 是 |
| 同义 alias、旧 key、unknown section/field | strict schema reject | 是 |
| 同一 `(profile, slot)` 重复 | ambiguity reject | 是 |
| binding slot/profile/ref 组合非法 | reject | 是 |
| `binding.profile` 与 `runtime.profile` 不同 | cross-field reject | 是 |
| `bindingRef` 为空、URL、secret、credential 或正文 | security reject | 是 |
| flag=true 但 profile/slot/正式合同不允许 | reject；不能变为“true 但偷偷 disabled” | 是 |
| forbidden boundary key | design/security violation reject | 是 |

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_environment_profiles_matrix.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“环境 / profile 总表”“Profile 外部依赖矩阵”“来源矩阵”“测试/验收承接矩阵”和“跨 profile 审计”。

环境角色、runtime profile 与 readiness 是三个不同主语。local/CI/test/staging/prod 是部署或验证上下文；配置只使用 03 已定义的三个 profile；任何 profile 名都不能证明服务健康、数据 current、capability active 或产品 ready。

| 环境 / profile | 用途 | 配置来源 | 外部依赖 | 敏感配置处理 | 差异说明 |
|---|---|---|---|---|---|
| local design/dev → `local-fake` | 本地对象、flow、UI shell 与负向验证 | local strict JSON + optional defaults | parity fake host/formal adapters；session-volatile carrier；fake diagnostic 可选 | 零 raw secret；fixture 不含 credential/body | 允许 fake；flags 默认 false；不证明 integration |
| CI unit/contract → `local-fake` | 可重复 schema、guard 和 fake/formal parity 验证 | checked test JSON；fixture selector 在 document 外 | deterministic parity fake；不要求网络 | 零 secret；fixture 做 redaction 约束 | fake 必须覆盖 blocked/unknown/cancel；本表不表示测试已运行 |
| integration/test → `integration-pending` | formal surface 到达后的按 facet 集成 | 单一受控 strict JSON | 已闭合 facet 才可绑定，其余 pending；volatile state | credential 由 test host/SDK 外部处理 | 当前 positive owner facet 仍 blocked；flags false |
| staging-like → `production-pending` | future production-like rehearsal | 单一受控发布 artifact | 仅 approved formal bindings；不得 fake | browser artifact 零 secret | 当前 blocked/minimal；不得声称 staging ready |
| production → `production-pending` | 正式产品运行目标 | 单一批准 immutable artifact | 所有所需 formal/host/carrier/sink authority 需另行闭合 | 零 raw secret/ref；认证材料由 host/SDK 处理 | 当前 pending，不是可发布 profile；flags false |

| dependency family | `local-fake` | `integration-pending` | `production-pending` |
|---|---|---|---|
| host lifecycle/presentation/route/a11y | parity fake 或受控 local host；仍执行 guards | formal test host 待定 | approved production host 待定 |
| formal owner/SDK adapters | parity fake；不得登记 production `bound` | per-facet contract 到达才可 bind；当前 pending | 全部 required facet 正式闭合才可 bind；当前 pending |
| state carrier | session-volatile | session-volatile | session-volatile 上限；configured medium 未授权 |
| SDK invalidation | false / disabled | false / disabled pending contract | false / disabled pending contract |
| diagnostics | false；可选 body-free fake sink | false；formal test sink 待合同 | false；production sink/envelope pending |
| external L5/L6 links | disabled / pending | 按双方停审合同 | 按双方停审合同；当前不得依赖 |

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“敏感级别归一规则”“敏感配置读取边界图”“禁止输出与泄露风险审计”“读取、轮换与审计承接”和“对详细设计的影响判定”。

当前 P0 没有 `sensitive` 或 `secret` 配置项。四项配置均为 `internal` 装配语义。这个结论不允许将 token、password、private key、cookie、credential、DSN、endpoint 或所谓 secret ref 塞进普通 browser JSON；相反，它明确规定这些材料不属于当前 Console 配置边界。

#### 敏感配置读取图: L5-console 配置与安全边界

```text
[host / SDK authentication boundary]
          |  (opaque authenticated session; raw material not exposed)
          v
[ConsoleRuntimeDependencies / formal adapters]
          ^
          |
[Console strict JSON config]
  profile / slots / local ref / booleans only
          |
          v
[validator + redaction gate]
          |
  secret-like key/value -> reject, no echo
```

关键说明：

- host/SDK 可以在自己的正式安全边界中处理认证，但 credential 不能进入 Console config、state、diagnostic、error 或 page model。
- `bindingRef` 不得作为 endpoint、credential、URL 或 secret ref 的别名，也不得被业务代码解析。
- 当前不调用 KMS、Vault、secret provider 或 credential rotation API；未来引入会改变 builder/adapter/lifecycle，必须先回写 03。

| 配置项 / 材料 | 敏感级别 | 存储方式 | 是否可明文 | 轮换方式 | 审计要求 |
|---|---|---|---|---|---|
| `runtime.profile` | `internal` | strict JSON | 可在内部配置 artifact 中 | 无 | 只记录安全变更类别，不作为业务诊断 |
| `bindings.adapterBindings[].slot/profile` | `internal` | strict JSON | 可 | 无 | 记录结构变化，不记录依赖正文 |
| `bindings.adapterBindings[].bindingRef` | `internal` / opaque | strict JSON 中的非空 opaque 字符串 | 不是 secret，但不得展开或解析 | 无 | 最多记录安全 classification / redacted digest，不记录值 |
| 两个 `enable*` boolean | `internal` | strict JSON | 可 | 无 | 记录 enabled/disabled 变更类别 |
| endpoint、URL、raw SDK config | `sensitive` / forbidden | 不得进入 Console 配置 | 否 | 由正式 host/SDK 边界决定 | Console 只记录安全拒绝类别 |
| token、password、private key、cookie、DSN、raw credential | `secret` | 不得进入任何 Console 材料 | 否 | 正式安全 owner/provider | 外部安全审计；Console 不接触 |
| owner response/event/command/evidence body | forbidden body | 不得进入 config/state/diagnostic | 否 | 不适用 | safe-field/redaction 边界负责拒绝 |

| 输出面 | 允许输出 | 禁止输出 | 失败处理 |
|---|---|---|---|
| parser/validator issue | module/key class、issue kind、profile class、local diagnostic ref | raw JSON/value/path/URL/secret/body | reject whole document；不回显原值 |
| `ConsolePortError` | kind、source、operation/reason ref、retry disposition | HTTP body/status、SDK exception、credential、stack | typed safe error |
| `DiagnosticContext` | approved phase/outcome/ref/redaction marker | config、raw bindingRef、body、secret、DOM、URL | factory/gate failed；不调用 sink |
| `ClientStateRecord` | approved interaction fields | config、adapter、SDK client、secret、raw response | whole-record reject |
| host focus/announce | approved action/status key | error text、owner rationale、user input、secret | equivalent fallback |
| external change/audit record | artifact/version ref、redacted digest、safe key class | full document/raw value/secret/body | 外部 owner 负责；Console 不创建 formal audit |

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_loading_validation_activation.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“配置加载流程图”“加载 / 校验 / 生效表”“按域装配与 activation posture”“validation issue surface”和“跨加载校验审计”。

#### 配置加载流程图: L5-console 配置加载与校验

```text
[safe defaults for optional fields]
        +
[one host-provided strict JSON document with required profile]
        |
        v
[source selection + whole-document merge]
        -> [strict JSON parse / duplicate & unknown check]
        -> [module/type/enum/opaque-ref validation]
        -> [cross-field & forbidden-boundary validation]
        -> [ConsoleClientBindingConfig construction]
        -> [register injected ConsoleRuntimeDependencies]
        -> [observe adapter/state/diagnostic availability]
        -> [buildConsoleRuntime]
        -> [bootstrap shell: presentable / restricted / minimal / closed]
```

关键说明：

- loader 必须把 JSON module fields 显式映射为 03 的 typed fields；特别是将 `bindingRef` 字符串经 `NonEmptyOpaqueValue` 和 local-ref factory 构造为 `LocalReference<'diagnostic'>`。
- whole-document validation 完成前不得构造或暴露 partial runtime。
- `buildConsoleRuntime` 不能因为 package、method、route、fake、binding 或 flag 存在就把 slot 标为 `bound`。
- 配置 validation 成功只证明本地输入合法，不证明 owner service 可达、数据 fresh、capability active、audit 完整或系统 ready。

| 配置项 / 组 | 加载时机 | parse / type validate | cross-field validate | assemble target | 生效方式 | 失败策略 |
|---|---|---|---|---|---|---|
| `runtime.profile` | bootstrap 前 | strict enum string | required；与每个 binding.profile 一致 | `ConsoleClientBindingConfig.profile` | `startup` | fail-fast |
| `bindings.adapterBindings` | bootstrap 前 | array/object；closed slot/profile/ref；字符串→validated local ref | unique `(profile,slot)`；owner-required facet 由 registry 合同判定；禁止 URL/secret/body | `adapterBindings` | `startup` | reject whole document |
| `invalidation.enableSdkInvalidation` | bootstrap 前 | boolean | true 需正式 envelope/id/order/dedup + exact slot；当前不满足 | `enableSdkInvalidation` | `startup` | reject true / false disabled |
| `diagnostics.enableDiagnostics` | bootstrap 前 | boolean | true 需 profile 允许的 sink binding；production 合同当前缺失 | `enableDiagnostics` | `startup` | reject unsupported true / false disabled |
| whole document | bootstrap 前 | strict JSON；duplicate/unknown/alias/extra reject | 上述全部 + forbidden boundary | `buildConsoleRuntime` input | `startup` | 不构造 partial runtime |

| 生效方式 | 适用项 | 触发 | 回退 | 结论 |
|---|---|---|---|---|
| `startup` | 四项全部 | 新 runtime bootstrap | 修正文档或用经重新验证的 approved document 重建 | P0 唯一方式 |
| `reload` | 无 | 不适用 | 不提供 | future design-change-required |
| `hot` | 无 | 不适用 | 不提供 | P0 禁止 |
| `build-time` | 无 | 不适用 | 不提供 | bundler/framework 未锁定 |
| `static` | forbidden boundaries | 正式设计版本变化 | 走设计评审 | 不是普通配置 |

| validation issue class | 允许输出 | 禁止输出 | 运行影响 |
|---|---|---|---|
| parse/duplicate/unknown | safe module/key class、issue kind、local diagnostic ref | raw document/value/path | fail-fast |
| missing/invalid profile | key class、allowed enum class | raw file/body | fail-fast |
| invalid binding | module、slot class、issue kind | bindingRef raw value、URL、owner body | reject document |
| cross-field mismatch | field/profile/slot class | full values/secret | reject document |
| forbidden material | forbidden class | detected raw material | security reject |
| builder dependency unavailable | facet + safe posture | SDK exception/body/credential | restricted/minimal 或 fail-fast，遵守 03 entry 契约 |

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“变更 actor 与评审层级”“配置变更表”“审计记录安全规则”“回滚规则矩阵”和“跨变更审计”。

Console runtime 不提供 admin toggle、leaf patch、hot reload 或在线 LKG。配置变更由外部 configuration/release 边界发起和审计：生成完整新文档，评审并验证，随后构造新 runtime。Console 不拥有正式配置审计 truth。

| 变更类型 | 发起方 | 评审要求 | 生效方式 | 审计记录 | 回滚方式 |
|---|---|---|---|---|---|
| profile | 外部 configuration/release 维护者 | enum、环境映射、fake isolation、依赖完整性 | 新 runtime startup | old/new redacted digest、profile class、review refs、validation outcome | previous approved whole document + revalidation + restart |
| binding array | 外部 configuration/release 维护者 | slot/profile/ref、唯一性、contract/registry 和安全评审 | 新 registry/runtime startup | changed slot classes、redacted digest、contract review ref | previous approved whole document + revalidation |
| invalidation flag | 外部 configuration/release 维护者 | false→true 需 SDK event contract；当前不可批准 | 新 runtime startup | flag class、review refs、validation result | restore false document + restart |
| diagnostics flag | 外部 configuration/release 维护者 | false→true 需 privacy/redaction/sink contract；production 当前不可批准 | 新 runtime startup | flag class、privacy/contract review refs | restore false document + restart |
| rollback | 外部 configuration/release 维护者 | 目标 artifact 仍批准且适配当前 schema/authority | 新 runtime startup | from/to refs、reason、validation outcome | 若目标也失败，保持新 bootstrap blocked；不连续猜版本 |

外部审计只允许 artifact/version ref、redacted canonical digest、safe module/key class、actor/reviewer/reason ref、validation outcome、activation posture class 和 rollback ref。禁止存储 raw JSON/value、bindingRef opaque value、endpoint/URL、secret、owner body、SDK exception/stack 或用户输入。本文未生成任何 audit record、artifact 或 digest，也不规定具体算法或工单系统。

| 失败阶段 | 当前 runtime | 新 runtime | 回滚规则 |
|---|---|---|---|
| source/parse/type/cross-field 失败 | 已运行实例继续使用其冻结配置，直至由 host 管理生命周期 | 不构造 | 修正文档或选择 previous approved document，重新校验再 bootstrap |
| builder/mandatory dependency 失败 | 不被新发布隐式修改 | 不暴露 protected runtime | 回滚完整 document；不得只删失败 slot 绕过评审 |
| optional runtime dependency 后续不可用 | 按 03 partial/disabled/failed 姿态 | 不适用 | 不是 config rollback；走 formal recovery/host 处置，不能换配置提升状态 |
| 新配置效果异常但 shape 合法 | 由 host/release 控制实例生命周期 | 可停止或替换 | 经评审回滚整文档并新 bootstrap；不以 UI 状态作为唯一判据 |
| previous artifact 已不兼容 | 保持安全停止或当前冻结实例 | 不构造 | 不强行回滚；产生新批准修复文档 |

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_degradation.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“策略术语”“失效模式表”“按域失败策略”“告警 / 安全记录规则”“测试切口”和“跨失效审计”。

本文区分四种姿态：无效配置文档使新 runtime `fail-fast`；formal facet 不足使相应交互 `fail-closed`；optional path 未配置或不可用为 `disabled/failed`；已安全构造但依赖部分不可用时保持 `restricted/minimal/partial`。这些姿态不能互相替代，也不能映射为 owner 不存在、权限拒绝或产品 readiness。

| 失效模式 | 影响 | 系统行为 | 是否记录 / 告警 | 测试切口 |
|---|---|---|---|---|
| external document 缺失/不可读 | 无 required profile | 新 runtime fail-fast；无 partial runtime | 外部 config/release error，safe source ref only | missing/unreadable source |
| malformed JSON / duplicate key | shape 不可判定 | reject whole document | safe parse issue；no raw body | malformed/duplicate/comment/trailing negative |
| unknown section/field/alias | schema 漂移或历史污染 | reject whole document | safe module/key class | unknown/legacy key |
| profile 缺失/unknown | runtime posture 不明 | fail-fast；不 default fake | profile issue class | required/enum |
| binding shape、duplicate 或 profile mismatch | registry 不可信 | reject whole document | safe slot/profile class | type/unique/cross-field |
| bindingRef 空、URL、secret 或 body | 安全边界破坏 | security reject；不回显 | forbidden class only | opaque ref/forbidden-body |
| invalidation=true 且合同/slot 缺失 | consumer 不安全 | reject new runtime；false 才可启动 | pending-contract class | prerequisite matrix |
| diagnostics=true 且 sink/profile 不允许 | 泄露或结果耦合风险 | reject；false → disabled | safe sink posture | fake-only/production reject |
| mandatory host/dependency 缺失 | shell/guard 无法装配 | builder fail-closed；按 03 restricted/minimal 或 fail-fast | safe facet/posture | dependency partial availability |
| owner adapter runtime unavailable | 对应 partition 不可读/写 | per-owner unavailable/partial/blocked；无关区域继续 | body-free diagnostic 可选 | partition isolation |
| diagnostic sink runtime 失败 | 辅助诊断丢失 | `failed/disabled`；业务结果不变；不递归 | safe error kind only | failure/cancel/no recursion |
| invalidation hint runtime unavailable | 无异步提示 | disabled/unavailable；显式 Query/revalidation 仍为主链 | safe posture | hint absent/unavailable |
| state carrier unavailable | 交互连续性受损 | reload/clear/minimal；不恢复 formal positive，不重发 command | safe carrier posture | unavailable/ambiguous |
| artifact drift / digest mismatch | 发布输入不可复核 | 外部 release gate 阻断新 bootstrap；不自动切换 | external safe digest refs | drift/rollback |
| remote/admin/hot key 出现 | unsupported 控制面 | reject | design violation class | unsupported source/control |

高风险错误禁止 silent fallback。P0 不支持在线 last-known-good；外部 owner 可以选择 previous approved artifact，但必须用当前 schema 和 authority 重新校验并创建新 runtime。

### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 console“能打开多个面板”,而是系统验证 `L5-console` 是否真正满足“平台控制台 / 工作台产品层”的设计要求,尤其要证明以下几点成立:
- ConsoleWorkspace / PanelState / CrossPanelContext / ConsoleActionEntry / PermissionHint 构成正式工作台层真相
- `ConsoleWorkspace ≠ domain source truth`、`PanelState ≠ business state`、`Console action entry ≠ execution truth` 等核心边界成立
- workspace entry / global nav / section switch / panel orchestration 能统一组织多个产品面
- unified summaries / dashboard / previews 始终只消费 source 视图,且 `Unified dashboard ≠ unified source model`
- quick actions / command palette / handoff 只提供动作入口,不会误导用户认为 source action 已完成
- permission / stale / saved layout / workspace preference 始终保持解释层和个性化层语义,且 `permission hint ≠ authorization truth`、`workspace preference ≠ domain state`
- 多 panel 协同时 source refs 持续可追溯,不会把共享上下文误写成共享业务状态

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 工作台入口与全局导航部分 | workspace entry 对象 | P0 | ConsoleWorkspace、GlobalNavState、SectionSwitch、WorkspaceEntry、PinnedEntry |
| 多面板组织与上下文联动部分 | panel orchestration 对象 | P0 | PanelState、CrossPanelContext、SplitViewLayout、DrilldownTarget、SharedShellState |
| 操作入口与工作流辅助部分 | action entry 对象 | P0 | ConsoleActionEntry、CommandPaletteItem、QuickActionEntry、BulkActionEntry、HandoffRequest |
| 统一视图消费与摘要呈现部分 | unified summary 对象 | P0 | UnifiedSummaryCard、DashboardSlice、DetailPreviewCard、HealthSnapshotBlock、CapabilitySnapshotBlock |
| 状态提示、权限反馈与个性化工作台部分 | assist/personalization 对象 | P0 | PermissionHint、StaleWarning、SavedLayout、WorkspacePreference、StatusAssistBanner |
| chat / runtime / artifact / observability / archive / capability-hub 真相本体 | 非范围 | P2 | 只验 console 如何组织其只读消费面与操作入口,不验 source truth 全部实现 |
| 共享 UI 组件库、底层渲染引擎和 analytics 本体 | 非范围 | P2 | 只验工作台交互语义,不验组件库或分析平台底层实现 |
| source action 真正执行成功 | 非范围 | P2 | 只验 action entry 与提示链,不验 source system 动作全链条 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / product owner | `input.validate_workspace_entry_boundary`、`context.validate_cross_panel_boundary`、`entry.validate_action_entry_boundary`、`input.validate_summary_source_boundary`、`input.validate_assist_source_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + projection + shell adapter + publisher 联动 | backend / product owner | `OpenWorkspace`、`SyncCrossPanelContext`、`TriggerQuickAction`、`BuildUnifiedSummary`、`BuildPermissionHint`、`SaveWorkspaceLayout` | workspace、panel、action、summary、assist 五条主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | chat/runtime/artifact/obs/archive → console panels、action entry → source dispatch、summary → users/operators | 输入输出语义一致 |
| 恢复专项测试 | 验证 stale、source ref 失效、action backlog、layout 非法、permission 冲突等异常链 | architecture / QA | missing refs、context drift、action pending、summary stale、layout conflict | 工作台不误导、错误被正确阻断或标记 |
| 投影一致性测试 | 验证 workspace/panel/summary/hint 视图与 source refs 一致 | backend / QA | workspace summary rebuild、panel projection rebuild、dashboard slice rebuild、stale hint rebuild | 投影只读且与 source refs 一致 |
| 端到端主线测试 | 验证最小统一工作台闭环 | QA / owner | open workspace → open/sync panels → trigger action → update summary/hints | console 工作台闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `ConsoleWorkspace ≠ domain source truth` | workspace 只能组织 source refs,不反写源仓真相 | 单元 + 集成测试 | 是 | workspace/source compare |
| `PanelState ≠ business state` | panel state 只表达 UX 状态,不替代业务状态 | 单元 + 集成测试 | 是 | panel state / source diff |
| `Console action entry ≠ execution truth` | 动作入口触发不等于 source action 已成功完成 | 单元 + 事件链测试 | 是 | action history / source dispatch compare |
| `Unified dashboard ≠ unified source model` | unified summary 只能消费 source summaries,不反写源真相 | 单元 + 投影一致性测试 | 是 | dashboard/source compare |
| `permission hint ≠ authorization truth` | 权限提示只是解释层,不替代真实授权判断 | 单元 + 集成测试 | 是 | permission hint/source auth compare |
| `cross-panel context ≠ shared source state` | 多 panel 联动只共享 UX 上下文,不共享业务真相 | 单元 + 集成测试 | 是 | cross-panel/source compare |
| `workspace preference ≠ domain state` | 个性化布局和偏好不能污染领域状态 | 单元 + 恢复专项测试 | 是 | preference/state diff |
| summary / preview / hint 可回指 source refs | 所有摘要、预览、提示都能追溯 source refs | 集成 + 投影一致性测试 | 是 | refs compare |
| stale / permission / action 分层明确 | stale、无权限、已触发未成功等状态可被清晰区分 | 集成 + 恢复专项测试 | 是 | hint/action/status compare |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | OpenWorkspace 成功建立正式工作台上下文 | entry refs 合法 | OpenWorkspace | ConsoleWorkspace / GlobalNavState 创建成功 |
| TC-002 | workspace 不得反写 source truth | source refs 存在 | negative flow | 仅生成 workspace view,不改 source state |
| TC-003 | OpenPanel / SplitPanel 成功组织多面板 | workspace 已打开 | OpenPanel / SplitPanel | PanelState / SplitViewLayout 创建成功 |
| TC-004 | SyncCrossPanelContext 成功同步共享上下文 | 多个 panel 已打开 | SyncCrossPanelContext | CrossPanelContext 生效,相关 panel 更新 |
| TC-005 | cross-panel context 不得被当成共享业务真相 | shared context 存在 | negative flow | 无 source truth 被写回 |
| TC-006 | TriggerQuickAction 只记录动作入口并发起 source dispatch | action entry 合法 | TriggerQuickAction | action history 追加成功 |
| TC-007 | quick action 不得被展示为已成功执行 | source dispatch pending/fail | TriggerQuickAction + source response | UI 显示已触发/待确认而非成功 |
| TC-008 | BuildUnifiedSummary 成功聚合多域摘要视图 | source summaries 齐全 | BuildUnifiedSummary | UnifiedSummaryCard / DashboardSlice 创建成功 |

| TC-010 | BuildPermissionHint 成功生成权限与 stale 提示 | source auth/status 输入齐全 | BuildPermissionHint | PermissionHint / StaleWarning 创建成功 |
| TC-011 | permission hint 不得替代 authorization truth | auth source 存在 | negative flow | 仅解释提示,不改授权真相 |
| TC-012 | SaveWorkspaceLayout / UpdateWorkspacePreference 成功保存个性化工作台 | workspace 已打开 + layout 合法 | SaveWorkspaceLayout / UpdateWorkspacePreference | SavedLayout / WorkspacePreference 创建成功 |
| TC-013 | saved layout 非法时阻断恢复或保存 | layout 结构非法 | SaveWorkspaceLayout / RestoreWorkspace | 返回 `SAVED_LAYOUT_INVALID` |
| TC-014 | source stale 时正确显示 stale/warning 而不是伪造最新摘要 | source summary 延迟或失联 | BuildUnifiedSummary / BuildPermissionHint | stale 标记正确呈现 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 workspace / global nav,都必须回归工作台入口和 entry refs 主线
- 每次改动 panels / split / context sync,都必须回归跨面板联动与 context 主线
- 每次改动 quick actions / command palette / handoff,都必须回归 action entry 与 source dispatch 分层主线
- 每次改动 dashboard / summary / preview,都必须回归 unified view 与 source refs 主线
- 每次改动 permission/stale/layout/preferences,都必须回归解释层和个性化层边界主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 多租户 / 多工作区协同后续细化 | 验收矩阵需扩充 | TL / 架构 |
| archive/history/capability 面继续长胖 | summary / panel/context 验收需增加更多样本 | console / archive / hub |
| analytics / personalization 需求增长 | usage/prefs 验收需扩充 | product / analytics |

#### 测试分层图：Console 风险发现栈

```text
[Release gate / evidence assembly]
              ^
[Architecture / static checks]
              ^
[Semantic accessibility]
              ^
[Controlled composition]
              ^
[Port / adapter contract]
              ^
[Module / flow]
              ^
[Unit / pure contract]
```

关键说明：

- 箭头表示证明累积，上层不得替代下层断言。
- 权限收紧、Query no-write、unknown no-replay、forbidden body 和局部隔离必须在 release gate 前失败。
- DB/repository/UoW/outbox/worker/job 不是待补 integration layer，而是本仓架构静态否决项。
- release gate 只汇总未来测试证据，不签发 owner truth、验收 verdict 或 readiness。

| 层级 | 主要职责 | 执行时机（future） | 失败姿态 |
|---|---|---|---|
| pure-contract | factory/guard/ref/state/config/redaction | local/PR | P0 blocking |
| module-flow | 5 Command、16 Query、disabled consumer、no-write/single-flight/late drop | PR/main | P0 blocking |
| port-adapter | callable surface、safe mapping、error/cancel/unknown、fake parity | main | P0 safety blocking；exact positive blocked |
| controlled-composition | profile/runtime builder、owner fan-out、partial/failure injection | main/nightly | P0 safety blocking |
| semantic-a11y | same action/guard/outcome、focus/announce/recovery | main；selected compatibility later | semantic P0 blocking；matrix conditional |
| architecture-static | SDK-only、forbidden units/imports、surface/write count | PR/main/release | VETO blocking |
| release-evidence-assembly | minimal closure、profile/redaction/dependency/report integrity | release candidate | 缺失/失败阻断送验；不自行裁决 |

## 11. 缺陷管理与复验规则

本章定义未来测试发现的问题如何分级、阻断、复验和关闭。S/A/B/R 是测试管理分类，不是 owner 业务状态；缺陷记录、执行 run、artifact、report 与关闭结果当前均不存在。

### 11.1 缺陷分级

| 级别 | 定义 | Console 示例 | 处理 | 阻断 |
|---|---|---|---|---|
| S | VETO/P0 safety、truth boundary、redaction、dependency、config fail-closed 或 evidence integrity 被破坏 | Query 写入；route 产生资格；raw body 泄露；unknown replay；静态表宣告 EV；pending profile 装配未批准 fake | 必须修复并复验；不可风险接受 | 是 |

| Query、diagnostic 或 optional consumer side path 改写 owner/local truth | S；16 Query zero-write 与 side-path isolation 必须复验 |
| partial/empty/failed partition 被合成 normal、verdict 或 readiness | S；逐 owner posture 与 failure isolation 必须复验 |

| artifact/report 缺失或 run mismatch、静态 evidence/VETO pass、伪 signoff | S；source suite、pairing 和 no-static-evidence 必须复验 |

### 13.5 失败归档、审查与真实性

失败 suite 必须保留 `report.json`、已执行 case JSON、redacted stdout/stderr（如产生）、safe failure reason、gate status、artifact/report digests 与 defect ref。重跑必须使用新 run_id，禁止删除失败 run 或以“最后一次成功”隐藏历史。

| 审查对象 | 自动步骤 | 人 / Agent 必审 | 禁止 |
|---|---|---|---|
| suite report | raw case 汇总 | 失败解释、遗漏 case、blocker posture | 手改为 pass |
| evidence index | pairing/redaction/static checks | TC/AC/VETO 追溯与争议 | 无 raw source 补录 EV |
| acceptance draft | fixed-run report 抽取 | 风险接受角色、开放项、送验范围 | 自动 signoff/readiness |
| review notes | 无 | 完整性审查与分歧 | 替代新版 06 裁决 |

未来 evidence 资格要求：每个 EV 有同 run 的 suite artifact/report 与 digests；failed/blocked/unavailable 姿态保真；redaction、pairing 与 no-static-evidence checks 通过；无 owner body、DB snapshot、完整 trace、credential 或 diagnostic receipt 充当证明。Console 只归档 body-free refs、枚举、计数、digest、执行关系与 safe failure reason。

## 14. 回归策略与残余风险

> 校准来源：
> - `design-calibration/05_test_plan_step_14_regression_risks.md`
>
> 延伸阅读：
> - 建议继续阅读上述中间产物的“变更类型 → 最小回归集”“全量 P0 回归触发与集合”“S 级修复与特殊变更回归”“残余风险表”“不可风险接受项”和“必须转入新版 06 的事项”。

本章定义未来变更如何触发最小或全量 P0 回归，并记录不能形成 positive verdict 的风险。它不执行回归、不填写缺陷状态、不接受风险，也不替代新版 06 的裁决。

### 14.1 变更到最小回归

| 变更类型 | 最小 TC / suite / check | 全量 P0 触发 |
|---|---|---|
| requirements / AC / VETO | affected family + release safety + traceability review | 任一 C/FR/BR/DR/IF/DEP/NFR/AC/VETO 语义变化 |
| entry/access/navigation | CTX/NAV/SEC + pure/module/a11y | context/visibility/qualification/disclosure 上限变化 |
| views / 16 Query | VIEW/ADAPTER + module/port/redaction | surface、safe fields、axes、zero-write 变化 |
| intent / 5 Command | INTENT/CONSISTENCY + module/port/concurrency | submit/result/reconcile/unknown/no-replay 变化 |
| eight topic composition | TOPIC/SEC/RECOVERY + composition/recovery | owner set/order/activation/strict-empty/isolation 变化 |
| recovery/error/a11y | RECOVERY/A11Y + recovery/a11y/redaction | error union、recovery ceiling、core action 变化 |
| Port/adapter/SDK binding | ADAPTER + affected protocol + port/architecture | public contract、mapping、private boundary 变化 |
| invalidation | ADAPTER-005/006 + CONSISTENCY-008 | envelope/order/dedup/apply 首次启用或变化 |
| carrier/state | STATE/CONSISTENCY + pure/concurrency/composition | medium/scope/TTL/migration/whole-record 变化 |
| diagnostics/redaction | DIAG/SEC + redaction/report audit | whitelist/sink/corpus/scan scope 变化 |
| config/profile | CONFIG + ADAPTER-004/005 + config/architecture | key/default/profile/source/lifecycle/failure 变化 |
| module/protocol/dependency | ARCH + architecture/release-dependency | 10 modules、5+16+1、0 Event/Job、owner write 变化 |
| suite/gate/evidence tooling | changed suite + pairing/no-static check | blocking topology、schema、digest 或 EV derivation 变化 |
| S 修复 | original TC + same family + affected suite/check | 一律全量 P0 |

### 14.2 全量 P0 集合与特殊回归

全量 P0 至少包含：`console-pure-contract`、`console-module-flow`、`console-config-redline`、`console-architecture-static`、`console-port-adapter`、`console-controlled-composition`、`console-semantic-a11y`、`console-redaction-boundary`、`console-concurrency-race`、`console-recovery-matrix`、`console-report-pairing-audit`，五个 release safety/config/redaction/dependency/report suites/checks，以及 §13 的 report generation、pairing、redaction、no-static-evidence 和 review-ready acceptance draft。

七项 VETO、truth/Policy/Gate boundary、protocol/write inventory、formal/local phase、unknown/no-replay、state scope/positive recovery、四项配置/三 profile、redaction/dependency/evidence schema、release blocking topology 或任一 S 修复变化时必须运行该集合。配置、redaction、dependency 或 evidence 变化不得只运行生成脚本而跳过来源 suite。Blocked positive 与 selected suite 不因“全量”二字自动解锁。

### 14.3 残余风险

| 风险 / blocker | 影响 | 当前缓解与解锁触发 | 确认角色 |
|---|---|---|---|
| `CON-Q-034` exact owner/SDK surfaces | positive adapter、submit、active posture不能证明 | safety/no-call P0；合同到达重开 03/05，跑 selected/full | owner + SDK + 验收 |
| `CON-Q-035～037` scope/visibility/qualification/safe fields | positive disclosure/action/view 不完整 | fail-closed/minimum disclosure；authority 到达跑 contract/security | identity/Policy/Gate/owners |

| `CON-Q-039～043` owner-specific seams | 八主题 positive/material/action 不完整 | per-owner pending/read-only/partial；逐 owner 到达跑 selected | corresponding owners + 验收 |

### 14.4 不可接受项与 06 承接

以下项目不得转为 residual：任何 VETO/S、private boundary/第二 truth/Query write、access bypass、伪完成或 unknown replay、forbidden material 泄露、UI/flag/threshold/partial result 推导 verdict/readiness、核心 a11y 不等价、partition failure 扩散或掩盖、config silent fallback/partial runtime，以及 static evidence、run mismatch、缺 artifact/report pair 或伪 signoff。它们必须修复并执行全量 P0。

新版 `06-验收标准.md` 必须收口：AC/VETO 所需 EV family 与充分性、blocked positive 的裁决上限、selected owner/browser/AT 是否为 release 必需、量化硬阈值、风险接受角色与条件、证据保留与 signoff 边界、`production-pending` 不等 readiness，以及实现仓/runner 不可用时只能 blocked/not-run。05 不提前回答这些裁决问题。

### 14.5 回归归档

| 回归类型 | Future 归档要求 |
|---|---|
| 最小回归 | 新 run_id、regression scope、source refs、suite artifacts/reports、evidence index |
| 全量 P0 | 完整 run report、全部 blocking suites/checks、acceptance draft、review-ready risk list |
| S/A 复验 | failed run + fixed run + original TC + same family/suite/check + 防回归决定 |
| selected/conditional | authority ref、selected environment；blocked/unavailable 不贡献 positive EV |
| residual review | `reports/acceptance/risk-acceptance.md` + `reports/review/*`；不替代 06 |

每次 future 回归使用新 run_id，不覆盖旧 run，不引用 `latest`；没有真实 artifact/report pair 就没有 evidence instance。

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L5-console` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L5-console` 是平台控制台 / 工作台产品层,不是 source truth 仓或单一页面仓
- ConsoleWorkspace / PanelState / CrossPanelContext / ConsoleActionEntry / PermissionHint 构成正式工作台层真相
- `ConsoleWorkspace ≠ domain source truth`、`PanelState ≠ business state`、`Console action entry ≠ execution truth` 等核心边界必须成立
- workspace entry / global nav / section switch / panel orchestration 必须统一组织多个产品面
- unified summaries / dashboard / previews 始终只能消费 source 视图,且 `Unified dashboard ≠ unified source model`
- quick actions / command palette / handoff 只提供动作入口,不得误导用户认为 source action 已完成
- permission / stale / saved layout / workspace preference 必须始终保持解释层和个性化层语义,且 `permission hint ≠ authorization truth`、`workspace preference ≠ domain state`
- 多 panel 协同时 source refs 必须持续可追溯,不得把共享上下文误写成共享业务状态

因此,本次验收的目的不是笼统判断“能不能做个控制台页面”,而是判断 console 的 workspace 入口主线、多面板联动主线、action entry 主线、unified summary 主线与 assist/personalization 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 工作台入口与全局导航部分 | 是 | ConsoleWorkspace、GlobalNavState、SectionSwitch、WorkspaceEntry、PinnedEntry |
| 多面板组织与上下文联动部分 | 是 | PanelState、CrossPanelContext、SplitViewLayout、DrilldownTarget、SharedShellState |
| 操作入口与工作流辅助部分 | 是 | ConsoleActionEntry、CommandPaletteItem、QuickActionEntry、BulkActionEntry、HandoffRequest |
| 统一视图消费与摘要呈现部分 | 是 | UnifiedSummaryCard、DashboardSlice、DetailPreviewCard、HealthSnapshotBlock、CapabilitySnapshotBlock |
| 状态提示、权限反馈与个性化工作台部分 | 是 | PermissionHint、StaleWarning、SavedLayout、WorkspacePreference、StatusAssistBanner |
| chat / runtime / artifact / observability / archive / capability-hub 真相本体 | 否 | 只验 console 如何组织其只读消费面与操作入口,不验 source truth 全部实现 |
| 共享 UI 组件库、底层渲染引擎和 analytics 本体 | 否 | 只验工作台交互语义,不验组件库或分析平台底层实现 |
| source action 真正执行成功 | 否 | 只验 action entry 与提示链,不验 source system 动作全链条 |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | workspace/panel 反写真相 / quick action 被误展示为成功 / unified summary 冒充 source truth / permission hint 冒充授权真相 |
| A | 视情况 | 主线可跑但 context drift、stale 提示、layout restore、summary 对账不稳 |
| B | 可带着走 | 非关键视图、低优先级布局或摘要展示异常 |

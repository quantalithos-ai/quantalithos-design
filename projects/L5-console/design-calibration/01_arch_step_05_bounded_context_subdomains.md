## 3. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 本仓内部有哪些子域或本地上下文？ | 可信管理交互编排、访问语境与导航、来源保真视图、受控意图与结果、管理主题组织、韧性与可访问交互，以及正式语境/资格引用、owner-safe 视图影子、正式请求/结果引用。 |

| 哪些是支撑子域？ | 访问语境与导航、来源保真视图、受控意图与结果、管理主题组织、韧性与可访问交互均为支撑子域；它们分别承接 Console 自有交互语义。 |
| 哪些只是本地索引/投影/引用？ | 正式 actor/scope/visibility/资格摘要与引用、owner-safe 查询快照/对象引用、receipt/result/reconciliation/audit/evidence 安全引用均是本地影子；本轮不建立事件驱动业务 projection/cursor/replay。 |
| 它们之间的上下文映射关系是什么？ | 核心编排以访问语境为前提，组合来源保真视图、受控意图/结果、主题组织和韧性；三类本地影子只服务对应支撑上下文并随正式语境/owner 状态失效。 |

## 5. 改动前后对比与设计取舍

### 5.1 改动前后对比

| 维度 | 历史口径 | 本步口径 | 原因 |
|---|---|---|---|
| 核心子域 | 外部治理/组织/审计主题 | 可信管理交互编排 | Console 的不可替代性是安全的人类交互闭环，不是外部 truth。 |
| 支撑结构 | 页面族或技术模块 | 访问、视图、意图/结果、主题组织、韧性 | 可从 C1~C6 推导且不锁实现。 |
| 本地影子 | 通用聚合投影、权限缓存 | 正式语境/资格引用、owner-safe 快照/ref、结果引用 | 保持可失效、最小化、无正文。 |
| 页面主题 | 各自成为领域上下文 | 统一为 owner-partitioned 管理主题组织 | 防止复制十多个 owner 的领域模型。 |
| 权限 | Permissions 上下文 | 访问语境支撑 + 外部决定引用影子 | Console 不拥有授权 truth。 |

### 5.2 设计取舍

| 方案 | 优点 | 代价 / 风险 | 结论 |
|---|---|---|---|
| A. 按每个外部 owner 建一个 Console 子域 | 页面映射直接。 | 会复制领域语言、规则和状态，并误导为本地 truth。 | 不采用。 |
| B. 按 C1~C6 每个能力都设为核心子域 | 与需求编号对齐。 | 核心过多，且能力闭环不等于领域真相。 | 不采用。 |
| C. 单一核心交互编排 + 五个支撑语义 + 三类本地影子 | 保护 Console 的产品独特性和外部 owner 边界。 | 主题页面的细粒度要在 02/03 再展开。 | 采用。 |
| D. 把所有客户端状态都归本地投影 | 分类简单。 | 会把 Console 自有草稿/导航 truth 与外部快照混为一类。 | 不采用。 |
| E. 建事件驱动跨域投影上下文 | 可离线组合多域结果。 | 引入 cursor/replay/rebuild 和第二 truth，违反仓边界。 | 不采用。 |

## 6. 结构化中间产物

### 6.1 子域 / 上下文划分表

| 名称 | 类型 | 作用 | 与其他部分的关系 |
|---|---|---|---|
| 可信管理交互编排 | 核心子域 | 承载从可信语境到安全读取、受控意图、正式结果和恢复的整体产品语义。 | 组合全部支撑子域，但不吸收任何 owner truth。 |
| 访问语境与导航 | 支撑子域 | 承载客户端会话连续性、入口组织和正式访问姿态的呈现语义。 | 为其余支撑子域提供当前交互语境，消费正式语境/资格引用。 |
| 来源保真视图 | 支撑子域 | 承载 owner-safe 结果的来源、多轴状态、探索和安全回链语义。 | 依附访问语境，消费 owner-safe 视图影子，不反写 owner。 |
| 受控意图与结果 | 支撑子域 | 承载草稿、复核、提交经历、正式结果呈现和 unknown 挂起语义。 | 依附访问语境并引用 owner receipt/result，不拥有副作用。 |
| 管理主题组织 | 支撑子域 | 承载八类管理主题的信息组织、能力裁剪和跨主题导航语义。 | 组合来源保真视图与受控意图，不把主题合成跨域 truth。 |
| 韧性与可访问交互 | 支撑子域 | 承载局部降级、恢复、焦点、播报和等价操作路径语义。 | 横切其他支撑子域，但不改变其 owner 状态或资格上限。 |
| 正式语境与资格引用 | 本地索引 / 投影 / 引用 | 为客户端呈现当前 actor/scope/visibility/资格提供可失效安全影子。 | 只服务访问语境与导航，不形成认证或授权缓存 truth。 |
| owner-safe 视图影子 | 本地索引 / 投影 / 引用 | 为当前页面呈现来源、状态、摘要和安全引用提供临时影子。 | 服务来源保真视图和主题组织，随 owner/语境/可见性失效。 |
| 正式请求与结果引用 | 本地索引 / 投影 / 引用 | 为提交经历、receipt/result/reconciliation 和追溯回链提供安全影子。 | 服务受控意图与结果；不包含业务对象、审批、audit/evidence 正文。 |

### 6.3 统一语言词汇表

| 词汇 | 所属上下文 | 本步含义 | 禁止混用 |
|---|---|---|---|
| 可信管理交互 | 可信管理交互编排 | 在正式语境、来源和结果上限内可理解、可恢复的客户端闭环 | owner 业务事务或治理裁决 |
| 客户端会话壳 | 访问语境与导航 | 维持页面连续性和当前交互选择的 Console 状态 | credential、认证 session 或授权 truth |
| 入口姿态 | 访问语境与导航 | 对 visible/restricted/disabled/unknown 的安全呈现 | allow/deny 决定本体 |
| 来源保真 | 来源保真视图 | 保留 owner/source、freshness、coverage、availability、consistency | 客户端合成的完整/当前/一致结论 |
| 正式空 | 来源保真视图 | owner 可见范围内明确返回无结果 | missing、not-visible、partial、unavailable |
| 草稿 | 受控意图与结果 | 尚未提交的用户意图和本地复核状态 | 正式对象、命令受理或批准 |
| 请求经历 | 受控意图与结果 | Console 可负责的提交、等待和需回查交互事实 | owner committed result |
| 正式结果 | 受控意图与结果 | owner 明确确认或拒绝的业务结果 | HTTP 成功、toast、刷新、缓存状态 |
| 管理主题 | 管理主题组织 | 按 owner 划分的管理消费入口 | Console 自有领域或跨域 truth |
| 局部降级 | 韧性与可访问交互 | 只影响可证明依赖某 owner/能力的区域 | 全局失败或统一健康结论 |
| 安全恢复 | 韧性与可访问交互 | 重验、重试、回查、退出或草稿保持等不放宽边界的路径 | 自动重放 unknown 副作用 |
| 安全影子 | 本地索引 / 投影 / 引用 | 可失效、可撤除、仅供当前交互呈现的 snapshot/ref | source truth、离线替身或授权缓存 |

### 6.5 跨上下文语义边界审计

| 审计项 | 结果 | 说明 |
|---|---|---|
| 核心子域是否唯一 | pass | 只有可信管理交互编排为核心；外部 owner 主题未被升格。 |
| 支撑子域职责是否重叠 | pass | 访问、视图、意图/结果、主题组织、韧性分别有唯一主语。 |
| 页面/owner 是否被误作子域 | pass | 八类管理主题统一为组织语义，truth 仍在外部。 |
| 客户端 truth 与外部快照是否混层 | pass | 草稿/导航/恢复是支撑语义；外部数据只进入三类影子。 |
| visibility 是否变成本地授权 | pass | 正式语境与资格单元只是可失效引用。 |
| owner-safe 影子是否变成业务 projection | pass | 禁止 cursor/replay/rebuild，按 owner 失效且不存正文。 |
| receipt/result 引用是否变成业务结果 truth | pass | Console 只呈现正式结果引用，不能自行决定结果。 |
| 韧性是否覆盖正式状态 | pass | 恢复只能收紧或重新取得 owner 结果，不改变语义。 |
| 统一语言是否存在冲突 | pass | session/授权、view/truth、草稿/result、诊断/audit 均有禁止混用。 |
| pending 是否被润色为已支持 | pass | exact surface、生命周期、activation 和量化项继续 pending。 |

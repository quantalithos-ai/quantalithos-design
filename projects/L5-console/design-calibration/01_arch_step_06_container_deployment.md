## 3. SOP 问题回答

| 问题 | 回答 |
|---|---|
| 运行时有哪些正式容器或运行单元？ | 一个由浏览器/辅助技术入口环境承载的 Console 交互客户端，以及一个与其逻辑同边界的有界客户端状态承载。L0 SDK/正式 owner 与条件化诊断消费者是框外运行时对接边界。 |
| 同步入口在哪里？ | 所有用户导航、查询、筛选、草稿、提交和恢复意图从浏览器/辅助技术入口环境进入 Console 交互客户端；业务读取/意图再经 SDK/正式 owner 边界完成。 |
| 异步消费者或后台任务在哪里？ | 当前没有独立的 Console 异步消费者、后台 job 或业务 worker。owner 异步工作只以正式结果/ref 被读取；SDK 正式状态提示若存在，只作为交互客户端中的失效提示，不建立事件 cursor/replay/projection。 |
| 数据库、缓存、总线如何接入？ | 不接入业务数据库、owner repository 或私有总线。有界客户端状态承载保存 Console-owned 交互事实及可失效安全影子；其内存/会话/持久介质、TTL 和跨设备范围仍 pending，不能形成授权或业务 truth。 |
| 哪些运行单元必须分开部署，哪些可以同部署？ | 交互客户端与有界状态承载属于同一客户端产品边界，逻辑上分责但可同交付/同运行环境承载。SDK、owner 服务和诊断消费者必须保持外部边界；当前不要求也不允许凭空新增 Console BFF、数据库或 worker。 |
| 哪些通信关系是正式主路径？ | 入口环境进入交互客户端，客户端依赖本地状态承载保持交互连续性，并经 SDK/正式 owner 边界取得查询/资格/结果或提交受控意图。诊断是可选旁路，失败不能改变业务语义。 |

## 5. 改动前后对比与设计取舍

### 5.1 改动前后对比

| 维度 | 历史口径 | 本步口径 | 原因 |
|---|---|---|---|
| 中心承载 | SPA + 多个源码模块 | 浏览器侧 Console 交互客户端 | 容器图表达运行角色，不表达代码目录。 |
| 状态 | shared store/cache 未分 truth | 有界客户端状态承载，明确交互 truth 与可失效影子 | 防止缓存/偏好成为授权或业务 truth。 |
| 服务端 | 可暗示聚合/BFF | 当前无 Console 自有服务端 | 所有业务读取经 SDK/owner，不新增第二真相层。 |
| 异步 | 内部事件或后台刷新候选 | 无独立消费者/worker；仅可选失效提示 | Console 不拥有 projection/cursor/replay。 |
| 报告/导出 | 本地 helper 生成 | owner 正式能力生成，Console 只呈现请求和 ref | 守住 evidence/report/archive 正文边界。 |

### 5.2 设计取舍

| 方案 | 优点 | 代价 / 风险 | 结论 |
|---|---|---|---|
| A. 单一浏览器侧交互运行单元 + 有界客户端状态承载 | 与产品形态和 truth 边界一致，故障可按 owner 分区。 | 不能靠服务端私有聚合隐藏 owner 差异。 | 采用。 |
| B. 新增 Console BFF / 聚合数据库 | 可集中 fan-out 和转换。 | 无正式需求来源，会复制权限/规则/正文并形成第二 truth。 | 不采用。 |
| C. 每个管理主题独立微前端/独立部署 | 可独立发布。 | 当前无规模或组织 authority，增加会话、资格和状态语义漂移风险。 | 不作为当前架构决定。 |
| D. 直接消费内部事件并维护本地投影 | 页面可能更及时。 | 引入 cursor、重放、重建和业务投影所有权。 | 不采用。 |
| E. 将所有本地状态只放内存且禁止持久 | 边界最小。 | 可能无法承接用户明确保存的偏好和草稿连续性。 | 不锁定；介质和生命周期留 `CON-Q-044`，安全上限已固定。 |

### 6.1 容器 / 部署架构图

#### 容器 / 部署架构图：L5-console

             | browser / assistive technology |
             | entry environment              |
             +---------------+----------------+

  +======================================================+

  |   +----------------------------------------------+   |
  |   | Console interactive client                   |   |
  |   | synchronous management experience            |   |
  |   +---------------------+------------------------+   |
  |                         | carry / depend              |

  |   | bounded client-state carrier                 |   |
  |   +----------------------------------------------+   |
  +=========================+============================+
                            | depend

             +--------------+--------------+
             | L0-sdk / formal owner       |
             | runtime access boundary     |
             +--------------+--------------+
                            |
                            | depend (optional)
                            v
             +--------------+--------------+
             | safe diagnostics consumer  |
             +-----------------------------+

图示说明：

- 该图表达运行承载目标，不声明已有进程、部署、实现仓、环境或集成事实。
- Console 当前只有一个同步交互运行单元；有界客户端状态承载是逻辑状态边界，不预设数据库、缓存产品或持久介质。
- `L0-sdk / formal owner` 是外部运行时访问边界，不能被 BFF、数据库直连或私有总线替代。
- 安全诊断消费者是条件化旁路；其失败不得改变权限、业务结果或恢复语义。

### 6.2 运行单元说明表

| 对象 | 类型 | 主要职责 | 运行关系 | 说明 |
|---|---|---|---|---|
| 浏览器 / 辅助技术入口环境 | 运行时对接的正式外部边界 | 承接用户输入并呈现可感知、可操作的 Console 体验 | 入口到交互客户端 | 不授予权限；精确兼容矩阵 pending。 |
| Console 交互客户端 | 同步入口单元 | 承载会话壳、导航、查询/意图呈现、结果解释、恢复和 a11y 交互 | 接收入口，依赖状态承载和正式访问边界 | 不等同特定 SPA 框架、进程或源码模块。 |
| 有界客户端状态承载 | 正式存储承载 | 承载 Console-owned 交互事实和可失效的 owner-safe 影子 | 被交互客户端承载/依赖 | 逻辑边界不表示永久存储；不得保存 forbidden body 或授权 truth。 |
| `L0-sdk` / 正式 owner 访问边界 | 运行时对接的正式外部边界 | 提供正式语境、资格、查询、意图受理、结果和安全引用能力 | 被交互客户端依赖 | exact surface/activation 分 owner pending；不得私有旁路。 |
| 安全诊断消费者 | 运行时对接的正式外部边界 | 条件化接收最小客户端交互诊断 | 被交互客户端可选依赖 | 不构成 audit/evidence；缺失或故障不改变业务行为。 |

### 6.3 不存在的运行单元与基础设施

| 候选对象 | 当前结论 | 边界理由 |
|---|---|---|
| Console 自有业务 API/BFF | `not_in_architecture` | 无正式需求/owner 依据；会形成聚合、规则或安全旁路。 |
| Console 业务数据库 | `not_in_architecture` | Console 不拥有外部 truth；本地状态介质不能升级为业务仓。 |
| 独立异步消费者 | `not_in_architecture` | 状态通知仅是 SDK 可选提示，不维护 cursor/replay/projection。 |
| 后台业务 worker/job | `not_in_architecture` | owner 异步任务归 owner，Console 只读正式状态/ref。 |
| 私有消息总线连接 | `forbidden` | 违反 SDK/正式服务边界并引入内部事件语义。 |
| 本地报告/evidence/archive 生成器 | `forbidden` | 正文与正式结果归 Observability/Artifact/Archive 等 owner。 |

### 6.4 部署与通信收束说明

Console 交互客户端与有界客户端状态承载属于同一产品运行边界，职责上分离但当前没有依据要求拆成独立部署。交付形态保持“浏览器可运行的管理客户端”，不在架构层锁定渲染方式、静态托管、进程、镜像或集群；这些只能在后续技术与实施文档基于 authority 决定。SDK/owner 与诊断消费者始终是外部边界，不能同部署假设为共享数据库或共享事务。当前正式主路径是入口环境到交互客户端，再经正式访问边界取得结果；本地状态只承载交互连续性。

### 6.5 Step 7 承接输入

| Step 7 需要收敛 | 本步提供的边界 |
|---|---|
| 内部责任层 | 交互入口、交互编排/呈现、有界客户端状态、外部访问适配与诊断边界需明确依赖方向；不是源码目录。 |
| 外部依赖 | L0-core/L0-sdk 与 L1~L4 owner 经正式边界；无 DB、私有 bus、BFF 或服务源码。 |
| 事件依赖 | 仅 SDK 正式封装提示可选，收到后重验；不构成直接事件依赖。 |
| 运行隔离 | owner 故障按区域隔离，诊断独立，语境不可验证 fail-closed。 |

## 7. 复杂度判断

当前运行承载只有一个核心同步单元、一个逻辑状态承载和三个外部边界，单图可清楚表达。无需为八个主题拆运行单元，也无依据新增微前端、BFF、worker、数据库或事件消费者。若未来组织规模、独立发布或性能 authority 要求拆分，必须在演进路线以触发条件重新审查，不能由本步伪造当前部署事实。

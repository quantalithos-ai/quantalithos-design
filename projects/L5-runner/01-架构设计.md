## 1. 业务背景与驱动力

### 1.1 业务背景

Runner 是 Quantalithos “把交付物真正交到用户手上”的最后一跳。AI 团队完成需求、设计、代码、测试和 Release 之后,用户仍然需要一个**不要求懂部署、不要求配环境、不要求会命令行**的入口把软件跑起来。Runner 因此不是简单的下载器,而是把 artifact 域中的 Release 包,通过 sandbox 域的受控执行能力,转成一个用户可以启动、停止、查看日志和重新运行的本地实例。

### 1.2 业务驱动力

**业务驱动力**:
- 非开发者管理者需要直接体验 AI 团队产出的软件,而不是面对压缩包和说明书
- 平台要证明自己交付的是“可运行的软件”,不是“需要开发者再接一道手工部署”的半成品
- 试用、演示、采购评估等场景都需要快速、低门槛、可重复的运行入口

**技术驱动力**:
- 需要与 artifact 的 Release/Baseline 语义、sandbox 的统一接口、SDK 的统一接入策略保持一致
- 需要在桌面端和 CLI 后备路径上提供同一套运行生命周期、日志模型和资源管理模型

### 1.3 成功标准(可量化)

| 维度 | 指标 | 目标值 | 测量 |
|---|---|---|---|
| 性能 | 冷启动 | < 30s | benchmark |
| 性能 | 热启动 | < 5s | benchmark |
| 容量 | 多项目并发 | ≥ 10 | 压测 |
| 安全 | 宿主逃逸次数 | 0 | 安全测试 |
| 可用性 | 启停成功率 | ≥ 99.9% 样本流 | E2E / 监控 |
| 一致性 | Runner 与 Sandbox 共用接口 | 100% | 集成测试 |

## 2. 约束条件

### 2.1 不可变约束

| 约束 | 来源 | 影响 |
|---|---|---|
| 只运行 approved / baselined Release | README + artifact 规则 | 运行前必须做 release gate 校验 |
| 所有运行必须走 SandboxService | sandbox 仓约束 | Runner 不得绕过沙箱 |
| 用户不可修改 Release 内容 | README | 本地缓存必须视为只读工件 |
| 版本选择必须显式,禁 `latest` | README | UI/CLI 必须展示明确版本 |
| Runner 与 Runtime 共用 Sandbox 接口 | sandbox 约束 | 本地运行生命周期要与 L4 接口对齐 |

### 2.2 可变约束

| 约束 | 当前值 | 可调整空间 |
|---|---|---|
| 桌面壳层 | Tauri 优先 | Electron 作为备选 |
| GUI/CLI 比重 | 桌面为主,CLI 兜底 | 后续可扩更多自动化场景 |
| 分享运行 | 首期不做公网暴露 | 后续可受控扩展 |
| 日志回传 | 可选集成 Chat/observability | 首期可本地优先 |

### 2.3 容量规划

| 资源 | 上限 | 量化依据 |
|---|---|---|
| 冷启动 | < 30s | README |
| 热启动 | < 5s | README |
| 并发运行实例 | ≥ 10 | README |
| 运行版本选择 | 显式 semver / digest | 版本可信要求 |

## 3. 架构风格与选型

### 3.1 变化维度识别

| 维度 | 变化频率 | 应对策略 |
|---|---|---|
| 支持平台(macOS/Windows/Linux) | 中 | shell + shared run core |
| Release 形态与元数据 | 中 | artifact adapter 隔离 |
| sandbox backend 行为差异 | 中 | sandbox adapter 与 execution facade |
| 日志与诊断需求 | 高 | run session model + diagnostics layer |
| 多实例资源管理 | 中高 | local session registry |

### 3.2 架构风格决策框架

**候选架构风格**:

| 风格 | 优势 | 劣势 | 适用性 |
|---|---|---|---|
| **shared run core + desktop shell + sandbox facade**(当前) | 行为一致、跨平台可控、便于 CLI 共用 | 抽象层较多 | ✅ |
| 纯 GUI 应用,逻辑塞进窗口层 | 起步快 | 难以复用 CLI 与诊断逻辑 | ❌ |
| 直接把 sandbox 细节暴露给用户 | 实现简单 | 违背非开发者叙事 | ❌ |
| 运行时动态部署器 | 灵活 | 范围膨胀,与 Runner 定位冲突 | ❌ |

**最终选择**:**共享运行核心 + 平台壳层 + 统一 sandbox facade + artifact-driven release flow**

### 3.3 架构风格约束-收益分析

| 约束 | 收益 | 成本 |
|---|---|---|
| Runner 不解释部署细节,只暴露“运行/停止/日志” | 用户心智简单 | 需隐藏复杂错误细节 |
| 共享运行核心覆盖 GUI/CLI | 口径一致、可测试性高 | 结构略重 |
| 只读 Release + 显式版本 | 交付可信、可追溯 | 用户灵活性受限 |

## 4. 系统边界与上下文

### 4.1 系统上下文图(C4 Context 级)

```text
非开发者用户 / 演示者 / 采购者
              │
              ▼
        ★ quantalithos-runner ★
        - release selector
        - local run sessions
        - logs / status / cleanup
           │           │
           │           └────────▶ sandbox(secure execution)
           └────────────────────▶ sdk -> artifact/work services
```

### 4.2 职责边界(做什么 / 不做什么)

**做什么**:
- ✅ 列出并选择可运行的 Release 版本
- ✅ 下载、缓存并在沙箱中启动 Release
- ✅ 展示本地运行状态、日志、访问入口和资源摘要
- ✅ 提供一键停止、清理和重启能力

**不做什么**:
- ❌ 不编辑源代码或 Release 内容
- ❌ 不做生产部署编排或云端托管
- ❌ 不替代 artifact 的真相源与审批逻辑
- ❌ 不绕过 sandbox 执行任何运行任务

### 4.3 外部系统可用性约束

| 外部依赖 | SLA | 依赖风险 | 降级策略 |
|---|---|---|---|
| SDK | 100%(编译期) | 接口漂移 | 版本锁 |
| artifact service | 99.9% | 下载失败 / Release 不可达 | 重试 / 本地缓存回退 |
| work service | 99.9% | 项目元数据缺失 | 局部降级显示 |
| sandbox | 99.9% | 启动失败 / 停止失败 | 显示诊断并阻断运行 |
| observability(可选日志上报) | 99.95% | 日志上报失败 | 本地保留摘要 |

### 4.4 关键依赖风险

- sandbox 接口若与 Runner 脱节,会让“可运行”与“可审计/可隔离”分成两套模型
- Release 元数据若不足以表达运行所需信息,Runner 会在端侧被迫猜测环境和入口
- 多实例与多版本共存若没有本地会话注册机制,极易出现端口冲突和资源泄露

## 5. 限界上下文与子域划分

### 5.1 子域分类

| 子域 | 分类 | 说明 |
|---|---|---|
| Release Access | 核心域 | 获取、选择与校验 Release |
| Run Session Management | 核心域 | 本地运行实例生命周期 |
| Sandbox Execution | 核心域 | 对接 L4 sandbox 的统一执行面 |
| Diagnostics | 支撑子域 | 日志、错误摘要、恢复建议 |
| Platform Shell | 支撑子域 | 桌面 GUI 与 CLI 壳层 |

### 5.2 限界上下文划分与职责

| 上下文 | 职责 | 核心对象 |
|---|---|---|
| Release Catalog | 项目->Release 列表与版本选择 | ReleaseOption |
| Run Session | launching/running/stopped/failed 生命周期 | LocalRunSession |
| Execution | sandbox 启停、端口、资源 | SandboxExecutionView |
| Diagnostics | 日志、错误、重试提示 | RunDiagnostic |
| Shell | GUI/CLI 入口与平台交互 | RunnerShellState |

### 5.3 上下文映射关系

- artifact → Release Catalog: **Conformist**，Runner 只采用 artifact 给出的 release 真相
- sandbox → Execution: **Open Host Service**，Runner 通过统一接口运行/停止
- work → Release Catalog: **Customer-Supplier**，确认项目归属与权限上下文
- observability ← Diagnostics(可选): 诊断摘要可进入审计与支持链

### 5.4 统一语言词汇表

| 术语 | 定义 | 使用场景 |
|---|---|---|
| ReleaseOption | 可被用户选择运行的某个发布版本 | Release Access |
| LocalRunSession | Runner 管理的一次本地运行会话 | Run Session |
| SandboxExecutionView | 对 L4 sandbox 执行实体的端侧投影 | Execution |
| RunDiagnostic | 人类可读的运行失败或告警摘要 | Diagnostics |
| Warm Start | 已有本地缓存时的快速重启路径 | Run Session |

## 6. 容器/部署架构

### 6.1 容器图(C4 Container 级)

```text
user
 │
 ▼
desktop shell / CLI
      │
      ▼
 shared runner core
 ├─ release catalog adapter
 ├─ run session registry
 ├─ diagnostics layer
 └─ sandbox facade
      │        │
      │        └────────▶ sandbox service
      └─────────────────▶ sdk -> artifact/work
```

### 6.2 每个容器的职责与技术栈

| 容器 / 进程 | 职责 | 技术栈 | 资源要求 |
|---|---|---|---|
| desktop shell | 窗口、通知、基础交互 | Rust + Tauri/Electron | 主产品壳 |
| CLI shell | 无 GUI 环境下的后备入口 | Rust CLI | 辅助入口 |
| shared runner core | Release/运行/诊断共用逻辑 | Rust | 核心逻辑 |
| sandbox facade | 对接 L4 sandbox | Rust + SDK / local adapter | 执行边界 |
| session registry | 维护本地运行实例状态 | Rust | 低内存、强一致 |

### 6.3 通信方式与选择理由

| 场景 | 选择 | 备选 | 理由 |
|---|---|---|---|
| Runner → Server | Rust SDK | 直接拼 RPC/HTTP | 统一契约与认证 |
| Runner → Sandbox | 统一 SandboxService 接口 | 本地 shell/daemon 直连 | 保持安全与运行口径一致 |
| GUI/CLI 共用逻辑 | shared core | 两套独立实现 | 避免行为分叉 |
| 日志诊断输出 | structured summaries + raw logs | 只给原始日志 | 面向非开发者需要人类可读摘要 |

### 6.4 数据存储归属

| 数据 | 写入方 | 读取方 |
|---|---|---|
| Release 真相 | artifact service | runner |
| 本地缓存 | runner | runner |
| 本地运行会话 | runner | runner / user |
| 运行日志摘要 | runner / sandbox | runner / observability(可选) |

### 6.5 部署拓扑

- Runner 作为本地桌面应用和 CLI 存在
- 真正的执行仍在本地 Sandbox 中发生
- Runner 不附带自建后端,只通过 SDK 访问 Server

## 7. 依赖方向与层间约束

### 7.1 依赖方向图

```text
shell(gui/cli)
    │
    ▼
shared runner core
    ├─▶ release access
    ├─▶ run session registry
    ├─▶ diagnostics
    └─▶ sandbox facade
            │
            ▼
      sdk / sandbox truth
```

### 7.2 层间约束规则

- shell 只承载交互差异,不直接操作 sandbox 或 SDK
- shared runner core 不持有业务真相,只维护本地会话与缓存视图
- sandbox facade 只消费统一接口,不得自行重实现执行策略
- diagnostics 层不改变执行语义,只负责聚合和解释错误信息
- Release Catalog 只展示显式版本,不推断 latest

### 7.3 依赖倒置的接口点

| 接口 | 定义位置 | 实现位置 |
|---|---|---|
| ReleaseCatalogAdapter | runner core | Rust SDK artifact/work adapter |
| SandboxExecutor | runner core | sandbox facade adapter |
| RunSessionStore | runner core | local persistent/in-memory registry |
| DiagnosticsSink | runner core | local logs / optional observability sink |

### 7.4 依赖健康度评估

| 指标 | 当前预期 |
|---|---|
| 传入耦合 | 中(用户入口单产品) |
| 传出耦合 | 中高(artifact/work/sandbox/sdk/observability) |
| 不稳定性 | 中 |
| 抽象度 | 中高(shared run core + adapters) |

## 8. 数据所有权与一致性策略

### 8.1 数据所有权矩阵

| 数据 | 拥有者 | 消费者 | 一致性策略 | 风险 |
|---|---|---|---|---|
| Release truth | artifact | runner | 最终一致 | stale cache |
| Project access truth | work/auth | runner | 最终一致 | 权限延迟 |
| Sandbox execution truth | sandbox | runner | 调用内确认 + 最终一致 | 异常残留 |
| Local run session | runner | runner / user | 本地强一致 | 崩溃恢复 |
| Diagnostics summary | runner | user / support | 本地强一致,可选上报 | 日志泄露 |

### 8.2 一致性层次

- Release/Project 权限真相来自 Server,Runner 最终一致消费
- 本地会话与缓存由 Runner 本地强一致维护
- Sandbox 执行状态通过接口确认与后续最终一致同步

### 8.3 补偿机制设计

| 场景 | 触发 | 补偿动作 | 幂等保证 |
|---|---|---|---|
| 下载成功但启动失败 | sandbox 启动报错 | 保留缓存,清理半成品会话 | `run_request_id + release_id` |
| 停止失败 | sandbox 未成功 kill | 标记为 uncertain state,允许重试 | `session_id` |
| 日志上报失败 | observability 不可用 | 保留本地摘要 | `session_id` |
| 重复启动同版本 | 用户重复点击 | 复用或显式新建,不默默覆盖旧会话 | `release_id + user_choice` |

## 9. 关键技术选型

### 9.1 Rust shared runner core

| 维度 | 内容 |
|---|---|
| 当前选择 | Rust 作为共享核心 |
| 备选方案 | TS/Electron-only / Go |
| 选择理由 | 便于桌面壳与 CLI 共用,且与 sandbox / sdk-rust 生态贴合 |
| 演进路径 | UI 层可迭代,核心逻辑保持稳定 |
| 不可逆程度 | 中 |

### 9.2 Tauri 优先的桌面壳层

| 维度 | 内容 |
|---|---|
| 当前选择 | Tauri 优先 |
| 备选方案 | Electron |
| 选择理由 | 与 Rust 核心更贴合,资源占用更轻,更适合本地运行器定位 |
| 演进路径 | 若跨平台集成受限,可回退 Electron |
| 不可逆程度 | 中 |

### 9.3 SDK-first artifact consumption

| 维度 | 内容 |
|---|---|
| 当前选择 | 通过 Rust SDK 获取 Release 与项目信息 |
| 备选方案 | 前端直连服务 / 自写客户端 |
| 选择理由 | 统一契约与认证语义,避免 Runner 形成私有接入层 |
| 演进路径 | SDK 可增强 download/stream helpers |
| 不可逆程度 | 高 |

### 9.4 Sandbox facade

| 维度 | 内容 |
|---|---|
| 当前选择 | 通过统一 SandboxService 启停 |
| 备选方案 | 直接调用 Docker/本机进程 |
| 选择理由 | 不破坏安全隔离边界,与 Runtime 共享模型 |
| 演进路径 | 随 L4 backend 增强而演化 |
| 不可逆程度 | 高 |

## 10. 备选方案与取舍

### 10.1 候选方案对比

| 维度 | 方案 A:shared core + sandbox facade(当前) | 方案 B:GUI 直连逻辑 | 方案 C:本地动态部署器 |
|---|---|---|---|
| 非开发者友好 | 高 | 中 | 低 |
| 安全性 | 高 | 中 | 低 |
| 复用性 | 高 | 低 | 中 |
| 实施复杂度 | 中 | 低 | 高 |
| 定位清晰度 | 高 | 中 | 低 |

### 10.2 最终选择与理由

选择 A,因为 Runner 的核心不是“本地部署能力”,而是“把可信 Release 低门槛地跑起来”。A 能同时守住安全、可追溯与用户心智；B 会让逻辑散落在壳层；C 则会把产品拖向复杂部署器,偏离 Runner 的使用场景。

## 12. 演进路线

### 12.1 当前架构状态与已知债务

| 债务项 | 影响 | 优先级 |
|---|---|---|
| 桌面壳层(Tauri/Electron)未定 | 影响平台体验与资源占用 | P1 |
| 多实例端口冲突策略未定 | 影响并发运行稳定性 | P1 |
| 日志回传到 Chat/observability 的交互未定 | 影响排障体验 | P1 |
| 受控分享运行未展开 | 影响后续演示场景 | P2 |

### 12.2 触发条件(可量化)

| 指标 | 阈值 | 动作 |
|---|---|---|
| 冷启动 > 30s | 持续 1 周 | 优化下载/缓存/启动路径 |
| 热启动 > 5s | 持续 1 周 | 优化本地缓存与会话恢复 |
| 多实例冲突率高 | > 阈值 | 增加更强端口/资源调度层 |
| 启停失败率上升 | > 阈值 | 强化 diagnostics 与 sandbox 对接 |

### 12.3 演进步骤

```text
阶段 1: Release 列表 + 下载 + sandbox 启停主路径跑通
   └─ 可停止点:非开发者能完成运行与停止

阶段 2: 日志/诊断/多实例管理稳定
   └─ 可停止点:演示与试用体验可靠

阶段 3: 平台增强、受控分享与更复杂资源策略
   └─ 可停止点:Runner 成熟为交付落地产品
```

### 12.4 目标架构

Runner 的目标架构不是“本地部署器”,而是 **交付物试用与运行的可信入口**:用户在这里面对的是软件版本、运行状态和使用结果,而不是容器、编排和基础设施。未来再增强,也必须围绕“可运行、可信、低门槛、可停止”四条主线收敛。

## 13. 风险与待确认事项

### 13.1 常见风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 冷启动过慢 | 中 | 高 | 缓存/镜像预热/状态可见 |
| 端口或资源冲突 | 中 | 中 | 显式冲突提示与调度策略 |
| 日志对用户过于技术化 | 高 | 中 | 诊断摘要层 |
| 误运行错误版本 | 中 | 高 | 显式版本选择 |

### 13.2 边缘风险

- 平台间沙箱行为差异导致同一 Release 表现不同
- 分享运行需求演变成公网暴露与安全边界问题
- 本地缓存过大影响磁盘与清理策略

## 14. 上线策略

### 14.1 灰度方案

```text
阶段 1: 单平台样本 Release 运行主路径
阶段 2: 多项目 / 多版本样本流
阶段 3: 引入日志诊断和多实例管理
阶段 4: 扩到更多平台与 CLI 后备入口
```

### 14.2 回滚策略

| 触发条件 | 等级 | 回滚步骤 |
|---|---|---|
| 启动流程普遍失败 | S 级 | 回滚 runner 版本或停用新启动流程 |
| sandbox 对接异常 | S 级 | 停止新运行入口,保留历史状态查看 |
| 误运行非 approved Release | S 级 | 立即关闭相关运行入口并修复校验 |
| 多实例冲突导致广泛失败 | A 级 | 降级为单实例或关闭并发运行 |

### 14.3 监控指标

| 指标 | 阈值 | 告警方式 |
|---|---|---|
| 冷启动耗时 | > 30s | warning |
| 热启动耗时 | > 5s | warning |
| 启停失败率 | > 阈值 | major |
| 非 approved 运行尝试 | > 0 | security |
| 多实例冲突率 | > 阈值 | warning |

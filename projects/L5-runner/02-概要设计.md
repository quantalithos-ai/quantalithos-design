## 3. 约束条件

> 校准来源：
> - [design-calibration/02_hld_step_03_constraints.md](design-calibration/02_hld_step_03_constraints.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“结构化约束总表”“后续 Step 约束映射”和“历史污染扫描”。

### 3.1 硬约束

| 约束 | 概要设计口径 |
|---|---|
| Truth ownership | Runner 只拥有本地选择/世代、取得/cache/验证姿态、运行/控制/清理 intent、资源观察、保护/恢复、展示和诊断姿态；不创建或反写 Release、approval、Project、execution、boundary、lease、cleanup、evidence 或 archive truth。 |
| 显式不可变版本 | 每次副作用绑定 exact Release/version、scope 与 generation；禁止 `latest`、默认分支、目录最新文件和可变 tag。 |
| Authority fail-closed | Artifact/Governance authority 必须可验证、current、未撤销/过期且 scope 无冲突；cache、角色、历史成功、ACK/HTTP 200 不能补齐。 |
| 材料绑定 | transfer complete、verified、qualified 和 protected/releasable 分轴；source/version/digest/generation 任一漂移都使旧资格失效。 |
| 多轴生命周期 | request intent、accepted、boundary、execution、control result、terminal、cleanup、release、eviction 独立；PID/端口/socket/toast/本地日志不能跨轴推导。 |
| Unknown 冻结 | timeout、断线、session/source/generation/lease mismatch 或 event gap 使危险副作用冻结；只读 reconcile/manual-review，禁止自动 replay。 |
| 保护优先 | lease/capture/handoff/retention/orphan 任一 active、missing 或 unknown 时，不得 cleanup 后删除或淘汰材料。 |
| Query no-write | query、render、reconnect view 不创建、刷新、修复或反写任何状态；refresh/reconcile 是独立 Operations。 |
| 安全预览 | preview/diagnosis/handoff 必须 bounded、redacted、带 source/freshness/visibility；禁止 raw body、secret 或 owner 正文进入普通持久化。 |
| 证据边界 | local log、telemetry、diagnosis、preview、job success 和 handoff receipt 均非 audit/evidence/report/verdict/signoff。 |
| SDK-first | 跨域只经 L0-sdk/正式 API/公开 adapter；禁止相邻仓内部表、事务、源码、Sandbox 私有 backend 或 L0-bus topic/group。 |
| 本地一致性 | 本地 aggregate/intent/basis 使用 expected-version 强一致；跨 owner 只声明带来源的最终一致投影，不使用共享事务。 |
| 技术中立 | 不从 README 继承 Rust/Tauri/Electron/Docker/gVisor/Firecracker、数据库、协议、进程模型或平台命令。 |
| 数量与性能 authority | 无 workload/测试 authority 不写固定 concurrency、capacity、timeout、retry 或 P95/P99；只保留 bounded/progress/backpressure 结构。 |
| 配置边界 | 配置不能启用 implicit version、跳过 authority/integrity、把 unknown 变 success、绕过 guard/redaction、改变 owner 或依赖方向。 |

### 3.2 Blocker 约束

| Blocker | 影响面 | 本文安全处理 |
|---|---|---|
| `RUN-UP-001` | Release locator/manifest/digest/signature/revoke/expire | required material ports + blocked/quarantine/stale；不锁 API/算法/transport |
| `RUN-UP-002` | authority chain/scope/expiry/revoke/conflict | selection blocked/invalidated；不本地批准 |
| `RUN-UP-003` | Sandbox request/idempotency/lease/cleanup/reconcile | required port、intent 与 unknown/recovery；不声明正向集成 |
| `RUN-UP-004` | Runtime status/result/recovery safe read | owner-safe projection + unavailable/unknown |
| `RUN-UP-005` | diagnostic/handoff/receipt/visibility/retention | bounded local diagnosis + blocked handoff；非 evidence |
| `RUN-UP-006` | Archive safe ref/restore | peripheral unavailable；不影响核心成功 |
| `RUN-UP-007` | cross-platform probe/allocation/cleanup responsibility | local/owner 双视图、unknown/conflict；不固定平台参数 |
| `RUN-UP-008` | SDK client/version/error/redaction/trace | semantic required ports；exact mapping 后置 |

## 5. 主要组成部分、职责与边界

> 校准来源：

>
> 延伸阅读：建议继续阅读上述中间产物的“组成部分总表”“对象发现维度”和“各组成部分独立停审”。

### 5.1 组成部分总表

| 组成部分 | 核心职责 | 主要代码主体 | 不承担什么 |
|---|---|---|---|
| Context and explicit selection | 解析可信 context，保存 exact Release/version、scope、generation 和 authority posture | entry facade、selection/context services、`RunnerContextRef`、`ReleaseSelection` | 不创建 Release、baseline、approval、Project/Work truth |
| Material acquisition and qualification | 解析 locator、下载/cache/quarantine、完整性/平台验证和资格晋级 | acquisition/qualification services/jobs、task/cache/integrity objects | 不发布/修改 Artifact，不以 transfer complete 代替资格 |
| Run intent and lifecycle | 建立 run/control intent，组合 Sandbox/Runtime owner status/ref | lifecycle/control services、intent objects、owner projection | 不执行 Runtime loop、不拥有 boundary/lease/outcome |
| Resource, cleanup and recovery protection | 本地资源观察、保护/cleanup、断线/restart reconcile/manual review | resource/recovery service/job、observation/guard/case | 不调度全局资源、不拥有 owner cleanup、不 replay unknown |
| Preview, diagnosis and handoff | 组合 bounded/redacted preview、失败分类和 safe handoff posture | preview/diagnosis/handoff services、三个对象 | 不保存 raw body，不生成 evidence/report/verdict/signoff |
| Entry and presentation composition | 将 GUI/CLI/product 映射到共同用例，组合多轴 read model 与 connectivity | inbound adapters、presenters、read-model composer | 不直连外部 client/store，不决定 domain authority |

### 5.2 对象发现维度

| 组成部分 | Truth / State | Projection / Read model | Reference / Policy | 正式关键对象 |
|---|---|---|---|---|
| Context/selection | selection/generation | selection posture | context/release/authority refs；exact binding | `RunnerContextRef`、`SelectionGeneration`、`ReleaseSelection` |
| Material | task/cache/integrity | progress/qualification sections | source/manifest refs；quarantine/promotion | `AcquisitionTask`、`MaterialCacheEntry`、`IntegrityPosture` |
| Lifecycle | run/control intent | owner request/execution/control/result | Sandbox/Runtime refs；accepted != running | `RunIntent`、`ControlIntent`、`OwnerRunProjection` |
| Resource/recovery | guard/recovery | conflict/cleanup/connectivity views | probe/lease/cleanup refs；no replay | `ResourceObservation`、`ProtectionGuard`、`RecoveryCase` |
| Diagnosis/handoff | diagnosis/handoff | output/diagnostic views | safe output/handoff refs；redaction | `OutputPreview`、`FailureDiagnosis`、`HandoffPosture` |
| Entry/presentation | local composition state | multi-section read model | source/freshness/visibility | `RunnerReadModel`、`ConnectivityView` |

### 5.3 各部分交互总图

```text
Context and explicit selection
              │ exact selection + generation
              ▼
Material acquisition and qualification
              │ qualified material binding
              ▼
Resource / preflight protection ───────► Run intent and lifecycle
              │                                     │ owner refs/status
              │                                     ▼
              └────────────────────────► Preview, diagnosis and handoff
                                                    │ safe sections
                                                    ▼
                                      Entry and presentation composition

Owner snapshots/refs and local observations enter only through formal
ports. Recovery may re-read every part but never replays unknown side
effects or rewrites owner truth.
```

关键说明：

- 主线从 explicit selection 开始；不存在以历史 run/card/queue 为起点的旁路。
- 所有箭头经过 application/domain gate，不代表共享数据库、跨仓事务或协议时序。
- Recovery 是 query/reconcile，不是补偿执行器；Entry/presentation 是只读组合。
- Archive 等外围能力不参与 qualified、running 或 cleanup 成功判断。

#### 5.4.1 Context and explicit selection

| 代码主体 / 模块 | 类型 | 作用 | 后续展开位置 |
|---|---|---|---|
| `RunnerEntryFacade` | Application boundary | 为所有入口提供统一 context/command/query 门禁 | §7～§8、03 |
| `SelectionService` | Application | 编排 context、explicit selection 与 authority check | §7～§9、03 |

接缝：向 Material 交付同一 generation 的 current selection binding；authority 漂移使下游资格/意图失效。不得以角色、cache 或历史成功生成 current。

#### 5.4.2 Material acquisition and qualification

接缝：向 Lifecycle 只交付同 selection/source/digest binding 的 qualified material；向 Resource 交付 protected subject。传输完成、文件存在或 cache 命中均不能绕过验证。

#### 5.4.3 Run intent and lifecycle

| `OwnerRunProjection` | Projection | 组合 owner request/execution/control/result refs | §6～§9 |
| Sandbox/Runtime ports | Required ports | 正式请求/控制/cleanup 与 safe status/result read | §7、§13 |

接缝：从 Material/Resource 接收 qualified binding 和 preflight/guard；向 Diagnosis/Entry 只提供带 source/freshness 的多轴状态。不得以 ACK、PID、端口或日志推 running/terminal。

#### 5.4.4 Resource, cleanup and recovery protection

| 代码主体 / 模块 | 类型 | 作用 | 后续展开位置 |
|---|---|---|---|
| `ResourceRecoveryService` | Application | 编排 local probe、protection、cleanup 和 recovery | §7～§10、03 |
| Reconcile/Eviction Jobs | Operations | 只读 owner 对账与安全候选评估 | §7～§8、03 |
| observation/guard/recovery objects | Domain / Observation | 分开 local resource、release eligibility 和 frozen recovery | §6、§9 |
| platform/clock/Sandbox read ports | Ports | 提供 local observation 和 owner-safe allocation/lease/cleanup basis | §7、§13 |

接缝：向 cache/diagnosis 提供 ProtectionGuard；向 Lifecycle/Entry 提供 conflict/recovery posture。任何 missing/unknown protection 均禁止释放。

|---|---|---|---|

| `HandoffService` | Application | 准备并提交允许的 diagnostic refs/summary | §7～§9、03 |
| preview/diagnosis/handoff objects | Projection / local record/state | 表达安全展示、分类和交接姿态 | §6、§9 |

接缝：从 Lifecycle/Resource 接收 safe refs/失败姿态，向 Entry 提供安全 sections，向 ProtectionGuard 提供 handoff/retention posture。不得以 raw log fallback 或 receipt 升级证据。

| logical presenters | Presentation | 显示 section-level source/freshness/visibility/unknown | §12、03 |

接缝：只读取前五部分，不成为第二 truth；render/query 不触发 refresh/repair。平台壳能力可以降级展示，但不能改变 domain 或 owner 边界。

## 6. 关键对象轮廓

> 校准来源：
> - [design-calibration/02_hld_step_06_key_objects.md](design-calibration/02_hld_step_06_key_objects.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“对象候选池筛选”“逐组成部分对象正式化”和“跨对象一致性审计”。

对象只承载 Runner-owned local truth、safe owner projection/ref 或 local observation；service、job、port、repository、DTO、页面和 raw owner response 不升格为领域对象。Safe refs 的完整字段与共享契约留 03 核验。

### 6.1 Context and explicit selection

#### 6.1.1 `RunnerContextRef`

| 项 | 内容 |
|---|---|
| 对象类型 | immutable context object |
| 主要责任 | 绑定已解析 actor/session/project/platform 安全引用、scope、freshness 和 visibility，不复制身份或项目正文。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `context_id` | `RunnerContextId` | 本地关联标识，不是身份 ID |
| `actor_ref` / `session_ref` | `ActorRef` / `SessionRef` | 正式 actor/session 安全引用 |
| `project_ref` | `OptionalProjectRef` | 可选项目语境，不推断 ProjectMember |
| `scope_ref` | `RunnerScopeRef` | 当前适用 scope |
| `platform_ref` | `PlatformContextRef` | 端侧平台语境，不是资源 truth |
| `source_freshness` / `visibility` | `SourceFreshness` / `VisibilityPosture` | 来源当前性与限制 |

| 函数骨架 | 作用 |
|---|---|
| `assert_usable(RunnerScopeRef scope_ref)` | 检查 scope/freshness/visibility，不授予权限 |
| `mark_stale(StaleReason reason)` | 产生 stale 姿态并触发冻结 |
| `from_resolution(ContextResolution resolution)` | 仅从正式 resolver 的 safe result 构造 |

禁止保存 token/secret、身份/项目正文，或用本地角色和旧 session 推导 authority。

#### 6.1.2 `SelectionGeneration`

| 项 | 内容 |
|---|---|
| 对象类型 | immutable value object |
| 主要责任 | 区分每次显式选择世代，阻止旧资格、cache 或 intent 跨选择复用。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `value` | `GenerationNumber` | 本地单调世代值 |
| `cause` | `SelectionChangeCause` | initial/user_change/source_invalidation/context_change |
| `predecessor` | `OptionalGenerationNumber` | 前一世代引用 |
| `created_at` | `Timestamp` | 本地生成时间，非 owner 版本时间 |

| 函数骨架 | 作用 |
|---|---|
| `is_successor_of(SelectionGeneration previous)` | 校验本地世代连续性 |
| `initial(SelectionChangeCause cause)` | 创建首个明确世代 |
| `next(SelectionGeneration previous, SelectionChangeCause cause)` | 创建 successor；不原地修改旧世代 |

它不等于 Release version、digest 或 event cursor。

#### 6.1.3 `ReleaseSelection`

| 项 | 内容 |
|---|---|
| 对象类型 | local aggregate |
| 主要责任 | 保存 explicit Release/version、context、scope、generation 与 authority ref/失效姿态。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `selection_id` | `RunnerSelectionId` | Runner 本地选择标识 |
| `context_ref` | `RunnerContextRef` | 选择时的可信语境 |
| `release_ref` / `version_ref` | `ReleaseRef` / `ArtifactVersionRef` | exact immutable source；禁止 latest |
| `scope_ref` | `RunnerScopeRef` | 适用范围 |
| `generation` | `SelectionGeneration` | 当前选择世代 |
| `authority_ref` | `OptionalAuthorityRef` | 正式 authority 引用，不等本地批准 |
| `state` | `SelectionState` | selected/checking/current/stale/invalidated/blocked |

| 状态 | 作用 |
|---|---|
| `selected` / `checking` | 已显式选择 / 正在读取正式 authority；均不允许副作用 |
| `current` | authority current 且 binding 一致，可进入材料准备 |
| `stale` / `invalidated` / `blocked` | 依据过时 / 世代失效 / 无法证明；均禁止继续 |

| 函数骨架 | 作用 |
|---|---|
| `bind_authority(AuthoritySnapshotRef authority_ref, SourceFreshness freshness)` | 绑定正式结论，不生成 approval |
| `invalidate(SelectionInvalidation reason, SelectionGeneration next_generation)` | 失效当前世代及下游资格 |
| `assert_binding(ReleaseRef release_ref, ArtifactVersionRef version_ref, SelectionGeneration generation)` | 校验副作用 binding |
| `select(RunnerContextRef context_ref, ReleaseRef release_ref, ArtifactVersionRef version_ref, RunnerScopeRef scope_ref, SelectionGeneration generation)` | 从 explicit input 建立 selected 聚合 |

禁止隐式版本、修改 Release 内容或生成 approval。

### 6.2 Material acquisition and qualification

#### 6.2.1 `AcquisitionTask`

| 项 | 内容 |
|---|---|
| 对象类型 | local aggregate |
| 主要责任 | 承载与 selection binding 绑定的 locator resolution、transfer progress、pause/resume/cancel 与 failure。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `task_id` | `AcquisitionTaskId` | 本地任务标识 |
| `selection_binding` | `SelectionBinding` | release/version/scope/generation binding |
| `locator_ref` | `OptionalLocatorRef` | safe locator ref，不保存 secret URL |
| `state` | `AcquisitionState` | absent/resolving/transferring/paused/complete/failed/cancelled |
| `progress` | `TransferProgress` | 有界进度，不证明完整性 |
| `material_handle` | `OptionalLocalMaterialHandle` | quarantine 抽象句柄 |
| `failure` | `OptionalAcquisitionFailure` | redacted failure |

| 函数骨架 | 作用 |
|---|---|
| `record_progress(TransferProgress progress)` | 更新同一次取得的有界进度 |
| `pause(AcquisitionPauseReason reason)` | 标记暂停，不伪造完成 |
| `complete(LocalMaterialHandle material_handle)` | 只确认 transfer complete 并交给 quarantine |
| `fail(AcquisitionFailure failure)` | 保存 redacted 失败姿态 |
| `start(SelectionBinding selection_binding, AcquisitionTaskId task_id)` | 创建尚未解析 locator 的任务 |

`complete` 不推出 verified/qualified；禁止保存 raw transport response。

#### 6.2.2 `MaterialCacheEntry`

| 项 | 内容 |
|---|---|
| 对象类型 | local entity |
| 主要责任 | 记录本地材料与 source/digest/generation 的不可变绑定、qualification 生命周期和保护引用。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `cache_entry_id` | `CacheEntryId` | 本地 cache 标识 |
| `source_binding` | `MaterialSourceBinding` | release/version/digest/generation binding |
| `storage_handle` | `LocalMaterialHandle` | 抽象句柄，不暴露原始平台路径 |
| `integrity_posture_ref` | `IntegrityPostureRef` | 最近验证记录引用 |
| `state` | `MaterialCacheState` | quarantined/qualified/stale/invalid/evicted |
| `protection_refs` | `ProtectionRefSet` | lease/capture/handoff/retention/orphan refs |
| `eviction_candidate` | `EvictionCandidatePosture` | candidate/not_candidate/unknown；不是删除许可 |
| `last_used_at` | `Timestamp` | 候选输入，不覆盖保护 |

| 函数骨架 | 作用 |
|---|---|
| `promote(IntegrityPosture posture, AuthoritySnapshotRef authority_ref)` | 同 binding 且验证 current 后晋级 |
| `protect(ProtectionRef protection_ref)` | 增加活动保护 |
| `release_protection(ProtectionRef protection_ref, OwnerConfirmationRef confirmation_ref)` | 仅凭正式解除依据移除保护 |
| `mark_stale(StaleReason reason)` | 阻止旧材料用于新副作用 |
| `quarantine(MaterialSourceBinding source_binding, LocalMaterialHandle storage_handle)` | transfer complete 后创建，初态非 qualified |

删除资格由 `ProtectionGuard` 独立裁决；不得修改/重打包 Release，或用磁盘压力绕过保护。

#### 6.2.3 `IntegrityPosture`

| 项 | 内容 |
|---|---|
| 对象类型 | local verification record / state object |
| 主要责任 | 记录 owner-provided manifest/policy 下的 digest、signature、platform 与 authority freshness 结果。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `posture_id` | `IntegrityPostureId` | 本地验证记录标识 |
| `source_binding` | `MaterialSourceBinding` | 被验证材料的 immutable binding |
| `manifest_ref` | `ManifestRef` | 正式 manifest 引用 |
| `digest_result` | `DigestCheckResult` | 内容验证结果，不锁算法 |
| `signature_result` | `SignatureCheckResult` | 正式 policy 下的签名结果 |
| `platform_result` | `PlatformCompatibilityResult` | 端侧兼容姿态，不授予 Sandbox policy |
| `authority_freshness` | `SourceFreshness` | 启动前 authority 当前性 |
| `state` | `IntegrityState` | pending/verifying/verified/invalid/stale/blocked |

| 函数骨架 | 作用 |
|---|---|
| `record_results(DigestCheckResult digest, SignatureCheckResult signature, PlatformCompatibilityResult platform)` | 组合检查结果，不生成 approval |
| `assert_qualified(MaterialSourceBinding binding, SourceFreshness freshness)` | 校验同一 source binding/currentness |
| `invalidate(IntegrityInvalidation reason)` | source/authority 变化后禁止复用 |
| `begin(MaterialSourceBinding source_binding, ManifestRef manifest_ref)` | 从正式 manifest ref 建立 pending posture |

禁止自选算法、签名 policy 或补齐缺失 manifest；verified 不等 approved/running。

### 6.3 Run intent and lifecycle

#### 6.3.1 `RunIntent`

| 项 | 内容 |
|---|---|
| 对象类型 | local aggregate |
| 主要责任 | 保存一次与 context、selection、qualified material 绑定的 run request intent 与提交姿态。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `run_intent_id` | `RunIntentId` | Runner 本地意图标识 |
| `context_ref` | `RunnerContextRef` | actor/session/scope 语境 |
| `selection_binding` | `SelectionBinding` | exact Release/version/generation |
| `material_binding` | `QualifiedMaterialBinding` | qualified cache/digest/posture ref |
| `request_metadata` | `RunnerCommandMetadata` | correlation/idempotency/issued-at 骨架 |
| `sandbox_request_ref` | `OptionalSandboxRequestRef` | owner 接收后的 safe ref |
| `state` | `RunIntentState` | draft/submitting/accepted/rejected/unknown/invalidated |

| 函数骨架 | 作用 |
|---|---|
| `mark_submitting(RunnerCommandMetadata metadata)` | 固定幂等/correlation 并进入提交中 |
| `record_receipt(SandboxRequestRef request_ref, OwnerReceiptPosture receipt)` | 记录 owner receipt，不标 running |
| `mark_unknown(UnknownReason reason)` | 冻结自动重放，要求 reconcile |
| `invalidate(BindingMismatch mismatch)` | 阻止失效 intent 继续 |
| `create(RunnerContextRef context_ref, SelectionBinding selection_binding, QualifiedMaterialBinding material_binding, RunnerCommandMetadata metadata)` | 仅在 binding/qualification 一致时建立 |

不拥有 boundary、lease 或 execution outcome；accepted 不推出 running。

#### 6.3.2 `ControlIntent`

| 项 | 内容 |
|---|---|
| 对象类型 | local entity |
| 主要责任 | 承载 start/stop/cancel/cleanup intent、expected owner basis 和 owner result posture。 |

| 字段 | 类型 | 作用 |
|---|---|---|

| `run_intent_id` | `RunIntentId` | 所属运行意图 |
| `kind` | `ControlIntentKind` | start/stop/cancel/cleanup_request |
| `expected_owner_basis` | `OwnerStateBasis` | expected request/run/lease epoch |
| `metadata` | `RunnerCommandMetadata` | idempotency/correlation |
| `state` | `ControlIntentState` | pending/accepted/confirmed/rejected/unknown/conflict |
| `owner_result_ref` | `OptionalControlResultRef` | 正式控制结果引用 |

| 函数骨架 | 作用 |
|---|---|
| `record_owner_result(ControlResultRef result_ref, OwnerControlPosture posture)` | 记录正式结果，不推资源释放 |
| `mark_conflict(OwnerStateBasis actual_basis)` | 暴露 basis 冲突并冻结 |
| `requires_reconcile()` | 判断 unknown/conflict 是否需恢复 |
| `request(ControlIntentKind kind, RunIntentId run_intent_id, OwnerStateBasis expected_owner_basis, RunnerCommandMetadata metadata)` | 创建单一幂等控制意图 |

不实现任意 retry/replay；confirmed stop 不等 cleaned。

| 函数骨架 | 作用 |
|---|---|

| `mark_stale(StaleReason reason)` | 暴露旧投影，不改 owner |
| `can_display_running()` | 只有 current owner execution 支撑时为真 |
| `empty(RunIntentId run_intent_id)` | 建立无 owner ref 的 projection，不默认 pending/running |

禁止由 PID、端口、toast 或本地日志推导 owner posture，也禁止 Query 时刷新/修复。

### 6.4 Resource, cleanup and recovery protection

#### 6.4.1 `ResourceObservation`

| 项 | 内容 |

| 字段 | 类型 | 作用 |

#### 6.4.2 `ProtectionGuard`

| 项 | 内容 |
|---|---|
| 对象类型 | domain guard |
| 主要责任 | 汇总 lease/capture/handoff/retention/orphan 保护，保守裁决本地材料是否可释放。 |

| 字段 | 类型 | 作用 |

| `guard_id` / `subject` | `ProtectionGuardId` / `ProtectedSubjectRef` | guard 与受保护 subject |

| `capture_posture` | `CaptureProtectionPosture` | capture 保护 |

|---|---|

| `assert_releasable(OwnerCleanupBasis cleanup_basis)` | 校验 guard 与 owner cleanup basis 一致 |
| `protect(ProtectedSubjectRef subject, ProtectionInputs inputs)` | 初建 guard；默认 unknown/protected |

|---|---|
| `record_snapshot(OwnerRecoverySnapshot snapshot)` | 应用只读 owner basis |
| `reconcile(RecoveryExpectedBasis expected, OwnerRecoverySnapshot actual)` | 只收敛可证明状态，不重放 |
| `require_manual_review(ReconcileFailure reason)` | 标记无法证明的冲突 |
| `freeze(RecoveryTrigger trigger, RecoverySubjectRefSet subject_refs, RecoveryExpectedBasis expected_basis)` | 立即冻结受影响副作用 |

禁止推进 owner cursor、修复 owner truth 或自动 replay；closed 不表示 owner run success。

### 6.5 Preview, diagnosis and handoff

#### 6.5.1 `OutputPreview`

| 项 | 内容 |
|---|---|
| 对象类型 | read projection |
| 主要责任 | 表达带来源、freshness、visibility 和 truncation 的安全输出预览。 |

| 字段 | 类型 | 作用 |

| `preview_id` | `OutputPreviewId` | 本地 view 标识 |
| `source_refs` | `OutputSourceRefSet` | Sandbox/Runtime/Artifact/Observability safe refs |
| `content` | `RedactedBoundedContent` | 已裁剪/脱敏内容，非 raw body |
| `visibility` / `freshness` | `VisibilityPosture` / `SourceFreshness` | 限制与当前性 |
| `truncation` | `TruncationPosture` | 是否及为何裁剪 |

| 函数骨架 | 作用 |
|---|---|
| `assert_safe(RedactionPolicyRef policy_ref)` | 确认内容满足正式安全边界 |
| `mark_stale(StaleReason reason)` | 标 stale，不刷新 owner |
| `compose(SafeOutputMaterial material, RedactionResult redaction, SourceFreshness freshness)` | 仅从 owner-safe material 构造 |

不保存 raw stdout/stderr、secret 或 Artifact 正文，也不解释为 evidence/report/result truth。

#### 6.5.2 `FailureDiagnosis`

| 项 | 内容 |
|---|---|
| 对象类型 | local diagnostic record |
| 主要责任 | 将 owner/local safe failure 映射为 source、impact、classification 和 next step，不猜终态。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `diagnosis_id` | `FailureDiagnosisId` | 本地诊断标识 |
| `subject_refs` / `source_failures` | typed safe ref sets | 受影响对象与安全失败来源 |
| `classification` | `FailureClass` | authority/material/resource/request/execution/control/cleanup/connectivity/handoff |
| `impact` | `FailureImpact` | 对当前主线和用户动作的影响 |
| `next_step` | `SafeNextStep` | retry-read/reselect/reverify/reconcile/manual-review/contact-owner |
| `freshness` | `SourceFreshness` | 诊断依据当前性 |

| 函数骨架 | 作用 |
|---|---|
| `classify(FailureSignals signals)` | 按来源区分失败，不压成 generic error |
| `mark_uncertain(UncertaintyReason reason)` | 依据不足时保留 unknown，不输出 verdict |
| `diagnose(DiagnosticSubjectRefSet subjects, FailureSignals signals, RedactionResult redaction)` | 仅从 safe signals 建立本地诊断 |

不修改 source failure、生成 verdict/signoff 或建议自动 replay unknown side effect。

#### 6.5.3 `HandoffPosture`

| 项 | 内容 |
|---|---|
| 对象类型 | local handoff state object |
| 主要责任 | 跟踪 redacted diagnostic/refs 的交接 intent、receipt 和 visibility，不迁移 evidence ownership。 |

| 字段 | 类型 | 作用 |
|---|---|---|
| `handoff_id` | `DiagnosticHandoffId` | 本地 handoff 标识 |
| `diagnosis_ref` | `FailureDiagnosisRef` | 被交接诊断引用 |
| `material_refs` | `SafeHandoffMaterialRefSet` | 允许交接的 refs/summary |
| `target_ref` | `HandoffTargetRef` | 正式目标引用 |
| `state` | `HandoffState` | draft/pending/accepted/blocked/delivered/failed/unknown |
| `receipt_ref` | `OptionalHandoffReceiptRef` | 正式 receipt 引用 |
| `visibility` | `VisibilityPosture` | 交接结果可见性 |

| 函数骨架 | 作用 |
|---|---|
| `submit(HandoffCommandMetadata metadata)` | 固定 correlation/idempotency 并进入 pending |
| `record_receipt(HandoffReceiptRef receipt_ref, OwnerHandoffPosture posture)` | 记录 owner receipt，不创建 evidence |
| `mark_unknown(UnknownReason reason)` | 冻结自动重发并进入 reconcile |
| `prepare(FailureDiagnosisRef diagnosis_ref, SafeHandoffMaterialRefSet material_refs, HandoffTargetRef target_ref)` | 仅用 redacted/allowed refs 建立 draft |

accepted/delivered 均不等 evidence/verdict/signoff；禁止保存原始日志正文。

| 审计项 | 结论 |

| Ownership | local truth、owner projection、safe ref、local observation、read model 分离 |

## 7. API / 接口骨架

> 校准来源：
> - [design-calibration/02_hld_step_07_api_interface_skeleton.md](design-calibration/02_hld_step_07_api_interface_skeleton.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“按组成部分接口骨架索引”“接口归属停审”和“required-port readiness”。

### 7.1 分类与共通边界

| 类别 | Runner 口径 |
|---|---|
| Command | 显式改变 Runner-owned selection/intent/control/handoff；副作用入口带 `ActorContext`、`CommandMetadata` 和 `IdempotencyKey`，绑定 expected generation/source/digest/owner basis。 |
| Query | 只读 local truth、safe projection/ref 和 observation；带 actor/visibility context，不创建、refresh、repair 或写入。 |
| Inbound Consumer | 只消费 owner 已提交事实；需要正式 envelope/event id/source version/dedup/order/gap 合同。当前四类均 planned/blocked。 |
| Outbound Event | 当前不适用：无经需求/架构和消费者合同确认的 Runner-owned event family。 |
| Operations Job | 承接长时取得/验证、只读 reconcile、projection refresh 和 eviction evaluation；job success 非 owner success。 |
| Required Port | 表达 Runner 所需能力与安全失败语义，不证明同名 client/DTO/transport 已存在。 |

### 7.2 Command API

| API | 输入骨架 | 输出骨架 | 主要处理 | 写入结果 |
|---|---|---|---|---|
| `SelectRelease` | `ActorContext`、`SelectReleaseInput`、`CommandMetadata`、`IdempotencyKey` | `ReleaseSelectionResult` | 拒绝隐式版本，解析 context/authority，创建 generation/selection | selection；旧资格/intent 失效 |
| `InvalidateSelection` | `ActorContext`、`SelectionInvalidationInput`、`CommandMetadata` | `SelectionInvalidationResult` | 校验 source/generation 并失效 | successor generation + invalidated posture |
| `RequestMaterialAcquisition` | actor、`AcquisitionRequestInput`、metadata、idempotency | `AcquisitionRequestResult` | 校验 current binding/authority，建立 task | `AcquisitionTask`，不生成 verified |
| `PauseAcquisition` | actor、`AcquisitionControlInput`、metadata | `AcquisitionControlResult` | 暂停本地取得 | paused posture |
| `ResumeAcquisition` | actor、control input、metadata、idempotency | `AcquisitionControlResult` | 重验 binding/authority 后恢复 | transferring 或 blocked |
| `CancelAcquisition` | actor、control input、metadata | `AcquisitionControlResult` | 取消取得；清理另走 guard | cancelled posture，非 deleted |
| `RequestRun` | actor、`RunRequestInput`、metadata、idempotency | `RunRequestResult` | 校验 context/selection/material/protection，建立并提交 intent | `RunIntent` + optional owner request ref |
| `RequestRunControl` | actor、`RunControlInput`、metadata、idempotency | `RunControlResult` | 建立 start/stop/cancel intent 并提交正式 port | `ControlIntent`; accepted/rejected/conflict/unknown |
| `RequestCleanup` | actor、`CleanupRequestInput`、metadata、idempotency | `CleanupRequestResult` | 评估 guard，允许时提交 owner cleanup intent | cleanup intent/ref；非 released |
| `OpenManualReview` | actor、`ManualReviewInput`、metadata | `ManualReviewResult` | 将不可证明 recovery case 置 manual_review | `RecoveryCase` 更新；非 override |
| `RequestDiagnosticHandoff` | actor、`DiagnosticHandoffInput`、metadata、idempotency | `DiagnosticHandoffResult` | 校验 redaction/visibility 并提交 safe refs/summary | `HandoffPosture`；非 evidence |

所有 adapter timeout/ambiguous 结果返回 `unknown` 并关联 recovery；入口不得自动重放。

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - [design-calibration/02_hld_step_08_processing_flows.md](design-calibration/02_hld_step_08_processing_flows.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“处理流覆盖清单”“按主要组成部分展开处理流”和“事务、副作用与 unknown 出口审计”。

### 8.1 通用 Command 写路径

```text
Command + ActorContext + CommandMetadata + IdempotencyKey
  │
  ▼
Inbound / RunnerEntryFacade
  - 校验 explicit refs、context 和 operation identity
  │
  ▼
Application Service
  - 事务外读取 owner-safe basis / local observation
  - 校验 generation/source/digest/owner expected basis
  │
  ▼
Local transaction A
  - expected-version 校验并保存 Runner-owned intent/state
  │
  ▼
Required Port（事务外）
  ├─ explicit result ─► Local transaction B：应用 owner ref/posture
  └─ ambiguous ───────► Local transaction B：unknown + RecoveryCase
  │
  ▼
Typed Result（不推导 owner success）
```

关键设计点：

- 本地事务不包网络、下载、验证或 owner call；跨仓没有共享事务。
- Idempotency 固定同一 operation identity，不授权 automatic retry。
- 03 继续展开 operation persistence、expected version、crash window 和 typed errors。

### 8.2 SelectRelease 处理流

```text
SelectRelease(ActorContext actor, SelectReleaseInput input,
              CommandMetadata metadata, IdempotencyKey idempotency_key)
  │
  ▼
RunnerEntryFacade / SelectionService
  - 拒绝 latest/default/newest；解析 safe context
  - 事务外读取 ReleaseAuthorityReadPort
  │
  ▼
Local transaction
  - SelectionGeneration.next(SelectionGeneration previous,
                             SelectionChangeCause cause)
  - ReleaseSelection.select(RunnerContextRef context_ref, ReleaseRef release_ref,
                            ArtifactVersionRef version_ref, RunnerScopeRef scope_ref,
                            SelectionGeneration generation)
  - 使旧 generation 的资格/intent 不可继续
  │
  ▼
ReleaseSelectionResult（selected/checking/current/blocked；非 approval）
```

关键设计点：

- Authority read result 在提交 selection 前再次比较 context/generation expected version。
- 选择成功不等于 material qualified 或 run allowed。
- 已发且结果不明的旧 intent 进入 recovery，不能本地“撤销成功”。

### 8.3 AcquireAndVerifyMaterialJob 处理流

```text
AcquireAndVerifyMaterialJob(AcquisitionTaskId task_id)
  │
  ▼
Acquire Job
  - claim persisted task；重读 selection/authority/source basis
  │
  ▼
AcquisitionService（事务外）
  - MaterialSourcePort.resolve(MaterialSourceQuery query)
  - MaterialSourcePort.transfer(MaterialTransferRequest request)
  │
  ▼
Short local transactions
  - AcquisitionTask.record_progress(TransferProgress progress)
  - MaterialCacheEntry.quarantine(MaterialSourceBinding source_binding,
                                  LocalMaterialHandle storage_handle)
  │
  ▼
QualificationService（事务外）
  - IntegrityVerifierPort.verify(IntegrityVerificationRequest request)
  │
  ▼
Final local transaction
  ├─ same current basis + checks pass ─► verified + qualified
  ├─ mismatch/invalid ────────────────► invalid/quarantine
  └─ missing/ambiguous ───────────────► blocked/stale；不晋级
```

关键设计点：

- Transfer、quarantine、verification、authority current 和 qualification 是独立检查点。
- 每次短事务比较 task version 与 immutable binding；旧 worker 结果不得覆盖新世代。
- `RUN-UP-001/002/008` 未关闭时正向 resolve/transfer/verify 为 blocked。

### 8.4 RequestRun / RequestRunControl 处理流

```text
RequestRun | RequestRunControl
  │
  ▼
RunnerEntryFacade / Lifecycle Service
  - 重验 context/selection/authority/material/guard/resource impact
  - control 另校验 expected request/run/lease basis
  │
  ▼
Local transaction A
  - RunIntent.create(RunnerContextRef context_ref,
                     SelectionBinding selection_binding,
                     QualifiedMaterialBinding material_binding,
                     RunnerCommandMetadata metadata)
  - ControlIntent.request(ControlIntentKind kind, RunIntentId run_intent_id,
                          OwnerStateBasis expected_owner_basis,
                          RunnerCommandMetadata metadata)
  - 固定 metadata、correlation、idempotency 与 expected basis
  │
  ▼
SandboxRunPort.request(SandboxRunRequest request) /
SandboxRunPort.control(SandboxControlRequest request)（事务外；当前 blocked）
  │
  ├─ receipt/result ─► Local transaction B：accepted/rejected/confirmed/conflict
  └─ timeout/ambiguous ─► unknown + RecoveryCase；禁止 replay
  │
  ▼
Typed result（accepted != running；stop confirmed != cleaned）
```

关键设计点：

- 这是唯一正式 run/control 出口；入口不能直连 Sandbox 私有 backend 或 Runtime。
- ACK 只影响 request/control axis，PID/port 只进入 resource observation。
- 图省略的完整签名和 exact owner DTO 必须等合同闭合后由 03 定义。

### 8.5 RequestCleanup / ReconcileRunnerStateJob 处理流

```text
RequestCleanup
  │
  ▼
ResourceRecoveryService
  - 事务外读取 lease/capture/handoff/retention/orphan basis
  - ProtectionGuard.evaluate(ProtectionInputs inputs)
  │
  ├─ protected/blocked/unknown ─► 不调用 cleanup、不删除材料
  └─ releasable + current basis
        │
        ▼
    保存 cleanup intent ─► SandboxRunPort.cleanup(SandboxCleanupRequest request)
                           （事务外）
        │                    ├─ confirmed ─► 记录 owner ref，重新评估 guard
        │                    └─ ambiguous ─► unknown + RecoveryCase
        ▼
    CleanupRequestResult（非 released/evicted）

RecoveryCase frozen
  └─ ReconcileRunnerStateJob ─► formal read ports ─► local reconcile
                                    ├─ matches ─► reconciled
                                    ├─ mismatch ─► conflict
                                    └─ cannot prove ─► manual_review
```

关键设计点：

- Cleanup intent、accepted、confirmed、owner released 和 local evicted 是不同阶段。
- Reconnect/online 只允许启动只读 reconcile，不表示恢复成功。
- Reconcile 不推进 owner cursor、不修复 owner truth、不补发 unknown command。

### 8.6 Preview / Diagnosis / Handoff 处理流

```text
Safe owner output/failure refs
  │
  ▼
DiagnosticReadPort + RedactionPort（事务外）
  - bounded source only；redaction failure => blocked
  │
  ▼
OutputPreview / FailureDiagnosis
  - source/freshness/visibility/truncation/uncertainty
  │ explicit RequestDiagnosticHandoff
  ▼
Local transaction A：HandoffPosture draft -> pending
  │
  ▼
ObservabilityHandoffPort.submit(DiagnosticHandoffRequest request)
  （事务外；当前 blocked）
  ├─ receipt ─► Local transaction B：accepted/delivered/failed
  └─ ambiguous ─► unknown + RecoveryCase；不自动 resend
```

关键设计点：

- 不通过 raw logs 或未脱敏正文作 fallback；empty、restricted 与 unavailable 可区分。
- Accepted/delivered 只说明交接姿态，不能创建 evidence/report/verdict/signoff。
- Handoff/retention 只是一项 protection input，不能单独授权材料删除。

### 8.7 GetRunnerReadModel / RefreshVisibleSourcesJob 处理流

```text
GetRunnerReadModel(ActorContext actor, RunnerReadModelQueryInput input)
  │
  ▼
RunnerReadModelComposer（只读）
  - 读取六部分 safe sections；保留各自 source/freshness/visibility
  - compose + redact_for；不 refresh/repair/write
  │
  ├─ all ready ─► multi-axis view
  ├─ partial/stale ─► section-level degraded view
  └─ context unavailable ─► explicit unavailable

Explicit foreground/scheduled trigger
  └─ RefreshVisibleSourcesJob（独立 Operations）
       └─ formal read ports ─► generation-matched local projection update
```

关键设计点：

- GUI、CLI 和 product entry 共用同一 Query/Command facade。
- 一个 section 可用不证明其他 section current；顶层无单一 success。
- Refresh generation 与 user selection generation 冲突时丢弃旧结果或标 stale。

### 8.8 Planned Consumer 通用处理流

```text
Owner event candidate
  │
  ▼
Contract readiness gate
  ├─ 当前 schema/client/source 未闭合 ─► blocked；不解析、不写 projection
  └─ 未来正式合同可验证
       │
       ▼
    Consumer
      - 校验 envelope/event id/source version/visibility
       │
       ▼
    Local transaction
      - dedup + order/gap check + apply owner-safe fact
      - gap/conflict => stale + RecoveryCase
       │
       ▼
    Applied / Duplicate / Stale-Reconcile
```

关键设计点：

- 当前四类 Consumer 均是 planned/blocked；未来分支不是 readiness 声明。
- Consumer 只承接 owner 已提交事实，不能以 last-arrival 覆盖 current。
- 当前无 Runner outbound event/outbox 处理流。

## 9. 状态定义与状态流转

> 校准来源：
> - [design-calibration/02_hld_step_09_state_machine.md](design-calibration/02_hld_step_09_state_machine.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“按组成部分状态集合”“允许/禁止迁移”和“跨轴状态传播关系图”。

### 9.1 状态轴总表

Runner 有多个正交状态机，不存在统一 `RunnerRun.status` 或单一 success。Owner request/execution/control/lease/cleanup/result 等只作为 projection axes，Runner 不决定其合法迁移。

| 组成部分 | 对象 / 状态轴 | 来源 | Runner 是否拥有迁移 | 正常主线门禁 |
|---|---|---|---:|---|
| Context/selection | `SelectionGeneration`、`ReleaseSelection.state` | local + authority basis | 是 | current generation 才能进入材料准备 |
| Material | `AcquisitionTask.state` | local job/control | 是 | complete 只进入验证 |
| Material | `IntegrityPosture.state`、`MaterialCacheEntry.state` | verifier + owner policy refs / local material | 是 | current verified + same binding 才 qualified |
| Material/resource | `ProtectionGuard.state` | owner refs 的保守本地评估 | 是（派生重算） | 仅 releasable 可进入释放 gate |
| Lifecycle | `RunIntent.state`、`ControlIntent.state` | local command + owner receipt/result | 是 | accepted/confirmed 只作用本轴 |
| Lifecycle | owner request/execution/control/result axes | Sandbox/Runtime safe source | 否，只投影 | running/terminal 必须由 current owner source 证明 |
| Resource/recovery | `ResourceObservation.posture` | local platform observation | 否，替换新观察 | available 非 allocated/leased |
| Resource/recovery | `RecoveryCase.state` | local recovery + owner reads | 是 | reconciled 后仍须重跑当前 command gate |
| Diagnosis/handoff | preview/diagnosis postures | derived safe sources | 否，替换新 projection | 不进入 run success |
| Diagnosis/handoff | `HandoffPosture.state` | local intent + owner receipt | 是 | delivered 也非 evidence |
| Entry/presentation | `ConnectivityView.state`、read-model sections | local observation/composition | 否 | online 不清除其他轴 stale/unknown |

### 9.2 Selection 状态定义与流转

| 状态 | 含义 | 是否可进入正常主线 | 说明 |
|---|---|---|---|
| `selected` | exact selection 已建立，authority 未证明 | 否 | 只能进入 checking |
| `checking` | 正读取/比较正式 authority | 否 | 禁止副作用 |
| `current` | authority current、visible 且 binding 一致 | 是，受限 | 只允许材料准备 |
| `stale` | 先前 basis freshness 不足 | 否 | 必须重验 |
| `invalidated` | 换选、撤销/过期或 context/source drift | 否 | 本 generation terminal |
| `blocked` | contract/visibility/conflict 使结论不可证明 | 否 | 新 basis 后才能 recheck |

```text
<no selection> ─ SelectRelease/create generation ─► selected
selected ─ authority check ─► checking
checking
  ├─ current + binding match ─► current
  ├─ contract/visibility/conflict ─► blocked
  └─ source/freshness drift ─► stale

current ─ refresh required ─► checking
current ─ change/revoke/expire/context drift ─► invalidated
stale|blocked ─ explicit recheck with new basis ─► checking
```

关键说明：

- `invalidated` 不回 current；换选创建 successor generation 和新 selection。
- 禁止 `selected -> current` 跳过 authority；cache/role/history/latest 均不能触发 current。
- Current selection 不等 material qualified 或 run allowed。

### 9.3 Material 状态定义与流转

| 状态轴 | 核心状态 | 正常主线口径 |
|---|---|---|
| Acquisition | absent/resolving/transferring/paused/complete/failed/cancelled | complete 只说明 transfer 并形成 quarantine handle |
| Integrity | pending/verifying/verified/invalid/stale/blocked | 只有 same-binding/current verified 参与 qualification |
| Cache | quarantined/qualified/stale/invalid/evicted | qualified 可提交 run；evicted 是 local material terminal |
| Protection | protected/releasable/blocked/unknown | independent axis；只有 releasable 可尝试 safe release |

```text
absent ─ request ─► resolving ─ locator ─► transferring
                                      ├─ pause ─► paused ─ valid resume ─► transferring
                                      ├─ failure ─► failed
                                      ├─ cancel ─► cancelled
                                      └─ complete ─► cache quarantined + integrity pending

integrity pending ─ verify ─► verifying
                               ├─ checks pass ─► verified
                               ├─ mismatch ─► invalid
                               └─ drift/missing ─► stale|blocked

verified + current authority + same binding ─► cache qualified
cache qualified ─ source/generation drift ─► cache stale
cache + ProtectionGuard releasable + safe release ─► cache evicted
```

关键说明：

- Transfer、integrity、qualification 和 protection/releasability 是四轴。
- 禁止 complete 直接 qualified，或 invalid/stale/blocked 不经新验证直接 verified。
- 任意 cache 状态在 guard 非 releasable 时都不能 evicted。

### 9.4 Run / Control / Owner lifecycle 状态定义与流转

| 状态轴 | 状态 | 边界 |
|---|---|---|
| RunIntent | draft/submitting/accepted/rejected/unknown/invalidated | accepted 仅 owner 接收；unknown 禁止 replay |
| ControlIntent | pending/accepted/confirmed/rejected/unknown/conflict | confirmed 仅本控制效果；stop 非 cleanup |
| Owner request | pending/accepted/rejected/unknown | Runner 只投影 |
| Owner execution | not_started/starting/running/stopping/terminal/unknown | 只有 formal current source 支撑 running/terminal |
| Projection quality | current/stale/partial/restricted/unavailable | 非 current 不授权新副作用 |

```text
RunIntent:
draft ─ submit ─► submitting
                    ├─ owner accepted ─► accepted
                    ├─ owner rejected ─► rejected
                    └─ ambiguous ─► unknown ─ read-only reconcile
active intent ─ binding invalidation ─► invalidated

ControlIntent:
pending
  ├─ owner accepted ─► accepted ─ effect result ─► confirmed
  ├─ owner rejected ─► rejected
  ├─ basis mismatch ─► conflict
  └─ ambiguous ─► unknown
unknown|conflict ─ read-only reconcile ─► owner-proven posture
```

关键说明：

- Reconcile 应用 owner 已有结果，不重新提交原副作用。
- 禁止 accepted 跨轴迁移到 running/terminal，或 confirmed stop 跨轴迁移到 cleaned/released。
- PID、port、socket、toast 和 local log 不能触发 owner execution 迁移。

### 9.5 Protection / Recovery / Connectivity 状态定义与流转

| 对象 | 状态 | 边界 |
|---|---|---|
| `ProtectionGuard` | protected/releasable/blocked/unknown | missing/stale/conflict 保守为 unknown；releasable 不是 release result |
| `RecoveryCase` | frozen/querying/reconciled/conflict/manual_review/closed | query-only；closed 非 run success |
| `ConnectivityView` | online/degraded/offline/reconnecting/reconciling/manual_review | local projection；online 非业务 current |

```text
ProtectionGuard:
unknown
  ├─ active protection ─► protected
  ├─ explicit owner block ─► blocked
  └─ all required release basis current ─► releasable
any state ─ basis stale/missing/conflict ─► unknown

RecoveryCase:
frozen ─ reconcile starts ─► querying
                              ├─ basis matches ─► reconciled ─ safe close ─► closed
                              ├─ mismatch ─► conflict ─ new read ─► querying
                              └─ cannot prove ─► manual_review

ConnectivityView:
online ─ partial/full loss ─► degraded|offline
offline|degraded ─ transport returns ─► reconnecting ─ read-only recovery ─► reconciling
reconciling ─ proven ─► online|degraded
reconciling ─ unproven ─► manual_review
```

关键说明：

- Guard 不能因 user click、disk pressure、stop ACK 或默认值进入 releasable。
- Recovery conflict/manual review 没有新 resolution basis 不能 closed。
- Connectivity change 不修改 selection/run/cleanup/handoff 状态或触发 replay。

### 9.6 Handoff 状态定义与流转

| 状态 | 含义 | 正常主线口径 |
|---|---|---|
| `draft` | safe material 已准备，未提交 | 受限，非 evidence |
| `pending` | 已提交，等待 owner | 结果未确认 |
| `accepted` | owner 接受交接 | 非 delivered/evidence |
| `delivered` | 正式 receipt 确认送达 | 非 verdict/signoff |
| `blocked` / `failed` / `unknown` | 无法交接 / 明确失败 / 结果不明 | unknown 只读 reconcile，不自动 resend |

```text
draft ─ submit ─► pending
                   ├─ owner accepted ─► accepted ─ delivery receipt ─► delivered
                   ├─ owner blocked ─► blocked
                   ├─ owner failure ─► failed
                   └─ ambiguous ─► unknown ─ read-only reconcile
```

关键说明：

- 禁止 draft/pending 在无正式 receipt 时直接 delivered。
- Accepted/delivered 不能迁移为 evidence/report/verdict/signoff；这些不是 Runner 状态。
- Preview/diagnosis visibility 不随 handoff 升级，redaction 不能被绕过。

### 9.7 跨轴状态传播关系图

```text
Selection/generation change
  ├─► IntegrityPosture stale + MaterialCacheEntry stale
  ├─► unsafe/unsubmitted RunIntent invalidated
  └─► ambiguous submitted intent ─► RecoveryCase frozen

Acquisition complete
  └─► cache quarantined + integrity pending
         └─ verified + current authority + same binding
              └─► cache qualified ─► permits RequestRun gate only

Owner request/control/execution result or gap
  ├─► OwnerRunProjection (owner-attributed axes only)
  └─ ambiguous/gap ─► RecoveryCase frozen/querying

Lease/capture/handoff/retention/orphan projections
  └─► ProtectionGuard re-evaluation
         └─ releasable ─► permits cleanup/release gate only

All local truth + safe projections + observations
  └─► RunnerReadModel sections（no write / no aggregate success）
```

关键说明：

- 箭头表示 local invalidation、derivation 或 gate 影响，不表示跨域反写或分布式事务。
- “Permits gate” 不表示动作已执行或结果成功；Command 仍重验 current basis。
- 当前没有 Runner outbound event/outbox propagation。
- Gap/mismatch/ambiguous 一律传播为 stale/unknown/recovery，不乐观成功。

## 10. 异常与边界场景轮廓

> 校准来源：
> - [design-calibration/02_hld_step_10_exceptions_boundaries.md](design-calibration/02_hld_step_10_exceptions_boundaries.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“按组成部分异常与边界”“横切 crash window”和“异常到对象/接口/状态承接审计”。

本章只列会改变处理流、状态机或跨部分协作的异常；普通字段校验、完整 error code、retry/backoff 数值、补偿脚本和运维步骤留给 03～05。

### 10.1 异常与边界场景表

| 场景 | 应落在哪个部分处理 | 当前概要口径 |
|---|---|---|
| Context 缺失/过期/restricted | Context resolver + selection | Command blocked；已有 ambiguous operation 进入 recovery，不猜身份/权限 |
| `latest`、default branch、directory newest、mutable tag | Inbound + `ReleaseSelection` | 明确拒绝，不从 history/cache 解析 exact ref |
| Authority 缺失、过期、撤销、scope conflict 或 owner unavailable | Selection/authority boundary | blocked/stale/invalidated；不得 acquire/run，不本地批准 |
| Authority check 与 local selection commit 之间 source version 漂移 | Selection expected-version gate | 丢弃旧结果，不提交 current |
| Generation 在 acquire/verify/run 建立期间变化 | Selection propagation + downstream services | 旧 integrity/cache/intent 失效；已可能提交者进入 recovery |
| Locator/manifest 不可见、过期或 constraint 不可解释 | Material source + acquisition | failed/blocked/quarantine；不保存 secret locator |
| Download 中断、应用退出或网络切换 | `AcquisitionTask` + Job | paused/failed/unknown；resume 前重验 binding/authority |
| Provider 声称 complete 但无稳定 quarantine handle | Cache boundary | 不进入 complete/quarantined，按 failure/unknown 收束 |
| Cancel 与 transfer completion 竞态 | Acquisition/cancellation boundary | 不晋级；残留仅进受保护 quarantine/safe cleanup |
| Digest/signature/platform/source mismatch | Verifier + `IntegrityPosture` | invalid；禁止改名、重打包、宽松算法或 local override |
| Verification 后 authority/manifest/digest/generation 漂移 | Integrity/cache propagation | stale；禁止 RequestRun，必须新 basis 重验 |
| Cache metadata 存在但 bytes 缺失/损坏 | Cache + qualification | stale/invalid；metadata 不证明 qualified |
| Disk pressure/capacity exceeded | Eviction evaluation + guard | 只生成 candidate；active/unknown protection 优先 |
| Request binding 不一致 | Lifecycle service/domain assertions | 本地拒绝，不创建可提交 intent，不调用 owner |
| Intent 已落盘、外部 call 前崩溃 | Operation boundary + recovery | 只有可证明 not-sent 才允许新的显式提交；否则 reconcile |
| Owner 可能已接收、timeout/断线或 receipt 落盘前崩溃 | Intent + `RecoveryCase` | unknown；按 correlation/idempotency 只读查询，禁止 replay |
| Same idempotency key 对应不同 binding/payload | Command metadata + store/owner port | explicit conflict；旧 receipt 不复用给新 operation |
| Control expected basis conflict | Control + owner projection | conflict/frozen；读取 current owner state，不强制覆盖 |
| ACK 到达但效果未确认 | Intent/control projection | accepted 与 confirmed/running 分开 |
| Sandbox/Runtime safe views 矛盾或 event/query 不同版本 | Owner projection + recovery | conflict/unknown/stale，保留来源；不选更乐观一方 |
| PID/port/socket/toast/local log 与 owner state 不同 | Resource/diagnosis + lifecycle view | 显示 observation conflict，不改变 owner state |
| Local probe 与 owner allocation/lease 冲突 | Resource recovery | 双视图显式 conflict，以 owner qualification 为准；不抢占 |
| Platform probe unsupported/permission denied/stale | Platform port + observation | unknown/unavailable；安全前置 fail-closed |
| Cleanup 前任一 protection active/missing/stale/conflict | `ProtectionGuard` + cleanup | protected/blocked/unknown；不调用清理、不删除 |
| Cleanup accepted 未 confirmed 或 result ambiguous | Cleanup intent + recovery | pending/unknown；不标 released，不重复 cleanup |
| Cleanup confirmed 但 local material 仍受保护 | Cleanup/material guard | Owner resource result 与 local release 分离，继续保护 |
| Disconnect/suspend/restart/session expiry/lease change | Connectivity + recovery | 冻结受影响副作用，重验 context/generation/lease/status |
| Reconnect 但 source stale，或 recovery reads 部分 unavailable | Refresh/Reconcile | reconciling/partial；不能用 online/多数来源推收敛 |
| Manual review 无新 formal basis | Recovery/manual-review | 继续冻结/保护；manual review 不是 override/signoff |
| State store unavailable/write conflict/corruption | Store port + application services | 无法原子保存 intent/basis 时禁止新副作用；可能已发者 recovery |
| Clock jump/suspend 使 freshness 不可信 | Clock/connectivity + affected objects | stale/unknown；重读 owner，不乐观延长 |
| Diagnostic source restricted/partial/stale/unavailable | Preview/diagnosis | 对应安全 posture；不 raw-log/empty-success fallback |
| Redaction policy 缺失、失败或结果不可验证 | Redaction + preview/handoff gate | blocked/restricted；不显示/发送未脱敏材料 |
| Handoff material stale/visibility changed 或 owner unavailable | Handoff service/port | re-prepare 或 blocked；不复用旧材料 |
| Handoff result ambiguous/receipt gap | Handoff + recovery | unknown/query reconcile；不 resend，不解除保护 |
| Read-model 某 section not-ready/stale | Read-model composer | section-level degraded；其余可读，无 aggregate success |
| Query/render 遇到 stale projection | Presenter/query service | 只显示 stale，不在 render 内 refresh/repair/write |
| Refresh 与 user selection 并发 | Refresh generation gate | 丢弃旧结果或标 stale，不覆盖新 generation |
| SDK/adapter 返回 unknown schema 或 HTTP success 缺语义字段 | Adapter readiness/normalization | malformed/unknown/blocked，不提升为 current/accepted/running |

### 10.2 异常影响图

```text
正常主线候选
  context -> explicit selection -> authority current
          -> acquire -> quarantine -> verify -> qualified
          -> run/control intent -> owner projection
          -> cleanup/protection -> preview/diagnosis/handoff
  │
  ├─ binding/source/authority drift
  │     └─► stale/invalidated/blocked ─► 禁止后续副作用
  │
  ├─ external side effect ambiguous / crash window
  │     └─► unknown ─► RecoveryCase frozen ─► read-only reconcile
  │                                      ├─ proven ─► re-run current gate
  │                                      └─ unproven ─► manual_review
  │
  ├─ active or unknown protection
  │     └─► protected/blocked ─► 禁止 cleanup/material release
  │
  └─ visibility/redaction/source gap
        └─► partial/restricted/unavailable ─► 不用 raw/local/default 补齐
```

关键说明：

- 图表达四类会改变主线的异常出口，不表达 error code、retry 参数、补偿脚本或操作手册。
- “Re-run current gate” 是重新校验当前前置，不是 replay 原副作用。
- Fail-closed 同时约束 authority、材料、owner side effects、保护和敏感展示。
- 异常只改变 Runner local state/view，不修改上游 truth。

## 11. 配置影响轮廓

> 校准来源：
> - [design-calibration/02_hld_step_11_configuration_impact.md](design-calibration/02_hld_step_11_configuration_impact.md)
>
> 延伸阅读：建议继续阅读上述中间产物的“直接与间接配置消费边界”“禁止配置化边界”和“03/04 配置承接”。

### 11.1 配置影响轮廓表

| 主要部分 / 接缝 | 是否受配置影响 | 配置影响类型 | 交给详细设计展开 |
|---|---|---|---|
| Composition root/runtime builder | 是 | source/profile/provider/startup validation | typed config grouping、loader/validator、immutable snapshot、builder injection |
| GUI/CLI/product adapters | 间接 | profile/display capability/locale/feature exposure | validated presentation policy；共同 facade 注入 |
| Application services | 间接 | bounded policy/operation budget/port capability | 只接 typed policy/ports；不读 raw config |
| Context/authority/material/Sandbox/Runtime/diagnostic/archive adapters | 是 | endpoint/SDK profile/timeout/capability/secret ref | per-adapter config、client factory、readiness/error normalization |
| Material transfer/cache/store/verifier | 是 | provider/store root/capacity/concurrency/checkpoint/trust ref | provider factory、path/capacity validation、atomic capability、owner-policy validation |
| Platform/clock/connectivity/redaction adapters | 是 | provider/capability/probe/read budget/policy ref | OS capability、monotonic/freshness、mandatory redaction validation |
| Acquire/Eviction/Reconcile/Diagnosis/Refresh Jobs | 是 | schedule/trigger/batch/concurrency/read budget/cancellation | `JobConfig`、claim/checkpoint、bounded execution；语义出口固定 |
| ProtectionGuard、domain objects/state machines | 否或仅接正式 inputs | 不适用 / owner-derived policy inputs | 不读配置；missing→unknown、transition/invariant 固定 |
| Presentation/read-model | 间接 | clipping/display/poll presentation policy | typed presenter policy；render no side effect |
| Telemetry/local operational logging | 是 | sink/sampling/bounded fields/retention/redaction ref | safe telemetry config；与 audit/evidence 分离 |
| Planned Consumers | 是但当前 blocked | formal seam enablement/subscription/dedup capacity | 合同闭合后才定义；禁止 generic topic/group |
| Runner outbound events | 不适用 | 不适用 | 当前不能由 feature flag/config 创建 |

### 11.2 禁止配置化边界

| 禁止配置化边界 | 原因 | 若需改变应回到哪里 |
|---|---|---|
| Implicit `latest`/default/newest、跳过 context/authority | 破坏 explicit selection、ownership 和 traceability | 00/01 与 §3、§6、§9 |
| Local authority/approval override、修改 Release | 把配置变成 Artifact/Governance owner | 相邻 owner 合同与 00/01 |
| 跳过 integrity/platform/source binding 或本地选择宽松 policy | 未验证材料进入 run | §3、§6、§8～§10 |
| 合并 complete/verified/qualified/accepted/running/cleanup/evicted | 破坏多轴安全语义 | §6、§9；需重开概要 |
| ACK/PID/port/log -> success；unknown -> success/replay | 错误升级或重复 side effect | §8～§10 |
| 关闭 generation/source/digest/lease expected-basis checks | 破坏 local/owner consistency | §6～§10 与 03 transaction design |
| Query/render/reconnect 写入或隐式 refresh | 破坏 no-write 和 recovery boundary | §7～§10 |
| 绕过 ProtectionGuard 或 disk-pressure override | 可能误删 active/unknown material | §6、§9～§10 |
| 关闭 redaction/bound/source/freshness/visibility | 可能泄露 raw body/secret 或伪造完整信息 | §3、§6～§10 |
| Local log/diagnosis/receipt -> audit/evidence/verdict/signoff | Evidence owner 不在 Runner | Observability contract + 00/01 |
| 直连 sibling DB/source/private Sandbox backend/L0-bus topic | 绕过 SDK/public boundary | 全局依赖规则、01 §8 |
| Config 新增 outbound event 或关闭 intent/basis atomic save | 无消费者合同 / 扩大 crash risk | 回退 00～02 / 03 transaction design |
| Unsafe/incompatible config 采用弱默认 | 违反 fail-closed | 03 ConfigValidator/ConfigError |

### 11.3 配置影响轮廓图

```text
Config sources + secret references
              │
              ▼
ConfigLoader / ConfigValidator
  - immutable validated snapshot
  - incompatible/missing/unsafe => fail-fast or blocked
              │
              ▼
Composition root / runtime builder
  ├─► Entry / presentation adapters
  ├─► Owner / platform / redaction adapters
  ├─► State store / material cache providers
  └─► Operations jobs and bounded resource policies
              │
              ▼
Application services receive typed ports/policies only
              │
              ▼
Domain objects / state machines / guards
  - no raw configuration access
  - invariants and ownership fixed
```

关键说明：

- 图不选择配置格式、加载库、密钥系统、部署挂载或 hot reload。
- Domain 不直接读配置；可调预算先成为 validated typed policy。
- Provider 可替换不允许直连私有实现，且不代表 owner adapter ready。
- 03 定义实现契约；04 才定义正式 key、值、来源、示例和变更说明。

## 12. 详细设计承接清单

> 校准来源：
> - [design-calibration/02_hld_step_12_detailed_design_handoff.md](design-calibration/02_hld_step_12_detailed_design_handoff.md)

### 13.1 设计风险

| 风险 | 影响 | 当前处理口径 |
|---|---|---|
| Artifact/Governance contract 未闭合（`RUN-UP-001/002`） | Selection、authority、acquire/verify/qualification/request gate | Required ports + blocked/stale/invalidated；不本地批准/自选 policy |
| Sandbox/Runtime contract 未闭合（`RUN-UP-003/004/007`） | Run/control/execution/cleanup/recovery | Intent + owner projection + unknown/reconcile；不接 private backend，不声明正向集成 |
| Observability contract 未闭合（`RUN-UP-005`） | Preview/diagnosis/handoff/retention protection | Bounded/redacted local negative closure；blocked handoff；receipt 非 evidence |
| SDK exact surface 未核验（`RUN-UP-008`） | All adapters/errors/metadata/trace/consumer readiness | Required semantic ports；03 核验真实 SDK，再 adapter mapping |
| Multi-owner eventual consistency/event-query gap | Owner projections、Refresh/Reconcile、read model | Source/version/freshness/visibility；gap→stale/reconcile，不 last-arrival-wins |
| External side effect / local transaction crash windows | Run/control/cleanup/handoff operations | Persist intent/basis first；ambiguous=unknown；query-first/no replay |
| Bytes/metadata/integrity/protection/release 跨承载 | Acquisition/cache/store/guard/recovery | Quarantine-first、binding recheck、missing protection→unknown、safe release 后 evicted |
| Cross-platform observations 可被误作 owner resource truth | Platform/resource/cleanup UX | Local/owner dual view；unsupported/permission/freshness→unknown；不抢占 |
| Store/clock/connectivity failures | Intent atomicity、freshness、recovery | Fail-before-side-effect；clock drift→stale；reconnect only starts reconcile |
| 多轴状态实现/UX 复杂，易回退 single status | Objects/state/pages/acceptance | Typed axes、source attribution、transition tests；合并必须回退概要 |
| Config/provider flexibility 绕门禁 | Composition/adapters/jobs/store | Domain no raw config；security/ownership/state/transaction invariants non-configurable |
| Local diagnosis/telemetry 被升级为 evidence | Logging/diagnosis/handoff/acceptance | Explicit non-authoritative types/wording；no raw body/no formal verdict |
| Planned Consumers 被误认为 ready | Event adapters/dedup/gap store | 全部 planned/blocked；无 formal seam 时 query/reconcile |

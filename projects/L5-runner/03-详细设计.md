### 5.1 七个逻辑模块总表

| 模块 | 主要责任 | 对外暴露 | 允许依赖 | 禁止依赖/行为 |
|---|---|---|---|---|
| `contracts` | typed ref/state/reason、Command/Query/Consumer/Job DTO、view、receipt、safe error | public semantic types | core semantic primitives | 不依赖 domain/application/infra；不保存 owner 正文/secret |
| `domain` | Runner-local truth、binding、不变量、guard、RecoveryCase、纯 transition | object/policy/domain error | `contracts` | 不读 store/SDK/OS/Sandbox/owner truth |
| `application` | use-case 编排、门禁、UoW、幂等、外部副作用顺序 | facade、port trait、application error | `contracts`、`domain` | 不依赖具体 infra；不由 UI 直接改 truth |
| `infra` | local repository/cache/projection、SDK/API/platform/redaction adapter、composition | port implementations、availability markers | contracts/domain/application | 不绕过 application；不暴露私有 owner 实现 |
| `entry` | GUI/CLI/product inbound、request validation、presentation mapping | command/query dispatch surface | contracts/application | 不直连 repository/store/adapter/domain transition |
| `worker` | planned inbound consumer、header-first readiness、receipt/disposition | consumer dispatch surface | contracts/application | 不解析未授权 payload；不写 owner cursor/直接 store |
| `operations` | 五个显式 Job、claim/checkpoint/report、refresh/reconcile | job dispatch/report surface | contracts/application | Query 不隐式 refresh；unknown 不自动 replay/reclaim |

依赖方向固定为：

```text
core semantic primitives
          | use
          v
      contracts
          v
       domain
          v
     application ---- defines ----> semantic ports
          v                              ^
        infra -------- implements -------+
       ^  ^  ^
       |  |  |
     entry worker operations
```

关键说明：该图是逻辑依赖图，不是 crate、进程或部署图；`ports` 不是第八个模块；entry/worker/operations 不互相调用，不直接访问 store 或 adapter。

### 5.2 `contracts` 模块

| capability | 输入/输出 | 状态/副作用 | 后续承接 |
|---|---|---|---|
| shared identity | opaque local id、owner ref、scope、generation | 无副作用 | Step 6 object carriers |
| public protocol | actor、metadata、request、result、view、receipt | schema validation only | Step 8/9 |
| safe surface | visibility、freshness、degraded、issue、source attribution | body 可为空；不写 store | Step 8 Query |

contracts 不拥有 Release、Approval、SandboxLease、RuntimeExecution、Evidence、raw log 或 secret；`latest/default/newest/tag/branch` 不可在 DTO 中表达。

### 5.3 `domain` 模块

domain 拥有 `ReleaseSelection`、`AcquisitionTask`、`MaterialCacheEntry`、`IntegrityPosture`、`RunIntent`、`ControlIntent`、`OwnerRunProjection`、`ResourceObservation`、`ProtectionGuard`、`RecoveryCase`、`OutputPreview`、`FailureDiagnosis`、`HandoffPosture`、`RunnerReadModel`、`ConnectivityView` 及其状态/原因 carrier。每个 transition 只改自身字段；external I/O、trace/audit/result/projection 写入由 application 编排。

### 5.4 `application` 模块

应用服务组：`SelectionService`、`AcquisitionService`、`QualificationService`、`RunLifecycleService`、`ControlService`、`ResourceRecoveryService`、`PreviewService`、`DiagnosisService`、`HandoffService`、`RunnerReadModelComposer`、`ConnectivityService`。所有写入口统一执行：trusted metadata 校验 → canonical digest → idempotency reservation → versioned load → domain transition → external call（若有）→ local commit/result/recovery。Query 永远 no-write。

### 5.5 `infra`、`entry`、`worker`、`operations`

- `infra` 只实现 semantic port；HTTP status、ACK、PID、端口、文件路径和 adapter availability 不能直接构造业务 truth。
- `entry` 只验证 actor/scope/metadata/DTO，并把请求交给 application facade；presenter 只能展示 committed safe sections。
- `worker` 当前只允许 header-first 的 `Blocked`/`Unsupported`/`Rejected` 或严格 stored `Duplicate`；不解析 payload、不计算 payload hash、不 ACK。
- `operations` 的 Job report 是本地技术/运营 surface；不把 Completed/Partial/Blocked/Failed 映射为 approved/running/cleaned/evidence。

### 5.6 模块测试切口

| 模块 | 最小切口 |
|---|---|
| contracts | required field、显式 selector、metadata、view/page、safe error、禁止 `latest` |
| domain | factory、合法/非法 transition、binding/generation、guard fail-closed、RecoveryCase |
| application | reservation/UoW 顺序、duplicate zero-side-effect、Query no-write、external unknown |
| infra | fake/durable semantic parity、adapter blocked/readiness、version conflict、redaction |
| entry | route/body/name mismatch、actor/scope、presentation no-write |
| worker | header-only negative path、strict duplicate receipt、gap/unsupported disposition |
| operations | claim/checkpoint/report、duplicate replay、no owner repair、generation guard |

### 5.7 第 5 章收口摘要

第 5 章只固定逻辑模块与职责，不把逻辑模块误写成已存在的 crate/package。对象字段级契约见 Step 6，port/adapter 函数签名见 Step 7；任何 exact SDK、store 或 physical path 仍受 §3/§4 blocker 约束。

## 7. API / Command / Query / Event / Job 协议契约

> 校准来源：
> - `design-calibration/03_ddd_step_08_protocol_contracts.md`
>
> 延伸阅读：
> - Step 8 §6 的 metadata/page/result/error helper，§7～§8 的每个 Command/Query schema，§9 的 Consumer negative surface，§10 的 outbound no-residue audit，§11 的 Job schema。

### 7.1 通用协议纪律

- Command、Consumer、Job 使用 trusted actor/trace/metadata；Query 使用无写 metadata。body 不得自报 actor、scope、trace、idempotency 或 transport route。
- 所有 Command/Job/Consumer 都必须有稳定 operation identity、canonical request digest 和 duplicate surface；Query 禁止 reservation。
- request schema 只表达 exact immutable `ReleaseRef + ArtifactVersionRef + scope + generation`；不允许 `latest/default/newest/tag/branch`。
- Query response 必须包含 `RunnerViewSurface`（read subject、projection ref/generation、visibility、freshness、degraded、source attribution）；restricted/unknown 可 body-free 返回。
- `Accepted != Running`、`Confirmed != Cleaned`、`Complete != Verified != Qualified`、local receipt/report != evidence/verdict/signoff。

## 8. 逐接口函数级处理流

> 校准来源：
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读：
> - Step 9 §6～§12 的通用模板，以及 §13～§20 的 11 Command、12 Query、4 Consumer、0 outbound、5 Job 逐条 flow；Step 9 §21 的跨 flow 审计。

### 8.1 通用 Command 写路径

```text
[trusted entry validate actor/scope/metadata/body]
        |
        v
[canonical digest + idempotency reserve]
        |
        v
[versioned local read + domain transition + local tx A]
        |
        +--> [no external I/O] --> [local result + trace/marker + tx commit]
        |
        +--> [one external read/effect outside UoW]
                                  |
                         explicit / ambiguous
                                  v
                     [typed outcome / readback RecoveryCase]
                                  |
                                  v
                [stored safe result first, then idempotency complete]
```

入口校验失败不 reserve、不访问 repository；duplicate 只 replay exact stored result；same key/different digest 返回 Conflict；commit unknown 不重跑。

### 8.2 Command flow summary（C01～C11）

| Flow | 函数级主链 | 关键状态/副作用 |
|---|---|---|
| C01 SelectRelease | `RunnerEntryDispatchPort.dispatch_command` → `SelectionService.select_release` → `ContextReadPort.resolve_context` → `ReleaseSelection::select` → `ReleaseAuthorityReadPort.assess_exact_release` → stored result | Selected→Checking→Current/Blocked/Stale；exact generation |
| C02 InvalidateSelection | load versioned selection → successor generation → `ReleaseSelection::invalidate` → bounded local freeze | selection fence 先提交；partial propagation→RecoveryCase |
| C03 RequestMaterialAcquisition | load selection → revalidate authority → `AcquisitionTask::start` → source readiness/locator | 只建立 task；不下载/验证 |
| C04 PauseAcquisition | load task → binding check → `AcquisitionTask::pause` → save | Query/worker signal不替代 checkpoint |
| C05 ResumeAcquisition | load task → re-read authority/source/binding → `AcquisitionTask::resume` | stale/unknown blocked；不第二条 transfer |
| C06 CancelAcquisition | load task → `AcquisitionTask::cancel` | Cancelled 不等 bytes released/evicted |
| C07 RequestRun | load context/selection/cache/integrity/guard → `RunIntent::create/mark_submitting` → `SandboxRunPort.request_run` | Accepted 只 request axis；ambiguous→Unknown+RecoveryCase |
| C08 RequestRunControl | read owner basis → `ControlIntent::request` → Sandbox control | Accepted/Confirmed 只当前 control kind |
| C09 RequestCleanup | re-read protections → `ProtectionGuard::evaluate` → Sandbox cleanup → guarded cache release | Confirmed cleanup 不等 local release；guard unknown fail-closed |
| C10 OpenManualReview | load RecoveryCase/version → `require_manual_review` → save/result | manual review 不是 override/close/replay |
| C11 RequestDiagnosticHandoff | load diagnosis → redaction validation → `HandoffPosture::prepare` → Observability handoff | receipt/delivered 非 evidence；unknown 不 resend |

### 8.3 Query flow summary（Q01～Q12）

每个 Query 都执行：trusted metadata/body validation → canonical read subject/visibility resolution → committed repository/read-section loads → section/page/view assembly → `RunnerViewSurface` 返回。Query 不开启写 UoW、不 reserve/save/refresh/reconcile/probe/cleanup/dispatch job。

| Flow family | Query |
|---|---|
| context/selection/material | Q01 `ResolveRunnerContext`；Q02 `ListSelectableReleases`；Q03 `GetSelectionPosture`；Q04 `GetMaterialPreparation`；Q05 `GetCacheProtection` |
| lifecycle/resource/recovery | Q06 `GetRunLifecycle`；Q07 `GetResourceCleanupView`；Q08 `GetRecoveryCase` |
| preview/diagnosis/handoff/read model | Q09 `GetOutputPreview`；Q10 `GetFailureDiagnosis`；Q11 `GetHandoffPosture`；Q12 `GetRunnerReadModel` |

详细字段来源、empty/not-visible/degraded surface、函数签名和每条 flow 的错误/测试切口见 Step 9 §15～§17。

### 8.4 Consumer flow summary（E01～E04）

```text
[inspect trusted header/source/schema/readiness]
        | blocked/unsupported/rejected
        v
[body-free receipt, no ACK, no payload parse/hash/store]
        |
        +--> [strict stored Duplicate replay only]
```

四个 Consumer 均当前 blocked；不得把消息到达、ACK 或 header 当运行成功、cleanup/evidence 或 owner cursor。

### 8.5 Job flow summary（J01～J05）

| Job | 主链 | 关键一致性 |
|---|---|---|
| J01 | claim → task/source/verify/cache bounded stages → checkpoint/report | transfer/verified/qualified 分轴 |
| J02 | bounded candidate page → re-read guard/protection → candidate report | 不执行 delete/release |
| J03 | claim → formal read-only owner/local reads → RecoveryCase reconcile/projection | 不 mutation、不 resend/reclaim |
| J04 | diagnostic bounded read → redaction → preview/diagnosis | raw body 不落库 |
| J05 | explicit source reads → subject/scope/generation/version guard → replace existing section | missing identity 不 upsert；旧 generation 丢弃 |

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - `design-calibration/03_ddd_step_11_persistence_consistency.md`
>
> 延伸阅读：
> - Step 11 §5～§12 的 ownership/store/repository/UoW/transaction/consistency/failure 表；Step 13 的 result/idempotency consistency 规则。

### 10.1 Logical store 与所有权

| logical store/record | 用途 | owner | 核心版本/唯一性 |
|---|---|---|---|
| context/selection/generation | explicit local selection | domain | exact id；`runner_version` + generation |
| acquisition/integrity/cache | transfer/qualification/cache metadata | domain | binding/index；expected version |
| run/control/projection | local intent + attributed owner safe projection | domain | intent version；projection source version/generation |
| resource/guard/recovery | observation/protection/freeze | domain | subject + version |
| preview/diagnosis/handoff | bounded safe presentation | domain | canonical subject set + version |
| read sections/connectivity | committed safe composition | entry/domain/infra | existing identity + generation/version |
| idempotency/stored results | duplicate/replay surface | application | key+operation+digest unique；result immutable |
| jobs/claims/checkpoints/reports | local operations technical state | operations | job/claim/checkpoint refs + version |
| consumer receipts/adapter markers | negative receipt/readiness | worker/infra | trusted dedup/header identity；immutable receipt |

不得保存 Release bytes、raw payload、raw log、credential、owner cursor、Sandbox private state、formal evidence/report/verdict/signoff body。

### 10.2 Repository/UoW 规则

- existing mutable object 使用 `Option<Versioned<T>>` 和 exact `RunnerExpectedVersion`；新 identity 才允许 `Absent`。
- `get`/`find`/`list(page)` 只读；`save(value, expected, uow)` 负责 optimistic version；`append` 为 immutable receipt/history；projection replacement 必须带既有 identity、generation 和 expected version。
- `RunnerUnitOfWork` 只覆盖 Runner-owned local store；external read/effect 永远在 UoW 外。
- Command/Job/Consumer 的 result/receipt/report surface 必须先保存，再标记 idempotency `Completed`；Completed 但 surface 缺失为 `Unknown + RecoveryCase`，不得重跑。
- Query 不 reserve、不开写 UoW、不刷新、不修复、不 reconcile、不 probe、不 cleanup、不 dispatch job。

### 10.3 External I/O 与事务顺序

```text
[validate + reserve] -> [local tx A: intent/basis] -> [one external call]
       -> [explicit outcome: local tx B]
       -> [ambiguous outcome: readback/recovery tx, no resend]
       -> [stored safe surface] -> [idempotency complete]
```

`C01/C02` 的 selection fence、`C07` 的 run intent tx A/B、`C08/C09` 的 control/cleanup intent、`J01/J02/J03/J04/J05` 的 claim/checkpoint/report/section replacement 均遵循 Step 11 表格。精确 backend、lock、migration、corruption repair 未选择。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读：
> - Step 12 的错误分层、public mapping、异常分支、recovery、dead-letter/delayed/rejected 和反模式表。

### 11.1 错误分层

| 层 | 典型内容 | public 处理 |
|---|---|---|
| domain | invalid transition、binding mismatch、guard fail-closed | typed rejected/conflict/blocked |
| application | idempotency conflict、version conflict、UoW/contract violation | `Conflict`/`Blocked` 或安全 application error |
| port/infra | unavailable、unsupported、timeout、corruption、serialization | typed blocked/unknown/degraded；不按字符串猜 |
| entry/protocol | missing metadata、name/body mismatch、forbidden selector | body-free rejected |
| worker | unsupported schema、header invalid、gap、duplicate receipt | negative disposition/recovery |
| job | claim/checkpoint/report failure、partial、unknown | local report；不升级业务 truth |

### 11.2 Unknown 与恢复

Unknown 覆盖 external effect ambiguity、commit status unknown、stored result missing、claim/checkpoint ambiguity、source/event gap 和 visibility/transport 不明。每个 Unknown 必须保留 typed issue、expected basis、subject refs 和 `RecoveryCase`；唯一允许的后续是 explicit read-only reconcile/manual review。禁止自动 replay、resend、reclaim、resume、cleanup 或 release。

### 11.3 Consumer 与 dead-letter 边界

当前 Consumer 只允许 header-first `Blocked/Unsupported/Rejected/Quarantined` 和 strict stored `Duplicate`；不得解析/保存 payload。未来 delayed/quarantined/dead-letter 只有在正式 transport/isolation contract 闭合后重开 Step 8/9。DLQ、telemetry backend、diagnostic store 未选定，不在本文伪造。

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：
> - Step 13 的 key/digest matrix、并发场景、duplicate/in-flight/conflict、commit-unknown、projection/outbox/reference/handoff 规则。

### 12.1 幂等键和 digest

| 操作 | identity | canonical digest | duplicate surface |
|---|---|---|---|
| Command | trusted command idempotency key | operation + stable result-affecting fields；排除 time/trace/request/random/raw body | exact stored command result |
| Consumer | trusted header dedup identity + consumer namespace | 仅在正式 payload contract ready 后扩展；当前不得计算 payload hash | stored receipt only |
| Job | job key + job kind + stable input/basis | scope/binding/page/generation/basis | exact stored job report |
| Query | none | read subject/visibility 只用于读取 | no replay record |

### 12.2 Concurrent collision / re-entry

| 场景 | 处理 |
|---|---|
| same key/same digest | replay exact result；零 domain/owner/job 副作用 |
| same key/different digest | Conflict；不得覆盖旧 record |
| Reserved/in-flight | 返回 typed InProgress/Unknown；不第二次执行 |
| expected version/generation mismatch | Conflict/Blocked；重读后由显式新 operation 决定 |
| external call/terminal commit unknown | RecoveryCase + readback；不重发 |
| Query/render/reconnect 并发 | no-write；只读 committed section |
| J05 projection replacement race | generation/version guard；冲突丢弃或 degraded，不 upsert missing identity |
| unknown Job claim/checkpoint | freeze + recovery；不自动 reclaim/resume |

### 14.2 Flow 观测闭环

11 Command 必须能关联 entry、validation、reservation、local transition、result/recovery；12 Query 只记录 read/visibility/freshness；4 Consumer 记录 header/readiness/disposition；5 Job 记录 entry/claim/checkpoint/report；J05 记录 generation/version conflict；diagnosis/handoff 记录 redaction 和安全 refs。Rejected/duplicate/blocked 不写 accepted business trace，不产生 outbound event。

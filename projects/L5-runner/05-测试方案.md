### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 runner“能显示一个 run 列表”,而是系统验证 `L5-runner` 是否真正满足“面向任务与执行入口的运行承载产品层 / runner experience 层”的设计要求,尤其要证明以下几点成立:
- RunnerRun / RunQueueEntry / RunnerRunState / RunControlEntry / RunOutputPreview / RunHealthHint 构成正式 runner 体验层真相
- `RunnerRun ≠ Runtime execution truth`、`RunControlEntry ≠ control success truth`、`RunOutputPreview ≠ Artifact truth`、`RunHealthHint ≠ Observability truth`、`VisibleCapabilityState ≠ capability contract truth` 等核心边界成立
- run entry / queue / state / output / hint 五条产品主线可以统一组织,并且 source refs 持续可追溯
- retry/replay/cancel/kill 等控制入口只表达用户动作意图,不会误导用户认为动作已成功完成
- output preview / artifact result / evidence refs 只消费 source 结果,不反写真相
- queue wait、capability unavailable、quota/deny、health degraded 等非 happy path 提示有统一解释层,让用户理解下一步动作

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 运行入口与运行单元部分 | run entry 对象 | P0 | RunnerRun、RunQueueEntry、RunCard、ExecutionTargetSummary、VisibleRunIdentity |
| 运行状态与执行进度呈现部分 | run state UX 对象 | P0 | RunnerRunState、RunPhase、ProgressSegment、StreamExcerpt、ResourceUsageBadge |
| 控制动作与恢复交互部分 | control UX 对象 | P0 | RunControlEntry、RetryIntent、ReplayIntent、CancelIntent、KillIntent、ContinueIntent |
| 结果、产物与上下文消费部分 | result/context UX 对象 | P0 | RunOutputPreview、ArtifactResultCard、FileRefCard、ExecutionSummaryCard、EvidenceRefCard |
| 状态提示、能力提示与运行辅助部分 | hint/assist UX 对象 | P0 | RunHealthHint、VisibleCapabilityState、QueueWaitHint、QuotaHint、NextStepSuggestion |
| runtime / sandbox / artifact / observability / capability-hub 真相本体 | 非范围 | P2 | 只验 runner 如何消费其结果并组织运行产品体验,不验 source truth 全部实现 |
| scheduler / host runtime / analytics 本体 | 非范围 | P2 | 只验 runner 的入口、可见状态和交互逻辑,不验底层执行系统实现 |
| source control 真正执行成功 | 非范围 | P2 | 只验 control entry 与提示链,不验下游 control 完整实现 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / product owner | `input.validate_runner_run_boundary`、`input.validate_run_state_source_boundary`、`entry.validate_control_entry_boundary`、`input.validate_output_source_boundary`、`input.validate_hint_source_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + projection + render + publisher 联动 | backend / product owner | `CreateRun`、`BuildRunStateView`、`BuildStreamExcerpts`、`TriggerRetry`、`BuildRunOutputPreview`、`BuildRunHealthHint` | run、state、control、result、hint 五条主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | runtime → run/state、sandbox → stream/output、artifact/archive → result cards、observability/hub → hints、control → source dispatch | 输入输出语义一致 |
| 恢复专项测试 | 验证 state mismatch、stream 断裂、action pending、preview stale、hint/source 冲突等异常链 | architecture / QA | queue drift、dispatch fail、preview stale、capability deny、hint conflict | 体验不误导、错误被正确阻断或标记 |
| 投影一致性测试 | 验证 run list/detail/output/hint 视图与 source refs 一致 | backend / QA | run list rebuild、state view rebuild、output preview rebuild、hint view rebuild | 投影只读且与 source refs 一致 |
| 端到端主线测试 | 验证最小统一运行体验闭环 | QA / owner | create run → queued/running → output preview → hint → control entry | runner 体验闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `RunnerRun ≠ Runtime execution truth` | RunnerRun 只承载产品层 run 体验,不替代 runtime 真相 | 单元 + 集成测试 | 是 | run/source compare |
| `RunControlEntry ≠ control success truth` | control entry 只表达入口,不代表 source 控制动作已完成 | 单元 + 事件链测试 | 是 | action/result compare |
| `RunOutputPreview ≠ Artifact truth` | output preview 只消费 artifact/sandbox/archive 结果,不反写源真相 | 单元 + 集成测试 | 是 | preview/source compare |
| `RunHealthHint ≠ Observability truth` | hint 只是解释层,不替代观测真相 | 单元 + 集成测试 | 是 | hint/source compare |
| `VisibleCapabilityState ≠ capability contract truth` | runner 显示的能力状态只是可见摘要,不冒充 contract 真相 | 单元 + 事件链测试 | 是 | capability/source compare |
| `queue/slot view ≠ scheduler truth` | 队列卡片和槽位提示不替代底层调度真相 | 单元 + 集成测试 | 是 | queue/source compare |
| run state / stream / output 对账 | phase、stream、output 必须一致可追溯 | 集成 + 恢复专项测试 | 是 | state/stream/output compare |
| control / replay 不可误导 | UI 必须区分已触发、处理中、已完成、失败 | 集成 + 恢复专项测试 | 是 | control state trace |
| output / evidence / hint 可回指 source refs | 结果和提示都可回溯 | 集成 + 投影一致性测试 | 是 | refs compare |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local run store / fake runtime-sandbox-artifact-obs-hub inputs / fake console shell | debug run state / partial output visible / hint refresh enabled | 容易只测 happy path |

| staging | 端到端演练 | real-like source refs / render pipeline / preview services / hint inputs / console embed | queue/state/output/hint/control evidence enabled | 高频状态变化与控制动作时序差异放大 |

| TC-002 | run queue 视图不得替代 scheduler/source queue 真相 | queue source 存在 | negative flow | 仅显示队列卡片,不改写源真相 |
| TC-003 | BuildRunStateView 成功渲染统一 run 状态 | runtime/sandbox 输入齐全 | BuildRunStateView | RunnerRunState 创建成功 |

| TC-012 | capability hint 不得冒充 capability contract truth | capability source 存在 | negative flow | 仅显示可见状态,不替代 contract truth |
| TC-013 | queue wait hint / quota hint 成功表达等待与资源限制 | queue/quota 输入存在 | BuildQueueHint / BuildQuotaHint | hint 生成成功 |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | runner 视图反写真相 / control entry 被误展示为成功 / output preview 冒充 artifact truth / hint 冒充 source truth |
| A | 主线可跑但 queue drift、stream 对账、preview stale、hint/source 对账不稳 |
| B | 非关键展示、低优先级 preview / summary 细节异常 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 run / queue / run card,都必须回归 run entry 与 source refs 主线
- 每次改动 phase / stream / usage / status,都必须回归运行状态和流式体验主线
- 每次改动 retry/replay/cancel/kill,都必须回归 control entry 与 source result 分层主线
- 每次改动 preview / artifact result / evidence refs,都必须回归结果消费与 source refs 主线
- 每次改动 health/capability/queue hints,都必须回归解释层与 source truth 分离主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 多 run 并发和批量操作后续细化 | 验收矩阵需扩充 | TL / 架构 |
| artifact / archive / sandbox 结果消费能力继续演进 | preview/result 验收需增加更多样本 | runner / artifact / archive |
| analytics / behavior 需求增长 | usage/action 行为验收需扩充 | product / analytics |

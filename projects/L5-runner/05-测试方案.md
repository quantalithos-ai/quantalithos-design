### 1.3 Truth ownership 与测试红线

Runner 可以拥有本地产品运行请求、下载/cache 状态、用户选择、展示状态和端侧资源视图，但不拥有 Release/Artifact truth、Governance approval、项目状态、Sandbox execution/isolation truth、Runtime execution truth、Observability truth 或 Archive truth。所有测试必须同时证明下列边界：

- 只接受显式 immutable Release/version/scope/generation；拒绝 `latest`、默认分支、可变 tag 或任何“最新”推断。
- `Complete != Verified != Qualified`；下载完成不能越过 manifest、digest、signature、platform 和 authority freshness。
- `Accepted != Running`；Sandbox 接受、transport ACK、PID、端口或本地进程观察不能证明运行成功。
- `Confirmed != Cleaned`；control/cleanup receipt 不能证明 owner 已清理，也不能绕过 lease、capture、handoff、retention 或 orphan guard。
- `Delivered/receipt/local log != formal evidence`；Runner 的本地记录不得成为正式审计或验收证据。
- Query 全部 no-write；planned Consumer header-first、no-payload、no-hash、no-store、no-ACK；Job 不修复 owner truth。
- Unknown、commit unknown 或断线后必须 freeze、建立/关联 `RecoveryCase` 并 query-first/manual-review；不得 replay、resend、reclaim 或 resume 危险副作用。
- Runner-owned outbound event 数量固定为 0；不得创建 outbox、publisher、topic 或借事件反写上游 truth。
- 只允许正式 SDK/API/public adapter；不得直接编译或复用 Sandbox 私有实现，也不得预设 Docker、Tauri、gVisor 或 Firecracker。

### 2.1 测试目标

本方案的目标是证明 Runner-owned semantic safety、traceability 与 fail-closed 行为，而不是证明相邻仓 truth 或产品 readiness。核心证明链为：

```text
trusted context + exact selection
  -> authority and material qualification
  -> run/control intent without truth escalation
  -> owner-attributed read projection
  -> guarded cleanup and frozen recovery
  -> bounded preview/diagnosis/handoff
  -> fixed-run artifact/report/evidence generation（未来执行时）
```

横切目标包括 strict configuration、idempotency、version/generation/UoW、no-write/no-parse/no-truth-repair、redaction、依赖边界、资源冲突、跨平台安全姿态和真实证据生成链。

|---|---:|---|---|
| Trusted context 与 exact `ReleaseSelection` | P0 | actor/scope/platform/ref/generation 完整；隐式 selector 拒绝 | semantic planned |
| Authority、material acquisition 与 integrity qualification | P0 | transfer、manifest、digest、signature、platform、authority freshness 分轴且 fail-closed | positive owner seam blocked |
| `RequestRun` 与 `RunIntentState` | P0 | qualified binding、resource guard、request outcome、Accepted/Pending/Unknown 分离 | Sandbox positive blocked |
| `RequestRunControl` 与 `ControlIntentState` | P0 | Start/Stop/Cancel intent、basis、receipt、Confirmed/Conflict/Unknown 分离 | owner result blocked |
| `RequestCleanup`、`ProtectionGuard`、`RecoveryCase` | P0 | guard-first、active protections、unknown freeze、manual review、no replay | destructive cleanup 不执行 |
| 12 Query 与 `RunnerReadModel` | P0 | visible/empty/not-visible/degraded/stale；全部 no-write | local semantic planned |
| 4 planned Consumer | P0（当前负向） | header-first、strict duplicate、no payload/hash/store/ACK | positive apply blocked |
| 5 Operations Job | P0 | claim/checkpoint/report、bounded iteration、duplicate、Blocked/Unknown 保真、no truth repair | external positive blocked |

### 2.3 非范围

- 不测试相邻仓内部 truth、私有数据库、Runtime loop、Sandbox backend、Artifact/Governance/Archive 内部实现。
- 不选择实现语言、GUI/CLI shell、数据库、cache、transport、容器或虚拟化产品。
- 不验证 UI shell 像素布局；只验证页面/展示所消费的正式 read surface、状态含义、安全摘要与失败交互。
- 不创建实现仓、测试 runner、CI、script、fixture、artifact、report 或 evidence，也不运行测试。
- 不生成 baseline、commit、run_id、测试结果、Release digest、verdict、signoff 或 readiness。
- 不使用旧方案中的固定性能数字；在 workload/SLO authority 到达前只定义测量方法。

### 2.4 失败与范围判定

P0 truth、安全、状态分轴、no-write/no-replay/no-truth-repair、redaction、配置 fail-closed、依赖和 evidence integrity 任一失败都必须阻断对应候选。P1/P2 或 blocked 项可以进入残余风险，但不得降低 P0 红线，也不得把未执行或依赖不可用记为通过。

### 4.1 测试金字塔

#### 测试分层图: L5-runner 测试金字塔

```text
[Future release gate / evidence summary]
  fixed-run smoke + profile/config/boundary/redaction + report completeness
                              ^
[API / Worker / Job entry]
  envelope/dispatch + header-first Consumer + five Job surfaces
                              ^
[Integration with fake / controlled adapters]
  repository/UoW + owner/platform failures + builder/readiness + recovery
                              ^
[Application service / orchestration]
  Command order/idempotency + Query no-write + Unknown/RecoveryCase
                              ^
[Contract / Domain unit]
  refs/DTO/metadata/digest + state/policy + strict config/redaction
```

关键说明：

- 图表达风险应在哪个最早层级发现，以及 release gate 只汇总低层结果。
- Fake/controlled integration 不表达上游产品、真实 platform 或 release 已就绪。
- 当前所有层级均为 planned/not-run，E2E/release 路径保持 blocked。

高风险断言必须在最早可定位层发现，不能推迟到 E2E：状态轴分离在 Domain/Service，Query no-write 在 Service write audit，duplicate 和 commit unknown 在 Service/UoW，Consumer no-payload/no-ACK 在 Worker，Job no-owner-repair 在 Job orchestration，redaction 在 helper 与输出扫描两层。

### 4.2 分层策略

| 层级 | 目标与典型内容 | 主要 profile | 未来触发 | 失败处理 |
|---|---|---|---|---|
| Contract / Unit | finite DTO、required metadata、exact selector、digest、factory、不变量、state matrix、strict config、redaction | `test-deterministic` | PR / main / nightly | P0 阻断 |
| Application service | 11 Command、12 Query no-write、idempotency、stored result、UoW 顺序、RecoveryCase、typed error | `test-deterministic` | PR / main / nightly | P0 阻断 |
| Fake / controlled integration | repository version/generation、adapter availability、resource conflict、redaction failure、claim/checkpoint、builder | `test-deterministic` / `integration-pending` | main / nightly / controlled | semantic P0 阻断；真实正向 blocked |
| API / Worker / Job entry | name/body/metadata、exactly-one dispatch、Consumer header-first、Job input/report | `test-deterministic` / `integration-pending` | main / nightly | P0 阻断 |
| E2E / release gate | 最小 selected-run 组合、四 profile、boundary/redaction、fixed-run report/evidence 汇总 | `integration-pending` / `product-pending` | future staging/release | 当前 blocked；不计 P0 通过 |

### 4.3 分层不变量

- fake/controlled adapter 只证明 Runner 编排与 formal port 语义，不证明上游产品合同或 readiness。
- Release gate 只汇总低层真实结果，不替代 11 Command、12 Query、Consumer/Job 和状态机断言。
- transport status、ACK、PID、端口、本地日志或 UI toast 不得升级为业务 truth。
- `local-safe` 只用于本地 schema、blocked UX 与单用例复现；`product-pending` 名称本身不赋予产品能力。
- 当前不存在实际 test runner、CI 或 E2E；所有层级均为 planned，正向 owner/product 层为 blocked。

### 7.4 替身、隔离与清理边界

- `test-deterministic` 使用显式 semantic fake/controlled ports、logical stores、write/call spies；fake 不携带 owner 私有 DTO 或正文。
- Consumer fixture 必须 header-only；payload opaque/absent，不生成 payload digest，不设 owner cursor/ACK success。
- Job seed 必须有 job kind/run ref/idempotency/actor/trace/basis/bounded batch/claim-checkpoint version，不得包含 owner lease 或 event target。
- Semantic in-memory 数据按 run namespace 丢弃；future durable store 只允许 run-scoped cleanup 或明确 rollback，不得全库 truncate。
- Cleanup unknown 时先保留 protection 和 RecoveryCase；不得为清理测试删除受保护 material。
- `local-safe`、`test-deterministic`、`integration-pending`、`product-pending` 数据不得混用；fake positive 不能关闭 `RUN-UP-*`。

```text
                                | [runtime]
                     [entry / worker / operations]
                                | [runtime / event]
          +---------------------+---------------------+
          v                                           v
[controlled owner/platform adapters]        [header/replay fixtures]
          |
 Artifact / Governance / Sandbox / Runtime /
 Observability / Archive / Platform (blocked refs only)
```

关键说明：

- `[compile]` 只表示 L0-core/L0-sdk 是待 authority 核验的编译候选，不表示 package/path/version 已存在。
- `[runtime]` 只通过正式 SDK/API/semantic adapter 与 safe ref/view；不得加载 sibling 私有源码或内部表。
- `[event]` 仅用于 planned Consumer 的 header-first negative/replay fixture；Runner outbound event 始终为 0。

| 依赖 | 类型 | P0 协作方式 | 禁止行为 |
|---|---|---|---|
| L0-core / L0-sdk | compile candidate + SDK runtime | typed ref/error/trace fixture 与 SDK-first adapter contract；exact package/version pending | shadow type、复制 SDK、绕过 SDK |
| Artifact / Governance | runtime | locator/integrity/authority semantic fake 与 blocked/unknown vectors | 读内部表、修改 Release/approval truth |
| Work / Workspace | runtime/ref | context/scope/visibility safe ref/view | 复制 project/work truth |
| Sandbox / Runtime | runtime | request/control/cleanup/status safe semantic adapter | private backend、PID/端口/log 推导 truth |
| Observability / Archive | runtime/ref | redacted diagnosis/handoff/archive ref 与 blocked sink | 本地日志升格 evidence、Archive 参与核心 success |
| Platform resource | runtime | bounded observation/conflict/unknown fake | 固定 OS 命令、静默抢占或伪造 allocation |
| planned Consumer | event | header-only envelope、stored receipt、negative vector | 私有 topic/group、payload parse、ACK |
| local stores/cache | internal runtime | repository/UoW/cache controlled fake | in-memory fallback 冒充 durable product |

### 8.4 配置域与环境行为

| 配置域 | `test-deterministic` 重点 | integration/product 重点 | 失败行为 |
|---|---|---|---|
| `runtime` | explicit schema/profile/config identity | immutable approved document identity | missing/unknown/mismatch fail-fast |
| `stores` | isolated fake state/projection/result/operation/cache refs | durable capability per slot | core guarantee不足则 builder非Ready |
| `bindings` | closed semantic fake slots | controlled/formal public refs | unknown/duplicate reject；configured≠ready |
| `limits` | finite deterministic values within static cap | workload authority required | zero/overflow/无authority扩大 reject/Blocked |
| `observability` | mandatory redaction + forbidden scan | controlled/formal safe sink | no visible content/handoff；no raw fallback |
| `determinism` | fixed clock/id/digest/fixture refs | controlled/formal providers | missing provider fail-fast or mutation blocked |
| `features` | explicit false/request/reject tests | prerequisites + formal review | flag 不创建 Consumer/event/owner mutation |

Strict JSON 的 unknown/duplicate key、comment/trailing、type/profile mismatch 必须整份拒绝，不回退旧值/default。Store capability 缺失不能暴露 half facade；adapter slot 必须区分 configured/enabled/ready；reload 采用新 immutable snapshot/new builder，禁止 hot patch、leaf override、`latest` 或 last-known-good 静默 fallback。

### 8.5 环境不可用判定

预期 controlled unavailable/unsupported 是对应负向 TC 的输入，只有 typed outcome 与零危险副作用满足时该 TC 才可通过。实现仓/runner/fixture/core capability 缺失，或非预期 adapter/harness 崩溃，使 suite 为 `not_run/blocked`。`integration-pending`/`product-pending` 的真实依赖不存在时不得 fake fallback，也不得生成 release evidence。

### 9.4 结果、重试与自动化边界

| 结果 | 规则 | 是否计通过 |
|---|---|---:|
| `pass` | assertion、redaction、boundary、cleanup 均满足 | 是 |
| `assertion_failed` | 保留首失败、input refs、diff、profile；诊断重跑不能覆盖 | 否 |
| `flaky_suspected` / `timeout` | 独立尝试和原因入档；无权威预算不事后挑样本 | 否 |
| `expected_controlled_failure` | 仅当 TC 明确注入且 typed outcome/zero-effect 满足 | 仅该负向 TC |

| `harness_infra_failure` | 修复后用新 run 重启 | 否 |
| `redaction_failure` / `cleanup_failure` | 安全阻断；业务结果不得覆盖该失败 | 否 / incomplete |

全部语义 P0 必须具备可重复自动化切口；页面可理解性和 future product 跨平台体验可以人工补充，但不能替代 P0 gate。任何重跑必须使用新 run ID 并关联 predecessor，不得覆盖原始结果。

### 10.2 安全与 truth-boundary negative

| 场景 | 方法 | 阻断断言 |
|---|---|---|
| `latest`/default/tag/cache latest | selection mutation | reject/Blocked；selection/download/run/owner call = 0 |
| authority/approval/baseline 缺失、撤销、过期或冲突 | controlled authority vector | 不本地批准；material/run mutation = 0 |
| manifest/digest/signature/platform mismatch | material fault vector | transfer/complete 不升级 verified/qualified |
| actor/scope/visibility 越权 | entry/context mutation | body 不覆盖 trusted scope；read/write/dispatch = 0 |
| private SDK/backend/internal DB/bus/topic | future import/call/dependency scan | finding 数必须为 0；scanner 不可用则阻断 |
| Query/render/reconnect 写入 | write/UoW/port spy | reserve/save/refresh/reconcile/probe/cleanup/dispatch = 0 |
| Consumer payload/ACK | header-only opaque fixture | read/parse/hash/store/ACK = 0 |
| local projection/receipt/report 写 owner truth | call audit | Artifact/Governance/Sandbox/Runtime/Observability/Archive truth writes = 0 |
| protected material cleanup | missing/stale/conflicting guard | release/delete/evict = 0；保持 Protected/Unknown/Blocked |
| raw secret/body/path/URL/PID/port/stack | canary 穿过所有输出面 | machine artifact 与 human report 均 0 visible findings；无 raw fallback |

### 10.3 一致性、幂等、恢复与依赖失效

| 类别 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| same key / same digest | completed idempotency record | exact stored result；domain/port/UoW=0；`DuplicateReplayed` | current-truth 重算 |
| same key / different digest | stable semantic mutation | `IdempotencyConflict`；原记录不变 | overwrite / retry |
| in-progress collision | deterministic concurrent actors | no takeover/no second effect；必要时 RecoveryCase | 双 effect |
| stale version/generation | repository/projection fake | Conflict；no LWW；Query replace=0 | 覆盖新状态/upsert |
| UoW commit response lost | terminal commit fault | Unknown + RecoveryCase；effect knowledge 与 commit knowledge 分离 | replay/resend |
| claim/checkpoint stale | two Job workers | Blocked/Unknown；old fence 不写 report | reclaim/resume |
| request/control/cleanup 断线 | lost response or ACK timeout | accepted/pending/unknown 分轴、query-first/manual review | Running/Cleaned claim、kill retry |
| owner read unavailable | J03/Q08 fault | Frozen/ManualReview/degraded | inferred terminal、local close |
| missing stored result/receipt | duplicate/replay path | ConsistencyUnknown；不重建 | 当前状态拼 result |
| source/authority/verifier unavailable | controlled adapter | typed Blocked/Unavailable/Unverified；zero unsafe effect | cache latest、skip verify |
| Sandbox/Runtime/platform unavailable | controlled adapter | Rejected/Blocked/Unknown/Unsupported | PID/port/private backend fallback |
| redaction/diagnostic/Archive unavailable | sink/ref fault | no visible unsafe content；peripheral blocked | raw local log/package fallback |
| core store/UoW capability missing | builder marker | build Failed/Blocked；facade absent | in-memory half facade |

恢复测试的通过含义是“安全停留且可追踪”，不是自动恢复成功。真实 owner readback/reconciliation 只有在正式 seam、subject/basis/version 可证明时才可形成正向结果。

### 10.4 观测、审计与 redaction

| 输出面 | 必须存在 | 必须不存在 |
|---|---|---|
| Command | operation kind、safe refs、validation/reservation/transition/result或recovery correlation | raw body、secret、完整 key、owner body |
| Query | read subject、visibility、freshness、section/generation | reservation/save/refresh/reconcile/dispatch marker |
| Consumer | safe header source/schema/event/dedup 与 disposition | payload bytes、owner cursor、ACK success |
| Job | job kind/run/claim/checkpoint/report refs 与 bounded counts | owner truth、evidence body、raw report payload |
| Metric | finite operation/outcome/category label | actor/subject/request/result/trace 等高基数 ID |
| Handoff / local report | safe correlation 与明确 non-evidence posture | formal audit/evidence/verdict/signoff claim |

Redaction 必须同时扫描 machine artifact、stdout/stderr、人读报告和 acceptance/review draft。Scanner unavailable 不等于 clean；Unknown telemetry 只能记录 safe issue/RecoveryCase，不能发 success metric 或 accepted business trace。

### 10.5 跨平台、资源、端口与清理

使用平台中立 `ResourceObservation`、source/freshness、requested resource、owner allocation/lease 与 `ProtectionGuard`。本地 probe 只形成 observation：available 不等于 allocated，conflict 不允许静默换端口或抢占，unknown/unsupported 必须 Blocked/Unsupported。Cleanup 必须重读 active lease、capture、handoff、retention、orphan 等保护轴；owner ACK 与 local receipt 均不等于 Cleaned/Evicted。

该专项不验证 OS、容器、虚拟化或 Sandbox backend 内部正确性，不锁定 Docker/Tauri/gVisor/Firecracker。Sleep/restart/reconnect 只允许 freeze、revalidate、query-first/manual review，不允许自动 resume/replay。

### 10.6 性能、容量与 UX

| 测量/审查面 | 方法 | Authority 状态 | 当前不得宣称 |
|---|---|---|---|
| selection/config/integrity validation | fixed-size deterministic cases，记录样本与分布 | workload/NFR 待定 | 性能达标 |
| query/read presentation | bounded page/view 重复只读，区分 cache posture | 产品/平台待定 | UI SLA |
| recovery/reconcile | controlled unavailable/unknown，记录安全停留 | 运维/可靠性待定 | 自动恢复率 |
| redaction/scan | fixed corpus + size buckets | 安全/平台待定 | 零成本/生产吞吐 |
| idempotency/UoW/claim concurrency | bounded deterministic collision | 实现/store 待定 | 支持具体并发数 |
| cache/material growth | bounded long-run fixture/replay、残留趋势 | capacity 待定 | durable leak-free |
| cross-platform overhead | approved platform 上相同逻辑数据 | platform 待定 | OS parity/readiness |
| blocked/unknown/conflict/recovery UX | scripted safe view + review checklist | P1 supplement | owner outcome 或 release evidence |

在阈值来源、workload、平台和实现仓闭合前，性能仅可产 measurement plan 或 exploratory data，不进入 P0/release gate。不得继承历史数字，timeout 仍按 §9 分类。人工 UX review 只能补充原因、source/freshness、影响与安全下一步，不能关闭语义 gate。

### 11.1 缺陷分级

| 等级 | 定义 / Runner 例子 | 处理 | 阻断 |
|---|---|---|---:|
| `S` | truth/security/evidence 红线：`latest` 放行、未 qualified 请求、Accepted→Running、Query/Job truth write、Unknown replay、保护材料删除、raw secret、private dependency、静态 EV | 必须修复、扩大复验、相关 check + 人工审查；不可风险接受 | 是 |
| `A` | P0 case/blocking suite 失败但未命中 S，或 harness 使安全语义不能稳定证明 | 必须修复；只有证明不影响 P0且有明确接受角色/期限才可暂记 | 通常是 |
| `B` | 非 P0、局部可读性/维护性或已批准 P1/P2 问题 | 排期或 residual；不得改 P0 结果 | 否 |
| `R` | 正式范围外或等待 authority：生产容量、真实跨仓 recovery、平台矩阵、retention | 登记影响、缓解、触发与候选角色；不声称已验证 | 否 |

### 11.2 一票否决与风险接受

下列任一行为固定为 S：绕过 exact context/selection/authority/integrity；把 transfer/ACK/PID/port/toast 升级为 qualified/running/success；绕过 cleanup protection；自动 replay/resend/reclaim/resume Unknown；泄露正文/secret 或伪装 evidence；写任一上游 truth；Query 写入、Consumer parse/ACK、Job repair owner；发 Runner event；依赖 sibling private implementation；invalid config silent fallback、profile contamination 或 half facade；缺 raw artifact、run mismatch、`latest` evidence、静态 pass/verdict 或 scanner 失效。

S、P0 redaction/dependency/config fail-closed/evidence integrity 不可接受。A 只有具备明确测试/验收责任角色、期限、影响和回归计划时才可讨论，release 前通常阻断。B/R 可登记，但 `blocked` 不等于 accepted，更不等于 pass。无正式阈值的性能 sample 只能记录趋势。

### 11.3 修复后复验矩阵

| 变更/缺陷面 | 最小用例族 | 必跑 suite/check | 额外边界 |
|---|---|---|---|
| context/authority/material | CTX/MAT/CON/ENT/CFG | CONTRACT/DOMAIN/SERVICE/CONFIG | no latest、scope/generation、authority/integrity、zero owner call |
| request/control/owner | REQ/CTL/OWN | SERVICE/CONTROLLED/ENTRY | accepted/pending/unknown/Running 分离、no truth write |
| resource/cleanup/recovery | RES/REC/UOW/JOB | DOMAIN/UOW/JOB/REPLAY | guard/lease、commit unknown、no replay/delete |
| preview/diagnosis/handoff | PRE/OBS | CONTRACT/SECURITY/REPLAY + redaction | forbidden corpus、低基数、local≠evidence |
| Query/read model/projection | QRY/UOW-005/006 | SERVICE/ENTRY/UOW/SECURITY | representative Query writes=0 |
| protocol/entry/Consumer | CON/ENT/CNS | CONTRACT/ENTRY/CONSUMER | metadata、name/body、header-first、Duplicate、no ACK |
| idempotency/UoW/Job | IDM/UOW/JOB | SERVICE/UOW/JOB/REPLAY | same/different digest、claim/checkpoint、stored result |
| config/dependency/readiness | CFG/BND + affected family | CONFIG/CONTROLLED/SECURITY + dependency | strict source、profile isolation、configured≠ready |
| report/evidence | affected source family/slot | source suite + redaction/link/pairing/no-static | fixed run、raw/report pair、no static evidence |

必须重跑原失败 TC、同 family 的主线/负向/边界或 Unknown 代表、主 suite 与受影响安全 check。共享 object/state/protocol/metadata/idempotency/projection/redaction/config/dependency/evidence schema 改变时不得只跑一个 case；按 §14 扩大到相关 family 或全量 P0。

### 11.4 关闭条件与防回归

缺陷关闭必须记录影响/根因/修复、失败前（若执行过）与修复后固定 run、TC/CUT/suite artifact/report、实际未执行范围、相关 redaction/dependency/link/pairing check、新增防回归测试或不新增理由。S 不允许接受；A/B/R 的接受必须具备有权角色、期限和触发条件。没有真实 run/artifact/report 的设计阶段条目只能是 `planned/blocked`，不能 closed/pass。

手工或 E2E 首次发现的 P0 必须下沉到最早 Contract/Domain/Service/Entry 层；redaction、private dependency、report pairing、`latest`、duplicate/commit unknown/claim race/cleanup 漏检必须扩充相应 deterministic corpus/check 并进入 blocking gate。

### 12.5 T2～T4 退出与结果分类

T2 必须为每个已授权 slot 保留正向、负向、Unavailable、Unknown 与恢复的真实 artifact/report，并保持 owner outcome 与 Runner posture 分离。T3 必须在 approved environment 中覆盖 authority/integrity、Sandbox/Runtime lifecycle、resource/cleanup、preview/diagnosis/handoff、跨平台和安全。T4 必须满足新版 06/治理要求的 AC/VETO、fixed-run evidence、review 和 residual acceptance；05 不自行生成 verdict/signoff。

| 结果 | 是否满足退出 | 处理 |
|---|---:|---|
| `pass` | 对该 TC/suite 是 | 汇总，但仍受层级准则约束 |
| `fail` | 否 | 建 S/A，按 §11 复验 |
| `blocked` | 否 | 保留 blocker、owner、触发和未执行范围 |
| `not_run` | 否 | 修复前置后用新 run；不计 pass |
| `timeout` / `flaky` | 否 | 保留所有尝试、阶段和 issue；不挑结果 |
| `incomplete` | 否 | 补齐或重跑；不静默合并 |
| `risk_accepted` | 仅可作非阻断 residual | 记录有权接受角色、期限、触发；不改成 pass |

当前只有 T0 设计准则成立。T1～T4 均为 `blocked/not_run`，没有任何实际退出、测试 pass、evidence-ready 或 release readiness。

### 13.3 Machine artifact 目录与最小 schema

```text
artifacts/test/<run_id>/
  meta/context.json
  meta/config-summary.json
  meta/source-revisions.json
  evidence-index.json
  checks/{redaction,dependency-boundary,evidence-links,report-pairing}.json
  suites/<suite>/report.json
  suites/<suite>/{stdout,stderr}.log
  suites/<suite>/cases/<tc_id>.json
  suites/<suite>/artifacts/<safe_name>.json
```

目录根不得加入 project 子层或 `latest`。共享 artifact status 固定为 `passed/failed/blocked/not_run/timeout/flaky/incomplete`；assertion 为 `passed/failed/not_run`；review 为 `pending/reviewed/disputed`；redaction 为 `clean/failed/unavailable/not_applicable`。Blocked/not-run 不得压成 skipped-pass，review 不得回写 raw status。

| Artifact | 最小必需字段 / 约束 |
|---|---|
| `meta/context.json` | schema、run ID、started_at、layer/profile/environment、suite/trigger/change refs、artifact/report roots、redacted environment、future canonical digest；不得伪填 digest |
| case JSON | run/suite/TC/CUT/profile/dataset refs、status、assertions、safe issue/blocker、call/write/cleanup refs、digest；actual value 仅 bounded safe value/ref |
| suite `report.json` | planned/executed/not-run case refs+digests、counts、failure/blocker、cleanup/redaction refs、digest；不得压缩失败类别 |
| check JSON | run/check/status、safe finding category/source refs、digest；不得保存 raw finding value |
| evidence index/item | same-run context、slot/family/status、逐项 TC、suite、artifact/report refs+digests、AC/blocker/issue、item/index digest；只从 raw/report/check 生成 |
| incomplete slot | slot、missing producer/TC、blocker、status；不分配 EV alias |

Stdout/stderr 必须存在并被 redaction scan；无输出可为空，但须被 suite report 引用 digest。Digest 算法/规范待实现 authority 统一登记，不能由单 suite 自行发明。

### 13.4 Human-readable report 与生成关系

```text
reports/
  README.md
  runs/<run_id>/
    summary.md
    evidence-index.md
    gate-results.md
    redaction-check.md
    dependency-boundary.md
    evidence-link-check.md
    report-pairing.md
    suites/<suite>.md
    evidence/<evidence_id>.md
  acceptance/{handoff,veto-checklist,risk-acceptance,open-issues}.md
  review/{reviewer-notes,agent-review}.md
```

Run reports 只能聚合同一 fixed run。Suite/run/evidence 报告必须由 raw artifact 生成；acceptance 只记录 source run/digest、范围、未执行项、blocker 与风险，不宣告通过；review 可标 reviewed/disputed，但不得改 raw 或把 failed/blocked 改成 pass。生成器必须在 `scripts/reports/`，报告目录只存输出。

#### 报告生成与审查表

| 报告 | 来源 artifact/report | 逻辑生成器 | 输出 | 人 / Agent 审查要求 |
|---|---|---|---|---|
| Suite summary | suite `report.json`、case JSON、redacted logs | `scripts/reports/render-suite-report.sh` | `reports/runs/<run_id>/suites/<suite>.md` | case/status/failure/blocker/cleanup 与 raw 一致 |
| Run summary / gate results | context + all suite/check reports | `scripts/reports/render-run-summary.sh` | `summary.md`、`gate-results.md` | planned/executed/not-run 分母与 T1/T2/T3 分层准确 |
| Evidence index/detail | valid same-run raw/report/check pairs | future evidence-index report stage | `evidence-index.md`、`evidence/<evidence_id>.md` | 抽查逐 TC/CUT/AC、digest、blocker 与 status |
| Check reports | redaction/dependency/link/pairing check JSON | future check report stage | 对应 fixed check report | finding、unavailable、missing source 不得隐藏 |
| Acceptance handoff / veto / risk / issues | fixed-run reports/evidence index + §11/§14 | future acceptance handoff stage | `reports/acceptance/*.md` | 补范围、未执行、风险和争议；不写 verdict/signoff |
| Reviewer / agent notes | acceptance set + selected raw refs | independent review | `reports/review/*.md` | 只标 reviewed/disputed，不覆盖 raw |

### 13.5 Evidence integrity checks

| Check | 阻断条件 | 安全输出 |
|---|---|---|
| redaction | raw secret/token/body/sensitive ref/path/URL/PID/port/stack，或 scanner unavailable | category/count/safe issue ref，不回显 value |
| dependency boundary | sibling private source/backend、SDK bypass、direct DB/bus/topic、旧技术假定 | dependency kind/source class/finding ref |
| evidence link | TC/CUT/suite/artifact/report/AC/run/digest orphan/mismatch、wildcard machine ref、duplicate主归属 | missing/mismatch categories |
| report pairing | missing report/log/case source、report无raw、raw无report | missing path/ref 与 suite status |
| no-static-evidence | slot/catalog/手写 JSON 生成 EV、`latest`、无 producer pair 的 pass/verdict | invalid claim category/source ref |

任一 check failed/unavailable 使 slot incomplete 或 run failed/blocked。Fail/blocked/not-run/timeout/flaky、redaction finding、cleanup unknown、report/link failure 和 superseding run 都必须保留；新 run 追加 predecessor/supersedes ref，不能修改旧 status/digest。Retention 当前仅用条件式 guard：验收候选保留至审查完成，失败/复验保留至缺陷关闭，争议保留至争议关闭，invalidated evidence 追加失效引用而不回写；没有 authority 的天数不得伪造。

### 14.2 全量 P0 触发与集合

下列变化强制全量：AC/VETO/S 红线；truth ownership 或依赖方向；11 Command/12 Query/4 Consumer/0 event/5 Job inventory；正式 state/transition 或四组状态分离；UoW/idempotency/version/generation/RecoveryCase/claim；四 profile/config/readiness/redaction/rollback；evidence checks/status/gate；任何 upstream positive seam 或 physical implementation/store 首次落定。

全量集合为 CONTRACT、DOMAIN、SERVICE、UOW、CONTROLLED、ENTRY、CONSUMER、JOB、CONFIG、SECURITY、REPLAY（source 不可用则显式 blocked），加全部 redaction/dependency/link/pairing/no-static checks，以及 §13 report/evidence generation 和 review-ready acceptance draft。E2E 只在 T2/T3 进入条件满足时加入，不替代 T1 分母。

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L5-runner` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L5-runner` 是面向任务与执行入口的运行承载产品层 / runner experience 层,不是 runtime 真相仓、sandbox 执行仓或 artifact 真相仓
- RunnerRun / RunQueueEntry / RunnerRunState / RunControlEntry / RunOutputPreview / RunHealthHint 构成正式 runner 体验层真相
- `RunnerRun ≠ Runtime execution truth`、`RunControlEntry ≠ control success truth`、`RunOutputPreview ≠ Artifact truth`、`RunHealthHint ≠ Observability truth`、`VisibleCapabilityState ≠ capability contract truth` 等核心边界必须成立
- run entry / queue / state / output / hint 五条产品主线必须能统一组织,且 source refs 持续可追溯
- retry/replay/cancel/kill 等控制入口只表达用户动作意图,不得误导用户认为动作已成功完成
- output preview / artifact result / evidence refs 只消费 source 结果,不得反写真相
- queue wait、capability unavailable、quota/deny、health degraded 等非 happy path 提示必须有统一解释层,让用户理解下一步动作

因此,本次验收的目的不是笼统判断“能不能做个 run 页面”,而是判断 runner 的 run entry 主线、state/render 主线、control 主线、output/result 主线与 hint/assist 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 运行入口与运行单元部分 | 是 | RunnerRun、RunQueueEntry、RunCard、ExecutionTargetSummary、VisibleRunIdentity |
| 运行状态与执行进度呈现部分 | 是 | RunnerRunState、RunPhase、ProgressSegment、StreamExcerpt、ResourceUsageBadge |
| 控制动作与恢复交互部分 | 是 | RunControlEntry、RetryIntent、ReplayIntent、CancelIntent、KillIntent、ContinueIntent |
| 结果、产物与上下文消费部分 | 是 | RunOutputPreview、ArtifactResultCard、FileRefCard、ExecutionSummaryCard、EvidenceRefCard |
| 状态提示、能力提示与运行辅助部分 | 是 | RunHealthHint、VisibleCapabilityState、QueueWaitHint、QuotaHint、NextStepSuggestion |
| runtime / sandbox / artifact / observability / capability-hub 真相本体 | 否 | 只验 runner 如何消费其结果并组织运行产品体验,不验 source truth 全部实现 |
| scheduler / host runtime / analytics 本体 | 否 | 只验 runner 的入口、可见状态和交互逻辑,不验底层执行系统实现 |
| source control 真正执行成功 | 否 | 只验 control entry 与提示链,不验下游 control 完整实现 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateRun / OpenRun / ListRuns | 合法 target/source refs 时必须形成正式 RunnerRun / RunQueueEntry / RunCard | API 响应 / DB 记录 / source ref compare | [] |
| Run 入口边界 | RunnerRun 只能表达运行产品层可见单元,不得替代 runtime execution truth | run/source compare / negative flow | [] |
| BuildRunStateView / BuildStreamExcerpts | runtime/sandbox 输入齐全时必须形成统一 RunnerRunState、phase、stream/usage 视图 | state view / stream excerpts / compare report | [] |
| State/render 边界 | run progress view 不得替代 runtime execution truth；stdout excerpt 不得替代 sandbox output truth | compare report / negative flow | [] |
| TriggerRetry / TriggerReplay / TriggerCancel / TriggerKill | control entry 触发后必须形成正式控制记录并分发到 source control 层 | control history / source dispatch trace | [] |
| Control 边界 | RunControlEntry 只表达入口,不得展示为控制动作已成功完成；replay UI 不得替代 replay execution truth | action/result compare / negative flow | [] |
| BuildRunOutputPreview / BuildArtifactResultCard / BuildEvidenceRefs | artifact/archive/sandbox refs 合法时必须形成结果、产物和证据消费面 | output preview / result cards / evidence refs | [] |
| Result/preview 边界 | RunOutputPreview 只能消费 source outputs,不得替代 artifact truth 或 archive truth | preview/source compare / negative flow | [] |
| BuildRunHealthHint / BuildCapabilityHint / BuildQueueHint | health/capability/queue 输入合法时必须形成统一解释层提示与 next-step 建议 | hint views / suggestion outputs / compare report | [] |
| Hint/assist 边界 | RunHealthHint 不得替代 observability truth；VisibleCapabilityState 不得替代 capability contract truth；queue wait hint 不得替代 scheduler truth | hint/source compare / negative flow | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | runner 视图反写真相 / control entry 被误展示为成功 / output preview 冒充 artifact truth / hint 冒充 source truth |
| A | 视情况 | 主线可跑但 queue drift、stream 对账、preview stale、hint/source 对账不稳 |
| B | 可带着走 | 非关键展示、低优先级 preview / summary 细节异常 |

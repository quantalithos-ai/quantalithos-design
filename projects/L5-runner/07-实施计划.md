### 6.2 编写、提交与评审纪律

- 一笔实现 commit 只对应一个 `commit-ph-*` boundary；不得按文件随意拆分，也不得把无关能力拼接到同一提交。
- commit title 使用 `{type}({scope}): {subject}` 的计划格式，`type` 使用英文，具体语言、shell 和工具命令待 authority 到达后才绑定；当前不生成真实 commit message 或 hash。
- Commit Gate 与 Handoff Gate 分离；提交记录只能在真实 baseline、真实检查、真实 review 到达后填写。设计仓本轮不提交 commit。
- 失败、blocked、not_run、incomplete 和旧 run 材料必须保留；不得以静态表、手工状态、跨 run 拼接或删除失败材料制造绿色结果。

实现期的提交规则只在目标实现仓和 authority 到达后生效：一笔 commit 对应一个 boundary；title 使用 `{type}({scope}): {subject}` 计划格式；body 按 boundary 子功能分组；Commit Gate、Handoff Gate、review 和证据状态分离。具体语言、formatter、build、lint、test、packaging 和 commit hook 不得从 README 或旧文档继承。

交付包必须能从固定 raw artifact、suite/report/check、evidence index/detail、handoff、VETO、open issues、risk eligibility 和 independent review 回到同一 run、scope、profile、baseline 和 source/config digest。脚本只能生成初稿和机器检查，不能自行形成最终 verdict；实现负责人不能自签验收或 readiness。

### 12.1 结果语义

| 结果 | 允许含义 | 当前/未来限制 |
|---|---|---|
| `implementation_complete` | P0 实施、required gate、review、证据和设计闭环满足 07 handoff 条件 | 不等于 06 verdict、signoff 或 release readiness |
| `conditional_handoff` | P0 主线成立且只剩符合 06 eligibility 的 residual | 不得绕过 required seam、P0、VETO、S 级或 evidence 缺口 |

| `blocked` | 目标仓、authority、baseline、工具、设计 truth 或红线未到达 | 等待、回写或修复，不提交、不生成 verdict |

5. 18 CUT、108 planned TC、12 suite、18 slot、AC/AR/TX/NFA/VETO 与 boundary 主归属无孤儿或漂移。

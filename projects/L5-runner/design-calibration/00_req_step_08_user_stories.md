## 1. 本步目标与约束

本步把角色目标写成可追溯的用户故事，说明业务价值和其支撑的核心能力节点。故事不使用 API、Command、数据库、组件或内部调用链命名；外围增强与边界外事项不混入核心故事。

## 2. 能力节点小循环

### 2.1 `CP-RUN-01` 可信语境与显式选择

| 故事 ID | 用户故事 | 目标类型 | 业务价值 | 闭环关系 |
|---|---|---|---|---|
| `US-RUN-001` | 作为运行用户，我希望在可信项目/会话语境中明确选择一个不可变的 Release 版本，以便我知道即将运行的确切产物。 | 核心闭环 | 避免误运行可变或错误版本。 | 可信语境与显式选择 |
| `US-RUN-002` | 作为项目负责人，我希望在开始取得材料前看到该版本的正式可消费、适用范围和有效性姿态，以便我能判断是否应继续。 | 核心闭环 | 让版本选择与治理/发布语境可解释地衔接。 | 可信语境与显式选择 |

**主验收条件**：Given actor/context 可验证且存在多个版本，When 用户选择一个明确版本，Then Runner 保留该选择及其来源语境，并不以 `latest` 或默认值替代。
**替代验收条件**：Given 版本不可见、已撤销、已过期或 authority 无法验证，When 用户尝试继续，Then Runner 阻止后续运行准备并显示可解释的 `blocked/pending/invalid` 姿态。

**节点停审**：故事只描述选择目标，不把批准、版本创建或项目成员资格写成 Runner 行为；`US-RUN-001~002` 可进入功能需求讨论。

### 2.2 `CP-RUN-02` authority、取得与完整性资格

| 故事 ID | 用户故事 | 目标类型 | 业务价值 | 闭环关系 |
|---|---|---|---|---|
| `US-RUN-003` | 作为试用者，我希望看到材料取得进度、暂停/恢复和失败原因，以便我能判断端侧准备是否仍在进行。 | 核心闭环 | 降低下载过程的不确定性，避免重复操作。 | authority、取得与完整性资格 |
| `US-RUN-004` | 作为运行用户，我希望在材料真正可运行前看到完整性和平台资格结论，以便不会启动损坏、被撤销或不兼容的产物。 | 核心闭环 | 把安全验证置于执行之前。 | authority、取得与完整性资格 |

**主验收条件**：Given 选定版本有正式取得语境，When 材料取得并完成验证，Then 用户能区分传输完成、验证通过和可运行资格。
**替代验收条件**：Given 传输中断、digest/signature 不匹配、manifest 缺失或 authority 过期，When 用户尝试启动，Then 材料保持受限/隔离状态且不能进入正式 Sandbox 请求。

**节点停审**：故事不指定下载协议、签名算法、cache 介质或校验实现；`US-RUN-003~004` 可进入功能需求讨论。

### 2.3 `CP-RUN-03` 受控请求与生命周期表达

| 故事 ID | 用户故事 | 目标类型 | 业务价值 | 闭环关系 |
|---|---|---|---|---|
| `US-RUN-005` | 作为运行用户，我希望用已验证的版本发起正式受控运行请求，并知道请求是已接收、待确认还是被拒绝，以便我不会把提交动作误认为已经运行。 | 核心闭环 | 保持用户意图、Sandbox 接收和实际运行的语义分离。 | 受控请求与生命周期表达 |
| `US-RUN-006` | 作为运行用户，我希望看到运行从准备、启动、运行、停止到终态的清晰状态，并能发起允许的停止或取消意图。 | 核心闭环 | 让生命周期和控制影响可理解、可追溯。 | 受控请求与生命周期表达 |

**主验收条件**：Given 本地资格满足且正式边界可用，When 用户发起运行，Then Runner 展示请求关联和 owner 返回的生命周期姿态，并明确 `accepted` 不等于 `running`。
**替代验收条件**：Given owner 返回 pending/unknown 或连接中断，When 用户查看或再次操作，Then Runner 冻结可能重复副作用的动作，要求查询或 reconcile，不显示成功。

**节点停审**：故事不把 RunnerRun 当 Runtime truth，不定义 Runtime/Sandbox 控制协议；`US-RUN-005~006` 可进入功能需求讨论。

### 2.4 `CP-RUN-04` 资源、清理与恢复安全

| 故事 ID | 用户故事 | 目标类型 | 业务价值 | 闭环关系 |
|---|---|---|---|---|
| `US-RUN-007` | 作为运行用户，我希望在启动前看到端口、文件或本机资源冲突及其影响，以便我能选择安全的处理方式。 | 核心闭环 | 避免隐式抢占和难以诊断的启动失败。 | 资源、清理与恢复安全 |
| `US-RUN-008` | 作为支持/运维操作员，我希望在网络断线、应用重启或 lease 丢失后看到哪些状态已确认、哪些仍未知，以便能安全地协助恢复。 | 核心闭环 | 防止未知副作用被重复执行。 | 资源、清理与恢复安全 |
| `US-RUN-009` | 作为运行用户，我希望停止或清理后知道资源是否已释放、哪些材料仍受保护，以便不会误删仍在使用的运行材料。 | 核心闭环 | 保持运行、lease、capture 和本地材料的清理一致性。 | 资源、清理与恢复安全 |

**主验收条件**：Given 本地存在冲突或活动运行，When 用户查看资源/清理状态，Then Runner 清楚区分 probe、owner allocation、lease、cleanup 和本地材料保护。
**替代验收条件**：Given 连接中断、lease/orphan 状态未知或 cleanup guard 未确认，When 用户请求强制清理，Then Runner 阻止危险动作并保留 reconcile/人工处理入口。

**节点停审**：故事不授予 Runner 全局调度、强制 kill 或 Sandbox cleanup 权限；`US-RUN-007~009` 可进入功能需求讨论。

### 2.5 `CP-RUN-05` 预览、诊断与追溯交接

| 故事 ID | 用户故事 | 目标类型 | 业务价值 | 闭环关系 |
|---|---|---|---|---|
| `US-RUN-010` | 作为运行用户，我希望看到经过裁剪的输出预览、阶段摘要和来源引用，以便理解软件当前表现而不接触不必要的敏感正文。 | 核心闭环 | 提供可用反馈，同时保护 secret/raw body。 | 预览、诊断与追溯交接 |
| `US-RUN-011` | 作为运行用户，我希望失败信息说明影响、来源和下一步，而不是只显示“启动失败”，以便采取正确的恢复动作。 | 核心闭环 | 将复杂跨域失败转化为可理解的安全行动建议。 | 预览、诊断与追溯交接 |
| `US-RUN-012` | 作为审计/安全查看者，我希望看到安全诊断摘要和正式交接的状态，以便知道哪些信息已交给 Observability，而不把本地日志当成证据。 | 核心闭环 | 保持诊断、审计和证据 authority 分离。 | 预览、诊断与追溯交接 |

**主验收条件**：Given 存在安全 output/diagnostic source ref，When 用户打开预览或诊断，Then Runner 显示有限摘要、来源和 freshness，并明确其不是 Artifact/evidence/verdict。
**替代验收条件**：Given source 不可见、摘要不完整或 handoff 被阻断，When 用户查看结果，Then Runner 显示 partial/restricted/blocked，不补造正文或最终结论。

**节点停审**：故事不把 handoff receipt 当最终报告，不把本地 telemetry 当审计证据；`US-RUN-010~012` 可进入功能需求讨论。

## 4. 边界外故事审计

以下看似合理的目标不进入 Runner 故事表：修改 Release 内容、审批版本、编排 Runtime loop、实现 Sandbox backend、生成正式 evidence/verdict、编辑源码、生产部署和自动分享公网地址。这些目标分别归 Artifact/Governance/Runtime/Sandbox/Observability/Sync/部署或后续产品边界。

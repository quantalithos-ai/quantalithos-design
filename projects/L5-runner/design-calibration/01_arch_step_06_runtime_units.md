## 1. 本步问题回答与承载原则

本步只说明 Runner 的正式运行承载角色，不锁定桌面框架、CLI 实现、进程模型、镜像、集群或部署参数。Runner 的运行结构必须让入口、后台取得/恢复、展示组合和平台能力观察保持可替换，同时让 Sandbox/Runtime 成为正式外部运行边界，而不是被 Runner 内嵌。

## 3. 运行单元说明表

| 对象 | 类型 | 主要职责 | 运行关系 | 说明 |
|---|---|---|---|---|
| 同步入口承载 | 同步入口单元 | 承接入口系统的选择、查询、控制和展示请求。 | 入口本地视图与意图承载。 | 入口形态可为 GUI/CLI/其他正式调用方，但具体技术不在本步锁定。 |
| 本地视图与意图承载 | 同步入口单元 | 组合 Runner-owned intent、owner-safe snapshot/ref 和展示状态。 | 处理同步入口请求，向取得/恢复和诊断预览承载提供安全语义。 | 不拥有外部 truth，不直接接触私有实现。 |
| 取得/恢复承载 | 后台处理单元 | 承接下载恢复、cache/quarantine 保护、状态对账和本地恢复整理。 | 处理/消费正式来源和本地生命周期信号。 | 不以后台任务修复上游 truth，不自动重放未知副作用。 |
| 诊断/预览承载 | 后台处理单元 | 生成 bounded/redacted preview、失败分类和 handoff posture。 | 处理/消费 owner-safe source 与本地观察。 | 不保存 raw body，不生成 evidence/report/verdict。 |
| Runner-owned 本地状态 | 正式存储承载 | 承载选择、意图、保护、验证姿态、恢复标记和安全 refs。 | 被入口、后台和诊断承载依赖。 | 存储实现和 schema 后置；不承载上游正文。 |
| 平台能力/资源依赖 | 正式基础设施依赖 | 提供文件、网络、路径、端口、容量和应用生命周期观察。 | 被入口和后台承载依赖。 | 观察有 freshness；不拥有 scheduler、allocation 或 lease truth。 |
| SDK/正式边界 | 运行时对接的正式外部边界 | 提供跨域访问、错误/redaction/trace 和公开能力入口。 | 入口/后台承载通过正式边界接入。 | exact SDK surface 未闭合，保持条件性。 |
| Sandbox/Runtime | 运行时对接的正式外部边界 | 提供受控执行、状态、结果、lease 和 cleanup owner 能力。 | 入口/后台承载向其提交和消费正式状态。 | Runner 不内嵌或编译其私有实现。 |

## 4. 部署关系与承载边界

Runner 的入口承载、后台承接、诊断组合和本地状态可以在同一端侧产品中协作，但它们的架构职责仍保持分离；是否同进程、同包或拆分部署留给后续实现设计。Sandbox/Runtime 是外部受控执行边界，不能被视为 Runner 的内部承载。L0-sdk 和平台能力是正式接缝/基础设施边界，不是 Runner-owned 业务存储。

## 5. 运行边界红线

| 红线 | 承载层保护 |
|---|---|
| 本地状态承载不保存上游正文 | 只承载 Runner-owned truth、snapshot/ref 和保护 metadata。 |
| 后台承载不自动关闭 unknown | 恢复、对账和清理候选遇到未知时保持挂起。 |
| 入口承载不直连私有 backend | 所有跨域动作经 SDK/公开 adapter。 |
| 诊断承载不成为观测 owner | handoff 是交接姿态，不是正式 evidence。 |

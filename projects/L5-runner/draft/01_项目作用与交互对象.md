## 1. 一句话定位

`L5-runner` 是用户在端侧选择并运行一个**已获正式授权、可验证且不可变的 Release/Artifact 版本**的产品入口。它负责把用户的显式选择、下载与本地 cache、完整性验证、Sandbox 正式请求、启动/停止/清理意图、端口与资源冲突、运行输出预览、失败诊断和断线恢复组织成可解释的本地体验；它不拥有 Release、Artifact、Governance、Runtime、Sandbox、Observability 或 Archive 的正式真相。

它回答的是：

> “这台端侧设备正在为哪个明确版本准备运行、准备是否通过、当前本地控制意图和展示状态是什么、用户下一步应该做什么？”

它不回答的是：

> “这个版本是否被批准、Artifact 正文和基线是什么、Sandbox 是否真正隔离、Runtime 是否实际执行成功、观察证据是否成立、归档是否完成。”

### 1.1 为什么必须单独存在

| 易混淆对象 | Runner 的边界结论 |
|---|---|
| `L1-artifact` | Artifact owner 拥有 Artifact fact、版本、血缘、baseline 和 consumable reference。Runner 只能消费正式 Release/Artifact 引用并保存本地取得与验证状态，不能修改 Release 内容、创建版本、冻结 baseline 或把下载副本写回 Artifact truth。 |
| `L1-governance` | Governance owner 拥有 Policy、Gate、Decision、Approval 和 Control。Runner 只能验证上游明确给出的 approved/baselined authority chain；不能凭用户身份、缓存、历史成功或 Sandbox ACK 推断“已批准”。 |
| `L1-work` / `L1-workspace` | Work 拥有 Project、ProjectMember、WorkItem；Workspace 拥有跨域 read model。Runner 可以接收项目上下文或安全摘要作为运行语境，但不创建、推进、修复项目状态，也不把 RunnerRun 写回 Work/Workspace truth。 |
| `L2-runtime` | Runtime 拥有 Runtime execution truth、loop、checkpoint、recovery 和 outcome。Runner 保存端侧运行请求与展示状态，必要时消费正式 Runtime read surface；不能把本地“启动成功”、进程存在或画面刷新写成 Runtime outcome。 |
| `L4-sandbox` | Sandbox 拥有 boundary、policy execution、controlled run、capture、handoff、lease、cleanup 和 redline containment truth。Runner 只能通过 SDK/正式 adapter 发起请求并展示 ACK、运行状态、失败或清理姿态，不能直接复用/编译 Sandbox 私有实现，也不能把 `accepted` 当 `running`。 |
| `L4-observability` | Observability 拥有 observation material、audit projection、diagnostic view、report/handoff 和 retention marker。Runner 可展示安全诊断摘要、提交允许的 handoff；本地日志、UI telemetry、stdout/stderr 摘录都不是正式 evidence、report、verdict 或 signoff。 |
| `L4-archive` | Archive 拥有归档包、完整性、兼容性、恢复材料和 owner handoff 语义。Runner 不以 archive 可用或下载完成推导归档成功；归档正向合同未闭合时只保留受限消费 seam。 |
| `L0-sdk` / `L0-core` | SDK 是正式访问封装和 fake boundary，Core 是共享契约候选来源。Runner 必须通过 SDK 或经评审的 adapter 访问上游，不把 sibling 源码、内部表或私有 transport 变成依赖。 |
| `L0-bus` | Bus 拥有 delivery、ack/fail、retry、dead-letter 和 replay truth。Runner 可以由 SDK/正式事件 seam 接收变化，但本地 cursor、cache 或 UI 刷新不等于 Bus delivery truth。 |
| `L5-console` / `L5-chat` / `L5-sync` | 这些是互补产品或同步消费者。Runner 可提供安全的本地运行摘要或 deep link；不能接管 Console 会话、Chat 对话、Sync 游标或其它产品的 UI truth。 |

Runner 单独存在的价值是把“端侧运行准备和用户控制体验”与“服务端发布/治理/执行/观测真相”隔开。没有这一层，产品会直接把下载目录、进程句柄或本地日志误当成批准、运行成功和审计证据；Runner 越界则会形成第二个 Release/Execution/Sandbox 真相中心。

## 2. 本仓拥有 / 只消费 / 禁止拥有

| 主题 | Runner 可以拥有 | 只消费 / 回链 | 禁止拥有或反写 |
|---|---|---|---|
| 本地运行请求 | 用户显式选择、请求关联、目标设备/平台语境、控制意图、取消/停止/清理意图。 | source release ref、project context、actor/session context。 | Runtime execution、Sandbox control、Governance approval。 |
| Release 选择 | 显式 `release_ref` / 版本标识、选择来源、用户确认和选择失效状态。 | Artifact/Release summary、formal baseline membership、Governance authority chain。 | `latest` 解析、版本创建、Release 内容编辑、baseline/approval 结论。 |
| 下载与 cache | 下载任务、局部 cache entry、传输进度、重试姿态、保留/淘汰意图和本地路径抽象。 | 正式 download locator、manifest、digest/signature policy、revoke/expire signal。 | 把 cache 当 Release truth；在未验证时启动；以 HTTP 200 或文件存在替代完整性通过。 |
| 完整性验证 | 本地验证结果、验证算法/策略引用、失败原因和待复核姿态。 | Artifact 提供的 manifest/digest/signature authority。 | 自行批准未知签名、修改材料后重新声明同一 digest、将验证通过改写为治理批准。 |
| Sandbox 请求 | 请求生命周期、adapter correlation、ACK/拒绝/待确认/未知显示和本地重试门禁。 | Sandbox context/boundary/policy/lease/controlled run/cleanup truth。 | 直接调用私有 backend、编译私有实现、把 ACK 当 running/succeeded、绕过 policy/lease。 |
| RunnerRun 本地状态 | 本地 `RunnerRun`、控制意图、展示状态、诊断摘要引用、连接/恢复姿态。 | Runtime/Sandbox status refs、observability diagnostic view、artifact output refs。 | 反写 Runtime outcome、Sandbox execution state、Observability evidence 或 Project status。 |
| 端侧资源视图 | 端口占用视图、资源可用性摘要、冲突提示、清理候选和用户确认。 | OS/platform resource probe 结果与 Sandbox 分配结果。 | 将本地可用性当治理/调度/容量真相；自动抢占他人资源或跳过 cleanup guard。 |
| 输出预览 | 经裁剪的 stdout/stderr 摘录、结果摘要、链接/引用卡片、展示 freshness。 | Sandbox capture、Runtime result、Artifact/Archive/Observability safe ref。 | 保存或上传完整 secret/raw body；把 preview 当 Artifact 正文、evidence 或最终结果。 |
| 诊断与交接 | 安全诊断摘要、用户可读失败分类、handoff 请求和本地关联。 | Observability safe diagnostic/handoff receipt 和正式报告状态。 | 把本地日志当正式审计；把 handoff ACK 当 verdict/signoff；修复上游 truth。 |
| 连接与恢复 | 本地断线、重连、未决请求、cursor、orphan/cleanup 提醒和恢复 UI 状态。 | 上游 version/status/cursor、Sandbox lease/reconcile 结果。 | 自动重放未知副作用、以重连成功覆盖未知结果、单方面释放仍受保护资源。 |

### 2.1 必须始终显式的 authority chain

Runner 只有在以下信息均由正式边界提供且可验证时，才能进入下载或运行准备：

```text
user explicit release selection
  -> Artifact/Release reference is resolvable
  -> selected version is immutable and baseline-compatible
  -> Governance approval/decision scope is applicable and not revoked/expired
  -> locator + manifest + digest/signature are available
  -> local bytes pass integrity verification
  -> Sandbox formal request accepted by its own guards
```

任何一环缺失、过期、冲突、不可见或无法验证，都只能产生 `pending`、`blocked`、`unknown`、`stale` 或 `unavailable` 等安全姿态，不得用“上次成功”“默认版本”“本地管理员”“Sandbox accepted”补齐链条。

## 3. 交互对象总览（候选系统上下文）

```text
                         +---------------------------+
                         | L0-core / L0-sdk          |
                         | refs, errors, auth, APIs  |
                         +-------------+-------------+
                                       |
                              formal SDK / adapters
                                       v
 +------------------+       +---------+----------+       +----------------------+
 | user / local OS  | ----> |     L5-runner       | ----> | L1-artifact           |
 | platform resources| UI  | select/cache/run    | read  | Release/version/base |
 +---------+--------+       | preview/diagnostic  | ----> | L1-governance         |
           |                +----+------+---------+ read  | approval/policy       |
           |                     |      |          ----> | L2-runtime            |
           |                     |      |          read  | execution read        |
           |                     |      |          ----> | L4-sandbox            |
           |                     |      |          cmd   | boundary/run/cleanup  |
           |                     |      |          ----> | L4-observability      |
           |                     |      |          hand  | diagnostic/audit      |
           |                     |      |          ----> | L4-archive            |
           |                     |      |          ref   | restore/archive view  |
           |                     |      +-----------> | L1-work/workspace     |
           |                     |                    | project context       |
           |                     +------------------> | L5-console/sync/chat  |
           |                                          | safe downstream refs  |
           +------------------------------------------+
```

图示是边界方向，不代表所有接口已经存在。Runner 不共享上游数据库事务，不读取 sibling 内部表，不直接订阅未经 SDK 封装的内部 topic；正式 query、command、event、handoff 和 transport 仍须在后续校准中逐项闭口。

## 4. 依赖裁剪表（候选）

| 关联项目 | 全局关系 | Runner 角色 | 依赖类型 | 是否进入主链 | 当前裁剪理由 |
|---|---|---|---|---|---|
| `L0-core` | shared contract base | 条件型编译依赖 | `compile` | 是，待 exact contract | 只使用已正式化的 ref、error、metadata、version 和 visibility 类型；不本地 shadow。 |
| `L0-sdk` | 官方访问封装 | 主要访问边界 | `adapter / runtime` | 是 | 所有 Release、Governance、Runtime、Sandbox、Observability 访问优先走 SDK/正式 client；具体 surface 未闭合前不命名为 ready。 |
| `L1-artifact` | Artifact/Release/version/baseline owner | 只读消费方 | `runtime + ref` | 是，受合同门禁 | 当前已确认 Artifact truth ownership，但 download locator、integrity manifest、Release revoke/expire 消费语义仍 pending。 |
| `L1-governance` | approval/policy/decision owner | 只读 authority consumer | `runtime + ref` | 是，受合同门禁 | Runner 不能本地推断批准；Artifact version/baseline 与 Decision 的正式绑定尚待上游闭口。 |
| `L1-work` | Project/ProjectMember/WorkItem owner | 语境消费者 | `runtime + ref` | 条件 | 只接收项目上下文和安全摘要，不进入运行真相主线。 |
| `L1-workspace` | 跨域只读工作区 owner | 可选 safe-view 消费方 | `runtime + ref` | 否/条件 | 不能用 workspace view 替代 ProjectMember、Release 或 RunnerRun truth；仅在正式 export 面成立后使用。 |
| `L2-runtime` | Runtime execution owner | 运行状态/结果消费者 | `runtime + ref` | 是，受合同门禁 | Runner 不扩展 runtime control；只消费正式状态/结果和恢复提示。 |
| `L4-sandbox` | isolation/execution boundary owner | 正式请求方 | `adapter / runtime + ref` | 是 | 必须使用公开 SDK/adapter；私有 backend、容器实现、宿主句柄均不成为 Runner compile 依赖。 |
| `L4-observability` | observation/diagnostic/handoff owner | 摘要与 handoff 消费方 | `runtime + ref` | 是，受合同门禁 | 只保留安全摘要和 handoff receipt；不保存 raw body 或 evidence body。 |
| `L4-archive` | archive/restore owner | 受限结果消费者 | `runtime + ref` | 否/条件 | 正向 archive 合同未闭合，不能把 archive 状态当运行成功或清理完成。 |
| `L0-bus` | delivery backbone | 间接事件载体 | `event` | 否，除非 SDK 暴露 | Runner 不拥有 delivery/ack/replay truth；本地 cursor 只服务恢复。 |
| `L5-console` / 其他产品 | 下游产品 | safe summary/deep-link consumer | `adapter / ref` | 否 | Runner 不接管 Console 会话和其他产品本地状态。 |

### 4.1 禁止依赖

| 禁止做法 | 原因 | 正确协作方式 |
|---|---|---|
| 直接读取 Artifact/Governance/Sandbox/Observability 数据库或内部表 | 绕过 owner visibility、审计和版本语义。 | 经 SDK、正式 query/command 或评审 adapter。 |
| 通过源码/path 依赖 Sandbox 私有 crate、Docker/gVisor/Firecracker/Tauri 实现 | 把可替换实现变成跨域契约并破坏 isolation owner。 | 只依赖公开 Sandbox API/adapter seam；技术实现后置核验。 |
| 将 `latest`、默认分支或目录中最新文件作为运行版本 | 不可审计、可变且无法证明治理适用性。 | 要求用户显式选择不可变 release/version ref。 |
| 在 Runner 修改 Release、manifest、digest 或 baseline 内容 | 形成第二 Artifact truth，破坏签名和回溯。 | 失败时停止并返回 source ref/诊断。 |
| 把 process alive、HTTP 200、Sandbox ACK 或本地 toast 当运行成功 | 入口/接收/本地状态均不等于执行结果。 | 分离 request、accepted、running、observed、terminal、cleanup。 |
| 把本地 stdout/stderr、telemetry 或截图当正式审计/evidence | 内容可能不完整、未验证、含 secret。 | 仅展示经裁剪 preview，正式证据走 Observability/Artifact owner。 |
| 以 cache、重连或自动重试覆盖 unknown 副作用 | 可能重复启动、重复停止或扩大影响。 | 先查询正式状态，再按明确的 reconcile/control 语义处理。 |

## 5. 可见性、敏感数据与所有权边界

Runner 每个页面或状态卡都必须同时保留：`actor/scope`、选择的 source ref、source version/digest（如可见）、本地观察时间、freshness/coverage、availability、错误类别和下一步动作。一个本地缓存命中只能说明“曾经取得过材料”，不能说明当前仍获授权或可运行。

| 输入 | Runner 允许行为 | Runner 禁止行为 |
|---|---|---|
| actor/session/project context | 建立本次请求语境和 UI 裁剪。 | 解释成员资格、审批角色或项目责任。 |
| Release/version/baseline result | 展示显式选项、版本、来源和可消费姿态。 | 用空列表/缓存/默认值补造 approved 或 baseline。 |
| Governance decision/approval | 显示 applicability、expiry/revocation/conflict 等正式结果。 | 本地 RBAC、默认 allow、把下载成功映射为 approval。 |
| download locator/manifest/digest/signature | 进行本地传输与验证，记录 safe digest/ref。 | 保存 credential、修改正文或绕过验证。 |
| Sandbox/runtime status | 保真显示请求、运行、失败、资源和 cleanup 相关来源状态。 | 把本地 PID、socket 或 ACK 写成 source outcome。 |
| output/capture/diagnostic | 展示裁剪摘要、ref、freshness 和 handoff 状态。 | 将 raw body、secret、完整 stdout/stderr 或 evidence body 作为常驻 truth。 |
| OS resource probe | 显示当前设备的端口/容量/冲突线索。 | 将探针结果宣称为全局 scheduler/host capacity truth。 |

当 visibility、authority、digest、lease、cleanup 或 source status 无法验证时，默认行为必须是遮蔽敏感内容、阻止危险动作、保留可解释错误和安全的恢复入口（`fail-closed`）。

## 6. 历史材料污染审计

| 旧材料 / 说法 | 当前核对结论 | 处置 |
|---|---|---|
| Tauri 优先、Electron 备选、Rust shared runner core | 只是历史技术候选，未经过当前跨平台、SDK、Sandbox adapter 和安全约束核验。 | 不进入 draft 合同；在架构校准阶段重新比较。 |
| Docker / gVisor / Firecracker 由 Runner 直接管理 | 越过 Sandbox owner，且可能把私有实现编译进 Runner。 | 淘汰为直接依赖；仅作为 Sandbox 技术候选的历史输入。 |
| `SandboxService`、`runtime_execution_ref`、`RunControlEntry` 等旧命名 | 可能混合了 Runtime/Sandbox/产品层语义，未形成当前正式合同。 | 仅用于冲突扫描；新文档先使用边界性候选名并等待校准。 |
| `latest`、冷启动 `<30s`、热启动 `<5s`、并发 `≥10`、成功率 `99.9%` | 没有当前 authority 支撑，且会把历史假设伪装成 NFR。 | 全部标为 `historical_candidate / pending_nfr`，不继承。 |
| RunnerRun、提示、队列、health/capability view 作为持久化运行真相 | 把产品层投影越界成 Runtime/Scheduler/Observability truth。 | 只保留为本地展示/意图候选，逐项回到 owner。 |
| retry/replay/cancel/kill/queue/slot 由 Runner 自己执行 | 旧文档把 Runtime、Sandbox、Scheduler 控制混合到产品层。 | Runner 只拥有用户意图和结果展示；真实动作经正式 owner API。 |
| 本地日志回传 Chat、UI telemetry 作为审计证据 | 违反 Observability body-free/evidence 边界。 | 只保留安全 handoff seam 和本地诊断。 |

## 7. 上游 pending / blocker 候选登记

| ID | 未闭合主题 | 对 Runner 的当前上限 |
|---|---|---|
| `RUN-UP-001` | Artifact 尚未提供完整的可下载 Release consumption object、locator/transport seam、integrity manifest、digest/signature 和 revoke/expire 消费合同。 | 只能定义显式选择、adapter seam 和完整性门禁；不能锁具体下载 API、签名算法或传输协议。 |
| `RUN-UP-002` | Governance 尚未正式绑定 Artifact version/baseline 与 approval/decision 的 authority chain、scope、expiry/revoke/conflict 语义。 | 不能本地判断 approved；下载/启动前保持 `blocked/pending`。 |
| `RUN-UP-003` | Sandbox 正式 adapter 的 Runner-facing DTO、请求幂等、active lease、断线恢复、orphan/reaper 和 cleanup 交接仍需逐项闭口。 | 只能承接 `accepted ≠ running`、guard/lease/cleanup 原则；不能声明可运行。 |
| `RUN-UP-004` | Runtime 的端侧消费面、运行状态/结果引用和恢复语义未形成 Runner 专用合同。 | Runner 不扩展 Runtime control；只保留只读 adapter seam。 |
| `RUN-UP-005` | Observability 的安全 diagnostic DTO、handoff 请求/receipt、visibility/freshness 和 retention 交接面未形成 Runner-facing 合同。 | 只能展示 safe summary/handoff 候选；不能把本地诊断写成 evidence/report/verdict。 |
| `RUN-UP-006` | Archive 正向消费/恢复能力和 Runner 交接协议未闭合。 | 不把 archive 状态纳入启动成功、运行成功或清理成功。 |
| `RUN-UP-007` | 跨平台 host resource/port probe、Sandbox resource allocation 和清理责任边界未统一。 | 只定义本地资源视图与冲突 fail-closed；不承诺调度容量、固定端口或平台实现。 |
| `RUN-UP-008` | L0-sdk 的精确 client version、error/redaction/trace surface 尚待核验。 | 只使用 SDK-first 原则，不伪造 method、版本或 fake readiness。 |

## 8. 本篇讨论结论

本篇将 Runner 收束为“端侧已授权软件产物的运行入口与本地运行体验”：它拥有显式选择、下载/cache、完整性验证结果、控制意图、展示状态、资源视图、诊断和恢复姿态；所有发布、治理、执行、隔离、观测、归档和项目真相均由上游 owner 持有。下一篇将沿这一边界推演功能闭环、状态轴和失败语义，第三篇再推演模块、adapter seam、对象类别和可落码前的分层方向。未闭合合同继续保持 `pending / blocked`。

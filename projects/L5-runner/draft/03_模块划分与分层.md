 Cross-cutting: SDK boundary, redaction, idempotency, query no-write,

## 2. 实现分层（候选）

| 分层 | Runner 内职责 | 依赖纪律 |
|---|---|---|
| Product shell / platform host | 窗口/生命周期、导航、权限提示、OS integration、网络/休眠事件。 | 不决定业务 authority；具体桌面壳待架构校准。 |
| Feature modules | 选择、下载、验证、运行控制、preview、diagnostic、recovery 页面/交互。 | 只调用 application facade，不直连数据库或私有上游。 |
| Application orchestration | 编排本地状态、SDK query/command、确认、重查、缓存失效和错误映射。 | 不创建 Artifact/Governance/Runtime/Sandbox truth；unknown 不自动重放。 |
| Domain/local state | RunnerRun、DownloadTask、CacheEntry、IntegrityCheck、ControlIntent、ResourceView、RecoveryCursor 等本地状态与不变量。 | 仅拥有端侧产品状态；所有 source 状态保留 ref/version/digest。 |
| View-model / safety policy | 多轴状态映射、redaction、错误分类、next-step、跨平台展示。 | 不压平 pending/blocked/unknown，不本地推导 approval/readiness。 |
| SDK / formal adapters | Artifact/Release、Governance、Runtime、Sandbox、Observability、Archive、context 的 client seam。 | 只接受正式 API/adapter；不存在的 surface 保持 blocked，不能 fake-ready。 |
| Local persistence / cache | 持久化安全请求、cache metadata、cursor、用户选择和可恢复草稿。 | 不保存 secret/raw body/永久授权；按 scope/version 隔离并可失效。 |
| Resource/OS adapters | 端口、文件、进程、网络、平台能力探针和本地 cleanup handle。 | 只提供观察和受控意图，不替代 Sandbox allocation/cleanup truth。 |
| Diagnostics / redacted telemetry | 安全故障、连接、性能和用户操作诊断。 | 不成为 Observability evidence/audit/verdict；禁止敏感正文。 |
| Test seams | fake SDK、状态机 fixture、故障注入、跨平台 contract harness。 | fake 只证明本地编排和 negative boundary，不证明真实集成。 |

### 2.1 层间依赖图

```text
presentation / platform host
             |
             v
feature modules --> application orchestration --> local domain/state
             |                    |                     |
             |                    v                     v
             +------------> SDK/formal adapters   local persistence/cache
                                      |
             +------------------------+-------------------------+
             v                        v                         v
      Artifact/Governance       Runtime/Sandbox          Observability/Archive

OS/resource adapters and redacted telemetry are side ports;
they may inform local views but never become source-truth providers.
```

禁止反向依赖：presentation 不能调用 owner 数据库；local cache 不能覆盖 source result；adapter 不能把 transport success 映射为 committed；resource probe 不能授予运行资格；diagnostic 不能生成 verdict。

## 3. 关键对象类别（候选）

### 3.1 Runner-owned local truth / state

| 对象类别 | 作用 | 必须保留的来源/边界 |
|---|---|---|
| `RunnerRun` | 一个端侧运行请求和本地生命周期外壳。 | selected release ref、request ref、scope、local version、source status refs；不含 Runtime outcome truth。 |
| `ReleaseSelection` | 用户显式选择和确认语境。 | immutable release/version ref、selection source、authority check ref、invalidated reason。 |
| `DownloadTask` | 一次受限下载过程。 | locator ref、request digest、progress、attempt、transport posture；不证明完整性。 |
| `CacheEntry` | 与 immutable source 绑定的本地材料元数据。 | version/ref、digest、integrity state、protection refs、path abstraction；不存 Release truth。 |
| `IntegrityCheck` | 本地材料验证记录。 | manifest/digest/signature refs、algorithm policy ref、result、checked bytes metadata；不生成 approval。 |
| `SandboxRequestIntent` | 发起正式 Sandbox 请求的用户意图及关联。 | idempotency/correlation、input refs、submitted/receipt posture；不等于 boundary。 |
| `RunnerControlIntent` | start/stop/cancel/cleanup 等端侧控制意图。 | expected source version、impact、request status、reconcile requirement；不等于控制成功。 |
| `ResourceConflictView` | 本地端口/文件/容量冲突的观察结果。 | probe time、resource key hash/ref、owner visibility、resolution hint；不代表全局 scheduler。 |
| `RecoveryCursor` | 断线/重启后的安全读取进度和本地 generation。 | source cursor/version、local generation、lease/reconcile ref；不推进 Bus/owner cursor。 |
| `LocalDiagnosticRecord` | 本地安全诊断和 handoff 关联。 | redacted reason、source refs、trace/correlation、retention class；不成为 audit/evidence。 |

### 3.2 Derived view / presentation values

| 类别 | 作用 | 关键不变量 |
|---|---|---|
| `AuthorityPostureView` | 显示 selected/current/pending/revoked/expired/conflict。 | 只映射 Artifact/Governance 正式结果。 |
| `PreparationPostureView` | 显示 locator/download/integrity/platform readiness。 | `ready` 必须有所有正式前置；不把 cache hit 当 ready。 |
| `ExecutionPostureView` | 显示 request/accepted/boundary/running/terminal/unknown。 | `accepted ≠ running`；terminal 需 source result。 |
| `CleanupPostureView` | 显示 requested/guarded/released/protected/orphan/unknown。 | 未确认不得删除受保护材料。 |
| `OutputPreviewView` | 显示有限摘录、摘要、ref 和 freshness。 | 不包含 raw body/secret，不冒充 Artifact/evidence。 |
| `DiagnosticSummaryView` | 显示安全故障类别、影响和 next-step。 | 不改变 source failure、不给 verdict。 |
| `ConnectivityView` | 显示 online/degraded/offline/reconnecting。 | 不覆盖 source state 或自动重放未知动作。 |

### 3.3 外部引用 / 结果类别

`ReleaseRef`、`ArtifactVersionRef`、`BaselineRef`、`GovernanceDecisionRef`、`SandboxRequestRef`、`BoundaryRef`、`LeaseRef`、`RuntimeRunRef`、`OutputRef`、`DiagnosticRef`、`HandoffRef`、`ArchiveRef` 均只表达安全引用和来源绑定；它们不转移 owner authority，也不允许 Runner 复制正文或重写生命周期。

## 4. 状态组与一致性边界（候选）

### 4.1 多轴状态组

| 状态组 | 候选轴 | 关键规则 |
|---|---|---|
| Selection/authority | `none / selected / checking / current / stale / revoked / expired / conflict / blocked` | 非 `current` 不得进入启动资格；选择状态不等于 approval。 |
| Download/cache | `absent / resolving / transferring / paused / incomplete / quarantined / verified / invalid / stale / evicted` | 只有 source authority current + cache verified 才可提交 Sandbox。 |
| Request/control | `not_sent / submitting / accepted / pending / rejected / confirmed / unknown` | accepted 只是 receipt；unknown 需 reconcile，不自动重放。 |
| Execution display | `not_started / starting / running / stopping / terminal / unknown` | running/terminal 必须来自正式 Runtime/Sandbox status/result。 |
| Resource/cleanup | `available / conflict / reserved / protected / requested / released / orphan / blocked / unknown` | probe、reservation、lease、cleanup 各自独立。 |
| Output/diagnostic | `none / partial / available / stale / restricted / blocked / unavailable` | 摘要可用不等于证据成立。 |
| Connectivity/recovery | `online / degraded / offline / reconnecting / reconciliating / manual_review` | 连接状态不覆盖业务状态；side effect 在未知时冻结。 |

### 4.2 关键一致性规则

1. 一个 `RunnerRun` 必须绑定一个显式 immutable release/version ref；改变选择必须产生新 generation，不能就地改写已发出的请求。
2. Download、Integrity、Authority、Sandbox Request、Execution、Cleanup 是独立状态组；任何投影不得用单字段 `status=success` 代替它们。
3. Query、刷新、分页、重连和渲染均 no-write 于上游 truth；本地 cursor/generation 变化不等于 owner 状态变化。
4. `accepted`、`verified`、`boundary_established`、`running`、`terminal`、`cleaned` 各有独立来源和证据边界，不能由邻近状态推导。
5. source version/digest、lease epoch、expected local version 和 idempotency key 不匹配时，写路径必须停止并返回 `stale/conflict/unknown`。
6. active lease、capture、handoff、retention 或 orphan 保护存在时，cache/运行目录不得被淘汰；cleanup guard 未通过时不释放资源。
7. 本地诊断只能保留 body-free、redacted ref 和有限摘要；任何 raw output/secret 都不得进入持久化 Runner truth。

### 4.3 建议的事务 / 交接边界

| 边界 | Runner 本地可原子化内容 | 明确不跨越 |
|---|---|---|
| Selection generation | 选择、scope、authority check request、旧选择失效标记 | 不原子化 Governance/Artifact truth。 |
| Download promotion | incomplete/quarantine bytes metadata、integrity result、cache promotion marker | 不修改 Release/manifest/baseline。 |
| Control intent | intent、correlation、local status、reconcile marker | 不把本地提交与 Sandbox/Runtime effect 合并。 |
| Recovery checkpoint | local cursor、generation、last safe source refs、connectivity posture | 不推进 Bus/owner cursor，不关闭未知副作用。 |
| Cleanup candidate | 用户清理意图、保护检查结果、待确认 marker | 不绕过 lease/retention/cleanup guard。 |
| Diagnostic handoff | redacted summary、source refs、handoff request/receipt marker | 不创建 Observability evidence/report/verdict。 |

## 7. 配置与安全边界预演

后续 `04` 只能配置运行时选择和体验策略，例如下载并发上限类别、缓存保留分类、redaction profile、平台 capability allowlist、诊断采样和连接退避类别；不得配置化改变 truth owner、绕过 authority/签名/lease/cleanup、把 unknown 变 success、启用 `latest` 或关闭安全日志交接。

敏感配置、credential、locator secret、签名密钥和外部正文不进入 Runner 文档示例或本地日志。配置缺失、schema 不支持、source contract 未闭合时应 fail-fast 或保持 `blocked`，不能以宽松默认值启动。

## 9. 跨模块红线审计

| 红线 | draft 防线 |
|---|---|
| RunnerRun 变成 Runtime/Sandbox truth | RunnerRun 只保存本地请求和展示状态，所有 source status 通过 ref 回指。 |
| Release 被本地修改或使用 latest | 显式 immutable selection + authority gate；cache 不能替代。 |
| Sandbox ACK 被当运行成功 | request、boundary、running、terminal、cleanup 多轴分离。 |
| Query/刷新触发 repair 或副作用 | 所有 read/reconnect/render no-write；repair/reconcile 必须是正式 owner 语义。 |
| 本地日志变成 audit/evidence | redaction-first、body-free、Observability handoff；本地 telemetry 仅诊断。 |
| 资源探针变成 scheduler truth | probe、allocation、lease、cleanup 独立表达。 |
| 旧技术选择回流 | 框架、容器、transport、性能数值全部标 historical/pending。 |
| fake/placeholder 证明 ready | fake 只验证本地逻辑；正向 real seam 未闭合即 blocked。 |

## 10. 本篇结论

Runner 的候选模块可归纳为：**语境与资源、Release authority、下载/cache、完整性、Sandbox 控制、RunnerRun 展示、输出预览、诊断 handoff、清理保护、断线恢复**。实现分层坚持 product/application/local-state/view-model/SDK-adapter/persistence/platform/telemetry/test-seam 的方向；状态按 authority、download、request、execution、cleanup、output、connectivity 多轴表达。下一步若获得用户确认，应先建立 Runner 专属 calibration flow 和 project ledger，再从正式 `00` 的 SOP Step 1 开始；在此之前不创建正式设计、实现台账或 boundary skeleton。

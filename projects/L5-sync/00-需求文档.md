## 1. 与上游文档的关系声明

> 校准来源：
> - `design-calibration/00_req_step_01_upstream_relationship.md`
>
> 延伸阅读：请阅读上述文件的“结构化来源映射”和“历史材料污染诊断”。

L5-sync 承接产品层对 L5 本地开发工作区入口的定位、全局依赖规则对 Layer 5 并行窗口的约束，以及 `L0-sdk`、`L1-identity`、`L1-work`、`L1-governance`、`L1-artifact`、`L1-workspace`、`L4-archive` 和 `L4-observability` 的当前正式 owner 边界。

本文只细化“平台正式来源如何被本地工作区安全消费、观察、增量更新并交给正式 Review handoff”这一窄域。Project、Artifact、Baseline、Review Gate、Workspace projection、Archive、身份授权、Git remote 和观测/验收真相仍由各自 owner 负责；Sync 只拥有一次本地同步操作的局部状态。

README、旧正式 `00/01/02/03/05/06` 和旧 draft 只作为 `historical_material` 或污染审计输入，不直接定义当前需求、接口、技术选择或指标。

## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_scope_boundary.md`
>
> 延伸阅读：请阅读上述文件的“边界声明表”和“相邻概念易混淆边界”。

`L5-sync` 是平台与本地开发工作区之间的受控同步入口：在用户显式选择 project/version/source 且 principal、权限、来源和本地目标均可验证时，初始化、观察、增量更新和准备 review handoff，并维护本地 session、metadata、cursor、mapping、冲突、恢复和 provenance 关联。

它不是 Project、Artifact、Baseline、Review Gate、Workspace projection、Archive 或 Git remote truth owner；不是跨 chat/console/runner 的统一状态同步器、bus delivery/replay 协调器或跨端一致性中心；不是 Git 替代品，也不自动 merge、rebase、push 或覆盖用户未提交修改。

| 主题 | L5-sync 拥有 | 只消费/回链 | 禁止拥有或执行 |
|---|---|---|---|
| session | 本地同步尝试、阶段、幂等关联和恢复点 | 外部 correlation、source ref、probe 结果 | 平台任务、业务生命周期或治理 verdict |
| working copy | 本地目标绑定、Git/filesystem 观察、受控 materialization 记录 | Artifact/Workspace source ref 与版本语境 | Workspace projection、Artifact 正文、Git remote truth |
| metadata | 受控 `.qs-sync` provenance、generation、mapping、cursor 关联 | owner ref、版本/水位、迁移提示 | 伪造/静默删除 provenance；credential 入 metadata |
| conflict/recovery | dirty-state 保护、冲突记录、checkpoint、unknown outcome 关联 | Git/fs 观察和外部 probe | 自动 merge/rebase/push、强制覆盖、盲重试 |
| review handoff | 本地候选冻结/准备和提交 attempt | Review Gate 接收/decision 状态 | 接受、批准、signoff、Baseline 创建 |
| project posture | 本地可执行性缓存和失效标记 | Project/Archive 正式姿态 | 猜测 active、绕过 archived/dissolved 限制 |

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：请阅读上述文件的“现状与问题”和“业务问题与技术问题”。

Quantalithos 的平台事实和治理流程主要存在于服务侧，但开发者、项目接手人和评审者仍需要在本地 IDE、Git 和文件系统中检查、补充和验证代码类产出。本地工作流必须继续服从显式项目/版本选择、权限和 Review Gate，而不能退化为脱离平台上下文的普通 Git 目录。

当前主要问题是：用户可能从目录、默认分支、Git remote 或旧缓存猜测上下文；本地 dirty/untracked 修改可能被覆盖；来源分叉和 metadata 漂移缺少统一冲突语义；本地 commit、上传成功或 HTTP/transport ACK 容易被误读为 Artifact/Baseline 或 Review accepted；网络中断、版本缺口和结果不确定时盲目重试会重复副作用；权限撤销、归档项目和 provenance 缺口需要安全停止。

| 分类 | 问题 |
|---|---|
| 业务问题 | 用户需要在本地开发效率与平台治理之间建立可解释的受控桥；本地修改回流必须仍进入正式 Review Gate。 |
| 业务问题 | 项目/版本/来源选择必须由用户显式确认，权限、归档姿态和 provenance 不能由本地工具猜测。 |
| 技术问题 | platform source cursor、local applied cursor、Git HEAD/working tree、handoff ACK 和 Review decision 需要分层表示。 |
| 技术问题 | 增量更新、mapping、冲突、断点恢复和 unknown outcome 需要可重入且不覆盖 dirty worktree 的行为边界。 |
| 技术问题 | SDK、Artifact/Workspace、Governance、Archive 与 Git/filesystem seam 尚未全部闭合，精确接口需后置核验。 |

## 4. 目标与非目标

> 校准来源：
> - `design-calibration/00_req_step_04_goals_non_goals.md`
>
> 延伸阅读：请阅读上述文件的“目标表”和“非目标表”。

### 4.1 目标

| ID | 目标 | 判断口径 |
|---|---|---|
| `G-SYNC-001` | 每次操作绑定显式 project、version/source 和本地目标。 | 缺少选择或绑定失效时 blocked/needs-action，不从目录、分支或缓存猜测。 |
| `G-SYNC-002` | principal、项目姿态、权限和来源资格在 materialization/handoff 前可解释。 | 认证、权限、归档或来源未知时不产生危险副作用。 |
| `G-SYNC-003` | working copy 初始化、status、增量 pull 和 provenance 具有可追溯的局部结果。 | 能分开 source/local cursor、Git 状态、metadata generation 和操作结果。 |
| `G-SYNC-004` | dirty 修改、来源分叉、映射冲突和 metadata 不一致得到显式保护。 | 冲突可见、可暂停、可恢复并等待人工决定；不覆盖 dirty worktree。 |
| `G-SYNC-005` | `push-review` 只形成正式 Review handoff。 | ACK、远端对象或本地 commit 不单独表示 accepted/approved/signoff。 |
| `G-SYNC-006` | 外部调用中断或 unknown outcome 可安全探测和恢复。 | 重试前有 probe/幂等关联；无法证明等价时 blocked/needs-action。 |
| `G-SYNC-007` | 归档、权限撤销和 provenance 失效会收紧可执行范围。 | 失效/撤销/归档项目不能凭旧缓存继续操作。 |
| `G-SYNC-008` | Git/filesystem 适配不改变平台 truth。 | adapter 只观察和受限 I/O；merge/rebase/push 不自动发生。 |

### 4.2 非目标

| ID | 非目标 | 归属/理由 |
|---|---|---|
| `NG-SYNC-001` | 拥有或修改 Project、ProjectMember、Artifact、Baseline、Review Gate、Workspace projection 或 Archive。 | 由相应 L1/L4 owner 负责。 |
| `NG-SYNC-002` | 把本地 Git commit、remote branch、上传 ACK 或 HTTP 成功当平台 truth。 | 这些只是本地或传输观察结果。 |
| `NG-SYNC-003` | 自动 merge、rebase、push、stash、覆盖用户修改或替用户做冲突决定。 | 冲突和副作用决策必须显式。 |
| `NG-SYNC-004` | 成为跨产品同步协调器、bus delivery/replay owner 或 Workspace read-model owner。 | 超出本仓窄域。 |
| `NG-SYNC-005` | 在需求阶段锁定 Rust/Tauri、Git LFS、浅克隆、数据库、固定 metadata 布局或性能数字。 | 当前缺少 authority，后置核验。 |
| `NG-SYNC-006` | 保存外部正文、credential、token、私钥或正式 evidence/report 正文。 | 只保留必要快照和安全引用。 |
| `NG-SYNC-007` | 生成 review verdict、acceptance、signoff、evidence、report 或 readiness。 | 由治理/观测/验收 owner 负责。 |

## 5. 用户与角色

| 角色 | 类型 | 主要场景 | 需求层边界 |
|---|---|---|---|
| 开发者/项目成员 | 人类 | 显式选择项目和版本、初始化工作副本、pull、status、处理冲突、发起 push-review。 | 受正式 Project/ProjectMember 权限和 Review Gate 规则约束。 |
| 项目接手人/代码评审者 | 人类 | 接收既有来源、在本地检查和修改、准备候选交给 review handoff。 | 不获得 Artifact/Baseline 创建权或 Gate 接受权。 |
| 支持/工作区维护者 | 人类 | 处理 metadata 损坏、恢复、路径冲突、unknown outcome 和归档姿态提示。 | 只能修复/重绑允许的本地状态，不得伪造 provenance 或上游真相。 |
| 审计/安全查看者 | 人类 | 查看来源绑定、操作关联、冲突和 handoff 的安全摘要。 | 只读，不能通过 Sync 批准、上传或绕过 Gate。 |
| 产品/SDK 调用方 | 系统/调用方 | 以正式 SDK/API 消费 status、source binding、handoff 状态和安全诊断。 | 不因消费 Sync 读面获得 truth ownership。 |

| Git/filesystem 环境 | 外部系统 | 提供 HEAD/index/tree、路径、dirty 状态、锁和工具能力。 | 只构成本地观察边界，不成为平台 truth。 |
| Sync 本地维护任务 | 系统 | 恢复 metadata、记录 checkpoint、重算 local status、探测 unknown outcome。 | 不修复 owner truth、不自动 merge/rebase/push、不伪造业务成功。 |

## 6. 使用方与依赖

> 校准来源：
> - `design-calibration/00_req_step_06_consumers_dependencies.md`
> - `design-calibration/00_req_step_12_interfaces_dependencies.md`
>
> 延伸阅读：请阅读上述文件的“依赖裁剪表”“依赖类型分类表”和“外部能力依赖边界表”。

| 关联方 | Sync 消费/提供的能力 | 全局依赖类型 | 主链状态与边界 |
|---|---|---|---|
| `L0-core` / `L0-sdk` | shared ref/error/trace 与正式平台访问 | 编译期/运行期 | 精确 surface 未核验前不锁方法名；不得绕过 SDK。 |
| `L1-identity` | principal、认证语境和身份引用 | 运行期/ref | 身份未知即 blocked；不拥有 credential/identity truth。 |
| `L1-work` | Project、ProjectMember、权限、项目姿态 | 运行期/ref | 无正式结论不继续；不创建项目或成员。 |
| `L1-governance` | Review handoff、接收/查询和 decision ref | 运行期/ref | ACK 不等于 accepted；协议未闭合只能准备候选。 |
| `L1-artifact` | Artifact/version/source、manifest 和增量来源 | 运行期/ref | 不复制正文/版本链；comparator/locator 缺失则 blocked。 |
| `L1-workspace` | 条件性的 Workspace projection/source binding 摘要 | 运行期/ref | 不把 local working copy 当 projection。 |
| `L4-archive` | archived/dissolved/retired posture 和安全 ref | 运行期/ref | posture 未知 fail-closed；不执行 archive mutation。 |
| `L4-observability` | redacted diagnostic/correlation（若合同允许） | 运行期/事件（条件） | 不证明业务成功或 Review verdict。 |
| Git CLI/library | HEAD/index/tree、工具能力和受限本地动作 | 外部 adapter | remote truth 不纳入；merge/rebase/push 不自动。 |
| filesystem/OS | 路径、锁、原子 I/O、dirty/untracked 观察 | 外部 adapter | 路径/权限/本地修改未知时停止。 |

### 6.1 依赖裁剪图

```text
 principal / Project / posture
          | runtime/ref
          v
      +---+---------------------+
      |        L5-sync          |
      | local session + copy    |
      | cursor/conflict/handoff |
      +---+----------+----------+
          ^          ^
          |          |
  Artifact/Workspace | Git/filesystem
  source/version     | local observation/I/O
          |          |
          +----+-----+
               v
       Governance Review Gate
       handoff/decision ref

 L0-sdk/L0-core = formal access/shared contracts
 L4-archive      = conditional posture/ref
 L4-observability= conditional diagnostics only
```

### 6.2 禁止依赖

- 读取上游内部表、共享数据库或跨仓事务。
- 直接订阅任意 bus topic，或拥有 delivery/replay truth。
- 把 Git remote branch/commit 当 Artifact/Baseline。
- 把上传 ACK、HTTP 200、日志或 trace 当 Review accepted。
- 依赖 GUI、LFS、浅克隆作为核心闭环前置。
- 以本地缓存代替 identity/work/governance 权限结论。

## 7. 核心能力闭环

> 校准来源：
> - `design-calibration/00_req_step_07_core_capability_loop.md`
>
> 延伸阅读：请阅读上述文件的“核心能力闭环图”和“能力节点与停审清单”。

```text
显式主体 / 项目 / 版本选择与权限语境
              |
              v
正式来源绑定与本地工作副本安全初始化
              |
              v
只读观察、增量获取与本地 materialization 保护
              |
              v
冲突检测、人工决策、断点恢复与幂等探测
              |
              v
候选冻结、Review handoff 与 provenance 回链
              |
              v
可解释 status / 诊断 / 归档姿态失效处理
```

| 节点 | 能力名称 | 成立/退出条件 |
|---|---|---|
| `CP-SYNC-01` | 显式选择与访问语境 | 选择、权限、项目姿态和来源资格可解释；否则 denied/blocked/needs-action。 |
| `CP-SYNC-02` | 来源绑定与 working-copy 初始化 | source/version/target/generation/provenance 形成可回链 binding；目标或 metadata 不安全则停止。 |
| `CP-SYNC-03` | status、增量获取与 materialization | status 只读；pull/clone 只应用可验证增量并记录 local applied cursor；dirty/缺口不覆盖。 |
| `CP-SYNC-04` | 冲突保护与恢复 | 冲突可见并等待人工决定；安全步骤可恢复；副作用 unknown 先 probe。 |
| `CP-SYNC-05` | Review handoff 与 provenance | 候选可冻结并交给正式 Gate，记录 transport/handoff ref；ACK 不升格 accepted。 |
| `CP-SYNC-06` | 结果分层、归档姿态与诊断 | 分开报告 cursor、Git、transport、decision、archive posture；失效时 fail-closed。 |

批量预取、多工作区比较、归档浏览和 GUI 属于外围增强；创建/修改上游真相、跨端 replay、自动 merge/rebase/push、正式 verdict/evidence/report/readiness 属于边界外能力。

## 10. 业务规则与边界约束

> 校准来源：

| ID | 类型 | 规则 |
|---|---|---|
| `BR-SYNC-001` | 不变量 | 每次操作必须绑定明确 principal、project、version/source、target 和 operation。 |
| `BR-SYNC-002` | 禁止行为 | 不得以 `latest`、默认分支、目录最新文件、Git remote 或旧缓存猜测上下文。 |
| `BR-SYNC-003` | 边界约束 | 权限、项目姿态、来源可见性和允许动作必须来自正式 owner；不得本地 default allow。 |
| `BR-SYNC-004` | 禁止行为 | owner 结论 unknown/stale/revoked/archived/dissolved/conflicting/unsupported 时不得产生危险副作用。 |
| `BR-SYNC-005` | 不变量 | working-copy binding 必须回指 source/version/target/generation/provenance。 |
| `BR-SYNC-006` | 禁止行为 | 不得覆盖 dirty/untracked 或无法解释的本地修改；不得自动 stash/merge/rebase。 |
| `BR-SYNC-007` | 显式变化 | metadata 初始化、迁移、重绑、失效和修复必须可解释；不得静默删除或伪造 provenance。 |
| `BR-SYNC-008` | 不变量 | platform cursor、local cursor、Git HEAD/commit、working-tree、handoff transport 和 Review decision 必须分离。 |
| `BR-SYNC-009` | 禁止行为 | status/query 不得隐式 refresh、推进 cursor、修复冲突或改变上游状态。 |
| `BR-SYNC-010` | 边界约束 | 无 comparator、增量 cursor、mapping 或 gap/replay 语义时 pull 必须 blocked/needs-action。 |
| `BR-SYNC-011` | 不变量 | 冲突必须保留来源、路径/映射、依据、影响和恢复关联，并等待人工/owner 决策。 |
| `BR-SYNC-012` | 禁止行为 | 不得自动 merge/rebase/push、强制覆盖、删除冲突证据或把无冲突推断为 accepted。 |
| `BR-SYNC-013` | 显式变化 | 外部副作用调用遵循 prepare→call→probe/finalize；unknown 先探测。 |
| `BR-SYNC-014` | 不变量 | 等价输入的重复操作必须可解释、可回链并幂等；无法证明等价不得自动重放。 |
| `BR-SYNC-015` | 边界约束 | `push-review` 只提交候选 handoff；commit、ACK、HTTP 200 或 remote object 不等于 Artifact/Baseline/accepted/approved/signoff。 |
| `BR-SYNC-016` | 禁止行为 | 不得绕过 Review Gate、直接写主分支、修改 Governance decision 或产生 verdict。 |
| `BR-SYNC-017` | 不变量 | 归档/撤销/source 失效优先于本地缓存；重新验证失败时 fail-closed。 |
| `BR-SYNC-018` | 边界约束 | provenance、source ref、工具/路径关联和恢复历史不得伪造、静默抹除或无记录重绑定。 |
| `BR-SYNC-019` | 禁止行为 | 不得保存/输出外部 raw 正文、credential、token、私钥或敏感 evidence/report 内容。 |
| `BR-SYNC-020` | 边界约束 | Git/filesystem adapter 仅执行白名单观察、锁、路径保护和原子 materialize；remote truth 不归 Sync。 |
| `BR-SYNC-021` | 不变量 | local session/status/conflict/recovery 只描述本地同步操作，不冒充平台业务生命周期。 |
| `BR-SYNC-022` | 边界约束 | 诊断、telemetry、handoff receipt 和 cache 不单独证明同步成功、Review accepted 或 readiness。 |
| `BR-SYNC-023` | 禁止行为 | 不得通过共享数据库、内部表、任意 bus、私有 endpoint 或跨仓事务绕过正式 seam。 |
| `BR-SYNC-024` | 显式变化 | 用户冲突决定、继续 materialize、重绑或提交 handoff 必须可见并形成新的本地关联。 |
| `BR-SYNC-025` | 边界约束 | LFS、浅克隆、GUI/Tauri、批量预取等待核验，不得改变核心安全门禁或被宣称已支持。 |

## 11. 数据需求与数据归属

> 校准来源：
> - `design-calibration/00_req_step_11_data_ownership.md`
>
> 延伸阅读：请阅读上述文件的“数据归属总表”和“数据生命周期与保护”。

| 数据主题 | 类型 | L5-sync 口径 |
|---|---|---|
| session、阶段、attempt、幂等关联 | Sync-owned truth | 解释一次本地同步操作；不等于平台 job。 |
| working-copy binding、路径安全、工具能力 | Sync-owned truth | 绑定本地目录与受限 adapter；随环境/重绑失效。 |
| source/local cursor、generation、mapping、coverage | Sync-owned truth | 记录本地来源应用进度；不等于 bus delivery 或 Artifact authority。 |
| 冲突记录、影响、依据、人工决定关联 | Sync-owned truth | 保护 dirty/source/metadata 冲突并保留历史。 |
| checkpoint、probe、handoff attempt、transport outcome | Sync-owned truth | 支持恢复和结果分层；不证明外部最终成功。 |
| `.qs-sync` provenance metadata | Sync-owned truth（形态 pending） | 回链 source/version/path/tool/generation/handoff；不得静默伪造/抹除。 |
| identity/project/permission/posture、Artifact/Workspace source/version 摘要 | owner snapshot | 带 source/version/freshness；stale/partial/restricted/unavailable 不当 current。 |
| Governance/Archive/Observability handoff、decision、diagnostic ref | safe reference | 只保留最小安全引用和状态，不转移 owner。 |
| Artifact/Workspace/Review/Archive/Git 正文、credential、token、私钥、raw stdout/stderr、evidence/report 正文 | 禁止保存正文 | 不进入本地持久化、status、日志或 handoff。 |

快照失效、撤销或归档时必须收紧本地操作；清理只能作用于可删除的 Sync-owned 局部状态，不得抹除受保护 provenance、冲突证据或来源链。

### 12.2 外部依赖边界

Sync 依赖 `L0-core/L0-sdk` 的正式访问与 shared contract；消费 `L1-identity`、`L1-work`、`L1-artifact`、`L1-workspace`、`L1-governance`、`L4-archive` 和 `L4-observability` 的能力级结果；使用 Git/filesystem 作为本地 adapter。查询必须 no-write，变更只表达意图和局部结果，事件/后台任务不得取得额外 truth ownership。

CLI 精确命令/参数/退出码、HTTP/RPC/SDK 方法、DTO/JSON/proto、事件 payload、port/adapter trait、repository、数据库、metadata 字段/目录、重试/锁/事务、LFS/浅克隆/GUI 均后置到后续设计阶段重新校准。

## 13. 非功能需求

> 校准来源：
> - `design-calibration/00_req_step_13_nonfunctional.md`
>
> 延伸阅读：请阅读上述文件的“能力级质量约束”和“全局非功能需求”。

| 非功能类别 | 要求 | 判断口径/目标值 |
|---|---|---|
| 性能 | 本地编排、来源检查、增量更新和 handoff 准备不应成为不可解释的主链瓶颈。 | 后续按权威 workload 量化 P95/P99、规模、带宽、并发和恢复时限；当前不承诺数字。 |
| 可用性 | owner/网络/Git/fs 失效、冲突或归档变化时仍提供安全状态和下一步。 | 允许 blocked/pending/unknown/unsupported；不以降级为成功。 |
| 安全 | 不得越权拥有 Project、Artifact、Baseline、Review、Workspace、Archive、Git remote truth 或敏感正文。 | owner 单一；unknown、不可见和冲突 fail-closed。 |
| 审计/可追溯 | 选择、binding、materialization、冲突、恢复、handoff 和姿态变化可回链。 | 关键 local result 有 source/correlation/provenance；不声称正式 audit/evidence。 |
| 幂等/一致性 | source/local cursor、Git 状态、transport、handoff 和 Review decision 不得混为单一状态。 | 重复、重连和刷新不隐式改变 owner truth；unknown 保持可见。 |
| 可观测性 | 本地异常和安全边界可形成低敏、有限诊断材料。 | 不含 credential/raw body/私钥；observability 失效不改变业务结果。 |

能力级约束包括：显式版本和权限不得由缓存补齐；metadata/provenance 不得未知重绑；dirty/conflict/unknown 必须暂停；handoff ACK 与 Review decision 分离；诊断 redacted/bounded。旧材料固定的可用性、吞吐、延迟、LFS、浅克隆和 GUI 数字没有当前 authority，不作为目标值。

### 14.1 一票否决项

- `VETO-SYNC-001`：自动 merge、rebase、push、stash、覆盖用户未提交修改或盲重放未知副作用。
- `VETO-SYNC-002`：把本地 commit、上传 ACK、HTTP 200、remote object、日志或 cache 当作 Artifact/Baseline/Review accepted/approved/signoff。
- `VETO-SYNC-003`：Sync 创建、修改或伪造 Project、Artifact、Baseline、Review Gate、Workspace projection、Archive 或 Git remote truth。
- `VETO-SYNC-004`：metadata/provenance、冲突证据、credential 或外部正文被删除、伪造、泄露或静默重绑定。
- `VETO-SYNC-005`：权限、归档、来源或 comparator unknown 时仍执行危险 materialization/handoff。

本节定义未来判断，不表示已有实现、测试、artifact、report、evidence、verdict、signoff 或 readiness。

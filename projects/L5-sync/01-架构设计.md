## 2. 业务背景与驱动力

> 校准来源：
> - `design-calibration/01_arch_step_02_arch_goals_constraints.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“架构目标表”“不可变约束表”和“当前阶段可接受取舍表”。

AI 产出进入本地 IDE 后，平台 owner truth、本地用户修改、Git 状态和正式治理链会同时存在。若没有独立架构边界，pull 可能覆盖本地修改，Git commit 或上传 ACK 可能被误当成平台 Artifact/Review 结果，恢复可能在 unknown outcome 下重复副作用，provenance 也可能退化成无法审计的日志。

`L5-sync` 的结构性驱动力是：让开发者保留本地 Git/filesystem 工作方式，同时让项目选择、来源版本、权限、增量应用、冲突、恢复和 Review handoff 仍受平台正式 owner 约束。

| 架构目标 | 说明 |
|---|---|
| 承载可解释的本地同步操作真相 | session、cursor、冲突、恢复与 handoff 必须可回链，不能散落在 Git 或日志中。 |
| 守住平台 owner 与本地 working copy 的边界 | Sync 不复制或反写 Project、Artifact、Workspace、Review、Archive 或 Git remote truth。 |
| 支撑“观察—门禁—应用—记录”的安全主路径 | 权限、来源、版本、映射和 dirty 状态未确认时不得产生危险副作用。 |
| 允许人工冲突裁决和可探测恢复 | 冲突与 unknown outcome 必须可暂停、探测和人工处理。 |
| 让 Review handoff 与正式 decision 可区分 | transport ACK 或 HTTP 成功不得被显示为 accepted/approved。 |
| 让 Git/filesystem 与 SDK 适配可替换 | 技术变化不得反向控制 local core 或平台 owner。 |
| 让 provenance 与诊断可审计但不吸收敏感正文 | 追溯不能以保存 credential、正文或正式 evidence 为代价。 |

## 3. 约束条件

> 校准来源：
> - `design-calibration/01_arch_step_01_requirements_baseline.md`
> - `design-calibration/01_arch_step_02_arch_goals_constraints.md`
>
> 延伸阅读：建议阅读两份中间产物的“架构硬约束”“阶段取舍”“架构非目标”和“自检”。

### 3.1 不可变约束

| 约束 | 说明 |
|---|---|
| 不拥有 Project、Artifact、Baseline、Review Gate、Workspace projection、Archive 或 Git remote truth | 外部对象仍由各正式 owner 管理。 |
| 不自动 merge、rebase、push、stash，不覆盖 dirty/untracked | 用户本地修改与人工冲突裁决不可绕过。 |
| 不把本地 commit、ACK、HTTP 200、remote object、日志或 cache 当业务接受 | Git、transport、handoff、decision 必须分层。 |
| status/query 不产生隐式写入 | 查询不得 refresh source、推进 cursor、修复 metadata 或改变上游。 |
| owner unknown/stale/revoked/archived/dissolved/conflicting 时 fail-closed | 旧缓存不得授权危险动作。 |
| 未证明副作用等价时不自动重放 | unknown outcome 必须先 probe 或转人工处理。 |
| 不删除、伪造或静默重绑定 provenance | metadata 迁移、修复、重绑均须可解释。 |
| 不以共享数据库、内部表、任意 bus、私有 endpoint 或跨仓事务绕过 seam | 保护依赖方向和单一 truth。 |

### 3.2 当前阶段可接受取舍

| 取舍 | 当前口径 |
|---|---|
| 工作区范围 | 先闭合单个显式绑定工作区；多工作区批处理仅作外围能力。 |
| 来源范围 | 逐来源执行门禁；批量预取不得放宽单来源检查。 |
| Git 工具范围 | 只锁观察、锁、路径保护和原子应用能力；具体工具矩阵后置。 |
| 大仓策略 | LFS、浅克隆和专用优化保持 pending，不作当前承诺。 |
| metadata 形态 | 只锁受控、版本化、可回链方向；字段、布局和迁移待确认。 |
| GUI / Web IDE | 可作未来入口壳层，不进入核心同步语义。 |

### 3.3 架构非目标

| 非目标 | 不展开原因 |
|---|---|
| 设计 Project/Artifact/Baseline/Review/Workspace/Archive 内部架构 | 它们有各自 owner，本仓只消费正式边界。 |
| 设计 Git remote/server truth 或 VCS 替代品 | 本仓只适配本地 working copy 与正式 handoff。 |
| 设计自动 merge/rebase/push 或自动冲突裁决 | 与需求红线冲突。 |
| 设计认证、统一权限中心或治理裁决 | Sync 只执行正式检查和转交。 |
| 设计 GUI、LFS、浅克隆的具体产品/实现 | 当前需求与支持矩阵未闭合。 |
| 设计字段、schema、命令 parser、数据库或测试用例 | 属于后续设计文档。 |

## 4. 职责边界

> 校准来源：
> - `design-calibration/01_arch_step_03_responsibility_boundary.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“职责边界表”“边界红线清单”和“架构单元职责停审记录”。

### 4.1 职责边界表

| 职责项 | 类型 | 说明 |
|---|---|---|
| 本地同步语境与 operation lifecycle | 做 | 管理显式选择、阶段和本地结果，不代表平台业务生命周期。 |
| working-copy binding 与受控 metadata/provenance | 做 | 将本地目录、source/version、generation 和工具关联起来。 |
| 来源资格与权限检查编排 | 做 | 调用正式 owner seam；不拥有权限 truth。 |
| source materialization orchestration | 做 | 组织全量/增量读取和安全应用；不拥有来源正文。 |
| Git/filesystem observation 与受限 apply | 做 | 观察 dirty/path 状态并执行白名单原子应用。 |
| conflict、checkpoint、recovery 和 probe | 做 | 保留本地操作语义和人工决定关联。 |
| Review handoff preparation/attempt | 做 | 冻结候选、发起 handoff、记录 transport/probe ref。 |
| 分层诊断和 archive posture 展示 | 做 | 输出 bounded/redacted 状态，不生成 evidence/verdict。 |
| Project/ProjectMember/Artifact/Baseline truth | 不做 | 这些业务对象由 `L1-work` / `L1-artifact` 管理。 |
| Workspace projection truth | 不做 | 本地 working copy 不能替代 `L1-workspace` projection。 |
| Review Gate/Decision/accepted truth | 不做 | 由 `L1-governance` 裁决，Sync 只交接与读取。 |
| Archive package/recovery truth | 不做 | 由 `L4-archive` 管理，Sync 只消费 posture/ref。 |
| Git remote/branch policy truth | 不做 | remote 与分支策略不归 Sync。 |
| authentication/authorization policy truth | 不做 | 只消费正式判断并 fail-closed。 |
| local working copy 与 Workspace projection | 易混淆职责 | 前者是本地目录事实，后者归 `L1-workspace`。 |
| local commit 与 Artifact/Baseline | 易混淆职责 | commit 只属 Git 语境，平台对象归 `L1-artifact`。 |
| handoff attempt 与 Review decision | 易混淆职责 | attempt 属本地操作，decision 归 `L1-governance`。 |
| local access snapshot 与 permission truth | 易混淆职责 | snapshot 不授权，正式 owner 结论才是门禁输入。 |

### 4.2 边界红线

- Git adapter 不得暴露自动 merge/rebase/push/stash 或任意命令执行能力。
- handoff attempt、transport ACK、probe outcome 和 Review decision 不得合并成一个 `success`。
- metadata 迁移、重绑、失效和修复不得静默删除或伪造 provenance。
- dirty/untracked/path protection 或 source comparator unknown 时必须停止或转人工。

| SDK formal boundary | 外部运行期边界 | owner checks/source/handoff/probe/read | 同步调用为主，具体协议 pending | 不替换为私有 endpoint/shared DB。 |

### 7.3 部署结论

当前是随本地开发环境部署的客户端边界，不要求独立线上后端、业务数据库、共享缓存或直接 bus。入口、编排和恢复职责可同进程，但能力必须隔离；未来 GUI 只能作为复用同一 core 的入口，不得复制核心逻辑。

## 8. 依赖方向与层间约束

> 校准来源：
> - `design-calibration/01_arch_step_07_dependency_direction.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“内部依赖方向图”“跨仓依赖裁剪”“禁止依赖”和“停审记录”。

### 8.1 内部依赖方向

```text
+----------------------------+
| command / interaction entry|
+-------------+--------------+
              v
+-------------+--------------+
| application orchestration  |
+------+------+--------------+
       |      |
       v      v
+------+--+  +----------------+
| local   |  | capability     |
| core    |  | ports          |
+---------+  +-------+--------+
                     ^
                     |
             +-------+---------+
             | SDK / Git / fs  |
             | state adapters  |
             +-----------------+
```

图示说明：

1. 箭头表达依赖方向，不表达运行调用顺序。
2. Adapter 实现由 core 定义的 port；core 不依赖 concrete SDK/Git/fs/store。
3. Entry 不得直接获得外部 mutation capability。

### 8.2 层间约束

| 架构责任层 / 依赖角色 | 允许依赖 | 禁止依赖 | 说明 |
|---|---|---|---|
| Entry | application contracts、safe result | Git/SDK/store concrete mutation | 所有副作用交给 application orchestration。 |
| Application | local core、capability ports | 私有 owner endpoint、shared DB、任意 shell | owner/tool/fs 只能通过 ports 接入。 |
| Local core | shared value/ID/error/correlation 候选 | SDK concrete client、Git/fs/network/storage concrete | 由 core 定义的 ports 隔离外部设施。 |
| Ports | local semantic types | provider body/schema、UI concern | 只表达本地所需的有限能力。 |
| Adapters | ports、SDK/tool/fs concrete facilities | 改写 core invariant 或裁决 owner truth | 只翻译和执行，不决定业务语义。 |

### 8.3 本仓依赖裁剪表

| 关联项目/边界 | 本仓角色 | 依赖类型 | 是否主链 | 裁剪口径 |
|---|---|---|---|---|
| `L0-core` | 依赖方 | 编译期候选 | 是 | shared IDs/refs/errors/trace；精确使用后置 |
| `L0-sdk` | 依赖方 | 编译期 + 运行期 | 是 | 正式 owner capability 入口；surface pending |
| identity/work/artifact/workspace/governance/archive | 依赖/交接方 | 运行期（经 SDK） | 是 | 不形成 sibling 源码或数据依赖 |
| local Git/filesystem | 依赖方 | 本地运行期 | 是 | 白名单 observation/lock/path/apply |
| observability | 协作方 | 运行期/telemetry | 是 | bounded/redacted，不决定 success |
| `L0-bus` | 间接关系 | 事件协作 | 否 | 当前不直接订阅；未来需正式 SDK/owner contract |

### 8.4 本仓禁止依赖表

| 禁止依赖 | 原因 | 正确协作方式 |
|---|---|---|
| Core → SDK/Git/fs concrete implementation | 技术反向控制核心语义 | ports + inward adapters |
| Sync → sibling 源码/private endpoint/owner DB | 破坏单一 truth 与版本边界 | `L0-sdk` 正式 seam |
| Entry/UI → mutation adapter | 绕过应用门禁 | application orchestration |
| Git adapter → platform decision | 工具状态不能定义业务 truth | owner decision via SDK |

### 8.5 依赖裁剪图: L5-sync

```text
+-----------------------+
| L5-sync               |
+----+------------------+
     +--> [compile] L0-core
     +--> [compile/runtime] L0-sdk
     +--> [runtime via SDK] identity / work / artifact / workspace
     +--> [runtime via SDK] governance / archive
     +--> [runtime] local Git / filesystem
     +--> [runtime] observability boundary
     -X-> [event] direct L0-bus (not in current mainline)
```

图示说明：

1. 只有 `[compile]` 可进入 package dependency；runtime/event 不得误写为 path dependency。
2. 所有 sibling owner 默认经 SDK 正式运行期边界。
3. 直接事件协作被裁剪出当前主线。

## 9. 数据所有权与一致性策略

> 校准来源：
> - `design-calibration/01_arch_step_08_data_ownership_consistency.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“数据归属表”“按架构单元的数据所有权表”“一致性策略”和“跨数据边界审计”。

### 9.1 数据归属

| 数据项 | 数据类型 | 归属说明 | 边界说明 |
|---|---|---|---|
| session / operation phase | local truth | L5-sync | 不等于平台 lifecycle。 |
| binding / metadata generation | local truth | L5-sync | 只描述 local target/source relation。 |
| local applied cursor / mapping | local truth | L5-sync | 不等于 platform latest 或 Git HEAD。 |
| conflict / checkpoint / recovery | local truth | L5-sync | 不自动裁决或证明外部成功。 |
| handoff attempt / transport / probe association | local truth | L5-sync | 不等于 Gate/Decision/accepted。 |
| provenance / bounded diagnostic history | local truth | L5-sync | 不等于 formal evidence。 |
| principal/project/access/posture | snapshot/reference | 外部 identity/work owner | source/freshness required；不得 default allow。 |
| Artifact/Workspace source/version/watermark | snapshot/reference | Artifact/Workspace owner | source priority/comparator pending。 |
| Review Gate/Decision | reference/snapshot | Governance owner | read only；ACK 不改变 decision。 |
| Archive posture/package ref | reference/snapshot | Archive owner | 不复制 package/recovery body。 |
| Git HEAD/branch/index/worktree/remote | observation/reference | Git/local user/remote owner | Sync 只保存受限 observation。 |
| owner bodies/credentials/raw evidence/report/log | forbidden body | 外部 owner/secret systems | 不保存、不输出、不进入 metadata truth。 |

### 9.2 版本与游标角色

platform/source version、local applied cursor、Git HEAD/commit、working-tree status、metadata generation、handoff transport 和 Review decision 是不同语义。任何一项都不能作为另一项的隐式替代；尤其 Git commit 不等于 Artifact/Baseline，ACK 不等于 Review decision。

### 9.3 一致性策略

| 数据关系 / 场景 | 关联数据类型 | 一致性口径 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| binding generation 与 metadata integrity | local truth | local transition strong consistency | 不切 generation，保留旧安全状态或 blocked | 不锁具体存储实现。 |
| apply result 与 local cursor | local truth + Git/fs observation | local atomic visibility | outcome 不明时 cursor 不宣称推进，进入 recovery | 防止 cursor 超前掩盖损坏。 |
| conflict/checkpoint/provenance | local truth | local strong association | 缺依据时 blocked/manual-review | 冲突不能退化为错误字符串。 |
| frozen candidate 与 source/binding | local truth + source ref | freeze-bound consistency | drift/dirty/generation change 使候选失效 | handoff 前重新验证。 |
| owner snapshot 与 mutation | external snapshot/ref | eventual + pre-effect revalidation | stale/unknown 时不执行危险副作用 | cache 仅用于显示，不授权。 |
| handoff 与 Review decision | local truth + external ref | eventual, explicitly layered | ACK/timeout 只更新 transport/probe | 不以 HTTP 成功代替 accepted。 |
| duplicate/reconnect/retry | local correlation | idempotent local correlation | 等价未证明则 probe/manual-review | 不盲目重放外部副作用。 |

### 9.4 数据边界图

```text
 external owner truth                  local L5-sync truth
 +--------------------+              +-------------------------+
 | project/source/    | --ref/snap-->| session/binding/cursor  |
 | review/archive     |              | mapping/conflict/checkpt|
 +--------------------+              | handoff/provenance      |
                                     +------------+------------+
                                                  |
                                                  v
                                     +------------+------------+
                                     | Git/filesystem working  |
                                     | copy observations       |
                                     +-------------------------+
```

图示说明：

1. 外部 owner 只以 ref/snapshot 进入，不将正文或 truth 复制给 Sync。
2. Local truth 只解释同步操作，并经受限 seam 观察/应用 working copy。
3. Local cache/state 不得反写外部 owner decision。

## 10. 关键交互与通信方式

> 校准来源：
> - `design-calibration/01_arch_step_09_interactions_communication.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“关键交互场景表”“按架构单元的通信判断”和“跨交互边界审计”。

### 10.1 关键交互场景

| 交互场景 | 交互边界 | 交互目的 | 边界说明 |
|---|---|---|---|
| explicit select/access | Entry ↔ Selection/SDK owner | 建立明确 session 与资格检查关联 | unknown/denied 时 blocked，不用 cache 授权。 |
| bind working copy | Application ↔ SDK source + local state + Git/fs | 建立或更新 binding generation | dirty/metadata ambiguity 时停止，不隐式重绑。 |
| status | Entry ↔ local state/Git/fs + optional owner read | 分层观察 source/local/Git/conflict/handoff | 不推进 cursor、不修复状态。 |
| clone/pull materialize | Application ↔ source read/comparator + Git/fs | 安全应用全量或增量来源 | gap/dirty/conflict 时 pause/manual。 |
| conflict/recovery | Application ↔ local state/Git/fs + probe | 保存冲突与恢复关联并决定是否续行 | 不自动解决或盲重放。 |
| push-review prepare | Application ↔ local observation + Governance capability | 重新检查并冻结候选 | dirty/drift/archived 时 blocked。 |
| handoff call/probe | Application ↔ Governance via SDK | 发起候选交接并探测 unknown outcome | transport/probe 不等于 decision。 |
| decision/posture read | Entry ↔ Governance/Archive/Observability | 读取外部结果、姿态和诊断关联 | ACK 不升格 accepted，观测不决定成功。 |

### 10.2 通信方式判断

| 交互场景 | 推荐通信方式 | 不宜采用的方式 | 失败处理口径 | 说明 |
|---|---|---|---|---|
| explicit select/access | 同步 owner query | cache/default allow | unknown/denied → blocked | 危险操作前需要当前资格结论。 |
| bind working copy | 同步 owner read + local atomic write | 后台隐式重绑 | dirty/ambiguity → stop | binding generation 必须与 local state 原子关联。 |
| status | 只读同步查询 | 隐式 refresh/repair | stale/unknown 分层显示 | 查询不得产生写副作用。 |
| clone/pull materialize | 分段同步 + 本地可续工作 | 事件触发自动 apply | gap/dirty/conflict → pause/manual | 长时工作可续，但每段仍服从门禁。 |
| conflict/recovery | 本地同步 + probe/manual | 自动 merge 或 blind retry | no proof → manual | 人工决定与 probe 结果必须留痕。 |
| push-review prepare | 同步重新检查和冻结 | 直接 Git push | drift/archived → blocked | 正式 handoff 前冻结明确候选。 |
| handoff call/probe | 同步 call + 可续 probe | timeout 后直接重放 | unknown → pending/manual | 使用 prepare→call→probe/finalize。 |
| decision/posture read | 只读 owner query | 以 ACK/telemetry 推断结果 | stale/unknown 分层显示 | 外部 owner 仍拥有 decision/posture truth。 |

当前不直接依赖内部事件。未来事件只能提示 stale/source/posture/review 变化，不能自动应用 working copy、推进 cursor 或决定 accepted。

### 10.3 简化交互图

```text
User intent -> Entry -> owner checks -> Application
                                      |
                                      +-> source read/compare -> Git/fs apply
                                      |                         -> checkpoint/cursor
                                      +-> conflict/recovery -> probe/manual
                                      +-> freeze -> handoff call
                                                   -> ACK / probe / decision read
```

图示说明：

1. 图表达交互类型和结果层，不表达 API/schema/thread。
2. Source apply、local checkpoint 和 Review decision 是不同结果。
3. Probe/manual 处理 unknown，不是隐式重试。

## 11. 关键技术选型

> 校准来源：
> - `design-calibration/01_arch_step_10_technology_choices.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“关键技术机制表”“技术适用表”和“当前不采用口径”。

### 11.1 关键技术机制

| 技术机制 | 解决的问题 | 采用理由 | 代价 / 约束 | 说明 |
|---|---|---|---|---|
| Ports / adapters | 隔离 SDK、Git/fs、store 与 local core | 遵守依赖倒置并保留设施可替换性 | seam 与校验成本增加 | 当前采用的架构机制，不锁具体库。 |
| Explicit context + fail-closed gate | 防止 implicit latest/default allow | 对齐显式选择和 owner 资格规则 | 用户需显式选择 | unknown 不产生危险副作用。 |
| Local transition/checkpoint model | 防止 partial success并支持恢复 | local truth 需要可回链阶段语义 | 状态迁移需严格审计 | 不以 Git commit 或日志代替。 |
| Source vs working-copy separation | 防止覆盖用户修改与双真相 | 对齐 Artifact/Workspace owner 与 dirty protection | comparator/mapping 合同 pending | 合同不明时 materialization blocked。 |
| Prepare/call/probe/finalize | 处理 external unknown outcome | 避免 timeout 后盲重放 | probe 合同 pending | 等价未证明时转人工。 |
| Layered result semantics | 区分 Git/transport/decision/archive | 防止低层成功升格为业务接受 | 输出模型更复杂 | status 与 handoff 均使用分层结果。 |
| Redaction-first / forbidden body | 保护正文与 secret | 对齐 forbidden-body 与 provenance 边界 | 排障材料需 bounded | telemetry/diagnostic 不生成 verdict。 |

### 11.2 当前不采用

| 方向 | 当前口径 |
|---|---|
| Rust/Tauri | 不作当前架构结论；实现语言和 GUI 支持待后续合同与需求。 |
| Git LFS / 浅克隆 | 不作支持承诺；需 source/Git compatibility 和 workload 证据。 |
| 常驻 daemon | 不作默认部署形态。 |
| 直接 L0-bus 订阅 | 不进入当前主链。 |
| 共享数据库 / 私有 endpoint | 禁止作为跨仓 seam。 |
| 自动 merge/rebase/push | 违反需求红线，不是未来优化。 |

## 12. 备选方案与取舍

> 校准来源：
> - `design-calibration/01_arch_step_11_alternatives_tradeoffs.md`
>
> 延伸阅读：建议继续阅读上述中间产物的“方案路径比较表”“当前主线方案”和“取舍结论”。

### 12.1 方案路径比较

| 方案路径 | 解决的问题 | 主要收益 | 主要代价 / 约束 | 当前结论 | 说明 |
|---|---|---|---|---|---|
| 受控本地桥 | 平台 owner 与本地 working copy 的安全协作 | 独立 dirty/path gate、local provenance/cursor、checkpoint/probe、handoff 分层 | 状态和 seam 较多，部分场景需 pending/manual | 采用 | 在不吞并外部 truth 的前提下同时闭合 non-overwrite、恢复和 Review Gate。 |
| 纯 Git 脚本/插件 | 以熟悉工具快速搬运文件 | 初期实现低、最接近 Git 心智 | 保护依赖脚本纪律，provenance/cursor 退化为 commit/log，容易绕过 owner/Gate | 不采用 | 无法稳定承载本地同步操作 truth。 |
| 远程全能同步服务 | 集中控制版本、权限与同步 | 远端可集中治理和观测 | 远端/本地协调复杂，副作用面大，易吞并多个 owner 或形成第二平台 truth | 不采用当前主线 | 偏离本地受控入口定位，并引入高耦合远程承载。 |

### 12.2 取舍结论

采用受控本地桥，牺牲部分“一键自动化”和较低初始复杂度，换取 non-overwrite、owner 单一真相、unknown 可恢复、Review Gate 不绕过和结果分层。Project/Artifact/Workspace/Archive 内部实现、Git server、GUI、LFS backend 等不是本仓架构备选。

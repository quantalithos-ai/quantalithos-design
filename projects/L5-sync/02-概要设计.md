| `HC-SYNC-14` | candidate freeze-bound | source/binding generation/local observation/digest 漂移使候选失效 |

| `HC-SYNC-17` | ports/adapters + whitelist | 不直连 owner DB/private endpoint/arbitrary shell/bus |

### 4.1 架构模块到代码主体映射图

```text
L5-sync controlled local synchronization
├─ Selection & Access
│  ├─ SelectionAccessService / OperationEligibilityPolicy
│  └─ OwnerAccessPort / OwnerReferenceStore
├─ Working Copy & Metadata
│  ├─ WorkingCopyService / MetadataMaintenanceService
│  └─ MetadataStore / LocalStateUnitOfWork / local observation ports
├─ Source Materialization
│  ├─ MaterializationService / MaterializationPlan
│  └─ MaterialSourcePort / GitWorktreePort / FilesystemApplyPort
├─ Conflict & Recovery
│  ├─ ConflictRecoveryService / RecoveryProbeService
│  └─ RecoveryProbePort / checkpoint and conflict repositories
└─ Review Handoff & Provenance
   ├─ ReviewHandoffService / ProvenanceService
   └─ ReviewHandoffPort / ReviewDecisionReadPort / DiagnosticsPort
```

关键说明：

- 五个顶层名称是业务主要组成部分；其下名称是 planned skeleton，不表示已有文件/类。
- External owner refs 是共享支撑，不成为第六个业务 truth 组成部分。
- `OperationCoordinator` 与 `SyncStatusQueryService` 横跨五部分，只编排/读取，不增加 ownership。

### 4.2 实现分层视图

```text
CLI / maintenance trigger / SDK-facing query
                       │
                       ▼
Inbound / Operations
CloneCommandEntry / PullCommandEntry / StatusQueryEntry / PushReviewCommandEntry
                       │
                       ▼
Application Services
OperationCoordinator + five-part services + SyncStatusQueryService
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
Domain Model / Policies          Ports
local truth + guards             owner / source / handoff / Git / fs / diagnostics
             │                   ▲
             ▼                   │
Local metadata persistence       Adapters
MetadataStore / UnitOfWork       SDK / Git / filesystem / observability
```

关键说明：

- 一个业务部分跨多个实现层；同一层可承接多个部分，二者不能混用。
- Entry 只解析 intent/展示 typed result；所有 mutation 经 Application + Domain guard。
- Domain 不依赖 concrete SDK/Git/fs/store；adapter 实现 inward-defined ports。
- Query 只组合 persisted truth、允许的 read-only observation 与 snapshot，不隐式 refresh/repair。

### 4.3 分层主体

| 层 | 主体 | 作用 |
|---|---|---|
| Inbound / Operations | 四 CLI entries、`MetadataMaintenanceEntry`、`RecoveryOperationsEntry` | 解析显式输入、映射安全结果 |
| Application | coordinator、五部分 services、`SyncStatusQueryService` | 编排门禁、transitions 与 ports |
| Domain | `SyncOperation`、29 对象/guards/policies/views | local truth/invariant/typed state |
| Ports | owner/source/handoff/probe、Git/fs、store、diagnostics | core 所需最小能力 |
| Persistence | `MetadataStore`、`LocalStateUnitOfWork`、repositories/views | 保存 `.qs-sync` 逻辑主题 |
| Adapters | SDK、Git、filesystem、metadata、diagnostics | 翻译正式 facility，执行白名单动作 |

|---|---|---|---|
| Selection & Access | explicit context、owner eligibility/posture、pre-effect revalidation | `SelectionAccessService`、policy、access port | auth/authorization、Project lifecycle |

### 5.2 各部分交互总图

```text
Explicit user intent
        │
```

### 5.3 Selection & Access

核心 capabilities：建立 immutable selection 和 local operation；读取 owner eligibility/posture；mutation 前 revalidate；只读展示 persisted access slice；正式合同存在时消费 invalidation。对象候选为 `SyncOperation`、`SyncSelection`、`AccessEvaluation`、`OperationEligibilityPolicy`、`ExternalOwnerSnapshot`。

接缝：向 CP2 提供 selection/operation/refs，向 CP3/CP5 提供 current eligibility，并为 CP4 resume 重新验证。禁止从 path/remote/branch/cache/latest 推断语境，禁止本地授权或执行 archive mutation。

### 5.4 Working Copy & Metadata

核心 capabilities：inspect target；init binding/manifest；load/validate metadata；显式 migrate/repair/rebind；维护 cursor/mapping；只读 local observation/status slice。对象候选为 binding、manifest、cursor、mapping、observation 和两个 safety/integrity policies。

接缝：从 CP1 接受显式语境；向 CP3 提供 generation/cursor/mapping/observation；通过 CP4 处理 partial/unknown；向 CP5 提供 candidate freeze anchors。禁止 query 写入、silent rebind、provenance 删除和任意 Git/fs command。

### 5.5 Source Materialization

核心 capabilities：resolve source；compare source/local cursor；build/validate plan；apply controlled changes；仅在 proven result 上 finalize；显式恢复 local-safe stage。对象候选为 `MaterializationPlan`、`SourceDelta`、`PathChangeSet`、`MaterializationRun` 和 safety policy。

接缝：消费 CP1 eligibility 与 CP2 local anchors；所有 dirty/path/gap/partial/unknown 转 CP4；向 CP5 提供 body-free provenance facts。禁止创造 source priority/comparator、把 Git commit 当平台版本或在 unknown 时推进 cursor。

### 5.6 Conflict & Recovery

核心 capabilities：classify conflict；capture checkpoint；record manual intent；evaluate resume；prepare/probe unknown；cancel local continuation；只读 conflict/recovery slice。对象候选为 conflict、checkpoint、manual resolution、probe 和 recovery policy。

接缝：从 CP1/CP2 获取 current context，从 CP3/CP5 获取 failed/unknown attempts；安全恢复返回 owning part 的新 operation/plan，不能在 recovery 内绕过原门禁。禁止自动 merge/rebase/stash/overwrite、blind replay 或用 telemetry 当 probe。

### 5.7 Review Handoff & Provenance

核心 capabilities：inspect/freeze candidate；prepare durable attempt；call/probe/read official handoff；assemble layered status；append protected provenance；emit bounded diagnostics。对象候选为 candidate、attempt、provenance、两个 policies 和两个 views。

接缝：联合 CP1 eligibility、CP2 generation/observation、CP3 source/materialization refs、CP4 conflict/probe facts。任何 drift 使 candidate 失效；transport 与 Decision 只用 safe refs 关联。禁止创建/批准 Gate、Git push、ACK elevation、secret/body/evidence fabrication。

跨部分审计结论：共享对象 `SyncOperation`、`ExternalOwnerSnapshot`、`SyncStatusView` 各有唯一主责；所有 mutation 经过 owning policy 与 CP2 local UoW；对象→§6、接口→§7、流→§8、状态→§9、异常→§10、配置→§11 均有明确落点。

### 6.1 CP1 Selection & Access

#### 6.1.1 `SyncOperation`

##### 基本信息

CP1 local aggregate/correlation anchor；表达一次显式 mutation/maintenance 的本地阶段，不是平台 job、Project 或 Review lifecycle。来源：创建 operation、恢复和 handoff 关联。

##### 关键字段

| 字段 | 类型 | 作用 |
|---|---|---|
| `operation_id` | `SyncOperationId` | 本地 identity |
| `operation_kind` | `SyncOperationKind` | Clone/Pull/PushReview/MetadataMaintenance/Recovery 等 |
| `selection_ref` | `SyncSelectionRef` | 固定显式选择 |
| `state` | `SyncOperationState` | operation 状态轴 |
| `correlation_ref` | `CorrelationRef` | 低敏关联 |
| `active_checkpoint_ref` | `Optional<RecoveryCheckpointRef>` | 当前恢复点，不证明外部完成 |
| `last_transition_ref` | `OperationTransitionRef` | 最近显式迁移/provenance |

##### 状态集合

`Planned`、`Validating`、`Ready`、`Running`、`NeedsAction`、`Completed`、`Cancelled`、`FailedKnown`。`Completed` 只表示 local operation 已知终局。

##### 成员函数

| 函数 | 参数 | 作用 |
|---|---|---|
| `begin_validation` | `AccessEvaluationRef evaluation_ref` | 进入校验 |
| `mark_ready` | `EligibilityProofRef proof_ref` | policy 允许时 Ready |
| `begin_stage` | `OperationStage stage`、`RecoveryCheckpointRef checkpoint_ref` | 进入明确阶段 |
| `require_action` | `NeedsActionReason reason`、`ConflictRecordRef conflict_ref` | 暂停并暴露下一动作 |
| `complete_local_result` | `LocalOperationResultRef result_ref` | 记录本地终局 |
| `cancel` | `ActorRef actor_ref`、`CancellationReason reason` | 显式取消并保留 history |

##### 工厂函数

`plan_mutation(SyncOperationId operation_id, SyncOperationKind operation_kind, SyncSelectionRef selection_ref, CorrelationRef correlation_ref, ObservedAt started_at)`。

##### 禁止事项

禁止把 `Completed` 解释为 Artifact/Baseline/Review accepted/readiness；禁止为 `status` query 持久化 operation；禁止从本对象推断权限或外部副作用结果。

#### 6.1.2 `SyncSelection`

##### 基本信息

CP1 immutable value object；固定 principal/project/version/source/target/operation，不复制外部实体。

##### 关键字段

| 字段 | 类型 | 作用 |
|---|---|---|

### 6.3 CP3 Source Materialization

#### 6.3.1 `MaterializationPlan`

##### 基本信息

##### 关键字段

| 字段 | 类型 | 作用 |

##### 状态集合

| 函数 | 参数 | 作用 |

##### 工厂函数

`draft(MaterializationPlanId plan_id, SyncOperationRef operation_ref, WorkingCopyBindingRef binding_ref, MetadataGeneration binding_generation, AccessEvaluationRef access_evaluation_ref, SourceDeltaRef source_delta_ref, PathChangeSetRef path_change_set_ref, ContentFingerprintRef precondition_fingerprint_ref, Optional<SourceCursorRef> target_cursor_ref)`。

##### 禁止事项

禁止在 source authority/comparator/mapping 缺失或 dirty/path unknown 时 Validated；禁止 plan 自动执行、修改 metadata 或触发 merge/rebase；禁止跨 selection/binding/generation/observation 复用。

##### 禁止事项

##### 禁止事项

| `checkpoint_partial` | `RecoveryCheckpointRef checkpoint_ref`、`SafeFailureSummary failure_summary` | 保留 partial |

##### 禁止事项

#### 6.3.5 `MaterializationSafetyPolicy`

### 6.6 对象闭环

29 个对象的主责分布为 CP1=5、CP2=7、CP3=5、CP4=5、CP5=7。plan 与 outcome、owner snapshot 与授权、candidate/transport/probe/Decision、local cursor 与 source/Git state 均保持分离；`SYNC-UP-001~010` 仅限制正向合同，不允许删减 typed blocked/unsupported/needs-action/probe-required 路径。

### 7.1 分类与共享语境

| 类别 | 适用性与语义 | 必需上下文 | 硬边界 |

### 7.8 条件性 consumers、无 outbound events 与 jobs

当前正式 01 不以 `L0-bus` 为主链。以下 consumers 只有 owner 的正式 SDK/event contract 闭合后才可启用；当前均为 `blocked/planned`。

| Consumer | 正式来源 | 输入 | 本地结果 | 禁止 |
|---|---|---|---|---|
| `ConsumeAccessOrPostureInvalidated` | Identity/Work/Archive | `AccessOrPostureInvalidatedEvent event`、envelope/event id/idempotency key | snapshot/evaluation stale；plan/candidate invalidation intent | 不自动取消或写 owner |
| `ConsumeMaterialSourceInvalidated` | Artifact/Workspace | `MaterialSourceInvalidatedEvent event`、envelope/event id/idempotency key | source/cursor continuity unknown；plan/candidate stale | 不自动 pull/apply |
| `ConsumeReviewDecisionChanged` | Governance | `ReviewDecisionChangedEvent event`、envelope/event id/idempotency key | safe Decision snapshot/ref update | 不产生或重解释 Decision |

Consumer 只有在 source attribution、event identity、schema compatibility 与 dedup contract 全部成立时写 local invalidation/snapshot；payload 正文不落 metadata，也不得触发 Git/fs mutation、handoff retry 或冲突自动决定。

当前没有 outbound event：local CLI operation、metadata transition、conflict 和 handoff attempt 不自动广播成平台事实；因而不创建 outbox/topic/delivery state。若未来引入，必须回退 00/01/02 重审消费者、payload、可靠性和 ownership。

| Job | typed input / result | 安全边界 |
|---|---|---|
| `ScanMetadataIntegrity` | `MetadataIntegrityScanInput input` → `MetadataIntegrityScanResult result` | 只读/分类 records；不 repair/migrate/delete provenance |
| `ProbePendingHandoffAttempts` | `PendingHandoffProbeInput input` → `PendingHandoffProbeJobResult result` | 仅已有 ProbeRequired attempts；不重放 submit、不生成 verdict |
| `MarkStaleOwnerSnapshots` | `SnapshotStalenessScanInput input` → `SnapshotStalenessScanResult result` | 可标 stale/invalidated；不 owner refresh、不把 TTL 当授权规则 |

每个 job 另带 `SystemActorContext actor`、`JobMetadata metadata`、`IdempotencyKey idempotency_key`。不存在自动 pull、auto-merge、auto-push-review、自动 conflict resolution、provenance cleanup 或 Git remote sync job。

### 7.9 Port / Adapter 总边界

| Port / boundary | Adapter family | 最小能力 | 明确禁止 | 合同状态 |
|---|---|---|---|---|
| `OwnerAccessPort` | L0-sdk identity/work/archive | principal/project/member/posture/action safe result | 本地授权、private endpoint、cache allow | `SYNC-UP-001/003` blocked |
| `MaterialSourcePort` | L0-sdk artifact/workspace | locator/version/cursor/delta/comparator safe result | 发明 source priority、copy owner body | `SYNC-UP-001/002/008` blocked |
| `ReviewHandoffPort` / `ReviewDecisionReadPort` | L0-sdk governance | submit/probe/read safe ref/result | ACK-as-Decision、越权 Gate mutation | `SYNC-UP-001/004/005` blocked |
| `MetadataStore` / `LocalStateUnitOfWork` | `.qs-sync` persistence | generation-checked load/transition/commit | secret/body、silent rebind/delete | `SYNC-UP-006` physical schema blocked |
| Git observation/worktree ports | Git tool | local HEAD/index/tree/dirty/capability、白名单 apply | remote truth、push/merge/rebase/stash/arbitrary shell | `SYNC-UP-007/009/010` pending/blocked |
| Filesystem inspect/apply ports | OS/filesystem | canonical path、symlink/permission/lock、stage/commit | path escape、dirty overwrite、provenance deletion | `SYNC-UP-010` exact contract blocked |
| `RecoveryProbePort` | owner-specific probe adapter | prior attempt 的 known/unknown probe | blind replay、telemetry inference | `SYNC-UP-004/005` blocked |
| `DiagnosticsPort` | L4-observability-neutral adapter | body-free correlation/safe failure | evidence/report/verdict/readiness | boundary stable；surface 受 `SYNC-UP-001` |

Clock、ID 和 bounded digest provider 也是 local infrastructure adapters，但不能作业务 truth 或 security decision。

### 7.10 接口闭环

Command、Query、Consumer、Event、Job 五类已逐项判断：四个 P0 CLI 有唯一用例；所有 Get/List/Status/Inspect 纯读；refresh/probe/migrate/rebind 均显式写入口；conditional consumers 不冒充现有集成；outbound event 明确不适用；所有 adapter 都由 inward-defined ports 约束。`SYNC-UP-001~010` 阻断真实方法、payload/topic、物理 schema、exact Git/fs operations 和 CLI flags/exit codes，但不改变上述 fail-closed 接口形状。

## 8. 关键处理流 / 重要函数数据流

> 校准来源：
> - `design-calibration/02_hld_step_08_processing_flows.md`
>
> 延伸阅读：建议继续阅读上述文件的“通用处理流骨架与覆盖清单”、各 CP“处理流停审”“跨处理流一致性审计”和“未独立展开处理流的取舍”。

以下图是 planned data/control-flow contract，不证明 service、transaction、adapter 或 recovery 已实现。图中的 local UoW 只约束本地可见性，不声称 SDK、Git、filesystem 和 metadata store 构成跨设施事务。

### 8.1 四类通用处理流

#### 8.1.1 Mutation 写路径

```text
Typed Command
  → Inbound：校验 explicit context / actor / metadata / idempotency
  → Application：读 local state，CP1 revalidate，副作用前 durable operation/checkpoint/attempt
  → Domain + Ports：generation/fingerprint/conflict/provenance hard gates，有限 facility call
  → LocalStateUnitOfWork：只提交 known local transition；unknown 保留 checkpoint/probe-required
  → Typed Command Result
```

关键说明：

- Entry 不直接获得 adapter/store mutation capability；所有 effect 均经过 application 与 domain gate。
- External/local effect 前先建立 durable correlation；unknown 只能形成 checkpoint/probe-required。

#### 8.1.2 Query 读路径

```text
Typed Query
  → Query Inbound：校验 actor / query metadata / visibility
  → Query Service：读 persisted truth；仅明示时作 read-only Git/fs observation
  → View：保留 stale/unknown/unsupported/blocked，bounded redaction
  → Typed View Result
  → No Write / No Refresh / No Probe / No Diagnostic Emission
```

关键说明：

- 缺失 slice 保持 Missing/Unknown，不退化成 empty、clean 或 success。
- Read completeness 与业务状态分开；bounded redaction 不得改变来源状态。

#### 8.1.3 条件性 Consumer 路径

```text
Formal Owner Event
  → Consumer：验证 envelope/event-id/source/schema/dedup
  → Invalidation Service：提取 safe refs，不复制 body
  → Snapshot/Evaluation/Plan/Candidate：stale/invalidated 或 safe Decision ref
  → LocalStateUnitOfWork：dedup + local invalidation
  → Consumer Result / No Automatic Apply, Resolve, Retry or Handoff
```

关键说明：

- 当前 consumer 合同均未闭合，该路径只是 `blocked/planned` skeleton，不授权订阅私有 topic。
- Consumer 只提交 local invalidation/ref，不自动 apply、resolve、retry 或 handoff。

#### 8.1.4 Operations Job 路径

```text
Job Trigger
  → Job：读 persisted target set / metadata / idempotency
  → Application：逐 target 重验 job eligibility
  → Policy + Limited Port：scan / formal probe / stale classification
  → LocalStateUnitOfWork：保存 per-target typed result
  → Job Result / No Owner Repair / No Batch-success Elevation
```

关键说明：

- System actor 不获得用户 Command 或 owner mutation 权限。
- Batch completion 不覆盖 per-target blocked/unknown，也不形成 evidence/readiness。

### 8.2 CP1 Selection & Access 处理流

#### 8.2.1 `SharedMutationEligibilityGate`

```text
Mutation Command
  → construct SyncSelection.from_explicit_refs(...)
  → OwnerAccessPort.check_eligibility(request, context)
  → capture minimal ExternalOwnerSnapshot
  → OperationEligibilityPolicy.evaluate(selection, owner_results, evaluation_time)
  ├─ fresh Eligible → persist evaluation/snapshot/operation relation → eligible context
  └─ unknown/stale/denied/blocked → typed blocker / no protected side effect
```

关键说明：

- 该 gate 嵌入每个 mutation，不能产生可离线复用的 authorization token。
- 目标 stage 改变或副作用临近时再次 revalidate；`SYNC-UP-001/003` 未闭合则 fail-closed。

#### 8.2.2 `ConsumeAccessOrPostureInvalidated`

```text
AccessOrPostureInvalidatedEvent
  → validate envelope / source / schema / dedup
  → locate snapshot/evaluation and affected refs
  → invalidate snapshot; mark evaluation stale
  → invalidate unexecuted plan/frozen candidate
  → commit dedup + local invalidation
  → no owner mutation / no file deletion / no automatic external cancellation
```

关键说明：

- 进行中的 effect 进入 CP4 checkpoint/needs-action；已完成历史不删除。
- 本流在正式 event contract 前保持 blocked，不执行 owner mutation、file deletion 或 external cancellation。

#### 8.2.3 `MarkStaleOwnerSnapshots`

```text
SnapshotStalenessScanInput
  → read persisted freshness/source-version per snapshot
  → apply SnapshotFreshnessRule
  → mark Stale/Unknown only
  → commit per-target transition/blocker
  → SnapshotStalenessScanResult
```

关键说明：

- 时间/TTL 只能收紧状态，不能证明 Fresh 或重新授权。
- Job 不调用 owner refresh、materialization 或 handoff。

### 8.3 CP2 Working Copy & Metadata 处理流

#### 8.3.1 `CloneWorkingCopy`

```text
CloneWorkingCopyCommand
  → CloneCommandEntry validates actor/metadata/idempotency/explicit selection
  → OperationCoordinator + SharedMutationEligibilityGate
  → FilesystemPort.inspect_target + read-only WorkingCopyObservation
  → WorkingCopySafetyPolicy.evaluate_target
  → prepare Initializing binding/manifest/cursor/mapping/checkpoint/provenance root
  → resolve full source → build/validate plan → controlled local apply
  ├─ proven apply + same generation → atomic local finalize → CloneWorkingCopyResult
  └─ conflict/partial/unknown → Restricted/Initializing + checkpoint → typed needs-action
```

关键说明：

- Target inspection 先于任何 metadata/file mutation；非空、dirty、ambiguous binding 或 unsafe path 不自动接管。
- 成功上限只是 local working-copy finalize，不表示 Artifact/Baseline 或平台 readiness。

#### 8.3.2 `MigrateSyncMetadata`

```text
MigrateSyncMetadataCommand
  → explicit maintenance entry + SharedMutationEligibilityGate
  → load binding/prior manifest/protected provenance/active checkpoints
  → MetadataIntegrityPolicy.validate_migration(prior, candidate)
  ├─ closure proven → new generation manifest + Migration provenance
  │                  → generation-checked UoW commit → MetadataMigrationResult
  └─ unknown/corrupt/unsupported/active-ref gap → blocked / no silent repair
```

关键说明：

- Status/scan 不调用本流；提交 outcome 不明时进入 recovery，不伪造新 generation 已生效。
- 物理切换、backup 和 compatibility 留 03，并受 `SYNC-UP-006` 阻断。

#### 8.3.3 `RebindWorkingCopy`

```text
RebindWorkingCopyCommand(old binding, new explicit selection, target, reason)
  → revalidate new owner context
  → inspect old binding/current target/active conflict/recovery/handoff
  → WorkingCopySafetyPolicy + MetadataIntegrityPolicy
  ├─ clean, known, provenance-closed → create new generation binding/manifest
  │                                  → preserve old→new provenance → commit
  └─ dirty/unknown/protected-history/source mismatch → needs-action
```

关键说明：

- Rebind 必须创建新 generation 和 old→new provenance relation，不是原地改写 refs。
- Dirty/unknown/protected-history/source mismatch 均停止，不得删除来源链或绕过 local protection。

#### 8.3.4 `InspectWorkingCopy`

```text
InspectWorkingCopyQuery
  → StatusQueryEntry
  → GitObservationPort.observe_worktree + FilesystemPort.inspect_target
  → construct bounded immutable WorkingCopyObservation
  → redacted WorkingCopyObservationView
  → No Persist / No Write Lock / No Fetch / No Tree Mutation
```

关键说明：

- Dirty、untracked、path/tool unknown 必须保留，observation 不 attach/persist 到 binding。
- Adapter 不执行 fetch/repair，也不返回 raw stdout/stderr 或 file body。

#### 8.3.5 `ScanMetadataIntegrity`

```text
MetadataIntegrityScanInput + SystemActorContext
  → load manifest/binding/record summaries/provenance closure
  → MetadataIntegrityPolicy.evaluate(...)
  → classify Valid/NeedsMigration/Corrupt/Unknown/ReadOnlyProtected
  → save changed classification + optional safe diagnostic relation
  → per-target MetadataIntegrityScanResult
```

关键说明：

- Scan 不 repair、migrate、delete 或 rebind；只保存 typed integrity classification。
- 只有正式完整性证明可恢复 Valid，batch success 不隐藏单 target 损坏。

### 8.4 CP3 Source Materialization 处理流

#### 8.4.1 `PullWorkingCopy`

```text
PullWorkingCopyCommand
  → PullCommandEntry + SharedMutationEligibilityGate
  → load binding/manifest/cursor/mapping; prepare operation/checkpoint
  → MaterialSourcePort.resolve_source + read_delta outside local write transaction
  → SourceDelta.is_continuous_from(cursor)
  ├─ gap/unsupported/unknown → blocked/needs-action; old cursor retained
  └─ continuous → build MaterializationPlan + PathChangeSet
       → observe current target + MaterializationSafetyPolicy.validate_plan
       → durable Prepared run/checkpoint
       → whitelisted Git/filesystem local apply
       ├─ dirty/drift/conflict → CP4 ConflictRecord
       ├─ partial/unknown → checkpoint; old cursor retained
       └─ AppliedPendingFinalize + same generation
            → UoW commits mapping/cursor/provenance/run Finalized
            → PullWorkingCopyResult
```

关键说明：

- Source read/comparison、local plan、facility apply 和 metadata finalize 是不同阶段；Git/process success 不能跳过验证。
- Cursor 只在 proven apply + same generation UoW 后推进；`SYNC-UP-002/007/008/010` 未闭合时正向分支 blocked。

#### 8.4.2 `ConsumeMaterialSourceInvalidated`

```text
MaterialSourceInvalidatedEvent
  → validate envelope/source/schema/dedup
  → locate source snapshot/cursor/unexecuted plan/frozen candidate
  → invalidate snapshot; cursor continuity=Unknown
  → invalidate plan/candidate; keep finalized local history
  → commit dedup + invalidation/provenance relation
  → explicit future Pull required / no local file mutation
```

关键说明：

- 本流不自动 pull、rollback、delete 或 overwrite，只迫使下次 mutation 重新 resolve/compare。
- 已 finalized 的 local content/cursor 作为历史保留，但不得继续宣传为 owner current。

### 8.5 CP4 Conflict & Recovery 处理流

#### 8.5.1 `RecordConflictResolution`

```text
RecordConflictResolutionCommand
  → load open ConflictRecord/current checkpoint/allowed decisions
  → ManualResolution.record(...)
  → ManualResolution.validate(conflict, current_context, RecoverySafetyPolicy)
  → commit resolution intent + ResolutionRecorded + provenance
  → ConflictResolutionResult / Explicit Resume Required
```

关键说明：

- 记录决定与执行严格分离；后续必须显式 `ResumeSyncOperation` 并重新验证。
- Job/tool 不得冒充 actor，KeepLocal/ApplySource 也不能直接成为强制覆盖。

#### 8.5.2 `ResumeSyncOperation`

```text
ResumeSyncOperationCommand(operation/checkpoint/resolution refs)
  → load current binding/source/local/attempt context
  → SharedMutationEligibilityGate
  → RecoverySafetyPolicy.classify_next_action(checkpoint, current_context)
  ├─ ResumeLocal → only proven local-safe stage
  ├─ Revalidate/Replan → return to owning CP with new plan/stage
  ├─ ProbeRequired → ProbeUnknownOutcome
  └─ Manual/Stop → remain NeedsAction
  → owning policy + UoW → new checkpoint/result
```

关键说明：

- Resume 是重新判定，不是从程序计数器继续；drift 可迫使 replan/stop。
- External effect unknown 只能走 ProbeRequired；用户“确认重试”不能替代 equivalence contract。

#### 8.5.3 `ProbeUnknownOutcome`

```text
ProbeUnknownOutcomeCommand(prior attempt/checkpoint)
  → durable ProbeRecord.prepare(attempt, kind, idempotency context)
  → RecoveryProbePort.probe_external_attempt outside local transaction
  → classify ResolvedKnown / StillUnknown / Unsupported / FailedKnown
  → HandoffResultPolicy preserves transport/probe/Decision layers
  → commit probe/attempt/checkpoint/provenance
  → ProbeUnknownOutcomeResult / No Automatic Replay
```

关键说明：

- Durable probe intent 先于 external probe；probe 自身 unknown 时继续保持 unknown。
- 只能探测明确 prior attempt，不能猜 remote object 或以 telemetry 替代正式结果。

#### 8.5.4 `ProbePendingHandoffAttempts`

```text
PendingHandoffProbeInput
  → select durable ProbeRequired attempts
  → per-attempt lease/current checkpoint
  → same formal path as ProbeUnknownOutcome
  → save known/unknown/unsupported per attempt
  → partial-safe PendingHandoffProbeJobResult
  → No Submit Retry / No Decision Generation
```

关键说明：

- 该 job 是 probe 调度，不是 handoff retry worker；不调用 submit/retry。
- Batch finished 不等于所有 attempt resolved，每个 unknown/manual 结果独立保留。

### 8.6 CP5 Review Handoff & Provenance 处理流

#### 8.6.1 `PushReviewCandidate`

```text
PushReviewCandidateCommand
  → PushReviewCommandEntry + SharedMutationEligibilityGate
  → load binding/generation/cursor/current observation/open conflict/recovery
  → CandidateEligibilityPolicy.evaluate
  ├─ blocked/dirty/drift/unknown → typed blocker
  └─ eligible → ReviewCandidate.freeze(digest, scope, observation)
       → durable candidate + HandoffAttempt.Prepared + checkpoint + provenance
       → ReviewHandoffPort.submit_candidate outside local transaction
       ├─ known transport/ref → layered save; Decision remains external
       └─ timeout/lost response → OutcomeUnknown→ProbeRequired; no replay
       → PushReviewCandidateResult
```

关键说明：

- Freeze/attempt/checkpoint/provenance 必须在 call 前 durable；任一 drift 使旧 candidate 失效。
- 输出最多证明 local candidate、attempt、transport 和 external ref；`SYNC-UP-001/004/005` 未闭合时只能 prepared/blocked。

#### 8.6.2 `RefreshReviewHandoffStatus`

```text
RefreshReviewHandoffStatusCommand(explicit attempt/ref)
  → load attempt/existing probe/persisted Decision snapshot
  → unknown attempt ? formal RecoveryProbePort : ReviewDecisionReadPort
  → capture safe Governance snapshot
  → HandoffResultPolicy assembles local/transport/probe/Decision layers
  → commit snapshot/attempt/provenance relation
  → ReviewHandoffRefreshResult / No Governance Mutation
```

关键说明：

- Refresh 是显式写 local snapshot 的 Command；`GetReviewHandoffStatus` 不走本流。
- Decision 只转述 owner ref/result；Missing/Stale/Unknown 不补成 pending 或 accepted。

#### 8.6.3 `GetSyncStatus`

```text
GetSyncStatusQuery
  → StatusQueryEntry
  → read CP1~CP5 persisted slices
  → optional explicit read-only Git/fs observation; never persist
  → assemble LayeredHandoffStatus + SyncStatusView
  → preserve missing/stale/unknown/unsupported/blocked + redaction
  → layered GetSyncStatusResult
  → No Write / No Owner Refresh / No Probe / No Cursor Advance
```

关键说明：

- Optional local observation 是 ephemeral read-only slice，不 attach/persist 或 emit diagnostic。
- Read completeness 不是 sync success；source/cursor/Git/recovery/transport/Decision/archive posture 保持独立。

#### 8.6.4 `ConsumeReviewDecisionChanged`

```text
ReviewDecisionChangedEvent
  → validate Governance source/ref/schema/dedup
  → associate by official handoff/Gate ref
  ├─ unique visible match → capture safe Decision snapshot
  │                        → commit dedup + snapshot + provenance
  └─ unmatched/ambiguous/restricted → typed blocked/unknown; no fake attempt
  → Consumer Result / No Candidate, File, Gate or Decision Mutation
```

关键说明：

- Consumer 只转述 owner state/ref；不触发新 handoff，也不重解释 accepted/rejected。
- Unmatched/ambiguous ref 不创建伪 attempt；正式 event contract 前保持 blocked/planned。

### 8.7 未独立展开的接口

| 接口组 | 处理口径 | 原因 / 边界 |
|---|---|---|
| 其余 Get/List Queries | §8.1.2 通用 query path | 明确 repository/view read + redaction；无 fallback/refresh/repair |
| `CancelSyncOperation` | §8.1.1 通用 local command path | 标 Cancelled、收束 local checkpoint、append provenance；不 external cancel、不删历史、不改 files/source/handoff |
| 单独 port operations | 嵌入 owning use-case 图 | Port 是内部 seam，不冒充用户 API |

### 8.8 处理流闭环

四类通用流和 18 个关键图完整覆盖 Step 7 的 P0 mutations、会写 local state 的 conditional consumers、影响一致性的 jobs 及复杂 status/inspect query。所有 flow 使用 Step 6 已定义对象；query no-write、proven apply 后 cursor finalize、durable-before-external-effect、unknown→probe/manual、ACK/Decision 分层和 provenance body-free 均闭合。精确 UoW/crash window/lock/staging/compensation、adapter invocation 与 error mapping 交 03；合同缺失时返回 blocked/unsupported/needs-action/probe-required。

## 9. 状态定义与状态流转

> 校准来源：
> - `design-calibration/02_hld_step_09_state_machine.md`
>
> 延伸阅读：建议继续阅读上述文件的“状态主语筛选与归属”、各 CP“状态停审”“状态传播关系图”和“跨状态一致性审计”。

本设计没有全局 `sync success` 状态。Operation、access snapshot、binding/metadata、source cursor、working tree、plan/run、conflict/recovery、transport/probe、Governance Decision 与 archive posture 是独立状态轴；任一局部终态都不能替代其他轴。

### 9.1 状态主语与归属

| 部分 | 有 local lifecycle 的对象 | 状态轴 |
|---|---|---|
| CP1 | `SyncOperation` | Planned/Validating/Ready/Running/NeedsAction/Completed/Cancelled/FailedKnown |
| CP1 | `AccessEvaluation` | Eligible/Denied/Blocked/Unknown/Stale |
| CP1 | `ExternalOwnerSnapshot` | Fresh/Stale/Unknown/Invalidated/Unavailable |
| CP2 | `WorkingCopyBinding` | Initializing/Bound/Restricted/NeedsMigration/NeedsRebind/Invalidated |
| CP2 | `MetadataManifest` | Valid/NeedsMigration/Corrupt/Unknown/ReadOnlyProtected |
| CP2 | `CursorState` | Unset/Continuous/Gap/Unknown/Unsupported |
| CP2 | `MappingSet` | Valid/Conflict/Unknown/Invalidated |
| CP3 | `MaterializationPlan` | Draft/Validated/Invalidated/Consumed |
| CP3 | `PathChangeSet` | Draft/Safe/Conflict/Blocked/Unknown |
| CP3 | `MaterializationRun` | Prepared/Applying/AppliedPendingFinalize/Finalized/Partial/OutcomeUnknown/Blocked/FailedKnown |
| CP4 | `ConflictRecord` | Open/AwaitingDecision/ResolutionRecorded/Superseded/Closed |
| CP4 | `RecoveryCheckpoint` | Captured/Resumable/Invalidated/ProbeRequired/Completed |
| CP4 | `ManualResolution` | Recorded/Validated/Applied/Superseded/Rejected |
| CP4 | `ProbeRecord` | Prepared/InFlight/ResolvedKnown/StillUnknown/Unsupported/FailedKnown |
| CP5 | `ReviewCandidate` | Inspecting/Eligible/Frozen/Invalidated/HandedOff |
| CP5 | `HandoffAttempt` | Prepared/Calling/TransportKnown/OutcomeUnknown/ProbeRequired/ExternalPending/TerminalKnown |
| CP5 | `ProvenanceRecord` | Active/Superseded/Protected/IntegrityUnknown |

`SyncSelection`、`WorkingCopyObservation` 和 `SourceDelta` 是 immutable value/classification；七个 policy 无 lifecycle；`LayeredHandoffStatus` 与 `SyncStatusView` 是 derived views，只保留来源状态轴和读取完整性，均不得伪造 state machine。

### 9.2 CP1 Selection & Access 状态

```text
SyncOperation.Planned
        │ shared eligibility gate
        ▼
SyncOperation.Validating
   ┌────┼───────────────┐
   ▼    ▼               ▼
 Ready  NeedsAction     FailedKnown
   │      │ explicit resume/revalidate
   ▼      └──────────────► Validating
Running
   ├────────► NeedsAction
   ├────────► Completed
   ├────────► FailedKnown
   └────────► Cancelled

ExternalOwnerSnapshot.Fresh ──invalidation/expiry──► Stale/Invalidated/Unavailable
AccessEvaluation.Eligible   ──snapshot/action drift─► Stale
```

关键说明：

- Operation、evaluation 与 snapshot 是三条轴；Completed 不传播为 owner success 或 Review accepted。
- NeedsAction 必须经 explicit Resume 返回 Validating；Fresh/Eligible 只能由新的 owner proof 建立。

允许迁移：

| 对象 | From → To | 条件 |
|---|---|---|
| Operation | Planned → Validating → Ready | shared gate 开始；fresh Eligible 且 local preconditions 成立 |
| Operation | Ready → Running | durable stage/checkpoint 已准备 |
| Operation | Validating/Running → NeedsAction | blocker/conflict/unknown/probe/manual |
| Operation | NeedsAction → Validating | explicit Resume + current context recheck |
| Operation | Running → Completed/FailedKnown | 已知 local result |
| Operation | non-terminal → Cancelled | actor 显式取消；不表示 external rollback |
| Evaluation | Eligible → Stale | snapshot invalidation 或 action/context drift |
| Snapshot | Fresh → Stale/Invalidated/Unavailable | freshness/source contract、正式 invalidation 或 owner unavailable |
| Snapshot/Evaluation | non-fresh → new Fresh/Eligible record | 仅新的正式 owner result |

禁止 `NeedsAction→Running/Completed` 绕过 revalidation；禁止 Denied/Blocked/Unknown/Stale 依靠 default、cache、网络恢复或配置变 Eligible；禁止 Cancelled→Completed 冒充外部撤销；禁止 snapshot 不经 owner proof 原地恢复 Fresh。CP1 状态传播只会使 evaluation、未执行 plan/candidate 或 operation 更保守，不改已 finalize local content 和任何 owner truth。

### 9.3 CP2 Working Copy & Metadata 状态

```text
WorkingCopyBinding.Initializing
        │ manifest + initial local result proven
        ▼
WorkingCopyBinding.Bound
   ├─ integrity/schema drift ─► NeedsMigration
   ├─ source/target mismatch ─► NeedsRebind
   ├─ posture/safety issue ───► Restricted
   └─ relation invalidated ───► Invalidated

MetadataManifest.Valid
   ├─ unsupported older schema ─► NeedsMigration
   ├─ failed integrity ─────────► Corrupt
   ├─ unverifiable closure ─────► Unknown
   └─ protected legacy state ───► ReadOnlyProtected

CursorState.Unset ──proven initial finalize──► Continuous
CursorState.Continuous ──gap/invalidation──► Gap/Unknown/Unsupported
```

关键说明：

- Binding、manifest、cursor、mapping 与 worktree observation 彼此独立，Bound 不是综合 Ready。
- Migration/Rebind 建立新 generation/relation；status/source observation 不推动 cursor 或 schema state。

Binding、manifest、cursor、mapping 和 worktree observation 始终分轴；Bound 不等于 clean、cursor continuous 或 metadata writable。

| 对象 | 允许迁移 | 必要条件 |
|---|---|---|
| Binding | Initializing→Bound | manifest/binding/provenance 与 initial local result 已知闭合 |
| Binding | Bound→Restricted/NeedsMigration/NeedsRebind；non-terminal→Invalidated | typed posture/safety/schema/source/target/invalidation |
| Manifest | Valid→NeedsMigration/Corrupt/Unknown/ReadOnlyProtected | load/scan/invalidation typed result |
| Manifest | NeedsMigration→new-generation Valid | explicit `MigrateSyncMetadata` committed |
| Cursor | Unset→Continuous；Continuous→new Continuous | proven initial/incremental finalize |
| Cursor | Continuous→Gap/Unknown/Unsupported | comparator/source invalidation/contract loss |
| Mapping | Valid→Conflict/Unknown/Invalidated | path/source/generation change |
| Mapping | Conflict→new-version Valid | explicit resolution + new plan + proven finalize |

禁止 Initializing 在 partial/unknown 或 provenance/schema 不明时 Bound；禁止 query/scan 通过删除记录把 Corrupt/Unknown 变 Valid；禁止以时间戳、Git commit、收到顺序或强制 full 假设把 cursor Gap/Unknown/Unsupported 变 Continuous；禁止 Sync 自动 stash/merge/rebase/overwrite 令 dirty tree 变 clean；禁止 Invalidated mapping 跨 generation 复活。

Manifest 非 Valid 会使 binding Restricted/NeedsMigration 并阻断新 plan/candidate；dirty/path/tool unknown 会使 plan/candidate invalidated 或形成 conflict，但不直接改 cursor；rebind/migrate 新 generation 会使旧 plan/candidate/checkpoint 失效或需显式迁移，且保留 old→new provenance。

### 9.4 CP3 Source Materialization 状态

```text
MaterializationPlan.Draft
   ├─ all gates pass ─────────► Validated ──durable run prepared──► Consumed
   └─ conflict/blocker/drift ─► Invalidated

PathChangeSet.Draft
   └─ safety evaluation ─► Safe / Conflict / Blocked / Unknown

MaterializationRun.Prepared
        │ current preconditions match
        ▼
MaterializationRun.Applying
   ├─ known complete ─► AppliedPendingFinalize ──same-generation UoW──► Finalized
   ├─ partial ────────► Partial
   ├─ outcome unknown ► OutcomeUnknown
   ├─ blocked ────────► Blocked
   └─ known failure ──► FailedKnown
```

关键说明：

- Validated plan 是一次性 precondition conclusion；执行前 drift 会使其失效。
- AppliedPendingFinalize 与 Finalized 分开；Partial/OutcomeUnknown 进入 CP4 且不推进 cursor。

| 对象 | 允许迁移 | 条件 |
|---|---|---|
| Plan | Draft→Validated | access/source continuity/generation/observation/path safety 全通过 |
| Plan | Draft/Validated→Invalidated | drift/invalidation/conflict/blocker |
| Plan | Validated→Consumed | durable Run.Prepared 已建立 |
| PathChangeSet | Draft→Safe/Conflict/Blocked/Unknown | current observation/mapping/policy evaluation |
| Run | Prepared→Applying | plan 与 current context 仍匹配 |
| Run | Applying→AppliedPendingFinalize | local apply steps 全部 known complete |
| Run | AppliedPendingFinalize→Finalized | same-generation UoW 提交 cursor/mapping/provenance |
| Run | Applying→Partial/OutcomeUnknown/Blocked/FailedKnown | typed facility/application outcome |
| Run | Partial/OutcomeUnknown→new Run.Prepared | CP4 explicit Resume/Replan；旧 run 不改成 Finalized |

禁止 Draft/Invalidated/Consumed plan 直接 apply；禁止 Conflict/Blocked/Unknown path-set 无新 observation/mapping/decision 变 Safe；禁止 Partial/OutcomeUnknown/Blocked/FailedKnown 直接补为 Finalized；禁止 Applying 跳过 AppliedPendingFinalize；禁止 Gap/Unsupported source delta 当 NoOp/Full/Incremental。

只有 Run.Finalized 才可生成新的 cursor/mapping/provenance version 并允许 operation Completed。Partial/OutcomeUnknown 必须产生 checkpoint、使 operation NeedsAction，并可能形成 conflict；plan invalidation 不改 files/cursor。

### 9.5 CP4 Conflict & Recovery 状态

```text
ConflictRecord.Open ──needs actor──► AwaitingDecision
       │                                  │ RecordConflictResolution
       │ new detection                    ▼
       └────────► Superseded      ResolutionRecorded
                                          │ new plan / known safe result
                                          ▼
                                        Closed

RecoveryCheckpoint.Captured
   ├─ local-safe proof ─► Resumable ──known result──► Completed
   ├─ input drift ──────► Invalidated
   └─ possible external effect ─► ProbeRequired

ProbeRecord.Prepared ─► InFlight
   ├─ formal known result ─► ResolvedKnown
   ├─ still unknown ───────► StillUnknown
   ├─ no contract ─────────► Unsupported
   └─ probe failed known ───► FailedKnown
```

关键说明：

- ResolutionRecorded 只是 intent；只有新 action 的 known safe result 才能关闭 conflict。
- Resumable 仅适用于 local-safe step；ResolvedKnown probe 也不自动等于 Governance Decision。

| 对象 | 允许迁移 | 条件 |
|---|---|---|
| Conflict | Open→AwaitingDecision→ResolutionRecorded | explicit actor/owner input；valid resolution intent |
| Conflict | non-closed→Superseded | 新检测事实替代旧 basis |
| Conflict | ResolutionRecorded→Closed | Resume/Replan 产生 known safe result |
| Checkpoint | Captured→Resumable/Invalidated/ProbeRequired | RecoverySafetyPolicy current-context classification |
| Checkpoint | Resumable/ProbeRequired→Completed | known resumed result，或 formal probe 后 owning flow known result |
| Resolution | Recorded→Validated/Rejected/Superseded | current context/scope/actor validation |
| Resolution | Validated→Applied | 对应 local action 已知完成 |
| Probe | Prepared→InFlight→terminal classification | formal probe invocation/result |
| Probe | StillUnknown→new Probe.Prepared | later explicit command/job；旧 record 保留 |

禁止仅凭用户点击、日志或“无 Git conflict”关闭 conflict；禁止 Invalidated checkpoint 原地恢复 Resumable；禁止 Recorded resolution 跳过 validation/action 变 Applied；禁止用 retry count/telemetry/cache 把 unknown probe 补成 known；禁止 local cancel 把 external attempt 标 rolled back。

Open/Awaiting/ResolutionRecorded 会使 owning plan/candidate invalidated、operation NeedsAction；Validated resolution 只允许建立新 stage/plan；ProbeRequired 传播到相关 attempt 和 operation；Probe outcome 进入 CP5 layered status，但不修改 Governance Decision。

### 9.6 CP5 Review Handoff & Provenance 状态

```text
ReviewCandidate.Inspecting
   ├─ gates pass ─► Eligible ──freeze──► Frozen ──durable attempt──► HandedOff
   └─ blocker/drift ───────────────────► Invalidated
                         Frozen/HandedOff ──later drift────────────► Invalidated

HandoffAttempt.Prepared ─► Calling
   ├─ known transport + external ref ─► TransportKnown ─► ExternalPending
   ├─ lost/timeout response ──────────► OutcomeUnknown ─► ProbeRequired
   └─ formal owner terminal state ref ──────────────────► TerminalKnown

ProbeRequired ──formal probe──► ExternalPending / TerminalKnown / ProbeRequired

ProvenanceRecord.Active
   ├─ replacement relation ─► Superseded
   ├─ active reference ─────► Protected
   └─ verification gap ─────► IntegrityUnknown
```

关键说明：

- Candidate/attempt/transport terminal 名称都不产生 Governance verdict；Decision 只来自 owner snapshot。
- OutcomeUnknown 必须 ProbeRequired；provenance 被 supersede/protect 也不允许 silent delete。

| 对象 | 允许迁移 | 条件 |
|---|---|---|
| Candidate | Inspecting→Eligible→Frozen | all gates pass；digest/scope/generation/observation committed |
| Candidate | Frozen→HandedOff | durable HandoffAttempt.Prepared 关联 |
| Candidate | non-invalidated→Invalidated | local/source/access/posture/generation/conflict drift |
| Attempt | Prepared→Calling | durable prepare 后正式 call |
| Attempt | Calling→TransportKnown | transport outcome known |
| Attempt | Calling→OutcomeUnknown→ProbeRequired | response lost/timeout + checkpoint classification |
| Attempt | TransportKnown→ExternalPending | official external handoff/Gate ref exists；Decision pending/unknown |
| Attempt | TransportKnown/ExternalPending/ProbeRequired→TerminalKnown | formal owner read/probe 返回 terminal state ref |
| Provenance | Active→Protected/Superseded/IntegrityUnknown | active refs、新 relation 或 integrity gap |

禁止 Candidate 跳过 Frozen/durable attempt 进入 HandedOff；禁止 Invalidated candidate 原地复活；禁止 attempt 未正式 call 就 TransportKnown/ExternalPending；禁止 OutcomeUnknown/ProbeRequired 返回 Calling 盲重放；禁止 ACK、HTTP 200、remote object 或 Git commit 推进 Decision；禁止通过补造/删除 refs 把 IntegrityUnknown 变 Active。

### 9.7 跨状态传播

```text
Owner access/posture/source invalidated
  ├─► AccessEvaluation.Stale
  ├─► MaterializationPlan.Invalidated
  └─► ReviewCandidate.Invalidated

Working-copy / generation drift
  ├─► PathChangeSet.Conflict or Unknown
  ├─► MaterializationRun blocked / RecoveryCheckpoint
  └─► ReviewCandidate.Invalidated

MaterializationRun.Partial / OutcomeUnknown
  └─► RecoveryCheckpoint + SyncOperation.NeedsAction

HandoffAttempt.OutcomeUnknown
  └─► RecoveryCheckpoint.ProbeRequired + ProbeRecord

Formal Governance Decision snapshot
  └─► LayeredHandoffStatus.external_decision_state only
       └─X local files / Project / Artifact / Baseline / Archive mutation
```

关键说明：

- Propagation 只使 local state 更保守或更新 read-only external layer，不自动修改 Git/filesystem/owner truth。
- 每条 propagation 都必须由明确 Command、Consumer、Job 或 owning service 经 local UoW 提交。

传播必须由 §7/§8 的明确 Command、Consumer、Job 或 owning service 通过 local UoW 提交，不允许 hidden observer side effect。`Completed`、`Valid`、`Eligible`、`Fresh`、`Finalized`、`TerminalKnown` 均带对象主语；任何一个都不是 global success。精确 enum、guards、optimistic concurrency、persistence/outcome mapping 交 03，受阻的正向迁移保持 blocked/unsupported。

## 10. 异常与边界场景轮廓

> 校准来源：
> - `design-calibration/02_hld_step_10_exceptions_boundaries.md`
>
> 延伸阅读：建议继续阅读上述文件的六类异常表、“异常影响图”和“异常边界审计”。

本章只固定“场景—主责/对象—安全姿态”；error taxonomy/code、retry/backoff、compensation、rollback script 和 operator runbook 交 03/05/07。Known failure、conflict/drift 与 outcome unknown 必须分流，不能统一成 retry。

### 10.1 Selection & Access

| ID | 场景 | 主责 / 对象 | 概要姿态 |

### 10.7 异常影响与恢复路由

```text
Explicit-input / owner / local / source / handoff anomaly
                         │
                         ▼
Owning part classifies typed result
     ┌───────────────────┼────────────────────┐
     ▼                   ▼                    ▼
Known safe failure    Conflict / drift    Outcome unknown
     │                   │                    │
     ▼                   ▼                    ▼
stop + preserve       invalidate plan /   durable checkpoint
known history         candidate + manual  + formal probe
                         │                    │
                         └─────────┬──────────┘
                                   ▼
                         blocked / needs-action
                                   │
                   explicit revalidate/replan/resume/probe/manual only
```

关键说明：

- Known failure、conflict/drift 与 outcome unknown 使用不同的停止和恢复路径，不能统一 retry。
- CP4 提供 recovery semantics，但 owning part 保留对应 truth 和重新验证责任。

异常始终由拥有相应状态的部分分类；CP4 提供恢复语义，但不吞并其他部分 truth。所有路径都禁止自动 merge/rebase/push、cursor 超前、ACK 升格、provenance 删除或通过 private fallback 绕开 owner contract。`SYNC-UP-001~010` 决定 adapter 能否进一步精确分类/探测；未闭合时保持 Unknown/Unsupported/Blocked。

## 11. 配置影响轮廓

> 校准来源：
> - `design-calibration/02_hld_step_11_configuration_impact.md`
>
> 延伸阅读：建议继续阅读上述文件的“配置影响轮廓表”“禁止配置化边界表”“03 / 04 承接方向”和“配置影响审计”。

本章只识别配置影响类别、注入位置和不可配置边界，不定义 key、default、precedence、environment variable、JSON/YAML、secret 名称或完整配置类型。Raw configuration 只允许停留在 loader/validator/composition/adapter 层；Application/Domain 接收已验证的 typed capabilities、budgets 和 policies，不直接读取环境配置。

### 11.1 配置影响

| 主体 / 接缝 | 影响类型 | 影响方式与上限 | 03 承接 |
|---|---|---|---|
| CLI / Inbound | profile selection、output/redaction format、resource hint | 只能解析显式选择；不能提供 implicit project/version/source 或 default allow | typed CLI/runtime input、validated injection |
| CP1 Selection & Access | owner adapter profile、freshness source、capability availability | hard blockers 固定；adapter config 不决定 permission/posture | access adapter contract、validation-failure mapping |
| CP2 Working Copy & Metadata | metadata backend/layout strategy、allowed target-root/lock capability | 不锁物理 schema；不能允许 secret/body、silent rebind/repair | metadata/filesystem config types、runtime builder、migration compatibility |
| CP3 Source Materialization | supported source adapter、transfer/staging budgets、tool capability | 不能配置 source priority/comparator；budget exhaustion 是 blocked/partial | source/Git/fs adapter config、bounded-resource contracts |
| CP4 Conflict & Recovery | probe schedule/resource budget、job lease/batch、manual UX hint | 不能开启 auto resolve/blind retry；本章不定数值 | job/probe config types、immutable per-attempt snapshot |
| CP5 Review Handoff & Provenance | Governance profile、redaction/diagnostic sink、retention capability declaration | 不能配置 ACK-as-accepted、provenance deletion 或 evidence fabrication | handoff/diagnostic contracts、safe config-snapshot refs |
| `MetadataStore` / UoW | persistence/locking/durability capability | 不满足 generation/protected-history/local-visibility contract 即 Unsupported | adapter constructor inputs、capability validation |
| SDK owner adapters | endpoint/profile/transport/TLS/credential-reference source | 只连接正式 capability；不得 private endpoint/schema workaround | shared SDK mapping、credential-provider seam、compatibility check |
| Git adapter | executable/library selection、capability detection、bounded invocation | arbitrary command 禁止；LFS/shallow 无合同仍 Unsupported | tool configuration、capability probe、command whitelist |
| Filesystem adapter | allowed roots、staging/lock facilities、resource budget | 禁止 path escape/symlink unsafe/overwrite；root 不等于 project selection | path-policy type、validated canonical roots |
| Diagnostics adapter | sink、sampling/budget、redaction profile | sampling 不删 protected provenance、不改变业务结果；正文/secret 永禁 | redaction injection、failure isolation |
| Conditional consumers | 有正式 capability/schema contract 后的 binding 与 budget | enable flag 不创造合同；缺合同必须 refuse startup/Unsupported | binding validation、dedup-store contract |
| Operations jobs | scheduling/batch/lease/budget | eligibility/hard gates 固定；不能 auto pull/handoff/repair | JobConfig family、builder injection、per-target result |
| Clock/ID/digest providers | provider implementation/capability | 不稳定 ID/digest 不得破坏 identity/integrity；算法需安全审查 | provider ports、config validation |

Credential 只可由外部安全机制以安全 provider ref 注入 SDK adapter 的运行语境，不能进入 `.qs-sync`、普通 runtime config snapshot、status 或 diagnostics。在途 operation、plan、candidate、attempt 必须绑定 immutable config/capability context ref；热更新不得改写历史语境。

### 11.3 配置注入边界

```text
Validated runtime configuration
        ├─► inbound / output presentation
        ├─► adapter selection + capability declaration
        ├─► local persistence / path / lock facilities
        ├─► job / probe / transfer resource budgets
        └─► diagnostics / redaction sinks
                         │
                         ▼
                  Runtime composition
                         │ inject typed contracts
                         ▼
             Application Services / Ports
                         │
                         ▼
               Domain policies / hard gates
             (fixed; never read raw config)
```

关键说明：

- Raw configuration 停在 loader/validator/composition/adapter；Domain 只接收 validated typed contracts。
- Configuration 可使 adapter Unsupported/startup blocked，但不能放宽 hard gates 或创造 owner capability。

配置可以导致 startup blocked、adapter Unsupported 或 budget-exhausted typed result；不能使缺失合同或安全失败成为 success，也不能把 LFS、shallow clone、GUI/Tauri 的历史候选变成当前支持。

| 下游 | 必须展开 | 仍然禁止 |
|---|---|---|
| 03 | loader/validator/runtime-builder roles、typed config families、adapter/service injection、immutable snapshot/ref、validation-error mapping、job/consumer startup capability checks | actual keys/defaults/env/JSON、未经核验的 provider library |
| 04 | keys、sources、precedence、defaults、required/optional、validation constraints、examples、secret references、change/restart behavior | domain invariant override、owner truth/source priority、unsafe automation |
| 05 | invalid/missing/conflicting config、unsupported adapter、secret/redaction、budget exhaustion、config-change isolation 的测试设计 | 当前阶段的 test run/result |

`SYNC-UP-001/002/004/006~010` 阻止相应 adapter/config family 的精确字段和 validation rules 定稿；未闭合时 runtime validation 必须返回 Unsupported/Blocked。Runtime language/framework、config library、Git tool/library、metadata backend 和 GUI/Tauri 均未在 02 选择。

### 5.1 模块依赖与通用契约

```text
[cli / operations]
        | call
        v
[orchestration] ---> [five feature application services]
                              | pure call / inward port
                              v
                    [feature domain + ports]
                              ^
                              | implements
                    [SDK / Git / fs / metadata adapters]

[config / composition] --construct only--> the complete graph
```

关键说明：

- 五个 feature 是业务主轴；`orchestration/adapters/operations/composition/config/cli` 是正交技术层，不成为第六个 truth owner。
- feature 间只传 typed ref、snapshot、decision 和 application contract；不 import 对方 concrete service/store/adapter。
- Domain 使用 readonly interface、pure factory/transition 与 `SyncResult<T,E>`；所有预期分支不以 exception 表达。
- mutable local object 由 repository 返回 `Versioned<T>`；写入必须携带 `ExpectedLocalVersion` 和 `LocalStateUnitOfWork`。
- `Optional<T>` 固定为 `T | null`，set 为去重 readonly array，ref 为带 literal kind 的 `OpaqueRef<K>`；不用 `undefined`、裸 string 或 `Record<string, unknown>` 填补契约。

## 8. 逐接口函数级处理流

> 校准来源：
> - `design-calibration/03_ddd_step_09_function_flows.md`
>
> 延伸阅读：建议继续阅读该文件的“Shared flow discipline”、10 条 Command flow、13 条 Query flow、3 条 Consumer flow、3 条 Job flow 及 per-flow/cross-flow 停审表。

### 8.1 通用 mutation/effect 边界

```text
[validate exact envelope/body/selection]
        | calculate canonical digest
        v
[prepare local UoW]
  reserve idempotency -> ensure runtime binding snapshot
  load Versioned<T> -> guards -> durable intent/checkpoint/run/attempt
  append proof/transition/result/invocation/provenance as required
  commit
        |
        v
[typed SDK/Git/filesystem effect outside UoW]
        |
        v
[finalize local UoW]
  reload versions/generation/fingerprint
  known result -> exact state revisions + stored result + idempotency completion
  ambiguous result -> OutcomeUnknown/ProbeRequired + checkpoint
  commit
```

关键说明：

- 纯 local command 可在单 UoW 收束；不得为了套模板伪造 external phase。
- rollback 只回滚当前未提交 local write，不回滚已发生 SDK/Git/filesystem effect，不删除已提交 attempt/provenance。
- duplicate known 原样回放 stored carrier；duplicate unknown/in-flight 不重跑 effect，返回 delayed/probe-required/needs-action。
- 危险 effect 前重验 access/posture、runtime snapshot、generation、working-copy fingerprint 和 exact route capability。

### 8.2 10 条 Command flow 索引

| Flow | Prepare / effect / finalize | 关键异常与恢复 |
|---|---|---|
| `CloneWorkingCopyFlow` | durable selection/operation/binding/manifest/plan/run/checkpoint/root provenance → bounded local stage/apply → run/cursor/mapping/manifest/binding/provenance atomic finalize | incompatible target/gap/dirty/path/partial/unknown；不覆盖、不推 cursor |
| `MigrateSyncMetadataFlow` | versioned old graph + lock → new generation objects/provenance 同 UoW | unsupported/corrupt/dangling/commit unknown；不 in-place rewrite |
| `RebindWorkingCopyFlow` | explicit new selection + owner/local guard → new binding/generation/relation | mismatch/dirty/schema unknown；不 materialize/guess selection |
| `PullWorkingCopyFlow` | delta/path/plan/run/checkpoint durable → bounded apply → same-generation atomic finalize | Gap/Conflict/Partial/OutcomeUnknown；explicit Resume/Replan/Manual |
| `RecordConflictResolutionFlow` | load active conflict/checkpoint → save manual intent/conflict relation | no external effect；只返回 Resume required |
| `ResumeSyncOperationFlow` | reload exact checkpoint/fingerprint/generation → classify typed branch → new plan/run/probe as needed | drift 导致 invalidate/replan；不 NeedsAction→Running 跳转 |
| `ProbeUnknownOutcomeFlow` | prior attempt/checkpoint → durable ProbeRecord/invocation → formal probe → known/still-unknown finalize | 不 original submit；known 不必然 accepted/closed |
| `CancelSyncOperationFlow` | load operation/checkpoint/attempt → local Cancelled result/provenance | possible external effect 仍显式；不 remote cancel/cleanup |
| `PushReviewCandidateFlow` | inspect/evaluate/freeze candidate → durable attempt/checkpoint/invocation → submit → transport/unknown layers | pre-call drift/known reject/ACK/unknown；Probe/Refresh only，不 resubmit/Git push |
| `RefreshReviewHandoffStatusFlow` | load attempt/layer → exact Decision read 或 formal probe → body-free snapshot/attempt/provenance | missing/invisible/still unknown；不写 Gate/Decision |

| `ConsumeAccessOrPostureInvalidatedFlow` | validate official envelope/order/digest；resolve typed refs；versioned conservative transitions | receipt/provenance/idempotency 同 UoW；不 cancel/pull/handoff |
| `ConsumeMaterialSourceInvalidatedFlow` | exact source mapping；cursor/plan/candidate 只收紧 | 不 auto pull/rollback/rewrite finalized history |

### 9.2 跨状态传播

| 触发事实 | 允许传播 | 明确不传播 |
|---|---|---|
| access/posture invalidation | Snapshot 收紧；Evaluation→Stale；unconsumed Plan/Candidate→Invalidated；Operation may NeedsAction | 不改 Project/Archive，不取消 external effect，不回滚 Finalized files/cursor |
| source invalidation | Cursor→Unknown；Plan/Candidate→Invalidated | 不 auto pull/full/rollback，不改 applied cursor |
| metadata degradation | Manifest→non-Valid；Binding→Restricted/NeedsMigration；affected plan/candidate invalidated | 不 auto repair/migrate/rebind/delete |
| generation/rebind | old binding/cursor/mapping/plan/candidate 收紧；建新 identities/provenance | 不重写 old truth/history，不 auto materialize |
| working-copy drift | PathSet→Conflict；Plan/Candidate→Invalidated；Conflict Open；Operation NeedsAction | 不 stash/merge/rebase/overwrite，cursor 不动 |
| local effect partial/unknown | Run→Partial/OutcomeUnknown；Checkpoint 分类；Operation NeedsAction | 不 finalize/cursor advance/blind retry |
| handoff unknown / formal owner read | Attempt→OutcomeUnknown→ProbeRequired；formal result 可到 ExternalPending/TerminalKnown | 不 resubmit，不建 Gate/Decision，不 accepted elevation |
| provenance gap | Active/Protected→IntegrityUnknown；dependent mutation blocked | 不补 parent/digest，不删除/隐藏 |

每个传播都必须经 owning flow、exact helper、versioned reload 和 local UoW；不存在 observer side effect。Illegal transition 统一返回 typed `invalid_transition/context_mismatch/invariant_violation`，绝不 silent no-op。

## 10. 数据持久化、事务与一致性契约

> 校准来源：
> - `design-calibration/03_ddd_step_11_persistence_transaction_consistency.md`
>
> 延伸阅读：建议继续阅读该文件的“数据所有权实现表”“Logical store”“Repository callable surface”“Local UoW”“commit ambiguity”和“禁止持久化规则”。

### 10.1 所有权与 logical stores

L5-sync 仅持久 local sync truth：selection/operation/access snapshot、working-copy binding/manifest/cursor/mapping/observation、plan/delta/path/run、conflict/checkpoint/resolution/probe、candidate/attempt/provenance，以及 proof/transition/result/invocation、runtime binding snapshot 和 exact replay carrier。Project、Artifact、Baseline、Review Gate/Decision、Workspace projection、Archive、Git remote 仅以 typed ref/version/digest/body-free snapshot/layer 出现。

| Store family | Identity / version | 关键一致性 |
|---|---|---|
| 17 lifecycle object stores | 每对象独立 typed primary key；mutable revision 用 `LocalEntityVersion` | 状态 helper 与 expected-version save 一一对应；terminal/degraded history retained |
| immutable input/history | selection、observation、delta、eligibility proof、transition、local result、invocation | append-only；ID 由 `IdPort`；missing/mismatched record 是 consistency defect |
| runtime binding snapshots | `snapshotRef`；exact ensure only | same ref 不同 content 冲突；operation/plan/candidate/attempt 使用同一 immutable ref |
| idempotency | `(channel, operationName, key)` + canonical digest | bare key 不跨 Command/Consumer/Job 共享；completion 必须有 exact typed carrier |
| consumer receipt / job result | `(consumer,eventId/key)`；`(job,runRef/key)` | raw payload 不存；duplicate 原样回放完整 receipt/report+items |
| provenance | provenance id + subject/parent/digest indexes | append/protect/supersede/integrity-unknown；old generation/parent 不删除 |

`.qs-sync` 在本文仅是受控 logical namespace。物理文件/表、schema version、driver、migration、retention 和 crash implementation 保持 `SYNC-UP-006 blocked`。Durable adapter 可合并或拆分 store，但不得改变 identity、typed index、version、append 与 atomic visibility 语义。

### 10.2 UoW 与原子可见性

| 边界 | 必须同一 local commit 可见的写集 |
|---|---|
| operation transition | operation revision + exact transition record + local result（terminal 时）+ provenance |
| binding/generation change | new generation objects + old protected refs + metadata transition + provenance |
| materialization finalize | run Finalized + cursor + mapping + manifest/binding refs + plan/path relation + provenance + stored result/idempotency completion |
| handoff call prepare | Prepared attempt + invocation identity + checkpoint + candidate relation，且在 call 前提交 |
| probe prepare/finalize | ProbeRecord + invocation 在 probe 前；result + attempt/checkpoint/provenance 在后续提交 |
| accepted Consumer | conservative target transitions + provenance + full receipt + idempotency completion |
| completed Job | 已提交 per-item changes + full typed job result + idempotency completion |

SDK/Git/filesystem 不在 local transaction 内，不存在分布式 rollback 声明。Query 不 begin UoW、不 append observation/diagnostic/provenance、不 repair/probe。`StoredSyncOperationResult` / receipt / job result 与 idempotency terminal posture 必须共同可见；terminal 但 carrier missing/wrong kind 是 defect，不是可回放成功。

### 10.3 Commit status unknown

```text
commit known success -> return exact stored carrier
commit known failure -> rollback current UoW; no external claim
commit status unknown
  -> keep the original namespaced identity + digest
  -> reload idempotency, stored carrier, subject version, attempt/checkpoint
  -> complete + correct carrier: exact replay
  -> in-flight/outcome-unknown: delayed / needs-action / probe-required
  -> missing or mismatched carrier: consistency defect / manual intervention
```

不得用新 key、cache、文件时间、Git status、HTTP ACK、log 或 retry count 将 commit unknown 解释为成功/失败。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：
> - `design-calibration/03_ddd_step_12_error_recovery.md`
>
> 延伸阅读：建议继续阅读该文件的“错误层级与稳定类型”“Command/Query/Consumer/Job 映射”“异常分支”“恢复口径”和“Consistency defect catalog”。

### 11.1 错误分层

| 层 | 稳定 family | 责任 |
|---|---|---|
| Domain | `invalid_input`、`invalid_transition`、`context_mismatch`、`invariant_violation`、`blocked`、`unsupported`、`unknown` | 只表达 typed rule/result；不知道 repository/SDK/Git/CLI。 |
| Application | validation/not-found/not-visible/domain-rejected/version-conflict/idempotency-conflict/in-progress/dependency-unavailable/outcome-unknown/duplicate-result-missing/commit-unknown/consistency-defect | 将 domain/port/UoW 结果归一为 recovery class。 |
| Port/Adapter | typed `ApplicationPortError` | 解码 `unknown`，区分 known denial/unavailable/invalid response/known local I/O/outcome unknown；raw exception 不上泄。 |
| Protocol/CLI | Command/Query/Consumer/Job disposition + safe protocol error | 映射 public surface；exit code 仍留 04/07。 |

### 11.2 异常与恢复矩阵

| 场景 | 必须做 | 恢复 / 禁止 |
|---|---|---|
| invalid envelope/body before reserve | stable rejection；zero UoW/effect | caller 修正；不猜默认值 |
| same key + digest completed | 读取并验证 exact carrier，原样回放 | 不重跑 domain/effect/scan/probe |
| same identity different digest | `idempotency_conflict`; zero effect | 不覆盖旧 reservation |
| in-flight | delayed/already-in-progress | 不以进程退出/超时接管 |
| version/generation conflict | rollback stale UoW；reload 后重验 | 不 stale overwrite；不重放已发 effect |
| dirty/path/source conflict | conflict/checkpoint/needs-action | explicit human decision + new Resume/Replan；不 stash/merge/overwrite |
| local apply partial/unknown | Run Partial/OutcomeUnknown + checkpoint；cursor unchanged | re-observe/explicit recovery；不把 old run 改 Finalized |
| handoff effect unknown | durable attempt/checkpoint + ProbeRequired | formal probe/read/manual；不 resubmit/switch key |
| unsupported capability/schema | typed blocked/unsupported | 升级合同/配置后新 operation；不当 empty success |
| missing proof/result/provenance | consistency defect; dependent mutation blocked | manual/design repair；不从 current truth/log 补造 |
| Query read failure | partial/missing/not-visible/unavailable slice | caller re-query/显式 Command；Query 不写/修/探测 |
| Consumer invalid/ambiguous | reject/quarantine/body-free receipt as later contract permits | 不保存 raw payload，不自动执行 |
| Job item failure | typed item + full stored report | 不隐藏在 batch completed，不表示 readiness |

`SafeFailureSummary`、receipt、job item、diagnostic 只可含 stable code、typed ref、capability 和 redaction marker；不得包含 secret、raw payload、absolute path、diff、stdout/stderr、stack 或 provider private reason。

## 12. 并发、幂等与重入保护

> 校准来源：
> - `design-calibration/03_ddd_step_13_concurrency_idempotency.md`
>
> 延伸阅读：建议继续阅读该文件的“并发场景表”“幂等 identity/digest”“Duplicate 处理矩阵”“Git/filesystem 重入”“unknown”和“Job per-item 重入”。

### 12.1 三层保护

| 保护层 | 责任 | 不能替代 |
|---|---|---|
| repository version/unique key | 防 local truth stale overwrite，保证 create/update/index uniqueness | metadata generation、source cursor、working-copy lock |
| target lease + generation + fingerprint | 协调 cooperating Sync writer，检测用户/Git/fs drift | optimistic version、owner authorization，也不证明外部修改不存在 |
| namespaced idempotency + canonical digest | 防 Command/Consumer/Job 重复入口和语义不同请求碰撞 | 平台 external exactly-once/probe equivalence |

Canonical digest 包含 stable actor authority scope、exact operation name、explicit selection/target/generation/scope 及该 operation 的语义字段；排除 correlation/requested time/job run retry attempt/runtime snapshot/ref body/credential 等 volatile 或禁止内容。集合/路径先 validation + canonical ordering，再计算 digest。

### 12.2 Duplicate 与 effect unknown

| Existing posture | Same digest | Different digest |
|---|---|---|
| absent | atomic reserve，进入 owning flow | atomic reserve（首次） |
| completed | 验证 kind 后 exact stored carrier replay | conflict; zero write/effect |
| reserved/in-flight | already-in-progress/delayed; zero second writer | conflict |
| outcome-unknown | 回放原 unknown attempt/checkpoint 并引导 explicit recovery | conflict |
| completed but carrier missing/wrong | consistency defect; no recompute | consistency defect/conflict |

Git/filesystem apply 在 run/checkpoint/plan/path/fingerprint durable 后执行；若 partial/unknown，不使用同 run 重放。Review handoff 在 attempt/invocation/checkpoint durable 后调用；OutcomeUnknown 只通过 prior attempt 的 formal probe/read 收束，不 submit again。Local commit unknown 只允许原 identity/digest reload。

### 12.3 Job 和 Query 重入

- Job 对每个 target 单独 reload/version guard/UoW；已提交 item 是真实 local transition，不等最终 report 才生效。
- 旧 job key 处于 in-flight/commit-unknown 时不允许另一 worker 接管或拼接 report。新授权 run 用新 key/run ref，对已收紧的状态做 no-op，新 report 只描述新 run。
- Probe job 必须重验 attempt/checkpoint/latest probe；InFlight/StillUnknown 不自动再 probe，known terminal 不调 adapter。
- Query 无 idempotency record/UoW/lock/write/probe；每次是当前授权的 read，而不是固定旧 snapshot 或触发隐式 refresh。

## 13. 配置引用与外部依赖绑定

> 校准来源：
> - `design-calibration/03_ddd_step_14_config_dependencies.md`
>
> 延伸阅读：建议继续阅读该文件的“Typed config 与 runtime binding carrier”“配置引用表”“外部依赖绑定”“Capability validation”“Runtime composition 顺序”和“不可配置化边界”。

### 13.1 Typed config 与读取边界

| Config family | 稳定 code shape | 注入点 / 04 承接 |
|---|---|---|
| `SyncBoundaryLimits` | request/page/path scope/target scope/diagnostic 正数上限 | entry/mapper；具体数值、raw key/source/precedence 留 04 |
| `SyncExecutionBudgets` | local read/commit/lock、SDK read、external/local effect、shutdown timeout 与 max concurrent mutations | wrapper/composition；无 03 默认 |
| `SyncJobBudgets` | max batch / parallel items | job runner；不创建 schedule/scope/key |
| `SyncMetadataBindings` | store/UoW/lock adapter refs | metadata factory；physical backend/schema/migration blocked |
| `SyncSdkBindings` | profile/credential-provider/owner/source/handoff/decision/probe adapter refs | SDK adapters；endpoint/TLS/secret/version/method 留 04/上游 |
| `SyncLocalToolBindings` | Git observation/worktree、fs inspection/apply、allowed-root policy refs | local adapters；具体 executable/library 待定 |
| `SyncSupportBindings` | diagnostics/redaction/clock/ID/digest adapter/algorithm refs | composition；无 secret/raw payload |
| `SyncOperationsBindings` | 3 Consumer refs + explicit job runner ref | Consumer 保持 blocked；不因有 ref 就注册 |

只有 `src/config/load_runtime_config.ts` 读取 raw `unknown`，`validate_runtime_config.ts` 转为 immutable `ValidatedSyncRuntimeConfig`，`src/composition/*` 解析 binding 并构建 graph。Adapter constructor 只获得所需局部 family；Application 只获得 ports 与最小 limits/budgets；Domain 不读 env/file/profile 或完整 config。所有数值必须是 finite safe positive integer，不 clamp、不默认无限/零。

### 13.2 Capability snapshot 与 runtime composition

`SyncAdapterCapability` 是 closed union，覆盖 metadata read/atomic write/target lock、owner/source read、Git/fs inspect/apply、review submit/Decision read/recovery probe、diagnostics/clock/ID/digest、3 Consumer 和 3 Job capability。每项必须恰有一个 `AdapterCapabilityBinding`，availability 仅可为 `bound | blocked | unsupported | unknown`。

| 规则 | 契约 |
|---|---|
| `bound` | 只证明 typed constructor/static capability validation 成功；不证明健康、授权、source freshness、working tree clean 或 readiness。 |
| immutable context | 每个 composition 创建一个 body-free `AdapterCapabilitySnapshot`；首次 mutation 与 operation 初始 revision 同 UoW exact `ensure`。 |
| context propagation | `SyncOperation`、`MaterializationPlan`、`ReviewCandidate`、`HandoffAttempt` 使用同一 `runtimeBindingSnapshotRef`；不用当前热更新 config 替换历史语境。 |
| read graph | 不持有 UoW/write/lock/probe/handoff/diagnostic-emit capability；Inspect 只有 read-only Git/fs。 |
| mutation graph | 每 route 做 exact capability preflight；基础 metadata atomicity/version/append/replay/lock 不满足则不构造可写图。 |
| test doubles | 只在 test composition 显式注入；不进 production registry，不关闭上游 blocker。 |

Runtime builder 顺序固定为：load/validate config → reject hard-boundary override → resolve Clock/ID/Digest → metadata read/write/UoW/lock/snapshot repositories → fs/Git → SDK → diagnostics → classify exact capabilities → allocate immutable snapshot → build read-only graph → build mutation facade → conditional Consumer/Job registration。Config reload 若后续获得授权，必须产生新 composition/snapshot，不改写在途对象。

### 13.3 Timeout、依赖与不可配置化边界

当前不定义 generic retry config。Local read timeout 映射 unavailable/unknown；commit timeout 是 `commit_status_unknown`；SDK read fail-closed；handoff/probe/Git/fs effect timeout 是 partial/outcome-unknown；diagnostics failure 隔离。上述分支均不自动 retry。

配置必须拒绝：implicit/default/latest selection，local authorization/owner override，Query hidden write，dirty/path/symlink/lock unknown 继续，auto fetch/merge/rebase/push/stash，以 config 定义 source authority/comparator/gap fallback，partial/unknown 推 cursor，silent migrate/rebind/repair/delete，blind retry/switch key，ACK/Git/log 升格，owner truth 本地化，raw body/credential/evidence 持久化，fake-positive，LFS/shallow/GUI/Tauri positive enablement，以及删除 protected/unknown/replay history。

## 14. 可观测性与审计埋点契约

> 校准来源：
> - `design-calibration/03_ddd_step_15_observability_audit.md`
>
> 延伸阅读：建议继续阅读该文件的“Technical instrumentation contracts”“结构化日志”“指标”“Trace/span”“Safe diagnostic”“Local durable audit”和“Redaction/forbidden-field”。

### 14.1 Runtime signal 与 durable traceability 分层

| 层 | Contract | 能证明 | 不能证明 |
|---|---|---|---|
| technical signal | `SyncTelemetryPort.tryEmitLog/tryRecordMetric/tryStartSpan` | 一次调用的安全技术观察，best effort | business success、effect known、owner truth、evidence/readiness |
| support diagnostic | `DiagnosticsPort.emitSafeDiagnostic` + `SafeDiagnosticRecord` | sink 对 body-free support record 的技术接收姿态 | operation success、artifact/report/evidence、formal probe |
| durable local history | transition/provenance/proof/result/invocation/checkpoint/run/attempt/receipt/job result/runtime snapshot | 已提交的精确 local relation/action/posture | Project/Artifact/Baseline/Gate/Decision/Archive 或 production execution |

Domain 不依赖 telemetry。Entry/application/UoW/adapter wrapper 在已定义边界发射信号；repository 不偷偷记录业务成功。Query 可发 best-effort signal 但仍 zero-write。Telemetry 丢失不得通过重放 Command/Consumer/Job/effect 来“补齐”。

### 14.2 Closed signal schema

| Signal | 必须使用的 closed 维度 | 约束 |
|---|---|---|
| structured log | event code、channel、exact operation、stage、layered disposition、bounded correlation/local refs、duration | 不用 free-form attribute/error；不写 path/body/output |
| metric | exact operation/capability/disposition/error-kind 的低基数 label | ID/ref/key/digest/path/version/cursor/branch/error text 绝不作 label |
| span | command/query/consumer/job/UoW/lock/owner-read/source-read/local-observation/local-apply/handoff/probe/runtime-composition | span `ok/error/unset` 只表示 instrumentation call，不消解 `OutcomeUnknown` |
| safe diagnostic | stable code、correlation/operation/checkpoint/capability、allowlisted supporting/provenance refs、redaction marker | emission known/unknown 不进 business result/recovery |

Metric family 至少包括 entry count/duration、validation rejection、idempotency、UoW/lock、dependency/effect、handoff、conflict/unknown/recovery、consumer/job item、capability binding 和 telemetry drop。Counter 是观测次数，不是 unique truth transition；`sync_capability_binding` 不得汇总成 `sync_ready=1`。

### 14.3 Redaction 与 failure isolation

| 内容 | Signal | Durable local store |
|---|---|---|
| secret/token/credential material | 永久禁止 | 永久禁止；仅在已定义 protocol context 可保存 opaque credential ref |
| raw request/event/provider response/file body/diff/stdout/stderr/stack | 永久禁止 | 永久禁止；domain-required canonical path ref 不等于 path body |
| actor/project/version/source/target/ref values | log/span 默认禁止；metric 永久禁止 | 仅 owning typed record 按契约保存 |
| correlation/operation/checkpoint/attempt/probe/provenance refs | 只在 allowlisted event/span/diagnostic | 按 owning record 保存 |
| artifact/report/evidence/verdict/signoff/readiness claim | 永久禁止 | 永久禁止；未来正式 external ref 需新合同 |

Telemetry adapter throw/drop/unavailable 必须归一为 `dropped/unavailable`，不 rollback、不重试 effect、不改 public result、不建 checkpoint。Durable provenance 写失败仍是 owning UoW 失败/unknown，不得用日志代替后宣称成功。Log/span/metric 不是 formal probe。

## 15. 测试切口与最小验证清单

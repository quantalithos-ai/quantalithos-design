## 2. 本次配置设计目标与范围

> 校准来源：
> - `design-calibration/04_config_step_02_scope.md`
>
> 延伸阅读：建议继续阅读上述文件的“P0/P1/P2 配置口径”“当前范围”“明确非范围”和“完成上限”小节。

### 2.1 P0 目标

P0 不是把所有外部能力做成可用实例，而是形成一个可严格解析、可校验、可组合、可保守分类的配置候选：

- 九个 raw section、42 个既有 leaf：`identity 2 + boundary 5 + execution 8 + jobs 2 + metadata 3 + sdk 7 + localTools 5 + support 6 + operations 4`；
- 38 个 non-nullable leaf required；4 个 `operations.*` slot 允许显式 `null`；
- 普通来源优先级：`approved code-declared default < selected strict JSON < allowlisted environment`；
- strict JSON、closed section、duplicate/alias/unknown/forbidden 全部拒绝；高优先级非法值不得 fallback；
- startup/cold、job-run-start、entry-local、test harness 四种生效面；新 composition 产生 immutable snapshot；
- ref-only sensitive handling、safe output、capability `bound/blocked/unsupported/unknown` 分层；
- 配置不得夺取 Project/Artifact/Baseline/Review Gate/Workspace/Archive/Git remote truth，也不得绕过 dirty-worktree、provenance 或 Query no-write 红线。

### 2.2 P1/P2 与完成上限

| 层级 | 本文姿态 | 进入条件 |
|---|---|---|
| P0 | 当前正式配置契约；可以定义 schema、source、profile、validation、activation、change、failure 和下游输入 | 既有 03 code shape 不变；保持上游 blocker |
| P1 | 真实/controlled SDK、metadata、Git/fs、secret provider、staging-like 等 future integration | exact owner contract、adapter、测试/验收和运维承接闭合后另行重开 |
| P2 | remote config center、admin override、hot reload、online LKG、production-like 深度产品化、跨版本工具扩展 | 先回写 03/上游 ADR，再重新执行受影响 04 Step |

本文不声明任何 P1/P2 实例、endpoint、provider、工具支持、测试结果、部署状态或 readiness。

## 3. 配置控制面总览

> 校准来源：
> - `design-calibration/04_config_step_03_control_plane.md`
>
> 延伸阅读：建议继续阅读上述文件的“配置来源链图”“配置控制面总表”“配置域逐项停审记录”和“跨控制面闭环审计”小节。

#### 配置来源链图: L5-sync 配置覆盖与冷生效链

```text
[approved code-declared defaults]
             +
[selected strict JSON candidate]
             +
[allowlisted environment overlay]
             |
             v
[source selection + conflict check]
             |
             v
[strict JSON / duplicate / alias / unknown / forbidden scan]
             |
             v
[type + range + ref + sensitive + cross-field validation]
             |
             v
[ValidatedSyncRuntimeConfig]
             |
             v
[runtime composition: Clock/ID/Digest -> metadata -> Git/fs -> SDK -> diagnostics]
             |
             v
[AdapterCapabilitySnapshot: bound | blocked | unsupported | unknown]
             |
       +-----+------+
       v            v
[read graph]   [mutation facade]
 zero-write     required static bindings only
       |            |
       +-----+------+
             v
[conditional Consumer/Job registration intent]
```


图示说明：

1. 只有 `src/config/*` 读取 raw source；composition 只读取 typed validated config，Application 只获得既有 ports、最小 limits/budgets 和 snapshot ref，Domain 不读 raw config/env/profile。
2. `bound` 只表示 typed constructor/static capability validation 通过，不表示健康、授权、source freshness、clean worktree、Review accepted、evidence 或 readiness。
3. builder 任一 required stage 失败时不暴露半装配 mutation facade；合法但 blocked/unsupported/unknown 的 route 继续保守阻断。

### 3.1 控制面总表

| 控制面 | 作用 | 绑定对象 / 模块 | P0 语义 |
|---|---|---|---|
| source selection | 选择一个 candidate 并处理来源冲突 | `src/config/*` | default < strict JSON < allowlisted env；高优先级非法不 fallback |
| parse/structure | 严格 JSON、closed section、duplicate/alias/unknown/forbidden | loader/validator | whole-candidate reject |
| typed validation | 42 leaf 的 type/range/ref/required/nullability/cross-field | `ValidatedSyncRuntimeConfig` | invalid 不产生 typed config |
| composition | 依次装配 provider refs、metadata、Git/fs、SDK、diagnostics | `src/composition/*` | 新 composition + immutable snapshot |
| capability classification | 每个 exact capability 的保守姿态 | `AdapterCapabilitySnapshot` | `bound/blocked/unsupported/unknown`，不升格 |
| read graph | Query/inspect 只读能力 | application/query graph | 不持有 UoW/write/lock/probe/diagnostic-emit |
| mutation graph | command/effect 所需的 preflight 与 local consistency | existing ports/facade | required static bindings 和 per-entry capability 必须满足 |
| conditional operations | Consumer/Job 注册意图 | `SyncOperationsBindings` | `null`/blocked 不创建 topic、daemon、schedule、actor、scope 或 key |
| safe support | redaction、digest、Clock、ID、bounded diagnostics | `SyncSupportBindings` | safe record only，不生成 evidence/readiness |

### 3.2 配置读取与依赖方向

配置是控制面，不是业务真相。`src/config/*`、composition 和 adapter registry 可以使用 validated binding；业务 Domain、Project/Artifact/Review/Workspace/Archive owner 和 Git remote 不从配置取得所有权。配置也不改变 UoW、idempotency、state transition、provenance append/protect 或 Query zero-write。



## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_categories_boundaries.md`
>
> 延伸阅读：建议继续阅读上述文件的“配置分类与更新时机总表”“更新时机与冻结规则”“禁止配置化项表”和“分类边界逐域停审记录”小节。

### 4.1 配置类别与生效面

| 类别 | 可承载内容 | 生效边界 | 冻结 / 失败 |
|---|---|---|---|
| `startup_cold_runtime` | identity、limits、budgets、adapter/provider refs、support refs | startup/cold 新 composition | invalid → fail-fast；新 snapshot immutable |
| `job_run_start_pinned` | 既有 `SyncJobBudgets` 的 bounded run-local pin、显式 job input | 每个新 job run | 只能收窄；非法 → current job rejected；在途 run 不变 |
| `entry_local_request` | 当前 command/query 的显式 selector、target、path、scope、conflict/resume 输入 | 当前 entry | 不写回 global config；unknown safety → entry rejected/blocked |
| `sensitive_opaque_ref` | provider、adapter、root-policy、metadata 等 opaque ref | startup/cold；新 ref 需新 composition | raw material 永不接受；解析只在 adapter-private |
| `diagnostic_redaction` | safe diagnostic sink、redaction policy、digest identity | startup/cold | deny policy 只能收紧；不输出 raw/ref/body |
| `test_deterministic_only` | test-only Clock/ID/Digest/fake refs、脱敏 replay ref | test harness | 不进入 production-like；不产 evidence/readiness |
| `peripheral_registration_intent` | 四个 nullable operations slot | cold conditional registration / explicit job entry | `null` 不注册；ref 不等 bound/ready |

### 4.2 冻结规则

P0 不支持 runtime reload、hot adapter replacement、online LKG、admin override、config center、自动 retry/rollback 或在途 snapshot rebind。配置回退只能显式选择已验证候选并重新 cold compose/restart；不能撤销已发生的 SDK/Git/filesystem/Review effect。

### 4.3 永久禁止配置化项

| 禁止项 | 处理 |
|---|---|
| Project/Artifact/Baseline/Review Gate/Workspace/Archive/Git remote ownership 或 truth override | whole-candidate reject 或回流正式设计 |
| implicit/default/latest project/version/source/target selection | reject；必须显式选择 |
| owner permission、本地 authorization、source authority/comparator/gap fallback | reject/blocked；不本地生成 allow |
| raw secret、credential、endpoint/body、文件正文、Git stdout/stderr、provider payload | reject；不截断、不 mask 后继续 |
| Query repair/refresh/probe/write、hidden UoW 或 diagnostic write | reject；Query 保持 zero-write |
| dirty/untracked/path/symlink/root/lock unknown 时继续或覆盖 | fail-closed；不覆盖用户修改 |
| auto merge/rebase/push/stash、blind retry、换 key 重放 unknown effect | reject；保留 checkpoint/probe/manual |
| 删除/伪造/覆盖 provenance、把 ACK/Git commit/job report 当 accepted/Artifact/Baseline | reject；保留 truth/evidence 分层 |
| P0 LFS、浅克隆、GUI/Tauri、daemon/scheduler 的正向开关 | historical/pending；上游矩阵闭合前不进入 schema |

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority_conflicts.md`
>
> 延伸阅读：建议继续阅读上述文件的“来源解析链与唯一候选”“配置来源优先级总表”“冲突、重复与不可用处理表”“来源优先级逐域停审记录”和“跨来源冲突审计”小节。

### 5.1 普通来源优先级

```text
approved code-declared default
        < selected strict JSON candidate
        < allowlisted environment overlay
```

| 来源 | 适用内容 | 优先级 / 规则 | 不可用或非法时 |
|---|---|---|---|
| approved code-declared default | 仅明确 `default_allowed` 的 leaf；当前只包括四个 `operations.* = null` | 最低；不能为 required leaf 发明默认 | required 最终缺失 → startup fail-fast |
| selected strict JSON | 九个 closed section、canonical 42 leaf；`identity.configRef` 必须在此提供并校验 | 覆盖 approved default；必须是单个显式 candidate | 不可读/语法错误/duplicate/alias/unknown/forbidden → whole-candidate reject |
| allowlisted environment | 允许覆盖的普通 scalar 或 opaque ref；不得提供任意 key | 覆盖 strict JSON；存在但非法时不得回退 | fail-fast；不使用 JSON/default/cache/旧 snapshot |
| profile selector | 只选择当前允许 profile；不得选择业务对象 | 与 candidate `profileRef` 冲突时 reject | startup 或 current entry rejected |
| job-run input | 只在既有 run-local 边界 pin bounded 值 | 不能覆盖 startup invariant，只能收窄 | current job rejected |
| entry-local request | 当前 selector/target/path/scope/conflict/resume input | 不属于 global config precedence | current entry rejected；不写回 config |
| test fixture | 仅 `ci-test` 或显式 test composition | 隔离于 production-like registry | test composition fail-fast |
| config center/admin override | P0 无适用 leaf | unsupported source | reject；不得降级到其他 source 后宣称同一候选生效 |

Raw secret/material 永不参加上述优先级；它不是“高优先级敏感配置”，而是 forbidden content。

### 5.2 冲突与不可用处理

| 场景 | 处理 |
|---|---|
| 同一 source duplicate key | whole-candidate reject；不采用最后一次覆盖 |
| alias/大小写/归一化路径碰撞 | reject；canonical key 只能有一个 |
| unknown section/key 或 forbidden invariant override | reject；不 warning 后忽略 |
| 高优先级值存在但类型/范围/ref 不合法 | fail-fast；不得 fallback lower source |
| selected JSON 缺失或不可读 | 没有 candidate；startup fail-fast |
| required leaf 最终缺失 | 不产生 `ValidatedSyncRuntimeConfig` |
| optional operations leaf 缺失 | 归一为 `null`，仅表示未注册，不表示 disabled/healthy/ready |
| ref 语法合法但合同未闭合 | candidate 可被验证；capability 保留 `blocked/unsupported/unknown` |
| source/candidate digest 漂移 | 拒绝新 composition，重新完整校验；旧 snapshot 不改写 |

### 5.3 来源边界

环境变量 key 名、文件路径、mount、secret provider 产品和部署方式留给 09；本文只固定 allowlist、优先级和失败语义。任何下游不得把环境名隐式转换为 profile，也不得用 entry/job 参数扩大 global config、owner authority、scope、idempotency 或 safety invariant。

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_environment_profiles_matrix.md`
>
> 延伸阅读：建议继续阅读上述文件的“P0/P1/P2 profile 总表”“Profile 配置来源矩阵”“敏感配置与 profile 处理矩阵”“Profile 停审记录”和“跨 profile 审计”小节。

Profile 是配置组合语境，不是部署实例、环境名、授权、source selection、health 或 readiness。

### 6.1 Profile 总表

| Profile | 层级 / 用途 | 配置来源 | Adapter / sensitive 姿态 | 能力上限 |
|---|---|---|---|---|
| `local-dev` | P0；本地开发和负向/边界验证 | selected strict JSON + allowlisted env；显式 selector | local/test-capable refs；不提供 raw secret | 可构造安全 composition；正向 SDK/source/tool 仍可 blocked/unknown |
| `ci-test` | P0；确定性 contract/negative test composition | strict fixture JSON + test harness refs | deterministic Clock/ID/Digest、fake/controlled refs，仅 test registry | 不证明真实 integration、production health、evidence 或 readiness |
| `integration-like` | P0 语义；受控接缝验证 | strict JSON + operations-controlled opaque refs | 可声明真实/controlled refs，但解析和 capability 受 blocker | 不因 ref 存在变成授权、fresh、clean 或 accepted |
| `operations-replay` | P0 语义；对已存在脱敏 local carrier 的 bounded replay/恢复分析 | strict JSON + explicit replay ref + bounded job input | 只读/受控 recovery refs；默认不发新外部 effect | 不自动修复、重提 handoff、推进 cursor 或覆盖工作区 |
| `staging-like` | P1 direction / waiting | future deployment candidate | future approved provider/target refs | 不进入 P0 runtime enum/schema，不创建实例 |
| `production-like` | P1/P2 direction / blocked | future operations-controlled source | approved provider only；禁止 fake/test/replay ref | exact owner/tool/store/source/review/ops gates 闭合前不声明 ready |

### 6.2 Profile 不变量

- 四个 P0 profile 使用同一 42-leaf schema、source precedence、strict validation、truth ownership 和 no-output 红线；profile 不能放宽安全边界。
- `local-dev` / `ci-test` 的 fake 或 deterministic binding 不关闭 `SYNC-UP-*`，不能进入 production-like registry。
- `integration-like` 只是 controlled seam，不表示真实 endpoint、provider、permission、source freshness 或 Review accepted。
- `operations-replay` 不能读取未脱敏 body、创建新外部副作用、修改旧 report/attempt、删除 provenance 或用 replay ref 自动提交。
- staging/production 的挂载、环境变量映射、secret provider、rotation、告警和 runbook 留给 09；未确认前状态只能是 `planned/blocked/waiting`。

### 6.3 下游矩阵

| 下游 | 必须承接 | 不得解释为 |
|---|---|---|
| 05 | profile/source/fixture/adapter ceiling、negative/failure cuts | profile 已部署或真实 run 已通过 |
| 06 | profile isolation、fake rejection、source no-fallback 和 capability ceiling | staging/production accepted/readiness |
| 07 | planned composition/adapter/test tasks；本地工具选择仍待确认 | 模块/文件/commit 已存在 |
| 09 | 环境到 profile 的显式映射、provider/secret/runbook | 可以改变 schema、source priority 或启用 hot/LKG |

| `localTools` | `SyncLocalToolBindings`（5） | typed Git/fs/root-policy refs；无任意 command/remote |

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_sensitive_secrets.md`
>
> 延伸阅读：建议继续阅读上述文件的“敏感级别与 ref 语义归一”“敏感配置读取与生命周期图”“敏感配置清单”“禁止输出与最小暴露规则”“逐域停审记录”和“跨敏感配置泄露风险审计”小节。

### 8.1 敏感级别

| 级别 | 含义 | 普通配置可承载 | 输出 / 审计 |
|---|---|---|---|
| `public` | 无安全、拓扑或授权信息的 closed class | 可以，仍受 strict schema | 只允许低基数 closed enum |
| `internal` | limit、timeout、profile class、slot、redaction/digest policy | typed config/ref | 只输出 allowlisted class/code/marker |
| `sensitive` | credential/provider、store、target/route/root policy、外部拓扑或身份 ref | 仅 opaque ref | full ref、endpoint/path、拓扑细节默认禁止 |
| `secret` | token、password、private key、certificate body、raw credential/provider response | 永不允许作为配置 leaf | 永久禁止进入 config、snapshot、metadata、telemetry、report 或文档示例 |

`support.redactionPolicyRef` 和 `support.digestAlgorithmRef` 虽非秘密材料，但属于 safety-critical internal config：缺失或无法证明安全时 fail-fast；不能由高优先级 source 放宽 deny policy 或隐式切换 digest semantics。

### 8.2 Opaque ref 四层边界

| 层 | 允许 | 禁止 |
|---|---|---|
| raw candidate | canonical opaque ref 或 nullable operations `null` | raw secret、endpoint/body、shell/argv、path body、provider response |
| validated config / composition | typed ref、slot、profile、safe policy class | material、owner/source payload、Git output、readiness claim |
| adapter-private resolution | 未来正式 contract 允许时的最小生命周期 credential material | application/domain/local store/telemetry 持有或缓存材料 |
| durable/output surface | owning contract 需要的 typed relation、safe issue/change marker | secret、full sensitive ref、raw path/body、diff/stdout/stderr、provider response |

### 8.3 读取、解析与轮换

```text
[strict candidate / allowlisted env]
          |
          | opaque ref only
          v
[shape + sensitive-content validation]
          |
          v
[typed ref in ValidatedSyncRuntimeConfig]
          |
          +--> [immutable runtime snapshot: ref/slot only]
          |
          +--> [adapter-private resolver, if formally supported]
                        |
                        v
                 [single bounded call]
```

- loader 只校验 ref grammar、canonical slot 和 forbidden content；不解析 credential material。
- provider resolution 若未来获授权，只能在 adapter-private 边界，材料不得跨入 application/domain/`.qs-sync`/observability。
- rotation 通过新 opaque ref、新候选和新 cold composition/restart 生效；job-local ref 只在新 run pin。
- 旧 operation/plan/candidate/attempt 继续原 `runtimeBindingSnapshotRef`；不得原地换 provider 或因 rotation 重放 unknown effect。
- ref/credential/provider 成功不自动证明 owner permission、source freshness、Git clean、Review accepted 或 readiness。

### 8.4 敏感族处理

| 配置族 | 存储 / 读取 | 轮换 | 审计最小集 |
|---|---|---|---|
| `identity.*` | typed identity/profile ref；full ref 不进 telemetry | 新 candidate + cold composition | section/slot、profile class、validation/change marker |
| `metadata.*` | opaque store/UoW/lock refs；不含 DSN/lease/endpoint | 新 refs + restart；旧 metadata/provenance 不迁移或删除 | slot、capability posture、redacted marker |
| `sdk.*` | opaque SDK/provider/owner/source/handoff/Decision/probe refs；material adapter-private | 新 refs + cold composition；旧 attempt 不重提 | slot、safe disposition、blocker/issue/change marker |
| `localTools.*` | typed Git/fs/root-policy refs；无 executable path/argv/remote/stdout | 新 refs + cold composition；dirty state 不覆盖 | tool slot、safe capability/issue marker |
| `support.*` | closed safe record refs；redaction/digest/Clock/ID 固定 | 新 composition；既有 ID/digest 不重算 | provider/algorithm class、validation/change marker |
| `operations.*` | nullable registration refs；无 topic/body/credential | cold registration/new explicit job | slot、null/non-null class、registration disposition |

### 8.5 禁止输出矩阵

| 输出面 | 允许的最小字段 | 永久禁止 |
|---|---|---|
| validation issue / error | stable code、section/slot class、opaque issue ref、bounded profile class | raw key/value、full ref、secret、provider body、stack |
| structured log / span | closed event/stage/capability/disposition、bounded correlation ref | credential/target/root ref、path/body、request/response、Git/fs output |
| metric label | low-cardinality profile/slot/capability/disposition/error class | 任意 ref/key/digest/path/version/cursor/actor、secret |
| safe diagnostic | stable code、capability、bounded local refs、redaction marker | secret、full ref、raw path/body、external response、evidence/readiness |
| `.qs-sync` metadata | owning contract 需要的 typed relation和 body-free integrity marker | secret/material、provider response、file body/diff/stdout/stderr、完整 endpoint/root path |
| command/query/job result | typed disposition、safe issue/local refs、manual/probe requirement | raw config、secret/full ref、external payload、ACK/local commit 升格 |
| local audit/provenance | section/slot、approved redacted old/new marker、validation disposition | raw config/full ref/body、formal evidence/verdict/signoff |

输出必须“先裁剪再序列化”；不能先记录完整对象再依赖 sink 清洗。对 raw ref/path/body 做普通 hash 也不会自动变安全，除非未来正式威胁模型和专用类型明确批准。

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_loading_validation_activation.md`
>
> 延伸阅读：建议继续阅读上述文件的“配置加载流程图”“配置组加载、校验、生效与失败总表”“Cross-field validation matrix”“Runtime builder assemble target table”“Config validation issue surface”和“跨加载校验审计表”小节。

### 9.1 加载与校验顺序

```text
source selection
  -> transient candidate
  -> strict JSON parse
  -> duplicate / alias / unknown / forbidden scan
  -> section / required / type / range / ref validation
  -> sensitive-content / hard-boundary validation
  -> cross-field validation
  -> immutable ValidatedSyncRuntimeConfig
  -> composition binding
  -> exact capability classification
  -> immutable AdapterCapabilitySnapshot
  -> read graph
  -> mutation facade
  -> conditional operations registration
```

任一步 required validation 失败都不产生新的 typed config、snapshot 或 facade。Raw source/body 在 issue surface 前必须裁剪；Application/Domain 不重新读取 source。

### 9.2 结构、类型与 cross-field 校验

| 校验轴 | 必须满足 |
|---|---|
| syntax | runtime 只接受 strict JSON；JSONC 注释、尾逗号、截断和宽松语法拒绝 |
| structure | 九个 closed section；duplicate/alias/unknown/forbidden whole-candidate reject |
| required/nullability | 38 required leaf 全部存在；4 operations slot 只能 `null` 或 canonical opaque ref；空字符串不表示 null |
| numbers | finite safe positive integer；bytes/items/paths/records/ms 单位不可混淆；不 clamp、不默认无限/零 |
| identity/profile | `configRef` canonical；profile 只允许四个 P0 语义值；selector conflict reject |
| boundaries/jobs | `maxBatchItems <= maxTargetScopeItems`；`maxParallelItems <= maxConcurrentMutations`；job input 只能收窄 |
| metadata | store/UoW/lock 独立校验；同一 ref 不自动证明全部 capability；physical schema 不由 config 推断 |
| SDK | profile/provider/owner/source/handoff/Decision/probe 各自分类；owner 成功不推出 source/handoff 成功 |
| local tools | observation/apply/root-policy/non-overwrite 相容；LFS/shallow/GUI/remote/shell 不在 schema |
| support | redaction 只能收紧；digest adapter/algorithm 相容；deterministic provider 只在 test composition |
| operations | non-null 仍需 formal contract/capability；不得生成 topic/schema/schedule/actor/scope/key |

### 9.3 Builder 与 capability separation

Runtime builder 顺序固定为：Clock/ID/Digest → metadata read/write/UoW/lock/snapshot → filesystem/Git → SDK → diagnostics → classify capabilities → allocate immutable snapshot → read-only graph → mutation facade → conditional operations。

| 层 | 结果 | 不得混淆为 |
|---|---|---|
| source/config validation | valid typed candidate 或 safe issue | adapter 可用、owner 授权、route ready |
| capability classification | `bound/blocked/unsupported/unknown` | health、permission、source freshness、clean worktree、accepted |
| per-call disposition | known/denied/unavailable/invalid/unknown | config fallback 或全局 capability truth |
| business carrier | operation/query/consumer/job 的既有 typed result | Artifact/Baseline/Review Decision/evidence/readiness |

Read graph 不持有 UoW/write/lock/probe/handoff/diagnostic-emit capability。Mutation facade 只有在 required static bindings、redaction safety、snapshot 和 route graph 构造完成后才暴露；每个 entry 仍必须进行 exact capability 与 owner/local safety preflight。

### 9.4 生效与冻结矩阵

| 生效面 | 允许 | 冻结规则 | 失败 |
|---|---|---|---|
| startup/cold | 全局 42 leaf candidate | new composition + new immutable snapshot | no typed config/snapshot/facade |
| job-run-start | bounded job budgets 和显式 run input | current run pin；old run/report 不改 | current job rejected |
| entry-local | 当前 selector/target/path/scope/conflict/resume | current entry only；不写回 global config | current entry rejected/blocked |
| test harness | deterministic refs 和脱敏 fixture | isolated test composition | test composition fail-fast |
| reload/hot | P0 unsupported | current composition unchanged | whole-request reject |

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit_rollback.md`
>
> 延伸阅读：建议继续阅读上述文件的“变更 actor、权限边界与评审层级”“42 leaf 的变更控制分组”“变更总表”“变更审计记录规则”“生效边界与回滚规则矩阵”和“跨变更审计 / 回滚审计表”小节。

### 10.1 Actor 与风险等级

| Caller / role ref | 可提出 | 不可执行 |
|---|---|---|
| config maintainer / release automation | startup/cold candidate 和已评审 ref 变更 | 本地授权、绕过 validator、写 raw secret、启用 hot/reload |
| authorized job caller | current run 的 bounded batch/parallel/target/replay input | 改 global config、actor/scope/key、旧 report或 in-flight run |
| entry caller | current entry 的 selector/path/scope/conflict/resume input | 扩权、猜 latest/default、写回 global config |
| test harness | `ci-test` deterministic refs 和脱敏 fixture | 向 production-like 注入 fake，或生成 integration evidence/readiness |
| design-change reviewer | 评审会改变 03 的正式设计变更 | 直接让 critical runtime candidate 生效 |

这些 role ref 只是入口语境，不证明 Identity/Work/部署 owner 已授权。

| 风险级别 | 典型变更 | 门禁 |
|---|---|---|
| low | 已批准范围内收窄 limit/timeout/job budget | validation + safe audit；按既有 activation 生效 |
| medium | P0 profile/test-only refs、非安全关键 provider refs | reviewer/change ref + validation；不提升 fake capability |
| high | identity、metadata/SDK/Git/fs/root-policy、redaction/digest、operations、scope/concurrency widening | 明确评审、safe audit、rollback plan、cold activation |
| critical | raw material、redaction 放宽、implicit selection、owner/review/provenance/state/UoW/query-write override、hot/reload、auto Git actions | whole-candidate reject；若需求成立先回 00～03 |

### 10.2 变更与回退矩阵

| 变更面 | 生效 | 回退 / 失败 | 不得做 |
|---|---|---|---|
| startup candidate | strict load/validate 后 new cold composition/restart | invalid 不激活；显式选择 previous approved/validated candidate 再完整 compose | online patch、自动 LKG、半图复用 |
| identity/profile/ref | new composition；old objects pin old snapshot | 新 composition 失败则保留旧 composition，并显式修正后再试 | 改写历史 operation/attempt、fallback fake |
| job-run input | new authorized run | current run reject/partial/unknown；新 run 使用新 run identity | 接管旧 run、换 key、改旧 report |
| entry-local | current entry | caller 新 entry 显式修正 | 写回 global config、猜 selection、覆盖 dirty worktree |
| test harness | isolated rebuild | 修正 fixture 后重组 | 影响 production-like 或生成真实 readiness |
| reload/hot | unsupported | 保持 current composition | partial swap、old snapshot rebinding |
| sensitive ref rotation | new ref + cold composition/new run | old operation/attempt 保持旧 snapshot | raw material、原地替换、重提 unknown effect |

配置 rollback 只能控制后续 composition/run/entry/test 语境，不能声明撤销已经发生的 SDK、Git、filesystem、Review handoff、平台 truth 或用户工作区 effect。Unknown effect 继续使用原 key、attempt/checkpoint、formal probe/read 或 manual resolution。

### 10.3 安全审计最小集

可记录：section/slot、risk class、activation kind、opaque actor/change/reason/reviewer/rollback/issue refs、approved redacted canonical digest、validation/capability/activation disposition 和 bounded timestamp/context。

不得记录：raw config、secret、full sensitive ref、endpoint/path/body、Git output、provider response、完整 diff，或把 audit receipt/digest 当 Artifact、Baseline、Review accepted、evidence、signoff、readiness。

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_degradation.md`
>
> 延伸阅读：建议继续阅读上述文件的“策略术语与既有 disposition 映射”“失效决策流程图”“42 leaf 按配置域的失效覆盖”“通用失效模式表”“按 activation surface 的失败矩阵”和“观测、告警与安全字段矩阵”小节。

### 11.1 策略词汇

| 策略 | 精确定义 | 不得解释为 |
|---|---|---|
| `fail-fast` | 当前边界立即停止，不产生新 typed config/composition，或不启动当前 job/entry/test | 外部 rollback、Review 结论、平台 truth |
| `fail-closed` | 安全/ownership/provenance/dirty/path/redaction 不明确时拒绝 | bound、健康、授权、accepted、readiness |
| `degraded` | 读取/非核心依赖不完整被显式保留，不伪造 local truth | 非法配置的成功替代 |
| `delayed` | 既有 Consumer/Job 语义允许暂缓当前处理并保留 key/ref/status | 自动扩大 scope、换 key、盲重放 |
| `failed_known` | effect 已知失败，由既有 carrier 表达 | 外部 owner 已回滚或 Review rejected |
| `outcome_unknown` | 无法证明 effect 是否发生，保留 attempt/checkpoint 并 probe/manual | “失败所以未发生”、自动 retry |
| `blocked/unsupported/unknown` | capability/route posture | parse success、健康、授权或 readiness |
| restart rollback | 显式选择已验证候选后重新 load/validate/cold compose | online LKG、in-flight snapshot rebinding |

### 11.2 配置错误与运行依赖失效

| 场景 | 系统行为 | 恢复 / 禁止 |
|---|---|---|
| required section/leaf 缺失 | startup fail-fast；无 typed config/snapshot/facade | 修正候选；不 fallback lower source |
| strict JSON/duplicate/alias/unknown/forbidden | whole-candidate reject + safe issue | 不忽略、不 last-write-wins |
| type/range/ref/cross-field/sensitive 错误 | startup/job/entry/test 对应边界 reject | 不 clamp、不回显原值 |
| legal ref but contract blocked/unknown | conservative snapshot；affected route blocked | 关闭真实 blocker 后 new composition |
| metadata read unavailable | Query partial/unavailable；mutation blocked | Query 不 repair/write |
| local commit timeout | `commit_status_unknown`，原 identity/digest reload | 不用新 key/cache/log猜成功 |
| owner/source read unavailable | command blocked/dependency unavailable；Query unavailable | 不本地授权或猜 source |
| Review handoff/Decision/probe unavailable | blocked 或 `outcome_unknown`；probe/manual | ACK/timeout 不等 accepted；不 resubmit |
| Git observation unavailable | inspect unavailable/blocked；apply 禁止 | unknown 不当 clean |
| Git/fs apply partial/unknown | checkpoint + `outcome_unknown`；cursor 不推进 | 不自动重放/覆盖/merge/rebase/push/stash |
| diagnostics sink unavailable | 业务 disposition 不变；安全 drop/unavailable | 不 rollback/replay effect，不用 raw fallback |
| operations slot `null` | 不注册对应 Consumer/runner | 不创建 runtime resource，不报告 ready |

### 11.3 Drift、expiry 与 activation surface

| Surface | 配置/输入失败 | 依赖失败 | 允许恢复 |
|---|---|---|---|
| startup/cold | fail-fast/fail-closed；不产生新 graph | required route blocked/unknown | 修正或显式选择已验证候选后 cold restart |
| job-run-start | current job rejected | runner/target unavailable → blocked/failed_known/partial/unknown | new authorized run；旧 report/run immutable |
| entry-local | current entry rejected | owner/source/Git/fs/metadata unavailable → blocked/unavailable/unknown | new explicit entry；Query zero-write |
| test harness | test composition fail-fast | test adapter blocked | 修正脱敏 fixture 后重组 |
| reload/hot | unsupported reject | N/A | 显式 startup restart only |

Candidate/config digest 漂移阻止新 composition；在途对象继续原 snapshot。External/ref/fixture expired 或 freshness 无法安全判断时，mutation fail-closed，read surface可返回 unavailable/unknown；本文不新增隐式 TTL、自动 refresh、repair 或 retry。

### 11.4 安全观测

配置拒绝、capability blocked、query degraded、consumer/job disposition、effect unknown 和 drift/expiry 可以通过既有 safe telemetry/diagnostic seam 记录 closed code、slot/capability、bounded ref、redaction marker 和 disposition。不得记录 raw config/full ref/secret/body/path/Git output，也不得把 alert receipt 或 metric 当 evidence、accepted 或 readiness。

11. Query/operations：Query zero-write，operations.* = null 不注册资源，未闭合 contract 不启动 runner；
12. evidence boundary：设计输入、实际 run、artifact、report、evidence、verdict、signoff、readiness 必须分层。

## 13. 配置迁移、废弃与演进

> 校准来源：
> - design-calibration/04_config_step_13_migration_deprecation_evolution.md
>
> 当前无可核验的已发布旧 runtime config schema、旧 canonical leaf、旧 alias、旧环境映射或旧 .qs-sync physical schema 迁移合同。README、旧 05/06、draft 和历史配置片段均为 historical_material，不得自动解析、兼容、转换或写回当前 P0 candidate。

### 13.1 迁移与废弃规则

| 场景 | P0 处理 | 未来启用条件 |
|---|---|---|
| unknown section/key、alias、旧命名或重复 key | whole-candidate reject；不猜测映射 | 先确认 canonical mapping，再回写 03/04 并增加测试/验收门禁 |
| 缺失 required leaf | fail-fast；不使用历史默认或旧 snapshot | 明确新 schema 的 default_allowed 或 migration contract |
| nullable operations leaf 缺失 | 仅归一为 null；表示未注册，不表示 ready | 新 contract/registration 先经 03/04 |
| sensitive ref/provider 轮换 | 新 opaque ref + 新 candidate + cold composition；旧 operation/attempt 继续旧 snapshot | provider、rotation、审计合同闭合 |
| .qs-sync physical schema/migration/retention/crash semantics | 不推断；保持 SYNC-UP-006 blocked | metadata owner 与 03 durable carrier 回写闭合 |
| profile rename/environment remap | 不隐式转换；显式选择新 profile/candidate | 发布迁移说明、回退候选和验收门禁 |
| config center/admin override/hot/LKG | P0 unsupported/reject | 先回写 03，再重开受影响 04 Step |

### 13.2 废弃生命周期

未来批准的变更必须显式登记 introduced → active → deprecated → rejected/removed 生命周期、受影响 canonical leaf、替代项、兼容窗口、审计 marker、回退候选和 owner。deprecated 不等于已移除；rejected/removed 不得静默接受；任何 public DTO/error/state/carrier 变化都必须先回写 03。

### 13.3 .qs-sync 双轨边界

本文只定义 logical metadata binding（store/UoW/lock/snapshot、cursor/mapping/conflict/provenance 的 owner relation 和安全边界），不定义 physical file/table/key、版本号、migration script、retention、crash recovery 或删除语义。逻辑配置演进与物理 metadata 演进必须分轨，未闭合前不得把其中一轨伪装成另一轨已迁移。

### 13.4 演进触发器

新增/删除/重命名 leaf、section、profile、required/nullability 或 source；remote config center/admin override/reload/hot/online LKG；secret provider API/rotation/audit；retry/backoff、Consumer/Job、scheduler/topic/scope/key、新 durable carrier；physical .qs-sync migration；Git LFS、浅克隆、GUI/Tauri、具体 library/bin/parser/SDK dependency 的正向支持；或任何改变 Project/Artifact/Baseline/Review Gate/Workspace/Archive/Git remote ownership、provenance 或 evidence boundary 的设计，均必须先回写 03 并重新执行受影响 04 Step。触发前只允许 planned/blocked/waiting。

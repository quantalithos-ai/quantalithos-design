## 2. 验收目标与范围

> 校准来源：
> - `design-calibration/06_acceptance_step_02_scope.md`
>
> 延伸阅读：阅读该文件的“验收范围矩阵”“P0 能力到需求映射”“范围裁决流”和“回填草稿”。

本轮验收目标是裁决 `L5-sync` 的 local sync contract、所有权边界、安全红线、接口/状态/一致性、配置和证据结构是否满足交付门禁。Sync 可以拥有 local sync session、working-copy metadata、cursor、mapping、conflict、checkpoint、attempt、provenance、受限 observation 和 safe diagnostic；不得拥有 Project、Artifact、Baseline、Review Gate/Decision、Workspace projection、Archive 或 Git remote truth。

| 范围项 | 类型 | 优先级 | 裁决目标 | 非范围/限制 |
|---|---|---:|---|---|
| `CP-SYNC-01` selection/access | core local contract | P0 | explicit principal/project/version/source/target/operation；owner/access/posture unknown fail-closed | 不拥有 Identity/Work truth；owner positive contract 未闭合时 blocked |
| `CP-SYNC-02` binding/metadata | core local contract | P0 | binding、generation、manifest、cursor、mapping、provenance 可回链 | `.qs-sync` physical schema、driver、retention、crash semantics blocked |
| `CP-SYNC-03` status/pull/materialize | local contract + tool seam | P0 | status zero-write；pull 仅在 comparator/gap/path/dirty/source/access known-safe 时执行 | source provider/Git/fs positive integration blocked |
| `CP-SYNC-04` conflict/recovery | core local contract | P0 | conflict fact、checkpoint、manual resolution、probe、resume/cancel 可解释；不盲重放 | formal probe/Git/fs exact contract blocked |
| `CP-SYNC-05` handoff/provenance | local candidate/attempt contract | P0 | candidate freeze、attempt-before-call、transport/probe/Decision 分层 | Governance Gate/Decision owner truth blocked |
| `CP-SYNC-06` posture/diagnostic | local safety/read surface | P0 | posture 收紧、diagnostic body-free/bounded、Query zero-write | Observability backend/evidence truth 不属本仓 |
| 10 Command、13 Query | public protocol | P0 | exact validation、分层结果、Query no-write | CLI parser、binary、exit code、tool library 待确认 |
| 3 Consumer、3 Job | conditional operations | P0 contract / P1 positive | envelope、receipt、保守失效、per-item、replay、no-repair | event/source/scheduler exact contract 未闭合时 blocked |
| 42 leaf、4 P0 profile | configuration | P0 | strict JSON、source precedence、required/nullability、activation/failure/redaction | 实际 secret provider/部署不在本文实现范围 |
| SDK/source/access/review/probe、physical metadata、Git/fs | external/local seam | P1 | 合同闭合后证明 adapter mapping 和 fail-closed | `SYNC-UP-*`/`SYNC-LOCAL-*` 当前阻塞 |
| 批量预取、结果比较、归档引用、容量数字、LFS、浅克隆、GUI/Tauri | peripheral | P2/deferred | 只有明确 scope trigger 后扩大范围 | 不改变 P0 安全门禁 |

P0 功能失败不得被 P1/P2 结果抵销；P1 positive unavailable 只有在 P0 local/negative/evidence 完整且风险有正式接受人时，才可能进入“有条件通过”候选。

## 3. 验收基线

> 校准来源：
> - `design-calibration/06_acceptance_step_03_baseline.md`
>
> 延伸阅读：阅读该文件的“验收基线表”“证据入口基线”“不可接受引用”和“基线固定门禁”。

正式验收必须固定以下基线；当前设计阶段只定义占位格式，不填写实际 source ref、implementation/build、config digest、fixture 或 `run_id`。

| 基线类型 | 必须固定内容 | 标识格式 | 当前状态 |
|---|---|---|---|
| 需求/设计 | 00～04 source ref、commit 或 digest | `<design-ref-00>` ～ `<design-ref-04>` | 待送验固定 |
| 测试方案 | `05-测试方案.md` source ref/digest | `<test-plan-ref>` | 待送验固定 |
| 标准 | SOP、书写规范、真相源闭环标准 source ref | `<standard-ref>` | 待固定 |
| 交付 | implementation commit、build id、image digest | `<delivery-ref>` | 未提供；缺失不得开始真实验收 |
| 依赖 | L0/core contract 与需消费的 owner refs | `<dependency-ref-set>` | 合同部分待定 |
| 环境/配置 | `local-dev`、`ci-test`、`integration-like`、`operations-replay`；config digest/runtime composition | `<profile-ref-set>` | 设计已定义，实例待固定 |
| 数据 | 脱敏 fixture、seed、replay root、清理说明 | `<fixture-ref-set>` | 未提供 |

固定证据入口：

| 入口 | 固定路径 | 用途 |
|---|---|---|
| 原始 artifact | `artifacts/test/<run_id>/...` | 复核机器原始 suite/case 证据、digest 和失败原因 |
| 运行报告 | `reports/runs/<run_id>/...` | 阅读 summary、gate、EV index、redaction/dependency/report audit |
| 验收交接 | `reports/acceptance/handoff.md` | 送验范围、基线、P0/P1/P2、未覆盖和审查 |
| 一票否决清单 | `reports/acceptance/veto-checklist.md` | 逐项检查 VETO，不得默认 passed |
| 风险接受 | `reports/acceptance/risk-acceptance.md` | 支撑有条件通过，必须含 acceptor 和后续动作 |

禁止使用 `latest`、工作树当前状态、`artifacts/test/<project>/<run_id>`、`reports/<project>`、local Git commit 作为 Artifact/Baseline、ACK/HTTP 200/remote object/cache/log/telemetry/job report 作为 accepted/approved/signoff/readiness。

## 4. 进入条件与退出条件

> 校准来源：
> - `design-calibration/06_acceptance_step_04_entry_exit.md`
>
> 延伸阅读：阅读该文件的“进入条件”“退出条件”“暂停/不可裁决条件”和“进入/退出来源追溯”。

### 4.1 进入条件

- [ ] 00～05、标准、依赖 source refs 已固定。
- [ ] implementation commit/build/image digest 已固定，且不是 `latest` 或未提交工作树状态。
- [ ] 四个 P0 profile 的 config digest、source precedence、runtime composition、fixture/replay root 已固定。
- [ ] 单一 `<run_id>` 已固定；raw root 为 `artifacts/test/<run_id>/`。
- [ ] 每个 P0 blocking suite 有 raw `report.json`、case refs、status、failure reason、profile/config ref 和 artifact digest。
- [ ] `reports/runs/<run_id>/` 有 summary、gate-results、evidence-index、suite reports、redaction-check、dependency-boundary、report-audit。
- [ ] `reports/acceptance/handoff.md`、`veto-checklist.md` 已生成并经人或 Agent 审查；有 residual 时另有 `risk-acceptance.md`。
- [ ] 无未关闭 S/VETO、redaction/dependency/report audit 阻断；P0 unavailable 不得标 passed。

### 4.2 退出条件

- [ ] 每个 `AC-SYNC-001~020` 有明确 `通过/失败/不适用+正式理由`。
- [ ] 每个 P0 AC 可回指正式设计契约、`TC-SYNC-*`、`EV-SYNC-*`、固定 report path 和 raw artifact。
- [ ] `VETO-SYNC-001~005` 均有真实检查证据，未默认 passed、未被风险接受覆盖。
- [ ] P0 blocking suite 均有 raw artifact/report pair；evidence index 无 orphan EV、latest 或项目子目录路径。
- [ ] redaction/dependency/report audit 均通过，或失败明确导致不通过。
- [ ] Query zero-write、owner truth boundary、dirty non-overwrite、unknown fail-closed、ACK≠accepted、commit≠Artifact/Baseline 有证据覆盖。
- [ ] S=0；A 已修复复验或有允许的正式接受；B/R 已进入风险接受并有责任人、接受人和截止/触发条件。
- [ ] 最终结论和签署材料齐备；签署不替代风险接受。

### 4.3 暂停/不可裁决

缺 source/build/config/fixture/run、缺 raw/report pair、静态 evidence、VETO/redaction/dependency/report audit 失败、设计契约无法绑定或 handoff 未审查时，只能暂停或不通过。上游正向 owner/Git/fs/physical contract 未闭合时，保持 `blocked/waiting`，不得用 fake、cache、ACK、log、telemetry 或静态 mapping 关闭。

### 7.1 协议计数与依赖边界

| 协议族 | 精确数量/名称 | 验收口径 |
|---|---:|---|
| Command | 10：`CloneWorkingCopy`、`MigrateSyncMetadata`、`RebindWorkingCopy`、`PullWorkingCopy`、`RecordConflictResolution`、`ResumeSyncOperation`、`ProbeUnknownOutcome`、`CancelSyncOperation`、`PushReviewCandidate`、`RefreshReviewHandoffStatus` | envelope、typed ref、validation、same/different digest、version/generation、prepare-before-effect、known/partial/unknown、exact carrier、禁止调用 |
| Query | 13：`GetAccessEvaluation`、`GetSyncOperation`、`GetWorkingCopyBinding`、`GetMetadataHealth`、`InspectWorkingCopy`、`GetMaterializationStatus`、`GetConflict`、`ListConflicts`、`GetRecoveryStatus`、`GetSyncStatus`、`GetReviewHandoffStatus`、`GetProvenance`、`GetSyncDiagnosticSummary` | hit/missing/not-visible/partial/unavailable/stale；不 begin UoW、reserve idempotency、write/lock/probe/handoff/diagnostic emit |
| Inbound Consumer | 3：`ConsumeAccessOrPostureInvalidated`、`ConsumeMaterialSourceInvalidated`、`ConsumeReviewDecisionChanged` | envelope/source/schema/version/digest/idempotency；只收紧 local snapshot/plan/candidate；duplicate/quarantine 保守处理 |
| Outbound Event | 0，`not_applicable` | 不创建 outbox/topic/publisher/event state；local transition 不升格平台 event truth |
| Operations Job | 3：`ScanMetadataIntegrity`、`ProbePendingHandoffAttempts`、`MarkStaleOwnerSnapshots` | bounded input、per-item version/UoW、exact replay、partial/unknown、无 repair/migrate/rebind/delete/submit/readiness |

### 7.2 跨仓依赖验收

| 依赖类型 | 允许范围 | 验收方式 |
|---|---|---|
| 编译期 | `L0-core`、`L0-sdk` 既定边界 | 只验 shared contract/typed seam；不得引入 sibling business compile dependency |
| 运行期 | Identity、Work、Artifact、Workspace、Governance、Archive、Observability 经 SDK/adapter | 验 typed request/response/error/availability 和 fail-closed；exact contract 未闭合时 blocked/waiting |
| 事件协作 | 条件 inbound consumer；经正式 event seam | 验 envelope/receipt/quarantine/conservative invalidation；不新增 outbound event |
| 本地工具 | Git/filesystem/metadata adapter | 验白名单、path/dirty/lock、atomic materialize、unknown；支持矩阵未闭合时 blocked |

### 8.2 事务与原子可见性

| UoW 边界 | 必须共同可见的写集 | 失败条件 |
|---|---|---|
| operation transition | operation revision、transition、terminal local result、provenance | terminal 但 carrier/result/provenance 缺失 |
| binding/generation | new generation、old protected refs、metadata transition、provenance | 旧链覆盖/删除或新 binding 缺 ref |
| materialization finalize | run Finalized、cursor、mapping、manifest/binding、plan/path、provenance、stored result/idempotency completion | cursor 先动、partial/unknown 当 Finalized |
| handoff prepare | Prepared attempt、invocation identity、checkpoint、candidate relation before external call | effect 已发但 attempt/checkpoint 不可回链 |
| probe prepare/finalize | probe/invocation before probe；result/attempt/checkpoint/provenance after | probe 覆盖 prior unknown 或 carrier 缺失 |
| accepted Consumer | conservative transition、provenance、full receipt、idempotency completion | raw payload 入库、receipt 缺失、修改 owner truth |
| completed Job | per-item committed changes、typed job result、idempotency completion | batch completed 隐藏 item failure或冒充 readiness |

### 8.3 幂等、并发和 unknown

- same identity + same digest + completed：必须 exact replay stored typed carrier，零新 effect。
- same identity + different digest：必须 `idempotency_conflict`，zero write/effect。
- reserved/in-flight：必须 delayed/already-in-progress，第二 writer 为零，不接管、不换 key。
- commit status unknown：保持原 identity/digest，reload idempotency、carrier、subject version、attempt/checkpoint；缺失或错 kind 为 consistency defect/manual intervention。
- version/generation/lease/fingerprint race：stale UoW 回滚或转 conflict/needs_action，不能 stale overwrite。
- Query 每次只读；不得以 refresh、repair、probe、lock 或诊断写入补齐结果。

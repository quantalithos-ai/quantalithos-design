### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L5-sync` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L5-sync` 是系统间状态同步与跨端一致性产品层 / sync experience 层,不是 source truth 仓或总线仓
- SyncTask / SyncStatus / ConflictView / SurfaceSyncView / ReplayRequest 构成正式同步体验层真相
- `SyncTask ≠ source domain truth`、`SyncStatus ≠ source object state`、`sync pipeline ≠ bus truth`、`ConflictView ≠ source conflict truth` 等核心边界必须成立
- source change → sync task → status → delivery → recovery 五条同步体验主线必须能统一组织,且 source refs 持续可追溯
- stale / conflict / lag / replay / resync 都必须有统一状态与修复入口,不得让用户和 operators 误解“已同步/已恢复”
- per-surface sync views 只消费 source results,不反写源真相,并且 chat / console / runner 必须看到一致状态
- replay / resync / repair 只重做同步过程,不重做业务裁决或改写 source truth

因此,本次验收的目的不是笼统判断“能不能把变更同步到多个面”,而是判断 sync 的 task 主线、status 主线、conflict 主线、delivery 主线与 recovery 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 同步对象识别与任务入口部分 | 是 | SyncTask、SyncTarget、SyncScope、SyncAudience、SourceChangeIntake |
| 同步编排与状态推进部分 | 是 | SyncStatus、SyncCheckpoint、SyncLagSnapshot、SyncAckRecord、SyncProgressView |
| 冲突检测与一致性修复部分 | 是 | ConflictView、DivergenceRecord、StaleMarker、ResolutionProposal、ManualResolveEntry |
| 跨端分发与消费体验部分 | 是 | SurfaceSyncView、DeliveryEnvelope、VisibilityFilter、SurfaceSyncSummary |
| 重试、回放与运维干预部分 | 是 | ReplayRequest、ResyncTicket、RepairEntry、BacklogInspection、SyncRecoveryRecord |
| source truth 仓、L0-bus transport truth、底层队列/CDC/复制系统本体 | 否 | 只验 sync 如何消费 source changes 并组织一致性体验,不验底层真相和基础设施全部实现 |
| 自动化修复脚本和 source-side 真正业务修复逻辑 | 否 | 只验 sync repair/replay 入口与状态链,不验底层修复脚本全部实现 |
| observability / archive 真相本体 | 否 | 只验 sync 如何输出诊断和恢复证据,不验其他仓全部实现 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateSyncTask / BindSourceChange | 合法 source refs 和 target surfaces 时必须形成正式 SyncTask | API 响应 / DB 记录 / refs compare | [] |
| SyncTask 边界 | SyncTask 只能表达同步任务,不得替代 source domain truth 或 source object truth | task/source compare / negative flow | [] |
| AdvanceSyncStatus / RecordCheckpoint | sync task 推进后必须形成统一 SyncStatus / checkpoint / lag 记录 | status record / checkpoint / lag report | [] |
| SyncStatus 边界 | sync status 只能表达同步过程,不得替代 source object state 或 bus truth | compare report / negative flow | [] |
| DetectConflict / BuildConflictView | stale/divergence/failed 时必须形成统一 ConflictView / ResolutionProposal / ManualResolveEntry | conflict view / resolution proposal / stale markers | [] |
| Conflict 边界 | conflict view 只能表达解释层冲突,不得替代 source conflict truth | compare report / negative flow | [] |
| BuildSurfaceSyncView / DeliverSurfaceProjection | synced/replaying 状态必须正确分发到 chat / console / runner 等消费面 | per-surface view / delivery trace / cross-surface compare | [] |
| Delivery 边界 | sync-ready projection 只能消费 source results,不得替代 source projection truth 或让不同消费面看到冲突状态 | view/source compare / negative flow | [] |
| TriggerReplay / TriggerResync / CreateRepairEntry | failed/stale/conflict 时必须形成正式 replay/resync/repair 入口与证据链 | replay request / resync ticket / repair entry / history | [] |
| Recovery 边界 | replay/resync 只能重做同步过程,不得重做业务裁决或直接改写 source truth | replay/source compare / negative flow | [] |

## 7. 安全与治理门禁

| 门禁项 | 要求 | 证据 | 结论 |
|---|---|---|---|
| SyncTask 不可反写真相 | sync 任务与状态不得回写 source truth | task/source compare / negative flow | [] |
| sync pipeline 不可冒充 bus truth | 同步链只能消费 bus,不能替代 transport truth | pipeline/bus compare / negative flow | [] |
| conflict 解释层不可冒充源冲突真相 | ConflictView 只能解释不一致,不能替代 source conflict 模型 | conflict/source compare / negative flow | [] |
| replay/resync 不可越权 | replay/resync 只能重做同步过程,不得改写 source truth 或重做业务裁决 | replay/source compare / negative flow | [] |
| per-surface 一致性不可失真 | 任一消费面 stale/lag 时不得整体显示为 synced | cross-surface compare / stale logs | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | sync 任务或状态反写真相 / conflict 误导为 source truth / per-surface 仍 stale 却整体显示 synced / replay/resync 越权改写真相 |
| A | 视情况 | 主线可跑但 stale/lag、repair 票据、delivery 一致性或 backlog 诊断不稳 |
| B | 可带着走 | 非关键视图、低优先级 backlog 展示或趋势异常 |

## 5. 实施阶段与依赖顺序

> 校准来源：
> - `design-calibration/07_implementation_plan_step_05_phases.md`
>
> 延伸阅读：阶段依赖图、阶段总表、可验证增量说明和跨 phase 依赖闭环审计。

本计划在实现仓存在且获得明确移交授权后，按单 agent、单序列、先设计门禁后工作区门禁的顺序推进。当前只固定未来顺序，不授权任何实现。

```text
PH-01 Foundation and composition
  -> PH-02 Selection/access and metadata
  -> PH-03 Inspection and materialization
  -> PH-04 Conflict/recovery and consistency
  -> PH-05 Review handoff and provenance
  -> PH-06 Query and CLI surfaces
  -> PH-07 Consumers, jobs and operations
  -> PH-08 Gates, reports and acceptance handoff
```

| `PH-02` | explicit selection/access、operation、binding、generation、cursor、mapping | PH-01 | `commit-02-a/b` | `blocked` |
| `PH-03` | read-only status/inspection、delta/plan、path safety、known-safe materialization | PH-02 | `commit-03-a/b` | `blocked` |
| `PH-04` | conflict facts、checkpoint、manual resolution、probe、unknown/replay/idempotency | PH-03 | `commit-04-a/b` | `blocked` |
| `PH-05` | candidate freeze、attempt-before-call、transport/probe/Decision 分层、provenance protection | PH-04 | `commit-05-a/b` | `blocked` |
| `PH-06` | 13 Query zero-write、诊断脱敏、CLI safe entry | PH-05 | `commit-06-a/b` | `waiting` |

- 不按文件、对象或外部服务目录提前实现；每个阶段必须形成可审查的行为增量。

- physical `.qs-sync`、owner positive contract、Git/filesystem effect 和 Review/Decision positive contract 未闭合时，相关阶段停在 `blocked` 或 `waiting`。
- PH-08 只能审查真实固定 run 的 artifact/report；计划标识、静态模板和 fake 不能关闭验收门禁。

`.qs-sync` logical schema 的最小闭环如下；它是实现 boundary 的字段分组和一致性检查表，不是未经批准的 physical file/table schema：

| Logical record family | Identity/version boundary | Required consistency |
|---|---|---|
| binding/manifest/generation | binding identity、manifest identity、`LocalEntityVersion`、generation ref | binding、manifest、cursor、mapping 同 binding+generation；迁移建新 generation，旧链保留 |
| cursor/mapping | source cursor ref、continuity state、mapping ref、expected local version | observed cursor 与 applied cursor 分离；只有 known `Finalized` finalize 才推进 applied cursor |
| integrity/observation | metadata integrity state、working-copy fingerprint/observation ref | Query observation 不落库、不修复；corrupt/unknown/restricted 保留并显式暴露 |
| operation/run/checkpoint | operation/run/checkpoint IDs、generation、fingerprint、prior attempt ref | prepare/effect/finalize 分离；partial/unknown 保留 checkpoint，不能补写 Finalized |
| provenance/candidate/attempt | provenance id、subject/parent/digest index、candidate/attempt refs | append/protect/supersede/integrity-unknown；不删除 parent，不把 ACK/local commit 升格 |
| idempotency/receipt/result | `(channel, operationName, key)`、canonical digest、typed stored carrier、consumer/job identity | same digest exact replay；different digest conflict；carrier 缺失是 consistency defect，不重算 truth |

所有 public carrier、view、receipt、job result、diagnostic 和 report hook 都必须保留 missing/not-visible/partial/unknown/degraded 语义；不得以 empty/clean/success/accepted/ready 替代。此索引不授权实现，且受 §9 blocker 与 §12 完成判定约束。

## 10. 回退、暂停与变更控制

> 校准来源：
> - `design-calibration/07_implementation_plan_step_10_rollback_change.md`

触发字段/DTO/ref/state/metadata 缺口、owner/source/review/probe unknown、dirty/untracked/path/symlink/lock unknown、Build/Test/Redaction/Dependency gate failure、VETO/S defect、Scope Gate 越界、用户改动被触碰、design baseline 改变或 raw secret/body/path/Git output 泄漏时，立即暂停受影响 boundary；记录 blocker，不跳过门禁。

| 场景 | 允许动作 | 禁止动作 | 恢复条件 |
|---|---|---|---|
| 未提交 boundary 的 gate fail | 在 allowed scope 内修复并重跑 | reset/checkout 用户文件、跨 boundary 修复 | 当前 gate 真实通过 |
| 已提交 boundary 缺陷 | 新 fix boundary 或项目规则允许的安全 revert | 改写已交付 commit | 原 TC/family/audit 复验 |
| external effect unknown | 保留 identity/digest/attempt/checkpoint，正式 probe/manual | retry、换 key、push/merge/rebase/stash | known result 或人工 resolution |
| partial materialization | 保留 checkpoint，cursor 不推进 | 自动清理、重放、覆盖 dirty | safe recovery + revalidation |
| 设计变化 | 标记旧 boundary superseded/blocked，重切并刷新 baseline | 在代码中静默兼容两个真相 | 新设计和新 boundary 审核 |
| report/evidence 失败 | 保留原 run，只重跑 check/report | 用 `latest` 覆盖旧 run | pairing/redaction/report audit |

变更类型与回写范围固定为：新字段/DTO/state 回写 03（必要时 05/06）；新 config leaf/source 回写 04/05/06；owner/API/error/version 回写 01/03；test/suite/evidence path 回写 05/06/07；phase/boundary 变化回写 07 flow、Step 6、ledger skeleton；用户新增功能或启用历史 LFS/浅克隆/GUI 先回到 00～03 重审。`blocked` 不得直接跳到 `implement`；unknown 不得被代码回退伪造成 known/failed。

# 03 · L5-sync 模块划分与分层（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源
> 前置：`draft/01_项目作用与交互对象.md`、`draft/02_功能推演.md`。本文是候选职责图，不授权创建代码模块、crate、数据库表、CLI 路由、事件 schema 或 worker。

## 1. 模块划分原则

模块边界围绕“本地受控同步操作”而不是“平台所有状态”划分。每个模块必须能说明：它拥有哪种 Sync-local truth、读取哪个正式 seam、失败时如何停下，以及如何避免把本地状态冒充 Project、Artifact、Baseline、Review Gate、Workspace、Archive 或 Git remote truth。

## 2. 业务主要组成部分（候选）

| # | 组成部分 | 核心职责 | 不承担什么 |
|---|---|---|---|
| 1 | `Sync local truth core` | 维护 session、binding、cursor、mapping、conflict、attempt、recovery、provenance 和其不变量。 | 不拥有任何平台真相，不把 transport 或 local commit升级为业务状态。 |
| 2 | `Selection and access gateway` | 接收显式 project/version/source/target，协调 principal、权限、项目姿态和允许操作检查。 | 不认证、不创建 ProjectMember、不本地解释 authorization。 |
| 3 | `Artifact/Workspace source resolver` | 解析可消费的 material source、版本、来源优先级、snapshot/incremental seam 和回链。 | 不拥有 Artifact/Workspace projection、正文、版本链或 baseline。 |
| 4 | `Working-copy and metadata manager` | 识别目标目录、维护 `.qs-sync` 受控 metadata、锁、mapping、迁移和完整性结果。 | 不覆盖 dirty worktree、不删除/伪造 provenance、不把 metadata 当平台真相。 |
| 5 | `Git/filesystem observation and adapter boundary` | 观察 HEAD/index/tree、文件指纹、工具能力并执行受限读写/原子 materialization。 | 不自动 merge/rebase/push，不决定 Review 或 remote truth。 |
| 6 | `Incremental pull/materialization` | 比较 cursor/version、应用安全增量、维护 checkpoint 和本地 applied cursor。 | 不在 comparator/gap 不明时猜测，不绕过冲突保护。 |
| 7 | `Conflict and local-change protection` | 分类 dirty/conflict/metadata/source 分叉，冻结危险操作并提供人工决策/恢复点。 | 不自动解决、stash、覆盖或删除证据。 |
| 8 | `Review preparation and handoff` | 形成候选、冻结本地状态、调用正式 handoff、记录 ACK/probe/ref。 | 不上传即接受、不批准、不自动 push、不拥有 Gate。 |
| 9 | `Recovery, idempotency, diagnostics and archive posture` | 处理 prepare→call→probe/finalize、重试、unknown outcome、归档姿态和安全诊断。 | 不把诊断/重试/归档提示当外部真相或完成证据。 |

### 2.1 组成部分关系

```text
      [Selection & access gateway]
                  |
                  v
      [Source resolver] ---- owner SDK/read seams
                  |
                  v
 [Working-copy + metadata manager] <---- [Git/filesystem adapters]
                  |
                  v
       [Incremental materialization]
             |              |
             v              v
 [Conflict/local protection] [Sync local truth core]
             |              |
             +-------+------+
                     v
         [Review preparation/handoff]
                     |
                     v
 [Recovery/idempotency/diagnostics/archive posture]
```

该图表示依赖方向而非必须的运行时调用顺序。所有模块共享的状态必须由 local truth core 以可审计方式收口；外部 owner 调用只能经 port/adapter。

## 3. 实现分层（候选）

| 分层 | 候选职责 | 边界纪律 |
|---|---|---|
| CLI / inbound operations | 解析 `clone`、`pull`、`status`、`push-review` 及后续命令方向，展示安全结果和 needs-action。 | 精确参数、退出码和 transport 待正式 Step 5+；入口不直接写平台 truth。 |
| Application orchestration | 编排选择、权限、source resolve、local observation、materialization、handoff 和 recovery。 | 跨域调用只经 ports；区分 query/status 与显式写操作。 |
| Local domain/state | 定义 Sync-owned session、binding、cursor、mapping、conflict、attempt、provenance、posture snapshot 等候选对象。 | 不复制外部实体正文、授权规则或 Review decision。 |
| Platform SDK ports | 抽象 identity/work/artifact/workspace/governance/archive query、source fetch、handoff、probe。 | port 不是 owner；无正式合同就保持 blocked，不补造 RPC。 |
| Git/filesystem adapters | 读取本地状态，执行白名单内的 materialize/锁/原子文件操作。 | 明确禁止 merge/rebase/push；必须先做 dirty/path/metadata 检查。 |
| Metadata persistence | 保存 `.qs-sync` 受控 metadata、版本/完整性、migration、provenance 和恢复 checkpoint。 | 目录/schema/加密/保留仍 pending；不得把 credential 写入 metadata。 |
| Conflict/recovery services | 比较来源与本地状态，保存冲突、checkpoint、idempotency/probe 和结果分层。 | 不隐式重试副作用，不删除冲突证据，不把 ACK 当 verdict。 |
| Read/status surface | 组装可解释状态、coverage、provenance、degraded/blocked 原因。 | status 只观察，不推进 cursor、refresh 或业务状态。 |
| Review handoff surface | 产生候选、冻结、提交和外部状态查询的安全边界。 | 不接受、不 signoff、不自动推送或改变 Gate。 |
| Diagnostics/observability | 记录 correlation、审计事件、工具能力和安全故障上下文。 | 诊断不是成功 truth，敏感信息需裁剪。 |

## 4. 关键对象类别（字段后置）

### 4.1 Sync-owned local truth

| 对象类别 | 可能承载 | 关键隔离 |
|---|---|---|
| `SyncSession` | principal 关联、operation、阶段、attempt、结果和关联 ID。 | 不是平台 job、Project lifecycle 或 Review lifecycle。 |
| `SourceBinding` | project/version/source/target ref、权限/姿态检查结论、绑定世代。 | 不拥有 source 实体或授权。 |
| `WorkingCopyBinding` | 本地绝对/规范化路径标识、Git/filesystem capability、目标指纹和锁语境。 | 不等于 Workspace projection 或 Git remote。 |
| `CursorState` | source cursor、local applied cursor、generation、gap 和 comparator 结果。 | 不等于 bus delivery cursor、Git commit 或用户 read cursor。 |
| `MappingRecord` | source item/version 到本地路径/object 的可回链映射。 | 不成为 Artifact lineage、Baseline 或 remote branch。 |
| `ConflictRecord` | 冲突类型、受影响路径/ref、检测证据、用户决策和恢复点。 | 不存放自动解决或伪造“无冲突”结论。 |
| `HandoffAttempt` | 候选 revision、冻结、请求幂等键、transport outcome、probe 状态和外部 ref。 | 不承载 Review accepted/Decision authority。 |
| `ProvenanceRecord` | source/version/path/tool/cursor/handoff 的来源关联与完整性。 | 不可静默删除或伪造；具体保留规则 pending。 |
| `RecoveryCheckpoint` | 可安全重启的阶段、输入指纹、已完成局部步骤和下一动作。 | 不证明外部副作用已完成。 |

### 4.2 外部 ref / observation

| 类别 | 允许保存 | 禁止解释 |
|---|---|---|
| principal/access ref | 调用主体、权限检查 ref、过期/撤销结果 | 本地授权真相、成员生命周期 |
| Artifact/Workspace source ref | 可 materialize 的来源、版本和水位 | 本地文件就是 Artifact/Baseline |
| Git observation | HEAD、index/tree、dirty/untracked、工具版本和受限命令结果 | commit 是平台版本或 push 已完成 |
| Review/Governance ref | handoff、Gate、decision 的外部标识与查询状态 | ACK 是 accepted，Sync 可批准 |
| Archive posture ref | archived/dissolved/retired/active 等查询结果 | Sync 可恢复/归档或继续被禁止操作 |

## 5. 状态机方向（候选）

```text
unbound -> selecting -> access-verified -> source-bound
                                      |
                                      +--> denied / archived / blocked

source-bound -> inspecting -> ready-to-materialize -> applying -> applied
                    |                 |                  |
                    v                 v                  v
                 dirty             conflict              partial/unknown
                    +-----------------+------------------+
                                      v
                                  needs-action

applied -> review-prepared -> handoff-submitted -> probe-required -> external-pending
                                                               |                 |
                                                               v                 v
                                                         retry-safe          decision-ref-known
```

这不是正式状态枚举或可执行流程图。必须在后续设计中分离：

- source binding/access 状态；
- 本地 materialization 状态；
- Git/filesystem dirty/conflict 状态；
- cursor/mapping/recovery 状态；
- handoff transport 状态；
- 外部 Review decision 只读状态。

任何状态转换都要说明触发条件、证据、幂等性、回滚/恢复和禁止的隐式副作用。

## 6. 关键 port / adapter seam（候选）

| seam | 方向 | 允许语义 | 必须防止 |
|---|---|---|---|
| `PrincipalAccessPort` | 出站 | 验证 principal、project/member 权限和姿态 | 本地默认 allow、绕过身份/工作 owner |
| `SourceResolverPort` | 出站 | 解析 Artifact/Workspace source、版本、cursor、materialization 输入 | 自行拼接正文、复制 owner 表 |
| `GitAdapter` | 本地 | 观察、受限 object/path 操作、工具能力检测 | merge/rebase/push、remote truth 越界 |
| `FilesystemAdapter` | 本地 | 路径安全、锁、原子读写、指纹和未提交修改保护 | 覆盖用户变更、跟随危险 symlink、删除 provenance |
| `MetadataStore` | 本地 | 保存/读取/迁移/校验 `.qs-sync` metadata | credential 泄漏、静默重绑定、不可追溯改写 |
| `HandoffPort` | 出站 | 准备/上传/提交 review candidate、查询 handoff/probe | ACK-as-accept、自动批准或 push |
| `ArchivePosturePort` | 出站 | 读取 archived/dissolved/retired posture 与允许操作提示 | 伪造 active、执行 archive mutation |
| `RecoveryProbePort` | 出站 | 查询 unknown outcome 的外部副作用状态 | 盲目重放或把 timeout 当失败/成功 |
| `DiagnosticsPort` | 双向 | correlation、审计和安全错误材料 | 用 trace/log 伪造业务 verdict |

端口名称只是草稿类别；正式协议须由当前上游 SDK、治理、Artifact、Workspace、Archive 和 observability 文档共同校准。

## 7. 模块间不变量与依赖方向

1. `status`/query 只能读取已持久化的 local truth 和外部只读状态；不能隐式推进 cursor、写 metadata 或修复冲突。
2. materialization 必须先经过 selection/access、source binding、path/dirty/metadata 检查；任何检查未知均停在 blocked/needs-action。
3. Git adapter 与 filesystem adapter 只能执行明示白名单操作；merge/rebase/push 永不成为默认或隐式步骤。
4. local cursor、Git HEAD、working-tree state、handoff transport 和 Review decision 分开持久化与报告。
5. 任何外部副作用调用采用 `prepare → call → probe/finalize` 恢复纪律；幂等键和 probe 结果不能冒充 Review verdict。
6. provenance 与冲突证据的删除/迁移必须可解释；不得因重试、清理或用户取消而静默抹除来源链。
7. 归档/撤销/权限变化优先于本地缓存；无法重新验证时 fail-closed。
8. 模拟 SDK/Git/filesystem 只证明本地模块行为，不证明真实上游、remote、Artifact、Gate 或 archive 已集成。

## 8. 后续正式设计的落码粒度提示

从正式 Step 5 起，需要逐项收敛但本 draft 不提前决定：CLI 命令与参数、应用服务/模块名、对象字段与 metadata schema、SDK/Git/filesystem adapter 接口、状态转换、冲突分类与恢复流程、配置键、测试切口、证据边界和每个外部结果的来源等级。正式 `07` 还必须创建 implementation ledger 与 planned boundary skeleton；本 draft 不创建、不伪造这些产物。

## 9. 上游 pending / blocker 候选

| 候选 | 影响模块 | 未闭合时的限制 |
|---|---|---|
| `SYNC-MOD-UP-001` | source resolver / access gateway | 不锁 source 优先级、版本 comparator 或 SDK method。 |
| `SYNC-MOD-UP-002` | metadata manager / local truth core | 不锁 `.qs-sync` schema、迁移、完整性或保留。 |
| `SYNC-MOD-UP-003` | pull/materialization / cursor | 不承诺增量、replay、gap 或原子提交语义。 |
| `SYNC-MOD-UP-004` | Git/filesystem adapters | 不承诺 LFS、浅克隆、GUI 或具体工具版本。 |
| `SYNC-MOD-UP-005` | conflict/recovery | 不自动解决、不盲重试 unknown outcome。 |
| `SYNC-MOD-UP-006` | handoff | 不锁 upload/ACK/probe/Review decision 协议。 |
| `SYNC-MOD-UP-007` | archive/diagnostics | 不把姿态缓存或日志当 owner truth。 |

## 10. 本篇结论

候选模块已围绕 Sync-local truth、显式访问、来源解析、working copy/metadata、Git/filesystem、增量 materialization、冲突保护、Review handoff 和恢复诊断形成分层。它们是进入正式校准时的讨论起点，不是代码结构、实现承诺或集成证明；所有未闭合上游边界继续保持 pending/blocked。

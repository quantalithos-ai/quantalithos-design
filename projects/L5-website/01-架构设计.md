## 1. 业务背景与驱动力

### 1.1 业务背景

Website 是 Quantalithos 向外界表达自己的唯一静态门面。它承担的不是业务执行,而是**定位、说服、解释、导航与公开文档分发**。在这个层面,Website 必须帮助外部访客快速建立三个判断：这是什么产品、它和现有 AI 编程工具有什么不同、我下一步该去哪里。如果 Chat 是“用户开始使用产品”的入口,那 Website 是“用户决定是否愿意开始”的入口。

### 1.2 业务驱动力

**业务驱动力**:
- 外部访客需要在不登录、不看代码、不理解后端结构的前提下快速理解产品定位
- 营销、文档、FAQ、Release Notes 需要一个可公开访问、可版本对应、可搜索引擎收录的站点
- 平台需要一个把“10 产品生态”讲清楚的统一对外表达空间

**技术驱动力**:
- 必须完全独立部署,不耦合 Server 的运行时 API
- 必须能从 design 仓与 SDK 文档中同步可公开内容,同时守住公开/私有边界
- 必须以静态站点方式达成性能、SEO、无障碍和合规目标

### 1.3 成功标准(可量化)

| 维度 | 指标 | 目标值 | 测量 |
|---|---|---|---|
| 可用性 | 静态站点可用率 | ≥ 99.9% | 监控 |
| 内容 | 10 产品页完整 | 10/10 | 内容检查 |
| 一致性 | 文档版本对应率 | 100% | 内容检查 |
| 无障碍 | WCAG 2.2 AA 关键路径 | 100% | accessibility audit |
| 合规 | Cookie/追踪同意覆盖 | 100% | 合规检查 |
| 导流 | 登录/注册入口可用 | 100% | E2E |

## 3. 架构风格与选型

### 3.1 变化维度识别

| 维度 | 变化频率 | 应对策略 |
|---|---|---|
| 产品介绍内容 | 中高 | content-driven pages |
| 公开文档同步 | 中高 | build-time sync pipeline |
| SEO/内容增长 | 高 | static-first information architecture |
| 多语言与搜索策略 | 中 | 可插拔内容/索引层 |
| 认证导流目标 | 中 | outbound auth links abstraction |

### 3.2 架构风格决策框架

**候选架构风格**:

| 风格 | 优势 | 劣势 | 适用性 |
|---|---|---|---|
| **静态站点 + 构建期内容同步**(当前) | 性能好、SEO 友好、独立部署清晰 | 动态扩展需额外设计 | ✅ |
| 运行时 CMS / 动态站点 | 编辑方便 | 与独立部署和最小复杂度冲突 | ❌ |
| 直接把文档嵌入应用产品 | 减少一个站点 | 品牌/文档/应用边界混乱 | ❌ |
| 全手写静态内容,不同步源文档 | 起步快 | 极易内容漂移 | ❌ |

**最终选择**:**静态站点生成 + 构建期内容同步 + 明确的公开边界**

### 3.3 架构风格约束-收益分析

| 约束 | 收益 | 成本 |
|---|---|---|
| 完全独立部署 | 安全边界清晰、部署简单 | 无法复用应用内动态能力 |
| 构建期同步内容 | 保持文档与 design/SDK 对齐 | 需要设计同步白名单与版本逻辑 |
| 公共内容模板固定 | 对外表达一致 | 内容自由度略受限 |

## 4. 系统边界与上下文

### 4.1 系统上下文图(C4 Context 级)

```text
外部访客 / 搜索引擎 / 现有用户
              │
              ▼
        ★ quantalithos-website ★
        - home / products / docs / blog
        - versioned public content
        - auth redirection
           │            │
           │            └────────▶ auth entrypoints (external)
           └─────────────────────▶ build-time content sources(design/sdk)
```

### 4.2 职责边界(做什么 / 不做什么)

**做什么**:
- ✅ 公开呈现产品定位、10 产品结构、FAQ、博客、版本化文档
- ✅ 提供从公开站点到注册/登录/应用入口的清晰导流
- ✅ 同步公开文档与 SDK API 文档摘要
- ✅ 承担 SEO、Accessibility 和内容治理要求

**不做什么**:
- ❌ 不承载登录后的动态产品功能
- ❌ 不作为 Chat/Console 的替代入口
- ❌ 不直接查询或修改 Server 运行时业务数据
- ❌ 不承担 Playground 或复杂交互式 Demo(首期)

### 4.3 外部系统可用性约束

| 外部依赖 | SLA | 依赖风险 | 降级策略 |
|---|---|---|---|
| design 仓公开文档 | 构建期可用 | 内容同步失败 | 保留旧版本内容 |
| SDK 文档源 | 构建期可用 | API docs 不可更新 | 保留旧版本 docs |
| 认证入口 URL | 高 | 跳转失效 | fallback URL / 提示页 |
| CDN / 静态托管 | ≥ 99.9% | 公开站点不可达 | 回退备用托管 |

### 4.4 关键依赖风险

- 构建期同步如果无严格白名单,极易把内部文档误公开
- 版本标识如果只是文案而非构建元数据,公开文档会快速漂移
- 若站点被扩展为半动态应用,Website 与产品入口边界会迅速模糊

## 5. 限界上下文与子域划分

### 5.1 子域分类

| 子域 | 分类 | 说明 |
|---|---|---|
| Brand Narrative | 核心域 | 首页、定位、产品价值表达 |
| Product Catalog | 核心域 | 10 产品页与“刻意不做”边界说明 |
| Public Documentation | 核心域 | docs / FAQ / migration / API 导航 |
| Release Communication | 支撑子域 | 博客 / release notes |
| Traffic & Consent | 支撑子域 | SEO、导流、cookie/tracking 同意 |

### 5.2 限界上下文划分与职责

| 上下文 | 职责 | 核心对象 |
|---|---|---|
| Home | 首页叙事与 CTA | HomeContent |
| Products | 10 产品页信息结构 | ProductPage |
| Docs | 公开文档与 API 入口 | PublicDoc |
| Blog | 发布说明与文章 | BlogEntry |
| Consent | Cookie/追踪与合规提示 | ConsentState |
| Redirect | 登录/注册导流 | RedirectTarget |

### 5.3 上下文映射关系

- design/sdk docs → Docs: **Customer-Supplier**，Website 消费公开内容源
- Products ↔ Home: **Shared narrative model**,首页摘要链接到产品页
- Redirect → Chat/Console/Auth entrypoints: **Open Host Service**,只负责跳转不持业务状态
- Blog ↔ Docs: **Loose coupling**,release notes 可反向引用文档更新

### 5.4 统一语言词汇表

| 术语 | 定义 | 使用场景 |
|---|---|---|
| PublicDoc | 对外公开的文档页面 | Docs |
| ProductPage | 单个产品的公开介绍页 | Products |
| ConsentState | 访客是否同意 Cookie/追踪的状态 | Consent |
| RedirectTarget | 登录/注册/应用导流目标 | Redirect |
| VersionLabel | 显示在公开内容上的产品版本标识 | Docs / Blog |

## 6. 容器/部署架构

### 6.1 容器图(C4 Container 级)

```text
static site generator build
   ├─ content sync from design/sdk
   ├─ page generation
   └─ sitemap/feed/assets
              │
              ▼
        CDN / static hosting
              │
              ▼
      visitors / search engines
```

### 6.2 每个容器的职责与技术栈

| 容器 / 进程 | 职责 | 技术栈 | 资源要求 |
|---|---|---|---|
| site generator | 构建静态页面与内容索引 | Astro / Next.js SSG | 构建期资源 |
| content sync step | 从 design/sdk 拉取公开内容 | TypeScript/Node script | 构建期 |
| static host / CDN | 托管页面、资源与文档 | Cloudflare / CloudFront | 公开可用性 |
| consent layer | 管理 cookie/追踪同意 | lightweight client-side layer | 运行时轻逻辑 |

### 6.3 通信方式与选择理由

| 场景 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 内容同步 | 构建期脚本拉取 | 运行时 API | 保持独立部署与缓存友好 |
| 登录/注册导流 | 外链跳转 | 站内实现 auth | 不把 Website 做成应用 |
| 文档渲染 | 静态生成 | 运行时 CMS | 性能、SEO 与独立性更优 |

### 6.4 数据存储归属

| 数据 | 写入方 | 读取方 |
|---|---|---|
| 公开站点内容 | Website content source / maintainers | 外部访客 |
| 版本标识 | 构建流水线 | 外部访客 |
| consent 状态 | visitor browser | consent layer |
| docs/blog 索引 | Website build | search / visitors |

### 6.5 部署拓扑

- Website 以静态站点单独部署
- docs 可作为二级域名或同站子路径,但仍共用静态发布链
- 构建产物只依赖公开内容源,运行时不依赖 Server

## 7. 依赖方向与层间约束

### 7.1 依赖方向图

```text
content sources
     │
     ▼
build pipeline
     │
     ├─▶ site generation
     ├─▶ version labeling
     ├─▶ consent assets
     └─▶ deploy to static host
```

### 7.2 层间约束规则

- 公开内容同步必须通过白名单控制,不能任意抓 design 仓内容
- 页面层不依赖任何登录后业务 API
- 版本标识必须来自构建元数据,不能靠手写常量维持
- auth 导流只做跳转,不在站内持有登录状态
- Blog/Docs/Products 的内容更新不应破坏首页叙事骨架

### 7.3 依赖倒置的接口点

| 接口 | 定义位置 | 实现位置 |
|---|---|---|
| PublicContentSource | build domain | design/sdk sync adapters |
| VersionProvider | build domain | CI/release metadata adapter |
| RedirectProvider | page/domain | deployment/auth config |
| ConsentProvider | runtime light layer | client-side adapter |

### 7.4 依赖健康度评估

| 指标 | 当前预期 |
|---|---|
| 传入耦合 | 低(主要是公开内容源) |
| 传出耦合 | 低(CDN / auth links / search engines) |
| 不稳定性 | 低 |
| 抽象度 | 中(build/content/deploy 分层明确) |

## 8. 数据所有权与一致性策略

### 8.1 数据所有权矩阵

| 数据 | 拥有者 | 消费者 | 一致性策略 | 风险 |
|---|---|---|---|---|
| 品牌与产品页面内容 | Website content maintainers | 外部访客 | 构建内强一致 | 人工内容漂移 |
| 公开文档内容 | design/sdk 公开源 + Website 同步 | 外部访客 | 构建期最终一致 | 版本错配 |
| 版本标识 | release/build pipeline | 外部访客 | 构建内强一致 | 手写错误 |
| consent 状态 | visitor browser | Website client layer | 本地强一致 | 合规失败 |

### 8.2 一致性层次

- 页面与版本标识在单次构建内强一致
- design/sdk 源文档到公开文档是构建期最终一致
- 访客 cookie/consent 状态只在本地会话内强一致

### 8.3 补偿机制设计

| 场景 | 触发 | 补偿动作 | 幂等保证 |
|---|---|---|---|
| docs sync 失败 | 构建期内容源不可用 | 保留旧文档版本并提示 | `build_id + source_ref` |
| 版本标识缺失 | release metadata 不可用 | 阻断发布 | `build_id` |
| consent 逻辑异常 | 浏览器端错误 | 默认禁用追踪脚本 | `visitor_session` |

## 10. 备选方案与取舍

### 10.1 候选方案对比

| 维度 | 方案 A:静态站点 + 构建期同步(当前) | 方案 B:动态 CMS 站点 | 方案 C:把官网并入应用 |
|---|---|---|---|
| 独立性 | 高 | 中 | 低 |
| SEO/性能 | 高 | 中 | 中 |
| 内容一致性 | 高 | 中 | 低 |
| 实施复杂度 | 中 | 中高 | 中 |
| 边界清晰度 | 高 | 中 | 低 |

### 10.2 最终选择与理由

选择 A,因为 Website 的价值在于**清晰、快速、独立、可索引、可控**。B 会引入不必要的动态复杂度；C 会把公开站点与登录后应用边界混淆。A 更符合 Website 的角色定位。

## 11. 横切关注点

### 11.1 韧性

| 能力 | 策略 |
|---|---|
| 降级 | 内容同步失败时保留上次成功构建 |
| 隔离 | docs/blog/products/home 构建模块隔离 |
| 回退 | 站点发布可快速回滚到上一版静态构建 |

### 11.2 可观测性

| 维度 | 落地 |
|---|---|
| 日志 | 构建同步、发布、导流异常 |
| 指标 | 构建成功率、页面可达性、SEO 索引状态 |

| 健康检查 | 关注关键页面、文档页、sitemap、auth redirect |

### 11.3 安全

| 维度 | 落地 |
|---|---|
| 公开内容边界 | 构建同步白名单 |
| 合规追踪 | consent 先于 tracking |
| 外链安全 | 跳转与外部链接经过显式配置 |
| 独立部署 | 不混入需要登录的动态功能 |

### 11.4 配置管理

| 维度 | 落地 |
|---|---|
| 外部化 | 域名、认证入口、同步源、SEO 配置外部化 |
| 环境隔离 | staging/prod 使用不同域名与索引策略 |
| 动态更新 | 内容通过构建链更新,不在运行时改写 |
| 配置五要素 | type / default / source / scope / constraints 明确 |

### 11.5 性能预算表

| 环节 | 预算 | 测量方式 | 来源依据 |
|---|---|---|---|
| 首页可读性 | 首屏快速可读 | Lighthouse / Web Vitals | 品牌主入口 |
| docs 访问 | 公开文档快速可达 | Lighthouse / synthetic checks | 文档站主路径 |
| 版本对应性 | 100% | 内容检查 | 文档控制硬要求 |
| CTA 跳转 | 100% 可用 | E2E | 导流主路径 |

## 12. 演进路线

### 12.1 当前架构状态与已知债务

| 债务项 | 影响 | 优先级 |
|---|---|---|
| 多语言策略未定 | 影响全球化内容维护 | P1 |
| Playground 是否预留未定 | 影响未来开发者体验入口 | P1 |
| API docs 同步粒度未定 | 影响文档维护成本 | P1 |
| 搜索策略未定 | 影响大规模文档检索体验 | P2 |

### 12.2 触发条件(可量化)

| 指标 | 阈值 | 动作 |
|---|---|---|
| 公开文档增长过快 | > 阈值 | 增强搜索/信息架构 |
| 版本错配问题出现 | > 0 | 强化构建时版本校验 |
| 多语言需求明确 | 产品决策触发 | 设计 i18n 内容流水线 |
| Playground 需求持续升高 | > 2 个 Sprint | 单独设计在线试用能力 |

### 12.3 演进步骤

```text
阶段 1: 首页 / 产品页 / docs / auth 导流主路径跑通
   └─ 可停止点:外部访客能理解与进入产品

阶段 2: 博客 / 版本化文档 / 搜索增强
   └─ 可停止点:内容站稳定成长

阶段 3: 多语言 / Playground / 高级 SEO 与内容体系
   └─ 可停止点:Website 成熟为品牌与文档中枢
```

### 12.4 目标架构

Website 的目标架构不是“简单官网”,而是 **Quantalithos 的公开叙事与知识入口**:对外表达产品、对内约束公开内容边界、对文档负责版本对应。未来再扩展,也必须围绕“公开、独立、可控、清晰”四条主线,而不能滑向半应用或半 CMS 的混合体。

## 14. 上线策略

### 14.1 灰度方案

```text
阶段 1: 首页 / 产品页 / docs 主路径上线
阶段 2: 博客 / release notes / 导流细节完善
阶段 3: 搜索与版本化增强
阶段 4: 多语言/Playground 等后续扩展
```

### 14.2 回滚策略

| 触发条件 | 等级 | 回滚步骤 |
|---|---|---|
| 首页/产品页重大内容错误 | S 级 | 回滚静态构建版本 |
| docs 同步错误公开内容 | S 级 | 下线对应文档并回滚同步脚本 |
| 认证导流失效 | A 级 | 临时替换为 fallback 链接与公告 |
| 追踪同意异常 | A 级 | 关闭追踪脚本 |

### 14.3 监控指标

| 指标 | 阈值 | 告警方式 |
|---|---|---|
| 关键页面可访问性 | < 99.9% | major |
| 文档版本错配 | > 0 | warning |
| 导流跳转失败 | > 阈值 | warning |
| sitemap / 索引异常 | > 阈值 | growth/seo |

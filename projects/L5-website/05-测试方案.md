### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、协议、异常流、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 website“能打开页面”,而是系统验证 `L5-website` 是否真正满足“平台外部门户 / 品牌与公开入口产品层”的设计要求,尤其要证明以下几点成立:
- WebsitePage / PublicCapabilitySummary / MethodOverview / CTAEntry / MarketplaceTeaser / PublicDocsNavigation / FeedbackEntry / ConversionEvent 构成正式 website 门户层真相
- `WebsitePage ≠ source truth`、`public capability summary ≠ capability contract truth`、`method overview ≠ method-library truth`、`website entry ≠ console workspace` 等核心边界成立
- brand / summary / CTA / resources / growth 五条公开门户主线可以统一组织,并且 source refs 持续可追溯
- CTA 只做导流与转化入口,不误导用户认为已完成注册、登录或正式进入产品
- teaser/docs/resources 只做公开摘要与导览,不反写 marketplace、docs 或 release truth
- feedback / conversion / campaign 只表达站点运营信号,且 `marketing metrics ≠ product truth`

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 门户入口与品牌表达部分 | landing/brand 对象 | P0 | WebsitePage、HeroBlock、BrandSurface、public nav |
| 产品能力与方法概览展示部分 | public summary 对象 | P0 | PublicCapabilitySummary、MethodOverview、UseCaseCard、ReleaseHighlightCard |
| 转化入口与产品导流部分 | CTA / funnel 对象 | P0 | CTAEntry、trial/login/demo/get-started 入口、ConversionEvent |
| 生态、案例与公开资源部分 | teaser/resource 对象 | P0 | MarketplaceTeaser、PublicDocsNavigation、FAQ / blog / release / resource cards |
| 反馈、增长分析与站点运营部分 | growth/ops 对象 | P0 | FeedbackEntry、CampaignSurface、AnnouncementBanner、funnel summaries |
| console / chat / marketplace / method-library / capability-hub / docs source truth 本体 | 非范围 | P2 | 只验 website 如何消费公开摘要和导流入口,不验这些 source truth 全部实现 |
| account/member 真相、auth 系统本体 | 非范围 | P2 | 只验 CTA 导流入口,不验底层账号系统实现 |
| analytics / BI / 广告投放平台本体 | 非范围 | P2 | 只验网站运营信号输出,不验底层分析系统实现 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / product owner | `input.validate_public_summary_boundary`、`cta.validate_entry_boundary`、`event.validate_growth_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + projection + CTA routing + analytics emitters 联动 | backend / product owner | `BuildWebsitePage`、`BuildPublicCapabilitySummary`、`ResolveCTAEntry`、`TriggerCTA`、`BuildMarketplaceTeaser`、`BuildDocsNavigation`、`SaveFeedbackEntry`、`RecordConversionEvent` | brand、summary、CTA、resources、growth 五条主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | capability/method refs → public summaries、CTA → console/chat/marketplace/auth entries、feedback → analytics/growth | 输入输出语义一致 |
| 恢复专项测试 | 验证 source refs 缺失、CTA 不可达、teaser 过期、docs stale、feedback 缺上下文等异常链 | architecture / QA | stale refs、invalid CTA、resource fallback、feedback context missing | 门户不误导、错误被正确阻断或降级 |
| 投影一致性测试 | 验证 landing/summary/teaser/docs/funnel 视图与 source refs 一致 | backend / QA | landing rebuild、summary rebuild、teaser rebuild、docs nav rebuild、funnel rebuild | 投影只读且与 source refs 一致 |
| 端到端主线测试 | 验证最小对外门户闭环 | QA / owner | open landing → read summaries → click CTA → browse resources → emit feedback/conversion | 网站闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `WebsitePage ≠ source truth` | 公共页面只组织公开摘要和入口,不反写真相 | 单元 + 集成测试 | 是 | page/source compare |
| `public capability summary ≠ capability contract truth` | 能力概览只表达公开摘要,不替代 contract 真相 | 单元 + 集成测试 | 是 | capability summary compare |
| `method overview ≠ method-library truth` | 方法概览只做认知层摘要,不替代权威定义 | 单元 + 事件链测试 | 是 | method summary compare |
| `website entry ≠ console workspace` | CTA 只表达导流入口,不等于已进入内部工作台 | 单元 + 集成测试 | 是 | CTA/entry compare |
| `marketplace teaser/listing summary ≠ marketplace transaction truth` | teaser 只做生态摘要与导览 | 单元 + 集成测试 | 是 | teaser/source compare |
| `marketing metrics ≠ product truth` | 转化、点击、campaign 只表达增长视角 | 单元 + 集成测试 | 是 | analytics/product compare |
| CTA 目标必须可达且合法 | 试用/登录/demo/get-started 入口校验 | 集成 + 恢复专项测试 | 是 | CTA routing logs |
| public resources / docs nav 可回指 | docs/FAQ/release/resource 入口可回指 source refs | 集成 + 投影一致性测试 | 是 | refs compare |
| feedback / conversion 可追溯 | feedback 与 CTA 事件可绑定 page/CTA context | 集成 + 事件链测试 | 是 | feedback/conversion histories |

## 10. 缺陷管理与异常升级

| 严重级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | public page 反写真相 / CTA 越权导流 / teaser 冒充 marketplace 真相 / docs nav 冒充 docs source truth / metrics 冒充 product truth |
| A | 视情况 | 主线可跑但 stale/fallback、CTA 可达性、summary/source 对账或 funnel 事件不稳 |
| B | 可带着走 | 非关键展示、低优先级文案或 teaser 细节异常 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 landing / nav / brand,都必须回归门户入口与 source refs 主线
- 每次改动 capability/method overview,都必须回归公开概览与 source truth 边界主线
- 每次改动 CTA / login / trial / demo / get-started,都必须回归导流入口与 conversion 主线
- 每次改动 teaser/docs/resources,都必须回归公开资源导览与 fallback 主线
- 每次改动 feedback / campaign / funnel,都必须回归增长信号与 product truth 分离主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 多 campaign / 多入口 / 多文案变体后续细化 | 验收矩阵需扩充 | TL / 架构 |
| marketplace/docs 公开面继续演进 | teaser/nav 验收需增加更多样本 | website / marketplace / docs |
| 增长/分析需求增长 | funnel / feedback 验收需扩充 | product / analytics |

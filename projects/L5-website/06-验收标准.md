### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L5-website` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L5-website` 是平台外部门户 / 品牌与公开入口产品层,不是 console 工作台仓、chat 交互仓或业务真相仓
- WebsitePage / PublicCapabilitySummary / MethodOverview / CTAEntry / MarketplaceTeaser / PublicDocsNavigation / FeedbackEntry / ConversionEvent 构成正式 website 门户层真相
- `WebsitePage ≠ source truth`、`public capability summary ≠ capability contract truth`、`method overview ≠ method-library truth`、`website entry ≠ console workspace` 等核心边界必须成立
- brand / summary / CTA / resources / growth 五条公开门户主线必须能统一组织,且 source refs 持续可追溯
- CTA 只做导流与转化入口,不得误导用户认为已完成注册、登录或正式进入产品
- teaser/docs/resources 只做公开摘要与导览,不得反写 marketplace、docs 或 release truth
- feedback / conversion / campaign 只表达站点运营信号,且 `marketing metrics ≠ product truth`

因此,本次验收的目的不是笼统判断“能不能做个官网”,而是判断 website 的 brand 主线、public summary 主线、CTA/funnel 主线、resource/teaser 主线与 growth/feedback 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 门户入口与品牌表达部分 | 是 | WebsitePage、HeroBlock、BrandSurface、public nav |
| 产品能力与方法概览展示部分 | 是 | PublicCapabilitySummary、MethodOverview、UseCaseCard、ReleaseHighlightCard |
| 转化入口与产品导流部分 | 是 | CTAEntry、trial/login/demo/get-started 入口、ConversionEvent |
| 生态、案例与公开资源部分 | 是 | MarketplaceTeaser、PublicDocsNavigation、FAQ / blog / release / resource cards |
| 反馈、增长分析与站点运营部分 | 是 | FeedbackEntry、CampaignSurface、AnnouncementBanner、funnel summaries |
| console / chat / marketplace / method-library / capability-hub / docs source truth 本体 | 否 | 只验 website 如何消费公开摘要和导流入口,不验这些 source truth 全部实现 |
| account/member 真相、auth 系统本体 | 否 | 只验 CTA 导流入口,不验底层账号系统实现 |
| analytics / BI / 广告投放平台本体 | 否 | 只验网站运营信号输出,不验底层分析系统实现 |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | public page 反写真相 / CTA 越权导流 / teaser 冒充 marketplace 真相 / docs nav 冒充 docs source truth / metrics 冒充 product truth |
| A | 视情况 | 主线可跑但 stale/fallback、CTA 可达性、summary/source 对账或 funnel 事件不稳 |
| B | 可带着走 | 非关键展示、低优先级文案或 teaser 细节异常 |

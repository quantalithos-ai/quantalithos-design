## 2. 本仓定位与边界

> 校准来源：
> - `design-calibration/00_req_step_02_position_boundary.md`
>
> 延伸阅读：
> - 阅读该中间产物§7/§8的仓级边界，以及§9的来源协议、actor与安全读取限制。

| 字段 | 结论 |
|---|---|
| 一句话定义 | `L6-bridges` 是Slack、Mattermost、Telegram、Discord的外部协作协议适配与桥接局部状态层。 |
| 本仓不是什么 | 它不是内部业务真相仓、外部平台真相仓、统一认证授权中心、聊天UI或跨平台广播中心。 |
| 边界对象列表 | 仓：L1-conversation、L1-identity、L1-governance、L1-artifact、L1-workspace、L0-sdk、L4-observability、L5-chat；系统：四个外部平台；概念：接收确认、内部提交、外部效果。 |
| 单独成仓原因 | 外部协议差异、授权映射与投递不确定性需要独立收束，不能反向定义内部领域事实。 |

本仓隔离平台协议变化与桥接局部状态。Conversation的对话事实、Identity的AI成员身份、Governance的裁决和Workspace的只读投影分别有正式owner；平台消息与桥接记录不能形成内部或外部的第二真相源。

## 3. 背景与问题定义

> 校准来源：
> - `design-calibration/00_req_step_03_problem_context.md`
>
> 延伸阅读：
> - 阅读该中间产物§7.1~7.3和§8，了解背景、问题与非量化口径的范围。

团队、个人与社区已在Slack、Mattermost、Telegram、Discord中协作。产品矩阵将Bridges列为既有渠道的触达延伸，需要明确外部交互与内部协作的需求关系。当前输入为设计材料，不是生产账号、投递或审批运行事实。

| 问题 | 当前表现 | 影响范围 / 后果 |
|---|---|---|
| 入口与责任割裂 | 既有渠道协作中的外部主体与内部责任关系尚需逐项闭合 | 外部操作可能无法解释内部责任或授权 |
| 平台语义不可等同 | 平台位置/消息与内部Conversation/Turn、接收确认与业务结果不能直接对应 | 映射、编辑删除及回调可能误报业务结果 |
| 恢复与安全缺口 | 平台接入、secret、gap和未知效果的运行依据未建立 | 失败恢复可能造成重复效果、泄露或虚假就绪判断 |

现阶段无量化基线；这些是需求收束问题，不宣称线上事故已发生。

| 类型 | 内容 |
|---|---|
| 业务问题 | 既有渠道可达性、主体责任可解释性、治理与审计一致性 |
| 技术问题 | 平台对象差异、授权引用与来源版本缺口、确认/提交/送达分离、未知结果及secret安全边界 |

## 4. 目标与非目标

> 校准来源：
> - `design-calibration/00_req_step_04_goals_non_goals.md`
>
> 延伸阅读：
> - 阅读该中间产物§7.1/§7.2和§8，核对目标判断条件、非目标及实际验证资格。

### 4.1 目标

| 目标 | 说明 | 验证方式 |
|---|---|---|
| G-BR-001 真相边界成立 | 仅保有桥接局部状态，不形成内部或平台第二真相 | 归属与只读/写入反例审计 |
| G-BR-002 显式授权成立 | 主体、目标、内容和操作有可验证授权，未知不放行 | 绑定、撤销、跨租户及回调反例 |
| G-BR-003 双向语义可解释 | inbound/outbound保留来源与阶段结果，接收确认、内部提交和外部效果分开 | 协议与状态追溯、重复/未知结果切口 |
| G-BR-004 四平台差异明确 | 各平台有独立支持/降级/不支持范围，不承诺语义等价 | 官方来源版本核验、能力矩阵及adapter合同切口 |
| G-BR-005 恢复与安全交接成立 | 失败可解释、受控恢复可追溯，消息体/secret/敏感审批不进入观测证据 | 故障/重放反例、安全材料白名单审计 |

验证方式是必须满足的判断要求，不表示测试已执行或目标已达成。

### 4.2 非目标

| 非目标 | 不做原因 |
|---|---|
| 内部Conversation/Turn、Identity、Gate/Decision、Artifact、Workspace truth | 各owner负责，本仓只转换与引用 |
| 外部账号/频道/消息平台truth或全量备份 | 平台负责，mapping不等于平台实体 |
| external ID自动创建GlobalMember或授予参与/审批权限 | 外部账号不等内部AI身份或授权主体 |
| 默认低敏感审批、敏感Gate完整外显 | 外显与操作分别由正式责任链决定 |
| 完整Chat/Console或跨平台广播 | 并行产品不提供未停审正式输入，各平台独立绑定 |
| 用ACK/HTTP成功代替内部提交、投递或执行完成 | 不同系统阶段不可相互证明 |
| 当前需求交付中的代码实施、真实账号/凭证配置、SDK/OAuth/KMS/路由定案及真实测试验收 | 需求定义不建立实现或运行事实，未核验选型与证据不能成为既成输入 |

## 5. 用户与角色

> 校准来源：

| 角色 | 类型 | 使用场景 |
|---|---|---|
| 外部协作参与者 | 人类 | 在获准频道、群组或私聊中协作，并查看被允许接收的反馈 |
| 绑定管理者 | 人类 | 组织接入、范围调整、暂停、撤销与secret引用维护 |
| 获授权审批者 | 人类 | 接收允许外显的提示，仅在外部操作资格成立时参与治理交互 |
| 恢复维护者 | 人类 | 处理gap、未知效果、限流与失效绑定，只修桥接局部状态 |
| 审计者 | 人类 | 读取授权范围内body-free来源、操作及交接记录 |
| AI员工结果来源 | 系统角色 | 提供已提交且允许外显的结果，不替代人类审批责任 |
| 协议接入与交付调用方 | 系统角色 | 接入受权平台事件或交付受权来源，保留独立阶段状态 |

| 能力级操作 | 参与者 | 绑定管理者 | 审批者 | 恢复维护者 | 审计者 | 系统角色 |
|---|---|---|---|---|---|---|
| 参与/读取协作 | 按参与与visibility依据 | 无默认权 | 按参与与visibility依据 | 无默认权 | 无正文默认权 | 按正式来源与消费资格 |
| 维护绑定/secret引用 | 否 | 按管理授权 | 否 | 仅获委托的局部维护 | 否 | 仅显式委托，不持raw secret |
| 外部治理动作 | 无默认权 | 无默认权 | 按当前owner的actor/action/basis | 否 | 否 | 不冒充人类审批主体 |
| 局部回放/对账 | 否 | 无默认权 | 否 | 按恢复授权，未知效果不盲发 | 否 | 仅符合已验证恢复合同 |
| 安全审计读取 | 无默认权 | 无默认权 | 无默认权 | 按维护读取范围 | 按审计范围 | 仅安全handoff |

矩阵表达职责差异，不定义权限系统。平台签名、安装scope、角色称谓或external ID均不自动授予资格；human actor责任链缺失时fail-closed，GlobalMember只按Identity正式AI身份语义使用。Conversation的Integration actor表示可信来源，不替代human责任。

| 方向 | 对方 | 提供 / 依赖内容 | 是否闭环前置 | 失效影响 |

### 9.4 协议阶段语义

| 方向 | 阶段 / 结果 | 禁止等同 |
|---|---|---|
| binding | configured -> waiting/blocked或active -> suspended/revoked | active不证明平台可用或业务已提交 |
| inbound | received -> verified/authorized -> owner_handoff -> accepted/rejected/pending/indeterminate | ACK不等owner accepted，accepted fact不自动等Turn |
| outbound | prepared -> dispatching -> platform_accepted/known_rejected/retry_wait/indeterminate，缺前置blocked | 内部commit不等receipt，platform_accepted不等已读 |
| callback | verified -> owner_handoff或invalid/expired/replayed/blocked -> owner独立结果 | HTTP/deferred response不等Decision |
| recovery | gap/unknown -> 权威reconcile或blocked/missing_source/indeterminate | timeout、lease失效或重启不证明未产生效果 |

这些是需求语义，不是最终enum/schema。后续02/03必须保留状态主语与转移guard，04闭合可验证配置/secret引用，不由实现端猜新成功状态或默认retry。

| 数据项 | 数据类型 | 归属说明 | 生命周期口径 |
|---|---|---|---|
| DR-BR-014 source/processing/delivery cursor及gap | 真相数据 | 本仓处理位置/缺口，不拥有平台/Bus完整性truth | 仅可比namespace/epoch受控推进或证明覆盖，不越gap complete |
| DR-BR-015 去重结果及稳定effect关系 | 真相数据 | 获准operation的去重/局部effect关联 | 同义复用、冲突隔离，超过获准覆盖范围不自动重放 |

### 11.6 ref失效及安全读取

ref须有owner、scope、版本与读取资格；字符串存在不等可解析。missing/revoked/expired/stale/incomparable分别表达，不以空body、默认摘要、cache或猜测target掩盖。局部失效标记的维护是显式操作，普通query只读既有状态，不向owner写入或暗中恢复。附件/回调私有URL仅private seam使用，durable mapping保非secret locator/ref。

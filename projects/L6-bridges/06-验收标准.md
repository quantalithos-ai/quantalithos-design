### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L6-bridges` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L6-bridges` 是平台对外桥接层 / protocol-adapter product layer,不是 source truth 仓、bus truth 仓或 marketplace transaction 仓
- BridgeRequest / BridgeMapping / BridgeDelivery / ReplayRequest / IntegrationStatus 构成正式桥接体验层真相
- `BridgeMapping ≠ source truth`、`bridge delivery ≠ bus truth`、`external endpoint status ≠ internal execution truth`、`Protocol translation ≠ domain model truth` 等核心边界必须成立
- request → mapping → delivery → replay/recovery → diagnostics 五条桥接主线必须能统一组织,且 source refs 持续可追溯
- outbound / inbound / bidirectional delivery 的成功/失败/ack/timeout/duplicate 都必须被一致表达
- replay / resend / resync / repair 只重做桥接过程,不得重做业务裁决或改写 source truth
- partner/integration status、config summary、failure reason 必须始终只是可见诊断层,不能冒充 marketplace 或 observability 真相

因此,本次验收的目的不是笼统判断“能不能对接第三方接口”,而是判断 bridges 的 intake 主线、mapping 主线、delivery 主线、recovery 主线与 diagnostics 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 桥接对象识别与接入入口部分 | 是 | BridgeRequest、BridgeTarget、BridgeDirection、SourceBridgeRef、ExternalEndpointRef |
| 协议映射与载荷转换部分 | 是 | BridgeMapping、ProtocolAdapter、PayloadSchemaVersion、FieldTranslationRule、PayloadEnvelope |
| 投送编排与交付结果部分 | 是 | BridgeDelivery、DeliveryResult、DeliveryAck、TimeoutRecord、DuplicateMarker |
| 同步、回放与故障恢复部分 | 是 | ReplayRequest、ResyncTicket、RepairEntry、BridgeFailureRecord、DeadLetterLikeBridgeRecord |
| 对外可见性与集成运维部分 | 是 | IntegrationStatus、PartnerConfigSummary、FailureReasonView、BridgeHealthView、DeliveryHistoryView |
| source truth、L0-bus transport truth、capability-hub contract truth、marketplace truth、第三方系统本体 | 否 | 只验 bridges 如何消费 source inputs 并组织桥接体验,不验底层 source truths 或第三方系统全部实现 |
| 底层网关、scheduler、重试库本体 | 否 | 只验桥接层的 request/mapping/delivery/recovery/diagnostics 语义,不验底层基础设施实现 |
| 业务裁决与业务回滚逻辑 | 否 | 只验 bridges 的 replay/resync 不越界,不验业务决策链本体 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateBridgeRequest / ResolveBridgeTarget | source refs、target system、direction 合法时必须形成正式 BridgeRequest | API 响应 / DB 记录 / refs compare | [] |
| Bridge entry 边界 | bridge request 只能表达桥接入口,不得替代 source truth 或 bus truth | request/source compare / negative flow | [] |
| BuildBridgePayload / ResolveProtocolAdapter | schema 与 field rules 合法时必须形成正式 BridgeMapping / PayloadEnvelope | mapping row / schema version / payload compare | [] |
| Mapping 边界 | protocol translation 只能翻译 source refs,不得污染 domain model truth 或 external schema truth | compare report / negative flow | [] |
| DispatchBridge / RecordAck / RecordTimeout | payload 和 endpoint 匹配时必须形成正式 BridgeDelivery / DeliveryResult / DeliveryAck / TimeoutRecord | delivery row / ack log / timeout log | [] |
| Delivery 边界 | bridge delivery 只表达桥接交付过程,不得替代 bus truth；外部 endpoint status 不得替代 internal execution truth | compare report / negative flow | [] |
| TriggerReplay / TriggerResync / CreateRepairEntry | failed/timeout/duplicate 条件下必须形成 replay/resync/repair 入口与恢复证据链 | replay request / resync ticket / repair entry / history | [] |
| Recovery 边界 | replay/resync 只能重做桥接过程,不得改写 source truth 或重做业务裁决 | replay/source compare / negative flow | [] |
| BuildIntegrationStatus / BuildFailureReasonView / BuildPartnerConfigSummary | delivery/replay/partner 输入齐全时必须形成正式 status/diagnostics/partner summary 视图 | integration status / failure reason / partner summary views | [] |
| Diagnostics/partner 边界 | diagnostics 不能替代 observability truth；partner config summary 不能替代 marketplace truth | compare report / negative flow | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | 桥接映射反写真相 / delivery 冒充 bus truth / replay/resync 越权改写真相 / diagnostics 冒充 source truth |
| A | 视情况 | 主线可跑但 schema 漂移、ACK/timeout 对账、partner 配置摘要、failure reason 解释不稳 |
| B | 可带着走 | 非关键视图、低优先级状态摘要或诊断文案异常 |

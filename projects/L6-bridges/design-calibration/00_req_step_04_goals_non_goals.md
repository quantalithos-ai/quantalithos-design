## 7. 结构化中间产物

### 7.1 目标

| 目标 | 说明 | 验证方式 |
|---|---|---|
| G-BR-001 真相边界成立 | 本仓仅保有桥接局部状态，不形成内部或平台第二真相 | 归属与只读/写入反例审计 |
| G-BR-002 显式授权成立 | 主体、目标、内容和操作均有可验证授权；未知不放行 | 绑定、撤销、跨租户及回调反例 |
| G-BR-003 双向语义可解释 | inbound/outbound保留来源与阶段结果；接收确认、内部提交和外部效果分开 | 协议与状态追溯、重复/未知结果切口 |
| G-BR-004 四平台差异明确 | 各平台有独立支持/降级/不支持范围，不承诺语义等价 | 官方资料版本核验、能力矩阵及adapter合同切口 |
| G-BR-005 恢复与安全交接成立 | 局部失败可解释、受控恢复可追溯；消息体/secret/敏感审批不进入观测证据 | 故障与重放反例、安全材料白名单审计 |

验证方式是后续必须满足的判断要求，不表示测试已执行或目标已达成。

### 7.2 非目标

| 非目标 | 不做原因 |
|---|---|
| 内部Conversation/Turn、Identity、Gate/Decision、Artifact、Workspace truth | 各owner负责；本仓只转换与引用 |
| 外部账号/频道/消息平台truth或全量备份 | 平台负责；mapping不等于平台实体 |
| external ID自动创建GlobalMember或自动授予参与/审批权限 | 外部账号不等同内部AI身份或授权主体 |
| 默认低敏感审批、敏感Gate完整外显 | 外显与操作均由正式责任链决定 |
| 完整Chat/Console、跨平台一条消息多端广播 | 并行产品不作为未停审输入；各平台独立绑定 |
| 以ACK/HTTP成功代替内部提交、投递或执行完成 | 不同系统阶段不可相互证明 |
| 本轮代码实现、真实账号/凭证配置、SDK/OAuth/KMS/路由产品定案、真实测试/验收或commit | 当前只授权需求校准；不得伪造实施事实 |

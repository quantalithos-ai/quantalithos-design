## 1. 一句话定位（已确认的讨论方向）

`L6-bridges` 是外部协作平台的**协议适配与桥接边界层**：在存在显式授权的 `external-binding` 前提下，把 Slack、Mattermost、Telegram、Discord 等平台的事件、消息、线程、附件引用和交互回调，转换为内部可接受的 command/ref；再把内部已经提交且允许外显的事实，转换为外部平台 payload 并组织投递、回执、重试和恢复。

它只拥有以下 Bridges 局部状态：

- bridge configuration；
- 经授权的 `external-binding relation`；
- external identity/channel/message/thread 的 mapping relation；
- source/delivery cursor；
- deduplication 与 replay records；
- delivery attempt、receipt 和 adapter-local state；
- 安全的 source marker、failure、recovery 和 audit handoff reference。

它不拥有任何内部业务真相，也不宣称拥有外部平台真相。桥接的核心不是“把外部平台复制进来”，而是把跨边界的授权、转换、投递和不确定性收敛在一个可审计的局部边界中。

### 1.1 为什么必须单独存在

| 易混淆对象 | 边界结论 |
|---|---|
| `L1-conversation` | Conversation、Turn、Participant、accepted truth 由 Conversation 拥有；Bridges 只提交 bridge-origin command、消费已提交 ref/event，并维护外部映射。 |
| `L1-identity` | `GlobalMember`、身份生命周期和成员语义由 Identity 拥有；Bridges 可以保存已授权的外部绑定关系，但不得因 `external_id` 自动创建 GlobalMember。 |
| `L1-governance` | Policy、Gate、Decision 和授权结论由 Governance 拥有；外部按钮、回复和 webhook 不能绕过 Policy/Gate，敏感内容必须降级展示或回到受控入口。 |
| `L1-artifact` | Artifact 正文、版本、血缘和访问授权由 Artifact 拥有；Bridges 只保存附件引用、外部上传/链接结果和必要的映射状态。 |
| `L1-workspace` | Workspace、scope、visibility 和工作区局部状态由 Workspace 拥有；Bridges 只消费可验证的 scope/visibility 输入，并维护外部频道或路由的绑定，不形成第二套 workspace 权限。 |
| `L0-sdk` | SDK 提供 typed client、访问封装和契约载体；Bridges 通过它访问服务，不把 SDK cache、client state 或 SDK 默认值当业务真相。 |
| `L4-observability` | Observability 接收 body-free receipt、attempt、cursor、failure 和安全审计交接；Bridges 不把外部消息体、secret、token 或敏感 Gate 内容写入日志/证据。 |
| 外部平台本体 | Slack、Mattermost、Telegram、Discord 的用户、频道、消息、ACK、限流和平台 schema 由平台自身拥有；Bridges 只保存必要的映射和交互结果。 |
| `L0-bus`（若作为传输 seam） | Bus 的 delivery、ack、retry、dead-letter、replay carrier truth 归 Bus；Bridges 只消费授权的 event/ref 并拥有自己的应用 cursor/dedup。 |
| `L5-chat` | 当前是并行产品入口，未停审内容不得成为 Bridges 的正式上游输入；后续只可通过已闭合的 Conversation/Governance 等合同协作。 |

若没有独立 Bridges 层，平台 webhook、SDK 差异、external ID、ACK、限流和回放语义会散落在 Conversation、产品入口或各平台脚本中，最终把平台偶然行为误写成内部事实。若 Bridges 越界，它又会变成身份、对话、治理或外部平台的第二真相源。

### 1.2 桥接对象的最小语义

| 对象方向 | 候选对象 | 归属与限制 |
|---|---|---|
| 外部身份 | `external_account_ref`、`external_user_id`、平台/租户标识 | 平台提供 ID；是否能映射到 `GlobalMember` 必须由显式授权关系决定。 |
| 外部位置 | `external_channel_ref`、DM、thread、message route | 平台拥有频道/线程真相；Bridges 只保存与内部 scope/Conversation 的受控 mapping。 |
| 外部内容 | message、edit、delete、reaction、attachment reference | 只在 adapter 私有处理和受控映射中使用；禁止复制为内部业务正文。 |
| 内部来源 | Conversation/Turn、Identity、Gate/Decision、Artifact、Workspace 的 typed ref/event | 由各 owning domain 提供；Bridges 不通过外部 schema 反推内部真相。 |
| 投递结果 | attempt、receipt、ACK、timeout、unknown、retryable | 只解释 Bridges 的外部效果；不等于内部 Turn 提交或内部执行完成。 |

| 入站 | 验签/回调验证结果、normalized envelope、source marker、dedup 结果、inbound cursor | 外部平台事件、Conversation 接受/拒绝结果、治理结论 | Conversation/Turn 正文真相、平台原始事件存档 |

## 3. 交互对象总览（系统上下文草图）

```text
                         +-----------------------------+
                         | External platforms          |
                         | Slack / MM / Telegram /    |
                         | Discord                     |
                         +-------------+---------------+
                                       | webhook / callback
                                       | API / ACK / error
                                       v
                         +-------------+---------------+
                         |        L6-bridges           |
                         | adapter + bridge core       |
                         | binding / mapping           |
                         | cursor / dedup / replay     |
                         | delivery / receipt / state  |
                         +--+---------+---------+-------+
                            |         |         |
              typed ref /  |         |         | body-free safe handoff
              command/event |         |         v
                            |         |  +--------------+
                            |         +->| L4-observe   |
                            |            | safe audit   |
                            |            +--------------+
                            |
          +-----------------+-------------------------------+
          | L0-sdk typed clients / event and ref seams       |
          +--+------------+------------+-----------+---------+
             |            |            |           |
             v            v            v           v
       conversation   identity   governance   artifact   workspace
       owner truth    owner      owner        owner      scope/visibility

          +----------------+       +-------------------------+
          | OAuth/API/KMS  |-----> | adapter private secret  |
          | opaque refs    |       | material, never output  |
          +----------------+       +-------------------------+
```

图示说明：

- 内部 owning domain 通过 SDK、query、event、ref 或 command seam 协作；Bridges 不共享它们的数据库事务或内部表。
- 外部平台 ACK 只属于平台/adapter 交互阶段；Conversation 的 accepted truth、Bridges 的 delivery receipt 和外部送达结果是三条不同语义。
- `L4-observability` 只接收经允许的 body-free 材料；它不成为 Bridges 的 mapping、delivery 或治理真相 owner。
- secret provider 只解决 opaque reference；原始 secret 不进入 Bridges durable state、日志、证据或外部 payload。

### 4.1 禁止依赖（候选）

| 禁止依赖 / 做法 | 禁止原因 | 正确协作方式 |
|---|---|---|
| Bridges 直接读写 Conversation、Identity、Governance、Artifact 或 Workspace 内部表 | 破坏 source ownership，无法解释 accepted truth 与回滚边界。 | 使用正式 query、event、ref、command 或 SDK adapter seam。 |
| 以外部平台用户/频道自动推导 GlobalMember、ProjectMember、Workspace visibility | 会形成隐式授权和 fail-open 路径。 | 显式 external-binding + owning domain 授权；未知即拒绝或隔离。 |
| 以平台 ACK、HTTP 2xx 或 bot success 代替内部 Turn/Decision/Execution 结果 | 混淆跨系统状态。 | 分开记录 internal commit、delivery attempt、external receipt 和 unknown。 |
| 在日志、trace、metrics、evidence、report 中写入外部消息体、secret 或敏感 Gate | 违反最小披露和审计边界。 | 只交接有限类别、safe ref、digest/cursor 和脱敏结果。 |
| adapter 直接修改 Governance 或 Conversation | 平台协议层不应成为业务命令 owner。 | 验证 callback 后生成 owner command，由 owning domain 作决定。 |
| 为了重试 unknown 结果而更换 token、target、binding 或 intent | 可能造成重复外部副作用。 | same-token probe、manual reconcile 或明确 indeterminate。 |
| 把某一平台的 thread/edit/delete/attachment 能力伪装成所有平台共有语义 | 隐藏能力差异，导致数据和用户预期漂移。 | capability matrix + explicit unsupported/degraded 状态。 |

## 5. Inbound / outbound / callback 交互草图（候选）

```text
Inbound:
external event
  -> adapter verify / replay guard
  -> binding + identity + workspace scope check
  -> normalize + source marker + dedup reservation
  -> governance / gate admission
  -> Conversation bridge-origin command
  -> accepted / rejected / pending result
  -> mapping + cursor + receipt (local Bridges truth)
  -> platform ACK is recorded separately

Outbound:
committed internal ref/event
  -> binding + visibility + policy check
  -> platform payload translation / sensitive degradation
  -> attachment reference resolution
  -> immutable intent + idempotency key
  -> rate limit / order gate
  -> platform adapter API call
  -> attempt / ACK / timeout / unknown receipt
  -> retry / replay / manual reconcile if needed

Callback:
platform button / interaction callback
  -> signature + freshness + binding verification
  -> mapping + identity + governance context
  -> owner command (Gate / Conversation / other)
  -> owner result
  -> optional external update through a new delivery intent
```

这三条链不得被压缩成“收到平台消息即提交 Turn”或“平台返回成功即业务成功”。确切状态机、事务边界、幂等键和 cursor 语义留待后续 calibration 与正式 `03` 收口。

## 6. 数据、secret 与证据边界（候选）

| 材料 | 可进入 Bridges durable state | 只能停留在 adapter/private seam | 禁止进入日志/证据 |
|---|---|---|---|
| binding identity、platform kind、mapping ref、schema version | ✅ |  | 仅输出受控 safe ref/类别 |
| external message/channel IDs、cursor、dedup key | ✅（按最小范围） |  | 不输出完整消息内容 |
| normalized metadata、source marker、attempt/receipt category | ✅ |  | 只能脱敏、低基数、可回链 |
| raw message body、完整 attachment body | 仅在明确的瞬时 adapter 处理内 | ✅ | ❌ |
| OAuth token、API key、KMS material、签名 secret | ❌ | ✅ | ❌ |
| 敏感 Gate/Decision 正文 | ❌ | 不应跨入 Bridges | ❌ |
| 真实外部账号、真实投递成功、测试 run、evidence、verdict | 只能记录实际 receipt/ref |  | 不得伪造 |

## 9. 本篇讨论结论

本篇将 `L6-bridges` 限定为“受授权的跨平台 mapping、protocol translation、delivery、callback verification、replay/recovery 和安全交接”边界，并明确 Conversation、Identity、Governance、Artifact、Workspace、Observability 及外部平台各自的 authority。下一篇只推演能力闭环和失败语义；不会用 draft 补造上游合同、平台账号、secret、实现或证据。

# 02 · L6-bridges 功能推演（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源\
> 前置：`draft/01_项目作用与交互对象.md`\
> 本文回答：Bridges 需要形成什么能力闭环；inbound、outbound、callback、mapping、回放和投递状态如何分层；平台差异、外部失败和上游不可用时如何表达；哪些能力仍必须保持 `pending / blocked`。

本文只推演能力语义，不锁定 API、DTO、事件 payload、数据库、索引、消息后端、平台 SDK、OAuth 产品、KMS 实现、调度器或具体 UI。未有 owning domain 或平台合同的正向路径，不以 fake、默认值或历史文档补齐。

## 1. 核心能力闭环（候选）

### C1 · 显式绑定与接入准入

Bridges 只能在存在有效 `external-binding` 的情况下接收或发送外部交互。绑定至少要能表达平台/租户、外部位置、内部安全 ref、授权状态、适用范围、配置版本和撤销/失效结果；具体字段后置。

```text
admin/config intent
  -> validate adapter/config/secret refs
  -> resolve identity/workspace/governance applicability
  -> create or update binding (Bridges-owned)
  -> active / blocked / revoked / waiting
```

绑定激活不代表外部平台已经可用，也不代表 GlobalMember、Policy、Workspace 或 secret provider 已完成真实部署。

### C2 · Inbound 接收、验证与内部提交交接

```text
platform event / callback
  -> adapter signature + freshness + replay check
  -> external-binding lookup
  -> external identity/channel/message mapping lookup
  -> source marker + dedup reservation
  -> workspace scope / visibility check
  -> governance admission
  -> Conversation bridge-origin command
  -> accepted / rejected / pending / indeterminate
  -> Bridges mapping + cursor + receipt
```

本闭环的关键分离：

- 平台收到 webhook 的 ACK 不等于内部 Turn 已提交；
- Conversation 接受 command 不等于外部回复已送达；
- dedup reservation 不等于业务事实已创建；
- 未授权或无法验证的 external ID 必须拒绝、隔离或等待人工处理，不得自动创建 GlobalMember。

### C3 · Outbound 转换、投递与回执

```text
committed internal ref/event
  -> binding + visibility + policy check
  -> source marker / mapping resolution
  -> canonical-to-platform translation
  -> sensitive Gate degradation if required
  -> artifact reference conversion
  -> immutable delivery intent + idempotency key
  -> ordering / rate-limit admission
  -> platform adapter call
  -> attempt / ACK / timeout / unknown receipt
  -> retry / replay / manual reconcile
```

delivery receipt 只能说明 Bridges 对外部平台的尝试和已知结果。无论平台返回 2xx、message id 还是业务拒收，都不能覆盖 Conversation、Governance、Artifact 或 Workspace 的内部 truth。

### C4 · Callback 与交互动作闭环

平台按钮、modal、slash command、reaction 或其他交互回调，先经过 adapter 验签、时效和 replay protection，再转成 owner command/ref。

```text
external interaction
  -> verify signature / binding / freshness
  -> resolve identity + scope + source mapping
  -> Governance Policy/Gate admission
  -> owner command (Conversation/Governance/etc.)
  -> owner result
  -> optional new delivery intent
```

Bridges 不在本地直接批准/拒绝 Gate，也不把 callback 的 HTTP success 当作 Decision 已提交。

### C5 · 映射、幂等与回放

每个入站 source event、出站 delivery intent、callback interaction 和 replay attempt 都需要可解释的 idempotency namespace。mapping、source cursor、delivery receipt 和 read/业务状态必须分离。

```text
source position / external event id
  -> dedup reservation
  -> apply or explicit duplicate result
  -> cursor advance / gap marker
  -> replay or resync request when needed
```

对 unknown external result 不得盲重试；只能走 same-token probe、manual reconcile、明确的 indeterminate 或平台规定的安全恢复路径。

### C6 · 平台差异与能力降级

每个平台的 edit、delete、thread、attachment、mention、callback、rate-limit、ACK 和 retry 行为必须显式记录为 capability/unsupported/degraded 结果，不能把一个平台的成功语义伪装成所有平台通用能力。

## 2. 核心闭环的进入 / 退出条件（候选）

| 闭环 | 进入条件 | 正常退出 | 非正常退出 |
|---|---|---|---|
| 绑定激活 | config、binding、适用 scope 和 secret ref 可验证 | Bridges-owned binding active | blocked / revoked / waiting，不外呼 |
| Inbound | 签名、binding、mapping 和必要 visibility 可验证 | owner command 已明确 accepted/rejected/pending，局部 receipt 已记录 | unauthorized / duplicate / quarantined / indeterminate |
| Outbound | committed source ref/event、binding、policy 和 payload snapshot 可用 | attempt/receipt 明确为 delivered、rejected 或其他平台结果 | retryable / unknown / manually_reconcile / blocked |
| Callback | signature、freshness、binding、source mapping 可验证 | owner command/result 有明确 handoff | invalid / expired / replayed / governance_blocked |
| Replay/resync | gap、cursor、intent 或 source ref 可定位 | same namespace 的局部状态收敛 | blocked / missing_source / unknown / manual |
| Observability handoff | 只含允许的 safe summary/ref 和 correlation | accepted / rejected / queued 等安全 disposition | unavailable / backlog / blocked，不伪造 evidence |

没有“默认成功”退出。缺少 authority、版本、水位、secret 或可验证回执时，结果必须带有原因和受影响的 scope/intent。

## 3. 候选功能清单

### 3.1 核心功能（候选 FR）

| ID | 功能 | 优先级 | 依赖 | 讨论语义 |
|---|---|---:|---|---|
| `BR-FR-001` | Adapter configuration and binding | P0 | L0-sdk、secret seam、external platform | 管理平台 profile、路由、授权 binding 和生命周期。 |
| `BR-FR-002` | Inbound verification and normalization | P0 | platform adapter、callback contract | 验签、防重放、统一 source marker 和 normalized envelope。 |
| `BR-FR-003` | External mapping | P0 | L1-identity、L1-workspace、L1-conversation | 维护 external identity/channel/message/thread 与内部 safe ref 的显式关系。 |
| `BR-FR-004` | Inbound Conversation handoff | P0 | L1-conversation、L1-governance | 将合规外部事件转为 owner command；不直接写 Turn。 |
| `BR-FR-005` | Outbound protocol translation | P0 | Conversation、Governance、Artifact、Workspace | 将 committed ref/event 转成平台 payload，并保留 source/provenance 语义。 |
| `BR-FR-006` | Sensitive Gate projection | P0 | L1-governance | 低敏感可按正式规则降级展示；敏感内容回受控入口。 |
| `BR-FR-007` | Callback action handoff | P0 | platform verification、Governance、Conversation | 验证回调后生成 owner command，不本地改治理状态。 |
| `BR-FR-008` | Delivery intent / attempt / receipt | P0 | adapter、local durable state | 区分 prepared、attempt、external receipt、timeout、unknown。 |
| `BR-FR-009` | Deduplication and cursor | P0 | source/event contract | 记录入站、出站、callback 和 replay 的幂等结果及 cursor/gap。 |
| `BR-FR-010` | Order / rate-limit / retry | P1 | platform capability、scheduler seam | per-binding 限流、顺序约束、backoff 和安全恢复。 |
| `BR-FR-011` | Edit / delete / thread / attachment mapping | P1 | platform capability、Artifact、Conversation | 显式表示可支持、不可支持、降级和失效。 |
| `BR-FR-012` | Safe observability handoff | P0 | L4-observability | 只交接 body-free receipt、状态类别、cursor 和安全引用。 |
| `BR-FR-013` | Replay / resync / manual repair | P1 | cursor、owner replay/query、operators | 只修复 Bridges-owned state，不修复 source truth。 |
| `BR-FR-014` | Secret reference and rotation seam | P0 | OAuth/API Key/KMS | 只保存 opaque reference；历史 intent 使用其绑定快照，不盲切换。 |

### 3.2 外围增强候选（不替代核心）

| 能力 | 价值 | 当前限制 |
|---|---|---|
| 多平台 capability discovery | 在配置和 UI 中解释平台差异 | 不能用 discovery 结果替代正式 capability contract。 |
| operator diagnostics view | 帮助定位 binding、mapping、cursor、rate-limit 和 receipt 状态 | 不展示 raw message、secret 或敏感 Gate；不生成 verdict/signoff。 |
| 按平台的低敏感卡片 | 提升轻量审批和提醒体验 | 必须由 Governance 给出允许外显的语义，不能由 adapter 自定。 |
| 外部历史回放 | 修复平台短时不可用或 cursor gap | 需平台 replay/owner source 合同，不能假定平台可无限回放。 |

## 4. 失败与降级语义（候选统一口径）

| 失败点 | Bridges 结果 | 不允许的降级 |
|---|---|---|
| callback 签名、时间窗或 replay 校验失败 | reject / security event category / no owner command | 猜测来源、继续处理或记录原始内容 |
| binding 不存在、已撤销或 scope 不匹配 | rejected / blocked / quarantine | 使用当前默认 binding 或其他租户映射 |
| external identity 未授权 | rejected / admin-action-needed | 自动创建 GlobalMember 或借用相似用户 |
| Workspace visibility/route 不可验证 | fail-closed / waiting | default allow、沿用旧可见性、继续外发 |
| Governance 不可用或 Gate 敏感度未知 | blocked 或降级到受控入口 | 直接显示完整审批内容或绕过 Policy |
| Conversation accepted truth 未知 | pending / indeterminate；保留局部 intent | 重复创建 Turn 或把 ACK 当 accepted |
| Artifact ref 失效/无权/过期 | link-only、degraded 或 blocked | 上传未授权正文、记录 blob 内容 |
| 外部平台 timeout/5xx/限流 | retryable / queued / backoff / manual | 无幂等地重复外呼或隐藏失败 |
| 外部结果 unknown | same-token probe / manual reconcile / indeterminate | 更换 token、target、binding 后盲重试 |
| edit/delete/thread 不支持 | unsupported / out-of-sync / degraded receipt | 假装已修改或删除全部平台历史 |
| secret resolver unavailable | blocked / disabled for affected binding | 明文 fallback、从日志或历史 payload 恢复 secret |
| Observability handoff unavailable | safe backlog / pending / blocked（依正式合同） | 丢弃审计、写入 raw body 或伪造 evidence |
| cursor gap / replay source unavailable | gap / rebuilding / manual | 直接标记 caught-up 或跳过缺口 |

### 4.1 事件与投影异常矩阵（候选）

| 事件类别 | 可持久化材料 | 需要等待/人工的信号 | 禁止推断 |
|---|---|---|---|
| inbound duplicate | dedup key、source marker、duplicate category | 是否需要 source reconcile | duplicate 不等于 Turn 已存在，除非 owner 明确返回。 |
| outbound accepted by platform | intent ref、attempt、platform receipt category | 内部 execution/Turn outcome | platform ACK 不等于业务完成。 |
| outbound unknown | immutable intent、same-token probe state | external side effect 是否发生 | unknown 不等于 failed，也不等于 success。 |
| replay gap | cursor、gap range/category、replay request | owner/platform replay availability | gap 不等于数据可丢失或可用默认值补齐。 |
| mapping revoked | binding/mapping version、revocation result | 历史消息是否仍可安全展示 | revoke 不等于删除内部 source truth。 |

## 5. 不同平台差异的最小表达（候选）

| 能力 | Bridges 需要记录 | 不可统一假设 |
|---|---|---|
| Message identity | platform、tenant、channel、message、thread ref | 所有平台 ID 全局唯一或永久稳定 |
| Thread/reply | parent mapping、reply relation、unsupported/degraded | DM、group、thread 的语义相同 |
| Edit/delete | intent、capability、result、stale marker | 删除一定可回溯、编辑一定可重放 |
| Attachment | artifact ref、external upload/link result、expiry | 外部 URL 永久有效、平台允许任意附件 |
| Interaction callback | signature/freshness/nonce、action ref、owner result | HTTP success 等于 Decision 成功 |
| Rate limit | binding/route bucket、retry-after category、backoff state | 所有平台都有相同窗口、配额或 retry-after |
| External ACK | stage、receipt category、platform ref | ACK 等于内部提交或用户已看见 |

## 6. 非目标（候选）

| ID | 非目标 | 原因 / 归属 |
|---|---|---|
| `BR-NG-001` | 成为 Conversation、Turn、Identity、Gate、Artifact 或 Workspace 真相源 | 各 L1 owning domain。 |
| `BR-NG-002` | 取代 Chat/Console，提供完整协作前台 | Bridges 是受限触达和协议边界，不是产品 UI truth。 |
| `BR-NG-003` | 自动开户、自动创建 GlobalMember 或推断组织授权 | Identity/治理流程必须显式授权。 |
| `BR-NG-004` | 在外部平台完整呈现高敏感 Gate/Decision | Governance 与受控审批入口负责敏感内容。 |
| `BR-NG-005` | 保存外部平台全量消息、附件或 token | 平台本体、Artifact 和 secret provider 负责各自材料。 |
| `BR-NG-006` | 用外部 ACK/receipt 代替内部执行/提交真相 | 交付结果与 source truth 必须分离。 |
| `BR-NG-007` | 默认跨平台广播或统一覆盖各平台差异 | 每个 binding、平台能力和策略独立。 |
| `BR-NG-008` | 在实现前宣称真实账号、token、投递、测试、evidence、verdict 或 readiness | 当前仅有设计 seam，不能伪造外部事实。 |

## 7. 关键设计问题与 pending（正式校准时逐项收口）

| 问题 | 需要哪一类事实 | 当前处理 |
|---|---|---|
| inbound command 与 Turn accepted 的精确边界 | Conversation owner contract | pending，不锁 API 或 ACK 时点。 |
| external-binding 与 GlobalMember 的授权生命周期 | Identity/admin contract | pending，只保留显式授权/撤销原则。 |
| Gate 敏感度、外显字段和 callback owner | Governance contract | pending，未知即降级/回平台。 |
| Workspace channel/visibility/route input | Workspace query/event contract | 受 `WS-UP-001~008` 控制，unknown fail-closed。 |
| attachment ref、上传和过期 | Artifact contract + platform capability | pending，不选 blob/URL 产品。 |
| idempotency key 和 cursor namespace | source/event/platform contract | pending，不用 timestamp 或猜测 ID 代替。 |
| external unknown 的恢复协议 | platform/provider + operational contract | pending，只允许 same-token/manual 方向。 |
| OAuth/API key/KMS/SDK/路由选择 | security/provider/platform decision | pending，不伪造 provider、token 或 account。 |
| body-free Observability handoff | L4 contract | pending；当前不声称存在真实 evidence。 |
| L5-chat 的正式接缝 | 并行项目停审后的 contract | 不作为当前正式输入。 |

## 8. 本篇讨论结论

本篇把 Bridges 的功能闭环限定为：显式绑定、入站验证与交接、出站转换与投递、回调验证、mapping/dedup/cursor、平台差异、限流/重试、回放/恢复和安全观测交接。下一篇将把这些能力划分为业务组成部分、实现层、对象类别、状态组与 port/seam；仍不锁具体代码、协议、配置键或平台产品选择。

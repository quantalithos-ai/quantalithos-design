> 本文回答：为实现 Bridges 的 mapping、转换、投递、回调、恢复和审计交接闭环，需要哪些候选业务组成部分、实现分层、对象和状态组；哪些一致性边界必须保持；哪些部分因上游或平台合同未闭口而保持 blocked。

## 1. 业务主要组成部分（候选，10 个）

| # | 组成部分 | 核心职责 | 不承担什么 | 承接能力 |
|---|---|---|---|---|
| 1 | `Bridge configuration and binding registry` | 保存 adapter profile、配置版本、授权 `external-binding`、路由范围、撤销和失效状态。 | 不保存 raw secret、不授予 GlobalMember/Policy 权限、不拥有平台管理员真相。 | C1、`BR-FR-001`、`BR-FR-014`。 |
| 2 | `Platform ingress and callback verifier` | 接收 webhook/callback，执行签名、时效、nonce/replay 和平台 envelope 校验。 | 不决定内部业务语义、不直接修改 Gate/Turn。 | C2、C4、`BR-FR-002`、`BR-FR-007`。 |
| 3 | `External mapping and source marker` | 维护 external identity/channel/message/thread 与内部安全 ref 的显式 mapping，以及来源标记和映射失效。 | 不创建 GlobalMember、Conversation、Workspace 或平台对象。 | C2、C3、`BR-FR-003`。 |
| 4 | `Scope, identity and policy gateway` | 编排 Identity、Workspace、Governance 的授权、范围、可见性和 Policy/Gate admission。 | 不形成第二套 authorization truth，不以本地默认值放行。 | C2、C3、C4、`BR-FR-004/006`。 |
| 5 | `Protocol translation and safe projection` | 将 canonical refs/events 转成平台 payload，将平台事件转成 normalized input；处理 Gate 降级、字段裁剪和能力差异。 | 不把 external schema 或 projection 变成 domain truth，不暴露敏感内容。 | C2、C3、C6、`BR-FR-005/006/011`。 |
| 6 | `Outbound delivery orchestration` | 组织 immutable intent、顺序、限流、平台调用、attempt、receipt 和交付状态。 | 不把平台 ACK 当内部提交，不直接决定业务执行成功。 | C3、`BR-FR-008/010`。 |
| 7 | `Cursor, idempotency and replay coordination` | 维护 source/delivery/callback cursor、dedup、gap、replay、resync 和 manual reconcile 状态。 | 不拥有 Bus delivery、source replay truth 或外部平台完整历史。 | C5、`BR-FR-009/013`。 |
| 8 | `Attachment and capability adaptation` | 将 Artifact ref 与平台 attachment/link 能力对接，维护 edit/delete/thread/attachment capability 结果。 | 不存 Artifact 正文、不假设各平台能力一致。 | C3、C6、`BR-FR-011`。 |
| 9 | `Receipt, audit and diagnostics handoff` | 形成 body-free safe handoff、failure category、integration diagnostics 和受控 operator read surface。 | 不生成 evidence/verdict/signoff，不记录 raw body/secret。 | `BR-FR-012`、operator recovery。 |
| 10 | `Secret and adapter-local seam` | 通过 opaque ref 解析 secret，构造平台 adapter 私有句柄，维护 adapter-local state 和 availability。 | 不将 material 写入 durable state、日志、事件或业务对象。 | C1、C3、`BR-FR-014`。 |

             |                      |

## 2. 实现分层（候选）

| 分层 | Bridges 内职责 | 边界与纪律 |
|---|---|---|
| Platform ingress / adapter | 处理平台协议、验签、回调、API 调用和平台能力探测 | 不把平台 schema 直接暴露为内部 domain object；不持有业务真相。 |
| Application orchestration | 编排 binding、mapping、owner query/command、translation、delivery、replay 和失败分类 | 跨仓访问只能经 port/seam；不能用默认值绕过缺失合同。 |
| Bridge domain policy | 定义 binding、mapping、cursor、dedup、intent、attempt、receipt、callback verification 和 adapter-local 状态 | 只保护 Bridges-owned invariant；不重写 Policy/Gate/Identity/Artifact/Workspace 规则。 |
| Translation / projection | 维护 canonical ref 到 external payload、external event 到 normalized input、敏感裁剪和 capability result | 只生成 bridge projection；禁止复制 source truth 或敏感正文。 |
| Ports / external seams | 提供 SDK client、Conversation、Identity、Governance、Artifact、Workspace、Observability、secret 和 platform adapter 接口 | port 不是 owner；未闭口 seam 必须返回 blocked/pending/fail-closed。 |
| Persistence / local state | 保存 binding、mapping、cursor、dedup、intent、attempt、receipt、replay 和 adapter-local safe state | 不保存 raw token/message body，不使用共享 owner 表。 |
| Maintenance / diagnostics | 执行 replay/resync、unknown reconcile、rate-limit recovery、mapping audit 和 operator 查询 | 不修复 source truth，不把维护成功写成外部或内部业务完成。 |

## 3. 关键对象方向（只列类别，字段后置到正式 02/03）

### 3.1 Bridges 自有配置、绑定和 mapping

| 对象类别 | 作用 | 核心边界 |
|---|---|---|
| `BridgeConfiguration` | 表达平台 adapter、路由、能力、版本和安全引用的可校验配置快照。 | 不含 raw secret，不以配置声称代替实际 provider/平台可用性。 |
| `ExternalBinding` | 表达平台/租户/外部位置与内部安全 ref 的授权关系、适用 scope、版本和撤销。 | 绑定是 Bridges-owned relation；GlobalMember、Workspace、Policy 仍由各 owner 决定。 |
| `ExternalIdentityMapping` | external account/user 与内部 identity ref 的受控映射。 | 不自动创建 GlobalMember，不把同名/邮箱相似当授权。 |
| `ExternalChannelMapping` | external channel/DM/thread route 与 Conversation/Workspace safe ref 的映射。 | 不创建内部 Conversation/Workspace，不声明平台频道可见性。 |
| `ExternalMessageMapping` | external message/edit/delete/thread 与 Turn/source ref、source marker 的关联。 | 不等于 Turn truth、平台消息全量历史或送达状态。 |
| `SourceMarker` | 标记 bridged source、平台、binding/version 和必要 provenance。 | 只保存最小可追溯元数据，不带 raw body。 |

### 3.2 入站、出站和回调对象

| 对象类别 | 作用 | 核心边界 |
|---|---|---|
| `InboundEnvelope` | 规范化平台事件、验证结果、external refs、source position 和安全 metadata。 | 不是 Conversation/Turn，不保存未经允许的外部正文。 |
| `CallbackVerification` | 保存签名、freshness、nonce/replay、binding 和验证结果类别。 | 不代表 Gate/Decision 已提交。 |
| `OutboundIntent` | 冻结 source ref、binding/version、payload projection ref、idempotency namespace 和目标范围。 | intent commit 不等于外部送达。 |
| `DeliveryAttempt` | 记录一次平台调用、时间、阶段、超时和结果类别。 | 不把 provider response 当业务 verdict。 |
| `DeliveryReceipt` | 保存可解释的 external receipt/ACK/timeout/unknown/rejected 结果。 | 不等于 internal accepted truth、Turn commit 或执行完成。 |
| `AttachmentProjection` | 保存 Artifact ref 到 external upload/link 的映射、能力和过期状态。 | 不保存 Artifact 正文、永久公开 URL 或 secret。 |

### 3.3 游标、幂等、恢复和私有状态

| 对象类别 | 作用 | 核心边界 |
|---|---|---|
| `MappingCursor` | 记录平台 source position、delivery position 或 callback position 的局部进度。 | source cursor、delivery cursor、用户 read cursor 不能混用。 |
| `DeduplicationRecord` | 记录 source event、callback、outbound intent 或 replay 的幂等保留和结果。 | duplicate 记录不自动证明 owner truth 已存在。 |
| `GapRecord` | 表达 cursor 缺口、顺序冲突、不可重放和影响范围。 | 不允许以 timestamp、默认 offset 或“已成功”掩盖缺口。 |
| `ReplayRequest` | 表达受控 replay/resync/manual reconcile 的目标、namespace 和状态。 | 不拥有 Bus/platform replay carrier truth。 |
| `AdapterLocalState` | 保存 adapter 私有 availability、rate bucket、nonce cache 和能力状态。 | 不向 domain 或日志泄露 secret/material/平台内部全量数据。 |
| `SecretRef` | 只表达 provider/locator 的 opaque 引用和版本类别。 | 不是 raw credential，不允许 hash/base64 作为替代泄露。 |

## 4. 状态组与一致性边界（候选）

### 4.1 状态组

| 状态组 | 承载对象 | 状态候选 | 不变量 |
|---|---|---|---|
| Binding | `ExternalBinding` | draft / validating / active / blocked / revoked / expired | 未验证授权、scope 或 secret capability 时不能 active。 |
| Inbound verification | `InboundEnvelope` / `CallbackVerification` | received / verified / rejected / duplicate / quarantined / pending | 未验证来源不得产生 owner command。 |
| Mapping | identity/channel/message mapping | unresolved / authorized / stale / conflicted / revoked | 不能用默认映射、模糊匹配或当前 binding 覆盖历史 binding。 |
| Admission | scope/identity/policy result | checking / allowed / degraded / denied / unavailable | unknown visibility/policy 必须 fail-closed。 |
| Translation | normalized/payload projection | not_started / translated / degraded / unsupported / invalid | projection 不得声称拥有 source schema truth。 |
| Outbound intent | `OutboundIntent` | prepared / committed / queued / blocked / superseded | intent 必须绑定 immutable source snapshot/ref 和 idempotency namespace。 |
| Delivery | `DeliveryAttempt` / `Receipt` | pending / in_flight / delivered / rejected / retryable / timed_out / unknown / manual | platform ACK 与 internal commit 分开；unknown 不得盲重试。 |
| Cursor/replay | `MappingCursor` / `GapRecord` / `ReplayRequest` | initial / advancing / duplicate / gap / replaying / caught_up / blocked | 不以 read cursor、时间戳或本地默认值替代 source position。 |
| Adapter-local | rate/capability/secret handle | unavailable / ready / throttled / degraded / expired | private material 不能进入 durable/log/evidence。 |
| Observability handoff | safe receipt/audit handoff | pending / accepted / rejected / queued / unavailable | 不生成 evidence、verdict、signoff 或 readiness。 |

### 4.2 关键一致性规则（候选）

1. **source truth 与 bridge truth 分离**：Conversation/Turn、Identity、Policy/Gate/Decision、Artifact、Workspace 和平台消息永远由各自 owner 持有；Bridges 只保存 mapping、intent、attempt、receipt、cursor 和 adapter-local state。
2. **ACK、commit、delivery 三分离**：平台 ACK、内部 owner accepted/committed、外部 delivery receipt 必须有不同状态和证据引用，不能相互推断。
3. **binding first**：任何 inbound、outbound、callback、replay 和 secret resolution 都必须绑定到显式 binding/version；历史 intent 不得自动切到当前 route。
4. **authorization before effect**：在 identity、workspace visibility 和 Governance admission 未明确前，不能提交 owner command、构造可见 payload 或执行外部副作用。
5. **idempotency before retry**：先保存 immutable intent/dedup reservation，再进行外部调用；unknown 只能 same-token probe/manual，不得换 binding 或 token 盲重试。
6. **cursor separation**：source cursor、delivery cursor、callback nonce/replay state 和业务/user read state 是不同状态组，任何一个推进都不能推断其他组成功。
7. **platform capability explicit**：edit/delete/thread/attachment/mention/callback/rate-limit 差异必须落为 capability、unsupported、degraded 或 stale 结果。
8. **no raw sensitive material**：外部正文、附件正文、token、secret、敏感 Gate/Decision 内容不得进入 Bridges durable state、日志、trace、metrics、evidence 或 report。
9. **unknown remains unknown**：外部状态、commit-unknown、provider availability 或上游 handoff 不可验证时保持 indeterminate/manual，不用 default success 或失败猜测收口。
10. **query no-write**：只读 mapping、capability、diagnostic 和 owner query 不得隐式创建业务 mapping、推进 cursor、触发外呼或修改 source truth；变更必须走显式 command/maintenance path。

### 4.3 建议的事务 / 交接边界（候选）

| 用例 | Bridges 内可原子收口 | 外部边界 / 禁止假设 |
|---|---|---|
| 保存 binding 变更 | 配置快照、binding version、授权状态和安全 ref | 不代表平台 OAuth 已完成、secret 可解析或 external call 成功。 |
| 接收 inbound event | 验证结果、dedup reservation、normalized metadata、mapping/cursor 结果 | Conversation 是否提交 Turn、平台 ACK 是否发出分别处理。 |
| 创建 outbound intent | source ref、binding/version、payload projection ref、idempotency key、intent state | 不等于平台已接收、用户已看到或内部执行成功。 |
| 完成 external attempt | attempt、receipt category、retry/manual state、safe diagnostics | 不更新 Conversation/Decision/Artifact/Workspace 真相。 |
| 处理 callback | verification、mapping、owner command handoff 状态 | 不在 Bridges 内直接写 Gate/Decision。 |
| 应用 replay | dedup/application record、cursor、gap/replay state、局部 mapping/projection | 不等于 Bus/platform replay completion 或 source repair。 |
| 交接 Observability | safe handoff intent、correlation、disposition/backlog 状态 | 不等于 evidence/report/verdict/signoff。 |

## 5. 关键 port / seam 类别（候选，不锁协议）

| seam | 方向 | 能力语义 | 当前约束 |
|---|---|---|---|
| `PlatformAdapter` | 双向 | 接收 event/callback，执行 send/edit/delete/thread/attachment，返回平台结果 | 每个平台独立 capability；不能直接改业务 truth。 |
| `BindingResolver` | 入站 | 查询/验证 binding、授权、version、scope 和撤销 | owner/admin contract pending；unknown 不放行。 |
| `IdentityMappingPort` | 双向 | 解析 external identity 与授权 internal identity ref | 不自动创建 GlobalMember；撤销需可追踪。 |
| `ConversationPort` | 双向 | 提交 bridge-origin command，消费 committed Conversation/Turn refs/events | accepted、commit、delivery 分离；exact contract pending。 |
| `GovernancePort` | 双向 | 请求 Policy/Gate/Decision admission、敏感度和 callback owner | 不在 Bridges 本地形成 Decision。 |
| `ArtifactRefPort` | 双向 | 解析安全 attachment ref、授权上传/链接结果和过期状态 | 不读/存 Artifact 正文；contract pending。 |
| `WorkspaceScopePort` | 入站 | 校验 channel/scope/visibility/route/attention 语境 | `WS-UP-001~008` 未闭合处 fail-closed。 |
| `SecretResolver` | 入站 | 由 opaque ref 解析 adapter 私有 credential handle | raw material 仅 private memory；provider/rotation pending。 |
| `IdempotencyStore` | 内部 | reservation/result compatibility、unknown 和 replay namespace | 不以 digest/hash 暗存 secret 或正文。 |
| `CursorStore` | 内部 | source/delivery/callback cursor、gap、watermark、replay checkpoint | 不与平台或 Bus cursor truth 混淆。 |
| `DeliveryStore` | 内部 | immutable intent、attempt、receipt、retry/manual 状态 | 不写 owner execution truth。 |
| `ObservabilitySafeHandoff` | 出站 | body-free correlation、status category、safe ref、redaction result | L4 合同和真实实现尚未闭口。 |
| `OperatorRepairPort` | 入站 | revoke、rebind、replay、resync、manual reconcile、diagnostics read | 需权限和审计；不能直接修 source domain。 |

`fake`、`controlled` 或 `disabled` adapter 只可在后续测试中模拟这些 seam 的延迟、拒绝、超时和 capability 差异，不能证明真实平台、账号、token、投递、run、artifact、report 或 evidence 存在。

## 6. 关系、存储与输出边界（候选）

| 材料 | 建议归属 | 最小内容方向 | 禁止内容 |
|---|---|---|---|
| binding/config | Bridges local state + secret ref | platform kind、scope、version、status、opaque ref | raw secret、provider body、默认账号 |
| mapping | Bridges local state | external IDs、internal safe refs、binding/version、validity、source marker | internal正文、全量平台用户资料 |
| cursor/dedup/gap | Bridges local state | namespace、position、key category、result、gap、replay ref | 用 timestamp 猜顺序、隐藏缺口 |
| intent/attempt/receipt | Bridges local state | source ref、payload digest/ref、attempt、platform receipt category、retry state | raw payload、平台 token、业务 verdict |
| attachment | mapping/attempt metadata | Artifact ref、external ref、capability、expiry、result | Artifact body、永久凭证、未授权下载内容 |
| diagnostics | safe read/handoff | finite phase/result/error category、safe issue/correlation ref | message body、secret、敏感 Gate、完整 provider error chain |
| platform private state | adapter/private registry | capability/rate bucket/nonce/handle status | private material 暴露到 domain、日志或 evidence |

任何 payload snapshot 如需 durable 保存，必须先确定允许保存的字段和敏感级别；不能以 generic JSON、压缩、hash、base64 或错误链绕过禁止输出。

## 7. 模块裁剪与推进顺序建议（供正式 07 参考，不构成计划承诺）

| 阶段方向 | 最小组成部分 | 进入条件 | 当前状态 |
|---|---|---|---|
| A. local bridge foundation | 1、3、7 的最小 binding/mapping/dedup 子集 | local ownership、撤销和敏感输出边界可表达 | 可讨论；不代表真实平台可用。 |
| B. verified inbound | 2、4、5、7 的一个平台输入 slice | adapter 验签、Identity/Workspace/Governance/Conversation seam 闭合 | `BR-UP-001~005/008` 控制。 |
| C. committed outbound | 5、6、8 的一个平台投递 slice | committed source ref、binding、payload/capability、idempotency 和 receipt contract 闭合 | external/provider 条件型。 |
| D. callback / low-sensitivity Gate | 2、4、5、6 | Governance callback、sensitive classification 和 owner command 闭合 | `BR-UP-003/008` 控制。 |
| E. recovery and replay | 7、9、10 | cursor/gap/replay、unknown recovery、operator authorization 和 safe handoff 闭合 | `BR-UP-006/009` 控制。 |
| F. attachment/edit/thread parity | 5、8 | Artifact ref 和逐平台 capability contract 闭合 | `BR-UP-004/008` 控制。 |
| G. multi-platform expansion | 2、5、6、8、10 | 每个平台独立 adapter/config/secret/receipt 证据可建立 | 不得用单平台 fake 代替。 |

第一版正确的裁剪方向不是“先接通四个平台”，而是先证明一个 binding、一个 inbound 或 outbound slice 能在授权、mapping、幂等、ACK/commit/delivery 分离、敏感裁剪和失败恢复语义下成立。每加入一个平台或 source domain，都必须独立获得其 contract 和边界证据。

## 8. 本篇讨论结论

候选结构已将 `L6-bridges` 划分为配置绑定、平台入口、mapping、scope/policy、协议转换、投递编排、cursor/dedup/replay、附件/能力适配、safe observability handoff 和 secret/adapter-local seam 十类职责，并保持 source truth、platform truth、delivery truth 与 bridge local truth 分离。后续正式校准必须逐项收口对象字段、状态转换、事务、port、平台 capability、配置和测试切口；在此之前，本篇不得被解释为实现、集成、外部投递或 readiness 承诺。

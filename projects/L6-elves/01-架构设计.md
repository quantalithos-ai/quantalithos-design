## 1. 业务背景与驱动力

### 1.1 业务背景

`L6-elves` 的目标不是把 Quantalithos 再复制成一个新的聊天前台,也不是把主体框架塞进每个外部设备里。它要解决的是另一类问题:当用户没有主动打开 chat / console / runner 时,主体当前在做什么、是否需要用户注意、是否需要用户给一个轻量回应,这些信息缺少一个持续可见、低打扰、可驻留的外显层。`L6-elves` 因此被定义为**主体框架在外部宿主中的驻留 companion 壳**:它负责把最小状态、轻提示、轻交互和主界面导流投影到桌面驻留宿主与可穿戴轻提示宿主,但不成为新的业务真相源。

### 1.2 业务驱动力

**业务驱动力**:
- 用户需要在不打开主界面的前提下,随时感知主体是否空闲、忙碌、等待、阻塞、完成或异常
- 用户需要一种低打扰存在体来承担提醒、陪伴与轻量回应,而不是每次都进入重交互界面
- 当事情变复杂时,系统必须把用户平滑导回正式产品面,而不是在设备侧继续堆叠复杂交互

**技术驱动力**:
- 需要把主体状态安全投影到不同宿主,同时保持统一语义边界,避免桌面与可穿戴行为漂移
- 需要把轻提示、轻输入、确认动作和导流升级收敛到共享核心,而不是在每个宿主各写一套逻辑
- 需要保证外部宿主只消费上游事件或投影,不持有 member / runtime / chat / account 真相
- 需要把提示投递、用户确认、导流升级和宿主故障统一留痕到 observability 链路

### 1.3 成功标准(可量化)

| 维度 | 指标 | 目标值 | 测量 |
|---|---|---|---|
| 边界 | 宿主范围遵循基础版边界 | 100% 仅 desktop + wearable light prompt | 文档评审 + 架构检查 |
| 一致性 | `ElfPresence` 仅使用六态最小集合 | 100% | 设计评审 |
| 导流 | 复杂场景仅导向 `chat / console / runner` | 100% | 架构评审 + E2E 设计用例 |
| 安全 | 不新增 member/runtime/account/chat 真相 | 100% | 边界检查 |
| 可观察性 | 轻提示、轻交互、导流链路可留痕 | 100% 主路径 | 审计设计评审 |
| 体验 | 用户能看状态、收提醒、做轻回应并升级回主界面 | 100% 基础版主路径 | E2E 设计验收 |

## 2. 约束条件

### 2.1 不可变约束

| 约束 | 来源 | 影响 |
|---|---|---|
| `L6-elves` 只做基础版 | `projects/L6-elves/00-需求文档.md` | 不能预埋完整多轮对话主面 |
| 宿主范围只包含桌面驻留宿主与可穿戴设备轻提示宿主 | `00-需求文档.md` §1/§3 | 宿主适配层不能扩写其他端 |
| `ElfPresence` 只允许 `idle / busy / waiting / blocked / done / error` | `00-需求文档.md` §3/§4 | 状态模型必须最小化 |
| 导流目标只允许 `chat / console / runner` | `00-需求文档.md` §3/§5 | 不得导向未定义外部入口 |
| `Elf ≠ Member` | `00-需求文档.md` §4 | 不得在 elves 中重建成员身份真相 |
| `Elf shell ≠ chat truth` | `00-需求文档.md` §4 | 不得把精灵写成新的会话真相面 |
| `Elf presence ≠ runtime truth` | `00-需求文档.md` §4 | 状态只能投影,不能反转为执行真相 |
| `Elf device binding ≠ account/member truth` | `00-需求文档.md` §4 | 设备绑定只能是局部宿主绑定事实 |
| `Elf prompt surface ≠ full conversation surface` | `00-需求文档.md` §4 | 轻输入不能退化成短会话入口 |
| `Elf action ≠ business orchestration` | `00-需求文档.md` §4 | 宿主动作不能越权承担业务编排 |
| 跨域只通过事件,不做跨域直 RPC / 共享事务 | `product/六域模型.md` §2.2 | elves 只能消费事件/投影,不能成为跨域真相拼装中心 |
| `chat / console / runner` 是 distinct product surfaces | `projects/L5-chat/01-架构设计.md` + `architecture/开发路线图与优先级.md` | 导流必须保持三者边界,不能混并 |

### 2.2 可变约束

| 约束 | 当前值 | 可调整空间 |
|---|---|---|
| 桌面驻留技术壳 | 未定 | 可在 Tauri / 其他桌面壳间择一 |
| 可穿戴提示接入方式 | 轻提示优先 | 可后续细化通知协议 |
| 提示投递策略 | 低打扰优先 | 可按宿主增加节流与静音策略 |
| 设备绑定存储方式 | 本地/服务端候选 | 只要不突破真相边界可调整 |
| 导流触发阈值 | 规则式优先 | 可后续增强为更细粒度策略 |

### 2.3 容量规划

| 资源 | 上限 | 量化依据 |
|---|---|---|
| 宿主类型 | 2 | 基础版硬边界 |
| 状态集合 | 6 | `00-需求文档.md` 固定范围 |
| 导流目标 | 3 | `00-需求文档.md` 固定范围 |
| 轻输入类型 | 3 类 | 简短文本 / 确认取消忽略 / 唤醒入口 |

## 3. 架构风格与选型

### 3.1 变化维度识别

| 维度 | 变化频率 | 应对策略 |
|---|---|---|
| 宿主呈现差异 | 高 | `per-host adapters` 隔离宿主差异 |
| 轻提示策略 | 中高 | `ElfNudge` 分类与策略从共享核心统一管理 |
| 导流判定 | 中 | `diversion router` 统一裁决 |
| 轻交互输入种类 | 中 | `ElfPromptSurface` 最小化建模 |
| 状态投影来源 | 中 | `Presence Projection` 统一收敛 |

### 3.2 架构风格决策框架

**候选架构风格**:

| 风格 | 优势 | 劣势 | 适用性 |
|---|---|---|---|
| **shared elf core + per-host adapters**(当前) | 统一语义边界、宿主差异可隔离、便于基础版控边界 | 需要先定义共享核心 | ✅ |
| 每个宿主各写一套精灵逻辑 | 启动快 | 语义漂移、维护成本高、边界难统一 | ❌ |
| 把 chat 缩小后直接塞进宿主 | 复用主界面逻辑 | 会把精灵做成迷你 chat,突破边界 | ❌ |
| 让设备端本地自治承接复杂交互 | 宿主能力强 | 直接越过基础版定位和真相边界 | ❌ |

**最终选择**:**共享 elf 核心 + 宿主适配壳层 + 受控导流升级**

### 3.3 架构风格约束-收益分析

| 约束 | 收益 | 成本 |
|---|---|---|
| 共享核心统一状态/提示/导流语义 | 不同宿主不易漂移 | 需要先抽象最小公共能力 |
| 宿主只做适配层 | 能守住真相边界 | 某些宿主原生能力不能全量开放 |
| 复杂交互统一导回主产品面 | 保持产品边界清晰 | 宿主内体验故意不追求“全能” |
| 六态最小集合固定 | 状态表达稳定、可审计 | 不追求过细的设备侧语义 |

## 4. 系统边界与上下文

### 4.1 系统上下文图(C4 Context 级)

```text
users
  │
  ▼
external hosts
  ├─ desktop residency host
  └─ wearable light-prompt host
            │
            ▼
      ★ quantalithos-elves ★
      - presence projection
      - nudge delivery
      - light interaction gateway
      - diversion router
            │            │            │
            │            │            └────────▶ observability
            │            └────────────────────▶ chat / console / runner
            └─────────────────────────────────▶ upstream truth projections(events/sdk)
```

### 4.2 职责边界(做什么 / 不做什么)

**做什么**:
- ✅ 把主体框架的最小状态集合投影为用户可见的 `ElfPresence`
- ✅ 向桌面驻留宿主与可穿戴轻提示宿主投递低打扰提醒
- ✅ 承接一句短输入、确认/取消/忽略、唤醒入口等轻交互
- ✅ 在超出边界时把用户导回 `chat / console / runner`
- ✅ 对宿主侧提示、确认、导流和故障进行留痕

**不做什么**:
- ❌ 不持有 member / runtime / chat / account 的业务真相
- ❌ 不承载完整多轮复杂对话主面
- ❌ 不在设备侧继续执行完整业务主线
- ❌ 不做复杂自治决策或多设备复杂同步编排
- ❌ 不把宿主动作升级成业务编排入口

### 4.3 外部系统可用性约束

| 外部依赖 | SLA | 依赖风险 | 降级策略 |
|---|---|---|---|
| 上游状态投影 / SDK / 事件源 | 99.9% | 状态更新不及时 | 保留最近一次可见状态 + 标记 stale |
| `chat` | 99.9% | 无法导回协作主界面 | 明确提示稍后重试 |
| `console` | 99.9% | 管理导流失败 | 回退到可见状态 + 重试入口 |
| `runner` | 99.9% | 执行入口导流失败 | 提示稍后在主界面继续 |
| observability | 99.95% | 宿主交互留痕失败 | 本地暂存 / 延迟补发 |

### 4.4 关键依赖风险

- 如果把宿主差异直接泄漏到核心逻辑,桌面与可穿戴会快速演化成两套产品
- 如果把 `ElfPresence` 写成 runtime 真状态,会破坏上游真相边界
- 如果把轻输入持续扩写,`ElfPromptSurface` 会滑向完整 conversation surface
- 如果导流目标不收口,elves 会退化成任意入口跳板,破坏主产品面边界

## 5. 限界上下文与子域划分

### 5.1 子域分类

| 子域 | 分类 | 说明 |
|---|---|---|
| Presence Projection | 核心域 | 把上游状态投影为六态 `ElfPresence` |
| Nudge Delivery | 核心域 | 轻提示分类、低打扰投递与投递结果 |
| Light Interaction Gateway | 核心域 | 轻输入、本地承接、升级导流判定 |
| Host Adaptation | 支撑子域 | desktop / wearable 宿主差异适配 |
| Binding | 支撑子域 | `ElfDeviceBinding` 与宿主绑定关系 |
| Audit / Observability Integration | 支撑子域 | 提示、交互、导流、错误留痕 |

### 5.2 限界上下文划分与职责

| 上下文 | 职责 | 核心对象 |
|---|---|---|
| Presence Projection | 统一状态投影、去抖、过期处理 | `ElfPresenceView` |
| Nudge Delivery | 提示分类、节流、静音、投递确认 | `ElfNudge` / `NudgePolicy` |
| Light Interaction Gateway | 处理一句短输入、确认/取消/忽略、唤醒动作 | `ElfPromptSurface` / `ElfAction` |
| Host Adaptation | 把核心语义映射到桌面或可穿戴宿主能力 | `DesktopShellAdapter` / `WearablePromptAdapter` |
| Binding | 维护设备绑定局部事实 | `ElfDeviceBinding` |
| Audit | 输出宿主交互与故障链路审计记录 | `ElfAuditRecord` |

### 5.3 上下文映射关系

- 上游主体状态投影 → Presence Projection: **Conformist + Projection**，elves 只遵从和投影上游事实
- Presence Projection → Nudge Delivery: **状态驱动提示**,由状态变化决定是否产生提示
- Light Interaction Gateway → `chat / console / runner`: **Guarded Diversion**，复杂交互不在本地继续承接
- Host Adaptation ↔ 共享核心: **Adapter**，宿主私有能力不反向污染核心语义
- Audit ← 所有宿主交互: **append-only observability projection**

### 5.4 统一语言词汇表

| 术语 | 定义 | 使用场景 |
|---|---|---|
| ElfPresence | 面向用户可见的六态最小状态投影 | Presence Projection |
| ElfNudge | 发给用户的低打扰轻提示 | Nudge Delivery |
| ElfPromptSurface | 精灵开放的最小输入面 | Light Interaction Gateway |
| ElfAction | 精灵可直接承接的一次轻交互动作 | Light Interaction Gateway |
| ElfDeviceBinding | 精灵与宿主设备的局部绑定关系 | Binding |
| Diversion Router | 把复杂交互导回正式产品面的受控升级器 | Diversion |
| Host Adapter | 负责把共享核心映射到具体宿主的适配层 | Host Adaptation |

## 6. 容器/部署架构

### 6.1 容器图(C4 Container 级)

```text
external hosts
  ├─ desktop residency adapter
  └─ wearable light-prompt adapter
             │
             ▼
        shared elf core
        ├─ presence projection
        ├─ nudge delivery
        ├─ light interaction gateway
        ├─ diversion router
        └─ binding manager
             │          │          │
             │          │          └────────▶ observability sink
             │          └──────────────────▶ chat / console / runner
             └─────────────────────────────▶ upstream event/sdk projections
```

### 6.2 每个容器的职责与技术栈

| 容器 / 进程 | 职责 | 技术栈 | 资源要求 |
|---|---|---|---|
| shared elf core | 统一状态、提示、轻交互、导流裁决 | 待定 | 逻辑核心 |
| desktop residency adapter | 桌面驻留、状态区、轻提示、主界面唤起 | 待定 | 宿主特化 |
| wearable light-prompt adapter | 可穿戴轻提示、轻确认、唤醒入口 | 待定 | 宿主特化 |
| observability sink adapter | 宿主交互与故障留痕 | 复用平台能力 | 追加写入 |

### 6.3 通信方式与数据存储归属

| 通信 / 数据 | 方向 | 方式 | 归属 |
|---|---|---|---|
| 上游状态投影 | 上游 → shared elf core | 事件 / SDK 投影 | 上游真相 |
| 轻提示下发 | shared elf core → host adapters | 本地调用 / 宿主协议 | elves 投影行为 |
| 轻交互回收 | host adapters → shared elf core | 本地事件 | elves 局部行为 |
| 导流升级 | shared elf core → chat/console/runner | 受控唤起 / 跳转 | 正式产品面 |
| 交互留痕 | shared elf core → observability | 追加写入 | observability |
| 设备绑定局部事实 | host adapters / core | 本地或服务端绑定记录 | elves 局部绑定事实 |

### 6.4 部署拓扑

- 桌面驻留宿主与可穿戴轻提示宿主都只承载壳层与共享核心,不承载业务真相
- 基础版不要求多宿主复杂联动拓扑
- 基础版允许按宿主分别灰度,不要求一次性全宿主齐发

## 7. 依赖方向与层间约束

### 7.1 依赖方向图

```text
host adapters
    │
    ▼
shared elf core
    ├─▶ upstream event/sdk projections
    ├─▶ chat / console / runner
    └─▶ observability
```

### 7.2 层间约束规则

| 规则 | 说明 |
|---|---|
| 宿主适配层不得推断新的业务真相 | host adapter 只能消费共享核心给出的语义 |
| 共享核心不得越过投影边界去声明 runtime/member/account 真相 | 只可处理外显投影与宿主交互 |
| 导流路由层不得开放未定义目标 | 只允许 `chat / console / runner` |
| 轻交互层不得扩写为完整对话层 | `ElfPromptSurface` 只承接最小输入面 |
| 绑定层不得演化为身份系统 | `ElfDeviceBinding` 不是 account/member truth |
| 审计输出必须 append-only | 宿主行为只能补发,不能重写历史 |

### 7.3 依赖倒置的接口点

- `PresenceSourcePort`: 抽象上游状态投影输入
- `HostAdapterPort`: 抽象桌面与可穿戴宿主输出能力
- `DiversionPort`: 抽象 `chat / console / runner` 的导流接口
- `AuditPort`: 抽象 observability 留痕输出

## 8. 数据所有权与一致性策略

### 8.1 数据所有权矩阵

| 数据 | 类型 | 写入方 | 读取方 | 说明 |
|---|---|---|---|---|
| `ElfPresence` | 投影态 | shared elf core | hosts / users | 不是 runtime 真相 |
| `ElfNudge` | 提示投影 | shared elf core | hosts / users | 基于状态与规则生成 |
| `ElfPromptSurface` 输入 | 宿主输入记录 | host adapters | shared elf core | 不是 conversation 真相 |
| `ElfAction` 结果 | 宿主交互记录 | shared elf core | observability / hosts | 只代表轻交互结果 |
| `ElfDeviceBinding` | 局部绑定事实 | binding layer | shared elf core / adapters | 不是 account/member truth |
| 导流结果 | 交互记录 | diversion router | observability | 正式界面才承载后续真相 |

### 8.2 一致性层次

| 层次 | 策略 | 说明 |
|---|---|---|
| elves 内局部状态 | 强一致 | 同一宿主内的提示、交互、导流裁决保持一致 |
| elves 与上游状态真相 | 最终一致 | `ElfPresence` 允许短暂滞后 |
| elves 与正式产品面 | 最终一致 | 导流成功后由正式产品面继续承接真相 |
| elves 与 observability | 追加式最终一致 | 写失败可补发,不重写历史 |

### 8.3 补偿机制设计

| 场景 | 补偿 |
|---|---|
| 上游状态更新延迟 | 保留最近一次状态并标记 stale |
| 提示投递失败 | 重试或降级为被动可见状态 |
| 宿主离线 | 暂停主动提醒,恢复后按策略补发 |
| 导流失败 | 回退为明确可见的“打开主界面失败,请稍后重试” |
| 审计写入失败 | 本地暂存,稍后补发 |

---

## 9. 关键技术选型

### 9.1 决策四元组

| 主题 | 当前选择 | 备选 | 理由 | 演进路径 |
|---|---|---|---|---|
| 总体结构 | shared elf core + per-host adapters | 每宿主独立实现 | 统一语义边界最重要 | 后续可增加更多 host adapter |
| 状态模型 | 六态最小投影 | 更细状态机 | 基础版要先写死边界 | 概要设计再细化映射规则 |
| 交互升级 | diversion-first | 宿主内继续深承接 | 保持主产品面边界 | 后续仍只在受控范围增强 |
| 输入面 | minimal prompt surface | 设备侧短会话 | 防止滑向完整聊天面 | 后续只细化动作,不扩 full surface |
| 绑定模型 | device-local binding fact | account/member truth binding | 保住身份边界 | 后续可增强绑定治理,不改真相归属 |

### 9.2 不可逆程度评估

| 决策 | 不可逆程度 | 说明 |
|---|---|---|
| 共享核心 + 宿主适配层 | 中高 | 决定后续演进骨架 |
| 六态最小集合 | 中 | 会直接影响上游投影与宿主语义 |
| 只导流到 `chat / console / runner` | 中 | 决定主产品边界 |
| 设备绑定不进入身份真相 | 高 | 这是领域边界决策 |

## 10. 备选方案与取舍

### 10.1 方案对比

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| 方案 A: shared elf core + per-host adapters | 语义统一、边界清晰、宿主差异可隔离 | 需要先定义共享核心 | ✅ 采用 |
| 方案 B: 每宿主独立 companion | 实现快、宿主自由度高 | 语义漂移,重复实现,边界失控 | ❌ |
| 方案 C: 直接把 chat 缩小塞进宿主 | 复用部分交互模型 | 违反 `Elf shell ≠ chat truth` | ❌ |
| 方案 D: 设备侧自治执行 | 宿主能力强 | 违反基础版与业务编排边界 | ❌ |

### 10.2 选择理由

- `L6-elves` 当前最重要的不是功能多,而是边界硬
- 基础版要优先保证“精灵是 companion 壳,不是另一个主体入口”
- 因此最少约束且最能守住边界的方案,就是共享核心统一语义,宿主适配层只负责外显与接入差异

## 11. 横切关注点

### 11.1 韧性

| 项目 | 策略 |
|---|---|
| 状态投影失败 | 保留最近一次可见状态 |
| 提示失败 | 重试 / 降级为被动可见 |
| 宿主离线 | 暂停主动提醒,恢复后补发 |
| 导流失败 | 显式失败提示 + 重试入口 |
| 宿主能力不足 | 降级为状态显示 + 唤起主界面 |

### 11.2 可观测性

- 提示投递必须留痕
- 用户确认 / 取消 / 忽略必须留痕
- 导流目标、导流成功/失败必须留痕
- 宿主离线、静音、关闭等关键状态必须留痕

### 11.3 安全

- 不越权承接业务编排
- 不泄露 member / runtime / chat / account 真相
- 设备绑定信息按最小必要暴露
- 宿主提示内容按最小必要外显

### 11.4 配置管理

- 支持宿主开关
- 支持静音 / 关闭
- 支持提示节流
- 支持桌面与可穿戴各自的最小化策略配置

### 11.5 性能预算表

| 环节 | 预算 | 说明 |
|---|---|---|
| 上游状态投影进入 shared elf core | < 200ms | 保证状态外显及时 |
| shared elf core 生成提示策略 | < 100ms | 低打扰提示不可显著滞后 |
| 宿主投递提示 | < 300ms | 保证提醒有效性 |
| 导流升级响应 | < 500ms | 复杂场景要尽快回主界面 |

## 12. 演进路线

### 12.1 当前架构状态与已知债务

- 当前仅完成 `00-需求文档.md` 收口
- `01-架构设计.md` 首版只锁定基础版骨架,不追求详细实现策略
- 宿主技术壳、投影接入协议、静音策略等仍属于后续概要设计细化项

### 12.2 演进触发条件

| 触发条件 | 演进方向 |
|---|---|
| 桌面宿主稳定并通过主路径验收 | 补强桌面驻留体验 |
| 可穿戴轻提示主路径成立 | 补强轻确认与恢复策略 |
| 提示种类增多 | 强化 `ElfNudge` 分类与节流 |
| 导流失败或误导流率过高 | 强化导流判定与回退策略 |

### 12.3 演进步骤

1. **阶段 1**:桌面驻留宿主 + 可穿戴轻提示宿主最小闭环
2. **阶段 2**:轻交互稳定化,完善静音/关闭/恢复
3. **阶段 3**:在不突破基础版边界的前提下细化提示策略与宿主适配能力

### 12.4 目标架构

目标不是把 elves 做成新的前台,而是在多个外部宿主中维持同一套 companion 壳语义:最小状态可见、轻提示可达、轻交互可控、复杂交互可升级回正式产品面。

## 14. 上线策略

### 14.1 灰度方案

- 先灰度桌面驻留宿主
- 再灰度可穿戴轻提示宿主
- 每类宿主都允许单独开关与单独回退

### 14.2 回滚策略

- 关闭某个宿主适配层
- 关闭主动提醒,保留被动可见状态
- 必要时仅保留唤起主界面入口,暂停轻交互

### 14.3 监控指标

| 指标 | 说明 |
|---|---|
| 状态投影成功率 | 六态外显是否持续可用 |
| 提示投递成功率 | 主动提醒是否稳定 |
| 误导流率 | 是否把本可轻承接的动作错误升级 |
| 导流失败率 | 导回正式产品面的可靠性 |
| 宿主静音/关闭比率 | 是否出现打扰过强迹象 |

### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`
   - 抽取:主要部分、主流程、状态机、非法转换、事件、错误语义、最小可运行闭环
2. **再识别测试对象**
   - 分清对象级、函数级、流程级、边界级、事件级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 elves“会显示状态”或“会弹一个提示”,而是系统验证 `L6-elves` 是否真正满足“外部宿主 companion 层”的设计要求,尤其要证明以下几点成立:
- `ElfPresence` / `ElfNudge` / `ElfPromptSurface` / `ElfAction` / `ElfDeviceBinding` / `GuardedDiversion` 构成正式 elves 层真相
- `Elf ≠ Member`、`Elf shell ≠ chat truth`、`Elf presence ≠ runtime truth`、`Elf device binding ≠ account/member truth`、`Elf prompt surface ≠ full conversation surface`、`Elf action ≠ business orchestration` 等核心边界成立
- 状态投影、轻提示、轻交互、宿主适配、受控导流五条主链可以统一组织,并且 source refs 持续可追溯
- desktop residency host 与 wearable light-prompt host 只在承载方式上不同,不改变同一 source ref 的语义状态
- prompt / action / diversion 只表达本地最小交互、升级入口和宿主侧结果,不会误导用户认为 source action 已成功完成
- stale / suppressed / degraded / diverted / failed 等非 happy path 结果有统一语义,并且 replay / reconnect / backfill 只修复投影和 evidence,不改写真相

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 状态投影与存在外显部分 | presence 对象 | P0 | `ElfPresence`、`PresenceSourceRef`、`PresenceProjectionRule`、`ElfPresenceView` |
| 轻提示与低打扰投递部分 | nudge 对象 | P0 | `ElfNudge`、`NudgeIntent`、`NudgePolicy`、`NudgeOutcome`、`NudgeHistoryView` |
| 轻交互承接与最小输入面部分 | prompt/action 对象 | P0 | `ElfPromptSurface`、`PromptInputDraft`、`ElfAction`、`ElfActionResult` |
| 宿主适配与设备绑定部分 | host/binding 对象 | P0 | `DesktopResidencyAdapter`、`WearableLightPromptAdapter`、`ElfDeviceBinding`、`BindingView` |
| 受控导流与外部可见状态部分 | diversion/evidence 对象 | P0 | `GuardedDiversion`、`DiversionOutcome`、`ElfVisibleOutcome`、`BehaviorEvidenceRecord` |
| member / runtime / chat / account 真相本体 | 非范围 | P2 | 只验 elves 如何消费或导流其结果,不验 source truth 全部实现 |
| 宿主协议底层实现、未来态多设备复杂同步 | 非范围 | P2 | 只验基础版宿主 companion 主线,不验未来态生态能力 |
| 任意外部跳转与复杂自治编排 | 非范围 | P2 | 只验 `chat / console / runner` guarded diversion,不验未定义目标 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / product owner | `presence.validate_presence_source_boundary`、`presence.validate_state_enum`、`prompt.validate_prompt_surface_boundary`、`binding.validate_binding_boundary`、`diversion.validate_target_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + adapter + publisher + projection 联动 | backend / product owner | `ProjectElfPresence`、`PlanElfNudge`、`DispatchElfNudge`、`OpenPromptSurface`、`HandleElfAction`、`BindElfDevice`、`TriggerGuardedDiversion` | presence、nudge、prompt、binding、diversion 五条主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | upstream projection → desktop/wearable、elves → `chat/console/runner`、elves → observability | 输入输出语义一致 |
| 恢复专项测试 | 验证 stale、suppression、binding drift、host offline、diversion fail、evidence backlog 等异常链 | architecture / QA | stale state、suppressed nudge、expired prompt、binding revoked、diversion fail、backfill evidence | companion 体验不误导、错误被正确阻断或标记 |
| 投影一致性测试 | 验证 desktop/wearable/visible outcome/history 与 source refs 一致 | backend / QA | presence view rebuild、nudge history rebuild、prompt view rebuild、binding view rebuild、visible outcome rebuild | 投影只读且与 source refs 一致 |
| 端到端主线测试 | 验证最小 elves companion 闭环 | QA / owner | bind host → externalize state → show nudge → minimal action → divert → archive evidence | elves 基础版闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `Elf ≠ Member` | elf shell/device binding 只能消费或引用 member 结果,不持有成员真相 | 单元 + 集成测试 | 是 | binding/member compare |
| `Elf shell ≠ chat truth` | elf shell 只展示最小状态与交互,不得替代 chat 正式真相 | 单元 + 集成测试 | 是 | shell/chat compare |
| `Elf presence ≠ runtime truth` | presence 只投影 runtime/source 结果,不冒充执行真相 | 单元 + 集成测试 | 是 | presence/runtime compare |
| `Elf device binding ≠ account/member truth` | 绑定只表达宿主局部事实,不等于身份绑定 | 单元 + 集成测试 | 是 | binding/account compare |
| `Elf prompt surface ≠ full conversation surface` | prompt 只承接最小动作,不得变成 mini-chat | 单元 + 集成测试 | 是 | prompt/conversation compare |
| `Elf action ≠ business orchestration` | action 只表达本地交互或导流入口,不等于业务执行完成 | 单元 + 事件链测试 | 是 | action/result compare |
| 六态最小状态集合固定 | 外显状态只能是 `idle / busy / waiting / blocked / done / error` | 单元 + 集成测试 | 是 | state enum compare |
| desktop / wearable 语义一致 | 同一 source ref 在两类宿主显示的语义状态一致 | 集成 + 投影一致性测试 | 是 | cross-host compare |
| guarded diversion 只允许 `chat / console / runner` | 超界动作只能升级到三个正式承接面 | 单元 + 集成测试 | 是 | diversion target compare |
| diversion triggered ≠ diversion completed | 已触发导流不得被误展示为已完成 | 集成 + 恢复专项测试 | 是 | handoff receipt compare |
| append-only evidence 可回指 source refs | 所有宿主侧行为记录和 evidence 都可追溯 | 集成 + 投影一致性测试 | 是 | history/source refs compare |

## 10. 缺陷管理与异常升级

| 严重级别 | 定义 | 处理要求 |
|---|---|---|
| S | 任一 truth boundary 被破坏 / 任一非法状态越界 / 任一 source truth 被 elves 流程反写 / diversion 被误展示为完成 / prompt surface 滑向 full conversation surface |
| A | 主线可跑但 stale/lag/reconnect/diversion/evidence 一致性不稳 |
| B | 非关键展示细节、次要 explain copy 或低优先级历史展示异常 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 presence / freshness / stale 逻辑,都必须回归六态映射与 source refs 主线
- 每次改动 nudge / suppression / delivery,都必须回归低打扰策略与 outcome 主线
- 每次改动 prompt / action / guard,都必须回归最小输入面与 orchestration 边界主线
- 每次改动 desktop / wearable adapters 或 binding lifecycle,都必须回归 cross-host 语义一致性主线
- 每次改动 diversion / evidence / backfill,都必须回归 triggered vs completed、append-only history 与 source refs 主线

### 11.2 残余风险

| 风险 | 影响 | 接受人 |
|---|---|---|
| 未来态更多宿主或多设备编排加入 | 验收矩阵需扩充 | TL / 架构 |
| 可穿戴宿主能力继续演进 | prompt / host capability 验收需增加更多样本 | elves / device side |
| observability/evidence 需求增长 | history/backfill/trace 验收需扩充 | platform / observability |

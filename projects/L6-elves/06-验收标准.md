## 1. 验收背景与范围

### 1.1 验收背景

`L6-elves` 的本次验收目标,不是证明“宿主上能看到一个状态”或“会弹一个轻提示”,而是系统验证基础版 `L6-elves` 是否真正成立为**外部宿主 companion 层**。本次验收必须证明:
- `ElfPresence` / `ElfNudge` / `ElfPromptSurface` / `ElfAction` / `ElfDeviceBinding` / `GuardedDiversion` 构成正式 elves 层真相
- `Elf ≠ Member`、`Elf shell ≠ chat truth`、`Elf presence ≠ runtime truth`、`Elf device binding ≠ account/member truth`、`Elf prompt surface ≠ full conversation surface`、`Elf action ≠ business orchestration` 六条硬边界全部成立
- 状态投影、轻提示、轻交互、宿主适配、受控导流五段主链全部闭环
- `desktop residency host` 与 `wearable light-prompt host` 只在承载方式上不同,不改变同一 source ref 的语义状态
- `chat / console / runner` 的 guarded diversion 始终受控,并严格满足 `triggered != completed`

### 1.2 验收范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 状态投影与存在外显部分 | presence 主链 | P0 | `ElfPresence`、六态外显、stale/freshness |
| 轻提示与低打扰投递部分 | nudge 主链 | P0 | `ElfNudge`、suppressed/degraded/delivered |
| 轻交互承接与最小输入面部分 | prompt/action 主链 | P0 | `ElfPromptSurface`、`ElfAction`、最小动作集合 |
| 宿主适配与设备绑定部分 | host/binding 主链 | P0 | desktop / wearable adapters、`ElfDeviceBinding` |
| 受控导流与外部可见状态部分 | diversion/evidence 主链 | P0 | `GuardedDiversion`、`ElfVisibleOutcome`、`BehaviorEvidenceRecord` |
| member / runtime / chat / account source truth 本体 | 非范围 | P2 | 只验 elves 如何消费/导流其结果,不验 source truth 全部实现 |
| 完整 chat surface / 完整 runtime orchestration / 多设备复杂同步 | 非范围 | P2 | 只验基础版 companion 主线 |
| 本体宿主协议实现与未来态宿主扩展能力 | 非范围 | P2 | 只验当前基础版宿主边界 |

## 4. 功能验收门禁

### 4.1 状态投影与存在外显门禁

| 门禁项 | 通过条件 | 证据 | 不通过条件 |
|---|---|---|---|
| 六态最小集合 | 外显状态仅允许 `idle / busy / waiting / blocked / done / error` | state enum compare | 出现六态外状态仍被外显 |
| presence 投影边界 | `ElfPresence` 只消费 source projection,不冒充 runtime truth | presence/runtime compare | `ElfPresence ≠ runtime truth` 被破坏 |
| stale 可见性 | stale / source missing 时明确标记,不伪造 fresh | stale marker logs / screenshots | stale 状态被静默隐藏或伪装为 fresh |
| 双宿主语义一致 | desktop / wearable 对同一 source ref 语义一致 | cross-host compare | 同一 source ref 两宿主显示不同语义状态 |

### 4.2 轻提示与低打扰投递门禁

| 门禁项 | 通过条件 | 证据 | 不通过条件 |
|---|---|---|---|
| nudge 正式分类 | `delivered / failed / suppressed / degraded` 明确区分 | nudge history logs | 结果语义混并 |
| suppression 留痕 | suppress / mute / throttle 都有正式记录 | suppression records | suppressed 被静默吞掉 |
| 低打扰不误导 | 提示送达不被误当作业务完成 | action/result compare | delivered 被展示为 source 完成 |
| 主链完整性 | waiting/blocked/done/error 提示链稳定成立 | nudge planning / dispatch / outcome logs | 高价值状态不触发正式提示链 |

### 4.3 轻交互承接与最小输入面门禁

| 门禁项 | 通过条件 | 证据 | 不通过条件 |
|---|---|---|---|
| 最小动作集合 | 仅支持一句短输入、确认/取消/忽略、唤醒 | prompt/action compare | 出现 full conversation / 附件 / 多轮上下文承接 |
| prompt 边界 | `ElfPromptSurface` 始终是最小输入面,不是 mini-chat | prompt/conversation compare | `Elf prompt surface ≠ full conversation surface` 被破坏 |
| action 语义 | handled / rejected / diverted / failed 明确区分 | action trace | dismiss/ack 被误当业务完成 |
| orchestration 边界 | `ElfAction` 不直接承担业务编排 | action/result compare | `Elf action ≠ business orchestration` 被破坏 |

### 4.4 宿主适配与设备绑定门禁

| 门禁项 | 通过条件 | 证据 | 不通过条件 |
|---|---|---|---|
| shared core 语义一致 | desktop / wearable 只改承载方式,不改语义 | cross-host compare | host adapter 发明新状态词表或治理语义 |
| binding 局部事实 | `ElfDeviceBinding` 只表达宿主局部绑定 | binding/account compare | `Elf device binding ≠ account/member truth` 被破坏 |
| degraded / revoked / offline | 宿主异常时正确拒绝或降级 | host fault logs | revoked / offline 后仍继续主线 |
| capability 降级正确性 | capability 不足时退化到最小可见状态或唤起入口 | host capability logs | capability 不足仍声称支持完整动作 |

### 4.5 受控导流与外部可见状态门禁

| 门禁项 | 通过条件 | 证据 | 不通过条件 |
|---|---|---|---|
| 导流目标收口 | 只允许 `chat / console / runner` | diversion target compare | 出现任意其他导流目标 |
| triggered != completed | 没有 receipt 时不得展示 completed | handoff receipts / compare | triggered 被误展示为 completed |
| visible outcome / evidence 分离 | `ElfVisibleOutcome` 与 `BehaviorEvidenceRecord` 分别成立 | outcome/evidence compare | 两者混成单一对象或语义 |
| 导流失败处理 | diversion fail 时只能报失败/稍后重试,不得继续复杂交互 | failure trace / screenshots | fail 后 elves 内继续承接复杂主业务 |

## 5. 非功能验收门禁

| 维度 | 通过条件 | 证据 | 阈值 / 不通过条件 |
|---|---|---|---|
| 一致性 | desktop / wearable 语义一致率达标 | cross-host compare | 100% 样本链,否则不通过 |
| 延迟 | presence externalization / nudge planning / diversion 响应满足 03 预算 | benchmark / trace | 任一关键链显著超预算则不通过 |
| 可理解性 | stale / suppressed / degraded / diverted 解释完整 | UX review / compare | 100% 样本链 |
| 可恢复性 | reconnect / replay / backfill 后 companion 主线恢复 | replay/reconnect logs | 100% 样本链 |
| 可追溯性 | presence/prompt/diversion/evidence 可回指 source refs | refs compare | 100% |
| 安全/治理 | 红线误突破成功率为 0 | negative flow | >0 直接不通过 |

## 6. 三红线验收门禁

### 6.1 可审计性

必须通过:
- 状态、提示、动作、导流、恢复和故障都有 append-only evidence
- 所有 P0 高风险链路都有正式归档证据

不通过:
- 关键宿主行为没有 evidence
- history 可被重写或无法留存

### 6.2 可追溯性

必须通过:
- 任一可见状态、提示、导流结果都能回指 source refs
- 任一 handoff / recovery / backfill 都可回溯链路来源

不通过:
- source refs 无法重建
- visible result 无法对账到 source refs

### 6.3 可裁剪性

必须通过:
- desktop / wearable、提示策略、导流策略、binding 策略可分层关闭或降级
- 某一宿主异常不会把整体 companion 主线耦死

不通过:
- 两类宿主被写成一个不可拆整体
- 关闭某策略会导致其他主链失控

## 7. 安全与治理门禁

以下任一失败,直接一票否决:
- `Elf ≠ Member` 被破坏
- `Elf shell ≠ chat truth` 被破坏
- `Elf presence ≠ runtime truth` 被破坏
- `Elf device binding ≠ account/member truth` 被破坏
- `Elf prompt surface ≠ full conversation surface` 被破坏
- `Elf action ≠ business orchestration` 被破坏
- `triggered != completed` 被破坏
- append-only evidence 断裂
- source refs traceability 缺失
- replay/reconnect/backfill 改写 source truth

## 8. 缺陷分级与放行规则

| 等级 | 定义 | 放行语义 |
|---|---|---|
| S | 任一 truth boundary 被破坏 / 任一非法状态越界 / 任一 source truth 被 elves 流程反写 / diversion 被误展示为 completed / prompt surface 滑向 full conversation surface | 直接不通过 |
| A | 主线可跑,但 stale/lag/reconnect/diversion/evidence 一致性不稳 | 仅在签字接收且不破坏主链时可条件通过 |
| B | 非关键展示细节异常 | 可带病放行,但需登记 |

### 放行规则

- **通过**:
  - 全部 P0 + 五段主链 + 三红线通过
  - 无 S 级缺陷
  - 证据齐全
- **有条件通过**:
  - 无 S 级缺陷
  - 存在已签字接收的 A/B 级遗留
  - 不影响主链、不影响红线、不改变基础版范围
- **不通过**:
  - 任一主链失败
  - 任一红线破坏
  - 任一关键证据缺失
  - 任一 S 级缺陷残留

## 9. 风险接受与遗留项

### 可接受遗留项

仅允许以下类型进入风险接受:
- 不破坏红线的 B 级展示细节问题
- 已明确 owner 和回归窗口的受控 A 级问题
- 不影响基础版范围、不改变五段主链语义的 explain copy / 低优先级历史展示问题

### 不可接受遗留项

以下任一不得进入条件放行:
- truth boundary 风险
- state semantics 风险
- guarded diversion 风险
- evidence traceability 缺口
- replay/reconnect/backfill 误改写 source truth 风险

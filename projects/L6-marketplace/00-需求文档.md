## 2. 本仓定位与边界

> 校准来源：[Step2定位边界](design-calibration/00_req_step_02_position_boundary.md)。延伸阅读其结构化产物、取舍与待确认事项。

| 字段 | 内容 |
|---|---|
| 一句话定义 | L6-marketplace是引用驱动的生态资产发布、目录上架与分发局部事实边界。 |
| 本仓不是什么 | 它不是资产正文仓、注册中心、审批系统、身份认证系统、安装执行器或财务账本。 |
| 边界对象列表 | 仓：method-library、capability-hub、member-images、Artifact、Governance、Identity；能力：认证、安装激活、Billing。 |
| 单独成仓原因 | 跨资产owner的市场事实需要独立且一致的责任主语，不能合并到某一内容owner。 |

市场上架与owner资产正式化是不同事实，分发关系与接收系统激活也是不同事实。独立市场边界组织共同生态体验，同时避免方法目录、能力注册、治理决定与市场状态混为一套真相。

## 3. 背景与问题定义

> 校准来源：[Step3问题背景](design-calibration/00_req_step_03_problem_context.md)。延伸阅读其问题分类、回填草稿与数据依据边界。

Quantalithos希望社区、组织与第三方复用沉淀的方法、能力与成员镜像。资产来源跨越多个领域，生态市场主题需要形成一致的需求语言，否则可信发布与后续责任难以界定。

| 问题 | 当前表现 | 影响范围/后果 |
|---|---|---|
| 跨类型资产市场责任未一致收束 | owner正式化、上架与分发接收混用“发布” | 无法判断来源版本与当前可获取性 |
| 可信发布前置资格不完整 | publisher验证、审核绑定、材料适用合同有缺口 | 内容及合规责任可能被界面或扫描替代 |
| 撤回与外部交接结果不明确 | 影响关系、通知送达、未知接收与恢复权限未统一 | 用户与维护者无法判断风险是否已处理 |

| 类型 | 内容 |
|---|---|
| 业务问题 | 生态复用的可信来源、发布责任与撤回影响难以统一理解。 |
| 技术问题 | owner引用、版本、可见性、正式决定及交接状态的语义边界尚不完整。 |

当前没有现网用户研究、访问量、成功率或性能测量，不给虚构量化数字。

## 4. 目标与非目标

> 校准来源：[Step4目标范围](design-calibration/00_req_step_04_goals_non_goals.md)。延伸阅读其目标/非目标表与范围收束。

| 目标 | 说明 | 验证方式 |
|---|---|---|
| G-MP-1 市场责任唯一 | 市场事实不替代外部真相 | 归属与负向边界审查 |
| G-MP-2 可信上架 | publisher、owner引用、材料及正式决定共同约束上架 | 有效绑定与缺失/过期/错版本情景 |
| G-MP-3 可见发现与版本选择 | 区分五类标签、市场版本与来源版本 | 可见/受限/撤回/无版本情景 |
| G-MP-4 受控分发 | 关系与接收结果清楚，不虚构安装/支付 | 重复/失败/未知/确认情景 |
| G-MP-5 撤回责任与恢复 | 停新分发、已知影响、通知与失败可追溯 | 并发撤回/重试/未知/恢复情景 |

| 非目标 | 不做原因 |
|---|---|
| NG-MP-1 资产正文/版本链/Registry | 对应资产及Artifact owner拥有 |
| NG-MP-2 批准、认证与授权真相 | Governance及正式安全owner拥有；publisher验证owner尚缺 |
| NG-MP-3 安装/成员创建/运行激活 | 接收系统拥有，ACK不证明激活 |
| NG-MP-4 Billing/支付/订阅/结算/分成/跨境交易 | 无正式owner，全部future/blocker，不建立局部财务账本 |
| NG-MP-5 无合同的Deployment Package执行/打包 | 包owner、29110适用及安装回退合同未闭合 |
| NG-MP-6 评分评论/推荐/持久收藏/高级统计 | 外围增强，不是核心可信发布分发前提 |

五类市场标签必须映射正式owner类型后才能开放正向发布。资产集合可关联已有版本引用，不因此获得可执行包正文所有权。局部entitlement仅指正式受控获取资格来源视图；当前无transaction写路径，不能推断付款/订阅或用免费降级绕过授权。

## 5. 用户与角色

> 校准来源：[Step5角色](design-calibration/00_req_step_05_users_roles.md)。延伸阅读其角色表、条件权限矩阵及authority边界。

| 角色 | 类型 | 使用场景 |
|---|---|---|
| 消费者 | 人类 | 可见资产评估、版本选择及获取状态查看 |
| 发布者 | 人类 | 自己负责的资产申请、版本及撤回责任 |
| 组织管理者 | 人类 | 组织范围资产发布、可见性与获取责任 |
| 审核协作者 | 人类 | 材料、缺口及正式决定的协作查看 |
| 市场维护者 | 人类 | 有依据的处置、失败恢复与通知跟进 |
| 审计者 | 人类 | 范围内来源、变化与交接记录审阅 |
| 系统调用者 | 系统 | 受控消费目录、版本与获取状态 |
| 集成执行者 | 系统 | 已声明owner结果交接，不产生外部结论 |
| 后台维护任务 | 系统 | 局部索引重建、对账与通知/交接重试 |

| 操作类型 | 消费者 | 发布者/组织管理者 | 审核协作者 | 市场维护者 | 审计者 | 系统角色 |
|---|---|---|---|---|---|---|
| 发现与读取 | 可见范围 | 可见范围 | 审核职责范围 | 受控范围 | 审计范围 | 已授予范围 |
| 发布申请 | 不允许 | 责任绑定且授权有效 | 不允许 | 不能冒充publisher | 不允许 | 明确代理责任时 |
| 治理批准 | 不允许 | 不允许 | 仅Governance正式职责 | 不允许 | 不允许 | 不允许本地推断 |
| 获取 | 授权及接收合同有效 | 同样受gate | 不因角色获权 | 不因角色获权 | 不因角色获权 | 正式consumer scope |
| 撤回/限制 | 不允许 | 有自己/组织范围依据 | 有正式治理依据 | 有处置依据 | 不允许 | 正式来源映射 |
| 重试/重建 | 不允许 | 查看自己的失败 | 查看相关缺口 | 有维护权限、不写外部truth | 只读 | 受控维护范围 |

职责角色不是RoleDefinition、Identity角色或认证凭证；publisher relation不产生主体/组织资质与权限。系统任务也不能豁免治理、可见性及摘要校验。无正式authority时相应写路径拒绝/等待。

## 7. 核心能力闭环

> 校准来源：[Step7核心闭环](design-calibration/00_req_step_07_core_capability_loop.md)。延伸阅读其能力进入/退出门槛及逐能力停审要求。

可信来源与发布责任、正式审核约束、可见发现与版本选择、受控分发、撤回影响与审计恢复必须共同成立。缺少分发只是目录，缺少治理或撤回责任则不是可信市场；审计、授权、幂等与失败边界贯穿所有能力。

```text
C-MP-1 可信来源与发布责任能够成立
  -> C-MP-2 受正式审核约束的市场上架能够成立
  -> C-MP-3 可见资产发现与明确版本选择能够成立
  -> C-MP-4 受控分发及可判别接收关系能够成立
  -> C-MP-5 撤回影响、通知与审计恢复责任能够成立
```

图只表达能力逻辑依赖，不表示接口、事件或实施时序。

| 分类 | 内容 |
|---|---|
| 核心能力闭环 | C-MP-1～5 |
| 外围增强 | 收藏、评论评分、推荐、高级统计、真实归档恢复与跨产品管理体验 |
| 边界外 | 外部正文/Registry、approval、身份/授权truth、安装运行、财务与无owner可执行包 |

| 节点 | 成立与停审条件 | 正向前置 |
|---|---|---|
| C1 | 来源、材料与发布责任可验证且不复制truth | MP-UP-001/003/004、MP-SRC-013 |
| C2 | 申请/审核交接/market version分离，有正式有效批准binding | MP-UP-002、MP-SRC-010/011 |
| C3 | 发现、详情、选择不绕scope、撤回或来源资格 | MP-UP-001/003 |
| C4 | 当前资格与exact版本/receiver匹配，分发/接收/安装分层 | MP-UP-005，正式安全来源 |
| C5 | 停新分发、已知影响、通知与审计恢复结果可判别 | MP-UP-007/008；归档future |

五类候选展示：方法资产、流程模板、角色定义归方法库；能力资产归能力池；成员镜像归member-images。展示标签不是正式owner枚举；文件格式/Artifact ref不自动获得上架资格。具体路径必须先qualified正式consumer合同。

## 10. 业务规则与边界约束

> 校准来源：[Step10规则审计](design-calibration/00_req_step_10_rules_boundary_constraints.md)。延伸阅读其truth source/失败姿态、状态主语审计与§8所链能力附录原规则。

|---|---|---|---|
| BR-MP-101 | 不变量 | owner类型/ref/version/digest/visibility/资格一致可核验；展示标签不自定义上游enum | 来源/FR101 |
| BR-MP-102 | 边界约束 | publisher relation不产生身份、组织认证或授权，系统actor不豁免scope | 责任/FR102 |

| BR-MP-104 | 显式变化 | 来源/材料/责任基线变更须重核验并保留旧依据，不覆盖已提交申请 | 基线/FR101～103 |
| BR-MP-201 | 治理约束 | 只有有效正式批准匹配申请/来源版本/材料/scope才可上架，豁免不默认等于批准 | review/version/FR202/203 |
| BR-MP-202 | 不变量 | submitted基线不能就地改成另一版本，修订需新依据与复审 | 申请/FR201/202 |
| BR-MP-203 | 显式变化 | listing/version上架、限制、撤回须有正式局部处置依据，查询不推进 | 市场状态/FR203 |
| BR-MP-204 | 禁止行为 | 不创建approval，ACK、材料齐备或摘要可读/fresh不构成批准 | handoff/FR202/203 |
| BR-MP-301 | 不变量 | 市场不能扩大owner/scope可见性；搜索/总数/提示/详情/历史均受约束 | 查询/FR301/302 |
| BR-MP-302 | 禁止行为 | 查询/索引不批准、上架、获取或修truth，不凭ref字符串推scope | 查询/FR301～303 |
| BR-MP-303 | 不变量 | 市场版本唯一绑定不可变owner版本，不静默替换用户选择 | 版本/FR303 |
| BR-MP-304 | 边界约束 | 市场分类/metadata不并进方法库或能力池，不伪造评分、预览或兼容结论 | 目录/FR301/302 |
| BR-MP-401 | 不变量 | 新分发按当前来源/权限/市场版本/未撤回资格再核验，UI选择或缓存不授权 | 获取/FR401/402 |

| BR-MP-403 | 不变量 | 同意图重复只一个局部关系与原结果，不同意图冲突；external unknown先对账 | 分发恢复/FR402/403 |
| BR-MP-404 | 禁止行为 | 无Billing owner不接受/推断paid/settled/subscribed；免费同样受授权 | entitlement/FR401 |

| BR-MP-502 | 不变量 | 影响仅来自已知关系/正式receiver来源，未知交接保守纳入，不声称全安装覆盖 | 影响/FR502 |
| BR-MP-503 | 禁止行为 | 计划/attempt/ACK不等送达/已读/已处置，不自动卸载或修改owner truth | 通知/FR502/504 |
| BR-MP-504 | 审计约束 | 关键变化/意图/基线/来源/结果/unknown可追溯，不伪造外部审计归档状态 | 追溯/FR503 |
| BR-MP-505 | 边界约束 | 恢复只修授权局部派生状态或推进有依据局部处理，不由索引造truth、不删历史、不修外部truth | 恢复/FR504 |

重新上架必须有新有效依据与显式处置，不能因来源恢复或通知重试自动复活旧批准/撤回版本。索引陈旧不等owner撤销；本地blocked不等Governance rejected。

### 一票否决项

- VETO-MP-1：复制外部truth/资产正文/credential或伪造来源资质。
- VETO-MP-2：本地生成/推断approval，或使用不匹配、失效决定上架。
- VETO-MP-3：以UI、public标签、缓存或索引绕scope/撤回门槛。
- VETO-MP-4：将获取/ACK当安装激活，或无财务authority造付款/订阅结果。
- VETO-MP-5：撤回后放行新分发，伪造通知/审计/恢复结果，篡历史或反写外部truth。

文档检查只证明引用和边界一致；原型fixtures只证明展示交互；未来fake只证明局部语义，不证明真实asset/digest/scan/signature/approval/payment/install/notice/audit。真实集成仅证明该run与scope，正式签核仍由其owner决定。当前没有evidence、verdict、risk acceptance或signoff。

## 2. 背景与问题定义

### 2.1 业务背景

Quantalithos 不只是一个内部闭环系统,还要成为一个可以沉淀和分发**方法资产、能力资产和运行资产**的平台。随着 ProcessTemplate、RoleDefinition、MCP Tool、Member 镜像和 Deployment Package 的积累,这些资产不能永远只待在单个组织内部或散落在文档、仓库和聊天记录里。L6-marketplace 的职责就是把这些资产变成可发布、可审核、可搜索、可购买、可安装、可撤销、可审计的市场化对象,并在生态扩张时保持合规与第三方治理边界。

### 2.2 现状与痛点(量化)

| 维度 | 当前状态(段 3 当前) | 痛点 |
|---|---|---|
| 仓文档 | 只有 README 骨架 | 段 3 收尾前最后一个生态层样板尚未建立 |
| 方法资产真相源 | `L3-method-library` 已完成 00/01 | 发布到市场的边界、审核与分发未仓级化 |
| 能力池真相源 | `L3-capability-hub` 已完成 00/01 | MCP Tool 集合如何上架未产品化 |
| Member 镜像资产 | `L2-member-images` 已完成 00/01 | Role+镜像资产上架与安全扫描边界未正式化 |
| 审核流 | README 已提出 marketplace-review Gate | 合规+内容共批的验收口径尚未成文 |

### 2.3 为什么要做(量化依据)

- `product/产品矩阵.md` 已把 Marketplace 定义为 **⑩ 独立生态产品**
- README 已明确 MK1~MK6，包括上架走 marketplace-review Gate、Deployment Package 格式、发布者身份验证、安装可审计、撤销通知与镜像扫描
- `L3-method-library` 已将 MethodPlugin / MethodConfiguration 设计为可分发资产,Marketplace 是这些资产的直接外部消费者
- 若没有 Marketplace,Quantalithos 的方法和能力积累难以形成社区与平台网络效应

### 2.4 业务问题 vs 技术问题

- **业务问题**:第三方和组织内部如何安全地共享、分发、购买与复用 Quantalithos 资产
- **技术问题**:资产包格式、上架审核、发布者身份、搜索/标签、购买/安装链路、撤销通知、镜像扫描签名、资产真相与市场展示分离

## 5. 核心用例与用户故事

### 5.1 核心用例

1. 发布者提交一个资产包进入上架审核流
2. 审核者通过 marketplace-review Gate 做合规+内容共批
3. 用户搜索、筛选并安装 ProcessTemplate / Role+镜像 / MCP Tool / Deployment Package
4. 发布者或管理员撤销上架并通知已安装用户
5. 平台对上架的镜像类资产做扫描与签名校验

### 5.2 用户故事卡片

| 字段 | 内容 |
|---|---|
| ID | US-001 |
| 用户故事 | 作为 **发布者**,我想要 **提交一个资产并进入 marketplace-review 审核**,以便 **在平台中安全、合规地发布我的模板或工具** |
| 优先级 | P0 |
| 验收条件 | **Given** 资产包完整且发布者身份有效 **When** 提交上架 **Then** 资产进入 marketplace-review Gate |

| 字段 | 内容 |
|---|---|
| ID | US-002 |
| 用户故事 | 作为 **采购者/安装者**,我想要 **搜索并安装符合我场景的资产**,以便 **快速复用已有方法、工具或镜像** |
| 优先级 | P0 |
| 验收条件 | **Given** 市场中存在已发布资产 **When** 搜索并安装 **Then** 获得对应下载/订阅/安装结果且行为可审计 |

| 字段 | 内容 |
|---|---|
| ID | US-003 |
| 用户故事 | 作为 **审核者**,我想要 **在 Gate 中同时完成内容审核与合规审核**,以便 **第三方资产不会绕过平台治理边界** |
| 优先级 | P0 |
| 验收条件 | **Given** 一个待上架资产 **When** 审核流程执行 **Then** 合规与内容两侧状态都可见且共同决定是否发布 |

| 字段 | 内容 |
|---|---|
| ID | US-004 |
| 用户故事 | 作为 **平台**,我想要 **在 Role/Member 镜像类资产上架前强制扫描与签名校验**,以便 **降低供应链风险** |
| 优先级 | P0 |
| 验收条件 | **Given** 一个镜像类资产 **When** 上架前校验 **Then** 若扫描或签名失败则拒绝发布 |

| 字段 | 内容 |
|---|---|
| ID | US-005 |
| 用户故事 | 作为 **已安装用户**,我想要 **在某个资产被撤销上架时收到通知**,以便 **评估是否继续使用、替换或停止该资产** |
| 优先级 | P1 |
| 验收条件 | **Given** 已安装某资产 **When** 发布者或审核方撤销上架 **Then** 已安装用户收到通知与后续建议 |

### 5.3 替代流程

- 资产包格式不合法 → 上架前拒绝并给出校验原因
- 发布者身份不满足要求 → 阻止进入审核流
- 审核未通过 → 资产保持未发布且记录原因
- 支付/订阅系统不可用(未来) → 可回退到免费/组织内分发模式

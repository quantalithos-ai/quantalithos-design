### 2.1 设计目标与局部所有权

| 责任 | 本地拥有 | 完成链路 |
|---|---|---|
| U1 来源/发布责任 | publisher relation、核验记录与安全引用组合 | 正式publisher资格、source/material引用与失效 |
| U2 发布申请/审核交接 | Draft/Submitted申请、固定basis、handoff与decision binding | 提交→Governance handoff→正式决定匹配→current复核 |
| U3 目录/市场版本 | listing metadata、分类、MarketVersion上架状态 | 列表/搜索→详情→显式版本选择；审批与资产仍外部 |
| U4 受控分发 | intent、attempt、relation、正式outcome binding | 获取资格→受理→单原intent dispatch/probe→结果/晚结果 |
| U5 撤回/影响/通知 | disposition、known impact、notice intent/binding | 限制/撤回→固定upper已知影响→通知→原意图对账 |
| U6 审计/恢复 | operation/context/fullresult、audit、work/plan/permission/checkpoint/recovery | 完整原结果重放、崩溃续责与安全Obs交接 |
| U7 引用/读面 | qualified body-free snapshot、derived projection | 正式引用刷新、完整索引重建、当前披露与freshness |

前端不是纯静态页面：它承接typed API、状态映射、筛选/版本选择、发布与获取意图、进度和双语展示；所有业务决定及局部持久状态由后台产生。Web、API、Worker可独立构建部署，但同属一个Marketplace产品和设计边界。

#### 5.1.4 对象实现契约

##### SourceBinding

完整定义：[U1 SourceBinding卡](design-calibration/03_ddd_step_06_part_u1.md#sourcebinding)，以下是相同schema的正文摘录，不增字段。

```rust
/// Binds an immutable owner asset without copying its body or generating its digest.
pub struct SourceBinding {
    /// Uses the formally resolved typed owner reference.
    pub owner_ref: TypedOwnerReference,
    /// Uses the immutable version supplied by the owner.
    pub owner_version: OwnerVersionRef,
    /// Uses the owner's asset digest; Marketplace must not recompute it.
    pub asset_digest: OwnerAssetDigest,
    /// Uses the owner's formal visibility basis.
    pub visibility_ref: OwnerVisibilityRef,
    /// Uses the owner's formal consumption eligibility basis.
    pub eligibility_ref: OwnerEligibilityRef,
}
```

五字段全部来自正式SourceOwner输出；missing/mismatch拒绝，不从摘要字符串推导。`from_owner(input: QualifiedSourceInput) -> Result<Self, DomainError>`完整copy，`matches(&self, candidate: SourceBinding) -> bool`逐typed字段比对，`validate(&self)`及`rehydrate(row: SourceBindingRow)`返回`Result<_, DomainError>`且完整校验；无mutation或I/O。

其他immutable卡分别见[U1](design-calibration/03_ddd_step_06_part_u1.md)、[U2](design-calibration/03_ddd_step_06_part_u2.md)、[U4](design-calibration/03_ddd_step_06_part_u4.md)、[U5](design-calibration/03_ddd_step_06_part_u5.md)、[U6](design-calibration/03_ddd_step_06_part_u6.md)、[U7](design-calibration/03_ddd_step_06_part_u7.md)；卡上归属为contracts的类型只在contracts定义，domain对应文件re-export。public结果/view字段和codec读取[Step8共享面](design-calibration/03_ddd_step_08_shared_surface.md)及七U协议详情，不将immutable组合改为本地生命周期。

#### 5.1.5 Trait / Port / Adapter契约

不声明I/O port、不实现SDK/SQL；共享type及DTO validation不是第18个port。所有外部qualified类型只由正式adapter受控转换，不允许客户JSON自证。

#### 5.1.6 模块内关键函数

类型的validator、immutable `from_*`/`matches`/validated codec使用上述卡的完整签名，只有纯校验和copy；状态迁移归domain。协议入口完整签名由§7规范性协议给出，contracts不能调Service。

#### 5.1.7 模块错误类型

#### 5.7.4 对象实现契约

#### 5.7.5 Trait / Port / Adapter契约

只用Marketplace API typed client，协议镜像以§7 schema为authority；没有浏览器owner SDK/DB、私有审批/支付/扫描port。人类auth的传输策略等待正式owner与04，不自行设计local认证truth。

#### 5.7.6 模块内关键函数

useMarketQuery只发16Q和映射ReadSurface，不触发refresh/rebuild；useMarketCommand保持同intent key与完整原payload，Unknown显示原operation进度而非“失败再试”。版本选择使用SelectMarketVersion结果，不用最大SemVer代资格；获取使用RequestDistribution，不推installed。

#### 5.7.7 模块错误类型

只消费有限MarketError/ReadSurface/Job进度，区分Rejected、NotVisible、Missing、Degraded、CommitUnknown与正式Confirmed；不展示raw错误或从按钮禁用状态推approval。

#### 5.7.8 模块测试切口

`apps/web/tests/marketplace_protocol_tests.ts`、`marketplace_locale_tests.ts`、`marketplace_workflow_tests.ts`：runtime DTO校验、默认En/切Zh不改意图、完整workflow loading/empty/hidden/stale/unknown/late，Query和locale不写业务truth。

### 8.3 Job A/B、原意图与结果帧

#### 调用时序图: 原计划与外部效果分段

```text
trusted JobEnvelope
      | call prepare and current disclosure
      v
A local Tx --append--> Reserved + claim + checkpoint + permission
      | commit KnownCommitted only
      v
formal owner --SDK-dispatch-or-probe--> exact original intent
      | result or typed unknown
      v
B new local Tx --reload--> current objects + revisions + fence
      | assign new committed frame
      v
facts + late duties + audit + full report + successors --tx-commit--> original result
```

关键说明：
- A commit未知时不发外效应；外部调用不持SQL锁，lease超时不证明notcommit。
- B使用新frame与新读取revision；`result_reserved`保持原IDs/context，仅cursor替换B frame，A checkpoint immutable。
- 结果不足以证明原fullreport时，旧Operation仍Reserved/waiting；新合法Reconcile报告可独立保存。

完整[Job共同执行契约](design-calibration/03_ddd_step_09_job_execution.md)和每U独立插入点共同约束A/B。可能commit只原intent probe，formal notcommitted且currentgate允许才合法重试；distribution新attempt/newtarget但原receiver intent不变。晚结果与Cancel/Withdraw可以共存，必须同B保存关系/增量impact/必要续责，不能删除历史或复活准入。

### 10.2 提交帧、隔离与锁序

RW：READ COMMITTED，`begin(ReadWrite)`先取得`mp_commit_frame(id=1)`行锁，之后key→publisher→version→其他owning typed PK。多个key/ref稳定排序；帧锁持至commit/rollback，外部I/O不持SQL。RO：REPEATABLE READ READ ONLY，不写锁、counter、Clock/ID。

`assign_cursor`在同Tx staged事实后递增事务counter，同Tx多次调用同frame；rollback撤销counter和所有写集。每变更row.source_sequence、audit.cursor、receipt/report采用对应提交frame；Job B必须新RW、新cursor，不能复制A。帧锁保证commit顺序，不能换成非事务sequence或时间戳。全局写吞吐代价保留Q-MP-01，未声称性能满足。

| 执行段 | 原子写集 / 读取要求 | 错误与提交不确定 |
|---|---|---|
| fresh Command | 原Core context/Reserved、typed facts/history/sidecar、work+plan、audit、完整result、Completed | 任一失败整个Tx rollback；commitUnknown只原key核对 |
| replay / 16Q | 当前披露后RO完整原值/typedview；每出口关闭RO | 零新ID/context/audit/work/effect；Missing必须可披露 |
| Job A | 原Reserved/context、claim、完整checkpoint、必要permission与maintenance begin | KnownCommitted才下一外部段；Unknown零dispatch |
| 外部段 | 正式SDK originalintent dispatch/probe，无SQL Tx | timeout/ACK不是notcommitted或approval |
| Job B | 新frame、reload/fence/revision、正式outcome或实际gap、late duties、audit、完整report、work/后继plans、Completed | B失败保留A，不能回滚owner；旧fence拒绝覆写 |
| 原Job恢复 | 原完整checkpoint/request/IDs及正式证明，finish_original与当前B同UoW | 原report不足保持Reserved，不由当前view补Complete |
| snapshot / projection | snapshot state+材料+validity或整套projection/manifest/view，同report/audit/work提交 | mismatch/missing/sourcechanged不Qualified/Fresh |

Tx handle只由UoW consume一次；port不隐式commit/业务retry，drop不是rollback正式证明。fake必须同隔离、frame、CAS/UK/FK、完整codec与commit故障语义，不用private map绕公开读取面。

### 10.3 固定upper历史与索引重建

每mutable save同Tx向mp_fact_versions追加完整body-free Row/scope/revision/frame。fixedupper续页及Projection plan/read按subject取latest-as-of-upper，不直接用当前行`source_sequence<=upper`，否则后续更新会漏掉原窗口项；历史镜像缺失IntegrityFailure，不假无项。

内部排序为source_sequence、finite位置tag、真实typed PK；Impact union Relation/UnknownAttempt共用精确compound cursor，不双表共享摘要after。每页完整after/upper在原DeferredPlan保存。KnownScopeComplete只固定upper本地knownset；late B新frame→include_delta→Partial与durable续责。适用disposition全部遍历，有界预算不能截断称Complete。

Projection source_cursor是**kind/scope依赖集合**的MAX(source_sequence)，不是global counter；plan/read/publish/check使用相同谓词：

| MarketProjectionKind | 唯一committed truth / qualified slice来源 |
|---|---|
| Catalog | listing/category/version、关联publisher/verification、source资格safe snapshot |
| Progress | application/basis/review、distribution intent/attempt/relation与相应snapshot |
| Impact | disposition/impact/notice、relation/unknown attempt与相应snapshot |
| Audit | accepted业务audit与recovery事实，排除纯维护selfaudit/report |

排除operation/context/key/checkpoint/permission/lease、projection自身及纯维护report/selfaudit，避免自追踪循环；业务仍可通过GetMarketAudit读取真实safe audit。完整非空typedplan每key必须一次Rendered/Omitted，原子publish整套manifest/view，旧index不能重建truth。Fresh缺body/manifest IntegrityFailure，current source高水位变化Stale。

### 10.4 搜索与当前披露

PG17搜索统一literal substring OR simple FTS，pg_trgm辅助；中文按字面子串，不声称中文分词，短词有界literal fallback。参数化SQL，SQLwildcard字符按literal，不作regex；title/description/tags/type/category仅来自已获披露safe metadata。

current scope/source constraints/本地处置先筛选，再文本/排序/page/count；同谓词返回items/count/token，索引仅缩小候选，不决定资格。排序稳定frame/typed PK，不承诺相关性排序或已达延迟SLO。索引/extension不可用不能默换语义或假Empty，按正式profile预算安全Degraded/Unavailable。

## 11. 错误模型、异常分支与恢复口径

> 校准来源：[Step12 错误与恢复](design-calibration/03_ddd_step_12_errors_recovery.md)。
>
> 延伸阅读：该文件§7.1三层finite错误、§7.2十八HTTP/Query映射、§7.4全部阶段化异常/恢复矩阵。

### 11.1 分层错误与安全映射

不增各层第二套enum。DomainError十variant、PortError七variant、ExternalPortError八variant，以Step6 shared与Step7定义为准，全部穷尽转换见Step12§7.1。MarketError只`code/reason_ref/operation_ref`；reason/operation可选且当前披露允许，禁止raw SQL/stack/SDK body/token/URL与自由文本。

Domain输入/错ref→InvalidInput，binding→BindingMismatch，transition→IllegalTransition，缺正式source/authority→ContractBlocked，condition不足→IntegrityFailure，fence→FenceMismatch。Port UniqueConflict在operation key竞争先重新find、比fingerprint，same原值replay/busy，异intent IdempotencyConflict；其他业务UK对外VersionConflict，不泄露constraint名。KnownNotCommitted必须正式exact intent proof，只由Job有限outcome处理，不自产成功/新错误码。

|---|---|---|
| InvalidInput | 400 | typed输入/token错误，no-echo |
| MissingIdempotencyKey | 400 | 仅C/J，Query无key要求 |
| NotAuthorized | 403 | scope/actor资格缺，不披露存在性 |

### 11.3 阶段化失败恢复

完整异常矩阵以Step12§7.4逐场景为规范，以下保留关键不可绕规则。

| 失败窗口 | 允许动作 | 禁止动作 |
|---|---|---|
| preaccept / 已证明local rollback | safe拒绝或同intent重新读当前输入 | 存accepted成功audit/伪外部结果 |
| samekey Completed / Reserved | 完整原重放 / in-progress与原checkpoint恢复 | 重跑业务、新ID、覆盖旧结果 |
| local commit Unknown | 新RO查原key/context/checkpoint/fullresult；须正式终局或重新取得帧锁后核验 | 一次keymissing就断言rollback或盲重试 |
| A已commit / permission可能外发 | 只原intent probe；formal notcommit且currentgate允许后合法重试 | 因没看到call/lease过期/timeout再发一次 |
| B失败 / 原report不足 | 保留A原责任；正式Reconcile可存本次报告，旧Reservedwaiting | currentview补原报告、删key/强Complete |
| cancel/withdraw后late Confirmed | exact匹配后保存原attempt/relation/所有适用impact与后继 | 丢晚结果、删除原history或重开Listed |
| snapshot/rebuild失败 | 实际Stale/Unavailable/typedgap，原continuation不丢 | 缺源假Empty、部分manifest Fresh、旧index修truth |

## 12. 并发、幂等与重入保护

> 校准来源：[Step13 并发幂等](design-calibration/03_ddd_step_13_concurrency_idempotency.md)、[Step7 分页输入](design-calibration/03_ddd_step_07_typed_ports.md)。
>
> 延伸阅读：Step13§7.1～7.3原key/33DTO完整canonical投影、§7.5～7.6竞争/codec/位置；Step7 PageReadContext/MarketPageSelector显式输入。

### 12.1 Key与完整原结果

21C key只Core meta.request，12J key只context.request；唯一`(kind,正式scope,exact UTF8 key bytes)`，不trim/casefold/Unicode normalize，PG BYTEA或等效exact C-collation，无自动TTL。Query不创建operation/key/context。key是metadata派生索引，context原值读取必须核对。

当前可信actor/scope/disclosure→canonical→RO lookup，Completed只完整原result，Reserved busy，异指纹conflict；fresh进入RW帧/key锁后再次find，只有赢家分配ID/cursor。全部replay零新audit/work/O/P/claim/effect，不因当前业务gate变化重新执行；当前披露仍每次强制。

### 12.2 Canonical意图

application sealed CanonicalMarketIntent只有33有限C/J DTO显式impl，prepare/reserve均要求该bound；Query/任意Serialize/任意JSON无impl。完整typed callable、字段投影表与所有嵌套规则以Step13§7.2～7.3为规范，不用Serde默认输出直接hash。

bytes为UTF8 `quantalithos-marketplace/intent/v1` +0x00+RFC8785 JCS对象，恰含operation、actor identity、delegated_by、scope完整wrapper、完整business。SHA256小写64hex仅本地意图指纹，不是owner资产digest。operation用现有exact variant，actor/delegate只正式Core actor_id/kind；无display/rolehint/locale、trace/requestid/time/key、当次resolver ref或lease/fence generation。

字符串原UTF8；全部整数投影decimal字符串（公共协议仍原数字类型），Optional显式null，enum固定tag/value。Set canonical字节排序且拒绝重复；明确unordered的Release verification_refs、Verify/Draft material_candidates、metadata tags按规则排序，其余Vec保序，**PlanImpactNotifications.targets保序**。business全字段递归纳入，不能排除expected_revision或typed plan。成熟JCS库patch/MSRV/golden/parity等待授权实施验证，不在本文给虚构hash样本。

### 12.3 资源竞争与重入

完整竞争矩阵见Step13§7.5，含publisher release与正向、version处置/许可、cancel/late结果、notice自然键、claim/fence、refresh/rebuild、category父环和impact续页。RW帧→key→publisher→version→其他typed PK固定序；current正式precheck在SQL外，写段重读本地binding/revision。局部锁不保证跨owner撤销原子性。

lease到期或cancel不是外部未提交证明；旧fence不得覆盖，新授权Reconcile仅原intent probe。formal notcommit与currentgate满足才newattempt/newwork target，receiver originalintent不变。samekey原checkpoint不能以新Job metadata替原external intent，Dispatch/Reconcile pair仅已定义12入口。

### 12.4 公共分页与typed位置

七paged方法输入PageReadContext原Core actor/delegate、当前SafeReadContext与固定selector；SafeReadContext不含身份，不从disclosure_ref/HTTP偷读。内部RepositoryPositionSubject六variant为OwnedSubject、Relation、Work、Audit、Basis、Qualification，以真实PK区分同subject多audit/work。

public CorePageToken采用BASE64URL_NOPAD(RFC8785 JSON)，完整private frame/算法以Step13§7.6为规范；schema/selector/scope/request_binding/upper/after齐全。request_binding含selector、scope、actor/delegate、全部typedfilter、current source constraints，不含page token/limit/trace/locale/易变resolver ref。

token不是授权签名或凭证。current披露每次强制，upper不越实际committed高水位，after合法family/parent/filter/scope且不越upper；checksum可计算不准入隐藏信息。排序为frame/finite tag/typed PK，不用locale collation或Rust enum Ord。last可见项才产生next token，同谓词count；filter/可见anchor变化InvalidCursor→InvalidInput，旧索引highwater变化Stale/重新分页，不假空成功。

### 14.4 Observation生产与证据边界

O work生产方为21C+八J：review2、distribution2、impact1、notice2、reference1。audit构造后、receipt/report前用已有schedule创建；target与effectintent均Observation(original_operation)，冻结audit_refs当前为该operation真实`[audit_ref]`，work+plan+audit+result同Tx，原receipt/report包含实际work ID。Worker按持久plan调typed DTO，不扫描audit猜intent。

RunMarketRecovery无O、只P；Dispatch/ReconcileObservation与Rebuild无O/P递归，防自身audit链和projection高水位循环。原replay零O/P。qualify/dispatch/probe匹配原operation、frozen auditset、scope和原permission；正式producer/redaction/SDK合同缺则真实Blocked，无外部call/binding。

正式ObservationOutcomeBinding只正式owner QualifiedObservationOutcome全字段匹配后保存；local audit≠Obs receipt≠evidence。潜在commit无probe继续waiting，ACK不升级receipt/approval。当前无Archive export/restore、Bus/outbox或支付流水，不能构造run/verdict/signoff/readiness。

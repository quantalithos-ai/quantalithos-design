## 2. 本次配置设计目标与范围

> 校准来源：
> - `design-calibration/04_config_step_02_scope.md`
>
> 延伸阅读：建议继续阅读上述文件的“SOP问题回答”“结构化中间产物”“非范围”。

目标是提供一个严格、可审查、可失败的JSON控制面：在不复制上游truth的前提下装配API listener、PG配置引用、SDK profile、八slot引用、Worker预算和Web展示绑定。

| 目标 | 说明 | 交付给下游的结果 |
|---|---|---|
| P0启动装配 | 解析并校验七字段、profile和八slot引用 | 03 runtime builder的输入边界 |
| P0安全边界 | raw secret只在provider内解析；未知键和bypass拒绝 | 05/06的安全与失败门禁 |
| P1环境姿态 | local/test/staging/production能力矩阵 | 05配置组合、07实施前置 |
| P1变更恢复 | 冷更新、快照、审计摘要和last-known-good | 运维资料和验收输入 |
| P2保留 | config center、admin override、hot/reload、新slot、财务/归档lane | future/blocker，需重开文档 |

| 非范围 | 留给哪一层 / 哪份文档 |
|---|---|
| 具体部署命令、挂载、拓扑、TLS/CORS/auth运维值 | 平台/部署与运维资料；若形成typed字段先回写03 |
| owner正文、资产血缘、Registry/Adapter truth、Governance approval | 唯一owner正式文档与SDK/consumer合同 |
| 完整测试case、执行报告、验收verdict | 05/06；本轮不生成run或evidence |
| phase、task、commit boundary、实现ledger/skeleton | 07；正式07前不创建 |
| Billing、支付、订阅、收入分成、跨境交易、Archive写入、active event/outbox | future/blocker；00/01/02受控重开 |

配置文件可以改变技术资源姿态，但不能改变业务truth、审核决定、可见性、版本状态、幂等/事务/审计原子性或任何外部effect的结果语义。

## 4. 配置分类与边界

> 校准来源：
> - `design-calibration/04_config_step_04_categories_boundaries.md`
>
> 延伸阅读：建议继续阅读上述文件的“配置分类表”“禁止配置化项”和“跨分类/禁止项审计”。

| 配置类别 | 说明 | 示例 | 是否允许热更新 | 主要风险 |
|---|---|---|---:|---|
| `startup` | 服务启动读取的listener、ref、owner、worker项 | `api.bind` | 否 | 错配导致拒启动或能力阻断 |
| `build-time` | Web构建期公共API绑定 | `VITE_MARKETPLACE_API_BASE` | 否 | 构建连错服务或泄露端点 |
| `display` | 只影响展示的locale | `web.default_locale` | 否；用户本地偏好仅展示 | 误改业务key/ref |
| `sensitive reference` | 指向provider资源的opaque ref | `secret-ref://...`形状 | 否 | 泄露、profile错配、不可达 |
| `budget` | Worker正值资源预算 | batch/lease | 否 | 超预算、未知Q-MP-01上限 |
| `diagnostic` | 03固定的有限安全标签语义 | redaction/profile类别 | 否 | 高基数、raw body或secret泄露 |

| 禁止配置化项 | 原因 | 如需改变应走什么流程 |
|---|---|---|
| Governance approval、publisher/org认证、source/material eligibility | authority不属于Marketplace | 上游owner/SDK合同与00/01受控变更 |
| visibility/scope/current disclosure、query no-write | 防越权读取和隐藏信息 | 03/上位BR/协议重开 |
| state transition、withdrawal、exact version、idempotency/fingerprint | 领域不变量 | 回03 Step6/10/13并重审 |
| frame/CAS/as-of/fullresult/audit-work原子性 | 一致性和恢复边界 | 回03 Step11～13 |
| retry-all、blind retry、force success/installed/paid | 外部Unknown和财务边界 | owner/00/01受控变更 |
| owner正文/digest重算、scan/signature/ACK当approval | 避免第二套资产/审核真相 | 相应owner正式合同 |
| active event/outbox、Billing、Archive writer | 当前无正式lane/schema | 先00/01再重开02～04 |

逐域边界结论：`api`只startup，`storage`只startup/ref，`sdk`/`owner`只startup/ref，`worker`只startup/budget，`web`只build-time/display；当前没有hot/reload类别。任何未知键均拒绝，而不是作为高级运维开关保留。

## 5. 配置来源、优先级与冲突处理

> 校准来源：
> - `design-calibration/04_config_step_05_sources_priority.md`
>
> 延伸阅读：建议继续阅读上述文件的“来源优先级与冲突规则”“按配置域覆盖表与停审”。

来源的优先级是解析权威顺序，不是任意环境覆盖链：静态安全不变量最高；严格JSON是业务外部配置的唯一快照；命令行/环境变量只选择路径；secret provider只解析ref；Web公共API地址只在build-time生效。

| 来源 / 层 | 优先级 | 适用配置 | 冲突处理 | 不可用时策略 |
|---|---:|---|---|---|
| 代码静态安全不变量 | 最高 | 类型、八kind集合、禁止键、无hot/reload | 文件违反即拒绝 | startup fail-fast |
| 严格JSON配置文件 | 主来源 | 六配置域和envelope | 重复键/未知键/类型错拒绝 | API/Worker拒启动，Web构建失败 |
| `--config <path>` / `MARKETPLACE_CONFIG_PATH` | 选择器 | 文件路径 | 同时给出时必须是相同规范化路径 | 无路径不自动搜索 |
| secret provider | ref解析 | PG/SDK/owner敏感引用 | raw secret不得回写JSON或日志 | 关键storage拒装配；slot可Blocked |
| `VITE_MARKETPLACE_API_BASE` | Web build-time | 公共API origin | 只允许一个受控origin | 构建拒绝 |
| config center/admin/hot reload | 不适用 | 无 | 不接受、不静默忽略 | 设计上拒绝 |

| 冲突场景 | 处理规则 | 阻断范围 |
|---|---|---|
| path入口同时存在且不一致 | fail-fast | API/Worker |
| JSON重复键、未知顶层/域内键 | fail-fast | 当前快照 |
| `schema_version`或`profile`不支持 | fail-fast | 当前进程 |
| 文件profile与受控环境姿态冲突 | 不自动切换profile，拒绝 | 当前进程 |
| raw value覆盖secret ref | fail-fast并redact诊断 | 当前快照 |
| owner slot重复/未知kind | schema拒绝；缺slot只形成Blocked | owner能力 |
| Web origin含凭证或不在allowlist | 构建拒绝 | Web bundle |

同层冲突不使用最后写入胜出；缺少服务必填项也不通过安全默认。`default_locale`是唯一安全默认，默认值只影响展示语言。

## 6. 环境、部署 profile 与配置矩阵

> 校准来源：
> - `design-calibration/04_config_step_06_environment_matrix.md`
>
> 延伸阅读：建议继续阅读上述文件的“环境与配置矩阵”“Profile能力门禁”。

本设计定义四个逻辑profile；CI复用`test`，不新增业务profile。profile只说明资源/依赖姿态，不改变approval、scope、visibility、state、fingerprint、installed/paid或外部结果。

| profile | 用途 | storage姿态 | owner/SDK姿态 | 敏感处理 | 允许的验证范围 | 不能宣称 |
|---|---|---|---|---|---|---|
| `local` | loader解析、局部负例和Web联调 | 可只验证schema；无真实PG则Unavailable | 缺资格/缺slot为Blocked；原型不算Bound | 只ref，禁止明文 | 配置解析、UI展示和负例 | 真实发布、审核、分发、ready |
| `test` | 单元/契约/故障注入和CI | 隔离测试存储 | 可用等价fake/test adapter，语义不强于port | 测试secret/fixture且redacted | 配置边界和负例 | 生产owner资格、真实交付 |
| `staging` | 非生产接缝验证 | durable能力、schema/extension待核验 | 仅已批准非生产正式合同 | 不混入生产secret | 集成前置和验收准备 | 生产容量、审批、支付 |
| `production` | 正式服务 | 正式PG能力必需 | 八slot逐项exact contract/mapping/current authority；无fake | 正式provider必需 | 完成正式门禁后才可运行 | 当前可部署、ready、paid、installed |

| 能力门禁 | local | test | staging | production |
|---|---|---|---|---|
| JSON/schema/unknown-key校验 | 允许 | 必须 | 必须 | 必须 |
| 七字段RuntimeConfig装配 | 负例 | 测试组合 | 需真实前置 | 需正式前置 |
| 八slot positive Bound | 不可宣称 | 仅测试姿态 | 逐slot待核验 | 逐slot正式核验 |
| hot/reload | 禁止 | 禁止 | 禁止 | 禁止 |
| production fake fallback | 禁止 | 仅test composition | 禁止 | 禁止 |

`0.0.0.0:9090`只属于draft局域网原型，不是正式配置默认。各profile不填写真实DSN、数值baseline、拓扑、provider名称或部署命令；Q-MP-01和外部qualification未闭合时保持blocked。

### 7.1 配置项总清单

| 配置项 | 类型 | 默认值 | 必填 | 来源 / 作用域 | 生效 | 敏感级别 | 失败策略 | 关联模块 |
|---|---|---|---:|---|---|---|---|---|
| `api.bind` | SocketAddr字符串 | 无 | 是 | JSON/profile | startup | internal | 解析失败拒API启动 | api |
| `storage.postgres_config_ref` | 非空opaque ref | 无 | 是 | JSON/profile + provider | startup | sensitive | 无法解析/连接拒装配 | storage |
| `sdk.profile_ref` | typed profile ref | 无 | 是 | JSON/profile + provider | startup | sensitive | positive adapter不装配 | sdk |
| `owner.bindings[].kind` | 八kind枚举 | 无 | 条件 | JSON/profile | startup | internal | unknown/duplicate拒绝；缺slot形成Blocked | owner |
| `owner.bindings[].configuration_ref` | typed ref | 无 | 条件 | JSON/profile + provider | startup | sensitive | 相关slot Blocked | owner |
| `worker.batch_limit` | u32，>0且profile上限内 | 无 | 是（Worker） | JSON/profile | startup | internal | 缺失/0/超限拒Worker | worker |
| `worker.lease_millis` | u64，>0且checked-add安全 | 无 | 是（Worker） | JSON/profile | startup | internal | 缺失/0/溢出拒Worker | worker |
| `web.api_base` | build-time allowlisted URL | 无 | 是（Web） | `VITE_MARKETPLACE_API_BASE` | build-time | internal | 非allowlist/含凭证构建失败 | web |
| `web.default_locale` | `En`或`Zh` | `En` | 否 | JSON或静态安全默认 | startup/display | public | 非法拒绝；缺失En | web |

`schema_version`和`profile`是loader metadata，不是业务配置项。服务`RuntimeConfig`只接`api_bind`、`postgres_config_ref`、`sdk_profile_ref`、`owner_bindings`、`worker_batch_limit`、`lease_millis`、`default_locale`七个字段；`owner.bindings[].kind/configuration_ref`作为entry整体映射`owner_bindings`，`web.default_locale`映射`default_locale`，`web.api_base`留在Web build/runtime公共边界。八个owner kind固定为`Source`、`Publisher`、`Material`、`Governance`、`Scope`、`Receiver`、`Notice`、`Observation`；没有Billing、Archive或Bus slot。

## 8. 敏感配置与密钥管理

> 校准来源：
> - `design-calibration/04_config_step_08_secrets.md`
>
> 延伸阅读：建议继续阅读上述文件的“敏感级别与存储边界”“解析、使用和轮换流程”。

### 8.1 敏感级别

| 级别 | 含义 | 本项目示例 | 处理要求 |
|---|---|---|---|
| `public` | 可公开且不改变权限 | `En`/`Zh` | 可进配置；只记录有限枚举 |
| `internal` | 内部运行参数 | bind、batch、lease | 不进入公开API/Web bundle；审计只记键名/结果 |
| `sensitive` | 暴露会带来连接或运营风险 | PG/SDK/owner configuration_ref | 只保存opaque ref；不记录完整ref/value |
| `secret` | 真实秘密材料 | raw DSN、password、token、private key | 不进JSON、CLI、Web、RuntimeConfig或domain |

`postgres_config_ref`、`sdk.profile_ref`和owner `configuration_ref`属于`sensitive reference`；provider返回的真实材料属于`secret`。引用URI不证明provider存在，也不证明adapter已Bound。

### 8.2 读取、轮换与审计

```text
[JSON opaque ref]
       |
       v
[loader schema check]
       |
       v
[approved secret provider]
       |
       v
[typed adapter/builder scope]
       |
       v
[RuntimeConfig + ports; no raw secret in domain]
```

图示说明：

- provider只按ref解析，不能把raw secret写回JSON、RuntimeConfig、日志或Web。
- provider不可达时不使用空值、公共默认值或生产fake；PG关键依赖拒装配，owner/SDK能力可保持Blocked。
- 轮换通过新快照和受控重启完成；旧值兼容窗口由provider/owner合同决定。

| 表面 | 禁止内容 | 允许内容 |
|---|---|---|
| API/Web DTO | DSN、token、provider ref、owner凭据 | 有界能力状态、redacted错误类别、locale |
| 日志/trace/metric | raw value、完整ref、URL query、response body、credential | 有限slot、阶段、结果、错误code |
| 配置审计 | secret/value/body | profile、域、slot、版本化结果、redacted摘要 |
| CLI/process | secret argv、shell history中的raw凭据 | 配置文件路径选择器 |
| domain/application | 文件/env/provider读取 | 已校验typed ports和资源句柄 |
| Web bundle | DB、SDK profile、owner endpoint、credential | 公共API base和En/Zh资源 |

当前没有独立cursor/TLS/auth key字段；若未来需要，必须先回写03并重开04，不得在配置文件中私造第八业务字段。

## 9. 配置加载、校验与生效机制

> 校准来源：
> - `design-calibration/04_config_step_09_loading_validation.md`
>
> 延伸阅读：建议继续阅读上述文件的“加载与装配链”“分层校验规则”。

### 9.1 加载链

```text
[--config path / MARKETPLACE_CONFIG_PATH]
                 |
                 v
      [read once, strict JSON]
                 |
                 v
[envelope/schema/profile/unknown-key validation]
                 |
                 v
 [typed seven-field RuntimeConfig mapping]
                 |
                 v
[range/relationship + owner set validation]
                 |
                 v
 [secret-ref/PG/SDK/owner capability checks]
                 |
                 v
 [assemble_runtime -> API or Worker facade]
```

图示说明：

- envelope metadata在loader结束后不进入业务RuntimeConfig。
- 配置加载不调用审批、列表、分发或状态迁移；domain/application不读raw文件/env/provider。
- PG关键能力失败拒装配；外部资格缺口只能得到Blocked/Unavailable，不自动换fake。

### 9.2 分层校验与失败

| 校验层 | 必须检查 | 通过后 | 失败后 |
|---|---|---|---|
| 来源选择 | path存在、两入口无冲突、无自动搜索 | 单一文件 | API/Worker fail-fast |
| JSON语法 | UTF-8、语法、重复键 | 解析树 | fail-fast |
| envelope | schema_version/profile值域 | 六域校验 | fail-fast |
| key/type | 未知域/键、类型匹配 | typed候选 | fail-fast |
| field relation | bind、非空ref、worker正值/checked-add、locale | 七字段 | fail-fast或Worker拒绝 |
| owner set | 八kind、无重复、ref形状；缺slot明确Blocked | typed bindings | 配置错拒绝/资格缺口Blocked |
| provider/qualification | ref、profile/版本、exact operation/schema/current authority | adapter候选 | storage拒装配；slot Blocked |
| assembly | PG schema/extension、同Tx ports、API/Worker组合 | facade | 资源清理后拒启动 |

### 9.3 生效方式

| 表面 | 生效方式 | 变更方式 | 当前状态 |
|---|---|---|---|
| API bind和server七字段 | `startup` | 新快照+重启 | 启用 |
| Worker budget和owner/store/sdk refs | `startup` | 新快照+重启；不动态换adapter | 启用 |
| Web公共API base | `build-time` | 重新构建并校验origin | 启用 |
| Web locale | startup/display；用户偏好仅展示 | 新快照或本地display preference | 启用 |
| config center/admin/hot reload | `hot/reload` | 不提供 | 禁用 |

校验成功仅说明快照可装配，不说明Governance approval、publisher认证、receiver安装、支付或Observation evidence成立。失败时已打开的pool/client/provider handle关闭或drop；不启动listener、claim、effect或accepted业务结果。

## 10. 配置变更、审计与回滚

> 校准来源：
> - `design-calibration/04_config_step_10_change_audit.md`
>
> 延伸阅读：建议继续阅读上述文件的“配置变更状态流”“变更审计字段”。

### 10.1 变更状态流

```text
[Proposed snapshot]
        |
        v
[schema/profile/ref validation]
        |
   +----+----+
   |         |
 invalid   valid
   |         |
 reject   [approved snapshot]
                 |
                 v
        [restart / rebuild]
                 |
          +------+------+
          |             |
       starts        fails
          |             |
          v             v
 [current config]  [last-known-good]
```

图示说明：

- 这是配置快照流，不是市场版本、listing或分发状态流。
- startup失败不进行半切换；运行平台保留上一份已验证快照。
- 当前没有在线reload、灰度config center或admin override。

### 10.2 审计与回滚

| 审计字段 | 规则 |
|---|---|
| revision/fingerprint metadata | 由受控发布系统/loader提供；不在本文生成实际digest，不进入RuntimeConfig或业务key |
| profile/schema_version | 有限枚举 |
| 操作者类别 | 人类/自动发布器类别，不记录凭证 |
| 变更域/slot | 有限allowlist，不记录完整ref |
| 结果/错误类别 | 采用有限redacted诊断 |
| raw value/secret/body/业务operation | 永不记录 |

新快照通过校验后才可替换旧快照；失败保留last-known-good。回滚只重新指向已验证快照并重启，不回滚listing/version/disposition/operation/notice/receiver状态，不重发未知外部effect。若未来需要持久化配置审计，必须复用正式观察/审计合同；本轮不新建market event/outbox或Archive writer。

## 11. 失效模式与降级 / fail-fast 策略

> 校准来源：
> - `design-calibration/04_config_step_11_failure_modes.md`
>
> 延伸阅读：建议继续阅读上述文件的“失效矩阵”“降级允许范围”。

| 失效 | 结果 | 策略 |
|---|---|---|
| 路径、JSON、重复键、未知键、schema/profile错误 | 进程/快照拒绝 | `fail-fast` |
| bind、ref、worker值非法 | API/Worker不启动 | `fail-fast` |
| PG关键能力/provider不可用 | 无本地accepting assembly | `fail-fast` |
| SDK/owner exact资格缺失 | 受影响slot/操作不可用 | `fail-closed`，Blocked/Unavailable |
| Scope resolver不可用 | 受影响读写全部拒绝 | `fail-closed` |
| locale缺失 | 展示回安全En | `default-fallback`仅此项 |
| Web API base非法/含凭证 | Web构建拒绝 | `fail-fast` |
| telemetry/audit sink丢失 | 业务结果不变 | `degraded`安全诊断 |
| 外部dispatch Unknown | 保留Unknown，先probe | 复用03原意图解析 |

不允许把Blocked、Unavailable或Unknown压缩为空成功、Empty列表、Installed、Paid或NoticeDelivered；不允许production fake fallback、retry-all、force-success或配置绕过approval/visibility/state/幂等/审计原子性。

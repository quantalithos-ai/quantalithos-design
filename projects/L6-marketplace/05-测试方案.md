### 13.2 Schema、摘要与真实性

机器schema为`marketplace-test/v1`、JSON Schema2020-12，11kind/48defs的完整required/nullable/enum/ref/writer边界见规范性附录。envelope包含schema_version/kind/run_id/record_digest/body；kind限context、registry、subcase-manifest、case、log-entry、suite-report、check-report、run-report、evidence-detail、evidence-index、acceptance-draft。所有object拒unknown；duplicate key在解析时拒绝，date-time严格RFC3339 UTC。

run_id满足`^[A-Za-z0-9][A-Za-z0-9._-]{0,95}$`且不为latest/点目录；RecordRef仅同run logical相对路径，禁止absolute/../symlink/跨run。baseline仅实际implementation/generator commit及设计bytes来源；本轮不填假commit/hash。所有计数来自实际runner，整数上限2^53-1或明确decimal string，Q/replay九counter均零但不能由报告器伪默认。

SHA-256固定小写64hex：JSON record采用RFC8785成熟库canonical UTF-8，**仅删除该record顶层record_digest**，保留所有child/ref digest；mode=json-record。MD/非JSON文件/设计来源按exact bytes、mode=raw-bytes；JSONL逐line同schema、文件hash raw bytes。asset_digest、fingerprint和artifact hash不能混用；hash不是approval或owner签名。

#### 证据流图: 同run单向生成

```text
registry / subcase manifest -> context -> logs / case raw
                                           |
                                           v
suite raw / generated JSON+MD -> artifact-stage checks
                                           |
                                           v
run report -> EV detail / MD -> evidence index / MD
                                           |
                                           v
                    seal-stage checks -> acceptance draft
```

关键说明：EV不回指index，index不回指seal，check不引用自己的输出；两stage文件不覆写。writer serialization与import都重新校schema/hash/redaction，不能信`passed`标签。stdout/stderr也只写log-entry envelope，不留任意原始stack/body/credential。

passed须actual执行且全部expected assertions matched，无空断言/缺subcase；not_run不能伪造start/finish。suite/run counts来自raw，缺执行显式not_run，任何unexpected blocked/unavailable/非零check均阻P0。失败仍报告和safe日志；report失败保raw与tooling gap，不能补静态成功。secret原值只在内存检测/安全隔离，归档仅redacted内容。

### 读前说明 · 测试方案标准生产流程

`05-测试方案` 不是从“想到哪些 case 就列哪些 case”开始写,而是从 `02/03` 已冻结的结构、状态机、交互边界和高风险接缝反推测试方案。

建议按以下流程产出:
1. **先收输入**
   - 读取 `00-需求文档.md`、`01-架构设计.md`、`02-概要设计.md`、`03-详细设计.md`

   - 分清对象级、函数级、流程级、边界级、协议级测试对象
3. **按主要部分分组**
   - 每个主要部分先列: 必测对象 / 必测函数 / 必测状态流 / 必测异常流
4. **再按测试层级细化**
   - 单元测试 / 集成测试 / 事件链测试 / 恢复测试 / 投影一致性测试 / 端到端主线测试
5. **最后补执行方案**
   - 测试数据、环境依赖、串行执行顺序、CI 门禁、证据归档路径

> 先按“主要部分 + 风险边界”组织,再按测试层级展开,不要反过来只按技术类型罗列测试。

## 1. 测试目标与范围

### 1.1 测试目标

本轮测试的目标不是单纯证明 marketplace“能列出资产并允许安装”,而是系统验证 `L6-marketplace` 是否真正满足“生态分发、上架与交易产品层 / marketplace experience 层”的设计要求,尤其要证明以下几点成立:
- MarketplaceListing / PackageRelease / InstallRecord / EntitlementView / RatingReview / RankingView 构成正式生态消费层真相
- `MarketplaceListing ≠ source asset truth`、`package listing ≠ package definition truth`、`Install record ≠ installed system truth`、`transaction/subscription view ≠ finance ledger truth`、`rating/review ≠ asset quality truth`、`compatibility badge ≠ runtime guarantee truth` 等核心边界成立
- listing / release / install / entitlement / review 五条生态主线必须能统一组织,且 source refs 持续可追溯
- package、compatibility、install、purchase、subscription 的状态必须层次清晰,避免“已装好/已启用/已付费/已授权”混层
- rating/review/featured/ranking 必须始终带有 usage/install/feedback 证据链,不直接污染 source asset truth

### 1.2 测试范围 / 非范围

| 范围项 | 类型 | 优先级 | 说明 |
|---|---|---|---|
| 资产上架与目录部分 | listing/catalog 对象 | P0 | MarketplaceListing、ListingCatalog、CategoryTag、PublisherProfile、VisibilityState |
| 版本、兼容性与包分发部分 | package/release 对象 | P0 | PackageRelease、ReleaseChannel、CompatibilityBadge、InstallBundle、DeliveryArtifactRef |
| 安装、启用与订阅消费部分 | install/consumption 对象 | P0 | InstallRequest、InstallRecord、EnableState、SubscriptionState、UpgradePlan、UninstallRequest |
| 交易、权益与结算可见性部分 | entitlement/commerce 对象 | P0 | PurchaseSnapshot、EntitlementView、LicenseSummary、InvoiceView、AccessState |
| 评价、反馈与生态运营部分 | rating/review/ops 对象 | P0 | RatingEntry、ReviewEntry、FeaturedSlot、RankingView、AbuseReport、ModerationHint |
| method-library / capability-hub / bridges source truth、本地 package storage、本地支付账本 | 非范围 | P2 | 只验 marketplace 如何消费其输入并组织生态分发/交易体验,不验底层 source truths 与基础设施全部实现 |
| account/member 真相、支付系统本体、auth 本体 | 非范围 | P2 | 只验 marketplace 的 install/subscription/entitlement 可见状态,不验底层账户/支付系统 |
| website / console 的入口壳与页面容器 | 非范围 | P2 | 只验 marketplace 入口消费语义,不验外层容器系统 |

## 2. 测试策略与分层

| 层级 | 目标 | 责任 | 典型内容 | 通过标准 |
|---|---|---|---|---|
| 单元测试 | 验证对象成员函数与局部不变量 | domain / product owner | `input.validate_listing_source_boundary`、`input.validate_release_source_boundary`、`input.validate_install_boundary`、`input.validate_entitlement_boundary`、`input.validate_ranking_boundary` | 边界与不变量符合设计 |
| 集成测试 | 验证 service + repo + projection + package store + entitlement emitters 联动 | backend / product owner | `CreateListing`、`PublishRelease`、`BuildCompatibilityMatrix`、`CreateInstallRequest`、`RecordInstall`、`BuildEntitlementView`、`SubmitRating`、`BuildRankingView` | listing、release、install、commerce、ecosystem 五条主线同时成立 |
| 事件链测试 | 验证上下游接缝链 | integration / platform owner | source asset refs → listing、release → install、install/purchase → entitlement、review → ranking/featured、website/console → entry consume | 输入输出语义一致 |
| 恢复专项测试 | 验证 refs 缺失、compatibility 漂移、install/activation 错位、entitlement conflict、review 缺上下文等异常链 | architecture / QA | invalid refs、stale release、install pending、ledger mismatch、review misuse | 体验不误导、错误被正确阻断或标记 |
| 投影一致性测试 | 验证 catalog/detail/compatibility/install/ranking 视图与主记录一致 | backend / QA | catalog rebuild、compatibility rebuild、install status rebuild、ranking rebuild | 投影只读且与主线一致 |
| 端到端主线测试 | 验证最小生态消费闭环 | QA / owner | listing → release → install → entitlement → review/ranking | marketplace 体验闭环跑通 |

## 3. 需求追溯与覆盖矩阵

| 需求/规则 | 测试场景 | 测试层级 | 自动化 | 证据 |
|---|---|---|---|---|
| `MarketplaceListing ≠ source asset truth` | listing 只消费 source refs,不替代资产权威定义 | 单元 + 集成测试 | 是 | listing/source compare |
| `package listing ≠ package definition truth` | release/bundle 只表达分发版本,不替代 package/source definition truth | 单元 + 集成测试 | 是 | release/source compare |
| `Install record ≠ installed system truth` | install 记录只表达 marketplace 消费结果,不替代系统实际激活真相 | 单元 + 集成测试 | 是 | install/activation compare |
| `transaction/subscription view ≠ finance ledger truth` | entitlement/license/invoice 只表达可见商业状态 | 单元 + 集成测试 | 是 | entitlement/ledger compare |
| `rating/review ≠ asset quality truth` | 评分和评论只是反馈层,不替代正式质量结论 | 单元 + 集成测试 | 是 | review/quality compare |
| `compatibility badge ≠ runtime guarantee truth` | compatibility 只是声明或验证结果,不保证运行成功 | 单元 + 恢复测试 | 是 | compatibility/install compare |
| install / subscribe / purchase 状态分层 | 已安装/已启用/已订阅/已授权必须明确区分 | 集成 + 事件链测试 | 是 | install/subscription/entitlement compare |
| teaser/ranking 只消费证据 | featured/ranking 必须建立在 usage/install/review 证据链上 | 集成 + 投影一致性测试 | 是 | ranking evidence compare |
| 未公开或未授权资产不可见 | draft/hidden/forbidden 资产不得出现在 catalog | 集成 + 安全测试 | 是 | visibility filter / catalog logs |

## 4. 环境与配置矩阵

| 环境 | 用途 | 依赖 | 关键配置 | 风险 |
|---|---|---|---|---|
| dev | 本地主线验证 | local listing store / fake source refs / fake install/entitlement inputs / fake package storage | debug listing/release/install state / stale markers visible | 容易只测 happy path |
| test | CI / 集成测试 | deterministic method/hub/bridge fixtures / fake package store / fake auth/payment inputs / fake website-console consumers | isolated marketplace tables / fixed source refs / review context enforcement | cross-source 与商业状态样本不足 |
| staging | 端到端演练 | real-like source refs / release artifacts / entitlement inputs / ranking consumers | install/upgrade/entitlement/featured evidence enabled | 多版本、多组织和复杂权限差异放大 |

## 6. 核心测试场景

| 场景 ID | 场景 | 前置条件 | 步骤摘要 | 预期结果 |
|---|---|---|---|---|
| TC-001 | CreateListing 成功创建正式上架条目 | source asset refs 合法 | CreateListing | MarketplaceListing 创建成功 |
| TC-002 | 未公开或非法 refs 资产不得进入公开 catalog | refs 缺失或 visibility 非 public | CreateListing / QueryCatalog | 返回 `LISTING_SOURCE_REF_INVALID` 或不出现在 catalog |
| TC-003 | PublishRelease 成功生成 package release 与 install bundle | listing 存在 + package refs 合法 | PublishRelease | PackageRelease / InstallBundle 创建成功 |
| TC-004 | compatibility 漂移或 bundle 缺失时阻断 release 或 install | 兼容性输入不匹配 | BuildCompatibilityMatrix / CreateInstallRequest | 返回 `RELEASE_NOT_COMPATIBLE` |
| TC-005 | CreateInstallRequest / RecordInstall 成功创建安装记录 | release 可安装 + 用户上下文合法 | CreateInstallRequest / RecordInstall | InstallRequest / InstallRecord 创建成功 |
| TC-006 | install 记录不得等同 source 系统已激活成功 | source activation 尚未完成 | RecordInstall + compare | install 可见但 activation 未自动等同 |
| TC-007 | BuildEntitlementView 成功生成统一权益可见状态 | payment/auth/install 输入齐全 | BuildEntitlementView | EntitlementView / LicenseSummary 创建成功 |
| TC-008 | entitlement 与 ledger/auth 结果冲突时标记 pending/conflict | ledger 或 auth 延迟 | BuildEntitlementView | 返回 pending/stale 或 conflict 标识 |
| TC-009 | SubmitRating / SubmitReview 成功记录生态反馈 | listing/install context 合法 | SubmitRating / SubmitReview | RatingEntry / ReviewEntry 创建成功 |
| TC-010 | review 缺安装上下文时拒绝提交 | install context 缺失 | SubmitReview | 返回 `REVIEW_CONTEXT_INVALID` |
| TC-011 | BuildRankingView 成功生成 ranking / featured | rating/review/usage 证据齐全 | BuildRankingView | RankingView / FeaturedSlot 创建成功 |
| TC-012 | ranking/featured 无证据链时不得更新 | usage/install/review 证据不足 | BuildRankingView | 阻断排行/精选更新 |
| TC-013 | transaction/subscription 视图只表达可见状态 | entitlement 输入存在 | BuildEntitlementView + compare | 不反写 finance/auth truth |
| TC-014 | hidden/draft listing 不得被 console/website 入口误导性展示 | visibility 非 public | QueryCatalog / entry consume | listing 不可见或被正确标记 |

## 10. 缺陷管理与异常升级

| 严重级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | listing 反写真相 / install 冒充激活真相 / entitlement 冒充 ledger 真相 / ranking 无证据链却公开发布 |
| A | 视情况 | 主线可跑但 stale/fallback、compatibility 漂移、entitlement conflict、review/install 上下文不稳 |
| B | 可带着走 | 非关键展示、低优先级 teaser / ranking 文案或细节异常 |

## 11. 回归策略与残余风险

### 11.1 回归策略
- 每次改动 listing / catalog / visibility,都必须回归资产发现与 source refs 主线
- 每次改动 release / compatibility / install bundle,都必须回归 package 分发与兼容性主线
- 每次改动 install / subscribe / upgrade / uninstall,都必须回归消费状态与 source activation 分层主线
- 每次改动 entitlement / transaction views,都必须回归 finance/auth 分层主线
- 每次改动 rating / review / ranking / featured,都必须回归生态反馈与运营证据链主线

### 11.2 残余风险
| 风险 | 影响 | 接受人 |
|---|---|---|
| 多 catalog / 多区域分发后续细化 | 验收矩阵需扩充 | TL / 架构 |
| 更复杂订阅/授权模型继续演进 | entitlement 验收需增加更多样本 | marketplace / finance / auth |
| 推荐/运营逻辑继续丰富 | ranking/featured 验收需扩充 | product / growth |

### 读前说明 · 验收标准标准生产流程

`06-验收标准` 不是从“我想验什么”开始写,而是从 `02/03/05` 已明确的目标、边界、红线、主流程结果和测试门禁反推验收门禁。

建议按以下流程产出:
1. **先收输入**
   - 读取 `02-概要设计.md`、`03-详细设计.md`、`05-测试方案.md`
   - 抽取: 目标/非目标、主要部分边界、主流程关键结果、实现红线、高风险验收点、最小可运行闭环、05 中的强测试门禁
2. **再识别验收对象**
   - 分清功能结果、边界结果、状态结果、对外交互结果、恢复结果、投影结果
3. **按主要部分分组**
   - 每个主要部分分别列: 必须满足什么 / 绝不能出现什么 / 哪些是一票否决
4. **明确通过/不通过条件**
   - 每条验收项必须写清通过条件、失败条件、失败意味着哪条边界被破坏
5. **最后形成门禁清单**
   - 单列一票否决项、可延期优化项、风险接受项与接受人

> 先按“主要部分 + 不可破坏边界”组织,再落成功能门禁和非功能门禁,不要只写口号式验收条目。

## 1. 验收背景与范围

### 1.1 验收背景

本次验收针对 `L6-marketplace` 的第一批核心设计主线展开。当前 `02-概要设计.md`、`03-详细设计.md` 与 `05-测试方案.md` 已经明确:
- `L6-marketplace` 是生态分发、上架与交易产品层 / marketplace experience 层,不是方法资产定义仓、capability 接入真相仓或 finance ledger 仓
- MarketplaceListing / PackageRelease / InstallRecord / EntitlementView / RatingReview / RankingView 构成正式生态消费层真相
- `MarketplaceListing ≠ source asset truth`、`package listing ≠ package definition truth`、`Install record ≠ installed system truth`、`transaction/subscription view ≠ finance ledger truth`、`rating/review ≠ asset quality truth`、`compatibility badge ≠ runtime guarantee truth` 等核心边界必须成立
- listing / release / install / entitlement / review 五条生态主线必须能统一组织,且 source refs 持续可追溯
- package、compatibility、install、purchase、subscription 的状态必须层次清晰,避免“已装好/已启用/已付费/已授权”混层
- rating/review/featured/ranking 必须始终带有 usage/install/feedback 证据链,不得直接污染 source asset truth

因此,本次验收的目的不是笼统判断“能不能把插件摆上商店”,而是判断 marketplace 的 listing 主线、release/compatibility 主线、install/consumption 主线、entitlement/transaction 主线与 review/ops 主线是否真的成立,是否可作为后续阶段的稳定基线。

### 1.2 验收范围 / 非范围

| 项 | 是否纳入 | 说明 |
|---|---|---|
| 资产上架与目录部分 | 是 | MarketplaceListing、ListingCatalog、CategoryTag、PublisherProfile、VisibilityState |
| 版本、兼容性与包分发部分 | 是 | PackageRelease、ReleaseChannel、CompatibilityBadge、InstallBundle、DeliveryArtifactRef |
| 安装、启用与订阅消费部分 | 是 | InstallRequest、InstallRecord、EnableState、SubscriptionState、UpgradePlan、UninstallRequest |
| 交易、权益与结算可见性部分 | 是 | PurchaseSnapshot、EntitlementView、LicenseSummary、InvoiceView、AccessState |
| 评价、反馈与生态运营部分 | 是 | RatingEntry、ReviewEntry、FeaturedSlot、RankingView、AbuseReport、ModerationHint |
| method-library / capability-hub / bridges source truth、本地 package storage、本地支付账本 | 否 | 只验 marketplace 如何消费其输入并组织生态分发/交易体验,不验底层 source truths 与基础设施全部实现 |
| account/member 真相、支付系统本体、auth 本体 | 否 | 只验 marketplace 的 install/subscription/entitlement 可见状态,不验底层账户/支付系统 |
| website / console 的入口壳与页面容器 | 否 | 只验 marketplace 入口消费语义,不验外层容器系统 |

## 4. 功能验收门禁

| 功能/场景 | 门禁条件 | 证据 | 结论 |
|---|---|---|---|
| CreateListing / PublishListing / QueryCatalog | source asset refs 合法时必须形成正式 listing/catalog | API 响应 / DB 记录 / refs compare | [] |
| Listing 边界 | MarketplaceListing 只能表达消费入口,不得替代 source asset truth | listing/source compare / negative flow | [] |
| PublishRelease / BuildCompatibilityMatrix / BuildInstallBundle | package refs 完整时必须形成正式 release/compatibility/install bundle | release row / compatibility badge / bundle refs | [] |
| Release/compatibility 边界 | package listing 不得替代 package definition truth；compatibility badge 不得冒充 runtime guarantee truth | compare report / negative flow | [] |
| CreateInstallRequest / RecordInstall / UpgradeInstall | install/enable/upgrade 必须形成正式消费主线记录 | install request / install record / upgrade plan | [] |
| Install 边界 | InstallRecord 只能表达 marketplace 消费结果,不得替代 installed system truth 或 source activation truth | install/activation compare / negative flow | [] |
| BuildEntitlementView / RecordPurchaseSnapshot | purchase/subscription/entitlement 必须形成正式可见状态视图 | entitlement view / purchase snapshot / license summary | [] |
| Transaction/entitlement 边界 | entitlement 和订阅可见性不得替代 finance ledger truth 或 source authorization truth | compare report / negative flow | [] |
| SubmitRating / SubmitReview / BuildRankingView / BuildFeaturedSlots | rating/review/ranking/featured 必须形成正式生态运营主线 | rating/review records / ranking view / featured slots | [] |
| Review/ops 边界 | rating/review 只是反馈层,不得替代 asset quality truth；ranking/featured 不得替代 source merit truth | review/quality compare / negative flow | [] |

## 8. 缺陷分级与放行规则

| 缺陷级别 | 是否允许放行 | 说明 |
|---|---|---|
| S | 否 | listing 反写真相 / install 冒充激活真相 / entitlement 冒充 ledger 真相 / ranking 无证据链却公开发布 |
| A | 视情况 | 主线可跑但 stale/fallback、compatibility 漂移、entitlement conflict、review/install 上下文不稳 |
| B | 可带着走 | 非关键展示、低优先级 teaser / ranking 文案或细节异常 |

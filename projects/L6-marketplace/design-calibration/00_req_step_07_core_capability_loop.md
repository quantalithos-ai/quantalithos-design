## 3. SOP 问题回答

1. 无本仓缺什么？缺统一且独立于内容 owner 的市场责任、版本可获取性与撤回传播事实。
2. 共同能力？可信来源/发布责任、受控审核/上架、可见发现/版本选择、受控分发、撤回影响/审计恢复。
3. 缺一如何？来源缺失是假商品；治理缺失是自审；发现缺失不能生态复用；分发缺失只是目录；撤回恢复缺失责任不闭合。
4. 外围？评分、推荐、持久收藏、统计、跨产品高级后台与归档。
5. 边界外？资产正文、approval、认证/权限 truth、安装激活、财务与可执行联合包 owner。
6. 功能如何回填？发布材料/publisher 验证归来源；review handoff/版本状态归上架；搜索/分类/详情归发现；获取/接收状态归分发；撤回/通知/安全审计/重试归责任闭环。
7. 拆哪些节点？五个节点，publisher 与引用合为可信发布责任，审计失败恢复不是可选外围。
8. 讨论顺序？C-MP-1 到 C-MP-5；后一节点必须承接前一资格与失败语义。
9. 停审证明？每节点故事、功能、规则、数据归属、接口依赖、质量、验收与证据上限一致；缺口可明确 fail-closed，不可声称正向 ready。

## 7. 结构化中间产物

市场必须有可信且可追溯的资产来源与发布责任，在正式审核约束下形成市场上架事实，使可见用户能选择明确版本并受控获取，最后在撤回与失败时保留影响、通知与恢复责任。五类能力共同成立才是完整市场；缺少分发只是目录，缺少治理或撤回责任则不是可信市场。

```text
C-MP-1 可信来源与发布责任能够成立
  -> C-MP-2 受正式审核约束的市场上架能够成立
  -> C-MP-3 可见资产发现与明确版本选择能够成立
  -> C-MP-4 受控分发及可判别接收关系能够成立
  -> C-MP-5 撤回影响、通知与审计恢复责任能够成立
```

图只表达能力逻辑依赖，不表示调用、传输或实施顺序。审计、幂等、失败和授权约束贯穿所有节点，不由最后一个节点补做前面资格。

| 分类 | 内容 |
|---|---|
| 核心能力闭环 | C-MP-1～5 |
| 外围增强能力 | 收藏、评分评论、推荐排序、高级统计、真实归档恢复及跨产品管理体验 |
| 边界外能力 | 外部正文、Registry truth、Governance approval、身份/授权 truth、安装运行、财务与无 owner 可执行包 |

| 节点 | 进入条件 | 退出/停审证明 | 当前正向前置 |
|---|---|---|---|
| C-MP-1 | Step 1/2 的 owner 边界 | 来源与 publisher 责任可判定、拒绝无 authority | MP-UP-001/003/004、MP-SRC-013 |
| C-MP-2 | C1 资格，不以 UI 自补 | 申请/治理 handoff/市场版本互相区分 | MP-UP-002、MP-SRC-010/011 |
| C-MP-3 | C2 可见版本语义 | 搜索/详情/选择不绕可见性及撤回 | MP-UP-001；查询 projection 不授予资格 |
| C-MP-4 | C3 exact 选择+C1/C2 再校验 | 分发/接收/未知/资格与安装 truth 分离 | MP-UP-005；安全 owner 缺口 |
| C-MP-5 | 前四类关系可追溯 | 停新分发、已知影响边界、通知及审计恢复可判定 | MP-UP-007/008，Archive 可后置但不声称闭合 |

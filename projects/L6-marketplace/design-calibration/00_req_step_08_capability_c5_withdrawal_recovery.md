# C-MP-5. 撤回影响、通知与审计恢复需求小循环

## 1. 能力状态与计划

`pass / stop_review`；C1～4 停审。输入/问题/诊断/取舍 done，结构化/草稿/自检 pending。

## 2. 输入

前四能力关系/版本/资格与 pending；MP-UP-007/008、MP-SRC-005/008/012；Observability 正式安全审计边界，Archive source matrix 没有市场；产品 MK4/5 与子项目 MK4 区分。

## 3. SOP 问题回答

1. 故事：发布者/维护者希望停新分发并处理已知影响；消费者需要知道自己已获取版本的变化；审计者与维护者需要追溯失败并恢复而不造成功。
2. 功能：有依据撤回/限制，影响关系枚举与通知，局部审计与外部 handoff，受控重试/重建/对账。市场只能枚举已知分发关系，不宣称知道所有实际安装用户。
3. 规则：撤回立即影响新的获取资格，通知失败不能回滚撤回；有限资格未知时暂停新分发而非假撤销外部 truth。送达/已读/已处置不同；改变安装/源 truth 必须 owner；重复/乱序提示重核验，不自行生成 authority。
4. 数据：局部撤回事实/影响集合/通知计划与attempt/安全审计历史本地 truth；渠道结果、审计/归档引用只引用；外部日志/证据/包正文不入市场。
5. 接口：显式撤回、受控正式来源变更映射、追溯查询、后台通知/交接/对账。Marketplace producer admission、receipt 和 redaction 待闭合；Archive 未授权 source 不默认启用导出恢复。
6. 质量：局部业务变更与历史/后续影响意图一致提交；按版本/关系范围稳定枚举/分页去重，cursor 不当权限；未知接收用户通知亦需保守覆盖，范围不完整有标记。重试同 intent，持久 attempt 与结果可查。
7. 验收：并发上架/获取/撤回、已确认与未知交接关系、通知失败/未知/重复、owner 来源失效、审计 receiver unavailable、索引丢失均可判别；重建来源是局部已提交 truth 或正式 owner snapshot，不能由 projection 造 truth；不自动删除历史/外部数据。

## 4. 诊断

旧00 §5 US-005 承诺已安装用户收到通知但无安装关系 authority；旧§7 notification 100% 未区分覆盖/送达。draft01 Archive handoff 图将未纳入 source matrix 的市场 lane 画成成立；不能把 local audit=observability accepted，或恢复包校验=业务恢复。

## 5. 改前后

| 项 | 改前 | 改后 | 原因 |
|---|---|---|---|
| 影响人群 | 全部已安装用户 | 已知分发关系及未知交接保守影响、范围缺口标记 | 市场不拥有安装 census |
| 通知 | attempt=送达 | 计划、尝试、receipt、送达、用户处置分开 | 不能伪造通知成功 |
| 审计/归档 | 默认全局完成 | local history、外部交接和条件归档分开 | source/admission 未闭合 |

## 6. 取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 先停新分发、保守影响、独立通知状态 | 安全且可恢复 | 渠道/审计正向合同仍缺 | 采用 |
| 通知成功才完成撤回 | 简单一状态 | 渠道故障继续风险分发 | 不采用 |
| 市场自动卸载/修复/全局归档恢复 | 用户感觉闭环 | 越权接收系统/Archive truth | 不采用 |

## 1. 一句话定位

`L6-marketplace` 是面向生态资产的发布申请、目录 listing、版本上架、分发关系、撤回通知和受控获取视图边界。它把 owner 提供的不可变资产引用、版本、摘要、签名/扫描材料引用和 Governance 正式决定组织为可搜索、可审核、可获取和可追溯的 marketplace 体验，但不拥有资产正文、治理批准、身份真相、运行时激活或财务账本。

它回答的是：

```text
在当前 publisher、visibility、owner reference 和 Governance decision 均可验证的前提下，
这个资产是否存在 marketplace listing、哪个版本可被展示/获取、哪些用户或组织可看到，
以及撤回或分发变化应如何被记录和通知。
```

它不回答的是：

```text
资产正文是什么、方法/工具如何实现、谁拥有身份、治理是否应该批准、
安装后系统是否真的激活、支付是否已经结算、运行时是否兼容。
```

## 2. 为什么必须单独存在

### 首版讨论范围：可发布内容

2026-10-01 用户确认当前原型第一版暂按现状收口；此确认不是正式需求、上游合同或实现验收。

| 资产类型 | 正文拥有方 | Marketplace 边界 |
|---|---|---|
| 方法资产 | `L3-method-library` | 引用方法定义版本，组织展示与发布申请。 |
| 流程模板 | `L3-method-library` | 引用模板版本，不拥有流程执行真相。 |
| 角色定义 | `L3-method-library` | 引用可复用角色定义，不替代 Identity 的角色、身份或成员资格。 |
| 能力资产 | `L3-capability-hub` | 引用能力版本，不复制 Registry/Adapter truth。 |
| 成员镜像 | `L2-member-images` | 引用镜像版本及审核材料，不保存镜像内容。 |

五类均为首版讨论范围，不表示正向发布/获取合同已经闭合。文件格式不是资产类型，存在 Artifact 引用也不自动获得上架资格。

资产集合可以组织多个已存在的版本引用；可执行 Deployment Package 必须另行明确 package owner、依赖、安装与回退合同。技能包、共享规则、UI 组件、应用作品暂列待支持；身份、账号和治理审批结果不得作为市场资产。

| 易混淆对象 | 边界结论 |
|---|---|
| `L3-method-library` | 拥有 method、role、process template 定义；Marketplace 只保存 owner ref、版本、摘要和发布入口。 |
| `L3-capability-hub` | 拥有 capability registry、adapter/provider contract 和工具能力真相；Marketplace 不注册工具，也不复制 adapter truth。 |
| `L2-member-images` | 拥有镜像内容与构建资产；Marketplace 只引用可分发镜像版本，不拥有镜像正文。 |
| `L1-artifact` | 拥有 Artifact、Evidence、Baseline 正文、版本和血缘；Marketplace 只消费不可变 artifact/package ref。 |
| `L1-governance` | 拥有 Gate、Approval、Decision、Policy 和治理控制真相；Marketplace 必须消费正式决定，不能自行产生 approval。 |
| `L1-identity` | 拥有 GlobalMember、Actor、Role 和身份生命周期；Marketplace 只绑定 publisher/consumer 的正式身份引用。 |
| `L0-sdk` | 提供统一访问、事件和错误封装；Marketplace 不把 SDK cache 或 client state 当领域真相。 |
| `L4-observability` | 拥有观察材料、审计投影和交接面；Marketplace 只提供可审计的 marketplace-local 事实与引用。 |
| `L4-archive` | 拥有归档/恢复材料边界；Marketplace 可被归档或提供 handoff，但不拥有 archive package truth。 |
| Billing / payment / subscription | 当前无正式 owner；Marketplace 只能保留局部可见状态或 future/blocker，不建立 finance ledger。 |

若没有独立 Marketplace，发布者、产品入口和各资产 owner 会分别拼接发布状态、版本选择、可见性和撤回通知，形成多个互相冲突的生态入口。若 Marketplace 越界，则会变成资产第二真相源、隐性治理中心或伪造支付系统。

## 3. 本仓拥有 / 只消费 / 禁止拥有

| 主题 | Marketplace 拥有 | 只消费 / 回链 | 禁止拥有 |
|---|---|---|---|
| Listing | listing identity、目录分类、公开摘要、可见性状态、publisher relation、来源引用集合。 | owner asset ref、source version、摘要、可见性决定。 | 资产正文、owner 版本链、方法/工具实现。 |
| Release | marketplace 版本上架状态、channel、分发关系和兼容性声明视图。 | owner package/version ref、兼容性材料和正式 runtime 约束。 | package definition truth、runtime guarantee、安装后激活真相。 |
| Review handoff | 发布申请、审核上下文、Governance decision ref、材料缺口和 handoff 状态。 | Governance 正式决定、Artifact/Evidence ref、签名/扫描结果 ref。 | approval、verdict、签名、扫描或 ACK 本身。 |
| Distribution | 获取/安装请求、分发 attempt、delivery ref、撤回状态和通知记录。 | 外部 package store、owner delivery、consumer/installation receiver 结果。 | 安装系统状态、源包激活状态、底层存储 truth。 |
| Publisher relation | publisher profile 引用、验证状态视图、组织关联和发布责任绑定。 | Identity truth、组织凭证、验证服务结果。 | 认证、实名或组织身份真相。 |
| Entitlement / transaction 局部状态 | 明确纳入范围的 entitlement/transaction 可见状态、来源和未知/阻塞标记。 | 正式授权、支付/订阅/账单结果。 | finance ledger、支付结算、收入分成、跨境交易真相。 |
| Audit / notification | marketplace-local 操作记录、撤回影响范围、通知 attempt 和结果。 | Observability audit handoff、下游接收确认。 | 全局审计库、业务 owner 审批记录、通知渠道 truth。 |

## 4. 交互对象总览

```text
                           +----------------------+
                           |       L0-core          |
                           | shared refs/errors    |
                           +-----------+------------+
                                       |
                                       v
                           +----------------------+
                           |       L0-sdk           |
                           | access/event boundary  |
                           +-----------+------------+
                                       |
                                       v
+----------------------+      +-------+--------+      +----------------------+
| L3-method-library    |----->|                |<-----| L3-capability-hub    |
| method/role/template | refs |                | refs  | capability/tool       |
| source truth         |      | L6-marketplace |      | source truth          |
+----------------------+      |                |      +----------------------+
                              +---+---------+--+
                                  ^         ^
                                  |         |
                    owner refs    |         | governance decision refs
                                  |         |
             +--------------------+--+   +--+---------------------+
             | L2-member-images       |   | L1-governance           |
             | image/build truth      |   | Gate/Approval/Decision  |
             +-----------------------+   +--------------------------+
                                  ^
                                  |
                 +----------------+----------------+
                 | L1-artifact / L1-identity       |
                 | body/ref and publisher truth    |
                 +---------------------------------+

        +------------------+     +------------------+     +------------------+
        | L5-console       |     | L5-website       |     | L5-sync / bridges|
        | admin/review UI  |     | public catalog   |     | consume/notify   |
        +--------+---------+     +--------+---------+     +--------+---------+
                 |                        |                       |
                 +------------------------+-----------------------+
                                          v
                                 marketplace read surface

        L4-observability <---- audit/trace handoff ---- L6-marketplace
        L4-archive        <---- archive/export handoff - L6-marketplace
```

图示只表达边界方向：owner 提供引用与材料，Governance 提供正式决定，Marketplace 组织生态状态，下游入口消费稳定读面。它不表示共享数据库、跨仓事务或已存在的具体 event schema。

## 5. 本仓依赖裁剪表（候选）

| 关联项目 | 全局关系 | 本仓角色 | 依赖类型 | 是否进入当前主链 | 裁剪理由 |
|---|---|---|---|---|---|
| `L0-core` | shared contract base | 依赖方 | `compile` candidate | 条件型 | 仅复用已正式导出的 ref、错误、版本和事件契约；不在本仓 shadow。 |
| `L0-sdk` | official access layer | 被依赖/协作方 | `adapter + ref` | 是 | 通过正式 SDK/API 暴露 marketplace 读写面；SDK 不成为 marketplace truth。 |
| `L1-identity` | identity owner | 只读消费者 | `runtime + ref + event` | 是 | publisher、actor、consumer 绑定只使用正式身份引用。 |
| `L1-governance` | decision owner | 必要前置协作方 | `runtime + ref + event` | 是 | 上架审核必须消费正式 Governance decision；无决定则 blocked。 |
| `L1-artifact` | artifact/evidence owner | 只读消费者 | `runtime + ref + event` | 是 | 只接收不可变资产/证据引用，不保存正文。 |
| `L3-method-library` | method/role/template owner | 资产来源方 | `runtime + ref + event` | 是 | 维护资产来源、版本和发布资格，Marketplace 仅组织入口。 |
| `L3-capability-hub` | capability/tool owner | 资产来源方 | `runtime + ref + event` | 是 | 维护 capability/tool truth，Marketplace 不注册或改写 adapter。 |
| `L2-member-images` | image/build owner | 资产来源方 | `runtime + ref + event` | 条件型 | 仅对明确纳入的镜像资产消费版本与构建引用。 |
| `L4-observability` | observation/audit owner | 交接/消费方 | `runtime + ref` | 是 | 提供 audit handoff；不把 Marketplace 事实升级成全局审计 truth。 |
| `L4-archive` | archive/recovery owner | 下游交接方 | `runtime + ref` | 后续 | 只提供归档/恢复 handoff，不反向定义当前 listing truth。 |
| billing/payment | 未有正式 owner | future/blocker | `external` | 否 | 不在本轮私造交易、订阅、收入或支付真相。 |

## 6. 禁止依赖与历史材料处置

| 禁止依赖/做法 | 禁止原因 | 正确协作方式 |
|---|---|---|
| 复制 method、role、template、tool、image 或 artifact 正文 | 形成第二套资产真相。 | 保存 owner ref、版本、摘要、digest/visibility 引用。 |
| Marketplace 自行创建 marketplace-review approval | 把分发层变成治理中心。 | 消费 `L1-governance` 正式 decision/ref。 |
| 把签名、扫描、ACK 当成审核通过 | 技术材料不能替代 Governance verdict。 | 作为审核材料引用和失败条件输入。 |
| 共享 owner 表、跨仓事务或直接读取内部表 | 破坏 ownership 和可恢复边界。 | 经正式 query/event/adapter seam 协作。 |
| 建立本地 payment/finance ledger | 当前没有正式 billing owner。 | 记录 `unknown / blocked / future` 的局部可见状态。 |
| 把 install record 当成系统已激活 | Marketplace 无法证明运行时提交。 | 记录分发 attempt 和 receiver result，激活由 owner 负责。 |

旧 README 和旧正式文档中的 TypeScript Web、Python CLI、Trivy/Grype、cosign、29110 包、购买/订阅等只作为历史意图；具体技术、协议、工具和指标必须在后续 SOP 中重新闭合，不能直接继承为当前设计结论。

## 7. 当前 pending / blocker 候选

| ID | 未闭合边界 | 当前影响 |
|---|---|---|
| `MP-UP-001` | 各 owner 的不可变 asset ref、版本、摘要、可见性和撤回引用字段未统一。 | 只能定义引用边界，不能锁定 DTO/协议字段。 |
| `MP-UP-002` | Governance 上架审核 decision 的输入、状态、撤回/复审和适用范围未形成 Marketplace 专用消费合同。 | 未取得正式 decision 时必须 blocked。 |
| `MP-UP-003` | Publisher identity、组织凭证和验证结果的正式来源与生命周期未闭口。 | 只能保存 identity ref/验证视图，不能自行实名验证。 |
| `MP-UP-004` | 签名、扫描、SBOM/材料引用及其失效语义未统一。 | 只能记录材料 ref/status，不得判定 approval。 |
| `MP-UP-005` | Package delivery、install receiver、installed activation 的 owner 和回执语义未闭口。 | 只能描述获取/分发 attempt，不能承诺安装成功。 |
| `MP-UP-006` | Billing、支付、订阅、分成和跨境交易没有正式 owner。 | 商业状态必须 `future / blocked / unknown`。 |
| `MP-UP-007` | 撤回影响范围、通知渠道、重试和用户处置建议尚无统一合同。 | 可记录撤回与通知 attempt，不能承诺送达。 |
| `MP-UP-008` | Marketplace 与 Observability/Archive 的审计和归档 handoff 未闭口。 | 保留 adapter/ref seam，不宣称 audit/archive 完成。 |

## 8. 本篇讨论结论

本轮把 Marketplace 收敛为“资产引用驱动的生态发布与分发边界”：它拥有 listing、版本上架、分发、撤回、通知和有限商业可见状态；它依赖 owner ref 与 Governance 正式决定；它不拥有任何资产正文、审批结论、身份真相、运行激活或财务账本。后续 `02` 将在这一边界上推演能力闭环，所有 `MP-UP-001~008` 在正式合同闭合前继续保持 pending/blocker。

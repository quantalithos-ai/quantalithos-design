# 02 · L6-marketplace 功能推演（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源\
> 前置：`draft/01_项目作用与交互对象.md`\
> 本文回答：Marketplace 需要形成什么能力闭环；发布申请、审核 handoff、listing、版本、获取、撤回、通知、publisher 验证和审计如何分层；哪些能力因上游合同未闭口保持 pending/blocker。

本文不锁定 API 路径、事件 schema、数据库表、代码模块、支付方案、扫描工具或实现仓。

## 1. 核心能力闭环

Marketplace 的核心闭环是：

```text
publisher / owner reference 验证
        -> 发布申请与材料收集
        -> Governance 正式审核 handoff
        -> listing / visibility / category 形成
        -> 版本上架与分发关系建立
        -> 用户查询、选择、获取/安装请求
        -> 撤回、影响范围计算与通知 attempt
        -> 审计、重试、失效与恢复
```

核心能力节点：

| ID | 能力节点 | 成立条件 | 不代表 |
|---|---|---|---|
| `C1` | Owner asset reference intake | owner ref、版本、摘要、可见性和发布资格可验证 | Marketplace 获得资产正文所有权。 |
| `C2` | Publisher relation and verification view | identity/组织引用和验证结果可解释 | Marketplace 执行认证或实名审核。 |
| `C3` | Release application and Governance handoff | 申请材料完整，能交给 Governance 并接收正式 decision/ref | Marketplace 产生 approval。 |
| `C4` | Listing/catalog publication | decision、visibility、category 和 source refs 均有效 | listing 变成 source asset truth。 |
| `C5` | Version selection and distribution | 可用 release、channel、delivery ref 和权限语境可验证 | 安装系统已经激活。 |
| `C6` | Revocation and impact notification | 撤回来源、影响范围、通知渠道/receiver 可解释 | 通知已送达或用户已完成处置。 |
| `C7` | Audit/provenance and failure recovery | listing/release/distribution/notification 均有 provenance、状态和重试边界 | Observability/Archive/Finance 已完成。 |

核心能力缺一不可：没有 `C3`，上架审核会退化为 Marketplace 自审；没有 `C5`，listing 只是目录；没有 `C6`，撤回会留下安全与用户影响缺口；没有 `C7`，无法区分未处理、失败和未知结果。

## 2. 主要功能主题

### 首版消费者与发布者补充范围

- 消费者目录按五类稳定资产类型筛选，不按示例条目 ID 分类；同类允许多个 Listing。
- 支持浏览、搜索、对应资产详情、浏览器会话内收藏/取消收藏及演示获取记录。
- 详情分别显示资产拥有方、来源版本、引用与接收合同缺口、审核材料和状态。
- 发布申请按类型选择 owner：方法/模板/角色关联 Method Library，能力关联 Capability Hub，镜像关联 Member Images。
- 申请材料包括不可变引用、版本、摘要校验值、展示摘要及审核材料引用；镜像需显式展示签名、扫描和 SBOM 引用要求。
- 展示“待支持类型”，不把缺少 owner 的类型混入正常申请选项。
- 预览、评价和统计需有来源；暂无材料时显示缺失，不伪造截图、评分或质量结论。

这些是第一版原型讨论输入。收藏属于候选消费者局部状态；持久化、作用域与正式接口须在后续 SOP 独立确认。获取记录只表达请求/交接，不表达安装激活。

| 功能主题 | Marketplace 对外行为 | 依赖/约束 | 当前状态 |
|---|---|---|---|
| 发布申请 | 接收 publisher、asset ref、版本、摘要、分类、可见性和审核材料引用。 | 不接收或保存资产正文；缺 owner ref 即拒绝或 blocked。 | 可推演 |
| publisher relation | 绑定 publisher identity/organization ref 和验证状态。 | identity owner 提供正式引用与验证结果。 | pending `MP-UP-003` |
| 审核 handoff | 形成 review case，提交 Governance，记录 decision ref、缺口和回退状态。 | 不自行通过/拒绝；签名/扫描只作材料。 | pending `MP-UP-002/004` |
| listing/catalog | 创建、更新、隐藏、公开或限制 listing，支持分类、标签、排序和搜索投影。 | 可见性以正式 owner/Governance 结论为门槛。 | 可推演 |
| 版本上架 | 选择 owner release/version ref，维护 channel、兼容性声明视图和上架状态。 | 不替代 package definition 或 runtime compatibility truth。 | pending `MP-UP-001/005` |
| 获取/安装请求 | 记录用户/组织获取、下载、安装或订阅请求及 delivery handoff。 | 外部 delivery/receiver 结果必须可区分成功、失败、未知。 | pending `MP-UP-005/006` |
| entitlement 局部视图 | 展示明确来源的授权/订阅/可获取状态。 | 不建立支付、账单、授权本体。 | blocked `MP-UP-006` |
| 撤回 | 标记 listing/release withdrawn、冻结新获取、保留影响范围和原因。 | 撤回来源可来自 publisher、Governance 或 owner；语义待统一。 | pending `MP-UP-007` |
| 影响通知 | 生成已获取/安装关系的通知计划、attempt、重试和结果。 | 不把 attempt 当送达；通知渠道由正式 owner 提供。 | pending `MP-UP-007` |
| 审计与恢复 | 暴露 provenance、状态变化、失败原因、重试和人工介入边界。 | 只交接给 Observability/Archive，不伪造外部证据。 | pending `MP-UP-008` |

## 3. 发布到分发的候选流程

```text
[Publisher]
    |
    | submit asset_ref + version + publisher_ref + materials
    v
[Marketplace Release Application]
    |
    | validate refs / visibility / completeness
    +---- invalid ----> [rejected or blocked; no listing]
    |
    v
[Governance Review Handoff]
    |
    | formal decision/ref only
    +---- pending/rejected/revoked ----> [no public listing]
    |
    v
[Listing + Catalog Projection]
    |
    v
[Release/Channel Selection]
    |
    v
[Get/Install/Delivery Handoff]
    |
    +---- success/partial/unknown ----> [local distribution record]
    |
    v
[Audit + Consumer View]

[Owner/Governance Revocation]
    -> [withdraw listing/release]
    -> [freeze new distribution]
    -> [compute affected relations]
    -> [notification attempts]
    -> [observability/archive handoff]
```

该流程的每个箭头都表示边界交接，不表示跨仓原子事务。任何 external commit unknown 都必须保持 unknown/blocked，不能由 Marketplace 推断成功。

## 4. 用户故事方向

| ID | 用户故事 | 核心能力 | 验收方向 |
|---|---|---|---|
| `US-MP-001` | 作为 publisher，我希望提交带有 owner ref 和版本的资产申请，以便进入受控审核。 | C1/C3 | ref 缺失、版本不一致或可见性不可验证时不得形成公开 listing。 |
| `US-MP-002` | 作为 reviewer，我希望看到完整的审核 handoff 和 Governance decision ref，以便知道 Marketplace 没有自审。 | C3 | 无正式 decision 时保持 pending/blocked。 |
| `US-MP-003` | 作为消费者，我希望按分类、标签和版本筛选可见资产，以便选择可获取版本。 | C4/C5 | 不可见、撤回或无有效版本不得出现在可获取结果中。 |
| `US-MP-004` | 作为组织管理员，我希望看到 publisher、版本、兼容性材料和来源引用，以便评估分发风险。 | C1/C2/C5/C7 | 每个显示项可回链 owner ref 和材料状态。 |
| `US-MP-005` | 作为消费者，我希望发起获取/安装请求并知道结果是成功、失败还是未知。 | C5 | 不把请求记录当成已安装或已激活。 |
| `US-MP-006` | 作为发布者或授权审核角色，我希望撤回资产并触发影响通知，以便停止新的分发并告知受影响用户。 | C6 | 撤回会冻结新分发；通知未送达时保留可见失败状态。 |
| `US-MP-007` | 作为审计者，我希望追溯 listing、release、distribution、revocation 和 notification 的来源与状态变化。 | C7 | 每条记录有 provenance、时间、状态和失败边界。 |

## 5. 状态与结果语义方向

### 5.1 发布申请 / 审核 handoff

```text
draft -> submitted -> validating -> review_pending
review_pending -> approved_by_governance -> listing_eligible
review_pending -> rejected / blocked / withdrawn
approved_by_governance -> revoked
```

`approved_by_governance` 只表示收到可验证的 Governance decision ref；它不表示签名、扫描、安装、支付或运行时兼容已成功。

### 5.2 Listing / release

```text
candidate -> hidden -> public/restricted
public/restricted -> superseded / withdrawn / blocked
candidate -> rejected
```

### 5.3 Distribution / notification

```text
requested -> accepted -> handing_off
handing_off -> succeeded / failed / partial / commit_unknown

planned -> sending -> delivered / failed / retrying / unknown
```

具体状态枚举、转换条件和 owner 必须在后续 02/03 校准中逐项锁定。

## 6. 失败与降级原则

| 失败类型 | Marketplace 行为 | 禁止推断 |
|---|---|---|
| owner ref 缺失/过期 | 拒绝 listing 或标记 blocked | 不能复制旧正文补齐。 |
| Governance decision 缺失/冲突 | 不公开、不上架、保持 pending/blocked | 不能用 reviewer 操作、ACK 或扫描结果替代 approval。 |
| publisher identity 未知 | 限制发布申请或保持验证 pending | 不能本地创建身份或组织凭证。 |
| 签名/扫描未知或失败 | 标记材料状态，按策略阻止对应发布 | 不能宣称治理通过或资产安全。 |
| delivery/receiver unknown | 记录 commit_unknown，允许重试/人工介入 | 不能宣称已安装、已激活或已授权。 |
| 撤回通知失败 | listing 继续 withdrawn，通知状态重试/失败 | 不能宣称用户已收到。 |
| billing 缺失 | entitlement/transaction 显示 unknown/future/blocker | 不能建立金额、账单、分成或支付结果。 |

## 7. 读面与消费者交互

Marketplace 对外读面至少需要能够表达：

```text
listing identity
source asset ref / version
publisher ref / verification status
visibility / governance decision ref
release/channel state
compatibility/material references
distribution state
withdrawal reason/status
notification status
provenance / coverage / degraded status
```

读面不得把缺失字段静默转成默认公开、默认兼容、默认已安装或默认已支付。任何降级均需带原因和证据边界。

## 8. 本篇讨论结论

Marketplace 的核心闭环不是“把资产展示出来”，而是“引用验证 → Governance handoff → listing/version → controlled distribution → withdrawal/notification → audit/recovery”。其中审核、签名、扫描、身份、支付和安装激活均有外部 owner；在 owner 合同未闭合前，Marketplace 只保留引用、状态、阻塞和交接语义，不补造成功事实。

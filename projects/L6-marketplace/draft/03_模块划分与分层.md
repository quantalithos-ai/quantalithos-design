# 03 · L6-marketplace 模块划分与分层（draft）

> 状态：`draft / pre-calibration`，非正式设计真相源\
> 前置：`draft/01_项目作用与交互对象.md`、`draft/02_功能推演.md`\
> 本文回答：为了形成 Marketplace 发布与分发闭环，需要哪些候选业务组成部分、实现分层、关键对象、状态组和外部 seam；哪些部分因上游合同未闭口保持 blocked。

本文只做模块预推演，不创建 package、trait、数据库表、接口路由、事件 schema、配置键、测试报告或实现承诺。

## 0. 项目内运行单元边界

首版 UI 由消费者目录/详情/收藏与获取记录、Publisher 发布申请、运营审核交接/版本分发/撤回通知/恢复三类表面组成。同一项目内分工，不新增独立设计仓。

目录使用稳定资产类型键 `method / template / role / capability / image`，不能将 Listing ID 当分类。发布表单的 owner 与材料说明随类型变化，但不会在前端创建 source truth 或批准结论。

本项目保持一个 `L6-marketplace` 设计仓，但实现形态拆为前端、API、Worker 和共享包。前端只负责展示/输入，API 负责请求边界，Worker 负责异步维护；Marketplace 领域规则不放在 UI 中。

```text
marketplace-web       -> catalog / publisher / admin UI
marketplace-api       -> command/query HTTP boundary
marketplace-worker    -> projection / retry / notification / recovery
shared packages       -> contracts / domain / application / adapters
```

这些是运行和代码组织边界，不是新的正式项目依赖，也不改变 Marketplace 对 source truth、Governance、Identity、Artifact、Billing、Observability 或 Archive 的 ownership 约束。

## 2. 实现分层（候选）

| 分层 | Marketplace 内职责 | 边界与纪律 |
|---|---|---|
| Inbound / Operations | 接收发布申请、审核回执、获取/安装请求、撤回请求、通知/维护触发。 | 不在入口直接写 owner truth；transport/SDK 不进入领域语义。 |
| Application Services | 编排 ref 验证、发布 handoff、listing/release 变化、分发、撤回、通知和查询。 | 跨仓调用只能经正式 port；外部 unknown 必须保留。 |
| Domain Model / Policies | 定义 listing、release、review handoff、distribution、withdrawal、notification、provenance 的本地不变量。 | 不解析资产正文，不生成 Governance approval，不推断 payment/activation。 |
| External Ports / Seams | owner ref/query、identity verification、Governance decision、signature/scan material、delivery receiver、notification channel、observability/archive handoff。 | port 不是 owner；未闭口 seam 返回 pending/blocked/unknown。 |
| Persistence / Projection | 保存 Marketplace-owned listing/release/review/distribution/withdrawal/notification 局部事实与查询投影。 | 不存外部正文，不共享 owner 表，不让 projection 变成 source truth。 |
| Index / Catalog Projection | 维护分类、标签、搜索、排序和 visibility 过滤投影。 | 撤回/失效优先于缓存；索引不是授权真相。 |
| Maintenance / Recovery | 幂等重试、过期 ref 检查、撤回影响重算、索引重建和 handoff 对账。 | 不自动修复 owner truth，不把 job success 当外部完成。 |

### 2.1 候选代码主体映射

```text
Marketplace listing core              -> domain listing/release aggregate
Publisher verification                -> publisher relation service / port
Review handoff                        -> review application service / decision port
Version and distribution              -> release/distribution service / receiver port
Catalog/search                        -> read projection / index adapter
Withdrawal/notification               -> withdrawal service / notification port
Entitlement local view                -> external-state view assembler
Provenance/audit/recovery             -> provenance recorder / maintenance jobs
```

上述名称只表达职责，不授权创建同名 crate、module、table 或 API。

| `ReviewHandoff` | 记录发布申请、材料集合、Governance decision ref、缺口和回执状态。 | 不拥有 approval/verdict。 |
| `DistributionRecord` | 记录获取/安装请求、delivery ref、receiver handoff 和结果状态。 | 不表示 installed system truth。 |
| `WithdrawalRecord` | 记录撤回来源、原因、影响范围、冻结时间和状态。 | 不改变 owner asset truth 或用户系统状态。 |
| `NotificationAttempt` | 记录受影响关系、渠道引用、发送 attempt、重试和结果。 | 不表示实际送达或用户已处置。 |

### 3.2 外部引用与材料视图

| 类别 | Marketplace 如何使用 | 禁止保存 |
|---|---|---|
| Asset owner ref | 建立 listing/release 来源绑定。 | asset/method/tool/image/package 正文。 |
| Governance decision ref | 判定是否可进入 listing eligible/publication。 | approval body、policy body、替代 verdict。 |
| Publisher identity ref | 绑定 publisher 与 organization 关系。 | 身份凭证、认证密钥、GlobalMember 正文。 |
| Signature/scan/SBOM ref | 记录材料存在、版本、状态和失效原因。 | 将材料复制成审核结论或完整扫描数据库。 |
| Delivery/receiver ref | 建立获取/安装 handoff。 | installed activation、runtime state、receiver 内部表。 |
| Audit/archive handoff ref | 交接操作和来源材料。 | 全局 observability backend、archive package body。 |

## 4. 状态组与一致性边界（候选）

| 状态组 | 承载对象 | 状态候选 | 不变量 |
|---|---|---|---|
| Publisher verification | `PublisherRelation` | unknown / pending / verified / restricted / revoked | unknown 不得转为 verified；Marketplace 不自行验证身份。 |
| Review handoff | `ReviewHandoff` | draft / submitted / validating / pending_governance / approved_ref / rejected / blocked / revoked | approved 只能由正式 Governance decision ref 驱动。 |
| Listing visibility | `MarketplaceListing` | hidden / restricted / public / superseded / withdrawn / blocked | visibility 不可绕过 Governance/owner 撤回或失效。 |
| Release publication | `ReleaseListing` | candidate / eligible / published / deprecated / withdrawn / blocked | published 只表示 marketplace 可分发，不表示运行时兼容或激活。 |
| Distribution | `DistributionRecord` | requested / accepted / handing_off / succeeded / failed / partial / commit_unknown | commit_unknown 不得折算为 succeeded。 |
| Withdrawal | `WithdrawalRecord` | requested / validating / effective / frozen / notification_pending / completed / partial / blocked | effective 需冻结新分发；通知完成另行判定。 |
| Notification | `NotificationAttempt` | planned / sending / delivered / failed / retrying / unknown | attempt 不等于送达，不等于用户处置。 |
| External commercial view | entitlement/transaction view | unavailable / pending / active_view / expired_view / blocked / unknown | 不产生 finance ledger 或 payment success。 |

### 4.1 关键一致性规则

1. **Source-owned 与 Marketplace-owned 分离**：Marketplace local transaction 只能改变 listing/release/distribution/notification 等局部事实，不能改变 owner asset、Governance、Identity、Artifact 或 runtime truth。
2. **Governance first**：没有可验证的正式 decision/ref，listing 不得进入公开或可获取状态；签名、扫描、ACK 不能替代该条件。
3. **Visibility fail-closed**：可见性、publisher、owner ref 或撤回状态未知/冲突时，查询与分发面必须限制、隐藏或 blocked。
4. **Version reference integrity**：listing/release 必须绑定不可变 source version；版本变化形成新局部记录或显式 supersession，不覆盖旧来源。
5. **Distribution separation**：获取请求、delivery handoff、receiver result 和 installed activation 是不同状态链，不能互相推导。
6. **Commercial separation**：transaction/entitlement view 只能消费正式外部状态；没有 billing owner 时保持 unknown/future/blocker。
7. **Idempotent external effects**：同一发布申请、撤回、分发或通知 intent 重复提交不能产生重复有效记录；外部副作用必须有幂等键和 unknown 处理。
8. **Provenance required**：每个公开 listing、release、withdrawal 和 distribution result 都必须能回链 owner ref、版本、decision/material 状态和局部变更来源。

### 4.2 建议的事务/交接边界

| 用例 | Marketplace 内可原子收口 | 外部边界 / 禁止假设 |
|---|---|---|
| 创建发布申请 | application、publisher relation ref、asset/version refs、材料清单。 | owner ref 合法性和 Governance 接受需外部确认。 |
| 接收 Governance decision | handoff 状态、decision ref、listing eligibility。 | 不等于 source asset、扫描或支付成功。 |
| 发布 listing/release | listing/release、catalog projection、provenance。 | 不写 owner asset，不保证 runtime compatibility。 |
| 记录 distribution intent | distribution record、idempotency、delivery handoff 状态。 | receiver commit/installed activation 在外部。 |
| 生效撤回 | withdrawal、listing/release freeze、影响关系快照。 | 通知送达与用户处置另行完成。 |
| 记录 notification attempt | attempt、重试计数、结果和 provenance。 | 渠道 delivery truth 在外部。 |
| 查询 catalog | 纯读取 listing/release/index/provenance。 | 不隐式刷新、发布、通知或改变状态。 |

## 5. 关键 port / seam 类别

| seam | 方向 | 能力语义 | 当前约束 |
|---|---|---|---|
| Asset owner ref resolver | 出站 | 验证资产 owner、版本、摘要、可见性和撤回输入。 | 不读内部表；缺合同则 blocked。 |
| Publisher identity resolver | 出站 | 获取 publisher/organization ref 和验证结果。 | 不自行认证或持有凭证。 |
| Governance decision port | 双向 | 提交 review handoff、读取正式 decision/ref。 | Marketplace 不生成 approval；pending/rejected/unknown 必须显式。 |
| Artifact/material ref port | 出站 | 获取签名、扫描、SBOM、Evidence 等材料引用/状态。 | 材料不能自动升级为 approval。 |
| Delivery/installation receiver | 出站 | 交接 package/version 获取或安装请求，接收结果。 | 不把 receiver 成功外推为系统激活。 |
| Notification channel port | 出站 | 提交撤回影响通知并接收发送结果。 | 未闭合渠道合同不得宣称 delivered。 |
| Catalog/search read port | 出站 | 提供公开/组织/受限目录查询和版本选择。 | visibility/withdrawal 先于索引命中。 |
| Observability handoff | 出站 | 提交 marketplace-local audit/provenance 材料。 | 不拥有全局 audit truth。 |
| Archive handoff | 出站 | 提交可归档 listing/release/withdrawal/distribution 材料引用。 | 不拥有 archive package 或恢复结果。 |
| Billing/entitlement port | 出站，future | 获取支付/订阅/权益可见状态。 | 当前无 owner，保持 blocked/future。 |

`fake` 只能在后续测试中模拟上述 seam 的成功、缺失、延迟、冲突和 unknown；不能证明真实 owner、Governance、支付或 receiver 已完成集成。

## 6. 模块裁剪与推进顺序建议

| 阶段方向 | 最小组成部分 | 进入条件 | 当前状态 |
|---|---|---|---|
| A. listing/reference foundation | 1、2 的最小子集 | 至少一个 owner ref、publisher ref 和 visibility 输入可验证。 | `MP-UP-001/003` 控制。 |
| B. Governance handoff | 3、8 的最小子集 | review input、decision/ref、材料失败语义闭口。 | `MP-UP-002/004` 控制。 |
| C. catalog/publication | 1、5 的最小子集 | listing eligible、撤回与可见性语义稳定。 | 可继续推演。 |
| D. version/distribution | 4、8 的最小子集 | release ref、delivery receiver 和结果状态闭口。 | `MP-UP-005` 控制。 |
| E. withdrawal/notification | 6、8 的最小子集 | 影响关系、通知渠道、重试与未知状态闭口。 | `MP-UP-007` 控制。 |
| F. entitlement view | 7 的最小子集 | 正式 billing/authorization owner 出现。 | `MP-UP-006` blocked。 |
| G. archive/audit handoff | 8 的 handoff 子集 | Observability/Archive 接口正式化。 | `MP-UP-008` 控制。 |

第一版不应从“完整商店”反推所有能力，而应先证明一个资产类型、一个 publisher relation、一个 Governance handoff、一个可见 listing 和一个可区分的 distribution/withdrawal 失败链路。每新增一种资产类型，都必须独立完成 owner ref、版本、可见性、审核材料和分发 receiver 的闭环。

## 7. 本篇讨论结论

候选模块已将 Marketplace 划分为 listing core、publisher relation、review handoff、version/distribution、catalog/search、withdrawal/notification、entitlement local view 和 provenance/recovery 八类职责，并以 source truth、Governance、Identity、Artifact、delivery、billing 等 seam 隔离外部 ownership。正式 01~03 需要继续逐项收敛对象字段、状态转换、事务、端口、配置、测试切口与证据边界；在 `MP-UP-001~008` 未闭口前，本文所有模块均保持 draft/pending/blocked。

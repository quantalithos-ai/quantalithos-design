# 05 · L6-marketplace 原型说明（draft）

> 状态：`prototype / non-production / non-authoritative`\
> 日期：2026-10-01（第一版讨论基线）\
> 目的：验证 Marketplace 的信息架构、角色入口、状态表达和操作路径。\
> 访问方式：静态原型服务器绑定 `0.0.0.0`，在具备局域网网卡的运行环境中可由同网段设备访问。

## 1. 原型边界

本原型只使用本地 fixture，不连接真实 API、数据库、SDK、Governance、Identity、资产 owner、支付、安装接收方、Observability 或 Archive。

原型中的操作按钮只改变浏览器内的演示状态，不产生：

- Governance approval、verdict、signoff 或 readiness
- 真实 publisher 验证或身份凭证
- 真实签名、扫描、SBOM 或安全结论
- 真实获取、安装、运行时激活或支付结果
- 真实 audit evidence、通知送达或归档结果

## 2. 页面范围

```text
Catalog
  -> Listing detail
  -> My assets / favorites / acquisition request history
  -> Version/distribution view

Publisher
  -> Release application
  -> Governance handoff status
  -> Withdrawal request

Operations
  -> Listing/release management
  -> Impact and notification status
  -> Blocked/unknown recovery view
```

## 3. Fixture 状态覆盖

原型至少展示以下状态：

```text
public
restricted
pending_review
blocked
withdrawn
stale_reference
distribution_succeeded
distribution_failed
distribution_commit_unknown
notification_failed
billing_unavailable
```

## 4. 局域网访问

原型服务器必须监听 `0.0.0.0`，而不是只监听 `127.0.0.1`。访问地址格式为：

```text
http://<宿主机局域网IPv4>:9090/
```

如果当前运行环境只有 loopback 接口，其他设备无法访问，这是运行环境网络限制，不代表原型代码不支持局域网绑定。实际部署到开发机时，需要确认防火墙允许 TCP `9090` 入站。宿主机地址需要在每次启动时核验，不作为固定部署地址。

## 5. 后续落地

原型只验证页面结构、信息层级、状态文案和操作路径。确认后，正式实现仍以真实技术栈和正式文档为准：Next.js/React、Marketplace API、Worker、PostgreSQL、正式 owner adapters 和真实契约测试。

## 三、核心组件设计

### 3.1 GateCard（门禁审批卡片）

```vue
<!-- components/chat/GateCard.vue -->
<template>
  <div class="gate-card" :class="{ pending: !responded }">
    <div class="gate-header">
      <span class="gate-icon">🔒</span>
      <span class="gate-title">{{ gate.title }}</span>
      <span class="gate-timeout" v-if="gate.timeout">⏰ {{ remainingTime }}</span>
    </div>
    <div class="gate-desc">{{ gate.description }}</div>
    <div class="gate-artifacts" v-if="gate.artifacts?.length">
      <div v-for="a in gate.artifacts" :key="a.id" class="artifact-link">
        📄 {{ a.name }}
      </div>
    </div>
    <div class="gate-actions" v-if="!responded">
      <button class="btn-approve" @click="respond('approve')">✅ 确认通过</button>
      <button class="btn-reject" @click="respond('request_changes')">❌ 需要修改</button>
    </div>
    <div class="gate-result" v-else>
      {{ responded === 'approve' ? '✅ 已通过' : '❌ 已驳回' }}
    </div>
  </div>
</template>

<script setup lang="ts">
import { ref, computed } from 'vue'
import { respondGate } from '../../sdk'

const props = defineProps<{ gate: GateCardData }>()
const responded = ref<string | null>(null)

async function respond(action: string) {
  await respondGate(props.gate.id, action)
  responded.value = action
}
</script>
```

### 3.3 数据流

```
用户操作 → Pinia Store → sdk-wasm → gate → platform/flow/runtime
                ↑                                    │
                └────────────── 响应 ─────────────────┘

Phase 1（轮询）：
  Store 定时调用 sdk-wasm API 刷新数据

Phase 2（WebSocket）：
  sdk-wasm 建立 WS 连接 → 收到事件 → 更新 Store → Vue 响应式更新 UI
```

## 六、并发与一致性

### 6.1 竞态场景分析

chat 是纯前端 SPA，运行在浏览器单线程中，并发问题主要来自异步操作交错。

| 竞态场景 | 共享资源 | 控制策略 |
|---------|---------|---------|
| 用户快速切换项目 | Pinia store 中的当前项目数据 | 切换时 abort 上一次请求（AbortController）；store 写入前检查 project_id 是否仍为当前项目 |
| 轮询刷新与用户操作并发 | 消息列表 store | 轮询结果合并到列表（按 message_id 去重）；用户发送的消息立即乐观插入 |
| 门禁审批重复点击 | 门禁状态 | 点击后立即 disable 按钮（乐观 UI）；API 返回后确认状态 |
| WASM 初始化与首次 API 调用 | sdk-wasm 实例 | init() 返回 Promise，所有 API 调用 await init() 完成后再执行 |
| Phase 2 WS 事件与 API 响应同时更新同一工单 | workitems store | 以 updated_at 更新的为准；WS 事件通常更新 |

### 6.2 乐观更新策略

| 操作 | 乐观行为 | 失败回滚 |
|------|---------|---------|
| 发送消息 | 立即插入消息列表（pending 状态） | API 失败 → 标记为发送失败，显示重试按钮 |
| 门禁审批 | 立即显示"已通过/已驳回" | API 失败 → 恢复为待审批状态，toast 提示 |
| 工单状态变更 | 立即更新看板位置 | API 失败 → 回滚到原状态 |

## 七、性能设计

### 7.1 首屏加载优化

| 优化项 | 方案 | 效果 |
|--------|------|------|
| 路由懒加载 | 非首屏页面 `() => import('./views/KanbanView.vue')` | 首屏只加载 ChatView |
| WASM 异步加载 | `init()` 不阻塞首屏渲染；加载中显示骨架屏 | FCP 不受 WASM 影响 |
| Naive UI 按需导入 | `unplugin-vue-components` 自动按需导入 | 减少 ~200KB |
| 图片懒加载 | `v-lazy` 指令 + IntersectionObserver | 减少首屏请求数 |

### 7.2 运行时性能

| 热点 | 优化方案 |
|------|---------|
| 消息列表（>100 条） | vue-virtual-scroller 虚拟滚动，只渲染可见区域（~20 条） |
| 看板拖拽 | 使用 vuedraggable + requestAnimationFrame，避免频繁 DOM 操作 |
| 流程图 SVG | 使用 `<svg>` 而非 Canvas；节点数 < 50 时 SVG 性能足够 |
| 轮询频率 | Phase 1：5s 间隔轮询活跃项目；非活跃标签页暂停轮询（visibilitychange） |

### 7.3 包体积预算

| 模块 | 预估体积（gzip） |
|------|-----------------|
| Vue 3 + Vue Router + Pinia | ~40KB |
| Naive UI（按需导入） | ~80KB |
| 业务代码 | ~50KB |
| sdk-wasm | ~200KB（Phase 1） |
| **总计** | **~370KB** |

## 九、部署与运维

### 9.1 部署架构

```
Phase 1：

  npm run build → dist/ 静态文件
  → Nginx 托管 dist/
  → 所有路由 fallback 到 index.html（SPA）

Phase 2（Tauri）：

  npm run build → dist/
  → cargo tauri build → .dmg / .msi / .AppImage
```

### 9.2 配置项（五要素）

| 配置项 | 类型 | 默认值 | 范围 | 依赖 | 排查 |
|--------|------|--------|------|------|------|
| VITE_GATE_URL | string | http://localhost:8000 | 合法 URL | gate 运行中 | 浏览器 Network 面板检查请求目标 |
| VITE_WS_URL | string | ws://localhost:8000/ws | ws:// URL | gate WS 端点可达 | 浏览器 Console 检查 WS 连接状态 |
| VITE_POLL_INTERVAL_MS | int | 5000 | 1000–30000 | 无 | 过短增加服务端压力 |

> 注意：Vite 环境变量在构建时注入（`import.meta.env.VITE_*`），运行时不可修改。

### 9.3 Nginx 配置

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    # SPA fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # WASM MIME type
    location ~* \.wasm$ {
        types { application/wasm wasm; }
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 安全头
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;
}
```

## 一、项目定位

### 1.1 核心职责

quantalithos-console 是平台的管理配置入口，面向管理员和项目负责人。

```
chat vs console：

  chat（日常协作）                    console（管理配置）
  ─────────────                      ──────────────────
  和 Agent 聊天                       配置 Agent 角色
  看 Agent 执行过程                   编辑流程模板
  审批门禁                            管理工单和产物
  查看项目进度                        监控系统状态
  
  用户每天用                          管理员按需用
  实时交互                            CRUD 管理
```

### 1.2 在整体架构中的位置

```
quantalithos-chat (聊天)    quantalithos-console (管理)
      │                              │
      │ sdk-wasm                     │ sdk-wasm
      └──────────┬───────────────────┘
                 │
      quantalithos-sdk
                 │
                 │ HTTP/WebSocket
                 ▼
      quantalithos-gate (API 网关)
                 │
      ┌──────────┼──────────┐
      ▼          ▼          ▼
   platform    flow      runtime
```

### 1.3 和 chat 的关系

| 维度 | chat | console |
|------|------|---------|
| 用户 | 所有用户 | 管理员 / 项目负责人 |
| 场景 | 日常协作（聊天、审批、看执行） | 管理配置（配置、编辑、监控） |
| 技术栈 | Vue 3 + Vite + Naive UI + sdk-wasm | 相同 |
| 共享 | sdk-wasm（API 调用） | 相同 |
| 部署 | 独立部署（:3000） | 独立部署（:3001） |

## 二、功能模块

### 2.1 项目管理

- 项目列表（创建 / 归档 / 删除 / 筛选）
- 项目详情（基本信息 / 成员管理 / 配置）
- 项目仪表盘（进度概览 / 工单统计 / 产物统计 / Agent 活跃度）

### 2.2 工单管理

- 工单列表（筛选 / 搜索 / 批量操作）
- 看板视图（按状态分列 / 拖拽流转）
- 工单详情（状态历史 / 评论 / 关联产物 / 依赖关系）
- 依赖图可视化（DAG 图，显示任务间依赖和执行波次）

### 2.3 Agent 配置中心

- 角色定义管理（YAML 编辑器 + 实时预览 + 语法校验）
- 共享规则管理（启用 / 禁用 / 编辑 / 按项目覆盖）
- 三级覆盖可视化（system → company → project 合并结果预览）
- Agent 运行状态（在线 / 执行中 / 挂起 / 状态栈查看）

### 2.4 流程模板管理

- 流程模板列表（pipeline / stage / agent 分类）
- BPMN 流程图查看器（Phase 2：只读渲染）
- BPMN 流程图编辑器（Phase 3：可视化拖拽编辑节点和边）
- 流程模板版本管理（版本历史 / diff / 回滚）
- 流程实例监控（当前运行中的流程 + Token 状态 + 节点执行进度）

### 2.5 产物管理

- 产物列表（按项目 / 类型 / 标签筛选）
- 产物预览（Markdown 渲染 / 代码高亮 / JSON 格式化 / 图片）
- 版本历史（diff 对比 / 回滚）
- 产物关系图（来源追踪：哪个节点产出 / 哪个任务引用）

### 2.6 设计系统（Phase 2 基础 / Phase 3 完整）

- Design Tokens 管理（颜色 / 字体 / 间距 / 圆角 / 主题）
  - 数据来源：platform hub-design API（`GET/POST /api/projects/:pid/design/tokens`）
  - 编辑器：取色器 + 字体选择 + 间距滑块 + 实时预览
- 组件库管理（组件定义 / 变体 / 预览）
  - 数据来源：platform hub-design API（`GET/POST /api/design/components`）
  - 预览：调用 `GET /api/design/components/:id/preview` 渲染实时效果
  - 三级覆盖：system 内置组件 + project 自定义组件
- 原型管理（原型列表 / 预览 / 版本）
  - 数据来源：platform hub-design API（`GET/POST /api/projects/:pid/design/prototypes`）
  - 预览：调用 `GET /api/design/prototypes/:id/preview` 渲染页面
- 未来（Phase 3）：内置原型编辑器（拖拽组合组件）或 集成 Penpot

### 2.7 Git 仓库管理（Phase 2）

- 仓库列表（一个项目可有多个仓库：backend / frontend / docs / infra）
  - 数据来源：platform hub-integration API（`GET /api/projects/:pid/git/repos`）
- 提交历史（commit 列表 + 作者 + 关联工单 + 文件变更统计）
  - 数据来源：hub-integration 代理 Gitea API（`GET /api/projects/:pid/git/repos/:rid/commits`）
- 分支管理（分支列表 + 当前分支 + 保护分支）
  - 数据来源：`GET /api/projects/:pid/git/repos/:rid/branches`
- Pull Request（PR 列表 + 详情 + diff + 审查状态）
  - 数据来源：`GET /api/projects/:pid/git/repos/:rid/pulls`
  - diff 展示：DiffViewer 组件（代码高亮 + 行级对比）
- 代码浏览器（文件树 + 代码查看 + 语法高亮）
  - 数据来源：`GET /api/projects/:pid/git/repos/:rid/contents/:path`
- 工单关联（查看某个工单关联的所有 commit 和 PR）
  - 数据来源：`GET /api/workitems/:id/git`

### 2.8 用户与权限

- 用户管理（创建 / 禁用 / 角色分配）
- 角色权限（admin / user / viewer）
- API Token 管理（创建 / 吊销 / 权限范围）
- 操作审计日志（谁在什么时候做了什么）

### 2.8 系统监控

- 服务健康状态（platform / flow / runtime / gate 的 /health 端点）
- LLM 调用统计（token 消耗 / 成本 / 平均延迟 / 错误率）
- Agent 执行统计（任务完成率 / 平均耗时 / 重试率）
- 错误日志（最近错误 / 按服务筛选 / 详情查看）

### 2.9 系统设置

- 全局配置（LLM 模型选择 / API Key / 默认参数）
- 事件总线配置（Phase 1 进程内 / Phase 2 Redis）
- 存储配置（MinIO / S3 连接信息）
- 通知配置（邮件 / Webhook）

## 六、约束条件

### 6.1 技术约束

| 约束 | 说明 |
|------|------|
| 框架 | Vue 3 + Composition API + TypeScript，与 chat 统一技术栈 |
| 构建 | Vite |
| 数据获取 | 全部通过 sdk-wasm，不直接调用 platform/gate API |
| 状态管理 | Pinia |
| 独立部署 | console 与 chat 独立部署（不同端口），共享 sdk-wasm |
| 管理员权限 | console 所有页面需要 admin/manager 角色，普通用户不可访问 |

### 6.2 容量规划

| 指标 | Phase 1 目标 | Phase 2 目标 |
|------|-------------|-------------|
| 首屏加载（gzip） | < 600KB（不含 WASM） | < 1MB（含 WASM + Monaco） |
| 项目列表渲染（100 个） | < 200ms | < 200ms |
| 工单看板渲染（200 工单） | < 300ms | < 300ms |
| BPMN 流程图渲染（50 节点） | — | < 500ms |
| 内存占用 | < 150MB | < 300MB（含 Monaco 编辑器） |

### 6.3 层间约束

| 约束 | 说明 |
|------|------|
| views/ 不直接调用 sdk-wasm | views 通过 stores/ 获取数据 |
| stores/ 是唯一的数据源 | 所有组件从 Pinia store 读取 |
| components/ 不依赖 stores/ | 通用组件通过 props 接收数据 |
| sdk/ 是唯一的网络层 | 所有 API 调用封装在 sdk/ |
| console 与 chat 不共享组件 | 各自独立的组件库；Phase 3 评估抽取共享 UI 库 |

```
依赖方向（单向）：

  views/（页面模块 ×11）
    │
    ├──> stores/（Pinia 状态管理）
    │       │
    │       └──> sdk/（SDK 薄封装）
    │              │
    │              └──> @quantalithos/sdk-wasm
    │
    └──> components/（通用组件，通过 props）
```

## 七、技术选型（决策四元组）

### 7.1 YAML 编辑器（Agent 配置）

| 维度 | 当前选择 |
|------|---------|
| 方案 | Monaco Editor（VS Code 内核） |
| 备选 | ① CodeMirror 6　② Ace Editor　③ 纯 textarea |
| 理由 | Monaco 支持 YAML 语法高亮 + 自动补全 + 错误提示；与 VS Code 体验一致；CodeMirror 6 轻量但 YAML 支持需要额外插件 |
| 演进路径 | 长期使用 Monaco；Phase 3 增加自定义 YAML Schema 校验（Agent 配置结构） |

### 7.2 BPMN 流程图（Phase 2）

| 维度 | 当前选择 |
|------|---------|
| 方案 | Vue Flow（基于 React Flow 的 Vue 3 移植） |
| 备选 | ① bpmn.js　② D3.js 自绘　③ mermaid.js |
| 理由 | Vue Flow 原生 Vue 3 组件，支持自定义节点和边；bpmn.js 功能强但体积大（~500KB）且 Vue 集成需要额外封装；D3 自绘开发成本高 |
| 演进路径 | Phase 2 只读渲染；Phase 3 可视化拖拽编辑 |

### 7.3 代码高亮（产物预览 / Git 代码浏览）

| 维度 | 当前选择 |
|------|---------|
| 方案 | Shiki（VS Code 语法引擎） |
| 备选 | ① Prism.js　② highlight.js　③ Monaco 只读模式 |
| 理由 | Shiki 使用 VS Code 的 TextMate 语法，高亮质量最高；Prism/highlight.js 语法覆盖不如 Shiki；Monaco 只读模式体积过大 |
| 演进路径 | 长期使用 Shiki |

## 八、横切关注点

### 8.1 安全

| 关注点 | 方案 |
|--------|------|
| 权限控制 | 路由守卫检查用户角色（admin/manager）；无权限跳转 403 页面 |
| XSS 防护 | Vue 3 默认转义；Markdown 渲染用 DOMPurify；Monaco 编辑器内容不注入 DOM |
| CSRF | 同 chat，JWT 在 header，无 CSRF 风险 |
| 敏感操作确认 | 删除项目/重置数据库等操作需要二次确认弹窗 |

### 8.2 性能

| 关注点 | 方案 |
|--------|------|
| Monaco 懒加载 | 只在 Agent 配置页面加载 Monaco（~2MB），其他页面不加载 |
| 列表分页 | 项目/工单/产物列表分页加载（page_size=50） |
| 表格虚拟滚动 | Naive UI NDataTable 内置虚拟滚动 |
| 路由懒加载 | 11 个页面模块全部懒加载 |

### 8.3 可用性

| 关注点 | 方案 |
|--------|------|
| 表单保存提示 | 编辑中离开页面 → beforeRouteLeave 提示"未保存的更改" |
| 操作反馈 | 所有 CRUD 操作完成后 toast 提示成功/失败 |
| 加载状态 | 每个页面有 loading 骨架屏 |

### 8.4 可观测性

| 维度 | 方案 |
|------|------|
| 错误上报 | Phase 2 接入 Sentry |
| 操作审计 | 敏感操作（删除/配置变更）记录到 platform 审计日志 |

### 8.5 成本

| 关注点 | 方案 |
|--------|------|
| 托管 | 同 chat，Nginx 静态文件托管 |
| 包体积 | Monaco 懒加载避免首屏膨胀；Naive UI 按需导入 |

## 九、风险与缓解策略

| # | 风险 | 影响 | 概率 | 缓解策略 |
|---|------|------|------|---------|
| 1 | Monaco Editor 包体积过大（~2MB） | 首屏加载慢 | 中 | 懒加载（只在 Agent 配置页加载）；Phase 2 评估 CodeMirror 6 替代 |
| 2 | 11 个页面模块开发量大 | 开发周期长 | 高 | Phase 1 只实现核心 5 个（项目/工单/Agent/产物/系统监控）；其余 Phase 2 |
| 3 | console 与 chat 组件重复 | 维护成本高 | 中 | Phase 1 各自独立；Phase 3 抽取共享 UI 库 |
| 4 | BPMN 流程图编辑器复杂度高 | Phase 3 延期 | 中 | Phase 2 只做只读渲染；Phase 3 评估集成 bpmn.js 而非自研 |

## 十、上线策略

### 10.1 灰度方案

| 阶段 | 范围 | 观察时间 | 推进条件 |
|------|------|---------|---------|
| 内部测试 | 开发团队 | 3 天 | 核心 CRUD 流程跑通 |
| 管理员 | 项目管理员 | 1 周 | 无 P0 bug |
| 全量 | 所有管理员 | 持续 | — |

### 10.2 回滚策略

| 触发条件 | 回滚步骤 |
|---------|---------|
| 白屏率 > 1% | Nginx 切回旧版本 |
| CRUD 操作失败率 > 5% | 排查 SDK/API 问题；回退版本 |

### 10.3 上线监控指标

| 指标 | 告警阈值 |
|------|---------|
| 白屏率 | > 1% |
| FCP | > 3s |
| JS 错误率 | > 0.5% |
| API 调用失败率 | > 5% |

# quantalithos-core 实施计划

> 核心共享库 — Python (Pydantic + asyncio)
> 关联详细设计：`projects/quantalithos-core/design/详细设计.md`

---

## 一、前置条件

### 1.1 必读文档

在开始编码之前，必须完整阅读以下文档：

| 文档 | 阅读目的 |
|------|---------|
| docs/design/架构设计.md | 理解 core 在 15 个子项目中的位置（被 flow 和 runtime 依赖的共享库） |
| projects/quantalithos-core/design/概要设计.md | 理解 BPMN 引擎 + 通信协议 + 共享数据模型三大职责 |
| projects/quantalithos-core/design/详细设计.md | 理解所有结构体定义、引擎逻辑、接口契约 |
| docs/design/设计模式使用规范.md | 理解 Strategy（策略注册表）、Template Method（引擎主循环）的使用场景 |
| docs/design/Google-Python编码规范.md | Python 编码规范（类型注解、docstring、async/await） |

### 1.2 编码约束

- 语言：Python 3.11+，代码全英文（变量名/函数名/注释/字符串）
- 唯一依赖：pydantic >= 2.0（零网络依赖）
- 不包含任何 IO 操作（文件/网络/数据库）
- async 方法仅在 strategy.execute() 和 provider 接口中使用
- Commit scope：bpmn | protocol | models | sandbox | tests

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

## 二、技术风险评估

**结论：不需要 Spike。**

- 纯 Python 库，无外部依赖风险
- Pydantic V2 是成熟库
- BPMN 引擎是自研逻辑，不依赖第三方
- Token 状态机是简单状态转换

## 五、回退规则

| 阶段 2 | Pydantic V2 的 discriminated union 无法满足多态反序列化 | 回到详细设计，调整 NODE_TYPE_MAP 方案 |
| 阶段 3 | ParallelGateway 的 Token fork/join 比预期复杂 | 回到详细设计 §十三 并发分析，重新评估 |
| 阶段 3 | _match_condition 无法覆盖实际需求 | 回到详细设计 §六，提前引入 simpleeval 库 |

## 一、前置条件

> **必须先阅读** `docs/design/实施计划书写规范.md` §二-A 前置条件，完成 Git 仓库初始化和通用前置检查。
> 以下仅列出本项目特有的前置条件。

### 1.1 必读文档

| 文档 | 阅读目的 |
|------|---------|
| docs/design/架构设计.md | 理解 gate 作为唯一外部入口的位置 |
| projects/quantalithos-gate/design/概要设计.md | 理解无状态设计、技术选型决策、横切关注点 |
| projects/quantalithos-gate/design/详细设计.md | 理解 JWT 实现、反向代理、WebSocket 管理、限流、代码骨架 |
| docs/design/设计模式使用规范.md | 理解 Middleware Chain（中间件链）、Strategy（路由匹配）的使用场景 |
| docs/design/Rust编码规范.md | Rust 编码规范（命名/错误处理/trait 设计/unsafe 规范） |

### 1.2 编码约束

- 语言：Rust，代码全英文
- 框架：axum 0.7 + reqwest 0.12 + jsonwebtoken 9 + tokio 1.0 + governor 0.6
- 无数据库（gate 无状态）
- 不包含业务逻辑（纯转发 + 认证 + 限流）
- 不使用 unwrap()/expect()（除初始化阶段的不可恢复错误）
- Commit scope：auth | router | ws | ratelimit | logging | config | api

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

## 二、技术风险评估

gate 技术栈成熟（axum + reqwest + JWT），无需 Spike。

| 风险 | 影响 | 是否需要 Spike | 缓解方式 |
|------|------|---------------|---------|
| reqwest WASM target 与 native target 行为差异 | 不影响 gate（gate 是服务端） | 否 | gate 只用 native target |
| governor 限流精度 | 低（±1 token 偏差可接受） | 否 | 集成测试验证 |
| tokio-tungstenite 与 axum 的 WebSocket 集成 | Phase 2 才实现 | 否 | Phase 2 前有充足时间验证 |

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 1 | axum 版本不兼容导致编译失败 | 概要设计，评估 axum 版本或换 actix-web |
| 阶段 2 | 配置结构无法满足路由需求 | 详细设计，重新设计 RouteConfig 结构 |
| 阶段 3 | reqwest 反向代理无法透传 streaming body | 详细设计，评估 hyper 直接转发（不经过 reqwest） |
| 阶段 3 | JWT 库不支持所需的 claims 结构 | 详细设计，评估换 jose 或手写 JWT |
| 阶段 4 | governor 限流精度不满足需求 | 详细设计，评估自研 Token Bucket 或换 ratelimit crate |
| 阶段 5 | tracing JSON 输出格式不符合日志平台要求 | 详细设计，自定义 tracing Layer |

> 基础设施 — Docker Compose + 数据库迁移 + CI/CD + 监控
> 关联详细设计：`projects/quantalithos-infra/design/详细设计.md`

## 一、前置条件

> **必须先阅读** `docs/design/实施计划书写规范.md` §二-A 前置条件，完成 Git 仓库初始化和通用前置检查。
> 以下仅列出本项目特有的前置条件。

### 1.1 必读文档

| 文档 | 阅读目的 |
|------|---------|
| docs/design/架构设计.md | 理解各服务的依赖关系和部署拓扑 |
| projects/quantalithos-infra/design/概要设计.md | 理解模块划分、技术选型、端口规划 |
| projects/quantalithos-infra/design/详细设计.md | 理解 Docker Compose 配置、迁移脚本、启动流程 |
| projects/quantalithos-platform/design/详细设计.md §二 | 理解 SQL DDL（迁移文件内容来源） |

### 1.2 编码约束

- 语言：Shell (Bash) + YAML + SQL，脚本全英文注释
- 工具：Docker Compose v2 + sqlx-cli + psql
- 所有脚本必须幂等（重复执行不报错、不破坏数据）
- 敏感信息通过环境变量注入，不硬编码
- Commit scope：docker | migrations | seeds | scripts | config | ci | monitoring

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

### 1.4 工具链准备

```bash
docker --version          # >= 24.0
docker compose version    # >= 2.20
psql --version            # >= 16（可选，用于手动调试）
```

## 二、技术风险评估

infra 技术栈成熟（Docker + PostgreSQL + Shell），无需 Spike。

| 风险 | 影响 | 是否需要 Spike | 缓解方式 |
|------|------|---------------|---------|
| Docker Compose v2 语法与 v1 差异 | 低 | 否 | 统一使用 `docker compose`（不用 `docker-compose`） |
| sqlx migrate 与手写 SQL 的兼容性 | 低 | 否 | 迁移文件用纯 SQL，不依赖 sqlx 特有语法 |
| 多服务启动顺序 | 中 | 否 | depends_on + healthcheck 保证依赖就绪 |

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 2 | SQL 迁移文件与 platform 详细设计不一致 | 详细设计，对齐 DDL |
| 阶段 3 | Rust 多阶段构建镜像过大（>500MB） | Dockerfile，优化构建层 / 换 alpine 基础镜像 |
| 阶段 3 | docker compose up 启动顺序不稳定 | docker-compose.yml，增加 healthcheck + restart policy |
| 阶段 4 | pg_dump 备份文件过大 | 评估增量备份（WAL archiving）或压缩策略 |
| 阶段 5 | GitHub Actions 构建超时（>30min） | CI 配置，拆分并行 job + 优化 Docker cache |

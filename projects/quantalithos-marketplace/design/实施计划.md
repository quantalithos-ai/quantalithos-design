### 1.2 编码约束

- 语言：Rust，代码全英文
- 框架：axum 0.7 + sqlx 0.8 + serde 1.0
- hub-marketplace 是 platform workspace 的一个 crate，遵循 platform 的模块化架构
- 所有数据库操作通过 sqlx（编译时 SQL 校验）
- 文件存储通过 MinIO（S3 兼容 API）
- Commit scope：marketplace-model | marketplace-handler | marketplace-repo | marketplace-search | marketplace-import

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

### 1.4 工具链准备

```bash
rustc --version       # stable >= 1.78
cargo --version       # >= 1.78
sqlx-cli --version    # >= 0.8（数据库迁移）
```

## 二、技术风险评估

| 风险 | 影响 | 是否需要 Spike | 缓解方式 |
|------|------|---------------|---------|
| PostgreSQL ILIKE 搜索性能（资产量 > 500） | 中 | 否 | Phase 2 用 pg_trgm GIN 索引优化；Phase 3 引入 Meilisearch |
| MinIO 预签名 URL 生成 | 低 | 否 | aws-sdk-s3 crate 原生支持 presigned URL |
| 一键导入跨 hub 调用的事务一致性 | 中 | 否 | 导入和计数分离（详细设计 §六.3），导入失败不计数 |

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 2 | JSONB 存储结构化资产性能不足 | 详细设计，评估拆分为独立表 |
| 阶段 3 | 一键导入跨 hub 调用失败率高 | 详细设计，评估异步导入（消息队列） |
| 阶段 3 | 6 种资产类型导入逻辑过于复杂 | 缩减 Phase 2 范围（只做 process_template + role_definition） |
| 阶段 4 | 并发冲突频繁（UNIQUE 约束报错多） | 评估悲观锁（SELECT FOR UPDATE） |
| 阶段 5 | ILIKE 搜索 P95 > 200ms | 提前引入 Meilisearch（原计划 Phase 3） |

# quantalithos-marketplace 概要设计

> 资产市场 — 流程模板、技能包、角色定义、应用作品的发布/搜索/下载平台

---

## 一、项目定位

### 1.1 核心职责

quantalithos-marketplace 是一个统一的资产市场，用户可以分享和获取各类资产。

```
用户能做什么：

  发布者：
  ├── 上传流程模板（"我设计了一个 TDD 工作流"）
  ├── 上传技能包（"我训练了一个代码审查技能"）
  ├── 上传角色定义（"我定义了一个全栈开发角色"）
  ├── 上传共享规则（"我写了一套代码规范"）
  ├── 上传 UI 组件（"我做了一个评论组件"）
  └── 发布应用作品（"我用 AI 做了一个博客系统"）

  消费者：
  ├── 浏览、搜索、筛选
  ├── 查看详情、截图、评分
  ├── 一键导入到自己的项目
  └── 评分、评论、收藏
```

### 1.2 6 种资产类型

| 类型 | asset_type | 内容 | 导入目标 |
|------|-----------|------|---------|
| 流程模板 | process_template | ProcessDefinition YAML | platform process_templates 表 |
| 技能包 | skill | Agent 技能定义（prompt + 工具组合） | platform process_templates(type=skill) |
| 角色定义 | role_definition | RoleDefinition YAML | platform role_definitions 表 |
| 共享规则 | shared_rule | SharedRule YAML | platform shared_rules 表 |
| UI 组件 | component | 组件定义（template + styles + props） | platform components 表 |
| 应用作品 | app | 构建产物（Docker 镜像 / 静态文件） | runner 下载运行 |

### 1.3 在整体架构中的位置

```
  发布者                                    消费者
    │                                         │
    │ 上传资产                                │ 浏览/下载
    ▼                                         ▼
┌─────────────────────────────────────────────────┐

│  ├── 浏览页（分类 + 搜索 + 排行）                │

│  ├── 发布页（上传 + 填写信息）                   │
│  └── 个人中心（我的发布 + 收藏）                 │
└──────────────────────┬──────────────────────────┘
                       │ sdk-api
                       ▼
┌─────────────────────────────────────────────────┐
│  platform hub-marketplace（Phase 2）             │
│  ├── 资产 CRUD + 版本管理                        │
│  ├── 搜索（标签 + 全文）                         │
```

## 二、数据模型

```sql
-- marketplace_assets：资产主表
CREATE TABLE marketplace_assets (
    id              BIGSERIAL       PRIMARY KEY,
    asset_type      VARCHAR(32)     NOT NULL,       -- process_template | skill | role_definition | shared_rule | component | app
    name            VARCHAR(256)    NOT NULL,
    description     TEXT            NOT NULL DEFAULT '',
    author_id       VARCHAR(64)     NOT NULL,       -- 发布者 user_id
    author_name     VARCHAR(128)    NOT NULL,
    version         VARCHAR(32)     NOT NULL DEFAULT '1.0.0',
    tags            JSONB           NOT NULL DEFAULT '[]',
    category        VARCHAR(64)     NOT NULL DEFAULT 'general',
    license         VARCHAR(32)     NOT NULL DEFAULT 'MIT',
    -- 内容
    content_type    VARCHAR(16)     NOT NULL,        -- yaml | json | binary
    content_data    JSONB,                           -- YAML/JSON 类资产的内容
    file_path       VARCHAR(512),                    -- 二进制类资产的 MinIO 路径
    file_size       BIGINT,
    -- 展示
    readme          TEXT            NOT NULL DEFAULT '',
    screenshots     JSONB           NOT NULL DEFAULT '[]',  -- [{ url, caption }]
    -- 统计
    download_count  INTEGER         NOT NULL DEFAULT 0,
    rating_avg      DECIMAL(3,2)    NOT NULL DEFAULT 0,
    rating_count    INTEGER         NOT NULL DEFAULT 0,
    -- 状态
    status          VARCHAR(16)     NOT NULL DEFAULT 'published',  -- draft | published | archived | rejected
    -- 时间
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ma_type ON marketplace_assets(asset_type);
CREATE INDEX idx_ma_author ON marketplace_assets(author_id);
CREATE INDEX idx_ma_category ON marketplace_assets(category);
CREATE INDEX idx_ma_status ON marketplace_assets(status);

-- marketplace_versions：版本历史
CREATE TABLE marketplace_versions (
    id              BIGSERIAL       PRIMARY KEY,
    asset_id        BIGINT          NOT NULL REFERENCES marketplace_assets(id) ON DELETE CASCADE,
    version         VARCHAR(32)     NOT NULL,
    changelog       TEXT            NOT NULL DEFAULT '',
    content_data    JSONB,
    file_path       VARCHAR(512),
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    UNIQUE(asset_id, version)
);

-- marketplace_reviews：评分评论
CREATE TABLE marketplace_reviews (
    id              BIGSERIAL       PRIMARY KEY,
    asset_id        BIGINT          NOT NULL REFERENCES marketplace_assets(id) ON DELETE CASCADE,
    user_id         VARCHAR(64)     NOT NULL,
    rating          INTEGER         NOT NULL CHECK (rating >= 1 AND rating <= 5),
    comment         TEXT            NOT NULL DEFAULT '',
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    UNIQUE(asset_id, user_id)
);

-- marketplace_favorites：收藏
CREATE TABLE marketplace_favorites (
    id              BIGSERIAL       PRIMARY KEY,
    asset_id        BIGINT          NOT NULL REFERENCES marketplace_assets(id) ON DELETE CASCADE,
    user_id         VARCHAR(64)     NOT NULL,
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    UNIQUE(asset_id, user_id)
);
```

## 三、API 设计

```
-- 浏览
GET    /api/marketplace/assets                    搜索资产（?type=&tag=&q=&sort=&page=）
GET    /api/marketplace/assets/:id                资产详情
GET    /api/marketplace/assets/:id/versions       版本历史
GET    /api/marketplace/assets/:id/reviews        评论列表
GET    /api/marketplace/categories                分类列表
GET    /api/marketplace/tags/popular              热门标签
GET    /api/marketplace/ranking                   排行榜（?type=&period=weekly）

-- 发布
POST   /api/marketplace/assets                    发布资产
PUT    /api/marketplace/assets/:id                更新资产信息
POST   /api/marketplace/assets/:id/versions       发布新版本
DELETE /api/marketplace/assets/:id                下架

-- 互动
POST   /api/marketplace/assets/:id/reviews        评分评论
POST   /api/marketplace/assets/:id/favorite       收藏/取消收藏
POST   /api/marketplace/assets/:id/download       下载（记录统计）

-- 导入
POST   /api/marketplace/assets/:id/import/:pid    一键导入到项目
       → 根据 asset_type 导入到 platform 对应的表

-- 个人中心
GET    /api/marketplace/my/assets                 我发布的
GET    /api/marketplace/my/favorites              我收藏的
GET    /api/marketplace/my/downloads              我下载的
```

## 四、一键导入流程

```
用户在 console 市场页面点击"导入到项目"：

  console → POST /api/marketplace/assets/42/import/blog
                │
                ▼
  hub-marketplace 根据 asset_type 分发：

    process_template:
      → 读取 content_data（ProcessDefinition YAML）
      → POST /api/agent-config/processes
      → 写入 process_templates 表（scope=project, project_id=blog）

    role_definition:
      → 读取 content_data（RoleDefinition YAML）
      → POST /api/projects/blog/agent-config/roles
      → 写入 role_definitions 表（scope=project）

    shared_rule:
      → 读取 content_data
      → POST /api/projects/blog/agent-config/shared-rules
      → 写入 shared_rules 表（scope=project）

    component:
      → 读取 content_data
      → POST /api/projects/blog/design/components
      → 写入 components 表（scope=project）

    app:
      → 返回下载链接
      → runner 下载安装

    skill:
      → 读取 content_data
      → POST /api/agent-config/processes
      → 写入 process_templates 表（process_type=skill）
```

## 七、约束条件

### 7.1 技术约束

| 约束 | 说明 |
|------|------|
| 语言 | Rust（axum + sqlx），与 platform 共用技术栈 |
| 数据库 | PostgreSQL 16，marketplace 表与 platform 共用同一实例 |
| 文件存储 | Phase 2 MinIO（S3 兼容），存储 app 类资产的构建产物 |
| 搜索引擎 | Phase 2 PostgreSQL ILIKE；Phase 3 Meilisearch（中文分词 + 全文搜索） |
| 前端 | Vue 3，嵌入 quantalithos-console 的市场页面模块 |
| 部署 | hub-marketplace 作为 platform 的一个 crate，随 platform 一起部署 |

### 7.2 容量规划

| 指标 | Phase 2 目标 | Phase 3 目标 |
|------|-------------|-------------|
| 资产总数 | < 500 | < 5000 |
| 单次搜索 P95 响应时间 | < 200ms（ILIKE） | < 50ms（Meilisearch） |
| 单资产最大文件体积 | 50MB（app 类） | 200MB |
| 并发下载数 | 10 | 50 |
| 数据库连接池 | 共用 platform 连接池（10） | 共用（50） |

### 7.3 合规约束

- 资产内容不得包含恶意代码（Phase 3 引入自动扫描）
- 用户上传的文件存储在 MinIO，不直接暴露文件系统路径
- 评分评论不可匿名（绑定 user_id）

## 八、层间约束

```
依赖方向（单向，不可反向依赖）：

  console 市场页面
       │
       │ 只通过 sdk-api 调用
       ▼
  gate（API 网关）
       │
       │ 认证后转发
       ▼
  hub-marketplace（platform crate）
       │
       ├── 读写 → PostgreSQL（marketplace_* 表）
       ├── 读写 → MinIO（app 类资产文件）
       ├── 调用 → hub-agent-config（导入 process_template/role/rule）
       ├── 调用 → hub-design（导入 component）
       └── 发布 → EventBus（AssetPublished / AssetDownloaded 事件）

禁止的依赖：
  ✗ hub-marketplace 不得直接调用 runtime 或 flow
  ✗ hub-marketplace 不得绕过 gate 直接接收外部请求
  ✗ console 不得直接访问 MinIO（通过 marketplace API 代理下载）
```

## 九、横切关注点

### 9.1 安全

| 关注点 | 方案 |
|--------|------|
| 认证 | 由 gate 层处理（JWT），marketplace 信任 X-User-Id 请求头 |
| 授权 | Phase 2 仅作者可编辑/下架自己的资产；Phase 3 管理员审核权限 |
| 文件上传校验 | 文件类型白名单（zip/tar.gz/docker image）+ 大小限制（50MB） |
| 内容安全 | Phase 3 引入自动扫描（恶意代码检测 + 敏感信息检测） |

### 9.2 性能

| 关注点 | 方案 |
|--------|------|
| 搜索性能 | Phase 2 PostgreSQL ILIKE + 索引；Phase 3 Meilisearch 全文搜索 |
| 下载性能 | MinIO 预签名 URL 直接下载，不经过 platform 代理 |
| 排行榜 | Phase 2 实时查询（ORDER BY download_count）；Phase 3 Redis 缓存（TTL 5min） |
| 热门标签 | Phase 2 实时聚合；Phase 3 定时任务预计算 |

### 9.3 可用性

| 关注点 | 方案 |
|--------|------|
| MinIO 不可用 | 结构化资产（JSONB）不受影响；文件类资产返回 503 |
| Meilisearch 不可用（Phase 3） | 降级到 PostgreSQL ILIKE 搜索 |
| 数据库不可用 | 整个 marketplace 不可用（与 platform 共命运） |

### 9.4 可观测性

| 维度 | 方案 |
|------|------|
| 日志 | tracing::instrument 标注所有 handler，记录 asset_id / user_id / action |
| 指标 | 搜索 QPS、下载次数/秒、发布次数/天、平均评分 |
| 追踪 | 复用 platform 的 X-Request-Id 链路追踪 |
| 告警 | 搜索 P95 > 500ms、下载失败率 > 5% |

### 9.5 成本

| 资源 | Phase 2 | Phase 3 |
|------|---------|---------|
| PostgreSQL | 共用 platform 实例，无额外成本 | 同左 |
| MinIO | 单节点，10GB 存储 | 集群，100GB |
| Meilisearch | 无 | 单节点，1GB 内存 |

## 十、风险与缓解策略

| # | 风险 | 影响 | 概率 | 缓解策略 |
|---|------|------|------|---------|
| 1 | ILIKE 搜索在资产量增长后性能下降 | 搜索响应变慢 | 中 | Phase 2 加 GIN 索引（pg_trgm）；Phase 3 迁移到 Meilisearch |
| 2 | 大文件上传导致 MinIO 存储不足 | 新资产无法发布 | 低 | 文件大小限制（50MB）+ 存储监控告警 |
| 3 | 恶意资产（含后门的流程模板/角色定义） | 导入后影响项目安全 | 中 | Phase 2 人工审核；Phase 3 自动扫描（YAML schema 校验 + 关键字检测） |
| 4 | 导入时目标模块 API 不可用 | 导入失败 | 低 | 返回明确错误信息 + 重试提示；不做异步重试（用户手动重试） |
| 5 | 评分刷分（同一用户多次评分） | 评分不真实 | 低 | UNIQUE(asset_id, user_id) 约束，一人一票 |
| 6 | 版本冲突（两人同时发布同一资产的新版本） | 数据不一致 | 低 | UNIQUE(asset_id, version) 约束 + 乐观锁（updated_at 校验） |

## 十一、上线策略

### 11.1 Phase 2 上线

| 步骤 | 操作 | 回滚方案 |
|------|------|---------|
| 1 | 执行 DDL（marketplace_assets + marketplace_versions） | DROP TABLE |
| 2 | 部署 platform 新版本（含 hub-marketplace） | 回滚到旧版本二进制 |
| 3 | 加载 seeds 数据（系统预置资产） | DELETE FROM marketplace_assets WHERE author_id='system' |
| 4 | console 开启市场页面入口 | 关闭入口（feature flag） |
| 5 | 监控 24h：搜索 P95、下载成功率、错误日志 | — |

### 11.2 Phase 3 上线

| 步骤 | 操作 | 回滚方案 |
|------|------|---------|
| 1 | 部署 Meilisearch 实例 | 停止 Meilisearch，降级到 ILIKE |
| 2 | 全量同步资产数据到 Meilisearch | 重新同步 |
| 3 | 执行 DDL（marketplace_reviews + marketplace_favorites） | DROP TABLE |
| 4 | 部署 platform 新版本（含评分评论 + 审核） | 回滚到 Phase 2 版本 |
| 5 | 开启审核流程（新发布资产需审核） | 关闭审核（直接发布） |

### 11.3 监控指标

| 指标 | 正常范围 | 告警阈值 |
|------|---------|---------|
| 搜索 P95 | < 200ms | > 500ms |
| 下载成功率 | > 99% | < 95% |
| 导入成功率 | > 95% | < 90% |
| 错误率（5xx） | < 1% | > 5% |

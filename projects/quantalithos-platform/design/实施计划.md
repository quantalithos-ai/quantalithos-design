> 平台数据服务 — Rust (axum + sqlx + PostgreSQL)

## 一、语言与提交规范

### 1.1 代码语言要求

- 所有代码文件全英文（变量名、函数名、注释、字符串常量）
- 不允许出现任何中文字符
- 用户面向的文本通过 i18n 机制处理（Phase 2）
- 文档注释使用英文（`///` doc comments）

### 1.2 Commit Message 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type:** feat | fix | refactor | docs | test | chore | perf | ci | style

**Scope:** project | workitem | artifact | agent-config | snapshot | event | api | common | design | integration | knowledge

**Footer 规范：**

| 场景 | footer 内容 |
|------|------------|
| AI 辅助编写 | `Co-Authored-By: Claude <noreply@anthropic.com>` |
| 关联 issue | `Closes #42` 或 `Refs #42` |
| 破坏性变更 | `BREAKING CHANGE: <description>` |

**多功能改动示例（按功能分组，每个功能列出文件和改动内容）：**
```
feat(platform): add task scheduling and auto-assign

任务调度：
- hub-workitem/src/task_scheduler.rs (+180): implement start_execution and on_task_completed
- hub-workitem/src/handler.rs (+45): register start-execution route

自动指派：
- hub-workitem/src/service.rs (+60): implement auto_assign with role-based rules
- hub-workitem/src/handler.rs (+12): call auto_assign in transition handler

事件发布：
- hub-common/src/event_bus.rs (+8): add TaskBecameReady and AllTasksCompleted variants

Co-Authored-By: Claude <noreply@anthropic.com>
```

**单功能改动示例：**
```
feat(workitem): implement state machine validation

- hub-workitem/src/state_machine.rs (+95): add TASK/BUG/REQUIREMENT transition tables
- hub-workitem/src/handler.rs (+5): call validate_transition before status update
- hub-workitem/tests/state_machine_test.rs (+120): cover all legal and illegal transitions
```

**AI 辅助修复示例：**
```
fix(engine): prevent token advancement when gateway has no matching condition

- hub-workitem/src/state_machine.rs (~3): change silent None return to RuntimeError

Co-Authored-By: Claude <noreply@anthropic.com>
```

### 1.3 分支策略

```
main                    — 稳定版本
├── develop             — 开发主线
├── feat/workitem-crud  — 功能分支
├── fix/transition-bug  — 修复分支
└── refactor/view-trait — 重构分支
```

## 二、适用的架构模式

### 2.1 GoF 模式

| 模式 | 应用场景 | 实现位置 |
|------|---------|---------|
| Strategy | 自动指派策略（按角色/负载选择 assignee） | hub-workitem/src/service.rs |
| Observer | EventBus 事件发布/订阅 | hub-common/src/event_bus.rs |
| Factory Method | ViewRenderer 按资源类型创建不同视图 | hub-api/src/views.rs |
| Template Method | handler 统一流程（校验→执行→事件→响应） | hub-*/src/handler.rs |

### 2.2 PEAA 模式

| 模式 | 应用场景 | 实现位置 |
|------|---------|---------|
| Repository | WorkItemRepo trait 抽象数据访问 | hub-common/src/repo.rs |
| Service Layer | TaskScheduler, auto_assign 业务逻辑 | hub-workitem/src/task_scheduler.rs |
| Data Mapper | sqlx::FromRow 映射 DB row → struct | hub-*/src/model.rs |
| Identity Map | 三级覆盖缓存 | hub-agent-config/src/scope_resolver.rs |

### 2.3 DDD 模式

| 模式 | 应用场景 | 实现位置 |
|------|---------|---------|
| Domain Event | PlatformEvent 领域事件 | hub-common/src/event_bus.rs |
| Aggregate Root | WorkItem（transition 通过它操作） | hub-workitem/src/model.rs |
| Value Object | Priority, WorkItemType（不可变，按值比较） | hub-workitem/src/model.rs |
| Repository | 数据访问抽象（trait + impl） | hub-*/src/repo.rs |

### 2.4 微服务/云原生模式

| 模式 | 应用场景 | 实现位置 |
|------|---------|---------|
| Event Sourcing | WorkItemTransition 历史记录 | hub-workitem/src/handler.rs |
| Health Check | /health 端点 | hub-api/src/router.rs |
| Externalized Config | YAML 配置文件 | config/ |
| Distributed Tracing | request_id 贯穿全链路 | hub-api/src/middleware.rs |

## 三、代码规范

### 3.1 Rust 命名规范

| 类型 | 风格 | 示例 |
|------|------|------|
| struct / enum | PascalCase | `WorkItem`, `ProjectStatus` |
| function / method | snake_case | `validate_transition`, `get_ai_view` |
| constant | SCREAMING_SNAKE_CASE | `MAX_RETRIES`, `TASK_TRANSITIONS` |
| module | snake_case | `state_machine`, `event_bus` |
| trait | PascalCase | `WorkItemRepo`, `ViewRenderer` |
| crate | kebab-case | `hub-workitem`, `hub-common` |

### 3.2 错误处理规范

```rust
// 统一使用 PlatformError enum
// handler 返回 Result<Json<T>, PlatformError>
// 通过 From<sqlx::Error> 自动转换数据库错误
// 不使用 unwrap() / expect() — 除非是初始化阶段的不可恢复错误
```

### 3.3 测试规范

```rust
// 单元测试：#[tokio::test] + MockRepo
// 集成测试：#[sqlx::test(migrations = "./migrations")]
// 测试文件位置：同模块 tests/ 目录或 #[cfg(test)] mod tests
// 命名：test_{function_name}_{scenario}_{expected_result}
```

### 3.4 文档规范

```rust
/// Brief one-line description.
///
/// Detailed explanation of design intent, why this approach was chosen,
/// and how it interacts with other components.
///
/// # Arguments
/// * `id` - The workitem unique identifier
///
/// # Returns
/// The updated workitem with new status and assignee
///
/// # Errors
/// * `PlatformError::NotFound` - if workitem does not exist
/// * `PlatformError::InvalidTransition` - if state transition is illegal
```

## 四、技术要求

### 4.1 依赖库

| 依赖 | 版本 | 用途 |
|------|------|------|
| axum | 0.7+ | HTTP 框架 |
| sqlx | 0.7+ | 数据库（PostgreSQL） |
| tokio | 1.0+ | 异步运行时 |
| serde / serde_json | 1.0+ | 序列化 |
| chrono | 0.4+ | 时间处理 |
| tracing | 0.1+ | 结构化日志 |
| uuid | 1.0+ | ID 生成 |
| thiserror | 1.0+ | 错误类型派生 |

### 4.2 性能要求

| 指标 | 目标 |
|------|------|
| API P95 响应时间 | < 100ms（简单 CRUD）/ < 500ms（聚合查询） |
| 并发项目数 | 1-5（Phase 1） |
| 数据库连接池 | max_connections = 10 |

### 4.3 安全要求

| 要求 | 实现 |
|------|------|
| SQL 注入防护 | sqlx 参数化查询（编译时校验） |
| 输入校验 | Pydantic-style validation（serde + custom validators） |
| 敏感数据 | 不在日志中输出 token/password |

## 五、实施顺序

### Phase 1 里程碑

```
M1: 基础骨架（Week 1）
  ├── Cargo workspace 初始化
  ├── hub-common: PgPool + PlatformError + EventBus
  ├── hub-api: axum server + /health
  └── migrations: 初始 schema（projects + team_members）

M2: 项目管理（Week 2）
  ├── hub-project: CRUD + members + suspend/resume
  ├── hub-api: project routes + AI/Card/Progress views
  └── seeds: system roles + shared rules

M3: 工单管理（Week 3-4）
  ├── hub-workitem: CRUD + state machine + auto_assign
  ├── hub-workitem: TaskScheduler (start_execution + on_task_completed)
  ├── hub-workitem: comments + dependencies + transitions
  └── hub-api: workitem routes + AI/Card/Timeline views

M4: 配置与产物（Week 5）
  ├── hub-agent-config: roles + rules + processes + scope_resolver
  ├── hub-artifact: CRUD + versioning (structured only)
  ├── hub-snapshot: agent + workflow snapshots
  └── hub-api: remaining routes

M5: 集成测试（Week 6）
  ├── 端到端测试（完整 transition 流程）
  ├── 性能基准测试
  └── 文档（API spec）
```

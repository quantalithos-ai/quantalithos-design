### 1.2 编码约束

- 语言：Rust（engine 层）+ TypeScript（Shell UI），代码全英文
- 桌面框架：Tauri 2.x + tokio 1.0 + serde 1.0
- 前端框架：Vue 3 + Vite + TypeScript
- 不直接访问 platform 数据库（通过 HTTP API）
- 所有平台适配通过 trait 抽象 + 条件编译
- 不使用 unwrap()/expect()（除初始化阶段的不可恢复错误）
- Commit scope：engine | shell | bridge | platform-adapt | downloader | version | config | common

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

## 二、技术风险评估

**需要 Spike：Tauri WebView 沙箱隔离能力**

| 风险 | 验证方式 | 通过标准 |
|------|---------|---------|
| Tauri WebView 是否支持多实例独立存储 | 创建两个 WebView，各自写 localStorage | 互相读不到对方数据 |
| Tauri WebView 网络拦截能力 | 配置 CSP + navigation 白名单 | 非白名单域名请求被拦截 |
| Tauri commands 与 Vue 3 的通信延迟 | 测量 invoke() 往返时间 | P95 < 5ms |
| 本地文件加载性能（file:// 协议） | 加载 10MB 静态资源 | 加载时间 < 500ms |

Spike 代码位置：`spike/tauri_webview_sandbox/`（不合并主干）

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 0 | Tauri WebView 不支持多实例独立存储 | 概要设计，评估换 Electron 或 iframe 方案 |
| 阶段 0 | Tauri 网络拦截能力不足 | 详细设计，评估用 Service Worker 拦截替代 |
| 阶段 2 | platform API 不稳定导致下载频繁失败 | 详细设计，增加本地 mock server + 离线开发模式 |
| 阶段 3 | WebView 沙箱隔离在某平台不生效 | 概要设计，该平台降级为 iframe 模式 |
| 阶段 3 | 原生桥接延迟过高（P95 > 50ms） | 详细设计，评估批量调用 + 缓存策略 |
| 阶段 4 | 应用启动时间超过 5s | 详细设计 §十二，优化 WebView 创建 + 资源预加载 |

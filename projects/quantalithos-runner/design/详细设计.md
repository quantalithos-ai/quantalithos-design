## 二、数据结构

### 2.1 InstalledApp

```rust
// engine/app_manager.rs
//
// 已安装应用数据模型 — 描述用户设备上已下载并安装的应用。
//
// 设计意图：
//   Runner 类似微信小程序/Steam — 用户从 platform 下载应用包，
//   解压到本地，通过 WebView 容器运行。InstalledApp 记录每个应用的本地状态。
//
// 与 platform 的关系：
//   platform 存储构建产物（build artifacts），Runner 下载后变为 InstalledApp。
//   latest_version 通过定期检查 platform API 获取（GET /projects/:pid/builds?latest=true）。

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct InstalledApp {
    pub project_id: String,               // 所属项目 ID（如 "blog"）
    pub name: String,                     // 应用名称（如 "博客系统"）
    pub description: String,              // 应用描述
    pub icon_url: Option<String>,         // 应用图标 URL（从 platform 获取）
    pub current_version: String,          // 当前已安装版本（如 "0.3"）
    pub latest_version: Option<String>,   // 最新可用版本（检查更新后填入，None = 未检查）
    pub build_id: String,                 // 对应的构建 ID（如 "build-blog-003"）
    pub build_type: BuildType,            // 应用类型（决定 WebView 加载方式）
    pub install_path: String,             // 本地解压路径（如 "/data/apps/blog/"）
    pub install_size: u64,                // 安装大小（字节）— 用于存储管理
    pub status: AppStatus,                // 当前状态
    pub permissions: Vec<Permission>,     // 已授权的权限列表
    pub installed_at: DateTime<Utc>,      // 安装时间
    pub last_opened_at: Option<DateTime<Utc>>,  // 最后打开时间（用于排序"最近使用"）
}

/// 构建类型 — 决定 WebView 如何加载应用
///
/// WebApp：完整的前后端应用（本地启动 Nginx + API server）
/// StaticSite：纯静态站点（直接加载 index.html）
/// Game：WebGL/Canvas 游戏（加载 index.html，需要更大的内存配额）
/// FlutterWeb：Flutter Web 导出（加载 flutter 的 index.html + service worker）
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum BuildType {
    WebApp,                               // 前后端完整应用（Nginx + API）
    StaticSite,                           // 纯静态站点（HTML/CSS/JS）
    Game,                                 // WebGL / Canvas 游戏
    FlutterWeb,                           // Flutter Web 导出
}

/// 应用状态 — 生命周期状态机
///
/// Installing → Ready → Running → Ready（关闭后）
/// Ready → Updating → Ready（更新完成）
/// 任何状态 → Error（出错）
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum AppStatus {
    Installing,                           // 下载/解压中
    Ready,                                // 可运行（已安装，未打开）
    Running,                              // 运行中（WebView 已加载）
    Updating,                             // 更新中（下载新版本）
    Error,                                // 安装/运行出错（需要重试或重装）
}

/// 权限类型 — 应用可以请求的原生能力
///
/// 用户首次使用某权限时弹窗询问，授权后记录到 InstalledApp.permissions。
/// 用户可以在权限管理页面随时撤销。
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum Permission {
    Camera,          // 相机（拍照/扫码）
    Geolocation,     // 地理位置
    Storage,         // 本地存储（超出 WebView 默认配额）
    Notification,    // 系统通知
    Microphone,      // 麦克风
    Clipboard,       // 剪贴板读写
}
```

### 2.2 AppBundle（从 platform 下载的包）

```rust
// engine/downloader.rs
//
// 应用包 — 从 platform 下载的构建产物描述。
// Runner 根据 AppBundle 的信息下载、校验、解压应用。

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct AppBundle {
    pub build_id: String,                 // 构建 ID（如 "build-blog-003"）
    pub project_id: String,               // 所属项目
    pub version: String,                  // 版本号（如 "0.3"）
    pub build_type: BuildType,            // 应用类型（决定加载方式）
    pub artifacts: Vec<BundleArtifact>,   // 包含的产物列表（可能有多个文件）
    pub entry_point: String,              // 入口文件路径（如 "index.html" 或 "dist/index.html"）
    pub api_base_url: Option<String>,     // 后端 API 地址（WebApp 类型需要，StaticSite 不需要）
    pub checksum: String,                 // 整包 SHA256 校验（下载后验证完整性）
    pub total_size: u64,                  // 总大小（字节）— 下载前展示给用户
}

/// 包内单个产物 — 一个 AppBundle 可能包含多个文件（前端 + 后端 + 配置）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct BundleArtifact {
    pub name: String,                     // 文件名（如 "blog-frontend-v0.3.tar.gz"）
    pub artifact_type: String,            // 产物类型："static"（前端）| "binary"（后端）| "config"（配置）
    pub download_url: String,             // 下载地址（platform API URL）
    pub size: u64,                        // 文件大小（字节）
    pub checksum: String,                 // 单文件 SHA256（下载后逐个验证）
}
```

### 2.3 WebViewConfig（每个应用的 WebView 配置）

```rust
// engine/webview_container.rs
//
// WebView 配置 — 每个应用运行时的隔离和权限设置。
//
// 设计意图：
//   每个应用在独立的 WebView 中运行，互相隔离（存储/网络/权限）。
//   WebViewConfig 决定了 WebView 的安全边界。
//
// entry_url 两种模式：
//   本地模式：file:///apps/blog/index.html（已下载的应用）
//   预览模式：https://preview-blog.quantalithos.local（sandbox preview 模式）

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WebViewConfig {
    pub app_id: String,                   // 应用标识（= project_id）
    pub entry_url: String,                // WebView 加载的入口 URL
    pub sandbox: SandboxConfig,           // 沙箱隔离配置
    pub bridge_permissions: Vec<Permission>,  // 已授权的原生桥接权限
    pub user_agent: Option<String>,       // 自定义 UA（某些应用需要特定 UA）
    pub allow_navigation: Vec<String>,    // 允许跳转的域名白名单（防止应用跳转到外部网站）
}

/// 应用沙箱配置 — 隔离存储和网络
///
/// 每个应用有独立的存储空间（localStorage/IndexedDB/Cookies），
/// 互相不可见。网络访问通过白名单限制。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SandboxConfig {
    pub storage_path: String,             // 隔离存储路径（如 "/apps/blog/data/"）
    pub storage_quota_mb: u64,            // 存储配额（默认 100MB，超出后写入失败）
    pub network_whitelist: Vec<String>,   // 网络白名单（应用只能访问这些域名）
    pub allow_local_storage: bool,        // 是否允许 localStorage（默认 true）
    pub allow_indexed_db: bool,           // 是否允许 IndexedDB（默认 true）
    pub allow_cookies: bool,              // 是否允许 Cookies（默认 true）
}
```

### 3.1 AppManager 实现

```rust
// engine/app_manager.rs
//
// 应用管理器 — Runner 的核心组件，管理应用的安装/卸载/更新/启动。
//
// 设计意图：
//   AppManager 是 Runner 的"应用商店后端" — 从 platform 获取可用应用列表，
//   下载安装包，校验完整性，解压到本地，注册到 registry。
//   所有应用状态持久化到 registry.json（本地 JSON 文件）。

pub struct AppManager {
    apps: HashMap<String, InstalledApp>,  // 已安装应用（内存缓存，启动时从 registry.json 加载）
    storage_root: PathBuf,                // 应用存储根目录（如 "/apps/"）
    platform_client: PlatformClient,      // platform API 客户端（通过 gate 访问）
}

impl AppManager {
    /// 从 platform 拉取可安装的应用列表
    pub async fn fetch_available_apps(&self) -> Result<Vec<AvailableApp>, RunnerError> {
        let projects = self.platform_client.projects().list_with_builds().await?;
        Ok(projects.into_iter().map(|p| AvailableApp {
            project_id: p.id,
            name: p.name,
            description: p.description,
            latest_version: p.latest_build.map(|b| b.version),
            installed_version: self.apps.get(&p.id).map(|a| a.current_version.clone()),
            has_update: self.check_update(&p.id, &p.latest_build),
        }).collect())
    }

    /// 安装应用
    pub async fn install(&mut self, project_id: &str) -> Result<InstalledApp, RunnerError> {
        // 1. 获取最新构建信息
        let build = self.platform_client.builds()
            .get_latest(project_id).await?
            .ok_or(RunnerError::NoBuild(project_id.into()))?;

        // 2. 下载应用包
        let bundle_path = self.download(&build).await?;

        // 3. 校验 checksum
        let actual_hash = sha256_file(&bundle_path)?;
        if actual_hash != build.checksum {
            return Err(RunnerError::ChecksumMismatch {
                expected: build.checksum,
                actual: actual_hash,
            });
        }

        // 4. 解压到应用目录
        let install_path = self.storage_root.join(project_id);
        extract_zip(&bundle_path, &install_path)?;

        // 5. 读取 manifest
        let manifest = read_manifest(&install_path)?;

        // 6. 注册应用
        let app = InstalledApp {
            project_id: project_id.into(),
            name: manifest.name,
            description: manifest.description,
            current_version: build.version,
            build_id: build.build_id,
            build_type: manifest.build_type,
            install_path: install_path.to_string_lossy().into(),
            install_size: dir_size(&install_path)?,
            status: AppStatus::Ready,
            permissions: vec![],
            installed_at: Utc::now(),
            ..Default::default()
        };
        self.apps.insert(project_id.into(), app.clone());
        self.save_registry()?;

        Ok(app)
    }

    /// 检查更新
    pub async fn check_updates(&mut self) -> Result<Vec<UpdateInfo>, RunnerError> {
        let mut updates = vec![];
        for (pid, app) in &self.apps {
            let latest = self.platform_client.builds()
                .get_latest(pid).await?;
            if let Some(build) = latest {
                if build.version != app.current_version {
                    updates.push(UpdateInfo {
                        project_id: pid.clone(),
                        current_version: app.current_version.clone(),
                        new_version: build.version,
                        size: build.total_size,
                    });
                }
            }
        }
        Ok(updates)
    }
}
```

## 四、WebView 容器与应用沙箱

### 4.1 WebView 容器

```rust
// engine/webview_container.rs
//
// WebView 容器 — 每个应用运行在独立的 WebView 实例中。
//
// 设计意图：
//   WebView 是应用的"运行时沙箱" — 加载应用的 HTML/JS/CSS，
//   提供隔离的存储和网络环境，通过 NativeBridge 暴露受控的原生能力。
//
// 平台适配：
//   macOS → WKWebView（Safari 内核）
//   Windows → WebView2（Chromium 内核）
//   Web/PWA → iframe（浏览器沙箱）
//   通过 #[cfg(target_os)] 条件编译选择实现。

pub struct WebViewContainer {
    app_id: String,                       // 应用标识（= project_id）
    config: WebViewConfig,                // WebView 配置（入口 URL + 沙箱 + 权限）
    bridge: NativeBridge,                 // 原生桥接实例（处理 JS → Native 调用）
}

impl WebViewContainer {
    /// 创建并启动 WebView
    pub fn launch(app: &InstalledApp) -> Result<Self, RunnerError> {
        let config = WebViewConfig {
            app_id: app.project_id.clone(),
            entry_url: format!("file://{}/index.html", app.install_path),
            sandbox: SandboxConfig {
                storage_path: format!("{}/data/", app.install_path),
                storage_quota_mb: 100,
                network_whitelist: vec![
                    "localhost".into(),
                    "quantalithos.local".into(),
                ],
                allow_local_storage: true,
                allow_indexed_db: true,
                allow_cookies: true,
            },
            bridge_permissions: app.permissions.clone(),
            allow_navigation: vec![],
        };

        let bridge = NativeBridge::new(&app.project_id, &config.bridge_permissions);

        // 创建 WebView（平台相关）
        #[cfg(target_os = "macos")]
        let webview = create_wkwebview(&config, &bridge)?;
        #[cfg(target_os = "windows")]
        let webview = create_webview2(&config, &bridge)?;
        #[cfg(target_arch = "wasm32")]
        let webview = create_iframe(&config, &bridge)?;

        Ok(Self { app_id: app.project_id.clone(), config, bridge })
    }
}
```

```

  │  JS 环境（隔离）                          │

  │  ├── IndexedDB → /apps/blog/data/        │
  │  ├── fetch() → 只能访问白名单域名         │  ← 网络隔离

  └──────────────────────────────────────────┘

  ┌─ 电商平台 WebView ──────────────────────┐
  │                                          │
  │  完全独立的 JS 环境                       │
  │  ├── localStorage → /apps/shop/data/     │  ← 和博客互不可见
  │  └── ...                                 │
```

### 4.2 原生桥接

```rust
// engine/bridge.rs
//
// 原生桥接 — WebView 内的 JS 代码通过此桥接调用原生能力。
//
// 设计意图：
//   应用运行在 WebView 沙箱中，无法直接访问原生 API（相机/GPS/通知等）。
//   NativeBridge 在 WebView 中注入 window.quantalithos 全局对象，
//   应用通过它调用原生能力，Runner 在 Native 侧校验权限后执行。
//
// 安全模型：
//   1. 每个应用有独立的 NativeBridge 实例（不共享状态）
//   2. 调用前检查 permissions 列表（未授权 → 弹窗询问用户）
//   3. storage 始终可用（沙箱隔离，不需要额外授权）
//   4. 未知方法 → 返回错误（不会静默失败）

pub struct NativeBridge {
    app_id: String,                       // 所属应用（决定存储路径和权限范围）
    permissions: Vec<Permission>,         // 已授权的权限列表（从 InstalledApp 加载）
}

impl NativeBridge {
    /// 注入到 WebView 的 JS 全局对象
    pub fn inject_js(&self) -> String {
        format!(r#"
            window.quantalithos = {{
                appId: "{}",
                
                // 存储（始终可用，沙箱隔离）
                storage: {{
                    get: (key) => window.__bridge_call("storage.get", {{ key }}),
                    set: (key, value) => window.__bridge_call("storage.set", {{ key, value }}),
                    remove: (key) => window.__bridge_call("storage.remove", {{ key }}),
                }},
                
                // 相机（需要授权）
                camera: {{
                    capture: () => window.__bridge_call("camera.capture", {{}}),
                    isAvailable: () => {},
                }},
                
                // 地理位置（需要授权）
                geolocation: {{
                    getCurrentPosition: () => window.__bridge_call("geo.current", {{}}),
                }},
                
                // 通知（需要授权）
                notification: {{
                    show: (title, body) => window.__bridge_call("notify.show", {{ title, body }}),
                }},
                
                // 剪贴板（需要授权）
                clipboard: {{
                    read: () => window.__bridge_call("clipboard.read", {{}}),
                    write: (text) => window.__bridge_call("clipboard.write", {{ text }}),
                }},
                
                // 应用信息（始终可用）
                app: {{
                    getVersion: () => "{}",
                    getPlatform: () => window.__bridge_call("app.platform", {{}}),
                }},
            }};
        "#, self.app_id, "0.3")
    }

    /// 处理 JS 调用
    pub async fn handle_call(&self, method: &str, args: serde_json::Value) -> Result<serde_json::Value, RunnerError> {
        // 权限检查
        let required = match method {
            "camera.capture" => Some(Permission::Camera),
            "geo.current" => Some(Permission::Geolocation),
            "notify.show" => Some(Permission::Notification),
            "clipboard.read" | "clipboard.write" => Some(Permission::Clipboard),
            "storage.get" | "storage.set" | "storage.remove" => None, // 存储始终可用
            "app.platform" => None,
            _ => return Err(RunnerError::UnknownBridgeMethod(method.into())),
        };

        if let Some(perm) = required {
            if !self.permissions.contains(&perm) {
                return Err(RunnerError::PermissionDenied(perm));
            }
        }

        // 执行原生操作
        match method {
            "storage.get" => {
                let key = args["key"].as_str().unwrap_or("");
                let value = self.storage_get(key)?;
                Ok(serde_json::json!(value))
            },
            "storage.set" => {
                let key = args["key"].as_str().unwrap_or("");
                let value = args["value"].as_str().unwrap_or("");
                self.storage_set(key, value)?;
                Ok(serde_json::json!(true))
            },
            "camera.capture" => {
                let photo = self.capture_photo().await?;
                Ok(serde_json::json!({ "data": photo.base64, "width": photo.width, "height": photo.height }))
            },
            "geo.current" => {
                let pos = self.get_position().await?;
                Ok(serde_json::json!({ "lat": pos.lat, "lng": pos.lng, "accuracy": pos.accuracy }))
            },
            _ => Err(RunnerError::UnknownBridgeMethod(method.into())),
        }
    }
}
```

### 5.2 VersionManager

```rust
// engine/version_manager.rs
//
// 版本管理器 — 应用的更新、回滚、备份清理。
//
// 更新策略（6 步）：
//   1. 下载新版本到临时目录（不影响当前运行的应用）
//   2. 校验 checksum（防止下载损坏或篡改）
//   3. 备份旧版本（用于回滚）
//   4. 替换（原子操作：rename）
//   5. 更新注册信息
//   6. 清理旧备份（保留最近 2 个版本）
//
// 回滚策略：
//   交换当前版本和最近的备份（双向 rename），不需要重新下载。
//   用户数据（/data/ 目录）不随版本更新/回滚变化。

pub struct VersionManager {
    app_manager: Arc<AppManager>,         // 应用管理器（读写注册信息）
    platform_client: PlatformClient,      // platform API（获取最新构建信息）
}

impl VersionManager {
    /// 更新应用到最新版本
    pub async fn update(&self, project_id: &str) -> Result<InstalledApp, RunnerError> {
        let app = self.app_manager.get(project_id)?;
        let old_path = app.install_path.clone();
        let old_version = app.current_version.clone();

        // 1. 下载新版本到临时目录
        let new_build = self.platform_client.builds()
            .get_latest(project_id).await?
            .ok_or(RunnerError::NoBuild(project_id.into()))?;

        let temp_path = format!("{}.updating", old_path);
        self.app_manager.download_to(&new_build, &temp_path).await?;

        // 2. 校验
        let hash = sha256_file(&format!("{}.zip", temp_path))?;
        if hash != new_build.checksum {
            fs::remove_dir_all(&temp_path).ok();
            return Err(RunnerError::ChecksumMismatch {
                expected: new_build.checksum,
                actual: hash,
            });
        }

        // 3. 备份旧版本（用于回滚）
        let backup_path = format!(".backup-{}", old_path, old_version);
        fs::rename(&old_path, &backup_path)?;

        // 4. 替换
        fs::rename(&temp_path, &old_path)?;

        // 5. 更新注册信息
        let updated = self.app_manager.update_version(
            project_id, &new_build.version, &new_build.build_id
        )?;

        // 6. 清理备份（保留最近 2 个版本用于回滚）
        self.cleanup_old_backups(project_id, 2)?;

        Ok(updated)
    }

    /// 回滚到上一个版本
    pub async fn rollback(&self, project_id: &str) -> Result<InstalledApp, RunnerError> {
        let app = self.app_manager.get(project_id)?;
        let install_path = &app.install_path;

        // 查找最近的备份
        let backup = self.find_latest_backup(project_id)?
            .ok_or(RunnerError::NoBackup(project_id.into()))?;

        // 交换当前版本和备份
        let temp = format!("{}.rollback-temp", install_path);
        fs::rename(install_path, &temp)?;
        fs::rename(&backup.path, install_path)?;
        fs::rename(&temp, &backup.path)?;

        // 更新注册信息
        let rolled_back = self.app_manager.update_version(
            project_id, &backup.version, &backup.build_id
        )?;

        Ok(rolled_back)
    }
}
```

## 十一、并发与一致性

### 11.1 应用安装/更新的并发控制

```
场景：用户快速点击"安装"两次，或安装过程中点击"取消"再重新安装

  请求 A（安装 blog）          请求 B（安装 blog）
  ─────────────────          ─────────────────
       │                          │
  ① 检查 apps 中是否已有 blog     │
     → 没有，继续                  │
       │                     ① 检查 apps 中是否已有 blog
       │                        → 没有，继续
  ② 设置状态 Installing           │
       │                     ② 设置状态 Installing ← 冲突！
       ▼                          ▼
    两个下载任务同时进行 → 文件覆盖 → 数据损坏

解决方案：操作锁（per-app mutex）

  AppManager {
      apps: HashMap<String, InstalledApp>,
      locks: HashMap<String, Arc<Mutex<()>>>,  // 每个应用一把锁
  }

  async fn install(&mut self, project_id: &str) -> Result<InstalledApp, RunnerError> {
      let lock = self.locks
          .entry(project_id.into())
          .or_insert_with(|| Arc::new(Mutex::new(())))
          .clone();

      let _guard = lock.lock().await;

      // 加锁后再次检查状态（double-check）
      if let Some(app) = self.apps.get(project_id) {
          if app.status == AppStatus::Installing {
              return Err(RunnerError::AlreadyInstalling(project_id.into()));
          }
          if app.status == AppStatus::Ready {
              return Err(RunnerError::AlreadyInstalled(project_id.into()));
          }
      }

      // ... 正常安装流程
  }
```

### 11.2 WebView 生命周期竞态

```
场景：用户快速切换应用（打开 A → 立即切换到 B → A 还在加载中）

  时间线：
  ─────────────────────────────────────────────────
  t0  用户点击打开 blog
  t1  创建 WebView(blog)，开始加载 index.html
  t2  用户点击打开 shop（blog 还没加载完）
  t3  需要关闭 blog WebView + 创建 shop WebView
  t4  blog WebView 的 onLoad 回调触发 ← 此时 blog 已被关闭

解决方案：generation counter（代际计数器）

  struct WebViewManager {
      current_app: Option<String>,
      generation: u64,  // 每次切换 +1
  }

  async fn switch_app(&mut self, app_id: &str) {
      self.generation += 1;
      let my_gen = self.generation;

      // 关闭当前应用
      if let Some(current) = &self.current_app {
          self.close_webview(current).await;
      }

      // 创建新 WebView
      self.current_app = Some(app_id.into());
      let webview = WebViewContainer::launch(app).await;

      // 加载完成回调中检查 generation
      webview.on_load(move |_| {
          if my_gen != self.generation {
              // 用户已切换到其他应用，忽略此回调
              return;
          }
          // 正常处理加载完成
      });
  }
```

### 11.3 版本更新与运行中应用的冲突

```
场景：应用正在运行时，后台检查到新版本并开始更新

  解决方案：运行中的应用不允许更新

  async fn update(&self, project_id: &str) -> Result<InstalledApp, RunnerError> {
      let app = self.app_manager.get(project_id)?;

      // 运行中不允许更新
      if app.status == AppStatus::Running {
          return Err(RunnerError::AppRunning(project_id.into()));
      }

      // ... 正常更新流程
  }

  更新流程的原子性保证：
    1. 下载到临时目录（/apps/blog.updating/）
    2. 校验 checksum
    3. 备份旧版本（rename /apps/blog/ → /apps/blog.backup-0.2/）
    4. 替换（rename /apps/blog.updating/ → /apps/blog/）

  步骤 3-4 使用 rename（原子操作），中间断电不会导致数据丢失：
    - 步骤 3 前断电：旧版本完好
    - 步骤 3-4 之间断电：旧版本在 backup，新版本在 .updating
      → 启动时检测到异常状态 → 自动回滚（rename backup 回来）
    - 步骤 4 后断电：新版本已就位
```

### 12.1 应用启动时间预算

```

  │  加载 index.html（本地文件）     │ < 200ms │ file://    │
  │  应用 JS 初始化                 │ < 1500ms│ 应用自身   │
  │  首屏渲染                       │ < 500ms │ 应用自身   │
  │  ─────────────────────────────────────────────────── │
  │  总计                           │ < 2760ms│           │
  │  余量                           │  240ms  │           │
  └──────────────────────────────────────────────────────┘
```

### 12.2 WebView 内存管理

```
Phase 2：单应用运行模式

  同一时间只有一个 WebView 实例运行。
  切换应用时：关闭当前 WebView → 创建新 WebView。
  内存上限：单 WebView < 256MB。

Phase 3：多应用切换模式

  最多 3-5 个 WebView 实例。
  后台应用冻结策略：
    - 切到后台 > 30s → 冻结 JS 执行（暂停 timer/requestAnimationFrame）
    - 切到后台 > 5min → 保存状态 → 销毁 WebView → 切回时重建
    - 内存压力时 → 按 LRU 顺序销毁后台应用

  内存监控：
    定期检查 WebView 进程内存（每 10s）
    超过 200MB → 日志警告
    超过 400MB → 提示用户重启应用
```

### 12.3 应用包大小优化

```
下载优化：

  Phase 2：
    - ZIP 压缩（通常压缩率 60-70%）
    - 断点续传（HTTP Range 请求）
    - 下载进度展示

  Phase 3：
    - 增量更新（bsdiff/zstd patch）
      旧版本 + patch → 新版本
      patch 大小通常为全量包的 10-30%
    - 资源去重（多个应用共享的 JS 库只下载一次）

  本地存储优化：
    - 每个应用存储配额 100MB（可在设置中调整）
    - 备份版本最多保留 2 个
    - 超过总存储限制时提示用户清理
```

### 12.4 网络请求优化

```
应用列表缓存策略：

  首次加载：GET /api/projects?has_builds=true → 缓存到内存
  缓存有效期：60s
  刷新策略：下拉刷新 / 切回应用列表页时检查

  更新检查频率：
    前台时：每 5 分钟检查一次
    后台时：不检查
    用户手动：随时可触发

  请求超时：
    应用列表：5s
    应用包下载：不超时（但有进度监控，30s 无进度则重试）
    更新检查：3s
```

## 十四、幂等设计

### 14.1 应用安装幂等

```
场景：用户点击"安装"后网络超时，不确定是否成功，再次点击"安装"

  幂等键：project_id + version

  处理逻辑：

  install(project_id, version)
      │
      ▼
  检查 registry.json 中是否已有该 project_id
      │
      ├── 已有 + 版本相同 + 状态=Ready → 返回已安装信息（幂等成功）
      │
      ├── 已有 + 状态=Installing → 返回 AlreadyInstalling（安装进行中）
      │
      ├── 已有 + 版本不同 → 走更新流程
      │
      └── 没有 → 正常安装

  启动时异常状态修复：

  Runner 启动时扫描 registry.json：
      │
      ├── 状态=Installing → 安装未完成
      │   检查 install_path 是否存在完整文件
      │   ├── 完整 → 修正状态为 Ready
      │   └── 不完整 → 清理残留文件 + 从 registry 移除
      │
      ├── 状态=Updating → 更新未完成
      │   检查 .updating 临时目录
      │   ├── 存在 → 清理临时目录 + 恢复状态为 Ready
      │   └── 不存在 → 检查 backup 是否需要回滚
      │
      └── 状态=Ready/Running → 正常
```

### 14.2 应用更新幂等

```
场景：更新过程中 Runner 崩溃，重启后再次触发更新

  幂等键：project_id + target_version

  处理逻辑：

  update(project_id, target_version)
      │
      ▼
  检查当前版本是否已经是 target_version
      │
      ├── 是 → 返回成功（幂等，已是目标版本）
      │
      └── 否 → 检查是否有残留的 .updating 目录
          │
          ├── 有 → 校验 .updating 目录的完整性
          │   ├── 完整 + checksum 匹配 → 跳过下载，直接执行替换
          │   └── 不完整 → 清理后重新下载
          │
          └── 没有 → 正常更新流程
```

### 14.3 应用卸载幂等

```
场景：卸载过程中断，再次卸载

  幂等键：project_id

  处理逻辑：

  uninstall(project_id)
      │
      ▼
  检查 registry.json 中是否有该 project_id
      │
      ├── 没有 → 返回成功（幂等，已卸载）
      │
      └── 有 → 正常卸载流程
          1. 从 registry 移除记录
          2. 保存 registry.json
          3. 删除应用目录
          4. 删除备份目录

  注意：先更新 registry 再删文件。
  如果删文件时中断，下次启动时扫描发现
  registry 中没有该应用 → 清理孤立目录。
```

### 14.4 桥接调用幂等

```
原生桥接调用天然幂等的操作：
  storage.get(key)     → 读操作，天然幂等
  storage.set(key, v)  → 写操作，最后一次写入生效
  storage.remove(key)  → 删除操作，重复删除无副作用
  app.getVersion()     → 读操作，天然幂等
  app.getPlatform()    → 读操作，天然幂等

非幂等操作（需要应用层处理）：
  camera.capture()     → 每次调用都会打开相机，由应用自行控制
  notify.show(t, b)    → 每次调用都会弹通知，由应用自行去重
```

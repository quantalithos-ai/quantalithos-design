## 二、技术风险评估

**需要 Spike：LLM function calling 验证**

| 风险 | 验证方式 | 通过标准 |
|------|---------|---------|
| Anthropic SDK function calling 返回格式 | 最简脚本调用 Claude API + 工具定义 | tool_calls 包含正确的 name + arguments |
| OpenAI-compatible provider tool calling 差异（Kimi / MiniMax / GLM） | 分别用 `openai` SDK 调用各 provider 的 chat completion + tool 定义 | 返回体可统一解析为相同 `ToolCall` 结构 |
| Provider-specific 参数兼容性（temperature / thinking / tool_choice） | 对每个 provider 做最小参数矩阵验证 | 不会因默认参数注入导致 400 或语义错误 |
| arguments 是否总是合法 JSON | 10 种工具定义测试 | 100% 可解析 |
| 多轮 think→act 循环稳定性 | 模拟 3 轮循环 | 无异常 |

Spike 代码位置：`spike/llm_function_calling.py`（不合并主干）

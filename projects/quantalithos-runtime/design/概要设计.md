# quantalithos-runtime 概要设计

> Agent 运行时 — 统一 Agent 模型、三级控制、消息驱动主循环

---

## 一、项目定位

### 1.1 核心职责

Agent Runtime 是整个 AI 研发协作平台的核心引擎，负责：

- Agent 生命周期管理（创建、挂起、恢复、销毁）
- Agent 角色定义加载（从外部加载，不自带模板）
- LLM 调用封装（统一接口、流式输出、路由预留）
- 工具调用系统（三层权限校验、沙箱隔离、MCP 预留）
- 消息驱动主循环（统一入口、状态栈管理）
- 三级控制（Free / Guided / Enforced）
- 安全防御（prompt 隔离、输入清洗、沙箱加固）

技术栈：Phase 1 纯 Python，Phase 2 按需引入 Rust（PyO3）

### 1.2 在整体架构中的位置

```
quantalithos-chat (聊天前端)
      │
      │ sdk-wasm
      ▼
quantalithos-gate (API 网关)

      │                  │                  │
      ▼                  ▼                  ▼
quantalithos-flow       quantalithos-platform     ╔═════════════════╗
(流程引擎/daemon)   (平台数据服务)        ║ quantalithos-runtime  ║
      │                  │           ║ (Agent 运行时)    ║
      │                  │           ╚═════════════════╝
      └──────────────────┴────────────────────┘
                              │
                     ┌────────┴────────┐
                     │                 │
                     ▼                 ▼
              quantalithos-sync       quantalithos-infra
```

### 1.3 与 quantalithos-flow 的分工

| 职责 | flow | runtime |
|------|------|---------|
| 项目级流程编排 | ✅ | — |
| Agent 生命周期指令 | 发出 agent_create/destroy/suspend/resume | ✅ 执行 |
| 任务分配 | 发出 FlowMessage(task_assign) | ✅ 执行 |
| Agent think→act 循环 | — | ✅ |
| 工具权限（节点级） | 下发 allowed_tools | ✅ 校验 |
| 门禁与审批 | ✅ | — |
| LLM 调用 | — | ✅ |

### 1.4 与 quantalithos-sync 的衔接

runtime 不自带任何模板。角色定义、共享规则、工作流模板全部从外部加载：
- Phase 1：从本地文件（quantalithos-sync restore 拉取到 `project_files/` 目录）
- Phase 2：从 platform API

## 三、核心设计决策

### 3.1 统一 Agent 模型与三级控制

所有 Agent 同一种类型，通过三级控制区分行为。详见 `docs/design/Agent统一模型与三级控制设计.md`。

| 级别 | 名称 | 说明 | 适用场景 |
|------|------|------|---------|
| Level 1 | Free | LLM 自己决定怎么做 | 对话、回答问题、头脑风暴 |
| Level 2 | Guided | prompt 里注入步骤指引 | Assistant 启动流程、需求收集 |
| Level 3 | Enforced | 每步只注入当前步骤 | TDD、代码审查、发布流程 |

状态栈：Agent 用状态栈记录"我现在在做什么"（idle / task / session / reply / waiting）。

统一消息入口：POST /messages，所有输入（任务分配、群聊消息、用户消息）走同一个入口。

### 3.2 工具权限（三层）

```
最终可用工具 = 状态允许 ∩ 角色 tools ∩ 任务 allowed_tools

第一层 状态级：
  idle（普通角色）→ 只读 + send_chat_message
  idle（管理角色 TL/Assistant）→ 只读 + task_create + workitem_assign + send_chat_message
  task → 由第二三层决定
  reply / session → 只读 + send_chat_message

第二层 角色级：角色定义的 tools 字段
第三层 节点级：任务分配时的 allowed_tools
```

### 3.3 安全防御

- prompt 隔离：用户输入和系统指令之间加隔离标记
- 输入清洗：移除伪标签和注入模式
- prompt 优先级保护：shared_rules 硬约束在最高优先级，不可被项目级覆盖
- 沙箱加固：Docker 非 root + 只读文件系统 + 网络隔离 + seccomp
- 怀疑机制：代码审查/测试/阶段交接时注入"前序产出可能有错"的提示

### 3.4 Prompt 五层组装

```
第一层：系统硬约束（shared_rules 中有 schema 的部分，不可覆盖）
第二层：角色身份 + 约束
第三层：软性指引（shared_rules 中没有 schema 的部分）
第四层：任务上下文（安全隔离标记包裹）
第五层：用户输入（最低信任级别，安全隔离标记包裹）
```

### 3.5 LLM 调用

- 统一客户端接口（OpenAI / Anthropic）
- 路由预留：Phase 1 固定模型，Phase 2 按节点类型选择模型
- 错误处理：超时/限流指数退避重试，最多 3 次
- 可观测性：按 OpenTelemetry GenAI 语义约定记录 gen_ai.* 属性

### 3.6 记忆系统

- Phase 1：内存对话记忆（每个 Agent 独立的 conversation 列表）
- Phase 2：持久化到 PostgreSQL + 记忆压缩
- Phase 3：长期记忆（向量库，跨项目经验检索）

### 3.7 MCP 兼容预留

工具注册表预留 MCP 接口。Phase 1 不实现，但接口设计兼容 MCP 的 JSON-RPC + inputSchema 格式。

## 四、接口设计

### 4.1 统一消息入口

```
POST /messages     接收所有消息（FlowMessage）
GET  /health       健康检查
GET  /agents       当前活跃的 Agent 列表
GET  /agents/{id}  Agent 详情
```

### 4.2 消息类型

| 类型 | 说明 | 需要 Agent 已存在 |
|------|------|------------------|
| agent_create | 创建 Agent 实例 | ❌ |
| agent_destroy | 销毁 Agent 实例 | ✅ |
| agent_suspend | 挂起 Agent | ✅ |
| agent_resume | 恢复 Agent | ❌ |
| task_assign | 分配任务 | ✅（不存在返回 404） |
| session_start | 发起协作会议 | ✅ |
| session_end | 结束协作会议 | ✅ |
| chat_message | 群聊消息 | ✅ |
| ask_reply | ask_teammate 回复 | ✅ |
| user_message | 用户直接消息 | ✅ |
| task_cancel | 取消任务 | ✅ |

### 4.3 上报结果

```python
class NodeResult:
    message_id: str           # 对应的 FlowMessage.message_id
    agent_id: str
    result_type: str          # completed | blocked | failed
    output: Optional[dict]
    reason: Optional[str]
    reasoning_trace: Optional[str]  # 推理链摘要（可追溯性）
    created_at: datetime
```

## 五、Phase 分期

### Phase 1

| 模块 | 范围 |
|------|------|
| api | POST /messages 统一入口 |
| engine | MainLoop（task_assign + chat_message）+ AgentExecutor |
| agent | 创建/销毁 + 外部加载角色 + 五层 prompt + 输入清洗 |
| llm | OpenAI + Anthropic 客户端 |
| tools | 内置工具 + submit_step_result + ask_teammate + send_chat_message + workitem_ops |
| memory | 内存对话记忆 |
| 控制级别 | Level 1 (Free) + Level 3 (Enforced) |
| 角色 | Assistant + Tech Lead |

### Phase 2

| 模块 | 范围 |
|------|------|
| engine | WorkflowEngine (Level 3) + SessionHandler |
| agent | 挂起/恢复 + platform API 加载 + Level 2 (Guided) |
| llm | 基于规则的模型路由 |
| tools | MCP 兼容 |
| memory | 持久化到 PostgreSQL |
| 角色 | Backend Dev + Frontend Dev + Tester + DevOps |

### Phase 3

| 模块 | 范围 |
|------|------|
| llm | 自适应路由（xRouter） |
| memory | 向量库长期记忆 |
| 安全 | gVisor/Firecracker 沙箱 |
| runtime | Rust 框架骨架（PyO3） |

### 1.2 编码约束

- 语言：Rust，代码全英文
- 框架：axum 0.7 + bollard 0.16 + tokio 1.0 + serde 1.0 + serde_yaml 0.9
- 外部依赖：Docker Engine（必须运行）
- 不直接依赖 platform/flow/runtime（通过 HTTP API 通信）
- 不使用 unwrap()/expect()（除初始化阶段）
- Commit scope：api | docker | gitea | templates | config | common

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

## 二、技术风险评估

**需要 Spike：bollard Docker API 集成**

| 风险 | 验证方式 | 通过标准 |
|------|---------|---------|
| bollard 能否通过 unix socket 调用 Docker API | 写最简 Rust 程序调用 docker.list_containers() | 返回容器列表 |
| bollard exec 能否获取 stdout/stderr 流 | 调用 docker.create_exec + start_exec | 获取命令输出 + exit code |
| docker-compose up 能否通过 bollard 触发 | 测试 bollard 调用 `docker compose up -d` | 容器组启动成功 |

Spike 代码位置：`spike/bollard_test/`（不合并主干）

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 0 | bollard 无法通过 unix socket 连接 Docker | 概要设计，评估换 shiplift 或直接调用 Docker CLI |
| 阶段 0 | docker compose 无法通过 bollard 触发 | 详细设计，改为 std::process::Command 调用 docker compose CLI |
| 阶段 2 | 容器模板渲染逻辑过于复杂 | 详细设计，评估引入 tera 模板引擎替代手写字符串替换 |
| 阶段 3 | compose up 启动时间 > 60s（镜像过大） | 概要设计，精简基础镜像或改为预拉取策略 |
| 阶段 4 | exec 流式输出在大输出时内存溢出 | 详细设计，改为流式写入临时文件 + 分页读取 |
| 阶段 5 | docker ps 恢复状态不完整 | 详细设计，引入本地 JSON 文件持久化 sandbox_store |

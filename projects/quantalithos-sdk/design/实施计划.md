### 1.2 编码约束

- 语言：Rust，代码全英文
- 框架：reqwest 0.12 + serde 1.0 + chrono 0.4 + wasm-bindgen 0.2 + js-sys 0.3
- 编译目标：native (x86_64) + wasm32-unknown-unknown
- sdk-models 零外部依赖（仅 serde + chrono）
- 依赖方向严格单向：models → api/ws → store → wasm
- 不使用 unwrap()/expect()（除测试代码）
- Commit scope：models | api | ws | store | wasm | bindings | common

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

### 1.4 工具链准备

```bash
# WASM 编译目标
rustup target add wasm32-unknown-unknown
# wasm-bindgen CLI
cargo install wasm-bindgen-cli
# wasm-pack（测试用）
cargo install wasm-pack
# Node.js（npm 发布用）
node --version  # >= 18
```

## 二、技术风险评估

**需要 Spike：reqwest WASM target + wasm-bindgen 集成**

| 风险 | 验证方式 | 通过标准 |
|------|---------|---------|
| reqwest 在 wasm32 target 下能否正常发 HTTP 请求 | 写最简 WASM 程序调用 reqwest GET | 浏览器中 fetch 成功返回 |
| wasm-bindgen 能否正确传递 Rust struct 到 JS | 定义简单 struct + #[wasm_bindgen] 导出 | JS 侧能读取 struct 字段 |
| serde_json 序列化的 JSON 能否在 JS 侧正确解析 | Rust 序列化 → JS JSON.parse | 字段名和值一致 |
| WASM 包体积是否在预算内 | 编译 release + gzip 测量 | < 300KB gzip（最简 API 客户端） |

Spike 代码位置：`spike/wasm_reqwest_test/`（不合并主干）

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 0 | reqwest WASM target 编译失败或运行时异常 | 概要设计，评估换 gloo-net 或手写 fetch 封装 |
| 阶段 0 | WASM 包体积 > 500KB（最简客户端） | 概要设计，评估 sdk-api 用 TS 重写（仅 web 端） |
| 阶段 2 | sdk-models 与 platform JSON 不兼容 | 详细设计，对齐字段名/类型/Optional 标注 |
| 阶段 3 | wasm-bindgen 无法导出复杂返回类型 | 详细设计，统一用 JSON 字符串传递（不依赖自动类型转换） |
| 阶段 4 | SdkError → JsValue 转换丢失信息 | 详细设计，改为 JSON 序列化错误对象 |
| 阶段 5 | wasm-opt 优化后功能异常 | 降低优化级别（-O2 替代 -Oz）或跳过 wasm-opt |

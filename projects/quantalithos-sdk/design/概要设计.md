# quantalithos-sdk 概要设计

> 跨平台客户端 SDK — Rust 实现，模块化 crate，支持 WASM/Tauri/Flutter/Native 绑定

---

## 一、项目定位

### 1.1 核心职责

quantalithos-sdk 是所有客户端（web、desktop、mobile）与 quantalithos-platform 交互的统一基础库。

```
                    quantalithos-platform (API)
                           │
                           │ HTTP + WebSocket
                           │
                    ╔══════╧══════════╗
                    ║ quantalithos-   ║
                    ║   sdk (Rust)    ║
                    ╚══════╤══════════╝
                           │
              ┌────────────┼────────────────────┐
              │            │                    │
              ▼            ▼                    ▼
         sdk-wasm     Tauri 直接调用      UniFFI 绑定
         (浏览器)     (桌面端)            (iOS/Android/Flutter)
              │            │                    │
              ▼            ▼                    ▼
         quantalithos  quantalithos        quantalithos
           -chat         -chat               -mobile
         (Vue 3 web)   (Tauri desktop)     (Phase 3)
```

**不做的事：**
- 不做 UI 渲染 — 那是各端的事
- 不做平台特性（通知、托盘）— 那是各端的事
- 不做业务编排 — 那是 flow 的事

### 1.2 谁消费 SDK

| 消费者 | 使用的 crate | 绑定方式 |
|--------|-------------|---------|
| quantalithos-chat (Vue 3 web) | sdk-models + sdk-api + sdk-ws + sdk-store → sdk-wasm | WASM + TS 薄封装 |
| quantalithos-chat (Tauri desktop) | sdk-models + sdk-api + sdk-ws + sdk-store | Rust 直接调用 |
| quantalithos-sync | sdk-models + sdk-api | Rust 直接调用 |
| quantalithos-mobile (Phase 3) | sdk-models + sdk-api + sdk-ws + sdk-store | UniFFI → Swift/Kotlin |

### 1.3 与 quantalithos-sync 的关系

sync 当前自己实现了 platform API 客户端（client/ 模块）。SDK 完成后，sync 应该迁移到使用 sdk-api：

```
当前：
  quantalithos-sync/src/client/     # 自己实现的 API 客户端
    ├── project.rs
    ├── workitem.rs
    └── artifact.rs

迁移后：
  quantalithos-sync
    └── 依赖 sdk-models + sdk-api   # 复用 SDK 的 API 客户端
```

### 2.1 依赖关系

```
sdk-models（零依赖，纯数据结构）
    │
    ├──> sdk-api（HTTP 客户端）
    │       │
    ├──> sdk-ws（WebSocket）
    │       │
    └───────┴──> sdk-store（状态管理，依赖 api + ws）
                     │
                     └──> sdk-wasm（WASM 绑定，依赖 store）

消费者按需引用：
  sync    → sdk-models + sdk-api          （最轻量）
  Tauri   → sdk-models + sdk-api + sdk-ws + sdk-store（完整，Rust 直接调用）
  web     → sdk-wasm                      （WASM 包，内含全部）
  mobile  → UniFFI 绑定 sdk-store         （Phase 3）
```

## 三、核心模块设计

### 3.1 sdk-models — 数据模型

纯数据结构，零外部依赖（只依赖 serde），所有其他 crate 和消费者都依赖它。

| 模块 | 包含的类型 | 说明 |
|------|-----------|------|
| project.rs | Project, ProjectStatus, TeamMember | 项目和团队 |
| workitem.rs | WorkItem, WorkItemType, Priority, WorkItemTransition, WorkItemComment | 工单和状态变更 |
| artifact.rs | Artifact, ArtifactVersion | 产物和版本 |
| role.rs | RoleDefinition, SharedRule, ProcessTemplate | Agent 配置 |
| llm.rs | ModelInfo, ProjectLlmConfig | LLM 模型配置 |
| message.rs | FlowMessage, FlowMessageType, NodeResult, NodeResultType | flow↔runtime 通信协议 |
| payload.rs | NodeExecutePayload, ChatMessagePayload, AgentCreatePayload, ReplyTo | 消息负载类型 |
| bpmn.rs | FlowNode（tagged enum）, FlowEdge | BPMN 节点（前端渲染用） |
| views.rs | AiView, CardView, ProgressView, PipelineProgress, StageProgress, TaskSummary | 多视图模型 |

> 完整的 struct 定义见详细设计 §二。

### 3.2 sdk-api — platform API 客户端

封装所有 platform HTTP API 调用，提供类型安全的 Rust 接口。

| API 模块 | 核心方法 | 对应 platform 端点 |
|---------|---------|-------------------|
| ProjectApi | create / get / list / get_progress / list_members | /api/projects/* |
| WorkItemApi | create / get / list / transition / assign / get_ai_view / get_card_view | /api/workitems/* |
| ArtifactApi | create / get / list / get_content / list_versions | /api/artifacts/* |
| AgentConfigApi | get_role / list_rules / get_process / get_process_graph / fork_process | /api/agent-config/* |
| SnapshotApi | save_agent / get_agent / save_workflow / get_latest_workflow | /api/snapshots/* |
| LlmApi | list_models / get_model / get_project_config / update_project_config | /api/system/models/* |

> 完整的方法签名和实现见详细设计 §三。

### 3.3 sdk-ws — WebSocket 连接管理（Phase 2）

| 组件 | 职责 |
|------|------|
| WsConnection | 连接管理（连接/断开/自动重连/心跳） |
| Subscription | 订阅管理（按 topic 订阅/取消订阅） |

核心方法签名：

| 方法 | 说明 |
|------|------|
| connect() | 建立 WebSocket 连接（携带 JWT token） |
| disconnect() | 断开连接 |
| on_message(callback) | 注册消息回调（收到 PlatformEvent 时触发） |
| subscribe_project(pid) | 订阅项目级事件（工单变更、阶段推进等） |
| unsubscribe(topic) | 取消订阅 |

> Phase 2 实现。完整定义见详细设计 §3.5（待补充）。

### 3.4 sdk-store — 状态管理（Phase 2）

| 组件 | 职责 |
|------|------|
| ChatStore | 聊天状态（消息列表、群聊、门禁） |
| ProjectStore | 项目状态（阶段进度、团队） |
| WorkItemStore | 工单状态（看板、列表） |

核心方法签名：

| 方法 | 说明 |
|------|------|
| load_project(pid) | 加载项目的聊天室列表和进度 |
| send_message(room_id, content) | 发送聊天消息 |
| respond_gate(gate_id, action, comment) | 处理门禁审批 |
| get_kanban(pid) | 获取工单看板数据 |
| get_progress(pid) | 获取项目进度（流程图数据） |

> Phase 2 实现。完整定义见详细设计 §3.6（待补充）。

### 3.5 sdk-wasm — WASM 绑定

Phase 1 采用全局 PlatformClient + 独立函数的方式（无状态），Phase 2 引入 sdk-store 后升级为有状态的 QuantalithosClient。

> Phase 1 的 WASM 绑定实现见详细设计 §四。

**Vue 3 中使用（TS 薄封装）：**

```typescript
// quantalithos-chat/src/sdk.ts — TS 薄封装
import init, { QuantalithosClient } from '@quantalithos/sdk-wasm'

let client: QuantalithosClient

export async function initSDK(platformUrl: string, token: string) {
  await init()  // 初始化 WASM
  client = new QuantalithosClient(platformUrl, token)
  await client.connect()
}

export async function loadProject(projectId: string) {
  return JSON.parse(await client.load_project(projectId))
}

export async function getWorkitemCard(id: string): Promise<CardView> {
  return JSON.parse(await client.get_workitem_card(id))
}

export async function respondGate(gateId: string, action: string) {
  await client.respond_gate(gateId, action)
}
```

```vue
<!-- quantalithos-chat/src/components/WorkitemCard.vue -->
<template>
  <div class="card">
    <h3>{{ card.title }}</h3>
    <span :style="{ color: card.status.color }">{{ card.status.label }}</span>
    <div v-for="badge in card.badges" :key="badge.label">{{ badge.label }}</div>
  </div>
</template>

<script setup>
import { ref, onMounted } from 'vue'
import { getWorkitemCard } from '../sdk'

const props = defineProps(['workitemId'])
const card = ref(null)

onMounted(async () => {
  card.value = await getWorkitemCard(props.workitemId)
})
</script>
```

| crate | 依赖 | 说明 |

## 五、Phase 分期

### Phase 1

| crate | 实现范围 |
|-------|---------|
| sdk-models | 全部数据模型 |
| sdk-api | 全部 platform API 客户端 |
| sdk-wasm | 基础绑定（API 调用） |

Phase 1 不实现 sdk-ws 和 sdk-store，chat 前端直接调用 sdk-wasm 的 API 方法。

### Phase 2

| crate | 实现范围 |
|-------|---------|
| sdk-ws | WebSocket 连接、订阅、重连 |
| sdk-store | 状态管理、门禁交互、通知逻辑 |
| sdk-wasm | 完整绑定（含 WebSocket 和状态管理） |
| sync 迁移 | sync 的 client/ 模块迁移到使用 sdk-api |

### Phase 3

| crate | 实现范围 |
|-------|---------|
| bindings/uniffi | UniFFI 绑定（Swift/Kotlin） |
| bindings/typescript | 自动生成 TS 类型定义 |
| Tauri 集成 | desktop 端直接调用 sdk-store |
| Flutter 集成 | flutter_rust_bridge 绑定 |

## 六、与其他子项目的关系

```
quantalithos-sdk
    │
    ├──> quantalithos-chat (web)     通过 sdk-wasm 调用
    ├──> quantalithos-chat (Tauri)   Rust 直接调用 sdk-store
    ├──> quantalithos-sync           Rust 直接调用 sdk-api + sdk-models
    └──> quantalithos-mobile         通过 UniFFI 调用（Phase 3）

quantalithos-platform
    │
    └──> 被 sdk-api 调用（HTTP API）
    └──> 被 sdk-ws 连接（WebSocket）
```

## 七、待细化

- sdk-wasm 的包体积优化（tree-shaking、wasm-opt）
- sdk-api 的请求缓存策略（哪些 API 可以缓存、TTL 多长）
- sdk-ws 的重连策略（指数退避、最大重试次数）
- sdk-store 的离线支持（网络断开时缓存操作，恢复后同步）
- TS 类型定义的自动生成方案（tsify / wasm-bindgen 自动导出）
- 错误处理统一（Rust Error → WASM JsValue → TS Error 的转换链）

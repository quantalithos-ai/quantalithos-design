### 1.2 编码约束

- 语言：Rust，代码全英文
- 框架：axum 0.7 + tokio 1.0 + serde 1.0 + reqwest 0.12
- 外部依赖：Appium 2.0 server（独立进程）、ADB（Android SDK Platform Tools）
- 不直接依赖 runtime/flow（通过 HTTP API 解耦）
- 所有平台驱动通过 DeviceDriver trait 抽象（便于 mock 测试）
- 不使用 unwrap()/expect()（除初始化阶段的不可恢复错误）
- Commit scope：device | job | driver | result | api | config | common

### 1.3 环境准备

| 依赖 | 版本 | 用途 | 安装验证 |
|------|------|------|---------|
| Rust toolchain | stable (≥1.78) | 编译 testbed | `rustc --version` |
| Appium | 2.x | UI 自动化引擎 | `appium --version` |

| Android Emulator | ≥34 | 本地模拟器 | `emulator -list-avds` |
| Node.js | ≥18 | Appium 运行时 | `node --version` |

## 二、技术风险评估

**需要 Spike：Appium HTTP API + Rust 集成**

| 风险 | 验证方式 | 通过标准 |
|------|---------|---------|
| Rust reqwest 调用 Appium W3C WebDriver API 是否顺畅 | 写最简 Rust 程序创建 Appium session + 点击元素 | session 创建成功 + 元素点击成功 |
| Appium session 创建耗时是否可接受 | 测量 10 次 session 创建时间 | P95 < 5s（模拟器）/ P95 < 8s（真机） |
| ADB 命令通过 tokio::process::Command 异步执行是否稳定 | 异步执行 adb install + adb logcat | 安装成功 + 日志获取完整 |
| YAML 测试脚本的 serde 反序列化（tagged enum） | 解析 5 种不同 action 的 YAML 脚本 | 所有 action 正确解析为对应 TestStep variant |

Spike 代码位置：`spike/appium_rust_test/`（不合并主干）

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 0 | Appium W3C API 与 Rust reqwest 集成有不可解决的兼容问题 | 概要设计，评估换用 Appium client library（Python/JS sidecar） |
| 阶段 0 | ADB 异步执行在 tokio runtime 中不稳定（死锁/hang） | 详细设计，评估用 blocking task（spawn_blocking）隔离 ADB 调用 |
| 阶段 2 | Appium session 创建耗时 > 15s，严重影响测试效率 | 详细设计，引入 session 池（预创建 + 复用） |

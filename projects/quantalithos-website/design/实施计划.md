## 一、前置条件

> **必须先阅读** `docs/design/实施计划书写规范.md` §二-A 前置条件，完成 Git 仓库初始化和通用前置检查。

### 1.1 必读文档

| 文档 | 阅读目的 |
|------|---------|
| projects/quantalithos-website/design/概要设计.md | 理解页面结构、技术栈、层间约束、上线策略 |
| projects/quantalithos-website/design/详细设计.md | 理解目录结构、VitePress 配置、首页设计、测试设计 |
| VitePress 官方文档 (https://vitepress.dev) | 理解框架能力和配置项 |

### 1.2 编码约束

- 语言：TypeScript（配置文件）+ Markdown（内容）+ Vue 3 SFC（自定义组件），代码全英文
- 框架：VitePress（Vue 3 + Vite）
- 内容与主题分离：Markdown 不包含样式代码，Vue 组件不硬编码文案
- 图片格式：截图用 WebP，图标/Logo 用 SVG
- Commit scope：config | content | theme | components | ci | assets

### 1.3 提交规范

遵循 `docs/design/实施计划书写规范.md` §前置条件 3 的 commit 格式。

### 1.4 工具链准备

```bash
node --version    # >= 18
npm --version     # >= 9
```

## 二、技术风险评估

| 风险 | 影响 | 是否需要 Spike | 缓解方式 |
|------|------|---------------|---------|
| VitePress 自定义主题与默认主题冲突 | 中 | 否 | 继承默认主题（extends defaultTheme），只覆盖需要的部分 |
| 自定义 Vue 组件在 SSG 构建时报错 | 中 | 否 | 组件中避免直接访问 window/document；需要时用 `<ClientOnly>` 包裹 |
| Markdown 中嵌入 Vue 组件的 HMR 不稳定 | 低 | 否 | VitePress 已原生支持；复杂组件抽到 .vue 文件而非内联 |
| 图片体积过大导致构建产物膨胀 | 中 | 否 | CI 中加图片体积检查；WebP 格式；单张 < 200 KB |
| Algolia DocSearch 申请周期不确定 | 低 | 否 | Phase 1 使用 VitePress 内置本地搜索，Phase 2 再迁移 |

## 五、回退规则

| 阶段 | 回退触发条件 | 回退目标 |
|------|------------|---------|
| 阶段 1 | VitePress 版本与 Node.js 不兼容 | 概要设计，确认 Node.js 版本要求；降级 VitePress 版本 |
| 阶段 2 | 内容与实际产品设计严重不一致 | 概要设计，重新对齐页面结构和内容范围 |
| 阶段 3 | 自定义组件导致 SSG 构建失败 | 详细设计，简化组件（移除 SSR 不兼容的代码，用 ClientOnly 包裹） |
| 阶段 4 | Lighthouse 评分持续低于 90 | 详细设计 §八 性能设计，逐项排查优化措施 |
| 阶段 5 | Vercel 部署失败或域名配置异常 | 概要设计 §十一 上线策略，评估切换到 Cloudflare Pages |

# quantalithos-website 概要设计

> 官网 — 产品介绍、文档中心、市场入口、社区链接

---

## 一、项目定位

### 1.1 核心职责

quantalithos-website 是项目的公开门面，面向潜在用户和开发者。

**做的事：**
- 产品介绍和演示
- 文档中心（快速开始、API 文档、架构说明）
- 市场入口（跳转到 console）
- 社区入口（GitHub、Discord）
- 更新日志和路线图

**不做的事：**
- 不做用户认证（跳转到 console 登录）
- 不做业务功能（全部在 console/chat/runner 中）
- 不做付费/定价

### 1.2 在整体架构中的位置

```
公开访问（无需登录）              登录后
─────────────────              ──────
quantalithos-website            quantalithos-chat（协作）
├── 首页                        quantalithos-console（管理）
├── 产品介绍                    quantalithos-runner（体验）
├── 文档中心
├── 市场预览 → 跳转 console
├── GitHub → 跳转 github.com
└── 静态站点，CDN 部署
```

## 七、约束条件

### 7.1 技术约束

| 约束 | 说明 | 来源 |
|------|------|------|
| 纯静态站点 | 不运行服务端代码，所有页面构建时生成 HTML | VitePress 框架特性 |
| Node.js >= 18 | VitePress 构建要求 | VitePress 文档 |
| Markdown 驱动 | 内容全部用 Markdown 编写，Vue 组件仅用于交互增强 | 团队约定 |
| 无用户认证 | 官网不做登录，需要登录的功能跳转到 console | 项目定位 |
| 无数据库 | 静态站点无后端存储，市场预览数据构建时拉取或客户端 fetch | 架构决策 |
| 中文为主 | 首期仅支持中文，Phase 2 评估 i18n | 团队决策 |

### 7.2 容量规划

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 页面数量 | Phase 1: ~15 页，Phase 2: ~30 页 | Markdown 文件数 |
| 构建产物体积 | < 5 MB（不含图片） | HTML + JS + CSS |
| 单页 HTML | < 100 KB（gzip 后） | 首屏加载性能 |
| 图片总量 | < 20 MB | 截图 + Logo + OG Image |
| 构建时间 | < 30 秒 | VitePress 增量构建 |

## 八、层间约束

VitePress 项目的三层分离原则：

```
┌─────────────────────────────────────────────────────┐
│  内容层（docs/*.md）                                  │
│  · 纯 Markdown 文本 + frontmatter 元数据             │
│  · 不包含样式代码，不直接操作 DOM                     │
│  · 可由非开发人员（技术写作）独立编辑                 │
├─────────────────────────────────────────────────────┤
│  主题层（.vitepress/theme/）                          │
│  · Vue 组件 + CSS 样式                               │
│  · 只读取 frontmatter 和 VitePress API               │
│  · 不硬编码业务内容（文案从 Markdown 传入）           │
├─────────────────────────────────────────────────────┤
│  配置层（.vitepress/config.ts）                       │
│  · 导航结构、侧边栏、搜索、站点元数据                │
│  · 不包含组件逻辑和样式                              │
│  · 修改导航不需要改组件代码                          │
└─────────────────────────────────────────────────────┘
```

**约束规则：**

| 规则 | 说明 |
|------|------|
| 内容层不依赖主题层 | Markdown 文件在任何 VitePress 主题下都能渲染 |
| 主题层不硬编码内容 | 组件通过 props / slots / frontmatter 接收数据 |
| 配置层不包含逻辑 | config.ts 只做声明式配置，不写业务函数 |
| 图片资源放 public/ | 不在 Markdown 中使用相对路径引用 theme 内资源 |

## 九、横切关注点

### 9.1 SEO

| 措施 | 实现方式 |
|------|---------|
| 语义化 HTML | VitePress 默认生成语义化标签（h1-h6, nav, main, footer） |
| Open Graph 标签 | config.ts 配置 head 注入 og:title, og:description, og:image |
| sitemap.xml | VitePress 内置 sitemap 生成（config.ts 设置 sitemap.hostname） |
| robots.txt | public/robots.txt 允许所有爬虫 |
| 结构化数据 | 首页注入 JSON-LD（Organization + SoftwareApplication） |
| 页面标题 | 每个 Markdown 的 frontmatter title 自动映射为 <title> |

### 9.2 性能

| 措施 | 实现方式 |
|------|---------|
| 静态预渲染 | VitePress 构建时生成纯 HTML，首屏无需 JS 即可阅读 |
| 资源哈希 | Vite 构建自动给 JS/CSS 加 content hash，长期缓存 |
| 图片优化 | 截图用 WebP 格式，Logo 用 SVG |
| 字体 | 使用系统字体栈，不加载自定义字体 |
| 懒加载 | 非首屏图片加 loading="lazy" |
| 预加载 | VitePress 自动对链接做 prefetch |

### 9.3 可用性

| 措施 | 实现方式 |
|------|---------|
| CDN 部署 | Vercel / Cloudflare Pages 全球边缘节点 |
| 无服务端依赖 | 纯静态文件，CDN 挂了才不可用 |
| 降级方案 | JS 加载失败仍可阅读 HTML 内容（SSG 优势） |
| 监控 | Vercel Analytics 或 Cloudflare Web Analytics（免费） |

### 9.4 成本

| 项目 | 预估成本 | 说明 |
|------|---------|------|
| 托管 | $0 | Vercel 免费计划（100 GB 带宽/月） |
| 域名 | ~$12/年 | .com 域名 |
| CDN | $0 | Vercel / Cloudflare 自带 |
| 搜索 | $0 | Phase 1 本地搜索；Phase 2 Algolia DocSearch 对开源免费 |
| 分析 | $0 | Plausible Cloud $9/月 或自托管 Umami $0 |

## 十、风险与缓解策略

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|---------|
| VitePress 大版本升级破坏兼容 | 低 | 中 | 锁定 VitePress 版本（package.json exact version）；升级前在分支验证 |
| 文档内容与产品实际不一致 | 高 | 高 | 文档纳入 CI 检查（链接有效性）；产品发版时同步更新文档 |
| 市场预览 API 不可用 | 中 | 低 | Phase 2 功能；客户端 fetch 失败时显示占位内容 |
| 图片体积过大拖慢加载 | 中 | 中 | CI 中检查图片体积；WebP 格式；设置最大尺寸限制 |
| Algolia DocSearch 申请未通过 | 低 | 低 | 继续使用 VitePress 内置本地搜索 |
| SEO 排名不理想 | 中 | 中 | 持续优化 meta 标签；产出高质量技术博客引流 |

## 十一、上线策略

### 11.1 部署流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  开发者   │    │  GitHub   │    │  Vercel   │    │   CDN    │
│  推送代码 │───▶│  main 分支│───▶│  自动构建 │───▶│  全球分发│
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                     │
                     ▼
                ┌──────────┐
                │ PR 预览   │
                │ 每个 PR   │
                │ 独立 URL  │
                └──────────┘
```

### 11.2 环境策略

| 环境 | 触发条件 | URL | 用途 |
|------|---------|-----|------|
| Preview | PR 创建/更新 | `pr-{id}.quantalithos.vercel.app` | PR 审查 |
| Production | 合并到 main | `quantalithos.ai` | 正式站点 |

### 11.3 发布检查清单

| 检查项 | 方式 |
|--------|------|
| 构建成功 | Vercel 自动构建，失败则阻止部署 |
| 链接有效 | CI 运行 link checker（检查死链） |
| Lighthouse 评分 | Performance > 90, Accessibility > 90, SEO > 90 |
| OG Image 正确 | 社交分享预览检查 |
| 移动端适配 | 响应式布局在 375px 宽度下正常 |

### 11.4 回滚方案

Vercel 支持一键回滚到任意历史部署版本，无需代码操作。

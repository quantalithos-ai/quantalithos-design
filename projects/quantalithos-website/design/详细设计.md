## 六、数据来源声明

quantalithos-website 是纯静态站点，不拥有数据库，所有数据来源如下：

| 数据 | 来源 | 获取时机 | 更新方式 |
|------|------|---------|---------|
| 产品介绍文案 | docs/product/*.md | 构建时 | 开发者编辑 Markdown → 重新构建 |
| 使用指南 | docs/guide/*.md | 构建时 | 同上 |
| 架构文档 | docs/architecture/*.md | 构建时 | 同上 |
| API 文档 | docs/api/*.md | 构建时 | Phase 2 从 OpenAPI spec 自动生成 |
| 更新日志 | docs/community/changelog.md | 构建时 | 发版时手动更新或从 GitHub Releases 拉取 |
| 路线图 | docs/community/roadmap.md | 构建时 | 手动维护 |
| 市场热门资产 | platform REST API | 客户端运行时 fetch | Phase 2；fetch 失败显示占位内容 |
| 访问统计 | Plausible / Umami | 客户端运行时 | 第三方服务，不影响站点渲染 |
| 搜索索引 | VitePress MiniSearch | 构建时生成 | 每次构建自动重建索引 |

**数据所有权：** 本项目不产生用户数据，不存储任何用户信息。访问统计由第三方服务处理，遵循其隐私政策。

## 七、并发与一致性

### 7.1 不适用声明

quantalithos-website 是静态站点生成器（SSG）项目，不涉及：

- 服务端并发请求处理
- 数据库读写竞争
- 分布式一致性
- 会话状态管理

**原因：** VitePress 在构建时将所有 Markdown 编译为静态 HTML 文件，部署到 CDN 后由边缘节点直接返回文件，不运行任何服务端代码。每个用户请求都是独立的静态文件读取，不存在并发冲突。

### 7.2 唯一的并发场景

| 场景 | 说明 | 处理方式 |
|------|------|---------|
| 多人同时编辑 Markdown | 开发阶段的 Git 协作 | Git 分支 + PR 合并解决冲突 |
| 构建竞争 | 多个 PR 同时触发构建 | Vercel 自动排队，每个 PR 独立预览环境 |
| 市场预览 API 并发 | Phase 2 客户端 fetch | 浏览器原生处理；加 loading 状态和错误兜底 |

## 八、性能设计

### 8.1 性能目标

| 指标 | 目标值 | 测量工具 |
|------|--------|---------|
| Lighthouse Performance | > 90 | Chrome DevTools / CI |
| Lighthouse Accessibility | > 90 | Chrome DevTools / CI |
| Lighthouse SEO | > 90 | Chrome DevTools / CI |
| First Contentful Paint (FCP) | < 1.5s | Lighthouse |
| Largest Contentful Paint (LCP) | < 2.5s | Lighthouse |
| Cumulative Layout Shift (CLS) | < 0.1 | Lighthouse |
| Total Blocking Time (TBT) | < 200ms | Lighthouse |

### 8.2 优化措施

**构建时优化：**

| 措施 | 说明 |
|------|------|
| SSG 预渲染 | VitePress 构建时生成完整 HTML，首屏无需等待 JS |
| 代码分割 | Vite 自动按路由分割 JS chunk |
| Tree Shaking | Vite 自动移除未使用的代码 |
| CSS 内联 | 关键 CSS 内联到 HTML head |
| 资源哈希 | JS/CSS 文件名含 content hash，支持长期缓存 |

**图片优化：**

| 措施 | 说明 |
|------|------|
| WebP 格式 | 截图统一使用 WebP（比 PNG 小 25-35%） |
| SVG 优先 | Logo、图标、架构图使用 SVG |
| 尺寸限制 | 单张截图 < 200 KB，OG Image < 100 KB |
| 懒加载 | 非首屏图片添加 `loading="lazy"` 属性 |
| 响应式图片 | 大截图提供 1x/2x 两种尺寸（Phase 2） |

**运行时优化：**

| 措施 | 说明 |
|------|------|
| 系统字体栈 | 不加载自定义字体，消除 FOIT/FOUT |
| 链接预取 | VitePress 自动对可视区域内链接做 prefetch |
| 无第三方 JS 阻塞 | 统计脚本异步加载（async/defer） |

### 8.3 CDN 缓存策略

| 资源类型 | Cache-Control | 说明 |
|---------|---------------|------|
| HTML | `public, max-age=0, must-revalidate` | 每次检查是否有新版本 |
| JS/CSS（带 hash） | `public, max-age=31536000, immutable` | 内容变化 hash 变化，可永久缓存 |
| 图片 | `public, max-age=86400` | 24 小时缓存 |
| favicon/logo | `public, max-age=604800` | 7 天缓存 |

## 九、测试设计

### 9.1 测试策略

静态站点的测试重点不在单元测试，而在构建验证和内容完整性。

| 测试类型 | 工具 | 检查内容 | 运行时机 |
|---------|------|---------|---------|
| 构建验证 | `vitepress build` | 构建是否成功，无编译错误 | 每次 CI |
| 链接检查 | lychee / linkinator | 内部链接和外部链接是否有效 | 每次 CI |
| HTML 校验 | html-validate | HTML 语法是否正确 | 每次 CI |
| 可访问性 | axe-core / pa11y | WCAG 2.1 AA 级别合规 | 每次 CI |
| Lighthouse CI | @lhci/cli | Performance/A11y/SEO 评分 | PR 合并前 |
| 视觉回归 | Percy / Playwright screenshot | 页面截图对比（Phase 2） | PR 合并前 |

### 9.2 CI 流水线

```yaml
# .github/workflows/ci.yml 伪代码
#
# 触发：push to main / PR
# 步骤：
#   1. npm ci
#   2. vitepress build          → 构建验证
#   3. lychee ./dist            → 链接检查
#   4. pa11y-ci                 → 可访问性检查
#   5. lhci autorun             → Lighthouse 评分
```

### 9.3 链接检查规则

| 规则 | 说明 |
|------|------|
| 内部链接 | 所有 `[text](/path)` 必须指向存在的页面 |
| 锚点链接 | `[text](#anchor)` 必须指向存在的标题 |
| 外部链接 | 允许超时但不允许 404 |
| 图片引用 | 所有 `![alt](/path)` 必须指向存在的文件 |
| 排除列表 | localhost 链接、示例域名（example.com）排除检查 |

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐

│ 编辑 .md │───▶│ push/PR  │───▶│ VitePress│───▶│  Vercel  │───▶│ 全球边缘 │

                     │               │
                     │               ▼
                     │          ┌──────────┐
```

### 10.2 各环节职责

| 环节 | 输入 | 处理 | 输出 |
|------|------|------|------|
| 内容编写 | 产品需求 / 技术文档 | 编写 Markdown + 截图 | docs/*.md + public/screenshots/ |
| Git 推送 | 修改后的文件 | 版本控制 + PR 审查 | Git commit |
| CI 构建 | Git commit | VitePress build + 测试 | dist/ 静态文件 |
| 部署平台 | dist/ 静态文件 | 上传到 CDN 源站 | 部署版本 |
| CDN 分发 | 部署版本 | 边缘缓存 + HTTPS | 用户可访问的页面 |

### 10.3 与其他子项目的关系

```
quantalithos-website（本项目）
│
├── 引用 ← quantalithos-platform 的 API 文档
│         （Phase 2: 从 OpenAPI spec 自动生成 docs/api/*.md）
│
├── 引用 ← 各子项目的架构设计文档
│         （手动同步关键内容到 docs/architecture/）
│
├── 跳转 → quantalithos-console
│         （市场入口、登录入口）
│
└── 跳转 → GitHub 仓库
          （源码、Issues、Discussions）
```

**数据流方向：** 单向引用。website 只读取其他子项目的公开文档，不被其他子项目依赖。这保证了 website 的独立构建和部署。

## 一、项目定位

### 1.1 核心职责

Agent Runtime 是整个 AI 研发协作平台的**核心引擎**，负责：

- **Agent 生命周期管理**：实例化、销毁、持久化
- **Agent 角色定义**：Prompt 管理、工具权限、行为约束
- **LLM 调用封装**：统一接口、流式输出、成本追踪
- **工具调用系统**：工具注册、执行、沙箱隔离
- **多 Agent 协作**：消息路由、群聊管理
- **状态机管理**：状态转换、事件驱动

### 1.2 在整体架构中的位置

### 3.4 tools - 工具系统

#### 3.4.0 工具与技能的区别

**工具（Tool）**：原子操作能力，单一职责
- 例如：`file_read`、`git_commit`、`terminal_execute`
- 运行时注册，全局可用
- 权限控制：角色定义中的 `tools` 列表

**技能（Skill）**：工具组合 + 执行流程 + 领域知识
- 例如：`代码审查`、`故障诊断`、`部署流程`
- 可由助手动态创建（参考 Hermes 自进化）
- 权限控制：角色定义中的 `skills` 列表

```
工具层级结构：

┌─────────────────────────────────────────────────────────┐
│                        技能层                            │
│  code_review_skill = [git_diff, file_read, lint_check]  │
│  deploy_skill = [build, test, deploy, notify]           │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│                        巀具层                            │
│  file_read | git_commit | terminal_execute | ...       │
└─────────────────────────────────────────────────────────┘
```

**技能示例：**

```yaml
# skills/code_review.yaml
skill_id: code_review
name: 代码审查技能
description: 自动化代码审查流程
steps:
  - tool: git_diff
    params: {target_branch: "main"}
  - tool: file_read
    params: {files: "${git_diff.output.changed_files}"}
  - tool: lint_check
    params: {files: "${git_diff.output.changed_files}"}
  - tool: generate_review_comment
    params: {context: "${previous_steps.output}"}
validation:
  - lint_check.output.passed == true
on_failure:
  - post_comment
  - notify_author
```

```python
class CreateRoleTool(Tool):
    """让助手可以动态创建新角色"""
    
    tool_name = "create_role"
    description = "创建一个新的角色定义"
    parameters = {
        "type": "object",
        "properties": {
            "role_name": {
                "type": "string",
                "description": "角色显示名称"
            },
            "identity": {
                "type": "string",
                "description": "角色身份描述（自然语言）"
            },
            "constraints": {
                "type": "array",
                "items": {"type": "string"},
                "description": "行为约束列表"
            },
            "tools": {
                "type": "array",
                "items": {"type": "string"},
                "description": "可用工具列表"
            },
            "read_paths": {
                "type": "array",
                "items": {"type": "string"},
                "description": "可读路径"
            },
            "write_paths": {
                "type": "array",
                "items": {"type": "string"},
                "description": "可写路径"
            },
            "forbidden_paths": {
                "type": "array",
                "items": {"type": "string"},
                "description": "禁止访问路径"
            },
            "extends": {
                "type": "string",
                "description": "继承自哪个角色（可选）"
            }
        },
        "required": ["role_name", "identity", "tools"]
    }
    
    async def execute(self, **kwargs) -> ToolResult:
        """执行角色创建"""
        
        # 1. 创建角色定义
        role_def = RoleDefinition(
            role_id=generate_role_id(kwargs["role_name"]),
            role_name=kwargs["role_name"],
            identity=kwargs["identity"],
            constraints=kwargs.get("constraints", []),
            tools=kwargs["tools"],
            permissions=PermissionConfig(
                read_paths=kwargs.get("read_paths", []),
                write_paths=kwargs.get("write_paths", []),
                forbidden_paths=kwargs.get("forbidden_paths", [])
            ),
            created_by="assistant",
            extends=kwargs.get("extends")
        )
        
        # 2. 验证角色定义
        validation_result = self.validate_role_definition(role_def)
        if not validation_result.is_valid:
            return ToolResult(
                success=False,
                error=f"角色定义验证失败: {validation_result.error}"
            )
        
        # 3. 存储到角色库
        role_store.save(role_def)
        
        # 4. 注册到运行时
        agent_runtime.register_role(role_def)
        
        return ToolResult(
            success=True,
            data={
                "role_id": role_def.role_id,
                "message": f"角色 {role_def.role_name} 创建成功"
            }
        )
    
    def validate_role_definition(self, role_def: RoleDefinition) -> ValidationResult:
        """验证角色定义的合法性"""
        
        # 检查 role_id 是否已存在
        if role_store.exists(role_def.role_id):
            return ValidationResult(
                is_valid=False,
                error=f"角色 {role_def.role_id} 已存在"
            )
        
        # 检查继承的角色是否存在
        if role_def.extends and not role_store.exists(role_def.extends):
            return ValidationResult(
                is_valid=False,
                error=f"继承的目标角色 {role_def.extends} 不存在"
            )
        
        # 检查工具是否都可用
        available_tools = tool_registry.list_tools()
        for tool_name in role_def.tools:
            if tool_name not in available_tools:
                return ValidationResult(
                    is_valid=False,
                    error=f"工具 {tool_name} 不存在"
                )
        
        return ValidationResult(is_valid=True)
```

### 3.5 roles - 角色定义

#### 3.5.1 设计理念

**核心原则：角色定义数据化，而非代码化。**

传统做法是将角色写死在代码中，每次新增角色都需要修改代码并重新部署。本系统采用数据化的角色定义：

- 角色定义是数据对象，存储在 `role_store` 中
- 助手可以通过工具动态创建新角色
- 运行时动态加载和注册角色
- 支持角色继承与组合

#### 3.5.2 角色定义结构

**设计原则：优先使用 YAML/JSON，而非 Markdown**

原因：
- ✅ 结构化：YAML/JSON 天然支持嵌套、数组、对象
- ✅ 可验证：可通过 JSON Schema 校验格式
- ✅ 可编程：易于序列化/反序列化，无需解析 Markdown
- ✅ 可继承：YAML 支持锚点和合并，便于角色继承

```python
class RoleDefinition(BaseModel):
    """角色定义 - 数据对象"""
    
    # 基本信息
    role_id: str                      # 唯一标识
    role_name: str                    # 显示名称
    description: str                  # 简短描述
    
    # 身份与约束
    identity: str                     # 身份描述（自然语言）
    constraints: List[str]            # 行为约束
    
    # 能力配置
    tools: List[str]                  # 可用工具列表
    skills: List[str]                 # 可用技能列表（技能是工具的组合）
    
    # 记忆配置
    memory_config: MemoryConfig       # 记忆策略配置
    
    # 权限配置
    permissions: PermissionConfig     # 路径权限
    
    # 自进化配置
    evolution_config: EvolutionConfig # 技能自迭代配置
    
    # 元信息
    created_by: str                   # "system" | "assistant" | "user"
    created_at: datetime
    version: str
    
    # 可选：继承
    extends: Optional[str] = None     # 继承自哪个角色
    overrides: Optional[dict] = None  # 覆盖配置


class MemoryConfig(BaseModel):
    """记忆策略配置"""
    enable_long_term: bool            # 是否启用长期记忆
    compression_threshold: int        # 压缩阈值（消息数）
    retention_days: int               # 记忆保留天数
    enable_user_profile: bool         # 是否学习用户偏好


class EvolutionConfig(BaseModel):
    """自进化配置（参考 Hermes）"""
    enable_auto_skill: bool           # 是否自动生成技能
    skill_improvement: bool           # 是否在使用中迭代技能
    frozen_snapshot: bool             # 是否启用冻结快照（降低 Token）


class PermissionConfig(BaseModel):
    """权限配置"""
    read_paths: List[str]             # 可读路径
    write_paths: List[str]            # 可写路径
    forbidden_paths: List[str]        # 禁止访问路径
    
    # 工具级权限细化（参考 OpenClaw）
    tool_restrictions: Dict[str, Any] # 工具限制条件
    # 例如：{"code_execute": {"max_timeout": 30, "sandbox": true}}
```

#### 3.5.2.5 YAML vs Markdown 对比

| 维度 | YAML | Markdown | 结论 |
|------|------|----------|------|
| **结构化** | ✅ 原生支持嵌套、数组 | ❌ 需手动解析 | **YAML 胜** |
| **可验证** | ✅ JSON Schema 校验 | ❌ 无标准校验 | **YAML 胜** |
| **可读性** | ⚠️ 略低（需熟悉语法） | ✅ 高（人类友好） | **Markdown 胜** |
| **可维护** | ✅ 工具支持完善 | ⚠️ 易出现格式混乱 | **YAML 胜** |
| **可继承** | ✅ 锚点/合并机制 | ❌ 不支持 | **YAML 胜** |
| **跨语言** | ✅ 通用序列化格式 | ⚠️ 需解析库 | **YAML 胜** |

**最终建议：**
- 角色定义：✅ YAML（`role_store/*.yaml`）
- 技能定义：✅ YAML（`skill_store/*.yaml`）
- 共享规则：✅ YAML（`prompts/shared/*.yaml`）
- Prompt 组装：在代码中将 YAML 数据转换为自然语言

#### 3.5.2.6 Prompt 组装逻辑（从 YAML 到自然语言）

```python
def build_system_prompt(role_id: str) -> str:
    """从 YAML 角色定义组装系统 Prompt"""
    
    # 1. 加载角色定义（YAML）
    role_def = role_store.load_yaml(role_id)
    
    # 2. 加载共享规则（YAML）
    shared_rules = load_shared_rules()
    
    # 3. 转换为自然语言
    prompt = f"""
{format_shared_rules(shared_rules)}

# 角色身份
{role_def['identity']}

# 行为约束
{format_constraints(role_def['constraints'])}

# 权限说明
可访问路径：{', '.join(role_def['permissions']['read_paths'])}
可修改路径：{', '.join(role_def['permissions']['write_paths'])}
禁止访问：{', '.join(role_def['permissions']['forbidden_paths'])}
"""
    return prompt


def format_shared_rules(rules: dict) -> str:
    """将共享规则转换为自然语言"""
    
    formatted = []
    for rule_id, rule in rules.items():
        formatted.append(f"## {rule['name']}\n{rule['description']}")
        
        if 'behavior' in rule:
            for key, value in rule['behavior'].items():
                formatted.append(f"- {key}: {value}")
    
    return '\n\n'.join(formatted)
```

#### 3.5.3 项目级角色团队

**核心问题：如何为每个项目独立创建不同的角色团队？**

##### 3.5.3.1 当前设计的不足

当前设计存在的问题：
- ❌ 角色定义存储在全局 `role_store/`，所有项目共享
- ❌ 项目无法自定义角色（如修改权限、添加技能）
- ❌ 同一角色在不同项目中可能有不同的权限需求
- ❌ 无法为特定项目创建专属角色

```python
async def create_project_team(project_id: str, team_config: dict):
    """为项目组建团队"""
    
    team_members = []
    
    for role_config in team_config['team']:
        role_id = role_config['role_id']
        count = role_config['count']
        source = role_config['source']
        
        # 1. 查找角色定义
        role_def = find_role_definition(
            role_id=role_id,
            project_id=project_id,
            source=source
        )
        
        if not role_def:
            # 2. 角色不存在，AI 辅助创建
            role_def = await create_role_with_ai(
                role_id=role_id,
                project_context=team_config,
                user_confirmation=True
            )
        
        # 3. 实例化多个 Agent
        for i in range(count):
            agent = await instantiate_agent(
                role_def=role_def,
                project_id=project_id,
                agent_id=f"{role_id}-{i+1}"
            )
            team_members.append(agent)
    
    return team_members


def find_role_definition(role_id: str, project_id: str, source: str):
    """按优先级查找角色定义"""
    
    search_paths = [
        f"project_roles/{project_id}/{role_id}.yaml",     # 项目级
        f"company_templates/{role_id}/definition.yaml",   # 公司级
        f"system_templates/{role_id}/definition.yaml",    # 系统级
    ]
    
    for path in search_paths:
        if os.path.exists(path):
            return load_yaml(path)
    
    return None
```

##### 3.5.3.7 运行时权限隔离

```python
class ProjectAwarePermissionChecker:
    """项目感知的权限检查器"""
    
    def check_permission(
        self,
        agent: Agent,
        action: str,
        target_path: str
    ) -> bool:
        """检查 Agent 在项目中的权限"""
        
        # 1. 获取项目 ID
        project_id = agent.project_id
        
        # 2. 加载项目级角色定义
        role_def = self.load_project_role(
            project_id=project_id,
            role_id=agent.role_id
        )
        
        # 3. 检查路径前缀
        project_base = f"projects/{project_id}/"
        if not target_path.startswith(project_base):
            # 不允许访问其他项目的文件
            return False
        
        # 4. 检查项目级权限
        relative_path = target_path[len(project_base):]
        permissions = role_def['permissions']
        
        # 检查禁止访问
        if self.match_paths(relative_path, permissions['forbidden_paths']):
            return False
        
        # 检查写权限
        if action == 'write':
            return self.match_paths(relative_path, permissions['write_paths'])
        
        # 检查读权限
        if action == 'read':
            return self.match_paths(relative_path, permissions['read_paths'])
        
        return False
```

- ✅ **分支隔离** - 不同分支可有不同的角色配置

- ❌ 需要在项目启动时加载项目仓库中的角色定义
- ❌ 角色定义分散在多个仓库，全局视角不直观

- **系统级/公司级角色** → 存储在 `agent-runtime` 内
- **项目级角色** → 存储在项目仓库的 `.agent/` 目录

```
1. 项目仓库：{project_root}/.agent/roles/{role_id}.yaml
   ↓ 不存在
   
2. 公司模板：agent-runtime/company_templates/{role_id}/
   ↓ 不存在
   
3. 系统模板：agent-runtime/system_templates/{role_id}/
   ↓ 不存在
   
4. AI 辅助创建 → 保存到项目仓库 .agent/roles/
```

**代码实现：**

```python
class RoleDefinitionResolver:
    """角色定义解析器"""
    
    def resolve_role_definition(
        self,
        role_id: str,
        project_root: str
    ) -> RoleDefinition:
        """按优先级查找角色定义"""
        
        # 1. 项目仓库中的角色定义（最高优先级）
        project_role_path = f"{project_root}/.agent/roles/{role_id}.yaml"
        if os.path.exists(project_role_path):
            return self.load_yaml(project_role_path)
        
        # 2. 公司级模板
        company_role_path = f"company_templates/{role_id}/definition.yaml"
        if os.path.exists(company_role_path):
            return self.load_yaml(company_role_path)
        
        # 3. 系统级模板
        system_role_path = f"system_templates/{role_id}/definition.yaml"
        if os.path.exists(system_role_path):
            return self.load_yaml(system_role_path)
        
        # 4. 角色不存在，返回 None
        return None
    
    async def create_role_if_missing(
        self,
        role_id: str,
        project_root: str,
        project_context: dict
    ) -> RoleDefinition:
        """如果角色缺失，AI 辅助创建并保存到项目仓库"""
        
        role_def = self.resolve_role_definition(role_id, project_root)
        if role_def:
            return role_def
        
        # AI 辅助创建
        role_def = await self.ai_create_role(
            role_id=role_id,
            context=project_context
        )
        
        # 保存到项目仓库
        save_path = f"{project_root}/.agent/roles/{role_id}.yaml"
        self.save_yaml(role_def, save_path)
        
        return role_def
```

**项目启动流程：**

```python
async def bootstrap_project(project_root: str):
    """项目启动流程"""
    
    # 1. 加载团队配置
    team_config = load_yaml(f"{project_root}/.agent/team.yaml")
    
    # 2. 解析所有角色定义
    resolver = RoleDefinitionResolver()
    
    for role_config in team_config['team']:
        role_id = role_config['role_id']

            role_id=role_id,
            project_root=project_root

        # 如果缺失，AI 创建并保存到项目仓库
        if not role_def:
            role_def = await resolver.create_role_if_missing(
                role_id=role_id,
                project_root=project_root,
                project_context=team_config
            )
        
        # 实例化 Agent
        await instantiate_agent(role_def, project_root)
```

```python
def build_system_prompt(role_id: str) -> str:
    """从 YAML 角色定义组装系统 Prompt"""
    
    # 第一层：加载共享规则（YAML）
    shared_rules = load_shared_rules_from_yaml()
    # communication.yaml + tdd.yaml + debugging.yaml + ...
    
    # 第二层：加载角色定义（YAML）
    role_def = role_store.load_yaml(role_id)
    # 从 role_store/role_id.yaml 读取角色定义数据
    
    # 第三层：转换为 Prompt 文本
    role_prompt = format_role_prompt(role_def)
    # 将 role_def['identity'], role_def['constraints'],
    # role_def['permissions'] 转换为自然语言描述
    
    # 组装
    system_prompt = f"""
{format_shared_rules(shared_rules)}

{role_prompt}
"""
    return system_prompt


def format_role_prompt(role_def: dict) -> str:
    """将 YAML 角色定义转换为 Prompt 文本"""
    
    constraints_text = '\n'.join(f'- {c}' for c in role_def['constraints'])
    
    prompt = f"""
# 角色身份
{role_def['identity']}

# 行为约束
{constraints_text}

# 权限说明
可访问路径：{', '.join(role_def['permissions']['read_paths'])}
可修改路径：{', '.join(role_def['permissions']['write_paths'])}
禁止访问：{', '.join(role_def['permissions']['forbidden_paths'])}
"""
    return prompt


def load_shared_rules_from_yaml() -> dict:
    """从 YAML 文件加载共享规则"""
    
    import yaml
    from pathlib import Path
    
    rules = {}
    shared_dir = Path('prompts/shared/')
    
    for yaml_file in shared_dir.glob('*.yaml'):
        with open(yaml_file, 'r', encoding='utf-8') as f:
            rule = yaml.safe_load(f)
            rules[rule['rule_id']] = rule
    
    return rules
```

```python
class AgentExecutor:
    """Agent 执行器"""
    
    async def run(self, agent: Agent, message: Message):
        """运行 Agent 处理消息"""
        
        while True:
            # 1. 更新状态
            agent.state = AgentState.THINKING
            
            # 2. 思考
            tool_call = await agent.think()
            
            if tool_call:
                # 3. 执行工具
                agent.state = AgentState.ACTING
                result = await agent.act(tool_call)
                
                # 将结果加入记忆，继续思考
                agent.memory.add_tool_result(result)
                continue
            
            # 4. 生成响应
            response = await agent.generate_response()
            
            # 5. 发送消息
            await self.send_message(response)
            
            # 6. 更新状态
            agent.state = AgentState.WAITING
            break
```

```
   - 哪些工具被组合使用
   - 参数传递模式
   - 验证逻辑
   │
   ▼
3. 生成技能定义
   skill_manager.create_skill_from_trace(
       task_trace=execution_trace,
       skill_name="数据迁移流程",
       min_reuse_potential=0.7
   )
   │
   ▼
4. 存储到技能库
   skill_store.save(skill_def)
   │
   ▼
5. 后续自动复用
   当识别到相似任务时，自动推荐使用该技能
```

```python
class SkillEvolutionEngine:

        # 2. 识别改进点
```

#### 7.4.2 冻结快照模式（参考 Hermes）

```python
class FrozenSnapshot:
    """冻结快照 - 降低 Token 消耗"""
    
    def create_snapshot(self, messages: List[Message]):
        """创建不可变的对话快照"""
        # 1. 计算快照 Hash
        snapshot_hash = self.compute_hash(messages)
        
        # 2. 存储快照
        self.snapshot_store.save(
            hash=snapshot_hash,
            content=messages,
            created_at=datetime.now()
        )
        
        # 3. 后续请求复用快照
        # 只发送快照 Hash + 新消息
        # LLM 服务端可根据 Hash 恢复上下文
        return snapshot_hash
```

**优势：**
- 显著降低 API Token 消耗
- 支持 Prompt Cache（Anthropic 原生优化）
- 避免重复发送相同上下文

### 7.5 权限控制设计要点

#### 7.5.1 多层权限控制

```
权限检查流程：

Agent 请求操作
       │
       ├─ 第1层：角色级工具权限
       │    工具是否在 role_def.tools 中？
       │
       ├─ 第2层：角色级技能权限
       │    技能是否在 role_def.skills 中？
       │
       ├─ 第3层：路径权限
       │    路径是否在 permissions.read/write_paths 中？
       │
       ├─ 第4层：工具级限制
       │    是否满足 permissions.tool_restrictions？
       │    例如：code_execute 的 max_timeout
       │
       └─ 第5层：运行时安全检查
            沙箱隔离、敏感操作审计
```

#### 7.5.2 工具级限制示例

```python
# Tech Lead 角色定义
role_def = RoleDefinition(
    role_id="tech_lead",
    tools=["code_execute", "git_commit", ...],
    permissions=PermissionConfig(
        read_paths=["src/", "docs/", "tests/"],
        write_paths=["docs/", "tasks/"],
        forbidden_paths=["deploy/", "secrets/"],
        tool_restrictions={
            "code_execute": {
                "max_timeout": 30,           # 最多执行 30 秒
                "sandbox": True,              # 必须在沙箱中执行
                "forbidden_commands": ["rm -rf"]
            },
            "git_commit": {
                "require_review": True,       # 需要代码审查
                "protected_branches": ["main", "master"]
            }
        }
    )
)
```

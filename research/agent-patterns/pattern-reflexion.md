# Reflexion

> 论文：Shinn et al., 2023 — "Reflexion: Language Agents with Verbal Reinforcement Learning"

---

## 核心思想

Agent 执行任务后，反思自己的表现，总结经验教训，在下一次尝试中改进。

```
尝试 1：
  执行任务 → 结果不好
  反思："我直接写了代码没写测试，导致后面发现 bug 很晚"

尝试 2：
  执行任务（带着反思经验）→ 结果好一些
  反思："这次先写了测试，但忘了边界情况"

尝试 3：
  执行任务（带着两次反思）→ 结果很好
  反思："这次覆盖了边界情况，全部通过"
```

## 工作方式

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  执行    │────>│  评估    │────>│  反思    │
│  (Act)   │     │(Evaluate)│     │(Reflect) │
└──────────┘     └──────────┘     └────┬─────┘
     ↑                                 │
     │         反思经验存入记忆          │
     │    ┌──────────────────────┐     │
     └────│  记忆（经验列表）     │<────┘
          └──────────────────────┘

下一次执行时，记忆中的反思经验注入 prompt：
  "上次你犯了以下错误：...
   这次请注意避免。"
```

特点：
- 多次尝试，逐步改进
- 反思是自然语言（不是数值奖励）
- 经验可以跨任务复用

## 对我们的价值

```
核心价值：高 — 映射到我们的多个场景

1. 代码审查 → 修改 → 重新审查
   Agent 提交代码 → TL 审查不通过 → Agent 反思审查意见 → 修改 → 重新提交
   审查意见 = 反思经验
   这就是 Reflexion 模式

2. 测试失败 → 修复 → 重新测试
   Agent 跑测试 → 失败 → 分析失败原因 → 修复 → 重新测试
   失败原因 = 反思经验

3. 长期记忆（Phase 3）
   Agent 在项目 A 中学到"多对多关系用关联表"
   在项目 B 中遇到类似场景 → 从记忆中检索经验 → 直接用正确方案
   跨项目经验 = Reflexion 的记忆

4. 技能自进化（Phase 3）
   Agent 多次执行 TDD 后，总结出更高效的 TDD 步骤
   → 更新技能模板
   → 下次执行时用改进后的步骤
```

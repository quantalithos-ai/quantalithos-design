# Self-Refine

> 论文：Madaan et al., 2023 — "Self-Refine: Iterative Refinement with Self-Feedback"

---

## 核心思想

LLM 生成初始输出后，自己评估质量，自己提出改进建议，自己修改，循环直到满意。

```
生成初始版本
    │
    ▼
自我评估："这个 PRD 缺少非功能需求部分"
    │
    ▼
自我修改：补充非功能需求
    │
    ▼
再次评估："现在内容完整了，但优先级不够清晰"
    │
    ▼
再次修改：加上优先级标注
    │
    ▼
再次评估："满意，可以提交"
    │
    ▼
最终输出
```

## 工作方式

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  生成    │────>│  评估    │────>│  修改    │
│(Generate)│     │(Critique)│     │ (Refine) │
└──────────┘     └──────────┘     └────┬─────┘
                      ↑                │
                      │   不满意        │
                      └────────────────┘
                      │
                      │ 满意
                      ▼
                 最终输出
```

特点：
- 同一个 LLM 做生成、评估、修改（不需要外部反馈）
- 迭代改进（不是一次性生成）
- 适合文本生成类任务（PRD、设计文档、代码）

## 与 Reflexion 的区别

```
Reflexion：
  执行 → 外部评估（测试结果、审查意见）→ 反思 → 重新执行
  反馈来自外部（真实环境）

Self-Refine：
  生成 → 自我评估 → 自我修改 → 再评估
  反馈来自自己（LLM 自己评判）

Reflexion 更可靠（外部反馈是真实的）
Self-Refine 更快（不需要外部环境）
```

## 对我们的价值

```
价值：中

适合 TL 撰写 PRD 的场景：
  TL 生成 PRD 初稿 → 自我评估 → 修改 → 再评估 → 提交评审

但我们已经有更好的机制：
  TL 生成 PRD → 全员评审（session）→ 根据评审意见修改
  外部评审 > 自我评估

Self-Refine 可以作为"提交评审前的自检"：
  TL 写完 PRD → Self-Refine 自检一轮 → 再提交评审
  减少评审中发现的低级问题
```

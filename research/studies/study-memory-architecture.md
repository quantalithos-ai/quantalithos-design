# Agent 记忆架构

> 论文：Hierarchical Memory (arxiv 2507.22925), Context Management (arxiv 2512.22087), Autonomous Memory (arxiv 2601.07190)
> 对我们的价值：Phase 2 记忆系统的架构参考

---

## 一、学术共识：三层记忆

```
┌─────────────────────────────────────────────────────────────┐
│  工作记忆（Working Memory）                                  │
│  当前任务的即时上下文                                         │
│  容量：小（当前 LLM 上下文窗口）                              │
│  生命周期：当前任务                                           │
│  内容：NodeAssignment.action + 当前对话 + 工具调用结果        │
│  策略：全部保留，不压缩                                       │
├─────────────────────────────────────────────────────────────┤
│  短期记忆（Short-term Memory）                               │
│  近期交互的压缩摘要                                           │
│  容量：中（几千 token）                                       │
│  生命周期：当前项目                                           │
│  内容：之前任务的摘要、审查意见、决策记录                      │
│  策略：主动压缩（保留关键信息，丢弃细节）                      │
├─────────────────────────────────────────────────────────────┤
│  长期记忆（Long-term Memory）                                │
│  跨项目的经验和知识                                           │
│  容量：大（向量库）                                           │
│  生命周期：永久                                               │
│  内容：成功经验、失败教训、技术决策、代码模式                  │
│  策略：语义检索（用当前任务描述检索相关经验）                  │
└─────────────────────────────────────────────────────────────┘
```

## 二、上下文膨胀问题（Context Bloat）

```
问题（arxiv 2601.07190）：

Agent 在阶段 3 执行 5 个任务，每个任务 10 轮 think→act：
  TASK-001: 10 轮 × ~2000 tokens = 20000 tokens
  TASK-002: 10 轮 × ~2000 tokens = 20000 tokens
  TASK-003: 10 轮 × ~2000 tokens = 20000 tokens
  ...

如果不压缩，到 TASK-005 时对话历史已经 100000+ tokens
→ 超出上下文窗口
→ 即使没超出，LLM 对长上下文的推理质量也会下降
→ token 成本爆炸
```

## 三、Cat 框架的三层分区（arxiv 2512.22087）

```
┌─────────────────────────────────────────────────────────────┐
│  稳定任务语义（Stable Task Semantics）                        │
│  不变的背景信息，始终保留                                     │
│  内容：角色定义、共享规则、当前任务描述                        │
│  → 对应我们的 system prompt                                  │
├─────────────────────────────────────────────────────────────┤
│  压缩长期记忆（Compressed Long-term）                        │
│  之前任务的压缩摘要                                           │
│  内容："TASK-001 完成了脚手架搭建，用了 Rust + Axum"          │
│  → Agent 主动压缩，不是被动截断                               │
├─────────────────────────────────────────────────────────────┤
│  高保真短期交互（High-fidelity Short-term）                   │
│  当前任务的完整交互历史                                       │
│  内容：最近 N 轮的完整 think→act 记录                        │
│  → 保留完整细节，不压缩                                      │
└─────────────────────────────────────────────────────────────┘

组装顺序：
  system_prompt = 稳定语义 + 压缩记忆 + 短期交互
  
  总 token 预算分配：
    稳定语义：~2000 tokens（固定）
    压缩记忆：~2000 tokens（随任务数增长，但压缩后恒定）
    短期交互：~4000 tokens（最近 N 轮，滑动窗口）
    LLM 回复空间：~4000 tokens
    总计：~12000 tokens（可控）
```

## 四、与我们的设计映射

```
Phase 1（当前）：
  只有对话历史（内存），不压缩
  每个 NodeAssignment 是独立的（不跨任务）
  → 不存在膨胀问题（每个任务独立）

Phase 2（需要实现）：
  对话记忆持久化到 PostgreSQL
  Agent 快照/恢复时需要恢复记忆
  跨任务时需要压缩之前的记忆
  → 参考 Cat 框架的三层分区

Phase 3（需要实现）：
  长期记忆存入向量库
  跨项目经验检索
  反思式检索（arxiv 2512.20237）
```

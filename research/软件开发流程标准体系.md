# 软件开发流程标准体系 — 从零梳理

> 本文档记录从底层到高层逐层梳理软件开发流程标准体系的讨论过程与结论。
> 目标：建立一套完整的、可落地的开发流程认知框架。

---

## 背景

基于对 17 种软件开发流程标准的系统分析（BPMN 2.0、SPEM 2.0、ISO 12207、ISO 15288、ISO 29110、CMMI-DEV、SPICE、ISO/IEC 330xx、Automotive SPICE、ISO 9001、Scrum、Kanban、XP、SAFe、DevOps、ITIL、COBIT），我们重新定义了标准体系的层级模型，并从最底层开始逐层讨论。

## 层级模型

原始四层模型（流程表达 → 生命周期 → 能力评估 → 执行方法）存在问题：表达标准不是真正的底层，它是工具层——得先有东西要画，才谈得上怎么画。

重新定义的六层模型：

```
第 0 层：原子概念    角色 × 活动 × 制品（方法内容）
第 1 层：流程表达    怎么把活动组织成有序的流程（BPMN / SPEM）
第 2 层：生命周期    从头到尾应该有哪些过程（12207 / 15288）
第 3 层：能力评估    这些过程做得好不好（CMMI / SPICE）
第 4 层：执行方法    团队日常具体怎么跑（Scrum / XP / DevOps）
第 5 层：治理合规    组织层面怎么管控（ISO 9001 / COBIT）
```

---

## 第 0 层：原子概念 — 角色 × 活动 × 制品

### 核心问题

一群人协作完成软件，最基本的构成单元是什么？

### 答案：三个原子概念

```
角色（谁来做）  ×  活动（做什么）  ×  制品（产出什么）
     Role            Activity          Work Product
```

SPEM 2.0 把这三个叫 Method Content（方法内容），是所有流程标准的公共地基。不管用瀑布、Scrum、还是 BPMN 编排，最终都是在回答：谁、做什么、产出什么。

---

### 1. 角色（Role）

角色不是"人"，是一组职责和能力的集合。一个人可以扮演多个角色，一个角色可以由多个人承担。

**角色的本质**：这件事需要什么样的能力和权限才能做？

**三个构成要素**：

```
角色 = 身份（我是谁）+ 能力（我能做什么）+ 权限（我被允许做什么）
```

- 身份：角色在团队中的定位和职责边界（架构师负责技术决策，不负责写测试）
- 能力：角色拥有的技能和工具（后端开发能写代码、能操作数据库）
- 权限：角色被允许的操作范围（测试工程师能读所有代码，但不能改生产代码）

**角色间关系**：只有两种——协作（共同完成一个活动）和交接（一个角色的产出是另一个角色的输入）。

---

### 2. 活动（Activity）

活动是角色执行的一个有目的的工作单元。它消费输入、产出输出、有明确的完成条件。

**活动的本质**：要做什么事，才能把输入变成输出？

**三个层级**：

```
过程（Process）  >  活动（Activity）  >  任务（Task）
   粗粒度              中粒度              细粒度
  "需求分析"        "收集用户需求"       "访谈用户A"
```

**活动间关系**：四种——顺序（A 做完才能做 B）、并行（A 和 B 可以同时做）、条件（根据结果选 A 或 B）、循环（不满足条件就重做）。

---

### 3. 制品（Work Product）

制品是活动的可验证产出物。它是角色之间交接的载体，也是质量检查的对象。

**制品的本质**：怎么证明这件事做完了、做对了？

**两个维度**：

```
按形态：    文档 / 代码 / 配置 / 数据 / 模型 / 决策记录
按生命周期：草稿 → 评审中 → 已批准 → 已归档 → 已废弃
```

制品不等于文档。一段通过测试的代码是制品，一个部署成功的环境是制品，一条记录在案的决策也是制品。

---

### 4. 三者的关系

```
        ┌──────────┐
        │   角色    │
        │  (Role)  │
        └────┬─────┘
             │ 执行
             ▼
        ┌──────────┐       ┌──────────┐
        │   活动    │──────►│   制品    │
        │(Activity)│ 产出   │(Product) │
        └────▲─────┘       └────┬─────┘
             │                  │
             │    消费          │
             └──────────────────┘

一个活动由一个或多个角色执行
一个活动消费零个或多个制品作为输入
一个活动产出一个或多个制品作为输出
上一个活动的输出制品 = 下一个活动的输入制品（交接链）
```

这就是整个软件开发流程的原子模型。所有上层标准——BPMN 的节点和边、12207 的过程定义、Scrum 的角色和工件、CMMI 的实践域——都是在这三个概念上做组合和约束。

## 二、审查轮次

### 轮次 1：协议对齐（P0）

**目标：确保 core 定义的共享协议在 flow 和 runtime 中被正确使用。**

这是最关键的一轮。多个 AI 各自编写 flow 和 runtime，它们对共享协议的理解可能不一致。

```
审查路径：

  core（定义）
    │
    ├──→ flow（发送 FlowMessage / 接收 NodeResult）
    │
    └──→ runtime（接收 FlowMessage / 返回 NodeResult）
```

| # | 审查项 | 对照文件 |
|---|--------|---------|
| 1.1 | FlowMessage 模型字段三方一致 | core 定义 vs flow 使用 vs runtime 使用 |
| 1.2 | FlowMessageType 枚举值三方一致 | core 定义 vs flow dispatch vs runtime dispatch |
| 1.3 | NodeExecutePayload 字段一致 | core 定义 vs flow 构造 vs runtime 解析 |
| 1.4 | ChatMessagePayload 字段一致 | core 定义 vs flow 构造 vs runtime 解析 |
| 1.5 | NodeResult 字段一致 | core 定义 vs runtime 返回 vs flow 解析 |
| 1.6 | NodeResultType 枚举值一致 | core 定义 vs runtime 使用 vs flow 使用 |
| 1.7 | SandboxProvider 接口一致 | core 定义 vs runtime 调用 vs sandbox 实现 |
| 1.8 | platform API 路径一致 | platform 路由表 vs gate 转发 vs flow 调用 vs runtime 调用 |

**产出：** `审查报告/core.md` 中的协议对齐部分

## 四、通过标准

| 级别 | 条件 | 判定 |
|------|------|------|
| 通过 | 所有项目 0 Critical + 0 Major | 进入联调 |
| 有条件通过 | 0 Critical，Major ≤ 5 且已记录修复计划 | 进入联调，并行修复 Major |
| 不通过 | 存在 Critical 问题 | 修复后重新审查 |

### Critical 问题定义

以下任一情况判定为 Critical：

- 协议字段不一致（FlowMessage / NodeResult 在三方不对齐）
- platform API 路径在调用方不一致
- SQL DDL 与 Rust struct 字段不匹配
- 存在硬编码密钥
- 存在 SQL 拼接注入风险
- 服务启动后立即 panic / crash

### Major 问题定义

- 设计偏离（多了/少了模块、接口签名不一致）
- unwrap/expect 在非初始化代码中使用
- 缺少输入校验
- 注释质量不达标（核心函数无文档注释）
- 依赖不在设计选型范围内

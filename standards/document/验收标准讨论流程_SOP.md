# 验收标准讨论流程_SOP

> 目标: 定义 `06-验收标准.md` 如何通过讨论逐步生成。
> 适用对象: 人类作者、Claude/其他 Agent、多人协作讨论。
> 与 `验收标准书写规范.md` 的关系: 书写规范定义最终结果结构;本 SOP 定义内容生成顺序。
> 与 `设计文档讨论中间产物规范.md` 的关系: 本 SOP 定义每一步问什么;中间产物规范定义每一步讨论后留下什么、如何确认、如何回填。

## 1. 适用前提

本 SOP 适用于:

```text
需要为一个仓 / 一个模块 / 一个子系统编写 06-验收标准.md
且希望先通过讨论逐步收敛验收目标、验收基线、门禁、证据、一票否决和风险接受
```

它不适用于:

```text
重新定义需求目标
重新定义测试用例
记录测试执行报告
安排开发实施任务
替代发布 runbook
```

---

## 2. 核心原则

### 2.1 验收标准是裁决文档

验收标准必须支持“通过 / 有条件通过 / 不通过”的明确判断,不能写成测试过程流水账。

### 2.2 先固定基线,后定义门禁

不先固定需求、设计、测试、交付、环境和数据基线,就不能定义验收门禁。

### 2.3 门禁必须可判定

每条验收项都必须有通过条件、失败条件和证据来源。

### 2.4 风险接受必须显式

有条件通过只能建立在明确风险、接受人、后续动作和截止时间的基础上。

### 2.5 中间产物先于正式文档

不得直接跳到正式 `06-验收标准.md`。

执行链路必须是:

```text
本步输入
  -> 应问的问题
  -> SOP 问题回答
  -> Step 中间产物
  -> 回填草稿
  -> 用户确认 / 门禁通过
  -> 正式验收标准章节
```

Step 中间产物必须放在对应子项目的 `design-calibration/` 目录下，并遵循 `standards/document/设计文档讨论中间产物规范.md`。

每个 Step 的中间产物至少包含：

- Step 状态
- 本步输入
- SOP 问题回答
- 当前文档问题诊断
- 改动前后对比
- 验收裁决取舍
- 结构化中间产物
- 回填草稿
- 待确认事项
- 进入下一步条件

推荐中间产物命名:

```text
06_acceptance_calibration_flow.md
06_acceptance_step_01_input_boundary.md
06_acceptance_step_02_scope.md
...
```

### 2.6 ASCII 图输出统一

如本 SOP 中输出验收裁决流、证据流或发布门禁关系图,必须同时收稳:

```text
图类型
图标题
ASCII 图正文
图后 2~5 条关键说明
```

所有 ASCII 图必须遵守 `验收标准书写规范.md` 的通用输出规则。

## 3. Step 模板字段

| 字段 | 作用 |
|---|---|
| 本步目标 | 说明本步要解决什么验收裁决问题 |
| 本步输入 | 说明进入本步前必须具备哪些上游信息 |
| 本步输出 | 说明本步必须产出什么结构化结果 |
| 应问的问题 | 用于把输入收敛成输出的问题集合 |
| 期望产出 | 本步应该沉淀的表、图、矩阵或清单 |
| 回填位置 | 指向 `06-验收标准.md` 的章节 |
| 执行约束 | 说明本步允许和禁止的做法 |
| 进入下一步的条件 | 判断本步是否完成的门禁 |

---

## 4. 建议的讨论总流程

```text
Step 1. 确认验收输入边界
Step 2. 明确验收目标与范围
Step 3. 固定验收基线
Step 4. 定义进入条件与退出条件
Step 5. 定义功能验收门禁
Step 6. 定义数据边界与架构红线验收
Step 7. 定义接口、事件与跨仓同步验收
Step 8. 定义状态机、事务与一致性验收
Step 9. 定义非功能验收门禁
Step 10. 定义可观测性、审计与证据门禁
Step 11. 定义一票否决项
Step 12. 定义缺陷分级、复验与放行规则
Step 13. 定义风险接受与遗留项
Step 14. 定义最终结论与签署口径
Step 15. 整理正式验收标准文档
```

## 5. 每一步的讨论目标、输入与产出

### Step 1. 确认验收输入边界

#### 本步目标

确认验收标准承接哪些需求、设计、测试和交付输入。

#### 本步输入

- `00-需求文档.md`
- `01-架构设计.md`
- `02-概要设计.md`
- `03-详细设计.md`
- `05-测试方案.md`
- 交付版本 / 送验说明

#### 本步输出

- 验收输入映射表
- 验收标准不再回答的问题
- 验收标准必须回答的问题

#### 应问的问题

1. 本轮验收依据哪些需求和设计?
2. 哪些测试证据会支撑验收裁决?
3. 哪些交付版本、环境和数据会成为基线?
4. 哪些内容属于测试方案或实施计划,不应写进验收标准?
5. 是否存在阻塞验收标准生成的上游缺口?

#### 期望产出

| 来源文档 | 验收输入 | 本文如何裁决 |
|---|---|---|

#### 回填位置

`06-验收标准.md` §1。

#### 执行约束

- 不得重新发明需求和测试用例。
- 不得把测试执行结果写入验收标准草案。

#### 进入下一步的条件

- 验收输入和边界清楚。

### Step 2. 明确验收目标与范围

#### 本步目标

定义本轮验收裁决什么、不裁决什么。

#### 本步输入

- Step 1 输入映射
- 需求目标 / 非目标
- 测试方案范围

#### 本步输出

- 验收目标
- 范围 / 非范围表

#### 应问的问题

1. 本轮验收的核心裁决目标是什么?
2. P0/P1/P2 验收范围如何划分?
3. 哪些下游能力只验接缝?
4. 哪些非范围会影响最终结论?
5. 哪些范围项可能成为一票否决?

#### 期望产出

| 验收范围项 | 类型 | 优先级 | 裁决目标 | 非范围 / 说明 |
|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §2。

#### 执行约束

- 非范围必须显式。
- 不能用“本次全部验收”代替范围表。

#### 进入下一步的条件

- 验收范围可裁决。

### Step 3. 固定验收基线

#### 本步目标

固定需求、设计、测试、交付、环境和数据基线。

#### 本步输入

- 范围表
- 送验版本
- 测试报告 / 证据 run
- 环境配置

#### 本步输出

- 验收基线表

#### 应问的问题

1. 按哪一版需求和设计验收?
2. 按哪一版测试方案和测试结果裁决?
3. 送验 build / commit / image 是什么?
4. 环境、配置、数据和依赖是什么?
5. 基线变更如何处理?

#### 期望产出

| 基线类型 | 基线内容 | 版本 / 标识 | 说明 |
|---|---|---|---|

#### 回填位置

`06-验收标准.md` §3。

#### 执行约束

- 不得使用“最新版本”作为基线。

#### 进入下一步的条件

- 基线可定位、可复查。

### Step 4. 定义进入条件与退出条件

#### 本步目标

定义验收开始和结束的门禁。

#### 本步输入

- 验收基线
- 测试方案退出准则

#### 本步输出

- 进入条件
- 退出条件

#### 应问的问题

1. 开始验收前哪些基线必须确认?
2. 哪些测试证据必须先生成?
3. 哪些缺陷会阻断进入验收?
4. 退出验收需要哪些结论?
5. 哪些风险必须先接受?

#### 期望产出

```md
### 进入条件

- [ ] <条件>

### 退出条件

- [ ] <条件>
```

#### 回填位置

`06-验收标准.md` §4。

#### 执行约束

- 条件必须可判定。

#### 进入下一步的条件

- 进入 / 退出条件无模糊项。

### Step 5. 定义功能验收门禁

#### 本步目标

把功能需求和主流程转成验收项。

#### 本步输入

- 需求功能清单
- 详细设计处理流
- 测试方案用例与证据

#### 本步输出

- 功能验收门禁表

#### 应问的问题

1. 每个 P0 功能的通过条件是什么?
2. 每个 P0 功能的失败条件是什么?
3. 证据来自哪些测试用例或报告?
4. 哪些 P1 功能只做后置边界验收?
5. 哪些功能失败会导致总体不通过?

#### 期望产出

| 验收项 ID | 功能 / 场景 | 优先级 | 通过条件 | 失败条件 | 证据来源 |
|---|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §5。

#### 执行约束

- 不得只写“功能可用”。

#### 进入下一步的条件

- P0 功能都有可裁决门禁。

### Step 6. 定义数据边界与架构红线验收

#### 本步目标

把架构边界和数据所有权转成验收红线。

#### 本步输入

- 架构设计数据所有权
- 概要 / 详细设计禁止事项

#### 本步输出

- 架构红线验收表

#### 应问的问题

1. 哪些数据不得由本仓保存?
2. 哪些下游不得反向改写真相?
3. 哪些 projection / cache 不得反写真相?
4. 哪些 P1 能力不得污染 P0?
5. 红线失败时是否一票否决?

#### 期望产出

| 红线 ID | 红线 | 通过条件 | 失败条件 | 证据来源 |
|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §6。

#### 执行约束

- 红线必须可检查。

#### 进入下一步的条件

- 数据边界和架构红线都有验收项。

### Step 7. 定义接口、事件与跨仓同步验收

#### 本步目标

定义 API、Event、Job 和下游同步的验收门禁。

#### 本步输入

- 详细设计协议章节
- 测试方案接口用例
- 下游接缝说明

#### 本步输出

- 接口 / 事件 / 同步验收表

#### 应问的问题

1. 每个 P0 Command / Query 如何验收?
2. 每个 P0 Event 如何证明可消费 / 可重放?
3. 每个 P0 Job 如何证明幂等和恢复?
4. 跨仓同步成功标准是什么?
5. 下游未就绪时如何验接缝?

#### 期望产出

| 验收项 ID | 接口 / 事件 / 下游 | 通过条件 | 失败条件 | 证据来源 |
|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §7。

#### 执行约束

- 不得要求验收下游仓完整实现,除非本轮范围明确包含。

#### 进入下一步的条件

- P0 接口、事件和同步都有裁决口径。

### Step 8. 定义状态机、事务与一致性验收

#### 本步目标

定义状态、事务、一致性、幂等和并发验收门禁。

#### 本步输入

- 详细设计状态机 / 事务 / 并发章节
- 测试方案一致性用例

#### 本步输出

- 状态与一致性验收表

#### 应问的问题

1. 哪些合法状态迁移必须通过?
2. 哪些非法迁移必须拒绝?
3. 哪些事务必须原子提交?
4. 哪些幂等和并发行为必须成立?
5. 失败时如何判定不通过?

#### 期望产出

| 验收项 ID | 主题 | 通过条件 | 失败条件 | 证据来源 |
|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §8。

#### 执行约束

- 事务和状态验收必须有明确副作用断言。

#### 进入下一步的条件

- 状态和一致性门禁可裁决。

### Step 9. 定义非功能验收门禁

#### 本步目标

定义性能、安全、可用性、兼容性、恢复等非功能门禁。

#### 本步输入

- 非功能需求
- 测试方案专项测试

#### 本步输出

- 非功能验收表

#### 应问的问题

1. 哪些非功能指标是 P0?
2. 阈值来自需求、设计还是运行基线?
3. 哪些专项未覆盖,是否影响验收?
4. 哪些非功能失败会阻断发布?
5. 证据来自哪里?

#### 期望产出

| 验收项 ID | 维度 | 指标 / 要求 | 阈值 | 证据来源 | 结论口径 |
|---|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §9。

#### 执行约束

- 阈值不得无来源。

#### 进入下一步的条件

- 非功能裁决口径明确。

### Step 10. 定义可观测性、审计与证据门禁

#### 本步目标

定义哪些证据必须存在才能验收通过。

#### 本步输入

- 详细设计观测 / 审计章节
- 测试方案证据归档设计

#### 本步输出

- 证据门禁表

#### 应问的问题

1. 哪些行为必须有 audit record?
2. 哪些行为必须有 trace / log / metric?
3. 哪些测试报告必须归档?
4. 证据缺失是否导致不通过?
5. 证据如何被复查?

#### 期望产出

| 验收项 ID | 证据主题 | 必须存在的证据 | 通过条件 | 失败条件 |
|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §10。

#### 执行约束

- 不得用口头确认替代证据。

#### 进入下一步的条件

- P0 证据门禁完整。

### Step 11. 定义一票否决项

#### 本步目标

定义任何情况下都不能通过验收的问题。

#### 本步输入

- 需求红线
- 架构红线
- 详细设计不变量
- 安全 / 合规要求

#### 本步输出

- 一票否决项表

#### 应问的问题

1. 哪些失败会直接导致不通过?
2. 否决项来自哪个需求或设计红线?
3. 否决项如何检查?
4. 否决项是否允许风险接受?
5. 否决项是否覆盖所有 P0 红线?

#### 期望产出

| 否决项 ID | 否决项 | 原因 | 证据 / 检查方式 |
|---|---|---|---|

#### 回填位置

`06-验收标准.md` §11。

#### 执行约束

- 一票否决项不得被风险接受覆盖。

#### 进入下一步的条件

- 否决项清楚且可检查。

### Step 12. 定义缺陷分级、复验与放行规则

#### 本步目标

定义缺陷如何影响验收结论。

#### 本步输入

- 测试方案缺陷规则
- 一票否决项

#### 本步输出

- 缺陷分级表
- 复验规则
- 放行规则

#### 应问的问题

1. S/A/B 缺陷如何定义?
2. 每级缺陷对验收结论有什么影响?
3. 修复后如何复验?
4. 哪些缺陷可以风险接受?
5. 哪些缺陷必须阻断下一阶段?

#### 期望产出

| 缺陷级别 | 定义 | 对结论的影响 | 复验要求 |
|---|---|---|---|

#### 回填位置

`06-验收标准.md` §12。

#### 执行约束

- 缺陷规则必须与一票否决项一致。

#### 进入下一步的条件

- 缺陷对结论的影响可判定。

### Step 13. 定义风险接受与遗留项

#### 本步目标

定义有条件通过所需的风险接受结构。

#### 本步输入

- 测试方案残余风险
- 待确认事项
- 缺陷分级规则

#### 本步输出

- 风险接受表

#### 应问的问题

1. 哪些风险可以支持有条件通过?
2. 哪些风险不能接受?
3. 每个风险的接受人是谁?
4. 后续动作和截止时间是什么?
5. 风险是否需要同步到实施计划或问题记录?

#### 期望产出

| 风险 / 遗留项 | 影响 | 接受理由 | 后续动作 | 责任人 | 接受人 | 截止时间 |
|---|---|---|---|---|---|---|

#### 回填位置

`06-验收标准.md` §13。

#### 执行约束

- 没有接受人的风险不能作为有条件通过依据。

#### 进入下一步的条件

- 所有残余风险都有处理口径。

### Step 14. 定义最终结论与签署口径

#### 本步目标

定义最终结论如何表达和签署。

#### 本步输入

- 所有验收门禁
- 风险接受表
- 缺陷规则

#### 本步输出

- 结论表
- 签署表

#### 应问的问题

1. 结论只能有哪些取值?
2. 何时允许进入下一阶段?
3. 何时允许发布准备?
4. 哪些角色必须签署?
5. 签署是否代表风险接受?

#### 期望产出

| 维度 | 结论 | 说明 |
|---|---|---|

| 角色 | 姓名 / 责任 | 结论 | 日期 |
|---|---|---|---|

#### 回填位置

`06-验收标准.md` §14。

#### 执行约束

- 禁止使用模糊结论。

#### 进入下一步的条件

- 结论和签署口径完整。

### Step 15. 整理正式验收标准文档

#### 本步目标

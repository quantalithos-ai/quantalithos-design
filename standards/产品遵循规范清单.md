# 产品遵循规范清单

> **文档定位**:10 个产品在**产品侧**必须遵守的规范清单。按产品展开,每个产品列出**强制项**(Blocker)+ **推荐项**(Warning)。
>
> **与子项目清单的分工**:
> - 本文 = **产品层规范**(一个产品由多仓组合而来,规范服务于"产品整体用户体验、发布节奏、合规形态")
> - `子项目遵循规范清单.md` = **仓库层规范**(单个仓库内的代码、文档、接口约束)
>
> **上游依据**:
> - `standards/README.md` §一 三条横切红线(最高约束)
> - `product/产品矩阵.md` 10 产品定位
> - `architecture/标准对齐全景图.md` §一 L5/L6 层
>
> **如何使用**:产品发版前,对照本文清单逐条过;任何强制项未满足即 Blocker。

---

## 零、共同强制项(所有产品必守)

以下 **8 条**不管哪个产品都必须满足。不在每个产品章节重复。

| # | 共同强制项 | 依据 |
|---|---|---|
| C1 | 所有业务能力通过 **SDK** 连 Server,不得绕过直连 L1 六域服务 | `产品矩阵.md` §2.3 共同原则 3 |
| C2 | 产品自身行为发事件进 **observability**,不只业务发事件 | §2.3 共同原则 5 + 三红线 1 |
| C3 | 跨域事件遵循 **CloudEvents 1.0** + **W3C Trace Context** 贯穿 | `六域模型.md` §2.2 |
| C4 | 所有 UI 面向用户的文案不出现"编译 / 部署 / 分支"等开发者语境(Assistant 被 @ 时除外) | `最终目的.md` §3.1 |
| C5 | UI 产品必须覆盖 **25010 Interaction Capability 六子特性** | 标准对齐全景图 §一 |
| C6 | **三红线** 在产品自身发布流程中也适用(不允许"我们是产品部门可以免审计") | `README.md` §一 |
| C7 | 重大发布(Server major / AI Members 新 Role / SDK breaking)必须经过相应 Gate | `产品矩阵.md` §9.4 |
| C8 | 产品的 README / User Doc 必须列出**刻意不做**的事,避免用户期待错位 | `最终目的.md` §八 |

## 一、① Chat

### 强制项

| # | 项 | 依据 |
|---|---|---|
| CH1 | Conversation 四形态(group / channel / dm / thread)UI 实现必须完整,不允许省略 | `六域模型.md` §4.2.1 |
| CH2 | Turn 五 kind(message / mention / decision / artifact / gate)UI 必须各自有明确渲染方式,GateCard 必须六段式完整展示 | `六域模型.md` §4.2.2 + §7.2.1 |
| CH3 | GateCard 的 candidate_options 必须清楚展示"选这个会发生什么"(consequences 字段) | `最终目的.md` §3.5 + 42001 A.9 |
| CH4 | 员工登录视图(查看某 Member 在干什么)必须实时、可进可出,不允许"登录后跳转到 Console" | `最终目的.md` §3.2 |
| CH5 | **Accessibility WCAG 2.2 AA** 基线 | 25010 Inclusivity |
| CH6 | 实时推送使用 **AG-UI 17 事件**,不自定义私有事件 | 标准对齐全景图 |
| CH7 | 对话历史永久可查,不做"30 天自动删除"这类破坏可审计性的设计 | 三红线 1 |
| CH8 | 多端(桌面 + Web + Mobile)共用同一 Conversation 实时同步,不做端侧本地独立对话 | `产品矩阵.md` §3.1 |

### 推荐项

- 支持 **Slash commands**(`/gate approve` / `/hire role=qa` 等)加速管理者操作
- 支持 **键盘快捷键**(参照 Slack / Discord 最佳实践)
- **消息编辑** 必须显示"已编辑"标识(不允许悄悄改 Turn;Turn 本体不可变的前提下,编辑要通过新 Turn 覆盖旧 Turn 的显示)
- **移动端不做全功能**,仅覆盖接收通知 + 审批 Gate + 简短回复

### 刻意不做(产品叙事强约束)

- ❌ 不内嵌 IDE(违反"用户是管理者"叙事)
- ❌ 不做详细代码编辑(最多 diff 预览)
- ❌ 不暴露 Server 配置和运维(那是 Console)

## 二、② Runner

### 强制项

| # | 项 | 依据 |
|---|---|---|
| RN1 | 只能运行 **已 approved / baselined 的 Release Artifact**,不能运行任意 Artifact | `六域模型.md` §八状态机 |
| RN2 | **沙箱隔离**(Docker / gVisor / Firecracker),不允许 Release 包直接在主机跑 | Research 沙箱逃逸 |
| RN3 | 运行日志发事件进 observability(包括启动 / 崩溃 / 资源使用) | 红线 1 |
| RN4 | 用户无法修改 Release 包内容(即使在本机) | 红线 1 + 25010 Integrity |
| RN5 | **版本选择必须显式**:UI 显示当前运行哪个 Release 版本,不允许"自动用最新" | 红线 1 |
| RN6 | 支持一键停止、清理资源、释放端口 | 25010 Reliability |

### 推荐项

- 同时运行多项目时提供资源看板(各项目 CPU / 内存 / 端口)
- 运行失败时收集日志并提供"回传 Quantalithos"选项(用户授权后发 Turn 进 dm 给 Assistant 分析)
- 支持"一键分享给朋友试用"(生成临时访问链接)

### 刻意不做

- ❌ 不做调试器
- ❌ 不做生产部署(生产部署走 DevOps 过程,Runner 是"本地跑")

## 三、③ Sync

### 强制项

| # | 项 | 依据 |
|---|---|---|
| SY1 | 仅允许在用户**拥有权限**的 Project 下同步 | 42001 A.3 责任链 |
| SY2 | 任何本地修改的 push-back 必须进入 **review Gate**,不允许直接进主分支 | 红线 1 + `六域模型.md` §七 |
| SY3 | 冲突必须由**用户决策**,不允许自动合并 | 红线 2 |
| SY4 | 本地同步的代码完整保留来源元数据(`.qs-sync/metadata.json`),不能移除 | 红线 2 + 42001 A.7 |
| SY5 | **不做自动推送**,所有 push-back 必须明示"要推回"命令 | 42001 A.9 Responsible Use |

### 推荐项

- 支持 `git` 子命令 passthrough(用户在本地可用完整 git 能力)
- 支持 Web IDE 集成(通过 editor URL scheme)
- 支持 dry-run 模式

### 刻意不做

- ❌ 不替代 git
- ❌ 不做自动合并 / rebase
- ❌ 不做跨项目同步

## 四、④ Website

### 强制项

| # | 项 | 依据 |
|---|---|---|
| WB1 | **Accessibility WCAG 2.2 AA** | 25010 Inclusivity |
| WB2 | 不嵌入需要登录的动态功能(保持独立部署) | `产品矩阵.md` §3.4 |
| WB3 | 文档站版本与 Server 版本对应标识,**不混版本** | 9001 文档控制 |
| WB4 | Cookie / 追踪同意必须符合 **GDPR** 基线 | 42001 A.7 |
| WB5 | 刻意不做章节:每款产品介绍页必须有"这个产品不做什么"段落 | C8 |

### 推荐项

- 支持中英文(优先)+ 其他语言(社区贡献)
- 提供 Feed / Release Notes RSS
- 开源文档允许社区 PR

### 刻意不做

- ❌ 不做应用功能
- ❌ 不做在线 Playground(未来独立产品)

## 五、⑤ Console

### 强制项

| # | 项 | 依据 |
|---|---|---|
| CS1 | 必须有 **Management Review UI**(42001 §9.3) | 42001 |
| CS2 | **SoA 编辑 UI**:列出 42001 附录 A 所有 38 控制项,每项可标注 applicability + implementation_status + evidence_refs | 42001 §6.1.3 |
| CS3 | **AIIA 面板**:每个项目的 AIIA 状态、审批记录、残余风险清单可见 | 42001 §8.2 |
| CS4 | **审计事件回放**:任意时间窗口内的事件可以按 project / member / domain 过滤回放 | 红线 1 |
| CS5 | **哈希链验证**入口:审计事件的哈希链完整性可一键验证并生成报告 | 红线 1 |
| CS6 | 所有管理操作必须留痕,不允许"静默修改" | 红线 1 |
| CS7 | **权限模型必须显式**:谁能看审计 / 谁能改 Role / 谁能发 Policy 清晰可配 | 42001 A.3 |

### 推荐项

- 仪表盘(Dashboard)可配置,不同角色看不同指标
- 支持**组织级别**和**项目级别**两个粒度
- DORA / EBM 指标图表 + 自定义指标 + 导出

### 刻意不做

- ❌ 不做日常协作(那是 Chat)
- ❌ 不做代码编辑
- ❌ 不做项目立项(那是 Chat 里发起)

## 六、⑥ Server

### 强制项

| # | 项 | 依据 |
|---|---|---|
| SV1 | 必须提供 **自托管(Docker Compose / Helm)** 和 **SaaS** 两种部署形态 | `产品矩阵.md` §5.1 |
| SV2 | 自托管部署包版本化发布,含 **完整 release notes + 升级指南 + 回滚指南** | 25010 Reliability |
| SV3 | **多租户隔离**(SaaS 场景):数据 / 事件 / observability 严格分隔 | 42001 A.3 + 27001 |
| SV4 | 通过 **Helm Chart** 或 **Docker Compose** 提供的部署包**必须能在无互联网环境下启动**(air-gap 支持) | 企业合规场景需要 |
| SV5 | Server 升级不得丢失 archive / observability 数据 | 红线 1 + 9001 文档保留 |
| SV6 | **Gate 机制**:release-confirm Gate 必须在主版本发布前走一次(产品自身发布也应用 Gate) | C7 |
| SV7 | 提供 **健康检查**端点(liveness / readiness)和 OTel 指标 | 25010 Reliability |

### 推荐项

- 提供 **一键回滚** 能力
- 提供 **流量灰度** 能力
- SaaS 版本提供 **Status Page**

### 刻意不做

- ❌ 不做 LLM 模型服务(调用 Anthropic / OpenAI / 自托管 LLM)
- ❌ 不做支付 / 计费(暂)

## 七、⑦ AI Members

### 强制项

| # | 项 | 依据 |
|---|---|---|
| AM1 | 镜像**按 Role 预构建**,不在运行时现装工具 | ADR-0005 |
| AM2 | 每个镜像含 **image digest 签名**,member-service 拉取时校验签名 | 红线 1 + 42001 A.4 |
| AM3 | 镜像版本与 Server major.minor **同步** | `产品矩阵.md` §9 |
| AM4 | `ai-member-base` 层的安全补丁必须**即时发布**(不等定期发版) | Research 沙箱加固 |
| AM5 | 新 Role 上线必须走 **role-introduction Gate**(方法论负责人 + 产品负责人共批) | C7 |
| AM6 | 镜像中**禁止**内置任何硬编码的 API Key 或 credential | 红线 1 + 27001 |
| AM7 | 镜像构建清单(BOM)发布,列出所有 apt / pip / npm 依赖及版本 | 42001 A.7 Data Provenance |

### 推荐项

- 按需多架构支持(amd64 + arm64)
- 镜像扫描(Trivy / Grype)进 CI 每次构建必扫
- 提供"最小镜像"变体(去掉可选工具,用于资源受限场景)

### 刻意不做

- ❌ 不允许项目级定制镜像(镜像按 Role 统一,项目差异通过 tool_scope + policy_overrides 裁剪)

## 八、⑧ Bridges

### 强制项

| # | 项 | 依据 |
|---|---|---|
| BR1 | **权限边界**:外部平台操作不得绕过 Quantalithos 的 Policy 和 Gate | 42001 A.10 |
| BR2 | **external_id → GlobalMember 映射**必须由组织明确授权,不得自动创建 | 42001 A.3 |
| BR3 | **敏感 Gate**(release / impact-assessment / archive)在外部平台不渲染完整内容,只提示"请打开 Chat 审批" | 红线 1 |
| BR4 | 外部平台的消息进入 Conversation 作为 Turn,**必须标记 bridged_from 来源** | 红线 2 |
| BR5 | 外部平台 Bot 账号的所有操作发事件进 observability,**标识这是桥接来源** | 红线 1 |
| BR6 | 外部平台 API Key 存储加密,轮换机制完备 | 27001 |

### 推荐项

- 支持 OAuth 接入(而非只 API Key)
- Bot 帮助文档本地化(按平台的用户习惯)

### 刻意不做

- ❌ 不让外部平台用户跳过 Chat 执行"不该在外部做"的动作
- ❌ 不允许跨平台混合 Conversation

## 九、⑨ SDK

### 强制项

| # | 项 | 依据 |
|---|---|---|
| SK1 | 三语言(Python / Rust / TypeScript)版本**独立发版**但版本号同步 | `产品矩阵.md` §9 |
| SK2 | 类型定义由 **core proto 自动生成**,不手写 | 25010 Interoperability |
| SK3 | **Breaking change 必须经过 Gate**(SDK 负责人 + 所有端侧产品负责人共批) | C7 |
| SK4 | 每个 API 有**完整 docstring + 示例 + 类型注解** | 9001 文档完备 |
| SK5 | 内置 **OTel trace 自动传播**,用户调用 SDK 即有 trace | 标准对齐全景图 |
| SK6 | 内置 **MCP Client 能力**,方便开发者构建 MCP-aware 工具 | 标准对齐全景图 |
| SK7 | **Deprecated API 至少给 2 个 minor 过渡期**,不允许当版移除 | 25010 Compatibility |

### 推荐项

- 每个版本提供 migration guide
- 支持多种认证方式(OAuth / API Key / mTLS)
- 内置 retry + 指数退避默认配置

### 刻意不做

- ❌ 不做 UI 组件
- ❌ 不做本地缓存

## 十、⑩ Marketplace

### 强制项

| # | 项 | 依据 |
|---|---|---|
| MK1 | 资产上架必须经过 **marketplace-review Gate**(合规 + 内容审核共批) | 42001 A.10 |
| MK2 | 资产使用 **29110 Deployment Package** 格式打包 | 29110 |
| MK3 | 资产发布者身份验证(实名 / 组织凭证) | 42001 A.3 + 9001 供应商 |
| MK4 | 购买 / 安装后的资产在用户侧**可审计** | 红线 1 |
| MK5 | 支持**撤销上架**(发布者 / 审核方)和**通知已安装用户** | 红线 1 + 42001 A.10 |
| MK6 | Role / Member 镜像资产上架前必须过安全扫描 | Research + 42001 A.4 |

### 推荐项

- 评分 + 评论(但评论要合规审核)
- 搜索 + 分类 + 标签
- 排行榜 / 推荐机制(基于使用度而非付费)

### 刻意不做

- ❌ 不做 LLM 模型市场
- ❌ 不做人力服务
- ❌ 不做代码片段市场

## 附录:发版前 Go/NoGo 模板

```markdown
## <产品名> vX.Y.Z 发版前检查清单

### 共同强制项(8)
- [ ] C1 … C8 逐项确认

### 产品强制项(<产品> 的 N 项)
- [ ] 逐项确认

### 三红线最终确认
- [ ] 可审计性:所有新功能的写操作已加事件
- [ ] 可追溯性:所有新产物可反向追溯到需求
- [ ] 可裁剪性:所有新过程 / 角色 / 策略已在 method-library,非 hardcode

### 文档
- [ ] CHANGELOG 更新
- [ ] User Doc 更新
- [ ] Migration Guide(breaking 变更时)
- [ ] 刻意不做章节更新

### Gate
- [ ] release-confirm Gate 已批准(对 Server major / AI Members 新 Role / SDK breaking)
```
